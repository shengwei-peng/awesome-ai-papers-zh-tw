## 摘要翻譯

強化學習（Reinforcement Learning, RL）搜尋代理（search agents）通常將檢索（retrieval）建模為自由格式自然語言查詢生成（free-form natural-language query generation），並使用最終答案獎勵（final-answer rewards）來最佳化多輪互動（multi-turn interactions）。現有研究主要透過更密集或更具結構化的信用信號（credit signals）來改進訓練，但很少檢視檢索在策略-環境介面（policy-environment interface）上的形式化是否適當。我們在 Search-R1 訓練過程中觀察到明顯的檢索混疊（retrieval aliasing）：針對同一問題的抽樣軌跡（rollouts）持續生成相異查詢字串（distinct query strings），但其累積證據集合（accumulated evidence sets）卻越來越重疊。我們將此現象稱為檢索等價崩潰（retrieval-equivalence collapse）；在此狀態下，軌跡（trajectories）在檢索決策（retrieval decisions）方面趨近效用等價（utility equivalence），使得組內回報（within-group returns）幾乎沒有有效的檢索對比（effective retrieval contrast）。為了解決此問題，我們提出 Harness-G（圖結構化檢索框架，graph-structured retrieval framework），重新設計此介面。它將自由格式自然語言查詢生成重新形式化為有限動作選擇（finite action selection）：策略（policy）選擇一個證據句（evidence sentence）或實體（entity），或選擇回答（answer）；環境（environment）則建構動作選單（action menu）、追蹤檢索狀態（retrieval state），並驗證與執行每個選擇（validate and execute each choice）。此介面減少了語言混疊（linguistic aliasing），並使同狀態替代方案（same-state alternatives）可直接比較。在此介面基礎上，我們提出結構化非短視信用分配（Structured Non-myopic Credit, SNC），其使用凍結答案評分器（frozen answer scorer）來比較選定動作（selected action）與其替代方案（alternatives），並將下游增益（downstream gains）分配給促成它們的較早動作（earlier actions）。在六個問答基準測試（QA benchmarks）中，Harness-G 在兩個評估模型規模（model scale）下均達到最高的平均 F1 分數（average F1），分別在 1.5B 與 3B 模型規模上，超越最強基線（strongest baseline）Graph-R1 達 10.74 點與 3.98 點。

### 核心貢獻（3～5點）
- 觀察並形式化 Search-R1 訓練中的檢索混疊（retrieval aliasing）現象，將其命名為檢索等價崩潰（retrieval-equivalence collapse），指出此現象會使軌跡在檢索決策上趨近效用等價，導致組內回報缺乏有效檢索對比。
- 提出 Harness-G（圖結構化檢索框架），將自由格式自然語言查詢生成重新設計為有限動作選擇，由環境負責建構動作選單、追蹤檢索狀態並驗證執行每個選擇，以降低語言混疊並使同狀態替代方案可直接比較。
- 提出結構化非短視信用分配（SNC），利用凍結答案評分器比較選定動作與其替代方案，並將下游增益回饋給促成它們的較早動作，從而改善多輪互動中的信用分配。
- 在六個問答基準測試上，於 1.5B 與 3B 模型規模均取得最高平均 F1 分數，分別超越最強基線 Graph-R1 達 10.74 點與 3.98 點。

### 適合對象
適合對強化學習、檢索增強生成、多跳推理與問答系統有興趣的研究者與工程師，特別是關注策略-環境介面設計、信用分配機制與搜尋代理訓練穩定性的讀者。

## 深度分析

#### 方法論解析

##### 1. 問題診斷：檢索等價崩潰（retrieval-equivalence collapse）

本文首先指出，現有 RL 搜尋代理（RL search agents）——如 Search-R1——將檢索（retrieval）建模為「自由格式自然語言查詢生成（free-form natural-language query generation）」。在訓練過程中，策略（policy）會針對同一問題產生大量表面相異的查詢字串（distinct query strings），但這些查詢累積下來的證據集合（accumulated evidence sets）卻高度重疊。作者將此現象命名為**檢索混疊（retrieval aliasing）**，並進一步觀察到**檢索等價崩潰**：隨著訓練進行，rollout（抽樣軌跡）雖然在查詢形式（query-form）上仍保持多樣性，但在檢索結果（retrieval-outcome）上卻迅速收斂到少數等價類別（equivalence class）。

這對群組相對優化（group-relative optimization，例如 GRPO）造成兩大傷害：

- **組內優勢消失（vanishing within-group advantages）**：同一等價群組內的軌跡（trajectory）獲得幾乎相同的回報（return），導致策略無法從中區分出較好的檢索決策（retrieval decisions）。
- **檢索信用混淆（confounded retrieval credit）**：即使最終答案不同，回報差異也主要來自下游推理或答案生成，而非檢索品質，導致信用分配（credit assignment）錯誤。

##### 2. 核心設計：圖結構化檢索框架（graph-structured retrieval framework）

為了解決上述問題，Harness-G 重新設計了**策略-環境介面（policy-environment interface）**。它不再讓策略直接生成自然語言查詢（natural-language query），而是將檢索重新定義為**有限動作選擇（finite action selection）**：

- **動作選單（action menu）**：環境（environment）在每一步提供一組有限的可選動作，包括：
  - **Select（選擇證據句）**：選擇一個證據句（evidence sentence）；
  - **Lookup（查詢實體）**：選擇一個實體（entity）進行擴展；
  - **Answer（回答）**：終止檢索並產生答案（answer）。

這些動作在一個**三部圖（tripartite graph）**上進行，環境負責建構動作選單、追蹤檢索狀態（retrieval state）、驗證並執行每個選擇。這樣的介面有幾個好處：

- **降低語言混疊（linguistic aliasing）**：策略不再糾結於用不同語言表達同一檢索意圖，而是直接選擇語義單元（句子或實體）。
- **同狀態替代方案可比較（same-state alternatives directly comparable）**：在相同狀態（state）下，不同動作選項被明確列出，便於進行對比學習。
- **環境承擔查詢建構與執行**：策略只需輸出動作 ID，環境負責將其轉換為實際檢索並更新狀態，減少了策略的負擔。

##### 3. 結構化非短視信用分配（Structured Non-myopic Credit, SNC）

在圖結構化介面的基礎上，作者提出 SNC，包含兩個核心機制：

- **邊界相對信用（frontier-relative credit）**：利用一個**凍結答案評分器（frozen answer scorer）**，在只讀預覽（read-only previews）下比較「選定動作（selected action）」與「同狀態替代方案（alternatives）」的預期效用。這提供了局部動作層級的對比信號。
- **啟用信用（enablement credit）**：將下游增益（downstream gains）沿著軌跡依賴關係回傳給較早動作（earlier actions），讓「橋接性」檢索動作也能獲得延遲獎勵（delayed reward）。

SNC 的關鍵在於結合了**同狀態對比**與**跨步長期信用**，既避免了短視（myopic）獎勵的問題，也讓中間檢索步驟能獲得明確的信用信號（credit signals）。

#### 實驗數據解讀

##### 1. 主實驗結果

作者在六個 QA 基準測試（QA benchmarks）上進行評估，涵蓋多跳推理（multi-hop reasoning）與開放領域問答（open-domain QA）。結果顯示：

- **1.5B 模型規模（model scale）**：Harness-G 的平均 F1 分數（average F1）超越最強基線 Graph-R1 **10.74 點**。
- **3B 模型規模**：Harness-G 超越 Graph-R1 **3.98 點**。

這兩個尺度的提升都相當顯著，尤其在 1.5B 模型上，顯示 Harness-G 的介面設計與信用分配機制對較小模型特別有幫助——可能是因為小模型在自由查詢介面（free-query interface）下更容易產生語言混疊，而有限動作選擇降低了其決策負擔。

##### 2. 控制實驗的意涵

文中提到進行了控制研究（controlled studies），分別驗證：

- **動作選單（action menu）**單獨帶來的增益；
- **SNC**單獨帶來的增益。

這表示 Harness-G 的整體提升並非單一元件所致，而是**介面設計**與**信用分配**相輔相成的結果。動作選單解決了檢索等價崩潰，提供了可對比的動作空間；SNC 則在這個空間上提供了精細且非短視的信用信號。

##### 3. 現象觀察的實證價值

圖 1a 顯示，在 Search-R1 訓練中，查詢形式多樣性（query-form diversity）維持高位，但檢索結果多樣性（retrieval-outcome diversity）迅速崩潰，跨越多個檢索等價類別（retrieval-equivalence class）的 rollout 群組比例從約 86% 降至 10% 以下。這定量地證明了「虛假探索（illusory exploration）」的存在：策略看似在探索不同查詢，實際上並未產生有效的檢索對比（effective retrieval contrast）。

圖 1b 則顯示，在相同轉移條件下，動作選單能保留更多檢索相異結果，這為 Harness-G 的設計提供了直觀的經驗支持。

#### 與現有研究的比較

##### 1. 與 Search-R1 等自由查詢代理的差異

Search-R1、R1-Searcher、DeepResearcher 等方法保留了傳統的**自由查詢介面（free-query interface）**：策略生成自然語言查詢，環境執行檢索。這些方法主要透過最終答案獎勵（final-answer rewards）進行優化，容易出現獎勵崩潰（reward crashes）、重複檢索（repetitive retrieval）與組內優勢消失等問題。

Harness-G 的創新在於從**介面層級**解決問題：它不是單純改進獎勵函數或增加過程獎勵（process rewards），而是改變了動作空間的定義，讓檢索決策變得離散、有限且可比較。

##### 2. 與 Graph-R1 的關係

Graph-R1 是本文最強基線（strongest baseline），本身可能已經使用某種圖結構或結構化信號。Harness-G 在 1.5B 與 3B 都顯著超越 Graph-R1，顯示其圖結構化設計與 SNC 優於現有的圖導向 RL 檢索方法。具體而言，Harness-G 的優勢可能來自：

- 更明確的動作選單機制；
- 凍結答案評分器提供的穩定對比信號；
- 啟用信用對長期依賴的建模。

##### 3. 與其他信用分配方法的比較

現有研究如 IGPO、StepSearch、ReasonRAG、CriticSearch、Tree-GRPO、GiGPO 等，主要透過資訊增益（information gain）、中間監督、回顧式評論家（retrospective critic）或樹狀對比來提供更密集的信用信號。然而，這些方法大多保留自由查詢介面，因此無法從根本上解決**檢索混疊**與**檢索等價崩潰**。

Harness-G 的 SNC 與這些方法不同之處在於：

- 它利用動作選單產生的**邊界（frontier）**進行同狀態對比；
- 它使用**凍結答案評分器**而非可學習的評論家，避免評論家本身被策略影響；
- 它明確建模**啟用關係**，將下游增益歸因於較早動作。

##### 4. 限制與潛在弱點

儘管結果強勁，本文方法仍有幾點值得注意：

- **動作選單的建構依賴環境能力**：若環境無法有效從文件中抽取高品質的證據句（evidence sentence）與實體（entity），則動作空間可能遺漏關鍵資訊。
- **三部圖的表達能力有限**：某些複雜檢索意圖可能無法僅透過「選句」或「查實體」來表達，特別是需要聚合、比較或數值運算的情境。
- **凍結答案評分器的偏差**：SNC 的品質取決於該評分器的準確性與泛化能力，若評分器對某些領域有偏，則信用分配也會跟著有偏。
- **計算成本**：環境需要在每一步建構動作選單、執行多次預覽與評分，可能增加訓練與推論的開銷。

#### 未來研究方向

##### 1. 動作空間的擴展

目前 Harness-G 的動作僅包含選擇證據句、查詢實體與回答。未來可考慮加入更豐富的動作類型，例如：

- **聚合動作（aggregation action）**：將多個證據句合併為新的推論節點；
- **比較動作（comparison action）**：比較兩個實體或數值；
- **反事實查詢（counterfactual lookup）**：針對假設性情境進行檢索。

這將使圖結構化檢索框架能處理更複雜的多跳推理任務。

##### 2. 與真實網路檢索的結合

本文的實驗可能基於靜態或模擬檢索環境。未來可將 Harness-G 擴展至**真實網路搜尋（live-web retrieval）**，讓動作選單從搜尋引擎結果頁面（SERP）中動態建構。這需要解決動作選單規模過大、延遲高、噪訊多等挑戰。

##### 3. 更精細的啟用信用建模

目前的啟用信用沿軌跡依賴關係傳播。未來可引入更正式的因果歸因框架（causal attribution framework），例如 Shapley 值或反事實軌跡分析，以更精確地判斷哪些較早動作真正「啟用」了後續成功。

##### 4. 跨領域與跨語言泛化

可研究 Harness-G 在跨領域（cross-domain）與跨語言（cross-lingual）設定下的表現，特別是當凍結答案評分器與目標領域不匹配時，如何進行適應或微調。

##### 5. 與過程獎勵模型的結合

Harness-G 的 SNC 可與現有的過程獎勵模型（process reward models）或資訊增益方法結合，形成多層次的信用信號。例如，可用過程獎勵提供即時反饋，再用 SNC 提供長期啟用信用。

##### 6. 理論分析

未來可對檢索等價崩潰進行更嚴謹的理論刻畫，例如分析在什麼條件下自由查詢介面會必然導致效用等價（utility equivalence），以及動作選單如何改變策略梯度估計的變異數（variance）。

##### 7. 效率與可擴展性

動作選單的建構與凍結評分器的多次呼叫可能帶來顯著計算成本。未來可研究如何透過快取（caching）、近似評分或層級式動作選單來提升效率，使 Harness-G 能應用於更大規模的模型與更長的檢索軌跡。

## 論文問答

**Q1：什麼是檢索等價崩潰（retrieval-equivalence collapse），它在 Search-R1 訓練中如何被觀察到？**

A：檢索等價崩潰是指策略在面對同一問題時，持續產生表面相異的查詢字串，但這些查詢所累積的證據集合卻越來越重疊，最終使不同軌跡在檢索決策上趨近效用等價的現象。在 Search-R1 的訓練過程中，作者發現查詢形式多樣性維持在高點，但檢索結果多樣性卻迅速下降，橫跨多個檢索等價類別的 rollout 群組比例從約 86% 降至 10% 以下。這種虛假探索使得組內回報缺乏有效檢索對比，強化學習難以區分好壞的檢索決策。

**Q2：為何現有的流程獎勵、資訊增益或更細緻的信用信號無法根本解決檢索等價崩潰？**

A：現有方法大多在既有的自由查詢介面上增加更密集的獎勵或信用信號，卻未改變「自由格式自然語言查詢→檢索結果」這種多對一的鬆散映射關係。由於語言混疊，策略可以輕易產生語意等價但字串不同的查詢，導致查詢形式多樣性無法轉化為真正的檢索決策多樣性。因此，即使加入流程獎勵，rollout 群組仍可能只包含少數幾個檢索上真正不同的樣本，無法恢復有效的檢索對比。

**Q3：為什麼策略-環境介面（policy-environment interface）是 RL 搜尋代理優化的核心問題？**

A：策略-環境介面決定了策略可執行的動作空間，以及環境如何回傳狀態與獎勵，直接影響信用分配能否對應到真正的決策差異。在自由查詢介面中，動作是開放式字串，環境再將其映射為檢索結果，這種鬆散耦合讓相同狀態下的替代方案難以直接比較。只有重新設計介面，把檢索建模為有限動作選擇，才能讓策略在同一狀態下面對可列舉的替代動作，從而產生穩定且可解釋的檢索對比。

**Q4：Harness-G 的圖結構化檢索介面如何重新定義檢索動作？**

A：Harness-G 將傳統的自由格式查詢生成改為有限動作選擇：策略每一步從動作選單中選擇一個證據句、一個實體，或選擇直接作答。環境負責建構選單、追蹤檢索狀態、驗證並執行每個選擇，同時維護一個三部圖（tripartite graph）來組織證據與實體之間的關係。這種設計把開放式語言輸出轉換成離散決策，使相同狀態下的不同選項能夠被直接比較，顯著降低語言混疊。

**Q5：結構化非短視信用分配（SNC）包含哪兩個機制？它們各自解決什麼問題？**

A：SNC 由 frontier-relative credit 與 enablement credit 兩部分組成。前者利用凍結答案評分器與只讀預覽，在同一狀態下比較被選動作與其替代方案，提供局部動作對比；後者則沿軌跡中的依賴關係，將下游增益回傳給較早促成這些結果的橋接動作，解決延遲獎勵問題。兩者結合使 Harness-G 能同時評估當前選擇的相對價值，並表彰為後續成功檢索鋪路的早期決策。

**Q6：為何 Harness-G 選擇「有限動作選擇」而非持續讓模型生成自由查詢？選單設計的關鍵取捨是什麼？**

A：有限動作選擇能消除語言層面的別名問題，讓每一個動作對應到明確的檢索結果，從而提升相同狀態下替代方案的可比性。動作選單由環境根據當前檢索狀態與三部圖動態建構，包含可選的證據句、實體以及終止作答，確保策略不會在無窮的語言空間中迷失。關鍵取捨在於選單必須足夠豐富以涵蓋重要檢索路徑，又不能過大以免增加策略決策負擔與訓練難度。

**Q7：實驗在哪些設定上進行？主要結果是什麼？**

A：作者在六個問答基準測試上評估 Harness-G，這些測試涵蓋多跳推理與開放領域問答任務，並在 1.5B 與 3B 兩種模型規模下進行比較。結果顯示 Harness-G 在兩個規模上都取得最高的平均 F1 分數，分別比最強基線 Graph-R1 高出 10.74 分與 3.98 分。這顯示圖結構化介面與 SNC 的結合能顯著提升搜尋代理的問答表現，尤其在較小模型上優勢更為明顯。

**Q8：動作選單與 SNC 各自帶來多少貢獻？有無控制實驗驗證？**

A：論文進行了控制研究，分別驗證動作選單與 SNC 的貢獻，結果顯示兩者皆對最終性能有正向影響。動作選單透過減少語言混疊與保留更多檢索相異結果，提升了 rollout 群組內的有效檢索對比；SNC 則透過 frontier-relative credit 與 enablement credit 提供更精確的信用分配。雖然摘要未列出各項消融實驗的詳細數字，但明確指出兩項設計各自都能帶來顯著增益。

**Q9：Harness-G 與 Search-R1、Graph-R1 相比，在檢索行為與指標上有何差異？**

A：相較於 Search-R1 的自由查詢介面，Harness-G 的 rollout 群組能保留更多檢索結果相異的軌跡，避免檢索等價崩潰。與 Graph-R1 相比，Harness-G 在六個基準的平均 F1 上於 1.5B 與 3B 規模分別領先 10.74 與 3.98 分。這表示 Harness-G 不只在最終答案正確率上更優，也在檢索決策層面產生了更穩定、可區分的訓練信號。

**Q10：Harness-G 適合應用在哪些實際場景？**

A：Harness-G 特別適合需要多輪外部檢索的知識密集型問答系統，例如法律文獻查詢、醫學診斷輔助、企業內部知識庫搜尋與學術文獻綜述。在這些場景中，答案通常需要串連多個證據片段，而自由查詢介面容易產生語意重複的檢索。Harness-G 的圖結構化介面能讓代理有系統地探索實體與證據句之間的關係，並透過 SNC 學習哪些中間檢索步驟真正有助於最終答案。

**Q11：在產品化部署時，Harness-G 需要考慮哪些工程與設計因素？**

A：首先，環境必須能夠即時建構動作選單並維護三部圖，這對檢索索引、實體連結與狀態追蹤的延遲提出較高要求。其次，選單大小與圖的稀疏度需要權衡：過大的選單會增加策略決策難度與推理成本，過小則可能遺漏關鍵檢索路徑。此外，凍結答案評分器的品質與更新頻率會直接影響 SNC 的準確性，因此需要定期校準或與更強大的評分模型整合。

**Q12：Harness-G 對 RL 搜尋代理與檢索增強生成領域可能帶來什麼影響？**

A：Harness-G 顯示檢索介面設計本身與信用分配機制同樣重要，提醒研究者不應只專注於改進獎勵函數而忽略策略與環境之間的動作空間。它將多跳檢索重新框架為圖上的有限動作選擇，為後續研究提供了一個更結構化、可解釋的訓練範式。這種介面與學習協同設計的思路，也可能啟發其他需要反覆與外部工具互動的強化學習應用，例如程式合成、科學實驗規劃與對話式推薦系統。

**Q13：Harness-G 有哪些可能的限制或假設？**

A：一項主要限制是它依賴環境能夠預先建構或動態維護證據句與實體之間的圖結構，這在開放網路或高度動態的資料來源上可能較難實現。此外，SNC 使用的凍結答案評分器若與最終評估標準不一致，可能會引入偏差或低估某些檢索路徑的價值。最後，動作選單的覆蓋範圍受限於圖的連通性與檢索品質，若關鍵證據未被索引或連結，代理將無法透過選單選取。

**Q14：在什麼情況下 Harness-G 可能會失敗或表現不佳？**

A：當問題所需的關鍵證據句或實體未出現在動作選單中時，代理即使策略正確也無法完成檢索，導致答案錯誤。若凍結答案評分器對某些答案變體過於嚴格或寬鬆，SNC 會給出錯誤的相對信用，進而誤導策略學習。另外，在圖極為稀疏或檢索系統本身品質不佳的資料集上，Harness-G 的優勢可能會被基礎檢索能力的不足所抵消。

**Q15：未來可以朝哪些方向延伸 Harness-G？**

A：未來可將 Harness-G 擴展到即時開放網路檢索，讓環境在每次互動中動態擴充圖結構，而非僅依賴靜態索引。另一方向是讓動作選單具備適應性，根據策略當前的不確定性或問題類型自動調整大小與內容。此外，可探索聯合學習圖建構與策略，或結合更強大的基礎模型與多模態證據，以進一步提升在複雜推理任務上的泛化能力與穩健性。

## 實務應用指南

### 適用場景

1. **企業內部知識庫多跳問答**  
   當問題需要串連多份文件才能回答時，Harness-G 的圖結構化檢索框架可將內部文件、表格與實體關係轉為有限動作選單，避免自由格式查詢生成造成的語言混疊，提升跨部門知識查詢的準確度。

2. **法律與法規遵循研究**  
   法律檢索常需從條文、判例、解釋函中累積證據集合。透過證據句與實體作為可選動作，環境可驗證並執行每個選擇，確保引用的法條與判決確實支撐最終答案，減少幻覺風險。

3. **醫學文獻與臨床證據檢索**  
   在醫學問答中，模型必須從多篇文獻中找出支持或反對某治療方式的證據句。Harness-G 的結構化非短視信用分配（SNC）能將下游增益歸因給較早開啟關鍵文獻的動作，適合需要可追溯證據鏈的場景。

4. **複雜產品文件客服代理**  
   當使用者詢問涉及多個產品規格、相容性或故障排除步驟時，動作選單可將每個文件段落與產品實體變成可選動作，讓搜尋代理在有限狀態空間中進行多輪互動，降低重複檢索與獎勵崩潰。

5. **學術研究輔助工具**  
   針對需要整合多篇論文、作者、實驗結果的開放領域問答，Harness-G 可將論文句子與實體建構成圖，並透過凍結答案評分器提供穩定的中間信用信號，協助研究者快速定位關鍵文獻。

### 實作前置條件

**資料準備**
- 已清洗且可切分的語料庫，例如文件、條文或論文全文。
- 可從語料中抽取的**證據句**與**實體**，並建立其關聯圖。
- 每個問題對應的參考答案或答案評分標準，用於訓練與評估。
- 若使用 SNC，需預先訓練或準備一個**凍結答案評分器**，能對部分軌跡給予穩定分數。

**運算資源**
- 至少具備訓練 1.5B 至 3B 參數語言模型的 GPU 叢集，建議使用多卡 A100/H100。
- 圖建構與檢索索引（如向量資料庫、稀疏檢索器）需額外記憶體與儲存空間。
- 推論階段需部署環境以即時建構動作選單並執行檢索。

**技術能力**
- 熟悉強化學習（RL）與群組相對策略最佳化（如 GRPO）。
- 具備大型語言模型微調與推理框架（如 vLLM、SGLang、Transformers）經驗。
- 熟悉資訊檢索流程，包含文件切分、索引、重排序與證據抽取。
- 能設計與維護圖結構化環境，並將其封裝為 RL 環境介面。

### 實作步驟建議

1. **定義任務與評估指標**  
   明確問題類型（多跳問答或開放領域問答），選定 F1 分數或其他適合的問答基準測試指標，並決定答案形式（抽取式、生成式或選項式）。

2. **建構圖結構化語料**  
   將語料切分為句子或段落，抽取實體，並建立「問題—實體—證據句」的三部圖。確保每個狀態下的動作選單規模可控，避免動作空間過大。

3. **實作 Harness-G 環境**  
   開發環境模組，負責：
   - 根據當前檢索狀態建構動作選單；
   - 驗證並執行每個選擇；
   - 更新累積證據集合；
   - 在選擇答案時呼叫答案評分器或最終答案獎勵機制。

4. **訓練策略模型**  
   使用有限動作選擇重新定義策略-環境介面，讓策略從動作選單中選取證據句、實體或答案。搭配 SNC 進行訓練，利用凍結答案評分器比較選定動作與同狀態替代方案，並將下游增益傳播給較早動作。

5. **評估與對齊**  
   在開發集上監控檢索結果多樣性與組內回報差異，確認未出現檢索等價崩潰。與 Search-R1、Graph-R1 等基線進行比較，分析平均 F1 與各項指標。

6. **部署與持續監控**  
   將訓練好的策略與環境部署為服務，並持續追蹤檢索狀態、動作分佈與答案品質。定期更新圖結構與凍結答案評分器，以適應語料變化。

### 潛在風險與注意事項

- **圖覆蓋率不足**  
  若語料中的關鍵證據句或實體未被納入圖中，動作選單將無法提供正確選項。建議結合自動抽取與人工審核，並保留動態擴充圖的機制。

- **動作選單過大導致訓練不穩定**  
  當每個狀態的可選動作過多時，策略難以學習有效檢索對比。可透過檢索器預先篩選 top-k 候選，或依實體類型分層建構選單。

- **凍結答案評分器的偏差**  
  SNC 依賴凍結答案評分器提供信用信號，若評分器本身對特定答案形式有偏見，將放大錯誤信用。建議在訓練前驗證評分器與人類標註的一致性。

- **延遲與運算成本**  
  每次動作都需要環境建構選單、執行檢索並更新狀態，推論延遲可能高於單次自由查詢。可透過快取熱門實體與證據句、預建索引來降低延遲。

- **獎勵駭入與捷徑行為**  
  策略可能學會選取能騙過答案評分器的證據句，而非真正相關的內容。建議加入答案可解釋性檢查，並監控證據集合與答案之間的邏輯一致性。

### 與其他技術的整合建議

- **與現有 RAG 管線整合**  
  Harness-G 可置於傳統檢索增強生成（RAG）系統之後，作為多輪檢索決策層。向量資料庫負責初篩，Harness-G 負責在圖上進行有限動作選擇與狀態追蹤。

- **與搜尋引擎或企業內部檢索系統整合**  
  環境可呼叫現有搜尋引擎 API 來建構動作選單，並將選定的證據句或實體對應回原始文件，實現與既有搜尋基礎設施的無縫銜接。

- **與工具使用框架整合**  
  可將 Select、Lookup、Answer 三種動作封裝為標準化工具呼叫，讓 Harness-G 成為更廣泛代理系統（如 ReAct、LangGraph）中的一個檢索工具節點。

- **與評估與監控平台整合**  
  將檢索狀態、動作軌跡與 SNC 信用分數輸出到監控儀表板，協助工程師追蹤檢索等價崩潰、組內回報分佈與長期效能趨勢。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從「檢索等價崩潰」與「自由查詢介面」的問題直覺開始，理解為何讓模型自由生成查詢字串會導致語言混疊；接著把 Harness-G 想像成「把開放題變成選擇題」的檢索系統，重點在於環境提供動作選單並追蹤檢索狀態，最後再淺嚐 SNC 如何透過凍結答案評分器給予中間獎勵。

**AI 工程師**  
請聚焦於策略-環境介面的重新設計：如何將語料轉為三部圖、如何實作動作選單的建構與驗證、以及如何將 SNC 嵌入現有 RL 訓練迴路。特別注意動作空間大小、凍結答案評分器的推論成本，以及與現有 RAG 或工具框架整合時的延遲與錯誤處理。

**研究人員**  
本文的核心貢獻在於指出檢索決策層面的效用等價問題，並透過有限動作選擇與結構化非短視信用分配恢復有效檢索對比。建議深入分析檢索結果多樣性與組內回報的關係，並思考 SNC 與其他過程獎勵、資訊增益方法的理論差異，以及在不同圖結構與任務上的泛化性。

**產品經理**  
請將本文視為一個「降低搜尋代理不穩定風險」的設計方案：它透過結構化介面減少幻覺與重複檢索，並以可解釋的動作軌跡提升答案可信度。評估時應關注平均 F1 提升、使用者可接受的延遲、建構與維護圖結構語料的成本，以及與現有客服或知識庫產品的整合難度。
