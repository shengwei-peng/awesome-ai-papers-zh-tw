Clover-35B-A3B-Preview 的方法論核心在於將**混合專家模型 (mixture-of-experts, MoE)** 架構與**區塊擴散 (block diffusion)** 機制進行深度融合，並引入**門控 Delta 網路 (Gated Delta Networks)** 作為序列混合的核心元件。其技術設計可從以下幾個層面進行剖析：

**1. 區塊擴散框架的基礎建構**

Clover 採用吸收式遮罩 (absorbing-mask) 的前向破壞過程 (forward corruption process)，其中每個位置以機率 $\alpha_t$ 保留原令牌，否則被替換為遮罩令牌 $m$。此設計承襲自 D3PM 與 MDLM 的離散擴散 (discrete diffusion) 路線，但透過**區塊化**將生成過程分解為 $B_1, ..., B_K$ 的序列進度 (sequential progress)，並在每個區塊內執行平行去噪 (parallel denoising)。每個區塊 $B_k$ 的條件上下文 $c_k$ 包含提示詞 (prompt) 與先前已完成的區塊，這使得模型能夠在保留自迴歸 (autoregressive) 序列一致性的同時，享有區塊內的平行生成優勢。

**2. 門控 Delta 網路的雙向適配**

Gated Delta Networks 的原始設計採用因果遞迴 (causal recurrence)，透過衰減係數 $\gamma_i$ 與更新係數 $\beta_i$ 控制記憶狀態 $S_i$ 的保留與寫入，並以 delta 規則 (delta rule) 計算新值與檢索值之間的殘差。Clover 的關鍵創新在於**區分已完成歷史 (completed history) 與當前活躍區塊 (active block)**：

- 對於已完成的上下文，維持原本的因果遞迴機制，以遞迴記憶 (recurrent memory) 形式壓縮歷史資訊；
- 對於當前正在去噪的區塊，則改用**雙向 softmax 注意力 (bidirectional softmax attention)**，使區塊內的令牌能夠彼此互動。

**3. 共享 softmax 與歷史記憶讀取的競爭機制**

Clover 最具特色的設計是讓**歷史記憶讀取 (historical memory readout)** 與**當前區塊令牌**在**共享 softmax (shared softmax)** 中競爭。這意味著模型在計算注意力分佈時，歷史資訊並非以獨立鍵值 (key-value) 形式附加，而是直接參與 softmax 的歸一化競爭。這種設計迫使模型學習如何平衡「依賴歷史壓縮表示」與「依賴當前區塊局部上下文」的權重，是一種資訊路由 (information routing) 的端到端學習機制。

**4. 可學習區塊大小校準與右上下文卷積**

模型引入**可學習區塊大小校準 (learnable block-size calibration)**，允許模型在訓練過程中動態調整區塊大小的有效範圍，避免固定區塊大小所帶來的靈活性限制。此外，**零初始化的右上下文卷積分支 (zero-initialized right-context convolution branch)** 是一個獨立的並聯分支，專門處理右側上下文資訊。零初始化 (zero-initialized) 確保訓練初期此分支不影響主路徑輸出，模型可逐步學習是否需要啟用此分支，這是典型的殘差式初始化策略 (residual-style initialization)。

**5. 自推測解碼整合**

Clover 整合了**自推測解碼 (self-speculative decoding)** 機制，類似 DFlash 與 DFlash 2 的設計：擴散式區塊預測提供候選令牌，自迴歸驗證決定可提交的 prefix。這使得同一模型能同時支援擴散解碼、自迴歸解碼與自推測解碼，與 NVIDIA Nemotron-Labs-Diffusion 的設計哲學一致。

## 論文問答

**Q1：為什麼擴散語言模型（DLM）在代理應用中具有吸引力？**
A：擴散語言模型透過迭代去噪重建序列，能夠並行預測多個 token，這種特性使其在生成順序上具有極大的彈性。相較於傳統的自迴歸模型，DLM 在推論效率上具有顯著優勢，特別適合需要反覆與環境互動的代理應用場景。此外，DLM 的並行生成特性使其在處理長序列或複雜任務時，能更有效地利用硬體資源，這對於實際部署至關重要。

**Q2：現有的開放擴散語言模型在代理任務上表現如何？為何需要 Clover？**
A：根據論文的比較，現有的開放擴散語言模型如 LLaDA2.2 flash 和 DiffusionGemma 在 Terminal-Bench 2.1 和 SWE-bench Verified 等代理基準測試上，仍明顯落後於 Qwen 等自迴歸基線模型。雖然這些模型在隔離的推理或程式碼生成任務上表現不錯，但這並不能保證其在儲存庫層級的問題求解中同樣可靠。因此，Clover 的核心動機正是要在保留擴散模型並行生成效率的同時，推進其在代理任務上的能力，使其能與頂級自迴歸模型競爭。

**Q3：為什麼代理應用對擴散語言模型特別具有挑戰性？**
A：代理應用不僅要求模型具備強大的工具使用能力，還需要能夠在反覆的環境互動中維持高效且穩定的生成品質。與單純的文本生成不同，代理任務往往涉及多步驟決策、長程規劃以及對外部系統的操作，這對模型的推理深度和執行效率都提出了更高要求。此外，開放權重的擴散語言模型在這類需要嚴謹可靠性的場景中，仍面臨著如何平衡生成品質與推論速度的挑戰。

**Q4：Clover 如何將 Gated Delta Networks 適配到區塊擴散？**
A：Clover 的核心架構創新在於將 Gated Delta Networks 的遞迴記憶機制與區塊擴散相結合：對於先前已生成的上下文，模型使用遞迴記憶來表示其資訊；而對於當前正在去噪的區塊，則採用雙向 softmax 注意力來處理內部 token 之間的互動。這種設計的關鍵在於，歷史記憶的讀取結果會與當前區塊的 token 在一個共享的 softmax 中競爭，從而實現兩種資訊來源的無縫整合。

**Q5：Clover 架構中還有哪些重要的設計選擇？**
A：除了共享 softmax 的設計外，Clover 還引入了兩個重要的元件：首先是可學習的區塊大小校準機制，使模型能根據任務特性動態調整區塊大小；其次是一個獨立且零初始化的右上下文卷積分支，這個分支在訓練初期不會影響輸出，但隨著訓練進行可以學習捕捉右側上下文的資訊。這些設計共同確保了模型在處理長序列時能夠兼顧效率與品質。

**Q6：為何 Clover 選擇 35B 總參數、3B 啟用參數的混合專家配置？**
A：Clover 採用混合專家（MoE）架構，總參數量約為 350 億，但每個 token 僅啟用約 30 億參數，這種配置在能力與效率之間取得了良好平衡。該架構是基於 Qwen3.6-35B-A3B 的文本骨幹進行改造，使其能夠適配區塊擴散的訓練範式。MoE 的設計不僅維持了模型的強大表達能力，還顯著降低了單次推論的計算成本，這對於需要快速反應的代理應用尤為重要。

**Q7：Clover 在哪些代理基準測試中表現領先？**
A：Clover 在七項代理評測指標中全面領先，其中最引人注目的是在 SWE-bench Verified 上達到 73.6 分，以及在 Terminal-Bench 2.1 上達到 51.7 分。這些基準測試分別評估了模型在軟體工程任務和終端機操作任務上的能力，是衡量代理實用性的重要指標。相較於其他開放擴散語言模型，Clover 的表現證明了其在複雜代理工作流程中的競爭力。

**Q8：Clover 的推論速度表現如何？**
A：在內部代理工作負載上，Clover 使用單張 NVIDIA GB300 GPU，在 BF16 精度、批次大小為一的條件下，實現了每秒 680 個 token 的生成速度。這樣的速度對於需要即時反應的代理應用來說是相當可觀的，能夠支援多輪對話與工具呼叫的流暢進行。論文中特別強調，這個速度是在實際代理任務場景下測得的，而非單純的基準測試，因此更能反映真實部署中的效能。

**Q9：Clover 的決策模型變體有何特色與效益？**
A：Clover 的決策模型變體是一個創新的設計，它能夠在單一去噪過程中同時生成多個相關問題的答案，這充分利用了擴散模型並行生成的優勢。在內部 500 個群組的測試中，這種聯合預測方式將問題準確率從 90.37% 提升至 93.88%，並將全對群組準確率從 65.4% 大幅提升至 77.0%。這個結果顯示，當多個問題之間存在關聯性時，聯合預測能夠利用問題間的相互資訊來提升整體表現。

**Q10：Clover 的實際應用場景有哪些？**
A：Clover 主要針對需要工具使用與環境互動的代理編碼任務，這包括軟體工程問題求解、終端機操作以及儲存庫層級的程式碼修改等場景。其強大的代理能力使其能夠勝任自動化程式碼修復、CI/CD 流程管理、開發環境配置等實際工作。此外，由於其支援思考模式生成，Clover 也適用於需要深度推理的複雜決策任務。

**Q11：Clover 在部署方面有何特殊考量？**
A：Clover 的開發團隊特別強調在消費級裝置上本地運行的基礎設施支援，這對於隱私敏感或離線環境的應用至關重要。為了促進採用，他們釋出了完整的模型權重、監督式微調（SFT）程式碼以及推論引擎，讓開發者能夠靈活地根據自身需求進行調整。論文中還專門評估了在受限記憶體條件下的部署效能，確保模型能在資源有限的環境中正常運作。

**Q12：Clover 對擴散語言模型領域的整體影響是什麼？**
A：Clover 的發表證明了擴散語言模型不僅能在特定任務上表現優異，還能在代理應用等高難度場景中與頂級自迴歸模型競爭，這對推動 DLM 的工業化採用具有重要意義。透過開源模型權重與完整的訓練推論工具鏈，Clover 為研究社群提供了寶貴的資源，有助於加速擴散語言模型技術的迭代與改進。此外，其在 Gated Delta Networks 與區塊擴散結合上的創新，也為未來的架構設計提供了新的思路。

**Q13：Clover 目前存在哪些已知的限制？**
A：作為 Preview 版本，Clover 仍處於持續改進的階段，其推論速度雖然已達到 680 tokens/s，但相較於成熟的商業系統仍有提升空間。此外，模型目前主要專注於文本任務，多模態能力尚未擴展，這限制了其在圖文理解等多媒體場景中的應用。在極長序列處理或高度專業化的領域，Clover 的表現可能也會受到區塊大小設計與訓練資料分布的影響。

**Q14：Clover 在哪些情況下可能表現不佳？**
A：對於需要極長距離依賴或跨區塊精確記憶的任務，Clover 的遞迴記憶機制可能會累積誤差，導致資訊遺失。在高度專業化的垂直領域（如特定科學研究或小眾程式語言），由於訓練資料的分布差異，模型表現可能不如專門微調過的小模型。此外，區塊大小的選擇會影響生成效率與品質的權衡，在某些對延遲極為敏感的即時應用中，可能需要更仔細地調整相關參數。

**Q15：Clover 未來的發展方向是什麼？**
A：根據論文所述，Clover 團隊計劃從三個方向持續改進模型：首先是進一步提升推論速度與整體模型性能，使其能夠在更多場景中實用化；其次是擴展多模態能力，讓模型能夠處理圖像、音訊等多種類型的輸入；最後是持續為擴散語言模型社群的發展做出貢獻，包括分享研究成果、開源工具以及與其他研究者合作。這些方向顯示出 Clover 不僅是一個獨立的模型，更是推動整個 DLM 生態系統發展的重要力量。

**硬體需求**
- 訓練或微調：建議多張 NVIDIA H100/H200 或 GB300 等級 GPU，總顯存至少 280GB（35B 參數 × 8 bytes 訓練狀態）

**資料需求**
- 預訓練資料：通常由模型提供者準備，採用者無需重新預訓練

**技能需求**
- 熟悉 PyTorch 與分散式訓練框架（DeepSpeed、FSDP 或 Megatron）
- 理解擴散語言模型（DLM）與自迴歸模型的差異，特別是去噪過程與平行解碼
- 具備 MoE 架構的部署經驗，理解專家路由與負載平衡
- 熟悉區塊擴散（block diffusion）的區塊大小校準與右上下文卷積概念

在自有硬體上重現論文的關鍵指標：SWE-bench Verified 73.6、Terminal-Bench 2.1 51.7、生成速度 680 tokens/s。若結果有顯著落差，需排查硬體配置、批次大小、精度設定是否與論文一致。

**步驟三：領域微調（可選）**
若通用模型在特定領域表現不足，使用 SFT 程式碼進行微調。建議從小學習率（1e-5 至 5e-6）開始，採用 LoRA 或 QLoRA 以降低記憶體需求。微調時需特別注意區塊大小的設定，因為模型對區塊大小有可學習的校準機制。

**步驟四：推論引擎配置**
根據部署場景選擇合適的解碼策略：
- 追求低延遲：使用較小的區塊大小與較少的去噪迭代
- 追求高品質：使用較大的區塊大小與完整的去噪過程
- 結合自推測解碼（self-speculative decoding）以加速生成

**步驟五：代理框架整合**
將 Clover 整合到代理框架中（如 LangChain、AutoGen、自建框架）。需設計工具呼叫介面、錯誤恢復機制、與環境互動的協議。SWE-bench 場景需要檔案系統操作、測試執行、結果解析等能力。

**步驟六：決策模型變體部署（可選）**
若應用涉及批次關聯問題，部署決策模型變體。需設計問題分組邏輯、聯合預測的 prompt 格式、後處理以拆分各問題的答案。

**步驟七：監控與持續改進**
部署後監控關鍵指標：生成速度、任務成功率、token 使用量、錯誤模式。收集失敗案例用於後續微調或提示工程優化。

### 潛在風險與注意事項

**風險一：擴散模型的輸出不穩定性**
擴散語言模型在去噪過程中可能產生不一致或重複的輸出。緩解方式：使用信心感知平行解碼（confidence-aware parallel decoding），設定信心閾值過濾低品質預測，並實作輸出驗證機制。

**風險二：MoE 架構的負載不平衡**
35B 總參數但僅啟用 3B 的 MoE 架構容易出現專家負載不均，導致部分專家過載、部分閒置。緩解方式：監控專家使用率，必要時加入負載平衡損失或動態路由調整。

**風險三：區塊大小選擇的敏感性**
模型對區塊大小有可學習的校準，但不同任務的最佳區塊大小可能不同。緩解方式：在新任務上進行區塊大小的消融實驗，並考慮使用自適應區塊大小策略。

**風險四：右上下文卷積的零初始化影響**
右上下文卷積分支以零初始化開始，訓練初期可能影響模型表現。緩解方式：給予充分的預熱訓練步數，或在微調時使用較小的學習率避免破壞已學習的權重。

**風險五：硬體需求門檻高**
單張 GB300 才能達到最佳效能，限制了部署彈性。緩解方式：使用量化（INT8、INT4）降低記憶體需求，或採用模型並行在多張消費級 GPU 上部署。

**風險六：代理任務的長尾錯誤**
SWE-bench 與 Terminal-Bench 雖然表現領先，但仍有近 30-50% 的失敗率。緩解方式：設計重試機制、人工審核關鍵決策、收集失敗案例持續改進。

### 與其他技術的整合建議

**與自迴歸模型的混合部署**
在需要極高穩定性的場景，可將 Clover 與自迴歸模型（如 Qwen 系列）並行部署，以自迴歸模型作為備援或驗證層。Clover 的自推測解碼機制也允許在同一模型內結合擴散與自迴歸解碼。

**與程式碼分析工具鏈整合**
將 Clover 接入靜態分析工具（如 ESLint、Pylint）、測試框架（pytest、Jest）、版本控制（Git）形成完整的開發代理生態。SWE-bench 的成功經驗顯示，工具使用能力是代理表現的關鍵。

**與 RAG 系統結合**
對於需要外部知識的任務，將 Clover 與檢索增強生成（RAG）系統整合。Clover 的區塊擴散特性適合處理長上下文，可作為 RAG 的最終生成器。

**與 CI/CD 流程整合**
將 Clover 部署為 CI/CD 流程中的自動化審查者或修復者，特別適合處理測試失敗、程式碼風格問題、依賴衝突等場景。Terminal-Bench 的能力可應用於基礎設施即程式碼（IaC）的自動化維護。

**與多模態系統的銜接**
論文提到將擴展多模態能力，目前可作為純文字代理使用，未來可與視覺理解、語音輸入等模態整合，構建更全面的代理系統。

**與開源代理框架整合**
Clover 可作為 LangChain、AutoGen、CrewAI 等開源代理框架的語言模型後端。需注意這些框架通常預設自迴生成介面，可能需要適配層來處理擴散模型的平行輸出特性。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先閱讀第 1 節（Introduction）了解擴散語言模型的基本概念與動機，再跳過技術細節直接看第 3 節的評測結果，理解 Clover 在實際任務上的表現。重點關注「適用場景」與「實作前置條件」兩節，評估自己的需求是否與 Clover 的能力匹配。不需要深入理解 Gated Delta Networks 或區塊擴散的數學細節。

**給 AI 工程師**
重點閱讀第 2 節（Preliminaries）與第 3.1 節（Model overview），理解遮罩擴散、區塊生成、自推測解碼、門控 Delta 網路的技術細節。特別注意「實作步驟建議」中的推論引擎配置與解碼策略選擇，這些是部署時的關鍵決策點。建議實際運行基準測試驗證硬體效能，並嘗試不同的區塊大小配置。

**給研究者**
重點閱讀第 2.3 節（Gated Delta Networks）與第 3.1 節中關於歷史記憶讀取、共享 softmax、右上下文卷積的描述，這是論文的技術核心創新。將 Clover 的混合架構（遞迴記憶 + 雙向注意力）與現有擴散語言模型（如 LLaDA、Dream）進行比較分析。決策模型變體的聯合預測機制也是值得深入研究的方向。

**給產品經理**
重點閱讀摘要與第 1 節，理解 Clover 的市場定位（代理應用）與相對優勢（領先七項代理指標）。關注「適用場景」中描述的具體業務場景，評估導入的投資報酬率。「潛在風險與注意事項」中的硬體需求與失敗率是制定產品期望的重要參考。建議先以小規模試點驗證效果，再決定是否全面導入。
