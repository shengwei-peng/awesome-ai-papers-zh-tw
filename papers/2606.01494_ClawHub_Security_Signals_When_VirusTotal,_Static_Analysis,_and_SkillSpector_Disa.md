# ClawHub 安全訊號：當 VirusTotal、靜態分析與 SkillSpector 判定分歧時

**原文標題：** ClawHub Security Signals: When VirusTotal, Static Analysis, and SkillSpector Disagree

**發布日期：** 2026-05-31

## ⚡ TL;DR

研究發現代理程式技能安全不能依賴單一掃描器，因不同掃描器存在結構性分歧與盲點。
釋出三類掃描證據之銀標準語料，比較VirusTotal、靜態分析與SkillSpector判定差異。
三種掃描器三重一致性僅0.69%，81.9%標記僅由單一掃描器發出，顯示技能安全需分層治理。

## 摘要翻譯

代理程式技能（Agent skills）以可重複使用的指令、工具、指令碼、參考資料與工作流程擴展 AI 代理程式（AI agents），建立起一個有別於模型安全性（model safety）與傳統套件惡意軟體偵測（traditional package-malware detection）的安全邊界（security boundary）。ClawHub 安全訊號（ClawHub Security Signals）是一個已清理消毒（sanitized）的資料集，收錄 67,453 個最新公開的 OpenClaw 技能版本。每一資料列均將已編修遮蔽（redacted）的 SKILL.md 內容、已清理消毒（sanitized）的捆綁檔案（bundled files）（若有），與最終的 ClawScan 註冊庫裁決（registry verdict）及三類掃描器證據配對：VirusTotal、靜態啟發式分析（static heuristic analysis）與 NVIDIA SkillSpector。

我們並非估計惡意技能盛行率（prevalence），而是研究掃描器之間的分歧。這三個掃描器鮮少標記到相同的技能：任兩者的重疊（overlap）至多佔其合併陽性數（combined positives）的 10.4%，僅有 0.69% 的技能被三者同時標記，而有 81.9% 的被標記技能（flagged skills）是由單一掃描器所識別。此分歧依攻擊面（attack surface）呈現結構化特徵。SkillSpector 發出的是語義化代理風險建議（semantic agentic-risk advisories），而非惡意軟體聲譽訊號（malware-reputation signals）；其在 25,504 筆可疑資料列（suspicious rows）中對 19,209 筆（75.3%）呈現陽性判定（positive），但在 206 筆惡意資料列（malicious rows）中僅對 14 筆（6.8%）呈現陽性判定。惡意裁決區域（malicious-verdict region）則呈現相反特徵：206 筆惡意資料列中有 150 筆（72.8%）為 VirusTotal 陽性判定，這與捆綁程式碼（bundled-code）的惡意軟體證據一致。

這些結果顯示，代理程式技能安全需要分層治理（layered governance），而非單一掃描器的允許／封鎖決策（allow/block decisions）。本語料庫（corpus）以已清理消毒（sanitized）的銀標準資料集（silver-standard dataset）形式釋出：其標籤為註冊庫的自動化裁決（automated verdicts），而非人工標註真實標準（human-annotated ground truth）；此次釋出代表一份早期、具版本控制的快照，旨在支援社群，同時人工標註子集合亦在開發中。我們鼓勵後續研究，包括專為技能安全分級處理（skill-security triage）設計的模型。

### 核心貢獻（3～5點）
- 釋出大規模多訊號資料集：收錄 67,453 個最新公開 OpenClaw 技能版本，將已編修遮蔽的 SKILL.md、已清理消毒的捆綁檔案與 ClawScan 註冊庫裁決及三類掃描器證據（VirusTotal、靜態啟發式分析、NVIDIA SkillSpector）進行配對。
- 量化掃描器分歧：任兩掃描器重疊至多佔合併陽性數的 10.4%，僅 0.69% 技能被三者同時標記，81.9% 被標記技能僅由單一掃描器識別。
- 揭示依攻擊面結構化的分歧特徵：SkillSpector 對可疑資料列高度敏感（75.3% 陽性判定）但對惡意資料列極低（6.8%）；VirusTotal 則在惡意裁決區域佔主導（72.8%），與捆綁程式碼惡意軟體證據一致。
- 提出分層治理主張：代理程式技能安全無法依賴單一掃描器的允許／封鎖決策，而需採取分層治理與分層式系統性防禦。
- 提供社群研究基礎：以已清理消毒的銀標準資料集形式釋出，支援技能安全分級處理等後續研究，並同步開發人工標註真實標準子集合。

### 適合對象
建置 AI 代理程式與技能註冊庫之安全機制的研究者、開發自動化技能驗證流程的資安工程師、關注傳統惡意軟體偵測與語義化代理風險交會領域的威脅分析師，以及從事模型安全性與分層式系統性防禦研究的學術與產業社群。

## 深度分析

#### 方法論解析

本研究的核心方法論並非提出單一偵測演算法，而是建構一個**多訊號信任語料庫（multi-signal trust corpus）**，以系統性量化三種獨立掃描器（scanner families）在面對**代理程式技能（agent skills）**時的結構性分歧。資料集涵蓋 67,453 筆來自 OpenClaw 公開註冊庫的最新技能版本，每筆資料列包含已編修遮蔽（redacted）的 SKILL.md 內容、已清理消毒（sanitized）的**捆綁檔案（bundled files）**（若存在）、ClawScan 的**註冊庫裁決（registry verdict）**，以及三組掃描證據：**VirusTotal**（惡意軟體聲譽訊號，malware-reputation signals）、**靜態啟發式分析（static heuristic analysis）**（Artifact 層檔案特徵）、以及 **NVIDIA SkillSpector**（語義化代理風險建議，semantic agentic-risk advisories）。

作者首先建立一個多層次威脅模型（multifaceted threat model），將**代理程式技能（agent skills）**的風險拆解為三個**攻擊面（attack surface）**：
1. **Artifact layer**：技能套件本身，包含**捆綁程式碼（bundled-code）**、隱藏指令、機密洩漏、不可信安裝來源等；
2. **Tool/MCP layer**：技能期望代理程式使用的工具、API 與 Model Context Protocol（MCP）伺服器，涉及權限委託與工具描述的真實性；
3. **Runtime layer**：代理程式實際執行時的行為，包含文字層與工具呼叫層的落差。

方法論上，三組掃描器被對應至不同層次：VirusTotal 與靜態分析（static analysis）主要覆蓋 Artifact layer，掃描所有容器內檔案；SkillSpector 則深入 Tool/MCP layer，針對技能指令與**能力宣告（capability declarations）**進行語義推理；而 Runtime layer 在本研究中並未被任何掃描器完整觀測。這種分層對應是解釋後續分歧的理論基礎。

在分析技術上，研究採用**弱監督來源（weak-supervision sources）**框架，明確將 ClawScan 的自動化裁決（automated verdicts）視為**銀標準資料集（silver-standard dataset）**，而非**真實標準（ground truth）**。每個標籤的**來源脈絡（lineage）**均被完整揭露，以確保**認識論（epistemics）**上的透明性。量化指標包含原始一致性（raw agreement）、**機會校正一致性（chance-corrected agreement）**、兩兩掃描器在**合併陽性數（combined positives）**上的重疊率（overlap）、**三重一致性（triple-agreement）**，以及**單一掃描器標記（single-scanner flags）**的比例。進一步地，作者執行**條件式裁決分析（verdict-conditioned analysis）**，將樣本依最終裁決分為可疑（suspicious）與惡意（malicious）兩大區域，分別檢視三組掃描器的**陽性判定（positive）**分布，從而揭示分歧並非隨機雜訊，而是與**攻擊面（attack surface）**高度相關的結構性現象。

#### 實驗數據解讀

實驗結果最引人注目的發現是掃描器之間的極低重疊與高度互補性。在 67,453 筆技能中，僅有 468 筆（**0.69%**）同時被三組掃描器標記，即**三重一致性（triple-agreement）**極低；而 **81.9%** 的**被標記技能（flagged skills）**僅由單一掃描器偵測，缺乏**相互佐證（corroboration）**。任兩組掃描器的**重疊（overlap）**至多佔其**合併陽性數（combined positives）**的 10.4%，且僅略高於隨機機率預期。這些數字強烈顯示，若註冊庫採用單一掃描器作為**允許／封鎖決策（allow/block decisions）**的唯一依據，將會完整繼承該掃描器的**盲點（blindspots）**。

然而，分歧並非隨機雜訊，而是呈現清晰的**攻擊面分離結果（surface-separation result）**。在 25,504 筆**可疑資料列（suspicious rows）**中，SkillSpector 的**陽性判定（positive）**高達 19,209 筆（**75.3%**），顯示其對於語義層的異常極為敏感；相對地，在 206 筆**惡意資料列（malicious rows）**中，SkillSpector 僅標記 14 筆（**6.8%**），而 VirusTotal 卻標記了 150 筆（**72.8%**）。這種反向分布（inverse profile）具有關鍵意涵：**惡意裁決區域（malicious-verdict region）**主要由**捆綁程式碼惡意軟體證據（bundled-code malware evidence）**驅動，屬於傳統惡意軟體偵測範疇；而**可疑資料列（suspicious rows）**則由**語義化代理風險（semantic agentic-risk）**主導，涉及指令誘導、能力宣告不實等 Agentic 層次威脅。

這種**訊號量級分離（signal-magnitude separation）**指出，若將三組掃描器的輸出簡化為單一布林值或惡意分數，將會抹除最有價值的結構資訊。對於資安防禦者而言，VirusTotal 的**惡意軟體聲譽訊號（malware-reputation signals）**與 SkillSpector 的**語義化代理風險建議（semantic agentic-risk advisories）**應被視為正交且互補的維度，而非彼此競爭的替代方案。數據亦暗示，現行**傳統套件惡意軟體偵測（traditional package-malware detection）**與新興的 Agentic 風險偵測之間存在顯著的偵測斷層，亟需**分層式系統性防禦（layered, systemic defense）**來銜接。

#### 與現有研究的比較

本研究在學術脈絡中定位為既有文獻的互補（complementary）而非競爭。Guo et al. 提出針對新興技能市集的多代理稽核系統；Li et al. 則貢獻了組態注入（configuration-injection）的威脅分類學與具體案例，這些工作著重於**盛行率（prevalence）**估計與單一偵測方法。相對地，本文首次將註冊庫層級的**自動化裁決（automated verdicts）**與三組獨立掃描器的原始輸出配對，公開量測**多掃描器分歧（multi-scanner disagreement）**，並釋出**銀標準資料集（silver-standard dataset）**供社群檢驗。

在 MCP 與工具層安全方面，既有研究已記錄工具毒化（tool poisoning）、rug-pull 更新攻擊與本地 MCP 伺服器的權限濫用。本研究透過 SkillSpector 的數據，將這些 Tool/MCP layer 的風險從抽象的攻擊分類轉化為可量化的掃描器輸出，並證明此類風險與 Artifact layer 的惡意軟體偵測幾乎不重疊。此外，過往對於 Alexa 等語音助理擴充生態系的研究揭示了市集審查薄弱、權限揭露不全等問題；本文則將類似問題提升至 AI Agent 時代，指出**代理程式技能（agent skills）**作為**可攜式套件（portable bundle）**，其**安全邊界（security boundary）**既不同於**模型安全性（model safety）**，也不同於傳統套件安全。

本研究的主要限制在於其**效度威脅（threats-to-validity）**：標籤來自 ClawScan 的**自動化裁決（automated verdicts）**，屬於**弱監督來源（weak-supervision sources）**，準確度未知；資料集經過**編修遮蔽（redacted）**與**清理消毒（sanitized）**，可能影響部分微觀分析；且 Runtime layer 完全未被觀測，無法捕捉文字安全與工具呼叫安全之間的實際落差。此外，作為早期快照（v1），尚缺乏**人工標註真實標準（human-annotated ground truth）**。

#### 可重現性評估

在可重現性方面，本研究採取部分開放的策略。資料集已於 HuggingFace 公開釋出（`OpenClaw/clawhub-security-signals`），包含 67,453 筆技能的**已編修遮蔽（redacted）**內容、**已清理消毒（sanitized）**的**捆綁檔案（bundled files）**與三組掃描證據，並明確標示為版本化（versioned）的 v1 **銀標準資料集（silver-standard dataset）**。作者對每個標籤的**來源脈絡（lineage）**與**認識論（epistemics）**保持高度透明，這對於第三方進行後設分析或開發**技能安全分級處理（skill-security triage）**模型極具價值。

然而，完整的實驗重現面臨若干障礙。首先，ClawScan 的內部**註冊庫裁決（registry verdict）**邏輯並未在文中完整開源；其次，VirusTotal 為商業 API 服務，其引擎版本與偵測規則隨時間變動，靜態啟發式分析（static heuristic analysis）的具體規則亦未詳細揭露；第三，NVIDIA SkillSpector 作為語義化掃描器，其模型權重、訓練資料與推論細節可能受限於專有授權。因此，雖然**多訊號信任語料庫（multi-signal trust corpus）**本身可作為公共基準（benchmark），但若要完全重現從原始技能到最終裁決的完整**技能驗證流程（skill verification pipeline）**，第三方可能難以在相同條件下複製所有掃描器的內部狀態。整體而言，本研究在資料層面具備良好的可重現性，但在掃描器與裁決系統的演算法層面仍屬部分開放。

#### 未來研究方向

基於本文所揭示的結構性分歧，未來研究可沿以下數個方向展開：

第一，開發**人工裁決後繼版本（human-adjudicated successor）**。由於現行資料集為**銀標準（silver-standard）**，下一步應針對掃描器高度分歧的案例進行過取樣（over-sample），建立**人工標註真實標準（human-annotated ground truth）**，以校準各**弱監督來源（weak-supervision sources）**的實際準確度，並訓練專門的**技能安全分級處理（skill-security triage）**模型。

第二，強化 Runtime layer 的觀測能力。當前掃描器均無法完整觀測代理程式實際執行時的行為，未來應整合沙箱化執行（sandboxed execution）、工具使用遙測（telemetry of tool use）與 Agentic 攻擊基準測試（benchmarks of agentic attacks and defenses），以彌補文字層安全與工具呼叫層安全之間的落差。

第三，推動**分層治理（layered governance）**的具體架構。本文證明單一掃描器不足以支撐**允許／封鎖決策（allow/block decisions）**，未來研究可探索跨層次的中繼分類器（meta-classifier），結合 Artifact layer 的**惡意軟體聲譽訊號（malware-reputation signals）**與 Tool/MCP layer 的**語義化代理風險建議（semantic agentic-risk advisories）**，實現動態風險評分而非二元判定。

第四，實作**簽章（signing）**與供應鏈驗證。文中提及**簽章（signing）**已納入**技能驗證流程（skill verification pipeline）**的設計但尚未實作，未來可建立技能發布者的密碼學身份驗證機制，以降低**能力宣告（capability declarations）**與**捆綁程式碼（bundled-code）**之間的不匹配風險。

第五，擴展至 MCP 伺服器與工具層的縱深防禦。鑑於 SkillSpector 已顯示對 Tool/MCP layer 風險的高度敏感性，未來可針對 MCP 伺服器的工具毒化（tool poisoning）、描述注入與權限提升進行大規模稽核，並將其與技能層的掃描結果進行關聯分析，建構從技能到工具的全鏈路信任評估體系。

## 論文問答

**Q1：這篇論文針對 AI 代理程式技能提出了什麼核心安全問題？**

A：這篇論文指出，代理程式技能作為一種可重複使用的軟體層，其安全邊界既不同於基礎模型安全性，也不同於傳統套件惡意軟體偵測，因而形成了一個獨特且尚未被充分研究的風險範疇。技能套件內含程序性知識、工具使用模式、能力宣告，有時還包含可執行輔助程式碼，使其攻擊面橫跨成品層、工具層與執行階段層。現有的單一偵測工具並未針對這種多層次架構設計，導致註冊庫難以透過傳統方式有效辨識與治理技能相關的複合風險。

**Q2：為何傳統惡意軟體偵測方法（如 VirusTotal）與語義風險分析工具無法單獨確保代理程式技能的安全？**

A：VirusTotal 等傳統掃描器主要運作於成品層，針對捆綁程式碼進行惡意軟體聲譽偵測，而 SkillSpector 則專注於語義化代理風險建議，分析技能在工具／MCP 層的指令與宣告能力。由於代理程式技能的風險分散在技術堆疊的不同層次，單一掃描器只能觀察到特定攻擊面，並繼承該層次的盲點。因此，依賴任何單一掃描器作為決定性依據，都會使註冊庫完全暴露於該工具無法涵蓋的風險之中。

**Q3：相較於估計惡意技能的盛行率，為何研究掃描器分歧更具重要性？**

A：作者認為，單純估計惡意樣本的盛行率會掩蓋代理程式技能風險的結構性本質，因為不同掃描器偵測到的是技術堆疊中截然不同的威脅。量化掃描器分歧能夠揭示：風險並非隨機分布，而是與特定攻擊面緊密相關，且絕大多數標記缺乏相互佐證。這項認識至關重要，因為它直接證明了代理技能安全必須採取分層治理，而非仰賴任何單一掃描器的二元化允許／封鎖決策。

**Q4：本研究的核心方法為何？ClawHub 安全訊號資料集是如何建構的？**

A：研究者彙整了 67,453 個最新公開的 OpenClaw 技能版本，將已編修遮蔽的 SKILL.md 內容與已清理消毒的捆綁檔案，配對至 ClawScan 註冊庫的自動化裁決結果。隨後，他們針對每個技能收集三個獨立掃描器家族——VirusTotal、靜態啟發式分析與 NVIDIA SkillSpector——的偵測證據，以系統性測量其一致性與分歧。該資料集被明確定位為銀標準資料集，每個標籤的來源脈絡均完全公開，而非宣稱其為人工標註真實標準。

**Q5：本研究在掃描器分歧性質上的關鍵創見是什麼？**

A：核心創見在於掃描器分歧並非隨機雜訊或工具缺陷，而是具有結構性的攻擊面分離結果。研究發現，被裁定為惡意的資料列主要由捆綁程式碼的惡意軟體證據所驅動（VirusTotal 陽性率高），而被裁定為可疑的資料列則多與語義化代理風險相關（SkillSpector 陽性率高）。這種訊號量級分離顯示，不同掃描器其實是在觀察同一物件的不同層次，使得它們的分歧本身成為最具參考價值的結構化資訊。

**Q6：作者為何選擇釋出以自動化裁決為基礎的銀標準資料集，而非等待人工標註完成？**

A：由於觀察到的分歧是結構性而非偶發性的，作者認為社群需要及早取得這些多訊號信任語料庫，以直接檢視分歧樣態並開發專用的技能安全分級處理工具。釋出早期版本化快照並明確標示其為弱監督來源，體現了嚴謹的認識論態度：自動化裁決的準確度雖未知，但其來源脈絡完全透明。未來計畫發展人工裁決後繼版本，但當前的銀標準釋出已能支持社群在開發人工標註真實標準的同時，同步推進多訊號分析研究。

**Q7：作者採用了什麼實驗設計來量化三個掃描器之間的分歧？**

A：作者以 67,453 個技能版本為對象，計算 VirusTotal、靜態分析與 SkillSpector 之間的原始一致性與機會校正一致性，並測量任兩個掃描器重疊的合併陽性數比例。實驗進一步以註冊庫裁決結果為條件，分別檢視「可疑資料列」與「惡意資料列」中各掃描器的陽性判定分布。這種條件式裁決分析使研究者能夠區分不同風險類別對應的掃描器訊號特徵，而非僅呈現整體統計數字。

**Q8：本研究最具代表性的量化發現為何？掃描器重疊與專業化呈現什麼樣貌？**

A：三個掃描器極少同時標記同一技能：任兩者的重疊至多僅占其合併陽性數的 10.4%，三重一致性更低至 0.69%，且有 81.9% 的被標記技能僅由單一掃描器偵測到。在 25,504 筆可疑資料列中，SkillSpector 的陽性判定高達 75.3%，但在 206 筆惡意資料列中僅有 6.8%；相對地，VirusTotal 在惡意資料列中的陽性率為 72.8%。這些數據清楚顯示，不同掃描器專精於不同攻擊面，其陽性訊號幾乎無法相互替代。

**Q9：條件式裁決分析如何進一步釐清掃描器訊號與風險類別之間的關係？**

A：透過將資料集依註冊庫的自動化裁決分為可疑與惡意兩群，作者發現兩群呈現出幾乎相反的掃描器輪廓：惡意裁決區域主要由 VirusTotal 捕捉的捆綁程式碼惡意軟體證據所主導，而可疑區域則主要由 SkillSpector 識別的語義化代理風險建議所驅動。這種訊號量級分離證實，註冊庫的自動分類大致對應到不同的技術堆疊層次。若將這些異質訊號強行折疊為單一指標，將會抹除對建構分層式系統性防禦最有價值的結構資訊。

**Q10：技能註冊庫或市場應如何將這些發現應用於實際的內容審核流程？**

A：註冊庫應立即放棄以單一掃描器作為二元化允許／封鎖決策的依據，改為導入分層治理架構，同時納入成品層掃描器與語義層掃描器的訊號。鑑於 81.9% 的被標記技能僅來自單一掃描器，任何只部署一種工具的審核機制都會讓特定類別的風險完全失控。實務上，應將每個掃描器視為觀察特定攻擊面的弱監督來源，並設計能夠綜合多訊號的系統性防禦流程，而非簡單的過濾機制。

**Q11：從不同掃描器觀察技術堆疊不同層次的發現中，可衍生出哪些產品與工程考量？**

A：工程團隊必須在產品設計上區分惡意軟體聲譽訊號與語義化代理風險建議，因為兩者追蹤的是技能截然不同的屬性，不可混為一談。論文提出的技能驗證流程建議在最终裁決前整合多訊號輸入，並規劃未來導入簽章機制以強化信任基礎。此外，由於目前三個掃描器皆未完整觀察執行階段層，產品端必須額外部署沙箱執行或行為遙測，以彌補靜態與語義分析在動態行為驗證上的缺口。

**Q12：這項工作對 AI 代理程式安全與軟體供應鏈治理的廣泛領域有何影響？**

A：本研究確立了代理程式技能是一個獨立於基礎模型與傳統套件管理的軟體層，需要專屬的安全邊界與治理框架。透過釋出首個公開呈現多掃描器分歧的註冊庫規模資料集，它為技能安全分級處理模型與多訊號信任機制提供了實證基礎。作者同時將此議題與 Alexa 技能生態系等歷史擴充套件市場的教訓連結，警示若缺乏分層式系統性防禦，新興的代理程式技能市場將重蹈信任基礎設施不足的覆轍。

**Q13：作者明確承認了哪些主要限制與認識論上的謹慎態度？**

A：作者明確指出，該資料集屬於銀標準資料集，其標籤來自註冊庫的自動化裁決，而非經過人工確認的真實標準，因此每個標籤的準確度均屬未知。他們將每個掃描器都視為準確度不明的弱監督來源，並刻意公開每個標籤的來源脈絡，避免將自動化結果包裝成絕對真理。此外，目前的釋出僅是早期版本化快照，旨在支持社群研究，而非提供最終定論。

**Q14：在這三個掃描器組成的驗證流程中，哪些類型的風險或失效案例很可能被遺漏？**

A：三個掃描器皆未完整涵蓋執行階段層，也就是 AI 代理程式在實際執行技能時的動態行為，這使得依賴執行上下文或動態互動的攻擊難以被靜態偵測。文字層級的安全性並不保證轉移至工具呼叫安全性，因此即使靜態分析與語義分析皆顯示無害，技能仍可能在執行時觸發高風險的代理行為。此外，針對攝取外部內容的技能所進行的間接提示注入，或透過被下毒的 MCP 工具描述發動的攻擊，也可能無法被現行的成品層與語義層掃描器完整捕捉。

**Q15：作者提出了哪些未來研究方向與資料集改進計畫，以填補現有缺口？**

A：作者計畫開發人工裁決後繼版本，針對掃描器分歧案例進行過採樣與人工審判定版，從而逐步超越銀標準的侷限。他們鼓勵後續研究開發專門針對技能安全分級處理的模型，使其能夠最佳化地整合來自多個弱監督來源的異質訊號。未來工作也應探索透過沙箱執行與行為遙測來觀察目前未被檢視的執行階段層，以銜接靜態註冊庫掃描與動態代理風險之間的落差。

## 實務應用指南

### 適用場景

1. **公開技能註冊庫的自動化上架審查**：適用於 OpenClaw 等代理程式技能市集，在技能發布前同步執行 VirusTotal、靜態啟發式分析與 SkillSpector 三軌掃描，避免單一掃描器盲點導致惡意或高風險技能流入生態系。
2. **企業內部 AI 代理程式治理**：當組織內部團隊共用自製技能時，可建立分層治理閘道，區分「捆綁程式碼帶有惡意軟體聲譽訊號」與「語義上存在代理風險」兩類問題，並導向不同的資安複審流程。
3. **資安廠商開發技能專用偵測引擎**：利用本文釋出的 67,453 筆銀標準語料庫，訓練專門針對 SKILL.md 與能力宣告的語義化分類模型，補充傳統防毒軟體在代理程式技能領域的覆蓋缺口。
4. **紅隊演練與攻擊面盤點**：透過三掃描器的結構化分歧（Artifact 層、Tool/MCP 層、Runtime 層的訊號分離），系統性盤點技能在技術堆疊各層的暴露面，而非僅檢查單一維度。
5. **弱監督與多訊號信任語料庫研究**：作為學術研究的銀標準資料集，支援發展結合自動化裁決與多掃描器弱監督來源的模型，特別適合探索掃描器不一致性（disagreement）本身的結構性意義。

### 實作前置條件

- **資料**：須能存取 Hugging Face 上的 `clawhub-security-signals` v1 資料集，包含已編修遮蔽的 SKILL.md 與已清理消毒的捆綁檔案；同時須具備 VirusTotal API、靜態啟發式分析引擎（如 YARA 或自訂規則庫），以及 NVIDIA SkillSpector（或同等 LLM-based 語義分析器）的介接能力。
- **運算資源**：執行靜態分析與檔案解壓縮的 CPU 叢集；執行 SkillSpector 語義推論所需的 GPU（建議 A10/L4 等級以上）；儲存 67,453 筆技能版本與掃描中繼資料的物件儲存空間（建議預留 100GB 以上）。
- **技能門檻**：熟悉 Python 資料處理（pandas/arrow）、OpenClaw bundle 結構、基礎惡意軟體靜態特徵分析（PE/ELF/腳本），以及 MCP/Agent 架構中各層安全邊界的區別。

### 實作步驟建議

1. **建立多層掃描管線**：平行部署 Artifact 層（VirusTotal + 靜態啟發式分析）與 Tool/MCP 層（SkillSpector 語義分析），確保三個掃描器獨立運作、互不干擾，並保留各自的原始訊號量級。
2. **匯入銀標準語料**：從 Hugging Face 載入 v1 資料集，將 SKILL.md 與捆綁檔案還原為結構化分析格式（如 JSONL），同時將 ClawScan 註冊庫裁決作為初始弱監督標籤，但明確標註其為自動化裁決而非人工標註真實標準。
3. **計算分歧矩陣**：針對每一筆技能計算原始一致性與機會校正一致性，識別單一掃描器標記（81.9%）與三重一致性（0.69%）的樣本分佈，建立「惡意裁決區域」與「可疑裁決區域」的風險分群。
4. **設計分層裁決引擎**：避免二元化的允許／封鎖決策。例如：VirusTotal 陽性且捆綁程式碼存在 → 歸入惡意裁決區域；SkillSpector 陽性但其他兩者陰性 → 歸入可疑裁決區域並觸發人工複審。
5. **建構爭議案例複審佇列**：針對掃描器分歧樣本（特別是 SkillSpector 與 VirusTotal 結果互斥者）建立優先審查佇列，作為未來人工裁決後繼版本的種子資料，並記錄每筆標籤的來源脈絡。
6. **持續監控與回饋**：將註冊庫裁決結果與三掃描器訊號量級分離趨勢納入儀表板，定期重新校準靜態啟發式規則與 SkillSpector 的語義提示詞，以反映技能生態系的演變。

### 潛在風險與注意事項

- **銀標準限制**：v1 標籤為 ClawScan 自動化裁決，非人工標註真實標準。若直接將其作為 ground truth 訓練監督式模型，可能放大註冊庫自身的系統性偏誤，建議僅作為弱監督來源使用。
- **單一掃描器盲點**：若僅以 VirusTotal 作為上架閘道，將遺漏 75.3% 的可疑語義代理風險；若僅依賴 SkillSpector，則會放行 72.8% 的捆綁程式碼惡意軟體。任何單一掃描器的允許／封鎖決策都會繼承其完整盲點。
- **清理消毒造成的證據滅失**：資料集已清理消毒，實際部署時須確保原始捆綁檔案在隔離沙箱中分析，避免惡意程式碼在掃描節點意外執行。
- **攻擊面混淆**：勿將模型安全性（model safety）與技能安全性（skill security）混為一談。基礎模型對齊並無法防禦透過 SKILL.md 進行的間接提示注入，兩者屬於不同的安全邊界。
- **低三重一致性的誤解**：0.69% 的三重一致性不代表掃描器「不準」，而是反映不同層次攻擊面的結構化分歧。決策者應將此視為分層式系統性防禦的必要證據，而非汰換掃描器的理由。

### 與其他技術的整合建議

- **CI/CD 整合**：將三掃描器管線嵌入技能提交前的持續整合流程，作為合併請求（MR）的強制檢查關卡，並依據分層裁決結果決定阻擋、警告或放行。
- **SIEM/SOAR**：將掃描結果（VirusTotal 聲譽、靜態啟發式觸發規則、SkillSpector 語義風險類別）以結構化日誌輸出至企業資安資訊事件管理系統，關聯現有端點偵測回應（EDR）警報，形成跨層次關聯分析。
- **MCP 安全層**：在 Tool/MCP 層部署額外的工具描述驗證與權限邊界檢查，彌補 SkillSpector 僅分析宣告能力、無法觀測 runtime 實際行為的缺口。
- **傳統套件掃描器**：對捆綁檔案中的輔助程式碼，可疊加現有套件生態系（如 npm、PyPI）的漏洞掃描與依賴檢查工具，強化 Artifact 層覆蓋率。
- **人工複審工單系統**：對單一掃描器標記（81.9%）自動開立資安複審工單，並針對惡意裁決區域與可疑裁決區域設置不同的服務等級協議（SLA），確保高風險樣本優先處理。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從「2.1 什麼是代理程式技能」與詞彙表開始，理解 SKILL.md、捆綁檔案與 AI 代理程式的關係。重點掌握「為何不能只用防毒軟體檢查技能」這一核心概念，無需深入統計細節。
- **AI 工程師**：聚焦第 4–6 節的掃描器管線架構與分歧量化方法。注意 SkillSpector 的語義化代理風險建議與 VirusTotal 的惡意軟體聲譽訊號在資料格式與延遲上的差異，並參考第 13 節的分層治理建議設計實際的允許／封鎖決策邏輯。
- **研究人員**：仔細閱讀第 3、10、11 節的效度威脅與資料集定位。本文的銀標準特性與弱監督來源設計是方法論核心，建議以「掃描器分歧」而非「惡意盛行率」作為研究問題，並利用釋出的語料庫發展專門針對技能安全分級處理（skill-security triage）的模型。
- **產品經理**：關注摘要與第 6、7 節的條件式裁決分析。重點在於向利害關係人溝通：三掃描器的低重疊率是「分層防禦的必要性」而非「產品缺陷」，並據此規劃從自動化銀標準過渡到人工裁決後繼版本的產品路線圖與資源配置。
