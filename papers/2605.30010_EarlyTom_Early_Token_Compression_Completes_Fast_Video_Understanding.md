# EarlyTom：早期標記壓縮實現快速影片理解

**原文標題：** EarlyTom: Early Token Compression Completes Fast Video Understanding

## ⚡ TL;DR

現有影片大型語言模型的視覺編碼器處理大量標記造成推論延遲，且既有壓縮方法未能優化此瓶頸。
本文提出EarlyTom，在視覺編碼器內部進行早期幀合併與解耦式空間標記選擇，無需訓練即可壓縮標記。
EarlyTom將首標記時間縮短2.65倍、運算量降61%，並維持全標記基線的準確度。

## 摘要翻譯

影片大型語言模型（Video-LLMs）在影片理解（video understanding）任務中展現出強大的能力。然而，處理大量視覺標記（visual tokens）所帶來的低效率，仍阻礙其實際部署（practical deployment）。儘管近期方法能在維持與全標記基線（full-token baselines）相當準確度（accuracy）的同時，達到極低的標記保留率（token retention ratios），但大多數方法僅於預填充（prefilling）後期階段（late stage of prefilling）進行壓縮，導致視覺編碼器（vision encoder）的效率未能最佳化。本文首先揭示，視覺編碼（vision encoding）在首標記時間（time-to-first-token, TTFT）中佔有相當大的比重。因此，相較於僅在視覺編碼器後方壓縮視覺標記，在編碼器內部進行壓縮仍具有相當大的探索空間。基於此洞察，我們提出 EarlyTom，一個免訓練（training-free）的標記壓縮（token compression）框架，在視覺編碼器內部進行早期視覺標記壓縮（early-stage visual token compression），從而顯著降低 TTFT 並提升吞吐量（throughput）。此外，我們引入解耦式空間標記選擇策略（decoupled spatial token selection strategy），以提升整體壓縮效益（compression effectiveness）。EarlyTom 在單張 NVIDIA A100 GPU 上針對 LLaVA-OneVision-7B 模型，最高可帶來 2.65 倍的 TTFT 縮短效果，並將浮點運算次數（FLOPs）最高減少 61%，同時維持與全標記基線（full-token baseline）相當的準確度（accuracy）。這些改進大幅提升 Video-LLMs 在真實世界（real-world）生產場景（production scenarios）中部署的實用性。

## 深度分析

#### 方法論解析

本文的核心洞察來自於對首標記時間（Time-to-First-Token, TTFT）組成的延遲剖析（Latency Profiling）。作者發現，在現有的影片大型語言模型（Video-LLMs）推論流程中，視覺編碼器（Vision Encoder）往往佔據了 TTFT 的顯著比例——在基線（Baseline）方法中佔 36.3%，而在部分先進方法（如 VisionZip 與 HoliTom）中甚至攀升至 68.4% 與 55.8%。這意味著僅在預填充（Prefilling）後期、投影層（Projector）之後或大型語言模型（Large Language Model, LLM）內部進行標記壓縮（Token Compression），並無法有效解決視覺編碼（Vision Encoding）階段本身的運算瓶頸。因此，EarlyTom 將壓縮時機「前移」，提出早期標記壓縮（Early-Stage Visual Token Compression）機制。

EarlyTom 框架包含兩大核心組件：

1. **視覺編碼器內部幀合併（Inner Vision Encoder Frame Merging）**：此為免訓練（Training-Free）機制，直接在視覺編碼器（Vision Encoder）的內部層級中執行幀合併（Frame Merging）。透過在編碼過程中即合併時間與空間維度上的冗餘視覺標記（Visual Tokens），避免大量冗餘資訊被傳遞至後續的投影層（Projector）與 LLM，從而從源頭降低浮點運算次數（FLOPs）與記憶體搬移成本。

2. **解耦式空間標記選擇策略（Decoupled Spatial Token Selection Strategy）**：此策略與上述幀合併機制在系統層級（System Level）進行協同設計，進一步針對空間維度篩選關鍵標記。其「解耦」特性在於將時間壓縮與空間選擇分開處理，避免傳統方法中因耦合決策而引入的偏差（Bias），並以極低的額外延遲開銷達成更高的壓縮效益（Compression Effectiveness）。

整體而言，EarlyTom 並非僅是演算法層面的改進，而是針對推論效率（Inference Efficiency）進行的全系統最佳化：透過在視覺編碼器（Vision Encoder）早期階段即完成主要壓縮，顯著縮短 TTFT，並提升吞吐量（Throughput）。

#### 實驗數據解讀

作者以 LLaVA-OneVision-7B 為基礎模型，在單張 NVIDIA A100 GPU 上進行評估，並於四個廣泛使用的影片理解（Video Understanding）基準測試（Benchmarks）—— MVBench、EgoSchema、LongVideoBench 與 VideoMME —— 上驗證效能。

關鍵數據如下：

*   **首標記時間（TTFT）**：在僅保留 10% 標記保留率（Token Retention Ratios）的設定下，EarlyTom 實現了高達 **2.65 倍** 的 TTFT 降低。這直接證明了在視覺編碼器（Vision Encoder）內部進行早期壓縮，對於縮短推論延遲具有決定性作用。
*   **浮點運算次數（FLOPs）**：相較於全標記基線（Full-Token Baseline），FLOPs 降低達 **61%**，顯示此方法在運算量削減上極具成效。
*   **吞吐量（Throughput）**：達到 **1.3 倍** 的加速，對於需要高並發處理的真實世界（Real-World）生產場景（Production Scenarios）而言，具有直接的實務價值。
*   **準確度（Accuracy）**：在大幅壓縮的情況下，EarlyTom 於四大基準測試（Benchmarks）上的平均準確度（Accuracy）與全標記基線（Full-Token Baseline）維持相當水準（圖一右側散佈圖顯示 EarlyTom 位於效能與效率權衡的最前沿，達到最先進的（State-of-the-Art）表現）。

這些結果共同說明：透過早期標記壓縮（Early Token Compression），可以在不犧牲下游任務品質的前提下，突破現有方法僅優化 LLM 階段所面臨的效率天花板。

#### 與現有研究的比較

本文將現有標記壓縮方法分為三大類，並明確定位 EarlyTom 的優勢與差異：

**1. 相較於編碼器內部壓縮方法（Intra-Encoder Token Compression）**  
諸如 ToMe、PiToMe、VisionZip、LLaVAPruMerge 等方法，雖然已在視覺編碼器（Vision Encoder）或投影層（Projector）內嘗試合併或篩選標記，但它們多半仍是在編碼過程的較後期才進行壓縮，或未與系統層級的延遲最佳化深度結合。EarlyTom 則更進一步將壓縮時機推進至編碼器內部的「早期階段」，並透過解耦式空間標記選擇策略（Decoupled Spatial Token Selection Strategy）降低額外開銷，因此在 TTFT 改善上更為顯著。

**2. 相較於預填充（Prefilling）後期與 LLM 內部壓縮方法**  
FastV、SparseVLM、PyramidDrop 等方法專注於 LLM 預填充（Prefilling）階段或解碼階段的標記壓縮。這類方法雖能降低 LLM 部分的運算量，但對於視覺編碼（Vision Encoding）所耗費的大量時間無能為力，因此對 TTFT 的改善相對有限。EarlyTom 正是填補了這一空白，直接攻擊視覺編碼器（Vision Encoder）造成的延遲瓶頸。

**3. 相較於混合式方法（Hybrid Approaches）**  
HoliTom、FastVID、DyCoke 等嘗試結合多階段壓縮管線，但根據本文的延遲剖析（Latency Profiling），它們仍舊未能充分解決視覺編碼器（Vision Encoder）的效率問題，甚至因額外的計算開銷而讓 TTFT 問題更加惡化。EarlyTom 以單一且輕量的早期壓縮框架，避免了複雜多階段管線所帶來的系統開銷。

**限制（Limitations）**  
儘管成效顯著，目前實驗主要集中於 LLaVA-OneVision-7B 單一模型架構，其在其他視覺編碼器（Vision Encoder）或不同規模的影片大型語言模型（Video-LLMs）上的泛化性仍需更多驗證。此外，免訓練（Training-Free）的設計雖然利於部署，但固定規則的幀合併（Frame Merging）與空間選擇在面對極端複雜或高度動態的影片內容時，可能不如學習式方法具備足夠的適應性；過度壓縮亦可能對需要細粒度空間細節的任務構成潛在風險。

#### 未來研究方向

基於 EarlyTom 的貢獻與現有框架，以下為幾個具潛力的後續研究方向：

1. **跨架構泛化與驗證**：將早期標記壓縮（Early Token Compression）框架擴展至其他視覺編碼器（Vision Encoder）架構（如 SigLIP、EVA-CLIP、DINOv2）以及不同參數規模的影片大型語言模型（Video-LLMs），驗證其通用性與擴展性。

2. **全鏈路多階段協同壓縮**：結合 EarlyTom（專注於視覺編碼器階段）與 LLM 內部的標記壓縮技術（如 FastV、SparseVLM），設計從視覺編碼（Vision Encoding）、投影層（Projector）到 LLM 預填充（Prefilling）的全鏈路最佳化策略，探索效率與準確度（Accuracy）的極限權衡。

3. **自適應標記保留率（Adaptive Token Retention Ratios）**：目前方法採用固定的壓縮比例，未來可設計依據影片內容複雜度、時間冗餘度或任務需求動態調整標記保留率（Token Retention Ratios）的機制，以在靜態場景與高度動態場景之間自動取得最佳平衡。

4. **輕量級學習增強**：在維持免訓練（Training-Free）部署優勢的前提下，探索輕量級的偏好微調（Preference Tuning）或增強式學習，讓幀合併（Frame Merging）與空間選擇的決策能夠根據特定領域資料進行少量適應，進一步提升壓縮效益（Compression Effectiveness）。

5. **邊緣裝置與生產場景部署最佳化**：針對記憶體與運算資源更受限的邊緣裝置（如行動裝置、嵌入式系統）進行系統層級的最佳化，推動 Video-LLMs 在真實世界（Real-World）生產場景（Production Scenarios）中的大規模實際部署（Practical Deployment）。

## 論文問答

**Q1：影片大型語言模型在實際部署時面臨的主要效率挑戰是什麼？**
A：影片大型語言模型（Video-LLMs）在處理連續影像時必須應對巨量的視覺標記，導致推論過程中的運算成本極為高昂。根據延遲剖析結果，視覺編碼階段消耗了整體首標記時間（TTFT）的相當大比例，成為模型回應速度的主要瓶頸。這種低效率使得Video-LLMs難以直接應用於需要即時反應的真實世界生產場景。

**Q2：現有的標記壓縮方法為何無法有效解決影片大型語言模型的推論延遲問題？**
A：現有的大多數方法僅在預填充的後期階段或大型語言模型內部進行標記壓縮，導致視覺編碼器本身的效率始終未被最佳化。研究顯示，在部分最先進的方法中，視覺編碼甚至佔據了高達55.8%至68.4%的TTFT，這意味著壓縮發生得太晚，無法減輕編碼器的沉重負擔。此外，許多現有方法在壓縮過程中引入了顯著的額外運算開銷，反而進一步拖慢了整體推論速度。

**Q3：為何降低首標記時間（TTFT）對於影片大型語言模型的實用性至關重要？**
A：TTFT衡量的是從使用者送出請求到模型生成第一個回應標記所需的等待時間，直接影響互動體驗的流暢度。在計算資源受限的應用中，例如大規模影片檢索系統，過長的TTFT會嚴重限制服務的即時反應能力與整體吞吐量。因此，有效縮短TTFT不僅是提升推論效率的關鍵，更是決定Video-LLMs能否成功部署於實際生產環境的核心因素。

**Q4：EarlyTom的核心設計理念是什麼？它與傳統壓縮方法的主要差異為何？**
A：EarlyTom提出了一種免訓練的早期標記壓縮框架，其核心創新在於將壓縮操作從傳統的預填充後期前移到視覺編碼器內部進行早期視覺標記壓縮。具體而言，它透過視覺編碼器內部幀合併機制，在編碼過程中即時壓縮冗餘的視覺資訊，從而從源頭減少運算量。這與僅在視覺編碼完成後或語言模型內部才處理標記的傳統方法有著本質區別，能夠更有效地削減TTFT。

**Q5：EarlyTom提出了哪些關鍵創新來提升壓縮效益與推論效率？**
A：除了早期壓縮外，EarlyTom還引入了解耦式空間標記選擇策略，該策略能夠在系統層面進一步減少視覺標記數量，同時最小化額外的延遲開銷。這種設計避免了傳統壓縮方法可能引入的偏差，確保在大幅提升效率的同時維持模型準確度。透過將編碼器內部幀合併與空間選擇相結合，EarlyTom實現了高達2.65倍的TTFT縮短與61%的浮點運算次數降低。

**Q6：為何EarlyTom選擇採用「免訓練」與「早期壓縮」的設計策略？**
A：採用免訓練策略意味著該框架可以直接應用於現有的預訓練模型，無需耗費大量運算資源進行微調或重新訓練，這大幅降低了實際部署的門檻與成本。而早期壓縮的設計則是基於延遲剖析的關鍵發現：視覺編碼階段是TTFT的主要瓶頸，因此只有在編碼器內部進行壓縮才能從根本上削減運算負擔。這兩項設計選擇共同確保了EarlyTom在真實生產環境中的實用性與即插即用的便利性。

**Q7：本研究在哪些基準測試上評估EarlyTom的效能？使用了什麼模型與硬體設定？**
A：研究選擇了四個廣泛使用的影片理解基準測試，包括MVBench、EgoSchema、LongVideoBench與VideoMME，以全面評估模型的理解能力。實驗採用LLaVA-OneVision-7B模型作為骨幹，並在單張NVIDIA A100 GPU上進行推論效率的測量。這樣的設定涵蓋了準確度與效率的雙重評估，能夠充分驗證EarlyTom在實際硬體環境中的表現。

**Q8：EarlyTom在推論效率與模型準確度方面達成了哪些具體成果？**
A：在僅保留10%標記的情況下，EarlyTom成功將TTFT降低最高達2.65倍，並將浮點運算次數減少最高達61%，同時吞吐量提升了1.3倍。在準確度方面，EarlyTom在多項基準測試上的平均表現與全標記基線相當，維持了具有競爭力的影片理解品質。這些結果顯示，EarlyTom成功打破了效率與準確度之間的傳統權衡，達成了最先進的效能表現。

**Q9：從論文中的實驗數據來看，不同壓縮組件對整體準確度的影響為何？**
A：根據圖一所示的各組件平均準確度數據，解耦式空間選擇與分詞器均達到58.2的平均分，而僅使用幀合併則降至54.1，顯示單獨的早期幀合併雖能有效降低運算量，但可能對準確度造成較大影響。然而，當結合空間選擇等策略後，整體系統能夠在大幅壓縮標記的同時，將平均準確度恢復至與全標記基線相近的水準。這證明了EarlyTom的多階段壓縮設計具有互補性，能夠彌補單一組件的不足並提升整體壓縮效益。

**Q10：EarlyTom的設計特別適合哪些實際應用場景？**
A：EarlyTom特別適合需要快速回應與高吞吐量的計算密集型應用，例如大規模影片檢索系統、即時影片分析與監控平台，以及需要處理長影片內容的互動式對話系統。在這些場景中，TTFT的長短直接影響使用者體驗與系統的即時處理能力。由於EarlyTom能顯著降低TTFT並提升吞吐量，它使得在資源有限的生產環境中部署高效能Video-LLMs成為可能。

**Q11：在實際產品部署時，EarlyTom相較於其他方法具備哪些優勢？**
A：作為一個免訓練框架，EarlyTom可以直接整合至現有的Video-LLM推論管線中，無需額外的模型訓練或微調成本，這對於追求快速上線與低維護成本的產品團隊極具吸引力。此外，它在單張NVIDIA A100 GPU上即可實現顯著的TTFT縮短與FLOPs降低，代表企業無需大規模擴充硬體就能提升服務效率。這種即插即用的特性與硬體友好性，大幅增強了Video-LLMs在真實生產場景中的實用性。

**Q12：EarlyTom對影片大型語言模型領域可能帶來什麼樣的影響與貢獻？**
A：EarlyTom挑戰了傳統上將壓縮焦點放在語言模型階段的慣例，證明了在視覺編碼器內部進行早期壓縮是突破TTFT瓶頸的關鍵方向。這項工作為後續研究開闢了新的探索空間，促使學界與業界重新審視視覺編碼階段的最佳化潛力。透過在不犧牲準確度的前提下大幅提升推論效率，EarlyTom推動了Video-LLMs從實驗室研究走向實際大規模應用的進程。

**Q13：根據論文內容，EarlyTom或現有方法可能存在哪些潛在的限制？**
A：從實驗數據觀察，單獨使用幀合併策略時平均準確度下降至54.1，顯示過度依賴早期壓縮可能在某些任務上導致細微的視覺資訊遺失。此外，目前的研究主要基於LLaVA-OneVision-7B單一模型架構進行驗證，其在其他規模或架構的Video-LLMs上的通用性仍需更多實驗支持。這些因素意味著在極端壓縮率或特定複雜影片內容的場景下，系統可能面臨準確度與效率之間更嚴峻的權衡。

**Q14：哪些情況下EarlyTom的壓縮策略可能面臨挑戰或表現較差？**
A：當影片內容包含快速變化的場景、細微的時間動態或需要精確幀級別理解的任務時，過早的幀合併可能會模糊關鍵的時間邊界資訊，導致模型誤判。例如，在僅採用幀合併而缺乏後續空間選擇輔助的情況下，準確度明顯低於完整框架。這暗示對於高度依賴時間解析度的影片理解任務，單純的早期壓縮可能不足以保留所有必要的語義資訊。

**Q15：基於EarlyTom的研究成果，未來可以朝哪些方向進一步發展？**
A：未來研究可以探索將早期壓縮機制擴展至更多樣化的視覺編碼器架構，並針對不同長度與類型的影片內容設計自適應的壓縮率調整策略。此外，結合其他層級的壓縮技術，例如投影層最佳化或語言模型內部的動態快取剪枝，有望進一步推升整體推論效率。最後，開發能夠根據任務難度與影片內容複雜度自動平衡壓縮強度的智慧調度機制，也是值得深入探索的方向。

## 實務應用指南

### 適用場景

1. **即時影片客服與智慧監控**：銀行、電商或公共安全領域的即時影片問答與異常事件偵測，需在 1 秒內回應，EarlyTom 透過降低首標記時間（TTFT）滿足低延遲需求。
2. **邊緣裝置影片摘要**：在工廠巡檢機器人或車載系統上部署 Video-LLM，受限于功耗與記憶體，利用早期標記壓縮減少 61% 浮點運算次數（FLOPs），使 7B 級模型可在單卡 A100 甚至邊緣 GPU 上運行。
3. **大規模影片內容審查與檢索**：短影音平台或雲端儲存服務需批次處理海量影片，透過提升吞吐量與降低單片成本，實現高性價比的內容理解管線。
4. **直播串流即時互動**：教育或娛樂直播中，觀眾上傳影片片段並即時提問，EarlyTom 可在視覺編碼器階段先壓縮冗餘幀，避免預填充後期才壓縮造成的瓶頸。
5. **多模態自動駕駛感知**：車輛需快速理解連續視訊流以進行決策，視覺編碼器內部幀合併能減少時序冗餘，同時維持與全標記基線相近的準確度。

### 實作前置條件

- **運算資源**：至少一台配備 NVIDIA A100 GPU（80 GB）的伺服器，用於重現論文基準與部署；若為邊緣場景，建議先於 A100 完成參數調校，再轉譯至目標硬體。
- **模型與程式碼基礎**：需具備 LLaVA-OneVision-7B 或相容架構（含 ViT 視覺編碼器與投影層）的推論環境，以及 EarlyTom 官方釋出的免訓練壓縮模組。
- **資料準備**：目標領域的驗證影片集（建議涵蓋不同解析度與幀率），並準備 MVBench、VideoMME 等基準測試資料以進行準確度回歸測試。
- **技術能力**：熟悉 PyTorch 中間層（hook）操作以插入幀合併邏輯、理解注意力圖（attention map）與多頭自注意力機制，並具備 CUDA 推論優化經驗。
- **系統環境**：CUDA 11.8+、Python 3.9+、Transformers 函式庫，以及 vLLM 或 Triton Inference Server 等推論服務框架（若需整合至生產環境）。

### 實作步驟建議

1. **基線剖析**：先部署全標記基線模型，使用 nsys 或 PyTorch Profiler 量化 TTFT 組成，確認視覺編碼器確實佔總延遲 35% 以上，驗證優化空間。
2. **插入早期壓縮模組**：在視覺編碼器內部（如 ViT 的中間層）整合 EarlyTom 的幀合併機制，無需修改預訓練權重，透過特徵空間相似度合併連續冗餘幀。
3. **導入解耦式空間選擇**：於編碼器輸出端加入空間標記選擇策略，將壓縮率逐步調降至 10%，並觀察下游任務準確度變化。
4. **系統層級共設計**：調整投影層（Projector）與 LLM 預填充階段的批次大小（batch size），確保 EarlyTom 節省的 TTFT 不會被後續管線阻塞抵銷。
5. **端到端驗證**：於 MVBench、EgoSchema、LongVideoBench、VideoMME 執行準確度測試，確認平均表現與全標記基線差距在 1% 以內；同時測量 TTFT 與吞吐量，目標達成 2 倍以上加速。
6. **生產化部署**：將修改後的視覺編碼器封裝為 ONNX 或 TensorRT 引擎，整合至現有推論服務，並建立動態保留率開關，依據請求優先級（即時 vs 離線）切換壓縮強度。

### 潛在風險與注意事項

- **細粒度動作遺失**：幀合併可能平滑快速動作或微小物體的特徵，建議在體育分析、工業瑕疵檢測等場景保留較高標記保留率（如 15–20%），或搭配光流法預篩選關鍵幀。
- **推論引擎相容性**：部分編譯式加速框架（如 TensorRT）對動態形狀（dynamic shape）支援有限，若標記數量在編碼器內變化，需確認客製化算子可正確編譯，或改用固定壓縮比例。
- **極端壓縮下的偏差**：雖然論文顯示 10% 保留率仍維持準確度，但特定長尾任務（如需要閱讀影片內文字或辨識罕見手勢）可能衰退，務必以領域資料進行回歸測試。
- **記憶體頻寬陷阱**：EarlyTom 減少 FLOPs，但若幀合併操作引入過多 GPU 記憶體搬移，可能抵銷運算節省效益，建議使用融合式核心（fused kernel）實作合併邏輯。

### 與其他技術的整合建議

- **與 LLM 推論引擎疊加**：EarlyTom 負責視覺編碼器階段壓縮，可與 vLLM、TensorRT-LLM 或 SGLang 搭配，將節省下的 TTFT 轉化為更高的連續批處理（continuous batching）吞吐量。
- **串接後期壓縮方法**：在 EarlyTom 將標記壓至 10% 後，可於 LLM 預填充階段再導入 FastV 或 PyramidDrop 進行二次篩選，形成「編碼器內早期壓縮 → LLM 前晚期壓縮」的雙層加速管線。
- **結合影片前處理**：於進入視覺編碼器前，先以輕量場景轉換偵測（scene detection）或鏡頭切換偵測模組分群，使 EarlyTom 的幀合併更精準，避免跨場景錯誤合併。
- **模型量化與編譯**：將 EarlyTom 整合後的模型進行 INT8/FP8 量化與編譯，進一步放大 FLOPs 降低帶來的延遲優勢，特別適合雲端大規模部署。

### 給不同背景讀者的閱讀建議

- **初學者**：請先理解「首標記時間（TTFT）」與「吞吐量」這兩個推論效率指標，並建立「視覺編碼器 → 投影層 → 大型語言模型」的基本管線概念；EarlyTom 的核心價值在於「免訓練即可加速」，您只需將它想像成在影片進入 AI 大腦前，先由一位高效的剪輯師刪除冗餘畫面，而不需要重新訓練整個模型。
- **AI 工程師**：重點關注第 3 節的延遲剖析與第 4 節的幀合併實作細節，特別是如何在不改變預訓練權重的情況下，於 ViT 中間層插入基於注意力相似度的合併邏輯；同時留意解耦式空間選擇的系統層級設計，這是實際上線時維持準確度的關鍵，建議搭配 Profiler 驗證記憶體頻寬是否成為新瓶頸。
- **研究人員**：本文的學術貢獻在於挑戰「標記壓縮僅能在預填充後期或 LLM 內部進行」的既有假設，證明視覺編碼器內部仍存在巨大優化空間；建議深入分析幀合併與空間選擇的協同機制，並思考如何將此早期壓縮概念擴展至其他模態（如音訊或 3D 點雲）或更高效的編碼器架構（如 Mamba 或狀態空間模型）。
- **產品經理**：EarlyTom 在單張 A100 上實現 2.65 倍 TTFT 降低與 61% FLOPs 削減，意味著相同的影片理解服務可減少超過一半的 GPU 叢集成本，或讓原本無法即時化的產品（如直播互動問答）變得可行；由於方法為免訓練，導入時無需承擔模型重新訓練的時程與資料成本，是短期內提升 Video-LLM 產品競爭力的高 CP 值選項。
