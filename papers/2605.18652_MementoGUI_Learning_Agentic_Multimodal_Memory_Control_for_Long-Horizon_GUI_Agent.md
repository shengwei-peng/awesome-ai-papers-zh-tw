## ⚡ TL;DR

長期 GUI 任務中，現有代理因冗餘截圖或純文字記憶而遺失關鍵視覺證據。
本文提出 MementoGUI，以學習型控制器線上管理多模態工作與情節記憶，無需微調骨幹。
於多項基準測試中，MementoGUI 顯著提升凍結骨幹的任務成功率與動作匹配並優於基線。

## 摘要翻譯

近年來，GUI 代理（GUI agents）在視覺定位（visual grounding）與動作預測（action prediction）方面已取得顯著進展，但在需於多個介面轉換間維持任務狀態的長程任務（long-horizon tasks）中，仍顯脆弱。現有的代理通常依賴原始歷史重播（raw history replay）或純文字記憶（text-only memory），前者使模型被冗餘截圖（redundant screenshots）淹沒，後者則捨棄了未來決策所需的局部視覺證據（localized visual evidence）。為了解決這些限制，我們提出了 MementoGUI，一個即插即用（plug-in）的代理式記憶框架（agentic memory framework），為基於多模態大型語言模型（MLLM）的 GUI 代理配備了 MementoCore，一個用於線上記憶選擇（online memory selection）、壓縮（compression）與檢索（retrieval）的學習型控制器（learned controller）。MementoGUI 並非將互動歷史（interaction history）視為固定上下文（fixed context），而是將長程 GUI 控制（long-horizon GUI control）形式化為一個線上記憶控制（online memory-control）問題：工作記憶（working memory）選擇性地保留與任務相關的介面事件（task-relevant interface events），並輔以文字摘要（textual summaries）與 ROI 層級的視覺證據（ROI-level visual evidence）；而情節記憶（episodic memory）則透過習得的相關性選擇（learned relevance selection）來檢索可重複使用的過往軌跡（reusable past trajectories）。MementoCore 將記憶控制（memory control）模組化為專門的運算子（specialized operators），用於步驟處理（step processing）、記憶壓縮（memory compression）、情節寫入（episodic writing）與情節選擇（episodic selection），無需微調（finetuning）GUI 代理骨幹模型（GUI agent backbone）即可實現即插即用的記憶增強（plug-in memory augmentation）。我們進一步開發了一個可擴展的資料整理管線（data curation pipeline），將電腦使用軌跡（computer-use trajectories）轉換為記憶控制器（memory-controller）的訓練資料；提出 MementoGUI-Bench 以評估 GUI 代理中的長程決策（long-horizon decision-making）；並設計了基於 MLLM 的指標（metrics），用於語義動作匹配（semantic action matching）、任務進度（task progress）與記憶一致性（memory consistency）。在 GUI-Odyssey、MM-Mind2Web 與 MementoGUI-Bench 上的實驗顯示，MementoGUI 相較於無歷史（no-history）、歷史重播（history-replay）與純文字記憶基線（text-only memory baselines），穩定提升 GUI 代理的表現，而更大的 MementoCore 骨幹模型（backbones）則能進一步強化記憶增強型 GUI 控制（memory-augmented GUI control）。

### 核心貢獻（3～5點）
- 提出即插即用（plug-in）的代理式記憶框架 MementoGUI，透過 MementoCore 學習型控制器為基於 MLLM 的 GUI 代理提供線上記憶選擇、壓縮與檢索能力，且無需微調（finetuning）GUI 代理骨幹模型（GUI agent backbone）。
- 將長程 GUI 控制形式化為線上記憶控制問題，透過工作記憶保存任務相關的 ROI 層級視覺證據與文字摘要，並以情節記憶（episodic memory）搭配習得的相關性選擇檢索可重複使用的過往軌跡。
- 建立可擴展的資料整理管線（data curation pipeline），將電腦使用軌跡（computer-use trajectories）自動轉換為記憶控制器訓練資料。
- 推出 MementoGUI-Bench 評測基準與基於 MLLM 的評估指標（語義動作匹配、任務進度、記憶一致性），用於評估 GUI 代理的長程決策能力。
- 在 GUI-Odyssey、MM-Mind2Web 與 MementoGUI-Bench 上驗證，相較於無歷史、歷史重播與純文字記憶基線（baselines），MementoGUI 能穩定提升代理表現。

### 適合對象
適合對 GUI 代理（GUI agents）、多模態大型語言模型（MLLM）應用、長程任務規劃與記憶機制設計感興趣的研究者與工程師，特別是關注如何透過記憶控制解決上下文長度問題（context-length problem），以提升跨應用程式行動環境（cross-app mobile environment）或長時間電腦使用軌跡中複雜任務執行效能的讀者。

## 深度分析

#### 方法論解析

MementoGUI 的核心貢獻在於將 long-horizon GUI control (長期 GUI 控制) 重新框架化為一個 online memory-control (線上記憶控制) 問題，而非單純的 context-length problem (上下文長度問題)。傳統的 GUI agent (GUI 代理) 通常將互動歷史視為 fixed context (固定上下文)，透過原始截圖串流或純文字歷史進行條件化，導致模型被冗餘資訊淹沒，或遺失 localized visual evidence (局部視覺證據)。為此，作者提出 MementoCore，一個學習型的記憶控制器，將記憶控制模組化為四個專門運算子：step processing (步驟處理)、memory compression (記憶壓縮)、episodic writing (情節寫入) 與 episodic selection (情節選擇)。

該框架採用雙重記憶架構，在兩個 complementary timescales (互補時間尺度) 上運作：working memory (工作記憶) 負責維護演進中的任務狀態，選擇性地保留與任務相關的介面事件，並以 concise event summary (簡潔事件摘要) 搭配 ROI 層級的視覺證據；episodic memory (情節記憶) 則負責儲存可重用的過去軌跡，並透過學習的相關性選擇機制進行檢索。這種設計使 MementoGUI 成為一個 plug-in agentic memory framework (外掛式代理式記憶框架)：它將 frozen GUI backbone (凍結 GUI 骨幹模型) 與 decision-oriented control layer (決策導向控制層) 分離，無需對底層的 action policy (動作策略) 進行 finetuning (微調)，即可為現有的 GUI agent backbone (GUI 代理骨幹模型) 提供記憶增強。

在訓練資料層面，作者設計了一個可擴展的 data curation pipeline (資料整理管線)，將 PSAI 的 computer-use trajectory (電腦使用軌跡) 轉換為記憶控制器的訓練訊號。該管線首先產生 frame-level 與 subgoal-level 的標註，再針對四大記憶運算子建構監督式微調 (SFT) 資料，最後透過 rule-based corruption 與 VLM 評判篩選建立 preference pairs，使 MementoCore 能在最小化軌跡層級人工標註的前提下學習記憶操作。人類驗證顯示 200 筆隨機抽樣軌跡中有 197 筆被判定為完全正確，顯示該自動化管線具備相當高的標註品質。

#### 實驗數據解讀

實驗涵蓋三個評估基準：cross-app mobile environment (跨應用程式行動環境) 的 GUI-Odyssey、多模態網頁設定的 MM-Mind2Web，以及作者自行提出的 MementoGUI-Bench。後者專門針對記憶依賴的長期決策進行評估，填補了現有基準在長期狀態管理評測上的缺口。比較 baseline (基線) 包含 no-history、history-replay 與 text-only memory 三種設定，全面檢驗不同記憶表徵形式對 GUI agent (GUI 代理) 的影響。

量化結果顯示，MementoGUI 能持續提升 frozen GUI backbone (凍結 GUI 骨幹模型) 的表現。以 GUI-Odyssey 搭配 UI-Venus-1.5-8B 為例，action matching (動作匹配) 從 54.58 提升至 68.32，trajectory success 從 1.29 躍升至 3.57。這不僅顯著優於無歷史基線，也大幅超越原始歷史重播與純文字記憶方法。值得注意的是，實驗發現擴大 MementoCore 的骨幹規模能進一步強化記憶增強的 GUI 控制效果，暗示記憶控制本身的容量與推理能力對最終決策品質具有直接影響。

除了傳統的 GUI 指標，作者還提出多項記憶感知指標，包括 semantic action matching (語義動作匹配)、task progress (任務進度) 與 memory consistency (記憶一致性)。這些指標由 Multimodal Large Language Model (MLLM) 進行評判，能更細緻地捕捉代理在長期互動中是否遺忘約束、重複無效動作，或正確追蹤子目標完成狀態。數據整體支持本文的核心假設：對於長期 GUI 代理而言，學習控制多模態記憶比單純依賴更長的原始互動歷史或純文字記憶表徵更為有效。

#### 與現有研究的比較

在記憶系統方面，現有研究大致可分為三類：第一類是 passive history conditioning (被動歷史條件化)，如原始互動歷史重播或結構化提示，這類方法雖能延長上下文，但無法主動篩選決策相關資訊；第二類是針對單一任務內的緊湊歷史管理，如 MGA 與 adaptive history modeling，主要改善軌跡壓縮但缺乏跨任務重用機制；第三類則聚焦跨任務經驗重用，如 Chain-of-Experience、EchoTrail 與 HybridAgent，透過可檢索軌跡或結構化知識實現遷移學習。更廣泛的代理記憶研究亦包含 memory streams、skill libraries、procedural memory 與 retrieval-augmented refinement 等。

相較於上述方法，MementoGUI 的差異化優勢在於：它並非僅將歷史視為被動上下文，而是將 long-horizon GUI control (長期 GUI 控制) 視為主動的 agentic multimodal memory control (代理式多模態記憶控制) 問題。透過學習型控制器決定「何時更新記憶、保留什麼證據、如何壓縮互動歷史、何時檢索過去經驗」，MementoGUI 能保留局部視覺狀態變化（如暫時選單、已選取 widget 狀態），這些線索在後續截圖中可能已不可見。此外，其 plug-in 設計允許在不修改底層 GUI agent backbone (GUI 代理骨幹模型) action prediction (動作預測) 邏輯的前提下，直接為現有模型提供記憶增強，這在實務部署上具有高度靈活性。

然而，本文方法仍存在若干限制。首先，訓練高度依賴 PSAI computer-use trajectory (電腦使用軌跡) 的品質與規模，雖然人類驗證顯示高準確率，但自動化標註管線在更複雜或跨領域環境中的泛化能力仍有待驗證。其次，MementoCore 作為額外的學習型模組，在每一步互動中需執行記憶選擇、壓縮與檢索，對即時性要求高的 GUI 自動化場景可能帶來推論延遲。最後，目前框架主要針對單一代理的記憶管理，尚未探討多代理系統間的 episodic memory (情節記憶) 共享或協作機制。

#### 可重現性評估

從提供的文本脈絡來看，MementoGUI 的訓練與評估涉及多個外部資源與自建的處理流程。資料層面，記憶控制器的監督訊號來自 PSAI [18] 資料集中的 computer-use trajectory (電腦使用軌跡)，作者雖詳細描述了從原始影片與後設資料轉換為 frame-level 與 subgoal-level 標註的預處理流程，但 PSAI 資料集的取得管道、授權條款與完整規模在節錄內容中並未完整揭露。此外，preference pairs 的建構依賴 VLM 作為評判者進行篩選，不同 VLM 版本或提示設計可能導致訓練資料分布差異，進而影響重現性。

在評估資源方面，作者新提出了 MementoGUI-Bench 作為長期決策的專用基準，並設計了基於 MLLM 的評估指標。這些指標雖然能捕捉語義層面的 task progress (任務進度) 與 memory consistency (記憶一致性)，但 MLLM 評判本身存在隨機性與潛在偏見，且計算成本高昂，對於資源有限的研究團隊可能構成重現門檻。

至於原始碼、模型權重與完整 data curation pipeline (資料整理管線) 的開源釋出狀態，根據目前提供的上下文（包含摘要、引言與方法章節的節錄），並未明確提及是否已公開於程式碼倉庫或模型庫。因此，在缺乏開放原始碼與預訓練權重的情況下，其他研究者難以完全重現從資料整理、控制器訓練到最終評估的完整流程。建議作者後續釋出標準化的訓練腳本、MementoCore checkpoints 與 MementoGUI-Bench 的評估工具，以提升社群的可重現性。

#### 未來研究方向

基於 MementoGUI 的架構與實驗結果，未來研究可從以下幾個方向延伸：

第一，**即時效率與壓縮演算法優化**。目前的 MementoCore 在每一步皆需執行線上記憶選擇與壓縮，未來可探索更輕量化的記憶運算子，或結合 parametric memory (參數化記憶) 與 compressed memory (壓縮記憶) 技術，以降低推論延遲，使框架適用於需要毫秒級反應的即時 GUI 控制場景。

第二，**極長期視野與終身學習**。現有實驗雖已驗證 MementoGUI 在長期任務上的優勢，但對於包含數百甚至數千步互動的 very long-horizon tasks (極長期任務)，episodic memory (情節記憶) 的規模與檢索效率將面臨挑戰。未來可研究自我組織 (self-organizing) 的情節記憶索引、記憶遺忘機制，以及代理在持續互動中線上更新 episodic memory (情節記憶) 的能力，逐步邁向 lifelong learning (終身學習) 的 GUI agent (GUI 代理)。

第三，**跨領域遷移與通用代理記憶**。MementoGUI 的記憶控制框架原則上可泛化至其他需要視覺 grounding 與長期狀態管理的環境，如 open-world planning (開放世界規劃)、機器人操作介面或科學實驗控制。研究如何將 ROI 層級視覺證據的保留機制遷移至非 GUI 領域，將有助於發展通用的 agentic multimodal memory control (代理式多模態記憶控制) 範式。

第四，**多代理協作與共享記憶**。目前框架聚焦單一代理的記憶管理。未來可探討多個 GUI agent (GUI 代理) 如何共享 episodic memory (情節記憶) 庫，透過分散式記憶檢索避免重複探索，並利用集體經驗加速新任務的學習曲線。

第五，**錯誤恢復與反事實推理**。episodic memory (情節記憶) 中儲存的失敗軌跡可用於 counterfactual reasoning (反事實推理) 與策略修正。未來可讓代理主動分析過去失敗的 computer-use trajectory (電腦使用軌跡)，自動生成約束條件或替代計畫，進一步提升長期任務的容錯能力與 self-improvement (自主改進) 潛力。

## 論文問答

**Q1：MementoGUI 旨在解決長期 GUI 代理中的什麼核心問題？**
A：MementoGUI 主要解決現有 GUI 代理在長期任務中無法有效維護跨多個介面轉換之任務狀態的脆弱性。隨著軌跡長度增加，代理容易遺忘限制條件、失去進度追蹤或重複無效動作，因為關鍵證據往往是局部且短暫的，例如已選取的小工具狀態或暫時性選單選項。這顯示瓶頸已從單步視覺理解轉移為長期多模態狀態的主動管理。

**Q2：為何原始歷史重播與純文字記憶在長期 GUI 控制中會失效？**
A：原始歷史重播會以冗餘的截圖淹沒模型，而純文字記憶則捨棄了未來決策所需的局部視覺證據。在長期 GUI 軌跡中，有用的證據稀疏且分佈不均，更長的歷史或純文字表示不一定能提供有助於決策的上下文，反而可能引入冗餘或干擾資訊。因此，這些被動方法無法有效保留任務相關的多模態線索，例如稍後需要參考的早期指令或視覺狀態變化。

**Q3：為何主動記憶管理對 GUI 代理而言比單純擴展上下文長度更重要？**
A：本文主張長期 GUI 控制更適合被視為多模態記憶控制問題，而非單純的上下文長度問題，因為有用的證據稀疏且轉瞬即逝。僅僅提供更長的上下文無法解決應保留什麼、如何壓縮以及何時檢索過去證據以支援未來決策的問題。有效的代理必須主動管理記憶，選擇性地更新、壓縮與檢索相關的多模態狀態，而非被動地依賴原始互動歷史。

**Q4：MementoGUI 的核心架構為何，它如何與 GUI 代理骨幹模型互動？**
A：MementoGUI 是一個即插即用的代理式多模態記憶控制框架，透過名為 MementoCore 的學習型記憶控制器來增強凍結的 GUI 骨幹模型，無需微調動作策略本身。該控制器維護工作記憶以處理不斷演變的任務內狀態，並維護情節記憶以儲存先前互動中可重複使用的經驗，將相關互動歷史轉換為結構化的多模態上下文。這種設計將互動歷史從被動的上下文重播轉變為決策導向的控制層，再餵入凍結的骨幹模型進行動作預測。

**Q5：MementoCore 包含哪些專門化運算子，其功能各是什麼？**
A：MementoCore 將記憶控制模組化為四個專門化運算子：步驟處理、記憶壓縮、情節寫入與情節選擇。步驟處理負責處理傳入的互動事件；記憶壓縮透過保留任務相關的介面事件與簡潔文字摘要及 ROI 層級視覺證據來凝練工作記憶；情節寫入儲存可重複使用的過去軌跡；情節選擇則透過學習的相關性選擇機制檢索過去經驗。這種模組化設計無需微調底層 GUI 代理骨幹模型即可實現記憶增強。

**Q6：MementoGUI 的工作記憶與情節記憶有何不同，為何需要這種雙重記憶設計？**
A：工作記憶選擇性地保留不斷演變的任務內狀態，包含簡潔事件摘要與 ROI 層級的局部視覺參考；情節記憶則透過學習的相關性選擇儲存並檢索先前互動中可重複使用的軌跡。這種雙重記憶設計是必要的，因為工作記憶處理跨介面轉換的即時任務狀態延續，而情節記憶則實現跨任務的過去經驗重用。兩者以互補的時間尺度協同運作，使代理能同時處理當前任務的連續性與長期知識累積。

**Q7：MementoGUI 在哪些基準上進行評估，關鍵性能提升為何？**
A：MementoGUI 在 GUI-Odyssey、Multimodal-Mind2Web 以及新提出的 MementoGUI-Bench 上進行評估。例如，在 GUI-Odyssey 上使用 UI-Venus-1.5-8B 時，MementoGUI 將動作匹配率從 54.58 提升至 68.32，軌跡成功率從 1.29 提升至 3.57。這些結果顯示，相較於無歷史、歷史重播與純文字記憶基線，MementoGUI 能持續帶來顯著改善。

**Q8：MementoGUI-Bench 是什麼，它引入了哪些獨特的評估指標？**
A：MementoGUI-Bench 是專為評估依賴記憶的長期 GUI 決策而設計的基準測試。它引入了記憶感知指標，包括語義動作匹配、任務進度與記憶一致性，以超越標準 GUI 指標來評估長期行為。這使得研究者能更細緻地評估代理在長時間互動中維護與利用多模態記憶的能力。

**Q9：擴展 MementoCore 骨幹模型規模如何影響性能，這對記憶控制器的容量有何啟示？**
A：實驗顯示，更大的 MementoCore 骨幹模型能進一步強化記憶增強的 GUI 控制，表明學習型記憶控制器的容量直接影響記憶操作的品質。這種擴展趨勢意味著記憶選擇、壓縮與檢索均受益於模型容量的增加，與其他學習型控制策略類似。這支持了將記憶管理視為學習問題而非依賴固定啟發式規則的設計選擇。

**Q10：在哪些實際應用場景中，MementoGUI 相較於標準 GUI 代理最具優勢？**
A：MementoGUI 在複雜多步驟工作流程中最具優勢，例如跨應用程式的行動任務或冗長的網頁流程，其中關鍵資訊會在眾多畫面中短暫出現。舉例來說，需要參考早期指令、暫時選取的小工具狀態或已完成子目標的任務，都能受益於控制器保留局部視覺證據與簡潔摘要的能力。這使其特別適合企業流程自動化、輔助無障礙工具以及在動態軟體環境中運作的個人助理代理。

**Q11：MementoGUI 的即插即用設計對產品開發與部署有何益處？**
A：即插即用設計讓 MementoGUI 無需微調底層動作模型即可增強凍結的 GUI 骨幹，大幅降低部署成本與工程負擔。產品團隊可以在不重新訓練昂貴基礎模型或不干擾現有動作策略的情況下，為既有代理加入先進的記憶能力。因此，它能加速迭代並更容易整合到橫跨桌面、網頁與行動平台的各類 GUI 自動化產品中。

**Q12：將 GUI 控制重新框架為記憶控制問題，對自主代理領域有何更廣泛的影響？**
A：此舉將研究重心從單步感知的漸進式改進，轉移至動態視覺環境中長期狀態管理這一根本挑戰。這種典範鼓勵開發能主動決定記憶與檢索內容的代理式系統，並可能影響機器人學、開放世界規劃與科學計算等其他領域的記憶架構。MementoGUI 透過證明學習型記憶控制優於被動歷史條件設定，為未來自主代理將結構化多模態記憶系統作為核心決策層樹立了先例。

**Q13：作為即插即用的記憶增強系統，MementoGUI 面臨哪些固有的限制或權衡？**
A：作為即插即用模組，MementoGUI 必須在無法微調凍結 GUI 骨幹模型的前提下運作，這意味著其成效根本上受限於骨幹模型本身的單步感知與動作預測能力。該框架依賴可擴展但複雜的資料整理管線來產生記憶運算子的訓練訊號，儘管有人工驗證，仍可能引入標註雜訊或特定領域偏差。此外，引入獨立的學習型控制器相較於簡單的歷史條件基線增加了計算與架構複雜度，這是性能提升與系統開銷之間的權衡。

**Q14：在哪些情況下，MementoGUI 的記憶控制機制可能無法改善任務表現？**
A：若 MementoCore 在壓縮工作記憶時錯誤地捨棄了後續關鍵的局部視覺證據，或從情節記憶中檢索到不相關的片段，則產生的結構化上下文可能誤導而非協助凍結的 GUI 骨幹。當骨幹模型缺乏有效利用豐富多模態記憶上下文的能力時，系統也可能表現不佳，因為兩個組件並非聯合訓練。此外，在有用線索極度稀疏或高度模糊的軌跡中，即使是學習型控制器也可能無法區分常規轉換與決策關鍵事件。

**Q15：未來有哪些有前景的研究方向可以延伸 MementoGUI 的典範？**
A：未來研究可探索記憶控制器與 GUI 骨幹模型的聯合最佳化，以實現記憶檢索與動作生成之間更緊密的耦合，從而克服凍結骨幹的限制。延伸情節記憶機制以支援跨平台與跨應用程式的遷移學習，將使代理能將網頁自動化中獲得的可重用技能遷移至行動或桌面環境。此外，將元學習或終身適應能力整合至 MementoCore，可使記憶控制器從持續互動中不斷改進其選擇與壓縮策略，而不僅依賴離線整理的資料集。

## 實務應用指南

### 適用場景

1. **跨應用程式行動裝置自動化**：例如在手機上完成「搜尋航班→比價→截圖傳給同事→開啟行事曆建立提醒」等流程，代理必須記住前一步驟的資訊，並在跨 App 切換後仍能追蹤任務狀態。
2. **長流程網頁操作**：如後台管理系統的資料登打、多頁表單填寫與審核，代理需持續記錄已完成的子目標、暫時選單狀態與局部視覺線索，避免在頁面轉換後遺失關鍵上下文。
3. **企業級電腦使用自動化（RPA）**：處理財務對帳、報表產生等涉及多視窗切換的桌面級長期任務，其中選中的欄位、暫時彈窗等 ROI 層級視覺證據對後續決策至關重要。
4. **視覺化教學與客服代理**：在引導使用者操作軟體時，需記住使用者過往的點擊歷程與當前介面狀態，以提供個人化的下一步建議，並在對話中斷後恢復上下文。
5. **複雜軟體測試與品質驗證**：執行需數十步的端到端 UI 測試，代理必須記錄中間狀態與前置條件，避免重複無效操作或遺漏關鍵檢查點。

### 實作前置條件

- **資料**：需具備大量電腦使用軌跡（含螢幕錄影／截圖與對應操作後設資料），或現有公開資料集（如 GUI-Odyssey、Multimodal-Mind2Web）。論文使用 PSAI 資料集，並需能產生畫面層級與子目標層級標註，作為記憶控制器的訓練訊號。
- **運算資源**：訓練 MementoCore 需多張高階 GPU（如 A100／H100）以支援多模態大型語言模型（MLLM）的訓練；推論階段需同時承載凍結 GUI 骨幹模型與記憶控制器的雙模型運算，記憶體與延遲預算需提前評估。
- **技術能力**：團隊需熟悉 MLLM 架構、GUI 代理的視覺接地（visual grounding）、資料整理管線建置，以及偏好最佳化（如 DPO）流程；具備 PyTorch 與分散式訓練經驗為佳。
- **基礎設施**：需建置自動化標註與 VLM 評分篩選系統，以產生記憶控制運算子的 SFT 資料與偏好對，並具備人工抽樣驗證的閘門機制。

### 實作步驟建議

1. **選定並凍結 GUI 骨幹模型**：挑選現成的 MLLM-based GUI 代理（如 UI-Venus-1.5、Qwen2-VL 等）作為動作策略基底，保持其權重凍結，不進行微調，確保 MementoGUI 的可插拔性。
2. **建立資料整理管線**：收集原始電腦使用軌跡，透過自動化前處理產生畫面層級與子目標層級標註，並轉換為四種記憶控制運算子（步驟處理、記憶壓縮、情節寫入、情節選擇）的 SFT 訓練資料。
3. **設計 MementoCore 架構**：實作工作記憶（保存當前任務相關事件與 ROI 層級視覺證據）與情節記憶（儲存可重複使用的過去軌跡）的雙層記憶體，並將記憶控制模組化為對應運算子。
4. **訓練記憶控制器**：先以 SFT 資料訓練基礎記憶操作，再透過規則式破壞與 VLM 判斷篩選建立偏好對，進行偏好最佳化，使控制器學會選擇性保留與相關性檢索。
5. **整合決策導向控制層**：在每次決策前，由 MementoCore 主動產生結構化多模態上下文（簡潔事件摘要與局部視覺證據），取代被動的原始歷史重播，再餵入凍結 GUI 骨幹模型進行動作預測。
6. **評估與持續迭代**：於 MementoGUI-Bench 或自建長期任務基準上，採用語義動作匹配、任務進度與記憶一致性等指標評估；針對失敗案例擴充情節記憶庫，並定期驗證自動標註品質。

### 潛在風險與注意事項

- **記憶過度壓縮**：工作記憶若過度精簡，可能遺失關鍵的 ROI 層級視覺證據（如暫時選單狀態、已勾選核取方塊），導致後續決策錯誤。建議設定視覺證據保留的硬性門檻，避免僅依賴純文字記憶。
- **情節記憶檢索偏差**：錯誤的相關性選擇會引入無關或過時的歷史軌跡，干擾當前任務。應建立嚴謹的負樣本採樣機制，並以 VLM 進行相關性二階驗證。
- **雙模型運算開銷**：凍結 GUI 骨幹模型與 MementoCore 同時運行會增加延遲與 GPU 記憶體壓力。產品化時需評估模型量化、推論加速或記憶體分頁策略。
- **自動標註誤差累積**：資料整理管線的錯誤會直接傳遞給記憶控制器。建議參考論文做法，保留人工抽樣驗證閘門（如每批次抽驗 1–2% 軌跡）。
- **跨平台領域偏移**：行動裝置與網頁環境的視覺分佈與操作邏輯不同，單一記憶控制器可能難以泛化。跨平台部署時應分域收集電腦使用軌跡，或採用領域適應技術。

### 與其他技術的整合建議

- **RPA 平台**：將 MementoGUI 作為外掛式智慧記憶層，疊加於現有 RPA（如 UiPath、Power Automate）之上，專責長流程中的跨步狀態管理，而非取代既有控制邏輯。
- **檢索增強生成（RAG）**：將情節記憶視為專門的 GUI-RAG，與企業知識庫串接，使代理能同時檢索歷史操作經驗與業務規則文件，強化決策依據。
- **推論服務框架**：透過 vLLM、TGI 或 SGLang 統一部署凍結 GUI 骨幹模型與 MementoCore，利用 API 閘道動態路由當前畫面與記憶上下文，降低系統耦合。
- **分層強化學習**：將 MementoCore 的高階記憶操作（何時寫入、檢索）與底層動作策略的低階控制分離，以 Hierarchical RL 進一步提升探索效率與長期規劃能力。
- **可觀測性工具**：整合 Langfuse、LangSmith 或自研追蹤系統，記錄工作記憶與情節記憶的讀寫歷程，便於診斷長期任務中的遺忘、重複行為或記憶不一致問題。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從論文的 Introduction 與適用場景入手，先建立「為何長期 GUI 任務需要主動記憶管理」的直覺，重點區分「工作記憶」與「情節記憶」的互補角色，暫時跳過運算子與訓練管線的技術細節。
- **AI 工程師**：請聚焦資料整理管線與 MementoCore 的四個運算子實作，特別留意「凍結 GUI 骨幹模型」與「可插拔記憶控制器」的系統邊界；同時務必評估雙模型推論延遲與記憶體預算，這是從論文走向產品的最關鍵工程權衡。
- **研究人員**：建議深入分析記憶控制問題的數學建模與 MLLM-based 評估指標（語義動作匹配、記憶一致性），並思考能否將此框架擴展至機器人操作或開放世界遊戲等其他長期決策領域，或改進為線上強化學習範式。
- **產品經理**：請將閱讀重心放在實驗結果與基線比較（無歷史、原始歷史重播、純文字記憶），理解 MementoGUI 在何種任務長度與複雜度下能顯著提升成功率；據此評估導入所需的額外訓練資料成本、運算資源與使用者體驗權衡。
