## ⚡ TL;DR

長程任務需持續累積狀態，但安全常仰賴外部防護或事後對齊，難以內建於模型本身。
提出Safin-1，以MARCH架構內容路由檢索脈絡錨點與持久狀態，並以可拆卸安全狀態做測試時適應。
評測顯示通用與長脈絡能力、效率皆提升，安全狀態使越獄成功率降逾四成與五成，且過度拒絕少於LoRA。

## 摘要翻譯

長程複雜任務（long-horizon complex tasks）要求基礎模型（foundation models）能夠累積資訊、維持內部狀態（internal states），並在長期互動中持續適應。安全性應是模型本身的內在屬性，而非僅仰賴外部防護機制（external safeguards）或事後對齊（post-hoc alignment，例如監督式微調〔supervised fine-tuning〕）等行為約束（behavioral constraints）。這催生了「內在安全（Safety from Within）」的概念：安全相關能力透過模型的原生計算（native computation）來表徵與調用。我們提出 Safin-1，一個透過記憶路由（memory routing）與狀態演化（state evolution）來實現此原則的基礎模型家族。Safin-1 建構於 MARCH（Memory-Anchor Routing across Context History）之上，這是一種可維持結構化記憶狀態（structured memory states），並透過內容條件化路由（content-conditioned routing）選擇性地檢索（retrieval）相關歷史資訊的網路架構。它支援在測試時適應（test-time adaptation）持久能力狀態（persistent capability states），而無需反覆修改骨幹網路（backbone），從而在共享基礎（shared foundation）上實現受控專門化（controlled specialization）。我們透過安全狀態（Safety State）在下游安全任務（downstream safety tasks）上探討此路由狀態介面（routed-state interface），展現出基於狀態的有效適應，並帶來顯著的安全提升。更廣泛地說，路由狀態介面將情境記憶（contextual memory）與持久能力適應（persistent capability adaptation）統一於模型的原生計算之中，將記憶從先前脈絡（prior context）的被動記錄（passive record），重新框架為維持與演化模型行為（model behavior）的主動基質（active substrate）。針對通用能力（general capabilities）、長脈絡理解（long-context understanding）、檢索（retrieval）與效率（efficiency）的評估，進一步驗證了 Safin-1。這些發現為安全性作為一種狀態原生且可適應維護的能力提供了一條途徑。本研究僅是「內在安全」在架構層面的初步探索；欲實現此一更宏觀的願景，仍需大量後續研究。

### 核心貢獻（3～5點）
- 提出「內在安全（Safety from Within）」理念，將安全能力內建於模型的原生計算，而非僅仰賴外部防護機制或事後對齊等行為約束。
- 設計 MARCH 架構，透過記憶路由與狀態演化維持結構化記憶狀態，並以內容條件化路由選擇性檢索歷史資訊。
- 支援在測試時對持久能力狀態（如安全狀態）進行適應，無需反覆修改骨幹網路，實現共享基礎上的受控專門化。
- 在下游安全任務上驗證安全狀態的狀態適應效果，顯著提升模型安全性。
- 將記憶重新框架為主動基質，統一情境記憶與持久能力適應於模型的原生計算之中。

### 適合對象
對大型語言模型安全對齊、記憶增強架構、長脈絡推理與測試時適應有興趣的研究者與工程師，特別是關注如何將安全能力內建於模型內部狀態、而非僅依賴外部防護機制或後訓練對齊的讀者。

## 深度分析

#### 方法論解析

Safin-1（Safety from Within，內在安全）的核心主張是：安全能力不應僅靠外部防護機制（external safeguards）或事後對齊（post-hoc alignment）來約束行為，而應以**模型原生計算（native computation）**內的狀態形式存在，並在需要時被選擇性呼叫。為此，作者提出 **MARCH（Memory-Anchor Routing across Context History，跨脈絡歷史的記憶錨點路由）** 架構，將遞迴狀態（recurrent state）的演化軌跡轉化為可定址、可檢索的結構化記憶狀態（structured memory states）。

MARCH 可拆解為三個機制：

1. **脈絡衍生狀態錨點（Context-Derived State Anchors）**  
   在遞迴骨幹網路（backbone）向前演化的過程中，系統定期對當前遞迴狀態做「檢查點」（checkpoint），形成一組歷史狀態錨點。每個錨點並非單純的過去狀態複本，而是與一個緊湊的、狀態感知的路由鍵（routing key）配對，使後續詞元（token）能判斷該錨點是否與當前計算相關。這把記憶從被動記錄（passive record）提升為主動基質（active substrate）。

2. **內容路由狀態檢索（Content-Routed State Retrieval）**  
   每個詞元在計算時會產生查詢（query），與狀態錨點的路由鍵進行內容條件化路由（content-conditioned routing），選出相關的歷史狀態，或選擇「null」選項以忽略歷史。被檢索到的狀態會與當前遞迴路徑融合，且設計上保留底層遞迴的動態行為。這相當於在狀態層級實現稀疏注意力（sparse attention）：不是對所有詞元做鍵值快取（token-level key–value cache）比對，而是對壓縮後的遞迴記憶進行選擇性讀取。

3. **持久能力狀態（Persistent Capability States）**  
   狀態庫（state bank）不僅能存放動態的脈絡錨點，也能容納學習來的持久能力狀態。作者以 **Safety State（安全狀態）** 為首例：在凍結語言模型骨幹的前提下，僅學習一組可附加／卸除的安全狀態，並由同樣的路由器決定每個詞元是否引用它。這實現了**測試時適應（test-time adaptation）**與**受控專門化（controlled specialization）**：同一個共享基礎（shared foundation）模型可透過掛載不同狀態來獲得不同能力，而無需反覆微調骨幹權重。

在實作層面，作者提出 **生產者–讀取者實作（Producer–Reader Implementation）**，包含稠密與稀疏路由的融合核心，並將稀疏狀態路由擴展到 128K 詞元的序列長度，使歷史檢索在長脈絡下仍具計算可行性。

整體而言，Safin-1 的方法論把「記憶」與「能力適應」統一到同一個路由狀態介面（routed-state interface）：脈絡記憶（contextual memory）負責保留長程歷史資訊，持久能力狀態負責編碼可重複使用的行為約束（behavioral constraints），兩者都透過模型內部的原生狀態演化來維護與呼叫。

#### 實驗數據解讀

論文的驗證分為兩個互補階段：小規模架構驗證與大規模能力／安全評估。

**小規模 MARCH 驗證（0.8B 參數）**  
作者在 50B 詞元上預訓練了基於 Gated DeltaNet、Kimi Delta Attention 與 Gated DeltaNet-2 的對照模型，並將 MARCH 套用於其上。結果顯示，MARCH 在以下任務帶來一致提升：

- **一般語言建模（general language modeling）**：狀態路由未損害模型對下一詞元的建模能力。
- **長度外推（Length Extrapolation）與聯想回憶（Associative Recall）**：MARCH 能回復較早的狀態錨點，減輕傳統遞迴模型「後來狀態覆蓋先前關聯」的問題。
- **長脈絡理解（LongBench）與情境內檢索（In-Context Retrieval）**：在長距離依賴任務與真實世界檢索場景中表現提升。
- **RULER NIAH**：顯示模型能在極長脈絡中定位並提取關鍵資訊，甚至可外推到訓練時未見的長度。

這些結果支持一個核心論點：透過內容路由保留多個歷史狀態，能夠在維持恆定記憶解碼（constant-memory decoding）優勢的同時，緩解單一狀態瓶頸（single-state bottleneck）。

**大規模 Safin-1 驗證（4B 與 35B-A3B）**  
作者以混合 Qwen3.5 骨幹進行持續預訓練（continual pretraining）與監督式微調（supervised fine-tuning），分別得到 4B 稠密模型與 35B-A3B 混合專家（mixture-of-experts）模型。在十項通用能力基準上，宏觀平均（macro-average）從 66.79 提升至 69.20（4B），從 76.25 提升至 78.35（35B-A3B）。提升最明顯的領域是具挑戰性的推理與競賽級數學，這暗示狀態路由有助於在長推理過程中維持並回收有用的中間計算，而不會犧牲廣泛通用能力。兩種規模與兩種骨幹組織（dense 與 MoE）都呈現類似模式，初步說明該效益具備規模遷移性。

**Safety State 的安全–效用權衡（Safety–Utility Trade-off）**  
在凍結 Safin-1 SFT 檢查點的條件下，作者僅學習一個持久的 Safety State。結果顯示：

- 越獄攻擊成功率（jailbreak attack success rate）平均下降 **42.3%（4B）** 與 **52.3%（35B-A3B）**。
- 相較於訓練條件相當的 rank-8 LoRA 控制組，Safety State 產生顯著較少的過度拒絕（over-refusal）。

這表示 Safety State 並非對所有輸入施加全域性的行為抑制，而是透過路由器選擇性地引用安全狀態，從而在提升安全性的同時保留對良性查詢的回應能力。這正是「內在安全」相較於傳統外部對齊的關鍵優勢。

**效率評估**  
稀疏狀態路由在長達 128K 詞元的序列上進行評估，顯示狀態層級稀疏性可類比於稀疏注意力，將計算與記憶體成本控制在可接受範圍。

不過，論文也坦承這只是初步探索，部分實驗細節（如攻擊集合、過度拒絕的量化指標、各基準的完整分項）在提供的摘要與目錄中尚未完整揭露，需參照全文與附錄進一步確認。

#### 與現有研究的比較

**相較於自注意力（Self-Attention）與 KV Cache**  
自注意力能精細存取每個先前詞元，但訓練成本為二次方（quadratic training cost），且鍵值快取隨序列長度線性增長。MARCH 透過遞迴壓縮與狀態錨點，實現恆定記憶解碼，並以內容路由恢復相關歷史，從而在長序列場景中更具效率優勢。

**相較於遞迴、線性注意力與狀態空間模型（SSM）**  
RNN、線性注意力、選擇性狀態空間模型（selective state-space models）與 Delta 規則遞迴（delta-rule recurrences）都將因果前綴（causal prefix）壓縮為固定大小狀態，但通常只暴露最新狀態供讀取，導致早期關聯被衰減或覆蓋。近期研究透過擴大記憶、多狀態路由或時間組織的狀態集合來緩解此問題，MARCH 則進一步提供緊湊且內容可定址的狀態檢索介面，使歷史狀態能被選擇性召回，而非僅被動保留。

**相較於現有安全對齊方法**  
傳統方法包括監督式微調、RLHF、對抗訓練、系統提示、表徵介入（representation interventions）與 LoRA 轉接器（adapters）等，多數屬於外部約束或權重修改。Safety State 的差異在於：

- **原生性**：安全能力內建於模型自身的遞迴狀態系統。
- **可分離性**：Safety State 可附加或移除，不影響共享基礎模型。
- **選擇性**：由路由器決定是否引用，減少對良性查詢的過度抑制。
- **測試時適應**：無需反覆修改骨幹即可進行能力專門化。

與 rank-8 LoRA 控制組相比，Safety State 在達到更高安全性的同時產生更少 over-refusal，顯示狀態層級適應可能比低秩權重修改更擅長處理安全–效用權衡。

**與 R2AI 觀點（R2AI perspective）的呼應**  
R2AI 主張可擴展安全（scalable safety）應與模型能力共同演化，結合抵抗已知威脅與韌性面對未知風險。Safin-1 透過狀態原生（state-native）且可適應維護的安全能力，為此願景提供了一個具體的架構級實例。

**限制與未解問題**  
- 目前僅展示單一 Safety State，尚未探討多個持久狀態的組合與衝突。
- 安全評估集中於已知越獄攻擊，對未知風險的韌性（resilience to unforeseen risks）仍需更多紅隊測試。
- 路由器的決策過程尚缺乏系統性的可解釋性分析。
- 狀態庫的記憶容量、遺忘機制與長期穩定性仍有待理論與實證研究。

#### 可重現性評估

從提供的上下文來看，論文在附錄 A 中收錄了訓練配置（A.1 小規模 MARCH 驗證、A.2 大規模 Safin-1 訓練、A.3 Safety State 專門化），這對重現研究是正面訊號。然而，在提供的摘要與目錄中，**並未明確提及是否公開原始碼、資料集、模型權重或評估腳本**，這對可重現性構成以下挑戰：

1. **工程實作細節**：MARCH 的生產者–讀取者實作涉及融合的稠密／稀疏路由核心、狀態錨點的檢查點策略、以及與遞迴骨幹的無縫整合。這些高度依賴客製化 CUDA 核心或高效能運算實作，若無開源程式碼，外部研究者難以精確復現效率與能力數據。

2. **資料組成與前處理**：持續預訓練與 Safety State 訓練都依賴特定資料混合（data mixture）與有害／無害範例的篩選。若資料卡片（data card）未公開，重現安全–效用權衡結果會有困難。

3. **評估協定**：越獄攻擊成功率與 over-refusal 的衡量需要標準化的攻擊集合與評分準則。不同攻擊庫與評分器會顯著影響結果，因此公開評估工具至關重要。

4. **模型權重**：若 Safin-1 檢查點未釋出，社群無法直接驗證大規模結果，也難以在此基礎上進行後續研究。

綜合而言，本研究在方法描述與附錄配置上具備一定的可重現性基礎，但要達到社群可驗證、可擴展的標準，仍需作者釋出程式碼、資料說明、模型權重與完整評估流程。

#### 未來研究方向

1. **多持久狀態的組合與路由**  
   未來可探索除了 Safety State 之外的其他持久能力狀態，例如推理風格、領域專長、工具使用規範或個人化偏好。關鍵問題在於：當多個狀態同時存在時，路由器如何決定權重？狀態之間是否會互相干擾？如何設計組合式狀態學習目標？

2. **動態狀態庫管理**  
   目前的狀態錨點是定期檢查點，未來可研究自適應的錨點生成、壓縮、合併與遺忘機制。例如，依據資訊重要性動態決定檢查點頻率，或建立層級式狀態摘要，以在有限記憶體下保存更長的歷史。

3. **理論與可解釋性分析**  
   需要對 MARCH 的記憶容量、路由動態與狀態可恢復條件進行理論刻畫。同時，透過機械式可解釋性（mechanistic interpretability）分析路由器在何種輸入下引用 Safety State，有助於理解並強化安全行為。

4. **更廣泛的安全與對齊研究**  
   Safety State 可與 RLHF、DPO、憲法 AI 等方法結合，將獎勵信號轉化為狀態更新而非權重更新。未來也可針對更廣泛的越獄攻擊、提示注入（prompt injection）、多輪對話操縱與未知風險進行紅隊測試。

5. **規模與多模態擴展**  
   將 MARCH 與 Safety State 擴展到更大規模（如 100B+）與多模態基礎模型（視覺、音訊、動作狀態）是自然的下一步。特別是對於需要長程互動的具身智能（embodied AI）與智慧代理人（agent）系統，狀態原生記憶與能力可能更具價值。

6. **硬體感知的高效實作**  
   稀疏狀態路由需要專用的記憶體階層與核心最佳化，未來可研究狀態庫的量化、分頁（paging）、以及與現代加速器記憶體架構的協同設計，以支援百萬詞元以上的上下文。

7. **線上與個人化適應**  
   由於持久狀態可在不修改骨幹的情況下更新，未來可探索使用者層級的線上狀態適應，使模型在保護隱私與安全的前提下，持續學習個人化偏好與規範。

總結來說，Safin-1 與 MARCH 為「內在安全」提供了一個具體且可擴展的架構方向，但從初步探索到成熟可靠的基礎模型範式，仍需在理論、工程、安全評估與開放生態上持續投入。

## 論文問答

**Q1：長程智慧任務中，Safin-1 試圖解決什麼核心問題？**
A：Safin-1 針對的是長程複雜任務中「連續性」的雙重需求：模型必須在漫長互動中保留過往脈絡，同時根據當前情境可靠地調用適當能力。傳統方法把上下文記憶與可重複使用行為分開處理，導致安全等能力往往只能透過外部防護或事後對齊來強加。Safin-1 提出「內在安全」，希望讓安全相關能力成為模型原生計算的一部分，並隨著狀態演化而持續維護。

**Q2：現有方法在記憶與安全上有哪些主要限制？**
A：自注意力機制雖能精細存取過去詞元，但訓練成本隨序列長度呈二次方增長，且鍵值快取會不斷膨脹。遞迴或線性注意力模型把因果前綴壓縮成固定大小狀態，卻通常只暴露最新狀態，舊有關聯一旦被覆蓋便難以恢復。至於安全，常見做法是透過監督式微調、轉接器或推論時前綴等外部或事後手段施加行為約束，這些方式不僅難以隨能力同步演化，還可能過度拒絕有用回應。

**Q3：為何「內在安全」對可擴展的安全系統至關重要？**
A：R2AI 觀點認為，可擴展安全應與模型能力同步演化，既要抵抗已知威脅，也要對未知風險具備韌性。把安全視為模型內部狀態的原生能力，而非單純外部限制，能讓安全機制隨著模型狀態持續更新，並在長程互動中選擇性調用。這種設計有助於減少僅靠事後對齊帶來的過度拒絕，並使安全行為更穩定地融入模型的原生計算流程。

**Q4：MARCH 的核心運作機制是什麼？**
A：MARCH 全名為 Memory-Anchor Routing across Context History，它會在遞迴骨幹網路演化的過程中定期檢查點，把過去的狀態版本保存為可定址的「狀態錨點」。每個錨點都配備一個緊湊且具狀態感知的路由鍵，讓當前詞元能依據內容條件化路由，檢索相關歷史狀態或選擇空選項。檢索到的狀態會與當前遞迴路徑融合，既保留底層遞迴的行為，又把模型自身的狀態軌跡轉化為因果且端對端可訓練的內部記憶。

**Q5：持久能力狀態與安全狀態的創新之處在哪裡？**
A：持久能力狀態是放在與脈絡衍生錨點同一記憶庫中的學習狀態，能讓模型在不修改共享骨幹網路的情況下進行測試時適應與受控專門化。安全狀態是這種持久狀態的具體實例：研究者凍結語言模型骨幹，僅從有害與無害範例中學習一個可拆卸的安全狀態，再由既有路由器決定每個詞元是否調用它。這讓安全專門化成為模型原生遞迴狀態系統的一部分，同時保留通用基礎模型，並可隨時附加或移除。

**Q6：Safin-1 在架構設計上做了哪些關鍵選擇，為何這樣設計？**
A：設計者選擇把遞迴狀態的歷史版本保存為錨點，而非保留完整的詞元級鍵值快取，這樣能在長序列上維持恆定記憶解碼並降低儲存成本。他們引入內容條件化路由與空選項，使模型只在需要時才檢索歷史狀態，避免無差別地融合所有過去資訊。此外，把持久能力狀態與動態錨點放在同一記憶庫，統一了情境記憶與持久能力適應的介面，讓記憶從被動記錄變成主動維護與演化行為的基質。

**Q7：論文使用了哪些評估來驗證 Safin-1？**
A：評估分為兩個互補階段：第一階段以 0.8B 規模進行控制實驗，在 500 億詞元上預訓練並把 MARCH 應用於 Gated DeltaNet、Kimi Delta Attention 與 Gated DeltaNet-2，測試一般語言建模、LongBench、真實世界情境內檢索與 RULER NIAH 等長脈絡任務。第二階段把 Safin-1 擴展到 4B 與 35B-A3B 的混合 Qwen3.5 骨幹，進行持續預訓練與監督式微調，並在十項能力基準上評估通用能力。此外，研究者也針對持久安全狀態測試越獄攻擊成功率與過度拒絕，並評估長達 128K 詞元的效率與可擴展性。

**Q8：Safin-1 的主要實驗結果有哪些？**
A：在小規模驗證中，MARCH 在多個遞迴骨幹上帶來一致進步，包括一般語言建模、長脈絡理解、情境內檢索，以及超越訓練脈絡長度的外推能力。放大到 4B 與 35B-A3B 後，十項能力基準的宏觀平均分別從 66.79 提升到 69.20、從 76.25 提升到 78.35，尤其在具挑戰性的推理與競賽級數學上進步明顯。安全狀態則使平均越獄攻擊成功率在 4B 下降 42.3%、在 35B-A3B 下降 52.3%，同時比訓練條件相當的 rank-8 LoRA 對照組產生更少的過度拒絕。

**Q9：從架構分析與消融實驗可得出什麼結論？**
A：把 MARCH 應用於三種不同遞迴骨幹後，研究顯示記憶路由機制能穩定提升長程任務表現，並非僅對單一架構有效。在 4B 密集模型與 35B-A3B 混合專家模型上觀察到類似的進步模式，說明狀態路由的好處能跨越模型規模與骨幹組織。稀疏狀態路由則提供類似稀疏注意力的狀態層級類比，讓模型在長達 128K 詞元的序列中仍能高效選擇壓縮後的遞迴記憶，進一步驗證了效率與可擴展性。

**Q10：Safin-1 可應用於哪些實際場景？**
A：Safin-1 特別適合需要長期連貫性的應用，例如多輪對話代理、長文件分析與摘要、程式碼生成中的長期依賴追蹤，以及持續學習的個人化助手。由於它能選擇性地檢索過去狀態並調用持久能力狀態，模型在面對長程推理任務時較不易遺失關鍵資訊。安全狀態的設計也讓高風險場景中的行為約束能更靈活地附加與更新。

**Q11：若將 Safin-1 產品化，需要考慮哪些因素？**
A：安全狀態可拆卸且無需重寫共享骨幹，這讓產品團隊能針對不同法規、使用場景或風險等級快速切換安全專門化，而不用重新訓練整個模型。稀疏狀態路由與高效生產者–讀取者實作支援長達 128K 詞元的推論，對於長文件處理與長對話服務的延遲與記憶體成本相當有利。然而，產品部署仍需監控路由決策的可解釋性、狀態庫的儲存管理，以及安全狀態被繞過或誤用的風險。

**Q12：這項研究對人工智慧領域可能帶來什麼影響？**
A：Safin-1 把記憶重新框定為主動維護與演化模型行為的基質，而不只是被動保存先前脈絡，這可能改變未來基礎模型設計的思維。它提供了一種不同於傳統監督式微調、RLHF 或外部過濾器的安全途徑，讓安全能力內建於模型原生計算之中。這種「內在安全」與 R2AI 願景一致，為發展能隨能力同步演化、兼具抵抗已知威脅與韌性面對未知風險的安全系統開啟了新方向。

**Q13：作者承認哪些限制？**
A：作者明確指出這項工作只是「內在安全」願景的初步架構探索，距離完整實現還需要大量後續研究。目前僅以安全狀態作為持久能力狀態的第一個例證，尚未涵蓋其他可能的能力狀態或更複雜的安全策略。此外，實驗雖跨越多個規模與骨幹，但對於極大規模、多語言或高度對抗性環境中的長期穩定性仍待驗證。

**Q14：在哪些情況下 MARCH 或安全狀態可能失效？**
A：如果歷史狀態在遞迴過程中被嚴重覆蓋或衰減，且路由鍵無法正確編碼其語義，模型就可能檢索不到關鍵資訊。稀疏路由雖然提升效率，但也可能因為選擇錯誤的狀態而遺漏重要記憶，導致長程推理中斷。安全狀態的選擇性調用同樣可能失靈：當有害與無害提示的界線模糊，或攻擊者設計出專門繞過狀態路由的越獄策略時，模型仍可能產生不當輸出。

**Q15：未來研究可以朝哪些方向延伸？**
A：未來可以探索更多種類的持久能力狀態，例如針對特定領域推理、個人化風格或多語言行為的專門狀態，並研究它們之間的交互與衝突。另一方面，可發展線上或持續適應機制，使安全狀態能隨著新威脅與使用情境動態更新，而不需要離線重新訓練。最後，從理論上分析狀態路由的穩定性、可解釋性與對抗性魯棒性，並將 MARCH 介面推廣到更多互補架構，將是實現「內在安全」長遠願景的重要課題。

## 實務應用指南

### 適用場景

1. **長時間互動的企業客服與個人助理**  
   適合需要記住數十輪對話、使用者偏好與過往問題脈絡的場景。MARCH 的脈絡衍生狀態錨點能讓模型在長對話中選擇性召回早期資訊，而安全狀態可在不凍結骨幹網路的情況下持續抑制越獄攻擊。

2. **長程式碼開發與複雜推理助手**  
   在長檔案、多檔案程式碼庫或數學競賽級推理中，模型需要維持長程狀態並回溯先前推論步驟。Safin-1 的記憶路由與狀態演化有助於維持長推理軌跡，減少中間資訊被覆蓋的問題。

3. **金融、法律與醫療合規文件分析**  
   這類領域需要同時處理超長文件（128K 等級）並遵守嚴格行為約束。安全狀態可作為持久能力狀態，內建於模型原生計算中，降低機密或有害回覆的風險，同時減少過度拒答。

4. **多輪創意協作與教育輔導**  
   當使用者與模型進行長時間寫作、設計或教學互動時，持久能力狀態可儲存風格、目標與學習進度，並透過內容條件化路由在適當時機啟用。

5. **結合內部知識庫的 RAG 與企業搜尋**  
   將 MARCH 作為模型內部的結構化記憶基質，與外部向量資料庫互補：外部檢索負責跨會話知識，內部狀態錨點負責當前長脈絡中的精細召回與推理銜接。

### 實作步驟建議

1. **選擇並修改骨幹網路**  
   在選定的基礎模型（如 Gated DeltaNet、Kimi Delta Attention 或 Qwen3.5 系列）中整合 MARCH 層，加入週期性狀態檢查點與狀態感知路由鍵。

2. **持續預訓練建立共享基礎**  
   使用領域與長脈絡資料進行持續預訓練，讓模型學會維護與檢索結構化記憶狀態，同時保持通用能力。

3. **監督式微調強化能力**  
   針對目標任務（推理、長脈絡理解、情境內檢索）進行監督式微調，形成穩定的 Safin-1 檢查點。

4. **設計並訓練持久能力狀態**  
   凍結語言模型骨幹，僅學習一或多個持久能力狀態。例如安全狀態可從有害與良性範例中學習，並透過現有路由器決定每個詞元的貢獻。

5. **建構狀態錨點庫與路由機制**  
   實作狀態錨點的儲存、內容條件化檢索與稀疏路由；提供附加／移除能力狀態的介面，讓不同專門化狀態可在測試時適應而不改動骨幹。

6. **全面評估**  
   在通用能力基準、LongBench、RULER NIAH、真實情境內檢索、越獄攻擊成功率與過度拒答率上進行評估，確認沒有顯著犧牲效用。

7. **部署與監控**  
   上線時啟用安全狀態，並持續監控長序列下的延遲、記憶體使用與異常輸出。保留狀態卸除與備用外部防護機制，以應對未預期風險。

8. **迭代更新**  
   隨著新威脅出現，可單獨更新持久安全狀態或新增其他能力狀態，而無需重新訓練整個基礎模型。

### 潛在風險與注意事項

- **安全–效用權衡**  
  安全狀態雖能降低越獄成功率，但仍可能增加過度拒答。建議透過紅隊測試與良性查詢集持續衡量，並調整狀態強度。

- **狀態庫的記憶體與計算開銷**  
  儲存大量狀態錨點會增加推論記憶體。可透過稀疏狀態路由與狀態壓縮緩解，但需驗證長序列外推能力是否下降。

- **路由不穩定或錯誤召回**  
  內容條件化路由可能選錯歷史狀態，導致幻覺或行為不一致。應加入路由可解釋性分析與異常偵測。

- **持久狀態被繞過**  
  針對安全狀態的對抗性攻擊可能隨時間演進，需要定期紅隊測試與狀態更新，而非僅依賴單一內部狀態。

- **災難性遺忘與狀態干擾**  
  新增多個持久能力狀態時，可能互相干擾。建議分階段驗證每個狀態對通用能力的影響。

- **過度依賴內建安全而忽略外部防護**  
  「內在安全」是願景而非萬靈丹，現階段仍應搭配輸出過濾、監控與人類回饋機制作為縱深防禦。

- **實驗性質**  
  論文本質是初步架構探索，大規模部署前應在真實環境中進行充分驗證。
