REA（Routed Embodied Agent，路由式具身代理）的核心設計動機源於一個關鍵觀察：當前具身智慧（embodied intelligence）領域存在兩類互補但難以整合的系統——以基礎模型（foundation models）為代表的審議式大腦（deliberative brain / System 2），以及以視覺-語言-動作模型（VLA）與全身控制器（whole-body controllers）為代表的反應式小腦（reactive cerebellum / System 0）。前者推理能力強但速度慢、成本高；後者執行效率高但泛化能力有限。REA 提出將兩者透過一個具身路由器（embodied router / System 1）統一在同一運行時（runtime）中，並以一條「黃金法則」（golden rule）作為設計準則：**任何運行中的策略都不應等待大腦**（no running policy waits on the brain）。

**三層契約（Three-Level Contract）**

REA 的架構由三個層級組成，每層有明確的職責分工：

1. **System 2（審議式大腦）**：以基礎模型代理（agent）形式存在，可離線或在線生成策略、提供建議（advice）或進行判斷（judge）。其角色是「備援」而非「主控制器」，僅在必要時被諮詢。
2. **System 1（具身路由器）**：核心調度層，負責決定執行哪個策略、何時諮詢大腦，且不阻塞正在運行的策略。這是 REA 區別於傳統代理迴圈（agentic loop）的關鍵設計。
3. **System 0（反應式小腦）**：包含凍結程式（frozen programs）、VLA 策略或全身控制器等快速策略，在片段（segment）或策略邊界（policy boundary）將控制權交還路由器。

**三大核心機制**

**(1) 路由記憶（Route Memory）**：REA 在開發階段（development episodes）預先測量每個策略在每個任務上的成功率與成本，並將結果存入路由記憶。這使得策略選擇可以脫離 System 2 的推理過程，僅在遇到「兩難情境」（dilemma）時才呼叫大腦。這一設計直接解決了「代理驅動並呼叫快速策略」時快速迴圈被阻塞的問題——實驗數據顯示，傳統的阻塞式顧問（blocking advisor）每個 LIBERO-Pro 回合讓機器人閒置 2.6 秒，佔控制時間的 20%。

**(2) 邊界觸發判斷閘（Boundary-triggered Judge Gate）**：針對「快速策略驅動並在錯誤時呼叫代理」模式中靜默失敗（silent failures）難以捕捉的問題，REA 設計了在策略執行邊界（非錯誤觸發）並行諮詢 System 2 的機制。判斷閘決定任務是否完成：若已完成則停止並保護已完成的工作（避免重複執行導致成功狀態被撤銷）；若未完成則啟動升級。這解決了兩個常見問題：(a) 持久性錯誤反覆觸發大腦；(b) 多數失敗無明確錯誤訊號。實驗中，例外觸發式路由器（exception-triggered router）在 590 個 LIBERO-Pro 回合中僅升級 6 次，儘管有 166 次失敗——凸顯了邊界觸發設計的必要性。

**(3) 共享預算升級階梯（Shared-budget Escalation Ladder）**：為避免恢復過程無限循環，REA 在一個共享的步數與時間預算（shared step and time budget）下，從當前狀態派遣下一個策略。這確保恢復是有界的（bounded recovery），且不同策略間的資源調度是統一而非各自獨立的。

**非同步執行模式（Asynchronous Mode）**

除了傳統的序列執行模式，REA 還提供非同步模式：策略以各自速率運行，System 2 並行提供建議或判斷。這使得大腦的推理時間與小腦的執行時間可以重疊，進一步降低整體延遲。

**對齊評估協議（Aligned Evaluation Protocol）**

REA 同時提供一個統一的評估框架，使程式碼策略（code-as-policies）與 VLA 策略能在相同的模擬器、機器人、觀測格式與成功標準下進行比較。這填補了現有研究中「代理系統與 VLA 系統各自在不同技術棧上開發與評分」的空白。

**主要結果：LIBERO-Pro 基準**

在 60 個 LIBERO-Pro 任務、共 3,000 個測試回合上，REA 達到 95.9% 的成功率，超越最強單一基線 Agents SDK + GPT-6 的 94.7%（p=0.004），且僅落後於一個「事後諸葛亮」式的逐任務 oracle（oracle with hindsight）不到 1%。在效率方面，REA 是最快的計時方法，控制時間比 Agents SDK + GPT-6 少 17%，比阻塞式顧問少 25%。這組數據說明三件事：(a) 路由策略確實能從策略池（policy pool）中提取超越任何單一策略的表現；(b) 效率提升並非以成功率為代價，反而同步改善；(c) 與理論上限的差距僅 1%，說明框架已接近該策略池下的最優解。

**失敗恢復能力**

REA 將 ASPIRE 策略提升 +8.6%，將零樣本 GPT-6 策略提升 +7.0%。判斷閘機制（judge gating）相較於例外觸發式路由器額外帶來 +3.1% 的提升。這些消融數據（ablation data）清楚展示了各機制的增量貢獻：路由記憶解決了「選擇最優策略」的問題，判斷閘解決了「何時停止與升級」的問題，升級階梯解決了「如何有效恢復」的問題。

**跨方法整合能力**

REA 能在同一運行時中同時運作學習型策略（learned policies，如 VLA）與程式化策略（programmatic policies，如程式碼生成）。在 RoboTwin 2.0 的 100 回合研究中，REA 搭配 VLA 達到 84%，搭配 VLA+程式碼達到 86%，均超越最強單一 VLA 基線 MEDex 的 80%。這證明了 REA 的策略無關性（policy-agnostic）——它不綁定特定類型的策略，而是作為一個通用的協調層。

**擴展性驗證**

REA 成功轉移至 BEHAVIOR-1K 基準（日常家務任務模擬）以及真實的 Unitree G1 人形機器人，在所有比較方法中達到最高觀察成功率。此外，在 AlohaMini2 雙臂操作平台上進行了四方法比較的真實世界方塊放置實驗。這些結果說明 REA 並非僅在特定模擬器中有效，而是具有跨平台、跨機器人類型的泛化能力。

**速度細節（Speed Details）**

附錄 A.1 提供了詳細的速度分析。從摘要與正文可知，REA 的控制步數（control steps）減少 25%、控制時間（control time）減少 17%，這主要歸功於：(a) 路由記憶避免了不必要的代理呼叫；(b) 非同步模式使大腦推理與小腦執行並行；(c) 邊界觸發判斷閘避免了反覆升級的浪費。

**視覺判斷校準（Visual-Judge Calibration）**

附錄 B.5 探討了視覺判斷器的校準過程。由於判斷閘依賴視覺模型判斷任務是否完成，判斷器的準確性直接影響系統表現。校準過程確保判斷器在「假陽性」（誤判完成）與「假陰性」（漏判完成）之間取得平衡，避免過早停止或無謂升級。

#### 與現有研究的比較

**定位**

REA 處於「雙系統機器人模型」（dual-system robot models）的研究脈絡中，與近期工作如 [13-17] 有共同的出發點——分離審議式推理與反應式控制。然而，REA 的獨特貢獻在於：(a) 提供統一的運行時而非鬆散的組合；(b) 解決非同步協調的具體技術挑戰；(c) 提供對齊的評估協議使跨方法比較成為可能。

**相較於代理驅動方法（Agent-driven methods）**

傳統代理方法（如 ASPIRE、Codex + GPT-6 管道）在 LIBERO-Pro 上表現出色但成本極高——ASPIRE 的修復迴圈每個任務中位耗時 43 分鐘，Codex + GPT-6 管道為 60 個任務消耗 89M 輸入 tokens。REA 透過路由記憶將這些昂貴的代理呼叫從關鍵路徑上移除，僅在必要時觸發，從而大幅降低成本同時維持或提升成功率。

**相較於 VLA 方法**

VLA 模型（如 [7-10]）在標準 LIBERO 上可超過 90%，但在 LIBERO-Pro 的擾動測試集上表現崩塌。REA 將 VLA 視為策略池中的一員，透過路由器在 VLA 失敗時升級到其他策略，從而緩解 VLA 泛化能力不足的問題。實驗中 REA 將 VLA 策略的表現從 80%（MEDex）提升到 84-86%。

**相較於單標記 VLM 基線（One-Token VLM Baseline）**

附錄 C.4 探討了將 VLM 直接作為小腦（即每步輸出一個動作標記）的可能性。結果顯示這類方法在 LIBERO-Pro 上幾乎完全失敗（單標記方法解決 1/1,987 回合，笛卡爾 IK 方法解決 0/600 回合）。這凸顯了「基礎模型不適合作為細粒度控制器」（fine-grained controllers）的核心論點，也證明了 REA 將大腦與小腦分離的設計正當性。

**相對於 Show-Harness 基線**

附錄 C.3 提供了 Show-Harness 基線的對比，進一步驗證 REA 的改進並非來自於評估框架的調整，而是來自於運行時設計本身的優勢。

**限制與不足**

儘管 REA 表現出色，仍存在以下限制：

1. **路由記憶的預先測量成本**：路由記憶需要在開發階段對每個策略在每個任務上進行測量，這本身需要一定的計算資源。對於新任務或新策略的冷啟動（cold start）場景，路由記憶可能不準確或不存在。
2. **策略池的覆蓋範圍**：REA 的表現上限受策略池中策略的品質限制。若所有可用策略在某任務上均失敗，REA 也無法成功。
3. **視覺判斷器的依賴**：判斷閘的有效性依賴視覺判斷模型的準確性。若判斷器本身有偏誤，可能導致過早停止或無謂升級。
4. **真實機器人實驗規模有限**：Unitree G1 與 AlohaMini2 的實驗規模相對較小，未充分展示在更複雜真實場景中的穩定性。

REA 開啟了多個值得深入探索的研究方向：

**1. 路由學習的自動化**

當前的路由記憶依賴預先測量，未來可探索：(a) 利用線上學習（online learning）動態更新路由記憶；(b) 使用元學習（meta-learning）使路由器能快速適應新任務；(c) 引入不確定性估計（uncertainty estimation）來處理路由記憶不準確的情況。

**2. 策略池的擴展與組合**

REA 目前假設策略池是預先定義的，未來可探索：(a) 自動發現與生成新策略（如透過大型語言模型自動編寫程式碼策略）；(b) 策略間的動態組合（如將 VLA 的運動控制與程式碼的任務規劃即時組合）；(c) 跨機器人遷移的策略適配。

**4. 非同步模式的理論分析**

REA 的非同步模式雖然實驗有效，但缺乏理論分析。未來可：(a) 建立非同步協調的延遲與成功率權衡模型；(b) 分析不同策略速率下的最優排程策略；(c) 探討在資源受限（如邊緣計算）場景下的非同步設計。

**5. 安全與可靠性**

在真實機器人部署中，安全至關重要。未來可：(a) 引入安全約束到升級階梯中（如避免某些危險動作）；(b) 設計故障安全機制（fail-safe mechanisms）以處理判斷器或路由器本身的故障；(c) 探索形式化驗證（formal verification）以確保系統行為符合預期。

**6. 人機協作**

REA 的三層架構天然適合人機協作場景。未來可：(a) 將人類納入 System 2（如人類提供高階指導）；(b) 設計人類干預介面（如在判斷閘不確定時請求人類確認）；(c) 探索從人類示範中學習路由策略。

**7. 跨領域遷移**

REA 在機器人操作任務上表現出色，未來可探索其在其他具身領域的應用，如：(a) 自動駕駛（審議式路徑規劃 + 反應式車輛控制）；(b) 家庭服務機器人（任務級推理 + 操作級控制）；(c) 工業自動化（流程優化 + 即時控制）。

**8. 基準與評估的標準化**

REA 的對齊評估協議是重要貢獻，未來可推動：(a) 建立跨方法、跨機器人的統一基準；(b) 定義標準化的成本與延遲指標；(c) 推動社群採用統一的評估協議以促進公平比較。

## 論文問答

**Q1：REA 主要解決了什麼核心問題？為何這個問題在具身智能領域如此重要？**

A：REA 試圖解決「審議式大腦（基礎模型代理）」與「反應式小腦（VLA 與全身控制器）」之間無法有效協作的難題。基礎模型雖然具備強健的高階推理能力，但運行速度慢、成本高昂，無法直接作為細粒度控制器；反之，VLA 與全身控制器雖然反應迅速，卻在面對擾動或未見情境時容易失效。這個問題之所以關鍵，是因為真實世界的機器人任務既需要長程推理（拆解任務、判斷成功），也需要即時反射動作（避障、抓取），單一系統無法兼顧。REA 透過統一運行時框架，讓兩種互補的智能體在同一架構下協作，這對推動通用具身智能至關重要。

**Q2：為什麼現有方法（純基礎模型代理或純 VLA）會失敗？**

A：純基礎模型代理的失敗來自速度與成本：根據本文實測，ASPIRE 的修復迴圈在 LIBERO 任務上單次中位數耗時 43 分鐘，而 Codex + GPT-6 流程為 60 個 LIBERO-Pro 任務產生程式碼就消耗了 89M 輸入 token。更糟的是，當模型被要求直接輸出一標記或笛卡兒 IK 動作時，在 1,987 個 LIBERO-Pro 回合中僅成功 1 次，600 個回合中成功 0 次。另一方面，純 VLA 在標準 LIBERO 上雖可超過 90%，但在 LIBERO-Pro 的擾動測試集上表現崩潰，顯示其泛化能力不足。兩類方法各有致命缺陷，說明單一系統無法勝任具身控制的全部需求。

**Q3：將審議式大腦與反應式小腦結合時，存在哪兩個主要障礙？**

A：第一個障礙是缺乏統一的運行時與評估協議——代理型系統與 VLA 型系統各自建立在不同的模擬器、機器人、觀測格式與成功準則上，難以在同一回合上公平比較。第二個障礙是非同步協調極為困難：當代理主導並呼叫快速策略時，快速迴圈會被代理的每次決策阻塞（實測中代理顧問讓機器人在每個 LIBERO-Pro 回合閒置 2.6 秒，佔控制時間的 20%）；反之，當快速策略主導並在錯誤時呼叫代理時，會反覆觸發回退，且大多數失敗根本不會引發錯誤訊號（例外觸發路由器在 590 回合中僅升級 6 次，卻有 166 次失敗）。這兩個障礙使得「腦—小腦」雙系統架構雖直觀卻難以落地。

**Q4：REA 的核心架構是什麼？三層系統如何分工？**

A：REA 採用三層契約架構：System 2（審議式大腦）由代理組成，可離線或線上生成策略、提供建議或進行判斷；System 1（具身路由器）決定執行哪個策略以及何時諮詢大腦，但不會阻塞正在運行的策略；System 0（反應式小腦）承載快速策略（凍結程式、VLA 策略或全身控制器），在片段或策略邊界將控制權交還路由器。這種分工讓高階推理與低階執行得以解耦，並透過統一的介面契約實現跨模擬器與跨機器人的可移植性。值得注意的是，REA 同時支援傳統的序列執行模式與非同步模式，使 System 2 能與執行中的策略並行運作。

**Q5：REA 的「黃金法則」是什麼？為何這個設計如此關鍵？**

A：黃金法則是「無運行中的策略需等待大腦」（no running policy waits on the brain）。這個設計的關鍵在於它從根本上避免了阻塞問題：傳統代理迴圈中，VLA 必須等待代理決策才能繼續動作，導致機器人長時間閒置；而 REA 透過讓大腦預先準備策略、僅在必要時介入，使快速策略能以自身節奏持續執行。實驗結果顯示，遵循此法則使 REA 比阻塞式顧問減少了 25% 的控制步數與 17% 的控制時間。這項原則也體現了 REA 的設計哲學——將大腦從派遣路徑上移開，僅在邊界或困境時介入。

**Q6：REA 的三大關鍵設計（路由記憶、判斷閘、升級階梯）各自扮演什麼角色？**

A：路由記憶（Route Memory）預先儲存每個策略在各任務上的成功率與成本，使路由器能在不諮詢大腦的情況下快速選擇策略，僅在面臨兩難時才呼叫 System 2。邊界觸發判斷閘（Boundary-triggered Judge Gate）在策略執行的邊界並行諮詢 System 2 來判斷任務是否完成——若已完成則停止並保護成果，若未完成則升級，從而避免反覆觸發回退或錯過靜默失敗。共享預算升級階梯（Shared-budget Escalation Ladder）在統一的步數與時間預算下，從當前狀態派遣下一個策略，確保恢復過程有界且可預測。這三者共同實現了「快速執行、智慧介入、有界恢復」的目標。

**Q7：REA 在哪些基準上進行了評估？主要的實驗設定為何？**

A：REA 在多個基準上進行了廣泛評估：核心實驗涵蓋 LIBERO-Pro 的 60 個任務共 3,000 個測試回合；擴展實驗包括 RoboTwin 2.0 的 100 回合研究與 BEHAVIOR-1K；真實機器人實驗則在 Unitree G1 人形機器人與 AlohaMini2 雙臂平台上進行。這種跨模擬器與跨機器人的評估設計，是為了驗證 REA 作為統一運行時的可移植性。實驗同時比較了學習型策略（VLA）與程式化策略（程式碼），並納入 MEDex、Agents SDK + GPT-6、ASPIRE 等強基線作為對照。

**Q8：REA 的關鍵性能成果為何？相較於基線有哪些具體改進？**

A：在 LIBERO-Pro 上，REA 達到 95.9% 的成功率，超越最強單一基線 Agents SDK + GPT-6 的 94.7%（p=0.004），且距離事後每任務 oracle 僅差 1%。在效率方面，REA 是最快的計時方法，控制時間比 Agents SDK + GPT-6 少 17%，比阻塞式顧問少 25%。在失敗恢復方面，REA 使 ASPIRE 與零樣本 GPT-6 策略分別提升 8.6% 與 7.0%，判斷閘機制單獨貢獻了 3.1% 的增益。在 RoboTwin 2.0 上，REA 以 VLA 策略達到 84%、以 VLA+程式碼達到 86%，優於最強單一 VLA 基線 MEDex 的 80%。

**Q9：消融研究揭示了哪些增益來源？各元件的相對貢獻為何？**

A：消融研究顯示增益來自三個層面：首先，路由機制本身優於各策略生成基線，證明「選擇合適策略」比「生成更好的單一策略」更有效。其次，路由記憶顯著減少了等待代理的時間——沒有路由記憶時，路由器會反覆諮詢 System 2，導致嚴重阻塞。第三，判斷閘在例外觸發機制之外額外貢獻 3.1% 的成功率，因為它能捕捉靜默失敗並保護已完成的工作。此外，跨方法研究顯示 REA 能同時改善來自不同方法（ASPIRE、GPT-6 等）的策略，證明其作為運行時的通用價值，而非僅對特定策略有效。

**Q10：REA 適用於哪些實際應用場景？**

A：REA 適用於任何需要長程推理與即時控制並存的機器人任務，例如家庭服務機器人（整理房間、烹飪輔助）、工業協作機器人（複雜裝配、異常處理）以及人形機器人的全身操控（如 Unitree G1 走向並推動椅子的實驗）。在這些場景中，任務往往包含多個子目標、需要應對環境擾動，且對延遲敏感。REA 的統一運行時讓開發者能混合使用程式化策略（處理結構化子任務）與 VLA 策略（處理感知豐富的子任務），並透過路由器自動選擇最佳組合，這對實際部署的機器人系統特別有價值。

**Q11：REA 如何實現跨機器人與跨模擬器的可移植性？**

A：REA 的可移植性來自其抽象化的三層契約：System 0 只需提供「執行片段並在邊界返回」的介面，System 1 只需根據路由記憶與判斷閘做派遣決策，System 2 只需提供建議或判斷。這種設計讓同一個 REA 運行時能在 LIBERO-Pro（桌面操作）、RoboTwin 2.0（雙臂操作）、BEHAVIOR-1K（日常家務）與真實機器人（Unitree G1、AlohaMini2）上運作，而無需修改核心邏輯。實驗中 REA 在所有這些平台上都達到了「觀察到的最高成功率」，證明了其架構的通用性。

**Q12：REA 對機器人開發的實務影響為何？**

A：REA 對機器人開發的實務影響體現在三方面：第一，它降低了整合成本——開發者無需從頭設計代理與 VLA 的協調機制，可直接使用 REA 的運行時。第二，它提升了系統可靠性——透過路由記憶預先評估策略、判斷閘捕捉靜默失敗、升級階梯限制恢復成本，使系統行為更可預測。第三，它支援異質策略共存——學習型策略（VLA）與程式化策略（程式碼）可在同一運行時中協作，這對實際產品開發特別重要，因為不同子任務往往適合不同類型的策略。這些特性使 REA 成為從研究原型走向產品部署的橋樑。

**Q13：REA 存在哪些已承認的限制？**

A：REA 的限制主要來自其依賴的元件：首先，路由記憶的品質受限於開發回合的覆蓋率——若某個任務在開發階段未被充分探索，路由器可能缺乏可靠的先驗資訊。其次，判斷閘的效果取決於 System 2 視覺判斷器的校準品質，若判斷器本身有偏差，可能導致誤判完成或漏判失敗。第三，REA 目前主要在受控模擬器與有限真實機器人上驗證，面對高度動態的真實環境（如人群互動、極端光照）時，其表現仍待檢驗。最後，黃金法則雖然避免了阻塞，但也意味著 System 2 必須能容忍「延遲介入」，這對某些需要即時糾正的場景可能不夠。

**Q14：REA 在哪些情況下可能失敗？有哪些已知的邊界案例？**

A：REA 的失敗案例可能發生在以下情境：當所有可用策略在某任務上都失敗時，路由記憶無法提供有用指引，升級階梯會在預算耗盡後停止；當判斷閘的視覺判斷器對完成狀態產生誤判時，可能過早停止（導致任務未完成）或過晚停止（浪費預算）。此外，若任務需要嚴格的即時反應（例如快速避障），而非同步模式可能仍不足以滿足延遲需求。從實驗數據看，REA 在 LIBERO-Pro 上仍有約 4% 的失敗率，說明即使是最佳整合也無法達到 100% 成功率，這些剩餘失敗往往發生在多策略都無法處理的極端擾動下。

**Q15：REA 的未來研究方向為何？**

A：REA 的未來發展可能朝幾個方向延伸：第一，路由記憶可從靜態先驗擴展為線上學習，根據實際執行結果動態更新策略評估，這將提升在未見任務上的表現。第二，判斷閘可整合更豐富的多模態感知（如觸覺、力覺）以提升完成判斷的可靠性。第三，REA 的三層架構可擴展至多機器人協作場景，讓多個具身代理共享路由記憶與升級階梯。第四，黃金法則可進一步形式化，研究在哪些情境下允許「有限度的等待」是更優的取捨。第五，將 REA 與基礎模型的線上微調結合，使 System 2 能根據部署經驗持續改進，這將是通往更通用具身智能的重要一步。

- 具備視覺語言模型（VLM）作為判斷器的提示工程（prompt engineering）能力。

### 實作步驟建議

1. **定義三層契約（Three-Level Contract）**
   - 明定 System 0 策略的回傳介面：必須在「段邊界」（segment boundary）或「策略邊界」（policy boundary）回傳控制權，而非以錯誤或例外作為唯一信號。
   - 明定 System 1 路由器的決策介面：輸入為當前狀態與候選策略清單，輸出為下一個執行策略。
   - 明定 System 2 大腦的介入時機：僅在路由器主動諮詢時回應，不阻塞運行中的策略。

2. **建立策略池與路由記憶**
   - 為每個任務蒐集所有候選策略（VLA、程式化、混合）在開發回合上的成功率、平均步數、平均時間。
   - 將這些指標存入路由記憶表，路由器據此選擇「預期成功率最高且成本最低」的策略。
   - 設計「匹配困難子集」（matched hard subset）以驗證路由選擇的穩健性。

3. **實作邊界觸發判斷閘（Boundary-Triggered Judge Gate）**
   - 在每個策略執行結束的邊界，並行呼叫 System 2 的視覺判斷器判斷任務是否完成。
   - 若判斷為「未完成」，觸發升級階梯；若判斷為「完成」，立即停止並保護已完成的工作，避免重複執行導致狀態破壞。
   - 校準視覺判斷器：使用視覺判斷校準（visual-judge calibration）資料集調整誤判率。

4. **設計共享預算升級階梯（Shared-Budget Escalation Ladder）**
   - 為每個回合設定總步數與總時間預算，所有策略升級共享此預算。
   - 升級順序可由路由記憶決定：先嘗試低成本策略，失敗後依序升級至較高成本或較可靠的策略。
   - 預算耗盡則終止並回報失敗。

5. **整合非同步執行模式**
   - System 2 在背景執行政策生成或判斷，不阻塞 System 0 的即時控制迴圈。
   - 使用訊息佇列或事件驅動架構連接三層，確保「無運行中的策略需等待大腦」的黃金法則。

6. **採用對齊評估協議（Aligned Evaluation Protocol）**
   - 統一觀察格式、成功準則、控制步數與時間的計量方式。
   - 在 LIBERO-Pro、RoboTwin 2.0、BEHAVIOR-1K 上使用相同回合數（建議每任務 ≥ 50 回合）進行評估。

7. **部署至實體機器人**
   - 先在模擬器驗證三層契約與路由記憶的正確性。
   - 移植至 Unitree G1 或 AlohaMini2 時，額外量測 System 1 路由決策的延遲（論文中路由器等待造成 2.6 秒/回合的閒置時間，需透過非同步設計消除）。
   - 進行真實世界的方塊放置等多方法比較，確認學習型與程式化策略在同一運行時下的相容性。

### 潛在風險與注意事項

1. **路由記憶的過時風險**：若部署環境漂移（光照、物件外觀變化），預先儲存的成功率可能失效。緩解：定期以新樣本更新路由記憶，或在路由器中加入信心區間，信心低時主動諮詢 System 2。

2. **視覺判斷器的誤判**：判斷閘可能將「未完成」誤判為「完成」而提前停止，或將「已完成」誤判為「未完成」而觸發不必要的升級。緩解：以視覺判斷校準資料集反覆調整提示與模型，並設置保守預設（預設為「未完成」以保護已完成的工作）。

3. **預算耗盡的連鎖失敗**：當升級階梯在某任務反覆失敗，整個回合預算可能被耗盡，導致其他任務也無法執行。緩解：為每個任務設定獨立預算，或在預算接近耗盡時切換至更保守的策略。

4. **System 2 成本失控**：若路由器過於頻繁諮詢大腦，雖然不阻塞控制迴圈，但 API 成本可能飆升。緩解：在路由記憶中記錄每次諮詢的成本，設定每回合諮詢次數上限。

5. **非同步通訊的競態條件**：System 2 的判斷結果可能在策略已切換後才送達，造成狀態不一致。緩解：為每個判斷請求加上時間戳與狀態快照，過期結果予以丟棄。

6. **跨模擬器移植的介面不相容**：不同模擬器的觀察空間與動作空間差異可能使 System 0 策略無法直接共用。緩解：在 System 1 與 System 0 之間加入適配層（adapter），將異質觀察統一為路由器可理解的表徵。

7. **重複執行的副作用**：若任務已完成但路由器未察覺而再次執行，可能破壞已完成的部分。緩解：判斷閘確認完成後立即凍結狀態，並在路由記憶中標記該任務為「已完成」。

### 與其他技術的整合建議

1. **與 ROS 2 整合**：REA 的三層契約可映射至 ROS 2 的節點（node）與主題（topic），System 0 為即時控制節點、System 1 為決策節點、System 2 為服務節點（service node），利用 ROS 2 的 DDS 通訊實現非同步協調。

2. **與 LangChain / Agents SDK 整合**：System 2 可直接以 Agents SDK + GPT-6 實作，論文中此組合達 94.7% 成功率；REA 在其上額外提升至 95.9% 並縮短 17% 控制時間。建議將代理的「規劃」與「判斷」拆分為兩個獨立工具，讓路由器可單獨呼叫。

3. **與 VLA 模型庫整合**：OpenVLA、π₀、RT-2 等 VLA 可直接作為 System 0 候選策略，無需修改模型本身，只需包裝符合三層契約的介面。

4. **與程式化策略框架整合**：ASPIRE、Code-as-Policies 等生成的程式碼策略可作為 System 0 的另一類候選，論文中 VLA+code 組合在 RoboTwin 2.0 達 86% 成功率，優於單一 VLA。

5. **與全身控制器整合**：SONIC 等全身控制器可作為人形機器人的 System 0，處理平衡與步態；System 2 負責長程任務規劃，System 1 負責兩者切換。

6. **與監控與可觀測性工具整合**：建議整合 Prometheus 或 OpenTelemetry，追蹤每回合的策略切換次數、判斷閘呼叫次數、預算消耗，以便持續優化路由記憶。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）了解「大腦—小腦」雙系統動機，再看圖 1 的三層架構示意；接著跳到第 4.2 節的路由結果，理解 REA 在 LIBERO-Pro 上 95.9% 成功率的意義。實作上可從單一任務、單一 VLA 開始，逐步加入路由器與判斷閘。

**給 AI 工程師**：重點研讀第 3 節（The REA Runtime）與附錄 B（The Router），特別是 Episode Loop、Route Memory 與 Judge Gate 的實作細節；附錄 C.4 的單標記 VLM 基線實驗（1/1987 成功率）凸顯了純大腦控制的不可行性，是理解「為何需要小腦」的關鍵證據。部署時優先處理非同步通訊與預算控制兩個工程難點。

**給研究者**：第 4.5 節「Where Do the Gains Come From?」的消融分析（判斷閘 +3.1%、路由記憶減少等待）是論文的核心貢獻；附錄 B.2 的匹配困難子集與 B.5 的視覺判斷校準提供了可重現的實驗設計。建議將 REA 框架擴展至其他雙系統機器人模型（如 HiRT、CoVLA），探討路由機制的泛化性。

**給產品經理**：REA 的價值在於「讓昂貴的大腦與便宜的小腦在同一系統中協同」，關鍵指標為：成功率（95.9% vs 94.7%）、控制時間縮短 17%、控制步數縮短 25%。在產品規劃上，可將 REA 視為「策略編排層」，向上對接任務規劃 API、向下相容既有 VLA 與控制棧；跨模擬器與實體機器人的可移植性（BEHAVIOR-1K、Unitree G1、AlohaMini2）降低了多平台部署的工程風險。
