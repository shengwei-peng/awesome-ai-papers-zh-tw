# Code-as-Room：透過代理式程式碼合成從俯視圖生成三維房間

## ⚡ TL;DR

現有方法從俯視圖生成完整三維房間時常不穩定且易陷入無限迴圈，文字亦難以精確表達空間資訊。
提出Code-as-Room，以結構化流程將俯視圖轉為Blender碼，分階段合成三維房間。
建立三維房間程式碼合成基準測試，實驗證明所提框架能穩定生成高品質且可執行的三維室內場景。

## 摘要翻譯

設計真實且具功能性的三維室內房間（3D indoor rooms）對於廣泛的應用至關重要，包括室內設計、虛擬實境（virtual reality）、遊戲與具身人工智慧（embodied AI）。儘管近期基於多模態大型語言模型（MLLM）的方法在從文字描述或參考影像進行三維房間合成（3D room synthesis）方面展現出巨大潛力，但基於文字的方法難以捕捉精確的空間資訊，而現有以影像為條件的代理（image-conditioned agents）在執行從俯視圖（top-down view）生成整體房間的任務時，存在不穩定性與無限迴圈（infinite looping）的問題。為克服這些侷限，我們提出 Code-as-Room，一個配備結構化執行架構（structured execution harness）的基於 MLLM 的代理式框架（agentic framework），其以 Blender 程式碼（Blender code）表示三維房間。給定一張房間俯視圖（top-down room image），該框架解析參考影像以提取場景元素（scene elements）及其空間關係（spatial relationships），並在一個系統化的多階段流程中，合成用於幾何（geometry）、材質（materials）與光照（lighting）的可執行的 Blender 程式碼（executable Blender code）。該框架於整個過程中維護一個跨階段記憶模組（cross-stage memory module），以緩解現有基於代理的框架（agent-based frameworks）所固有的上下文遺忘（context forgetting）問題。我們進一步提出一個專用於基於程式碼的三維房間合成之基準測試（benchmark），涵蓋多種評估協定（evaluation protocols）。基於此基準測試，本研究與現有基於代理的方法（agent-based methods）進行全面比較，以驗證所提出之執行架構（execution harness）的有效性。

### 核心貢獻（3～5點）
- 提出 Code-as-Room，一個基於 MLLM 的代理式框架，透過結構化執行架構以 Blender 程式碼表示三維房間，實現從俯視圖生成完整室內場景。
- 設計系統化的多階段流程，自動解析場景元素與空間關係，並合成涵蓋幾何、材質與光照的可執行 Blender 程式碼。
- 引入跨階段記憶模組，有效緩解現有基於代理的框架所固有的上下文遺忘問題。
- 建立專用於基於程式碼之三維房間合成的基準測試，提供多樣化的評估協定。
- 透過與現有基於代理的方法進行全面比較，驗證所提出執行架構的有效性與優越性。

### 適合對象
從事三維電腦視覺、室內場景合成、具身人工智慧、多模態大型語言模型與代理式系統，以及電腦圖學等領域的研究人員與開發者；特別適合關注以程式碼表徵場景（code-as-scene）、自動化三維內容生成，以及欲結合俯視圖進行結構化三維房間重建之讀者。

## 深度分析

#### 方法論解析

Code-as-Room（CaR）是一個以多模態大型語言模型（Multimodal Large Language Models, MLLMs）為核心的代理式框架（agentic framework），透過代理式程式碼合成（agentic code synthesis）與結構化執行框架（structured execution harness）將單張俯視圖（top-down view）轉譯為可執行的 Blender 程式碼（Blender code），從而實現三維房間合成（3D room synthesis）。不同於既有方法僅將 MLLM 視為單次預測器，CaR 將生成流程拆解為多個原則性階段，並透過跨階段記憶模組（cross-stage memory module）維持長程一致性。

第一階段為場景解析與場景圖（scene graph）建構。框架首先解析俯視圖，識別三大類別的場景元素：主要家具、附屬於其上的小配件，以及由門、窗、牆構成的室內裝修。接著，系統推論這些元素間的空間關係（spatial relationships），形成整體性的場景圖表徵。此步驟直接回應了文字驅動方法難以捕捉精確空間資訊的缺陷，將俯視圖所蘊含的全域空間先驗（global spatial prior）轉化為結構化的中間表徵。

第二階段為佈局程式碼生成與迭代精煉。基於場景圖，代理首先合成所有識別元素的佈局程式碼，隨後進入渲染-比對回饋迴圈（render-and-compare feedback loop）。在此迴圈中，MLLM 以其視覺識別能力比較渲染結果與原始參考圖像，逐步修正物件位置與整體空間排列。這個設計與 VIGA 的分析-合成迴圈（analysis-by-synthesis loop）有本質差異：CaR 的迴圈被約束在佈局精煉階段，且受惠於結構化執行框架的階段邊界，避免了既有程式碼代理（coding agent）在 holistic generation 時常見的無限迴圈（infinite looping）與不穩定輸出。

第三階段為物件屬性剖析（object profiling）。在佈局確立後，MLLM 針對每個組成三維物件（constituent 3D objects）推論其外觀、功能屬性與材質特性。這種延遲屬性推論的策略確保了物件細節不會干擾早期佈局決策，體現了「先結構、後外觀」的設計哲學。

第四階段為物件程式碼生成。代理根據剖析所得的屬性檔案，嚴格條件化地合成幾何與表面材質的 Blender 程式碼。對於具有複雜幾何細節的小尺度物件，框架引入資產檢索與三維物件生成作為輔助模組，彌補 MLLM 在精細幾何合成上的不足。

第五階段為室內裝飾與光照。系統生成紋理（texture）、材質與光照（lighting）程式碼，完成室內裝飾，顯著提升合成房間的感知美學與照片級真實感（photorealistic fidelity）。

貫穿全流程的關鍵機制是跨階段記憶模組。該模組持續儲存各階段輸出，有效緩解既有基於代理的框架（agent-based frameworks）中普遍的上下文遺忘（context forgetting）問題。這對於需要維持幾何、材質、光照一致性的三維室內房間（3D indoor rooms）合成尤為關鍵。

#### 實驗數據解讀

由於提供的文本未包含完整實驗數據表格，以下針對其宣稱的基準測試（benchmark）設計與評估邏輯進行解析。作者建構了一個專屬於基於程式碼的三維房間合成任務的基準測試，其評估協議（evaluation protocols）涵蓋四大維度：

首先是視覺內容理解（visual content understanding）。此維度評估 MLLM 代理是否能正確識別俯視圖中的場景元素類別與數量。不同於一般圖像生成任務僅評估最終像素品質，此指標直接檢驗代理對輸入條件的忠實度，確保生成的三維室內房間不會遺漏或幻覺化關鍵家具。

其次是空間關係推理（spatial relationship reasoning）。俯視圖的核心價值在於編碼精確的空間資訊，因此基準測試必須量測生成場景中物件的相對位置、朝向（orientation）與佈局拓撲是否與輸入對齊。這是 CaR 相較於文字驅動方法的主要優勢所在，因為文字描述難以指定「精確位置」與「詳細朝向」。

第三是視覺到程式碼生成能力（vision-to-code generation capability）。此為該任務的獨特挑戰：評估生成的 Blender 程式碼是否可執行、完整，且能正確實例化幾何、材質與光照。這不僅是語法正確性檢查，更涉及程式碼語義與視覺意圖的一致性。

第四是場景品質（scene quality），包含視覺品質與功能合理性。作者提及與現有基於代理的方法（existing agent-based methods）進行全面比較，以驗證結構化執行框架的有效性。從方法論推斷，CaR 應在生成穩定性（避免無限迴圈）與空間對齊度上顯著優於 VIGA 等自由迭代代理，而在視覺豐富度上超越純粹佈局優化的傳統方法。

#### 與現有研究的比較

相較於傳統電腦圖學方法，CaR 擺脫了程序化生成（procedural generation）、規則或約束驅動的物件擺放（constraint-driven object placement）對手工規則與預定義類別的依賴。早期方法雖能透過室內設計準則與人體工學目標優化佈局，但面對複雜真實世界的空間關係與彈性使用者需求時顯得僵化。

在 MLLM 驅動的範疇中，現有研究大致可分為文字驅動與代理式兩類。Holodeck、LLplace、LAYOUTVLM 與 I-Design 等方法將場景表示為 JSON 或其他結構化格式，依據語言指令預測空間佈局與物件屬性。然而，文字描述本質上難以傳達精確的室內空間資訊，導致生成結果常與使用者偏好錯位。CaR 以俯視圖作為全域空間先驗，直接將視覺佈局轉譯為三維空間，解決了文字條件化的根本限制。

在代理式框架方面，SceneWeaver 採用自我反思代理（self-reflective agent）協調多種生成工具；SAGE 結合場景生成器與評論者（critic）以產生適用於具身智慧的模擬環境；SceneSmith 則使用階層式視覺語言模型（VLM）代理逐步建構室內場景。儘管這些方法引入工具使用與回饋迴圈，它們本質上仍以文字或高層任務為驅動，對於「以房間層級圖像作為直接條件」的應用場景探索不足。

與 CaR 最直接相關的是 VIGA，其開創了 Code-as-scene 典範，以程式碼代理生成可執行的 Blender 程式碼來建構三維場景。然而，VIGA 針對透視圖（perspective images）設計，當天真地擴展至俯視圖的完整房間生成時，不僅難以恢復細粒度空間細節，更容易陷入無限迴圈，導致不穩定且不可靠的輸出。CaR 透過結構化執行框架明確劃分解析、佈局、剖析、生成、裝飾等階段，並以跨階段記憶模組維持上下文，從根本上抑制了代理的發散行為。

儘管如此，CaR 仍存在若干侷限。俯視圖本質上缺乏高度資訊，且可能因遮擋造成歧義；對於複雜小配件，框架仍需仰賴外部資產檢索或三維物件生成模組，未能完全由程式碼代理自主解決；此外，多階段 MLLM 呼叫與迭代渲染-比對流程可能帶來顯著的計算延遲與 API 成本。

#### 可重現性評估

根據目前提供的文本，作者並未明確提及是否開源釋出原始碼、基準測試資料集或模型權重，這對研究社群的完全重現構成一定挑戰。然而，該方法具備若干有利於重現的特性：其生成目標為 Blender 程式碼，而 Blender 本身為開源軟體；核心依賴現成 MLLM 的推理能力，無需從頭訓練專屬模型，降低了硬體門檻。

若要達成嚴格的可重現性，以下組件必須公開：首先是基準測試（benchmark）的完整資料集與評分腳本，特別是針對視覺內容理解、空間關係推理與視覺到程式碼能力的量化指標；其次是結構化執行框架中各階段的提示模板（prompt templates），因為代理行為高度依賴提示設計；第三是渲染-比對回饋迴圈的具體實作細節，例如比較時使用的渲染視角、解析度與判斷準則；最後是跨階段記憶模組的資料結構與讀寫協議。缺少這些細節，其他研究者雖能複製概念，卻難以復現相同的穩定性與生成品質。

#### 未來研究方向

第一，多視角條件化生成。當前 CaR 僅接受單張俯視圖，未來可探索融合俯視圖與透視圖，甚至使用者提供的環繞影像或影片，以解決單一視角的高度歧義與遮擋問題。

第二，即時互動式設計工具。現有流程為批次式（batch）多階段管線，未來可發展為支援設計師即時介入的互動式系統，例如允許使用者在任何階段修改場景圖或調整物件屬性，並透過增量更新而非全量重算來降低延遲。

第三，強化程式碼代理的幾何生成能力。目前對於複雜小配件仍需輔助資產模組，未來研究可聚焦於提升 MLLM 直接合成精細幾何細節的能力，或結合神經輻射場（NeRF）與程式化建模的混合表徵，減少對外部資產庫的依賴。

第四，具身智慧（embodied AI）整合。與 ProcTHOR、SAGE 等環境接軌，確保 CaR 生成的房間不僅在視覺上逼真，更具備物理正確性與功能合理性，例如確保門可開啟、通道寬度符合導航需求。

第五，記憶機制擴展。可探索將跨階段記憶模組與外部向量資料庫或圖資料庫結合，以支援更大規模、多房間甚至建築層級的場景生成，同時維持長程一致性。

第六，自動化評估精進。開發無需人工介入的自動化指標，特別是針對空間關係推理與程式碼語義正確性的精確量測，將有助於降低基準測試成本並加速迭代。

## 論文問答

**Q1：Code-as-Room 旨在解決三維室內房間合成領域中的什麼核心問題？**
A：Code-as-Room 主要解決如何自動生成既真實又具功能性的三維室內房間這一核心難題。傳統手動建模不僅勞力密集，還需要專業的三維物件建模、空間擺設與材質燈光調整知識；而傳統的程式化或規則驅動方法則受限於預定義類別與人工設計的規則，難以靈活處理複雜的真實空間關係。此外，現有的多模態大型語言模型方法在處理文字描述時缺乏精確空間資訊，而基於影像的代理框架在面對俯視圖進行整體房間生成時又容易出現不穩定與無限迴圈的問題。

**Q2：為何現有的文字驅動與影像條件式代理方法無法充分滿足三維房間生成的需求？**
A：文字驅動的方法依賴自然語言描述，但語言本質上難以精確傳達物件數量、確切位置與詳細朝向等室內空間資訊，導致生成結果常與使用者期望不符。另一方面，現有的影像條件式代理方法（如 VIGA）雖然在透視圖上展現潛力，但當擴展到俯視圖以進行整體房間生成時，不僅難以恢復細粒度的空間細節，更嚴重的是代理容易陷入無限迴圈，造成生成過程極不穩定。這些限制使得現有方法無法可靠地從視覺參考中重建完整且精確的三維室內空間。

**Q3：俯視圖影像引導對於實務上的三維房間設計流程為何特別重要？**
A：在真實的室內設計工作流程中，專業設計師經常以俯視平面圖、草圖或類地板規劃圖作為核心參考依據，因為這類影像本身就蘊含了豐富的空間先驗與整體場景外觀。相較於文字描述，這種視覺輸入能讓設計師在進入細部三維建模前，反覆迭代地確認空間佈局與物件安排，是更為直接且直觀的設計媒介。因此，讓系統能直接從俯視圖生成三維房間，可有效銜接傳統二維規劃工具與最終三維執行成果，大幅簡化整體設計管線。

**Q4：Code-as-Room 的核心方法論是什麼？它如何表達三維房間？**
A：Code-as-Room 是一個基於多模態大型語言模型的代理式框架，配備了結構化執行框架，並以可執行的 Blender 程式碼來表達完整的三維房間。給定一張俯視參考影像後，框架會系統性地解析場景元素，包括主要家具、附屬的小型配件以及門窗牆面等室內裝修，並推論其空間關係以建立整體場景圖表。隨後，這些結構化的理解會被轉譯為多階段的 Blender 程式碼，涵蓋佈局、幾何、材質與燈光，進而合成出完整的三維房間。

**Q5：結構化執行框架與跨階段記憶模組的關鍵創新之處為何？**
A：結構化執行框架透過原則性的多階段管線來編排代理行為，涵蓋佈局生成、渲染比對修正、物件特徵分析與材質合成等階段，從而避免了先前代理框架中常見的不穩定與無限迴圈問題。與此相輔相成的是跨階段記憶模組，它在整個管線中持續保存每個階段的輸出與決策，有效緩解了長程代理任務中普遍存在的上下文遺忘現象。這兩項機制協同運作，確保了基於俯視圖的三維房間合成過程既穩定又連貫，並能逐步精緻化。

**Q6：Code-as-Room 為何選擇合成可執行的 Blender 程式碼，而非使用 JSON 或其他結構化格式？**
A：合成可執行的 Blender 程式碼能讓框架直接在專業三維編輯環境中生成幾何形狀、表面材質與燈光配置，產出可立即編輯與渲染的資產。相較於 JSON 等靜態結構化格式僅能描述場景並需後續檢索或生成步驟，Blender 程式碼本身就同時編碼了空間佈局與精確的程式化或網格建構指令。這種 code-as-scene 典範不僅延續了 VIGA 等前作的概念，更提供了一種統一且可執行的表達方式，能自然支援透過渲染比對進行的迭代修正迴圈。

A：本文提出的專用基準測試針對基於程式碼的三維房間合成任務，除了評估視覺品質外，更嚴格檢視視覺內容理解、空間關係推理與視覺到程式碼的生成能力。現有的基準與評估協議並不足以衡量將俯視圖轉譯為可執行程式碼的獨特挑戰，因為它們往往忽略了幾何與空間排列的精確對應關係。建立此基準有助於系統性地比較各種多模態大型語言模型與代理框架，並以標準化指標驗證所提出之執行框架的有效性。

**Q8：與現有基於代理的方法進行全面比較後，關於 Code-as-Room 的有效性得出什麼結論？**
A：實驗結果顯示，相較於容易陷入無限迴圈且無法從俯視圖恢復細粒度空間細節的現有代理方法，Code-as-Room 在穩定性與生成品質上均達到更優異的表現。結構化執行框架使系統能夠維持連貫的多階段合成，而跨階段記憶模組則確保了整個管線的上下文一致性。這些比較充分驗證了所提出的執行框架對於可靠的基於程式碼之三維房間生成至關重要，特別是在處理來自視覺輸入的複雜整體房間佈局時。

A：Code-as-Room 可直接應用於專業室內設計工作流程，讓設計師快速將二維平面圖與俯視草圖轉換為 Blender 中完整且可編輯的三維房間模型。該框架也能服務虛擬實境與遊戲產業，透過自動化從佈局影像建立真實室內環境的過程，大幅縮短手動建模時間。此外，它還能支援具身人工智慧研究，生成具功能性且可模擬的三維房間，為訓練與評估智慧代理提供豐富的空間情境。

A：Code-as-Room 證明了結構化執行框架與跨階段記憶能夠穩定複雜的長程程式碼生成任務，從而為視覺內容創作領域的代理式人工智慧建立了超越單純文字或影像生成的新典範。其在視覺到程式碼轉譯上的成功，鼓勵未來發展更穩健的代理框架，以橋接二維視覺理解與可執行的三維內容，潛力可擴展至整棟建築或室外環境。對於具身人工智慧而言，能夠依據平面圖快速合成真實且基於程式碼的房間，有助於加速多樣化訓練環境的建構，進而培育更具泛化能力與空間感知能力的智慧代理。

**Q13：如文中所述，Code-as-Room 框架有哪些已知的限制？**
A：儘管論文展示了顯著進展，但框架依賴多模態大型語言模型代理進行程式碼生成，在面對極度複雜或雜亂的場景時，對於具有複雜幾何細節的小型配件仍可能面臨剖析能力不足的限制。多階段管線雖然具備結構，但其成效高度仰賴初始場景解析與場景圖表建構的準確性，早期階段的錯誤可能傳播並限制後續的修正空間。此外，迭代渲染與模型推論所帶來的運算開銷，也可能使其在即時應用或快速原型製作情境中受到侷限。

**Q14：當 Code-as-Room 處理具挑戰性的俯視房間影像時，可能出現哪些類型的失敗案例？**
A：當遇到模糊或嚴重遮擋的俯視佈局時，框架可能會誤判空間關係或混淆物件類別，例如將矮櫃與長凳錯認，導致產生錯誤的佈局程式碼與不合理的房間擺設。對於具有複雜幾何形狀的小型配件，即便輔以資產檢索模組，生成或檢索到的物件仍可能無法精確匹配從俯視圖推論出的視覺外觀。另外，若參考影像包含少見或非標準的房間形狀，偏離常見的訓練分佈，代理也可能產生重複或與情境不符的家具擺放結果。

A：未來研究可探索將結構化執行框架擴展至多房間或整層樓平面圖生成，超越單一房間合成，以掌握房間之間的連通性與建築一致性。將即時物理模擬與人體工學驗證整合進回饋迴圈，將能進一步提升生成房間的功能真實性，確保合成空間不僅視覺準確，更具實用居住性。此外，開發專為視覺到程式碼生成任務最佳化的輕量級微調視覺語言模型，也有助於降低推論成本，並改善對高度細緻或風格多樣室內場景的處理能力。

## 實務應用指南

### 適用場景

- **室內設計與裝潢提案**：設計師可將手繪或 CAD 輸出的平面配置圖、俯視圖直接轉為可互動的三維室內房間，用於客戶提案與空間驗證，縮短手動建模週期。
- **遊戲與虛擬實境場景量產**：遊戲美術與 VR 開發團隊能依據關卡設計師的俯視佈局圖，自動批次生成具備幾何、材質與燈光設定的 Blender 場景，再匯入遊戲引擎進行細部調整。
- **具身智慧訓練環境建置**：研究機構可基於真實空間的俯視圖，自動合成具備精確空間關係與物理屬性的三維房間，作為機器人導航與操作任務的模擬訓練場域。
- **房地產與租賃平台虛擬導覽**：將建物平面圖或現場空拍俯視圖轉為可漫遊的三維空間，搭配材質與照明程式碼生成，快速建立線上看屋的數位孿生場景。
- **建築與工程早期空間規劃驗證**：建築師在設計初期利用俯視草圖驗證家具動線、採光與空間比例，透過代理式程式碼合成即時產出可編輯的三維方案。

### 實作前置條件

- **資料準備**：需收集高解析度且比例正確的俯視圖或類平面圖影像作為輸入；同時建置或採購授權明確的三維物件資產庫（如家具、裝飾品），以支援資產檢索與生成輔助模組。
- **運算資源**：需配備具備充足 VRAM 的 GPU 伺服器，用於 MLLM 推理與 Blender 即時渲染；若採用雲端 API，需評估影像輸入的 Token 成本與頻繁呼叫的延遲。
- **技術與人力**：團隊需具備 Python 程式能力、Blender 腳本開發經驗，以及對電腦視覺與大型多模態模型（MLLM）API 串接的基礎認知；建議配置一名熟悉室內設計語彙的領域專家，負責驗證場景圖與空間關係的合理性。

### 實作步驟建議

1. **輸入標準化與前處理**：建立俯視圖影像的前處理管線，統一解析度、視角比例與色彩空間，確保後續 MLLM 能正確辨識主要家具、附屬小物件與門窗牆面等室內裝修元素。
2. **部署結構化執行框架**：將 MLLM 代理封裝於具備明確階段定義的執行框架（Execution Harness）中，設定每個階段的輸入輸出規格與終止條件，避免代理陷入無限迴圈。
3. **場景解析與場景圖建構**：讓代理分析輸入影像，提取物件類別、數量與空間關係，形成結構化的場景圖表示，作為後續程式碼合成的全局空間先驗。
4. **佈局程式碼生成與回饋修正**：先合成所有識別元素的佈局程式碼，啟動渲染比對迴圈（Render-and-Compare），利用 MLLM 的視覺辨識能力比較渲染結果與原始俯視圖，迭代修正物件位置與朝向。
5. **物件剖析與屬性推論**：在確定佈局後，針對每個物件推論其外觀、功能屬性與材質特性，建立詳細的物件輪廓（Object Profile），作為幾何與材質程式碼生成的嚴格條件。
6. **幾何與材質程式碼合成**：依據物件輪廓，讓代理生成 Blender 幾何建模與表面材質程式碼；對於幾何細節複雜的小物件，啟用輔助資產檢索或三維生成模組進行補強。
7. **紋理、材質與照明裝飾**：最後階段生成紋理映射、材質節點與室內燈光程式碼，提升合成房間的感知美學與擬真度。
8. **維護跨階段記憶模組**：在整個管線中持續運作跨階段記憶模組，儲存各階段輸出與中繼決策，防止代理因上下文長度限制而遺忘前期空間約束。
9. **自動化執行與產品整合**：建立自動化 Blender 批次執行環境，將輸出的程式碼轉為最終三維場景檔案，並銜接後製管線或遊戲引擎匯出工具。

### 潛在風險與注意事項

- **代理不穩定與無限迴圈**：現有基於代理的框架在處理全景房間生成時，容易因缺乏明確階段控制而反覆修正。務必實作結構化執行框架，為每個階段設定嚴格的完成條件與最大迭代次數上限。
- **上下文遺忘導致空間不一致**：隨著生成階段推進，MLLM 可能遺忘早期佈局決策。必須落實跨階段記憶模組，將場景圖、物件輪廓與已確認的程式碼片段持續餵入後續提示。
- **俯視圖細節損失**：俯視圖雖具全局空間資訊，但可能缺乏高度、垂直結構與細部紋理資訊。建議保留可選的透視參考圖或高度標註作為輔助輸入，或於後製階段由人工介入調整。
- **程式碼執行安全性**：自動生成並執行 Blender 程式碼存在潛在風險。應在沙箱環境或容器化空間中執行代理產生的腳本，避免檔案系統或網路層面的未授權操作。
- **資產授權與合規性**：若整合外部三維資產庫或生成模型，需確認商業使用授權條款，避免合成場景中的物件涉及版權爭議。

### 與其他技術的整合建議

- **CAD/BIM 軟體流程**：將 AutoCAD、Revit 或 SketchUp 輸出的平面圖直接作為俯視圖輸入；生成後的 Blender 場景可透過 FBX/USD 格式回傳至 BIM 管線，進行工程細部設計。
- **遊戲引擎管線**：將 Blender 輸出經由 glTF 或 FBX 匯入 Unity、Unreal Engine，銜接現有的關卡編輯、光照烘焙與物理模擬流程。
- **擴散模型與影像生成**：在輸入端整合文字轉影像或線稿轉彩現的擴散模型，讓設計師僅需文字描述即可產生俯視圖，再進入 Code-as-Room 管線；或在材質階段利用影像生成模型補強紋理細節。
- **雲端 MLLM 與渲染農場**：對接 GPT-4V、Claude 或其他視覺語言模型 API 作為代理後端，並搭配雲端渲染農場處理大規模批次房的渲染比對與最終輸出。
- **資產管理平台**：串接內部數位資產管理系統（DAM）或公開資源（如 Sketchfab、TurboSquid），使代理在物件剖析階段能自動查詢並替換符合授權與風格需求的三維模型。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先聚焦於「俯視圖輸入→三維房間輸出」的核心概念，理解代理式框架如何透過多階段管線降低單一步驟的複雜度；Blender 程式碼細節與 MLLM 提示工程可暫時略過，待熟悉三維管線基礎後再深入。
- **AI 工程師**：請重點關注結構化執行框架的實作機制、跨階段記憶模組的狀態管理設計，以及渲染比對迴圈中視覺回饋如何與程式碼生成代理形成閉環；這些是將論文方法轉為穩定產品的關鍵工程細節。
- **研究人員**：建議深入探討基準測試的設計邏輯，以及本文與 VIGA 等現有代理方法在俯視圖條件下的差異；特別留意空間關係推理、視覺理解轉譯為程式碼的評估指標，這些是推動後續研究的突破口。
- **產品經理**：請優先評估適用場景與組織現有設計流程的契合度，盤點俯視圖資料來源、三維資產庫授權與 GPU 運算成本；同時關注結構化框架如何解決「無限迴圈」與「不穩定生成」等過往代理式方案難以商品化的痛點。
