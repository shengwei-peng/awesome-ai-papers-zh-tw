# 判斷為無用卻仍繼續查詢：工具使用代理鮮少將自身的證據判斷轉化為停止決策

**原文標題：** Judged Useless, Queried Anyway: Tool-Using Agents Rarely Turn Their Own Evidence Judgments into Stopping Decisions  
**作者：** Chubin Zhang、Zhenglin Wan、Xingrui Yu 等 7 位作者  
**發布日期：** 2026-10-05  
**HF 連結：** [https://huggingface.co/papers/2610.06191](https://huggingface.co/papers/2610.06191)  
**arXiv：** [https://arxiv.org/abs/2610.06191](https://arxiv.org/abs/2610.06191)  

---

## ⚡ TL;DR

工具使用代理能正確判斷檢索來源失效，卻極少據此停止查詢。
作者測試七種代理與多種提示線索，僅有執行框架強制整合步驟能讓停止決策依循證據。
強制規則提升所有模型在失效來源的表現，預算加倍時停止點不變，並經預註冊複製驗證。

---

## 摘要翻譯

當代理的工具持續回傳無用結果時，應停止依賴該工具。在具有受控來源失效 (Controlled Source Failures) 的檢索環境 (Retrieval Environment) 中，我們將代理如何判斷結果與其實際行為加以區分。我們比較代理在判斷為無用的較長與較短結果序列之後，於相同步驟停止的情形；對於時鐘驅動停止 (Clock-Driven Stopping) 或期限驅動停止 (Deadline-Driven Stopping)，此對比為零。就我們所記錄的判斷而言，所測試的七個工具使用代理 (Tool-Using Agents) 在 97–100% 的情況下將失效來源 (Failing Source) 的結果判定為無用（證據判斷 (Evidence Judgments)），但其中大多數鮮少依此判斷做出停止決策 (Stopping Decisions)。提示線索 (Prompt Cues) 會改變其停止的時機，但不會改變其停止的依據。允許從記憶回答 (Answering from Memory) 以及推理模式 (Reasoning Mode) 可在不論證據的情況下提早停止；所設定的預算 (Budget) 會使 7-8B 模型 (7-8B Models) 的停止點移至期限；而提示中的停止規則 (Stopping Rule) 或呼叫成本 (Call Cost) 至多僅被部分遵循。唯有當執行框架 (Harness) 強制實施一個整合步驟 (Integration Step)，要求代理在連續五次判定為無用的結果後作答時，停止才會依循證據。此步驟提升了所有模型的失效來源成功率 (Failing-Source Success)，在預算加倍 (Budget Doubling) 時保持停止點固定，且當代理陳述其判斷時無需額外的判斷呼叫 (Judgment Call)。在 300 道新題目 (Fresh Questions) 上進行的預先註冊複製實驗 (Pre-Registered Replication) 確認了此分離現象 (Dissociation) 及該規則的效果。

### 核心貢獻（3～5點）
- 揭示工具使用代理 (Tool-Using Agents) 中存在判斷與行動的分離現象 (Dissociation)：代理能正確判斷結果無用（97–100%），卻鮮少據此做出停止決策 (Stopping Decisions)。
- 系統性比較多種提示線索 (Prompt Cues) 的效果邊界：提示線索可改變停止時機，但未必改變停止依據；唯有執行框架 (Harness) 強制介入的整合步驟 (Integration Step) 能使停止真正依循證據。
- 提出並驗證一個簡單有效的整合步驟 (Integration Step)：要求代理在連續五次判定為無用的結果後作答，可提升所有模型的失效來源成功率 (Failing-Source Success)，且在預算加倍 (Budget Doubling) 時保持停止點固定，無需額外的判斷呼叫 (Judgment Call)。
- 透過預先註冊的複製實驗 (Pre-Registered Replication) 於 300 道新題目 (Fresh Questions) 上確認分離現象 (Dissociation) 及該規則效果的穩健性。

### 適合對象
從事大語言模型代理 (LLM Agents)、檢索增強生成 (RAG)、工具使用 (Tool Use) 或 AI 代理評測研究的學者與工程師；對代理決策行為、人機互動設計或 AI 安全性議題感興趣的研究人員；以及關注 AI 系統中「判斷」與「行動」一致性問題的實務工作者。

## 深度分析

#### 方法論解析

本論文的核心方法論在於建構一個能夠精確分離「判斷（judgment）」、「信念（belief）」與「行動（action）」三者的受控實驗環境，並透過一個稱為時間匹配對比（time-matched contrast, Δ）的統計指標來檢驗代理是否真正整合了自己的證據判斷。

**1. 受控檢索環境與來源失效設計**

作者設計了一個檢索環境（retrieval environment），其中可以精確控制來源失效（source failures）的發生時機與恢復時機。這與真實環境中「搜尋索引過期」或「檢索器漂移」等情境對應，但具有實驗可控性。環境中包含一個會持續返回不相關結果的失效來源（failing source），以及可能恢復的正常來源。這種設計讓研究者能夠觀察代理在面對持續無用證據時的行為模式。

**2. 三層分離的測量框架**

論文的方法論突破在於將過去被混為一談的三個層次分離開來：
- **判斷層（Judgment Layer）**：代理是否正確評估了檢索結果的相關性？
- **信念層（Belief Layer）**：代理是否相信繼續搜尋會有回報？
- **行動層（Action Layer）**：代理是否將判斷或信念轉化為停止行動？

這種分離至關重要，因為僅看「成功率」無法區分一個在固定步數停止的代理、一個在期限停止的代理、以及一個在足夠無用證據後停止的代理——三者可能在相同條件下表現相同。

**3. 時間匹配對比 Δ 的設計**

Δ 是本論文最關鍵的方法論創新。其邏輯如下：若代理真正整合了自己的判斷，則在「同一個步驟」下，經歷過較長連續無用結果的代理應該比經歷過較短連續無用結果的代理更傾向停止。具體而言：
- 若代理在步驟 *t* 停止，且其當前連續無用結果的「run length」為 *r*，則 Δ 比較的是在相同步驟 *t* 但不同 run length 下的停止機率差異。
- Δ > 0 表示代理整合了判斷（run length 越長越傾向停止）。
- Δ = 0 表示代理按時鐘或期限停止（與證據無關）。
- Δ < 0 表示代理的停止反而追蹤有用證據（run length 越長越不停止）。

這個指標的精妙之處在於它排除了「時鐘驅動停止（clock-driven stopping）」與「期限驅動停止（deadline-driven stopping）」的混淆，因為這兩種策略在固定條件下也會產生停止行為，但 Δ 為零。

**4. 整合預測與序列決策理論**

論文將「離開一個來源」建模為一個序列決策（sequential decision）。理論上：
- 在第一個無用結果就離開的代理，會錯過那些會恢復的來源所提供的證據。
- 永遠不離開的代理，則會把整個預算（budget）浪費在永遠不會恢復的來源上。
- 最佳策略應該追蹤「當前連續無用結果的 run length」，而非「總共累積的無用結果數」，因為 run length 會在來源恢復時自動重置。

這個理論框架為實驗提供了清晰的預測，使得 Δ 的測量具有理論意義。

**5. 強制整合步驟（Enforced Integration Step）的設計**

當發現代理無法自主整合判斷時，作者設計了一個由執行框架（harness）強制執行的整合步驟：當代理連續五次判斷結果為「無用」時，執行框架限制代理只能執行 `finish` 動作。這個設計的關鍵特性包括：
- 不需要代理額外做出判斷呼叫（judgment call），因為它讀取的是代理已有的判斷。
- 對於在推理中陳述判斷的代理，執行框架可以直接從推理文字中讀取。
- 這個步驟使得停止點在預算加倍時保持固定，證明停止確實追蹤證據而非預算。

**6. 預先註冊的複製實驗**

作者進行了一個預先註冊的複製實驗（pre-registered replication），使用 300 個新題目（fresh questions）來驗證分離現象（dissociation）與強制規則的效果。這種預先註冊的方法論增強了發現的可信度，避免了事後調整假設的風險。

#### 實驗數據解讀

**1. 判斷正確性數據**

在七個被測試的代理中，所有記錄了判斷的模型都將失效來源的結果標記為「無用」的機率達到 97–100%。具體而言：
- Qwen2.5-7B：99.9%（3/122）
- Llama-3.1-8B：98.4%（1/282）
- Qwen3-8B：99.6%（1/292）
- Qwen3-32B：99.4%（19/284）
- Claude Haiku 4.5：99.9%（1/284）

這些數據揭示了一個驚人的事實：代理在判斷層面幾乎是完美的——它們清楚地知道結果是無用的。然而，這些判斷卻極少轉化為行動。

**2. 行動層面的失敗數據**

在五個連續無用判斷後，無輔助（unaided）的開源模型在這些題目上回答的比例極低：
- 五個模型中有五個在最多 7% 的題目上回答。
- Claude Haiku 4.5 在 284 個有此情況的題目中，僅自主回答了 1 個。

這形成了「判斷-行動分離效應（dissociation effect）」的明確證據：代理知道該停止，但不會停止。

**3. Claude Haiku 4.5 的對比實驗**

最引人注目的數據來自 Claude Haiku 4.5 的對比：
- 無輔助時：在 284 個有五個連續無用結果的題目中，僅正確回答 1 個。
- 強制規則下：在相同的 284 個題目中，正確回答 114 個。

這意味著答案其實就在代理的記憶中（它甚至在步驟 6 回憶起 Barlow 是樂隊成員），但代理卻繼續搜尋直到預算耗盡。強制規則將成功率從 0.35% 提升到 40.1%，提升幅度超過 100 倍。

**4. 提示線索（Prompt Cues）的效果**

論文測試了多種提示線索對停止行為的影響：
- **從記憶回答的權限（Permission to answer from memory）**：可以帶來早期停止，但與證據無關。
- **推理模式（Reasoning mode）**：同樣可以帶來早期停止，但與證據無關。
- **明確的預算陳述（Stated budget）**：將 7-8B 模型的停止點移到期限，且這個停止點會隨預算變動而移動。
- **停止規則或呼叫成本（Stopping rule or call cost）**：最多被部分遵循。
- **顯示運行中的無用計數**：不會讓代理據此停止。

關鍵發現是：這些提示線索改變了代理「何時」停止，但沒有改變代理「根據什麼」停止。換言之，它們影響的是停止的時機，而非停止的依據。

**5. 強制整合步驟的效果**

當執行框架強制執行「五個連續無用結果後必須回答」的規則時：
- 每個模型在失效來源上的成功率都上升。
- 停止點在預算加倍時保持固定（證明停止追蹤證據而非預算）。
- 對於在推理中陳述判斷的代理，不需要額外的判斷呼叫。

**6. Δ 的具體數值**

雖然論文中沒有列出所有模型的具體 Δ 值，但明確指出「每個無輔助的開源模型都有負的 Δ」。這意味著這些代理的停止行為不僅沒有追蹤無用證據的 run length，反而在某種程度上追蹤了有用證據——run length 越長，它們越不傾向停止。這是一個反直覺但極為重要的發現。

**7. 預先註冊複製的結果**

在 300 個新題目上的預先註冊複製實驗確認了分離現象與強制規則的效果。這增強了原始發現的穩健性，並降低了偶然相關或過度擬合的風險。

#### 與現有研究的比較

**1. 與 Xie et al. [2026] 的過度搜尋研究**

Xie et al. [2026] 記錄了搜尋增強模型會過度搜尋（over-search）的現象。本論文在此基礎上更進一步：過度搜尋是症狀，而本論文揭示了症狀背後的機制——判斷與行動的分離。Xie et al. 沒有區分「代理判斷錯誤」與「代理判斷正確但不行動」，而本論文透過分離測量明確指出問題在於行動層而非判斷層。

**2. 與 Zhang et al. [2026b] 的判斷失真研究**

Zhang et al. [2026b] 將深度研究代理持續瀏覽不相關結果的現象歸因於「判斷失真（distorted judgment）」。本論文對此提出了修正：判斷本身並未失真（97-100% 的正確率），失真的可能是「判斷到行動的轉化機制」。這是一個重要的理論修正，因為它指向了不同的解決方案——不是改善判斷，而是改善整合。

**3. 本論文的主要貢獻**

相較於現有研究，本論文的貢獻在於：
- **方法論貢獻**：提出了 Δ 指標，能夠區分時鐘驅動、期限驅動與證據驅動的停止行為。
- **理論貢獻**：將離開來源的決策形式化為序列決策問題，並指出最佳策略應追蹤 run length 而非總計數。
- **實證貢獻**：明確證明了判斷-行動分離的存在，並量化了其程度。
- **實務貢獻**：提出了一個簡單有效的執行框架層介入方案，能在不修改模型權重的情況下大幅提升效能。

**4. 論文的限制**

儘管貢獻顯著，本論文也存在一些限制：
- **環境單一性**：實驗在受控的單一失效來源環境中進行，真實環境中可能有多個部分失效的來源，行為模式可能不同。
- **任務類型**：主要使用兩跳問題（two-hop questions），其他類型的任務（如多跳推理、開放式問答）可能呈現不同模式。
- **模型範圍**：測試了七個代理，但對於更大或更新的模型（如 GPT-5、Claude Opus 等）的行為尚未充分探索。
- **強制規則的通用性**：五個連續無用結果的閾值是經驗設定，是否對所有任務都最優仍未知。
- **缺乏理論解釋**：論文清楚描述了「是什麼」但對「為什麼」判斷-行動分離會發生缺乏深入的理論分析（例如，是否與訓練目標、RLHF 偏好有關）。

#### 可重現性評估

**1. 程式碼可用性**

論文提供了 GitHub 連結：`github.com/bennidict23/judged-useless-queried-anyway`。這使得其他研究者可以：
- 重現實驗環境與來源失效控制機制。
- 實作 Δ 指標的計算。
- 測試其他模型在相同環境下的行為。

**2. 資料集與題目**

- 原始實驗使用的題目集未明確說明是否公開，但預先註冊的複製實驗使用了 300 個新題目，暗示原始實驗也有對應的題目集。
- 兩跳問題（two-hop questions）的設計細節在附錄中應有說明。

**3. 模型權重**

- 開源模型（Qwen2.5-7B、Llama-3.1-8B、Qwen3-8B、Qwen3-32B）的權重可從 Hugging Face 等平台獲取。
- Claude Haiku 4.5 是閉源模型，僅能透過 API 訪問，這限制了其結果的獨立驗證。

**4. 預先註冊的複製**

預先註冊的複製實驗（pre-registered replication）是可重現性的重要保障：
- 在 300 個新題目上驗證了主要發現。
- 預先註冊意味著假設和分析計劃在數據收集前已確定，減少了事後調整的風險。
- 複製的成功增強了原始發現的可信度。

**5. 可重現性的潛在挑戰**

- **API 變動**：閉源模型的 API 行為可能隨版本更新而改變，影響重現性。
- **隨機性**：LLM 的輸出具有隨機性，論文中是否充分控制了隨機種子（random seed）與溫度（temperature）參數需要檢視。
- **環境細節**：檢索環境的具體實作（如索引結構、查詢處理）可能影響結果。

#### 未來研究方向

**1. 判斷-行動分離的理論基礎**

最根本的開放問題是：為什麼 LLM 代理會出現判斷-行動分離？可能的研究方向包括：
- **訓練目標分析**：標準的語言模型訓練目標是否鼓勵「繼續生成」而非「停止」？RLHF 是否獎勵了過度謹慎？
- **注意力機制研究**：代理在生成「繼續搜尋」決策時，是否真的「看到」了自己之前的判斷？
- **表徵分析**：判斷資訊是否在模型的內部表徵中被保留到決策時刻？

**2. 多來源與部分失效場景**

本論文主要關注單一失效來源，未來可探索：
- 多個來源同時部分失效的情境。
- 來源品質隨時間動態變化的場景。
- 代理需要在多個來源間動態切換的情境。

**3. 更通用的整合機制**

五個連續無用結果的閾值是經驗設定，未來可研究：
- 自適應閾值：根據任務難度動態調整。
- 機率性停止：根據 run length 計算停止機率，而非硬性閾值。
- 貝葉斯整合：將判斷視為對來源狀態的貝葉斯更新。

**4. 跨任務與跨領域的泛化**

本論文聚焦於兩跳問題，未來可探索：
- 多跳推理任務中的停止行為。
- 程式碼生成、除錯任務中的工具使用停止。
- 對話系統中的「我不知道」識別與停止。

**5. 代理架構的改進**

強制整合步驟是一個外部介入方案，未來可研究：
- 將整合機制內化到模型架構中（例如，專門的「停止決策模組」）。
- 訓練目標中加入「適當停止」的獎勵。
- 開發能夠自我監控並調整停止策略的元認知代理。

**6. 與其他代理失敗模式的關聯**

判斷-行動分離可能與其他已知的代理失敗模式有關：
- **過度自信**：代理可能高估繼續搜尋的價值。
- **獎勵 hacking**：在某些訓練設定下，「完成更多步驟」可能被隱式獎勵。
- **對齊問題**：代理的目標與使用者的目標不一致，導致過度搜尋。

**7. 評估基準的建立**

本論文提出的 Δ 指標可以成為評估代理「證據整合能力」的標準基準。未來可建立：
- 標準化的「停止行為評估套件」。
- 涵蓋多種任務類型的綜合測試。
- 將 Δ 作為模型發布時的標準報告指標。

**8. 人機協作中的停止**

在人類監督的情境下：
- 代理應該在什麼時候請求人類介入？
- 人類如何有效地傳達「停止」指令？
- 代理如何區分「人類要求繼續」與「人類要求停止」？

這些方向不僅能深化我們對 LLM 代理行為的理解，也能直接指導更實用、更可靠的代理系統設計。

## 論文問答

**Q1：這篇論文主要探討什麼核心問題？**
A：這篇論文探討工具使用型大型語言模型代理（tool-using LLM agents）的一個關鍵失敗模式：當檢索來源（retrieval source）持續回傳無用結果時，代理雖然能正確判斷這些結果「無用」，卻幾乎不會據此停止查詢。論文將此現象定義為「判斷」與「行動」之間的解離（dissociation），亦即代理的證據判斷（evidence judgments）與其停止決策（stopping decisions）之間存在系統性斷裂。這項問題之所以重要，是因為來源失效（source failures）在真實部署中經常以無聲方式發生——代理仍會收到文字，但這些文字已不再有助於回答問題。

**Q2：為什麼現有的提示工程或訓練方法無法有效解決此問題？**
A：現有方法多以最終成功率作為衡量指標，但單看成功率無法區分代理是基於證據、基於時鐘（clock-driven stopping）還是基於期限（deadline-driven stopping）而停止。論文的實驗顯示，提示線索（prompt cues）雖然會改變代理「何時」停止，卻無法改變其「依據什麼」而停止——無論是允許從記憶回答、加入推理模式（reasoning mode）、明列預算（budget）、寫入停止規則（stopping rule）或呼叫成本（call cost），代理至多只是部分遵循。這意味著僅靠提示工程無法讓代理學會將自身的證據判斷整合進停止決策中。

**Q3：為什麼這個問題在實務上值得重視？**
A：在真實應用中，搜尋索引（search index）可能過時、檢索器（retriever）可能偏離主題，導致代理花費大量計算預算在已失效的來源上，卻錯失從內部知識回答的機會。論文中 Claude Haiku 4.5 的案例顯示，當強制其在五次連續無用判斷後回答時，可在 284 題中正確回答 114 題，而未受強制時僅正確回答 1 題。這代表此問題不僅是效率浪費，更直接造成可避免的答錯，因此對部署成本與可靠性皆有實質影響。

**Q4：論文提出的核心方法是什麼？其關鍵創新點為何？**
A：論文的關鍵創新在於由執行框架（harness）強制執行的「整合步驟」（integration step）：當代理連續五次將檢索結果標記為「無用」時，框架會限制其只能選擇「結束並回答」這個動作，從而把停止決策與證據判斷綁定。這個做法跳脫了單純依賴提示工程的思路，改由外部系統強制整合證據，使停止點真正回應證據而非時鐘或期限。對於會在推理中明確陳述判斷的代理，框架可直接讀取其推理內容中的判斷，無需額外要求代理做出判斷呼叫（judgment call）。

**Q5：論文中用來區分停止依據的「時間匹配對比 Δ」是如何運作的？**
A：時間匹配對比 Δ 的設計邏輯是：在相同的步數下，比較代理在「較長連續無用結果序列之後」與「較短無用結果序列之後」的停止機率差異。若 Δ 為正值，代表代理會整合自身的證據判斷；若 Δ 為零，代表代理是依時鐘或期限停止；若 Δ 為負值，則代表代理反而是在看到有用證據時才停止。這個對比設計巧妙地排除了「單純因為時間到了才停」的混淆，使研究者能精準判斷停止行為究竟回應的是什麼。

**Q6：為什麼論文選擇使用「受控來源失效」（controlled source failures）的實驗設計？**
A：受控來源失效的設計讓研究者能精準決定來源何時失效以及是否恢復，進而將代理的判斷與行動分離測量。在真實環境中，來源失效往往是漸進且難以觀察的，無法區分代理是因為證據不足而停，還是因為時間到了而停。透過控制失效的時機與持續長度，論文得以系統性地檢驗代理是否會根據「連續無用結果的長度」調整停止機率，這正是良好序列決策（sequential decision）所應具備的行為。

**Q7：論文的實驗設定與評估對象為何？**
A：論文測試了七個代理，涵蓋 Qwen2.5-7B、Llama-3.1-8B、Qwen3-8B、Qwen3-32B 與 Claude Haiku 4.5 等不同規模與家族的模型。實驗在受控的檢索環境（retrieval environment）中進行，並以兩跳問題（two-hop question）作為基準，因為這類問題需要多次檢索才能回答，能有效暴露代理的停止行為。此外，論文還進行了一項預先註冊的複製實驗（pre-registered replication），使用 300 個全新題目（fresh questions）來驗證主要發現的穩健性。

**Q8：論文最重要的實驗結果為何？**
A：最關鍵的結果是：所有記錄到判斷的模型都將失效來源的結果標記為無用的比例高達 97–100%，然而其中五個模型在五次連續無用判斷後仍會回答的比例最多僅 7%。換言之，代理的判斷幾乎完全正確，但其行動卻幾乎完全忽略這些判斷，清楚展示了判斷與行動的解離現象。當執行框架強制整合步驟後，每個模型在失效來源上的成功率（failing-source success）皆提升，且停止點在預算加倍（budget doubling）時保持不變，證明停止行為已真正回應證據。

**Q9：論文中進行了哪些消融實驗（ablation studies）來檢驗不同提示策略的效果？**
A：論文系統性地測試了多種提示策略，包括：允許從記憶回答（answering from memory）、啟用推理模式、在提示中明列預算、寫入停止規則、加入呼叫成本，以及顯示目前無用判斷的累計次數。結果顯示，這些策略至多只能部分改變代理的停止時機，卻無法讓停止依據真正轉向證據本身。唯有由執行框架強制整合步驟，才能讓停止行為穩定地回應證據，這凸顯了單純提示工程的根本局限。

**Q10：這項研究在哪些實際應用場景中具有重要意義？**
A：任何仰賴外部工具的代理系統皆受此問題影響，包括深度研究代理（deep-research agents）、檢索增強生成（RAG）系統、自動化客服機器人，以及程式碼輔助代理。在這些場景中，工具來源可能因索引過時、API 變更或網路問題而失效，若代理無法及時察覺並停止，將造成使用者等待時間拉長與營運成本上升。論文的發現對這些場景的可靠性設計具有直接參考價值。

**Q11：從產品部署的角度，這項研究帶來哪些設計啟示？**
A：產品設計者不應假設代理會自行將證據判斷轉化為停止決策，而應在執行框架層級加入類似論文中提出的整合機制。這代表停止邏輯應由系統強制執行，而非完全委由模型自行決定。此外，設計者也應考慮到不同規模模型（如 7–8B 模型與更大模型）對提示線索的反應不一致——例如 7–8B 模型在給定明確預算時會將停止點移到期限，這在預算變動時會造成不穩定的使用者體驗。

**Q12：這項研究對整個 LLM 代理研究領域有何影響？**
A：論文提出了一個重要的方法論貢獻：透過時間匹配對比 Δ，研究者得以嚴格區分代理的停止究竟回應於證據、時鐘還是期限，這對未來評估代理行為的可解釋性深具價值。同時，論文挑戰了「只要提示寫得夠清楚，代理就會遵循」的常見假設，強調判斷與行動之間可能存在系統性解離，這將促使後續研究更重視代理內部狀態與外部行動之間的對齊機制。

**Q13：論文本身承認哪些研究限制？**
A：論文的實驗主要在受控的檢索環境中進行，雖然這有助於內部效度，但可能無法完全代表真實世界中更為複雜且嘈雜的工具失效情境。此外，五次連續無用判斷的閾值是基於特定實驗設定所選，未必是所有任務或所有模型的最佳設定。論文的測試模型數量有限，且對於不主動陳述判斷的模型，仍需依賴額外的判斷呼叫機制，這在實務部署上可能增加整合成本。

**Q14：在哪些情況下論文中提出的方法可能會失效？**
A：當來源失效是間歇性的——即偶爾仍會回傳有用結果——五次連續無用的閾值可能過於敏感，導致代理在來源即將恢復時過早停止。此外，對於不會在推理中明確陳述判斷的模型，框架需要額外的判斷呼叫機制，這本身就可能引入新的錯誤來源。若代理的判斷本身不可靠（例如對於「有用」與「無用」的標準模糊），則強制整合步驟反而會把錯誤的判斷放大成錯誤的停止決策。

**Q15：基於這項研究，未來有哪些值得探索的研究方向？**
A：未來可朝幾個方向延伸：首先是將整合機制推廣到其他類型的工具（如程式碼執行、資料庫查詢），檢查判斷—行動解離是否為跨工具的普遍現象；其次是學習式的閾值調整，讓整合步驟的觸發條件能根據任務特性動態最佳化；第三是將整合機制與代理的整體規劃能力結合，使停止決策不僅回應當前證據，還能考慮未來步驟的預期收益。這些方向皆有助於建立更可靠且更有效率的工具使用型代理系統。

## 實務應用指南

### 適用場景

1. **企業 RAG 系統面對不穩定的內部知識庫**：當企業內部文件索引因權限變更、版本更新或同步失敗而失效時，問答代理會反覆查詢同一個損壞的來源，浪費 token 預算並延遲回應。整合步驟可在代理連續判定五次結果無用後強制其整合記憶作答，避免無止境的重試。

2. **客戶支援聊天機器人整合第三方 API**：當 CRM、工單系統或物流追蹤 API 暫時故障時，代理會持續呼叫並收到空泛或錯誤的回應。導入「五連無用即停止」規則可讓代理在 API 失效時改用對話歷史與政策文件作答，維持服務不中斷。

3. **深度研究代理處理多源搜尋**：當某個搜尋引擎或學術資料庫被防火牆擋下、回傳過時索引或被反爬蟲機制限流時，代理應能識別並切換至其他來源。本研究的整合步驟可作為多源編排層的仲裁邏輯。

4. **程式碼助手查詢文件伺服器**：當語言伺服器（LSP）、套件文件站或 Git 倉庫鏡像失效時，程式碼代理會反覆查詢並收到無關結果。整合步驟可讓代理在判定來源失效後改用訓練知識或本地快取作答。

5. **多代理協作中的單點失效**：在主管代理分派任務給多個專家代理的架構中，若某個專家代理的檢索工具失效，主管代理應能根據該專家回報的「無用」訊號提早切換，而非等待預算耗盡。

### 實作前置條件

**資料需求**
- 代理的查詢軌跡日誌（每一步的工具呼叫、檢索結果、代理的判斷文字）
- 標註過的「有用／無用」判斷資料集，用於校驗代理的判斷與人類標註的一致性
- 來源失效的模擬環境或真實失效事件紀錄，用於離線評估
- 預先註冊的測試題庫（建議至少 300 題），涵蓋單跳與多跳問題

**運算資源**
- 至少一台可運行 7B–8B 開源模型的 GPU 伺服器（如單張 A100 或 H100），用於本地推理與判斷擷取
- 商業模型 API 存取權限（Claude Haiku 4.5、GPT 系列等）作為基準比較
- 檢索環境的容器化部署（Docker / Kubernetes），以便注入受控的來源失效

**技能需求**
- 熟悉 LLM 代理框架（LangChain、AutoGen、CrewAI 或自製迴圈）
- 能撰寫 side-channel 判斷擷取邏輯（從代理的推理文字中解析「無用」標記）
- 具備基本的實驗設計能力，能執行預先註冊的複製實驗
- 理解 prompt engineering 與 token 預算控制

### 實作步驟建議

1. **建立受控檢索環境**：依照論文 §2 的設計，部署一個檢索沙盒，將來源分為「正常」與「失效」兩組。失效來源在指定問題上固定回傳不相關內容，並可設定「是否恢復」以模擬間歇性故障。

2. **實作側通道判斷擷取**：在代理迴圈中加入判斷記錄層。每次工具回傳後，要求代理輸出一行結構化標記（例如 `JUDGMENT: useless` 或 `JUDGMENT: useful`），並存入軌跡日誌。這是後續整合步驟的輸入。

3. **建立時間匹配對比指標 Δ**：在同一個步驟上，比較「長串無用結果後停止」與「短串無用結果後停止」的比例差異。Δ 為正代表整合判斷、為零代表時鐘／期限驅動、為負代表反向行為。將此指標納入 CI 儀表板。

4. **部署整合步驟（核心介入）**：在代理迴圈中加入規則：「若連續五次 `JUDGMENT: useless`，則隱藏所有工具選項，只保留 `finish` 動作」。此步驟由執行框架（harness）強制執行，不依賴代理自發遵守。

5. **支援推理內判斷的免額外呼叫模式**：若代理已在推理文字中自然寫出「這個結果無用」之類的語句，執行框架可用規則式解析器讀取該語句，省去要求代理額外輸出結構化標記的 token 成本。

6. **預先註冊評估**：在投入正式環境前，先在 300 題新題上預先註冊評估計畫，記錄 Δ、失效來源成功率、停止步驟分布。論文已驗證此規模足以確認分離現象與規則效果。

7. **預算加倍壓力測試**：將代理的呼叫預算加倍，驗證整合步驟下的停止點是否保持固定。若停止點隨預算移動，代表仍受期限驅動，需檢查整合步驟是否被繞過。

8. **上線監控**：在生產環境中持續監控「連續無用次數」分布與「強制整合觸發率」。若某來源的觸發率異常飆升，應觸發來源健康檢查告警。

### 潛在風險與注意事項

**風險一：判斷擷取失敗導致規則誤觸發**
若側通道解析器漏抓或誤抓「無用」標記，可能在代理其實認為結果有用時強制其停止。緩解方式：保留人類標註的黃金資料集做迴歸測試，並對解析失敗的軌跡設 fallback 為「不觸發整合」。

**風險二：過早停止損失可恢復來源**
若來源只是暫時失效（例如 API 限流恢復中），五次門檻可能過短。緩解方式：將門檻設為可調參數，並在來源健康度指標良好時提高門檻；或在來源歷史恢復率高的場景改用七次或十次。

**風險三：代理學會「假裝無用」以提早結束**
若代理被激勵（例如獎勵提早回答）誤導，可能傾向把有用結果也標記為無用以觸發整合。緩解方式：監控「判斷為有用但答案錯誤」的比例，並對異常模型做 prompt 對齊審查。

**風險四：整合步驟與多代理編排衝突**
在主管—專家代理架構中，整合步驟可能讓專家代理提早交卷，主管代理失去繼續追問的機會。緩解方式：將整合步驟設為可配置，僅在單代理或葉節點啟用，並讓主管代理可覆寫。

**風險五：token 成本未真正下降**
雖然停止點提早，但若側通道要求代理每次都額外輸出判斷標記，可能反而增加成本。緩解方式：優先採用「推理內判斷解析」模式，僅在代理未自然寫出判斷時才要求結構化輸出。

**風險六：預先註冊的題庫與真實分布漂移**
300 題的預先註冊樣本若與生產問題分布差異過大，結論可能不外推。緩解方式：定期以新一批預先註冊題目做季度複製實驗，並在題庫中保留一定比例的長尾問題。

### 與其他技術的整合建議

**與 ReAct / Toolformer 風格的代理迴圈整合**
在現有的「思考—行動—觀察」迴圈中，於「觀察」階段後插入判斷記錄層與整合步驟檢查點。整合步驟觸發時，將下一輪的可用動作集合縮減為僅 `finish`。

**與 LangChain Callback / AutoGen Guardrail 整合**
將整合規則實作為 callback handler 或 guardrail，在每次工具回傳後檢查連續無用計數器。優點是無需修改代理核心程式碼，可作為外掛部署。

**與檢索增強生成（RAG）管線整合**
在向量資料庫層加入「來源健康度」標記。當某來源連續被標記為無用時，自動將其從候選來源池中暫時移除，並在整合步驟觸發時讓代理改用其他來源或記憶作答。

**與成本控制與可觀測性平台整合**
將 Δ 指標、連續無用計數、整合觸發率匯入既有的 LLM 可觀測性平台（如 LangSmith、Helicone、Datadog LLM Observability），並設定告警閾值。

**與 A/B 測試框架整合**
將整合步驟的啟用與否作為實驗變數，與既有 prompt 變體、模型版本變體一起做多因子 A/B 測試，以分離「整合步驟效果」與「其他改動效果」。

**與人類回饋強化學習（RLHF）管線整合**
將「正確整合判斷並提早停止」作為獎勵訊號之一，訓練代理在內部策略中學會此行為，而無需依賴執行框架強制介入。

### 給不同背景讀者的閱讀建議

**給初學者**：先讀摘要與 §1 的圖 1，理解「代理看得出結果無用，卻繼續查詢」這個反直覺現象。接著看 §3 的 Δ 指標定義，這是整篇論文的分析骨幹。實作上可先在自己的小專案中試著加入「連續五次無用就強制回答」的規則，觀察行為變化。

**給 AI 工程師**：重點讀 §4 與 §5。§4 揭示了「prompt 提示無效」這個重要工程教訓——告訴代理規則不如讓執行框架強制執行。§5 的整合步驟是可立即部署的程式碼模式，建議直接參考論文的 GitHub 倉庫（github.com/bennidict23/judged-useless-queried-anyway）並整合進現有代理迴圈。

**給研究者**：核心貢獻在於「分離判斷與行動」這個分析框架（Δ 指標）以及「執行框架強制介入優於 prompt 提示」這個反直覺結論。可延伸方向包括：將 Δ 推廣到多來源編排、探討判斷擷取對齊訓練、與認知科學中「行動—信念分離」文獻對話。預先註冊的 300 題複製實驗設計也值得在自己的研究中採用。

**給產品經理**：關鍵訊息是「使用者體驗問題往往不是模型不夠聰明，而是模型不會停」。當使用者抱怨代理「一直轉圈」或「重複問同樣的問題」，很可能就是論文描述的「判斷與行動分離」現象。整合步驟是一個低成本、高槓桿的介入點，可在不更換模型的情況下顯著改善回應速度與成功率。建議在產品路線圖中將「執行框架層的停止邏輯」列為優先項。
