# Skill2Real：零樣本模擬到真實機器人操作之代理式技能學習

**原文標題：** Skill2Real: Agentic Skill Learning for Zero-Shot Sim-to-Real Robot Manipulation  
**作者：** Xincheng He、Siyu Ma、Chang Yu 等 8 位作者  
**發布日期：** 2026-10-02  
**HF 連結：** [https://huggingface.co/papers/2610.02788](https://huggingface.co/papers/2610.02788)

## ⚡ TL;DR

模擬到真實機器人操作中，現有方法將預算耗於任務無關的低階表徵，難以獲得可重用的任務知識。
本文提出 Skill2Real 框架，透過共享 API 與提議驗證治理迴圈，階層式學習小腦與大腦技能。
凍結技能使 LIBERO-Pro Long 成功率從 2.0% 升至 56.3%，UR5e 完成率達 78.75%。

## 摘要翻譯

將機器人技能（Robot Manipulation）從模擬遷移至真實世界，需要在感知（Perception）、動力學（Dynamics）與具身形態（Embodiment）差異下仍可使用的任務知識。我們提出 Skill2Real，一個透過共享應用程式介面（Application Programming Interface, API）學習可執行技能的代理式策略（Agentic Policy）框架。提議者-驗證者-治理者（Proposer-Verifier-Governor, PVG）迴圈利用特權模擬證據（Privileged Simulation Evidence）來診斷結果並驗證更新，同時使所學技能根植於公開觀測（Public Observations）與 API 語義（API Semantics）之中。小腦（Cerebellum）首先獲取局部操作技能（Local Manipulation Skills）；接著大腦（Brain）在小腦凍結的情況下學習任務層級組合（Task-Level Composition）。兩種記憶皆可在無需任務策略微調（Task Policy Fine-Tuning）或技能記憶更新（Skill-Memory Updates）的情況下遷移至真實機器人。當 GPT-5.6 Sol 在 LIBERO-90 上學習技能時，使用 GPT-6 Astra 評估每個凍結檢查點（Frozen Checkpoint），可將 LIBERO-Pro Long 的成功率從 2.0% 提升至 56.3%，且無需在 Pro Long 上進行訓練。獨立的 Robosuite 訓練在七項任務中，分別以 Sol 與 Opus 5 達到 85.1% 與 89.4% 的平均成功率（Mean Success）。由 Sol 於 LIBERO-90 訓練所得之凍結技能，透過 Astra 在四項真實世界操作任務中達到 78.75% 的平均完成率（Mean Completion）。在 LIBERO-90 訓練期間移除驗證者（Verifier）或治理者（Governor），分別使最終 Pro Long 成功率降低 17.3 與 13.3 個百分點（Percentage Points）。這些結果顯示，透過通用機器人介面（Common Robot Interface）學習並遷移可執行技能階層（Hierarchy of Executable Skills）是可行的。

### 核心貢獻（3～5點）
- **提出 Skill2Real 代理式策略框架**：透過共享 API 學習可執行技能，使所學技能根植於公開觀測與 API 語義，跨越模擬與真實之間的感知、動力學與具身形態差異。
- **設計 PVG 非對稱迴圈機制**：以提議者-驗證者-治理者三角色分工，利用特權模擬證據診斷結果並驗證更新，確保技能學習的可靠性與可遷移性。
- **實現階層式技能分工與凍結遷移**：小腦模組先獲取局部操作技能，大腦模組在小腦凍結下學習任務層級組合；兩者皆可無需微調直接遷移至真實機器人。
- **在多項基準測試與真實機器人上展現顯著成效**：LIBERO-Pro Long 成功率從 2.0% 提升至 56.3%（無需在 Pro Long 上訓練）；Robosuite 七項任務平均成功率達 85.1%–89.4%；真實世界四項操作任務平均完成率達 78.75%。
- **消融實驗驗證各元件必要性**：移除驗證者或治理者分別使最終 Pro Long 成功率降低 17.3 與 13.3 個百分點，證實 PVG 三角色缺一不可。

### 適合對象
從事機器人操作（Robot Manipulation）、模擬到真實遷移（Sim-to-Real Transfer）、階層式強化學習（Hierarchical Reinforcement Learning）、視覺-語言-動作模型（VLA Model）以及具身 AI（Embodied AI）研究的學者與工程師；特別關注如何將基礎模型（Foundation Models）與大型語言模型（LLM）整合至機器人策略設計、追求零樣本泛化（Zero-Shot Generalization）與真實世界部署的研究團隊與產業界研發人員。

## 深度分析

#### 方法論解析

Skill2Real 的核心方法論建立在「資訊分離」(information separation) 的設計哲學上，將用於監督技能學習的資訊與執行技能所需的資訊明確區分開來。這一設計直接回應了模擬到真實遷移 (Sim-to-Real Transfer) 中長期存在的瓶頸：傳統域隨機化 (Domain Randomization) 與非對稱演員-評論家 (Asymmetric Actor-Critic) 方法常將學習預算 (Learning Budget) 大量消耗於建模光照、紋理等任務無關 (Task-Agnostic) 的低階表徵 (Low-Level Representations)，而非獲取可重用的操作知識。

**共享程式碼策略介面 (Shared Code-Based Policy Interface)**

整個框架的轉移邊界 (Transfer Boundary) 由一個基於程式碼的策略介面定義。該介面具備以下關鍵特性：
- 程式透過 API 語義 (API Semantics) 呼叫操作，後端各自提供感知、校正與低階執行
- 模擬器特權資訊 (Privileged Information) 僅用於評估與改善行為
- 持久化的技能知識完全透過公開觀測 (Public Observations) 與 API 返回值 (API Returns) 表達

這種設計使得任務知識可在模擬與真實之間重用，而無需將模擬器專屬狀態納入部署策略。

**非對稱 Proposer-Verifier-Governor (PVG) 迴圈**

PVG 迴圈是 Skill2Real 的核心學習機制，其「非對稱」(Asymmetric) 特性體現在三個角色對資訊的存取權限差異：

1. **提議者 (Proposer)**：僅基於公開觀測與 API 返回值執行程式並提出可重用的更新提案
2. **驗證者 (Verifier)**：利用特權模擬證據 (Privileged Simulation Evidence) 診斷執行結果，並將診斷轉譯為基於公開資訊的回饋
3. **治理者 (Governor)**：彙整多輪驗證回放 (Validation Rollouts) 的證據，僅接受有充分支援的更新進入記憶

此設計的精妙之處在於：學習過程可享受模擬器的特權資訊帶來的豐富監督信號，但最終沉澱的技能知識卻完全基於部署時可獲取的公開資訊，從根本上避免了模擬器特徵洩漏 (Simulator Feature Leakage) 問題。

**雙階層技能學習策略 (Hierarchical Skill Learning)**

Skill2Real 採用兩階段階層式策略學習 (Hierarchical Policy Learning)：

- **階段 I — 小腦 (Cerebellum) 學習**：獲取可重用的局部操作技能 (Local Manipulation Skills)，例如抓取、放置、推動等動作基元 (Motor Primitives)
- **階段 II — 大腦 (Brain) 學習**：在凍結 (Frozen) 的小腦技能庫基礎上，學習將其組合成具備規劃 (Planning) 與恢復 (Recovery) 能力的長時程式 (Long-Horizon Programs)

關鍵設計決策在於：階段 II 訓練時小腦完全凍結，這確保了兩個層級的技能可獨立遷移，且大腦學習的是「如何使用技能」而非「如何執行技能」，符合選項框架 (Options Framework) 與技能串接 (Skill Chaining) 的經典階層式強化學習 (Hierarchical Reinforcement Learning) 思想。

**跨域基礎對齊 (Cross-Domain Grounding)**

Skill2Real 仰賴基礎視覺語言模型 (Foundation VLMs) 提供跨域基礎對齊能力。這意味著 VLM 不僅作為感知編碼器，更作為將模擬經驗「翻譯」至真實世界的語義橋樑，使得在模擬中學到的程式語義可在真實觀測下被正確解讀。

#### 實驗數據解讀

**跨任務套件泛化能力 (Cross-Task Suite Generalization)**

最關鍵的實驗結果是 Skill2Real 在**未見過的** LIBERO-Pro Long 任務上的表現：
- Astra 模型：2.0% → 35.3%（僅小腦）→ 56.3%（完整階層）
- Opus 5 模型：0.5% → 29.3%（僅小腦）→ 49.0%（完整階層）

這項結果的深層意義在於：技能是在 LIBERO-90 上學習的，但評估是在完全不同的 LIBERO-Pro Long 上進行，且**未對 Pro Long 進行任何訓練**。從 2.0% 躍升至 56.3% 的 54.3 百分點 (Percentage Points) 增益，證明了學到的技能具備真正的跨任務組合性 (Composability)，而非僅是任務特定的過擬合。

**階層式結構的價值驗證**

從「無記憶 → 僅小腦 → 完整階層」的漸進式增益（2.0% → 35.3% → 56.3%）清晰展示了兩個層級的互補貢獻：
- 小腦貢獻了約 33 百分點的基礎能力提升
- 大腦在凍結的小腦基礎上額外貢獻了 21 百分點

這驗證了「局部技能 + 任務組合」的分層設計優於單一扁平策略。

**跨模型一致性 (Cross-Model Consistency)**

在 Robosuite 七個任務上的獨立訓練結果：
- Sol：16.6% → 85.1%（68.5 百分點增益）
- Opus 5：19.4% → 89.4%（70.0 百分點增益）

兩個不同基礎模型均獲得約 70 百分點的大幅提升，顯示 Skill2Real 增加的能力是**正交於 (Orthogonal to)** 基礎模型本身的——即 Skill2Real 並非僅僅「喚醒」基礎模型的潛能，而是真正注入了可遷移的任務知識。

**真實世界遷移 (Real-World Transfer)**

UR5e 實體機器人上的四個任務實驗：
- 僅局部技能：56.25% 平均完成率
- 完整 Brain-Cerebellum 階層：78.75% 平均完成率
- 對照組（無 Skill2Real）：27.50%

22.5 百分點的階層增益與 51.25 百分點的整體增益，證明了：
1. 模擬學到的凍結技能確實可零樣本遷移至真實機器人
2. 大腦的任務組合能力在真實世界中同樣有效
3. 框架對光照、材質、動力學變化具有魯棒性 (Robustness)

**消融實驗 (Ablation Study) 的關鍵發現**

移除驗證者導致 17.3 百分點下降，移除治理者導致 13.3 百分點下降。這兩個數字揭示了：
- 驗證者的特權診斷對技能品質至關重要（貢獻更大）
- 治理者的多輪驗證彙整機制防止了過早接受低品質更新
- 兩者結合形成了一個穩健的「證據門檻」(Evidence Threshold) 機制

#### 與現有研究的比較

**與傳統 Sim-to-Real 方法的比較**

| 面向 | 域隨機化 / 非對稱 AC | Skill2Real |
|------|---------------------|-----------|
| 學習預算分配 | 大量消耗於視覺變化建模 | 集中於任務知識獲取 |
| 遷移機制 | 學習域不變表徵 | 透過 API 語義凍結技能 |
| 監督信號 | 獎勵函數 | 特權模擬證據 + 公開回饋 |
| 部署需求 | 通常需領域適配 | 零樣本，無需微調 |

相較於 Pinto 等人 (2018) 的特權評論家方法，Skill2Real 並非將特權資訊用於價值估計，而是用於技能驗證，這避免了特權資訊在部署時的依賴問題。

**與程式碼生成方法的比較**

與 Liang 等人 (2022) 的程式碼生成策略相比，Skill2Real 的差異在於：
- 程式碼生成方法「組裝」外部提供的基元
- Skill2Real 從經驗中「獲取」局部技能與任務策略
- 後者產生的技能庫是經過驗證的，而非僅憑語言模型直覺

**與技能庫系統的比較**

相較於 Tziafas & Kasaei (2024) 與 Lu 等人 (2026) 等代表性技能庫系統：
- 這些系統通常依賴人類引導或真實世界執行回饋
- Skill2Real 完全在模擬中學習，僅使用特權模擬證據作為監督
- 這大幅降低了真實世界數據收集成本

**與 VLA 模型的比較**

相較於 RT-2、Octo 等視覺-語言-動作 (VLA) 模型：
- VLA 模型將感知、推理、控制整合於單一神經網路
- Skill2Real 採用模組化架構 (Modular Architecture)，將技能顯式化為可檢查、可修改的程式
- 後者提供了更強的可解釋性 (Interpretability) 與錯誤恢復 (Error Recovery) 能力

**現有限制 (Limitations)**

1. **對 API 設計的依賴**：框架效能高度依賴共享介面的設計品質，不良的 API 抽象會限制可學技能的多樣性
2. **模擬器品質假設**：特權證據的品質受模擬器物理保真度限制，接觸動力學 (Contact Dynamics) 等現象的模擬誤差仍會影響遷移
3. **VLM 能力天花板**：跨域基礎對齊仰賴基礎視覺語言模型，當 VLM 對特定領域缺乏理解時，技能語義可能錯位
4. **計算成本**：多輪驗證回放與治理者彙整機制帶來額外的模擬計算開銷

#### 可重現性評估

**優點**

- 論文提供了專案頁面 (skill2real.github.io)，便於讀者追蹤程式碼與資料釋出狀況
- 實驗橫跨三個獨立基準 (LIBERO-90、LIBERO-Pro Long、Robosuite) 與真實機器人，提供了多層次的驗證
- 消融實驗明確分離了各元件的貢獻，有助於理解設計選擇的必要性
- 使用了多個基礎模型 (Sol、Astra、Opus 5) 進行評估，減少了對單一模型的過度擬合風險

**疑慮與缺口**

- 論文中未明確說明程式碼、訓練資料、模型權重是否會開源釋出
- 真實世界實驗僅在 UR5e 上進行四個任務，硬體多樣性有限
- 模擬器設定的隨機性、隨機種子等影響可重現性的細節未在現有文本中詳述
- 基礎模型版本（GPT-5.6 Sol、GPT-6 Astra、Opus 5）並非公開可取得的模型，這對獨立重現構成挑戰

**可重現性評級**：中等。框架概念與方法論可被獨立實驗室借鏡並重新實作，但精確的數字重現需要取得相同的基礎模型與模擬環境配置，這在當前並非完全可及。

#### 未來研究方向

**1. 技能抽象層次的自動化發現**

當前 Skill2Real 的小腦技能由研究者預定義或透過學習湧現，但技能的最佳抽象層次（例如「抓取杯子」vs「閉合夾爪於特定位置」）仍待探索。未來可研究如何讓治理者自動決定技能的粒度與命名空間。

**2. 多機器人具身形態遷移 (Cross-Embodiment Transfer)**

目前實驗集中於 UR5e 單臂與 Robosuite 中的雙臂設定。將 Skill2Real 擴展至異質具身形態（如四足機器人搭配機械臂、人形機器人）將考驗 API 抽象的泛化能力，並推動「具身無關」(Embodiment-Agnostic) 技能庫的發展。

**3. 持續學習與技能累積 (Continual Skill Accumulation)**

當前框架在固定任務集上學習後凍結。引入持續學習 (Continual Learning) 機制，使技能庫能在不引發災難性遺忘 (Catastrophic Forgetting) 的前提下持續擴展，將是邁向終身機器人學習 (Lifelong Robot Learning) 的關鍵一步。

**4. 形式化驗證與安全性保證 (Formal Verification & Safety Guarantees)**

既然技能以程式碼形式表達，便可對其進行形式化驗證。未來可探索如何為學到的技能提供安全性的形式化保證，特別是在人機協作 (Human-Robot Collaboration) 場景中。

**5. 與基礎模型的雙向互動**

當前 Skill2Real 主要將 VLM 用於跨域基礎對齊。可探索讓學到的技能庫反過來增強 VLM 的推理能力，形成「技能增強的視覺語言模型」(Skill-Augmented VLM)，用於更廣泛的具身 AI (Embodied AI) 應用。

**6. 從模擬到真實的不確定性量化**

目前的遷移是確定性的。可引入不確定性估計 (Uncertainty Estimation) 機制，讓機器人在面對高不確定性的真實觀測時主動請求人類協助或切換至更保守的策略，提升部署可靠性 (Reliability)。

**7. 技能組合的搜尋效率**

大腦學習任務組合的過程可被視為程式合成 (Program Synthesis) 問題。引入神經符號 (Neuro-Symbolic) 方法或大型語言模型輔助的搜尋策略，可能加速長時程式 (Long-Horizon Programs) 的發現。

**8. 跨域遷移的理論分析**

目前 Skill2Real 的有效性主要透過經驗驗證。從資訊理論或因果推論角度分析「為何凍結的階層化程式碼技能能跨越域差距」，將為未來設計提供更堅實的理論基礎。

## 論文問答

**Q1：什麼是零樣本模擬到真實（zero-shot sim-to-real）機器人操作的核心問題？**
A：零樣本模擬到真實的核心問題在於如何讓機器人在模擬環境中學到的行為，能夠無需額外的真實世界訓練就直接部署到實體機器人上。模擬與真實之間存在著感知（光照、材質）、動力學（接觸、摩擦）以及具身形態（embodiment）等多方面的差異，這些差異會讓模擬中表現良好的策略在真實環境中失效。對於長時程操作任務而言，挑戰更為嚴峻，因為機器人不僅要可靠地執行局部操作技能，還必須將這些技能組合成任務層級的行為，並在中間動作失敗時進行恢復。Skill2Real 正是針對這個瓶頸，提出了一套能夠學習可重用、可組合任務知識的代理式策略框架。

**Q2：現有的模擬到真實方法為何無法徹底解決這個問題？**
A：傳統的域隨機化（domain randomization）與非對稱演員-評論家（asymmetric actor-critic）方法主要透過學習對域偏移不變的策略或表徵來縮小差距，但這些方法往往將大量學習預算花在建模與任務無關的低階表徵（例如光照與紋理變化），而非獲取可重用的操作知識。基於程式碼生成的方法雖然讓行為變得可組合，但它們通常只是組裝外部提供的基元，而非從經驗中真正學會局部技能與任務策略。代表性的技能庫系統則依賴人類引導或真實世界執行回饋來累積程式，這在實務上既昂貴又難以擴展。Skill2Real 透過基礎視覺語言模型（VLMs）提供跨域基礎對齊，並將模擬學習導向經驗證的階層式可執行知識，從而突破了上述瓶頸。

**Q3：為什麼這個問題對機器人領域至關重要？**
A：模擬到真實的零樣本遷移是機器人能否大規模部署的關鍵，因為真實世界的訓練成本高昂、耗時且存在安全風險，而模擬則提供了可擴展、可重現的學習環境。若無法有效遷移，再多模擬經驗也無法轉化為實體機器人的實用能力。對於長時程操作任務而言，僅僅遷移單一動作是不夠的，機器人必須能夠規劃、組合技能並從失敗中恢復，這對家庭服務、工業自動化等場景尤其重要。Skill2Real 所展示的階層式可執行技能遷移能力，為機器人從模擬學習走向真實應用提供了一條可擴展且無需真實任務微調的路徑。

**Q4：Skill2Real 的核心機制——非對稱提議者-驗證者-治理者（PVG）迴圈是如何運作的？**
A：PVG 迴圈是一個三角色協作的學習機制，其中提議者（Proposer）根據公開觀測與 API 返回值執行程式並提出可重用的更新，驗證者（Verifier）則利用特權模擬證據診斷執行結果並產生公開基礎對齊的回饋，而治理者（Governor）則彙整多輪驗證回放的證據，僅在更新獲得充分支持時才將其納入記憶。這種非對稱設計的關鍵在於，提議者僅能存取部署時可得的公開資訊，而驗證者則可使用模擬器內部的特權狀態來評估行為品質，從而讓學習過程能利用模擬優勢卻不污染部署策略。整個迴圈透過共享的程式碼式策略介面運作，確保學到的技能在模擬與真實之間具有一致的語義。

**Q5：將特權模擬證據與公開觀測分離是 Skill2Real 的關鍵創新，這個設計帶來什麼優勢？**
A：這個分離的核心優勢在於它定義了清晰的遷移邊界：模擬器特權可用於評估與改進行為，但持久化的技能知識則完全透過公開觀測與 API 語義表達，因此部署時的策略不會依賴任何模擬器專屬的狀態。這種設計讓任務知識能夠在模擬與真實之間無縫重用，而無需將模擬器內部資訊編碼進部署策略中。共享介面定義了遷移邊界——程式呼叫具有共同語義的操作，而每個後端（模擬或真實）則提供各自的感知、校正與低階執行機制。這種分離也讓 Skill2Real 能夠在零樣本設定下，無需真實世界的任務策略微調或技能記憶更新，就能將凍結的技能遷移到實體機器人。

**Q6：為什麼 Skill2Real 採用階層式的小腦（Cerebellum）-大腦（Brain）設計？**
A：階層式設計反映了長時程操作任務的自然結構：局部操作技能（如抓取、放置、推動）是可重用的基本單元，而任務層級的行為則需要將這些技能組合成長時程程式並具備規劃與恢復能力。Skill2Real 的第一階段讓小腦學習可重用的局部操作技能，第二階段則凍結這個技能庫，讓大腦學習如何將其組成長時程任務程式。這種「先凍結再組合」的策略避免了兩個層級同時學習時的不穩定性，也確保了小腦學到的局部技能能夠被不同的大腦策略所重用。實驗結果證實了這個設計的價值——在真實 UR5e 上，完整的大腦-小腦階層達到 78.75% 的平均任務完成率，而僅有局部技能時僅為 56.25%。

**Q7：Skill2Real 在哪些基準測試上進行了評估，主要結果為何？**
A：Skill2Real 在三個層級的基準測試上進行了評估：LIBERO-90（用於訓練技能）、LIBERO-Pro Long（未見過的長時程任務）以及 Robosuite 的七個單臂與雙臂任務。在 LIBERO-Pro Long 上，凍結的 LIBERO-90 技能將成功率從 2.0% 提升至 56.3%（使用 Astra）以及從 0.5% 提升至 49.0%（使用 Opus 5），展現了跨任務與跨提議者的泛化能力。在 Robosuite 上，獨立學習的技能庫將平均成功率從 16.6% 提升至 85.1%（使用 Sol）以及從 19.4% 提升至 89.4%（使用 Opus 5）。在真實 UR5e 機器人上，凍結的 Sol 訓練 LIBERO-90 技能在四個操作任務上達到 78.75% 的平均完成率，證實了模擬到真實的零樣本遷移確實可行。

**Q8：消融實驗揭示了驗證者與治理者的重要性，具體數據為何？**
A：在 LIBERO-90 訓練過程中移除驗證者或治理者都會顯著降低最終在 LIBERO-Pro Long 上的成功率。具體而言，移除驗證者會使最終成功率降低 17.3 個百分點，而移除治理者則會降低 13.3 個百分點。這些數據表明，驗證者提供的特權模擬證據診斷對於產生高品質的公開基礎對齊回饋是不可或缺的，而治理者透過彙整多輪驗證回放的證據來決定是否接受更新，則提供了重要的品質把關機制。這兩個元件共同確保了只有經過充分驗證的技能更新才會被納入記憶，從而維持了技能庫的可靠性與可遷移性。

**Q9：真實世界的遷移效能與模擬中的表現相比如何？**
A：在真實 UR5e 機器人上，Skill2Real 達到 78.75% 的平均任務完成率，相較於僅有局部技能時的 56.25% 有顯著提升，證實了任務層級組合對於長時程行為的價值。值得注意的是，這個遷移是在完全凍結的技能庫下實現的，沒有進行任何真實世界的任務策略微調或技能記憶更新。模擬與真實之間的效能差距（模擬中 LIBERO-Pro Long 達 56.3%，真實中四個任務達 78.75%）反映了不同任務難度與評估標準的差異，但整體而言，Skill2Real 展現了對光照、材質與動力學變化的魯棒性。這項結果支持了「透過通用機器人介面學習並遷移可執行技能階層」的可行性。

**Q10：Skill2Real 適合哪些實際應用場景？**
A：Skill2Real 特別適合那些需要在模擬中學習複雜操作技能並部署到真實機器人的場景，例如工業自動化中的零件組裝、倉儲物流中的物品分揀與搬運、以及家庭服務機器人的日常家務操作。由於其零樣本遷移特性，企業可以在不接觸實體機器人的情況下，透過模擬訓練來開發機器人技能，大幅降低開發成本與時間。對於需要快速適應新任務的場景，Skill2Real 的階層式技能組合能力也提供了靈活性——只需訓練新的小腦技能或大腦組合策略，就能擴展機器人的能力範圍。此外，在醫療機器人、危險環境作業等真實訓練成本極高的領域，這種模擬學習、真實部署的模式尤為重要。

**Q11：從產品化的角度來看，Skill2Real 帶來哪些工程考量？**
A：從產品化角度，Skill2Real 的共享程式碼式策略介面設計有利於模組化開發，不同團隊可以分別負責模擬訓練、真實部署與介面維護，降低了系統整合的複雜度。然而，產品化過程中也需考量幾個工程議題：首先，基礎視覺語言模型的推論延遲與計算成本會影響即時控制的效能，需要在邊緣裝置上進行最佳化；其次，技能庫的品質管控至關重要，因為凍結的技能一旦部署就很難即時修正，需要建立完善的模擬驗證流程；最後，不同機器人硬體的 API 語義對齊也是實務上的挑戰，需要為每種機器人平台開發對應的介面實作。

**Q12：Skill2Real 對機器人與 AI 領域的更廣泛影響是什麼？**
A：Skill2Real 展示了一種「正交於基礎模型能力」的遷移途徑——它透過在模擬中學習可遷移的任務知識，為基礎模型本身無法直接獲得的機器人操作能力提供了補充。這種思路可能會影響未來機器人學習的研究方向，從單純依賴更大基礎模型轉向結合模擬學習與基礎模型推理的混合架構。其階層式可執行技能的設計也呼應了神經符號 AI 的趨勢，將符號化的程式組合與神經網路的感知能力相結合。長期來看，這種框架可能促進機器人技能市場的發展——技能可以被開發、驗證、共享並部署到不同的機器人平台上，加速機器人技術的普及。

**Q13：Skill2Real 存在哪些已承認的限制？**
A：Skill2Real 的效能高度依賴底層基礎視覺語言模型的能力，因此其表現會受到模型品質與成本的限制——使用更強的模型（如 Opus 5）通常能帶來更好的結果，但也代表更高的運算開銷。此外，雖然框架設計支援跨域遷移，但對於與訓練環境差異極大的真實場景（例如極端光照、未知物體類別），效能可能仍會下降。技能庫的建構需要大量的模擬訓練時間與運算資源，這對於資源有限的團隊可能構成門檻。最後，目前的評估主要集中在桌面級操作任務，對於更複雜的移動機器人或全身操作任務的適用性仍有待驗證。

**Q14：Skill2Real 可能面臨哪些失敗案例？**
A：在高度動態或非結構化的環境中（例如物體被意外推倒、多機器人協作場景），Skill2Real 的恢復機制可能無法及時應對所有失敗模式。當任務需要精確的力控制或觸覺回饋時，僅依賴視覺觀測的策略介面可能不足以完成操作。對於訓練中未見過的物體形狀或材質，技能庫中的局部技能可能無法直接適用，需要大腦層級進行更複雜的推理。此外，若真實機器人的感測器噪音或校準誤差超出模擬訓練時的隨機化範圍，技能執行可能會產生累積誤差，導致長時程任務失敗。

**Q15：基於 Skill2Real 的未來研究方向有哪些？**
A：未來研究可以朝幾個方向延伸：首先，將技能庫擴展到更多元的操作基元與任務類型，並探索跨具身形態的技能遷移，例如將單臂技能遷移到雙臂或移動機器人；其次，引入更豐富的感知模態（如觸覺、力回饋）到策略介面中，以處理需要精確物理交互的任務；第三，結合人類示範或偏好回饋來加速技能學習，並探索技能庫的持續更新機制而不破壞已學到的知識；最後，將 Skill2Real 的階層式設計與大型視覺-語言-動作（VLA）模型相結合，探討如何在保持可解釋性的同時利用更大規模的預訓練模型，是一個值得深入探索的方向。

## 實務應用指南

### 適用場景

1. **倉儲物流揀選與分揀作業**：在高度變化的 SKU、容器與光照條件下，傳統視覺策略常因外觀差異失效。Skill2Real 的「凍結技能庫」可直接從模擬遷移至真實分揀站，無需針對每個新產品重新收集真實示範資料，特別適用於 SKU 週轉率高的電商履約中心。

2. **長時程裝配任務（汽車電子、半導體後段封裝）**：當任務需要「抓取 → 對位 → 插入 → 鎖附」等多步驟組合時，Brain 層的任務組合能力可將已驗證的局部技能（Cerebellum）組合成可恢復的長時程式，適用於需要錯誤恢復的精密裝配產線。

3. **實驗室自動化（高通量藥物篩選、生物樣本處理）**：實驗室任務環境變化頻繁（耗材批次、液面高度、機器人標定漂移），且不容許大量真機試誤。透過共享程式碼介面，模擬中學到的技能可在不同實驗室機台間遷移，縮短部署時間。

4. **服務機器人於非結構化家庭/餐飲場景**：例如整理桌面、收拾餐具等任務，環境具備高度感知與動力學差異。Skill2Real 的跨域基礎對齊（cross-domain grounding）讓基礎視覺語言模型（VLM）能在真實場景中即時對齊模擬學到的技能語義。

5. **教育與研究型機器人平台**：大學與研究機構常受限於真機時數與維護成本。Skill2Real 允許學生在模擬器中學習並驗證技能，再以零樣本方式部署至 UR5e 等標準硬體，降低研究門檻。

### 實作前置條件

**資料需求**
- 模擬環境資產：LIBERO-90、LIBERO-Pro Long、Robosuite 任務定義與場景檔案；UR5e 對應的 MuJoCo/Isaac Sim 模型與標定參數。
- 基礎視覺語言模型 API 存取權限（GPT-5.6 Sol、GPT-6 Astra、Opus 5 等），用於 Proposer 與 Verifier 的程式碼生成與診斷。
- 真實機器人介面層：UR5e 的 RTDE 控制介面、相機內外參、夾爪驅動程式，以及與模擬器對齊的觀測空間定義（RGB、夾爪狀態、末端位姿）。

**運算資源**
- 模擬訓練階段：建議至少 1–2 張高階 GPU（如 A100/H100）用於批次回放與 VLM 推理；VLM 呼叫頻率高時需注意 API 成本與速率限制。
- 部署階段：單張中階 GPU 或高效能邊緣設備即可執行凍結的技能庫推論；VLM 呼叫可採雲端或本地小型 VLM 替代方案。

**技能門檻**
- 熟悉 Python 與程式碼生成式代理（code-as-policy）模式，理解 Proposer-Verifier-Governor（PVG）三角色分工。
- 具備機器人學基礎：座標系轉換、正逆運動學、夾爪控制介面。
- 具備強化學習或模仿學習經驗者能更快理解 Cerebellum 與 Brain 的階層式學習策略；無經驗者亦可從程式碼介面層切入。

### 實作步驟建議

**階段一：建立共享程式碼介面（1–2 週）**
1. 定義 API 語義層：盤點模擬器與真實機器人均可呼叫的操作（如 `pick(obj)`、`place(obj, target)`、`move_to(pose)`），確保語義在兩端一致。
2. 實作雙後端：模擬端呼叫 MuJoCo/Robosuite/LIBERO；真實端呼叫 UR5e RTDE 與相機驅動。介面層負責隱藏後端差異，僅暴露公開觀測。
3. 設計觀測抽象：統一 RGB 影像、夾爪狀態、末端位姿的資料結構，避免將模擬器內部狀態（如物體真實座標）洩漏至部署端。

**階段二：實作 PVG 迴圈（2–3 週）**
1. Proposer：基於 VLM 從公開觀測與 API 返回值生成可執行程式。
2. Verifier：利用特權模擬證據（物體真實位置、接觸力、任務完成旗標）診斷執行結果，並轉譯為公開可解讀的回饋。
3. Governor：彙整多輪驗證回放，僅在統計證據支持時接受技能更新，避免單次雜訊導致錯誤記憶。
4. 設計驗證回放的批次協議：每次技能更新需通過 N 次獨立回放的成功率閾值。

**階段三：階層式技能學習（3–4 週）**
1. 訓練 Cerebellum：在 LIBERO-90 上學習可重用的局部操作技能，凍結後存入技能記憶。
2. 訓練 Brain：以凍結的 Cerebellum 為基礎，學習長時程任務組合（含規劃與恢復邏輯）。
3. 跨基準測試：在未見過的 LIBERO-Pro Long 上評估凍結技能庫的遷移能力，目標對齊論文的 56.3% 成功率基準。

**階段四：真實部署與驗證（2–3 週）**
1. 將凍結技能庫載入真實機器人，Proposer 透過相同介面對齊真實觀測。
2. 在 UR5e 上執行四類操作任務，量測平均完成率（論文基準 78.75%）。
3. 收集失敗案例，回頭檢視 Verifier 診斷品質與 Governor 接受準則是否需調整。

**階段五：產品化封裝（持續）**
1. 建立技能版本管理與回滾機制。
2. 設計監控儀表板：追蹤任務成功率、回退次數、VLM 呼叫成本。
3. 撰寫操作手冊：明列技能庫更新流程、API 變更審核、真機安全停機程序。

### 潛在風險與注意事項

**風險一：VLM 幻覺導致危險動作**
- *緩解*：所有 Proposer 生成的程式必須經過 Governor 的多回合驗證；高風險動作（如接近關節極限、夾爪高速閉合）應在介面層加入硬體層安全護欄。

**風險二：模擬器與真實世界的動力學差距未被覆蓋**
- *緩解*：在域隨機化中納入接觸動力學、摩擦係數、馬達延遲等參數；若差距過大，於 Cerebellum 階段保留少量真機示範資料用於殘差策略微調。

**風險三：技能庫膨脹導致檢索效率下降**
- *緩解*：對技能庫做語義聚類與層次化索引；定期淘汰低使用率或被 Governor 拒絕的技能。

**風險四：跨模型遷移時 Proposer 行為不一致**
- *緩解*：在介面層加入輸出結構化校驗（JSON Schema），強制所有 VLM 遵循統一的程式碼風格；對關鍵技能提供單元測試。

**風險五：API 成本與延遲影響即時性**
- *緩解*：將高頻子任務（如夾爪開合）預編譯為本地動作基元，僅在規劃與恢復階段呼叫 VLM；考慮本地部署小型 VLM 作為備援。

**風險六：凍結技能庫無法適應硬體變更**
- *緩解*：保留「技能庫熱修補」通道，僅允許經過完整 PVG 驗證的更新進入；硬體變更需觸發新一輪 Cerebellum 訓練。

### 與其他技術的整合建議

1. **與擴散策略（Diffusion Policy）整合**：將 Cerebellum 學到的局部技能作為擴散策略的動作基元，Brain 層負責切換與組合，兼顧學習效率與動作平滑度。

2. **與檢索增強生成（RAG）整合**：將技能庫以向量資料庫形式儲存，Proposer 在生成程式前先檢索最相關技能，提升長時程任務的語義對齊。

3. **與 ROS 2 整合**：將共享程式碼介面封裝為 ROS 2 節點，使 Skill2Real 可無縫接入既有機器人作業系統生態，支援分散式部署。

4. **與視覺-語言-動作（VLA）模型整合**：以 VLA 模型作為 Proposer 的骨幹，Cerebellum 與 Brain 的技能庫作為其高階記憶，補強 VLA 在長時程任務上的規劃能力。

5. **與 MLOps 平台整合**：將 PVG 迴圈的訓練、驗證、部署流程納入 CI/CD 流水線，確保每次技能更新皆可追溯、可回滾、可重現。

6. **與數位孿生平台整合**：將模擬器與真實機台狀態同步，使 Verifier 的特權證據可在數位孿生中重現，加速除錯與合規審查。

---

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）與第 3 節（Method）的整體架構圖，建立「Proposer 提議、Verifier 驗證、Governor 治理」三角色分工的直覺；接著跳到實驗章節的消融實驗，理解移除 Verifier 或 Governor 對最終效能的影響（17.3 與 13.3 百分點），這有助於掌握每個元件的必要性，而無需深入數學細節。

**給 AI 工程師**：重點研讀第 3 節的 PVG 迴圈實作細節與第 4 節的階層式訓練流程，特別關注 Cerebellum 凍結後 Brain 如何組合技能的設計；建議動手實作一個最小可運行版本（單一 LIBERO 任務 + GPT 系列 API），驗證介面抽象是否足以隔離模擬器特權資訊，並評估 VLM 呼叫成本與延遲在自家基礎設施下的可行性。

**給研究者**：第 2 節（Related Work）提供了完整的定位座標——相較於域隨機化、特權評論家、程式碼生成方法與人類引導技能庫的差異；建議深入分析 PVG 的非對稱資訊流設計如何避免「將模擬器特權狀態洩漏至部署策略」這個核心瓶頸，並思考此框架在非機器人領域（如程式碼生成、科學實驗自動化）的可遷移性。

**給產品經理**：聚焦於第 1 節的問題陳述、第 4 節的跨基準測試結果（LIBERO-Pro Long 從 2.0% 提升至 56.3%、真實 UR5e 達 78.75% 平均完成率）以及消融實驗的商業意涵；理解「凍結技能庫零樣本遷移」代表客戶無需為每個新場景重新訓練，這對縮短交付週期、降低售後維護成本有直接影響；同時關注 VLM API 成本與安全護欄設計，作為商業化時的風險評估依據。
