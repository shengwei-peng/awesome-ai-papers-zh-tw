## ⚡ TL;DR

探討影片生成模型是否真正理解物理法則並轉化為可執行的機器人操作。
提出 Dream.exe 框架，透過影片到執行管線將生成動作轉為機器人軌跡並於物理模擬器驗證。
實驗發現部分模型可成功執行，但視覺品質無法預測物理可執行性。

## 摘要翻譯

影片生成模型（video generation models）在合成視覺上具吸引力的內容方面已取得顯著進展，但其輸出仍侷限於虛擬領域。一個自然而然的問題是：當這些模型生成的影片從螢幕進入現實時，它們能在多大程度上反映物理世界（physical world）？我們提出以機器人操作（robotic manipulation）作為探討此問題的具體且可量測的窗口：若一個模型真正內化了物理法則（internalized physical laws），其所描繪的動作應能轉化為可執行的機器人行為（executable robot behavior）。我們提出 Dream.exe，一個透過影片到執行管線（video-to-execution pipeline）將此準則具體實現的評估框架（evaluation framework）。給定一張場景影像（scene image）與一項任務描述（task description），Dream.exe 會合成一段操作影片（manipulation video），將生成動作（generated motion）轉換為機器人軌跡（robot trajectories），並在物理模擬器（physics simulator）中執行這些軌跡，從而產生純視覺指標（purely visual metrics）無法提供的接地訊號（grounding signal）。利用此管線，我們評估了 8 個模型，涵蓋前沿閉源生成模型（frontier closed-source generators）、開源生成模型（open-source generators）與機器人專用模型（robot-specific models）。我們的基準測試（benchmark）涵蓋 101 項人工整理的操作任務（manipulation tasks），分為三個物理複雜度（physical complexity）等級，並從視覺品質（visual quality）、軌跡忠實度（trajectory fidelity）與執行成功率（execution success）等面向進行量測。令人鼓舞的是，數個模型達到了可量測的執行成功率，顯示從網際網路規模資料（internet-scale data）中學得的生成先驗（generative priors）已編碼了有意義的物理知識（physical knowledge）。然而，視覺品質被證明是對可執行性（executability）預測力不佳的指標，揭示了標準視覺評估（standard visual evaluations）無法捕捉的模型能力面向。Dream.exe 將於 https://github.com/showlab/Dream.exe 開源釋出。

### 核心貢獻（3～5點）
- 提出以機器人操作作為檢驗影片生成模型是否內化物理法則的具體窗口，並設計 Dream.exe 評估框架，透過影片到執行管線產生純視覺指標無法提供的接地訊號。
- 建構涵蓋 101 項人工整理操作任務、三個物理複雜度等級的基準測試，系統性評估 8 個前沿閉源、開源及機器人專用模型。
- 證實從網際網路規模資料學得的生成先驗已編碼有意義的物理知識，數個模型可達到可量測的執行成功率。
- 揭示視覺品質是對可執行性預測力不佳的指標，標準視覺評估無法捕捉模型在物理有效性上的真實能力差距。

### 適合對象
從事機器人學習、影片生成模型與世界模型研究，以及關注生成式 AI 物理一致性與可執行性評估的學者與工程師。特別適合需要跨足電腦視覺與具身智能領域、尋求嚴謹物理 grounding 方法的研究者參考。

## 深度分析

#### 方法論解析

Dream.exe 的核心命題在於：若 Video Generation Models（影片生成模型）確實透過 Internet-scale Data（網際網路規模資料）學得了 Implicit World Models（隱式世界模型），則其生成的動作理應能轉譯為 Executable Robot Behavior（可執行的機器人行為）。為此，作者提出一套 Video-to-Execution Pipeline（影片到執行管線），將純視覺的生成結果轉化為可在 Physics Simulator（物理模擬器）中執行的機器人指令，並以 Task Success（任務成功）作為 Grounding Signal（接地訊號）。

該管線的輸入為一張 Scene Image（場景影像）與一段自然語言的 Task Description（任務描述）。首先，模型需生成一段 Manipulation Video（操作影片）。接著，系統透過一個五階段的影片到軌跡提取管線恢復可執行運動：利用 Monocular Depth Estimation（單眼深度估計）與已知的 Camera Parameters（相機參數），將 2D End-effector（末端執行器）像素運動提升至 World-frame 3D Trajectories（世界座標系三維軌跡）；依據 Interaction Context（交互情境）推斷 Gripper Timing（夾爪開合時機）；最終轉換為 Structured Action Stream（結構化動作流）以供機器人控制器遵循。

評估框架設計了三個軸向：首先是 Visual Evaluation（視覺評估），檢視 Robot Stability（機器人穩定性）、Physical Plausibility（物理合理性）與 Task Adherence（任務遵循度）；其次是 Trajectory Evaluation（軌跡評估），衡量提取出的 Robot Trajectories（機器人軌跡）之 Trajectory Fidelity（軌跡忠實度）；最後是 Closed-loop Execution（閉環執行），在模擬環境中取得 Fine-grained Success Scores（細粒度成功評分）與 Overall Task Success Rate（整體任務成功率）。任務套件包含 101 個人工策劃的 Manipulation Tasks（操作任務），取材自 RoboCasa365，並依 Physical Complexity（物理複雜度）分為三個層級，涵蓋單一物體的 Atomic Manipulation（原子操作）到多階段的 Composite Tasks（複合任務）。

#### 實驗數據解讀

本研究評估了 8 個模型，橫跨 Frontier Closed-source Generators（前沿閉源生成模型，如 Wan、Kling、Veo）、Open-source Generators（開源生成模型）以及 Robot-specific Models（機器人專用模型）。實驗結果呈現三項值得深思的發現。

第一，部分通用影片生成模型確實達到了可測量的 Execution Success（執行成功率）。這項結果支持了 Generative Priors（生成先驗）已從大規模資料中編碼了 Meaningful Physical Knowledge（有意義的物理知識）的假說，顯示 World Model Hypothesis（世界模型假說）並非純粹推測。

第二，Visual Quality（視覺品質）與 Executability（可執行性）之間存在顯著脫鉤。在標準視覺指標上領先的模型，往往在物理執行階段失敗；反之，視覺分數平庸的模型卻可能產生物理有效的軌跡。這直接證明 Purely Visual Metrics（純視覺指標）無法捕捉 Physical Validity（物理有效性），也揭示了 Temporal Consistency（時間一致性）或 Photorealistic（照片級真實感）等傳統指標的盲點。

第三，Robot-specific Policy Model（機器人專用策略模型）並未穩定勝過通用生成模型。後者在多樣化的任務與 Camera Viewpoints（相機視角）上展現更強的 Generalization（泛化能力）。這暗示專為機器人設計的模型可能過度擬合於特定分佈，而通用模型從網路資料中學到的廣泛先驗反而有助於跨域遷移。

#### 與現有研究的比較

既有研究主要沿兩條軸線發展，而 Dream.exe 恰好填補了兩者之間的鴻溝。其一為 Video Generation Benchmarks（影片生成基準測試），如 EvalCrafter、VBench 與 T2V-CompBench。這些框架評估 Visual Quality（視覺品質）、Motion Quality（動作品質）、Text-video Alignment（文字-影片對齊）與 Compositional Reasoning（組合推理），但本質上只問影片「看起來是否自然」，而不問其隱含的運動「是否能在 Physical World（物理世界）中完成任務」。換言之，一個生成機器手臂優雅穿過桌面的模型，與另一個生成物理有效運動的模型，在這些基準中可能無法區分。

其二為 Robot Learning（機器人學習）領域近期興起的方向，即利用生成影片作為 Scalable Behavioral Priors（可擴展的行為先驗），以減少對昂貴 Physical Demonstrations（物理示範）的依賴。然而，這些研究多將生成影片直接當作訓練資料，缺乏對其內含物理知識的直接驗證。Dream.exe 的貢獻在於首次將 World Model Hypothesis（世界模型假說）轉化為可操作的檢驗標準：透過閉環物理模擬提供標準視覺評估無法給予的 Grounding Signal（接地訊號）。

相較於 Brooks et al.、Kang et al. 等人提出的 Implicit World Models（隱式世界模型）與 Physical Causality（物理因果關係）推論，Dream.exe 不僅驗證這些 Statistical Regularities（統計規律性）是否存在，更進一步量化其對機器人任務的實用價值。

#### 可重現性評估

Dream.exe 框架本身承諾 Open-source（開源），原始碼將釋出於 https://github.com/showlab/Dream.exe，這對社群後續研究極具價值。任務套件基於公開的 RoboCasa365 資料集，包含 101 個手動策劃的 Manipulation Tasks（操作任務），並明確定義三個 Physical Complexity（物理複雜度）層級，具備一定的標準化基礎。

然而，完整重現所有實驗結果仍面臨挑戰。受評的 8 個模型中包含多個 Frontier Closed-source Generators（前沿閉源生成模型），如 Wan、Kling、Veo 等，這些模型僅能透過 API 呼叫取得輸出，並無 Open Weights（開放權重）或訓練細節。這意味著其他研究者無法在相同隨機種子或內部參數下完全複製其生成行為。此外，Video-to-trajectory Extraction（影片到軌跡提取）管線依賴 Monocular Depth Estimation（單眼深度估計）模組與特定的 Physics Simulator（物理模擬器），雖然技術細節已於文中說明，但模擬器版本、控制器參數與接觸動力學的設定若未完整釋出，仍可能影響 Execution Success（執行成功率）的絕對數值。

整體而言，Benchmark（基準測試）的評估協議與任務定義具備高度可重現性，但涉及商業閉源模型的比較結果，本質上受限於 API 的可用性與服務條款變動。

#### 未來研究方向

Dream.exe 開啟了多條值得深入探索的研究路徑。首先，目前的 Video-to-execution Pipeline（影片到執行管線）僅能從像素變化中隱式恢復運動，缺乏 Explicit 3D Geometry（顯式三維幾何）、Contact Forces（接觸力）與 Gripper State（夾爪狀態）的直接表徵。未來可結合 3D-aware Generation（三維感知生成）或具備物理約束的擴散模型，提升軌跡提取的精確度與穩健性。

其次，Execution Feedback（執行回饋）可作為訓練訊號，用於微調 Video Generation Models（影片生成模型）。若能建立「生成—執行—評分—更新」的迴路，有望縮小 Visual Quality（視覺品質）與 Executability（可執行性）之間的落差，使模型不僅「看起來真實」，更能「物理上可行」。

第三，Benchmark（基準測試）可擴展至更廣泛的物理現象，例如 Fluid Dynamics（流體動力學）、可變形物體操作，以及更複雜的 Multi-stage Composite Tasks（多階段複合任務）。同時，從 Simulation（模擬）遷移至真實機器人硬體（Sim-to-real Transfer），將是驗證這些生成先驗是否真正適用於 Physical World（物理世界）的關鍵下一步。

最後，通用生成模型在 Generalization（泛化能力）上勝過 Robot-specific Models（機器人專用模型）的發現，暗示未來可將大型影片生成模型視為 World Models（世界模型），應用於 Model-based Reinforcement Learning（基於模型的強化學習）或長期規劃，進一步釋放 Internet-scale Data（網際網路規模資料）中隱含的物理知識。

## 論文問答

**Q1：Dream.exe 旨在解決的核心問題是什麼？**
A：Dream.exe 旨在解決影片生成模型雖然能產生視覺上極具說服力的內容，卻缺乏對物理世界真實法則理解的根本落差。這些模型的輸出目前仍局限於虛擬領域，標準評估無法判斷其生成的動作是否真正內化了物理法則，或僅是像素層面的統計規律性重現。透過機器人操作這一具體且可量測的窗口，Dream.exe 試圖驗證當生成影片從螢幕進入現實時，其隱含的運動是否真能轉化為可執行的機器人行為。

**Q2：為何現有的影片生成基準測試無法有效評估模型的物理理解能力？**
A：現有的基準測試主要依賴視覺品質、時間一致性與人類美學評分等純視覺指標，這些指標只能衡量影片看起來是否自然，卻無法檢驗其物理有效性。舉例來說，一個生成機器手臂優雅穿過桌面的模型，在標準視覺評估中與產生物理有效軌跡的模型難以區分。因此，這些評估方式無法提供接地訊號來確認模型究竟學到了隱式世界模型，還是僅掌握了表面像素的相關性。

**Q3：為何選擇機器人操作作為評估模型理解物理世界的窗口？**
A：機器人操作提供了一個具體且明確的測試平台，因為其成功標準嚴格取決於機器人能否在物理模擬器中實際完成任務，而非僅憑人類主觀判斷。這類任務要求模型精確遵循幾何關係、接觸力與物體動力學等物理法則，任何違反現實的細節都會直接導致執行失敗。透過將生成影片轉換為可執行的機器人軌跡，Dream.exe 在視覺生成與物理現實之間建立了直接的因果連結，使模型能力變得可量測且無歧義。

**Q4：Dream.exe 框架的核心方法論是什麼？**
A：Dream.exe 提出了一套完整的影片到執行管線，彌補像素空間生成與機器人控制之間的鴻溝。此評估框架在給定場景影像與任務描述後，首先合成一段操作影片，接著透過五個步驟從中萃取隱含的動作並還原為三維軌跡，最後在物理模擬器中執行這些軌跡。這個閉迴路系統以任務執行成功率作為接地訊號，提供了純視覺指標無法給予的客觀評估。

**Q5：實現影片到軌跡轉換的關鍵創新是什麼？**
A：關鍵創新在於將隱式編碼的二維像素運動，提升為顯式的世界座標系三維機器人軌跡，且無需生成過程中提供任何真實三維監督。該管線利用單目深度估計與已知相機參數，從幾何上定位末端執行器的運動，並根據影片中的交互情境推斷夾爪的開合時機。這使得系統能夠僅從原始像素序列中重建出包含夾爪狀態與接觸力的結構化動作串流，從而實現可執行軌跡的恢復。

**Q6：為何基準測試要將操作任務分層為三種物理複雜度？**
A：將任務分層為從單一物體的原子操作到多階段複合任務的三個等級，使 Dream.exe 能夠系統性地評估模型在不同難度下的物理理解能力。較簡單的任務可檢驗基本的幾何與運動學一致性，而複雜任務則要求模型具備長期規劃、多步驟推理與持續的物理合理性。這樣的設計選擇能夠揭示模型從成功執行到失敗的邊界究竟落在何處，從而對其內化物理知識的極限提供細緻的洞察。

**Q7：Dream.exe 的基準測試包含哪些內容，共評估了多少模型？**
A：該基準測試包含從 RoboCasa365 精選出的 101 段手動策劃操作任務片段，涵蓋多樣化場景並劃分為三個難度等級。研究團隊利用此測試套件評估了八個不同的模型，範圍涵蓋前沿閉源生成模型、開源生成模型以及機器人專用模型。這樣廣泛的選擇確保了比較不僅能反映一般影片生成的最新水準，也能檢視專門針對機器人領域設計的模型表現。

**Q8：關於模型表現，實驗最重大的發現是什麼？**
A：實驗發現若干通用影片生成模型達到了可量測的執行成功率，顯示從網際網路規模資料中學到的生成先驗確實編碼了有意義的物理知識。然而研究也指出，視覺品質是可執行性的不良預測指標，意味著在標準知覺指標上領先的模型，其輸出在物理具現化時經常失敗。此外，機器人專用模型並未一致地超越通用生成模型，因為後者在面對多樣化任務與不同相機視角時展現出更強的泛化能力。

**Q9：三軌道評估揭示了模型能力的哪些面向？**
A：涵蓋視覺評估、軌跡忠實度分析與閉迴路執行成功率的三軌道評估，提供了單一指標無法呈現的多維度能力剖面。它揭露了系統性的失效模式，例如某些模型可能產生視覺上穩定的影片，但其軌跡卻違反物理限制或無法在模擬中完成任務。這種解耦顯示視覺合理性、軌跡準確度與執行成功率是彼此獨立的能力軸線，必須同時納入評估才能完整理解模型表現。

**Q10：Dream.exe 在真實世界的機器人學習管線中可以如何應用？**
A：Dream.exe 可作為機器人學習中可擴展的行為先驗來源，有助於減少對昂貴物理示範與真實世界資料收集的高度依賴。透過將生成影片導入執行管線進行篩選，實務工作者能自動策展出在物理上有效的軌跡，供模擬環境中的模仿學習或強化學習使用。這種方法能夠加速機器人在非結構化環境中的部署，特別是在收集真實訓練資料成本過高或具有危險性的場景中。

**Q11：視覺品質與可執行性之間的落差，對影片生成平台有哪些產品層面的意涵？**
A：視覺品質與可執行性之間的脫節意味著，針對人類觀賞最佳化的商業影片生成工具可能隱含物理不一致性，使其不適合用於機器人或工業模擬應用。對於希望利用這些模型產生合成訓練資料的產品團隊而言，必須納入像 Dream.exe 這樣以物理為基礎的驗證管線，以確保生成內容不僅美觀，更具機械上的正確性。這也暗示未來的產品功能需要在傳統解析度與真實感指標之外，明確提供物理合理性的認證機制。

**Q12：Dream.exe 可能如何影響影片生成與具身人工智慧交叉領域的未來研究？**
A：透過引入以執行為基礎的接地訊號，Dream.exe 將評估典範從被動的視覺檢視轉向主動的物理驗證，可能促使研究優先順序轉向學習真正世界模型的模型，而非僅掌握表面外觀統計的模型。它建立了一個嚴謹的基準，鼓勵開發具備具身感知、接觸推理與長期物理一致性的影片生成器。這有望促進電腦視覺與機器人學社群的更緊密整合，推動模型在訓練階段就明確朝向可執行性進行最佳化。

**Q13：論文承認 Dream.exe 框架存在哪些根本限制？**
A：該框架目前依賴固定的影片到軌跡萃取管線，其中使用單目深度估計與已知相機參數，在處理嚴重遮擋或訓練時未見過的新穎相機視角時可能引入誤差。此外，評估目前僅限於物理模擬器內，由於摩擦力、致動器動力學與感測器雜訊等模擬與真實落差，結果未必能完美遷移到真實機器人上。基準測試目前也聚焦於桌面操作任務，對於高自由度人形機器人或大規模戶外環境的擴展性仍屬未解問題。

**Q14：在影片到軌跡轉換與執行過程中，暴露了哪些類型的失效案例？**
A：常見的失效案例包括生成影片中機器手臂與物體或桌面發生穿透，違反碰撞約束，但在標準指標下仍顯得視覺連貫。另一類失敗涉及夾爪開合時機推斷錯誤，模型描繪的抓取動作與實際接觸點不符，導致模擬中物體滑落。多階段複合任務則經常因為各步驟間累積的物理誤差而失敗，顯示模型即便在單幀畫面看起來真實的情況下，仍難以掌握長期因果推理。

**Q15：論文建議了哪些未來研究方向？**
A：作者建議未來應開發明確以物理執行目標進行訓練的影片生成模型，而非僅最佳化像素層級重建或美學品質。後續研究可將管線擴展至真實機器人硬體以閉合模擬到現實的迴路，並將任務套件擴充至可變形物體、工具使用與人機協作等更廣泛的領域。此外，將可微分物理或神經物理引擎直接整合進影片生成器的訓練損失中，被視為使模型本質上就能夠「夢見」可執行操作的一條極具前景的路徑。

## 實務應用指南

### 適用場景

1. **自動化產線快速程式生成**：針對少量多樣的組裝任務，作業員以自然語言任務描述與單張場景影像，由影片生成模型產出操作影片，再經 Dream.exe 的影片到執行管線轉為機器人軌跡，快速部署於物理模擬器驗證，縮短新產品導入週期。
2. **物流倉儲異質品揀選**：在電商物流中心處理形狀、包裝各異的 SKU 時，利用網際網路規模資料訓練出的生成先驗產生抓取與放置的動態預測，透過物理模擬器驗證碰撞與穩定性，再下放至實體機器手臂執行，降低對大量真實物理示範的依賴。
3. **服務型機器人任務規劃驗證**：家用或醫療輔助機器人在執行多階段複合操作（如「拿杯子、倒水、放回原位」）前，先以影片生成模型「想像」完整流程，並在模擬環境中檢驗物理有效性與執行成功率，作為安全上線前的把關機制。
4. **生成式模型能力稽核與選型**：企業在評估前沿閉源生成模型（如 Kling、Wan）或開源生成模型（如 CogVideoX、HunyuanVideo）時，不僅評估視覺品質，更透過 Dream.exe 的執行成功率與軌跡忠實度指標，篩選真正內化物理法則的模型，避免被純視覺指標誤導。
5. **具身智慧資料擴增**：將影片生成模型的輸出經 Dream.exe 過濾，留下物理可執行的片段作為高品質行為先驗，補充機器人學習中真實操作資料的不足，特別適用於罕見或高風險操作任務的模擬訓練。

### 實作前置條件

- **資料**：需準備高品質的場景影像（RGB）與對應的自然語言任務描述；若需進行量化評估，需具備類 RoboCasa365 格式的操作任務定義，包含物件姿態、相機參數與真實機器人軌跡作為比對基準。
- **運算**：影片生成模型推論需高階 GPU（如 A100／H100）支援；物理模擬器閉環執行需額外運算資源；若要完整跑完 101 個操作任務的基準測試，建議具備多卡叢集或雲端彈性運算能力。
- **技能**：團隊需具備電腦視覺（單目深度估計、2D 關鍵點追蹤）、機器人學（正向／逆向運動學、軌跡規劃）與物理模擬（接觸力建模、夾爪控制）的跨領域知識；同時需熟悉影片生成模型的 API 呼叫或開源權重部署。

### 實作步驟建議

1. **環境建置與資料準備**：建置與 RoboCasa 相容的物理模擬器環境，匯入 3D 場景與機器人模型，校準相機內參與外參；蒐集並標註初始場景影像與任務描述。
2. **影片生成與品質初篩**：將場景影像與任務描述餵入目標影片生成模型，產出操作影片；先以標準視覺評估（如 FVD、CLIPSIM）過濾明顯低品質樣本，但保留視覺分數中等卻可能具物理合理性的候選。
3. **2D 到 3D 軌跡提取**：執行 Dream.exe 的五步驟影片到執行管線——偵測末端執行器 2D 像素軌跡、利用單目深度估計與已知相機參數提升至世界座標 3D 軌跡、根據互動語境推斷夾爪開合時機、轉換為結構化動作串流。
4. **閉環執行與指標蒐集**：將軌跡輸入機器人控制器，在物理模擬器中執行，記錄執行成功率、軌跡忠實度與任務達成細項；針對失敗案例分類（碰撞、滑脫、未到達、時序錯誤）。
5. **模型選型與迭代優化**：比較不同模型的視覺品質與可執行性關聯，選出執行成功率高的生成先驗；針對特定失敗模式（如深度估計誤差導致的高度偏移）優化軌跡提取模組，或微調影片生成模型以增強物理一致性。
6. **模擬到真實（Sim-to-Real）部署**：將驗證過的軌跡透過域隨機化或殘差學習遷移至實體機器人，並以 Dream.exe 的接地訊號作為數位孿生環境的驗證基準。

### 潛在風險與注意事項

- **視覺品質陷阱**：切勿僅以視覺流暢度或照片級真實感作為模型選型依據。論文明確指出視覺品質與可執行性相關性低，建議一律以物理模擬器的執行成功率作為最終驗收標準。
- **單目深度估計誤差**：2D 到 3D 的提升依賴單目深度估計，對於反光、透明或弱紋理物件容易產生系統性偏差，導致機器人軌跡在深度方向偏移。建議對這類物件引入額外幾何先驗或多視角補償。
- **接觸動力學缺失**：影片生成模型未顯式編碼接觸力與夾爪狀態，可能產生「穿模」或「假抓取」等物理無效動作。需在軌跡提取階段加入接觸偵測與力回饋檢查，並在模擬器中設定嚴格的碰撞偵測。
- **相機視角偏差**：不同相機視角會顯著影響生成品質與軌跡提取精度。部署時應固定相機參數，或訓練視角不變的特徵提取器，避免因視角變化導致執行成功率波動。
- **閉源模型 API 限制**：若使用 Kling、Wan 等閉源模型，需注意 API 的解析度、幀率與內容審查限制，可能影響機器人操作細節的生成完整性。建議保留開源生成模型作為備案。

### 與其他技術的整合建議

- **與機器人作業系統（ROS/ROS2）整合**：將 Dream.exe 的軌跡輸出封裝為 ROS Action 或 Topic，無縫銜接現有機器人控制器與運動規劃框架（如 MoveIt），實現從影片生成到實機控制的端到端管線。
- **與數位孿生平台整合**：將物理模擬器中的執行結果回饋至數位孿生環境（如 NVIDIA Isaac Sim、Unity Robotics），利用接地訊號同步更新虛擬場景狀態，建立「生成—驗證—部署」的閉環。
- **與大型語言模型（LLM）整合**：由 LLM 負責高階任務拆解與自然語言任務描述生成，Dream.exe 負責低階軌跡驗證與執行，形成多層次具身智慧架構。LLM 亦可根據模擬失敗回饋自動重寫任務描述，迭代優化生成結果。
- **與擴散模型微調管線整合**：針對特定操作領域（如精密組裝），可將 Dream.exe 的執行成功率作為獎勵訊號，透過強化學習或直接偏好優化（DPO）微調開源影片擴散模型，使其生成更具物理可執行性的操作影片。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從論文的圖二與摘要開始，先理解「影片生成→軌跡提取→物理模擬執行」的大致流程，不必深究單目深度估計或相機參數的數學細節；重點掌握「視覺好看不等於物理可做」這一核心發現，並嘗試在開源的 RoboCasa 環境中跑通 Dream.exe 的範例程式，建立直觀感受。
- **AI 工程師**：請聚焦第三章的影片到執行管線實作細節，特別是 2D 像素軌跡如何透過深度估計與相機參數提升至 3D 世界座標、夾爪時機推論的啟發式規則，以及與物理模擬器的介接方式；同時留意論文對八個模型在軌跡忠實度與執行成功率上的量化比較，作為選型與系統整合的參考。
- **研究人員**：建議深入分析第四節的實驗設計與失敗案例，特別是視覺品質與可執行性脫鉤的現象背後，隱式世界模型究竟編碼了哪些物理知識、又缺失了哪些接觸動力學；可進一步探討如何將 Dream.exe 的接地訊號融入影片生成模型的訓練損失，或擴展至更複雜的多手臂協作與彈性物體操作場景。
- **產品經理**：請將閱讀重心放在論文的適用場景與商業價值轉化，理解 Dream.exe 如何作為「生成式 AI 的物理驗收測試」；評估導入時需權衡閉源模型（視覺品質高但可控性低）與開源模型（可微調但需自建運算）的總體擁有成本，並將執行成功率設定為上線前的關鍵績效指標（KPI），而非僅追求影片解析度或流暢度。
