# UniClawBench：真實世界任務的通用主動式代理基準測試

## ⚡ TL;DR

現有基準多為沙箱單輪評估，且按情境分類混淆多項能力，難以診斷主動代理的失敗原因。
提出UniClawBench，按五項能力設計400雙語任務，在Docker以檢查點與三角色閉環評估。
跨模型與框架的實驗顯示，基礎模型能力與框架設計共同決定主動代理在真實環境的表現。

## 摘要翻譯

大型語言模型（large language models, LLM）與多模態大型語言模型（multimodal large language models, MLLM）的快速發展，加速了能操作日常工具（everyday tools）並在真實環境中協助使用者的主動式代理（proactive agents）之興起。然而，現有基準測試（benchmarks）難以有效評估此類代理，因為它們通常仰賴沙箱環境（sandboxed environments）與單輪評估典範（single-turn evaluation paradigm）。此外，其基於情境的任務分類法（scenario-based task taxonomy）在同一任務類別中混合了多種模型能力，使得難以辨識代理失敗的根本原因（root causes of agent failures）。為了克服這些限制，我們提出 UniClawBench，這是第一個能力導向基準測試（capability-driven benchmark），旨在評估動態真實世界環境（dynamic real-world environments）中的主動式代理。UniClawBench 圍繞五項基礎模型能力（foundational capability dimensions）建構：技能使用（Skill Usage）、探索能力（Exploration）、長上下文推理（Long-Context Reasoning）、多模態理解（Multimodal Understanding）與跨平台協調（Cross-Platform Coordination）。基於這些能力，我們設計了 400 項雙語真實世界任務（bilingual real-world tasks）。不同於仰賴靜態預錄答案的現有基準測試，我們的基準測試在即時 Docker 容器（live Docker containers）中，利用細粒度逐步完成檢查點（fine-grained step-by-step completion checkpoints）來評估代理。此外，我們設計了一個閉環評估策略（closed-loop evaluation strategy），包含執行代理（executor agent）、隱藏監督代理（hidden supervisor agent）與使用者代理（user agent），以模擬真實的多輪人類回饋（multi-turn human feedback），同時避免洩漏評分標準（grading criteria）。為了釐清基礎模型能力（base model capabilities）與代理框架（agent frameworks）層級設計選擇的個別影響，我們在多個代理框架下評估最先進的模型（state-of-the-art models）。透過跨模型與框架的全面比較（comprehensive comparisons），我們展示了基礎模型能力與代理框架設計如何共同影響真實世界環境中的表現。為了促進未來研究，我們將基準測試與程式碼公開於 https://github.com/HKU-MMLab/UniClawBench。

### 核心貢獻（3～5點）
- 提出首個能力導向基準測試 UniClawBench，以五項基礎能力維度評估主動式代理，並設計 400 項雙語真實世界任務。
- 在即時 Docker 容器中進行動態評估，採用細粒度逐步完成檢查點，取代傳統靜態預錄答案。
- 設計閉環評估策略，透過執行代理、隱藏監督代理與使用者代理模擬真實多輪人類回饋，並確保評分標準的資訊隔離（information isolation）。
- 在多個代理框架下評估最先進模型，區分基礎模型能力與框架設計對實際表現的個別與共同影響。
- 公開釋出基準測試與程式碼，供後續研究複現與擴展。

### 適合對象
本論文適合大型語言模型與多模態大型語言模型研究者、主動式代理與代理框架開發者、基準測試設計者，以及關注真實世界部署與人機協作互動的學術與產業讀者。

## 深度分析

#### 方法論解析

UniClawBench（本論文提出的通用主動代理基準測試）的核心方法論可從「能力導向的任務設計」、「動態真實世界環境（dynamic real-world environments）」、「細粒度逐步完成檢查點（fine-grained step-by-step completion checkpoints）」以及「三角色閉環評估策略（closed-loop evaluation strategy）」四個層面進行拆解。

首先，在任務設計上，作者明確揚棄傳統「基於情境的任務分類法（scenario-based task taxonomy）」（例如將任務分為 office、research 等應用情境），改採「能力導向基準測試（capability-driven benchmark）」。他們將主動式代理（proactive agents）在真實環境中所需的行為拆解為五項基礎能力維度（foundational capability dimensions）：

1. **Skill Usage（技能使用）**：代理能否正確呼叫、組合並重複使用預先定義或可學習的技能（skills），例如操作瀏覽器（browsers）、終端機（terminals）或各種日常工具（everyday tools）。
2. **Exploration（探索能力）**：在資訊不完整或環境狀態未知時，代理是否能主動探索、發現必要資訊並調整計畫。
3. **Long-Context Reasoning（長上下文推理）**：代理能否在長時間、多步驟的軌跡中維持目標一致性，處理長程依賴與中間狀態。
4. **Multimodal Understanding（多模態理解）**：代理對於螢幕截圖、介面元素、檔案內容等非文字訊號的理解與對齊能力。
5. **Cross-Platform Coordination（跨平台協調）**：代理能否在瀏覽器、作業系統、本地檔案系統等多個平台間同步狀態、轉移資訊並完成任務。

基於這五項能力，作者手動設計了 400 個雙語真實世界任務（bilingual real-world tasks），涵蓋英文與中文，以測試語言與文化差異對代理行為的影響。所有任務都在配備真實軟體、即時瀏覽器（live browsers）與本地檔案系統的即時 Docker 容器（live Docker containers）中執行，這與 WebArena（自架網站鏡像，self-hosted website mirrors）或 OSWorld（虛擬機器中的快取頁面，cached pages within virtual machines）等沙箱環境（sandboxed environments）形成鮮明對比。

其次，針對動態真實世界環境中缺乏穩定的真實標註（stable ground truth）的問題，UniClawBench 放棄傳統的預錄答案（pre-recorded answers），改為為每個任務設計細粒度逐步完成檢查點。這些檢查點不僅評估最終結果，也評估中間輸出（intermediate outputs）與執行過程中的推理證據。一個隱藏監督代理（hidden supervisor agent）掌握這些隱藏的評分標準（grading criteria），並在每一步判斷代理是否達成該階段要求。這種設計使得評估能夠適應價格變動、網頁內容更新等動態因素，同時仍保持客觀性。

第三，為了在模擬多輪人類回饋（multi-turn human feedback）的同時防止資料污染（data contamination），UniClawBench 提出嚴格的三角色閉環評估架構，作為資訊隔離（information isolation）的防火牆：

- **執行代理（executor agent）**：即被測試的主動式代理，負責與環境互動並產生可見軌跡（visible trajectory）。
- **隱藏監督代理（hidden supervisor agent）**：掌握完整評分標準，私下檢查執行代理的進度，但不與執行代理直接溝通。
- **使用者代理（user agent）**：模擬人類使用者（automated user simulator），僅能觀察執行代理的可見軌跡與來自監督代理的粗略進度訊號，並據此提供自然修正（natural corrections）。

這種設計解決了「若要提供有效回饋，模擬使用者必須知道正確答案；但知道正確答案又可能洩漏評分標準」的兩難。使用者代理只能根據表面行為與進度訊號給出回饋，從而保留人類與代理互動（human-agent interaction）的閉環特性（closed-loop nature），同時避免答案或評分標準外洩。

最後，在實驗設計上，作者進行兩組互補的比較：一是在固定代理框架（OpenClaw）下比較多個最先進模型（state-of-the-art models），以隔離基礎模型能力（base model capabilities）的差異；二是在多個代理框架（OpenClaw、EDICT、Nanobot）下比較代表性模型，以研究代理框架（agent frameworks）的設計如何放大或限制基礎模型能力。這種「模型 × 框架」的聯合分析，是理解真實世界複雜度（real-world complexity）中效能來源的關鍵。

#### 實驗數據解讀

由於提供的節錄未包含具體數值結果，以下從實驗設計邏輯、預期指標與潛在意涵進行解讀。

第一組實驗「跨模型比較」將多個大型語言模型（large language models, LLM）與多模態大型語言模型（multimodal large language models, MLLM）置於相同的 OpenClaw 框架下。這種設計的優點在於控制變因：所有模型使用相同的工具呼叫介面、記憶體管理與規劃流程，因此觀察到的差異主要反映基礎模型能力。預期指標應包括：

- **任務成功率（task success rate）**：整體 400 個任務中完成的比例。
- **細粒度檢查點達成率（checkpoint completion rate）**：每個任務內部各步驟的完成比例，能夠定位代理在哪一階段失敗。
- **各能力維度分數**：按 Skill Usage、Exploration、Long-Context Reasoning、Multimodal Understanding、Cross-Platform Coordination 分別計算成功率，以診斷代理失敗的根本原因（root causes of agent failures）。
- **互動輪數（number of turns）**：衡量閉環評估中代理達成目標所需的回饋次數，反映效率與溝通成本。
- **錯誤模式分佈**：例如工具呼叫錯誤、視覺感知錯誤、長程遺忘、跨平台狀態不一致等。

第二組實驗「跨框架比較」則將代表性模型分別部署於 OpenClaw、EDICT 與 Nanobot。OpenClaw 採用 hub-and-spoke 架構，強調多平台整合與技能管理；Nanobot 強調輕量、可擴展的核心；EDICT 則代表另一種框架設計哲學。透過比較同一模型在不同框架下的表現，可以分離「模型能力」與「框架設計」的貢獻。預期可觀察到的現象包括：

- 若某模型在 OpenClaw 下表現顯著優於 Nanobot，可能代表 OpenClaw 的工具抽象層（tool abstraction）或記憶體機制更適合該類任務。
- 若跨框架的差異在 Cross-Platform Coordination 任務上特別大，則暗示框架的狀態同步與跨平台協調機制是關鍵瓶頸。
- 若 Long-Context Reasoning 任務的表現主要由模型決定、框架影響較小，則說明長上下文能力是基礎模型的原生瓶頸，難以透過框架設計彌補。

整體而言，這兩組實驗的價值不在於單一排行榜，而在於提供「診斷式」分析：透過能力維度與框架維度的交叉拆解，研究者可以判斷失敗是來自視覺感知（visual perception）、長上下文推理、工具使用（tool usage）還是框架的狀態管理。這正是傳統基於情境的任務分類法難以提供的洞見。

#### 與現有研究的比較

相較於現有的代理基準測試（benchmark for AI agents），UniClawBench 在以下幾個維度有明顯區隔與進步：

1. **從沙箱到真實世界**：WebArena 使用自架網站鏡像，OSWorld 使用虛擬機器中的快取頁面，這些環境雖然穩定，但與真實網路服務、即時內容存在差距。UniClawBench 在即時 Docker 容器中執行真實軟體與即時瀏覽器，更能反映真實世界複雜度。

2. **從單輪到閉環**：多數現有基準測試採用單輪評估典範（single-turn evaluation paradigm），忽略人類與代理互動的閉環特性。UniClawBench 透過使用者代理模擬多輪回饋，更接近實際使用情境。

3. **從情境分類到能力導向**：傳統基準測試按應用情境分類，容易將視覺、推理、工具使用等多種能力混在同一類別。UniClawBench 的能力導向設計能更精準地定位代理失敗的根本原因。

4. **資訊隔離機制**：ClawBench、ClawMark 等雖也強調真實環境與動態情境，但較少詳細處理「模擬使用者回饋時如何避免洩漏評分標準」的問題。UniClawBench 的三角色設計是對此問題的系統性回應。

5. **跨框架評估**：多數基準測試僅在單一框架下比較模型。UniClawBench 同時比較 OpenClaw、EDICT、Nanobot，有助於區分基礎模型能力與框架設計的貢獻。

然而，UniClawBench 也存在若干限制：

- **可擴展性**：400 個任務為手動設計，雖然品質較高，但擴展到數千或數萬任務時成本高昂。相較於可自動生成的網頁任務，其規模受限。
- **環境穩定性**：即時 Docker 容器雖比靜態沙箱更真實，但網頁內容、價格、介面變化仍可能導致任務在不同時間執行時結果不一致，增加可重現性挑戰。
- **容器與真實使用者環境的差距**：Docker 容器仍是一種隔離環境，與真實使用者長期使用的個人電腦、帳號狀態、瀏覽器設定仍有距離。
- **使用者代理的擬真度**：自動化使用者模擬器（automated user simulator）能否真實反映人類使用者的回饋風格、耐心程度與錯誤糾正方式，仍有待驗證。
- **語言與文化覆蓋**：目前僅涵蓋英文與中文，對於其他語言與文化情境的泛化性有限。
- **框架選擇**：僅比較三個框架，且均為學術/開源平台，未涵蓋商業級助理系統，可能限制結論的普遍性。

#### 可重現性評估

在可重現性（reproducibility）方面，UniClawBench 採取開源策略，論文指出其基準測試與程式碼已公開於 GitHub（https://github.com/HKU-MMLab/UniClawBench）。這對於後續研究至關重要，因為閉環評估涉及執行代理、隱藏監督代理與使用者代理之間的複雜互動，若無公開程式碼，其他團隊難以複製評估流程。

具體而言，可重現性的優勢包括：

- **任務與檢查點公開**：若 400 個雙語任務及其細粒度逐步完成檢查點完整釋出，研究者可以直接在相同條件下測試新模型。
- **Docker 環境標準化**：使用 Docker 容器可以固定作業系統、軟體版本與相依套件，降低環境差異帶來的變異。
- **評估流程透明**：三角色閉環評估的程式碼若公開，則隱藏監督代理與使用者代理的提示詞（prompts）、進度訊號定義與資訊隔離機制都可被檢視與改進。

但可重現性也面臨挑戰：

- **動態網路內容**：由於任務涉及真實網站，商品價格、頁面結構、API 回應可能隨時間改變，導致相同任務在不同時間執行時結果不同。論文雖以檢查點機制緩解此問題，但完全重現仍困難。
- **模型 API 版本**：實驗使用最先進模型的 API，而這些模型可能持續更新。若論文未記錄確切的模型版本、API 日期與參數設定，後續研究難以完全複製數值結果。
- **未公開模型權重**：部分最先進模型為專有模型，無法取得權重，這意味著其他研究者只能在相同 API 條件下近似重現，而非完全控制模型本身。
- **執行成本與時間**：400 個任務 × 多輪互動 × 多個模型與框架的組合，評估成本可能相當高，對資源較少的團隊構成門檻。

總體而言，UniClawBench 在開源與流程透明方面做得相當扎實，但動態真實世界環境的本質決定了其可重現性無法達到傳統靜態資料集的水準，這是能力導向、真實世界基準測試必須接受的權衡。

#### 未來研究方向

基於 UniClawBench 的設計與限制，未來研究可朝以下方向延伸：

1. **自動化任務與檢查點生成**：目前 400 個任務為手動設計，未來可結合 LLM 與人工驗證，自動生成更大規模、覆蓋更多能力維度的任務與對應檢查點，並確保其動態環境下的穩定性。

2. **擴展能力維度**：除了現有五項基礎能力，可加入持續學習、個人化記憶、多代理協作、安全性與隱私保護、主動打斷與時機判斷等維度，以更完整評估數位同事（digital coworkers）所需的長期能力。

3. **更真實的使用者模擬**：開發基於真實使用者對話資料訓練的使用者代理，模擬不同耐心程度、領域知識與溝通風格的人類，並引入對抗性回饋以測試代理的穩健性。

4. **長期動態環境評估**：借鏡 ClawMark 的多日同事情境，將評估從單次任務延伸到數日甚至數週的持續互動，研究代理如何在後端持續變化的環境中維持效能。

5. **混合真實與可控環境**：為了兼顧真實性與可重現性，可設計部分任務在真實環境執行、部分在可控的模擬環境執行，並建立對應的對照機制。

6. **框架設計的系統性優化**：利用 UniClawBench 的診斷結果，針對長上下文推理設計更好的記憶體壓縮機制，針對跨平台協調設計統一狀態表示，針對探索能力設計更積極的資訊收集策略。

7. **多語言與跨文化擴展**：將雙語任務擴展到更多語言與地區，研究文化差異（例如不同電商平台、行事曆習慣、檔案管理邏輯）對代理能力的影響。

8. **成本與效率分析**：除了成功率，未來可系統性評估代理的執行成本、延遲、API 呼叫次數與能源消耗，推動更實用的主動式代理系統。

9. **開源專用基礎模型**：目前多依賴商業 API，未來可基於 UniClawBench 的訓練與評估數據，訓練專門針對主動式代理的開源大型語言模型，並公開權重以提升研究可及性。

10. **安全與對齊評估**：主動式代理能長期操作使用者工具，潛在風險包括資料外洩、誤操作與權限濫用。未來可在 UniClawBench 中加入安全檢查點，評估代理在面對惡意指令、隱私衝突與權限邊界時的行為。

## 論文問答

**Q1：UniClawBench 主要想解決什麼問題？**
A：UniClawBench 旨在解決現有基準測試難以有效評估主動式代理在動態真實世界環境中表現的問題。隨著大型語言模型與多模態大型語言模型的發展，主動式代理已能操作瀏覽器、終端機等日常工具，但現有評測多停留在沙箱環境或單輪互動，無法反映真實使用情境。因此，本研究提出第一個能力導向的通用基準測試，以系統化衡量代理在真實世界中的核心能力。

**Q2：為什麼現有的基準測試無法有效評估主動式代理？**
A：現有基準測試存在三項結構性限制：首先，它們常依賴自架網站鏡像或虛擬機器中的快取頁面，無法捕捉真實世界的動態複雜度；其次，大多數採用單輪評估典範，忽略了人類與代理之間反覆回饋的閉環特性；最後，它們以應用情境來分類任務，導致視覺感知、長上下文推理與工具使用等不同能力被混在同一類別中，難以辨識代理失敗的根本原因。

**Q3：能力導向的基準測試為何重要？**
A：能力導向的基準測試能將複雜任務拆解為可獨立評估的基礎能力維度，讓研究者清楚知道代理在哪個環節表現不足。這種設計不僅有助於定位基礎模型的弱點，也能揭示不同代理框架設計對效能的影響。唯有精確診斷失敗來源，才能針對性地改進模型與系統架構，推動主動式代理在真實場景中的實用化。

**Q4：UniClawBench 的核心方法是什麼？**
A：UniClawBench 圍繞五項基礎能力維度來設計：技能使用、探索能力、長上下文推理、多模態理解與跨平台協調。研究團隊基於這五項能力手動設計了 400 個中英雙語真實世界任務，並在即時 Docker 容器中執行，配備真實軟體、即時瀏覽器與本地檔案系統。評估時不再使用預錄答案，而是透過細粒度逐步完成檢查點來衡量代理的執行過程。

**Q5：UniClawBench 的關鍵創新有哪些？**
A：其關鍵創新包括能力導向的任務分類、動態環境下的逐步檢查點評估，以及防止資訊洩漏的閉環評估策略。不同於傳統基準測試依賴靜態真實標註，UniClawBench 針對每個任務設計可驗證的中間步驟檢查點，以適應真實世界內容會變動的特性。此外，三角色閉環設計讓使用者代理能根據可見軌跡提供自然回饋，同時避免評分標準外洩給被測代理。

**Q6：UniClawBench 如何同時處理動態真實標註與資訊隔離的挑戰？**
A：為了處理動態環境中缺乏穩定真實標註的問題，UniClawBench 放棄預錄答案，改以細粒度逐步完成檢查點作為評估依據，讓隱藏監督代理能根據中間證據判斷進度。在資訊隔離方面，系統採用執行代理、隱藏監督代理與使用者代理三角色分離的架構，形成資訊防火牆。隱藏監督代理掌握詳細評分標準，而使用者代理只能看到代理的可見執行軌跡與粗略進度訊號，從而模擬真實多輪回饋而不洩漏答案。

**Q7：論文進行了哪些實驗來驗證 UniClawBench 的有效性？**
A：研究團隊進行了兩組實驗：第一組在 OpenClaw 框架下評估多個最先進模型，以隔離基礎模型能力的差異；第二組則將代表性模型分別置於 OpenClaw、EDICT 與 Nanobot 三種代理框架中進行比較，以研究框架設計對任務表現的影響。透過跨模型與跨框架的全面比較，實驗能同時揭示基礎模型能力與代理架構設計如何共同塑造真實世界任務的效能。

A：實驗結果顯示，基礎模型能力與代理框架設計會共同影響代理在不同能力維度上的表現，單純比較模型或框架都不足以完整解釋效能差異。不同模型在技能使用、探索、長上下文推理、多模態理解與跨平台協調等維度上呈現出各自的優劣勢。這些發現強調了在評估主動式代理時，必須同時考慮底層模型能力與上層框架設計的交互作用。

**Q9：論文是否有進行類似消融研究的分析？**
A：雖然文中未明確標示為消融研究，但跨框架評估本身即是一種系統性的對照分析，可視為對框架設計貢獻的拆解。透過固定模型、更換框架，研究者能觀察到不同代理架構如何放大或限制基礎模型的能力。同樣地，固定框架、更換模型則能隔離基礎模型能力的影響，這兩組比較共同構成了對效能來源的細緻剖析。

**Q10：UniClawBench 的任務設計對應哪些實際應用場景？**
A：UniClawBench 的任務涵蓋日常工作的全範疇，包括辦公室文書處理、網頁資訊查詢、檔案系統操作、跨平台資料整合與個人助理任務等。這些任務要求代理同時使用瀏覽器、終端機與本地軟體，並在多個平台之間協調行動。這樣的設計貼近真實使用者會交給數位同事處理的複雜事務，有助於評估代理作為長期個人助理的潛力。

A：產品化時必須重視工具整合的穩定性、多輪人機互動的自然性，以及動態環境下的容錯能力。開發者需要確保代理能正確理解使用者回饋，同時避免因環境變動而產生過時或錯誤的執行結果。此外，隱私保護與安全性也是關鍵，因為主動式代理會長期接觸使用者的檔案、帳號與個人資料。

### 實作前置條件

- **資料與任務設計**  
  需準備中英雙語任務描述，並為每項任務定義細粒度逐步完成檢查點。建議先從五項基礎能力維度（技能使用、探索能力、長上下文推理、多模態理解、跨平台協調）出發，再擴充到真實日常情境。

- **即時執行環境**  
  需部署配備真實軟體、瀏覽器與本地檔案系統的 Docker 容器，並確保容器能存取即時網頁與外部服務，以反映真實世界複雜度。

- **運算資源**  
  除容器運行所需的 CPU／記憶體外，若評估多模態大型語言模型，還需配備足夠 GPU 資源；同時要預留執行多輪互動與重複實驗的時間與成本。

- **代理框架與模型 API**  
  需準備至少一種代理框架（如 OpenClaw、EDICT 或 Nanobot），並取得受測模型的 API 或權重存取權限，以便進行跨模型與跨框架比較。

- **評估管線與三角色實作**  
  需建置執行代理、隱藏監督代理與使用者代理。隱藏監督代理必須掌握評分標準但不能向被測代理洩漏；使用者代理則只能根據可見軌跡與粗略進度訊號產生自然修正。

- **法規與安全準備**  
  因涉及即時網頁、真實帳號與潛在寫入操作，需確認資料隱私、服務條款與內部資安政策，必要時使用隔離帳號與網路限制。

### 實作步驟建議

1. **定義評估目標與能力維度**  
   依產品需求選擇重點能力維度，例如若產品強調跨應用自動化，則優先設計「跨平台協調」與「技能使用」任務。

2. **設計任務與逐步完成檢查點**  
   將每項任務拆解為可觀察的中間步驟，並為每個步驟設定明確證據要求（如網頁截圖、檔案內容、指令輸出），避免僅以最終結果評分。

3. **建置即時 Docker 評估環境**  
   建立標準化容器映像檔，安裝必要軟體與瀏覽器，設定網路與持久化儲存，並確保每次實驗可從乾淨狀態啟動。

4. **實作三角色閉環評估**  
   開發執行代理負責與被測模型互動；隱藏監督代理在背景比對檢查點；使用者代理根據可見軌跡給予多輪人類回饋，並嚴格隔離評分標準。

5. **執行跨模型與跨框架實驗**  
   固定框架變動模型，以比較基礎模型能力；再固定模型變動框架，以分析框架設計影響。記錄每項任務的逐步完成度與失敗位置。

6. **根據失敗根因迭代改進**  
   利用能力導向分類定位瓶頸，例如發現多數失敗集中在「多模態理解」，則優先強化視覺感知或改進截圖解析策略。

7. **建立可重現的評估報告與 CI 管線**  
   將環境設定、任務定義與評分腳本版本化，並整合至持續整合流程，讓每次模型或框架更新都能自動產出對照報告。

### 潛在風險與注意事項

- **動態環境導致真實標註不穩定**  
  真實網頁價格、介面與內容會變動，預錄答案容易過期。應以逐步完成檢查點取代固定答案，並定期維護任務與檢查點。

- **評分資訊洩漏給被測代理**  
  若使用者代理或監督代理不當暴露評分標準，會造成資料污染。必須落實資訊隔離，讓使用者代理僅能看到公開軌跡與粗略進度。

- **執行成本與延遲高昂**  
  多輪互動加上即時網頁操作會顯著增加時間與費用。建議先以抽樣任務進行試驗，再擴大到完整 400 項任務。

- **安全與隱私風險**  
  代理可能在真實環境中誤刪檔案、發送訊息或下單。應使用隔離帳號、限制寫入權限，並在容器層級設定快照與復原機制。

- **過度擬合檢查點**  
  模型可能學會滿足檢查點形式卻未真正完成任務。設計檢查點時應結合語義驗證與多樣化任務變體，降低投機行為。

- **可重現性挑戰**  
  即時網頁與外部服務狀態難以完全複製。建議記錄執行時間戳、容器版本與網路狀態，並對關鍵任務保留截圖與日誌。

  優先關注「適用場景」與「與其他技術的整合建議」，評估 UniClawBench 是否適合作為產品上線前的驗收標準；同時留意執行成本、安全風險與多輪互動體驗，以便規劃資源與風險控管。
