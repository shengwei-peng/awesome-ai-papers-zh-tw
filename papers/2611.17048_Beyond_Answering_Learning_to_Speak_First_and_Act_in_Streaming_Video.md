AURA 2.0 的方法論設計圍繞「從被動回應到主動發起」這一根本性轉變展開，其核心架構建立在 AURA 的串流互動基礎之上，並引入三項關鍵升級與一項記憶機制。

**模型發起對話 (Model-Initiated Conversation, MIC)** 是本文最具突破性的方法論創新。傳統串流影片模型遵循「使用者驅動互動 (user-driven interaction)」範式，僅在使用者提出查詢時才決定何時回應。MIC 則要求模型同時承擔兩項決策：(1) 是否主動發起對話；(2) 該討論什麼主題。這兩項決策的依據來自兩個層面——演進中的視覺串流 (visual stream) 與當前對話上下文 (conversational context)。值得注意的是，MIC 並非簡單的「看到事件就發言」，而是需要避免重複性或不必要的打擾，這體現了對對話品質的精細控制。具體實作上，作者採用了基於聚焦損失 (focal-loss-based) 的監督方式來處理回應控制詞元 (response-control tokens) 的不平衡問題，這是因為「保持沉默」與「發起對話」的樣本比例天然存在嚴重傾斜。

**串流感知工具呼叫 (Stream-Aware Tool Calling, SATC)** 將工具使用從靜態問答場景擴展至串流互動場景。模型能根據當前視覺與對話上下文主動呼叫外部工具，並將返回資訊整合至進行中的互動中。這項設計的關鍵在於「串流感知」——工具呼叫的時機與內容必須與視覺事件同步，而非僅回應文字查詢。

**互動式視覺定位 (Interactive Visual Grounding, IVG)** 實現了雙向的視覺定位能力。在輸入端，使用者可在影片幀上標記物件供模型識別；在輸出端，模型可產生幀對齊 (frame-aligned) 的邊界框 (bounding boxes) 將回應連結至特定物件與區域。這項能力使對話從純文字層面擴展至視覺-語言的雙向參照。

**長程互動記憶 (Long-Horizon Interaction Memory, LHIM)** 解決了串流場景下的上下文連貫性 (contextual continuity) 問題。當視覺觀察移出主動視覺窗口 (active visual window) 後，顯著事件會被摘要為文字描述並納入持續的對話上下文。LHIM 與 AURA 既有的視覺上下文管理機制互補，前者保留窗口外的語意資訊，後者管理窗口內的視覺細節。

- 風險：串流影片可能包含敏感個資，長時間觀察引發隱私疑慮
- 緩解：本地端部署敏感場景；明確告知使用者模型會主動觀察；提供資料保留期限設定

**計算成本與延遲**
- 風險：串流處理與長程記憶導致推論成本高、回應延遲
- 緩解：採用視覺窗口壓縮、事件摘要蒸餾；邊緣-雲端混合部署；快取常見查詢

**回應控制 token 的類別不平衡**
- 風險：「發話」與「沉默」樣本極度不平衡，模型傾向沉默
- 緩解：採用 focal loss 監督回應控制 token；調整採樣策略；加入主動發話的增強樣本

### 與其他技術的整合建議

**與既有 LLM / Chatbot 整合**
可將 AURA 2.0 作為視覺感知前端，串接既有的文字 LLM（如 GPT、Claude）作為推理後端，透過 API 傳遞視覺事件摘要與工具呼叫結果，兼顧視覺能力與既有對話系統的投資。

**與 RAG（檢索增強生成）整合**
SATC 的工具呼叫可擴展為 RAG 檢索：當模型觀察到需要外部知識的事件時，主動檢索知識庫並將結果融入回應。這對於教育、客服、醫療等知識密集場景特別有用。

**與物聯網（IoT）裝置整合**
透過 SATC 呼叫 IoT 控制介面，讓模型不只「說」還能「做」：觀察到燈沒關時呼叫關燈、偵測到瓦斯外洩時呼叫緊急遮斷。這需要設計安全的工具呼叫權限控管。

**與邊緣運算整合**
對於隱私敏感或低延遲需求場景（如家庭照護、車載系統），可將視覺編碼器與輕量版模型部署於邊緣裝置，僅將事件摘要與必要查詢傳送至雲端，兼顧即時性與隱私。

**與多模態輸入擴充**
AURA 2.0 目前以視覺串流為主，可擴展整合音訊串流（環境音、語音）、感測器資料（IMU、GPS），讓「主動發起對話」的觸發條件更豐富多元。

**與評測框架整合**
將 AURA 2.0 的 MIC、SATC、IVG 評估方法整合至企業內部評測體系，建立領域專屬的主動性與工具使用基準，避免僅依賴學術公開基準。
