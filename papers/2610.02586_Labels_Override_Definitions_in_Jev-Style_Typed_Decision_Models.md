# Jev 風格類型化決策模型中標籤凌駕定義

**原文標題：** Labels Override Definitions in Jev-Style Typed Decision Models  
**作者：** Seyedarmin Azizi、Erfan Baghaei Potraghloo、Massoud Pedram  
**發布日期：** 2026-10-01  
**HF 連結：** [https://huggingface.co/papers/2610.02586](https://huggingface.co/papers/2610.02586)

## ⚡ TL;DR

類型化決策模型雖應依選項定義作答，實際上卻常被選項標籤主導，形成選項標籤偏差。
本文提出PolicyBench合成路由測試集與雙呼叫測試，並比較不同選項格式與模型實作。
實驗顯示標籤壓過定義，選項改為A、B準確率提升逾15%，問題根源在提示詞渲染而非決策頭。

## 摘要翻譯

類型化決策模型（typed decision model）會針對一筆輸入回答一個固定問題，並對數個呼叫者定義（caller-defined）的選項（option）各回傳一個機率（probability）。每個選項具有一個簡短標籤（label）與一段書面定義（definition），開發者於其中陳述模型應套用的規則。Jev 為路由（routing）、內容審核（moderation）與分流（triage）引入了此介面（interface），隨後亦出現開放實作（open implementation）；而每當語言模型被當作分類器（classifier）、對標籤字串打分（scoring label strings）時，也會進行相同的操作。我們研究這些可檢視並修補權重（weight）的開放權重（open-weight）類型化決策模型，並探討機率究竟依循定義還是標籤。我們將對標籤的偏好稱為選項標籤偏差（option-label bias）。

橫跨四個開放權重類型化決策模型、三種從 Qwen2.5 骨幹模型（backbone）讀取答案的方式、十一項分類任務（classification task），以及我們提出的 PolicyBench（一項規則僅出現在定義中的合成路由測試集（synthetic routing suite）），結果顯示答案主要取決於標籤。刪除所有定義並未改變準確率（accuracy）（LAYA-TD：0.8559 對比 0.8487），儘管這些定義單獨可達 0.7971；而將選項重新命名為 A 與 B 則使準確率提升 +0.1511 [+0.1377, +0.1646]。VON 系統不受影響，兩個程式碼庫僅在一個表示式上相異：LAYA 將每個選項寫成「{label}: {definition}」，而 VON 只寫入定義。將該表示式在兩個方向上對調，且不更動任何權重，會使三個 LAYA 檢查點（checkpoint）完全保持不變（+0.0000 [+0.0000, +0.0000]），也會在 VON 中製造出相同效應：當標籤與其定義矛盾時，VON 的準確率從 0.8511 降至 0.2281。先前研究將此失效歸因於這些模型用來取代文字解碼器（text decoder）的受限決策頭（constrained decision head）；我們的結果則將問題定位於提示詞渲染（prompt rendering）。我們提出一種雙呼叫測試（two-call test），供實務工作者判斷其模型屬於何種情況，並評估四種緩解方法（mitigation）的實際效益。

### 核心貢獻（3～5點）
- 發現開放權重類型化決策模型普遍存在選項標籤偏差（option-label bias）：模型輸出主要依循標籤（label）而非定義（definition）。
- 定位問題根源於提示詞渲染（prompt rendering），而非受限決策頭（constrained decision head）：LAYA 使用「{label}: {definition}」格式會導致標籤凌駕定義，VON 僅使用定義則不受影響。
- 提出 PolicyBench 合成路由測試集（synthetic routing suite），規則僅出現在定義中，可用於診斷選項標籤偏差。
- 提出雙呼叫測試（two-call test），協助實務工作者判斷模型是否受標籤偏差影響。
- 評估四種緩解方法（mitigation）的實際效益，為實務應用提供參考。

### 適合對象
從事大型語言模型應用、分類系統、路由（routing）／內容審核（moderation）／分流（triage）決策系統開發的研究者與工程師，特別是關注模型可解釋性、提示詞工程（prompt engineering）以及開放權重（open-weight）模型部署的實務工作者。

## 深度分析

#### 方法論解析

本研究的核心問題是：在 Jev-style（Jev 風格）的 typed decision model（類型化決策模型）介面中，模型回傳的機率究竟是對 option definition（選項定義）的後驗（posterior），還是實際上被 option label（選項標籤）所主導。作者將後者稱為 option-label bias（選項標籤偏差）。為了分離這兩條資訊通道，論文設計了一套從觀察、診斷到介入的完整方法論。

首先，在請求層級，typed decision model 的介面要求呼叫者為每個 option（選項）提供 label（標籤）與 definition（定義）。理論上 label 只是事後讀取答案的識別符，definition 才是模型應該依循的規則。作者利用這個結構進行 channel ablation（通道消融）：把 definition 全部刪除只留 label，或把 label 替換成 A、B 等無意義符號只留 definition，從而量化兩者各自的貢獻。這種設計直接檢驗「定義才是決策依據」這一介面隱含承諾。

其次，為了在規則「只」存在於 definition 的場景下進行嚴格評估，作者提出了 PolicyBench，一個 synthetic routing suite（合成路由測試集）。在 PolicyBench 中，每個樣本的正確答案由生成屬性決定，option 的 definition 才承載判斷規則，而 label 被系統性地操控為 aligned label（一致標籤）、arbitrary label（任意標籤）與 misleading label（誤導性標籤）。這讓研究者能夠在控制 definition 明確性（specificity）的 XF（controlled form）條件下，純粹測量 label 對決策的干擾。

第三，作者進行了一項關鍵的雙向介入實驗：在不改變任何 weight（權重）、decision head（決策頭）或 calibration（校正）參數的前提下，只修改 prompt rendering（提示詞渲染）中 option template（選項模板）的寫法。具體來說，LAYA 系列原本使用「{label}: {definition}」的格式，VON 則只寫入 definition；作者把這個表達式在兩個系統間互換，觀察 accuracy（準確率）與分佈變化。這是論文最具說服力的因果論證，因為它把機制定位在「選項字串如何被寫入模型輸入」，而非模型架構本身。

第四，為了讓實務使用者能夠在無法接觸模型內部的情况下自我診斷，作者提出 two-call test（雙呼叫測試）：對同一問題呼叫兩次，僅改變 option label，保留 definition 不變，然後比較兩次回傳的 probability（機率）分佈。若分佈改變，即可判定 label 正在影響決策。這個測試不需要 label、不需要 held-out data（保留資料），也不需要 weight access（權重存取），非常適合部署前的快速稽核。

最後，論文還測量了四種 mitigation（緩解方法）的實際效益，並額外報告了兩個獨立現象：negated yes/no question（否定式是非題）幾乎不被閱讀，以及當 label 與 definition 衝突時，模型的 confidence score（信心分數）會把錯誤答案排在更高位置。這些方法論環環相扣，從現象描述、機制定位到實務診斷與補救，形成一條完整的證據鏈。

#### 實驗數據解讀

實驗結果對「定義導向」這一介面假設提出了強烈質疑。在 PolicyBench 的 XF 條件下，LAYA-TD、LAYA-EN 與 Qwen2.5-7B 的表現都隨著 label 語義化而顯著下降；相對地，VON 在四種 label 條件下幾乎完全平坦，因為它從未把 label 寫入模型輸入。最具衝擊性的數據是 LAYA-EN：當 label 被設為 misleading label 時，準確率跌至 0.5297，幾乎等於 chance level（隨機基準）0.5，這表示模型幾乎完全忽略 definition，只根據 label 名稱做判斷。

在十一項 classification task（分類任務）上的 ablation 結果進一步強化了這個結論。對 LAYA-TD 而言，刪除所有 definition 只保留 label，準確率為 0.8559；保留完整 definition 的原始設定準確率為 0.8487，兩者幾乎相同。這說明 definition 的存在與否並未提升表現，label 已經足以支撐決策。然而，當把 label 換成 A、B 等 arbitrary label 而只保留 definition 時，準確率仍有 0.7971；這顯示 definition 本身確實含有判斷資訊，只是當語義化 label 同時出現時，模型傾向使用更「廉價」的 label 線索。把 option 重新命名為 A、B 可使準確率提升 +0.1511（95% bootstrap interval 為 [+0.1377, +0.1646]），這是一個非常大且穩定的效益，也成為最簡單的緩解手段。

雙向介入實驗則提供了因果層面的決定性證據。當把 LAYA 的 option template 從「{label}: {definition}」改成只寫 definition，三個 LAYA checkpoint（檢查點）對 label 變化變得完全 invariant（不變），變化量為 +0.0000 [+0.0000, +0.0000]。反過來，在 VON 的輸入中加入 label 後，當 label 與 definition 矛盾時，準確率從 0.8511 暴跌至 0.2281。這證明 effect 並非來自 constrained decision head（受限決策頭）或 text decoder（文字解碼器）的差異，而是單純來自 prompt rendering 是否把 label 洩漏給模型。

Qwen2.5-7B 作為一個使用傳統語言模型進行 scoring label strings（對標籤字串打分）的 readout，表現出至少同等強烈的 option-label bias。這直接反駁了 Sun et al. (2026) 把類似現象歸因於 decision head 的說法，因為 Qwen2.5-7B 並沒有這類受限決策頭，仍然出現相同問題。換言之，只要模型在輸入中同時看到 label 與 definition，且 label 具有語義，就可能發生偏差。

另一個值得警惕的發現是 confidence score 的行為。當 label 與 definition 不一致時，模型對錯誤答案的信心反而更高，這意味著實務上無法依賴 confidence threshold（信心閾值）來過濾錯誤。再加上 negated yes/no question 幾乎不被閱讀的獨立失敗，顯示這類介面在語法理解上還存在其他結構性問題，而不僅是 label 干擾。

#### 與現有研究的比較

本研究最直接對話的對象是 Sun et al. (2026)。該研究在 hosted model（託管模型）上觀察到「重新命名 option 會改變答案」的現象，並將其歸因於 typed decision model 用來取代 text decoder 的 constrained decision head。本論文則透過兩條證據推翻這項歸因：第一，Qwen2.5-7B 這類沒有受限決策頭的傳統語言模型，在 scoring option strings 時也出現同樣甚至更强的 effect；第二，透過單純改變 prompt rendering 的 option template，就能在 LAYA 上消除 effect、在 VON 上創造 effect，而無需更動任何 weight 或 decision head。因此，先前研究把問題定位在模型架構頭部是不正確的，真正的問題在於輸入表徵。

Tang & Zheng (2026) 對早期二十八篇相關論文進行稽核，發現只有 5/26 的研究包含來自普通語言模型的 label-probability baseline，只有 1/27 的研究測試過對 option 名稱的 invariance。本論文正好填補了這兩項缺口：它同時提供普通語言模型 readout 作為 baseline，又系統性地測試了 label 變化下的 invariance，並把兩者連結起來解釋 effect 的來源。

相較於過去僅止於「觀察到 renaming 會改變答案」的研究，本論文的貢獻在於建立了一個可操作的因果框架：透過 channel ablation 分離 label 與 definition 的貢獻、透過 PolicyBench 創造規則僅存在於 definition 的評估場景、透過雙向介入定位機制、透過 two-call test 提供部署前診斷、並透過實證測量而非原則推薦來評估 mitigations。這些方法論上的進展使得研究結論不只適用於 dedicated typed decision model，也適用於任何把 language model 當作 classifier（分類器）使用的 pipeline。

不過，本研究也有明確的 scope 限制。作者並未測量 Jev 本身，因為其 internals 仍為封閉；所有關於 mechanism 的結論僅適用於 open-weight（開放權重）的 open implementation。此外，PolicyBench 是 synthetic routing suite，雖然能精確控制生成屬性，但真實世界中的 label-definition 互動可能更複雜；Qwen2.5-7B 的 readout 實驗雖然有力，但僅針對單一 backbone（骨幹模型），未來需要擴展到其他模型家族。最後，論文測量的四種 mitigations 都是「測量其效益」而非「推薦原則」，實務選擇仍需視應用場景而定。

#### 可重現性評估

本研究在可重現性方面具有相當高的優勢。所有受測模型均為 open-weight，包括 LAYA-TD、LAYA-EN、LAYA-ML 與 VON，且論文強調「每一個數字都可以在不使用 vendor API key 的情況下重現」。這消除了許多封閉模型研究面臨的再現障礙。PolicyBench 作為 synthetic routing suite，其樣本與 ground truth 由生成屬性決定，只要釋出生成腳本與評估協定，就能被其他研究者完整複製。

然而，目前提供的上下文並未明確說明作者是否已公開原始碼、PolicyBench 資料集與實驗腳本。從論文敘述來看，所有必要的「原料」——模型權重、輸入格式、option template、評估指標與 bootstrap 95% interval 計算方式——都已具備，因此原則上重現門檻很低。若作者進一步釋出完整程式碼與 PolicyBench 生成流程，則這項研究將達到幾乎完全可重現的水準。

值得注意的是，由於 Jev 本身未被測量，任何想驗證 Jev 是否也存在相同機制的人都無法進行，除非該模型的內部實作未來開放。這是研究在可重現性與外部效度上的一個明確邊界：結論對 open implementation 高度可信，但對封閉商業系統僅具類推意義。

#### 未來研究方向

這篇論文打開了數個值得後續探索的方向。首先，在模型架構與 backbone 方面，應該把相同測試擴展到更多語言模型家族（例如 Llama、Mistral、Gemini 開放版本等），以確認 option-label bias 是否普遍存在，以及不同預訓練語料與 tokenizer 是否會放大或縮小該效應。對於 Jev 或其他封閉系統，未來若能取得內部實作，也可驗證本研究的機制結論是否成立。

其次，在訓練方法上，可以設計專門的 fine-tuning objective（微調目標）來強制模型忽略 label、專注 definition。例如，在訓練時隨機化 option label、使用對比學習讓模型學到「相同 definition 不同 label 應有相同輸出」、或在 loss 中懲罰對 label 的依賴。這類方法若與 PolicyBench 結合，可形成一個標準化的 robustness benchmark（穩健性基準）。

第三，介面標準化層面，未來的 typed decision model API 可以明確規範 prompt rendering 不得把 label 寫入模型輸入，或至少提供一個「definition-only rendering」模式供呼叫者選擇。這類標準若能被主流框架採納，將從源頭減少 option-label bias。

第四，在信心校正與錯誤偵測方面，由於本研究發現 confidence score 在 label-definition 衝突時會反向排序錯誤，未來需要發展更可靠的 uncertainty quantification（不確定性量化）方法，例如針對 option 進行 permutation ensemble（排列集成）或利用 two-call test 作為 runtime monitor（執行期監控）。

第五，可以進一步研究 label 語義與預訓練先驗的交互作用。例如，「billing」這類常見詞可能在預訓練中具有強烈語義先驗，導致模型傾向選擇它，即使 definition 並不支持。透過系統性地操控 label 的常見程度與 definition 的 specificity，可以量化這種先驗的影響。

最後，本研究發現的 negated yes/no question 失敗提示，typed decision model 在語法理解上可能存在更廣泛的盲點。未來可以建立涵蓋否定、比較級、條件句與量化詞的語法 robustness test suite，並與 option-label bias 研究相互參照，以全面提升這類介面的可靠性。

## 論文問答

**Q1：什麼是類型化決策模型，它解決了什麼問題？**
A：類型化決策模型是一種專門用來回答固定問題，並為每個呼叫者定義的選項返回機率分布的神經網路系統，常見於路由、內容審核與分流等應用。與傳統語言模型不同，它不進行自迴歸解碼，而是透過單次前向傳播直接輸出各選項的機率，因此成本與延遲顯著低於 frontier 語言模型。這種介面讓開發者能夠透過選項的定義來陳述決策規則，並用標籤作為後續讀取答案的識別符號。

**Q2：這類介面對「標籤」與「定義」的基本假設是什麼？**
A：這類介面的基本假設是模型返回的機率應該是對選項「定義」的後驗機率，而標籤僅作為識別名稱，不應影響決策。換句話說，開發者將「Enterprise 方案且要求退款時升級」這類規則寫入定義欄位後，模型應根據該規則判斷輸入屬於哪個選項。然而本研究發現，在大多數開放權重實作中，答案實際上主要由標籤決定，定義反而被覆蓋，這種現象稱為選項標籤偏差。

**Q3：為什麼選項標籤偏差在生產系統中特別令人擔憂？**
A：在生產環境中，開發者通常會賦予選項有意義的名稱以便理解與系統整合，例如「billing」或「refund」。當標籤與定義不一致時，模型可能會忽略真正的業務規則而選擇聽起來正確的標籤，導致錯誤的路由或審核決策。更糟的是，模型的信心分數在標籤與定義衝突時會朝錯誤方向排序，使得單純依賴閾值過濾無法有效捕捉這類錯誤。

**Q4：作者如何隔離標籤與定義各自的影響？**
A：作者透過系統性的消融實驗分離標籤與定義兩個通道：他們比較完整輸入、刪除所有定義僅保留標籤，以及刪除所有標籤僅保留定義三種條件。此外，他們還將選項重新命名為 A、B 等任意名稱，觀察準確率的變化。最關鍵的是，他們在兩個獨立訓練的系統之間單向修改選項模板，證明僅改變提示詞渲染方式就能創造或消除此效應。

**Q5：PolicyBench 是什麼，為什麼要設計它？**
A：PolicyBench 是本文提出的合成路由測試集，其設計重點在於讓決策規則只出現在選項定義中，而標籤則被系統性地操控為一致、任意或誤導性三種條件。由於正確答案可從生成屬性計算得出，研究者能夠精確評估模型是否真正遵循定義而非標籤。這個測試集填補了現有評估的缺口，因為真實世界的分類任務往往無法區分模型是依賴標籤還是定義。

**Q6：什麼是雙呼叫測試，它能診斷什麼？**
A：雙呼叫測試是一種簡單的診斷方法：呼叫者用完全相同的問題與定義，只改變選項標籤，然後比較兩次返回的機率分布。如果分布不同，就表示標籤正在影響決策。這個測試不需要標籤、不需要保留資料，也不需要存取模型權重，因此非常適合實務人員在部署前快速檢查模型行為。

**Q7：實驗的主要量化發現是什麼？**
A：主要量化結果顯示，在三個 LAYA 檢查點與 Qwen2.5-7B 的語言模型讀取中，答案主要由標籤決定。具體而言，刪除所有定義後 LAYA-TD 的準確率仍維持 0.8559，與完整輸入的 0.8487 幾乎相同；而將選項重新命名為 A、B 後準確率提升了 +0.1511。相對地，VON 模型完全不受標籤影響，因為它從不將標籤寫入模型輸入。

**Q8：作者如何證明問題出在提示詞渲染而非受限決策頭？**
A：作者透過在兩個獨立系統之間單向修改選項模板來定位問題根源：將 LAYA 的「{label}: {definition}」改為僅寫入定義，三個 LAYA 檢查點都變得完全對標籤不變；反之，將 VON 的模板改為包含標籤後，當標籤與定義矛盾時其準確率從 0.8511 暴跌至 0.2281。由於權重、決策頭與校正都未改變，這證明效應來自提示詞渲染而非受限決策頭。這也與 Sun 等人將此現象歸因於決策頭的說法相矛盾。

**Q9：除了標籤偏差，研究還發現哪些其他失敗模式？**
A：除了選項標籤偏差，研究還發現第二個獨立失敗：否定形式的 yes/no 問題根本沒有被正確閱讀。此外，當標籤與定義衝突導致決策被破壞時，模型的信心分數並未降低，反而會錯誤地對錯誤答案賦予更高信心。這意味著實務上不能依賴信心閾值來偵測或過濾由標籤偏差引起的錯誤。

**Q10：實務使用者應該採取哪些立即行動？**
A：實務使用者應該首先執行雙呼叫測試，確認模型是否會因標籤改變而改變答案。如果發現標籤會影響決策，且真正重要的規則存在於定義中，就應該將選項重新命名為 A、B 等任意名稱，這在 PolicyBench 上可帶來顯著的準確率提升。同時，不應依賴模型的信心分數來捕捉這類錯誤，因為信心分數在錯誤發生時可能反而更高。

**Q11：這項發現對路由、審核與分流產品的設計有何啟示？**
A：對於路由、內容審核與分流等產品設計，這項發現意味著介面呈現方式會直接決定模型是否遵循業務規則。產品團隊應該審查選項模板，確保標籤不會被寫入模型輸入，或者至少提供讓使用者僅傳入定義的選項。此外，評估流程中應該納入標籤不變性測試，作為上線前的標準檢查項目。

**Q12：這對使用語言模型作為分類器、對標籤字串打分的做法有何意義？**
A：這項發現同樣適用於將語言模型當作分類器、透過對標籤字串打分來取得答案的常見做法。由於 Qwen2.5-7B 在相同選項字串上表現出至少同樣強烈的標籤效應，這表示問題不限於專用的類型化決策模型，而是廣泛存在於以標籤為基礎的分類介面中。因此，任何使用語言模型進行分類的系統都應該檢視其提示詞中標籤與定義的相對權重。

**Q13：本研究有哪些主要限制？**
A：本研究的主要限制在於未測量 Jev 本身，因為其內部機制封閉，而本文的機制主張僅適用於開放權重系統。此外，雖然實驗涵蓋十一個分類任務與 PolicyBench，但真實世界應用的多樣性可能還會揭示其他未觀察到的失效模式。研究也主要基於 Qwen2.5 骨幹與 LAYA、VON 兩個程式碼庫，其他架構或訓練方法可能需要進一步驗證。

**Q14：未來研究可以朝哪些方向延伸？**
A：未來研究可以朝幾個方向延伸：首先，發展能夠自動偵測並修正提示詞渲染問題的工具或訓練目標；其次，探討如何在保留標籤可讀性的同時，透過模型架構或微調讓模型真正學會遵循定義；最後，可以將雙呼叫測試與標籤不變性檢查標準化，納入類型化決策模型與語言模型分類器的評估基準中。

**Q15：這項研究對模型評估審計有什麼更廣泛的影響？**
A：這項研究對模型評估審計有深遠影響：作者回顧前二十八篇相關論文時發現，僅有 5/26 包含普通語言模型的標籤機率基線，僅有 1/27 測試選項名稱的不變性。這顯示社群長期忽視了一個關鍵的效度威脅，因為沒有不變性測試就看不見效應，沒有基線就無法歸因。未來的評估框架應該將這兩項檢查列為基本要求，特別是在高風險的決策應用中。

## 實務應用指南

### 適用場景

1. **客服單自動路由**  
   將客戶來信或對話內容分派到 billing、technical_support、legal 等部門。每個部門選項附上定義（如「invoices, payments and refunds」），由模型直接回傳機率。

2. **合約條款風險分類**  
   判斷合約條款是否屬於不公平條款、競業禁止、資料使用條款等，開發者把判斷規則寫在選項定義中，標籤僅作為輸出識別。

3. **內容審核與分流（moderation / triage）**  
   對貼文、評論或商品資訊進行多類別審核，例如 spam、harassment、misinformation，每個類別以定義描述實際判定標準。

4. **醫療或緊急事件分級**  
   根據病患主訴或事件描述，分配到不同處置等級，定義中載明分流規則，標籤僅供後續系統讀取。

5. **文件歸檔與標籤輔助**  
   將電子郵件、發票或支援文件自動歸入預設類別，規則寫在定義欄位，讓業務人員可透過修改定義調整模型行為。

---

### 實作前置條件

- **資料準備**  
  需有一份代表性的輸入樣本（state），以及每個問題的選項標籤與定義。建議同時準備「標籤與定義一致」、「標籤為 A/B」、「標籤與定義相反」三種版本，以便執行雙呼叫測試。

- **模型與權重**  
  本研究使用開放權重模型（LAYA-TD、LAYA-EN、LAYA-ML、VON）與 Qwen2.5-7B 作為對照。若使用封閉式 API（如 Jev），可執行雙呼叫測試，但無法驗證提示詞渲染機制。

- **運算資源**  
  類型化決策模型只需單次前向傳播（one forward pass），7B 等級模型可在單張消費級 GPU 或雲端執行個體上運行；若僅做語言模型分類器對照實驗，則需能對標籤字串打分。

- **技能需求**  
  熟悉 Python、能修改提示詞模板（option template）與選項格式（option format）、會計算準確率與自助法 95% 信賴區間。若要做機制驗證，需能檢視或覆寫模型輸入渲染程式碼。

---

### 實作步驟建議

1. **建立選項定義為唯一規則來源**  
   把真正要模型遵循的規則寫進每個選項的 definition 欄位，label 欄位先用 A、B、C 等無意義名稱，避免標籤本身洩漏答案。

2. **執行雙呼叫測試（two-call test）**  
   對同一筆輸入發送兩次請求，僅改變選項標籤（例如 A/B 改為 billing/refund），比較兩次回傳的機率分布。若分布改變，表示模型存在選項標籤偏差（option-label bias）。

3. **根據測試結果調整提示詞渲染**  
   - 若發現標籤會影響結果，檢查選項在模型輸入中的格式是否為「{label}: {definition}」。  
   - 若可修改程式碼，將格式改為僅輸入定義（definition-only），即可消除標籤偏差。  
   - 若無法修改程式碼，則在生產環境中持續使用 A、B、C 等標籤，並在後處理階段映射回真實名稱。

4. **在 PolicyBench 或自製合成測試集上驗證**  
   建立規則只出現在定義中的測試案例，並比較 aligned、arbitrary、misleading 三種標籤條件下的準確率，確認模型是否確實依定義決策。

5. **部署與監控**  
   上線後持續抽樣檢查：當標籤與定義衝突時，模型置信分數（confidence score）並不可靠，因此不要單獨以置信閾值作為錯誤偵測機制，應搭配人工抽檢與業務指標監控。

---

### 潛在風險與注意事項

- **標籤偏差導致規則失效**  
  若選項格式為「{label}: {definition}」，模型可能忽略定義、直接依標籤作答。研究顯示，將標籤改為 A/B 可提升準確率 +0.1511，而誤導性標籤會讓 LAYA-EN 準確率跌至接近隨機基準。

- **置信分數方向錯誤**  
  當標籤與定義矛盾時，模型對錯誤答案的置信分數可能高於正確答案，因此不應以 confidence threshold 作為品質閘門。

- **刪除定義並不會降低表現**  
  在某些系統中，移除所有定義後準確率幾乎不變（laya-td：0.8559 vs. 0.8487），這表示模型並未真正使用定義，必須透過雙呼叫測試主動檢查。

- **不同程式碼庫行為不同**  
  LAYA 與 VON 的差異僅在於一行程式碼：是否把 label 寫進輸入。因此不要假設所有類型化決策模型行為一致，每次引入新模型都應重新測試。

- **緩解方法需實測**  
  論文測量了四種緩解方法，但沒有單一萬靈丹。建議在自身資料上實測，再決定採用哪一種。

---

### 與其他技術的整合建議

- **與 LLM 管線整合**  
  類型化決策模型可取代「提示語言模型對固定標籤字串打分」的分類器節點，降低延遲與成本；但上線前應用同一組標籤字串在骨幹語言模型（如 Qwen2.5-7B）上跑基線，確認偏差來源。

- **與規則引擎搭配**  
  對於高風險決策，可將模型輸出視為初步分類，再經由規則引擎覆寫關鍵案例；特別是當標籤與定義可能衝突時，規則引擎可作為最後防線。

- **與監控與可觀測性工具整合**  
  紀錄每次請求的選項格式、標籤與定義內容，並在儀表板上追蹤「標籤交換後機率變化」的指標，作為線上漂移偵測的一部分。

- **與後處理映射層整合**  
  在資料庫或 API 回應中，將 A、B、C 等內部標籤映射回業務名稱，讓前端與下游系統仍看到有意義的部門或類別名稱。

---

### 給不同背景讀者的閱讀建議

- **初學者**  
  先理解「標籤」與「定義」的區別：標籤只是選項名稱，定義才是規則。重點看「雙呼叫測試」與「把標籤改成 A/B」這兩個實務建議，就能避免最常見的錯誤。

- **AI 工程師**  
  請聚焦 §5.5 的單行程式碼干預與 §6 的四種緩解方法。你應該能重現「改變 option template 即可消除或製造標籤偏差」的實驗，並把結論轉成上線前的自動化測試。

- **研究人員**  
  建議細讀 §2.3 的類型化決策模型與語言模型分類器之間的對應關係、§5.3 對受限決策頭（constrained decision head）假說的反證，以及 §5.7 的否定疑問句獨立失效現象，這些都是後續機制研究的切入點。

- **產品經理**  
  重點看圖 1 與「What to do about it」段落：這個問題會直接影響產品準確率與使用者信任。請把「雙呼叫測試」納入上線清單，並與工程團隊確認選項格式是否把標籤寫進了模型輸入。
