自主研究代理在有限預算下，檢索到的相關來源常未被有效運用。

## 摘要翻譯

自主研究代理（autonomous agents）必須在有限的研究預算（research budget）內獲取並對證據進行推理。然而，相關來源可能仍未被檢視或使用，導致檢索覆蓋率（retrieval coverage）與用於指導研究的證據之間存在落差。核心挑戰在於將快速局部判斷（local judgments）與不斷變化的證據需求對齊，並將其發現回饋至研究決策（research decisions）中。我們提出 JevGPT，一種用於自主研究（autonomous research）的雙系統架構（dual-system architecture），將快速證據處理（fast evidence processing）與審慎研究規劃（deliberative research planning）結合。系統二（System Two）設定證據目標（evidence objective）並整合發現，而系統一（System One）則定位支援文件（supporting documents）、評估相關性，並引導進一步的來源檢視（source inspection）。獨立的來源判斷（source judgment）平行執行；選定的原始段落引導下一步研究。在固定語料庫問答（fixed-corpus question answering）與文件排序（document ranking）上的實驗顯示，JevGPT 達到領先的任務效能，且比效能相當的研究代理完成速度更快、成本更低。證據分析顯示在研究迴圈（research loop）中進行更廣泛的來源檢視與更高的支援文件覆蓋率，凸顯高效證據處理是邁向更具能力的自主研究的途徑。

### 核心貢獻（3～5點）
- 提出 JevGPT 雙系統架構，將系統二的審慎研究規劃與系統一（快速判斷模型 Jev）的快速證據處理相結合，實現高效的自主研究。
- 透過獨立的來源判斷平行執行與原始段落的回饋機制，縮小檢索覆蓋率與實際用於指導研究的證據之間的落差。
- 在固定語料庫問答與文件排序兩項任務上，JevGPT 以更快的完成速度與更低的 API 成本達到領先的任務效能。
- 證據分析顯示 JevGPT 在研究迴圈中實現更廣泛的來源檢視與更高的支援文件覆蓋率，凸顯快速證據處理作為提升自主研究能力之關鍵途徑。

### 適合對象
從事資訊檢索、問答系統、語言模型代理（LLM agents）與自主研究系統研究的學者與工程師；對雙系統認知架構（如 Kahneman 的快思慢想）應用於 AI 系統感興趣的研究者；以及關注如何以有限預算提升代理式搜尋（agentic search）效率與成本效益的實務工作者。

## 深度分析

#### 方法論解析

JevGPT 的核心設計靈感來自 Kahneman (2011) 提出的雙重歷程理論 (dual-process theory)，將自主研究代理 (autonomous research agent) 的認知過程劃分為兩個互補的子系統，並透過明確的職責分工與資訊流耦合來解決「檢索覆蓋率 (retrieval coverage) 與證據使用 (evidence use) 之間的落差」這一核心問題。

**系統二 (System Two) 的角色與職責**

系統二作為審慎研究規劃 (deliberative research planning) 模組，承擔三項關鍵功能：(1) 設定證據目標 (evidence objective)，即根據當前研究狀態定義需要獲取的證據類型；(2) 委派任務給系統一；(3) 整合系統一回傳的發現以形成下一步研究行動。在形式化表述中，系統二是一個生成式策略 G，於步驟 t 根據歷史 h_t 產生動作 a_t ∈ {搜尋查詢、證據請求、最終答案或排序}。此設計的關鍵洞見在於：研究規劃需要累積的全域調查資訊，而來源判斷 (source judgment) 則可被限定在明確的證據目標範圍內——這種資訊範圍的不對稱性是雙系統分工得以成立的理論基礎。

**系統一 (System One) 的角色與職責**

系統一採用 Almeida (2026) 提出的 Jev 模型作為快速判斷模型 (fast judgment model)，負責三類任務特定的讀取器 (task-specific readers)：

1. **證據定位 (Evidence Localization)**：針對問答任務，根據系統二給定的局部問題，從候選文件中定位相關段落 (passage localization)。
2. **相關性評估 (Relevance Assessment)**：針對排序任務，根據原始主題評估候選文件的相關性分數，並選擇段落以指導下一批閱讀。
3. **證據探索 (Evidence Discovery)**：根據原始任務背景，主動評估潛在的研究線索 (research leads)，並異步收集段落以擴展證據基礎。

這三個讀取器的並行執行 (parallel execution) 是 JevGPT 效率優勢的關鍵來源——獨立判斷可在同一證據目標下同時運行，無需等待彼此結果。

**資訊流與回饋機制**

如 Figure 3 所示，JevGPT 的資訊流呈現一個雙向耦合結構：系統二發出的證據請求傳遞給系統一的三類讀取器；讀取器返回經過選擇的原始段落 (selected original passages) 與局部判斷結果；系統二整合這些發現後產生下一個研究動作。虛線迴圈 (dashed loops) 表示適應性閱讀機制——當局部判斷顯示需要更多上下文時，讀取器可擴展閱讀範圍；虛線探索分支 (dashed discovery branch) 則以異步方式供應額外的研究線索，使系統能在不阻塞主迴圈的情況下擴展證據池。

此架構相較於既有方法（如 Pi-Serini 將檢索、瀏覽、文件閱讀分離；RISE 暴露有界文件工作區）的根本差異在於：JevGPT 不僅分離處理與推理，更透過「證據目標」這個明確介面將局部決策連接到全域研究決策，使快速判斷能夠動態引導證據獲取 (evidence acquisition) 的方向。

#### 實驗數據解讀

**BrowseComp-Plus 問答任務**

Figure 2(a) 顯示在 BrowseComp-Plus 基準上，JevGPT（以星號標記）在準確率 (Accuracy) 與 API 成本 (API cost per question, USD) 的二維空間中佔據左上角位置，即在最低成本區間達到最高準確率。具體而言，JevGPT 的 API 成本約在 0.5–1.0 USD 區間，準確率達到約 86–90%，明顯優於 Reason-ColBERT、AtlasNav、Agentica、Pi-Serini、BCP/ReAct 與 RISE 等基線方法。值得注意的是，Pi-Serini 與 BCP/ReAct 雖在成本上接近 JevGPT，但準確率較低；而 AtlasNav 與 Agentica 雖準確率較高，卻伴隨顯著更高的 API 成本（2–3 USD）。

**NeuCLIRBench 文件排序任務**

Figure 2(b) 顯示在 NeuCLIRBench 上，JevGPT 同樣在 nDCG@20 與 API 成本 (API cost per topic, USD) 的權衡中表現優異，nDCG@20 約達 52–54，成本約 0.6–0.8 USD。相較於 RankGPT、Agentica、BCP/ReAct 與 Pi-Serini，JevGPT 在排序品質與成本效益上均具優勢。此面板僅展示基於 GPT 的方法，排除了 Reason-ColBERT 等非 GPT 基線。

**結果的實質意涵**

這些數據揭示三個關鍵發現：(1) JevGPT 不僅在品質上領先，更在成本效率上具有顯著優勢——這對實際部署至關重要，因為自主研究代理的經濟可行性直接取決於每次查詢的 API 開銷；(2) 雙系統架構並未因引入額外的判斷模型而增加成本，反而透過並行化與目標導向的處理降低了整體開銷；(3) 證據分析（evidence analysis）顯示 JevGPT 實現了更廣泛的來源檢視 (broader source inspection) 與更高的支援文件覆蓋率 (greater coverage of supporting documents)，驗證了「高效證據處理 (efficient evidence processing) 是更強大自主研究之路徑」這一核心論點。

**消融研究 (ablation study) 的意涵**

論文提及進行了消融研究以檢驗各元件對任務效能的影響。雖然具體數字未在提供的文本中呈現，但此設計表明作者試圖釐清：(a) 系統二的規劃能力貢獻；(b) 系統一三類讀取器的個別效用；(c) 並行化機制對效率的影響。這對於理解架構中哪些設計決策真正關鍵至關重要。

#### 與現有研究的比較

**相較於代理式搜尋 (agentic search) 先驅**

JevGPT 與 ReAct (Yao et al., 2023)、IRCoT (Trivedi et al., 2023)、Search-R1 (Jin et al., 2025) 的根本差異在於：後三者將推理與資訊存取交錯進行，但未明確分離「全域規劃」與「局部判斷」的不同資訊需求。WriteHERE (Xiong et al., 2025) 雖在遞迴規劃與執行間交錯，但同樣缺乏明確的雙系統分工。JevGPT 透過證據目標這個介面，使快速判斷能夠在受限範圍內高效運行，同時保持與全域研究決策的連結。

**相較於固定語料庫研究系統**

在固定語料庫設定下，BCP/ReAct (Chen et al., 2026) 提供工具迴圈但缺乏專門的證據處理機制；Pi-Serini (Hsu et al., 2026) 雖分離檢索、瀏覽與閱讀，但未將局部判斷回饋至研究決策；RISE (Zhuang et al., 2026) 透過有界工作區管理上下文，但同樣缺乏目標導向的證據獲取；AtlasNav (Guo et al., 2026) 提供持久語料庫導航，但未明確分離快速判斷與審慎規劃。JevGPT 的獨特貢獻在於：將「證據目標」作為系統二與系統一之間的明確契約，使局部判斷能夠動態適應變化的證據需求。

**相較於雙系統推理架構**

SwiftSage (Lin et al., 2023) 結合快速動作模型與 LLM 規劃器，但聚焦於對話任務；MARS (Chen et al., 2025) 聯合優化資訊處理與研究推理，但未明確分離兩個系統的職責；Jev-Mem (Jiang et al., 2026) 將快速判斷用於記憶控制；Mnemon (Wang, 2026) 結合 LLM 搜尋規劃與 Jev 對原始對話記錄的判斷。JevGPT 將此分工專門化於語料庫研究：系統二設定證據目標，系統一透過有界判斷引導來源選擇與閱讀。

**限制與未解問題**

儘管 JevGPT 表現優異，仍存在若干限制：(1) 雙系統介面（證據目標）的設計需要領域知識，未來可能需要自動化目標生成機制；(2) 並行化雖提升效率，但對 API 速率限制 (rate limit) 的影響未在文本中明確討論；(3) 實驗僅限於固定語料庫設定，在開放網路搜尋 (open-web search) 場景下的泛化性有待驗證；(4) 系統二作為生成式策略的決策品質上限，可能受制於底層 LLM 的推理能力。

#### 可重現性評估

**資料集可及性**

兩個評估基準 BrowseComp-Plus (Chen et al., 2026) 與 NeuCLIRBench (Lawrie et al., 2025) 均為公開基準，可供研究者重現實驗。然而，基準的具體版本、預處理流程與評估腳本的細節需參考原始論文。

**程式碼與模型權重**

根據提供的文本，JevGPT 的開源狀態未明確聲明。系統一所使用的 Jev 模型由 Almeida (2026) 提出，其獨立可及性需查證該論文。系統二的底層 LLM（從 Figure 2 推斷為 GPT 系列）為閉源商業模型，僅能透過 API 存取，這對完全重現實驗構成限制——API 成本、速率限制與模型版本更新均可能影響結果的可重現性。

**超參數與設定**

文本未提供詳細的超參數設定（如並行讀取器數量、證據目標的具體格式、適應性閱讀的觸發條件等），這些對於精確重現至關重要。此外，BM25 檢索的參數、證據段落的最大長度、讀取器的批次大小等實作細節亦需從附錄或程式碼倉庫獲取。

**重現建議**

欲重現此研究的團隊應：(1) 確認 Jev 模型的授權與可及性；(2) 取得 BrowseComp-Plus 與 NeuCLIRBench 的官方評估腳本；(3) 記錄所使用的 GPT 模型版本與 API 設定；(4) 實作並驗證三類讀取器的介面契約；(5) 進行多次運行以估計結果的變異性。

#### 未來研究方向

**動態預算分配機制**

當前 JevGPT 在固定預算下表現優異，但未明確討論預算分配的動態調整策略。未來研究可探索：(1) 根據問題難度自適應分配檢索深度 (retrieval depth) 與閱讀時間；(2) 在證據目標間動態切換資源優先級；(3) 引入早期停止機制以避免過度探索低收益線索。

**多模態證據整合**

當前架構主要處理文本證據。擴展至多模態場景（如圖表、表格、程式碼）需要：(1) 重新設計證據目標的表示方式以容納異質資料型態；(2) 為不同模態開發專門的讀取器；(3) 研究跨模態證據的整合與衝突解決機制。

**證據目標的自動化生成**

目前證據目標由系統二手動設定，未來可探索：(1) 從問題自動推導初始證據目標；(2) 根據中間發現動態精化目標；(3) 學習跨任務的目標模板以提升遷移能力。

**與人類研究者的協作介面**

將 JevGPT 擴展為人機協作系統，使人類研究者能：(1) 注入領域知識以引導證據目標；(2) 即時介入關鍵決策點；(3) 審閱與修正系統二的規劃。這對於高風險領域（如醫學、法律）的應用至關重要。

**理論分析與形式化保證**

當前實驗結果雖具說服力，但缺乏對雙系統架構效率優勢的理論分析。未來可：(1) 形式化證明並行化在何種條件下優於序列處理；(2) 分析證據目標的資訊理論下界；(3) 研究系統失敗模式與恢復機制。

**跨語言與跨領域泛化**

實驗僅涵蓋英語基準與特定領域，未來應驗證：(1) 在低資源語言上的效能；(2) 在科學、法律、醫學等專業領域的適應性；(3) 跨語料庫遷移的可行性。

**長期研究代理的記憶機制**

當前 JevGPT 處理單一查詢，未考慮跨查詢的經驗累積。整合 Jev-Mem (Jiang et al., 2026) 等記憶機制，使代理能從過去研究中學習策略，將是邁向更通用自主研究系統的重要一步。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於自主研究代理（autonomous research agents）在有限預算下進行證據獲取與推理時，所面臨的「檢索覆蓋率」與「證據使用」之間的落差問題。雖然相關來源可能被檢索到，但未必會被實際檢視或用於後續的研究決策，導致代理無法有效整合證據來支援推理。作者指出，問題的根源在於「快速的局部判斷」與「不斷演變的證據需求」之間缺乏協調機制，使得研究規劃與來源評估脫節。

**Q2：為什麼現有的自主研究方法無法有效解決這個問題？**
A：現有方法如 ReAct、IRCoT、Search-R1、WriteHERE 等雖然能將推理與外部資訊存取交錯進行，但通常將文件處理與研究推理分離，導致快速的局部判斷無法引導整個研究過程中的證據獲取。此外，雖然增加檢索深度可以改善候選召回率，但預覽召回率飽和後，相關來源仍可能未被實際使用。這意味著僅僅擴大檢索範圍並不足以提升研究品質，必須讓局部判斷能動態地回饋到研究決策中。

**Q3：為什麼這個問題對自主研究領域很重要？**
A：自主研究代理的能力高度受限於其如何在有限預算內分配資源，因為每次搜尋都會暴露需要檢視的候選來源，而評估這些來源所花費的時間會直接影響代理能追蹤的線索數量與蒐集的支援證據量。若證據處理效率低落，即使檢索到大量相關來源，代理也無法有效利用，從而限制了更深入、更全面的研究。因此，提升證據處理效率是擴展可用證據、支援更強大自主研究的關鍵途徑。

**Q4：JevGPT 的核心方法是什麼？**
A：JevGPT 採用雙系統架構（dual-system architecture），將研究規劃與證據處理明確分工。系統二（System Two）作為審慎的研究規劃者，負責設定證據目標、整合發現並決定下一步研究方向；系統一（System One）則以 Jev 快速判斷模型為核心，負責來源選擇、段落定位（passage localization）、相關性評估（relevance assessment）以及持續閱讀（continued reading）的引導。系統二發出具體的證據請求，系統一在該目標下進行獨立的平行判斷，並將選定的原始段落回傳給系統二，以銜接局部決策與後續研究行動。

**Q5：JevGPT 的關鍵創新是什麼？**
A：JevGPT 的關鍵創新在於觀察到「研究規劃」與「局部證據判斷」需要不同範疇的資訊——前者仰賴累積的調查脈絡，後者則可被明確的證據目標所限定。基於此洞見，作者設計了讓獨立判斷在該目標下平行運行的機制，並讓其發現回饋到研究流程中以指導下一個目標。這種設計使得代理能在預算內檢視更多來源，同時適應不斷變化的證據需求，因為部分發現可以即時重新導向搜尋或閱讀方向。

**Q6：雙系統架構中有哪些重要的設計選擇？**
A：在架構設計上，JevGPT 選擇讓系統二發出具體的證據請求（如 QA 任務的局部問題或排序任務的原始主題），而非籠統的指令，使系統一能針對性地進行判斷。系統一包含三類任務特定的讀者：證據定位、相關性評估與證據探索（evidence discovery），其中證據探索分支以非同步方式提供額外的研究線索。此外，虛線迴圈允許根據初步結果調整閱讀範圍（擴展或取得上下文），體現了對動態證據需求的適應能力。

**Q7：論文中使用了哪些基準測試來評估 JevGPT？**
A：論文中使用了兩個基準測試：BrowseComp-Plus 用於固定語料庫問答（fixed-corpus question answering），而 NeuCLIRBench 則用於文件排序（document ranking）。前者評估代理在固定語料庫中回答問題的準確率（Accuracy），後者則以 nDCG@20 衡量排序品質。這兩個基準涵蓋了自主研究的兩大典型任務，使評估結果具有代表性。

**Q8：JevGPT 的主要實驗結果為何？**
A：實驗結果顯示，JevGPT 在兩個基準上都達到領先的任務表現，同時具有更快的完成速度與更低的 API 成本。從圖 2 的品質與成本散佈圖可見，JevGPT 在 BrowseComp-Plus 上以較低的每題 API 成本達到約 86% 的準確率，並在 NeuCLIRBench 上以較低的每主題成本取得最高的 nDCG@20。這意味著 JevGPT 不僅在效能上優於 Reason-ColBERT、AtlasNav、Agentica、Pi-Serini、BCP/ReAct、RISE、RankGPT 等基準方法，還在效率上具有明顯優勢。

**Q9：消融研究（ablation study）揭示了哪些架構特性？**
A：消融研究探討了 JevGPT 各元件如何將檢索到的來源轉化為有用的證據，以及這些元件如何影響任務效能。證據分析顯示，JevGPT 在研究迴圈中檢視了更廣泛的來源，並對支援文件具有更高的覆蓋率，凸顯了快速證據處理作為更強大自主研究途徑的價值。這些結果支持了雙系統分工的設計理念：系統二的規劃與系統一的快速判斷共同促成更全面的證據蒐集與利用。

**Q10：JevGPT 可以應用於哪些實際場景？**
A：JevGPT 可應用於需要從大量文件中蒐集並整合證據的場景，例如企業內部知識庫問答、法律案件研究、學術文獻回顧、醫學證據綜述以及新聞調查報導等。在這些場景中，使用者通常需要在有限時間內從固定語料庫中找到最相關的證據，而 JevGPT 的高效率與高品質使其特別適合需要快速產出可靠答案或排序的應用。

**Q11：從產品化的角度，JevGPT 的設計帶來哪些考量？**
A：從產品角度來看，JevGPT 的雙系統架構意味著需要同時部署兩個模型，這增加了系統複雜度與維運成本，但透過平行化處理與任務分工，可在整體上降低每次查詢的 API 成本並縮短回應時間。產品設計時應考慮如何向使用者透明化呈現證據來源與推理過程，以增強可信度。此外，由於系統一使用快速判斷模型，產品需評估其在不同領域的判斷品質，並考慮是否需要領域微調。

**Q12：JevGPT 對自主研究領域的更廣泛影響是什麼？**
A：JevGPT 將雙系統推理（dual-system reasoning）的概念從心理學與認知科學引入自主研究代理的設計，展示了快速判斷與審慎規劃分工的威力。這種架構可能啟發後續研究探索更細緻的任務分工，例如將證據探索、來源評估與整合寫入分別交由不同模組負責。同時，JevGPT 強調「證據使用」而非僅「檢索覆蓋」的觀點，將促使研究者重新思考如何衡量自主代理的真實能力。

**Q13：JevGPT 有哪些已承認的限制？**
A：雖然論文中未明確列出所有限制，但從方法描述可推知，JevGPT 的效能依賴於系統二（基於大型語言模型）與系統一（Jev 快速判斷模型）兩者的協調品質，若任一元件失效都可能影響整體表現。此外，雙系統架構增加了實作複雜度，且其平行化設計需要相應的基礎設施支援。論文的實驗僅在固定語料庫的 QA 與排序任務上進行，對開放式網路搜尋或多模態證據的適用性仍有待驗證。

**Q14：JevGPT 可能會在哪些情況下失敗？**
A：JevGPT 可能會在以下情況下表現不佳：當證據目標設定不精確時，系統一的快速判斷可能偏離真正需求；當語料庫中相關證據極為稀少或分散時，平行判斷的效率優勢可能無法彌補證據本身的不足；當任務需要跨文件推理或長鏈邏輯時，僅靠原始段落回傳可能不足以支援系統二進行整合。此外，若系統二的規劃陷入重複或無效的搜尋循環，雙系統架構也無法自動跳出。

**Q15：未來的研究方向有哪些？**
A：未來研究可朝幾個方向延伸：將 JevGPT 從固定語料庫擴展到開放式網路搜尋與多模態證據（如圖片、表格）；探索更細粒度的任務分工，例如將證據探索、衝突偵測與可信度評估交由專門模組負責；研究如何讓雙系統在更複雜的多步推理任務中保持協調；以及將此架構應用於其他需要高效證據處理的領域，如科學綜述生成或自動化事實查核。此外，如何讓系統二的規劃更具可解釋性與可監督性，也是值得探索的方向。

### 實作前置條件

**資料面**
- **固定語料庫**：需事先準備好欲研究的文件集合（QA 任務）或候選文件池（排序任務），文件需經過解析（PDF、HTML、純文字）並建立 BM25 索引。
- **段落切分**：文件需切分為可定位的段落（passage），以便系統一能精確回傳原文片段。
- **評估資料集**：建議準備 BrowseComp-Plus、NeuCLIRBench 等公開基準，或自建領域內的問答對與排序標註，用於離線驗證。

**運算資源**
- **大型語言模型 API**：系統二需使用具備規劃與整合能力的中大型 LLM（如 GPT 系列），作為審慎推理的核心。
- **快速判斷模型**：系統一採用 Jev 等輕量判斷模型，可於單一 GPU（如 A100／H100）部署，或透過低延遲 API 呼叫。
- **檢索基礎設施**：BM25 檢索器（如 Pyserini）與候選文件儲存空間；語料庫規模若達數百萬文件，需配置足夠的記憶體與磁碟。

**技能門檻**
- **LLM 代理開發經驗**：熟悉 ReAct、IRCoT 等代理框架，能設計系統二的動作空間（搜尋、證據請求、整合、最終答案）。
- **檢索系統操作**：理解 BM25、稠密檢索與重排序流程，能將檢索結果串接至代理迴圈。
- **分散式／並行處理**：因系統一的判斷以並行方式執行，需具備任務排程與批次處理能力。
- **領域知識**：若應用於法律、醫學等專業領域，需具備該領域的證據評估標準，以設定合適的證據目標。

### 實作步驟建議

**步驟一：界定任務與語料庫範圍**
明確目標任務為「問答」或「文件排序」，並選定固定語料庫。QA 任務需準備問題集與標準答案；排序任務需準備主題與相關性標註。建議先以公開基準（BrowseComp-Plus、NeuCLIRBench）建立效能基線。

**步驟二：建立檢索基礎設施**
使用 Pyserini 或類似工具建立 BM25 索引，並實作候選文件擷取 API。針對 QA 任務，設計「文件＋段落」回傳格式；針對排序任務，設計批次候選評分介面。

**步驟三：實作系統二（審慎規劃代理）**
設計系統二的動作空間：
- 搜尋查詢（search query）
- 證據請求（evidence request），需明確指定目標（例如「找出支持 X 論點的段落」）
- 整合動作（integrate findings）
- 最終輸出（answer 或 ranked list）

採用 ReAct 風格的提示工程或微調方式，讓 LLM 能依歷史研究狀態產生下一個動作。

**步驟四：實作系統一（快速判斷模型）**
部署 Jev 或類似快速判斷模型，提供三項核心能力：
- **證據定位（Evidence Localization）**：根據證據目標從文件中找出相關段落（QA 任務以局部問題引導）。
- **相關性評估（Relevance Assessment）**：對候選文件評分並選取（排序任務以原始主題評分）。
- **證據探索（Evidence Discovery）**：主動檢視額外候選，發掘新研究線索。

實作並行判斷機制，使多份候選文件的評估可同時進行。

**步驟五：設計研究迴圈與回饋機制**
串接系統二與系統一：系統二發出證據請求 → 系統一回傳選定的原始段落 → 段落進入系統二的歷史狀態 → 系統二據此規劃下一步。設計「適應性閱讀」（adaptive reading）機制，允許系統一在發現部分相關內容時擴大閱讀範圍或擷取上下文。

**步驟六：加入主動探索分支**
實作圖 3 中的虛線探索分支：系統一在背景中持續檢視新候選，產出研究線索（research leads）回饋給系統二，擴大證據覆蓋率。

**步驟七：離線評估與調校**
以準備好的基準資料集評估任務效能（Accuracy、nDCG@20）、API 成本與完成時間。透過消融實驗（如移除系統一、移除並行判斷）找出瓶頸元件並調校。

**步驟八：部署與監控**
將系統封裝為服務，記錄每輪研究的動作、證據請求與回傳段落。建立監控指標：證據覆蓋率、單題 API 成本、平均完成時間，並設定異常告警。

### 潛在風險與注意事項

**風險一：證據目標設定不當導致研究方向偏移**
系統二的證據目標若過於模糊或偏頗，系統一會在錯誤方向上高效運算，浪費預算卻產出無用證據。
**緩解**：設計證據目標的範本與審核機制；對系統二的輸出進行抽樣檢視；引入反思步驟讓系統二定期檢視當前證據是否仍對齊最終目標。

**風險二：並行判斷的成本失控**
雖然單一判斷成本低，但若系統一並行檢視大量候選，總成本可能超出預期。
**緩解**：設定每輪研究的候選上限與並行數量上限；監控單題 API 成本並設定閾值告警；採用早期停止機制，當證據已充分時停止進一步檢視。

**風險三：系統一判斷錯誤被系統二放大**
系統一的快速判斷若產生錯誤（例如將不相關段落標記為相關），系統二可能據此規劃錯誤的下一步。
**緩解**：保留原始段落而非僅採用判斷結果；設計交叉驗證機制（例如對高風險判斷進行二次確認）；定期以人工標註資料評估系統一的準確率。

**風險四：固定語料庫的時效性與完整性限制**
JevGPT 設計基於固定語料庫，無法處理需要即時資訊或跨語料庫整合的問題。
**緩解**：明確界定系統適用範圍；對超出語料庫的問題設計降級回應（例如提示「此問題需查詢最新資料」）；定期更新語料庫索引。

**風險五：領域專業知識不足導致證據誤用**
在法律、醫學等高風險領域，系統回傳的段落可能被誤用為權威依據。
**緩解**：在輸出中加入「此為輔助證據，需專業人士確認」的提示；保留完整引用來源；對高風險決策保留人工審核環節。

**風險六：提示注入與惡意內容**
若語料庫中包含惡意內容，攻擊者可能透過精心設計的文件影響系統二的判斷。
**緩解**：對輸入至系統二的段落進行來源可信度評估；對系統二的輸出進行安全過濾；限制可執行的動作類型。

### 與其他技術的整合建議

**與既有 RAG 系統整合**
JevGPT 可作為傳統 RAG 流程的「深度研究層」，在初步檢索後對 top-k 候選進行多輪證據萃取。具體做法：將 JevGPT 的系統二包裝為 LangChain 或 LlamaIndex 的自訂 Agent，系統一則作為內部工具；當使用者問題需要多步推理時呼叫 JevGPT，簡單問題則走標準 RAG 路徑。

**與 ReAct／IRCoT 框架相容**
JevGPT 的系統二本質上是 ReAct 風格的代理，可直接整合至現有的 ReAct 工具迴圈。差異在於 JevGPT 將「證據請求」與「來源判斷」明確分離，使規劃與執行解耦，便於除錯與監控。

**與 BM25 與神經檢索器混合**
系統一的候選來源不限於 BM25，可整合稠密檢索（如 Dense Passage Retrieval）作為前置篩選，再由 JevGPT 進行深度證據萃取。NeuCLIRBench 的實驗顯示 GPT 式方法在排序任務上表現優異，可作為 JevGPT 的補充評分器。

**與企業知識管理平台整合**
透過 API 將 JevGPT 接入 Confluence、Notion、SharePoint 等平台，使其能對企業內部文件進行研究。需設計權限控管機制，確保系統僅能存取使用者有權限的文件。

**與監控與可觀測性工具整合**
整合 LangSmith、Weights & Biases 或自建儀表板，記錄每輪研究的動作序列、證據請求與回傳段落，便於事後審計與效能分析。

**與人類專家迴路整合**
在高風險應用中，於系統二產生最終答案前插入人工審核節點；或在系統一發現高不確定性時主動請求專家輸入，形成「AI 研究 + 人類覆核」的協作模式。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先閱讀第 1 節（Introduction）以理解 JevGPT 想解決的問題——為什麼「檢索到」不等於「使用到」——以及雙系統設計的動機。接著看圖 3 的架構圖，建立「系統二規劃、系統一執行」的心智模型。技術細節可先略過，專注於「證據目標」這個核心概念：它讓快速判斷變得有方向，也讓研究過程可被監控。

**給 AI 工程師**
重點閱讀第 3 節（Method）與圖 3，掌握系統二的動作空間設計、系統一的三大能力（證據定位、相關性評估、證據探索）以及並行判斷的實作方式。建議動手實作最小可行版本：先用 GPT-4 作為系統二、Jev 作為系統一、BM25 作為檢索器，在 BrowseComp-Plus 子集上重現實驗。接著優化並行數量、證據目標的提示工程，以及適應性閱讀的觸發條件，以降低 API 成本。

**給研究者**
重點關注第 1 節的關鍵觀察（研究規劃與局部證據判斷需要不同範圍的資訊）與第 4 節的實驗分析（證據覆蓋率與任務效能的關聯）。可進一步探索的方向包括：證據目標的自動生成、系統一判斷的可解釋性、多代理協作下的研究分工，以及在開放域（非固定語料庫）情境下的延伸。建議與 Schmidhuber 的強化學習控制器、Kahneman 的雙過程理論等經典文獻對照閱讀，理解 JevGPT 在更長的研究脈絡中的定位。

**給產品經理**
重點理解 JevGPT 的價值主張：在相同或更低的 API 成本下，達成更廣的證據覆蓋與更高的任務準確率。圖 2 的成本—品質散佈圖是與利害關係人溝通的有力工具。應用場景優先選擇「證據完整性直接影響決策品質」的領域（如法律研究、客戶支援），並設計「AI 給證據、人類做決策」的協作流程。需特別注意高風險領域的人工審核節點設計，以及 API 成本對單位經濟的影響。
