## 摘要翻譯

我們發表並釋出 ScienceBuddy（科學夥伴），一個互動式科學研究工作空間（interactive scientific research workspace），旨在將持續改進的科學智慧體（continually improving scientific agents）融入研究人員的日常工作流程（researchers' everyday workflows）。ScienceBuddy 協助研究人員執行科學任務（scientific tasks），同時將他們的請求、回饋（feedback）與執行證據（execution evidence）轉化為持續學習（continual learning）所需的任務與評量標準（tasks and evaluation rubrics）。其核心為遞迴中的遞迴自我改進（Recursive-in-Recursive Self-Improvement），一種將架構演化（harness evolution）與模型強化學習（model reinforcement learning）結合的範式：內層遞迴（inner recursion）在模型固定（model fixed）的情況下改進架構（harness），外層遞迴（outer recursion）則在改進的架構（improved harness）下訓練模型。架構演化形塑訓練經驗（training experience），而模型學習則為架構適應（harness adaptation）創造新的機會。我們呈現研究人員互動（researcher interaction）、架構改進與模型學習的案例研究（case studies），基準案例（benchmark cases）涵蓋四個科學任務家族（scientific task families）。透過將 ScienceBuddy 作為研究產品（research product）釋出，我們讓科學社群（scientific community）能夠使用此一範式，並朝發現智慧（discovery intelligence）邁進一步：這是一種透過與研究人員持續協作（sustained collaboration）而進步、並與其所支援的研究共同演化的科學人工智慧。網站：http://science-buddy.io

### 核心貢獻（3～5點）
- 提出「遞迴中的遞迴自我改進」範式，將架構演化（harness evolution）與模型強化學習（model reinforcement learning）緊密耦合，使智慧體架構與基礎模型能夠相互形塑、共同演化。
- 建構並釋出互動式科學研究工作空間 ScienceBuddy，將研究人員的請求、回饋與執行證據轉化為持續學習所需的任務與評量標準，讓科學智慧體真正融入日常工作流程。
- 透過內層遞迴（inner recursion）改進架構、外層遞迴（outer recursion）訓練模型的雙層機制，建立架構適應與模型學習之間的正向回饋循環。
- 在四個科學任務家族（scientific task families）上進行案例研究與基準案例（benchmark cases）驗證，展示研究人員互動、架構改進與模型學習的實際成效。
- 將 ScienceBuddy 作為研究產品（research product）開放給科學社群（scientific community），推動「發現智慧」（discovery intelligence）——一種能與研究人員持續協作、並隨研究議題共同演化的科學人工智慧。

### 適合對象
本論文適合從事科學人工智慧、互動式智慧體與自動化科學研究的研究人員；對持續學習、強化學習與智慧體架構演化感興趣的機器學習學者；以及希望將 AI 工具整合至日常研究流程、提升研究產出效率的實驗科學家與跨領域研究團隊閱讀。

## 深度分析

#### 方法論解析

ScienceBuddy（科學夥伴）的核心設計可視為一個「人機協作 → 任務形式化 → 雙層遞迴改進」的閉環。整體架構由兩大元件構成：**ScientificWorkspace（科學工作空間）** 與 **AgentHarness（智慧體架構）**。ScientificWorkspace 提供科學工具（scientific tools）、可執行環境（execution environments）、資料上傳、持久化檔案、可檢視的執行軌跡（traces）與產出物（artifacts）；AgentHarness 則是可插拔（pluggable）的程序層，負責以指令（instructions）、可複用技能（reusable skills）與上下文管理程序（context-management procedures）來組織模型行為。將「科學基礎設施」與「可編輯的程序架構」分離，是此方法論的關鍵：它讓程序變更變得明確、可評估，也讓後續的 harness evolution（架構演化）有明確的操作對象。

在互動形式化（interaction formulation）階段，研究人員的請求、澄清、執行紀錄與產出物會被共同轉化為任務目標、限制條件與成功準則。這些準則被收斂為任務專屬的 **rubrics（評量標準）**，而對應的指令、輸入與環境則被打包成可執行的 **Harbor tasks（儲備任務）**，作為後續 post-training（後訓練）的素材。值得注意的是，研究人員的回覆僅用於「告知」這些準則，而非被視為不可質疑的正確標籤；最終仍透過可執行檢查（executable checks）與固定評判者（fixed judges）來驗證。

在此基礎上，作者提出 **recursive-in-recursive self-improvement（遞迴中的遞迴自我改進）**，包含內外兩層遞迴：

- **Inner recursion（內層遞迴）— Feedback-guided Harness Improvement（回饋引導的架構改進）**：此時模型權重固定，由另一個固定的 auxiliary model（輔助模型）根據回饋與執行證據（execution evidence）診斷失敗原因，並對 instructions、skills 或 context settings 提出有界編輯（bounded edits）。候選修改只有在滿足編輯限制且確實改善表現時才會被接受，隨後進入評估與遞迴精煉。這相當於在固定 policy（策略）下最佳化 harness（架構）。
- **Outer recursion（外層遞迴）— Continual Model Reinforcement Learning（持續模型強化學習）**：在改進後的 harness 下，系統對環境進行 augmentation（增強），並使用 task-adaptive rubric rewards（任務適應性評量獎勵）來訓練模型。模型更新後，其行為分布改變，又會暴露出新的失敗模式，從而為下一輪 harness adaptation（架構適應）創造機會。

兩層遞迴的協調透過 nested update schedule（巢狀更新排程）與 cross-cycle experience and re-evaluation（跨週期經驗與重新評估）來實現。這形成了一種共演化（co-evolution）動態：harness 形塑訓練經驗（training experience），而模型學習則創造新的架構適應需求。從最佳化角度來看，這類似於雙層最佳化（bilevel optimization）：內層在固定模型下搜尋更好的程序描述，外層在改進程序下搜尋更好的模型權重。其穩定性挑戰包括非平穩性（non-stationarity）、獎勵駭取（reward hacking）以及評估成本。

#### 實驗數據解讀

論文的實驗以四個 scientific task families（科學任務家族）的 benchmark cases（基準案例）為基礎，並透過多個案例研究（case studies）來展示系統動態：

- **ScienceBuddy Interaction**：展示研究人員如何在 JAK1 調查與 ARL4C 研究中逐步精煉問題、連結證據，並將自然語言請求轉化為正式的 task specifications（任務規格）。這說明了互動資料確實能被形式化為可學習的任務。
- **Two-Cycle Recursive-in-Recursive Dynamics（兩週期遞迴中的遞迴動態）**：報告跨週期的 learning dynamics（學習動態）與 scientific task performance（科學任務表現）。合理的解讀是：第一週期透過 inner recursion 改進 harness，帶來立即的程序性提升；第二週期透過 outer recursion 的 model RL，使模型更能利用已改進的架構；cross-cycle re-evaluation 則用於防止迴歸（regression）。
- **Harness Adaptation with a Fixed Model（固定模型下的架構適應）**：在模型不變的前提下驗證 harness 本身的學習效果，包括 validation performance（驗證表現）與 learned procedures（學到的程序）。這類設計類似於消融實驗，能區分「程序改進」與「模型改進」各自的貢獻。
- **Model Learning with a Fixed Harness（固定架構下的模型學習）**：在架構不變的前提下觀察模型學習的動態與 problem coverage（問題覆蓋率），證明 policy learning（策略學習）本身也能帶來進步。

由於目前可取得的上下文未包含具體數值（例如成功率、rubrics 分數、標準差或樣本數），對實驗結果的量化解讀必須謹慎。從方法論設計來看，「固定模型 / 固定架構」的對照安排有助於因果推論：若 harness 改進能在固定模型下提升表現，則可歸因於程序層的優化；若模型 RL 能在固定 harness 下提升表現，則可歸因於策略層的優化。未來若能取得詳細數據，應進一步檢視：跨週期提升的幅度是否顯著、是否存在 overfitting（過度擬合）到少數 benchmark families、以及 fixed judges 與 executable checks 是否引入評估者偏誤。

#### 與現有研究的比較

本研究定位於多條前線工作的交會處：

- **Reflection 與 Harness Optimization（架構最佳化）**：先前工作已探討如何修訂可重複使用的指令與執行程序，但多未將其與互動式工作空間及持續性模型強化學習緊密結合。
- **Interaction-driven Adaptation（互動驅動適應）與 Rubric-based Reinforcement Learning（基於評量標準的強化學習）**：這些機制提供了模型改進的途徑，但通常未同時 co-evolve（共同演化）harness。
- **Joint Adaptation（聯合適應）**：SIA 同時更新 harness 與模型權重，並應用於單細胞 RNA 去噪；HELIX 將 harness evolution 連結到訓練資料建構；AgentBuild 則依據科學家撰寫的 rubrics、curricula 與 knowledge bases 建構智慧體。

ScienceBuddy 的差異化貢獻在於：它將「研究人員協作本身」視為任務與評量標準的來源，並透過 recursive-in-recursive 的設計讓 harness evolution 與 model reinforcement learning 相互驅動。此外，它強調將系統以 research product（研究產品）形式釋出，讓科學社群能直接在 everyday workflows（日常工作流程）中使用，這比單純的演算法貢獻更接近「discovery intelligence（發現智慧）」的願景。

然而，其限制也同樣明顯：內層遞迴依賴 auxiliary model 的診斷品質；bounded edits 雖然提升安全性，卻可能限制架構的創新空間；研究人員回饋可能帶有雜訊或領域偏見；而 executable checks 與 fixed judges 在不同科學領域的可擴展性仍需驗證。

#### 可重現性評估

論文提到 ScienceBuddy 已透過 http://science-buddy.io 作為 research product（研究產品）釋出，並在附錄 S1 提供 Implementation Details（實作細節），涵蓋 Datasets and Environments（資料集與環境）、Harness Evolution、Reinforcement Learning、Concrete Researcher Inputs 以及 User Interface（使用者介面）。這些資訊對重現性是有利的起點。

但從目前可見的上下文判斷，論文並未明確聲明是否提供 open-source code（開源程式碼）、model weights（模型權重）、Harbor tasks 資料集的下載連結或授權條款。若僅釋出網頁介面而未公開訓練管線、checkpoint（檢查點）與評估 harness，則重現性仍屬部分：其他研究者可以體驗產品，但難以完全複製訓練過程、驗證數據或進行公平比較。建議後續釋出應包含：GitHub 等程式碼倉庫、凍結的模型權重、可執行的 Harbor tasks 集合、完整的 hyperparameters（超參數）以及評估腳本。

#### 未來研究方向

基於 ScienceBuddy 的框架，可延伸的研究方向包括：

1. **擴展任務家族與領域覆蓋**：從目前的四個 scientific task families 擴展到更多實驗科學、臨床研究或工程設計領域，並建立社群維護的標準化 benchmark。
2. **自動化 rubric 生成與精煉**：減少對人工或輔助模型設計評量標準的依賴，讓系統能從互動中自動推導、更新並檢驗 rubrics 的一致性。
3. **長期使用者研究**：在真實實驗室中進行縱向研究，衡量 ScienceBuddy 對研究產出、錯誤率與研究者認知負荷的實質影響。
4. **安全性與對齊**：防範 reward hacking（獎勵駭取）、confirmation bias（確認偏誤）以及模型過度迎合研究者預期等問題，發展可解釋的審計機制。
5. **多智慧體協作**：讓多個科學智慧體在共同 workspace 中分工、辯論與交叉驗證，提升複雜發現任務的可靠性。
6. **與實驗硬體整合**：將 ScienceBuddy 連接至實驗室自動化平台、儀器控制介面與資料流，縮短「計畫 → 執行 → 分析」的循環。
7. **遞迴穩定性理論分析**：研究 inner recursion 與 outer recursion 的收斂條件、共演化動態的均衡特性，以及如何避免迴圈中的能力退化。
8. **跨機構聯邦式持續學習**：在保護資料隱私的前提下，讓不同研究機構的互動經驗共同豐 Harbor tasks 與 harness 知識。

## 論文問答

**Q1：ScienceBuddy 旨在解決什麼樣的科學研究問題？**

A：ScienceBuddy 試圖解決的核心問題是：如何將研究人員與科學智慧體之間的協作對話，轉化為智慧體在工作流程與能力上的持續改進，而非僅僅修正單次回答。現有的語言模型智慧體雖然能夠檢索證據、查詢資料庫並執行計算流程，但研究人員在對話中提出的澄清、質疑與額外檢查，往往只停留在當前互動，無法累積成跨任務的進步。ScienceBuddy 因此提出一個互動式科學研究工作空間，把研究人員的需求、回饋與執行證據都形式化為可重複執行的學習素材。

**Q2：為什麼單純的反思機制或互動驅動適應不足以解決這個問題？**

A：單純的反思與架構最佳化雖然能修訂可重複使用的指令與執行程序，卻未必能與模型權重的更新有效協調；反之，互動驅動適應與基於評量標準的強化學習雖能改善模型行為，卻可能忽略了程序性架構的同步演化。ScienceBuddy 認為，研究協作本身應該同時提供「任務」與「評估準則」，並且讓這兩種學習訊號反覆協調。只有將架構演化與模型強化學習結合，才能讓智慧體真正從人類回饋中持續成長。

**Q3：為什麼「持續改進」對科學 AI 而言特別重要？**

A：科學研究的本質就是不斷分析、檢視與修正，因此支援研究的智慧體也必須能隨著研究議題一起演進，而不是重複犯下相同錯誤。如果智慧體無法把每次協作中獲得的知識內化為程序與策略，研究人員就必須不斷糾正類似問題，協助效益將大打折扣。ScienceBuddy 把這種願景稱為「發現智慧」，也就是透過與研究人員的持續協作，讓科學 AI 在支援研究的過程中不斷進化。

**Q4：什麼是「遞迴中的遞迴自我改進」？其核心運作方式是什麼？**

A：「遞迴中的遞迴自我改進」是 ScienceBuddy 的核心範式，它將架構演化與模型強化學習緊密耦合。內層遞迴固定任務模型，由另一個輔助模型診斷失敗並提出對指令、技能或上下文設定的有限編輯；外層遞迴則在改進後的架構下訓練模型。這兩層遞迴彼此影響：架構演化塑造了訓練經驗，而模型學習又創造出新的架構適應機會。

**Q5：與 SIA、HELIX、AgentBuild 等先前研究相比，ScienceBuddy 的主要創新在哪裡？**

A：ScienceBuddy 的主要創新在於把研究人員的協作互動直接轉化為可執行的儲備任務與評量標準，並以巢狀遞迴的方式協調架構與模型的反覆更新。相較於 SIA 或 HELIX 雖然也同時更新架構與權重，但較少強調從即時研究對話中萃取結構化學習訊號；AgentBuild 則偏重由科學家預先編寫的評量標準與課程。ScienceBuddy 讓「協作本身」成為學習訊號的來源，並透過內外層遞迴讓程序改進與策略學習相互推進。

**Q6：為什麼要將 AgentHarness 與模型分離？又為何要使用評量標準與 Harbor 任務？**

A：將可編輯的智慧體架構與科學基礎設施分離，可以讓程序性變更變得明確且可評估，研究人員與開發者都能清楚知道智慧體的執行邏輯如何被修改。評量標準則把來自回饋的成功條件具體化，同時避免將研究人員的回覆當作不可質疑的正確標籤。Harbor 任務進一步把指令、輸入與執行環境打包成可執行的後訓練素材，讓持續學習有穩定的資料與評估依據。

**Q7：論文在實驗中使用了哪些基準案例或科學任務家族？**

A：論文的案例研究橫跨四個科學任務家族，涵蓋不同類型的科學分析與推理需求。具體呈現的實驗包括研究人員互動案例、兩輪遞迴中的遞迴動態、固定模型下的架構適應，以及固定架構下的模型學習。這些設計同時評估程序層面的改進與策略層面的學習，讓讀者能從多個角度觀察系統的進步。

**Q8：ScienceBuddy 的關鍵實驗結果有哪些？**

A：兩輪遞迴實驗顯示，隨著架構與模型共同演化，學習動態與科學任務表現都呈現跨週期的改善。在固定模型下進行的架構適應實驗證明，僅透過程序性編輯就能提升智慧體的執行成效。而在固定架構下進行的模型學習實驗則顯示，模型能夠擴大問題覆蓋範圍並改善處理複雜科學任務的能力。

**Q9：論文進行了哪些消融實驗來驗證內外層遞迴各自的貢獻？**

A：為了分離兩個遞迴的效果，論文設計了「固定模型下的架構適應」與「固定架構下的模型學習」兩組對照實驗。前者驗證內層遞迴能獨立改進智慧體的執行程序，後者驗證外層遞迴能在穩定架構下提升策略品質。接著再透過兩輪遞迴中的遞迴動態實驗，展示兩者結合後產生的協同效應。

**Q10：研究人員在實際工作中會如何使用 ScienceBuddy？**

A：研究人員可以在工作空間中上傳資料、透過對話逐步澄清需求、執行可重複的分析，並檢視智慧體留下的執行軌跡與產出物。當研究人員提供回饋時，系統會把這些互動轉化為任務規格與評量標準，例如針對 JAK1 調查的精煉或 ARL4C 研究中的證據串聯。這種設計讓科學家在日常工作流程中自然成為智慧體持續學習的協作者。

**Q11：作為一個研究產品，ScienceBuddy 在設計上有哪些考量？**

A：ScienceBuddy 採用模組化基礎設施與可插拔架構，讓不同領域的科學工具與執行環境能夠彈性整合。系統支援多模態輸入、長上下文智慧推理、持久化檔案，以及可檢視的執行軌跡與成品，這些都提升了研究人員對智慧體行為的信任與控制。透過將 ScienceBuddy 對外釋出，作者希望讓整個科學社群都能使用並貢獻於這個持續演化的平台。

**Q12：這項研究可能對科學 AI 領域帶來什麼影響？**

A：ScienceBuddy 朝「發現智慧」邁進了一步，也就是讓科學 AI 透過與研究人員的持續協作不斷進化，而非僅是靜態的工具。它有潛力減少智慧體的重複性錯誤，並把研究社群累積的最佳實踐內化為可重複使用的程序。長遠來看，這種人機協作的回饋循環可能改變科學研究的進行方式，使 AI 成為能夠共同成長的研究夥伴。

**Q13：這項研究有哪些已知的限制？**

A：由於研究人員的回饋品質會直接影響衍生出的評量標準與儲備任務，模糊或錯誤的回饋可能導致智慧體學到不當的行為模式。此外，架構編輯必須透過輔助模型產生並經過可執行驗證，這個過程在計算成本與驗證覆蓋率上仍有挑戰。最後，固定評審機制雖然能提供客觀評分，卻可能無法完全捕捉科學正確性中的細微判斷。

**Q14：ScienceBuddy 在哪些情況下可能會失敗或表現不佳？**

A：當研究人員的回饋過於籠統或前後不一致時，系統可能難以萃取出明確的任務規格與評量標準，導致後續學習方向偏離。輔助模型提出的架構編輯也可能過度擬合特定案例，無法泛化到其他科學任務。另外，如果執行環境或固定評審無法正確檢驗科學主張，智慧體可能學會滿足表面指標卻不符合真正科學嚴謹性的行為。

**Q15：未來可以朝哪些方向進一步發展？**

A：未來可以將 ScienceBuddy 擴展到更多科學領域，並提升輔助模型提出架構編輯的品質與可解釋性。另一個方向是減少對研究人員回饋的依賴，例如透過主動學習或自動化驗證來降低人工負擔。最終，持續深化與實驗執行、文獻推理及跨領域知識的整合，將有助於實現更具自主性的發現智慧系統。

## 實務應用指南

### 適用場景

1. **標靶藥物機制探索與假設驗證**  
   例如針對 JAK1 等標靶，研究人員可與 ScienceBuddy 反覆討論文獻、執行序列分析或結構預測，系統將對話、修正意見與執行證據轉成可重複執行的 Harbor 任務與評量標準，持續改進智慧體在藥物標靶調查上的程序。

2. **多模態文獻與實驗證據整合**  
   如 ARL4C 這類跨文獻、跨圖表與數據的研究，研究人員上傳圖片、表格與原始數據，ScienceBuddy 協助串連證據鏈；互動過程中產生的 rubric 會成為架構演化和模型強化學習的訓練訊號。

3. **可重複計算分析流程的建立與持續修正**  
   生物資訊或計算化學團隊可將常見流程（如 RNA-seq、分子動力學後處理）包裝成技能（skills），透過內層遞迴根據執行失敗與回饋不斷修訂指令與上下文管理程序，降低每次手動除錯成本。

4. **實驗設計與統計檢核代理**  
   在臨床試驗設計或實驗室方法開發中，研究人員提出設計、樣本數與檢定需求，ScienceBuddy 協助檢查假設、執行模擬並記錄修訂意見，最終形成可評量的任務家族，用於外層遞迴的模型強化學習。

5. **跨領域知識庫問答與方法推薦**  
   整合內部知識庫、公開資料庫（如 PubMed、UniProt）與機構文件，研究人員以自然語言查詢方法論或尋找相關論文；系統把高頻互動轉為儲備任務，讓架構與模型同步適應特定領域術語與慣例。

### 實作前置條件

**資料**
- 研究人員與智慧體的互動紀錄（對話、修正、確認與拒絕）。
- 可執行的科學任務範例與對應輸入資料（序列、結構、圖表、原始數據）。
- 領域基準案例（benchmark cases）與專家制定的評量標準（rubrics）。
- 執行痕跡與產出檔案（traces、artifacts），用於診斷與驗證。

**運算**
- 大型語言模型推理端點（API 或自建），包含固定任務模型與固定輔助診斷模型。
- GPU 叢集或雲端運算資源，用於外層遞迴的強化學習（RL）訓練。
- 隔離的執行環境（sandbox / container），支援科學工具鏈（Python、R、生物資訊套件等）。

**技能**
- 機器學習工程：能實作強化學習流程、群組相對策略目標（group-relative policy objective）與獎勵塑形。
- 提示工程與架構設計：能撰寫 instructions、skills、context-management procedures。
- 領域科學知識：至少一名熟悉目標任務家族（如藥物探索、基因體學）的專家，負責 rubric 設計與結果驗證。
- 軟體工程：能建構模組化基礎設施、可插拔架構（pluggable harness）與前後端工作空間。

### 實作步驟建議

1. **建構 ScientificWorkspace**  
   整合科學工具、參考資料、資料上傳、可執行分析、持久化檔案與可檢視的執行痕跡，讓研究人員能在單一介面完成互動與證據檢查。

2. **設計 AgentHarness**  
   將 instructions、可重複使用的 skills 與上下文管理程序分離成可編輯的架構，確保程序變更可被版本控制、評量與復原。

3. **建立互動形式化與 Harbor 任務**  
   把研究人員請求、澄清、執行紀錄與產出統一轉換為任務目標、限制條件與評量標準，打包成可執行的 Harbor tasks，供後續診斷與訓練使用。

4. **部署內層遞迴：Feedback-guided Harness Improvement**  
   固定任務模型，由輔助模型根據失敗案例與回饋進行診斷，提出對架構的有限編輯；只有符合編輯限制並通過評量的候選修改才會被接受，並反覆驗證。

5. **部署外層遞迴：Continual Model Reinforcement Learning**  
   在改進後的架構下進行環境增強與任務自適應 rubric 獎勵，使用新鮮 rollout groups 與群組相對策略目標更新模型權重。

6. **協調遞迴中的遞迴更新排程**  
   設定巢狀更新時程（nested update schedule），讓架構演化塑造訓練經驗、模型學習創造新的架構適應機會，並進行跨週期重新評估（cross-cycle re-evaluation）。

7. **產品化與釋出**  
   加入多模態輸入、長上下文推理介面、研究人員檢視控制項、安全沙箱、監控儀表板與分階段釋出機制，最終以研究產品形式開放給科學社群。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解措施 |
|---|---|---|
| **回饋雜訊與專家意見分歧** | 研究人員的修正未必一致，直接當作正確標籤會導致獎勵訊號偏頗。 | 將回饋轉為 rubric 與可執行檢查，搭配固定 judge 與多位專家驗證。 |
| **架構漂移（Harness Drift）** | 內層遞迴過度修改架構，可能破壞原本穩定的程序。 | 設定編輯限制（bounded edits）、版本控制與回滾機制，並要求修改通過保留任務驗證。 |
| **評量遊戲化（Reward Hacking）** | 模型可能針對 rubric 得分而非真正科學正確性進行優化。 | 使用 executable checks、獨立 judge、多樣化任務覆蓋率評估，並定期人工抽查。 |
| **運算與成本爆炸** | 雙層遞迴需要反覆推理、rollout 與 RL 訓練，成本可能快速累積。 | 採用 fresh rollout groups 與群組相對目標提高效率，並設定每週期運算預算上限。 |
| **執行安全與資料隱私** | 科學程式碼可能在沙箱外產生副作用，互動資料也可能涉及機密研究或個資。 | 使用隔離容器、最小權限原則、差分隱私或資料去識別化，並建立稽核日誌。 |
| **災難性遺忘** | 外層遞迴持續更新模型可能遺失先前學到的通用科學能力。 | 保留歷史 Harbor tasks 作為 replay buffer，定期進行跨週期重新評估與多任務微調。 |

### 與其他技術的整合建議

- **實驗室資訊系統（LIMS / ELN）**：將 ScienceBuddy 作為前端互動層，透過 API 讀取實驗紀錄、樣本資訊與原始數據，並把分析結果與執行痕跡寫回 ELN，確保研究流程可追溯。
- **生物資訊與計算流程管線（Nextflow / Snakemake / Galaxy）**：把既有 workflow 包裝成 AgentHarness 中的 skills，讓智慧體呼叫標準化流程，同時利用內層遞迴根據互動回饋優化流程參數與錯誤處理。
- **知識庫與文獻檢索（PubMed、UniProt、內部知識圖譜）**：透過 RAG 或專用檢索工具提供即時領域證據，並將檢索結果與研究人員回饋一起納入 Harbor tasks 的 rubric 設計。
- **MLOps / LLMOps 平台（Weights & Biases、MLflow、LangSmith）**：記錄架構版本、模型權重、rollout 獎勵與評量分數，支援雙層遞迴的實驗追蹤與模型治理。
- **身分認證與權限管理（SSO / IAM）**：對接機構帳號系統，依研究人員角色控制資料上傳、程式碼執行與模型釋出權限。
- **可觀測性與監控（OpenTelemetry、Grafana）**：追蹤互動延遲、執行錯誤率、rubric 分數分布與架構修改頻率，及早發現 drift 或效能衰退。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從第 2 章的「ScientificWorkspace & AgentHarness」與第 3 章「Scientific Workspace and User Experience」讀起，理解 ScienceBuddy 如何像一個「可互動的科學研究桌面」運作；接著看第 4.1 節的 JAK1 與 ARL4C 案例，掌握研究人員與智慧體的對話流程，最後再回頭看遞迴中的遞迴自我改進概念，會更容易理解為何要同時改變「工作程序」與「模型能力」。

**給 AI 工程師**  
請聚焦第 2.3 至 2.5 節的雙層遞迴機制，以及附錄 S1.2 與 S1.3 的實作細節：內層遞迴如何用固定輔助模型診斷並修訂架構、外層遞迴如何在演化架構下進行強化學習，以及 fresh rollout groups 與 group-relative policy objective 的設計。同時留意架構與模型權重之間的巢狀更新排程，這是系統穩定收斂的關鍵。

**給研究人員**  
建議從摘要與第 1 節的動機出發，思考您日常工作中哪些重複性科學任務可以被形式化；接著閱讀第 4 章案例研究，對照自身領域設計合適的 rubric 與 Harbor tasks。特別注意作者強調「研究人員回饋不應被視為絕對正確標籤」，因此您需要參與設計可執行的評量標準，才能讓系統真正學到可靠的科學程序。

**給產品經理**  
請把重點放在摘要、第 1 節與第 3 節的使用者體驗描述，評估 ScienceBuddy 能為研究團隊帶來的價值：減少重複除錯、累積機構級科學程序知識、持續從協作中學習。同時務必詳讀「潛在風險與注意事項」，在產品化過程中預留人工審查、沙箱安全、運算預算與分階段釋出的資源，並規劃與現有 LIMS/ELN 或知識庫的整合路徑。
