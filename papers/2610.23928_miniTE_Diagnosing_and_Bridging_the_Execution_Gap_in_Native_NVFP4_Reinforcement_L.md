miniTE 的方法論核心在於揭示並解決一個被既有研究忽略的關鍵問題：**在原生 NVFP4 強化學習管線中，即使學習器（learner）與採樣器（sampler）共享相同的模型權重與標稱數值格式，兩者之間仍存在顯著的執行差異（execution gap）**。此差異會透過重要性比率（importance ratio）與裁剪決策（clipping decision）進入策略梯度更新，進而影響學習穩定性與最終效能。

**問題形式化**

論文將學習器策略 $\pi^L_\theta$ 與採樣器策略 $\pi^R_{\bar{\theta}}$ 的執行差異定義為：

$$\delta^{num}_t = \log \pi^L_\theta(a_t|s_t) - \log \pi^R_\theta(a_t|s_t)$$

其中 $\bar{\theta}$ 為採樣時的權重版本。透過凍結參數版本、token ID 與評分上下文，僅分離出純粹的執行差異。此形式化使診斷能聚焦於「數值執行規格（execution specification）」而非權重滯後或採樣變異。

**NVFP4 格式的隱含自由度**

NVFP4 採用 E2M1 值搭配每 16 值一組的 E4M3 區塊縮放（block scaling）與外層 FP32 縮放（outer scaling）。然而，僅有格式名稱並不足以完整定義計算行為，因為以下選擇仍屬開放：
- **縮放域（scale domain）**：外層縮放可作用於整個張量或按行（row-wise）
- **捨入指令（rounding instruction）**
- **累加順序（reduction order）**
- **填充（padding）策略**
- **路由器權重與輸出轉換（cast）的介入位置**

這些選擇構成「執行規格」，是診斷與實作的關鍵單位。

**三層診斷框架**

論文設計了三組對照實驗來分離不同來源的數值差異：

1. **量化誤差（quantization error）**：同一計算堆疊內 NVFP4 對 BF16 的差異
2. **跨堆疊執行差異（cross-stack execution difference）**：學習器對採樣器
3. **實作差異（implementation difference）**：同一運算子的最佳化版本對參考實作

具體控制變量包括：
- **凍結策略評分（frozen-policy scoring）**：揭示 NVFP4 擴大了跨引擎對數機率尾部分布
- **目標層路由一致性（target-layer routing agreement）**：固定專家 ID 後，FC1/FC2 輸出仍存在差異
- **僅採樣器縮放變更（sampler-only scaling change）**：證明單純調整縮放無法建立一致性

**miniTE 框架設計**

miniTE 採用雙路徑設計：
- **嚴格執行路徑（strict execution path）**：作為跨引擎對齊的參考基準
- **預設路徑（default path）**：結合逐詞元量化（per-token quantization）、原生分組 GEMM 實作與 BF16 反向傳遞

關鍵設計理念是**不修改強化學習目標**，僅透過數值對齊與運算子最佳化提升效率與穩定性。

**運算子層級最佳化**

論文將量化與分組 GEMM 視為連貫的資料流（connected dataflow），而非獨立元件。這是因為路由式專家工作負載（routed expert workload）需要：
- 運算元準備（operand preparation）
- 表示轉換（representation conversion）
- 分派（dispatch）

若僅最佳化 GEMM 核心而忽略周邊資料搬移，FP4 算術增益將無法轉化為端到端加速。

**與既有方法的關鍵區別**

| 面向 | 既有方法 | miniTE |
|------|---------|--------|
| 對齊目標 | 權重與格式匹配 | 完整執行規格對齊 |
| 反向精度 | 多為低精度 | 保留 BF16 反向 |
| 診斷工具 | 通常缺乏 | 內建可重複使用的診斷 |

- **現象**：NVFP4 需要 Blackwell 架構硬體支援，在舊架構（如 Hopper）上無法運行

**風險三：MoE 路由敏感性**
- **現象**：路由器精度不足可能導致專家選擇不一致，進而放大 FC1/FC2 輸出差異
- **緩解**：使用選擇性路由器精度（路由器保留高精度）；啟用路由重放；監控專家負載平衡

**風險四：整合瓶頸**
- **現象**：權重轉換與節點間同步可能成為吞吐量瓶頸，特別是在多節點環境
- **緩解**：使用 miniTE 的整合測量工具識別瓶頸；考慮權重快取；評估非同步同步策略

**風險五：學習率與超參數敏感度**
- **現象**：低精度訓練對學習率、clip 邊界等超參數更敏感
- **緩解**：從 BF16 訓練的成熟超參數出發，進行小規模網格搜尋；採用保守的學習率衰減策略

**風險六：基準效能落差**
- **現象**：在某些任務上，NVFP4 訓練的最終 benchmark 分數可能略低於 BF16
- **緩解**：使用 miniTE 的數值對齊工具縮小差距；考慮混合精度策略（部分層保留 BF16）
