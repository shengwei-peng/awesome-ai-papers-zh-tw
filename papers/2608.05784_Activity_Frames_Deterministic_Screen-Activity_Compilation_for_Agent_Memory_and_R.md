# 活動框架（Activity Frames）：用於智慧體記憶（Agent Memory）與重播（Replay）的確定性螢幕活動編譯（Deterministic Screen-Activity Compilation）

## ⚡ TL;DR

現有智慧體只能記住對話，無法記錄使用者實際做過什麼，導致重複耗費大量推論成本。
提出確定性零模型編譯管線，將螢幕擷取串流轉為型別化、可稽核的活動框架。
單日資料壓縮86倍且僅68毫秒，問答準確率達98.4%，並首次量化了例行開銷與重現率。

## 摘要翻譯

電腦使用智慧體（Computer-use Agents）為了重新推導使用者已執行過的例行程序，必須耗費完整的前沿推論（Frontier Inference）成本，因為現今智慧體的記憶只記錄使用者說了什麼，而非使用者做了什麼。我們透過一條確定性、零模型（Zero-model）的管線（Pipeline），將被動擷取的螢幕活動編譯為智慧體記憶（Agent Memory）：它把本地擷取串流（Local Capture Stream）分割成型別化活動框架（Typed Activity Frames），亦即帶有應用程式（Application）、網站（Site）、時序資訊（Timing）、輸入量（Input Volume），以及指回原始資料列（Raw Rows）之證據指標（Evidence Pointers）的有界片段（Bounded Episodes）；由於管線中無模型介入，輸出具有位元組一致（Byte-identical）、可快取（Cacheable）且可機械化稽核（Mechanically Auditable）等特性。

在某位專業人士的單使用者語料庫（Single-user Corpus）上（涵蓋 51 個活躍日，共 128,756 個框架），編譯器（Compiler）能在 68 毫秒內把一天的原始擷取壓縮為體積僅為原本 1/86 的提示就緒上下文區塊（Prompt-ready Context Block）；在獨立參考標準（Independent Oracle）下，讀取該區塊的智慧體回答當天相關問題的準確率達 98.4%（Wilson 95% 信賴區間（Wilson 95% CI）91.7–99.7%），相較於同一份擷取之大型語言模型摘要（LLM Summary）的 66–80%；此外，讀取該區塊的中階模型（Mid-tier Model）可媲美頂級模型（Frontier Model）。

同一個編譯器（Compiler）也可兼作需求端成本工具（Demand-side Cost Instrument）。它透過讀取被動的委派前人類活動（Pre-delegation Human Activity），而非智慧體執行軌跡（Agent Rollouts），提供兩個智慧體成本模型所假設、但據我們所知尚未被量化的參數：例行開銷比率（Routine Overhead Ratio）R 與例行重現率（Routine Recurrence）h。我們首次報告 R（模型化上界（Modeled Upper Bound））的值，介於 60 至 343 倍之間；可委派重現率（Delegable Recurrence）在樣本內（In-sample）為 9.0%、樣本外（Out-of-sample）為 7.7%，對應於實際全機群權杖上限（All-fleet Token Ceiling）約 8%。已編譯例行程序（Compiled Routine）可在模型不參與的情況下確定性重播（Replay），並在守衛匹配命中（Guard-matched Hit）的現場示範中以零模型權杖完成。綱要（Schema）、編譯器（Compiler）與評估框架（Evaluation Harness）均已開源。

### 核心貢獻（3～5點）
- 提出一條確定性、零模型（Zero-model）的螢幕活動編譯管線，將被動擷取轉換為型別化活動框架（Typed Activity Frames），作為智慧體可重播（Replay）的行為情節記憶（Behavioral Episodic Memory）。
- 在單使用者語料庫上驗證，一天的原始擷取可在 68 毫秒內壓縮為體積 1/86 的提示就緒上下文區塊（Prompt-ready Context Block），且問答準確率達 98.4%，顯著優於 LLM 摘要（LLM Summary）的 66–80%。
- 將編譯器（Compiler）兼作需求端成本工具（Demand-side Cost Instrument），首次量測 Routine Overhead Ratio R（60–343×）與可委派重現率（Delegable Recurrence，9.0% / 7.7%），並推估實際全機群權杖上限（All-fleet Token Ceiling）約 8%。
- 已編譯例行程序（Compiled Routine）可在模型不參與的情況下確定性重播（Replay），並在守衛匹配命中（Guard-matched Hit）示範中以零模型權杖完成。
- 開源綱要（Schema）、編譯器（Compiler）與評估框架（Evaluation Harness），便於後續研究重現與驗證。

### 適合對象
適合對長期 LLM 智慧體（Long-term LLM Agents）、電腦使用智慧體（Computer-use Agents）、智慧體記憶（Agent Memory）與外部化（Externalization）架構、螢幕活動連續擷取（Continuous Capture）與自動化，以及 AI 代理成本建模與可機械化稽核（Mechanically Auditable）系統感興趣的研究者與工程師。

## 深度分析

#### 方法論解析

本研究的核心是提出一條 **deterministic screen-activity compilation（確定性螢幕活動編譯）** 管線，把被動擷取到的螢幕活動轉換成 **Activity Frames（活動框架）**，作為 **computer-use agents（電腦使用智慧體）** 的 **agent memory（智慧體記憶）**。整條管線標榜 **zero-model pipeline（零模型管線）**：從輸入的 **local capture stream（本地擷取串流）** 到輸出的活動框架，完全不呼叫任何機器學習模型，因此輸出具有 **byte-identical（位元組一致）**、**cacheable（可快取）** 與 **mechanically auditable（可機械化稽核）** 的特性。

##### 輸入與問題設定

輸入來自事件驅動的螢幕擷取，每一筆 **raw row（原始資料列）** 只記錄「在時間 t，應用程式 a 顯示了視窗 w，且位於網址 u」。以論文語料為例，單日約有兩千筆 **snapshot rows（快照資料列）**。現行有兩種消費策略：一是 **raw search（原始搜尋）**，直接把整串快照交給模型，讓模型自行做 **sessionization（工作階段化）**、**deduplication（去重複）** 與 **duration accounting（持續時間計算）**，單日成本約 126,812 tokens；二是 **LLM summary（LLM 摘要）**，雖然壓縮率高，但帶來 **per-run cost（每次執行成本）**、**non-determinism（非確定性）**、長輸入可靠性下降，以及可能虛構未發生活動的風險。本研究主張兩者之間缺少一個「編譯層」：像編譯器把指令轉成結構化產物一樣，把快照串流編譯成活動框架。

##### 兩層式綱要（Two-tier Schema）

論文設計的 **schema（綱要）** 明確區分「測量事實」與「推論標籤」：

1. **第一層：測量事實（measured facts）**  
   只能由原始擷取資料直接導出的欄位，包括應用程式名稱、**site（網站）**、起訖時間、**dwell-based active time（基於停留的活躍時間）**、**typed page references（型別化頁面參考）**、**input volume（輸入量）**（按鍵、點擊次數等），以及指回原始資料列的 **evidence pointers（證據指標）**。這一層完全不含模型推論。

2. **第二層：推論標籤（tagged inference）**  
   允許加入推論結果，但必須滿足三個條件：使用命名空間隔離、附帶信心分數、並連結到支援它的測量證據。如此一來，解釋性內容不會污染第一層，也方便後續稽核與版本控制。

此外，綱要把「覆蓋缺口（coverage gaps）」與「盲點（blind spots）」列為強制文件元素，這是記憶系統中少見的設計：不隱藏不知道的事，而是明確標示出來。

##### 確定性編譯規則

編譯器使用一組純規則，無需學習元件：

- **Dwell crediting（停留計分）**：根據使用者在同一視窗或網址的停留時間計算活躍時間，避免把短暫切換誤判為長時間工作。
- **Session gaps（工作階段間隙）**：以時間間閾值把連續快照切分成獨立的 **bounded episodes（有界片段）**。
- **Flicker merging（閃爍合併）**：合併快速交替的應用程式或視窗切換（例如 Alt-Tab、對話框彈出），減少雜訊。
- **Nearest-frame attribution（最近框架歸因）**：把鍵盤、滑鼠等輸入事件歸因到時間上最接近且語境相關的框架。
- **Coordinate-based click resolution（基於座標的點擊解析）**：利用點擊座標對應到實際 UI 元素或連結。
- **Total URL-to-entity typing（URL 到實體的完整型別化）**：把原始網址映射到更高階的型別化實體參考，例如把 GitHub PR 網址標記為 `PullRequest`。

這些規則的組合產出 **typed activity frames（型別化活動框架）**，每個框架都是一段有明確邊界、攜帶應用程式與網站資訊、時序、輸入量與證據指標的結構化單元。

##### 重播執行器與成本參數

編譯器同時充當 **demand-side cost instrument（需求端成本工具）**。它從 **pre-delegation human activity（委派前人類活動）** 中讀取兩個過去未被實際測量的參數：

- **Routine Overhead Ratio R（例行開銷比率 R）**：模型化上界，表示智慧體從頭推導一次使用者已做過的例行程序所需成本，相對於人類實際執行該程序成本的倍率。
- **Routine recurrence h（例行重現率 h）**：人類活動中可被智慧體接管的例行程序比例，即 **delegable recurrence（可委派重現率）**。

論文進一步提供一個參數化重播執行器（parametric replay executor）。當已編譯的例行程序符合預設保護條件（**guard-matched hit（守衛匹配命中）**）時，可以完全不經過模型、以零 token 重新執行。

#### 實驗數據解讀

##### 語料庫與壓縮效率

實驗使用一位專業人士的 **single-user corpus（單使用者語料庫）**，共 61 天 live capture，產出 128,756 個活動框架、涵蓋 51 個活躍日。編譯器把單日原始擷取壓縮成可直接餵給模型的 **prompt-ready context block（提示就緒上下文區塊）**，體積縮小 **86×**。這意味著原本需要約 126,812 tokens 的原始資料，經編譯後僅需約 1,475 tokens 左右即可表達同日活動，顯著降低 **frontier inference（前沿推論）** 的上下文成本。

##### 編譯速度與位元組一致性

單日完整編譯僅需 **68 ms**。由於沒有模型參與，同一組 raw rows（原始資料列）與同一套規則永遠產生完全相同的輸出，達成 **byte-identical（位元組一致）** 與 **cacheable（可快取）**。這對長期 **LLM agents（長期 LLM 智慧體）** 至關重要：記憶可以離線重建、跨版本比對、並被版本控制。

##### 持續時間分布的意義

論文報告兩個時間指標：

- **median inter-capture gap（擷取間隔中位數）** 為 6.1 秒：這是錄製器的取樣節奏，不是人類行為節奏。
- **post-transit median frame（切換後框架持續時間中位數）** 為 0.9 分鐘：這才反映人類真正停留在某個工作脈絡的時間。

透過編譯規則，系統能區分「真正的短暫專注片段」、「單一快照經過（single-snapshot transits）」以及多螢幕造成的雜訊。這與中斷科學文獻中「三分鐘工作球體」與約 19 秒切換一次的發現相呼應。

##### 問答準確率

研究設計了一個獨立的 **independent oracle（獨立參考標準）** 來評估智慧體對當日活動問題的回答正確性。結果顯示：

- 讀取編譯後活動框架的準確率為 **98.4%**，**Wilson 95% CI（Wilson 95% 信賴區間）** 為 91.7–99.7%。
- 直接對相同擷取內容做 **LLM summary（LLM 摘要）** 的準確率僅 66–80%。
- 使用 **mid-tier model（中階模型）** 讀取編譯區塊，表現可與 frontier model（前沿模型）相當。

這說明瓶頸不在模型大小，而在輸入表示：一旦把雜訊去除、結構化後，較小模型也能達到高階模型水準。論文也指出「更強的模型能縮小但無法完全消除差距」，暗示殘餘錯誤可能來自綱要覆蓋範圍或邊界案例，而非推論能力。

##### 成本模型：R 與 h

這是本文較具原創性的實證貢獻：

- **R = 60–343×**：這是 **modeled upper bound（模型化上界）**，表示若智慧體每次都用 frontier inference 重新推導人類已做過的例行程序，其成本可能是人類執行成本的數十倍到數百倍。
- **h = 9.0% in-sample（樣本內）**、**7.7% out-of-sample（樣本外）**：可被委派的例行程序比例約 7–9%。
- 綜合 R 與 h，得到 **realistic all-fleet token ceiling（全機群權杖上限）** 約 **8%**：即使把全部可委派例行程序都交給智慧體，整體 fleet 的 token 開銷也有一個實際上限。

值得注意的是，h 僅個位數百分比，顯示並非所有人類活動都適合自動化；這對過度樂觀的 agent-cost 預測是一劑冷靜劑。另一方面，對於符合 **guard-matched hit（守衛匹配命中）** 的已編譯例行程序，重播時可達 **zero model tokens（零模型權杖）**，展現出明確的成本節省潛力。

#### 與現有研究的比較

##### 模型在迴路內的記憶建構

2025–2026 年出現一波以模型為核心的連續螢幕記憶系統：**MIRIX** 使用多智慧體與雲端模型呼叫；**FOCAL** 使用本地 VLM 為擷取內容寫工作階段摘要；**ProAgentBench** 在應用程式切換後進行模型標註；**SummAct** 用 LLM 把互動軌跡摘要成意圖；**OmniQuery** 則擴增個人媒體以支援問答。這些方法的共同點是「模型坐在記憶建構迴路內」，因此繼承了 **per-run cost（每次執行成本）**、**non-determinism（非確定性）** 與可能產生虛構情節的風險。

本研究的 **Activity Frames（活動框架）** 是這些方法的確定性對位：編譯路徑無模型，輸出可快取、可稽核；推論被隔離在第二層綱要，並且必須附帶證據指標。這是首次把「擷取層」以確定性方式實作成情節記憶系統的桌面實例。

##### 桌面活動結構化

早期研究如 **TaskTracer** 與 **SWISH** 已嘗試從視窗標題與切換行為推導任務結構；中斷科學則量化了工作碎片化。本研究與它們的關係在於：它不僅測量行為節奏，還把節奏轉換成智慧體可直接使用的結構化記憶，並且提供公開的編譯器與評估框架。

##### 優勢與侷限

**主要優勢：**

- 零模型帶來確定性、可重現性與低成本。
- 86× 壓縮率與 68 ms 編譯速度適合即時應用。
- QA 準確率顯著優於原始資料與 LLM 摘要。
- 首次從真實人類活動測量 R 與 h，補足 agent-cost 模型長期缺少的實證參數。

**主要侷限：**

- 單一使用者、專業人士語料，代表性有限；不同職業、不同使用模式的 R 與 h 可能差異很大。
- 確定性規則雖然穩定，但對語意複雜或跨應用程式的隱性任務可能捕捉不足。
- 重播需要穩定的 UI 環境與正確的 guard 條件，實際部署中 UI 變化可能降低命中率。
- 雖然資料處理在本地，但被動螢幕擷取本身涉及隱私與監控議題，需要強大的同意與存取控制機制。
- R 是模型化上界，不等同於真實部署中的實際開銷；h 也會隨使用者與時間變動。

#### 可重現性評估

本研究在可重現性方面表現良好。論文明確指出 **schema（綱要）**、**compiler（編譯器）** 與 **evaluation harness（評估框架）** 皆已開源。編譯器以 dependency-free Python 實作，包含：

- 一個本地擷取引擎（local capture engine）。
- 命令列介面（CLI）。
- 一個 **Model Context Protocol（MCP，模型上下文協定）** server，對任何支援 MCP 的智慧體暴露六個工具。

由於輸出是 byte-identical（位元組一致），研究者可以在不同機器上重跑相同輸入並比對結果，這對記憶系統的審計與除錯非常有價值。

然而，可重現性仍有兩個挑戰：

1. **原始語料庫未公開**：這是個人螢幕擷取資料，涉及高度隱私，論文不太可能釋出完整 raw rows（原始資料列）。因此外部研究者無法直接複製 128,756 框架的數值，只能在自己的擷取資料上重跑。
2. **模型與評估細節**：雖然評估框架開源，但問答基準的 oracle 建構、prompt 設計與模型選擇等細節，仍需參照釋出文件才能完整重現。

整體而言，這是一個「工具與方法論開源、但個人資料不公開」的合理模式，符合隱私保護與科學再現之間的平衡。

#### 未來研究方向

1. **多使用者與 fleet-scale 測量**  
   在更多職業、更多使用者上測量 **Routine Overhead Ratio R（例行開銷比率 R）** 與 **routine recurrence h（例行重現率 h）**，建立 R/h 的分布基準，並探討其與職業、工作型態的關係。

2. **即時串流編譯**  
   目前編譯似乎是批次處理單日資料。未來可發展成持續串流編譯，讓智慧體在活動發生當下就能取得更新後的 **agent memory（智慧體記憶）**。

3. **跨裝置與跨平台擴展**  
   把 Activity Frames（活動框架）從桌面擴展到瀏覽器分頁、行動裝置、IDE 外掛等，並處理不同平台間的同步與衝突。

4. **語意例行程序發現**  
   在確定性框架之上，加入輕量級的聚類或序列模式挖掘，自動發現重複出現的 routine（例行程序），而不必每次都依賴 frontier inference。

5. **推論層的校準與主動學習**  
   第二層綱要允許推論標籤，但未來可加入信心校準、主動學習與人類回饋機制，讓推論標籤在保持可稽核的前提下逐漸提升覆蓋率。

6. **隱私保護與聯邦式編譯**  
   研究如何在本地完成編譯後，以差分隱私或聯邦學習方式彙總 fleet 層級的 R/h 統計，而不洩漏個人 raw rows（原始資料列）。

7. **重播魯棒性**  
   開發對 UI 變化、解析度變化、應用程式版本更新更具魯棒性的 replay（重播）機制，例如結合視覺定位或 Accessibility Tree 的穩定識別碼。

8. **標準化公開基準**  
   建立一個去識別化、可公開下載的 screen-activity QA 基準，讓不同團隊能在相同條件下比較 raw search、LLM summary 與 Activity Frames（活動框架）的表現。

9. **混合式管線**  
   探索「確定性編譯 + 輕量 LLM 後處理」的混合架構：用 Activity Frames（活動框架）提供穩定骨架，再用小型模型進行語意摘要或意圖標註，兼顧確定性與語意豐富度。

10. **實際部署的成本與延遲測量**  
    把模型化上界 R 轉換成真實世界中的金錢成本、延遲與能源消耗，並在生產環境中驗證 **guard-matched hit（守衛匹配命中）** 的命中率與節省效益。

## 論文問答

**Q1：本文要解決的核心問題是什麼？為什麼現有的電腦使用智慧體會浪費前沿推論資源？**
A：本文指出，電腦使用智慧體在回答「我今天該優先處理什麼」這類問題時，只能看到對話紀錄、檔案或行事曆，卻無法看到使用者實際做過什麼。由於現有智慧體的記憶主要是對話記憶而非行為情節記憶，當使用者要求代理程式重複執行某項已經做過的例行工作時，智慧體必須動用完整的前沿大型語言模型重新推導整個流程。這種「重新發明輪子」的做法不僅消耗大量權杖與運算成本，也無法保證結果的正確性與一致性。

**Q2：為什麼直接將原始擷取資料列交給模型，或讓 LLM 摘要螢幕活動，都無法成為可信的智慧體記憶？**
A：原始搜尋策略會把數千筆快照資料列扁平地交給模型，讓模型自行負責工作階段化、去重複與持續時間計算，單日成本可高達十二萬六千多個權杖。LLM 摘要雖然能大幅壓縮，但繼承了摘要器的所有弱點：每次執行都有成本、輸出非確定性、長輸入下可靠性下降，甚至可能捏造從未發生的活動。兩者都無法產生可快取、可稽核、可信任的記憶，因此不適合作為長期智慧體的基礎設施。

**Q3：確定性編譯對智慧體記憶為何至關重要？**
A：確定性編譯確保相同的原始擷取串流總是產生位元組一致的活動框架，這讓記憶可以安全地快取、免費重建，並由機械化方式稽核。相較於 LLM 摘要每次執行可能產生不同結果，確定性輸出消除了版本不一致與幻覺風險，使代理程式能夠信賴記憶內容。此外，確定性也讓編譯結果成為可重播的例行程序基礎，為後續零權杖重播提供可能。

**Q4：什麼是活動框架？它們攜帶哪些關鍵資訊？**
A：活動框架是從螢幕擷取串流編譯而成的型別化、有界片段，代表使用者在特定應用程式或網站上的連續活動段落。每個框架記錄應用程式、網站、起訖時間、基於停留時間的活動時間、型別化頁面參考、輸入量，以及指回原始資料列的證據指標。這些結構化資訊讓智慧體無需重新推導，就能快速理解使用者做過什麼、做了多久、在哪些情境下進行。

**Q5：什麼是兩層綱要？為何要將測量事實與推論標籤分開？**
A：兩層綱要把活動表示分為測量事實層與推論標籤層：第一層只包含從擷取資料直接導出的確定性資訊，第二層才接受經過命名空間區隔、信心度標記並連結證據的推論標籤。這種設計避免讓模型的猜測污染核心事實，同時保留解釋性標註的空間。強制揭露覆蓋缺口與盲點也讓智慧體清楚知道哪些資訊是確定的、哪些只是推測，從而提升記憶的可信度。

**Q6：編譯器使用了哪些關鍵確定性規則？為什麼刻意不使用學習元件？**
A：編譯器運用停留時間歸因、工作階段間隙切分、閃爍合併、最近框架歸因、基於座標的點擊解析，以及完整 URL 到實體的型別化等規則，將原始快照轉換為活動框架。這些規則完全由資料庫與視窗演算法決定，不倚賴任何神經網路或語言模型，因此輸出可重現且無需每次付費推論。不使用學習元件也確保了輸出的可稽核性，讓開發者能夠追蹤每一筆框架對應到哪些原始資料列。

**Q7：實驗語料庫的規模為何？編譯器在壓縮與速度上達到什麼效果？**
A：論文使用一位專業人士在 61 天內產生的語料庫，其中包含 51 個活躍日、共計 128,756 個活動框架。編譯器能將一整天的原始擷取資料壓縮成提示就緒上下文區塊，體積縮小 86 倍，且單日完整編譯僅需 68 毫秒。這種高效率讓智慧體可以在對話開始前即時載入數週的行為情節記憶，而不必每次查詢都重新處理原始快照。

**Q8：下游問答基準測試的結果如何？與 LLM 摘要和不同模型層級相比有何差異？**
A：在針對當天活動的問答任務中，智慧體讀取編譯後的上下文區塊達到 98.4% 的準確率，Wilson 95% 信賴區間為 91.7% 至 99.7%，顯著優於讀取原始資料列或 LLM 摘要的表現。相較之下，直接對同一批擷取資料進行 LLM 摘要的準確率僅有 66% 至 80%。值得注意的是，中階模型讀取編譯區塊即可達到與前沿模型相當的水準，這表示活動框架能有效彌補模型規模差距。

**Q9：除了問答準確率，論文還報告了哪些實證分析？**
A：論文驗證了編譯輸出的位元組一致性與可重現性，並分析了實體型別覆蓋率與框架持續時間分布。持續時間分布顯示，去除短暫切換後的中位數框架長度約為 0.9 分鐘，這與中斷科學中三分鐘工作領域的發現相呼應，也幫助區分真正的短暫專注與單一快照過渡。這些分析共同證明編譯器不僅壓縮效率高，也能保留對行為理解至關重要的時間結構。

**Q10：編譯器如何作為需求端成本工具？它測量了哪些過去未被量化的參數？**
A：編譯器可以從被動擷取的委派前人類活動中直接讀取成本模型所需的兩個參數：例行開銷比率 R 與例行重現率 h。R 代表智慧體重複執行已有人類例行程序的成本倍率，論文報告其模型化上界為 60 倍至 343 倍；h 則是可被代理程式接管的例行程序比例，樣本內為 9.0%，樣本外為 7.7%。這些數值讓我們首次能以真實人類活動為基礎，估算整體代理程式艦隊的權杖消耗上限，論文估計約為 8%。

**Q11：什麼是例行重播？「守衛匹配命中時零權杖」在實務上代表什麼？**
A：例行重播是指將已編譯的例行程序在相同或相似環境中重新執行，由於編譯輸出是確定性且結構化的，重播過程可以完全不經過語言模型。當目前情境與已編譯例行的守衛條件匹配時，系統可以直接按框架記錄的步驟執行，實現零模型權杖消耗。這意味著對於重複性工作，代理程式無需每次都進行昂貴的前沿推論，從而大幅降低長期運營成本。

**Q12：這項工作在產品與架構層面有什麼意涵？**
A：論文提供開源的綱要、編譯器與評估框架，並透過 Model Context Protocol 伺服器公開六個工具，讓任何支援 MCP 的智慧體都能讀取與重播活動框架。這種設計讓行為情節記憶成為可插拔的基礎設施，而非綁定於特定模型或應用。對產品而言，這代表可以在保護隱私的本地端完成記憶編譯，同時讓不同層級的模型都能獲得一致且高品質的上下文。

**Q13：本文承認哪些主要限制？**
A：論文的實證評估主要基於單一專業人士的單使用者語料庫，雖然規模達到數十萬框架，但無法代表所有使用者族群或工作型態。此外，可委派重現率與例行開銷比率的數值來自特定個案，在不同產業、角色或軟體生態中可能有所差異。因此，這些結果應被視為首批實證測量而非最終普適結論，未來需要更多樣化的語料庫來驗證。

**Q14：編譯器可能在哪些情況下失敗或產生覆蓋缺口？**
A：當原始擷取串流本身缺少關鍵事件、取樣間隔過長，或應用程式視窗標題與 URL 無法清楚識別活動語義時，編譯器可能產生覆蓋缺口或錯誤的框架邊界。對於高度創意、非重複或涉及多個未擷取裝置的工作流程，框架可能無法完整捕捉意圖與因果關係。兩層綱要雖然強制標示盲點，但這並不意味著所有缺口都能自動修復，部分情況仍需人類標註或額外感測器補充。

**Q15：未來可以朝哪些方向延伸這項研究？**
A：未來可以擴展到多使用者、跨裝置與跨作業系統的語料庫，以驗證編譯規則在不同情境下的泛化能力。另一個方向是將活動框架與主動式智慧體更緊密整合，讓代理程式不僅能讀取記憶，還能根據框架中的證據指標主動確認或修正執行步驟。此外，可以進一步研究如何自動學習新的編譯規則或框架型別，同時仍保持確定性與可稽核性，以適應不斷演變的桌面應用生態。

## 實務應用指南

### 適用場景

1. **個人生產力助理的「行為情節記憶」**  
   將使用者一天的螢幕活動編譯成活動框架後，電腦使用智慧體無需每次都用前沿模型重新推論「主人上午在處理哪張 PR、下午切換了幾次上下文」。代理程式直接讀取提示就緒上下文區塊，回答當日優先事項、尋找未完成的草稿、或接續中斷的工作流程。

2. **企業內部標準作業程序（SOP）的自動萃取與重播**  
   記錄資深員工在特定應用程式與網站上的操作序列，編譯成已編譯例行程序。新進員工或代理程式可在守衛匹配命中時，以零模型權杖成本重播相同步驟，例如填寫固定表單、執行例行報表匯出。

3. **代理程式成本與接管潛力的需求端評估**  
   在被動擷取的人類活動語料庫上，直接量測例行開銷比率 R 與例行重現率 h，回答「我們真的該把這類工作交給智慧體嗎？」以及「全機群權杖上限會被吃到多少？」，避免僅憑直覺擴大代理程式部署。

4. **可機械化稽核的合規與資安紀錄**  
   由於編譯器輸出位元組一致、可快取，且每個活動框架都帶有指回原始資料列的證據指標，適合需要說明「某時段使用者確實在哪些應用程式、停留多久」的稽核情境，例如特權帳號操作軌跡或工時佐證。

5. **IT 支援與知識庫問答**  
   把使用者過去遇到的問題與排解過程編譯成結構化片段，支援「上週三那個報錯視窗後來怎麼處理的？」這類問題，準確率顯著高於直接對原始快照資料列或 LLM 摘要提問。

### 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **資料** | 連續或被動擷取的螢幕活動資料流，例如事件驅動擷取產生的快照資料列（時間戳、應用程式、視窗標題、URL、滑鼠／鍵盤輸入量）。論文使用單使用者語料庫 128,756 框架，建議至少累積數週資料以觀察例行重現率。 |
| **運算** | 編譯階段為零模型管線，僅需一般 CPU 與少量記憶體；論文單日編譯僅 68 ms。下游問答或重播可依需求選用中階或前沿模型，但編譯本身不需要 GPU 或雲端推論。 |
| **技能** | 熟悉 Python 與 JSON／SQL 綱要；能理解兩層式綱要（測量事實層與推論標籤層）；具備隱私與資安意識；若要让代理程式讀取，需了解 Model Context Protocol（MCP）工具註冊。 |
| **法律與倫理** | 必須取得被記錄者明確同意，並制定資料保留、去識別化與存取控管政策；螢幕擷取常含敏感個資，合規是部署前提而非附加步驟。 |

### 實作步驟建議

1. **建立本地擷取串流**  
   部署論文提供的本地擷取引擎，或對接現有自動化時間追蹤器、作業系統連續擷取 API，確保輸出包含時間、應用程式、視窗、URL、輸入事件等原始資料列。

2. **安裝並配置編譯器**  
   使用論文開源的 Python 編譯器，設定停留計分（dwell crediting）、工作階段間隙、閃爍合併（flicker merging）、最近框架歸因與座標點擊解析等規則，全部無需學習型元件。

3. **執行確定性編譯**  
   對單日或多日資料執行編譯，產生型別化活動框架；驗證位元組一致性——同一資料庫與視窗條件下重新執行應得到完全相同的輸出文件。

4. **分離測量與推論層**  
   只在第二層綱要加入推論標籤，並強制要求名稱空間、信心分數與證據指標；不讓推論汙染第一層的測量事實。

5. **建構問答與重播管線**  
   透過 MCP 伺服器把六個工具暴露給智慧體；先以獨立參考標準評估問答準確率，再於守衛條件匹配時啟動零權杖重播執行器。

6. **量測 R 與 h**  
   在樣本內與樣本外資料上計算例行開銷比率 R 與可委派重現率，推估全機群權杖上限，作為是否擴大代理程式接管的量化依據。

7. **產品化與監控**  
   將編譯輸出納入代理程式的提示就緒上下文區塊，設定快取與版本控制；持續監控覆蓋缺口與盲點，並保留人工覆核迴路。

### 潛在風險與注意事項

| 風險 | 說明與緩解 |
|---|---|
| **隱私與監控疑慮** | 螢幕擷取可能記錄密碼、私人訊息、醫療或財務內容。應採本地處理、加密儲存、最小權限存取，並讓使用者能隨時暫停或刪除紀錄。 |
| **確定性不等於真實性** | 編譯器輸出位元組一致，但僅反映「擷取到了什麼」；若擷取引擎遺漏視窗、取樣頻率不足，或使用者使用私人瀏覽模式，框架仍會出現覆蓋缺口。需把盲點列為文件必要元素。 |
| **推論層的幻覺風險** | 第二層的推論標籤可能錯誤命名活動意圖。緩解方式是強制名稱空間、信心分數與證據指標，並讓高風險決策保留人工確認。 |
| **過度依賴例行重現率** | h 僅表示「看起來會重複」，不代表「適合自動化」。某些活動涉及創意判斷或合規簽核，即使重複也不應無條件委派。 |
| **法律與勞資爭議** | 在企業場景部署前，需與法務、人資、工會或員工代表確認資料所有權、工時紀錄效力與監控邊界。 |
| **重播的環境漂移** | 已編譯例行程序重播時，若應用程式介面改版、URL 結構改變或權限不同，守衛匹配可能失效。需設計版本化與降級機制。 |

### 與其他技術的整合建議

- **Model Context Protocol（MCP）生態**  
  論文已提供 MCP 伺服器與六個工具，可直接讓任何支援 MCP 的智慧體讀取活動框架、查詢時序、觸發重播，無需額外自訂 API。

- **RAG 與向量資料庫**  
  把第一層測量事實視為結構化檢索來源，把第二層推論標籤與摘要向量化後存入向量資料庫；查詢時先取結構化框架，再視需要補充語意向量結果。

- **行事曆、郵件與任務管理 API**  
  將活動框架與 Google Calendar、Outlook、Notion、Jira 等對齊，可補強「會議前後做了什麼」的情境，並讓代理程式產生更貼近實際工作的優先建議。

- **現有時間追蹤與 SIEM 工具**  
  對接 Toggl、RescueTime、Splunk 或企業 SIEM，把自動化時間追蹤器的應用程式焦點事件轉換成活動框架，提升資料可解釋性與稽核價值。

- **代理程式框架**  
  無論使用 LangChain、AutoGen、OpenAI Agents SDK 或其他編排工具，都可把編譯後的提示就緒上下文區塊當作短期記憶注入，減少每次對話的前沿推論成本。

### 給不同背景讀者的閱讀建議

**初學者**：先從摘要與本指南的「適用場景」開始，理解「為什麼智慧體需要記住使用者做了什麼，而不只是說了什麼」。接著對照詞彙表掌握活動框架、零模型管線、證據指標等核心詞，最後再看第 3 節的兩層式綱要，就能建立整體輪廓。

**AI 工程師**：重點閱讀第 3～5 節的綱要設計、編譯規則與 MCP 實作。特別注意「測量事實層」與「推論標籤層」的分離、位元組一致性的實現方式，以及如何透過 MCP 工具把編譯結果餵給下游智慧體；這些是落地時最直接的技術細節。

**研究人員**：第 6 節的評估框架與第 7 節的需求端成本工具最值得深入。建議複現問答準確率實驗，並在不同語料庫上重新估計例行開銷比率 R 與例行重現率 h；論文開放的評估框架與編譯器為比較不同模型、不同使用者群體提供了標準化基礎。

**產品經理**：聚焦摘要中的 86× 壓縮率、98.4% 問答準確率與零權杖重播，評估 ROI 與使用者信任之間的平衡。同時務必把「隱私與同意」放在產品設計第一順位，並思考哪些場景適合自動重播、哪些場景只能作為輔助建議，避免過度擴大代理程式接管範圍。
