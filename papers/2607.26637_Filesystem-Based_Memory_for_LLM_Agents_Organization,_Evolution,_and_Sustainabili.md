# 大型語言模型智慧體的基於檔案系統的記憶：組織化、演進與永續性

**作者：** Sizhe Zhou、Sheldon Yu、Hui Wei 等 11 位作者

## ⚡ TL;DR

現有 LLM 智慧體雖以檔案系統作長期記憶，但從未驗證其能否隨規模成長而維持組織與效益。
本文以管理、搜尋、執行三角色共用記憶檔案系統，並在長對話與具身任務中變化形態、規模、工具與模型能力。
組織化雖約減半檢索成本，卻未提升答案品質；僅最強管理智慧體維持結構，工具集對儲存庫形態影響堪比換模型。

## 摘要翻譯

已部署的大型語言模型智慧體（LLM Agents）日益將其長期記憶（long-term memory）保存為檔案系統（filesystem）：一個由 Markdown 檔案（Markdown Files）構成的目錄樹（directory tree），智慧體本身透過通用檔案工具（generic file tools）對其進行讀取、寫入與重組。然而，相關研究多半忽略了這個媒介：既有系統設計專屬的記憶表示法（memory representations）並研究其上的檢索（retrieval），使得預設做法的兩項運作假設（working assumptions）未經檢驗：一是智慧體能否在記憶不斷累積、衝突與過時的同時，維持成長中儲存庫的組織化（organization）；二是這樣的組織化是否能帶來回報。我們首次針對大型語言模型智慧體的基於檔案系統的記憶（Filesystem-Based Memory）進行系統性探索。我們將此情境形式化為圍繞單一記憶檔案系統（memory filesystem）的三個角色：管理智慧體（management agent）負責整合與組織傳入內容（incoming content），搜尋智慧體（search agent）以引用來源（cited sources）回答查詢（queries），執行智慧體（execution agent）則提供任務軌跡（task trajectories），並將之提煉（distilled）為技能（skills），在單一儲存庫中統一陳述性記憶（declarative memory）與技能。橫跨長對話基準測試（long-conversation benchmarks）與具身任務（embodied tasks），我們改變記憶形態（memory shape）〔智慧體組織的階層（agent-organized hierarchy）、原文傾印（verbatim dump）、分塊檢索（chunk retrieval）〕、串流規模（stream scale）、工具組合（tool harness）〔沙箱化 Shell（sandboxed shell）、記憶工具式函數（memory-tool-style functions）、多樣化搜尋工具（varied search tooling）〕，以及管理智慧體與搜尋智慧體的強度，並在記憶成長過程中追蹤回答品質（answer quality）、成本（cost）與儲存庫健康度（store health）。組織化可靠換得的是搜尋經濟性（search economy）：當資料龐大時，經過組織的儲存庫大約可將檢索成本（retrieval cost）減半。然而，現今的智慧體未能兌現預設做法的承諾：在我們的成長研究（growth study）中，除最強管理智慧體（strongest management agent）外，其餘所有智慧體的組織化程度均會退化，且我們測試的所有智慧體都未能將組織化本身轉化為更好的回答。而模型並非影響儲存庫形態（store's shape）的唯一控制因素：單獨改變工具集（tool set）對儲存庫形態的影響，與更換模型一樣強烈。本研究將檔案系統的預設做法從一項假設轉變為智慧體記憶的設計空間（design space）。

### 核心貢獻（3～5點）
- 首次針對大型語言模型智慧體的基於檔案系統的記憶（Filesystem-Based Memory）進行系統性研究，將檔案系統預設做法從未經檢驗的假設轉化為可設計、可評估的設計空間（Design Space）。
- 提出圍繞單一記憶檔案系統（Memory Filesystem）的三角色形式化架構：管理智慧體（Management Agent）、搜尋智慧體（Search Agent）與執行智慧體（Execution Agent）。
- 在單一儲存庫中統一陳述性記憶（Declarative Memory）與可重複使用技能（Skills），並透過執行智慧體將任務軌跡（Task Trajectories）提煉為技能。
- 橫跨長對話基準測試與具身任務，系統性評估記憶形態（Memory Shape）、串流規模、工具組合（Tool Harness）與模型強度對回答品質、成本與儲存庫健康度的影響。
- 發現組織化可帶來搜尋經濟性（Search Economy），但現今智慧體難以維持組織化；同時工具集（Tool Set）對儲存庫形態的影響力與模型本身相當。

### 適合對象
從事大型語言模型智慧體長期記憶、檢索增強生成（RAG）或智慧體框架設計的研究人員與工程師；特別適合關注記憶儲存庫如何隨時間成長、組織與維持永續性的系統設計者、開發者，以及希望將檔案系統作為智慧體記憶媒介的實務應用團隊。

## 深度分析

#### 方法論解析

本研究將 Filesystem-Based Memory（基於檔案系統的記憶）從業界預設做法提升為一個可系統性研究的設計空間（Design Space）。其核心方法是圍繞單一 Memory Filesystem（記憶檔案系統）定義三個角色：Management Agent（管理智慧體）、Search Agent（搜尋智慧體）與 Execution Agent（執行智慧體）。這三個角色的職責劃分極簡，卻能對應到實際部署中的多種 harness（工具組合）配置。

Management Agent 負責將每筆傳入內容（Incoming Content）整合進 Directory Tree（目錄樹）結構的 Markdown Files（Markdown 檔案）中，並在記憶累積、衝突或過時時進行更新、調和與重組。Search Agent 則在回答 Query（查詢）時從檔案系統中檢索相關內容，並提供 Cited Sources（引用來源）。Execution Agent 負責產生 Task Trajectories（任務軌跡），這些軌跡再被 Management Agent 提煉為 Skills（技能），從而將 Declarative Memory（陳述性記憶）與 Procedural Content（程序性內容）統一在同一個 Unified Store（統一儲存庫）中。

研究設計了兩大實驗場景來驗證這個框架。第一個是 Conversational Memory（對話式記憶），使用 LoCoMo、PersonaMem 與 REALTALK 等 Long-Conversation Benchmarks（長對話基準測試），評估 Search Agent 能否在長期對話後正確回答問題並引用來源。第二個是 Procedural Memory（程序性記憶），使用 ALFWorld 這類 Embodied Tasks（具身任務）基準，評估 Execution Agent 在檢索到過去經驗提煉出的 Skills 後，任務成功率是否提升。

在變因控制上，作者系統性地改變四個維度：

1. **Memory Shape（記憶形態）**：比較 Agent-Organized Hierarchy（智慧體組織的階層）、Verbatim Dump（原文傾印）與 Chunk Retrieval（分塊檢索）三種儲存結構。
2. **Stream Scale（串流規模）**：觀察記憶內容從少量到大量累積時，儲存庫與檢索行為如何演變。
3. **Tool Harness（工具組合）**：比較 Sandboxed Shell（沙箱化 Shell）、Memory-Tool-Style Functions（記憶工具式函數）與 Varied Search Tooling（多樣化搜尋工具）對智慧體行為與儲存庫形態的影響。
4. **Backbone Model Capability（骨幹模型能力）**：改變 Management Agent 與 Search Agent 的模型強度，觀察能力差異如何影響 Organization（組織化）、Retrieval（檢索）與 Answer Quality（回答品質）。

評估指標同時涵蓋效果與成本：Answer Quality（正確性）、Cost（包含 rounds、tokens、content read）以及 Store Health（儲存庫健康度），後者特別關注早期記憶是否能在後續演進中存活、更新是否正確著陸、分類體系（Taxonomy）是否隨規模崩塌。這種「成長曲線而非端點」的評估方式，是本文方法論相較於過去研究的重要區別。

#### 實驗數據解讀

本研究的實驗結果可從五個研究問題（RQ1–RQ5）加以解讀，每個問題都在對話與技能兩個場景中獲得回答。

**RQ1：Organization 的實際形態**
結果顯示，當 Management Agent 被賦予組織任務時，它確實會建立以主題為基礎的 Directory Tree。但這個形態更像是模型能力的「簽名」，而非單純對資料規模的反應。隨著 Material（資料）增加，儲存庫傾向於 Consolidation（合併）而非 Sharding（碎片化）：階層會在資料夾、檔案與檔案內標題之間重新定位。最明顯的退化行為是「重組過程中無聲地濃縮內容」——除非加入明確的保存規則，否則 Management Agent 會在整理時遺失細節。這暗示 Organization 並非免費的結構紅利，而是需要被明確監督的過程。

**RQ2：Memory Shape 的價值**
沒有任何一種 Memory Shape 在所有情境下都勝出。Organization 最明確的收益是 Search Economy（搜尋經濟性）：當資料量變大時，有組織的儲存庫能將 Retrieval Cost（檢索成本）降低約一半。然而在正確性上，組織化本身並未穩定轉化為更好的答案。在 Skills 場景中，最佳形態會隨 Execution Agent 能力而翻轉：對強執行智慧體而言，Verbatim Dump 形式的完整軌跡最有幫助；對弱執行智慧體而言，經過提煉的指導性技能則更有效。這顯示 Memory Shape 的選擇必須與下游使用者的能力匹配，而非一概追求精簡或結構化。

**RQ3：Backbone Model Capability 的影響**
在對話場景中，Management Agent 的強度主要影響組織風格，而非直接提升答案品質；Search Agent 的強度則直接反映在回答表現上。但在寫入本身失敗時，模型能力會產生耦合效應：例如在某個基準中，Management Agent 對於已改變的偏好僅記錄為帶日期的更新，卻讓過時事實（Stale Facts）仍以現存特徵的形式保留；換用更強骨幹模型執行相同指令後，約可挽回一半損失。相對地，當儲存庫已能服務 Search Agent 時，單純升級模型並無顯著助益。在 Skills 場景中，能力更像是一道門檻：一旦跨過，儲存庫內容的重要性便高於執行模型的選擇。

**RQ4：Sustainability under Scaling**
在實驗所涵蓋的範圍內，儲存庫隨規模成長而變得更有用，累積經驗能部分替代 Execution Agent 的能力。Store Health 在兩個場景中大致穩定：對話式儲存庫傾向於早期建立少數檔案，之後只進行編輯而不刪除；技能儲存庫中早期記憶能夠存活，且強 Management Agent 傾向於維護既有檔案而非替換。然而 Organization 是較弱的一環：隨著多數儲存庫成長，對 Taxonomy Contract（分類體系契約）的遵循會衰退，僅有最強的 Management Agent 能維持。成本方面，每回合的整理成本並未下降，但維護良好的儲存庫相對於任務鏈產生的原始內容仍保持緊湊。唯一的規模相關負債是 Verbatim Dump 的「全數提供」式檢索，其 Retrieval Cost 會隨資料量線性增長。

**RQ5：Harness 的角色**
工具組合不僅是中性包裝。研究發現，增加工具會改變行為但不必然改變結果；而替換整組工具則會像替換模型一樣強烈地重塑儲存庫形態。具體方向與收益因場景而異：在長對話中，某些工具組合導致碎片化（Sharding）與檔案間連結；在技能場景中，某些工具組合則促進合併並帶來更好的表現。這意味著 Tool Harness 是設計 agent memory 時不可忽視的槓桿。

整體而言，實驗數據支持一個謹慎的結論：Filesystem-Based Memory 能夠在可測量的範圍內維持可用與健康，但其 Organization 收益主要體現在成本而非正確性，且維持組織化需要強大的 Management Agent 與適當的工具設計。

#### 與現有研究的比較

過去研究多聚焦於設計專用的 Memory Representations（記憶表示法），例如 OS-Style Paged Context（作業系統風格的分頁上下文）、Extracted Fact Stores（萃取事實儲存庫）、Temporal Knowledge Graphs（時態知識圖譜）、Self-Linking Note Networks（自我連結筆記網路）、Summary Banks（摘要庫）、Discourse-Unit Stores（話語單元儲存庫）與 Embedding-Organized Trees（嵌入向量組織的樹狀結構）。這些方法通常伴隨專屬介面與操作語義，研究重點在於 Retrieval 效能。本文則選擇研究業界實際採用的預設媒介——Filesystem——並將其視為一個尚未被系統檢驗的設計空間。

相較於學術上按項目操作的記憶機制（add、update、delete），本文強調對儲存庫「形狀」的操作：Management Agent 不僅寫入內容，還會移動、合併、分割與重新命名檔案與資料夾。相較於業界的背景整理機制（如 OpenAI 的 dreaming 或 Anthropic 的 Dreams），本文將整理工作放回 agent 本身，檢驗 agent 是否能在持續運作中自行維持組織化，而非依賴外部重建。

本文的主要貢獻在於：

- **統一視角**：將 Declarative Memory 與 Skills 放在同一個 Filesystem 中管理，並透過 Execution Agent 的軌跡提煉技能，形成閉環。
- **成長導向評估**：不只看最終表現，而是追蹤 Store Health 隨 Stream Scale 的變化。
- **工具即設計變因**：將 Tool Harness 從背景設定提升為影響儲存庫形態的核心變因。

然而本文也有明確限制。首先，實驗範圍仍屬於「可測量的長期範圍」，尚未達到數月甚至數年的真實部署規模。其次，Management Agent 的組織化能力高度依賴模型強度，這意味著在資源受限的場景中，Filesystem-Based Memory 的 Organization 可能難以維持。第三，研究發現 Organization 對 Answer Quality 的提升並不穩定，這對「結構化整理必然帶來品質提升」的直覺提出挑戰。最後，實驗主要使用公開基準，雖具代表性，但與真實世界長期使用者互動的複雜度仍有差距。

#### 可重現性評估

本研究使用的資料集均為公開資源：LoCoMo、PersonaMem、REALTALK 與 ALFWorld，這些 Long-Conversation Benchmarks 與 Embodied Tasks 基準在學界已廣泛使用，有利於其他研究者複現對話與技能兩大場景。模型方面，作者比較了不同強度的 Management Agent 與 Search Agent，雖未在提供的摘要與引言中明確列出模型名稱與版本，但從實驗設計推測應使用了可公開透過 API 存取的商用 LLM，這意味著其他研究者可在取得 API 權限後重現模型能力變因。

然而，目前提供的上下文並未包含原始碼、實驗腳本或模型權重的公開連結。Filesystem-Based Memory 的實作細節——例如 Management Agent 的 prompt、儲存庫初始化規則、Taxonomy Contract 的具體內容、各種 Tool Harness 的實作方式——對重現至關重要。若作者未在完整論文或附錄中釋出這些細節，則重現難度會顯著提高。此外，由於實驗涉及 agent 與檔案系統的長期互動，隨機性與模型 API 行為的變動也可能造成結果波動。

整體而言，本研究在資料集與評估指標上具備良好的可重現基礎，但實作層面的透明度將是決定社群能否真正複製與延伸此工作的關鍵。建議作者釋出實驗框架、prompt 模板與儲存庫健康度的評量腳本，以提升可重現性。

#### 未來研究方向

基於本文的發現，未來研究可沿以下方向深入：

1. **更強大的 Management Agent 與主動整理策略**
   既然只有最強的 Management Agent 能維持 Organization，未來可探索專門為記憶整理設計的模型架構或 fine-tuning 目標，例如學習偵測 Duplicates（重複項目）、Contradictions（矛盾）與 Stale Facts，並主動觸發重組。

2. **混合式 Memory Shape**
   本文發現不同形態適合不同能力組合。未來可設計動態混合系統：對高能力 Execution Agent 保留 Verbatim Dump，對需要指導的任務自動提煉 Skills，並根據查詢成本在兩者間切換。

3. **工具設計作為第一級研究對象**
   Harness 對儲存庫形態的影響與模型相當，未來可系統化設計 Memory Tool 的函數介面，例如加入「比較兩份記憶」、「合併檔案」、「標記過時」等結構化操作，並研究這些操作如何改變 agent 的整理行為。

4. **長期規模與真實部署研究**
   本文的成長研究仍在可控範圍內。未來需要在真實使用者互動中進行數週至數月的追蹤，觀察 Store Health、檢索成本與使用者信任如何隨時間演化。

5. **衝突解決與時間推理機制**
   實驗中發現偏好更新與過時事實並存的問題。未來可引入更明確的時間戳、版本控制與衝突解決協議，讓 Management Agent 能更可靠地調和矛盾記憶。

6. **多 agent 協作記憶管理**
   可將 Management、Search 與 Execution 三個角色分配給不同專精模型，形成多 agent 協作架構，並研究角色間的契約與溝通成本。

7. **人機協同的記憶策展**
   由於完全自動的 Organization 仍會退化，未來可研究人類在關鍵節點介入（例如確認重組、標記重要記憶）如何以最低成本維持儲存庫健康。

8. **理論模型與儲存庫動力學**
   本文提供豐富的實證觀察，但未建立形式化模型。未來可發展記憶儲存庫的動力學理論，預測在不同寫入速率、更新頻率與檢索模式下，Organization 何時會崩塌或穩定。

總結來說，Filesystem-Based Memory（基於檔案系統的記憶）已從一個被預設採用但未被檢驗的媒介，轉變為一個值得系統性設計的研究領域。本文的價值在於揭示：Organization 能帶來 Search Economy，但維持它需要強模型與好工具；未來的工作應在這個設計空間中繼續探索，讓 LLM Agents（大型語言模型智慧體）的長期記憶真正達到可持續、可信賴且高效檢索的目標。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於「基於檔案系統的記憶」這個在實際部署中愈來愈常見、卻鮮少被系統性研究的預設做法。過去的研究大多設計專屬的記憶表示法並研究其檢索，但對於檔案系統記憶的兩個運作假設——智慧體能否在記憶持續累積、衝突與過時的過程中維持組織化，以及這樣的組織化是否值得成本——幾乎沒有驗證。本研究首次把這個預設做法從假設轉變為可測量的設計空間，探討記憶儲存庫如何隨規模成長而演進與維持永續性。

**Q2：現有的客製化記憶表示法與外部整合機制為何不足以解決問題？**
A：現有的學術記憶操作通常只針對單一項目進行新增、更新或刪除，從不觸及儲存庫的整體形態，因此無法處理記憶分散、重複與矛盾等結構性問題。業界的外部整合機制（例如「dreaming」）雖然會在背景重建記憶，但這種做法游離於正在工作的智慧體之外，只能治標，無法回答智慧體本身能否主動維持組織化。結果是，檔案系統記憶的預設優勢——可檢視、可攜且原生階層式——雖被廣泛採用，卻缺乏關於其長期健康度的實證基礎。

**Q3：為什麼研究基於檔案系統的記憶具有重要性？**
A：檔案系統是當前許多部署型智慧體（如程式編寫智慧體與個人助理）的實際記憶媒介，因為它與智慧體已掌握的通用檔案工具自然銜接，並且具備可檢視與可攜的特性。它同時能統一存放陳述性記憶與程序性記憶（即技能），讓事實與經驗提煉出的可重複使用技能共存於單一儲存庫。如果預設假設不成立，隨著記憶成長，儲存庫將退化、檢索成本飆升，最終可能連無記憶基線都不如，因此亟需系統性研究來支撐設計決策。

**Q4：論文提出的核心形式化架構是什麼？**
A：作者將設定形式化為圍繞單一記憶檔案系統的三種角色：管理智慧體負責整合傳入內容並維持儲存庫組織化；搜尋智慧體負責查詢並以引用來源回答；執行智慧體則產生任務軌跡，這些軌跡再被提煉為技能。這三種角色的合約被刻意設計得極簡，以便對應到實際部署中的不同工具組合，甚至在某些編碼代理中可能由同一個模型兼任。透過這種分工，研究能同時檢視記憶的組織、檢索與程序性學習三個面向。

**Q5：實驗設計中的關鍵變因與衡量指標有哪些？**
A：研究系統性地變動四個主要變因：記憶形態（智慧體組織的階層、原文傾印、分塊檢索）、串流規模、工具組合（沙箱化 Shell、記憶工具式函數、多樣化搜尋工具），以及管理與搜尋智慧體的模型強度。衡量指標不僅包含回答品質，也包含成本（回合數、token 數、讀取內容量）與儲存庫健康度（早期記憶是否存活、更新是否正確著陸、分類體系是否維持）。這種「成長曲線」而非單一終點的評估方式，是理解記憶永續性的關鍵。

**Q6：相較於過去研究，本篇論文的方法論創新在哪裡？**
A：最主要的創新在於把「檔案系統作為記憶預設」從一個未經檢驗的前提，轉變為可操作的設計空間。作者不僅將陳述性記憶與技能統一在同一個儲存庫中，還強調追蹤儲存庫隨時間演進的形態與健康度，而不只是終點的正確率。此外，研究顯示工具組合同樣是塑造儲存庫形態的強力槓桿，這讓記憶設計不再只取決於模型能力，也取決於智慧體如何與檔案系統互動。

**Q7：實驗使用了哪些基準測試與任務？**
A：在對話記憶方面，研究採用了 LoCoMo、PersonaMem 與 REALTALK 等長對話基準測試，這些測試要求智慧體在長時間對話後仍能正確回答問題並引用來源。在程序性記憶方面，則使用 ALFWorld 這類具身任務，評估固定執行智慧體能否透過檢索過去任務軌跡提煉出的技能來提升成功率。這兩類設定分別對應陳述性記憶與技能記憶，讓研究能涵蓋記憶檔案系統的多元應用場景。

**Q8：關於組織化的價值，研究得到了哪些關鍵結果？**
A：研究發現組織化最明確的價值在於「搜尋經濟性」：當資料量龐大時，經過組織的儲存庫能將檢索成本大致減半。然而，在實驗中沒有任何智慧體能把組織化本身轉化為更高的回答品質，這顯示結構整理並非萬靈丹。在技能任務上，最佳記憶形態會隨執行智慧體的強度而翻轉：強大的執行智慧體適合使用完整的原文軌跡，而較弱的執行智慧體則更受益於已提煉過的指導性技能。

**Q9：模型能力與工具組合的消融實驗揭示了什麼？**
A：實驗顯示搜尋智慧體的模型強度會直接反映在回答品質上，而管理智慧體的強度則主要影響組織風格與儲存庫健康度。當管理智慧體能力不足時，儲存庫的分類體系會隨成長而侵蝕，只有最強的管理模型能維持穩定的階層結構。更令人意外的是，單純更換工具集對儲存庫形態的影響，幾乎與更換模型一樣強烈，這說明工具組合並非中性的包裝，而是記憶組織化的重要控制因素。

**Q10：哪些實際應用場景最能從基於檔案系統的記憶中受益？**
A：長期陪伴型個人助理、跨工作階段的程式編寫智慧體，以及需要持續從經驗中學習的自主智慧體，都是最適合的場景。這些應用都需要記憶跨越多次對話或任務，並且不斷吸收新資訊、調和衝突與過時內容。檔案系統記憶不僅與智慧體現有的檔案工具自然整合，也方便人類開發者檢視與除錯，這在實際產品部署中極具吸引力。

**Q11：對於產品化部署，論文提出了哪些設計考量？**
A：首先，必須根據目標權衡成本與正確性：若重視檢索經濟性，應投資於強大的管理智慧體與適當的階層組織；若執行智慧體本身很強，則可保留較完整的原文軌跡。其次，工具組合的選擇會直接塑造儲存庫形態，因此不能視為單純的介面包裝。最後，為了避免重組過程中無聲地壓縮或遺失內容，必須加入明確的保存規則，否則儲存庫健康度會隨時間下降。

**Q12：這項研究可能對整個領域帶來什麼影響？**
A：這項研究把檔案系統記憶從「預設做法」提升為值得深入設計的研究對象，促使學界與業界同時關注模型能力、工具設計與儲存庫形態三者的交互作用。它也示範了如何將陳述性記憶與程序性記憶統一在同一個可檢視、可演進的儲存庫中，為未來的長期記憶系統提供參考架構。整體而言，這項工作為「智慧體能否像大腦一樣持續組織與更新記憶」這個宏大問題，提供了可量測且可複現的實證起點。

**Q13：論文承認了哪些主要限制？**
A：研究涵蓋的時間範圍與串流規模雖然已具挑戰性，但仍屬於可被測量的範圍，尚未觸及數月或數年的超長期運作。實驗僅針對少數長對話基準與一項具身任務，工具組合與模型族群的覆蓋也有限。此外，即使在實驗範圍內，也只有最強的管理智慧體能穩定維持分類體系，這暗示現有模型距離完全自主的永續記憶仍有差距。

**Q14：研究中觀察到哪些退化或失敗行為？**
A：管理智慧體在重組儲存庫時，若未加入保存規則，會無聲地將內容濃縮，導致細節遺失。在偏好變更的場景中，部分管理智慧體無法一致地將變更記錄為帶日期的更新，反而讓過時事實繼續以「現存特質」的形式殘留。此外，隨著儲存庫成長，大多數智慧體對分類體系的遵循度會逐漸侵蝕，顯示組織化是記憶永續性中較脆弱的一環。

**Q15：未來研究可以朝哪些方向發展？**
A：未來可以發展更精細的保存規則與自動化重組觸發機制，讓智慧體在內容累積到某個門檻時才進行結構調整。也可以探索混合記憶形態，例如同時保留原文軌跡與提煉技能，並根據執行智慧體的能力動態選擇檢索來源。更長遠來看，需要將研究擴展到更長的時間跨度、多智慧體共享儲存庫，以及讓組織化真正轉化為更高回答品質的學習機制。

## 適用場景

1. **長期個人助理與客戶關係管理**  
   讓助理在數週到數月的對話中持續記住用戶偏好、過往事件與未完成的待辦事項。管理智慧體將每次對話內容整合進 Markdown 檔案，搜尋智慧體在回答時引用來源，避免「每次重新認識用戶」。

2. **程式編寫智慧體的跨 Session 記憶**  
   編碼代理在多次互動中累積架構決策、API 使用慣例與常見錯誤修復。將這些內容以檔案系統形式保存，可讓後續對話直接查閱先前寫下的筆記與技能，減少重複探索。

3. **企業內部知識的持續策展與問答**  
   把會議紀錄、產品規格、規範文件串流餵給管理智慧體，由它主動分類、合併重複主題、標記過時事實，形成可搜尋的目錄樹。員工透過搜尋智慧體提問並取得附帶出處的回答。

4. **具身任務與流程自動化的技能庫**  
   固定執行智慧體在環境中完成任務後，將任務軌跡提煉為可重複使用技能，存入同一個檔案系統儲存庫。後續遇到類似任務時，執行智慧體可直接檢索並套用已累積的程序性記憶。

5. **教育或輔導代理的長期學習檔案**  
   追蹤學習者的錯誤模式、進度與個人化建議。管理智慧體隨時間更新學習者輪廓，搜尋智慧體則在生成回饋時引用具體歷史紀錄，提升可信度。

## 實作前置條件

- **資料準備**  
  需要可長期累積的對話紀錄或任務軌跡；建議預先定義領域分類體系（taxonomy）與檔案命名規範，作為管理智慧體的初始結構。若涉及偏好或事實變更，需準備時間戳記與更新規則。

- **運算資源**  
  需可呼叫具備工具使用能力的大型語言模型；建議搭配沙箱化 Shell 或記憶工具式函數，讓智慧體能安全地讀寫、移動、搜尋 Markdown 檔案。若採用分塊檢索輔助，可額外配置向量資料庫與嵌入模型，但檔案系統仍應作為主要介面。

- **技能與團隊準備**  
  團隊應熟悉提示工程、代理工具呼叫、檔案系統操作，以及評估指標設計（回答品質、檢索成本、儲存庫健康度）。同時需要資料治理流程，以處理敏感資訊與隱私合規。

## 實作步驟建議

1. **界定記憶契約**  
   先決定要存放陳述性記憶（事實、偏好、規則）還是程序性記憶（技能），或兩者統一於同一儲存庫。

2. **設計最小工具集**  
   從通用檔案操作開始：讀取、寫入、移動、刪除、列出目錄、搜尋。避免一開始就引入過多專用記憶工具，以免限制儲存庫形態。

3. **建立初始目錄樣板**  
   提供預設的目錄樹與 Markdown 範本，例如 `people/`、`projects/`、`skills/`，讓管理智慧體有結構可循。

4. **實作管理智慧體**  
   讓它以「逐段整合」方式處理傳入內容：去重、調和矛盾、標記日期、必要時重組資料夾。務必加入**保存規則**，防止它在重組時無聲壓縮或遺失早期記憶。

5. **實作搜尋智慧體**  
   要求它在回答時引用具體檔案與段落，並根據問題選擇瀏覽目錄樹或直接搜尋關鍵字。

6. **加入技能提煉流程（若適用）**  
   讓固定執行智慧體產生任務軌跡，再由管理智慧體或獨立模組將軌跡蒸餾為可重複使用技能，存回檔案系統。

7. **建立成長監測儀表板**  
   持續追蹤回答品質、檢索成本（讀取 token 數、搜尋回合）、儲存庫健康度（檔案數量、階層深度、過時事實比例、早期記憶存活率）。

8. **迭代調整工具組與模型**  
   根據成長曲線而非單點表現做決策。若組織化侵蝕，可嘗試更強管理模型、調整工具集，或引入週期性外部重建作為備援。

9. **長期壓力測試後上線**  
   在真實規模的資料流上跑數輪，觀察儲存庫形態與檢索成本變化，再開放給終端使用者。

## 潛在風險與注意事項

- **組織化會隨規模侵蝕**  
  實證顯示，除了最強的管理智慧體外，多數代理難以長期維持分類體系。需定期稽核目錄樹，並把「維持階層」明確寫入提示。

- **無聲壓縮導致資訊遺失**  
  管理智慧體在重組時可能過度摘要。建議加入保存規則，例如「合併檔案時必須保留所有原始事實，僅允許重新分組」。

- **過時事實與矛盾**  
  偏好或狀態改變時，代理可能只追加新段落而未標記舊段落失效。應要求以日期標註更新，並在搜尋時優先採用最新資訊。

- **工具集並非中性包裝**  
  改變可用工具會顯著重塑儲存庫形態。新增或替換工具後，必須重新評估儲存庫健康度與檢索成本。

- **原文傾印的檢索成本線性增長**  
  雖然把完整對話傾印成檔案最簡單，但規模變大後檢索成本會急遽上升。組織化雖不一定提升答案正確性，卻能有效降低檢索開銷。

- **組織化不一定直接轉化為更好答案**  
  在對話任務中，答案品質更仰賴搜尋智慧體的能力；在技能任務中，則取決於執行智慧體強度與儲存內容的匹配。應根據目標選擇投入方向。

## 與其他技術的整合建議

- **向量資料庫作為輔助，而非取代檔案系統**  
  可用嵌入向量加速大規模關鍵字搜尋，但讓檔案系統維持主要介面，保留可檢視性與可攜性。

- **外部摘要與週期性重建機制**  
  可借鏡「dreaming」概念，定期在背景對整個儲存庫進行摘要或重建，作為代理日常維護的備援，而非完全依賴代理自行整理。

- **與版本控制整合**  
  將記憶檔案納入 Git 管理，方便人類審查變更、回滾錯誤更新，並追蹤儲存庫隨時間的演進。

- **結構化資料庫存放高頻更新事實**  
  對於經常變動的數值型狀態（如帳戶餘額、最新進度），可同步寫入傳統資料庫，檔案系統則保留脈絡與來源說明。

- **銜接現有 RAG Pipeline**  
  讓檔案系統成為 RAG 的主要知識來源，搜尋智慧體負責路由查詢、選擇檔案，再將相關段落餵給生成模型。

- **可觀測性工具**  
  接入日誌與監控系統，持續追蹤管理智慧體的寫入行為、搜尋智慧體的檢索路徑，以及儲存庫健康度指標。

## 給不同背景讀者的閱讀建議

**給初學者：**  
這篇論文把「讓智慧體像人類整理筆記一樣管理記憶」這個預設做法攤開來檢驗。你可以先聚焦在「管理智慧體、搜尋智慧體、執行智慧體」三個角色，以及為什麼用 Markdown 檔案與目錄樹來儲存記憶，不必急著深入統計細節。

**給 AI 工程師：**  
重點在於工具契約與模型能力的權衡。你會看到工具集如何形塑儲存庫形態、管理智慧體的強度如何影響組織化品質，以及為什麼評估必須看「成長曲線」而非單點正確率。建議把論文中的監測指標直接套用到你的代理系統。

**給研究人員：**  
本文提供了一個可擴展的實證框架，適合進一步探討組織化的價值、模型能力與工具設計的交互作用，以及長期永續性的機制。特別值得追蹤的問題是：在什麼條件下，智慧體能將檔案系統的結構優勢真正轉化為更好的推理與決策。

**給產品經理：**  
這份研究提醒你不要預設「讓 AI 自動整理檔案就一定更好」。組織化最穩定的回報是降低檢索成本，但不一定提升答案品質；產品設計上應預留人工稽核與週期性重建的預算，並把儲存庫健康度當成與準確率同等重要的上線指標。
