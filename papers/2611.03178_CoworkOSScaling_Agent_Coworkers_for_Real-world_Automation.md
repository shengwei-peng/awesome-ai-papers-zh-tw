CoworkOS 的核心設計理念建立在「任務策略（task strategy）」與「執行管理（execution management）」的分離原則之上，這是一種將認知決策與系統運行解耦的架構哲學。整個系統採用三層代理框架（three-layer agent framework），由 Main Agent、Coordinator Runtime 與可選的 Subagents 組成，形成清晰的責任分工。

**Main Agent（主代理）** 作為頂層決策者，負責制定整體任務計畫、分解工作、選擇執行策略（直接執行或委派），並評估最終產出的工件（artifacts）品質。這種設計讓模型本身保有自主決策權，而非被硬編碼的工作流程所限制。

**Coordinator Runtime（協調器執行環境）** 扮演運行時中樞的角色，負責分派子任務、監控 Subagents 的生命週期、維護狀態與回饋機制。這層抽象使得長時程任務（long-horizon tasks）的持續監控與決策成為可能，Subagents 可以在其監管下維持長時間運行而不會遺失上下文。

**Subagents（子代理）** 在被指派的上下文與資源範圍內執行具體任務，使用工具並做出局部決策。這種階層式設計支援兩種互補需求：透過集體智慧（collective intelligence）處理複雜生產力任務，同時透過 Coordinator 維持長時程監控能力。

在**人機協作（human-in-the-loop）** 方面，CoworkOS 構建了一個可擴展的應用生態系統，涵蓋 CLI 執行、搜尋、檔案操作、MCP 介面等基礎工具，並延伸至文件編輯器、PPTist、CAD、Blender 等專業應用。其獨特之處在於「共用應用物件（shared application object）」概念——人類與代理可檢視並修改同一份演進中的文件、模型或場景，使人類參與能透過對話與直接修改工件兩種途徑融入自主執行流程。

為維持跨代理與跨會話的連續性，系統引入兩項關鍵機制：**階層式工作區（hierarchical workspaces）** 讓代理可檢視並重用彼此的工作檔案與候選工件；**持久化語意記憶（persistent semantic memory）** 記錄關鍵決策、約束條件與未完成工作；**長時間運行的 Job** 則保留狀態與日誌，使工作中斷後可被準確接續。

#### 與現有研究的比較

CoworkOS 將代理系統的演進劃分為三個漸進階段：**Agent Workflow**（如 Chain-of-Thought、Tree-of-Thoughts、ReAct、Reflexion、DSPy、AFlow、MetaGPT）→ **Agent Assistant**（如 LangChain、LangGraph、AutoGen、OpenClaw）→ **Agent Cowork**（如 Claude Code、Codex、OpenHands、DeepSeek Harness、Kimi Code、ZCode、Qoder、Hermes Agent）。這個分類框架揭示了 CoworkOS 的定位：它並非要取代既有系統，而是試圖在「複雜生產力任務」與「持續監控決策」兩個維度上同時達到前沿水準。

#### 未來研究方向

基於 CoworkOS 的設計理念與實驗結果，可識別以下值得探索的研究方向：

**1. RSI 的長期穩定性與安全性**：五輪迭代已展現可行性，但遞迴自我改進在更長時間尺度下是否會偏離預期目標、產生獎勵 hacking（reward hacking）或對齊漂移（alignment drift），是邁向 ASI 的關鍵議題。未來可研究形式化驗證（formal verification）與人類監督介入點的設計。

**2. 跨代理通訊協議標準化**：目前 CoworkOS 的 Subagent 委派機制為內部設計，若能發展類似 MCP（Model Context Protocol）的開放標準，將促進異質代理間的互操作性，推動「代理經濟（agent economy）」的形成。

**3. 語意記憶的理論基礎**：持久化語意記憶目前以工程實作為主，缺乏關於「哪些資訊值得記憶」、「記憶如何隨時間衰減」、「跨任務記憶遷移」的理論框架。可借鑑人類認知科學中的遺忘曲線（forgetting curve）與情節記憶（episodic memory）研究。

**4. 人機協作的細粒度控制**：當前「共用應用層」允許人類直接修改工件，但缺乏對修改意圖的語意理解機制。未來可探索人類操作的可解釋性（interpretability）——系統是否能理解「人類刪除了某段程式碼是因為發現了 bug，還是改變了設計方向」。

**5. 領域專屬 Cowork 模式**：CoworkOS 展現了通用性，但在 Harvey LAB 等專業領域表現仍有提升空間。針對法律、醫療、工程等垂直領域的 Cowork 客製化，以及領域專家知識如何融入 Subagent 的決策過程，是重要的應用研究方向。

**6. 效率與品質的權衡**：三層架構的協調開銷對於簡單任務可能不經濟，未來可研究自適應架構（adaptive architecture）——根據任務複雜度動態選擇單代理直接執行或多代理協作模式，以優化計算資源使用。

**7. 評估方法的革新**：現有基準測試多聚焦於單輪任務完成度，難以衡量長時程協作品質。需發展新的評估維度，如「跨會話連續性」、「人類介入後的恢復能力」、「工件演進的可追溯性」等指標，以更全面地評估 Cowork 系統的真實價值。

當人類直接修改工件而未透過對話告知代理時，可能造成代理決策與工件狀態脫節。**緩解方式**：在共用應用層加入變更通知機制，強制代理在關鍵修改後重新讀取工件狀態。

### 風險四：Subagent 委派的責任邊界模糊
若 Main Agent 與 Subagents 的職責劃分不清，可能出現重工或遺漏。**緩解方式**：明確定義 Coordinator 的派工契約與驗收標準，並記錄每次委派的決策依據。

### 風險五：自動化後訓練的評估偏差
RSI 驅動的自動化後訓練若僅針對少數基準優化，可能產生過擬合。**緩解方式**：維持多元基準組合（如論文的 8 個基準平均），並定期以保留集驗證泛化表現。

## 與其他技術的整合建議

### 與 LangGraph / AutoGen 整合
CoworkOS 的三層架構可與 LangGraph 的狀態圖或 AutoGen 的多代理對話機制互補。建議將 LangGraph 用於 Subagent 內部的推理-行動迴圈，AutoGen 用於跨 Subagent 的協商對話，而 CoworkOS 的 Coordinator Runtime 負責更高層級的派工與監控。

### 與 MCP（Model Context Protocol）整合
論文中提及 MCP 介面作為基礎工具能力，建議將企業內部的專業工具（ERP、CRM、CAD）封裝為 MCP 伺服器，讓 CoworkOS 的 Subagents 能即插即用。

### 與既有 RAG 與語意記憶系統整合
CoworkOS 的持久化語意記憶可與向量資料庫（如 Milvus、Weaviate）整合，將關鍵決策、約束與未完成工作編碼為可檢索的語意片段，支援跨 session 的知識延續。

### 與 CI/CD 與 MLOps 平台整合
將 CoworkOS 的 Jobs 與日誌接入 CI/CD 流程（如 GitHub Actions）或 MLOps 平台（如 MLflow），讓代理執行的訓練、評估與部署可被追蹤與審核。

### 與人類協作工具整合
將共用應用層與企業協作平台（如 Notion、Confluence、Figma）對接，使人類可在熟悉的介面中檢視與修改代理產出的工件，降低採用門檻。
