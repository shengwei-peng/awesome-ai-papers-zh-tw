## ⚡ TL;DR

本文探討網站能否透過被動觀察UI軌跡辨識LLM瀏覽器代理程式的底層模型身份。

## 摘要翻譯

隨著 LLM 瀏覽器代理程式 (LLM browser agents) 日益代為瀏覽網頁，一個自然的問題隨之浮現：網站能否以被動方式識別驅動代理程式的底層模型 (underlying model)？這將構成重大的安全性風險，使攻擊者得以依已知模型漏洞 (model vulnerabilities) 量身打造針對性攻擊 (targeted attacks)。我們在 14 個前沿大型語言模型 (frontier LLMs) 與四個網頁環境 (web environments) 中（涵蓋資訊檢索 (information retrieval) 及購物任務 (shopping tasks)），證明透過被動式 JavaScript 追蹤器 (passive JavaScript tracker) 所擷取的代理程式動作與時間特徵 (action and timing features)，足以識別底層模型，宏觀 F1 分數 (Macro F1) 高達 96%。我們透過證明以代理程式動作訓練的分類器 (classifiers) 可跨不同模型尺寸與家族 (model sizes and families) 泛化，將此攻擊面形式化。我們進一步證明，僅需少量互動軌跡 (interaction traces) 即可訓練出效能良好的分類器，且代理程式身份可於回合 (episode) 早期推論 (inference) 得出。在動作間注入隨機化時間延遲 (randomised timing delays) 雖能大幅削弱分類器效能，但無法提供穩健防護：以延遲軌跡重新訓練的分類器可大幅恢復效能。我們公開釋出實驗框架 (harness) 與代理程式軌跡的標註語料庫 (labelled corpus)：https://github.com/KabakaWilliam/known_actions（詳見此處）。

### 核心貢獻（3～5點）
- 僅憑被動式 JavaScript 追蹤器擷取的動作與時間特徵，即可識別代理程式的底層模型，宏觀 F1 分數高達 96%。
- 以代理程式動作訓練的分類器可跨不同模型尺寸與家族泛化，顯示攻擊面具備強健的通用性。
- 僅需少量互動軌跡即可訓練出高效能分類器，且能在回合早期推論代理程式身份。
- 隨機化時間延遲雖可暫時削弱分類器，但無法提供穩健防護：以延遲軌跡重新訓練後，分類器效能可大幅恢復。
- 公開釋出實驗框架與代理程式軌跡的標註語料庫，以利後續研究與防禦設計。

### 適合對象
對 LLM 代理程式安全性、網頁隱私與自動化客戶端辨識有興趣的研究者與工程師；特別適合關注瀏覽器代理程式威脅模型、對抗式機器學習，以及欲設計有效防禦機制之資安社群與模型開發者。

## 深度分析

#### 方法論解析

本研究將 LLM 瀏覽器代理程式（LLM browser agents）的識別問題形式化為一個監督式分類（supervised classification）任務，其輸入為單一網域內的互動軌跡（interaction traces），輸出則為底層模型（underlying model）的預測身份（predicted identity）。具體而言，代理程式（agent）透過固定的瀏覽器實驗框架（browser harness）與網頁環境（web environment）互動，在每個時間步（timestep）根據當前畫面觀察（observation，即渲染後的截圖）產生動作（action），例如點擊（clicks）、捲動（scrolls）、按鍵（keypresses）等。研究團隊將一次完整的瀏覽任務定義為一個回合（episode），並將其記錄為一連串的 UI 軌跡（UI traces）：

τ = {(s_t, u_t, Δt_t)}_{t=1}^T

其中 Δt_t 為事件間隔（inter-event interval），即連續動作之間的經過時間。值得注意的是，作者刻意限制分析僅使用客戶端（client-side）的行為軌跡（behavioural traces），完全不採用瀏覽器屬性與標頭（browser attributes and headers）等靜態特徵，以避免這些容易被偽造（spoofed）的訊號。

在威脅模型（threat model）方面，本研究假設的是被動式共置敵手（passive co-located adversary），也就是控制目標網站的站方營運者。該敵手透過注入式 JavaScript（injected JavaScript）在被造訪的頁面中植入被動式 JavaScript 追蹤器（passive JavaScript tracker），被動地記錄代理程式的動作時間軸（action timeline）與事件間隔，無需任何網路層級的可見性（network-level visibility）。這與傳統的網路流量側通道攻擊（side-channel attacks）有本質區別：敵手的程式碼與受害者運行於同一環境（co-located），直接收集 UI 層級的動作與時間特徵（action and timing features）。

分類器（classifier）的設計上，作者選用輕量級的 XGBoost 模型，將動作類型與其時間動態編碼為特徵向量，學習不同前沿大型語言模型（frontier LLMs）在導航與互動時展現的時間與結構動態（temporal and structural dynamics）。由於所有實驗代理程式共用相同的動作空間與瀏覽器實驗框架，任何可區分的行為差異都可歸因於基礎模型（foundation model）本身，而非執行環境或工具配置。

在防禦分析（defence analysis）部分，作者評估了隨機化時間延遲（randomised timing delays）作為防禦機制的有效性，即在動作之間注入隨機的停頓以破壞時間指紋。實驗顯示，這種標準的瀏覽器常規化（browser normalisation）確實會顯著降低分類器效能，但若敵手以延遲後的軌跡重新訓練分類器，效能便會大幅恢復。

#### 實驗數據解讀

本研究橫跨 14 個前沿大型語言模型與四個網頁環境（web environments），涵蓋資訊檢索（information retrieval）與購物任務（shopping tasks）兩大類型。核心評估指標為宏觀 F1 分數（Macro F1），在僅使用被動收集的 UI 軌跡（UI traces）作為輸入的情況下，最高可達 96% 的識別準確率。這項結果顯示，代理程式的行為軌跡（behavioural traces）本身就蘊含強烈的模型特定訊號，足以作為穩定的指紋辨識（fingerprinting）依據。

實驗進一步證明，訓練完成的分類器（classifier）具備跨模型尺寸與家族（model sizes and families）的泛化能力。這意味著即使面對同一模型家族中不同參數規模的變體，或是從未在訓練集中出現的模型版本，行為特徵仍能維持一定的區分度。此外，作者發現僅需少量互動軌跡（few interaction traces）即可訓練出強健的識別模型，顯示指紋訊號的密度很高，不需要大規模資料即可建立有效的攻擊管道。

在攻擊的即時性方面，研究指出代理程式身份可以在回合（episode）的早期階段就被推論（inference）出來。這對於敵手而言極具實務價值：站方營運者無需等待完整工作階段結束，就能在造訪過程中即時識別底層模型（underlying model），進而啟動針對性攻擊（targeted attacks），例如利用已知的模型漏洞（model vulnerabilities）發動越獄攻擊（jailbreaks）或縮小白箱對抗攻擊（white-box adversarial attack）的搜尋空間。

防禦實驗的數據則揭示了殘酷的現實：雖然隨機化時間延遲（randomised timing delays）能在短期內矇騙未經調適的分類器，但這並未提供穩健保護（robust protection）。一旦敵手將延遲後的互動軌跡納入重新訓練，分類器效能便會大幅回升。這暗示單純的時間擾動無法徹底抹除模型行為的結構性差異，僅能提高敵手的資料收集成本，而無法阻斷攻擊鏈。

#### 與現有研究的比較

傳統的機器人偵測（bot detection）與瀏覽器指紋辨識（browser fingerprinting）文獻多將問題框限為二元分類：人類使用者（human users）對上自動化客戶端（automated clients）或腳本化自動化（scripted automation）。本研究則進一步探問更細緻的問題：在已知客戶端為 LLM 瀏覽器代理程式（LLM browser agents）的前提下，能否僅憑其動作識別出底層模型（underlying model）？這將觀察點（observation point）從「是否為機器人」推進到「是哪一種模型」，大幅提升了指紋辨識的粒度。

相較於被動收集瀏覽器屬性與標頭（browser attributes and headers）以重新識別（re-identify）人類使用者的傳統技術，本研究的優勢在於不依賴靜態屬性。靜態屬性雖然規模化程度高，但容易被偽造（spoofed）或修改；而行為軌跡（behavioural traces）反映的是模型內部的規劃與決策動態，更難以透過簡單的參數調整來掩蓋。

在與 LLM 指紋辨識相關研究的對照上，Pasquini 等人採取主動探測（active probing）策略，透過發送精心設計的查詢並分析回應來識別模型版本。本研究則完全採用被動觀察：敵手無需發送任何特殊查詢，僅需在頁面中植入被動式 JavaScript 追蹤器（passive JavaScript tracker），記錄代理程式自然瀏覽產生的 UI 軌跡（UI traces）。這使得攻擊更隱蔽，且適用於任何正常造訪情境。

Zhang 等人的研究與本設定最為接近，他們證明任務導向的 LLM 代理程式會在網路流量中留下獨特的封包指紋。然而，Zhang 等人的攻擊屬於網路層級觀察（on-path），依賴工具呼叫產生的封包後設資料（packet-level metadata）。本研究則屬於被動式共置敵手（passive co-located adversary），僅利用頁面內的 UI 事件，且由於所有代理程式共用相同的瀏覽器實驗框架（harness）與動作空間，分類器直接鎖定基礎模型（foundation model）本身，而非特定的應用程式或工具配置。這顯示指紋攻擊的表面（attack surface）已從網路觀察者與主動探測者，擴展到被造訪的頁面本身。

本研究的主要限制在於，為了控制變異性，作者將互動軌跡限制在單一網域（single domain）內；此外，實驗假設所有代理程式使用相同的瀏覽器實驗框架，這在生產環境（production）中可能不盡相同，因為不同服務商可能採用客製化的前端介面或動作空間。最後，作為一份預印本（preprint），部分實驗細節（如完整的特徵工程流程或錯誤分析）在提供的文本中尚未完全展開。

#### 可重現性評估

本研究在可重現性（reproducibility）方面表現突出。作者公開釋出了瀏覽器實驗框架（browser harness）以及一個標註語料庫（labelled corpus），其中包含於四個網頁環境中收集的代理程式互動軌跡（agent interaction traces），並已標註對應的底層模型身份。該實驗框架相容於閉源與開源 LLM（closed and open-source LLMs），這對於後續研究行為歸因（behavioural attribution）至關重要，因為它允許其他研究者以相同的設定比對不同模型的軌跡特徵。

然而，由於實驗對象為前沿大型語言模型（frontier LLMs），這些模型多為商業 API 服務，研究團隊無法釋出模型權重（model weights）。這意味著其他研究者若要完全重現 96% 宏觀 F1 分數（Macro F1）的結果，仍需自行取得這 14 個模型的 API 存取權限，並在相同的網頁環境中執行實驗框架。儘管如此，釋出的標註語料庫已足以讓社群直接訓練與驗證分類器（classifier），大幅降低重現門檻。整體而言，本研究在資料與工具層面的開放度，為 LLM 代理程式安全領域建立了良好的可重現基準。

#### 未來研究方向

首先，在防禦機制方面，未來研究可探索超越隨機化時間延遲（randomised timing delays）的策略。例如，在動作層級引入隨機化的動作選擇擾動、模擬人類使用者的神經肌肉結構（neuromotor structure）於滑鼠軌跡與捲動行為，或採用差分隱私（differential privacy）機制來模糊化行為軌跡（behavioural traces）中的模型特定訊號。關鍵挑戰在於設計能夠抵禦「重訓練敵手」（retraining adversary）的防禦，因為本研究已證明單純的時間擾動可被輕易適應。

其次，目前實驗將軌跡限制在單一網域（single domain）以控制環境變異性，但未來可朝跨網域（cross-domain）與多頁面（multi-page）情境擴展，探討指紋訊號在複雜導航結構中的穩定性。此外，將方法從受控的網頁環境（web environments）推進到真實生產環境（production）的大規模部署，評估動態內容、反機器人機制（anti-bot measures）與多樣化使用者查詢對識別準確率的影響，亦是重要的實務方向。

第三，理論層面的探究同樣關鍵：為何不同基礎模型（foundation model）會產生獨特的時間與結構動態（temporal and structural dynamics）？這可能與預訓練資料組成、指令微調（instruction tuning）策略或視覺語言對齊（vision-language alignment）方式有關。建立理論模型來解釋這些行為差異的來源，有助於設計從根本上去除指紋的代理程式架構。

最後，隨著 LLM 瀏覽器代理程式（LLM browser agents）從研究原型（research prototypes）大規模進入生產環境，隱私保護導向的代理程式設計將成為顯學。未來可研究透過標準化中介層（standardized intermediate layers）或安全執行環境（secure enclaves）來隔離模型身份與可觀察行為，使得即使敵手完全控制頁面，也無法從 UI 軌跡（UI traces）中推論出底層模型，從而阻斷目標識別（target identification）與後續的漏洞利用（exploitation）。

## 論文問答

**Q1：這篇論文指出的 LLM 瀏覽器代理程式核心安全問題是什麼？**
A：隨著 LLM 瀏覽器代理程式逐漸從研究原型走向生產環境，它們造訪的每一個網頁都成為潛在的觀察點，而作者證明單靠被動觀察就足以識別驅動代理程式的底層基礎模型。這種透過 UI 軌跡進行的指紋辨識，會讓使用者的代理程式身份暴露給敵手，進而開啟針對性攻擊的大門。由於不同模型具有各自的已知漏洞與越獄手法，一旦被識別，攻擊者就能量身打造更有效的白箱對抗攻擊或模型特定漏洞利用，對使用者安全構成重大威脅。

**Q2：現有的機器人偵測與瀏覽器指紋辨識方法為何無法有效應對本文所述的威脅？**
A：現有方法大多將問題框限為二元分類——即區分人類與自動化客戶端——而非進一步判斷「若客戶端是代理程式，究竟是哪一個底層模型在操控」。這些傳統技術依賴瀏覽器屬性、標頭或網路層後設資料，而這類靜態特徵相對容易被偽造或規避。更重要的是，它們忽略了不同前沿大型語言模型在導航、點擊與頁面互動時所展現的獨特時間與結構動態，因此無法捕捉隱含在行為軌跡中的模型身份訊號。

**Q3：為何識別 LLM 代理程式的底層模型被視為重大的安全風險？**
A：在經典安全框架中，目標識別是邁向漏洞利用的首要步驟，而知道確切的底層模型能讓敵手從已知的模型特定弱點中挑選最有效的越獄攻擊或對抗樣本。這不僅大幅縮小了白箱對抗攻擊的搜尋空間，也使得攻擊者能精準利用該模型的偏差、已知失效模式或安全對齊漏洞。因此，模型指紋辨識將原本僅屬偵察階段的行為轉化為強大的攻擊原語，使代理程式面臨高度針對性且難以防禦的 exploitation。

**Q4：本文用於指紋辨識 LLM 瀏覽器代理程式的核心方法論為何？**
A：作者將代理程式識別形式化為一個針對行為軌跡的監督式分類問題，透過注入被動式 JavaScript 追蹤器來收集代理程式在網頁上的操作記錄。該追蹤器會記錄點擊、捲動、按鍵等 UI 動作，以及連續動作之間的精確事件間隔時間，從而構成包含時間與結構動態的互動軌跡。這些軌跡隨後被輸入輕量級分類器（如 XGBoost），學習將獨特的互動模式對應到特定的底層模型身份，而無需仰賴可被偽造的瀏覽器標頭或網路後設資料。

**Q5：相較於先前的 LLM 與代理程式指紋辨識研究，本文的關鍵創新何在？**
A：過往研究多採取主動探測方式，透過精心設計的查詢並分析模型回應來進行識別，或是由網路路徑上的攻擊者觀察封包層流量特徵；本文則證明僅憑代理程式在日常瀏覽中產生的普通 UI 事件，就足以達成高精準度的模型歸因。關鍵創新在於展示了一個被動式共置敵手——例如網站營運者——能單從頁面內的行為軌跡推斷底層模型，且不受特定應用程式、工具配置或實驗框架差異的影響。這揭示了一個全新的攻擊表面：被造訪的網頁本身即可成為精確行為指紋辨識的直接觀察點。

**Q6：作者為何選擇僅使用客戶端 UI 軌跡，而非伺服器端後設資料或瀏覽器靜態指紋？**
A：作者刻意將分析限制在客戶端互動訊號，因為瀏覽器屬性、IP 位址、TLS 指紋與標頭等靜態特徵對於有動機的敵手而言相對容易偽造或跨代理程式標準化。相對地，模型在規劃與執行動作時所展現的時間與結構動態——例如導航路徑、點擊座標與事件間隔——是內建於基礎模型決策過程的特性，難以在不根本改變代理行為的前提下被仿造。透過聚焦於這些行為軌跡，該方法能直接鎖定模型身份，並對隱藏傳統指紋的常見規避技術保持穩健性。

**Q7：本文採用哪些實驗設定與基準來評估指紋攻擊的有效性？**
A：評估涵蓋 14 個前沿大型語言模型，並在四個橫跨資訊檢索與購物任務的網頁環境中進行，以確保任務複雜度與頁面結構的多樣性。所有代理程式皆透過固定的瀏覽器實驗框架操作，且共享相同的動作空間，從而將行為變異的來源隔離至底層基礎模型本身，而非外部工具差異。作者透過注入式 JavaScript 追蹤器收集已標註的互動軌跡，並以宏觀 F1 分數評估分類器效能，同時透過將軌跡限制於單一網域來控制環境變異性。

**Q8：關於指紋攻擊的準確度與實用性，本文有哪些關鍵實驗結果？**
A：訓練完成的分類器在 14 個前沿模型上達到最高 96% 的宏觀 F1 分數，顯示 UI 軌跡蘊含極強的識別訊號。此外，該攻擊在資料有限的情況下依然實用，因為僅需少量互動軌跡就能訓練出強大的分類器，且能在單一瀏覽回合的早期階段推斷代理程式身份。這些結果證實行為指紋辨識不僅準確度極高，在僅能觀察到短暫或部分工作階段的真實世界場景中也同樣可行。

**Q9：隨機化時間延遲作為防禦手段的效果如何？消融研究揭示了什麼？**
A：在動作之間注入隨機化時間延遲確實會初步降低分類器效能，因為它擾亂了軌跡中可預測的時間模式。然而，這項防禦無法提供穩健保護，因為當敵手使用包含延遲軌跡的資料重新訓練分類器後，其效能便大幅回升。這項消融研究揭示識別訊號不僅編碼於原始時間間隔中，更持續存在於動作的結構序列與排序裡，因此單純的時間隨機化不足以抵禦持續性的敵手。

**Q10：敵手可能在哪些實際場景中部署這種指紋辨識技術？**
A：被動式共置敵手——例如惡意網站營運者或第三方腳本注入者——可在任何 LLM 代理程式造訪的頁面上部署此技術，默默盤點正在瀏覽的模型種類。取得這項情資後，敵手能動態投放針對特定模型的越獄提示、對抗內容或已知漏洞的利用載荷。此外，競爭對手或監控行為者也能利用此方法追蹤特定 AI 代理程式在網路上的採用與部署模式，而無需主動探測或網路攔截能力。

**Q11：鑑於這些發現，LLM 瀏覽器代理程式的開發者在產品與部署上應考量哪些因素？**
A：開發者必須認知到代理程式造訪的每個網頁都是潛在觀察點，這意味著透過傳統標頭偽造來隱藏模型身份的安全矇蔽策略，根本無法抵禦行為分析。產品團隊因此應整合超越表面隨機化的防禦策略，例如動態變化動作序列、在結構與時間維度同時引入類人類行為雜訊，或採用與底層基礎模型輸出脫鉤的模型無關中介層。此外，向使用者透明揭露指紋辨識風險，並在代理程式設計中導入隱私保護瀏覽模式，也應成為標準考量。

**Q12：這項研究可能對網路安全、AI 代理程式部署與對抗機器學習等更廣泛領域產生什麼影響？**
A：這項研究將 LLM 代理程式的威脅模型從傳統的人類與機器人之二元區分，轉變為更細緻的模型歸因格局，促使安全社群重新思考 AI 驅動自動化時代下的指紋定義。它透過證明 UI 互動中的行為側通道可作為可靠識別特徵，串連了網路安全與對抗機器學習領域，並可能激發針對代理程式的混淆與匿名化新研究。對於 AI 部署領域而言，這些發現強調若未處理代理程式內建行為特徵就將其大規模推入生產環境，將使使用者與平台暴露於新型且高度針對性的利用風險之中。

**Q13：本文提出的指紋辨識方法有哪些已承認的限制？**
A：研究為控制環境變異性，將軌跡限制於單一網域的單次工作階段，這可能限制了分類器在高度異質的多網站瀏覽模式下，若無額外訓練資料的泛化能力。此外，實驗假設所有代理程式使用固定的瀏覽器實驗框架與相同動作空間，雖然這確保了觀察到的行為差異可歸因於模型本身，但真實世界中採用客製化工具鏈或包裝器的部署可能引入本研究未隔離的混淆變數。防禦分析也指出，雖然簡單的時間延遲不足以抵禦攻擊，但更複雜的結構性防禦並未經過窮盡測試，行為混淆的極限仍屬開放問題。

**Q14：在哪些條件下，指紋辨識分類器可能失效或產生不可靠的預測？**
A：若代理程式被明確指示模仿其他模型的行為模式，或先進防禦機制同時隨機化互動的結構序列與時間動態，並在保留任務完成能力的前提下摧毀模型特定特徵，分類器可能難以準確識別。當代理程式在重度系統負載或網路延遲下運作，外部雜訊可能導致與模型規劃過程無關的軌跡擾動，進而降低分類準確度，除非分類器已針對此類擾動資料進行訓練。此外，若回合極短且互動極少，尤其是在初始動作對多數模型而言都屬通用的情況下，可能缺乏足夠訊號進行可靠的早期身份推論。

**Q15：這項工作為緩解或延伸 LLM 代理程式指紋辨識指出了哪些未來研究方向？**
A：未來研究應探索更先進的行為匿名化技術，在不妨礙任務效率的前提下同時改變軌跡的結構與時間維度，可能借鏡差分隱私或對抗訓練典範。研究者亦可探討聯邦或集成式代理架構——即由多個模型共同參與決策——是否能有效模糊單一模型分類器可偵測的行為指紋。在攻擊面延伸方面，將此指紋辨識方法擴展至多網域工作階段、動態網頁應用與即時串流互動，將有助於全面刻畫行為歸因技術在日益複雜部署環境中的穩健性與可擴展性。

## 實務應用指南

### 適用場景

1. **網站安全與 Bot 管理**：電商、內容平台或金融機構可在生產環境中部署被動式 JavaScript 追蹤器，將傳統「人類 vs. 自動化客戶端」的二元分類，升級為識別具體底層模型（如 GPT、Claude、Qwen 等）的多類別指紋辨識，以便針對不同 LLM 瀏覽器代理程式實施差異化存取控制。
2. **針對性威脅防禦**：資安團隊可依據預測身份，對已知存在特定模型漏洞或易受越獄攻擊的代理程式，動態啟用額外輸入驗證、速率限制或蜜罐頁面，降低白箱對抗攻擊與針對性攻擊的成功機率。
3. **競品情報與市場監控**：企業可偵測競爭對手是否使用特定前沿大型語言模型進行自動化價格爬蟲、庫存監控或內容擷取，並依據行為軌跡的時間與結構動態，追溯其底層模型家族與尺寸。
4. **廣告流量品質驗證**：廣告技術平台可透過 UI 軌跡區分人類使用者與不同 LLM 代理程式，避免廣告曝光被非人類流量消耗，提升媒體購買的透明度。
5. **合規與資料治理**：醫療、法律或政府網站可藉由辨識自動化訪客的模型身份，評估其資料擷取風險，並依據識別結果調整資料揭露策略，確保符合隱私法規要求。

### 實作前置條件

- **資料**：需取得標註語料庫，包含多個模型家族與尺寸的互動軌跡。建議先使用本研究釋出的實驗框架與標註資料作為基線，再針對目標網頁環境（如資訊檢索、購物任務）補充收集新的 UI 軌跡。
- **運算**：訓練輕量級分類器（如 XGBoost）所需的運算資源極低，一般單一伺服器或受管機器學習執行個體即可負荷；主要成本在於維護可注入注入式 JavaScript 的網頁基礎架構，以及儲存連續事件日誌。
- **技術能力**：前端工程能力（編寫與部署被動式 JavaScript 追蹤器）、資料工程能力（處理動作時間軸與事件間隔特徵），以及基礎機器學習知識（特徵工程、多類別分類器訓練與宏觀 F1 分數評估）。

### 實作步驟建議

1. **部署被動式追蹤器**：在目標網域的頁面中植入輕量級 JavaScript，被動記錄點擊、捲動、按鍵等動作類型及其時間戳，形成原始行為軌跡。確保追蹤器不影響頁面效能，並避免收集可偽造的瀏覽器屬性與標頭。
2. **建立標註語料庫**：利用瀏覽器實驗框架，讓各前沿大型語言模型在控制環境中執行相同任務回合，產生帶有模型身份標籤的互動軌跡。建議覆蓋多種網頁環境，以驗證後續泛化能力。
3. **特徵工程**：從原始軌跡中提取動作與時間特徵，包括動作序列（如點擊→捲動→按鍵的轉移機率）、事件間隔（inter-event interval）的統計分佈，以及跨頁面導航的結構模式。
4. **訓練與驗證分類器**：使用 XGBoost 等輕量級模型訓練多類別分類器，以宏觀 F1 分數評估。特別驗證分類器在少量互動軌跡下的表現，以及能否在回合早期即完成推論。
5. **測試泛化與對抗韌性**：評估分類器是否可跨模型尺寸與家族泛化。同時測試隨機化時間延遲防禦的影響：先測試延遲對原始模型的降效程度，再以延遲後的軌跡重新訓練，確認識別信號是否可被復原。
6. **生產環境部署與持續更新**：將分類器整合為即時推論服務，對每個工作階段的 UI 軌跡進行模型身份預測。建立持續學習管線，定期使用新釋出的 LLM 代理程式軌跡重新訓練，以應對模型行為漂移。

### 潛在風險與注意事項

- **隱私與法規風險**：詳細記錄使用者互動軌跡可能涉及個人資料處理，需確保符合 GDPR、個資法等規範，並明確告知資料收集範圍與用途。
- **對抗適應性**：攻擊者可能在得知追蹤機制後，刻意混淆動作時間軸或模擬其他模型的行為模式。隨機化時間延遲雖可短暫降低分類器效能，但研究顯示敵手可透過重新訓練大幅恢復預測表現，故不應視為唯一防線。
- **誤判與標籤漂移**：新釋出的基礎模型或現有模型的更新版本，可能產生訓練時未見過的行為軌跡，導致誤判。需建立未知類別偵測機制，並定期以新資料校準模型。
- **道德與雙重用途**：此技術本質上屬於目標識別的一環，可能被濫用於發動針對性攻擊。組織應建立嚴格的使用治理政策，僅將指紋辨識結果用於防禦性安全監控。
- **效能開銷**：雖然 JavaScript 追蹤器本身輕量，但大規模收集與即時分析事件串流可能增加後端負載，需評估邊緣運算或抽樣策略。

### 與其他技術的整合建議

- **Bot 管理與行為生物特徵平台**：將本技術作為現有「人類 vs. 機器人」辨識系統的補充層，提供細緻的模型身份標籤，而非僅輸出二元結果。
- **SIEM / SOAR**：將分類器輸出的預測身份與置信度送至安全資訊與事件管理系統，作為安全劇本（playbook）的觸發條件，例如當偵測到高風險模型時自動提升監控等級。
- **WAF（Web Application Firewall）**：依據即時識別出的底層模型，動態調整 WAF 規則。例如對已知易受特定越獄攻擊模式影響的模型，加強表單輸入與提示內容的過濾。
- **瀏覽器指紋辨識**：結合傳統被動收集的瀏覽器屬性（如 Canvas、WebGL、字體）與 UI 行為軌跡，建立多層次識別架構。即使靜態屬性被偽造，行為動態仍可提供穩定的識別信號。
- **A/B 測試與內容個人化**：內容平台可依據訪客是否為 LLM 代理程式及其模型類型，動態調整內容呈現、驗證機制或價格資訊，平衡使用者體驗與自動化風險。

### 給不同背景讀者的閱讀建議

**初學者**：請先聚焦摘要與圖一，理解核心概念——網站僅透過被動觀察點擊、捲動與按鍵的時間與結構動態，就能辨識造訪的 AI 代理程式身份。暫時跳過 XGBoost 特徵工程與威脅模型的形式化數學符號，重點掌握「行為即指紋」的直覺。

**AI 工程師**：請深入閱讀實驗框架（harness）的實作細節、特徵提取管線，以及如何在生產環境中低延遲部署 XGBoost 分類器。特別注意隨機化時間延遲防禦的局限性——研究顯示重新訓練即可復原效能，這對設計防禦系統至關重要。

**研究人員**：建議仔細分析問題形式化章節與相關工作，特別是與 Pasquini et al.（主動探測回應）及 Zhang et al.（網路流量層指紋）的比較。本研究的貢獻在於證明共置敵手僅需 UI 軌跡即可達成模型歸因，可延伸探討更強大的防禦機制或理論下界。

**產品經理**：請優先閱讀適用場景與防禦分析，評估將此技術導入現有產品的商業價值與風險。重點關注 bot 管理、廣告流量驗證與競品監控的應用潛力，同時審慎評估對使用者隱私、法規合規及品牌信任的影響。
