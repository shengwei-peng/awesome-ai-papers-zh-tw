## ⚡ TL;DR

現有AI代理治理僅是應用層中介軟體，與代理共用程序信任邊界，無法強制調解身分、輸入、記憶與執行。
提出AgentKernel，四大支柱提供不可繞過的強制調解：身分、分級感知、資訊流記憶與語義執行。
讓代理會話可稽核、可組合且可大規模部署，提升檢索正確性並支撐跨組織可信協作。

## 摘要翻譯

現代人工智慧代理（AI agents）經常跨越信任邊界（trust boundaries）：它們接收未受信任內容（untrusted content），將其與特權指令（privileged instructions）結合，將中間信念（intermediate beliefs）保存於長期記憶（long-term memory）中，並呼叫特權工具（privileged tools）。這形成了一個攻擊面，使惡意載荷（malicious payloads）得以透過模型輸入（model inputs）進入，並導致有害的工具行為（harmful tool actions）。然而，現有的治理堆疊（governance stacks）仍屬於應用程式層中介軟體（application-level middleware），與其所監控的代理共用同一個程序信任邊界（process trust boundary）。我們主張，代理需要一個作業系統基底（operating-system substrate），提供身分識別（identity）、輸入調解（input mediation）、記憶治理（memory governance）與執行控制（execution control）等強制性、不可繞過的服務（mandatory, non-bypassable services）。

我們提出 AgentKernel，一個以「安全性作為首要設計約束（security as a first-class design constraint）」為核心前提所建構的信任原生代理作業系統（trust-native agent operating system）。AgentKernel 將代理生命週期（agent lifecycle）納入一道強制執行邊界（mandatory enforcement boundary），並組織為四大支柱：身分識別（Identity）、感知（Perception）、認知（Cognition）與執行（Execution）。每個支柱都針對語義平面（semantic plane）上的失效，改寫經典作業系統安全原則（classical OS security principles），包括委派濫用（delegation abuse）、提示注入（prompt injection）、記憶毒害（memory poisoning）與工具誤用（tool misuse）。

AgentKernel 將結構性安全（structural security）視為能力倍增器（capability multiplier）。核心所管理的身分識別（Kernel-managed identity）支援可信任的跨組織協作（cross-organization collaboration）；分級感知（graduated perception）取代脆弱單點過濾器（brittle single-point filters）；資訊流控制記憶（information-flow-controlled memory）在提升檢索保真度（retrieval fidelity）的同時限制毒害；而語義到核心強制執行（semantic-to-kernel enforcement）則允許在不可繞過邊界（non-bypassable boundary）的保護下賦予更廣泛的工具特權（broader tool privileges）。我們將 AgentKernel 定位為編排框架（orchestration frameworks）、代理執行環境（agent runtimes）、治理平台（governance platforms）與執行沙箱（execution sandboxes）之下所欠缺的作業系統層，並透過系統性比較（systematic comparison）與安全分析（security analysis），展示單一整合式架構（integrated architecture）如何能夠在完整代理生命週期（full agent lifecycle）中強制執行安全性。

### 核心貢獻（3～5點）
- 提出 AgentKernel，一個以安全性為首要設計約束的信任原生代理作業系統，將代理生命週期納入強制執行邊界。
- 建立四大支柱架構（身分識別、感知、認知、執行），將經典作業系統安全原則改寫並應用於語義平面的代理失效模式。
- 論證結構性安全可作為能力倍增器，促成可信任的跨組織協作、更廣泛的工具特權，以及更高的檢索保真度。
- 定位 AgentKernel 為現有編排框架、代理執行環境、治理平台與執行沙箱之下所欠缺的作業系統層。
- 透過系統性比較與安全分析，展示單一整合式架構如何在完整代理生命週期中強制執行安全性。

### 適合對象
人工智慧安全研究者、代理系統架構師、企業級 AI 平台開發者，以及關注 LLM 代理治理、記憶安全與工具執行隔離的資安與系統工程師。

## 深度分析

#### 方法論解析

AgentKernel 的核心主張是將「安全性作為首要設計約束（security as a first-class design constraint）」，把傳統作業系統的強制調解機制提升到語義平面（semantic plane）。論文將代理生命週期（agent lifecycle）封裝在一個單一的強制執行邊界（mandatory enforcement boundary）內，並以四大支柱重新組織信任流動：

1. **Identity（身分識別）**：將「誰正在行動」從自我宣告字串（self-declared strings）提升為具備密碼學基礎的註冊、能力鏈（capability chains）與相互遠端證明（mutual attestation）。這使得編排（orchestration）、委派（delegation）與代理間交接都帶有可驗證的來源（provenance），從而抑制委派濫用（delegation abuse）。
2. **Perception（感知）**：以分級感知（graduated perception）取代脆弱單點過濾器（brittle single-point filters）。來自網頁、程式碼倉儲、對話等未受信任內容（untrusted content）在進入模型上下文前，先被標記為帶風險標籤的輸入，並在與系統指令混為一體前逐步降低風險。
3. **Cognition（認知）**：記憶不是被動的向量資料庫，而是受資訊流規範（information-flow discipline）約束的儲存空間。每個記憶項目都攜帶汙點（taint）與政策格（policy lattice）語義，確保被毒害的信念無法偽裝成操作事實，從而提升檢索保真度（retrieval fidelity）並限制記憶毒害（memory poisoning）。
4. **Execution（執行）**：透過分段橋接（staged bridge）把語義層宣告的工具意圖綁定到系統呼叫層級的強制執行，例如 eBPF 掛鉤與程序樹監控。這讓工具實作內部的特權升級無法超出核心對授權範圍的視野，解決工具誤用（tool misuse）與模糊權限（vague permissions）問題。

這四大支柱並非可替換的外掛，而是共同實例化一個共享的參考監控器（reference-monitor）紀律：不可繞過（non-bypassable）、預設拒絕（deny-by-default）、縱深防禦（defense-in-depth）、最小整合介面。論文強調，這是把經典作業系統安全原則（classical OS security principles）——程序隔離（process isolation）、強制存取控制（mandatory access control）、來源追蹤——從原始位址空間與系統呼叫映射到「提示注入（prompt injection）取代緩衝區溢位、對話上下文取代原始記憶體」的語義代理世界。

#### 實驗數據解讀

目前提供的摘要與第一章節並未包含任何量化實驗結果。論文宣稱透過「系統性比較（systematic comparison）」與「安全分析（security analysis）」來論證 AgentKernel 的必要性，但具體的評估指標、資料集、模型權重或實作細節在現有片段中均未出現。

從方法論推導，未來若進行實證評估，應關注以下指標：

- **攻擊緩解率**：針對提示注入、間接提示注入、記憶毒害與工具誤用的攻擊成功率（attack success rate, ASR）在導入 AgentKernel 前後的變化。
- **政策覆蓋率**：強制執行邊界對完整代理生命週期中各信任邊界轉換點的覆蓋比例。
- **檢索保真度（retrieval fidelity）**：在受汙點標記的長期記憶（long-term memory）中，正確區分可信與不可信上下文的能力。
- **執行開銷**：eBPF 掛鉤、密碼學身分識別與資訊流追蹤對延遲與吞吐量的影響。
- **跨組織協作（cross-organization collaboration）效率**：相互遠端證明與能力委派在異質代理間建立信任所需的步驟數與失敗率。

由於目前片段缺乏數據，我們無法驗證 AgentKernel 是否真能在實際系統中達到宣稱的「結構性安全（structural security）」與「能力倍增器（capability multiplier）」效果。讀者應期待完整論文提供對照實驗，例如與 LangChain、AutoGen、Letta、Microsoft Agent Governance Toolkit（AGT）等現有框架在相同攻擊場景下的比較。

#### 與現有研究的比較

論文把現有方案分為四個框架層級（harness tiers），並指出它們各自只能填補部分缺口：

| 層級 | 代表系統 | 現有貢獻 | AgentKernel 的差異 |
|---|---|---|---|
| 編排框架（orchestration frameworks） | LangChain / LangGraph、AutoGen、CrewAI、Microsoft Agent Framework、Semantic Kernel | 可組合工作流程與工具路由 | 缺乏強制執行邊界，無法 mediate 未受信任輸入與高特權工具之間的融合 |
| 代理執行環境（agent runtimes） | AIOS、OpenFang、SmythOS SRE、Letta | 排程、可觀測性、分層記憶、部分 WASM / 雲端資源隔離 | 未將身分識別、感知、記憶、執行統一成單一核心 |
| 治理平台（governance platforms） | Microsoft Agent Governance Toolkit、LangSmith、AgentOps | 政策、審批、追蹤管線 | 屬於應用程式層治理，與代理業務邏輯共享程序信任邊界（process trust boundary），可被繞過 |
| 執行沙箱（execution sandboxes） | nono、E2B、Anthropic sandbox-runtime | 隔離主機層運算 | 只管執行，不管感知如何毒害長期記憶或委派如何被濫用 |

AgentKernel 的主要改進在於把上述四層整合為一個位於其下的作業系統基底（operating-system substrate），提供「強制性、不可繞過的服務（mandatory, non-bypassable services）」。相較於現有方案，它試圖解決三個結構性弱點：

- **碎片化（Fragmentation）**：統一身分訊號、感知標籤、記憶儲存、工具執行器與政策引擎的來源語義。
- **模糊信任邊界（Blurry trust boundaries）**：核心與代理業務邏輯分離，使安全表面與應用表面可獨立審計與替換。
- **非強制執行（Non-mandatory enforcement）**：從可選中介軟體（middleware）掛鉤升級為綁定實際系統呼叫佈局的強制執行。

然而，現有片段也暴露若干限制：

- **實作細節不足**：語義到核心強制執行（semantic-to-kernel enforcement）如何精確映射 LLM 產生的高階意圖到 eBPF 政策，仍缺乏形式化說明。
- **效能與擴展性未知**：密碼學身分識別、細粒度資訊流追蹤與系統呼叫監控可能帶來顯著開銷。
- **LLM 的隨機性**：即使核心強制執行邊界存在，模型本身的生成行為仍可能以非預期方式組合上下文，造成語義繞過。
- **集中化風險**：若 AgentKernel 本身被攻破，所有支柱同時失效，因此核心的最小化與可驗證性至關重要。

#### 未來研究方向

AgentKernel 的提出開啟了多條值得後續探索的研究路徑：

1. **形式化驗證參考監控器**：為 AgentKernel 的核心強制執行邊界建立形式化模型，證明其不可繞過性與政策組合下的安全性。
2. **高效能語義汙點追蹤**：在向量記憶與檢索系統中實現低開銷的強制汙點標記（mandatory taint）與資訊流控制記憶（information-flow-controlled memory）。
3. **跨組織代理身分標準**：設計通用的密碼學委派與相互遠端證明協定，使不同組織開發的代理能夠安全協作。
4. **語義權限本體論**：建立從自然語言或結構化工具描述自動推導系統呼叫級權限的語義權限模型。
5. **eBPF / 核心政策語言**：為代理工具開發專用的政策語言，使開發者能宣告「此工具可讀取哪些目錄、可呼叫哪些程序」，並由核心自動強制執行。
6. **對抗性評估基準**：建立涵蓋間接提示注入、長期記憶毒害、多跳委派攻擊與工具實作內特權升級的標準化測試集。
7. **人在迴路（human-in-the-loop）與動態升級**：在分級感知與執行橋接中設計可解釋的升級機制，讓操作者在高風險動作前進行審批。
8. **中毒後復原與回滾**：研究如何在記憶毒害發生後偵測、隔離並修復受汙染的信念，而不影響合法長期記憶。
9. **與現有編排框架的漸進整合**：探索如何在 LangChain、LangGraph、CrewAI 等現有框架下方透明地插入 AgentKernel，降低採用門檻。
10. **硬體強化核心**：結合可信執行環境（TEE）與機密運算，進一步隔離 AgentKernel 本身，避免核心成為單一失效點。

## 論文問答

**Q1：AgentKernel 主要想解決什麼安全問題？**

A：現代基於大型語言模型的智慧代理經常跨越信任邊界，它們會攝取未受信任內容、將其與特權指令結合、把中間信念持久化到長期記憶，並呼叫高特權工具。這形成了一個攻擊面，使惡意載荷能透過模型輸入進入，最終導致有害工具行為。AgentKernel 正是要填補這個基礎設施缺口，提供一個強制性、不可繞過的作業系統基底來統一調解代理生命週期中的每一個信任轉換。

**Q2：現有的編排框架、代理執行環境、治理平台與執行沙箱為何無法根本解決這個問題？**

A：現有方案呈現出三個反覆出現的結構性弱點：碎片化、模糊的信任邊界，以及非強制性執行。身分訊號、感知過濾器、記憶儲存與工具執行器常以鬆散耦合的套件形式存在，彼此缺乏統一的來源標籤與程序間通訊基板；即使旗艦治理堆疊也與代理商業邏輯共用同一個程序信任邊界，導致策略、提示與工具交錯而無法獨立稽核。此外，許多防禦僅是可選的中介掛鉤，無法約束實際的系統呼叫佈局，因此無法提供真正不可繞過的保證。

**Q3：為什麼需要作業系統層級的基底，而不是再增加更多應用程式層防護？**

A：傳統應用程式誕生於已經具備程序隔離、虛擬記憶體、檔案系統與強制存取控制等豐富作業系統層級調解基礎設施的環境，而人工智慧代理卻處於基礎設施真空。缺少這個基底不只造成安全缺口，也限制了可靠性、可稽核性與大規模跨組織協作的可能性。AgentKernel 主張把經典作業系統安全原則提升到語義平面，讓安全性成為代理設計的首要約束，而非事後貼上的補丁。

**Q4：AgentKernel 的核心方法與架構是什麼？**

A：AgentKernel 將代理核心包裹在一個安全核心內，任何跨越都必須經過這個強制執行邊界。整個架構圍繞四大支柱組成：身分識別、感知、認知與執行，分別對應委派濫用、提示注入、記憶毒害與工具誤用等語義平面失敗模式。這四大支柱共同實現單一參考監控器，確保從未受信任輸入到可稽核輸出的每個階段都受到強制調解。

**Q5：與經典作業系統安全相比，AgentKernel 的關鍵創新在哪裡？**

A：AgentKernel 把不可繞過調解、預設拒絕組合、縱深防禦與最小整合面等經典原則，從記憶體位址與系統呼叫層提升到提示注入與對話上下文等語義平面。它提供密碼學基礎的身分識別、分級感知管線、資訊流控制記憶，以及語義到核心強制執行，並將這些能力整合為單一的信任原生代理作業系統。這種整合式架構避免了把各種防禦當成可替換外掛所帶來的保證破碎問題。

**Q6：為什麼四大支柱必須被設計成單一系統，而非可互換的外掛？**

A：四大支柱實現的是同一套參考監控器規範：身分識別確立行為主體，感知為未受信任內容加上標籤並降低風險，認知透過資訊流規範讓汙染信念無法偽裝成操作事實，執行則把語義權限繫結到系統呼叫層級的強制執行。若把它們拆成獨立外掛，某一階段的妥協可能會在不被察覺的情況下破壞其他階段的假設。只有單一核心才能確保完整代理生命週期中的保證可組合且不可繞過。

**Q7：論文使用了哪些評估面向或基準來驗證 AgentKernel？**

A：根據摘要與引言，論文採用系統性比較與安全分析，評估 AgentKernel 在身分識別、輸入調解、記憶治理與執行控制四個維度上的表現。雖然提供的節錄未列出詳細數據，但可以合理推論其評估會包含模擬的提示注入、委派濫用、記憶毒害與工具特權升級等攻擊情境。重點不在於單一準確率指標，而在於展示端到端強制執行能否貫穿整個代理生命週期。

## 實務應用指南

## 適用場景

**跨組織多代理 DevOps 管道**
論文動機情境即為典型：一個編排器將 PR 審查與條件式部署委派給多個專業代理。AgentKernel 適合這類需要跨團隊、跨服務帳號協作的場景，透過核心管理的身分識別提供可驗證的委派鏈，並以分級感知與資訊流控制記憶防止惡意 PR 留言間接污染部署決策。

**長期記憶型企業顧問或客服代理**
當代理需要持續記住客戶偏好、內部知識或合規政策時，記憶毒害與檢索保真度成為關鍵風險。AgentKernel 的認知支柱可將每筆記憶項目標記來源與汙點，避免未受信任內容在後續對話中被當成操作事實召回。

**高特權程式編寫代理產品**
類似 Cursor、Claude Code、GitHub Copilot / OpenAI Codex 這類原生整合開發環境助理，經常讀取私有程式庫並執行終端機指令。AgentKernel 的執行支柱能將「允許修改哪些檔案」這類語義權限，綁定到實際的系統呼叫層級強制執行，降低工具誤用導致的權限升級。

**第三方插件或代理市集生態**
當組織允許外部開發者上架工具或技能時，傳統應用程式層中介軟體與代理商業邏輯共享程序信任邊界，容易產生繞過。AgentKernel 作為不可繞過邊界，可為每個外掛建立強制執行邊界與能力範圍，類似作業系統對使用者空間程序的限制。

## 實作前置條件

**資料準備**
需要可驗證的身分識別憑證（例如組織簽發的 x.509、OIDC token、硬體信任根）；所有進入代理上下文的未受信任內容必須帶有來源標籤；記憶庫中的每個項目需要預先定義汙點標記與政策格語義；工具呼叫日誌與系統呼叫軌跡必須能夠被核心層級收集。

**運算與基礎設施**
需要支援 eBPF、seccomp 或核心模組的主機，以實現語義到核心強制執行；執行環境應能運行容器、WASM 或基於雲端的資源隔離；向量資料庫需支援每項目 metadata 與存取控制標籤；政策引擎與參考監控器必須部署在與代理商業邏輯不同的信任邊界內。

**技能與團隊組成**
團隊需同時具備作業系統安全（核心鉤子、強制存取控制、程序隔離）、LLM 應用架構（提示工程、RAG、工具使用）、身分與存取管理（IAM、委派、相互 attestation），以及可觀測性與稽核（追蹤、紅隊測試、事件回應）的跨領域能力。

## 實作步驟建議

**步驟一：盤點信任邊界與生命週期維度**
先繪出代理在委派、感知、記憶、執行四個階段中，未受信任內容與特權指令如何交錯。明確標示哪些元件目前與代理共享程序信任邊界，哪些僅是選用中介軟體。

**步驟二：建立強制執行邊界與參考監控器**
將 AgentKernel 設為代理生命週期必經的單一參考監控器，確保所有跨邊界操作（輸入進入上下文、記憶寫入、工具呼叫）都無法被代理本身或外掛繞過。這通常意味著核心服務運行在獨立程序或受保護的核心空間。

**步驟三：依序實作四大支柱**
先從身分識別開始，將自我宣告字串替換為加密基礎的註冊與能力鏈；接著建立分級感知管線，對網頁、程式庫、對話內容進行風險分層與降險；再導入資訊流控制記憶，讓汙點與政策語義隨檢索傳播；最後實作執行支柱，將語義權限對應到系統呼叫層級的 eBPF 鉤子或程序樹監控。

**步驟四：綁定語義授權到實際主機行為**
這是最關鍵的「最後一哩」：當代理宣告「只讀取 /tmp/project」時，核心必須能攔截並拒絕任何超出該範圍的檔案系統、網路或子程序操作，而非僅在工具參數層檢查。

**步驟五：持續稽核、紅隊測試與漸進部署**
建立針對提示注入、記憶毒害、委派濫用、工具誤用的紅隊測試集；先從低風險工具與唯讀權限開始試點，再逐步放寬特權；同時保留完整稽核軌跡以供事後調查。

## 潛在風險與注意事項

**效能與延遲開銷**
核心層級攔截、加密身分驗證、分級感知管線都會增加延遲。建議對延遲敏感路徑採用非同步或快取策略，但不可為了效能削弱強制執行邊界的不可繞過性。

**誤判導致的可用性下降**
過於嚴格的感知過濾或記憶存取控制可能阻擋合法輸入。應設計分級降險而非單純封鎖，並提供明確的稽核日誌讓營運團隊能夠快速覆寫與調整政策。

**繞過與供應鏈攻擊**
AgentKernel 本身成為高價值攻擊目標。必須確保其核心程式碼經過形式化或半形式化驗證、最小化整合介面，並透過硬體信任根或機密運算保護其啟動鏈。

**治理與法規合規**
強制性、不可繞過的服務可能與現有資料處理同意機制衝突。實作前需確認身分識別、記憶留存與工具呼叫記錄是否符合 GDPR、個資法等法規要求。

## 與其他技術的整合建議

**編排框架**
LangChain / LangGraph、AutoGen、CrewAI、Microsoft Agent Framework、Semantic Kernel 可繼續負責高階工作流程與工具路由，但應將所有跨信任邊界呼叫導向 AgentKernel，而非直接與模型或工具互動。

**代理執行環境**
AIOS、OpenFang、SmythOS SRE、Letta 等代理執行環境可將排程與可觀測性保留在應用層，而把強制執行邊界、身分識別與記憶治理交給 AgentKernel，形成「執行環境 + 安全核心」的分層架構。

**治理平台與可觀測性**
Microsoft Agent Governance Toolkit、LangSmith、AgentOps 可作為政策制定與稽核介面，但須注意它們目前多為應用程式層治理，應透過 AgentKernel 的 API 將政策轉譯為核心層強制規則，避免與代理共享程序信任邊界。

**執行沙箱**
E2B、nono、Anthropic sandbox-runtime 等執行沙箱負責隔離運算資源，AgentKernel 則負責決定「什麼內容與授權可以進入沙箱」。兩者結合可同時解決語義層污染與主機層逃逸。

**雲端 IAM 與機密運算**
整合企業現有的 IAM、KMS、TPM / vTPM 與機密 VM，可強化身分識別支柱的相互 attestation，並保護參考監控器本身的執行狀態。

## 給不同背景讀者的閱讀建議

**給初學者**
建議先聚焦論文的動機情境與四大支柱圖示，把 AgentKernel 想像成「專為智慧代理設計的作業系統」，重點理解為何現有框架無法解決提示注入與工具誤用，而不必急著深入 eBPF 或資訊流格理論；遇到專有名詞時可對照詞彙表。

**給 AI 工程師**
請特別關注分級感知管線與語義到核心強制執行的實作細節，思考如何在不重寫現有 LangChain / LangGraph 管線的前提下，將 AgentKernel 插入為強制中介層；同時評估記憶庫的 metadata 設計是否能承載汙點與政策標籤。

**給研究人員**
論文的核心貢獻在於將經典作業系統安全原則（參考監控器、強制存取控制、不可繞過性）提升到語義平面；建議深入檢視其形式化安全分析與系統性比較，並可進一步探索資訊流控制在神經符號推理、多代理協作與長期記憶中的理論極限。

**給產品經理**
請把 AgentKernel 視為一個「能力倍增器」而非單純安全功能：它不只能降低事件風險，還能讓產品開放更高特權工具、支援跨組織協作與第三方外掛生態。評估時應同時計算安全收益與新商業場景的機會成本，並規劃與現有治理堆疊的漸進整合路徑。
