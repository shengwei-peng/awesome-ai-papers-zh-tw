## ⚡ TL;DR

現有智能體工具組優化依賴真實驗證集，但部署環境難以取得標註資料。
回溯式工具組優化（RHO）利用過往軌跡，透過自我驗證與成對自我偏好進行自監督優化。
單輪優化使SWE-Bench Pro通過率自59%升至78%，無需外部評分並改善長時程表現。

## 摘要翻譯

智能體仰賴由技能、工具與工作流程構成的工具組（Harness）來解決複雜問題。持續改進此工具組對於適應新任務至關重要。然而，現有的優化方法通常需要真實驗證集（Ground-Truth Validation Set），但這類標註資料（Labeled Data）在實際部署（Deployment）環境中難以取得。為解決此問題，我們提出回溯式工具組優化（Retrospective Harness Optimization, RHO），這是一種自監督方法（Self-Supervised Method），僅利用過往軌跡（Trajectories）即可優化智能體工具組。具體而言，RHO 從過往軌跡中選取一個由具挑戰性任務（Tasks）組成的多樣核心集（Coreset），並以平行方式重新求解。智能體利用自我驗證（Self-Validation）與自我一致性（Self-Consistency）分析這些軌跡展開（Trajectory Rollouts），接著生成候選工具組更新（Candidate Harness Updates），並透過自身的成對自我偏好（Pairwise Self-Preference）選出最有效者。我們橫跨三個不同領域評估 RHO，涵蓋軟體工程（Software Engineering）、技術性工作（Technical Work）與知識性工作（Knowledge Work）。值得注意的是，僅需單一優化回合（Optimization Round），即可在無須任何外部評分（External Grading）的情況下，將 SWE-Bench Pro 的通過率（Pass Rate）從 59% 提升至 78%。此外，我們的分析顯示 RHO 能有效鎖定先前的失效模式（Failure Modes）。因此，優化後的工具組改變了智能體的行為模式（Behavior Patterns），並在長時程階段（Long-Horizon Sessions）中維持更高的準確率（Accuracy）。

### 核心貢獻（3～5點）
- 提出無需真實驗證集與外部評分的自監督工具組優化框架 RHO，僅利用過往未標註軌跡即可持續改進智能體。
- 結合核心集選取、平行軌跡展開、自我驗證與自我一致性診斷，以及成對自我偏好機制，自動生成並篩選最有效的工具組更新。
- 跨軟體工程、技術性工作與知識性工作三大領域驗證，單一優化回合即可顯著提升任務通過率（如 SWE-Bench Pro 從 59% 提升至 78%）。
- 能有效針對既有失效模式進行改善，使優化後的工具組改變智能體行為模式，並在長時程階段維持高準確率。

### 適合對象
從事 LLM 智能體、自主系統與提示工程相關研究或開發的學者與工程師；特別適合需要在缺乏標註資料的實際部署環境中，持續優化 AI 工具組與工作流程的產品團隊與技術主管。

## 深度分析

#### 方法論解析

本文提出回溯式工具組優化（Retrospective Harness Optimization, RHO），其核心目標是在缺乏真實驗證集（Ground-Truth Validation Set）與標註資料（Labeled Data）的實際部署（Deployment）場景中，僅利用未標註軌跡（Unlabeled Trajectories）來持續改進 LLM 智能體（LLM Agent）的工具組（Harness）。工具組在此定義為智能體可持久使用的工具、提示（Prompt）與技能之集合，而軌跡（Trajectory）則記錄了智能體執行任務（Task）時的完整推理、行動與觀察過程。

由於真實效用函數 U 無法直接觀測，RHO 以成對自我偏好（Pairwise Self-Preference）作為潛在效用的代理估計子。整個流程分為三個階段，對應演算法 1 的設計：

**第一階段：核心集選取（Coreset Selection）**
面對大量原始軌跡（Raw Trajectories），RHO 首先透過難度評判器（difficulty judge）為每個任務與其對應軌跡計算難度分數。接著，利用行列式點過程（Determinantal Point Process, DPP）進行 DPP-GREEDY 採樣，從中挑選出大小為 k、兼具多樣性與挑戰性的核心集（Coreset）。此步驟確保後續優化能聚焦於涵蓋不同失效模式（Failure Mode）的關鍵任務，而非僅累積簡單成功案例。

**第二階段：群組展開（Group Rollout）**
對於核心集中的每個任務，智能體使用當前工具組進行 G 次平行展開（Rollout），產生平行軌跡（Parallel Trajectories）。此階段萃取兩類診斷訊號（Diagnostics Signal）：
1. **自我驗證（Self-Validation）**：診斷單一軌跡內部的錯誤，即軌跡內失效（Within-Trajectory Failure）。
2. **自我一致性（Self-Consistency）**：比較多次展開結果，偵測跨軌跡分歧（Cross-Trajectory Disagreement）。

這兩種訊號無需外部評分（External Grading），完全由智能體自行產生，形成後續優化的指導依據。

**第三階段：工具組提案（Harness Proposal）與最佳候選選擇**
基於前述診斷訊號，RHO 透過 optimize 運算子並行生成 N 個候選工具組（Candidate Harness）。對於每個候選工具組，智能體重新求解核心集任務，產生新的軌跡展開（Trajectory Rollouts）。隨後，透過 rank 運算子執行成對自我偏好比較：將候選工具組產生的軌跡與基線（Baseline）工具組的固定軌跡 τ^(0) 進行比較，計算平均偏好分數 S_j。最終選擇分數最高的候選工具組 h_j*，但僅當 S_j* > 0 時才接受更新，否則保留原始工具組 h_0。

整體而言，RHO 屬於自監督方法（Self-Supervised Method），其所有運算子（judge、solve、optimize、rank）均由同一骨幹模型（backbone）實例化，不依賴任何外部標籤。

#### 實驗數據解讀

作者在三個異質領域進行評估：軟體工程（Software Engineering）、技術性工作（Technical Work）與知識性工作（Knowledge Work）。其中最引人注目的結果出現在 SWE-Bench Pro 基準測試上：僅經過單次優化回合（Optimization Round），智能體的通過率（Pass Rate）即從 59% 大幅提升至 78%，且過程中完全未使用任何外部評分機制。這代表 RHO 能夠從過往失敗經驗中萃取出高價值的改進訊號，其效率遠超單純的經驗累積（Experience Accumulation）。

進一步的行為分析顯示，優化後的工具組確實改變了智能體的行為模式（Behavior Pattern）。具體而言，RHO 會針對過去常見的失效模式設計特定技能與工具，使智能體在面對類似情境時採取不同的推理或工具呼叫策略。這種改變不僅提升單點任務的準確率（Accuracy），更在長時程階段（Long-Horizon Session）中維持較高的穩定性，顯示工具組更新有效抑制了錯誤在長期互動中的累積與放大。

此外，作者對診斷訊號的貢獻進行量化分析，指出核心集選取、群組展開與工具組提案三個步驟具有漸進式的訊號隔離效果：核心集確保任務難度與多樣性，群組展開透過平行軌跡暴露不穩定行為，而最終的自我偏好則篩選出真正帶來統計上顯著改進的工具組更新（Harness Update）。這說明 RHO 的每個環節都對最終效能提升有實質貢獻，而非僅依賴單一技巧。

#### 與現有研究的比較

在工具組優化（Harness Optimization）的研究脈絡中，現有方法無論是 LLM-as-optimizer、文字梯度更新（textual gradient updates）、ADAS 或 Meta-Harness，皆屬於驗證回饋優化（Validation-Feedback Optimization）範疇，必須依賴帶有標籤的驗證指標來引導搜尋方向。RHO 的根本差異在於完全捨棄真實驗證集，僅透過未標註軌跡與智能體自身的偏好判斷完成優化，這使其在實際部署環境中具有明顯的適用性優勢。

另一方面，在智能體自我改進（Agent Self-Improvement）的相關研究中，Dynamic Cheatsheet、ReasoningBank、MemMA、Sleep-time Compute 以及 SkillOS 等方法，主要聚焦於豐富智能體的記憶、上下文或技能庫，但並未觸及工具組的其他核心元件（如可執行工具、工作流程程式碼或系統提示）。RHO 則是對完整工具組進行結構性調整，包括新增或修改工具、重組工作流程與更新指令（Instruction），因此其優化範圍更為全面。

然而，RHO 仍存在若干限制。首先，其運算成本不容忽視：核心集選取後需進行 k×G 次展開以產生診斷訊號，再加上 N×k 次重新求解以評估候選工具組，對於大型語言模型而言，這代表顯著的推理開銷。其次，整個流程高度仰賴自我偏好的品質——若智能體無法可靠地比較兩組軌跡的優劣，則可能選出次佳甚至劣化的工具組更新。最後，本文強調單次回溯即可見效，但對於多次迭代應用時是否會出現效能飽和、工具組漂移（harness drift）或不穩定等問題，尚未提供深入分析。

#### 可重現性評估

就提供的論文內容而言，作者以偽代碼（Algorithm 1）清楚呈現 RHO 的三階段流程，這為重現提供了重要的結構藍圖。然而，在開源資源方面，文中並未明確提及原始碼、模型權重或實驗所用之過往軌跡資料集是否公開。雖然 SWE-Bench Pro 屬於公開基準，但 RHO 的實際重現仍高度依賴以下未公開的實作細節：

1. **運算子提示設計**：難度評判器、自我驗證、自我一致性、optimize 與 rank 等運算子的具體提示模板。
2. **DPP 特徵表示**：用於行列式點過程（DPP）的軌跡特徵嵌入方法（文中雖提及 t-SNE 視覺化，但未說明 DPP 的實際特徵抽取方式）。
3. **工具組表示與修改機制**：工具組 h 的資料結構、以及候選工具組的採樣與編輯邏輯。
4. **超參數設定**：核心集大小 k、群組大小 G、候選數量 N 與 DPP 權重 θ 的選擇依據。

由於所有運算子均由同一骨幹模型實例化，理論上此方法具有模型不可知性（model-agnostic），但重現性仍取決於上述實作細節的完整釋出。

#### 未來研究方向

1. **多回合迭代與持續學習**：本文證明單次優化回合即可帶來顯著增益，但未探討反覆執行 RHO 的動態行為。未來可研究連續多輪回溯式優化是否會導致效能飽和、工具組過擬合於歷史任務，或產生類似災難性遺忘的現象，並建立相應的收斂理論。

2. **自我偏好的可靠性理論**：目前以成對自我偏好作為潛在效用的代理仍屬經驗性設計。未來研究可探討在何種條件下（如模型能力門檻、任務難度分佈）自我偏好能可靠地近似真實效能，並量化其誤差界限。

3. **混合稀疏外部回饋**：雖然 RHO 完全無需標註資料，但在部分外部評分可取得的場景下，設計結合自我偏好與稀疏真實標籤的混合機制，有望在降低標註成本的同時進一步提升優化效率與上限。

4. **自適應超參數調整**：目前 k、G、N 等參數均為固定值。未來可發展依據軌跡分佈密度、任務難度或運算預算動態調整這些參數的策略，以在有限的展開（Rollout）預算下最大化優化效益。

5. **跨領域工具組遷移**：本文分別於軟體工程、技術性工作與知識性工作驗證 RHO，但未探討在一個領域優化後的工具組能否遷移至其他領域。若能有效遷移，將大幅降低多領域部署時的優化成本。

6. **長時程錯誤傳播的因果分析**：實驗顯示優化後的準確率（Accuracy）在長時程階段（Long-Horizon Session）得以維持，但其背後機制——例如是否透過減少複合性錯誤傳播（compounding error propagation）或改善中間步驟的恢復能力——值得更深入的因果分析與驗證。

## 論文問答

**Q1：RHO 旨在解決 AI 智能體在實際部署後的什麼核心問題？**
A：RHO 主要解決的是在真實部署環境中，AI 智能體的「工具組」（harness）難以持續優化的問題，因為現有方法通常依賴帶有正確答案的驗證集來評估與迭代，而這類標註資料在實務上往往難以取得。隨著智能體上線後面對新任務，其可用的技能、工具與工作流程必須不斷演進，但缺乏外部評分機制使得傳統的驗證回饋優化無法運作。因此，如何僅利用智能體過往執行留下的未標註軌跡來自我改進，成為 RHO 聚焦的核心挑戰。

**Q2：現有的工具組優化方法與智能體自我改進方法為何無法直接解決上述挑戰？**
A：現有的工具組優化方法，無論是提示詞搜尋、流程編譯或讓高階智能體改寫其程式碼，幾乎都仰賴一個帶有標籤的驗證指標來引導搜尋方向，這在部署後的真實環境中通常無法取得。另一方面，現有的自我改進方法雖然利用智能體自身的判斷取代外部標籤，但大多僅針對記憶庫、上下文或可重用的策略片段進行擴充，並未觸及工具組中更深層的可執行工具、工作流程與指令結構。換言之，前者受限於標註資料的稀缺性，後者則只優化了工具組的局部記憶元件，未能對整體 harness 進行全面性的回溯式更新。

**Q3：為何強調在部署階段「持續」改進工具組對智能體而言至關重要？**
A：智能體上線後會面臨動態且多樣的使用者任務，初始設計的工具組、提示詞與工作流程往往無法涵蓋所有未來情境，若缺乏持續演進機制，其性能將迅速觸及天花板。持續改進能讓智能體從實際執行過程中的失敗與成功軌跡中提煉經驗，進而調整行為模式以適應新任務的挑戰。這不僅關係到單次任務的準確率，更影響其在長時程階段中維持穩定表現的能力，因此部署後的自我優化是邁向自主智能體的關鍵一環。

**Q4：請詳細說明 RHO 的三階段流程，以及每個階段在整體優化中扮演的角色。**
A：RHO 的完整流程可分為「核心集選取」、「群組展開」與「最佳候選工具組提案」三個階段。首先在核心集選取階段，系統利用行列式點過程（DPP）從大量過往未標註軌跡中，挑選出一個規模小但涵蓋不同難度與多樣性的任務子集，確保後續優化能聚焦於具代表性的挑戰。接著進入群組展開階段，智能體針對核心集中的每個任務平行重新執行多次，產生大量平行軌跡，並透過自我驗證診斷單一軌跡內的失效，以及利用自我一致性檢測跨軌跡的分歧，從而萃取出具體的診斷訊號。最後在最佳候選工具組提案階段，系統依據這些診斷訊號生成多個候選工具組更新，並讓智能體以成對自我偏好的方式比較各候選組合與基線的軌跡表現，選出最能提升執行品質的更新版本，全程無需任何外部評分。

**Q5：RHO 提出的「軌跡自我偏好」機制相較於傳統優化範式，其關鍵創新價值為何？**
A：傳統範式必須仰賴潛在的效用函數或外部驗證集來計算通過率等明確指標，以判斷工具組的優劣，而 RHO 的創新在於以智能體自身的成對偏好估計器來取代這個無法直接觀測的效用函數。具體而言，智能體被賦予能力去比較同一任務下不同工具組所產生的多條軌跡，並產生偏好排序與理由，從而將「哪個工具組更好」的問題轉化為「哪組軌跡更受智能體自身青睞」的問題。這使得優化流程完全自監督化，擺脫了對真實驗證集與外部評分的依賴，讓智能體在部署後能獨立完成工具組的迭代升級。

**Q6：RHO 在核心集選取時為何採用行列式點過程（DPP），並同時結合自我驗證與自我一致性兩種診斷訊號？**
A：採用 DPP 是為了在有限的運算預算下，從海量過往軌跡中篩選出既具多樣性又涵蓋足夠挑戰性的任務子集，避免優化過程僅針對單一類型的簡單任務過擬合，確保工具組更新能泛化到更廣泛的情境。自我驗證負責挖掘單一軌跡內部的邏輯錯誤、工具誤用或推理斷裂等「軌跡內失效」，提供細粒度的失敗根因；而自我一致性則透過比較同一任務多次展開後的平行軌跡，捕捉結果分歧與不穩定行為，揭示工具組在面對相同輸入時的脆弱性。這兩種訊號相輔相成，前者定位具體的內部錯誤模式，後者暴露系統性的不確定區域，共同為後續的工具組更新提供明確且可操作的改進方向。

**Q7：RHO 的實驗評估涵蓋哪些領域與基準測試？**
A：研究團隊在三個差異顯著的領域評估 RHO 的有效性，分別是軟體工程、技術性工作與知識性工作，以驗證其跨域泛化能力。其中在軟體工程領域，具體使用了 SWE-Bench Pro 這項極具挑戰性的基準測試集，該測試集要求智能體根據真實的 GitHub issue 修改程式碼並通過單元測試。這三個領域涵蓋了從程式碼生成、工具操作到複雜推理的不同認知需求，能夠全面檢驗 RHO 對於不同類型工具組與任務型態的優化潛力。

**Q8：RHO 在實驗中取得了哪些最引人注目的量化成果？**
A：最顯著的成果是在軟體工程領域，僅僅經過一輪回溯式工具組優化，智能體在 SWE-Bench Pro 上的通過率便從 59% 大幅提升至 78%，且整個過程完全未使用任何外部評分或標註答案。這項進步不僅幅度驚人，更關鍵在於它證明了單次回顧性分析就能帶來實質的性能躍升，而非需要反覆迭代於昂貴的驗證集之上。此外，RHO 在三個不同領域均展現出一致的改進趨勢，顯示其自我偏好機制與診斷訊號的萃取具有跨任務的穩健性。

**Q9：論文中的深入分析如何說明 RHO 對失效模式的影響，以及各階段診斷訊號的貢獻？**
A：分析顯示 RHO 能夠精準地針對智能體過往遭遇的特定失效模式設計對應的技能與工具，例如新增能處理特定錯誤類型的元件，從而根本性地改變智能體的行為模式。這些有針對性的更新讓智能體在後續的長時程階段中維持更高的準確率，避免因重複陷入相同錯誤而導致的性能衰退。此外，論文進一步量化指出，RHO 的每一個步驟——從核心集選取、群組展開到訊號萃取——都會逐步隔離並放大對性能提升有貢獻的訊號，說明整個流程的設計環環相扣，而非僅仰賴單一環節的僥倖成功。

**Q10：在哪些實際部署情境中，RHO 的價值最為凸顯？**
A：RHO 特別適用於那些任務複雜、失敗成本高，但難以持續取得人工標註或外部自動評分的大規模線上環境，例如企業內部的自動化技術支援智能體、長期運行的軟體維護助手，或是需要頻繁適應新領域知識的研究輔助系統。在這些情境中，智能體每天產生大量未標註的執行軌跡，卻鮮少有餘裕為每筆資料建立正確答案以供傳統優化使用。RHO 能夠在背景利用這些現成的歷史資料進行定期的回溯分析，如同「睡眠時運算」般在離線階段自我精進，無需中斷線上服務或額外投入昂貴的標註人力。

**Q11：產品團隊在將 RHO 整合至現有智能體系統時，應考量哪些工程與設計層面的因素？**
A：產品團隊首先需要評估平行運算資源的可用性，因為 RHO 的核心集展開與候選工具組評估都涉及大量平行軌跡的生成，這對底層推理基礎設施的吞吐量與成本有直接影響。其次，由於 RHO 會實際改寫工具組中的可執行程式碼、提示詞與工作流程，團隊必須建立嚴謹的沙箱測試與版本控制機制，確保新生成的工具組在部署前不會引入安全風險或破壞既有功能。最後，團隊應持續監控智能體的自我偏好品質，因為若成對排序的判斷出現系統性偏差，可能導致優化方向偏離使用者真正的需求，因此適度保留人工稽核閘門仍是穩健上線的必要措施。

**Q12：RHO 可能對 LLM 智能體的研究與開發範式帶來什麼樣的轉變？**
A：RHO 推動了從「驗證回饋驅動」到「自我偏好驅動」的範式轉移，證明智能體無需外部真值標籤即可對自身的工具組進行結構性升級，這大幅拓展了自主智能體在開放世界中的可擴展性。對研究社群而言，這意味著未來的焦點可能從追求更大規模的標註資料集，轉向設計更強大的自我診斷與自我評價機制，使智能體能從自身的「經驗」中提煉知識。對產業界來說，這降低了持續維護昂貴評估基礎設施的門檻，使得智能體產品在部署後仍能像生物般自主演化，朝向真正的終身學習系統邁進。

**Q13：RHO 框架存在哪些固有的限制或前提假設？**
A：RHO 的有效性高度依賴過往軌跡的數量與品質，若智能體在初期部署階段累積的歷史資料過少或過於同質，DPP 選出的核心集可能無法涵蓋關鍵的失敗類型，導致優化缺乏方向性。此外，整個流程假設智能體具備足夠可靠的自我驗證與自我偏好能力，但對於某些需要外部世界知識才能判斷對錯的任務，自我評價仍可能出現盲點或過度自信的偏差。最後，雖然論文展示了單輪優化的顯著成效，但對於需要深度結構性調整的工具組，單次回溯是否足以支撐長期持續的效能增長，仍有待更長週期的觀察與驗證。

**Q14：在什麼情況下 RHO 可能產生次優甚至錯誤的工具組更新？**
A：當自我驗證與自我一致性訊號因任務本身的模糊性或智能體推理侷限而產生誤導時，後續生成的候選工具組可能會針對錯誤的「偽失效模式」進行過度修正，反而損害原有正確的行為邏輯。例如，若平行軌跡間的分歧源自任務描述的不確定性而非工具組缺陷，智能體可能錯誤地新增不必要的複雜規則來強制一致性，造成過度擬合。另外，如果候選工具組的生成空間不夠多樣，或自我偏好排序對細微的軌跡差異不敏感，RHO 也可能陷入局部最優，無法發現更具顛覆性的結構性改進方案。

**Q15：基於 RHO 的成果，未來研究可以朝哪些方向進一步延伸？**
A：未來研究可以探索將 RHO 擴展為多輪迭代式的回溯優化循環，讓智能體在連續的部署週期中不斷累積與精煉工具組，而非僅限於單次回顧。另一個方向是結合強化學習或元學習，讓核心集的選取策略與自我偏好模型本身也能隨著優化歷程動態適應，進一步提升診斷訊號的品質。此外，將 RHO 應用於多智能體協作場景，讓不同角色的智能體透過交叉評價彼此的軌跡來共同優化各自的工具組，或是發展更輕量化的近似演算法以降低大規模平行展開的運算成本，都是極具潛力的後續發展路徑。

## 實務應用指南

### 適用場景

**1. 企業內部軟體工程維護智能體**
適用於長期維護大型程式碼庫的內部開發智能體。當智能體每日處理大量未標註的除錯、重構或功能新增任務時，RHO 可定期回溯過往軌跡，針對反覆出現的編譯錯誤或測試失敗模式，自動更新工具組中的技能提示與工作流程，無需人工準備標準答案驗證集。

**2. 技術支援與維運排障智能體**
適用於需要呼叫多種內部工具（如日誌查詢、監控儀表板、知識庫檢索）的維運智能體。透過分析過往未標註的故障排查軌跡，RHO 能萃取出跨軌跡分歧與軌跡內失效的診斷訊號，進而優化工具呼叫順序與上下文組裝方式，提升長時程階段中的排障準確率。

**3. 法律或醫療知識工作輔助智能體**
適用於文件審閱、法規比對或病歷摘要等高專業門檻的知識性工作。由於取得外部標註成本極高，RHO 可利用自我驗證與自我一致性機制，從歷史軌跡中挑選爭議性高、難度分散的核心集，自動調整引用格式、檢查清單與推理步驟提示。

**4. 自動化數據分析與報告生成智能體**
適用於需頻繁產生商業智慧報告或實驗分析的自動化流程。智能體在執行數據查詢、視覺化與結論撰寫後，RHO 可針對過往生成失敗（如圖表遺漏、單位錯誤）進行回溯式優化，調整數據處理工具組與輸出格式指令。

**5. 多工具協作的研究或個人助理智能體**
適用於整合搜尋、計算、文件編輯與通訊工具的多功能助理。當使用者指派開放式長程任務（如市場調查、行程規劃）時，RHO 透過成對自我偏好比較不同工具組版本的展開軌跡，篩選出最能穩定完成多步驟任務的提示與工具組合。

### 實作前置條件

**資料準備**
- 累積至少數百至數千筆未標註軌跡，涵蓋多樣任務類型與難度分布。軌跡需完整記錄智能體的思考鏈、工具呼叫參數、環境觀察結果及最終輸出，以供後續自我驗證與行列式點過程（DPP）採樣使用。
- 建立軌跡儲存與版本控制規範，確保原始軌跡、基線工具組與候選工具組可一一對應追蹤。

**運算資源**
- 具備平行執行環境以支援群組展開（Group Rollout）與 Best-of-N 工具組提案。核心集大小 k、群組大小 G 與候選數 N 會產生 k×G＋N×k 次重新執行，需預留充足的 LLM API 配額或自有 GPU 叢集。
- 建議配置向量資料庫或物件儲存，用於存放歷史軌跡、DPP 特徵向量與多版本工具組快照。

**技能門檻**
- 團隊需具備工具組設計與維護能力，包括提示工程、可執行工具（如 Python 函數或 API 呼叫）開發，以及工作流程編排。
- 需有能力設計自我驗證規則（例如檢查軌跡內工具回傳碼、輸出格式合法性）與自我一致性比對邏輯（例如跨軌跡答案的語意相似度或執行結果等價性判斷）。
- 熟悉批次任務排程與分散式執行，以管理大規模平行展開的容錯與重試機制。

### 實作步驟建議

**步驟一：標準化軌跡收集與難度評分**
在生產環境中埋設結構化日誌，確保每筆軌跡都記錄任務輸入、完整執行步驟與環境回饋。部署初期先以固定工具組累積原始軌跡，並由難度評分模組（可為基於軌跡長度、工具呼叫次數或失敗訊號數量的啟發式規則）為每筆任務標註相對難度。

**步驟二：核心集選取（Coreset Selection）**
運用行列式點過程（DPP）從累積的未標註軌跡中，挑選兼具多樣性與挑戰性的核心集。實務上可將任務嵌入向量空間後計算 DPP，確保選出的任務同時覆蓋不同語意叢集與難度區間，避免優化過度集中在單一失效模式。

**步驟三：設計診斷訊號**
為目標領域建立兩類診斷訊號：一是「自我驗證」規則，用於偵測單一軌跡內部的執行錯誤（如例外拋出、空值回傳、格式不符）；二是「自我一致性」檢查，用於比對同一任務多次展開後的平行軌跡，標註結果分歧或推理路徑差異過大的案例。

**步驟四：群組展開與訊號萃取（Group Rollout）**
對核心集中的每個任務，使用當前基線工具組平行展開 G 次，產生平行軌跡。自動執行步驟三設計的診斷規則，萃取出軌跡內失效與跨軌跡分歧的具體案例，彙整為結構化診斷報告，作為後續優化的輸入。

**步驟五：生成候選工具組（Harness Proposal）**
將診斷報告輸入優化模組（可由另一個後設智能體或結構化模板驅動），生成 N 個候選工具組更新。每個候選版本應明確對應到欲修復的失效模式，例如新增特定錯誤處理技能、調整工具呼叫順序，或強化提示中的少樣本示例。

**步驟六：成對自我偏好評選（Pairwise Self-Preference）**
針對每個候選工具組，重新在核心集上執行展開，並與基線工具組的軌跡進行成對比較。設計偏好排名函數，讓智能體根據輸出品質、執行穩定性與診斷訊號改善幅度，選出總體自我偏好分數最高的候選版本。

**步驟七：漸進式部署與持續監控**
將獲選的工具組更新先導入灰度環境或影子模式，觀察其對新任務的影響。確認無明顯迴歸後再推播至生產環境，並持續收集新軌跡，作為下一輪 RHO 優化回合的輸入資料。

### 潛在風險與注意事項

**核心集偏差導致優化失焦**
若核心集選取僅覆蓋特定任務類型或難度過於集中，優化後的工具組可能在其他場景表現衰退。緩解方式：定期檢視 DPP 採樣結果，確保核心集涵蓋近期新增任務類型與不同難度層級，並保留一定比例的隨機採樣作為對照。

**自我偏好的過度自信與表面優化**
智能體可能偏好冗長但實質錯誤的軌跡，或僅優化表面格式而非根本推理邏輯。緩解方式：在成對自我偏好中引入硬性約束（如通過自我驗證門檻才具備評比資格），並結合領域啟發式規則（如程式碼必須通過編譯、數據必須符合 schema）作為篩選條件。

**運算成本與延遲爆炸**
群組展開與 Best-of-N 重新執行會產生大量 LLM 呼叫，可能導致成本與時間不可行。緩解方式：採用階層式篩選——先用較小模型或較少展開次數進行初篩，僅保留 Top-M 候選進入完整評估；或將非關鍵任務的展開排程於離峰時段。

**工具組更新後的效能迴歸**
針對過往失效模式的修復，可能意外破壞原本正確的執行路徑。緩解方式：在 RHO 流程中強制保留基線比較，僅當候選工具組在核心集上的自我偏好顯著優於基線（且無重大新增生錯誤）時才接受更新；生產環境採用 A/B 測試驗證。

**長時程階段的行為僵化**
反覆優化可能使工具組過度擬合於已發生的失效模式，降低對新興任務的泛化能力。緩解方式：限制單一回合的修改範圍（例如僅允許新增或修改少數技能），並設定工具組版本降級機制，確保當監控指標下滑時可快速回滾。

### 與其他技術的整合建議

**與可觀測性平台（Observability）整合**
將現有的 Langfuse、LangSmith 或自研追蹤系統作為原始軌跡的來源，直接匯入 RHO 的軌跡儲存層。統一日誌格式可降低資料清洗成本，並讓診斷訊號與現有監控儀表板連動。

**與提示版本控制及 CI/CD 整合**
將工具組（提示、工作流程程式碼、工具定義）視為程式碼資產，存放於 Git 倉庫。RHO 產生的候選工具組更新應以 Pull Request 形式提交，經由自動化測試與程式碼審查後再合併，確保優化過程符合工程規範。

**與檢索增強生成（RAG）及記憶庫互補**
RHO 優化的是「如何執行」的工具組結構（技能、工具順序、提示模板），而 RAG 與記憶庫提供的是「知道什麼」的外部知識。建議明確區分兩者：讓 RHO 負責工作流程與工具參數的演進，RAG 負責動態知識片段的召回，避免將靜態知識硬編碼進工具組提示。

**與外部驗證機制形成混合架構**
在部分任務確實能取得標註資料的情境下，可設計閘道機制：當真實驗證集存在時啟用傳統驗證回饋優化；當資料未標註時則啟用 RHO。兩者共享同一套核心集選取與展開基礎設施，最大化基礎建設的複用性。

**與多智能體框架協作**
若系統已採用多智能體架構（如專門負責程式碼、搜尋、驗證的不同智能體），可對每個子智能體獨立執行 RHO。亦可設立後設智能體（Meta-Agent）負責統籌各子智能體的診斷報告，並協調生成跨智能體的候選工具組更新，避免局部優化導致整體流程衝突。

### 給不同背景讀者的閱讀建議

**初學者**
請先聚焦論文圖一與圖二的高層概念，理解 RHO 的核心精神是「讓智能體在沒有標準答案的情況下，從自己的過往經驗中學習並改進」。不必急於理解行列式點過程（DPP）的數學細節，重點掌握「核心集選取→平行展開→自我診斷→偏好選擇」這四個直覺步驟，以及它與傳統「需要人工打分」的優化方式有何不同。

**AI 工程師**
建議深入研讀演算法一（Algorithm 1）與第 3 節的問題設定，關注如何將論文中的 `judge`、`solve`、`optimize`、`rank` 四個操作映射到您的實際系統。特別留意平行執行的工程細節（第 2 階段的平行展開與第 3 階段的 Best-of-N 平行生成）、診斷訊號的具體實作方式，以及如何設計穩健的「成對自我偏好」提示，避免模型過度自信。

**研究人員**
請著重分析 RHO 與現有工具組優化（如 ADAS、Meta-Harness）及智能體自我改進（如 SkillOS、ReasoningBank）的差異化貢獻。核心在於 RHO 以「自我偏好」完全取代「真實驗證回饋」的範式轉移，以及行列式點過程在難度感知多樣性採樣中的角色。建議細讀實驗分析章節，觀察 RHO 如何針對特定失效模式產生結構化的工具組更新，並思考此方法在不同智能體架構（如 ReAct、CodeAct）上的泛化性與理論限制。

**產品經理**
請將閱讀重點放在商業價值與資源權衡上：RHO 解決了「上線後缺乏標註資料就無法持續優化」的痛點，且論文顯示單一優化回合即可將 SWE-Bench Pro 通過率從 59% 提升至 78%。評估導入時，請同時估算平行展開所需的運算預算（與節省下來的人工標註成本相比），並規劃「持續學習」的產品路線圖——讓用戶感知到智能體會隨著使用時間增長而變得更可靠。
