## ⚡ TL;DR

電腦代理難以處理需要領域知識的陌生軟體，且人類示範難以分離工作流程規則與任務細節。
Work2Skill 以 WorkRecorder 收集螢幕與 AX 對齊示範，採代理式技能歸納。
四種模型下皆達最高分，於兩項基準較無技能基準提升 3.11 至 10.54 分。

## 摘要翻譯

電腦使用代理（Computer-use Agent）能執行日益複雜的 GUI（Graphical User Interface）任務，然而不熟悉的軟體以及需要人類領域知識（Domain Knowledge）的工作流程仍具挑戰性。人類示範（Human Demonstration）透過相同的 GUI 互動空間傳達程序性知識（Procedural Knowledge），但重複使用需要在脈絡中詮釋動作，並將工作流程規則（Workflow Rule）與任務特定細節（Task-Specific Detail）加以區隔。因此我們提出 Work2Skill，一個擷取人類 GUI 經驗以進行可重複使用代理技能歸納（Reusable Agent Skill Induction）的框架。WorkRecorder 提供該框架的基礎設施以蒐集此經驗，對齊螢幕錄影（Screen Recording）、滑鼠與鍵盤事件（Mouse and Keyboard Event），以及可取得的無障礙樹（Accessibility-Tree, AX）資訊。我們使用 WorkRecorder 建構 WorkDemo-350，這是人類桌面 GUI 示範（Desktop GUI Demonstration）的首個同步多模態資料集（Synchronized Multimodal Dataset），可用於可重複使用代理技能歸納與下游評估（Downstream Evaluation）。其 350 個示範皆已篩選，確保完整性與任務成功（Task Success）。接著我們提出一個代理式技能歸納（Agentic Skill Induction）方法，該方法按需檢查證據（Evidence Inspection）以產生可重複使用技能（Reusable Skill），擷取工作流程規則、步驟相依性（Step Dependency）與完成檢查（Completion Check）。當相同的四個執行模型（Execution Model）在共享執行設定（Shared Execution Setting）下配備由各方法歸納的技能時，Work2Skill 達到最高分數與成功率（Success Rate）。在 MyPCBench 有界動作（Bounded Action）上，相較於對應的無技能基準（No Skill Baseline），平均分數提升（Mean Score Improvement）為 4.67 至 10.54 分；在 OSWorld-Verified 的 286 任務子集（286-Task Subset）上，平均分數提升為 3.11 至 7.50 分。我們的程式碼與資料可取得於 https://github.com/china-qijizhifeng/Work2Skill。

### 核心貢獻（3～5點）
- 提出 **Work2Skill** 框架，透過 WorkRecorder 基礎設施擷取人類 GUI 經驗，並對齊螢幕錄影、滑鼠與鍵盤事件與無障礙樹資訊，作為可重複使用代理技能歸納的來源。
- 建構 **WorkDemo-350**，這是人類桌面 GUI 示範的首個同步多模態資料集，涵蓋 350 個經完整性與任務成功篩選的示範，可同時用於技能歸納與下游評估。
- 提出**代理式技能歸納方法**，按需檢查證據以產生可重複使用技能，明確擷取工作流程規則、步驟相依性與完成檢查，將通用流程與任務特定細節分離。
- 在 MyPCBench 有界動作與 OSWorld-Verified 286 任務子集上進行方法比較（Method Comparison），四個執行模型在共享執行設定下皆因 Work2Skill 歸納的技能而達到最高分數與成功率，相較無技能基準分別提升 4.67–10.54 分與 3.11–7.50 分。

### 適合對象
本論文最適合從事**電腦使用代理（Computer-use Agent）**、**GUI 自動化**、**代理人技能學習（Agent Skill Learning）**以及**程序性知識擷取（Procedural Knowledge Capture）**研究的學者與工程師閱讀；同時，對於關注**多模態資料集建構**、**人類示範學習（Learning from Human Demonstration）**與**桌面工作流程自動化**的業界研發人員亦具高度參考價值。

## 深度分析

#### 方法論解析

Work2Skill 的方法論設計圍繞三個相互耦合的元件展開，試圖解決 GUI 代理（GUI Agent）從人類示範中歸納可重複使用技能時面臨的三個核心挑戰：動作定位（Action Grounding）的語義模糊、方法比較的基準不一致、以及證據檢查（Evidence Inspection）的僵化流程。

**WorkRecorder 的多模態證據對齊機制**

WorkRecorder 是 Work2Skill 的基礎設施層，其核心設計理念在於將人類操作過程中的異質性輸入流（螢幕錄影、滑鼠與鍵盤事件、無障礙樹 AX 資訊）進行時間軸對齊與語義關聯。具體而言，系統在每個動作觸發時擷取對應的關鍵畫面（Keyframe），並將該畫面與輸入事件、AX 結構化資訊、以及應用程式/作業系統狀態綁定，形成一個「證據鏈」（Evidence Chain）。這種設計的關鍵優勢在於：當動作座標（Action Coordinate）僅能告訴代理「在哪裡點擊」時，AX 樹中的元素名稱（Element Name）與 UI 角色（UI Role）則提供了「點擊了什麼」的語義資訊，而關聯影片（Linked Video）保留了操作前後的狀態變化（State Change）與暫態（Transient State）。相較於 ShowUI-Aloha 僅依賴全螢幕畫面與目標裁切（Target Crop）的視覺定位（Visual Grounding）方式，以及 Demo2Tutorial 採用前後對比截圖（Before-and-After Screenshot）的做法，WorkRecorder 透過結構化 UI 證據（Structured UI Evidence）與視覺脈絡（Visual Context）的雙重錨定，顯著降低了動作語義推論的不確定性。

**WorkDemo-350 的資料集建構原則**

WorkDemo-350 收錄 350 筆經過完整性與任務成功篩選的人類桌面 GUI 示範（Desktop GUI Demonstration），涵蓋 64 個 MyPCBench Bounded Action 任務與 286 個 OSWorld-Verified 子集任務。這個資料集的核心價值不在於規模，而在於其作為「共通示範資源」（Common Demonstration Resource）的角色：所有方法在相同的來源經驗（Source Experience）與評估條件（Evaluation Condition）下進行比較，從而分離出歸納方法本身的差異，而非來源資料或評測協議的混雜效應。資料集封裝了同步的視覺證據、動作證據與 AX 資訊，使其能同時支援技能歸納（Skill Induction）與下游評估（Downstream Evaluation）。

**代理式技能歸納方法的程序設計**

代理式技能歸納（Agentic Skill Induction）是 Work2Skill 最具方法論創新性的部分。其設計哲學在於打破傳統管線式（Pipeline）方法中「先解析動作、再抽象程序」的預定義階段耦合。具體而言，該方法將證據檢查與技能撰寫交錯進行：歸納代理（Induction Agent）首先識別資訊需求（Identify Information Needs），接著透過工具（如 list_directory、glob、read_visual_evidence、watch_video、extract_video_frames 等）進行探索式證據擷取（Explore with Tools），然後更新假設並解決不確定性（Update Hypothesis & Resolve Uncertainty），最後將結果寫入技能工作區（Skill Workspace）。這種「按需證據檢查」（On-Demand Evidence Inspection）的設計直接借鑑了代理式影片理解（Agentic Video Understanding）中的主動證據獲取（Active Evidence Acquisition）思想，有效緩解了將長錄影一次性載入上下文所造成的上下文壓力（Context Pressure），同時避免了固定畫面選取（Frame Selection）可能遺漏關鍵細節的風險。

在技能撰寫階段，方法引導代理將示範特定的輸入（例如具體的儲存格座標、特定檔名）泛化為任務相依的描述（Task-Dependent Descriptions），同時保留三類核心結構性資訊：工作流程規則（Workflow Rule）、步驟相依性（Step Dependency）、以及完成檢查（Completion Check）。最終產出的技能能夠在沒有原始錄影的情況下引導代理執行，這是「可重複使用」（Reusable）的關鍵意涵。

#### 實驗數據解讀

Work2Skill 的實驗設計在多個維度上展現了嚴謹性，其數據結果可從以下幾個層面解讀：

**基準比較的量化效益**

在 MyPCBench Bounded Action 上，Work2Skill 相較於無技能基準（No Skill Baseline）在四個執行模型（Execution Model）上實現了 4.67 至 10.54 分的平均分數提升（Mean Score Improvement）；在 286 任務的 OSWorld-Verified 子集上，提升幅度為 3.11 至 7.50 分。這兩個數字區間的差異值得注意：MyPCBench 的提升幅度較大，可能反映其任務特性更依賴程序性知識（Procedural Knowledge）；而 OSWorld-Verified 的提升幅度較小但仍顯著，說明在更複雜的真實桌面環境中，技能歸納仍能帶來穩定的效益。重要的是，Work2Skill 在所有四個執行模型下均達到了最高分數與最高成功率（Success Rate），這意味著其效益並非依賴特定模型的優勢，而是具有跨模型的泛化能力。

**消融實驗的設計意涵**

論文提及的證據消融（Evidence Ablation）與管線提示詞比較（Pipeline Prompt Comparison）兩類分析，分別檢驗了輸入模態與歸納提示詞設計的角色。證據消融透過移除特定模態（例如僅保留視覺或僅保留 AX 資訊）來量化各模態的貢獻，這呼應了論文中「多模態證據改善技能品質」（Multimodal evidence improves skill quality）的核心發現。管線提示詞比較則將代理式方法與傳統管線式提示詞進行對比，驗證了「適應性探索優於固定證據處理」（Adaptive exploration outperforms fixed evidence processing）這一假設。

**泛化性測試的多重驗證**

論文設計了兩類泛化性測試：MyPCBench Jitter 測試在同應用程式內改變需求時技能的適應能力，跨模型轉移測試則檢驗技能在不同執行模型間的可移植性。這兩個測試共同支撐了「歸納技能可跨模型與任務泛化」（Induced skills generalize across models and tasks）的結論。從方法論角度，這種泛化性測試比單純的基準比較更能說明技能的「可重複使用」特性，因為真正的可重複使用不僅要求在相同任務上表現良好，更要求在變化情境下保持效用。

**基準方法的公平對齊**

值得注意的是，論文中將 ShowUI-Aloha 與 Demo2Tutorial 改編為「文字引導版本」（Text-Adapted Version），使其能在共享的文字引導介面下與 Work2Skill 比較。這種改編確保了比較的公平性：所有方法都基於相同的任務指令與執行環境，差異僅在於技能的來源與形式。這種控制變量的實驗設計提升了結論的可信度。

#### 與現有研究的比較

Work2Skill 在 GUI 代理從人類示範學習的研究譜系中佔據獨特位置，其與現有工作的關係可從三個維度分析：

**與學術方法的比較**

相較於 ShowUI-Aloha 將示範轉換為專家指令與語義動作軌跡（Semantic Action Trace）的方法，Work2Skill 的差異在於保留了更豐富的結構化證據（AX 資訊）並採用了更靈活的歸納程序。ShowUI-Aloha 依賴視覺定位推論目標語義，這在面對複雜 UI 元素時容易產生歧義；而 Work2Skill 透過 AX 樹直接獲取元素名稱與角色，降低了語義推論的負擔。相較於 Demo2Tutorial 使用前後對比截圖生成多模態教學（Multimodal Tutorial）的方法，Work2Skill 的優勢在於時間軸對齊的細粒度證據鏈，能夠捕捉中間操作（Intermediate Operation）與暫態，這對於理解多步驟工作流程至關重要。

**與工業產品的定位差異**

OpenAI 的 Record & Replay 與 Anthropic 的 Record a skill 將示範學習帶入面向使用者工具（User-Facing Tool）的層級，但這些產品側重於記錄與重放，而非抽象出可泛化的技能。Work2Skill 的學術定位在於系統性地研究「如何從示範中歸納出真正可重複使用的技能」，其方法論貢獻在於證據檢查的程序設計與技能結構的形式化，這是現有工業產品所缺乏的理論深度。

**方法論限制的坦誠面對**

儘管 Work2Skill 在多項指標上表現優異，其方法仍存在若干限制。首先，WorkDemo-350 的 350 筆示範規模相對有限，雖然經過嚴格篩選，但對於覆蓋多樣化軟體與工作流程而言仍可能不足。其次，代理式歸納方法的效能高度依賴底層大型語言模型的工具使用能力與視覺理解能力，這意味著其表現可能隨模型版本而波動。第三，技能歸納的品質評估目前主要透過下游執行表現間接測量，缺乏對技能本身品質（例如可讀性、完整性、可修改性）的直接評估指標。最後，論文中提及的「任務特定細節」（Task-Specific Detail）與「工作流程規則」（Workflow Rule）的分離是一個核心挑戰，但目前的方法如何處理邊界案例（例如示範中包含錯誤操作或探索性行為）尚不明確。

#### 可重現性評估

Work2Skill 在可重現性方面展現了良好的實踐：

**程式碼與資料的開放性**

論文明確聲明程式碼與資料可於 https://github.com/china-qijizhifeng/Work2Skill 取得，這為研究者重現實驗結果與基於此框架進行後續研究提供了基礎。WorkDemo-350 作為同步多模態資料集（Synchronized Multimodal Dataset），其封裝的視覺、動作與 AX 證據使得其他研究者能在相同的來源經驗上測試不同的歸納方法，這對於該領域的累積性發展至關重要。

**評估協議的標準化**

論文採用官方評估器（Official Evaluator）與共享的文字引導介面進行下游評估，這種標準化的評估協議（Evaluation Protocol）提升了結果的可比較性。MyPCBench Bounded Action 與 OSWorld-Verified 作為兩個獨立的基準（Benchmark），提供了跨環境的驗證。

**可重現性的潛在限制**

然而，若干因素可能影響完全重現：代理式歸納方法涉及大型語言模型的隨機性，相同的輸入可能產生略有不同的技能；WorkRecorder 的部署需要特定的環境配置（虛擬機、AX 資訊擷取工具等），這增加了重現的技術門檻；此外，論文中提及的四個執行模型的具體身份與版本未在提供的文本中明確說明，這可能影響跨實驗室的精確對齊。

#### 未來研究方向

Work2Skill 開啟了多個值得深入探索的研究方向：

**技能品質的形式化評估**

目前技能的效用透過下游執行表現間接測量，未來可發展對技能本身的直接評估指標，例如可讀性評分、步驟完整性檢查、跨任務可移植性測試等。這將有助於更精細地診斷歸納方法的優勢與不足。

**示範規模與多樣性的擴展**

WorkDemo-350 的 350 筆示範雖然品質嚴控，但規模有限。未來可探索更大規模、更多樣化軟體與工作流程的示範收集，並研究歸納方法在不同規模下的效能變化趨勢。

**錯誤處理與探索性行為的建模**

人類示範中常包含錯誤恢復、探索性嘗試等非線性行為。目前的方法如何處理這些複雜情況，以及如何從中歸納出魯棒的技能，是一個重要的開放問題。

**跨模態證據權重的自適應學習**

WorkRecorder 整合了視覺、動作、AX 三類證據，但各模態在不同任務中的相對重要性可能不同。未來可研究讓代理式方法自適應地學習證據權重，而非依賴固定的檢查順序。

**技能組合與層次化抽象**

當前的技能歸納主要處理單一工作流程，未來可探索如何將多個技能組合成更高層次的工作流，以及如何建立技能的層次化抽象結構，使其能支援更複雜的任務規劃。

**與強化學習的結合**

技能歸納提供了先驗程序性知識，未來可探索將歸納技能作為強化學習的初始化或獎勵塑形（Reward Shaping）信號，進一步提升代理在陌生環境中的學習效率。

**隱私與安全考量**

人類示範可能包含敏感資訊（密碼、個人資料等），未來需要研究如何在保留程序性知識的同時保護隱私，這對於 Work2Skill 在企業環境中的部署至關重要。

## 論文問答

**Q1：Work2Skill 試圖解決的核心問題是什麼？**
A：Work2Skill 試圖解決電腦使用代理在面對不熟悉軟體與工作流程時效能低落的核心問題。當使用者提出「提交我的報銷」這類任務時，指令本身並未指明應使用哪個內部入口、需附加哪些收據、或提交前應檢查哪些項目，而這些正是成功執行所需的程序性知識。Work2Skill 透過從人類 GUI 示範中歸納出可重複使用的技能，填補了使用者目標與具體 GUI 動作之間的知識鴻溝，使代理能將抽象的使用者意圖轉化為可執行的程序步驟。

**Q2：為何現有的 GUI 代理方法在處理不熟悉軟體時會失敗？**
A：現有方法主要依賴視覺定位從全螢幕畫面或前後對比截圖推斷目標控制項的語義，但缺乏無障礙樹（AX）等結構化 UI 證據時，這種推斷容易產生歧義。此外，固定的畫面選取策略可能遺漏暫態與中間操作，導致動作解析不完整。更根本的問題在於，這些方法將動作解析與程序抽象耦合在預先定義的管線階段中，無法在需要時回頭檢查細節，使得代理難以從單次示範中提煉出可泛化的程序性知識。

**Q3：為何人類示範是解決此問題的理想知識來源？**
A：人類與電腦使用代理共享相同的 GUI 互動空間，因此人類示範中的控制操作、動作序列與可見結果能直接引導代理的執行。相較於靜態文件或口頭說明，示範承載了豐富的程序性知識，包含工作流程規則、步驟相依性與完成檢查等隱性資訊。透過 WorkRecorder 對齊螢幕錄影、滑鼠鍵盤事件與 AX 資訊，這些示範得以被完整保留並供後續技能歸納使用，使代理能從真實的人類操作經驗中學習。

**Q4：Work2Skill 的三個核心組件分別是什麼？**
A：Work2Skill 由三個相互銜接的組件構成：WorkRecorder 負責擷取人類 GUI 經驗，對齊螢幕錄影、滑鼠鍵盤事件與可用的 AX 資訊；WorkDemo-350 是以此基礎建設蒐集的首個同步多模態桌面 GUI 示範資料集，涵蓋 350 個經完整性與任務成功篩選的示範；代理式技能歸納方法則在需要時主動檢查證據，從示範中提煉出捕捉工作流程規則、步驟相依性與完成檢查的可重複使用技能。

**Q5：代理式技能歸納方法的關鍵創新為何？**
A：此方法的關鍵創新在於將「按需證據檢查」與「技能撰寫與修訂」交錯進行，而非遵循預先定義的固定管線。歸納代理會主動識別資訊需求、探索工具、提出假設並解決不確定性，必要時可重新檢視來源錄影而不必一次載入整段內容。這種設計緩解了長錄影帶來的上下文壓力，也避免了固定子集選取可能遺漏細節的問題，使技能歸納過程更具適應性與精確性。

**Q6：WorkRecorder 為何要將螢幕錄影與 AX 資訊對齊？**
A：單獨的動作座標僅能告訴代理「在哪裡」發生了操作，卻無法說明「該控制項代表什麼意義」。WorkRecorder 透過對齊螢幕錄影、滑鼠鍵盤事件與 AX 資訊，使記錄下來的元素名稱與 UI 角色提供明確的控制項語義，而關聯影片則保留了周圍的狀態變化。這種雙重證據讓歸納代理能同時利用視覺脈絡與結構化 UI 證據來詮釋操作，大幅降低動作定位的歧義性。

**Q7：實驗使用了哪些基準測試？選擇的理由為何？**
A：實驗採用 MyPCBench Bounded Action 與 OSWorld-Verified 的 286 任務子集作為評估基準。MyPCBench 涵蓋 64 個任務，能測試代理在受控動作空間下的執行能力；OSWorld-Verified 則提供更真實且多樣化的桌面環境挑戰。兩者結合既能在標準化條件下比較方法差異，也能在開放環境中驗證技能的泛化性，並透過官方評估器與共享的文字指引介面確保比較的公平性。

**Q8：Work2Skill 的主要量化結果為何？**
A：在四種執行模型下，Work2Skill 在兩個基準上均達到最高分數與最高成功率。相較於無技能基準，Work2Skill 在 MyPCBench Bounded Action 上帶來 4.67 至 10.54 分的平均分數提升，在 OSWorld-Verified 的 286 任務子集上則帶來 3.11 至 7.50 分的提升。這些結果顯示，從人類示範中歸納出的可重複使用技能能穩定地改善代理表現，且改善幅度跨模型一致。

**Q9：消融實驗揭示了哪些關於輸入模態與提示設計的發現？**
A：證據消融實驗顯示，多模態證據（包括影片、影像與 AX 資訊）的組合能顯著提升技能品質，移除任一模態都會導致效能下降。Pipeline Prompt 比較則證明，採用按需探索的自適應方法優於固定證據處理流程，因為後者無法在需要時回頭檢查細節。這些發現共同強調了靈活的證據檢查機制與豐富的多模態輸入對於高品質技能歸納的重要性。

**Q10：Work2Skill 最能發揮價值的實務場景為何？**
A：Work2Skill 特別適用於企業內部流程自動化，例如報銷提交、報表生成、合規審查等需要遵循特定組織程序但缺乏明確書面指引的任務。在這些場景中，領域知識通常存在於資深員工的習慣操作中，新進員工或 AI 代理難以從通用文件中習得。透過錄製專家示範並歸納為技能，組織能將隱性程序知識轉化為可重複使用的資產，降低人員異動帶來的知識流失風險。

**Q11：Work2Skill 與 OpenAI Record & Replay、Claude Record a skill 等商業工具有何異同？**
A：三者共享「從人類示範中學習」的核心理念，但 Work2Skill 在學術框架下提供了更嚴謹的方法比較與評估協議。商業工具側重於使用者體驗與即時可用性，而 Work2Skill 則強調同步多模態資料集的建立、跨模型的技能轉移驗證、以及按需證據檢查的歸納方法。此外，Work2Skill 透過 WorkDemo-350 提供了公開的共通示範資源，使不同歸納方法能在相同條件下公平比較。

**Q12：Work2Skill 對 GUI 代理領域的更廣泛影響為何？**
A：Work2Skill 推動了 GUI 代理研究從「通用能力建構」向「個人化與組織化知識整合」的方向演進，證明了人類示範作為程序性知識來源的可行性。其貢獻的 WorkDemo-350 資料集與 WorkRecorder 基礎建設為後續研究提供了可重複使用的實驗平台，而代理式技能歸納方法則為處理長序列多模態證據提供了新的範式。這些進展有望促進 GUI 代理在企業、教育與專業服務等領域的實際部署。

**Q13：Work2Skill 存在哪些已承認的限制？**
A：Work2Skill 目前主要在桌面環境下驗證，對於行動裝置或網頁環境的適用性尚待確認。WorkDemo-350 的 350 個示範雖然經過篩選，但規模仍有限，可能無法涵蓋所有軟體與任務類型。此外，技能歸納的效果依賴於歸納代理的能力，當示範本身存在遺漏或錯誤時，歸納出的技能可能繼承這些缺陷，這是當前框架難以完全避免的風險。

**Q14：Work2Skill 可能遭遇哪些失敗案例或挑戰？**
A：在高度動態或視覺密集的介面中，僅靠 AX 資訊可能不足以完整描述操作意圖，導致技能歸納出現歧義。當示範任務與目標任務之間存在較大的介面或版本差異時，技能的轉移效果可能下降。此外，對於需要即時判斷或多分支決策的複雜工作流程，固定的技能描述可能無法涵蓋所有情境，需要代理具備額外的推理能力來處理例外情況。

**Q15：Work2Skill 開啟了哪些值得探索的未來方向？**
A：未來可將 Work2Skill 擴展至行動裝置與網頁環境，建立跨平台的統一示範資源與技能歸納框架。另一個方向是結合大型語言模型的推理能力，使歸納代理能處理更複雜的多分支工作流程與例外處理。此外，技能庫的累積、版本管理與跨使用者共享機制也是值得探索的課題，這將使 Work2Skill 從單次示範歸納工具演進為持續演化的組織知識管理系統。

## 實務應用指南

### 適用場景

1. **企業內部流程自動化**：員工示範如何提交報銷單、填寫請假申請、登打出貨單等內部系統操作，歸納出可重複使用技能供電腦使用代理執行，降低重複性人工作業。
2. **新進員工訓練與知識傳承**：資深員工示範如何使用內部工具（如 ERP、CRM、簽核系統），將程序性知識轉化為可重複使用技能文件，縮短新人上手時間。
3. **客服與技術支援自動化**：客服專家示範處理常見問題的步驟（如重設密碼、退款流程、帳號解鎖），歸納出技能供 AI 客服代理使用，提升回應效率。
4. **軟體遷移期間的流程保留**：在系統升級或介面改版前，記錄現有操作流程，確保業務不中斷並作為新系統流程設計參考。
5. **無障礙輔助與個人化自動化**：為身心障礙使用者或非技術背景人員自動化重複性高的桌面操作，將一次性示範轉化為可重複使用的個人化技能庫。

### 實作前置條件

**資料需求**
- 至少數十至數百筆人類 GUI 示範（WorkDemo-350 規模，含 64 個 MyPCBench Bounded Action 任務與 286 個 OSWorld-Verified 子集任務）。
- 螢幕錄影、滑鼠與鍵盤事件、無障礙樹（AX）資訊的同步擷取。
- 經過完整性與任務成功篩選的標註流程。
- 目標應用程式的可存取環境（虛擬機或容器化桌面）。

**運算需求**
- 支援長影片處理的視覺語言模型（VLM）。
- 具備代理式推理能力的大型語言模型（論文中使用 GPT-5.5，需支援工具呼叫與長 context）。
- 足夠的 context window 容納影片區間、影像與 AX 證據鏈。
- 影片抽幀、影像裁切、AX 解析等基礎工具鏈。
- 受控的虛擬機環境用於下游執行評估。

**技能門檻**
- GUI 自動化與無障礙樹（AX）概念理解。
- 代理框架設計與工具整合經驗。
- 影片理解與多模態模型應用能力。
- 提示工程、評估方法與基準測試設計經驗。

### 實作步驟建議

1. **部署 WorkRecorder 基礎設施**：建立螢幕錄影、輸入事件、無障礙樹資訊的同步擷取管線，確保動作觸發的關鍵畫面與時間戳精確對齊。
2. **收集領域專家示範**：邀請熟悉目標流程的人員執行任務並錄製，覆蓋目標應用程式的主要工作流程。
3. **篩選與驗證**：對每筆示範進行完整性（是否完成所有必要步驟）與任務成功（是否達成預期結果）檢查，淘汰不合格資料。
4. **建立證據鏈**：將每個動作與對應的截圖、輸入事件、AX 資訊關聯，形成可追溯的證據結構。
5. **執行代理式技能歸納**：讓歸納代理根據需求主動選取影片區間、影像與 AX 證據，撰寫包含工作流程規則、步驟相依性、完成檢查的可重複使用技能。
6. **下游執行評估**：在受控環境中以官方評估器（如 MyPCBench、OSWorld-Verified）與共享執行設定驗證技能效果，比較與無技能基準的差異。
7. **部署至生產代理**：將技能注入目標執行模型，建立技能版本管理、持續監控與定期重歸納機制。

### 潛在風險與注意事項

- **隱私與合規風險**：螢幕錄影可能擷取敏感資訊（個資、機密文件），需建立去識別化、加密儲存與存取控管機制，並符合 GDPR、HIPAA 等法規。
- **示範品質不穩定**：低品質、不完整或包含錯誤操作的示範會導致歸納出的技能不可靠，需要嚴格篩選並由領域專家覆核。
- **軟體版本變動導致技能失效**：UI 更新、功能改版可能使既有技能失效，需建立技能版本管理、失效偵測與自動重歸納流程。
- **Context window 限制**：長影片可能超出模型上下文，需採用分段檢查與按需載入策略，避免一次載入整段錄影。
- **技能過度具體化**：歸納過程若未妥善將任務特定細節泛化為任務相依描述，技能可能僅適用於單一任務而失去重用價值。
- **評估偏差與不可比性**：不同評估器、執行協議與任務集可能產生不一致的結果比較，應採用共享執行設定與官方評估器以確保公平比較。
- **代理推理成本**：代理式技能歸納需要多輪證據檢查與工具呼叫，推理成本與時間較高，需評估成本效益。

### 與其他技術的整合建議

- **RPA 平台整合**：將歸納出的技能轉換為 RPA 工作流程，與 UiPath、Automation Anywhere、Power Automate 等平台整合，擴展技能執行管道。
- **既有電腦使用代理**：作為外掛技能庫，提供程序性知識給 GPT-Computer-Use、Claude Computer Use 等代理，補強其在陌生軟體上的弱點。
- **知識管理系統**：將技能文件化並整合至企業 Wiki、Confluence、Notion 等知識庫，供人類員工查閱與代理呼叫。
- **MLOps/LLMops 管線**：建立技能歸納的持續訓練與評估管線，支援 A/B 測試、技能版本控管與效果監控。
- **內部系統 API 優先策略**：當 GUI 操作可由 API 取代時，提供 API 優先的混合執行策略，由代理自動選擇 GUI 或 API 管道。
- **企業 SSO 與權限管理**：整合企業身分驗證系統，確保技能執行時的權限控管與稽核紀錄。

### 給不同背景讀者的閱讀建議

**初學者**：建議先閱讀摘要與圖 1，理解 Work2Skill 框架的三個組成部分（WorkRecorder、WorkDemo-350、代理式技能歸納）的功能與互動關係，再瀏覽使用案例章節建立直觀認識；可暫時略過方法細節，聚焦於「人類示範如何轉化為代理技能」的核心概念。

**AI 工程師**：重點閱讀方法章節，特別是代理式技能歸納的證據檢查迴圈與技能撰寫提示設計；同時關注 WorkRecorder 的資料結構與證據鏈建構方式，作為實作參考；評估章節的共享執行設定與跨模型轉移實驗，對於設計自家代理的評估管線很有價值。

**研究者**：深入閱讀相關工作比較、消融實驗與評估設計，特別是不同歸納方法在共享執行設定下的公平比較框架，以及跨模型轉移實驗的設計意涵；WorkDemo-350 作為首個同步多模態桌面 GUI 示範資料集，可作為後續研究的基準資源。

**產品經理**：聚焦於使用案例與效益數據（平均分數提升 4.67–10.54 點），評估導入 Work2Skill 對企業流程自動化的 ROI；同時關注隱私、版本管理與評估偏差等落地風險，並思考與現有 RPA、知識管理系統的整合路徑。
