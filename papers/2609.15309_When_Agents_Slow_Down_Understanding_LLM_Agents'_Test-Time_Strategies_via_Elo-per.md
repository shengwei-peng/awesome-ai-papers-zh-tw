# 當智能體放緩時：以每 token Elo 分析理解 LLM 智能體的測試時策略

## ⚡ TL;DR

LLM 智能體的測試時運算策略難以衡量效能擴展。
本文提出每token Elo分析，以Bradley–Terry模型聚合任務內排序為可比較評分。
實驗顯示智能體最終不優於獨立取樣，而人類持續超線性進步；按擴展拐點分配預算可顯著提升Elo。

## 摘要翻譯

大型語言模型（LLM）智能體（agents）在修訂解答、使用工具、探索替代方案與決定何時停止的過程中，會自適應地分配測試時運算量（test-time compute）。這種測試時策略使得衡量智能體效能如何隨測試時運算量擴展變得困難。我們研究會為中間提交（intermediate submissions）提供連續分數（continuous scores）的開放式任務（open-ended tasks），使漫長軌跡中的進展均可被觀察。我們提出每 token Elo 分析（Elo-per-token analysis），追蹤每個 token 預算（token budget）下找到的最佳解，並使用 Bradley–Terry 模型將任務內排序（within-task orderings）聚合為跨不同分數尺度任務的 Elo 評分（Elo ratings）。我們將其應用於四個通用智能體（general-purpose agents）在四個開放式基準測試（open-ended benchmarks）上的表現，每場次（per-session）高達一億個 token，以及在三個受控單任務介入（single-task interventions）中的回饋驅動 LLM 優化框架（feedback-driven LLM optimization harnesses）。獨立取樣（Independent sampling）提供了一個理論上已有完整刻畫的參考基準，其 Elo 隨對數運算量（log compute）線性成長。相較於此參考基準，智能體起初將 token 轉換為 Elo 的速度快於獨立取樣，但邊際增益（marginal gains）會遞減，最終低於該參考基準。相對地，在共同的 AtCoder 啟發式競賽（AtCoder Heuristic Contest）任務上，歷史上最強的人類參賽者會在競賽時間內呈現超線性進步，為持續學習（continual learning）提供了證據，並在智能體放緩後仍有顯著進步空間。我們將擴展拐點（scaling inflection point）定義為邊際 Elo 增益與獨立取樣參考基準相符的每場次預算（per-session budget）。以此點作為每場次預算，我們在 FrontierCS 多格骨牌填裝（FrontierCS Polyomino Packing）上將一億個 token 分散到多個平行場次（parallel sessions），相較於一場長場次獲得 +264 Elo，相較於十場短場次則獲得 +355 Elo。

### 核心貢獻（3～5點）
- 提出每 token Elo 分析方法，結合 Bradley–Terry 模型聚合任務內排序，解決開放式任務中智能體測試時擴展難以衡量的問題。
- 大規模評估四個通用智能體在四個開放式基準測試上的表現，並與三個回饋驅動 LLM 優化框架的受控單任務介入進行比較。
- 發現智能體初期將 token 轉換為 Elo 的效率雖高於獨立取樣，但邊際增益會遞減並最終落後；相對地，人類參賽者呈現超線性進步，顯示持續學習與顯著進步空間。
- 定義擴展拐點作為最佳每場次預算，並驗證在 FrontierCS 多格骨牌填裝上將 token 分散到平行場次可顯著提升 Elo。

### 適合對象
對 LLM 智能體、測試時擴展、開放式任務評估及人機比較感興趣的研究人員與工程師，特別是從事推理模型、程式設計智能體、啟發式競賽及大規模 LLM 評估相關領域者。

## 深度分析

#### 方法論解析

本研究的核心方法是**每 token Elo 分析（Elo-per-token analysis）**，其目標是將不同系統、不同預算與不同任務上的表現放到同一個可比較的尺度上，並追蹤「隨著測試時運算量（test-time compute）增加，表現如何變化」這一動態過程。

##### 開放式任務與連續分數的優勢

傳統基準測試如 **SWE-bench** 通常只在最後給出一個**通過或失敗判定（pass-or-fail verdict）**，整條解題**軌跡（trajectory）**中的中間狀態被丟棄。相對地，**開放式任務（open-ended tasks）**—例如 **GPU 核心優化（GPU-kernel optimization）**、**啟發式程式設計競賽（heuristic programming contests）**—會對每一次**中間提交（intermediate submissions）**給出一個**純量分數（scalar score）**。這使得研究者可以觀察解題品質如何在長軌跡中逐步演化。

然而，**原始分數（raw scores）**本身不適合直接作為跨任務或跨系統的比較指標：不同任務使用不同單位，且同一任務內相同分數增量未必代表相同進步（例如從 80% 提升到 81% 通常遠比從 50% 到 60% 困難）。因此，本文選擇對提交進行「評分」而非「計分」。

##### Elo-per-token 的建構流程

1. **在每個 token 預算（token budget）下擷取最佳解**：對於每個系統在每個累積 token 數量，記錄到該點為止**找到的最佳解（best solution found）**。
2. **任務內成對比較（pairwise comparison）**：在同一任務與同一評測系統（judge）下，將不同系統、不同預算產生的最佳解兩兩比較。
3. **Bradley–Terry 模型聚合**：利用 **Bradley–Terry 模型（Bradley–Terry model）** 將這些**任務內排序（within-task orderings）**整合為單一的 **Elo 評分（Elo ratings）**。數學上，若系統 i 與 j 的潛在強度為 r_i、r_j，則 i 勝過 j 的機率可寫為  
   \[
   P(i \succ j)=\frac{e^{r_i}}{e^{r_i}+e^{r_j}}.
   \]
   透過最大概似估計擬合後，即可得到每個「系統—預算」組合的 Elo 值。

由於 Elo 只依賴同一任務內的相對排序，它對原始分數的非線性變換具有穩健性，也能跨任務比較。這讓 Elo-per-token 曲線成為一個「運算量感知」的評估工具。

##### 獨立取樣（independent sampling）作為理論參考

作者證明了一個重要的理論基準：如果將同一問題獨立解題 k 次並保留最佳嘗試，其 Elo 會與 **對數運算量（log compute）** 呈線性成長。更具體地，每增加一個數量級（decade）的運算量，約可獲得 400 Elo 的增益。這是一個**無分布假設（distribution-free）**的參考斜率，因為它僅來自「重複獨立嘗試並取最佳」這一記憶less 程序。

這條參考線的意義在於：它提供了一個判斷智能體策略是否「值得繼續投入更多 token」的客觀標準。若某策略的邊際 Elo 增益高於此斜率，則繼續投入比重新獨立取樣更有效；反之則應該停止或改採平行場次。

##### 擴展拐點（scaling inflection point）與預算分配

作者定義**擴展拐點（scaling inflection point）**為：在單一場次中，**邊際增益（marginal gains）**剛好等於獨立取樣參考斜率時的**每場次預算（per-session budget）**。以此預算為單位，可以決定一筆固定總 token 預算應該投入單一長場次，還是分割成多個**平行場次（parallel sessions）**。直覺上，當單場次的邊際效益低於獨立取樣時，將預算分散到多個獨立嘗試會更有效。

#### 實驗數據解讀

本文的實驗設計分為兩大主軸：一是在四個開放式基準測試上評估四個通用 **LLM 智能體（LLM agents）**，單場次最長達到 100M tokens；二是在三個**回饋驅動的 LLM 優化框架（feedback-driven LLM optimization harnesses）**中進行控制性的**單任務介入（single-task interventions）**。

##### 發現一：智能體終究退化成獨立取樣

實驗顯示，**Claude Code**、**Codex** 等通用程式設計智能體（coding agents）在軌跡初期能夠以高於獨立取樣的效率將 token 轉換為 Elo。這通常發生在它們進行迭代修訂（iterative revision）、工具呼叫與錯誤修正的階段。然而，經過最初幾次**上下文視窗壓縮（context-window compactions）**後，邊際增益迅速遞減，最終落在獨立取樣參考線之下，甚至更低。

這意味著：現有智能體雖然具備某種程度的「內部策略」，但它們無法在單一長軌跡中持續累積對問題的結構化理解。當上下文被壓縮或歷史資訊變得龐大時，它們的行為越來越接近**無記憶取樣（memoryless sampling）**。

##### 發現二：人類參賽者展現持續學習的超線性成長

在 **AtCoder 啟發式競賽（AtCoder Heuristic Contest）** 任務上，作者將智能體與歷史**專家人類參賽者（expert human contestants）**的提交記錄以相同評測系統重新評分。結果顯示，智能體在一天內便趨於平緩，而最強人類參賽者則在數天內持續**超線性（superlinear）**進步，最終超越智能體。

這提供了**持續學習（continual learning）**存在的實證：人類在解題過程中會不斷累積對問題結構、陷阱與啟發式的認識，而現有 LLM 智能體缺乏這種在單一任務內的知識累積機制。這也暗示智能體在開放式任務上仍有相當大的成長空間。

##### 發現三：擴展拐點可有效指導預算分配

在 **FrontierCS 多格骨牌填裝（FrontierCS Polyomino Packing）** 上，總預算為 100M tokens 時，作者將預算依據擴展拐點分為三個平行場次，結果相較於單一長場次提升了 +264 Elo，相較於十個短場次提升了 +355 Elo。在 **MLS-Bench** 上，以擴展拐點為基礎的分配同樣優於「全部集中」或「全部分散」這兩種極端。

這驗證了 Elo-per-token 不僅是描述性指標，更具有規範性價值：它可以告訴我們在給定總運算量下，應該讓單一智能體探索多深、又該啟動多少獨立嘗試。

#### 與現有研究的比較

##### 相對於測試時擴展（TTS）文獻

現有 **測試時擴展（test-time scaling, TTS）** 研究多聚焦於**推理模型（reasoning models）**，其策略由外部控制，例如**重複取樣（repeated sampling）**、**迭代修訂（iterative revision）**或**樹狀搜尋（tree search）**。這些方法通常比較「在固定預算下哪個策略較好」，但無法回答「繼續投入更多 token 是否仍然划算」。

本文的關鍵區別在於：**LLM 智能體（LLM agents）** 的測試時策略是由智能體自主執行（呼叫工具、接收環境回饋、決定何時停止）。因此，本文追蹤的是策略在整條軌跡上的**邊際價值**，而非僅終點表現。

##### 相對於成對評分與競技場方法

**Chatbot Arena** 等系統也使用成對比較與 Elo 來評估模型回應，但它們評比的是「對同一提示的最終回應」。本文則將評比的單位從「最終產物」擴展為「系統在某一 token 預算下的最佳解」，使 Elo 成為預算的函數。這與競賽程式設計中將模型與人類參賽者對齊 Elo 的做法也有概念上的延續，但進一步納入了動態預算維度。

##### 相對於 EdgeBench 等同期工作

同期工作 **EdgeBench** 對原始表現與互動時間的關係擬合一個 log-sigmoid 曲線，能描述智能體改善的形狀，但缺乏一個客觀參考來判斷飽和是否「過早」。本文提出的獨立取樣參考斜率正好填補這個缺口：任何偏離 400 Elo/decade 的偏差都可以解讀為策略效率高於或低於無記憶取樣。進一步地，這個參考斜率還能導出具體的固定預算分配規則。

##### 主要貢獻與限制

貢獻可歸納為三點：
1. 提出 Elo-per-token，統一衡量智能體、取樣基線與人類參賽者在不同任務與預算下的表現。
2. 證明獨立取樣的 Elo 與 log compute 線性成長，並實證顯示現有智能體在幾次上下文視窗壓縮後不再優於此定律。
3. 提出擴展拐點，作為固定預算下分割場次的決策依據。

限制方面：
- 僅適用於具有連續分數與可重複評測系統的開放式任務，無法直接套用於只有二元結果的任務。
- Elo 本質上是相對排序，若競爭者池或任務集合改變，絕對數值可能漂移。
- Bradley–Terry 模型假設可傳遞性與穩定的評測環境，實際上評測系統誤差或任務難度異質性可能影響估計。
- 實驗雖長達 100M tokens，但仍未解釋智能體內部為何會在上下文壓縮後失去效率。
- 人類比較僅限於 AtCoder Heuristic Contest，樣本與領域覆蓋有限。

#### 可重現性評估

從提供的文本來看，作者並未明確說明是否釋出原始碼、資料集或模型權重。由於實驗涉及 **Claude Code**、**Codex** 等專有模型與 API，即使論文詳細描述方法，若未公開完整提示詞、工具設定與軌跡記錄，其他研究者仍難以完全重現相同結果。

要重現本研究，至少需要以下元件：
- 每個場次的**中間提交（intermediate submissions）**記錄，以及對應的累積 token 數。
- 對所有提交進行重新評測（rejudging）的流程，以確保人類與智能體在相同評測系統下比較。
- Bradley–Terry 擬合程式與成對比較矩陣，讓社群能驗證 Elo 曲線的計算。
- 各任務的擴展拐點估計與預算分配細節。

此外，單場次高達 100M tokens 的實驗成本相當高昂，對學術界與開源社群的驗證構成實質門檻。建議作者釋出：
1. 去除敏感資訊後的原始軌跡；
2. 每個「系統—預算」點的最佳解與成對比較結果；
3. 可執行的 Elo 擬合與視覺化腳本；
4. 各任務的擴展拐點與預算分配建議表。

這將大幅提升研究的可重現性與後續比較的公平性。

#### 未來研究方向

1. **持續學習機制設計**：開發能夠在單一任務內累積結構化知識的智能體架構，例如自動建立啟發式庫、錯誤模式庫或問題分解筆記，以縮小人類超線性成長與智能體記憶less 取樣之間的差距。

2. **線上邊際 Elo 估計與自適應停止**：讓智能體在執行過程中即時估計自身的邊際 Elo 增益，並據此決定何時停止、何時重新啟動新場次，或何時切換策略。

3. **上下文管理與長軌跡記憶**：研究如何減少**上下文視窗壓縮（context-window compactions）**帶來的效能損失，例如發展更精選的記憶摘要、檢索機制或外部知識庫，使長軌跡仍能保持高效學習。

4. **擴展至其他領域**：將 Elo-per-token 框架應用到具有連續或部分回饋的任務，例如數學定理證明、機器人控制、科學實驗設計或藥物分子生成。

5. **超越無記憶取樣的理論模型**：建立能描述「具記憶、具學習能力智能體」的擴展定律，並分析其與獨立取樣參考線的漸近關係。

6. **多智能體與人口為本方法**：探索多個平行場次之間的知識遷移、演化搜尋或群體智慧，讓平行場次不只是獨立取樣，而是能互相學習的群體。

7. **人機協作擴展**：研究如何結合人類的持續學習能力與智能體的大規模取樣能力，例如讓人類在關鍵節點介入引導，或讓智能體輔助人類快速探索解空間。

8. **開放式任務的標準化基礎設施**：建立公開的軌跡資料庫、標準化評測流程與可重現的 Elo 評估工具，降低後續研究的進入門檻，並促進跨論文的公平比較。

## 論文問答

**Q1：這篇論文想要解決的核心問題是什麼？**

A：這篇論文聚焦於如何衡量 LLM 智能體在測試時擴展（test-time scaling）過程中，額外投入的 token 預算究竟能轉化為多少效能提升。與傳統推理模型可由外部控制重複取樣或迭代修訂不同，LLM 智能體會自行決定何時修訂解、呼叫工具、探索替代方案或停止，因此其測試時策略難以直接觀察與比較。作者提出的核心問題是：隨著測試時運算量增加，智能體的表現究竟如何擴展？這個問題對於理解智能體是否比獨立取樣更有效率地利用運算資源至關重要。

**Q2：為什麼傳統基準測試與原始分數無法直接回答這個問題？**

A：傳統基準如 SWE-bench 通常只給出最終提交的一次通過或失敗判定，並且會丟棄整個軌跡，因此無法觀察智能體在長軌跡中逐步改進的過程。雖然開放式任務會對每次中間提交給出連續分數，但不同任務的原始分數單位不同，而且同一任務內相等分數增量並不代表相等進步，例如從 80% 提升到 81% 可能比從 50% 提升到 60% 更困難。因此，必須用基於任務內排序的評分方式，而非直接使用原始分數，才能進行跨任務、跨預算的比較。

**Q3：測量智能體測試時擴展行為為什麼重要？**

A：測量擴展行為能夠判斷智能體的內部策略是否比單純的獨立取樣更快把運算量轉換成效能，這直接影響到固定預算下應該採用單場長時間執行還是多場平行執行。此外，這種測量也揭示了智能體與人類專家之間的持續學習差距：人類能在同一問題上持續累積知識並超線性進步，而現有智能體卻往往很快飽和。若無法準確量化這些現象，我們就難以設計出更高效的測試時策略與評估標準。

**Q4：什麼是每 token Elo 分析（Elo-per-token analysis）？**

A：每 token Elo 分析是一種把智能體在不同 token 預算下找到的最佳解進行成對比較，再透過 Bradley–Terry 模型聚合為 Elo 評分的方法。具體而言，它會追蹤在每個 token 預算下智能體目前為止找到的最佳提交，並將這些提交與同一任務下其他預算或其他系統的提交兩兩對決。由於 Elo 只依賴任務內的排序關係，因此可以跨越不同分數尺度的任務，把智能體、取樣基線與人類參賽者放在同一個共同尺度上比較。

**Q5：相較於過去的成對評分方法，每 token Elo 分析的關鍵創新在哪裡？**

A：過去的成對評分通常針對最終成品、單一回應或比賽結果給出固定評分，而每 token Elo 分析把「被評分的單位」定義為「某個系統在某個 token 預算下的狀態」，因此 Elo 成為運算量的函數而非單一排名。這使得研究者可以觀察智能體在軌跡中任何一點的邊際增益，並與獨立取樣的理論參考線比較。此外，論文證明獨立取樣會產生每十年運算量約 400 Elo 的線性成長，提供了一個無分布假設的基準來判斷智能體策略是否有效率。

**Q6：為什麼選擇使用 Bradley–Terry 模型與 Elo，而不是直接對原始分數做平均？**

A：原始分數在不同任務之間缺乏共同單位，而且同一任務內的分數往往呈現非線性，例如接近滿分時的微小提升可能代表極大困難。Bradley–Terry 模型與 Elo 評分只關心成對比較中的勝負排序，因此對原始分數的尺度和非線性不敏感。這種設計讓歷史人類提交記錄可以在相同評測系統下與智能體場次進入同一場「錦標賽」，從而實現跨任務、跨物種的公平比較。

**Q7：論文在哪些實驗設定上驗證了每 token Elo 分析？**

A：論文在四個開放式基準測試上評估了四個通用智能體，單場會話最長達到一億個 token；同時也在三個回饋驅動的 LLM 優化框架上進行控制性的單任務介入實驗。此外，作者還在 AtCoder 啟發式競賽的共享任務上，把智能體與最強的人類參賽者放在同一評測系統下比較。這些設定涵蓋了長軌跡觀察、控制實驗與人機對照，能夠從多個角度檢驗每 token Elo 分析的適用性。

**Q8：論文的兩大核心實證發現是什麼？**

A：第一個發現是，智能體在最初幾次上下文視窗壓縮之後，其每 token Elo 成長速度並不會超過獨立取樣，也就是說它們最終會「退化」到與無記憶取樣類似的擴展行為。第二個發現是，在 AtCoder 啟發式競賽任務上，最強的人類參賽者呈現超線性成長，能在數天內持續進步並超越智能體。這兩個結果共同指出：現有智能體缺乏在同一問題內持續累積知識的能力，而這正是人類表現持續提升的關鍵。

**Q9：論文中有哪些關於預算分配的消融或介入實驗結果？**

A：作者定義了擴展拐點，即每場會話的邊際 Elo 增益等於獨立取樣參考線時的 token 預算，並以此作為每場次預算來分配總 token。在 FrontierCS 多格骨牌填裝任務上，把一億 token 分成三場平行會話，比單一長會話高出 +264 Elo，也比分成十場短會話高出 +355 Elo。在 MLS-Bench 上，使用擴展拐點進行預算分配同樣優於極端配置，顯示該方法能夠指導固定總預算下的場次深度與場次數量取捨。

**Q10：每 token Elo 分析在實務上可以如何指導運算資源分配？**

A：透過追蹤每場會話的邊際 Elo 增益，產品團隊可以找到擴展拐點，也就是繼續投入 token 的效益剛好等於重新獨立取樣的臨界點。當總預算固定時，若單場邊際增益已低於參考線，就應該把預算切分成更多平行場次，以維持較高的整體 Elo 成長。一般而言，更大的總預算傾向於支持更多平行會話，這為部署時的運算排程與成本控管提供了可量化的決策依據。

**Q11：這些發現對智能體系統的產品設計有什麼啟示？**

A：研究顯示上下文視窗壓縮後智能體的擴展效率會迅速下降，這意味著現有系統的上下文管理與長期記憶仍然是重大瓶頸。產品團隊若希望讓智能體在長時間執行中持續進步，必須投資於更有效的記憶機制、軌跡摘要與持續學習能力，否則多數額外 token 只會產生類似獨立取樣的邊際效益。此外，在資源有限時，應根據擴展拐點決定何時停止單場執行並啟動新的平行場次，以避免浪費運算。

**Q12：每 token Elo 分析對整個 AI 評估領域可能帶來什麼影響？**

A：它為開放式任務提供了一個運算量感知的統一評估尺度，讓不同智能體、取樣基線與人類參賽者可以在同一標準下比較。這種方法把焦點從單一最終結果轉移到整個軌跡的邊際效率，有助於發現策略在何時開始失效。長遠來看，每 token Elo 分析可以成為衡量持續學習與測試時策略設計進展的重要工具，推動評估典範從靜態分數走向動態、資源感知的評分。

**Q13：這項研究有哪些已承認的限制？**

A：每 token Elo 分析需要任務具備連續分數與共享評測系統，才能對中間提交進行成對比較，因此不適用於只有最終通過或失敗判定的基準。此外，Bradley–Terry 模型假設成對比較能充分捕捉系統強度，可能無法反映某些複雜策略在特定子群上的差異。最後，雖然 Elo 對原始分數的非線性較不敏感，但它仍依賴評測系統的穩定性與可比性，若評測標準改變，歷史比較可能需要重新校正。

**Q14：論文指出了哪些智能體的失敗模式？**

A：最明顯的失敗模式是智能體在經過幾次上下文視窗壓縮後，其每 token 邊際 Elo 增益會跌至獨立取樣參考線以下，顯示長時間執行並未帶來持續進步。這代表智能體無法像人類一樣在同一問題內累積結構化知識，反而趨近於無記憶取樣。另一個失敗模式是若未妥善分配預算，把過多 token 投入單一長會話會導致整體 Elo 明顯低於適度平行化的配置。

**Q15：未來研究可以朝哪些方向延伸？**

A：未來可以發展具備真正持續學習與長期記憶的智能體，使其在單一問題上能夠像人類專家一樣超線性成長，而非在上下文壓縮後退化為獨立取樣。另一方面，可以將每 token Elo 分析擴展到更多類型的開放式任務，例如機器學習研究、GPU 核心優化或軟體工程長軌跡，以驗證其通用性。最後，結合主動學習、回饋驅動的提示優化與模型權重更新，或許能讓智能體在測試時不僅搜尋解空間，還能真正從軌跡中學習並提升後續決策品質。

## 實務應用指南

### 適用場景

1. **開放式演算法工程與啟發式競賽**  
   當任務會對每次中間提交給出連續分數（如 AtCoder 啟發式競賽、FrontierCS 多格骨牌填裝），可用每 token Elo 分析追蹤智能體在長軌跡中的進步，並決定何時該繼續迭代、何時該重開新場次。

2. **GPU 核心或系統層級自動優化**  
   在 GPU-kernel optimization、編譯器參數搜尋等場景，每次修改後都能取得效能純量分數。Elo-per-token 可將不同搜尋策略（迭代修訂、樹狀搜尋、平行獨立取樣）放在同一尺度上比較，找出真正的運算效率拐點。

3. **程式碼生成與除錯智能體的預算配置**  
   對於需要長時間執行的 coding agents（如 Claude Code、Codex），可用此方法判斷「把固定 token 預算投入單一長對話」與「拆成多場平行對話」哪個效益更高，避免上下文視窗壓縮後的邊際報酬遞減。

4. **回饋驅動的 LLM 優化框架評估**  
   在 prompt 優化、搜尋策略調參、模型權重微調等 feedback-driven harnesses 中，可用每 token Elo 作為穩定的評估指標，比較不同單任務介入手法在相同運算量下的學習曲線。

5. **人機協作與專家基準對齊**  
   當產品需要向客戶證明「AI 在特定開放式任務上達到或超越人類專家水準」時，可將歷史人類提交紀錄與智能體軌跡納入同一 Bradley–Terry 錦標賽，得到跨任務可比的 Elo 評分。

### 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **資料** | 每個任務必須能提供「中間提交的連續分數」或可比較的純量分數；若要比較人類，需要同一評測系統下的歷史提交紀錄。 |
| **運算** | 需能執行多場長軌跡實驗（論文中達 100M tokens），並記錄每場每個中間提交所消耗的累計 token 數。 |
| **技能** | 熟悉成對比較與 Bradley–Terry 模型擬合；具備設計評測系統（judge）與抽樣基準線（independent sampling）的能力。 |
| **工具** | 需有軌跡記錄與日誌系統、Elo 擬合函式庫（如 Python 的 `choix` 或自製 IRLS）、以及可重複執行平行場次的排程環境。 |

### 實作步驟建議

1. **定義可觀測的中間提交**  
   將任務從「最終通過／失敗」改成「每次提交都回傳純量分數」，確保軌跡中每個時間點的進步都可見。

2. **建立評測系統與成對比較資料**  
   對同一任務內的所有提交（來自不同智能體、不同 token 預算、或人類）兩兩比較，產生勝負紀錄。注意只使用任務內排序，避免跨任務原始分數直接比較。

3. **擬合 Elo 評分曲線**  
   以 Bradley–Terry 模型聚合勝負結果，得到「系統 × token 預算」的 Elo 評分。對每個系統畫出 Elo 對 log compute 的曲線。

4. **建立獨立取樣基準線**  
   理論上獨立取樣的 Elo 與 log compute 呈線性關係（每增加十倍運算量約 +400 Elo）。將此斜率作為參考線，判斷智能體是否優於無記憶取樣。

5. **找出擴展拐點**  
   定位智能體曲線的邊際增益等於獨立取樣參考線的 token 預算，即為 scaling inflection point。此點代表「繼續單場對話」與「重開平行場次」的效益轉折。

6. **依拐點重新分配預算**  
   將總 token 預算拆成多場次，每場使用接近拐點的 per-session budget，並行執行後取最佳解。論文在 FrontierCS 多格骨牌填裝上以此獲得 +264 Elo（相較單場）與 +355 Elo（相較十場短對話）。

7. **持續監控與迭代**  
   隨著模型或策略更新，重新擬合 Elo 曲線；因為拐點會移動，預算分配策略也應定期校正。

---

### 潛在風險與注意事項

- **原始分數的非線性陷阱**  
  不可直接用原始分數當進步指標。例如從 80% 提升到 81% 可能比 50% 到 60% 更難，必須透過成對比輾轉換成 Elo。

- **上下文視窗壓縮後的效能崩盤**  
  當對話超過上下文視窗而被壓縮，agent 的邊際增益往往迅速下降至獨立取樣以下。應在壓縮發生前記錄並觀察曲線轉折。

- **評測系統不一致**  
  若不同任務或不同版本的 judge 標準不同，Elo 的跨任務可比性會被破壞。必須確保所有提交使用同一評測系統。

- **抽樣基準線的實作偏差**  
  獨立取樣必須真正「無記憶」：每次嘗試不能繼承前次上下文或回饋，否則會高估基準線，導致拐點判斷錯誤。

- **過度擬合特定任務**  
  由於 Elo 是基於任務內排序，若任務樣本太少，評分可能對少數強解過度敏感。建議跨多個任務聚合後再做策略決策。

- **人類軌跡的可取得性與公平性**  
  與人類專家比較時，需注意人類有持續學習與睡眠效應，而 LLM 智能體目前多為無記憶取樣。比較應聚焦於「相同競賽時間與提交次數」的公平條件。

---

### 與其他技術的整合建議

- **與重複取樣（repeated sampling）框架整合**  
  將 Elo-per-token 作為上層指標，下層仍可用 majority vote、學習型驗證器或 verifier 來篩選候選解，但最終以 Elo 曲線判斷整體運算效率。

- **與樹狀搜尋或 MCTS 整合**  
  在節點擴展時，不只看原始分數，而是把節點提交納入 Bradley–Terry 錦標賽，用 Elo 作為節點選擇與剪枝依據。

- **與持續學習系統整合**  
  若未來 coding agents 具備跨場次記憶，可將每場結束後的知識累積視為「人類式持續學習」，並用 Elo 曲線檢驗是否出現超線性成長。

- **與 MLOps 監控整合**  
  在生產環境中，把每次中間提交的 token 消耗與 Elo 評分寫入監控儀表板，設定邊際增益低於獨立取樣參考線時自動觸發重開場次或升級策略。

- **與產品評估平台整合**  
  類似 Chatbot Arena 的成對比較基礎設施可直接複用：將「系統在特定 token 預算下的最佳解」視為一個參賽者，納入現有 Elo 排行榜。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦論文的圖一與核心概念：為什麼「原始分數」不能跨任務比較、Elo 如何透過成對勝負解決這個問題，以及「獨立取樣是線性成長」這條參考線的直覺。不必急著理解 Bradley–Terry 的數學推導，重點掌握「當邊際增益變低時，應該重開一場新對話」這個實務啟發。

**AI 工程師**  
請仔細閱讀方法章節（Elo-per-token 的建構方式）與實驗設計，特別是如何記錄每個中間提交的累計 token、如何擬合 Elo 曲線、以及如何計算 scaling inflection point。論文提供的獨立取樣理論基準線可以直接實作成產品內的預算分配 heuristics，建議從 FrontierCS 與 MLS-Bench 的實驗細節開始複現。

**研究人員**  
本論文的核心貢獻在於把「測試時擴展」從靜態的最終表現評估，轉變為動態的每 token 邊際效率分析。建議深入探討 Bradley–Terry 模型的假設、Elo 曲線的統計不確定性、以及與人類持續學習的對比。未來可延伸的方向包括：設計具備跨場次記憶的 coding agents、發展更細緻的上下文管理策略，以及將此方法推廣到非程式設計的開放式任務。

**產品經理**  
本研究提供了一個可落地的決策框架：當 AI 智能體在某任務上「變慢」時，與其無限追加 token，不如把預算拆成多場平行執行。建議關注「擴展拐點」與「平行場次 vs. 單場長對話」的實驗結論，並思考如何將其包裝成產品功能（例如自動重試、並行搜尋、預算上限建議）。同時，與人類專家的對比結果也提示：在需要持續學習的開放式任務上，AI 仍有顯著成長空間，可作為產品路線圖的長期賣點。
