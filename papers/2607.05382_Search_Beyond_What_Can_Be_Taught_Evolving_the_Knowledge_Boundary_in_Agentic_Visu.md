## ⚡ TL;DR

視覺生成器受固定語料限制，對開放演變的世界知識請求常自信捏造。
提出 SearchGen-20K 與先教後搜共同訓練框架，以雜訊抵抗的代理式推理器動態發現知識邊界。
前沿開源模型於該基準僅21–28分，本方法穩定優於無搜尋與盲目搜尋，並奠定遞迴自我改進基礎。

## 摘要翻譯

視覺生成器（visual generator）擅長渲染（rendering），卻會對未知事物自信地捏造（fabricate）。使用者請求（user request）是無邊界（unbounded）、不斷演變（evolving）且極度長尾（deeply long-tailed）的：新角色（new character）、熱門實體（trending entity）、截止後事件（post-cutoff event）等等。這個世界知識瓶頸（world-knowledge bottleneck）是結構性的：生成器在固定語料庫（fixed corpus）上訓練，但視覺世界本質上是開放式的。我們建構了 SearchGen-20K 與 SearchGen-Bench，包含 20,839 個提示詞（prompt），涵蓋 12 個失效類別（failure category）與 22 個領域（domain），並搭配預先執行（pre-executed）的百萬級多模態搜尋語料庫（multimodal search corpus）SearchGen-Corpus-1M，以支援離線可重現研究（offline reproducible research）。在 SearchGen-Bench 上，前沿開源生成模型（frontier open generator）僅獲得 21 至 28 分（滿分 100），這是現有基準無法察覺的 40 分崩跌。直覺的解決方案是引入搜尋工具（search tool），以實現代理式視覺生成（agentic visual generation）。然而，我們發現樸素搜尋（naive search）會失效：它不加區別地檢索，對生成器已能處理的提示詞注入雜訊（inject noise）。我們將根本原因（root cause）追溯到一個生成器專屬且不斷演變的知識邊界（knowledge boundary）：也就是生成器可透過訓練內化（internalize）的知識，與必須保留在外部上下文（external context）中的知識之間的分界。儘管此邊界難以預先明確界定，我們證明它可透過先教後搜共同訓練框架（teach-then-search co-training framework）被發掘。即使是此共同訓練（co-training）做法的最簡版本，也能產生單調改進（monotonic improvement），為視覺生成中、能夠滿足基於世界知識的請求（world-knowledge-grounded request）的遞迴自我改進（recursive self-improvement）奠定基礎。我們釋出完整資料集、共同訓練語料庫與搜尋語料庫，作為一套可重現評估框架（replayable harness），以支援工具增強式（tool-augmented）、基於世界知識的視覺生成。

### 核心貢獻（3～5點）
- 建構 SearchGen-20K、SearchGen-Bench 與 SearchGen-Corpus-1M，提供首個涵蓋 12 個失效類別、22 個領域、20,839 個提示詞的離線可重現評估框架，支援工具增強式視覺生成的可重複研究。
- 揭示前沿開源生成模型在世界知識提示詞上僅得 21–28 分（滿分 100），相較既有基準出現 40 分的性能崩跌，凸顯世界知識瓶頸的嚴重性。
- 發現樸素搜尋會對生成器已能處理的提示詞注入雜訊，證明搜尋必須以「生成器專屬且不斷演變的知識邊界」為依據，而非盲目觸發。
- 提出先教後搜共同訓練框架，透過聯合訓練自動發掘知識邊界，即使是最簡版本也能帶來單調改進，為視覺生成的遞迴自我改進奠定基礎。
- 完整釋出資料集、共同訓練語料庫與搜尋語料庫，作為可重播框架，推動代理式視覺生成與外部知識存取的研究。

### 適合對象
本論文最適合視覺生成、代理式 AI 與工具增強式生成領域的研究者，以及從事大規模視覺生成基準與資料集建構的學者。對於希望將生成模型部署於生產級 AIGC 平台、並解決新角色、熱門實體、截止後事件等長尾世界知識問題的工程師與產品團隊，亦具有高度參考價值。此外，關注遞迴自我改進、檢索增強生成與模型知識邊界分析的讀者，也能從本文的共同訓練框架與實證分析中獲得啟發。

## 深度分析

#### 方法論解析

本研究將問題定位為 **agentic visual generation（代理式視覺生成）**：視覺生成器（visual generator）不再單獨運作，而是配備一個能決定「何時搜尋、搜尋什麼、如何整合」的 **agentic reasoner（代理式推理器）**。整體方法可拆解為兩個相互鎖定的元件：一個具備雜訊抵抗力的搜尋推理器，以及一套 **teach-then-search co-training framework（先教後搜共同訓練框架）**。

##### 1. 雜訊抵抗的代理式推理器：gate–filter–integrate 管線

作者指出 **naive search（朴素搜尋）** 會對所有提示詞盲目觸發搜尋，導致兩種傷害：對生成器已經會畫的內容引入無謂雜訊，以及對檢索結果中的錯誤細節過度服從。為此，他們設計三階段管線：

- **Gate（閘門）**：判斷該提示詞是否跨越了 **knowledge boundary（知識邊界）**。若請求涉及的知識屬於「穩定且低維、可透過訓練內化」的範疇，則不觸發搜尋；若屬於「本質上具情境性、長尾、快速演變」的知識，才啟動搜尋。
- **Filter（過濾）**：對檢索回傳的多模態內容進行篩選，抑制無關的視覺細節、風格污染與虛假結構，避免 **search noise（搜尋雜訊）** 進入生成器的輸入空間。
- **Integrate（整合）**：將保留下來的外部參考資訊轉換為生成器可理解的條件訊號，例如適當的文本描述或視覺條件，使生成器在維持自身風格與構圖能力的同時，補足缺失的世界知識。

這個管線的核心設計哲學是：把「抵抗雜訊」的責任放在推理器端，而非要求生成器自行從嘈雜的檢索結果中辨別真偽。這對現今開源生成模型特別重要，因為它們傾向將所有條件訊號視為權威。

##### 2. 先教後搜的共同訓練：發現知識邊界

知識邊界難以事先人工規定，因此作者提出透過共同訓練來「發現」它。具體包含兩個互補步驟：

- **Online iterative DPO（線上迭代直接偏好最佳化）**：教導生成器內化那些它能夠吸收的 **world knowledge（世界知識）**，同時建立對不完美搜尋輸入的雜訊抵抗力。換言之，生成器一邊學習把可參數化的知識遷移至自身參數，一邊學會在檢索結果不乾淨時仍保持穩定輸出。
- **Rejection-sampling finetuning（拒絕採樣微調）**：校準搜尋推理器，使其只對「生成器無法被教會」的知識進行搜尋。透過比較「有搜尋」與「無搜尋」的輸出品質，推理器逐漸學會將搜尋資源集中在真正需要外部上下文的案例上。

這套 **co-training（共同訓練）** 的關鍵在於「生成器」與「推理器」同步演化：生成器變強後，原本需要搜尋的知識可能變成可內化，推理器就必須縮小搜尋範圍；反之，若推理器過度保守，生成器又會因缺乏參考而失敗。作者強調這是一個最小化但可擴展的配方（minimalist recipe），使用僅 8B 參數的代理式推理器搭配搜尋工具，即可超越單純生成與盲目搜尋的基線。

#### 實驗數據解讀

##### 1. 資料集與評測架構

研究建構了三項資源：

- **SearchGen-20K**：20,839 個基於世界知識的提示詞，橫跨 12 個 **failure category（失效類別）** 與 22 個 **domain（領域）**，並涵蓋雙語（英文 58%、中文 42%）與真實使用者長度分布（中文平均 89 字元、英文平均 266 字元）。
- **SearchGen-Bench**：對應的離線自動化評測基準，每個提示詞都附有細粒度的 **visual checklist（視覺檢查清單）**，支援全自動評分。
- **SearchGen-Corpus-1M**：預先執行的百萬級多模態搜尋語料庫，讓研究者能在離線環境重現檢索結果。

這樣的設計直接回應了現有基準的 **evaluation gap（評估落差）**：傳統基準多聚焦於構圖、美學或一般物件生成，難以捕捉「2025 大阪世博吉祥物」或「歷史上準確的斯巴達方陣」這類動態、長尾的世界知識失效。

##### 2. 主要量化結果

- **純生成基線的崩塌**：在 SearchGen-Bench 上，前沿開源生成模型僅得 21–28 分（滿分 100），相較於商業 API 上限約有 40 分的差距。這說明問題不在渲染能力，而在 **world-knowledge bottleneck（世界知識瓶頸）**。
- **朴素搜尋反而有害**：對所有提示詞觸發搜尋的 **blind search（盲目搜尋）** 策略，會在生成器已經能處理的案例上注入雜訊，導致整體品質下降。這驗證了「何時搜尋」與「搜尋什麼」必須被聯合解決。
- **生成器適應性搜尋的單調提升**：從 No Search → Blind Search → Generator-Adaptive Search，表現呈現 **monotonic improvement（單調改進）**。經過共同訓練的 8B 代理式推理器，能夠根據當前生成器的知識邊界動態決定搜尋與否，最終超越前沿生成器搭配前沿 VLM 的組合。

##### 3. 失效模式與領域分布

圖 4 顯示 SearchGen-20K 涵蓋人物、歷史、建築、運動、抽象、商業、物件、科技、藝術設計、文字符號、時尚、文化、螢幕與表演媒體、音樂與表演藝術、科學與自然、遊戲與 IP 等領域。作者特別指出，失效嚴重程度在領域與失效類別之間分布相對均勻，這排除了「問題只集中在少數冷門類別」的假設，凸顯世界知識瓶頸的普遍性。

#### 與現有研究的比較

##### 1. 相較於傳統視覺生成基準

現有基準如 DrawBench、PartiPrompts、HPSv2 等主要衡量構圖、美學、文字渲染或一般語意對齊，對於「模型是否知道 2025 年事件」或「某個小眾文化符號的準確外觀」缺乏系統性測試。SearchGen-Bench 填補了這個缺口，並以自動化視覺檢查清單支援大規模評估，這在以往多依賴人工評分的知識密集型任務中是一大進步。

##### 2. 相較於檢索增強生成（RAG）與工具使用研究

在大型語言模型領域，檢索增強生成已相對成熟，但視覺生成中的 **tool-augmented visual generation（工具增強式視覺生成）** 仍處於早期。本研究的貢獻在於指出視覺領域的特殊挑戰：

- **條件訊號的權威性問題**：語言模型對檢索文本通常具備一定批判能力，但開源視覺生成器傾向將所有視覺條件視為權威，導致檢索雜訊直接轉化為影像錯誤。
- **知識邊界的動態性**：視覺知識的可內化程度與生成器能力緊密相關，因此搜尋策略必須是 **generator-specific（生成器專屬）** 且 **evolving（不斷演變）**，而非靜態規則。

##### 3. 相較於商業 API

商業 API 在 SearchGen-Bench 上展現明顯較高的天花板，暗示其可能已透過更大規模資料、頻繁重新訓練或內部檢索機制緩解了部分瓶頸。本研究提出的開源配方讓社群得以在透明、可重現的環境中追趕這一差距，並提供可量化的中間目標。

##### 4. 限制

儘管方法新穎，仍有幾項限制值得注意：

- **最小化配方的規模**：目前僅展示單一迭代共同訓練，尚未驗證多輪 **recursive self-improvement（遞迴自我改進）** 的收斂性與穩定性。
- **搜尋語料庫的覆蓋率**：SearchGen-Corpus-1M 雖已預先執行，但對於極新事件或極度長尾實體，檢索品質仍是上限。
- **自動化檢查清單的完備性**：視覺檢查清單雖然可擴展，但對於需要細膩文化理解或美學判斷的項目，可能無法完全取代人工評估。
- **生成器專屬性**：知識邊界會隨生成器改變，因此同一套推理器無法直接遷移到不同架構或不同訓練階段的模型，需要重新校準。

#### 可重現性評估

本研究在可重現性方面下了顯著功夫，這對於資源較少的學術與開源社群尤其重要：

- **完整資料釋出**：SearchGen-20K、SearchGen-Bench 與 SearchGen-Corpus-1M 均對外釋出，後者為預先執行的多模態搜尋語料，避免即時線上搜尋帶來的不穩定性與不可重現性。
- **可重播框架（replayable harness）**：研究者可以在離線環境中重現檢索、推理與生成的完整流程，這對於比較不同方法、不同生成器或不同檢索策略至關重要。
- **自動化評分**：視覺檢查清單支援全自動評估，降低人工評分的主觀性與成本，使大規模實驗更易重複。

不過，論文摘要與引言中並未明確說明是否釋出共同訓練後的模型權重、訓練腳本或推理器實作細節。若這些元件未完整開源，則其他研究者在復現「Generator-Adaptive Search」的完整效能時，仍可能面臨工程門檻。建議後續釋出時補充：

- 8B agentic reasoner 的模型權重與訓練程式碼；
- DPO 與拒絕採樣微調的資料配對方式；
- gate–filter–integrate 各階段的具體提示詞設計與超參數。

#### 未來研究方向

##### 1. 遞迴自我改進的驗證與穩定化

作者已將 **recursive self-improvement（遞迴自我改進）** 定位為長期願景。未來研究可探討：當生成器與推理器進行多輪交替更新時，系統是否會收斂？是否會出現「遺忘已內化知識」或「推理器過度搜尋」的漂移？需要設計穩定的回饋機制與 early stopping 準則。

##### 2. 動態知識邊界的線上估計

目前知識邊界透過共同訓練離線發現。未來可發展線上估計方法，例如利用生成器的不確定性量化、內部注意力分布或對比輸出，即時判斷某提示詞是否跨越邊界，從而減少對大量配對資料的依賴。

##### 3. 更強大的多模態檢索與雜訊抑制

現有方法仍受限於檢索語料庫的品質。未來可結合視覺-語言檢索器、知識圖譜與多模態 RAG，並發展專門針對視覺生成的重排序（re-ranking）與摘要技術，以進一步降低 search noise。

##### 4. 跨語言與跨文化擴展

SearchGen-20K 已包含中英雙語，但未來可擴展至更多語言與區域文化，特別是那些在訓練語料中代表性不足、卻在真實使用者請求中頻繁出現的長尾文化符號。

##### 5. 與閉源商業系統的對齊與超越

研究已揭示商業 API 在知識密集型任務上的優勢。未來可透過更大規模的共同訓練、更頻繁的知識更新，以及將搜尋結果與生成器潛在空間更緊密結合，縮小並超越商業系統。

##### 6. 安全性、版權與真實性

當視覺生成器主動搜尋真實人物、品牌或近期事件時，必然涉及版權圖像、錯誤資訊與深度偽造風險。未來需要建立檢索來源透明化、引用機制與生成內容真實性標示，使 **agentic visual generation** 在實際部署時符合倫理與法律規範。

##### 7. 從文字到圖像擴展至更廣泛的視覺任務

本研究的框架原則上可延伸至圖像編輯、影片生成、3D 生成與多模態對話。未來可探討如何在這些任務中定義知識邊界，並設計對應的搜尋與整合策略。

## 論文問答

**Q1：什麼是視覺生成中的「世界知識瓶頸」，它與傳統的視覺合成瓶頸有何不同？**

A：世界知識瓶頸是指視覺生成器雖然具備強大的渲染能力，卻因訓練語料固定而無法掌握開放、演變且極度長尾的真實世界知識。與傳統的視覺合成瓶頸不同，這個問題不在於畫面品質或結構一致性，而在於模型對於 2025 年大阪世博吉祥物、近期熱門實體或區域文化符號等內容會自信地捏造。由於生成器被訓練成無論如何都要產出一張圖像，它缺乏辨識自身無知並主動取得外部知識的機制。

**Q2：為什麼現有的視覺生成基準測試無法發現這個世界知識問題？**

A：現有基準大多聚焦於渲染品質、構圖與一般語意對齊，導致前沿開源生成模型在這些測試上趨近飽和，卻無法反映真實使用者對於動態世界知識的需求。在 SearchGen-Bench 上，前沿開源生成模型僅得到 21 到 28 分（滿分 100），與商業 API 上限相差約 40 分，這個巨大的評估落差在傳統基準中完全不可見。因此，現有評測體系存在結構性缺口，無法捕捉會隨時間演變的世界知識失效模式。

**Q3：既然視覺生成器缺乏世界知識，為什麼單純加上搜尋工具並不能解決問題？**

A：樸素搜尋會對所有提示詞不加區分地觸發檢索，反而把雜訊注入那些生成器已經能處理的提示中，導致品質下降。檢索結果可能帶來無關的視覺細節、風格污染或錯誤結構，而開源生成器傾向將所有條件訊號視為權威，無法自動過濾噪音。因此，搜尋必須與生成器的知識狀態協調，否則會引發概念腐化與抄襲效應等新問題。

**Q4：什麼是「知識邊界」，為什麼說它是生成器特定且不斷演變的？**

A：知識邊界是可內化知識與需外部上下文補充知識之間的分界線：一側是穩定、低維、可透過訓練編碼進模型參數的知識，另一側是隨實例變化、演變快速或位於長尾的知識。這條邊界會隨著生成器能力提升而移動，因為原本需要搜尋的知識可能在增強監督後被模型內化。因此，對較弱生成器有利的搜尋策略，可能對較強生成器造成干擾，這使得邊界無法事先硬編碼，只能透過互動與訓練來發現。

**Q5：本文提出的核心方法包含哪兩個相互鎖定的元件？**

A：第一個元件是具備雜訊抵抗能力的代理式推理器，採用 gate–filter–integrate 三階段流程來決定何時搜尋、保留什麼檢索內容，以及如何整合外部資訊。第二個元件是「先教後搜」的共同訓練框架，透過線上迭代 DPO 讓生成器學習可吸收的知識，同時以拒絕採樣微調來校準推理器只搜尋生成器無法被教會的內容。這兩個元件相輔相成：推理器減少注入生成器的雜訊，而生成器的進步又回過頭改變知識邊界，進一步調整搜尋範圍。

**Q6：gate–filter–integrate 流程如何提升生成品質？**

A：Gate 階段判斷當前提示詞是否超出生成器內化知識的範圍，只在必要時觸發搜尋；Filter 階段從檢索結果中篩選與提示相關且無污染的參考內容；Integrate 階段將篩選後的資訊格式化並注入生成器的條件輸入空間。這個流程在雜訊到達生成器之前就加以抑制，避免開源模型將所有條件訊號視為權威而產生概念扭曲。整體而言，它把搜尋從「盲目檢索」轉變為「目標導向的參考諮詢」。

**Q7：SearchGen-20K、SearchGen-Bench 與 SearchGen-Corpus-1M 各自扮演什麼角色？**

A：SearchGen-20K 是包含 20,839 個提示詞的大規模資料集，涵蓋 12 種失效類別與 22 個領域，並附帶細粒度的視覺檢查清單以支援自動化評估。SearchGen-Bench 是對應的離線評測基準，用於量化模型在世界知識視覺生成任務上的表現。SearchGen-Corpus-1M 則是預先執行的百萬級多模態搜尋語料庫，讓研究者能在不依賴即時線上搜尋的情況下進行可重現的實驗。

**Q8：本文報告的關鍵實驗結果是什麼？**

A：在 SearchGen-Bench 上，前沿開源生成模型僅獲得 21 到 28 分，顯示出相較商業 API 上限約 40 分的嚴重崩落。透過本文提出的生成器適應式搜尋，即使只是 8B 的代理式推理器，也能超越前沿生成器搭配前沿視覺語言模型的表現。實驗結果呈現單調改進：從不搜尋、到樸素搜尋、再到生成器適應式搜尋，分數逐步提升。

**Q9：文中進行了哪些消融或對比實驗來驗證方法有效性？**

A：文中至少比較了三種設定：不搜尋（No Search）、盲目搜尋（Blind Search）以及生成器適應式搜尋（Generator-Adaptive Search）。結果顯示盲目搜尋會降低部分提示詞的品質，而適應式搜尋同時優於純生成與不加區分的搜尋。此外，單一迭代的最小化共同訓練配方就能產生穩定增益，暗示若持續迭代將有更大的遞迴自我改進空間。

**Q10：哪些實際應用場景最能從代理式視覺生成中受益？**

A：任何需要即時、長尾或高度專業視覺知識的場景都會受益，例如描繪 2025 年大阪世博吉祥物、歷史正確的斯巴達方陣、區域文化符號、小眾字體或近期新聞事件。這些請求往往落在訓練語料的知識截止點之後，或位於極度長尾的分布尾部。代理式搜尋就像插畫家先查閱參考資料再下筆，讓生成器能夠接地於真實世界知識。

**Q11：在產品化部署時，導入代理式視覺生成需要考慮哪些問題？**

A：首先需要動態決定何時觸發搜尋，以平衡延遲、成本與生成品質，避免對已知內容浪費檢索資源。其次必須建立強健的過濾機制，防止檢索結果帶來風格污染、版權風險或錯誤結構。最後，由於知識邊界會隨生成器能力提升而改變，產品需要持續的共同訓練與線上校準，才能維持搜尋策略與模型能力的同步。

**Q12：這項研究可能對視覺生成領域帶來什麼樣的影響？**

A：它將研究焦點從單純的影像渲染品質轉移到「世界知識接地」的評估與方法設計，並提出可重現的資料集與評估框架來推動領域進展。透過釋出 SearchGen-20K、SearchGen-Corpus-1M 與可重播框架，它降低了工具增強式視覺生成研究的門檻。長遠來看，它為遞迴自我改進的視覺生成系統奠定了基礎，使模型能隨著世界知識演變而不斷更新。

**Q13：作者承認或隱含了哪些限制？**

A：本文的共同訓練配方刻意保持最小化，僅進行單一迭代，因此仍有許多優化空間尚未探索。搜尋品質受限於語料庫的涵蓋範圍與檢索品質，若參考資料本身不足或錯誤，生成結果仍會失準。此外，知識邊界無法事先精確定義，必須透過實驗與共同訓練來發現，這增加了方法在全新領域上的遷移難度。

**Q14：哪些失效案例或負面效應在文中仍然被視為挑戰？**

A：當過濾機制失敗時，檢索結果仍可能導致概念腐化，讓生成影像混入不相關的視覺元素。開源生成器傾向將所有條件訊號視為權威，因此即使推理器已過濾，殘留的雜訊仍可能被忠實呈現。對於搜尋語料庫中缺乏多模態參考的極度長尾實體，系統目前仍無法憑空創造出正確的視覺知識。

**Q15：未來研究可以朝哪些方向延伸？**

A：未來可以建立真正的遞迴自我改進循環：生成器不斷擴大可內化的知識範圍，而推理器則相應縮小搜尋範圍並提升過濾精度。也可以將共同訓練擴展到更多迭代、更大規模的推理器，以及更即時更新的多模態搜尋語料庫。此外，發展更安全的資訊整合機制，使生成器能對抗不完美檢索結果，將是實現長期世界知識接地視覺生成的關鍵。

## 適用場景

1. **即時品牌與活動視覺生成**  
   行銷團隊需要為「2025 大阪世博吉祥物」、「最新熱門影集角色」或「本週發表的新車款」生成宣傳圖。這類提示詞涉及**截止後事件**與**熱門實體**，模型參數內沒有對應知識，必須透過**搜尋工具**取得最新參考資料，再由**代理式推理器**決定要渲染什麼。

2. **文化與歷史教育內容產製**  
   教材或博物館應用需要正確呈現「斯巴達方陣的歷史裝備」、「特定區域文化符號」或「小眾字體」。這類需求落在**世界知識瓶頸**與**長尾**領域，適合使用 **SearchGen-Bench** 的評估邏輯，並以 gate–filter–integrate 流程過濾錯誤參考，避免**概念汙染**與**複製效應**。

3. **遊戲與 IP 角色設計輔助**  
   遊戲工作室需要根據既有 IP 的**典型外觀**生成新姿勢或場景。若角色知識已可透過**增強式監督**內化到生成器，就不該盲目搜尋；反之，對於新角色或跨界聯名，則應觸發檢索並進行**雜訊抑制**。

4. **新聞與媒體插圖生成**  
   編輯室需要為「近期事件」或「新登場政治人物」快速產製配圖。此場景對事實正確性要求高，必須建立**知識邊界**判斷：模型已知的內容直接生成，未知內容先搜尋、再整合，並保留可稽核的**外部上下文**來源。

5. **電商與產品視覺自動化**  
   電商平台需要生成「最新 3C 產品外觀」、「季節性時尚單品」或「區域限定包裝」。這些需求常伴隨**固定幾何形狀**與**本質上具情境性的知識**交錯，適合採用**先教後搜共同訓練框架**，讓生成器學會已穩定出現的產品特徵，同時對長尾新品保留搜尋路徑。

## 實作步驟建議

1. **建立評測基準**  
   收集目標場景的真實使用者提示詞，參照 **SearchGen-Bench** 的分類法標註**失效類別**與**領域**，並為每題建立細粒度**視覺檢查清單**。先以現有**前沿開源生成模型**跑 baseline，量化**世界知識瓶頸**的嚴重程度。

2. **建置預先執行的搜尋語料庫**  
   針對評測集中的實體與事件，預先執行多模態搜尋並固定結果，形成 **SearchGen-Corpus-1M** 這類可重播資源。這能避免線上搜尋結果不穩定，並確保實驗可重現。

3. **部署 noise-resistant agentic reasoner**  
   實作 gate–filter–integrate 三階段流程：
   - **Gate**：判斷提示詞是否跨越**知識邊界**，決定是否觸發搜尋。
   - **Filter**：對檢索結果進行相關性與品質過濾，移除**雜訊**、風格汙染與無關細節。
   - **Integrate**：將篩選後的**外部上下文**轉換為生成器可理解的條件（如 caption、region prompt、reference image embedding）。

4. **執行先教後搜共同訓練**  
   - 對**視覺生成器**使用 online iterative DPO：讓模型學會內化可**參數化**的穩定知識，同時對不完美的搜尋輸入建立**雜訊抵抗**能力。
   - 對**代理式推理器**使用 rejection-sampling fine-tuning：校準其搜尋決策，使其只對生成器無法自行學會的內容觸發檢索。

5. **迭代評估與邊界更新**  
   每輪訓練後，在 **SearchGen-Bench** 或自建基準上測量 NO SEARCH → BLIND SEARCH → GENERATOR-ADAPTIVE SEARCH 的**單調改進**曲線。隨著生成器能力提升，重新估計**知識邊界**，縮減不必要的搜尋。

6. **產品化部署**  
   將訓練好的生成器與推理器封裝為服務，串接搜尋索引、快取機制與人工回饋迴路，並保留稽核日誌以滿足版權與事實查核需求。

## 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **盲目搜尋導致品質下降** | 對生成器已內化的知識仍觸發搜尋，會**注入雜訊**、引發概念扭曲或複製效應。 | 透過 gate 階段與共同訓練，讓推理器學會只在**知識邊界**外搜尋。 |
| **檢索結果的版權與隱私風險** | 搜尋返回的參考圖可能受版權保護，或包含個人影像。 | 建立來源過濾與使用授權檢查；生成時採用風格解耦與參考強度控制。 |
| **過度擬合評測集** | 若反覆以同一組 **SearchGen-20K** 調整模型，可能讓分數失真。 | 保留獨立測試集，並定期以真實使用者提示詞驗證。 |
| **知識邊界漂移** | 生成器能力提升後，原本需要搜尋的內容可能已可內化，固定策略會變得多餘。 | 將邊界估計納入持續監控，定期重新執行共同訓練。 |
| **自動化評估誤判** | **視覺檢查清單**可能遺漏文化細節或新興實體的變化。 | 結合人工抽檢與 VLM 輔助評分，並允許檢查清單版本迭代。 |
| **運算成本飆升** | 搜尋＋生成＋共同訓練的 pipeline 比純生成昂貴許多。 | 對高頻提示詞建立快取與分類器，減少不必要的檢索與微調。 |

## 與其他技術的整合建議

- **RAG 與檢索增強生成架構**  
  可將本文的 agentic reasoner 視為視覺版 RAG：搜尋語料庫對應 vector store，gate–filter–integrate 對應 retriever 與 reranker。建議與現有文字 RAG 系統共用實體解析與查詢改寫模組，但需額外處理圖像條件的**雜訊抑制**。

- **現有視覺生成平台（Stable Diffusion、FLUX 等）**  
  可將共同訓練後的 LoRA / full fine-tune 權重與推理器掛接在既有 inference pipeline 上。對於已部署的服務，建議先以 rejection-sampling 校準一個輕量 gate model，再逐步引入完整 agentic pipeline。

- **VLM 作為評判與過濾器**  
  使用 GPT-4V、Qwen-VL 等**前沿 VLM** 協助 filter 階段判斷檢索結果與提示詞的相關性，並作為自動化評估的裁判模型。但需注意 VLM 本身也有**知識截止點**，對最新實體可能誤判。

- **MLOps 與持續學習系統**  
  將搜尋語料、檢查清單與模型權重納入版本控制；設計資料回饋迴路，讓生產環境的真實錯誤案例自動回流到下一輪**先教後搜共同訓練**。

- **內容安全與版權過濾**  
  在搜尋結果進入生成器前，先經過 NSFW、浮水印、版權風險與人物識別過濾，並記錄使用的**參考資料**來源，以支援後續稽核。

## 給不同背景讀者的閱讀建議

**初學者**：這篇論文的核心訊息是「視覺生成模型會畫圖，但不代表它知道畫的是什麼」。建議先從圖 1 與圖 4 的範例入手，理解什麼是**世界知識瓶頸**，再看 §2 的資料集設計；技術細節如 DPO 與 rejection sampling 可先略讀，重點放在「為什麼不能對每個提示詞都搜尋」以及 gate–filter–integrate 的直覺。

**AI 工程師**：請聚焦 §3 的**代理式推理器**實作與**先教後搜共同訓練框架**。你需要評估如何將 gate–filter–integrate 接入現有 inference pipeline、如何維護**預先執行的搜尋語料庫**，以及如何設計自動化評估來監控**知識邊界**的漂移。論文釋出的 replayable harness 是最佳起點。

**研究人員**：本文的貢獻在於提出「generator-specific, evolving knowledge boundary」這一概念，並以 **SearchGen-Bench** 量化其影響。建議深入閱讀 §2.1 的失效模式分析、§3.3 的 co-training 設計，以及實驗中 NO SEARCH / BLIND SEARCH / GENERATOR-ADAPTIVE SEARCH 的比較。未來可延伸的方向包括邊界的線上估計、更強的雜訊抵抗機制，以及跨語言與跨文化的長尾分布分析。
