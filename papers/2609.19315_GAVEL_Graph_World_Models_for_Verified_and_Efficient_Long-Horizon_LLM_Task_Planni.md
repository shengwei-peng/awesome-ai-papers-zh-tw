## 摘要翻譯

大型語言模型（Large Language Models, LLMs）為長期機器人規劃（long-horizon robot planning）提供了靈活的介面，但其所生成的計畫往往未能遵守具身約束（embodiment constraints）、從規劃錯誤中恢復，也難以在部分可觀測性（partial observability）下進行有效推理。我們提出 GAVEL，一個以顯式圖世界模型（explicit graph world model）為核心、用於驗證與修復（verify and repair）長期 LLM 任務規劃（long-horizon LLM task planning）的框架。該圖表示相關的物體關係（object-relations）、動作前置條件（action pre-conditions）與動作效果（action effects），以及對未觀測物體位置（unobserved object locations）的機率信念（probabilistic beliefs）。此模型能夠在執行前預測 LLM 所生成動作（LLM-generated actions）的後果、偵測違規（violations），並修復那些修正方式可直接由圖世界模型推導出的違規。此方法亦僅在錯誤需要語義推理（semantic reasoning）時才啟用 LLM 重新規劃（LLM replanning）。

針對多任務指令（multi-task instructions），GAVEL 會對可能物體位置分布（distributions of possible object locations）進行推理，以重新排序剩餘子任務（reorder remaining subtasks）並最小化期望搜尋成本（minimize expected search cost）。我們在 BEHAVIOR-1K 上評估 GAVEL，涵蓋 100 個單一長期任務（single long-horizon tasks）與 500 則多任務指令。使用 Qwen3-8B 時，GAVEL 將單任務成功率（single-task success）從 41.2% 提升至 91.8%，並將多任務成功率（multi-task success）從 19.9% 提升至 92.6%。分布信念推理（distributional belief reasoning）亦使移動距離（travel distance）相較於靜態變體（static variant）減少約 5.4%。這些改進顯示，運用顯式圖世界模型這一機制能夠顯著提升長期具身規劃（long-horizon embodied planning）的可靠性與效率，且無論是輕量本地 LLM（compact local LLM）或前沿託管 LLM（frontier hosted LLM）皆然。

### 核心貢獻（3～5點）
- 提出 GAVEL 框架，以顯式圖世界模型（explicit graph world model）驗證與修復 LLM 生成的長期任務計畫，確保其遵守具身約束與動作前置條件。
- 將 LLM 重新規劃（LLM replanning）保留給需要語義推理（semantic reasoning）的錯誤，降低對大型模型的依賴並提升規劃效率。
- 針對多任務指令（multi-task instructions），基於可能物體位置分布（distributions of possible object locations）進行分布信念推理（distributional belief reasoning），動態重新排序子任務以最小化期望搜尋成本。
- 在 BEHAVIOR-1K 基準上驗證，使用 Qwen3-8B 即可將單任務與多任務成功率大幅提升，並降低移動距離。

### 適合對象
適合對機器人規劃（robot planning）、大型語言模型（LLMs）與長期具身規劃（long-horizon embodied planning）有興趣的研究者與工程師，特別是關注如何在邊緣部署（edge deployment）的輕量模型上提升規劃可靠性、驗證 LLM 生成動作之正確性，以及處理部分可觀測環境（partial observability）與多任務指令的研究者。

## 深度分析

#### 方法論解析

GAVEL（Graph World Models for Verified and Efficient Long-Horizon LLM Task Planning）的核心設計是將一個**顯式圖世界模型（explicit graph world model）**作為 LLM（Large Language Models，大型語言模型）長期任務規劃的「驗證與修復層」。整體流程可視為「LLM 提出語義計畫 → 圖模型模擬執行 → 偵測並修復可模型化錯誤 → 僅將語義層無法處理的錯誤回傳給 LLM 重新規劃（LLM replanning）」。

##### 1. 圖世界模型的組成

根據文中定義，環境被表示為一個**類型化場景圖（typed scene graph）**：

\[
G=(V,E,\Phi),\quad V=R\cup O\cup\{\rho\}
\]

其中：
- \(R\) 為房間實例（room instances），具有語義類型 \(\tau:R\to T\)；
- \(O\) 為任務相關物體（task-relevant objects），具有類別標記 \(c(o)\)；
- \(\rho\) 代表機器人自身；
- 邊 \(E\) 與特徵 \(\Phi\) 則編碼物體關係（object-relations）、動作前置條件（action pre-conditions）與動作效果（action effects）。

這個圖不僅是被動的環境描述，更是一個可執行的世界模型：它能夠對 LLM 生成的動作序列進行前向推論（roll forward），預測每一步執行後的狀態轉移（state transitions）。

##### 2. 計畫驗證與分層修復

GAVEL 對 LLM 計畫進行三類檢查：
- **前置條件檢查（precondition verification）**：例如機器人是否已靠近物體、是否已持有某物體；
- **目標完成檢查（goal completion verification）**：執行結束後是否達到目標狀態（intended state）；
- **安全性檢查（safety verification）**：動作是否違反具身約束（embodiment constraints）或其他安全限制。

當偵測到違規（violations）時，GAVEL 會區分兩種錯誤：
- **模型可導出的錯誤（model-derivable failures）**：例如「因未靠近而抓取失敗」，其修復動作直接由被違反的前置條件決定，例如先執行導航靠近。這類錯誤由圖模型直接修復，無需再次呼叫 LLM。
- **需要語義推理的錯誤（semantic failures）**：例如目標理解錯誤、任務順序語意錯誤、需要常識判斷的步驟缺失等，則回傳給 LLM 進行 LLM replanning。

這種分層機制降低了對 LLM 的呼叫頻率與成本，也減少了 LLM 因反覆重試而引入新錯誤的風險。

##### 3. 部分可觀測性與分布信念推理

在部分可觀測（partial observability）環境中，機器人可能知道環境佈局，但不確定任務相關物體的確切位置。GAVEL 對未觀測物體位置（unobserved object locations）維護**機率信念（probabilistic beliefs）**，即物體位置信念（object-location beliefs）的完整分布，而非僅保留最可能的單一估計。

這些信念被轉換為**期望搜尋成本（expected search cost）**。每完成一個子任務後，新的觀測會更新信念分布，GAVEL 再根據更新後的分布重新排序剩餘子任務（reorder remaining subtasks），以**最小化期望搜尋成本（minimize expected search cost）**。這屬於線上（online）的信念空間規劃（belief-space planning），能夠隨觀測動態調整任務順序。

##### 4. 多任務執行流程

對於多任務指令（multi-task instructions），GAVEL 的執行邏輯可概括如下：
1. LLM 根據自然語言指令（natural-language instructions）產生高層語義計畫；
2. 圖模型對計畫進行符號化模擬與驗證；
3. 若存在模型可修復的違規，直接插入對應的前置動作（prerequisite actions）或修正動作；
4. 執行過程中持續更新物體位置信念（object-location beliefs）；
5. 每完成一個子任務後，根據最新信念分布重新評估剩餘子任務順序；
6. 僅當錯誤涉及語義推理（semantic reasoning）時，才觸發 LLM replanning。

這種設計讓 LLM 專注於其擅長的語義理解與高層程序生成，而圖模型則負責精確、可解釋且低成本的執行層驗證與修復。

#### 實驗數據解讀

GAVEL 在 **BEHAVIOR-1K** 模擬環境中進行評估，測試分為兩大類：
- **單一長期任務（single long-horizon tasks）**：共 100 個任務；
- **多任務指令（multi-task instructions）**：共 500 個指令。

##### 1. 成功率提升

使用 **Qwen3-8B** 作為後端 LLM 時，主要結果如下：

| 指標 | 基線 | GAVEL |
|---|---|---|
| 單任務成功率（single-task success rate） | 41.2% | 91.8% |
| 多任務成功率（multi-task success rate） | 19.9% | 92.6% |

解讀：
- 單任務成功率提升超過 50 個百分點，顯示即使對於相對單純的長期任務，LLM 獨立規劃仍有很高的失敗率（failure rate），而圖世界模型能有效補足具身約束與前置條件方面的缺失。
- 多任務成功率從不足 20% 提升至超過 92%，提升幅度更為劇烈。這說明當規劃範圍（planning horizon）拉長、子任務數量增加時，LLM 更容易產生順序錯誤或忽略跨任務狀態影響，而 GAVEL 的驗證與信念推理能顯著抑制這類錯誤累積。

##### 2. 移動距離與效率

在多任務情境下，GAVEL 的**分布信念推理（distributional belief reasoning）**相較於一個靜態變體（static variant），可將**移動距離（travel distance）**降低約 **5.4%**。

解讀：
- 5.4% 的距離減少雖然在數字上看似不大，但它反映的是「保留完整機率分布」相對於「僅使用最可能位置」或「固定任務順序」的穩定效率增益。
- 在長期居家機器人任務中，移動距離直接關聯執行時間與能耗，因此這項改進具有實際意義。
- 更重要的是，這項改進是在成功率大幅提升的同時達成的，顯示 GAVEL 並非以犧牲效率來換取成功率，而是同時提升可靠性與效率。

##### 3. 對 LLM 能力的補充性

論文強調，GAVEL 的改進「across compact local and frontier hosted LLM capabilities」，即在輕量本地 LLM（compact local LLM）與前沿託管 LLM（frontier hosted LLM）上均有顯著提升。這意味著：
- 即使未來 LLM 能力持續增強，顯式世界模型仍能提供可解釋、確定性的驗證與修復機制；
- 對於邊緣部署（edge deployment）場景，GAVEL 讓較小的模型（如 Qwen3-8B）也能達到接近大型模型的規劃表現，降低部署成本與延遲。

#### 與現有研究的比較

##### 1. 相對於純 LLM 規劃方法

早期的 LLM-for-planning 方法如 **SayCan**、**Code as Policies**、**ProgPrompt**、**LLM-Planner**、**Inner Monologue** 等，主要依賴 LLM 直接生成動作序列或程式，並透過觀測回饋進行 LLM replanning。這類方法的問題在於：
- 隨著規劃範圍（planning horizon）拉長，失敗率（failure rate）快速上升；
- 每次錯誤都呼叫 LLM，成本高且容易引入新的幻覺錯誤；
- 難以系統性地處理具身約束（embodiment constraints）與前置條件。

GAVEL 的改進在於引入顯式圖世界模型，將「驗證」與「可導出修復」從 LLM 中分離出來，僅保留語義層的 LLM replanning。

##### 2. 相對於 propose-and-check 場景圖方法

**SayPlan** 等場景圖方法採用「提出—檢查」迴圈（propose-and-check loop）：LLM 提出計畫，結構化環境模型進行符號執行，不可行的動作再回傳 LLM 重試。這類方法雖然能驗證計畫，但本質上仍把圖當作被動的**驗證器（verifier）**。

GAVEL 的關鍵差異在於把圖視為**世界模型（world model）**：
- 不僅檢查合法性，還能模擬動作效果（action effects）；
- 能直接根據狀態轉移（state transitions）修復模型可導出的錯誤，無需每次都回傳 LLM；
- 能表達機率信念（probabilistic beliefs），支援部分可觀測（partial observability）下的決策。

##### 3. 相對於 EPoG

**EPoG（Expressive Planning over Graphs）** 是與 GAVEL 最接近的基線。EPoG 維護一個包含已觀測與預測物體的信念圖（belief graph），並透過圖編輯（graph edits）直接從當前狀態規劃到目標狀態，LLM 主要用於局部重規劃。

兩者的分工正好相反：
- **EPoG**：圖模型負責全局規劃，LLM 負責局部語義重規劃；
- **GAVEL**：LLM 負責生成語義程序，圖模型負責前向模擬、違規偵測與直接修復。

此外，EPoG 主要支援空間重排（spatial rearrangement）與拾取放置（pick and place）等簡單操作，難以表達需要多步動作語義的複雜目標（如「洗盤子」）。GAVEL 則透過動作前置條件與效果的顯式建模，支援更豐富的長期任務語義。

##### 4. 相對於信念空間與主動感知方法

**SEEK** 結合動態場景圖與關係語義網路（RSN）來預測物體可能位置；**L3MVN**、**COMRES-VLM** 等則利用 LLM/VLM 的常識引導探索。GAVEL 採用與 SEEK 類似的 RSN 來初始化房間層級的信念，但不同之處在於：
- 保留完整的物體位置信念分布，而非僅取最可能結果；
- 將信念轉換為期望搜尋成本，並用於線上任務順序重排；
- 與 LLM 規劃緊密結合，形成「語義規劃 + 符號驗證 + 機率決策」的統一框架。

##### 5. 限制

儘管 GAVEL 表現出色，仍有以下潛在限制：
- **圖模型建構成本**：顯式圖世界模型需要預先定義動作前置條件、效果與物體關係，對於開放式環境或新穎任務，人工設計或自動學習這些知識仍是挑戰。
- **信念表示範圍**：目前主要針對未觀測物體位置（unobserved object locations）進行機率信念推理，對於其他不確定性來源（如物體狀態、動作執行雜訊、人類行為）的建模仍有限。
- **對 LLM 的依賴**：雖然減少了 LLM 呼叫次數，但語義層的錯誤仍需要 LLM replanning，若 LLM 對任務語義理解錯誤，GAVEL 難以自行修正高層目標。
- **模擬到真實（sim-to-real）差距**：BEHAVIOR-1K 是模擬環境，真實機器人場景中的感知誤差、執行延遲與動作失敗模式可能更複雜。

#### 可重現性評估

根據目前提供的論文內容，作者並未明確提及是否公開原始碼、資料集處理流程或預訓練模型權重。因此，可重現性評估需從以下幾個層面進行判斷：

##### 1. 資料集與模擬環境

- **BEHAVIOR-1K** 是公開的長期居家機器人任務模擬基準，具備標準化的場景、任務定義與評估指標。這為重現實驗提供了良好的基礎。
- 若作者提供任務清單、初始條件與評估腳本，將大幅提升可重現性。

##### 2. 模型與實作細節

- 論文使用 **Qwen3-8B** 作為主要後端 LLM，該模型為公開可取得的前沿輕量模型，降低了硬體門檻。
- 然而，圖世界模型的具體實作（如動作模式定義、信念更新機制、任務重排演算法）若未開源，其他研究者需要從頭實作，重現難度較高。
- 提示工程（prompting）細節、LLM 呼叫次數上限、重試策略等超參數也會顯著影響結果，建議作者補充。

##### 3. 建議作者補充的項目

為提升可重現性，建議作者提供：
- 原始碼倉庫（包含圖模型建構、驗證修復邏輯、信念更新與任務重排模組）；
- 使用的 BEHAVIOR-1K 任務列表與隨機種子；
- Qwen3-8B 的提示模板（prompt templates）與解碼參數；
- 基線方法的實作細節與對照設定；
- 執行日誌與中間結果，以便分析錯誤類型與修復頻率。

目前根據現有資訊，可重現性評估為「**中等：基準環境公開，但核心方法實作細節與程式碼釋出狀態不明**」。

#### 未來研究方向

基於 GAVEL 的貢獻與限制，以下幾個方向值得進一步探索：

##### 1. 自動化圖世界模型學習

目前 GAVEL 依賴預先定義的動作前置條件、效果與物體關係。未來可研究如何從示範資料、自然語言說明或互動經驗中自動學習或擴充圖模型，降低人工設計成本，並提升對新穎任務與開放式環境的泛化能力。

##### 2. 更豐富的不確定性建模

除了未觀測物體位置（unobserved object locations），未來可將機率信念擴展到：
- 物體狀態不確定性（如是否乾淨、是否開啟）；
- 動作執行雜訊與失敗機率；
- 人類或其他動態代理的行為不確定性。

這將使 GAVEL 能處理更真實、更動態的居家環境。

##### 3. 與視覺語言模型（VLM）的深度融合

GAVEL 目前主要依賴符號化的圖模型與 LLM。結合 VLM（Vision-Language Models，視覺語言模型）可讓系統直接從原始影像更新場景圖、偵測物體狀態變化，並在感知層提供更豐富的語義資訊，進一步減少對人工設計特徵的依賴。

##### 4. 真實機器人驗證與 sim-to-real 遷移

未來可在真實機器人平台上驗證 GAVEL，並研究如何處理模擬環境中難以涵蓋的問題，例如：
- 感知誤差導致的場景圖不一致；
- 低階控制器失敗與重試；
- 非結構化環境中的導航與操作挑戰。

##### 5. 階層式規劃與多機器人協作

將 GAVEL 擴展至階層式規劃（hierarchical planning），讓高層 LLM 負責目標分解，低層圖模型負責子目標驗證與執行。此外，多機器人協作場景中，信念推理可用於協調搜尋與任務分配，進一步提升效率。

##### 6. 可解釋性與人機互動

GAVEL 的顯式圖模型天然具備可解釋性。未來可研究如何將驗證結果、修復動作與信念分布以自然語言或視覺化方式呈現給使用者，支援人機協作中的信任建立與錯誤診斷。

總結來說，GAVEL 透過顯式圖世界模型將 LLM 的語義能力與符號驗證、機率信念推理結合，為長期具身規劃（long-horizon embodied planning）提供了一個可靠且高效的框架。未來若能進一步降低圖模型建構成本、擴展不確定性建模範圍，並推進至真實機器人應用，將有望成為具身智慧領域的重要基礎架構。

## 論文問答

**Q1：GAVEL 主要想解決什麼問題？**

A：GAVEL 針對的是長期具身規劃中，大型語言模型（LLMs）產生的動作序列經常違反具身約束、無法從規劃錯誤中恢復，以及在部分可觀測環境下推理不足的問題。具體來說，機器人接收自然語言指令後，LLM 雖然能產生高階計畫，但這些計畫可能缺少前置動作、忽視物理限制，或根本無法達成目標狀態。GAVEL 透過引入顯式圖世界模型，在執行前驗證並修復 LLM 計畫，從而提升長期任務的成功率與執行可靠性。

**Q2：現有的 LLM 規劃方法與場景圖方法為什麼不足以解決這個問題？**

A：現有方法大致可分為純 LLM 規劃與「提出—檢查」式的場景圖驗證兩類，但兩者都有明顯缺陷。純 LLM 規劃在規劃範圍拉長時失敗率會上升，尤其對輕量本地 LLM 而言更不可靠；而場景圖方法雖能符號化執行計畫並找出不可行動作，卻往往把每次違規都丟回 LLM 重新規劃，這不僅增加成本，也可能引入新的錯誤。此外，像 EPoG 這類基於圖編輯的規劃器雖然快速可靠，但主要只能處理拾取與放置等空間重排任務，難以表達需要多步語義動作的複雜目標，例如「洗盤子」。

**Q3：為什麼需要一個「顯式圖世界模型」來輔助 LLM 規劃？**

A：顯式圖世界模型能把環境中的物體關係、動作前置條件與效果，以及未觀測物體位置的機率信念結構化地呈現出來，讓機器人在執行前就能預測動作後果。相較於把知識隱含在 LLM 參數中，這種模型能精確檢測違規並根據已定義的狀態轉移直接修復，避免不必要的 LLM 重新規劃。這對邊緣部署尤其重要，因為它能在不依賴強大雲端模型的情況下，顯著提升輕量本地 LLM 的長期規劃可靠性。

**Q4：GAVEL 的核心方法架構是什麼？**

A：GAVEL 以一個統一的顯式圖世界模型為基底，該模型包含房間與物體節點、物體間關係、每個動作的前置條件與效果，以及對未觀測物體位置的機率信念。當 LLM 產生計畫後，GAVEL 會在圖上逐步前推（roll forward）每個動作，驗證前置條件、目標完成度與安全性約束；若發現可由模型語義直接推導的錯誤，系統會自動修復。只有當錯誤涉及需要額外語義推理的情況時，GAVEL 才會將該失敗回傳給 LLM 進行重新規劃。

**Q5：GAVEL 與傳統驗證器或 EPoG 的關鍵創新差異在哪裡？**

A：傳統驗證器只是被動檢查計畫是否合法，發現違規後仍須呼叫 LLM 修正；GAVEL 則把圖模型當作主動的世界模型，能模擬動作結果並直接套用由動作語義隱含的修復。與 EPoG 相比，GAVEL 反轉了分工：EPoG 讓 LLM 主要負責局部重規劃，而圖編輯負責全局計畫；GAVEL 則讓 LLM 負責產生語義程序，圖模型負責驗證、修復與信念推理。這種設計保留了 LLM 的語義靈活性，同時利用符號模型確保計畫的物理與邏輯一致性。

**Q6：GAVEL 為什麼選擇保留完整的物體位置信念分布，而非只使用最可能位置？**

A：保留完整分布能讓 GAVEL 在部分可觀測環境中計算「期望搜尋成本」，而不只是根據單一最可能位置做決策。當機器人完成一個子任務後，新的觀測會更新對其他未觀測物體位置的信念，GAVEL 便可根據更新後的分布重新排序剩餘子任務，選擇當下預期代價最低的執行順序。實驗結果顯示，這種分布信念推理相較於靜態變體能減少約 5.4% 的移動距離，證明完整信念資訊對多任務效率有實質幫助。

**Q7：GAVEL 在哪些實驗設定與基準上進行評估？**

A：GAVEL 在 BEHAVIOR-1K 這個長期居家機器人任務模擬基準上進行測試，涵蓋 100 個單一長期任務與 500 個多任務指令。實驗同時使用了輕量本地 LLM（如 Qwen3-8B）與前沿託管 LLM，以驗證方法在不同模型能力下的表現。這樣的設計能同時檢驗 GAVEL 在緊湊邊緣模型與強大雲端模型上的互補性與泛用性。

**Q8：GAVEL 在實驗中取得了哪些關鍵成果？**

A：在使用 Qwen3-8B 的情況下，GAVEL 將單任務成功率從 41.2% 大幅提升至 91.8%，多任務成功率也從 19.9% 躍升至 92.6%，顯示圖世界模型能顯著彌補輕量 LLM 的長期規劃弱點。此外，分布信念推理讓機器人在多任務執行中減少約 5.4% 的移動距離，相較於把信念折疊成最可能位置的靜態變體更有效率。這些結果說明，即使使用較小的本地模型，GAVEL 也能達到接近甚至超越單純依賴大型模型的可靠性。

**Q9：GAVEL 的消融實驗或對照分析揭示了什麼？**

A：透過與靜態變體比較，研究發現保留完整物體位置信念分布能持續降低期望搜尋成本，因為它讓系統能根據最新觀測動態調整子任務順序。與 EPoG 等基線相比，GAVEL 在需要複雜語義動作的長期任務上表現更優，因為它讓 LLM 負責高階語義程序，而圖模型負責低階一致性與修復。整體而言，實驗顯示顯式世界模型推理與 LLM 能力提升是互補的，即使模型變強，符號驗證與信念推理仍能帶來顯著增益。

**Q10：GAVEL 在實際應用場景中適合做什麼？**

A：GAVEL 特別適合需要執行多步自然語言指令的家用服務機器人，例如「把客廳的髒盤子拿到廚房洗好再放回櫃子」。在這類任務中，機器人必須理解語義目標、滿足動作前置條件，並在不確定物品位置的情況下有效率地搜尋與執行。由於 GAVEL 能在執行前驗證計畫並在執行中根據觀測更新信念，它非常適合部分可觀測且動作順序會影響效率的長期居家任務。

**Q11：若要把 GAVEL 產品化，有哪些工程與設計考量？**

A：首先，GAVEL 能與輕量本地 LLM 搭配運作，這對注重隱私、延遲與成本的消費型機器人產品非常有利，因為它能減少對雲端 LLM 的頻繁呼叫。其次，圖世界模型需要在部署前建立動作前置條件、效果與環境關係的知識庫，這可能涉及領域工程與模擬器或真實環境的對齊。最後，執行前的驗證與修復機制可作為安全層，降低機器人因 LLM 幻覺或物理常識不足而產生危險或無效動作的風險。

**Q12：GAVEL 對機器人與 AI 領域可能帶來什麼影響？**

A：GAVEL 提供了一個結合神經語義推理與符號世界模型的範例，顯示兩者並非互斥，而是可以相輔相成。它證明在長期具身規劃中，顯式結構化知識能顯著提升 LLM 計畫的可靠性與效率，尤其對資源受限的邊緣裝置。這可能推動未來更多研究走向「神經—符號」融合的具身 AI 架構，讓語言模型負責高階語義，而符號模型負責可驗證、可解釋的物理與邏輯推理。

**Q13：GAVEL 目前有哪些可能的限制或前提假設？**

A：GAVEL 的圖世界模型需要預先定義動作的前置條件、效果以及相關物體關係，這在開放式真實環境中可能需要額外的領域知識或自動學習機制。此外，當錯誤超出模型所涵蓋的動作語義時，系統仍須回退到 LLM 重新規劃，這意味著未建模的物理現象或新穎任務仍可能導致失敗。目前的評估也主要集中在 BEHAVIOR-1K 模擬環境，未來尚需驗證其在真實機器人與更動態、更雜亂場景中的泛化能力。

**Q14：GAVEL 在什麼情況下可能會失敗或表現不佳？**

A：當任務失敗來自需要深層語義推理或常識判斷的原因時，例如指令含糊、需要推斷人類意圖，或遇到圖模型未涵蓋的新穎物體與動作，GAVEL 仍須依賴 LLM 重新規劃，而這可能再次引入錯誤。如果對未觀測物體位置的信念分布不準確，例如語義先驚嚴重偏離實際擺放，則基於期望成本的子任務重排序也可能變得次優。此外，在高度動態、物體狀態快速變化的環境中，圖模型的狀態轉移假設若無法及時更新，也會影響驗證與修復的正確性。

**Q15：未來可以從哪些方向延伸 GAVEL？**

A：未來可以讓圖世界模型從資料中自動學習或精煉動作模型，減少對人工領域知識的依賴，並擴展到更豐富的物理動力學與多機器人協作場景。另一個方向是將視覺感知與信念更新更緊密地整合，使機器人在真實世界中能根據觀測即時修正對未觀測物體的信念。此外，把 GAVEL 部署到真實機器人平台，並研究其在開放詞彙指令、長期互動與終身學習情境下的表現，將是邁向實用化長期具身規劃的重要下一步。

## 實務應用指南

### 適用場景

1. **居家服務機器人的長期家務指令**  
   例如「把沙發上的髒衣服放進洗衣機，然後倒入洗衣精並啟動」。這類任務包含多個前置動作（開門、拾取、搬運）、具身約束（雙手需空閒才能開門）與目標狀態驗證，GAVEL 的圖世界模型可在執行前偵測遺漏步驟並自動修復。

2. **倉儲與物流撿貨機器人**  
   面對「取 A、B、C 三樣商品並送到包裝站」這類多任務指令時，商品可能不在預期貨架上。GAVEL 透過物體位置信念分布，在每次觀測後重新排序剩餘子任務，降低尋找與移動的期望成本。

3. **醫療與照護輔助機器人**  
   例如「從藥櫃取藥並送至 3 號病房」。此場景對動作前置條件與安全約束要求高，圖模型可驗證「是否已解鎖藥櫃」「是否已確認病患身分」等條件，減少語義錯誤導致的風險。

4. **工業巡檢與維護機器人**  
   在大型廠房中，部分設備狀態或工具位置未即時可見。GAVEL 可維護未觀測物體的機率信念，並根據當前觀測動態調整巡檢順序，提升效率。

5. **人機協作裝配線**  
   LLM 負責將自然語言裝配指令轉為高階步驟，圖世界模型則驗證零件狀態、工具持有關係與鎖附順序，自動補上遺漏的前置步驟，僅在語義不明時才請 LLM 重新規劃。

### 實作前置條件

**資料準備**
- 環境語義模型：房間實例、物體類別、物體間的空間與語義關係（即 typed scene graph）。
- 動作本體（action ontology）：每個動作的前置條件（pre-conditions）、效果（effects）與安全約束。
- 自然語言指令與目標狀態定義：用於驅動 LLM 生成計畫，並供圖模型驗證目標達成。
- 物體位置先驗：例如 Relational Semantic Network（RSN）或領域知識，用於初始化未觀測物體的位置信念分布。

**運算資源**
- 輕量本地 LLM（如 Qwen3-8B）即可在邊緣設備執行高階規劃。
- 圖推理引擎計算量相對低，可在機器人端運行。
- 若採用前沿託管 LLM，需評估 API 延遲、成本與離線可用性。

**技術能力**
- 具身 AI／機器人規劃基礎。
- 知識圖譜或符號 AI 經驗（設計與維護動作本體）。
- LLM prompt engineering 與結構化輸出處理。
- 機率推理（貝葉斯更新、期望成本計算）。
- 模擬器使用經驗（如 BEHAVIOR-1K）與真實機器人系統整合能力。

### 實作步驟建議

1. **建立動作本體與場景圖**  
   列出機器人所有高階動作，明確定義每個動作的前置條件、效果與安全規則，並以 typed scene graph 表示環境中的房間、物體與機器人自身狀態。

2. **建置圖世界模型引擎**  
   實作前向模擬（forward rollout）、前置條件檢查、違規偵測，以及「可由模型推導的修復」機制。此引擎應能自動補上遺漏的前置動作，例如偵測到「抓取失敗因未靠近物體」時自動插入接近動作。

3. **接入 LLM 規劃器**  
   設計 prompt 使 LLM 輸出結構化的高階動作序列。將該序列送入圖引擎驗證；僅當錯誤需要額外語義推理時，才將錯誤資訊回傳給 LLM 進行重新規劃。

4. **實作物體位置信念管理與線上任務重排**  
   對未觀測物體維護機率信念分布，並在每次觀測後更新。根據期望搜尋成本與導航成本，動態重新排序剩餘子任務，避免任務順序在初始化後固定不變。

5. **模擬驗證與迭代**  
   在 BEHAVIOR-1K 或類似長期居家任務模擬器中，分別測試單一長期任務與多任務指令。記錄單任務成功率、多任務成功率、移動距離等指標，並針對常見失敗案例擴充動作本體。

6. **逐步部署到真實機器人**  
   將模擬中驗證過的規劃流程對接真實感知與控制模組，確保視覺輸入能正確更新場景圖節點與信念。初期保留人在迴路（human-in-the-loop），特別是處理語義失敗與安全關鍵決策。

### 潛在風險與注意事項

- **圖模型覆蓋不完整**  
  若動作本體或環境關係有遺漏，LLM 計畫中的違規可能無法被偵測。建議持續收集失敗案例並擴充本體，同時進行邊界案例測試。

- **LLM 幻覺導致語義錯誤**  
  當錯誤超出圖模型可修復範圍，回傳 LLM 重新規劃仍可能產生新的幻覺。應設計 fallback 機制，例如請求人類確認、縮小重新規劃範圍，或限制 LLM 輸出空間。

- **信念初始化偏差**  
  錯誤的物體位置先驗會讓線上任務重排序反而增加搜尋成本。應結合即時觀測更新信念，並在不確定性過高時加入主動探索策略。

- **延遲與成本權衡**  
  頻繁呼叫 LLM 重新規劃會增加延遲與費用。實作時應讓圖引擎盡量處理局部修復，將 LLM 保留給真正需要語義推理的情境。

- **安全關鍵任務的侷限**  
  GAVEL 的圖模型驗證並不等同於完整形式化驗證。在醫療、工業等高風險場景，仍需額外的安全監控層、緊急停止與合規審查。

### 與其他技術的整合建議

- **視覺語言模型（VLM）**  
  利用 VLM 進行場景理解、物體偵測與場景圖建構，並將偵測結果用於更新圖節點與物體位置信念。

- **SLAM 與語義地圖**  
  將 SLAM 輸出的房間拓撲與語義地圖作為圖世界模型的底層結構，支撐導航成本估計與房間層級的信念推理。

- **低階控制器與軌跡規劃**  
  GAVEL 輸出高階動作計畫後，可交由強化學習或軌跡最佳化模組執行具體運動控制，例如抓取姿態生成與避障。

- **機器人中介框架（ROS / MQTT）**  
  將圖世界模型引擎封裝為規劃服務，LLM 作為語義規劃節點，兩者透過 ROS topic／service 或 MQTT 交換動作、狀態與反饋。

- **企業知識圖譜**  
  若組織已有設備、物品與空間關係的知識圖譜，可直接用於初始化場景圖與語義先驗，降低資料準備成本。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先掌握「長期規劃」「部分可觀測性」與「前置條件／效果」的基本概念，再把焦點放在 GAVEL 為何要結合 LLM 與圖世界模型。數學公式與實作細節可暫時跳過，重點理解「驗證與修復」和「信念驅動的任務重排序」帶來的直覺優勢。

**AI 工程師**  
請著重於動作本體設計、圖引擎的前向模擬與修復邏輯、LLM prompt 與結構化輸出的介面，以及信念更新與線上優化的程式實作。建議搭配 BEHAVIOR-1K 的模擬環境動手實作，並評估本地 LLM 與託管 LLM 在延遲與成功率上的差異。

**研究人員**  
請關注 GAVEL 與 EPoG、SayPlan、belief-space planning 等方法在分工設計上的區別，以及論文中的消融實驗與評估指標。可進一步思考如何將顯式圖世界模型擴展到更開放的環境、更複雜的語義目標，或結合形式化方法提供可證明的安全保證。

**產品經理**  
請從商業價值角度理解：GAVEL 如何將單任務成功率從 41.2% 提升至 91.8%、多任務成功率從 19.9% 提升至 92.6%，並降低約 5.4% 的移動距離。評估時需同時考量適用場景、資料準備與本體維護成本、邊緣部署可行性，以及人機協作與安全風險。
