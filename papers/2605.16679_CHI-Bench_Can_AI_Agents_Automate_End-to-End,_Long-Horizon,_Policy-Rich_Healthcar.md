# CHI-Bench（χ-Bench）：AI 智慧體能否自動化端到端、長程、富含政策的醫療工作流程？

## ⚡ TL;DR

現有基準測試難以評估AI智慧體處理富含政策、多角色且需多方互動的醫療長程工作流程。
論文提出χ-Bench，以高擬真模擬器結合87個MCP工具與千餘份政策手冊，測試三類醫療端到端流程。
最佳智慧體僅完成28%任務，單次連續執行更降至3.8%，顯示政策密集領域的自動化瓶頸。

## 摘要翻譯

真實醫療作業的端到端（end-to-end）自動化，凸顯了現有基準測試中三項未能充分涵蓋的能力：政策密度（policy density），即決策必須奠基於龐大的醫療、保險與營運規則庫；多角色組合（multi-role composition），即單一任務要求智慧體（agent）扮演多種角色並進行交接（handoffs）；以及多方互動（multilateral interaction），即流程中的中間步驟為多輪對話，例如同儕審查（peer-to-peer review）與病患外展聯繫（patient outreach）。我們提出 χ-Bench（CHI-Bench），一個橫跨三個領域的長程（long-horizon）醫療工作流程（healthcare workflows）基準測試：醫療服務提供者（provider）端的事先授權（Prior Authorization, PA）、付款方（payer）利用率管理（Utilization Management, UM），以及照護管理（Care Management, CM）。每項任務在一個高擬真模擬器（high-fidelity simulator）中交給智慧體一個臨床病例（clinical case），此模擬器模擬 20 套醫療應用程式，並透過 87 個 MCP 工具（MCP tools）對外開放；智慧體必須在一份包含 1,290+ 份文件的管理式照護作業手冊（managed-care operations handbook）技能（skill）的引導下，透過工具呼叫（tool calls）與撰寫該角色的產出文件（artifacts），將流程推進至終端狀態（terminal status）。在 30 種智慧體測試框架（agent harness）／模型配置中，最佳智慧體僅解決 28.0% 的任務，沒有任何智慧體在嚴格的 pass^3 指標下達到 20%，而在單一工作階段（single session）中執行所有任務更使表現驟降至 3.8%。這些結果提出一項假設：類似的落差很可能在其他政策密集（policy-dense）、角色組合（role-composed）且不可逆（irreversible）的企業領域中浮現。

### 核心貢獻（3～5點）
- 提出首個專注於醫療端到端自動化的長程基準測試 χ-Bench（CHI-Bench），涵蓋事先授權（PA）、利用率管理（UM）與照護管理（CM）三大領域。
- 定義並評量三項關鍵能力缺口：政策密度（policy density）、多角色組合（multi-role composition）與多方互動（multilateral interaction）。
- 建構高擬真模擬環境，整合 20 套醫療應用程式、87 個 MCP 工具，以及 1,290+ 份文件的管理式照護作業手冊技能，要求智慧體透過工具呼叫與產出文件完成不可逆流程。
- 透過 30 種智慧體測試框架／模型配置進行大規模評估，實證顯示即使最先進的智慧體在嚴格指標下仍難以突破 20%，單一工作階段執行時表現更驟降至 3.8%。
- 揭示政策密集、角色組合且不可逆的企業領域可能存在類似的自動化落差，為後續研究提供明確方向。

### 適合對象
從事大型語言模型智慧體、醫療資訊系統與醫療行政自動化研究的學者與工程師；關注企業流程自動化、管理式照護營運，以及長程決策規劃在高度規範化領域應用的產品經理與政策制定者。

## 深度分析

#### 方法論解析

χ-Bench（CHI-Bench）的核心方法論在於建構一個高擬真模擬器（high-fidelity simulator），以壓力測試（stress-testing）前沿智慧體（frontier agents）在真實醫療工作流程中的端到端（end-to-end）自動化能力。其技術架構 χ-World Engine 模擬了 20 套日常醫療應用程式，透過 151 個 REST API 與 87 個 MCP 工具（MCP tools）暴露操作介面，並由 3 個 MCP 伺服器統籌管理。此設計並非僅提供離散的工具呼叫環境，而是建構了一個具備持續世界狀態（world state）的閉環系統，智慧體必須透過工具呼叫（tool calls）與產出文件（artifacts）的撰寫，驅動臨床個案（clinical case）至終端狀態（terminal status）。

在任務設計上，χ-Bench 鎖定三個高政策密度（policy density）的領域：醫療服務提供者（provider）的事先授權（Prior Authorization, PA）、付款方（payer）的利用率管理（Utilization Management, UM），以及註冊護理師照護管理師（RN care manager）的照護管理（Care Management, CM）。每項任務皆內嵌三大結構性挑戰：

1. **政策檢索（policy retrieval）與遵循**：智慧體必須在包含 1,279 份 markdown 文件的管理式照護作業手冊（managed-care operations handbook）中進行密集檢索，確保每個決策皆符合醫療指引、保險規則與作業程序（operational procedures）。這要求智慧體不僅具備檢索能力，更需進行跨文件的條件詮釋與長工具呼叫鏈（long tool-call chains）中的政策一致性維護。

2. **多角色組合（multi-role composition）與不可逆交接（irreversible handoffs）**：單一工作流程被切割為多個專業角色，如登記人員（intake clerk）、護理師（nurse）、醫師審查員（MD reviewer）、協調員（coordinator）等。智慧體必須在單一任務中切換領域知識與目標，且關鍵步驟一旦提交或路由即無法編輯或重新執行，形成終局性（terminal）狀態轉換。

3. **多方互動（multilateral interaction）與即時對話（live dialog）**：部分中間步驟並非背景執行（background execution）的工具呼叫，而是多輪對話（multi-turn dialogs），例如醫師對醫師的同儕審查（peer-to-peer review）或病患外展聯繫（patient outreach）。智慧體必須從非同步操作切換至同步對話，增量式收集資訊，並將結果帶回工作流程主幹。

評估機制採用複合驗證器（composite verifier），結合確定性檢查（deterministic checks）與基於評分標準的 LLM 評審（rubric-based LLM judge），針對最終的世界狀態（world state）、產出文件與事件軌跡（event trail）進行現場（in-situ）評分。指標設計包含 pass@1（單次嘗試通過率）、嚴格的 pass^3（三次獨立嘗試皆須通過，衡量可靠性），以及馬拉松式測試（marathon run，單一工作階段 single session 連續執行所有任務），後者特別用於評估長程狀態管理與錯誤累積效應。

#### 實驗數據解讀

實驗涵蓋 30 組智慧體測試框架／模型配置（agent harness/model configurations），橫跨主流專有大型語言模型（proprietary LLMs）與其官方智慧體框架。數據呈現出嚴峻的效能落差：

**整體通過率低迷**：最佳配置為 Claude Code 搭配 Claude Opus 4.6，在 pass@1 指標下僅解決 28.0% 的任務。這顯示即使是最先進的智慧體，在面對真實醫療工作流程時，其端到端自動化能力仍處於萌芽階段。更嚴格的是，在 pass^3 指標下（要求三次獨立執行皆成功），沒有任何智慧體突破 20%，揭示出智慧體行為的高度變異性與不可靠性。

**單一工作階段（single session）的效能崩潰**：當所有任務被串接在同一個馬拉松式工作階段中執行時，最佳效能驟降至 3.8%。此現象凸顯長程執行中的狀態漂移（state drift）、上下文窗口污染、以及錯誤累積（error accumulation）問題。在端到端的提供者—付款方競技場（provider–payer arena）中，最佳 PA 智慧體的通過率甚至歸零（0%），顯示跨組織邊界的完整流程自動化目前幾乎不可行。

**跨領域差異顯著**：從圖 3 可觀察到，利用率管理（UM）領域的表現相對較高（Claude Opus 4.6 達 41.3% pass@1），推測因其流程較為結構化，且主要為內部審查與文件比對；相對地，照護管理（CM）領域對多數模型極具挑戰性（例如 GPT-5.5 僅 1.3%，Gemini 3.1 Pro 為 0%），這可能源於 CM 涉及大量病患外展聯繫（patient outreach）與動態照護計畫（care plans）調整，需要更高程度的多邊互動與不確定性管理。事先授權（PA）則處於中間地帶，但涉及最複雜的跨組織政策協調。

**模型間的優劣勢分化**：Claude 系列在 UM 與 CM 領域明顯優於 GPT 與 Gemini 系列，可能反映其在長上下文遵循與結構化文件生成上的優勢；而 GPT-5.5 雖在 PA 領域領先（29.3%），但在 CM 領域同樣表現疲軟。圖 4 的對比進一步暗示，不同模型在特定檢查項目（如政策引用正確性、文件格式完整性、對話狀態追蹤）上存在系統性差異，而非單純的整體能力落差。

#### 與現有研究的比較

透過表 1 的九軸度覆蓋矩陣（coverage matrix）可清晰定位 χ-Bench 的獨特性。現有醫療 AI 基準測試（healthcare AI benchmarks）大致可分為四類，但皆存在明顯缺口：

1. **醫學知識測驗類**（如 MedQA、MedMCQA、PubMedQA）：僅評估事實性醫學知識（factual medical knowledge），缺乏工具使用（API tools）、長程規劃（long-horizon）與政策檢索能力評測。
2. **電子病歷查詢類**（如 EHRSQL、BioCoder、BioDSBench）：雖支援 API 工具呼叫，但多為短程查詢或單輪互動，未涉及多角色組合（multi-role composition）與不可逆工作流程。
3. **臨床智慧體類**（如 MedAgentsBench、AgentClinic、MedChain）：部分支援長程互動，但缺乏顯式的密集政策檢索（explicit dense policy retrieval）與隱藏狀態（hidden state）下的多方互動驗證。
4. **行政互動類**（如 HealthAdminBench）：此為最接近的競品（closest peer），但其聚焦於像素級或 DOM 層級的圖形介面（GUI）瀏覽，而非 χ-Bench 採用的結構化 MCP 工具；此外，HealthAdminBench 未涵蓋照護管理（CM）領域，亦缺乏大規模顯式政策手冊技能（policy handbook skill）。

在通用長程智慧體基準測試（long-horizon agent benchmarks）方面，SWE-Bench、WebArena、OSWorld、WorkArena 等雖具備長程執行與工具使用能力，但均未模擬多角色工作流程（multi-actor workflows）與政策密集（policy-dense）的決策環境。τ/τ2-Bench 與 TheAgentCompany 雖然配備模擬利害關係人（simulated stakeholders）與政策限制，但並未針對醫療領域，亦未觸及事先授權中特有的資訊不對稱與長期政策追蹤需求。

χ-Bench 的核心貢獻在於首次將以下六個要素整合於單一基準測試中：長程工具呼叫（long-horizon tool calls）、顯式密集政策檢索（explicit dense policy retrieval）、不可逆工作流程狀態（irreversible workflow state）、隱藏多方互動（hidden multilateral interaction）、持續模擬器狀態的現場驗證（in-situ verification against persisted simulator state），以及基於評分標準的 LLM 評審（rubric-based LLM judge）。這使其成為目前唯一在九個評估軸度上全數支援的醫療智慧體評測框架。

#### 可重現性評估

從正向角度觀之，χ-Bench 在可重現性（reproducibility）上具備若干優勢：其採用的 MCP（Model Context Protocol）為開放標準，工具介面為結構化 API，相較於 GUI 像素操作更易被不同研究團隊複製；政策手冊以 1,279 份 markdown 文件形式存在，格式標準化且易於版本控制；χ-World Engine 作為本地模擬器（local simulator），理論上可降低對外部即時服務的依賴，減少環境漂移（environment drift）。

然而，潛在的可重現性限制同樣顯著：

- **原始碼與資料集釋出狀態不明**：全文未明確聲明 χ-World Engine 的原始碼、20 套醫療應用程式的模擬邏輯、以及臨床個案資料集是否完全開源（open-source）。高擬真模擬器涉及大量領域知識與業務邏輯建置，若未釋出完整環境，第三方難以獨立重現。
- **評分主觀性與模型依賴**：複合驗證器中的 rubric-based LLM judge 部分，其評分結果可能因評審模型版本（如 GPT-4、Claude 3.5 或未來新版本）而產生評分漂移（score drift）。論文未詳述不同 LLM judge 間的一致性（inter-rater agreement）或與人類專家評分的一致性驗證。
- **專有模型限制**：實驗主要基於專有模型（proprietary models）如 GPT-5.5、Claude Opus 4.6 等，這些模型的權重（model weights）未公開，且其行為可能隨供應商更新而變化，導致歷史結果難以精確復現。
- **複雜環境配置**：87 個 MCP 工具橫跨 3 個 MCP 伺服器，涉及 151 個 REST API 的協同運作，本地部署的技術門檻與運算資源需求可能極高。

整體而言，χ-Bench 在方法論層面具備可重現的潛力，但實際上仍高度依賴作者團隊是否釋出完整的模擬器程式碼、測試案例與評估腳本。

#### 未來研究方向

基於 χ-Bench 所揭示的效能缺口，未來研究可沿以下幾個方向展開：

**1. 政策密集環境的專用架構**
現有通用智慧體架構難以應對 1,290+ 份文件的政策庫。未來可發展專為 policy-dense 領域設計的檢索增強生成（Retrieval-Augmented Generation, RAG）架構，結合層級式政策索引、條件邏輯推理模組，以及跨文件的一致性檢查機制，以降低政策引用錯誤率。

**2. 多角色記憶體與上下文切換**
針對 multi-role composition 的挑戰，需設計角色感知（role-aware）的記憶體架構，使智慧體能在 intake clerk、UM nurse、MD reviewer 等身份間切換時，正確隔離各角色的目標函數、知識邊界與責任範圍，避免目標混淆（goal confusion）與權限溢出。

**3. 不可逆決策的規劃與模擬**
由於 handoffs 為不可逆（irreversible），智慧體需具備「模擬執行」或「沙盒驗證」能力，例如在正式提交申請文件包（submission packets）前，先於內部規劃模組中進行類似蒙地卡羅樹搜尋（Monte Carlo Tree Search, MCTS）的軌跡評估，以預判終端狀態（terminal status）是否正確。

**4. 多邊對話的人機協作介面**
multilateral interaction 要求智慧體在背景執行（background execution）與即時對話（live dialog）間無縫切換。未來研究可探索混合主動式（mixed-initiative）對話系統，讓智慧體在與病患或醫師同儕互動時，能主動引導資訊收集，並將對話結果結構化回填至工作流程。

**5. 長程可靠性與錯誤恢復**
單一工作階段（single session）中 3.8% 的崩潰式表現，凸顯長程狀態壓縮與錯誤恢復（error recovery）機制的迫切性。研究方向包括檢查點（checkpointing）自動建立、執行軌跡的自我反思（self-reflection）、以及中繼狀態的動態修復協議。

**6. 跨領域遷移與企業級基準測試**
論文假設類似缺口將出現於其他政策密集、角色組合、不可逆的企業領域。未來可將 χ-Bench 框架遷移至保險理賠、法務合規、政府行政審查等場景，建立通用的企業長程工作流程基準測試家族。

**7. 評估方法論的精進**
發展更細緻的診斷性指標（diagnostic metrics），區分政策檢索錯誤、工具呼叫順序錯誤、對話狀態遺失與文件格式錯誤等失敗模式，並建立領域專家與 LLM judge 的一致性驗證標準，以提升評估的解釋性與公信力。

## 論文問答

**Q1：CHI-Bench 旨在解決醫療 AI 自動化領域中的什麼核心問題？**

A：美國醫療體系存在極度繁瑣的行政流程，例如事先授權、利用率管理與照護管理，這些都是耗時數週且涉及大量政策規章的長程任務。現有的 AI 智慧體雖然在程式編寫等領域展現出長程執行能力，卻缺乏對真實醫療營運場景的端到端壓力測試。CHI-Bench 因此聚焦於「政策密度」、「多角色組合」與「多方互動」這三項在當前基準測試中被嚴重低估的能力缺口，試圖填補理想化評測與真實臨床行政現實之間的鴻溝。

**Q2：為何現有的醫療或長程智慧體基準測試無法有效評估這類工作流程？**

A：現有的醫療基準大多僅評估單一面向，例如醫學知識問答、電子病歷查詢或短程臨床代理任務，未能涵蓋跨系統的長程工具呼叫與不可逆的狀態轉換。它們通常缺少高密度的政策檢索需求，也不具備多角色交接與多輪人機對話的模擬能力，導致無法反映管理式照護營運中「一旦提交即無法回退」的真實壓力。因此，在這些舊有基準上表現優異的智慧體，並不保證能應對實際醫療工作流程的複雜性。

**Q3：針對這三項被低估的能力進行嚴格評測，為何對醫療 AI 的發展至關重要？**

A：政策密度、多角色組合與多方互動並非邊緣案例，而是管理式照護營運的日常現實，任何一個環節出錯都可能導致病患延誤或給付拒絕。若缺乏嚴謹的端到端評測，產品團隊與研究人員將過度高估智慧體在真實企業環境中的可靠性，進而在實際部署時造成營運風險。建立 CHI-Bench 這類高擬真壓力測試，能夠確保技術進步真正轉化為可減輕行政負擔、提升病患照護效率的實用系統。

**Q4：CHI-Bench 的核心方法論是什麼？它如何建構評測環境？**

A：CHI-Bench 的核心是 χ-WorldEngine，這是一個高擬真模擬器，透過 87 個 MCP 工具介接 20 套日常醫療應用程式與 151 個 REST API，建構出包含付款方、醫療服務提供者與照護管理實體的完整生態系。受測智慧體會被賦予一個臨床個案，必須在模擬環境中發出工具呼叫、撰寫各角色產出文件（如申請文件包、審查紀錄或照護計畫），並依據上千份文件組成的管理式照護作業手冊將案件推進至終端狀態。評分則由複合驗證器執行，結合確定性規則檢查與基於評分標準的 LLM 評審，針對模擬器中持續存在的世界狀態與事件軌跡進行就地驗證。

**Q5：與先前最接近的相關工作相比，CHI-Bench 的關鍵創新體現在哪些層面？**

A：CHI-Bench 是首個在單一任務中同時結合長程工具呼叫、顯式密集政策檢索、不可逆工作流程狀態、隱性多方互動與就地驗證的基準測試，其覆蓋維度遠超 HealthAdminBench 等僅聚焦於像素或 DOM 層級網頁操作的同類研究。它透過結構化的 MCP 工具與明確的 1,279 份 Markdown 政策手冊來測試智慧體的規章檢索與推理能力，而非僅測試介面操作技巧。此外，它首次將照護管理領域中的病患外展聯繫納入評測，補足了從醫療服務提供者到付款方再到長期照護的完整光譜。

**Q6：作者為何選擇以 MCP 工具與顯式政策手冊，取代圖形化介面瀏覽作為主要互動模式？**

A：採用結構化的 MCP 工具能確保智慧體與模擬應用程式之間的互動是精確且可複現的，避免 GUI 操作帶來的雜訊與不穩定性，從而將評測焦點集中在工作流程推理本身。顯式政策手冊的設計則如實反映了管理式照護營運的核心挑戰：智慧體必須在超過千份的規章文件中正確檢索、詮釋並持續遵循適用政策。這樣的設計選擇有效地將「政策推理」與「介面操作」解耦，使得研究者能夠更準確地診斷智慧體在真實企業政策密集場景中的根本瓶頸。

**Q7：實驗評測涵蓋了哪些模型與智慧體框架配置？**

A：研究團隊總共評測了 30 種智慧體測試框架與模型配置，涵蓋當時主要的前沿模型，包括 GPT-5.5、GPT-5.4、GPT-5.4 Mini、Claude Opus 4.6 與 4.5、Claude Sonnet 4.6、Claude Haiku 4.5，以及 Gemini 3.1 Pro 與 Gemini 3 Flash。這些配置被部署於作者提供的第一方智慧體框架中，分別在事先授權、利用率管理與照護管理三個領域進行測試。此外，實驗還特別設計了「馬拉松式」單一工作階段測試，要求智慧體在同一個連續會話中執行所有任務，以檢視其長期記憶與錯誤累積的極限。

**Q8：實驗結果中最令人矚目的發現是什麼？**

A：表現最佳的配置（Claude Code 搭配 Claude Opus 4.6）在 pass@1 指標上僅能完成 28.0% 的任務，顯示即使是當時最頂尖的智慧體也遠未解決此基準。在嚴格的 pass^3 可靠性指標下，沒有任何智慧體能突破 20% 的門檻，意味著多數成功帶有高度隨機性而難以複現。更嚴峻的是，當所有任務在單一工作階段中連續執行時，整體表現暴跌至 3.8%，而在端到端的醫療服務提供者—付款方競技場中，最強的事先授權智慧體甚至完全失效（0%）。

**Q9：從不同領域與模型的表現差異中，可以歸納出哪些關於智慧體能力的洞察？**

A：實驗顯示各領域難度分布不均，利用率管理通常優於照護管理，暗示涉及病患外展與多輪對話的任務對現有模型而言格外艱難。Claude 系列模型在多數配置中優於 GPT 與 Gemini，尤其在利用率管理與照護管理領域展現出較強的穩定性。單一工作階段中的性能崩潰則清楚指出，當前前沿智慧體在長期上下文累積、跨領域記憶保持以及錯誤傳播控制方面存在嚴重缺陷，這些都是程式編寫類基準未能揭露的弱點。

**Q10：CHI-Bench 的發現對哪些真實世界的醫療應用場景最具參考價值？**

A：這些發現直接適用於醫院試圖自動化事先授權申請、保險公司建置利用率管理審查系統，以及照護管理機構執行長期病患協調與外展計畫的情境。這些都是量大、政策密集且涉及多方協調的高價值工作流程，自動化潛力巨大，但失敗成本也極高。CHI-Bench 提供了一個在正式上線前就能進行嚴格壓力測試的試驗場，幫助機構評估智慧體是否已準備好面對真實營運的複雜性，而非僅在簡化示範中表現良好。

**Q11：基於這些實驗結果，產品團隊在開發醫療 AI 智慧體時應考量哪些關鍵因素？**

A：產品團隊不應假設在程式編寫或一般工具使用基準上表現優異的智慧體，就能順利遷移至醫療行政工作流程。必須優先投資於強健的政策檢索架構、明確的角色切換機制，以及對不可逆交接點的嚴謹控管，因為在真實系統中一旦提交錯誤文件便難以挽回。此外，系統設計應保留人機協作的多邊互動介面，讓智慧體在面對同儕審查或病患聯繫等需要增量資訊收集的環節時，能夠無縫從背景執行轉換為即時對話模式。

**Q12：這項基準測試可能對更廣泛的 AI 與醫療領域帶來什麼樣的影響？**

A：CHI-Bench 為政策密集、多利害關係人參與的企業級智慧體評測樹立了嚴謹的新標竿，促使研究社群從理想化的程式編寫基準轉向處理真實行政流程的混亂現實。它透過量化數據揭示了前沿智慧體在真實長程企業工作流程中的能力鴻溝，有助於校準產業對短期內自動化程度的預期。藉由提供高擬真的開放評測框架，這項工作將引導未來研究朝向真正能減輕醫療行政負擔、改善營運效率的實用技術邁進。

**Q13：作者在本研究中承認了哪些主要的局限性？**

A：本基準目前聚焦於美國管理式照護體系，其保險規則與營運架構可能無法直接推廣至其他國家或單一支付者的醫療系統。儘管模擬器具有高擬真度，它終究是簡化後的環境，未必能完整捕捉實際生產系統中所有例外狀況、人為特例與即時變動。此外，評測部分依賴大型語言模型作為評審（LLM-as-a-judge），這雖然能處理複雜的語意評分，但也可能引入模型自身的偏見與一致性波動，需要謹慎詮釋。

**Q14：受測智慧體最常見的失敗模式有哪些？**

A：智慧體最頻繁的失敗來自政策檢索階段，無法從上千份文件的作業手冊中正確定位並詮釋適用的醫療與保險規則。在多角色組合方面，它們經常在不可逆的交接點出錯，例如提交錯誤的申請文件包或審查紀錄後，導致案件被鎖定在無法挽回的失敗狀態。此外，在多方互動情境如同儕審查或病患外展聯繫中，智慧體顯示出從背景工具執行切換到增量式資訊收集對話的困難，無法有效透過多輪對話推進工作流程。

**Q15：這篇論文提出了哪些未來的研究方向？**

A：未來研究應探索更專精的政策檢索與推理架構，例如針對密集規章文件設計的專用推理模組或檢索增強生成變體，以降低智慧體在長程任務中的政策引用錯誤。研究者也需要發展更強大的多角色上下文切換與長期記憶管理機制，避免單一工作階段中的性能隨著執行時間與任務數量增加而崩潰。最後，將此評測框架擴展至醫療以外的其他政策密集、角色組合且不可逆的企業領域（如法務、金融合規），將有助於驗證這些能力缺口是否為通用性的根本挑戰。

## 實務應用指南

### 適用場景

1. **管理式照護組織（MCO）的事先授權（PA）端到端處理**  
   適用於醫院或診所需向保險公司申請給付核准的場景。AI 智慧體可自動驗證保險範圍、蒐集臨床證據、撰寫申請文件包（submission packets），並處理後續的補件要求（RFI）與同儕審查（peer-to-peer review），最終將案件推進至終端狀態。

2. **保險方利用率管理（UM）的多角色審查流水線**  
   適用於保險公司審查醫療服務必要性與適當性的場景。智慧體需依序扮演登記人員（intake clerk）、利用率管理護理師（UM nurse）、醫師審查員（MD reviewer）等角色，完成案件受理、政策檢索、分級審查與核決，並處理不可逆的交接（handoffs）。

3. **註冊護理師照護管理（CM）的病患外展與計畫擬定**  
   適用於長期照護管理單位需主動聯繫病患、執行評估並擬定照護計畫的場景。智慧體需從背景執行（background execution）切換為即時對話（live dialog），透過多輪互動完成病患外展（patient outreach），再將收集到的資訊帶回工作流程，撰寫最終照護計畫（care plans）。

4. **醫療服務提供者與付款方之間的同儕審查協調**  
   適用於醫師對醫師（peer-to-peer）的專業審查場景，智慧體作為協調員（coordinator），在多邊對話中遞送臨床資訊、記錄雙方共識，並將結果寫回審查紀錄（review notes），完成多邊互動（multilateral interaction）。

5. **跨角色醫療行政作業的數位勞動力（Digital Workforce）**  
   適用於大型醫療體系希望以單一智慧體串連多個行政角色的場景，例如從案件登記、護理師初審、醫師複審到病患通知的全流程自動化，測試其在政策密集（policy-dense）與角色組合（role-composed）環境下的穩定性。

### 實作前置條件

**資料準備**
- **政策知識庫**：至少數百至數千份結構化與非結構化文件，涵蓋醫療指引、保險給付規則與營運作業程序（類似論文中 1,290+ 份 markdown 組成的管理式照護作業手冊）。
- **臨床與行政資料**：去識別化的病歷摘要、歷史申請案例、審查決策紀錄、以及照護管理中的評估表單與對話腳本。
- **系統介面規格**：目標醫療應用程式（如 EHR、保險理賠系統、排程系統）的 API 文件或 MCP（Model Context Protocol）介面定義。

**運算資源**
- **LLM 推論配額**：需支援長程（long-horizon）執行的 frontier model API（如 GPT-4.5/5 系列、Claude Opus、Gemini Pro）及其第一方 agent harness，單一案件可能觸發數十次至上百次工具呼叫（tool calls）。
- **模擬與驗證環境**：可運行高擬真模擬器（類似 χ-WorldEngine）的運算叢集，包含 20+ 醫療應用程式的容器化實例與 87+ MCP 工具伺服器。
- **向量資料庫與快取**：用於政策檢索的向量索引（如 Pinecone、Weaviate 或 Milvus）與工作流程狀態持久化儲存。

**技能與團隊**
- **醫療資訊學**：熟悉 HL7 FHIR、醫療資料交換標準與 HIPAA/個資法遵循。
- **Agent 工程**：具備 MCP 協定開發、提示工程（prompt engineering）、多角色協作 orchestration（如 LangGraph、AutoGen）與 RAG（Retrieval-Augmented Generation）實作經驗。
- **領域知識工程**：能將營運手冊轉譯為可驗證的規則庫，並設計確定性檢查（deterministic checks）與基於評分標準的 LLM 評審（rubric-based LLM judge）。

### 實作步驟建議

**步驟一：政策知識庫數位化與向量化**  
將管理式照護作業手冊等 1,000+ 份文件進行語意切分、向量化，並建立混合檢索架構（向量搜尋 + 關鍵字 / 知識圖譜），作為智慧體可呼叫的 skill。此為解決政策密度（policy density）挑戰的基礎建設。

**步驟二：建構高擬真沙盒環境（χ-WorldEngine 產品化）**  
將醫療機構現有的 15–25 套核心應用程式（EHR、理賠系統、排程系統等）封裝為 MCP 工具，確保工具呼叫能真實改變模擬器的世界狀態（world state），並產出可供驗證的事件軌跡（event trail）。

**步驟三：設計多角色 Agent 協作架構**  
定義每個角色的目標、權限與產出文件（artifacts）格式（如申請書、審查紀錄、照護計畫）。建立不可逆交接（handoff）協定：前一角色提交後，後續角色僅能讀取、無法修改，並在架構層強制執行 RBAC（Role-Based Access Control）。

**步驟四：開發複合驗證機制（Composite Verifier）**  
結合確定性檢查（例如欄位是否填寫、政策條件是否滿足）與基於評分標準的 LLM 評審（例如審查紀錄的臨床合理性），在模擬器內即時（in-situ）評分，避免離線評估與真實執行狀態脫節。

**步驟五：分階段部署與人機協作設計**  
- **第一階段（Copilot）**：單一角色輔助，例如僅協助 intake clerk 登記案件或僅協助 RN care manager 擬定照護計畫初稿。  
- **第二階段（單一領域端到端）**：在 PA、UM 或 CM 中擇一，完成從起始到終端狀態的全流程，但保留人類確認閘門（human-in-the-loop）。  
- **第三階段（Marathon Run）**：嘗試單一工作階段（single session）執行跨領域多任務，此時需引入狀態檢查點（checkpoint）與記憶體管理機制，以對抗長程執行中的效能衰退（論文中從 28.0% 跌至 3.8%）。

**步驟六：建立多方對話通道**  
針對同儕審查與病患外展，整合電話、簡訊、視訊或即時通訊 API，讓智慧體能在背景執行與即時對話（live dialog）之間無縫切換，並將對話結果結構化寫回工作流程。

### 潛在風險與注意事項

- **不可逆操作與終局性交接（Irreversible Handoffs）**  
  論文中強調一旦提交或路由即無法編輯。實務上必須在每次 handoff 前設立「模擬演練 + 人類確認閘門」，並在沙盒中完成充分回歸測試，才能進入正式環境。

- **政策幻覺（Policy Hallucination）**  
  LLM 可能誤解保險給付規則或醫療指引，導致錯誤核准或拒絕。建議採用「RAG 強制檢索 + 確定性規則引擎」雙軌驗證，禁止智慧體在未引用明確政策條文的情況下做出核決。

- **長程任務漂移與錯誤累積**  
  論文顯示單一工作階段執行全部任務時通過率僅 3.8%。產品化時應避免讓單一智慧體連續處理過多案件，而是採用任務切分、週期性狀態檢查點（checkpoint）與錯誤復原機制。

- **多方互動中的隱私與資安**  
  病患外展與 P2P 對話涉及受保護健康資訊（PHI）。所有對話紀錄必須加密、去識別化，並符合 HIPAA（美國）或本地個資法（如台灣個資法）規範，且需留存稽核軌跡（audit trail）。

- **角色權限混淆**  
  多角色組合（multi-role composition）架構若設計不當，可能發生護理師角色越權執行醫師審查的風險。必須在工具層與資料層同時實施嚴格的角色權限控管，確保每個 MCP 工具呼叫都帶有當前角色的身份憑證。

---

### 與其他技術的整合建議

- **EHR/EMR 系統（FHIR API）**  
  透過 HL7 FHIR 標準與 MCP 橋接，讓智慧體能直接讀取臨床文件（clinical documents）並將照護計畫（care plans）寫回病患電子病歷，避免資料孤島。

- **RPA（機器人流程自動化）**  
  對於缺乏現代化 API 的舊有醫療系統（legacy systems），可將智慧體的 tool calls 轉發給既有 RPA 腳本，由 RPA 執行 GUI 操作，形成「AI 決策 + RPA 執行」的混合架構。

- **向量資料庫與知識圖譜**  
  政策手冊的檢索建議採用混合架構：向量資料庫負責語意相似度搜尋，知識圖譜負責保險給付條件與醫療指引的邏輯推理，以降低政策檢索的偽陽性率。

- **即時通訊與客服平台**  
  整合電話語音（如 Twilio）、企業即時通訊（如 Slack、Microsoft Teams）或醫療專用客服系統，作為 multilateral interaction 的對話通道，並透過 webhook 將對話結果即時回傳至 agent orchestrator。

- **LLMOps 監控與可解釋性工具**  
  整合 LangSmith、Weights & Biases 或類似工具，追蹤長程事件軌跡（event trail）與每次 tool call 的輸入輸出，特別針對端到端提供者–付款方場景（provider–payer arena）進行根因分析，以理解為何通過率會崩跌至 0%。

### 給不同背景讀者的閱讀建議

**給初學者（Beginners）**  
請聚焦論文的圖 2 與圖 3。醫療 AI 不只是讓模型回答醫學考題，而是讓 AI 智慧體在「充滿規則、需要切換角色、還要與真人對話」的長程流程中擔任虛擬員工。把 χ-Bench 想像成一個數位醫院沙盒，它測試的是 AI 能否像真人一樣走完一整個行政流程，而非單純的問答正確率。

**給 AI 工程師（AI Engineers）**  
請深入閱讀第 3 節的 χ-WorldEngine 與 MCP 工具設計，特別注意 handoff 的不可逆性與世界狀態（world state）管理。論文結果顯示 marathon run（單一工作階段執行全部任務）會讓通過率從 28.0% 崩跌到 3.8%，這是長程 agent 在記憶體、錯誤累積與狀態追蹤上的硬限制，建議從 composite verifier 的實作細節中尋找改善靈感。

**給研究人員（Researchers）**  
請關注論文明確指出的三個研究缺口：政策密度（policy density）、多角色組合（multi-role composition）與多方互動（multilateral interaction）。這些是現有長程 agent 基準測試（如 SWE-Bench、WebArena、τ-Bench）未覆蓋的維度。建議延伸探討其他政策密集且不可逆的企業領域，例如法律合規審查、保險核保或金融監理申報。

**給產品經理（Product Managers）**  
請從 Figure 3 與實驗結果章節著手。即使是最前沿的模型（Claude Opus 4.6 + Claude Code）在真實醫療流程的 pass@1 也只有 28.0%，且嚴格 pass^3 未達 20%。這代表端到端無人化在現階段風險極高，產品路線圖應以「人機協作（human-in-the-loop）」為核心，優先鎖定單點突破（例如只做 intake clerk 的自動登記，或只做 RFI 回應），而非貿然推動全無人化的 prior authorization 或 utilization management。
