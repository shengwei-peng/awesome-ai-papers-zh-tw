## ⚡ TL;DR

長片影片由旁白腳本生成涉及多鏡頭決策的相互依賴，現有代理式編輯器難以兼顧品質與成本。
WeVisCut 提出腳本到影片代理框架，結合剪輯反推與驗證式回放資料管線，訓練單一 9B 策略。
100 項任務基準上，系統超越基礎模型與原生編輯器，符元成本僅 Opus 5 的 1/33。

從旁白（narration）產出長片影片（long-form video）需要跨鏡頭（shot）保持一致的相互依存決策。現有的代理式編輯器（agentic editors）常採用由通用模型（general models）驅動的多階段工作流程（multi-stage workflows），使得精簡且任務適配之策略（compact, task-adapted policies）在品質與成本間的取捨（quality-cost trade-off）仍不明確。我們以 WeVisCut 來填補此缺口，這是一個長片腳本到影片（script-to-video）系統，將工具執行（tool execution）與策略學習（policy learning）相結合。其代理框架（agent harness）維護共享製作狀態（shared production state），使工具回饋（tool feedback）能夠影響後續決策與修復。由於完成後的影片並不會顯現這些決策，我們的四階段資料管線（four-stage data pipeline）結合剪輯反推（editing inversion）與驗證式回放（verified replay），將還原出的剪輯意圖（editing intent）轉化為可執行監督訊號（executable supervision）。應用於 3,750 部完成後的影片，此管線產出超過 13 萬筆訓練樣本（training examples）。我們利用此監督訊號訓練單一 9B 參數策略（9B policy），該策略在同一代理框架內協調製作並從失敗中恢復。此外，我們提出一個 100 項任務基準測試（100-task benchmark）及五項互補評估指標（five complementary metrics），評估剪輯品質（editing quality）與交付可靠性（delivery reliability）。在共享工具環境（shared tool environment）下，WeVisCut 顯著優於其基礎模型（base model），同時每分鐘成功輸出（successful output minute）所消耗的生成符元（generated tokens）數量減少近 33 倍，表現與 Claude Opus 5 相當。在我們提出的評估指標上，它也優於任務對應之原生編輯器（task-matched native editors）。

### 核心貢獻（3～5點）
- **系統整合**：提出 WeVisCut 長片腳本到影片系統，透過代理框架維護共享製作狀態，使工具回饋能跨階段影響決策與修復。
- **資料管線**：設計四階段資料管線，結合剪輯反推與驗證式回放，從 3,750 部完成影片中產出超過 13 萬筆可執行監督訊號。
- **精簡策略**：訓練單一 9B 參數策略，在同一代理框架內同時負責協調製作與失敗恢復，實現品質與成本的平衡。
- **評估基準**：提出 100 項任務基準測試與五項互補評估指標，系統性衡量剪輯品質與交付可靠性。

### 適合對象
從事影片生成、智慧剪輯、代理式 AI（agentic AI）、強化學習與策略學習的研究者與工程師；尤其適合關注長片影片自動化製作、工具增強型語言模型（tool-augmented LMs）、以及訓練資料合成管線設計的讀者。

## 深度分析

#### 方法論解析

WeVisCut 的核心方法論圍繞三個相互耦合的設計支柱展開：**有狀態代理框架（stateful agent harness）**、**可執行監督訊號（executable supervision）建構管線**、以及**任務適配策略（task-adapted policy）的多階段訓練**。這三者在論文中以「工具執行 ↔ 策略學習」的雙向耦合為核心命題，試圖解決既有代理式編輯器（agentic editors）僅靠通用模型編排（orchestration）而缺乏精簡任務專用策略的品質—成本取捨（quality-cost trade-off）問題。

**1. 代理框架（Agent Harness）的設計哲學**

WeVisCut 的代理框架（Figure 2）採用「共享策略 + 有狀態執行環境（stateful runtime）」的分離架構。共享策略（shared policy）負責所有剪輯決策，而有狀態執行環境則負責工具呼叫（tool calls）的實際執行與製作產物（production artifacts）的持久化維護。這種設計的關鍵在於「共享製作狀態（shared production state）」——所有製作角色（production roles）共享同一份狀態，使得工具回饋（tool feedback）能夠即時影響後續決策，並支援有界修復（bounded repair）與重新規劃（replanning）。此一架構與 Crayotter 的多代理工作流程（multi-agent workflow）形成對比：Crayotter 透過專責代理（specialized agents）分工，但缺乏統一的狀態管理；而 WeVisCut 透過單一策略路由（role-routed policy）實現「一個模型扮演所有製作角色」的設計，這在部署成本與一致性維護上具有結構性優勢。

框架內建的「驗證式工具動作（validated tool actions）」機制確保每個工具呼叫在執行前經過合法性檢查，這對於長時序（long-horizon）任務尤為關鍵——一個錯誤的工具呼叫可能導致整個時間軸（timeline）崩潰。論文中特別強調「保留未受影響的成功產物（preserving unaffected artifacts from earlier successful production steps）」，這意味著修復機制具有局部性，避免因局部錯誤而觸發全面重做。

**2. 四階段資料管線（Four-Stage Data Pipeline）的方法論突破**

論文最具方法論創新性的部分在於如何從「已完成的影片」中萃取可執行的監督訊號。傳統的影片編輯資料缺乏工具呼叫、中間產物（intermediate artifacts）與失敗記錄，這使得直接從成品影片訓練代理變得不可行。WeVisCut 提出四階段管線（Figure 3）來解決此一根本性挑戰：

- **剪輯反推（Editing Inversion）**：從成品影片反推腳本—鏡頭意圖（script–shot intent），這是一個逆向工程問題，需要從視覺內容、時間軸結構與敘事邏輯中恢復原始剪輯決策。
- **驗證式回放（Verified Replay）**：將反推得到的剪輯意圖在實際製作工具中執行，並驗證執行結果是否與原始影片一致。此階段扮演「事實查核（ground-truth checking）」的角色，過濾反推過程中的幻覺（hallucination）。
- **觀察—反思—修復（Observe–Reflect–Repair）**：當回放揭示缺陷（defects）時，引入有界修正（bounded corrections）機制，在保留成功產物的前提下進行局部修復。此階段模擬了人類剪輯師「邊做邊改」的真實工作流程。
- **軌跡具體化（Trajectory Materialization）**：將前述階段記錄的執行過程（recorded executions）組織成包含工具回饋與修復結果的訓練樣本。

從 3,750 個影片專案中萃取超過 130K 筆訓練樣本，平均每個專案貢獻約 35 筆樣本，這個資料規模在影片編輯領域屬於中大型規模。值得注意的是，這個管線的設計哲學與 AgentTrek（從教學文件建構網頁代理軌跡）有異曲同工之妙，但 WeVisCut 處理的是更高維度、更長時序的影片製作任務。

**3. 三階段策略訓練的演算法設計**

訓練流程（Figure 4）採用循序漸進的三階段設計，每階段解決不同的學習瓶頸：

- **階段一：統一監督式微調（Unified SFT）+ 執行期驗證之拒絕取樣微調（Runtime-Verified RFT）**：建立基礎的工具使用與恢復能力。SFT 提供初始行為模式，RFT 則透過執行期驗證過濾掉無法成功執行的軌跡，確保訓練樣本的可執行性。
- **階段二：Guided-OPD**：學習在策略可達狀態（policy-reached states）上的恢復行為，同時逐步淘汰教師介入（teacher intervention）。Guided-OPD 混合教師與學生回合（turns），並使用截斷的教師 logits（truncated teacher logits）來控制干預程度。這與 DAgger 的專家標註策略以及 TurnOPD/Step-Level OPD 的細粒度監督形成方法論上的連續性。
- **階段三：RCF-DAPO（Role- and Context-Factored DAPO）**：論文的另一個關鍵創新。RCF-DAPO 將 DAPO 的群組相對比較（group-relative comparisons）限制在「對應角色（matched roles）與對應決策上下文（matched decision contexts）」內，避免跨角色比較帶來的雜訊。這對於多角色統一策略（multi-role unified policy）尤其重要——不同角色的決策空間與評估標準差異極大，跨角色比較會導致獎勵訊號失真。

整體而言，WeVisCut 的方法論展現了「系統設計 ↔ 資料建構 ↔ 策略學習」三者緊密耦合的工程哲學，這與當前 LLM 代理研究中「資料—演算法—環境」三位一體的趨勢高度一致。

#### 實驗數據解讀

**1. 基準測試（Benchmark）設計的評估哲學**

論文提出 100 項任務的基準測試，涵蓋 5 項互補評估指標（five complementary metrics），這套評估體系的設計反映了「不僅評估渲染結果，更評估製作過程」的核心理念。五項指標分別對應：

- **腳本忠實度（Script Fidelity）**：衡量渲染影片與原始腳本的一致性。
- **視覺—旁白對齊（Visual–Narration Alignment）**：評估視覺素材與旁白內容的語意匹配程度。
- **時間軸計畫實現度（Timeline Plan Realization）**：衡量實際時間軸與規劃時間軸的吻合度。
- **長時序一致性（Long-Horizon Consistency）**：評估跨鏡頭序列（shot sequence）的敘事連貫性。
- **端到端交付成功率（End-to-End Delivery Success）**：衡量從腳本到成功渲染影片的完整流程成功率。

這套指標體系的一個重要設計選擇是「將渲染影片與腳本及製作計畫（production plans）關聯起來」，使得評估超越了「能否成功渲染」的二元判斷，進入了「渲染品質是否達標」的細粒度評估。這與 VBench、VideoScore、VMBench 等純生成品質評估，以及 Goku-Bench 的指令式編輯評估形成互補。

**2. 關鍵實驗結果的解讀**

論文報告了三組關鍵比較結果：

- **與基礎模型（base model）的比較**：WeVisCut 在 Overall Score 上提升 16.0 點。這個數字的絕對值需要放在基準測試的滿分尺度下理解——若滿分為 100，則 16.0 點的提升屬於顯著改善；若採用相對提升，則意味著策略學習帶來了約 16% 的品質增益。這個結果驗證了「任務適配微調相對於通用模型的價值」。

- **與 Claude Opus 5 的比較**：在共享工具環境（shared tool environment）下，WeVisCut 達到與 Claude Opus 5 相當的品質，但每分鐘成功輸出僅使用約 1/33 的生成符元（generated tokens）。這個 33× 的效率優勢是論文最引人注目的結果之一。從經濟角度，這意味著 WeVisCut 的推理成本僅為 Claude Opus 5 的約 3%，這對於商業化部署具有重大意義。但需要注意的是，「每分鐘成功輸出」的計算方式需要明確——是否包含失敗案例的重試成本？是否包含工具呼叫的符元消耗？這些細節會顯著影響實際成本估算。

- **與任務對應之原生編輯器（task-matched native editors）的比較**：WeVisCut 在提出的五項指標上均優於原生編輯器。這表明任務專用策略在特定任務領域內可以超越通用工具，但此結論的外部有效性（external validity）受限於「任務對應」的範疇定義。

**3. 實驗設計的潛在疑慮**

雖然論文報告了令人印象深刻的結果，但有幾個實驗設計細節值得進一步審視：

- **基準測試的規模**：100 項任務對於影片編輯領域的全面評估而言規模偏小，可能無法充分覆蓋長片影片（long-form video）的多樣性場景。
- **「共享工具環境」的公平性**：WeVisCut 與 Claude Opus 5 在共享工具環境下比較，但兩者的工具呼叫模式可能不同——WeVisCut 的 9B 策略經過特定工具的微調，而 Claude Opus 5 可能需要更長的提示工程（prompt engineering）來適配相同工具。這種「適配不對稱」可能部分歸因於效率差異而非純粹的模型能力差異。
- **「成功輸出分鐘數」的定義**：33× 的效率優勢高度依賴於「成功輸出」的定義。若包含失敗重試，實際成本差距可能縮小。

#### 與現有研究的比較

**1. 在影片編輯代理領域的定位**

WeVisCut 的定位可以從兩個軸度來理解：**代理架構**與**訓練方法**。

在**代理架構**軸上，WeVisCut 與以下系統形成對比：

- **LAVE**：保持使用者在剪輯迴路中，屬於「人機協作」範式；WeVisCut 則追求「全自動化」。
- **CutClaw 與 CineAgents**：處理音樂同步剪輯與電影彙編，屬於特定子任務的自動化；WeVisCut 處理更通用的腳本到影片轉換。
- **Crayotter**：使用可追溯的多代理工作流程（traceable multi-agent workflow），強調流程透明度；WeVisCut 採用單一策略路由，強調部署簡潔性。
- **VideoAgent**：動態組裝專家代理（specialists），屬於「執行時編排」範式；WeVisCut 採用「訓練時整合」範式。
- **Aurora**：訓練規劃器進行局部編輯，屬於「局部自動化」；WeVisCut 處理完整的端到端流程。

在**訓練方法**軸上，WeVisCut 與以下工作形成對比：

- **「The Script is All You Need」**：訓練 ScripterAgent 但使用獨立的 DirectorAgent，屬於「多模型分工」；WeVisCut 使用單一 9B 策略統一所有角色。
- **後續 Crayotter 工作（9B 策略）**：使用最終影片偏好（final-video preferences）在人工建構的任務上訓練；WeVisCut 使用從成品影片反推出的可執行軌跡，資料來源更自然且規模更大。

**2. 相較於既有工作的改進**

WeVisCut 的主要改進可以歸納為三點：

- **資料效率**：透過剪輯反推與驗證式回放，從 3,750 個影片專案產出 130K+ 訓練樣本，資料利用率高於人工標註方法。
- **推理效率**：33× 的符元效率優勢使其在商業部署上具有顯著的成本競爭力。
- **統一性**：單一策略處理所有製作角色，避免了多代理系統的協調開銷與一致性問題。

**3. 既有工作的侷限性與 WeVisCut 的不足**

WeVisCut 並非沒有侷限性：

- **固定旁白假設**：WeVisCut 假設輸入包含固定旁白（fixed narration），這限制了其應用於「需要生成旁白」的場景。相較之下，部分既有工作支援更靈活的旁白合成（narration synthesis）。
- **單一模型規模**：9B 參數的策略雖然精簡，但對於極複雜的長片製作可能存在能力上限。Claude Opus 5 等更大模型在處理高度複雜任務時可能仍具優勢。
- **基準測試的外部有效性**：100 項任務的基準測試雖然精心設計，但對於真實世界的影片製作多樣性可能覆蓋不足。
- **可解釋性**：單一策略路由雖然部署簡潔，但相較於多代理系統的可追溯工作流程，其決策過程較難以審計。

#### 可重現性評估

**1. 程式碼與模型權重的可用性**

根據論文提供的全文內容，**WeVisCut 並未明確聲明開源（open-source）**。論文中沒有提及程式碼儲存庫（code repository）、模型權重（model weights）或資料集（dataset）的公開發布計畫。這對於學術可重現性（academic reproducibility）構成重大障礙。

**2. 資料管線的可重現性挑戰**

即使未來釋出程式碼，WeVisCut 的資料管線也面臨獨特的可重現性挑戰：

- **剪輯反推（Editing Inversion）的依賴性**：此步驟需要從成品影片反推剪輯意圖，其品質高度依賴於影片的元資料豐富度與反推模型的選擇。論文中未詳細說明反推模型的具體架構與訓練資料。
- **驗證式回放的工具依賴性**：回放過程依賴於特定的影片製作工具鏈，這些工具的版本、配置與 API 變化都可能影響重現結果。
- **觀察—反思—修復的隨機性**：修復過程可能涉及隨機探索，這使得相同輸入可能產生不同的訓練軌跡。

**3. 基準測試的可重現性**

100 項任務的基準測試與五項指標的設計是論文的重要貢獻之一，但論文中未提供完整的任務定義、評估腳本或評審標準（rubric）。若這些資源能夠公開，將大幅提升研究的可重現性與後續比較的便利性。

**4. 訓練細節的透明度**

## 論文問答

**Q1：為什麼從旁白腳本生成長片影片是一個困難的任務？**

A：從旁白腳本生成長片影片涉及多個相互依賴的決策，包括規劃、視覺素材檢索、旁白合成與時間軸組裝，這些決策必須在所有鏡頭之間保持連貫一致。改變某個鏡頭的持續時間會影響後續所有時間戳，而不合適的視覺素材可能需要同時重新檢索與重新規劃整個受影響的鏡頭序列。這種長程依賴性使得任務無法被簡單地分解為獨立子問題來解決，需要一個能夠維持共享製作狀態並支援跨鏡頭修復的整合系統。

**Q2：現有的代理式編輯器方法為何無法有效解決這個問題？**

A：現有的代理式編輯器通常採用由通用模型驅動的多階段工作流程，依賴專責代理與工具流程的編排，但這種編排本身並未說明如何訓練一個能在低符元成本下維持影片品質的精簡策略。Crayotter 等系統雖然訓練了 9B 剪輯模型，但使用的是基於人工建構任務的最終影片偏好，這種策略需要一個有狀態環境來執行與恢復，以及紮根於該環境的監督訊號。然而，已完成的影片並未記錄工具呼叫、中間產物與失敗過程，因此無法直接從中獲取可執行的監督訊號，這正是現有方法的核心瓶頸。

**Q3：為什麼這個問題在學術與產業上都很重要？**

A：奧森·威爾斯曾說「電影的全部雄辯都在剪輯室中實現」，凸顯了剪輯在影片製作中的核心地位。從產業角度來看，長片影片的自動化生產能大幅降低教育、行銷、紀錄片等領域的內容製作成本，並使個人創作者能產出專業級作品。從學術角度來看，這個問題橫跨代理式人工智慧、長程規劃、工具使用與多模態生成等多個前沿議題，是檢驗現代 AI 系統在複雜真實任務中表現的理想試金石。

**Q4：WeVisCut 的核心方法是什麼？**

A：WeVisCut 整合了三大核心組件：腳本到影片的代理框架、可執行的資料建構流程以及任務適配的策略。代理框架負責維持共享製作狀態並驗證工具動作，將執行回饋開放給檢視、有界修復與重新規劃，同時保留先前成功製作步驟中未受影響的產物。在這個框架內，系統透過四階段資料管線將 3,750 個影片專案轉化為超過 130K 筆訓練樣本，並用來訓練一個統一承擔所有製作角色的 9B 參數策略。

**Q5：WeVisCut 最關鍵的創新是什麼？**

A：WeVisCut 最關鍵的創新在於其四階段資料管線，能夠從已完成的影片中重建可執行的監督訊號。首先透過剪輯反推從成品影片中恢復腳本–鏡頭意圖，再以驗證式回放執行該意圖；當回放揭示缺陷時，系統會啟動觀察–反思–修復機制進行有界修正，保留已成功的產物；最後透過軌跡具體化將記錄的執行過程整理成包含工具回饋與修復結果的訓練樣本。這種「從成品反推意圖並重建可執行軌跡」的方法，突破了傳統監督式學習需要完整標註軌跡的限制。

**Q6：訓練策略的設計選擇有哪些考量？**

A：WeVisCut 採用三階段循序漸進的訓練策略，每一階段都針對前一階段的不足進行補強。第一階段透過統一監督式微調與執行期驗證之拒絕取樣微調建立基礎的工具使用與恢復能力；第二階段引入 Guided-OPD，在策略可達狀態上學習恢復行為，並逐步淘汰教師介入；第三階段則使用本文提出的 RCF-DAPO，僅在對應角色與決策上下文內比較執行期結果以優化決策。這種設計避免了直接從頭訓練一個複雜多角色策略的困難，並透過角色與上下文分解減少了獎勵信號的雜訊。

**Q7：論文中提出的評估基準測試有何特色？**

A：本文提出了一個包含 100 項腳本到影片任務的基準測試，並設計了五項互補的評估指標，分別評估腳本忠實度、視覺–旁白對齊、時間軸計畫實現、長程一致性與端到端交付成功。這些指標將渲染後的影片與其腳本和製作計畫關聯起來，使評估超越了單純的成功渲染，能夠更細緻地衡量剪輯品質與交付可靠性。這種結合影片品質與製作過程的評估方式，填補了現有基準測試如 VBench、VideoScore 與 VMBench 僅關注生成影片品質的不足。

**Q8：WeVisCut 的主要實驗結果為何？**

A：在共享工具環境下，WeVisCut 相較其基礎模型在 Overall Score 上提升了 16.0 分，並達到了與 Claude Opus 5 相當的表現水準，但每分鐘成功輸出所使用的生成符元數僅為後者的約 1/33。此外，完整的 WeVisCut 系統在本文提出的指標上也優於任務對應之原生編輯器。這些結果顯示，透過適當的監督訊號與訓練策略，較小的任務適配模型不僅能匹配大型通用模型的品質，還能在成本上取得顯著優勢。

**Q9：論文中是否有消融實驗來驗證各組件的貢獻？**

A：雖然提供的全文未明確列出消融實驗的數據，但從方法描述可以推論出三階段訓練本身即提供了逐步驗證的設計：每一階段的引入都對應前一階段未解決的問題，例如 Guided-OPD 解決了純監督式微調無法處理策略可達狀態的問題，而 RCF-DAPO 則進一步透過角色與上下文分解優化了獎勵信號。此外，四階段資料管線中的剪輯反推、驗證式回放、觀察–反思–修復與軌跡具體化各司其職，每個組件對最終監督訊號的品質都有具體貢獻。

**Q10：WeVisCut 的實際應用場景有哪些？**

A：WeVisCut 適用於任何需要從固定旁白腳本生成長片影片的場景，包括教育課程影片、紀錄片、企業簡報、產品介紹、新聞摘要與社群媒體內容等。在教育領域，教師可以將授課內容轉化為視覺化的影片教材；在行銷領域，企業可以快速將產品文案轉化為展示影片；在新聞領域，編輯可以將文字報導轉化為視覺新聞。這種自動化的影片生產流程特別適合需要大量產出但預算有限的中小型內容創作者。

**Q11：將 WeVisCut 產品化時需要考量哪些因素？**

A：產品化的關鍵優勢在於成本效益：WeVisCut 達到了與 Claude Opus 5 相當的品質，但每分鐘成功輸出僅需約 1/33 的生成符元數，這對於需要大規模產出影片的服務而言是巨大的經濟優勢。然而，產品化時仍需考量運算資源需求、影片渲染時間、視覺素材庫的授權與取得、以及對不同旁白語言與口音的支援。此外，系統對失敗的恢復能力雖然透過有界修復機制有所提升，但在生產環境中仍需設計人工介入的介面以處理邊緣案例。

**Q12：WeVisCut 對該研究領域有何影響？**

A：WeVisCut 展示了透過適當的監督訊號與訓練策略，緊湊的任務適配模型能夠在複雜的長程任務中匹配甚至超越大型通用模型，這對代理式人工智慧領域具有示範意義。其四階段資料管線提供了一個從成品資料中重建可執行監督訊號的通用範式，可應用於其他缺乏完整軌跡記錄的領域。此外，RCF-DAPO 中角色與上下文分解的概念也為多角色多任務的策略學習提供了新的思路，有望推動相關研究的發展。

**Q13：論文中承認的限制有哪些？**

A：WeVisCut 目前專注於固定旁白製作，這意味著系統假設輸入的旁白腳本是預先決定的，不支援在製作過程中動態生成或修改旁白。此外，訓練資料來自 3,750 個影片專案，這些專案的領域與風格會限制系統的適用範圍；對於訓練資料中未涵蓋的影片類型或視覺風格，系統的表現可能會下降。系統也依賴於一套特定的工具環境，若要遷移到不同的剪輯軟體或素材庫，需要重新適配。

**Q14：WeVisCut 可能遭遇哪些失敗案例？**

A：在驗證式回放階段，當重建的腳本–鏡頭意圖無法在當前工具環境中正確執行時，系統會遭遇缺陷；此時雖然可以透過觀察–反思–修復進行有界修正，但若缺陷超出有界修復的範圍，則可能需要重新規劃整個受影響的鏡頭序列。此外，當視覺素材檢索無法找到符合腳本描述的素材時，系統可能被迫使用次佳的替代方案，影響視覺–旁白對齊的品質。在長程一致性方面，若早期鏡頭的決策與後期需求衝突，系統可能難以在不破壞已成功產物的情況下進行調整。

**Q15：未來的研究方向有哪些？**

### 實作前置條件

**資料面**
- 至少數千筆「已完成」的旁白影片專案（建議 3,000 筆以上以對齊論文中 3,750 筆規模），需含腳本、鏡頭規劃、媒體素材與最終時間軸。
- 對應的素材庫（圖片、影片片段、旁白音檔）需有可程式存取的 metadata（時間碼、場景標籤、人物/物件標註）。
- 影片專案的版本歷史或編輯日誌（若無，須仰賴論文的「剪輯反推」流程從成品反推意圖）。

**算力面**
- 訓練階段：需具備可容納 9B 參數模型進行 SFT、RFT、Guided-OPD 與 RCF-DAPO 的 GPU 叢集（建議 H100 或同等級以上，建議 8 卡以上節點）。
- 推論階段：單一 9B 模型搭配工具環境即可部署，符元成本約為 Claude Opus 5 的 1/33，但仍需規劃 vLLM / SGLang 等高效推論框架。
- 工具執行環境：剪輯工具（FFmpeg、剪輯 API）、TTS、視覺素材檢索引擎皆需可程式呼叫並具備狀態保存機制。

**技能面**
- 熟悉 agent harness 設計（共享狀態、工具驗證、有界修復）。
- 具備長序列決策的 RL 經驗（PPO / GRPO / DAPO 家族），特別是角色分解式獎勵設計。
- 影音工程基礎（時間軸、編解碼、媒體 metadata 處理）。
- 資料工程能力（軌跡具體化、拒絕取樣、執行期驗證管線）。

### 實作步驟建議

1. **盤點既有影片資產並建立 metadata schema**：先對組織內的影片專案進行清查，定義腳本、鏡頭、素材、時間軸的結構化欄位，這是後續「剪輯反推」能否成功的關鍵。
2. **搭建有狀態的代理框架（agent harness）**：實作共享製作狀態（production state）、工具動作驗證層、檢視與有界修復機制，確保未受影響的成功產物不會被錯誤回滾。
3. **建立四階段資料管線**：
   - 階段一「剪輯反推」：從成品影片反推腳本–鏡頭意圖。
   - 階段二「驗證式回放」：在工具環境中執行反推意圖，記錄成功與失敗。
   - 階段三「觀察–反思–修復」：針對失敗案例進行有界修正，保留成功產物。
   - 階段四「軌跡具體化」：將執行紀錄整理為含工具回饋與修復結果的訓練樣本。
4. **三階段訓練 9B 策略模型**：
   - Phase 1：統一 SFT + 執行期驗證之拒絕取樣微調，建立工具使用與基礎修復能力。
   - Phase 2：Guided-OPD，在策略可達狀態上學習修復，逐步降低教師介入。
   - Phase 3：RCF-DAPO，在對應角色與決策上下文內比較執行期結果以優化決策。
5. **建立 100 項任務基準測試與五項評估指標**：腳本忠實度、視覺–旁白對齊、時間軸計畫實現度、長程一致性、端到端交付成功率，作為內部迭代與外部比較的共同語言。
6. **小規模試點 → 逐步放量**：先以單一業務場景（例如內部訓練教材）試運行，量測符元成本、成功率與人工覆核率，再擴展到其他場景。

### 潛在風險與注意事項

- **剪輯反推的歧義性**：成品影片不含原始編輯決策，反推意圖可能與原作者不同；緩解方式是引入多版本反推與人工抽樣驗證，並在資料管線中保留「反推信心分數」。
- **工具環境的非確定性**：視覺素材檢索、TTS、剪輯 API 的輸出可能隨版本或隨機種子變動，導致「驗證式回放」結果不一致；應固定工具版本、記錄隨機性來源，並在訓練樣本中標註環境指紋。
- **有界修復的範圍界定**：若修復動作過於激進，可能破壞先前成功的產物；若過於保守，則無法從失敗中恢復；建議以「保留成功產物」為硬性約束，並對修復步數設定上限。
- **RCF-DAPO 的獎勵稀疏問題**：長程任務中成功訊號稀少，僅在對應角色與上下文內比較可能導致訓練不穩定；可考慮加入中間檢查點獎勵或成形獎勵（shaping reward）。
- **基準測試的代表性**：100 項任務可能無法涵蓋所有業務場景；應在內部再擴充任務集，並定期以人工評審校正指標權重。
- **符元成本雖低但仍非零**：33 倍的成本優勢是相對值，絕對成本仍隨影片長度線性成長；建議設定每分鐘成本預算與監控儀表板。
- **法律與版權風險**：自動檢索的視覺素材可能涉及授權爭議；需在管線中嵌入素材授權檢查與人工覆核節點。

### 與其他技術的整合建議

- **與 RAG / 視覺素材庫整合**：將視覺素材檢索模組改為可插拔的 RAG 介面，支援企業自有的 DAM（Digital Asset Management）系統或第三方素材庫（如 Getty、Pexels API）。
- **與 TTS / 語音克隆整合**：旁白合成可接上 Azure TTS、ElevenLabs 或自架語音模型，保留語者一致性與情緒控制介面。
- **與剪輯工具整合**：透過 FFmpeg、Premiere Pro ExtendScript 或 DaVinci Resolve API 對接既有剪輯流程，讓 WeVisCut 產出的時間軸可直接匯入專業剪輯環境做最後微調。
- **與 MLOps / 監控整合**：將訓練樣本、推論軌跡、修復紀錄接入特徵商店與監控系統（如 Langfuse、Weights & Biases），以便追蹤品質漂移與成本趨勢。
- **與內容審核整合**：在交付前串接內容審核（NSFW、品牌安全、版權檢查）作為最後一道工具動作，確保合規。
- **與既有 agent 框架整合**：可將 WeVisCut 的 agent harness 視為一個垂直領域外掛，接入 LangGraph、AutoGen 等通用 agent 編排框架，處理跨系統的任務分派。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節，理解「為什麼長片影片生成需要 agent + 工具 + 策略學習」這個核心問題；接著跳到第 3 節的框架圖，理解「共享製作狀態」與「有界修復」的概念，再回頭看資料管線與訓練流程。實作上可先從小規模的腳本到影片 demo 開始，不必一開始就處理 130K 訓練樣本。

**給 AI 工程師**：重點放在第 3 節的 agent harness 設計、第 4 節的四階段資料管線（特別是「剪輯反推」與「驗證式回放」的工程實作），以及第 5 節的三階段訓練（Phase 2 的 Guided-OPD 與 Phase 3 的 RCF-DAPO 是相對少見的技術組合）。建議直接動手實作最小可運行版本：先做單鏡頭的腳本到影片，再逐步擴展到多鏡頭與修復流程。

**給研究者**：核心貢獻在於「將成品影片轉為可執行監督訊號」的資料管線設計，以及「角色與上下文分解式 DAPO（RCF-DAPO）」的獎勵設計。建議仔細閱讀第 4 節與第 5 節，並與 AgentTrek、Crayotter、DAPO 原論文做對比；100 項任務基準與五項指標也是可延伸的研究方向（例如擴充到其他長序列決策領域）。

**給產品經理**：重點關注第 1 節的問題陳述、第 6 節的實驗結果（16 分提升、33 倍符元成本優勢、與 Claude Opus 5 相當的品質），以及第 7 節的應用討論。建議從「適用場景」一節切入，挑選一個高 ROI 的業務場景（例如內部訓練教材或 Podcast 影音化）作為試點，並以五項指標作為與既有流程比較的基準。
