## ⚡ TL;DR

現有機器人策略僅靠被動觀察，無法推斷隱藏物理屬性，簡單互動又易過度探索。
PhysCaP 引入無訓練的質量與剛度估計，並以雙代理設計實現高效物理資訊探索。
真實與模擬任務中，PhysCaP 以更少互動與更短時間達成高成功率，消融實驗亦驗證模組有效性。

## 摘要翻譯

我們提出 PhysCaP，一個以物理資訊引導的程式即策略（Code-as-Policy）智能體，用於機器人操作（robotic manipulation）中的主動感知（active perception）。雖然視覺-語言-動作策略（Vision-Language-Action, VLA policies）擅長模仿示範，但它們僅依賴被動觀察（passive observation），無法推斷對操作至關重要的潛在物理屬性（latent physical properties）。PhysCaP 在程式即策略（Code-as-Policy）框架中加入物理資訊引導探索層（Physics-Informed Exploration Layer），使其能透過互動進行顯式資訊尋求（explicit information-seeking）。本方法引入無需訓練的物理屬性提取模組（Training-Free Physical Property Extraction Modules），僅利用機器人本體感覺（robot proprioception）即可估計物體質量（object mass）與剛度（stiffness），無需額外感測器。為了平衡探索成本與所獲資訊的效率，PhysCaP 採用雙代理設計（dual-agent design）：規劃器（Planner）決定何時探索、何時停止；優先排序器（Prioritizer）則過濾不合理互動（implausible interactions），並以啟發式優先分數（heuristic priority score）為其餘互動排序，從而實現高效且有目標的探索。我們在真實世界桌面操作任務（real-world tabletop manipulation tasks），包括搜尋隱藏物體（hidden objects）、檢測空罐（empty cans）與尋找成熟酪梨（ripe avocados），以及 LIBERO 中的一項模擬任務上評估 PhysCaP。結果顯示，現有的被動基線（passive baselines）與簡單互動基線（naive interactive baselines）在物理屬性被隱藏時會失效，或產生過度探索（over-explore）；相較之下，PhysCaP 能以較少的互動次數（interactions）與更短的執行時間（execution time）達到相近的表現。消融研究（ablation studies）進一步驗證了所提出物理屬性提取模組的有效性。專案頁面（Project page）：https://physcap.github.io

### 核心貢獻（3～5點）
- 提出 PhysCaP，將物理資訊引導探索（Physics-Informed Exploration）與程式即策略（Code-as-Policy）智能體結合，使機器人能透過互動主動感知潛在物理屬性。
- 設計無需訓練的物理屬性提取模組，僅利用機器人本體感覺即可估計物體質量與剛度，無需額外感測器或訓練。
- 提出雙代理設計（Planner + Prioritizer），平衡探索成本與資訊效益，過濾不合理互動並以啟發式優先分數排序，實現高效且有目標的探索。
- 在真實世界桌面操作任務與 LIBERO 模擬任務中驗證，相較被動基線與簡單互動基線，PhysCaP 以更少的互動次數與執行時間達到相近表現。
- 透過消融研究驗證物理屬性提取模組對整體系統的有效性。

### 適合對象
本論文適合機器人學、具代理性的機器人學習框架（agentic robot learning framework）與主動感知研究者；對結合大型語言模型／視覺語言模型與物理先驗以提升機器人操作感興趣的讀者；亦適合關注可解釋（interpretable）、可修改（modifiable）策略，以及低訓練成本機器人系統的工程師與研究生。

## 深度分析

#### 方法論解析

PhysCaP 的核心貢獻在於將 **Physics-Informed Exploration（物理資訊引導的探索）** 層嵌入現有的 **Code-as-Policy（程式即策略）** 框架，使機器人不再僅依賴 **Passive Observation（被動觀察）**，而能透過物理互動主動估計 **Latent Physical Properties（潛在物理屬性）**。整體方法可拆解為三個層次：底層的物理屬性提取模組、中間層的雙代理決策架構，以及頂層的程式碼生成與執行機制。

**1. 無需訓練的物理屬性提取模組（Training-Free Physical Property Extraction Modules）**

PhysCaP 提出從 **Robot Proprioception（機器人本體感覺）** 直接估計物體的 **Object Mass（物體質量）** 與 **Stiffness（剛度 / 硬度）**，無需額外的力覺或觸覺感測器。具體而言：

- **質量估計**：機器人透過夾爪抓取物體後執行提升動作，利用關節扭矩（joint torque）或馬達電流在靜力平衡條件下的變化，推算出物體施加於末端的重力負載。由於機器人自身運動學與動力學模型已知，扣除夾爪與手臂自重後，即可得到物體質量。這種方法屬於典型的「本體感覺測重（proprioceptive weighing）」，優點是硬體成本低，缺點是對摩擦力、加速度與夾持姿態敏感。
- **剛度估計**：機器人對物體施加可控的擠壓或按壓，並記錄末端執行器的位移與對應的反作用力（同樣由關節扭矩推估）。透過力–位移曲線的斜率即可估計物體的局部剛度。這對於判斷酪梨成熟度、包裝盒是否為空、物體是否為剛體等任務特別重要。

這兩個模組的關鍵在於「training-free」：它們不依賴大規模資料訓練，而是利用物理先驗與機器人模型進行閉式推估，因此具備良好的可解釋性與跨任務遷移能力。

**2. 雙代理決策架構：Planner 與 Prioritizer**

引入主動探索後，系統面臨一個基本權衡：在資訊不足下行動可能導致錯誤，而過度互動則會增加 **Execution Time（執行時間）** 與機械磨損。PhysCaP 透過 **Dual-Agent Design（雙代理設計）** 解決此問題：

- **Planner（規劃器）**：負責高階決策，判斷當前信念是否足以執行任務，抑或需要進一步探索。它本質上是一個基於不確定性與任務目標的停止條件控制器。當視覺觀測無法區分候選物體（例如多個外觀相似的罐子）時，Planner 會呼叫探索程序；當收集到的物理資訊已能做出高信心決策時，Planner 終止探索並進入任務執行階段。
- **Prioritizer（優先排序器）**：負責在眾多可能的互動中篩選並排序。它首先利用常識與物理先驗過濾 **Implausible Interactions（不合理互動）**（例如對一個明顯密封且未開封的罐子進行搖晃稱重），然後對剩餘候選動作計算 **Heuristic Priority Score（啟發式優先分數）**。此分數結合了視覺語言模型（VLM）對任務相關性的判斷與物理資訊增益的啟發式估計，使機器人優先執行最有可能改變決策的互動。

這種分工類似於「何時問問題」與「問誰」的區別：Planner 決定是否繼續探索，Prioritizer 決定探索哪個對象。兩者協同使 PhysCaP 能在減少 **Interactions（互動次數）** 的同時維持高成功率。

**3. 與 Code-as-Policy 的整合**

PhysCaP 延續 **Code-as-Policy（程式即策略）** 的模組化哲學，將感知、推理、記憶與控制封裝為可呼叫的函式。新增的物理探索層以額外 API 形式出現，例如 `get_mass()`、`measure_stiffness()` 等，讓大型語言模型（LLM）在生成程式碼時能夠顯式呼叫。這保留了 Code-as-Policy 的優勢：策略可解釋、可修改、可組合，並能利用 LLM 的常識推理能力來決定探索順序與條件。

整體流程可概括為：

1. LLM 根據任務指令與視覺觀測生成初始計畫。
2. 若觀測中存在無法直接辨識的隱藏屬性，Planner 啟動探索階段。
3. Prioritizer 篩選候選物體並排序，選出最具資訊量的互動。
4. 機器人執行物理互動，物理屬性提取模組更新信念狀態。
5. Planner 評估資訊是否足夠；若足夠則執行最終操作，否則回到步驟 3。

#### 實驗數據解讀

PhysCaP 在真實世界與模擬環境中進行評估，涵蓋三項真實桌面操作任務與一項 LIBERO 模擬任務：

- **Searching for Hidden Objects（搜尋隱藏物體）**：需要透過移動或掀開遮擋物來發現目標。
- **Detecting Empty Cans（檢測空罐）**：透過質量估計判斷哪個罐子為空。
- **Finding Ripe Avocados（挑選成熟酪梨）**：透過剛度估計判斷酪梨成熟度。
- **LIBERO 模擬空罐任務**：在可控模擬環境中驗證方法的可重複性與泛化性。

**評估指標**

論文強調的關鍵指標包括：

1. **Task Success Rate（任務成功率）**：是否正確完成指令。
2. **Average Number of Interactions（平均互動次數）**：完成任務所需的物理探索次數。
3. **Total Execution Time（總執行時間）**：從接收指令到完成任務的時間。
4. **Ablation Studies（消融研究）**：驗證物理屬性提取模組與雙代理設計的個別貢獻。

**結果的質性解讀**

根據摘要與內文描述，PhysCaP 相較於 **Passive Baselines（被動基線）**（純視覺的 Code-as-Policy 或 VLA）與 **Naive Interactive Baselines（簡單互動基線）** 呈現以下優勢：

- **被動基線的失敗模式**：當關鍵物理屬性被遮擋或無法從外觀推斷時（例如空罐與滿罐外觀相同、成熟與未熟酪梨顏色相近），僅依賴視覺輸入的策略無法區分，導致任務失敗。這凸顯了 **Active Perception（主動感知）** 的必要性。
- **簡單互動基線的失敗模式**：雖然透過互動可以取得物理資訊，但缺乏策略的互動往往對所有候選物體進行相同測量，造成 **Over-Explore（過度探索）**。例如對桌上每一個罐子都稱重，雖然最終能找出空罐，但互動次數與執行時間大幅增加。
- **PhysCaP 的優勢**：透過 Planner 的停止條件與 Prioritizer 的排序機制，PhysCaP 能夠在資訊足夠時提前終止探索，並優先測試最有可能的候選物體。結果顯示其在維持高成功率的同時，顯著降低互動次數與執行時間。

**消融研究的意義**

消融研究驗證了物理屬性提取模組的有效性，特別是：

- 質量估計模組對於空罐檢測至關重要；若移除或替換為隨機猜測，成功率會顯著下降。
- 剛度估計模組對於酪梨成熟度判斷不可或缺；純視覺特徵在此任務上表現不佳。
- Planner 與 Prioritizer 的組合能有效減少冗餘互動；單獨使用 Planner 而無 Prioritizer 仍可能因選擇不當候選物而增加互動次數。

由於提供的全文未包含具體數值表格，以上解讀基於摘要與方法論的邏輯推論。若需進行量化比較，建議參考原論文附錄中的實驗數據。

#### 與現有研究的比較

PhysCaP 的定位介於三條研究主軸之間：**Vision-Language-Action (VLA) policies（視覺-語言-動作策略）**、**Reinforcement Learning (RL)（強化學習）** 與 **Code-as-Policy（程式即策略）**。它試圖結合 VLA 的感知語言理解能力、RL 的主動探索精神，以及 Code-as-Policy 的模組化與可解釋性。

**相較於 VLA 模型**

VLA 模型（如 RT-1、RT-2、OpenVLA 等）透過大規模 **Imitation Learning（模仿學習）** 學習端到端的視覺–語言–動作映射，擅長執行複雜的 **Cloth Folding（摺疊衣物）** 或 **Object Rearrangement（物體重新排列）**。然而，它們本質上是反應式（reactive）的前饋策略，主要複製示範中的 **Task Completion Behaviors（任務完成行為）**，而非學習 **Exploratory Actions（探索性動作）**。當任務需要估計隱藏物理屬性時，VLA 缺乏顯式的資訊尋求機制。PhysCaP 透過物理資訊引導的探索層彌補了這一缺口。

**相較於強化學習**

RL 理論上可以發現探索行為，但面臨 **Sparse Rewards（稀疏獎勵）** 與 **Delayed Rewards（延遲獎勵）** 的問題：探索性動作本身不直接帶來任務獎勵，導致樣本效率低落。此外，RL 學到的策略通常是黑箱，難以解釋或修改。PhysCaP 則利用 LLM 與物理先驗進行結構化推理，無需針對每個新任務重新訓練，策略以可讀程式碼呈現，便於除錯與調整。

**相較於現有 Code-as-Policy 系統**

現有的 Code-as-Policy 系統（如 CaP、VoxPoser、CaP-Agent0 等）已將感知、規劃與控制模組化，但大多聚焦於語義與程序推理，缺乏主動獲取物理資訊的能力。PhysCaP 的創新在於：

- 增加物理屬性提取模組，使程式碼能夠呼叫 `get_mass()`、`measure_stiffness()` 等函式。
- 引入 Planner 與 Prioritizer，將「探索決策」與「探索對象選擇」分離，提升效率。
- 透過 **Prior Knowledge（先驗知識）**（例如「未開封的罐子不太可能是空的」）縮小探索空間。

**主要限制**

儘管 PhysCaP 在方法論上具有吸引力，仍存在若干限制：

- **物理屬性範圍有限**：目前僅處理質量與剛度，對於摩擦力、重心、可變形性、聲學特性等更廣泛的物理屬性尚未涵蓋。
- **依賴本體感覺的精度**：質量與剛度估計對關節扭矩解析度、摩擦力建模與夾持姿態敏感，低精度機器人可能產生較大誤差。
- **啟發式分數非最優**：Prioritizer 使用的 **Heuristic Priority Score（啟發式優先分數）** 雖然實用，但未必是資訊增益的全局最優解；在複雜多物體場景中可能次優。
- **任務範圍集中於桌面操作**：尚未驗證於更動態、非結構化的環境（如戶外、工廠流水線）。
- **LLM/VLM 的幻覺風險**：Planner 與 Prioritizer 都依賴大型模型的推理，可能因語義誤解或常識錯誤而做出錯誤探索決策。

#### 可重現性評估

可重現性是評估機器人研究的重要維度，尤其當方法涉及真實機器人硬體與多個基礎模型時。

**已公開資源**

- **Project Page（專案頁面）**：論文提供了 https://physcap.github.io，通常會包含影片展示、任務描述、補充材料與可能的程式碼連結。
- **模擬環境**：LIBERO 是公開的機器人操作基準，因此模擬空罐任務原則上可由其他研究者重現。

**未明確公開的資源**

根據提供的全文，論文並未明確說明是否公開：

- 原始程式碼（包括物理屬性提取模組、Planner/Prioritizer 的提示詞設計、控制原語實作）。
- 真實世界實驗的資料集或記錄（如感測器數據、任務執行軌跡）。
- 預訓練模型權重（雖然 PhysCaP 標榜 training-free，但仍可能依賴特定的 VLM/LLM API 與機器人驅動程式）。

**重現挑戰**

即使程式碼公開，重現 PhysCaP 仍面臨以下挑戰：

- **硬體依賴**：真實實驗使用 7-DoF AgileX PiPER 機械手臂，其他實驗室若使用不同機型，需重新校準動力學模型與本體感覺參數。
- **感測器噪聲**：質量與剛度估計對機器人關節扭矩與夾爪狀態敏感，不同硬體的噪聲特性可能影響結果。
- **基礎模型版本**：LLM 與 VLM 的輸出具有隨機性與版本依賴性，重現時需固定模型版本與隨機種子。
- **提示工程**：Planner 與 Prioritizer 的表現高度依賴提示詞設計，若未公開完整提示，難以完全複製決策行為。

**建議**

為提升可重現性，作者可考慮公開：
1. 核心程式碼與 Docker 環境。
2. 真實與模擬任務的詳細參數設定（夾持力、提升速度、測量次數等）。
3. 完整的 LLM/VLM 提示詞與解析邏輯。
4. 原始實驗數據與評估腳本，以便進行統計檢定。

#### 未來研究方向

PhysCaP 為物理資訊引導的 Code-as-Policy 開闢了方向，但未來仍有許多值得延伸的課題：

**1. 擴展物理屬性估計的範圍**

除了質量與剛度，未來可納入摩擦力、重心、慣性張量、聲學特性、熱傳導性等。例如，透過搖晃物體並分析聲音來判斷內容物；透過滑動來估計表面摩擦係數。這將使機器人能處理更廣泛的隱藏狀態估計問題。

**2. 學習式的 Prioritizer**

目前的 Prioritizer 使用啟發式分數，未來可引入機器學習或貝葉斯最佳實驗設計（Bayesian Optimal Experimental Design），讓系統從過往互動中學習如何最大化資訊增益，並自動適應新任務與新物體。

**3. 不確定性量化與安全探索**

PhysCaP 的 Planner 決定何時停止探索，但未來可加入更嚴謹的不確定性量化（如貝葉斯後驗熵、置信區間），並在探索過程中納入安全約束，避免對易碎物體或人類造成危險。

**4. 多模態感測器融合**

雖然 PhysCaP 強調僅用本體感覺，但融合低成本觸覺感測器、力矩感測器或麥克風，可顯著提升質量、剛度與其他物理屬性的估計精度，特別是在高噪聲環境中。

**5. 從模擬到真實的泛化（Sim-to-Real）**

未來可在更豐富的模擬環境中訓練或驗證探索策略，再透過領域隨機化（domain randomization）與適應技術遷移到真實機器人，降低對特定硬體的依賴。

**6. 長期記憶與終身學習**

目前的 PhysCaP 可能針對單一任務進行探索。未來可讓機器人累積跨任務的物理知識（例如「鋁罐通常輕、玻璃瓶通常重」），形成長期記憶，減少未來類似任務的探索次數。

**7. 與人類協作的資訊尋求**

當機器人無法透過物理互動取得足夠資訊時，可主動向人類提問（如「這個罐子可以搖嗎？」）。這將 PhysCaP 從純物理探索擴展到人機互動式的資訊尋求。

**8. 理論保證**

未來研究可探討 PhysCaP 的探索策略是否具備理論上的樣本複雜度界限或資訊增益下界，特別是在 Planner 與 Prioritizer 的決策過程中引入形式化分析。

總結而言，PhysCaP 透過將物理先驗與模組化程式策略結合，為機器人主動感知提供了一個可解釋且高效的框架。未來若能擴展物理屬性範圍、提升感測融合能力，並加強理論與開源基礎建設，將有潛力成為通用機器人操作系統的重要組件。

## 論文問答

**Q1：PhysCaP 主要想解決什麼樣的機器人操作問題？**  
A：PhysCaP 針對的是機器人在執行操作任務時，必須推論無法直接觀測的潛在物理屬性（例如質量、剛度或內部狀態）的挑戰。傳統的視覺-語言-動作策略大多依賴被動觀察，無法透過互動取得隱藏資訊，因此在面對空罐、成熟酪梨或被遮擋物體等任務時容易失敗。PhysCaP 透過引入物理資訊引導的探索層，讓 Code-as-Policy 智能體能主動與環境互動，以減少不確定性並做出更可靠的操作決策。

**Q2：為什麼現有的 VLA 策略與 Code-as-Policy 代理人在這類任務上表現不佳？**  
A：VLA 策略本質上是反應式的前饋模型，擅長模仿示範中的任務完成行為，但缺乏結構化的長程推理與主動資訊尋求能力。現有的 Code-as-Policy 系統雖然具備模組化推理與可解釋性，卻大多仍受限於被動感知，無法主動取得缺失的物理資訊。強化學習雖然理論上可以學習探索行為，但常因稀疏且延遲的獎勵而樣本效率低落，且產生的策略難以解釋或修改。

**Q3：主動感知在機器人操作中為何重要？**  
A：許多真實操作任務的關鍵資訊無法僅靠視覺取得，例如物體是否空心、內部是否有內容物，或表面硬度是否適合抓取。人類在面對這類不確定性時，會運用先驗知識主動進行具資訊量的互動，例如搖晃罐子或輕壓水果。PhysCaP 正是希望讓機器人也能進行這種顯式的資訊尋求，透過物理互動來更新信念，從而提升任務成功率與操作效率。

**Q4：PhysCaP 的核心架構包含哪些主要元件？**  
A：PhysCaP 在 Code-as-Policy 框架之上新增了一個物理資訊引導的探索層，並包含無需訓練的物理屬性提取模組，可從機器人本體感覺估計物體質量與剛度。此外，它採用雙代理設計：Planner 負責判斷何時需要探索、何時已收集足夠資訊並停止探索；Prioritizer 則負責過濾不合理的互動候選，並依據啟發式優先分數對剩餘動作進行排序。這些元件協同運作，使 PhysCaP 能在保持高成功率的同時減少不必要的互動。

**Q5：PhysCaP 的「無需訓練的物理屬性提取模組」有什麼創新之處？**  
A：這些模組能直接利用機器人自身的本體感覺回饋來估計物體質量與剛度，不需要額外的感測器（如觸覺感測器），也不需要針對新任務進行額外訓練。由於它們是基於物理先驗設計，因此具有可解釋性與良好的泛化潛力。這種設計大幅降低了部署成本，並讓 Code-as-Policy 智能體能將物理估計結果直接整合進高階規劃與決策流程中。

**Q6：為什麼 PhysCaP 要採用 Planner 與 Prioritizer 的雙代理設計？**  
A：主動探索本身存在一個基本權衡：互動不足可能導致資訊不夠而決策錯誤，互動過多則會浪費時間與執行成本。Planner 負責在這兩者之間做高階判斷，決定是否開始探索以及何時終止探索；Prioritizer 則進一步縮小探索空間，先排除與常識或物理先驗矛盾的互動，再依據視覺語言模型給出的啟發式優先分數對候選動作排序。這種分工讓 PhysCaP 能夠進行高效且具目標性的探索，避免被動基線的失敗與簡單互動基線的過度探索。

**Q7：PhysCaP 在哪些任務與環境中進行了評估？**  
A：論文在真實世界中使用 7-DoF AgileX PiPER 機器手臂進行了三項桌面操作任務：尋找隱藏方塊、檢測空罐，以及挑選成熟酪梨。此外，也在 LIBERO 模擬環境中評估了空罐檢測任務。這些任務涵蓋了遮擋、內部狀態與材質硬度等不同類型的隱藏物理資訊，能夠有效檢驗 PhysCaP 的主動感知能力。

**Q8：PhysCaP 的實驗結果與基線相比有何優勢？**  
A：實驗結果顯示，僅靠被動觀察的視覺-語言-動作策略與 Code-as-Policy 基線在物理屬性被隱藏時往往無法完成任務，而缺乏策略的簡單互動基線則會過度探索所有物體。相較之下，PhysCaP 在維持高任務成功率的同時，顯著減少了平均物理互動次數與總執行時間。這證明了其雙代理架構與物理資訊引導探索在效率與效能之間取得了良好平衡。

**Q9：消融研究驗證了哪些設計選擇？**  
A：消融研究主要驗證了物理屬性提取模組的有效性，顯示這些模組能夠可靠地估計物體質量與剛度，並對整體探索效率有實質貢獻。透過移除或替換這些模組，研究人員能夠量化它們在減少互動次數與提升決策準確度方面的作用。這些結果進一步支持了 PhysCaP 將物理先驗直接嵌入 Code-as-Policy 執行流程的設計方向。

**Q10：PhysCaP 在實際應用中可能適合哪些場景？**  
A：PhysCaP 特別適合視覺資訊不足、需要透過觸碰或移動來確認物體狀態的場景，例如倉儲分類中空箱與實箱的辨識、家庭環境中回收罐是否為空的檢查，以及超市或農業中水果成熟度的初步篩選。由於它不需要額外感測器，也能快速部署到不同的機器人平台上。這些特性使其在成本敏感且需要靈活適應的實際環境中具有高度應用潛力。

**Q11：若要将 PhysCaP 產品化，需要考慮哪些部署因素？**  
A：首先，雖然 PhysCaP 不需要額外訓練或專用感測器，但仍需穩定的低階控制器與安全的互動原語，以避免在探索過程中損壞物體或機器人。其次，大型語言模型與視覺語言模型的推理延遲與偶發錯誤會影響即時性與決策正確性，需要設計適當的錯誤處理與重試機制。最後，不同任務的物理先驗與啟發式分數可能需要根據應用場景進行調整，以確保系統在真實世界中的穩健表現。

**Q12：PhysCaP 對機器人學習領域可能帶來什麼影響？**  
A：PhysCaP 展示了如何將被動的視覺-語言-動作策略與主動的物理資訊探索結合，為具代理性的機器人學習框架提供了一個新的設計範式。它強調利用物理先驗與模組化程式策略來提升樣本效率與可解釋性，而非單純依賴大規模模仿學習。這種方向有望促進更多結合物理知識、主動感知與高階推理的機器人系統出現。

**Q13：PhysCaP 目前有哪些已知限制？**  
A：PhysCaP 目前主要針對質量與剛度這兩類物理屬性進行估計，對於更複雜的物理特性（如摩擦係數、重心或動態行為）的處理能力仍有限。此外，系統假設已具備適當的互動原語與可抓取物體，對於高度非結構化或極度擁擠的環境可能需要額外處理。大型語言模型與視覺語言模型在推理過程中也可能產生幻覺或錯誤排序，進而影響探索決策。

**Q14：在什麼情況下 PhysCaP 可能會失敗？**  
A：當多個候選物體在質量或剛度上非常接近時，物理屬性提取模組可能難以區分，導致 Prioritizer 做出錯誤排序。如果機器人本體感覺訊號受到雜訊干擾，或互動過程中發生滑動、碰撞等未預期情況，估計結果也會失準。此外，若 Planner 過早判斷資訊已足夠，或視覺語言模型對任務相關線索的優先分數判斷錯誤，都可能導致任務失敗。

**Q15：PhysCaP 未來可以朝哪些方向延伸與改進？**  
A：未來可以擴展物理屬性提取模組，使其能估計更多樣的物理量，例如摩擦、重心、彈性或聲音特徵。也可以結合線上學習或適應機制，讓智能體在互動過程中持續更新對物體與環境的模型。此外，將 PhysCaP 與更豐富的感測器（如觸覺、聽覺或多視角視覺）整合，並探索多物體同時互動與長期主動感知策略，將是極具潛力的研究方向。

## 實務應用指南

### 適用場景

1. **倉儲物流與品檢分類**：在揀貨或包裝站中，機器人可透過輕搖或稱重判斷容器是否為空、內容物是否正確，例如辨識空罐、確認盒子內是否有商品，減少單純依賴視覺造成的誤判。
2. **農產品與食品分選**：針對外觀難以區分的品項（如酪梨成熟度、水果硬度、麵包新鮮度），利用剛度估計模組輕壓判斷，協助自動分級與出貨。
3. **家庭服務與輔助機器人**：在整理桌面、收拾雜物或尋找被遮擋物品時，機器人能主動移開障礙物、推測物體質量與內容狀態，完成「把空罐丟掉」或「找出藏在後方的物品」等任務。
4. **回收與廢棄物分類**：透過質量與剛度估計區分塑膠瓶是否為空、紙盒與金屬罐的材質差異，提升分類準確率。
5. **製造業組裝前檢測**：在零件上線前快速確認重量、硬度是否符合規格，避免錯件或瑕疵品進入組裝流程。

### 實作前置條件

- **硬體**：至少需一台具備本體感覺回饋的機器手臂（如 AgileX PiPER）與平行夾爪，並配備 RGB-D 相機或一般相機用於視覺感知；無需額外力覺或觸覺感測器即可運行質量與剛度估計。
- **資料**：任務相關的先驗知識（如「未開封罐頭通常不空」、目標物質量範圍、剛度參考值）、物體姿態估計模型、機器人運動學與夾爪標定參數。
- **運算資源**：需可呼叫大型語言模型（LLM）與視覺語言模型（VLM）的 API 或本地部署環境，以及執行低階控制與狀態估計的邊緣運算單元。
- **技術能力**：團隊需熟悉機器人控制（ROS / 運動學 / 夾爪控制）、Python 程式開發、提示工程（prompt engineering）、基礎物理觀念，以及 Code-as-Policy 或 LLM-based agent 的系統設計經驗。

### 實作步驟建議

1. **建立基礎 Code-as-Policy 框架**：先讓 LLM 能根據自然語言指令生成可執行的機器人程式，並串接視覺感知、物體姿態估計與低階控制原語（如 `goto_pose()`、`close_gripper()`）。
2. **整合物理屬性提取模組**：實作質量估計（透過夾持後關節力矩推估）與剛度估計（透過輕壓物體後的位移與力回饋計算），並將其封裝為 `get_mass()`、`get_stiffness()` 等可呼叫函式。
3. **設計雙代理架構**：建構 Planner，負責判斷「資訊是否足夠」與「是否該繼續探索」；建構 Prioritizer，利用 VLM 與啟發式分數過濾不合理互動、排序高資訊量候選動作。
4. **建立控制原語與安全機制**：定義安全的探索動作（如輕握、輕壓、輕推），加入碰撞偵測、力量上限與緊急停止，避免過度施力損壞物體或機器人。
5. **在模擬環境驗證**：先在 LIBERO 等模擬環境中測試空罐辨識等任務，調整 Planner 停止條件與 Prioritizer 分數門檻，確認互動次數與成功率達標。
6. **部署到真實機器人並迭代**：從簡單桌面任務開始，逐步增加物體數量與遮擋難度，持續收集失敗案例並優化先驗規則與提示詞。

### 潛在風險與注意事項

- **過度探索導致效率低落**：若 Planner 停止條件過於保守，可能反覆測量所有物體。建議設定明確的資訊增益門檻與最大互動次數上限。
- **物理估計誤差**：質量與剛度估計會受夾取姿態、摩擦、機器人模型誤差影響。應定期重新標定，並在關鍵任務保留容錯範圍。
- **LLM / VLM 幻覺**：模型可能產生不合理的推論或優先分數。需透過 Prioritizer 的物理先驗過濾，並對生成程式進行語法與語義檢查。
- **安全風險**：探索性動作可能碰撞周圍物品或夾傷。務必加入力量限制、速度限制、工作空間邊界與人機協作安全機制。
- **泛化性限制**：在論文任務中表現良好，但面對全新材質、形狀或極端重量分布時，可能需要額外調整物理模組與先驗規則。

### 與其他技術的整合建議

- **與 VLA 策略搭配**：可將 PhysCaP 作為高階決策層，負責判斷何時需要探索；低階動作執行則可交由現成的視覺-語言-動作策略完成，結合兩者優勢。
- **結合 3D 視覺與 SLAM**：在尋找隱藏物體時，可先用三維重建或語義地圖縮小搜尋範圍，再由 PhysCaP 決定要移開哪些障礙物。
- **導入數位孿生（Digital Twin）**：在模擬環境中預先訓練 Planner 的停止策略與 Prioritizer 的排序規則，再轉移至真實機器人，降低實機試誤成本。
- **對接倉儲 / 製造執行系統（WMS / MES）**：將 PhysCaP 的判斷結果回傳至上位系統，用於庫存更新、異常通報或生產履歷記錄。
- **與多模態感測器融合**：雖然 PhysCaP 強調無需額外感測器，但在高風險場景可選擇性加入力覺或觸覺感測器，與本體感覺估計進行交叉驗證。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先從摘要與圖一開始，理解「被動觀察」與「主動探索」的差異，再觀看專案頁面的示範影片，建立直覺；技術細節可暫時略過，重點放在 PhysCaP 能解決什麼問題。
- **AI 工程師**：應聚焦於雙代理架構的實作細節，包括 Planner 的停止條件設計、Prioritizer 的啟發式分數、物理屬性提取模組的程式介面，以及如何將這些模組封裝成 LLM 可呼叫的函式。
- **研究人員**：可深入探討物理資訊引導探索的設計動機、與強化學習及被動 VLA 方法的比較，以及消融研究中質量與剛度模組的貢獻；未來可延伸至多物體交互、更複雜的物理屬性估計或線上適應機制。
- **產品經理**：重點關注適用場景、與現有自動化流程的整合方式、部署所需的硬體與人才成本，以及「減少互動次數同時維持成功率」所帶來的效益與投資報酬率。
