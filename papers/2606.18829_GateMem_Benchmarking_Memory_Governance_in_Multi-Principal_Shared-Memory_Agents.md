# GateMem：多主體共享記憶體代理之記憶體治理基準測試

## ⚡ TL;DR

現有記憶體基準測試多為單一使用者設計，無法評估多主體共享環境中的記憶體治理與安全風險。
本文提出 GateMem 基準測試，透過長篇多方互動與隱藏檢查點，聯合評估效用、存取控制與主動遺忘。
實驗顯示現行方法無法兼顧三者，長上下文提示治理較佳但成本高昂，檢索式方法仍會洩漏未授權或已刪資訊。

## 摘要翻譯

現有的大型語言模型代理（LLM agents）之記憶體基準測試（memory benchmarks）大多預設單一使用者設定（single-user settings），導致醫院、職場、校園與家庭等場景中的共享助理（shared assistants）相關研究仍顯不足。在這類部署中，多個主體（principals）會寫入共用記憶體池（memory pool），並依據不同的角色、範圍與關係

## 深度分析

#### 方法論解析

GateMem（多主體共享記憶體治理基準測試）將記憶體評估從傳統的 Single-user settings（單一使用者設定）轉移至 Multi-principal Shared Environment（多主體共享環境），並將其形式化為 Memory Governance（記憶體治理）問題。不同於以往僅追求 Recall（召回率）最大化的 Private Cache（私有快取）假設，本研究強調在 Common Pool（共用池）架構下，多個 Principals（主體）依據不同的 Roles, Scopes, and Relationships（角色、範圍與關係）進行寫入與查詢，因此 Memory Quality（記憶體品質）必須同時涵蓋資訊的正確提取與嚴格的存取控管。

在評估架構上，GateMem 採用三維聯合評量設計：
1. Utility（效用）：衡量代理對於合法的 Long-horizon Requests（長期請求）與 State Updates（狀態更新）的支援能力，確保在複雜互動中仍能提供有助益的回應。
2. Access Control（存取控制）：檢驗代理是否能依據 Contextual Authorization Boundaries（情境化授權邊界）拒絕未授權查詢。測試設計包含 Indirect Inference（間接推論）、Delegated Requests（委託請求）以及 Socially Engineered Recovery Attempts（社交工程恢復嘗試）等進階攻擊情境，以評估代理在面對非直接越權時的穩健性。
3. Active Forgetting（主動遺忘）：針對 Explicit Deletion Requests（明確刪除請求），評估代理在介面層級達成 Behavioral Non-recoverability（行為不可恢復性）的能力。此處刻意區別於 Certified Physical Erasure（認證實體抹除）或參數層級的 Machine Unlearning（機器遺忘），而是要求代理在後續互動中不得恢復、確認或間接重建已刪除資訊，屬於部署導向的 Episodic Forgetting（情節式遺忘）概念。

資料建構方面，GateMem 橫跨 Medical Domain（醫療領域）、Office Domain（職場領域）、Education Domain（教育領域）與 Household Domain（家庭領域），共設計 91 組 Long-form Multi-party Episodes（長篇多方互動片段），並透過 Incremental Memory Injection（增量式記憶體注入）模擬真實場景中記憶逐步累積的過程。評估流程包含 2,218 個 Hidden Checkpoints（隱藏檢查點），這些檢查點對受測模型不可見，用以避免模型針對評分規則過度擬合。模型在測試時僅能取得互動歷史、當前請求者身份與相關政策脈絡，但無法得知查詢標籤、評分規則或受保護目標，從而確保評估的客觀性。

此外，GateMem 引入 Structured Judging（結構化評判）機制與 Leak-target Annotations（洩漏目標標註）。前者提供系統化的評分準則，後者則明確標記不應外洩的敏感項目，並輔以 Leakage Audits（洩漏稽核）來量化未授權資訊揭露的嚴重程度。這種設計使得評估不僅是二元對錯判斷，而是能細緻衡量記憶體治理失敗的類型與幅度。

#### 實驗數據解讀

實驗涵蓋多樣化的 Baselines（基線方法）與 Backbone Models（骨幹模型），結果呈現一項核心發現：目前沒有任何方法能同時在 Utility（效用）、Access Control（存取控制）與 Active Forgetting（主動遺忘）三個維度上達到強健表現。這證實了 Memory Governance（記憶體治理）並非單純的技術優化問題，而是存在本質性的張力。

具體而言，Long-context Prompting（長上下文提示）往往在整體治理分數上表現最佳。將完整的互動歷史直接置於提示窗中，使 Backbone Model（骨幹模型）能夠隱式地推論 Principals（主體）間的關係與授權狀態，從而在 Access Control（存取控制）與 Active Forgetting（主動遺忘）任務上取得相對較高的準確率。然而，這種方法伴隨著極高的 Token Cost（Token 成本），在實際 Institutional Assistants（機構助理）部署中缺乏可擴展性，且當上下文長度超出模型處理上限時，其優勢將迅速衰退。

相對地，Retrieval-based Methods（檢索式方法）與 External-memory Methods（外部記憶體方法）雖然有效降低了推理成本，卻持續出現未授權資訊洩漏與刪除後恢復的失敗案例。這顯示現有的記憶檢索與壓縮機制在設計時並未內建治理意識：當記憶被切塊、索引或摘要後，與特定 Principal（主體）相關的授權標籤、刪除狀態或情境邊界容易在檢索過程中遺失或被忽略。換言之，這些方法在傳統 Recall（召回率）導向的 Memory Benchmarks（記憶體基準測試）中或許表現優異，但在 Multi-principal Shared Environment（多主體共享環境）中，高 Recall 反而成為 Security Vulnerability（安全漏洞）。

從領域別來看，Medical Domain（醫療領域）與 Office Domain（職場領域）由於涉及高度敏感的 Protected Memory（受保護記憶體）——如 Lab Results（檢驗結果）、HR Records（人力資源紀錄）與 Project Confidentiality（專案機密性）——其 Access Control（存取控制）失敗的後果最為嚴重。而 Household Domain（家庭領域）與 Education Domain（教育領域）雖然資訊敏感度較低，但由於角色關係動態變化頻繁（例如家庭成員權限調整或 Campus Workflows（校園工作流程）中的臨時授權），代理更容易在 Contextual Authorization Boundaries（情境化授權邊界）的動態更新上出錯。整體而言，實驗數據明確指出當前的 Persistent Assistants（常駐型助理）距離可靠的共享機構部署仍有顯著落差。

#### 與現有研究的比較

如 Table 1（表一）所示，現有的 Memory Benchmarks（記憶體基準測試）大多建立在 Single-user settings（單一使用者設定）或 Dyadic Chat（雙人對話）的假設上。例如 LoCoMo（LoCoMo）與 LongMemEval（LongMemEval）專注於 Long-term Recall（長期召回）與 Long-horizon Reasoning（長期推理），但缺乏 Shared Memory（共享記憶體）設計，亦未設置 Access Boundary（存取邊界）或 Deletion Probe（刪除探針）。PersonaMem（PersonaMem）與 PrefEval（PrefEval）則聚焦於 Single-user Profile（單一使用者輪廓）的 Personalization（個人化），同樣不涉治理議題。

在 Multi-party（多方）或 Collaboration（協作）場景中，EverMemBench（EverMemBench）與 RealMem（RealMem）雖然引入多群體互動，但其評估重心仍偏向專案導向的記憶使用，僅具備 Partial Access Boundary（部分存取邊界），且未測試刪除後的記憶恢復風險。MemoryArena（MemoryArena）與 AMA-Bench（AMA-Bench）則將記憶用於引導 Agent Actions（代理行動），而非治理共享資訊池。

較為接近的是 CIMemories（CIMemories）與 CI-Work（CI-Work），這兩項研究開始關注 Contextual Privacy（情境化隱私）與職場流程中的隱私權衡，具備 Partial Contextual Access Boundary（部分情境化存取邊界）。然而，它們並未將記憶體視為由多個 Principals（主體）共同寫入與查詢的 Common Pool（共用池），也未設計針對 Explicit Deletion Requests（明確刪除請求）的 Active Forgetting（主動遺忘）探針。

GateMem（多主體共享記憶體治理基準測試）的關鍵貢獻在於完成了一項典範轉移：從「記憶體作為 Private Cache（私有快取）」的 Recall（召回率）最大化，轉向「記憶體作為受治理資源」的三維聯合評估。這不僅填補了 Multi-principal Shared-Memory Agents（多主體共享記憶體代理）的評估空白，更將 Memory Quality（記憶體品質）的定義從「記得多少」擴展為「記得正確、拒絕非法、遺忘徹底」。

#### 可重現性評估

從方法論描述來看，GateMem 的 Benchmark Construction（基準測試建構）具備高度的結構化與透明性。研究團隊明確定義了 91 個 Long-form Multi-party Episodes（長篇多方互動片段）與 2,218 個 Hidden Checkpoints（隱藏檢查點）的規模，並詳細說明了 Incremental Memory Injection（增量式記憶體注入）的流程、模型可觀測與不可觀測的資訊邊界，以及 Structured Judging（結構化評判）與 Leak-target Annotations（洩漏目標標註）的設計邏輯。這些細節為第三方複製評估框架提供了清晰的藍圖。

然而，就當前提供的 Preprint（預印本）文本而言，作者尚未明確宣告原始碼、資料集或模型權重的公開釋出狀態。文中雖列出通訊作者電子郵件，暗示可透過學術聯繫取得相關資源，但缺乏開放取用的資料儲存庫連結或開源授權條款。在 Reproducibility（可重現性）的嚴格標準下，這意味著其他研究者目前僅能進行 Conceptual Replication（概念層級複製），而難以執行完全一致的 Numerical Reproduction（數值重現）。

若未來作者群能公開釋出完整的互動片段、檢查點標籤、評分規則與輔助稽核腳本，GateMem 將具備成為社群標準的潛力。反之，在資料未公開前，其可重現性仍屬「方法透明但資源受限」的階段。

#### 未來研究方向

基於 GateMem 所揭示的治理張力，未來研究可從以下五個方向深化：

第一，**低成本高治理的記憶體架構**。Long-context Prompting（長上下文提示）雖然表現較佳，但其 Token Cost（Token 成本）過高。未來需發展具備治理意識的 Sparse Attention（稀疏注意力）或階層式記憶架構，使模型在不載入全量歷史的前提下，仍能精確判斷 Contextual Authorization Boundaries（情境化授權邊界）與刪除狀態。

第二，**實體層與行為層遺忘的整合**。當前的 Active Forgetting（主動遺忘）僅要求 Behavioral Non-recoverability（行為不可恢復性），但未要求 Certified Physical Erasure（認證實體抹除）。未來研究可探索如何將外部記憶體的實體刪除機制（如向量資料庫的硬刪除與索引重建）與代理的行為約束結合，以符合更嚴格的資料保護法規（如 GDPR 的被遺忘權）。

第三，**對抗間接推論與社交工程攻擊**。GateMem 已揭露代理在 Indirect Inference（間接推論）與 Socially Engineered Recovery Attempts（社交工程恢復嘗試）下的脆弱性。未來可引入 Adversarial Training（對抗性訓練）或 Inference-time Monitoring（推理時監控），偵測並阻擋試圖繞過存取控制的對話模式。

第四，**動態角色與政策管理**。真實機構中的 Roles, Scopes, and Relationships（角色、範圍與關係）並非靜態。未來系統需支援即時的權限調整與政策更新，並確保 Incremental Memory Injection（增量式記憶體注入）過程中，新寫入的授權規則能正確覆蓋或修飾舊有記憶的存取標籤，避免時序上的權限混淆。

第五，**跨領域遷移與終身學習的相容性**。GateMem 橫跨四大領域，但未來需驗證在 Lifelong Learning（終身學習）情境下，持續的 State Updates（狀態更新）是否會逐漸侵蝕 Access Control（存取控制）與 Active Forgetting（主動遺忘）的效能。建立不隨時間遞減的記憶體治理機制，將是 Persistent Assistants（常駐型助理）邁向實用化的最後一哩路。

## 論文問答

**Q1：GateMem 旨在解決的核心問題是什麼？**

A：現有的記憶體基準測試大多假設單一使用者與私有記憶空間，未能反映真實世界中多主體共享機構助理的部署情境。在醫院、職場、校園與家庭等場域中，多位主體會依據不同角色、範圍與關係共同寫入並查詢同一個記憶體池，這使得記憶品質不再僅是召回問題，而是涉及治理的綜合挑戰。GateMem 正是為了填補這項研究缺口而設計，旨在評估多主體共享記憶體代理在真實機構環境中的治理表現。

**Q2：為何現有的記憶體基準測試與方法在多主體共享環境中會失效？**

A：傳統的記憶體基準測試將代理的記憶視為單一使用者的私有快取，其優化目標通常是最大化召回率，而這在共享環境中反而可能構成安全漏洞。例如，若助理成功召回敏感診斷紀錄，卻將其洩露給未經授權的家屬，或檢索已刪除的機密專案草稿給約聘人員，這種高召回率只代表系統治理失敗。現有方法缺乏對情境化授權邊界與明確刪除請求的測試，因此無法確保代理在多人共用時能同時維持效用、存取控制與主動遺忘。

**Q3：記憶體治理對於 LLM 代理的機構部署為何至關重要？**

A：在機構部署中，記憶體治理是防止敏感資訊外洩與確保法規遵循的核心機制，因為多位主體對共同記憶池的存取權限會隨角色與互動脈絡動態變化。若缺乏嚴謹的治理，代理可能在回答合法查詢時意外揭露機密給未授權請求者，或因過度保護隱私而拒絕回答授權使用者的正當問題。因此，記憶品質必須同時從「記住什麼」與「如何依情境邊界存取、保留與遺忘」兩個面向來衡量，這是共享機構助理能否可靠落地的關鍵。

**Q4：GateMem 的核心方法是什麼？它從哪三大維度進行評估？**

A：GateMem 是一個專為多主體共享記憶體代理設計的基準測試，其核心是聯合評估三大治理維度：對合法長期請求的效用（Utility）、跨情境授權邊界的存取控制（Access Control），以及回應明確刪除請求後的主動遺忘（Active Forgetting）。該基準涵蓋醫療、職場、教育與家庭四大機構領域，包含 91 個長篇多方互動片段與 2,218 個隱藏檢查點。透過結構化評判與洩漏目標標註，GateMem 能夠系統化地檢驗代理在複雜共享環境中的綜合治理能力。

**Q5：相較於先前的基準測試，GateMem 的關鍵創新設計為何？**

A：GateMem 的關鍵創新在於將評估焦點從單一使用者的召回率轉移到多主體共享環境的記憶體治理，並引入長篇多方互動片段、增量式記憶體注入、隱藏檢查點與洩漏目標標註等設計。不同於過往僅關注個人化偏好或長期推理的基準，GateMem 特別針對角色、範圍與關係設計了真實的失敗模式，包括間接推論、委託請求與社交工程式的恢復嘗試。這些設計使得評估能夠更貼近醫院、企業等機構中實際發生的資安與隱私風險。

**Q6：作者為何選擇在代理介面層級評估「主動遺忘」，而非要求對底層儲存進行認證式的實體抹除？**

A：作者選擇在代理介面層級評估主動遺忘，而非要求對底層儲存進行認證式的實體抹除，主要是因為共享記憶體代理需要一種面向部署的情境式遺忘概念，而非成本高昂的參數化機器遺忘。在實務上，當使用者要求刪除某項細節後，代理應該在後續互動中無法恢復、確認或間接重建該資訊，這種行為上的不可恢復性更符合實際產品需求。此設計選擇也讓評估能夠聚焦於代理的實際行為表現，而非受限於模型權重更新或重新訓練等技術瓶頸。

**Q7：GateMem 涵蓋哪些領域與情境，其測試片段又是如何建構的？**

A：GateMem 橫跨醫療、職場、教育與家庭四大領域，每個領域都建構了獨特的角色結構、授權模式與真實失敗模式。測試片段採用長篇多方互動形式，透過增量式記憶體注入逐步累積情境，並在過程中設置隱藏檢查點來評估代理在不同時間點的治理表現。這種設計能夠模擬真實機構環境中持續累積的互動歷史，並檢驗代理在面對複雜且動態變化的共享記憶時，是否能正確區分授權與未授權的存取請求。

**Q8：實驗中的主要發現為何？不同基線方法與骨幹模型的表現如何？**

A：實驗結果顯示，無論是長上下文提示、檢索式方法或外部記憶體方法，目前皆無法同時在效用、存取控制與主動遺忘三個維度上達到強勁表現。長上下文提示雖然往往能提供最佳的整體治理分數，但必須付出極高的 Token 成本；而檢索式與外部記憶體方法雖能降低運算成本，卻仍然會發生未經授權的資訊洩露與刪除後的記憶恢復失敗。這些結果一致表明，現有的記憶體代理設計距離可靠的共享機構部署仍有顯著落差。

**Q9：長上下文提示、檢索式方法與外部記憶體方法在治理與成本之間呈現出怎樣的權衡關係？**

A：長上下文提示透過將完整互動歷史置於提示窗中，通常能在效用與治理之間取得最佳平衡，但其代價是推理過程中消耗大量 Token，導致成本高昂。相較之下，檢索式方法與外部記憶體方法透過選擇性提取或外部資料庫來降低計算負擔，但在存取控制與主動遺忘方面表現較差。具體而言，這些方法仍會洩漏應受保護的敏感資訊給未授權請求者，或在收到刪除請求後讓使用者透過間接查詢恢復已遺忘的內容，顯示出成本與治理之間存在棘手的權衡難題。

**Q10：GateMem 的評估框架在哪些真實世界的機構場景中最直接適用？**

A：GateMem 的評估框架最直接適用於醫院臨床協調、企業機密專案管理、校園行政流程與家庭個人助理等需要多人共享同一智慧助理的場景。在這些環境中，不同角色如臨床醫師、病患管理員、住院醫師或專案成員與約聘人員，會依據各自權限與關係存取共同記憶池。該框架能夠檢驗助理是否在提供有用回應的同時，嚴格執行基於情境的授權邊界，並防止因角色混淆或權限誤判導致的機敏資料外洩。

**Q11：這項研究對於開發共享記憶體助理的工程師與產品設計者有何實務啟示？**

A：這項研究對產品開發者的重要啟示在於，設計共享記憶體助理時不能僅追求高召回率，而必須將治理機制視為與效用同等重要的核心功能。工程團隊需要建構能夠動態理解角色、範圍與關係的情境化存取控制系統，以因應機構環境中複雜且持續變化的授權需求。此外，產品必須提供可靠的主動遺忘介面，確保使用者在要求刪除特定資訊後，系統不會在後續對話中透過直接或間接推論再次揭露該內容，這對建立使用者信任與符合法規要求至關重要。

## 實務應用指南

### 適用場景

1. **醫療機構的多角色臨床協調**：病患管理員、臨床醫師與住院醫師共用共享記憶體庫，在維持跨團隊照護連續性的同時，確保檢驗結果與保險詳細資料僅對授權角色開放，並在患者要求下執行主動遺忘。
2. **企業內部的跨部門專案協作**：全職員工與約聘人員在同一記憶體池中協作，系統需區分專案機密性層級，防止未經授權的約聘人員取得已刪除機密專案草稿或人力資源紀錄。
3. **智慧校園的多主體服務平台**：學生、教師與行政人員透過常駐型助理查詢校園工作流程，系統必須依據角色、範圍與關係動態劃分情境化授權邊界，避免成績或個人資料在不同主體間過度流通。
4. **家庭共享助理的隱私治理**：家庭成員（如父母、子女、外傭）共用家用助理，助理需支援長期請求與狀態更新，但同時確保個人財務或醫療資訊不會因高召回率而洩漏給未經授權的成員，並能落實明確刪除請求。
5. **B2B SaaS 平台的多租戶客服代理**：服務不同企業客戶的共享助理必須在單一部署中隔離各租戶的記憶體池，確保 A 企業的合約細節不會在 B 企業用戶查詢時被間接推論或檢索出來。

### 實作前置條件

- **資料層面**：至少需準備多主體互動歷史資料、角色權限對照表、情境化授權政策文件，以及用於測試主動遺忘的明確刪除請求記錄。建議參考 GateMem 的長篇多方互動片段格式，設計符合目標領域的增量式記憶體注入腳本。
- **運算層面**：需可呼叫具備長上下文窗口的骨幹模型 API（如 GPT-4、Claude 3 系列）以執行長上下文提示基線；同時需部署向量資料庫（如 Milvus、Pinecone）與檢索基礎設施以測試檢索式方法與外部記憶體方法。評估階段需額外運算資源執行隱藏檢查點與結構化評判。
- **技術與知識層面**：團隊需具備提示工程、RAG 架構設計、存取控制政策建模能力，並熟悉資安隱私合規框架（如 HIPAA、GDPR 或個資法），以便正確定義洩漏目標標註與治理邊界。

### 實作步驟建議

1. **治理需求盤點與角色建模**：將傳統單一使用者設定的思維轉換為多主體共享環境，具體定義各主體的角色、範圍與關係，並繪製出共享記憶體庫中哪些區塊屬於受保護記憶體。
2. **設計增量式記憶體注入與三維評估劇本**：參考 GateMem 架構，為醫療、職場、教育或家庭領域撰寫長篇多方互動片段，並在關鍵時間點埋入隱藏檢查點，分別探測效用、存取控制與主動遺忘。
3. **選擇並實作記憶體架構**：若追求最高治理分數且可承受高 Token 成本，優先採用長上下文提示；若需服務大量主體與長期互動，則採用檢索式方法或外部記憶體方法，但必須額外加上存取控制層與邏輯刪除機制。
4. **建立結構化評判與洩漏稽核管線**：導入結構化評判流程，對代理輸出進行自動化評分；同時建立洩漏目標標註清單，定期執行輔助稽核以偵測間接推論洩漏。
5. **生產環境的持續監控與權衡調校**：部署後持續追蹤三維指標（效用、存取控制、主動遺忘）的權衡曲線，針對社會工程攻擊、委託請求等進階威脅進行紅隊演練，並依實際成本與風險容忍度調整架構。

### 潛在風險與注意事項

- **間接推論洩漏（Indirect Inference）**：攻擊者可能不直接詢問敏感資訊，而是透過多次看似無害的查詢拼湊出受保護記憶體的內容。建議在評估階段加入多輪對話式的隱藏檢查點，並限制單一主體在短時間內的上下文聚合範圍。
- **刪除後可恢復（Post-Deletion Recovery）**：外部記憶體方法常在向量資料庫、日誌或備份中殘留已刪除資訊，導致主動遺忘失敗。實作時應確保明確刪除請求能觸發記憶體池、檢索索引與生成層面的同步清除，而非僅做表面屏蔽。
- **過度保守拒答（Over-Restriction）**：過度強化情境化授權邊界可能使代理對合法主體的長期請求拒絕回應，造成效用下降。建議採用漸進式政策調校，並以結構化評判量化「正確拒絕」與「錯誤拒絕」的比例。
- **Token 成本膨脹**：長上下文提示雖在論文中展現較佳的記憶體治理表現，但在生產環境中面對大量主體與長篇互動歷史時，成本與延遲將急遽上升。應預先設定成本上限，並設計分層記憶（近期上下文 vs. 摘要化長期外部記憶）的混合架構。
- **社會工程與委託攻擊**：惡意主體可能偽裝身份或利用「幫同事查詢」等委託請求繞過存取控制。系統必須嚴格驗證當前請求者身份，並將請求者身份與政策上下文一併注入提示，而非僅依賴對話內容判斷。

### 與其他技術的整合建議

- **與企業身份與存取管理（IAM）整合**：將現有 RBAC/ABAC 系統的角色定義同步至代理的情境化授權邊界，使大型語言模型代理能繼承組織現有的權限拓撲，避免重複建構身份邏輯。
- **與向量資料庫及快取層整合**：採用支援中繼資料過濾的向量資料庫（如 Weaviate、Milvus）作為外部記憶體庫，在檢索階段即依主體角色預先過濾，降低生成階段的洩漏風險；同時確保快取層具備邏輯刪除與 TTL（存活時間）機制。
- **與隱私增強技術（PETs）整合**：對於高度敏感的醫療或人力資源紀錄，可在寫入共享記憶體池前導入差分隱私或安全多方運算，進一步強化靜態資料的保護強度。
- **與可觀測性與資安資訊整合**：將 GateMem 的隱藏檢查點與洩漏目標標註轉化為生產環境的持續監控規則，對接 SIEM（安全資訊與事件管理）或 LLM 防火牆（如 Lakera、HiddenLayer），實現即時的未授權存取告警。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦圖一與第一章，理解為何傳統記憶體基準測試追求的「高召回率」在多主體共享環境中反而會成為安全漏洞。掌握「效用、存取控制、主動遺忘」三個評估維度後，再對照家庭或校園的日常情境，就能建立對記憶體治理的直覺。
- **AI 工程師**：建議重點閱讀實驗章節與基線方法比較，深入評估長上下文提示與檢索式方法在自身系統中的 Token 成本與洩漏風險。可參考論文中的結構化評判設計，在內部建構自動化評測管線，並針對外部記憶體方法補強邏輯刪除與中繼資料過濾機制。
- **研究人員**：請深入分析效用、存取控制與主動遺忘三維之間的根本張力。論文顯示目前尚無方法能同時達成三項目標，這正是新型記憶架構（如神經符號結合、可控遺忘機制、或動態政策推理）的切入點，可從根本機制設計層面探索突破瓶頸的可能。
- **產品經理**：請聚焦醫療、職場、教育、家庭四個領域的具體劇本與失敗模式（如間接推論、委託請求、社會工程）。將 GateMem 的三維評估架構轉化為產品需求文件（PRD）中的隱私治理驗收標準與合規檢查清單，並以論文數據作為與資安或法務團隊溝通的依據。
