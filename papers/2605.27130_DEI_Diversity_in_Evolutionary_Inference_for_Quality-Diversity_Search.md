## 摘要翻譯

我們提出 DEI（演化推論多樣性；Diversity in Evolutionary Inference），一個分散式品質多樣性（Quality-Diversity, QD）搜尋框架，將異質（heterogeneous）大型語言模型（LLM）指派為各對等節點（peer node）的突變運算子（mutation operator），節點間並透過非阻塞集體操作（non-blocking collective operation）進行通訊。不同於同質平行搜尋（homogeneous parallel search）將單一模型的歸納偏置（inductive bias）複製到所有工作節點，DEI 將每個 LLM 的獨特創意先驗（creative prior）視為行為新穎性（behavioral novelty）的互補來源。我們以 DEI 擴展 Digital Red Queen（數位紅皇后）框架，使節點於每輪結束時分享局部最佳解（local optimal solution），作為下一輪族群（population）的種子。這產生了跨模型對抗壓力（cross-model adversarial pressure），帶來超越模型內自我對弈（intra-model self-play）的穩健性（robustness）。我們於 Core War（核心戰爭）領域進行評估，該領域為競技程式設計基準（competitive programming benchmark），其中 Redcode 戰士程式（warrior program）於模擬機器（simulated machine）內對戰。一個四節點異質集成（heterogeneous ensemble）（GPT-5.4-mini、Claude Sonnet 4.6、GPT-5.2 與 Claude Haiku 4.5）在總 LLM 呼叫預算（LLM-call budget）相等的情況下，相較單節點基線，合併檔案庫 QD 分數（merged-archive QD-Score）高出 124%（45.90 對 20.46），儲存格（cell）覆蓋率（coverage）亦高出 28%（80.6% 對 63.0%）。該異質集成在所有四個模型家族（model family）上，於 QD 分數、覆蓋率與保留解泛化性（held-out solution generality）方面亦優於相同預算的同質集成（homogeneous ensemble）。這些結果提供了首個實證證據，顯示模型多樣性——不僅僅是平行化——才是分散式基於 LLM 的 QD 搜尋（distributed LLM-based QD search）中增益的關鍵驅動因素。

### 核心貢獻（3～5點）
- 提出 DEI 分散式 QD 搜尋框架，將異質 LLM 指派為各對等節點的突變運算子，以模型間獨特創意先驗的互補性驅動行為新穎性，突破單一模型歸納偏置的限制。
- 擴展 Digital Red Queen（數位紅皇后）框架，使節點於每輪結束時分享局部最佳解以播種下一輪族群，透過跨模型對抗壓力提升穩健性，超越傳統模型內自我對弈。
- 在 Core War（核心戰爭）競技程式設計基準上驗證，四節點異質集成於相同 LLM 呼叫預算下，合併檔案庫 QD 分數較單節點基線提升 124%，儲存格覆蓋率提升 28%。
- 提供首個實證證據，證明於分散式基於 LLM 的 QD 搜尋中，模型多樣性（而非僅是平行化）才是效能增益的關鍵驅動因素；異質集成在保留解泛化性上亦全面優於同質集成。

### 適合對象
對演化計算、品質多樣性（QD）演算法、大型語言模型於程式合成與自動化搜尋之應用，以及分散式異質計算有興趣的研究人員與工程師。特別適合希望透過多模型集成與對抗性演化機制，突破單一 LLM 之歸納偏置與創意盲點，以提升自動化程式生成、競技策略搜尋及最佳化解泛化性之進階讀者。

## 深度分析

#### 方法論解析

DEI（演化推論多樣性，Diversity in Evolutionary Inference）的核心貢獻在於將「平行認知（parallel cognition）」引入分散式品質多樣性（QD）搜尋框架（distributed Quality-Diversity search framework）。傳統的同質平行搜尋（homogeneous parallel search）僅將單一大型語言模型（LLM）的推論呼叫分散至多個工作者（worker），其本質仍是複製同一歸納偏置（inductive bias）；相對地，DEI 將異質的 LLM 指派為各對等節點（peer node）上的突變運算子（mutation operator），使每個模型憑藉其獨特的創意先驗（creative prior）與程式分佈（distribution over programs），偏好地探索行為空間（behavioral space）中的不同區域，從而產生互補的行為新穎性（behavioral novelty）。

系統架構上，DEI 擴展了 Digital Red Queen（數位紅皇后）框架（DRQ framework）。在每一輪（round）結束時，各節點將其局部最佳解（local optimal solution）——即該輪的冠軍或菁英解（elite）——透過非同步冠軍分享（asynchronous champion sharing）機制廣播給其他節點，作為下一輪族群（population）的初始種子。這創造了跨模型對抗壓力（cross-model adversarial pressure）：節點不僅與自身歷史版本進行模型內自我對弈（intra-model self-play），還必須對抗由完全不同生成先驗（generative prior）所產生的策略。由於各 LLM 節點的硬體延遲差異極大，DEI 採用非阻塞集體操作（non-blocking collective operation），讓各節點獨立推進，避免同步屏障拖慢整體吞吐量，實現異質硬體參與下的高吞吐量。

在核心戰爭（Core War）領域中，適應度（fitness）計算採用 MARS 模擬器，以戰士程式（warrior program）在對戰中的存活比例衡量；行為特徵（behavioral characteristic, BC）空間則由時間空間乘積（Time-Space Product, TSP）與記憶體覆蓋率（Memory Coverage, MC）構成，用於 MAP-Elites 檔案庫（archive）的儲存格（cell）索引。此設計確保檔案庫同時涵蓋高適應度與多樣化的控制流模式（control-flow pattern），而保留解泛化性（held-out solution generality）則透過與固定人類撰寫戰士對戰的勝率衡量，作為解品質的最終指標。

#### 實驗數據解讀

實驗在嚴格控制 LLM 呼叫預算（LLM-call budget）的前提下進行，這是隔離「多樣性」作為因果因子的關鍵設計。由 GPT-5.4-mini、Claude Sonnet 4.6、GPT-5.2 與 Claude Haiku 4.5 組成的四節點異質集成（heterogeneous ensemble），相較於單節點基線（single-node baseline），在合併檔案庫 QD 分數（merged-archive QD-Score）上提升達 124%（45.90 對 20.46），覆蓋率（coverage）提升 28%（80.6% 對 63.0% 的儲存格）。更具說服力的是，異質集成在同等預算下亦全面優於同質集成（homogeneous ensemble），無論是在 QD 分數、覆蓋率或保留解泛化性上，於全部四個模型家族（model family）皆呈現一致優勢。

數據的深層意義在於：合併檔案庫 QD 分數的顯著提升，證明不同模型的歸納偏置確實能填補單一模型生成分佈（generative distribution）中的盲點（blind spot），觸及單一模型難以生成的利基（niche）。保留解泛化性的增強則顯示，跨模型對抗壓力驅動的穩健性（robustness）超越了單純的模型內自我對弈，使演化出的戰士程式不僅在特定對手輪替中表現優異，更能泛化至未見過的人類策略。由於總計算預算固定，這些增益無法歸因於額外的運算量，從而提供首次實證證據：在分散式基於 LLM 的 QD 搜尋（distributed LLM-based QD search）中，模型多樣性本身即為增益的關鍵驅動力，而非僅是平行化的副產物。

#### 與現有研究的比較

與 FunSearch 相比，後者雖然執行平行 LLM 搜尋，但所有呼叫均指向同一模型，多樣性僅來自隨機取樣（stochastic sampling），而非根本不同的生成先驗，因此無法系統性地覆蓋行為空間的邊緣區域。與原始 DRQ 框架相比，其原始設計僅在單一節點運行單一模型，該模型生成分佈的盲點將永久成為檔案庫的缺口。DEI 則將「擴展」從純粹的計算規模提升轉化為認知規模提升——透過異質模型的平行認知，主動利用不同模型的歸納偏置來覆蓋更廣的適應度地形（fitness landscape）。

此外，近期在強化學習與多智能體推理中的多樣性感知目標與多 LLM 辯論研究，雖然也強調生成多樣性對探索的助益，但 DEI 首次將此直覺系統性地應用於分散式 QD 搜尋，並以嚴格的預算控制與異質／同質對照實驗，證明模型多樣性本身即為因果因子。

潛在限制方面，目前評估僅集中於核心戰爭這一競技程式設計基準（competitive programming benchmark），領域特性（如 Redcode 的低階組合語言語義）可能與高階程式合成或自然語言推理任務存在差異；此外，實驗依賴商業 API 模型，其延遲與成本結構可能隨供應商而異，且非同步通訊雖提升吞吐量，但可能導致部分節點使用稍舊的對手資訊，其對收斂性的理論影響尚未深入探討。

#### 可重現性評估

根據提供的內容，MARS 模擬器的超參數詳見附錄 A，具備一定透明度。然而，文中並未明確提及原始碼開放、資料集釋出或模型權重公開。實驗所使用的 GPT-5.4-mini、Claude Sonnet 4.6 等皆為商業閉源模型，研究者需透過 API 取得存取權，且模型版本可能隨供應商更新而變動，增加長期可重現性的挑戰。核心戰爭的 Redcode 戰士程式與 MARS 模擬器雖為公開領域的競技程式設計基準，但人類撰寫的保留測試集組成與提示詞工程細節若未完整釋出，將使外部團隊難以完全復現合併檔案庫 QD 分數與覆蓋率的絕對數值。非同步通訊協定的實作細節（如訊息佇列長度、容錯機制）亦未在提供的文本中詳述，這是社群復現時需額外克服的門檻。

#### 未來研究方向

未來研究可朝以下方向延伸：首先，動態異質集成機制，即在搜尋過程中依據各模型對檔案庫覆蓋率的邊際貢獻，自動調整節點組成或 LLM 呼叫預算分配，而非固定四節點配置。其次，將 DEI 框架擴展至其他程式合成、藥物分子設計或機器人策略學習等領域，驗證跨領域的泛化性。第三，結合微調（fine-tuning）或知識蒸餾，將異質模型探索到的多樣菁英解蒸餾為單一專家模型，以降低部署成本並保留多樣性優勢。第四，發展理論分析框架，量化歸納偏置差異與檔案庫覆蓋率上界之間的關係，並探討非同步冠軍分享在動力學上的收斂保證。最後，針對大規模節點設計通訊壓縮與版本控制機制，在維持非阻塞集體操作效率的同時，降低跨節點的頻寬與記憶體開銷。

## 論文問答

**Q1：DEI 旨在解決分散式 LLM 演化搜尋中的什麼根本問題？**
A：DEI 旨在解決單一大型語言模型的歸納偏置所造成的「盲點」問題，這些盲點會在品質多樣性檔案庫中形成永久性的行為空間缺口。現有的同質平行搜尋方法僅僅將同一個模型的生成先驗複製到所有工作者上，即使增加運算量也無法突破該模型固有的程式分佈限制。因此，DEI 主張必須透過異質模型的平行認知，才能系統性地覆蓋單一模型難以觸及的行為利基。

**Q2：為何 FunSearch 與原始 DRQ 等同質平行搜尋框架無法達到真正的行為多樣性？**
A：FunSearch 等框架雖然平行化了計算，但並未平行化認知，所有工作者都呼叫同一個模型，其多樣性僅來自於隨機取樣而非根本不同的生成先驗。原始的 Digital Red Queen 框架雖然引入了對抗演化壓力，但其單節點單模型的設計意味著，一旦某個模型在特定行為區域存在生成分佈的盲點，該區域將永遠無法被探索。結果是，這些方法產生的多樣性僅限於固定分佈內的變異，無法像異質集成那樣透過互補的歸納偏置來系統性地填補檔案庫中的空缺。

**Q3：為什麼模型多樣性被認為比單純的平行化更關鍵，足以推動品質多樣性搜尋的進展？**
A：論文在固定 LLM 呼叫預算的前提下進行實驗，證明異質集成不僅勝過單節點基線，也勝過同等預算的同質集成，這顯示模型多樣性才是性能提升的因果驅動力，而非額外的運算量。每個 LLM 因其訓練資料、架構與對齊程序的不同，會形成獨特的創意先驗，並偏好探索行為空間中的不同區域。當這些互補的觀點被整合時，搜尋過程便能發現單一模型永遠無法獨自抵達的穩健解，從而顯著提升覆蓋率與泛化性。

**Q4：DEI 的核心架構是什麼，它如何將異質 LLM 整合進 QD 搜尋流程？**
A：DEI 是一個分散式品質多樣性搜尋框架，它將不同的異質大型語言模型指派為各對等節點的突變運算子，並以此擴展 Digital Red Queen 的架構。在每個演化回合結束時，各節點透過非阻塞集體操作，以非同步的方式將局部最佳解分享給所有同伴，這些外部菁英解會成為下一回合族群的種子。這種設計將整個集成視為一個平行認知系統，使每個節點都能以其獨特的歸納偏置為共享的合併檔案庫做出貢獻。

**Q5：DEI 的非同步冠軍分享協定在技術上的關鍵創新是什麼，為何對異質集成而言不可或缺？**
A：關鍵創新在於採用完全非同步的八卦式通訊機制，消除了同步屏障，讓每個節點能夠獨立前進，不受其他節點延遲的影響。這對異質集成不可或缺，因為不同模型的回應延遲差異極大，例如本地模型可能需要十秒，而前沿模型不到兩秒，同步屏障會迫使整個集成被最慢的參與者拖累。透過非同步分享，DEI 在最大化硬體吞吐量與利用率的同時，確保了跨節點的策略交叉授粉能夠持續進行。

**Q6：作者為何選擇擴展 Digital Red Queen 框架，而非從零建構一個全新的分散式 QD 系統？**
A：作者選擇擴展 DRQ，是因為它已在 MAP-Elites 中建立了有效的對抗演化壓力機制，並在核心戰爭等競技領域提供了經過驗證的單節點基線。基於這個基線，DEI 能夠將異質模型多樣性的影響與其他演算法變因區隔開來，直接比較單節點、同質多節點與異質多節點的表現差異。此外，DRQ 以回合為單位的冠軍選拔機制，天然地對應到 DEI 的跨節點通訊協定，使局部最佳解能順利轉化為跨模型的對手。

**Q7：DEI 使用什麼基準領域進行評估，為何該領域適合測試分散式 QD 搜尋？**
A：DEI 在核心戰爭（Core War）上進行評估，這是一個競技程式設計基準，Redcode 戰士程式在記憶體陣列 Redcode 模擬器（MARS）中相互對戰。該領域極其適合，因為其可行的策略空間非常豐富，涵蓋了向前複製的 imp、投擲 DAT 指令的 dwarf、掃描敵軍的 scanner 以及防禦型 fortress 等多樣戰術，單一生成偏置難以輕易窮盡。此外，其對抗本質使得跨模型對抗壓力能直接轉化為解的穩健性指標，這與 DEI 強調的異質對手探索不謀而合。

**Q8：驗證 DEI 異質集成有效性的主要量化結果為何？**
A：在四節點異質集成（包含 GPT-5.4-mini、Claude Sonnet 4.6、GPT-5.2 與 Claude Haiku 4.5）的實驗中，於相同 LLM 呼叫預算下，其合併檔案庫 QD 分數達到 45.90，較單節點基線的 20.46 高出 124%，覆蓋率也從 63.0% 提升至 80.6%。更重要的是，該異質集成在 QD 分數、覆蓋率與保留解泛化性等指標上，全面勝過使用相同預算的同質集成，且此優勢橫跨所有四個模型家族。這些結果提供了首個經驗證據，證明在分散式基於 LLM 的 QD 搜尋中，模型多樣性本身即是性能提升的關鍵。

**Q9：作者如何透過實驗設計將「多樣性」孤立為性能提升的因果因素，而非僅歸因於運算量增加？**
A：作者在所有實驗條件中嚴格控制總 LLM 呼叫預算保持一致，無論是單節點、同質多節點或異質多節點配置，都使用完全相同的 API 呼叫總數。在這樣的預算匹配設計下，異質集成仍然顯著優於同質集成，這意味著性能差異只能來自於模型間質性的生成先驗差異，而非量性的平行運算擴展。這項消融實驗有效地將多樣性確立為因果驅動力，而非單純的規模效應。

**Q10：DEI 的異質集成方法在哪些實際應用場景中最能發揮價值？**
A：DEI 最適合用於複雜的創意搜尋任務，例如自動化程式合成、遊戲策略發現或科學假設生成，這些場景的解空間極為龐大，且單一 LLM 無法完整覆蓋所有可行行為。當使用者同時擁有具備不同專長的模型時——例如擅長程式碼補全的模型與針對指令遵循微調的模型——DEI 能夠整合其優勢，且不受最慢系統的延遲拖累。其非同步架構特別適合部署於硬體與網路環境異質的分散式系統中，確保資源利用最大化。

**Q11：將 DEI 部署為生產級分散式搜尋平台時，必須考量哪些系統層面的問題？**
A：生產部署必須處理異質 LLM 端點之間極大的延遲與吞吐量差異，DEI 透過非阻塞非同步集體操作來避免節點拖慢整體進度，但實際環境中仍需建立容錯機制以處理延遲或遺失的冠軍分享訊息。營運者還需設計高效的分散式檔案庫合併策略，以維持一致的全球 QD 分數與儲存格狀態，並確保跨節點的資料一致性。此外，成本優化亦不可忽視，因為不同模型的計價結構各異，雖然固定預算抽象有助於比較，但動態配置策略可能進一步提升經濟效益。

**Q12：DEI 可能如何影響未來大型語言模型與演化計算交叉領域的研究方向？**
A：DEI 推動了從「將 LLM 平行化視為純粹運算擴展」到「將其視為平行認知」的典範轉移，促使學界正視不同模型心智在共享適應度地形上的協作探索。這可能啟發更多關於多樣性感知的演化目標、多智能體辯論機制作為突變運算子，以及不同訓練語料庫與架構如何對應到特定行為利基的理論刻畫研究。透過在控制預算下證明異質集成優於同質集成，本文鼓勵未來研究將模型選擇視為演算法設計的核心環節，而非僅是基礎設施配置細節。

**Q13：目前 DEI 框架有哪些已承認或隱含的限制？**
A：雖然文中未詳盡列舉所有限制，但隱含地指出 DEI 的成效取決於所選模型之間的互補多樣性程度；若異質集成中的模型生成分佈高度重疊，則在覆蓋率與 QD 分數上的預期增益可能會縮減。此外，該框架假設行為特徵空間的定義足夠精確，能夠捕捉不同模型所探索的利基，若行為特徵維度選擇不當，可能會遮蔽跨模型交叉授粉的效益。目前評估亦僅限於核心戰爭單一領域，對於其他具有不同適應度地形的任務環境，其泛化能力仍有待進一步驗證。

**Q14：在什麼條件下，DEI 可能無法勝過同質集成，甚至表現不如單節點基線？**
A：若選用的異質模型因訓練資料或架構血緣相近而共享相似的歸納偏置，則其探索將趨於重複而非互補，導致多樣性紅利消失。在解空間極度狹窄或同質的任務中，若單一調校良好的模型已能涵蓋絕大多數可行行為，則非同步協調與跨節點通訊的開銷可能無法帶來相應的回報。此外，若節點間的延遲差異過於極端，使得快速節點持續領先慢速節點多個回合，則分享的冠軍解可能已經過時或失去相關性，進而降低作為對手種子的有效性。

**Q15：DEI 為分散式 LLM 演化搜尋的未來研究指出了哪些方向？**
A：未來研究可探索自適應模型選擇機制，根據即時的檔案庫覆蓋率統計動態調整異質集成的組成，而非全程使用固定模型集合。另一個有潛力的方向是發展學習式通訊協定，讓系統能預測哪些冠軍解最可能填補同伴的盲點，從而在降低通訊成本的同時最大化交叉授粉效益。最後，將 DEI 擴展至競技程式設計以外的領域——例如藥物發現、硬體設計或開放式創意任務——將有助於確立其廣泛適用性，並針對更廣泛的科學與工業需求精煉其系統架構。

## 實務應用指南

### 適用場景

1. **競技遊戲與自動對弈策略庫建構**：適用於核心戰爭、即時戰略或卡牌對戰等競技程式設計領域。透過異質 LLM 節點各自演化具不同歸納偏置的戰士程式，利用跨模型對抗壓力產生覆蓋多種行為利基的穩健策略，避免單一模型陷入模型內自我對弈的盲點。
2. **自動化程式碼修補與漏洞挖掘**：在資安場景中，以不同模型家族生成多樣化的攻擊載荷或修補方案，透過品質多樣性搜尋覆蓋不同行為特徵（如執行時間、記憶體覆蓋範圍），篩選出對未知威脅具保留解泛化性的高品質解。
3. **機器人決策與動作行為設計**：針對搜救、競技或服務機器人等高維行為空間任務，將各 LLM 的創意先驗轉化為不同運動風格或決策模式，透過非同步分散式搜尋快速填滿 MAP-Elites 檔案庫，確保實體部署時的環境適應力。
4. **創意設計與組合最佳化**：應用於生成式建築設計、分子結構生成或內容創作，利用模型多樣性突破單一生成分佈的限制，產出在效能與結構特徵上均具多樣性的菁英解典藏。

### 實作前置條件

- **領域模擬環境**：需具備可量化適應度與行為特徵（BC）的模擬器（如核心戰爭的 MARS），並定義靜態保留集以評估泛化性。
- **異質 LLM 端點**：至少 3–4 個不同模型家族的 API 或本地端點（如 GPT 與 Claude 系列），具備顯著不同的生成先驗與延遲特性。
- **分散式運算資源**：可獨立運行的對等節點叢集，支援非阻塞集體操作；節點間需具備低頻寬即可承載的非同步冠軍分享通訊能力。
- **技術能力**：團隊需熟悉 MAP-Elites 演算法、分散式系統設計、LLM 提示工程，以及具備將模擬器與 LLM 呼叫管線解耦的系統工程能力。

### 實作步驟建議

1. **定義行為空間與模擬環境**：選定目標領域，建立模擬器並設計 2–3 維行為特徵空間與適應度函數，同時準備固定保留集以評估保留解泛化性。
2. **建構異質 LLM 突變運算子池**：依據各模型的歸納偏置與延遲，挑選 3–5 個不同規模與訓練背景的 LLM，設計專屬提示模板以引導其生成特定風格的候選解。
3. **部署非同步分散式節點**：於各對等節點實作 MAP-Elites 檔案庫，整合非同步冠軍分享協定，確保慢速節點不阻塞整體進度，並實作錯誤重試與逾時機制。
4. **實作跨模型冠軍分享機制**：每輪結束後將局部最佳解廣播至其他節點，作為下一輪的對手與族群種子，形成跨模型對抗壓力，驅動單一模型難以觸及的行為新穎性。
5. **建立合併評估與預算控管**：定期合併各節點檔案庫，計算合併檔案庫 QD 分數、覆蓋率與儲存格佔有率；在系統層設定全域 LLM 呼叫預算，避免成本失控。
6. **產品化封裝**：將最終檔案庫轉為可部署的解方案庫，提供查詢 API 或嵌入 CI/CD 管線，實現持續演化與迭代。

### 潛在風險與注意事項

- **通訊延遲與檔案庫同步衝突**：非同步冠軍分享雖提升吞吐量，但過時的局部最佳解可能覆蓋較新的菁英解。建議導入版本向量或時間戳記機制，並在合併時以適應度為最終仲裁依據。
- **模型偏置重疊而非互補**：若選用的異質模型訓練資料高度重疊，多樣性增益將有限，淪為昂貴的同質平行搜尋。導入前應先執行小規模先導實驗，驗證各模型獨立覆蓋的利基分佈是否具備顯著差異。
- **LLM 呼叫成本失控**：異質節點若未統一預算控管，總成本易超過單一節點基線。必須實作全域 token 預算或呼叫次數上限，並優先將高成本模型配置於收斂後期的細部探索。
- **領域模擬器瓶頸**：QD 搜尋需大量適應度評估，若模擬器無法水平擴展，將成為整體瓶頸。建議將模擬器與 LLM 節點徹底解耦，獨立擴展評估叢集。
- **行為特徵維度災難**：BC 空間維度過高會導致儲存格稀疏、覆蓋率難以提升。建議從低維（2–3 維）開始，必要時採用 CVT-MAP-Elites 或自適應離散化技術。

### 與其他技術的整合建議

- **現有 MLOps / LLMOps 管線**：透過 Kubernetes 或 Ray 部署對等節點，將 DEI 框架封裝為標準工作負載，利用 MLflow 或 Weights & Biases 追蹤跨節點 QD 分數與覆蓋率變化。
- **檢索增強生成（RAG）**：將歷代菁英解存入向量資料庫，讓各節點的 LLM 突變運算子在突變前檢索相似高適應度解，提升語義感知突變品質並加速收斂。
- **多智能體辯論框架**：在冠軍分享階段引入跨模型辯論，讓不同 LLM 對彼此的局部最佳解進行批評與改良，再將改良後的解納入檔案庫，強化對抗壓力與解品質。
- **持續整合 / 持續部署（CI/CD）**：將 DEI 演化循環設為夜間批次任務，自動產生新的測試案例、遊戲策略或修補方案，通過閘道測試後合併至主分支，形成自動化品質多樣性搜尋流水線。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先掌握 MAP-Elites 與品質多樣性搜尋的基本概念，再將本文視為「讓不同 AI 模型分工合作、互相競爭以產生更多元解決方案」的實例。不必急於理解非阻塞集體操作的技術細節，重點把握「模型多樣性本身——而非單純增加運算量——才是分散式搜尋增益的關鍵」這一核心結論。
- **AI 工程師**：應聚焦於非同步冠軍分享的實作細節與異質節點延遲差異的處理策略。建議從系統架構與實驗對照設定著手，評估如何將現有的單節點 QD 管線擴展為異質分散式叢集，並特別注意全域 LLM 呼叫預算控管、錯誤重試與檔案庫合併衝突的解決方案。
- **研究人員**：本文的核心貢獻在於以嚴格的預算控制實驗，驗證認知多樣性是分散式基於 LLM 的 QD 搜尋增益的因果驅動因子。建議深入檢視異質集成與同質集成的對照設計，並思考如何將此框架延伸至其他行為空間、演化演算法變體，或探討模型家族選擇與歸納偏置互補性的理論關係。
- **產品經理**：請將重點放在商業價值與成本效益。本文證明在相同 LLM 呼叫預算下，異質集成可顯著提升合併檔案庫 QD 分數與覆蓋率。評估導入時應盤點現有模型供應商的多樣性，將 DEI 定位為「以現有預算槓桿更高品質與多樣性解方案庫」的策略，而非單純增加平行運算支出。
