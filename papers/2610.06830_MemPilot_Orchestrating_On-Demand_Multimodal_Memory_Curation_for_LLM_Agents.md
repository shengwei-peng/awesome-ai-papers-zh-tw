## ⚡ TL;DR

解決現有代理記憶以查詢無關方式建構，造成浪費且難以靈活調控效能、成本與延遲權衡的問題。
提出 MemPilot 框架，以強化學習最佳化多步驟策略，動態調配異質模型進行按需記憶策展。
在五個多模態代理記憶基準上展現優於基準的效能–成本–延遲權衡前緣。

## 摘要翻譯

記憶已成為 LLM（Large Language Model，大語言模型）代理生態系中的核心一環，支援跨互動的資訊保留與再利用。然而，大多數現有的代理記憶系統以與查詢無關（query-agnostic）的方式建構記憶，這可能產生不必要的預處理成本，並捨棄後來證實至關重要的細節。近期研究已開始將記憶處理轉向執行階段適應（runtime adaptation），但通常專注於特定操作或固定處理方案，對效能、成本與延遲的彈性控制仍鮮少被探索。為解決此挑戰，我們提出 MemPilot——一個靈活的框架，可在不同的效能–成本–延遲（performance–cost–latency）偏好下編排按需記憶策展（on-demand memory curation）。具體而言，我們透過強化學習（reinforcement learning）最佳化一個多步驟 LLM 策略（multi-step LLM policy），使其在「從與查詢無關的記憶中擷取」與「將原始多模態歷史的查詢特定策展（query-specific curation）委派給異質 LLM 與 VLM（Vision Language Model，視覺語言模型）」之間進行迭代選擇。該策略聯合控制證據量、策展指令、模型選擇與視覺存取，實現執行階段運算的細粒度配置。為了在競爭目標下最佳化此策略，我們調整逐目標優勢解耦（objective-wise advantage decoupling），透過在聚合前分別估計每個目標的優勢。此外，我們引入基於前綴的邊際效用估計（prefix-based marginal utility estimation），用於跨多步驟展開（multi-step rollouts）的細粒度信用分配。在五個多模態代理記憶基準上的實驗展示了跨最佳化偏好的有利效能–成本–延遲權衡，且偏好掃描（preference sweeps）產生了比現有權衡感知基準（trade-off-aware baselines）更廣泛的前緣。

### 核心貢獻（3～5點）
- 提出 MemPilot 框架，首次在多模態代理記憶系統中實現按需記憶策展，支援效能、成本與延遲的彈性權衡控制。
- 設計多步驟 LLM 策略，透過強化學習最佳化，使其能迭代選擇從與查詢無關的記憶中擷取，或將查詢特定策展委派給異質 LLM 與 VLM。
- 提出逐目標優勢解耦與基於前綴的邊際效用估計兩項技術，解決多目標強化學習中的優勢估計與細粒度信用分配問題。
- 在五個多模態代理記憶基準上驗證，MemPilot 在不同最佳化偏好下均展現有利的效能–成本–延遲權衡，且偏好掃描產生的權衡前緣優於現有權衡感知基準。

### 適合對象
從事 LLM 代理、記憶系統、多模態 AI、強化學習及系統效率最佳化研究的學者與工程師；特別關注如何在實際部署中平衡效能、成本與延遲的研究團隊與產品技術負責人。

## 深度分析

#### 方法論解析

MemPilot 的核心設計理念在於打破傳統代理記憶系統中「查詢前一次性建構記憶」(pre-query construction) 的剛性限制，提出一個可在執行階段 (runtime) 動態調配多模態記憶策展 (multimodal memory curation) 的彈性框架。其方法論可從三個層次進行解析：

**1. 雙軌記憶架構 (Dual-Track Memory Architecture)**

MemPilot 採用一個簡潔但關鍵的設計原則：同時保留兩種記憶來源。第一軌是「與查詢無關的記憶庫」(query-agnostic memory bank)，這部分與現成的代理記憶系統 (off-the-shelf agent memory systems) 相容，提供高效的存取路徑；第二軌則是「原始多模態互動歷史」(raw multimodal history)，保留未經加工的完整資訊，供查詢特定的執行階段策展使用。這種設計的優勢在於：既不丟棄現有記憶系統的投資，又能針對未來不可預測的查詢需求保留細節資訊，避免「預處理成本浪費」與「細節丟失」這兩個傳統方法的固有缺陷。

**2. 多步驟 LLM 策略 (Multi-Step LLM Policy)**

MemPilot 的核心決策機制是一個由強化學習 (Reinforcement Learning, RL) 最佳化的多步驟 LLM 策略。該策略在推論時 (inference time) 建構一個「查詢自適應的編排軌跡」(query-adaptive orchestration trajectory)，在每一步迭代中做出以下四類細粒度決策：

- **證據量控制 (Evidence Amount)**：決定從原始歷史中提取多少證據進行處理；
- **策展指令生成 (Curation Instructions)**：決定如何對證據進行策展與轉化；
- **模型選擇 (Model Selection)**：在異質 LLM 與 VLM (heterogeneous LLMs and VLMs) 之間選擇合適的處理後端 (processing backend)；
- **視覺存取 (Visual Access)**：決定是否需要存取視覺證據。

這四個維度的聯合控制使 MemPilot 能夠在執行階段運算 (runtime computation) 上實現細粒度配置 (fine-grained allocation)，而非受限於人工設計的操作 (hand-designed operations)、預算層級 (budget tiers) 或固定處理管線 (fixed processing pipeline)。

**3. 多目標強化學習最佳化 (Multi-Objective RL Optimization)**

由於 MemPilot 同時最佳化效能、成本與延遲三個相互競爭的目標 (competing objectives)，傳統的 RL 方法難以直接應用。為此，論文提出兩個關鍵技術：

- **逐目標優勢解耦 (Objective-Wise Advantage Decoupling)**：分別估計每個目標的優勢值 (advantage)，再進行加權聚合 (weighted aggregation)。這種解耦使得不同目標的學習信號不會互相干擾，能夠根據使用者偏好 (optimization preferences) 靈活調整權重。

- **基於前綴的邊際效用估計 (Prefix-Based Marginal Utility Estimation)**：在多步驟展開 (multi-step rollouts) 中，估計每個策展步驟的邊際貢獻，實現細粒度信用分配 (fine-grained credit assignment)。這對於長軌跡的策略學習至關重要，因為它能精確識別哪些步驟對最終效能有實質貢獻。

從方法論角度看，MemPilot 的設計具有高度的模組化特性：記憶策展操作、模型選擇、視覺存取等決策被統一在一個 RL 策略下，使得整個系統能夠根據查詢難度 (query difficulty) 與證據模態 (evidence modality) 自適應調整，這與現有方法通常僅針對單一運作形式進行執行階段適應 (runtime adaptation) 的做法形成鮮明對比。

#### 實驗數據解讀

根據摘要與引言所述，MemPilot 在五個多模態代理記憶基準 (multimodal agent-memory benchmarks) 上進行了全面評估。雖然完整實驗數據未在提供的文本中呈現，但可從論述中提取以下關鍵實驗發現：

**1. 效能–成本–延遲權衡前緣 (Performance–Cost–Latency Frontier)**

實驗的核心結論是 MemPilot 在不同的最佳化偏好下均能達到有利的權衡前緣 (trade-off frontier)。這意味著：

- 在偏好效能的設定下，MemPilot 能以合理的成本與延遲換取最高的任務效能；
- 在偏好成本的設定下，能在維持可接受效能的前提下大幅降低詞元用量 (token usage) 與金錢成本 (monetary cost)；
- 在偏好延遲的設定下，能快速回應同時保持競爭性的表現。

**2. 偏好掃描的廣度 (Breadth of Preference Sweeps)**

「偏好掃描」(preference sweeps) 的結果顯示 MemPilot 的權衡前緣比現有的權衡感知基準 (trade-off-aware baselines) 更為寬廣。這是一個重要的量化指標：更寬廣的前緣意味著 MemPilot 能夠覆蓋更多樣化的使用者需求場景，在同一基準上提供更多樣的效能–成本–延遲組合選擇。

**3. 行為分析 (Behavioral Analyses)**

論文還報告了行為層面的分析，揭示 MemPilot 如何根據偏好變化自適應地重新分配執行階段運算 (runtime computation)。具體而言：

- **模型選擇的轉移**：當偏好成本時，策略傾向選擇較小或較便宜的模型；當偏好效能時，則傾向選擇能力更強但成本更高的模型；
- **視覺存取的調整**：策略根據查詢需求與偏好決定是否啟用視覺證據存取，避免不必要的視覺處理成本；
- **運算配置的動態變化**：證據量與策展指令的生成隨偏好動態調整。

雖然具體的數字（如各基準上的精確準確率、成本節省比例、延遲降低幅度）在提供的文本中未完整呈現，但從論述語氣與結論的強調點可以推斷，MemPilot 在多個維度上均展現出統計上顯著且實質性的改進。引言中特別強調「favorable trade-offs」與「broader frontiers」，暗示相對於 GAM、BudgetMem、MemGen、AdaMEM、MemRL 等基準方法，MemPilot 在 Pareto 前緣的覆蓋範圍上具有明顯優勢。

值得注意的是，論文中將延遲 (latency) 視為與效能、成本同等重要的顯式最佳化目標，這在現有研究中較為少見——多數方法僅關注詞元用量或金錢成本，而忽略了使用者實際體驗中的回應時間。

#### 與現有研究的比較

MemPilot 的定位可從三個維度與現有研究進行比較：

**1. 與查詢無關記憶系統的比較**

傳統的代理記憶系統（如 MemoryBank、A-Mem、MemGPT 等）採用查詢前一次性建構記憶的策略，雖然實作簡單且存取效率高，但存在兩個根本性缺陷：

- **預處理成本浪費**：建構的記憶中可能包含大量未來查詢不需要的內容；
- **細節丟失**：預處理過程中的摘要與抽象化操作會丟失對某些查詢至關重要的細節。

MemPilot 透過保留原始歷史作為第二軌記憶來源，徹底解決了細節丟失問題，同時透過策略性地選擇是否進行執行階段策展來控制預處理成本。

**2. 與執行階段適應方法的比較**

現有的執行階段記憶適應方法各有側重：

- **GAM (Yan et al., 2025a)**：執行即時研究 (just-in-time research)，但其運作模式較為固定；
- **BudgetMem (Zhang et al., 2026b)**：學習查詢感知的執行階段提取，但僅在預定義的預算層級下運作；
- **MemGen (Zhang et al., 2025a) 與 AdaMEM (Zhang et al., 2026d)**：動態生成或更新記憶指引，但通常遵循預定義的處理模式；
- **MemRL (Zhang et al., 2026c)**：從互動回饋中學習記憶效用，但適應維度有限；
- **查詢時證據蒸餾與延遲記憶建構** (Yin and Tang, 2026; Yu et al., 2026a)：專注於特定形式的執行階段操作。

MemPilot 的核心差異化在於其**編排的彈性 (orchestration flexibility)**：它不局限於單一形式的執行階段適應，而是透過統一的多步驟策略同時控制記憶存取、查詢特定策展、異質模型委託與視覺證據使用。這種「編排」而非「單一操作」的設計哲學，使 MemPilot 能夠探索更寬廣的權衡空間 (trade-off space)。

**3. 與 LLM 路由方法的比較**

LLM 路由 (LLM routing) 研究旨在根據查詢特性將其分配到合適的模型。MemPilot 借鑒了路由思想（異質模型選擇），但將其整合進更廣泛的記憶策展決策中。傳統路由方法通常僅做單次模型分配決策，而 MemPilot 的模型選擇是多步驟軌跡中的一個維度，與證據量、策展指令、視覺存取等決策聯合最佳化。

**4. MemPilot 的侷限性**

儘管 MemPilot 展現出明顯優勢，仍存在以下潛在侷限性：

- **RL 訓練成本**：訓練一個多步驟 RL 策略需要大量的展開 (rollouts) 與回饋信號，訓練成本可能較高；
- **策略複雜度**：四維度的聯合決策空間使得策略學習更具挑戰性，可能需要較多的訓練資料；
- **異質模型的相容性**：依賴異質 LLM 與 VLM 的 API 可用性與穩定性，在實際部署中可能面臨模型更新或服務中斷的風險；
- **基準的代表性**：五個基準的選擇是否能充分代表真實世界中的多模態代理記憶場景，仍有待驗證。

#### 未來研究方向

MemPilot 提出了一個靈活的執行階段記憶編排框架，為多個潛在的後續研究方向奠定了基礎：

**1. 擴展策展操作空間**

目前的 MemPilot 主要控制四個維度（證據量、策展指令、模型選擇、視覺存取）。未來可探索更豐富的策展操作，例如：

- 動態決定是否進行多輪推理 (multi-turn reasoning)；
- 引入工具呼叫 (tool use) 作為策展手段；
- 支援跨模態推理鏈 (cross-modal reasoning chains) 的建構。

**2. 個人化偏好學習**

目前的偏好需要使用者手動設定權重。未來可探索從使用者互動歷史中自動學習個人化偏好，使系統能夠適應不同使用者的成本敏感度與延遲容忍度。

**3. 線上持續學習**

MemPilot 的策略目前是離線訓練的。未來可探索線上持續學習 (online continual learning) 機制，使策略能夠在使用過程中根據回饋不斷改進，適應新興的查詢模式與模型選項。

**4. 理論分析**

目前缺乏對 MemPilot 權衡前緣的理論分析。未來可從資訊理論 (information theory) 或決策理論 (decision theory) 的角度，分析在給定的查詢分佈與模型能力下，理論上可達到的最優權衡前緣，並與 MemPilot 的實驗結果進行比較。

**5. 安全與隱私考量**

執行階段策展涉及對原始歷史的存取，這可能帶來隱私風險。未來可探索如何在策展過程中加入隱私保護機制（如差分隱私 (differential privacy)、聯邦學習 (federated learning) 等），同時維持效能。

**6. 跨領域遷移**

MemPilot 在多模態代理記憶基準上進行了驗證，但其框架具有領域無關性。未來可探索將其應用於其他需要長期記憶的場景，如醫療對話代理、教育輔導系統、程式設計助手等。

**7. 與人類協作的編排**

目前的編排完全由 LLM 策略自主決定。未來可探索人機協作 (human-in-the-loop) 的編排模式，讓人類專家能夠介入關鍵決策，特別是在高風險場景中。

**8. 環境影響考量**

除了成本與延遲，未來可將碳排放 (carbon footprint) 或能源消耗納入最佳化目標，使 MemPilot 成為一個更全面的「綠色 AI」編排框架。

這些方向不僅能延伸 MemPilot 的技術貢獻，也能推動整個代理記憶系統領域向更彈性、更高效、更負責任的方向發展。

## 論文問答

**Q1：MemPilot 主要解決什麼核心問題？**
A：MemPilot 旨在解決 LLM 代理在長時程互動中，記憶建構與查詢需求之間的錯位問題。傳統的代理記憶系統多採「與查詢無關」（query-agnostic）的方式預先建構記憶，這種方式不僅會產生不必要的預處理成本，還可能丟失對未來查詢至關重要的細節。MemPilot 透過按需策展（on-demand curation）的方式，讓記憶處理能根據實際查詢需求動態調整，從而在效能、成本與延遲三者之間取得更靈活的權衡。

**Q2：為什麼現有的查詢無關記憶系統會失敗？**
A：現有系統在查詢尚未發生時就預先處理整個互動歷史，這種「先建構、後查詢」的模式無法可靠預測未來查詢的具體需求，導致兩大問題：一是浪費運算資源在永遠不會被查詢的內容上，二是可能過度壓縮或遺漏對某些查詢關鍵的細節。此外，這些系統通常依賴人工設計的操作流程、預定義的預算層級或啟發式方法，效率控制被硬編碼進固定模組中，缺乏對查詢特性與證據模態的細粒度適應能力。

**Q3：為什麼靈活的執行階段適應如此重要？**
A：執行階段適應（runtime adaptation）能讓代理根據實際查詢難度與證據模態動態決定處理策略，這對於兼顧效能與效率至關重要。現有方法往往只針對部分效率目標（如詞元用量或金錢成本）進行最佳化，卻很少將使用者實際感受的延遲視為明確的最佳化目標。同時，固定處理後端也限制了對異質模型品質、成本與延遲差異的利用空間，使得可達成的權衡空間（trade-off space）受到嚴重限制。

**Q4：MemPilot 的核心方法是什麼？**
A：MemPilot 的核心是一個透過強化學習最佳化的多步驟 LLM 策略，該策略在推論時會反覆決定兩件事：一是從與查詢無關的記憶庫中擷取資訊，二是將原始多模態歷史的策展任務委派給異質的 LLM 或 VLM。這個策略同時控制證據量、策展指令、模型選擇與視覺存取四個維度，從而對執行階段運算進行細粒度配置。透過這樣的設計，MemPilot 能夠在不依賴固定處理管線的前提下，根據不同的最佳化偏好靈活調整行為。

**Q5：MemPilot 在策略最佳化上有什麼關鍵創新？**
A：MemPilot 提出了兩項關鍵創新來處理多目標最佳化下的策略學習問題。第一是「逐目標優勢解耦」（objective-wise advantage decoupling），它分別估計每個目標（如效能、成本、延遲）的優勢函數，再進行加權聚合，避免不同目標的梯度互相干擾。第二是「基於前綴的邊際效用估計」（prefix-based marginal utility estimation），它能評估多步驟展開中每個策展步驟的邊際貢獻，實現更精細的信用分配（credit assignment），使強化學習訊號更穩定有效。

**Q6：MemPilot 採用了哪些關鍵設計選擇來實現細粒度控制？**
A：MemPilot 採用了「保留查詢無關記憶 + 保留原始歷史」的雙軌設計，既能相容於現成的代理記憶系統以實現高效存取，又保留了查詢特定策展所需的完整資訊。策略本身被設計為多步驟決策過程，每一步都可以獨立選擇擷取來源、委派模型、策展指令與視覺存取，這種模組化設計使得不同偏好下的行為調整可以自然浮現。此外，透過偏好掃描（preference sweeps）而非單一偏好點，使用者能在更寬廣的權衡前緣（trade-off frontier）上選擇符合自身需求的設定。

**Q7：MemPilot 在哪些基準上進行了實驗？**
A：MemPilot 在五個多模態代理記憶基準（multimodal agent-memory benchmarks）上進行了系統性實驗，這些基準涵蓋了文字與視覺等多模態互動場景，能全面評估代理在長時程互動中的記憶與推理能力。實驗設計特別強調效能–成本–延遲三者的聯合權衡，而非僅看單一效能指標，這與傳統只報告準確率的做法形成對比。透過在多個基準上的測試，MemPilot 展現了其在不同任務特性下的泛化能力與穩健性。

**Q8：MemPilot 的關鍵實驗結果為何？**
A：實驗結果顯示，MemPilot 在不同的最佳化偏好下都能達成有利的效能–成本–延遲權衡，證明了其偏好感知設計的有效性。特別值得注意的是，細粒度的偏好掃描揭示出比現有權衡感知基準更寬廣的權衡前緣，代表 MemPilot 能探索到先前方法無法觸及的最佳化區域。行為分析進一步顯示，隨著偏好改變，MemPilot 會自適應地重新分配執行階段運算，包括調整模型選擇、視覺存取與計算配置，這種動態適應能力是固定管線方法所欠缺的。

**Q9：消融研究揭示了哪些設計元件的貢獻？**
A：雖然論文中未完整列出所有消融細節，但從方法描述可推知，逐目標優勢解耦對於穩定處理競爭目標（competing objectives）至關重要，因為不同目標的優勢若直接混合會造成梯度衝突。基於前綴的邊際效用估計則對多步驟展開中的細粒度信用分配扮演關鍵角色，移除它可能導致策略難以分辨哪些策展步驟真正有貢獻。此外，異質模型委派機制與視覺存取的細粒度控制被證實是擴展權衡空間的重要元件，缺一不可。

**Q10：MemPilot 適合哪些實際應用場景？**
A：MemPilot 特別適合需要長時程、持續性互動的代理應用，例如個人助理、客服機器人、複雜任務規劃代理等，這些場景中代理需要在多次對話中累積並利用經驗。在資源受限的部署環境（如邊緣裝置或成本敏感的商業應用）中，MemPilot 的成本與延遲控制能力尤為重要，因為它允許營運者根據預算動態調整行為。對於需要處理多模態資訊的場景（如視覺問答、文件理解、影片分析代理），MemPilot 對視覺存取與 VLM 委派的細粒度控制也提供了實用價值。

**Q11：將 MemPilot 整合到產品中需要考慮哪些因素？**
A：產品整合時首先需考慮異質模型的成本結構，因為 MemPilot 會動態選擇不同 LLM 與 VLM，營運者必須建立清晰的計價與監控機制以避免意外開支。其次，延遲敏感的使用者體驗需要仔細調校偏好權重，因為過度追求低成本可能導致回應時間過長而影響滿意度。此外，由於 MemPilot 採用強化學習策略，部署前需要充分的離線評估與 A/B 測試，以確保策略在不同使用者族群與查詢類型上的行為符合預期。

**Q12：MemPilot 對學術與產業領域有何影響？**
A：在學術上，MemPilot 將記憶系統的研究從「靜態建構」推向「動態編排」，並將多目標強化學習中的優勢解耦與邊際效用估計技術引入代理記憶領域，為後續研究開闢了新方向。在產業上，它提供了一個可實際部署的框架，幫助企業在效能與營運成本之間取得平衡，特別適合需要大規模代理服務的雲端供應商與 SaaS 業者。更廣泛地說，MemPilot 推廣的「偏好感知」設計理念可能會影響其他代理子系統（如工具使用、規劃）的設計，推動整個領域朝向更靈活、可調控的方向發展。

**Q13：MemPilot 存在哪些已承認的限制？**
A：MemPilot 的效能高度依賴底層異質模型的能力與成本特性，若可選模型池品質不佳或成本結構不合理，策略的最佳化空間將受到限制。此外，強化學習策略的訓練需要大量高品質的互動資料與精細設計的獎勵函數，這對於資料稀缺的領域或新興任務可能構成挑戰。論文中也暗示，雖然偏好掃描能產生寬廣的權衡前緣，但如何幫助非專家使用者直觀地選擇合適偏好仍是待解決的問題。

**Q14：MemPilot 在哪些情況下可能會失敗？**
A：在查詢極度模糊或需要跨多個分散證據片段進行推理的場景下，MemPilot 的策略可能難以正確判斷該擷取哪些記憶或委派哪個模型，導致策展品質下降。當原始多模態歷史中存在大量冗餘或低品質內容時，策展指令的效果可能受限，因為異質模型本身也難以從雜訊中提取有效訊號。此外，若使用者的偏好設定極端（例如要求極低延遲同時維持高效能），策略可能無法在所有基準上都找到滿意解，需要在權衡上做出取捨。

**Q15：MemPilot 未來的研究方向有哪些？**
A：未來可探索的方向包括將 MemPilot 擴展到更多模態（如音訊、感測器資料）以及更多類型的代理任務（如多代理協作、複雜規劃），以驗證其泛化能力。另一個有前景的方向是引入更豐富的使用者偏好模型，例如允許使用者在會話層級動態調整偏好，而非僅在部署前設定。此外，將 MemPilot 與其他代理子系統（如工具選擇、反思機制）整合，構建完全偏好感知的端到端代理，也是值得探索的長期願景。

## 實務應用指南

### 適用場景

1. **長時程個人助理（Personal AI Companion）**：當使用者與 AI 助理進行數週甚至數月的對話、照片分享、行程記錄時，MemPilot 可在查詢時動態決定要從預先整理的記憶庫擷取，還是即時策展原始對話紀錄。例如使用者詢問「去年夏天我去過哪些有海景的咖啡廳？」，系統可依據查詢難度決定是否需要視覺存取、調用較強的 VLM 進行影像比對。

2. **企業內部知識型代理（Enterprise Knowledge Agent）**：在客服、技術支援、內部稽核等場景中，代理需從大量歷史工單、螢幕截圖、會議記錄中提取證據。MemPilot 可根據問題複雜度與即時成本預算，自動選擇使用輕量 LLM 快速回應，或調用大型 VLM 進行深度多模態分析。

3. **多模態內容創作助手（Multimodal Content Creation Assistant）**：影片剪輯師、設計師與文案撰寫者常需參考過去的素材庫、參考圖、風格筆記。MemPilot 可在創作過程中按需策展相關的視覺與文字歷史，並依使用者設定的「品質優先」或「速度優先」偏好調整運算配置。

4. **醫療與臨床決策支援（Clinical Decision Support Agent）**：醫師查詢病患過去的影像報告、檢驗數據、用藥紀錄時，系統需在準確度、延遲與成本間取得平衡。MemPilot 可讓醫院依不同科別需求設定偏好權重，例如急診偏好低延遲、影像科偏好高準確度。

5. **教育與研究助理（Educational & Research Assistant）**：學生或研究者在長時間學習過程中累積筆記、論文截圖、實驗記錄。MemPilot 可在準備報告或文獻回顧時，依據問題深度動態決定策展強度，避免在簡單查詢上浪費大型模型資源。

### 實作前置條件

**資料需求**
- 具備結構化的多模態互動歷史（文字對話、影像、影片幀、音訊轉錄等），並保留「原始歷史」與「預整理記憶庫」兩種形式。
- 需有標註或可推導的查詢–證據配對資料，用於強化學習的獎勵訊號估計。
- 建議準備至少數千筆的查詢軌跡，以支援多步驟策略的穩定訓練。

**運算資源**
- 訓練階段需能同時部署多個異質模型（小型 LLM、中型 LLM、大型 VLM）以供策略選擇；建議具備多 GPU 環境或雲端 API 預算。
- 推論階段需具備模型路由層（model router）與延遲監控基礎設施，以即時收集每個策展步驟的成本與延遲數據。
- 強化學習訓練需支援多目標 rollouts 與優勢估計的分散式運算框架。

**技能前提**
- 熟悉強化學習（特別是策略梯度方法如 PPO）與多目標最佳化概念。
- 具備 LLM/VLM API 整合、模型路由設計、token 與成本估算經驗。
- 了解記憶系統設計（RAG、向量資料庫、記憶策展管線）與多模態資料前處理。
- 對 RLHF / 偏好對齊（preference alignment）有基本認識者會更容易掌握目標解耦機制。

### 實作步驟建議

1. **盤點現有記憶系統並設計雙軌架構**：保留既有的查詢無關記憶庫（query-agnostic memory bank）作為快速存取層，同時建立原始多模態歷史的存取介面（raw history store）。這是 MemPilot 設計原則的核心——兩者並存而非取代。

2. **定義異質模型池與其成本/延遲檔案**：盤點可用的 LLM 與 VLM，為每個模型記錄品質基準、單次呼叫成本、平均延遲、token 上限等 metadata。這份檔案將作為策略選擇模型的依據。

3. **設計多步驟策略的動作空間（action space）**：依據論文，策略需聯合控制四個維度——證據量（evidence amount）、策展指令（curation instructions）、模型選擇（model selection）、視覺存取（visual access）。建議先以離散動作原型實作，再視需要擴展為混合動作空間。

4. **建立獎勵函式與偏好權重介面**：定義效能、成本、延遲三個目標的量化指標，並提供讓使用者或產品端設定偏好權重的介面（例如權重向量 w = (w_perf, w_cost, w_latency)）。

5. **實作目標解耦的優勢估計（objective-wise advantage decoupling）**：分別估計每個目標的優勢函式，再依偏好權重進行加總聚合。實作時需注意每個目標的基線（baseline）應獨立計算，避免目標間互相干擾。

6. **加入基於前綴的邊際效用估計（prefix-based marginal utility estimation）**：在多步驟 rollout 中，估計每個策展步驟對最終獎勵的邊際貢獻，以提供更細粒度的信用分配（fine-grained credit assignment）。實作上可採用狀態價值分解或步驟級 critic。

7. **執行強化學習訓練並進行偏好掃描（preference sweep）**：在不同偏好權重下訓練多組策略，或以單一策略在推論時動態調整權重。論文顯示偏好掃描可揭示更廣的權衡前緣（trade-off frontier）。

8. **部署與監控**：上線後持續監控每個查詢的策略軌跡、模型呼叫分佈、成本與延遲，並定期以新資料微調策略。建議建立 A/B 測試框架以驗證不同偏好設定下的使用者體驗。

9. **行為分析與迭代**：依據論文建議，分析策略在不同偏好下的模型選擇、視覺存取、運算配置變化，找出可優化的環節（例如某些查詢類型始終過度策展）。

### 潛在風險與注意事項

- **獎勵 hacking 風險**：多目標強化學習中，策略可能學會「走捷徑」——例如在效能目標上作弊（產生幻覺）以換取低成本。**緩解方式**：在獎勵函式中加入誠實性懲罰項，並以人類評估定期抽樣驗證。

- **延遲測量失真**：網路波動、API 佇列排程會使延遲估計產生高方差，導致策略學習到次優的模型選擇。**緩解方式**：使用多次取樣平均、加入延遲容忍區間，並在獎勵中對極端延遲做 clip 處理。

- **多模態資料隱私與合規**：原始歷史保留意味著敏感資料（個資、醫療影像、機密文件）會被長期存取。**緩解方式**：實作存取控制、加密儲存、依據資料敏感度分層（高敏感資料不進入原始歷史層）。

- **模型異質性導致品質不一致**：不同 LLM/VLM 的輸出格式、錯誤模式不同，策展結果可能難以統一評估。**緩解方式**：設計標準化的策展輸出 schema，並在策略中引入輸出驗證步驟。

- **訓練成本高昂**：多目標 RL 加上多模型 rollouts 會消耗大量 API 額度。**緩解方式**：先用較小的模型池與較短的 rollout 進行消融實驗，再逐步擴展；或採用模擬環境降低真實 API 呼叫次數。

- **策略過擬配特定偏好**：若訓練資料中某偏好權重樣本過多，策略可能無法泛化到未見過的偏好組合。**緩解方式**：在偏好空間中均勻取樣，並加入偏好條件化（preference conditioning）使策略能依輸入權重動態調整。

- **視覺存取的隱含成本**：VLM 呼叫通常比純文字 LLM 昂貴且延遲高，若策略過度使用視覺存取會侵蝕成本與延遲目標。**緩解方式**：在獎勵函式中明確懲罰不必要的視覺呼叫，並以查詢類型分類器預先過濾。

### 與其他技術的整合建議

- **與既有 RAG 系統整合**：MemPilot 的查詢無關記憶層可相容於現成的向量資料庫（如 Pinecone、Weaviate、Milvus）與 RAG 管線；只需在其上加入「原始歷史策展」分支即可，無需替換既有基礎設施。

- **與模型路由框架整合**：可將 MemPilot 的策略視為「高階路由器」，與 RouteLLM、FrugalGPT、HybridLLM 等模型路由系統互補——前者負責記憶策展層級的決策，後者負責單次推論的模型選擇。

- **與代理框架（Agent Frameworks）整合**：在 LangGraph、AutoGen、CrewAI 等代理框架中，可將 MemPilot 作為一個「記憶策展節點」插入代理的工作流，於每次需要外部資訊時呼叫。

- **與 RLHF / 偏好對齊工具鏈整合**：目標解耦的優勢估計可借鑑 TRL、OpenRLHF 等開源 RLHF 框架的多獎勵建模機制；前綴邊際效用估計則可與 step-level credit assignment 文獻（如 Decision Transformer、IRIS）結合。

- **與可觀測性平台整合**：將策略軌跡、模型呼叫、延遲、成本等指標匯出至 Langfuse、Phoenix、Helicone 等 LLM 可觀測性平台，便於分析策略行為與除錯。

- **與成本控制系統整合**：與雲端成本監控（如 CloudZero、Vantage）對接，設定每個偏好設定下的預算上限，並在策略中以硬性約束形式介入。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先跳過強化學習與多目標最佳化的數學細節，專注於理解 MemPilot 的「雙軌記憶」設計原則——為什麼同時保留預整理記憶與原始歷史是關鍵。閱讀時可先看摘要與第 1 節的問題動機，建立直覺後再回頭看相關章節。建議搭配閱讀 RAG 與代理記憶的入門教材，建立基礎概念後再進入本論文的細節。

**給 AI 工程師**：重點放在第 1 節的「四個控制維度」（證據量、策展指令、模型選擇、視覺存取）與實作步驟中的動作空間設計。目標解耦的優勢估計與前綴邊際效用估計是工程上可立即借鏡的兩個技巧——即使不採用完整 RL 框架，也能將其思想融入 prompt engineering 或啟發式路由中。建議直接動手實作一個最小可行版本（minimal viable version），用 2–3 個模型與簡單的二元偏好權重驗證概念。

**給研究者**：本論文的核心研究問題是「如何在多目標偏好下進行細粒度的執行階段運算配置」，其方法論貢獻（目標解耦優勢估計 + 前綴邊際效用估計）具有跨領域的應用潛力，可延伸到工具使用、推論時運算分配（test-time compute scaling）、模型合併等議題。建議仔細閱讀方法章節的數學推導，並思考如何將「偏好掃描產生權衡前緣」這套評估範式應用到其他多目標 RL 場景。

**給產品經理**：MemPilot 的核心價值主張是「讓使用者或產品端可控地權衡效能、成本與延遲」，這對 SaaS 產品的定價分層與使用者體驗設計有直接啟發。建議關注偏好掃描（preference sweep）的概念——它意味著同一個系統可以服務「免費版（成本優先）」、「專業版（效能優先）」、「企業版（自訂偏好）」等多種客群，而無需維護多套獨立系統。閱讀時可聚焦於第 1 節的問題陳述、應用場景段落，以及實驗結果中的權衡前緣圖，這些最能幫助評估產品化的可行性與商業價值。
