## ⚡ TL;DR

現有工具架構限制長期自主能力，狀態遺失與動作受限使測量偏離模型真正潛能。
Prime Agent 透過持久 REPL、遞迴子智能體與可修訂記憶，程式化管理上下文與測試時計算。

## 摘要翻譯

語言模型（Language Model）是序列處理器（Sequential Processor），但長期自主能力（Long-horizon Agency）需要超越模型權重（Model Weights）與作用中上下文（Active Context）的外部資訊（External Information）與計算（Computation）。Prime Agent 是一個用於長期評估（Long-horizon Evaluation）與編碼智能體工作流程（Coding-agent Workflows）的開源工具架構（Open-source Harness）。持久化 IPython REPL（Persistent IPython REPL）遵循遞迴語言模型抽象（Recursive Language Model Abstraction），以進行程式化上下文處理（Programmatic Context Processing）與測試時計算（Test-time Compute）；而 Continual Harness 則跨軌跡（Trajectories）保存歷史紀錄（Histories）、記憶（Memories）、技能（Skills）、提示（Prompts）與子智能體規格（Subagent Specifications）。遞迴子智能體（Recursive Subagents）透過智能體間直接通訊（Direct Agent-to-agent Communication）進行協調，而 Agents View 則供人類檢視與管理守護程序支援的工作階段（Daemon-backed Sessions）。Prime Agent 標準化執行（Execution）、復原（Recovery）、驗證（Verification）與資源核算（Resource Accounting），同時將策略建構（Strategy Construction）交由模型負責。這個低摩擦（Low-friction）且高表達性的介面膜（Expressive Membrane）可避免工具架構失敗（Harness Failures）被誤判為模型失敗（Model Failures），並使測量結果更趨近模型真正的最大潛在能力（True Maximal Underlying Capability）。Prime Agent 將 ARC-AGI-3 RHAE Best@1 從 30% 提升至 95.5%，並在長上下文程式編寫（Long-context Coding）、GPU 核心生成（GPU-kernel Generation）、模擬器建構（Emulator Construction）與自主 nanoGPT 競速（Autonomous nanoGPT Speedruns）等任務上，表現與原生及常用工具架構（Native and Popular Harnesses）相當或更優。在 Factorio 上，我們發現精煉（Refinement）能帶來持續的技術進展（Continuous Technology Progression），而專用子智能體（Dedicated Subagents）則可實現平行化工作（Parallelized Work）。程式碼可於 https://github.com/PrimeIntellect-ai/prime-agent 取得。

### 核心貢獻（3～5點）
- 提出開源的 Prime Agent 工具架構（Harness），標準化長期評估與編碼智能體工作流程中的執行、復原、驗證與資源核算，同時將策略建構交由語言模型自主負責。
- 整合持久化 IPython REPL 與遞迴語言模型（RLM）抽象，支援程式化上下文處理與測試時計算，並透過 Continual Harness 跨軌跡保存歷史紀錄、記憶、技能、提示與子智能體規格。
- 實現遞迴子智能體間的直接通訊與 Agents View 人機介面，使人類能檢視與管理守護程序支援的長期工作階段。
- 在多項基準上達成顯著進展：ARC-AGI-3 RHAE Best@1 從 30% 提升至 95.5%，並在長上下文程式編寫、GPU 核心生成、模擬器建構與自主 nanoGPT 競速等任務上達到或超越原生及常用工具架構。
- 在 Factorio 等大型開放環境中驗證：精煉機制可帶來持續技術進展，專用子智能體則能實現平行化工作。

### 適合對象
本論文適合對語言模型智能體、長期自主決策、自我改進系統、編碼智能體工作流程，以及測試時計算與遞迴語言模型架構有興趣的研究人員與工程師。特別推薦給需要評估或建構能長時間執行複雜任務（如程式生成、模擬器建構、遊戲自動化）的開源智能體工具架構之讀者。

## 深度分析

#### 方法論解析

Prime Agent 的核心方法論是將「語言模型（language model）」從單純的序列處理器（sequential processor）轉變為一個具備外部可定址狀態（addressable state）的類馮紐曼（von Neumann-like）計算系統。為此，作者提出了一個四層狀態資訊快取（state information cache）架構，並以「遞迴語言模型（Recursive Language Model, RLM）」與「Continual Harness」作為連接各層的機制。

**L0–L3 資訊層級（information hierarchy）**
- **L0（模型權重, model weights）**：儲存先驗知識（prior knowledge）與學習到的計算模式，透過微調（fine-tuning）更新，在單次任務中視為固定。
- **L1（作用中上下文, active context）**：模型每次呼叫時可直接見到的 token-visible 工作狀態。透過智能體式壓縮（agentic compaction）主動重寫，以在有限上下文長度內保留關鍵資訊。
- **L2（持久化 REPL 與遞迴子智能體, persistent REPL and recursive subagents）**：提供程式化計算與遞迴呼叫的能力。模型可在持久化 IPython REPL 中執行程式、保留中間值、定義工具，並透過 RLM 抽象進行可程式化的上下文處理（programmatic context processing）。子智能體（subagents）在此層運作，形成遞迴的計算結構。
- **L3（磁碟備份歷史、記憶與技能, disk-backed history, memories, and skills）**：長期保存的軌跡（trajectories）、記憶（memories）、技能（skills）、提示（prompts）與子智能體規格（subagent specifications）。透過精煉（refinement）機制版本化與篩選，使過去經驗能夠改善未來計算。

資訊在不同層級間流動：L2 的 Python 值與工具輸出可序列化進入 L1；壓縮（compaction）將 L1 的對話前綴替換為摘要，同時把原始事件保留到 L3；Continual Harness 則從 L3 選取條目組合成後續的補充提示（supplemental prompts）。這種設計讓模型能夠讀取、轉換並寫入當前生成指令之外的可定址狀態，突破單次呼叫的上下文限制。

**遞迴語言模型（RLM）與程式化計算**
RLM 抽象讓上下文（context）與遞迴呼叫（recursive invocation）變得可程式化。模型不僅輸出文字，還能輸出可執行的程式、工具呼叫與子智能體規格。持久化 IPython REPL 作為計算基質（computational substrate），支援測試時計算（test-time compute）：模型可以在推論階段執行任意 Python 程式、進行數值模擬、驗證假設，並將結果回寫到上下文中。這把計算管理（computation management）從資訊管理（information management）中分離出來，使模型能夠自主決定如何分配計算資源。

**Continual Harness：從軌跡到可重用狀態**
Continual Harness 負責將執行軌跡（trajectories）轉化為可重用的長期狀態。它保存的內容包括：
- 追加式事件歷史（append-only event history）
- 選定的核心快照（kernel snapshots）
- 根節點化的工作階段樹（rooted session tree）
- 上下文與壓縮紀錄
- 持久化訊息佇列（persistent message queues）
- 版本化的 Continual Harness 狀態

透過分支（branching）或分叉（forking），系統可以建立新的邏輯延續而不刪除先前事件序列；復原（recovery）則能在相同身份下重建工作階段。這使得長期任務即使面對中斷、壓縮或子智能體失敗，也能持續推進。

**遞迴子智能體與智能體間直接通訊**
Prime Agent 支援遞迴子智能體（recursive subagents）透過智能體間直接通訊（direct agent-to-agent communication）進行協調。這與傳統的固定執行圖（fixed graph）不同：子智能體可以動態建立通訊連結、交換資訊、分配子任務，甚至形成多智能體群體（multi-agent swarms）。這種動態協調（dynamic coordination）讓模型能根據任務需求即時調整策略，而非受限於預先定義的工作流程。

**Agents View 與人機協作**
Agents View 提供視覺化介面，讓人類能夠檢視、附加（attach to）、訊息傳遞與介入守護程序支援的工作階段（daemon-backed sessions）。這降低了長期執行中的可觀測性門檻，使人類可以在不追蹤每一輪對話的情況下，對特定子智能體進行干預。

**長期控制機制**
Prime Agent 標準化了延續（continuation）、終止（termination）與資源核算（resource accounting）。工具架構（harness）負責可靠執行（reliable execution）、復原（recovery）與驗證（verification），而策略建構（strategy construction）則完全交給模型。這種低摩擦高表達性介面（low-friction expressive interface）確保工具架構失敗（harness failures）不會被誤判為模型失敗（model failures），從而讓測量（measurement）更接近模型真正的最大潛在能力（true maximal underlying capability）。

#### 實驗數據解讀

論文在多個長期（long-horizon）與高複雜度基準上驗證 Prime Agent，並強調兩類指標：固定支出分數（score at fixed expenditure）與實際高原分數（score at practical plateau）。

**ARC-AGI-3 RHAE Best@1**
最引人注目的結果是在 ARC-AGI-3 的 RHAE Best@1 指標上，Prime Agent 將表現從 30% 提升至 95.5%。這顯示在具備外部程式化計算、持久化狀態與可重用技能後，固定模型在抽象推理任務上的可達策略集合（reachable strategy set）大幅擴展。值得注意的是，這並非來自模型權重（L0）的改變，而是透過 L2/L3 的測試時計算與資訊管理實現的。

**長上下文程式編寫（long-context coding）**
Prime Agent 在長上下文程式編寫上達到或超過 Pi、Claude Code 與 Codex 的表現，並優於 HermesAgent、OpenCode 與 Kimi-Code 等其他工具架構。這說明其上下文壓縮與持久化歷史機制，能夠有效處理大型程式碼庫與長時間對話。

**GPU 核心生成（GPU-kernel generation）與模擬器建構（emulator construction）**
在 GPU-kernel generation 與 emulator construction 這類需要大量試誤、驗證與迭代精煉的任務中，Prime Agent 透過持久化 REPL 與可驗證執行，達到與主流商業工具相當或更好的表現。這類任務特別依賴測試時計算與程式化工具呼叫，正是 Prime Agent 的設計強項。

**自主 nanoGPT 競速（autonomous nanoGPT speedruns）**
論文報告了一次長達 85.5 小時的 nanoGPT 執行，並產生 19 個經驗證的紀錄（validated records）。這證明了 Prime Agent 在極長時間跨度下的穩定性：能夠持續執行、復原、驗證並累積可重用技能，而不會因狀態遺失（dropped state）或過早終止（terminated prematurely）而中斷。

**Factorio 與 MazeBench**
- 在 Factorio 中，Prime Agent 實現了僅用四個字元（four-character）的控制，並透過精煉（refinement）達成持續技術進展（continuous technology progression）。專用子智能體（dedicated subagents）能夠平行化工作（parallelized work），顯示多智能體協調在複雜模擬環境中的效益。
- 在 MazeBench 上，Prime Agent 支援長期探索（long-horizon exploration），進一步驗證其在地圖式、部分可觀測環境中的記憶與導航能力。

**指標解讀**
作者強調應關注「隨時間變化的效能曲線（shape of performance over time）」，而非僅看單點分數。Prime Agent 的設計目標是讓模型在給定時間與成本預算內持續改進，最終趨近其潛在能力上限。因此，95.5% 的 ARC-AGI-3 成績與 85.5 小時的 nanoGPT 執行，共同說明了工具架構對測量真實能力的重要性。

#### 與現有研究的比較

**相對於傳統 LLM 工具架構**
多數現有工具架構將模型視為被動的序列處理器，透過固定工作流程呼叫工具。Prime Agent 的差異在於：
1. **表達性（expressivity）**：提供原語（primitives）讓模型自行建構程式、子智能體與回饋迴路（feedback loops），而非限制在預設動作集合。
2. **狀態持久化**：透過 L2/L3 將狀態從作用中上下文外移，支援長期記憶與技能累積。
3. **遞迴與群體協調**：支援動態多智能體群體，而非固定圖（fixed graph）式的子任務分解。

**相對於 RLM 與 Continual Learning 研究**
Prime Agent 整合了 RLM 的可程式化上下文處理與 Continual Harness 的軌跡保留，並進一步加入智能體間直接通訊與人機協作介面。這使其不僅是理論抽象，更是一個可運作的開源工具架構。

**相對於商業編碼智能體（Pi、Claude Code、Codex）**
論文宣稱 Prime Agent 在長上下文程式編寫、GPU 核心生成與模擬器建構上達到或超過這些商業系統。若結果可重現，則代表開源工具架構在特定長期任務上已具備競爭力。然而，商業系統可能在一般對話品質、使用者介面成熟度與廣泛適用性上仍具優勢。

**相對於其他開源工具架構（HermesAgent、OpenCode、Kimi-Code）**
Prime Agent 在資訊層級設計、持久化 REPL、遞迴子智能體與 Continual Harness 方面更為完整。其強調的「工具架構失敗不應成為模型失敗」的設計哲學，也與許多現有工具形成對比。

**主要限制**
1. **策略品質仍依賴模型**：Prime Agent 提供強大的原語，但最終策略建構仍由模型決定。若模型無法有效利用這些機制，效能提升有限。
2. **資源成本**：長期執行與多智能體群體可能帶來高昂的 token 成本與計算開銷，論文對此的詳細資源核算（resource accounting）著墨有限。
3. **安全性與可控性**：遞迴子智能體與智能體間直接通訊增加了系統的複雜度，可能帶來未預期的行為或安全風險，論文未深入討論。
4. **泛化性驗證**：雖然在多個基準上表現優異，但這些結果是否適用於更廣泛的開放式任務，仍需更多研究。

#### 可重現性評估

**程式碼開源**
論文明確指出 Prime Agent 是開源工具架構（open-source harness），程式碼可於 https://github.com/PrimeIntellect-ai/prime-agent 取得。這是重現研究的基礎。

**資料集與基準**
實驗使用的基準包括 ARC-AGI-3、長上下文程式編寫任務、GPU-kernel generation、emulator construction、nanoGPT speedrun、Factorio 與 MazeBench。這些多為公開可取得的基準或開源專案，有利於重現。

**模型權重**
論文未明確說明使用哪一個底層語言模型（foundation model）。若實驗依賴特定閉源模型（如 Claude 或 Codex），則部分結果的可重現性會受限。若使用開源模型，則需確認模型權重、版本與推論參數是否公開。

**重現挑戰**
1. **長期執行成本**：85.5 小時的 nanoGPT 執行與多智能體 Factorio 實驗需要大量計算資源，一般研究者可能難以完全複製。
2. **環境依賴**：Factorio、GPU kernel 編譯環境與特定硬體設定可能增加重現難度。
3. **隨機性與種子**：長期自主執行對隨機性敏感，論文需說明是否使用固定種子與重複次數。
4. **評估腳本**：雖然工具架構開源，但論文使用的評估腳本、提示模板與子智能體規格是否一併釋出，將直接影響可重現性。

整體而言，Prime Agent 在程式碼透明度上表現良好，但完整重現所有實驗仍需額外的資源、環境與方法細節。

#### 未來研究方向

**1. 自動化精煉與智能體式垃圾回收（agentic garbage collection）**
目前 L3 的精煉與 L2 的狀態保留仍部分依賴模型決策。未來可研究如何讓模型自動判斷哪些記憶、技能與 REPL 值值得保留，哪些應刪除，以降低長期執行中的狀態膨脹。

**2. 大規模多智能體群體的協調理論**
Prime Agent 已支援智能體間直接通訊，但未深入探討通訊拓撲、共識機制與衝突解決。未來可借鏡分散式系統與群體智能（swarm intelligence）研究，設計更穩健的動態協調演算法。

**3. 長期安全與對齊（alignment）**
隨著執行時間拉長與子智能體數量增加，如何確保系統行為符合人類意圖、避免目標偏移（goal drift）與未授權行動，將是重要的研究方向。可結合可解釋性、監控與人機協作機制。

**4. 從軌跡中訓練下一代模型**
Continual Harness 保留了豐富的軌跡資料，未來可探索如何將這些資料用於微調（fine-tuning）或強化學習，以改善 L0 模型權重，使模型天生更擅長使用 Prime Agent 的原語。

**5. 更細緻的資源核算與成本最佳化**
未來可發展自動化的測試時計算分配策略，根據任務難度與預期收益動態調整子智能體數量、REPL 執行次數與上下文長度，以在固定支出分數與實際高原分數之間取得最佳平衡。

**6. 擴展到非程式化領域**
目前 Prime Agent 主要針對編碼智能體與長期評估設計。未來可將其資訊層級與遞迴子智能體框架擴展到科學發現、機器人控制、多模態任務規劃等更廣泛的長期自主能力領域。

**7. 標準化長期評估協定**
Prime Agent 強調標準化工具架構（standardized harness）對公平評估的重要性。未來可與社群合作建立長期自主能力的標準評估協定，包括資源計算、中斷復原、驗證流程與可重現性要求。

## 論文問答

**Q1：Prime Agent 試圖解決什麼核心問題？為何這個問題在當前語言模型發展中特別重要？**

A：Prime Agent 針對的是語言模型作為序列處理器的根本限制：模型每次決策只能使用儲存在權重與作用中上下文內的資訊，無法像通用電腦般讀寫外部可定址狀態。這使得單純的語言模型難以執行需要長期規劃、外部資訊管理與持續計算的複雜任務，例如大型軟體開發或開放式遊戲控制。因此，Prime Agent 提出一個開源工具架構，補足模型與真實計算環境之間缺失的計算基質，使模型能夠在推論時間建構程式、子智能體與回饋迴路，從而將測量結果推向真正的最大潛在能力。

**Q2：現有工具架構或方法在長期自主任務中存在哪些根本缺陷？這些缺陷如何導致測量結果偏離模型的真實能力？**

A：現有許多工具架構往往過度限制模型的行動空間，例如無法持久化狀態、限制有用的工具呼叫、錯誤核算資源或過早終止執行，導致許多所謂的「模型失敗」實際上是工具架構失敗。此外，傳統方法通常將工作流硬編碼在架構中，缺乏讓模型於測試時自行建構策略的表達性，使得模型只能遵循預先設定的固定流程。這些限制讓測量結果偏向工具架構的能力上限，而非模型本身的真實潛能，因此難以準確評估長期自主能力。

**Q3：為何論文強調工具架構的「表達性」是關鍵屬性？這與傳統預設工作流程的設計哲學有何不同？**

A：表達性決定了工具架構能讓模型在推論時間組合出多少種策略，而非只能遵循預先設定的固定流程，這對於複雜且動態的長期任務至關重要。一個高表達性的工具架構提供原語，讓模型能夠根據任務需求動態建立程式、子智能體與回饋迴路，從而擴展其可達策略集合。相較於傳統將工作流硬編碼在架構中的設計，Prime Agent 選擇將策略建構留給模型，使固定模型能夠透過測試時計算與資訊管理來適應多樣化的長期挑戰。

**Q4：Prime Agent 的核心架構如何同時管理資訊與計算？L0 到 L3 的狀態層級各自扮演什麼角色？**

A：Prime Agent 將資訊管理與計算管理分離，透過持久化 IPython REPL、遞迴語言模型抽象、Continual Harness 與智能體間直接通訊，建立一個多層次的狀態資訊快取。L0 是模型權重，儲存學習到的先驗知識與計算；L1 是作用中上下文，作為模型當次呼叫可直接看見的 token 工作狀態；L2 是持久化 REPL 與遞迴子智能體，支援程式化計算與保留的執行狀態；L3 則是磁碟備份的歷史、記憶、技能與提示，讓軌跡證據能夠跨工作階段精煉與重用。這四個層級透過壓縮、精煉與檢索等機制相互流動，使模型能夠讀取、轉換並寫入超出當前生成指令的可定址狀態。

**Q5：遞迴語言模型、Continual Harness 與智能體間直接通訊這三項創新如何相互支撐？它們分別解決了什麼問題？**

A：遞迴語言模型抽象讓上下文與遞迴呼叫變得可程式化，解決了傳統模型難以動態管理上下文與呼叫子程序的問題。Continual Harness 讓提示、子智能體規格、技能與記憶能夠跨軌跡修訂，解決了狀態在長期執行中遺失或無法累積的問題。智能體間直接通訊則讓多智能體群體能夠動態協調與資訊路由，而非遵循固定圖，解決了分散式計算中協作僵化的問題。這三項創新相互支撐：RLM 提供可程式化的計算單元，Continual Harness 保留並精煉長期證據，直接通訊則將資訊與計算連結起來，使固定模型能夠利用測試時計算擴展可達策略集合。

**Q6：Prime Agent 在設計上為何選擇將策略建構留給模型，而僅標準化執行、復原與資源核算？這樣的權衡帶來什麼好處？**

A：Prime Agent 選擇將策略建構留給模型，是因為論文認為工具架構應該是模型觀察與行動於世界的「膜」，而非限制模型行為的框架。透過標準化執行、復原、驗證與資源核算，Prime Agent 確保模型失敗反映的是任務超出其能力，而不是因為工具架構丟失狀態、限制有用動作或過早終止。這種低摩擦高表達性介面膜的設計，讓模型能夠自由運用程式化工具、資訊管理與群體管理，從而將測量結果推向模型真正的最大潛在能力，而非工具架構的人為限制。

**Q7：論文在哪些基準測試上評估 Prime Agent？這些任務如何涵蓋不同類型的長期自主能力？**

A：論文評估涵蓋 ARC-AGI-3、長上下文程式編寫、GPU 核心生成、模擬器建構、自主 nanoGPT 競速、Factorio 控制以及長期 MazeBench 探索等多樣化任務。這些基準測試橫跨抽象推理、程式生成、系統級工程與開放式遊戲環境，能夠檢驗工具架構在不同時間尺度、回饋結構與複雜度下的表現。特別是 ARC-AGI-3 與 nanoGPT 競速屬於需要長期迭代、驗證與狀態累積的任務，對工具架構的可靠性、表達性與資源管理能力提出嚴苛要求。

**Q8：Prime Agent 在 ARC-AGI-3、nanoGPT 競速與 Factorio 等任務上取得了哪些具體成果？這些結果說明了什麼？**

A：Prime Agent 將 ARC-AGI-3 RHAE Best@1 從 30% 顯著提升至 95.5%，顯示高表達性工具架構能夠大幅放大固定模型在抽象推理任務上的表現。在 nanoGPT 競速中，系統能夠持續執行 85.5 小時並產生 19 項經驗證紀錄，證明其具備長期穩定執行與持續驗證的能力。在 Factorio 中，精煉機制支援持續技術進展，而專用子智能體則能平行化工作以加速整體進程，這說明資訊精煉與多智能體協調對於開放式長期任務同樣關鍵。

**Q9：與 Pi、Claude Code、Codex 及其他開源工具架構相比，Prime Agent 的優勢主要體現在哪些方面？有哪些證據支持？**

A：Prime Agent 在長上下文程式編寫、GPU 核心生成與模擬器建構等任務上達到或超越 Pi、Claude Code 與 Codex 等原生與熱門工具架構，並在部分基準上優於 HermesAgent、OpenCode 與 Kimi-Code 等其他工具架構。其優勢主要來自於持久化 REPL、Continual Harness 與智能體間直接通訊等設計，這些元件讓模型能夠在長期執行中保留狀態、累積可重用技能並協調平行子智能體。這些比較結果說明，單靠模型能力不足以解決長期任務，工具架構的設計同樣決定了最終測量到的效能，而 Prime Agent 的標準化與高表達性介面有效減少了工具架構本身成為瓶頸的情況。

**Q10：Prime Agent 最適合應用於哪些實務場景？在軟體工程、系統建構與科學計算中分別能發揮什麼作用？**

A：Prime Agent 適用於需要長期執行與持續狀態管理的場景，例如大型軟體專案的自動化開發、GPU 核心優化、模擬器與編譯器建構，以及科學計算流程的自動化。在軟體工程中，模型可以反覆編寫程式、執行測試、修復錯誤並累積可重用技能；在系統建構中，遞迴子智能體能夠平行處理不同模組的設計與驗證；在科學計算中，持久化 REPL 讓模型能夠迭代實驗並保留中間結果。透過子智能體平行化與 Agents View 人類監督介面，Prime Agent 也能夠在企業級開發環境中作為可協作、可介入的自主夥伴運作。

**Q11：若將 Prime Agent 產品化部署，需要在安全性、可解釋性、資源管理與人機協作方面考量哪些議題？**

A：產品化時需考慮守護程序支援工作階段的安全性，由於系統允許模型執行外部程式碼並產生子智能體，必須建立適當的沙箱與權限控管以避免意外行為或惡意程式執行。資源核算的準確性也至關重要，因為長期執行中的計算成本可能相當可觀，需要透明的計費與限額機制。Agents View 的設計讓人類能夠檢視、附加訊息並介入子智能體工作階段，這對於維持使用者信任、操作透明度與人機協作品質非常重要。此外，錯誤復原與狀態回溯機制必須穩健，以確保長期任務不會因為單一失敗而完全中斷。

**Q12：Prime Agent 對語言模型評估典範、遞迴語言模型研究與多智能體系統發展可能帶來哪些深遠影響？**

A：Prime Agent 推動了從「模型中心」到「架構中心」的評估典範轉移，強調工具架構應標準化執行與測量，同時將策略建構留給模型，使評估結果更能反映模型的真實潛能。它證明透過高表達性工具架構，固定模型的長期自主能力可以被顯著放大，這對未來的遞迴語言模型與多智能體系統研究具有啟發意義，特別是在如何設計可程式化上下文與動態協調機制方面。此外，其開源特性與對長期評估指標的強調，有助於社群建立更公平、更貼近真實潛能的模型比較基準，並促進自我改進系統的持續學習研究。

**Q13：論文承認 Prime Agent 存在哪些限制？這些限制主要來自底層模型、計算成本還是系統複雜度？**

A：Prime Agent 雖然顯著提升了多項基準表現，但它仍高度依賴底層語言模型的推理與程式生成能力，若模型本身無法理解任務或生成正確程式，工具架構也難以完全彌補。長期執行帶來的計算成本與資源消耗可能相當可觀，這限制了在資源受限環境中的廣泛應用。系統的複雜度也意味著部署與維護需要較高的工程投入，包括守護程序管理、狀態一致性維護與多智能體協調的除錯。因此，Prime Agent 的限制同時來自於底層模型能力、計算經濟性與系統工程複雜度三個層面。

**Q14：在實際運作中，Prime Agent 可能出現哪些失敗模式？錯誤的記憶累積、子智能體溝通失敗或外部環境變化會造成什麼後果？**

A：當子智能體間通訊產生誤解或資訊路由錯誤時，可能導致平行工作重複、方向偏離或協調失效，進而浪費計算資源並延遲任務完成。若模型在 L2 或 L3 中累積了錯誤的記憶或技能，這些錯誤狀態會在後續軌跡中被持續放大，因為 Continual Harness 會將這些證據重新注入未來的提示中。此外，雖然工具架構標準化了執行與復原，但面對需要真實世界常識、物理互動或快速變化外部環境的任務時，仍可能因模型先驗知識不足或環境動態超出預期而失敗。這些失敗模式凸顯了人類監督與可介入機制在長期自主系統中的重要性。

**Q15：基於 Prime Agent 的設計，未來研究可以朝哪些方向延伸？持續學習、更大規模群體協調與更精細評估指標各有哪些潛力？**

A：未來研究可進一步優化智能體間通訊協定，讓更大規模的多智能體群體能夠有效率地協調、分工與動態重組，以處理更複雜的分散式任務。另一方向是將保留的軌跡用於訓練下一代模型，使系統從自我改進走向真正的持續學習，讓 L0 模型權重也能夠從長期執行經驗中獲益。此外，開發更自動化的評估指標與更細緻的資源核算方法，將有助於更準確地測量長期自主系統的真實能力上限，並區分模型能力進步與工具架構進步所帶來的貢獻。這些方向共同指向一個更具表達性、更可持續學習且更易於公平評估的自主智能體生態系統。

## 實務應用指南

### 適用場景

**長期軟體工程任務**：Prime Agent 特別適合需要數小時甚至數天持續迭代的編碼專案，例如大型程式碼庫重構、跨檔案功能實作、GPU 核心生成、模擬器建構，以及長上下文程式編寫。透過持久化 IPython REPL 與遞迴子智能體，模型可以逐步累積程式狀態、執行測試並持續精煉解法。

**自主機器學習實驗**：適用於 nanoGPT 競速這類需要反覆試誤的 ML 工程任務。系統可保留每次實驗的歷史紀錄、記憶與技能，讓模型在長期執行中學習哪些訓練策略有效，並透過驗證機制確保記錄正確性。

**複雜遊戲與模擬環境控制**：以 Factorio 為例，Prime Agent 能透過精煉機制達成持續技術進展，並利用專用子智能體執行平行化工作。這類場景也適用於長期迷宮探索、供應鏈模擬，或其他需要多步決策的環境。

**結構化推理與競賽解題**：在 ARC-AGI-3 這類抽象推理任務中，Prime Agent 將 RHAE Best@1 從 30% 提升至 95.5%，顯示其適合需要大量測試時計算與程式化上下文處理的推理挑戰。

**多智能體協作工作流程**：當單一模型難以同時處理規劃、執行、驗證與監控時，可利用智能體間直接通訊建立專責子智能體，例如一個負責程式碼生成、一個負責測試驗證、一個負責資源核算，並透過 Agents View 讓人類監督整體進度。

### 實作前置條件

**資料準備**：需要清晰的任務規格、可執行的評估指標、範例輸入輸出，以及用於 Continual Harness 的初始提示、技能範本與子智能體規格。若為程式任務，需準備可執行的測試套件與版本控制儲存庫。

**計算資源**：需要能持續運行的推論後端（支援遞迴語言模型呼叫）、執行持久化 REPL 與守護程序支援的工作階段的運算節點，以及足夠的磁碟空間保存 L3 狀態（歷史紀錄、記憶、技能、軌跡）。長期任務建議配置可容錯與自動重啟的基礎設施。

**技能需求**：團隊需熟悉 Python/IPython、LLM 工具呼叫與提示工程、基礎系統設計與守護程序管理，並具備評估基準設計能力。若使用多智能體群體，還需理解狀態路由、動態協調與資源核算機制。

### 實作步驟建議

1. **部署 Prime Agent 工具架構**：安裝開源程式碼，設定守護程序與 Agents View，確保根工作階段能穩定連接持久化 REPL 與外部環境。

2. **定義任務與評估指標**：將目標拆解為可驗證的子任務，決定採用固定支出分數或實際高原分數作為長期評估指標，並建立測試與資源追蹤機制。

3. **設計初始提示與子智能體規格**：撰寫根智能體與遞迴子智能體的系統提示，明確各子智能體的角色、通訊協定與停止條件。

4. **建構程式化工具與 REPL 工作流**：讓模型能透過程式化上下文處理讀寫 L2 狀態，例如執行 Python 程式碼、查詢檔案、執行測試，並將結果序列化回作用中上下文。

5. **啟用 Continual Harness 保留狀態**：設定歷史紀錄、記憶、技能與提示的保存與精煉規則，使跨軌跡的經驗能成為後續推論的補充資訊。

6. **執行試驗性運行與錯誤分析**：先以小型任務驗證執行、復原、驗證與資源核算是否正常，區分工具架構失敗與模型失敗，避免誤判能力上限。

7. **擴展至多智能體與長期執行**：引入專用子智能體與智能體間直接通訊，利用 Agents View 進行人機協作，並持續精煉可重用技能。

8. **產品化整合**：將驗證後的工作流程接入現有開發工具鏈，例如 Git、CI/CD、監控系統與模型服務基礎設施。

### 潛在風險與注意事項

**狀態遺失與復原失敗**：長期執行中，非序列化 Python 物件或外部程序可能無法正確重建。建議定期保存核心工件，並設計從保存點恢復的機制，而非僅依賴事件歷史。

**資源計算錯誤與成本失控**：測試時計算與遞迴呼叫可能快速累積。需明確追蹤 token、時間與運算成本，設定預算上限與早期預警，避免單一任務消耗過多資源。

**過早終止或無限迴圈**：模型可能錯誤判斷完成條件。應設計獨立驗證器與最大步數限制，並透過 Agents View 讓人類能介入異常工作階段。

**上下文壓縮遺失關鍵資訊**：智能體式壓縮雖能減少 token，但可能刪除後續需要的細節。建議保留原始事件於 L3，並讓模型能主動檢索歷史紀錄。

**工具架構失敗被誤判為模型失敗**：當執行環境、網路或儲存出問題時，可能看起來像模型能力不足。應建立完善的日誌與錯誤分類，確保測量的是真正的最大潛在能力。

**多智能體協調複雜度**：智能體間直接通訊若缺乏清晰協定，可能產生冗餘工作或死結。建議從少數專用子智能體開始，逐步擴展，並定義訊息格式與責任邊界。

### 與其他技術的整合建議

**版本控制系統**：將 Prime Agent 生成的程式碼、技能與子智能體規格納入 Git 管理，讓每次精煉與軌跡都能回溯，並與現有程式碼審查流程結合。

**CI/CD 與自動化測試**：把 Prime Agent 的驗證步驟接入持續整合管線，使模型生成的程式碼在合併前必須通過預設測試，降低部署風險。

**開發環境與 IDE**：透過 Agents View 提供視覺化監控，並可與 VS Code、Jupyter 等編輯器整合，讓工程師能直接附加到守護程序支援的工作階段進行除錯或介入。

**可觀測性與監控平台**：將事件歷史、資源使用、工具呼叫與錯誤紀錄輸出至現有監控系統，便於長期分析效能曲線與異常偵測。

**模型服務基礎設施**：Prime Agent 可部署於自有 GPU 叢集或雲端模型 API 之上，建議搭配負載平衡與快取機制，以支援大量平行遞迴子智能體的推論需求。

**向量資料庫與檢索系統**：對於規模龐大的 L3 記憶與技能，可外接向量資料庫進行語意檢索，讓模型在需要時快速找到相關歷史紀錄與可重用技能。

### 給不同背景讀者的閱讀建議

**初學者**：建議先從摘要與適用場景開始，理解 Prime Agent 如何讓語言模型像類馮紐曼電腦一樣讀寫外部狀態。不必急著深入 RLM 抽象或守護程序細節，可先透過官方範例執行簡單的長期編碼任務，感受持久化 REPL 與記憶機制帶來的差異。

**AI 工程師**：應聚焦於第 2 節的架構設計，特別是資訊階層（L0–L3）、程式化計算、Continual Harness 的狀態保存機制，以及遞迴子智能體的通訊協定。實作時請優先確保執行、復原、驗證與資源核算的穩定性，再擴展至多智能體群體。

**研究人員**：建議深入閱讀評估方法論與實驗結果，包括固定支出分數與實際高原分數的選擇、ARC-AGI-3 的效能提升，以及長期評估中如何區分工具架構失敗與模型失敗。可進一步探討智能體式壓縮、精煉與測試時計算對可達策略集合的影響。

**產品經理**：請優先關注適用場景、Agents View 的人機協作價值，以及與現有開發流程的整合方式。評估導入時應衡量長期任務的成功率提升、人力監督成本與計算支出之間的平衡，並從單一明確的使用案例開始試點。
