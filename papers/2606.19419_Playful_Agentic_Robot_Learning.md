## ⚡ TL;DR

現有智慧體機器人系統僅在收到明確指令後才被動學習，缺乏任務前主動累積可複用技能的能力。
本文提出RATs，使機器人透過玩樂自主提案探索任務、執行與驗證程式碼，並蒸餾成功經驗為可複用技能庫。
實驗顯示玩樂習得技能顯著提升下游任務表現，並能無需微調即插即用至其他智慧體，促進模擬與真實世界遷移。

## 摘要翻譯

現有的智慧體機器人系統能夠撰寫可執行的 Code-as-Policy（程式碼即策略）程式、觀察回饋，並在多次嘗試中修正行為，但它們在很大程度上仍屬任務驅動：可複用技能僅在收到明確指令後才會習得。我們研究玩樂式智慧體機器人學習，其中具身編碼智慧體在下游任務到來前，將自我導向玩樂作為持續技能學習階段。我們提出 RATs / RATS（機器人智慧體團隊），專為玩樂階段技能習得而設計。在玩樂過程中，RATs 提出兼具新穎性與可學習性的探索性任務，規劃並執行機器人程式碼策略，驗證階段性進展，診斷失敗原因，利用密集且步驟層級的回饋進行重試，並將成功的執行過程蒸餾為技能後收錄於持久性程式碼技能庫。在測試階段，智慧體從此凍結庫中複用相關技能，以協助解決新任務。於 LIBERO-PRO 與 MolmoSpaces 上的實驗顯示，透過玩樂習得的技能相較於無玩樂與隨機玩樂基線，能改善保留的下游任務表現，相較於 CaP-Agent0 分別提升了 20.6 與 17.0 個百分點。此外，所習得的技能可整合至其他推論階段的 Code-as-Policy（程式碼即策略）智慧體，只需將其檢索至上下文中，即可使 RoboSuite 與真實世界遷移分別提升 8.9 與 8.8 個百分點，且無需微調底層模型。

### 核心貢獻（3～5點）
- 提出「玩樂式智慧體機器人學習」範式，使具身編碼智慧體能在下游任務到來前，透過自我導向玩樂進行持續技能學習，突破傳統任務驅動的限制。
- 設計 RATs / RATS（機器人智慧體團隊）架構，實現探索性任務提案、機器人程式碼策略執行、階段性進展驗證、失敗診斷與技能蒸餾的完整閉環。
- 建立持久性程式碼技能庫，並在測試階段以凍結庫形式透過上下文檢索複用技能，無需微調底層模型即可提升新任務解決能力。
- 於 LIBERO-PRO 與 MolmoSpaces 驗證，相較於無玩樂與隨機玩樂基線顯著改善保留的下游任務表現，相對於 CaP-Agent0 分別提升 20.6 與 17.0 個百分點。
- 所習得之技能可整合至其他推論階段的 Code-as-Policy（程式碼即策略）智慧體，並成功實現 RoboSuite 與真實世界遷移，分別提升 8.9 與 8.8 個百分點。

### 適合對象
機器人學、具身人工智慧與基礎模型應用之研究者，以及致力於開發模組化、可檢查且無需微調即可持續學習之智慧體機器人系統的工程師與開發者。

## 深度分析

#### 方法論解析

本文提出 Playful Agentic Robot Learning（玩樂式智慧體機器人學習），其核心假設是：具身編碼智慧體（embodied coding agent）應在下游任務（downstream tasks）到來前，先透過自我導向玩樂（self-directed play）進行持續技能學習階段（continual skill-learning stage），以累積可複用技能（reusable skills）。為實現此範式，作者設計 RATs / RATS（Robotics Agent Teams，機器人智慧體團隊），將玩樂階段技能習得（play-time skill acquisition）視為明確的知識累積過程，而非僅是開放式探索的副產品。

RATs 的運作可分為玩樂期與推論階段（inference time）。在玩樂期，系統首先透過任務提案（task proposal）機制，依據新穎性–可學習性法則（novelty–learnability rule）主動生成探索性任務（exploratory tasks）。這些任務必須同時滿足「擴展當前技能庫（skill library）的新穎性」與「在物理上可達成的可學習性」，從而避免無意義的隨機互動或過度困難的嘗試。接著，智慧體針對提案進行規劃，產生機器人程式碼策略（robot-code policies），即 Code-as-Policy（Code-as-Policy（程式碼即策略））的可執行程式。

與多數僅仰賴任務層級成敗訊號的任務驅動（task-driven）系統不同，RATs 強調密集步驟級回饋（dense, step-level feedback）。執行過程中，智慧體團隊會進行逐步驗證（per-step verification），確認中間子目標的達成狀態；若發生失敗，則啟動診斷與多嘗試重試（multi-attempt retry），透過結構化的失敗診斷定位缺失能力，並保留策略中仍可運作的部分。一旦執行成功，系統便將成功的行為蒸餾為可呼叫的程式碼片段，存入持久性程式碼技能庫（persistent code skill library）。

在推論階段，此技能庫成為凍結庫（frozen library），不再更新。面對新的下游任務時，RATs 透過上下文檢索（context retrieval）將相關技能載入 prompt（提示）中，協助生成解決方案。這種設計使玩樂階段習得的知識能以 plug-and-play（即插即用）的方式被重複利用，且 without finetuning（無需微調）底層 foundation models（基礎模型）。

#### 實驗數據解讀

作者於 LIBERO-PRO 與 MolmoSpaces 兩個模擬環境中進行玩樂階段訓練，並以 held-out downstream tasks（保留的下游任務）評估泛化能力。主要比較基線為 CaP-Agent0（無玩樂階段的基線智慧體）以及 random-play baseline（隨機玩樂基線）。

數據顯示，RATs 在 LIBERO-PRO 上相較 CaP-Agent0 取得 20.6 percentage-point gains（百分點提升），在 MolmoSpaces 上則提升 17.0 百分點。這表明經過結構化玩樂所習得的技能，能顯著改善未見過任務的表現，且並非單純記憶訓練任務的結果。相較於隨機玩樂基線的劣勢，亦驗證了新穎性–可學習性法則在課程設計中的關鍵角色——並非所有探索都同等有效，貼近能力邊界的自我導向練習才能產生可遷移的技能。

更具說服力的是跨環境遷移實驗：將於 LIBERO-PRO 習得的技能庫透過上下文檢索直接植入另一個 CaP-Agent0 中，在 RoboSuite 上提升 8.9 百分點；在 real-world transfer（真實世界遷移）中亦提升 8.8 百分點。這兩項結果凸顯了程式碼技能庫的模組化與環境無關性——技能以高階程式碼形式儲存，使其能跨越模擬器與實體硬體的差異，且完全無需微調底層模型參數。這對於實體機器人部署具有重大實務意義，因為它降低了從模擬到真實的遷移門檻。

#### 與現有研究的比較

相較於發展機器人學（developmental robotics）與內在動機（intrinsic motivation）的經典文獻，本文並非首次提出以玩樂驅動技能習得。然而，過往方法多在固定感測運動（sensorimotor）、目標或特徵空間中進行探索，而 RATs 的創新在於將此典範擴展至 Code-as-Policy 智慧體：探索目標以自然語言表述，並透過可執行程式碼實現，使行為更具可解釋性與組合性。相較於 end-to-end（端對端）的 vision-language-action policies（視覺-語言-動作策略），RATs 採用的程式碼即策略路徑具備 modular and inspectable（模組化且可檢查的）優勢，便於除錯與維護。

在 continual learning（持續學習）領域，既有研究多假設預定義的任務家族、目標表征或外部提供的經驗流。RATs 的差異性在於將課程（curriculum）本身視為自主發現的對象，並在 Code-as-Policy 框架內完成任務提案、執行與技能蒸餾的閉環。相較於 CaP-X 等多輪回饋框架，雖然同樣具備執行驗證與自動技能合成能力，但 CaP-X 本質上仍屬 task-driven（任務驅動）——技能僅作為解決指定任務的副產品累積。RATs 則反轉此邏輯，主動詢問「機器人應在接到指令前練習什麼」，使持續技能學習階段從被動反應轉為主動預備。

與 Voyager 等開放式大型多模態智慧體相比，Voyager 展示了自動課程與可執行技能庫可支援終身探索，但 RATs 將此概念落實於物理具身的操作學習，並引入逐步驗證與失敗診斷等機制，以處理機器人領域中稀疏獎勵與物理約束的挑戰。

然而，本文亦存在可討論的限制。首先，實驗中的玩樂階段仍於模擬環境中進行，雖有真實世界遷移結果，但尚未展示直接在實體環境中長期自主玩樂的可行性。其次，技能庫的規模與檢索效率在長期運作下的可擴展性未被深入探討。此外，系統高度依賴基礎模型的程式生成與語意理解能力，若底層模型對特定機器人 API 的掌握不足，玩樂階段可能產生大量不可執行的提案，浪費互動預算。

#### 可重現性評估

就現有文本脈絡而言，作者並未明確提及原始碼、模型權重或完整超參數設定的公開釋出計畫。不過，本研究所使用的評估基準——LIBERO-PRO、MolmoSpaces 與 RoboSuite——均為已公開之模擬平台，這降低了環境建置的門檻。方法論上，RATs 主要透過提示工程（prompt engineering）與多智慧體協作架構實現，而非訓練新的模型權重，因此在理論上無需釋出大型模型即可重現核心機制。

然而，可重現性的關鍵瓶頸在於實作細節的透明度。任務提案中的新穎性–可學習性法則、逐步驗證的具體檢查邏輯、失敗診斷的提示設計，以及技能蒸餾為程式碼的確切規則，這些都高度影響系統效能，但摘要與引言中尚未提供偽代碼或演算法細節。若未來作者能釋出智慧體團隊的提示模板、技能庫的資料結構，以及玩樂階段的互動日誌，將大幅提升社群重現與延伸此研究的可能性。

#### 未來研究方向

基於 RATs 的架構與實驗結果，以下幾個方向值得後續探索：

第一，動態技能庫管理。目前推論階段採用 frozen library（凍結庫），未來可研究在測試時持續更新技能庫的機制，使智慧體在面對新環境時仍能邊做邊學，而非僅依賴玩樂期的預先累積。

第二，高階技能組合。現有機制主要透過 context retrieval（上下文檢索）將單一技能載入提示，但未來可探索如何將多個 reusable skills（可複用技能）進行語意層級的組合，以解決更長期的多階段下游任務，超越簡單的檢索-生成範式。

第三，真實世界玩樂。當前研究以模擬玩樂為主，再透過 real-world transfer（真實世界遷移）驗證。未來可直接在實體環境中執行 self-directed play（自我導向玩樂），並發展對應的安全機制與硬體磨損考量，這對於將此方法推向實際應用至關重要。

第四，自動化課程度量學習。本文採用簡單的 novelty–learnability rule（新穎性–可學習性法則）進行任務提案，後續可引入元學習（meta-learning）或貝葉斯最佳化，讓智慧體從玩樂經驗中主動學習何種任務特徵最能預測技能成長，進而取代人工設計的篩選規則。

第五，跨本體遷移。程式碼技能庫目前主要服務於特定機器人 API，但未來可研究如何將技能抽象為更高階的「物理約束-效果」對（affordance-effect pairs），使其能遷移至不同形態的機器人平台。

第六，混合式架構整合。將 RATs 的模組化程式碼技能與 end-to-end（端對端）的 vision-language-action policies（視覺-語言-動作策略）結合，讓低階控制由資料驅動策略處理，高階規劃與技能編排由 Code-as-Policy 負責，可能同時兼顧反應速度與可解釋性。

## 論文問答

**Q1：現有的智慧體機器人系統在技能學習上面臨什麼核心問題？**
A：現有的智慧體機器人系統大多屬於任務驅動模式，只有在收到明確指令後才會開始學習與累積可複用技能。這種被動反應式的持續學習方式，使得機器人無法在下游任務到來之前主動建立有用的行為庫。本文提出的玩樂式智慧體機器人學習，正是為了讓具身編碼智慧體在部署前透過自我導向玩樂，持續習得可複用的程式碼技能。

**Q2：為何現有的 Code-as-Policy 方法難以實現持續且主動的技能習得？**
A：現有的 Code-as-Policy 智慧體通常只在解決特定被指派任務的過程中，將成功執行視為副產品儲存為技能，缺乏自主探索的機制。即使具備技能庫，這些系統仍依賴稀疏的任務層級成功或失敗訊號，難以解釋哪個子步驟出錯或應保留何種行為。因此，它們無法像自然智能一樣，在明確目標出現前透過玩樂主動擴展自身的能力邊界。

**Q3：根據本文，玩樂對機器人學習為何重要？**
A：從自然智能的觀點來看，兒童在接收明確目標前，會透過玩樂探索物體、發現可控效果並練習新興動作常規，從而獲得可複用技能。這種自我導向的互動提供了一個兼顧新穎性、意義性與能力邊界的課程。對於 Code-as-Policy 智慧體而言，玩樂變得格外實用，因為探索目標可以用語言表達、以程式碼執行，並將成功行為儲存為可呼叫的程式碼技能。

**Q4：什麼是 RATS，它如何實現玩樂式智慧體機器人學習？**
A：RATS（Robotics Agent Teams，機器人智慧體團隊）是本文專為玩樂階段技能習得設計的多智慧體架構。在玩樂階段，智慧體團隊會提出探索性任務、規劃並執行機器人程式碼策略、驗證中間進度、診斷失敗原因、利用密集步驟層級回饋重試，並將成功的執行過程蒸餾為持久性程式碼技能庫。到了測試階段，智慧體即可從這個凍結庫中檢索相關技能，協助解決從未見過的下游任務。

**Q5：相較於過去的好奇心驅動或任務驅動方法，RATS 的關鍵創新是什麼？**
A：不同於早期在固定感覺運動空間中探索的系統，RATS 將 Code-as-Policy 的優勢與發展機器人學結合，使探索目標能以可執行程式碼呈現，並蒸餾為可複用的程式碼技能。它將玩樂視為明確的技能習得過程，而非僅是開放式隨機探索，透過規劃、逐步驗證與失敗診斷提供密集回饋。這種設計讓智慧體能在下游任務尚未指定前，主動決定應該練習並累積哪些技能。

**Q6：RATS 為何選擇使用結構化智慧體團隊與密集回饋機制，而非僅依賴稀疏的任務層級訊號？**
A：單一的任務層級成功或失敗訊號過於稀疏，無法清楚解釋機器人學到了什麼、哪個子步驟失敗，或應該保存何種可複用行為。RATS 的結構化團隊針對中間子目標與多次執行嘗試提供密集回饋，使系統得以保留策略中有效的部分，並定位缺失的能力。這些機制共同確保成功的行為能被正確地轉換為可跨任務呼叫的程式碼技能。

**Q7：實驗在哪些基準環境中進行？**
A：本文主要在 LIBERO-PRO 與 MolmoSpaces 這兩個模擬環境中評估 RATS，測試玩樂階段習得的技能能否提升保留下游任務的表現。此外，研究也進行了跨環境遷移實驗，將 LIBERO-PRO 習得的技能套用至 RoboSuite，並在真實世界場景中驗證轉移效果。這些基準涵蓋了多樣的操作任務，用以全面檢視技能庫的實用性與泛化能力。

**Q8：RATS 取得了哪些關鍵量化結果？**
A：在 LIBERO-PRO 上，RATS 的平均成功率較 CaP-Agent0 基線提升了 20.6 個百分點；在 MolmoSpaces 上則提升了 17.0 個百分點。更具體地說，當把習得的技能直接檢索到其他推論階段的 Code-as-Policy 智慧體上下文時，RoboSuite 的成功率提升了 8.9 個百分點，真實世界遷移也提升了 8.8 個百分點，且無需微調底層模型。這些結果顯示，透過玩樂習得的程式碼技能能顯著且即插即用地增強下游表現。

**Q9：與無玩樂和隨機玩樂基線相比，RATS 的表現如何？**
A：實驗顯示，RATS 的結構化玩樂所習得的技能，在保留下游任務上的表現優於無玩樂與隨機玩樂基線。這證明並非任何探索都有幫助，而是需要兼顧新穎性與可學習性的任務提案，以及具備密集回饋的執行與驗證機制，才能累積真正有價值的技能。若缺乏這些設計，智慧體將難以建立能遷移到新任務的可複用程式碼技能庫。

**Q10：玩樂式智慧體機器人學習適合應用在哪些實務場景？**
A：此範式特別適合部署在家庭服務機器人或倉儲物流機器人上，讓它們在閒置或充電期間自主練習操作技能。透過玩樂，機器人可預先累積抓取、堆疊或工具使用等可複用行為，無需工程師針對每項任務逐一示範或撰寫程式。當使用者後續提出具體需求時，機器人便能快速從技能庫中檢索並組合相關程式碼策略，有效縮短反應時間並提升成功率。

**Q11：將 RATS 整合至商業機器人系統時，有哪些重要的產品考量？**
A：RATS 將成功經驗蒸餾為持久性程式碼技能庫，並在測試階段凍結使用，這提供了無需微調昂貴基礎模型的即插即用機制。廠商可在機器人待機時啟動玩樂階段，持續擴充技能庫而不影響正式任務的執行。此外，Code-as-Policy 具備模組化且可檢查的特性，工程團隊能輕易審視、除錯與版本控制習得的技能，降低部署風險與維護成本。

**Q12：這項研究可能對機器人學習領域帶來什麼廣泛影響？**
A：本研究將機器人學習從被動的任務驅動模式轉向主動的玩樂驅動技能習得，與自然發展原則接軌，有助於減少對大量標示任務示範的依賴。它為具身編碼智慧體建立了持續學習的實用框架，並展示技能庫可跨環境與跨智慧體共享。這種可檢索、可遷移的程式碼技能庫機制，未來可能促進不同 Code-as-Policy 系統之間的互通性，加速整個領域的模組化發展。

**Q13：RATS 框架目前存在哪些已知的限制？**
A：目前的評估主要集中在 LIBERO-PRO、MolmoSpaces 等模擬環境，對於高度非結構化、物體種類無窮的真實世界場景，其擴展性仍有待驗證。玩樂的有效性高度依賴新穎性–可學習性法則與自我驗證機制，若感知雜訊過大或行為後果嚴重延遲，系統可能難以正確評估中間進度。此外，測試階段使用凍結庫的設計，意味著部署後的線上持續適應能力在現階段尚未被充分探討。

**Q14：在哪些情況下 RATS 可能會失敗或產出次優的技能？**
A：若玩樂階段提出的探索性任務過於簡單或遠超過智慧體當前能力，系統可能浪費互動時間，甚至累積無用的失敗模式而非有效技能。在難以透過視覺或程式化方式驗證中間進度的環境中，密集回饋迴路可能誤判子步驟的成功，導致習得脆弱的技能。此外，若下游任務所需的操控能力完全超出玩樂經驗的分布範圍，凍結的技能庫將無法提供任何相關支援，導致表現不佳。

**Q15：這項研究指出了哪些未來方向？**
A：未來研究可朝線上持續學習發展，讓技能庫在下游任務執行期間仍能動態更新，而非僅在測試時保持凍結。結合更複雜的內在動機訊號或人類引導的玩樂，也有助於進一步提升技能的品質與多樣性。另一個值得探索的方向是跨本體遷移，讓某類機器人習得的程式碼技能能透過上下文檢索，直接供不同硬體平台的智慧體調整使用。

## 實務應用指南

### 適用場景

1. **高變異性倉儲物流前置適應**  
   在正式接收揀貨或盤點指令前，讓機器人透過自我導向玩樂探索不同尺寸、材質與重量的箱體與包材，累積抓取、堆疊與放置的程式碼技能庫。當下游 WMS 下達新任務時，可直接檢索已習得的技能，縮短上線準備時間。

2. **長照與醫療輔助機器人的居家預備**  
   進入病患居家或病房前，機器人先在模擬或受控環境中進行玩樂階段技能習得，自主探索水杯、藥盒、遙控器等常見物品的操作方式。建立的持久性程式碼技能庫能於推論階段直接複用，降低對現場工程師調校的依賴。

3. **家庭服務機器人的跨環境部署**  
   面對不同家庭佈局與家具配置前，讓具身編碼智慧體透過探索性任務練習開門、拉抽屜、按開關等通用操作原語。這些可複用技能可隨著部署場景增加而持續擴充，形成跨家庭的即插即用能力。

4. **製造業快速換線與新治具適應**  
   產線切換或引入新治具時，機器人可在停機空檔進行自我導向玩樂，探索新零件的夾取點與擺放軌跡。透過無需微調的技能庫機制，將玩樂習得的能力直接遷移至正式組裝任務，減少產線 downtime。

5. **災害搜救與未知環境的模擬預演**  
   在數位孿生或模擬環境（如 RoboSuite）中進行大規模玩樂式探索，累積跨越障礙、操作閥門與搬運碎片的機器人程式碼策略。確認技能穩定後再進行真實世界遷移，提升未知場景的任務成功率。

### 實作前置條件

**資料與環境**  
- 機器人低階控制與感知 API 的完整封裝（如 ROS/ROS2 Action 或 gRPC 介面），供 Code-as-Policy 產生可執行程式碼。  
- 模擬環境（如 LIBERO-PRO、RoboSuite）或數位孿生平台，用於安全地執行高頻次的探索性任務。  
- 若需跨環境遷移，需準備領域隨機化（domain randomization）參數與少量真實世界校正資料。

**運算資源**  
- 基礎模型（LLM/VLM）的 API 存取權限或本地部署 GPU 叢集，用於多智慧體的規劃、診斷與程式碼生成。  
- 向量資料庫（如 Chroma、Pinecone）與程式碼版本控制系統，用於儲存與檢索持久性程式碼技能庫。  
- 足夠的運算預算支援多輪重試與密集回饋迴圈，單一玩樂階段可能涉及數百至數千次的生成-執行-驗證循環。

**技術能力**  
- 機器人作業系統開發與模擬到真實（sim-to-real）部署經驗。  
- 大型語言模型提示工程與多智慧體協作架構設計能力。  
- 基礎的程式碼靜態分析與單元測試能力，用於驗證智慧體產生的機器人程式碼策略是否安全。

### 實作步驟建議

**步驟一：環境抽象化與 API 封裝**  
將機器人的感知（如 `observe()`、`get_object_pose()`）與控制（如 `pick(obj)`、`place(loc)`）封裝為高階、模組化且可檢查的 API。這是 Code-as-Policy 的執行基礎，也是後續技能蒸餾的語法單元。

**步驟二：部署 RATS 多智慧體架構**  
建立機器人智慧體團隊，至少包含：任務提案者（遵循新穎性–可學習性法則）、規劃者（生成機器人程式碼策略）、執行驗證者（提供每步驟密集回饋）、失敗診斷者（定位錯誤子步驟）與記憶管理者（更新技能庫）。

**步驟三：啟動玩樂階段技能習得**  
讓系統在模擬環境中自主提出探索性任務，執行並驗證。對於每次嘗試，保留成功的中間子目標軌跡，對失敗進行診斷與重試。此階段不需人類提供下游任務指令。

**步驟四：技能蒸餾與持久化**  
將成功執行序列抽象化為泛用函式（如 `grasp_cylindrical_object(obj)`），去除硬編碼的特定物件 ID 與座標，存入持久性程式碼技能庫。建議為每個技能附加自然語言描述與執行成功率，便於後續語意檢索。

**步驟五：凍結技能庫並整合推論流程**  
當玩樂階段結束，將技能庫設為凍結庫。在推論階段面對下游任務時，透過上下文檢索將相關技能程式碼注入提示（prompt），讓基礎模型在生成新策略時直接呼叫已習得的能力。

**步驟六：跨系統遷移與真實部署**  
將習得的技能庫以純文字程式碼形式匯出，插入其他現有的 Code-as-Policy 智慧體（如 CaP-Agent0）的推論上下文，驗證跨環境提升效果後，再部署至實體機器人進行最終校正。

### 潛在風險與注意事項

**技能庫膨脹與檢索雜訊**  
隨著玩樂階段進行，程式碼技能庫可能過度增長，導致推論階段上下文過長或檢索到不相關技能。**建議**定期執行去重與語意聚類，並為技能庫建立階層式索引（如按操作類型與物件類別分群）。

**實體玩樂的安全性風險**  
自我導向玩樂在真實環境中可能導致碰撞、夾傷或硬體損壞。**建議**所有高頻探索必須在模擬或具備安全籠與緊急停止機制的受控環境中完成，實體機器人僅在凍結庫驗證階段以低速運行。

**任務提案的不可學習陷阱**  
若新穎性過高而超出機器人當前能力，可能導致反覆失敗且無法累積有效技能。**建議**為新穎性–可學習性法則設置動態門檻：當同一類探索任務連續失敗超過設定次數，自動降級難度或暫時排除該任務類型。

**模擬到真實的感知落差**  
模擬中習得的程式碼策略可能依賴完美深度估計或物件偵測。**建議**在技能程式碼中保留容錯參數（如容許誤差範圍、重試次數），並在真實世界遷移時加入視覺域適應（domain adaptation）層。

**底層基礎模型漂移**  
若使用外部 LLM API，供應商的模型更新可能改變程式碼生成風格或 API 呼叫語法，使已凍結的技能庫相容性受損。**建議**鎖定模型版本，或採用本地部署的開源模型以確保行為一致性。

### 與其他技術的整合建議

**與 ROS/ROS2 及行為樹整合**  
將 RATS 的程式碼技能庫封裝為 ROS Action 或 Service，使傳統機器人軟體架構（如行為樹、狀態機）能透過標準介面呼叫玩樂階段習得的能力，無需全盤重寫既有控制邏輯。

**與 VLA 端對端策略形成分層架構**  
讓 RATS 擔任高階規劃器，負責任務分解與技能序列編排；低階的視覺-語言-動作（VLA）策略則負責細部軌跡生成。Code-as-Policy 的模組化特性使其能輸出目標與約束給 VLA，結合兩者的優勢。

**與數位孿生（Digital Twin）整合**  
在數位孿生中執行大規模、高並行的玩樂階段，利用雲端算力快速累積技能庫，再將篩選後的凍結庫同步至邊緣端的實體機器人，實現雲端學習、邊緣推論的架構。

**與企業系統（WMS/MES）整合**  
在倉儲或製造場景中，讓 WMS/MES 的未來工單預告作為任務提案的輔助訊號（而非直接指令）。RATS 可據此主動提案相關探索性任務，預先擴充技能庫以應對即將到來的下游任務類型。

---

### 給不同背景讀者的閱讀建議

**給初學者**  
請先建立一個核心認知：本文的「玩樂」並非隨機亂動，而是有結構、有驗證的自我練習。建議從 Code-as-Policy（程式碼即策略）的基本概念與論文中的 CaP-Agent0 基線開始，理解為何「先玩再做事」比傳統任務驅動模式更能累積可複用能力。不必急著深入多智慧體細節，先掌握「技能庫」與「上下文檢索」這兩個機制即可。

**給 AI 工程師**  
請重點關注機器人智慧體團隊的實作分工：規劃、每步驗證、失敗診斷與記憶更新如何協同提供密集回饋。此外，技能庫的向量檢索設計與推論時的提示注入（prompt injection）是決定系統穩定度的關鍵。論文顯示無需微調底層模型即可透過檢索提升表現，這對降低維運與再訓練成本極具實務價值。

**給研究人員**  
可深入探討新穎性–可學習性法則的設計空間，以及密集回饋相對於稀疏任務訊號的理論優勢。此外，程式碼技能庫的組合泛化性、跨環境遷移（如 LIBERO-PRO 到 RoboSuite）的機制，以及玩樂階段與持續學習的收斂性，都是值得延伸的研究方向。

**給產品經理**  
請將玩樂階段視為「前置訓練」或「預備工時」的投資：雖然前期需要運算與時間成本，但能顯著縮短正式上線後的客製化與現場調校時間。技能庫的即插即用特性意味著一次學習、多場景複用，有助於降低後續整合成本與跨案場部署的邊際成本，特別適合需要快速規模化的機器人服務產品。
