## 深度分析

#### 方法論解析

本論文提出一個雙階段框架，解決長視野（long horizon）任務中程式化策略（program policies）演化所面臨的兩個核心挑戰：局部改進可能損害最終表現，以及切換新目標需要重新進行昂貴的合成（synthesis）過程。

**第一階段：反饋級聯（Feedback Cascade）**

傳統方法僅使用回合回報（episode returns）作為反饋訊號，在 Craftax 這種需要 100,000 步才能完成的程序生成環境（procedurally generated environment）中表現極差（最終樓層到達率僅 0.29%）。論文提出的反饋級聯包含五個層次（A→E），從粗到細逐步提供結構化反饋：

- **A. 回合級（Episode）**：傳統的二元成功指標 YF(P, s)，僅在最終通關時回報 1。
- **B. 樓層級（Floor）**：以到達特定樓層作為里程碑（milestone），利用公式 (2) 的因式分解 Jg(P) = ∏ Pr(E_{k+1}|E_k) 定位瓶頸。
- **C. 分支級（Branch）**：評估策略在特定分支點（如進入冰雪境界後返回火焰境界取資源）的延續性（continuation）。
- **D. 目標級（Goal）**：內部目標（internal goals）對應 RL 中的選項（options）框架，具有符號化的進入、完成與放棄謂詞（predicates），執行於呼叫堆疊上。
- **E. 模型級（Model ε）**：對信念更新（belief updates）進行密集評分（dense scoring），例如對即將受到的傷害、敵人冷卻時間或資源消耗等不可觀察量的預測準確度。

關鍵洞察在於「延續性評分」（continuation-scored feedback）的設計：對於一個編輯 P'，其接受標準並非子目標本身的完成度，而是該子目標完成後能否延續至最終目標。論文定義 ΔF(P', P) = E_{s∼ρF}[YF(P' ⊕F P, s) − YF(P, s)]，其中 ⊕F 表示在特定反饋層級 F 處替換程式碼片段。這種設計避免了「局部最優陷阱」——例如在冰雪境界中斷探索返回取食物的行為，只有在保留足夠生命值與時間完成後續旅程時才應被獎勵。

**第二階段：策略分解與目標編譯器（Goal Compiler）**

完成第一階段後，論文將單任務熟練策略（single-task competent policy）分解為兩個組件：

- **環境解譯器 I（Environment Interpreter）**：固定的機器（fixed machine），包含世界模型（world models）、空間記憶（spatial memory）與技能（skills）等領域知識（domain knowledge）。
- **規則程式 p_0**：可編輯的程式（editable program），包含針對原目標的程序性資訊（procedural information）。

此分解具有性能保證：P_0(h) = I(p_0)(h)，即原策略可由解譯器執行 p_0 重現。

接著，編碼代理（coding agent）最佳化一個可重用的目標編譯器 C_θ，該編譯器將結構化任務 g 映射為新的規則程式 p_g：

$$C_\theta(g) = \text{Link}(p_0, \text{Encode}(g), E_\theta(g))$$

其中：
- **Encode(g)**：將任務編碼為階段表格（stage tables），例如「floor 1: reach(1); floor 2: acquire(coal≥6), maintain(coal≥2); reach(2)」。
- **E_θ(g)**：發射器（emitter）輸出一條規則，例如 `rule sr_sequence [build] { try sr_control(&sk) as sk; }`。
- **Link**：將上述組件組合成完整的 p_g。

部署時，凍結的編譯器 C_{θ*} 將未見過的任務 g 轉譯為 p_g = C_{θ*}(g; p_0)，由固定機器 I 執行，整個過程無需推論時的大型語言模型呼叫（inference-time LLM calls）。

#### 實驗數據解讀

**主要實驗結果**

| 評估指標 | 回合級反饋 | 反饋級聯 |
|---------|-----------|---------|
| 最終樓層到達率（2,048 個世界） | 0.29% | 50.49% |
| 最終頭目擊敗率 | — | 28% |

這個 174 倍的提升（從 0.29% 到 50.49%）是本論文最核心的實驗貢獻。在 100,000 步的長視野、部分可觀察（partially observed）、程序生成環境中，能達到 50% 的最終樓層到達率，證明了反饋級聯設計的有效性。

**編譯器遷移實驗**

在 48 個未見過的任務上：
- 完整編譯器（含 guards）：71.30% 完成率
- 僅使用 guards：36.20% 完成率

這顯示目標編譯器相對於單純的保護機制（guards）有顯著優勢，且這些編譯器僅在 16 個短任務上訓練，就能零樣本遷移（zero-shot transfer）到更長的任務序列，無需任務特定調校（task-specific tuning）。

**關鍵觀察：局部與全局反饋的負相關**

論文特別指出，在編碼代理的程式碼更新過程中，「對到達下一樓層的影響」與「對到達最終樓層的影響」呈現負相關。這是一個反直覺但極為重要的發現：能幫助越過當前瓶頸的編輯，反而可能損害最終表現。這正是為何需要延續性評分而非子目標完成度作為反饋訊號的實證基礎。

**控制實驗**

論文進行了控制實驗（control experiments）確認編碼代理確實從所提出的框架（harness）中受益，而非僅靠 LLM 本身的先驗知識。這強化了方法論的可信度。

#### 與現有研究的比較

**與神經-符號式（Neuro-Symbolic）方法的關係**

本論文屬於神經-符號式勞動分工（neuro-symbolic division of labor）的範疇：昂貴的搜尋（expensive search）由 LLM 在開發階段執行，低成本且可審核的執行（cheap and auditable execution）由編譯後的 C 程式在部署時執行。這與 Liang et al. (2023) 和 Chaudhuri et al. (2021) 的程式合成（program synthesis）工作一脈相承，但更強調長視野任務的可行性。

**與強化學習的比較**

傳統強化學習（RL）在 Craftax 上的表現已有 Matthews et al. (2024) 的基準測試。本論文的程式化策略方法提供了一條替代路徑：無需梯度下降，無需神經網路權重，僅透過程式碼編輯與模擬器反饋（simulator feedback）即可達到 50% 的最終樓層到達率。這對於需要可解釋性、可審核性的應用場景特別有價值。

**與階層式強化學習（HRL）的關係**

內部目標（internal goals）的設計與 Sutton, Precup, and Singh (1999) 的選項框架（options framework）以及 Murphy (2026) 的受控階層式隱馬可夫模型（controlled hierarchical hidden Markov models）密切相關。本論文的貢獻在於將這些概念實現在程式化策略中，並展示了如何透過反饋級聯有效最佳化。

**改進與侷限性**

改進之處：
1. 首次系統性地展示反饋結構對程式化策略搜尋（policy search）的決定性影響。
2. 提出「延續性」概念，避免子目標最佳化中的短視陷阱。
3. 將單任務策略轉化為可重用目標編譯器，實現零樣本遷移。

侷限性：
1. 實驗僅在 Craftax 單一環境上驗證，泛化性有待確認。
2. 編碼代理的開發成本（包含多次模擬器運行）仍然高昂。
3. 編譯器的可重用性受限於原任務與新任務的結構相似性。
4. 對於需要即時反應或精細控制的任務，純程式化策略可能不如神經策略靈活。

**3. 理論分析**

論文觀察到「局部與全局反饋的負相關」，但缺乏理論解釋。未來工作可以：
- 形式化定義「延續性」的資訊理論度量
- 分析反饋級聯各層之間的資訊流
- 探討何時反饋級聯會失效

**4. 與神經策略的混合**

結合程式化策略的可解釋性與神經策略的適應性。例如：
- 程式化策略作為骨幹（backbone），神經網路處理例外情況
- 神經網路學習何時切換不同的程式化子策略
- 蒸餾（distillation）程式化策略為神經策略以加速部署

**5. 安全性與可驗證性**

程式化策略的一大優勢是可審核性（auditability）。未來可以：
- 整合靜態分析工具驗證策略的安全性
- 設計形式化規範（formal specifications）並自動驗證合規性
- 探索在安全關鍵領域（如機器人控制、醫療決策）的應用

**6. 編譯器的持續學習**

當前編譯器在固定訓練任務上最佳化後凍結。可以探索：
- 部署後的線上學習（online learning）機制
- 元學習（meta-learning）框架使編譯器快速適應新任務族
- 從人類示範中學習新的任務結構

**7. 社會與倫理影響**

程式化策略的零推論成本特性使其適合邊緣部署，但也引發：
- 自主系統的可解釋性要求
- 程式碼偏見（code bias）的檢測與緩解
- 與人類決策者的協作介面設計

本論文為程式化策略的長視野最佳化開闢了新路徑，其核心洞見——「反饋結構決定可行策略空間」——對更廣泛的機器學習與人工智慧研究都有深遠意義。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於長視野任務中程式化策略最佳化的兩個關鍵挑戰：局部改進可能損害最終成功率，以及為新目標切換需要昂貴的重新合成。具體而言，在 Craftax 這種需要十萬步動作的程序生成環境中，傳統的回合級反饋無法有效引導策略演化，因為早期決策的影響要等到數千步後才會顯現。作者提出一個兩階段框架來同時解決這兩個問題，透過反饋級聯提升單任務表現，再透過目標編譯器實現跨任務重用。

**Q2：為什麼現有的回合級反饋方法在長視野任務中會失敗？**
A：純量回合獎勵在長視野任務中會產生誤導性的回饋訊號，因為一個回合的成敗無法定位失敗發生的具體階段。論文發現，程式碼更新對「到達下一樓層」與「到達最終樓層」的影響呈現負相關，這意味著子目標的局部成功並非良好的價值函數。當代理在冰雪境界探索時，可能為了覓食而中斷探索返回前一樓層，但這種策略只有在代理有足夠生命值和時間完成剩餘旅程時才有用，凸顯了延續性評分的重要性。

**Q3：為什麼這個問題對神經-符號式 AI 領域很重要？**
A：程式碼代理能夠從模擬器反饋合成並最佳化基於程式碼的策略，使最終程式在部署時無需推論時的大型語言模型呼叫，實現了昂貴搜尋與低成本、可審核執行的勞動分工。這種神經-符號式範式對於需要可解釋性與可審計性的實際部署至關重要，特別是在延遲敏感或離線場景中。然而，反饋訊號的設計決定了可行策略的搜尋空間，因此理解何種反饋能引導程式化策略搜尋是擴展此範式的核心問題。

**Q4：反饋級聯的核心方法是什麼？**
A：反饋級聯是一種從粗粒度到細粒度的漸進式評分機制，從回合回報開始，逐步過渡到階層式目標與信念更新，每一層都能從模擬器中密集評分。具體而言，級聯包含五個層次：A 回合級、B 樓層級、C 分支級、D 目標級、E 模型級，每一層都評估編輯後的程式相對於現有程式的延續性表現（即從某個狀態點接續執行後的結果）。這種設計使得編輯的接受標準不再是子目標的完成條件，而是它所留下的延續性，從而避免局部改進損害最終表現的陷阱。

**Q5：目標編譯器的關鍵創新是什麼？**
A：目標編譯器 C_θ 將結構化任務 g 映射到新的規則程式 p_g，使得單一任務的熟練策略可以重複用於替代目標。其核心創新在於將先前最佳化的控制器分解為固定的環境解譯器 I（包含模型、記憶、技能）與規則程式 p_0，這樣編譯器只需生成新的規則部分，而世界模型等領域知識得以保留。經過五次獨立編譯器搜尋（僅在短任務上訓練），最終編譯器能夠零樣本遷移到更長的未見任務，無需任務特定調校或推論時的語言模型呼叫。

**Q6：將策略分解為解譯器與規則程式的設計選擇有何考量？**
A：這種分解的關鍵設計選擇在於明確劃分領域知識（世界模型、空間記憶、技能）與任務特定的程序性資訊。環境解譯器 I 作為固定機器，承載了跨任務可重用的模擬器互動邏輯，而規則程式 p_0 則是任務特定的決策邏輯，可以被編輯或替換。這種架構使得編譯器 C_θ 只需學習如何將任務描述編碼為新的規則序列，而無需重新學習整個遊戲的領域知識，大幅降低了搜尋空間並提升了遷移效率。

**Q7：實驗使用了什麼基準測試環境？**
A：實驗在 Craftax Full 環境中進行，這是一個程序生成的生存遊戲，包含九個樓層，從地表世界（樓層 0）到墓地（樓層 8），最終需要擊敗最終頭目（死靈法師）。代理每個回合有十萬步的動作預算，需要收集資源、合成工具與盔甲、管理物理狀態、戰鬥並穿越越來越困難的樓層。環境是部分可觀察的，代理必須學習自己的內部地圖、梯子位置與資源狀態，因為引擎在執行時不會提供隱藏狀態，這對策略的記憶與推理能力提出了極高要求。

**Q8：論文報告了哪些關鍵的量化結果？**
A：在 2048 個遊戲世界的測試集上，總體回合級反饋僅達到 0.29% 的最終樓層到達率，而反饋級聯將到達率提升至 50.49%，並達到 28% 的最終頭目擊敗率，展現了超過 170 倍的改進幅度。在編譯器遷移實驗中，48 個未見任務的完成率達到 71.30%，相比僅使用防護機制（guards）的 36.20% 有顯著提升。這些結果證明了反饋級聯在策略最佳化上的有效性，以及目標編譯器在零樣本遷移上的能力。

**Q9：論文進行了哪些消融實驗或控制實驗？**
A：論文進行了嚴格的群組評估（strict cohort evaluation），並審計了誤導性局部反饋的影響，特別是子目標完成度與最終成功率之間的負相關現象。此外，控制實驗確認了程式碼代理從所提出的框架中受益，比較了不同反饋層次對策略演化的影響。這些消融實驗驗證了反饋級聯中每一層的必要性，以及延續性評分相對於子目標評分的優勢，證明了精心設計的反饋訊號對於程式化策略搜尋至關重要。

**Q10：這項研究有哪些實際應用場景？**
A：這項研究適用於任何需要長視野規劃且對可審核性有要求的領域，例如工業自動化、機器人任務規劃、遊戲 AI 開發以及程式合成。由於最終策略是無需推論時語言模型呼叫的可執行程式，這對於延遲敏感或離線部署的場景特別有價值。此外，目標編譯器的設計使得同一套領域知識可以重複用於多個任務，大幅降低了為新任務開發策略的成本，這在任務多樣化的實際環境中尤為重要。

**Q11：從產品化角度，這個框架有哪些考量？**
A：從產品化角度，此框架的核心優勢在於部署階段無需語言模型呼叫，這意味著推理成本可降至接近零，且執行延遲僅取決於程式執行速度。然而，開發階段仍需要多次模擬器評估，這對計算資源提出了要求，且開發時間可能較長。此外，編譯器需要在一組訓練任務上進行搜尋，這需要事先定義任務空間並準備相應的模擬環境，這在實際部署前需要額外的前期投資與領域專業知識。

**Q12：這項研究對神經-符號式 AI 領域有何更廣泛的影響？**
A：這項研究展示了如何透過精心設計的反饋訊號來擴展程式化策略搜尋的可行性，對神經-符號式 AI 領域有重要啟示。它證明了將昂貴的搜尋階段與廉價的執行階段分離的可行性，並展示了如何將單任務策略轉化為可重用的目標編譯器。這種「學習如何編譯」的方法論可能會影響未來程式合成、神經-符號推理以及自動化決策系統的設計方向，特別是在需要可解釋性與可重用性的應用中。

**Q13：論文承認了哪些限制？**
A：論文承認其方法依賴於能夠從模擬器中密集評分的環境，這在某些真實世界場景中可能難以實現，因為真實環境的回饋往往稀疏且延遲。此外，編譯器的訓練需要一組結構化的訓練任務，這對於任務空間定義不清的領域可能具有挑戰性。雖然策略在部署時無需語言模型呼叫，但開發階段仍需要大量的模擬評估，這對計算資源有較高要求，可能限制其在資源受限環境中的應用。

**Q14：存在哪些失敗案例或邊界情況？**
A：論文中提到的一個關鍵失敗模式是，當代理在冰雪境界探索時為了覓食而中斷探索，這種局部合理的行為可能會損害最終成功率，凸顯了局部最優與全局最優之間的矛盾。此外，當訓練任務與測試任務的結構差異過大時，編譯器的零樣本遷移能力可能會下降，因為編譯器學到的規則組合模式可能無法泛化到全新的任務結構。論文也指出，子目標的局部成功與最終成功之間的負相關是反饋設計中的核心挑戰，需要謹慎處理。

**Q15：未來的研究方向有哪些？**
A：未來研究方向可能包括將此框架擴展到更複雜的真實世界環境，例如機器人控制或工業流程自動化，這需要解決真實環境中回饋稀疏的問題。此外，可以探索如何自動化訓練任務的生成與選擇，以減少對人工定義任務空間的依賴，使框架更加自主化。另一個有趣的方向是研究如何將延續性評分的思想應用於其他程式合成領域，例如程式修復或程式優化，以及探索更強大的編譯器架構以處理更長的任務序列和更複雜的任務組合。

## 實務應用指南

### 適用場景

1. **程序生成遊戲的 NPC 與 Boss 行為設計**：當遊戲關卡、地圖、敵人配置皆為程序生成時，傳統行為樹難以泛化。本框架可讓 LLM 透過模擬器反饋演化出可執行的 C 程式策略，部署時無需 LLM 呼叫，適合《Craftax》類生存遊戲、roguelike、自動化測試關卡等場景。

2. **工業機器人長視野操作任務**：在半結構化工廠環境中，機器人需在數萬個動作步內完成「取料→加工→組裝→品檢→入庫」等多階段任務。可將工廠模擬器作為環境，把每個工作站視為「樓層」，利用反饋級聯找出瓶頸並產生可重用策略。

3. **DevOps 與 IT 自動化長流程**：例如跨多個雲端服務、CI/CD 流水線、災難復原演練等需要數百至數千步決策的工作流程。可將基礎設施模擬器（如 Terraform + chaos engineering 環境）作為訓練場域，產生可審核、可版本控制的腳本策略。

4. **自動駕駛與無人機長程任務規劃**：在城市配送、無人機巡檢等場景中，任務包含「起飛→巡航→避障→投遞→返航」等多個里程碑，且每個里程碑的成功率會影響後續。可用本框架的延續性評分機制避免「為了到達中繼點而犧牲最終成功率」的陷阱。

5. **教育與訓練模擬器中的智慧教練**：例如醫學手術模擬、飛行模擬等需要數千步操作的訓練環境。可將單一專家策略分解為「環境解譯器 + 規則程式」，再訓練目標編譯器，使同一套底層能力可快速客製化不同訓練目標。

### 實作前置條件

**資料需求**

- C 語言（或 Rust/Lua 等可嵌入的高效語言）以撰寫策略本體

- 基礎強化學習概念（episode、return、option、hierarchical policy）
- 統計評估能力（cohort 評估、顯著性檢定、避免單一種子過擬合）

### 實作步驟建議

**步驟一：建立基準策略與反饋基線**
- 先讓 LLM 僅以「回合回報」為唯一反饋訊號產生策略，記錄其在測試集上的最終到達率（論文基準約 0.29%）。
- 同時建立里程碑分解：將任務切成 K 個有序里程碑（如樓層 0→1→…→8），並為每個里程碑定義「延續性評分」函式 Y_F。

**步驟二：實作反饋級聯（A→E）**
- A 回合級：總體成功指標
- B 樓層級：到達每個樓層的機率
- C 分支級：在每個樓層內部子程式的存活率
- D 目標級：階層式內部目標的完成與放棄
- E 模型級：信念更新（血量、敵人冷卻、資源枯竭）的準確度
- 讓 LLM 從粗到細逐步使用這些反饋，每一層只在前一層收斂後才啟用。

**步驟三：審核局部改進的誤導性**
- 對每次程式碼編輯，同時記錄「下一樓層到達率變化」與「最終樓層到達率變化」。
- 若兩者呈負相關，標記為「局部貪婪陷阱」，並在反饋中明確告知 LLM 採用延續性分數 ΔF(P′, P) 而非單點子目標完成率。

**步驟四：將策略分解為 (I, p₀)**
- 識別策略中的「固定機器」部分：世界模型、空間記憶、技能庫（這些是領域知識，跨任務可重用）。
- 識別「規則程式」部分：與特定任務目標耦合的程序（這些需要被編譯器替換）。
- 確保 I(p₀) 在語意上等價於原策略 P，並保留效能保證。

**步驟五：訓練目標編譯器 C_θ**
- 準備 16 個左右的短任務，每個任務以結構化格式描述（樓層表、資源閾值、序列約束）。
- 讓 LLM 編輯一個「發射器」E_θ，給定任務 g 後輸出一段規則程式片段。
- 連結器（Link）將 E_θ(g) 與 Encode(g)、p₀ 組合成完整策略 p_g，並由固定機器 I 執行。
- 以延續性評分作為反饋，搜尋最佳的 θ*。

**步驟六：凍結並部署**
- 凍結 θ*，不再進行任務特定調校。
- 部署時：給定新任務 g → C_θ*(g) 產出 p_g → I(p_g) 執行，整個過程無 LLM 呼叫。
- 在 48 個未見過的長任務上驗證零樣本遷移率（論文達 71.30%）。

**步驟七：建立持續監控**
- 監控編譯器在生產環境中產出的程式是否通過靜態分析與單元測試。
- 收集執行軌跡，用於未來版本的編譯器再訓練。

### 潛在風險與注意事項

**風險一：局部貪婪陷阱**
- 現象：LLM 為了提高「到達下一樓層」的機率而修改策略，卻降低了最終到達率。
- 緩解：強制使用延續性評分 ΔF 而非子目標完成率；定期審核「下一樓層 vs 最終樓層」的相關性。

**風險二：編譯器過擬合短任務**
- 現象：在 16 個訓練任務上表現良好，但無法泛化到長任務或新資源組合。
- 緩解：訓練任務應涵蓋多樣化的資源閾值與序列結構；保留獨立的遷移測試集；必要時加入規則約束（如「必須先有 coal 才能進入下一層」）。

**風險三：LLM 產生不安全或低效程式碼**
- 現象：策略可能無窮迴圈、記憶體洩漏、或繞過模擬器邊界。
- 緩解：在沙箱中執行；設定資源配額（CPU 時間、記憶體）；對產出程式做靜態分析與形式化驗證（若可能）。

**風險四：模擬器與現實落差（sim-to-real gap）**
- 現象：在模擬器中表現優異的策略，部署到真實機器人或真實系統時失效。
- 緩解：在模擬器中加入雜訊與隨機性；保留領域專家審核環節；先在受控環境小規模試點。

**風險五：開發成本高昂**
- 現象：每次 LLM 編輯都需要數千次模擬器評估，API 與運算成本可能快速累積。
- 緩解：使用較小的測試集進行早期篩選，僅對候選編輯做完整評估；快取模擬結果；考慮使用開源 LLM 以降低成本。

**風險六：可解釋性與合規性**
- 現象：雖然程式碼可審核，但 LLM 產生的邏輯可能難以追溯決策依據。
- 緩解：要求 LLM 在每次編輯時附上「變更理由」註解；建立決策日誌；對高風險應用保留人類覆寫機制。

### 與其他技術的整合建議

**與強化學習整合**
- 可將 LLM 演化出的程式策略作為「專家示範」，用於行為克隆或 offline RL 的初始化。
- 反之，RL 訓練出的神經策略可作為「參考基準」，衡量程式策略的效率與可解釋性。

**與經典規劃器整合**
- 將目標編譯器視為「從 PDDL 描述到可執行程式」的橋樑；經典規劃器負責高層次子目標排序，程式策略負責低層次動作執行。
- 對於需要嚴格保證的場景，可在編譯器輸出後接入模型檢查器（model checker）。

**與符號 AI 整合**
- 環境解譯器 I 可與本體論（ontology）系統對接，使信念更新具備語意一致性。
- 規則程式 p₀ 可改寫為可被 Datalog 或 Answer Set Programming 求解的格式，提升形式化驗證的可能性。

**與 MLOps 整合**
- 將「程式碼編輯 → 模擬評估 → 反饋」流程封裝為 CI/CD pipeline，每次策略更新都經過自動化測試。
- 使用 feature store 管理任務描述 Encode(g)，使用 model registry 管理編譯器版本 θ*。

**與監控與可觀測性整合**
- 在部署階段加入分散式追蹤（distributed tracing），記錄每個內部目標 u 的啟用、暫停、放棄事件。
- 將信念 ŷ 與真實狀態 y 的差距作為「模型漂移」指標，觸發編譯器再訓練。

### 給不同背景讀者的閱讀建議

**給初學者**：先讀第 1 節的「問題動機」與圖 1，建立「LLM 寫程式、程式執行時不用 LLM」這個核心分工概念。接著看第 2.1 節的里程碑分解公式，理解為什麼「把大任務切成小樓層」是關鍵。實作上可從一個簡單的網格世界開始，把「到達終點」切成「通過三個房間」，嘗試讓 LLM 寫出能跑完三個房間的 Python 腳本。

**給 AI 工程師**：重點放在第 2 節的「反饋級聯」設計與「延續性評分」ΔF 的實作細節。思考如何把這個框架移植到你手上的模擬器（遊戲、機器人、流程引擎）。特別注意「局部貪婪陷阱」：在 production 環境中，這種「指標看起來變好但實際變差」的現象極為常見，本文的 ΔF 設計值得借鏡。程式碼層面可參考 GitHub repo 中的 C 程式結構與編譯器搜尋腳本。

**給研究者**：本論文在「neuro-symbolic 勞動分工」與「hierarchical RL」之間搭了一座橋。建議延伸閱讀：(1) Sutton 的 options framework，理解內部目標 u 的理論基礎；(2) program synthesis 的近期工作，理解 LLM 在程式碼搜尋空間中的角色；(3) 終身學習與技能重用文獻，理解為什麼「分解為 (I, p₀)」能提升遷移能力。可考慮的研究方向：將延續性評分推廣至非二值獎勵、將編譯器搜尋形式化為 meta-learning 問題、探討反饋級聯的理論收斂性。

**給產品經理**：本框架的核心商業價值是「一次開發、多任務部署」——單一熟練策略可透過編譯器快速客製化為新任務的策略，且部署成本極低（無 LLM 呼叫）。適合需要「可審核、可版本控制、低延遲」決策的場景，例如金融交易規則、客服自動化、工業控制。導入時建議先從「單任務熟練策略」開始驗證 ROI，再投資編譯器訓練。風險方面需特別注意「模擬器與現實落差」與「開發階段的高 LLM 成本」，建議在 POC 階段就建立明確的成本與效能 KPI。
