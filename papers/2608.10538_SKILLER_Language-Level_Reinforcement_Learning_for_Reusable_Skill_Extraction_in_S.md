## ⚡ TL;DR

針對小型開源模型難以直接套用為強大閉源模型設計的智能體技能，導致任務失敗與部署成本高昂。
提出SKILLER，以自然語言強化學習讓強模型擔任actor/critic，生成執行器專屬技能。
於五項基準超越四基線，9B與4B分別提升最高20.4與13.3百分點，單技能任務匹敵閉源強模型。

## 摘要翻譯

智能體技能（Agent skills）是一種用於封裝程序性知識（procedural knowledge）與領域專業知識（domain expertise）的標準化格式，在智能體框架系統（agent harness systems）中作為持續約束語言模型行為空間（behavior space）、以實現可重複且高品質的任務執行（repeatable, high-quality task execution）的重要機制。然而，由於強大的閉源模型（closed-source models）伴隨高昂的推論成本（inference costs），目前流行的智能體框架系統（agent harness systems）（如 Codex 與 OpenClaw）在部署這些技能以完成真實世界任務（real-world tasks）時仍然過於昂貴。可部署於消費級 GPU（consumer-grade GPUs）上的開源模型（open-source models）能力正快速提升，藉由基於技能的行為約束（skill-based behavioral constraints），為大幅降低成本提供了極具吸引力的機會。然而，自動生成專為此類緊湊模型（compact models）量身打造的有效技能，仍然是重大的實務挑戰。為此，我們提出 SKILLER，一個自然語言驅動的強化學習框架（natural-language-driven reinforcement learning framework），旨在自動為小型模型生成執行器專屬技能（executor-specific skills）；該框架以強大模型（strong model）作為行動者（actor）與評論家（critic），將小型智能體系統（small-model agent system）視為環境（environment），並使所有強化學習訊號（reinforcement learning signals）皆完全透過自然語言（natural language）傳播。於五個相關基準測試（five relevant benchmarks）上，使用 Qwen3.5-9B（通義千問 3.5-9B）與 Qwen3.5-4B（通義千問 3.5-4B）進行的廣泛實驗評估顯示，SKILLER 優於三個開源與一個閉源技能生成或演化方法（skill generation or evolution methods），9B 模型的絕對提升幅度（absolute gains）達 4.3 至 20.4 百分點（percentage points），4B 模型則達 1.8 至 13.3 百分點，同時在 SkillsBench 的單技能任務（single-skill tasks）上，其性能與強大閉源模型相當，表現令人矚目。本專案儲存庫（project repository）位於 https://github.com/DANG-ai/SKILLER。

### 核心貢獻（3～5點）
- 提出 SKILLER，一個以自然語言傳遞所有強化學習訊號的語言層級強化學習框架，能自動為小型語言模型生成執行器專屬技能。
- 以強大模型同時擔任行動者與評論家，並將小型智能體系統視為環境，建立自然語言驅動的強化學習迴路。
- 在五個相關基準測試上，使用 Qwen3.5-9B 與 Qwen3.5-4B 進行驗證，相較於三個開源與一個閉源技能生成或演化方法達到顯著絕對提升。
- 在 SkillsBench 單技能任務上，小型模型搭配 SKILLER 生成之技能可匹敵強大閉源模型，同時顯著降低推論成本。

### 適合對象
適合對強化學習、智能體系統、小型語言模型能力增強，以及自動技能生成感興趣的研究人員與工程師；特別是關注如何在消費級 GPU 上部署高性價比自主智能體、降低閉源模型推論成本，或希望將程序性知識封裝為可重複使用技能的實務開發者。

## 深度分析

#### 方法論解析

SKILLER 的核心貢獻在於將「技能（skill）」重新定義為一種可在自然語言空間中最佳化的策略（policy），並以語言層級強化學習（Language-Level Reinforcement Learning）的框架進行自動生成與迭代修正。以下從問題設定、強化學習形式化、以及訓練推論流程三個層面進行解析。

##### 1. 問題設定：執行器專屬的模型錯配問題

在現有的智能體框架系統（agent harness systems）中，agent skills 被視為包裝程序性知識（procedural knowledge）、工具使用慣例（tool-use conventions）與領域專業知識（domain expertise）的標準化格式。這些技能透過行為約束（behavioral constraints）來縮限語言模型的行為空間（behavior space），以達成可重複且高品質的任務執行（repeatable, high-quality task execution）。然而，現行主流框架（如 Codex、ClaudeCode、OpenCode、OpenClaw）多依賴強大的閉源模型（closed-source models），推論成本（inference costs）極高。

相對地，Qwen3.5-9B、Qwen3.5-4B 等開源模型（open-source models）可在消費級 GPU（consumer-grade GPUs）上部署，若能配合適當的技能約束，便有潛力以極低成本完成特定任務。但關鍵障礙在於**執行器錯配（executor mismatch）**：為強大前沿模型（frontier models）設計的技能，無法直接轉移至小型語言模型（small language models）。小型模型容易出現引數幻覺（argument hallucination）、遺漏驗證步驟、或被過度複雜的分支指令牽引而偏離任務。因此，SKILLER 的目標是自動生成「執行器專屬技能（executor-specific skills）」，即針對目標緊湊模型（compact models）的獨特錯誤模式量身打造的技能。

##### 2. 強化學習形式化：以自然語言作為唯一訊號

SKILLER 將傳統的權重更新強化學習轉換為**語言層級策略迭代（language-level policy iteration）**，其形式化可概括如下：

- **策略（Policy）**：即當前的技能文本（skill text）。不同於神經網路權重，此處的策略是可讀、可編輯的自然語言文件，內含步驟、約束、工具呼叫規範與錯誤處理指引。
- **行動者（Actor）**：由強大模型（strong model）擔任，負責根據評論家（critic）的回饋產生技能的修改動作（policy update actions），例如新增驗證步驟、簡化分支邏輯、或重新編排工具呼叫順序。
- **評論家（Critic）**：同樣由強大模型擔任，負責診斷小型智能體系統（small-model agent system）的執行軌跡，並給出診斷性獎勵（diagnostic rewards）與改進建議。
- **環境（Environment）**：即目標小型模型的智能體迴路（agent loop）。該環境在給定任務與當前技能文本後執行動作，並回傳執行結果、中間軌跡與成敗訊號。
- **狀態（State）**：包含任務描述、當前技能版本、以及小型模型在環境中產生的執行軌跡（execution trace）。
- **獎勵（Reward）**：主要以通過率（pass rate）或任務成敗為基礎，並輔以評論家對失敗模式的細粒度診斷，例如「因未檢查檔案是否存在而導致工具呼叫失敗」。

所有強化學習訊號（reinforcement learning signals）——包括狀態、獎勵與策略更新——皆透過結構化自然語言（natural language）傳遞，無需對小型模型進行任何神經權重更新。這使得 SKILLER 能夠在不重新訓練目標模型的前提下，持續調整行為約束。

##### 3. 訓練與推論流程

從論文摘要與引言可推論，SKILLER 的運作流程包含以下階段：

1. **初始技能生成**：行動者根據任務描述與領域知識，產生一份針對目標小型模型的初版技能。此階段會考量緊湊模型的能力邊界，避免產生過度複雜的推理鏈。
2. **環境執行與軌跡收集**：將技能文本餵入小型智能體系統，於目標基準測試（benchmarks）上執行任務，並記錄完整軌跡。
3. **評論家診斷**：評論家分析成功與失敗案例，識別小型模型的特定失敗模式，例如錯誤的引數格式、忽略前置條件、或對模糊指令的過度推論。
4. **策略更新**：行動者根據診斷結果修改技能文本，可能採用漸進式技能揭露機制（progressive skill disclosure），即逐步增加約束細節，避免一次性給予過多資訊而壓垮小型模型。
5. **迭代收斂**：重複執行—診斷—更新循環，直到通過率收斂或達到預算上限。

這種設計的關鍵優勢在於**可解釋性與可轉移性**：由於策略是自然語言，研究者可以直接檢視技能為何有效或無效；同時，針對同一小型模型產生的技能可在相似任務間重複使用，符合可重複使用技能萃取（reusable skill extraction）的目標。

#### 實驗數據解讀

論文在五個相關基準測試（five relevant benchmarks）上進行評估，主要使用 Qwen3.5-9B 與 Qwen3.5-4B 作為目標執行模型，並與三個開源及一個閉源的技能生成或演化方法（skill generation or evolution methods）進行比較。

##### 1. 主要性能提升

實驗結果顯示，SKILLER 在兩個模型尺寸上均帶來顯著的絕對提升幅度（absolute gains）：

- **Qwen3.5-9B**：相較於基線方法，通過率（pass rate）提升 4.3 至 20.4 百分點（percentage points, pp）。
- **Qwen3.5-4B**：提升 1.8 至 13.3 百分點。

這些數據有幾層意義：

- **提升範圍廣泛**：從 1.8 pp 到 20.4 pp 的跨度顯示，SKILLER 的效益在不同任務難度與基線強度下並不一致。在部分任務上，現有方法已能產生尚可的技能，因此提升空間較小；而在模型錯配嚴重的任務上，執行器專屬的優化則帶來大幅改善。
- **小模型同樣受益**：即使 Qwen3.5-4B 的絕對能力較弱，SKILLER 仍能透過更嚴格的行為約束與錯誤處理機制，將其通過率推向可用水準。這印證了「適配的技能可彌補模型規模差距」的核心假設。

##### 2. SkillsBench 單技能任務的成本—性能分析

在 SkillsBench 的單技能任務（single-skill tasks）上，論文展示了引人注目的成本—性能圖（見 Figure 1）：

- **Qwen3.5-9B（SKILLER）** 的輸出價格（output price）比 Opus 4.7 Max 便宜 167 倍，且在特定任務上甚至超越使用精選技能（curated skills）的閉源前沿模型。
- **Qwen3.5-4B（SKILLER）** 比 Haiku 4.5 便宜 71 倍，同樣達到相近或更好的通過率。

這些數字需要謹慎解讀：

- **成本比較的基礎**：此處的成本主要指輸出價格（USD per 1M generated tokens），即模型生成 token 的費用。由於 SKILLER 的執行階段完全由小型模型負擔，推論成本遠低於閉源模型。然而，SKILLER 在訓練階段仍需呼叫強大模型作為行動者與評論家，這部分成本未在圖中呈現。
- **任務範圍限制**：Figure 1 聚焦於單技能任務（single-skill tasks），這類任務的程序性知識相對單純，較容易透過行為約束達成高成功率。對於需要多技能組合或長程規劃的複雜任務，成本優勢是否仍能維持，尚需更多數據支持。
- **「超越閉源模型」的意義**：Qwen3.5-9B 配合 SKILLER 技能後，在特定任務上超過使用精選技能的 Haiku 4.5 與 Sonnet 4.5，這說明當技能與執行器高度匹配時，較小且便宜的模型可以比昂貴模型更有效。這對真實世界任務（real-world tasks）的大規模部署具有重要啟示。

##### 3. 基準測試的多樣性

雖然論文未詳細列出五個基準測試的具體名稱，但從「單技能任務」與「多樣化評估」的敘述可推測，實驗涵蓋了不同領域與難度層級。這有助於驗證 SKILLER 的泛化能力，但讀者仍須注意：

- 若五個基準測試均屬於相似的程序性任務（如程式碼生成、網頁操作），則結果可能無法直接推廣到開放式對話或創意生成等任務。
- 論文未明確報告標準差或統計顯著性檢定，這使得我們難以判斷 4.3–20.4 pp 的提升是否在所有設定下都穩健。

#### 與現有研究的比較

##### 1. 定位於現有智能體技能研究

現有 agent skills 研究大致可分為兩類：

- **人工精選技能（curated skills）**：由領域專家撰寫，針對強大模型設計，如 Anthropic 相關框架所採用的技能格式。這類技能品質高，但成本高、可擴展性差，且無法直接轉移至小型模型。
- **自動技能生成或演化方法（skill generation or evolution methods）**：透過提示工程、搜尋、或演化演算法自動產生技能。這類方法雖然降低了人工成本，但通常產生「通用型」技能，未考慮目標執行器的具體能力與失敗模式。

SKILLER 的定位介於兩者之間：它自動生成技能，但同時針對特定執行器進行最佳化。這是其相較於開源與閉源基線方法的主要區別。

##### 2. 相較於傳統強化學習的創新

傳統強化學習（如 RLHF、PPO）通常透過梯度更新調整模型權重。SKILLER 則提出「語言層級策略迭代」，將策略視為文本而非權重，所有更新皆在自然語言空間中進行。這帶來以下優勢：

- **無需微調目標模型**：對於資源有限的使用者而言，無需收集大量資料或進行昂貴的模型訓練。
- **可解釋的優化過程**：每次策略更新都可被人類閱讀與審查，便於除錯與安全審核。
- **跨模型遷移彈性**：一旦針對某小型模型生成專屬技能，該技能可直接用於相同模型的不同部署實例。

然而，這種方法也有其限制：

- **優化空間受限**：由於不改變模型權重，SKILLER 無法提升小型模型本身的推理能力或知識儲備，僅能透過外部約束引導行為。對於超出模型能力過多的任務，技能再精緻也難以彌補根本能力不足。
- **依賴強大模型的診斷品質**：行動者與評論家的表現直接決定生成技能的品質。若強大模型無法準確診斷小型模型的失敗原因，則迭代可能收斂至次優解。
- **訓練階段成本仍高**：雖然執行階段便宜，但生成與優化技能仍需多次呼叫閉源前沿模型，對於需要頻繁適應新任務的場景，總成本可能不容忽視。

##### 3. 與現有開源框架的關係

論文提及 Codex、OpenClaw、OpenCode 等框架，這些框架多強調「以強大模型為核心」的執行範式。SKILLER 則提供了一種「降本增效」的替代路徑：利用強大模型作為離線的 skill engineer，而將實際執行交給小型模型。這與近期「模型級聯（model cascading）」與「推理時運算最佳化」的研究趨勢一致，但更進一步將優化焦點放在可重複使用的技能文本上。

#### 可重現性評估

##### 1. 開源資源

論文指出專案儲存庫（project repository）位於 https://github.com/DANG-ai/SKILLER。若該儲存庫包含以下內容，則可重現性較高：

- 完整的 SKILLER 框架程式碼，包括行動者、評論家與環境介面。
- 用於五個基準測試的評估腳本與資料前處理流程。
- 針對 Qwen3.5-9B 與 Qwen3.5-4B 的預設提示模板（prompt templates）與超參數。
- 生成的執行器專屬技能樣本，供研究者直接驗證。

##### 2. 模型權重與 API 可得性

- **目標模型**：Qwen3.5-9B 與 Qwen3.5-4B 為開源模型，權重可公開取得，可在消費級 GPU 上執行，這部分可重現性良好。
- **強大模型**：作為 actor 與 critic 的模型（如 GPT-5.5、Claude Opus 4.8）屬於閉源模型，需透過 API 呼叫。若論文未來公開實驗所使用的具體模型版本、API 參數與呼叫次數，則其他研究者較能複製結果；反之，則可重現性會受 API 行為變動影響。

##### 3. 潛在可重現性挑戰

- **未來模型與引用**：論文引用多個標示為 2026 年的文獻與模型版本（如 Qwen3.6、Gemma 4、GPT-5.5），在當前時間點這些資源可能尚未公開或不存在，這對立即複製實驗構成障礙。
- **漸進式技能揭露機制細節**：引言中提及的 progressive skill disclosure mechanism 在提供的片段中未完整說明，若儲存庫未詳細記載其實作，則難以完全重現。
- **隨機性與種子設定**：大型語言模型（LLM）的輸出具有隨機性，若論文未固定隨機種子並報告多次運行的變異，則單次實驗結果可能難以穩定複製。

整體而言，SKILLER 的可重現性高度依賴 GitHub 儲存庫的完整度與所使用閉源 API 的穩定性。目標小型模型開源是一大優勢，但強大模型的黑箱特性仍是主要不確定因素。

#### 未來研究方向

基於 SKILLER 的框架設計與實驗結果，以下幾個方向值得進一步探索：

##### 1. 多技能組合與長程規劃

目前實驗主要聚焦單技能任務（single-skill tasks）。未來可研究如何將多個執行器專屬技能組合，以處理需要跨領域工具協作與長程規劃的複雜任務。這涉及技能之間的依賴關係建模、執行順序排程，以及失敗時的動態技能切換。

##### 2. 評論家模型的輕量化

SKILLER 目前依賴強大閉源模型作為評論家，這在訓練階段仍具成本。未來可嘗試將評論家的診斷能力蒸餾（distillation）到較小的開源模型中，甚至讓目標小型模型具備自我診斷能力，以進一步降低整體成本。

##### 3. 視覺—語言技能的擴展

論文提及大型視覺—語言模型（LVLMs），但實驗似乎以語言任務為主。未來可將 SKILLER 擴展至視覺輸入，例如生成針對圖表理解、網頁截圖操作或機器人視覺導航的執行器專屬技能。

##### 4. 線上適應與持續學習

現有框架可能以離線批次方式優化技能。未來可研究線上適應機制，使智能體在部署過程中持續收集失敗案例，並即時更新技能文本，以應對環境變化與新任務類型。

##### 5. 自動獎勵建模與多目標最佳化

目前獎勵主要基於通過率與診斷回饋。未來可引入更細緻的獎勵函數，例如執行步驟數、API 呼叫成本、回應延遲與安全性指標，進行多目標最佳化，以產生在效率與正確性之間取得平衡的技能。

##### 6. 技能的可解釋性與安全審計

由於技能文本本身可讀，未來可發展自動化的安全審計工具，檢查生成的技能是否包含潛在的偏見、錯誤假設或危險行為模式，特別是在涉及程式碼執行與外部工具呼叫的場景。

##### 7. 跨模型族群的技能遷移

SKILLER 針對特定小型模型生成專屬技能。未來可研究如何將為 Qwen3.5-9B 生成的技能遷移至其他模型族群（如 Gemma 4 或 Llama 系列），並透過少量適應步驟快速產生對應的執行器專屬版本。

總結來說，SKILLER 為「以自然語言作為優化媒介」的智能體技能生成開闢了一條新途徑，其核心價值在於將強大模型的診斷能力轉化為小型模型可執行、可重複使用且成本低廉的行為約束。未來研究若能解決多技能組合、評論家輕量化與線上適應等挑戰，將有機會讓這一範式在更廣泛的真實世界任務中落地。

## 論文問答

**Q1：SKILLER 主要解決什麼問題？**
A：SKILLER 旨在解決如何為小型語言模型自動生成執行器專屬技能的問題。當前流行的智能體框架系統（如 Codex 與 OpenClaw）多依賴強大的閉源模型，導致推論成本極高，難以大規模部署於真實世界任務。雖然開源緊湊模型可部署於消費級 GPU 並顯著降低成本，但為其量身打造、可重複使用且高品質的技能仍是一大實務挑戰。因此，SKILLER 透過語言層級強化學習，自動萃取能約束小型模型行為空間的有效技能。

**Q2：為何現有為強大閉源模型設計的技能無法直接轉移至小型模型？**
A：這主要是因為存在嚴重的模型不匹配問題。為強大閉源前沿模型設計的行為約束、隱含推理步驟與錯誤恢復假設，對於緊湊模型往往過於複雜或不完備。小型語言模型容易出現參數幻覺、跳過必要驗證步驟，或被包含多個分支路徑的繁複指令帶偏。因此，直接移植高階技能到小型模型經常導致災難性的任務失敗。

**Q3：為小型模型生成專屬技能為何重要？**
A：為小型模型生成專屬技能能大幅降低部署成本，使自主智能體可在消費級 GPU 上運行。這不僅讓真實世界任務的大規模應用變得經濟可行，也減少對昂貴閉源模型的依賴。此外，良好的技能約束能持續限制小型模型的行為空間，確保任務執行的可重複性與高品質。這對於推動智能體技術的普及與落地具有關鍵意義。

**Q4：SKILLER 的核心方法架構為何？**
A：SKILLER 是一個自然語言驅動的強化學習框架，將文字形式的技能視為可最佳化的策略。它使用強大模型同時擔任行動者與評論家，並將小型智能體系統視為強化學習環境。所有強化學習訊號，包括狀態、診斷獎勵與策略更新動作，都完全透過結構化自然語言傳遞。這種設計讓框架能在不更新任何神經網路權重的情況下，反覆診斷並修復小型模型的獨特失敗模式。

**Q5：SKILLER 的關鍵創新是什麼？**
A：其關鍵創新在於提出語言層級策略迭代機制，把技能本身當作可最佳化的政策而非固定提示。不同於傳統強化學習更新模型權重，SKILLER 僅透過自然語言回饋迴路來診斷、修復並精煉技能內容。這種方法能有效彌合模型不匹配差距，針對緊湊模型的行為特性生成量身打造的約束。最終產出的執行器專屬技能無需微調目標模型，即可顯著提升其任務執行表現。

**Q6：SKILLER 有哪些重要的設計選擇？**
A：首先，SKILLER 採用漸進式技能揭露機制，避免小型模型因一次接收過多資訊而失焦。其次，它選用當代前沿強大模型作為行動者與評論家，以確保診斷與修復的品質。再者，所有狀態與獎勵訊號皆以結構化自然語言編碼，使強化學習過程對人類可解釋且易於除錯。這些選擇共同確保了技能生成過程的穩定性與可解釋性。

**Q7：實驗使用了哪些基準測試與模型？**
A：研究團隊在五個相關基準測試上進行廣泛評估，並以 SkillsBench 作為單技能任務的主要評測場景。目標執行模型選用開源的 Qwen3.5-9B 與 Qwen3.5-4B，這兩個緊湊模型均可部署於消費級 GPU。透過與三個開源及一個閉源技能生成或演化方法比較，實驗涵蓋了多樣化的任務類型與難度。這樣的設計能充分驗證 SKILLER 在不同規模小型模型上的泛化能力。

**Q8：SKILLER 取得了哪些關鍵實驗結果？**
A：SKILLER 在兩個目標模型上均顯著超越所有基線方法，Qwen3.5-9B 的絕對提升幅度達 4.3 至 20.4 百分點，Qwen3.5-4B 則達 1.8 至 13.3 百分點。更值得注意的是，在 SkillsBench 的單技能任務中，配備 SKILLER 技能的 Qwen3.5-9B 甚至能與使用精選技能的強大閉源模型性能相當。成本分析顯示，Qwen3.5-9B 搭配 SKILLER 可比 Claude 前沿模型便宜 167 倍，而 Qwen3.5-4B 也可便宜 71 倍。這些結果證明，執行器專屬技能能讓低成本小型模型在特定任務上匹敵高價閉源方案。

**Q9：實驗進行了哪些比較與消融分析？**
A：實驗將 SKILLER 與三個開源技能生成或演化方法以及一個閉源方法進行系統性比較，涵蓋單技能與多樣化任務情境。除了通過率比較，研究也進行成本效益分析，繪製輸出價格與任務通過率的關係圖。結果顯示無論在 9B 或 4B 模型上，SKILLER 都持續優於基線。這凸顯了語言層級強化學習與執行器專屬設計對技能品質的關鍵貢獻。

**Q10：SKILLER 適合哪些實際應用場景？**
A：SKILLER 特別適合需要重複執行、程序性知識明確的真實世界任務，例如資料處理、表單填寫、程式碼輔助與工具調度等。在這些場景中，透過技能約束小型模型的行為空間，可確保每次執行都遵循相同步驟與領域專業知識。由於目標模型可運行於消費級 GPU，企業與個人開發者都能以低成本部署穩定的智能體服務。這使其成為高頻率、成本敏感型應用的理想選擇。

**Q11：在產品化過程中需要考慮哪些因素？**
A：產品化時需權衡模型規模、輸出價格與任務複雜度，選擇最適合的 Qwen3.5-9B 或 Qwen3.5-4B 作為執行器。同時，技能庫需要持續維護與版本控制，因為真實世界任務的介面與規範會不斷演變。此外，雖然 SKILLER 降低了對閉源模型的依賴，但仍需前沿模型作為行動者與評論家，因此整體成本與延遲仍需納入評估。最後，應建立監控機制以追蹤技能在生產環境中的通過率與失敗模式。

**Q12：SKILLER 對智能體領域可能帶來什麼影響？**
A：SKILLER 展示了透過執行器專屬技能，小型開源模型也能在特定任務上達到甚至超越昂貴閉源模型的效果。這有助於打破目前智能體框架系統對閉源前沿模型的依賴，促進更開放、可負擔的智能體生態系統。同時，它推動了可重複使用技能萃取的研究，使程序性知識與領域專業知識能更廣泛地共享與再利用。長遠來看，這可能加速自主智能體在各行各業的普及。

A：從實驗結果來看，SKILLER 在單技能任務上表現尤為突出，但對於需要多項技能協同或高度開放推理的複雜任務，其優勢可能較不明顯。此外，技能生成過程仍依賴強大模型作為行動者與評論家，這意味著訓練階段的計算與 API 成本仍然存在。若目標任務的失敗模式過於多樣或超出小型模型的基本能力，語言層級修復也可能遇到瓶頸。這些都是未來研究需要進一步克服的課題。

A：當任務需要大量常識推理、長程規劃或動態適應未預期情境時，小型執行模型可能難以遵循技能完成任務。如果生成的技能過於複雜、包含過多分支路徑，或與小型模型的理解能力不匹配，也可能導致執行失敗。此外，當環境回饋稀疏或錯誤訊號不明確時，評論家難以提供有效的診斷獎勵，進而影響策略迭代效果。這些情況都凸顯了為執行器量身打造技能的重要性。

A：未來可探索多技能組合與協作機制，使 SKILLER 能處理更複雜的多步驟任務。另一方向是將框架擴展至更大規模的開源模型或其他模態，例如大型視覺語言模型，以驗證其通用性。此外，可研究自動化技能庫管理與終身學習，讓智能體能隨時間累積並更新程序性知識。最後，結合更細緻的獎勵模型與多輪對話診斷，有望進一步提升語言層級強化學習的效率與穩定性。

- 目標小型模型（如 Qwen3.5-9B 或 Qwen3.5-4B）可在消費級 GPU（如單張 24GB VRAM）上部署與推論。
- 強大模型（如 GPT-5.5 或 Claude opus 4.8）的 API 存取權限，作為 actor 與 critic；需預留足夠預算，因為訓練階段會產生大量自然語言互動。
- 可執行代理迴路（agent loop）的環境，例如 OpenClaw 或自製 harness。

**技能與知識前提**
- 熟悉提示工程（prompt engineering）與智能體框架系統（agent harness systems）的基本運作。
- 了解強化學習中 actor-critic 架構的概念，但不需要具備模型微調或 RLHF 的實作經驗。
- 具備目標領域的領域專業知識，以便設計合理的診斷規則與獎勵函數。

### 實作步驟建議

1. **界定任務範圍與評測基準**  
   選擇一個或多個單技能任務，建立對應的 SkillsBench 風格評測集，並設定目標通過率與成本上限。

2. **建立小型智能體系統作為環境**  
   將 Qwen3.5-9B 或 Qwen3.5-4B 接入代理迴路，設定工具使用慣例與觀察格式，確保環境能回傳執行狀態、錯誤訊息與最終結果。

3. **準備初始技能與執行軌跡**  
   使用現有精選技能或人工撰寫的種子技能啟動 SKILLER，並收集首批執行軌跡，涵蓋成功、失敗與邊界案例。

4. **執行語言層級策略迭代**  
   讓強大模型擔任 actor 生成技能變體，並由 critic 根據環境回饋進行診斷與獎勵評分。所有強化學習訊號（狀態、診斷獎勵、策略更新動作）均以結構化自然語言傳遞。

5. **驗證與收斂判斷**  
   在獨立驗證集上評估每次迭代產生的技能，監控絕對提升幅度（absolute gains）與過擬合跡象，選擇在驗證集上表現最穩定的技能版本。

6. **漸進式技能揭露與部署**  
   在生產環境中採用漸進式技能揭露機制，避免一次給予小型模型過多複雜指令；同時建立監控機制，持續收集失敗案例以供下一輪迭代。

### 潛在風險與注意事項

- **模型錯配（model mismatch）**  
  為強大模型設計的技能無法直接轉移到小型模型。解決方式是讓 SKILLER 以目標緊湊模型為環境，直接針對其獨特失敗模式進行診斷與修復。

- **自然語言獎勵的獎勵駭取（reward hacking）**  
  Critic 可能過度關注表面格式而忽略任務本質。建議結合自動化單元測試與人工抽樣審查，避免技能僅在評測指標上取巧。

- **強大模型 API 成本累積**  
  雖然部署階段使用小型模型可降低成本，但訓練階段仍需大量呼叫 actor/critic。建議設定每日呼叫預算、使用快取機制，並優先針對高價值任務進行技能萃取。

- **技能膨脹與延遲**  
  迭代過程中技能可能越來越長，導致小型模型推論延遲增加。應定期壓縮技能內容，並限制單次揭露的技能數量。

- **安全與幻覺風險**  
  小型模型仍可能產生幻覺引數或跳過驗證步驟。建議在技能中強制加入驗證步驟、工具呼叫確認與人類監督閘門。

  將生成的技能儲存於向量資料庫中，依任務語意進行檢索，再透過漸進式技能揭露機制餵給小型模型，提升多工場景的靈活性。

- **CI/CD 與自動化測試**  
  將 SKILLER 的評估流程整合進持續整合管線，每次更新技能後自動執行 SkillsBench 或內部基準測試，確保技能品質不回退。

- **可觀測性與人類回饋迴路**  
  搭配日誌追蹤、執行軌跡視覺化與人類在環（human-in-the-loop）審查，將真實世界任務中的失敗案例回流至 SKILLER，形成持續改善閉環。

- **混合部署架構**  
  對於複雜多步驟任務，可將 SKILLER 優化後的小型模型用於常見單技能任務，僅在少數困難案例上呼叫 Claude frontier 或 Qwen frontier，兼顧成本與性能。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從「適用場景」與「實作前置條件」讀起，理解 SKILLER 如何讓小型語言模型變得更便宜且更可靠；接著參考「實作步驟建議」中的六步流程，建立一個簡單的單技能任務原型，不必一開始就深入 actor-critic 的數學細節。

**AI 工程師**  
重點閱讀「實作步驟建議」與「與其他技術的整合建議」，關注如何將 SKILLER 接入現有 agent harness、如何設計結構化自然語言的狀態與獎勵格式，以及如何透過快取與預算控制降低強大模型 API 成本。

**研究人員**  
建議聚焦於語言層級強化學習的設計：將文字技能視為可優化策略、以自然語言傳播所有強化學習訊號，並思考這種無神經權重更新的方法與傳統 RLHF、提示優化（prompt optimization）及技能演化方法之間的理論關聯與限制。

**產品經理**  
請優先參考「適用場景」與「潛在風險與注意事項」，評估哪些真實世界任務最適合以 SKILLER 搭配小型模型落地，並在規劃時預留強大模型 API 的訓練預算、建立人類監督機制，以及設計成本—性能權衡的商業模型。
