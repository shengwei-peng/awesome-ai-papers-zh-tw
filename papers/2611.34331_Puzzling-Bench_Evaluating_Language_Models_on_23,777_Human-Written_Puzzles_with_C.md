## 摘要翻譯

我們推出 Puzzling-Bench，這是一個包含 23,777 道附帶社群驗證答案（community-verified answers）的謎題基準，題目來源為 Puzzling Stack Exchange 檔案庫（2014-2026）：謎語（riddles）、密碼（ciphers）、邏輯方陣（logic grids）、橫向思考題（lateral-thinking problems）、文字遊戲（wordplay）與趣味數學（recreational mathematics），其中三分之一附有圖像。每道謎題皆附有作者認可答案（author-accepted answer）、從作者認可答案中擷取的簡短參考答案（short reference answer；評估集採用 LLM 提取，並以 50 道謎題進行人工審核驗證）、作者自身的劇透標記提示（spoiler-tagged hints）、社群標籤（community tags）與創建日期，使該基準得以支援有／無提示消融（with/without-hint ablation）與類別分析（category analysis），並提供作為污染檢查（contamination check）的滾動式截止後切片（rolling post-cutoff slice；254 道發布於我們所評估的九個模型中，有六個（含最佳模型）訓練截止日之後的謎題）。我們以雙層評分器（two-tier scorer；標準化精確匹配 normalized exact match，再交由 LLM 評審 LLM judge）評估九個前沿模型（frontier models）與開源模型（open models），並透過來自兩個模型家族的三位評審來驗證 LLM 評審的可靠性：其判定結果（verdicts）一致率達 95-97%（Cohen's kappa 係數 0.82-0.96），任一模型的分數變動不超過 1.6 分，且未呈現同家族偏好（own-family preference）。最佳模型 GPT-6.1 在共享的 255 題謎題集上達到 74.8%；一組由 17 題謎題構成的困難核心（hard core）擊敗全部九個模型；模型間的失誤高度相關，且次佳模型僅為貪婪集成（greedy ensemble）貢獻一道謎題，不過橫跨全部九個模型的理想模型（oracle）可達 91%。在 100 題的多模態試點（multimodal pilot）中，圖像剝離對照（image-withheld control）使兩個最佳模型分別損失 24 與 35 分。我們公開資料集、評分流程（scoring pipeline）及所有逐列溯源（per-row provenance）。

## 深度分析

#### 方法論解析

Puzzling-Bench 的方法論核心在於將 Puzzling Stack Exchange 這個非典型的「問答」社群轉化為高品質推理評估基準。整體設計可分為四個環節：資料篩選、結構化欄位萃取、評分管線（scoring pipeline）設計，以及污染防護機制。

**資料篩選與驗證訊號的取得**

研究團隊採用 2026-06-30 的公開資料轉存（data dump），原始資料包含 30,526 個問題、69,546 個答案與 264,562 則留言。篩選漏斗（filtering funnel）分三階段：剔除被版主關閉的問題（2,694 筆，8.8%）、剔除無作者認可答案（author-accepted answer）的問題（4,054 筆，13.3%）、剔除答案缺失的問題（1 筆），最終保留 23,777 題（77.9%）。此設計的關鍵洞見在於：Puzzling Stack Exchange 的提問者（asker）通常已知答案並以此作為挑戰題（challenge）發布，因此「被接受的答案」實質上等同於作者驗證過的標準答案（ground truth），這與一般 Stack Overflow 的求助情境截然不同。據站內資深用戶估計，認可答案的正確率約達 99%，且約 5% 的題目存在多重有效答案。

**結構化欄位設計**

每筆保留的謎題包含六類資訊：標題、題幹（HTML 轉純文字，圖片以 `[image: alt-text]` 佔位符替代）、作者自寫的劇透標記提示（spoiler-tagged hints，20% 的題目有此欄位）、被接受的完整答案、簡短參考答案（short reference answer）、社群標籤（community tags，共 201 種）以及創建日期（creation dates）。圖片方面，原始資料中 42,642 個獨立圖片 URL 有 42,566 個成功抓取（99.8%），最終釋出集中包含 28,825 張圖片。這種結構化設計支援三類下游分析：提示消融（hint ablation）、類別分析（category analysis），以及按發布期間（posting period）切片的時序分析。

**參考答案萃取與驗證**

評估集採用 LLM 從完整認可答案中萃取簡短參考答案，並以 50 題人工審核（human review）作為品質檢核。這是因為完整答案往往冗長且包含解題過程，直接用於精確匹配會產生大量假陰性。

**雙層評分器（two-tier scorer）**

評分流程採兩階段設計：第一階段為標準化精確匹配（normalized exact match），處理大小寫、標點與空白變異；第二階段為 LLM 評審（LLM judge），處理語意等價但表述不同的情況。實驗顯示精確字串匹配（exact string match）僅能捕捉 45–60% 的正確答案，其餘仰賴 LLM 評審。

**評審驗證機制**

為避免 LLM 評審的偏誤，研究採用三項嚴格驗證：(1) 使用三個來自兩個模型家族的評審進行交叉檢驗，達成 95–97% 的判定一致性（verdicts agreement），Cohen's kappa 介於 0.82–0.96；(2) 確認三個評審「可互換」（interchangeable），任一評審替換都不會使任何模型的得分移動超過 1.6 分；(3) 直接測量同家族偏好（own-family preference），確認評審不會傾向自家模型的輸出。這套驗證流程回應了 Tan 等人 (2025) 與 Panickssery 等人 (2024) 對 LLM 評審可靠性的質疑。

**污染檢查（contamination check）設計**

由於基準包含 2014 至 2026 年的題目，研究團隊利用訓練截止日（training cutoff）切出 254 題「截止後」（post-cutoff）子集，作為九個模型中六個的污染檢查。此切片設計為「滾動式」（rolling），隨每季新資料轉存更新，是靜態基準中嵌入時序防護的巧妙折衷。

#### 實驗數據解讀

**整體模型排名**

在 255 題共享評估集上，GPT-6.1 以 74.8% 居首，Claude Opus 5.5 以 66.1% 居次。這個 8.7 個百分點的差距在當前前沿模型（frontier models）橫向比較中屬於顯著差距，顯示謎題推理仍是區分模型能力的重要維度。

**困難核心（hard core）現象**

17 題構成的「困難核心」同時擊敗全部九個模型，這個數字本身揭示了兩個訊息：(1) 基準中存在足夠的鑑別度天花板，避免飽和；(2) 這 17 題很可能代表了需要特定領域知識或多步驟橫向思考（lateral thinking）才能突破的題型，可作為未來模型改進的具體目標。

**模型失敗的相關性與互補覆蓋（complementary coverage）**

九個模型的失敗高度相關，但理想模型（oracle，即取九模型聯集）可達 91%。這個 16.2 個百分點的「理想模型紅利」說明：(1) 當前前沿模型在謎題推理上呈現系統性瓶頸，而非隨機失敗；(2) 不同模型確實存在互補優勢。然而貪婪集成（greedy ensemble）實驗顯示，第二佳模型僅貢獻 1 題，意味著互補覆蓋主要來自「前代模型」（previous-generation model）而非當前第二名，這暗示前沿模型之間的差異化正在收斂。

**多模態試點（multimodal pilot）的關鍵發現**

100 題多模態試點中，剝離圖像（image-withheld control）使兩個最佳模型分別損失 24 與 35 個百分點。這個巨大的落差有三層意涵：(1) 基準中三分之一的圖像承載了實質解題資訊，並非裝飾；(2) 純文字模型在此基準上會嚴重失真，必須以多模態模型評估；(3) 圖像理解能力是當前模型差異化的重要面向。

**方法論層面的兩個關鍵發現**

第一，超時記錄（timed-out rows）並非隨機缺失（missing at random），會系統性地膨脹（inflate）慢速模型的準確率。這是因為超時的往往是困難題目，慢速模型在這些題目上「不答」反而避免了錯誤懲罰，使表面分數虛高。第二，參考答案的選擇對最終分數的影響與評審選擇相當。這意味著基準的可信度不僅取決於評審，也取決於參考答案的萃取品質，兩者必須共同設計。

**精確匹配的覆蓋率**

精確字串匹配僅捕捉 45–60% 的正確答案，這個數字本身是評分管線設計的關鍵論證：若僅依賴字串匹配，將低估模型能力約一半，並誤判模型間的相對排名。

#### 與現有研究的比較

**相較於通用推理基準的定位**

Puzzling-Bench 與 BIG-bench、GSM8K、MATH、ARC、Humanity's Last Exam 等基準形成互補而非競爭關係。BIG-bench 涵蓋面廣但缺乏深度謎題類型；GSM8K 與 MATH 聚焦於算術應用題（arithmetic word problems）與競賽數學（competition mathematics），屬於單一推理維度；ARC 強調抽象視覺模式；Humanity's Last Exam 仰賴專家撰寫，題目成本高且更新慢。Puzzling-Bench 的獨特價值在於：(1) 題目由業餘愛好者為彼此設計，更接近「自然推理」而非考試題型；(2) 涵蓋謎語（riddles）、密碼（ciphers）、邏輯方陣（logic grids）、橫向思考題（lateral-thinking problems）、文字遊戲（wordplay）、趣味數學（recreational mathematics）等多元類型；(3) 規模達 23,777 題，遠超多數專項基準。

**相較於專項謎題基準的整合優勢**

既有謎題基準多採單一類型：Lin 等人 (2021) 與 Jiang 等人 (2023) 處理選擇題謎語；Huang 等人 (2024) 處理互動式橫向思考；Lin 等人 (2025) 處理生成的邏輯方陣；Rozner 等人 (2021)、Efrat 等人 (2021)、Sadallah 等人 (2024)、Saha 等人 (2025) 處理密語填字遊戲（cryptic crosswords）；Todd 等人 (2024) 與 Samdarshi 等人 (2024) 處理紐約時報 Connections 遊戲；Zhao 與 Anderson (2023)、Wu 等人 (2025) 處理 NPR 週日謎題。多模態謎題方面，Chia 等人 (2024) 處理抽象視覺模式、Gritsevskiy 等人 (2024) 處理 rebuses、Li 等人 (2026) 處理拼圖、Wang 等人 (2025) 處理謎題競賽。Puzzling-Bench 以單一基準整合上述所有類型，並附加提示、標籤、時間戳，是目前最全面的謎題評估資源。

**相較於活體基準的時序設計**

White 等人 (2025)、Jain 等人 (2025)、Vu 等人 (2024) 等活體基準透過持續更新題目對抗污染。Puzzling-Bench 採靜態但標記日期的折衷：基準本身不更新，但每季資料轉存提供新的截止後切片，使評估可在不重建基準的情況下持續監測污染程度。這對資源有限的研究團隊是務實的設計選擇。

**相較於 LLM 評審文獻的方法論貢獻**

Zheng 等人 (2023) 開啟 LLM 評審的系統化研究，但後續工作（Tan et al., 2025; Panickssery et al., 2024; Wataoka et al., 2024; Fang et al., 2026）揭示其在困難客觀題上的不可靠性與自偏好問題。Puzzling-Bench 將評審限制在「答案等價性」二元決策、報告三評審一致性、直接測量同家族偏好，是對這些批評的具體回應。

**限制與不足**

(1) 5% 的多重有效答案未處理，可能低估真實準確率；(2) 圖像僅 99.8% 抓取率，遺失 76 張；(3) 參考答案萃取仰賴 LLM，雖經 50 題人工驗證但樣本量有限；(4) 評估集僅 255 題共享子集，統計檢力受限；(5) 9 個模型中僅 6 個有截止後切片，無法對全部模型做污染檢查。

#### 可重現性評估

**資料釋出完整性**

研究團隊明確釋出三項資產：基準資料集（23,777 題）、評分流程（scoring pipeline）、每行溯源（per-row provenance）。資料採用 CC BY-SA 授權，與 Stack Exchange 原始授權一致，並保留發文識別碼與作者署名欄位，符合學術引用規範。圖像方面，99.8% 的抓取率與 Stack Exchange Image Dataset (Dernoncourt, 2023) 形成互補，2023-12-08 前的圖像另有歸檔。

**評分流程的可重現性**

### 潛在風險與注意事項

**風險一：逾時記錄非隨機缺失，會膨脹慢速模型的準確率**
- **現象**：推理時間較長的模型可能在困難題目上逾時而被排除，這些被排除的題目往往正是模型會答錯的題目，導致最終準確率被高估
- **緩解**：將逾時記錄視為「答錯」而非「缺失」；報告中同時呈現「含逾時」與「排除逾時」兩種準確率；為慢速模型設定更長的逾時上限或使用推測解碼（speculative decoding）加速

**風險二：參考答案選擇對評分結果影響極大**
- **現象**：論文明確指出「參考答案的選擇與評審的選擇同樣關鍵」，簡短參考答案的抽取方式會直接影響精確匹配率
- **緩解**：使用 LLM 提取參考答案後，進行人工抽樣審核（建議至少 50 題）；對同一題目準備多個等價參考答案；評審 prompt 中提供完整作者認可答案作為對照基準

**風險三：LLM 評審存在同家族偏好與不可靠性**
- **現象**：評審模型可能偏好自己家族模型的輸出（own-family preference），或在困難客觀題上表現不穩定
- **緩解**：使用至少兩個不同家族的評審模型；計算 Cohen's kappa 驗證一致性；對評審結果進行抽樣人工核對；限制評審任務為單純的「答案等價性」二元判斷

**風險四：基準資料的污染風險**
- **現象**：雖然 Puzzling-Bench 提供截止後切片，但模型可能在訓練過程中已接觸過 Stack Exchange 公開資料
- **緩解**：定期更新截止後切片（每季度一次）；結合多個時間點的切片進行趨勢分析；對模型在截止前後的表現差異進行統計檢定

**風險五：圖像版權與可存取性**
- **現象**：基準中三分之一的題目包含圖像，部分圖像 URL 可能失效或涉及第三方授權
- **緩解**：使用基準提供的本地圖像副本（28,825 張已下載）；建立圖像健康檢查機制；對外發布評估結果時注意圖像歸屬

**風險六：多答案題目的處理限制**
- **現象**：約 5% 的題目存在多個有效答案，但基準目前僅以作者認可答案為唯一標準
- **緩解**：在評審 prompt 中明確告知「可能存在其他有效答案」；對低信心評分進行人工覆核；追蹤後續多答案處理的改進工作

- 將 Puzzling-Bench 評估流程整合至 MLflow、Weights & Biases 等實驗追蹤平台
- 建立模型版本發布前的自動評估關卡（CI gate），確保新版本不會在推理能力上發生顯著回歸
- 結合 LangSmith、LangFuse 等 LLM 觀測工具，追蹤每題的推理鏈與失敗模式

**與紅隊與安全測試的整合**
- 將「困難核心」17 題作為紅隊測試案例庫，用於壓力測試新模型
- 利用「模型失敗高度相關」的特性，建立基準化的對抗測試套件
- 與 HarmBench、AdvBench 等安全基準組合，進行綜合能力與安全性評估

**與多模態管線的整合**
- 將 Puzzling-Bench 的多模態試點集整合至 VLM 評估流程（例如 LLaVA、Qwen-VL、GPT-4V 等的比較）
- 利用「圖像剝離對照」實驗設計，量化 OCR、視覺推理、跨模態理解等子能力
- 與 MMMU、MMStar 等多模態基準組合，建立完整的視覺語言模型評估體系

**與教育科技產品的整合**
- 將 Puzzling-Bench 作為題庫來源，透過 LLM 評審機制建立自動化評分系統
- 利用「提示消融」功能設計漸進式學習體驗（先給提示，再逐步撤除）
- 結合適性學習演算法，根據學生答題表現推薦對應難度的題目

**與資料管線的整合**
- 將 Puzzling-Bench 的資料處理流程（HTML 轉純文字、圖像下載、參考答案提取）模組化，作為 Stack Exchange 資料處理的參考實作
- 整合至 ETL 管線，定期從 Puzzling Stack Exchange 拉取新題目並更新評估集
- 與資料品質監控工具（例如 Great Expectations）整合，確保資料完整性

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節（Introduction），理解 Puzzling-Bench 的核心動機——為什麼「謎題」是測試 LLM 推理能力的好材料。接著跳讀第 3.1–3.2 節，了解資料來源與篩選流程，建立對基準規模與品質的基本認識。第 6 節的四個主要發現（精確匹配的侷限性、困難核心的存在、模型失敗的相關性、圖像的關鍵角色）是最直觀的結論，適合快速掌握基準的價值。實作上，初學者可以先從 255 題共用集開始，使用 API 呼叫 GPT-6.1 或 Claude Opus 5.5，體驗完整的評估流程。

**給 AI 工程師**：重點關注第 3 節（資料集建構細節）、第 4 節（評分管線設計）與第 6.4 節（逾時記錄的非隨機缺失問題）。工程師應特別注意「雙層評分器」的實作細節——精確匹配的標準化規則、LLM 評審的 prompt 工程、以及如何處理多答案題目。此外，第 5.4 節的多模態試點設計提供了「圖像剝離對照」的實驗範本，可直接應用於自家 VLM 的能力評估。建議將評估流程容器化並整合至 CI/CD，以支援模型迭代時的自動回歸測試。

**給研究者**：第 2 節（Related Work）提供了完整的推理基準與 LLM 評審文獻脈絡，第 6.1 節（評審驗證）與第 6.2 節（參考答案選擇的影響）是方法論上的重要貢獻，適合深入研讀並引用。「模型失敗高度相關」與「困難核心」17 題的發現，對研究模型互補性、集成學習與失敗模式分析具有啟發意義。研究者可進一步探索：困難題目的共同特徵、模型失敗的語義聚類、以及如何利用截止後切片建立更嚴格的污染檢測協議。此外，基準的「時間軸」特性為研究「資料污染對基準效度影響」提供了難得的實驗材料。

**給產品經理**：建議先閱讀摘要的四個主要發現，理解 Puzzling-Bench 能為產品決策提供哪些洞察。對產品選型而言，255 題共用集的排名（GPT-6.1 74.8%、Claude Opus 5.5 66.1%）提供了前沿模型的相對能力參考；「理想模型 91%」的數據則說明了多模型集成的潛在價值。對產品設計而言，「圖像貢獻 24–35 分」的發現提醒我們：在設計多模態產品時，視覺管線的品質至關重要；「提示消融」功能可作為漸進式教學或難度調節的設計工具。對風險管理而言，「逾時記錄非隨機缺失」與「LLM 評審同家族偏好」是部署 LLM 評估系統時必須注意的陷阱。建議將 Puzzling-Bench 納入產品上線前的標準評估流程，特別是涉及推理、創意或多模態能力的場景。
