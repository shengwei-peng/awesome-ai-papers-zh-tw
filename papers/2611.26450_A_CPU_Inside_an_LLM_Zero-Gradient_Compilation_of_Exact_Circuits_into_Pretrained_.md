## 深度分析

#### 方法論解析

本論文提出一種名為「零梯度電路嫁接」(Zero-Gradient Circuit Grafting) 的編譯框架，其核心目標是將確定性的數位邏輯（digital logic）直接寫入預訓練語言模型（Pretrained Language Model）的權重中，而無需任何梯度下降訓練或執行期工具呼叫。此方法論建立在三大解析基元（analytical primitives）之上，並透過五階段自動化編譯器（5-stage compiler）實現端到端的電路合成。

**第一基元：雙層 Mellin-GLU 求積（Mellin-GLU Quadrature）**

此機制解決了無偏置（bias-free）SwiGLU/GeGLU 層中未知逐詞元 RMSNorm 縮放的難題。傳統 RASP（Weiss et al., 2021）或 Tracr（Lindner et al., 2023）等編譯框架假設 MLP 存在偏置、絕對位置編碼與未正規化的線性傳遞，但這些假設在現代 LLM 中已被 RMSNorm、無偏置 SwiGLU/GeGLU（Shazeer, 2020）所違反。本方法透過 Mellin 變換將未知縮放因子轉化為沿對數間距門控網格（log-spaced gate grid）的平移操作，動態範圍（dynamic range）超過 250 倍，並提供 IEEE 754 與 TF32 層級的誤差界限（Theorem 3.2）。此設計的關鍵洞見在於：將乘法性縮放問題轉化為加法性平移問題，從而可在閉式（closed-form）下精確控制。

**第二基元：跨詞元尺度對消（Cross-Token Scale Cancellation）**

此機制結合兩種互補技術：
- **帶符號切比雪夫 Indefinite-RoPE 自匯聚注意力（Signed Chebyshev Indefinite-RoPE Self-Sink Attention）**：透過修改旋轉位置嵌入（RoPE）的頻率結構，使注意力分數在跨詞元累積時產生尺度對消。
- **無記憶 SiLU 反對稱 GatedDeltaNet 位移（Memoryless SiLU-Antisymmetric GatedDeltaNet Shifts）**：利用 GatedDeltaNet（Yang et al., 2025）的線性遞迴特性，透過反對稱設計實現無狀態的尺度消除（Theorem 3.3）。

兩者共同解決了多步算術中數值規模爆炸的問題，使 6 位數甚至 8 位數運算可在有限精度下穩定執行。

**第三基元：軸向寬度擴展（Axis-Aligned Width Extension）**

此機制將殘差流（residual stream）從原始寬度 $d$ 擴展至 $d+K$，並透過 $\sqrt{d/(d+K)}$ 範數補償（norm compensation）維持能量守恆。輸出端採用 Base-1000 規範化 BPE 發射（canonical BPE emission），將每位數字編碼為獨立的詞元（token），並透過差分綁定解嵌入（differential tied unembedding，+254/-256）確保正負號的精確區分（Theorem 3.4）。此設計巧妙地利用了現代 BPE 分詞器（tokenizer）對數字的子詞（subword）切分特性，使算術電路可與自然語言詞彙共存於同一詞彙表。

**五階段編譯器架構**

編譯器將高階算術規範（如 4-8 位數有號加、減、乘）自動分解為：
1. 邏輯規格化（將算術轉為布林/算術混合表示）
2. TC⁰ 深度電路分解（constant TC⁰ depth）
3. 基元映射至 GLU/Attention/DeltaNet 子層
4. 寬度擴展與範數補償
5. 詞元對齊與解嵌入綁定

整個流程在恆定 TC⁰ 深度下完成，這在電路複雜度理論中意味著可由具有常數深度、多項式閘數的閘電路模擬，與傳統循序進位加法器的線性深度形成對比。

#### 實驗數據解讀

**算術精度評估**

在 6 位數有號算術任務（$N=1{,}200$，BF16 精度）上：
- **IBM Granite 4.2 3B**：活躍非零值（active non-zeros）僅 1.07M-1.33M（佔總參數 $\leq 0.036\%$），ALU 前綴準確率（ALU-prefix accuracy）達 **99.17%**，搭配 FP32 側車（sidecar）可達 **100.00%**。
- **Alibaba Qwen 3.5 4B**：活躍非零值 2.25M-2.39M（$\leq 0.057\%$），ALU 前綴準確率直接達到 **100.00%**。

這些數據顯示，極稀疏的權重修改（$<0.06\%$ 非零）即可實現近乎完美的精確算術，這與 LoRA 微調形成鮮明對比——後者在 12.8K 樣本訓練下僅達到 42.2%/61.7%，且行內延續（inline continuation）能力為 0%。

**自然語言能力保留**

句中續接（mid-sentence resumption）準確率達 98%-100%，這是衡量模型在算術運算後能否無縫接續自然語言生成的關鍵指標。預註冊的 Tango 基準（$N=4{,}392$）通過率為 14/14，分布外觸發（out-of-distribution trigger）僅 0/11,134，顯示嫁接後的模型在長文本（>2K 詞元）生成中未出現能力退化。

**布林與奇偶電路**

3-文字布林電路（3-literal Boolean circuit）在 $N=1{,}728$ 樣本上達成 100% 準確率，並通過 42 層 Gemma 4 E4B 的稽核（audit）。5 位元多數/奇偶電路（Majority/Parity）同樣達到 100%。這些結果驗證了方法的通用性，不僅限於算術，亦可編譯通用布林邏輯。

**記憶體效率**

分解式區塊稀疏側車（factorized block-sparse sidecar）在 A100 GPU 上將 VRAM 控制在 7.89/10.65 GiB，搭配 INT8/INT4 量化與 FP32 側車可進一步降至 4.60/8.14 GiB，相較原始模型節省 42%-44% 記憶體。這對於邊緣部署具有重要意義。

**消融實驗（Ablation Studies）**

五基元留一法（leave-one-out）消融實驗顯示，移除任一基元都會導致算術精度顯著下降（8%-51%），證明三個機制缺一不可。固定維度 SVD 雕刻（$P_\perp$）與匹配 $(d+K)$ 對照組均無法同時達成算術精度與自然語言保留，凸顯本方法在權重空間編輯中的獨特優勢。

#### 與現有研究的比較

**與編譯框架的比較（RASP/Tracr）**

RASP 與 Tracr 從零建構玩具 Transformer，假設 MLP 偏置、絕對位置與未正規化線性傳遞，這些假設在現代 RMSNorm、無偏置 SwiGLU/GeGLU、RoPE、GatedDeltaNet 架構中均不成立。本方法直接針對這些現代化組件設計閉式基元，無需修改架構假設。

**與子空間注入的比較（CoNNs/Tracr-Injection）**

CoNNs（Weng et al., 2024）透過梯度訓練的適配器融合外部規則模組；Tracr-Injection（Vergara-Browne & Soto, 2025）結合子空間投影（$P_\perp = I - UU^\top$）與梯度蒸餾。這些方法仍需梯度優化與訓練資料，且參數開銷 $\geq 1.0\times$。本方法實現真正的零梯度、零樣本合成，參數開銷僅 $<0.06\%$。

**與權重空間虛擬機的比較（CALM W ASM VM）**

Percepta 的 CALM W ASM VM（Tzamos & Percepta Research, 2026）在專用虛擬機中執行多千詞元追蹤，而非通用預訓練 LM。本方法直接在通用 LM 權重中嵌入電路，無需專用 VM 基礎設施。

**與代理式權重空間編程的比較（WSP/SWD）**

Takehi 等人（2026）與 Yan 等人（2026）的代理式啟發式編輯啟發式擾動約 $10^3$ 個純量，本方法則透過解析基元實現確定性、可驗證的電路合成。

**與工具路由器的比較（PAL/Toolformer）**

PAL（Gao et al., 2023）與 Toolformer（Schick et al., 2023）透過主機正則表達式或 Python 解譯器路由算術請求，需 100% 主機介入且無法在權重內執行。本方法實現 100% 權重內執行，無需主機路由。

**與 LoRA 微調的比較**

同骨幹（same-backbone）LoRA SFT（12.8K 樣本，400 步 AdamW）在 1-6 位數算術上僅達 42-62% 精度，且行內散文延續能力為 0%。本方法在零訓練樣本下達成 99-100% 精度並保留 98-100% 句中續接能力，顯示梯度微調並非精確算術的必要條件。

**局限性**

1. **架構依賴性**：方法依賴特定的現代化組件（無偏置 SwiGLU/GeGLU、RoPE、GatedDeltaNet），對於使用 LayerNorm 或帶偏置 FFN 的較舊架構可能需要調整。
2. **運算類型限制**：目前主要展示有號整數加、減、乘，布林與奇偶電路，對於浮點運算、除法或更複雜函數（如超越函數）的擴展性未充分驗證。
3. **詞元化假設**：Base-1000 規範化 BPE 發射假設分詞器對數字有合理的子詞切分，對於使用 SentencePiece 單字元編碼或位元級 BPE 的模型可能需要重新設計。
4. **規模驗證**：實驗僅在 3B-4B 模型上驗證，對於更大規模（如 70B+）或更小規模（如 <1B）的泛化性尚待探索。
5. **理論保證的實證差距**：雖然提供 IEEE 754 誤差界限，但 BF16 下的 99.17% 與 FP32 側車下的 100% 之間的 0.83% 差距，暗示在更低精度下仍有數值穩定性挑戰。

### 實作步驟建議

1. **環境與模型準備（第 1–2 週）**
   - 選定目標模型（建議從 Granite 4.2 3B 或 Qwen 3.5 4B 起步），驗證其符合 bias-free RMSNorm + SwiGLU/GeGLU 假設。
   - 安裝依賴套件，配置 BF16/FP32 混合精度環境。
   - 載入 tokenizer，確認 BPE 編碼可支援 Base-1000 數字分塊。

2. **校準資料採集（第 3–5 天）**
   - 從任意文本語料（如 Wikipedia 子集）採樣 2L+1 個序列，提取每個子層的 RMSNorm 中位數。
   - 若無法取得校準資料，啟用 0-token 權重解析估計模式（論文中已驗證可行）。
   - 將校準結果序列化儲存，供編譯器後續使用。

3. **五階段編譯器執行（第 1–2 天）**
   - **階段 1**：宣告目標電路規格（4–8 位數 {+,−,×} 或 3-literal 布林）。
   - **階段 2**：Mellin-GLU 求積合成，產生 SwiGLU/GeGLU 層的閉式權重。
   - **階段 3**：Indefinite-RoPE 與 GatedDeltaNet 位移合成，處理跨詞元尺度對消。
   - **階段 4**：軸向寬度擴展（d→d+K）與 √(d/(d+K)) 範數補償。
   - **階段 5**：差分綁定解嵌入（+254, −256）與 Base-1000 BPE 對齊。
   - 編譯完成後，活躍非零值應控制在 ≤0.057%（Granite: 1.07M–1.33M；Qwen: 2.25M–2.39M）。

4. **驗證與稽核（第 3–7 天）**
   - 執行 6 位數算術測試（BF16），目標 ≥99% ALU 前綴準確率。
   - 執行 3-literal 布林測試（N=1,728），目標 100%。
   - 執行 5-bit Majority/Parity 測試，目標 100%。
   - 執行 Tango 14/14 預註冊分割（N=4,392），確認 0/11,134 OOD 觸發。
   - 進行五基元留一法（leave-one-out）消融實驗，確認各機制貢獻。

5. **量化與部署（第 2–3 週）**
   - 將 NL 權重量化至 INT8 或 INT4，保留算術側車為 FP32。
   - 部署至 A100 或相容 GPU，監控 VRAM 使用量（目標 ≤8.14 GiB）。
   - 整合至既有推論服務（vLLM、TGI 或自建 FastAPI）。
   - 設定監控指標：算術準確率、NL 困惑度（PPL）、句中續接率、IFEval 分數。

6. **持續監控與迭代（持續）**
   - 建立回歸測試管線，定期重跑 Tango 與算術基準。
   - 收集 OOD 觸發案例，必要時重新校準 norm 中位數。
   - 追蹤自然語言能力退化情形，必要時調整 K（寬度擴展量）。

### 潛在風險與注意事項

**數值精度風險**
- BF16 模式下可能出現 ±1 ULP 誤差，雖然 ALU 前綴準確率達 99.17%，但對要求絕對精確的場景（如密碼學雜湊、會計總帳）仍應啟用 FP32 側車以達 100%。
- 緩解措施：對關鍵運算路徑保留 FP32，並在輸出端加入 IEEE 754 對齊檢查。

**架構相容性限制**
- 本方法假設 bias-free RMSNorm 與 SwiGLU/GeGLU；若目標模型使用 LayerNorm、絕對位置編碼或帶偏置的 FFN，將違反 Theorem 3.2 的單層不可能性假設。
- 緩解措施：部署前先以架構稽核腳本驗證；若不相容，需考慮遷移至支援架構或採用混合方案。

**自然語言能力退化**
- 即使採用 √(d/(d+K)) 範數補償，寬度擴展仍可能輕微影響 PPL 或 ARC 等基準表現。
- 緩解措施：執行 Tango 非劣效（noninferior）測試，設定 PPL 退化容忍閾值（如 ≤5%）；若超標，縮減 K 或改用更窄的編碼方案。

**量化副作用**
- INT8/INT4 量化 NL 權重時，可能干擾已編譯電路的數值路徑。
- 緩解措施：採用「NL 量化 + 算術側車 FP32」的分離架構，避免量化誤差污染精確運算。

**編譯器錯誤與可審計性**
- 閉式基元雖無需訓練，但合成過程涉及多層數值操作，單一錯誤可能導致整條電路失效。
- 緩解措施：建立單元測試覆蓋每個基元；執行 42 層 Gemma 4 E4B 稽核（論文中已示範）以驗證深層穩定性。

**詞元化對齊失敗**
- Base-1000 規範化 BPE 假設 tokenizer 能整齊切分三位數區塊；若模型使用非標準 BPE（如 SentencePiece unigram），可能產生對齊漂移。
- 緩解措施：部署前驗證 BPE 編碼；若不相容，考慮自定義詞元化層或退回標準 Base-10 編碼（犧牲部分壓縮效率）。

### 與其他技術的整合建議

**與 LoRA 微調的整合**
- 本方法在算術任務上以零樣本超越 12.8K 樣本 LoRA（42.2%/61.7% vs. 99.17%/100%），但 LoRA 在開放式 NL 任務上仍有優勢。
- 整合策略：使用本方法編譯算術電路至基底權重，再以少量 LoRA 適應特定領域 NL 風格；兩者作用於不同權重子空間，不會互相干擾。

**與外部工具路由的整合**
- PAL/Toolformer 需 100% 主機路由，無法離線運作；本方法可作為離線後備方案。
- 整合策略：設計混合路由器——當裝置在線且工具可用時，優先呼叫 Python 解譯器；離線或工具不可用時，啟用編譯電路；兩者輸出經一致性檢查後再呈現給使用者。

**與 RASP/Tracr 的整合**
- RASP/Tracr 編譯至從零建構的玩具 Transformer，缺乏 NL 能力；本方法保留預訓練模型的 NL 能力。
- 整合策略：將 RASP/Tracr 作為設計驗證工具（快速原型），確認電路邏輯正確後，再以本方法編譯至實際預訓練模型。

**與稀疏權重分解（Sparse Weight Decomposition）的整合**
- SWD 從既有權重中萃取電路（包含 Qwen 3.5），本方法則從零合成電路。
- 整合策略：先以 SWD 探勘模型中已存在的算術子結構，再以本方法補完缺失部分，可降低活躍非零值比例。

**與量化管線的整合**
- 本方法的分解式區塊稀疏側car與 INT8/INT4 量化正交。
- 整合策略：在既有 GPTQ 或 AWQ 量化管線中，將算術側車標記為「不可量化」並保留 FP32；NL 權重照常量化。

**與推論框架的整合**
- 編譯後權重為標準 PyTorch 格式，可直接載入 vLLM、TGI、SGLang 等框架。
- 整合策略：若框架不支援自定義 RoPE 變體（Indefinite-RoPE），需在模型定義層注入對應實作；FlashAttention-2 與 TorchInductor 已驗證相容。
