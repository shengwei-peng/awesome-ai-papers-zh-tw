## 摘要翻譯

影片擴散變壓器（Video Diffusion Transformers, VideoDiTs）處理長時空權杖序列（spatio-temporal token sequences），使自注意力（self-attention）成為高解析度影片生成的主要瓶頸。無訓練稀疏注意力（training-free sparse attention）可降低此成本，但自適應 Top-p 路由（adaptive Top-p routing）在多 GPU 序列平行（multi-GPU sequence parallelism）下會造成各注意力頭（attention head）工作量不均。由此產生的工作量異質性（workload heterogeneity）使稀疏注意力成為排名層級落後者問題（rank-level straggler problem）。我們提出 FVAttn，一個無訓練稀疏注意力系統，可提升多 GPU 序列平行下自適應稀疏注意力的分散式執行效率（distributed execution efficiency）。FVAttn 使用 Top-p 路由、Top-k 安全下限（Top-k safety floor）與影片感知區塊組織（video-aware block organization）作為稀疏路由前端（sparse-routing frontend），並在執行階段修補具體化遮罩（materialized mask）。執行階段負載平衡透過點對點通訊（P2P communication）遷移少數負載較重的注意力頭，以縮短當前關鍵路徑（critical path）。鬆弛感知稀疏擴增（Slack-Aware Sparse Augmentation）以額外的高價值區塊（high-value blocks）填補殘餘非關鍵排名鬆弛（residual non-critical-rank slack），同時透過與既有計算重疊（overlap），將排程開銷（scheduling overhead）與遷移開銷（migration overhead）隱藏起來。在步數蒸餾（step-distilled）的 Wan2.2 I2V 上，FVAttn 將平均負載不平衡（average load imbalance）從 1.34 降至 1.08，並相較於 FlashAttention 達到 4.41 倍的注意力加速（attention speedup），同時取得 2.02–2.11 倍的 DiT 推論加速（DiT inference speedup），且視覺品質（visual quality）具競爭力。

### 核心貢獻（3～5點）
- 提出 FVAttn，一個無訓練稀疏注意力（training-free sparse attention）系統，專為多 GPU 序列平行（multi-GPU sequence parallelism）下的影片擴散變壓器（Video Diffusion Transformers）設計，解決自適應 Top-p 路由（adaptive Top-p routing）造成的工作量異質性（workload heterogeneity）與排名層級落後者問題（rank-level straggler problem）。
- 設計執行階段負載平衡（Runtime Load Balancing）機制，透過點對點通訊（P2P communication）動態遷移負載較重的注意力頭（attention head），縮短關鍵路徑（critical path）並降低推論延遲（inference latency）。
- 提出鬆弛感知稀疏擴增（Slack-Aware Sparse Augmentation），利用殘餘非關鍵排名鬆弛（residual non-critical-rank slack）增加高價值區塊（high-value blocks），在維持注意力保真度（attention fidelity）的同時提升稀疏效益。
- 透過與既有計算重疊（overlap）隱藏排程開銷（scheduling overhead）與遷移開銷（migration overhead），使負載平衡與稀疏路由的額外成本幾乎不被察覺。
- 在步數蒸餾（step-distilled）的 Wan2.2 I2V 模型上驗證，FVAttn 將平均負載不平衡（average load imbalance）從 1.34 降至 1.08，相較 FlashAttention 達到 4.41 倍注意力加速（attention speedup）與 2.02–2.11 倍 DiT 推論加速（DiT inference speedup），並保持具競爭力的視覺品質（visual quality）。

### 適合對象
適合從事高效能影片生成、擴散模型（diffusion models）推論加速、稀疏注意力（sparse attention）演算法設計，以及分散式深度學習系統的研究者與工程師。特別是關注多 GPU 序列平行（multi-GPU sequence parallelism）、自適應稀疏注意力（adaptive sparse attention）與執行階段負載平衡（Runtime Load Balancing）如何兼顧加速比與生成品質的讀者。

## 深度分析

#### 方法論解析

FVAttn 的核心設計可視為一個「前端稀疏路由（sparse-routing frontend）＋ 執行階段修復（runtime repair）」的兩階段架構。其目標是在保留 Top-p routing 所帶來的注意力保真度（attention fidelity）優勢的同時，解決序列平行（sequence parallelism）下因工作量異質性（workload heterogeneity）而產生的排名層級落後者問題（rank-level straggler problem）。

##### 1. 稀疏路由前端：Top-p + Top-k 安全下限 + 影片感知區塊組織

FVAttn 採用動態區塊稀疏注意力（dynamic block-sparse attention）。對於每個注意力頭（attention head）\(h\)、查詢區塊（query block）\(i\) 與鍵區塊（key block）\(j\)，路由模組會估計重要性分數 \(s_{h,i,j}\)，並產生二元遮罩 \(M_{h,i,j} \in \{0,1\}\)。與固定保留 \(k\) 個區塊的 Top-k routing 不同，Top-p routing 保留的是「累積正規化重要性達到閾值 \(p\)」的最小區塊集合。這使得集中式頭（concentrated head）可以只保留少數高質量區塊，而平坦或多峰式頭（flat or multi-modal head）則保留更多區塊，從而在相近的平均運算預算（compute budget）下獲得更高的注意力保真度。

為了避免極端稀疏導致的數值不穩定或品質退化，FVAttn 進一步引入 Top-k 安全下限（Top-k safety floor），確保每個查詢區塊至少保留一定數量的鍵區塊。此外，影片感知區塊組織（video-aware block organization）則利用影片的時空幾何結構來安排區塊順序，使相鄰的時空區塊在記憶體與計算上更具局部性，有助於後續的稀疏核心（sparse kernel）效率。

##### 2. 執行階段負載平衡（Runtime Load Balancing, RLB）

這是 FVAttn 最具區別性的機制。在 Ulysses 風格序列平行（Ulysses-style sequence parallelism）下，完整序列的每個注意力頭會透過 All-to-All 分散到不同 GPU rank。Top-p routing 的適應性導致每個頭保留的區塊數量不同，若多個高密度頭（high-density heads）剛好落在同一 rank，該 rank 就會成為同步注意力階段（synchronized attention phase）的落後者（straggler）。

FVAttn 的關鍵觀察是：這種負載傾斜（workload skew）高度局部化——絕大部分的工作量不平衡通常只集中在少數重載頭上。因此，RLB 不需要昂貴的全域重新分割（global repartitioning），而是在具體化遮罩（materialized mask）產生後，根據實際觀測到的每頭工作量（per-head workloads），透過點對點通訊（P2P communication）遷移少量重載頭。在預設的 8-GPU 設定下，每個 rank 最多只傳送與接收一個本地頭，約佔其分配頭集合的 20%，因此通訊開銷受到嚴格限制。

RLB 的決策流程可概括為：
1. **測量**：在 sparse mask materialization 後，統計每個頭的實際工作量。
2. **選擇**：識別造成關鍵路徑（critical path）延長的重載頭。
3. **遷移**：在通訊預算內，將選定的重載頭透過 P2P 遷移到負載較輕的 rank。
4. **執行**：各 rank 根據新的分佈執行稀疏注意力。

這種「事後修復」（post-routing repair）策略的優勢在於它使用的是真實工作量，而非歷史稀疏度（historical sparsity）、離線剖析（offline profiling）或近似相似度訊號（approximate similarity signals）。對於少步數機制（few-step regime）下的影片生成而言，相鄰步驟的頭密度變化可高達 97%、排名負載變化達 44%，任何基於歷史或近似訊號的預先佈局（pre-layout）策略都極為脆弱。

##### 3. 鬆弛感知稀疏擴增（Slack-Aware Sparse Augmentation, SASA）

在 RLB 完成後，某些非關鍵 rank 仍可能存在殘餘非關鍵排名鬆弛（residual non-critical-rank slack），也就是在全局關鍵路徑下仍有未被使用的計算容量。SASA 的設計是將這些閒置時間轉化為有用的計算：它只在測量到有鬆弛的 rank 上，根據區塊重要性排名（block-importance rankings）追加額外的高價值區塊（high-value blocks）。

這與「全域提高 Top-p 閾值」有本質區別：後者會增加所有 rank 的工作量，可能反而延長 makespan；而 SASA 是區域性的、受鬆弛預算限制的擴增，因此不會延長注意力總延遲，卻能改善稀疏遮罩覆蓋率（sparse-mask coverage），進一步提升注意力保真度。

##### 4. 重疊執行（overlap）與整體流程

FVAttn 將排程開銷（scheduling overhead）與遷移開銷（migration overhead）透過 overlap 技術隱藏在既有計算之後。整體流程可總結為：

- **Routing 決定計算什麼**：產生初始 sparse mask、每頭工作量、區塊重要性排名。
- **RLB 決定在哪裡計算**：遷移重載頭以縮短關鍵路徑。
- **SASA 將閒置容量轉為額外計算**：在鬆弛 rank 上追加高價值區塊。

這種分工使 FVAttn 能同時達到低延遲與高保真度，而不需要重新訓練模型。

#### 實驗數據解讀

論文在步數蒸餾（step-distilled）的 Wan2.2 I2V、Wan2.2 Animate 與 Wan2.1 T2V 上進行評估，主要關注負載平衡、注意力延遲、DiT 推論延遲與影片品質。

##### 1. 負載平衡改善

在 Wan2.2 I2V 上，RLB 將平均負載不平衡（average load imbalance）從 1.34 降至 1.08。這裡的負載不平衡因子可理解為「最忙 rank 工作量 / 平均 rank 工作量」。1.34 表示最忙 rank 比平均多 34% 的工作；降至 1.08 後，幾乎接近理想平衡。這直接驗證了「少量重載頭遷移即可消除大部分關鍵路徑延長」的假設。

##### 2. 注意力加速

完整 FVAttn 堆疊在 Wan2.2 I2V 上達到相對於 FlashAttention 4.41 倍的注意力加速（attention speedup）。考慮到 FlashAttention 是高度優化的稠密注意力基準演算法，這個數字代表稀疏化帶來的理論運算減少，加上 RLB 對分散式執行效率的修復，共同發揮了作用。值得注意的是，可見執行階段開銷僅 0.7 ms，顯示 overlap 與 P2P 遷移的開銷控制得相當好。

##### 3. 端到端 DiT 推論加速

FVAttn 在評估的工作負載上達到 2.02–2.11 倍的 DiT 推論加速（DiT inference speedup）。這低於純注意力加速的原因在於：注意力雖佔 Wan2.2-14B I2V 單步推論時間的 74.1%，但仍有前饋網路（FFN）、正規化、嵌入投影等其他組件無法被稀疏注意力加速。因此端到端加速約為注意力加速的對數線性比例，符合 Amdahl's Law 的預期。

##### 4. 影片品質

論文強調 FVAttn 在提升效率的同時保持「具競爭力的影片品質」（competitive video quality），並聲稱改善了品質–效率帕雷托前沿（quality–efficiency Pareto frontier）。這意味著與現有無訓練稀疏注意力方法相比，FVAttn 在相同延遲下通常能達到更好的視覺品質指標，或在相同品質下達到更低延遲。不過，由於提供的上下文未包含具體的 FVD、PSNR、LPIPS 或人類偏好分數，無法進一步量化比較。

##### 5. 實驗設定的意涵

選用 4-step distilled inference 作為主要評估場景具有實務意義：這是工業界常用的加速設定，但正如作者指出，步數蒸餾（step distillation）減少的是去噪步驟數量，並未改變每步的序列長度與二次方注意力成本。因此 FVAttn 的優化與步數蒸餾是互補（complementary）的，兩者結合可進一步降低總推論時間。

#### 與現有研究的比較

##### 1. 相對於靜態稀疏注意力

靜態稀疏模式（static sparse patterns）使用預先定義、與內容無關的結構，例如局部窗口、跨步採樣或固定稀疏區塊。這類方法的優點是工作量規則、易於平行化，但缺點是無法適應不同頭或不同查詢區塊的注意力分佈差異，容易遺漏遠距離或語意上重要的高價值區塊。FVAttn 透過 Top-p routing 與 SASA 動態調整保留區塊，在保真度上更具優勢。

##### 2. 相對於固定 Top-k 動態稀疏注意力

Top-k routing 保留固定數量的高得分鍵區塊，雖然工作量規則、便於負載平衡，但對於集中式頭會浪費計算在相對不重要的區塊上，而對於多峰式頭又可能截斷重要資訊。Top-p routing 則根據注意力分佈的質量集中程度自適應調整，通常能在相同平均運算預算下獲得更高的注意力保真度。FVAttn 進一步以 Top-k 安全下限避免過度稀疏，並以 RLB 解決 Top-p 帶來的負載不平衡。

##### 3. 相對於基於預先佈局的稀疏序列平行系統

現有稀疏序列平行系統常嘗試在當前注意力計算之前，利用歷史稀疏度、離線剖析或近似相似度訊號來決定頭或區塊的佈局。這類方法在穩定的工作負載下可能有效，但在少步數影片生成中極為脆弱：相鄰步驟的頭密度變化可達 97%，rank 負載變化達 44%。FVAttn 的 RLB 採用事後修復，使用具體化遮罩後的真實工作量，因此對動態變化更具魯棒性。

##### 4. 相對於完整遮罩後重新分割（full post-mask repartition）

理論上，在 sparse mask materialization 後進行完整重新分割可以達到最佳負載平衡，但這需要另一次大規模資料移動（例如另一輪 All-to-All），可能抵消稀疏注意力帶來的加速。FVAttn 的 RLB 只遷移少數重載頭，透過 P2P communication 完成，開銷遠低於全域重新分割，同時能恢復大部分的關鍵路徑效率。

##### 5. 限制與潛在弱點

- **局部性假設的適用範圍**：RLB 的有效性依賴「不平衡集中在少數重載頭」這一觀察。若在某些模型、解析度或批次大小下，不平衡廣泛分散於多個頭，則 P2P 遷移的通訊預算可能不足以修復關鍵路徑。
- **P2P 通訊拓撲依賴**：P2P 遷移效率與 GPU 間互連頻寬密切相關。在 NVLink 密集的節點內效果良好，但在跨節點或頻寬受限的硬體上，遷移開銷可能上升。
- **稀疏核心的實作複雜度**：動態區塊稀疏注意力的效率高度依賴客製化 CUDA kernel。論文未詳細說明 kernel 設計，這是重現與移植的關鍵。
- **品質指標細節不足**：雖然論文聲稱 competitive video quality，但提供的上下文未列出具體指標，難以判斷與基線的統計顯著性差異。

#### 未來研究方向

##### 1. 擴展至多節點與異質硬體

當前的 RLB 主要針對單一節點內的 8-GPU 設定設計。未來可研究在跨節點序列平行（例如與 tensor parallelism、pipeline parallelism 結合）下的負載平衡策略，並針對異質頻寬（如 NVLink vs. InfiniBand）設計自適應遷移預算。

##### 2. 與訓練感知稀疏注意力結合

FVAttn 是無訓練（training-free）方法，因此受限於現有預訓練模型的注意力分佈。未來可探索「訓練時即鼓勵稀疏且可平衡的注意力分佈」，例如透過正規化或輔助損失使 Top-p routing 產生的頭級工作量更均勻，從而降低執行階段負載平衡的壓力。

##### 3. 更精細的鬆弛利用策略

SASA 目前將鬆弛轉化為額外高價值區塊。未來可進一步研究如何將鬆弛用於其他互補任務，例如低成本的特徵快取更新、近似注意力計算、或與推論量化（quantization）結合以提升整體吞吐量。

##### 4. 理論保證與最適性分析

目前 RLB 採用貪婪或啟發式遷移策略。未來可建立形式化模型，證明在給定通訊預算下，RLB 能達到某種近似最優的 makespan 縮短比例，並分析不同稀疏分佈下的最壞情況界限。

##### 5. 推廣至其他生成模型與模態

FVAttn 針對影片 DiT 設計，但其核心思想——「稀疏路由後進行執行階段負載平衡」——可推廣至長序列生成的其他場景，例如長文本生成、音訊生成、3D 生成，甚至是多模態大模型中的長上下文注意力。

##### 6. 與編譯器或執行期排程框架整合

未來可將 FVAttn 的 RLB 與 SASA 整合進更通用的分散式深度學習編譯器或執行期（如 vLLM、TensorRT-LLM、Megatron-LM 的執行排程層），使其能自動適應不同模型與硬體配置，降低手動調校成本。

##### 7. 動態遮罩壓縮與通訊優化

隨著序列長度增加，sparse mask 本身的儲存與交換成本也會上升。未來可研究如何在 RLB 遷移過程中同時壓縮遮罩表示，或利用 mask 的結構性冗餘減少 P2P 傳輸量。

## 論文問答

**Q1：FVAttn 主要想解決影片生成中的什麼問題？**
A：FVAttn 針對的是影片擴散變壓器（VideoDiTs）在處理高解析度、長時空權杖序列時，自注意力運算成為推論瓶頸的問題。雖然無訓練稀疏注意力能透過跳過低價值的查詢–鍵互動來降低計算量，但自適應的 Top-p 路由會讓不同注意力頭保留的區塊數量差異很大，進而在多 GPU 序列平行下造成嚴重的每頭工作量異質性。這種負載不平衡在 Ulysses 風格序列平行中會轉化為排名層級的落後者問題，使得部分 GPU rank 在同步注意力階段空轉，抵消了稀疏化本應帶來的加速。

**Q2：為什麼現有的稀疏序列平行方法在少步數影片生成中不夠穩健？**
A：現有方法通常依賴歷史稀疏度、離線剖析或近似相似度訊號來預先決定頭或區塊的佈局，但這些訊號在少步數蒸餾設定下很容易過時。文中指出，相鄰步驟之間同一頭的密度變化最高可達 97%，同一 rank 的負載變化也可達 44%，因此基於過去資料的預佈局策略經常失準。更根本的是，在 Ulysses 風格序列平行中，當前稀疏注意力層的真實工作量只有在序列到頭的 All-to-All 完成、具體化遮罩產生之後才能觀察到；若要在遮罩產生後進行完整的重新分區，又需要額外的大量資料搬移，可能侵蝕稀疏注意力帶來的效益。

**Q3：負載不平衡為何在 Ulysses 風格序列平行下特別有害？**
A：在 Ulysses 風格序列平行中，完整的序列注意力頭會透過 All-to-All 分散到各個 GPU rank，因此每個 rank 負責的是若干完整的注意力頭。當多個高密度頭被映射到同一 rank 時，該 rank 的計算時間會明顯長於其他 rank，成為同步注意力階段的落後者。由於所有 rank 必須等待最慢者完成，其他已經算完的 rank 會被迫閒置，導致整體執行時間被少數重載頭拉長，稀疏注意力的理論加速也因此無法充分兌現。

**Q4：FVAttn 的核心架構由哪些元件組成？**
A：FVAttn 首先是一個自適應稀疏路由前端，結合 Top-p 路由、Top-k 安全下限與影片感知區塊組織來產生初始稀疏遮罩與執行階段後設資料。接著，執行階段負載平衡（Runtime Load Balancing, RLB）在具體化遮罩後根據真實的每頭工作量，透過點對點通訊遷移少數重載頭，以縮短當前關鍵路徑。最後，鬆弛感知稀疏擴增（Slack-Aware Sparse Augmentation, SASA）利用非關鍵 rank 的殘餘鬆弛時間加入額外高價值區塊，並透過重疊機制把排程與遷移開銷隱藏在既有計算之後。

**Q5：Runtime Load Balancing 如何運作，為何通訊開銷有限？**
A：RLB 在稀疏遮罩具體化之後才剖析每個注意力頭的實際工作量，因此能根據當前 invocation 的真實負載進行修復，而不是依賴過時預測。作者觀察到 Top-p 路由造成的負載傾斜高度集中於少數重載頭，因此只需遷移這些頭即可顯著改善平衡。在預設的 8-GPU 設定下，每個 rank 最多只會傳送與接收一個本地頭，約佔其被指配頭集合的 20%，透過點對點通訊完成，因而能以有限的通訊成本換取關鍵路徑的縮短。

**Q6：Slack-Aware Sparse Augmentation 的設計理念是什麼？它如何不延長整體延遲？**
A：SASA 的目標是在 RLB 之後，進一步利用仍存在的非關鍵 rank 殘餘鬆弛時間，把它轉化為有用的計算。與全域提高 Top-p 閾值不同，後者會讓所有 rank 都增加區塊、反而拉長 makespan，SASA 只會在測量到有鬆弛的 rank 上額外加入高價值區塊。這樣一來，原本會因為同步等待而浪費的閒置時間被用來提升稀疏遮罩覆蓋率，卻不會改變關鍵路徑長度，因此能在不增加注意力延遲的前提下改善注意力保真度。

**Q7：FVAttn 在哪些模型與設定上進行了評估？**
A：論文在 Wan2.2 I2V、Wan2.2 Animate 與 Wan2.1 T2V 上進行實驗，並採用 4-step 步數蒸餾推論設定。其中 Wan2.2 I2V 是主要的圖像轉影片基準，實驗預設使用 8 張 GPU 進行分散式推論。這些模型代表了目前業界常見的影片擴散變壓器，並且涵蓋了不同任務型態，能夠驗證 FVAttn 在多樣影片生成工作負載上的通用性。

**Q8：FVAttn 取得了哪些關鍵量化結果？**
A：在 Wan2.2 I2V 上，RLB 將平均負載不平衡因子從 1.34 降低到 1.08，顯示出顯著的負載均衡改善。完整的 FVAttn 堆疊相較於 FlashAttention 達到 4.41 倍的注意力加速，而整體 DiT 推論則有 2.02 至 2.11 倍的加速。可見的執行階段開銷僅約 0.7 毫秒，同時影片品質仍具競爭力，顯示該方法在效率與品質之間取得了良好平衡。

**Q9：有哪些實驗洞察支持 FVAttn 的設計選擇？**
A：實驗首先驗證了負載傾斜高度局部化的觀察，即少數重載頭是造成 rank 層級落後者的主因，這正是 RLB 只遷移少量頭即可有效的基礎。其次，RLB 單獨使用就能顯著降低負載不平衡，而 SASA 則進一步把殘餘鬆弛轉為額外高價值區塊，提升稀疏遮罩覆蓋率。最後，重疊機制成功將排程與遷移開銷隱藏在計算之後，使得可見延遲僅 0.7 毫秒，整體結果也持續位於品質–效率的帕雷托前緣之上。

**Q10：FVAttn 最適合應用在哪些部署場景？**
A：FVAttn 特別適合需要處理長序列、高解析度影片生成的多 GPU 部署環境，例如 720p 或更高解析度的互動式影片生成服務。在步數蒸餾後的少步數推論中，雖然去噪步數減少，但每步的序列長度與二次注意力成本不變，因此注意力仍是主要瓶頸，FVAttn 的稀疏化與負載平衡能直接針對此痛點。對於希望在不重新訓練模型的前提下提升推論吞吐與降低延遲的產品化系統，FVAttn 提供了一個即插即用的加速方案。

**Q11：將 FVAttn 整合到產品系統時需要考慮哪些工程問題？**
A：首先，系統必須支援高效的點對點通訊，因為 RLB 依賴 GPU 之間直接遷移重載頭，若 P2P 頻寬不足會影響修復效果。其次，需要與 Ulysses 風格序列平行緊密整合，並在 All-to-All 後即時產生具體化遮罩與每頭工作量剖析，這對執行階段排程器提出一定要求。最後，遷移預算與負載改善之間需要權衡，雖然預設每 rank 最多遷移一個頭已能取得良好效果，但在不同硬體拓撲或批次大小下可能需要調整參數。

**Q12：FVAttn 對高效影片生成領域可能帶來什麼影響？**
A：FVAttn 展示了自適應稀疏注意力的保真度優勢與分散式執行效率可以並存，打破了「自適應路由必然導致負載不均」的困境。由於它是無訓練方法，能直接應用於現有預訓練模型，降低了產業界採用的門檻。此外，其「執行階段修復」的設計哲學——在真實工作量可觀察後再進行輕量調整——也可能啟發未來在序列平行、長上下文模型與其他生成任務上的系統層級最佳化研究。

**Q13：FVAttn 有哪些潛在或已暗示的限制？**
A：FVAttn 目前主要針對 Ulysses 風格序列平行設計，若採用其他平行策略，其負載特性與遷移機制可能需要重新調整。此外，RLB 的有效性建立在負載傾斜高度局部化的假設上，若實際分佈中大量頭同時處於高密度狀態，僅遷移少數頭可能無法充分平衡。最後，雖然實驗顯示影片品質具競爭力，但與原始稠密注意力相比仍可能存在細微差異，對於極高品質要求的應用需要進一步評估。

**Q14：在什麼情況下 RLB 與 SASA 可能無法發揮作用？**
A：如果當前層的負載不平衡並非集中在少數頭，而是廣泛分佈於多數頭，則 RLB 的有限遷移預算將難以縮短關鍵路徑。若 GPU 之間的點對點通訊頻寬過低或拓撲不利，遷移重載頭的時間可能超過所節省的計算時間，反而造成負面效果。同樣地，如果所有 rank 都已處於關鍵路徑上而沒有殘餘鬆弛，SASA 就無法在不延長 makespan 的前提下加入額外區塊，其增益將會受限。

**Q15：未來可以朝哪些方向延伸 FVAttn？**
A：未來可以將執行階段負載平衡的概念擴展到其他序列平行策略，例如環狀注意力或混合平行，以適應更多硬體配置。也可以結合量化、快取或投機解碼等技術，進一步壓縮記憶體與計算開銷。此外，隨著影片解析度與幀數持續增加，設計更智慧的線上排程與預測機制，以及將此方法推廣到更長上下文或多模態生成任務，都是值得探索的方向。

## 實務應用指南

### 適用場景

1. **高解析度長影片生成服務**：例如使用 Wan2.2-14B I2V 生成 720p、5 秒以上影片，自注意力佔整體推論時間 70% 以上的場景，FVAttn 可直接縮短每步的去噪延遲。  
2. **少步數蒸餾後的互動式影像轉影片（I2V）**：在 4-step distilled 等低步數機制下，每步序列長度不變，FVAttn 能與步數蒸餾形成互補加速，適合需要即時預覽的產品。  
3. **多 GPU 序列平行部署**：採用 Ulysses 風格序列平行將完整序列的注意力頭分散到多張 GPU 時，Top-p 路由造成的排名層級負載不平衡最為明顯，正是 FVAttn 的設計目標。  
4. **大規模批次影片廣告或媒體生成**：需要高吞吐量且對單次生成延遲敏感的 A/B 測試、短影片廣告產線。  
5. **租賃 GPU 叢集或邊緣雲端推理**：當 GPU 以小時計費且 P2P/NVLink 頻寬充足時，降低負載不平衡可直接轉化為成本節省。

### 實作前置條件

- **資料**：無需重新訓練模型，但需要目標 VideoDiT 權重（如 Wan2.2 I2V、Wan2.2 Animate、Wan2.1 T2V）以及具代表性的提示與輸入圖像/影片，用於驗證視覺品質與延遲。  
- **運算**：建議至少 8 張具備 P2P/NVLink 的 GPU（如 NVIDIA H20），記憶體需容納模型權重、稀疏遮罩、區塊重要性分數與遷移緩衝區。  
- **技能**：需熟悉 CUDA 核心開發、Transformer 推論優化、Ulysses 序列平行與 All-to-All 通訊，並具備使用 nsys、PyTorch Profiler 等工具進行分散式效能剖析的能力。

### 實作步驟建議

1. **建立稠密基線**：在現有 FlashAttention + Ulysses 序列平行上量測注意力佔比、每頭密度、排名負載不平衡因子與端到端 DiT 延遲。  
2. **部署稀疏路由前端**：實作 Top-p 路由、Top-k 安全下限與影片感知區塊組織，於執行階段具體化遮罩並輸出每頭工作量與區塊重要性排序。  
3. **加入執行階段負載平衡（RLB）**：在遮罩具體化後，根據實際每頭工作量選擇少數高密度頭，透過點對點通訊遷移至輕量排名；在 8-GPU 設定中，每個排名預設最多傳送與接收一個本地頭。  
4. **加入鬆弛感知稀疏擴增（SASA）**：量測非關鍵排名的殘餘鬆弛，僅在這些排名上依區塊重要性排序追加高價值區塊，避免提高全域 Top-p 門檻而延長關鍵路徑。  
5. **重疊與系統整合**：將排程與遷移開銷重疊到既有計算之後，調整區塊大小、Top-p 門檻與 Top-k 下限，並與現有推理框架對接。  
6. **品質—效率驗證**：比較 FVD、PSNR、使用者偏好指標與 FlashAttention 基準的注意力加速、DiT 推論加速，確保落在品質—效率帕雷托前緣上。

### 潛在風險與注意事項

- **步驟間工作負載劇烈變化**：在少步數蒸餾設定中，相鄰步驟的頭密度變化可達 97%、排名負載變化達 44%，靜態預先配置容易失效，必須使用執行階段修復。  
- **P2P 遷移開銷上限**：若 GPU 間頻寬不足或拓撲不利，點對點通訊可能產生可見延遲，需嚴格限制每輪遷移頭數並透過重疊隱藏。  
- **SASA 不可重新製造落後者**：追加高價值區塊時必須精確估算該排名的剩餘鬆弛，否則會讓非關鍵排名變成新的關鍵路徑。  
- **保真度—速度權衡**：提高 Top-p 或擴增區塊會提升注意力保真度，但也會降低稀疏加速比，需針對每項任務校準門檻。  
- **核心正確性與數值穩定性**：區塊稀疏注意力的核心實作必須與 FlashAttention 對齊，避免遮罩具體化或重要性分數計算錯誤導致品質衰退。  
- **記憶體額外開銷**：儲存重要性分數、具體化遮罩與遷移緩衝區會增加記憶體用量，需在大型模型上預留餘裕。

### 與其他技術的整合建議

- **與步數蒸餾搭配**：FVAttn 不改變去噪步數，專注於每步注意力加速，可與現有 4-step distilled 等技術相乘，進一步縮短端到端延遲。  
- **與量化、編譯框架整合**：可將非注意力部分交給 FP8、TensorRT-LLM 或 vLLM 等編譯器處理，但需確認稀疏注意力核心與這些執行環境相容。  
- **嵌入現有序列平行框架**：在 DeepSpeed Ulysses、Megatron 等序列平行實作中，替換其注意力核心並加入 RLB 排程器，即可在不改動整體平行策略下獲益。  
- **接入推論服務系統**：與 Triton、Ray Serve 等動態批次服務整合時，建議監控每排名負載不平衡因子作為服務健康指標。  
- **結合提示快取與跨幀壓縮**：對於時空權杖序列中的跨幀冗餘，可先用提示快取或幀壓縮降低序列長度，再由 FVAttn 處理剩餘稀疏注意力。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先掌握自注意力為何是影片生成瓶頸、Top-p 與 Top-k 的差異，以及 Ulysses 風格序列平行的基本運作，再回頭理解 RLB 與 SASA 如何「事後修復」負載不平衡，會更容易跟上論文動機。  
- **AI 工程師**：請聚焦於遮罩具體化、點對點頭遷移排程、區塊稀疏核心與現有推理框架的整合細節，並善用剖析工具驗證遷移開銷是否確實被重疊隱藏。  
- **研究人員**：可關注本文的核心貢獻——將自適應稀疏注意力的「頭層級異質性」轉化為「排名層級落後者問題」，並以執行階段輕量修復取代昂貴的全域重新分割；可進一步探索其他路由策略或模型架構下的泛化性。  
- **產品經理**：重點關注商業指標：FVAttn 在 Wan2.2 I2V 上將平均負載不平衡從 1.34 降至 1.08、注意力加速達 4.41 倍、DiT 推論加速約 2 倍，同時維持競爭力視覺品質；評估時需同時考量部署所需的 GPU 拓撲、核心開發人力與品質驗證成本。
