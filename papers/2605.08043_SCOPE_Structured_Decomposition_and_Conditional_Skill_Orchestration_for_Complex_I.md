## 摘要翻譯

儘管文字生成圖像（Text-to-Image Generation）模型在視覺保真度（Visual Fidelity）方面已取得顯著進展，但由於在接地（Grounding）、生成與驗證（Verification）過程中必須同時追蹤多項需求，忠實實現複雜視覺意圖（Visual Intent）仍具挑戰性。我們將這些需求稱為語義承諾（Semantic Commitments），並將其生命週期不連續性（Lifecycle Discontinuity）形式化為概念裂隙（Conceptual Rift），即承諾可能在局部範圍內被解決或檢查，但無法在整個生成生命週期（Generation Lifecycle）中保持為可辨識的相同操作單元（Operational Units）。為解決此問題，我們提出 SCOPE，一個規格引導（Specification-Guided）的技能編排（Skill Orchestration）框架，該框架在持續演化的結構化規格（Structured Specification）中維護語義承諾，並針對未解決或被違反的承諾，條件式地調用檢索（Retrieval）、推理（Reasoning）與修復技能（Repair Skills）。為評估承諾層級的意圖實現（Intent Realization），我們引入 Gen-Arena，一個包含實體級規格（Entity-Level Specification）與約束級規格（Constraint-Level Specification）的人工標註（Human-Annotated）基準測試（Benchmark），並提出實體門控意圖通過率（Entity-Gated Intent Pass Rate, EGIP），一個嚴格的實體優先通過標準（Entity-First Pass Criterion）。SCOPE 在 Gen-Arena 上大幅超越所有評估的基準方法（Baselines），達到 0.60 EGIP，並在 WISE-V (0.907) 與 MindBench (0.61) 上也取得優異表現，證明了持續承諾追蹤（Persistent Commitment Tracking）在複雜圖像生成（Complex Image Generation）中的有效性。

### 核心貢獻（3～5點）
- **問題形式化**：提出「語義承諾」（Semantic Commitments）概念，並將其在生成生命週期中的不連續性形式化為「概念裂隙」（Conceptual Rift），揭示現有文字生成圖像模型在複雜意圖實現上的根本瓶頸。
- **方法創新**：提出 SCOPE 框架——一個規格引導的技能編排系統，透過持續演化的結構化規格維護語義承諾，並依據承諾狀態條件式地調用檢索、推理與修復技能，實現跨生成階段的持續承諾追蹤。
- **評測基準**：建構 Gen-Arena 人工標註基準測試，提供實體級與約束級規格，並設計嚴格的實體優先通過標準 EGIP，用以衡量承諾層級的意圖實現程度。
- **實驗驗證**：在 Gen-Arena（0.60 EGIP）、WISE-V（0.907）與 MindBench（0.61）三項基準測試上均取得領先表現，證實持續承諾追蹤機制對複雜圖像生成的有效性。

### 適合對象
- 從事文字生成圖像（Text-to-Image Generation）、多模態生成與可控生成研究的 AI/ML 研究者。
- 關注生成式模型評測方法論、基準測試設計與指標制定的電腦視覺與自然語言處理領域學者。
- 對 LLM 代理式規劃（Planning）、技能編排（Skill Orchestration）與迭代優化（Iterative Refinement）機制感興趣的研究人員。
- 工業實務界中需要將複雜視覺意圖轉化為高品質圖像輸出的應用開發者與產品設計師。

## 深度分析

#### 方法論解析

SCOPE 的核心方法論建立在兩個關鍵概念之上：**語義承諾（Semantic Commitments）** 與 **概念裂隙（Conceptual Rift）**。這兩個概念共同構成了問題形式化與解決方案的理論基礎。

**語義承諾的形式化定義**

語義承諾在本論文中被定義為「最終圖像必須滿足的條件，以實現使用者意圖」。這是一個比傳統 prompt 對齊更為嚴格的概念——它不僅要求圖像看起來合理，更要求每一個具體的視覺要求（實體存在性、屬性正確性、空間關係、約束條件等）都能在最終圖像中被驗證。論文中將這些承諾區分為兩類：顯式承諾（從 prompt 一開始就明確的）與隱式承諾（需要透過外部資訊接地 grounding 或場景推理才能確定的）。這種區分呼應了近期關於複雜視覺意圖實現的研究趨勢（Li et al., 2025a; Son et al., 2025; He et al., 2026a）。

**概念裂隙的識別**

概念裂隙（Conceptual Rift）描述的是一個生命週期不連續性問題：即使一個承諾在生成前被解析、在生成後被檢查、在後續步驟中被修訂，這些操作可能並未與同一個可識別的單元保持連結。論文中列舉了三個具體後果：（1）生成目標被稀釋（generation target may still be diluted）；（2）錯誤被誤歸因（error may be misattributed）；（3）修復動作針對性不足（repair action may be poorly targeted）。這個診斷精準地指出了現有 agentic 圖像生成方法的核心缺陷——它們的「中間表示」通常是為特定介入步驟量身打造的，而非為跨生命週期的承諾維護而設計。

**SCOPE 框架的架構設計**

SCOPE 採用「規格引導（Specification-Guided）」的設計哲學，將**結構化規格（Structured Specification）** 作為跨生成生命週期的共享介面（Shared Interface）。這個規格是「演進式的」（evolving），意味著它會隨著技能輸出與驗證結果的寫入而不斷更新。具體而言：

1. **結構化分解（Structured Decomposition）**：將複雜視覺意圖分解為可操作的語義承諾單元，每個單元都保持可識別性。
2. **條件式技能編排（Conditional Skill Orchestration）**：根據規格中未解決或被違反的承諾，條件式地調用三類技能：
   - **檢索技能（Retrieval Skills）**：接地缺失的外部資訊
   - **推理技能（Reasoning Skills）**：推斷隱式要求
   - **修復技能（Repair Skills）**：修訂被違反的承諾
3. **驗證回寫機制**：將技能輸出與驗證結果寫回規格，形成閉環。

這個設計的關鍵創新在於將「規格」從靜態描述提升為「動態操作介面」，使得每個技能調用都能精確對應到具體的承諾項目，並且其結果能在後續階段被持續追蹤。

**與傳統方法的本質差異**

傳統的多步介入方法（如檢索增強生成、迭代優化、規劃）雖然改善了生成品質的不同面向，但它們的介入是「局部操作」而非「統一生命週期」。SCOPE 的突破在於將這些局部操作統一在一個持續演進的結構化規格之下，使得「承諾」這個語義單元在整個生成過程中保持可表示、可驗證、可操作的統一性。

#### 實驗數據解讀

論文中報告了三個基準測試的結果，每個基準測試評估意圖實現的不同面向：

**Gen-Arena 基準測試（EGIP = 0.60）**

Gen-Arena 是本文新提出的人工標註基準測試，包含實體級與約束級的評估規格。**EGIP（Entity-Gated Intent Pass Rate，實體門控意圖通過率）** 是一個嚴格的「實體優先」通過標準——這意味著只有在所有必要實體都正確生成的前提下，相關約束才算通過。這種設計直接對應於論文中強調的「承諾層級意圖實現」理念：實體是約束的前提條件，缺少實體會導致下游約束無法被有意義地評估。

SCOPE 在 Gen-Arena 上達到 0.60 EGIP，並「大幅超越所有評估的基準方法」。雖然論文中未提供具體基準方法的數值，但「substantially outperforms」的措辭暗示了顯著的改進幅度。考慮到 EGIP 是嚴格的實體優先標準，0.60 的通過率代表著在複雜視覺意圖實現上的一個重要里程碑。

**WISE-V 基準測試（0.907）**

WISE-V 評估的是知識接地（knowledge-grounded）圖像生成能力。SCOPE 在此達到 0.907，這是一個非常高的分數，顯示其在處理需要外部知識接地的複雜場景時具有強大能力。這與 SCOPE 的檢索技能設計直接相關——透過結構化規格引導的條件式檢索，系統能更精確地識別需要外部資訊的承諾項目。

**MindBench 基準測試（0.61）**

MindBench 評估的是心理意象（mental imagery）層面的意圖實現，要求模型理解 prompt 中的隱含意圖。SCOPE 在此達到 0.61，雖然分數看似中等，但考慮到 MindBench 本身的高難度（涉及複雜的隱式意圖推理），這個結果仍具競爭力。

**數據解讀的關鍵洞察**

1. **基準測試的互補性**：三個基準測試分別評估了不同面向——Gen-Arena 強調承諾級追蹤、WISE-V 強調知識接地、MindBench 強調隱式推理。SCOPE 在三者上的強勁表現驗證了其框架的通用性。

2. **EGIP 設計的深意**：實體門控的設計哲學反映了論文中「下游失敗可能是上游缺失實體的後果」的洞察。這避免了將約束違反簡單歸因於約束本身的失敗，而是追溯到根本原因。

3. **改進幅度的相對意義**：在 Gen-Arena 上的「substantial outperformance」暗示了現有基準方法在承諾級追蹤上的根本性不足——它們可能在整體對齊上表現不錯，但在具體承諾的識別與維持上存在系統性缺陷。

#### 與現有研究的比較

**在 Agentic 圖像生成領域的定位**

SCOPE 與近期 agentic 圖像生成工作（Chen et al., 2025a; Ye et al., 2025; Xiang et al., 2025; Wang et al., 2025; Garg et al., 2026; He et al., 2026b; Han et al., 2026）共享「超越直接 prompt 條件化」的設計哲學，但 SCOPE 的獨特貢獻在於：

- **現有方法**：通常從特定介入角度改善生成（強化使用者請求解讀、接地視覺/事實證據、透過反思/反饋優化輸出）
- **SCOPE**：將這些介入統一在一個持續演進的結構化規格之下，確保每個介入都對應到具體的承諾項目

**在技能抽象領域的定位**

與 XSkill（Jiang et al., 2026a）和 GEMS（He et al., 2026b）等技能抽象工作相比：

- **XSkill**：從視覺工具軌跡累積任務級技能，但未探討技能如何與特定任務的演進語義承諾接地
- **GEMS**：為 agent-native 多模態生成引入記憶與領域技能，但同樣未強調技能調用與承諾的精確對應
- **SCOPE**：明確提出「技能使用應基於演進的語義承諾」，使得每次調用都針對具體的未解決或被違反項目，且其結果在後續階段保持可用

**相對於基準方法的改進**

雖然論文中未列出所有基準方法的具體數值，但從「substantially outperforms」的描述可以推斷，現有基準方法在 Gen-Arena 上的 EGIP 應該顯著低於 0.60。這反映了現有方法在「承諾級追蹤」上的根本性不足——即使它們在整體對齊或特定面向（如知識接地、隱式推理）上表現良好，但在維持承諾的可識別性與可操作性方面存在系統性缺陷。

**論文中未明確討論的限制**

從方法論描述中可以推斷幾個潛在限制：

1. **規格設計的複雜度**：結構化規格的設計需要領域知識，如何自動化規格的初始建構與持續演進是一個未明確說明的挑戰。
2. **技能庫的依賴**：SCOPE 的效果依賴於可用的檢索、推理、修復技能，這些技能的品質直接影響框架表現。
3. **計算成本**：多步介入與持續驗證可能帶來較高的計算開銷，論文中未討論效率問題。
4. **泛化性**：雖然在三個基準測試上表現強勁，但對於極度複雜或開放領域的視覺意圖，框架的可擴展性仍待驗證。

- **正面因素**：作為新提出的基準測試，Gen-Arena 的規格化設計（實體與約束的明確標註）有利於標準化評估
- **不確定因素**：論文中未明確說明 Gen-Arena 是否會公開發布、其規模大小、以及標註品質如何保證

**框架實作的可重現性**

論文中未明確提及程式碼開源或模型權重釋出。從方法論描述來看，SCOPE 的實作涉及：

1. 結構化規格的表示格式（未明確說明是 JSON、YAML 或自定義格式）
2. 技能庫的具體內容（檢索、推理、修復技能的具體實作）

這些細節的缺失使得完整重現存在一定挑戰。然而，論文中對方法論的清晰描述（特別是「演進式結構化規格」與「條件式技能編排」的核心思想）為後續實作提供了明確的指導。

**評估指標的可重現性**

EGIP 作為新的評估指標，其「實體優先」的設計哲學是清晰的，但具體的計算細節（如實體識別的容忍度、約束驗證的標準）需要在論文的補充材料或後續工作中進一步明確。

**與現有基準測試的整合**

SCOPE 在 WISE-V（0.907）和 MindBench（0.61）上的表現是可驗證的，因為這些是已存在的公開基準測試。然而，論文中未提供與這些基準測試上其他方法的詳細比較數據，這限制了對「強勁結果」的精確評估。

#### 未來研究方向

**1. 規格表示的自動化與標準化**

當前 SCOPE 的結構化規格設計需要領域知識，未來研究可以探索：

- **自動化規格生成**：利用大型語言模型從 prompt 自動生成初始結構化規格
- **規格演進的學習機制**：讓系統從成功與失敗案例中學習如何更好地演進規格
- **跨任務規格標準化**：建立通用的規格 schema，使得不同任務的承諾能夠統一表示

**2. 技能庫的擴展與組合**

SCOPE 目前聚焦於三類技能（檢索、推理、修復），未來可以探索：

- **更豐富的技能類型**：如規劃技能、抽象技能、創意技能等
- **技能的自動發現與蒸餾**：從成功軌跡中自動發現新的技能模式
- **技能的層次化組合**：將基本技能組合成更複雜的高階技能

**3. 驗證機制的強化**

驗證是 SCOPE 閉環的關鍵環節，未來可以探索：

- **多模態驗證模型**：結合視覺、語言、知識的多模態驗證
- **驗證的可解釋性**：不僅判斷對錯，還能解釋為什麼對錯
- **驗證的主動學習**：從人類反饋中學習更精確的驗證標準

**4. 效率與可擴展性**

多步介入與持續驗證帶來的計算成本是實際應用的障礙，未來可以探索：

- **早期停止機制**：在承諾已滿足時提前終止
- **並行化技能調用**：對於獨立的承諾項目並行處理
- **輕量化規格表示**：減少規格維護的開銷

**5. 跨模態與跨領域延伸**

SCOPE 的核心思想（承諾追蹤與規格引導）可以延伸到：

- **文字生成**：追蹤文本中的語義承諾
- **影片生成**：處理時間維度上的承諾演進
- **3D 生成**：處理空間與結構承諾
- **多模態對話**：在對話中維持跨輪次的承諾

**6. 理論基礎的深化**

概念裂隙的識別為複雜生成任務提供了新的理論視角，未來可以探索：

- **承諾的形式語義**：建立語義承諾的嚴格形式化定義
- **生命週期連續性的形式化**：將概念裂隙轉化為可驗證的數學性質
- **承諾滿足的計算複雜度**：分析不同類型承諾的滿足難度

**7. 人機協作模式**

SCOPE 的結構化規格為人機協作提供了自然介面，未來可以探索：

- **人類在迴路中的承諾編輯**：允許使用者直接修改規格中的承諾
- **可解釋的生成過程**：透過規格展示生成過程中的承諾狀態變化
- **互動式意圖精煉**：透過規格對話逐步精煉使用者的視覺意圖

這些研究方向不僅能進一步提升 SCOPE 框架的能力，也能推動整個複雜視覺意圖實現領域向更系統化、更可解釋、更實用的方向發展。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於複雜圖像生成中的「語義承諾」（Semantic Commitments）難以在整個生成生命週期中保持一致性的問題。具體而言，當使用者給出包含多個實體與約束的複雜提示時，這些需求並非同時可操作，有些需要先透過外部資訊接地（Grounding），有些則需經由推理才能確定。然而，現有的多步介入方法雖然能在局部階段解析或檢查這些承諾，卻無法讓它們在生成、驗證、修復等不同階段中保持可辨識的同一操作單元，從而產生「概念裂隙」（Conceptual Rift）。這個問題的核心在於：如何讓複雜視覺意圖背後的每一條承諾，從頭到尾都能被一致地表示、追蹤與執行。

**Q2：為什麼現有的多步生成方法無法徹底解決這個問題？**
A：現有的多步介入方法（如檢索、規劃、迭代優化等）雖然各自改善了複雜生成的某些面向，但它們的中介表示通常是為特定介入量身打造的，而非為了維持同一組語義承諾貫穿整個生命週期。這意味著即使系統成功檢索到相關資訊或識別出真實錯誤，生成目標仍可能被稀釋、錯誤可能被誤歸因，或修復動作可能對錯目標。換言之，多步化本身並不等於生命週期連續性（Lifecycle Continuity），這正是 SCOPE 試圖填補的關鍵缺口。

**Q3：為什麼這個問題對文字生成圖像領域很重要？**
A：隨著文字生成圖像（Text-to-Image Generation）模型進入實際與創意工作流程，使用者的提示越來越常描述必須嚴格成立的場景細節，視覺保真度（Visual Fidelity）已不再是唯一標準，圖像必須正確實例化使用者意圖描繪的場景。若系統無法在整個生成過程中持續追蹤每一條承諾，就會出現「看起來自然但意圖錯誤」的失敗，這對需要精準視覺內容的應用（例如設計、教育、敘事插畫）將是致命缺陷。因此，建立以承諾為中心的生成與評估框架，是該領域從「看起來像」走向「真的對」的關鍵一步。

**Q4：SCOPE 的核心方法是什麼？**
A：SCOPE 是一個「規格引導」（Specification-Guided）的技能編排（Skill Orchestration）框架，其核心是將視覺意圖表示為一個持續演化的結構化規格（Structured Specification），並以此作為生成、驗證與技能呼叫的共享介面（Shared Interface）。框架會根據規格中尚未解決或已被違反的承諾，條件式地呼叫檢索（Retrieval）、推理（Reasoning）與修復（Repair Skills）等技能，並將技能輸出與驗證結果回寫到規格中。這種設計讓複雜視覺意圖能以統一生命週期推進，而非一系列彼此脫鉤的局部操作。

**Q5：SCOPE 最關鍵的創新點是什麼？**
A：SCOPE 最關鍵的創新在於把「持續承諾追蹤」（Persistent Commitment Tracking）從隱性過程提升為顯性的結構化規格，使每一條語義承諾在接地、生成、驗證、修復等所有階段都保持可辨識、可驗證、可操作的同一單元。這與過去僅針對單一介入設計中介表示的做法形成對比：SCOPE 不是為某一個技能量身訂做表示，而是讓所有技能都圍繞同一份規格運作。這種「以規格為中心」的設計哲學，正是它能緩解概念裂隙、實現承諾級意圖實現（Intent Realization）的根本原因。

**Q6：SCOPE 在設計上有哪些重要的選擇？**
A：SCOPE 的設計選擇體現在三個層面：第一，採用結構化分解（Structured Decomposition）將複雜提示拆解為實體與約束層級的規格，便於精準定位與診斷；第二，採用條件式技能編排（Conditional Skill Orchestration），讓技能呼叫完全由規格中未解決或被違反的條目驅動，而非預先排定流程；第三，強調規格的「演化性」，技能輸出與驗證結果會被持續回寫，使規格隨生成進度動態更新。這三項選擇共同確保了生命週期連續性，也讓系統具備可解釋性與可介入性。

**Q7：論文中使用了哪些基準測試？為什麼選擇它們？**
A：論文中使用了三個基準測試：作者自行提出的 Gen-Arena，以及既有的 WISE-V 與 MindBench。Gen-Arena 是專為承諾級意圖實現設計的人工標註（Human-Annotated）基準，提供實體級與約束級規格，能診斷缺失實體、被違反的約束以及因前置條件未滿足而產生的下游失敗；WISE-V 與 MindBench 則用於驗證 SCOPE 在世界知識與心智理論等既有複雜生成任務上的泛化能力。這樣的組合既能在新指標上展現承諾追蹤的價值，也能在既有基準上證明方法的相容性與穩健性。

**Q8：SCOPE 的關鍵實驗結果為何？**
A：在 Gen-Arena 上，SCOPE 達到 0.60 的 EGIP（Entity-Gated Intent Pass Rate，實體門控意圖通過率），大幅超越所有評比的基準方法（Baselines），證明了以承諾為中心的設計在嚴格的實體優先通過標準（Entity-First Pass Criterion）下具有顯著優勢。在 WISE-V 上取得 0.907 的成績，在 MindBench 上取得 0.61，顯示 SCOPE 不僅在自家基準上表現突出，在世界知識與心智理論等不同面向的複雜生成任務上同樣具備強健的泛化能力。這些結果共同支持了「持續承諾追蹤對複雜圖像生成確實有效」的核心主張。

**Q9：論文中是否有消融實驗支持各設計元件的必要性？**
A：雖然提供的全文片段未完整列出消融實驗（Ablation Studies）的細節，但從方法描述可推論，結構化規格、條件式技能編排與回寫機制應為主要被驗證的元件。每一項設計都對應概念裂隙的不同面向：缺少結構化規格會使承諾無法跨階段保持同一單元；缺少條件式編排會使技能呼叫變成盲目流程；缺少回寫則會讓驗證與修復結果無法回流到後續生成。整體實驗結果（特別是 EGIP 的顯著提升）已間接支持這些元件缺一不可，具體消融數據應參見論文後續章節。

**Q10：SCOPE 適合哪些實際應用場景？**
A：SCOPE 特別適合需要嚴格視覺準確性的場景，例如敘事插畫（必須正確呈現多個角色與其互動）、教育教材（需要精準描繪歷史場景或科學概念）、產品設計（必須同時滿足多項規格約束）、以及廣告與行銷素材（需符合品牌指引與場景設定）。在這些場景中，任何一個實體缺失或約束違反都可能導致整張圖失效，因此以承諾追蹤為核心的 SCOPE 比傳統單次提示生成圖像（One-Shot Prompt-to-Image Generation）更能交付可用結果。

**Q11：將 SCOPE 落地為產品時需要考量哪些因素？**
A：產品化時需考量三個關鍵因素：首先是延遲與成本，多步技能編排會增加推理時間與 API 呼叫次數，需要在品質與回應速度間取得平衡；其次是規格的可編輯性與透明度，應讓使用者能檢視、修正結構化規格，以提升信任度與可控性；第三是錯誤恢復機制，當某條承諾反覆無法滿足時，系統應能優雅降級或提示使用者介入，而非無限迴圈呼叫修復技能。這些考量決定了 SCOPE 能否從研究框架走向穩定的產品體驗。

**Q12：SCOPE 對整個文字生成圖像領域的影響是什麼？**
A：SCOPE 的影響在於把評估與生成兩者都推向「承諾級」視角：在評估面，EGIP 與 Gen-Arena 提供了比整體對齊分數更嚴格、更具診斷力的標準；在生成面，規格引導的技能編排為多步生成提供了統一的中介語言。這種轉變可能促使後續研究不再只追求視覺保真度，而是同時追求「每一條使用者意圖是否被正確實例化」。長遠來看，SCOPE 提出的概念裂隙與持續承諾追蹤，有機會成為複雜生成任務的共同分析框架。

**Q13：論文中承認的限制有哪些？**
A：從全文脈絡可推論，SCOPE 的限制主要在於：依賴高品質的結構化規格建構，若初始承諾抽取或接地不準確，後續所有階段都會受影響；多步介入帶來的計算成本與延遲較高，可能不適合即時應用；以及 Gen-Arena 雖為人工標註，但覆蓋的語意類型仍有限，未必能窮舉所有複雜視覺意圖。這些限制提醒讀者，SCOPE 並非萬能解方，而是針對特定類型的複雜性提供結構化對策。

**Q14：SCOPE 可能會出現哪些失敗案例？**
A：可能的失敗案例包括：當提示中的實體過於模糊或隱喻性過強時，結構化分解可能無法正確拆解承諾；當外部檢索來源品質不佳時，接地階段可能引入錯誤資訊並污染後續生成；以及當多條承諾彼此衝突（例如「同時呈現白天與夜景」）時，條件式技能編排可能陷入反覆修復而無法收斂。此外，若驗證模型本身判斷力不足，也可能將正確生成誤判為違反承諾，導致不必要的修復循環。

**Q15：未來有哪些值得探索的研究方向？**
A：未來方向可分為三類：第一，擴大規格的表達能力，例如支援時序、空間關係與風格約束等更細緻的承諾類型；第二，引入學習式而非規則式的技能編排，讓系統能從大量軌跡中自動習得何時呼叫哪個技能；第三，將承諾追蹤從圖像生成延伸到影片或多模態長序列生成，處理跨時間的一致性問題。這些方向都呼應了論文中「以承諾為中心」的核心理念，也為複雜生成研究開啟了新的設計空間。

## 實務應用指南

### 適用場景

1. **電商商品情境圖生成**：當賣家需要為同一商品（例如「復古風格、放置於木質桌面、搭配綠色植物的陶瓷咖啡杯」）生成多張符合品牌規範的場景圖時，SCOPE 可將「陶瓷咖啡杯」「木質桌面」「綠色植物」「復古風格」等語義承諾分別追蹤，確保檢索風格參考圖、推理構圖、修復色彩偏差等技能都對應到正確的承諾單元，避免出現「杯子換成馬克杯」或「桌面材質錯誤」等下游錯誤。

2. **教育教材插圖自動化**：教科書出版社需要根據課文描述（例如「細胞分裂中期，染色體排列於赤道板上，紡錘絲連接至兩極」）生成精確的科學插圖。SCOPE 的實體優先評估（EGIP）能確保「染色體」「紡錘絲」「兩極」等實體先被正確生成，再檢查「排列於赤道板」等約束是否成立，特別適合需要高實體準確性的 STEM 教材場景。

3. **廣告創意素材 A/B 測試**：行銷團隊常需根據文案（例如「一位 30 歲女性，穿著黃色雨衣，在夜晚的東京街頭撐著透明傘，背景有霓虹燈」）生成多版本素材。SCOPE 可在生成後自動驗證每個承諾是否被滿足，快速診斷「年齡不符」「雨衣顏色錯誤」「缺少霓虹燈」等失敗原因，並針對性地觸發修復技能，縮短創意迭代週期。

4. **室內設計概念圖生成**：室內設計師輸入「北歐風客廳，包含灰色沙發、實木茶几、幾何圖案地毯、大面積落地窗引入自然光」時，SCOPE 能將風格、家具實體、空間約束分開管理，透過檢索技能補充北歐風參考圖，推理技能推斷「自然光」對陰影分布的隱含要求，產出更貼近設計師意圖的概念圖。

5. **遊戲場景概念藝術**：遊戲開發團隊需要根據世界觀文件生成大量場景圖，SCOPE 的結構化規格可作為美術團隊與 AI 系統之間的共享介面，使「中世紀城堡」「石橋護城河」「夕陽光線」等承諾在多次迭代中保持可識別性，方便美術總監針對特定承諾下達修改指令。

### 實作前置條件

**資料準備**
- **基礎文字生成圖像模型**：需具備支援長 prompt 解析的 T2I 模型（如 Stable Diffusion 3、FLUX、Imagen 3 等），作為最終圖像生成引擎。
- **多模態理解模型**：用於解析 prompt 中的實體與約束、驗證生成結果，建議使用 GPT-4V、Gemini 2.0 或開源的 Qwen2-VL、LLaVA-OneVision 等視覺語言模型。
- **檢索語料庫**：根據應用領域準備視覺參考圖庫（風格參考、實體參考）與文字知識庫（領域事實、隱含常識），可使用 CLIP、BLIP-2 等建立多模態索引。
- **評估標註資料**：若要建立自有 Gen-Arena 風格基準，需準備人工標註的實體級與約束級評估規格，每個 prompt 至少需要 3 位標註者達成一致性協議。

**運算資源**
- **推論階段**：單次複雜生成需 1 張高階 GPU（如 A100 80GB 或 H100），用於 T2I 模型與視覺語言模型的並行推論；多輪迭代場景建議配置 2–4 張 GPU。
- **訓練階段（可選）**：若要微調技能選擇策略或驗證器，需準備 8 張以上 GPU 的叢集，並使用 DeepSpeed ZeRO-3 或 FSDP 進行分散式訓練。
- **儲存與快取**：結構化規格的中間狀態、檢索結果、驗證歷史需持久化，建議配置向量資料庫（如 Milvus、Qdrant）與物件儲存。

**技能門檻**
- **LLM 代理開發經驗**：熟悉 LangChain、AutoGen 或自建 agent 框架，能設計條件式技能呼叫邏輯。
- **結構化輸出設計**：能設計可演化的規格 schema（建議使用 Pydantic 或 JSON Schema），並處理欄位新增、狀態轉移、版本控制。
- **多模態評估能力**：理解 VLM-as-a-Judge 的偏差與限制，能設計 prompt 緩解位置偏差、肯定偏差等問題。
- **領域知識**：對目標應用領域（如電商、教育、遊戲）的視覺構成與常見錯誤模式有基本理解。

### 實作步驟建議

**階段一：規格設計（第 1–2 週）**
1. 盤點目標應用場景的 prompt 類型，歸納出常見的實體類別（如人物、物品、場景元素）與約束類別（如風格、數量、空間關係、屬性）。
2. 設計結構化規格 schema，明確區分「實體」「約束」「隱含承諾」「驗證狀態」「修復歷史」等欄位，並定義狀態轉移規則（如 `unresolved → grounded → generated → verified`）。
3. 建立規格的版本控制機制，確保每次技能呼叫與驗證的結果都能回寫到同一個承諾單元。

**階段二：技能庫建置（第 3–4 週）**
1. 實作三類核心技能：
   - **檢索技能**：根據未接地的承諾，從向量資料庫檢索視覺或文字參考。
   - **推理技能**：根據已接地的承諾，推斷隱含約束（如「夜晚」→ 光源方向、陰影強度）。
   - **修復技能**：根據驗證失敗的承諾，產生針對性的 prompt 修改或局部重繪指令。
2. 為每個技能設計輸入輸出契約，使其能讀寫結構化規格。
3. 建立技能選擇策略，可使用規則式（基於承諾狀態）或學習式（基於 LLM 的 policy）。

**階段三：生成與驗證迴圈（第 5–6 週）**
1. 串接 T2I 模型與 VLM 驗證器，建立「生成 → 驗證 → 診斷 → 修復」的閉環。
2. 實作 EGIP 風格的實體優先評估：先檢查所有必要實體是否出現，再檢查約束是否滿足。
3. 設定最大迭代次數與終止條件（如所有承諾 `verified` 或達到上限），避免無限迴圈。

**階段四：基準建構與迭代（第 7–8 週）**
1. 蒐集 200–500 個領域內的典型 prompt，由 3 位標註者建立實體級與約束級評估規格。
2. 計算標註者間一致性（Cohen's Kappa 或 Krippendorff's alpha），過濾低一致性樣本。
3. 在基準上評估 SCOPE 與基線方法，診斷失敗案例，迭代優化規格 schema 與技能庫。

**階段五：產品化整合（第 9 週以後）**
1. 將規格狀態可視化，提供「為什麼這張圖失敗」「哪個承諾被違反」的診斷介面。
2. 提供人工介入點，讓使用者能標記錯誤的承諾解析或新增自訂承諾。
3. 建立監控指標：平均迭代次數、承諾通過率、技能呼叫成功率、使用者修改率。

### 潛在風險與注意事項

**風險一：規格膨脹與維護成本**
- **現象**：隨著應用場景擴展，規格 schema 持續新增欄位，導致舊資料不相容、技能契約混亂。
- **緩解**：採用語意化版本控制（semantic versioning），對規格變更進行向後相容性測試；定期重構 schema，淘汰低使用率欄位。

**風險二：VLM 驗證器的可靠性瓶頸**
- **現象**：視覺語言模型在細粒度實體計數、空間關係判斷上仍有顯著錯誤率，可能誤判承諾是否滿足。
- **緩解**：採用 ensemble 驗證（多個 VLM 投票）、結合 CLIP 相似度與物件偵測器（如 Grounding DINO）的混合驗證；對高風險承諾保留人工抽檢。

**風險三：技能呼叫的雪球效應**
- **現象**：一次修復失敗可能觸發連鎖技能呼叫，導致迭代次數膨脹、延遲增加、成本失控。
- **緩解**：設定每個承諾的最大修復次數、總迭代預算；實作「承諾優先級」機制，先修復高優先級承諾；對低信心修復直接降級為人工標記。

**風險四：概念裂隙的隱性殘留**
- **現象**：即使有結構化規格，仍可能在技能輸出回寫時遺失上下文，導致承諾單元在後續階段被誤識別。
- **緩解**：為每個承諾分配穩定的唯一識別碼（UUID），所有技能輸入輸出都必須攜帶此 ID；定期進行「承諾可追溯性」稽核。

**風險五：基準過擬合風險**
- **現象**：在 Gen-Arena 上表現優異的方法，可能過度擬合該基準的 prompt 分布，無法泛化到真實使用者輸入。
- **緩解**：建立多樣化的內部測試集，涵蓋長尾場景；採用留出法（hold-out）評估；監控真實使用者資料上的承諾通過率分布。

**風險六：延遲與成本**
- **現象**：多輪迭代顯著增加單次生成的延遲（可能從 5 秒增至 60 秒以上）與 API 成本。
- **緩解**：對簡單 prompt 啟用快速路徑（單次生成 + 輕量驗證）；快取常見承諾的檢索結果；使用較小的 VLM 進行初步篩選。

### 與其他技術的整合建議

**與 RAG 系統整合**
SCOPE 的檢索技能可作為多模態 RAG 系統的「承諾感知」入口。建議將向量資料庫的 metadata 與 SCOPE 的承諾 schema 對齊，使檢索結果能自動標註對應的承諾 ID。對於需要高度事實準確性的場景（如歷史場景、科學插圖），可整合知識圖譜（如 Wikidata、ConceptNet）作為推理技能的後端。

**與 ControlNet / IP-Adapter 等條件控制整合**
SCOPE 的結構化規格可作為 ControlNet 條件圖的生成依據。例如，「空間關係」承諾可轉換為深度圖或邊緣圖，「風格」承諾可透過 IP-Adapter 注入。這種整合能讓承諾級的控制訊號直接影響生成過程，而非僅依賴 prompt 文字。

**與 Diffusion 修復模型整合**
當修復技能需要局部重繪時，可整合 Stable Diffusion Inpainting 或 FLUX Fill 模型。建議將「被違反的承諾」與其對應的遮罩區域一同傳遞給修復模型，避免修復時破壞其他已通過的承諾。

**與工作流編排工具整合**
SCOPE 的條件式技能編排邏輯可封裝為 LangGraph、Prefect 或 Temporal 等工作流引擎的節點，使非技術使用者能透過視覺化介面調整技能呼叫順序與條件。這對產品化尤其重要。

**與 MLOps 平台整合**
將結構化規格、驗證結果、技能呼叫日誌接入 MLflow 或 Weights & Biases，便於追蹤每次生成的完整生命週期、診斷系統性失敗模式、累積訓練資料以持續優化技能選擇策略。

**與人類回饋系統整合**
在使用者標記「這張圖哪裡不對」時，將回饋直接對應到具體的承諾 ID，而非整體評分。這種細粒度回饋可用於 RLHF 或 DPO，持續優化承諾解析器與驗證器。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的問題描述，理解「為什麼複雜 prompt 的圖像生成很難」這個直覺問題，再讀第 3.1 節的整體 pipeline 圖，建立「規格 → 技能 → 驗證」的循環心智模型。暫時跳過技術細節，重點體會「把需求拆成可追蹤的承諾」這個核心思想，這對理解所有 agentic 系統都有幫助。

**給 AI 工程師**：重點閱讀第 3.1 節的規格 schema 設計與技能契約，理解如何將抽象的「語義承諾」落地為可程式化的資料結構。建議實際動手實作一個最小可行版本：用 Pydantic 定義規格、用 LangChain 串接檢索與驗證、用 Stable Diffusion 作為生成後端，在 50 個自建 prompt 上驗證概念，再逐步擴充技能庫。

**給研究者**：第 1 節的「Conceptual Rift」概念定義與第 3.2 節的 Gen-Arena 建構方法是論文的學術核心，值得仔細推敲。建議從三個方向延伸：(1) 探索更高效的承諾表示（如階層式、圖狀結構）；(2) 研究承諾級的因果歸因方法，診斷失敗的根因；(3) 將 EGIP 推廣到影片生成、3D 生成等其他模態，檢驗概念裂隙是否普遍存在。

**給產品經理**：重點理解 SCOPE 解決的「使用者意圖未被完整實現」這個商業問題，以及 EGIP 如何提供比傳統 FID、CLIPScore 更貼近使用者滿意度的評估指標。在規劃產品時，建議將「承諾通過率」作為核心 KPI，並設計讓使用者能標記具體失敗點的介面，這將同時提升使用者體驗與累積寶貴的訓練資料。
