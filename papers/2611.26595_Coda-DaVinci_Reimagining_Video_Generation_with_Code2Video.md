## 論文問答

**Q1：當前的影片生成模型面臨哪些核心挑戰，使得 Code2Video 這種新典範變得必要？**
A：當前的影片生成模型雖然在視覺品質與動作流暢度上已有長足進步，但在三個關鍵面向仍力有未逮：遵循複雜且細節化的指令、維持跨時間軸的場景狀態一致性，以及生成物理上合理的互動效果。這些限制源自於擴散式生成模型本質上以統計紋理與動作為主，缺乏對場景結構與物件關係的明確表徵。Code2Video 透過讓編碼代理先建構可執行的 3D 場景程式，再以此代理模型引導影片合成，正好補上了「顯式場景控制」這一塊缺口，使攝影機重訪同一場景時仍能維持一致的空間佈局與物件狀態。

**Q2：為什麼單純的「代理模型引導」並不一定能帶來品質提升？現有方法在哪些情境下會失效？**
A：代理模型的品質高度依賴其建構方式與任務特性，並非「越詳細越好」。當任務以動作自然度為核心、且場景控制帶來的邊際效益有限時，一個不完美的代理模型反而會把幾何或動作瑕疵傳遞到最終影片，產生比直接生成更僵硬、更不自然的結果。此外，代理模型粒度的選擇、是否採用物理模擬、以及合成提示詞是否與代理實體對齊，都會顯著影響下游品質——這說明 Code2Video 並非萬靈丹，而是一組需要依任務調校的設計取捨。

**Q3：為什麼「任務相依的權衡」是理解 Code2Video 能力的關鍵，而非單一通用結論？**
A：本文透過控制變因實驗與盲測人工評估，揭示了不同任務對代理模型的需求截然不同：在動作密集的任務中，粗粒度代理模型反而能保留較自然的動作；而在需要物理模擬的任務中，中粒度代理模型則提供更強的場景一致性。這意味著任何「代理模型永遠優於直接生成」或「越詳細越好」的論述都過於簡化。唯有正視這種任務相依的權衡，才能設計出真正實用的影片生成系統，而非在所有情境下套用同一種策略。

**Q4：Coda-DaVinci 的核心方法論是什麼？它如何實現「任務自適應」？**
A：Coda-DaVinci 的核心是一個任務自適應的代理式框架，會根據任務特性在「代理模型引導生成」與「直接生成」之間動態切換。當任務需要精確的場景或動作控制時（例如切割、剝除包裝等結構性互動），系統會啟動 3D 建模流程；而當任務以自然肢體動作為主、且代理動畫可能導致僵硬時，系統則傾向直接生成。這種選擇不是事先硬編碼，而是由編碼代理根據任務語意即時判斷，從而兼顧控制力與自然度。

**Q5：Coda-DaVinci 在代理模型設計上做了哪些關鍵的細粒度決策？**
A：在決定建模場景時，Coda-DaVinci 對不同實體採用不同的建模粒度：環境與結構化物件使用中粒度代理模型，人類主體則使用粗粒度代理模型——因為過於細緻的人體模型容易產生僵硬感，而細節的肢體動作可交由影片生成模型負責。此外，對於支援的物理互動，系統會調用 Blender 物理模擬而非腳本化動作，以獲得更真實的動力學行為。這種「分實體、分粒度」的設計是 Coda-DaVinci 區別於 VideoCoCo 等一律建模手部與手臂的方法的關鍵創新。

**Q6：Coda-DaVinci 的多代理框架如何確保生成品質與迭代修復能力？**
A：Coda-DaVinci 採用多代理框架來維持一個持久的場景工作區，使其能跨修訂與跨請求保留場景資產。編碼代理在寫入合成提示詞前會先進行視覺檢查，確認代理模型的外觀與動作是否符合預期；接著由獨立的驗收代理檢視最終影片是否滿足所有需求，並在發現未達成的條件時觸發修復流程。這種「代理撰寫提示詞＋視覺檢查＋獨立審查」的三層機制，使系統能在不斷迭代中逼近任務要求，而非一次性生成後即結束。

**Q7：Coda-DaVinci 在哪些基準測試上取得了領先成果？具體數據為何？**
A：在指令遵循方面，Coda-DaVinci 在 VTR 基準上領先所有比較方法；在場景一致性方面，則於 R2M 基準上居於首位。在物理合理性方面，系統於 World Models' Last Exam in Physics 上相較直接生成有明顯改善；在視覺真實感方面，於 T2AV-Compass 子集上超越了比較的 Code2Video 基線，逼近直接生成的水準。這些結果橫跨四個不同面向的基準，顯示 Coda-DaVinci 並非僅在單一指標上突出，而是具備較全面的能力提升。

**Q8：代理與生成器的配對以及渲染引擎的選擇會如何影響最終品質？**
A：本文的消融實驗顯示，不同的編碼代理與影片生成模型配對會產生不同的結果，並非所有組合都能發揮代理模型的優勢。在渲染引擎方面，Blender 相較 Three.js 能提供更高的視覺品質，但代價是更高的 token 消耗——這是一個明確的品質與成本權衡。這些發現提醒實務部署者：選擇 Coda-DaVinci 的元件時，必須同時考量任務需求、預算限制與品質目標，而非單獨優化某一個環節。

**Q9：長影片與多輪互動評估揭示了哪些額外的優勢與限制？**
A：在長影片與多輪互動設定下，Coda-DaVinci 相較直接延續生成展現了更佳的長程事件結構與跨場景一致性，證明了代理模型在維持敘事連貫性上的價值。然而，這些評估也暴露出兩個明顯的限制：轉場穩定性較低，以及對場景設定（如背景、道具擺放）的遵循度不如預期。這說明代理模型引導在「維持結構」上有效，但在「平滑過渡」與「細節遵循」上仍有改進空間。

**Q10：Coda-DaVinci 適合哪些實際應用場景？哪些場景可能不適合？**
A：Coda-DaVinci 特別適合需要精確場景控制、複雜物理互動或多次場景重訪的任務，例如教學影片、產品示範、烹飪教學、以及需要展示因果關係的科學演示。在這些場景中，3D 代理模型能確保物件狀態在攝影機移動後仍正確無誤。然而，對於以自然肢體動作或情緒表達為核心的場景（如舞蹈、戲劇表演），代理模型引導可能反而限制動作的自然度，此時直接生成會是更好的選擇。

**Q11：在產品化部署 Coda-DaVinci 時，需要考量哪些成本與品質的權衡？**
A：產品化時最關鍵的權衡是 token 成本與視覺品質的平衡：使用 Blender 而非 Three.js 雖能提升品質，但會顯著增加 token 消耗；此外，啟動 3D 建模流程本身也比直接生成耗費更多資源。因此，系統需要一個智慧的路由器，僅在代理模型能帶來明顯效益的任務上啟動完整流程，否則應退回直接生成以控制成本。這種「按需啟用」的設計正是 Coda-DaVinci 任務自適應精神的延伸。

**Q12：Coda-DaVinci 對影片生成領域的整體影響為何？它改變了哪些研究範式？**
A：Coda-DaVinci 的最大影響在於將「代理模型引導」從一個籠統的概念轉化為一套可依任務調校的工程方法論，迫使研究者正視代理模型粒度、物理模擬與提示詞對齊等細節設計。它也展示了多代理框架在影片生成中的潛力——透過視覺檢查與獨立審查實現迭代修復，這是傳統端到端模型難以做到的。更廣泛地看，這項工作推動了影片生成從「單一模型一次生成」轉向「代理協調多次生成」的範式轉移，為未來更複雜的影片創作系統奠定基礎。

**Q13：Coda-DaVinci 明確承認的限制有哪些？**
A：作者坦誠指出兩個主要限制：第一，在長影片評估中，轉場穩定性低於直接延續生成，意味著場景切換時容易出現不連貫；第二，對場景設定（如背景細節、道具擺放）的遵循度不如預期，顯示代理模型在「細節遵循」上仍有不足。此外，雖然 Coda-DaVinci 在多項基準上領先，但其在視覺真實感上仍「逼近」而非「超越」直接生成，說明代理模型引導在純視覺品質上仍有天花板。

**Q14：在哪些失敗案例中，Coda-DaVinci 的表現尤其不佳？**
A：從圖 2(a) 的對比可見，當任務涉及複雜的手部操作（如「切開葉子包裹的米糕並剝開包裝」）時，雖然 Coda-DaVinci 透過選擇性建模避免了 VideoCoCo 與 Codex+Blender 過度建模手部而產生的僵硬感，但仍可能在細微的手部動作協調上失敗。此外，在長影片的轉場時刻，系統容易出現場景設定偏離原始描述的情況，這是「代理模型引導」與「敘事連貫性」之間尚未完全解決的張力。

**Q15：基於本文發現，未來有哪些值得探索的研究方向？**
A：未來研究可朝幾個方向推進：首先，發展更智慧的代理模型路由器，使其能更精準地判斷何時該啟動 3D 建模、何時該直接生成，以進一步降低不必要的 token 成本；其次，設計專門針對長影片轉場穩定性與場景設定遵循度的機制，可能需要結合長上下文記憶或檢索增強生成；最後，探索更細緻的代理模型粒度控制方法，例如根據實體在畫面中的重要性動態調整細節層次，使控制力與自然度能同時達到最佳平衡。

## 實務應用指南

### 適用場景

1. **教育與教學影片製作**：當需要展示具備明確空間結構的物理過程（如化學反應裝置、力學實驗、烹飪步驟）時，Coda-DaVinci 的代理模型引導生成能維持場景一致性，避免物體在長影片中突然消失或變形，特別適合 STEM 教學內容。

2. **電商產品展示與操作教學**：對於需要展示產品拆解、組裝或使用流程的影片（例如「拆開葉子包裹的米餅」這類任務），系統可對結構化物件採用中粒度代理模型，而將手部細節交給影片生成模型處理，兼顧物理合理性與動作自然度。

3. **遊戲與動畫預覽（Pre-visualization）**：在正式動畫製作前，團隊可使用此框架快速生成具備場景重訪一致性的概念影片，透過 Blender 物理模擬驗證鏡頭運動與物件互動的可行性。

4. **多鏡頭敘事短片**：對於需要在不同時間點回到同一場景的敘事內容（如巡邏、偵探故事），代理模型能維持場景狀態，解決直接生成中常見的「葉子重新出現」等一致性問題。

5. **物理模擬驗證內容**：在 World Models' Last Exam in Physics 等基準上，需要展示重力、碰撞、流體等物理現象的影片生成任務。

### 實作前置條件

**資料需求**
- 任務描述文字提示詞（可選圖片或影片參考）
- 領域相關的評估基準資料集（如 VTR、R2M、T2AV-Compass）
- 用於盲測人工評估的標註指引與評分標準

**運算資源**
- 影片生成模型 API 或自託管環境（論文中使用 Seedance 等模型）
- Blender 授權與運算資源（用於中粒度代理模型與物理模擬）
- Three.js 環境（作為較低成本替代方案）
- 多代理 LLM 推理資源（編碼代理、視覺檢查代理、獨立審查代理）

**技能要求**
- 熟悉 Blender 3D 建模、腳本化動畫與物理模擬設定
- 理解 LLM 代理編排（agent orchestration）與工具呼叫（tool calling）
- 具備影片生成模型的提示詞工程經驗
- 能設計任務自適應的路由邏輯（task-adaptive routing）

### 實作步驟建議

**步驟一：建立任務分類器**
根據任務特性預判是否需要 3D 代理模型。判斷依據包括：是否涉及場景重訪、是否需要精確的物件軌跡控制、肢體動作自然度是否為首要考量。對於單純肢體動作展示且無需場景控制的任務，優先採用直接生成。

**步驟二：選擇代理模型粒度**
- **環境與結構化物件**：使用中粒度代理模型（medium-grained proxy），搭配 Blender 物理模擬
- **人類主體**：使用粗粒度代理模型（coarse proxy），將細部動作交給影片生成模型
- **物理互動**：在 Blender 支援的範圍內啟用物理模擬

**步驟三：建構編碼代理工作流**
編碼代理負責：(1) 根據任務與參考媒體生成 3D 代理模型；(2) 渲染代理影片；(3) 撰寫代理模型對齊的合成提示詞（proxy-aligned prompting），將外觀參考連結到代理模型中的具體實體。

**步驟四：實作多代理框架（multi-agent harness）**
- 持久化場景工作區（persistent scene workspace），跨修訂與連續請求保留場景資產
- 視覺檢查代理：對代理模型與生成影片進行視覺檢查
- 獨立審查代理（acceptance agent）：識別未滿足的需求並觸發修復迴圈

**步驟五：合成與評估**
將代理影片、合成提示詞與參考媒體送入影片生成模型。使用 VTR 評估指令遵循度、R2M 評估場景一致性，並進行盲測人工評估以驗證視覺真實感與物理合理性。

**步驟六：長影片與多輪評估**
針對長影片任務，評估事件結構、場景一致性、轉場穩定性與場景設定遵循度，識別系統在連續互動中的限制。

---

### 潛在風險與注意事項

**風險一：代理模型錯誤傳遞至最終影片**
幾何錯誤或動作錯誤會從代理模型擴散到生成結果。**緩解措施**：在視覺檢查階段嚴格把關代理模型品質；對高風險任務保留直接生成作為備援路徑。

**風險二：肢體動作僵硬**
過度細緻的人類主體代理模型會導致動作不自然。**緩解措施**：對人類主體一律採用粗粒度代理模型，將細部動作交給影片生成模型處理。

**風險三：Token 成本過高**
Blender 物理模擬與中粒度代理模型會顯著增加 token 消耗。**緩解措施**：在成本敏感場景下評估 Three.js 替代方案；建立任務分級機制，僅對高價值任務啟用完整管線。

**風險四：長影片轉場不穩定**
論文明確指出長影片在轉場穩定性與場景設定遵循度上仍有不足。**緩解措施**：將長影片拆解為多個短片段分別生成；在銜接處加入額外的視覺檢查與修復步驟。

**風險五：提示詞對齊失敗**
代理模型撰寫的提示詞若未與代理實體對齊，會降低生成品質。**緩解措施**：在提示詞中明確標註代理模型中的實體 ID 與外觀參考；採用獨立審查代理驗證提示詞與代理模型的一致性。

**風險六：基準表現不等於實際表現**
在 VTR 與 R2M 上的領先未必代表所有任務類型都優於直接生成。**緩解措施**：建立領域特定的評估集，避免僅依賴通用基準做決策。

### 與其他技術的整合建議

**與影片生成模型整合**
Coda-DaVinci 設計為模型無關（model-agnostic）的框架，可與 Seedance、Veo、Sora 等影片生成模型搭配。建議建立模型效能矩陣，記錄不同代理模型粒度與不同生成模型組合下的表現，作為路由決策的依據。

**與 3D 資產管線整合**
可將 Blender 場景與現有 DCC（Digital Content Creation）工具鏈（如 Maya、Houdini）整合，複用企業已有的 3D 資產庫。代理模型渲染輸出建議採用標準格式（如 EXR 序列、MP4），便於與既有影片後製流程銜接。

**與 LLM 代理平台整合**
多代理框架可基於 LangGraph、AutoGen 或 CrewAI 等代理編排平台實作。視覺檢查代理可串接 GPT-4V、Claude Vision 等視覺理解模型；獨立審查代理可採用不同模型家族以增加審查獨立性。

**與影片編輯與後製系統整合**
生成的代理模型引導影片可導入 DaVinci Resolve、Adobe Premiere 等 NLE 系統進行進一步剪輯。建議保留代理模型與生成影片的對應關係（metadata），便於後續修改時重新觸發生成。

**與評估與監控系統整合**
整合 VTR、R2M、T2AV-Compass 等基準的評估腳本，並建立持續監控儀表板，追蹤指令遵循度、場景一致性、物理合理性等指標在生產環境中的表現。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的圖 2，理解「代理模型引導生成」與「直接生成」的視覺差異，再閱讀第 3.1 節的公式 (1) 掌握基本管線概念。實際操作時，可從簡單的單一物件任務開始，體驗代理模型如何影響最終影片。

**給 AI 工程師**：重點關注第 3 節的實證分析與第 1 節中 Coda-DaVinci 的系統設計。建議直接閱讀「任務自適應路由」、「多代理框架」與「代理模型對齊提示詞」三個機制的實作細節，並思考如何將其抽象為可重用的軟體元件。論文中的代理–生成模型配對實驗與渲染引擎比較（Blender vs. Three.js）對架構選型特別有參考價值。

**給研究者**：第 3 節的控制變因實驗設計是本文最具學術價值之處，建議仔細研讀代理模型粒度、物理模擬、提示詞三個因子的實驗結果與任務相依的權衡（task-dependent trade-offs）。此外，長影片評估中揭示的「轉場穩定性」與「場景設定遵循度」限制，是值得延伸探索的研究方向。

**給產品經理**：聚焦於第 1 節的應用情境與第 3 節的任務相依權衡。理解「並非所有任務都適合代理模型引導」是關鍵——對於肢體動作展示類內容，直接生成可能更自然且成本更低。建議根據目標使用者的核心需求（一致性 vs. 自然度 vs. 物理合理性）來決定是否採用此框架，並將 token 成本納入商業模式評估。
