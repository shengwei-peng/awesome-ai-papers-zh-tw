## ⚡ TL;DR

端到端解析器將版面與內容序列化，導致解碼路徑過長且獨立區域無法並行。
PaDoc 以預測版面為共享頁面表示的分支，透過前綴條件分解與遮蔽平行解碼並行生成區域內容。
在 OmniDocBench 上取得頂尖整體分數，並顯著提升吞吐量與降低延遲。

## 摘要翻譯

端到端文件解析器（End-to-end Document Parsers）提供了統一的介面，但將頁面佈局（Page Layouts）與區域內容（Regional Contents）序列化（Serialization）為單一自迴歸序列（Autoregressive Sequence）。這種形式迫使獨立區域走上隨總內容量增長的解碼路徑；而裁切式兩階段解析器（Crop-based Two-stage Parsers）雖然提供區域層級的平行性，卻以重複的視覺預填充（Visual Prefills）與碎片化的頁面上下文（Fragmented Page Context）為代價。為了在移除相依性的同時保留完整頁面上下文（Full-page Context），我們提出 PaDoc，一種佈局導向解析器，將預測佈局（Predicted Layout）視為共享頁面表示（Shared Page Representation）之上的分支結構（Branching Structure）。在區域充分性假設（Region-Sufficiency Assumption）下，我們推導出一種前綴條件分解（Prefix-Conditioned Factorization），使佈局流（Layout Stream）與區域內容分支（Regional Content Branches）能夠同步推進，將解碼深度縮減至最長佈局-內容路徑（Longest Layout-Content Path）。我們在單一多模態大型語言模型（Multimodal Large Language Model, MLLM）中實現此分解：透過打包可變長度祖先注意力（Packed Variable-Length Ancestor Attention），在標準下一個詞元訓練（Next-Token Training）中保留可見性；並透過遮蔽平行解碼（Masked Parallel Decoding）建立分支，再由評估所用的 vLLM 後端（vLLM Backend）以並發請求（Concurrent Requests）方式服務，同時搭配快取常駐共享前綴重用（Cache-Resident Shared-Prefix Reuse）。在 OmniDocBench Full 上，PaDoc 達到 91.1 的整體佈局 F1（Overall Layout F1），並在端到端解析器中取得頂尖的整體分數（Overall Score）94.24，同時擁有最佳的文字編輯距離（Text Edit）0.038 與公式 CDM（Formula CDM）95.59。在 384 頁子集與單張 A800 GPU 上，它在五個並發層級（Concurrency Levels）中皆為最快的端到端解析器，相較於相同骨幹的序列式 SFT 基線（Sequential SFT Baseline），有效頁面吞吐量（Valid-Page Throughput）提升 67.4–118%，P95 延遲（P95 Latency）降低 39.2–54.9%。程式碼可於 https://github.com/Longin-Yu/Padoc 取得。

### 核心貢獻（3～5點）
- 提出佈局導向平行解碼（Layout-Grounded Parallel Decoding）架構，將預測佈局（Predicted Layout）視為共享頁面表示（Shared Page Representation）上的分支結構（Branching Structure），在保留完整頁面上下文（Full-page Context）的同時移除區域間相依性，將解碼深度縮減至最長佈局-內容路徑（Longest Layout-Content Path）。
- 在區域充分性假設（Region-Sufficiency Assumption）下推導前綴條件分解（Prefix-Conditioned Factorization），使佈局流（Layout Stream）與區域內容分支（Regional Content Branches）可同步推進。
- 於單一多模態大型語言模型（MLLM）中實現上述分解：透過打包可變長度祖先注意力（Packed Variable-Length Ancestor Attention）支援標準下一個詞元訓練（Next-Token Training），並以遮蔽平行解碼（Masked Parallel Decoding）結合 vLLM 後端（vLLM Backend）的並發請求（Concurrent Requests）與快取常駐共享前綴重用（Cache-Resident Shared-Prefix Reuse）加速推論。
- 在 OmniDocBench Full 上達到頂尖的端到端文件解析效能（整體分數 94.24、整體佈局 F1 91.1），並在 A800 GPU 上相較序列式 SFT 基線（Sequential SFT Baseline）顯著提升有效頁面吞吐量（Valid-Page Throughput）並降低 P95 延遲（P95 Latency）。

### 適合對象
適合多模態文件理解、端到端文件解析（End-to-end Document Parsing）、視覺語言模型加速，以及關注大規模文件智慧系統訓練與推論效率的研究者與工程師。尤其推薦給希望以單一多模態大型語言模型（MLLM）同時提升解析準確度與解碼速度的讀者。

## 深度分析

#### 方法論解析

##### 問題建模與機率分解

PaDoc 將文件解析（Document Parsing）視為一個聯合生成問題：給定頁面影像 \(X\)，模型需要同時預測頁面佈局（Page Layouts）\(B=(b_1,\dots,b_N)\) 與各區域內容（Regional Contents）\(Y=(Y_1,\dots,Y_N)\)。傳統端到端文件解析器（End-to-end Document Parsers）把 \((b_k, Y_k)\) 交錯序列化為單一自迴歸序列（Autoregressive Sequence），導致因果解碼器（Causal Decoder）必須先完成 \(Y_k\) 才能生成 \(b_{k+1}\)。其關鍵路徑（Critical Path）因此與所有區域內容長度之總和成長，對於包含大量可獨立識別區域（Independently Recognizable Regions）的頁面特別昂貴。

PaDoc 的核心理論基礎是**區域充分性假設（Region-Sufficiency Assumption）**：在給定頁面影像 \(X\) 與該區域佈局 \(B_k\) 的條件下，區域 \(k\) 的內容 \(Y_k\) 與其他區域的內容條件獨立。此假設允許將聯合機率重新分解為**前綴條件分解（Prefix-Conditioned Factorization）**：

\[
P(B,Y\mid X)=\prod_k P(b_{k+1}\mid X,B_{\le k})\,P(Y_k\mid X,B_{\le k}).
\]

在這個分解中，**佈局流（Layout Stream）**負責預測下一個區域的佈局 \(b_{k+1}\)，而對應的**區域內容分支（Regional Content Branches）**則同時預測當前區域的內容 \(Y_k\)；兩者共享相同前綴 \((X,B_{\le k})\)。由於各區域內容分支之間不再互相依賴，解碼深度從「所有內容長度總和」降為**最長佈局-內容路徑（Longest Layout-Content Path）**，亦即 \(\max_k\{\text{生成 }B_{\le k+1}\text{ 的長度}+\text{生成 }Y_k\text{ 的長度}\}\)。因為佈局詞元（Token）數量遠少於內容詞元，實際加速效果接近將頁面內容的最大區域長度取代總長度。

##### 訓練階段：打包可變長度祖先注意力

PaDoc 並未採用獨立的偵測頭（detector head）或辨識頭（recognizer head），而是在單一多模態大型語言模型（Multimodal Large Language Model, MLLM）內實現上述分解。訓練時使用**打包可變長度祖先注意力（Packed Variable-Length Ancestor Attention）**：每個區域內容分支的詞元只能看見影像前綴（Image Prefix）與其祖先佈局前綴（Layout Prefix），而看不見其他區域的內容詞元；佈局詞元則維持標準的因果注意力。

為了避免物質化一個巨大的密集注意力遮罩（dense attention mask），作者將不同長度的區域內容分支打包（pack）成批次，並以可變長度方式實現祖先可見性。這樣做的好處是保留了標準**下一個詞元訓練（Next-Token Training）**目標，無需設計特殊的損失函數或改變模型結構，就能讓模型學會「在共享頁面表示（Shared Page Representation）上進行分支生成」。

##### 推論階段：遮蔽平行解碼與 vLLM 服務

在推論時，PaDoc 使用**遮蔽平行解碼（Masked Parallel Decoding）**：當佈局流產生區域結束符號（region-closing tokens）後，系統即從共享前綴分叉出獨立的內容串流。每個分支在相同的祖先可見性下自迴歸生成，但彼此之間不干擾。為了實現真正的平行執行，作者將這些分支作為**並發請求（Concurrent Requests）**送進 **vLLM 後端（vLLM Backend）**，並利用 **快取常駐共享前綴重用（Cache-Resident Shared-Prefix Reuse）**技術：頁面影像與已生成的佈局前綴只需預填充（prefill）一次並常駐於 KV Cache，各內容分支僅需從前綴末端繼續解碼，避免重複視覺預填充（Visual Prefills）與碎片化頁面上下文（Fragmented Page Context）。

##### 模型初始化與訓練流程

PaDoc 直接以 Qwen3-VL-2B 檢查點初始化，並對所有模組進行持續預訓練（Continual Pre-Training, CPT）後再接高品質監督式微調（Supervised Fine-Tuning, SFT）。這意味著視覺編碼器、投影層與語言模型本體都會適應文件解析的佈局-內容平行生成任務，而非僅在固定視覺特徵上微調分類頭。

#### 實驗數據解讀

##### OmniDocBench Full 準確率

在 OmniDocBench Full 上，PaDoc 取得**整體佈局 F1（Overall Layout F1）** 91.1，顯示其佈局分析能力本身已達高水準。更值得注意的是，在端到端文件解析器（End-to-end Document Parsers）當中，PaDoc 的**整體分數（Overall Score）**達到 94.24，屬於頂尖表現；同時在**文字編輯距離（Text Edit）**（0.038）與**公式 CDM（Formula CDM）**（95.59）兩項指標上取得最佳成績。

這幾個數字的意義在於：平行化解碼並未以犧牲準確率為代價。相反地，由於每個區域內容分支都能保留**完整頁面上下文（Full-page Context）**，模型在處理文字與公式時擁有比裁切式兩階段解析器（Crop-based Two-stage Parsers）更豐富的全域線索，因此文字還原與公式辨識表現突出。佈局 F1 接近 91 也說明「佈局流」與「內容分支」能夠穩定協同，不會因為平行生成而導致佈局錯亂。

##### 效率評估

作者在 384 頁子集、單張 A800 GPU 上進行推論效率測試，並比較五個**並發層級（Concurrency Levels）**。相較於相同骨幹的**序列式 SFT 基線（Sequential SFT Baseline）**，PaDoc 的**有效頁面吞吐量（Valid-Page Throughput）**提升 67.4%–118%，**P95 延遲（P95 Latency）**降低 39.2%–54.9%，且在所有測試並發層級都是最快的端到端解析器。

這些數據有幾層含義：

1. **加速來自解碼深度縮短**：關鍵路徑從「所有區域內容總和」變為「最長佈局-內容路徑」，因此當頁面區域越多、內容分佈越不均勻時，加速越明顯。
2. **快取共享降低視覺編碼開銷**：透過 vLLM 的共享前綴重用，影像與佈局前綴只需計算一次，避免裁切式方法中對每個區域重複進行視覺編碼（Visual Encoding）。
3. **並發穩健性**：在五個並發層級都維持領先，表示 PaDoc 的平行分支能夠有效利用 GPU 批次化與記憶體頻寬，而非僅在低負載下有效。

##### 綜合意涵

準確率與效率同時提升的結果，強化了 PaDoc 方法論的說服力：它不是單純的推論加速技巧，而是一種重新定義文件解析機率結構的典範。透過把預測佈局（Predicted Layout）視為分支結構（Branching Structure），PaDoc 在保留端到端模型簡潔介面的同時，獲得了接近兩階段方法的區域級平行度。

#### 與現有研究的比較

##### 相對於序列式端到端解析器

早期的圖像到序列方法（如 Donut、Pix2Struct、Nougat）與近期的文件視覺語言模型（如 SmolDocling、olmOCR、Qianfan-OCR）都採用單一自迴歸序列輸出 Markdown、HTML 或佈局-內容記錄。這類方法的優勢是統一介面與端到端訓練，但缺點是將本來條件獨立的區域強制序列化，導致關鍵路徑過長。PaDoc 與它們使用相同的 MLLM 骨幹與訓練目標，但透過前綴條件分解解除區域內容之間的因果依賴，因此能在不犧牲全頁上下文的前提下顯著降低延遲。

##### 相對於裁切式兩階段解析器

佈局優先系統（Layout-First Systems）通常先執行佈局分析，再對每個區域裁切（Per-Region Crops）並行執行內容辨識。這種方法確實能暴露區域級平行度，但代價是重複視覺預填充（Visual Prefills）與碎片化頁面上下文（Fragmented Page Context）：每個裁切區域只能看到局部影像，無法利用全頁語境。PaDoc 的區域內容分支雖然也是並行生成，但所有分支都從共享的完整頁面表示分叉，因此兼具平行度與全頁上下文。

##### 相對於通用加速方法

近年來的推測性解碼（Speculative Decoding）與文字分支（Textual Branches）等通用加速器（General Accelerators）雖然也能創造平行分支，但這些分支往往不基於真實的視覺文件實例（Visual Document Instances），且可能被最終輸出排除。PaDoc 的分支則直接由預測佈局決定，每個分支對應一個真實的視覺區域，因此分支結構與文件語義一致，不會產生無效推測開銷。

##### 方法限制

儘管 PaDoc 表現出色，仍有幾項潛在限制：

1. **區域充分性假設的適用範圍**：當文件區域之間存在強語義依賴（例如跨欄表格、跨區域公式引用、閱讀順序會影響內容理解）時，假設可能不成立，導致內容分支遺失必要上下文。
2. **佈局錯誤的傳播**：若佈局流（Layout Stream）預測錯誤，後續內容分支將基於錯誤的區域邊界生成，錯誤會沿著分支結構放大。
3. **分支管理開銷**：雖然 vLLM 共享前綴重用降低了很多成本，但大量細小區域會增加並發請求調度與記憶體管理的複雜度。
4. **對 vLLM 後端的依賴**：目前的效率數據建立在 vLLM 的特定實現上，若換用其他推論引擎，可能需要重新設計分支排程與快取共享機制。
5. **評估範圍**：主要結果集中在 OmniDocBench Full，對於多語言、多欄複雜版面、手寫文件或低解析度掃描文件的泛化能力仍需更多驗證。

#### 可重現性評估

##### 開源程式碼與資料集

論文明確提供程式碼倉庫：https://github.com/Longin-Yu/Padoc。評估使用的 OmniDocBench Full 是公開資料集，因此資料層面的可重現性良好。骨幹模型 Qwen3-VL-2B 亦是公開檢查點，降低了復現門檻。

##### 模型權重與訓練成本

根據目前提供的上下文，作者並未明確說明是否釋出 PaDoc 的訓練後模型權重。若僅釋出訓練程式碼，研究者仍需自行執行持續預訓練（CPT）與監督式微調（SFT），這需要相當的 GPU 運算資源（論文使用 A800 等級硬體進行效率評估）。因此，**可重現性在「方法驗證」層面高，但在「直接使用預訓練模型」層面則取決於權重是否公開**。

##### 環境與實作細節

由於 PaDoc 的推論效率高度依賴 vLLM 後端（vLLM Backend）的共享前綴重用與並發請求實現，復現時需要確認 vLLM 版本、區域結束符號（region-closing tokens）的定義、打包可變長度祖先注意力的 CUDA kernel 或實作方式，以及與 Qwen3-VL-2B 視覺編碼器的相容性。若程式碼倉庫包含這些細節，則可重現性將大幅提升。

#### 未來研究方向

1. **放寬區域充分性假設**：可引入層次式或稀疏跨區域注意力，讓需要互相參照的區域在維持大部分平行度的同時，進行有限的跨分支資訊交換。
2. **動態分支與不確定性導向解碼**：根據佈局流的置信度決定是否提前分叉、合併或重新排序分支，以在準確率與速度之間做更細緻的權衡。
3. **多頁與串流文件解析**：將 PaDoc 的頁面級平行解碼擴展到多頁文件，甚至發展線上（online）解析，讓模型在收到部分頁面時即可開始生成。
4. **與推測性解碼結合**：在區域內容分支內部引入 draft-then-verify 機制，進一步縮短每個分支的關鍵路徑。
5. **分支負載平衡與排程最佳化**：針對長短差異極大的區域設計更智慧的 GPU 排程策略，減少因等待最長分支而造成的資源閒置。
6. **非矩形與重疊區域**：目前的區域內容分支隱含假設區域為矩形佈局，未來可研究多邊形、重疊或巢狀區域的分支表示法。
7. **跨語言與跨領域泛化**：在更多語言、更多文件類型（如表單、發票、學術論文、漫畫）上驗證方法，並發展領域自適應的佈局流。
8. **模型壓縮與邊緣部署**：透過量化、知識蒸餾或專家混合（MoE）縮小模型，使 PaDoc 能在資源受限的裝置上實現即時文件解析。
9. **可解釋的佈局-內容對齊**：開發視覺化工具，讓使用者理解每個內容分支對應的頁面區域與前綴條件，提升文件解析結果的可信度與可除錯性。
10. **應用於其他結構化生成任務**：PaDoc 的佈局導向平行解碼框架可推廣到網頁生成、表單理解、簡報結構化轉換等需要「先結構、後內容」的視覺-語言任務。

## 論文問答

**Q1：PaDoc 主要想解決端到端文件解析中的什麼根本問題？**

A：PaDoc 針對的核心問題是，現有端到端文件解析器把頁面佈局與各區域內容串接成一條自迴歸序列，導致彼此獨立的區域被迫依序生成，關鍵路徑會隨著總內容長度線性增長。這種扁平輸出序列無法反映文件真正的條件結構，使得解碼深度等於所有區域內容長度的總和。PaDoc 的目標是在保留完整頁面上下文的前提下，移除區域之間不必要的依賴，讓獨立可識別的區域能夠並行生成。

**Q2：序列式端到端解析器與裁切式兩階段解析器各自有哪些不足？**

A：序列式端到端解析器雖然能維持完整頁面上下文，卻因為因果解碼器的限制，必須完成前一個區域內容後才能預測下一個區域，造成解碼瓶頸。相對地，裁切式兩階段解析器雖然能暴露區域層級的平行性，但需要對每個區域裁切進行重複的視覺編碼，導致視覺預填充成本增加，並且割裂了頁面層級上下文。PaDoc 試圖結合兩者的優點：既保留共享的完整頁面表示，又讓各區域內容分支能夠並行推進。

**Q3：為什麼同時保留完整頁面上下文與區域層級平行性對文件解析很重要？**

A：完整頁面上下文能讓模型利用全域的版面、字體、圖表與鄰近區域資訊，減少因局部裁切造成的辨識錯誤，對於表格、公式與多欄排版尤其關鍵。區域層級平行性則能縮短實際解碼的關鍵路徑，讓包含大量獨立區域的頁面不必逐區生成，顯著提升吞吐量與降低延遲。PaDoc 透過佈局導向平行解碼，把這兩個看似衝突的目標統一在單一多模態大型語言模型中。

**Q4：PaDoc 的核心方法是什麼？請說明佈局導向平行解碼與前綴條件分解。**

A：PaDoc 把預測出的佈局視為覆蓋在共享頁面表示上的分支結構，並在區域充分性假設下推導出前綴條件分解：每個區域的內容僅依賴頁面影像與目前已產生的佈局前綴，而與其他區域的內容條件獨立。這使得佈局流與各區域內容分支可以從共同前綴出發，同步向前推進，解碼深度因此降為最長的佈局—內容路徑，而非所有區域內容長度的總和。整個過程不需要獨立的偵測頭或辨識頭，而是在單一 MLLM 內完成。

**Q5：PaDoc 在訓練與推論階段有哪些關鍵設計選擇？**

A：訓練時，PaDoc 使用打包可變長度祖先注意力，讓每個內容分支只看到影像與應該可見的佈局祖先，而遮蔽同層兄弟區域的內容，同時仍維持標準的下一個詞元訓練目標。推論時則採用遮蔽平行解碼，透過區域結束詞元把各內容分支實例化為彼此隔離的串流，並在 vLLM 後端上以並發請求的形式執行，搭配快取常駐的共享前綴重用。這兩項設計讓理論上的平行分解能夠無縫對應到現有加速框架的實作。

**Q6：區域充分性假設在 PaDoc 中扮演什麼角色？為何能省去獨立的偵測器與辨識器？**

A：區域充分性假設主張：給定頁面影像與該區域的佈局資訊後，區域內容的生成不再需要其他區域的內容作為條件。這個假設讓模型可以把佈局預測與內容生成放在同一個機率分解下，從而直接用單一 MLLM 同時輸出佈局與各區域內容，無需額外的裁切、偵測頭或專屬辨識模組。當然，這也意味著佈局預測的品質會直接影響內容分支的條件上下文，因此佈局流的準確性仍是整體效能的關鍵。

**Q7：PaDoc 在哪些基準與指標上進行評估？**

A：論文主要在 OmniDocBench Full 上評估佈局分析與端到端解析效能，指標包括整體佈局 F1、整體分數、文字編輯距離（Text Edit）以及公式 CDM。此外，作者也在 384 頁的子集與單張 A800 GPU 上測量推論效率，涵蓋五種並發層級的有效頁面吞吐量與 P95 延遲。這樣的評估設計同時檢驗了 PaDoc 的準確性與實際部署時的加速效益。

**Q8：PaDoc 取得了哪些關鍵量化結果？**

A：在 OmniDocBench Full 上，PaDoc 達到 91.1 的整體佈局 F1，並在端到端解析器中取得 94.24 的頂尖整體分數，同時擁有最佳的 Text Edit（0.038）與 Formula CDM（95.59）。在推論效率方面，相較於使用相同骨幹的序列式 SFT 基線，PaDoc 在五個並發層級下將有效頁面吞吐量提升 67.4% 至 118%，並把 P95 延遲降低 39.2% 至 54.9%。這些數據顯示 PaDoc 不僅準確，也是目前最快的端到端解析器之一。

**Q9：哪些對照實驗證明了 PaDoc 各項設計的貢獻？**

A：作者以相同骨幹的序列式 SFT 基線作為主要對照，證明在模型容量相同的情況下，佈局導向平行解碼能顯著縮短解碼深度並提升吞吐量。透過在不同並發層級下測試，也驗證了 PaDoc 的 vLLM 後端實作能夠有效利用快取常駐共享前綴重用，隨著並發數增加仍維持優勢。雖然論文未詳列所有消融，但佈局 F1 與端到端整體分數的同時提升，說明平行化解碼並未犧牲解析品質。

**Q10：PaDoc 最適合應用在哪些實務場景？**

A：PaDoc 特別適合需要大量處理掃描文件、PDF 頁面或數位版面的高吞吐量場景，例如財務報表自動化、發票與收據數位化、學術論文結構化擷取，以及法律合約與表單的內容抽取。這些文件通常包含多個獨立區域，如文字區塊、表格、公式與圖片，PaDoc 的區域層級平行性能顯著縮短每頁處理時間。對於需要即時回應的雲端文件解析服務而言，降低 P95 延遲也意味著更穩定的使用者體驗。

**Q11：在產品部署 PaDoc 時需要考慮哪些工程議題？**

A：首先，推論端需要支援 vLLM 後端與並發請求排程，才能充分發揮快取常駐共享前綴重用的效益，並根據硬體資源調整並發層級。其次，打包可變長度祖先注意力的實作需要處理不同頁面與不同區域數量的動態形狀，對批次化與記憶體管理提出挑戰。最後，由於 PaDoc 直接從 Qwen3-VL-2B 初始化並經過持續預訓練與監督式微調，部署時也需評估模型授權、推理成本與錯誤傳播風險。

**Q12：PaDoc 可能對文件解析領域帶來什麼影響？**

A：PaDoc 示範了如何在單一多模態大型語言模型內，把文件的條件結構轉化為可並行解碼的分支，而不必回到傳統的裁切式兩階段管線。這種佈局導向的解碼範式可能啟發更多結構化生成任務，例如網頁解析、簡報結構化或使用者介面理解，去探索類似的平行分解。此外，它結合了學術上的機率分解與工程上的 vLLM 加速，為未來端到端文件解析器的實用化提供了一條清晰路徑。

**Q13：PaDoc 有哪些已承認或潛在的限制？**

A：PaDoc 的核心假設是區域充分性，也就是每個區域內容只依賴頁面影像與自身佈局前綴；然而當區域之間存在強語意相依，例如跨欄的表格、相互引用的公式與文字說明時，這個假設可能不成立。此外，佈局流一旦預測錯誤，後續所有內容分支都會在錯誤的條件上下文下生成，錯誤會沿著分支結構傳播。目前論文也主要聚焦單頁文件，對於跨頁或多頁連貫結構的處理能力仍有待驗證。

**Q14：PaDoc 在哪些情況下可能出現失敗案例？**

A：當頁面佈局極度密集、區域高度重疊或邊界模糊時，佈局流可能產生錯誤的區域劃分，導致內容分支在錯誤的位置生成文字或公式。對於需要跨區域上下文才能正確理解的元素，例如被圖表包圍的註解或跨欄合併的複雜表格，區域充分性假設可能使模型遺失關鍵線索。此外，若文件具有非典型的閱讀順序或藝術化排版，預測佈局與實際語意結構不一致時，也可能降低解析品質。

**Q15：PaDoc 未來可以朝哪些方向延伸與改進？**

A：未來可以將 PaDoc 擴展至多頁文件，讓模型在頁面之間也建立共享上下文與跨頁佈局分支，以處理長篇報告與書籍。另一個方向是引入更細緻的層級式佈局結構，例如章節、段落、句子與詞彙的多層分支，進一步縮短關鍵路徑。也可以結合推測性解碼或互動式校正機制，在佈局預測不確定時讓使用者介入，或讓模型主動查詢跨區域資訊以放寬區域充分性假設。

## 實務應用指南

### 適用場景

1. **財務與法務文件數位化**：年報、招股書、合約等頁面通常同時包含多欄文字、表格與少數圖表，區域間相對獨立，適合以佈局導向平行解碼同時抽取各區塊內容，縮短整頁解析的關鍵路徑。
2. **學術論文與教科書處理**：這類文件充斥數學公式、多欄排版、圖表與參考文獻，PaDoc 可在保留完整頁面上下文的前提下，對公式區域與文字區域進行並行解碼，提升 Formula CDM 等指標表現。
3. **醫療病歷與檢驗報告自動化**：報告中常見表格、數值與文字交錯，且對上下文一致性要求高；使用共享頁面表示可避免裁切式兩階段解析器造成的碎片化頁面上下文問題。
4. **高並發單據與發票批次處理**：在需要同時處理大量頁面的場景中，透過 vLLM 後端的並發請求與快取常駐共享前綴重用，可顯著提升有效頁面吞吐量並降低 P95 延遲。
5. **企業知識庫與文件檢索前置處理**：將掃描 PDF 或影像轉為結構化 Markdown、HTML 或 JSON，作為下游檢索增強生成（RAG）系統的乾淨輸入。

### 實作前置條件

**資料條件**
- 高品質文件影像與對應的結構化標註，包括頁面佈局（區域座標與類別）、文字內容、公式與表格表示法。
- 標註需符合區域充分性假設，即各區域內容在給定頁面影像與已生成佈局前綴後，能夠相對獨立地預測。
- 若使用 OmniDocBench Full 格式，需確認資料涵蓋目標領域的版面變異。

**運算資源**
- 至少一張 A800 GPU 等級的運算資源，用於持續預訓練（CPT）與監督式微調（SFT）。
- vLLM 後端部署環境，並具備足夠的 GPU 記憶體以支援 KV cache 的共享前綴與多條區域內容分支並行。
- 若要走完整端到端流程，建議準備可彈性調整並發層級的推論服務。

**技術能力**
- 熟悉多模態大型語言模型（MLLM）的訓練流程，特別是視覺編碼器與解碼器的協作。
- 能夠實作或修改打包可變長度祖先注意力，並理解遮蔽平行解碼的因果關係。
- 具備 vLLM 部署、並發請求調度與效能監控經驗。

### 實作步驟建議

1. **資料整理與格式對齊**：將原始文件影像與標註轉換為佈局流與區域內容分支可並行學習的序列格式，確保每個區域的內容在訓練時只看見影像前綴與對應的佈局祖先。
2. **選定基礎模型**：以 Qwen3-VL-2B 或同等級 MLLM 作為起點，直接初始化視覺編碼器與語言解碼器。
3. **領域持續預訓練（CPT）**：在目標文件領域的大量頁面上進行 CPT，讓模型熟悉該領域的版面與詞彙分佈。
4. **監督式微調（SFT）**：使用打包可變長度祖先注意力，在標準下一個詞元訓練目標下學習佈局流與內容分支的聯合分佈；注意遮蔽邏輯必須排除兄弟區域內容，避免資訊洩漏。
5. **推論引擎建置**：以 vLLM 後端部署模型，實作遮蔽平行解碼，將每個區域內容分支視為獨立並發請求，並啟用共享前綴快取重用。
6. **並發與延遲調校**：在實際硬體上測試不同並發層級，監控有效頁面吞吐量與 P95 延遲，找出延遲與資源利用率的最佳平衡點。
7. **後處理與品質驗證**：將模型輸出的扁平序列還原為結構化格式（Markdown / HTML / JSON），並以整體佈局 F1、Text Edit、Formula CDM 等指標持續驗證。

### 潛在風險與注意事項

- **區域充分性假設失效**：當表格跨欄、文字與公式高度交錯，或區域間存在強語意依賴時，並行分支可能產生內容不一致。建議保留序列式 SFT 基線作為 fallback，並在關鍵頁面啟用重試或人工審核。
- **佈局錯誤的連鎖效應**：佈局流一旦預測錯誤，後續所有區域內容分支都會建立在錯誤的佈局前綴上。應優先提升佈局分析模型的準確度，並在後處理階段加入佈局合理性檢查。
- **GPU 記憶體壓力**：並發請求與共享前綴快取會顯著增加記憶體佔用，需根據頁面複雜度設定並發上限，並監控 OOM 風險。
- **訓練遮蔽邏輯複雜**：打包可變長度祖先注意力的實作容易出錯，特別是在可變長度序列打包時，必須確保每個內容分支只看見合法的祖先節點。
- **輸出格式與既有系統銜接**：PaDoc 的輸出是結構化序列，而非傳統 OCR 的純文字框，下游系統可能需要重新設計解析與儲存邏輯。

### 與其他技術的整合建議

- **與 RAG 系統銜接**：將 PaDoc 輸出的結構化 Markdown 或 JSON 直接寫入向量資料庫，作為檢索增強生成的前置資料來源，減少傳統 OCR 造成的版面雜訊。
- **與傳統 OCR 管線互補**：對於簡單單欄文件可繼續使用成熟 OCR，PaDoc 則專門處理多欄、表格、公式密集的複雜頁面，以降低整體導入成本。
- **與文件分類模型搭配**：先以輕量分類器判斷文件類型與複雜度，再決定是否啟用平行解碼，避免在簡單頁面上浪費並發資源。
- **與版面還原工具整合**：將預測佈局與區域內容分支輸出轉換為 HTML 或 Markdown，供前端閱讀器、編輯器或比對工具使用。
- **與監控與降級機制整合**：持續追蹤 P95 延遲、有效頁面吞吐量、整體佈局 F1 與 Text Edit，當指標異常時自動切換回序列式基線或觸發告警。

### 給不同背景讀者的閱讀建議

**初學者**：建議先從文件解析的基本任務與自迴歸序列的缺點開始，接著對照圖 1 理解三種典範的差異——序列式端到端、裁切式兩階段與 PaDoc 的佈局導向平行解碼，最後再閱讀適用場景與實作步驟，建立整體輪廓即可。

**AI 工程師**：應重點研讀打包可變長度祖先注意力的訓練實作細節、遮蔽平行解碼在推論階段的具體流程，以及 vLLM 後端如何透過共享前綴快取重用服務並發請求，這些是將論文轉為產品的關鍵。

**研究人員**：可聚焦於前綴條件分解的理論推導、區域充分性假設的適用邊界，以及 PaDoc 與推測性分支、裁切式兩階段解析器和通用解碼加速器之間的本質差異。

**產品經理**：建議優先關注適用場景、效能數據（有效頁面吞吐量提升 67.4–118%、P95 延遲降低 39.2–54.9%）與潛在風險，評估導入所需的資料標註成本、GPU 資源與業務價值，再決定試點範圍。
