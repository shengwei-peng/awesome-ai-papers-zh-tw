## ⚡ TL;DR

現有搜尋代理在強化學習中被迫同時處理語義決策與繁瑣狀態管理，導致學習效率低落且優化困難。
Harness-1透過狀態外部化框架將工作記憶交由環境維護，讓策略專注於搜尋、篩選與驗證等語義決策。
八項基準中，Harness-1精選召回率達0.730，領先開源對手11.4分，跨領域遷移突出。

## 摘要翻譯

## 深度分析

#### 方法論解析

本文的核心論點在於，傳統搜尋代理（Search agent）的強化學習（Reinforcement Learning, RL）範式將語義搜尋決策（Semantic search decision）與簿記管理（Bookkeeping）混為一談。在典型的交互紀錄（Transcript）架構中，策略（Policy）必須從不斷增長的原始觀察（Observation）中，隱式地重建候選池（Candidate pool）、精選集合（Curated set）、驗證紀錄（Verification record）與跨文件結構（Cross-document structure）。這導致獎勵信號難以歸因：當最終精選集合為空或錯誤時，RL 無法區分失敗根源是糟糕的查詢生成（Query generation）、遺忘的證據，還是未完成的驗證。

為此，作者提出狀態外部化框架（State-Externalizing Harness），將狀態管理（State management）從策略卸載至環境（Environment）。具體而言，Harness-1 的環境端維護一份持續性檢索狀態（Persistent retrieval state），包含：
1. **候選池（Candidate pool）**：所有曾檢索到的文件片段；
2. **精選集合（Curated set）**：經重要性標記（Importance-tagged）的保留文件，並設有容量上限與淘汰機制；
3. **精簡證據連結（Compact evidence link）**：以證據圖（Evidence graph）摘要形式呈現的跨文件連結（Cross-document link）；
4. **驗證紀錄（Verification record）**：策略所寫主張與來源文本的比對結果；
5. **壓縮與去重複觀察（Compressed and deduplicated observation）**：經 BM25 句子選擇與內容過濾後的搜尋結果；
6. **預算感知（Budget-aware）標記**：上下文長度與回合預算的即時提示。

策略僅保留高階語義決策：決定查詢內容、推薦或捨棄文件、選擇驗證主張，以及判斷終止時機。其動作空間為結構化編輯指令，例如 `curate`（新增、移除或標記文件重要性）、`verify`（針對記憶中的文件檢驗主張）、`review_docs`（無需重新呼叫語料庫即可重新呈現已見文件），而非單純地附加文字至交互紀錄。這使得每一回合的觀察都是環境透過上下文呈現（Context rendering）所回傳的顯式搜尋狀態（Explicit search state），而非原始工具輸出的堆疊。

為使此框架適合策略訓練，作者提出三項設計必要條件：
- **溫啟動精選（Warm-started curation）**：首次成功搜尋後，框架自動將前 k 個結果種子化至精選集合，避免早期獎勵稀疏且不可區分；
- **精簡衍生狀態呈現（Compact derived-state rendering）**：透過重要性標籤、證據圖摘要與驗證紀錄，確保工作記憶（Working memory）不會擠壓證據本身的上下文空間；
- **多樣性保留獎勵（Diversity-preserving incentives）**：獎勵函數同時考量精選集合層級的軌跡相關文件召回（trajectory relevant doc recall）、工具多樣性（tool diversity）、回答發現獎勵（answer found bonus）與回合懲罰（turn penalty），防止策略陷入重複搜尋（repeated search calls）的崩潰模式。

訓練管線分為四階段：首先以教師展開（Teacher Rollouts）收集高品質軌跡；接著進行監督式微調回放（SFT Replay）；再以 LoRA 取得 SFT 檢查點；最後以 CISPO 演算法執行 RL 訓練。此處的獎勵設計特別強調軌跡層級的精選召回率（Curated recall），而非僅有最終答案正確與否，從而提供更細緻的信用分配（credit assignment）。

#### 實驗數據解讀

Harness-1 在橫跨網頁、金融、專利與長上下文多跳問答（Multi-hop QA）的八項檢索基準測試上進行評估。核心指標為精選召回率（Curated recall），即精選集合中包含正相關文件的比例。該模型達到 **0.730 的平均精選召回率**，相較次強的開放式搜尋子代理（Open search subagent）提升 **+11.4 個百分點**，且能與規模大上許多的前沿模型搜尋器（Frontier-model searcher）抗衡。

這組數據可從三個層次解讀：

1. **絕對性能與規模效率**：作為基於 gpt-oss-20b（20B 參數）的檢索子代理（Retrieval subagent），Harness-1 以遠小於前沿模型的參數量達到可比性能，顯示將狀態管理外部化後，策略的參數可專注於語義搜尋決策，顯著提升參數效率。

2. **遷移與泛化**：其在保留遷移基準測試（Held-out transfer benchmark）上的增益尤為顯著。這暗示顯式搜尋狀態作為 RL 的學習介面，能學習到跨領域的檢索行為模式，而非僅記憶特定語料庫的表層特徵。當檢索流程被拆解為「搜尋 → 精選 → 驗證 → 回顧」的結構化節奏時，策略更容易將這些操作遷移至全新的專業領域（如金融或專利）。

3. **下游效用**：實驗亦顯示，將 Harness-1 的精選集合傳遞給凍結的前沿生成器（frozen frontier generators）時，下游回答準確率（downstream answer accuracy）隨之提升。這驗證了精選集合的品質不僅反映在召回率上，更實質減少了下游回答器（Downstream answerer）的幻覺與推理負擔。

值得注意的是，+11.4 分的領先幅度發生在開放式搜尋子代理之間，而與閉源前沿模型的競爭力則說明：在檢索任務中，環境架構（即具狀態搜尋框架，Stateful search harness）的設計可能與基礎模型的規模同等重要。

#### 與現有研究的比較

**相對於 ReAct 與推理與行動代理（Reasoning-and-acting agent）**
傳統 ReAct 範式與迭代檢索（Iterative retrieval）方法將思考、行動與觀察以線性交互紀錄串接。Harness-1 並未否定「思考-行動」循環的價值，而是將其中的簿記管理抽離至環境。這與近期主動檢索（Active retrieval）和工具使用訓練（Tool-use training）的方向一致，但更進一步主張：代理-電腦介面（Agent-computer interface）本身應具備記憶與狀態持久化能力，而非僅提供工具呼叫端點。

**相對於自我編輯搜尋（Self-editing search）與上下文剪枝（Context pruning）**
近期研究已開始將上下文管理視為搜尋流程的一環，例如透過自我編輯或剪枝來維持有效上下文。Harness-1 的差異在於「狀態的持續性與結構化」：精選集合、證據圖與驗證紀錄並非臨時修剪的產物，而是由框架持久維護、並以固定格式渲染回策略的顯式狀態。這使得 RL 的觀察空間（observation space）更穩定，降低了策略從非結構化文本中解析跨文件結構的負擔。

**相對於檢索強化學習（RL for retrieval）**
既有 RL 檢索研究多聚焦於查詢生成或多回合搜尋策略，但仍要求模型在內部處理所有歷史資訊。Harness-1 指出這會導致學習條件不良（poorly conditioned）：困難查詢的空集合獎勵、大型工具詞彙表（Tool vocabulary）的崩潰，以及獎勵歸因模糊。透過狀態外部化，Harness-1 將信用分配問題簡化為「語義決策是否改善精選集合」，而非「模型是否記得十回合前的證據」。

**方法限制**
首先，框架的工程複雜度顯著提高：開發者需實作候選池淘汰、證據圖維護、驗證快取等機制，這增加了系統的部署門檻。其次，策略的動作空間受限於結構化指令，雖然提升了可靠性，卻可能抑制需要自由形式探索的創意檢索行為。第三，目前評估主要聚焦於檢索效用（Retrieval utility）與精選召回率，對於極長軌跡（如數十回合的多跳問答）中的錯誤累積與狀態同步問題，探討相對有限。最後，教師展開階段若依賴大型閉源模型，則在完全開放的重現上仍可能存在門檻。

#### 可重現性評估

論文明確指出原始碼已公開於 GitHub，這為方法驗證提供了基礎。基礎模型採用 gpt-oss-20b，屬於開放權重（open weights）模型，降低了模型取得的障礙。訓練過程使用 LoRA，意味著完整微調所需的運算資源相對可控，研究者無需持有大量 GPU 叢集即可複現 SFT 階段。

然而，完整重現仍面臨若干挑戰：
- **教師資料生成（Teacher data generation）**：管線初期的教師展開若使用 GPT-4.5 等級的閉源模型產生約 900 條完整軌跡，則依賴特定 API 存取權限與成本，且論文未詳細說明教師策略的提示工程細節。
- **CISPO 強化學習**：雖然論文提及以 CISPO 進行 RL，但對其超參數、獎勵縮放係數與優化器設定的描述有限，這些細節對 RL 訓練的穩定性至關重要。
- **框架實作細節**：具狀態搜尋框架涉及壓縮與去重複觀察、BM25 句子選擇、重要性驅動淘汰等工程細節，其程式碼品質與文件完整度將直接影響社群能否順利接軌。
- **基準測試資料**：八項基準雖涵蓋公開領域，但部分領域（如金融、專利）的評估資料集可能需要額外整理或授權確認。

整體而言，Harness-1 在開源承諾上優於許多僅發布技術報告的前沿代理研究，但從「開源程式碼」到「可一鍵重現完整 RL 訓練管線」之間，仍需社群驗證其文件與依賴項的完整性。

#### 未來研究方向

1. **策略規模與框架不對稱擴展**
   當前策略為 20B 參數。未來可探討將策略擴展至 70B 或更大規模，同時維持相同的具狀態搜尋框架。這將驗證狀態外部化在超大模型是否仍具邊際效益，或當模型具備足夠長上下文與推理能力時，簿記管理是否可部分回歸策略本身。

2. **端到端聯合訓練**
   目前 Harness-1 的評估將精選集合傳遞給凍結的下游回答器。未來可讓檢索子代理與回答器進行聯合強化學習，使精選集合的優化目標直接對齊最終答案正確性，而非僅以召回率為代理指標。

3. **自適應上下文呈現（Adaptive Context Rendering）**
   當前框架的狀態渲染器為固定規則（如重要性標籤、證據圖摘要）。可引入輔助模型或學習式壓縮器，根據當前查詢動態決定哪些驗證紀錄或候選池資訊最相關，進一步節省上下文預算（context budget）。

4. **多代理共享狀態**
   將具狀態框架擴展至多代理系統，使多個專業化檢索子代理（如網頁、財經、專利各一個）共享同一個持續性檢索狀態。這需要設計代理間的精選集合合併與驗證紀錄衝突解決機制。

5. **理論分析：顯式狀態與泛化的因果關係**
   Harness-1 在保留遷移基準測試上的強勁表現暗示顯式狀態有助於泛化，但缺乏形式化分析。未來可從因果表示學習或選項框架（options framework）角度，證明將簿記管理從語義決策中分離，如何降低策略學習的 effective horizon 與狀態空間維度。

6. **持續學習與線上適應**
   目前的框架狀態在單一軌跡內持久化，但未跨軌跡累積。若允許框架在部署期間持續更新其證據圖與驗證快取，則搜尋代理可具備跨任務的終身學習能力，這對於長期監控型任務（如金融盡職調查）尤具價值。

## 論文問答

**Q1：現有搜尋代理的訓練範式存在什麼根本性問題？**

A：現有的搜尋代理通常被訓練為對不斷增長的交互紀錄進行決策的策略，這迫使模型必須同時處理語義搜尋決策與繁瑣的狀態管理工作。具體而言，策略不僅要決定如何搜尋，還必須從原始的、僅供附加的對話紀錄中，重新推導出哪些文件已看過、哪些證據有用、哪些限制仍未解決等資訊。這種設計將兩種本質不同的認知負擔混為一談，導致強化學習的優化過程效率低下且條件不良，因為策略必須耗費大量上下文空間與計算資源來進行可恢復的簿記管理，而非專注於高層次的搜尋推理。

**Q2：為何強迫策略從交互紀錄中管理狀態會導致強化學習訓練成效不彰？**

A：當交互紀錄隨著搜尋回合增長時，策略必須從這份僅供附加的日誌中重新發現搜尋狀態，例如已檢視的文件、已驗證的主張或跨文件結構，這使得學習過程變得極度沒效率。這種設計會引發多種訓練病態：困難查詢可能產生幾乎相同的空集合獎勵，大型工具詞彙表可能導致策略崩潰成重複的搜尋呼叫，而跨文件結構則可能因過於分散而難以可靠利用。更嚴重的是，當最終的精選集合為空或錯誤時，獎勵信號無法揭示失敗究竟是源於糟糕的搜尋、遺忘的證據、缺失的驗證，還是低劣的精選管理，從而讓信用分配變得極為困難。

**Q3：將語義決策與狀態管理分離為何對搜尋代理至關重要？**

A：將這兩者分離能讓強化學習專注於優化穩定的搜尋行為介面，而非要求模型同時學會可恢復的簿記工作，這大幅改善了學習的條件與效率。當環境端的框架負責維護候選池、精選集合與驗證紀錄時，策略的上下文與優化預算就能從繁瑣的例行狀態維護中釋放出來。如此一來，策略可以專注於更高層次的語義決策，例如決定搜尋方向、判斷文件重要性、選擇驗證目標以及決定何時終止，進而提升整體檢索品質與泛化能力。

**Q4：Harness-1 的核心架構是什麼，它如何在策略與框架之間分工？**

A：Harness-1 是一個基於 gpt-oss-20b 建構的 200 億參數搜尋代理，其核心由一個負責語義決策的策略與一個具狀態搜尋框架組成。策略保留所有高階語義決策權，包括決定發起什麼搜尋、保留或捨棄哪些文件、驗證哪些主張，以及判斷證據是否充足並停止搜尋。相對地，框架負責在環境端維護持續性檢索狀態，包含候選池、重要性標記的精選集合、精簡證據連結、驗證紀錄、壓縮與去重複觀察，以及預算感知的上下文呈現，從而實現認知卸載。

**Q5：本文指出的具狀態搜尋框架三大關鍵需求是什麼，它們如何實現？**

A：本文識別出三大需求：暖啟動精選、精簡衍生狀態呈現，以及保留多樣性的激勵。暖啟動精選透過在首次成功搜尋後自動植入暫定性精選集合來實現，避免早期獎勵無法區分的問題；精簡呈現則透過重要性標籤、證據圖摘要與驗證紀錄，確保框架狀態不會與實際證據爭奪策略的上下文空間。至於多樣性激勵，則透過獎勵設計鼓勵策略建立搜尋、精選、回顧與驗證的節奏，防止其崩潰成重複的單一行為模式。

**Q6：Harness-1 的動作空間與傳統的交互紀錄延伸方法有何不同？**

A：與傳統方法僅將代理行為附加到不斷增長的交互紀錄不同，Harness-1 的動作直接編輯由框架維護的持續性檢索狀態。例如，「curate」動作可以新增、移除文件或標記其重要性；「verify」動作將策略撰寫的主張與框架記憶中的文件進行比對；而「review_docs」則能在不呼叫新語料庫的情況下重新呈現先前看過的文件。這種狀態編輯範式將互動從被動的日誌記錄轉變為主動的狀態操作，使策略能夠在明確的顯式搜尋狀態上進行結構化推理。

**Q7：Harness-1 在哪些基準測試上進行評估，這些測試涵蓋哪些領域？**

A：Harness-1 在八個檢索基準測試上進行評估，涵蓋網路搜尋、金融、專利以及長上下文多跳問答等多元領域。這些測試檢驗代理在專業語料庫、開放網路任務以及需要跨文件推理的複雜情境中的檢索能力。其中特別包含保留遷移基準測試，用以評估代理透過顯式搜尋狀態所學到的檢索行為是否能夠超越訓練領域進行泛化。

**Q8：Harness-1 的主要量化結果為何，與其他代理相比表現如何？**

A：Harness-1 在八個基準測試上達到平均 0.730 的精選召回率，相較次強的開放式搜尋子代理提升了 11.4 個百分點。儘管僅為 200 億參數的模型，它仍能與規模大得多的前沿模型搜尋器保持競爭力。尤其在保留遷移基準測試上，其增益特別顯著，這顯示在顯式搜尋狀態上進行強化學習能夠產生超越訓練領域、具備良好泛化能力的檢索行為。

**Q9：有哪些證據顯示框架的狀態管理對下游任務表現有所貢獻？**

A：當 Harness-1 產生的精選集合被傳遞給凍結的前沿生成模型時，下游回答準確率獲得提升，這直接證明框架管理的狀態品質能夠惠及端到端系統。此外，它在保留遷移測試集上的強勁表現顯示，顯式搜尋狀態使代理學會了穩健的檢索策略，而非僅僅記憶特定領域的模式。框架透過壓縮與去重複觀察以及精簡的衍生狀態呈現，也確保了簿記資訊不會與實際證據爭奪策略有限的上下文空間，進一步支撐了整體效能。

**Q10：Harness-1 的狀態外部化設計在哪些實際應用場景中最具效益？**

A：這種設計在需要多回合、長時間追蹤大量文件並進行主張驗證的複雜檢索任務中特別有價值，例如金融分析、專利先前技術檢索或深度研究助理等場景。在這些應用中，代理必須維護結構化的搜尋狀態橫跨數十個步驟，若由策略自行進行簿記管理將迅速耗盡其上下文容量與推理能力。透過將認知負擔卸載至框架，系統能夠擴展到更長、更複雜的搜尋工作流程，同時維持高品質的語義決策與檢索準確度。

**Q11：將策略與框架狀態分離在產品層面帶來哪些優勢？**

A：這種分離從系統角度提供了模組化的好處，使狀態管理邏輯與語義策略能夠獨立迭代。產品團隊可以在不重新訓練核心 200 億參數模型的情況下，升級壓縮演算法、新增驗證工具或調整上下文預算規則，大幅降低部署風險與維運成本。此外，這種設計也讓企業更容易根據不同的資料架構、合規要求或領域特性來客製化框架，而無需修改底層策略模型本身。

**Q12：Harness-1 可能對工具使用代理與強化學習領域產生什麼廣泛影響？**

A：Harness-1 證明了代理與電腦之間的介面本身即是關鍵的方法論選擇，而非僅是實作細節，這可能促使未來的代理設計將持續性狀態視為環境的責任而非策略的負擔。這項工作有望將檢索與推理代理的訓練典範，從基於交互紀錄的強化學習轉向基於顯式結構化記憶的狀態強化學習。這種認知卸載的成功經驗也可能啟發其他工具使用領域——如軟體工程、機器人或科學實驗——發展出類似的狀態外部化框架設計。

**Q13：依賴具狀態框架可能存在哪些限制或代價？**

A：更豐富的框架雖然帶來效能增益，但也引入了額外的工程複雜度，並需要仔細設計以避免用過於冗長的衍生狀態壓垮策略。如果框架的狀態呈現過於繁瑣，它將與實際證據爭奪策略有限的上下文視窗，反而可能降低決策品質。此外，框架的設計內嵌了對於「哪些狀態重要」的假設，這可能在面對訓練時未預見到的全新搜尋情境時，限制了系統的靈活性與適應性。

**Q14：在什麼情況下 Harness-1 仍可能失敗或遭遇困難？**

A：若缺乏暖啟動機制，每次展開都從空的精選集合開始，早期獎勵將難以區分，策略可能難以學會有效的精選管理。如果獎勵函數僅重視發現文件而忽略多樣性，策略可能會忽略精選與驗證步驟，崩潰成重複搜尋的單調行為。此外，儘管框架維護了證據圖摘要，但對於極度複雜且無法被現有摘要機制充分捕捉的跨文件結構，關鍵資訊仍有可能在狀態轉換過程中遺失。

**Q15：這項工作暗示了哪些未來研究方向？**

A：未來研究可將狀態外部化的原則擴展到檢索以外的代理模態，例如程式碼生成或多模態工具使用。研究者也可以探索能夠根據任務難度或領域動態調整其狀態表徵的自適應框架，以進一步提升泛化能力。另一個方向是改進獎勵塑形與保留多樣性的激勵機制，以支援更長時間跨度的搜尋回合與更複雜的多層次驗證鏈，從而突破現有代理在極端複雜推理任務上的瓶頸。

## 實務應用指南

### 適用場景

1. **企業內部跨部門知識溯源與合規查核**  
   當查詢涉及「這份合約的修訂條款是否經過法務與財務雙方確認」時，需要跨文件驗證實體關係與主張真偽。Harness-1 的具狀態搜尋框架可維護候選池與驗證紀錄，讓策略專注於語義搜尋決策，而非從冗長交互紀錄中重建事實，適合處理需多跳推理（multi-hop）的內部知識庫檢索。

2. **金融研報與專利侵權分析**  
   金融與專利領域的檢索常需同時追蹤多份文件中的數據一致性與證據鏈。透過重要性標記的精選集合（importance-tagged curated set）與精簡證據連結（compact evidence link），系統能在預算感知（budget-aware）的上下文限制下，持續壓縮與去重複觀察，保留高價值證據給下游回答器。

3. **開放網頁的即時客服與動態問答**  
   面對開放網頁資訊，搜尋代理需在多輪展開（rollout）中決定何時搜尋、何時審閱已讀文件（review docs）、何時驗證。Harness-1 的狀態外部化設計將簿記管理（bookkeeping）移至環境端，降低策略在長對話中遺忘早期證據的風險，適合建構需長期維持搜尋狀態的互動式客服。

4. **學術文獻綜述與證據整理**  
   在進行系統性文獻回顧時，研究人員需要持續篩選、比對、剔除重複研究。Harness-1 的精選（curate）動作支援新增、移除與重要性標記，搭配自動播種（warm-started curation）機制，可在首次成功檢索後即產生初步精選集合，加速後續人工覆核流程。

5. **法律案件研究與判例交叉比對**  
   法律檢索常涉及判例事實、爭點與主文的交叉驗證。利用 verify 動作將策略撰寫的主張與記憶中的文件進行比對，並將判決記錄於驗證紀錄，可避免模型僅依賴生成幻覺進行論證，提升最終引用文件的可靠性。

### 實作前置條件

**資料需求**  
- 領域語料庫與對應的搜尋索引（支援 BM25 或向量檢索），用於實作 search_corpus、grep_corpus 等工具呼叫。  
- 查詢與相關文件對應關係（qrels）或教師軌跡（teacher trajectories），供 SFT Replay 與獎勵計算使用。  
- 驗證標註資料或來源文本對照表，以支撐 verify 動作的 ground-truth 設計。

**運算需求**  
- 至少可微調 20B 參數等級模型的 GPU 叢集（論文使用 gpt-oss-20b 搭配 LoRA）。  
- RL 訓練環境需支援多輪展開採樣與軌跡層級獎勵計算（trajectory recall、tool diversity、turn penalty 等）。  
- 獨立的搜尋框架（harness）伺服器或程序，用於維護持續性檢索狀態（persistent retrieval state），而非僅透過 API 呼叫無狀態搜尋引擎。

**技能需求**  
- 熟悉強化學習流程（特別是 CISPO 或 PPO 類演算法）與 reward shaping。  
- 具備大型語言模型微調經驗（LoRA、SFT、context window 管理）。  
- 能設計並維護狀態機系統，將候選池、精選集合、證據圖、搜尋歷史等結構化為環境端工作記憶（working memory）。

### 實作步驟建議

1. **建構具狀態搜尋框架（Stateful Search Harness）**  
   不要從「追加交互紀錄（transcript）」的 ReAct 風格開始。改為設計環境端狀態機，維護候選池、精選集合、證據圖摘要、驗證紀錄與上下文預算標記。每次策略行動後，由框架更新狀態並重新渲染（context rendering）回策略。

2. **實作狀態編輯型工具介面**  
   將工具設計為「編輯狀態」而非「回傳原始結果」。例如：curate 動作直接增刪精選集合並標記重要性；verify 動作寫入 claim-doc-verdict 三元組；review_docs 從全文儲存區重新渲染已讀文件，無需重新呼叫語料庫。

3. **教師軌跡生成與 Warm-Started Curation**  
   在教師展開（teacher rollouts）階段，於首次成功檢索後自動將 top-k 結果播種至精選集合（auto-seeding），避免早期獎勵稀疏導致學習訊號不足。確保教師資料、SFT Replay、RL 展開與評估皆使用相同的狀態渲染器。

4. **SFT 熱啟動**  
   使用教師軌跡對基礎模型進行監督式微調（SFT），讓策略先學會基本語法：如何產生 search_corpus 查詢、如何呼叫 curate 與 verify、以及何時輸出終止條件。

5. **RL 訓練與 Diversity-Preserving Reward**  
   以 CISPO 等 RL 演算法進行訓練。獎勵函數需同時包含：精選召回率（curated recall）、軌跡層級相關文件召回、工具多樣性（避免重複搜尋）、答案發現獎勵與回合懲罰。特別注意鼓勵「搜尋→精選→審閱→驗證」的節奏，防止策略收斂到單一行為。

6. **觀察壓縮與去重複化**  
   在狀態渲染至提示（prompt）前，實作 BM25 句子選擇、片段去重複與長度過濾，確保 derived state 不會擠壓實際證據的上下文空間。

7. **保留遷移評估與下游銜接**  
   在 held-out transfer benchmark 上評估 curated recall，確認檢索行為是否跨領域泛化。部署時將 Harness-1 的精選集合傳遞給凍結的前沿生成模型（frozen frontier generator）進行最終回答，無需重新訓練下游模型。

### 潛在風險與注意事項

- **獎勵稀疏與歸因模糊**  
  若僅以最终精選集合是否正確作為獎勵，策略難以判斷失敗來自於搜尋、遺忘證據或驗證不足。**緩解方式**：採用軌跡層級相關文件召回與多樣性獎勵，並在 harness 中記錄每份文件進入精選集合的時機，輔助信用分配（credit assignment）。

- **狀態渲染過度冗長**  
  若證據圖或驗證紀錄未經壓縮直接寫入提示，將快速耗盡上下文預算，導致策略無法讀取新證據。**緩解方式**：嚴格執行重要性標記淘汰、精簡證據連結摘要，並設定動態預算標記（budget marker）提醒模型剩餘容量。

- **領域過擬合**  
  在訓練領域（如財經或專利）表現良好，但遷移至開放網頁或多跳問答時精選召回率下滑。**緩解方式**：保留跨領域的保留遷移基準測試，並在 SFT 與 RL 階段混入多領域軌跡。

- **驗證幻覺與自我確認偏誤**  
  verify 動作依賴策略自行撰寫主張並比對記憶中的文件，可能產生錯誤確信。**緩解方式**：驗證紀錄必須保留原始來源文本的 chunk ID 與內容片段，不僅儲存 verdict，供後續人工或規則稽核。

- **框架維護複雜度**  
  狀態外部化雖減輕策略負擔，但將複雜度轉移至環境工程。**緩解方式**：初期可先以最小可行狀態（僅候選池 + 精選集合 + 搜尋歷史）起步，驗證 RL 收斂後再逐步加入證據圖與驗證紀錄。

### 與其他技術的整合建議

- **混合檢索索引**  
  將 Harness-1 的 search_corpus 與 grep_corpus 底層對接既有向量資料庫（如 Milvus、Pinecone）與傳統 BM25 索引（如 Elasticsearch），讓框架專注於狀態管理，索引層沿用現有基建。

- **下游 RAG 與 Frontier Generator**  
  Harness-1 作為檢索子代理（retrieval subagent），其輸出為經過精選與驗證的文件集合。可直接餵入現有的 RAG 流程或凍結的大型前沿模型（frontier-model searcher）作為上下文，無需替換既有生成模型。

- **LangChain / LlamaIndex 的編排邏輯**  
  若已使用這類框架進行工具編排，需調整其 AgentExecutor 的設計：將「transcript 追加」模式改為「狀態編輯」模式，讓每次工具呼叫回傳的是更新後的工作記憶渲染，而非僅回傳原始觀察字串。

- **監控與可觀測性系統**  
  在 ML pipeline 中追蹤 trajectory recall、tool diversity（搜尋 / 精選 / 驗證 / 審閱的比例分布）與精選集合大小變化，及早發現策略收斂至重複搜尋或過早終止等退化行為。

- **搜尋引擎 API**  
  針對開放網頁場景，可將 fan_out_search 對接 Google/Bing API 或內部爬蟲系統，並在 harness 中實作結果的去重複與壓縮，避免原始 HTML 內容直接進入策略上下文。

### 給不同背景讀者的閱讀建議

**給初學者**  
請聚焦論文圖二與「狀態外部化（state-externalizing）」的直觀概念：想像搜尋代理是一位研究員，Harness-1 的做法是給他一位專職助理（harness）負責整理資料夾、標記重點與核對出處，讓研究員專心決定要找什麼資料。先理解「讓環境記帳、讓模型思考」為何能提升品質，暫時略過 CISPO 強化學習的數學細節。

**給 AI 工程師**  
請重點研讀 harness 的狀態結構設計：精選集合的增刪語法、證據圖的摘要格式、驗證紀錄的儲存結構，以及論文如何將 trajectory recall 與 tool diversity 轉化為可計算的獎勵函數。評估現有 RLHF 基礎設施（如 TRL、Ray RLlib）能否支援「每步回傳結構化狀態而非純文字觀察」的環境介面。

**給研究者**  
請關注狀態外部化對強化學習學習動態的影響，特別是 warm-started curation 如何解決稀疏獎勵（sparse reward）下的早期探索問題，以及 diversity-preserving incentives 如何防止策略 collapse 至重複搜尋。這些設計對其他需要長期記憶的代理任務（如軟體工程代理、科學實驗規劃）具有跨領域啟發。

**給產品經理**  
請掌握「精選召回率（curated recall）」與跨領域遷移數據：Harness-1 在八個基準測試上達到 0.730 平均精選召回率，且在保留遷移測試集上增益特別顯著。評估導入時，請對照自身資料領域的「多跳推理密度」與「上下文長度限制」，估算將狀態管理從模型端移至環境端所需的工程投資與預期檢索品質提升。
