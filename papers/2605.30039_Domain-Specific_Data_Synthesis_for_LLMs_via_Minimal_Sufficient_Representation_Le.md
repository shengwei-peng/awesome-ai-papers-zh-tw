## 摘要翻譯

大型語言模型（Large Language Models, LLM）在通用能力方面已展現顯著的進展，並可透過在領域特定資料（Domain-Specific Data）上進行微調（Fine-Tuning），於特定領域達到優異的表現。然而，為目標領域（Target Domain）取得高品質資料仍是一項重大挑戰。現有的資料合成（Data Synthesis）方法遵循演繹典範（Deductive Paradigm），高度依賴以自然語言（Natural Language）表達的顯式領域描述（Explicit Domain Description）以及精心的提示工程（Prompt Engineering），限制了其在領域難以描述或正式表達之真實世界場景中的適用性。在本研究中，我們著手解決領域特定資料合成中一個尚未被充分探索的問題：在歸納典範（Inductive Paradigm）下，目標領域僅由一組參考範例（Reference Examples）定義，特別是當領域特徵難以用自然語言表達時。我們提出了一個新穎的框架 DOMINO，其從參考樣本（Reference Samples）中學習最小充分領域表徵（Minimal Sufficient Domain Representation），並利用該表徵引導生成領域對齊的合成資料（Domain-Aligned Synthetic Data）。DOMINO 整合提示微調（Prompt Tuning）與對比解耦目標函數（Contrastive Disentanglement Objective），以分離領域層級模式（Domain-Level Pattern）與樣本特定雜訊（Sample-Specific Noise），在保留核心領域特徵（Core Domain Characteristics）的同時緩解過度擬合（Overfitting）。在理論上，我們證明 DOMINO 擴展了合成資料分布（Synthetic Data Distribution）的支撐集（Support），確保更高的多樣性（Diversity）。在實證上，於具挑戰性、領域定義為隱式（Implicit Domain Definition）的程式碼基準測試（Coding Benchmark）中，使用 DOMINO 合成資料進行微調，相較於強大的指令微調骨幹模型（Instruction-Tuned Backbone），Pass@1 準確率（Pass@1 Accuracy）提升了高達 4.63%，展現其有效性與穩健性。本研究為領域特定資料合成建立了一個新典範，無需手動提示設計（Manual Prompt Design）或自然語言領域規格（Natural Language Domain Specification），即可實現實用且可擴展的領域適應（Domain Adaptation）。

### 核心貢獻（3～5點）
- 提出 DOMINO 框架，從參考樣本中學習最小充分領域表徵，並據以引導生成領域對齊的合成資料。
- 整合提示微調與對比解耦目標函數，有效分離領域層級模式與樣本特定雜訊，緩解過度擬合並保留核心領域特徵。
- 理論證明 DOMINO 能擴展合成資料分布的支撐集，確保合成資料具備更高的多樣性。
- 在領域定義為隱式的程式碼基準測試中，使用 DOMINO 合成資料進行微調，相較於指令微調骨幹模型，Pass@1 準確率提升高達 4.63%。
- 建立無需手動提示設計或自然語言領域規格之領域特定資料合成新典範，實現實用且可擴展的領域適應。

### 適合對象
從事大型語言模型領域適應、資料合成與表徵學習之研究者與實務工作者；關注提示微調、對比學習與解耦技術於生成式模型應用之學術與產業人士；以及需在隱式領域定義場景（如程式碼生成）中進行領域特定資料合成，且希望擺脫手動提示設計與自然語言領域規格依賴之開發者與研究團隊。

## 深度分析

#### 方法論解析

DOMINO（本文提出之資料合成框架）的核心在於建立一個 Inductive Paradigm（歸納典範），與傳統依賴 Explicit Domain Description（顯式領域描述）的 Deductive Paradigm（演繹典範）形成根本區別。在 Problem Definition（問題定義）上，Target Domain（目標領域）並非透過 Natural Language Domain Specification（自然語言領域規格）給定，而是僅由一組 Reference Sample（參考樣本）隱式定義。這種 Implicit Domain Definition（隱式領域定義）的設定，使得方法必須從有限的 Reference Example（參考範例）中歸納出潛在的領域規則，而非從預設的 Baseline Prompt（基準提示）進行推導，從而實現無需 Prompt Engineering（提示工程）與 Manual Prompt Design（手動提示設計）的 Domain-Specific Data Synthesis（領域特定資料合成）。

為此，作者提出 Minimal Sufficient Domain Representation（最小充分領域表徵），記為 𝐷∗。此表徵需同時滿足「充分性」與「最小性」兩項資訊理論準則：充分性確保其能完整捕捉 Core Domain Characteristics（核心領域特徵），最小性則確保其能剔除 Sample-Specific Noise（樣本特定雜訊），從而避免 Overfitting（過度擬合）。具體實現上，DOMINO 整合 Prompt Tuning（提示微調）與 Contrastive Disentanglement Objective（對比解耦目標函數）。首先，透過 Implicit Domain Representation Learning（隱式領域表徵學習），在凍結 Backbone（骨幹模型）參數的前提下，於輸入層引入可學習的 Soft Token（軟性詞元）作為連續領域嵌入。接著，透過 Contrastive Learning（對比學習）機制進行 Disentanglement（解耦），將 Domain-Level Pattern（領域層級模式）與個別樣本的特異性分離。此過程可視為 Minimal Sufficient Representation Learning（最小充分表徵學習）的實例化，其目標是提煉出僅保留領域本質的緊湊表徵。

在 Data Synthesis（資料合成）階段，DOMINO 將學習到的 𝐷∗ 注入生成過程，引導 Large Language Model（LLM, 大型語言模型）產生 Domain-Aligned Synthetic Data（領域對齊的合成資料）。理論層面，作者透過多個 Proposition（命題）證明該框架能擴張 Synthetic Data Distribution（合成資料分布）的 Support（支撐集），從而保證 Diversity（多樣性）；同時由於 𝐷∗ 過濾了雜訊，生成樣本能維持與目標領域的一致性，而非僅複製參考樣本的表面特徵。

#### 實驗數據解讀

Experimental Setup（實驗設定）選定 Coding Benchmark（程式碼基準測試）作為驗證場域，原因在於程式領域的領域特性往往難以用自然語言精確表述，屬於典型的隱式領域定義場景。評估指標採用 Pass@1 Accuracy（Pass@1 準確率），衡量模型在單次生成中通過測試的機率，對程式碼生成任務而言是嚴苛且實用的指標。

Main Results（主要結果）顯示，在具有挑戰性的編程任務上，以 DOMINO 合成的 Domain-Specific Data（領域特定資料）進行 Fine-Tuning（微調），相較於強大的 Instruction-Tuned Backbone（指令微調骨幹模型），Pass@1 Accuracy（Pass@1 準確率）最高提升達 4.63%。這證實了歸納式資料合成在真實 Domain Adaptation（領域適應）中的有效性。值得注意的是，作者亦指出單純以參考樣本進行 Supervised Fine-Tuning（監督式微調, SFT）可能失敗甚至損害效能，突顯 DOMINO 透過 Minimal Sufficient Representation Learning（最小充分表徵學習）避免記憶化、促進 Generalization（泛化）的價值。

Deeper Analysis（深入分析）部分涵蓋多項關鍵維度：
1. **Visualization（視覺化）Synthetic Sample Distribution（合成樣本分布）**：驗證 Synthetic Data（合成資料）確實擴展了分布支撐集，而非僅聚集在參考樣本周圍。
2. **𝐷∗ 的 Interpretability（可解釋性）**：Case Study（個案研究）顯示 𝐷∗ 能捕捉可理解的領域語義，證明 Soft Token（軟性詞元）並非無意義的優化產物。
3. **Task Domain（任務領域）Generalization（泛化）**：測試 DOMINO 在更多領域的通用性，確認其不侷限於單一程式語言或題型。
4. **Temperature（溫度, T）與 Domain-Level Soft Token Count（領域層級軟性詞元數量）的影響**：這些生成與模型容量的 Hyperparameter（超參數）調校實驗，揭示了方法對設定選擇的穩健範圍。
5. **Reference Data Percentage（參考資料比例）與 Hyperparameter 𝜆（超參數 𝜆）的影響**：探討資料效率與 Contrastive Disentanglement Objective（對比解耦目標函數）權重的敏感度，顯示即使在有限參考樣本下，DOMINO 仍能維持效能。

此外，Appendix（附錄）中的 Equal Size（同等規模）比較、Live Code Execution（即時程式碼執行）驗證，以及與 MAGPIE（MAGPIE, 基線資料合成方法）的延伸對照，進一步強化了結果的嚴謹性。

#### 與現有研究的比較

現有資料合成方法，無論是基於 Instruction Evolution（指令演化）、Key-point-driven Synthesis（關鍵點驅動合成）或 System Prompts（系統提示），皆隸屬 Deductive Paradigm（演繹典範）。它們共同依賴將領域知識轉譯為文字指令，需要繁複的 Prompt Engineering（提示工程）與 Manual Prompt Design（手動提示設計）。DOMINO 的根本突破在於完全免除 Natural Language Domain Specification（自然語言領域規格），僅需 Reference Example（參考範例）即可運作，這在領域知識難以言傳（如新興科學領域、商業機密邏輯或快速演變的網路俚語）時具有無可替代的實用價值。

相較於直接使用參考樣本進行微調的基線，DOMINO 透過 Contrastive Disentanglement Objective（對比解耦目標函數）分離 Domain-Level Pattern（領域層級模式）與 Sample-Specific Noise（樣本特定雜訊），克服了 SFT 在少量資料下傾向記憶表面特徵、導致 Out-of-Distribution（分布外）表現不佳的缺陷。與 MAGPIE（基線資料合成方法）相比，DOMINO 在參考樣本有限時展現更強的穩健性；Appendix（附錄）中針對 MAGPIE 增加參考樣本數量的實驗，側面暗示 DOMINO 在資料效率上具備優勢。

然而，本研究亦存在可推論的 Limitations（限制）。首先，參考樣本的品質與覆蓋度仍會直接影響學習到的 𝐷∗；若參考樣本存在偏差或極度稀疏，Synthetic Sample（合成樣本）可能繼承甚至放大該偏差。其次，雖然框架避免了 Manual Prompt Design（手動提示設計），但仍需調校如 𝜆、Temperature（溫度）及 Soft Token（軟性詞元）數量等 Hyperparameter（超參數），對於全新領域的自動化適應仍有優化空間。最後，目前實證主要集中在 Coding Benchmark（程式碼基準測試），雖有初步的 Task Domain（任務領域）Generalization（泛化）實驗，但在非程式類、高度抽象領域（如文學風格或音樂類型）的表現尚需更多驗證。

#### 可重現性評估

就提供的文本脈絡而言，作者並未明確宣告釋出開源程式碼、資料集或模型權重。因此，在開源可用性層面，目前無法確認本研究已伴隨公開的原始碼倉庫或預訓練權重。

#### 未來研究方向

基於 DOMINO 建立的歸納式資料合成新典範，未來研究可沿以下方向延伸：

**第一，多模態領域擴展**：將 Minimal Sufficient Representation Learning（最小充分表徵學習）推廣至圖像、音訊或跨模態領域，處理那些同樣難以用文字定義的風格或概念（如藝術流派、音樂類型），發展多模態版本的 DOMINO。

**第二，演繹與歸納的混合範式**：當部分自然語言描述可取得但不完整時，探索如何同時利用 Explicit Domain Description（顯式領域描述）與 Reference Sample（參考樣本），設計能融合兩種資訊來源的統一框架，兼顧精確性與靈活性。

**第三，理論深化與自動化**：進一步緊縮 Synthetic Data Distribution（合成資料分布）Support（支撐集）擴張的理論邊界，並開發 Hyperparameter（超參數）（如 𝜆、Temperature（溫度））的自適應選擇策略，減少對人工調校的依賴，實現真正的自動化 Domain Adaptation（領域適應）。

**第四，極端少量樣本情境**：探索在僅有極少數 Reference Sample（參考樣本）（如 1-shot 或 5-shot）時的 Representation Learning（表徵學習）策略，結合資料增強或 Meta-Learning（元學習）技術，進一步降低 Domain Adaptation（領域適應）的資料門檻。

**第五，𝐷∗ 的再利用**：除了 Data Synthesis（資料合成），Minimal Sufficient Domain Representation（最小充分領域表徵）𝐷∗ 可應用於領域偵測、Out-of-Distribution（分布外）樣本偵測或作為領域檢索的嵌入空間，拓展其應用價值。

**第六，與人類回饋的結合**：將 DOMINO 合成的資料進一步透過強化學習或人類偏好回饋（如 RLHF（基於人類回饋的強化學習） / DPO（直接偏好最佳化））進行篩選與優化，以確保 Synthetic Sample（合成樣本）不僅領域對齊，更符合人類對品質與安全性的要求。

## 論文問答

**Q1：DOMINO 旨在解決什麼核心問題？**
A：DOMINO 旨在解決當目標領域難以用自然語言明確描述時，如何進行領域特定資料合成的問題。現有的資料合成方法大多依賴演繹典範，需要顯式領域描述與精細的提示工程，但在許多真實場景中，領域特性僅能透過少數參考範例隱式定義。因此，本文聚焦於透過歸納典範，僅利用參考樣本來學習領域內在規則，進而生成符合該領域特性的合成資料。

**Q2：現有的資料合成方法為何在真實世界的領域適應中失效？**
A：現有方法遵循演繹典範，預設領域知識可以被轉化為文字指令，並高度依賴顯式領域描述與提示工程。然而，當領域由細微慣例或湧現模式所支配、難以用自然語言正式表述時，這種方法便會失效。此外，僅以有限的參考樣本進行監督式微調，容易導致模型記憶樣本表面的特徵而非學習可泛化的核心領域特徵，造成過度擬合與分布外任務表現不佳。

**Q3：以歸納方式進行領域特定資料合成為何對實務應用很重要？**
A：這個問題對於實務上的領域適應至關重要，因為在許多高價值場景中，領域正處於快速演變或難以文件化的狀態。例如新興科學領域的術語尚未固定、快速變遷的網路次文化，或是機密且文件不全的專有商業邏輯，這些情況下提供參考範例相對容易，但撰寫正式定義幾乎不可能。歸納典範讓實務工作者無需具備提示工程專長或撰寫自然語言領域規格，即可透過範例完成有效的領域適應。

**Q4：DOMINO 框架的核心方法論是什麼？**
A：DOMINO 的核心方法論是從參考樣本中學習一個最小充分領域表徵，並利用此表徵來引導大型語言模型生成領域對齊的合成資料。該框架結合了提示微調與對比解耦目標函數，將領域層級模式與樣本特定雜訊分離。透過這種方式，DOMINO 能夠學習到一個連續的隱式領域嵌入，並以此作為生成條件，促使模型產出遵循該領域歸納原則的新穎樣本。

**Q5：相較於先前的資料合成方法，DOMINO 的關鍵創新是什麼？**
A：DOMINO 的關鍵創新在於從演繹典範轉向歸納典範，以參考範例取代自然語言描述來定義目標領域。它提出了最小充分領域表徵的概念，在資訊理論的基礎上確保該表徵足以捕捉領域本質，同時最小化到足以排除導致過度擬合的無關雜訊。理論上，作者證明了 DOMINO 能夠擴展合成資料分布的支撐集，從而確保生成資料具有更高的多樣性。

**Q6：為何 DOMINO 選擇採用提示微調與對比解耦目標函數？**
A：提示微調被用來學習一個連續的領域嵌入，使模型能夠在不需手動提示設計的情況下，隱式地編碼複雜的領域特性。對比解耦目標函數則專門用於區分可泛化的領域層級模式與各樣本獨有的特異雜訊。這兩項設計的協同作用，使得 DOMINO 在緩解過度擬合有限參考資料的風險之餘，仍能保留生成忠實領域樣本所需的核心領域特徵。

**Q7：DOMINO 在哪些基準測試上進行評估，為何選擇這些測試？**
A：DOMINO 在具挑戰性的程式碼基準測試上進行評估，這些測試的領域定義屬於隱式，難以用自然語言清楚表述。程式碼領域經常涉及細微的風格慣例、邏輯模式與結構細節，這些特性無法透過簡單的文字指令完整捕捉。因此，這類隱式領域定義的基準測試成為驗證歸納式方法能否有效學習並重現領域特定特質的理想場景。

**Q8：主要實驗結果如何證明 DOMINO 的有效性？**
A：在程式碼生成任務上，以 DOMINO 合成資料進行微調後，Pass@1 準確率相較於強大的指令微調骨幹模型最高提升了 4.63%。這項顯著的進步證明了 DOMINO 能夠成功生成高品質且領域對齊的合成資料，並確實增強了模型表現。這些結果也顯示，即使在缺乏顯式領域描述的情況下，DOMINO 依然具有強健性與有效性。

**Q9：作者進行了哪些深入分析來驗證 DOMINO 的設計？**
A：作者進行了多項深入分析，包括視覺化合成樣本分布、探討學習表徵 D* 的可解釋性，以及測試 DOMINO 對更多任務領域的泛化能力。此外，研究也針對溫度（T）、領域層級軟性詞元數量、參考資料比例以及超參數 λ 進行系統性的影響分析。這些分析共同驗證了 DOMINO 的各個設計環節對於合成資料的多樣性與領域忠實度皆有重要貢獻。

**Q10：DOMINO 在哪些實際應用場景中特別具有價值？**
A：DOMINO 特別適用於新興科學領域，這些領域的術語與規範仍在快速演變且尚未固定。它同樣適用於如網路次文化或流行語等快速變遷的文化趨勢，以及機密或文件不全的專有商業邏輯。在這些場景中，實務人員往往可以輕易提供少數代表性範例，但幾乎不可能撰寫出完整的自然語言領域規格。

**Q11：DOMINO 對於產品部署有哪些實務優勢？**
A：DOMINO 消除了對手動提示設計與自然語言領域規格的依賴，大幅降低了領域適應的門檻。由於只需提供參考範例，即使不具備提示工程專長的使用者，也能將大型語言模型適應到特定專業領域。此外，一旦學習到最小充分領域表徵，框架即可持續生成大量合成樣本，具備良好的可擴展性與實用性。

**Q12：這項工作對領域適應與資料合成領域帶來什麼影響？**
A：這項工作建立了領域特定資料合成的新典範，證明了以範例驅動的隱式歸納可以取代傳統的顯式語言演繹。它為過去因難以文字化而無法觸及的領域開啟了模型適應的可能性。透過將資訊理論中的最小充分表徵學習與生成式資料合成相結合，本文為未來可擴展且無需人工定義的領域適應研究奠定了理論與實證基礎。

**Q13：作者承認 DOMINO 存在哪些限制？**
A：雖然詳細的限制討論收錄於附錄 A.3，但從方法設計與實驗分析可以推知，DOMINO 的成效取決於參考樣本是否充分涵蓋目標領域的核心特性。若參考資料比例過低或樣本不具代表性，則學習到的最小充分領域表徵可能無法完整捕捉領域的多樣性。此外，框架雖省去了手動提示設計，但仍需調整如超參數 λ 與領域層級軟性詞元數量等內部參數，這在部分部署環境中可能增加額外的調校負擔。

**Q14：在什麼情況下 DOMINO 可能失效或表現不佳？**
A：當提供的參考樣本極度有限，或未能涵蓋目標領域的關鍵變異性時，DOMINO 可能因歸納證據不足而難以學習正確的領域規則。若參考資料中包含風格衝突或雜訊過大的樣本，對比解耦目標函數可能會錯誤地將樣本特定雜訊保留為領域層級模式。此外，在連代表性範例都極度稀缺，或領域邊界本身模糊不清的情況下，最小充分領域表徵可能無法有效引導生成出忠實的合成樣本。

**Q15：這篇論文提出了哪些未來研究方向？**
A：論文於附錄 A.4 中提及未來工作，並在實驗章節探討了 DOMINO 對更多任務領域的泛化能力，暗示未來可將此歸納式合成典範擴展至更廣泛的應用場景。另一個方向是進一步深化對最小充分領域表徵的理論分析，例如針對合成資料分布支撐集擴展的性質進行更嚴謹的探討。此外，研究如何在有自然語言描述可參考時，將隱式範例歸納與顯式資訊結合，也是極具潛力的後續研究路徑。

## 實務應用指南

### 適用場景

1. **新興科學研究領域的資料擴增**：當目標領域術語尚未標準化（如新型材料科學或生物資訊學中的新發現），難以撰寫顯式領域描述時，可透過 50–200 筆參考樣本歸納出隱式領域定義，並以 DOMINO 生成領域對齊的合成資料，供後續微調使用。
2. **企業內部機密業務邏輯的領域適應**：針對未完整文件化或涉及商業機密的內部系統（如 legacy code 或專屬財務規則），團隊僅能提供少量去識別化的參考範例，DOMINO 可學習其核心領域特徵，避免將樣本特定雜訊誤認為領域規則。
3. **特定程式碼風格與內部程式庫的適配**：在軟體工程場景中，若團隊需讓指令微調骨幹模型學會公司特定的 API 呼叫慣例或程式碼基準測試風格，但難以用文字精確定義「好的內部程式碼」，即可採用歸納典範進行資料合成。
4. **快速演變的文化趨勢與網路語言生成**：面對網路次文化、流行語或區域性社群用語等目標領域，其邊界模糊且持續變動，DOMINO 能從少量代表性文本中學習最小充分領域表徵，生成符合當前語境的訓練資料。
5. **專家知識難以言傳的高專業度任務**：例如法律判決書中的特定法院見解風格、醫療病歷的專科書寫慣例，專家難以撰寫自然語言領域規格，但能挑出標準範例，此時適合以提示微調搭配對比解耦目標函數抽取隱式規則。

### 實作前置條件

- **資料準備**：需蒐集 50 至數百筆高品質參考樣本（依論文實驗，少量即可），重點在於「領域純度」而非數量。參考樣本應盡量覆蓋目標領域的多樣面向，且需經過基礎清洗與去重。
- **運算資源**：需具備可執行提示微調的 GPU 環境（如單卡 A100 或同等級顯卡），用於學習軟性詞元與對比解耦；另需可呼叫的骨幹模型 API 或本地部署的開源大型語言模型，作為合成資料生成器。
- **技術能力**：團隊需熟悉 PyTorch 與 Transformer 生態系，理解提示微調（Prompt Tuning）與對比學習（Contrastive Learning）的基本原理，並具備資料後處理（Post-processing）與 Pass@1 或同等任務評估指標的實作經驗。

### 實作步驟建議

1. **參考樣本策展與品質確認**：從目標領域中精選具代表性的參考範例，移除明顯離群值。此步驟決定最小充分領域表徵的上限。
2. **建立提示微調與對比解耦架構**：在骨幹模型前綴插入可學習的領域層級軟性詞元，設計對比解耦目標函數，將參考樣本配對為「同領域正例」與「跨領域負例」，以分離領域層級模式與樣本特定雜訊。
3. **訓練最小充分領域表徵 D\***：調整超參數 λ 平衡重建損失與對比損失，訓練直至 D\* 能穩定捕捉核心領域特徵。視覺化合成樣本分布確認其支撐集確實擴張。
4. **引導式合成資料生成**：將學習到的 D\* 作為隱式條件，輸入生成模型產生領域對齊的合成資料。建議掃描不同溫度（Temperature T）與生成數量，確保多樣性。
5. **目標模型微調與驗證**：以合成資料對目標大型語言模型進行監督式微調，並在保留的領域測試集上評估 Pass@1 準確率或其他任務指標，確認相較於基準提示法的提升。
6. **部署與持續迭代**：將訓練流程整合至 MLOps 管線，定期以新參考樣本更新 D\*，並監控合成資料分布是否漂移。

### 潛在風險與注意事項

- **過度擬合參考樣本**：若參考資料比例過低或樣本同質性過高，模型可能記憶表面特徵而非學習底層規則。建議透過對比解耦目標函數強制分離樣本特定雜訊，並以視覺化檢視合成樣本分布是否僅圍繞少數參考點。
- **領域層級軟性詞元數量設定失當**：過少的軟性詞元無法承載領域資訊，過多則容易引入雜訊。論文建議針對目標任務進行小規模網格搜尋，而非直接沿用通用設定。
- **溫度 T 與多樣性的權衡**：溫度過低會導致合成資料缺乏多樣性，過高則可能偏離領域核心。實務上應依據即時程式碼執行或人工抽樣結果，選擇能維持領域對齊且支撐集擴張的 T 值。
- **後處理與品質過濾不可省略**：生成後務必執行 Post-processing（如語法檢查、單元測試、重複過濾），避免將格式錯誤或邏輯無效的合成樣本餵入後續微調階段。
- **基準提示設計的隱藏成本**：雖然 DOMINO 減少手動提示設計，但在對比學習階段仍需設計負例取樣策略與基準提示（Baseline Prompts），這部分仍需領域專家介入審核。

### 與其他技術的整合建議

- **與 RAG（檢索增強生成）協作**：DOMINO 負責「訓練前」的資料合成與領域適應，RAG 則在「推論時」提供即時檢索能力。兩者結合可讓模型既具備領域內化知識，又能引用最新外部文件。
- **融入現有資料擴增管線**：可將 DOMINO 作為 MLOps 中的資料合成節點，與 MAGPIE 等演繹式方法並行。當部分領域可用自然語言規格描述時，以演繹法生成大規模通用資料；針對難以言傳的子領域，則啟動 DOMINO 的歸納典範。
- **搭配即時執行驗證環境**：在程式碼基準測試場景中，建議將合成資料直接餵入即時程式碼執行環境進行過濾，僅保留可執行且結果正確的樣本，形成「生成→執行→篩選→微調」的閉環。
- **接軌模型版本控制系統**：由於 D\* 與軟性詞元屬於連續向量，建議將其連同參考樣本版本一併記錄於模型倉庫（如 MLflow 或 Weights & Biases），確保合成資料分布的可追溯性。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦論文第 1 節與第 3.1 節的「歸納典範 vs. 演繹典範」概念，理解 DOMINO 解決的核心痛點——「有範例但寫不出領域定義」。數學證明與對比損失公式可先略讀，待熟悉提示微調基礎後再回頭細究。
- **AI 工程師**：建議深入研讀第 3.2 至 3.3 節的隱式領域表徵學習與對比解耦目標函數實作細節，特別是超參數 λ 的影響與領域層級軟性詞元的初始化策略。附錄 A.2 的實驗細節與後處理流程是復現與落地時的關鍵參考。
- **研究人員**：請重點關注第 3.3 節與附錄 A.1 的理論保證，尤其是命題 1–4 關於支撐集擴張與最小充分領域表徵的資訊理論分析。論文將資料合成問題重新框架為表徵學習問題，此視角對後續研究設計極具啟發性。
- **產品經理**：請優先閱讀摘要、第 1 節與第 4.2 節的主要結果。掌握「無需手動提示設計即可達成領域適應」的商業價值，並留意論文列出的適用場景（如新興科學、機密業務邏輯），評估其與自家產品資料痛點的匹配度。
