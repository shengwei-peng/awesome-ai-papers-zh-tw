## ⚡ TL;DR

現有智能體在理想化訓練後，面對真實世界雜訊時效能大幅退化。
本文提出NoisyAgent框架，透過結構化擾動與適應性課程排程，在訓練中注入使用者與工具雜訊。
實驗顯示該方法不僅提升動態環境下的穩健性，也在理想基準測試上帶來效能增益。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）的最新進展促使 LLMs 得以作為具備推理（reasoning）、規劃（planning）與工具使用（tool use）能力的互動式智能體（interactive agents）而廣泛部署。儘管在現有基準測試（benchmarks）上表現優異，此類智能體在部署至本質上隨機（stochastic）且具缺陷的真實世界環境時，往往出現顯著的效能退化（performance degradation）。我們認為這種差異源於理想化訓練設定（idealized training settings）與真實世界互動動態（real-world interaction dynamics）之間的根本性不匹配：當前典範仰賴精心挑選的任務指令（curated task instructions）以及穩定、控制良好的環境。為了彌合此差距，我們提出 NoisyAgent，一個將環境缺陷（environmental imperfections）明確納入智能體學習過程的智能體訓練框架（agentic training framework）。我們識別出真實世界情境中互動雜訊（interaction noise）的兩大主要來源：使用者雜訊（user noise），涵蓋使用者互動中的歧義性（ambiguity）與變異性（variability）；以及工具雜訊（tool noise），反映工具執行中的失敗與異常（anomalies）。我們透過修改使用者互動模式（user interaction patterns）並在訓練環境中模擬工具執行結果（tool execution results），將此類擾動（perturbations）引入訓練流程（training pipeline）。為了在穩定訓練的同時，鼓勵智能體處理日益困難的缺陷，雜訊僅施加於部分推展（rollouts），並隨著模型適應當前雜訊等級（noise level）而逐步提升難度。大量實驗證明，我們的方法能一致地提升智能體在雜訊與動態環境（dynamic environments）下的穩健性（agent robustness）。我們的分析顯示，在雜訊條件下訓練亦能在理想化基準測試（idealized benchmarks）上帶來效能增益，意味著受控地暴露於環境雜訊，能促進更具可泛化的推理（generalizable reasoning）與決策行為（decision-making behaviors）。我們的研究結果強調了對互動缺陷建模以彌合智能體訓練與真實世界部署（real-world deployment）之間差距的重要性。

### 核心貢獻（3～5點）
- 提出 NoisyAgent 智能體訓練框架，將環境缺陷（使用者雜訊與工具雜訊）系統性地納入智能體學習過程，以縮小理想化訓練與真實世界部署之間的差距。
- 設計漸進式雜訊注入機制：透過修改使用者互動模式與模擬工具執行結果引入擾動，僅對部分推展施加雜訊，並依據模型適應程度動態提升雜訊等級，兼顧訓練穩定性與挑戰性。
- 廣泛實驗證明，此方法能一致地提升智能體在雜訊與動態環境下的穩健性。
- 揭示受控地暴露於環境雜訊不僅能增強真實世界適應力，亦能在理想化基準測試上帶來效能增益，促進更具可泛化的推理與決策行為。

### 適合對象
從事大型語言模型智能體、強化學習與穩健性研究的學者與工程師，特別是關注真實世界部署、互動雜訊建模，以及致力於縮短理想化訓練與實際應用落差的研究者與實務工作者。

## 深度分析

#### 方法論解析

本研究提出之 NoisyAgent 是一個針對雜訊環境（noisy environments）的智能體訓練框架（agentic training framework），其核心目標在於縮小理想化訓練設定（idealized training settings）與真實世界互動動態（real-world interaction dynamics）之間的根本落差。方法論可拆解為四個層次：問題形式化、雜訊注入機制、課程式訓練排程，以及策略最佳化（policy optimization）。

在問題形式化層面，作者將每個任務建模為 Partially Observable Markov Decision Process（POMDP，部分可觀察馬可夫決策過程）：M = (S, A, O, T, R)。其中智能體（agents）狀態 s_t = (s_env, h_t, q) 整合了環境狀態、互動歷史與任務提示。值得注意的是，動作空間 A = A_user ∪ A_tool 與觀察空間 O = O_user ∪ O_tool 被顯式拆分為使用者端與工具端，這為後續結構化地注入互動雜訊（interaction noise）提供了明確的介面。此處採用之訓練目標為 Reinforcement Learning with Verifiable Rewards（RLVR，可驗證獎勵之強化學習），透過 verifier 在軌跡層級給予稀疏獎勵，並以 Group Relative Policy Optimization（GRPO，群組相對策略最佳化）進行策略最佳化。

雜訊注入機制是 NoisyAgent 的創新核心。作者識別出兩大真實世界雜訊來源：使用者雜訊（user noise）與工具雜訊（tool noise）。前者透過修改使用者指令（user instructions）與使用者互動模式（user interaction patterns）來模擬歧義性（ambiguity）與變異性（variability）；後者則透過模擬工具執行結果（tool execution results）或工具回應（tool responses）中的執行異常（execution anomalies）與失敗輸出，來反映外部工具（external tools）在真實部署中因不可控因素（uncontrollable factors）導致的環境缺陷（environmental imperfections）。這些結構化擾動（structured perturbations）並非全域施加，而是僅作用於部分推展（rollouts）上，形成混合推展（hybrid rollouts）——同時包含無雜訊軌跡（clean trajectories）與雜訊軌跡（noisy trajectories）。

為了避免貿然注入雜訊造成訓練動態（training dynamics）崩潰，作者設計了適應性排程器（adaptive scheduler）執行課程排程（curriculum schedule）。該排程器從輕微擾動（mild perturbations）開始，依據效能差距（∆）（performance gap）動態調整雜訊等級（noise level）與雜訊比例。具體而言，∆ 定義為同一任務在理想化環境與擾動環境下的表現落差；當智能體在當前階段展現足夠的智能體穩健性（agent robustness）時，排程器才提升雜訊強度。這確保了訓練過程始終處於「具挑戰性但可學習」的區間，避免在過度雜訊的區域進行無效率探索。

最後，在策略最佳化層面，GRPO 原本即採用群組歸一化（group-wise normalization）計算優勢函數。NoisyAgent 延續此設計，但透過混合推展使歸一化基準同時涵蓋無雜訊與雜訊軌跡，從而穩定異質互動條件（heterogeneous interaction conditions）下的梯度更新。整體而言，此方法論將環境缺陷從「部署時的意外」轉化為「訓練時的結構化課程」，是一種從迴避式穩健性轉向暴露式穩健性的典範轉移。

#### 實驗數據解讀

必須先聲明，根據提供的全文脈絡，文本在 Preliminary（預備知識）之環境擴展段落中截斷，實驗章節、數據表格與具體數值並未包含於上下文內。因此，本節將基於摘要（Abstract）與引言（Introduction）之宣稱，對其實驗設計邏輯與結果意涵進行結構性分析。

作者宣稱進行了廣泛實驗，其評估場景應包含兩類：一是在注入真實世界雜訊的擴增基準測試上測試智能體穩健性；二是在標準的理想化基準測試（idealized benchmarks）上驗證是否產生性能增益。前者直接驗證方法論的核心價值——智能體在雜訊與動態環境（dynamic environments）中能否維持效能；後者則是一項重要的副產品發現，暗示對環境雜訊的受控暴露能促進更可泛化推理（generalizable reasoning）與決策行為（decision-making behaviors）。

從方法論反推，實驗中最關鍵的指標應為效能差距（∆）（performance gap）。此指標不僅作為適應性排程器（adaptive scheduler）的訓練訊號，也應被用於量化最終模型的穩健性——即 ∆ 越小，代表智能體在理想與擾動條件下的表現越一致。若作者如宣稱般觀察到「在標準基準測試上亦有穩定增益」，則意味著雜訊感知訓練並未損害模型對無雜訊資料的擬合能力，反而透過豐富訓練分佈（implicit difficulty augmentation）提升了泛化邊界。這與傳統正則化或資料增強的邏輯一致，但差異在於此處的擾動是結構化且語義層次的（指令歧義、工具異常），而非單純的 token-level noise。

此外，由於訓練環境是透過自動化流程（automated pipeline）從高階領域規格合成而來，實驗的可擴展性與領域覆蓋度應是另一個隱含優勢。作者可能報告了跨領域（domain graph D 的不同採樣）的泛化結果，以證明方法不僅對特定雜訊樣態過擬合。然而，缺乏具體數據下，我們無法判斷該增益是統計顯著還是邊際改善，也無法評估不同雜訊等級（noise level）對最終收斂速度的影響。

#### 與現有研究的比較

本研究明確定位於填補現有智能體學習範式中的結構性缺口。現有範式普遍依賴理想化假設（idealized assumptions），包括精心挑選的任務指令（carefully curated task instructions）與穩定可控的環境 [13–15]。相較之下，NoisyAgent 將環境缺陷（environmental imperfections）內化為訓練流程的必要組件，而非部署後的例外處理。

在強化學習（reinforcement learning, RL）領域，隨機擾動（stochastic perturbations）已被證實能提升策略穩健性 [24–26]，但這些工作多集中於傳統 RL 的狀態或動作空間（如機器人控制中的物理擾動）。NoisyAgent 的貢獻在於將此概念遷移至以大型語言模型（large language models, LLMs）為基礎的互動式智能體（interactive agents）之語義與工具執行層面，並針對使用者雜訊（user noise）與工具雜訊（tool noise）設計了結構化生成機制。這比單純在輸入文字中加入隨機刪減或同義詞替換更具語義真實性，因為它模擬了真實互動中使用者意圖的歧義性（ambiguity）與外部工具（external tools）的執行異常（execution anomalies）。

在環境建構方面，作者延續了近期自動化環境擴展管線 [34] 的思路，透過領域圖譜（domain graph）合成可執行環境。NoisyAgent 的進步在於將此管線擴展為「雙面建構」：使用者端建構（user-side construction）負責生成任務目標與互動模式，工具端建構（tool-side construction）負責實現工具 API 與環境動態，並在兩端同時注入擾動。這使得訓練環境的規模化不再僅限於「乾淨」的組合空間，而是涵蓋了真實世界的異質互動條件（heterogeneous interaction conditions）。

然而，從現有文本亦可推論其限制。首先，雜訊模型目前僅涵蓋使用者與工具兩端，尚未明確處理 reward noise（獎勵雜訊）或環境轉移函數 T 本身的隨機性。其次，課程排程雖然直覺上有效，但其收斂性與最優性缺乏理論保證；若效能差距（∆）（performance gap）的估計本身存在高變異，可能導致排程器過早或過晚提升雜訊強度。最後，與所有基於合成環境的方法類似，其模擬的雜訊分佈是否與真實世界部署（real-world deployment）中的不可控因素（uncontrollable factors）一致，仍需外部驗證。

#### 可重現性評估

就提供的文本脈絡而言，作者並未提及原始碼、資料集或模型權重的公開釋出，因此從開放科學（open science）的角度，本研究的可重現性（reproducibility）在當前階段尚無法獨立驗證。以下從方法論設計層面評估其重現難度。

第一，環境建構依賴於一套自動化流程（automated pipeline），該流程從高階領域規格初始化領域特定工具集（domain-specific toolset）與統一資料庫綱要（unified database schema）。重現此系統需要完整的領域圖譜生成邏輯、工具鏈採樣機制，以及底層資料庫的實作細節。這些元件的缺失將使外部研究者難以重建相同的訓練流程（training pipeline）。

第二，雜訊注入的具體實作細節（如使用者指令的歧義化規則、工具回應的異常模擬機率分佈）在現有文本中僅有概念性描述，缺乏模板或參數設定。由於混合推展（hybrid rollouts）涉及無雜訊軌跡（clean trajectories）與雜訊軌跡（noisy trajectories）的比例調度，且適應性排程器（adaptive scheduler）依賴 ∆ 的計算閾值，這些超參數（初始雜訊比例、難度提升步長、GRPO 的群組大小 G）對訓練動態（training dynamics）至關重要，但均未在提供的段落中揭露。

第三，GRPO 與 RLVR 的基礎架構雖已見於公開文獻 [28–31]，但 NoisyAgent 的群組歸一化（group-wise normalization）在異質軌跡上的應用可能需要特定的實作調整（例如，是否對 clean 與 noisy 軌跡分別歸一化，或統一歸一化）。若無程式碼層級的釋出，這些實作細節將成為重現的暗礁。

整體而言，在缺乏原始碼與環境生成管線的情況下，本研究屬於「概念可重現、工程難重現」的類別。建議作者未來釋出環境合成框架與雜訊注入模板，以利社群驗證。

#### 未來研究方向

基於 NoisyAgent 的方法論架構，以下提出數個具潛力的後續研究方向：

1. **擴展雜訊光譜**：當前框架聚焦於使用者雜訊（user noise）與工具雜訊（tool noise）。未來可納入 observation noise（觀察雜訊，如部分可觀察狀態的遺失）、reward noise（獎勵雜訊，如 verifier 的評判誤差），以及 temporal noise（時間雜訊，如工具回應延遲）。這將使智能體在更極端的隨機（stochastic）環境中學習。

2. **理論分析課程排程器**：適應性排程器（adaptive scheduler）依據效能差距（∆）（performance gap）動態調整雜訊難度，但其收斂性與樣本複雜度（sample complexity）尚無理論保證。未來可針對此課程式 RL 建立後悔界（regret bound）或收斂定理，特別是在異質互動條件（heterogeneous interaction conditions）下的策略梯度穩定性分析。

3. **跨領域穩健性驗證**：現有環境基於領域圖譜（domain graph）合成，未來應驗證在跨領域（out-of-domain）圖譜上的 zero-shot robustness（零樣本穩健性）。若智能體僅對訓練時見過的雜訊型態穩健，則其可泛化推理（generalizable reasoning）仍屬有限。

4. **人類回饋對齊**：目前的使用者雜訊為自動生成，其分佈可能與真實人類的歧義性（ambiguity）與變異性（variability）存在差異。引入 human-in-the-loop（人類參與）收集真實互動數據，並以此校準雜訊生成模型，可縮小 simulation-to-reality（模擬到真實）的差距。

5. **多智能體雜訊交互**：將 NoisyAgent 擴展至多智能體系統，其中其他智能體亦在雜訊環境中決策。這將產生複合不確定性（compound uncertainty），要求智能體具備更高階的 theory of mind 與協商能力。

6. **不確定性量化與拒絕機制**：除了提升任務成功率，未來可訓練智能體主動估計自身在不確定互動中的信心水準，並在使用者指令（user instructions）過度歧義或工具回應（tool responses）嚴重異常時選擇「釐清」或「拒絕執行」，而非強行完成任務。這對高風險應用（high-stakes applications）的真實世界部署（real-world deployment）尤為重要。

## 論文問答

**Q1：為什麼現有的大型語言模型智能體在真實世界部署時會出現顯著的效能退化？**
A：現有的大型語言模型智能體大多在理想化且精心控制的環境中進行訓練，這些環境使用經過挑選的任務指令與穩定的互動設定。然而，真實世界本質上充滿隨機性與不完美性，使用者的互動方式具有歧義性與變異性，而外部工具也可能因不可控因素傳回雜訊、不完整甚至失敗的結果。這種訓練條件與部署環境之間的根本性差異，導致智能體在面對真實場景時無法維持其在基準測試上的高水準表現，進而產生顯著的效能退化。

**Q2：現有的智能體訓練典範存在什麼根本性的缺陷，使其難以應對真實場景？**
A：現有典範的核心缺陷在於過度依賴理想化假設，將訓練過程建立在環境穩定且互動完美的前提之上。這種做法忽略了真實部署場景中必然存在的環境缺陷與互動雜訊，使得智能體缺乏處理不確定性的經驗。由於訓練與部署之間存在嚴重的分佈偏移，智能體在遭遇未曾學習過的擾動時，往往無法有效恢復錯誤或適應意外結果，導致穩健性嚴重不足。

**Q3：為什麼在訓練過程中顯式建模環境缺陷對智能體的真實世界部署至關重要？**
A：真實世界的應用場景中，使用者雜訊與工具雜訊無所不在，若訓練過程完全排除這些因素，智能體將無法發展出應對現實複雜性的能力。透過在學習階段引入受控的環境不完美性，智能體能夠學習如何解決歧義、從錯誤中恢復，並適應非預期的執行結果。這種訓練方式不僅能縮短實驗室環境與真實世界之間的差距，更是確保智能體在實際應用中保持可靠與穩健的關鍵前提。

## 實務應用指南

### 適用場景

1. **企業級客戶服務與技術支援智能體**  
   真實用戶的提問常帶有歧義性、口語化或拼寫錯誤（使用者雜訊），同時後端系統如客戶關係管理（CRM）資料庫或庫存查詢 API 可能回傳超時或異常（工具雜訊）。NoisyAgent 可訓練智能體在這類異質互動條件下，仍能正確解析意圖並優雅降級。

2. **軟體開發與自動化維運（DevOps）助理**  
   開發者輸入的需求往往不完整或存在變異性（使用者雜訊），而編譯器、測試框架與第三方服務可能出現 flaky 錯誤或版本衝突（工具雜訊）。透過在訓練流程中注入執行異常，可提升智能體在真實開發環境中的除錯與規劃穩健性。

3. **醫療輔助問診與病歷處理系統**  
   患者描述症狀時常使用非專業且模糊的語言（使用者雜訊），而電子病歷（EHR）系統或醫療知識庫查詢可能回傳缺漏資料（工具雜訊）。此框架能讓智能體學習在資訊不完整時主動追問，而非直接產生高風險的錯誤推論。

4. **智慧製造與倉儲物流調度**  
   現場操作員的語音或文字指令可能簡略且含混（使用者雜訊），而機器手臂、感測器或倉儲管理系統的 API 可能回報異常狀態（工具雜訊）。NoisyAgent 可強化智能體在動態環境中的容錯與重新規劃能力。

### 實作前置條件

**資料與環境**
- **領域規格與領域圖（Domain Graph）**：需定義工具集、資料庫綱要與任務組合結構，作為自動化環境擴展的基礎。
- **無雜訊基準軌跡**：需預先建立一組乾淨的參考推展（clean trajectories），用於計算效能差距（∆）與初始化課程排程。
- **真實錯誤日誌**：收集生產環境中實際的使用者輸入變異與工具失敗模式，用以校準雜訊分布。

**運算資源**
- **GPU 叢集**：支援大型語言模型強化學習微調（如 GRPO），需具備足夠記憶體以同時執行多組推展（rollouts）。
- **環境模擬器**：可並行化執行使用者互動模擬與工具回應注入的運算節點。
- **向量資料庫與狀態儲存**：用於維護動態環境狀態與互動歷史。

**技能需求**
- **強化學習與策略最佳化**：熟悉 PPO/GRPO、優勢函數計算與群組歸一化。
- **LLM 微調與推理工程**：具備 vLLM、DeepSpeed 或類似框架的實作經驗。
- **API 與系統設計**：能設計結構化工具 API 並建置沙箱環境，避免訓練過程觸發真實副作用。
- **評估設計**：需建立可驗證獎勵（verifiable rewards）的評分規則與自動化評量管線。

### 實作步驟建議

**步驟一：建構可擴展的訓練環境**  
依據領域圖（Domain Graph）自動生成使用者端建構（任務提示與互動模式）與工具端建構（結構化 API 與環境資料庫）。先在此理想化環境中訓練基線策略，確保基本任務完成率達標。

**步驟二：定義並自動化注入結構化擾動**  
針對目標應用識別兩大雜訊來源：
- **使用者雜訊**：修改使用者指令，引入歧義性、風格變異、缺漏資訊或不可預測的行為模式。
- **工具雜訊**：模擬工具執行結果，如回傳不完整資料、異常錯誤碼或隨機延遲。  
建立自動化流程，將這些擾動注入訓練環境。

**步驟三：實作混合推展（Hybrid Rollouts）**  
對每個任務同時採樣無雜訊軌跡與雜訊軌跡，形成異質互動條件下的訓練資料。初始階段僅對少數推展注入輕微擾動，避免訓練動態過早失穩。

**步驟四：部署適應性排程器（Adaptive Scheduler）**  
持續監控無雜訊與有雜訊環境下的效能差距（∆）。當智能體在當前雜訊等級展現足夠穩健性時，再提升雜訊難度與注入比例。此課程排程確保訓練始終具備資訊性，而非被過度雜訊淹沒。

**步驟五：採用群組歸一化進行策略最佳化**  
使用 GRPO 等支援群組歸一化的演算法，在混合推展的批次上計算相對優勢。這能有效穩定學習過程，降低因軌跡獎勵分布差異過大導致的梯度方差。

**步驟六：雙軌評估與漸進部署**  
同時在理想化基準測試與帶有真實世界雜訊的測試集上驗證。通過後，先以影子模式（shadow mode）部署，比對生產流量中的穩健性提升，再逐步開放給終端使用者。

### 潛在風險與注意事項

- **訓練動態失穩**：若初期即採用高強度擾動或過高比例的雜訊推展，策略梯度方差將急遽放大，導致訓練崩潰。務必嚴格遵循由輕微擾動開始的課程排程，並監控群組獎勵的標準差。
- **群組歸一化掩蓋真實進展**：在異質互動條件下，GRPO 的歸一化可能使無雜訊與雜訊軌跡的獎勵相互抵消。建議分開記錄兩類軌跡的獨立獎勵曲線，作為輔助診斷指標。
- **雜訊分布與真實世界偏移**：若訓練中模擬的工具雜訊過於簡化（如僅隨機回傳空值），智能體可能無法泛化到實際的複合異常。應定期從生產日誌萃取真實錯誤模式，迭代更新擾動模型。
- **安全與副作用風險**：在訓練過程中模擬工具呼叫時，必須確保所有外部 API 處於沙箱或模擬狀態，避免對真實資料庫造成寫入或產生非預期費用。
- **過度保守行為**：過度強調雜訊恢復可能使智能體傾向於過度確認或拒絕執行。需在獎勵設計中平衡「謹慎」與「效率」，防止效能退化。

### 與其他技術的整合建議

- **檢索增強生成（RAG）與知識庫**：將工具雜訊擴展至檢索失敗情境（如知識庫回傳不相關片段），訓練智能體在檢索結果不穩定時切換推理策略或重構查詢。
- **可觀測性平台**：整合 LangSmith、Weights & Biases 或自建監控系統，細粒度追蹤每一條推展的雜訊類型、效能差距 ∆ 與策略熵值，協助調適適應性排程器。
- **API 閘道與混沌工程**：無需修改後端服務，透過 API Gateway 或服務網格（service mesh）有控制地注入延遲、錯誤碼與流量限制，作為真實工具雜訊的來源。
- **人類回饋強化學習（RLHF）**：在可驗證獎勵之外，引入人類偏好資料，特別針對「面對歧義時的互動禮貌性」與「錯誤恢復的流暢度」進行對齊。
- **結構化輸出與防護欄（Guardrails）**：即使經過雜訊訓練，仍建議在推理階段搭配輸入驗證與輸出解析器，作為最後一道安全防線。

### 給不同背景讀者的閱讀建議

**給初學者**：請先聚焦論文的核心直覺——「在訓練時刻意製造混亂，能讓智能體在真實世界的混亂中表現更好」。無需深入 GRPO 的數學推導，重點理解圖一的整體架構：混合推展、適應性排程與兩種雜訊來源。你可以將 NoisyAgent 想像成智能體的「疫苗接種」機制。

**給 AI 工程師**：請特別關注實作細節：混合推展中無雜訊與雜訊軌跡的比例如何設定、適應性排程器的 ∆ 閾值與難度提升策略、GRPO 的群組大小（group size）對異質條件穩定性的影響，以及如何設計可自動化擴展的領域圖與雜訊注入管線。這些是將論文轉化為產品的關鍵工程決策。

**給研究人員**：本文的理論貢獻在於將「環境缺陷」系統性地納入智能體強化學習的訓練動態，並提出雜訊作為隱式難度擴增（implicit difficulty augmentation）的觀點。建議深入探討課程排程在 POMDP 框架下的收斂性、群組歸一化對雙峰獎勵分布的影響，以及為何受控的環境雜訊能促進可泛化推理與決策行為。

**給產品經理**：這篇論文直接回應了「為何實驗室表現亮眼的 AI，上線後卻頻頻出錯」的商業痛點。請關注訓練投入與部署穩健性之間的權衡：雜訊訓練需要額外的運算與環境建置成本，但能顯著降低生產環境中的異常處理成本與使用者流失。評估時請同時追蹤理想化基準與帶噪測試的指標，向利害關係人說明這是一項同時提升「上限」與「下限」的投資。
