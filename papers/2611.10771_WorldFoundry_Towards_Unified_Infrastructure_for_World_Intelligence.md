## ⚡ TL;DR

視覺生成模型雖逼真，但缺乏持久狀態與因果一致性，且異質世界建模系統難以可重現地比較。
本文提出開源基礎設施WorldFoundry，統一模型探索、執行編排、產物管理與證據感知評測。
其目錄收錄270個模型、74項基準與62項指標，推動領域從感知合成邁向可量測的世界智慧。

### 核心貢獻（3～5點）
- 提出生成式世界模型的操作型定義：將其形式化為預測性動力系統，須具備持久化、歷史條件化表徵，並能對可觀察干預與反事實干預產生時間一致性軌跡。
- 衍生五維智慧導向框架：涵蓋感知基礎、持續狀態建模、可控轉換、動態感知預測與閉環互動，為世界建模能力提供系統化的評測維度。
- 開源 WorldFoundry 統一基礎設施：跨影片、三維、四維、具身動作與互動式世界系統，整合模型與基準探索、執行環境準備、執行編排、產物管理與互動式視覺化。
- 透過模態特定適配器保留各模態的原生輸入、執行語義、輸出表徵與評測協定，兼顧統一性與異質性。
- 建立可信度分離機制：以宣告檔、持久有效的產物契約與證據感知評分卡區分執行就緒度與評測性主張，實現可追溯的可重現比較。

## 深度分析

#### 方法論解析

WorldFoundry 的方法論核心在於提出一個**功能抽象（functional abstraction）**而非架構約束的統一框架，用以整合異質的生成式世界模型（generative world models）。此設計哲學體現於三個層次的解構：

**第一層：操作性定義（operational definition）的形式化**

論文將生成式世界模型定義為一個「預測性動力系統（predictive dynamical system）」，並將其拆解為三個緊耦合的功能元件：

1. **狀態推論（state inference）**：從觀察歷史中估計潛在環境狀態；
2. **前向模擬（forward simulation）**：預測該狀態在內生動力（endogenous dynamics）與外部干預（external interventions）下的演化；
3. **互動回應（interactive response）**：產生動作條件化（action-conditioned）的未來，作為視覺、幾何或任務特定的輸出。

此分解刻意保持「功能性而非架構性（functional rather than architectural）」，意即不強迫每個系統實作全部三項操作，而是以「能力進展（capability progression）」描述不同系統所支援的子集。例如，靜態 3D 方法強調持續狀態推論與幾何解碼；影片模型主要學習隱式轉換與觀察生成；4D 方法顯式表徵時變結構；具身模型（embodied models）則連結狀態估計與動作預測至決策過程。

**第二層：能力導向框架（intelligence-oriented framework）**

從上述定義衍生出五個能力維度：感知基礎（perceptual grounding）、持續狀態建模（persistent state modeling）、可控轉換（controllable transformation）、動態感知預測（dynamics-aware prediction）、閉環互動（closed-loop interaction）。此框架的關鍵洞見在於：**「視覺合理性（visual plausibility）」本身並不等於世界建模**——一個模型可能生成令人信服的影像，卻缺乏持續狀態、物理動力學或對干預的因果一致性回應。因此，框架強調「持久性（persistence）」必須是操作性的：干預必須在狀態中留下可約束後續預測的痕跡，每個新觀察也必須反過來修正該狀態。

**第三層：五層系統架構（five-layer system architecture）**

WorldFoundry 的工程實作採用分層設計：

- **表層（Surface Layer）**：提供 TUI、CLI、Workspace/Studio、Python API 與 MCP（Model Context Protocol）等多重互動介面，確保「一次執行可從每個互動與程式化介面觸及」；
- **統一推論與互動（Unified Inference and Interaction）**：核心執行層，透過 `GenerationRequest`、`WorldModelRunner`、`GenerationResult` 等抽象物件，支援一次性（one-shot）與會話常駐（session-resident）兩種執行模式，並透過原生參數（native parameters）保留各模型的執行語義（execution semantics）；
- **產物契約（Artifact Contracts）**：以 `ArtifactRef`（含 URI、格式、中繼資料、雜湊值）作為強型別參考，支援媒體、幾何、4D、動作、軌跡、狀態追蹤等多類產物；
- **評測與證據（Evaluation & Evidence）**：基準執行器（benchmark runner）將結果持久化為可重用的指標，並透過「證據感知評分卡（evidence-aware scorecard）」區分一致性、互動性、物理性、生成品質等面向；
- **模型與基準動物園（Model & Benchmark Zoo）**：以宣告檔（manifest）綁定探索、執行環境與評測，使每項主張可追溯至其證據。

**模態特定適配器（modality-specific adapters）**的設計哲學值得特別強調：適配器保留原生輸入、執行語義、輸出表徵與評測協定，避免將異質系統強行壓平為單一表示，從而在統一介面與原生語義之間取得平衡。

#### 實驗數據解讀

論文的實驗驗證呈現「規模優先於單點效能」的特徵，這與其作為基礎設施的定位一致：

**目錄規模（catalog scale）**

- **270 個模型條目（model entries）**：涵蓋影片、3D、4D、互動世界、具身動作五大模態；
- **74 個基準（benchmarks）**：對應各模態的標準評測集；
- **62 個已註冊指標條目（registered metric entries）**：包含 FVD、IS 等影片指標，以及物理一致性、因果回應等世界模型特定指標。

此規模本身即是一項貢獻：它意味著研究者可在統一環境下進行跨模態、跨模型的比較，而無需逐一處理各系統的環境配置。

**四模態實驗驗證**

1. **影片生成（Video Generation）**：驗證系統在處理時間一致性軌跡（temporally coherent trajectories）時的推論管線穩定性；
2. **互動式世界模型（Interactive World Model）**：測試閉環互動（closed-loop interaction）下的狀態持續性與動作回應；
3. **3D 與 4D 生成（3D & 4D Generation）**：檢驗幾何解碼與時變結構的產物契約是否完整；
4. **具身動作生成（Embodied Action Generation）**：驗證狀態估計與動作預測的整合。

**關鍵設計：執行就緒度與評測性主張的分離**

論文中最具方法論意義的設計是將「執行就緒度（execution readiness）」與「評測性主張（evaluative claims）」明確分離。具體而言：

- **就緒度證據（readiness evidence）**：記錄模型是否能成功載入、執行預檢（preflight）通過、產出有效產物；
- **執行證據（execution evidence）**：記錄實際執行結果、計時、錯誤狀態；
- **評測證據**：在基準上跑出的分數，附帶資料覆蓋率、評測器版本、執行環境等中繼資料。

此分離避免了「模型在某基準上分數很高，但實際上無法重現」的常見問題，使每項評測性主張都可追溯至具體的產物與執行紀錄。

**實驗結果的解讀限制**

需注意，論文的實證章節主要展示「系統可運作於多模態」而非「某模型優於另一模型」。這是基礎設施論文的典型定位：它提供可重現比較的舞台，而非宣稱特定模型的優越性。因此，讀者應將實驗結果理解為「WorldFoundry 確實能整合 270 個模型並產生可比較的證據」，而非單純的排行榜。

#### 與現有研究的比較

**與 OpenWorldLib 的關係**

論文明確指出 OpenWorldLib [5] 處理「整合問題的互補面向」，但 WorldFoundry 在以下幾點上有所不同：

- **更廣的模態覆蓋**：從影片擴展至 3D、4D、互動世界、具身動作；
- **更強的契約化（contractualization）**：透過 `ArtifactRef` 與強型別產物參考，確保產物的可追溯性與持久性；
- **更明確的證據分層**：將執行就緒度、執行證據、評測證據分離，避免混淆。

**與強化學習世界模型文獻的關係**

論文的定義援引了早期強化學習中的世界模型概念（如 Ha & Schmidhuber 的工作 [1-3]），但做了關鍵擴展：

- 從「決策輔助工具」擴展至「通用視覺/幾何/動作生成」；
- 強調「反事實干預（counterfactual intervention）」的回應能力，這在 RL 設定中較少被強調；
- 引入「持續狀態的操作性定義」，使世界模型與單純的影片生成器明確區分。

**與基礎模型（foundation model）研究的關係**

論文區分了「基礎生成模型（foundational generative models）」與「生成式世界模型（generative world models）」：前者著重感知合成（perceptual synthesis），後者必須滿足持續性、可控性、動力學一致性與閉環互動。此區分有助於釐清當前許多「世界模型」論文的真實定位——它們可能僅是高品質的影片生成器，而非真正的世界模型。

**限制與不足**

- **缺乏統一的基準協議**：雖然有 74 個基準，但跨基準的比較仍受限於各基準的評測協定差異；
- **指標的語義異質性**：62 個指標中，部分指標（如 FVD）僅衡量感知品質，未必反映世界建模的核心能力；
- **閉環評測的覆蓋不足**：互動式世界模型的評測通常需要昂貴的環境互動，論文中此類基準的數量與覆蓋深度未詳細披露；
- **未深入討論計算成本**：270 個模型的執行就緒度評估涉及大量運算資源，但論文未提供系統性的成本分析。

#### 可重現性評估

WorldFoundry 在可重現性（reproducibility）方面展現了極為嚴謹的設計，這也是其核心貢獻之一：

**開源基礎設施（open-source infrastructure）**

論文標題明確標示「open-source」，且系統包含完整的執行管線、模型動物園、基準動物園與視覺化工具，使第三方研究者可在本地部署並重現所有實驗。

**宣告檔系統（manifest system）**

每個模型與基準皆以宣告檔形式註冊，包含：
- **模型宣告檔（model manifests）**：IDs、任務、變體、執行環境設定檔（runtime profiles）、資產（assets）；
- **基準宣告檔（benchmark manifests）**：資料集、協定、評測器；
- **指標註冊（metric registration）**：可重用的指標定義。

此設計使「探索（discovery）」、「執行（execution）」、「評測（evaluation）」三者透過同一份宣告檔綁定，避免配置漂移（configuration drift）。

**產物契約（artifact contracts）**

每個產物皆以 `ArtifactRef` 形式持久化，包含：
- **URI**：唯一識別碼；
- **格式**：明確的資料格式；
- **中繼資料（metadata）**：產生時間、模型版本、隨機種子等；
- **雜湊值（hash）**：內容完整性驗證。

此契約確保產物在跨執行、跨環境下仍可被精確定位與驗證。

**證據感知評分卡（evidence-aware scorecard）**

評分卡不僅記錄分數，還記錄：
- **一致性（consistency）**：時間一致性、物理一致性；
- **互動性（interactivity）**：對干預的回應品質；
- **物理性（physicality）**：物理動力學的遵守程度；
- **生成品質（generation quality）**：感知合理性。

每項評測性主張皆可追溯至具體的產物與執行紀錄，這是當前世界模型研究中極為稀缺的可重現性保證。

**執行管線的可重現性**

`GenerationRequest` 包含解析後的設定（resolved config），`GenerationResult` 包含狀態、計時、錯誤，使每次執行的輸入與輸出皆可被完整重現。`WorldModelRunner` 支援一次性與會話常駐模式，後者對於閉環互動評測尤為關鍵。

**可重現性的潛在限制**

- **執行環境異質性**：不同模型可能依賴不同的 CUDA 版本、Python 版本、系統函式庫，論文中未詳細說明如何處理此類環境異質性；
- **資產管理**：模型權重、資料集資產的下載與版本控制涉及大量儲存空間，論文中未深入討論資產管理的具體機制；
- **隨機性控制**：雖然有隨機種子記錄，但分散式推論中的非確定性（non-determinism）仍是可重現性的潛在威脅。

#### 未來研究方向

基於 WorldFoundry 的設計與當前世界模型研究的缺口，可識別以下幾個值得探索的方向：

**1. 統一的物理一致性指標**

當前 62 個指標中，物理一致性（physical consistency）的測量仍依賴各基準的特定實作。發展一個**模態無關的物理一致性指標**（例如基於物理模擬器的反事實驗證）將是關鍵的下一步，使不同模態的模型可在同一物理性維度上比較。

**2. 反事實評測協定（counterfactual evaluation protocols）**

論文強調「反事實干預」是世界模型的核心能力，但現有基準多以觀察式評測為主。設計專門的**反事實評測協定**——例如「給定干預 A，預測結果；若實際結果為 B，則評估模型對 A→B 因果鏈的捕捉程度」——將有助於區分真正的世界模型與高品質影片生成器。

**3. 持續狀態的形式化驗證**

論文中「持續性是操作性的」這一定義可進一步形式化：發展**狀態可追溯性的形式化驗證方法**，例如透過資訊理論（information-theoretic）度量或因果介入分析（causal intervention analysis），量化「干預在狀態中留下的痕跡」。

**4. 跨模態遷移評測**

WorldFoundry 統一了多模態介面，但跨模態遷移（例如從影片預測遷移至 3D 重建，或從 3D 重建遷移至具身動作）尚未被系統評估。發展**跨模態遷移基準**將有助於理解不同表徵之間的互補性。

**5. 閉環互動的長期一致性**

當前閉環互動評測多聚焦於短時間窗口（數秒至數十秒）。發展**長期一致性基準**（例如數小時的環境演化、跨多個任務週期的狀態維持）將考驗世界模型的真正「持續性」。

**6. 與具身智慧（embodied intelligence）的深度整合**

論文已涵蓋具身動作生成，但與具身智慧（embodied AI）的整合仍處於早期階段。未來可探索：
- **真實機器人回饋迴路**：將 WorldFoundry 與真實機器人平台整合，使世界模型可在物理世界中驗證；
- **模擬到真實的遷移（sim-to-real transfer）**：利用世界模型作為模擬器，減少真實世界訓練資料的需求。

**7. 標準化與生態系建構**

WorldFoundry 的成功取決於社群採用。未來關鍵方向包括：
- **API 標準化**：推動 `GenerationRequest`、`ArtifactRef` 等抽象成為業界標準；
- **基準共識**：透過工作坊與共享任務（shared tasks）建立基準共識；
- **模型註冊激勵**：設計機制鼓勵模型作者提交宣告檔與執行證據。

**8. 認知架構整合**

論文的「世界智慧（world intelligence）」框架與認知科學中的世界模型理論（如 Friston 的預測編碼、Tenenbaum 的核心知識）有深層連結。未來可探索將 WorldFoundry 與**認知架構（cognitive architectures）**整合，使世界模型不僅是生成工具，更是推理與規劃的基礎。

**9. 安全與對齊考量**

隨著世界模型能力增強，其潛在濫用風險（如生成誤導性內容、模擬危險情境）也隨之上升。未來應發展**世界模型的安全評測維度**，例如對抗穩健性（adversarial robustness）、偏見檢測（bias detection）與因果對齊（causal alignment）。

**10. 效率與可及性**

270 個模型的整合涉及大量運算資源。未來應探索：
- **輕量化適配器**：降低模態特定適配器的運算開銷；
- **雲端原生架構**：使 WorldFoundry 可在雲端環境中彈性部署；
- **教育與入門工具**：降低新研究者的入門門檻，擴大社區參與。

總結而言，WorldFoundry 不僅是一個工程系統，更是一個**研究基礎設施的範式轉移**：它將世界模型研究從「各模型獨立評測」推向「統一、可追溯、可比較的科學評測」。其長期影響將取決於社群是否能圍繞此基礎設施建立共識，並持續擴展其能力維度與評測深度。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：論文指出視覺生成模型雖然能合成看似真實的觀察，但僅有視覺合理性並不等同於成功的世界建模，因為這類輸出往往缺乏持續狀態、物理動力學與因果一致性。真正的瓶頸在於不同模態（影片、3D、4D、具身動作、互動世界）的系統在表徵、執行環境、介面與評測協定上互不相容，使得能力難以組合、結果難以重現、進展難以量測。因此，問題的本質不只是演算法層次，更是基礎設施層次——需要共享基礎設施將異質模型整合到統一的函數抽象下。

**Q2：為什麼現有的世界模型研究方法與基礎設施無法有效解決這個問題？**
A：現有方法各自針對特定模態開發，影片生成器、神經場景表徵與具身策略雖然解決互補的子問題，但採用不相容的執行環境與介面，使得跨系統組合幾乎不可能。缺乏統一的函數抽象意味著異質模型無法在共享介面下被比較，導致可重現性差、跨模態評測困難。雖然 OpenWorldLib 等近期工作處理了部分整合問題，但仍未提供完整的統一基礎設施來同時支援探索、執行、產物管理與評測等環節。

**Q3：為什麼這個問題對世界智慧（World Intelligence）領域的進展至關重要？**
A：世界智慧要求系統能感知觀察、推論結構化狀態、預測其演變、表達後果並用於互動，這本質上需要跨模態的整合能力，而單一模態的優化無法達成此目標。沒有共享基礎設施，領域將停留在感知合成階段，無法邁向可量測的世界智慧，使得「進步」難以被客觀衡量。統一基礎設施是推動領域從單純合成走向真正世界建模、從封閉實驗走向可重現比較的關鍵使能器。

**Q4：WorldFoundry 提出的核心方法與架構是什麼？**
A：WorldFoundry 是一個開源基礎設施，統一了模型與基準探索、執行環境與資產準備、執行編排、產物管理與互動式視覺化等五大功能。系統透過模態特定適配器保留各系統的原生輸入、執行語義、輸出表徵與評測協定，避免強制統一造成的語意損失。整體架構分為五個層次：表層（Surface Layer）、統一推論與互動、產物契約、評測與證據、模型與基準動物園，每一層都對應特定職責並透過宣告檔綁定。

**Q5：WorldFoundry 的關鍵創新點有哪些？**
A：最重要的創新在於將「執行就緒度」與「評測性主張」分離，透過明確的宣告檔、耐用的產物契約與證據感知評分卡，使每項主張都可追溯到其支援產物，避免「聲稱優於某基準」卻無可重現證據的問題。系統對生成式世界模型提出嚴格定義：作為預測性動力系統，須具備持續狀態、可控轉換、動態感知預測與閉環互動等能力，這比純視覺合成模型有更高門檻。目前目錄已收錄 270 個模型條目、74 個基準與 62 個已註冊指標條目，並將就緒度證據與執行證據分開記錄。

**Q6：WorldFoundry 在抽象層次與設計選擇上做了哪些關鍵決定？**
A：抽象層次選擇在「函數」而非「架構」，定義狀態推論、前向模擬與互動回應三個耦合元件，使異質系統可在共享介面下組合，但不必每個系統都實作所有操作。模態特定適配器的設計承認不同模態有各自的原生語義，強行統一會造成語意損失，因此保留各系統的執行語義與輸出表徵。產物契約採用 URI、格式、元資料與雜湊等型別化參考，確保可追溯性與可重現性，這對科學研究的可信度至關重要。

**Q7：WorldFoundry 在實驗驗證中使用了哪些基準與評測面向？**
A：論文在四個主要領域進行實驗驗證：影片生成、互動式世界模型、3D 與 4D 生成、具身動作生成，覆蓋了世界建模的主要模態。系統支援 74 個基準與 62 個已註冊指標條目，評測面向涵蓋一致性、互動性、物理性與生成品質等，這些面向對應論文定義的能力進展框架。基準執行透過解析協定、資料覆蓋率、評估器與執行環境分離管理，使基準本身也可被獨立審視。

**Q8：WorldFoundry 實驗展示了哪些關鍵結果？**
A：WorldFoundry 成功展示了跨影片、3D/4D、互動世界與具身動作四大領域的可重現推論與評測，證明了統一基礎設施的可行性。證據感知評分卡將就緒度證據與執行證據分開記錄，使每項評測性主張都可追溯到具體產物，這是相對於傳統論文的重大改進。系統同時支援一次性（one-shot）與會話常駐（session-resident）兩種執行模式，適應不同應用場景，從單次生成到長期互動皆可處理。

**Q9：WorldFoundry 的設計中包含哪些消融性設計驗證？**
A：模態特定適配器的設計驗證了保留原生語義的重要性——若強制統一抽象，會造成語意損失並降低系統實用性，這透過支援異質模型的成功執行得到驗證。產物契約與宣告檔的分離展示了執行就緒度與評測性主張獨立管理的價值，使研究人員可分別審視「能否執行」與「表現如何」。系統分層架構（表層、推論互動、產物契約、評測證據、動物園）展示了模組化設計的可組合性，每層可獨立演進而不影響其他層。

**Q10：WorldFoundry 在實際應用情境中可發揮哪些作用？**
A：在跨模態世界模型研究中，WorldFoundry 可同時評估影片生成器與 4D 場景模型的物理一致性，使研究者能在統一基準下比較不同方法。互動式世界系統的開發者可利用閉環互動能力建構遊戲、模擬器與訓練環境，這些應用需要持續狀態與動作條件化回應。具身動作研究可結合影片預測與動作生成，建構更完整的機器人決策系統，這正是論文強調的「從感知合成邁向世界智慧」的具體實踐。

**Q11：WorldFoundry 在產品化與工程實踐上做了哪些考量？**
A：系統提供 TUI、CLI、工作區/工作室、Python API 與 MCP 等多種介面，適應不同開發者的工作流程，從命令列愛好者到 GUI 使用者皆可使用。產物管理支援媒體、幾何、4D、動作、軌跡與狀態追蹤等多種輸出類型，覆蓋世界建模的各種產出形式。執行支援本地檢查點與託管 API，兼顧離線研究與雲端部署需求，並透過預檢（preflight）機制在執行前驗證資源就緒度，降低失敗成本。

**Q12：WorldFoundry 對世界智慧研究領域的長期影響是什麼？**
A：WorldFoundry 將領域從感知合成推向可量測的世界智慧，提供統一的比較基準，使「進步」可被客觀衡量而非僅憑視覺印象判斷。透過可重現性基礎設施，研究成果可被獨立驗證與組合，這對科學累積至關重要——後續研究可基於先前成果繼續推進而非重複造輪。系統的開放性鼓勵社群貢獻模型、基準與指標，形成正向循環，使基礎設施本身隨領域發展而持續完善。

**Q13：WorldFoundry 承認了哪些限制？**
A：論文坦誠系統仍處於發展階段，雖然已收錄 270 個模型、74 個基準與 62 個指標，但覆蓋範圍仍非全面，新模型與新基準持續湧現需要持續整合。不同模態的原生語義保留與統一抽象之間存在張力，需要持續權衡——過度保留會削弱統一性，過度統一會損失語意。系統的可擴展性與長期維護也是挑戰，特別是當模型依賴的執行環境快速演進時，保持相容性需要持續投入。

**Q14：WorldFoundry 在哪些情況下可能無法正確評測或暴露模型的失敗？**
A：對於視覺合理性高但缺乏持續狀態的模型，系統能透過評分卡揭露其世界建模能力的不足，避免被表象迷惑。當模型無法維持跨干預的狀態一致性時，評測會反映在物理性與一致性指標上，使研究者能診斷具體缺陷。缺乏因果一致性的回應會在閉環互動評測中顯現，因為反事實干預的結果會與預期偏離，這正是純生成模型常見的失敗模式。

**Q15：WorldFoundry 未來的發展方向是什麼？**
A：未來可擴展更多模態與基準，特別是觸覺、嗅覺、聽覺等多感官整合，使世界建模更接近人類感知的多維度特性。系統可進一步整合強化學習與決策理論，強化具身智慧的評測，使世界模型能與決策系統無縫對接。長期目標是建立可量測、可比較、可組合的世界智慧基礎設施，推動 AGI 研究從概念走向可操作的工程實踐，這需要學界與業界的持續協作。

## 實務應用指南

### 適用場景

1. **機器人與具身 AI 訓練管線**：在工廠自動化、倉儲物流或服務機器人場域中，利用 WorldFoundry 的具身動作生成模組（Embodied Action Generation）建立可重現的模擬環境，將策略學習從昂貴的真機試錯轉移到雲端批次推論，並透過統一的產物契約（Artifact Contract）比對不同策略在相同基準下的成功率。

2. **自動駕駛與智慧運輸模擬**：以互動式世界系統（Interactive World System）為核心，將車輛、交通參與者與道路場景封裝為可注入干預（Intervention）的動力系統，用於閉環測試（Closed-Loop Testing）邊緣案例（corner cases），並以證據感知評分卡（Evidence-Aware Scorecard）追蹤每次回歸測試的可追溯證據。

3. **遊戲與互動娛樂資產生成**：遊戲工作室可透過 3D 與 4D 生成適配器批次產出角色、場景與時序動畫資產，並利用原生輸入（Native Input）保留各模型特有的控制語意（如骨骼綁定、攝影機軌跡），再以宣告檔（Manifest）統一管理資產版本。

4. **影視與短影音內容創作**：內容團隊可串接影片生成（Video Generation）介面，透過可控轉換（Controllable Transformation）對同一腳本生成多版本預覽，並以時間一致性軌跡（Temporally Coherent Trajectory）指標篩選符合敘事節奏的候選片段。

5. **學術研究與基準比較**：研究團隊可使用模型與基準動物園（Model and Benchmark Zoo）中的 270 個模型條目與 74 個基準，跨模態比較持續狀態建模（Persistent State Modeling）與動態感知預測（Dynamics-Aware Prediction）能力，並以就緒度證據（Readiness Evidence）與執行證據（Execution Evidence）分離「可執行」與「已評測」兩類主張。

**資料面**

- 容器化環境（Docker / Apptainer）以確保執行環境（Runtime）一致性。

**技能面**
- 熟悉 Python 程式設計與命令列工具操作，能透過 TUI/CLI 或 Python API 串接系統。
- 具備深度學習基礎（PyTorch、擴散模型、NeRF / Gaussian Splatting 等概念）。
- 理解生成式模型的輸入輸出語意與評測指標（如 FVD、PSNR、LPIPS、成功率等），以便正確解讀評分卡。

### 實作步驟建議

1. **釐清目標並選用模態**：先定義要解決的問題屬於影片生成、3D/4D 生成、具身動作還是互動式世界系統，據此挑選對應的模態特定適配器（Modality-Specific Adapter）。

2. **盤點模型與基準**：透過模型與基準動物園探索可用條目，閱讀模型宣告檔（Model Manifest）中的任務、變體與執行環境設定，並比對基準的覆蓋率與評測器是否符合需求。

3. **建立工作區與資產準備**：使用 Workspace / Studio 或 Python API 建立專案工作區，執行 Resolve & Preflight 流程，確認模型權重、執行環境與資產皆已就位，並區分執行就緒度（Execution Readiness）與評測性主張（Evaluative Claim）。

4. **撰寫生成請求與執行推論**：以 `GenerationRequest` 描述身份、輸入、控制項、原生參數與輸出綱要（Output Schema），透過 `WorldModelRunner` 採一次性（One-shot）或常駐會話（Session-Resident）模式執行；互動式任務可使用 Operator 與 Pipeline 進行閉環互動。

5. **管理產物與可追溯性**：將輸出統一封裝為 `ArtifactRef`（URI、格式、中繼資料、雜湊值），並透過產物契約持久化媒體、幾何、4D、動作、軌跡與狀態追蹤等資料，便於後續重現與稽核。

6. **執行基準評測**：呼叫基準執行器（Benchmark Runner），由評測器進行逐樣本彙總並寫入持久化結果，必要時註冊自訂指標（Registered Metric Entry）。

7. **解讀證據感知評分卡**：依一致性（Consistency）、互動性（Interactivity）、物理性（Physicality）與生成品質（Generation Quality）四個面向檢視結果，確認每項主張皆可追溯到對應產物。

8. **迭代與部署**：根據評分卡調整控制項或換用模型，重複步驟 4–7；通過驗證後，將工作區封裝為可重現的執行計畫（Run Contract），部署至正式環境。

### 潛在風險與注意事項

- **執行就緒 ≠ 評測通過**：模型可能已通過預檢（Preflight）但尚未產生評測證據，避免將「可執行」誤判為「效能達標」；應以證據感知評分卡為唯一依據。

- **原生語意流失**：不同模型的原生輸入與執行語意（Execution Semantics）差異大，若強行以統一介面抽象，可能損失細粒度控制；建議優先使用模態特定適配器，而非自行改寫介面。

- **產物膨脹與儲存成本**：影片與 4D 產物體積龐大，長期累積可能造成儲存與雜湊驗證成本上升；應建立產物生命週期管理與定期清理機制。

- **基準覆蓋率偏差**：基準的資料覆蓋率與評測器設定會直接影響結論，建議在解讀結果時同時檢視基準宣告檔，避免在未覆蓋的子任務上過度推論。

- **閉環互動的狀態漂移**：在互動式世界系統中，狀態推論若未正確吸收觀察回饋，可能產生持續狀態（Persistent State）漂移；應監控狀態追蹤（State Trace）並設置異常中斷條件。

- **API 與權重版本綁定**：託管 API 與本地檢查點的版本變動可能導致結果不可重現，建議在宣告檔中明確鎖定版本與雜湊值。

### 與其他技術的整合建議

- **與 MLOps / LLMOps 平台整合**：可將 WorldFoundry 的執行計畫（Run Contract）對接至 Kubeflow、Airflow 或 Vertex AI 等編排系統，將生成與評測納入既有 CI/CD 管線。

- **與資料湖與特徵儲存整合**：將 `ArtifactRef` 寫入物件儲存（如 S3、MinIO）並在特徵儲存（Feature Store）登錄中繼資料，方便下游訓練與分析任務直接消費。

- **與數位孿生（Digital Twin）平台整合**：以互動式世界系統作為數位孿生的動力核心，透過 MCP（Model Context Protocol）或 Python API 與 IoT 感測器串接，實現即時狀態同步。

- **與遊戲引擎整合**：透過 3D/4D 適配器將產出導入 Unity 或 Unreal Engine，使用原生幾何與動畫格式保留細節，並以宣告檔管理資產版本。

- **與評測與監控工具整合**：將證據感知評分卡匯出至 Grafana、Weights & Biases 或 MLflow，建立跨團隊的可追溯儀表板。

- **與 OpenWorldLib 等互補基礎設施協作**：WorldFoundry 專注於推論與評測的統一介面，可與其他開源函式庫在模型註冊、資產共享層面互補，避免重複造輪。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 3 節「統一的世界建模定義」，理解「狀態推論—前向模擬—互動回應」三個功能元件的意涵，再瀏覽第 4.1 節的系統總覽圖，建立 WorldFoundry 由表層、推論層、產物契約、評測層與動物園五個層級組成的心智模型；附錄 B、C、D 的支援清單可作為日後查詢的速查表。

**給 AI 工程師**：重點放在第 4.2–4.5 節，理解 `GenerationRequest`、`WorldModelRunner`、`ArtifactRef` 與評測執行器的資料流；建議直接安裝 WorldFoundry 並以 Python API 跑通一個影片生成範例，再逐步替換為 3D 或具身動作任務，以掌握模態特定適配器的差異。

**給研究者**：第 3.2 節的能力進展（Capability Progression）與第 3.3 節的分類法（Taxonomy）是建立研究定位的關鍵；第 5 節的實驗結果提供了跨模態比較的基準參考，建議以此為起點設計新指標並註冊至系統，以利後續跨論文比較。

**給產品經理**：聚焦於第 1 節的問題陳述、第 4.6 節的目錄規模（270 模型、74 基準、62 指標），以及第 6 節的限制與未來工作；理解「執行就緒」與「評測性主張」的分離，有助於在規劃產品時區分「技術可行性」與「效能驗證」兩個不同階段的決策點。
