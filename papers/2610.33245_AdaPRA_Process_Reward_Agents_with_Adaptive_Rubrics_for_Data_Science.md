## 深度分析

#### 方法論解析

AdaPRA 的方法論設計圍繞著解決資料科學代理 (Data Science Agents) 在自動化端到端機器學習工作流程 (End-to-End Machine Learning Workflow) 時所面臨的過程錯誤 (Process Errors) 問題。其核心架構由四個相互協作的元件組成，共同構成一個能夠跨嘗試累積知識並進行動態監督的系統。

**第一元件：持久化代理框架 (Persistent Harness)**

傳統的代理框架 (Agent Harness) 如 DSGym 在每次嘗試時都從零開始，這導致重複的探索性資料分析 (Exploratory Data Analysis, EDA)、基線模型 (Baseline Models) 訓練，以及對已知失敗策略的反覆嘗試，造成計算預算 (Budget) 的嚴重浪費。AdaPRA 的持久化框架打破了這一限制，將代理的工作區 (Workspace) 在同一任務的多重嘗試 (Repeated Attempts) 之間保留下來。這意味著前一次嘗試所產生的探索性洞察、訓練好的模型、已驗證的特徵工程策略都會被後續嘗試所繼承。從概念上來看，這種設計將檔案系統本身視為代理的長期記憶 (類似於 Xu et al., 2025 與 Zhou et al., 2026 所提出的「檔案即記憶」理念)，使代理能夠專注於新實驗而非重複勞動。

**第二元件：過程獎勵代理 (Process Reward Agent, PRA)**

PRA 是 AdaPRA 區別於傳統過程獎勵模型 (Process Reward Model, PRM) 的關鍵創新。傳統 PRM（如 Lightman et al., 2024）僅對軌跡 (Trajectory) 中的中間步驟進行評分，而 AdaPRA 的 PRA 則具備主動稽核 (Audit) 能力，能夠執行程式碼 (Code Execution)、檢查工作區產物，並透過工具調用來獲取證據。這種「主動驗證」設計直接回應了論文中 Figure 1 所揭示的關鍵問題：靜默錯誤 (Silent Errors) 不會在軌跡中留下任何痕跡。例如，當代理因錯誤的檔案路徑導致所有測試音檔 (Test Clips) 被載入為靜音音訊時，軌跡上看起來完全正常，但 PRA 透過執行「提交完整性 (Submission Integrity)」評分規準 (Rubric) 下的檢查，能夠識別出所有預測機率 (Predicted Probabilities) 完全相同的事實，從而定位錯誤根源。

PRA 的運作採用固定節奏 (Cadence) 的審查機制，類似於 Gandhi et al. (2026) 的做法，但更為精緻的是：PRA 只回報相關且失敗的評分規準，避免在代理的上下文視窗 (Context Window) 中灌入大量無關資訊。此外，面對長達數百輪的代理軌跡與龐大的工作區，PRA 採用按需上下文擷取 (On-Demand Context Pulling) 策略，而非將所有資訊塞入上下文。

**第三元件：種子評分規準自動發現 (Seed Rubric Discovery)**

AdaPRA 從過去代理執行的軌跡與工作區產物中自動挖掘評分規準，擴展了 Zhang et al. (2026b) 的方法。具體而言，該程序透過對比整個代理嘗試（包括其軌跡和工作區產物）來發現評分規準，而不僅僅依賴回應或軌跡本身。這種設計的優勢在於：許多錯誤僅在工作區產物中可見（例如，訓練好的模型存在但從未被用於預測），單純分析軌跡無法捕捉。

**第四元件：任務特定評分規準適應 (Task-Specific Rubric Adaptation)**

由於每個任務都有其獨特的陷阱，通用評分規準無法預見所有問題。AdaPRA 在嘗試過程中動態調整評分規準，類似於 RubricEM (Li et al., 2026) 與 Shao et al. (2025) 的思路，但應用場景不同：AdaPRA 在監督代理執行任務時即時適應評分規準，而非用於塑造訓練獎勵。透過任務特定的儲存機制，PRA 將通用評分規準無法涵蓋的陷阱轉化為明確的評分標準，供後續審查使用。

值得注意的是，AdaPRA 的評分規準適應不需要黃金回饋 (Gold Feedback) 如 Kaggle 分數，這使得該方法在缺乏即時真實標籤的場景下仍可運作。

#### 實驗數據解讀

**主要效能提升**

實驗結果顯示，AdaPRA 將 80B Qwen3-Coder-Next 代理在 Kaggle 排行榜百分位 (Leaderboard Percentile) 上的表現顯著提升：
- DSPredict-Easy：提升 24.5 點
- DSPredict-Hard：提升 14.8 點

這些任務橫跨視覺、文本、語音和分子預測等多個領域，證明了 AdaPRA 的跨領域泛化能力。特別值得注意的是，這些結果「匹配或超越」了配備高推理能力的 GPT-5.1，這對於一個 80B 規模的開源模型而言是相當顯著的成就。

**評分規準遷移性實驗**

論文中兩個關鍵的遷移性發現值得深入解讀：

1. **從簡單任務到困難任務的遷移**：在較容易任務上發現的評分規準能夠泛化到較困難的任務。這暗示了資料科學任務中的錯誤模式存在跨難度層級的共通性，可能反映了人類資料科學家在處理不同複雜度問題時所面臨的相似認知陷阱。

2. **跨基礎模型的遷移**：從一個基礎模型（如 Qwen）的執行中挖掘出的評分規準，能夠改善另一個基礎模型（DeepSeek-V3.2）的表現。這表明評分規準捕捉的是任務本身的結構性特徵，而非特定模型的行為模式，這對於評分規準作為通用監督工具的潛力提供了有力證據。

**消融實驗 (Ablation Studies)**

論文指出持久化框架、程式碼執行和評分規準適應各自對效能提升都有貢獻。雖然具體數字未在提供的文本中給出，但這三個元件的獨立貢獻驗證了 AdaPRA 設計中每個元件的必要性。

**與 DataPRM 的比較**

AdaPRA 擊敗了 DataPRM（一個專為資料科學設計的競爭性 PRM）。這個比較的意義在於：DataPRM 作為靜態評分規準集的 PRM，其表現不如具備動態適應能力和主動驗證能力的 AdaPRA，這凸顯了「主動稽核」相對於「被動評分」的優勢。

**過程錯誤減少**

除了最終效能提升外，AdaPRA 還減少了過程錯誤的發生頻率。這是一個重要的次要指標，因為它直接證明了過程監督 (Process Supervision) 的有效性——不僅是結果更好，過程也更為健全。

#### 與現有研究的比較

**與 ML 工程代理的比較**

AdaPRA 與 AIDE (Jiang et al., 2025) 和 ML-Master (Liu et al., 2025) 等 ML 工程代理採取了不同的設計哲學。這些系統使用外部支架 (Scaffold) 來維護候選解方案樹，並在每一步為模型提供精選的簡短上下文。相較之下，AdaPRA 將搜尋決策權交給程式碼代理 (Coding Agent) 本身，僅透過持久化框架保留工作區，讓代理決定要重複使用哪些資源。論文指出這兩種設計可以互補——未來可以將外部支架運行在持久化代理之上，形成更強大的組合。

**與評分規準適應相關研究的比較**

在評分規準適應領域，先前工作如 RubricEM (Li et al., 2026) 透過元強化學習 (Meta-RL) 訓練迴圈在演化緩衝區中新增和修剪評分標準；Shao et al. (2025) 在訓練過程中演化評分規準以緩解獎勵破解 (Reward Hacking)。這些工作的共同特徵是：將評分規準用於塑造訓練獎勵，並使用沒有工具或程式碼執行能力的標準 LLM 評判器 (LLM Judge) 來套用。AdaPRA 的差異化在於：它在監督代理執行任務的過程中即時適應評分規準，且 PRA 配備工具和程式碼執行能力，能進行更紮實的驗證。

**與過程獎勵代理相關研究的比較**

過程獎勵代理 (Process Reward Agents, PRAs) 已在多個領域得到探索：數學（Zhang et al., 2026a）、軟體工程（Raghavendra et al., 2026）、GUI（Xiong et al., 2025）、醫療推理（Sohn et al., 2026）、資料分析（Qiu et al., 2026）和通用獎勵建模（Peng et al., 2025）。雖然程式碼執行使驗證更加紮實，但現有 PRA 依賴靜態評分規準集。AdaPRA 的獨特之處在於：它同時稽核長時運行代理的軌跡和工作區，並將評分規準適應到每個任務。

**與評分規準發現相關研究的比較**

RubricEM 透過跨訓練回合的策略分解發現評分規準；Zhang et al. (2026b) 透過對比同一提示的兩個最高分候選回應來細化每提示的評分規準，用於 RL 後訓練。兩者都僅從回應或軌跡衍生評分規準，而 AdaPRA 還挖掘每次嘗試遺留的工作區產物，這是一個重要的方法論擴展。

**局限性分析**

儘管 AdaPRA 取得了顯著成果，仍存在若干局限性：

1. **對 PRA 模型品質的依賴**：AdaPRA 使用 Claude Sonnet-4.6 作為 PRA，這意味著系統效能部分取決於監督模型的品質。對於無法使用頂級閉源模型的場景，效能可能會下降。

2. **計算開銷**：持久化框架和持續的 PRA 審查會增加計算成本。雖然論文聲稱減少了過程錯誤，但未明確量化額外的監督成本是否被最終效能提升所抵消。

3. **評分規準品質的保證**：自動發現的評分規準可能包含噪聲或冗餘項目。雖然適應機制可以部分緩解，但缺乏對評分規準品質的系統性驗證。

4. **任務範圍**：雖然實驗涵蓋了多個領域，但所有任務都來自 Kaggle 風格的競賽。真實世界的企業資料科學問題可能涉及更多約束（如資料隱私、部署限制），AdaPRA 在這些場景下的表現尚待驗證。

#### 可重現性評估

**程式碼可用性**

論文明確聲明「我們也分享我們的程式碼以供可重現性 (Reproducibility)」，這是值得肯定的承諾。然而，僅憑這一聲明，我們無法評估程式碼的完整性、文件品質以及依賴項的明確性。理想情況下，可重現性評估應包括：

實驗使用的 DSPredict-Easy 和 DSPredict-Hard 基準測試是基於 DSGym (Nie et al., 2026) 的，這暗示了底層資料集應該是可訪問的。然而，論文中未明確說明是否提供了用於評分規準發現的「過去代理執行」的資料。

**模型權重可用性**

AdaPRA 使用的核心代理是 80B Qwen3-Coder-Next，這是一個開源模型，權重可從官方渠道獲取。PRA 使用的是 Claude Sonnet-4.6，這是一個閉源模型，使用者需要透過 API 訪問，這對完全可重現性構成了一定限制。

**整體可重現性評估**

考慮到程式碼共享的承諾、使用開源基礎模型、以及基於既有基準測試的實驗設計，AdaPRA 的可重現性處於中等偏上水準。主要的不確定性在於：閉源 PRA 模型的使用、評分規準發現程序的具體細節，以及完整的實驗配置。

## 論文問答

**Q1：AdaPRA 主要解決什麼問題？為何現有的資料科學代理在排行榜上表現不佳？**
A：AdaPRA 主要解決資料科學代理在端到端機器學習工作流程中表現遠遜於人類排行榜的問題。根據論文，現有代理（如 DSGym 中的代理）會犯下多種過程錯誤，包括簡單性偏誤（停在第一個有效流程管線而非探索更強的模型）、不健全的驗證、訓練目標不匹配以及驗證集洩漏等。這些錯誤往往「靜默」發生——流程管線仍會產生有效提交，但軌跡中完全沒有錯誤跡象，導致傳統只看軌跡的 LLM 評判器無法察覺。此外，現有框架每次嘗試都從零開始，重複執行相同的探索性資料分析 (EDA) 與基線模型，浪費了寶貴的計算預算。

**Q2：什麼是「過程錯誤」，為何它對資料科學代理特別具有挑戰性？**
A：過程錯誤指的是代理在中間步驟所犯下的錯誤，這些錯誤會累積並導致最終結果變差，但不一定會在最終提交中顯現出來。論文中以圖 1 為例：代理因為錯誤的檔案路徑，導致每個測試音檔都被載入為靜音音訊，因此所有 158,538 個測試樣本都被預測為「unknown」指令類別，但代理的軌跡卻完全沒有顯示任何錯誤。這類靜默錯誤對資料科學代理特別具有挑戰性，因為它們需要結合程式碼執行、軌跡分析與工作區稽核才能被偵測，單純的文字檢視無法發現。此外，證據分散在數百個對話輪次以及包含程式碼、模型與資料的工作區中，遠超過 LLM 的上下文視窗容量。

**Q3：為何縮小代理與人類排行榜之間的差距如此重要？**
A：縮小這個差距代表著自動化機器學習工作流程從「能跑」邁向「能贏」的重要進展，對於實際部署具有深遠意義。當代理能夠可靠地完成資料科學任務時，可以大幅降低企業與研究機構在重複性 ML 工程上的人力成本，讓資料科學家專注於更具創造性的問題。此外，論文中 AdaPRA 將 80B Qwen 模型的排行榜百分位提升 24.5 點（DSPredict-Easy）與 14.8 點（DSPredict-Hard），且表現匹配或超越 GPT-5.1 高推理版本，證明了開源模型搭配良好監督機制也能達到頂尖效能，這對 AI 民主化具有重要意義。

**Q4：AdaPRA 的四個核心元件是什麼？它們如何協同運作？**
A：AdaPRA 由四個核心元件組成：持久化代理框架 (Persistent Harness)、過程獎勵代理 (PRA)、自動種子評分規準發現 (Seed Rubric Discovery) 以及任務特定評分規準適應 (Task-Specific Rubric Adaptation)。持久化框架會保留代理的工作區，讓前一次嘗試的探索性發現、訓練好的模型與失敗策略都能延續到下一次嘗試，避免重複浪費預算。PRA 在每次嘗試過程中以固定節奏稽核代理的軌跡與工作區，透過執行程式碼與工具來檢查評分規準，並只回報相關且失敗的規準以避免淹沒代理的上下文。種子評分規準從過去代理的軌跡與工作區產物中挖掘，並透過任務特定適應機制隨著嘗試進行而調整，以涵蓋通用規準無法預見的任務陷阱。

**Q5：過程獎勵代理 (PRA) 與傳統過程獎勵模型 (PRM) 有何根本差異？**
A：PRA 與傳統 PRM 的根本差異在於「主動驗證」與「被動評分」之間的對比。傳統 PRM（如 Lightman et al., 2024）僅對中間步驟進行評分，而 PRA 則會執行程式碼、擷取證據或探索工作區來主動驗證後再評判，這在數學、軟體工程、GUI、醫學推理與資料分析等領域都已展現優勢。更關鍵的是，AdaPRA 的 PRA 不僅稽核軌跡，還稽核工作區中的程式碼、輸出與追蹤記錄，這對於偵測靜默錯誤至關重要。此外，AdaPRA 的 PRA 採用按需上下文擷取策略，解決了證據分散在數百個對話輪次與龐大工作區、無法全部塞入上下文視窗的問題。

**Q6：評分規準適應機制如何運作？為何它對效能提升至關重要？**
A：評分規準適應機制讓 PRA 能夠隨著任務進行而新增、修剪或修改評分規準，將通用規準無法涵蓋的任務特定陷阱轉化為明確的評判標準。論文中提到，這個機制借鑑了 RubricEM (Li et al., 2026) 與 Shao et al. (2025) 的思路，但關鍵差異在於 AdaPRA 在監督代理時即時適應規準，而非僅用於形塑訓練獎勵。這個機制至關重要，因為每個任務都有其獨特的陷阱（例如特定資料集的格式問題、特定領域的驗證方式），通用評分規準無法預見這些問題。論文的消融實驗明確顯示，評分規準適應是效能提升的重要貢獻者之一。

**Q7：AdaPRA 使用了哪些基準測試？主要的實驗結果為何？**
A：AdaPRA 主要在 DSGym 基準測試的兩個子集上進行評估：DSPredict-Easy 與 DSPredict-Hard，涵蓋視覺、文字、語音與分子預測等多種任務類型。實驗結果顯示，使用 Claude Sonnet-4.6 作為 PRA，將 80B Qwen3-Coder-Next 代理的 Kaggle 平均百分位在 DSPredict-Easy 上提升 24.5 點，在 DSPredict-Hard 上提升 14.8 點。更令人矚目的是，這些結果匹配或超越 GPT-5.1 高推理版本在所有指標上的表現，證明了良好設計的監督機制可以讓較小的開源模型達到頂尖效能。此外，AdaPRA 也擊敗了資料科學領域的競爭對手 DataPRM，展現了其方法論的優勢。

**Q8：消融實驗揭示了各元件的哪些貢獻？**
A：論文的消融實驗明確指出持久化框架、程式碼執行與評分規準適應各自都對效能提升有所貢獻。持久化框架透過保留工作區讓探索性發現、訓練好的模型與失敗策略得以延續，使每次嘗試能將固定預算用於新實驗而非重複勞動。程式碼執行讓 PRA 能夠主動驗證而非僅依賴文字軌跡，這對於偵測像「所有預測都是 unknown」這類靜默錯誤至關重要。評分規準適應則讓 PRA 能夠針對每個任務的特定陷阱調整評判標準，避免通用規準的盲點。這三個元件缺一不可，共同構成了 AdaPRA 的效能基礎。

**Q9：評分規準在不同任務與模型之間的遷移性如何？**
A：論文中展示了兩個重要的遷移性發現。首先，從較容易任務挖掘出的評分規準能夠遷移到較困難的任務，這是因為許多過程錯誤（如簡單性偏誤、不健全驗證）在不同難度的任務中具有共通性。其次，從一個基礎模型（Qwen）的執行中挖掘出的評分規準，能夠改善另一個基礎模型（DeepSeek-V3.2）的表現，這顯示評分規準捕捉的是任務與錯誤模式，而非模型特定行為。這些發現具有重要的實務意涵：組織可以從現有的代理執行歷史中挖掘評分規準，並將其應用於新任務或新模型，無需從頭開始建立監督機制。

**Q10：AdaPRA 在哪些實際場景中能發揮最大價值？**
A：AdaPRA 在需要高度可靠性且錯誤成本高昂的資料科學場景中價值最大，例如金融風險建模、醫療診斷輔助、藥物研發等領域。在這些場景中，靜默錯誤（如驗證集洩漏、訓練目標不匹配）可能導致嚴重的商業或臨床後果，而 AdaPRA 的工作區稽核能力能夠有效攔截這類問題。此外，對於計算預算有限的中小型企業或研究團隊，AdaPRA 的持久化框架能避免重複的 EDA 與基線模型訓練，讓寶貴的計算資源用於真正的新實驗。最後，對於使用開源模型（如 Qwen、DeepSeek）的組織，AdaPRA 證明了無需依賴最昂貴的閉源模型也能達到頂尖效能，大幅降低了部署成本。

**Q11：將 AdaPRA 部署到實際產品中需要考量哪些工程因素？**
A：部署 AdaPRA 需要考量多項工程因素。首先是 PRA 的運算成本：由於 PRA 需要在每次嘗試中以固定節奏執行程式碼與稽核工作區，這會增加額外的 LLM 推理與程式碼執行開銷，需要評估整體的延遲與成本影響。其次是工作區管理：持久化框架需要可靠的儲存與版本控制機制，以避免不同任務或嘗試之間的工作區混淆，並支援除錯時的狀態回溯。第三是評分規準的生命週期管理：種子評分規準需要定期從新的代理執行中重新挖掘與更新，以適應不斷演進的錯誤模式。最後是與現有 MLOps 流程的整合，包括 CI/CD、模型註冊表與監控儀表板的銜接。

**Q12：AdaPRA 對資料科學代理領域的更廣泛影響是什麼？**
A：AdaPRA 對資料科學代理領域的影響超越了單純的效能提升，它重新定義了「監督」在長時程代理中的角色。傳統上，代理監督依賴於最終結果的獎勵信號，而 AdaPRA 證明了透過評分規準驅動的過程監督，即使沒有 Kaggle 分數等黃金回饋，也能引導代理避開常見陷阱。這種「無需標籤的監督」範式對於現實世界部署至關重要，因為真實任務往往缺乏即時的正確性回饋。此外，AdaPRA 展示了開源模型搭配良好監督機制可以達到甚至超越頂尖閉源模型，這對 AI 領域的開源生態系具有積極意義，也為其他領域（如科學發現、軟體工程）的代理設計提供了可借鏡的範本。

**Q13：AdaPRA 有哪些已承認的限制？**
A：論文中承認了幾項重要限制。首先，AdaPRA 的效能高度依賴 PRA 本身的品質——論文中使用 Claude Sonnet-4.6 作為 PRA，這代表部署成本與供應商鎖定是實際考量。其次，評分規準的品質受限於挖掘過程中所使用的過去代理執行歷史的品質與多樣性，若歷史資料不足或偏頗，挖掘出的規準可能不夠全面。第三，AdaPRA 主要在 DSGym 基準上驗證，對於真實世界企業資料科學任務的泛化能力仍需更多實證。最後，論文中提到 PRA 採用按需上下文擷取策略，但對於極大規模工作區或極長對話的處理效率仍是開放問題。

**Q14：AdaPRA 在哪些失敗案例或邊緣情況下仍會遇到困難？**
A：AdaPRA 在幾種邊緣情況下仍可能遇到困難。對於需要高度領域專業知識的任務（如特定科學領域的特徵工程），通用評分規準可能無法捕捉領域特定的陷阱，即使經過任務特定適應也難以完全覆蓋。對於極度非結構化或雜訊極多的資料，PRA 的程式碼檢查可能難以區分「合理的探索」與「真正的錯誤」。此外，當代理的錯誤模式與過去挖掘出的規準完全不同（例如新型的程式碼漏洞或新型的資料洩漏模式）時，AdaPRA 可能無法及時偵測。最後，對於需要極長推理鏈或極多輪互動的複雜任務，固定節奏的稽核可能錯過某些關鍵的錯誤發生時點。

**Q15：基於 AdaPRA 的未來研究方向有哪些？**
A：基於 AdaPRA 的未來研究方向相當豐富。首先，可以將 AdaPRA 與外部候選解管理框架（如 AIDE 的解樹管理）結合，讓持久化代理框架同時擁有結構化的解空間管理，這在論文的相關工作章節已被提及為可能的延伸。其次，可以探索將評分規準適應機制擴展到跨任務的遷移學習，讓從一個領域學到的規準能夠自動調整以適應新領域。第三，可以研究如何讓 PRA 從被動稽核進化為主動建議，主動提出實驗設計或特徵工程的方向，而不僅僅是指出錯誤。第四，可以將 AdaPRA 的過程監督範式應用於其他長時程代理任務，如科學發現、軟體工程與自動化研究。最後，可以探索如何降低 PRA 的運算成本，例如透過蒸餾或規則化方法，讓監督機制更加輕量且易於部署。

## 實務應用指南

### 適用場景

**1. 自動化 Kaggle 風格競賽參與**
企業或研究團隊若需在固定預算下反覆嘗試 ML 競賽任務（例如預測、分類、迴歸），AdaPRA 的持久化框架可保留前幾次嘗試的 EDA 結果、訓練過的模型與失敗策略，避免每次從零開始。過程獎勵代理（PRA）能在中途攔截如「提交完整性」這類靜默錯誤（例如預測檔案路徑錯誤導致所有樣本被標為同一類），及時修正而非等到最終提交才發現。

**2. 企業內部 ML 流程自動化**
金融、零售、醫療等產業常需對結構化資料反覆建立預測模型。AdaPRA 可作為內部 AutoML 系統的監督層，針對資料洩漏（leaked validation sets）、訓練目標不匹配、驗證方式不健全等過程錯誤進行稽核，並將任務特定的陷阱（例如某欄位在測試集才出現）轉化為明確的評分規準，供後續嘗試複用。

**3. 多模態資料科學任務**
DSPredict-Hard 涵蓋視覺、文字、語音、分子預測等異質任務。對於需要處理音檔分類、影像辨識或文字分析的團隊，AdaPRA 的程式碼執行檢查能驗證資料載入是否正確（例如音檔是否真的被讀入而非靜音），這類錯誤在軌跡中完全無跡可循。

**4. 長時程資料分析專案**
當資料科學家需在數天或數週內反覆迭代同一分析任務（例如 A/B 測試分析、用戶行為分群），持久化框架可作為「專案記憶」，PRA 則在每次嘗試中以固定節奏審查進度，避免簡單性偏誤（停在第一個通過的流程而不再探索更強模型）。

**5. 跨模型遷移的監督訊號生產**
若組織同時使用多個基礎模型（例如 Qwen、DeepSeek-V3.2），可從一個模型的嘗試中挖掘評分規準，再遷移至監督另一個模型。論文已證明這種遷移有效，適合需要標準化品質管控的多模型環境。

### 實作前置條件

**資料需求**
- **歷史代理執行紀錄**：需蒐集過去代理在類似任務上的完整軌跡（程式碼、輸出、錯誤訊息）與工作區產物（產生的檔案、模型權重、EDA 圖表），用於種子評分規準的挖掘。建議至少累積數十個任務的紀錄。
- **任務描述與評估指標**：每個任務需有明確的輸入資料描述、提交格式規範與評分函式（模擬 Kaggle 排行榜）。
- **工作區快照機制**：需能保存每次嘗試後的完整檔案系統狀態，以便下次嘗試接續。

**運算資源**
- **基礎代理 LLM**：80B 規模的程式碼模型（如 Qwen3-Coder-Next）作為執行代理，需具備多輪工具呼叫與長上下文能力。
- **PRA 模型**：建議使用具備強推理能力的模型（如 Claude Sonnet-4.6 或同級），需支援工具呼叫與程式碼執行。
- **程式碼執行沙箱**：隔離環境以安全執行代理與 PRA 的檢查腳本，建議使用容器化方案（Docker、Firecracker）或 Jupyter Kernel。
- **預算分配**：每任務 5 次嘗試，每次嘗試中 PRA 以固定節奏審查，需預估 LLM API 成本與執行時間。

**技能前提**
- **ML 工程能力**：理解端到端 ML 工作流程（資料前處理、特徵工程、模型選擇、驗證策略）。
- **代理編排經驗**：熟悉工具呼叫代理的設計模式、軌跡記錄、上下文管理。
- **提示工程**：能設計評分規準的結構化表示與 PRA 的審查提示。
- **基礎設施維運**：能部署並監控沙箱環境、處理資源隔離與清理。

### 實作步驟建議

**步驟一：建立持久化代理框架**
取代傳統每次從零開始的 DSGym 式框架，設計一個跨嘗試保留工作區的執行環境。實作要點：
- 為每個任務分配獨立的工作目錄，跨嘗試持久化。
- 提供代理讀寫既有檔案的工具，使 EDA 結果、訓練過的模型、失敗策略可被後續嘗試讀取。
- 設定固定的嘗試次數上限（論文使用 5 次）與單次預算上限。

**步驟二：實作過程獎勵代理（PRA）**
PRA 是 AdaPRA 的核心監督者，需具備：
- **軌跡與工作區稽核能力**：能讀取代理的動作歷史並執行檔案系統操作。
- **程式碼執行工具**：能撰寫並執行檢查腳本（例如驗證預測檔案的預測機率分佈、檢查資料路徑是否存在）。
- **按需上下文擷取**：面對數百輪的長軌跡與龐大工作區，PRA 不應一次載入全部內容，而應根據當前評分規準動態拉取相關證據。
- **節奏化審查**：在嘗試進行中以固定節奏介入，而非僅在結束後回顧。

**步驟三：挖掘種子評分規準**
從歷史代理執行紀錄中自動發現常見錯誤模式：
- 對比高分與低分嘗試的軌跡差異，識別導致失敗的關鍵步驟。
- 檢查工作區產物（例如預測檔案、模型檔案），找出軌跡中未顯現的問題。
- 將發現的錯誤模式抽象為可重用的評分規準條目（例如「提交完整性：預測檔案應包含所有測試樣本且預測機率分佈合理」）。
- 論文證明從較易任務挖掘的評分規準可遷移至較難任務，可採取由易到難的漸進式挖掘策略。

**步驟四：實作任務特定評分規準適應**
每個任務進行中，PRA 應動態調整評分規準：
- 當發現新的任務特定陷阱（例如某欄位在測試集才出現），將其加入該任務的評分規準庫。
- 當某條規準反覆通過且不再提供訊息時，可將其標記為低優先級，避免淹沒代理的上下文。
- 維護每個任務獨立的評分規準儲存區，使後續嘗試能複用先前發現的陷阱。

**步驟五：整合與評估**
- 將 AdaPRA 接入現有的代理執行管線，確保 PRA 的介入不會過度干擾代理的自主探索。
- 在 DSPredict-Easy 與 DSPredict-Hard 等基準上驗證效能，目標是顯著提升排行榜百分位（論文報告 Easy +24.5、Hard +14.8）。
- 進行消融實驗，分別驗證持久化框架、程式碼執行、評分規準適應三者的貢獻。

### 潛在風險與注意事項

**風險一：評分規準品質高度依賴種子資料**
若歷史代理執行紀錄不足或品質不佳，挖掘出的種子評分規準可能遺漏關鍵錯誤模式或包含過多雜訊。**緩解措施**：採用由易到難的漸進式挖掘，先在已知錯誤類型豐富的任務上建立基準，再逐步擴展；定期由人工審查挖掘出的規準品質。

**風險二：PRA 介入過於頻繁或過於稀少**
節奏化審查的頻率若過高，會打斷代理的探索並消耗大量 LLM 預算；若過低，則無法及時攔截靜默錯誤。**緩解措施**：根據任務複雜度動態調整審查節奏；監控 PRA 報告的違規數量與代理最終表現的相關性，作為節奏調校的依據。

**風險三：程式碼執行沙箱的安全性與穩定性**
PRA 需執行代理產生的程式碼以進行檢查，這帶來資安風險與環境污染風險。**緩解措施**：使用強隔離的容器或微虛擬機；限制網路存取與檔案系統權限；設定執行逾時與資源配額；定期重置沙箱。

**風險四：上下文視窗管理不當**
PRA 在審查時若一次載入過多軌跡與工作區內容，會超出上下文限制或稀釋關鍵證據。**緩解措施**：實作嚴謹的按需擷取機制，僅載入與當前評分規準相關的程式碼片段、檔案摘要與錯誤訊息；使用檔案系統作為長期記憶而非全部塞入上下文。

**風險五：評分規準過度擬合特定任務**
任務特定的評分規準若過於細瑣，可能無法遷移至新任務，且會增加維護成本。**緩解措施**：區分通用規準（如「提交完整性」）與任務特定規準（如「本任務的音檔路徑格式」）；定期清理僅出現一次的細項。

**風險六：成本與延遲**
每任務 5 次嘗試加上 PRA 的反覆介入，會顯著增加 LLM API 成本與整體執行時間。**緩解措施**：監控每次嘗試的成本與時間；對簡單任務減少嘗試次數；考慮使用較小的 PRA 模型處理例行檢查，僅在複雜判斷時升級至旗艦模型。

### 與其他技術的整合建議

**與 ML 平台整合**
AdaPRA 可作為 MLflow、Kubeflow 或 Vertex AI 等平台的監督層外掛。在每次代理嘗試結束後，將工作區快照、評分規準違規報告、最終提交結果記錄至平台的實驗追蹤系統，便於後續分析與審計。

**與代理框架整合**
對於已使用 LangChain、AutoGen 或 CrewAI 等框架的團隊，可將 AdaPRA 的 PRA 實作為一個獨立的「監督者代理」，透過共享工作區與訊息佇列與主代理協作。持久化框架則可透過框架的狀態管理機制實現。

**與程式碼執行環境整合**
建議使用 Jupyter Kernel 或 Docker 容器作為統一的執行環境，使代理與 PRA 能在同一沙箱內運作並共享檔案系統。若已使用 Sagemaker 或 Azure ML 的 Notebook 環境，可將其作為基礎設施。

**與評分規準管理系統整合**
評分規準庫可設計為可版本控制的 YAML 或 JSON 檔案，支援跨任務繼承與覆寫。對於大型組織，可建立集中式的評分規準伺服器，供多個團隊共享與貢獻。

**與人類專家工作流整合**
在關鍵決策點（例如評分規準的最終審核、PRA 報告的處理），保留人類專家介入的介面。AdaPRA 的評分規準違規報告可作為人類審查的起點，而非取代人類判斷。

**給初學者**：建議先閱讀摘要與第 1 節的圖 1，理解 AdaPRA 解決的核心問題——資料科學代理會犯哪些「靜默錯誤」（例如預測檔案路徑錯誤導致所有樣本被標為同一類）。重點掌握四個核心概念：持久化框架、過程獎勵代理、評分規準挖掘、任務特定適應。先建立直覺，再深入方法細節。

**給 AI 工程師**：重點閱讀第 3 節方法章節，特別是 PRA 的程式碼執行稽核機制、按需上下文擷取策略、以及節奏化審查的設計。實作時可先從持久化框架與基本 PRA 開始，再逐步加入評分規準挖掘與適應。參考論文的消融實驗結果，優先實作貢獻最大的元件（程式碼執行與評分規準適應）。

**給研究者**：第 3.3 節的評分規準挖掘程序是值得深入探討的創新點，特別是它結合軌跡與工作區產物進行對比挖掘、且證明可從易任務遷移至難任務的發現。過程獎勵代理（PRA）相對於傳統過程獎勵模型（PRM）的擴展——加入工具與程式碼執行——也是值得追蹤的研究方向。建議延伸閱讀附錄 G 中與其他評分規準方法的比較。

**給產品經理**：重點關注第 1 節末段的實驗結果——80B Qwen 模型在 AdaPRA 加持下提升 24.5 與 14.8 個百分位，且匹配或超越 GPT-5.1 高推理模式。這意味著使用開源中等規模模型加上 AdaPRA 監督，有機會以更低成本達到頂級閉源模型的表現。評估導入 AdaPRA 時，應考慮 LLM API 成本、沙箱基礎設施投資、以及對現有 AutoML 流程的改造工作量。
