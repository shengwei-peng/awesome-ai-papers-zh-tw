# 大型語言模型迷失於演變中的使用者意圖

**原文標題：** LLMs Get Lost in Evolving User Intent  
**作者：** Jihoon Tack、Philippe Laban、Jennifer Neville  
**發布日期：** 2026-07-22  
**HF 連結：** [https://huggingface.co/papers/2607.20734](https://huggingface.co/papers/2607.20734)  
**arXiv：** [https://arxiv.org/abs/2607.20734](https://arxiv.org/abs/2607.20734)  

---

## ⚡ TL;DR

現有大型語言模型多於單輪、意圖完整的靜態設定中評估，難以追蹤對話中持續演變的使用者意圖。
本文提出將單輪基準轉換為多輪動態對話的框架，支援漸進揭露、修訂與任務轉換，並保留自動可驗證性。
實驗顯示模型在動態意圖下顯著下滑，GPT 5.5 數學從 99% 降至 80.5%，暴露追蹤缺口。

## 摘要翻譯

隨著大型語言模型（Large Language Models, LLMs）能力日益提升，它們越來越常被部署為協作型智能體（collaborative agents），透過迭代式互動（iterative interaction）承擔使用者委派的任務。然而，真實的互動本質上是動態（dynamic）的：使用者很少在一開始就明確表達其使用者意圖（user intent），而是隨著對話展開漸進式揭露（incrementally revealed）、修正並重塑意圖。儘管如此，現今的 LLM 仍主要在單輪（single-turn）、意圖已完全指定的靜態設定（static setting）下進行評估或訓練，留下了一個根本問題：當使用者意圖在對話過程中演變時，LLM 追蹤並依此行動的能力究竟有多好？

為了研究此問題，我們提出了一個框架，可將靜態的單輪任務轉換為動態的多輪（multi-turn）對話；在這些對話中，使用者的意圖會隨輪次演變——漸進式揭露、修正，有時甚至在對話中途轉向——同時保留每項任務原本的評估協定（evaluation protocol），使現有的基準測試（benchmarks）能作為受控的測試平台（testbeds）重複使用，而無需新的標註。在多項任務中，我們揭示了一個一致的現象：良好的靜態設定表現無法轉移至演變中的使用者意圖（evolving user intent）設定，且各模型家族（model families）的表現均顯著下滑。我們的發現指出了一項根本落差：現今的 LLM 尚無法忠實地追蹤並依據演變中的使用者意圖行動；這項能力在靜態評估中無法顯現，但對未來的協作型智能體至關重要。

### 核心貢獻（3～5點）
- 指出真實人機互動本質上為動態（dynamic），使用者意圖（user intent）會隨對話演變，但現今 LLM 多在單輪（single-turn）、意圖完全指定的靜態設定（static setting）下評估，形成重要研究缺口。
- 提出一個將靜態單輪任務轉換為動態多輪（multi-turn）對話的框架，在讓使用者意圖隨輪次漸進式揭露、修正與轉向的同時，保留原始評估協定（evaluation protocol）。

## 深度分析

#### 方法論解析

##### 問題設定與核心動機
本文針對的核心問題是：當大型語言模型（Large Language Models, LLMs）從被動的單輪（single-turn）問答聊天機器人，轉變為協作型智能體（collaborative agents）時，它們必須在長程任務（long-horizon tasks）中持續追蹤使用者意圖（user intent）。然而，現有的評估協定（evaluation protocol）與訓練資料大多假設使用者在第一輪就把意圖完整陳述，這與真實互動中「意圖隨對話逐步揭露、修正、轉向」的動態（dynamic）本質嚴重脫節。作者因此提出一個框架，把靜態（static）、可驗證的單輪基準測試（benchmarks）轉換成動態多輪（multi-turn）測試平台（testbeds），讓使用者意圖（evolving user intent）在對話中演變，同時保留原本的自動可驗證性（automatic verifiability）。

##### 意圖狀態的形式化
作者將使用者意圖形式化為一個可控的結構化狀態：

\[
I_t = (f_t, C_t, C_t^{\text{rev}}, y_t)
\]

其中：
- \(f_t\) 代表使用者想要執行的功能（function），例如 `search_restaurant`；
- \(C_t = \{c_{1,t}, \dots, c_{N,t}\}\) 是該功能所需的引數（arguments），例如 `{city, cuisine}`；
- \(C_t^{\text{rev}} \subseteq C_t\) 是已經揭露給智能體的引數子集；
- \(y_t\) 是對應任務的真實標準（ground truth），例如數學題答案或程式測試案例。

這種結構化表示不同於以往以提示詞（prompting）驅動的 LLM 使用者模擬器，因為它能精確控制「哪些資訊已揭露」「哪些值被修改」「何時轉換任務」，從而產生可重複、可分析的互動軌跡（trajectories）。

##### 三種對話動態（conversational dynamics）
框架定義了三種意圖狀態轉換（intent state transitions），這三種轉換並非互斥，可在同一輪同時發生：

1. **Argument reveal（引數揭露）**：使用者保留相同功能 \(f_t = f_{t-1}\)，但新增揭露一個或多個原本未揭露的引數，使 \(|C_t^{\text{rev}}| > |C_{t-1}^{\text{rev}}|\)。智能體需要把新資訊納入考量，而非僅依賴已揭露的片段。
2. **Argument revision（引數修正）**：使用者保留功能與已揭露引數集合，但改變至少一個已揭露引數的值，例如 `New York` 改為 `Brooklyn`。此時底層意圖已改變（\(C_t \neq C_{t-1}\)），智能體必須更新信念，不能錨定（anchor）在舊值上。
3. **Function switch（功能切換）**：使用者轉向新任務（\(f_t \neq f_{t-1}\)），但部分共享引數會被帶入新任務，例如「找餐廳」轉為「訂位」。智能體必須偵測任務轉移，同時重用相關上下文。

這三種動態涵蓋了真實對話中常見的「資訊漸進揭露」「需求改變」「目標轉向」，比單純的 under-specification（資訊不足）更接近真實使用者行為。

##### Anchor-and-retrospect 轉換流程
方法的核心是「錨定最終意圖、回溯建構前序對話」：
- 從現有的單輪可驗證資料集中提取最後一輪的錨定意圖（anchor intent），包含完整的功能、引數與答案 \(y_t\)；
- 以這個錨定為終點，反向合成（retrospectively construct）前面數輪的對話內容，讓每一輪都對應到合理的意圖轉換；
- 最後一輪保留原始資料集的完整意圖，因此智能體的最終動作可直接用原始資料集的驗證器（verifier）檢查，無需額外標註或以 LLM 為評判者（LLM-as-judge）。

這種設計讓現有 benchmarks 能被重複利用為 controlled testbeds，同時把對話長度與轉換次數當作可調參數，支援長程互動（long-horizon interaction）的規模化生成。

##### 可驗證性（automatic verifiability）的保留
由於最終輪的意圖與原始單輪任務完全一致，框架能直接使用原始評估協定：數學題比對最終答案、text-to-SQL 比對執行結果、程式設計比對單元測試、搜尋任務比對檢索結果。這避免了多輪軌跡發散特性（divergent nature）所導致的 ground truth 難以定義問題，也規避了 LLM-as-judge 的可靠性爭議。

##### 可控性與複雜度參數化
透過結構化狀態與轉換規則，研究者可以系統性地控制：
- 轉換次數（例如 6 次 intent transitions）；
- 轉換類型組合（僅揭露、僅修正、僅切換，或混合）；
- 對話輪數與每輪揭露的資訊量。

這使得評估面向（evaluation surface）從單一靜態輸入，擴展到一個組合爆炸的多輪軌跡空間，並能針對特定互動模式（interaction patterns）進行診斷。

#### 實驗數據解讀

##### 評估領域與模型
作者將框架應用到多個任務分佈（task distributions），包括數學（math）、text-to-SQL、搜尋（search）與程式設計（coding），並同時評估前沿閉源模型與開源模型。這樣的跨領域設計有助於檢驗「演變中的使用者意圖（evolving user intent）」是否為通用瓶頸，而非特定領域的現象。

##### 主要量化結果
摘要中最具代表性的數據是：在數學領域，GPT 5.5 的單輪準確率從 99.0% 下降到僅經歷 6 次 intent transitions 後的 80.5%。這是一個接近 20 個百分點的跌幅，顯示即使是非常強大的模型，在靜態設定（static setting）下的表現也無法直接遷移到動態多輪環境。

雖然文中未提供所有領域的完整表格，但作者強調「substantial drops across model families」，即不同模型家族（model families）都出現一致且顯著的衰退。這意味著問題並非單一模型的特殊缺陷，而是當前 LLM 架構與訓練範式在追蹤動態意圖上的結構性弱點。

##### 結果意涵
1. **靜態評估高估真實能力**：傳統單輪 benchmarks 測量的是「給定完整資訊後的推理與生成能力」，但無法反映智能體在資訊逐步揭露與變動時的表現。
2. **信念更新比資訊累積更困難**：Argument revision 要求模型遺忘或覆寫舊值，這與 Transformer 傾向於保留早期上下文資訊的機制存在張力。
3. **任務切換需要結構化理解**：Function switch 不僅是話題轉換，還涉及共享引數的繼承與新任務目標的辨識，這對目前以自迴歸方式生成回應的模型構成挑戰。

##### 錯誤模式推論
雖然文中未詳細列出錯誤分類，但從三種轉換類型可推論主要錯誤模式：
- **Anchoring bias（錨定偏誤）**：在 argument revision 後，模型仍使用舊引數值進行推理，例如繼續以 New York 而非 Brooklyn 搜尋餐廳。
- **遺漏切換訊號**：在 function switch 後，模型仍執行舊功能（例如繼續搜尋餐廳而非訂位），或忽略共享引數。
- **資訊整合不全**：在 argument reveal 過程中，模型未能把多輪揭露的片段組合成完整意圖，導致最終答案缺少必要條件。

##### 靜態與動態評估的落差
整體而言，實驗數據凸顯了一個被 static evaluation 隱藏的關鍵能力缺口：faithful tracking of evolving user intent。這項能力對未來的協作型智能體至關重要，卻無法透過現有的單輪 benchmarks 測量。作者因此主張，多輪、動態、可驗證的評估應成為 LLM 開發的標準環節。

#### 與現有研究的比較

##### 與現有多輪基準測試（multi-turn benchmarks）比較
近年已有許多多輪 benchmarks（如 Zheng et al., 2023; Kwan et al., 2024; Wang et al., 2024; Zhou et al., 2025），但它們普遍存在三項限制：
1. **獎勵機制依賴 LLM-as-judge**：評分由另一個 LLM 執行，可靠性存疑，且難以規模化驗證。
2. **使用者回合偏向短程**：每段互動的輪數有限，無法測量長程任務中的意圖追蹤。
3. **可控性（controllability）不足**：使用者行為大多僅限於漸進式資訊揭露（incremental information disclosure），難以系統性地測試 revision 與 task switching。

相較之下，本文框架保留原始資料集的可驗證答案（verifiable answers），並透過結構化狀態提供對轉換類型與次數的精細控制。

##### 與使用者模擬環境（user simulation environment）比較
現有的使用者模擬研究可分為兩類：

1. **Under-specification 模擬**（Sun et al., 2025; Laban et al., 2026a）：將完整題目轉為模糊提示，或把資訊切碎分散在多輪。這類方法只覆蓋單一動態軸，且受原始題目資訊量限制，難以擴展到長程互動。
2. **LLM 提示驅動的模擬使用者**（Yao et al., 2025; Qian et al., 2025a; Barres et al., 2026）：雖然能產生較自然的對話，但需要針對每個領域手動設計 schema，跨任務分佈（task distributions）的遷移性差，且難以保證可驗證性。

本文方法則結合了兩者的優點：像前者一樣可規模化且可驗證，又像後者一樣能產生包含 revision 與 task switching 的複雜互動。關鍵差異在於「結構化狀態 + 錨定回溯」的設計，使生成過程可控、可重複，並直接對應到原始 verifier。

##### 優勢總結
- **規模化**：無需為每個新任務分佈重新標註對話，降低標註成本（annotation cost）。
- **可驗證**：最終答案可直接用原始 benchmarks 的 verifier 檢查，避免 LLM-as-judge 的主觀性。
- **可控**：能獨立操縱 reveal、revision、switch 三種對話動態，進行細粒度診斷。
- **長程**：可透過增加轉換次數，生成任意長度的多輪軌跡。

##### 限制與適用範圍
儘管有上述優勢，框架仍有一些限制：
- **自然度與可控性的權衡**：結構化合成雖然可控，但產生的使用者語句可能不如真實人類對話自然，也難以捕捉情緒、偏好、隱含意圖等更細膩的使用者行為。
- **任務結構依賴**：方法最適合具有明確功能與引數的任務（如 math、text-to-SQL、search、coding）。對於開放式創作、深度研究（deep research）或氛圍編程（vibecoding）等較難形式化的任務，需要額外延申。
- **僅評估最終輸出**：雖然最終答案可驗證，但中間輪次的回應品質（例如是否主動確認、是否適當追問）並未被納入評估。
- **合成轉換的覆蓋範圍**：目前僅定義三種轉換，真實對話中還存在引數撤銷、多目標並行、目標層級改變等更複雜的動態。

#### 可重現性評估

##### 程式碼與資料集釋出狀況
根據目前提供的全文脈絡，作者尚未明確說明是否已公開原始碼、轉換後的資料集或使用者模擬框架的實作細節。由於這是一個強調「可重複利用現有 benchmarks」的方法，若能釋出轉換腳本與生成的多輪資料，將大幅提升研究社群的採用率與後續比較的公平性。

##### 模型權重與運算資源
- **閉源模型**：文中提到的 GPT 5.5 等前沿模型權重（model weights）並未公開，再現時需透過 API 呼叫，並承擔相應成本與版本差異風險。
- **開源模型**：若作者有評估開源模型，其權重通常可公開取得，但訓練細節、推論參數與 prompt 設計仍需論文補充才能完整重現。

##### 再現步驟與潛在障礙
理想情況下，重現本研究需要：
1. 取得原始單輪 benchmarks（如數學、text-to-SQL、search、coding 資料集）；
2. 使用作者提供的結構化提取器，從每個樣本中抽取 function、arguments 與 ground truth；
3. 根據設定的轉換次數與類型，執行回溯合成產生前序對話；
4. 以相同推論參數呼叫目標 LLM，收集最終輪輸出；
5. 使用原始 verifier 評分並計算各領域與各轉換條件下的準確率。

潛在障礙包括：
- 若未公開轉換演算法，社群難以精確複製「plausible preceding situations」的生成邏輯；
- 不同 LLM API 版本可能導致數值差異；
- 對於需要執行環境的任務（如 coding、SQL），verifier 的設定必須與原始 benchmarks 完全一致。

整體而言，本研究的可重現性高度依賴作者後續是否釋出程式碼與資料。在尚未公開前，建議將其視為「概念驗證與現象揭露」層級的研究，而非可立即大規模複製的標準化 benchmark。

#### 未來研究方向

##### 方法擴展
1. **更豐富的意圖轉換類型**：除了 argument reveal、revision、function switch，可進一步納入引數撤銷、條件約束新增、偏好改變、多目標並行、目標層級重組等，使對話動態更接近真實使用者。
2. **自然語言生成品質提升**：在保持結構化可控性的同時，引入更強大的語言模型來生成更自然、更多樣的使用者語句，縮小合成對話與真實對話的差距。
3. **跨領域遷移**：將框架擴展到開放式文件編輯（iterative document editing）、深度研究（deep research）、氛圍編程（vibecoding）等較難形式化的長程任務。

##### 模型訓練與架構
1. **專門的意圖追蹤訓練目標**：設計能強化信念更新與上下文選擇的損失函數，例如讓模型顯式預測當前意圖狀態 \(I_t\)，或在 revision 發生時給予更高權重。
2. **記憶與推理機制**：探索外部記憶模組、結構化意圖緩衝區、或顯式的「遺忘—更新」機制，以改善 argument revision 與 function switch 的表現。
3. **多輪強化學習與人類回饋（RLHF）**：將動態意圖追蹤納入多輪強化學習，讓模型從長期互動回饋中學習，而非僅從單輪正確答案學習。

##### 評估設計
1. **中間輪次評估**：除了最終答案正確性，也評估模型在中間輪次的行為，例如是否適當澄清、是否主動確認 revision、是否正確識別 task switch。
2. **不確定性與校準測量**：研究模型對自身意圖理解的信心是否校準，能否在資訊不足時拒絕貿然回答。
3. **真人參與評估**：結合真實使用者進行互動實驗，驗證合成環境中發現的現象是否會在真實對話中重現。

##### 真實使用者與安全性
1. **錯誤追蹤的風險分析**：探討當模型誤解演變中的使用者意圖時，可能導致的錯誤行動、資訊洩漏或有害輸出，並設計相應的安全防護。
2. **個人化與適應**：讓模型學習特定使用者的修正模式與偏好，提升長期協作中的意圖追蹤準確度。
3. **可解釋的意圖追蹤**：開發能向使用者展示其當前理解狀態的機制，讓使用者能及時糾正模型的誤解，形成更穩健的人機協作迴路。

## 論文問答

**Q1：這篇論文指出的大型語言模型核心問題是什麼？**
A：隨著大型語言模型越來越常被部署為協作型智能體，它們必須在迭代式互動中追蹤使用者意圖，但真實對話中的意圖往往是動態演變的，並不會在開頭就完整揭露。然而，現有的評估與訓練大多仍停留在單輪、靜態設定的情境，無法測量模型在演變中的使用者意圖下的表現。這造成了一個根本性的落差：我們不知道模型能否在對話過程中持續追蹤並正確回應不斷變化的意圖。

**Q2：為什麼現有的多輪基準測試無法充分捕捉演變中的使用者意圖？**
A：現有許多多輪基準測試依賴「以 LLM 為評判者」的方式來給分，而非使用可驗證答案，這降低了評估的可靠性與客觀性。此外，這些測試的使用者回合通常偏短程，且對使用者行為的可控性有限，大多只能模擬漸進式資訊揭露，忽略了修訂與任務切換等真實動態。再加上大規模多輪測試需要高昂的標註成本，真實標準難以定義，因此難以系統性地研究長程互動中的意圖追蹤能力。

**Q3：追蹤演變中的使用者意圖對未來協作型智能體為何至關重要？**
A：在氛圍編程、深度研究與迭代式文件編輯等長程任務中，使用者很少一次說清楚所有需求，而是會隨著對話推進逐步補充、修改或轉向。如果智能體無法及時更新對意圖的理解，就可能根據過時資訊產出錯誤或不相關的結果。因此，忠實追蹤演變中的使用者意圖是協作型智能體能否在真實世界穩定運作的關鍵能力。

**Q4：論文提出的核心方法是什麼？**
A：作者提出一個框架，能將任何具有可驗證答案的單輪資料集轉換為多輪互動環境，同時保留原始評估協定與自動可驗證性。具體做法是將原始單輪任務中的最終意圖作為錨點，再反向合成出合理的先前對話回合，並在過程中引入漸進揭露、資訊修訂與任務切換等對話動態。如此一來，現有的基準測試就能被重複利用為受控的測試平台，而無需額外的人工標註。

**Q5：論文定義了哪三種意圖狀態轉換？**
A：第一種是參數揭露，也就是使用者一開始未完整說明任務細節，後續回合才逐步補充參數；第二種是參數修訂，即使用者改變已經揭露過的某個參數值，智能體必須更新信念而非固守舊值；第三種是函式切換，也就是使用者從一個任務轉向另一個相關任務，但保留部分共享參數。這三種轉換可以同時發生，要求模型具備追蹤、更新與重用意圖的綜合能力。

**Q6：與過去的使用者模擬環境相比，這個框架的關鍵創新在哪裡？**
A：過去許多模擬器只能讓使用者維持在固定的資訊不足狀態，或需要針對不同任務分別手動設計綱要，難以跨領域擴展。本文將使用者意圖形式化為可控制的結構化狀態，並明確定義其轉換動態，因此能精確控制要揭露、修改或切換哪些資訊。同時，它保留了原始資料集的可驗證監督訊號，使得長程、多領域的意圖演變研究變得可規模化。

**Q7：實驗涵蓋了哪些基準測試與領域？**
A：作者展示了該框架在多個領域的通用性，包括數學、文字轉 SQL、搜尋與程式編寫等任務。這些都是原本具有明確答案或單元測試的單輪可驗證任務，適合轉換為多輪測試平台。實驗評估了多個前沿模型與開源模型家族，以比較它們在靜態與動態設定下的表現差異。

**Q8：論文的主要實證發現是什麼？**
A：研究發現，模型在單輪靜態設定中的強勁表現並無法直接遷移到演變意圖的多輪情境，各模型家族都出現顯著下降。舉例來說，GPT 5.5 在數學領域僅經過六次意圖轉換，準確率就從 99.0% 降至 80.5%。這顯示出靜態評估無法揭露的嚴重能力缺口，即便是最先進的模型也難以長期追蹤動態意圖。

**Q9：進一步分析指出模型失敗的關鍵因素是什麼？**
A：關鍵在於現今的大型語言模型難以追蹤使用者意圖在回合之間的變化，特別是當資訊被修訂或任務被切換時，模型往往仍錨定於較早的資訊。這種失敗不是單純的資訊累積問題，而是信念更新與意圖轉移偵測的問題。由於傳統單輪測試將所有意圖一次給定，因此完全無法暴露這類缺陷。

**Q10：哪些實際應用場景最能受惠於這項研究所強調的能力？**
A：氛圍編程中使用者會不斷調整需求，深度研究中查詢方向會隨新發現而修正，迭代式文件編輯中內容與風格會反覆修改，這些都需要模型持續追蹤演變意圖。此外，在對話式搜尋或訂位系統中，使用者可能先找餐廳、再改地點、最後轉為訂位，智能體必須即時適應。若缺乏這種能力，產品體驗將充滿錯誤與挫折。

**Q11：這些發現對產品開發與部署有什麼啟示？**
A：產品團隊不應僅憑單輪基準測試的分數來選擇或宣稱模型能力，而必須引入具有意圖演變的多輪評估。在介面設計上，可以讓使用者看到智能體目前理解的意圖狀態，並提供確認或修正的機制，以降低因資訊修訂或任務切換造成的錯誤。若未建立這類防護機制，直接部署的協作型智能體很可能產出過時或偏離使用者需求的結果。

**Q12：這項研究可能對大型語言模型評估領域帶來什麼影響？**
A：它將評估焦點從靜態準確率轉移到動態意圖追蹤，提供了一個可規模化且可驗證的替代方案，減少對以 LLM 為評判者的依賴。研究者也得以系統性地探討「修訂盲點」與「任務切換混淆」等過去難以量化的失敗模式。未來更多基準測試可能採用這種將單輪任務轉換為多輪互動的框架，以涵蓋更廣泛的真實使用情境。

**Q13：論文承認或暗示了哪些限制？**
A：由於對話回合是根據最終錨點反向合成而來，模擬出的對話動態可能無法完全呈現自然人類對話中的所有細微與不規則之處。此外，框架能產生的意圖演變仍受原始單輪資料集的資訊內容與任務結構所限制。某些真實世界中更複雜、更開放式的意圖轉變，可能無法簡單對應到論文定義的三種轉換類型。

**Q14：研究強調了哪些具體的失敗案例？**
A：當使用者修訂已經給過的細節時，例如地點從紐約改為布魯克林，模型常常仍根據舊資訊作答。在任務切換情境中，例如從找餐廳轉為訂位，模型可能未能正確偵測新任務，導致輸出與使用者當下意圖背道而馳。即使只經過少數幾次意圖轉換，頂尖模型的表現也會明顯下滑，顯示這是亟需解決的問題。

**Q15：這篇論文暗示了哪些未來研究方向？**
A：未來可以發展能顯式建模意圖狀態轉換的訓練方法，例如加入信念追蹤或意圖更新模組，讓模型學會在對話中主動更新理解。也可以將框架擴展到更多領域、更長的互動軌跡，並結合真實人類對話資料來彌補模擬與現實之間的差距。最終目標是打造出能夠忠實追蹤並依據演變中的使用者意圖採取行動的下一代協作型智能體。

## 實務應用指南

### 適用場景

1. **客戶支援對話機器人**  
   使用者在對話中逐步補充問題細節、更正先前提供的資訊，或從「查詢訂單」轉向「申請退貨」。將靜態 FAQ 或單輪問答基準測試轉換為多輪、意圖演變的測試平台，可驗證機器人是否能持續追蹤並正確回應。

2. **協作型程式編寫助手（Vibecoding）**  
   開發者先給出模糊需求，再逐輪補充規格、修改參數名稱或資料格式，甚至中途切換功能目標。把現有單輪編程題目轉成漸進揭露、修訂與任務切換的對話，能評估模型在長程迭代中維持程式正確性的能力。

3. **旅遊與餐廳預訂代理**  
   使用者可能先說「找紐約的素食餐廳」，接著改地點為布魯克林，最後轉為「訂位」。將結構化查詢任務轉為動態多輪互動，可測試代理如何繼承共用參數並偵測意圖轉換。

4. **迭代式文件編輯與深度研究助理**  
   使用者一開始只給大綱，隨後補充引用來源、修改寫作風格，或從「摘要」切換到「翻譯」。利用既有單輪文件處理基準測試，可建構長程、可驗證的編輯軌跡評估。

5. **數據分析與文字轉 SQL（Text-to-SQL）助手**  
   分析師逐步揭露表格欄位、修改篩選條件，或從「查詢銷售額」轉向「預測趨勢」。將靜態 SQL 資料集轉為多輪對話，能檢驗模型對修訂後意圖的追蹤與最終查詢的正確性。

### 實作前置條件

- **資料**：  
  - 可驗證的單輪任務資料集（如數學題、SQL 題、單元測試程式題），且具備自動評分器或驗證器。  
  - 每個任務的結構化意圖表示，至少包含「功能（function）」與「參數（arguments）」。

- **運算資源**：  
  - 足夠執行多輪 LLM 推理的 GPU 或 API 配額，因為每個對話軌跡會產生數倍於單輪的呼叫量。  
  - 儲存與追蹤多輪對話狀態的後端。

- **技術能力**：  
  - 熟悉提示工程與 LLM 代理框架（如 LangChain、LangGraph、OpenAI Agents SDK）。  
  - 能設計狀態機或結構化轉換規則，實作「參數揭露」、「參數修訂」、「功能切換」三種動態。  
  - 具備評估管線開發經驗，能將原始基準測試的驗證器無縫套用至多輪最終輸出。

---

### 實作步驟建議

1. **定義意圖結構與轉換規則**  
   為目標領域建立 `I_t = (f_t, C_t, C_t^rev, y_t)` 的結構化表示，並實作三種轉換：參數揭露、參數修訂、功能切換。

2. **從現有單輪資料集萃取錨定意圖**  
   將每筆單輪資料的最終答案視為「最終輪錨點」，反向推導合理的對話前史，確保最終輪仍可直接使用原始驗證器評分。

3. **建構使用者模擬器**  
   根據轉換規則自動生成多輪對話軌跡，控制揭露順序、修訂次數與任務切換次數，並支援調整互動長度與複雜度。

4. **建立評估管線**  
   保留原始評估協定，僅在最終輪執行可驗證評分；同時加入中間輪的意圖追蹤指標，例如參數記憶正確率、修訂後是否更新信念、任務切換偵測率。

5. **診斷模型弱點並迭代**  
   比較單輪與多輪表現，分析模型在哪些轉換類型下降最多，針對性地改進提示、增加 few-shot 範例，或進行微調。

6. **部署與持續監控**  
   將動態多輪評估整合至 CI/CD 流程，定期對新模型版本進行迴歸測試，並在生產環境監控真實對話中的意圖轉換與錯誤模式。

### 潛在風險與注意事項

- **錯誤累積與長程退化**  
  多輪互動中，模型一旦誤解早期意圖，錯誤會向後傳播。建議加入中間輪的「信念檢查」機制，讓模型定期摘要當前理解的使用者意圖。

- **過度擬合合成軌跡**  
  自動生成的對話可能無法完全反映真實使用者行為。應保留一定比例的真實對話資料或人機協作驗證，避免評估結果與實際部署脫節。

- **LLM-as-judge 的可靠性問題**  
  儘量使用原始資料集的可驗證答案（如單元測試、SQL 執行結果）作為主要評分依據，僅在必要時輔以 LLM 評判，並對其一致性進行審計。

- **使用者體驗與對話疲勞**  
  過長的漸進揭露可能讓真實使用者感到不耐。在產品中應允許使用者一次性補充完整資訊，而非強制多輪。

- **隱私與安全**  
  修訂與切換任務時可能涉及敏感資訊（如個人資料、付款細節）。需確保狀態管理符合資料最小化原則，並對話軌跡進行適當去識別化。

### 與其他技術的整合建議

- **RAG 與知識庫**：  
  將動態意圖狀態作為檢索條件，在意圖修訂時即時更新檢索查詢，避免模型依賴過時資訊。

- **代理框架（LangGraph / AutoGen / OpenAI Agents SDK）**：  
  把結構化意圖狀態嵌入代理的狀態圖中，讓每個節點根據當前 `I_t` 決定下一步動作，並透過邊緣條件偵測任務切換。

- **可觀測性平台**：  
  整合如 LangSmith、Weights & Biases 或自研追蹤系統，記錄每輪的意圖狀態轉換與模型信念，便於後續除錯與審計。

- **人機協作（Human-in-the-loop）**：  
  在關鍵意圖切換或高風險操作前，設計確認步驟，讓使用者核對代理對當前意圖的理解。

- **持續評估平台**：  
  將本文框架產生的動態基準測試接入自動化評估流程，與單輪基準測試並行執行，作為模型上線前的閘門。

### 給不同背景讀者的閱讀建議

- **初學者**：  
  建議先聚焦在「為什麼多輪對話比單輪困難」這個直覺：想像你請朋友幫忙訂餐廳，但中途改地點、改人數、還改成外帶——對方必須不斷更新理解，而不是只記得第一句話。本文把這種現象變成可測試的科學方法，讀懂圖 2 的三種轉換與第 3 節的意圖定義，就能掌握核心概念。

- **AI 工程師**：  
  重點閱讀第 3 節的結構化意圖表示與第 4 節的模擬框架實作細節，思考如何將 `I_t = (f_t, C_t, C_t^rev, y_t)` 映射到你現有的代理狀態管理。特別留意「保留原始驗證器」這個設計，它能讓你直接複用現有基準測試，而無需重新標註。

- **研究人員**：  
  本文的貢獻在於提出一個可擴展、可控制、可驗證的多輪評估框架，並揭示強大模型在靜態與動態設定間的表現落差。建議深入分析第 1 節的動機與第 6 節（若有的實驗結果），探討模型家族在不同轉換類型上的失敗模式，並思考是否能延伸至更開放式、非結構化的真實對話。

- **產品經理**：  
  把本文視為一個「風險預警」：你的 AI 產品在 demo 中單輪表現再好，也可能在真實使用者的迭代互動中快速退化。建議關注「適用場景」與「潛在風險」兩節，評估你的產品是否已經暴露在意圖演變的風險中，並規劃相應的評估與人機協作機制。
