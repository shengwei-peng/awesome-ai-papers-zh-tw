Axion 1.0 的核心方法論主張可歸納為一句話：**以資料品質取代流程複雜度**。論文明確挑戰了當前大型語言模型（LLM）後訓練（post-training）領域日益膨脹的趨勢——多階段中期訓練（mid-training）、多輪監督式微調（SFT）、直接偏好優化（DPO）、同策略蒸餾（OPD）等層層堆疊的複雜管線（pipeline）。Axion 1.0 僅採用三階段訓練流程：

**第一階段：自包含推理 SFT（Self-contained Reasoning SFT）**

此階段的關鍵創新在於「模型感知資料建構」（model-aware data construction）。與傳統靜態資料集不同，該方法根據基礎模型（base model）自身的解題能力來合成（synthesize）困難問題，並對其進行對抗式強化（adversarial strengthening）。具體而言，系統會：
1. 識別基礎模型已能成功解決的解題策略（solution strategies）；
2. 據此生成需要更複雜推理步驟的合成問題；
3. 對問題進行對抗式強化，使其難度恰好落在模型能力邊緣。

這種設計的理論基礎類似於「課程學習」（curriculum learning）與「對抗訓練」（adversarial training）的結合，但特別強調以模型自身能力分布作為難度校準基準，而非使用固定的難度分級。

**第二階段：工具依賴推理 SFT（Tool-dependent Reasoning SFT）**

此階段將模型從獨立推理擴展到與外部工具互動的推理。論文提出一個可擴展的任務建構流程，具備三個關鍵屬性：
- **多樣性（Diversity）**：任務來源涵蓋真實世界資料來源（real-world data sources）；
- **可驗證性（Verifiability）**：所有任務的答案可透過確定性計算（deterministic computation）自動驗證；
- **可擴展性（Scalability）**：建構流程本身可大規模運作，無需大量人工標註。

此設計呼應了近年來「可驗證獎勵」（verifiable rewards）在強化學習中的重要性——只有當任務結果可自動判定對錯時，才能進行大規模的自動化訓練。

**第三階段：強化學習（Reinforcement Learning）**

最後階段透過強化學習進一步強化長時程推理（long-horizon reasoning）與代理—環境互動（agent-environment interaction）。雖然論文未詳細說明具體的 RL 演算法（如 PPO、GRPO 或 RLOO），但從其強調「長軌跡」（long trajectories）來看，應屬於軌跡級（trajectory-level）的策略優化。

1. **資料優先於流程**：將研發投入集中於高品質資料建構，而非堆疊訓練階段；

## 潛在風險與注意事項

### 風險一：資料品質與多樣性不足
**問題**：模型感知資料建構可能過度集中於基座模型已掌握的領域，造成能力偏斜。
**緩解**：保留一定比例的通用資料；在資料建構中加入領域平衡機制；定期評估跨領域表現。

### 風險二：獎勵 hacking
**問題**：RL 階段可能使模型學會利用驗證器的漏洞，而非真正解決問題。
**緩解**：設計多重獎勵信號；定期人工審查模型輸出；使用對抗性測試案例驗證。

### 風險三：工具呼叫的可靠性
**問題**：在真實環境中，工具可能失敗、回傳錯誤或產生非預期結果。
**緩解**：在訓練資料中加入錯誤恢復範例；設計明確的錯誤處理協議；實作工具呼叫的日誌與監控。

### 風險四：長時程任務的累積誤差
**問題**：隨著軌跡增長，早期錯誤會被放大，導致整體任務失敗。
**緩解**：訓練模型具備自我檢查與回滾能力；在關鍵決策點加入驗證步驟；設計模組化任務分解。

### 風險五：開源模型的合規與安全風險
**問題**：完全開放的訓練配方可能被用於不當用途。
**緩解**：在資料建構中加入安全性過濾；發布時附帶使用指南與負責任 AI 聲明；建立社群監督機制。

### 風險六：重現成本高
**問題**：雖然論文強調「簡單」，但完整重現仍需大量計算資源與工程投入。
**緩解**：優先重現較小的 35B 版本；利用作者釋出的程式碼與資料作為起點；採用漸進式重現策略。
