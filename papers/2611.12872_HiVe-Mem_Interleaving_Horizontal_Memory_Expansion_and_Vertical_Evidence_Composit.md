HiVe-Mem 的方法論設計圍繞一個核心觀察：現有多模態記憶系統在「檢索覆蓋率」與「證據利用率」兩個維度上存在結構性缺陷。論文將這兩個維度分別命名為「水平」（Horizontal）與「垂直」（Vertical），形成一個二維設計框架，這個命名本身具有強烈的幾何直覺性——水平方向擴展記憶的「廣度」，垂直方向調整每筆記憶暴露的「深度」。

**第一階段：片段中心的多模態記憶建構（Episode-Centric Multimodal Memory Formation）**

論文將互動歷史 $H = \{x_t\}_{t=1}^{T}$ 視為一個持續增長的序列，每個互動 $x_t$ 可能同時包含文本內容與關聯影像。與將每個回合（turn）獨立處理的做法不同，HiVe-Mem 採用「片段中心」（episode-centric）的設計哲學，將多個相關回合聚合為一個記憶片段（memory episode）。這個設計選擇的關鍵在於：真實的長期互動中，單一回合往往不具備完整的語義獨立性，跨回合的上下文關聯才是資訊檢索的真正單位。

每個記憶片段在建構時同時保留兩類錨點（anchor）：
- **文本錨點（textual anchor）**：從互動中提取的語意濃縮資訊
- **視覺錨點（visual anchor）**：從影像中提取的視覺特徵

這兩類錨點在後續的水平擴展中扮演「橋接節點」的角色，使跨模態的關聯檢索成為可能。

**第二階段：水平記憶擴展（Horizontal Memory Expansion）**

這是論文最具方法論創新性的部分。傳統的語意檢索（semantic retrieval）依賴查詢與記憶條目之間的相似度匹配，這種「點對點」的檢索模式在多模態場景下容易遺漏分散於多個互動中的相關資訊。HiVe-Mem 的解決方案是將記憶片段組織成一個輕量級的關聯圖（relational graph），其中節點為記憶片段，邊則由跨片段的語境關聯性（cross-episode contextual affinity）決定。

具體而言，水平擴展的流程為：
1. **種子檢索（seed retrieval）**：首先透過語意相似度找出與查詢直接相關的種子記憶
2. **鄰居擴展（neighbor expansion）**：沿著關聯圖的邊，從種子出發擴展到語境相關的鄰居片段
3. **互補資訊恢復（complementary information recovery）**：透過這種「一跳或多跳」的擴展，恢復那些未被直接語意匹配但語境相關的記憶

這個設計的關鍵洞見在於：多模態歷史中的相關性不僅體現在語意層面，還體現在場景、實體、事件等共享線索（partial cue）上。論文特別強調「跨片段的語境親和性」（cross-episode contextual affinity）這個概念，認為相關片段之間可能共享部分視覺或文本線索，但未必形成明確的符號關係（symbolic relation）。這與傳統的知識圖譜（knowledge graph）方法形成對比——後者依賴明確的實體與關係抽取，而 HiVe-Mem 的關聯圖更為輕量，允許模糊的、基於錨點相似度的關聯。

**第三階段：垂直證據組合（Vertical Evidence Composition）**

水平擴展解決了「檢索什麼」的問題，垂直組合則解決「如何使用」的問題。論文指出，每筆被檢索到的記憶可能需要不同類型的證據來回答不同類型的查詢。例如：
- 某些記憶只需精簡摘要（compact summary）即可回答事實性問題
- 某些記憶需要接地視覺視圖（grounded visual view）來支援視覺推理
- 某些記憶需要原始影像（raw image）以保留細節資訊
- 某些記憶需要完整的互動歷史（interaction history）以理解上下文

HiVe-Mem 為每筆記憶保留五種證據形式：精簡摘要、圖像描述（caption）、接地視覺視圖、原始影像、互動歷史。這是一個「垂直」維度上的多層次表示。

核心創新在於引入一個**輕量級可訓練選擇器（lightweight trainable selector）**，這個選擇器透過強化學習（RL）訓練，能夠：
1. **獨立決策**：對每筆被檢索的記憶，獨立決定暴露哪些證據子集
2. **查詢條件化**：根據查詢內容調整證據組合
3. **聯合優化**：同時考慮答案品質與 token 消耗

這個設計的精妙之處在於「獨立性」——不同記憶可以暴露不同證據組合，避免了「一刀切」式的固定表示所帶來的資訊冗餘或不足問題。選擇器的輕量級設計也意味著它不會顯著增加推理開銷。

**兩維度的協同效應**

水平擴展與垂直組合並非獨立運作，而是形成互補：
- 水平擴展增加了被檢索記憶的數量與多樣性
- 垂直組合則控制了每筆記憶的證據暴露成本
- 兩者結合實現了「廣覆蓋、低消耗」的雙重目標

### 實作步驟建議

**步驟一：記憶片段建構與錨點抽取**
將原始互動歷史切分為記憶片段，每個片段抽取文字錨點（關鍵實體、事件描述）與視覺錨點（場景、物體、人物特徵）。建議先以規則式抽取建立 baseline，再逐步引入模型輔助。

**步驟二：建立關聯圖**
以片段為節點、文字與視覺錨點的相似度作為邊權重，建立輕量關聯圖。需決定圖的稀疏化策略（例如僅保留 top-k 相似邊），避免圖過於稠密影響檢索效率。

**步驟三：實作水平記憶擴展**
從語意檢索得到的種子片段出發，沿關聯圖進行 BFS 或啟發式擴展，設定擴展深度（建議 1-2 層）與節點數量上限。需設計去重機制，避免重複片段污染結果。

**步驟四：準備多形式證據池**
為每個記憶片段預先生成五種證據形式：精簡摘要、圖像描述、接地視覺視圖、原始影像、互動歷史。建議將摘要與描述預先快取，原始影像按需載入以節省 token。

**步驟五：訓練證據選擇器**
以強化學習訓練輕量選擇器，狀態包含查詢與候選片段特徵，動作為選擇證據子集。獎勵函數需同時考慮答案品質與 token 消耗。建議從小規模資料開始，逐步擴大。

**步驟六：整合推論管線**
將水平擴展與垂直組合串接為完整流程：查詢 → 語意檢索 → 水平擴展 → 證據選擇 → 組合輸入 → 基礎模型生成。需設計快取層以避免重複計算。

**步驟七：評估與調校**
在目標任務上進行 A/B 測試，比較 token 消耗與任務品質。建議監控擴展深度、證據選擇分布等指標，找出最佳超參數組合。

### 潛在風險與注意事項

**風險一：水平擴展引入噪音**
擴展過深或邊權重設計不當，可能引入不相關片段，反而降低檢索精準度。
**緩解**：設定嚴格的相似度門檻與節點數上限；引入顯式相關性評分機制；對擴展結果進行人工抽樣檢查。

**風險二：證據選擇器過擬合訓練分布**
若訓練資料的查詢類型過於單一，選擇器在面對新類型查詢時可能選擇不當證據。
**緩解**：蒐集多樣化查詢資料；加入規則式 fallback 機制；定期以新資料微調選擇器。

**風險三：影像編碼成本高**
原始影像與接地視覺視圖的編碼成本可能顯著影響延遲。
**緩解**：預先計算並快取影像 embedding；採用較小的視覺編碼器；對低優先級查詢降級為僅文字證據。

**風險四：記憶圖隨時間膨脹**
長期運作下，關聯圖節點數持續增長，檢索效率可能下降。
**緩解**：定期進行圖剪枝；對低活躍度片段進行摘要壓縮；採用分層索引架構。

**風險五：隱私與資料保留**
長期儲存使用者影像與對話涉及隱私風險。
**緩解**：實作資料生命週期管理；對敏感影像進行脫敏或雜訊化；遵循在地法規（如台灣《個人資料保護法》）。

**風險六：評估基準的代表性**
論文使用的三個基準可能無法完全代表實際部署場景。
**緩解**：在自有資料上建立評估集；進行影子部署（shadow deployment）驗證真實表現。
