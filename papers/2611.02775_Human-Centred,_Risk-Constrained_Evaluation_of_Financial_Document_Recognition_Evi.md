本論文提出一個**以人為本、風險約束**的金融文件識別評估框架，其核心方法論可從以下幾個層次解析：

**1. 證據基礎的類型化事實表示法（Evidence-grounded Typed Fact Representation）**

論文將金融文件中的資訊區分為三個語意層次，這是框架的基石：

- **逐字轉錄層（Verbatim Transcription Layer）**：保留來源文字的精確可見形式，例如「1.250,00 EUR」必須原樣保留，不可被靜默修正。
- **確定性正規化層（Deterministic Normalization Layer）**：在已宣告的語系慣例下，將可見文字轉為標準化值（如十進位金額、ISO 貨幣代碼）。
- **業務詮釋層（Business Interpretation Layer）**：基於業務規則的推論，例如將某行項目歸屬於特定發票或帳戶。

此三層分離的設計避免了傳統 OCR 評估中「轉錄即理解」的混淆，使每個層次的錯誤可被獨立診斷。

**2. 分層品質向量（Layered Quality Vector）**

框架定義了一個十維品質向量，涵蓋：

| 維度 | 評估對象 |
|------|---------|
| Text | 字元與詞的轉錄正確性 |
| Localization | 文字區域定位 |
| Layout | 版面結構保留 |
| Tables | 表格結構與跨頁關聯 |
| Fields | 欄位抽取 |
| Fact Correctness | 事實值正確性 |
| Evidence Grounding | 證據可追溯性 |
| Uncertainty | 信心估計的校準度 |
| Robustness | 跨條件穩健性 |
| Operational Performance | 吞吐量、延遲等營運指標 |

此設計刻意**保留診斷資訊**，而非將錯誤塌縮為單一編輯距離分數。

**3. 非補償性驗收閘門（Non-Compensatory Acceptance Gates）**

這是框架最具方法論突破性的部分。傳統 CER/WER 屬於**補償性評分（compensatory scoring）**——某欄位的嚴重錯誤可能被其他欄位的優異表現「平均掉」。論文提出：

- 對**關鍵欄位（critical fields）**——金額、識別碼、符號、期間、實體關聯——設定**單側不確定性界限（one-sided uncertainty bounds）**。
- 即使整體平均分數高，若任一關鍵欄位的錯誤率上限超過預設閾值，系統即**不通過驗收**。
- 這在形式上類似統計假說檢定中的單尾上界（upper confidence bound），將風險量化為可操作的決策準則。

**4. 選擇性自動化作為約束路由問題（Selective Automation as Constrained Routing）**

論文將「哪些案例交給機器、哪些送人工審核」形式化為：

$$\text{routing decision} = \arg\min_{a \in \{\text{auto, review}\}} \mathbb{E}[\text{loss}(a, x)]$$

其中損失函數考量：
- 自動化殘餘風險（residual risk）
- 人工審核的有效性（並非假設為 100% 正確）
- 審核成本與容量限制
- 損失敏感決策規則（loss-sensitive decision rule）

這比傳統「信心分數 < 閾值則送審」的啟發式更為嚴謹，因為它明確將**人類錯誤率**納入考量。

**5. 形式化結果（Formal Results）**

論文聲明三個理論結果：
- 補償性評分的侷限性：證明在某些風險結構下，加權平均分數無法反映關鍵錯誤的存在。
- **零觀察錯誤後的非零風險上界**：即使測試集上觀察到零錯誤，貝氏或頻率派觀點下殘餘風險仍有正下界，這對「零錯誤即安全」的直覺提出警示。
- 損失敏感路由規則的理論性質。

**6. 標註、抽樣與可重現性協議**

- **證據基礎標註（Evidence-grounded Annotation）**：每個標註須記錄可見來源、逐字轉錄、類型化標準值、語意角色，以及對模糊、缺漏、不可讀內容的明確狀態標記。
- **防洩漏基準分割（Leakage-resistant Partitions）**：避免訓練/測試資料污染。
- **可重現性卡（Reproducibility Card）**：類似 ML 領域的 model card，但針對評估流程本身。

## 實作步驟建議

1. **定義文件分類與評估單位**：依業務範圍建立文件分類法（發票、對帳單、財報等），並明確定義 corpus → document → page → region → field 的階層與相依性。
2. **建立類型化金融事實表示**：為每個欄位定義類型（金額、日期、識別碼、貨幣、稅率等）、單位、語意角色、關鍵性等級，並連結到來源區域。
3. **設計分層品質模型**：依「文字 → 定位 → 版面 → 表格 → 欄位 → 事實正確性 → 證據基礎 → 不確定性 → 穩健性 → 營運效能」逐層設計指標，避免單一聚合分數。
4. **設定非補償性驗收閘門**：在測試結果檢視前，先固定關鍵欄位的容差與單側不確定性上界；任何關鍵欄位超出上限即判定不通過，不被其他高分項掩蓋。
5. **設計選擇性自動化路由**：將「自動通過／人工審核／升級裁決」建模為約束路由問題，輸入包含自動化殘餘風險、人工審核有效性、審核成本與容量。
6. **建立標註與裁決程序**：定義標註者訓練、雙標、裁決流程，並區分「機器錯被人工抓到」「機器錯被人工放行」「機器對被人工誤改」「無法判定而升級」四種審核結果。
7. **部署可重現性卡與監控**：記錄資料版本、模型版本、隨機種子、硬體、推論設定；上線後持續監控關鍵欄位錯誤率與審核 SLA，並定期 requalification。

## 潛在風險與注意事項

- **以 CER／WER 為唯一指標**：編輯距離無法反映金額級數錯誤、符號錯誤、欄位錯置等高影響錯誤；必須搭配事實層級指標。
- **補償性評分掩蓋關鍵錯誤**：總分高不代表可用，必須以非補償閘門強制檢查關鍵欄位。
- **零觀察錯誤不等於零風險**：在樣本數有限時，零錯誤僅代表風險上界不為零，必須以單側信賴上界表達。
- **假設人工審核零成本且零失誤**：審核者會疲勞、會放行、會誤改，必須把審核有效性與成本納入路由決策。
- **標註洩漏**：訓練與測試若來自同一供應商、同一期間或同一版面，會低估真實風險；需以時間、機構、文件類型等維度強制分割。
- **正規化遮蔽不確定性**：將「1.250,00」靜默轉為「1250.00」會掩蓋來源模糊度，必須保留逐字與正規化兩層。
- **過度自動化**：在缺乏證據或信心不足時仍強行輸出，會把錯誤成本轉嫁到下游；應允許棄權與升級。

## 與其他技術的整合建議

- **LLM 與視覺語言模型（VLM）**：可作為文件理解骨幹，但輸出仍須對齊本框架的視覺證據契約（每個事實可追溯到來源區域），不可僅憑模型內部推論。
- **RPA 與 Workflow Engine**：將路由決策（自動通過／人工審核／升級）嵌入流程引擎，並以審核 SLA 與容量限制驅動派工。
- **ERP 與會計系統**：以結構化事實（金額、幣別、稅額、期間、實體關聯）作為入帳輸入，並保留證據封包供日後稽核。
- **法遵與稽核系統**：將證據封包（預測值、逐字視覺範圍、來源定位、正規化規則、信心、檢查結果）寫入不可變更的稽核日誌。
- **監控與可觀測性平台**：將分層品質指標、不確定性分布、子群錯誤率（語言、機構、文件類型）納入儀表板，設定告警與 requalification 觸發條件。
- **Conformal Prediction 與風險控制**：以共形預測產生欄位級信心區間，與本框架的單側不確定性上界直接對接，提供可證明的風險保證。
