# Prompt2Skill：從自然語言指令進行無監督技能最佳化

**原文標題：** Prompt2Skill: Unsupervised Skill Optimization From Natural Language Instructions

## ⚡ TL;DR

現有技能最佳化方法需要策展訓練資料，但使用者往往只有自然語言任務描述。
Prompt2Skill 從自然語言描述出發，由資料代理合成資料，技能代理以閉迴路反思編輯精煉技能。
在問答、閱讀理解、試算表操作與數學推理四領域，平均提升 10.8 個百分點且從未顯著退步。

## 摘要翻譯

技能是大型語言模型（LLMs）於推論階段所使用的外部產物，透過納入相關的程序性知識和領域知識，以提升其在專門領域的表現。由專家撰寫的技能成本高昂，且所生成的成品並未針對使用它們的特定模型進行最佳化，而其失敗模式會隨版本、規模和訓練方式而有所不同。此外，新興任務可能超出現有技能庫的範疇，從而在策展訓練資料可用之前，產生開發新技能的需求。近期研究已探索透過反思進行自動化技能最佳化，但它們需要策展的同分布訓練集，而使用者未必總是擁有。為了解決這些限制，我們提出 Prompt2Skill，一個僅從自然語言任務描述建構技能的框架。系統從提示中衍生出任務規格，發現或合成資料集，並在閉迴路中以反思式編輯精煉技能。在橫跨問答、閱讀理解、試算表操作和數學推理的四個領域中，Prompt2Skill 持續優於直接提示基準，於開源模型和前沿模型上平均提升 10.8 分。

### 核心貢獻（3～5點）
- 提出 Prompt2Skill 框架，僅需自然語言任務描述即可自動建構技能，無需依賴策展的同分布訓練集。
- 設計由任務規格衍生、資料集發現或合成、閉迴路反思式編輯精煉所組成的完整流程，使技能可針對特定目標模型進行最佳化。
- 解決專家撰寫技能成本高昂、且成品未針對消費模型最佳化的問題，同時回應新興任務超出既有技能庫範疇的挑戰。
- 在問答、閱讀理解、試算表操作與數學推理四個領域中，於開源模型與前沿模型上皆持續優於直接提示基準，平均提升 10.8 分。

### 適合對象
從事大型語言模型推論階段增強、自動化提示工程、領域專屬技能建構，或關注無監督方法以降低人工標註成本之研究人員與工程師；亦適合需要將 LLM 部署於專門領域（試算表操作、數學推理等）並希望提升其穩定性與表現的實務應用開發者。

## 深度分析

#### 方法論解析

**問題形式化（Problem Formulation）**

Prompt2Skill 將「技能最佳化」問題從傳統的監督式設定推向更一般化的無監督設定。傳統方法（如 SkillOpt、Trace2Skill）假設可取得一個來自任務分佈 $\mathcal{D}$ 的策展訓練集 $\{(x_i, y_i)\}$，用以評分並選擇候選技能。Prompt2Skill 則放寬此假設：系統僅接收自然語言任務描述 $d$（例如「我想要一個能閱讀維基百科段落並回答相關問題的模型」），以及至多數個示例 $E$，而無法觀察 $\mathcal{D}$ 本身。形式上，方法 $\mathcal{A}: (d, E, M, R, G, B) \mapsto \hat{s}$ 必須在不知道真實分佈的情況下產出技能 $\hat{s}$，其品質 $J(\hat{s}) = \mathbb{E}_{(x,y)\sim\mathcal{D}}[\mu(M_s(x), y)]$ 只能在事後於測試集上量測。這種設定極具實務價值——多數終端使用者僅有「心中所想」與少數示例，無法負擔策展大規模標註資料的成本。

**雙代理架構（Two-Agent Architecture）**

整體框架由兩個分工明確的代理組成：

1. **資料代理（Data Agent）**：負責將抽象的任務描述轉化為可操作的訓練素材。其運作流程為：
   - **任務規格生成（Task Specification Generation）**：透過 $f_{\theta_{\text{setup}}}(d, E)$ 聯合產生任務規格 $\tau$（包含輸入輸出契約、答案格式、評估方式）與初始種子技能 $s_0$。此處的關鍵設計是「聯合生成」——規格與種子技能並非獨立產物，而是相互約束的產出，避免規格過於空泛或技能過於偏離規格。
   - **資料檢索與合成（Data Retrieval and Synthesis）**：代理從線上資源檢索候選資料集，並依任務介面進行重新格式化（reformatting）；若無合適資料，則進行接地合成（grounded synthesis），生成符合任務規格的資料項。這種「檢索優先、合成兜底」的策略兼顧資料真實性與覆蓋率。

2. **技能代理（Skill Agent）**：在閉迴路中精煉種子技能。其核心機制為：
   - **推論執行與反思（Rollouts and Reflection）**：以目標模型 $M$ 搭配當前技能 $s$ 對一批保留項目執行推論，由反思模型（Reflector Model）根據 $M$ 的失敗案例提出候選編輯。
   - **統計驗收（Statistical Acceptance）**：每個編輯僅在「配對統計顯著性測試」（paired statistical significance test）通過時才被接受——即新技能 $s'$ 必須在「新批次」（fresh batch）上顯著優於 $s$，而非僅憑單點比較。這避免了過擬合於特定樣本。
   - **凍結驗證集最終選擇（Frozen Validation Set Final Selection）**：精煉完成後，於一個僅被查詢一次的凍結驗證集上做最終挑選，防止驗證集被多次窺探導致的選擇偏差。

**演算法特性分析**

此設計有幾項值得深入剖析的特性：

- **「新批次」紀律**：每次接受編輯的統計測試都使用全新的保留項目，而非重複使用同一批資料。這實質上將技能精煉過程轉化為一種「滾動驗證」（rolling validation），大幅降低過擬合風險。
- **編輯的有界性（Bounded Edits）**：編輯操作被限制為新增/刪除/替換（add/delete/replace），這與 SkillOpt 的設計一致，確保技能文件不會因無限制生成而失控。
- **目標模型特化（Target Model Specialization）**：技能是針對特定 $M$ 優化的，這呼應了論文中「失敗模式隨版本、規模、訓練而異」的觀察——同一份人類撰寫的技能未必適用於所有模型。

#### 實驗數據解讀

**跨領域表現**

論文在四個領域評估 Prompt2Skill：問答（Question Answering）、閱讀理解（Reading Comprehension）、試算表操作（Spreadsheet Manipulation）、數學推理（Mathematical Reasoning）。這四個領域的選擇具有互補性：QA 與閱讀理解偏向語言理解與知識檢索；試算表操作涉及結構化資料與工具使用；數學推理則考驗多步邏輯。平均 10.8 個百分點的改善橫跨開源與前沿模型（frontier models），且「從未顯著退步」（never significantly regresses），這是一個強韌性訊號——相較於許多 prompt optimization 方法常見的高方差，Prompt2Skill 表現出穩定的單調增益。

**基準線比較的意涵**

- **直接提示基準（Direct Prompting Baseline）**：10.8 個百分點的差距說明，僅憑自然語言描述，模型本身無法可靠地浮現出最佳實務；技能確實補足了模型參數化知識（parametric knowledge）的缺口。
- **前沿 LLM 單次撰寫技能**：論文將 Prompt2Skill 與「由前沿 LLM 僅從任務描述直接撰寫技能」相比，凸顯了「資料檢索 + 最佳化」相較於「單次生成」的價值。這暗示了單次 LLM 撰寫容易陷入「看似合理但未經驗證」的陷阱，而閉迴路精煉能系統性地剔除此類偽解。

**消融實驗（Ablations）**

雖然完整數據未在所提供片段中呈現，但論文聲稱「extensive ablations and case studies further isolate the contribution of each component」。從方法論可推論，關鍵消融項應包括：(1) 移除資料代理（僅用合成或僅用檢索）；(2) 移除統計驗收（改為單純接受所有編輯）；(3) 移除凍結驗證集（多次查詢驗證集）；(4) 改變反思模型與目標模型的同異關係（同模型 vs. 異模型反思）。這些消融將有助於釐清各模組的邊際貢獻。

**案例研究的價值**

論文強調 case studies 的重要性，這通常用於揭示：(1) 技能在迭代中如何從粗糙走向精煉；(2) 反思模型識別出的失敗模式類型；(3) 統計驗收拒絕的「看似改善但實為雜訊」的編輯案例。這些質化分析對理解方法的行為模式至關重要。

#### 與現有研究的比較

**與 Trace2Skill 的關係**

Trace2Skill（Ni et al., 2026）從代理執行軌跡（execution trajectories）出發，透過歸納推理（inductive reasoning）將反覆出現的失敗與替代方案壓縮為標準作業程序（Standard Operating Procedures, SOPs）。兩者的關鍵差異在於：
- **資料來源**：Trace2Skill 需要大量執行軌跡作為輸入；Prompt2Skill 僅需自然語言描述。
- **最佳化機制**：Trace2Skill 本質上是歸納式的，缺乏明確的評分函數；Prompt2Skill 引入統計驗收，具備更強的最佳化紀律。
- **適用場景**：Trace2Skill 適合已有大量代理經驗的場景；Prompt2Skill 適合冷啟動（cold start）場景。

**與 SkillOpt 的關係**

SkillOpt（Yang et al., 2026）將技能創建視為可控文本空間最佳化（controllable text-space optimization），由最佳化模型（optimizer model）將評分後的推論結果轉化為有界編輯。兩者共享「編輯式最佳化」的核心思想，但 Prompt2Skill 的根本突破在於：
- **無需同分布訓練集**：SkillOpt 需要大量同分布保留資料；Prompt2Skill 透過資料代理繞過此限制。
- **單示例崩潰問題**：Yang et al. 證實 SkillOpt 在訓練集縮減至單一示例時增益崩塌至「資料盲草稿」（data-blind draft）水平；Prompt2Skill 正是為解決此問題而設計。

**與人類撰寫技能的比較**

雖然論文未直接與人類專家技能進行大規模比較，但其設計動機明確指出人類撰寫的成本（需要領域知識、熟悉技能格式、針對模型行為迭代）以及「未針對特定模型最佳化」的缺陷。Prompt2Skill 的自動化迴路本質上是將人類專家的迭代經驗編碼為代理流程。

**侷限性（Limitations）**

需注意以下潛在限制：
1. **資料代理的可靠性**：檢索與合成的品質直接影響下游技能品質。若代理對任務描述理解錯誤，整個流程將偏離。
2. **反思模型的能力上限**：若反思模型無法準確診斷失敗模式，編輯將是雜訊。
3. **計算成本**：閉迴路精煉涉及大量推論執行，雖然無需權重更新（weight updates），但推論時間成本仍可觀。
4. **領域覆蓋**：四個領域雖具代表性，但對於高度專業化（如醫療診斷、法律推理）的領域，資料代理能否找到合適資料仍是未知數。

#### 可重現性評估

**程式碼與資料可用性**

從所提供的片段中，無法直接確認程式碼開源狀況。然而，鑑於此論文為 arXiv 預印本（Preprint. Under review），且方法涉及多個 LLM 呼叫與資料檢索流程，完整可重現性需要：
- **程式碼**：包含兩個代理的 prompt 模板、編輯操作實作、統計驗收邏輯。
- **資料**：四個領域的具體資料集來源、檢索查詢、合成 prompt。
- **模型權重**：目標模型若是開源模型（如 Llama 系列），需明確版本；若是商業 API（如 GPT、Claude），需記錄模型版本與呼叫參數。

**超參數與設定**

關鍵超參數包括：
- 閉迴路迭代次數上限
- 統計顯著性閾值（p-value threshold）
- 每批保留項目的大小
- 反思模型的選擇（同模型 vs. 異模型）
- 編輯操作的邊界（如最大新增/刪除字元數）

**評估指標**

論文使用任務特定的評估指標 $\mu$，但具體公式（如 QA 的 exact match、F1；數學的答案正確率；試算表的執行成功率）需在實驗章節確認。

**可重現性風險**

主要風險點在於：
1. **線上資料檢索的非確定性**：若資料代理從動態網路資源拉取資料，相同 prompt 可能產生不同結果。
2. **LLM API 的版本漂移**：商業模型版本更新可能導致結果變化。
3. **統計測試的隨機性**：批次抽樣的隨機性可能影響編輯接受與否。

#### 未來研究方向

**1. 反思模型的自我強化**

當前反思模型與目標模型可能是同一模型或不同模型。一個有趣方向是讓反思模型隨著精煉過程自我調整——透過觀察哪些反思建議被接受、哪些被拒絕，學習更精準的診斷模式。

**2. 跨任務遷移學習**

若 Prompt2Skill 在多個任務上累積大量精煉經驗，可探索技能間的遷移——例如，從「閱讀理解」精煉出的反思啟發（reflection heuristics）能否加速「QA」任務的精煉。這將使系統從「單任務專家」演進為「元學習者」。

**3. 人機協作介面**

完全自動化雖降低門檻，但在高風險領域，使用者可能希望介入編輯過程。研究「人在迴路中」（human-in-the-loop）的 Prompt2Skill 變體——例如，使用者可在統計驗收前預覽編輯並提供修正——將提升實用性。

**4. 技能組合與分解**

當前框架產出單一技能文件。未來可探索技能的階層化組合——將複雜任務分解為多個子技能，並學習其組合策略。這呼應了技能生態系（skill ecosystem）的概念。

**5. 形式化保證**

目前缺乏對 Prompt2Skill 收斂性或改善下界（improvement lower bound）的理論分析。借鑑 bandit 或 convex optimization 的工具，為閉迴路精煉提供形式化保證將是重要的理論貢獻。

**6. 偏誤與公平性審查**

技能是模型行為的「軟約束」。若資料代理檢索到帶有偏誤的資料，或反思模型強化了特定觀點，技能可能放大偏誤。未來工作應系統性地審查 Prompt2Skill 在偏誤基準上的表現。

**7. 與其他推論時技術的整合**

Prompt2Skill 可與其他推論時技術（如 chain-of-thought prompting、self-consistency、tool-augmented reasoning）正交組合。研究這些技術與技能最佳化的疊加效應，將有助於理解推論時增強的整體光譜。

**8. 領域特化變體**

針對特定領域（如程式碼生成、科學推理、創意寫作）設計領域特化的資料代理與反思模型，可能帶來超越通用版本的增益。例如，在數學領域，反思模型可整合符號驗證器（symbolic verifier）以提供更精確的失敗診斷。

## 論文問答

**Q1：Prompt2Skill 主要解決什麼核心問題？**
A：Prompt2Skill 旨在解決「技能（skill）撰寫成本高昂且缺乏模型特化」這個根本問題。在當前的大型語言模型部署實務中，技能通常是由人類專家撰寫的 markdown 檔案，會被放入模型的上下文中以提供程序性知識、領域慣例與工具使用指引，但每個新任務都需要領域專業知識、熟悉技能格式，並針對特定模型的行為進行反覆迭代。這種依賴人工的方式限制了可擴展性，使得新興任務在策展訓練資料尚未到位前難以快速建立對應技能。Prompt2Skill 因此提出一個端到端的多代理框架，只需自然語言任務描述即可自動產生經過最佳化的技能，無需使用者提供任何標註資料。

**Q2：為何現有的自動化技能最佳化方法（如 Trace2Skill、SkillOpt）在真實場景中會失效？**
A：現有方法如 Trace2Skill 透過歸納推理將執行軌跡合併為標準作業程序，而 SkillOpt 則將技能創建視為可控的文本空間最佳化，透過新增、刪除、替換等編輯操作來改進技能文件。然而，這些方法都預設能取得一個經過策展、與目標任務同分布的訓練集，並具備可靠的標籤——但這恰恰是實際部署的使用者所缺乏的資源。先前研究已顯示，當訓練集縮減到僅剩單一範例時，這些方法的效能會崩塌到與無資料的草稿相當的水準。因此 Prompt2Skill 移除了這個假設，處理的是「使用者僅有任務想像，可能搭配少數範例」的更貼近現實的設定。

**Q3：為什麼這個研究方向對 LLM 部署如此重要？**
A：此研究的重要性在於它直接回應了 LLM 從「通用模型」走向「專門化部署」過程中最關鍵的瓶頸——如何讓模型在不更新權重的情況下，僅憑上下文中的技能文件就能在特定任務上表現優異。隨著模型版本、規模與訓練資料的演變，模型的失敗模式也會隨之改變，使得人類專家撰寫的技能難以保持最佳狀態。此外，新興任務往往超出既有技能庫的範疇，而策展訓練資料的產生又需要時間，這中間存在明顯的空窗期。Prompt2Skill 透過從自然語言描述直接生成模型特化的技能，填補了這個空窗，使部署者能在資料尚未齊備時就獲得有效的任務支援。

**Q4：Prompt2Skill 的核心方法是什麼？**
A：Prompt2Skill 的核心方法是一個由兩個代理組成的多代理框架：資料代理（Data Agent）與技能代理（Skill Agent）。資料代理負責將自然語言任務描述轉換為任務規格，包含輸入輸出契約與答案格式，接著從線上資源檢索候選資料集，或在必要時重新格式化甚至合成接地的資料項，以建構一個經過驗證的資料池。技能代理則在這個資料池上進行閉迴路的精煉：透過推論執行取得目標模型自身的失敗案例，由反思模型提出候選編輯，每個編輯只有在新的保留批次上通過統計顯著的配對比較才會被接受，最終從一個僅被查詢一次的凍結驗證集中選出最終技能。

**Q5：相較於先前的 SkillOpt 等方法，Prompt2Skill 的關鍵創新是什麼？**
A：Prompt2Skill 最關鍵的創新在於它把「資料獲取」與「技能最佳化」這兩個原本分離的問題整合進同一個框架中。SkillOpt 等方法假設已有可靠的標註訓練集，因此只需專注於文本空間的最佳化；但 Prompt2Skill 認識到在無監督設定下，必須先由資料代理主動發現、處理或合成資料，才能為後續的技能精煉提供評分依據。此外，框架採用了「凍結驗證集僅查詢一次」的嚴格紀律，避免在多次迭代中過度擬合驗證集，這是對過往工作中驗證集使用方式的重要方法論改良。

**Q6：框架中有哪些重要的設計選擇值得深入探討？**
A：幾個值得探討的設計選擇包括：第一，採用「配對統計顯著性檢定」而非單純的分數比較來決定是否接受編輯，這降低了隨機波動導致的錯誤接受；第二，將驗證集的使用嚴格限制為最終選擇階段的一次查詢，避免了迭代過程中的資料洩漏與過擬合風險；第三，資料代理被賦予「檢索—處理—合成」三階段的彈性，使其能適應從「已有現成資料集」到「完全沒有可用資料」的各種情境；第四，反思模型是基於目標模型自身的失敗來提出編輯，這使得技能能針對特定模型的弱點進行特化，而非泛泛地套用通用最佳實務。

**Q7：實驗涵蓋了哪些基準測試與領域？**
A：實驗橫跨四個截然不同的領域以驗證框架的泛用性：問答（Question Answering）、閱讀理解（Reading Comprehension）、試算表操作（Spreadsheet Manipulation）以及數學推理（Mathematical Reasoning）。在模型選擇上，同時涵蓋了開源模型與商業前沿模型，總共五個不同的目標模型，以確保結論不僅限於特定模型家族。這種跨領域、跨模型的設計選擇，使得 10.8 個百分點的平均改善具有更強的說服力，因為它不是針對單一任務或單一模型族的過擬合結果。

**Q8：實驗的關鍵結果為何？**
A：最關鍵的結果是 Prompt2Skill 在所有測試配置中相較於直接提示基準平均提升了 10.8 個百分點，且從未在任何配置中出現統計顯著的退步——這意味著該方法不僅有效，還具有穩健的下限保證。另一個重要結果是，當與「僅由前沿 LLM 從任務描述直接撰寫技能」的基線比較時，Prompt2Skill 仍然勝出，這凸顯了資料檢索與最佳化迴圈對技能撰寫品質的實質貢獻，而非僅僅是 LLM 本身的寫作能力。這些結果共同支持了「自動化、無監督的技能生成」這條技術路線的可行性。

**Q9：消融研究揭示了哪些元件的相對貢獻？**
A：根據摘要與全文脈絡，消融研究透過逐一移除框架元件來隔離各部分的貢獻，結果顯示資料代理的檢索與合成能力、以及技能代理的閉迴路反思式編輯都是不可或缺的。具體而言，若僅由前沿 LLM 從任務描述直接撰寫技能而省略資料驅動的最佳化，效能會明顯下降，說明了「資料」與「最佳化」這兩個維度對最終品質都有實質影響。此外，案例研究進一步剖析了反思式編輯如何針對目標模型的特定失敗模式進行修正，證明了這種「從失敗中學習」的機制比靜態的技能撰寫更能貼合模型的實際行為。

**Q10：Prompt2Skill 在哪些實際場景中特別有用？**
A：Prompt2Skill 特別適用於以下場景：第一，企業或個人使用者面對一個全新的專門任務，既沒有標註資料，也沒有時間聘請領域專家撰寫技能時，只需提供一段自然語言描述即可獲得可用的技能；第二，當組織內部已有任務但缺乏策展訓練資料、且任務描述隨業務需求經常變動時，Prompt2Skill 能快速迭代產生對應技能；第三，在模型升級或更換時，由於不同版本的模型失敗模式不同，過去人類撰寫的技能可能失效，此時可重新運行 Prompt2Skill 為新模型量身打造技能，避免人工重新除錯的成本。

**Q11：從產品化的角度，這項工作帶來哪些考量？**
A：從產品化角度來看，Prompt2Skill 提示了一種新的「技能即服務」（Skill-as-a-Service）商業模式，使用者只需描述需求即可獲得模型特化的技能，而無需理解底層的提示工程細節。然而，產品化時需要考量幾個面向：首先，資料代理從線上資源檢索資料時涉及版權與合規問題，需要明確的資料來源治理；其次，閉迴路最佳化會消耗大量推論資源，必須權衡最佳化深度與成本；最後，技能的版本控制與可審核性也是企業部署時的重要需求，因為自動生成的技能需要能被追溯、審查與回滾。

**Q12：這項研究對整個領域會產生什麼樣的影響？**
A：這項研究的影響是深層次的：它將「技能開發」從一個需要專家人力投入的工藝活動，轉變為一個可由 AI 系統自動完成的工程流程，從而大幅降低了 LLM 專門化部署的門檻。更宏觀地看，它呼應了「以推理時計算換取能力」這個 LLM 領域的重要趨勢——與其訓練更大的模型，不如讓模型在推理時消費精心設計的上下文工件。Prompt2Skill 證明了這類工件可以由系統自動生成，這為未來「自我改進的 AI 助手」、「可程式化的模型行為」等研究方向奠定了基礎。

**Q13：論文承認了哪些限制？**
A：雖然全文未在所提供的片段中詳列所有限制，但從方法設計可以推論出幾項重要限制：第一，框架依賴資料代理能從線上資源檢索到相關資料，或在缺乏資料時具備足夠的合成能力，對於極度冷門或高度專業的領域，合成資料的品質可能不足以支撐有效的技能最佳化；第二，閉迴路最佳化需要反覆呼叫目標模型與反思模型，運算成本不低，且最佳化過程的收斂性並未在論文中深入分析；第三，技能是以 markdown 形式存在的文本工件，其效果高度依賴目標模型對長上下文的遵循能力，對於上下文視窗較小或指令遵循能力較弱的模型，效益可能打折。

**Q14：在哪些情況下 Prompt2Skill 可能會失敗？**
A：可能失敗的情境包括：第一，當任務描述過於模糊或抽象時，資料代理可能無法推斷出合理的輸入輸出契約，導致檢索或合成的資料與真實需求偏差過大；第二，當目標模型的失敗模式極為罕見或需要深度的領域專業知識才能診斷時，反思模型可能無法提出有效的編輯，使得閉迴路陷入停滯；第三，在需要即時性或高度動態更新的任務（例如即時新聞問答）中，靜態的技能生成流程無法跟上資料分布的快速漂移；第四，當任務涉及多輪對話、複雜工具鏈或長程規劃時，僅靠單一技能文件可能不足以捕捉所有必要的程序性知識。

**Q15：未來有哪些值得探索的研究方向？**
A：基於這項工作，未來值得探索的方向包括：第一，將 Prompt2Skill 擴展到多輪對話與代理型任務，使技能不僅是靜態的 markdown，而是可隨對話狀態動態組合的程序庫；第二，研究如何在多個任務間共享與遷移已學到的技能，避免每個新任務都從零開始最佳化；第三，探索將人類反饋（如「這個技能在某類輸入上仍會失敗」）納入閉迴路，使技能最佳化能結合自動化效率與人類判斷；第四，發展更輕量的版本，使框架能在邊緣裝置或資源受限的環境中運行；最後，從理論上分析閉迴路最佳化的收斂性與樣本複雜度，為方法提供更堅實的理論基礎。

律師事務所僅需提供「讀取合約段落並回答條款相關問題」這類描述，Data Agent 可從公開法律資料集（如 CUAD）合成接地資料，Skill Agent 再針對特定模型（如 GPT、Claude 或開源模型）精煉出最佳提示技能。

**3. 試算表自動化操作代理**
業務團隊描述「根據銷售試算表產生月度報表並標記異常」，Prompt2Skill 可從線上試算表基準資料集擷取範例，自動合成符合該企業欄位格式的訓練項目，並產出可重用的技能文件。

**4. 數學推理教學工具的個人化**
教育新創公司想為不同年級、不同模型部署客製化解題助手，但缺乏標註題庫。可用 Prompt2Skill 從 GSM8K、MATH 等資料集衍生任務規格，並為目標模型（如 Llama、Qwen 系列）量身打造技能。

**5. 新興任務的快速原型驗證**
當產品團隊想測試一個尚未有公開資料的新任務（例如「從會議記錄中萃取行動項目」），Prompt2Skill 可在數小時內產出可用技能雛型，協助評估可行性後再決定是否投入正式資料標註。

### 實作前置條件

**資料面**
- 目標任務的自然語言描述 d（必填），以及少量輸入輸出範例 E（選填，建議 1–5 筆）
- 可存取的線上資料來源（Hugging Face Datasets、公開 GitHub 儲存庫、網路搜尋 API）
- 凍結驗證集與測試集：需事先準備少量來自真實任務分布的標註資料，用於最終選擇與效能評估（即使 Prompt2Skill 本身不需要這些資料來訓練，仍需用於衡量 J(ŝ)）

**運算面**
- 目標模型 M 的推論環境（API 或自架），需支援批次推論以執行 rollouts
- 反思模型（Reflector）與最佳化模型（Optimizer）的推論資源——可與目標模型相同或更小
- 建議使用 vLLM、TGI 或類似高效推論框架以控制閉迴路精煉的成本
- 統計檢定所需的樣本數：每輪精煉至少需要數十至數百個保留項目以達到配對比較的統計顯著性

**技能面**
- 熟悉 LLM 提示工程與 JSON/Markdown 結構化輸出
- 理解假設檢定（paired comparison、bootstrap 或 sign test）
- 具備多代理系統的編排能力（如 LangGraph、AutoGen 或自訂 orchestrator）
- 對「技能文件」格式（Markdown 區段、程序性指令、工具呼叫範例）有基本概念

### 實作步驟建議

**步驟 1：定義任務輸入契約**
撰寫任務描述 d，盡量包含輸入格式、預期輸出格式與領域關鍵字。例如：「讀取一段維基百科條目，回答關於該條目事實的問題，答案為簡短文字」。同時準備 0–5 筆範例 E 供 Data Agent 釐清介面。

**步驟 2：建置 Data Agent**
實作 `f_θ_setup(d, E)`，讓 LLM 一次性產出：
- 任務規格 τ（包含輸入輸出契約、答案格式、評估方式）
- 種子技能 s₀（初版 Markdown 技能文件）
提示詞 θ_setup 應明確要求模型區分「已從描述推斷」與「需從範例推斷」的欄位。

**步驟 3：資料檢索與合成管線**
Data Agent 應具備三種資料獲取路徑：
- 檢索：從 Hugging Face 等來源搜尋符合 τ 的資料集
- 處理：將檢索到的資料重新格式化為 τ 定義的介面
- 接地合成：當檢索失敗或資料不足時，根據 τ 與種子技能生成新項目，並用目標模型自我驗證品質

**步驟 4：Skill Agent 閉迴路精煉**
實作 Algorithm 1 的核心迴圈：
1. 用當前技能 s 在新批次保留項目上執行 rollouts
2. 收集失敗案例，餵給反思模型產生候選編輯（新增/刪除/替換技能段落）
3. 在同一批新項目上做配對統計檢定，僅在顯著改善時接受編輯
4. 重複直到預算耗盡或無顯著改善

**步驟 5：凍結驗證集最終選擇**
從閉迴路過程中保留所有通過統計檢定的候選技能版本，在凍結驗證集上評估一次，選出最佳者 ŝ。**此驗證集僅使用一次**，避免過擬合到選擇程序本身。

**步驟 6：部署與監控**
將 ŝ 存入技能庫（建議結構化為 Markdown + YAML frontmatter），透過模型上下文注入使用。記錄每次部署的目標模型版本、任務描述與效能，便於日後重新最佳化。

### 潛在風險與注意事項

**風險 1：資料檢索失敗或品質低落**
當線上沒有符合 τ 的資料集時，Data Agent 可能合成低品質或偏頗的接地項目。
*緩解：* 對合成項目加入品質過濾器（例如要求目標模型在已知答案上通過率達標），並在最終驗證集上檢查分布漂移。

**風險 2：反思模型的偏見與局部最優**
Reflector 可能反覆提出同類型編輯，導致技能陷入局部最優。
*緩解：* 引入編輯多樣性懲罰、定期重置反思提示、或在閉迴路中加入隨機探索步驟。

**風險 3：統計顯著性誤判**
當保留批次過小或變異度高時，配對檢定可能誤接受或誤拒絕編輯。
*緩解：* 設定最小批次大小（例如 ≥ 50 項目）、使用嚴格顯著水準（p < 0.01），並對多次比較的 family-wise error 做校正。

**風險 4：技能過擬合到特定模型版本**
精煉出的技能可能僅對當前模型版本有效，模型升級後失效。
*緩解：* 在技能文件中保留「適用模型」標籤，並建立定期重跑 Prompt2Skill 的 CI/CD 流程。

**風險 5：計算成本失控**
閉迴路精煉需要大量 rollouts，成本可能遠超一次性人工撰寫技能。
*緩解：* 設定迭代上限與單次編輯預算，使用較小模型作為快速代理先篩選編輯，再用目標模型做最終驗證。

**風險 6：任務規格推斷錯誤**
當描述 d 模糊時，Data Agent 可能錯誤推斷輸入輸出契約。
*緩解：* 在介面中提供「規格確認」步驟，讓使用者（或另一個 LLM）審核 τ 後再進入精煉階段。

### 與其他技術的整合建議

**與 RAG 系統整合**
Prompt2Skill 產出的技能可作為 RAG 的「查詢改寫」或「答案格式化」模組。建議將技能文件與檢索器配置分離，使技能專注於程序性指令，檢索器負責事實性內容。

**與 Agent 框架整合**
技能可作為 Agent 的 system prompt 注入層。搭配 LangGraph、AutoGen 等框架時，建議將技能載入設計為可熱插拔的 middleware，方便在不同任務間切換。

**與 MLOps / LLMOps 整合**
將 Prompt2Skill 包裝成 CI/CD 流程：當新模型版本發布或任務描述變更時，自動觸發重新最佳化。建議將每次執行的資料快照、反思日誌與最終技能版本化儲存。

**與技能市集 / 技能庫整合**
產出的技能可上架到內部技能市集，搭配 metadata（目標模型、適用領域、預期效能）供其他團隊複用。注意為每個技能標註「是否經過 Prompt2Skill 最佳化」與「最佳化時的目標模型版本」。

**與評估平台整合**
將凍結驗證集與測試集接入評估平台（如 Promptfoo、LangSmith），持續監控部署後技能的實際表現，並在效能下降時自動觸發重新最佳化。

### 給不同背景讀者的閱讀建議

**給初學者：** 建議先讀第 1 節（Introduction）與第 2 節（Problem Definition），重點理解「技能」是什麼、為什麼需要自動化建立，以及 Prompt2Skill 解決的「沒有標註資料」這個痛點。跳過演算法細節，把重點放在 Figure 2 的框架圖與第 3 節的高階流程敘述，建立「任務描述 → 資料代理 → 技能代理 → 可用技能」的整體心智模型即可。

**給 AI 工程師：** 直接進入第 3 節（Prompt2Skill）與 Algorithm 1，仔細閱讀 Data Agent 的任務規格推斷、資料檢索合成流程，以及 Skill Agent 的閉迴路精煉細節——特別是配對統計檢定的接受準則與凍結驗證集的單次使用原則。實作時建議先以單一領域（如問答）做端到端 prototype，再逐步擴展到其他領域，並密切關注計算成本與迭代次數的權衡。

**給研究者：** 重點關注第 2 節的形式化問題定義（將任務分布 D 與評估指標 µ 視為隱變數的設定）、第 3 節的閉迴路接受準則設計，以及與 Trace2Skill、SkillOpt 的差異比較（前者從軌跡歸納、後者從標註資料最佳化，Prompt2Skill 則從純描述出發）。實驗章節的消融研究與案例分析是延伸研究方向的切入點，例如：反思模型的選擇對最終效能的影響、不同統計檢定方法的比較、跨任務的技能遷移等。

**給產品經理：** 聚焦第 1 節的動機段落與實驗結果（平均 10.8 個百分點改善、從未顯著退步），理解 Prompt2Skill 對「沒有資料也能客製化模型行為」這件事帶來的產品意義。在評估導入可行性時，建議從「任務描述是否清楚」、「是否有線上資料可檢索」、「是否有少量真實樣本作為最終驗證」三個維度判斷適用性，並預留 Prompt2Skill 重新執行的成本（時間與 API 費用）作為產品迭代週期的一部分。
