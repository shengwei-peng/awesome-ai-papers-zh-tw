HeLM 的核心設計理念源自人類「內心獨白」(inner monologue) 的認知機制，將自然語言作為機器人操作中的記憶表示形式。這個選擇具有三層理論基礎：(1) 語言是 VLM-based 策略的原生模態 (native modality)，無需額外的模態對齊；(2) 語言形式緊湊，能在長時程任務中保持可擴展性 (scalability)；(3) 語言記憶具有可檢視性 (inspectability)，便於失敗分析。

**階層式架構設計**

HeLM 採用雙層決策結構，將記憶管理與動作生成解耦：

- **高層策略 (High-Level Policy, HLP)**：基於 VLM 構建，負責維護語言形式的任務歷史，並產生動作指令 (action commands)。HLP 透過查詢語言記憶來決定當前應該執行什麼子任務。

- **低層策略 (Low-Level Policy, LLP)**：基於 VLA 構建，負責將 HLP 的指令轉化為具體的機器人動作。LLP 維持馬可夫假設 (Markovian assumption)，僅根據當前觀察生成動作。

這種解耦設計的關鍵優勢在於：HLP 處理需要長期依賴的非馬可夫推理，而 LLP 專注於短時程的精細操作 (fine manipulation)，兩者各司其職。

**分解式事件偵測 (Factorized Event Detection)**

HeLM 將事件偵測從記憶更新中分離出來。具體而言，系統並非在每個時間步都更新記憶，而是透過獨立的偵測機制判斷當前是否發生了任務相關事件 (task-relevant event)。這種設計避免了兩類問題：(1) 冗餘更新造成的計算浪費；(2) 無關事件污染記憶內容。

**事件觸發記憶更新 (Event-Triggered Memory Updates)**

記憶更新僅在兩種情況下觸發：(1) 偵測到任務相關事件；(2) 指令發生變化。這種觸發式機制大幅降低了記憶系統的運行頻率，同時確保關鍵資訊不會遺漏。

**雙欄位記憶組織**

HeLM 的語言記憶被組織為兩個欄位：

- **工作欄位 (Working Field)**：儲存當前指令週期內需要的資訊，例如「已按下紅色按鈕」這類計數與序列資訊。
- **情節欄位 (Episodic Field)**：儲存跨指令週期需要保留的資訊，支援跨回合 (inter-episode) 的持續性上下文 (persistent context)。

這個雙欄位設計使 HeLM 能同時處理回合內 (intra-episode) 與跨回合的非馬可夫任務。

#### 實驗數據解讀

**任務設計的全面性**

實驗涵蓋 10 個非馬可夫真實世界任務，共 56 個變體，其中包含 5 個新提出的跨回合任務。這種任務設計具有以下特點：

- **多樣性**：涵蓋計數任務（如「依序按下紅綠藍按鈕」）、空間記憶任務（如「擦拭窗戶的不同區域」）、以及序列任務。
- **難度梯度**：從簡單的回合內非馬可夫任務到需要跨回合持續性的複雜任務。
- **真實性**：所有任務均在真實世界中執行，而非模擬環境，這對實際部署具有重要意義。

**關鍵性能指標**

1. **回合內成功率提升 12.8 百分點**：相對於最強基準方法 (strongest baseline)，這個提升幅度在機器人操作領域屬於顯著改善。考慮到基準方法本身已包含記憶增強機制，這個差距凸顯了顯式語言記憶相對於潛在表示 (latent representation) 的優勢。

#### 與現有研究的比較

**與 Inner Monologue [7] 的關係**

Inner Monologue 透過提供語言反饋（如成功信號、場景描述）來支援閉環重規劃 (closed-loop replanning)。HeLM 與其的關鍵區別在於：

- Inner Monologue 的語言是「外部反饋」，由環境或人類提供
- HeLM 的語言記憶是「內部狀態」，由系統自主維護
- HeLM 顯式追蹤任務歷史，而 Inner Monologue 主要關注當前狀態評估

**與 MEM [27] 的關係**

MEM 結合了短時程視覺上下文與長時程文本記憶。HeLM 與其的差異在於：

- MEM 的記憶更新是連續的，而 HeLM 採用事件觸發機制
- HeLM 將事件偵測與記憶更新解耦，使每個模組可獨立優化
- HeLM 進一步探索了跨回合持續性，這是 MEM 未涉及的維度

**與潛在記憶方法的比較**

基於潛在嵌入 (latent embedding) 的方法（如 [10, 11, 12]）雖然有效，但存在兩個根本限制：

1. **可解釋性不足**：潛在表示難以直接解讀，使得失敗分析困難
2. **資訊密度不確定**：無法保證潛在向量保留了所有任務相關資訊（如精確計數）

HeLM 的顯式語言記憶直接解決了這些問題，但也帶來了新的挑戰：語言生成可能引入錯誤，且依賴 VLM 的語言理解能力。

**與視覺歷史方法的比較**

堆疊幀 (frame stacking) 或關鍵幀方法（如 [13, 14]）保留了豐富的視覺資訊，但計算成本隨時間線性增長。HeLM 的語言記憶在長時程下展現出明顯的效率優勢，這對於實際部署至關重要。

**現有方法的侷限性**

HeLM 論文中明確指出了現有 VLA 架構的結構性限制：馬可夫假設導致非馬可夫環境下的系統性失敗。這不僅是性能問題，更是架構設計的根本缺陷。HeLM 透過階層式設計從根本上解決了這個問題。

## 潛在風險與注意事項

**事件偵測漏報或誤報**
若事件偵測器漏報關鍵事件（例如未偵測到「按鈕已按下」），語言記憶將永遠停留在錯誤狀態，導致任務失敗。**緩解方式**：為關鍵事件加入「超時強制更新」機制，或在 LLP 動作空間異常時觸發 HLP 重新檢視。

**語言記憶累積雜訊**
隨著任務進行，記憶長度增加，HLP 可能被過時或冗餘資訊干擾。**緩解方式**：設計記憶摘要（summarization）機制，定期將舊記憶壓縮為更高層次的陳述。

**跨回合記憶的隱私與安全**
情節記憶（episodic memory）若包含使用者個資或敏感場景資訊，需注意儲存安全與存取權限。**緩解方式**：在記憶寫入前進行脫敏處理，並設計明確的記憶清除介面。

**HLP 與 LLP 同步延遲**
事件發生到 HLP 完成記憶更新之間存在延遲，若 LLP 在此期間執行錯誤動作，可能導致狀態不一致。**緩解方式**：在事件觸發瞬間暫停 LLP 動作，或設計 LLP 的「等待指令」模式。

**評估偏差**
論文的 56 個任務變體主要由作者設計，可能存在分布偏差。**緩解方式**：在自家場域中額外收集「未見過的任務變體」進行壓力測試，特別是組合泛化（compositional generalization）場景。

**給 AI 工程師**：重點閱讀第 2 節（Related Work）以了解 HeLM 與 Inner Monologue、MEM 等方法的差異，並仔細研究論文中關於「factorized event detection」與「event-triggered memory updates」的實作細節。建議直接閱讀程式碼（若公開）以掌握 HLP/LLP 的介面設計與 prompt 模板。

**給研究人員**：本論文在「inter-episode persistence」這個新軸向上有明確貢獻，建議從這個角度切入，思考是否能延伸至多代理人、長時程對話機器人、或終身學習（lifelong learning）等場景。論文的失敗分析（failure analysis）章節也值得仔細研讀，可能蘊含未來改進方向。

**給產品經理**：聚焦於「效率數字」（4.5× 記憶節省、2.5× 速度提升）與「可解釋性」這兩個產品價值點。HeLM 的語言記憶讓終端使用者能理解機器人「在想什麼」，這對信任建立與除錯成本有直接影響。評估自家產品中的多步驟任務是否屬於非馬可夫性質，以判斷 HeLM 是否值得導入。
