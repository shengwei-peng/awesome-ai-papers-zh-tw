## 摘要翻譯

在實體世界（real world）中實現靈巧機器人操作（dexterous robotic manipulation）高度依賴人工監督（human supervision）與演算法工程（algorithm engineering），這成為追求通用物理智能（general physical intelligence）的核心瓶頸。儘管新興的編程智能體（coding agents）能夠生成程式碼以自動化演算法搜尋，其成功仍大多侷限於數位環境（digital environments）。我們推測，要自動化機器人研究，所缺乏的抽象概念是一個可重複的實體世界策略改進（policy improvement）回饋迴路（feedback loop）：場景重置（reset the scene）、執行策略（execute a policy）、結果驗證（verify the outcome），以及為下一次迭代（iteration）進行精煉（refine）。為了彌補這一缺口，我們提出 ENPIRE，一個用於編程智能體（coding agents）的駕馭框架（harness framework），它以四個核心模組具現化這個實體回饋流程：環境模組（Environment module, EN），負責自動重置（automatic reset）與驗證（verification）；策略改進模組（Policy Improvement module, PI），啟動策略精煉（policy refinement）；Rollout 模組（Rollout module, R），透過一台或多台實體機器人（physical robots）平行運作來評估策略；以及演化模組（Evolution module, E），使編程智能體得以分析日誌（logs）、查閱文獻（consult literature）、改進訓練基礎設施（training infrastructure）與演算法程式碼，以處理失效模式（failure modes）。這個閉環系統（closed-loop system）將實體世界操作學習轉化為可控最佳化程序（controllable optimization procedure），在減少人工投入的同時，允許針對訓練配方（training recipe）與智能體變體（agent variants）進行公平的消融實驗（ablations）。在 ENPIRE 的驅動下，前沿編程智能體（frontier coding agents）能夠自主訓練策略，在具挑戰性的靈巧操作任務上達到 99% 的成功率，例如整理插銷盒（organizing a pin box）、緊固束線帶（fastening a zip tie）與工具使用（tool use）；當我們將智能體團隊部署於機器人艦隊（robot fleet）時，這一過程更能進一步加速。我們的結果顯示了一條實用且可擴展的途徑，以部署編程智能體來自主推進實體世界中的機器人技術。

### 核心貢獻（3～5點）
- 提出 ENPIRE 駕馭框架，以環境（EN）、策略改進（PI）、Rollout（R）與演化（E）四大模組建立實體世界機器人策略自改進的閉環系統，將真實世界操作學習轉化為可控最佳化程序。
- 實現自動化策略精煉：編程智能體可自主分析日誌、查閱文獻並改進訓練基礎設施與演算法程式碼，顯著減少人工監督與演算法工程的需求。
- 在高難度靈巧操作任務（如整理插銷盒、緊固束線帶與工具使用）上達到 99% 成功率，驗證框架於真實世界的有效性。
- 透過機器人艦隊與多智能體協作顯著加速訓練流程，展現邁向通用物理智能的實用且可擴展之路徑。

### 適合對象
機器人學、強化學習與人工智慧領域的研究者與工程師，特別是致力於實體世界機器人學習、自動化機器人研究流程，以及欲將編程智能體或大型語言模型應用於物理系統之學者與開發者。

## 深度分析

#### 方法論解析

ENPIRE 的核心貢獻在於提出一個 harness framework（駕馭框架），將傳統依賴 human supervision（人工監督）與 algorithm engineering（演算法工程）的實體機器人學習，轉化為可由 coding agents（編程智能體）自主管理的 controllable optimization procedure（可控最佳化程序）。其方法論可分解為兩個階段與四個核心模組。

首先，第一階段為 EN（Environment module（環境模組））建構期。此階段的目標是建立可重複的 physical feedback loop（實體回饋迴路）所需的基礎設施。coding agents 透過 tool calling（工具呼叫）與人類提供的高階回饋，自動生成並優化 env.py 與相關的 procedural tool calls（程序性工具呼叫）。這些程式碼定義了 safety boundaries（安全邊界）、automatic reset（自動重置）機制與 outcome verification（結果驗證）邏輯。一旦完成，這些介面即成為 immutable APIs（不可變應用程式介面），在後續實驗中重複使用。此階段雖需一次性 human feedback（人工回饋）投入，但攤提後可大幅降低後續干預需求。

第二階段為 PIRE（Policy Improvement module（策略改進模組）、Rollout module（Rollout 模組）、Evolution module（演化模組））自主運作期。在此階段，系統進入 fully autonomous autoresearch（完全自主的自動化研究）模式：coding agents 依據 real-world feedback（真實世界回饋）與 reward signals（獎勵訊號），獨立探索並優化多樣化的 training recipes（訓練配方）。具體而言，PI 模組負責啟動 policy refinement（策略精煉），支援包括 heuristic learning（啟發式學習）、behavior cloning（行為複製, BC）、offline reinforcement learning（離線強化學習）、online reinforcement learning（線上強化學習）與 Off2On RL（Off2On 強化學習）等多種 PI regimes（PI 機制）。R 模組則將訓練好的策略部署至 single or multiple physical robots（單一或多個實體機器人）進行 parallel evaluation（平行評估），並回傳 logs（日誌）。最後，E 模組中的 coding agents 分析這些日誌、查閱 literature（文獻）、診斷 failure modes（失效模式），並進一步改進 training infrastructure（訓練基礎設施）與 algorithm code（演算法程式碼）。

為了規模化，ENPIRE 引入 evolutionarily selection（演化式選擇）機制。系統可派遣 decentralized team of agents（去中心化智能體團隊）在 robot fleet（機器人艦隊）上 asynchronous（非同步地）測試不同假說，並依據平均成功率決定保留或放棄特定訓練配方。這種設計不僅加速收斂，也允許進行 fair ablations（公平消融實驗）與 agent variants（智能體變體）的系統性比較，最終將 real-world manipulation learning（真實世界操作學習）轉變為標準化的最佳化流程。

#### 實驗數據解讀

論文在多項 dexterous manipulation（靈巧操作）任務上驗證 ENPIRE 的有效性，包括 PushT（PushT 任務）、organizing pins into a pin box（將插銷整理至插銷盒）、using a cutter to cut a zip tie（使用切割器切割束線帶）、GPU insertion（GPU 插入）與 pin insertion（插銷插入）。實驗結果顯示，frontier coding agents（前沿編程智能體）在 ENPIRE 驅動下可自主開發策略，達到 99% success rate（成功率）。特別值得注意的是，在 pin insertion 任務中，策略收斂至 100% 成功率，且收斂速度超越 frontier human-in-the-loop method（前沿人工介入方法）［文獻 48］。

圖 2 的 hill-climb timeline（爬山時間軸）揭示了策略改進的細部動態。從初始 baseline（基線）出發，系統透過一系列漸進式調校逐步提升表現：引入 BC regularization（BC 正則化）帶來 +10.8 percentage points（pp）的顯著提升；調整 BC term weight（BC 項權重）貢獻 +0.4 pp；將 batch size（批次大小）從 1024 調降至 512 帶來 +1.3 pp；加入 Online RL mix（線上強化學習混合）與 controller compensation（控制器補償）分別貢獻 +3.8 pp 與 +0.9 pp。這些數據表明，coding agents 具備細粒度診斷與微調能力，而非僅進行粗淺的超參數搜尋。

在規模化實驗方面，研究團隊部署了由八台 bimanual YAM robot stations（雙臂 YAM 機器人工作站）組成的 robot fleet（機器人艦隊）。為量化 multi-agent physical auto research（多智能體實體自動化研究）的效率，論文提出兩項新指標：MRU（Mean Robot Utilization（平均機器人利用率））與 MTU（Mean Token Utilization（平均 Token 利用率））。前者衡量實體硬體的時間利用率，後者評估語言模型 token 的消耗效率。初步結果顯示，隨著平行運算規模擴大，整體研究吞吐量顯著提升，暗示了未來大規模部署的可能性。此外，論文亦在 RoboCasa（RoboCasa 模擬環境）中提供 simulation results（模擬結果），作為實體實驗的輔助驗證。

#### 與現有研究的比較

與現有文獻相比，ENPIRE 的差異化定位十分明確。傳統的 dexterous robotic manipulation（靈巧機器人操作）研究長期受制於 human supervision（人工監督）與 algorithmic engineering（演算法工程），研究人員必須全程參與 data collection（資料收集）、scene reset（場景重置）與 algorithm adjustment（演算法調整）的生命週期。ENPIRE 透過自動化的 environment construction（環境建構）與 closed-loop verification（閉環驗證），將人類角色從「全程看管者」轉變為「一次性規範提供者」，從而突破了這一瓶頸。

相較於近期在 digital environments（數位環境）中表現優異的 coding agents（編程智能體），ENPIRE 補足了進入 physical world（實體世界）的關鍵 abstraction（抽象層）——即可重複的實體回饋迴路。過往這類智能體僅能在虛擬空間中進行 algorithm search（演算法搜尋），而 ENPIRE 的 four core modules（四個核心模組）使其得以在真實硬體上執行假說驗證。此外，不同於單一機器人平台的自動化研究，ENPIRE 的 decentralized multi-agent（去中心化多智能體）與 evolutionary hypothesis selection（演化式假說選擇）機制，允許在 robot fleet（機器人艦隊）上進行真正的 parallelized autoresearch（平行化自動化研究）。

然而，本研究仍存在若干限制。首先，EN 階段仍需人類提供初始回饋以建構 env.py，尚未達到完全零樣本啟動的 general physical intelligence（通用物理智能）。其次，目前的 tool APIs（工具 API）與驗證邏輯具有任務特定性，跨任務的自動遷移能力仍屬初步階段。最後，實驗依賴特定型號的雙臂機器人平台與客製化的安全邊界，硬體門檻限制了方法在異質機器人上的即插即用性。

#### 可重現性評估

就可重現性而言，論文指出專案網站為 research.nvidia.com/labs/gear/enpire，但在提供的文本中並未明確聲明是否釋出 open-source code（開源程式碼）、datasets（資料集）或 model weights（模型權重）。這對於希望複現結果的研究社群構成不確定性。

硬體層面的 reproducibility barrier（可重現性障礙）尤為顯著。實驗核心仰賴八台 bimanual YAM robot stations（雙臂 YAM 機器人工作站）組成的機器人艦隊，這類配置涉及高昂的資本支出與維護成本，一般學術實驗室難以輕易複製。此外，EN 階段的 one-time setup cost（一次性設定成本）雖然概念上可攤提，但實際建構 automatic reset（自動重置）與 verification（驗證）機制仍需精密的系統整合工程。

在軟體層面，雖然 RoboCasa（RoboCasa 模擬環境）的 simulation results（模擬結果）提供了部分可重現的基準，但真實世界的 stochasticity（隨機性）、感測器雜訊與硬體差異意味著模擬環境無法完全捕捉實體部署的複雜度。為提升可重現性，建議未來釋出 env.py 的 template（模板）、agent prompts（智能體提示詞）以及詳細的 training recipes（訓練配方），使社群至少能在軟體邏輯層面驗證方法論。

#### 未來研究方向

展望未來，ENPIRE 為 physical autoresearch（實體自動化研究）開啟了多條值得探索的路徑。

第一，消除 EN 階段的人工依賴。當前仍需 human feedback（人工回饋）來初始化環境介面，未來可探索 vision-language models（視覺語言模型）或 foundation models（基礎模型）來自動推斷任務結構與 safety boundaries（安全邊界），實現真正的零樣本啟動。

第二，強化跨任務知識轉移。論文提及累積知識可轉移至 similar novel tasks（相似的新穎任務），但未來需要更系統化的 meta-learning（元學習）機制，使 coding agents 能自動識別任務間的共通結構，並遷移 tool APIs（工具 API）與 training infrastructure（訓練基礎設施）。

第三，提升資源效率。雖然 MRU（Mean Robot Utilization（平均機器人利用率））與 MTU（Mean Token Utilization（平均 Token 利用率））已提供評估基準，但未來需發展更先進的 multi-agent coordination（多智能體協調）策略，減少機器人閒置時間與語言模型 token 消耗，降低研究成本。

第四，安全與穩健性保證。目前的 safety mechanisms（安全機制）主要依賴手動設定的邊界，未來應研究自動化安全驗證與 formal guarantees（形式化保證），確保 autonomous physical experiments（自主實體實驗）不會損壞硬體或環境。

第五，深化模擬與實體的協同。可進一步利用 RoboCasa（RoboCasa 模擬環境）進行大規模的假說篩選，再透過 sim-to-real（模擬到真實）技術將最優的 training recipes（訓練配方）部署至實體艦隊，從而兼顧實驗吞吐量與真實性。

第六，擴展感知與診斷能力。整合更豐富的 perception（感知）模態（如觸覺與力回饋），使 failure mode analysis（失效模式分析）更為精細，進而提升 policy refinement（策略精煉）的品質與資料效率。

## 論文問答

**Q1：在實體世界中實現靈巧機器人操作的核心瓶頸是什麼？**
A：在實體世界中實現靈巧機器人操作的核心瓶頸，在於現有方法高度依賴人工監督與演算法工程。當我們擴大實體世界策略學習的規模時，人類必須持續在旁監督策略改進的生命週期，這種勞力密集的模式成為限制機器人快速獲得精細操作能力的主要因素。這種依賴性阻礙了通用物理智能的發展，因為它使得策略學習難以自動化且難以大規模擴展。

**Q2：為何現有的編程智能體無法直接解決實體世界的機器人操作問題？**
A：雖然新興的編程智能體在數位環境中能自動生成程式碼以搜尋演算法，但它們的成功大多僅限於虛擬空間。這些智能體缺乏一套可在實體世界中進行閉環假設驗證的環境介面，無法自動處理策略部署、場景重置與結果驗證等物理交互環節。由於缺少一個可重複的「重置→執行→驗證→精煉」回饋迴路，它們無法將程式碼生成與真實世界的物理執行緊密連結，因而難以實現實體策略的自主改進。

**Q3：為何將實體世界的回饋迴路自動化對推進機器人學至關重要？**
A：將此回饋迴路自動化，能將實體世界的操作學習轉化為一個可由智能體管理的可控最佳化程序，從而最小化人力投入。它不僅讓編程智能體能夠在無人工干預的情況下，獨立探索並最佳化多樣化的學習方法以最大化任務成功率，還允許研究者在不同的訓練配方與智能體變體之間進行公平的消融實驗。這為在真實世界中部署編程智能體以自主推進機器人技術，提供了一條實際且可擴展的路徑。

**Q4：ENPIRE 的四個核心模組分別是什麼，它們各自扮演什麼角色？**
A：ENPIRE 包含環境模組（EN）、策略改進模組（PI）、Rollout 模組（R）與演化模組（E）。環境模組負責自動場景重置與結果驗證；策略改進模組啟動策略精煉流程；Rollout 模組利用一台或多台並行運作的實體機器人評估策略表現；演化模組則讓編程智能體分析日誌、查閱文獻，並改進訓練基礎設施與演算法程式碼以解決失效模式。這四個模組共同構成了一個閉環的物理回饋常規，使編程智能體得以在無人工持續介入的情況下，管理實體世界策略最佳化的完整生命週期。

**Q5：ENPIRE 提出的兩階段實體自動化研究程序為何？其設計理念是什麼？**
A：ENPIRE 將整體流程分解為「環境建構（EN）」與「自動策略改進（PIRE）」兩個階段。在第一階段，編程智能體根據人工回饋，透過一次性的離線研究迴路來建構自動化的環境介面，包括建立安全邊界、自動重置與驗證程序，這些最終成為後續階段重複使用的固定 API。第二階段則轉為完全自主的線上自動化研究，智能體僅依據環境自動驗證訊號來精煉策略，如此設計可將一次性的人類指導成本與後續大規模自主最佳化分離，從而實現真正無人監督的策略改進。

**Q6：ENPIRE 如何實現多機器人並行擴展，並提出了哪些效率指標？**
A：為了在多機器人艦隊上擴展，ENPIRE 引入了演化式的假設選擇機制，派遣去中心化的智能體團隊在非同步狀態下測試不同訓練配方，並根據平均成功率共享或放棄想法。為了衡量此多智能體實體自動化研究的效率，作者提出了平均機器人利用率（MRU）與平均 Token 利用率（MTU）兩項關鍵指標。這些指標能夠系統性地評估物理硬體與計算資源在並行研究過程中的使用效率，為大規模自主實驗提供了可量化的評估基準。

## 實務應用指南

### 適用場景

1. **電子製造精密組裝**：例如 GPU 插槽安裝、插銷整理與束線帶緊固等靈巧操作任務。利用 ENPIRE 的自動重置與驗證機制，編程智能體可於實體產線上反覆迭代夾取與插入策略，將成功率收斂至 99% 以上，大幅減少人工示教與演算法調參成本。
2. **倉儲物流異質物品整理**：針對形狀不規則、質地各異的物件（如工具、小型零件）進行分類與包裝。透過環境模組（EN）建立自動場景重置與結果驗證，實現 24 小時無人化的策略自改進，無需人員全程旁觀。
3. **高風險或高重複性維修作業**：在需要使用特定工具（如切割器）或施力精細的場景中，由編程智能體自主探索安全且高效的操作軌跡與施力模式，降低人員暴露於危險環境的時間。
4. **多機台並行製程驗證**：於機器人艦隊上同時驗證多種訓練配方（training recipe）與演算法變體，加速新產品導入（NPI）時的製程參數收斂，並透過平均機器人利用率（MRU）與平均 Token 利用率（MTU）量化資源投入效益。

### 實作前置條件

- **資料準備**：清晰的任務定義文件、初始示範軌跡（若採用行為複製）、感測器（如相機、力覺感測器）校正參數，以及用於離線驗證的標準答案資料集或人工評分準則。
- **運算資源**：每座機器人工作站至少配置一張高階 GPU（用於策略訓練與推理）、邊緣運算單元（負責低延遲控制迴路），以及充足的 LLM API 配額（支援編程智能體進行程式生成與文獻查閱）。
- **技能需求**：機器人作業系統（如 ROS 2）整合能力、Python 程式開發經驗、基礎模仿學習或強化學習知識，以及 LLM 提示工程與工具呼叫（Tool Calling）設計經驗，以確保能正確定義 Environment 模組的 API 契約。

### 實作步驟建議

1. **環境介面建構（EN 階段）**：與編程智能體協作，將人工任務描述轉譯為 `env.py`，實作自動重置（automatic reset）、觀測提取與結果驗證（verification）函數。此階段需離線反覆測試，直到 API 行為正確且可重複，作為後續不可變的基礎建設。
2. **基線策略建立**：選擇初始策略改進模組（PI）機制（如行為複製、啟發式學習或 Off2On 強化學習），產生可執行的第一版策略，並透過 Rollout 模組（R）確認能順利驅動實體機器人完成基本動作。
3. **閉環自主迭代（PIRE 階段）**：啟動 ENPIRE 閉環系統，讓編程智能體根據實體 rollout 的獎勵訊號與日誌，自主調整訓練配方、演算法超參數或基礎設施程式碼，逐步提升任務成功率。
4. **艦隊規模化**：將系統擴展至機器人艦隊，啟用演化模組（E）非同步測試多種假設。監控 MRU 與 MTU 指標，識別並淘汰低效益的訓練配方，將運算與硬體資源集中於高潛力方向。
5. **產品化部署**：將收斂後的策略與環境 API 封裝為穩定服務，整合至工廠 MES 或倉儲管理系統。保留人工覆核閘門，僅在驗證函數或安全邊界更新時才需人工介入。

### 潛在風險與注意事項

- **實體安全與硬體保護**：自動重置與策略探索可能導致非預期碰撞，必須在 Environment 模組中設定嚴格的安全邊界（safety boundaries）與硬體急停機制，並於 EN 階段充分驗證重置腳本。
- **驗證函數的正確性**：若自動驗證邏輯存在漏洞，編程智能體將朝錯誤方向優化（例如利用視覺死角作弊）。EN 階段的離線人工驗證至關重要，建議引入多模態感測交叉確認。
- **機器人閒置與利用率**：任務重置時間過長或序列化 rollout 會嚴重壓低 MRU。應優化重置流程（如並行化夾具歸位與物件擺放），並透過機器人艦隊最大化平行執行。
- **API 成本控管**：演化模組反覆查閱文獻與生成程式碼將消耗大量 LLM Token。應設置預算上限、快取常見錯誤模式對應的修復方案，並對無法編譯或明顯低效的程式碼進行提前過濾。
- **模擬與真實落差**：雖可輔以 RoboCasa 等模擬器加速前期驗證，但最終策略收斂仍須以實體世界回饋為準。避免過度擬合模擬環境，並在轉移至真實機器人時保留探索緩衝。

### 與其他技術的整合建議

- **製造執行系統（MES）**：透過 OPC-UA 或 MQTT 將 Environment 模組對接 MES，接收工單並回報任務完成狀態，使 ENPIRE 成為全廠自動化閉環的一環。
- **數位孿生平台**：在 Isaac Sim 或 RoboCasa 中建立虛擬副本，讓編程智能體在部署至實體機器人前，先於數位環境離線驗證新演算法邏輯與重置腳本，降低硬體磨損風險。
- **視覺基礎模型**：整合 SAM3 等感知模型至 Environment 模組，自動化場景觀測與結果驗證，降低人工撰寫視覺處理程式的負擔，並提升對新物件的泛化能力。
- **多智能體協作框架**：利用 AutoGen 或 LangGraph 強化 Evolution 模組，實現多個編程智能體間的記憶共享、程式碼審查與分散式除錯，進一步提升自動化研究的產出效率。
- **雲端機器人管理**：透過 NVIDIA Isaac ROS 或雲端機器人平台統一管理艦隊的軟體更新、日誌彙集與遠端監控，確保大規模部署時的維運可控性。

### 給不同背景讀者的閱讀建議

- **初學者**：建議將 ENPIRE 理解為「一位能自己寫程式、自己動手做實驗、再根據結果改進的虛擬機器人研究員」。可從論文的圖二與真實任務範例（如整理插銷盒、切割束線帶）開始，先掌握閉環回饋與自動重置的核心概念，無需立即深究強化學習的數學推導。
- **AI 工程師**：重點關注 EN 與 PIRE 兩階段的介面設計，特別是 Environment 模組的 API 契約、編程智能體的工具呼叫（Tool Calling）實作，以及各種 PI 機制（如 Off2On RL、行為複製正則化）的切換邏輯。建議參考論文提出的 MRU 與 MTU 指標，評估自身硬體叢集的擴展瓶頸。
- **研究人員**：本文的核心貢獻在於將自動化研究（autoresearch）從數位環境延伸至實體世界，建議深入分析兩階段 autoresearch 的形式化定義，以及 Evolution 模組在機器人艦隊上的假設選擇與知識遷移機制。可進一步探索如何將此駕馭框架應用於更廣泛的具身智能（Embodied AI）與通用物理智能問題。
- **產品經理**：聚焦於「降低人工監督成本」與「可擴展性」這兩項商業價值。評估導入時應盤點現場任務的標準化程度與自動重置可行性，優先選擇高重複性、驗證標準明確的製程段（如電子零件插裝）作為概念驗證（PoC）切入點，並預留 LLM API 的營運預算。
