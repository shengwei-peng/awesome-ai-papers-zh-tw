# PaintBench：精確視覺編輯的確定性評估

**原文標題：** PaintBench: Deterministic Evaluation of Precise Visual Editing

## ⚡ TL;DR

現有多模態模型難以執行精確單一答案的視覺編輯，且現有評測依賴易偏差的評審模型。
本文提出PaintBench，以程序化生成二十種精確編輯任務，並採像素級確定性評估避免評審偏差。
實驗顯示最佳模型僅達17.1%mIoU，且分數與資料視覺化編輯任務呈強線性相關，驗證泛化能力。

## 摘要翻譯

雖然現今的多模態模型（Multimodal Models）擅長開放式視覺編輯（Open-Ended Visual Editing），但執行精確單一答案編輯（Precise Single-Answer Edits）仍是重大挑戰。為了探究這項挑戰，我們提出 PaintBench，這是一個動態可擴充基準測試（Dynamically Scalable Benchmark），針對 20 項基礎的精確視覺編輯（Precise Visual Editing）操作，分為四大類別：幾何變換（Geometric Transformation）、結構操作（Structural Manipulation）、顏色變更（Color Change）與符號推理（Symbolic Reasoning）。透過可設定複雜度（Configurable Complexity）的程序化生成（Procedural Generation），得以建立實質上無限且抗汙染（Contamination-Resistant）的評估套件（Evaluation Suite）；而確定性像素級評估（Deterministic Pixel-Level Evaluation）則消除了對易產生偏差的評審模型（Bias-Prone Judge Models）之依賴。在 11 個影像編輯模型（Image Editing Models）中，我們發現整體表現低落，目前表現最佳的業界領先模型（Industry Leader）僅達 17.1%（平均交併比（mIoU））。任務分解（Task Decomposition）揭示了特別具有挑戰性的操作類型——幾何變換（Geometric Transformation）、大多數的結構操作（Structural Manipulation）、基於公式的顏色變更（Formula-Based Color Change）——以及模型特定專長（Model-Specific Specializations）。細粒度基準診斷（Fine-Grained Benchmark Diagnostics）進一步顯示，物件數量（Object Count）、背景複雜度（Background Complexity）、色彩配置（Color Scheme）與編輯區域大小（Edit-Region Size）等場景變化（Scene Variations）會導致效能下降。為了測試 PaintBench 分數對應用任務表現的泛化（Generalization）能力，我們建立了一個針對資料視覺化編輯（Data Visualization Editing）的程序化確定性評估 TinyGrafixBench，並發現其與 PaintBench 分數具有強烈的線性相關（Linear Correlation）（決定係數 R² = 0.91，p < 0.001）。總體而言，PaintBench 為衡量與推動精確多模態視覺編輯（Precise Multimodal Visual Editing）的進展提供了嚴謹的基礎。

### 核心貢獻（3～5點）
- 提出 PaintBench，一個涵蓋幾何變換、結構操作、顏色變更與符號推理四大類別共 20 項基礎操作的動態可擴充基準測試，透過可設定複雜度的程序化生成建立實質上無限且抗汙染的評估套件。
- 採用確定性像素級評估機制，完全消除對易產生偏差之評審模型的依賴，提供嚴謹且可重現的精確視覺編輯效能衡量標準。
- 透過任務分解與細粒度基準診斷，系統性揭示各類操作難度、模型特定專長，以及物件數量、背景複雜度、色彩配置與編輯區域大小等場景變化對模型效能的影響。
- 建立資料視覺化編輯基準 TinyGrafixBench，驗證 PaintBench 分數對實際應用任務具有高度預測力（R² = 0.91，p < 0.001），證明其良好的泛化能力。

### 適合對象
從事多模態模型、影像編輯模型與電腦視覺研究的學者與工程師，特別是需要嚴謹評估框架來衡量模型在精確視覺編輯任務上之表現、診斷失效模式，以及追求可重現評估指標的研究者與開發者。

## 深度分析

#### 方法論解析

PaintBench 的核心方法論建立在「確定性評估 (deterministic evaluation)」典範之上，針對具備「精確單一答案編輯 (precise single-answer edits)」特性的視覺任務，建構可擴充且客觀的測量框架。其方法論可拆解為三個層次：任務設計、生成引擎與評估協議。

在任務設計層面，作者系統性地歸納出四大「任務類別 (task categories)」：「幾何變換 (geometric transformation)」、「結構操作 (structural manipulation)」、「顏色變更 (color change)」與「符號推理 (symbolic reasoning)」，共涵蓋 20 項基礎操作。幾何變換包含「平移 (translation)」、「旋轉 (rotation)」、「反射 (reflection)」、「縮放 (scaling)」與「錯切 (shearing)」；結構操作涵蓋「建構 (construction)」、「移除 (removal)」、「複製 (copying)」、「邊框 (border)」與「裁切 (cropping)」；顏色變更包含「重新上色 (recolor)」、「洪水填充 (flood fill)」、「混合 (blending)」[「漸層 (gradient)」] 與「點運算 (point operations)」；符號推理則包含「比較 (comparison)」、「排序 (ordering)」、「模式 (pattern)」[「計數 (counting)」] 與「圖例 (legend)」。此分類法的價值在於將「開放式視覺編輯 (open-ended visual editing)」中隱含的基礎操作顯式化，使評估能對應到具體的能力維度，而非僅得到模糊的整體偏好分數。

生成引擎採用「程序化生成 (procedural generation)」架構，透過隨機種子 (random seed) 與「可設定複雜度 (configurable complexity)」的場景參數，動態產生「輸入 (input)」影像、自然語言「指令 (instruction)」與唯一正確答案 (ground-truth answer)。這種設計使 PaintBench 具備理論上無限擴充的「評估套件 (evaluation suite)」，並具有「抗汙染 (contamination-resistant)」特性——由於測試樣本可透過未公開的種子即時生成，模型無法透過記憶訓練資料來取得不當優勢。此外，場景參數涵蓋「物件數量 (object count)」、「背景複雜度 (background complexity)」、「色彩配置 (color scheme)」與「編輯區域大小 (edit-region size)」等「視覺條件 (visual conditions)」，使基準測試同時具備細粒度診斷工具功能。

評估協議是 PaintBench 方法論最具區別性的貢獻。作者完全摒棄「易產生偏差的評審模型 (bias-prone judge models)」與人類主觀判斷，改採「確定性像素級評估 (deterministic pixel-level evaluation)」。具體而言，評分流程先計算「色彩距離 (color distance)」——結合感知色彩相似性來衡量像素級色差；接著計算「每題分數 (per-problem score)」即「IoU@t」（閾值 t 之「交併比 (Intersection over Union, IoU)」），同時考量編輯品質與保留品質（檢驗「背景像素 (background pixels)」與「非背景像素 (non-background pixels)」是否被意外更動）；最終以「平均交併比 (mIoU, mean Intersection over Union)」作為「總結指標 (summary metric)」。這種設計類比於 HumanEval 對程式碼生成的執行驗證，強調「執行正確性」而非「表面合理性」。

為驗證基準分數對應用任務的「泛化 (generalization)」能力，作者進一步提出 TinyGrafixBench，將相同的程序化生成與確定性評估哲學應用於「資料視覺化編輯 (data visualization editing)」，並同樣採用像素級比對確保評估邏輯的一致性。

#### 實驗數據解讀

實驗涵蓋 11 個「影像編輯模型 (image editing models)」，橫跨原生多模態生成器 (native multimodal generators)、擴散編輯器 (diffusion editors) 與流匹配編輯器 (flow-matching editors)。整體結果呈現嚴峻的能力缺口：即使目前「業界領先模型 (industry leader)」的 mIoU 也僅達 17.1%，顯示「精確視覺編輯 (precise visual editing)」仍是未解難題。

從「操作難度 (operation difficulty)」的「任務分解 (task decomposition)」觀察，「幾何變換 (geometric transformation)」、多數結構操作（如「建構 (construction)」、「複製 (copying)」、「邊框 (border)」），以及「基於公式的顏色變更 (formula-based color change)」（如「漸層 (gradient)」、「點運算 (point operations)」）對所有模型均構成系統性挑戰。相對地，「移除 (removal)」與單色「重新上色 (recolor)」等操作較為可行，但仍遠未達人類水準。值得注意的是，模型呈現顯著的「模型特定專長 (model-specific specializations)」：某些模型在特定操作上表現突出，卻在整體排名上未必領先，暗示現有模型並非透過通用原理解決問題，而可能依賴特定訓練偏差或架構歸納偏置。

「細粒度基準診斷 (fine-grained benchmark diagnostics)」揭示模型對「場景變化 (scene variations)」的「脆弱性 (brittleness)」。當場景出現條紋背景（「背景複雜度 (background complexity)」升高）、高「物件數量 (object count)」、非標準「色彩配置 (color scheme)」或小「編輯區域 (edit-regions)」時，模型表現顯著退化。這表示模型的「理解」並非基於穩健的幾何或語義抽象，而對低階視覺統計特徵過度敏感。

作者進一步歸納出「四大常見失效模式 (four common failure modes)」，其中「過度編輯 (over-edit)」尤為關鍵：模型經常不僅修改「目標區域 (target region)」，還波及「背景像素 (background pixels)」或「非背景像素 (non-background pixels)」，導致 IoU 急遽下降。這種「多做多錯」的傾向，在擴散模型與流匹配模型中可能源於去噪過程的全域性擴散特性，或指令跟隨機制對空間定位的解析度不足。

在泛化驗證方面，TinyGrafixBench 與 PaintBench 的分數呈現「強線性相關 (strong linear correlation)」（決定係數 R² = 0.91，p 值 < 0.001）。此結果具有雙重意涵：其一，PaintBench 測量的並非僅是「合成形狀 (synthetic shapes)」上的「玩具能力」，而是能預測實際資料視覺化編輯表現的基礎能力；其二，約 9% 的未解釋變異暗示真實應用場景仍存在額外挑戰（如文字渲染、圖表語義），值得後續探究。

#### 與現有研究的比較

現有「影像編輯基準 (image editing benchmarks)」主要依賴兩類評估典範：人類判斷，或透過「視覺語言模型 (vision-language models)」與感知指標（如 SSIM、LPIPS、FID）進行模型評分。這些方法適用於「開放式視覺編輯 (open-ended visual editing)」（如「讓天空更藍」），因為此類任務存在無限多組有效輸出，評估本質上接近偏好排序 (preference scoring) 而非正確性驗證。然而，針對具備唯一正解的精確編輯任務，依賴學習式評審模型 (learned judge models) 會引入系統性偏差，且無法解析像素級誤差。

PaintBench 的突破性在於將評估邏輯從「判斷」轉向「驗證」。透過「確定性像素級評估 (deterministic pixel-level evaluation)」，它消除了評審模型本身的偏見風險，並提供可重複、可解釋的數值指標。這與 HumanEval 在程式碼生成領域的革命性貢獻類比：不再由模型判斷程式碼「看起來對不對」，而是直接執行測試案例驗證輸出正確性。

相較於近期針對複雜編輯的基準，PaintBench 選擇聚焦於基礎操作的原子能力。這種「簡約但嚴格」的設計哲學，使其能作為診斷工具，精準定位模型在特定操作類型上的缺陷，而非僅提供模糊的整體分數。此外，PaintBench 明確將評估對象限定於「原生像素空間 (native pixel-space)」的影像編輯模型，排除「代理式 (agentic)」或「程式化 (programmatic)」方法（即呼叫繪圖引擎執行操作），從而測量模型本身的多模態理解與生成能力，而非外部工具的組合能力。

然而，此定位也帶來限制。PaintBench 目前以「合成形狀 (synthetic shapes)」為主要視覺素材，雖然 TinyGrafixBench 初步驗證了向資料視覺化領域的泛化，但對於自然影像（如照片級人像、複雜場景）中的精確編輯，其預測效度仍有待更多實證。此外，確定性評估雖然嚴格，但也意味著無法直接評估那些「語義正確但像素略有偏差」的合理輸出，可能對某些具備輕微空間容錯性的應用場景過於嚴苛。

#### 可重現性評估

PaintBench 在可重現性方面具備顯著優勢，其核心來自「程序化生成 (procedural generation)」的設計。由於每個測試樣本皆由隨機種子 (random seed) 與明確的場景參數決定，研究者只要取得相同的種子與參數配置，即可完全重現「輸入 (input)」影像、「指令 (instruction)」與正確答案 (ground-truth answer)。這種「以程式碼為資料」的典範，遠比靜態資料集更能抵抗資料遺失或版本差異。

基準測試包含 1,920 題的固定測試集，同時支援動態擴充。「抗汙染 (contamination-resistant)」特性進一步強化了可重現性的價值：即使模型開發者使用 PaintBench 的公開生成邏輯進行訓練，只要評估時採用未公開的新種子，便能確保測試結果的有效性。這對於當前多模態模型動輒在網路規模資料上預訓練的環境尤為重要。

評估流程本身亦具高度可重現性。「確定性像素級評估 (deterministic pixel-level evaluation)」完全排除主觀判斷，「IoU@t」與「mIoU」的計算僅依賴 ground-truth 與模型輸出的像素比對，不同實驗室執行相同評估腳本將得到完全一致的分數。這解決了現有基準中常見的評審模型版本差異、提示工程 (prompt engineering) 變異或人類評分者間信度問題。

不過，論文摘要與內文未明確提及原始碼、模型權重 (model weights) 或完整生成腳本是否完全開源。雖然方法論描述足以支持獨立重現，但實際的開源釋出狀態（如 GitHub 倉庫、API 文件）將決定社群能否無摩擦地採用此基準。理想情況下，作者應公開生成引擎的參數空間定義、「色彩距離 (color distance)」的實作細節，以及 11 個受測模型的確切推論配置，以達成最嚴格的科學可重現性標準。

#### 未來研究方向

基於 PaintBench 揭示的能力缺口與方法論框架，未來研究可沿以下方向展開：

第一，基礎操作能力的針對性強化。「幾何變換 (geometric transformation)」與「結構操作 (structural manipulation)」的普遍低分顯示，現有模型缺乏穩健的空間推理與幾何執行機制。未來可探索結合顯式幾何引擎（如可微分渲染 differentiable rendering）與生成模型的混合架構，或在擴散模型中注入顯式座標條件化 (coordinate conditioning) 與變換矩陣控制，以提升像素級定位精度。

第二，場景魯棒性 (robustness to scene variations) 的系統性改善。當前模型對條紋背景、高物件數量與非標準色彩配置的敏感度，暗示其依賴淺層統計捷徑而非抽象規則。未來研究可利用 PaintBench 的「可設定複雜度 (configurable complexity)」，建構漸進式訓練課程 (curriculum learning)，或開發專門的資料增強策略，強化模型在視覺干擾下的操作穩定性。

第三，「過度編輯 (over-edit)」抑制機制。模型傾向於修改「目標區域 (target region)」以外的像素，可能源於擴散過程中的全域去噪動態。研究者可探索區域遮罩約束 (regional masking constraints)、潛在空間中的局部編輯潛碼 (local edit latent codes)，或後處理階段的差分比對與修復管線，以實現「僅修改必要像素」的精確控制。

第四，基準測試的領域擴展。TinyGrafixBench 已驗證「資料視覺化編輯 (data visualization editing)」的泛化潛力。未來可將相同哲學延伸至科學圖表編輯、UI/UX 設計調整、衛星影像精確標註，或醫學影像的病灶區域修改等應用場景，建立領域專屬的確定性評估套件。

第五，PaintBench 作為診斷工具 (diagnostic instrument) 的深化應用。由於基準支援針對特定操作或視覺條件生成客製化測試集，未來模型開發者可將其整合至持續整合 (CI) 流程，作為模型迭代時的迴歸測試 (regression testing)。此外，結合錯誤分析 (error analysis) 與模型內部啟動圖 (activation mapping)，可進一步解構模型在執行精確編輯時的神經機制。

第六，評估指標的細緻化。雖然 mIoU 提供嚴格的整體衡量，但未來可發展分層指標，例如區分「語義正確但像素偏移」與「完全錯誤」的容錯評分，或針對邊緣銳利度、色彩準確度與空間定位分別設計子指標，使評估更能貼近不同應用的實際需求。

## 論文問答

**Q1：PaintBench 旨在解決的核心問題是什麼？**
A：PaintBench 旨在解決現有多模態模型在執行「精確單一答案視覺編輯」時表現不佳的問題。雖然當前模型在開放式視覺編輯任務上已相當熟練，但面對具有唯一正確答案的操作——例如將形狀精確平移特定像素、以指定色碼重新上色，或執行特定幾何變換——它們仍然難以準確完成。這項缺陷至關重要，因為許多實際應用（如技術圖表、專業設計與資料視覺化）要求的並非「看起來合理」的結果，而是像素級的正確性。

**Q2：為何現有的基準測試與評估方法無法充分衡量精確視覺編輯能力？**
A：現有的影像編輯基準大多依賴人類判斷，或透過視覺語言模型等易產生偏差的評審模型，以及 SSIM、LPIPS、FID 等感知指標進行評分。這些方法適用於沒有單一正確答案的開放式任務（例如「讓天空更藍」），但對於具有唯一正確答案的精確任務卻顯得力不從心。此外，基於模型的評審方式潛藏偏見，且無法進行像素級的正確性驗證，因而難以客觀衡量編輯結果與目標之間的細微偏差。

**Q3：確定性評估對於推動精確視覺編輯能力為何如此重要？**
A：確定性評估能夠排除人類或模型評審所帶來的主觀性與偏差，提供客觀且可重現的正確性度量。透過將輸出結果與唯一正確答案進行像素級的直接比對，研究人員得以嚴格量化編輯區域的準確度，以及應保留區域是否遭到意外更動。這種嚴謹的評估方式對於需要絕對精確的應用場景不可或缺，也為領域內的技術進步奠定了可量測的基礎。

**Q4：PaintBench 在基準建構上的核心方法是什麼？**
A：PaintBench 採用程序化生成（procedural generation）方法，以隨機種子與可設定的參數配置來產生輸入影像、自然語言指令以及唯一的正確答案。這種設計使基準測試具備動態可擴充性，理論上能生成近乎無限的題目，同時具備抗汙染特性，避免模型因訓練資料重疊而獲得不實高分。由於整個流程是確定性的，系統得以自動執行像素級評估，無需依賴任何外部評審模型。

**Q5：相較於以往的視覺編輯基準，PaintBench 的關鍵創新為何？**
A：其關鍵創新在於提出了一套無需評審模型的確定性像素級評估協定，結合感知色彩相似度的 IoU@t 與 mIoU 指標，同時兼顧「編輯品質」與「保留品質」。此外，透過可設定複雜度的程序化生成框架，PaintBench 不僅是靜態的能力快照，更能作為細粒度診斷工具，針對特定操作類型或視覺條件生成客製化測試集。這種設計從根本上將評估典範從「偏好打分」轉向「正確性驗證」，填補了精確視覺編輯領域的評估空白。

**Q6：作者在任務類別與評估指標上做出了哪些設計選擇？**
A：基準涵蓋四大任務類別——幾何變換、結構操作、顏色變更與符號推理——共計 20 種基本操作。在評估指標方面，作者設計了考量色彩距離閾值的像素級評估協定，使用 IoU@t 來容忍符合人眼感知的細微色差，並以平均交併比（mIoU）作為總結指標。值得注意的是，本研究刻意將評估對象聚焦於原生像素空間的影像編輯模型，而非將操作委派給傳統點陣引擎的代理式或程式化方法。

**Q7：論文中進行了哪些主要的基準實驗？**
A：作者針對 11 種影像編輯模型（涵蓋原生多模態生成器、擴散編輯器與流匹配編輯器）進行系統性評估，測試集包含 1,920 道 PaintBench 題目。為了驗證泛化性，研究團隊進一步建構了 TinyGrafixBench，將同樣的程序化、確定性評估哲學應用於資料視覺化編輯任務。此外，實驗亦透過調整場景參數（如物件數量、背景複雜度、色彩配置與編輯區域大小），進行控制變因的場景變化分析。

**Q8：關於模型表現與任務難度，研究有哪些關鍵發現？**
A：即使是目前業界領先的模型，其 mIoU 也僅達 17.1%，顯示精確視覺編輯對現有模型而言仍是重大挑戰。任務分解結果顯示，幾何變換、基於公式的顏色變更以及大多數結構操作任務對所有模型都一致地困難；相對而言，移除與單色操作較為可行，但仍遠未解決。此外，不同模型在個別操作上呈現出顯著的模型特定專長，這些專長往往與其整體排名不一致。

**Q9：消融實驗與診斷分析揭示了模型穩健性的哪些問題？**
A：細粒度基準診斷顯示，當場景出現條紋背景、高物件數量、非標準色彩配置或較小編輯區域時，模型表現會顯著下降。分析也歸納出四種常見的失效模式，並發現模型經常相對於目標區域進行過度編輯，連帶改動了不應變動的背景像素。這些結果共同指出，當前系統對視覺脈絡變化相當脆弱，且缺乏嚴格遵循精確空間與色彩指令所需的細粒度控制能力。

**Q10：哪些實際應用場景最能受惠於 PaintBench 所衡量的精確編輯能力？**
A：需要像素級準確度的場景最能受惠，例如技術插圖、專業平面設計與資料視覺化編輯。TinyGrafixBench 的設計即證明了相同的基礎操作能力對於修改圖表與圖形同樣至關重要。在專業工作流程中，即使是色值的細微偏差或物件位置的些許錯位，都可能導致輸出結果無法使用，因此 PaintBench 所測試的精確度具有直接的實務價值。

**Q11：產品團隊與業界從業人員應如何解讀基準結果，以應用於真實模型部署？**
A：產品團隊應認知到，即便是目前最頂尖的模型，在精確編輯上的得分仍然非常低，這意味著在高風險的精確工作流程中部署這些模型時，仍需大量人工監督或採用人機協作模式。基準結果清楚揭示，現有模型在精確色彩匹配、幾何對齊以及嚴格保留未編輯區域方面尚不可靠。因此，從業人員應將 PaintBench 視為診斷工具，在將模型整合至編輯產品前，先識別其在特定操作上的弱點。

**Q12：PaintBench 對多模態視覺編輯研究領域具有什麼更廣泛的影響？**
A：PaintBench 為精確多模態視覺編輯建立了嚴謹的確定性評估基礎，將評估典範從主觀的偏好打分轉向客觀的正確性驗證。透過提供可擴充且抗汙染的標準化測試套件，它使社群能夠公平比較不同模型，並系統性地識別根本性的能力缺口。而 PaintBench 與 TinyGrafixBench 之間的強線性相關（R² = 0.91, p < 0.001）則表明，提升 PaintBench 分數很可能會直接轉化為結構化視覺領域的實務進展。

**Q13：PaintBench 框架有哪些已知的限制？**
A：PaintBench 目前主要聚焦於合成形狀與受控的程序化場景，這可能無法完全涵蓋自然影像編輯中的所有細微差異。雖然 TinyGrafixBench 已初步證明其泛化至資料視覺化的能力，但所測試的應用領域範圍仍然有限。此外，本基準專注於評估原生像素空間模型，並未直接評估那些透過傳統圖形引擎執行編輯的代理式或程式化方法，這些方法在精確度上可能具有不同優勢。

**Q14：評估中凸顯了哪些失效案例與脆弱性因素？**
A：研究歸納了四種常見的失效模式，並特別指出模型傾向於過度編輯，導致目標區域以外的背景像素或非相關區域遭到意外更動。模型表現對場景變化顯得相當脆弱，在背景複雜度增加、物件數量變多、色彩配置非標準或編輯區域較小時，效能均會顯著下滑。這些發現顯示，當前模型缺乏穩健的空間定位能力與細粒度控制機制，難以可靠地執行精確編輯指令。

**Q15：論文對於改善精確視覺編輯提出了哪些未來方向？**
A：未來研究應優先針對幾何變換、基於公式的顏色變更與結構操作等持續困難的任務類型，開發更強大的模型架構。研究者可以利用 PaintBench 可設定的程序化生成器，建構針對特定能力（如小區域編輯或非標準色彩配置）的壓力測試與訓練資料集。長遠而言，推動精確視覺編輯的進展將需要能結合高層語意理解與嚴格像素級執行保真度的模型，特別是在指令接地與區域保留機制上尋求突破。

## 實務應用指南

### 適用場景

1. **多模態影像編輯模型的內部驗收與回歸測試**：產品團隊在迭代 instruction-tuned diffusion 或 flow-matching 編輯器時，可將 PaintBench 作為自動化回歸測試套件，針對平移、旋轉、重新上色、洪水填充等 20 項精確操作，驗證新版本是否退化，無需耗費人力進行主觀評分。
2. **設計工具與低程式碼平台的像素級正確性品質閘道**：Canva、Figma 外掛或自動化設計工具在輸出前，可利用 PaintBench 的確定性評估邏輯，確認模型僅修改目標區域、保留非背景像素，避免「過度編輯」導致使用者素材毀損。
3. **資料視覺化與報表自動化系統的編輯管線驗證**：參考 TinyGrafixBench 方法論，針對企業內部圖表生成流程建立評估套件，驗證 AI 在調整圖例、漸層、計數符號或排序時，是否精確對應資料值與視覺規範。
4. **AI 輔助醫學影像或衛星影像標註後處理**：在需要嚴格像素級正確性的領域（如腫瘤輪廓平移、建築物邊界調整），借用 PaintBench 的 IoU@t 與色彩距離機制，建立領域專屬的確定性評估流程，確保編輯誤差在臨床或測繪容忍範圍內。
5. **模型能力診斷與選型決策**：企業評估要接入哪家業界領先模型作為影像編輯後端時，可利用可設定複雜度的程序化題組，針對自身業務常見的高物件數量、條紋背景或特殊色彩配置進行壓力測試，避免僅憑示範案例做決策。

### 實作前置條件

- **資料**：無需外部資料集，但需準備隨機種子庫與場景參數配置表（涵蓋物件數量、背景複雜度、色彩配置、編輯區域大小）。若要做領域適配（如 UI 設計稿、醫學影像），需額外準備領域 base image 與對應的 ground-truth 生成邏輯。
- **運算**：推論階段需 GPU 執行被測影像編輯模型；評估階段僅需 CPU 與足夠記憶體進行像素級比對與 IoU 計算。建議具備批次處理能力，以應對動態可擴充基準測試的大規模題組。
- **技能**：熟悉 Python 與 Pillow／OpenCV；理解交併比（IoU）、mIoU 與色彩空間距離（如 RGB 歐氏距離或 CIEDE2000）；具備多模態模型 API 整合或本地部署經驗；若擴充 TinyGrafixBench，需了解 Matplotlib／Plotly 等資料視覺化工具的物件模型。

### 實作步驟建議

1. **建立種子庫與參數配置**：依據業務場景從 20 項操作中選取子集，設定場景變因的權重分布。例如，若產品常見複雜背景，則提高條紋背景與高物件數量的抽樣比例。
2. **自動化題目生成**：撰寫程序化生成腳本，輸入種子與參數，產出（輸入影像、自然語言指令、唯一正確答案）三元組。確保 ground truth 為像素級精確，且具備抗汙染特性。
3. **模型推論與輸出蒐集**：對被測模型進行批次推論，記錄輸出影像與推論延遲。建議同時記錄模型的拒絕回應或無效輸出，作為後續分析模型穩定性的依據。
4. **像素級評分管線建置**：實作 IoU@t 計算（掃描多個色彩距離閾值 t）與 mIoU 彙整。針對編輯品質與背景保留分別計算 false positive／false negative mask，量化過度編輯程度。
5. **細粒度診斷與閾值校準**：分析不同操作類型與視覺條件下的分數分布，找出模型脆弱點（如幾何變換或基於公式的顏色變更）；依據業務容忍度校準 t 值，例如醫療場景需極高色彩精度。
6. **建立回歸測試與監控儀表板**：將評估流程整合進 CI／CD，設定 mIoU 門檻；對關鍵操作類型設定獨立告警，避免整體平均分數掩蓋單項退化。
7. **領域擴充（選用）**：參考 TinyGrafixBench 的確定性評估哲學，將相同框架遷移至自身領域（如自動化簡報圖表、CAD 圖層編輯），建立專屬評估套件並驗證與 PaintBench 分數的線性相關。

### 潛在風險與注意事項

- **過度編輯誤判為正確**：模型可能大幅修改背景或鄰近像素，但視覺上仍看似正確。必須嚴格檢查非背景像素的保留率，不能僅依賴整體 mIoU。
- **色彩空間不一致**：模型輸出若經過壓縮或色彩 Profile 轉換（如 sRGB 與 Adobe RGB 差異），會導致像素級評估產生系統性偏差。建議統一輸入輸出格式、位元深度與色彩空間。
- **場景變化導致分數波動**：條紋背景、高物件數量、非標準色彩配置與小編輯區域會顯著降低模型表現。若業務場景恰好符合這些高難度條件，整體平均分數可能極低，需採用分層報告（stratified reporting）。
- **指令歧義與自然語言脆弱性**：即使任務具備單一答案，模型對指令用詞（如「clip」與「crop」）可能解讀不同。建議對同一操作使用多組同義指令進行穩健性測試。
- **評估指標與人類感知脫鉤**：像素級 IoU 對微小偏移極敏感，但人眼可能容忍 1–2 像素誤差。建議同時記錄多個閾值的 IoU@t，而非僅看單一門檻，並輔以視覺化差異圖進行人工抽檢。

### 與其他技術的整合建議

- **與 CI／CD 整合**：將 PaintBench 評估腳本封裝為 Docker 容器，在模型訓練或微調完成後自動觸發，作為合併前檢查（pre-merge check），確保精確視覺編輯能力不因版本迭代而退化。
- **與現有 VLM 評測棧互補**：PaintBench 負責「精確單一答案」任務；開放式視覺編輯（如「讓圖片更有氛圍」）仍可使用 LPIPS、FID 或 GPT-4V 評分。兩者並行可覆蓋從精確正確性到偏好品質的完整評估光譜。
- **與 Agentic 編輯管線搭配**：若產品採用「VLM 規劃＋傳統繪圖引擎執行」的 Agent 架構，可用 PaintBench 評估 VLM 產生的操作參數（如多邊形頂點座標、旋轉角度、縮放倍率）是否正確，而非直接評估最終像素。
- **與資料視覺化工具鏈整合**：將 TinyGrafixBench 的邏輯嵌入 Matplotlib／Plotly 的輸出管線，驗證 AI 調整圖表時，圖例、漸層、計數標記是否精確對應資料值，並作為圖表發布前的自動化品質閘道。
- **與 A／B 測試平台銜接**：利用 PaintBench 的可設定複雜度，針對線上流量中的高頻編輯意圖生成對應測試題組，離線評估新模型版本後，再決定是否投入線上 A／B 測試，降低全量上線風險。

- **初學者**：建議從圖 1 的 20 項基本操作與第 3 章的設計原則開始，理解「為何精確單一答案編輯比開放式視覺編輯更難評估」。接著閱讀第 5.3 節的四種常見失效模式，建立對當前模型限制的基本認知，再回頭理解像素級評估指標的意義。
