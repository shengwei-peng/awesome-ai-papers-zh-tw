本文提出「邊界感知策略學習」(Boundary-Aware Policy Learning)，其核心洞見在於：代理—策略協調系統的瓶頸不在於代理或策略本身的絕對能力，而在於兩者之間的「交接邊界」(handoff boundary) 是否寬廣且明確。所謂交接邊界，是指視覺運動策略 (visuomotor policy) 能夠可靠執行的起始狀態集合。現有系統通常採用「全任務策略」(whole-task policy)，其交接邊界狹窄且難以描述，導致代理傾向於從任務初始狀態就將整個任務交給策略執行，一旦失敗便難以恢復。

**第一階段：邊界明確化訓練 (Boundary-Explicit Training, BET)**

此階段的設計哲學是將策略的職責範圍從「整個任務」縮減至「接觸片段」(contact segment)，即機器人物理接觸目標物體的軌跡段。具體做法包含三個關鍵設計：

1. **資料切片策略**：從示範資料中擷取僅包含物理接觸的片段，而非完整任務軌跡。這與選項框架 (options framework) 中的「起始集」(initiation set) 概念有相似之處，但本文的目標並非建構可組合的技能庫，而是為了賦予策略一個明確的交接邊界。

2. **起始姿態多樣化**：在目標物體周圍收集具有多樣起始姿態 (start pose) 的接觸片段，使策略能從更廣泛的狀態空間可靠啟動，從而「拓寬」交接邊界。

3. **交接協議 (handoff protocol) 設計**：由於訓練資料的收集規則明確，邊界本身變得可形式化描述。代理只需透過簡短的文字協議即可理解何時該呼叫策略，無需透過探索或記憶來推測邊界位置。

此階段的權衡在於：邊界變得可靠，但策略覆蓋範圍縮小，代理必須透過更多語言模型呼叫來完成任務的非接觸部分（例如定位、對齊、場景理解等）。

**第二階段：邊界擴展自我改進 (Boundary-Expanding Self-Improvement, BESI)**

為解決第一階段帶來的效率問題，第二階段引入自我改進迴圈：

1. **系統回放收集**：收集整個系統（代理 + 策略）成功完成任務的完整回放 (system rollout)。

2. **資料篩選流程 (data curation pipeline)**：移除回放中的次優片段 (suboptimal segment)，保留高品質的接觸與非接觸段。

3. **策略重新訓練**：將篩選後的完整回放與第一階段的接觸片段合併，重新訓練策略，使交接邊界向任務的更早階段延伸，同時保留第一階段學到的寬廣邊界特性。

4. **代理重新探索**：代理使用重新訓練後的策略重新探索每個任務，發現可以更早交接，從而減少語言模型呼叫次數。

此設計形成一個良性循環：策略覆蓋範圍擴大 → 代理交接點前移 → 語言模型呼叫減少 → 系統效率提升，同時成功率不下降。

**方法論的深層意涵**

本文的方法論挑戰了機器人學習中一個常見假設：策略應該盡可能完整地覆蓋整個任務。透過刻意縮減策略職責，反而換來了更可靠的協調。這與軟體工程中「單一職責原則」(Single Responsibility Principle) 有異曲同工之妙。此外，將邊界視為可學習、可溝通的物件，而非隱含的資料分布特性，是一個重要的概念轉移。

#### 與現有研究的比較

**在代理—策略協調研究中的定位**

現有研究主要從「代理側」解決協調瓶頸，透過探索、記憶 (memory)、驗證 (verification) 等機制來應對策略的不確定性 [15, 32, 43, 51]。代表性地，Hi Robot、Rekep 等系統在固定策略周圍建立複雜的代理邏輯。本文則從「策略側」切入，透過訓練改變交接邊界本身的特性，這是一個根本性的視角轉換。

**與 Robo-COP 的比較**

Robo-COP [50] 同樣涉及 VLA 策略的自我改進，但其重點在於修復反覆出現的失敗模式並更新代理記憶。本文與之的關鍵差異在於：(1) 本文有明確的「邊界」概念作為設計原則；(2) 自我改進的目標是擴展交接邊界而非修復失敗；(3) 資料篩選流程針對次優片段而非失敗案例。

**與技能學習 (skill learning) 的關聯**

本文與選項框架 [38]、技能分解 [24, 25, 28, 29, 39] 有概念上的相似性——都涉及將任務分解為可重用的子任務。然而，本文並非追求技能的通用組合性，而是為了給定一個特定任務提供可靠的交接介面。這是一個更實用、更聚焦的目標。

**與通用 VLA 模型的關係**

本文的方法可應用於現有的 VLA 模型（如 RT-2、OpenVLA 等），作為後訓練 (post-training) 階段。這與近期 VLA 微調研究 [11, 13, 44, 47, 48] 的方向一致，但本文強調的是「邊界特性」而非「整體能力」。

**本文的侷限性**

1. **任務特定性**：方法需要為每個任務定義接觸片段，這在任務數量龐大時可能成為瓶頸。
2. **接觸片段的定義**：需要預先標註或自動偵測哪些軌跡段屬於「接觸」，這在某些任務中可能不明確。
3. **自我改進的收斂性**：第二階段的迭代過程是否會收斂、是否會出現災難性遺忘 (catastrophic forgetting)，需要更深入的分析。
4. **對代理能力的依賴**：方法假設代理具備足夠的場景理解與規劃能力，若代理本身能力不足，邊界再寬也無法彌補。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於代理協調式機器人操作（agent-orchestrated robot manipulation）系統中「交接邊界」（handoff boundary）的問題。在這類系統中，多模態代理負責高層任務決策，而視覺運動策略（visuomotor policy）負責精確的物理接觸操作；然而現成的視覺運動策略通常只能從有限的起始狀態可靠地執行，代理卻可能在這個範圍之外呼叫它，導致任務失敗。論文將這個策略可從之可靠執行的狀態範圍定義為「交接邊界」，並指出這個邊界往往狹窄且難以描述，使得代理與策略之間的協調變得不可靠。

**Q2：為什麼現有的代理協調式機器人系統會在交接環節失敗？**
A：現有系統通常採用「全任務策略」（whole-task policy），這類策略是從任務的初始狀態訓練來完成整個任務的，因此其交接邊界狹窄且難以在任務中段描述。當代理嘗試在任務中途將控制權交給策略時，往往會從邊界外的狀態呼叫，導致策略失敗；即使代理嘗試修正手臂姿態後再次交接，仍可能再次落在邊界之外，形成反覆失敗的循環。過去的研究多從代理端著手，透過探索、記憶與驗證來緩解此問題，但這些方法無法改變主要由訓練資料決定的策略邊界本身。

**Q3：為什麼這個問題對機器人操作領域至關重要？**
A：可靠的代理—策略協調是實現通用機器人操作的關鍵瓶頸，因為單一元件（無論是大型語言模型代理或視覺運動策略）都無法同時兼顧任務層級推理與精確物理接觸。若交接不可靠，整個系統的泛化能力與成功率都會受到嚴重限制，無法真正部署於多樣化的真實場景。論文的觀點——「穩健的代理—策略協調的關鍵不僅在於個別改進任一元件，更在於明確塑造兩者之間的邊界」——為這個長期挑戰提供了一個新的設計原則。

**Q4：邊界感知策略學習（Boundary-Aware Policy Learning）的核心想法是什麼？**
A：核心想法是透過訓練來「定義並擴展」交接邊界，而非僅從代理端約束或讓代理自行探索邊界。具體而言分為兩個階段：第一階段「邊界明確化訓練」（Boundary-Explicit Training）僅在接觸片段（contact segment）上微調策略，並以目標物體周圍多樣化的起始姿態收集資料，使邊界既寬廣又明確可描述；第二階段「邊界擴展自我改進」（Boundary-Expanding Self-Improvement）則在系統成功回放上重新訓練策略，使邊界向任務更早的階段延伸，讓代理能更早交接、減少語言模型呼叫次數。

**Q5：相較於現有方法，此論文最關鍵的創新點為何？**
A：最關鍵的創新在於「從策略端而非代理端」解決瓶頸——透過訓練塑造交接邊界，使其寬廣且明確可傳達給代理。這與 Robo-COP 等先前工作不同：Robo-COP 是在自身執行資料上微調視覺運動策略以修正反覆失敗，而本論文則刻意將策略限制在接觸片段上以獲得明確邊界，再透過自我改進逐步擴展邊界。此外，論文中提出的「交接協議」（handoff protocol）讓代理能透過簡短的規則描述理解邊界，這種將邊界「外化」為可溝通介面的設計是嶄新的。

**Q6：在兩個訓練階段中，有哪些重要的設計選擇？**
A：在邊界明確化訓練中，設計選擇是僅在「接觸片段」上微調策略，而非整個任務軌跡；接觸片段是機器人實際與物體物理互動的部分，這使得邊界規則明確且易於描述。同時，刻意以目標物體周圍多樣化的起始姿態收集資料，使邊界寬廣。在邊界擴展自我改進中，設計選擇是先收集系統的成功回放，再透過資料篩選流程（data curation pipeline）移除次優片段（suboptimal segment），然後將這些精選回放與第一階段的接觸片段合併重新訓練，從而在保留已學邊界的同時將其向任務早期延伸。

**Q7：論文中使用了哪些基準測試來評估方法？**
A：論文主要在兩個基準測試上評估：RoboTwin 2.0 與 RoboDojo。RoboTwin 2.0 提供隨機化場景（randomized scene）以測試系統在多樣化佈局下的泛化能力，而 RoboDojo 則作為另一個獨立的模擬器基準。這兩個基準涵蓋了不同的任務與場景設定，使評估結果更具說服力，能驗證方法在異質環境下的穩健性。

**Q8：論文報告了哪些關鍵的實驗結果？**
A：在 RoboTwin 2.0 隨機化場景中，本系統達到 98.4% 的成功率，比最強基線高出超過 26 個百分點。更值得注意的是，僅憑邊界明確化訓練（不含自我改進）就已超越基線，而加入邊界擴展自我改進後，在不損失成功率的前提下，API 成本平均降低 41.3%、執行時間縮短 37.5%。這些結果顯示方法不僅提升了可靠性，也顯著改善了效率，證明了「塑造邊界」這個設計原則的雙重效益。

**Q9：論文中進行了哪些消融實驗或分析？**
A：雖然提供的全文未詳列所有消融實驗細節，但從方法描述可看出，論文的設計本身就內含消融邏輯：僅使用邊界明確化訓練即可超越基線，而加入邊界擴展自我改進則進一步降低成本與時間，這清楚分離了兩個階段各自的貢獻。此外，論文中提到一個早期探索性研究（附錄 G）比較了讓代理直接控制機器人與代理—策略協調兩種範式，間接證明了後者更優。Sec. 4.4 中也分析了代理反覆從邊界外狀態交接導致失敗的現象，作為動機的實證支持。

**Q10：這項研究適用於哪些實際應用場景？**
A：這項研究適用於任何需要結合高層推理與精確操作的機器人應用，例如家庭服務機器人（整理物品、清潔）、倉儲物流（揀貨、包裝）、工業組裝（多步驟零件裝配）以及醫療輔助（器械遞送、樣本處理）等。在這些場景中，代理需要根據使用者指令靈活規劃任務順序，而物理接觸環節則需要精準的視覺運動控制；可靠的交接機制是讓這類系統真正落地的關鍵。

**Q11：將此方法部署為實際產品時，需要考慮哪些工程因素？**
A：產品化時需考慮以下因素：首先，邊界明確化訓練需要蒐集多樣化起始姿態的接觸片段資料，這在真實世界中成本高昂，可能需要結合模擬與真實資料；其次，自我改進階段仰賴系統持續產生成功回放，初期部署時成功率可能不足以支撐有效的自我改進循環；此外，41.3% 的 API 成本降低對商業部署至關重要，因為語言模型呼叫是主要的營運成本，而 37.5% 的執行時間縮短則直接影響使用者體驗與吞吐量。

**Q12：這項研究對機器人與人工智慧領域的更廣泛影響是什麼？**
A：這項研究最重要的影響是提出了「邊界設計」這個新原則——在混合系統中，元件之間的介面本身應被視為可設計的對象，而非僅僅是事後約束。這種思維可推廣至其他代理—模型、代理—工具或代理—人類的協作場景。此外，論文中「透過訓練讓介面變得可溝通」的概念，可能啟發後續關於可解釋、可協作機器人系統的研究，推動整個領域從「單一強大模型」轉向「明確分工且可靠銜接的混合系統」。

A：從全文可推論出幾項限制：第一，邊界明確化訓練僅針對接觸片段，這意味著非接觸階段（如導航、定位）仍完全依賴代理的語言模型呼叫，可能在某些任務中限制效率提升的幅度；第二，自我改進仰賴系統能產生足夠的成功回放，若初始策略覆蓋率不足，邊界擴展可能緩慢甚至停滯；第三，方法在隨機化場景中表現優異，但在更極端的分布外場景（如全新物體類型或複雜多步驟任務）下的泛化能力仍待驗證。

**Q14：此方法可能會在哪些情況下失敗？**
A：可能失敗的情況包括：當任務需要極長程的規劃且接觸片段在任務中占比很小時，代理仍需大量語言模型呼叫，效率優勢可能被削弱；當目標物體被嚴重遮擋或場景中存在多個相似物體時，邊界描述可能不夠精確，導致代理誤判交接時機；此外，若自我改進階段的資料篩選流程未能有效識別次優片段，可能將不良行為固化進策略，反而縮小邊界或降低可靠性。

A：未來方向可包括：將邊界設計原則推廣至多代理、多策略的協作場景，探討如何同時協調多個視覺運動策略；研究邊界的自動發現與形式化描述，使代理無需人工撰寫交接協議即可理解策略能力；結合基礎模型的進展，探索是否能從預訓練階段就內建「明確邊界」的能力，而非僅在微調階段塑造；以及將此方法從模擬環境推向真實機器人部署，驗證其在物理世界中的實用性與安全性。這些方向都可能進一步推動代理—策略協調系統走向真正的實用化。

**自我改進循環中的錯誤累積**
- 風險：若篩選流程放行了表面成功但實際次優的回放，策略可能逐步偏離正確行為。
- 緩解：保留一份固定的驗證集（不在自我改進中使用），每輪訓練後評估；對成功率設定下限，一旦下降即停止迭代。

**API 成本與延遲的非線性變化**
- 風險：邊界擴展後，代理可能在某些任務過早交接，導致策略失敗率上升，反而需要更多恢復呼叫，總成本不降反升。
- 緩解：以任務類型分群分析成本變化，對於邊界擴展效益不顯著的任务，保留較保守的交接時機。

**真實場景的隨機性超出訓練分布**
- 風險：模擬器中訓練的邊界在真實機器人上可能因感測器雜訊、光照變化而失效。
- 緩解：在真實環境中重新採樣起始姿態並微調；採用域隨機化（domain randomization）提升泛化性。

**多任務間的策略干擾**
- 風險：自我改進階段合併多任務資料時，新任務的接觸片段可能干擾舊任務的邊界。
- 緩解：採用多任務學習的標準技巧（任務標籤、梯度平衡），並對每任務單獨評估交接邊界的保持程度。

### 與其他技術的整合建議

**與現成 VLA 模型整合**
本方法可作為後訓練（post-training）階段套用於任何支援微調的 VLA 模型（OpenVLA、π0、RT-2 等）。建議先以全任務資料微調得到基線策略，再依本方法進行兩階段訓練，而非從頭訓練。

**與代理框架整合**
可與 LangChain、AutoGen 等代理框架結合，將交接協議編碼為結構化工具描述（tool schema），讓代理以函式呼叫形式查詢「目前狀態是否可交接」。記憶模組可儲存每次交接的成敗記錄，用於後續決策。

**與機器人作業系統（ROS）整合**
將視覺運動策略封裝為 ROS 動作伺服器，代理透過 ROS 服務呼叫觸發；交接邊界檢查可實作為獨立的 ROS 節點，在策略執行前攔截並驗證。

**與模擬器整合**
建議在 RoboTwin 2.0、RoboDojo 等模擬器中先完成兩階段訓練與驗證，再以 sim-to-real 轉移技術（域隨機化、實境微調）部署到真實機器人。模擬器的隨機化場景功能可直接用於生成多樣化起始姿態。

**與安全監控系統整合**
在策略執行期間，串接安全監控（如關節限位、碰撞偵測、力矩監控）。當策略偏離預期軌跡時，安全系統可強制中斷並通知代理接管，避免硬體損壞。

**與 MLOps 平台整合**
將自我改進循環封裝為 CI/CD 流程：每次資料累積達閾值即自動觸發訓練、評估、部署。需整合資料版本控制（DVC）、模型註冊（MLflow）與 A/B 測試框架，以安全地迭代策略版本。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的問題描述，理解「交接邊界」這個直覺概念——策略就像一個只會從特定位置起跑的短跑選手，代理則是教練，需要知道選手能從哪些位置起跑。重點掌握「為什麼現成策略在代理系統中容易失敗」這個核心問題，再回頭看方法細節會更順暢。可先跳過數學推導，專注於圖 1 與圖 2 的系統示意。

**給 AI 工程師**：重點關注第 3.2 與 3.3 節的實作細節，特別是接觸片段的切分邏輯、交接協議的設計格式、以及資料篩選流程的具體準則。建議直接以一個現成的 VLA 模型與代理框架（如 LangChain + OpenVLA）做最小可行實驗，驗證邊界明確化訓練對成功率的提升，再逐步引入自我改進循環。論文中 26 個百分點的提升與 41.3% 的成本下降是評估實作成效的明確基準。

**給研究者**：本論文的核心洞察在於「將代理—策略介面視為可學習的物件」，而非僅僅最佳化單一元件。建議從三個方向延伸：(1) 形式化交接邊界，例如以不確定度估計或可達集合（reachable set）描述邊界；(2) 將交接協議從靜態文字升級為代理可查詢的動態介面；(3) 探索多代理—多策略的協調場景，邊界概念如何泛化。Sec. 4.4 的失敗分析與 Appendix G 的早期探索實驗提供了豐富的研究線索。

**給產品經理**：本方法的核心商業價值在於「以訓練成本換取部署成本」——透過一次性的兩階段訓練，換取長期部署中 API 成本降低 41.3%、執行時間縮短 37.5%，且成功率提升至 98.4%。在評估導入時，建議關注三個指標：每任務的 LLM 呼叫次數、單次任務的端到端時間、以及策略失敗後的恢復成本。這些指標直接影響單位任務的營運成本與使用者體驗，適合作為產品決策的量化依據。
