## ⚡ TL;DR

現有代理式視覺推理模型缺乏工具調用適應性，且工具使用在簡單樣本上造成損害、在困難樣本上增益有限。
提出Beacon，結合必要性感知適應獎勵與提示引導式能力擴展，強化適應性工具調用與工具效應。
在13個基準測試中取得最佳平均效能，並顯著提升模式適應性與工具增益和損害間的差距。

## 摘要翻譯

代理式視覺推理（Agentic Visual Reasoning）的根本目標在於提升多模態大型語言模型（Multimodal Large Language Models, MLLMs）在複雜任務上的成功率，而非僅僅為其配備一個繁複卻低效的推理範式。在本研究中，我們透過工具使用（Tool Use）的兩個關鍵維度——模式適應性（Mode Adaptiveness, MA）與工具效應（Tool Effect, TE）——重新審視代理式視覺推理。模式適應性刻畫多模態大型語言模型是否能辨識工具真正必要的時機，並據以調用工具，從而避免不必要的計算開銷（Computational Overhead），同時提升在需要工具輔助的具挑戰性問題（Challenging Problems）上的效能。工具效應則刻畫工具使用的實際影響：工具應擴展模型在無法僅靠純文字推理（Text-Only Reasoning）解決的問題上的能力，同時避免在模型已可無工具解決的問題上引入額外錯誤。我們進行全面分析以量化這兩項特性，並實證揭示現有的代理式視覺推理模型僅具有限的模式適應性，且工具使用在困難樣本（Hard Examples）上帶來的增益，在很大程度上被其在模型已可解決的簡單樣本（Easy Examples）上所造成的損害所抵消。基於上述觀察，我們提出 Beacon，一個新穎的代理式視覺推理模型，可達到更強的整體效能（Overall Performance）、更佳的模式適應性，以及真正的工具帶來的效能增益（Genuine Tool-Induced Performance Gains）。Beacon 的核心在於強化學習階段（Reinforcement Learning Stage）中的必要性感知適應獎勵（Necessity-Aware Adaptive Reward）與提示引導式能力擴展（Hint-Guided Capability Expansion）機制，兩者分別鼓勵根據任務必要性（Task Necessity）進行適應性工具調用（Adaptive Tool Invocation），並強化模型在最具挑戰性的問題上的工具使用能力（Tool-Use Capability）。在多樣化基準測試（Diverse Benchmarks）上進行的廣泛實驗驗證了 Beacon 強大的整體效能，以及其在模式適應性與工具效應兩方面的顯著改善。

### 核心貢獻（3～5點）
- 從模式適應性（MA）與工具效應（TE）兩個維度，重新界定代理式視覺推理的評估標準與研究目標。
- 透過全面量化分析，揭示現有模型在適應性工具調用上的局限，以及工具使用於簡單樣本上造成損害、抵銷困難樣本增益的現象。
- 提出 Beacon 模型，於強化學習階段結合必要性感知適應獎勵與提示引導式能力擴展機制，以提升適應性工具調用與工具使用能力。
- 在多樣化基準測試上驗證 Beacon 於整體效能、模式適應性與工具效應的顯著改善。

### 適合對象
適合對多模態大型語言模型、代理式視覺推理、工具學習與強化學習有興趣的研究者與工程師，特別是關注如何設計具適應性且高效能的工具調用機制、以及如何評估工具帶來真實增益的讀者。

## 深度分析

#### 方法論解析

Beacon 的核心方法論可從「訓練管線」與「強化學習（RL）框架」兩個層次來理解。

**1. 整體訓練流程**

論文採用兩階段訓練策略：

- **監督式微調（SFT）資料合成管線（SFT Data Synthesis Pipeline）**：首先建立高品質資料，讓模型具備基礎的程式碼使用能力（code-use capabilities）。此階段著重於教會模型如何自主生成 Python 程式碼，以執行影像裁切（image cropping）、標註（annotation）、影像增強（enhancement）、旋轉（rotation）、拼接（stitching）、像素級計算（pixel-level computation）以及複雜數值計算（complex numerical calculations）等視覺與數值運算（visual and numerical operations）。
- **強化學習階段（Reinforcement Learning Stage）**：在 SFT 之後，進一步透過 RL 改善兩項關鍵能力：適應性工具調用（adaptive tool invocation）與工具使用能力（tool-use capability）。此階段包含兩項創新設計：**必要性感知適應獎勵（Necessity-Aware Adaptive Reward）** 與 **提示引導式展開策略（Hint-Guided Rollout Strategy）**。

**2. 必要性感知適應獎勵（Necessity-Aware Adaptive Reward）**

此獎勵機制旨在解決現有方法在「何時該用工具」上的缺陷。其設計遵循兩大原則：

- **模式條件標記（Mode-Conditioned Labeling）**：每個問題會同時評估其無工具可解性（tool-free solvability）與有工具輔助時的表現，據此標記該問題「需要工具」或「不需要工具」。這不同於僅依據教師模型（teacher model）單方面決定的做法。
- **線上標記（Online Labeling）**：標記是根據當前策略模型（current policy）的表現動態更新，而非固定依賴某個強大教師模型。這能避免 off-policy 問題，也就是策略模型與教師模型之間的分布不匹配（distribution mismatch）。

具體而言，若某問題在純文字推理（text-only reasoning）下已可穩定解決，則模型不應調用工具；反之，若純文字推理不足，則應鼓勵工具調用。這樣的獎勵設計讓模型學會依據任務必要性（task necessity）進行適應性工具調用（adaptive tool invocation），從而減少不必要的計算開銷（computational overhead）。

**3. 提示引導式能力擴展（Hint-Guided Capability Expansion）**

此機制對應於「工具效應（Tool Effect）」的第二個面向：工具應真正擴展模型能力，而非僅在簡單樣本上造成損害。論文發現，現有模型雖然在困難樣本（hard examples）上可能因工具而獲益，但這些增益常被簡單樣本（easy examples）上的錯誤所抵消。

為此，Beacon 採用 **提示引導式展開策略（Hint-Guided Rollout Strategy）**：針對那些無法透過純文字推理解決的問題，在 rollout 過程中提供有效工具使用軌跡（tool-use trajectories）的提示（hints）。這讓模型能夠接觸到高品質的中間多模態結果（intermediate multimodal results）生成方式，進而強化其在最具挑戰性問題上的工具使用能力（tool-use capability）。換言之，這不是單純減少工具使用，而是「在對的地方、用對的方式」使用工具，以實現真正的工具帶來效能增益（genuine tool-induced performance gains）。

**4. 推理階段的能力**

在推理時（inference），Beacon 能夠自主生成 Python 程式碼來執行多樣化的視覺與數值運算，並將這些中間結果整合進最終答案生成（final-answer generation）過程。這使其成為一個完整的代理式視覺推理模型（agentic visual reasoning model）。

#### 實驗數據解讀

雖然論文摘要與引言中未列出詳細數據表格，但從其宣稱與分析框架可歸納出以下重點：

**1. 評估指標：模式適應性（MA）與工具效應（TE）**

論文提出兩個核心診斷指標：

- **模式適應性（Mode Adaptiveness, MA）**：衡量模型是否能判斷何時需要工具。這包含兩個互補面向：
  - 在可透過純文字推理解決的問題上，避免不必要的工具調用（tool invocation）。
  - 在純文字推理不足時，主動調用工具。
- **工具效應（Tool Effect, TE）**：衡量工具使用對模型能力的實際影響：
  - **工具帶來的增益（Tool-Induced Gain）**：在無工具無法解決的困難樣本上，工具使用所帶來的成功率（success rate）提升。
  - **工具帶來的損害（Tool-Induced Harm）**：在原本已可透過純文字推理解決的簡單樣本上，工具使用所引入的額外錯誤。

論文強調，過去研究常以單次推理結果來判定無工具可解性（tool-free solvability），這容易受隨機性（stochasticity）干擾而不穩定。因此，Beacon 的分析採用多次推理運行（multiple inference runs），以獲得更穩健的評估。

**2. 現有模型的診斷結果**

論文發現現有代理式視覺推理模型（agentic visual reasoning models）普遍存在以下問題：

- **模式適應性（MA）有限**：模型傾向於過度或不足地調用工具，無法根據問題難度精準判斷。
- **工具效應（TE）不佳**：工具在困難樣本上的增益，很大程度上被簡單樣本上的損害所抵消，導致相對於純文字推理（text-only reasoning）的整體改善有限。

這意味著，單純增加工具使用頻率或提升工具執行能力，並不足以改善整體效能；關鍵在於「適時且有效」地使用工具。

**3. Beacon 的實驗結果**

論文在 13 個涵蓋多樣化視覺推理任務（visual reasoning tasks）的基準測試（benchmarks）上進行評估，結果顯示：

- **整體效能（overall performance）最佳**：Beacon 達到最高的平均效能（average performance）。
- **模式適應性（MA）顯著提升**：相較於現有模型，Beacon 更能根據任務必要性決定是否調用工具。
- **最大的工具增益與損害差距（gap between tool-induced gain and harm）**：這表示 Beacon 不僅在困難樣本上獲得真正的工具帶來效能增益（genuine tool-induced performance gains），也成功減少了在簡單樣本上的負面影響。

這些結果共同說明，Beacon 的 RL 框架同時改善了工具調用的適應性（adaptiveness）與工具執行的有效性（effectiveness）。

#### 與現有研究的比較

Beacon 在「適應性工具使用（adaptive and efficient tool use）」與「視覺工具真實效益（actual benefit of visual tools）」兩條研究線上，都做出了明確的改進。

**1. 相較於 CodeDance**

CodeDance 使用群組層級準確率（group-level accuracy）來決定適應性獎勵的優化方向：高準確率群組應減少工具使用，低準確率群組應增加工具使用。然而，這種設計存在一個關鍵缺陷：獎勵並未條件化於軌跡（trajectory）是否實際調用了工具。因此，一個成功使用工具的軌跡，可能僅因所屬群組整體準確率高，就被錯誤地懲罰。

Beacon 的 **必要性感知適應獎勵（Necessity-Aware Adaptive Reward）** 透過模式條件標記與線上標記，直接根據當前策略在「有工具」與「無工具」模式下的表現來決定標籤，避免了這種錯誤懲罰。

**2. 相較於 AdaTooler-V**

AdaTooler-V 使用教師模型 Qwen2.5-VL-72B 的工具帶來效能增益，來標記訓練樣本是否需要工具。這種方法的問題在於：

- **分布不匹配（distribution mismatch）**：教師模型與策略模型（policy）的能力與行為分布不同。
- **受教師能力限制**：若教師模型本身在某些問題上無法有效使用工具，則標記品質會受限。

Beacon 採用 **線上標記（online labeling）**，標記依據當前策略模型而非固定教師模型，從而減輕了分布不匹配問題，並能隨著策略進步動態調整。

**3. 相較於 Metis**

Metis 採用較簡單的策略，普遍鼓勵減少工具調用。雖然這能降低計算開銷，但缺乏任務依賴的適應性（task-dependent adaptiveness），可能在需要工具的困難問題上過度抑制工具使用。

Beacon 的設計則更為精細：它鼓勵「必要時才使用工具」，而非單純減少工具使用。這使其在簡單樣本上節省計算，同時在困難樣本上保留並強化工具使用能力。

**4. 相較於診斷性研究**

過去如 [42]、[16]、[8] 等研究雖然質疑視覺工具的真實效益，但大多僅提供二元診斷，且未提出明確解決方案。Beacon 不僅提出更穩健的分析框架（結合 MA 與 TE、多次推理運行），還設計了具體的 RL 方法來同時改善這兩個面向，填補了「診斷」與「解決方案」之間的缺口。

**5. 潛在限制**

儘管 Beacon 有顯著貢獻，仍有幾點值得注意：

- **標記穩定性**：模式條件標記依賴多次推理來判定無工具可解性，雖比單次穩定，但在樣本數較少或問題邊界模糊時，仍可能存在標記雜訊。
- **提示設計成本**：提示引導式展開策略需要為困難樣本準備有效提示，這可能涉及額外的人工設計或自動生成管線，其品質會直接影響能力擴展效果。
- **泛化性**：論文雖在 13 個基準測試上驗證，但這些測試是否涵蓋所有類型的視覺推理任務，以及方法在更開放、真實世界場景中的表現，仍需進一步檢驗。

#### 未來研究方向

Beacon 的框架為代理式視覺推理（agentic visual reasoning）開啟了多個值得探索的方向：

**1. 更細緻的適應性決策機制**

未來可研究如何讓模型不僅決定「是否」使用工具，還能決定「使用哪種工具」、「使用多少次」以及「何時停止」。這涉及多步工具規劃（multi-step tool planning）與動態計算預算分配（dynamic computational budget allocation）。

**2. 工具使用軌跡的可解釋性**

目前工具調用的決策過程仍較為黑箱。未來可結合可解釋性技術，分析模型在何種視覺特徵或問題結構下傾向調用工具，從而進一步提升模式適應性（MA）。

**3. 跨模態工具擴展**

Beacon 目前主要使用 Python 程式碼進行視覺與數值運算。未來可將框架擴展至更多外部工具（external tools），例如檢索系統、知識庫、專業視覺模型（如物體偵測、分割模型）等，並研究如何在多工具環境中維持適應性。

**4. 更穩健的無工具可解性估計**

雖然 Beacon 已採用多次推理運行來估計無工具可解性，但未來可進一步結合不確定性量化（uncertainty quantification）或共識機制（consensus-based methods），使標記更穩定，特別是在樣本邊界模糊的情況下。

**5. 開放式真實世界評估**

現有基準測試多為封閉式問答任務。未來可在更開放、真實的視覺推理場景中評估 Beacon，例如機器人操作、科學實驗分析或互動式視覺對話，以檢驗其工具使用策略的泛化能力。

**6. 與其他 RL 演算法的結合**

Beacon 的 RL 框架可與更先進的強化學習技術結合，例如群體相對策略優化（Group Relative Policy Optimization, GRPO）、直接偏好優化（Direct Preference Optimization, DPO）或過程獎勵模型（process reward models），以進一步提升訓練穩定性與最終效能。

## 論文問答

**Q1：代理式視覺推理的根本目標是什麼？這篇論文指出了現有方法在哪些核心層面存在不足？**

A：代理式視覺推理的根本目標是提升多模態大型語言模型（MLLMs）在複雜視覺任務上的成功率，而非僅僅讓模型具備一套看似強大卻效率低下的推理流程。本文指出，現有方法普遍忽略了兩個關鍵面向：模式適應性（MA），即模型是否能判斷何時真正需要調用外部工具；以及工具效應（TE），即工具使用是否真正擴展了模型在無法僅靠純文字推理解決的問題上的能力。由於這兩項不足，現有模型往往在簡單樣本上過度調用工具，導致計算開銷與錯誤增加，卻未能在困難樣本上帶來穩定的效能增益。

**Q2：為什麼現有的代理式視覺推理模型難以實現「真正的工具帶來效能增益」？**

A：現有模型的工具調用適應性有限，經常無差別地調用工具，使得在困難樣本上的工具帶來的效能增益被簡單樣本上的損害所抵消。過去研究大多只報告整體任務準確率，鮮少檢視工具是否被適當地、必要地使用，也未能區分工具是「擴展能力」還是「引入額外錯誤」。此外，現有的適應性強化學習策略也存在缺陷，例如以群組準確率決定獎勵方向會錯誤懲罰成功的工具輔助軌跡，或過度依賴固定教師模型而產生分佈不匹配問題。

**Q3：區分「需要工具」與「不需要工具」的問題為何如此重要？**

A：正確區分兩者能避免在已可透過純文字推理解決的簡單樣本上進行不必要的工具調用，從而降低計算開銷與延遲。同時，這也能確保模型將工具資源集中在真正具挑戰性的問題上，發揮外部工具擴展模型能力的作用。這種適應性工具調用不僅提升效率，也能減少因工具執行錯誤而導致的整體效能下降，是實現可靠代理式視覺推理的關鍵。

**Q4：Beacon 的核心架構與訓練流程包含哪些主要組件？**

A：Beacon 是本文提出的新型代理式視覺推理模型，其核心包含一個高品質的監督式微調（SFT）資料合成管線，以及一個創新的強化學習（RL）框架。在 SFT 階段，模型透過合成資料學習基本的程式碼使用能力，例如影像裁切、標註、增強、旋轉、拼接、像素級計算與複雜數值計算。在 RL 階段，則透過必要性感知適應獎勵與提示引導式展開策略，分別提升模型依任務必要性適應調用工具的能力，以及強化其在無工具不可解問題上的工具使用能力。

**Q5：必要性感知適應獎勵（Necessity-Aware Adaptive Reward）的設計原則是什麼？**

A：此獎勵機制遵循兩大原則：模式條件標記（mode-conditioned labeling）與線上標記（online labeling）。模式條件標記會同時參考模型在無工具與有工具條件下的表現，將每個問題標記為「需要工具」或「不需要工具」；線上標記則是根據當前策略的表現動態更新標籤，而非依賴固定的教師模型。這樣的設計能避免離策略（off-policy）問題，並精確地鼓勵模型只在真正必要時調用工具，從而提升工具調用適應性。

**Q6：提示引導式能力擴展（Hint-Guided Capability Expansion）機制如何運作，為何不可或缺？**

A：該機制透過提示引導式展開策略，讓模型在無法僅靠純文字推理解決的困難樣本上，接觸到有效的工具使用軌跡。這不僅能減少工具執行帶來的錯誤，更重要的是能真正擴展模型在最具挑戰性問題上的能力。過去研究發現工具使用強化學習往往只能減少錯誤，卻難以解決原本無工具就無法解決的問題，而提示引導式能力擴展正是為了彌補這項缺口。

**Q7：Beacon 在哪些基準測試上進行評估？主要實驗結果為何？**

A：Beacon 在 13 個涵蓋多樣化視覺推理任務的基準測試上進行評估。實驗結果顯示，Beacon 取得了最佳的平均效能，並在多項任務上展現出強大的整體表現。更重要的是，進一步分析顯示 Beacon 具有更強的工具調用適應性，以及工具帶來的增益與損害之間最大的差距，代表其工具使用既有效又適應性高。

**Q8：模式適應性（MA）與工具效應（TE）指標如何揭示 Beacon 相較於現有模型的優勢？**

A：透過多次推理執行來穩健評估無工具可解性後，研究發現現有模型在模式適應性上表現有限，且工具帶來的效能增益常被簡單樣本上的損害抵消。相較之下，Beacon 在這兩項指標上都有顯著改善，特別是在困難樣本上展現出真正的工具帶來效能增益，同時在簡單樣本上減少了不必要的錯誤。這顯示 Beacon 的強化學習框架同時提升了工具調用的適應性與有效性。

**Q9：哪些分析或消融研究支持了 Beacon 的設計選擇？**

A：本文提出的分析框架同時考量模式適應性與工具效應，並透過多次推理執行來獲得更穩健的無工具可解性估計，這比過去僅用單次推理結果進行二元判斷更為可靠。作者也將現有適應性方法（如 CodeDance、AdaTooler-V、Metis）的侷限性與 Beacon 的設計進行對比，說明模式條件標記與線上標記如何克服這些問題。這些分析共同支持了必要性感知適應獎勵與提示引導式能力擴展在提升適應性與工具效應上的有效性。

**Q10：Beacon 在哪些實際應用場景中特別具有價值？**

A：Beacon 特別適合需要精細視覺感知與複雜數值運算的場景，例如科學圖表分析、文件理解、醫學影像判讀、工程圖面測量，以及需要像素級計算或影像操作的自動化代理任務。由於模型能自動生成 Python 程式碼執行影像裁切、增強、拼接等操作，並進行複雜數值計算，因此能處理傳統純文字推理難以應對的問題。其適應性工具調用特性也讓它在資源受限的邊緣部署或高吞吐量服務中更具實用價值。

**Q11：在實際產品部署 Beacon 時，需要考慮哪些關鍵因素？**

A：首先必須權衡工具調用所帶來的延遲、計算成本與準確率提升，而 Beacon 的適應性調用機制有助於在兩者間取得平衡。其次，需要建立安全且穩定的程式碼執行環境，因為模型會自動生成並執行 Python 程式碼來操作影像與數據。此外，持續監控模式適應性與工具效應等指標，能幫助產品團隊及時發現過度或不足的工具調用問題，並進行針對性調校。

**Q12：這項研究可能對代理式視覺推理領域帶來什麼樣的影響？**

A：本文將研究焦點從單純追求整體準確率，轉向同時關注工具調用的適應性與工具執行的真實效益，為該領域提供了更細緻的評估視角。透過提出明確的指標與對應的強化學習框架，Beacon 為後續研究提供了一個可複製的範式，用以訓練真正會「適時且有效」使用工具的模型。這將推動未來多模態大型語言模型朝更高效、更可靠、更具擴展性的代理式系統發展。

**Q13：這篇論文有哪些已經或可能隱含的限制？**

A：本文目前標示為進行中的預印本，因此部分實驗與分析可能尚未經過同儕審查，且評估範圍限於選定的 13 個基準測試。線上標記機制依賴當前策略的表現，若策略本身仍不穩定，可能導致標籤估計出現雜訊。此外，提示引導式展開與程式碼執行環境的設計假設，可能無法完全涵蓋所有真實世界部署情境中的多樣性與安全性挑戰。

**Q14：Beacon 在哪些情況下仍可能出現失敗？**

A：當提示不足以引導模型找到正確的工具使用軌跡，或工具執行本身產生錯誤結果時，Beacon 仍可能無法解決極度困難的問題。若模型對任務必要性的判斷出現偏差，可能會在需要工具時未調用工具，或在簡單問題上過度調用工具。此外，面對與訓練資料分佈差異過大的新任務，或程式碼執行環境不一致時，模型的適應性與穩定性也可能下降。

**Q15：未來研究可以朝哪些方向延伸這項工作？**

A：未來可以將此框架擴展到更多樣化的外部工具與模態，例如網頁瀏覽、資料庫查詢或三維視覺操作，以進一步擴展代理能力。另一方面，可以結合不確定性估計或元學習，讓模型在面對新任務時能更精準地判斷工具必要性。此外，擴大強化學習資料整理策略的規模、探索人機協作模式，以及深入研究工具使用對模型可解釋性與安全性的長期影響，也都是值得持續探索的方向。

## 實務應用指南

### 適用場景

1. **工業視覺品質檢測與異常判讀**  
   在產線上拍攝的零件、PCB 或組裝影像中，模型需要量測尺寸、計算像素級瑕疵、比對標註位置，並只在需要時呼叫 Python 工具進行裁切、旋轉或數值運算，避免對顯而易見的良品過度調用工具。

2. **金融與商業文件圖表分析**  
   處理年報、發票或儀表板截圖時，模型需判斷何時要放大表格區域、拼接跨頁圖片、執行複雜數值計算；對於純文字即可回答的摘要問題，則應直接以純文字推理回覆，以降低延遲與成本。

3. **醫學影像輔助判讀**  
   針對 X 光、病理切片或視網膜影像，模型可在必要時調用像素級計算或影像增強工具來輔助診斷，但對於已能從影像與病歷文字直接推論的常見案例，應避免額外工具調用所帶來的錯誤風險。

4. **自動駕駛與機器人視覺規劃**  
   在需要理解道路標線、計算距離或判斷相對位置的場景中，模型可動態呼叫視覺與數值運算工具；而在簡單的場景描述任務中，則直接以純文字推理完成，提升反應速度。

5. **教育領域的數理圖形解題**  
   面對幾何圖、函數圖或統計圖問題，模型只在圖形資訊無法僅靠文字推論時，才呼叫程式碼工具進行標註、量測與計算，減少對簡單題目的不必要運算。

### 實作前置條件

- **資料準備**
  - 具備多樣化視覺推理任務的影像—問題配對，涵蓋簡單與困難樣本。
  - 可取得或合成高品質的監督式微調資料，包含 Python 程式碼使用軌跡、影像裁切、標註、增強、旋轉、拼接等操作範例。
  - 強化學習階段需整理「無工具可解性」標籤，並能區分需要工具與不需要工具的樣本。

- **運算資源**
  - 足夠支援多模態大型語言模型（MLLMs）監督式微調與強化學習的 GPU 叢集。
  - 安全的程式碼執行沙盒，用於執行模型生成的 Python 程式碼並回傳中間多模態結果。
  - 可進行多次推理以評估模式適應性（MA）與工具效應（TE）的評估環境。

- **技術與團隊能力**
  - 熟悉 MLLM 微調、強化學習（如 PPO、GRPO）與獎勵設計。
  - 具備提示工程與工具調用策略設計經驗。
  - 能建立安全隔離的程式碼執行環境，並處理潛在的資安風險。

### 實作步驟建議

1. **定義任務範圍與工具集合**  
   根據產品需求決定需要哪些外部工具，例如影像裁切、標註、增強、旋轉、拼接、像素級計算與複雜數值計算，並設計對應的 Python 程式碼執行介面。

2. **建立監督式微調資料合成管線**  
   透過高品質的 SFT 資料合成管線，讓模型學會基本的程式碼使用能力，包括如何根據問題生成適當的 Python 程式碼、解析執行結果並產生最終答案。

3. **執行監督式微調（SFT）**  
   使用合成資料對基礎 MLLM 進行微調，使其具備初步的工具使用能力與視覺推理能力。

4. **整理強化學習資料**  
   針對強化學習階段，篩選出具挑戰性的問題，並依據當前策略的無工具與有工具表現進行線上標註，區分需要工具與不需要工具的樣本。

5. **設計必要性感知適應獎勵**  
   獎勵設計應以「模式條件標註」為基礎：當樣本無需工具即可解決時，鼓勵模型不要調用工具；當樣本必須藉由工具才能解決時，則獎勵正確的工具調用。

6. **實作提示引導式展開策略**  
   對於那些無法透過純文字推理解決的困難樣本，在展開過程中提供提示，引導模型學習有效的工具使用軌跡，以強化其工具使用能力。

7. **進行強化學習訓練**  
   結合必要性感知適應獎勵與提示引導式展開策略，進行強化學習，提升模型的工具調用適應性與真正的工具帶來效能增益。

8. **部署與持續監控**  
   上線時搭配程式碼執行沙盒，並持續監控工具調用率、成功率、工具帶來的增益與損害，以及整體延遲與成本，作為後續迭代的依據。

### 潛在風險與注意事項

- **過度調用工具導致延遲與成本增加**  
  若模型在簡單樣本上也頻繁呼叫工具，會造成不必要的計算開銷。可透過必要性感知適應獎勵與線上標註機制抑制此現象。

- **工具使用反而降低簡單題正確率**  
  工具可能在原本可透過純文字推理正確回答的問題上引入錯誤。建議透過模式適應性（MA）與工具效應（TE）指標持續追蹤，並針對高損害樣本進行資料清洗或獎勵調整。

- **困難樣本仍無法有效使用工具**  
  若提示引導式展開策略不足，模型可能無法學會在真正困難的問題上擴展能力。應確保 RL 資料整理策略涵蓋足夠多樣的具挑戰性問題。

- **程式碼執行安全風險**  
  模型生成的 Python 程式碼可能包含惡意或危險操作。必須在隔離沙盒中執行，並限制可使用的函式庫與系統資源。

- **獎勵作弊與標籤不穩定**  
  單次推理的無工具可解性標籤容易受隨機性影響。建議採用多次推理進行更穩健的評估，並定期重新標註以反映當前策略能力。

- **建立監控儀表板**  
  追蹤工具調用率、無工具成功率、工具帶來的增益與損害間的差距、平均延遲與成本，協助產品團隊判斷是否需要調整工具集合或獎勵設計。
