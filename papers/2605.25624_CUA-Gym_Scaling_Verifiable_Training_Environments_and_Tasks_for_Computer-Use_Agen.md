# CUA-Gym：擴展電腦使用代理之可驗證訓練環境與任務規模

## ⚡ TL;DR

電腦使用代理缺乏可驗證的大規模強化學習訓練資料，限制了能力擴展。
提出CUA-Gym多代理協同生成任務、環境與獎勵，並建構模擬網頁環境Hub擴展訓練規模。
產出三萬餘筆驗證資料與百種環境，模型於OSWorld-Verified達72.6%，成果全數開源。

## 摘要翻譯

可驗證獎勵強化學習（Reinforcement Learning with Verifiable Rewards, RLVR）已在數學、工具使用與軟體工程等領域帶來突破，然而其擴展至電腦使用代理（Computer-Use Agents, CUA）時，卻因具備確定性獎勵（deterministic rewards）的可擴展訓練資料稀缺而遭遇瓶頸。為電腦使用代理建構此類資料需要彼此一致的任務指令（task instruction）、可執行環境（executable environment）與可驗證獎勵（verifiable reward）。然而，人工精選基準測試（hand-curated benchmarks）雖具備高獎勵保真度（reward fidelity），但涵蓋的應用較少；而基於 LLM 即評審（LLM-as-judge）的資料集雖能大規模擴展，卻缺乏可靠的驗證。我們提出 CUA-Gym，一個可共同生成任務指令、環境狀態（environment states）與獎勵函數（reward functions）的可擴展流程（scalable pipeline）。具體而言，生成器代理（Generator agent）負責建構初始環境狀態（initial environment state）與黃金環境狀態（golden environment states），而獨立的鑑別器代理（Discriminator agent）則依據任務規格撰寫獎勵函數。編排器代理（Orchestrator agent）在執行階段驅動兩者進行多輪迭代（iterative rounds）。生成的訓練元組（training tuples）隨後通過最終過濾器（final filter），結合 LLM 多數決（LLM majority voting）與代理展開（agent rollouts），確保品質超越每項任務的對抗驗證循環（adversarial loop）所能達成的水準。為了解決訓練環境稀缺的問題，我們進一步合成 CUA-Gym-Hub，一套涵蓋廣泛的高保真度（high-fidelity）模擬網頁應用程式（mock web applications），其基於真實世界軟體使用分佈（real-world software-use distributions），以數量級擴展 CUA RLVR 資料的規模。利用此流程，我們建構了 CUA-Gym，一個包含 32,112 筆已驗證 RLVR 訓練元組、基於 110 個環境的資料集。以 GSPO 在 CUA-Gym 上訓練後，我們的 CUA-Gym-A3B 與 CUA-Gym-A17B 在 OSWorld-Verified 上分別達到

## 深度分析

#### 方法論解析

CUA-Gym 的核心方法論在於解決電腦使用代理 (Computer-Use Agents, CUAs) 領域中，可驗證獎勵強化學習 (Reinforcement Learning with Verifiable Rewards, RLVR) 的結構性瓶頸。不同於數學或程式碼領域僅需「問題陳述 + 可檢查答案」的二元組，CUA 的 RLVR training tuple (訓練元組) 必須同時包含 task instruction (任務指令)、executable environment (可執行環境) 與 reward function (獎勵函數) 三個相互依賴的工程產物 (engineering artifacts)。任何單一元件的瑕疵都會導致策略最佳化 (policy optimization) 失效，而人工撰寫單一 tuple 往往需耗費數小時的專家心力，且應用多樣性 (application diversity) 會使成本隨不同軟體的驗證介面 (verification interfaces) 呈指數增長。

為此，作者提出三代理協同生成架構。首先，Generator agent (生成器代理) 負責建構 initial environment state (初始環境狀態) 與 golden environment states (黃金環境狀態)，透過生成 `initial_setup.py` 與 `golden_patch.py` 來定義任務的起點與終點。其次，Discriminator agent (鑑別器代理) 僅依據 task specification (主題規格) 與任務描述，獨立撰寫 reward function (獎勵函數)，並透過 strict information-isolation (嚴格資訊隔離) 避免其接觸 golden state 的實作細節，從根本上抑制 reward hacking (獎勵駭取)。第三，Orchestrator agent (編排器代理) 作為迭代中樞，驅動 Generator 與 Discriminator 進行 iterative rounds (迭代回合) 的對抗循環 (adversarial loop)：Discriminator 撰寫的獎勵函數必須在真實執行環境中區分初始狀態與黃金狀態，若無法通過驗證，Orchestrator 會產生反饋並要求修訂，直至 reward function 能穩定輸出確定性獎勵 (deterministic rewards)。

然而，單一任務的對抗驗證仍可能遺漏邊界案例。因此，流程末端設置 final filter (最終過濾器)，結合 LLM majority voting (LLM 多數決) 與 agent rollouts (代理展開)：後者讓實際代理在環境中執行軌跡，確認獎勵函數在真實行為分佈下仍保持 reward fidelity (獎勵保真度)。這道關卡確保了通過篩選的 training tuples (訓練元組) 具備超越單任務對抗循環的品質。

在環境層面，CUA-Gym 進一步將 environment diversity (環境多樣性) 視為獨立擴展軸。現有 benchmark 往往受限於真實軟體生態的稀缺性，因此作者建構 CUA-Gym-Hub：一套高保真度 (high-fidelity) 的 mock web applications (模擬網頁應用程式)。該流程先以 O*NET 職業分類與 Anthropic Economic Index 的真實世界軟體使用分佈 (real-world software-use distributions) 為依據，選定目標應用類型；再透過多代理合成流程實作具備 unified state API 的自包含模擬網頁應用，並以自動化瀏覽器測試驗證互動功能。這些環境具備可重現、可程式化且結構上忠於真實對應軟體的特性，每個環境可在共享的 resettable application pool 上支撐數千個獨立任務，從而將 task synthesis (任務合成) 與 environment scaling (環境擴展) 解耦。

最終產出的 CUA-Gym 資料集包含 32,112 個經過驗證的 RLVR 訓練元組，涵蓋 110 個環境（16 個桌面應用與 94 個來自 CUA-Gym-Hub 的合成網頁環境），構成目前最大規模的開源 CUA RLVR 資料集。

#### 實驗數據解讀

實驗部分以 Qwen3.5-35B-A3B 與 Qwen3.5-397B-A17B 兩個開源 Mixture-of-Experts (MoE) backbone 為基礎，採用 GSPO (Group... 文中未展開全名，但定位為類似 GRPO 的強化學習演算法) 進行 RLVR 訓練，得到 CUA-Gym-A3B 與 CUA-Gym-A17B 兩個檢查點。

在 OSWorld-Verified 基準測試上，兩個模型分別達到 62.1% 與 72.6% 的成績。這組數據具有三層意涵：其一，CUA-Gym-A3B 僅以約 A17B 基座模型 1/10 的總參數量，便達到與未經訓練的 A17B base 相當的效能，顯示 RLVR 訓練在參數效率 (parameter efficiency) 上的巨大潛力；其二，72.6% 的成績在相近規模的開源 CUAs 中創下 state-of-the-art；其三，效能隨資料量與環境數量平滑上升，擴展曲線 (scaling curves) 尚未飽和，暗示持續擴充仍具收益。

更具說服力的是跨平台遷移表現。在 held-out benchmark (保留測試基準) WebArena 上，相同檢查點相較於基座模型亦有顯著提升。這表明從 CUA-Gym-Hub 的合成網頁環境所學得的策略，能夠遷移至真實瀏覽器基準，部分消解了「模擬環境僅能學到表面特徵」的疑慮。

作者進一步執行消融分析，證實 environment diversity (環境多樣性) 是與資料量互補的獨立擴展軸。當環境池從 10 個擴充至 80 個時，所獲得的效能增益無法單純透過增加軌跡數量 (trajectory volume) 來彌補。這項發現對 CUA 領域的資料建構策略具有指導意義：未來的資源投入不應僅追求任務數量的堆疊，更需優先擴展環境覆蓋率。

此外，研究觀察到一項值得注意的湧現行為 (emergent behavior)：RL 訓練自發性地誘導出 multi-action tool calls (多動作工具呼叫)，在維持相同任務效能的前提下，將軌跡長度壓縮 33–45%。這種效率導向的行為湧現，與推理導向 RL 中觀察到的自發性驗證與自我反思 (self-reflection) 形成平行對照，暗示 RLVR 訓練可能同時重塑代理的行為策略與認知架構。

#### 與現有研究的比較

相較於既有文獻，CUA-Gym 同時滿足 scalable CUARLVR 所需的三項性質：deterministic verifiable rewards (確定性可驗證獎勵)、broad application coverage (廣泛應用覆蓋率) 與 scalable task diversity (可擴展任務多樣性)，填補了過往方法的缺口。

Hand-curated benchmarks (人工精選基準測試) 雖具備高 reward fidelity，但每個 tuple 需耗費大量專家工時，導致應用覆蓋率極低，無法支撐大規模 policy optimization。LLM-as-a-judge 或 VLM-as-a-judge 框架雖能擴展至任意任務，但引入的 reward noise (獎勵雜訊) 會破壞 RL 訓練的穩定性，無法提供 RLVR 所需的確定性訊號。Supervised datasets (監督式資料集) 雖涵蓋多樣應用，但僅提供 trajectory-level imitation targets (軌跡層級模仿目標) 而非 outcome rewards (結果獎勵)，本質上無法直接用於 RLVR。Code-native pipelines (原生程式碼流程) 雖能在 browser mocking environments (瀏覽器模擬環境) 中產生確定性獎勵，但規模與環境複雜度長期受限於人工編寫的程式碼範本。

CUA-Gym 的優勢在於將「環境建構」與「任務生成」皆代理化 (agentic)。透過 Generator、Discriminator 與 Orchestrator 的協作，將原本需數小時人工的工程產物壓縮為自動化流程；同時以 CUA-Gym-Hub 將環境規模擴展至 94 個高保真度網頁應用，使資料量較既有 CUA RLVR 資料集提升數個數量級 (orders of magnitude)。

儘管如此，本研究仍存在若干限制。首先，110 個環境中有 94 個為 mock web applications，僅 16 個為桌面應用，對於需要操作原生作業系統或複雜桌面軟體的任務，覆蓋率仍顯不足。其次，雖然 WebArena 上的遷移結果正面，但合成環境與真實動態網頁之間仍存在 sim-to-real gap，例如真實網站的登入機制、驗證碼、動態載入與 rate limiting 等並未完全模擬。第三，Discriminator 產生的 reward function 仍屬針對單一任務的客製化程式碼，其泛化性與維護成本在環境規模進一步擴大後可能成為新的瓶頸。

#### 可重現性評估

作者承諾將開源 (open-source) 完整的 synthesis pipeline (合成流程)、CUA-Gym 資料集、CUA-Gym-Hub 環境與模型權重，這在 CUA 領域屬於極為完整的開源力度，理論上能讓後續研究完整重現從資料生成到模型訓練的全流程。

然而，實際重現仍面臨若干挑戰。模型訓練採用 Qwen3.5-35B-A3B 與 397B-A17B 等 MoE backbone，對運算資源需求極高；資料合成階段需多次呼叫大型語言模型進行多代理迭代，並搭配 VM 環境執行 agent rollouts，基礎設施與 API 成本不容小覷。此外，CUA-Gym-Hub 的 mock web applications 雖具統一 API，但後續維護（如瀏覽器版本相容性、前端框架更新）需要持續的工程投入。若作者確實釋出包含自動化測試與環境重置機制的完整程式碼，將大幅降低社群的進入門檻；反之，若僅釋出靜態資料集，則環境的可重現性將打折扣。

#### 未來研究方向

環境保真度的躍升將是首要方向。當前 CUA-Gym-Hub 以 mock web applications 為主，未來可探索與真實瀏覽器實例的無縫整合，例如透過容器化技術動態部署真實開源網頁應用（如 WordPress、GitLab、Jira 等），或利用 live caching 機制在保護隱私的前提下擷取真實網站的靜態快照，進一步縮小 sim-to-real gap。

其次，桌面應用程式的擴展亟待突破。僅 16 個桌面環境限制了代理在 OS-level 操作的能力。未來可將相同的 agentic synthesis pipeline 應用於更多原生 GUI 應用（如 Excel、Photoshop、CAD 工具），並結合作業系統的 accessibility API 或螢幕解析技術，建構更廣泛的 executable environment 生態。

在獎勵函數層面，目前 Discriminator 針對每項任務生成專屬 reward function，維護成本隨規模遞增。未來可研究「可組合獎勵原語 (composable reward primitives)」或「可學習但具確定性約束的驗證器」，在保持 deterministic rewards 的前提下提升泛化性。同時，隨著環境複雜度增加，information-isolation (資訊隔離) 機制可能需要更嚴格的沙箱化 (sandboxing) 或密碼學承諾 (cryptographic commitment) 來防範更精巧的 reward hacking。

演算法層面，GSPO 與 GRPO 在 CUA 多模態軌跡上的收斂特性與樣本效率仍有待深入分析。未來可結合課程學習 (curriculum learning)，依據環境複雜度動態調整訓練批次，或探索 offline RLVR 與 online exploration 的混合範式，以降低對大規模代理展開的依賴。

最後，跨領域遷移與持續學習 (continual learning) 值得關注。本文已觀察到合成網頁環境到 WebArena 的正向遷移，但未來需系統性評估跨應用類型（如從文書處理遷移至試算表操作）的遷移效率，並建立持續從人類回饋或真實使用者軌跡中擴充 CUA-Gym-Hub 的機制，使 RLVR 資料生態能隨真實軟體演進而動態成長。

## 論文問答

**Q1：阻礙可驗證獎勵強化學習（RLVR）在電腦使用代理（CUA）領域取得突破的核心瓶頸是什麼？**

A：核心瓶頸在於具備確定性獎勵的可擴展訓練資料極度稀缺。與數學或程式碼領域不同，CUA 的訓練實例並非僅需問題敘述與可檢驗答案，而是由任務指令、可執行環境狀態與獎勵函數三者共同構成的複雜工程產物，彼此必須緊密協作。人工打造單一訓練元組往往耗費數小時的專家心力，且隨著應用多樣性增加而成本倍增，導致現有 CUA RLVR 資料集的規模遠遜於鄰近的文字領域。

**Q2：人工精選基準測試、LLM 即評審框架與監督式資料集為何無法滿足可擴展 CUA RLVR 的需求？**

A：人工精選基準雖具高獎勵保真度，但涵蓋的應用範圍過於狹隘，難以大規模擴展；LLM 或 VLM 即評審框架雖能廣泛評分各類任務，卻引入了獎勵雜訊，其非確定性的特性會破壞策略最佳化的穩定性。監督式資料集僅提供軌跡層級模仿目標而非結果獎勵，本質上無法用於強化學習；原生程式碼流程雖能產出確定性獎勵，但目前為止在環境規模與瀏覽器覆蓋率上仍相當受限。

**Q3：為何環境多樣性被視為與任務數量同等重要的擴展維度？**

A：真實世界中的知識工作者所使用的軟體景觀極為廣泛，代理必須具備跨應用遷移的能力，而非僅在單一狹窄領域中重複執行任務。現有基準測試僅覆蓋了實際軟體使用分佈中的一小片段，若訓練環境過於單一，策略極易過度擬合特定介面。因此，擴充環境廣度能促使代理學習可轉移的互動模式，是提升泛化能力與推動資料-效能擴展曲線的關鍵。

**Q4：CUA-Gym 流程如何協同生成可驗證 RLVR 訓練元組的三大核心元件？**

A：CUA-Gym 透過三個協調運作的程式設計代理，將過去需人工專家完成的工程工作自動化。生成器代理負責建構初始環境狀態與黃金環境狀態，鑑別器代理僅依據任務描述撰寫獎勵函數，而編排器代理則驅動兩者進行多輪迭代回合，直到獎勵函數能在執行中區分這兩種狀態。這種代理協同生成機制確保了任務指令、環境設定與獎勵函數三者相互一致，並能作為單一驗證過的訓練元組運作。

**Q5：CUA-Gym 採取了哪些機制來防止獎勵破解，並確保最終資料品質超越單項任務的對抗循環？**

A：流程在生成器代理與鑑別器代理之間實施嚴格的資訊隔離，避免獎勵函數利用隱藏線索或捷徑作弊。此外，所有生成的元組還須通過最終過濾器，結合 LLM 多數決與真實代理展開，以揪出那些雖通過單項對抗驗證、卻在實際代理行為下失效的案例。這種「對抗迭代加上行為壓力測試」的雙層品質把關，確保了 32,112 個訓練元組都具備足夠的保真度以支撐策略最佳化。

**Q6：作者為何選擇合成專屬的環境套件 CUA-Gym-Hub，而非僅依賴現有的真實應用程式？**

A：現有真實基準測試的應用覆蓋率過窄，且難以大規模重置或控制，無法滿足 RLVR 訓練所需的可重現性與可程式化性。作者依據職業分類與真實世界軟體使用分佈來篩選目標應用，再透過多代理合成流程建構具備統一狀態 API 的模擬網頁應用程式，使其在結構上忠實於真實對應軟體。這項設計將環境擴展與任務合成解耦，讓數千個不同的任務能在共享且可重置的環境池中生成，從而大幅擴展了可達成的資料規模。

**Q7：訓練後的模型在哪些基準測試上進行評估，這些測試分別衡量什麼能力？**

A：訓練後的 CUA-Gym-A3B 與 CUA-Gym-A17B 模型主要在 OSWorld-Verified 上進行評估，並額外在保留測試基準 WebArena 上驗證其泛化性。OSWorld-Verified 衡量代理在真實桌面與網頁環境中執行複雜任務的能力，而 WebArena 則專注於評估代理在真實瀏覽器中的網頁操作表現。在這兩個平台上進行評估，能同時驗證模型的絕對性能，以及從合成模擬環境到真實瀏覽器任務的跨平台遷移能力。

**Q8：CUA-Gym 訓練模型的主要效能成果為何，與先前開源 CUA 相比有何優勢？**

A：以 GSPO 在 CUA-Gym 上訓練後，A3B 與 A17B 模型在 OSWorld-Verified 上分別達到 62.1% 與 72.6%，在各自規模的開源電腦使用代理中創下新的最佳表現。值得注意的是，較小的 A3B 模型已能媲美未經訓練的 A17B 基礎模型，且總參數量僅約為後者的十分之一，顯示高品質 RLVR 資料能帶來極高的訓練效率。兩個檢查點在保留的 WebArena 基準上亦有所提升，證明訓練效益確實能遷移至訓練環境之外。

**Q9：擴展實驗揭示了資料量、環境多樣性與模型效能之間的何種關係？**

A：實驗顯示效能隨資料量增加與環境池擴大而平穩提升，這兩者是互補而非可互相替代的擴展軸線。關鍵發現是，將環境池從 10 個擴充至 80 個所帶來的增益，是單純增加軌跡數量所無法彌補的，這從實證上確立了環境多樣性作為獨立擴展維度的地位。此外，作者觀察到強化學習訓練會自發誘導多動作工具呼叫，在維持相同任務效能下將軌跡長度壓縮 33–45%，展現出一種新興的效率行為。

**Q10：CUA-Gym 流程與 CUA-Gym-Hub 在實務上可直接應用於哪些場景？**

A：研究團隊與開發者可利用開源的合成流程，針對自身目標應用快速生成新的可驗證 RLVR 訓練元組，無需負擔人工撰寫每個元組的昂貴成本。CUA-Gym-Hub 提供了一套可控制、可重置的模擬網頁應用程式，作為標準化的底層環境，支援電腦使用代理的跨領域訓練與評估。這些資源對於自動化數位知識工作——例如資料輸入、電子郵件管理與試算表操作——特別有價值，因為這些場景極度依賴任務完成與否的確定性驗證。

**Q11：相較於 LLM 即評審方法，確定性獎勵驗證在產品層面部署 CUA 系統時有何優勢？**

A：確定性獎勵排除了 LLM 即評審評分中固有的雜訊與不一致性，這對於大規模強化學習訓練期間維持策略最佳化的穩定性至關重要。在生產環境中，可驗證獎勵提供了明確且可稽核的成功或失敗訊號，使開發者更容易診斷代理錯誤，並向終端使用者保證服務層級的可靠性。這種可靠性對企業自動化產品尤為關鍵，因為模糊或波動的成功標準可能導致代價高昂的錯誤，並損害使用者信任。

**Q12：開源 CUA-Gym 可能對電腦使用代理的廣泛研究領域產生何種影響？**

A：透過公開完整的合成流程、資料集、環境與模型，作者大幅降低了可重現 CUA RLVR 研究的進入門檻，讓學術界與產業界得以擺脫小型人工精選資料集的束縛。這種大規模可驗證訓練資料的民主化，有望在 CUA 領域催化出類似數學與程式碼生成領域曾出現的資料-效能擴展突破。此外，將環境多樣性確立為經驗證的擴展軸線，能引導社群將精力投入建構更豐富、更全面的應用生態，而非僅在單一領域中堆疊更多任務。

**Q13：目前的 CUA-Gym 資料集與環境套件在結構上仍存在哪些限制或覆蓋缺口？**

A：儘管 CUA-Gym-Hub 顯著擴展了覆蓋範圍，但目前套件主要由合成的模擬網頁應用程式與僅 16 個桌面應用程式組成，可能尚未完全捕捉專有軟體或高度動態真實應用的完整複雜度。合成流程本身依賴底層大語言模型的程式碼生成能力，因此生成器或鑑別器產生的錯誤仍可能滲入最終資料集，即便已設有過濾機制。此外，現階段聚焦於網頁與桌面環境，也意味著行動作業系統或具備非標準介面的複雜企業軟體尚未被納入。

**Q14：在哪些情況下，CUA-Gym 流程可能無法產出有效訓練元組，或讓細微的獎勵破解持續存在？**

A：當生成器代理無法忠實重現特定專業真實應用程式的複雜狀態邏輯時，產出的模擬環境可能與真實行為產生偏差，導致無效元組。雖然流程採用了資訊隔離與最終過濾，鑑別器仍可能撰寫出過度擬合表面狀態差異、而非真正任務完成度的獎勵函數，特別是當 LLM 多數決與代理展開檢查未能窮盡邊緣案例時。對於需要細膩視覺理解或不穩定網頁動態下的多步驟時序推理任務，若自動化瀏覽器測試未能完整模擬對抗性代理行為，也可能讓這類案例通過驗證。

**Q15：CUA-Gym 為電腦使用代理的規模化與改進指出了哪些未來研究方向？**

A：未來研究應將環境合成流程擴展至原生桌面應用程式、行動平台以及包含驗證碼與速率限制等動態元素的即時網頁服務，在超越模擬環境的同時保留可重置性。研究者亦可進一步探究強化學習過程中觀察到的自發多動作工具呼叫行為，嘗試在更大模型中刻意誘導並最佳化這類效率增益。最後，開發更強健的對抗性驗證機制，並將環境池擴展至數百甚至數千個應用程式，將是維持資料-效能擴展曲線並縮小與專有前沿模型差距的關鍵。

## 實務應用指南

### 適用場景

1. **跨應用企業流程自動化（RPA 2.0）**  
   適用於需要橫跨多個 SaaS 工具（如 Gmail、Notion、Excel、內部 CRM）執行任務的場景。例如「讀取 Notion 客戶資料庫，依據條件篩選後，在 Gmail 發送個人化郵件並夾帶桌面上的報價單」。CUA-Gym 的聯合生成流程可為這類多步驟、跨平台任務產出確定性獎勵的訓練元組，避免傳統 LLM-as-judge 帶來的獎勵雜訊。

2. **高保真度軟體測試與 QA 自動化**  
   針對需要驗證複雜使用者路徑的產品團隊，可利用 CUA-Gym-Hub 快速建立模擬網頁應用程式作為測試沙盒。透過生成器代理與鑑別器代理的對抗循環，自動產生「執行特定操作後，系統狀態必須滿足某項後設條件」的測試案例，並以可執行的獎勵函數作為自動化斷言（assertion）。

3. **客服與後台營運代理訓練**  
   金融、電商或物流產業中，後台人員經常需要在多個網頁後台之間核對資料、審核訂單或更新庫存。利用 CUA-Gym 的規模化合成能力，可基於真實世界軟體使用分佈（如 O*NET 與 Anthropic Economic Index）建構貼近實務的模擬環境，訓練出具備跨平台操作能力的電腦使用代理（CUA）。

4. **新軟體上線前的模擬訓練環境**  
   當企業導入新的內部系統時，可利用 CUA-Gym-Hub 的環境合成流程，在真實系統上線前快速建立結構忠實的 mock web applications。員工或代理模型可在這些高保真度環境中演練操作流程，同時利用可驗證獎勵強化學習（RLVR）自動評分，降低正式環境的操作風險。

5. **資料遷移與批次處理任務**  
   適用於需要將資料從 A 平台整理、轉換後寫入 B 平台的重複性工作。例如從網頁報表下載 CSV、在桌面試算表進行樞紐分析，再將結果上傳至雲端資料庫。CUA-Gym 能為這類任務同時生成初始環境狀態、黃金環境狀態與獎勵函數，確保代理學習的是結果正確性而非僅僅模仿操作軌跡。

### 實作前置條件

**資料與環境**
- **基礎模型**：需準備一個開源的多模態語言模型（MoE 架構為佳，如論文採用的 Qwen3.5 系列）作為策略初始化的基礎模型。
- **環境基底**：至少需部署 CUA-Gym-Hub 中的部分模擬網頁應用程式，或自行透過論文提供的多代理合成流程建立新的可執行環境。若訓練目標包含桌面應用，則需準備對應的 VM 映像檔。
- **主題規格**：依據目標產業準備應用程式清單與高階任務描述，作為啟動生成器代理與鑑別器代理的種子輸入。

**運算資源**
- **訓練端**：以論文規模（32K 訓練元組、110 個環境）為參考，RLVR 訓練需具備數十張高端 GPU（如 A100/H100）的叢集，並搭配高速網路與大量記憶體以支援 MoE 模型的稀疏啟動與 GSPO 的群組採樣。
- **環境端**：需額外的 VM 叢集或容器化平台（如 Kubernetes）來平行托管數百至數千個瀏覽器模擬環境實例，供資料合成階段的代理展開與獎勵函數執行使用。

**技術能力**
- **強化學習工程**：熟悉策略最佳化演算法（GRPO/GSPO）、獎勵塑形（reward shaping）與分散式訓練框架。
- **全端開發與 DevOps**：需能維護模擬網頁應用程式的統一狀態 API、撰寫自動化瀏覽器測試，並具備 VM 生命週期管理與網路隔離經驗。
- **代理系統設計**：理解多代理協作架構，能實作資訊隔離機制，並調度編排器代理驅動生成器與鑑別器的迭代回合。

### 實作步驟建議

**步驟一：需求盤點與環境選型**  
參考論文方法，先以職業分類學（如 O*NET）與軟體使用分佈數據，盤點目標使用者日常涉及的應用程式。優先選擇高頻且具驗證介面的應用（如郵件、試算表、專案管理工具），確保後續能產出具確定性獎勵的任務。

**步驟二：部署 CUA-Gym-Hub 與環境驗證**  
下載論文開源的 CUA-Gym-Hub，或啟動多代理環境合成流程，為每個選定應用建立自包含的模擬網頁應用程式。每個環境必須提供統一的狀態 API，並通過自動化瀏覽器測試確認互動功能正確，才能進入後續的任務合成池。

**步驟三：啟動三代理協同合成**  
針對每個主題規格，依序執行：(1) 生成器代理建構初始環境狀態與黃金環境狀態；(2) 鑑別器代理僅依據任務指令撰寫獎勵函數，兩者間維持嚴格資訊隔離；(3) 編排器代理執行獎勵函數，若無法區分兩種狀態則回饋修訂，直至對抗循環收斂。

**步驟四：執行最終過濾與品質確保**  
通過對抗循環的訓練元組，需再經最終過濾器：先以 LLM 多數決檢視任務合理性，再透過代理展開於真實環境中執行，確認獎勵函數在實際代理行為下仍保持正確，剔除僅在靜態狀態下過關的瑕疵案例。

**步驟五：RLVR 策略最佳化**  
將過濾後的資料集以 GSPO 演算法進行策略最佳化。建議從小規模環境子集（如 10 個）開始驗證資料-效能擴展曲線，再逐步擴充至 80 個以上環境，觀察環境多樣性帶來的增益是否飽和。

**步驟六：產品化部署與持續迭代**  
將訓練完成的 CUA-Gym-A3B/A17B 等檢查點，透過瀏覽器自動化框架（如 Playwright）橋接至真實系統。建立監控機制追蹤代理在保留測試基準（如 WebArena）上的表現，並將真實失敗案例回流至資料合成流程，動態擴充 CUA-Gym-Hub 與訓練元組。

### 潛在風險與注意事項

- **獎勵駭入（Reward Hacking）**  
  若生成器代理與鑑別器代理之間資訊隔離不夠嚴格，模型可能學會利用獎勵函數的實作漏洞而非完成真正任務。務必確保鑑別器僅能存取任務指令與環境介面，無法接觸生成器的內部狀態或程式碼。

- **模擬與真實環境落差**  
  CUA-Gym-Hub 雖為高保真度模擬，但與真實桌面應用程式或動態網頁仍有差異。論文採用 16 個真實桌面應用程式搭配 94 個模擬網頁環境的混合策略，實務上應保留一定比例真實環境訓練資料，以維持跨平台轉移能力。

- **環境維護成本被低估**  
  模擬網頁應用程式需隨真實軟體版本更新（如 Gmail 或 Notion 介面改版）而調整。建議將自動化瀏覽器測試與環境建置流程嵌入 CI/CD，否則環境漂移將迅速侵蝕訓練資料的獎勵保真度。

- **規模化迷思：重數量輕多樣性**  
  論文明確指出環境多樣性是獨立於資料量的擴展軸。僅僅在少數幾個應用中大量生成任務，無法彌補環境覆蓋不足的瓶頸。產品團隊應將「新增一個應用環境」視為與「新增一萬筆資料」同等重要的投資。

- **運算與延遲挑戰**  
  MoE 模型的 RLVR 訓練與大規模 VM 環境平行執行對基礎設施壓力極大。若資源有限，建議先利用論文釋出的開源模型檢查點進行領域適應（domain adaptation），而非從頭訓練完整流程。

### 與其他技術的整合建議

- **與現有 RPA／低代碼平台整合**  
  將 CUA-Gym-Hub 作為企業內部的「訓練沙盒」，讓既有 RPA 流程（如 UiPath、n8n）的邏輯先在此驗證。訓練後的 CUA 可透過統一狀態 API 輸出標準化操作序列，再由 RPA 引擎轉譯為正式環境的執行指令，降低導入風險。

- **與瀏覽器自動化框架整合**  
  論文中的模擬環境已具備瀏覽器基礎，產品化時可無縫銜接 Playwright、Puppeteer 或 Selenium。建議在 RLVR 訓練後期引入「真實瀏覽器微調階段」，讓代理適應真實網頁的渲染延遲與動態載入行為。

- **與企業知識庫及 RAG 整合**  
  將內部操作手冊、教學影片與常見問題文件接入生成器代理的上下文檢索模組。如此一來，CUA-Gym 不只能生成通用任務，更能自動產出符合公司內部規範的領域特定任務指令與驗證規則。

- **與 CI/CD 及 MLOps 管線整合**  
  把資料合成流程（含環境建置、對抗循環、最終過濾）封裝為容器化工作流。當目標應用程式發布新版本或內部系統介面調整時，自動觸發環境更新與新任務生成，實現訓練資料的持續擴充（continual learning）。

- **與監督式微調（SFT）管線整合**  
  對於已有大量人工操作軌跡的團隊，可先用這些軌跡進行冷啟動監督式微調，再銜接 CUA-Gym 的 RLVR 階段。這種「SFT 暖機 + RLVR 優化」的兩階段策略，通常比單純從頭進行強化學習更穩定，且能更快收斂。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議從「為何需要確定性獎勵」這個核心概念入手，把 CUA-Gym 理解為一套「自動出題且自動改考卷」的系統。先掌握 RLVR 與 LLM-as-judge 的關鍵差異——前者像單元測試有明確對錯，後者像作文評分容易流於主觀——再逐步了解生成器、鑑別器與編排器三者的分工，無需一開始就深入 GSPO 的數學推導。

**給 AI 工程師**  
請重點關注資訊隔離的實作細節、GSPO 訓練的分散式配置，以及 VM 環境的平行化調度。論文中最值得移植到生產環節的是最終過濾器：它結合 LLM 多數決與代理展開，能有效攔截那些在靜態對抗中過關、卻在動態執行中失效的瑕疵元組。這段程式實作是確保資料品質的關鍵工程防線。

**給研究人員**  
請著重分析環境多樣性與資料量的擴展曲線，以及從模擬網頁應用程式到真實瀏覽器基準（WebArena）的轉移學習現象。論文觀察到的「多動作工具呼叫自發湧現」——即 RL 訓練後代理自動學會壓縮軌跡——是一個值得深挖的湧現行為，可與數學領域中自發驗證、自我反思的現象進行跨領域對照研究。

**給產品經理**  
這篇論文提供了一套開源、可規模化的資料生產線，讓團隊無需耗費大量人力標註，就能建立領域專屬的 CUA 訓練資料。關鍵啟示是：產品能力的天花板不只取決於任務數量，更取決於覆蓋的應用多樣性；投資環境建置與投資模型訓練同等重要。建議將 CUA-Gym-Hub 視為可重複使用的「數位員工訓練場」，並優先評估哪些內部流程最適合首批自動化。
