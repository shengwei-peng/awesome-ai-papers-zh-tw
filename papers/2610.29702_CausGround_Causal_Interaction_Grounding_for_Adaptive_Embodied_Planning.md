CausGround 的核心方法論建立在「動作中心因果知識」(action-centered causal knowledge) 的抽象化之上，試圖解決具身智能體 (embodied agents) 在新環境中部署時缺乏互動動態 (interaction dynamics) 知識的根本問題。整體框架可分為三個關鍵階段：知識蒸餾 (knowledge distillation)、世界狀態表徵 (world-state representation) 建構、以及任務相關因果基礎化 (task-relevant causal grounding)。

**第一階段：互動經驗的因果蒸餾**

CausGround 採用非參數化 (non-parametric) 設計，避免了傳統微調 (fine-tuning) 或強化學習 (reinforcement learning) 所需的大量環境特定資料與重複最佳化。其核心思想是將開放世界互動經驗 (open-world interaction experience) 抽象為「動作前置條件」(action preconditions) 與「動作效果」(action effects) 的成對表示。具體而言，每個動作 $a$ 被分解為：
- 前置條件集合 $P(a)$：描述動作可執行前必須成立的狀態條件
- 效果集合 $E(a)$：描述動作執行後世界狀態的變化

這種分解使得因果知識能夠跨任務、跨環境重複使用，因為同一個動作（如 Grab(cup)）在不同情境下的前置條件與效果具有結構相似性。

**第二階段：分解式世界狀態表徵**

論文提出一個關鍵的表徵設計——分解式世界狀態表徵 (factorized world-state representation)，其特點在於同時捕捉兩類資訊：
1. **物件屬性 (object attributes)**：例如 Robot.hand = free、Fridge.door = open、Cup.graspable = true
2. **物件間關係 (inter-object relations)**：例如 near(Robot, Cup)、on(Cup, Table)

這種雙重表徵的重要性在於：單純的物件屬性無法表達「機器人必須靠近杯子才能抓取」這類空間關係約束；而單純的關係表徵則無法表達「杯子必須是可抓取的」這類屬性約束。論文圖 1 中的範例清楚展示了此設計——PutIn(Cup, Fridge) 的可執行性需要同時滿足 Robot.holding = cup（屬性）與 Fridge.door = open（屬性），以及相應的空間接近性（關係）。

**第三階段：任務相關因果基礎化與規劃**

在規劃階段，CausGround 將當前觀察 (current observation) 與任務描述 (task description) 映射至相同的表徵空間，從而從 CausGround 函式庫中檢索並組合任務相關的因果依賴，形成局部因果圖 (local causal graph)。此圖支援兩種推理模式：
- **逆向推理 (backward reasoning)**：從目標狀態出發，回溯推導哪些前置條件必須先被滿足。例如，要 PutIn(Cup, Fridge)，必須先 Open(Fridge) 與 Grab(Cup)。
- **前向推理 (forward reasoning)**：從當前狀態出發，預測動作執行後的狀態變化，用於動作選擇 (action selection) 與多步驟規劃 (multi-step planning) 的驗證。

這種雙向推理機制使得規劃器能夠避免前置條件違反 (precondition violations) 導致的無效動作 (invalid actions) 與重複嘗試 (repeated attempts)，這正是長時程執行 (long-horizon execution) 中累積失敗的主要來源。

**與參數化適應方法的比較**

現有的非參數化方法（如 Ginting et al., 2025; Buoso et al., 2025）通常將經驗保留為非結構化軌跡 (unstructured trajectories) 或任務級記憶 (task-level memories)。這類方法的根本限制在於：
- 難以識別經驗中哪些部分是因果相關 (causally relevant) 而非偶然 (incidental)
- 跨任務重用性差
- 難以在當前視覺場景中進行基礎化 (grounding)

CausGround 的關鍵創新在於將經驗蒸餾為「動作中心因果知識」，並透過分解式世界狀態表徵實現精細的場景基礎化。這使得同一個因果知識片段可在不同任務、不同場景中被重用。

1. 同時捕捉物件屬性與物件間關係，解決了現有方法「不總是聯合捕捉」的限制
2. 結構化程度足以支援精確的前置條件檢查與效果預測

用於技能示範教學或工業培訓模擬。CausGround 的可解釋因果圖可作為教學輔助，讓學員理解「為何必須先做 A 才能做 B」，強化程序性知識的傳遞。

## 實作前置條件

**資料需求**
- **互動軌跡資料**：需收集目標環境中各動作的成功執行軌跡，建議每個動作至少 10–30 筆範例以萃取出穩定的因果模式。
- **物件與關係標註**：需具備物件屬性（graspable、movable、material 等）與物件間關係（near、on、inside 等）的標註資料或自動標註流程。
- **任務描述集**：用於評估規劃品質的任務集合，需涵蓋長時程（≥5 步）且具備明確目標狀態。

**運算資源**
- **MLLM 推論資源**：需具備推論等級的 GPU（如 A100、H100 或同等級雲端資源），用於視覺理解與規劃生成。
- **知識庫儲存**：因果知識庫為非參數化結構，可採 JSON / 圖資料庫（如 Neo4j）儲存，單一環境規模通常在數 MB 至數十 MB。
- **即時性需求**：若應用於即時機器人控制，建議規劃延遲在 1–3 秒內的推論管線。

**技能前提**
- **機器人學基礎**：理解動作語意、前置條件、效果的概念。
- **MLLM Prompt Engineering**：熟悉如何引導多模態模型輸出結構化資訊。
- **知識表示**：熟悉圖結構、屬性-關係分解等表徵方法。
- **領域專家協作**：針對特定應用場景，需有領域專家協助驗證因果知識的正確性。

## 實作步驟建議

**步驟一：定義動作集與世界狀態表徵**
盤點目標環境中所有可執行的高階動作（如 Grab、Open、PutIn、SwitchOn），並定義分解式世界狀態的 schema，包含物件屬性欄位與物件間關係類型。建議從小規模動作集（10–20 個）開始驗證。

**步驟二：收集與標註互動經驗**
在目標環境中執行各動作並記錄軌跡，標註每個時間點的世界狀態與動作結果。可採人工示範、遙操作或現有資料集（如 VirtualHome、RoboCasa）作為起點。

**步驟三：蒸餾因果知識**
從軌跡中識別每個動作的前置條件（執行前必須成立的狀態）與效果（執行後改變的狀態），並組織成以動作為中心的因果條目。此步驟可結合 MLLM 進行自動化萃取，再由人工抽樣驗證。

**步驟四：建立 CausGround 函式庫**
將蒸餾後的因果知識儲存為可查詢的函式庫，每條目包含動作名稱、前置條件清單、效果清單與相關物件/關係類型。

**步驟五：整合觀察接地流程**
在規劃時，將當前視覺觀察透過 MLLM 轉換為相同的分解式世界狀態表徵，並從函式庫中擷取任務相關的因果依賴，構建局部因果圖。

**步驟六：執行雙向推理與規劃**
結合逆向推理（從目標狀態回推前置條件）與前向推理（從當前狀態預測動作效果），由 MLLM 規劃器生成可執行的動作序列。

**步驟七：閉迴路評估與迭代**
在模擬環境（建議先採用 VirtualHome / RoboCasa）與真實機器人上進行閉迴路測試，記錄失敗案例並回頭檢視因果知識的完整性與正確性，反覆迭代。

## 潛在風險與注意事項

**風險一：因果知識萃取錯誤**
若前置條件或效果標註不正確，將直接導致規劃失敗。**緩解方式**：建立專家審核流程、設定自動化一致性檢查（如檢查效果是否與下一動作的前置條件一致）、保留人工覆寫介面。

**風險二：環境變化下的知識失效**
當環境配置（物件類型、空間佈局）改變時，舊的因果知識可能不再適用。**緩解方式**：設計知識版本管理、加入信心分數機制、保留線上增量更新能力。

**風險三：MLLM 觀察接地的錯誤傳播**
視覺觀察轉為世界狀態時的 MLLM 錯誤會向下傳播至整個規劃。**緩解方式**：採用多模型投票、加入不確定度估計、對關鍵物件/關係進行二次驗證。

**風險四：計算延遲影響即時性**
MLLM 推論成本較高，可能無法滿足即時控制需求。**緩解方式**：快取常見任務的因果圖、預先生成候選規劃、採分層架構（高階規劃與低階控制分離）。

**風險五：安全與可預測性**
在真實機器人應用中，錯誤的動作序列可能導致硬體損壞或人身傷害。**緩解方式**：在執行層加入硬體安全護欄、限制高風險動作需人工確認、保留緊急停止機制。

## 與其他技術的整合建議

**與視覺-語言-動作模型（VLA）整合**
CausGround 專注於高階規劃層，可與低階動作生成的 VLA 模型（如 RT-2、OpenVLA）形成互補：高階規劃決定「做什麼」，VLA 負責「怎麼做」。建議介面設計為高階動作序列的標準化輸出。

**與 SLAM / 場景圖整合**
場景圖（Scene Graph）已具備物件與關係的結構化表徵，可直接作為 CausGround 的世界狀態輸入，降低重複建置成本。建議採用 3D-WSG 或 OpenSceneGraph 等開放格式作為中介。

**與任務規劃器（如 PDDL 求解器）整合**
若組織已使用 PDDL 或 HTN 等傳統規劃器，可將 CausGround 的因果知識轉換為 PDDL 的 precondition 與 effect 欄位，結合傳統求解器的最佳化能力。

**與機器人作業系統（ROS 2）整合**
建議將 CausGround 封裝為 ROS 2 節點，透過標準化的 action / topic 介面與導航、感知、控制模組溝通，方便整合到既有機器人軟體堆疊。

**與持續學習系統整合**
雖 CausGround 為非參數化設計，但仍可與線上經驗收集管線整合，支援知識庫的增量擴充。建議設計明確的「探索-驗證-入庫」流程，避免低品質經驗污染知識庫。
