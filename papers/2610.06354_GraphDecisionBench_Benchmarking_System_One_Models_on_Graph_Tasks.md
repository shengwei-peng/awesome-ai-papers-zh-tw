## ⚡ TL;DR

System One 模型在圖任務上的能力未明，現有基準難以區分結構、圖文與序列決策品質。
本文提出 GraphDecisionBench，含圖認知、圖文決策與序列決策三任務族，採配對輸入與啟發式控制。
實驗評估十四種介面配置，發現鄰接正確非結構正確、圖文聯合未必提升預測、可行解亦非高品質。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）在圖理解（Graph Understanding）與圖決策（Graph Decision-Making）方面的應用日益受到關注，而 System One 模型（如 Jev）則直接從提供的選項中進行選擇。然而，System One 模型在圖相關任務（Graph-Related Tasks）上的能力仍不明確。我們提出 GraphDecide，一個結合結構任務輪廓（Structural Task Profiles）、配對圖文輸入對比（Matched Graph-Text Input Contrasts）與啟發式提案控制（Heuristic-proposal Controls）的模型無關基準（Model-Independent Benchmark），用以診斷圖決策效能（Graph Decision Performance）。我們評估 Jev 及相關的選擇式模型（Choice-based Models），並與語言模型基線（Language-Model Baselines）進行比較，涵蓋十四種模型介面配置（Model-Interface Configurations）。Jev 的結果展示了此基準的核心區辨：準確的鄰接識別（Adjacency Recognition）並不保證更全面的結構正確性（Structural Correctness）；整合圖文輸入（Graph-Text Input）並未持續提升預測；可行建構（Feasible Construction）亦無法確立高解品質（Solution Quality）。其任務契約（Task Contracts）、候選介面（Candidate Interfaces）與評分規則（Scoring Rules）支援跨原生選擇器（Native Selectors）與語言模型適配器（Language-Model Adapters）的比較。程式碼與彙整結果（Aggregate Results）可於 https://github.com/VictorYXL/JevGraphBench 取得。

### 核心貢獻（3～5點）
- 提出 GraphDecisionBench（GraphDecide），一個模型無關基準，整合結構任務輪廓、配對圖文輸入對比與啟發式提案控制三項設計元素，專門用於診斷圖決策效能
- 系統評估十四種模型介面配置，橫跨選擇式模型（如 Jev）與語言模型基線，提供跨模型類型的公平比較框架
- 揭示三項關鍵洞見：鄰接識別準確性不等於結構正確性、整合圖文輸入未必提升預測、可行建構不等於高解品質
- 透過任務契約、候選介面與評分規則三大機制，支援原生選擇器與語言模型適配器之間的可比性評測

### 適合對象
從事圖神經網路、大型語言模型評測、基準測試設計或人工智慧決策系統研究的學者與工程師；特別適合關注模型於結構化資料上推理能力、選擇式模型與生成式模型比較，以及圖任務診斷方法論的研究團隊。

## 深度分析

#### 方法論解析

GraphDecisionBench 的方法論核心在於將「圖決策能力」的評估從單一彙整分數（pooled accuracy）拆解為三個互補且可獨立診斷的任務族（task families），並透過統一的「選擇介面」（choice interface）將模型執行與任務規格解耦。

**1. 任務規格與模型執行的解耦設計**

此基準採用「任務契約（task contracts）」的概念，將圖實例（graph instances）、答案空間（answer spaces）、參考評估器（reference evaluators）與評分規則（scoring rules）獨立於模型本體定義。模型僅需透過「適配器（adapter）」提供決策即可參與評估。這種設計使得同一評估契約可同時適用於原生選擇器（native selectors，如 Jev）與語言模型適配器（language-model adapters），實現跨模型族群的公平比較。

**2. 三層診斷框架**

- **RQ1（圖認知，Graph Cognition）**：透過「結構任務輪廓（structural task profiles）」評估模型對局部連接（如鄰接識別，adjacency recognition）與整體圖性質（涵蓋路徑 paths、環 cycles、連通性 connectivity）的判斷能力。關鍵設計在於區分「鄰接識別正確」與「更廣泛結構正確性（broader structural correctness）」——前者僅需判斷兩節點是否相連，後者涉及路徑存在性、環結構等全局推理。

- **RQ2（圖文決策，Graph-Text Decision-Making）**：採用「配對圖文輸入對比（matched graph-text input contrasts）」設計，在固定文字證據與共享標籤錨點（label anchors）的條件下，比較純文字輸入、純關聯輸入（relational input）與兩者聯合輸入的效能差異。此設計直接回答「額外加入顯式邊緣資訊是否帶來預測增益」。

- **RQ3（圖上的序列決策，Sequential Decision-Making on Graphs）**：涵蓋旅行推銷員問題（TSP）、有號最大切割（signed MaxCut）、確定性影響力最大化（deterministic influence maximization）與二元模組度（binary modularity）。透過「候選池控制（candidate-pool controls）」區分三種建構模式：直接行動選擇（direct action selection）、池內隨機（within-pool random）與固定啟發式規則（fixed-rule comparisons），用以診斷模型選擇相對於外部啟發式提案的附加價值。

**3. 評估介面的標準化**

所有任務均透過統一的「候選介面（candidate interfaces）」運作，模型從供應選項中選擇並回傳機率（probabilities）。此設計與 Jev 等 System One 模型的操作模式天然契合，同時也允許語言模型透過適配器轉換為選擇形式。十四種模型介面配置（model-interface configurations）的設計確保涵蓋足夠的變異空間以進行系統性比較。

**4. 評分規則的多層次性**

評分規則不僅記錄最終正確性或目標值，更記錄「可行性（feasibility）」與「解品質（solution quality）」的差異。這使得基準能夠區分「產生可行解」與「產生高品質解」——前者僅需滿足約束，後者需在目標函數上表現優異。

#### 實驗數據解讀

雖然完整實驗數據需參閱論文後續章節，但從摘要與引言揭露的核心發現可解讀出三項關鍵的診斷性結論：

**1. 鄰接識別與結構正確性的非傳遞性**

Jev 在鄰接識別任務上表現準確，但此能力並不能保證在更廣泛的結構任務（如路徑判斷、環偵測、連通性推理）上同樣正確。這暗示局部二元判斷的成功可能僅反映淺層模式匹配，而非真正的圖結構理解。此發現對實務應用具有警示意義：在圖任務中部署 System One 模型時，不能僅憑鄰接層級的測試結果推論整體結構推理能力。

**2. 圖文聯合輸入的非一致增益**

在 RQ2 的配對輸入對比中，聯合圖文輸入並未一致地提升預測效能。這是一項反直覺但重要的發現：直觀上，額外的結構資訊應有助於決策，但實驗顯示在某些配置下，加入顯式邊緣資訊反而可能干擾模型判斷，或模型未能有效整合兩種模態的證據。這凸顯了「資訊存在」與「資訊被有效利用」之間的落差。

**3. 可行建構與高品質解的脫鉤**

RQ3 的結果顯示，模型能夠產生可行解（feasible construction）並不代表其解具有高品質（high solution quality）。這意味著在序列決策任務中，模型可能學會了滿足約束，但未能學會優化目標。此發現對於圖優化（graph optimization）應用至關重要：僅檢查可行性會嚴重高估模型的實用價值。

**4. 跨模型介面配置的比較意涵**

十四種模型介面配置的設計允許研究者區分：(a) 原生選擇器（如 Jev 及其變體）相對於語言模型基線的優勢；(b) 不同適配策略對效能的影響；(c) 啟發式提案控制下模型選擇的附加價值。這種多維度比較使得基準不僅報告「誰贏」，更診斷「為何贏」與「在何種條件下贏」。

#### 與現有研究的比較

**1. 相關基準的定位差異**

GraphDecisionBench 與既有圖基準形成互補而非競爭關係：

- **Open Graph Benchmark (OGB)** [8] 專注於圖學習的標準化資料集與評估協議，GraphDecisionBench 則聚焦於決策層面的診斷。
- **CLRS** [28] 評估演算法的學習執行，GraphDecisionBench 評估的是選擇式決策而非逐步演算法執行。
- **NLGraph** [29] 透過自然語言問題測試圖推理，GraphDecisionBench 則強調結構化選擇介面。
- **GraphArena** [26] 涵蓋多樣圖計算問題並明確評估可行性與解品質，與 GraphDecisionBench 的 RQ3 最為接近，但 GraphDecisionBench 進一步加入了候選池控制以區分模型選擇與外部提案的貢獻。
- **STaRK** [30] 評估知識庫中結合文字與關聯資訊的檢索，與 RQ2 的圖文決策有交集，但 GraphDecisionBench 的設計更強調配對對比。

**2. 與 Jev 相關評估的互補性**

- **JevBench** [24] 研究準確率、校準度（calibration）與成本，GraphDecisionBench 補充結構正確性、圖文資訊效用與序列解品質的維度。
- **WorldTour** [12] 評估 Jev 引導的路徑建構，GraphDecisionBench 將此擴展至更廣泛的圖優化任務。
- **JevAdvBench** [7] 檢查輸入擾動下的決策變化，GraphDecisionBench 則在固定輸入下檢查不同任務族間的能力轉移。

**3. 與 LLM 圖方法的關係**

GraphWiz [3]、GraphGPT [25]、GraphLLM [2]、GLEM [33]、TAPE [6] 等方法探索 LLM 與圖結構的整合，GraphDecisionBench 提供了一個評估此類整合在選擇式決策框架下表現的標準化場景。對於 FunSearch [23]、EoH [14]、ReEvo [32]、HeurAgenix [31] 等 LLM 輔助啟發式搜尋方法，GraphDecisionBench 的候選池控制設計可直接用於評估模型在啟發式選擇任務中的表現。

**4. 限制與未涵蓋面向**

- 基準的評估對象以 Jev 為主要案例，其他 System One 模型（如 SemIf [13]、Decider [15]、Kev [18]、Laya [4]）的覆蓋深度需透過後續實驗確認。
- 圖規模與類型的多樣性（從小型合成圖到大型真實圖）的影響尚未在現有揭露內容中充分說明。
- 基準假設任務本身並非新穎，其價值在於診斷框架而非新任務，這在引言中已明確聲明。

## 論文問答

**Q1：為什麼需要專門針對 System One 模型設計圖任務基準測試？**

A：System One 模型（如 Jev）採用「直接從供應選項中選擇並回傳機率」的決策模式，與需要顯式推理鏈的語言模型有本質差異，因此傳統以自然語言問答或長文本生成為主的圖基準測試無法直接評估其能力。圖任務涉及結構判斷、節點標籤預測與序列優化等多種決策型態，System One 模型在這些任務上的表現尚未被系統性地檢驗。GraphDecisionBench 的提出正是為了填補這一空白，提供一個模型無關的評估框架，使 Jev 等選擇式模型能與語言模型基線在統一介面下進行公平比較。

**Q2：現有的圖基準測試（如 NLGraph、GraphArena）在評估 System One 模型時有哪些不足？**

A：NLGraph 主要透過自然語言問題測試圖推理能力，但其介面設計假設模型能生成完整文字回答，無法直接評估僅回傳選項機率的選擇式模型。GraphArena 雖然涵蓋多樣的圖計算問題並評估可行性與解品質，但其評估重心在於最終目標值，無法診斷模型在不同結構操作上的細粒度表現。此外，這些基準測試通常將多個任務族彙整為單一能力分數，掩蓋了「鄰接識別準確」與「整體結構正確」之間的差異，也無法區分模型自身選擇能力與外部啟發式提案的貢獻。

**Q3：為什麼「彙整準確率」或「最終目標值」不足以診斷圖決策能力？**

A：單一的彙整分數無法回答三個關鍵問題：模型在某一結構操作上的成功是否能轉移到其他結構操作、額外的輸入元件是否真的帶來預測增益、以及輔助解是否反映模型的有效選擇而非強大的外部提案。例如，一個模型可能在鄰接識別上達到 95% 準確率，但在路徑或環的判斷上表現糟糕；同樣地，加入圖結構資訊未必總是提升分類表現。GraphDecisionBench 因此圍繞任務層級輪廓、配對輸入條件與候選池控制來組織評估，而非將三個任務族視為單一能力。

**Q4：GraphDecisionBench 的核心設計理念是什麼？它如何區分任務規格與模型執行？**

A：GraphDecisionBench 的核心設計理念是「任務規格與模型執行分離」，其圖實例、答案空間、參考評估器與評分規則定義了基準本身，而模型適配器（model adapter）則負責供應決策。這種分離使得 Jev 僅是主要的實證案例，而非任務定義或評估器的必要元件，從而支援跨模型介面配置的比較。基準透過統一的選擇介面串接結構任務輪廓、圖文輸入對比與序列建構控制，使不同類型的決策模型能在同一評估契約下接受檢驗。

**Q5：GraphDecisionBench 的三個任務族（RQ1-RQ3）分別回答什麼研究問題？**

A：RQ1「圖認知」探討模型回答局部連接與整體圖性質（路徑、環、連通性）問題的準確度，檢驗結構判斷能力是否在不同操作間一致。RQ2「圖文決策」針對相同的分類目標或檢索查詢，比較純文字輸入、純關係輸入與兩者結合下的表現差異，評估圖文資訊的附加價值。RQ3「序列決策」則檢驗模型能否透過連續選擇產生完整且可行的解，並將其品質與古典方法及固定啟發式規則比較，釐清模型選擇相對於外部提案的實際貢獻。

**Q6：「配對輸入條件」與「候選池控制」這兩個設計選擇如何實現診斷性比較？**

A：配對輸入條件透過在固定文字與共享標籤錨點或候選證據的前提下，比較加入顯式邊後的表現差異，使研究者能隔離出圖結構資訊本身的邊際貢獻，而非將其與其他變因混淆。候選池控制則透過直接建構、池內隨機與固定規則三種比較，評估模型選擇相對於外部供應啟發式引導的價值，避免將強大的提案誤歸功於模型。這兩個機制共同確保評估能揭示「可行建構」與「高品質解」之間的落差，以及「鄰接識別準確」與「整體結構正確」之間的不一致。

**Q7：GraphDecisionBench 涵蓋哪些具體的圖任務？為什麼選擇這些任務？**

A：在 RQ1 圖認知方面，基準涵蓋鄰接識別、路徑、環與連通性等結構性問題；在 RQ2 圖文決策方面，涵蓋節點分類與候選式檢索；在 RQ3 序列決策方面，則涵蓋旅行推銷員問題（TSP）、帶正負號的最大切割（signed MaxCut）、確定性影響力最大化與二元模組度（binary modularity）。這些任務的選擇反映三個原則：建立在既有圖問題與公開資料上而非引入新穎優化目標、涵蓋從局部到整體的結構操作多樣性、以及同時包含分類、檢索與組合優化等不同決策型態，使評估結果具有跨任務的泛化意義。

**Q8：Jev 在 GraphDecisionBench 上的關鍵實驗結果揭示了哪些現象？**

A：實驗結果揭示三個核心區別：準確的鄰接識別並不能保證更廣泛的結構正確性，顯示模型在局部與整體圖性質上的能力並不一致；聯合圖文輸入並非總是提升預測，說明額外的關係資訊有時反而干擾或冗餘；可行的建構並不等同於高品質的解，凸顯模型雖能產出符合約束的序列解，但其品質可能遠遜於古典方法或固定啟發式。這些發現挑戰了將單一能力分數視為模型圖理解代理指標的常見做法。

**Q9：GraphDecisionBench 如何支援跨模型介面配置（共 14 種）的比較？**

A：基準透過統一的任務契約、候選介面與評分規則，使原生選擇器（如 Jev 及其相關模型）與語言模型適配器能在同一框架下接受評估，而無需為每種模型介面重新設計評估流程。任務定義與評估器獨立於 Jev，允許相同的評估契約應用於其他決策模型，從而實現十四種模型介面配置的系統性比較。這種設計不僅降低了新模型加入評估的門檻，也使跨介面的相對優劣比較更具方法論上的嚴謹性。

**Q10：GraphDecisionBench 的研究成果對實際應用（如路徑規劃、社群網路分析）有何啟示？**

A：在路徑規劃應用中，研究結果提醒實務者：模型能產出可行路徑並不代表該路徑接近最優，因此部署時仍需結合古典演算法或領域啟發式作為品質下限的保障。在社群網路分析中，鄰接識別的高準確率可能被誤用為整體結構理解的代理指標，導致對模型在影響力傳播或模組偵測等任務上的能力過度樂觀。此外，圖文資訊結合並非總是帶來增益的發現，提示多模態系統設計者應謹慎評估每個輸入元件的邊際貢獻，而非預設「資訊越多越好」。

**Q11：在產品化或部署 System One 模型於圖決策任務時，應注意哪些設計考量？**

A：產品化時應將 GraphDecisionBench 的三項區別作為設計檢核點：避免僅以鄰接或局部任務的表現推論模型在整體結構任務上的能力、針對目標任務實證檢驗圖文結合是否真的帶來增益、以及對序列決策任務設定品質下限的古典或啟發式基線作為安全網。此外，部署時應考慮模型介面與基準介面的對齊成本，因為 GraphDecisionBench 的模型無關設計允許在不改動任務契約的前提下替換底層模型，這對模型的持續迭代與 A/B 測試具有實務價值。

**Q12：GraphDecisionBench 對圖學習、語言模型與決策系統的跨領域研究有何影響？**

A：對圖學習社群而言，基準提供了評估非傳統圖模型（如選擇式模型）在標準圖任務上的共同語言，有助於辨識哪些圖問題真正需要結構感知模型、哪些可由通用決策介面處理。對語言模型研究而言，基準揭示了 LLM 在圖結構推理上的細粒度不足，鼓勵開發更具結構感知的適配器或多模態融合策略。對決策系統研究而言，GraphDecisionBench 將 System One 模型的評估從單純的選項分類擴展到序列優化與品質診斷，推動了「選擇能力」與「解品質」解耦的研究議程。

**Q13：GraphDecisionBench 目前存在哪些已知的限制？**

A：基準目前主要聚焦於 Jev 作為實證案例，雖然其介面設計支援其他模型，但對 SemIf、Decider、Kev、Laya 等相關決策介面的全面評估尚未完整展開。此外，RQ3 的序列決策任務涵蓋 TSP、MaxCut、影響力最大化與模組度，但對於更大規模的圖實例或更複雜的約束滿足問題，基準的可擴展性仍待驗證。基準的評分規則雖然支援跨介面比較，但對於機率校準（calibration）與決策穩定性的細粒度量測仍不如 JevBench 等專門基準深入。

**Q14：在哪些場景下 System One 模型可能會失敗？基準測試如何揭示這些失敗模式？**

A：System One 模型可能在需要多步推理或長程依賴的整體結構任務（如環偵測、連通性判斷）上失敗，因為其介面僅供應局部選項而缺乏顯式推理階段；在圖文結合輸入下，當圖結構與文字描述存在衝突或冗餘時，模型可能因無法有效整合而表現不如純文字或純圖輸入。GraphDecisionBench 透過任務層級輪廓揭示這些失敗的細粒度模式：例如同一模型在鄰接任務上 95% 準確率但在環任務上僅 60%，或圖文結合輸入反而降低分類準確率，從而使研究者能精準定位失敗環節而非僅看到彙整分數下降。

**Q15：未來的研究方向有哪些？基準測試本身可以如何擴展？**

A：未來研究方向包括：將基準擴展至更大規模與更異質的圖實例（如社群網路、交通網路、生物網路）、納入更多決策介面（如 SemIf、Decider 等）以建立完整的 System One 模型生態評估、以及結合 JevBench 的校準分析與 JevAdvBench 的擾動穩定性分析，形成多維度的決策品質剖面。在基準本身擴展方面，可考慮加入動態圖、時序圖與多層圖等更具挑戰性的結構，以及探索與程式搜尋方法（如 FunSearch、EoH）的整合，使基準能評估「模型選擇 + 啟發式演化」的混合決策模式。

## 實務應用指南

### 適用場景

1. **物流配送路徑最佳化**：將 GraphDecisionBench 的 TSP（旅行銷售員問題）任務族直接套用於快遞、外送車隊的每日路線規劃。透過 Jev 等選擇式模型在節點序列上做重複決策，並以啟發式提案池（如最近鄰啟發式、2-opt 改進解）作為對照組，評估模型在真實配送限制下的解品質與可行性。

2. **社群網路影響力最大化**：在行銷活動、社群病毒式傳播模擬中，使用 RQ3 的確定性影響力最大化任務。模型需在每一步從候選節點中選擇下一個種子節點，可同時比較模型直接選擇、隨機選擇與固定啟發式提案的表現，協助行銷團隊判斷是否值得引入 LLM 輔助決策。

3. **知識圖譜檢索與分類**：在企業知識庫、醫療知識圖譜中，利用 RQ2 的圖文決策任務族。針對同一分類目標或檢索查詢，分別提供純文字、純圖關係、圖文聯合三種輸入，診斷哪種資訊組合對下游任務最有效，避免在生產環境中誤以為「資訊越多越好」。

4. **圖神經網路模型的單元測試套件**：將 GraphDecisionBench 的 RQ1 圖認知任務（鄰接識別、路徑、環、連通性）作為 GNN 模型上線前的回歸測試基準，確保模型在局部與整體結構判斷上一致，避免「鄰接正確但整體結構錯誤」的隱性缺陷。

5. **組合最佳化問題的模型選型評估**：在 MaxCut、二元模數度等 NP-hard 問題上，使用 GraphDecisionBench 的序列決策介面快速比較 Jev、LLM 基線與傳統啟發式的解品質，協助研究團隊在投入大量微調成本前，先行篩選有潛力的模型介面。

### 實作前置條件

**資料需求**：
- 圖結構資料：可使用公開資料集（如 Open Graph Benchmark、CLRS 內建實例），或自備領域圖（知識圖譜、運輸網路、社群網路）。
- 對應文字屬性：若執行 RQ2，需為節點準備文字描述或錨點標籤。
- 啟發式提案：針對 RQ3 的 TSP、MaxCut 等任務，需預先實作或引入至少一種經典啟發式（如最近鄰、貪婪法）作為提案池來源。

**運算資源**：
- Jev 等原生選擇式模型：單張消費級 GPU（如 RTX 3090）即可執行 14 種模型介面配置中的多數。
- LLM 基線（如 GPT、Claude、本地 LLaMA）：建議至少 24GB 顯存，或透過 API 呼叫以降低本地硬體需求。
- 評估階段：CPU 即可處理大部分結構驗證與評分邏輯。

**技能門檻**：
- 熟悉 Python 與圖論基礎概念（節點、邊、路徑、連通分量）。
- 了解選擇式模型與 LLM 的介面差異，能撰寫模型適配器（adapter）。
- 具備基本實驗設計能力，理解配對輸入、控制變數與評分契約的概念。

### 實作步驟建議

1. **釐清評估目標並選擇任務族**：先決定要回答 RQ1（結構正確性）、RQ2（圖文資訊效用）還是 RQ3（序列解品質），再從 GitHub 倉庫（`VictorYXL/GraphDecisionBench`）載入對應的任務契約與評分規則。

2. **準備圖實例與候選介面**：將資料轉換為基準要求的格式，定義候選選項的呈現方式（節點 ID、子圖、文字描述）。注意候選池的大小與排序會直接影響模型表現。

3. **配置模型介面**：從 14 種模型介面配置中挑選目標模型。原生選擇式模型（如 Jev）直接呼叫選擇介面；LLM 基線需透過提示工程將任務包裝為多選題，並關閉 deliberative reasoning 以模擬 System One 行為。

4. **執行配對輸入對比（RQ2 專屬）**：在固定文字與標籤錨點的前提下，分別以純文字、純圖關係、圖文聯合三種輸入執行同一組查詢，記錄差異以判斷「額外資訊是否真正有助於決策」。

5. **執行啟發式提案對照（RQ3 專屬）**：在同一任務上同時跑三種模式——模型直接構造、模型從啟發式提案池中選擇、純隨機選擇——以分離「模型選擇能力」與「外部提案品質」的貢獻。

6. **彙整結果並產出診斷報告**：依任務層級輪廓（task-level profiles）而非單一彙整分數呈現結果，特別標註「鄰接正確但整體結構錯誤」、「圖文聯合未優於單一輸入」、「可行但低品質」三類典型失敗模式。

7. **建立回歸基準**：將首次執行的結果存為基準版本，後續模型更新或資料變動時重跑相同契約，快速偵測退化。

### 潛在風險與注意事項

- **鄰接識別 ≠ 整體結構正確**：模型可能在「兩節點是否相鄰」這類局部任務上達到 90% 以上準確率，但在路徑存在性、環偵測、連通性等整體任務上表現不佳。務必分任務族報告結果，避免被彙整分數誤導。

- **圖文聯合輸入未必更佳**：直覺上「資訊越多越好」，但 GraphDecisionBench 的配對對比顯示，聯合輸入並非在所有目標上一致優於單一輸入。生產環境中應實測而非假設。

- **可行解 ≠ 高品質解**：模型可能成功構造出滿足約束的解（如合法 TSP 路線），但其總成本遠高於啟發式提案。務必同時報告可行性與品質兩個指標。

- **評分契約不一致的風險：不同任務族使用不同的評分規則（精確度、F1、目標函數值），跨族比較時需特別注意正規化方式，避免直接平均。

- **緩解措施**：在報告中始終提供任務層級細分；對 LLM 基線設定固定的隨機種子與溫度；在提案池對照中保留隨機基線作為下限錨點。

### 與其他技術的整合建議

- **與圖專用 LLM 整合**：GraphDecisionBench 的任務契約可作為 GraphWiz、GraphGPT、GraphLLM 等模型的標準化評估後端，無需修改基準本身，只需撰寫對應的模型適配器。

- **與啟發式搜尋框架整合**：FunSearch、EoH、ReEvo、HeurAgenix 等 LLM 輔助啟發式搜尋框架可將 GraphDecisionBench 的 RQ3 任務作為「目標問題庫」，評估其生成啟發式在選擇式模型引導下的實際表現。

- **與檢索基準整合**：RQ2 的圖文檢索任務可與 STaRK 等知識庫檢索基準互補——STaRK 評估整體檢索品質，GraphDecisionBench 評估選擇式模型在固定候選池中的相對表現。

- **與 GNN 評估管線整合**：將 RQ1 圖認知任務嵌入 GNN 訓練流程的驗證階段，作為結構推理能力的細粒度監控指標。

- **與 MLOps 平台整合**：將基準執行包裝為 CI/CD 中的模型評估步驟，搭配版本控制追蹤每次模型迭代在三個任務族上的細項表現。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節緒論，理解「System One 模型」與「選擇式介面」的概念差異，再看圖 1 的三個任務族示意。RQ1 的圖認知任務最直觀，可作為入門起點；RQ2 與 RQ3 涉及較多實驗設計概念，可先跳過細節，著重理解「為什麼要分任務族評估」。

**給 AI 工程師**：重點關注第 3 節的任務契約、候選介面與評分規則實作細節，以及 GitHub 倉庫中的模型適配器範例。特別留意 14 種模型介面配置的差異——這些配置直接決定了如何將既有模型包裝為基準可呼叫的形式。實作時優先建立「配對輸入對比」與「提案池對照」兩個實驗模板。

**給研究者**：本論文的核心貢獻在於方法論而非新模型——「任務層級輪廓 + 配對輸入對比 + 候選池控制」的三軸診斷框架值得借鏡。建議仔細閱讀三個研究問題的設計動機，並思考如何將此框架遷移至其他領域（如序列推薦、組合最佳化、符號推理）。Jev 的實驗結果本身可作為「選擇式模型在圖任務上的現況快照」。

**給產品經理**：聚焦於「鄰接正確不代表整體正確」、「圖文聯合未必更佳」、「可行不代表高品質」三個關鍵發現。這些結論提醒我們：在導入 LLM 輔助圖決策時，不能僅看彙整指標，必須依業務場景分項驗證。GraphDecisionBench 可作為採購或自研決策前的「盡職調查工具」，協助判斷模型在特定任務族上的真實能力邊界。
