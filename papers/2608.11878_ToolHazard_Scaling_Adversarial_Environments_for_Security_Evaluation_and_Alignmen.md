## ⚡ TL;DR

現有代理安全評估多仰賴手動環境與預設注入點，難以大規模擴展至多樣領域。
本文提出 ToolHazard，以三大模組合成可執行對抗環境、自動發現注入點並生成狀態基礎任務。
實驗顯示代理易受環境注入攻擊，且 ToolHazard 對齊資料能提升安全並保留良性效用。

## 摘要翻譯

基於大型語言模型（Large Language Model, LLM）的代理（LLM-based Agent）在整合外部工具（External Tool）後，容易受到嵌入於環境狀態（Environmental State）中的間接提示注入（Indirect Prompt Injection）攻擊。然而，現有研究大多依賴手動實現的環境（Manually Implemented Environment）或重複使用的環境（Reused Environment）、基於大型語言模型的工具模擬（LLM-based Tool Simulation），以及預定義注入位置（Predefined Injection Location），限制了在更廣泛領域中進行具可擴展性（Scalability）的安全研究。為彌合此缺口，我們提出 ToolHazard，一個可擴展的對抗環境（Adversarial Environment）合成框架，可減少人工工程，並支援透過新增種子領域（Seed Domain）與運算資源（Compute）來擴展。透過環境模擬器（Environment Simulator）、攻擊者代理（Attacker Agent）與使用者模擬器（User Simulator），ToolHazard 合成可執行且具狀態的環境（Executable Environment & Stateful Environment）、發現可行的注入點（Injection Point）、生成環境專屬的攻擊載荷（Payload），並建構基於狀態的長程任務（State-grounded Task & Long-horizon Task）。基於 ToolHazard，我們建構 ToolHazard-Bench，用於在複雜工作流程與多樣化環境攻擊下對代理進行壓力測試。實驗揭示代理存在重大漏洞，並顯示注入時機（Injection Timing）與注入位置（Injection Placement）會影響攻擊有效性。此外，由 ToolHazard 生成的對齊資料（Alignment Data）能在提升 ToolHazard-Bench 與 AgentDojo 兩者安全性的同時，保留良性任務效用（Benign Task Utility）。

### 核心貢獻（3～5點）
- 提出 ToolHazard，一個可擴展的對抗環境合成框架，能減少人工工程並透過新增種子領域與運算資源持續擴展。
- 透過環境模擬器、攻擊者代理與使用者模擬器三大模組，自動合成可執行且具狀態的環境、發現注入點、生成環境專屬攻擊載荷，並建構基於狀態的長程任務。
- 建構 ToolHazard-Bench 評估基準，用於在複雜工作流程與多樣化環境攻擊下對代理進行壓力測試。
- 實驗證實代理存在顯著漏洞，且注入時機與注入位置會顯著影響攻擊有效性。
- ToolHazard 生成的對齊資料可同時提升 ToolHazard-Bench 與 AgentDojo 上的安全性，並保留良性任務效用。

### 適合對象
從事大型語言模型代理安全、對抗穩健性、紅隊測試、對齊資料建構，以及代理安全評估基準設計的研究人員與工程師；亦適合關注工具整合代理在複雜對抗環境中風險的資安實務工作者與政策制定者參考。

## 深度分析

#### 方法論解析

ToolHazard（可擴展對抗環境合成框架）的核心目標，是將「間接提示注入（indirect prompt injection）」的評估與對齊（alignment）從「手動建構環境」與「預定義注入位置」的瓶頸中解放出來。其方法論可從三個層次理解：威脅模型（threat model）的形式化定義、三大模組的協作流程，以及由合成資料支撐的評估與對齊管線。

##### 1. 威脅模型的形式化定義

論文將 LLM-based Agent（基於大型語言模型之代理）的運作建模為：

\[
\tau = (q, a_1, o_1, \dots, a_T, o_T) \sim A(q, e)
\]

其中 \(q\) 為使用者查詢（user query），\(e\) 為環境（environment），\(a_t\) 與 \(o_t\) 分別代表第 \(t\) 步的動作（action）與環境觀察（observation）。攻擊者僅能在環境狀態（environmental state）中可寫入的位置 \(\ell\) 注入對抗指令 \(\delta\)，形成被污染的環境：

\[
e' = \text{Inject}(e, \ell, \delta), \quad \tau' \sim A(q, e')
\]

這個威脅模型有幾個重要限制：攻擊者不能修改使用者查詢、系統提示、工具實作或代理參數，只能透過電子郵件、文件、資料庫紀錄、工具輸出等「可注入屬性（injectable attribute）」來影響代理。這種設定貼近真實世界中的間接提示注入，但同時也凸顯了「發現可行注入點（injection point）」的困難——攻擊者必須先確認哪些環境狀態會在任務執行軌跡（trajectory）中進入代理的觀察。

##### 2. Environment Simulator（環境模擬器）

Environment Simulator 負責將「種子領域（seed domain）」擴展為可執行、有狀態（stateful）的工具互動環境。其內部又可細分為三個階段：

- **Environment Blueprint Planning（環境藍圖規劃）**：根據種子領域生成高階設計，包括實體（entities）、工具（tools）、約束（constraints）、環境類別屬性（env. class attributes）等。
- **Executable Program Construction（可執行程式建構）**：將藍圖轉換為可實際執行的程式碼，使代理能夠呼叫工具並觀察環境狀態變化。
- **Automated Quality Inspection（自動化品質檢驗）**：透過檢查函式（check function）驗證環境的正確性與可玩性，確保合成的環境不會因為程式錯誤而產生假陽性或假陰性。

這個模組是 ToolHazard 可擴展性（scalability）的關鍵：只要提供新的種子領域與運算資源（compute），就能持續產生新的環境，而不需要人工從頭撰寫每個領域的模擬器。

##### 3. Attacker Agent（攻擊者代理）

Attacker Agent 是 ToolHazard 最具方法論創新的部分。它不再依賴人工預先指定注入位置，而是主動規劃與執行攻擊：

- **Attack Point Discovery（攻擊點發現）**：分析環境中哪些屬性會被代理讀取或寫入，並判斷其是否會出現在任務執行過程的觀察中。
- **Injectable Attribute Identification（可注入屬性識別）**：進一步篩選出攻擊者有能力修改的屬性（例如電子郵件內文、備忘錄、資料庫欄位）。
- **Attack Policy / Payload Generation（攻擊策略／攻擊載荷生成）**：針對特定環境與任務生成環境專屬的 payload（攻擊載荷），並透過 Plan-and-Execute（規劃與執行）機制反覆調整。
- **Trajectory Collection（軌跡收集）**：實際執行被污染的環境，觀察代理反應，並以攻擊成功與否作為回饋。

這種設計讓 ToolHazard 能夠發現「任務可達成的注入點（task-reachable injection points）」，也就是那些不僅存在於環境中、而且會在良性使用者任務執行過程中被代理觀察到的位置。這比單純在環境中隨機插入攻擊文字更接近真實威脅模型。

##### 4. User Simulator（使用者模擬器）

User Simulator 的任務是生成「基於狀態的長程任務（state-grounded long-horizon tasks）」。具體而言，它會：

- 在初始化後的環境狀態中產生合理的使用者目標；
- 將目標轉換為自然語言查詢（query）與任務標的（task target）；
- 確保任務需要多步驟（multi-step）工具互動才能完成，從而提升工作流程複雜度（workflow complexity）。

這些任務必須與 Attacker Agent 發現的注入點相互對齊：攻擊者選擇的注入位置應該會在代理執行該任務時被觀察到，才能構成有效的評估案例。

##### 5. ToolHazard-Bench 與 ToolHazard-Align

基於上述三個模組，論文建構了兩個下游資產：

- **ToolHazard-Bench（評估基準）**：包含 28 個有狀態環境、512 個工具、87 個長程任務，用於壓力測試代理在複雜工作流程與多樣化環境攻擊下的表現。
- **ToolHazard-Align（對齊資料集）**：提供大規模對抗訓練資料，支援監督式微調（Supervised Fine-Tuning, SFT）與強化學習（Reinforcement Learning, RL），用於提升代理安全性同時保留良性任務效用（benign task utility）。

整體而言，ToolHazard 的方法論並非設計新的攻擊策略或 payload 包裝技巧，而是透過自動化環境合成、注入點發現與任務生成，將「對抗環境（adversarial environment）」的建構規模化。

#### 實驗數據解讀

雖然提供的全文片段未包含所有實驗表格，但從摘要、表 1（Table 1）與圖 1（Figure 1）已可提煉出幾個關鍵數據趨勢與其意義。

##### 1. 規模與複雜度指標

表 1 比較了現有代理安全評估基準（evaluation benchmark）與對齊資料集（alignment dataset）：

| 面向 | ToolHazard-Bench | AgentDojo | ASB | AgentHarm | AgentLAB |
|---|---|---|---|---|---|
| Stateful（有狀態） | ✓ | ✓ | ✗ | ✗ | ✓ |
| Domain Source（領域來源） | LLM-synthesized（LLM 合成） | Manual（人工） | Manual（人工） | Manual（人工） | Reused/Manual（重複使用／人工） |
| Steps/Task（每個任務的步驟數） | 15.56 | 4.19 | 2.96 | 3.47 | N/A |
| Candidate Tools/Task（每個任務的候選工具） | 18.75 | 18.50 | 3.00 | 3.53 | N/A |

從這些數字可以解讀出：

- **工作流程複雜度顯著提升**：ToolHazard-Bench 的平均步數達 15.56 步，遠超 AgentDojo 的 4.19 步與 ASB 的 2.96 步。這意味著代理需要在更長的決策序列中維持目標導向行為，同時抵抗環境中多個潛在注入點的干擾。
- **工具選擇空間大**：每個任務平均有 18.75 個候選工具，接近 AgentDojo 的 18.50，但任務步數卻是後者的三倍以上。這表示 ToolHazard-Bench 不僅要求代理會選工具，還要求在長程互動中持續正確選擇與組合工具。
- **環境來源的可擴展性**：不同於現有基準依賴手動實現的環境（manually implemented environment）或重複使用的環境（reused environment），ToolHazard 的環境來自 LLM 合成，這是其能夠擴展到 28 個領域的核心原因。

##### 2. 攻擊有效性發現

摘要與引言指出三項實證發現：

1. **LLM 代理對環境提示注入仍然高度脆弱**：即使在相對複雜的長程任務中，代表性情商代理仍會被環境中的對抗指令劫持。
2. **注入時機（injection timing）影響攻擊成功率**：代理越早遇到被注入的指令，攻擊越容易成功。這可能與「首因效應」或長程任務中的注意力衰減有關——早期注入的指令有機會在後續多步決策中持續發揮影響。
3. **注入位置（injection placement）影響攻擊成功率**：將注入指令放在觀察（observation）的末尾附近通常更有效。這與 LLM 對序列末尾資訊的注意力偏誤（recency bias）一致，也呼應了過去在直接提示注入中觀察到的現象。

這些發現對防禦設計具有實務意義：單純增加任務長度或工具數量並不能自動提升魯棒性，反而可能因為代理在長序列中對早期或末尾線索過度敏感而放大風險。

##### 3. 對齊資料的效果

論文報告，使用 ToolHazard-Align 進行 SFT 與 RL 後，代理在 ToolHazard-Bench 與 AgentDojo 上的安全性均獲得提升，同時良性任務效用（benign task utility）得以保留。這表示：

- ToolHazard 合成的對齊資料（alignment data）具有**跨基準遷移能力**，不僅對自身分佈有效，也能改善代理在現有手工基準上的表現。
- 由於 ToolHazard-Align 來自可執行的有狀態環境，它支援 RL 訓練所需的互動式軌跡與可驗證獎勵（verifiable rewards），這是 AgentAlign 等靜態軌跡資料集難以提供的。

#### 與現有研究的比較

##### 1. 相對於現有評估基準

- **AgentHarm** 與 **Agent-SafetyBench（ASB）**：主要聚焦於惡意使用者指令（malicious user instructions），即直接攻擊。ToolHazard 則專注於環境側攻擊（environment-side attacks），兩者互補。
- **InjecAgent、AgentDojo、SHADE-Arena**：雖然也研究環境側攻擊，但環境多為手動建構，注入位置通常預先定義（predefined injection location）。ToolHazard 透過 Attacker Agent 自動發現注入點，並生成環境專屬 payload。
- **AgentLAB、PIArena**：提供較多領域或較廣泛設定，但環境仍多為重複使用或人工調整。ToolHazard 的 LLM 合成環境在擴展性上更進一步。

##### 2. 相對於現有對齊資料集

- **AgentAlign、ToolAlign**：主要針對直接攻擊，資料多為靜態軌跡。
- **ToolSafety**：雖研究間接提示注入，但聚焦於有害內容生成（harmful content generation）而非代理劫持（agent hijacking）。
- **ToolHazard-Align**：提供可執行、有狀態環境中的長程互動軌跡，支援 SFT 與 RL，並且攻擊點由 LLM 自動發現而非預先定義。

##### 3. 定位與貢獻

ToolHazard 的定位並非「紅隊攻擊優化」（red-teaming），而是「對抗環境建構的規模化」。它不改進攻擊策略或 payload 包裝技巧，而是降低建構評估與訓練環境的人力成本，並讓環境能隨著新種子領域與運算資源持續擴展。

##### 4. 限制

儘管方法論具有創新性，仍有以下潛在限制：

- **LLM 合成品質的依賴**：環境、任務、注入點與 payload 的品質都取決於底層 LLM 的能力。若 LLM 產生語法錯誤、語義不一致或過於牽強的攻擊，可能影響評估效度。
- **種子領域的偏誤**：28 個領域雖多，但仍由初始種子決定，可能無法涵蓋所有真實世界應用場景。
- **攻擊模型的單一性**：目前僅考慮環境側攻擊，未同時納入惡意使用者、 compromised 工具或多代理互動等複合威脅。
- **可解釋性不足**：Attacker Agent 發現的注入點與生成的 payload 可能缺乏人類可讀的攻擊邏輯說明，增加審核與除錯難度。
- **未宣稱對抗自適應攻擊者**：ToolHazard 用於生成評估環境與對齊資料，但並不保證訓練後的代理能抵抗專門針對其弱點設計的自適應攻擊。

#### 可重現性評估

##### 1. 開源釋出

論文明確指出程式碼已釋出於：

> https://github.com/MurrayTom/ToolHazard

這對可重現性（reproducibility）是正面訊號。研究者原則上可以取得環境合成管線、Attacker Agent、User Simulator 與評估腳本。

##### 2. 資料集與模型權重

根據提供的片段，目前僅確認程式碼開源，尚未明確說明是否同時釋出：

- ToolHazard-Bench 的完整環境與任務資料；
- ToolHazard-Align 的對齊資料集；
- 經過 SFT/RL 訓練後的模型權重（model weights）。

若僅釋出程式碼，第三方仍需自行執行 LLM 合成流程，這會帶來兩個問題：

- **隨機性與成本**：LLM 合成具有隨機性，且需要大量 API 呼叫或本地 GPU 運算，重現完整 28 領域、512 工具、87 任務的基準成本不低。
- **版本依賴**：底層 LLM（如 GPT-4、Claude 等）的版本更新可能改變合成環境的品質與攻擊成功率，使得跨研究比較變得困難。

##### 3. 重現建議

為提升可重現性，建議作者未來補充：

- 固定種子的合成環境快照（snapshot）；
- 用於生成環境與任務的完整 prompt 模板；
- 訓練後檢查點（checkpoint）與超參數；
- 詳細的硬體與 API 消耗估算。

#### 未來研究方向

基於 ToolHazard 的架構與限制，可延伸出以下研究方向：

1. **多模態與跨領域擴展**：將 Environment Simulator 從文字環境擴展到包含圖像、音訊、結構化資料的多模態環境，並引入更多真實世界種子領域（如醫療、金融、工業控制）。
2. **自適應與多步攻擊**：讓 Attacker Agent 不僅注入單一指令，還能規劃多階段攻擊（例如先誘導代理洩漏資訊，再利用洩漏資訊進行後續攻擊）。
3. **動態防禦與對抗訓練**：在 ToolHazard 上訓練「防禦者代理」，與 Attacker Agent 進行對抗性博弈，形成自動化的攻擊—防禦共同演化環境。
4. **注入時機與位置的因果分析**：進一步量化 early-injection 與 end-of-observation injection 的因果效應，並發展相應的注意力重校準或提示淨化技術。
5. **人類在迴路驗證**：建立人類審核介面，讓安全研究者能夠驗證 LLM 合成的環境與攻擊是否合理，並回饋至合成管線以提升品質。
6. **真實工具整合**：將合成的環境從模擬器橋接到真實 API 與服務，評估代理在真實世界工具鏈中的脆弱性。
7. **多代理系統安全**：擴展威脅模型至多代理互動場景，研究一個被入侵的代理如何透過環境狀態影響其他代理。
8. **可解釋的攻擊發現**：讓 Attacker Agent 在發現注入點的同時生成自然語言解釋，說明為何該位置有效、預期代理行為為何，以提升紅隊活動的透明度。

## 論文問答

**Q1：什麼是針對 LLM 代理的間接提示注入攻擊，為何它對真實應用構成嚴重威脅？**

A：間接提示注入是指攻擊者將惡意指令嵌入代理所互動的環境狀態中，例如電子郵件內容、文件、資料庫紀錄或工具輸出，而非直接操縱使用者的查詢或系統提示。當基於大型語言模型的代理在執行任務時讀取這些被污染的狀態，模型可能會把注入指令視為當前任務的一部分，進而執行未經授權或有害的操作。由於現代自主代理常透過外部工具與真實系統互動，這類攻擊可在不更動使用者原始意圖的情況下竊取資料、刪除檔案或進行未授權交易，因此對實際部署的安全性影響極大。

**Q2：現有的代理安全研究在環境建構與攻擊設計上存在哪些可擴展性瓶頸？**

A：現有研究大多依賴手動實現或重複使用的環境，這使得跨領域擴展需要大量工程人力，且難以快速覆蓋新的應用場景。此外，許多方法採用預定義注入位置或基於大型語言模型的隨機工具模擬，無法動態發現任務執行過程中真正可達的注入點，也缺乏可執行、有狀態的互動環境來驗證攻擊結果。這些限制導致既有基準難以產生工作流程複雜、攻擊多樣且可規模化擴展的評估資料，阻礙了更廣泛領域的安全研究。

**Q3：為何需要可擴展的對抗環境合成框架來評估與對齊 LLM 代理？**

A：隨著 LLM 代理被部署到越來越多樣的領域，手動建立每個領域的對抗環境既不現實也難以持續維護，因此需要能隨著新增種子領域與運算資源自動擴展的合成範式。可擴展的對抗環境能同時提供真實的狀態轉移、長程任務規劃與動態攻擊注入，讓安全評估更接近實際使用情境。此外，這類框架還能大規模生成對齊資料，支援監督式微調與強化學習，在提升代理安全性的同時保留良性任務效用。

**Q4：ToolHazard 的核心架構由哪三個模組組成，各自負責什麼功能？**

A：ToolHazard 包含環境模擬器、攻擊者代理與使用者模擬器三大模組。環境模擬器負責合成可執行且具狀態的工具互動環境，並進行自動化品質檢查，確保環境能正確運作。攻擊者代理會分析環境狀態與工具介面，自動發現可行的注入點並生成針對該環境的攻擊載荷。使用者模擬器則根據環境狀態生成良性的基於狀態的長程任務，使整個評估流程同時具備真實任務目標與對抗測試條件。

**Q5：相較於既有基準，ToolHazard 在方法論上的關鍵創新是什麼？**

A：ToolHazard 的主要創新在於以大型語言模型驅動對抗環境的合成，從而大幅減少人工工程並支援透過新增種子領域與運算資源持續擴展。不同於過去依賴手動實現環境與預定義注入位置的做法，ToolHazard 能自動發現任務執行軌跡中可達的注入點，並生成環境專屬的攻擊載荷。同時，它產生的環境是有狀態且可執行的，能支援長程任務與可驗證的獎勵訊號，這為後續的強化學習對齊提供了過去靜態軌跡資料所缺乏的基礎。

**Q6：ToolHazard 為何要將攻擊者代理與使用者模擬器分開設計，而非使用單一模型同時產生任務與攻擊？**

A：分離設計讓攻擊者代理能專注於分析環境結構、識別可被寫入的狀態屬性，並主動規劃與執行提示注入，從而發現真正具有威脅性的攻擊點。使用者模擬器則獨立負責生成符合環境狀態的良性使用者查詢與長程任務，確保任務目標真實且與攻擊無關，避免任務本身帶有惡意傾向。這種解耦不僅讓威脅模型更清晰，也能更準確地衡量代理在面對環境側攻擊時的穩健性，並維持良性任務效用作為對照基準。

**Q7：ToolHazard-Bench 的規模與複雜度與現有基準相比有何優勢？**

A：ToolHazard-Bench 包含 87 個長程任務，橫跨 28 個有狀態環境與 512 個工具，每個任務平均約 15.56 個步驟與 18.75 個候選工具，工作流程複雜度顯著高於 AgentDojo、ASB 等現有基準。其環境與任務皆由大型語言模型合成，注入點與攻擊載荷也透過攻擊者代理自動發現與生成，而非預先人工設定。這使得 ToolHazard-Bench 能提供更貼近真實應用的動態攻擊場景，並能隨著新領域加入持續擴充評估範圍。

**Q8：實驗揭示了哪些關於代理脆弱性與攻擊有效性的重要發現？**

A：實驗顯示，代表性的 LLM 代理在面對環境側的間接提示注入時仍然高度脆弱，容易被操縱執行非預期操作。研究進一步發現，攻擊效果與注入時機和位置密切相關：當惡意指令在代理執行軌跡中較早被遇到，並且被放置在觀察內容接近結尾的位置時，攻擊成功率通常更高。此外，使用 ToolHazard 生成的對齊資料進行訓練後，代理在 ToolHazard-Bench 與 AgentDojo 上的安全性均顯著提升，同時良性任務效用並未明顯下降。

**Q9：ToolHazard 生成的對齊資料在訓練方式與效果上有哪些值得注意的結果？**

A：ToolHazard-Align 不僅提供靜態軌跡供監督式微調使用，還因為環境可執行且具狀態，能產生可驗證的獎勵訊號以支援強化學習對齊。實驗結果顯示，無論是在 ToolHazard-Bench 還是跨基準的 AgentDojo 上，經過 ToolHazard 對齊資料訓練的代理都能有效降低攻擊成功率。更重要的是，這種安全提升並未以犧牲正常任務表現為代價，顯示該方法在增強代理防禦能力的同時，仍能維持其在良性任務上的實用性。

**Q10：ToolHazard 可應用於哪些真實世界或企業場景來進行安全測試？**

A：ToolHazard 可應用於任何 LLM 代理透過外部工具讀取外部內容的場景，例如電子郵件助理讀取被植入惡意指令的郵件、文件管理代理處理被篡改的檔案、客戶服務代理查詢被污染的資料庫紀錄，或程式開發代理使用被植入後門的工具輸出。企業可利用此框架針對內部工作流程建立專屬的對抗測試環境，在產品上線前進行紅隊演練。由於環境可執行且具狀態，安全團隊能驗證代理是否會在真實系統中執行未授權操作，而不僅是理論上的風險推估。

**Q11：若要在產品開發流程中導入 ToolHazard，應考量哪些實務因素？**

A：首先需確保合成環境與目標產品的工具介面、狀態轉移與資料格式具有足夠相似度，因此可能需要以真實系統的種子領域作為起點並進行品質檢查。其次，攻擊者代理發現的注入點與載荷應納入持續性的安全回歸測試，並隨著產品功能迭代定期重新生成對抗案例。最後，企業應將 ToolHazard 產生的對齊資料整合進監督式微調與強化學習流程，並監控良性任務效用，以避免過度防禦導致使用者體驗下降。

**Q12：ToolHazard 對 LLM 代理安全研究領域可能帶來哪些長遠影響？**

A：ToolHazard 提供了一個可擴展的對抗環境合成典範，能顯著降低跨領域安全評估所需的人力成本，並使研究社群能夠快速擴充新的應用領域與攻擊場景。它將評估基準從靜態、預定義的設定推向動態、狀態導向且可驗證的互動環境，有助於發現更真實的漏洞。此外，透過支援強化學習對齊，ToolHazard 也為未來開發具備長期穩健性的自主代理提供了重要的資料與方法基礎。

**Q13：ToolHazard 目前有哪些潛在限制或需要人工介入的地方？**

A：雖然 ToolHazard 大幅減少人工工程，但環境模擬器合成的程式與狀態仍可能出現語法錯誤、邏輯不一致或不符合真實領域規範的問題，因此需要自動化品質檢查與必要時的人工驗證。種子領域的品質與多樣性會直接影響合成環境的覆蓋範圍與真實性，若種子設計不當，可能導致生成的對抗案例過於單一。此外，攻擊者代理雖能發現許多可達注入點，但對於需要複合操作或非顯式狀態傳播的進階攻擊，自動發現能力可能仍有不足。

**Q14：在哪些情況下，ToolHazard 合成的攻擊或環境可能會失效或產生誤導性結果？**

A：若 LLM 代理本身對間接提示注入具有較強的指令遵循過濾或工具使用驗證機制，部分自動生成的攻擊載荷可能無法成功觸發惡意行為。合成環境有時可能過度簡化真實系統的複雜性，導致在基準上觀察到的高攻擊成功率無法完全外推到實際部署。另外，若攻擊者代理或使用者模擬器出現幻覺，可能生成不符合環境狀態的任務或無法執行的注入點，這時就需要品質檢查機制來剔除無效樣本。

**Q15：未來研究可從哪些方向進一步擴展 ToolHazard 的能力與應用範圍？**

A：未來可將威脅模型從單純的環境側攻擊擴展到使用者與環境共謀的混合攻擊，或多代理系統中代理間互相影響的場景。也可引入線上適應性攻擊者，使其能根據代理的即時回饋動態調整注入策略，進一步測試代理的動態防禦能力。此外，結合人類專家回饋進行環境與攻擊驗證、將框架應用於真實世界服務的滲透測試，以及探索更開放式的強化學習獎勵設計，都是值得深入發展的方向。

## 實務應用指南

### 適用場景

1. **金融服務代理的安全驗收**：銀行、保險或證券業的 LLM 代理常透過 API 操作帳戶餘額查詢、交易下單、理賠申請或客戶資料調閱。ToolHazard 可合成這類有狀態環境，驗證攻擊者能否透過交易備註、客戶留言或文件內容注入惡意指令，導致代理執行未經授權的轉帳或資料外洩。

2. **企業知識庫與文件協作平台**：結合 RAG 的代理會讀取電子郵件、共享文件、工單系統與資料庫紀錄。ToolHazard 能模擬這些環境狀態被污染的情境，例如在某份合約附件或工單描述中植入提示注入，測試代理是否會因此修改權限、刪除檔案或洩漏機密。

3. **醫療與健康照護決策輔助**：醫院或遠距醫療代理可能存取電子病歷、預約系統與用藥資料庫。透過 ToolHazard 合成可執行的醫療資訊環境，可評估攻擊者篡改病歷備註或藥品說明後，是否會誘導代理做出錯誤的預約變更或給藥建議。

4. **電商與客戶服務自動化**：處理訂單、退款、物流查詢與會員管理的代理，經常讀取使用者輸入的退貨原因、商品評價或客服對話紀錄。ToolHazard 可協助發現這些「使用者可寫入的環境狀態」中，哪些欄位會進入代理觀察並成為有效注入點。

5. **軟體開發與 DevOps 代理**：能操作程式碼倉庫、CI/CD 管線與雲端資源的代理，若讀取到被污染的 issue 內容、commit message 或監控告警，可能執行危險指令。ToolHazard 可用於建立這類環境的對抗測試基準，作為代理上線前的紅隊演練。

### 實作前置條件

**資料準備**
- 至少一個種子領域的完整工具規格，包括工具名稱、輸入輸出格式、API 文件與業務流程說明。
- 真實或合成的環境狀態樣本，例如資料庫結構描述、文件範本、電子郵件格式與使用者任務描述。
- 明確的威脅模型定義，例如哪些狀態欄位是攻擊者可寫入、哪些操作屬於高風險行為。

**運算資源**
- LLM API 配額：Environment Simulator、Attacker Agent 與 User Simulator 皆需呼叫大型語言模型進行合成與規劃。
- 可執行環境：需容器化或隔離的執行環境來運行合成的有狀態程式，避免對抗測試影響生產系統。
- GPU 資源（選用）：若計畫使用 ToolHazard-Align 進行監督式微調或強化學習對齊，需準備相應的運算資源。

**技能需求**
- LLM 代理開發與提示工程經驗。
- 資安紅隊思維，熟悉間接提示注入與代理劫持攻擊。
- Python 程式開發與 API 設計能力。
- 強化學習基礎（選用，用於 RL 對齊階段）。

### 實作步驟建議

1. **定義種子領域與威脅模型**：選定要評估的應用領域，列出代理可呼叫的工具、環境狀態類型，以及攻擊者可寫入的狀態位置。

2. **準備工具與環境規格**：將現有 API 文件或業務規則轉換為 ToolHazard 可讀取的結構化描述，作為 Environment Simulator 的輸入。

3. **合成可執行的有狀態環境**：使用 Environment Simulator 生成環境藍圖、實體、工具函式與約束條件，並經過自動化品質檢查確保環境可執行且狀態一致。

4. **生成基於狀態的長程良性任務**：透過 User Simulator 根據環境狀態產生多步驟使用者查詢與任務目標，確保任務與環境狀態緊密結合。

5. **發現注入點並生成攻擊載荷**：使用 Attacker Agent 分析環境中哪些屬性會進入代理觀察，並針對每個可行注入點生成環境專屬的攻擊載荷。

6. **建構評估基準並執行紅隊測試**：將合成環境、任務與攻擊組合成 ToolHazard-Bench，對目標代理進行大規模評估，記錄攻擊成功率與執行軌跡。

7. **合成對齊資料並進行安全對齊**：利用評估結果產生 ToolHazard-Align 資料，進行監督式微調或強化學習，提升代理在對抗環境下的穩健性。

8. **持續迭代擴展新領域**：隨著業務新增工具或領域，重複上述流程，將新種子領域納入環境池，實現可擴展的安全評估。

### 潛在風險與注意事項

- **合成環境與真實環境的語義落差**：LLM 生成的環境可能在邏輯細節上與真實系統不一致，建議以真實 API 規格為基礎進行驗證，並在關鍵業務規則上加入人工審查。
- **攻擊載荷生成的不穩定性**：Attacker Agent 產生的載荷可能因模型版本或溫度參數而變動，建議固定種子、多次採樣並建立可重現的評估腳本。
- **過度對齊導致效用下降**：論文指出對齊資料可提升安全性同時保留良性任務效用，但實務上仍需監控代理在一般任務上的表現，避免過度防禦造成使用者體驗劣化。
- **資料隱私與合規風險**：若使用真實業務資料作為種子，需進行去識別化或改用合成資料，並確保對抗測試在隔離環境中執行。
- **評估指標設計偏誤**：攻擊成功率需搭配任務完成率、誤判率與觀察位置等維度綜合判讀，避免僅以單一指標決定代理是否安全。
- **注入時機與位置的偏誤**：研究發現較早遇到且靠近觀察結尾的注入更有效，設計測試時應涵蓋不同時間點與位置，避免評估結論過度樂觀。

### 與其他技術的整合建議

- **CI/CD 安全閘道**：將 ToolHazard-Bench 整合至代理上線前的持續整合流程，作為自動化紅隊測試關卡，未通過安全門檻即阻止部署。
- **RAG 與知識庫系統**：把 ToolHazard 合成的文件污染案例直接餵入企業 RAG 評估管線，測試檢索與生成階段的抗注入能力。
- **現有代理框架**：可將 ToolHazard 產生的環境包裝為 LangChain、AutoGen 或自研代理框架可呼叫的工具，降低與現有系統整合的門檻。
- **RLHF 與安全對齊流程**：將 ToolHazard-Align 作為額外的對抗偏好資料來源，與現有的安全微調資料混合使用，強化代理在間接提示注入情境下的拒絕能力。
- **SIEM/SOAR 平台**：將 ToolHazard 評估中發現的高風險攻擊模式轉換為偵測規則，整合至安全資訊與事件管理系統，強化生產環境的即時監控。

### 給不同背景讀者的閱讀建議

**初學者**：建議先掌握「間接提示注入」與「LLM 代理」的基本概念，再閱讀論文的威脅模型與圖一框架概覽。不必一開始就深入三個模組的實作細節，重點理解 ToolHazard 如何自動化產生對抗環境，以及為何這比手動建構環境更具擴展性。

**AI 工程師**：請聚焦於 Environment Simulator、Attacker Agent 與 User Simulator 的輸入輸出設計，以及如何把合成的可執行環境銜接到現有代理框架。實作時需特別注意狀態一致性、工具執行隔離與攻擊軌跡的可重現性，並參考論文方法將評估與對齊資料整合進微調管線。

**研究人員**：建議深入分析論文提出的可擴展合成範式，以及注入時機、觀察位置對攻擊有效性的影響。可進一步探索如何提升 Attacker Agent 的發現覆蓋率、降低合成環境的幻覺問題，或將 ToolHazard 的對齊資料應用於更進階的強化學習演算法。

**產品經理**：請優先關注適用場景、成本效益與風險管理。理解 ToolHazard 能為哪些產品線提供自動化紅隊測試，評估引入該框架所需的 LLM API 與運算成本，並規劃如何將安全對齊結果轉化為上線前的驗收標準與使用者溝通策略。
