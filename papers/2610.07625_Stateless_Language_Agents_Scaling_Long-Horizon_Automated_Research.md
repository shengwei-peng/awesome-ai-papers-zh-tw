## ⚡ TL;DR

長時程自動化研究中，代理反覆重播歷史、重複工作或停止實驗，單純增加推論無法持續產出進展。
本文提出無狀態語言代理，由框架持有研究狀態並重建角色專屬脈絡，由顧問指派平行工作代理執行實驗。
SLA在十億令牌預算下於所有任務達最佳結果，以少84%令牌追平最強基線，顧問僅耗不到0.6%令牌。

## 摘要翻譯

自動化研究系統日益以長時程方式運行大語言模型代理（LLM Agents），但單純增加推論（Inference）並不會自動帶來更多進展：代理會重播日益增長的歷史、重複彼此的工作，或在令牌消耗（Token Consumption）持續進行的同時停止實驗。然而，多數評估採用較短的令牌預算（Token Budget）或過早飽和（Saturation）的基準測試（Benchmarks），使這些失效模式（Failure Modes）未能受到檢驗。我們將這些失敗歸因於兩個選擇：研究狀態（Research State）存放在何處，以及由誰決定下一步該嘗試什麼。我們提出無狀態語言代理（Stateless Language Agents, SLAs），其建立在「無狀態代理驅動的有狀態搜尋」（Stateful Search with Stateless Agents）原則之上：沒有任何代理會將對話歷史（Conversations）延續至後續呼叫（Invocations）；相反地，執行框架（Harness）擁有研究狀態（候選解〔Candidate Solutions〕與量測結果〔Measured Outcomes〕），並為每次呼叫重建一個全新的、角色專屬的脈絡（Role-Specific Context）。每個代理所看見的內容因此成為一項明確的設計選擇，而非隨執行過程不斷增長的歷史。我們在 SLA 框架（SLA Framework）中實作此原則，其中無狀態的顧問代理（Advisor）會讀取由執行框架彙整、橫跨各搜尋方向（Search Directions）的證據，並將具體的實驗（Experiments）以明確指派任務（Explicit Assignments）的方式交給平行的工作代理（Workers）。我們在軟體工程（Software Engineering）、核心最佳化（Kernel Optimization）與演算法設計（Algorithm Design）等任務上，以高達十億令牌的預算，將 SLA 與三個近期提出的框架進行比較。SLA 在每項任務上都達到最佳最終結果，並以減少超過 84% 的令牌數達到最強核心最佳化基線方法（Baselines）的最終表現。來自共享檢查點（Checkpoints）的消融實驗（Ablations）顯示，聚焦式脈絡（Focused Contexts）與明確指派任務皆對 SLA 的進展有所貢獻，其效應在完整執行過程中可相互疊加，而顧問代理所消耗的令牌比例不到 0.6%。這些結果支持將持久的研究狀態排除於代理對話之外的 SLA 設計，並顯示較短的評估時程（Evaluation Horizons）可能誤判研究系統及其各組成部分。

### 核心貢獻（3～5點）
- **診斷長時程自動化研究的失效模式**：指出單純增加推論並非萬靈丹，代理會出現重播歷史、重複工作、停止實驗等問題，並將根因歸結於「研究狀態存放位置」與「下一步決策者」兩個設計選擇。
- **提出無狀態語言代理（SLA）的核心原則**：主張「無狀態代理驅動的有狀態搜尋」，由執行框架統一持有研究狀態，並為每次呼叫重建角色專屬的全新脈絡，使代理所見內容成為可設計的選項，而非隨執行膨脹的歷史。
- **實作 SLA 框架並驗證其效能**：以無狀態顧問代理讀取彙整證據、指派具體實驗予平行工作代理，在軟體工程、核心最佳化與演算法設計等任務上，於高達十億令牌的預算下全面超越三個近期框架。
- **展現顯著的效率優勢**：SLA 以減少超過 84% 令牌數即達到最強核心最佳化基線的最終表現，且顧問代理僅佔總令牌消耗的 0.6%，證明聚焦式脈絡與明確指派任務的設計具高度成本效益。
- **揭示短評估時程的誤判風險**：透過消融實驗與共享檢查點分析，論證僅以短預算或易飽和基準評估研究系統，可能嚴重低估或誤判其真實能力與各元件的相對貢獻。

### 適合對象
- 從事自動化研究、LLM 代理系統與長時程任務規劃的研究者與工程師
- 關注代理架構設計、狀態管理與成本效率最佳化的 AI 系統架構師
- 設計或選用 AI 研究基準、評估方法論的學術與產業實務工作者
- 對可擴展性、平行化代理協作與程式碼／演算法自動生成感興趣的機器學習與軟體工程領域研究生

## 深度分析

#### 方法論解析

本文提出**無狀態語言代理（Stateless Language Agents, SLAs）**，其核心設計哲學可概括為一句話：「**無狀態代理驅動的有狀態搜尋（stateful search with stateless agents）**」。這個看似矛盾的表述，實則精準地切分了自動化研究系統中兩個長期被混淆的概念——**代理的狀態（state）** 與 **代理的脈絡（context）**。

**1. 狀態與脈絡的形式化區分**

作者將「狀態」定義為跨呼叫（invocations）持續存在的資訊（候選解、量測結果、失敗紀錄），而「脈絡」則是單次呼叫中代理實際看見的內容。傳統的 LLM 代理系統將這兩者混為一談：對話歷史（conversation）既是狀態載體，也是脈絡來源，導致隨著執行時間延長，脈絡中累積的歷史越來越冗長。SLAs 的關鍵洞見在於：**狀態應由外部執行框架（harness）持有，代理本身則保持無狀態**。每次呼叫時，harness 根據當前任務需求，從持久化的研究狀態中「重建（reconstruct）」一個嶄新且角色專屬的脈絡（role-specific context）注入給代理。

**2. 雙層代理架構：Advisor 與 Workers**

SLA 框架將代理角色明確分工為兩類：

- **無狀態顧問代理（Stateless Advisor）**：負責讀取 harness 摘要過的全域證據（跨所有搜尋方向的候選解與量測結果），並據此指派具體實驗給各個工作代理。Advisor 本身不執行程式碼、不修改候選解，僅扮演「決策中樞」。
- **無狀態工作代理（Stateless Workers）**：每個 Worker 僅看見自己的指派任務、保留的候選解、以及本地端的回饋信號。Worker 之間不共享對話歷史，避免重複勞動。

這個架構解決了兩個長時程自動化研究的核心痛點：

- **脈絡膨脹問題**：Worker 不再需要重播整個搜尋歷史，只需聚焦於當前實驗；Advisor 雖需全域視野，但透過 harness 的摘要機制，脈絡長度可控。
- **探索協調問題**：Advisor 的明確指派（explicit assignments）確保平行 Workers 不會重複實作同一個功能，而是分散到不同的搜尋方向。

**3. 實驗可重現性的設計巧思**

由於研究狀態完全由 harness 持有，SLA 天然支援**從相同檢查點（checkpoint）恢復執行**——這對消融實驗（ablations）至關重要。作者能夠在完全相同的搜尋狀態下，移除 Advisor 脈絡重建、Worker 脈絡隔離、或 Advisor 指派機制，量化各元件的邊際貢獻。這種「實驗儀器化」的能力，是傳統對話式代理架構難以實現的。

**4. 與傳統 AutoResearch 框架的根本差異**

以 CORAL 為例，其代理在長達 231M 令牌後便反覆宣告自身解為最優，98% 的後續 session 不再發起工具呼叫，但令牌仍在持續消耗。這正是「狀態與脈緒不分離」的典型後果：代理的對話歷史已無法支撐新的探索決策，但系統仍將其視為有效狀態。SLA 透過將決策權（Advisor）與執行權（Workers）解耦，並讓決策依據來自結構化的證據摘要而非對話累積，從根本上切斷了這種「無效消耗」的迴圈。

#### 實驗數據解讀

**1. 核心結果：品質與效率的雙重突破**

在 **Anthropic 核心最佳化（kernel optimization）** 任務上，使用 Codex 模型時，SLA 的三次執行全部優於基線方法的九次執行（圖 1a）。更具說服力的是效率指標：SLA 僅用 **67.9M 累計令牌** 便達到了最強基線的最終效能，而基線需要 **986.3M 令牌**——這是 **14.5 倍的令牌節省（93.1% 降幅）**。在 FrontierSWE 軟體工程基準的四個任務（libexpat、Git→Zig、Dart→Haskell、Lua 編譯器）上，SLA 在完整 700M 令牌預算下平均超越最強任務專用基線 **4.95 分**。

**2. 排名反轉現象：評估時程的警示**

圖 1b 揭示了一個極為重要的方法論發現：**在 175M 令牌（25% 預算）時，SLA 在四個任務中均落後於最強基線；但在 700M 令牌（完整預算）時，SLA 在所有任務上反超**。具體而言，libexpat 上 SLA 從 −0.85 翻轉為 +6.75，Git→Zig 從 −3.90 翻轉為 +0.86，Dart→Haskell 從 −11.27 翻轉為 +6.68，Lua 編譯器從 −2.75 翻轉為 +5.49。這意味著**短預算評估會系統性地誤判研究系統的相對優劣**——那些在早期快速收斂但缺乏持續探索能力的方法，會被錯誤地評為更優。

**3. 基準飽和問題的量化**

作者以 26 圓堆積（26-circle packing）為例，展示基準過早飽和的危害：四種方法在僅 5M 令牌時便已收斂至彼此差距 2.3×10⁻¹⁰ 以內。這種飽和基準無法區分「快速達到天花板」與「持續轉化計算為進步」的能力差異，因此本文刻意選擇長時程、未飽和的任務進行評估。

**4. 消融實驗的複合效應**

從共享檢查點進行的消融實驗揭示了各元件的貢獻具有**跨時程複合性**：

- 移除 Worker 脈絡隔離：在 100M 令牌的延續執行中損失 5–11 個週期，但在完整 1B 令牌執行中損失 **224 個週期**。
- 移除 Advisor 指派機制：平行 Workers 反覆實作同一個功能（附錄 D.3），證明協調機制對避免冗餘探索不可或缺。
- 移除 Advisor 脈絡重建：Advisor 失去全域視野後，指派品質下降。

這些結果支持一個關鍵假設：**脈絡管理與實驗選擇的設計選擇，其效果會隨執行時間累積而放大**，而非線性衰減。

**5. 協調成本的可忽略性**

Advisor 僅消耗 **0.24–0.51% 的令牌** 與 **1.2–2.3% 的模型成本**，相比之下 SwarmResearch 的 Shepherd 消耗 8.4–10.7% 的令牌與 6.1–7.4% 的成本。這說明 SLA 的協調機制並非「以效率換品質」，而是**在幾乎可忽略的開銷下換取顯著的進步持續性**。

#### 與現有研究的比較

**1. 與三大基線框架的定位差異**

| 框架 | 狀態管理方式 | 協調機制 | 主要失效模式 |
|------|-------------|---------|-------------|
| **EvoX** | 演化式群體，狀態分散於個體 | 選擇、變異、交叉 | 缺乏語意層級的探索指導 |
| **CORAL** | 代理對話累積為狀態 | 隱式（依賴代理自主） | 231M 令牌後停滯，98% session 無工具呼叫 |
| **SwarmResearch** | 集中式狀態 + Shepherd 協調 | 集中式決策 | 協調成本高（8.4–10.7% 令牌） |
| **SLA（本文）** | Harness 持有狀態，代理無狀態 | Advisor 指派 + Worker 隔離 | 依賴摘要品質（潛在瓶頸） |

SLA 的獨特貢獻在於**將狀態所有權從代理轉移到 harness**，這在現有文獻中並無先例。EvoX 將狀態編碼進演化群體，CORAL 將狀態編碼進對話歷史，SwarmResearch 雖有集中式狀態但仍讓 Shepherd 維持對話上下文——三者都未實現「代理完全無狀態」的設計。

**2. 對自動化研究（AutoResearch）領域的推進**

本文將 AutoResearch 的評估標準從「迭代次數」或「模型呼叫次數」轉向**累計令牌數（cumulative tokens）** 作為統一度量衡。這一轉變看似細節，實則影響深遠：不同框架的單次呼叫成本差異巨大，唯有以令牌為單位才能公平比較「計算投入 vs. 進步產出」的效率。

**3. 對 LLM 代理設計的更廣泛啟示**

「狀態與脈絡分離」的原則不僅適用於自動化研究，也可推廣至任何長時程代理任務（程式碼維護、科學發現、資料分析）。本文實質上論證了一個更通用的設計準則：**對話歷史不應作為狀態的唯一載體**。

**4. 局限性與未明確討論的問題**

- **摘要品質瓶頸**：Advisor 的決策依賴 harness 對證據的摘要，若摘要遺漏關鍵細節，Advisor 的指派可能誤導 Workers。本文未深入探討摘要機制的失效模式。
- **Advisor 的單點故障**：所有 Workers 的指派都來自單一 Advisor，若 Advisor 陷入局部最優的指派策略，整個系統的探索方向可能偏斜。雖然實驗結果未顯示此問題，但理論上存在風險。
- **任務領域的侷限性**：評估集中在程式碼相關任務（核心最佳化、語言移植、演算法設計），對於需要豐富領域知識或人類回饋的研究任務（如自然科學假設生成），SLA 的適用性未經驗證。
- **模型依賴性**：主要結果使用 Codex + GPT-5.5，雖然也報告了 Claude Code 的結果（84% 令牌節省），但不同模型對 Advisor 指派的理解與執行能力可能差異顯著。

#### 未來研究方向

**1. 摘要機制的理論化與改進**

Advisor 的決策品質上限由 harness 的摘要品質決定。未來研究可探索：

- **自適應摘要**：根據 Advisor 的歷史決策品質，動態調整摘要的詳細程度與結構。
- **可驗證的摘要**：設計摘要的保真度指標，自動偵測摘要遺漏關鍵證據的情況。
- **多層次摘要**：區分「全域趨勢摘要」與「局部細節摘要」，讓 Advisor 在不同決策粒度間切換。

**2. 從單一 Advisor 到階層式協調**

當 Workers 數量擴展至數十甚至數百時，單一 Advisor 可能成為瓶頸。可探索：

- **階層式 Advisor**：頂層 Advisor 劃分子領域，底層 Advisor 負責具體指派。
- **競爭式 Advisor**：多個 Advisor 提出不同指派方案，由 meta-controller 選擇。
- **Advisor 的負載平衡**：根據 Worker 完成速度動態調整指派密度。

**3. 跨領域泛化**

SLA 目前在程式碼任務上驗證，未來可推廣至：

- **科學發現**：藥物設計、材料科學、蛋白質工程——這些領域有明確的量測目標（結合力、能量、活性），適合 SLA 的「候選解 + 量測結果」狀態模型。
- **機器學習研究**：自動化模型架構搜尋、超參數最佳化、神經網路壓縮。
- **創意任務**：遊戲關卡設計、音樂作曲——需要將「品質」量化為可比較的指標。

**4. 與人類研究的混合模式**

完全自動化的研究系統在可預見的未來仍難以取代人類科學家。可探索：

- **人類在迴圈中（human-in-the-loop）的 SLA**：Advisor 在關鍵決策點諮詢人類專家。
- **可解釋的指派**：讓 Advisor 解釋為何指派特定實驗，增強人類對系統的信任。
- **人類回饋的狀態整合**：將人類評價納入研究狀態，影響未來的 Advisor 指派。

**5. 理論分析：為何「無狀態」優於「有狀態」**

本文以實驗結果支持 SLA 的設計，但缺乏形式化的理論解釋。未來可從以下角度切入：

- **資訊理論觀點**：對話歷史中的冗餘資訊如何隨時間累積？無狀態設計如何實現資訊壓縮？
- **最佳化理論觀點**：將 SLA 視為一種非凸函數的最佳化演算法，分析其收斂速率與避免局部最優的能力。
- **學習理論觀點**：Advisor 的指派策略是否可形式化為某種 bandit 或強化學習問題？

**6. 評估方法論的標準化**

本文揭示了「短預算評估會誤判系統」的問題。未來可推動：

- **長時程基準的標準化**：建立類似 FrontierSWE 但涵蓋更多領域的長時程評估套件。
- **令牌效率指標**：將「達到目標品質所需的令牌數」作為標準報告指標。
- **飽和偵測機制**：自動判定基準是否已飽和，避免在飽和基準上浪費計算資源。

**7. 與基礎模型能力的共同演化**

SLA 的效能上限也取決於底層 LLM 的能力。隨著模型在長脈絡理解、工具使用、程式碼生成上的進步，SLA 的 Advisor 與 Workers 將能處理更複雜的任務。未來可探索：

- **模型規模與 SLA 效能的 scaling law**：Advisor 與 Workers 應使用相同還是不同規模的模型？
- **專用 vs. 通用模型**：Advisor 是否需要專門訓練以提升指派品質？

這些方向不僅能深化對 SLA 的理解，也將推動整個自動化研究領域向更可靠、更高效的方向發展。

## 論文問答

**Q1：為什麼長時程自動化研究中，單純增加推論預算並不能保證研究進展？**
A：根據本文，長時程自動化研究面臨的核心問題是「更多推論並不等於更多進展」。當 LLM 代理在長時程運行時，會出現三種典型失效模式：代理反覆重播日益增長的歷史記錄、彼此之間重複相同的工作，或在實驗停滯後仍持續消耗令牌。這些失效模式源於兩個根本性的設計選擇——研究狀態存放在哪裡，以及由誰決定下一步該嘗試什麼——而現有系統在這兩個選擇上往往缺乏明確設計。

**Q2：現有的自動化研究評估方式有哪些不足之處？**
A：現有評估通常以迭代次數或模型呼叫次數而非令牌數來衡量預算，且多數基準測試會過早飽和。例如在 26-circle packing 任務上，四種方法在 5M 令牌內就達到彼此差距僅 2.3×10⁻¹⁰ 的結果。這種飽和的基準只能測量方法多快觸及天花板，而非能否持續將計算轉化為進展，導致上下文管理與實驗選擇等設計選擇的影響未被充分檢驗。

**Q3：為什麼「研究狀態存放位置」與「下一步決策者」是兩個關鍵設計選擇？**
A：這兩個選擇直接決定了長時程研究的成敗。第一個選擇涉及「保留經驗同時控制脈絡」的挑戰：候選解、評估結果與失敗嘗試都是可重用的證據，但重播日益增長的歷史會消耗令牌並降低代理行為品質。第二個選擇涉及「將累積證據轉化為有效探索」的挑戰：記錄下來的發現並不能自動決定下一步該嘗試什麼，例如 CORAL 的一次 GPU 核心任務執行中，最後一次改進出現在 231M 令牌，之後代理反覆宣告其解為最優解，最終 1,500 次會話中有 98% 沒有呼叫任何工具。

**Q4：SLA 的核心原則「無狀態代理驅動的有狀態搜尋」是什麼意思？**
A：SLA 區分了代理的「狀態」（跨呼叫持續保存的內容）與「脈絡」（單次呼叫中看到的內容）。無狀態代理不保留任何狀態，包括其對話歷史，都不會延續到下一次呼叫。然而這並不意味著它沒有脈絡——執行框架（harness）擁有研究狀態（候選解與量測結果），並在每次呼叫時從中重建一個全新的、角色專屬的脈絡。如此一來，每個代理看到的內容就成為一個明確的設計選擇，而非隨執行累積的對話副產物。

**Q5：SLA 框架如何透過「執行框架控制的脈絡重建」來解決長時程挑戰？**
A：SLA 框架中，無狀態的 Advisor 看到的是跨所有搜尋方向的結構化證據摘要，而每個無狀態的 Worker 只看到自己的任務指派、保留的候選解與本地回饋。這種設計讓 Advisor 能夠掌握全局資訊以做出協調決策，同時讓 Worker 不被不相關的歷史淹沒，從而兼顧了經驗保留與脈絡控制兩個看似矛盾的需求。這也使得 SLA 成為一個實驗工具——消融實驗可以從相同的檢查點研究狀態恢復執行。

**Q6：SLA 如何透過「證據驅動的工作指派」避免平行代理之間的重複工作？**
A：SLA 由 Advisor 將累積的證據轉化為具體的實驗指派，使平行的 Workers 執行不同的實驗而非彼此重複。這與 SwarmResearch 等框架中代理可能自行選擇相似方向的情況形成對比。明確的指派機制讓每個 Worker 的工作內容由 Advisor 根據全局證據統一調配，避免了「多個代理同時嘗試同一想法」的資源浪費，這也是 SLA 在 FrontierSWE 任務上能夠在 175M 令牌時落後、但在 700M 令牌時反超基線的關鍵原因。

**Q7：SLA 在哪些基準任務上進行了評估？**
A：SLA 在三類長時程任務上進行評估：軟體工程（FrontierSWE，包含 libexpat、Git→Zig、Dart→Haskell、Lua 編譯器等）、核心最佳化（Anthropic kernel optimization）以及演算法設計。預算最高達到十億累計令牌，並與三個近期框架（EvoX、CORAL、SwarmResearch）進行比較，使用 Codex 搭配 GPT-5.5 等模型。這些任務的共同特徵是具有可量測的目標但沒有已知最優解，需要大量實驗迭代才能逐步逼近更好的解。

**Q8：SLA 的關鍵實驗結果為何？**
A：SLA 在每個評估任務上都達到了最佳的全預算結果。在使用 Codex 的 Anthropic 核心最佳化任務上，所有三次 SLA 執行的結果都優於所有九次基線執行；SLA 以 93% 較少的令牌（67.9M vs. 986.3M）即達到最強基線的平均最終效能。在 FrontierSWE 上，SLA 平均比最強的逐任務基線高出 4.95 分。這顯示 SLA 不僅找到更強的解，還大幅降低了達成目標所需的令牌數，證明了其架構設計的實質效益。

**Q9：消融實驗揭示了哪些設計選擇的貢獻？**
A：從共享檢查點進行的消融實驗顯示，聚焦式脈絡與明確指派都對 SLA 的進展有貢獻，且其效應會在完整執行中累積放大。具體而言：移除 Advisor 脈絡重建、Worker 脈絡隔離或 Advisor 指派都會降低平均進展；移除 Worker 隔離在 100M 令牌的延續執行中損失 5–11 個週期，但在完整 1B 令牌執行中損失高達 224 個週期。若無明確指派，平行的 Workers 會反覆實作同一個功能（詳見附錄 D.3），證明了這兩個機制缺一不可。

**Q10：SLA 適用於哪些實際的自動化研究場景？**
A：SLA 特別適用於需要長時程迭代探索的研究任務，包括軟體工程中的程式語言移植（如 Git→Zig、Dart→Haskell）、函式庫開發（libexpat）、編譯器建置（Lua 編譯器）、GPU 核心最佳化，以及演算法設計。這些任務的共同特徵是具有可量測的目標但沒有已知最優解，需要大量實驗迭代才能逐步逼近更好的解。對於企業研發團隊而言，SLA 的框架可以被應用於自動化測試案例生成、效能調校、程式碼重構等場景。

**Q11：從產品化角度來看，SLA 的成本效益如何？**
A：SLA 展現了極高的成本效益：Advisor 僅消耗 0.24–0.51% 的令牌與 1.2–2.3% 的模型成本，相比之下 SwarmResearch 的 Shepherd 消耗 8.4–10.7% 的令牌與 6.1–7.4% 的成本。這意味著明確的協調機制不僅有效，而且非常便宜——因為協調與實作被分離開來，Worker 模型可以選用較便宜的模型，而 Advisor 因為只看摘要證據，所需資源極少。這種成本結構讓 SLA 在實際部署時具有明顯的經濟優勢。

**Q12：SLA 對自動化研究領域的整體影響是什麼？**
A：SLA 的結果主張將持久的研究狀態保留在代理對話之外，並顯示短評估時程可能誤判研究系統及其元件。這對領域的影響包括：促使研究者重新思考代理架構中「狀態」與「脈絡」的分工；強調長時程評估的必要性；以及展示如何透過明確的協調機制實現高效的多代理協作。這些發現可能改變未來自動化研究系統的設計方向，從「讓代理記住一切」轉向「讓框架管理狀態、讓代理專注於當前任務」。

**Q13：SLA 框架有哪些已知的限制？**
A：雖然論文中沒有明確列出所有限制，但從內容可推斷幾項：SLA 的有效性依賴於 Advisor 能夠正確解讀證據並做出好的指派，若 Advisor 模型能力不足，可能會限制整體效能。此外，SLA 的評估主要集中在程式碼相關任務（軟體工程、核心最佳化、演算法設計），對於需要不同類型推理（如自然科學研究、數學證明）的任務，其適用性仍待驗證。另一個潛在限制是，Worker 之間的隔離雖然避免了冗餘，但也限制了它們從彼此的中間結果中學習的可能性。

**Q14：SLA 在哪些情況下可能會失敗？**
A：SLA 可能失敗的情境包括：當任務的搜尋空間過於發散、Advisor 難以從證據中提煉有意義的方向時；當任務需要高度依賴脈絡的細粒度推理、Worker 的聚焦式脈絡不足以支撐時；以及當任務的本質需要代理之間共享大量中間狀態、而非僅依賴結構化證據摘要時。此外，若評估指標本身有缺陷或容易被「hack」，SLA 的最佳化方向也可能偏離真正的研究目標，這是所有自動化研究系統的共同風險。

**Q15：SLA 未來可以朝哪些方向發展？**
A：未來發展方向可能包括：將 SLA 原則應用於更廣泛的研究領域（如科學發現、數學定理證明）；探索更進階的 Advisor 機制（例如階層式 Advisor 或學習式指派策略）；研究如何讓 Worker 也能在保留隔離性的同時共享部分有用的中間結果；以及發展更好的長時程評估基準，避免飽和問題，從而更準確地衡量自動化研究系統的真實進展能力。此外，將 SLA 與人類研究者的偏好對齊、引入領域知識作為先驗，也是值得探索的方向。

## 實務應用指南

### 適用場景

**1. 大規模 GPU 核心最佳化任務**
適用於需要反覆迭代、量測效能的程式碼最佳化場景，例如深度學習框架的算子核心、資料庫查詢引擎、影像處理管線等。SLA 的 Advisor-Worker 架構特別適合此類任務，因為每個最佳化方向（向量化、記憶體布局、平行化策略）都需要獨立探索，且每次實驗都有明確的量測指標（加速比、吞吐量）。

**2. 跨語言程式碼移植與重構**
例如將 Git 從 C 移植到 Zig、Dart 移植到 Haskell 等大型專案。這類任務需要長時間探索（數百萬至數十億令牌）、多個平行實驗（不同模組、不同移植策略），且容易陷入「重複實作同一個功能」的陷阱。SLA 的明確指派機制可避免 Worker 重複勞動。

**3. 自動化演算法發現與競賽程式設計**
適用於無已知最佳解、需要創造性探索的演算法設計問題（如 26 圓堆疊、組合最佳化、啟發式搜尋）。SLA 的搜尋方向追蹤機制能保留跨方向的證據，避免單一 Worker 陷入局部最佳解。

**4. 企業內部的 CI/CD 與基礎設施調校**
長期運行的建置流程最佳化、雲端資源配置調校、測試套件優化等。這些任務通常有明確的量測指標（建置時間、成本、錯誤率），且需要跨多個調校維度（快取策略、平行度、資源配額）平行探索。

**5. 科學研究自動化（藥物篩選、材料設計、模型架構搜尋）**
需要大量實驗迭代、每次實驗有量化結果、且探索空間龐大的研究任務。SLA 的「harness 持有研究狀態」設計讓研究人員能在不中斷實驗的情況下，從檢查點恢復並進行消融實驗。

### 實作前置條件

**資料需求**
- **可量測的評估函式**：每個任務都需要能自動執行的評估腳本，回傳數值化結果（加速比、通過率、分數等）。這是 SLA 區分「有進展」與「原地踏步」的基礎。
- **候選解儲存庫**：需要持久化儲存所有候選解及其對應的量測結果（檔案系統、物件儲存、資料庫皆可），作為 harness 持有的研究狀態。
- **任務規格文件**：清楚定義任務目標、輸入輸出格式、評估標準，供 Advisor 與 Worker 參考。
- **基準測試集**：用於驗證系統在已知任務上的表現，並進行消融實驗。

**運算資源**
- **多組 LLM API 配額或自架模型服務**：Worker 數量決定平行度，論文中每個任務通常同時運行 3–10 個 Worker。
- **充足的令牌預算**：完整實驗需數億至數十億令牌；建議初次實作先以 1M–10M 令牌小規模驗證。
- **任務執行環境**：每個 Worker 需要獨立的沙箱環境（容器、虛擬機）來執行程式碼並量測結果。
- **檢查點儲存空間**：每次狀態快照可能包含數百至數千個候選解，需規劃儲存容量。

**技能門檻**
- **LLM 代理設計經驗**：熟悉 prompt engineering、工具呼叫（function calling）、代理迴圈設計。
- **分散式系統基礎**：理解任務排程、狀態同步、故障恢復機制。
- **領域專業知識**：例如做核心最佳化需要懂 CUDA、SIMD；做程式移植需要懂來源與目標語言的語意差異。
- **評估方法論**：能設計可靠的評估函式，避免量測雜訊掩蓋真實進展。

### 實作步驟建議

**步驟 1：設計 Harness 架構**
建立中央調控層，負責持有研究狀態（候選解 + 量測結果）、管理 Worker 生命週期、記錄檢查點。Harness 應提供 API 讓 Advisor 查詢狀態、指派任務，並讓 Worker 提交結果。建議採用事件驅動或訊息佇列架構，方便水平擴展。

**步驟 2：實作狀態管理與檢查點機制**
設計候選解的儲存格式（程式碼、量測結果、中繼資料、評估時間戳記）。實作序列化與反序列化邏輯，確保能從任意檢查點完整恢復研究狀態。這是後續消融實驗的基礎，也是 SLA 能「實驗性儀器化」的關鍵。

**步驟 3：建構無狀態 Advisor**
Advisor 接收由 harness 摘要的證據（跨搜尋方向的彙整），輸出具體的實驗指派。Prompt 設計需包含：當前所有搜尋方向、每個方向的最新結果、未探索的空間、Worker 數量與能力。關鍵是讓 Advisor 看到「全局證據」而非單一 Worker 的對話歷史。

**步驟 4：建構無狀態 Worker**
每個 Worker 接收單一明確的指派（要做什麼實驗、用什麼方法、評估什麼指標），加上其保留的最佳候選解與本地回饋。Worker 完成後提交結果給 harness，不保留任何對話狀態。確保每次呼叫都是「全新的」——這是 SLA 區別於傳統代理的核心。

**步驟 5：實作脈絡重建邏輯**
為 Advisor 與 Worker 分別設計脈絡組裝函式。Advisor 的脈絡應聚焦於「跨方向的證據彙整」；Worker 的脈絡應聚焦於「單一指派 + 該方向的本地回饋」。避免將整個對話歷史塞入脈絡——這正是論文中「聚焦式脈絡」消融實驗要驗證的設計選擇。

**步驟 6：加入實驗指派機制**
設計 Advisor 的輸出格式（結構化的實驗規格），讓 Worker 能直接執行。應包含：實驗目標、實作方向、評估指標、預期輸出。論文的消融實驗顯示，沒有明確指派時 Worker 會重複實作同一個功能。

**步驟 7：執行小規模消融實驗**
從共享檢查點出發，比較「有/無 Advisor 脈絡重建」、「有/無 Worker 脈絡隔離」、「有/無明確指派」三個變體。論文的發現是這些效應會在完整 1B 令牌執行中累積放大，因此消融實驗需在足夠長的時程上進行才能觀察到差異。

**步驟 8：擴展到完整預算並監控**
逐步放大令牌預算（10M → 100M → 1B），監控 Advisor 令牌佔比（論文顯示 <0.6%）、Worker 重複率、進展速率。設定停滯偵測機制，當連續 N 次實驗無進展時觸發 Advisor 重新規劃搜尋方向。

### 潛在風險與注意事項

**風險 1：評估函式雜訊掩蓋真實進展**
若評估結果波動過大（例如 GPU 執行時間受背景程序影響），SLA 的「量測結果」會誤導 Advisor 與 Worker 的決策。**緩解措施**：多次執行取中位數、控制實驗環境（固定硬體、關閉背景服務）、使用統計顯著性檢定。

**風險 2：Worker 重複勞動**
即使有 Advisor 指派，若指派粒度太粗，Worker 仍可能在細節上重複。論文的消融實驗顯示，沒有明確指派時 Worker 會反覆實作同一個功能。**緩解措施**：指派規格需包含「具體實作方向」而非僅「目標」，並在 harness 層加入相似度偵測。

**風險 3：過早收斂到次佳解**
Advisor 可能過早判定某方向已「飽和」而停止探索。**緩解措施**：保留一定比例的探索預算（ε-greedy 策略）、定期重啟冷啟動實驗、記錄「長期未改善但未宣告失敗」的方向供人工審查。

**風險 4：令牌成本失控**
長時程執行的成本可能遠超預期，尤其當 Worker 陷入無效迴圈時。**緩解措施**：設定硬性令牌上限、實作單次呼叫的令牌配額、監控 Advisor 與 Worker 的成本比例（論文顯示 Advisor 應遠低於 Worker）。

**風險 5：檢查點膨脹**
隨著執行時間增長，候選解數量可能膨脹到難以管理的規模。**緩解措施**：定期清理被淘汰的候選解、實作候選解的摘要與聚類、設定保留上限（例如只保留每個方向的前 K 名）。

**風險 6：模型升級導致可重現性問題**
論文中使用 Codex 與 GPT-5.5，若模型版本更新，結果可能無法重現。**緩解措施**：固定模型版本與 API 端點、記錄所有實驗的模型指紋、在論文中明確標註模型版本。

### 與其他技術的整合建議

**與現有代理框架整合**
SLA 的「harness + 無狀態代理」架構可與 LangChain、AutoGen、CrewAI 等框架共存——這些框架負責單次呼叫內的代理邏輯（工具呼叫、推理迴圈），而 SLA 的 harness 負責跨呼叫的狀態管理與脈絡重建。建議將 SLA 視為「代理編排層」，建構在現有框架之上。

**與版本控制系統整合**
將每個候選解視為一次 commit，自動記錄在 Git 儲存庫中。這讓研究人員能隨時回溯、比較、cherry-pick 特定候選解。Harness 可透過 Git API 讀取歷史，並在評估時 checkout 對應版本。

**與監控系統整合**
將每次實驗的量測結果串流至 Prometheus、Grafana 或 Weights & Biases，建立即時儀表板。關鍵指標包括：進展速率（單位令牌的改進量）、Worker 利用率、Advisor 指派多樣性、評估函式穩定性。

**與排程系統整合**
對於企業內部應用，可將 SLA 整合至 Kubernetes 或 Airflow，讓長時程研究任務能彈性分配資源、優雅處理故障、與其他工作負載共存。

**與人類專家工作流程整合**
Advisor 的指派可設計為「人類可審查」的格式，讓領域專家能介入修正方向。Harness 應支援「暫停 → 人工審查 → 調整指派策略 → 繼續執行」的工作流程，這在科學研究自動化中特別重要。

**與評估基準整合**
論文中使用的 FrontierSWE、Anthropic Kernel Optimization 等基準可作為標準化測試套件。建議在自家系統上定期執行這些基準，建立可比較的效能追蹤。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節，理解「為什麼長時程自動化研究會失敗」這個問題——核心是「更多推論不等於更多進展」。接著看圖 1 的視覺化結果，感受 SLA 在令牌效率上的優勢（14.5 倍令牌節省）。不需要深入技術細節，重點是建立「harness 持有狀態、代理保持無狀態」這個設計直覺。

**給 AI 工程師**：重點閱讀第 2 節（SLA 框架設計）與第 4 節（消融實驗）。理解 Advisor 與 Worker 的脈絡組裝差異、明確指派的格式設計、檢查點機制的實作細節。建議直接參考論文的開源程式碼（GitHub 連結在首頁），從小規模實驗開始重現結果，再逐步擴展到自己的應用場景。特別注意「聚焦式脈絡」與「明確指派」這兩個消融實驗的結論——它們會在完整執行中累積放大。

**給研究者**：重點閱讀第 3 節（實驗設計）與第 5 節（討論）。論文的核心貢獻不只是 SLA 框架本身，而是「短評估時程會誤判研究系統」這個方法論洞察。建議從這個角度思考：你的研究領域中，有哪些評估方式可能因為時程太短而錯失重要現象？論文的消融實驗設計（從共享檢查點恢復）也值得借鏡，這是一種比「從頭重跑」更有效率的實驗方法。

**給產品經理**：重點閱讀摘要與圖 1 的視覺化結果，理解 SLA 在「令牌效率」上的商業價值——同樣的結果用 14.5 倍更少的成本達成，這直接轉化為 API 費用節省。論文的「Advisor 只佔 0.6% 令牌」這個數字說明協調成本極低，意味著 SLA 可以大規模部署而不會被協調開銷拖垮。建議將 SLA 視為「長時程 AI 代理任務的基礎設施層」，評估在你的產品線中哪些任務適合採用這種架構（例如需要數小時至數天持續運行的自動化任務）。
