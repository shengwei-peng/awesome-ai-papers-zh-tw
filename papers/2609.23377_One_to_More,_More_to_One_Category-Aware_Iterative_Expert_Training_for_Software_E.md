## ⚡ TL;DR

倉庫級軟體工程任務類別異質，聯合強化學習常出現類別蹺蹺板效應，整體指標掩蓋部分類別退步。

## 摘要翻譯

倉庫級軟體工程（Repository-level software engineering, SWE）涵蓋異質的任務類別，而這些類別在匯集式智慧體強化學習（pooled agentic reinforcement learning）下的進展可能並不均衡：某些類別的進步伴隨著其他類別的退步，而整體解決率（aggregate resolution）則掩蓋了這些變化。受此類別蹺蹺板效應（category see-saw）驅動，我們提出一套類別感知的專家訓練與策略整合框架（category-aware expert-training and policy-integration framework）。可執行任務建構（Executable task construction）與 SWE 標註器（SWE Labeler），一個基於證據的多軸標註系統（evidence-grounded multi-axis labeling system），共同組織訓練池。初始的類別特定強化學習（Category-specific RL）提升了平均訓練成功率，但實例級進展（instance-level progress）仍不均衡，因此促使我們明確鞏固成功行為（consolidation of successful behavior）並採用策略自適應任務選擇（policy-adaptive task selection）。同源類別專家（Same-origin category experts）交替進行長程智慧體迷你強化學習（long-horizon Agentic-miniRL）與更新-修復-擴展（Refresh-Repair-Expand, RRE）：更新後的策略會刷新實例掌握度（instance mastery），沿用自身的已驗證成功軌跡（verified successful trajectories）進行修復式監督微調（Repair SFT），並重新選擇任務以進行進一步的強化學習（Reinforcement learning, RL）。標籤路由多教師同策略蒸餾（Label-routed multi-teacher on-policy distillation, MOPD）將各專家整合為單一可部署的學生模型，並透過 ReLU 門控獎勵外推（ReLU-gated reward extrapolation），僅保留每位教師相對於參考基準（reference）的改進方向。專家訓練與策略整合無需外部模型提供解題軌跡或動作目標。我們透過整體與逐類解決率、相對於各聯合強化學習基線（Joint-RL baseline）的最小類別提升（minimum category lift），以及專家增益恢復（expert-gain recovery），來評估匯集式強化學習（Pooled RL）、平衡式強化學習（Balanced RL）、專家訓練過程，以及單一模型整合的效果。最終的 MOPD 策略在 Pro-618 上達到 58.04% 的平均解決率（mean resolution），在 SWE-bench 多語言（SWE-bench Multilingual）上達到 59.00%，分別較基礎模型（base model）提升 5.39 與 2.78 個百分點。

### 核心貢獻（3～5點）
- 揭示並解決匯集式智慧體強化學習中的「類別蹺蹺板效應」，提出類別感知的專家訓練與策略整合框架。
- 設計可執行任務建構與基於證據的多軸 SWE 標註器，系統化地組織異質訓練資料。
- 提出更新-修復-擴展（RRE）迭代循環，結合長程智慧體迷你強化學習與修復式監督微調，鞏固成功行為並自適應選擇訓練任務。
- 透過標籤路由多教師同策略蒸餾（MOPD）與 ReLU 門控獎勵外推，將多個同源類別專家整合為單一可部署策略。
- 在 Pro-618 與 SWE-bench 多語言測試集上取得顯著提升，且整個流程無需外部模型提供解答軌跡。

### 適合對象
適合對大型語言模型智慧體、倉庫級軟體工程任務、長程強化學習，以及多專家模型整合與蒸餾有興趣的研究者與工程師；特別是關注 SWE-bench 系列基準、程式碼生成與修復系統，以及希望改善異質任務訓練穩定性的實務開發者。

## 深度分析

#### 方法論解析

本研究的核心命題是：在 Repository-level software engineering（倉庫級軟體工程）這類高度異質的長程任務中，傳統將所有資料混合後進行 Joint training on the pooled mixture（匯集混合資料的聯合訓練）會掩蓋類別間的相互牽制，即所謂的 Category see-saw（類別蹺蹺板效應）。作者因此提出 Category-aware Iterative Expert Training（類別感知迭代式專家訓練）與 Policy Integration（策略整合）框架，整體可拆解為四個環節：可執行任務建構與標註、同源類別專家訓練、Refresh–Repair–Expand（RRE，更新–修復–擴展）迭代循環，以及 Label-routed multi-teacher on-policy distillation（MOPD，標籤路由多教師同策略蒸餾）。

**1. SWE Labeler（SWE 標註器）：以證據為基礎的多軸分類**

作者首先建立 SWE Labeler（SWE 標註器），這是一套 Evidence-grounded multi-axis labeling system（基於證據的多軸標註系統）。與一般僅依賴人工標題或領域直覺的分類不同，此系統透過 Source-grounded label definitions（源頭導向的標籤定義）與明確決策規則，對 issue–change 實例以及 Agent interaction trajectories（智慧體互動軌跡）進行標註。系統包含兩個層級語義軸與三個順序尺度軸，能夠同時描述「任務本質」（例如 service and data-layer bugfixes（服務與資料層錯誤修復）、user-facing interface adjustments（使用者介面調整）、infrastructure and tooling changes（基礎設施與工具變更）、performance or security patches（效能或安全性修補））以及「難度／規模」等面向。這些標籤不只用於訓練池建構，也決定後續 MOPD 中的 teacher routing（教師路由），使整個流程具有可稽核性（auditable）。

**2. Executable task construction（可執行任務建構）**

在進入訓練前，原始 issue 必須被轉換為可透過 Executable-verdict interface（可執行裁決介面）驗證的任務。這意味著每個實例都配備測試或檢查機制，讓 Agent（智慧體）在長程軌跡末端能獲得稀疏但客觀的環境獎勵（environment reward）。這種設計與 SWE-bench 系列的精神一致：正確性不是由人類判斷，而是由執行結果決定。

**3. Same-origin category experts（同源類別專家）與 RRE**

作者從單一 Base model（基礎模型）出發，為每個類別訓練 Same-origin category experts（同源類別專家）。這裡的「同源」很重要：它確保各專家起始點相同，後續差異純粹來自類別特定資料，從而降低整合時的分布偏移。每個類別專家的訓練並非一次性 RL，而是交替進行 Long-horizon Agentic-miniRL（長程智慧體迷你強化學習）與 RRE：

- **Refresh（更新）**：評估當前策略對各實例的 Instance mastery（實例掌握度），確認哪些實例已經穩定解決、哪些已經遺忘或退步。
- **Repair（修復）**：利用前一段 RL 產生的 Verified successful trajectories（已驗證成功軌跡），進行 Repair SFT（修復式監督微調）。這一步的關鍵在於「用自己的成功軌跡修復自己」，不需要外部模型提供解答，從而鞏固 Successful behavior（成功行為）。
- **Expand（擴展）**：從更廣泛的訓練池中進行 Policy-adaptive task selection（策略自適應任務選擇），挑選當前策略尚未掌握、但可能帶來最大學習增益的任務，進入下一輪 RL。

這個循環同時解決了兩個問題：長程 RL 中 Instance mastery（實例掌握度）會隨時間漂移，導致固定訓練池 stale；以及平均成功率上升時，部分實例其實在退步。RRE 透過持續刷新與修復，將成功行為固化到策略中。

**4. Label-routed MOPD（標籤路由多教師同策略蒸餾）**

訓練出多個類別專家後，最終目標是將其整合為單一可部署模型。作者採用 Label-routed multi-teacher on-policy distillation（標籤路由多教師同策略蒸餾）：學生模型在訓練時，依據當前任務的標籤決定由哪一位類別專家擔任教師，並在該教師的引導下進行 On-policy distillation（同策略蒸餾）。為了避免教師將自己的退步方向也傳遞給學生，作者引入 ReLU-gated reward extrapolation（ReLU 門控獎勵外推）：以 Reference（參考基準）策略為錨點，只保留教師相對於參考策略有正向改進的方向。這使得 MOPD 不僅是模仿教師行為，更學習「相對於基線的改進方向」。值得注意的是，整個專家訓練與策略整合過程無需外部模型提供解答軌跡或動作目標，所有訓練訊號來自環境獎勵與策略自身產生的軌跡。

#### 實驗數據解讀

作者在兩個基準上進行評估：Pro-618 與 SWE-bench Multilingual（SWE-bench 多語言）。比較對象包括 Base model（基礎模型）、Pooled RL（匯集式強化學習）與 Balanced RL（平衡式強化學習）。評估指標除了常見的 Mean resolution（平均解決率）外，特別強調 per-category resolution（各類別解決率）、Minimum category lift（最小類別提升）以及 Expert-gain recovery（專家增益恢復）。

**1. 整體表現**

最終 MOPD policy（MOPD 策略）在 Pro-618 上達到 58.04% 的 Mean resolution（平均解決率），相較 Base model（基礎模型）提升 5.39 個百分點；在 SWE-bench Multilingual（SWE-bench 多語言）上達到 59.00%，提升 2.78 個百分點。這些數字顯示，經過類別專家訓練與整合後的單一模型，不僅在整體上優於未經訓練的基礎模型，也優於直接進行 Pooled RL（匯集式強化學習）的聯合訓練基線。

**2. 類別層級的解讀**

本研究最重要的貢獻不在於絕對分數，而在於揭示 Aggregate metric（聚合指標）無法反映的現象。Pooled RL（匯集式強化學習）雖然可能維持穩定的整體分數，但某些類別進步的同時，其他類別卻在退步，這正是 Category see-saw（類別蹺蹺板效應）。Balanced RL（平衡式強化學習）透過類別取樣平衡試圖緩解此問題，但僅靠平衡曝光並不足以產生強大的類別專家。相較之下，本方法先讓各類別獨立發展出專精能力，再透過 MOPD 合併，因此能在 per-category resolution（各類別解決率）上同時取得進步。

**3. Minimum category lift（最小類別提升）**

Minimum category lift（最小類別提升）衡量的是：相較於各個 Joint-RL baseline（聯合強化學習基線），所有類別中「最差」的相對提升是多少。這個指標對於評估公平性與穩健性特別重要。如果某個方法在大部分類別表現優異，卻在少數類別嚴重退步，其 Minimum category lift（最小類別提升）就會很低。本方法強調該指標，意味著整合後的策略不僅追求平均表現，也避免犧牲任何類別。

**4. Expert-gain recovery（專家增益恢復）**

Expert-gain recovery（專家增益恢復）則衡量最終單一學生模型保留了多少來自各類別專家的增益。這是專家整合方法的核心挑戰：如果蒸餾過程中遺失了專家的特殊能力，那麼訓練專家的成本就白費了。實驗結果顯示 MOPD 能有效回收專家增益，說明 ReLU-gated reward extrapolation（ReLU 門控獎勵外推）與 label routing（標籤路由）確實有助於保留各教師的改進方向。

**5. 綜合意義**

從實驗設計來看，作者刻意同時報告 aggregate（整體）與 per-category（各類別）結果，並引入 Minimum category lift（最小類別提升）與 Expert-gain recovery（專家增益恢復），這反映出研究目標並非單純刷分，而是理解並改善長程 Agentic RL（智慧體強化學習）中的結構性學習問題。對於實務部署而言，一個在所有類別都穩定進步的單一模型，遠比一個平均高分但特定類別嚴重退步的模型更有價值。

#### 與現有研究的比較

本研究在現有文獻中處於三個方法家族的交會點，並針對各自的缺口提出補強。

**1. 相較於匯集式聯合訓練（SWE-RL、SWE-Gym、SWE-Master）**

現有系統如 SWE-RL、SWE-Gym 與 SWE-Master 大多採用 Pooled RL（匯集式強化學習）或混合 SFT（Supervised fine-tuning，監督式微調）與 RL（Reinforcement learning，強化學習）來訓練共享策略。這些方法方便擴展，但忽略了 Repository-level SWE（倉庫級軟體工程）任務在 Trajectory length（軌跡長度）、Reward variance（獎勵變異）與 Data frequency（資料頻率）上的差異。本研究指出，即使任務共享底層技能（如程式碼編輯、測試執行），Joint update（聯合更新）仍可能幫助某一類別而傷害另一類別。透過類別分離與後續整合，本方法在避免 Category see-saw（類別蹺蹺板效應）上更具結構優勢。

**2. 相較於子任務流程分解（Agentless、SWE-Fixer、AutoCodeRover）**

Agentless、SWE-Fixer 與 AutoCodeRover 等研究將 issue resolution 拆解為 Localization（定位）、Retrieval（檢索）、Editing（編輯）等功能階段。這種 Pipeline decomposition into subtasks（子任務流程分解）與本研究是互補關係：前者分解的是「解題流程」，本研究分解的是「訓練資料分布」。未來兩者結合，可能同時在流程模組與類別專家兩個層次進行專精化。

**3. 相較於跨領域專家拆分與融合（Branch-Train-Merge、MOPD、ExOPD）**

Branch-Train-Merge、MOPD 與 ExOPD 等方法已在數學、程式碼生成、指令遵循等傳統領域驗證了專家拆分與融合的有效性。然而，這些方法的 Domain experts（領域專家）劃分通常由領域邊界自然給定（例如數學 vs. 程式碼）。本研究的特殊之處在於：它在一個單一領域（Repository-level SWE，倉庫級軟體工程）內部，透過 SWE Labeler（SWE 標註器）主動建立類別粒度，並訓練 Same-origin category experts（同源類別專家）。此外，本研究的 MOPD 並非直接沿用跨領域版本，而是結合 ReLU-gated reward extrapolation（ReLU 門控獎勵外推）與 label routing（標籤路由），並且完全不需要外部模型提供軌跡。

**4. 限制與待釐清之處**

儘管方法新穎，仍有若干限制。首先，SWE Labeler（SWE 標註器）的類別體系是否完備、是否適用於所有 Repository-level SWE（倉庫級軟體工程）資料集，仍需更多驗證。其次，類別粒度是一個權衡：過粗無法捕捉異質性，過細則每類資料太少、專家訓練不穩定。第三，MOPD 雖然能回收大部分專家增益，但蒸餾過程仍可能遺失部分細微能力，特別是當教師之間的行為模式高度衝突時。最後，本方法依賴 Executable-verdict interface（可執行裁決介面），對於難以自動驗證的維護任務（例如設計重構、文件更新），其適用性會受到限制。

#### 可重現性評估

從目前提供的預印本內容來看，作者尚未明確釋出原始碼、資料處理流程、模型權重或訓練設定。可重現性因此面臨以下挑戰：

- **SWE Labeler（SWE 標註器）的決策規則**：雖然文中提到 Source-grounded label definitions（源頭導向的標籤定義）與明確規則，但具體的標註邏輯、特徵提取方式與人工校驗流程並未詳細公開。
- **Executable task construction（可執行任務建構）**：將原始 issue 轉換為可執行任務需要特定的環境設定、依賴安裝與測試篩選邏輯，這些細節對重現訓練池至關重要。
- **RRE 與 Agentic-miniRL（智慧體迷你強化學習）**：長程 RL 的獎勵設計、採樣策略、超參數（如學習率、KL 約束、軌跡長度上限）以及 Repair SFT（修復式監督微調）的資料篩選門檻，都會顯著影響結果。
- **MOPD 實作**：Label routing（標籤路由）的具體實現、Reference（參考基準）策略的選擇、ReLU-gated reward extrapolation（ReLU 門控獎勵外推）的計算方式，都需要程式碼才能精確重現。
- **基準資料**：SWE-bench Multilingual（SWE-bench 多語言）是公開基準，但 Pro-618 的組成與取得方式在提供的片段中並未說明。

整體而言，本研究的方法論描述已足夠讓讀者理解高層設計，但要進行獨立重現，仍需作者釋出完整的程式碼、標註規則、訓練配置與模型檢查點。建議後續版本補充開源連結、資料處理腳本，以及各基線的詳細超參數。

#### 未來研究方向

本研究為 Repository-level SWE（倉庫級軟體工程）的類別感知訓練開闢了多條後續研究路徑：

**1. 自動化類別發現**

目前的類別由 SWE Labeler（SWE 標註器）以規則方式定義。未來可結合無監督或半監督學習，從大量 issue–change 軌跡中自動發現潛在類別結構，減少人工設計成本，並發現人類難以預見的任務群聚。

**2. 動態類別平衡與線上路由**

本研究的 MOPD 使用固定 label routing（標籤路由）。未來可探索根據學生模型在各类別上的即時表現，動態調整教師權重或訓練取樣比例，進一步提升 Minimum category lift（最小類別提升）。

**3. 多粒度類別層次結構**

目前的兩個語義軸與三個順序軸可進一步擴展為層次化分類。例如，在「服務與資料層錯誤修復」下再細分為 ORM、API、序列化等子類別，並訓練對應的 sub-experts（子專家），最後透過層次化蒸餾整合。

**4. 跨類別知識遷移**

Same-origin category experts（同源類別專家）雖然獨立訓練，但彼此之間可能存在可遷移的共享技能。未來可研究如何在 RRE 的 Expand（擴展）階段，讓專家從其他類別的成功軌跡中選擇性學習，提升資料效率。

**5. 稀疏獎勵與密集獎勵模型**

Repository-level SWE（倉庫級軟體工程）的環境獎勵極為稀疏。未來可結合過程獎勵模型（process reward model）或學習型驗證器，為長程軌跡提供更密集的訓練訊號，減少對最終測試通過與否的依賴。

**6. 與外部軌跡教師的結合**

本方法強調無需外部模型提供解答軌跡，這在資料隱私或成本考量下是優勢。但在某些場景中，結合高品質外部軌跡作為輔助教師，可能進一步提升專家上限與整合效果。

**7. 理論理解 Category see-saw（類別蹺蹺板效應）**

目前對 Category see-saw（類別蹺蹺板效應）的觀察主要來自實證。未來可從多任務學習、梯度干擾與神經網路表示理論角度，量化不同類別間的衝突與協同，並據此設計更優化的訓練目標。

**8. 擴展至其他長程智慧體領域**

本框架的核心思想——先按可觀察標籤拆分訓練分布、再透過參考錨定的蒸餾整合——可應用於其他長程 Agentic tasks（智慧體任務），例如科學實驗設計、複雜資料分析或自動化系統管理。

**9. 持續學習與類別遺忘**

隨著新類別任務不斷出現，如何在新增類別專家的同時避免覆蓋舊類別能力，是值得研究的持續學習問題。RRE 的 Repair（修復）機制已具備雛形，但未來可結合彈性權重鞏固（EWC）等技術進一步強化。

**10. 更細緻的評估指標**

除了 Mean resolution（平均解決率）與 Minimum category lift（最小類別提升），未來可引入編輯距離、測試覆蓋率變化、執行成本、推理步數效率等指標，全面評估 SWE agents（軟體工程智慧體）的實用性。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**

A：這篇論文聚焦於倉庫級軟體工程（SWE）智慧體在強化學習訓練過程中，因任務類別異質性而導致的「類別蹺蹺板效應」（category see-saw）。具體來說，當所有類別的任務被混合在一起進行聯合 RL 訓練時，某些類別的表現會進步，但同時其他類別卻可能退步，而整體平均指標往往會掩蓋這種內部的此消彼長。作者希望建立一個能夠同時提升整體與各類別解決率的訓練框架，讓單一可部署模型既能廣泛又能穩定地處理不同類型的軟體工程任務。

**Q2：現有的匯集式強化學習方法為何在 SWE 任務上效果有限？**

A：現有方法如 SWE-RL、SWE-Gym 與 SWE-Master 通常將不同類別的任務混合成單一資料池進行聯合訓練，這種做法雖然實作方便，卻忽略了不同 SWE 任務在軌跡長度、獎勵變異與資料頻率上的結構性差異。例如，局部邏輯修復、跨模組相容性變更、建置修復與安全性修補所需的證據來源、工具互動模式與驗證方式都截然不同，導致聯合梯度更新可能對某些類別有利、對其他類別有害。更關鍵的是，單一的聚合指標無法揭露這種類別間的能力重分配，使得研究者難以察覺並修復特定類別的退化。

**Q3：為什麼「類別感知」的訓練方式對軟體工程智慧體特別重要？**

A：軟體工程任務本質上具有高度異質性，涵蓋服務與資料層錯誤修復、使用者介面調整、基礎設施變更以及效能或安全性修補等不同工程情境，每種情境都需要不同的推理策略與工具使用模式。如果訓練過程不區分這些類別，模型很容易在常見或獎勵訊號較穩定的任務上過度優化，卻在少見或高變異的任務上逐漸遺忘。透過類別感知訓練，研究者可以明確追蹤每個類別的進展、針對性地發展專家能力，並在整合階段確保單一模型保留各類別的專長。

**Q4：本文提出的核心訓練框架包含哪些主要元件？**

A：本文提出的框架包含三大核心元件：SWE Labeler 多軸標註系統、Refresh–Repair–Expand（RRE）迭代專家訓練循環，以及標籤路由多教師同策略蒸餾（MOPD）。首先，SWE Labeler 依據可觀察的任務特徵與軌跡證據，將訓練資料劃分為可審計的類別；接著，每個類別從同一基礎模型出發，透過 RRE 循環交替進行長程 Agentic-miniRL、成功軌跡修復式 SFT，以及策略自適應的任務擴展；最後，各類別專家透過 MOPD 被整合為單一可部署學生模型，並利用 ReLU 門控獎勵外推保留每位教師相對於參考基準的改進方向。

**Q5：Refresh–Repair–Expand（RRE）機制如何解決專家訓練中的退化問題？**

A：RRE 是一個三階段迭代循環，專門用來處理長程 RL 訓練中常見的「平均進步但個別實例退化」的現象。在 Refresh 階段，更新後的策略會重新評估並刷新對各實例的掌握度；在 Repair 階段，策略會利用自己在前一輪 RL 中產生且已驗證成功的軌跡進行監督式微調，藉此鞏固成功行為並修復遺忘；在 Expand 階段，則根據當前策略的弱點自適應地選擇新的訓練前沿任務，進行下一輪 RL 擴展。這種設計讓專家訓練不僅追求平均成功率的提升，也持續維護每個實例層級的穩定性。

**Q6：為什麼選擇「同源類別專家」與「同策略蒸餾」來整合專家能力？**

A：選擇同源類別專人是因為所有專家都從同一個基礎模型發展而來，這樣可以確保各專家在參數空間與行為分佈上具有較高的相容性，降低後續整合時的衝突與災難性遺忘風險。同策略蒸餾（on-policy distillation）則讓學生模型在每位教師自己的生成分佈下進行學習，而不是依賴外部模型提供的解答軌跡，這使得整個訓練與整合過程完全自給自足。此外，ReLU 門控獎勵外推機制確保學生只吸收每位教師相對於參考策略的「正向改進方向」，避免將教師的退化行為一併繼承過來。

**Q7：論文在哪些基準測試上進行評估，使用了哪些關鍵指標？**

A：論文主要在 Pro-618 與 SWE-bench Multilingual 兩個測試集上進行評估，同時也與匯集式 RL（Pooled RL）和平衡式 RL（Balanced RL）兩種聯合 RL 基線進行比較。評估指標除了整體平均解決率（mean resolution）之外，還特別強調每個類別的解決率變化、相對於聯合 RL 基線的「最小類別提升」（minimum category lift），以及整合後策略對專家增益的保留程度（expert-gain recovery）。這些指標共同確保模型不只在平均表現上進步，也能在各類別上均衡地提升。

**Q8：本文方法的關鍵實驗結果是什麼？**

A：最終的 MOPD 整合策略在 Pro-618 上達到 58.04% 的平均解決率，在 SWE-bench Multilingual 上達到 59.00%，相較於基礎模型分別提升了 5.39 與 2.78 個百分點。更重要的是，這些整體提升伴隨著各類別解決率的改善，而不只是少數類別的進步被平均後的假象。與 Pooled RL 和 Balanced RL 基線相比，本文方法在最小類別提升與專家增益恢復等指標上也展現出更穩健的類別級表現。

**Q9：論文進行了哪些消融或對照實驗來驗證方法設計？**

A：論文系統性地比較了 Pooled RL、Balanced RL、類別專家發展過程，以及最終 MOPD 整合策略在不同階段的表現。這些比較不僅包含整體解決率，也包含每個類別的解決率變化，以驗證類別感知訓練確實能緩解類別蹺蹺板效應。此外，透過追蹤專家增益恢復率，作者證明 MOPD 能夠有效地將多個類別專家的能力保留在單一模型中，而不會因整合而大幅損失各專家的專長。

**Q10：這個方法在實際軟體工程場景中可以如何應用？**

A：這個方法特別適合需要處理多樣化程式碼維護任務的企業級開發環境，例如同時需要修復後端服務錯誤、調整前端介面、更新基礎設施配置與修補安全漏洞的大型程式碼倉庫。透過類別感知訓練，開發團隊可以針對自家程式碼庫中最常見的任務類型訓練專門的智慧體能力，並確保單一部署模型不會偏廢某些關鍵類別。這對於需要穩定、可預測且可解釋的自動化程式碼維護流程的組織來說，具有很高的實用價值。

**Q11：在產品化過程中，這個框架有哪些需要特別考量的地方？**

A：首先，SWE Labeler 的類別定義需要根據目標程式碼庫的實際任務分佈進行調整，不同組織的任務類別可能與論文中的劃分有所不同，因此標註規則的可審計性與可擴展性非常重要。其次，RRE 循環涉及多輪 RL 與 SFT 的交替訓練，對運算資源與訓練管線的穩定性有較高要求，產品化時需要設計高效的評估與篩選機制。最後，MOPD 整合階段雖然能產生單一可部署模型，但仍需持續監控各類別在真實環境中的表現，以避免隨著資料分佈漂移而出現新的類別退化。

**Q12：這項研究對軟體工程智慧體領域可能帶來什麼影響？**

A：這項研究首次在單一軟體工程領域內系統性地引入類別感知專家訓練與整合，為未來的 SWE 智慧體研究提供了一個新的分析與訓練範式。它強調了僅看整體指標可能誤導研究方向，並示範了如何透過可審計的標註系統與迭代專家訓練來發現並修復類別層級的退化。長遠來看，這種方法可能推動更多針對特定工程情境的專業化智慧體發展，並促進單一通用模型與多專家能力之間的更有效整合。

**Q13：這個框架有哪些已知的限制？**

A：首先，類別劃分依賴於 SWE Labeler 的規則與標註品質，如果某些任務的類別邊界模糊或標註規則未能涵蓋新興任務類型，可能會影響專家訓練與路由的準確性。其次，RRE 循環需要反覆執行 RL 與 SFT，訓練成本顯著高於單一輪次的聯合訓練，對於資源有限的研究者或團隊來說可能較難直接複製。此外，雖然 MOPD 能整合多個專家，但當類別數量增加或專家之間的行為差異過大時，整合難度與衝突風險也可能隨之上升。

**Q14：在什麼樣的任務或情境下，這個方法可能比較容易失敗？**

A：當任務同時橫跨多個類別特徵、難以被單一類別標籤清楚歸類時，標籤路由可能會將其導向不適合的教師，導致學生模型學到次優策略。此外，如果某個類別的訓練資料極度稀少或獎勵訊號極為稀疏，即使進行類別特定 RL，專家也可能難以穩定學到有效行為。最後，對於需要大量領域特定知識或涉及複雜多檔案互動的長程任務，若基礎模型的先驗能力不足，RRE 與 MOPD 的增益可能會受到限制。

**Q15：未來有哪些可能的研究方向可以延伸這項工作？**

A：未來可以探索更動態、更細粒度的類別劃分方式，例如根據任務的程式語言、倉庫規模或修改複雜度進行多維度分群，而不僅限於目前的語義類別。另一個方向是發展更自動化的 RRE 調度機制，讓系統能根據即時的實例掌握度訊號自動決定何時進行 Refresh、Repair 或 Expand，減少人工設計的訓練排程。此外，也可以研究如何將這個框架與外部知識庫、檢索增強生成或多模態程式碼理解技術結合，進一步提升智慧體在更廣泛、更複雜軟體工程任務上的泛化能力。

## 實務應用指南

### 適用場景

1. **大型企業內部倉庫的維護型智慧體**  
   在單體或微服務程式碼庫中，每日湧入的 issue 橫跨服務與資料層錯誤修復、使用者介面調整、基礎設施與工具變更、效能或安全性修補等類別。本方法可先以 SWE Labeler 將任務分類，再針對每類訓練同源類別專家，最後透過標籤路由多教師同策略蒸餾整合為單一可部署策略，讓一個模型同時掌握多種維修風格。

2. **多語言開源專案自動化 issue 處理**  
   對於同時包含 Python、JavaScript、Go、Java 等多種語言的專案，傳統匯集式強化學習容易因語言與任務類別差異過大而產生類別蹺蹺板效應。採用類別感知迭代式專家訓練，可為不同語言或倉庫情境建立專家，再整合成單一模型，提升 SWE-bench Multilingual 這類多語言基準的整體與各類別解決率。

3. **CI/CD 管線中的自動化失敗修復**  
   當持續整合測試失敗時，系統可依失敗類別（例如建置修復、跨模組相容性變更、測試 flaky 修復）路由至對應的類別專家策略，自動生成 patch 並透過可執行裁決介面驗證，減少人工介入與修復週期。

4. **程式碼審查輔助與自動修復建議**  
   在 pull request 階段，依據變更類別啟動對應專家，針對定位、編輯、驗證等長程軌跡提供建議。由於訓練過程保留已驗證成功軌跡，審查者可追溯模型決策依據，提升可解釋性與信任度。

5. **新進工程師培訓與知識傳承**  
   將各類別專家的成功行為鞏固為可重播軌跡，搭配基於證據的多軸標註系統，能作為教學案例庫，幫助新手理解不同工程情境下的證據來源、工具互動模式與驗證方式。

### 實作前置條件

**資料條件**
- 可執行任務建構：需要具備測試裁決的倉庫級任務集合，例如 SWE-bench 格式的 issue–patch 配對，並能自動執行測試以判定成功或失敗。
- 多軸標註資料：需準備 issue 描述、程式碼變更、倉庫結構等資訊，供 SWE Labeler 進行基於證據的類別標註。
- 參考基準軌跡：用於計算 ReLU 門控獎勵外推與評估專家增益恢復的基礎模型 rollout 結果。

**運算條件**
- 長程智慧體強化學習基礎設施：需支援長軌跡 rollout、高頻工具呼叫與環境互動的 GPU/CPU 叢集。
- 可擴展的執行環境：每個任務需在隔離容器或沙箱中執行，避免未經審查的程式碼帶來安全風險。
- 儲存與追蹤系統：用於保存已驗證成功軌跡、策略檢查點、類別標籤與評估指標。

**技術能力**
- 熟悉監督式微調與強化學習流程，特別是 on-policy 方法與策略蒸餾。
- 具備智慧體設計經驗，包括工具使用、狀態管理與長程規劃。
- 能夠操作 SWE-bench 類型的評估框架，並具備程式碼倉庫分析與測試除錯能力。

### 實作步驟建議

1. **建構可執行任務池與多軸標註**  
   使用 SWE Labeler 對所有訓練與評估任務進行基於證據的分類，建立兩個層級語義軸與三個序數尺度軸，確保類別定義可稽核且可用於後續教師路由。

2. **建立聯合強化學習基線**  
   先訓練匯集式強化學習與平衡式強化學習基線，觀察整體指標與各類別解決率的變化，確認是否存在類別蹺蹺板效應，並作為後續專家訓練的比較基準。

3. **分軌訓練同源類別專家**  
   依標籤將任務分為多個類別軌道，從同一基礎模型出發，交替執行長程智慧體迷你強化學習與修復式監督微調，形成更新-修復-擴展循環。

4. **執行更新-修復-擴展迭代**  
   - **更新**：評估當前策略對各實例的掌握度，識別遺忘或退步的實例。  
   - **修復**：從前一次強化學習軌跡中抽取已驗證成功軌跡，進行 Repair SFT 以鞏固成功行為。  
   - **擴展**：依據策略自適應任務選擇，從更廣泛的任務池中挑選新的訓練前線，繼續進行類別特定強化學習。

5. **整合為單一可部署策略**  
   透過標籤路由多教師同策略蒸餾，將各類別專家合併為單一學生模型。蒸餾過程中使用 ReLU 門控獎勵外推，只保留各教師相對於參考基準的改進方向。

6. **全面評估與診斷**  
   同時檢視平均解決率、各類別解決率、最小類別提升與專家增益恢復等指標，確認整合後策略未遺忘專家模型的優勢。

7. **部署與持續監控**  
   在生產環境中依任務標籤路由至對應專家行為，持續收集執行結果並定期重新執行更新-修復-擴展循環，以對抗長期訓練帶來的實例掌握度飄移。

### 潛在風險與注意事項

| 風險 | 說明 | 因應措施 |
|---|---|---|
| **類別標籤不穩定** | 若 SWE Labeler 的決策規則模糊，會導致訓練池與教師路由錯誤。 | 採用基於證據的明確規則，定期人工抽樣稽核，並保留標註理由。 |
| **實例過擬合** | 專家可能記住訓練實例的特定解法，而非學到通用策略。 | 保留獨立驗證集，監控訓練實例與未見實例的表現差距，適時擴展新任務。 |
| **整合時災難性遺忘** | MOPD 合併多教師時，可能遺失部分類別的專家增益。 | 使用標籤路由與 ReLU 門控獎勵外推，並以專家增益恢復指標追蹤保留程度。 |
| **獎勵稀疏與高變異** | 倉庫級任務只有最終測試結果提供獎勵，中間步驟訊號弱。 | 結合已驗證成功軌跡的 Repair SFT，提供中間行為的密集監督訊號。 |
| **執行環境安全** | 自動執行未知程式碼可能導致資料外洩或系統損害。 | 所有 rollout 必須在隔離沙箱或一次性容器中進行，限制網路與檔案系統權限。 |
| **測試不穩定** | flaky 測試會造成獎勵估計錯誤，影響策略更新方向。 | 使用確定性測試環境，必要時重複執行多次測試以穩定裁決。 |
| **運算成本高昂** | 長程軌跡與多軌專家訓練需要大量運算資源。 | 從小規模類別與任務子集開始驗證，再逐步擴展；善用輕量化的 Agentic-miniRL。 |

### 與其他技術的整合建議

- **Issue 追蹤系統**：與 Jira、GitHub Issues、GitLab Issues 整合，自動擷取 issue 描述與標籤，作為 SWE Labeler 的輸入，並將生成的 patch 以 pull request 形式回傳。
- **CI/CD 管線**：嵌入 GitHub Actions、GitLab CI 或 Jenkins，在測試失敗時觸發類別感知修復流程，並利用可執行裁決介面自動驗證 patch。
- **程式碼審查平台**：與 GitHub PR、GitLab MR、Bitbucket 整合，於審查階段提供依類別路由的修復建議與成功軌跡說明。
- **檢索增強生成系統**：結合程式碼索引、向量資料庫與檢索模組，強化專家在定位階段的證據收集能力，但保留專家策略作為最終決策核心。
- **現有監督式微調與強化學習管線**：可將本方法的 RRE 循環與 MOPD 作為後訓練階段，疊加在已有的基礎模型或通用程式碼模型之上。
- **多智慧體協作框架**：將不同類別專家視為可協作的專長智慧體，由上游路由器依任務標籤分派，並在複合任務中進行多輪協商與驗證。

### 給不同背景讀者的閱讀建議

**初學者**：建議先聚焦「類別蹺蹺板效應」這個核心動機，以及「更新-修復-擴展」循環的直覺：模型先學、再修復忘記的部分、再挑戰新任務。理解這個循環後，再回頭看 SWE Labeler 如何將複雜的軟體工程任務分成可管理的類別，會更容易掌握整篇論文的設計精神。

**AI 工程師**：請重點閱讀 Agentic-miniRL 的實作細節、RRE 的資料流與檢查點管理、Repair SFT 如何從已驗證成功軌跡中篩選訓練資料，以及 MOPD 的標籤路由與 ReLU 門控獎勵外推公式。這些是將論文方法落地為產品時最需要複現與調校的部分。

**研究人員**：建議深入分析類別感知訓練的評估指標設計，包括最小類別提升與專家增益恢復，並思考 SWE Labeler 的多軸分類框架是否可遷移到其他長程決策任務。此外，獎勵外推與多教師同策略蒸餾的理論性質也值得進一步探討。

**產品經理**：請優先關注適用場景、潛在風險與各類別指標的商業意義。理解「整體解決率穩定但某些類別退步」的現象，有助於設定合理的產品目標與監控儀表板；同時要評估沙箱執行、人工稽核與持續迭代所需的營運成本與風險控管機制。
