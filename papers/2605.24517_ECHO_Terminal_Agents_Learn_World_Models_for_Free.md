## ⚡ TL;DR

標準 GRPO 捨棄終端機回饋，使多數失敗推展缺乏策略梯度訊號。
ECHO 以輔助損失預測環境回應，將終端輸出轉為密集監督訊號。
Qwen3-8B 與 14B 的 pass@1 近乎翻倍，且無需專家示範即可自我改進。

## 摘要翻譯

CLI 智慧體（CLI agents）是語言模型（language models）最接近具身環境（embodied setting）的形式：模型發出指令，終端機執行這些指令，而回傳的串流——標準輸出（stdout）、標準錯誤（stderr）、檔案（files）、日誌（logs）與追蹤紀錄（traces）——則記錄了後果。我們主張這個串流是一種監督訊號（supervision signal），但標準的智慧體強化學習（agent RL）卻將其捨棄：GRPO 式訓練以稀疏結果層級獎勵（sparse outcome-level rewards）更新動作詞元（action tokens），同時忽略了推展（rollout）中已經存在的環境回應（environment responses）。儘管失敗推展（failed rollouts）包含關於環境如何回應的豐富證據，卻僅提供極少的策略梯度訊號（policy-gradient signal）。我們提出 ECHO（Environment Cross-entropy Hybrid Objective），這是一個混合目標函數（hybrid objective），結合了作用於動作詞元（action tokens）上的標準策略梯度（policy-gradient）損失，以及一個輔助損失（auxiliary loss），用於訓練策略（policy）預測其自身動作所產生的環境觀察詞元（environment observation tokens）。ECHO 沿用與 GRPO 相同的前向傳播（forward pass），無需額外的推展（rollouts），並將終端機回饋轉化為適用於所有推展（rollouts）的密集監督（dense supervision）。ECHO 在 TerminalBench-2.0 上將 GRPO 的 pass@1 提升一倍：Qwen3-8B 從 2.70% 提升至 5.17%，Qwen3-14B 則從 5.17% 提升至 10.79%。ECHO 所產生的策略（policies）也能更好地預測終端機動態（terminal dynamics），即使是在它們未生成的軌跡（trajectories）上：在保留推展（held-out rollouts）中，它大幅降低了環境詞元交叉熵（environment-token cross-entropy），而單獨使用 GRPO 幾乎無法改變此數值。從基礎 Qwen3-8B 出發，ECHO 在保留終端機任務（held-out terminal tasks）上達到與先進行專家監督式微調（expert-SFT）再執行 GRPO 相當的效能，且無需專家示範（expert demonstrations）；並在 TerminalBench-2.0 上恢復了約一半由專家監督式微調（expert-SFT）初始化所帶來的效益。在某些設定下，單獨使用環境預測損失就能實現無驗證器自我改進（verifier-free self-improvement），使策略（policies）僅透過環境互動（environment interactions）即可在未見過的分佈外任務（OOD tasks）上獲得改善。綜合而言，這些結果顯示環境觀察（environment observations）不僅僅是未來動作的上下文，而是每個推展（rollout）中都已存在的密集且同策略（dense, on-policy）的監督訊號（supervision signal）。

### 核心貢獻（3～5點）
- 提出 ECHO（Environment Cross-entropy Hybrid Objective）混合目標函數：在標準策略梯度損失之外，加入預測環境觀察詞元的輔助損失，將終端機回饋轉化為適用於所有推展的密集監督，且無需額外推展。
- 顯著提升基準測試效能：在 TerminalBench-2.0 上將 GRPO 的 pass@1 提升一倍，Qwen3-8B 從 2.70% 提升至 5.17%，Qwen3-14B 從 5.17% 提升至 10.79%。
- 學習可遷移的終端機世界模型：ECHO 訓練出的策略能更好地預測終端機動態，即使在保留推展上也能顯著降低環境詞元交叉熵，展現出對環境回應的泛化能力。
- 擺脫對專家示範的依賴：從基礎 Qwen3-8B 出發，無需專家示範即可在保留終端機任務上達到「先專家監督式微調再 GRPO」的同等效能，並在 TerminalBench-2.0 上恢復約一半的專家初始化效益。
- 實現無驗證器的自我改進：僅靠環境預測損失與環境互動，策略就能在未見過的分佈外（OOD）任務上自我改善，顯示環境觀察本身就是有效的同策略監督訊號。

### 適合對象
從事大型語言模型代理系統、強化學習與工具使用研究的學者與工程師；特別是關注多輪智慧體強化學習、世界模型學習，以及希望在不依賴專家示範或外部驗證器的前提下，提升 CLI 智慧體於終端機環境中任務表現的研究者與實務開發者。

## 深度分析

#### 方法論解析

CLI 智慧體（CLI agents）是語言模型（language models）最接近具身環境（embodied setting）的應用場景。在標準的智慧體強化學習（agent RL）框架下，特別是 GRPO（Group Relative Policy Optimization），訓練過程僅針對 action tokens（動作詞元）計算 policy-gradient（策略梯度），並依賴 sparse outcome-level rewards（稀疏結果層級獎勵）。然而，environment responses（環境回應）——包括 stdout（標準輸出）、stderr（標準錯誤）、exit codes（退出碼）、files（檔案）、logs（日誌）與 traces（追蹤紀錄）——雖然存在於每一次 rollout（推展）中，卻未被視為 supervision signal（監督訊號）。在作者設定的 Qwen3-8B 實驗中，僅有不到 15% 的同策略（on-policy）rollout 能成功解決任務，這意味著超過 85% 的失敗推展（failed rollouts）幾乎不產生 policy-gradient signal（策略梯度訊號），但其實這些軌跡（trajectory）包含了大量關於終端機（terminal）如何回應的豐富證據。

ECHO（Environment Cross-entropy Hybrid Objective）的核心貢獻在於將這些 environment observations（環境觀察）轉化為 dense supervision（密集監督）。其 hybrid objective（混合目標函數）可表述為：

L_ECHO(θ) = L_GRPO(θ; A) + λ L_Env(θ; O′)

其中 A 為 assistant-action positions（助理動作位置），O′ 為 terminal-output positions（終端機輸出位置）的子集。L_Env 是對 environment observation tokens（環境觀察詞元）的 cross-entropy（交叉熵），並以總觀察長度 |O| 進行正規化。關鍵在於，此 hybrid objective（混合目標函數）與 GRPO 共享單一 forward pass（前向傳播）：計算 action tokens（動作詞元）的 logits 時，同時透過不同遮罩在 environment observation tokens（環境觀察詞元）位置收集 logits。因此 ECHO 不需要額外的 rollout（推展）、teacher model（教師模型）或第二次 forward pass（前向傳播），僅需一次 masked log-probability sum 即可完成。

由於預測目標來自當前 policy（策略）自身的 rollout（推展），ECHO 是 on-policy（同策略）的。隨著 agent（智慧體）能力提升並探索新的 terminal states，environment（環境）產生的新回應自動形成 self-evolving curriculum（自我演進課程）。這迫使 policy（策略）追蹤其命令的 latent consequences（潛在後果）——例如哪些 files（檔案）被建立、哪些假設失敗、哪些測試中斷、container state（容器狀態）如何改變——從而在文本層面學習一個 world model（世界模型）。即使 rollout 最終失敗，預測 terminal output（終端機輸出）的過程仍能提供關於「世界如何回應」的密集訊號，這正是標準 GRPO 所浪費的最豐富資訊來源。

#### 實驗數據解讀

在公開基準 TerminalBench-2.0 上，ECHO 幾乎將 pass@1 翻倍：Qwen3-8B 從 2.70% 提升至 5.17%，Qwen3-14B 從 5.17% 提升至 10.79%。這顯示即使不增加模型參數或 rollout（推展）數量，僅靠挖掘既有推展中的 environment-token（環境詞元）資訊，就能顯著提升任務解決率。對於一個僅以 auxiliary loss（輔助損失）形式存在的修改而言，如此大幅度的性能躍升極具說服力。

更具理論意義的是 held-out evaluations（保留評估）。在來自更強大的 Qwen3-32B policy（策略）所產生的 held-out rollouts（保留推展）上，ECHO 顯著降低了 environment-token cross-entropy（環境詞元交叉熵），而單純 GRPO 幾乎無法改變此數值。這項結果至關重要：它不僅證明 ECHO 提升了任務成功率，更證明 policy（策略）真正學會了 terminal dynamics（終端機動態）——即具備預測未見過軌跡中 environment responses（環境回應）的能力，而非僅僅過擬合（overfit）到特定的動作序列。

在減少對專家示範依賴方面，從 base Qwen3-8B 出發，ECHO 在內部評估上達到了與 OpenThinker-Agent-v1-SFT（經過約 15k 筆 expert-SFT（專家監督式微調）初始化）再接續 GRPO 相當的表現，且完全未使用任何 expert demonstrations（專家示範）。在 TerminalBench-2.0 上，ECHO 也彌補了約一半的 expert-SFT（專家監督式微調）初始化優勢。這意味著 environment-prediction loss（環境預測損失）可在某種程度上替代昂貴的人工示範，為無法取得高品質 SFT 資料的領域提供了一條可行的訓練路徑。

最引人注目的是 verifier-free self-improvement（無驗證器自我改進）的發現：在某些設定下，即使沒有 verifier（驗證器）提供二元獎勵，policy（策略）僅透過 environment interactions（環境互動）並預測其回應，就能在 unseen OOD tasks（分佈外任務）上自我提升。這暗示 environment observations（環境觀察）本身就是一種自我監督訊號，足以驅動策略探索，而不必依賴外部獎勵機制。

#### 與現有研究的比較

相較於標準的 multi-turn agent RL（多輪智慧體強化學習）——如 GRPO、PPO 及其變體——ECHO 突破了僅將 environment responses（環境回應）視為上下文的慣例，首次系統性地將 terminal output（終端機輸出）作為 dense supervision（密集監督）直接納入 policy（策略）更新。過去雖有研究使用 auxiliary loss（輔助損失），但多半需要額外的網路、凍結的離線資料或 teacher model（教師模型）；ECHO 的創新在於完全利用現有 rollout（推展）的相同 forward pass（前向傳播），計算開銷極低，卻能將失敗推展（failed rollouts）轉化為有效訓練訊號。

相較於傳統的 world model（世界模型）研究，ECHO 學習的是「文本投影」層級的動態：它預測的是 container state（容器狀態）經過 terminal 渲染後的 lossy textual projection（損失性文本投影），包括 stdout（標準輸出）、stderr（標準錯誤）、file contents（檔案內容）等，而非完整的 filesystem（檔案系統）或 process tree（程序樹）。這使其在實作上極為輕量，無需設計複雜的狀態空間或轉移函數，但也限制了其對 hidden task state（隱藏任務狀態）的建模能力——畢竟並非所有容器內的變化都會反映在文本輸出中。

相較於 expert-SFT（專家監督式微調），ECHO 提供了一條無需 expert demonstrations（專家示範）的訓練路徑，顯著降低了資料收集成本。然而，其限制也同樣明顯：目前僅在 Docker task environments（Docker 任務環境）與 Qwen3 系列模型上驗證，對於 GUI agents 或 web agents 等非文字觀察環境的適用性尚不清楚。此外，O′ 的選取策略、權重 λ 的調校，以及觀察長度正規化的細節，在提供的文本中尚未完全揭露，這可能影響跨任務的泛化與超參數移植。

#### 可重現性評估

從可重現性（reproducibility）角度評估，本研究具備部分優勢：基礎模型 Qwen3-8B 與 Qwen3-14B 為開放權重（open-weight），評估基準 TerminalBench-2.0 為公開資料集，且任務環境基於 Docker task environments（Docker 任務環境），理論上具備標準化優勢。然而，根據提供的文本，作者並未明確說明是否釋出訓練程式碼、超參數（如 λ 與 O′ 的選取準則）、或微調後的 model weights（模型權重）。Docker 任務環境的確切建構方式、transcript（對話紀錄）的解析邏輯，以及內部評估的完整任務列表，亦未在節錄中詳細交代。因此，雖然核心概念——在 GRPO 的 action tokens（動作詞元）遮罩外增加 environment-token cross-entropy（環境詞元交叉熵）——實作上相對簡潔，但完整的實驗重現仍仰賴作者後續釋出原始碼與環境設定，否則社群難以精確復現其內部評估與 OOD tasks（分佈外任務）上的自我改進結果。

#### 未來研究方向

未來研究方向可從五個面向延伸。第一，擴展至非 terminal 的 embodied settings（具身環境）：將 ECHO 的核心思想應用於 GUI agents（預測畫面變化）或 web agents（預測 HTML/網頁回應），驗證 environment observation prediction（環境觀察預測）是否仍能提供 dense supervision（密集監督）。第二，最佳化觀察目標選擇：目前 O′ 為 O 的子集，未來可研究基於資訊量的動態選擇——例如僅預測 stderr（標準錯誤）或檔案差異——以提升學習效率並降低雜訊。第三，結合潛在世界模型：在文本預測之外，引入 latent state representations（潛在狀態表示），同時預測可觀察的 terminal output（終端機輸出）與隱藏的 container state（容器狀態），彌補當前文本投影的損失性。第四，探索純粹的 verifier-free self-improvement（無驗證器自我改進）機制：將 ECHO 視為內在動機（intrinsic motivation），設計僅依賴 environment interactions（環境互動）的 curriculum learning（課程學習）演算法，用於 OOD tasks（分佈外任務）的持續適應。第五，理論分析：形式化地證明 environment-token prediction（環境詞元預測）如何降低策略梯度估計的變異數，或改善長軌跡的信用分配（credit assignment），為 hybrid objective（混合目標函數）提供更堅實的優化理論基礎。

## 論文問答

**Q1：ECHO 旨在解決終端機智慧體訓練中的什麼核心問題？**
A：ECHO 主要解決標準智慧體強化學習中監督訊號過於稀疏且延遲的核心問題。在傳統的 GRPO 訓練框架下，模型僅能從最終的二元獎勵（任務成功或失敗）獲得策略梯度訊號，導致絕大多數失敗推展幾乎無法提供有效的學習訊號。然而，這些失敗的軌跡實際上包含了終端機對每個動作的詳細回應，例如錯誤訊息、檔案內容與日誌輸出，ECHO 正是要將這些被忽略的環境回應轉化為密集的監督訊號，使每一次互動都能貢獻於策略學習。

**Q2：為什麼現有的 GRPO 方法無法有效利用失敗推展中的豐富資訊？**
A：現有的 GRPO 方法僅在助理動作詞元上計算策略梯度損失，並完全依賴稀疏的結果層級二元獎勵來更新策略。當推展失敗時，整條軌跡只會收到軌跡層級的負面訊號，而終端機輸出的每一個詞元雖然都進入了模型的前向傳播作為上下文，卻沒有任何一個詞元進入損失函數。這種設計使得模型無法從環境的具體回饋中學習指令的潛在後果，從而浪費了絕大多數互動中蘊含的豐富資訊。

**Q3：為什麼終端機環境觀察被視為有價值的監督訊號？**
A：終端機輸出是容器狀態的損失性文字投影，包含了標準輸出、標準錯誤、退出碼、檔案內容與測試失敗等資訊，能夠反映動作執行後的真實環境狀態。預測這些觀察詞元要求策略追蹤其指令的潛在後果，例如哪些檔案被創建、哪些假設失敗或哪些測試中斷，這實際上迫使模型學習終端機的動態規律。因此，能夠良好預測終端輸出的策略，在某種程度上真正理解了終端機的運作方式，而不僅僅是機械地生成指令。

**Q4：ECHO 混合目標函數的核心機制是什麼，它與標準 GRPO 有何不同？**
A：ECHO 的核心機制是在標準 GRPO 的策略梯度損失之外，增加了一個輔助的環境預測損失，對環境觀察詞元計算長度正規化的交叉熵。不同於 GRPO 僅將動作詞元作為訓練目標，ECHO 同時要求模型預測自身動作所引發的終端機輸出詞元，將環境回應從單純的上下文轉變為直接的監督目標。這種混合目標函數讓模型在同一個前向傳播中同時學習「如何行動」以及「環境將如何回應」，從而將環境串流轉化為密集的監督訊號。

**Q5：ECHO 如何在不需要額外前向傳播或推展的情況下加入環境詞元預測？**
A：ECHO 巧妙地重用了 GRPO 原本就會計算的前向傳播 logits，僅透過不同的詞元位置遮罩來區分動作詞元和環境觀察詞元。具體而言，GRPO 在助理動作位置計算策略梯度，而 ECHO 則額外從同一組 logits 中收集終端機輸出位置的機率分佈，用於計算環境預測的交叉熵損失。這種設計不需要第二個前向傳播、教師模型或額外的推展，唯一增加的工作是遮罩後的對數機率加總，因此計算開銷極小。

**Q6：為什麼論文主張預測環境詞元有助於策略發展出對終端機動態的更好理解？**
A：論文借用了語言建模中的直覺：良好的預測意味著對潛在現實的理解，預測下一個詞元的能力反映了對生成該詞元背後機制的掌握。預測終端機輸出要求策略追蹤隱藏的容器狀態變化，包括檔案系統的修改、程序執行的結果以及錯誤的傳播路徑，這實際上是在學習一個關於終端機的世界模型。當策略能夠準確預期環境回應時，它就能發展出更好的先驗知識，以判斷哪些未來指令更可能暴露有用狀態、修復錯誤或推進任務。

**Q7：ECHO 在 TerminalBench-2.0 上的主要量化結果是什麼？**
A：在 TerminalBench-2.0 基準測試上，ECHO 幾乎將 GRPO 的 pass@1 表現翻倍：Qwen3-8B 從 2.70% 提升至 5.17%，而 Qwen3-14B 則從 5.17% 躍升至 10.79%。這些結果顯示，無論是在較小還是較大的模型規模上，加入環境預測損失都能帶來顯著且一致的效能增益。此外，這些改進是在沒有額外專家示範或增加推展次數的情況下達成的，證明了環境觀察本身即為強大的學習訊號。

**Q8：ECHO 在保留軌跡上的表現揭示了模型學到的世界模型具備什麼特性？**
A：在來自更強大的 Qwen3-32B 策略所生成的保留軌跡上，ECHO 能夠顯著降低環境詞元的交叉熵，而單獨使用 GRPO 則幾乎無法改善這項指標。這表示 ECHO 訓練出的策略不僅在自身生成的軌跡上表現更好，也發展出了對終端機一般性動態的預測能力，即使面對它未曾產生的指令序列亦然。這項發現強烈暗示模型內部確實形成了一個關於終端機行為的世界模型，而不僅僅是過擬合到自身的動作模式。

**Q9：與專家 SFT 的比較顯示了 ECHO 在資料效率方面的什麼優勢？**
A：從基礎的 Qwen3-8B 出發，ECHO 在內部評估上能夠匹配先經過約 15,000 筆專家示範進行監督式微調、再執行 GRPO 的 OpenThinker-Agent-v1-SFT 模型，且完全不需要任何專家示範。在 TerminalBench-2.0 上，ECHO 也彌補了大約一半的專家 SFT 初始化所帶來的效能差距。這顯示透過直接從環境互動中學習密集的回饋訊號，ECHO 大幅降低了對昂貴且難以取得的人工專家軌跡的依賴，展現出優異的資料效率與自主學習潛力。

**Q10：ECHO 如何降低實際 CLI 智慧體開發中對專家示範的依賴？**
A：在實務上，收集高品質的專家示範往往成本高昂且難以規模化，而 ECHO 證明僅透過與終端機環境互動並預測其回應，基礎模型就能達到與專家 SFT 初始化相當的效能。這意味著開發者可以在缺乏大量人工標註軌跡的情況下，直接從基礎模型開始訓練智慧體，顯著降低進入門檻與資料準備成本。對於需要快速適應新領域或內部專有系統的企業應用而言，這種無需專家示範即可自我提升的能力極具商業價值。

**Q11：無驗證器自我改進對 ECHO 在生產環境部署意味著什麼？**
A：無驗證器自我改進意味著在某些設定下，策略僅透過與環境互動並學習預測環境回應，就能在未曾見過的分布外任務上持續進步，而不需要外部獎勵模型或任務驗證器提供成功與失敗的標籤。這對生產環境至關重要，因為許多真實世界的 CLI 任務難以設計自動化驗證器，且人工驗證成本極高。ECHO 的這項特性使得智慧體能夠在部署後持續從實際互動中學習與適應，為建構自主演進的終端機智慧體系統提供了可行的技術路徑。

**Q12：ECHO 的方法可能如何影響具身人工智慧與互動式語言智慧體的更廣泛領域？**
A：ECHO 提出了一個普遍適用的原則：環境觀察不僅是決策的上下文，更是密集的同策略監督訊號，這個洞見可以擴展到任何具有豐富環境回饋的互動式領域，例如網頁導航、機器人控制或資料庫操作。透過將環境動態預測納入策略學習的核心目標，研究者可以建構出更具理解力與適應性的具身智慧體，而非僅追求稀疏獎勵的最大化。這種範式轉移可能促使未來的智慧體訓練框架重新審視環境回應的角色，將世界模型的學習與策略優化更緊密地結合在一起。

**Q13：使用終端機輸出作為監督訊號存在哪些固有局限性？**
A：終端機輸出本質上是容器狀態的損失性文字投影，它無法完整呈現底層的檔案系統全貌、程序樹結構或隱藏的任務狀態，因此模型只能學到部分可觀察的動態規律。此外，若終端機輸出過於冗長、雜訊過多或包含敏感資訊，可能會增加學習難度或帶來安全與隱私的顧慮。這種監督訊號的品質也高度依賴環境本身的設計，如果環境回饋含糊不清或誤導性強，模型可能會學到錯誤的因果關係。

**Q14：在哪些情境下，ECHO 的環境預測損失可能無法提供有用的學習訊號？**
A：當環境回應幾乎是隨機的、與動作無關，或者極度單調重複時，預測這些觀察詞元將無法幫助策略理解動作與後果之間的因果關係。同樣地，如果任務的成功與否主要取決於驗證器檢查的隱藏狀態，而終端機輸出無法反映這些關鍵狀態變化，那麼環境預測損失可能會引導模型學習與任務目標無關的表面規律。此外，在分佈外任務中，若環境動態與訓練時差異過大，單純的環境預測可能不足以支撐有效的策略改進。

**Q15：論文暗示了 ECHO 混合目標函數的哪些未來擴展方向？**
A：論文暗示未來可以將 ECHO 的原則擴展到更多類型的互動環境，超越終端機設定，探索網頁、API 或實體機器人等領域中環境觀察的預測價值。另一個方向是將環境預測損失與更複雜的世界模型架構結合，例如顯式的狀態表示學習或因果推理模組，以彌補終端機輸出僅為部分觀察的不足。此外，研究者可以進一步探索如何動態調整輔助損失的權重，或將 ECHO 與離線資料結合，以在更廣泛的應用場景中實現穩定且高效的智慧體自我改進。

## 實務應用指南

### 適用場景

1. **DevOps 自動化與 CI/CD 故障排除**：CLI 智慧體在 Docker 任務環境中執行編譯、測試、讀取日誌與標準錯誤，自動修復建置失敗，並從失敗推展中學習終端機動態。
2. **雲端基礎設施維運**：透過終端機指令查詢服務狀態、調整設定檔、分析追蹤紀錄，處理部署與維運任務，利用 ECHO 將環境回應轉為密集監督訊號。
3. **資料工程與 ETL 管線除錯**：智慧體執行資料處理腳本，檢查輸出檔案內容與退出碼，迭代修正轉換邏輯，即使無專家示範也能透過環境互動自我改進。
4. **資安稽核與滲透測試輔助**：在隔離容器中執行掃描指令，根據標準輸出與檔案系統回饋調整後續動作，學習潛在後果與容器狀態變化。
5. **自動化系統管理**：分析系統日誌、重啟服務、修改設定，透過多輪智慧體強化學習適應不同伺服器狀態，並預測終端機輸出以驗證自身理解。

### 實作前置條件

- **資料**：具備明確終端機輸出位置的推展資料（包含助理動作位置與環境觀察詞元）、任務驗證器（verifier）提供的二元獎勵，以及 Docker 容器狀態的快照能力。
- **運算**：至少支援 8B 參數模型全參數微調或 LoRA 的 GPU 叢集（如 A100/H100）、可平行執行多個 Docker 任務環境的運算節點。
- **技能**：熟悉 GRPO 演算法、PyTorch 分散式訓練、容器化技術，以及能夠處理長序列對話紀錄的資料管線設計能力。

### 實作步驟建議

1. **建構可復現的 Docker 任務環境**：將目標任務（如程式修復、設定調整）封裝為標準化容器，確保每次推展的標準輸出、標準錯誤與檔案內容一致。
2. **選定基礎語言模型**：建議以 Qwen3-8B 或 Qwen3-14B 等具備工具使用能力的模型為起點，降低冷啟動難度。
3. **實作多輪推展迴圈**：建立「產生動作詞元 → 解析為 Shell 指令 → 於容器執行 → 回傳環境觀察」的互動管線，完整記錄對話紀錄。
4. **建立 GRPO 基線**：先以標準 GRPO 訓練，僅在助理動作位置計算策略梯度，確認稀疏結果層級獎勵的收斂基準。
5. **嵌入 ECHO 混合目標函數**：在同一個前向傳播中，額外蒐集終端機輸出位置的 logits，加入環境詞元交叉熵作為輔助損失，設定權重 λ（建議從 0.1–1.0 區間搜尋）。
6. **設計觀察詞元遮罩策略**：決定 O′ 子集（例如排除過長日誌、僅保留前 N 個環境觀察詞元），並以總觀察長度 |O| 進行正規化。
7. **同步評估終端機動態**：在保留終端機任務上，除了 pass@1 任務成功率，同時追蹤環境詞元交叉熵，確認策略確實學到終端機回應模式。
8. **產品化部署**：將訓練後的策略匯出為推理服務，加上指令沙箱、輸出過濾與人類確認閘門，導入實際維運流程。

### 潛在風險與注意事項

- **指令執行安全**：CLI 智慧體具備具身環境的操作能力，必須在嚴格隔離的 Docker 任務環境中執行，避免存取生產環境的檔案系統與程序樹。
- **觀察資料雜訊**：終端機輸出常包含大量無關日誌，若未妥善篩選 O′ 子集，輔助損失可能因雜訊而稀釋訓練訊號，建議結合啟發式規則或學習型遮罩。
- **獎勵錯位**：環境預測損失與任務成功並非完全正相關，過高的 λ 可能使策略過度擬合預測終端機動態，卻忽略解決任務本身，需透過保留集監控 pass@1 變化。
- **記憶體與長文本壓力**：多輪推展的對話紀錄可能極長，即使 ECHO 無需額外前向傳播，大量環境觀察詞元仍會佔用 GPU 記憶體，建議實作梯度檢查點與序列並行化。
- **分佈外退化**：在分佈外任務上，無驗證器自我改進的效果可能不穩定，產品上線前應針對目標任務分佈進行充分驗證。

### 與其他技術的整合建議

- **與專家監督式微調銜接**：若已有專家示範資料，可先執行專家-SFT 初始化再銜接 ECHO；若無專家資料，ECHO 可直接從基礎模型啟動，降低資料收集成本。
- **搭配現有驗證器架構**：ECHO 並未移除對二元驗證器的需求，而是補強其稀疏性，可無縫整合現有的測試框架、靜態分析工具或人工設計的獎勵函數。
- **結合檢索增強生成（RAG）**：在執行動作前，讓智慧體檢索指令手冊或歷史修復紀錄，將檢索結果作為對話紀錄的一部分，提升環境預測的準確度。
- **容器編排平台整合**：透過 Kubernetes 動態調度 Docker 任務環境，支援大規模平行推展與自動化資源回收。
- **可觀測性工具串接**：將終端機輸出即時導入結構化日誌系統，便於離線分析環境觀察詞元的預測誤差，持續優化訓練資料品質。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦「預測即理解」的核心直覺——當智慧體能準確預測自己下達指令後的終端機輸出，就代表它正在建立對環境因果關係的內在模型。建議從論文的 Introduction 與 Method（§3）開始，暫時略過複雜的 GRPO 數學推導，把 ECHO 想像成「讓失敗推展也能教會智慧體認識世界」的訓練技巧。
- **AI 工程師**：重點閱讀 Method（§3）與實驗設定，理解如何在現有 GRPO 程式碼中僅透過「增加一組遮罩（assistant-action positions 與 terminal-output positions）」與「長度正規化的交叉熵損失」來實作 ECHO，無需額外前向傳播或教師模型。特別注意觀察詞元子集 O′ 的選取與正規化方式，這是工程落地時影響收斂的關鍵細節。
- **研究人員**：建議深入分析 §5.2 與 §5.5 的結果，思考 ECHO 在表徵塑造（representation shaping）層面的理論意涵——環境觀察詞元作為同策略密集監督訊號，如何與稀疏策略梯度互補。可進一步探討輔助損失權重 λ 的動態排程、環境預測與世界模型（world model）的理論連結，以及在不同具身環境（非終端機領域）的泛化性。
- **產品經理**：請優先關注 §5.1 與 §5.3 的商業指標：ECHO 在 TerminalBench-2.0 上幾乎翻倍 pass@1，且能從基礎模型直接達到「專家-SFT + GRPO」的效果，省去約 15K 筆專家示範的收集成本。這意味著在終端機自動化產品中，可縮短冷啟動週期、降低人工標註預算，同時透過環境互動實現持續自我改進。
