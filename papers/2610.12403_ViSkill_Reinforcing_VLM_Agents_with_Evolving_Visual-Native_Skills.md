## ⚡ TL;DR

現有技能增強代理以文字表示空間經驗，造成幾何資訊流失，且技能構建與策略優化脫鉤。
本文提出ViSkill框架，將成功軌跡編碼為視覺技能卡，透過技能檢索與獎勵塑形形成閉環回饋。
在Sokoban等環境中達0.89成功率，冷啟動後提升至0.91，收斂速度超越標準PPO。

## 摘要翻譯

技能增強型代理（Skill-Augmented Agent）透過將成功軌跡（Trajectory）蒸餾（Distillation）為可重用策略（Reusable Strategy）來提升樣本效率（Sample Efficiency）。然而，現有方法大多仍以文字為中心，將空間佈局（Spatial Layout）與動作-狀態對應（Action-State Correspondence）線性化（Linearization）為語言，導致關鍵的幾何結構（Geometric Structure）流失。近期研究已開始納入視覺證據（Visual Evidence），但將技能的構建與更新與策略優化（Policy Optimization）分開處理，使得兩者之間的相互改進仍未被充分探索。我們提出 ViSkill，一個視覺原生技能（Visual-Native Skill）學習框架，將成功互動編碼為視覺語言模型代理（VLM Agent）可直接存取的複合視覺技能卡（Visual Skill Card）。檢索到的技能同時引導推理（Inference）與獎勵塑形（Reward Shaping），而成功軌跡則被蒸餾回技能庫（Skill Library）中，形成一個閉環回饋迴路（Closed Feedback Loop），使技能累積（Skill Accumulation）與策略改進（Policy Improvement）相互強化。可選的冷啟動機制（Cold-Start Mechanism）進一步加速早期學習。在推箱子（Sokoban）、冰湖（FrozenLake）與 PrimitiveSkill 上進行評估，ViSkill 達到 0.89 的整體成功率（Success Rate），經冷啟動初始化（Cold-Start Initialization）後更提升至 0.91，不僅超越所有評比的專有基準模型（Proprietary Baseline）與開源基準模型（Open-Source Baseline），收斂（Convergence）速度亦快於標準近端策略優化（PPO）。程式碼公開於 https://github.com/ZJU-REAL/ViSkill。

### 核心貢獻（3～5點）
- **提出視覺原生技能表示（Visual-Native Skill Representation）**：突破既有以文字為中心（Text-Centric Skill Representation）的技能建構方式，透過視覺技能卡忠實保留空間佈局與幾何資訊（Geometric Information），避免線性化所造成的有損空間抽象（Lossy Spatial Abstraction）。
- **建立閉環回饋迴路（Closed Feedback Loop）**：將技能檢索（Skill Retrieval）、技能利用（Skill Utilization）與技能構建（Skill Construction）整合於同一框架，使技能累積與策略改進形成雙向交互作用（Bidirectional Interplay），實現技能與策略的共同演化。
- **設計可選冷啟動機制（Cold-Start Mechanism）**：在早期訓練階段注入先驗策略以緩解冷啟動問題，使整體成功率由 0.89 提升至 0.91，並加速收斂。
- **跨環境實驗驗證**：於推箱子（Sokoban）、冰湖（FrozenLake）與 PrimitiveSkill 三項基準環境中全面評估，結果顯示 ViSkill 在樣本效率與最終效能上均超越專有與開源基準模型，且收斂速度快於標準 PPO。

### 適合對象
從事視覺語言模型（VLM）、強化學習（RL）、智慧代理（Agent）決策與規劃、視覺推理及程式性知識（Procedural Knowledge）獲取等領域的研究者與工程師；尤其適合關注樣本效率、多步驟操控（Multi-Step Manipulation）、物體操控（Object Manipulation）與障礙物導航（Obstacle Navigation）等空間推理任務，並希望探索如何將視覺證據融入策略學習（Policy Learning）與技能獲取（Visual Skill Acquisition）的學術與實務工作者。

## 深度分析

#### 方法論解析

ViSkill 的核心設計理念在於解決視覺語言模型代理（VLM Agent）在強化學習（Reinforcement Learning, RL）訓練中面臨的兩個根本性缺陷：**表示差距（Representation Gap）** 與 **學習差距（Learning Gap）**。前者源於現有技能增強型代理（Skill-Augmented Agent）多採用以文字為中心的技能表示（Text-Centric Skill Representation），將空間佈局（Spatial Layout）、相對位置（Relative Position）與動作-狀態對應（Action-State Correspondence）線性化（Linearization）為自然語言描述，造成有損空間抽象（Lossy Spatial Abstraction）；後者則體現在技能構建（Skill Construction）與策略優化（Policy Optimization）通常被解耦處理，視覺技能獲取（Visual Skill Acquisition）與策略學習（Policy Learning）之間的雙向交互作用（Bidirectional Interplay）未被充分探索。

**視覺原生技能表示（Visual-Native Skill Representation）**

ViSkill 將每一條成功軌跡（Trajectory）編碼為一張「視覺技能卡（Visual Skill Card）」，這是一張將標註軌跡（Annotated Trajectory）與渲染後的策略（Rendered Strategy）合成為單一影像的複合技能（Composite Skill）表示。具體而言，每張技能卡 $C_k$ 包含三類資訊：

1. **幾何特徵 $g_k$**：從軌跡關鍵幀中提取的空間配置編碼，用於支援幾何感知的技能檢索（Skill Retrieval）；
2. **效用值 $u_k$**：衡量該技能在歷史中被成功調用的頻率與品質；
3. **調用計數 $n_k$**：記錄技能被檢索的次數，用於平衡探索與利用。

這種設計的關鍵洞見在於：VLM 本身具備強大的視覺理解能力，將技能以影像形式直接注入視覺上下文（visual context），能夠實現忠實的視覺定位（Faithful Visual Grounding），避免文字描述在傳遞空間結構時的資訊損耗。

**技能檢索機制**

給定當前任務狀態，ViSkill 透過幾何相似度匹配進行技能檢索：

$$s_k = \text{sim}(g, g_k)$$

其中 $g$ 為當前狀態的幾何特徵。最終檢索評分 $q_k$ 結合相似度與效用值：

$$q_k = \alpha s_k + (1-\alpha) u_k$$

當 $q_{k^\star} \geq \delta_r$ 時，選取最優技能 $z_{k^\star}$ 並注入代理的視覺輸入。這種基於幾何配置的檢索方式比純文字匹配更能捕捉空間結構的相似性。

**技能引導的獎勵塑形（Reward Shaping）**

ViSkill 設計了技能引導獎勵 $R(\tau)$：

$$R(\tau) = \begin{cases} r_{\text{task}}(\tau), & \text{if } y_\tau = 1 \\ r_{\text{task}}(\tau) + \lambda \cdot r_{\text{skill}}(\tau, z), & \text{otherwise} \end{cases}$$

其中 $y_\tau = 1$ 表示軌跡成功。對於失敗但展現出技能相關進展的軌跡，系統會給予部分信用（partial credit），從而緩解稀疏獎勵問題。這種獎勵塑形機制使得即使最終未達成的嘗試，只要其中某些子步驟符合已學技能的特徵，仍能獲得學習信號。

**技能蒸餾（Skill Distillation）與閉環回饋**

成功軌跡需通過品質閘門 $q_{\max} < \delta_d$ 與新穎性閘門 $L_\tau \leq L_{\text{budget}}$ 的雙重篩選，方可被蒸餾為新技能 $z_{\text{new}}$ 加入技能庫（Skill Library）。這一閉環回饋迴路（Closed Feedback Loop）的運作邏輯為：檢索到的技能透過情境示範（in-context demonstration）與獎勵塑形改善策略，而改善後的策略又產生更高品質的軌跡，回流至技能庫形成更優質的技能，形成技能累積（Skill Accumulation）與策略改進（Policy Improvement）的正向循環。

**冷啟動機制（Cold-Start Mechanism）**

為緩解早期訓練中技能庫稀疏導致的冷啟動問題，ViSkill 引入可選的冷啟動初始化（Cold-Start Initialization），利用求解器（solver）預先生成少量多樣化的種子技能。這些種子技能為早期策略提供有意義的引導，加速收斂（Convergence）過程。

#### 實驗數據解讀

ViSkill 在三個基準環境上進行了系統性評估：

1. **Sokoban（推箱子）**：經典的離散二維空間規劃任務，要求將所有箱子推至目標位置，涉及多步驟操控（Multi-Step Manipulation）與障礙物導航（Obstacle Navigation）；
2. **FrozenLake（冰湖）**：標準強化學習基準環境，測試在不確定性下的路徑規劃能力；
3. **PrimitiveSkill**：涉及座標定位的三維物體操控（Object Manipulation）任務。

**主要結果**

ViSkill 達到了 0.89 的整體成功率（Success Rate），加入冷啟動初始化後進一步提升至 0.91。這一成績超越了所有評估的專有基準模型（Proprietary Baseline）與開源基準模型（Open-Source Baseline）。值得注意的是，論文明確指出 ViSkill 在收斂速度上亦優於標準 PPO（Proximal Policy Optimization），這意味著其在樣本效率（Sample Efficiency）上具有顯著優勢——在達到相同性能水平時所需的環境互動次數更少。

**消融實驗的意涵**

論文報告了兩項關鍵消融結果：

1. **視覺表示 vs. 文字表示**：視覺技能表示在所有任務上均一致地優於以文字為中心的替代方案，這直接驗證了「表示差距」假設——空間結構的視覺保留對策略執行（Strategy Execution）至關重要；
2. **聯合優化 vs. 解耦累積**：在聯合策略優化下蒸餾的技能比獨立累積的技能具有更強的遷移能力，這證實了「學習差距」假設——技能構建與策略優化的雙向耦合能產生更有效的程序性知識（Procedural Knowledge）。

**收斂行為分析**

ViSkill 在整個訓練過程中均維持更高的成功率，而非僅在最終性能上取勝。這一現象反映了閉環回饋迴路的動態特性：技能庫隨訓練逐步豐富，而更豐富的技能庫又加速策略改善，形成自我強化的良性循環。相比之下，標準 PPO 缺乏這種外部記憶機制，必須從零開始重新發現相似的空間解法（Spatial Solution）。

#### 與現有研究的比較

**定位**

ViSkill 處於三個研究方向的交匯點：視覺語言模型的強化學習、技能增強型代理、以及視覺證據（Visual Evidence）整合。與現有工作相比，其核心差異化在於：

| 面向 | 現有方法 | ViSkill |
|------|----------|---------|
| 技能表示 | 文字描述、結構化工作流 | 視覺技能卡（複合影像） |
| 技能與策略的關係 | 解耦建構與優化 | 閉環回饋、聯合優化 |
| 獎勵設計 | 純任務獎勵 | 任務獎勵 + 技能引導部分信用 |
| 冷啟動 | 通常無 | 可選求解器種子技能 |

**改進**

相較於以文字為中心的方法（如基於自然語言指令的技能庫），ViSkill 的視覺原生表示避免了空間資訊在語言化過程中的損失，這對於需要精確空間推理的任務（如 Sokoban）尤為關鍵。相較於近期開始整合視覺證據但仍將技能建構與策略優化分離的工作，ViSkill 的閉環設計使得技能品質能隨策略進步而持續提升。

**限制**

儘管結果令人鼓舞，仍需指出幾項潛在限制：

1. **視覺技能卡的計算成本**：每張技能卡都是一張高資訊密度影像，技能庫的持續增長可能帶來儲存與檢索的開銷；
2. **幾何特徵的泛化性**：當前提取幾何特徵 $g_k$ 的方式可能在跨環境遷移時面臨挑戰；
3. **評估環境的範圍**：目前實驗集中於離散動作空間與相對受限的環境，在更開放的真實世界場景中的表現尚待驗證；
4. **冷啟動對求解器的依賴**：冷啟動機制需要任務具備可靠的求解器，這在某些領域可能不易獲得。

#### 可重現性評估

ViSkill 在可重現性方面表現良好：

1. **程式碼開源**：作者明確提供了程式碼倉庫連結（https://github.com/ZJU-REAL/ViSkill），便於研究者復現實驗結果；
2. **基準環境公開**：Sokoban、FrozenLake 與 PrimitiveSkill 均為公開可用的基準環境，降低了環境配置門檻；
3. **論文細節**：方法論章節提供了技能檢索評分、獎勵塑形公式、蒸餾閘門條件等關鍵超參數的數學描述。

然而，若要完全重現實驗，仍需關注以下要素：

- **VLM 骨幹網路**：論文中使用的具體 VLM 架構與版本需從程式碼確認；
- **PPO 超參數**：標準 PPO 的超參數設定（如學習率、clip ratio、GAE 參數等）對結果有顯著影響；
- **技能庫容量與檢索閾值**：$\delta_r$、$\delta_d$、$L_{\text{budget}}$ 等閾值的具體數值需從程式碼或附錄獲取；
- **隨機性控制**：多次隨機種子的成功率均值與標準差未在摘要中提供，但對於評估結果的穩健性至關重要。

#### 未來研究方向

ViSkill 開啟了多個值得深入探索的方向：

1. **技能抽象層級化**：當前每張技能卡對應一條完整軌跡，未來可探索將技能組織為多層級抽象（如原子動作 → 子程序 → 完整策略），以支援更靈活的組合與遷移；

2. **跨任務技能遷移**：目前技能庫在任務間的共享機制尚不明確，研究如何使在一個任務中學到的視覺技能遷移至結構相似但語義不同的任務，將是提升樣本效率的關鍵；

3. **動態技能精煉**：隨著策略演進，早期累積的技能可能變得冗餘或過時。引入技能淘汰與合併機制，維持技能庫的精煉性與多樣性之間的平衡，是一個值得探討的問題；

4. **真實世界機器人整合**：將 ViSkill 從模擬環境擴展至真實機器人操控，需要解決感知噪聲、動作不確定性等挑戰，同時驗證視覺技能卡在物理世界中的實用性；

5. **理論分析**：閉環回饋迴路的收斂性、穩定性與最優性缺乏理論保障，未來可從優化理論或線上學習的角度分析技能累積與策略改進的交互動力學；

6. **多模態技能擴展**：將視覺技能卡的概念延伸至包含聽覺、觸覺等其他模態的複合技能表示，可能為多模態代理開啟新的可能性；

7. **人機協作技能庫**：探索人類專家如何參與技能庫的構建與審核，使 ViSkill 不僅能從自主經驗中學習，也能吸收人類的程序性知識，形成更強大的混合智慧系統。

總體而言，ViSkill 透過將視覺原生表示與閉環技能-策略聯合優化相結合，為視覺語言模型代理的強化學習提供了一條新穎且有效的技術路徑，其核心洞見——空間經驗（Spatial Experience）應以視覺形式而非文字形式保留——對整個領域具有方法論上的啟示意義。

## 論文問答

**Q1：ViSkill 試圖解決的核心問題是什麼？**
A：ViSkill 試圖解決視覺語言模型（VLM）代理在視覺基礎環境中進行強化學習時所面臨的「經驗無法被有效重用」的問題。在標準強化學習框架下，成功的策略僅以隱式方式被吸收進策略參數中，導致代理在每個回合都必須重新發現相似的空間解法，造成樣本效率低落。論文中指出，成功的軌跡本身已蘊含可重用的程序性知識，例如如何繞過障礙物或如何協調多步驟物體操控，這些經驗若能被顯式保留並跨回合重用，將大幅提升學習效率。因此 ViSkill 的核心目標是建立一個能將成功經驗外化為可檢索、可重用的視覺原生技能庫的框架。

**Q2：為何現有以文字為中心的技能表示法在視覺基礎環境中會失效？**
A：現有以文字為中心的技能表示法會將空間佈局、相對位置以及動作-狀態對應「線性化」為自然語言描述，這種抽象過程本質上是「有損的空間抽象」，會遺失對策略執行至關重要的幾何資訊。例如在推箱子遊戲中，「玩家在箱子正上方、目標在牆後的右下方」這類文字描述無法忠實保留空間結構，使代理難以正確推導出推動方向與路徑規劃。論文的圖 1 明確展示了這種落差：文字版本只能給出模糊的方向性指引，而視覺原生版本則能直接呈現完整的空間配置與動作序列。這種表示差距（representation gap）在需要精細空間推理的任務中尤其致命。

**Q3：論文中所說的「學習差距」（learning gap）為何重要？**
A：學習差距指的是現有方法即使開始將視覺證據納入技能建構與利用，卻仍將技能建構與策略優化「解耦」處理，導致視覺技能獲取與策略學習之間的雙向交互作用被嚴重忽略。這種解耦意味著技能庫無法隨著策略的進步而動態更新，反之策略也無法從持續累積的高品質技能中獲益，形成單向、靜態的知識傳遞。論文中強調，這種缺乏雙向互補的設計會限制技能增強型代理在視覺基礎任務中的效能天花板。ViSkill 正是為了填補此差距，設計出技能累積與策略改進相互強化的閉環回饋迴路。

**Q4：ViSkill 的核心方法是什麼？**
A：ViSkill 的核心方法是將每次成功的互動編碼為「複合視覺技能卡」（composite visual skill card），這種技能卡將標註過的軌跡畫面與由策略蒸餾出的策略描述渲染成統一張圖片，直接保留成功經驗的空間與程序脈絡。給定當前任務狀態時，ViSkill 透過比對幾何配置從技能庫中檢索最相關的技能，並將完整的技能卡注入 VLM 的視覺上下文中。被檢索出的技能同時還會提供一個「技能引導獎勵」（skill-guided reward），對展現出技能相關進展但尚未完全成功的軌跡給予部分信用。每個回合結束後，通過品質與新穎性門檻的成功軌跡會被蒸餾回技能庫，形成動態成長的視覺原生技能庫。

**Q5：視覺技能卡相較於傳統文字技能描述的關鍵創新為何？**
A：視覺技能卡的關鍵創新在於它將「標註軌跡」與「渲染後的策略」整合為單一圖像，使 VLM 代理能以原生視覺方式接收程序性經驗，而無需經過語言線性化的有損轉換。這種設計實現了論文中所稱的「忠實視覺定位」（faithful visual grounding），因為空間佈局、物體相對位置與動作-狀態對應都能在像素層級被完整保留。相較於文字描述，視覺技能卡不僅降低了資訊損失，也更貼近 VLM 本身的感知模態，使代理能直接運用其視覺推理能力解讀經驗。此外，每張技能卡還附帶幾何特徵、效用值與使用計數等元資料，支援後續的幾何感知檢索與品質控管。

**Q6：ViSkill 的閉環回饋迴路是如何運作的？**
A：ViSkill 的閉環回饋迴路由三個相互強化的機制構成：技能檢索、技能引導強化優化、以及技能蒸餾。在推理階段，代理根據當前狀態的幾何特徵從技能庫中檢索最相關的技能卡，並將其注入視覺上下文以引導動作選擇；在訓練階段，被檢索的技能提供技能引導獎勵，與 PPO 的稀疏任務獎勵結合形成更密集的學習信號；最後，每回合結束後通過品質與新穎性雙重門檻的成功軌跡會被蒸餾為新技能並加入函式庫。這樣一來，被檢索的技能透過情境示範與獎勵塑形來改善策略，而改善後的策略又能貢獻更高品質的技能回流到函式庫，形成正向的自我強化循環。

**Q7：ViSkill 在哪些基準環境上進行了評估？為何選擇這些環境？**
A：ViSkill 在三個基準環境上進行評估：推箱子（Sokoban）、冰湖（FrozenLake）以及 PrimitiveSkill。選擇這些環境是因為它們橫跨了離散二維空間規劃（Sokoban、FrozenLake）與座標基礎的三維物體操控（PrimitiveSkill）兩大類視覺基礎任務，能全面檢驗框架在不同視覺複雜度下的泛化能力。Sokoban 是經典的空間規劃基準，需要代理理解相對位置並規劃多步驟推箱動作；FrozenLake 則考驗代理在稀疏獎勵下的導航與避障能力；PrimitiveSkill 則涉及三維空間中的精細物體操控。這三者的組合使評估結果能反映 ViSkill 在不同視覺推理需求下的穩健性。

**Q8：ViSkill 的關鍵實驗結果為何？**
A：ViSkill 在三個基準環境上取得了 0.89 的整體成功率，加上冷啟動初始化後更提升至 0.91，超越了所有評估的專有基準模型與開源基準模型。除了最終效能外，ViSkill 在訓練過程中收斂速度也明顯快於標準 PPO，並在整個訓練曲線上都維持更高的成功率，反映出技能累積與策略改進之間的正向回饋效果。這些結果證明了視覺原生技能表示相較於文字替代方案在樣本效率與最終表現上的雙重優勢，也驗證了閉環設計相較於解耦式技能建構的實質效益。

**Q9：ViSkill 的消融研究揭示了哪些關鍵發現？**
A：消融研究揭示了兩個關鍵發現：第一，視覺技能表示在所有對照組中皆持續優於以文字為中心的替代方案，證明了視覺原生表示在保留空間結構上的不可替代性；第二，在聯合策略優化下蒸餾出的技能比未經此過程累積的技能更具遷移效果，凸顯了技能建構與策略學習雙向耦合的重要性。這兩項消融結果共同支持了論文的核心論點：視覺原生表示與閉環優化缺一不可，僅改善其中一項並不足以達到最佳效能。這也意味著未來相關研究若僅著眼於表示形式而忽略學習機制的設計，將難以充分釋放技能增強型代理的潛力。

**Q10：ViSkill 適用於哪些實際應用場景？**
A：ViSkill 特別適用於需要視覺推理與多步驟空間決策的實際場景，例如機器人操控、自動駕駛路徑規劃、遊戲 AI 以及工業自動化中的視覺引導任務。在機器人領域，代理需要理解物體在三維空間中的相對位置並規劃多步驟操控序列，這正是 PrimitiveSkill 所模擬的情境；在自動駕駛中，代理需要在動態視覺環境中導航並避障，類似 FrozenLake 的稀疏獎勵設定；在遊戲 AI 與教育訓練模擬中，ViSkill 的可重用技能庫能讓代理快速累積並遷移經驗，降低訓練成本。這些場景的共同特徵是視覺資訊密集、空間推理關鍵、且任務具有程序性結構。

**Q11：將 ViSkill 部署到實際產品時需要考量哪些因素？**
A：將 ViSkill 部署到實際產品時需考量多項工程因素：首先，技能庫的儲存與檢索成本會隨技能數量成長，需要設計有效的索引與淘汰機制以維持回應延遲在可接受範圍內；其次，視覺技能卡的渲染品質與解析度會直接影響 VLM 的解讀效果，需要在視覺保真度與推論成本之間取得平衡；第三，技能引導獎勵的權重 λ 屬於敏感超參數，過強的獎勵塑形可能導致策略偏離任務目標；最後，技能庫中新技能的品質與新穎性門檻需要根據任務特性調整，過於寬鬆會引入低品質技能，過於嚴格則會限制技能多樣性。這些考量顯示出 ViSkill 從研究框架走向產品化仍需進行系統性的工程調校。

**Q12：ViSkill 對視覺語言模型代理研究領域的更廣泛影響為何？**
A：ViSkill 對該領域的更廣泛影響在於它重新定義了「經驗」在強化學習中的角色，從單純的訓練信號轉變為可外化、可檢索、可累積的視覺知識資產。這種觀點的轉變可能啟發後續研究探索更多模態原生（而非文字中介）的知識表示形式，例如音訊技能卡或觸覺技能卡。此外，ViSkill 所展示的「技能累積與策略改進相互強化」的正向回饋原則，可被推廣至其他需要長期經驗累積的代理學習範式，例如持續學習與終身學習。從實務面來看，ViSkill 為建構可解釋、可審核的代理行為提供了新的可能性，因為技能卡本身就是人類可理解的視覺化經驗記錄。

**Q13：ViSkill 在論文中有哪些已承認的限制？**
A：雖然論文未明確列出獨立章節討論限制，但從方法設計與實驗範圍可推論出若干已隱含承認的限制：首先是視覺技能卡依賴於高品質的軌跡標註與渲染，這在更複雜的真實世界環境中可能難以自動化生成；其次是技能庫的容量與多樣性管理仍仰賴人工設定的品質與新穎性門檻，缺乏自適應機制；第三是實驗僅在三個基準環境上驗證，對於真實世界三維場景中更複雜的視覺變化（如光照、遮擋、紋理變化）的穩健性尚未充分檢驗。這些限制提示了後續工作需要在更大規模、更多樣化的環境中驗證 ViSkill 的泛化能力。

**Q14：ViSkill 可能會在哪些情境下失效？**
A：ViSkill 可能會在以下幾種情境下失效：第一，當任務的視覺配置與技能庫中任何技能的幾何特徵都不相似時，技能檢索將無法提供有用引導，代理會退化為無技能輔助的標準 PPO 學習；第二，當環境的視覺呈現高度動態或隨機化（如隨機生成的地圖、變化的光照），技能卡中的視覺模式可能無法穩定對應到新狀態；第三，當任務需要極長程規劃或跨多個獨立子任務的組合時，單一技能卡可能不足以編碼完整的策略，需要更複雜的技能組合機制；第四，當 VLM 本身的視覺編碼能力不足以解讀細微空間差異時，視覺技能卡的優勢也會被削弱。這些失效情境凸顯了 ViSkill 並非通用解方，仍需依任務特性審慎評估適用性。

**Q15：基於 ViSkill 的未來研究方向有哪些？**
A：基於 ViSkill 的未來研究方向可從多個維度展開：在表示層面，可探索更高維度或多模態的技能卡，例如結合深度資訊、語音指令或觸覺回饋的複合技能表示；在學習機制層面，可研究自適應的品質與新穎性門檻，讓技能庫能根據代理的學習階段動態調整收錄標準；在理論層面，可進一步形式化閉環回饋迴路的收斂性與穩定性條件，並分析技能多樣性與策略效能之間的理論關聯；在應用層面，可將 ViSkill 推廣至真實機器人、自動駕駛與多代理協作等更複雜的場景，並探索跨任務、跨環境的技能遷移機制。這些方向共同指向一個更宏觀的願景：建構能像人類一樣累積並重用視覺經驗的通用視覺語言代理。

## 實務應用指南

### 適用場景

ViSkill 的視覺原生技能學習框架特別適合以下幾類實際應用場景：

**1. 機器人倉儲物流操控**
在倉儲自動化中，機器人需要根據視覺輸入判斷貨物位置、避開障礙物並完成搬運任務。ViSkill 可將成功搬運軌跡蒸餾為視覺技能卡（例如「將貨物從 A 區推至 B 區的標準路徑」），新機器人上線時只需檢索相似幾何配置即可快速上手，無需從零開始訓練。

**2. 工業裝配線視覺引導**
對於需要多步驟空間操作的精密組裝任務（如電子元件插件、機械手臂焊接），可將師傅級技師的操作軌跡記錄為視覺技能卡，新進機器人或新任務可透過技能檢索獲得「視覺示範」，大幅縮短冷啟動時間並降低失敗率。

**3. 自動駕駛邊角案例處理**
面對施工改道、特殊路口等長尾場景，可將成功處理這類場景的駕駛軌跡蒸餾為視覺技能卡。當車輛再次遇到相似幾何配置時，自動檢索對應技能作為視覺上下文引導，並透過獎勵塑形鼓勵策略朝正確方向收斂。

**4. 遊戲 AI 與 NPC 行為生成**
在遊戲開發中，可讓 NPC 透過 ViSkill 累積「視覺技能庫」，學習如何在不同地形配置下完成任務（推箱子式解謎、戰術走位）。技能卡以圖像形式呈現，便於美術與企劃團隊審視與調整。

**5. 室內服務機器人**
家用或商用服務機器人需在動態環境中完成送餐、清潔、巡檢等任務。ViSkill 的閉環回饋機制可讓機器人在實際運行中持續累積新技能，並即時用於後續決策，特別適合需要長期部署、持續學習的場景。

### 實作前置條件

**資料需求**
- **環境互動介面**：需具備可程式化控制的視覺環境（遊戲引擎、機器人模擬器如 MuJoCo/Isaac Sim、網頁自動化環境如 BrowserGym），能回傳畫面像素與動作空間。
- **示範軌跡資料**：冷啟動機制需要少量由專家解題器（solver）或人類示範產生的成功軌跡，建議至少 50–200 條涵蓋多樣幾何配置。
- **任務狀態描述**：每個環境需提供結構化狀態資訊（網格座標、物件相對位置等），用於技能檢索時的幾何匹配。
- **獎勵函數定義**：需設計稀疏任務獎勵（成功/失敗）以及可選的進度指標，用於技能引導獎勵塑形。

**運算資源**
- **VLM 推論**：建議使用具備視覺理解能力的開源模型（如 Qwen2-VL、InternVL）或 API（如 GPT-4V、Claude），單次推論需支援圖像輸入。
- **訓練算力**：PPO 訓練需多 GPU 環境（建議至少 4×A100/H100），視覺技能卡的渲染與編碼可於 CPU/GPU 混合執行。
- **儲存空間**：技能庫會隨訓練累積成長，建議預留數十 GB 至 TB 等級的向量與圖像儲存。

**技能門檻**
- **強化學習基礎**：團隊需熟悉 PPO、GAE 等策略優化演算法，以及視覺強化學習的常見陷阱（稀疏獎勵、credit assignment）。
- **VLM 工程能力**：需具備視覺語言模型的 prompt 設計、視覺上下文注入（visual prompting）經驗。
- **電腦視覺處理**：熟悉物件偵測、軌跡標註、圖像合成等技能卡生成流程。
- **檢索系統開發**：能實作基於幾何特徵的相似度計算（向量檢索或傳統特徵匹配）。

### 實作步驟建議

**階段一：環境與基準建置（2–4 週）**
1. 選定目標環境並封裝為統一介面（observation、action、reward、done）。
2. 實作 baseline PPO 訓練 pipeline，確認 VLM agent 可在環境中完成基本互動。
3. 建立軌跡記錄模組，儲存每回合的畫面序列、動作序列與最終成敗標記。

**階段二：視覺技能卡生成（3–5 週）**
1. 設計技能卡的視覺模板：將標註後的關鍵幀（標示物件位置、動作箭頭）與策略文字描述合成為單一圖像。
2. 實作軌跡蒸餾流程：對成功軌跡進行品質篩選（長度、效率）與新穎性篩選（與既有技能的距離），通過門檻者入庫。
3. 建立技能元資料：每張技能卡需附帶幾何特徵向量（用於檢索）、效用統計（歷史成功率）、使用次數。

**階段三：技能檢索與獎勵塑形（3–4 週）**
1. 實作幾何感知檢索器：根據當前狀態與技能庫計算相似度分數，結合效用權重得出綜合評分。
2. 將檢索到的技能卡注入 VLM 的視覺上下文（與當前畫面並排或疊加呈現）。
3. 設計技能引導獎勵：對失敗但展現技能相關進度的軌跡給予部分獎勵，公式參考論文中的 $r_{\text{skill}}(\tau, z)$。

**階段四：閉環整合與冷啟動（2–3 週）**
1. 串接完整迴路：策略 → 環境互動 → 軌跡收集 → 蒸餾入庫 → 技能檢索 → 下一輪策略。
2. 實作冷啟動機制：預先以專家解題器產生多樣化種子技能，填入技能庫以加速早期訓練。
3. 監控技能庫成長曲線與策略收斂速度，調整蒸餾門檻與檢索閾值。

**階段五：評估與部署（持續）**
1. 在 Sokoban、FrozenLake 等基準上驗證效能，確認超越 PPO baseline 與其他技能增強方法。
2. 進行消融實驗：視覺 vs 文字技能表示、聯合優化 vs 獨立優化，量化各元件貢獻。
3. 將訓練好的策略與技能庫打包部署，建立技能庫更新與版本管理流程。

### 潛在風險與注意事項

**風險一：技能庫膨脹與檢索效率下降**
隨訓練進行，技能庫可能累積大量相似技能，導致檢索變慢且引入雜訊。
**緩解**：設定技能數量上限、定期合併相似技能（聚類）、使用近似最近鄰（ANN）索引如 FAISS。

**風險二：視覺技能卡品質不穩定**
若軌跡標註品質差或策略描述模糊，技能卡可能誤導後續 agent。
**緩解**：建立品質閾值（最短路徑比例、成功率）、引入人工抽樣審核、讓 VLM 對技能卡做自我評分。

**風險三：冷啟動種子技能的偏差**
若專家解題器產生的種子技能過於單一，會限制後續探索空間。
**緩解**：刻意蒐集多樣化幾何配置、加入隨機擾動版本、定期重置部分技能庫以鼓勵探索。

**風險四：獎勵塑形導致策略偏離**
技能引導獎勵若設計不當，可能讓 agent 過度追求「展現技能相關進度」而忽略最終任務目標。
**緩解**：限制塑形獎勵權重 $\lambda$、僅在失敗軌跡啟用、定期檢查策略是否仍以最終獎勵為主要驅動。

**風險五：VLM 視覺上下文長度限制**
注入技能卡會佔用 VLM 的視覺 token 預算，可能壓縮當前觀察的解析度。
**緩解**：技能卡採高壓縮渲染、僅在關鍵決策點注入、選擇支援長上下文的 VLM（如百萬 token 等級模型）。

**風險六：模擬到真實的轉移差距**
若在模擬器訓練，視覺技能可能無法直接遷移到真實機器人。
**緩解**：在技能卡中加入域隨機化（光照、紋理）、建立模擬到真實的微調流程、保留少量真實示範用於校正。

### 與其他技術的整合建議

**與 RAG（檢索增強生成）整合**
ViSkill 的技能檢索本質上是視覺版的 RAG。可將技能庫視為長期記憶，與短期對話記憶、工具呼叫結果共同組成 agent 的多層次上下文。建議將技能檢索設計為獨立服務，透過標準介面（如 REST 或 gRPC）供 agent 呼叫。

**與 Agent 框架整合**
可將 ViSkill 嵌入 LangGraph、AutoGen、CrewAI 等主流 agent 框架，作為「視覺記憶模組」。在每個決策節點呼叫技能檢索，並將結果以 system message 或視覺附件形式傳遞給 VLM。

**與傳統 RL 演算法整合**
ViSkill 的獎勵塑形機制可與 SAC、TD3 等 off-policy 演算法結合，技能引導獎勵作為輔助訊號加速收斂。需注意 on-policy 與 off-policy 對獎勵塑形的相容性差異。

**與模仿學習整合**
可先用行為克隆（behavior cloning）從人類示範預訓練策略，再以 ViSkill 進行 RL 微調。技能庫可同時作為模仿學習的資料增強來源。

**與多模態基礎模型整合**
當新版 VLM 釋出時，可將既有技能庫遷移至新模型：保留幾何特徵與策略描述，重新渲染技能卡以適配新模型的視覺編碼偏好。建議建立技能庫的 schema 標準化，便於跨模型遷移。

**與 MLOps 平台整合**
將技能庫視為一級模型資產，納入模型註冊表（model registry）進行版本管理；技能蒸餾流程可整合進 CI/CD pipeline，每次策略更新自動觸發技能庫重建與評估。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先閱讀第 1 節的問題動機與圖 1，理解「為什麼以文字描述空間經驗會失真」這個核心直覺，再跳到結論看 ViSkill 在三個基準上的成功率數字（0.89 / 0.91）。中間的演算法細節可以略過，重點是建立「視覺技能卡 = 可重用的視覺示範」這個概念。搭配論文的 GitHub 程式碼跑一遍 Sokoban 範例，會比純讀文字更快掌握全貌。

**給 AI 工程師**
重點關注第 2 節的相關工作分類（特別是 2.2 技能增強型代理）與圖 2 的系統架構圖。實作時建議先還原 baseline PPO pipeline，再分模組加入技能卡生成、檢索、獎勵塑形。特別注意技能蒸餾的品質與新穎性門檻——這是影響最終效能的關鍵超參數，可參考論文的消融實驗數據設定初始值。

**給研究者**
本文的核心創新在於「視覺原生表示」與「技能累積與策略優化的閉環」兩個層面的結合。建議從表示差距（representation gap）與學習差距（learning gap）兩個視角切入，思考這兩個 gap 是否在其他模態（音訊、觸覺）也存在類似問題。冷啟動機制、幾何感知檢索、聯合優化的數學推導值得仔細推敲，這些都是可延伸的研究方向。

**給產品經理**
ViSkill 的價值主張是「讓 VLM agent 從經驗中累積可重用的視覺技能，減少重複探索並加速收斂」。在評估導入可行性時，請關注三點：(1) 目標任務是否具有可重複的空間模式（倉儲、裝配、駕駛適合；純對話任務不適合）；(2) 能否取得少量高品質示範用於冷啟動；(3) 視覺技能庫的維護成本（標註、審核、版本管理）是否在預算內。論文的基準數據可作為內部 POC 驗收的參考標竿。
