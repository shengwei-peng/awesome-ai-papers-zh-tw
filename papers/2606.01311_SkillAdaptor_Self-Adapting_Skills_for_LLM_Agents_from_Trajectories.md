## 摘要翻譯

大型語言模型 (LLM) 代理日益依賴可重複使用的外部技能來解決長時程互動任務。現有的無需訓練的技能適配流程通常從完整軌跡或會話級回饋更新技能，這使得失敗歸因過於粗糙，且經常產生不穩定或過於廣泛的修訂。我們提出 SkillAdaptor——一個具備明確失敗歸因、無需訓練的步驟級技能適配框架，且可外掛於 OpenClaw 類代理框架。給定一個失敗軌跡，SkillAdaptor 識別首個可操作的錯誤步驟，將責任連結至候選技能，並在明確的驗收檢查下進行針對性更新，同時保持凍結的骨幹模型不變。我們在 WebShop、PinchBench 和 Claw-Eval 上使用 Kimi-K2.5、GLM-5 和 GPT-5.2 進行評估。SkillAdaptor 在所有三個基準測試上均優於無技能基準和技能適配基準，最大單一指標改進幅度為：PinchBench 平均分數 (%) 提升 +1.5 分、Claw-Eval 平均分數提升 +1.8、WebShop 成功率提升 +1.7。這些結果表明，步驟級歸因有助於實現更穩定且可審核的無需訓練技能維護。程式碼將在 https://github.com/zjunlp/SkillAdaptor 開源釋出。

### 核心貢獻（3～5點）
- 提出 SkillAdaptor 框架：一個具備明確失敗歸因、無需訓練的步驟級技能適配框架，可作為外掛元件整合至 OpenClaw 類代理框架。
- 引入精細化的失敗歸因機制：透過識別失敗軌跡中的首個可操作的錯誤步驟，將責任精確連結至候選技能，避免軌跡級反思所帶來的信用分配問題。
- 設計穩健的技能更新流程：在明確的驗收檢查下進行針對性更新，同時保持骨幹模型凍結，有效避免錯誤導向的修訂與技能缺陷的擴散。
- 在三項基準測試上驗證有效性：於 WebShop、PinchBench、Claw-Eval 上搭配 Kimi-K2.5、GLM-5、GPT-5.2 進行實驗，於所有基準測試上均超越無技能基準與技能適配基準，最大單一指標改進達 +1.8 分。

### 適合對象
從事 LLM 代理、工具使用、網頁互動與長時程任務規劃研究的學者與工程師；關注無需訓練方法、技能庫維護、記憶蒸餾與工作流優化的研究人員；以及希望理解步驟級信用分配與模組化執行後適配如何提升代理可靠性與可審核性的實務開發者。

## 深度分析

#### 方法論解析

SkillAdaptor 提出了一種**步驟級技能適配框架 (step-level skill adaptation framework)**，其核心設計理念是將傳統的軌跡級反思 (trajectory-level reflection) 轉變為精細化的步驟級歸因 (step-level attribution)。整個方法論可從三個層面深入理解：

**1. 問題形式化 (Problem Formulation)**

論文將 LLM 代理 (LLM agent) 的執行過程形式化為軌跡 τ = {(aₜ, oₜ)}ᵀₜ₌₁，其中 aₜ 為動作、oₜ 為觀察。技能庫 K = {s₁, s₂, ..., sₙ} 為可更新的文字化技能記錄，每筆技能包含標題、原則 (principle) 與適用條件 (applicability conditions)。骨幹模型 (backbone) 保持凍結，僅透過更新 K 來最大化期望成功率：

$$\max_K \mathbb{E}_{q \sim Q}[\text{success}(\text{Run}(q, K))]$$

此形式化凸顯了方法的兩個關鍵特性：訓練無需 (training-free) 與可審計性 (auditability)，所有改進皆可歸因於技能庫的更新。

**2. 三階段適配流程 (Three-Stage Adaptation Pipeline)**

**(a) 歸因階段 (Attribution)**：此階段包含兩個子模組：
- **定位器 (Localizer)**：從失敗軌跡中識別「首個可操作的錯誤步驟 (first actionable fault step)」t*，並生成觀察到的失敗描述 π 與改進建議。關鍵在於「可操作」一詞——並非所有錯誤步驟都適合作為修訂起點，定位器需判斷哪些步驟的修正能實質改善最終結果。
- **連結器 (Linker)**：基於 t* 估計檢索技能中各技能的責任權重 {(sⱼ, wⱼ)}，輸出加權的可疑技能 (suspect skills) 集合。此設計避免了將失敗信號擴散至不相關技能的問題。

**(b) 修改階段 (Modification)**：包含生成器 (Generator) 與修訂器 (Reviser)。Generator 根據歸因結果產生新技能候選，Reviser 則對現有可疑技能進行精準修訂。值得注意的是，方法僅修訂被歸因為有責任的技能，而非對整個技能庫進行廣泛修訂 (broad revision)，這是與現有方法最關鍵的差異。

**(c) 資格審查階段 (Qualification)**：此階段執行明確的驗收檢查 (acceptance check)，對生成或修訂的技能進行品質把關，拒絕不合格的更新並記錄至拒絕歷史 (rejected history)，避免低品質技能污染技能庫。

**3. 技能初始化與檢索機制 (Skill Initialization & Retrieval)**

框架初始化時不依賴任何外部技能庫，而是先讓骨幹模型在無技能增強下執行任務集，成功軌跡經蒸餾形成初始技能庫 K₀。技能檢索採用兩階段策略：先用 Qwen3-Embedding-8B 編碼計算餘弦相似度，取 top-kᵣₑₜ 候選，再由骨幹 LLM 進行重排序 (rerank)。此混合檢索策略兼顧效率與語意精確度。

**4. 迭代控制 (Iteration Control)**

適配過程最多迭代 10 輪，或當技能庫連續 3 輪無變化時提前停止，最終技能庫 K* 凍結不再更新。此設計防止過度擬合特定失敗模式，同時控制計算成本。

#### 實驗數據解讀

**1. 基準測試與模型配置**

實驗在三個互補的基準上進行：
- **WebShop**：以成功率 (Succ%) 與分數 (Score) 衡量，模擬真實網頁購物互動
- **PinchBench**：以平均分數百分比 (Avg Score%) 衡量
- **Claw-Eval**：以平均分數 (Avg Score) 與 Pass@3% 衡量

使用的骨幹模型涵蓋三個層級：Kimi-K2.5、GLM-5 與 GPT-5.2，這種多模型配置有助於驗證方法的泛化性，而非僅針對特定模型的過擬合。

**2. 主要結果分析**

**PinchBench 與 Claw-Eval (Table 1)**：
- SkillAdaptor 在所有三個模型上均優於 Base Model 與 OpenSpace 基準
- PinchBench 上最大改進：GPT-5.2 從 74.8% 提升至 76.6% (+1.8 點)
- Claw-Eval 上最大改進：Kimi-K2.5 從 73.2 提升至 75.8 (+2.6 點)，Pass@3% 從 74.4% 提升至 77.4%
- 值得注意的是，標準差 (standard deviation) 在多數情況下低於基準方法，顯示方法不僅提升平均表現，也提升穩定性

**WebShop (Table 2)**：
- SkillAdaptor 在所有模型上皆達到最佳表現
- GPT-5.2 成功率從 25.0% 提升至 34.3% (+9.3 點絕對提升)
- Kimi-K2.5 分數從 32.1 提升至 41.6 (+9.5 點)
- 與四個強基準 (A-Mem、AWM、ExpeL、EvoSkill) 相比皆有顯著優勢，特別是相對於 EvoSkill 仍有 +1.2 至 +1.7 點的提升

**3. 改進幅度的解讀**

雖然摘要中強調的「最大單一指標改進」分別為 +1.5、+1.8、+1.7 點看似溫和，但需注意以下幾點：
- 這些是在已高度優化的基準上取得的改進，邊際效應遞減明顯
- 標準差普遍較低，意味著改進具有一致性而非隨機波動
- 跨三個基準、三個模型的一致性提升，顯示方法具有穩健的泛化能力
- 在 WebShop 上相對於 Base Model 的絕對提升可達 +9.3 點，顯示實際應用價值

**4. 基準方法的選擇意涵**

WebShop 比較中納入的基準涵蓋了主要技術路線：
- **A-Mem**：基於記憶蒸餾 (memory distillation) 的方法
- **AWM**：工作流優化 (workflow refinement) 路線
- **ExpeL**：經驗學習方法
- **EvoSkill**：迭代式技能演化 (iterative skill evolution)

SkillAdaptor 在所有基準上的優勢，顯示步驟級歸因相較於這些軌跡級方法具有結構性優勢。

#### 與現有研究的比較

**1. 定位 (Positioning)**

SkillAdaptor 精準定位於「無需訓練的技能適配 (training-free skill adaptation)」這一研究分支，與以下技術路線形成對比：

| 技術路線 | 代表方法 | 與 SkillAdaptor 的差異 |
|---------|---------|---------------------|
| 記憶蒸餾 | A-Mem (Xu et al., 2025) | 從完整軌跡蒸餾，無步驟級歸因 |
| 工作流優化 | AWM (Wang et al., 2025) | 優化整體工作流而非單一技能 |
| 回顧式回饋 | Zhao et al. (2024) | 依賴會話級回饋 (session-level feedback) |
| 迭代式技能演化 | EvoSkill, Liu et al. (2026b) | 演化整個技能庫而非精準修訂 |

**2. 核心創新點**

相較於現有研究，SkillAdaptor 的三大創新在於：

**(a) 步驟級歸因機制**：現有方法多以整條軌跡的成功/失敗作為修訂信號，這在長時程任務 (long-horizon task) 中會引發嚴重的信用分配問題 (credit-assignment problem)。一個早期錯誤可能導致後續多步看似合理但實際無效的動作，軌跡級反思會將失敗責任擴散至所有步驟，導致錯誤導向的修訂 (misdirected revision)。

**(b) 精準技能修訂**：透過 Linker 輸出的加權可疑技能集合，方法僅修訂被歸因為有責任的技能，避免對無關技能造成負面影響。這與 EvoSkill 等整庫演化方法形成鮮明對比。

**(c) 明確的驗收機制**：Qualifier 階段的驗收檢查為技能更新提供了品質門檻，這在現有方法中較為少見，多數方法直接接受生成或修訂的技能。

**3. 局限性分析**

儘管方法設計精巧，仍存在以下局限：

- **依賴 LLM 判斷的可靠性**：Localizer 與 Linker 的準確性高度依賴骨幹模型的推理能力。對於較弱的模型，步驟級歸因可能反而引入噪訊
- **計算成本**：每個失敗軌跡需經過多個 LLM 呼叫（定位、連結、生成、修訂、審查），相較於簡單的軌跡級反思成本更高
- **技能庫膨脹問題**：雖然有驗收機制，但隨著迭代進行，技能庫仍可能累積冗餘技能，論文中未明確提及技能去重機制
- **領域泛化性**：實驗集中在網頁互動與代理任務，未涵蓋程式碼生成、工具使用等其他長時程場景
- **基準的新穎性**：PinchBench 與 Claw-Eval 為較新基準，社群採用率有限，跨基準的可比性需謹慎解讀

**4. 與 OpenClaw 類框架的整合**

方法設計為 OpenClaw 類代理框架 (OpenClaw-class agent harness) 的外掛元件 (plug-in component)，這種模組化設計降低了整合門檻，但也意味著其效能受底層框架的技能檢索與執行機制影響。

#### 未來研究方向

**1. 歸因機制的深化**

- **多步驟聯合歸因**：當前方法僅定位「首個可操作的錯誤步驟」，但失敗可能源於多個步驟的累積效應。發展多步驟聯合歸因模型可進一步提升修訂精準度
- **反事實推理 (Counterfactual Reasoning)**：引入「若步驟 t* 採取不同動作會如何」的推理機制，可為歸因提供更強的因果證據
- **跨軌跡歸因**：當多條失敗軌跡呈現相似模式時，進行跨軌跡的歸因聚合可提升歸因穩定性

**2. 技能庫管理**

- **技能去重與合併**：發展自動化的技能去重機制，防止技能庫膨脹
- **技能階層化**：將技能組織為階層結構，提升檢索效率與可解釋性
- **技能生命週期管理**：引入技能的新增、淘汰、版本控制機制

**3. 應用領域拓展**

- **程式碼生成與除錯**：將方法應用於程式碼任務，技能可對應為程式設計模式或除錯策略
- **多模態代理**：擴展至視覺-語言代理，技能可包含視覺處理策略
- **多代理協作**：在多代理系統中應用步驟級歸因，分析代理間的互動失敗

**4. 理論分析**

- **收斂性分析**：形式化分析迭代適配過程的收斂性質
- **泛化界 (Generalization Bound)**：建立技能庫大小與任務效能間的理論關係
- **歸因可信度度量**：發展量化歸因結果可信度的方法

**5. 與其他技術的結合**

- **與強化學習結合**：將步驟級歸因產生的信用分配信號用於強化學習的獎勵塑形 (reward shaping)
- **與過程獎勵模型 (Process Reward Model) 結合**：利用專門的過程獎勵模型提升歸因準確性
- **與神經符號方法結合**：將技能表示為可執行的程式碼，提升技能的可驗證性

**6. 評測基準發展**

- **歸因準確度基準**：建立專門評測步驟級歸因準確度的基準
- **技能品質基準**：發展自動化評估技能品質的指標
- **長時程任務基準**：構建更貼近真實應用的長時程代理任務

**7. 效率優化**

- **增量式歸因**：避免對每條失敗軌跡都進行完整的三階段處理
- **快取機制**：對相似的失敗模式建立歸因結果快取
- **輕量化模型**：使用較小的模型執行歸因，降低計算成本

這些研究方向不僅能深化 SkillAdaptor 本身的方法論，也能推動整個「無需訓練的代理改進」研究社群的發展，特別是在長時程任務的信用分配這一核心挑戰上取得突破。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文主要解決 LLM 代理在長時程任務中進行無需訓練的技能適配時所面臨的信用分配問題。現有的訓練免技能適配方法通常以整條軌跡或會話級回饋作為反思單位，導致失敗歸因過於粗糙。當一條失敗軌跡中可能只有少數步驟出錯，卻牽動後續許多正確決策時，這種粗粒度的歸因會讓修訂變得不穩定或過於廣泛。SkillAdaptor 正是為了回應這個瓶頸而提出。

**Q2：為什麼現有的軌跡級反思方法在長時程任務中容易失效？**
A：在長時程環境中，一條失敗軌跡往往夾雜著大量正確的中間決策，真正的失敗可能只源自少數早期的錯誤步驟。當更新主要由最終結果驅動時，失敗訊號會被擴散到無關的步驟與技能上，造成錯誤導向的修訂。這種信用分配問題在單一早期錯誤導致後續許多動作失效時尤其嚴重，使得整體技能維護變得脆弱。

**Q3：為什麼步驟級歸因對技能維護如此重要？**
A：步驟級歸因能精準定位到造成失敗的具體步驟與對應技能，使修訂範圍縮小到真正有缺陷的部分。這不僅避免了對無關技能的過度修改，也讓技能庫的演化過程更可審查、更穩定。論文的實驗結果也顯示，這種精細化的歸因比單純擴充技能庫或對整條軌跡進行反思更能帶來穩定的代理改進。

**Q4：SkillAdaptor 的核心方法是什麼？**
A：SkillAdaptor 採用三階段流程：歸因（Attribution）、修改（Modification）與驗收（Qualification）。在歸因階段，定位器（Localizer）從失敗軌跡中找出首個可歸責的錯誤步驟，連結器（Linker）則估計哪些檢索到的技能對該失敗負有最大責任。修改階段由生成器（Generator）與修訂器（Reviser）根據責任權重產生新技能或修訂既有技能，最後由資格審查器（Qualifier）進行明確的驗收檢查，僅接受通過檢查的更新。

**Q5：SkillAdaptor 相比於現有方法的主要創新點是什麼？**
A：最主要的創新在於將適配從軌跡級反思轉變為步驟級歸因，並透過定位器與連結器實現明確的失敗歸因。這使得技能更新具有針對性而非廣泛修訂，並在凍結骨幹模型的前提下，僅透過技能庫 K 的更新來提升代理表現。此外，該框架以模組化設計呈現，可作為外掛元件整合進 OpenClaw 類代理框架中。

**Q6：SkillAdaptor 在設計上有哪些重要的選擇？**
A：在檢索方面，系統使用 Qwen3-Embedding-8B 對任務與技能進行編碼，先以餘弦相似度取出 top-k 候選，再由骨幹 LLM 進行重排序以提升檢索品質。在迭代控制上，適配過程最多執行 10 輪，或當技能庫連續 3 輪未變化時提前停止，這有助於控制計算成本並避免過度擬合。整體設計強調凍結骨幹模型，僅更新技能庫，使方法保持訓練免的特性。

**Q7：實驗使用了哪些基準測試與模型？**
A：實驗涵蓋三個基準測試：WebShop（網頁購物互動）、PinchBench 與 Claw-Eval（涵蓋長時程工具使用與代理任務）。模型方面則評估了三個骨幹 LLM：Kimi-K2.5、GLM-5 與 GPT-5.2，以驗證方法的跨模型泛化能力。比較對象包括無技能基準、骨幹模型直接執行，以及多個技能適配基準如 OpenSpace、A-Mem、AWM、ExpeL 與 EvoSkill。

**Q8：主要的實驗結果為何？**
A：SkillAdaptor 在三個基準測試上均穩定超越所有無技能與技能適配基準。具體而言，在 PinchBench 平均分數提升 +1.5 點、Claw-Eval 平均分數提升 +1.8 點、WebShop 成功率提升 +1.7 點。這些改善在三個不同骨幹模型上皆一致，顯示步驟級歸因所帶來的效益並非依賴特定模型，而是源自方法本身的設計優勢。

**Q9：論文中是否有消融實驗驗證各元件的貢獻？**
A：根據論文中描述的框架結構，SkillAdaptor 的每個元件——定位器、連結器、生成器、修訂器與資格審查器——都承擔明確功能，因此消融實驗對於驗證各階段的必要性相當關鍵。論文中提及資格審查器透過明確的驗收檢查來決定是否接受更新，這意味著移除該元件可能導致不穩定的技能被納入庫中。雖然提供的全文片段未完整展示消融結果，但框架的模組化設計使各元件的單獨貢獻得以被獨立評估。

**Q10：SkillAdaptor 可以應用於哪些實際場景？**
A：任何需要 LLM 代理在長時程互動中持續改進、但又無法或不希望重新訓練模型的場景都適合採用，例如網頁自動化操作、電子商務任務、複雜工具鏈呼叫等。由於方法為訓練免且模組化，企業可在不更動底層模型 API 的前提下，僅透過技能庫的迭代來提升代理表現。對於需要可審查、可追溯改進過程的應用（如金融操作或合規流程），步驟級歸因所提供的可解釋性尤為重要。

**Q11：在實際產品部署中需要考慮哪些因素？**
A：部署時需考量步驟級分析的計算成本，因為每條失敗軌跡都需要經過定位、連結、生成與驗收等多個 LLM 呼叫，這對延遲敏感的場景可能形成瓶頸。此外，技能庫的儲存與版本管理、與既有代理框架（如 OpenClaw）的整合介面、以及如何處理技能之間的相互依賴，都是實務上必須處理的問題。對於多團隊協作的環境，技能庫的權限控管與審核流程也應一併納入設計考量。

**Q12：這項研究對 LLM 代理領域的影響是什麼？**
A：這項研究凸顯了信用分配在代理改進中的核心地位，提醒研究者不應僅專注於擴充技能庫或對整條軌跡進行反思。更重要的是，它提供了一個可即插即用的解決方案，能與現有代理框架無縫整合，降低實務採用的門檻。長期而言，這種強調精準歸因與可審查性的設計思路，可能成為未來訓練免代理改進方法的主流範式。

**Q13：這篇論文承認的限制有哪些？**
A：作為一個訓練免方法，SkillAdaptor 的表現上限受限於骨幹模型本身的能力，無法透過參數更新來突破模型固有的推理瓶頸。此外，方法的成效仰賴初始技能庫的品質，若初始化階段蒸餾出的技能本身有偏差，後續的歸因與修訂也可能繼承這些問題。對於多個技能以複雜方式相互影響的情境，目前的設計是否能妥善處理責任歸屬，仍有待更深入的分析。

**Q14：在什麼情況下 SkillAdaptor 可能會失敗？**
A：當定位器無法正確識別首個可歸責的錯誤步驟時，後續的連結與修訂都將建立在錯誤的前提之上，導致改進無效甚至惡化。同樣地，若連結器將責任誤歸到非關鍵技能，則修訂方向將偏離真正需要改進的部分。此外，若資格審查器的驗收標準過於嚴格，可能拒絕許多潛在有用的更新，使迭代過程停滯；若過於寬鬆，則可能引入不穩定的技能。

**Q15：未來的研究方向有哪些？**
A：未來可探索將步驟級歸因與其他適配方法（如記憶蒸餾或工作流優化）相結合，以發揮互補優勢。此外，將方法擴展至多模態代理、處理更大型技能庫的檢索效率、以及從理論層面分析歸因品質與最終表現之間的關係，都是值得深入的方向。另一個有趣的方向是研究如何在多代理協作環境中共享與遷移技能庫，使歸因與修訂的成果能跨任務、跨領域複用。

## 實務應用指南

### 適用場景

**1. 企業內部流程自動化代理的持續優化**
在客服、訂單處理、ERP 操作等長時程業務流程中，代理經常需要依賴一套固定的「技能庫」來完成多步驟任務（例如查詢訂單、修改地址、申請退款）。SkillAdaptor 的步驟級失敗歸因特別適合這類場景：當某個對話最終失敗時，系統能精準定位是哪一個動作（例如「未先驗證客戶身份就執行退款」）導致失敗，並只更新對應的技能條目，避免誤改其他正常運作的流程。

**2. 程式碼代理（Code Agent）的工具使用改進**
在 SWE-bench 類的程式修復任務中，代理常會在多輪工具呼叫後才發現錯誤。SkillAdaptor 可用於：(a) 識別代理第一次呼叫錯誤工具或讀錯檔案的步驟；(b) 將失敗歸因到「檔案定位技能」或「測試執行技能」；(c) 自動修訂技能的程序欄位（例如新增「先 ls 再 cat」的步驟）。這對企業內部程式碼助手特別有價值，因為技能庫可以隨著專案演進而自動更新。

**3. 網頁自動化代理（RPA + LLM）的穩定性提升**
對於需要操作瀏覽器完成任務的代理（如 WebShop、內部後台操作），UI 變動經常導致既有技能失效。SkillAdaptor 的步驟級歸因可以判斷是「點擊按鈕」失敗還是「表單填寫」失敗，並針對性更新對應技能的程序描述，而不會動到其他仍然有效的部分。這比傳統的「整個工作流重寫」更穩定。

**4. 多代理協作系統中的技能治理**
在多代理架構中，不同代理共享或交換技能庫。SkillAdaptor 的「驗收檢查（Qualifier）」機制可以作為技能品質的守門員：當某個代理提出的技能修訂在其他代理的測試軌跡上無法改善表現時，自動拒絕該修訂。這對需要嚴格控管技能品質的生產環境特別重要。

**5. 教育與訓練領域的代理行為審核**
在 AI 教學或訓練場景中，需要追蹤代理「為什麼在某一步犯了錯」。SkillAdaptor 提供的可審計性（auditable）正好符合需求：每個技能修訂都有明確的失敗步驟、可疑技能清單、修訂前後對比，方便教師或審查員理解代理行為演化過程。

### 實作前置條件

**資料需求**
- **任務分布 Q 的定義**：需要明確的任務描述格式（例如自然語言指令 + 環境互動介面），以及可重複執行的環境（WebShop、PinchBench、Claw-Eval，或自有的內部環境）。
- **初始成功軌跡集**：用於從零蒸餾初始技能庫 K₀。建議至少準備 50–200 條成功軌跡，覆蓋主要任務類型。
- **失敗軌跡收集機制**：需要能夠自動判定任務成功/失敗的 oracle（環境回傳的 reward 或自訂驗證函式）。
- **技能結構化欄位**：每個技能需包含 title、principle、applicability condition、procedure 等欄位，這些欄位需事先設計好 schema。

**計算資源需求**
- **骨幹 LLM API 存取**：需要可呼叫的 LLM 端點（論文中使用 Kimi-K2.5、GLM-5、GPT-5.2 等大型模型）。建議使用支援 function calling 與長上下文的模型。
- **嵌入模型**：論文中使用 Qwen3-Embedding-8B 進行技能檢索。若無此模型，可替換為同類語義嵌入模型（如 BGE、E5 系列）。
- **重排序推理算力**：最終的 Rerank 階段由骨幹 LLM 完成，需要支援長上下文的推理能力。
- **迭代預算**：每次迭代需要執行完整任務集並收集軌跡，建議預留 10 輪迭代的算力（論文設定上限 10 輪，或連續 3 輪無變化即停止）。

**技能與知識前置**
- **熟悉 LLM Agent 框架**：需要了解 ReAct、Reflexion、OpenClaw 等代理架構的基本概念。
- **具備軌跡分析能力**：能夠解析代理的動作-觀察序列，並設計 Localizer 的 prompt 來定位失敗步驟。
- **具備檢索增強生成（RAG）經驗**：技能檢索階段是典型的 RAG 流程，需要熟悉向量檢索 + 重排序的兩階段架構。
- **評估指標設計**：需要定義任務成功率、平均分數等量化指標，以便判斷技能修訂是否真的改善表現。

### 實作步驟建議

**步驟 1：建立任務環境與基準介面**
- 選定目標環境（WebShop、PinchBench、Claw-Eval 或自建環境）。
- 實作 `Run(q, K)` 函式：接收任務 q 與技能子集 K，回傳執行軌跡 τ 與成功標記 r。
- 確保環境可重置、可重現，並提供結構化的動作-觀察介面。

**步驟 2：設計技能資料結構**
- 定義技能的 schema：`{title, principle, applicability_condition, procedure}`。
- procedure 建議以步驟列表形式儲存（例如 `["step 1: ...", "step 2: ...", ...]`），方便後續針對性修訂。
- 建立技能庫的版本控制機制（git 或資料庫），以便追蹤每次修訂。

**步驟 3：實作技能初始化（Skill Initialization）**
- 在沒有任何技能的情況下，讓骨幹 LLM 執行任務集 Q。
- 收集成功軌跡，使用 LLM 蒸餾出初始技能 K₀。
- 建議每 5–10 條相似成功軌跡歸納出一條技能，避免技能庫過於細碎。

**步驟 4：實作技能注入（Skill Injection）**
- 使用嵌入模型 ϕ(·) 編碼任務描述 d_q 與所有技能。
- 取 top-k_ret 個候選技能（建議 k_ret = 5–10）。
- 由骨幹 LLM 進行 Rerank，選出最終注入到 prompt 的技能子集 S_q。
- 將 S_q 注入到代理的 system prompt 或 context 中。

**步驟 5：實作歸因模組（Attribution）**
- **Localizer**：設計 prompt，讓 LLM 根據 (q, τ, S_q) 輸出 `(t*, π)`，其中 t* 是首個可歸責的失敗步驟，π 是觀察到的失敗行為與改進建議。
- **Linker**：設計 prompt，讓 LLM 根據 (q, τ, t*, S_q) 輸出可疑技能的加權集合 `{(s_j, w_j)}` 與適配動作 `â ∈ {REVISE, GENERATE}`。
- 建議加入 chain-of-thought 提示，提高歸因準確度。

**步驟 6：實作修訂模組（Modification）**
- **Generator**：當 `â = GENERATE` 時，根據失敗描述生成全新技能。
- **Reviser**：當 `â = REVISE` 時，僅修改可疑技能中權重最高的 1–2 條，保留其他技能不變。
- 修訂時保留「修訂歷史」，方便後續審計與回滾。

**步驟 7：實作驗收模組（Qualification）**
- 設計 acceptance check：在驗證集上測試修訂後的技能庫是否真的改善表現。
- 若新技能在驗證軌跡上無法提升成功率，則拒絕該修訂並保留舊版本。
- 建議使用與訓練集不同的 held-out 驗證集，避免過擬合。

**步驟 8：迭代與收斂**
- 重複步驟 4–7，最多 10 輪，或直到技能庫連續 3 輪無變化。
- 凍結最終的 K*，作為生產環境使用的技能庫。
- 持續監控：部署後仍應定期收集失敗軌跡，觸發新一輪適配。

**步驟 9：評估與上線**
- 在 WebShop、PinchBench、Claw-Eval 或自有測試集上比較 SkillAdaptor 與無技能基準、OpenSpace、A-Mem、AWM、ExpeL、EvoSkill 等基線。
- 論文報告的典型增益：WebShop 成功率 +1.7、PinchBench Avg Score% +1.5、Claw-Eval Avg Score +1.8。
- 灰度上線：先在小流量驗證穩定性，再全面部署。

### 潛在風險與注意事項

**風險 1：歸因錯誤導致技能被誤改**
Localizer 可能將失敗歸因到錯誤的步驟（例如將 UI 渲染延遲誤判為邏輯錯誤），進而修訂不相關的技能。
**緩解**：在 Qualifier 階段加入嚴格驗證；若修訂後驗證集表現下降，自動回滾；保留人工審核介面。

**風險 2：技能庫膨脹與檢索成本**
隨著迭代進行，技能數量可能快速增長，導致檢索延遲與 token 成本上升。
**緩解**：定期合併相似技能、淘汰低使用率的技能、設定技能數量上限（例如 ≤ 100 條）。

**風險 3：過擬合到特定任務分布**
技能庫可能過度擬合到訓練任務分布，在新任務類型上表現下降。
**緩解**：保留多樣化的驗證集、定期在 out-of-distribution 任務上測試、避免過度細化的技能。

**風險 4：骨幹 LLM 變動導致技能失效**
若企業更換底層 LLM（例如從 GPT-5.2 換到下一代模型），既有技能可能不再適用。
**緩解**：設計技能時使用模型無關的描述、準備 LLM 切換時的技能重審流程。

**風險 5：失敗軌跡的隱私與合規問題**
失敗軌跡可能包含敏感資訊（用戶輸入、內部資料），用於技能適配時需注意合規。
**緩解**：對軌跡進行脫敏處理、限制技能適配的資料存取權限、遵守資料保留政策。

**風險 6：迭代成本不可控**
每輪迭代需要執行完整任務集，若任務集很大則成本高昂。
**緩解**：使用較小的子集進行快速迭代、只在驗證集上做完整評估、實作早停機制。

### 與其他技術的整合建議

**與 RAG 系統整合**
SkillAdaptor 的技能檢索階段本質上是 RAG。建議將技能庫接入企業既有的向量資料庫（如 Milvus、Qdrant、Weaviate），並使用統一的嵌入服務。技能本身可作為一種特殊的「文件」，與其他知識庫條目共存。

**與 Agent 框架整合**
SkillAdaptor 設計為 OpenClaw 類代理框架的外掛元件。整合時應：
- 在代理執行後插入「軌跡收集 → 技能適配」的 pipeline；
- 將技能庫暴露為代理可呼叫的 context 注入介面；
- 提供標準化的技能 schema，方便不同代理共享技能。

**與監控與可觀測性系統整合**
- 將每次技能修訂記錄到審計日誌（包含失敗步驟、可疑技能、修訂前後對比）；
- 整合到 Prometheus/Grafana 等監控系統，追蹤技能庫大小、迭代次數、成功率變化；
- 設定告警：當技能庫連續多輪無改善或表現下降時通知工程師。

**與 CI/CD 流程整合**
- 將技能適配流程納入 CI：每次骨幹 LLM 更新或環境變動時，自動觸發技能重審；
- 使用 A/B 測試框架比較新舊技能庫的表現；
- 自動化回滾機制：當新技能庫表現低於閾值時自動切回舊版本。

**與人類回饋（RLHF / RLAIF）整合**
- 將人類審核員對技能修訂的接受/拒絕作為額外信號；
- 可進一步訓練一個獎勵模型來預測技能修訂的品質，輔助 Qualifier 決策；
- 結合線上 A/B 測試的人類偏好資料，持續優化歸因與修訂策略。

**與其他記憶蒸餾方法整合**
SkillAdaptor 與 A-Mem、AWM、ExpeL、EvoSkill 等方法並非互斥。可設計混合策略：
- 使用 A-Mem 做短期記憶、SkillAdaptor 做長期技能演化；
- 使用 ExpeL 做經驗儲存、SkillAdaptor 做步驟級技能精煉；
- 透過統一的技能抽象層讓不同來源的技能共存。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）了解「為什麼需要步驟級歸因」，再跳到第 3 節（Method）的整體框架圖（Figure 1）建立直觀印象。核心概念只有三個：技能庫（K）、失敗軌跡（τ）、步驟級歸因（Localizer + Linker）。理解「為什麼軌跡級反思會失敗」比理解具體演算法更重要。可以先在 WebShop 環境上跑通最小範例，再深入細節。

**給 AI 工程師**：重點閱讀第 3 節的 Skill Injection 與 Skill Adaptation 細節，特別是 Localizer、Linker、Generator、Reviser、Qualifier 五個模組的 prompt 設計與互動流程。實作時建議先復現 WebShop 上的結果（論文報告 +1.7 成功率），再遷移到自有環境。注意嵌入模型的選擇（Qwen3-Embedding-8B）與重排序策略對最終表現影響顯著。建議將技能庫設計為可熱更新的外部儲存，方便迭代。

**給研究者**：本文的核心貢獻在於將「信用分配問題（credit-assignment problem）」從強化學習領域引入到 LLM 代理的技能適配中。建議從這個視角出發，比較 SkillAdaptor 與既有方法（如 ExpeL、EvoSkill）在歸因粒度上的差異。可進一步探索的方向：(1) 將步驟級歸因擴展到多代理協作場景；(2) 結合成績預測模型自動化 Qualifier；(3) 理論分析步驟級歸因的收斂性與樣本複雜度。論文的限制（僅在 3 個基準、3 個模型上評估）也是值得延伸的方向。

**給產品經理**：SkillAdaptor 解決的核心問題是「如何讓 LLM 代理在生產環境中持續變好，而不需要重新訓練模型」。這對產品決策的意義在於：(1) 可以在不依賴模型供應商的情況下累積領域專屬技能；(2) 失敗案例會自動轉化為技能改進，形成正向循環；(3) 步驟級歸因讓技能演化可審計、可回滾，降低生產風險。建議在產品 roadmap 中將「技能庫管理」視為一級功能，並評估其對客服、運營、研發等場景的 ROI。論文中 +1.5 到 +1.8 的指標提升在生產環境中可能對應顯著的營收或成本改善。
