# GORGO：跨區域網路感知大型語言模型服務的線上調校

## ⚡ TL;DR

現有跨區域LLM負載平衡策略忽略網路延遲與整體成本，導致副本負載與快取不均。
提出GORGO代理，以可調權重整合網路延遲、預填充與排隊成本，並用演化策略線上調校。
GORGO較基線降低p95首Token時間6.9–15.5%、端對端延遲14.3–30.9%。

## 摘要翻譯

越來越多大型語言模型推論服務（LLM inference services）會將用戶端請求（client requests）代理轉送至分佈於全球地（globally）的引擎副本（engine replicas）。負載平衡策略（load-balancing policies）在針對延遲（latency）與首 Token 時間（Time-to-first-token, TTFT）等指標進行直接最佳化（directly optimize）時，必須同時考量 KV 快取局部性（KV-cache locality）、副本負載（replica load）與變動網路延遲（variable network latency）等因素。然而，現有系統僅在其成本模型（cost model）中評估這些因素的一部分，導致負載與 KV 快取（KV-cache）在副本間出現不平衡分佈（unbalanced distributions）。我們提出 GORGO，一種透過可調參數（tunable parameters）整體納入因素（holistically factors）網路延遲（network latency）、預填充成本（prefill cost）與排隊延遲（queueing delay）的代理架構（proxy architecture）。由於 LMSYS-Chat1M 與 WildChat-4.8M 等開源對話資料集（open-source chat datasets）缺乏長上下文（long-context）、高前綴重用（high prefix-reuse）的資料，我們根據長上下文生產環境中繼資料（production metadata）建構並釋出合成資料集（synthetic dataset）ART-Chat-2.5M。在取自 ART-Chat-2.5M 的調校區間（tuning window）中，演化策略（Evolutionary strategies, ES）引導 GORGO 路由策略（GORGO policy）的參數值（parameter values），直接最佳化第 95 百分位數首 Token 時間（p95 TTFT）。在保留的評估區間（held-out evaluation windows）中，我們固定從調校學得的參數值，相較於簡單會話親和性（simple session affinity）與前綴快取（prefix-cache）等基線負載平衡策略（baseline load-balancing policies），將 p95 TTFT 降低 6.9–15.5%，並將 p95 端對端（end-to-end, E2E）延遲降低 14.3–30.9%。程式碼與 ART-Chat-2.5M 資料集可於 https://github.com/Arcadia-Research-Team/GORGO 取得。

### 核心貢獻（3～5點）
- 提出 GORGO 代理架構（proxy architecture），透過可調參數（tunable parameters）整體納入網路延遲、預填充成本與排隊延遲，以改善跨區域 LLM 服務的路由決策。
- 釋出合成資料集 ART-Chat-2.5M，填補現有開源對話資料集在長上下文與高前綴重用情境上的不足。
- 設計以演化策略（Evolutionary strategies, ES）為基礎的線上調校機制，直接針對第 95 百分位數首 Token 時間（p95 TTFT）進行最佳化。
- 在保留評估區間中相較於簡單會話親和性與前綴快取等基線策略，顯著降低 p95 TTFT（6.9–15.5%）與 p95 端對端延遲（14.3–30.9%）。

### 適合對象
本論文適合從事大型語言模型服務系統（LLM serving systems）、分散式推論架構、雲端負載平衡、KV 快取與前綴快取（prefix caching）最佳化，以及跨區域網路感知（network-aware）系統設計的研究人員與系統工程師閱讀。對於關注真實用戶工作負載（real user workloads）下延遲與 TTFT 最佳化的實務部署者亦具高度參考價值。

## 深度分析

#### 方法論解析

本研究提出的 **GORGO** 是一個專為**跨區域（Cross-Region）** LLM 推論服務設計的 **Proxy（代理）** 架構，核心目標是將影響 **TTFT（Time-to-First-Token，首 Token 時間）** 的三項主要成本——**network latency（網路延遲）**、**prefill cost（預填充成本）** 與 **queueing delay（排隊延遲）**——整合進單一可調校的成本模型中，並透過 **evolutionary strategies（ES，演化策略）** 在真實工作負載上進行 **online tuning（線上調校）**。

##### 1. TTFT 成本模型的數學化

論文首先將單一副本上的 TTFT 拆解為三項：

\[
\text{TTFT} = T_{\text{network}}(i) + T_{\text{queue}}(i) + T_{\text{prefill}}(x_r \setminus c_i)
\]

其中：

- \(T_{\text{network}}\) 為 **RTT（Round Trip Time，往返時間）**，即 **client（用戶端）** 到 **engine replica（引擎副本）** 的來回網路延遲。
- \(T_{\text{queue}}\) 為排隊延遲，反映請求到達時前面尚有多少 **in-flight requests（飛行中請求）**。
- \(T_{\text{prefill}}\) 為實際需要計算的預填充成本，取決於輸入序列 \(x_r\) 與副本 \(i\) 上已快取前綴 \(c_i\) 的差集；透過 **prefix caching（前綴快取）**，可將已計算過的 KV 直接重用，顯著降低 TTFT。

在跨區域部署中，這三項成本存在量綱與時間尺度上的巨大差異：RTT 可能從 10 ms 到 1 s 不等，prefill 成本取決於 token 數與快取命中與否，queueing delay 則受 **continuous batching（連續批次處理）** 與 **KV-cache budget（KV 快取預算）** 影響。因此，論文將其擴展為帶權重的可調模型：

\[
\text{TTFT} = W_{\text{rtt}} \cdot T_{\text{network}}(\text{RTT}_i) + W_{\text{queue}} \cdot T_{\text{queue}}\left(i, \sum_{j=1}^{n_r} x_j\right) + T_{\text{prefill}}(x_r \setminus c_i)
\]

此處 \(W_{\text{rtt}}\) 與 \(W_{\text{queue}}\) 為可調參數，而 \(W_{\text{prefill}}\) 固定為 1。固定 prefill 權重的設計具有重要意義：由於 GORGO 的決策本質上是比較不同副本間的相對成本，因此真正影響路由的是權重之間的「比例」而非絕對數值。這樣的參數化讓網路延遲、排隊長度與預填充成本這三種不同單位的量，能夠被正規化到同一個可比較的尺度上。

值得注意的是，\(T_{\text{queue}}\) 在實作上並非直接讀取引擎內部的真實佇列長度，而是使用 **proxy（代理）** 端可觀測的指標：即該副本上「尚未收到完成事件」的所有請求 token 總數。這是一個在分散式系統中極具實務意義的設計，因為直接從引擎取得即時佇列狀態會有時間延遲與通訊開銷，而 proxy 端記錄的未完成請求 token 數則是一個可即時取得、且與真實排隊壓力高度相關的代理變數。

##### 2. GORGO Proxy 的路由決策

GORGO **Proxy（代理）** 的路由邏輯非常直接：對於每個進入的請求，計算其在所有可用副本上的加權 TTFT 成本，並將請求導向成本最低的副本。這使得策略能夠同時考慮：

- 哪個副本擁有較完整的 **KV-cache locality（KV 快取局部性）**（降低 prefill 成本）；
- 哪個副本距離較近、RTT 較低（降低網路延遲）；
- 哪個副本目前負載較輕（降低 queueing delay）。

與傳統的 **session affinity（會話親和性）** 或 **prefix reuse（前綴重用）** 策略相比，GORGO 不會盲目地將同一會話或相同前綴的請求全部綁定到單一副本；當該副本因 **bursty workloads（突發性工作負載）** 而趨近飽和時，GORGO 可以主動將部分請求轉發到網路稍遠但負載較輕的副本，從而避免 **head-of-line（HOL，隊頭阻塞）** 排隊延遲。

##### 3. 線上調校：\((1+1)\) Evolutionary Strategy（演化策略）

GORGO 使用簡單但有效的 \((1+1)\) **evolutionary strategy（ES，演化策略）** 來調校 \(W_{\text{rtt}}\) 與 \(W_{\text{queue}}\)。具體流程如下：

1. 在 **tuning window（調校區間）** 內，對當前權重 \(x_{t,k}\) 進行對數空間下的隨機擾動：

\[
x'_k = \text{clip}\left(\exp\left(\ln(x_{t,k}) + \sigma_t \cdot z_k\right), [lo_k, hi_k]\right)
\]

其中 \(z_k \sim \mathcal{N}(0,1)\)，\(\sigma_t\) 為步長，\([lo_k, hi_k]\) 為每個權重的上下界。

2. 使用擾動後的權重進行路由，並在該調校區間結束後評估 **p95 TTFT（第 95 百分位數首 Token 時間）**。
3. 若子代權重優於父代，則更新為新的 incumbent；同時根據 **Rechenberg’s 1/5 success rule** 調整 \(\sigma_t\)，維持約五分之一的接受率，以平衡探索與收斂。

選擇對數空間進行擾動是關鍵設計：由於權重必須為正數，且不同數量級的權重可能對應截然不同的路由行為（例如極高的 \(W_{\text{rtt}}\) 會使策略幾乎變成最近副本路由），對數空間能讓搜尋在數量級層面上均勻探索，避免線性尺度下小數值區域被過度採樣。

將目標函數直接設為 p95 TTFT 也體現了研究的實務導向：對於互動式 LLM 服務而言，**perceived latency（感知延遲）** 的尾部表現往往比平均值更重要，因為少數高延遲請求會顯著影響使用者體驗。

#### 實驗數據解讀

論文的實驗設計圍繞三個核心問題展開：(1) 現有開源資料集是否足以評估快取感知路由策略？(2) GORGO 在長上下文、高前綴重用的真實工作負載上能帶來多少改善？(3) 這些改善是否伴隨可量化的權衡？

##### 1. 資料集特性與動機

論文比較了三個資料集：

| 資料集 | 平均輸入 token 數 | 用戶內前綴重用 | 全域前綱重用 |
|---|---|---|---|
| LMSYS-Chat-1M | 467 | — | 3.4% |
| WildChat-4.8M | 2,925 | 4.7% | 32.5% |
| **ART-Chat-2.5M** | **17,964** | **89.4%** | **89.7%** |

現有開源資料集如 LMSYS-Chat-1M 與 WildChat-4.8M 雖然規模龐大，但缺乏兩個關鍵特性：**long-context（長上下文）** 提示與高 **prefix reuse（前綴重用）** 的多輪對話。在短上下文、低前綱重用的情況下，**prefix-cache（前綴快取）** 策略相較於 **random（隨機）** 或 **least-load（最小負載）** 幾乎沒有可測量的優勢，這使得現有基準難以區分先進路由策略的價值。

為此，作者釋出 **ART-Chat-2.5M**，這是從生產環境一週的 **production metadata（生產環境中繼資料）** 合成而來的 **LLM traffic trace（LLM 流量軌跡）**，採用 **Mooncake FAST'25 format**。該資料集保留了原始工作負載的前綱重用結構，並包含 **per-request timestamps（每筆請求時間戳）**，可透過線性縮放時間間隔來模擬不同程度的 **saturation profiles（飽和輪廓）**。這對於在受控環境中研究 **compute-constrained regimes（運算受限情境）** 至關重要。

##### 2. 主要效能結果

在保留的 **held-out evaluation windows（保留評估區間）** 中，GORGO 相較於 **simple session affinity（簡單會話親和性）** 與 **prefix-cache（前綱快取）** 等基線策略，達成：

- **p95 TTFT 降低 6.9%–15.5%**
- **p95 end-to-end（E2E）latency（端對端延遲）降低 14.3%–30.9%**

這兩項改善同時出現具有重要意義。傳統上，優化 TTFT 與優化 E2E latency 可能存在衝突：若將過多請求集中到少數「較熱」的副本以最大化 KV-cache 命中，雖然單次請求的 prefill 時間會下降，但整體負載不平衡會導致 **decode memory contention（解碼記憶體競爭）** 加劇，反而使 E2E latency 惡化。GORGO 透過同時納入 queueing delay 與 network latency，避免了過度集中，因此能同時改善尾部 TTFT 與 E2E latency。

##### 3. 連續批次處理下的行為特徵

論文進一步指出，在 **continuous batching（連續批次處理）** 的運作模式下，單純追求 KV-cache 命中的策略可能會被「次優化」：當一個副本已經在執行大量 decode 工作時，即使新請求能命中快取，加入該批次仍可能因記憶體與計算資源競爭而延遲。GORGO 透過 proxy 端記錄的未完成請求 token 數來間接估計這種壓力，從而避免將請求導向已經過熱的副本。這說明了「以 proxy 可觀測指標為條件」的成本模型，對於緩解 continuous batching 帶來的負面效應具有實質幫助。

##### 4. 結果的解釋空間

儘管數據亮眼，仍需注意幾點：

- 改善幅度（6.9%–15.5%）雖顯著，但高度依賴工作負載特性。在 ART-Chat-2.5M 這種長上下文、高前綱重用的場景下，prefill 成本佔 TTFT 很大比例，因此快取感知與負載平衡結合的策略價值較高。若應用於短上下文、低重用的 API 呼叫型工作負載，改善可能較小。
- 實驗中的「保留評估區間」與「調校區間」來自同一資料集，雖然時間上切分，但分佈相似。這驗證了策略在穩定工作負載下的泛化能力，但對於分佈劇烈漂移的真實線上環境，仍需額外驗證。

#### 與現有研究的比較

##### 1. 相較於傳統負載平衡策略

現有 **load-balancing policies（負載平衡策略）** 大致可分為三類：

1. **Least-load（最小負載）**：僅考慮副本負載，忽略 KV-cache 局部性與網路延遲。
2. **Session affinity（會話親和性）**：透過 **consistent hashing（一致性雜湊）** 等方式維持會話與副本的綁定，提升快取命中，但無法處理副本飽和或跨區域網路差異。
3. **Prefix reuse / Prefix-cache（前綱重用 / 前綱快取）**：將相同前綱導向同一副本，最大化 KV-cache reuse，但同樣未考慮 network latency 與 queueing delay。

GORGO 的貢獻在於將這三類策略關注的單一因素整合進統一框架，並透過可調權重與線上調校自動找到適合當前工作負載的平衡點。這使得 GORGO 在計算資源緊張時，能夠動態犧牲部分快取命中率以換取更低的排隊與網路延遲。

##### 2. 相較於 Mooncake 等分散式推論系統

Mooncake（FAST'25）同樣強調 KV-cache 的全局管理與 prefix caching，但其論文主要聚焦於引擎層級的記憶體池化與預填充—解碼分離。GORGO 則專注於 **Proxy（代理）** 層的路由決策，並且特別針對 **cross-region（跨區域）** 場景中的 **heterogeneous network latency（異質網路延遲）**。兩者可視為互補：Mooncake 提供強大的引擎層快取能力，而 GORGO 決定請求應該被送往哪個區域的哪個副本，以最大化這些快取的效益。

##### 3. 相較於其他線上調校或學習型排程

現有許多學習型排程系統使用強化學習（RL）或貝葉斯最佳化來調整叢集層級資源配置。GORGO 選擇 \((1+1)\) ES 而非更複雜的 RL，具有幾項優勢：

- **實作簡單**：不需要維護複雜的狀態空間、獎勵塑形或策略網路。
- **樣本效率高**：每個調校區間只需評估單一權重組合，適合線上環境中快速迭代。
- **可解釋性強**：權重直接對應 network、queue、prefill 三項成本的相對重要性。

然而，這也帶來限制：ES 本質上是一種局部搜尋，若目標函數存在多個局部極值，可能無法找到全局最佳解；此外，目前僅調校兩個權重，未探索更複雜的決策邊界（例如非線性組合、動態門檻、或依請求類型切換策略）。

##### 4. 主要限制

- **成本模型的近似性**：\(T_{\text{queue}}\) 使用 proxy 端未完成的 token 數作為代理指標，雖然實務可行，但並非引擎內部真實的佇列長度或批次狀態。在極端 **bursty workloads（突發性工作負載）** 下，proxy 觀測可能滯後於實際引擎狀態。
- **單一目標函數**：目前僅以 p95 TTFT 為目標進行調校，雖然論文觀察到 E2E latency 也隨之改善，但這並非被直接最佳化。對於某些應用（如長文生成服務），可能需要在 TTFT 與 E2E latency 之間進行顯式權衡。
- **資料集的代表性**：ART-Chat-2.5M 雖基於生產 metadata，但經過合成處理，且來自特定應用場景（長上下文、高前綱重用）。其在其他領域（如程式碼助手、多模態對話）的適用性仍需驗證。
- **未考慮故障與彈性**：論文未討論副本故障、網路分區或動態擴縮容情境下的策略行為，這些都是實際跨區域部署中不可忽視的議題。

#### 可重現性評估

##### 1. 開源釋出

論文明確表示 **code（程式碼）** 與 **ART-Chat-2.5M dataset（資料集）** 已釋出於：

> https://github.com/Arcadia-Research-Team/GORGO

這對於可重現性是一大加分。研究者可以直接下載資料集、重現路由策略，並在相同或不同的工作負載上進行比較。

##### 2. 資料集格式與可用性

ART-Chat-2.5M 採用 **Mooncake FAST'25 format**，包含：

- **Per-request timestamps（每筆請求時間戳）**
- 請求 metadata
- 合成產生的 chat completion 資料

由於具備時間戳，研究者可以線性縮放請求間隔，模擬從低負載到高 **saturation（飽和）** 的各種情境。這種設計大幅提升了實驗的可重複性與可擴展性，因為不需要存取真實生產環境即可重現類似的負載輪廓。

##### 3. 模型權重與訓練需求

GORGO 並非一個深度學習模型，而是一套路由策略與調校機制，因此不存在傳統意義上的 **model weights（模型權重）**。重現所需的主要元件包括：

- GORGO Proxy 的實作
- 基線路由策略（session affinity、prefix-cache、least-load 等）
- \((1+1)\) ES 調校器
- 與 **inference engines（推論引擎）**（如 **vLLM** 或 **SGLang**）的整合介面

若程式碼完整釋出上述元件，則重現門檻相對較低；反之，若僅釋出資料集與部分腳本，則其他研究者仍需自行實作 proxy 與引擎互動邏輯。

##### 4. 潛在重現挑戰

- **跨區域測試床**：真實的跨區域網路延遲難以在單一資料中心內精確模擬。論文可能使用模擬或部分真實部署，重現時需要額外的網路拓撲配置。
- **引擎版本差異**：不同版本的 vLLM 或 SGLang 在 prefix caching、continuous batching 與 KV-cache 管理上的行為可能不同，可能影響重現結果。
- **隨機性與調校過程**：ES 調校具有隨機性，不同種子或調校區間長度可能導致學到的權重略有差異，論文應提供建議的超參數與種子設定以提升可重現性。

#### 未來研究方向

基於 GORGO 的貢獻與限制，以下幾個方向值得進一步探索：

##### 1. 多目標線上調校

目前 GORGO 僅以 p95 TTFT 為單一目標。未來可將 **multi-objective optimization（多目標最佳化）** 引入，例如同時最佳化 p95 TTFT、p95 E2E latency、**KV-cache hit rate（KV 快取命中率）** 與 **request concentration（請求集中度）**。透過 Pareto frontier（帕雷托前沿）分析，營運者可以根據服務等級目標（SLO）選擇最適合的權重組合。

##### 2. 非穩態工作負載下的自適應調校

真實線上工作負載通常具有日週期性、突發事件與趨勢漂移。未來可研究如何讓 GORGO 在 **non-stationary workloads（非穩態工作負載）** 下持續適應，例如引入遺忘機制、滑動調校區間、或結合線上學習來偵測分佈漂移並自動重新觸發調校。

##### 3. 更精細的引擎狀態感知

目前 \(T_{\text{queue}}\) 僅使用 proxy 端可觀測的未完成 token 數。未來可探索與推論引擎更深度的整合，例如取得即時批次狀態、KV-cache 剩餘容量、或預估 prefill 時間，以建立更準確的成本模型。這可能需要在 proxy 與引擎之間定義新的控制平面協定。

##### 4. 與預填充—解碼分離架構的結合

將 GORGO 與 Mooncake 等 **prefill-decode disaggregation（預填充—解碼分離）** 架構結合，可能進一步釋放潛力。在此情境下，路由決策不僅要選擇副本，還要決定 prefill 與 decode 階段分別由哪些節點執行，成本模型將變得更加複雜但也更具彈性。

##### 5. 異質硬體與成本感知路由

跨區域部署中，不同區域的硬體成本、能源價格與碳足跡可能差異甚大。未來可在成本模型中加入 **cost-aware（成本感知）** 與 **energy-aware（能源感知）** 項，使 GORGO 不僅優化延遲，也能在成本與永續性之間取得平衡。

##### 6. 理論分析與最適性保證

目前 GORGO 的效能主要透過實驗驗證。未來可針對其成本模型與 ES 調校進行理論分析，例如證明在某些簡化假設下（如穩態泊松到達、指數服務時間）策略的競爭比或收斂性，為實務應用提供更強的保證。

##### 7. 容錯與動態拓撲

真實跨區域服務必須面對副本故障、網路分區與自動擴縮容。未來可研究 GORGO 在這些動態拓撲變化下的行為，並設計相應的容錯機制，例如快速偵測失效副本、優雅降級、或與 **service mesh（服務網格）** 整合。

##### 8. 推廣至多模態與推論鏈路

隨著多模態 LLM 與 **agentic workflows（代理式工作流）** 興起，請求可能涉及圖片、音訊或跨多次 API 呼叫的推理鏈路。將 GORGO 的成本模型推廣到這些更複雜的請求類型，將是極具應用價值的方向。

## 論文問答

**Q1：GORGO 主要想解決什麼問題？**

A：GORGO 針對的是跨區域部署的大型語言模型推論服務中，如何將用戶端請求（client requests）有效率地路由到全球分佈的引擎副本（engine replicas）。在這種情境下，首 Token 時間（TTFT）深受網路延遲（network latency）、預填充成本（prefill cost）與排隊延遲（queueing delay）三者共同影響。然而，現有負載平衡策略往往只考慮其中一或兩項因素，導致無法同時兼顧 KV 快取命中率與整體延遲表現。

**Q2：現有的負載平衡策略為什麼在跨區域場景中表現不佳？**

A：現有基線策略如最小負載（least-load）、會話親和性（session affinity）與前綴重用（prefix reuse）通常只關注副本負載（replica load）或 KV 快取命中率（KV-cache hit rate），卻忽略了跨區域網路延遲可能高達數百毫秒甚至 1 秒。當高親和性的副本在運算受限情境（compute-constrained regimes）下被突發性工作負載（bursty workloads）灌爆時，會產生嚴重的隊頭阻塞排隊延遲（HOL queueing delays），反而抵消前綴快取帶來的好處。因此，單一因素的優化無法在真實世界的不均衡網路與負載條件中維持穩定的低延遲。

**Q3：為什麼同時考慮網路延遲、預填充成本與排隊延遲對 LLM 服務系統很重要？**

A：使用者感知延遲（perceived latency）主要由 TTFT 決定，而 TTFT 在單一副本上就是由網路往返時間、預填充計算與佇列等待三者組成。隨著上下文視窗（context windows）變長，前綴快取（prefix caching）能顯著降低預填充時間，但若副本選擇不當，節省的計算成本會被高 RTT 或長佇列吃掉。尤其在跨區域部署中，網路延遲的異質性（heterogeneous network latency）極大，只有整體納入（holistically factors）這三項成本，才能在最大化 KV 快取重用的同時避免負載飽和。

**Q4：GORGO 的核心方法是什麼？**

A：GORGO 是一個代理架構（proxy architecture），它為每個請求計算一個綜合成本，並將請求導向成本最低的引擎副本。此成本模型將 RTT、佇列中未完成的請求 token 數，以及未命中 KV 快取的前綴 token 數加權組合，並透過可調參數（tunable parameters）\(W_{rtt}\) 與 \(W_{queue}\) 來正規化不同測量單位。接著，GORGO 使用 (1+1) 演化策略（evolutionary strategies）在真實工作負載上線上調校（online tuning）這些權重，以直接最佳化 p95 TTFT。

**Q5：相較於既有研究，GORGO 的關鍵創新在哪裡？**

A：GORGO 的關鍵創新在於把網路延遲、預填充成本與排隊延遲整合進單一可調校的成本模型，並且透過線上演化策略持續依據真實用戶工作負載進行最佳化。不同於僅在離線環境中設計啟發式規則的做法，GORGO 讓代理能根據當下流量特性自動學出最適權重。此外，它透過代理端記錄的副本負載來緩解連續批次處理（continuous batching）對 TTFT 造成的干擾，這在現實推論引擎中特別重要。

**Q6：GORGO 在設計上有哪些值得注意的選擇？**

A：首先，GORGO 將預填充項的權重固定為 1，因為路由決策只取決於各項成本的相對比例，這樣可以減少需要調校的參數數量。其次，它採用對數空間中的乘法擾動來更新權重，並使用 Rechenberg 的 1/5 成功規則動態調整步長，使演化策略能穩定收斂。最後，由於從副本取得即時佇列資訊有時間延遲，GORGO 選擇以代理端觀察到的飛行中請求（in-flight requests）總 token 數作為排隊延遲的代理指標，這在實作上更可行。

**Q7：論文使用了哪些資料集與評估方式？**

A：論文釋出了 ART-Chat-2.5M，這是從生產環境中繼資料（production metadata）合成而來的長上下文、多輪對話資料集，平均輸入長度達 17,964 個 token，全域前綴重用率（global prefix reuse）高達 89.7%。相較之下，LMSYS-Chat1M 與 WildChat-4.8M 等開源對話資料集缺乏長上下文與高前綴重用的特性，難以有效評估快取感知策略。ART-Chat-2.5M 採用 Mooncake FAST'25 格式，包含每筆請求時間戳（per-request timestamps），可線性縮放以模擬不同程度的副本飽和輪廓（saturation profiles）。

**Q8：GORGO 在實驗中取得了哪些關鍵結果？**

A：在保留評估區間（held-out evaluation windows）中，GORGO 相較於簡單會話親和性（simple session affinity）與前綴快取（prefix-cache）等基線負載平衡策略（baseline load-balancing policies），將 p95 TTFT 降低了 6.9% 至 15.5%。同時，p95 端對端延遲（p95 end-to-end latency）也改善了 14.3% 至 30.9%。這顯示同時考量網路、預填充與排隊成本，能夠在真實長上下文工作負載中同時提升首 token 與完整回應的延遲表現。

**Q9：實驗中揭示了哪些權衡與消融觀察？**

A：實驗發現，演化策略驅動的爬山調校器（ES-driven hillclimb tuner）傾向利用距離代理較近且 KV 快取較完整的較熱副本（warmer replicas），這能顯著降低 TTFT，但過度集中請求（request concentration）會使端對端延遲惡化。因此，GORGO 也刻畫了請求集中度與 TTFT 之間的權衡，讓營運者能依據服務層級目標選擇適當的調校方向。此外，透過在成本模型中納入代理端記錄的副本負載，可以有效減緩連續批次處理造成的隊頭阻塞，進一步在多項延遲指標上獲得改善。

**Q10：在哪些實際場景下應該優先考慮使用 GORGO？**

A：當 LLM 推論服務採用跨區域（cross-region）部署且不同區域間 RTT 差異顯著時，GORGO 的網路感知設計特別有價值。此外，若應用以長上下文（long-context）與多輪對話（multi-turn conversation）為主，並且存在高前綴重用（high prefix-reuse），前綴快取的效益會被放大，此時需要 GORGO 來平衡快取命中與負載飽和。最後，在運算受限情境或突發性工作負載頻繁的環境中，GORGO 能避免單一副本過載而產生的隊頭阻塞。

**Q11：將 GORGO 導入產品時需要考慮哪些因素？**

A：首先，代理必須能可靠地記錄或估計每個副本的飛行中請求數量，因為從推論引擎取得即時佇列資訊會有延遲。其次，調校區間（tuning window）的選擇與權重範圍（hyperparameter ranges）會影響線上演化策略的收斂速度與穩定性，需要根據實際流量週期進行設定。最後，產品團隊必須明確 TTFT 與端對端延遲之間的權衡，並決定是要使用持續線上調校的 GORGO，還是使用在保留資料上學好權重的離線 GORGO。

**Q12：這項研究對 LLM 服務領域可能帶來什麼影響？**

A：GORGO 證明了在跨區域 LLM 服務中，網路延遲應該與 KV 快取局部性（KV-cache locality）和副本負載一起被納入路由決策，這將影響未來代理設計的思維。同時，釋出的 ART-Chat-2.5M 資料集填補了現有開源資料集在長上下文與高前綴重用方面的不足，為快取感知路由研究提供了更貼近生產環境的評估基準。論文也提供了逐案情境（case-by-case scenario）分析，幫助從業者判斷何時該使用基線策略、線上 GORGO 或離線 GORGO。

**Q13：論文承認了哪些限制？**

A：ART-Chat-2.5M 雖然基於真實生產中繼資料，但聊天內容是合成生成，因此與實際用戶對話仍可能存在分佈差異。此外，排隊延遲是透過代理端觀察的飛行中請求 token 數來近似，而非引擎內部真正的佇列長度，這在極端情況下可能不夠精確。最後，(1+1) 演化策略雖然簡單有效，但本質上仍可能收斂到區域最佳解，且成本模型的函數形式是預先設定的，未必適用於所有工作負載。

**Q14：GORGO 在哪些情況下可能表現不佳或失效？**

A：當流量極度突發且多個副本同時趨近飽和時，即使 GORGO 的成本模型也難以找到明顯較佳的路由目標。若代理端取得的副本負載資訊嚴重過時，連續批次處理可能會讓實際佇列狀態與成本估計脫節，導致決策失準。此外，如果某條鏈路的網路延遲遠高於其他成本數個量級，權重調校可能會過度偏向 RTT，反而犧牲長上下文工作負載中前綴快取所能帶來的預填充節省。

**Q15：未來可以朝哪些方向延伸這項工作？**

A：未來可以將解碼階段的記憶體競爭（decode memory contention）更直接地納入成本模型，而不只是透過飛行中請求數間接估計。也可以探索多目標最佳化框架，同時最小化 TTFT 與端對端延遲，並根據不同服務層級目標自動切換權重。此外，將 GORGO 擴展到異質硬體環境、結合更先進的線上學習演算法，以及在真實生產系統中進行長期線上部署驗證，都是值得深入研究的方向。

## 實務應用指南

### 適用場景

1. **全球多區域 LLM API 服務**  
   當推論引擎副本分散於北美、歐洲、亞洲等多個區域，且用戶端與副本間 RTT 差異可達數十毫秒至數百毫秒時，GORGO 可同時權衡網路延遲、KV 快取命中與副本佇列長度，降低 p95 TTFT。

2. **長上下文、多輪對話產品**  
   適用於法律文件分析、程式碼助手、企業知識庫問答等場景：這類工作負載輸入長、對話輪數多，前綴重用率高，prefix caching 的收益大，但也容易因請求集中而導致副本飽和，GORGO 可在「快取命中」與「負載分散」間取得平衡。

3. **突發性流量產品**  
   例如行銷活動、限時直播或教育平台考試期間，短時間內大量請求湧入。GORGO 的 queue 成本項能偵測佇列阻塞，將部分請求導向負載較輕但網路稍遠的副本，避免單一熱副本產生隊頭阻塞延遲。

4. **需要線上持續調校的企業級服務**  
   對於已具備即時指標蒐集與 A/B 測試基礎設施的團隊，可利用 GORGO 的 (1+1) 演化策略，在真實流量上持續微調路由權重，直接最佳化 p95 TTFT 等業務指標。

5. **快取導向的異質 GPU 叢集**  
   當叢集中同時存在高記憶體與低記憶體副本，或不同副本預載了不同模型版本／LoRA 時，GORGO 的成本模型可擴充為納入記憶體預算與快取局部性，協助請求導向最適合的副本。

### 實作步驟建議

1. **建立指標與成本模型基線**  
   在 Proxy 上實作 TTFT 成本函式：  
   `TTFT = W_rtt × RTT + W_queue × queue_tokens + prefill(tokens_not_cached)`  
   先以手動設定的權重（例如 `W_rtt = 1`、`W_queue = 1`）上線，蒐集 p95 TTFT、p95 E2E latency、KV-cache hit rate 與副本負載分佈。

2. **準備調校與評估資料**  
   若使用自有流量，需切分 tuning window 與 held-out evaluation window；若缺乏長上下文高重用資料，可先用 ART-Chat-2.5M 進行離線模擬，再遷移到真實流量。

3. **部署 (1+1) 演化策略調校器**  
   在 tuning window 內，每個時間步對 `W_rtt` 與 `W_queue` 進行對數空間擾動，根據 p95 TTFT 決定是否接受新權重，並依 Rechenberg 1/5 規則調整步長 σ。

4. **固定權重並進行保留評估**  
   調校結束後，將學到的權重套用至 held-out evaluation window，驗證相對於 session affinity、prefix reuse、least-load 等基線的 p95 TTFT 與 E2E latency 改善幅度。

5. **線上漸進式部署**  
   先以 shadow mode 比對 GORGO 路由決策與現行策略的差異，再對 1% → 10% → 50% 流量逐步切換；持續監控 queue 深度與副本飽和，必要時重新觸發調校。

6. **迭代擴充成本項**  
   當系統成熟後，可視需求加入 decode memory contention、GPU 記憶體預算、模型版本親和性等額外成本項，並調整對應權重。

---

### 潛在風險與注意事項

- **權重過度擬合調校區間**  
  在單一飽和輪廓下調出的權重，可能無法泛化到其他流量模式。建議使用多個不同時間尺度的調校區間，並在 held-out window 驗證。

- **TTFT 與 E2E latency 的權衡**  
  過度強調 RTT 與 queue 可能導致請求過度集中於少數「較熱副本」，反而提升 E2E latency。產品上線前需同時監控兩項指標，並依業務目標調整權重範圍。

- **指標延遲導致決策失真**  
  副本佇列深度從 Proxy 端取得通常有數十至數百毫秒延遲，在極高吞吐下可能低估真實負載。可搭配指數加權移動平均與本地 Proxy 側的 in-flight 請求計數作為補償。

- **線上調校的安全性**  
  演化策略會主動探索權重空間，可能在短時間內將流量導向不適合的副本。建議設定權重上下界、每步最大流量偏移比例，並在離峰時段執行調校。

- **前綴快取命中率被稀釋**  
  若 `W_queue` 過高，請求會被分散到多個副本，降低 KV-cache reuse。可設定 prefix 命中獎勵項或限制單一會話的副本跳轉次數。

---

### 與其他技術的整合建議

- **推論引擎**：可直接搭配已支援 prefix caching 的 vLLM 或 SGLang；若使用 Mooncake 架構，ART-Chat-2.5M 的 FAST'25 格式軌跡可直接匯入其模擬與排程管線。

- **服務網格 / Gateway**：可將 GORGO 成本模型實作為 Envoy 或 Istio 的自訂路由插件，利用其健康檢查與負載回報機制取得 RTT 與佇列資訊。

- **可觀測性堆疊**：將 `W_rtt`、`W_queue`、p95 TTFT、KV-cache hit rate 與副本負載分佈寫入 Prometheus，並以 Grafana 建立即時儀表板，協助判斷是否需要重新觸發 ES 調校。

- **自動擴縮容（Auto-scaler）**：GORGO 專注於請求層級路由，可與 Kubernetes HPA/VPA 或自訂 auto-scaler 搭配；當所有副本 queue 深度持續過高時，由 auto-scaler 啟動新副本，再由 GORGO 將流量導向新副本。

- **A/B 測試平台**：將 GORGO 作為一個實驗變體，與現行 least-load 或 prefix-reuse 策略並行，透過流量分桶比較業務指標，降低全面上線風險。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦第 1 節與第 2.1 節，理解 TTFT 為何由網路延遲、預填充時間與排隊延遲組成，以及 prefix caching 在多輪對話中的價值；接著看第 5 節的逐案情境，建立「何時該用哪種路由策略」的直覺，數學細節可暫時略過。

**AI 工程師**  
重點閱讀第 2.2 節的 GORGO Proxy 設計與 (1+1) 演化策略實作細節，並參考第 3 節的資料集建構方式；實作時請特別注意指標延遲、權重上下界與線上調校的安全機制，這些是從論文走向產品的關鍵。

**研究人員**  
可深入分析成本模型的設計空間：例如將 queue 項從「in-flight token 數」改為「預估 decode memory contention」、或探討在多目標最佳化（TTFT vs. E2E latency）下 Pareto 前沿的形狀；ART-Chat-2.5M 也可作為未來快取感知路由研究的標準測試軌跡。

**產品經理**  
請優先關注摘要與第 1 節的業務指標：GORGO 能在真實工作負載上降低 6.9–15.5% 的 p95 TTFT 與 14.3–30.9% 的 p95 E2E latency；同時留意「TTFT 改善可能以 E2E latency 為代價」這項權衡，並與工程團隊共同定義上線成功的指標與風險閾值。
