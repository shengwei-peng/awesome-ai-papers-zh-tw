# SCOPE：將自然語言政策編譯為神經符號（Neurosymbolic）謂詞程式

**原文標題：** SCOPE: Compiling Natural-Language Policies into Neurosymbolic Predicate Programs

**發布日期：** 2026-10-22

## ⚡ TL;DR

解決LLM代理在複合式多輪政策執行中，現有方法在準確率、成本與穩定性間難以兼顧的問題。
提出SCOPE，將政策編譯為神經符號謂詞程式，結合小型模型與組合程式碼，以對抗式反例聯合最佳化。
在多項真實政策任務中達到最高平均準確率，預測穩定且可解釋，並能以低成本模型達到旗艦推理模型的表現。

## 摘要翻譯

大語言模型代理（LLM Agent）的政策執行（Policy Enforcement）已從單輪內容審核（Single-turn Content Moderation），轉變為針對多輪對話記錄（Multi-turn Transcript）與工具呼叫軌跡（Tool-call Trajectory）進行評估的複合式（Compound）、應用特定政策（Application-specific Constraint）。微調防護欄模型（Fine-tuned Guardrail Model）雖然高效，但在複合式政策上效能會下降；而大語言模型擔任評審（LLM-as-a-Judge）的方法雖能達到更高的準確率，卻伴隨高昂的推論成本（Inference Cost），且傾向產生不穩定的預測。神經符號（Neurosymbolic）方法提供了一個自然的替代方案，將政策分解（Decomposition）為在明確邏輯（Explicit Logic）下組合（Composition）的聚焦神經決策（Neural Decision）。然而，現有的符號層（Symbolic Layer）缺乏所需的表達能力（Expressiveness），且是針對固定資料而非政策本身進行最佳化。為了解決這個問題，我們提出 SCOPE，它將政策編譯為神經謂詞（Neural Predicate）的可執行程式（Executable Program），該程式由小型模型（Small Model）、確定性萃取器（Deterministic Extractor），以及組合其輸出的 Python 程式碼（Python Code）所構成並執行。該程式與其訓練資料（Training Data）進行聯合最佳化（Joint Optimization），透過對抗式生成（Adversarial Generation）反例（Counterexample），專門針對程式偏離政策的區域。我們在真實世界政策任務（Real-world Policy Task）的基準測試（Benchmark）上，將 SCOPE 與提示詞最佳化（Prompt Optimization）、任務分解（Task Decomposition）及工作流程生成（Workflow Generation）等基線方法（Baseline）進行比較，在所有任務與模型上皆達到最高的平均準確率（Average Accuracy）。使用最弱執行器（Weakest Executor）最佳化的程式無需進一步最佳化即可遷移（Transfer）至其他模型。這使得它們能夠在低成本模型（Inexpensive Model）上部署（Deployment）於生產環境（Production），並達到與旗艦推理模型（Frontier Reasoning Model）相當的準確率。不同於這些單一整體模型（Monolithic Model），SCOPE 產生的預測顯著更為穩定（Stable Prediction），且每個判定結果（Verdict）都可透過產生該結果的謂詞輸出（Predicate Output）進行解釋（Interpretability）。此外，我們透過消融實驗（Ablation Study）驗證了方法的關鍵元件（Component）。SCOPE 因此能在生產規模（Production Scale）上實現可靠（Reliability）、可解釋且高效（Efficiency）的政策執行。

### 核心貢獻（3～5點）
- **提出 SCOPE 框架**：將自然語言政策（Natural-Language Policy）編譯為由神經謂詞、確定性萃取器與組合程式碼構成的可執行程式，兼顧表達能力與部署效率。
- **聯合最佳化機制**：程式與其訓練資料進行聯合最佳化，並透過對抗式反例生成（Adversarial Counterexample Generation）精準攻擊程式偏離政策的區域，提升政策貼合度。
- **跨模型遷移能力**：以最弱執行器最佳化所得的程式可無需重新最佳化即遷移至其他模型，使低成本模型在生產環境中達到與旗艦推理模型相當的準確率。
- **穩定性與可解釋性**：相較於單一整體模型，SCOPE 產生顯著更穩定的預測，且每個判定結果皆可追溯至具體的謂詞輸出，提供內建的可解釋性（Interpretable Verdict）。
- **全面實驗驗證**：在真實世界政策任務基準測試上，於多項任務與模型中達到最高平均準確率，並透過消融實驗確認各關鍵元件的必要性。

### 適合對象
- 研究**大語言模型安全與政策執行（Policy Enforcement）**的學者與工程師，特別關注內容審核（Content Moderation）、防護欄（Guardrail）機制設計者。
- 從事**神經符號（Neurosymbolic）方法**、可解釋 AI（Interpretable AI）研究的團隊。
- 需要在**生產環境（Production）**中部署高效、可解釋、低成本政策分類器（Policy Classifier）的產業實務者，如 AI 平台架構師、應用安全工程師與合規（Compliance）團隊。
- 對**對抗式生成（Adversarial Generation）**、聯合最佳化（Joint Optimization）與跨模型遷移（Transfer Learning）感興趣的機器學習研究者。

## 深度分析

#### 方法論解析

SCOPE（Symbolic Composition Over Predicates and Extractors，符號組合於謂詞與萃取器之上）的核心主張是：自然語言政策（natural-language policy）不應被「解讀」，而應被「編譯」。這個觀點翻轉了傳統 LLM-as-a-judge（大語言模型擔任評審）典範中將政策視為提示詞一部分、由單一整體模型（monolithic model）即時推理的做法，改為離線編譯、線上執行的兩階段流程。

**架構組成與職責分工**

SCOPE 編譯產出的目標物是一個「分解程式」（decomposition program），由三類元件構成：

1. **神經謂詞（neural predicate）**：由小型、低成本模型（weak executor，弱執行器）回答的窄範圍分類決策。每個謂詞對應政策中的一個子句（clause）、條件（condition）或例外（exception），刻意保持「窄而淺」，使弱模型能在無需延伸推理的情況下作答。

2. **確定性萃取器（deterministic extractor）**：處理政策中需要精確計算的部分，例如多輪對話記錄（multi-turn transcript）中的計數、跨欄位的字串比對、結構化欄位解析等。這類任務交給規則程式碼比交給神經模型更可靠。

3. **組合程式碼（composition code）**：以 Python 程式碼形式存在，將上述元件的輸出組合成最終判定結果（verdict）。這是 SCOPE 與既有神經符號（neurosymbolic）方法最關鍵的差異點——組合層不是 checklist（檢核清單）、加權規則集（weighted rule set）、布林規則或機率規則，而是具備完整 Turing 表達力的可執行程式碼（executable program），能自然表達條件分支、迭代、例外處理與子句間的交互作用（interaction）。

**雙層對抗式生成（adversarial generation）機制**

SCOPE 對「政策本身」而非「政策代理物」進行最佳化，這透過一個反覆運行的對抗式生成器（adversarial generator）實現。生成器在兩個層級產生反例（counterexample）：

- **局部對抗（local adversarial）**：針對單一謂詞偏離其對應子句語義的「局部漂移」（local drift）。當某個謂詞在訓練資料上表現良好但對其應轉錄的子句失去精確對應時，生成器會構造樣本迫使該謂詞重新校準。

- **系統性失敗（systemic failure）**：針對整體分解偏離政策的「全域漂移」（global drift），例如遺漏某個謂詞、誤判子句間的交互作用、或在組合邏輯中錯誤路由某個條件。

每個反例由一個強教師模型（strong teacher）套用完整政策進行標註（label），這個成本僅在編譯階段一次性支付。最佳化迴圈（optimization loop）反覆執行：生成反例 → 重新最佳化謂詞表述與組合程式碼 → 再次生成反例，直到收斂。**聯合最佳化（joint optimization）** 的對象是「程式 + 訓練資料」，而非僅僅是程式本身，這是 SCOPE 區別於既有工作的第二個關鍵設計。

**為何選擇「程式碼」作為組合層**

作者明確指出，現有符號層在兩個軸向上不足：表達能力（expressiveness）與偏差（bias）。Checklist、加權規則、布林規則等無法表達條件式、迭代與計算結構；而既有的合成方法（rule set tuned to training samples、program searched against static benchmark、function verified against self-generated tests）都是對政策的代理物（proxy）進行擬合，而非對政策本身。Python 程式碼同時解決了這兩個問題：它具備足夠的表達能力，且最佳化目標直接是政策本身——透過反例驅動的迭代改進（iterative refinement）將程式推向與政策一致。

#### 實驗數據解讀

**基準測試（benchmark）設計**

作者釋出了一個由四個政策執行任務（policy-enforcement task）構成的基準測試，來源涵蓋公開基準測試與模擬已部署的代理系統（deployed agentic system）。四個任務刻意覆蓋政策執行中四種典型難度維度：

1. **長代理軌跡（long agent trace）**：判斷單位是完整的工具呼叫軌跡（tool-call trajectory），證據僅佔上下文一小部分。
2. **多輪計數（multi-turn counting）**：需要在多輪對話記錄中正確計數觸發條件。
3. **評論者稽核（critic auditing）**：對另一個模型的批評進行審查。
4. **動態多標籤輸出（dynamic multi-label output）**：判定結果本身是動態數量的標籤集合，而非固定類別。

這四個任務的選擇具有代表性，因為它們對應了論文中反覆強調的「現代政策」特徵：複合條件、例外、計數、子句交互、長輸入。

**主要結果的意涵**

SCOPE 在多數「任務 × 執行器」設定中達到最高準確率（accuracy），優於三類基線方法（baseline）：提示詞最佳化（prompt optimization）、神經符號方法、工作流程生成（workflow generation）。這個結果的解讀重點不在於「SCOPE 贏了」，而在於**贏的幅度隨執行器變弱而擴大**。這意味著 SCOPE 的價值在低成本部署場景中最為顯著——當執行器是小型模型時，傳統方法的準確率急劇下降，但 SCOPE 因為將政策編譯成弱模型也能回答的窄謂詞，準確率對執行器選擇變得不敏感。

**遷移性（transfer）實驗**

最具實務意涵的發現是：以最弱執行器（weakest executor）編譯出的程式，無需重新最佳化即可直接遷移到其他模型。這打破了「編譯結果綁定特定模型」的常見疑慮。其底層原因是：當謂詞被設計為「無需延伸推理即可回答」時，謂詞的難度已被壓低到多數模型都能勝任的水準，因此換模型不會破壞整體效能。

**穩定性（stability）對比**

論文強調 SCOPE 的判定結果「幾乎固定」（nearly fixed），而推理模型（reasoning model）在重複執行時會翻轉相當比例的判定。這個差異的根源在於：單一整體模型的判定是對整段輸入的整體性推理，輸入的微小擾動或內部採樣變異都會傳播到最終輸出；而 SCOPE 的判定是對若干窄分類的邏輯組合，每個分類本身穩定，組合邏輯是確定性的，因此整體判定穩定。

**可解釋性（interpretability）作為副產物**

每個 SCOPE 判定都可追溯到產生它的謂詞輸出，這不是事後解釋（post-hoc rationale），而是判定過程本身的結構性產物。對於需要稽核或申訴流程的政策執行場景，這是相較於 LLM-as-a-judge 的根本性優勢。

**消融實驗（ablation study）**

消融實驗確認對抗式生成是這些增益的核心元件。移除反例生成機制後，SCOPE 退化為對靜態訓練集擬合的程式，會喪失對局部漂移與全域漂移的修正能力，效能回到接近基線的水準。

#### 與現有研究的比較

**相對於微調防護欄模型（fine-tuned guardrail model）**

微調防護欄模型（如 [37, 31, 98, 24]）在單一、範圍明確的規則上可與遠大模型匹敵，但當政策變為複合式（compound policy）時，單一模型的容量（capacity）成為上限（ceiling），準確率下降。SCOPE 透過分解繞過了這個上限：每個謂詞都是窄範圍的，因此每個謂詞的難度都落在弱模型的能力範圍內，而組合層用程式碼處理複雜度。

**相對於 LLM-as-a-judge**

LLM-as-a-judge 具備處理複合政策的能力，但有三個缺陷：推論成本（inference cost）與延遲（latency）使其不適用於生產規模（production scale）的高吞吐量分類（high-throughput classification）；預測不穩定（unstable prediction），變異性（variance）隨輸入子句數增加而上升；即使專用推理模型在複雜度門檻（complexity threshold）後也會崩潰（collapse）而非平滑擴展。SCOPE 在這三個維度上都有結構性優勢：成本由弱模型承擔、穩定性由窄分類與確定性組合保證、可擴展性由程式碼的表達力保證。

**相對於既有神經符號方法**

既有神經符號方法（如 checklist [46, 15]、加權規則集 [93, 58]、布林/機率規則 [12, 38, 92]）的符號層受限於表達能力，無法處理條件式、迭代、計算結構。SCOPE 用 Python 程式碼取代這些受限形式語言，獲得了完整的表達能力。另一類方法（如 [99, 34, 56]）雖然也合成程式，但最佳化對象是靜態基準測試或自我生成的測試與規格，而非政策本身；SCOPE 的反例驅動最佳化直接以政策為目標。

**相對於工作流程生成（workflow generation）**

工作流程生成方法將政策分解為多步驟流程，但流程本身仍由 LLM 執行，每一步都繼承了 LLM 的不穩定性與成本問題。SCOPE 的分解粒度更細：每個謂詞都是單一決策，組合是確定性程式碼，因此整體系統的行為更可預測。

**限制與未解決問題**

- **編譯成本**：每個反例需要強教師模型標註，雖然成本僅在編譯階段支付，但對於政策頻繁更新的場景，總成本仍可能顯著。
- **政策變更的處理**：當政策本身改變時，現有程式可能需要大幅重編，遷移性在政策層面的表現未在論文中詳細討論。
- **謂詞設計的自動化程度**：論文中「分解程式」的初始結構如何產生？是人工撰寫、由 LLM 草擬、還是其他方式？這影響方法的可重現性與擴展性。
- **錯誤的傳播**：若某個神經謂詞系統性錯誤，組合程式碼無法自動偵測或補償，因為組合是確定性的。

#### 可重現性評估

**程式碼與資料的釋出**

論文標題與摘要未明確聲明程式碼與基準測試的釋出狀態，但從「We release a benchmark of four policy-enforcement tasks」的措辭可推斷基準測試會公開。SCOPE 的核心實作——最佳化迴圈、對抗式生成器、組合程式碼框架——是否一併釋出則需查閱正式版本或附錄。

**模型權重**

SCOPE 編譯出的「分解程式」本身不是模型權重，而是一組謂詞提示詞、Python 程式碼與（可能的）小型分類器權重。若使用微調的小型模型作為神經謂詞，這些權重需要隨程式碼一起釋出才能完整重現實驗。論文提到「Programs compiled with our weakest executor transfer directly to other models」，暗示編譯產物與具體模型解耦，這有利於重現：研究者可以用自己的小型模型重新執行謂詞。

**實驗設定的可重現性**

四個基準任務的描述、政策文字、評估指標（accuracy）與執行器清單若在論文中完整列出，則實驗可重現。論文強調「average accuracy across tasks and models」作為主要指標，這需要明確的任務清單與模型清單。

**對抗式生成的重現難度**

對抗式生成器（adversarial generator）本身的實作細節——如何構造局部反例與系統性反例、如何選擇生成策略、如何控制生成品質——是重現的關鍵。若論文中僅給出高階描述而未提供演算法細節或偽程式碼，重現的工程成本可能較高。

**強教師模型的依賴**

編譯階段使用的強教師模型（用於標註反例）是另一個重現變數。若該模型是閉源旗艦模型（如 GPT-4、Claude），重現者需要取得等效模型或自行標註，這會顯著影響可重現性。

#### 未來研究方向

**政策演進與增量編譯**

現有 SCOPE 假設政策在編譯期間固定。實際部署中政策經常更新（新增例外、調整閾值、修改子句交互）。研究方向包括：如何從現有編譯產物增量更新而非從頭編譯；如何偵測政策變更並自動標記需要重新編譯的謂詞；如何維持版本控制與可追溯性。

**自動化謂詞發現**

目前未明確說明分解程式的初始結構如何產生。若由人工撰寫，則擴展性受限；若由 LLM 草擬，則需要研究如何確保草擬品質、如何驗證謂詞對子句的忠實度、如何處理 LLM 草擬時的遺漏與錯誤。

**錯誤隔離與容錯**

確定性組合的一個副作用是錯誤會傳播且不會被偵測。未來工作可以引入：謂詞間的一致性檢查（例如同一事實被多個謂詞獨立判定時的交叉驗證）、不確定性傳播（將謂詞的信心度納入組合）、以及對組合結果的健全性檢查（sanity check）。

**跨政策遷移**

不同政策之間可能共享大量謂詞（例如「是否包含個人資訊」、「是否涉及未成年人」）。研究如何建立可重用的謂詞庫、如何在編譯新政策時自動識別可重用的元件、如何處理謂詞在不同政策上下文中的語義漂移，是提升 SCOPE 工程效率的關鍵。

**更廣泛的應用領域**

SCOPE 的核心思想——將自然語言規格編譯成由弱神經元件與確定性程式碼組成的可執行程式——不限於政策執行。可應用於：合約審查（contract review）、法規遵循檢查（regulatory compliance check）、醫療指引執行（clinical guideline enforcement）、教育評量標準（educational rubric enforcement）等。這些領域共享「自然語言規格 + 需要可解釋、可穩定、低成本執行」的特性。

**理論分析**

SCOPE 的經驗結果強勁，但缺乏對「為何窄謂詞組合能達到與旗艦推理模型相當的準確率」的理論分析。未來工作可以研究：謂詞難度與執行器能力之間的匹配條件；組合程式碼的表達能力與政策複雜度之間的形式化關係；以及反例驅動最佳化的收斂性理論。

**與其他分解典範的整合**

SCOPE 的分解是「水平」的（將政策切成多個獨立謂詞）。這與「垂直」分解（如 chain-of-thought、tree-of-thought）互補。未來工作可以探索兩者的混合：對於需要多步推理的子句使用垂直分解，對於需要並行檢查的多個條件使用水平分解，並由組合程式碼統一協調。

**基準測試的擴展**

四個任務的基準測試是良好的起點，但政策執行的應用場景遠多於此。擴展基準測試以涵蓋更多政策類型（如金融合規、醫療隱私、內容分級）、更多輸入形式（如圖片描述、程式碼、表格）、更多語言，將有助於更全面評估 SCOPE 及其後續工作的泛化能力。

## 論文問答

**Q1：為什麼 LLM 代理的政策執行變得比以往更加困難？**

A：隨著 LLM 從單輪內容審核演進到多輪助理與使用工具的代理，政策與其管轄的輸入都變得更為複雜。判斷的單位不再是單一訊息，而是長對話記錄、結構化計畫或代理軌跡，且現代政策很少是單一扁平類別，而是捆綁條件、例外、計數與交互作用，必須整體評估。這意味著一個被忽略的子句就會導致誤判違規或漏判義務，使政策執行既關鍵又困難，因為判定取決於複合式、上下文相關的規格，而非單一表層特徵。

**Q2：現有的政策執行方法有哪些主要限制？**

A：微調的防護欄模型雖然快速且便宜，在單一明確規則上表現良好，但當政策變成多個交互條件的複合式政策時，其容量成為上限，準確率隨之下降。大語言模型擔任評審的做法雖然在複合式政策上更有能力，但預測不穩定，變異性隨輸入子句數量增加而上升，且推理模型在超過複雜度門檻後會崩潰而非擴展通過；其推論成本與延遲也使其在生產規模的高吞吐量分類中不切實際。現有的神經符號方法則受限於符號層的表達能力（無法表達條件式、迭代與計算結構）以及偏差（學習層是針對代理而非政策本身擬合）。

**Q3：為什麼政策執行在生產環境中特別具有挑戰性？**

A：政策執行者把關每一次互動，其成本在每次互動中支付，因此必須便宜才能在高吞吐量分類中可行。判定結果必須一致，因為一個會隨位置或表面形式變動的判定根本不算執行政策。在長對話記錄、代理軌跡等輸入中，決定判定的證據往往只占上下文的一小部分，但政策仍必須準確，因為一個被忽略的子句就會產生誤判違規或漏判義務。這三項要求——便宜、一致、準確——同時滿足是政策執行在生產規模的核心挑戰，也是現有方法難以跨越的門檻。

**Q4：SCOPE 的核心方法是什麼？**

A：SCOPE 將自然語言政策編譯成一個可執行的神經符號程式，由神經謂詞（由小型模型回答）、確定性萃取器（用於精確計算）以及組合其輸出的 Python 程式碼所組成。這個分解程式將政策拆解成狹窄的神經決策，並在明確邏輯下組合它們，使每個子決策範圍更小、可由弱模型回答，從而降低運行成本。組合層使用程式碼而非基於規則的形式化方法（如檢查表、加權規則集、布林或概率規則），能自然地表達真實世界政策中的條件式、迭代與計算結構。

**Q5：SCOPE 與現有神經符號方法的關鍵創新是什麼？**

A：關鍵創新在於程式與其訓練資料的聯合最佳化：SCOPE 不是僅依賴靜態訓練集，而是使用對抗式生成器反覆產生反例，針對當前程式偏離政策規格之處。對抗式生成在兩個層次運作——局部對抗（單一謂詞不再追蹤其轉錄的子句）與系統性失敗（整體分解錯過某個謂詞或誤路由子句間的交互作用）。每個反例由強教師套用完整政策進行標註，而該成本僅在編譯時支付一次，從而緩解了符號層針對代理而非政策本身的偏差問題，使最佳化單位是複合式政策而非單一規則。

**Q6：SCOPE 的設計選擇如何影響其在生產環境中的可用性？**

A：一旦政策被編譯成弱模型無需推理即可回答的謂詞，準確率就變得對執行器選擇幾乎不敏感，這是部署上的關鍵優勢。以最弱執行器最佳化的程式可直接遷移至其他模型，無需重新最佳化，並在推論成本的一小部分下匹配旗艦推理模型的準確率。每個判定都可追溯到產生它的謂詞輸出，而非事後的解釋，這對於需要稽核與合規的應用至關重要，且預測穩定性遠優於單一整體模型——後者在重複運行中會翻轉相當比例的判定，而 SCOPE 的判定幾乎固定不變。

**Q7：SCOPE 在哪些基準測試上進行評估？**

A：SCOPE 在一個由四個政策執行任務組成的基準測試上進行評估，這些任務源自公開基準或模擬已部署的代理系統。這些任務涵蓋長代理軌跡、多輪計數、評論者稽核以及動態多標籤輸出等多種政策執行場景，反映了真實世界中政策執行所面臨的不同挑戰——從結構化計畫到多輪對話記錄的評估。任務的多樣性使評估能夠檢驗 SCOPE 在不同政策結構與輸入類型下的泛化能力，而非僅針對單一場景最佳化。

**Q8：SCOPE 的主要實驗結果為何？**

A：SCOPE 在大多數任務-執行器設定中達到最佳準確率，平均而言優於提示詞最佳化、神經符號方法與工作流程生成等基線方法。其優勢隨著執行器變弱而擴大：以最弱執行器最佳化的程式遷移至其他模型時，能匹配旗艦推理模型的準確率，但推論成本僅為其一小部分。SCOPE 的預測也遠比推理模型穩定——後者在重複運行中會翻轉相當比例的判定，而 SCOPE 的判定幾乎固定不變，這對於生產環境中的一致性要求至關重要。

**Q9：消融實驗揭示了哪些關鍵發現？**

A：消融實驗確認對抗式生成是 SCOPE 性能提升的核心，移除該元件會顯著降低準確率。這驗證了針對當前程式偏離政策之處產生反例的策略，比僅依賴靜態訓練集更為有效，因為後者無法針對性地暴露程式的弱點。消融結果也支持了 SCOPE 的設計假設：透過狹窄的神經決策與明確的邏輯組合，可以將政策執行從不透明的單一判斷轉變為可最佳化、可檢查、可大規模部署的程式，這是神經符號方法相較於純神經或純符號方法的根本優勢。

**Q10：SCOPE 適用於哪些實際應用場景？**

A：SCOPE 適用於任何需要對 LLM 代理行為進行政策執行的場景，包括內容規則、法規義務以及應用特定的允許系統行為約束。具體而言，它可用於多輪助理的對話記錄審核、使用工具的代理軌跡檢查，以及結構化計畫的合規性驗證。在這些場景中，SCOPE 的可解釋判定與穩定預測使其特別適合需要稽核追蹤的合規應用，例如金融、醫療或法律領域中對代理行為的監管要求。

**Q11：在產品化部署時，SCOPE 帶來哪些實際好處？**

A：在生產規模部署時，SCOPE 的核心優勢在於成本與可解釋性：由於程式完全在弱模型上運行，無需昂貴的旗艦推理模型，從而大幅降低推論成本與延遲，使高吞吐量分類變得經濟可行。每個判定都可追溯到具體的謂詞輸出，這對於需要向監管機構或內部稽核解釋判定依據的場景至關重要，避免了「黑箱」決策的合規風險。此外，預測的高度穩定性意味著相同輸入不會產生翻轉的判定，這對使用者體驗與政策執行的一致性都是關鍵。

A：SCOPE 的一個關鍵限制是其在編譯時需要強教師來標註對抗式生成的反例，雖然該成本僅支付一次，但對於無法取得強模型存取的組織可能構成障礙。此外，SCOPE 的有效性取決於政策能被分解為狹窄、可由弱模型回答的子決策；對於某些高度耦合、無法乾淨分解的政策，分解程式的設計可能會遇到困難。雖然論文未明確列出失敗案例，但可預期在政策規格本身模糊或子句間交互極為複雜的情況下，SCOPE 的表現可能會下降，因為這會增加對抗式生成器有效覆蓋政策空間的難度。

### 適用場景

1. **客服與對話式 AI 助理的內容合規審查**：當企業部署多輪對話助理時，需即時判斷對話是否違反品牌溝通規範、禁詞清單、敏感產業（如金融、醫療）的揭露義務。SCOPE 可將「不得承諾投資報酬率」「不得提供診斷建議」等複合式政策編譯為可執行的謂詞程式，每輪對話皆可低成本審查。

2. **AI 代理（Agent）的工具呼叫軌跡稽核**：當 LLM 代理執行多步驟任務（如自動下單、API 串接、檔案操作）時，組織需驗證代理是否遵守「不得刪除使用者資料」「不得在未授權下呼叫付費 API」「不得繞過審批流程」等軌跡層級政策。SCOPE 將整段代理軌跡作為輸入，輸出可解釋的違規判定。

3. **法規遵循與監管申報自動化**：金融機構、醫療機構需對生成內容是否符合 GDPR、HIPAA、MiCA 等法規進行批次審查。SCOPE 可將「資料是否包含可識別個人資訊」「是否提及未經核准的醫療適應症」等規則編譯為程式，於生產環境以小型模型執行，達到與旗艦推理模型相當的準確率。

4. **內部生成式 AI 工具的使用守則執行**：企業內部部署的程式碼助理、文件生成工具需遵守「不得輸出競爭對手產品名稱」「不得協助撰寫離職信」「不得產生未加密的客戶資料」等應用特定約束。SCOPE 將守則編譯後嵌入 API 閘道，每次請求皆經審查。

5. **教育與兒少內容平台的發文預檢**：社群平台、論壇需在使用者發布前檢查內容是否違反「不得包含霸凌用語」「不得洩漏個資」「未滿 18 歲使用者不得接觸特定主題」等多條件政策。SCOPE 的可解釋判定可附帶違規子句說明，便利申訴流程。

### 實作前置條件

**資料準備**
- **政策文本**：需具備結構清晰、條件明確的自然語言政策文件。模糊或自相矛盾的條文會直接影響編譯品質，建議先由領域專家與法務共同校稿。
- **種子樣本（Seed Samples）**：每項任務至少需數十至數百筆已標註的範例（合規／違規），覆蓋政策中各子句的典型觸發情境。標註品質比數量更關鍵，建議由熟悉政策的審查員產製。
- **強教師模型（Strong Teacher）API 存取權**：用於在對抗式生成階段對反例進行標註。建議使用具備長上下文處理能力的前沿推理模型（如 GPT-4 等級），此為一次性編譯成本。

**運算資源**
- **開發階段**：需具備呼叫前沿 LLM API 的額度（用於強教師標註與對抗式生成），以及執行小型開源模型（如 7B–13B 參數等級）的 GPU 環境以訓練與評估謂詞。
- **生產部署階段**：僅需小型模型的推論資源（單張消費級 GPU 或雲端小型實例即可），因為編譯後的程式完全在弱執行器上運行。

**技能門檻**
- **Python 程式設計**：能撰寫中等複雜度的組合邏輯（條件分支、迴圈、計數、例外處理），並理解如何將政策條文映射為程式結構。
- **提示工程（Prompt Engineering）**：為每個神經謂詞設計精準的子任務提示詞，避免謂詞之間的語義重疊或遺漏。
- **基礎機器學習概念**：理解模型評估、訓練-測試切分、對抗式資料增強的原理，以便調校最佳化迴圈。
- **政策領域知識**：由熟悉業務規則的領域專家參與謂詞設計與反例審查，純技術角色無法獨立完成編譯。

### 實作步驟建議

**步驟一：政策拆解與種子樣本整備**
盤點欲執行的政策文本，識別其中的條件、例外、計數規則與子句間的交互作用（例如「若 A 且非 B，則違規；但若同時滿足 C，則例外」）。針對每個子句準備 20–50 筆正反例種子樣本，並由領域專家完成標註。

**步驟二：初始分解程式草稿**
依政策結構手動撰寫第一版 Python 組合程式，將每個子句對應到一個神經謂詞或確定性萃取器。神經謂詞的提示詞應聚焦於單一可判斷的子問題（例如「此訊息是否提及具體金額？」），避免在一個謂詞內做複合判斷。確定性萃取器用於可由規則精確處理的子句（如正則表達式比對、計數閾值）。

**步驟三：建立評估基準**
從種子樣本中切分出獨立的測試集（建議 20–30%），其餘作為訓練集。定義準確率、穩定性（重複執行的一致率）、可解釋性（謂詞輸出與最終判定的對應可追溯性）三類指標。

**步驟四：對抗式反例生成迴圈**
啟動 SCOPE 的最佳化迴圈：
- **局部對抗（Local Adversarial）**：針對每個神經謂詞，由生成器產出該謂詞可能誤判的邊界樣本（例如措辭稍異但語意相同的違規內容），由強教師重新標註後加入訓練集。
- **系統性對抗（Systemic Failure）**：針對整體組合程式，產出多個謂詞皆正確但組合結果錯誤的樣本（例如子句交互作用被忽略的情境），同樣由強教師標註後加入訓練集。
- 每輪迭代後重新評估測試集，當準確率收斂或達到預期門檻時停止。

**步驟五：跨模型遷移驗證**
使用最弱執行器（如 7B 等級開源模型）完成編譯後，將程式直接部署至其他模型（中型、開源、閉源皆可），無需重新最佳化。驗證準確率是否維持在可接受範圍內，以確認遷移性。

**步驟六：生產部署與監控**
將編譯後的分解程式封裝為 API 服務，前端應用於每次請求時呼叫。部署初期建議保留強教師的影子模式（Shadow Mode）日誌，比對 SCOPE 判定與強教師判定的一致率，持續蒐集真實流量中的潛在反例，定期觸發再編譯。

**步驟七：可解釋性介接**
為每筆判定保留完整的謂詞輸出鏈（哪個謂詞觸發、其信心值為何、組合邏輯如何路由至最終判定），供申訴審查、稽核日誌與合規報告使用。

### 潛在風險與注意事項

**風險一：政策本身模糊或矛盾**
若原始政策文本存在歧義（例如「適當地」「合理範圍內」等模糊詞），編譯出的程式將繼承此模糊性，導致判定不一致。
**緩解**：編譯前先由領域專家與法務將政策改寫為可機器判讀的條文，明確列舉例外與邊界情境。

**風險二：對抗式生成的成本與覆蓋不足**
強教師標註是編譯階段的主要成本，若反例生成器無法觸及某些罕見但關鍵的子句交互，程式可能在生產中遭遇未見過的失敗模式。
**緩解**：結合規則式反例產生器（針對已知邊界）與基於 LLM 的反例產生器（探索未知邊界），並設定最大迭代次數與成本上限。

**風險三：神經謂詞之間的語義洩漏**
若多個謂詞隱含判斷了同一個子問題，會導致組合邏輯失效（例如兩個謂詞對「是否為醫療建議」給出相反答案）。
**緩解**：在設計階段為每個謂詞撰寫明確的「輸入-輸出契約」，並在測試集中加入專門檢測謂詞一致性的案例。

**風險四：跨模型遷移的效能落差**
雖然論文宣稱程式可遷移，但若目標模型的指令遵循能力過弱，部分神經謂詞可能無法穩定輸出預期格式。
**緩解**：遷移前先以小型樣本集（50–100 筆）驗證目標模型的謂詞輸出格式與準確率，必要時為弱模型設計更精簡的提示詞或後處理解析邏輯。

**風險五：政策演進後的程式陳舊化**
當政策更新（例如新增例外條款），原編譯程式可能不再準確，但不會自動失效。
**緩解**：建立政策變更的版本控管流程，每次政策更新即觸發增量再編譯，並保留前一版本程式作為 fallback。

**風險六：可解釋性的誤導**
使用者可能誤將「可解釋判定」等同於「正確判定」，但謂詞輸出鏈本身仍可能包含錯誤。
**緩解**：在介面上明確標示「此判定基於下列謂詞輸出，僅供審查參考」，並提供申訴與人工覆核管道。

### 與其他技術的整合建議

**與 LLM-as-a-Judge 整合**
SCOPE 並非要取代 LLM-as-a-Judge，而是作為其編譯產物。在生產環境中，可將 SCOPE 程式作為第一線高速篩選（處理 90% 以上的一般請求），僅將低信心或邊界案例升級至強教師模型進行二次審查，形成「SCOPE 優先、LLM 兜底」的兩階段架構，兼顧成本與準確率。

**與微調防護欄模型整合**
若組織已部署微調的小型防護欄模型，可將其作為 SCOPE 的弱執行器，無需重新訓練。SCOPE 的組合邏輯層會補足單一模型在複合政策上的容量天花板，兩者形成「模型 + 邏輯」的互補結構。

**與規則引擎（如 Open Policy Agent、Drools）整合**
確定性萃取器部分可外包給既有規則引擎處理，SCOPE 專注於需要語意理解的子句。組合程式可透過 API 呼叫規則引擎結果，再與神經謂詞輸出組合。

**與代理框架（如 LangChain、AutoGen）整合**
在代理軌跡稽核場景中，可在代理執行的每個關鍵節點（工具呼叫前、狀態變更後）插入 SCOPE 判定呼叫，作為代理的「合規守門人」。判定結果可寫入代理的狀態記憶，影響後續步驟的決策。

**與可觀測性平台整合**
將每筆判定的謂詞輸出鏈寫入日誌系統（如 OpenTelemetry、Datadog），建立可搜尋的合規事件流，供稽核、報表與異常偵測使用。

**與 CI/CD 流程整合**
將 SCOPE 編譯過程納入 ML Ops 流程：政策變更觸發 CI 重新編譯，自動化評估通過後自動部署至預備環境，人工抽樣驗證後升級至生產環境。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先閱讀第 1 節的問題陳述，理解為何單純的「提示詞工程」或「微調小模型」無法處理複合式政策；接著重點理解圖 1 的編譯流程圖，掌握「政策 → 分解程式 → 對抗式生成 → 最佳化」的高階概念。實作層面的細節（謂詞設計、組合程式撰寫）可先略過，待具備 Python 與提示工程基礎後再深入。

**給 AI 工程師**
重點關注第 1 節中對現有神經符號方法不足的分析（表達能力與偏誤兩個軸），以及第 4 節的實驗設計（基準任務、執行器選擇、遷移實驗、消融實驗）。建議嘗試以論文中釋出的基準任務重現 SCOPE 流程，從中體驗對抗式生成迴圈的調校技巧，並評估將其應用於自身業務政策的可行性。

**給研究者**
本論文的核心貢獻在於「將政策編譯為可執行程式並聯合最佳化資料」的範式轉移，以及「局部對抗 vs 系統性對抗」的雙層反例生成機制。建議深入分析第 3 節的方法細節，特別是反例生成器的設計空間、組合程式的搜尋演算法、以及強教師標註的成本-效益權衡。可進一步探索的方向包括：自動謂詞發現、跨政策遷移、多語言政策編譯、與形式化驗證的結合。

**給產品經理**
本論文的核心訊息是：政策執行不必依賴昂貴且不穩定的前沿模型，可透過編譯為結構化程式來兼顧成本、準確率、可解釋性與穩定性。建議關注第 1 節的問題動機、第 4 節的實驗結果（特別是「最弱執行器遷移後達到與旗艦推理模型相當的準確率」這項發現），以及第 5 節的部署建議。在評估導入時，應將「政策編譯的一次性成本」與「每次推論的節省成本」一併納入 ROI 計算，並預留政策演進後的再編譯預算。
