# 工業物聯網網路中輕量級入侵偵測模型之跨域泛化失效

**原文標題：** Cross-Domain Generalization Failure in Lightweight Intrusion Detection Models for IIoT Networks  
**作者：** MD Azizul Hakim、Md Shihab Uddin、Talha Ibne Anis  
**發布日期：** 2026-07-01  
**HF 連結：** [https://huggingface.co/papers/2607.00553](https://huggingface.co/papers/2607.00553)

## ⚡ TL;DR

輕量級工業物聯網入侵偵測模型僅在訓練網路內評估，跨域泛化能力未經驗證。
研究將四種輕量模型於單一資料集訓練，直接測試於兩相異資料集，並以可解釋性分析與消融實驗探究特徵依賴。
結果顯示跨網路泛化失效，粗粒度連接埠特徵僅轉移捷徑，域內準確率不足以評估部署準備度。

## 摘要翻譯

輕量級（Lightweight）機器學習模型由於適合資源受限（Resource-Constrained）的邊緣部署（Edge Deployment），近年來被廣泛提出用於工業物聯網（Industrial Internet of Things, IIoT）網路的入侵偵測。大多數已發表的結果僅在其訓練網路內評估這些模型，導致其在未見網路（Unseen Networks）上的行為仍缺乏驗證。本研究以單一工業物聯網資料集訓練四種輕量級架構，並在不重新訓練的情況下，使用僅含三個來源共通屬性之特徵表示（Feature Representation），於兩個結構相異（Structurally Distinct）的工業物聯網資料集上進行跨網路評估（Cross-Network Evaluation）。針對兩個最佳效能模型（Top-Performing Models）的可解釋性分析（Explainability Analysis）顯示，兩者皆極度依賴粗粒度連接埠類別特徵（Coarse Port-Category Features）；最具影響力的類別在來源域（Source Domain）攻擊流量（Attack Traffic）中的出現率，為兩個目標域（Target Domain）的 96 至 435 倍，顯示降低連接埠解析度（Port Resolution）僅是轉移而非消除已有文獻記載的捷徑（Shortcut）。在自然不平衡類別分布（Naturally Imbalanced Class Distributions）下的評估揭示另一項效應：所使用的評估協定（Evaluation Protocol）可能翻轉對於「哪個目標網路（Target Network）看似構成更大泛化挑戰」的判斷。本研究亦評估了對抗穩健性（Adversarial Robustness），以及透過有限目標域暴露（Target-Domain Exposure）進行恢復的效果；對抗擾動（Adversarial Perturbation）的穩健性與跨網路泛化無關，而透過適應（Adaptation）達成的恢復則因架構不同而有顯著差異。這些發現指出，部署準備度（Deployment Readiness）應透過貼近實際的類別分布下之跨網路評估來衡量，而非僅憑域內準確率（Within-Domain Accuracy）。

### 核心貢獻（3～5點）
- 建立跨資料集零樣本評估架構：在不重新訓練的情況下，以三個來源共通屬性構成之特徵表示，於結構相異的未見工業物聯網網路上評估輕量級入侵偵測模型，揭露嚴重的跨域泛化失效。
- 可解釋性分析揭露捷徑學習機制：最佳效能模型極度依賴粗粒度連接埠類別特徵，而降低連接埠解析度僅是轉移而非消除文獻已記載的捷徑。
- 評估協定與類別分布的交互作用：在自然不平衡類別分布下，評估協定的選擇可能翻轉對於「哪個目標網路構成更大泛化挑戰」的判斷。
- 對抗穩健性與適應恢復的獨立性：對抗擾動的穩健性與跨網路泛化能力無顯著關聯，而透過有限目標域暴露進行適應的恢復效果則因模型架構而異。
- 提出部署準備度評估準則：主張應以貼近實際類別分布下的跨網路評估取代單純的域內準確率，作為邊緣部署前的必要衡量標準。

### 適合對象
從事工業物聯網安全、邊緣人工智慧系統部署，以及輕量級機器學習模型設計的研究人員與工程師；特別適合關注模型跨域泛化能力、可解釋性分析，以及如何在資源受限環境下建立穩健入侵偵測系統的讀者。

## 深度分析

#### 方法論解析

本研究針對 Lightweight (輕量級) Intrusion Detection Models (入侵偵測模型) 在 IIoT Networks (工業物聯網網路) 上的 Cross-Domain Generalization Failure (跨域泛化失效) 進行系統性探究。隨著 Sensors, Controllers, and Actuators (感測器、控制器與致動器) 日益普及，工業環境的 Attack Surface (攻擊面) 持續擴大，傳統 Server-Grade Intrusion Detection (伺服器級入侵偵測) 難以觸及所有節點，使得適合 Edge Deployment (邊緣部署) 的 Lightweight Machine Learning Models (輕量級機器學習模型) 成為必要選項。這些模型必須在 Computation, Memory, and Energy Budgets (運算、記憶體與能源預算) 極度 Resource-Constrained (資源受限) 的 Edge Hardware (邊緣硬體) 上運行，因此其設計與評估必須重新審視。

研究採用 Cross-Dataset Study (跨資料集研究) 架構，選定四種具代表性的輕量架構：Decision Tree (決策樹) 與三種 Compact Neural Network Designs (緊湊神經網路設計)。模型於單一 Source Domain (來源域) 的資料集上訓練後，透過 Zero-Shot Transfer (零樣本遷移) 方式，直接部署於兩個 Structurally Distinct (結構相異) 的 Target Domains (目標域) 進行評估，期間不進行重新訓練。為排除因資料格式差異所導致的效能落差，Feature Representation (特徵表示) 被嚴格限制為三個資料集共有的屬性，確保 Cross-Network Evaluation (跨網路評估) 的公平性。

為診斷效能崩潰的根因，作者對 Top-Performing Models (最佳效能模型) 實施 Explainability Analysis (可解釋性分析)，量化模型的 Feature Reliance (特徵依賴)。結果顯示模型高度依賴 Coarse Port-Category Features (粗粒度連接埠類別特徵)。為驗證此現象是否構成 Shortcut (捷徑)，研究設計了針對性的 Ablation Test (消融測試)：透過降低 Port Resolution (連接埠解析度)，觀察模型是擺脫了捷徑，抑或僅將依賴轉移至更粗粒度的連接埠分桶。此外，研究比較了兩種 Evaluation Protocol (評估協定)：Artificially Balanced (人工平衡) 與 Naturally Imbalanced Class Distributions (自然不平衡類別分布)，以檢驗學術 Benchmarks (基準資料集) 常用的平衡設定是否掩蓋了真實部署條件下的風險。

研究亦獨立評估 Adversarial Robustness (對抗穩健性)，測試模型在 Adversarial Perturbation (對抗擾動) 下的表現，並探討其與跨網路泛化能力的關聯性。最後，作者透過 Limited Target-Domain Exposure (目標域暴露) 實驗，以少量 Labeled Sample (標記樣本) 進行 Fine-Tuning (微調)，評估 Local Adaptation (局部適應) 能否有效恢復跨域效能，並觀察此恢復能力是否為所有輕量架構的共通特性。

#### 實驗數據解讀

實驗結果首先證實，Within-Domain Performance (域內效能) 與 Cross-Network Performance (跨網路效能) 之間存在嚴重脫鉤。儘管模型在 Source Network (來源網路) 上可達近乎完美的 Within-Domain Accuracy (域內準確率)，但面對具有不同 Device Composition (裝置組成)、Traffic Patterns (流量模式) 與 Attacker Behavior (攻擊者行為) 的 Unseen Networks (未見網路) 時，效能顯著崩潰。這直接挑戰了現有文獻以 Same-Dataset Evaluation (同資料集評估) 作為部署依據的慣例。

Explainability Analysis (可解釋性分析) 揭示，模型決策極度仰賴少數 Coarse Port-Category Features (粗粒度連接埠類別特徵）。進一步的量化比較顯示，最具影響力的連接埠分類在 Source Domain (來源域) 的 Attack Traffic (攻擊流量) 中，出現頻率為 Gotham 目標資料的 96 倍、WUSTL-IIoT-2021 目標資料的 435 倍。這項 Port-Bucket Prevalence (連接埠分桶普及率) 的極端差異，證明了降低 Port Resolution (連接埠解析度) 並未移除捷徑，而是將其從 Raw Port Memorization (原始連接埠記憶) 轉移至粗粒度類別本身。換言之，特徵粗化僅是重新定位了投機規則，而非解決 Domain Shift 的根本問題。

在 Class Distributions (類別分布) 的影響方面，研究發現 Naturally Imbalanced Class Distributions (自然不平衡類別分布) 會顯著改變對 Target Network (目標網路) 難易度的判斷。具體而言，在 Artificially Balanced (人工平衡) 設定下看似較易泛化的目標網路，於自然分布中可能成為較困難的挑戰，反之亦然。這意味著採用平衡協定不僅過度樂觀，甚至可能導致對 Deployment Readiness (部署準備度) 的排序性誤判。

Adversarial Robustness (對抗穩健性) 實驗則顯示，抵抗 Adversarial Perturbation (對抗擾動) 的能力與 Cross-Domain Generalization Failure (跨域泛化失效) 無顯著相關。這項發現具有重要的方法論意涵：對抗穩健性測試無法替代 Cross-Network Evaluation (跨網路評估)，兩者評估的是模型不同面向的脆弱性。最後，Fine-Tuning (微調) 實驗指出，透過少量目標資料進行 Adaptation (適應) 的效果高度取決於架構本身，並非所有 Lightweight Machine Learning Models (輕量級機器學習模型) 都具備同等的恢復潛力。

#### 與現有研究的比較

相較於既有文獻，本研究在數個層面做出明確區隔與推進。首先，針對 Edge-IIoTset、WUSTL-IIoT 與 Gotham 等主流 Benchmarks (基準資料集)，原始發表文獻均僅報告 Same-Dataset Evaluation (同資料集評估) 結果，未驗證模型於不同網路間的適用性。本研究首次以輕量架構為對象，系統性地證明其跨網路失效，填補了 Lightweight (輕量級) IIoT 入侵偵測在 Cross-Dataset Study (跨資料集研究) 上的空白。

在企業網路領域，Cantone et al.、D’Hooge et al. 與 Verkerken et al. 等雖已觀察到跨資料集效能崩潰，但其研究對象並非 Resource-Constrained (資源受限) 的 Edge Hardware (邊緣硬體)，也未觸及工業場景特有的裝置異質性與協議組成。Engelen et al. 雖已證實 Destination Port 可作為捷徑，後續研究多採取迴避策略（直接移除 IP 與連接埠特徵），而本研究則正面檢驗此機制：透過比較粗化前後的 Feature Reliance (特徵依賴) 與跨域效能，明確指出降低解析度僅是轉移而非消除捷徑。

與精神上最接近的 Layeghy and Portmann 相比，本研究進一步納入三項關鍵設計：針對單一混淆特徵的 Ablation Test (消融測試)、Artificially Balanced (人工平衡) 與 Naturally Imbalanced Class Distributions (自然不平衡類別分布) 的對照，以及少量樣本恢復實驗。這些設計使診斷更為精準，也更貼近 Realistic Deployment Scenario (真實部署場景)。

然而，本研究仍存在若干限制。實驗僅涵蓋四種架構與單一 Source Network (來源網路)，且 Traffic Capture Format (流量擷取格式) 的差異可能透過特徵對齊過程被部分平滑化；未來仍需驗證這些發現是否適用於更多元的 Feature Representation (特徵表示) 與模型家族。

#### 可重現性評估

從資料可用性來看，本研究使用的三個 Benchmarks (基準資料集)—Edge-IIoTset、Gotham 與 WUSTL-IIoT-2021—均為公開資料集，理論上具備重現的資料基礎。方法論層面，作者明確說明了跨資料集特徵對齊策略、四種模型架構（Decision Tree (決策樹) 與 Compact Neural Network Designs (緊湊神經網路設計)）、以及 Artificially Balanced (人工平衡) 與 Naturally Imbalanced (自然不平衡) 兩種 Evaluation Protocol (評估協定) 的實施方式，整體實驗設計描述尚稱完整。

儘管如此，就提供的預印本片段觀察，作者並未提及原始碼、模型權重或實作框架（如 TensorFlow、PyTorch、Scikit-learn）的釋出計畫。由於三個資料集的 Traffic Capture Format (流量擷取格式) 與 Feature Representation (特徵表示) 欄位存在差異，從原始封包到統一輸入的前處理管線（如連接埠分桶規則、特徵縮放方式）若未完整公開，將大幅增加獨立重現的難度。此外，作為一份 Preprint，其同儕審查狀態與附屬材料完整性仍待確認。綜合而言，本研究在概念與方法上具備可重現性，但實務層面的完整再現仍高度依賴未來是否釋出標準化的前處理腳本與實驗管線。

#### 未來研究方向

基於上述發現，未來研究可沿以下方向深化。第一，社群應將 Cross-Network Evaluation (跨網路評估) 列為 IIoT Intrusion Detection Models (入侵偵測模型) 的強制性上線標準，而非僅以 Within-Domain Accuracy (域內準確率) 作為 Deployment Readiness (部署準備度) 的代理指標。第二，特徵工程研究應致力開發完全擺脫連接埠資訊的行為驅動表徵，而非持續在 Port Resolution (連接埠解析度) 的粗細之間調整，因為任何基於連接埠分桶的設計在面對極端 Port-Bucket Prevalence (連接埠分桶普及率) 差異時，皆可能淪為新的 Shortcut (捷徑)。

第三，鑒於 Adaptation (適應) 能力高度依賴架構，針對 Resource-Efficient (資源效率型) 模型進行神經架構搜尋（NAS），以內建 Domain Generalization 能力，將是兼顧 Edge Hardware (邊緣硬體) 限制與跨域穩健性的重要途徑。第四，需進一步檢視除連接埠外的其他潛在捷徑，例如時間模式、封包大小分布或協議標頭欄位，是否會在連接埠特徵被移除後取而代之。第五，未來可探索半監督或自監督的 Local Adaptation (局部適應) 機制，以降低對 Target-Domain Exposure (目標域暴露) 中標記樣本數量的依賴。最後，結合對抗訓練與域泛化技術，同時處理 Adversarial Perturbation (對抗擾動) 與跨網路偏移，以及透過 Federated Learning 在保護隱私的前提下聚合多網路知識，亦是極具潛力的後續方向。

## 論文問答

**Q1：這篇論文指出輕量級工業物聯網入侵偵測模型目前存在的核心問題是什麼？**
A：這篇論文指出，現有輕量級入侵偵測模型幾乎全部僅在單一資料集的域內進行訓練與測試，導致學界與產界產生「問題已解決」的錯覺。然而，真實的工業物聯網部署場景中，模型經常需要在與訓練環境完全不同的網路上運作，面對相異的裝置組成、流量模式與攻擊者行為。這種「同資料集評估」與「真實跨網路部署」之間的巨大落差，使得宣稱的高準確率難以反映模型在實際邊緣硬體上的可靠度。

**Q2：為何現行主流的單一資料集評估範式無法反映真實的工業物聯網部署條件？**
A：單一資料集評估預設了訓練與測試資料來自完全相同的底層分布，但實際上不同工業現場的網路拓撲、設備類型與協定組成皆存在顯著差異。在這種封閉環境下，模型極易學習到資料集特有的捷徑，例如依賴特定連接埠號碼或裝置指紋等表面特徵，而非真正可遷移的攻擊行為模式。因此，一旦模型被部署到未見網路，這些投機性的關聯便會失效，導致效能急遽衰退。

**Q3：跨域泛化失效的問題為何對邊緣部署的輕量級模型特別關鍵？**
A：輕量級模型專為資源受限的邊緣硬體設計，其運算、記憶體與能源預算極為有限，因此成為工業物聯網入侵偵測的首選方案。然而，正是因為模型容量較小，它們更容易過度擬合訓練域的局部統計特性，將特定連接埠類別等粗粒度特徵誤認為攻擊的穩定指標。若僅憑域內準確率就將這類模型部署到關鍵基礎設施，一旦遭遇跨網路環境，其防禦缺口可能導致嚴重的安全漏洞。

**Q4：本研究採用的核心實驗方法為何？**
A：研究團隊選用四種具代表性的輕量級架構，包含決策樹與三種緊湊神經網路設計，先於單一來源域資料集上進行訓練，隨後在不重新訓練的條件下，直接對兩個結構相異的目標域資料集進行零樣本遷移測試。為了確保跨資料集比較的公平性，特徵表示被嚴格限制為三個資料集共有的屬性，避免來源域特有的資訊洩漏。這種設計直接模擬了邊緣裝置在缺乏大量本地標記資料時，必須立即上線運作的實際情境。

**Q5：本研究在隔離跨域失效原因方面的關鍵創新是什麼？**
A：不同於僅觀察效能衰退的既有研究，本文結合可解釋性分析與針對性消融測試，精確定位連接埠類別特徵為主要混淆因子。作者發現，即使將原始連接埠號碼粗化為廣泛的類別分桶，模型仍會將依賴轉移到這些粗粒度連接埠類別本身，顯示單純降低特徵解析度只是「搬移」而非「移除」捷徑。透過量化比較，研究進一步證明最具影響力的連接埠分類在來源域攻擊流量中的出現率，分別是 Gotham 目標域的約 96 倍與 WUSTL-IIoT-2021 目標域的約 435 倍，從而確立了泛化失效的具體機制。

**Q6：為何論文刻意比較人工平衡與自然不平衡的類別分布？**
A：過去文獻普遍採用人工平衡的類別分布作為評估標準，但這與真實工業網路中攻擊流量遠少於正常流量的自然不平衡狀態嚴重脫節。作者透過這項比較發現，評估協定的選擇竟能反轉「哪個目標網路更具挑戰性」的結論，顯示平衡測試會系統性地誤導對模型部署準備度的判斷。此設計選擇凸顯了在真實類別分布下進行跨網路評估的必要性，以避免對實際營運風險產生錯誤認知。

**Q7：實驗使用了哪些資料集，它們在本研究中各自扮演什麼角色？**
A：本研究使用 Edge-IIoTset 作為來源域訓練資料集，並以 Gotham 與 WUSTL-IIoT-2021 作為兩個獨立的目標域評估資料集。這三個資料集在來源網路、裝置組成與流量擷取格式上皆存在結構性差異，能夠有效模擬跨工業場域部署的真實情境。值得注意的是，這些資料集的原始發表文獻均僅報告域內結果，本研究則首次系統性地檢驗了輕量級模型在這些資料集之間的遷移能力。

**Q8：關於模型對連接埠類別特徵的依賴，實驗的主要發現為何？**
A：針對兩個最佳效能模型的可解釋性分析顯示，它們的決策幾乎完全仰賴粗粒度連接埠類別特徵。最具影響力的連接埠分類在來源域攻擊流量中的普及率，相較於 Gotham 高出約 96 倍，相較於 WUSTL-IIoT-2021 更高出約 435 倍。這種極端的分布偏斜證實模型並未學習到可泛化的攻擊行為，而是利用連接埠分桶普及率的域內統計偏差作為投機捷徑，且單純粗化連接埠解析度無法根除此問題。

**Q9：對抗穩健性與少量目標域暴露的實驗揭示了什麼結果？**
A：研究發現模型對對抗擾動的抵抗能力與其跨網路泛化表現完全無關，這意味著對抗穩健性無法作為跨域部署準備度的替代指標。相對地，透過少量目標域標記樣本進行微調後的效能恢復程度，會因架構不同而產生顯著差異，顯示並非所有輕量級設計都具備同等的局部適應潛力。這些結果提醒實務工作者，在挑選邊緣部署模型時，必須獨立檢驗其跨網路泛化與適應能力，而非僅參考對抗測試或域內準確率。

**Q10：實務工作者應如何重新思考邊緣型工業物聯網入侵偵測的部署準備度評估？**
A：實務工作者應摒棄「域內準確率足夠即可上線」的傳統思維，將跨網路評估列為強制性驗證項目。評估時必須採用自然不平衡的類別分布，以貼近真實營運條件，而非僅報告人工平衡下的理想數據。唯有如此，才能避免將僅會記憶來源域假象的模型部署至關鍵基礎設施，確保所選用的偵測器在異質工業環境中仍能維持可靠運作。

**Q11：評估協定能夠反轉目標網路挑戰難度排序的發現，對產品開發有何實務意涵？**
A：這項發現意味著產品開發者與安全稽核人員必須慎選與真實世界類別分布一致的評估指標，而非依賴人工平衡測試集所呈現的假象。若廠商僅以平衡資料展示優異的跨資料集準確率，同一模型在自然不平衡的實際部署中，可能在原本被認為較簡單的網路上發生災難性失效。因此，工業物聯網安全產品的採購與認證流程應強制要求揭露模型在不平衡、跨網路條件下的表現，以防範過度樂觀的風險評估。

**Q12：這些發現將如何影響未來工業物聯網資料集與基準測試標準的設計？**
A：研究結果強烈主張未來的入侵偵測基準應將跨網路評估視為標準要求，而非可有可無的擴充項目。資料集設計者應考慮主動移除或匿名化原始連接埠號碼、IP 位址等來源識別特徵，以鼓勵模型學習行為導向而非身份導向的表示。此外，基準測試倡議應採納自然不平衡的評估協定，確保公開的指標能真實反映保護異質、資源受限工業網路所面臨的挑戰。

**Q13：從研究設計來看，本研究存在哪些可推論的局限性？**
A：本研究僅評估四種輕量級架構，且僅在三個特定工業物聯網資料集間測試遷移性，其發現未必能推廣至所有邊緣可部署模型。為了確保跨資料集比較的可行性，特徵表示被限制為三個來源共有的屬性，這可能排除了某些有助於提升泛化能力但並非普遍存在的資訊。此外，研究雖然精確定位了連接埠類別捷徑，但並未排除其他潛在的資料集特定混淆因子，這些因子同樣可能導致跨域泛化失效。

**Q14：基於這項工作，未來研究應正視哪些失敗案例或負面結果？**
A：一項重要的負面結果是，將連接埠解析度粗化為廣泛分桶並未移除捷徑，模型僅是將依賴轉移至更粗粒度的類別，泛化缺口依舊存在。這顯示未來研究必須面對更困難的問題：設計從根本上對網路特定識別符保持不變的特徵表示，而非僅對其進行模糊化。此外，少量樣本適應的恢復程度呈現顯著的架構依賴性，暗示某些輕量級設計可能天生不適合域適應，亟需深入探討阻礙或促進領域遷移的歸納偏置。

**Q15：本研究對改善輕量級工業物聯網入侵偵測的跨域泛化提出了哪些未來方向？**
A：本研究暗示未來應優先發展行為導向的特徵工程，徹底排除對連接埠、IP 等來源欄位的依賴，可借鏡近期主動移除這類識別符的物聯網資料集設計。另一關鍵方向是開發專為少量樣本域適應最佳化的輕量級架構，因為現有設計的恢復潛力差異極大。最後，學界與產界應將跨網路、自然不平衡條件下的評估列為強制驗證步驟，使模型僅在證明其於結構相異的工業網路間皆具穩健性後，方獲准進入實際部署階段。

## 實務應用指南

### 適用場景

**多廠區智慧製造邊緣防護**  
當企業在多個生產據點部署輕量級入侵偵測模型時，各廠區的裝置組成、控制器品牌與流量模式往往不同。本研究的跨網路評估框架可直接用於驗證：於 A 廠區訓練的模型，能否在 B 廠區的資源受限閘道器上維持偵測效能，避免因域內準確率過高而產生虛假的安全信心。

**關鍵基礎設施分散式 IIoT 閘道**  
能源、水利或交通系統常在偏遠場站部署邊緣硬體，這些場站的網路拓撲與總部實驗環境差異極大。此場景適用本文的「零樣本遷移」評估流程，在正式上線前即識別模型是否過度依賴特定連接埠類別等捷徑特徵，並預先規劃小樣本局部適應策略。

**供應鏈異質裝置整合**  
製造業導入第三方或客戶現場的 IIoT 設備時，常面臨訓練資料與實際流量結構相異的問題。本文的特徵限制方法（僅使用跨來源可用的屬性）與跨資料集驗證流程，可作為導入前評估協定的一部分，確保輕量級模型不會因裝置差異而全面失效。

**託管式 IIoT 安全監控服務（MSSP）**  
資安服務商需以單一輕量級模型架構服務多家客戶的工業網路。本研究指出，人工平衡類別分布的評估會嚴重誤導效能排名；MSSP 可依據本文建議，改採自然不平衡類別分布進行跨網路評估，並為不同客戶選擇適應性較佳的模型架構。

**傳統工控網路輕量化升級**  
老舊工業場域欲以低運算、低記憶體預算的邊緣硬體取代伺服器級入侵偵測時，常缺乏大量標記資料重新訓練。本文評估「少量目標域暴露即可恢復效能」的實驗結果，可協助業者判斷：僅蒐集少量目標網路標記樣本進行微調，是否足以讓特定輕量架構恢復可接受的偵測率。

### 實作前置條件

**資料層面**  
至少需要三個結構相異的 IIoT 資料集：一個作為來源域（訓練用），兩個以上作為目標域（跨網路測試用）。各資料集必須能萃取出一組共同屬性的特徵表示（例如：通訊協定類型、粗粒度連接埠類別、封包長度統計值），且需保留原始攻擊流量的自然不平衡類別分布，以供對照實驗。若資料集僅提供原始封包（PCAP），需具備擷取並對齊這些共通特徵的前處理能力。

**運算層面**  
訓練階段僅需一般工作站等級資源；但為了貼近真實部署條件，需準備與目標場域一致的邊緣硬體（如 ARM Cortex 系列、輕量 FPGA 或嵌入式 GPU）作為推理效能與記憶體佔用的驗證平台。此外，需保留足夠空間執行可解釋性分析（如 SHAP 或特徵重要性計算）與對抗擾動生成實驗。

**技術與知識層面**  
團隊需熟悉工業網路流量特性（如 Modbus、OPC-UA、MQTT 等協定在 IIoT 中的行為模式），具備網路特徵工程經驗，並能操作至少四種輕量級機器學習模型（如決策樹與三種緊湊神經網路設計）。同時需理解類別不平衡評估指標（如 F1-score、MCC），而非僅依賴準確率。

---

### 實作步驟建議

**1. 建立跨網路統一特徵表示**  
在資料前處理階段，嚴格限制特徵僅使用所有資料集共有的屬性。特別注意連接埠欄位：若採用粗粒度連接埠類別特徵，需記錄各類別在來源域與目標域攻擊流量中的普及率，作為後續比對基線。

**2. 於來源域訓練並保留自然分布**  
使用來源域資料集訓練四種輕量級架構。訓練時避免過度採樣或欠採樣，保留自然不平衡類別分布，以確保後續評估能反映真實部署場景。

**3. 執行零樣本跨網路評估**  
將訓練完成的模型直接套用至兩個目標網路資料集，不進行重新訓練。記錄各模型在域內與跨網路的效能落差，並觀察哪個目標域的挑戰更大——注意：此結果可能因評估協定（人工平衡 vs. 自然分布）而反轉。

**4. 可解釋性分析定位捷徑特徵**  
針對域內表現最佳的一至兩個模型，執行可解釋性分析。檢視模型是否過度依賴單一或少數連接埠分桶類別；若發現最具影響力的類別在來源域攻擊流量中的出現率遠高於目標域（如研究中所示達 96 至 435 倍），即確認捷徑特徵存在。

**5. 消融測試驗證特徵粒度影響**  
將連接埠解析度進一步調整（或移除該特徵）後重新訓練與評估。若跨網路效能仍未改善，則證明單純粗化特徵並未移除捷徑，只是將問題從「原始連接埠記憶」轉移至「粗粒度連接埠類別依賴」。

**6. 於自然不平衡分布下重測**  
分別在人工平衡與自然不平衡兩種設定下計算效能指標。比較兩種設定下，哪個目標網路被判定為「較難泛化」的結論是否一致；若出現反轉，則應以自然分布的評估結果作為部署依據。

**7. 獨立評估對抗穩健性**  
對各模型產生對抗擾動樣本，測試其對抗穩健性。將此結果與跨網路泛化效能進行比對——依據研究發現，兩者無顯著關聯，因此不應以「對抗樣本抵抗力強」推論「跨網路適應力佳」。

**8. 小樣本目標域微調與架構選型**  
從每個目標網路抽取少量標記樣本（如 1% 至 5%），對各模型進行微調。記錄各架構的效能恢復程度；由於恢復能力具架構相依性，應選擇在跨域落差與適應性之間取得最佳平衡的設計，而非僅看域內準確率。

**9. 上線後持續監控特徵漂移**  
部署後持續追蹤關鍵連接埠類別特徵的分布變化。若目標網路流量中某些高影響力類別的出現率顯著偏離訓練時的統計特性，應觸發局部適應或重新評估流程。

### 潛在風險與注意事項

**捷徑特徵陷阱**  
粗粒度連接埠類別特徵看似比原始連接埠號碼更通用，實則可能將捷徑從「記憶特定埠號」轉化為「依賴特定類別的出現頻率」。若來源域與目標域的攻擊者在連接埠使用習慣上差異極大（如研究發現高達數百倍的普及率差距），模型將在跨網路評估中崩潰。建議在可解釋性分析中優先檢查此類頻率差異，而非僅比較特徵名稱是否一致。

**人工平衡評估的誤導**  
許多基準研究採用人工平衡類別分布以獲得亮眼的準確率，但這會掩蓋模型在真實、傾斜流量中的表現，甚至反轉不同目標網路的難易度排序。實務上應一律以自然不平衡類別分布作為部署準備度的主要評估標準。

**對抗穩健性與跨域泛化脫鉤**  
團隊可能誤以為通過對抗樣本測試的模型就具備足夠的「強健性」以應對未知網路。本文明確顯示對抗穩健性與跨網路泛化失效無關，兩者需分開測試、分別驗證，不可相互替代。

**架構相依的適應能力**  
並非所有輕量級模型都能透過少量目標域資料有效恢復。某些緊湊神經網路設計可能因參數量過少或表徵空間受限，微調後仍無法彌補跨域落差。建議在產品化前，針對候選架構執行標準化的小樣本適應基準測試。

**特徵可用性落差**  
若目標網路的流量擷取格式或前置處理流程與訓練時不同（例如缺少某些統計欄位），統一特徵表示可能被迫捨棄更多資訊，進一步加劇效能衰退。需在資料治理階段即確保跨網路特徵的可用性與語義一致性。

### 與其他技術的整合建議

**SIEM / SOAR 平台**  
將輕量級模型的跨網路不確定性量化（如以目標域微調前的效能落差作為信心權重）後，再傳送至 SIEM。對於來自高風險目標網路的告警，若模型處於低信心區間，SOAR 可自動升級調查優先級或觸發額外封包取證，而非僅依賴單一二元判斷。

**網路微分段（Micro-Segmentation）**  
與其部署單一模型監控整個 IIoT 骨幹，不如結合網路微分段架構，在每個區段部署專屬輕量級模型。各區段可視為獨立「目標域」，利用本文的跨網路評估方法預先篩選最適合該區段裝置組成的架構，降低單一模型全面失效的風險。

**聯邦學習（Federated Learning）**  
在無法集中收集各廠區資料的場景下，可將本文發現的「捷徑特徵」資訊作為聯邦聚合的約束條件。例如，於聯邦訓練中抑制對高風險連接埠類別的全局權重，促使模型學習更行為導向的表徵，而非特定網路的統計捷徑。

**數位孿生（Digital Twin）**  
於實際部署前，在數位孿生環境中模擬目標網路的流量特性與攻擊劇本，執行跨網路評估。透過孿生平台快速產生結構相異但特徵分布可控的測試資料，驗證輕量級模型在面對未見網路時的表現，減少直接在實體產線上試錯的成本。

**OT / IT 閘道器**  
在 OT 與 IT 交界處部署輕量級 IDS，利用閘道器標準化不同下層 IIoT 協定的特徵表示。由於閘道器通常具備較邊緣感測器更充裕的運算、記憶體與能源預算，可在此處執行較複雜的特徵對齊與初步可解釋性分析，再將精簡後的特徵向量分發至更底層的資源受限節點。

### 給不同背景讀者的閱讀建議

**初學者**  
請先聚焦於「為什麼同資料集準確率會誤導人」以及「連接埠號碼為何是陷阱」。本文的核心訊息是：模型在訓練網路上表現再好，也不代表它能看懂另一個工廠的網路。建議從第三節的跨網路評估結果與可解釋性分析開始讀，理解「捷徑」如何讓模型投機取巧，並記得在實務上永遠要求「跨網路測試」而非只看單一資料集的分數。

**AI 工程師**  
請重點關注特徵工程限制、消融測試設計，以及不同輕量級架構在小樣本微調下的恢復曲線。本文對你的實作價值在於：提供了一套可複製的跨域驗證流程，特別是「統一特徵表示 → 零樣本遷移 → 解釋性定位 → 自然分布重測」的 pipeline。建議仔細檢視連接埠解析度實驗的細節，並將「對抗穩健性與跨域泛化無關」這項發現納入你的模型驗收清單，避免用錯誤的指標背書。

**研究人員**  
本文的貢獻在於將跨資料集泛化失效的現象，從一般企業網路延伸至 IIoT 輕量級模型，並以消融實驗證明「粗化特徵並未移除捷徑，只是轉移捷徑」。建議深入探討第四節的量化分析（96 倍與 435 倍普及率差異），以及評估協定如何反轉目標域難度排序。若你正在設計新的 IIoT 基準資料集，請考慮將跨網路評估與自然不平衡分布列為強制性測試項目，而非選配。

**產品經理**  
對你而言，最重要的結論是「部署準備度無法從域內準確率推論」。在評估任何輕量級 IIoT 入侵偵測方案時，請要求供應商提供跨網路（而非僅同資料集）的效能數據，並確認測試是在自然不平衡類別分布下進行。此外，「少量目標資料即可恢復」的能力因架構而異，這意味著選型時需預留適應性驗證的時間與目標場域標記資料預算，切勿因單一實驗室數據而壓縮上線前的風險評估週期。
