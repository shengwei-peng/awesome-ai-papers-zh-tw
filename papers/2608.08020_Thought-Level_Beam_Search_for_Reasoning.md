## ⚡ TL;DR

測試時運算擴展效率低落，現有平行取樣與減法式剪枝無法有效把運算分配到有前景的部分軌跡。

## 摘要翻譯

測試時運算擴展（test-time compute scaling）是大型推理模型（large reasoning models, LRMs）效能的主要驅動力，但極度的低效制約了現有方法，使關鍵問題從「應投入多少運算」轉向「應將運算分配至何處」。我們將測試時推理（test-time reasoning）形式化為針對部分軌跡（partial trajectories）的受限運算分配問題（constrained compute allocation problem）。在固定硬體預算（hardware budget）下，現有範式無法主動將運算分配給最具前景的部分進展（partial progress）：傳統平行取樣（parallel sampling）獨立處理各條軌跡，造成嚴重的記憶體瓶頸（memory bottleneck）；減法式剪枝（subtractive pruning）則導致硬體資源閒置，且無法主動且充分地改變輸出分布（output distribution）。為克服此二元對立，我們提出 Gambit，一種執行思維層級束搜尋（thought-level beam search）的推論演算法（inference algorithm）。Gambit 定期剪除不具前景的軌跡（pruning unpromising trajectories），並立即從高品質前綴（high-quality prefixes）進行分支（branching），透過輕量評分器（light-weight scorer）探測隱藏狀態（hidden states），動態地將運算集中於最具前景的推理軌跡（reasoning traces），同時持續維持高硬體利用率（hardware utilization）。在多個模型與基準測試上的廣泛評估顯示，Gambit 嚴格優於現有基線。在相同硬體限制下，相較於剪枝基線，我們的方法在 HMMT-24 上帶來最高達 +6.7% 的絕對準確率增益（absolute accuracy gain），在 AIME-25 上達 +3.3%；軌跡完成（trace completion）吞吐量超過兩倍；相較於標準平行取樣，總 token 消耗量（token consumption）最高減少 68.5%。

### 核心貢獻（3～5點）
- 將測試時推理形式化為針對部分軌跡的受限運算分配問題，把研究焦點從「投入多少運算」轉移到「運算應分配至何處」。
- 提出 Gambit 推論演算法，執行思維層級束搜尋：定期剪除不具前景的軌跡，並立即從高品質前綴分支，以輕量評分器探測隱藏狀態來動態集中運算。
- 在維持連續高硬體利用率的同時，顯著改善記憶體效率與輸出分布的品質，克服傳統平行取樣與減法式剪枝的兩難。
- 在多個模型與數學競賽基準測試上進行廣泛評估，證明 Gambit 嚴格優於現有基線。
- 在相同硬體限制下，於 HMMT-24 與 AIME-25 分別帶來 +6.7% 與 +3.3% 的絕對準確率增益，軌跡完成吞吐量超過兩倍，並相較標準平行取樣減少最高 68.5% 的 token 消耗量。

### 適合對象
本論文適合從事大型語言模型推理、測試時運算擴展、高效率推論系統與解碼演算法研究的學者與工程師；對於關注如何在固定硬體預算下提升大型推理模型數學推理效能與吞吐量的系統研究者與實務部署人員亦具高度參考價值。

## 深度分析

#### 方法論解析

本文將測試時推理（test-time reasoning）重新形式化為一個在部分軌跡（partial trajectories）上的受限運算分配問題（constrained compute allocation problem）：在固定硬體預算（hardware budget）下，必須決定把計算資源投放到哪些尚未完成的推理軌跡（reasoning traces）上。作者指出，現行兩大範式各有根本缺陷：傳統平行取樣（parallel sampling）把每條軌跡當成獨立試驗，導致記憶體瓶頸（memory bottleneck）與大量冗餘計算；減法式剪枝（subtractive pruning）雖能終止低品質軌跡，卻讓釋出的運算容量閒置，無法主動改變輸出分布（output distribution）。為此，作者提出 Gambit（Gambit）這個推論演算法（inference algorithm），核心精神是執行思維層級束搜尋（thought-level beam search）：在推理過程中週期性地剪除不具前景的軌跡（pruning unpromising trajectories），並立即從高品質前綴（high-quality prefixes）進行分支（branching），把計算動態集中到最有潛力的推理路徑上。

Gambit 的設計對應三個緊密耦合的挑戰：

1. **檢查點儲存（checkpointing）有潛力的部分軌跡**  
   作者觀察到，成功與失敗的軌跡往往在前期共享嚴謹的中間前綴，之後才分歧。因此必須在生成過程中捕捉這些狀態。Gambit 使用輕量評分器（light-weight scorer）探測模型的隱藏狀態（hidden states），可採用現成的 hidden-state probes（改編自 STEP）或自訂的序列評分器。然而，早期推理不完整，訊號雜訊高，單純依賴評分器很脆弱。為此，Gambit 引入嚴格的 warm-up threshold（暖身閾值）：在達到足夠的推理深度之前，不進行評分與檢查點儲存，確保只把邏輯上穩定的前綴保留下來。

2. **主動運算重新分配（active compute reallocation）以放大有前景的軌跡**  
   僅僅終止低分軌跡無法改變底層取樣分布（sampling distribution）。Gambit 透過週期性的同步剪枝—分支操作（synchronized prune-and-branch），把被剪除軌跡釋出的容量立刻用來擴展高分前綴，從而主動把輸出分布推向正確答案。這與單純減法式剪枝有本質區別：後者只會讓 GPU 逐漸閒置，而 Gambit 保持活躍計算量。

3. **維持硬體利用率（hardware utilization）**  
   平行取樣會快速塞滿 KV cache，造成現代推論引擎（如 vLLM）中的嚴重排隊延遲；減法式剪枝則造成硬體飢餓（hardware starvation）。Gambit 採用零和分配政策（zero-sum allocation policy）：維持固定大小的活躍軌跡池（active trace pool），剪除一條軌跡就立即從高品質前綴分支出一條新軌跡填補，從而讓 GPU 在整個解碼過程中保持高負載。

此外，為了平衡探索（exploration）與利用（exploitation），避免所有資源都擠到單一最高分配軌跡造成貪婪崩潰（greedy collapse），Gambit 使用解耦記憶體管理（decoupled memory management）機制，避免過度集中於單一前綴。整體而言，Gambit 把測試時運算擴展（test-time compute scaling）從被動取樣轉變為主動、系統感知的搜尋過程，並且直接建構在 vLLM（vLLM）之上，系統開銷低於 1%。

#### 實驗數據解讀

作者在 AIME（AIME-25）、HMMT（HMMT-24）與 GPQA-Diamond 等具挑戰性的數理推理基準測試（benchmarks）上進行評估，涵蓋不同模型架構（例如 Qwen3-8B（Qwen3-8B）），並在相同硬體限制（如 NVIDIA B300（NVIDIA B300））下與基線比較。主要結果可從三個指標解讀：

- **準確率（accuracy）**：相較於積極的減法式剪枝基線，Gambit 在 HMMT-24 上取得 +6.7% 的絕對準確率增益（absolute accuracy gain），在 AIME-25 上取得 +3.3%。這顯示單純終止低品質軌跡不足以提升最終答案正確率；必須把釋出的運算主動重新分配到高品質前綴，才能實質改變輸出分布。HMMT 的增益高於 AIME，可能反映 HMMT 題目更長、推理更脆弱，因而更能從「保留共享的有前景前綴（shared promising prefix）」與「分支探索多條後續」中獲益。

- **Token 消耗量（token consumption）**：相較於標準平行取樣（standard parallel sampling），Gambit 最多減少 68.5% 的總 token 使用量。這來自兩方面：一是低品質軌跡被提前剪除，不必生成到最後；二是高品質前綴被重複利用，避免平行取樣中反覆從頭生成相同前段。值得注意的是，這個數字是相對於平行取樣，而非相對於減法式剪枝；後者本身也能節省 token，但無法像 Gambit 同時提升準確率。

- **吞吐量（throughput）與延遲（latency）**：Gambit 在軌跡完成（trace completion）的吞吐量上達到 >2× 的提升，且系統開銷 <1%。這說明固定大小的活躍軌跡池有效緩解了記憶體瓶頸，避免 vLLM 因 KV cache 爆滿而排隊；同時零和分配政策防止硬體飢餓，使 GPU 在整個解碼過程中維持高利用率。

綜合來看，實驗結果支持 Gambit「嚴格支配（strictly dominates）」現有基線的宣稱：在相同硬體預算下，它同時提升準確率、降低 token 消耗、並加快有效吞吐量。這三項指標通常存在權衡（例如增加取樣數可提升準確率但大幅增加 token 與延遲），Gambit 能同時改善，顯示其計算分配策略確實比被動平行取樣更接近帕雷托最優。

#### 與現有研究的比較

Gambit 的定位介於傳統測試時運算擴展、推論時間搜尋（inference-time search）與高效能服務（efficient serving）三條研究線之間，主要改進與限制如下：

**相對於平行取樣與自一致性（Self-consistency）**  
平行取樣把每條推理軌跡視為獨立試驗，再透過自一致性進行多數決投票。這會造成大量冗餘：模型反覆探索退化路徑（degenerate pathways），且大量長軌跡同時駐留記憶體，形成記憶體瓶頸。Gambit 透過共享高品質前綴與主動運算重新分配，避免重複生成相同前段，並把資源導向正確機率較高的分支。

**相對於減法式剪枝（如 DeepConf、STEP）**  
DeepConf 與 STEP 等研究使用模型內部訊號（internal signals）進行基於分數的剪枝（score-based pruning），提前終止低分軌跡以減少 KV cache 壓力。然而，它們屬於「只減不加」：被終止的軌跡釋出的容量閒置，導致硬體飢餓，且底層取樣分布幾乎不變。Gambit 的關鍵差異在於「剪枝後立即分支」，把釋出的運算轉化為對高品質前綴的放大，從而主動改變輸出分布。

**相對於樹狀思維（Tree-of-Thoughts, ToT）與蒙地卡羅樹搜尋（MCTS）**  
ToT 與 MCTS 把推理視為由過程獎勵模型（Process Reward Models, PRMs）或價值函數引導的結構化搜尋。它們的優勢在於平衡探索與利用，但其非同步、不對稱的擴展方式與現代大型語言模型（LLM）同步、大批次（large-batch）的推論特性相衝突。Gambit 把搜尋重新設計為硬體受限的同步束分配：透過固定大小的活躍軌跡池與週期性同步剪枝—分支，使其能直接運行於 vLLM 等現代推論引擎。

**相對於過程獎勵模型（PRMs）**  
PRMs 能精確評估中間步驟，但計算成本高。Gambit 採用輕量評分器探測隱藏狀態，大幅降低每次評估的開銷；同時以 warm-up threshold 緩解早期訊號雜訊，彌補輕量評分器可能不夠穩健的問題。

**主要限制**  
首先，Gambit 的成效高度依賴輕量評分器的品質：若評分器系統性錯誤地將有潛力的前綴判為低分，剪枝與分支反而會放大錯誤。其次，warm-up threshold、剪枝週期、活躍池大小、分支數量等超參數需要針對不同任務與模型調整，泛化性仍需更多驗證。第三，固定大小的活躍軌跡池雖能維持利用率，但若池子過小可能限制多樣性，導致過早收斂到少數模式。第四，目前評估集中在數學與科學推理任務，對於結構化程度較低或需要創意發散的任務（如開放式寫作、程式碼生成中的多樣化解法）是否同樣有效，仍屬未知。最後，隱藏狀態探針通常與特定模型架構綁定，跨模型遷移可能需要重新訓練或校準。

#### 可重現性評估

本文在可重現性方面提供了相當正面的基礎設施：

- **程式碼開源**：作者已將程式碼釋出於 https://github.com/Dao-AILab/Gambit.git，這大幅降低重現門檻。實作直接建構在 vLLM（vLLM）之上，後者為廣泛使用的開源推論引擎，社群對其部署與調校相對熟悉。
- **資料集公開**：AIME（AIME-25）、HMMT（HMMT-24）與 GPQA-Diamond 均為公開可取得的基準測試，無需特殊授權即可使用。
- **模型權重**：文中提及的 Qwen3-8B（Qwen3-8B）為開源模型權重，其他模型若同樣採用開源權重（如 Llama、DeepSeek 系列），則重現性更高。

然而，仍有幾項潛在挑戰：

- **超參數與實作細節**：雖然程式碼已開源，但從提供的摘要與引言無法得知 warm-up threshold、beam 週期、活躍軌跡池大小、分支因子、評分器訓練資料與架構等關鍵細節。這些細節通常出現在論文附錄或程式碼文件中，重現時必須仔細對照。
- **硬體環境**：實驗使用 NVIDIA B300（NVIDIA B300）等最先進硬體（state-of-the-art hardware），並強調在相同硬體限制下比較。若研究者使用不同 GPU 或記體體配置，KV cache 壓力與排隊行為可能不同，吞吐量與延遲數字會有所差異。
- **評分器訓練**：若 Gambit 使用自訂序列評分器或改編自 STEP 的 hidden-state probes，則需要對應的訓練資料與標籤。雖然論文可能提供預訓練探針，但若無法取得，研究者需自行收集過程標籤並重新訓練，這會增加重現難度。
- **vLLM 版本相依性**：推論引擎的版本差異可能影響排程、記憶體管理與 KV cache 行為，重現時需鎖定與論文相同的 vLLM 版本與相關依賴。

整體而言，Gambit 的可重現性優於許多僅提供數據表的論文，但完整重現仍需仔細處理超參數、評分器訓練與硬體環境。

#### 未來研究方向

Gambit 開啟了數個值得後續探索的方向：

1. **更強大且可遷移的評分器**  
   目前使用輕量 hidden-state probes 或自訂序列評分器，未來可研究如何結合過程獎勵模型（PRMs）與輕量內部訊號，形成級聯式評分：早期使用低成本探針，後期引入較準確但昂貴的 PRM。此外，開發跨模型架構通用的隱藏狀態探針，可提升方法的可遷移性。

2. **自適應超參數調控**  
   固定 warm-up threshold 與剪枝週期可能對簡單題目過於保守、對困難題目過於激進。未來可根據當前軌跡長度、評分器不確定性、問題難度估計等訊號，動態調整檢查點時機與分支強度。

3. **理論分析**  
   目前結果以實證為主，未來可建立正式框架，分析在何種條件下 thought-level beam search 相對於平行取樣具有更低的後悔值（regret）或更高的正確答案機率，並給出運算預算（compute budget）與準確率之間的理論權衡。

4. **跨裝置與多節點擴展**  
   Gambit 目前聚焦單一 GPU 或節點內的零和分配。未來可將固定大小活躍池的概念擴展到多 GPU、多節點環境，並與推測解碼（speculative decoding）、前綴快取（prefix caching）等技術結合，進一步提升吞吐量。

5. **多樣性與探索機制**  
   為避免活躍軌跡池過度集中於少數前綴，可引入顯式的多樣性獎勵，例如基於軌跡間相似度的行列式點過程（DPP）選擇，或 entropy-based 的探索獎勵，確保分支不僅放大高分前綴，也保留足夠的探索空間。

6. **更廣泛的任務與模態**  
   除了數學與科學推理，未來可評估 Gambit 在程式碼生成、定理證明、多步驟規劃（agentic planning）、多模態推理等任務上的效果。這些任務的推理結構與數學題不同，可能需要重新定義「思維層級」的邊界。

7. **與測試時訓練（test-time training）結合**  
   Gambit 專注於推論階段的運算分配，未來可探索與測試時微調或模型更新機制結合：在搜尋過程中根據新產生的軌跡即時調整模型參數，進一步提升推理能力。

8. **成本與能源指標**  
   除了 token 消耗量與吞吐量，未來可納入牆鐘時間（wall-clock time）、能源消耗與金錢成本等更貼近實際部署的指標，全面評估 Gambit 在商業化服務中的價值。

## 論文問答

**[Background & Motivation]**

**Q1：這篇論文主要想解決什麼問題？**
A：本文指出，雖然測試時運算擴展（test-time compute scaling）是大型推理模型（LRMs）進步的關鍵驅動力，但現有方法極度沒效率，導致邊際效益遞減。作者將測試時推理形式化為「在硬體預算限制下，對部分軌跡（partial trajectories）進行運算分配」的問題。核心問題已從「要花多少運算」轉變為「要把運算分配到哪裡」，才能讓額外的推論計算真正轉化為準確率提升。

**Q2：傳統平行取樣（parallel sampling）與減法式剪枝（subtractive pruning）各有哪些根本缺陷？**
A：傳統平行取樣把每條推理軌跡當成獨立試驗，會重複探索大量退化路徑，造成嚴重的記憶體瓶頸與冗餘計算，且多數軌跡最終仍導向錯誤答案。減法式剪枝雖然能提前終止低分軌跡以減輕記憶體壓力，但它只是把釋放出的容量閒置，無法主動把運算重新分配到高潛力的前綴上。結果是輸出分布幾乎沒有改變，GPU 還會因為活躍軌跡減少而面臨硬體飢餓（hardware starvation）。

**Q3：為什麼「主動把運算分配給有前景的部分進展」如此重要？**
A：推理過程本質上很脆弱，但成功與失敗的軌跡往往在前期共享嚴謹的推理前綴，之後才分叉。若能及時檢查點儲存（checkpointing）這些高品質前綴，就能避免一個後續小錯誤導致之前所有正確進展被浪費。更重要的是，主動放大這些前綴能真正改變取樣分布，使模型傾向產出正確答案，而不是被動地大量取樣。

**[Method & Innovation]**

**Q4：Gambit 的核心機制是什麼？**
A：Gambit 是一種在「思維層級」（thought-level）執行束搜尋（beam search）的推論演算法，它把測試時推理視為對部分軌跡的搜尋過程。演算法會週期性地剪除不具前景的軌跡，並立即從高品質前綴分支（branch）出多條後續軌跡，把運算動態集中到最有希望的推理路徑上。整個過程透過輕量評分器探測隱藏狀態來打分，並維持固定大小的活躍軌跡池，以確保硬體利用率。

**Q5：Gambit 如何對應文中提出的三大挑戰？**
A：針對「檢查點儲存有前景的前綴」，Gambit 使用模型內部訊號（如隱藏狀態探針或序列評分器），並加入嚴格的預熱門檻（warmup threshold），等到推理深度足夠、訊號較穩定後才進行打分與儲存。針對「放大有前景的軌跡」，它採用週期化的同步剪枝—分支操作，把被釋放的運算主動重新分配給高分前綴。針對「維持硬體利用率」，它實施零和分配政策（zero-sum allocation），讓活躍軌跡數量保持恆定，避免記憶體爆滿或 GPU 閒置。

**Q6：Gambit 有哪些關鍵設計選擇，為何這樣設計？**
A：首先是嚴格的預熱門檻，因為早期推理不完整，內部訊號雜訊很大，延遲打分能避免錯誤地儲存或剪除軌跡。其次是解耦的記憶體管理機制，防止演算法過度集中於單一最高分軌跡而導致貪婪崩潰（greedy collapse），從而平衡探索與利用。最後是固定大小的活躍軌跡池，這讓系統在整個解碼過程中保持持續高硬體利用率，並與現代大型批次推論引擎相容。

**[Experiments & Results]**

**Q7：論文在哪些基準測試與模型上驗證 Gambit？**
A：實驗涵蓋 AIME-25、HMMT-24 與 GPQA-Diamond 等具挑戰性的數學與科學推理基準。模型方面則跨越多種架構，包括 Qwen3-8B 等開源大型推理模型。整個系統建構在 vLLM 推論引擎之上，並與標準平行取樣及減法式剪枝基線進行比較。

**Q8：Gambit 的主要量化結果為何？**
A：在相同硬體限制下，Gambit 相較於積極剪枝基線在 HMMT-24 上帶來 +6.7% 的絕對準確率增益，在 AIME-25 上提升 +3.3%。與標準平行取樣相比，總 token 消耗量最高可減少 68.5%。此外，Gambit 的軌跡完成吞吐量（trace completion throughput）超過兩倍，而系統開銷低於 1%。

**Q9：這些結果暗示了什麼樣的消融或比較洞察？**
A：Gambit 在多個模型與基準上「嚴格優於」（strictly dominates）現有基線，顯示單純增加取樣數或只做減法剪枝都不夠。準確率、吞吐量與 token 效率同時提升，說明主動重新分配運算不僅改善答案品質，也解決了硬體閒置與記憶體瓶頸。預熱門檻與解耦記憶體管理的設計則確保搜尋不會過早收斂或過度集中於少數軌跡。

**[Applications & Impact]**

**Q10：Gambit 在哪些實際場景特別有價值？**
A：它特別適合需要生成長思維鏈（chain of thought）的高風險數學與科學問題求解，例如競賽數學或研究級推理任務。在 GPU 記憶體有限、延遲敏感的服務環境中，Gambit 能在相同硬體上完成更多問題。對於以 API 形式提供推理能力的產品，它也能降低每題成本並縮短回應時間。

**Q11：若要在產品中部署 Gambit，需要考慮哪些因素？**
A：Gambit 已整合於 vLLM，並使用輕量評分器探測隱藏狀態，額外系統開銷極低，部署門檻相對友善。由於活躍軌跡池大小固定，可避免 KV cache 爆滿造成的排隊延遲。不過仍需針對不同模型與任務調整預熱門檻、剪枝頻率與分支策略，以在探索與利用之間取得最佳平衡。

**Q12：這項研究對整個領域可能帶來什麼影響？**
A：它把測試時運算擴展的研究焦點從「堆疊計算量」轉向「智慧分配計算」，為後續工作提供新的問題框架。Gambit 也搭起了結構化搜尋（如 MCTS、Tree-of-Thoughts）與現代大型批次 LLM 服務之間的橋樑，證明兩者可以結合為同步的硬體感知束搜尋。未來的推論系統可能會更普遍地採用這種「主動、系統感知」的搜尋範式。

**[Limitations & Future]**

**Q13：論文承認了哪些限制？**
A：早期推理訊號本身帶有雜訊，因此必須依賴預熱門檻，這可能錯失某些在淺層就顯現潛力的前綴。輕量評分器雖然高效，但判斷力仍不如昂貴的過程獎勵模型（PRM），可能在某些邊界案例上出錯。此外，Gambit 需要存取模型內部隱藏狀態並進行同步批次管理，對於純黑箱 API 的適用性會受到限制。

**Q14：Gambit 可能在什麼情況下失敗？**
A：對於模型根本無法解決的最難實例，例如文中提到 Qwen3-8B 在 AIME-2025 上即使取樣 512 條軌跡仍會失敗，Gambit 也無法突破模型能力上限。如果輕量評分器在預熱門檻之前或之後錯誤地剪除了正確前綴，搜尋可能會過早崩潰。另外，若問題在極早期就出現無法挽回的錯誤，且該錯誤發生在打分啟動之前，則相關運算仍會被浪費。

**Q15：未來可以朝哪些方向延伸這項工作？**
A：未來可發展更穩定、在淺層推理即可信賴的過程獎勵模型或內部訊號探針，以降低對預熱門檻的依賴。也可以結合自適應的束寬度與深度排程，甚至引入部分非同步元素，在保持硬體利用率的同時增加靈活性。更長遠來看，可將思維層級束搜尋擴展到多模態推理與分散式服務架構中。

1. **高難度數理與科學問答系統**  
   例如競賽數學（AIME、HMMT）、大學程度物理／化學題目求解，或企業內部 R&D 的複雜推導任務。這類問題正確軌跡稀少，Gambit 的思維層級束搜尋能把運算主動集中到少數有潛力的部分軌跡，避免平行取樣大量無效答案。

2. **長鏈推理的程式碼生成與除錯**  
   在需要多步驟規劃的軟體工程任務（如演算法設計、測試案例生成、錯誤定位）中，Gambit 可透過檢查點儲存高品質前綴，並在發現低品質分支時立即剪除並分支到更有希望的程式骨架，提升正確率與吞吐量。

   對於必須逐步檢視條文、引用與條件的長文件推理，Gambit 可在固定硬體預算下持續追蹤多條分析路徑，並利用輕量評分器即時判斷哪條論證前綴更值得深入，減少無謂的 token 消耗。

4. **低延遲、高硬體利用率的推理服務**  
   當 GPU 記憶體與 KV cache 成為瓶頸時（例如使用 vLLM 部署長思維鏈模型），Gambit 的恆定活躍軌跡池與零和分配策略可維持高硬體利用率，適合需要同時服務多名使用者、又希望控制成本的生產環境。

5. **需要主動運算重新分配的搜尋型 Agent**  
   例如多步工具呼叫、網頁瀏覽、資料庫查詢規劃等 Agent 系統，Gambit 能把被剪除路徑釋放的運算預算立即轉移到高品質前綴，避免減法式剪枝造成的硬體閒置與分布偏移不足。

## 實作前置條件

**資料前提**
- 需取得或建構目標領域的「過程級」驗證資料，例如帶有中間步驟正確性標註的數學解題軌跡，或能產生部分軌跡分數的程式執行回饋。
- 若使用隱藏狀態探針（hidden-state probes），需要收集模型在推理過程中各層 hidden states 與對應步驟標籤，以便訓練或微調輕量評分器。
- 建議準備與生產環境同分布的驗證集，用於校準 warm-up threshold、beam width 與分支頻率。

**運算前提**
- 至少具備一張可執行目標 LRM 推理的 GPU（論文使用 NVIDIA B300 等級），並安裝 vLLM 或相容的同步批次推理引擎。
- 需要足夠的 GPU 記憶體來維持恆定大小的活躍軌跡池；實際大小取決於模型參數量、最大思維鏈長度與 beam width。
- 若使用自訂序列評分器，需額外訓練與推理資源，但遠小於重新訓練主模型。

**技能前提**
- 熟悉 LLM 推理管線、KV cache 管理與 vLLM 的批次調度機制。
- 具備訓練輕量分類器或探針的經驗（PyTorch、Hugging Face Transformers）。
- 理解束搜尋、Self-Consistency、過程獎勵模型（PRM）與減法式剪枝的基本概念。
- 具備系統效能分析能力，能測量吞吐量、延遲、記憶體佔用與 token 消耗量。

## 實作步驟建議

1. **建立基線與問題分析**  
   先在目標任務上運行標準平行取樣（Self-Consistency）與現有減法式剪枝基線，記錄準確率、token 消耗量、GPU 記憶體佔用與完成延遲。確認瓶頸是記憶體飽和、硬體閒置，還是輸出分布偏移不足。

2. **選擇或訓練輕量評分器**  
   根據資源選擇：
   - 使用現成 hidden-state probe（如 STEP 提供的探針）進行快速驗證；
   - 或訓練自訂序列評分器，輸入為部分軌跡的 hidden states，輸出為該前綴的品質分數。
   在驗證集上評估評分器在不同推理深度的可靠性，特別注意早期步驟訊號雜訊高的問題。

3. **設定 warm-up threshold 與檢查點策略**  
   決定在多少個思考步驟或 token 之後才啟動評分與檢查點儲存。此閾值應足夠大，使前綴邏輯結構穩定；但也要避免過晚，導致浪費運算在無用分支上。

4. **實作恆定活躍軌跡池與週期性剪枝—分支**  
   在 vLLM 上層封裝排程器：
   - 維持固定數量的活躍部分軌跡；
   - 每隔固定步驟或 token 數，對所有活躍軌跡評分；
   - 剪除低分軌跡，並立即從高分前綴分支產生新軌跡，保持池大小恆定。
   確保分支操作能與 vLLM 的同步批次解碼對接，避免非同步擴展造成的硬體利用率下降。

5. **加入探索—開發平衡機制**  
   避免所有資源都集中到單一最高分軌跡。可透過分數加溫度抽樣、強制保留少量多樣性軌跡，或限制同一前綴的最大分支數，防止貪婪崩潰（greedy collapse）。

6. **端到端評估與迭代**  
   在相同硬體限制下比較 Gambit 與基線：準確率、吞吐量、總 token 消耗、完成延遲與記憶體峰值。根據結果調整 beam width、評分頻率、warm-up threshold 與分支策略。

7. **部署與監控**  
   將 Gambit 封裝為可重用的推論服務模組，並監控生產環境中的硬體利用率、queueing delay、每題 token 成本與正確率。建立回饋迴路，持續更新評分器與閾值。

## 潛在風險與注意事項

- **輕量評分器過早判斷的風險**  
  早期推理步驟訊號雜訊高，過早剪枝可能誤殺正確軌跡。應透過 warm-up threshold 延後評分，並在驗證集上量化「誤剪率」。

- **貪婪崩潰與多樣性喪失**  
  若過度分支到單一高分前綴，可能錯失其他正確但初期分數較低的路徑。建議保留最低比例的多樣性軌跡，並對分數進行溫度調整。

- **與批次推理引擎的同步摩擦**  
  Gambit 的週期性剪枝—分支需要與 vLLM 的同步解碼步驟對齊。若實作不當，可能導致部分 GPU 核心閒置或記憶體碎片化。建議在排程層統一管理活躍軌跡池。

- **評分器領域偏移**  
  在訓練資料以外的任務上，hidden-state probe 或序列評分器可能失效。應針對目標領域重新校準，或採用領域自適應技術。

- **除錯與可解釋性挑戰**  
  思維層級束搜尋的動態重新分配使單一軌跡的生成歷史變得複雜。建議記錄每條軌跡的分支來源、評分歷史與剪除原因，便於後續分析。

- **硬體記憶體上限仍是硬約束**  
  雖然 Gambit 比平行取樣更省記憶體，但長思維鏈仍會快速消耗 KV cache。需設定合理的最大軌跡長度與 beam width，並考慮分頁注意力（paged attention）等底層優化。

## 與其他技術的整合建議

- **與 vLLM／TensorRT-LLM 等推理引擎整合**  
  Gambit 最適合部署在支援同步大批次解碼的引擎上。可將其排程邏輯實作為引擎上層的「軌跡池管理器」，透過標準 API 提交與回收序列，避免修改底層 CUDA kernel。

- **與過程獎勵模型（PRM）互補**  
  若已有高品質 PRM，可將其作為 Gambit 的輕量評分器之一，但建議保留 hidden-state probe 作為更快速的備選，以平衡準確度與延遲。

- **與 Self-Consistency／多數決整合**  
  Gambit 產生的軌跡仍可使用 Self-Consistency 進行最終答案聚合。由於 Gambit 已主動提升高品質軌跡比例，通常可用更少的樣本數達到同等或更高的多數決準確率。

- **與推論時訓練／微調方法結合**  
  可將 Gambit 搜尋過程中發現的高品質前綴與最終正確軌跡收集為訓練資料，用於後續的 SFT 或 RL 微調，形成「搜尋—蒸餾—再搜尋」的良性循環。

- **與 Agent 工具鏈整合**  
  在需要呼叫外部工具（計算器、檢索、程式執行）的 Agent 中，可把每次工具呼叫視為一個「思考步驟」，並用 Gambit 決定是否繼續當前工具序列或分支到替代策略。

建議深入分析理論框架與實驗對照：作者將測試時推理形式化為「受限運算分配問題」，並比較 Gambit 與平行取樣、減法式剪枝在輸出分布偏移上的差異。可進一步探討評分器設計、探索—開發權衡、以及與 MCTS／ToT 的理論關聯。

**產品經理**  
請優先看適用場景、效能數字與成本效益：Gambit 在相同硬體下提升 AIME-25 與 HMMT-24 準確率、token 消耗降低 68.5%、吞吐量提升兩倍以上。評估時請同時考慮實作複雜度、維護成本與目標用戶對延遲的容忍度，判斷是否值得從現有 Self-Consistency 方案升級。
