# ContinualSkillBench：大型語言模型智慧體（LLM Agents）能否真正演化其能力？

**原文標題：** ContinualSkillBench: Can LLM Agents Truly Evolve Their Capabilities?

**發布日期：** 2026-08-04

## ⚡ TL;DR

現有 LLM 智慧體難以驗證其技能是否真正演化並提升任務能力。
本文提出 ContinualSkillBench，以五領域、各百項遞進子任務動態評估上下文持續技能學習。
循序執行多能提升表現，但效益因模型與領域而異，且較弱模型傾向累積片段化技能。

---

## 摘要翻譯

現代智慧體框架為大型語言模型（Large Language Models, LLMs）配備外部技能庫（external skill libraries），以解決複雜任務。然而，目前仍不清楚這些系統是否能有效演化其技能，以及演化後的技能是否能提升任務解決能力。為了彌補此一差距，我們提出 ContinualSkillBench，一個用於上下文持續技能學習（in-context continual skill learning）的動態評估框架（dynamic evaluation framework）。其涵蓋五個具代表性的領域，每個領域包含 100 個相互關聯的子任務（subtasks），依難度與跨任務技能重複使用（cross-task skill reuse）機會遞增排序。我們的實驗顯示，循序執行（sequential execution）通常能提升效能，但增益在不同模型與領域間差異甚大。此外，平均而言，上下文持續技能學習的表現與顯式技能維護（explicit skill maintenance）相當，這顯示大部分改善源自對先前上下文與任務回饋（task feedback）的適應，而非僅來自可重複使用的技能抽象化（reusable skill abstraction）。儘管如此，顯式技能對於需要可重複使用程序（reusable procedures）或精確輸出（precise outputs）的任務仍具有選擇性優勢。我們進一步發現，能力較弱的模型傾向於累積更大、更碎片化的任務特定技能（task-specific skills）集合。這些發現顯示，目前的上下文技能演化（in-context skill evolution）機制能夠支援持續適應（continual adaptation），但仍難以持續地將經驗鞏固為穩健且可轉移的技能。

### 核心貢獻（3～5點）
- 提出 ContinualSkillBench，一個專為上下文持續技能學習（in-context continual skill learning）設計的動態評估框架，涵蓋五個領域，每個領域包含 100 個依難度與跨任務技能重複使用機會遞增排序的子任務。
- 實證顯示循序執行（sequential execution）通常可提升效能，但增益幅度在不同模型與領域間存在顯著差異。
- 發現平均而言，上下文持續技能學習的表現與顯式技能維護（explicit skill maintenance）相當，暗示效能提升主要來自對先前上下文與任務回饋的適應，而非僅來自可重複使用的技能抽象化。
- 指出顯式技能在需要可重複使用程序（reusable procedures）或精確輸出（precise outputs）的任務上具有選擇性優勢。
- 揭示能力較弱的模型傾向累積更大、更碎片化的任務特定技能（task-specific skills）集合，反映其在經驗鞏固與技能轉移上的困難。

### 適合對象
本論文適合從事大型語言模型智慧體（LLM Agents）、持續學習（continual learning）、技能學習與演化、以及智慧體基準測試（agent benchmarks）相關研究的學者與工程師；特別是關注如何透過外部技能庫（external skill libraries）與上下文學習機制，使智慧體在長期任務序列中動態累積並重複使用技能的讀者。

## 深度分析

#### 方法論解析

##### 1. 評估架構：三階段 pipeline

本研究提出的 **ContinualSkillBench** 是一個動態評估框架（dynamic evaluation framework），用於檢驗 **LLM Agents（大型語言模型智慧體）** 在長序列任務中是否能透過 **in-context continual skill learning（上下文持續技能學習）** 真正演化其能力。整體流程可分為三個階段（見論文圖 1）：

- **Phase 1: Benchmark Construction（基準建構）**  
  從五個領域（Law（法律）、Healthcare（醫療保健）、Finance（金融）、Mathematics（數學）、Office（辦公））收集約 30,000 個原始任務，形成任務池。

- **Phase 2: Quality Filtering & Sorting（品質過濾與排序）**  
  透過 **LLM-assisted filtering（LLM 輔助過濾）**、**skill-dependency analysis（技能依賴關係分析）**、任務難度排序與 **human review（人工審查）**，將每個領域精簡為 100 個相互關聯的 **subtasks（子任務）**，並依難度與 **cross-task skill reuse（跨任務技能重複使用）** 的潛力進行排序。

- **Phase 3: Evaluation（評估）**  
  在每個子任務中，智慧體依序執行 **Instruction（指令理解）**、**Execution（執行）**、**Reflection（反思）** 三個步驟；並比較 **Sequential（循序執行）** 與 **Independent（獨立基線）** 兩種執行模式的差異，以 **normalized reward（標準化獎勵）** 的差值 **Δ** 作為持續學習效益的量化指標。

##### 2. 任務設計：三層難度與三項核心技能

為了模擬真實世界中能力逐步擴展的情境，作者將每個領域的任務池設計成具有層次結構：

- **基礎層**：使用經典但具挑戰性的資料集（如 OlympiadBench、LawBench、TAT-QA），測試基本知識處理能力。
- **中間層**：採用開放式智慧體資料集（如 GAIA、ClawBench、MedAgentsBench、MathCoder），要求多步推理、工具使用與環境互動。
- **高階層**：引入複雜的人類評估基準（如 One-MillionBench, OMBench），測試高階策略決策。

每個領域錨定於 **three core skills（三項核心技能）**，後續任務在邏輯上依賴先前任務所練習的技能。這種設計讓 **downstream objectives（下游目標）** 明確依賴前期經驗，從而創造出適合 **continual learning（持續學習）** 與 **skill evolution（技能演化）** 的測試場域。

##### 3. 執行模式與技能維護機制

論文比較了兩種主要執行模式：

- **Sequential Agents（循序智慧體）**：在每個子任務完成後，根據 **task feedback（任務回饋）** 建立、修改或刪除 **skill repository（技能儲存庫）** 中的技能；更新後的技能庫會被帶入下一個任務。
- **Independent Baselines（獨立基線）**：每個子任務都從頭開始執行，不繼承任何先前上下文或技能。

進一步地，作者將 Sequential 條件再細分，比較：

- **Explicit Skill Maintenance（顯式技能維護）**：主動維護一個結構化的 **external skill library（外部技能庫）**。
- **In-Context Learning（上下文學習）**：僅透過擴展的 **context windows（上下文視窗）** 保留先前任務的經驗與回饋，而不明確儲存可重複使用的技能。

這樣的對照設計有助於區分「效能提升來自於可重複使用的 **skill abstraction（技能抽象化）**」還是僅來自於「對先前上下文與回饋的適應」。

##### 4. 技能庫的分析維度

除了任務層級的 **normalized reward（標準化獎勵）**，作者也從 **skill repository（技能儲存庫）** 的結構進行診斷，包括：

- 技能總數（例如 GPT-4o 在五個領域累積 384 個技能，而 GPT-5.3-Codex 僅 205 個）。
- 技能被重複使用的頻率（reuse frequency）。
- 技能品質分數（quality scores）。

這些指標幫助判斷智慧體是否能將經驗 **consolidate（鞏固）** 成穩健且可轉移的技能，而非僅累積大量片段化的 **task-specific skills（任務特定技能）**。

---

#### 實驗數據解讀

##### 1. 循序執行帶來整體但不均勻的增益

實驗結果顯示，在 15 個 **model–domain combinations（模型–領域組合）** 中，有 14 個組合的 **Sequential（循序執行）** 表現優於 **Independent（獨立基線）**，整體 **aggregate relative gain（總體相對增益）** 達到 **16.9%**。這初步說明：

- 當前的 **LLM Agents** 確實能從持續互動中獲益；
- 先前的任務經驗與回饋對後續任務有正向影響。

然而，這些增益「**vary substantially across models and domains（在不同模型與領域間差異極大）**」。這暗示：

- 某些領域的任務結構更利於經驗遷移；
- 不同 **foundation models（基礎模型）** 在持續學習機制上的穩健性並不一致；
- 單一平均數字可能掩蓋了部分組合中幾乎無效甚至負向的情況（雖然本研究中僅 1/15 未改善）。

##### 2. 顯式技能維護 vs. 上下文學習：意外的接近

在三個領域的消融實驗中，**in-context learning（上下文學習）** 的平均 **normalized reward（標準化獎勵）** 為 **0.605**，而 **explicit skill maintenance（顯式技能維護）** 為 **0.602**，兩者幾乎相當。這是一個值得深入解讀的發現：

- **正面解讀**：現代 LLM 的長上下文能力已足以支撐某種程度的持續適應，無需額外的結構化技能管理機制。
- **負面解讀**：這也意味著目前許多所謂的「技能演化」可能並未真正形成可重複使用的 **reusable procedures（可重複使用程序）**，而只是在「記住先前做過什麼」。
- **選擇性優勢**：儘管平均表現相近，**explicit skills（顯式技能）** 在需要精確輸出（**precise outputs**）或標準化流程的任務上仍具優勢。這符合直覺：當任務要求嚴格的格式、數值準確度或固定步驟時，結構化的技能比鬆散的上下文更有用。

##### 3. 技能庫的質與量：能力較弱的模型傾向累積更多碎片

作者觀察到不同模型維護 **skill repository（技能儲存庫）** 的方式差異顯著：

- **GPT-4o**：累積 384 個技能，但這些技能的重用頻率較低、品質分數也較低。
- **GPT-5.3-Codex**：僅累積 205 個技能，但重用率與品質較高。

這顯示：

- **能力較弱的模型傾向產生更大、更碎片化的技能集合**，可能是因為它們難以抽象出通用規則，只能為每個新任務建立專門的 **task-specific skills（任務特定技能）**。
- **較強的模型能夠進行更好的 skill abstraction（技能抽象化）**，將多個任務的經驗收斂成較少但更具通用性的技能。
- 然而，即使是 GPT-4o，其技能重用率與品質仍有改善空間，說明目前的 **in-context skill evolution（上下文技能演化）** 機制尚未能穩定地將經驗轉化為 robust and transferable skills（穩健且可轉移的技能）。

##### 4. 綜合意涵

整體而言，實驗數據描繪出一幅「部分成功但尚未成熟」的圖像：

- **持續適應確實發生**：循序執行幾乎總是優於獨立執行。
- **但能力擴展有限**：許多增益來自上下文適應，而非真正的技能抽象與遷移。
- **顯式技能庫仍有價值**：在特定任務類型中不可或缺。
- **模型間存在系統性差異**：較弱模型不僅表現較差，其技能庫結構也更不健康。

#### 與現有研究的比較

##### 1. 相較於靜態技能基準的進展

現有許多 **agent benchmarks（智慧體基準測試）**（如論文引用的 Mialon et al., 2023; Zhang et al., 2026; Ye et al., 2026）通常假設 **fixed set of tools（固定工具集）** 或靜態技能集合。相較之下：

- **ContinualSkillBench** 強調 **dynamic skill evolution（動態技能演化）**，技能庫會隨任務序列持續更新。
- 任務並非隨機呈現，而是依難度與 **skill dependencies（技能依賴關係）** 排序，更貼近真實的終身學習（**lifelong learning**）情境。

##### 2. 相較於 SkillsBench

**SkillsBench** 透過 **no-skill conditions（無技能條件）** 與 **curated-skill conditions（精選技能條件）** 的比較，評估外部提供技能的效用。然而：

- SkillsBench 不研究技能庫如何在長序列互動中演化。
- ContinualSkillBench 則關注智慧體能否「自己長出」技能，並檢驗這些技能是否提升後續任務表現。

##### 3. 相較於 SkillLearnBench、CL-Bench 與 SkillCraft

- **SkillLearnBench**：聚焦於從種子實例生成與精煉技能，並評估技能品質與執行行為。
- **CL-Bench**：採用具有共享潛在結構的 stateful task sequences（具狀態任務序列），比較不同記憶架構。
- **SkillCraft**：關注可執行工具組合的獲取與重用。

**ContinualSkillBench** 的定位在於：

- 研究「長期、異質任務流」中的技能演化，而非單一重複任務或固定執行流程。
- 每個任務流包含多種來源與評估格式，並由反覆出現的 **core skills（核心技能）** 連結，從而測試經驗能否被鞏固並遷移到不同下游任務。

##### 4. 相較於傳統微調與災難性遺忘研究

傳統透過 **parametric updates（參數更新）**（如 **fine-tuning（微調）**）適應新任務常導致 **catastrophic forgetting（災難性遺忘）**。本研究延續近年 **in-context continual learning（上下文持續學習）** 的路線（Wu et al., 2024; Raparthy et al., 2023），利用擴展的 **context windows（上下文視窗）** 與外部技能庫，避免修改模型權重。

##### 5. 主要貢獻與侷限

**主要貢獻**：

- 提出首個專注於 **in-context continual skill learning（上下文持續技能學習）** 的動態評估框架。
- 建構五個領域、每領域 100 個有序子任務的長序列基準。
- 透過比較 Sequential / Independent 與 explicit / in-context 條件，區分「上下文適應」與「技能抽象」的貢獻。
- 從技能庫的質與量診斷不同模型的持續學習行為。

**侷限**：

- 論文目前提供的細節有限，例如 **normalized reward（標準化獎勵）** 的計算公式、任務難度與技能依賴的量化方式、以及 **human review（人工審查）** 的具體流程尚未完全揭露。
- 部分引用的文獻年份為 2025 或 2026，可能為預印本或尚未廣泛驗證的工作，需留意其可參考性。
- 實驗主要使用專有模型（如 GPT-4o、GPT-5.3-Codex），結果可能受 API 版本與提示工程影響，難以完全複製。
- 雖然強調跨任務遷移，但對於「哪些技能確實被重用」以及「重用如何具體提升表現」的因果分析仍較為粗粒度。

#### 可重現性評估

##### 1. 開源程式碼

論文提供了原始碼連結：

> https://github.com/gtynnn060110-hash/continual-skill-bench-final

這是正向訊號，意味著：

- 評估框架（**harnesses（評估框架）**）、任務載入流程、Sequential / Independent 執行邏輯、以及技能庫管理機制原則上可被檢視與重複使用。
- 其他研究者可以在此基礎上測試自己的模型或改進技能演化演算法。

##### 2. 資料集可用性

- 任務來源多為現有公開基準（如 OlympiadBench、LawBench、TAT-QA、GAIA、ClawBench、MedAgentsBench、MathCoder、OMBench），這些資料集原則上可公開取得。
- 然而，論文從約 30,000 個原始任務篩選出 500 個最終子任務的具體篩選準則、LLM 輔助過濾的提示詞、以及人工審查的標準，若未完整釋出，將影響精確重現。
- 任務排序所依賴的 **skill-dependency analysis（技能依賴關係分析）** 方法與難度評分函數，也需要額外文件說明才能確保可重現。

##### 3. 模型權重與 API 依賴

- 實驗涉及 **GPT-4o** 與 **GPT-5.3-Codex** 等專有模型，其權重不公開，且 API 行為可能隨時間變化。
- 這意味著即使程式碼與資料集完全公開，不同時間點、不同 API 版本的實驗結果仍可能存在差異。
- 若未來能補充開源模型（如 Llama、Qwen、DeepSeek 等）的實驗，將大幅提升結果的可比較性與可重現性。

##### 4. 評估指標透明度

- **Normalized reward（標準化獎勵）** 是核心指標，但目前尚不清楚其是否為 0–1 之間的標準化分數、是否結合了正確性與部分正確性、以及不同領域的獎勵函數是否一致。
- 技能品質分數（quality scores）與重用頻率的計算方式也需要更詳細的定義，才能讓其他研究者進行相同分析。

##### 5. 可重現性總結

| 項目 | 狀態 | 說明 |
|---|---|---|
| 原始碼 | 已公開 | 提供 GitHub 連結 |
| 原始資料集 | 多數公開 | 來自現有公開基準 |
| 篩選與排序細節 | 部分不明 | 需補充提示詞與人工審查標準 |
| 模型權重 | 不公開 | 依賴專有 API |
| 評估指標定義 | 部分不明 | 需補充 normalized reward 與 skill quality 計算方式 |

整體而言，本研究在「框架開源」與「資料來源公開」方面具備基礎可重現性，但在「篩選流程、指標定義、專有模型穩定性」方面仍有強化空間。

#### 未來研究方向

##### 1. 更細緻的因果分析：區分「記住」與「學會」

本研究發現 **in-context learning（上下文學習）** 與 **explicit skill maintenance（顯式技能維護）** 的平均表現相近，但未來需要更精確地區分：

- 效能提升有多少來自於「記住先前見過的類似任務」？
- 有多少來自於「抽象出可泛化的程序」？

可透過設計「干擾任務」或「遠距離遷移測試」來檢驗技能的真正泛化能力。

##### 2. 技能庫的自我組織與壓縮

實驗發現較弱模型會累積大量碎片化的 **task-specific skills（任務特定技能）**。未來可研究：

- 自動技能合併（skill merging）與抽象化機制；
- 基於使用頻率與品質的技能修剪（pruning）策略；
- 層級式技能組織（hierarchical skill organization），讓智慧體能根據任務需求動態檢索與組合技能。

##### 3. 跨領域技能遷移

目前五個領域分開評估，未來可探討：

- 在法律領域學到的「合約條款解析」技能，是否能遷移到金融領域的「貸款協議分析」？
- 如何設計領域無關（domain-agnostic）的技能表示，以促進更廣泛的 **cross-task skill reuse（跨任務技能重複使用）**？

##### 4. 結合參數更新與上下文學習的混合架構

雖然本研究聚焦 **in-context continual learning（上下文持續學習）** 以避免 **catastrophic forgetting（災難性遺忘）**，但未來可探索：

- 輕量級的參數更新（如 LoRA、adapter）與外部技能庫的結合；
- 在保留長期記憶的同時，針對高頻技能進行微調；
- 設計「何時該寫入技能庫、何時該更新參數」的元學習策略。

##### 5. 開源模型與可解釋性研究

目前實驗主要使用專有模型，未來應：

- 在開源 **foundation models（基礎模型）** 上進行大規模比較；
- 分析不同模型架構（如 dense vs. MoE）對技能演化與重用的影響；
- 開發可視化工具，展示技能如何在任務序列中生成、被呼叫與被修改。

##### 6. 動態難度調適與個人化學習路徑

目前的任務順序是固定的，未來可朝 **adaptive task sequencing（適應性任務排序）** 發展：

- 根據智慧體當前能力動態調整任務難度；
- 設計個人化的 **curriculum learning（課程學習）** 路徑，最大化技能習得效率；
- 將 ContinualSkillBench 擴展為互動式訓練環境，而不只是評估工具。

##### 7. 人類對齊與安全考量

隨著智慧體持續演化自身技能，也必須關注：

- 技能庫中是否會累積錯誤或偏見？
- 如何設計審查機制，避免有害技能的自我強化？
- 在醫療、法律等高風險領域，如何確保演化出的技能符合專業標準與法規？

這些問題將是 **LLM Agents** 從「能持續學習」走向「能安全且可靠地持續學習」的關鍵挑戰。

## 論文問答

**Q1：ContinualSkillBench 主要想解決什麼問題？為什麼僅依賴預訓練權重不足以應對真實世界任務？**

A：本研究指出，現代大型語言模型智慧體雖然配備了外部技能庫來處理複雜任務，但我們仍不清楚這些系統是否能真正隨著互動持續演化技能，並將演化後的技能轉化為解題能力的擴展。真實世界任務需求多樣且不斷變化，單靠預訓練階段學到的靜態知識往往無法應對新任務或動態環境。因此，需要一個能評估智慧體在長序列任務中持續學習、抽象並重複使用技能的動態基準。

**Q2：現有的靜態技能庫與微調方法為什麼難以支援持續技能演化？**

A：大多數現有智慧體框架假設技能庫是固定的，無法根據新任務動態更新，這在真實環境中會嚴重限制適應能力。另一方面，透過標準微調進行參數更新雖然能學習新任務，卻容易引發災難性遺忘，破壞原本已學會的能力。為了迴避這些問題，近期研究轉向上下文持續學習，利用擴展的上下文視窗讓智慧體在不改變模型權重的情況下動態更新與檢索技能。

**Q3：為什麼評估持續技能學習很重要？相較於現有基準，ContinualSkillBench 填補了哪些空白？**

A：現有許多智慧體基準測試只在固定工具集或人工精選技能的條件下評估任務完成度，無法觀察技能庫如何隨任務序列演化。雖然 SkillsBench、SkillLearnBench、CL-Bench 與 SkillCraft 等研究開始關注技能學習，但它們多聚焦於單一任務、固定流程或可執行工具組合，較少探討長期、異質任務流中的技能抽象與跨任務重複使用。ContinualSkillBench 透過五個領域、每個領域 100 個相互關聯且依難度排序的子任務，提供了一個能檢驗經驗是否被鞏固為可轉移技能的實證場域。

**Q4：ContinualSkillBench 的核心設計是什麼？任務序列如何組織？**

A：該基準包含五個領域專屬的任務流，分別是醫療保健、法律、數學、金融與辦公室應用，每個領域由 100 個子任務組成。這些子任務並非隨機排列，而是依據難度與潛在的跨任務技能重複使用機會進行排序，並錨定在三項核心技能上。智慧體完成每個子任務後會收到任務回饋，並可據此建立或修改技能儲存庫，更新後的技能庫將在後續任務中繼續使用。

**Q5：相較於 SkillsBench、SkillLearnBench、CL-Bench 與 SkillCraft，ContinualSkillBench 的關鍵創新在哪裡？**

A：與 SkillsBench 僅比較有無精選技能的靜態條件不同，ContinualSkillBench 強調技能庫在長序列互動中的動態演化。SkillLearnBench 主要評估從種子實例生成與精煉技能的方法，CL-Bench 關注具有共享潛在結構的狀態化任務序列，SkillCraft 則聚焦可執行工具組合的獲取與重複使用；相較之下，本基準研究的是跨越多樣來源與評估格式的長期異質任務流。這種設計讓研究者能檢驗從一個任務獲得的經驗，是否能被鞏固成結構化技能並在不同下游任務中重複使用。

**Q6：在任務建構上做了哪些設計選擇，以確保評估的真實性與層次感？**

A：研究團隊選擇了五個具有實際應用價值且常需要多步推理或細膩人類評估的領域，避免使用過度簡化的合成環境。任務池來自三個層級的現有基準：底層使用 OlympiadBench、LawBench、TAT-QA 等經典資料集測試基礎知識處理；中層採用 GAIA、ClawBench、MedAgentsBench、MathCoder 等開放式智慧體資料集，要求多步推理、工具使用與環境互動；頂層則納入 One-Million-Bench 等複雜人類評估基準，用於高階策略決策。這種分層設計確保了任務具備漸進的複雜度與技能依賴關係，使下游目標能自然依賴先前任務所練習的技能。

**Q7：實驗中比較了哪些執行設定與學習機制？**

A：實驗主要比較循序執行與獨立基線：循序執行讓智慧體在任務序列中持續更新技能儲存庫，而獨立基線則讓每個任務從頭開始、不繼承先前上下文。此外，研究還比較了顯式技能維護與純上下文學習，前者會主動維護與更新明確儲存的技能，後者則依賴模型對先前上下文與回饋的隱式適應。透過這些對照，作者能區分性能提升是來自可重複使用的技能抽象化，還是僅來自對先前上下文的適應。

**Q8：實驗的主要結果有哪些？**

A：在 15 個模型與領域組合中，循序執行在 14 個組合中提升了標準化獎勵，總體相對增益達到 16.9%，但提升幅度在不同模型與領域間差異顯著。在三個納入消融研究的領域中，純上下文學習的平均標準化獎勵為 0.605，與顯式技能維護的 0.602 相當，顯示許多改進來自對先前上下文與回饋的適應，而非單靠可重複使用的技能抽象化。然而，對於需要可重複使用程序或精確輸出的任務，顯式技能仍展現出選擇性優勢。

**Q9：消融研究揭示了顯式技能與上下文學習之間的什麼關係？**

A：消融結果顯示，平均而言顯式技能維護並未顯著優於純上下文學習，這意味著當前模型很大一部分的持續適應能力來自於對先前互動上下文的隱式利用。儘管如此，顯式技能在需要標準化可重複使用程序或對輸出準確度要求高的任務上仍具價值，因為它能把經驗提煉成穩定的操作步驟。這也暗示未來的設計應該根據任務特性，靈活結合顯式技能儲存與上下文適應兩種機制。

**Q10：持續技能演化在哪些實際應用場景中特別有價值？**

A：在法律、醫療保健、金融、數學與辦公室自動化等領域，智慧體經常需要處理複雜且需求不斷變化的任務，持續技能演化能讓它們隨著案例累積而改進。例如法律助理智慧體可以從一系列合約審查任務中抽象出標準檢查清單，醫療診斷助理則能從過往病例中學習並更新診斷流程。這種能力讓智慧體不僅能完成單一任務，還能在長期服務中逐漸形成領域專長。

**Q11：在產品化部署持續演化技能庫的智慧體時，需要考慮哪些問題？**

A：首先必須監控技能儲存庫的品質與重用率，避免累積大量碎片化、任務特定但難以轉移的技能。研究發現能力較弱的模型傾向累積更大、更分散的技能集合，例如 GPT-4o 在五個領域中累積了 384 個技能，但這些技能的重用頻率與品質評分較低。因此產品設計上需要引入技能合併、過濾與品質評估機制，並確保顯式技能能真正轉化為穩定且可重複使用的程序。

**Q12：這個基準可能對智慧體研究與開發帶來什麼影響？**

A：ContinualSkillBench 提供了一個標準化的動態評估框架，讓研究者能系統性地比較不同模型在長期任務序列中的技能演化能力。它有助於區分「僅適應上下文」與「真正形成可轉移技能」這兩種現象，從而推動更具結構化的持續學習方法。長遠來看，這將促進智慧體從靜態工具使用者，轉變為能夠在真實環境中不斷自我改進的終身學習系統。

**Q13：論文承認目前上下文技能演化機制存在哪些限制？**

A：作者指出，雖然現有的上下文持續學習機制能支援一定程度的持續適應，但它們仍難以穩定地將經驗鞏固為強健且可轉移的技能。許多性能提升來自對先前上下文與回饋的適應，而非真正的技能抽象化，這限制了智慧體在面對全新但結構相似任務時的泛化能力。此外，不同模型在技能庫的維護策略與品質上差異很大，顯示目前尚缺乏一致且可靠的技能演化範式。

**Q14：實驗中觀察到哪些失敗案例或負面現象？**

A：研究發現能力較弱的模型傾向於累積數量更多、更為碎片化的任務特定技能，這些技能較少被後續任務重複使用，品質評分也較低。相對地，更強的模型雖然技能數量較少，卻能維持較高品質與重用率，顯示它們在技能抽象化上表現較好。這個現象說明，單純增加技能數量並不能保證持續學習的成功，反而可能導致技能庫膨脹與管理困難。

**Q15：這項研究提出了哪些未來方向？**

A：未來研究可以探索更有效的技能抽象化與合併機制，幫助智慧體從經驗中提煉出更通用、可重複使用的程序。另一個方向是結合顯式技能維護與上下文學習的優勢，根據任務需求動態決定何時儲存技能、何時依賴上下文適應。此外，也需要發展更細緻的評估指標，以衡量技能的轉移性、重用率與長期穩定性，從而推動真正具備終身學習能力的大型語言模型智慧體。

## 實務應用指南

### 適用場景

1. **法律文件審查與合規追蹤**  
   在律師事務所或企業法務部門中，可將合約審查、法規比對、判例檢索等任務串接為循序任務流。代理人在處理早期簡單合約時學習「條款萃取」「風險標記」等核心技能，後續面對跨國併購或監管調查等複雜文件時，直接重複使用已演化的技能庫，減少重複提示工程的成本。

2. **醫療決策輔助與病歷管理**  
   醫院或健康科技團隊可部署持續學習代理人，依序處理症狀分類、檢驗報告解析、用藥交互作用檢查與治療建議生成。透過上下文持續技能學習，系統能在不微調模型參數的前提下，逐步累積專科領域的 reusable procedures，並根據新任務回饋修正診斷邏輯。

3. **金融稽核與風險評估**  
   銀行、保險或會計事務所可將財報分析、異常交易偵測、法規遵循檢查與壓力測試報告組成任務序列。代理人在早期任務中習得標準化分析程序，後期應用於跨市場、跨產品的綜合風險評估，提升輸出一致性與精確度。

4. **企業辦公自動化（Office Automation）**  
   針對跨部門的行政流程，例如會議紀要生成、電子郵件分類、報表彙整與專案進度追蹤，可建構循序執行的辦公代理人。技能庫隨著任務流動態演化，讓模型逐步掌握組織內部格式與流程慣例，減少每項新任務都從頭開始的開銷。

5. **個人化數學與程式教育輔導**  
   教育平台可設計由易到難的解題序列，讓 LLM 代理人在教導基礎運算、代數推導、幾何證明與競賽題目的過程中，持續提煉解題策略與常見錯誤模式。顯式技能維護有助於產生精確輸出，降低反覆出現的計算或格式錯誤。

---

### 實作前置條件

- **資料準備**  
  需要一個具備難度遞增與技能依賴關係的任務序列，每個領域建議至少 50–100 個相互關聯的子任務，並標註對應的核心技能與預期輸出格式。任務應包含正確答案或評分標準，以便產生任務回饋。

- **運算資源**  
  主要成本來自 LLM API 呼叫與序列評估。建議預留足夠的上下文視窗長度（以支援長任務流），並準備評估用的運算環境來執行 Sequential 與 Independent 兩種對照實驗。若使用開源模型，需配置可支援長上下文的 GPU 或推論服務。

- **技能與工具前提**  
  團隊應熟悉提示工程、代理人框架（如 ReAct、LangChain、AutoGen 或自訂 harness），並具備設計技能儲存庫（skill repository）與反思模組的能力。此外，需要建立標準化獎勵指標與品質過濾流程，以衡量技能演化帶來的實質增益。

---

### 實作步驟建議

1. **定義領域與核心技能**  
   選定 1–2 個高價值領域（如法律、醫療保健或金融），並歸納出 3 項左右可跨任務重複使用的核心技能，作為後續任務設計與技能庫組織的錨點。

2. **蒐集與建構循序任務流**  
   從現有資料集（如 LawBench、MedAgentsBench、TAT-QA、GAIA 等）與內部業務資料中，挑選涵蓋基礎知識、多步推理與高階決策的子任務。依據難度與技能依賴關係排序，確保下游目標能自然繼承先前任務所練習的技能。

3. **建立評估框架（Harness）**  
   實作「指令生成 → 任務執行 → 反思與技能更新」的循環。設計 Independent 基線（每個任務從頭開始）與 Sequential 代理人（可讀取先前上下文並更新技能庫），並定義 normalized reward 與技能品質評分。

4. **實作顯式技能維護機制**  
   讓代理人在每次任務後根據回饋建立、合併或修改技能。技能應以結構化格式儲存（例如自然語言模板、工具呼叫序列或參數化程序），並記錄使用頻率與品質分數，避免累積過多任務特定技能。

5. **執行對照實驗並分析 Δ**  
   同時跑 Sequential 與 Independent 兩種設定，計算總體相對增益（aggregate relative gain）與各領域的差異。若發現某些領域進步有限，應回頭檢視任務排序、技能抽象化程度或回饋訊號是否足夠。

6. **迭代優化並導入生產環境**  
   根據實驗結果調整任務順序、技能合併策略與反思提示。上線後持續監控技能庫規模、重複使用頻率與輸出品質，定期清理低品質或極少使用的技能。

---

### 潛在風險與注意事項

- **技能碎片化與儲存庫膨脹**  
  實驗顯示，能力較弱的模型傾向累積大量任務特定技能。應設立技能合併與淘汰機制，例如當多個技能語意相似時自動合併，或定期移除長期未被呼叫的低分技能。

- **過度依賴上下文而非真正的技能抽象化**  
  上下文持續學習雖然平均表現接近顯式技能維護，但部分增益可能僅來自對先前上下文與回饋的適應。對於需要精確輸出或可重複使用程序的任務，仍建議保留顯式技能庫。

- **上下文視窗限制與資訊稀釋**  
  隨著任務序列增長，早期重要資訊可能被擠出上下文視窗。可搭配摘要機制或將關鍵經驗固化為技能，降低對長上下文的絕對依賴。

- **安全、隱私與法規風險**  
  在法律、醫療保健與金融等領域，錯誤輸出可能帶來嚴重後果。技能演化過程中必須保留人類監督、版本控制與可解釋性紀錄，並符合相關產業法規。

- **評估成本與再現性**  
  長序列任務與多次 API 呼叫會產生高昂成本。建議先以小規模原型驗證核心假設，再擴展到完整 100 子任務的領域流，並固定隨機種子與提示版本以確保實驗可再現。

### 與其他技術的整合建議

- **檢索增強生成（RAG）**  
  將外部技能庫視為可檢索的知識來源，搭配向量資料庫儲存技能嵌入。當新任務到達時，先檢索最相關的技能再執行，可減少上下文長度並提升跨任務技能重複使用效率。

- **工作流程編排與 MLOps 平台**  
  透過 Airflow、Prefect 或自訂 workflow engine 管理任務序列與評估排程。將 Sequential／Independent 實驗納入 CI/CD，持續追蹤 normalized reward 與技能庫健康度指標。

- **人機協作（Human-in-the-Loop）**  
  在醫療、法律等高風險場景，讓領域專家審核新生成的技能與關鍵任務輸出。專家回饋可作為高品質的任務回饋來源，加速技能演化並降低錯誤放大風險。

- **微調與參數更新互補**  
  雖然本論文聚焦無參數更新的上下文持續學習，但在資料量充足且任務穩定後，可將高品質技能或經驗轉化為微調資料，進一步鞏固通用能力，同時保留動態技能庫以應對新任務。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先從摘要與「適用場景」著手，理解「為什麼要讓 LLM 代理人持續學習技能」以及「循序執行」與「獨立執行」的差別。接著閱讀實作步驟建議，把整個流程想像成一個會隨著工作經驗越來越熟練的虛擬助理，不必一開始就深入數學細節。

- **AI 工程師**  
  重點關注評估框架設計、顯式技能維護機制與實驗對照方法。論文指出上下文持續學習與顯式技能維護的平均表現相近，因此在實作時應根據任務特性選擇策略，並特別注意技能庫的合併、清理與檢索效率。

- **研究人員**  
  建議深入分析不同模型在技能庫規模、重複使用頻率與品質分數上的差異，以及各領域增益不一致的原因。可延伸探討如何設計更有效的技能抽象化機制、減少任務特定技能的累積，並將本基準與其他持續學習或技能學習研究進行比較。

- **產品經理**  
  本論文提供了一個可量化的評估視角：透過 Sequential 與 Independent 的 Δ 來判斷「經驗是否真的轉化為能力」。在規劃產品時，應優先選擇具有明確核心技能與可排序任務流的領域，並把「技能重複使用率」與「輸出精確度」列為關鍵產品指標，同時預留專家審核與風險控管機制。
