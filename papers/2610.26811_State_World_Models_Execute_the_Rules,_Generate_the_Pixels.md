## 摘要翻譯

現有的世界模型能從單張影像生成動作條件影片。許多模型聚焦於攝影機移動，讓使用者能探索生成場景。然而，當動作的結果取決於當前幀中不可見的狀態時，僅靠導航無法確保動作遵循持久性規則。我們提出 Stateful Harness，一個將世界演變與影片渲染分離的框架，以支援狀態化與規則約束式互動。它在指定規則下維護一個持續演變的世界狀態，使用凍結影片模型渲染每個產生的事件，並利用生成的片段來更新下一輪的世界狀態。在每一輪中，框架解析使用者選擇的動作，並將產生的事件編譯為指令；同時，可編輯 3D 場景的預覽片段提供空間與攝影機引導。為了評估規則遵循度，我們建構了 WorldState-Bench，一個包含 50 組反事實孿生對的基準測試，這些孿生對共享初始影像與動作，但在隱藏狀態與預期結局上有所不同。在僅規則提示下，11 個受評估的影片後端中，表現最佳者能在 32% 的孿生對中為兩種情況都產生預期結局。對於 MiniMax-H3，指定預期結局將此比率從 32% 提升至 64%，而完整的框架在使用相同凍結模型的情況下達到 92%。這些結果支援將規則執行與影片渲染分離，以處理具有隱藏狀態的世界互動。

### 核心貢獻（3～5點）
- 提出 **Stateful Harness** 框架，將世界演變與影片渲染解耦，使隱藏狀態下的規則遵循成為可能。
- 設計基於凍結影片模型的迴圈機制：每一輪由規則執行決定世界狀態更新，再以生成片段回饋至下一輪狀態。
- 建構 **WorldState-Bench** 基準測試，含 50 組反事實孿生對，專門評估模型在相同動作但不同隱藏狀態下的規則遵循能力。
- 實驗證明：完整框架在 **MiniMax-H3** 上將規則遵循率從僅規則提示的 32% 提升至 92%，驗證分離式架構的顯著效益。

### 適合對象
從事影片世界模型、互動式生成式 AI、遊戲引擎與敘事系統研究之學者與工程師；對可控影片生成、規則約束式生成、視覺語言模型（VLM）代理，以及具隱藏狀態之世界模擬有興趣的研究人員；以及尋求將生成式影片技術應用於遊戲開發、互動敘事或模擬訓練等領域的業界實務工作者。

## 深度分析

#### 方法論解析

STATEFUL HARNESS 的核心設計理念在於將「世界演變（World Evolution）」與「影片渲染（Video Rendering）」兩個職責明確分離，這是相較於傳統端到端影片世界模型（Video World Models）的根本性架構轉變。傳統方法將狀態管理隱含地編碼於模型權重中，導致規則遵循度（Rule Compliance）難以控制且無法驗證；本框架則將規則執行（Rule Execution）外化為可審計的程式邏輯。

**三層架構組成：**

1. **語意狀態層（Semantic State Layer）**：由一個程式編寫代理（Coding Agent）根據世界描述（World Description）與初始影像（Initial Image）自動生成，定義世界狀態（World State）、可用動作（Available Actions）與可執行規則（Executable Rules）。這層以型別化程式（typed program）形式存在，記錄諸如物品欄（Inventory）、進度（Progress）等隱藏變數（Hidden Variables）。

2. **空間狀態層（Spatial State Layer）**：以可編輯 3D 場景（Editable 3D Scene）形式存在，提供可定址空間狀態（Addressable Spatial State），負責在多輪互動中維持場景佈局（Scene Layout）與攝影機路徑（Camera Paths）的一致性。

3. **渲染層（Rendering Layer）**：採用凍結影片模型（Frozen Video Model），不進行微調，僅接收來自上層的指令進行生成。

**單回合運作流程：**

每個回合（turn）的運作遵循嚴格的閉環（closed loop）程序：
- 使用者觀察當前場景並選擇動作
- 執行環境（Runtime）根據當前狀態解析該動作，判斷其是否觸發事件
- 解析後的事件被編譯為 VisualScript 指令
- 從更新後的 3D 場景產生預覽片段（Preview Clip），提供空間與攝影機引導（Spatial and Camera Guidance）
- 凍結影片模型基於視覺錨點（Visual Anchor，來自初始影像或前一片段）、VisualScript 指令與預覽片段渲染事件
- 視覺語言模型（Vision Language Model, VLM）解讀生成片段，根據觀察到的事件提議語意與空間狀態更新
- 執行環境僅納入與固定規則相容的更新，確保規則始終具權威性

此設計的關鍵洞見在於：規則的權威性（authority of state transitions）來自於規則執行與影片渲染的解耦。影片模型無需「理解」規則，只需忠實渲染被告知的內容；而規則遵循度則由外層邏輯強制保證。

#### 實驗數據解讀

**WorldState-Bench 基準設計：**

此基準包含 50 組反事實孿生對（Counterfactual Twin Pairs），每對共享相同的初始畫面、動作與規則程式，但隱藏變數不同，因此需要截然不同的結局。這種設計巧妙地隔離了「視覺相似但語意不同」的情境，正是當前影片世界模型最難處理的場景。

**Change-to-Comply 評估協議：**

- **Change**：評估動作是否產生可辨識的事件
- **Comply**：評估該事件是否滿足可執行規則

**PAIRFOLLOW 與 PAIRSTRICT 雙指標：**

- **PAIRFOLLOW**：要求兩個反事實案例皆顯示其預期結局（Required Endings）
- **PAIRSTRICT**：在 PAIRFOLLOW 基礎上，額外要求禁止結局不出現於任一剪輯中

**關鍵數據解讀：**

| 條件 | PAIRFOLLOW | PAIRSTRICT |
|------|-----------|-----------|
| 11 個影片後端中最佳（僅規則提示） | 32% | — |
| MiniMax-H3 + 指定預期結局 | 64% | 4% |
| MiniMax-H3 + 完整 STATEFUL HARNESS | 92% | 90% |

這組數據揭示了幾個重要現象：

1. **規則提示的侷限性**：僅透過規則提示（Rule-Only Prompting）讓影片模型自行推論，表現僅 32%，說明當前影片模型難以從規則文字推導出正確的視覺結局。

2. **指定結局的雙刃劍效應**：明確指定預期結局使 PAIRFOLLOW 翻倍至 64%，但 PAIRSTRICT 僅 4%，意味著模型傾向於「過度生成」——即使被告知不應出現某結局，仍會渲染出來。這反映了影片模型缺乏「否定性控制（negative control）」能力。

3. **完整框架的決定性優勢**：完整 STATEFUL HARNESS 達到 92% PAIRFOLLOW 與 90% PAIRSTRICT，兩者差距僅 2%，證明了閉環機制（規則解析 → 渲染 → VLM 觀察 → 狀態更新）能有效抑制禁止結局的洩漏。

4. **PAIRSTRICT 的重要性**：PAIRSTRICT 從 4% 躍升至 90% 是最關鍵的進步，因為它衡量的是「精確遵循」而非「大致符合」，這對實際應用至關重要。

#### 與現有研究的比較

**與傳統影片世界模型的比較：**

現有互動式影片世界模型（Interactive Video World Models）如 Genie 系列、Oasis 等，主要聚焦於導航訊號（Navigation Signals）與攝影機移動（Camera Movement），允許使用者探索生成場景。然而，導航控制僅使場景「可探索」，並不決定互動後果。STATEFUL HARNESS 透過引入顯式狀態與規則執行，填補了「回應式影片（Responsive Video）≠ 規則遵循影片」之間的鴻溝。

**與基於引擎的世界模型比較：**

PWM（Programmable World Model）耦合引擎與 3D 物件框表示，在像素層進行條件化；Code World Model 將程式維護的狀態編譯為代理影片並微調渲染器。這些方法需要引擎或微調，而 STATEFUL HARNESS 採用凍結影片模型，無需任何訓練，這是其最大優勢——新世界只需撰寫小型型別化程式即可運作。

**與顯式狀態方法的比較：**

部分研究從生成畫面恢復狀態、對選定狀態變數進行條件化、或生成敘事與角色狀態。STATEFUL HARNESS 的獨特之處在於結合三個最小介面：持久可編輯場景、語意狀態分類帳（semantic state ledger）、與凍結渲染器的標準參考輸入。這種組合的精簡性使其易於擴展至自訂世界。

**與世界模型評估基準的比較：**

現有基準多衡量視覺品質、提示遵循度、導航、主體動作、事件編輯與視角變化。WorldState-Bench 是首個專門針對「隱藏狀態下規則遵循」的基準，採用反事實評估（Counterfactual Evaluation）協議，這在現有文獻中並未建立。

**侷限性：**

1. **依賴 VLM 的觀察品質**：狀態更新仰賴 VLM 正確解讀生成片段，若 VLM 誤判，狀態可能錯誤傳播。
2. **3D 場景編輯負擔**：需要為每個新世界建立可編輯 3D 場景，雖比從頭訓練模型輕量，但仍需人工設計。
3. **單回合評估為主**：雖展示多回合（如圖 6 的決鬥），但基準主要為單回合探測，長期一致性尚未系統量化。
4. **規則表達能力受限**：規則需以程式形式表達，複雜敘事邏輯的表達可能受限。

## 論文問答

**Q1：為什麼現有的影片世界模型無法有效處理具有隱藏狀態的互動？**
A：現有的影片世界模型主要專注於從單張影像生成動作條件影片，並以攝影機移動為核心，讓使用者探索生成的場景。然而，這類模型在面對依賴隱藏狀態的互動時會出現根本性的不足——例如同一個「開鎖動作」在玩家持有鑰匙時應該打開寶箱，但若沒有鑰匙則不應開啟。當初始畫面看起來相同時，純粹基於視覺的影片模型無法區分這兩種情境，因為它缺乏對語意狀態（如物品欄、進度）的明確記錄。這正是論文所指出「回應式影片並不自動保證動作遵循持久性規則」的關鍵問題。

**Q2：什麼是「狀態世界模型」？它與傳統影片世界模型的根本差異為何？**
A：狀態世界模型（State World Models）是論文中提出的新概念，其核心在於將規則執行、影片生成與視覺觀察整合成一個封閉迴圈，使世界能夠根據明確的規則演化並保持狀態的持續性。與傳統影片世界模型僅生成視覺回應不同，狀態世界模型要求動作的後果必須由可定址的語意狀態與空間狀態共同決定，並在後續互動中持續生效。這種設計使得「同一動作在不同隱藏狀態下產生不同結果」成為可能，從而解決了純視覺模型無法處理反事實情境的根本缺陷。

**Q3：為什麼僅靠導航控制不足以建立可信的互動式世界模型？**
A：導航控制雖然能讓使用者探索生成的場景，但它僅決定了攝影機的移動路徑，並未規定互動的後果規則。當一個動作的結果取決於當前畫面中不可見的狀態時——例如玩家是否持有特定鑰匙、某個 NPC 是否已被擊敗——純粹的導航式生成無法區分這些情境。論文中以寶箱的例子清楚說明了這個問題：相同的初始視角與開啟動作，在不同隱藏狀態下應產生截然不同的結果。因此，要建立真正可信的互動式世界模型，必須引入明確的語意狀態與可執行的規則，而非僅依賴視覺條件生成。

**Q4：Stateful Harness 框架的核心設計理念是什麼？為什麼要將世界演變與影片渲染分離？**
A：Stateful Harness 的核心設計理念是「將規則執行從影片渲染中分離出來」，由執行環境負責根據當前世界狀態解析使用者動作並編譯成 VisualScript 指令，再交由凍結的影片模型渲染對應事件。這種分離的關鍵優勢在於：規則的權威性由執行環境保證，而非依賴影片模型「猜測」正確的結果；同時影片模型可以保持凍結，無需針對每個新世界進行微調。透過可編輯的 3D 場景提供空間與攝影機引導，並由視覺語言模型觀察生成片段以更新世界狀態，整個系統形成一個自我維持的封閉迴圈。

**Q5：規則執行、影片生成與視覺觀察如何形成封閉迴圈？**
A：這個封閉迴圈由三個關鍵環節組成：首先，執行環境根據固定的可執行規則解析使用者選擇的動作，並將結果事件編譯成 VisualScript 指令；接著，凍結的影片模型根據這些指令、來自可編輯 3D 場景的預覽片段，以及視覺錨點（來自初始影像或前一片段）來渲染事件；最後，視覺語言模型觀察生成的影片片段，並根據觀察到的事件提出語意與空間狀態的更新建議。執行環境僅納入與固定規則相容的更新，從而確保狀態演化的權威性，並為下一輪互動提供正確的基礎。

**Q6：為什麼選擇使用凍結的影片模型而非微調？這種設計選擇的權衡為何？**
A：選擇使用凍結的影片模型是基於「通用性與效率」的考量——透過將規則執行外置於影片模型，新世界只需撰寫一個小型類型化程式即可定義，無需對渲染器進行昂貴的微調訓練。這種設計的權衡在於：雖然凍結模型在面對新規則時可能無法完美渲染所有細節，但透過 VisualScript 指令、預覽片段與視覺錨點的多重引導，可以大幅提升規則遵循度。實驗結果證明了這個權衡的合理性——同一個凍結的 MiniMax-H3 模型，僅透過完整的 Stateful Harness 框架就能將 PAIRFOLLOW 從 32% 提升至 92%，顯示分離架構的強大效益。

**Q7：WorldState-Bench 的設計有何獨特之處？反事實孿生對如何測試規則遵循度？**
A：WorldState-Bench 的獨特之處在於採用「反事實孿生對」（counterfactual twin pairs）的設計：每對案例共享相同的初始畫面與動作，但具有不同的隱藏變數，因此需要產生截然不同的預期結局。這種設計直接挑戰影片模型區分隱藏狀態的能力——若模型僅依賴視覺條件，則兩支影片很可能產生相同（或相似）的結果，從而無法通過測試。基準測試採用 Change-to-Comply 協議：Change 評估動作是否產生可辨識的事件，Comply 則評估該事件是否滿足可執行規則，這種雙重評估確保了測試既關注視覺變化也關注規則一致性。

**Q8：PAIRFOLLOW 與 PAIRSTRICT 兩個指標有何差異？為何需要兩個指標？**
A：PAIRFOLLOW 要求孿生對中的兩支影片都顯示其對應的預期結局，著重於「正向生成」的準確性；而 PAIRSTRICT 則在 PAIRFOLLOW 的基礎上，進一步要求被禁止的結局不出現在任一支影片中，強調「負向排除」的嚴格性。需要兩個指標是因為它們捕捉了不同的失敗模式：一個模型可能正確生成了預期結局，但同時也錯誤地出現了被禁止的結局（例如寶箱打開了，但門也意外打開了）。在論文的實驗中，MiniMax-H3 在僅指定預期結局時 PAIRFOLLOW 達到 64%，但 PAIRSTRICT 僅 4%，這個巨大差距凸顯了嚴格評估的必要性。

**Q9：從 32% 到 92% 的提升說明了什麼？不同條件下的消融結果如何解讀？**
A：從 32% 到 92% 的 PAIRFOLLOW 提升是一個極具說服力的消融結果：在僅使用規則提示的條件下，即使是 11 個影片後端中表現最好的也只有 32%；當明確指定預期結局時，MiniMax-H3 提升至 64%；而完整的 Stateful Harness 框架則達到 92%。這個漸進式提升清楚說明了三個關鍵要素的貢獻：明確的規則提示提供了基本指引，指定結局提供了更強的監督訊號，而完整的框架則透過預覽片段、視覺錨點與狀態更新機制實現了質的飛躍。值得注意的是，所有結果都來自同一個凍結的模型，這證明了框架設計本身——而非模型規模或微調——才是提升規則遵循度的關鍵。

**Q10：Stateful Harness 可應用於哪些實際場景？**
A：Stateful Harness 的應用場景相當廣泛，特別適合需要「持久性規則」與「隱藏狀態」的互動式系統。在遊戲開發中，它可以用於快速原型設計——設計師只需撰寫世界定義程式，就能讓玩家與 AI 生成的影片世界互動，而無需從零建構完整的遊戲引擎。在教育訓練模擬中，框架可用於建立具有明確規則的虛擬環境，例如醫療程序模擬或工業設備操作訓練，學習者的動作會根據隱藏狀態（如已完成的步驟、持有的工具）產生正確的後果。此外，在敘事娛樂與互動式電影領域，這個框架能讓觀眾的選擇產生符合世界觀邏輯的持久影響。

**Q11：將此框架產品化時需要考慮哪些工程挑戰？**
A：產品化 Stateful Harness 面臨多項工程挑戰：首先，視覺語言模型的觀察與狀態更新環節需要高度可靠性，因為錯誤的狀態推論會導致後續互動的連鎖失誤，這在長篇對話或多輪互動中尤其關鍵。其次，可編輯 3D 場景的建立與維護需要使用者或自動化工具提供足夠品質的空間資訊，這對一般使用者而言可能是進入門檻。再者，凍結影片模型的渲染延遲與成本需要最佳化，因為每個動作都需要生成影片片段並進行觀察推理，這在即時互動場景中可能成為瓶頸。最後，規則程式的撰寫需要兼顧表達力與安全性，避免使用者定義的規則產生意外後果。

**Q12：這項研究對世界模型領域的長期影響為何？**
A：這項研究的長期影響在於重新定位了世界模型的研究方向——從「如何生成更真實的影片」轉向「如何讓世界遵循明確的規則」。透過證明凍結的影片模型在正確的框架下可以達到 92% 的規則遵循度，論文挑戰了「必須微調影片模型才能處理複雜互動」的假設，為訓練-free 的世界建構開闢了新道路。此外，WorldState-Bench 與 Change-to-Comply 協議提供了一個標準化的評估方法，有助於未來研究進行可比較的實驗。這種「分離架構」的思路也可能影響其他領域，例如將語言模型的推理能力與影片生成能力解耦，以建立更可靠的多模態互動系統。

**Q13：論文承認的限制有哪些？**
A：論文承認的限制主要體現在幾個方面：首先，雖然 PAIRFOLLOW 達到 92%，但 PAIRSTRICT 的 90% 顯示仍有少數案例出現「預期結局正確但被禁止結局也出現」的情況，這反映了影片生成在精確控制上的固有困難。其次，框架的效能高度依賴視覺語言模型的觀察品質，若 VLM 無法正確識別生成影片中的細微變化，狀態更新就會出錯。再者，論文的評估主要集中在單輪反事實探測，雖然展示了多輪對決的案例，但缺乏對長篇互動的系統性量化評估。最後，規則的表達能力受限於可程式化引擎的能力，並非所有類型的世界邏輯都能輕易編碼。

**Q14：在什麼情況下 Stateful Harness 可能會失敗？**
A：Stateful Harness 可能失敗的情境包括：當視覺語言模型無法從生成影片中可靠地提取狀態變化資訊時（例如極細微的視覺差異或遮擋場景），狀態更新就會偏離實際發生的事件。當規則邏輯過於複雜或涉及多個相互依賴的隱藏變數時，執行環境的解析可能產生預期外的結果。當凍結的影片模型無法渲染出 VisualScript 指令所描述的特定事件時（例如模型從未見過的奇幻生物動作），即使規則正確，視覺輸出仍可能與預期不符。此外，在需要極高即時性的應用中，多輪的影片生成與 VLM 觀察所累積的延遲可能導致使用者體驗下降。

**Q15：未來的研究方向有哪些？**
A：未來的研究方向可從幾個維度展開：在評估方法上，可以擴展 WorldState-Bench 以涵蓋更長的互動序列、更複雜的規則結構，以及多代理互動情境。在技術改進上，可以探索更高效的視覺語言模型觀察機制，或開發專門針對狀態更新最佳化的輕量模型。在規則表達上，可以研究更豐富的規則語言，使非程式設計師也能輕鬆定義世界邏輯。在應用拓展上，可以將框架應用於機器人模擬、自動駕駛測試等需要明確規則與隱藏狀態的領域。此外，研究如何讓影片模型本身更好地遵循 VisualScript 指令（即使保持凍結），也是一個有價值的方向，可能進一步縮小 PAIRFOLLOW 與 PAIRSTRICT 之間的差距。

## 實務應用指南

### 適用場景

1. **互動式敘事遊戲與視覺小說開發**：遊戲設計師可利用 Stateful Harness 快速打造具備「隱藏狀態」分支邏輯的敘事體驗。例如，玩家是否持有鑰匙決定寶箱能否開啟、是否已與 NPC 交談決定能否進入特定區域。相較於傳統遊戲引擎需要完整美術與程式團隊，此框架只需撰寫一份「世界定義」即可生成對應影片。

2. **教育訓練模擬器**：在醫療、工業操作、緊急應變等領域，學習者的「隱藏狀態」（如已完成的檢查步驟、持有的工具）會影響後續動作的結果。可用於建構低成本、客製化的程序性訓練情境，例如「未關閉電源就開啟設備會導致短路」的因果演示。

3. **行銷與電商互動式影片**：品牌可為產品設計「選擇你的冒險」式互動影片，觀眾的隱藏偏好（已瀏覽的品項、加入購物車的商品）決定下一段影片走向，提升個人化體驗並降低傳統互動影片的製作成本。

4. **AI 代理人（Agent）行為評估環境**：研究人員可將 Stateful Harness 作為可控的測試平台，評估 VLM 或具身代理在「狀態依賴」任務中的表現，例如測試代理是否能正確推理「拿取鑰匙後才能開門」這類規則。

5. **電影分鏡與前期視覺化**：編劇與導演可在不實際拍攝的情況下，透過規則驅動的影片生成探索不同敘事分支的視覺呈現，加速創意發想與腳本迭代。

### 實作前置條件

**資料需求**
- 一張高品質的「初始影像」作為視覺錨點（建議解析度 ≥ 1080p，主體清晰、構圖簡潔）
- 一份「世界描述」文件，描述場景、物件、角色與其屬性
- 一份「規則程式」：以型別化程式語言（如 Python 或自訂 DSL）描述狀態變數、可執行的動作、與規則邏輯
- 一個「可編輯 3D 場景」檔案（如 Blender、USD、glTF 格式），用於空間佈局與攝影機路徑

**運算資源**
- 一台配備 ≥ 24GB VRAM 的 GPU（如 NVIDIA A6000 / RTX 4090），用於執行凍結的影片生成模型
- 影片生成推論時間：單段 5 秒 1080p 影片約需 30–90 秒（依模型而異）
- 視覺語言模型（VLM）推論：可使用 7B–13B 參數的開源模型（如 Qwen2-VL、LLaVA），單次推論 < 5 秒
- 程式編寫代理（coding agent）：可使用 GPT-4、Claude 或本地 LLM，建議具備函式呼叫能力

**技能前提**
- 熟悉 Python 程式設計與基本的狀態機概念
- 具備 3D 場景編輯基礎（Blender 或類似工具）
- 對影片生成模型（Diffusion-based）的提示工程（prompt engineering）有基本理解
- 了解 VLM 的能力邊界與幻覺風險

### 實作步驟建議

**步驟 1：定義世界規格**
從一張初始影像與一段世界描述開始，使用 coding agent 自動產生三項產出：
- `world_state.py`：語意狀態結構（如 `inventory: list[str]`、`progress: int`）
- `actions.py`：可用動作的列舉與參數
- `rules.py`：可執行規則，例如 `if "key" in inventory and action == "open_chest": unlock_chest()`

**步驟 2：建立可編輯 3D 場景**
在 Blender 或類似工具中重現初始影像的空間佈局，標註關鍵物件的座標、可互動區域、與攝影機路徑。輸出為結構化檔案（建議 JSON + glTF），供執行環境在每回合讀取與更新。

**步驟 3：組裝 Stateful Harness 執行環境**
實作以下迴圈：
1. 接收使用者動作 → 呼叫 `rules.resolve(state, action)` 解析事件
2. 將事件編譯為 VisualScript 指令（含文字描述、空間座標、攝影機軌跡）
3. 從 3D 場景渲染「預覽片段」提供空間與攝影機引導
4. 將 VisualScript + 預覽片段 + 視覺錨點（初始影像或前一片段最後一幀）送入凍結的影片模型
5. 使用 VLM 解讀生成片段，更新語意與空間狀態
6. 將更新寫回 `world_state`，進入下一回合

**步驟 4：整合影片後端**
選擇一個影片生成模型作為凍結後端（論文中評測 11 個）。建議從開源模型（如 Wan2.1、HunyuanVideo）開始，搭配 ControlNet 或類似的攝影機/深度控制機制以接受預覽片段引導。

**步驟 5：建立評估迴路**
參考 WorldState-Bench 的 Change-to-Comply 協議：
- 為每個情境準備「反事實孿生對」：相同初始影像與動作，但隱藏狀態不同
- 自動檢查生成影片是否呈現「預期結局」且未出現「禁止結局」
- 計算 PAIRFOLLOW 與 PAIRSTRICT 兩項指標

**步驟 6：迭代與優化**
- 若 PAIRSTRICT 偏低：強化 VLM 的狀態更新邏輯，加入規則一致性檢查
- 若影片品質不穩：調整 VisualScript 指令的具體度，或更換影片後端
- 若空間一致性差：增加 3D 場景的細節，或使用更強的攝影機控制模組

**步驟 7：部署為產品**
- 將執行環境容器化（Docker），提供 REST API 或 WebSocket 介面
- 前端可用 React/Vue 串接，顯示當前狀態、可用動作、與生成影片
- 加入狀態序列化機制，支援存檔/讀檔與多回合長劇情

### 潛在風險與注意事項

**風險 1：影片模型對「禁止結局」的幻覺**
即使明確指示「不要開門」，影片模型仍可能生成開門畫面。PAIRSTRICT 在僅指定預期結局時僅 4%，顯示此問題嚴重。
**緩解**：在 VisualScript 中加入負向提示詞（negative prompt）；使用影片後處理模型檢測並裁剪違規片段；設計規則時避免依賴「未發生事件」的視覺呈現。

**風險 2：VLM 狀態更新的錯誤累積**
VLM 解讀影片時可能誤判事件，導致狀態錯誤並在後續回合放大。
**緩解**：為每個狀態更新設定「規則相容性檢查」；保留狀態變更日誌以便回溯；對關鍵狀態轉換要求 VLM 給出信心分數，低於閾值時改為詢問使用者。

**風險 3：3D 場景與生成影片的視覺落差**
預覽片段來自 3D 場景，但最終影片由擴散模型生成，兩者風格可能不一致，造成引導失效。
**緩解**：3D 場景使用簡化幾何與中性材質，僅作為空間骨架；或對影片模型進行 LoRA 微調以貼近 3D 場景風格。

**風險 4：長回合劇情的狀態膨脹**
隨著回合增加，狀態變數與規則分支可能指數成長，難以維護。
**緩解**：採用模組化規則設計（每個 NPC/區域獨立規則檔）；定期重構世界定義；對未使用的狀態變數進行剪枝。

**風險 5：算力成本與延遲**
每個回合需呼叫影片模型，單回合 30–90 秒的延遲對即時互動是障礙。
**緩解**：預先生成常見動作的影片片段作為快取；採用較小的影片模型（如 1.3B 參數）作為預覽，僅在關鍵劇情點使用高品質模型。

**風險 6：規則設計的複雜度天花板**
論文展示的是「單回合、單規則」情境；複雜的多步驟規則（如合成兩個物品）尚未充分驗證。
**緩解**：將複雜規則拆解為多個原子動作；先在 WorldState-Bench 上驗證每個原子規則的 PAIRSTRICT 達標後再組合。

### 與其他技術的整合建議

**與遊戲引擎（Unity / Unreal）整合**
將 Stateful Harness 作為「敘事層」，遊戲引擎負責物理與操作手感。透過 WebSocket 將引擎中的玩家動作傳給 Harness，再將生成的影片以貼圖或序列幀方式回傳引擎播放。適合用於 2D 視覺小說或過場動畫。

**與 LLM Agent 框架（LangGraph / AutoGen）整合**
將 Harness 的 `rules.resolve()` 與 `state.update()` 包裝為 Agent 可呼叫的工具（tool），讓 LLM Agent 在執行任務時能「看見」自己動作的視覺後果，並據此調整策略。適合用於具身代理的視覺推理評測。

**與 RAG（檢索增強生成）系統整合**
將「世界定義」與「規則程式」存入向量資料庫，使用者可用自然語言查詢「現在能做什麼？」或「鑰匙在哪裡？」，由 RAG 系統從狀態中檢索並回答。

**與傳統影片編輯工具整合**
將生成的影片片段導入 DaVinci Resolve 或 Premiere Pro，由剪輯師進行後製（調色、配音、剪接）。Harness 負責生成「素材」，人類負責「成片」，兼顧效率與品質。

**與數位孿生（Digital Twin）平台整合**
在工業或城市數位孿生場景中，將感測器資料寫入 Harness 的世界狀態，影片生成作為「情境模擬器」，讓決策者以影片形式預覽不同操作的可能後果。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的 Figure 1 與 Figure 2，理解「為什麼需要分離規則執行與影片渲染」這個核心動機。接著跳到 WorldState-Bench 的評估結果（PAIRFOLLOW 從 32% 提升到 92%），這個數字能直觀感受框架的價值。技術細節可先略過，重點掌握「狀態、規則、影片」三者的分工概念。

**給 AI 工程師**：重點關注第 3 節的 Stateful Harness 架構圖與 VisualScript 編譯流程。建議實際動手實作一個最小可行版本：選一個開源影片模型（如 Wan2.1）、搭配 Qwen2-VL 作為 VLM、用 Blender 建一個簡單場景，重現論文的閉環流程。PAIRFOLLOW 與 PAIRSTRICT 的差距（92% vs 90%）暗示「禁止結局」的視覺消除仍是工程難題，值得深入研究。

**給研究者**：論文的關鍵貢獻在於「Change-to-Comply 協議」與「反事實孿生對」評測設計，這比單純的視覺品質指標更能反映世界模型的「規則遵循能力」。建議延伸方向：(1) 將 PAIRSTRICT 從 90% 推向 99% 需要什麼機制？(2) 多回合狀態傳遞的誤差累積如何量化？(3) 規則程式是否能由 LLM 自動合成並驗證？Table 12 對相關工作的介面比較是很好的起點。

**給產品經理**：這個框架的商業價值在於「用規則程式取代美術資產」，可大幅降低互動式影片的製作成本。建議先思考目標客群：遊戲工作室、行銷團隊、教育訓練機構各有不同的「世界定義」複雜度需求。PAIRFOLLOW 92% 已達可用水準，但 PAIRSTRICT 90% 仍意味著每 10 次互動約有 1 次出現「幻覺結局」，產品設計上需要準備「重試機制」或「人類審核節點」來緩解。
