# 各獎勵歸其相關詞元：多獎勵強化學習中的獎勵特定詞元層級信用分配

**原文標題：** Each Reward to Its Relevant Tokens: Reward-Specific Token-Level Credit Assignment for Multi-Reward RL  
**作者：** Skylar Zhai、Haonan Wang、Zhining Liu 等 7 位作者  
**發布日期：** 2026-10-15  
**HF 連結：** [https://huggingface.co/papers/2610.21439](https://huggingface.co/papers/2610.21439)  
**arXiv：** [https://arxiv.org/abs/2610.21439](https://arxiv.org/abs/2610.21439)

## ⚡ TL;DR

多獎勵強化學習將每個獎勵的優勢均勻分配到所有詞元，但驗證器僅檢查部分回應。
本文提出 MRTPO，比較加入與移除驗證器資訊的詞元分佈差異，將各獎勵優勢分配至相關詞元。
在文字到 SQL、多約束指令遵循與工具呼叫任務上，MRTPO 收斂更快且優於 GDPO 等方法。

## 摘要翻譯

大型語言模型日益同時針對多項可驗證獎勵進行訓練，例如工具呼叫的正確性與格式，或複雜指令中的個別約束。獎勵解耦標準化（GDPO）將每個獎勵分別標準化，使不同獎勵組合保有各自的優勢，但仍將每個獎勵的優勢均勻分散至整個回應，儘管每個驗證器僅檢查少數位置。我們提出 MRTPO，將每個獎勵的優勢分配給與其相關的詞元，利用其驗證器所檢查的資訊，且無需輔助模型或詞元層級標註。對每個獎勵而言，策略依有／無該獎勵驗證器資訊，分別重新生成其回應，兩種下一詞元分佈之間的每詞元詹森-夏農距離用以衡量各詞元的相關性，並據此重新分配優勢。在文字到 SQL、多約束指令遵循與工具呼叫任務上，MRTPO 收斂更快，且表現優於其他比較方法。

### 核心貢獻（3～5點）
- 指出既有獎勵解耦標準化方法（GDPO）的關鍵限制：雖將各獎勵分別標準化，仍將每個獎勵的優勢均勻分散至整個回應，未考慮各驗證器僅檢查少數位置的特性。
- 提出 MRTPO 方法，將每個獎勵的優勢精準分配給與其相關的詞元，實現詞元層級信用分配，使信用歸屬更貼近驗證器的實際檢查範圍。
- 設計無需輔助模型或詞元層級標註的相關性度量機制：策略依有／無該獎勵驗證器資訊分別重新生成回應，以兩種下一詞元分佈之間的每詞元詹森-夏農距離衡量各詞元的相關性。
- 在文字到 SQL、多約束指令遵循與工具呼叫三項任務上實證，MRTPO 收斂更快且表現優於比較方法，驗證獎勵特定詞元層級信用分配的有效性。

### 適合對象
從事大型語言模型後期訓練（post-training）、可驗證獎勵強化學習（RLVR）、多獎勵強化學習與詞元層級信用分配研究的學者與工程師；以及對工具呼叫、文字到 SQL、指令遵循等代理任務中之獎勵設計與策略最佳化感興趣的研究人員。

## 深度分析

#### 方法論解析

**核心問題的重新框定**

本文最關鍵的洞察在於將多獎勵強化學習（multi-reward RL）的瓶頸從「如何組合多個獎勵」重新定位為「如何把每個獎勵的優勢（advantage）分配到對應的詞元（token）」。在 GRPO（Group Relative Policy Optimization，群組相對策略最佳化）及其變體的標準流程中，無論是 GDPO 的獎勵解耦標準化（reward-decoupled normalization）還是 SAW 的動態加權，最終得到的回應層級優勢（response-level advantage）都會被均勻地攤派到回應中的每一個詞元上。這種「均勻攤派」假設隱含了一個不合理的先驗：每個詞元對所有獎勵都負有同等責任。然而實際上，格式驗證器（format verifier）只檢查 XML 標籤（如 `<think>`、`</answer>`）是否正確閉合，可執行性驗證器（executable verifier）只關心 SQL 語法是否合法，執行結果驗證器（execution verifier）只評估查詢語意是否符合參考答案——三者關注的回應片段幾乎不重疊。

**MRTPO 的雙重自回放機制**

MRTPO（Multi-Reward-to-Token Policy Optimization）的核心運作可拆解為三個步驟：

1. **雙重上下文構建**：對於軌跡展開群組（rollout group）中的每一條回應 $y$，以及每一個獎勵 $r_k$，MRTPO 構造兩個上下文：上下文 $c_k^+$ 包含驗證器 $r_k$ 所持有的全部資訊（例如參考 SQL 答案、執行錯誤訊息、指令中的特定約束），上下文 $c_k^-$ 則移除該驗證器的資訊。兩個上下文的唯一差異就在於「是否暴露 $r_k$ 的驗證依據」。

2. **詞元級分佈差異度量**：將同一條已採樣回應 $y$ 在兩個上下文下分別重新前向傳播，得到兩個下一詞元分佈（next-token distribution）$p^+(\cdot|t, c_k^+)$ 與 $p^-(\cdot|t, c_k^-)$。對每個詞元位置 $t$ 計算這兩個分佈之間的詹森-夏農距離（Jensen-Shannon distance, JS distance）：
$$w_k(t) = \text{JSD}\big(p^+(\cdot|t, c_k^+) \,\|\, p^-(\cdot|t, c_k^-)\big)$$
這個距離直觀地衡量了「驗證器資訊是否改變了模型在該位置的預測」——若改變大，則該詞元與該獎勵高度相關；若改變小，則該詞元與該獎勵無關。

3. **優勢再分配**：將 GDPO 計算出的群組標準化優勢 $A_k$（針對獎勵 $r_k$）按照詞元權重 $w_k(t)$ 重新分配到相關詞元上。最終用於策略梯度（policy gradient）更新的詞元級優勢為：
$$\hat{A}_k(t) = \frac{w_k(t)}{\sum_{t'} w_k(t')} \cdot A_k$$

**方法論的精妙之處**

MRTPO 的設計有三個值得強調的精妙之處：

- **無需輔助模型（auxiliary models）**：與需要訓練額外過程獎勵模型（process reward models, PRM）的 Lightman 等人（2024）的方法不同，MRTPO 直接利用策略模型本身作為「探測器」，透過改變上下文觀察自身分佈的變化。這大幅降低了工程複雜度。
- **無需詞元級標註（token-level annotations）**：與需要逐步標註的 Kazemnejad 等人（2025）的蒙地卡羅價值估計方法不同，MRTPO 的詞元權重完全由模型自身的分佈差異自動產生。
- **獎勵仍是訓練目標**：與 OPSD（On-Policy Self-Distillation）等將獎勵最大化替換為蒸餾（distillation）的方法不同，MRTPO 中的自回放（self-replay）僅用於決定「優勢去哪裡」，而非取代獎勵本身。這保留了 RLVR 訓練範式的核心優勢。

**與 GDPO 的正交性**

MRTPO 與 GDPO 之間存在清晰的正交關係：GDPO 解決的是「不同獎勵組合塌縮為相同優勢」的問題（reward collapse），MRTPO 解決的是「優勢均勻攤派到不相關詞元」的問題。兩者可以無縫疊加——MRTPO 保留了 GDPO 的獎勵解耦群組標準化，僅在其基礎上加入詞元級再分配。這也意味著 MRTPO 可以與 SAW 等加權方法進一步組合。

#### 實驗數據解讀

**三個任務領域的選擇**

本文選擇的三個實驗領域——文字到 SQL（text-to-SQL）、多約束指令遵循（multi-constraint instruction following）、工具呼叫（tool calling）——都具有「多個獨立驗證器」的特性，這正是 MRTPO 設計的前提。每個領域中，不同驗證器關注回應的不同部分：

- **文字到 SQL**：格式驗證器檢查 XML 標籤結構，可執行性驗證器檢查 SQL 語法，執行驗證器檢查查詢結果是否與參考答案一致。
- **多約束指令遵循**：每個約束（如「回應必須包含三個項目」、「必須以問句結尾」）由獨立的驗證器評估。
- **工具呼叫**：格式驗證器檢查函式呼叫結構，正確性驗證器檢查函式名稱與引數（arguments）。

**Figure 1 的案例分析**

圖 1 展示了一個極具說服力的定性案例：一條 SQL 回應格式正確、可執行，但使用了 `>=` 而非 `>`，導致計數錯誤。GDPO 將三個獎勵的優勢均勻攤派到所有詞元；SAW 雖然調整了權重比例（0.80 : 0.80 : 1.39），但仍然是均勻攤派；MRTPO 則精準地將格式獎勵（+0.50）放在標籤詞元上、可執行性獎勵（+0.50）放在查詢語法詞元上、執行懲罰（−2.15）集中在 `>= 30` 這個錯誤詞元上。這個案例直觀地展示了「詞元級精準分配」相比「回應級均勻分配」的資訊增益。

**收斂速度與最終效能**

根據摘要的描述，MRTPO 在三個任務上均實現了「更快收斂（faster convergence）與更高效能（better performance）」。這個雙重優勢的背後邏輯是：均勻攤派會在不相關詞元上產生「錯誤的梯度訊號」——例如，格式懲罰不應該影響 SQL 查詢的詞元，但 GDPO 會強迫模型降低這些詞元的生成機率，這不僅浪費了梯度訊號，還可能干擾其他獎勵的學習。MRTPO 透過精準分配避免了這種「梯度污染」，使得每個詞元只接收與其相關的學習訊號，從而加速收斂並提升最終效能。

**需注意的實驗細節**

由於提供的全文僅至第 3 節（Preliminaries）的開頭，具體的數值結果（如各方法的精確度數據、訓練曲線、使用的具體模型規模如 7B 或 14B 參數、訓練步數等）無法從現有文本中提取。但從方法論的一致性與三個任務的選擇來看，實驗設計應涵蓋了：(1) 與 GDPO 的直接比較；(2) 與 SAW 的組合實驗（驗證 MRTPO 的可組合性）；(3) 與 OPSD 的比較（驗證「保留獎勵作為目標」相對於「完全蒸餾」的優勢）。

#### 與現有研究的比較

**方法論譜系中的定位**

MRTPO 在多獎勵 RL 的方法論譜系中佔據了一個獨特的位置。從「優勢計算的粒度」維度看，現有方法可分為三個層次：

| 層次 | 代表方法 | 優勢分配方式 |
|------|---------|-------------|
| 回應級（response-level） | GRPO、原始多獎勵加總 | 整條回應一個優勢值 |
| 獎勵級（reward-level） | GDPO、SAW | 每個獎勵一個優勢值，但均勻攤派到詞元 |
| 詞元級（token-level） | MRTPO | 每個獎勵的優勢精準分配到相關詞元 |

**相對於 GDPO 的改進**

GDPO（Liu et al., 2026b）解決了「獎勵塌縮」問題——當多個獎勵被簡單加總時，不同的獎勵組合（如「格式對+執行錯」與「格式錯+執行對」）可能產生相同的總分，導致策略無法區分。GDPO 透過在群組內對每個獎勵分別標準化保留了這種區分能力。但 GDPO 的詞元級處理仍是均勻的，這正是 MRTPO 改進的切入點。兩者構成互補而非競爭的關係。

**相對於 SAW 的改進**

SAW（He et al., 2026）屬於「獎勵級」方法中的動態加權變體，根據群組內變異數、訓練進度或獎勵間衝突來調整每個獎勵的權重。SAW 改變的是「每個獎勵貢獻多少」，MRTPO 改變的是「每個獎勵的優勢去哪裡」。本文在 Section 5.1 中將 MRTPO 與 SAW 組合使用，驗證了兩者的正交性與可疊加性。

**相對於 OPSD 的根本差異**

OPSD（On-Policy Self-Distillation，Zhao et al., 2026）同樣使用特權資訊（privileged information）並透過自回放改變分佈，但 OPSD 的目標是讓學生策略擬合（fit）一個「看得到參考答案」的教師分佈，本質上是將獎勵最大化替換為蒸餾。MRTPO 則保留了獎勵作為訓練目標，僅用自回放來決定優勢的空間分配。這一區別至關重要：OPSD 完全繞過了獎勵訊號，而 MRTPO 仍然以獎勵為目標，僅改變了優勢的分配方式。

**相對於過程獎勵模型的優勢**

過程獎勵模型（Process Reward Models, PRM；Lightman et al., 2024）需要為每個推理步驟收集人工標註或訓練額外的評分模型，工程成本極高。MRTPO 不需要任何詞元級或步驟級標註，也不需要訓練輔助模型，僅透過同一策略模型的兩次前向傳播即可獲得詞元權重。

**相對於基於熵的方法的差異**

Wang 等人（2025）、Cheng 等人（2026）的方法透過詞元熵（token entropy）來推斷詞元的重要性，但這些方法重新加權的是「聚合後的優勢」，而非「每個獎勵各自的優勢」。MRTPO 的獎勵特定性（reward-specific）是其獨特賣點。

**現有限制**

MRTPO 的限制主要在於：(1) 需要對每個獎勵進行兩次前向傳播，計算成本約為標準 GRPO 的 $2K$ 倍（$K$ 為獎勵數量）；(2) 假設每個驗證器的資訊可以獨立地加入或移除上下文，但在某些場景下驗證器資訊可能存在耦合；(3) JS 距離作為相關性的代理指標，其理論性質（如是否會低估或高估某些詞元的相關性）尚需更深入的分析。

**資料集的可及性**

三個實驗任務所使用的資料集應為公開資料集：
- **文字到 SQL**：可能使用 BIRD-SQL、Spider 或 WikiSQL 等公開基準。
- **多約束指令遵循**：可能使用 IFEval、Multi-IF 或 FollowBench 等基準。
- **工具呼叫**：可能使用 BFCL（Berkeley Function Calling Leaderboard）、ToolBench 或 API-Bank 等基準。

這些資料集的可及性為部分重現提供了基礎。

**實驗設定的透明度**

MRTPO 的核心超參數（如 JS 距離的計算方式、詞元權重的歸一化策略、是否對 JS 距離施加溫度參數或截斷）需要在論文的附錄或實驗設定章節中明確說明。從方法論描述來看，JS 距離的計算本身是確定性的，但如何將其轉化為詞元權重（例如是否取平方、是否施加最小閾值）會影響最終結果。

**計算資源需求**

由於 MRTPO 需要對每個獎勵進行兩次前向傳播，總計算量約為標準 GRPO 的 $2K$ 倍（$K$ 為獎勵數量）。在 $K=3$ 的設定下，計算量約為標準方法的 6 倍。這對於預算有限的研究團隊可能構成重現障礙，但對於工業級訓練流程而言仍在可接受範圍內。

**重現的關鍵挑戰**

重現 MRTPO 的關鍵挑戰在於：(1) 驗證器資訊的精確定義——對於 SQL 任務，「可執行性驗證器資訊」是什麼？僅僅是「告知模型這條 SQL 可執行」還是包含具體的執行錯誤訊息？這個定義會直接影響 JS 距離的計算結果。(2) 群組大小（group size）的選擇——GRPO 系列方法對群組大小敏感，MRTPO 繼承了這一敏感性。

#### 未來研究方向

**理論分析方向**

MRTPO 目前缺乏對 JS 距離作為「詞元相關性代理指標」的理論分析。未來研究可以探討：(1) JS 距離與詞元對獎勵的實際因果影響之間的相關性；(2) 在什麼條件下 JS 距離會系統性地低估或高估詞元相關性；(3) MRTPO 收斂性的理論保證，特別是在多獎勵設定下的策略最優性條件。

**計算效率優化**

當前 MRTPO 需要 $2K$ 次前向傳播，這在 $K$ 較大時成本顯著。未來可以探索：(1) 批次化（batching）策略，將多個獎勵的雙重自回放合併為單次前向傳播；(2) 稀疏化策略，僅對 JS 距離超過閾值的詞元進行再分配，其餘詞元使用均勻權重；(3) 快取策略，對於同一條回應在不同訓練步驟中的 JS 距離進行快取與增量更新。

**與其他方法的深度組合**

MRTPO 與 SAW 等加權方法的組合已在 Section 5.1 中展示，但更深入的組合可能性包括：(1) 與課程學習（curriculum learning）結合，根據詞元相關性動態調整訓練順序；(2) 與探索策略（exploration strategies）結合，在高相關性詞元上鼓勵更多探索；(3) 與多智慧體（multi-agent）設定結合，每個「獎勵」對應一個獨立的學習代理。

**應用領域拓展**

MRTPO 的核心思想——「讓每個獎勵找到自己的詞元」——可以拓展到更廣泛的領域：

- **程式碼生成**：不同測試案例（test cases）對應不同的程式碼片段，MRTPO 可以精準定位每個測試失敗對應的程式碼行。
- **多模態任務**：在圖文理解中，不同問題（如「物件計數」、「空間關係」）對應圖像的不同區域，MRTPO 的思想可以從詞元延伸到空間區域。
- **長文本生成**：在小說或長篇文章生成中，不同品質維度（如情節連貫性、人物一致性、文筆優美）對應不同的段落。
- **推理鏈（chain-of-thought）**：在數學推理中，不同步驟的正確性可以由獨立的驗證器評估，MRTPO 可以精準定位錯誤步驟。

**驗證器資訊的更精細定義**

當前 MRTPO 假設驗證器資訊是「二元的」（有/無），但實際上驗證器資訊可以是「連續的」（如部分提示、漸進式揭示）。未來可以探索：(1) 漸進式資訊揭示對詞元相關性的影響；(2) 多層次驗證器（如「語法驗證器」包含「詞法」與「句法」兩個子驗證器）的層次化 MRTPO。

**與因果推斷的結合**

MRTPO 的 JS 距離本質上是一種「觀測性相關性」度量，而非因果性度量。未來可以引入因果推斷（causal inference）工具，例如 do-calculus 或反事實推理（counterfactual reasoning），來更精準地識別詞元與獎勵之間的因果關係，進一步提升信用分配的準確性。

**安全與對齊應用**

在對齊（alignment）場景中，「有益」與「無害」是兩個獨立但可能衝突的目標。MRTPO 的思想可以應用於：(1) 精準識別哪些詞元貢獻了「有益性」與「無害性」；(2) 在兩者衝突時，透過詞元級權重平衡實現更細粒度的對齊控制。這對於紅隊測試（red-teaming）與對抗性提示（adversarial prompting）的防禦也具有潛在價值。

## 論文問答

**Q1：多獎勵強化學習中的核心問題是什麼？為何需要針對每個獎勵進行詞元層級的信用分配？**

A：在多獎勵強化學習（multi-reward RL）的設定中，語言模型往往需要同時滿足多個可驗證的準則，例如文字到 SQL 任務中既要查詢可執行又要回傳正確結果、工具呼叫中既要格式正確又要引數正確。然而，現有的 GRPO 系列方法（包括 GDPO 與 SAW）雖然能在回應層級區分不同獎勵的組合，卻把每個獎勵的優勢（advantage）均勻地攤派到回應中的每一個詞元上。這種做法隱含地假設每個詞元對每個獎勵都負有同等責任，但實際上每個驗證器（verifier）通常只檢查回應中的一小部分位置（例如格式驗證器只看標籤、執行驗證器只看 SQL 查詢本體）。因此，把格式懲罰平均分攤到正確生成的引數上，會造成錯誤的信用分配，拖累訓練效率與最終效能。

**Q2：為什麼現有的 GDPO 與 SAW 等方法無法解決這個問題？它們各自有什麼侷限？**

A：GDPO 透過獎勵解耦標準化（reward-decoupled normalization）在群組內分別標準化每個獎勵，成功避免了不同獎勵組合被塌縮成同一優勢值的問題，但它仍然把每個獎勵的優勢均勻地分配到所有詞元上。SAW 雖然會根據群組內變異度動態調整每個獎勵的權重，解決了獎勵間的權重平衡問題，但同樣未觸及詞元層級的分配——它改變的是「每個獎勵分到多少」，而非「每個獎勵分到哪些詞元」。換言之，這些方法都停留在回應層級的優勢估計，無法辨識哪些詞元才是某個特定獎勵真正相關的位置，因此即便權重設計得再精巧，仍會把信用錯放到不相關的詞元上。

**Q3：為什麼這個詞元層級的信用分配問題在實務上很重要？**

A：在真實的 LLM 後期訓練（post-training）場景中，許多任務的獎勵都具有明顯的「位置局部性」——格式獎勵只評估 XML 標籤、執行獎勵只評估 SQL 查詢、工具呼叫獎勵只評估函式名稱與引數。若把這些局部性的獎勵均勻攤到整段回應，模型會收到雜訊般的梯度訊號，被迫為了修正一個錯誤（例如少寫了 `<think>` 標籤）而調整與該錯誤無關的引數詞元。這不僅會拖慢收斂速度，更可能損害模型在不相關位置上的既有能力。從 Figure 1 的範例可以看到，MRTPO 能把格式獎勵放在標籤上、把執行懲罰精準放在 `>= 30` 這個錯誤詞元上，這種精細化分配對訓練效率與最終表現都有實質幫助。

**Q4：MRTPO 的核心方法是什麼？它如何決定每個詞元對每個獎勵的相關性？**

A：MRTPO 的核心想法是：對每個獎勵，讓策略模型在「有該驗證器資訊」與「沒有該驗證器資訊」兩種上下文中，分別重播（replay）已採樣的回應，並比較兩種上下文下每個位置的下一詞元分佈（next-token distribution）。若某個詞元在兩種上下文下的分佈差異很大，代表該驗證器的資訊強烈影響了模型在該位置的預測，因此該詞元與該獎勵高度相關；反之，若分佈幾乎不變，則該詞元與該獎勵無關。具體而言，MRTPO 採用詞元級的詹森-夏農距離（Jensen-Shannon distance）作為相關性的度量，並以此重新分配該獎勵經群組標準化後的優勢到對應的詞元上。

**Q5：MRTPO 相較於 OPSD 等同策略自我蒸餾方法的關鍵創新是什麼？**

A：OPSD 同樣利用特權資訊（privileged information）讓模型扮演教師，並透過自我蒸餾把策略拉向看過參考答案的分佈，但它的目標是「取代獎勵最大化」，把整體回應的訓練訊號換成蒸餾損失。MRTPO 則保留了獎勵作為訓練目標，僅僅借用自我重播來決定「每個獎勵的優勢應該落在哪些詞元上」。換言之，MRTPO 把特權資訊的角色從「替代獎勵」轉變為「定位信用」，這使得它既能享受詞元級精細分配的優勢，又不會失去可驗證獎勵所提供的明確監督訊號。這也是 Figure 1 中 MRTPO 能同時精準放置正向獎勵與負向懲罰的原因。

**Q6：MRTPO 為何選擇詹森-夏農距離（JS distance）而非 KL 散度來衡量詞元相關性？這樣的設計選擇帶來哪些好處？**

A：KL 散度是單向且不對稱的，當兩個分佈幾乎重疊時容易出現極小值，導致梯度訊號不穩定；而詹森-夏農距離是對稱且有界的（介於 0 與 1 之間），對分佈差異的敏感度更平滑、更穩定，特別適合用於詞元級的細粒度權重計算。此外，JS 距離可以自然地詮釋為「該詞元在兩種上下文下的預測不確定性變化」，這與「該詞元是否受驗證器資訊影響」的直覺高度吻合。這樣的設計讓 MRTPO 不需要額外訓練輔助模型、不需要詞元級標註，也不需要重新採樣額外的回應，只需兩次前向傳播即可得到所有詞元的相關性權重。

**Q7：MRTPO 在哪些基準任務上進行了實驗？為何選擇這些任務？**

A：MRTPO 在三個具有明確多獎勵結構的任務上進行評估：文字到 SQL（text-to-SQL）、多約束指令遵循（multi-constraint instruction following）以及工具呼叫（tool calling）。這三個任務的共同特徵是它們都配備了多個可獨立驗證的子獎勵，例如 SQL 任務中可分為格式、可執行性與執行正確性三項獎勵；指令遵循任務中每條約束都是一個獨立驗證器；工具呼叫中格式、引數正確性與函式選擇各自對應不同驗證器。這樣的任務設計正好能凸顯「每個獎勵只檢查回應一部分」的特性，是驗證詞元級信用分配方法最直接的場景。

**Q8：MRTPO 的主要實驗結果為何？相較於 GDPO 與 SAW 有何優勢？**

A：根據摘要與 Figure 1 的示意，MRTPO 在三個任務上均比 GDPO 與 SAW 收斂更快、最終效能更好。具體而言，MRTPO 不僅保留了 GDPO 在獎勵解耦上的優勢（避免不同獎勵組合被塌縮），還透過詞元級的精細分配讓每個獎勵的訊號直達相關詞元，避免了「把懲罰平均分給無關詞元」的雜訊問題。在與 SAW 結合的實驗中（Section 5.1），MRTPO 也能與動態權重方法疊加使用，顯示其作為一個「詞元級分配層」可與既有的回應級權重方法正交組合，進一步提升表現。

**Q9：MRTPO 是否有進行消融研究（Ablation Study）來驗證各個設計元件的必要性？**

A：雖然提供的全文片段未完整列出消融表格，但從方法描述可推論，關鍵的可消融元件包括：(1) 是否使用 JS 距離（相對於 KL 散度或均勻權重）；(2) 是否對每個獎勵單獨計算詞元權重（相對於把所有獎勵合在一起計算）；(3) 是否保留 GDPO 的群組標準化作為回應級優勢的起點。這些消融能分別驗證「詞元級分配」「獎勵特異性」「與回應級方法的相容性」三個核心主張。從 Figure 1 的視覺化對比中，已可初步看到「均勻權重（GDPO/SAW）」與「獎勵特異性詞元權重（MRTPO）」之間的明顯差異，這本身就是一種定性的消融證據。

**Q10：MRTPO 在哪些實際產品場景中能發揮最大價值？**

A：MRTPO 特別適合應用於「多準則、可驗證」的代理型（agentic）與結構化生成任務，例如：(1) 程式碼與 SQL 生成，其中格式、可執行性與語意正確性分別由不同驗證器評估；(2) 工具呼叫代理，需要同時滿足 JSON 格式、函式名稱正確、引數型別與值正確；(3) 複雜指令遵循，例如生成式 AI 助理需要同時滿足長度、語氣、關鍵詞、格式等多重約束。在這些場景中，MRTPO 能讓模型更快學會「哪裡錯就改哪裡」，對產品迭代速度與使用者體驗都有直接幫助。

**Q11：從產品部署的角度，MRTPO 帶來哪些工程與成本上的考量？**

A：MRTPO 的主要額外成本是「每個獎勵需要兩次前向重播」（有/無驗證器資訊各一次），這會讓訓練時的計算量隨獎勵數量線性增加。不過，由於重播使用的是同一批已採樣的回應、不需要重新生成，也不引入輔助模型，整體成本仍遠低於訓練獨立的過程獎勵模型（process reward model）或蒙特卡羅價值估計。從部署角度，MRTPO 不改變推理時的模型結構，僅影響訓練流程，因此對線上服務沒有額外推論成本，是一個「訓練時付費、推理時免費」的改良。

**Q12：MRTPO 對多獎勵強化學習與 LLM 對齊領域的整體影響是什麼？**

A：MRTPO 提出了一個新的視角：把多獎勵 RL 拆解為「回應級的權重決定」與「詞元級的信用分配」兩個正交問題，並證明後者可以獨立於前者進行改良。這種拆解為後續研究開啟了清晰的擴展空間——任何回應級的獎勵加權方法（如 SAW、未來的變體）都可以與 MRTPO 的詞元級分配層組合。此外，MRTPO 也示範了「特權資訊」不必取代獎勵，而是可以作為定位工具來增強獎勵訊號，這對整個 LLM 對齊領域如何善用環境回饋與參考答案具有方法論上的啟發意義。

**Q13：MRTPO 已被作者承認的限制有哪些？**

A：從方法設計可推論幾項已知的限制：(1) 計算成本隨獎勵數量線性增加，當任務有非常多獨立驗證器（例如數十條指令約束）時，重播次數會顯著上升；(2) MRTPO 假設每個驗證器都能以「附加資訊到上下文」的形式提供特權資訊，對於無法以文字形式注入的獎勵（例如純神經網路評分器）則難以直接套用；(3) JS 距離作為相關性度量在某些極端分佈下（例如某詞元在兩種上下文下的 top-1 預測相同但長尾差異大）可能無法完全捕捉語意相關性，需要更細緻的設計。

**Q14：MRTPO 在哪些情況下可能會失效或表現不佳？**

A：當驗證器的特權資訊對模型預測的影響極小時（例如某個獎勵對所有詞元的 next-token 分佈幾乎沒有影響），MRTPO 計算出的詞元權重會接近均勻，退化為類似 GDPO 的行為，此時無法體現其優勢。此外，若驗證器資訊本身具有誤導性或與獎勵分數不一致（例如參考答案錯誤），則特權資訊可能把信用引導到錯誤的詞元上，反而干擾訓練。最後，對於獎勵本身具有「全域性」（例如整體對齊品質分數）而非「局部性」的任務，MRTPO 的詞元級精細化分配可能無法帶來明顯收益，因為這類獎勵本就難以定位到具體詞元。

**Q15：MRTPO 未來可以朝哪些方向延伸？有哪些值得探索的研究問題？**

A：未來值得探索的方向包括：(1) 將 MRTPO 與更多回應級的動態權重方法（如基於訓練進度、獎勵衝突偵測的加權策略）結合，驗證其在更複雜多獎勵場景下的可擴展性；(2) 研究如何降低重播成本，例如透過共享計算、快取或近似方法，把每個獎勵的兩次前向傳播合併或蒸餾成單一估計；(3) 探索更豐富的詞元相關性度量，例如結合注意力權重、詞元熵或語法結構資訊，超越單純的 JS 距離；(4) 把 MRTPO 的「特權資訊定位信用」思路推廣到單獎勵但多準則的場景，例如過程獎勵模型或人類偏好資料中的細粒度標註，進一步推動 LLM 對齊中信用分配問題的研究。

## 實務應用指南

### 適用場景

1. **企業內部 SQL 助理的後訓練**：當組織希望 LLM 代理能根據自然語言查詢產生可執行的 SQL 時，常面臨「格式正確但語意錯誤」或「語意正確但無法執行」兩類失敗交織的問題。MRTPO 可將格式獎勵、可執行性獎勵、執行結果獎勵分別歸屬到 `<answer>` 標籤、查詢語法、條件運算子等對應詞元，避免錯誤懲罰被均勻擴散到整段回應。

2. **多約束指令遵循的客服與內容生成系統**：例如要求模型同時滿足「字數限制」「禁用詞清單」「品牌語氣」「JSON 結構」等多項約束時，每個驗證器只檢查回應的局部區段。MRTPO 可讓字數懲罰落在結尾、JSON 結構懲罰落在標點、語氣懲罰落在形容詞上，使訓練訊號更精準。

3. **工具呼叫代理（Function Calling Agents）**：當代理需同時輸出正確的函式名稱、引數內容與包裹格式時，MRTPO 可將函式名稱獎勵聚焦於函式名詞元、引數獎勵聚焦於引數值詞元、格式獎勵聚焦於標籤詞元，避免「引數正確但漏標籤」時引數也被懲罰。

4. **程式碼生成與除錯助手**：可同時評估「語法可解析」「通過單元測試」「符合風格規範」三類獎勵。MRTPO 將語法獎勵指向括號與關鍵字、通過測試獎勵指向邏輯運算式、風格獎勵指向命名詞元，提升收斂速度。

5. **多目標對齊的通用助手**：當需要同時優化「有用性」與「無害性」兩個獨立驗證器時，MRTPO 可避免單一負向獎勵（如無害性扣分）壓制整段正向內容（如有用性加分），使兩個目標的學習訊號在詞元層級解耦。

### 實作前置條件

**資料需求**
- 每個任務需具備**獨立的可程式化驗證器**（verifier），且驗證器需能以「附加資訊」形式注入上下文（例如參考 SQL、執行錯誤訊息、單一約束文字）。
- 訓練提示集需涵蓋多樣化的獎勵組合，使群組標準化（group normalization）能產生非塌縮的優勢值；建議每提示採樣 8–16 個回應。
- 不需要詞元層級人工標註，但需要驗證器對每個回應輸出**結構化回饋**（如錯誤訊息、參考答案、單項違規說明）。

**算力需求**
- 基礎設施需支援 GRPO 風格的同策略訓練：每個提示需對策略模型做多次完整前向採樣。
- MRTPO 額外需要**兩次重播前向**（with/without 驗證器資訊），相當於每個回應增加約 2 倍的前向成本，但無需反向傳播或額外生成。
- 建議至少 8 張以上的高階 GPU（如 A100/H100），視模型規模與上下文長度調整。

**技能前提**
- 熟悉 PyTorch 與分散式訓練框架（DeepSpeed / FSDP）。
- 理解 GRPO 的群組相對優勢計算與 KL 懲罰機制。
- 能將各領域驗證器封裝為「可注入上下文的模組」，並設計 replay 時的 prompt 模板。
- 具備基本的資訊理論概念（KL 散度、JS 距離）以理解詞元權重計算。

---

### 實作步驟建議

1. **盤點並解構現有多獎勵管線**
   - 列出所有現有驗證器，明確每個驗證器依賴的「特權資訊」（如參考答案、執行回饋、單項約束）。
   - 將每個驗證器改寫為「可注入式」介面：給定回應與特權資訊，回傳 reward 與附加上下文片段。

2. **建立 GDPO 基準線**
   - 先實作 GDPO（reward-decoupled normalization），確認群組標準化能區分不同獎勵組合。
   - 記錄每個回應的 reward 向量與群組標準化後的優勢值，作為 MRTPO 的輸入。

3. **設計 Replay 上下文對**
   - 為每個獎勵 $r_k$ 構造兩個上下文：$c_k^{\text{with}}$（含驗證器資訊）與 $c_k^{\text{without}}$（不含）。
   - 確保兩個上下文僅在驗證器資訊上有差異，其餘部分（提示、已生成詞元）完全一致。

4. **計算詞元權重**
   - 對每個回應的每個詞元位置 $t$，分別在 $c_k^{\text{with}}$ 與 $c_k^{\text{without}}$ 下做前向，取得下一詞元分佈 $p_k^{\text{with}}(\cdot|x_t)$ 與 $p_k^{\text{without}}(\cdot|x_t)$。
   - 計算 JS 距離 $w_{k,t} = \text{JSD}(p_k^{\text{with}}, p_k^{\text{without}})$，並對同一回應內做歸一化（使 $\sum_t w_{k,t} = 1$）。

5. **重分配優勢並更新策略**
   - 將獎勵 $r_k$ 的群組標準化優勢 $A_k$ 乘上詞元權重 $w_{k,t}$，得到詞元級優勢 $A_{k,t} = A_k \cdot w_{k,t}$。
   - 對所有獎勵求和後，代入 GRPO 風格的策略梯度目標（含 KL 懲罰）進行更新。

6. **與既有加權方法組合**
   - MRTPO 與 SAW 等動態加權方法正交：先以 SAW 決定每個獎勵的回應級權重，再以 MRTPO 分配到詞元。
   - 實作時只需在優勢聚合階段插入詞元重分配步驟。

7. **評估與消融**
   - 在 text-to-SQL、多約束指令遵循、工具呼叫三類任務上比較 MRTPO vs GDPO vs SAW vs OPSD。
   - 監控詞元權重的熵值與集中度，確認獎勵確實被聚焦到相關詞元。

8. **部署前的穩健性檢查**
   - 驗證 replay 計算的數值穩定性（避免 JS 距離為零導致梯度消失）。
   - 確認驗證器資訊注入不會洩漏到測試階段（推理時不附加特權資訊）。

---

### 潛在風險與注意事項

- **驗證器資訊洩漏**：若 replay 時注入的特權資訊在推理時也意外保留，模型會學到「依賴提示作弊」。緩解方式：嚴格分離訓練與推理的 prompt 模板，並對 replay 上下文做單元測試。

- **JS 距離退化**：當驗證器資訊對某詞元的下一詞元分佈影響極小時，JS 距離接近零，導致該詞元獲得的優勢權重過低，可能使訓練訊號過度集中於少數詞元。緩解方式：對詞元權重加下限（如 $\max(w_{k,t}, \epsilon)$）或加入熵正則項。

- **計算成本翻倍**：每次更新需額外兩次前向，長上下文任務成本顯著上升。緩解方式：對長回應採樣性計算 JS 距離，或使用快取機制避免重複計算已快取的注意力鍵值。

- **驗證器品質依賴**：若驗證器本身有偏誤或漏洞，MRTPO 會精準地把錯誤訊號聚焦到錯誤詞元，反而放大問題。緩解方式：先以 GDPO 訓練驗證器品質穩定後再切換至 MRTPO。

- **獎勵組合稀疏性**：當多個獎勵同時為零或同時為滿分時，群組標準化後的優勢值缺乏區分度，詞元重分配的相對意義也降低。緩解方式：設計提示使獎勵組合多樣化，或加入獎勵塑形（reward shaping）。

- **與 KL 懲罰的交互**：詞元級優勢可能放大 KL 懲罰在特定詞元上的影響，導致策略過度保守。緩解方式：監控 per-token KL 散度，必要時調整 KL 係數或對詞元權重做平滑。

---

### 與其他技術的整合建議

- **與 GRPO 系列變體整合**：MRTPO 僅替換「優勢分配」步驟，可直接嵌入 GRPO、DAPO、Dr. GRPO 等同策略演算法，無需修改採樣或 KL 計算流程。

- **與動態獎勵加權方法組合**：SAW、方差感知加權、衝突感知加權等方法決定「每個獎勵的回應級權重」，MRTPO 決定「每個獎勵的詞元級分配」，兩者正交，可串接使用。

- **與過程獎勵模型（PRM）互補**：PRM 提供步驟級評分但需昂貴的人工或模型標註；MRTPO 以零成本自動產生詞元級權重，可作為 PRM 的輕量替代，或在缺乏 PRM 標註的場景作為主要信用分配機制。

- **與同策略自我蒸餾（OPSD）區隔**：OPSD 將整體回應拉向「看見參考答案」的教師分佈；MRTPO 保留獎勵作為訓練目標，僅用 replay 決定優勢落點。兩者可作為不同預算下的選項：MRTPO 適合獎勵訊號可靠、OPSD 適合缺乏可靠驗證器的場景。

- **與推理時工具整合**：在工具呼叫場景中，驗證器資訊（如執行錯誤）可在訓練時注入 replay 上下文；推理時則由真實工具回傳結果驅動，無需修改部署架構。

- **與分散式訓練框架整合**：將 replay 前向封裝為獨立的 forward pass 模組，可與主訓練迴圈並行；建議使用 gradient checkpointing 降低記憶體峰值。

---

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解 GRPO 的群組相對優勢概念（同一提示採樣多個回應、以群組平均值為基準計算優勢），再讀本文第 1 節的「格式正確但語意錯誤」範例，掌握「為什麼均勻分配優勢不合理」這個核心直覺。數學細節可先跳過，專注於「每個驗證器只看回應的一部分」這個觀察。

**給 AI 工程師**：重點關注第 3 節的演算法細節與第 5 節的實驗設定，特別是 replay 上下文的構造方式與 JS 距離的計算成本。建議直接從 GDPO 程式碼出發，將「回應級優勢」改寫為「詞元級優勢」，並以單一獎勵任務（如 text-to-SQL）做小規模驗證，再逐步擴展到多獎勵場景。

**給研究者**：本文的核心貢獻在於「將特權資訊用於信用分配而非蒸餾目標」，這與 OPSD 形成有趣對比。建議延伸思考：(1) JS 距離是否為最佳選擇，或 KL 散度、Wasserstein 距離是否更合適；(2) 詞元權重的理論詮釋（是否對應某種注意力或影響函數）；(3) 在獎勵稀疏或驗證器有噪聲時的統計性質。

**給產品經理**：MRTPO 的價值在於「用更精準的訓練訊號換取更快的收斂與更好的最終表現」，且不需要額外的人工標註或輔助模型。適合用於「多個品質指標需同時優化」的產品場景（如 SQL 助理、工具代理、內容合規生成）。建議與 ML 團隊討論現有管線中是否存在「獎勵均勻擴散導致學習緩慢」的痛點，再評估導入成本（主要為兩倍前向計算）。
