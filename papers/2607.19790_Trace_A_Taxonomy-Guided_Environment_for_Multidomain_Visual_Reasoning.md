# TRACE：一個分類法引導的多領域視覺推理環境

**作者：** Md Tanvirul Alam

## ⚡ TL;DR

視覺語言模型的可驗證獎勵強化學習缺乏同時廣泛、可精確驗證且可複現的訓練資料。
提出TRACE，以分類法將場景文法與任務程式分離，並由共享語義狀態產生影像、提示、答案與驗證。
於六萬四千筆實例進行RLVR，3B與7B在24項基準宏觀平均提升3.51與4.06百分點。

## 摘要翻譯

可驗證獎勵的強化學習（Reinforcement Learning with Verifiable Rewards, RLVR）已顯著提升語言模型推理（Language-Model Reasoning）能力，然而將其擴展至視覺語言模型（Vision-Language Models）仍受限於缺乏同時具備廣泛性、可精確驗證（Exact Verification）且可複現的（Reproducible）訓練資料。本研究提出 TRACE，一個分類法引導環境（Taxonomy-Guided Environment）下的多領域視覺推理（Multidomain Visual Reasoning）環境。TRACE 將任務建構分解為場景文法（Scene Grammar）與可執行任務程式（Executable Task Program），使視覺實現（Visual Realization）與答案計算（Answer Computation）分離。一個共享的語義狀態（Semantic State）決定渲染影像、提示、型別化答案（Typed Answer）、驗證器狀態（Verifier State）以及可重播的實例追蹤（Instance Trace）。該環境涵蓋 1,000 項任務，分布於 277 個場景文法（Scene Grammar）與 11 個視覺領域（Visual Domains）之中，並具備受控的語義與視覺變化。在 64,000 筆 TRACE 實例上執行 RLVR，使 Qwen2.5-VL-3B 與 Qwen2.5-VL-7B 在 24 項外部基準測試（External Benchmarks）上的宏觀平均（Macro-Average）分別提升 3.51 與 4.06 個百分點，顯示廣泛的程序式訓練（Procedural Training）能夠遷移（Transfer）到生成任務的分布之外。專案頁面：https://maveryn.github.io/trace/。

### 核心貢獻（3～5點）
- 提出 TRACE 環境，以分類法引導的方式系統化建構跨 11 個視覺領域、277 個場景文法的 1,000 項視覺推理任務。
- 將任務建構分解為場景文法與可執行任務程式，使視覺實現與答案計算解耦，並透過共享語義狀態統一影像、提示、型別化答案、驗證器狀態與可重播實例追蹤。
- 提供可精確驗證且可複現的訓練資料，支援以可驗證獎勵進行強化學習（RLVR）。
- 在 64,000 筆 TRACE 實例上進行 RLVR 訓練，使 Qwen2.5-VL-3B 與 Qwen2.5-VL-7B 在 24 項外部基準測試的宏觀平均顯著提升，證明程序式訓練可遷移至生成任務分布之外。

### 適合對象
本論文適合視覺語言模型、可驗證獎勵強化學習（RLVR）、視覺推理、程序式訓練與合成資料生成等領域的研究人員與工程師閱讀，尤其對關注如何以大規模可控生成環境提升模型泛化與遷移能力的讀者具有高度參考價值。

## 深度分析

#### 方法論解析

TRACE 的核心設計可視為一套「以程式為中心的分類體系（program-centered taxonomy）」，其將視覺推理任務的建構拆解為三個可獨立設計、卻又透過共享語義狀態（shared semantic state）緊密銜接的元件：**場景文法（scene grammar）**、**可執行任務程式（executable task program）** 與 **獎勵契約（reward contract）**。這種分離式架構讓「視覺實現（visual realization）」與「答案計算（answer computation）」不再糾纏在同一個模板或標註流程中，從而兼顧廣度、可控性與精確驗證（exact verification）。

1. **場景文法（scene grammar）**  
   場景文法定義了一個視覺領域中可能出現的物件、屬性、關係與佈局家族（layout family）。在 TRACE 中，共涵蓋 277 個場景文法，橫跨圖表（charts）、遊戲（games）、幾何（geometry）、圖形（graphs）、圖示（icons）、插圖（illustrations）、頁面（pages）、物理（physics）、謎題（puzzles）、符號（symbolic）與三維場景（3D scenes）等 11 個視覺領域（visual domains）。每個文法不僅決定影像可以長什麼樣子，也決定了其上可以執行哪些推理運算。

2. **可執行任務程式（executable task program）**  
   任務程式指定了「給定某個語義狀態後，應該計算什麼、輸出什麼型別的答案」。它與場景文法分離，因此同一個場景文法可以對應多種任務，而同一種任務邏輯也可以跨視覺領域複用。透過這種程式化定義，TRACE 將 1,000 個任務組織成穩定的取樣單位（sampling units），每個任務都有明確的推理邊界（reasoning boundaries）。

3. **有界查詢變化（bounded query variation）**  
   為了避免「每換一個問題參數就要新增一個任務」的膨脹，TRACE 引入有界查詢變化：在不改變任務身份（task identity）的前提下，改變有意義的任務參數，例如極值方向（extremum direction）。這讓單一任務能產生多樣實例，同時保持語義與視覺變化的可控性。

4. **共享語義狀態（shared semantic state）與 generator–renderer–verifier 流程**  
   每個實例都從一個共享語義狀態出發，該狀態同時決定了：
   - 渲染後的影像（rendered image）
   - 給模型的提示（prompt）
   - 型別化答案（typed answer）
   - 驗證器狀態（verifier state）
   - 可重播的實例追蹤（replayable instance trace）

   這意味著監督訊號並非來自人工或模型的事後標註，而是直接來自任務程式的執行結果。因此獎勵是精確獎勵（exact rewards），可完全客觀驗證，並且具備可複現性（reproducible）。整個流程可概括為：generator 根據場景文法與任務程式產生語義狀態 → renderer 將其視覺實現為影像 → verifier 根據 verifier state 檢查答案正確性。

5. **與強化學習的銜接**  
   TRACE 的設計天然適合 **可驗證獎勵的強化學習（Reinforcement Learning with Verifiable Rewards, RLVR）**：模型輸出答案後，環境可立即回傳 0/1 或更細緻的規則型獎勵，無需昂貴的人工判斷。這讓訓練分布可以無限擴充，同時維持答案驗證的客觀性。

#### 實驗數據解讀

論文以 **Qwen2.5-VL-3B** 與 **Qwen2.5-VL-7B** 兩個視覺語言模型（vision-language models）進行 RLVR 訓練，訓練資料為從 TRACE 產生的 **64,000 筆實例**，並在 **24 個外部基準測試（external benchmarks）** 上評估遷移（transfer）表現。主要結果如下：

- **Qwen2.5-VL-3B**：24 項基準的宏觀平均（macro-average）提升 **3.51 個百分點**，其中 21/24 項基準呈現正向改變。
- **Qwen2.5-VL-7B**：宏觀平均提升 **4.06 個百分點**，且 **24/24 項基準全部正向**。

這幾個數字值得從多個角度解讀：

1. **廣度遷移的證據**  
   訓練資料完全來自 TRACE 的程序式生成（procedural training），但測試卻是在外部、真實或人工建構的基準上進行。宏觀平均提升 3–4 點，顯示程序式視覺推理訓練確實能遷移到生成任務分布（generated task distributions）之外，這回應了論文一開始提出的核心問題：如何讓視覺 RLVR 資料同時具備廣度、精確驗證與可複現性。

2. **模型規模與一致性**  
   7B 模型不僅絕對提升更大（4.06 vs. 3.51），而且所有 24 項基準都進步；3B 模型雖有 21/24 正向，但仍有 3 項未提升。這暗示：當程序式訓練資料的領域覆蓋夠廣時，較大模型更能穩定吸收並遷移這些推理模式；小模型可能因容量限制，在某些外部任務上出現負遷移或飽和。

3. **宏觀平均的意義與限制**  
   宏觀平均將所有基準視為同等重要，能反映整體推理能力的廣泛提升，但可能掩蓋個別基準的差異。例如某些視覺數學或空間推理基準可能提升較多，而某些需要真實世界知識的基準提升較少。論文未在提供的摘要與前言中細分各基準數據，因此進一步分析需要參閱完整實驗表格。

4. **64K 實例的訓練效率**  
   相較於其他多模態 RL 研究動輒數十萬甚至上百萬筆資料（如 Veroscale 的 600K），TRACE 僅用 64K 實例就取得顯著宏觀提升。這可能歸功於：
   - 任務定義的穩定性與多樣性（1,000 任務 × 有界查詢變化）
   - 精確獎勵減少了雜訊，讓模型更有效學習
   - 語義狀態與視覺實現分離，使同一推理邏輯能以多種視覺形式出現，提升樣本效率

5. **尚待釐清的問題**  
   - 外部基準的組成為何？是否與 TRACE 的 11 個視覺領域有對應關係？
   - 提升主要來自「看過類似任務類型」還是「學到通用推理策略」？
   - 若將 TRACE 與真實影像資料混合，效果是否會進一步提升？

#### 與現有研究的比較

TRACE 的定位可從四條相關研究脈絡來理解：

1. **受控視覺任務生成（Controlled visual task generation）**  
   CLEVR 與 GQA 利用場景圖（scene graphs）與功能程式進行組合式視覺問答；TaskMeAnything 進一步將其擴展為可擴展的隨選引擎。TRACE 繼承了這些工作的結構化精神，但將「可執行任務定義」提升為穩定的取樣、驗證與 RL 訓練單位，而不僅是問題生成單位。

2. **可執行 generator–verifier 環境**  
   Reasoning Gym 與 Enigma 在文字或符號領域展示了 generator–verifier 架構對 RLVR 的價值：可無限生成實例、精確驗證、控制難度。TRACE 將此模式擴展到**渲染後的視覺狀態（rendered visual states）**，並明確分離場景文法與任務程式，這是先前系統較少觸及的。

3. **多模態 RL 資料混合（Multimodal RL data mixtures）**  
   Visual-RFT、Vision-R1、LMM-R1、MM-Eureka、R1-Onevision、Reason-RFT、VLM-R1 與 Veroscale 等研究透過混合大量現有資料集並設計任務特定獎勵（task-specific rewards）來進行多模態 RL。這類方法的優勢在於資料來源豐富，但缺點是繼承了來源集合（source collections）的異質任務粒度、取樣單位與推理邊界。TRACE 則反其道而行：在實例生成前就定義好任務程式與獎勵契約，從而獲得更一致的訓練訊號。

4. **合成且可驗證的視覺 RL 資料**  
   Jigsaw-R1 等研究使用單一或少量緊密相關的視覺任務（如拼圖）作為 RL 測試平台。這類系統雖然可控，但領域狹窄。TRACE 的關鍵改進在於將廣度（1,000 任務、277 場景文法、11 視覺領域）、可控性與精確驗證整合到同一個連貫的任務組織中。

**主要優勢總結：**
- 廣度與結構化並存：11 個視覺領域、1,000 任務，卻仍維持程式化定義。
- 精確且可複現的獎勵：答案直接來自任務程式執行，非事後標註。
- 視覺與語義分離：同一語義狀態可渲染為不同視覺風格，提升泛化。
- 穩定的任務身份：有界查詢變化讓單一任務產生多樣實例，而不造成任務膨脹。

**潛在限制：**
- 目前仍屬合成資料環境，雖然視覺領域多元，但與真實世界影像的分布差距仍存在。
- 場景文法與任務程式需要大量人工設計，擴展到更多開放領域的成本不低。
- 論文摘要與前言未詳細說明 24 個外部基準的選擇標準與個別表現，難以判斷遷移的具體機制。
- 對於需要常識、語用或文化背景的視覺推理，程序式生成可能難以覆蓋。

#### 可重現性評估

可重現性（reproducibility）是 TRACE 設計中反覆強調的特點，因為每個實例都來自可執行的場景文法與任務程式，並留下可重播的實例追蹤（instance trace）。理論上，只要擁有相同的程式與隨機種子，就能完全重現相同的影像、提示與答案。

然而，就**實際開放資源**而言，目前提供的資訊僅限於：

- **專案頁面（project page）**：https://maveryn.github.io/trace/

論文摘要與前言並未明確說明是否會釋出：
- 原始碼（source code）
- 場景文法與任務程式的完整集合
- 64,000 筆訓練實例或其生成腳本
- 微調後的模型權重（model weights）
- 24 個外部基準的詳細評估設定與結果表格

因此，從現有資訊評估，TRACE 的**方法論可重現性很高**（因為實例由程式決定），但**實務可重現性仍取決於作者後續是否釋出完整程式碼與資料**。建議讀者透過專案頁面追蹤後續釋出內容，並在復現時特別注意：

1. 渲染引擎版本與相依套件是否一致。
2. 任務程式與 verifier 的規則細節是否完整文件化。
3. RLVR 訓練的超參數、獎勵函數與取樣策略是否公開。
4. 外部基準的預處理流程與評估指標是否標準化。

若作者能釋出完整的 generator–renderer–verifier 程式碼與預訓練模型，TRACE 將成為視覺 RLVR 領域極具價值的開放基礎設施。

#### 未來研究方向

TRACE 的架構為多個後續研究方向開啟了可能性：

1. **自動化分類體系擴展**  
   目前 277 個場景文法與 1,000 個任務仍由人工設計。未來可探索以大型語言模型（large language models）自動生成或擴展場景文法與任務程式，並透過 verifier 自動檢驗其一致性，進一步降低擴展成本。

2. **結合真實影像的程序式訓練**  
   TRACE 目前以合成影像為主。未來可研究如何將真實影像的場景圖（scene graphs）或視覺語言模型產生的結構化描述轉換為 TRACE 的語義狀態，從而縮小合成與真實分布的差距。

3. **難度與課程控制**  
   有界查詢變化已提供基礎的難度控制，但未來可進一步設計自適應課程（adaptive curriculum），根據模型在 verifier 上的表現動態調整任務難度與領域混合比例。

4. **更細緻的獎勵設計**  
   目前以精確驗證為主，未來可探索部分獎勵（partial rewards）、過程獎勵（process rewards）或基於 instance trace 的解釋性獎勵，以支援更複雜的多步推理。

5. **跨模態與跨領域遷移分析**  
   深入分析 11 個視覺領域中，哪些領域的訓練對哪些外部基準最有幫助，從而建立領域間的遷移矩陣，並指導更高效的資料混合策略。

6. **開放式視覺推理**  
   目前 TRACE 的任務多為封閉型答案（typed answer）。未來可擴展到開放式生成任務，例如要求模型產生解釋、繪製輔助圖形或撰寫推理過程，並設計相應的 verifier。

7. **與其他 RL 演算法的整合**  
   除了 RLVR，未來可測試 TRACE 在 PPO、DPO、GRPO 等不同強化學習框架下的表現，並比較其樣本效率與最終性能。

8. **視覺穩健性與對抗測試**  
   由於語義狀態與視覺實現分離，TRACE 特別適合進行系統性的視覺擾動測試，例如改變顏色、視角、雜訊或渲染風格，以評估模型的視覺穩健性。

9. **多智能體與互動式視覺推理**  
   將 TRACE 擴展為互動式環境，讓模型可以主動提問、要求放大特定區域或進行多輪觀察，從而研究主動視覺推理（active visual reasoning）。

10. **建立社群共享的視覺推理基礎設施**  
    若 TRACE 能成為開放平台，讓研究者貢獻新的場景文法、任務程式與 verifier，將有助於建立類似 Reasoning Gym 的視覺版本，推動整個領域的系統化發展。

## 論文問答

**Q1：將可驗證獎勵的強化學習（RLVR）擴展到視覺語言模型時，核心瓶頸是什麼？**

A：核心瓶頸在於缺乏同時具備「廣泛性」、「精確可驗證性」與「可複現性」的視覺訓練資料。視覺語言模型的問題必須根植於影像內容，答案必須能被客觀且廉價地驗證，同時任務變化不能侷限於少數固定模板。現有資料往往只能滿足其中一兩項要求，導致 RLVR 在視覺領域難以像數學或程式領域那樣穩定提升推理能力。

**Q2：為什麼單純混合大量現成資料集的策略無法解決上述問題？**

A：大型訓練混合資料集雖然能擴大覆蓋範圍，但會繼承來源集合中異質的任務粒度、取樣單位與推理邊界。不同資料集的題型難度、答案格式與評量標準不一致，使得獎勵設計與模型學習變得困難。因此，這種策略難以形成一個任務單位穩定、獎勵精確且可系統性分析的訓練環境。

**Q3：現有的程序式生成系統又有哪些不足，促使 TRACE 的誕生？**

A：現有程序式系統雖然能提供精確監督與可控生成，但大多只聚焦於單一場景文法或少數緊密相關的目標，例如拼圖、視覺邏輯謎題或抽象感知任務。它們難以同時兼顧廣度、可控性與精確驗證，也較少將任務程式作為取樣、驗證與強化學習的穩定單位。TRACE 正是為了彌補這個缺口，提出一個以分類法為基礎、橫跨多視覺領域的統一環境。

**Q4：TRACE 的核心方法架構包含哪些主要元件？**

A：TRACE 將任務建構拆解為場景文法、可執行任務程式與獎勵契約三大元件。場景文法定義可渲染的物件、關係與佈局家族；可執行任務程式指定答案的計算邏輯與型別；獎勵契約則定義答案的精確驗證方式。此外，「有界查詢變化」能在不改變任務本身的前提下，改變有意義的任務參數，例如極值方向，從而產生受控的實例變化。

**Q5：TRACE 相較於 CLEVR 或 TaskMeAnything 等前作，關鍵創新在哪裡？**

A：TRACE 延續了 CLEVR 與 TaskMeAnything 的結構化場景表示與可執行問題程式傳統，但進一步把「可執行任務定義」提升為生成、取樣、驗證與 RL 訓練的穩定單位。它不僅用程式產生實例，更讓同一語義狀態同時決定影像、提示、型別化答案與驗證器狀態，使監督直接來自任務計算而非事後標註。這種設計讓 TRACE 能涵蓋 1,000 項任務、277 個場景文法與 11 個視覺領域，並保持任務一致性與精確獎勵。

**Q6：為什麼 TRACE 要將視覺實現與答案計算分離？**

A：將場景文法與可執行任務程式分離，可以讓視覺實現專注於把語義狀態渲染成影像，而答案計算則獨立於渲染過程執行。這種分離使得系統能在保持任務身份穩定的同時，對語義內容與視覺風格進行受控變化，例如改變顏色、視角或物件排列。同時，由於答案直接來自共享語義狀態的計算，訓練信號更為精確，也更容易追蹤與重播每個實例的生成軌跡。

**Q7：論文進行了哪些實驗來驗證 TRACE 的效用？**

A：作者使用 TRACE 生成 64,000 個訓練實例，對 Qwen2.5-VL-3B 與 Qwen2.5-VL-7B 進行 RLVR 訓練，並在 24 個外部視覺推理基準測試上進行評估。這些外部基準涵蓋視覺數學、計數、空間推理、圖表理解等多種任務，並非 TRACE 內部生成的相同分布。實驗目的在於檢驗程序式視覺任務訓練是否能遷移到生成任務分布之外的真實評測。

**Q8：實驗的主要結果是什麼？**

A：在 24 個外部基準的宏觀平均上，Qwen2.5-VL-3B 提升了 3.51 個百分點，Qwen2.5-VL-7B 提升了 4.06 個百分點。在 3B 模型上，24 個基準中有 21 個出現正向平均變化；在 7B 模型上，全部 24 個基準都呈現正向進步。這些結果顯示，廣泛的程序式訓練確實能促進模型在分布外任務上的遷移表現。

**Q9：從實驗結果可以得出什麼樣的分析或啟示？**

A：結果表明，廣泛且可驗證的程序式訓練能夠支撐跨領域的遷移，而不僅僅是記住生成任務的模板。由於 TRACE 的獎勵來自語義狀態的直接計算，模型學到的是與視覺內容緊密連結的推理策略，而非僅依賴表面統計規律。此外，有界查詢變化與可控視覺變化的設計，讓訓練資料在擴充多樣性的同時，仍維持穩定的任務身份與精確獎勵，這對 RLVR 的穩定訓練至關重要。

**Q10：TRACE 在實務上可以應用於哪些場景？**

A：TRACE 可用於大規模視覺語言模型的推理能力訓練與診斷，特別適合需要精確答案的領域，例如圖表分析、幾何證明、物理模擬、棋盤遊戲與文件版面理解。它也能作為自動化基準測試平台，依據分類法有系統地產生難度遞增的測試題，支援課程學習與模型弱點分析。此外，由於每個實例都附帶可重播的實例追蹤與驗證器狀態，TRACE 也適合做為可解釋性研究與錯誤分析的工具。

**Q11：若要将 TRACE 部署到實際產品或訓練管線中，需要考慮哪些因素？**

A：首先必須整合渲染器、任務程式執行環境與驗證器，確保影像、提示與答案之間的一致性。其次，分類法與場景文法需要持續維護與擴充，以涵蓋更多真實世界領域並避免分布過度狹隘。最後，獎勵契約的設計、取樣策略與難度調度都會影響訓練效率，因此需要監控模型在不同任務與視覺領域上的學習動態，並適時調整資料混合比例。

**Q12：TRACE 對視覺語言模型與多模態強化學習領域可能帶來什麼影響？**

A：TRACE 將廣度、精確驗證與可複現性整合到單一連貫的環境中，為多模態 RLVR 提供了一個可擴展且可分析的訓練範式。它把研究焦點從「收集與混合現有資料集」轉向「以程式為中心的任務分類法」，使任務設計、取樣與驗證變得更加系統化。這種方法不僅能提升模型在標準基準上的表現，也為未來研究跨領域遷移、推理組合性與資料效率提供了堅實的實驗平台。

**Q13：論文可能承認哪些限制？**

A：TRACE 目前主要產生合成或渲染影像，與真實世界照片在視覺複雜度與雜訊分布上仍有差距。此外，1,000 項任務與 11 個視覺領域雖然廣泛，但仍無法涵蓋所有真實視覺推理情境，例如需要大量常識或開放式語言生成的任務。分類法與場景文法的人工設計也需要相當成本，如何自動擴充並保持語義與驗證品質，仍是未來挑戰。

**Q14：在哪些情況下，使用 TRACE 訓練的模型可能會失敗或表現不佳？**

A：當輸入影像來自 TRACE 未涵蓋的視覺領域，或包含真實世界常見的雜訊、遮擋與非理想光照時，模型可能難以正確推理。對於需要外部常識、文化背景知識或開放式描述答案的任務，精確驗證的設計也較難直接套用。此外，若測試題目的語言表述與訓練分布差異過大，或答案型別超出獎勵契約的定義範圍，模型同樣可能出現遷移失敗。

**Q15：未來可以朝哪些方向延伸 TRACE？**

A：未來可以擴充分類法以納入更多真實影像領域，例如結合真實影像的場景圖或三維重建結果，縮小合成與真實資料之間的差距。也可以研究自適應取樣與難度課程，讓模型在訓練過程中自動聚焦於高價值或高難度任務。此外，將生成式模型與 TRACE 的驗證機制結合，探索開放式視覺推理的精確獎勵設計，以及更大規模下的擴展法則，都是值得深入的方向。

## 實務應用指南

### 適用場景

1. **多領域視覺問答（Multidomain VQA）的訓練資料擴充**  
   當現實資料標註成本過高或難以取得時，可用 TRACE 的程序式生成能力，針對圖表、幾何、圖形、物理示意圖、遊戲畫面等 11 個視覺領域，快速產生大量可驗證的訓練實例，補足視覺語言模型在特定推理類型上的資料缺口。

2. **可驗證獎勵強化學習（RLVR）的視覺微調**  
   適合需要將 RLVR 從文字推理擴展到視覺語言模型的團隊。TRACE 提供共享語義狀態、型別化答案與驗證器狀態，讓獎勵函數能精確判定模型輸出是否正確，避免人工標註或模型評分的不確定性。

3. **視覺推理能力的可控制診斷與評估**  
   研究或產品團隊可利用場景文法與有界查詢變化，系統性地調整物件屬性、關係、佈局或問題參數，以定位模型在組合推理、空間推理、數量推理或圖表解讀上的弱點。

4. **教育與測評內容的動態生成**  
   可應用於自動出題系統，例如根據幾何單元即時生成不同難度的圖形題、根據物理情境生成示意圖與計算題，並透過可執行任務程式自動產生答案與解析軌跡。

5. **多模態模型產品上線前的安全與穩定性測試**  
   在部署視覺語言模型前，可用 TRACE 產生涵蓋多領域、具精確答案的測試集，驗證模型在結構化視覺輸入下的輸出一致性與幻覺風險。

### 實作前置條件

- **資料條件**  
  不需要大量人工標註影像，但需要具備領域知識的人員撰寫或擴充場景文法與可執行任務程式。若目標領域不在現有 11 個視覺領域內，需額外設計對應的渲染器與獎勵契約。

- **運算條件**  
  參考論文規模，進行 RLVR 微調至少需要能執行 Qwen2.5-VL-3B 或 7B 等級模型的 GPU 叢集；生成實例本身可平行化，但需要穩定的渲染與語義狀態管理後端。若僅用於評估，則運算需求主要來自渲染與模型推論。

- **技能條件**  
  團隊需熟悉視覺語言模型微調流程、強化學習基礎（如 PPO、GRPO 或類似 RLVR 方法），以及具備程式生成與規則式驗證的開發能力。設計場景文法與任務程式時，需要結合領域專家與工程人員共同協作。

---

### 實作步驟建議

1. **定義目標推理能力與視覺領域**  
   先釐清產品需要強化的能力，例如圖表判讀、幾何證明、空間關係或物理量計算，並對應到 TRACE 的場景文法與視覺領域。

2. **選擇或擴充場景文法與任務程式**  
   從現有 277 個場景文法中挑選符合需求的子集，或新增領域專屬文法。同步設計可執行任務程式，明確答案型別與計算邏輯。

3. **建立共享語義狀態與渲染管線**  
   確保每個實例的語義狀態能同時決定影像、提示、型別化答案與驗證器狀態，並讓渲染結果在視覺上具備足夠變化但保持任務一致性。

4. **設計獎勵契約與有界查詢變化**  
   為每個任務定義精確驗證規則，並利用有界查詢變化產生同一任務下的多樣實例，避免過度依賴固定模板。

5. **生成訓練與評估實例**  
   依目標規模產生實例，例如論文使用的 64,000 筆資料，並保留部分留出實例用於同分布驗證。

6. **執行 RLVR 微調**  
   使用可驗證獎勵對視覺語言模型進行強化學習微調，監控獎勵訊號穩定性與模型輸出格式收斂情形。

7. **外部基準測試與錯誤分析**  
   在 24 個或自選外部基準測試上評估宏觀平均表現，並針對表現下滑的領域回頭調整場景文法、任務程式或取樣比例。

8. **部署與持續迭代**  
   將模型整合至產品流程，並定期以 TRACE 產生新任務進行再訓練或回歸測試，維持模型對新視覺推理模式的適應力。

---

### 潛在風險與注意事項

- **渲染與真實世界分布落差**  
  TRACE 的影像為程序生成，可能與真實照片、手繪圖表或掃描文件風格不同。建議在產品場景中搭配真實資料進行領域適應，或設計風格多樣的渲染器。

- **獎勵駭入（Reward Hacking）**  
  模型可能學會利用驗證規則的漏洞取得高分，例如輸出符合型別但無意義的答案。應定期檢視驗證器狀態與實例追蹤，並加入語義合理性檢查。

- **任務設計偏差導致遷移有限**  
  若場景文法過於狹隘或任務程式覆蓋不足，RLVR 可能僅提升同分布表現。建議參考論文做法，維持跨 11 個視覺領域的廣泛覆蓋，並監控外部基準的宏觀平均變化。

- **渲染與驗證管線的維護成本**  
  隨著任務數量增加，場景文法、渲染器與獎勵契約的維護會變得複雜。應建立模組化架構與自動化測試，確保新增任務不會破壞既有驗證邏輯。

- **模型過度擬合程序生成風格**  
  長期使用 TRACE 資料訓練可能使模型對合成影像過度敏感。建議保留一定比例的真實世界資料，並進行週期性的風格擾動與對抗測試。

---

### 與其他技術的整合建議

- **與現有資料管線整合**  
  可將 TRACE 視為資料合成層，與真實資料集、開放資料集（如 GQA、CLEVR）混合使用。透過控制取樣單位與比例，彌補真實資料在稀有推理類型上的不足。

- **與多模態 RL 框架整合**  
  TRACE 的驗證器狀態可直接作為 RLVR 框架的獎勵訊號來源，無需額外訓練獎勵模型。可與 Ver-RFT、MM-Eureka、LMM-R1 等方法的訓練流程結合。

- **與模型評估平台整合**  
  將 TRACE 產生的實例與留出實例納入持續整合（CI）流程，作為視覺語言模型每次更新後的回歸測試集，並與外部基準測試結果一併追蹤。

- **與檢索增強生成（RAG）或工具使用整合**  
  對於需要外部知識的視覺推理任務，可讓模型先利用 TRACE 訓練出的結構化推理能力，再呼叫計算工具、知識庫或程式執行器完成最終答案。

- **與資料選擇與課程學習方法整合**  
  可結合 SoTA with Less、RAP 或 MoDoMoDo 等資料選擇策略，從 TRACE 的大量生成實例中篩選高價值樣本，或依難度安排課程學習順序。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先聚焦於論文的圖一與第一節，理解 TRACE 如何將「產生影像」與「計算答案」分開，以及為何「可驗證獎勵」對訓練視覺語言模型很重要。可先將 TRACE 想像成一座能自動出題、自動改考的虛擬考場，再逐步認識場景文法與任務程式的角色。

- **AI 工程師**  
  重點閱讀方法設計與實驗設定，特別是共享語義狀態、獎勵契約與有界查詢變化的實作細節。建議評估如何將 TRACE 的生成管線嵌入現有的 RLVR 訓練流程，並注意渲染器、驗證器與模型輸出格式之間的介面設計。

- **研究人員**  
  建議深入分析 TRACE 的任務分類法與 1,000 個任務的組織方式，思考其對「廣度、可控性、精確驗證」三者權衡的設計選擇。可進一步探討程序式訓練的遷移機制，或將 TRACE 作為研究視覺推理瓶頸與獎勵設計的實驗平台。

- **產品經理**  
  建議從適用場景與實驗結果開始，理解 TRACE 能為產品帶來的價值：以可控、可擴展的方式產生訓練與測試資料，並提升視覺語言模型在多項外部基準上的宏觀平均表現。後續可與工程團隊討論領域擴充、渲染風格與真實資料混合的策略，以規劃最小可行產品與上線時程。
