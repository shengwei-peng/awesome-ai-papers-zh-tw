## 摘要翻譯

權重空間模型合併（Weight-Space Model Merging）通常被形式化為對檢查點（checkpoint）進行的代數運算（algebraic operation），然而在大型語言模型（Large Language Model, LLM）規模下，瓶頸資源往往是必須讀取的專家權重（expert weights）集合。我們提出 MergePipe，一個預算感知執行層（budget-aware execution layer），將大型語言模型合併框架為專家存取集合問題（expert access-set problem）：給定一個合併運算子（merge operator），以及共享權重座標系統（shared weight coordinate system）中的一個檢查點家族（checkpoint family），在明確的 I/O 預算（I/O budget）下選擇應存取哪些專家差異區塊（expert delta blocks）。MergePipe 為參數區塊（parameter blocks）建立索引、建構確定性存取計畫（deterministic access plan），並透過可重播清單（replayable manifest）執行其所導出的預算合併。此計畫依構造即為預算健全的（budget-sound），且在完整預算下可恢復全讀取合併（full-read merge）；對於固定係數加法運算子（fixed-coefficient additive operator），遺漏更新誤差（omitted-update error）受被省略差異（omitted delta）的範數（norm）所界定。在 Qwen 與 Llama 的合併工作負載上，MergePipe 將專家權重讀取（Expert Reads）I/O 降低最高達一個數量級，並實現最高達 11 倍的加速比（speedup）。具代表性的預算掃描（budget sweep）顯示，與全讀取合併相比，參數偏差（parameter deviation）為 O(10^{-3})，且在下游基準測試（downstream benchmark）上未見單調劣化。

### 核心貢獻（3～5點）
- 將大型語言模型合併框架為專家存取集合問題，提出預算感知執行層 MergePipe，在明確 I/O 預算下選擇性存取專家差異區塊，突破傳統全讀取合併的 I/O 瓶頸。
- 提供理論保證：存取計畫依構造即為預算健全，於完整預算可恢復全讀取合併；針對固定係數加法運算子，證明遺漏更新誤差受被省略差異的範數所界定。
- 在 Qwen 與 Llama 合併工作負載上驗證，降低專家權重讀取 I/O 達一個數量級，並實現最高 11 倍加速比。
- 透過預算掃描實證，參數偏差僅 O(10^{-3})，且下游基準測試效能未出現單調劣化，確認預算合併的實用性。

### 適合對象
從事大型語言模型後訓練整合、模型合併與壓縮、以及分散式系統 I/O 最佳化研究的學者與工程師；特別適合需要在儲存頻寬受限環境中進行可擴展權重空間模型合併，並重視理論保證與可重現執行之讀者。

## 深度分析

#### 方法論解析

本文的核心方法論在於將 weight-space model merging（權重空間模型合併）從傳統的代數運算（algebraic operation）重新定義為 expert access-set problem（專家存取集合問題）。在 LLM（大型語言模型）規模下，瓶頸並非計算本身，而是 expert reads（專家權重讀取）所產生的 I/O（輸入／輸出）。作者提出的 MergePipe 是一個 budget-aware execution layer（預算感知執行層），其關鍵抽象是引入 access mask（存取遮罩） A∈{0,1}^{|U|}，其中 A_{i,t,b}=1 表示在合併過程中必須讀取第 i 個 expert（專家）在 tensor（張量） t 的第 b 個 parameter block（參數區塊）。整體的 expert-read cost（專家讀取成本）定義為 C_expert(A)=∑ A_{i,t,b} c_{i,t,b}，並受到明確的 I/O budget（I/O 預算） B 所約束。

MergePipe 的執行流程分為規劃與執行兩階段。在規劃階段，系統會針對 checkpoint family（檢查點家族）中的每一個 expert delta block（專家差異區塊）計算 access score（存取分數） s(i,t,b)，此分數可來自 norm（範數）、sketch（草圖）、coverage（覆蓋率）或後設資料。接著，planner（規劃器）透過 greedy heuristic（貪婪啟發式演算法）或 score-per-byte heuristic（每位元組分數啟發式演算法）產生一個 deterministic access plan（確定性存取計畫），決定在預算內應讀取哪些區塊。在執行階段，executor（執行器）僅根據該計畫讀取被選中的區塊，並透過 replayable manifest（可重播清單）記錄整個執行軌跡，確保實驗的可重現性。

方法論上最關鍵的設計是 non-anticipatory operator（非預期性運算子） Ψ_op。這個條件要求：只要兩組 delta tuples（差異元組）在被選取項目上的數值相同，即使被省略的項目不同，運算子也必須輸出相同的 budgeted merge（預算化合併）結果。這使得 omitted entries（被省略的項目）僅由 mask 本身表徵，而無需實際觸發 storage read（儲存讀取），從根本上將「讀取哪些權重」與「如何組合權重」解耦。在此架構下，plan 是 budget-sound（預算健全的）：只要規劃時滿足 C_expert(A)≤B，實際執行成本 Crun_expert(A) 必然也不超過 B。同時，當預算充足、A=1 時，系統自動恢復為 full-read merge（全讀取合併），滿足 full-budget consistency（全預算一致性）。

理論貢獻方面，Corollary 1（推論一）指出：若 full-read merging 的總成本隨專家數量 K 線性增長為 KC̄，則在固定絕對預算 B 下，expert-read fraction（專家讀取比例）會以 O(1/K) 衰減。這意味著當專家池（expert pool）擴大時，MergePipe 的相對效益會愈發顯著，將原本 I/O-bound（I/O 受限）的合併流程轉化為可擴展的常數預算流程。Proposition 2（命題二）則針對 fixed-coefficient additive operator（固定係數加法運算子）提供 omitted-update error（遺漏更新誤差）的 L2 bound：∥M_full−M_A∥_2 ≤ ∑ q_{t,b}(A)，其中 q_{t,b}(A) 與被省略差異的範數成正比。這個 bound 直接為 norm-based 或 sketch-based 的區塊選擇策略提供了理論正當性——最大化保留的 utility（效用）等同於最小化誤差上界。值得注意的是，此 bound 並不適用於 TIES、DARE 等會因 access mask 改變係數、進行 sparsification（稀疏化）或 sign selection（符號選擇）的運算子；對於這類運算子，MergePipe 仍提供相同的 budgeted execution（預算化執行）抽象，但 fidelity（保真度）必須透過實證評估。

#### 實驗數據解讀

實驗部分以 Qwen（Qwen）與 Llama（Llama）兩大開源模型家族為對象，設計了多組 merging workloads（合併工作負載）。數據呈現三個層次的驗證：系統效能、參數保真度，以及下游任務表現。

在系統層面，MergePipe 可將 expert-read I/O（專家讀取 I/O）降低 up to an order of magnitude（高達一個數量級），並取得 up to 11× speedups（高達 11 倍加速比）。這兩個數字必須放在一起解讀：高達 11 倍的加速比並非來自更快的矩陣運算，而是來自大幅減少的權重讀取量。這直接驗證了作者的核心論點——在 LLM 規模下，model merging 是 I/O-bound 而非 compute-bound（計算受限）。當 K 增加時，naive merge 的讀取成本線性增長，而 MergePipe 透過預算控制將其壓制在固定上限，使得 wall-clock time（實際執行時間）的改善與理論上的 O(1/K) 專家讀取比例相呼應。

在參數保真度方面，representative budget sweeps（代表性預算掃描）顯示，budgeted merge 與 full-read merge 之間的 parameter deviation（參數偏差）僅有 O(10^{−3}) 數量級。對於動輒數十億參數的 LLM 而言，10^{−3} 量級的逐元素偏差極小，暗示 greedy heuristic 所捨棄的差異區塊多屬於「低能量」更新，對整體參數向量的影響有限。這與 Proposition 2 的 omitted delta bound（被省略差異界）一致：若規劃器優先保留高範數差異，則遺漏的主要是範數較小的雜訊或冗餘更新。

最具實務意義的發現是 downstream benchmark（下游基準測試）上「no monotonic degradation（無單調劣化）」。這表示降低預算並不會系統性地損害模型在下游任務的表現；合併品質與預算之間並非簡單的單調遞減關係，而是存在一個可利用的 speed–fidelity frontier（速度–保真度權衡前沿）。對實務部署者而言，這意味著可以在不進行完整訓練或 full-read merge 的情況下，透過調整 I/O budget 快速探索合併配置，並有高度信心維持下游效能。

#### 與現有研究的比較

既有研究如 AVG（Wortsman et al., 2022）、TIES（Yadav et al., 2023）、DARE（Yu et al., 2024）等主要聚焦於 merge operator（合併運算子）的設計：探討 task vectors（任務向量）、signs（符號）、sparsity masks（稀疏遮罩）或 low-rank updates（低秩更新）應如何結合。這些工作回答的是「如何合併」（how to combine）。MergePipe 的創新則在於提出「該讀取哪些專家參數」（which expert parameters must be read）這一執行層次的問題，將 merging 抽象為 budgeted resource allocation（預算化資源分配）。

在定位上，MergePipe 與 symmetry alignment（對稱對齊）或 permutation alignment（置換對齊）方法呈現互補（complementary）關係。後者解決的是不同專家是否處於 shared weight coordinate system（共享權重座標系統）的問題；一旦權重透過對齊方法被映射到同一座標圖表（coordinate chart），MergePipe 便負責在該座標系統內決定哪些 expert deltas（專家差異）值得在有限預算下被讀取。因此，MergePipe 假設 homologous setting（同源設定）——即專家來自 shared base（共享基底）或已完成對齊——這既是其方法論前提，也是與對齊文獻的自然介接點。

然而，本文也明確承認其限制。首先，Proposition 2 的 additive omission bound（加法遺漏界）僅適用於 fixed-coefficient additive operator；對於 TIES、DARE 等 selected-only renormalization（僅選取重新正規化）或隨機丟棄機制，access mask 會反過來影響係數與稀疏模式，理論誤差界不再成立，必須依賴實證評估。其次，目前的規劃器採用 greedy 或 score-per-byte 啟發式，而非 exact knapsack optimization（精確背包問題最佳化），這意味著在極端預算壓力下，存取集合可能仍有次優性。最後，MergePipe 不解決座標對齊問題；若專家來自不同基底或經過差異極大的微調流程，單純的區塊選擇無法彌補座標系統不一致造成的品質損失。

#### 可重現性評估

可重現性方面，作者明確釋出了原始碼（code：wyy-code/mergepipe），這為社群驗證提供了基礎。更重要的是，MergePipe 的方法論內建了可重現性機制：deterministic access plan（確定性存取計畫）與 replayable manifest（可重播清單）確保給定相同的合併運算子、檢查點家族與預算 B，任何執行器都能重現完全一致的區塊讀取軌跡與最終輸出。這種「manifest 驅動」的設計在實驗追蹤與生產稽核上都極具價值。

實驗採用的 Qwen 與 Llama 均為公開權重的模型家族，降低了外部復現的門檻。不過，從提供的摘錄中，部分實作細節如區塊大小（block size）的劃分策略、offline catalog construction（離線目錄建構）的具體開銷、以及下游基準測試的確切資料集與評量指標，並未在片段中完整揭露。儘管如此，由於核心演算法與程式碼已開源，這些細節可透過原始碼補足。整體而言，本文在理論推導（命題與推論的完整證明置於附錄）與系統實作之間取得了良好平衡，具備高度的可重現性潛力。

#### 未來研究方向

從方法論延伸，未來研究可朝以下方向推進：

第一，**理論界限的擴展**。目前僅對 fixed-coefficient additive operator 有嚴格的 omitted-update error bound。為 TIES、DARE 等非加法或係數依賴於 mask 的運算子建立類似的理論保證，將大幅提升 budgeted merging 的嚴謹性。此外，以 exact knapsack optimization（精確背包問題最佳化）取代 greedy heuristic，或發展具近似保證的規劃演算法，可進一步壓低參數偏差。

第二，**動態與階層式預算分配**。當前 MergePipe 採用全局預算 B 與統一的區塊成本模型。未來可探索 layer-wise（逐層）或 block-wise adaptive budgeting（自適應預算分配），根據各層對下游任務的敏感度差異動態調整讀取比例，可能在相同 I/O 預算下獲得更高的下游保真度。

第三，**與分散式系統的整合**。LLM checkpoint 家族常儲存於遠端分散式儲存（distributed storage）或物件儲存中。將 MergePipe 的 I/O budget 概念擴展至 network bandwidth（網路頻寬）與 latency（延遲），並與 model serving framework（模型服務框架）結合，可實現「隨選合併」（on-demand merging）的部署場景。

第四，**放寬同源設定**。目前方法假設專家已處於共享座標系統。未來可研究將 MergePipe 與 lightweight online permutation alignment（輕量線上置換對齊）結合，使預算化存取集合能應用於未經事先對齊的異質專家，擴大適用範圍至多基地微調或跨架構遷移學習。

第五，**跨模態與更細緻的存取單位**。將 budgeted access sets 的概念延伸至 vision-language model（視覺語言模型）或多模態檢查點家族，並探索 sub-block（子區塊）或 row/column-level（行／列層級）的存取粒度，可能在極高維度參數空間中發掘更細緻的速度–保真度權衡。

## 論文問答

**Q1：MergePipe 試圖解決權重空間模型合併中的哪個根本問題？**
A：MergePipe 針對的是大型語言模型在權重空間合併時，讀取專家權重所產生的 I/O 瓶頸問題。傳統觀點將模型合併視為檢查點上的代數運算，但當專家池規模擴大時，讀取所有專家差異區塊的成本會隨專家數量 K 近乎線性增長，使得整個流程從計算受限轉為 I/O 受限。因此，真正的擴展性障礙往往不在於合併運算本身的計算量，而在於必須從儲存裝置讀取的大量專家權重。

**Q2：為何現有的樸素合併腳本無法有效擴展到現代的檢查點家族？**
A：現有的樸素合併腳本通常將檢查點視為不透明檔案，在執行 AVG、TIES 或 DARE 等規則時會掃描並讀取所有專家的全部參數，完全忽略並非每個權重區塊都對最終合併有同等重要性。這種「全讀取」策略導致專家讀取成本隨專家數量線性上升，在 LLM 規模下很快便會耗盡 I/O 頻寬與儲存讀取預算。由於缺乏對權重存取層級的抽象，這些方法無法在有限預算下選擇性地讀取最具影響力的差異區塊，因而難以應對專家數量持續增長的現實需求。

**Q3：為何作者認為「預算化專家讀取」與設計更好的合併規則同等重要？**
A：過往研究多聚焦於如何設計更優的合併規則，例如透過稀疏遮罩、任務向量或低秩更新來結合專家，但較少關注在執行層面「哪些參數必須被讀取」這一資源配置問題。隨著現代 LLM 開發產生越來越多的檢查點家族，合併作業的執行成本已從純粹的數學運算轉移到實際的儲存 I/O 開銷。MergePipe 的主張正是：在 LLM 規模下，模型合併需要權重存取抽象，而不僅是更好的合併規則，因為沒有效率的存取策略，再好的合併演算法也會被 I/O 瓶頸拖慢而難以實用。

**Q4：MergePipe 的核心方法如何重新定義傳統的合併問題？**
A：MergePipe 將傳統的權重合併重新定義為「專家存取集合問題」，在給定合併運算子與共享權重座標系統中的檢查點家族後，系統會明確選擇在 I/O 預算內應該讀取哪些專家差異區塊。它透過建立參數區塊索引、建構確定性存取計畫，並產生可重播的清單來執行預算約束下的合併。這種方式將「存取哪些區塊」與「如何組合已存取的差異」解耦，使得合併執行層能夠在嚴格的預算控制下運作，並確保執行過程透明且可重現。

**Q5：存取遮罩在 MergePipe 中扮演什麼角色，它如何保證預算健全性？**
A：存取遮罩（access mask）A 是一個二元決策變數，標記了每一個專家差異區塊 (i,t,b) 是否應該被讀取，而 MergePipe 確保規劃的遮罩滿足 C_expert(A) ≤ B 的預算約束，因此計畫在構造上就是預算健全的。執行器只會讀取被選中的區塊，遺漏的條目僅由遮罩編碼，不會觸發實際的儲存讀取，從而嚴格控制 I/O 成本。當預算充足時（A=1），系統能完全恢復全讀取合併的結果，這確保了方法在極限情況下的正確性與一致性。

**Q6：MergePipe 為何在規劃階段採用確定性貪婪或每單位成本評分啟發式，而非精確最佳化？**
A：雖然理想的存取集合目標可以寫成帶有預算約束的組合最佳化問題，但 MergePipe 在實作上採用確定性貪婪或每位元組評分啟發式方法，以在規劃效率與解的品質之間取得平衡。這類啟發式方法能夠快速根據差異區塊的範數、草圖（sketch）或其他後設資料計算存取分數，並在有限預算內選擇高分區塊，避免了精確背包問題求解可能帶來的過高計算開銷。這種設計選擇反映了 MergePipe 的核心哲學：將規劃與執行分離，並以可負擔的離線分析成本換取執行階段的大幅 I/O 節省。

**Q7：MergePipe 在哪些模型家族與工作負載上進行了評估？**
A：MergePipe 在 Qwen 與 Llama 這兩個主流開源大型語言模型的檢查點家族上進行了廣泛的合併工作負載測試。這些實驗涵蓋了不同規模的專家池與多樣的合併情境，用以驗證方法在真實 LLM 架構下的有效性與泛化能力。選擇這兩個模型家族是因為它們代表了現代 LLM 生態系中常見的共享基底與多樣化微調變體，能充分檢驗預算感知合併在實務上的價值。

**Q8：MergePipe 達成了哪些主要的量化改進？**
A：實驗結果顯示，MergePipe 能夠將專家讀取 I/O 降低高達一個數量級，並在執行速度上實現最高達 11 倍的加速。在代表性的預算掃描實驗中，預算化合併與全讀取合併之間的參數偏差僅為 O(10^-3) 量級，顯示出極高的權重保真度。更重要的是，下游基準測試並未出現單調性退化，證明在大幅減少 I/O 的同時，模型效能仍能維持穩定，達成了速度與準確度的良好權衡。

**Q9：對於加法運算子，預算約束下的遺漏更新誤差具有什麼理論性質？**
A：對於固定係數加法運算子，命題二證明了遺漏更新誤差可由被省略差異的範數所界定，具體而言，全讀取與預算化合併結果的 L2 距離上限為被遮罩排除項的加權範數總和。這個理論保證意味著只要根據 |α_i|·||Δ_i||_2 等分數優先選擇重要區塊，就能有效控制近似誤差。雖然此界限不適用於 TIES 或 DARE 等會改變係數或進行隨機丟棄的運算子，但 MergePipe 仍為這些運算子提供相同的預算執行抽象，並透過實證評估其保真度。

**Q10：在哪些實際的 LLM 部署場景中，MergePipe 最能發揮價值？**
A：MergePipe 特別適用於需要頻繁合併大量領域專家或指令微調變體的場景，例如企業內部擁有數十個針對不同部門微調的共享基底模型，卻希望在有限儲存頻寬下快速產生統一的部署模型。在雲端推理服務或邊緣裝置上，當儲存讀取速度成為瓶頸時，透過預算感知存取計畫能顯著縮短合併延遲。此外，對於需要迭代式合併或動態組合專家的系統，降低線性增長的 I/O 成本更是維持服務可擴展性與即時性的關鍵。

**Q11：MergePipe 如何與現有的模型對齊工作流程整合？**
A：MergePipe 假設標準的同源設定，即所有專家來自共享基底或已透過對稱對齊、置換對齊等方法調整至共同權重座標系統，因此它能無縫銜接現有的權重對齊流程。在產品化時，開發者可以先執行對齊步驟，再將 MergePipe 作為執行層插入，負責在給定 I/O 預算下選擇與讀取差異區塊。其產生的可重播清單（replayable manifest）也便於 MLOps 流程進行版本控制、稽核與重現，提升生產環境的可維護性與透明度。

**Q12：MergePipe 可能如何改變權重空間模型合併領域的研究方向？**
A：MergePipe 將研究焦點從單純設計更精巧的合併規則，擴展到執行層面的權重存取抽象與資源預算管理，為權重空間合併領域引入了系統層級的視角。這種範式轉移可能激發更多關於「在有限 I/O 下最大化合併品質」的研究，例如發展更精確的區塊重要性估計方法或動態預算分配策略。長遠來看，當合併被視為可預算化的資料庫查詢操作時，整個領域可能會借鑑資料庫與儲存系統的優化技術，進一步推動大規模模型合併的工業化應用。

**Q13：MergePipe 的適用性受到哪些關鍵假設的限制？**
A：MergePipe 目前主要適用於同源設定，即所有專家必須來自同一共享基底，或已透過外部對齊方法置於共同的權重座標系統中，這限制了它在任意異質模型間直接應用的可能性。此外，對於非加法運算子如 TIES 和 DARE，雖然系統仍提供預算執行框架，但目前缺乏類似固定係數加法運算子那樣嚴格的遺漏更新誤差理論界限。這些假設意味著在使用 MergePipe 之前，必須先確保模型權重已適當對齊，且對於複雜的非線性合併規則，其近似品質仍需依賴實證驗證而非理論保證。

**Q14：在什麼條件下，預算化合併可能表現不佳？**
A：當各專家差異區塊的重要性分布極為均勻，或每個區塊對下游任務都有近乎同等的關鍵影響時，貪婪地省略任何區塊都可能導致明顯的效能下降，此時預算化合併的優勢會被削弱。如果離線分析階段使用的範數或草圖分數無法準確反映區塊的真實貢獻，規劃器可能會錯誤地保留低價值區塊而排除高價值區塊，進而放大近似誤差。此外，在預算極度緊縮且專家數量龐大的情況下，即使理論誤差界限很小，實際的下游基準表現仍可能出現非單調波動，需要謹慎設定預算閾值。

**Q15：作者暗示了哪些 MergePipe 的自然延伸方向？**
A：未來研究可以朝幾個方向延伸：首先，發展適用於非固定係數運算子（如 TIES、DARE）的理論誤差界限，以補齊目前僅對加法運算子有嚴格保證的缺口。其次，可以探索超越貪婪啟發式的規劃演算法，例如利用區塊間的相依性結構或任務特定資訊來設計更精緻的存取分數。最後，將 MergePipe 的預算框架擴展到非同源設定，結合更強大的對稱或置換對齊技術，或許能讓選擇性權重讀取的好處惠及更廣泛的異質模型合併場景。

**多領域企業級 LLM 整合部署**

**邊緣或儲存頻寬受限環境的模型更新**  
在邊緣資料中心或具備嚴格網路出口限制的環境中，讀取數十個到數百個專家檢查點的全量權重可能不可行。透過預算感知的差異區塊選取，僅傳輸與合併高影響力的專家差異區塊，使權重空間模型合併能在儲存受限條件下完成。

**頻繁迭代的多專家 MLOps 管線**  
實驗平台或自動化微調系統每日產生大量檢查點家族，需持續執行合併以產生基準模型。MergePipe 的確定性存取計畫與可重播清單適合嵌入 CI/CD 流程，讓工程團隊在專家數量 K 增加時，仍維持接近固定的合併執行時間與 I/O 成本。

**多租戶個人化模型服務**  
SaaS 平台為不同客戶維護微調後的轉接器或差異更新，並依需求動態合併特定客戶子集的專家權重。MergePipe 允許為每個合併請求設定獨立的專家讀取預算，在服務層級協定（SLA）內完成客製化合併，而不必載入整個專家池。

**災難恢復與模型版本重建**  
利用可重播清單記錄每次合併的存取遮罩與運算子參數，可在基底模型與差異區塊儲存庫上，精準重建歷史合併結果。這對於審計、回溯除錯，以及從部分儲存節點故障中快速恢復特定版本至關重要。

### 實作前置條件

**資料條件**  
所有專家檢查點必須處於同源設定，即源自同一共享基底模型，或已透過對稱對齊、置換對齊等方法進入共同權重座標系統。此外，需預先為每個專家差異區塊計算後設資料（如 L2 範數、稀疏遮罩覆蓋率、低秩近似能量），作為存取評分的依據。

**運算條件**  
執行環境需具備可隨機讀取區塊的高速儲存（如 NVMe SSD 或支援範圍請求的分散式物件儲存），且 I/O 頻寬須為明顯瓶頸，方能體現預算控制的效益。同時需要足夠記憶體載入基底區塊與被選取的專家差異區塊，並具備輸出檢查點的寫入權限。

**技能條件**  
團隊需熟悉 PyTorch 或 TensorFlow 的檢查點格式與記憶體對應機制，具備分散式儲存系統操作經驗，並理解權重空間模型合併運算子（如 AVG、TIES、DARE）的基本原理與差異。若需自訂評分函數，則需基礎線性代數與最佳化知識。

### 實作步驟建議

**步驟一：權重座標系統對齊與驗證**  
確認所有專家檢查點已對齊至共享權重座標系統。若專家來自不同微調路徑但非同一基底，需先執行置換對齊或對稱對齊，確保神經元對應關係一致，否則後續差異區塊的範數評分將失去意義。

**步驟二：差異區塊索引化與目錄建構**  
將每個專家檢查點轉換為相對於共享基底的專家差異區塊（expert delta blocks）。建立區塊層級索引，記錄每個參數區塊的識別碼、張量位置、讀取成本，以及離線分析得到的評分資訊（如範數、稀疏度）。此目錄建構成本應攤提或計入總預算。

**步驟三：評分函數選擇與預算規劃**  
依據合併運算子類型選擇適當的評分策略：若使用固定係數加法運算子，可採用 L2 範數作為存取分數，直接對應遺漏更新誤差界限；若使用 TIES 或 DARE，則需結合符號一致性或稀疏遮罩覆蓋率設計啟發式評分。設定明確的 I/O 預算 B，執行貪婪或每字節評分啟發式演算法產生確定性存取計畫。

**步驟四：產生可重播清單與存取遮罩**  
輸出二元存取遮罩（access mask）與可重播清單（replayable manifest），明確記錄哪些 (專家, 張量, 區塊) 組合被選取、讀取順序、合併係數，以及隨機化運算子所需的亂數種子。此清單即為預算健全的執行契約。

**步驟五：遮罩感知合併執行**  
載入基底區塊，依據清單僅讀取被選取的專家差異區塊，執行遮罩感知運算子（mask-aware operator）。被省略的區塊僅由遮罩編碼，不觸發儲存讀取。完成後寫出最終合併檢查點。

**步驟六：下游驗證與管線整合**  
在下游基準測試上驗證合併品質。若參數偏差或任務效能未達門檻，則放寬預算或調整評分權重。將通過驗證的存取計畫與清單納入模型版本控制與自動化管線，實現可重現的預算化合併。

### 潛在風險與注意事項

**同源設定違規導致品質崩潰**  
若專家檢查點未源自同一共享基底，或未經對齊進入共同權重座標系統，差異區塊的幾何意義將失效，合併結果可能產生無法預測的參數偏差。實作前務必驗證所有檢查點的座標一致性，必要時先執行對齊演算法。

**非加法運算子的理論保證缺口**  
TIES、DARE 等涉及稀疏化、符號選擇或重新縮放的運算子，其遺漏更新誤差無法像固定係數加法運算子那樣被範數嚴格界定。對於這類運算子，不可僅依賴理論界限推斷品質，必須透過代表性的下游基準測試進行經驗性驗證。

**離線分析成本低估**  
建立區塊索引與計算範數等離線分析步驟同樣涉及儲存讀取。若將這些成本排除在預算外，可能導致實際總 I/O 超支。建議將目錄建構視為一次性攤提成本，或在每次合併運行中將其計入專家讀取預算。

**記憶體碎片化與讀取效率**  
區塊級隨機讀取可能導致記憶體映射碎片化與儲存尋道 overhead。建議在執行層實作區塊預取與讀取順序重排，將邏輯上分散的區塊盡可能轉換為連續的儲存讀取請求，以維持實際加速比。

**隨機運算子的再現性風險**  
DARE 等隨機化運算子若未固定亂數種子，不同執行可能產生不同的存取計畫與合併結果。可重播清單必須完整記錄種子與遮罩參數，並在驗證環境與生產環境使用相同的偽亂數產生器實作。

### 與其他技術的整合建議

**與對齊方法互補串接**  
MergePipe 與對稱對齊、置換對齊方法在管線中互補。建議在模型合併管線的前段，先以 Git Re-Basin 或類似技術完成神經元排列對齊，使權重進入共同座標系統後，再接入 MergePipe 執行預算感知的區塊選取與合併。

**與 PEFT 及 Adapter 架構整合**  
當專家權重以 LoRA、Adapter 等輕量差異更新形式存在時，可將這些低秩更新視為專家差異區塊直接納入存取集合評分。由於這類更新體積遠小於全量權重，MergePipe 的預算控制可進一步放大其儲存效率優勢。

**與模型版本控制系統整合**  
將 MergePipe 產生的可重播清單與 MLflow、DVC 或自研模型倉庫綁定，使每次合併的存取遮罩、預算設定、評分函數版本與下游效能指標一併納入版本控制，實現合併行為的完整可追溯性。

**與分散式儲存及快取層整合**  
在基於物件儲存（如 S3、MinIO）的環境中，將區塊索引與後設資料存放於高速鍵值儲存（如 Redis、Etcd），差異區塊存放於物件儲存。透過支援範圍請求的儲存客戶端，僅下載被選取區塊的位元組範圍，避免全檔案傳輸。

論文的核心貢獻在於將權重空間合併重新定義為專家存取集合問題，並提供預算健全性與加法遺漏誤差界限。建議深入分析 Proposition 1 與 2，思考如何將此框架擴展至非加法運算子（如 DARE）的理論保證，或結合主動學習中的核心集選取策略，進一步提升評分函數的樣本效率。

**產品經理**  
將 MergePipe 視為「在不犧牲下游效能的前提下，將多專家合併成本降低一個數量級」的基礎設施。閱讀時請聚焦摘要與實驗結論：當專家池規模 K 擴大時，傳統全讀取合併的 I/O 成本線性增長，而 MergePipe 能在固定預算下維持 O(1/K) 的讀取比例，這直接轉化為雲端儲存費用與模型迭代速度的競爭優勢。
