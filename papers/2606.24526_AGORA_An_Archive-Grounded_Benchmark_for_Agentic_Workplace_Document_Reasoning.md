# AGORA：基於檔案庫的代理式職場文件推理基準測試

## ⚡ TL;DR

現有基準難以評估代理在雜亂職場檔案庫中主動探索與跨文件推理的能力。
本研究提出AGORA基準，以代理式流程建構橫跨八大領域、近萬份真實文件的推理題目。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）日益被部署為能對文件進行推理的智能代理（agents），而非僅憑參數化知識（parametric knowledge）作答。我們研究基於檔案庫的推理（archive-grounded reasoning）：在龐大且雜亂的職場文件館藏中尋找稀疏證據（sparse evidence），調和術語（terminology）、單位（units）與時間慣例（time conventions）上的不一致，並計算答案（computing an answer）。現有的基準測試（benchmarks）僅涵蓋此情境的部分面向，且沒有任何一個同時強調檔案庫基礎性（archive-groundedness）、代理式探索（agentic exploration）與跨領域涵蓋範圍（cross-domain coverage）。本文提出 Agora，這個基準測試（benchmark）結合了 362 道問題與八個領域集合（domain collections），包含 9,664 份真實文件（authentic documents）與 3.72 億詞元（tokens），遠超過任何模型的上下文視窗（context window），因此智能代理（agents）必須進行策略性探索（deliberate exploration），而非窮舉式掃描（exhaustive scan）。Agora 是透過代理式流程（agentic pipeline）建構而成，結合跨文件任務合成（cross-document task synthesis）、防洩漏混淆處理（leakage-preventing obfuscation）與難度篩選（difficulty filtering）。評估八個模型後，我們發現此任務遠未解決：即使最強的模型也僅達到 59.4% 準確率（accuracy），且在不同領域（domains）間存在顯著差異。

### 核心貢獻（3～5點）
- 定義「基於檔案庫的推理」（archive-grounded reasoning）任務，涵蓋稀疏證據（sparse evidence）定位、術語／單位／時間慣例不一致性之調和，以及答案計算（computing an answer）三大挑戰。
- 提出 Agora 基準測試，首次同時強調檔案庫基礎性（archive-groundedness）、代理式探索（agentic exploration）與跨領域涵蓋範圍（cross-domain coverage）。
- 以 362 道問題、八個領域集合（domain collections）、9,664 份真實文件（authentic documents）與 3.72 億詞元（tokens）建構超大規模測試集，迫使智能代理（agents）必須進行策略性探索（deliberate exploration），而非窮舉式掃描（exhaustive scan）。
- 設計結合跨文件任務合成（cross-document task synthesis）、防洩漏混淆處理（leakage-preventing obfuscation）與難度篩選（difficulty filtering）的代理式建構流程（agentic pipeline），確保評測品質。
- 評估八個模型，發現最強模型準確率（accuracy）僅達 59.4%，顯示此任務遠未解決，且不同領域（domains）間存在顯著差異。

### 適合對象
從事大型語言模型（LLMs）與智能代理（agents）研究的學者與工程師；於企業場景（enterprise settings）中需處理內部檔案庫（internal archives）與知識工作任務（knowledge-work tasks）的開發者；以及金融分析師（financial analysts）、法律研究人員（legal researchers）、政策團隊（policy teams）等需驗證模型在真實職場文件上表現的專業人士。

## 深度分析

#### 方法論解析

AGORA（Archive-Grounded Office Reasoning Assessment）的核心設計在於模擬真實企業場景（enterprise settings）中的知識工作任務（knowledge-work tasks），要求語言代理（language agents）必須在遠超上下文視窗（context window）承載量的雜亂館藏（messy collection）中執行基於檔案庫的推理（archive-grounded reasoning）。具體而言，其方法論可拆解為三個層次：

第一，資料與任務設計。AGORA 涵蓋八個專業領域（domains）的領域集合（domain collections），包含農業（Agriculture, Agri）、建築（Architecture, Arch）、商業（Business, Biz）、教育（Education, Edu）、金融（Finance, Fin）、醫療（Health）、法律（Law）與科技（Technology, Tech），共計 9,664 份真實文件（authentic documents）、372M 詞元（tokens）以及 362 道自然語言查詢（queries）。每道題目皆要求代理在單一固定館藏內定位稀疏證據（sparse evidence）、調和矛盾（reconciling inconsistencies）——包括不一致的術語（inconsistent terminology）、單位（units）與時間慣例（time conventions）——並透過多步驟計算（computing an answer）得出唯一可驗證的數值答案（verifiable numeric answer）。由於館藏規模遠超任何現行模型的上下文視窗，代理無法依賴窮舉式掃描（exhaustive scan），而必須採取策略性探索（deliberate exploration）。

第二，基準測試建構管線。作者設計了一套代理式管線（agentic pipeline）以確保題目品質與難度：（1）跨文件任務合成（cross-document task synthesis），自動生成需橫跨多份職場文件（workplace files）才能解答的多跳問題；（2）防洩漏混淆處理（leakage-preventing obfuscation），避免測試內容被模型以參數化知識（parametric knowledge）記憶而洩漏；（3）難度篩選（difficulty filtering），剔除過於簡單或無法穩定驗證的樣本；以及（4）人工驗證，確保答案正確性與館藏內可導出性。

第三，評測架構標準化。為聚焦模型層級的推理能力而非複雜腳手架（scaffolding）差異，所有實驗均在 mini-swe-agent 中進行，且僅暴露 bash 工具。這種極簡介面迫使模型展現真正的代理式探索（agentic exploration）能力——包括主動檔案導航（active file navigation）、證據選擇與程式碼執行（code execution）——從而精確衡量其檔案庫基礎性（archive-groundedness）。

#### 實驗數據解讀

實驗評估了八款模型（eight models），橫跨專有模型與開源權重模型（open-weight models）。整體準確率（overall accuracy）顯示，即便是最強模型也僅達 59.4%，幾乎觸及但未跨越 60% 門檻，顯示代理式職場文件推理（agentic workplace document reasoning）仍遠未解決（far from solved）。圖一中可觀察到明顯的效能斷層：頂尖模型接近 60%，而部分模型僅有 3.04%、6.35% 與 11.33% 的準確率（accuracy），揭示出當前不同架構在面對真實內部檔案庫（internal archives）時的能力鴻溝。

更值得關注的是跨領域（cross-domain）的表現差異。實驗發現，各領域的領先模型往往不同於總體排名，意味著難度並非基準測試（benchmark）本身的靜態屬性，而是特定模型與特定領域互動後湧現的性質。例如，某模型可能在金融（Fin）領域表現優異，卻在法律（Law）或建築（Arch）領域大幅衰退。這項發現凸顯了單一領域或單一來源基準測試的侷限：它們會隱藏模型在調和矛盾、理解分散文件（scattered documents）與適應領域特定慣例上的弱點。AGORA 透過跨領域涵蓋範圍（cross-domain coverage）成功揭露了這些隱藏落差，為後續研究提供了明確的提升空間（headroom）。

#### 與現有研究的比較

如表一所示，現有基準測試僅能覆蓋職場推理的部分需求。多跳問答（multi-hop QA）基準如 HotpotQA、MuSiQue 與 FRAMES 雖然要求跨文件推理，但其語料多為同質的維基百科（Wikipedia），缺乏職場文件的格式多樣性與不規則組織。文件問答（document QA）與表格問答（table QA）基準如 TAT-QA 與 FinanceBench 雖然涉及財務報告等專業內容，但本質上仍屬閱讀理解（reading-comprehension）任務，不要求代理執行檔案系統導航或跨異質文件的多步驟計算。代理與網頁瀏覽基準如 GAIA 與 BrowseComp 則運作於開放網路（open web）或模擬環境，而非有界限的內部檔案庫，因此無法評估模型在封閉企業場景中的可靠性。

最接近的前置研究是 OfficeQA Pro，其結合檢索與計算並使用大型企業風格語料；然而，該基準僅源自單一外部來源（single external source），領域與文件格式涵蓋受限。相較之下，AGORA 首次同時強調檔案庫基礎性（archive-groundedness）、代理式探索（agentic exploration）與跨領域涵蓋範圍（cross-domain coverage）三項要素，並以真實職場文件的術語、單位與時間慣例不一致性作為核心挑戰。

當然，AGORA 仍存在若干限制。首先，362 題的規模相較於動輒數千甚至上萬題的傳統問答基準仍屬精緻型設計。其次，答案形式限於可驗證的數值，尚未涵蓋開放式生成、解釋性輸出或決策（decision-making）建議等更貼近真實知識工作的輸出類型。第三，評測僅提供 bash 工具，雖有助於標準化，但可能低估企業代理使用專業工具（如 SQL、試算表或領域特定 API）的潛力。

#### 可重現性評估

從方法論設計來看，AGORA 具備多項有利於可重現性（reproducibility）的特徵。首先，每道題目皆設計為具有唯一數值答案，使評估過程完全確定性（deterministic），無需人工或模型評判（human or model-based judgment），從根本消除了主觀評分偏差。其次，mini-swe-agent 統一代理介面（agent interface），僅暴露 bash 工具，確保不同模型在相同操作環境下受測，減少了因複雜腳手架差異所導致的評測噪音。第三，建構管線明確描述了跨文件任務合成（cross-document task synthesis）、防洩漏混淆處理（leakage-preventing obfuscation）與難度篩選（difficulty filtering）的步驟，為社群複製題目生成邏輯提供了藍圖。

然而，就提供的文本摘錄而言，尚未見到原始碼（source code）、資料集（dataset）下載連結或模型權重（model weights）的公開釋出資訊。由於館藏包含真實職場文件，版權與隱私問題可能構成公開釋出的實務障礙。建議作者至少釋出建構管線程式碼與去識別化後的題目-答案對（question-answer pairs），即便文件本體需以受控方式存取，亦能確保研究社群重現評測流程並進行公平比較。

#### 未來研究方向

基於 AGORA 所揭示的挑戰，未來研究可沿以下方向推進：

第一，規模與題型擴展。將目前 362 題的規模擴增，並納入開放式答案、解釋生成與多選題型，以評估模型在對話流暢度（fluency in chat）之外的決策輔助與論證能力。第二，工具多樣性。超越單一 bash 工具，整合試算表（spreadsheets）、結構化查詢語言（SQL）、文件解析器與領域特定工具，使代理能力評估更貼近真實企業場景。第三，動態檔案庫研究。現行基準採用靜態館藏，未來可探討代理如何因應內部檔案庫的即時更新——例如新增、刪除或修改文件——並維持答案的可驗證性。第四，長上下文與策略性探索的權衡。隨著上下文視窗（context window）持續擴大，需系統性研究策略性探索（deliberate exploration）是否仍具優勢，抑或窮舉式掃描（exhaustive scan）將成為可行替代方案。第五，領域特化代理。針對金融、法律、醫療等專業領域開發具備領域適應能力的專屬架構，強化術語調和、單位換算與時間慣例對齊能力。第六，多代理協作。設計多代理系統（multi-agent systems），讓不同專長代理分別負責檢索、計算與驗證，以提升複雜推理的整體準確率。第七，安全與隱私。在內部檔案庫場景中，研究如何在不暴露敏感資訊的前提下進行端對端評測、微調與部署，確保企業導入時的資料治理合規性。

## 論文問答

**Q1：AGORA 旨在解決的核心問題是什麼？**
A：AGORA 旨在解決職場環境中「基於檔案庫的推理」挑戰，即智能代理必須在龐大且雜亂的真實文件館藏中，定位稀疏證據並調和術語、單位與時間慣例上的不一致性。這類任務遠超傳統閱讀理解的範疇，要求代理主動瀏覽目錄結構、執行多步驟運算，並從異質文件中推導出可驗證的答案。隨著大型語言模型越來越多地被部署為企業內部的知識工作助手，評測其處理真實職場檔案庫的能力變得至關重要。

**Q2：現有的基準測試為何無法充分評估代理式文件推理能力？**
A：現有的多跳問答基準測試（如 HotpotQA）通常依賴維基百科等同質性語料庫，無法反映職場文件在格式與組織上的多樣性與不規則性。文件問答基準測試大多被框定為閱讀理解任務，不要求代理瀏覽檔案系統或對異質文件進行多步驟計算。此外，現有的代理與網頁瀏覽基準測試多在開放網路或模擬環境中運作，而非在封閉的內部檔案庫上進行推理，就連最接近的 OfficeQA Pro 也僅限於單一外部來源。

**Q3：為何評測基於檔案庫的推理能力對職場 AI 代理的發展如此重要？**
A：在企業場景中，語言代理的價值不在於產生流暢的對話回應，而在於協助使用者完成覆蓋內部檔案庫的真實知識工作任務。無論是金融分析師核實跨報告的數據、法律研究人員追蹤相關條款與判例，或是政策團隊綜合分散文件的證據，都必須處理術語衝突、單位不一致與稀疏證據等挑戰。若缺乏針對這些能力的嚴格評測，我們將無法判斷代理是否能成為可靠、可驗證且真正能輔助決策的職場助手。

**Q4：AGORA 基準測試的核心建構方法為何？**
A：AGORA 透過一套代理式管線進行建構，首先利用深度搜尋收集橫跨八個專業領域的真實文件，再合成需要橫跨多份文件才能解答的多跳推理問題。為了確保品質與公平性，管線接著執行防洩漏混淆處理以避免資料污染，並透過難度篩選與人工驗證確保問題具備適當挑戰性。最終產出的 362 道查詢各自搭配一個領域集合，總計 9,664 份文件與 3.72 億詞元，遠超任何模型的上下文視窗，迫使代理必須進行策略性探索而非窮舉式掃描。

**Q5：AGORA 相較於以往基準測試的關鍵創新為何？**
A：AGORA 是首個同時強調三大維度的基準測試：以固定館藏為基礎的檔案庫基礎性、需要主動瀏覽的代理式探索，以及橫跨八個專業領域的跨領域涵蓋範圍。不同於以往工作，它將自然語言查詢與遠超模型上下文視窗的真實職場文件配對，從而迫使代理發展出具選擇性的探索策略。此外，其代理式建構管線能自動生成跨文件推理任務，並透過防洩漏混淆技術避免測試資料污染訓練資料，確保評測結果的真實性與嚴謹性。

**Q6：作者為何選擇使用僅提供 bash 工具的極簡代理框架（mini-swe-agent）進行評測？**
A：作者刻意將代理介面限制在單一 bash 工具，以保持互動環境的固定與簡潔。這項設計選擇確保了模型之間的比較能聚焦於模型層級的推理能力、證據選擇與工具使用，而非複雜的代理腳手架或特殊架構所帶來的優勢。透過標準化操作介面，AGORA 能更清晰地揭示不同模型在自主導航檔案結構與推導答案時的本質差異。

**Q7：實驗採用了哪些模型與評測設定來測試 AGORA？**
A：作者評測了八款包含專有模型與開源權重模型的混合陣容，所有模型皆在僅暴露 bash 工具的 mini-swe-agent 框架中運行。這些模型被測試於橫跨農業、建築、商業、教育、金融、醫療、法律與科技等八個領域的文件集合上。每道題目都要求代理在無法窮舉掃描的情況下，瀏覽檔案結構、定位稀疏證據，並計算出可驗證的數值答案。

**Q8：模型在 AGORA 上的評測結果中最重大的發現是什麼？**
A：評測結果顯示，基於檔案庫的文件推理仍遠未被解決，即便是最強大的模型也僅達到 59.4% 的整體準確率，尚未突破 60% 的門檻。更重要的是，不同領域之間的表現存在顯著差異，顯示難度並非單純來自基準測試本身，而是源於特定模型與特定領域之間的互動效應。此外，各領域的領先模型排名往往與總體排名不同，這意味著單一來源或單一領域的評測會隱藏模型在特定專業脈絡下的重大弱點。

**Q9：各領域表現的差異揭示了當前語言代理的什麼特性？**
A：各領域之間顯著的準確率落差顯示，當前代理在不同專業脈絡下的能力分布極不均勻，在某些領域表現尚可，但在其他領域卻明顯不足。這項發現意味著總體準確率可能掩蓋模型在特定專業領域的嚴重缺陷，因此跨領域評測對於全面了解模型能力至關重要。難度源於模型與領域互動的現象也暗示，提升通用檔案庫推理能力必須針對各領域的術語、文件結構與證據稀疏性等特性進行專門處理。

**Q10：AGORA 所評測的推理能力在哪些真實職場情境中最具價值？**
A：這類推理能力直接適用於金融分析場景，分析師必須在格式不一致的多份報告與試算表中核實數據並進行計算。法律研究人員同樣受益於能夠在龐大且組織鬆散的資料庫中追蹤相關條款與判例的代理。此外，政策團隊需要從分散的內部文件中綜合證據以支持知情決策，這正是 AGORA 所強調的跨文件、多步驟推理能力的典型應用。

**Q11：根據 AGORA 的研究發現，產品開發者在建構職場代理時應考量哪些因素？**
A：開發者必須認知到，當企業檔案庫的規模遠超模型上下文視窗時，代理無法依賴窮舉式掃描或淺層關鍵字匹配來完成任務。他們必須設計具備策略性探索能力的系統，使模型能夠規劃搜尋路徑、調和不同文件間不一致的術語與單位，並執行多步驟運算。由於 AGORA 顯示各領域表現差異顯著，開發者應針對多元專業情境進行測試與優化，而非假設模型具備均一的跨領域能力。

**Q12：AGORA 可能如何影響代理基準測試與開發的未來走向？**
A：AGORA 為評測語言代理是否能對真實內部檔案庫進行可靠推理設立了新的標準，將評測焦點從平坦或網頁規模的語料庫轉向雜亂的職場館藏。透過引入跨領域涵蓋範圍與可驗證的數值答案，它推動領域朝向更嚴謹、更貼近決策需求的評估準則發展。這項轉變預計將刺激更多關於高效探索策略、矛盾調和機制，以及適應不同專業領域的代理架構的研究。

**Q13：AGORA 基準測試的設計存在哪些固有的限制？**
A：AGORA 聚焦於具備唯一可驗證數值答案的問題，這雖然確保了評測的客觀性，但同時也限制了所評估推理任務的類型，無法涵蓋開放式生成或質性分析任務。由於採用真實職場文件作為館藏，資料集自然繼承了真實檔案庫中不規則的組織方式與潛在雜訊，這可能引入與核心推理能力無關的變異性。此外，評測使用極簡的 bash 介面雖然確保了公平比較，但也可能無法完全反映配備更複雜腳手架之代理在實際應用中的全部潛力。

**Q14：低準確率與領域差異顯示了當前模型在哪些方面的失敗？**
A：沒有任何模型突破 60% 準確率的事實表明，現有代理在定位稀疏證據與調和大型文件集合中的不一致性方面仍面臨重大困難。特定領域的失敗案例顯示，模型經常缺乏處理某些專業術語與文件結構所需的領域理解，或無法採取有效的探索策略來檢索關鍵資訊。這些失敗凸顯了代理仍過於頻繁地依賴無效的搜尋模式，或在執行必要的跨文件數值運算時發生錯誤，顯示其自主推理與工具使用能力尚不成熟。

**Q15：AGORA 的研究結果為改善基於檔案庫的推理代理指出了哪些未來研究方向？**
A：未來研究應優先發展更具策略性的探索機制，使代理能夠在無法窮舉掃描的龐大館藏中智慧地導航與檢索。提升模型調和異質文件間不一致術語、單位與時間慣例的能力，是另一個亟需突破的關鍵方向。此外，深入探究為何特定領域對當前模型更具挑戰性，並發展能夠適應不同專業脈絡的領域自適應推理模組，將有助於縮小 AGORA 所揭示的跨領域性能落差。

## 實務應用指南

### 適用場景

1. **企業財務稽核與盡職調查**：金融分析師需在數千份雜亂的內部報告、試算表與合約中，定位稀疏證據以驗證關鍵數字。代理必須調和不同文件間不一致的術語與單位（例如「k」與「thousand」、「百萬」與「M」），並執行跨文件計算，產出可驗證的數值結論。

2. **法律事務所合約與判例追蹤**：法律研究人員面對組織鬆散的內部檔案庫，需追蹤橫跨多份文件的條款與判例。代理必須主動導航檔案結構，處理不同文件對同一法律概念的不一致用語，並推導出具體的數值或邏輯答案（例如計算違約金總額或追溯條款適用期間）。

3. **政府政策跨部門資料統整**：政策團隊需從分散且格式各異的文件中綜合證據，例如在教育領域計算跨國標準化指標。代理需調和不同國家的時間慣例（如「2024/6/1」與「Jun 1, 2024」）與統計口徑，進行多步驟數值運算，輔助決策。

4. **醫療病歷與臨床試驗交叉驗證**：醫療人員需在大量病歷、檢驗報告與試驗紀錄中，搜尋特定病患的稀疏證據。代理需處理不同醫院系統的術語差異與單位換算（如血糖值單位差異），並計算風險指標或劑量總和。

5. **建築工程專案文件審查**：處理橫跨設計圖、規格書、採購合約的雜亂館藏，自動核對材料數量、單位換算與日期格式不一致的問題，並計算專案總成本或工期緩衝天數。

### 實作前置條件

- **資料條件**：需具備真實職場文件組成的領域集合，總詞元數應遠超過目標模型的上下文視窗（例如數百萬至數億詞元），以強迫代理進行策略性探索而非窮舉式掃描。文件需呈現真實的異質性（PDF、Word、Excel、純文字混雜）與組織不規則性。此外，必須建立防洩漏混淆處理機制，避免測試資料污染模型訓練資料。

- **運算條件**：需部署具備工具使用能力的 LLM 推理環境，並建議採用最小化代理介面（如僅暴露 bash 工具），以隔離模型本身的推理與檔案導航能力。需配備足夠的儲存與索引系統支援代理式探索，以及可自動比對數值答案的評估框架，確保評估過程確定且可重現。

- **技能條件**：團隊需熟悉檢索增強生成（RAG）與代理框架（如 ReAct、SWE-agent），具備資料工程能力以清洗雜亂的原始文件，並擁有領域專家知識以執行跨文件任務合成、難度篩選與人工驗證。

### 實作步驟建議

1. **館藏盤點與領域定義**：盤點內部檔案庫，依領域（如金融、法律、醫療、教育）劃分文件集合，確認其具備真實職場的雜亂特性，包括格式混雜、資料夾結構不規則、術語與單位不統一。

2. **建立代理式探索環境**：部署輕量級代理框架（如 mini-swe-agent），僅提供 bash 等基礎工具，強制代理主動導航檔案結構。設定嚴格的上下文視窗限制，模擬真實部署中無法一次性讀取全館的場景。

3. **跨文件任務合成與問題設計**：利用自動化管線或領域專家，設計需橫跨多份文件才能解答的問題。每題應具備唯一、可驗證的數值答案，並刻意納入需調和時間慣例、單位換算或術語不一致的計算步驟。

4. **防洩漏與品質控管**：對文件進行防洩漏混淆處理（如替換專有名詞、擾動非關鍵數值），並透過難度篩選移除可直接關鍵字掃描得出答案的簡單題目，再經人工驗證確保題目品質。

5. **模型評估與領域適配**：在固定工具介面下評估多個模型，記錄整體準確率與各領域準確率。注意領域間的表現差異，針對弱點領域調整代理的探索策略或引入領域專家規則。

6. **產品化整合**：將驗證過的代理流程封裝為 API，整合至企業知識管理平臺。保留答案溯源與計算過程顯示功能，並設計人工覆核機制，因目前最強模型準確率仍僅約六成。

### 潛在風險與注意事項

- **過度依賴窮舉式掃描**：若給予代理過長的上下文或過強的全文檢索工具，可能使其淪為關鍵字匹配，喪失策略性探索能力。應嚴格限制上下文視窗，強迫代理透過目錄結構與檔案名稱進行有選擇的瀏覽。

- **術語與單位不一致導致計算錯誤**：職場文件中普遍存在不一致的術語、單位與時間慣例。若未在提示詞或工具中明確要求標準化（例如統一貨幣單位或日期格式），代理極易產生幻覺或計算偏差。

- **資料洩漏與污染**：內部檔案庫常含機敏資訊，且若測試內容與模型訓練資料重疊，將高估真實表現。必須實施防洩漏混淆處理，並建立訓練資料隔離機制。

- **整體準確率掩蓋領域弱點**：單一總分可能隱藏特定領域的嚴重缺陷（例如某模型在金融表現佳但在法律表現差）。應建立分領域儀表板，並針對弱點領域加強資料清洗或採用領域專家模型。

- **工具權限與安全性**：代理在檔案系統中執行 bash 指令具潛在風險，需在沙箱環境中運行，嚴格限制寫入、刪除與網路存取權限，避免誤刪或外洩內部檔案。

### 與其他技術的整合建議

- **與 RAG 系統整合**：將 AGORA 的代理式探索邏輯作為 RAG 的上層協調器。由傳統檢索器負責初步召回相關文件區塊，再由代理負責跨文件的語意調和與數值計算，彌補傳統 RAG 難以處理多跳推理與複雜運算的缺口。

- **與企業知識管理平臺整合**：透過 API 將代理接入現有文件管理系統（如 SharePoint、Confluence）。利用平臺的中繼資料強化檔案導航效率，同時讓代理將答案、引用來源與計算過程回寫至系統日誌，確保可驗證性。

- **與結構化資料庫協作**：對於高度結構化的數據（如財務報表、庫存紀錄），先以傳統 ETL 或表格解析工具（如 Pandas、專用 PDF 表格解析器）提取結構化資料，再由代理進行跨文件的語意推理與計算，降低純文字處理的錯誤率。

- **與人機協同審查介面整合**：由於目前最強模型僅達 59.4% 準確率，建議將代理輸出導入審查工作流。介面應標註不確定區塊、顯示逐步計算過程，並由領域專家進行最終確認，而非直接採用全自動決策。

### 給不同背景讀者的閱讀建議

- **初學者**：這篇論文展示了「會聊天的 AI」與「會辦公的 AI」之間的鴻溝。建議先理解「為何不能直接把全部文件塞給 AI」（因為上下文視窗不夠），以及「為何需要代理自己找文件」（因為真實職場文件很亂）。重點看圖一與表一的比較，就能快速掌握這個基準測試與傳統問答的差異。

- **AI 工程師**：請聚焦於論文的評估設定與 mini-swe-agent 的實作細節。作者刻意簡化工具介面（僅保留 bash）以隔離模型能力，這對你在設計企業代理時極具參考價值。同時注意各領域準確率的巨大差異，這意味著在實際部署時，單一模型很難通吃所有領域，需考慮領域路由或專家混合架構。

- **研究人員**：本文的核心貢獻在於提出了「基於檔案庫的推理」這個尚未被充分研究的設定，並透過防洩漏混淆與難度篩選建立了高品質的跨領域基準。建議深入分析代理行為與錯誤模式，特別是模型在策略性探索與調和術語不一致時的失敗案例，這些將是下一代代理架構的重要研究方向。

- **產品經理**：這份研究直接點出了企業 AI 助理的商業化瓶頸：即使最強大的模型，在真實雜亂檔案庫中的準確率也僅約六成。建議將 AGORA 視為內部 POC 的測試標準，優先選擇結構化程度較高、術語較一致的領域（如財務）切入，並規劃「人機協同」而非「全自動」的產品路線圖，同時預留領域適配的預算與時程。
