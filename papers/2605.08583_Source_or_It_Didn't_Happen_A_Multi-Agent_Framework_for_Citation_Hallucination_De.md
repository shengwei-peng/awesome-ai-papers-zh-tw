## ⚡ TL;DR

解決LLM虛構引用問題，現有偵測器僅給二元判斷，缺乏欄位層級細粒度稽核。
提出CiteTracer多代理框架，採用12碼分類法與四階段級聯偵測流程。

## 摘要翻譯

大型語言模型日益廣泛應用於科學寫作中，然而它們可能虛構看似合理但無法通過書目驗證的引用形式條目。現有的偵測器通常將驗證簡化為二元找到／未找到的判斷，並依賴脆弱的解析或不完整的檢索，難以為稽核者提供欄位層級的訊號。我們將引用幻覺偵測重新框架化為分類法對齊的欄位層級裁決，並提出一套涵蓋真實引用、潛在引用與幻覺引用的 12 碼分類法。基於此分類法，我們建構了 CiteTracer，一個級聯式多代理偵測器，能從 PDF 與 BibTeX 中擷取結構化引用，透過快取查找、URL 擷取、學術搜尋連接器及網路搜尋來檢索證據，套用確定性欄位比對，並將模糊案例路由至類別專家裁決者。我們發布了一個包含 2,450 筆合成引用的基準測試，該基準以真實種子為基礎，透過受控的 LLM 變異所建構，並搭配 957 筆取自 ICLR 2026 及某匿名會議桌面拒稿投稿的真實世界虛構引用。CiteTracer 在合成基準上達到 97.1% 的準確率，真實引用、潛在引用與幻覺引用的類別層級 F1 分數分別為 97.0、95.8 與 98.5，並在真實世界資料集上偵測出 97.1% 的虛構引用，且未進行棄權。程式碼：https://github.com/aaFrostnova/CiteTracer。

### 核心貢獻（3～5點）
- **問題重新框架化**：將引用幻覺偵測從二元真實／偽造判斷，重新定義為「分類法對齊的欄位層級裁決」，使稽核者能取得細粒度的欄位層級診斷訊號，而非僅有粗略的整體標籤。
- **12 碼分類法**：提出一套涵蓋真實引用、潛在引用與幻覺引用三大類別的細粒度分類法，能系統性地區分不同類型的引用錯誤與不確定性。
- **CiteTracer 系統**：建構一個級聯式多代理偵測器，整合引用擷取器、級聯證據收集器、欄位比對器與類別專家裁決者，透過快取查找、URL 擷取、學術搜尋連接器與網路搜尋等多層級證據檢索機制，處理模糊案例。
- **雙軌基準測試**：發布包含 2,450 筆合成引用（基於真實種子並透過受控 LLM 變異生成）與 957 筆真實世界虛構引用（取自 ICLR 2026 及匿名會議桌面拒稿投稿）的綜合性基準，兼顧實驗可控性與實務真實性。
- **優異效能**：在合成基準上達到 97.1% 準確率，三類別 F1 分數均超過 95%；在真實世界資料集上偵測出 97.1% 的虛構引用，且無需棄權，展現強健的實務部署潛力。

### 適合對象
- **LLM 可靠性與幻覺研究人員**：從事大型語言模型事實性、引用完整性與幻覺偵測相關研究的工作者。
- **學術期刊編輯與會議審稿人**：需要自動化工具輔助辨識可疑引用、進行欄位層級稽核的學術出版從業者。
- **學術誠信與科研倫理工作者**：負責調查疑似虛構引用、維護書目完整性的研究倫理委員會成員。
- **NLP 與資訊檢索工程師**：開發科學寫作輔助工具、引用管理系統或學術搜尋引擎的技術實務者。
- **AI 輔助寫作工具開發者**：欲將引用驗證功能整合至寫作輔助產品中的產業界研發團隊。

## 深度分析

#### 方法論解析

CiteTracer 的方法論核心在於將引用幻覺偵測（Citation Hallucination Detection）從傳統的二元判斷（Binary Judgment）重新框架化為「分類法對齊的欄位層級裁決」（Taxonomy-Aligned Field-Level Adjudication），並透過級聯式多代理偵測器（Cascading Multi-Agent Detector）實現此一目標。其方法論可從三個層面深入剖析：

**一、12 碼分類法（12-Code Taxonomy）的設計邏輯**

該分類法將引用劃分為三大類別：真實引用（Real Citation）、潛在引用（Potential Citation）、幻覺引用（Hallucinated Citation），並向下展開為 12 個細粒度代碼。這種設計反映了對「失敗表面」（Failure Surface）的精細化拆解——幻覺引用並非單一現象，而是涵蓋從「真實論文但元資料錯誤」到「完全虛構條目」的連續光譜。潛在引用類別的引入尤為關鍵，它填補了既有系統將「暱稱變體」（Nickname Variant）、「非學術來源」（Non-Academic Source）、「邊緣元資料缺失」（Peripheral Metadata Gap）等模糊案例一律歸為偽造的二元化盲點，使稽核者（Auditor）能依據不同裁決類型採取更正（Correction）、拒絕（Rejection）或標記不確定性（Uncertainty）等差異化處置。

**二、四模組級聯架構的職能分工**

CiteTracer 採用循序執行的四階段管線：

1. **引用擷取器（Reference Extractor）**：針對 PDF 輸入，採用「版面感知」（Layout-Aware）策略，先以邊界框裁切（bounding-box crop）每條引用，再交由視覺型大型語言模型（Vision LLM）重新解析。此設計回應了既有工具在 PDF 解析上的脆弱性——傳統解析器常發生條目遺漏、作者與標題跨欄錯切，甚至自身產生幻覺欄位。對 BibTeX 輸入則直接進行結構化欄位層級記錄（Structured Field-Level Record）的抽取。

2. **級聯證據收集器（Cascading Evidence Collector）**：依序走訪記憶體快取（Memory Cache）、URL 擷取（URL Fetch）、八個學術搜尋連接器（Scholar Connectors）與網路搜尋（Web Search）。此「裁決驅動級聯」（verdict-driven cascade）的設計哲學在於：當快取命中即可終止，避免不必要的 API 呼叫與延遲；當證據不足時才逐步升級至更昂貴的檢索管道，兼顧效率與覆蓋率。

3. **欄位比對器（Field Matcher）**：對擷取記錄與證據進行確定性欄位比對（Deterministic Field Matching），逐欄位比對標題、作者、會議名稱、年份、識別碼（DOI 等）與邊緣元資料。確定性規則的引入降低了對 LLM 判斷的依賴，提升可解釋性與可重現性。

4. **類別專家裁決者（Class-Specialist Judgers）**：僅在確定性規則無法裁決的模糊案例（Ambiguous Case）上啟用，由三個類別專家代理分別針對真實、潛在、幻覺三類進行裁決，最終輸出分類法對齊裁決（Taxonomy-Aligned Verdict），並標註出錯欄位（Offending Field）與理由。

**三、合成基準的建構方法論**

2,450 條合成引用（Synthetic Citation）的建構採用「真實種子」（Real Seed）加上「受控 LLM 變異」（LLM Mutation）的策略：先從異質書目來源抽取真實引用，再以 LLM 對個別欄位進行受控變異，使每條條目皆攜帶已知真實代碼（ground-truth code）。此設計解決了引用幻覺偵測領域長期缺乏標註資料的困境，並支援五種渲染風格的測試，增強泛化性驗證。

#### 實驗數據解讀

CiteTracer 的實驗結果可從三個維度解讀：

**一、合成基準上的整體表現**

在 2,450 條合成引用上，CiteTracer 達到 97.1% 的準確率（Accuracy），類別層級 F1（Class-Level F1）分別為：真實引用 97.0、潛在引用 95.8、幻覺引用 98.5。此結果揭示一個重要現象：幻覺引用的 F1 高於真實引用，意味著系統對「明確虛構」的偵測能力反而最強；潛在引用 F1 最低（95.8），反映此類別的內在模糊性——暱稱變體與邊緣元資料缺失本質上介於真實與虛構之間，裁決難度較高。

**二、真實世界資料集上的召回表現**

在 957 條由 ICLR 2026 與匿名會議桌面拒稿投稿（Desk-Rejected Submission）所提供的真實虛構引用上，CiteTracer 偵測出 97.1% 的虛構案例，且未發生棄權（Abstaining）。此結果的實務意義重大：棄權率為零意味著系統在面對高風險的真實審稿場景時，不會以「無法判斷」規避責任，這對會議程式委員會（Program Committee）的決策至關重要。

**三、跨輸入格式的穩健性**

實驗涵蓋 PDF 與 BibTeX 兩種輸入格式，並與五個先進基線比較：GPT-5.5 Thinking、Claude 4.7 Opus Adaptive Thinking、Gemini 3.1 Pro、GPTZero、Hallucinator。CiteTracer 在兩種輸入下皆超越所有基線於各類別的表現，證實其多代理架構對輸入格式變異具有韌性。

然而，需注意以下數據解讀上的限制：(1) 合成基準的「受控變異」雖保證標註品質，但可能無法完全反映真實 LLM 產生幻覺引用的分布；(2) 97.1% 的真實世界召回率雖高，但剩餘 2.9% 的漏報在會議審稿規模化情境下仍可能造成實質傷害；(3) 報告未提供精確率（Precision）數據，若系統將真實引用誤判為虛構，可能導致無辜作者被誤拒。

#### 與現有研究的比較

CiteTracer 相較於既有引用稽核工具（Citation Auditor）的定位可從三個軸線分析：

**一、從二元到多元的典範轉移**

既有商業稽核工具如 Citely、SwanRef、CiteCheck、RefCheck-AI，以及學術稽核系統 CiteAudit，皆僅輸出二元真實/偽造標籤（Binary Real-or-Fake Label）。此設計的問題在於：當稽核者收到「偽造」標籤時，仍須自行診斷哪個欄位出錯，徒增工作量。CiteTracer 的欄位層級稽核（Field-Level Audit）與分類法對齊裁決直接輸出出錯欄位與理由，將診斷工作自動化，這是質的躍進而非量的提升。

**二、從標題作者中心到全欄位覆蓋**

開放工具 Hallucinator 雖查詢超過十個書目資料庫（Bibliographic Database），卻僅以標題與作者作為裁決依據，忽略會議名稱、年份、DOI、頁碼、出版者等欄位。GPTZero 的幻覺模式雖交叉查驗外部來源，卻僅稽核五個欄位（標題、作者、日期、URL、出版者）且需付費訂閱。CiteTracer 覆蓋所有核心書目欄位，且以開放原始碼釋出，在覆蓋面與可及性上皆具優勢。

**三、從單一代理到級聯多代理的架構演進**

既有系統多採單一 LLM 代理或平行 API 查詢，缺乏對「證據強度」的層級化處理。CiteTracer 的級聯架構先以確定性規則處理明確案例，僅將模糊案例路由至類別專家裁決者，此設計在運算成本與準確率間取得較佳平衡。

**四、限制與未竟之處**

儘管 CiteTracer 表現優異，仍存在以下限制：(1) 對非英語引用的支援未明確說明，跨語言書目驗證仍是開放問題；(2) 視覺 LLM 的引用擷取雖優於傳統解析器，但仍可能產生自身幻覺；(3) 系統對「真實但被惡意竄改」的引用（如作者自刪除的預印本）可能誤判；(4) 與既有工具的比較未涵蓋所有場景，例如未說明在極長參考文獻清單（如 200+ 條）下的吞吐量表現。

#### 可重現性評估

CiteTracer 在可重現性方面展現了明確的承諾，但仍有若干待釐清之處：

**一、程式碼與資料的開放性**

作者於 GitHub 公開程式碼（https://github.com/aaFrostnova/CiteTracer），並釋出 2,450 條合成基準與 957 條真實世界虛構引用資料集。此雙重釋出對領域發展至關重要——既有引用幻覺偵測研究常因缺乏標註資料而難以比較，CiteTracer 提供了可重複實驗的基礎設施。

**二、模型權重與 API 依賴**

需注意的潛在可重現性障礙包括：(1) 系統依賴多個外部書目 API（八個學術搜尋連接器），這些 API 的可用性、費率政策與回傳格式可能隨時間變動，影響長期可重現性；(2) 視覺 LLM 的選擇未明確指定，若使用閉源模型（如 GPT-5.5、Claude 4.7），則無法保證結果完全可重現；(3) 類別專家裁決者的提示工程（prompt engineering）細節若未充分公開，可能影響結果穩定性。

**三、評估指標的完整性**

報告提供了準確率與類別層級 F1，但未提供精確率-召回率曲線（Precision-Recall Curve）、混淆矩陣（Confusion Matrix）或各 12 碼分類法代碼的細粒度表現。若能釋出這些細節，將有助於後續研究針對特定失敗模式進行改進。

**四、與會議政策的整合**

ICLR 2026、ICML 2026、ACM CCS 2026 等會議已將引用幻覺偵測納入審稿流程，CiteTracer 若能提供標準化介面（如 OpenReview 整合），將有助於從研究原型走向實務部署。

#### 未來研究方向

CiteTracer 開啟了多條值得探索的研究路徑：

**一、跨語言與跨文化書目驗證**

當前系統主要針對英語學術出版品，未來可擴展至中文、日文、阿拉伯文等非英語引用，並處理各語言特有的會議名稱變體、作者姓名翻譯規則（如漢字姓名拼音化）等挑戰。此方向對全球南方（Global South）學術社群尤為重要。

**二、引用意圖層級的幻覺偵測**

CiteTracer 聚焦於書目完整性（Bibliographic Integrity），即「引用是否存在」。下一階段可探索「引用是否支撐其聲明」的語意層級驗證——即使引用真實，仍可能因斷章取義或張冠李戴而構成不誠實引用。此問題需要結合論文本體與引用內容的語意比對。

**三、對抗性攻擊與防禦**

隨著引用幻覺偵測工具的部署，惡意使用者可能設計對抗樣本（adversarial examples）以規避偵測，例如刻意選擇難以驗證的邊緣來源或操縱欄位順序。未來研究可探討 CiteTracer 對此類攻擊的韌性，並發展對抗訓練機制。

**四、即時性與規模化部署**

會議審稿週期緊湊，未來可研究 CiteTracer 在批次處理數千篇投稿時的吞吐量最佳化，例如透過快取預熱、平行化證據收集與增量式驗證等技術，將單篇引用驗證時間從秒級降至毫秒級。

**五、與引用圖譜（Citation Graph）的整合**

單一引用的驗證可進一步擴展至引用圖譜層級：若一篇論文的參考文獻清單中多數引用皆指向同一可疑來源叢集，或引用網絡呈現異常結構（如循環引用、星形結構），可能暗示系統性虛構。結合圖神經網絡（Graph Neural Network）與書目驗證將是值得探索的方向。

**六、倫理與治理框架**

引用幻覺偵測工具的部署涉及誤判風險——若系統將真實引用誤判為虛構，可能對無辜作者造成聲譽損害。未來研究應發展人機協作（Human-in-the-Loop）機制、申訴流程與不確定性量化（Uncertainty Quantification）方法，確保自動化裁決的公平性與可問責性。

**七、領域特化模型**

不同學科領域的引用慣例差異顯著（如計算機科學偏好會議，生物醫學偏好期刊）。未來可發展領域特化的引用驗證模型，內建各領域的書目慣例知識，提升跨領域泛化能力。

## 論文問答

**Q1：什麼是「引用幻覺」，為什麼它在學術寫作中是一個特別嚴重的問題？**
A：引用幻覺指的是大型語言模型生成的引用形式條目（citation-shaped entry），雖然在表面上具備標題、作者、會議、年份、DOI 等欄位的形式，但其中部分或全部欄位無法通過書目驗證（bibliographic verification），可能對應到不存在的出版物、欄位錯置的真實論文，或是真實與虛構欄位混雜的條目。它之所以特別嚴重，是因為引用屬於高風險事實聲明（high-stakes factual claim），其欄位必須外部可驗證（externally verifiable），但 LLM 卻極度流暢地產出「看起來合理」的參考文獻，使錯誤難以被肉眼察覺。一旦幻覺引用進入正式發表或被搜尋引擎收錄，就會剝奪原作者應得的學術信用、破壞可重現性（reproducibility），並讓錯誤的書目資料在學術生態系中持續傳播與放大。

**Q2：現有的引用稽核工具（citation auditor）為何無法有效解決這個問題？**
A：現有工具普遍將驗證簡化為二元真實/偽造標籤（binary Real-or-Fake label），無論是商業工具如 Citely、SwanRef、CiteCheck、RefCheck-AI，或是學術工具如 CiteAudit，都只輸出一個 yes/no 訊號，無法告訴稽核者「哪個欄位錯了」與「為什麼錯」，迫使稽核者必須自行重做診斷工作。更關鍵的是，這些工具對「中間地帶」的處理過於粗糙——暱稱變體（nickname variant）、非學術來源（non-academic source）、邊緣元資料缺失（peripheral metadata gap）等情況都被壓縮成同一個二元訊號。此外，PDF 解析階段本身就很脆弱，現有工具的 reference parser 會掉條目、誤切作者與標題的範圍，甚至自己產生幻覺欄位，讓驗證器在輸入端就繼承了損壞的資料。

**Q3：為什麼這個問題在 2025–2026 年變得格外迫切？**
A：這個問題已經從研究好奇心升級為部署層級的營運議題：NeurIPS 2025 的主席記錄了投稿中普遍存在的虛構引用，ICLR 2026 累積了超過 600 篇因引用問題被桌面拒稿（desk-reject queue）的投稿，ACM CCS 2026 也發布了透明報告，列舉出審稿週期中標記為 AI 虛構的引用。這意味著引用幻覺不再是個案，而是會議層級必須處理的系統性風險。隨著 LLM 深度嵌入研究工作流程（從構思、潤稿到草擬投稿），引用幻覺的發生率與規模都急劇上升，使得發展可審計、可解釋的欄位層級偵測框架成為學術通訊基礎設施的當務之急。

**Q4：CiteTracer 的核心方法架構是什麼？它如何運作？**
A：CiteTracer 是一個四階段的級聯式多代理偵測器（cascading multi-agent detector），依序執行：(1) 引用擷取器（Reference Extractor）將每個引用區塊（citation block）解析為結構化欄位層級記錄（structured field-level record），對於 PDF 輸入會先用版面感知的視覺 LLM 從 bounding-box 裁切重新解析；(2) 級聯證據收集器（Cascading Evidence Collector）依序走訪記憶體快取、URL 擷取、八個學術搜尋連接器（Scholar Connector）與網路搜尋；(3) 欄位比對器（Field Matcher）以確定性規則（deterministic field matching）逐欄位比對記錄與證據；(4) 類別專家裁決者（Class-Specialist Judger）接手模糊案例（ambiguous case），輸出分類法對齊裁決（taxonomy-aligned verdict），標記出錯欄位（offending field）與理由。這種「先規則、後裁決」的設計讓簡單案例快速通過、困難案例才動用昂貴的 LLM 推理。

**Q5：12 碼分類法的創新價值在哪裡？為什麼需要這麼細的分類？**
A：12 碼分類法將引用狀態劃分為三大類——真實引用（Real）、潛在引用（Potential）、幻覺引用（Hallucinated）——並在每個類別下細分具體的欄位層級失敗模式，例如標題錯誤、作者不存在、會議不對應、年份不符、DOI 無效等。這樣的細粒度分類法（fine-grained taxonomy）讓稽核者能依據不同錯誤類型採取不同處置：更正（correction）、拒絕（rejection）、或不確定性（uncertainty），而非被迫接受單一二元判斷。更重要的是，每個分類碼都對應到具體的欄位證據需求，使下游的證據檢索與欄位比對可以針對性地進行，這是過去二元標籤系統無法支援的稽核粒度。

**Q6：CiteTracer 在設計上做了哪些關鍵的權衡？**
A：最關鍵的權衡是「確定性規則 vs. LLM 推理」的成本分配：作者選擇讓欄位比對器先用確定性規則處理明確案例，僅將模糊案例路由到類別專家裁決者，這大幅降低了對昂貴 LLM 推理的依賴，同時保留了對邊緣案例的判斷力。另一個權衡是「檢索廣度 vs. 延遲」：級聯證據收集器依序走訪快取、URL、八個學術搜尋連接器與網路搜尋，而非平行查詢所有來源，這在維持高召回率的同時控制了平均延遲。此外，PDF 與 BibTeX 雙輸入支援也是一個設計選擇——透過引用擷取器統一輸出結構化記錄，使下游驗證流程對輸入格式無感，提升了系統在真實工作流程中的實用性。

**Q7：CiteTracer 釋出的基準測試是如何建構的？為什麼這樣設計？**
A：基準測試包含 2,450 條合成引用（synthetic citation）與 957 條真實世界虛構引用（real-world fabricated citation）。合成部分採用「真實種子 + 受控 LLM 變異」的策略：先從異質書目來源抽取真實引用作為種子，再以 LLM 對特定欄位施加受控變異，使每筆條目都帶有已知的 ground-truth 分類碼，這解決了過去引用偵測任務缺乏可靠標註的問題。真實世界部分則直接取自 ICLR 2026 桌面拒稿佇列與一個匿名會議的拒稿投稿，代表了會議主席實際標記為虛構的案例。這種「合成 + 真實」雙軌設計兼顧了評估的可控性與部署的真實性，並涵蓋五種引用渲染風格，使基準測試更具代表性。

**Q8：CiteTracer 的主要實驗結果為何？它在哪些基準上超越了現有方法？**
A：在 2,450 條合成基準上，CiteTracer 達到 97.1% 的整體準確率（accuracy），類別層級 F1（class-level F1）分別為真實引用 97.0、潛在引用 95.8、幻覺引用 98.5；在 957 條真實世界虛構引用上，它檢出 97.1% 的虛構案例且未發生棄權（abstaining）。在與五個先進基準的比較中——GPT-5.5 Thinking、Claude 4.7 Opus Adaptive Thinking、Gemini 3.1 Pro、GPTZero、Hallucinator——CiteTracer 在 PDF 與 BibTeX 兩種輸入下都於每個類別上勝出。值得注意的是，潛在引用類別的 F1（95.8）低於其他兩類，反映出「中間地帶」確實是分類上最具挑戰性的區段，這也驗證了引入此類別的必要性。

**Q9：CiteTracer 的各模組對最終效能的貢獻如何？有哪些消融研究上的洞見？**
A：雖然全文未完整列出消融數據，但從架構設計可推論出關鍵洞見：移除引用擷取器的版面感知視覺 LLM 重新解析，PDF 輸入的效能會顯著下降，因為傳統 parser 會在輸入端就引入錯誤；移除級聯證據收集器中的任一層（快取、URL、學術搜尋連接器、網路搜尋）都會降低召回率，特別是對於冷門或新近發表的論文；將所有案例都丟給 LLM 裁決而不先用確定性規則過濾，會犧牲成本效益且可能因 LLM 幻覺而降低精確度；只使用單一通用裁決者而非三個類別專家，則會在潛在引用類別上損失最多效能，因為該類別需要同時理解「真實但有瑕疵」與「虛構但看似合理」的細微差異。

**Q10：CiteTracer 在實際學術工作流程中可以如何被部署使用？**
A：在會議審稿階段，程式委員會可以將 CiteTracer 整合進投稿系統，自動掃描所有投稿的參考文獻，對每條引用輸出分類法對齊裁決與出錯欄位，讓領域主席與審稿人能在短時間內聚焦於高風險案例。在期刊編輯流程中，編輯部可將其作為初篩工具，標記需要作者更正或解釋的引用，降低編輯工作量。在個人學術寫作階段，作者可在投稿前用 CiteTracer 自查，特別是當他們使用 LLM 輔助撰寫文獻回顧時，能即時發現幻覺引用並替換為真實來源。此外，圖書館員與學術誠信辦公室也可將其用於回溯性稽核，清理已被搜尋引擎收錄的虛構條目。

**Q11：將 CiteTracer 產品化時需要考量哪些工程與商業因素？**
A：工程上，級聯證據收集器對多個書目 API 的並行呼叫需要處理速率限制、API 金鑰管理與失敗重試，並設計去重與快取策略以控制外部 API 成本；視覺 LLM 重新解析 PDF 引用區塊會帶來可觀的推理成本與延遲，需要評估是否對所有引用都執行或僅針對 parser 信心不足的條目。商業上，GPTZero 將完整功能放在付費訂閱後的策略顯示出此類工具有明確的付費意願，特別是會議、期刊與大學學術誠信辦公室；產品定位需區隔「全自動稽核」與「人工複審輔助」兩種模式，後者可能更符合學術界對可解釋性的要求。此外，必須設計明確的棄權政策（abstention policy），對於無法驗證的引用應誠實標示為不確定，而非強行給出二元判斷。

**Q12：CiteTracer 對學術界與 AI 安全研究的更廣泛影響是什麼？**
A：對學術界而言，CiteTracer 提供了一個可審計的基礎設施，讓引用完整性（citation integrity）從「靠作者自律」轉變為「可工具化檢驗」，這對於正在經歷 LLM 大量產出內容衝擊的學術通訊系統至關重要，也回應了 ICLR、ICML、ACM CCS 等頂級會議 2026 週期新政策的實際需求。對 AI 安全研究而言，它示範了一個「分類法對齊的欄位層級裁決」（taxonomy-aligned field-level adjudication）範式——將幻覺偵測從二元分類提升為結構化、可解釋、可行動的診斷，這個思路可延伸到其他高風險事實聲明領域，如法律引用、醫療證據、新聞事實查核等。

**Q13：CiteTracer 已承認的限制有哪些？**
A：系統效能高度依賴外部書目 API 的可用性與覆蓋率，對於非英語論文、極冷門出版物、或新近發表尚未被索引的論文，級聯證據收集器可能無法取得足夠證據，導致棄權或誤判。視覺 LLM 重新解析 PDF 雖然比傳統 parser 更強健，但仍受限於 LLM 本身的幻覺傾向，特別是在處理複雜多欄排版、數學符號或非拉丁字符時可能引入新的錯誤。此外，潛在引用類別的 F1（95.8）低於其他兩類，顯示「中間地帶」的判定仍是難題；系統也未明確處理引用上下文（citation context）的真實性，即引用是否真的支持文中聲明，這屬於語義層級的問題而非書目層級。

**Q14：CiteTracer 在哪些情境下可能會失敗？**
A：在書目資料庫覆蓋不足的情境下會失敗，例如非英語期刊、區域性研討會、灰色文獻（gray literature）、或剛上線尚未被 Google Scholar 收錄的預印本。在 PDF 排版極度複雜或低品質掃描的情境下，引用擷取器的視覺 LLM 可能誤切欄位，繼而讓下游驗證基於錯誤輸入。對於刻意構造的對抗性引用——例如故意模仿真實論文的標題但作者為虛構——若書目 API 無法返回精確匹配，系統可能誤判為真實。此外，當引用涉及作者更名、機構重組、會議改名等歷史變遷時，確定性欄位比對規則可能過於嚴格而將真實引用誤標為潛在或幻覺。

**Q15：基於 CiteTracer 的工作，未來有哪些值得探索的研究方向？**
A：未來可朝幾個方向延伸：(1) 從書目層級擴展到語義層級，偵測引用是否真的支持文中聲明（citation context verification），這需要結合引用上下文與被引論文的內容比對；(2) 將 12 碼分類法擴展為更細粒度或跨語言版本，覆蓋非英語學術圈的引用模式；(3) 引入主動學習與人類回饋循環，讓類別專家裁決者能從稽核者的修正中持續改進；(4) 探索對抗魯棒性，研究如何防禦刻意繞過偵測的構造性幻覺引用；(5) 將此「分類法對齊的欄位層級裁決」範式推廣到其他高風險事實領域，如法律判決引用、醫學證據等級、新聞引用查核等，建構通用的可審計事實查核基礎設施。

## 實務應用指南

### 適用場景

1. **會議與期刊投稿審稿系統**：將 CiteTracer 嵌入 ICLR、ICML、ACM CCS 等大型會議的投稿系統，在 desk-reject 階段自動掃描參考文獻區塊。審稿主席可在 600+ 投稿的佇列中快速定位含有虛構引用的稿件，減少人工核對書目 API 的時間成本，並輸出欄位層級的裁決供審稿決定引用。

2. **學術寫作輔助工具的內建稽核層**：整合至 Overleaf、Zotero、Notion AI 等寫作工具中，當使用者透過 LLM 草擬段落並插入引用時，即時觸發 Reference Extractor 解析 PDF/BibTeX，於寫作當下回饋「此引用為真實/潛在/幻覺」標籤與出錯欄位，避免幻覺引用進入最終稿件。

3. **大學與研究機構的研究誠信辦公室**：作為機構內部的研究誠信稽核工具，掃描已發表或投稿中的論文，特別針對研究生與博士後的稿件進行批次檢查。透過 12 碼分類法對應到機構的處置流程（更正、撤稿、警示），讓研究誠信委員會能依據出錯欄位與嚴重程度分流處理。

4. **出版社與預印本平台的自動化品管**：arXiv、bioRxiv 等預印本平台可在每日新上架稿件中批次執行 CiteTracer，針對高風險欄位（標題、作者、會議名稱、年份）進行級聯證據收集，並對模糊案例路由至類別專家裁決者，協助平台維護書目完整性。

5. **企業研發部門的技術報告與專利引用驗證**：在企業撰寫技術白皮書、專利說明書或內部技術報告時，自動驗證引用之學術文獻是否真實存在，避免引用不存在或被竄改的文獻影響企業聲譽或專利有效性。

### 實作前置條件

**資料需求**
- 至少數千筆已標註的真實引用作為訓練與驗證基準（建議從 Semantic Scholar、OpenAlex、CrossRef 等開放書目 API 收集）
- 涵蓋五種以上渲染風格的 PDF 引用區塊樣本（單欄、雙欄、IEEE、ACM、Nature 等格式）
- 來自真實會議的虛構引用樣本（如 ICLR 2026 桌面拒稿投稿資料集）作為壓力測試集
- 領域專家標註的欄位層級裁決資料，用於微調類別專家裁決者

**計算資源**
- 視覺 LLM（如 GPT-5.5、Claude 4.7 Opus）API 存取權，用於 Reference Extractor 的版面感知解析
- 多個書目 API 的 API key 或本地部署版本（Semantic Scholar、CrossRef、OpenAlex、DBLP、PubMed、arXiv、Google Scholar 等至少 8 個學術搜尋連接器）
- 網路搜尋 API（如 SerpAPI、Bing Search API）作為最後一層證據檢索
- 充足的 LLM 推理算力（建議使用 A100/H100 等級 GPU 或對應的雲端 API 額度），因為類別專家裁決者需要對模糊案例進行推理
- 向量資料庫（如 Pinecone、Weaviate、Qdrant）用於記憶體快取的語意比對

**技能需求**
- Python 後端開發能力，熟悉 FastAPI 或 Flask 等框架
- 多代理框架使用經驗（如 LangGraph、AutoGen、CrewAI）
- PDF 解析與版面分析（PyMuPDF、pdfplumber、LayoutLM）
- 書目格式處理（BibTeX parser、CSL processor）
- 提示工程（prompt engineering）能力，特別是針對類別專家裁決者的設計
- 評估指標設計經驗（混淆矩陣、類別層級 F1、棄權率分析）

### 實作步驟建議

**階段一：基準建構（2-4 週）**
1. 從 Semantic Scholar、OpenAlex 等開放資料源收集真實引用作為真實種子
2. 設計 12 碼分類法的標註規範文件，邀請領域專家對 500-1000 筆樣本進行標註，建立黃金標準
3. 實作 LLM 變異管線，針對每個欄位（標題、作者、會議、年份、DOI、頁碼、出版商）設計可控的變異操作，生成 2,450 筆合成引用
4. 收集真實世界的虛構引用（如 ICLR 2026 桌面拒稿投稿），建立 957 筆的真實世界資料集

**階段二：核心模組開發（4-6 週）**
5. 實作 Reference Extractor：先以規則式解析器處理 BibTeX 輸入，再以視覺 LLM 處理 PDF 輸入，採用 bounding-box crop + VLM 的版面感知策略
6. 建構級聯證據收集器：依序串接記憶體快取 → URL 擷取 → 8 個學術搜尋連接器 → 網路搜尋，每一層設定終止條件
7. 實作確定性欄位比對器：設計欄位層級的規則（如標題相似度閾值、作者姓氏比對、DOI 精確匹配）
8. 設計三個類別專家裁決者（REAL、POTENTIAL、HALLUCINATED），每個裁決者針對其類別的特性設計專屬提示詞

**階段三：整合與評估（2-3 週）**
9. 將四個模組串接為完整的 CiteTracer 流程，設計模組間的介面契約（結構化欄位層級記錄）
10. 在合成基準上評估，目標達到 97.1% 準確率與類別層級 F1（REAL 97.0、POTENTIAL 95.8、HALLUCINATED 98.5）
11. 在真實世界資料集上評估虛構引用召回率，目標達到 97.1% 且不棄權
12. 與五個基線（GPT-5.5 Thinking、Claude 4.7 Opus、Gemini 3.1 Pro、GPTZero、Hallucinator）進行比較

**階段四：產品化（3-4 週）**
13. 將系統封裝為 REST API 或 CLI 工具，支援 PDF 與 BibTeX 雙輸入
14. 設計裁決結果的視覺化介面，清楚標示出錯欄位與裁決理由
15. 實作批次處理與快取機制，降低重複引用的 API 呼叫成本
16. 建立監控儀表板，追蹤各類別裁決分佈、棄權率、API 呼叫延遲

### 潛在風險與注意事項

**風險一：視覺 LLM 自身的幻覺問題**
Reference Extractor 使用視覺 LLM 解析 PDF 引用區塊時，VLM 本身可能產生幻覺欄位（例如將作者姓名誤判為標題）。緩解策略：對 VLM 輸出進行信心度閾值過濾，並與規則式解析器的結果進行交叉驗證；對低信心度案例路由至類別專家裁決者。

**風險二：書目 API 的覆蓋偏差**
不同學術搜尋連接器對不同領域的覆蓋率差異極大（例如 DBLP 偏重電腦科學、PubMed 偏重生醫）。緩解策略：採用平行查詢多個連接器並取聯集；對查無結果的引用不要直接判定為虛構，而應進入下一層級（網路搜尋）或標記為潛在引用。

**風險三：POTENTIAL 類別的標註模糊性**
暱稱變體（如「NeurIPS」vs.「Neural Information Processing Systems」）、非學術來源、邊緣元資料缺失等情況在標註者間容易產生分歧。緩解策略：建立詳細的標註規範文件並計算標註者間一致性（IAA）；對低一致性案例進行裁決會議討論。

**風險四：API 成本與延遲**
完整流程涉及多次 LLM 推理與多個書目 API 呼叫，單筆引用處理成本可能偏高。緩解策略：設計強健的記憶體快取層；對高信心度的確定性比對結果跳過類別專家裁決者；採用小型模型處理簡單案例、大型模型僅處理模糊案例的階層式推理策略。

**風險五：對抗性攻擊與迴避**
惡意使用者可能刻意構造「看起來像真實引用」的條目來繞過偵測。緩解策略：定期更新訓練資料以納入新型態的虛構模式；對引用進行多欄位交叉一致性檢查（例如作者所屬機構與會議領域是否吻合）。

**風險六：隱私與資料合規**
處理未發表的投稿稿件時，可能涉及敏感的學術內容。緩解策略：採用本地部署版本的 LLM 與書目 API；建立資料保留政策，審查完成後自動刪除原始 PDF；遵循機構的 IRB 與資料治理規範。

### 與其他技術的整合建議

**與書目管理工具整合**：與 Zotero、Mendeley、EndNote 等書目管理工具建立外掛介面，當使用者從這些工具匯出引用時自動觸發 CiteTracer 驗證。可透過 Zotero 的 translator API 或 Mendeley 的 SDK 實作。

**與學術搜尋引擎整合**：與 Semantic Scholar、OpenAlex、CrossRef 等書目資料庫建立雙向連結。當 CiteTracer 偵測到潛在引用時，可將該引用提交至這些資料庫的審核流程，協助資料庫維護品質。

**與寫作輔助 LLM 整合**：將 CiteTracer 作為 LLM 寫作工具（如 ChatGPT、Claude、Notion AI）的「引用守門員」。在 LLM 生成引用時即時呼叫 CiteTracer 進行驗證，並將裁決結果回傳給 LLM 進行修正，形成自我修正的迴圈。

**與會議審稿系統整合**：與 OpenReview、CMT、EasyChair 等審稿系統整合，在投稿階段自動執行 CiteTracer，並將裁決結果附加至投稿的 metadata 中，供審稿人與主席參考。

**與研究誠信平台整合**：與 Retraction Watch、PubPeer 等研究誠信平台建立資料共享機制。當 CiteTracer 在某篇論文中偵測到虛構引用時，可將該資訊匿名化後提交至這些平台，協助建立跨機構的虛構引用資料庫。

**與企業知識管理整合**：與 Confluence、Notion、SharePoint 等企業知識管理系統整合，在技術報告、白皮書發布前自動驗證引用，提升企業文件的可信度。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節的「問題描述」部分，理解為何引用幻覺是一個獨立且重要的問題類型（不同於一般的事實幻覺），以及為何二元真實/偽造標籤不足以應對實務需求。接著閱讀圖 1 的系統總覽，建立 CiteTracer 四階段流程（擷取 → 收集 → 比對 → 裁決）的整體印象。技術細節可先跳過，專注於理解「為什麼需要欄位層級的裁決」這個核心論點。

**給 AI 工程師**：建議從第 1 節的「現有偵測器的兩個缺口」切入，理解 CiteTracer 解決的工程問題（PDF 解析損壞、書目 API 覆蓋不足、二元標籤的資訊損失）。接著仔細閱讀圖 1 與方法章節，特別關注四個模組的介面契約、級聯證據收集器的終止條件設計、確定性規則與類別專家裁決者之間的路由邏輯。建議直接閱讀 GitHub 程式碼（https://github.com/aaFrostnova/CiteTracer），從 Reference Extractor 的版面感知策略開始，理解 bounding-box crop + VLM 的實作細節。

**給研究者**：建議從第 2 節的相關工作開始，建立引用幻覺偵測的研究地圖。接著仔細閱讀 12 碼分類法的設計邏輯，理解為何需要區分 REAL、POTENTIAL、HALLUCINATED 三個類別，以及每個類別下的欄位層級失敗模式。實驗章節是重點，建議仔細分析混淆矩陣與各類別的錯誤案例，理解 CiteTracer 在哪些情境下會失效。基準建構方法（真實種子 + 可控 LLM 變異）是值得參考的研究方法論，可應用於其他領域的幻覺偵測研究。

**給產品經理**：建議先閱讀摘要與第 1 節，理解引用幻覺偵測的市場需求（ICLR 2026 已有 600+ 桌面拒稿投稿、ICML 與 ACM CCS 2026 也有相關政策）。接著閱讀「適用場景」與「實作步驟建議」，評估將 CiteTracer 整合至自家產品的可行性與投資報酬率。特別關注「潛在風險與注意事項」中的 API 成本與延遲問題，這會直接影響產品的定價與使用者體驗。建議與工程團隊討論「階段一：基準建構」的資料需求，評估是否能取得足夠的真實引用與虛構引用樣本。
