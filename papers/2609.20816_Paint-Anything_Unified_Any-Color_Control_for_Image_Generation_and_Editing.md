## 摘要翻譯

專業設計需要任意顏色控制（Any-Color Control）：一種能夠針對影像生成（Image Generation）與影像編輯（Image Editing），以任意 24 位元十六進位值（24-bit hex value）指定物件目標顏色的能力。先前研究已探索顏色生成（Color Generation）、顏色編輯與著色（Colorization），但通常仰賴專用的顏色表示法（Color Representations）或專門推論程序（Specialized Inference Procedures）。大型語言模型（Large Language Models）的進展提供了一個更簡單的起點：即使是緊湊型模型也能將十六進位值（Hex Values）與顏色語義（Color Semantics）建立關聯。我們提出 Paint-Anything，透過物件層級顏色監督（Object-Level Color Supervision），學習一個用於生成與編輯的共享十六進位提示介面（Shared Hex-Prompt Interface）。我們開發了一個資料管線（Data Pipeline），透過物件定位（Object Grounding）、感知式顏色標註（Perceptual Color Labeling）與編輯配對合成（Editing-Pair Synthesis），從真實影像（Real Images）建構 Paint-500K。由於陰影（Shadows）使得真實影像標籤僅為近似顏色（Approximate Colors），我們以純色錨點（Pure-Color Anchors）來補充此監督，其像素與配對的十六進位值（Paired Hex Values）完全匹配。這些錨點僅於高雜訊時間步（High-Noise Timesteps）使用，低雜訊訓練（Low-Noise Training）則保留給真實影像。我們進一步提出 Any Color 基準測試（Any Color Benchmark, ACBench），包含 ACBench-T2I 與 ACBench-Edit，以衡量兩項任務中的物件層級十六進位顏色保真度（Object-Level Hex Color Fidelity）。在 FLUX.2-4B 上，Paint-Anything 相較於基礎模型（Base Model）分別將 ACBench-T2I 與 ACBench-Edit 分數提升 85.3% 與 28.3%，消融實驗（Ablations）亦驗證了此訓練配方（Training Recipe）的有效性。Paint-Anything 在比較方法（Compared Methods）中亦達到最高的平均 CompColor 分數（CompColor Score）。

### 核心貢獻（3～5點）
- 提出統一任意顏色控制方法 Paint-Anything，透過共享十六進位提示介面（Shared Hex-Prompt Interface）同時支援影像生成與影像編輯，無需任務專屬模組（Task-Specific Modules）。
- 開發 Paint-500K 資料管線，結合物件定位、感知式顏色標註與編輯配對合成，從真實影像建構大規模訓練資料。
- 設計純色錨點策略，於高雜訊時間步提供精確顏色監督，並保留低雜訊訓練給真實影像，以兼顧顏色精確度與自然影像品質。
- 建立 Any Color 基準測試（ACBench），包含 ACBench-T2I 與 ACBench-Edit 兩個子集，以物件層級十六進位顏色保真度評測生成與編輯方法。
- 在 FLUX.2-4B 上顯著提升顏色保真度分數，並透過消融實驗驗證訓練配方之有效性，同時在比較方法中取得最高平均 CompColor 分數。

### 適合對象
本論文最適合電腦視覺與生成式 AI 研究者、擴散模型（Diffusion Models）條件控制相關開發者，以及從事影像編輯、設計工具與顏色精確生成應用之實務工作者閱讀。對於關注文字轉影像（Text-to-Image, T2I）遵循提示能力（Prompt-Following Capability）、物件重新上色（Object Recoloring）與大規模視覺資料管線建構之讀者亦具高度參考價值。

## 深度分析

#### 方法論解析

##### 1. 核心設計哲學：以 Hex 字串作為原生提示介面

Paint-Anything（統一任意顏色控制方法）的核心假設是：現代大型語言模型（Large Language Models, LLMs）已經能將原始十六進位色碼（raw hex code）對應到合理的顏色語義（color semantics）。作者以 Qwen3-4B 進行探針實驗，發現即使只有 4B 參數的緊湊模型，也能解讀 `#F0FFF1`、`#E8D00A` 等 hex 字串並產生可理解的顏色描述。這意味著不需要額外的顏色編碼器或專門的數值嵌入層，hex code 可以直接作為文字提示（text prompt）的一部分被文字編碼器（text encoder）處理。

具體實作上，hex code 會被包裝在 `<color></color>` 標籤中，並與物件詞組（object phrase）綁定，例如：

> A `<color>#A7C7E7</color>` bed, lit by two warm bedside lamps...

這種共享十六進位提示介面（shared hex-prompt interface）讓單一微調模型（single finetuned model）同時支援：
- 十六進位條件生成（hex-conditioned generation）：從頭生成符合指定顏色的影像；
- 物件重新上色（object recoloring）：根據編輯指令與條件影像修改特定物件顏色。

相較於過去需要學習式顏色權杖（learned color tokens）、數值顏色嵌入或邊界框（bounding box）布局的方法，Paint-Anything 將顏色規格（color specification）完全保留在提示空間內，降低了對模型架構的侵入性。

##### 2. Paint-500K 資料流程：從真實影像建立物件層級監督

為了讓模型學會將 hex code 與影像中物件的真實顏色對應，作者設計了一條自動化資料流程（data pipeline），從真實影像（real images）建構出 Paint-500K 資料集。流程包含三個主要步驟：

1. **物件定位（object grounding）**：使用視覺語言模型（Vision-Language Model, VLM）辨識與圖說相關的物件。
2. **分割遮罩（segmentation masks）**：將物件像素隔離，以便後續估計顏色。
3. **感知式顏色標註（perceptual color labeling）**：在 CIELAB 色彩空間中進行 MeanShift 聚類，估計物件在自然光照下的主導顏色。

由於真實影像中存在陰影（shadows）、反射與材質紋理，這些標籤只能視為近似顏色（approximate colors），而非像素級的精確 hex 值。這是資料流程的根本限制，也是作者引入純色錨點（pure-color anchors）的原因。

此外，資料流程還包含編輯配對合成（editing-pair synthesis），用於產生成對的編輯前後影像，使模型能同時學習影像生成與影像編輯（image editing）任務。

##### 3. 訓練架構與時間步閘控的純色錨點

根據圖 3 的訓練架構描述，Paint-Anything 基於 flow-matching objective（流匹配目標）訓練去噪 Transformer（denoising transformer）：

- **文字編碼器**：將包含 `<color>#AABBCC</color>` 的文字提示編碼為文字權杖（text tokens）。
- **VAE（變分自編碼器）**：將目標影像編碼為潛在表示。
- **去噪 Transformer**：在擴散時間步（diffusion timesteps）上進行訓練。
- **條件影像（condition image）**：對於編輯任務，編輯前的影像以乾淨潛在編碼的形式在 `t=0` 提供給模型。

為了解決真實影像標籤僅為近似顏色的問題，作者引入純色錨點（pure-color anchors）：每個樣本將一個 hex code 與一張純色目標影像配對，且像素完全匹配其配對的十六進位值（paired hex values）。關鍵在於這些錨點並非在所有時間步都使用，而是僅在高雜訊時間步（high-noise timesteps）`t ∈ [t_gate, 1]` 啟用；相對地，真實世界目標影像（real-world targets）則在整個時間範圍 `t ∈ (0, 1)` 取樣。

這種時間步閘控（timestep gating）的設計具有明確的物理意義：

- **高雜訊區間**：影像結構尚未成形，模型主要學習低階統計與顏色語義。此時使用純色錨點，可以提供從 hex 字串到 RGB 統計的乾淨映射，強化顏色保真度。
- **低雜訊區間**：影像細節逐漸浮現，模型需要學習自然光照、陰影、材質與紋理。此時僅使用真實影像，避免純色錨點讓輸出變得過於平坦或不自然。

這種「高雜訊學顏色、低雜訊學真實感」的策略，是 Paint-Anything 能同時達成高顏色保真度與自然視覺品質的關鍵。

#### 實驗數據解讀

##### 1. ACBench：物件層級十六進位顏色保真度評測

作者提出 Any Color Benchmark（ACBench），這是首個針對物件層級十六進位顏色保真度（object-level hex color fidelity）的評測基準，分為兩個子集：

- **ACBench-T2I**：評估文字轉影像（text-to-image, T2I）生成中，指定物件區域與請求 hex code 的顏色一致程度。
- **ACBench-Edit**：評估影像編輯任務中，被修改物件區域與目標 hex code 的顏色一致程度。

該基準的設計重點在於「物件層級」而非「全圖平均」：它只比對與提示中物件相對應的區域，這對於評估真實的設計場景至關重要，因為使用者通常只要求特定物件（如床單、燈罩、和服）變色，而非整張圖的色調。

##### 2. FLUX.2-4B 上的主要結果

在 FLUX.2-4B 基礎模型（base model）上進行微調後，Paint-Anything 相對於基礎模型獲得以下提升：

| 任務 | 相對提升 |
|---|---|
| ACBench-T2I | +85.3% |
| ACBench-Edit | +28.3% |

這兩個數字值得分開解讀：

- **T2I 提升 85.3%**：基礎模型在生成階段對於精確 hex code 的遵循能力較弱，往往只能理解「藍色」、「紅色」等語意類別，難以對應到特定數值。Paint-Anything 透過物件層級顏色監督（object-level color supervision）與純色錨點，大幅改善這個問題。
- **Edit 提升 28.3%**：基礎模型本身已具備一定程度的指令跟隨與顏色編輯能力，因此編輯任務的相對提升空間較小。但即便如此，28.3% 仍顯示 Paint-Anything 能在保留原始場景結構與光影的前提下，更精準地將物件調整至目標 hex 值。

##### 3. CompColor、GenColorBench 與人類偏好

除了 ACBench，作者還報告：

- **CompColor score**：在 named-color 與 hex prompt 兩種設定下，Paint-Anything 均取得最高平均 CompColor 分數，顯示其顏色控制能力能泛化到不同提示形式。
- **GenColorBench NCU 評估**：進一步驗證模型在更廣泛的顏色生成場景中的表現。
- **人類偏好研究（Appendices A and K）**：補充量化指標，確認人類觀察者更偏好 Paint-Anything 的輸出。

這些跨基準、跨指標的一致性提升，強化了方法有效性的可信度。

##### 4. 消融實驗的意涵

文中提到消融實驗（ablations）支持訓練配方（training recipe），特別是純色錨點為學習可靠像素空間顏色控制的重要成分。這呼應了方法論中的核心假設：僅靠真實影像的近似標籤不足以學會精確的 hex-to-RGB 映射，必須在高雜訊時間步引入乾淨的純色參考。

#### 與現有研究的比較

##### 1. 相較於文字轉影像中的顏色控制方法

過去研究大致可分為兩類：

- **學習式方法**：如學習式顏色提示（learnable color prompts）、CIELAB 對齊的文字嵌入、數值顏色編碼器（numeric-color encoders）等。這些方法通常需要為顏色設計專屬模組，限制了跨架構遷移能力。
- **免訓練推論時方法**：如取樣引導（sampling guidance）、注意力 / 數值操作（attention/value manipulation）、顏色對齊目標等。這類方法雖然無需重新訓練，但往往增加推論成本，且難以同時覆蓋生成與編輯任務。

Paint-Anything 的差異在於：它將顏色控制完全內建於提示（prompt-native），不需要額外的控制路徑或昂貴的推論時最佳化。這使得方法更容易隨著基礎模型（如 FLUX.2-4B）的進步而擴展。

##### 2. 相較於 NumColor 與 BBQ-to-Image

- **NumColor** 學習數值顏色嵌入，需要專門的顏色編碼器。
- **BBQ-to-Image** 使用結構化提示，結合邊界框與 RGB 三元組，依賴中間布局表示。

Paint-Anything 則直接使用 hex code 作為文字，並透過物件詞組進行語意綁定，無需專門的顏色編碼器或邊界框座標。這簡化了使用介面，也讓生成與編輯能共享同一套提示語言。

##### 3. 相較於顏色編輯與著色方法

傳統的影像編輯與著色（colorization）方法常採用提示編輯、指令微調、反轉（inversion）、上下文編輯、基於流的編輯或條件控制等技術。這些方法通常針對單一任務設計，難以統一處理「從無到有生成指定顏色」與「修改現有影像顏色」兩種需求。

Paint-Anything 透過共享十六進位提示介面，將兩個任務統一為同一個提示跟隨能力（prompt-following capability），這在方法論上是一個重要的簡化。

##### 4. 限制與潛在弱點

儘管結果令人印象深刻，仍需注意以下限制：

- **標籤近似性**：真實影像標籤受陰影與光照影響，只能估計主導色，無法完美對應材質在不同光照下的真實反射色。
- **物件定位品質依賴**：資料流程仰賴 VLM 定位與分割模型的準確度，對於小物件、透明物體或高度反光材質可能產生錯誤監督。
- **物件層級而非像素層級**：目前評測與監督集中在物件層級，對於漸層、多色紋理或精細區域控制可能不足。
- **基礎模型依賴**：方法表現與 FLUX.2-4B 等基礎模型的文字理解與生成能力高度相關。
- **未明確開源**：根據提供的上下文，未見程式碼、資料集或模型權重釋出的說明，這影響可重現性與後續研究接續。

#### 可重現性評估

##### 1. 方法描述的可重現程度

Paint-Anything 的方法論在概念上相對清晰：使用 `<color>#AABBCC</color>` 標籤、物件層級監督、時間步閘控的純色錨點。然而，要完整重現仍有數個關鍵細節需要作者進一步釋出：

- **Paint-500K 的確切篩選與標註參數**：例如 VLM 選擇、分割模型、MeanShift 頻寬、CIELAB 轉換方式、主導色選取準則等。
- **純色錨點的取樣比例與閘控閾值 `t_gate`**：這直接影響顏色保真度與自然感之間的權衡。
- **訓練超參數**：學習率、批次大小、訓練步數、是否凍結文字編碼器或 VAE 等。
- **FLUX.2-4B 微調細節**：是否使用 LoRA、全參數微調、記憶體優化策略等。

##### 2. 資料集與評測基準的可取得性

Paint-500K 與 ACBench 是本文提出的新資源。若作者未公開釋出，其他研究者難以直接比較。ACBench 的設計雖然在文中已有描述，但具體的提示集合、物件遮罩取得方式、顏色距離度量等細節，仍需公開才能確保公平比較。

##### 3. 程式碼與模型權重

根據目前提供的上下文，未提及公開程式碼、資料集或模型權重。文中僅提到 NumColor 與 BBQ-to-Image 的公開推論程式碼與檢查點在評估時無法取得。對於 Paint-Anything 本身，若未來能釋出：

- 微調後的模型權重；
- Paint-500K 的建構腳本與資料；
- ACBench 的評測程式碼；

將大幅提升可重現性，並促進社群在顏色控制領域的後續研究。

##### 4. 整體評估

在沒有公開資源的情況下，Paint-Anything 的可重現性屬於「中等偏低」：核心概念可理解，但實作細節與資料規模龐大，單靠論文描述難以完全復現。若作者後續開源，則可提升至「高」。

#### 未來研究方向

##### 1. 擴展到多物件與調色盤層級控制

目前的 Paint-Anything 主要針對單一物件的單一 hex 值。未來可發展為同時控制多個物件與整組調色盤（palette），例如：「將床單設為 `#A7C7E7`、檯燈設為 `#FFD580`、霓虹燈設為 `#7DF9FF`」，並確保整體色彩和諧。

##### 2. 空間與漸層顏色控制

除了物件層級的均勻顏色，未來可研究空間變化的顏色控制，例如漸層、紋理中的多色分佈、或材質屬性（金屬、絲綢、霧面）與顏色的聯合控制。

##### 3. 結合材質、光照與風格控制

真實設計中，顏色並非孤立屬性，而是與材質、光照、風格緊密相連。未來可將 Paint-Anything 與風格遷移、材質生成、光照編輯等方法結合，實現更全面的視覺設計控制。

##### 4. 改善資料流程以處理複雜場景

針對透明物體、反光表面、陰影強烈或低光源場景，可引入更精細的物理基礎渲染（physically-based rendering）或本徵影像分解（intrinsic image decomposition），以取得更準確的物件本色（albedo）監督，減少陰影造成的近似標籤問題。

##### 5. 發展更細緻的評測指標

ACBench 已邁出重要一步，但未來可加入：
- 感知均勻色彩空間中的距離（如 CIEDE2000）；
- 對光照條件變化的魯棒性評估；
- 編輯前後一致性（identity preservation）與背景保留度量；
- 多物件場景下的區域正確性評估。

##### 6. 應用於影片與 3D 內容生成

將 hex 提示介面擴展到影片生成與 3D 資產生成，可讓品牌設計、動畫製作與遊戲資產開發受益。關鍵挑戰在於時間一致性與視角一致性。

##### 7. 與 LLM 設計代理整合

未來可將 Paint-Anything 嵌入 LLM 驅動的設計代理（design agent），讓使用者以自然語言描述品牌需求，由代理自動選擇調色盤、生成或編輯影像，並根據回饋迭代。

##### 8. 降低推論成本與邊緣部署

雖然 Paint-Anything 不需要推論時最佳化，但基於 FLUX.2-4B 等大型擴散模型的推論成本仍然高昂。未來可研究知識蒸餾、模型量化或輕量級適配器，使任意顏色控制能在資源受限環境中運行。

## 論文問答

**Q1：什麼是「任意顏色控制」（any-color control），為什麼在專業設計中很重要？**

A：任意顏色控制是指使用者能夠以任意的 24 位元十六進位色碼（例如 #10A9FF）來指定物件的目標顏色，而不只是使用「藍色」或「紅色」這類模糊詞彙。對品牌設計師或電商而言，這種精確的顏色規格是基本需求，因為品牌識別色或新品系列的指定色必須被準確呈現。目前的生成模型雖然能畫出豐富場景，卻常常無法忠實遵循明確的數值色碼，因此任意顏色控制是讓生成式 AI 成為可靠設計工具的關鍵能力。

**Q2：現有的顏色控制方法為什麼無法滿足任意顏色控制的需求？**

A：過去的方法通常需要任務專屬模組、學習式顏色權杖，或是在推論時使用取樣引導、注意力／數值操作等額外技術。這些設計往往難以擴展到完整的 24 位元色彩空間，也不容易遷移到新的模型架構，並會增加推論成本。結果是顏色生成、著色與編輯常被當成彼此獨立的問題，而非一個統一的原生提示遵循能力。

**Q3：為什麼選擇十六進位字串作為統一的顏色介面？**

A：十六進位色碼是一種精簡、數值化且通用的顏色規格，可以直接寫進文字提示中。作者發現即使是 Qwen3-4B 這類緊湊的大型語言模型，也能將 #F0FFF1、#E8D00A 等原始十六進位色碼對應到合理的顏色語義。由於十六進位字串可以綁定在物件詞組上，因此能讓單一模型透過同一套提示語言同時處理生成與編輯任務。

**Q4：Paint-Anything 的核心方法是什麼？**

A：Paint-Anything 是一個經過微調的統一模型，它透過物件層級的顏色監督來學習共享的十六進位提示介面。模型在提示中直接使用 `<color>#AABBCC</color>` 這類明確標記來表示目標顏色，不需要額外的顏色編碼器或推論時控制器。它透過 Paint-500K 資料集進行訓練，使單一模型就能同時支援文字轉影像生成與物件重新上色。

**Q5：Paint-Anything 的關鍵創新是什麼？**

A：關鍵創新在於結合真實影像監督與「純色錨點」（pure-color anchors），並透過時間步閘控來使用它們。純色錨點將十六進位色碼與純色影像配對，提供像素完全匹配十六進位值的乾淨參考，且只在高雜訊時間步啟用，以學習精確的顏色語義。在低雜訊時間步則使用自然影像進行訓練，從而保留真實的陰影、質感與光照。

**Q6：Paint-500K 資料集是如何建構的？**

A：Paint-500K 是從真實影像出發，透過資料管線自動產生物件層級的十六進位標籤。流程包括使用視覺語言模型進行物件定位、以分割遮罩隔離物件像素，並在 CIELAB 空間中使用 MeanShift 分群來估計感知上的主導顏色。此外，編輯配對合成會產生前後對比的編輯樣本，使資料集能同時支援文字轉影像生成與影像編輯任務。

**Q7：Any Color Benchmark（ACBench）是什麼？它包含哪些部分？**

A：ACBench 是本文提出的物件層級十六進位顏色保真度基準測試，用來衡量生成或編輯結果是否忠實於指定的色碼。它分為 ACBench-T2I 與 ACBench-Edit 兩個子集，前者評估文字轉影像生成，後者評估影像編輯。兩者都會檢查生成或編輯區域的實際顏色與請求的十六進位值之間的吻合程度。

**Q8：Paint-Anything 在實驗中取得了哪些關鍵結果？**

A：在 FLUX.2-4B 骨幹上，Paint-Anything 相較於基礎模型分別將 ACBench-T2I 與 ACBench-Edit 分數提升了 85.3% 與 28.3%。它在 CompColor 分數上也取得了所有比較方法中的最高平均分，無論是在命名顏色提示還是十六進位提示下都表現最佳。此外，GenColorBench 評估與人類偏好研究也進一步驗證了這些進步。

**Q9：消融實驗支持了哪些訓練設計？**

A：消融實驗顯示純色錨點是學習可靠像素空間顏色控制的重要成分。只有在高雜訊時間步使用錨點，才能避免干擾低雜訊階段所學到的真實影像細節。如果移除或錯誤使用純色錨點監督，模型將難以把十六進位字串準確對應到 RGB 統計值。

**Q10：Paint-Anything 有哪些實際應用場景？**

A：在品牌設計中，設計師可以要求商標使用特定的品牌藍色；在電商領域，產品圖需要符合新品系列的指定紅色或藍色。數位藝術家也能根據精確調色盤生成或重新上色場景。統一的提示介面減少了在生成、著色與編輯工具之間切換的需求。

**Q11：從產品部署的角度，Paint-Anything 有什麼優勢？**

A：使用者只需在提示中輸入十六進位色碼即可指定顏色，不需要額外模組或逐張影像的最佳化。同一個微調後的模型既能從零開始生成影像，也能編輯現有影像，簡化了系統整合。相較於需要輔助控制器或反覆細修的方法，這也降低了推論成本與延遲。

**Q12：這項研究對生成式 AI 領域可能帶來什麼影響？**

A：這項研究將精確顏色控制重新定義為一種原生提示遵循能力，而非多個獨立任務的集合。它證明現代語言模型可以為原始數值十六進位色碼建立基礎對應，且物件層級監督足以學習統一的生成與編輯。這可能促使未來的多模態系統將數值顏色規格視為第一類控制訊號。

**Q13：Paint-Anything 有哪些已知的限制？**

A：真實影像的顏色標籤會因陰影與光照而僅是近似顏色，因此監督訊號本身帶有雜訊。資料管線依賴物件定位與分割的準確度，這些階段的錯誤會傳遞到顏色標籤。此外，複雜材質、半透明物體與空間變化的顏色並未被明確建模。

**Q14：Paint-Anything 可能出現哪些失敗案例？**

A：當物件具有強烈陰影、複雜紋理或相互反射時，模型可能產生視覺合理但與指定色碼不完全一致的平均顏色。少見或訓練分佈外的十六進位色碼可能較難準確呈現。在編輯任務中，若物件邊界或定位模糊，顏色變化可能溢出到不應改變的區域。

**Q15：未來可以朝哪些方向延伸這項工作？**

A：未來可將任意顏色控制擴展到影片與三維生成，並保持時間或視角上的一致性。研究者也可以分解材質與光照，以實現更物理正確的重新上色。另一個方向是結合使用者提供的遮罩或參考影像，讓十六進位提示能與更細緻的空間與語義控制搭配使用。

## 實務應用指南

### 適用場景

1. **品牌視覺資產生成**  
   企業可將品牌色以 `#0047AB`、`#FFD700` 等明確十六進位色碼寫入提示，直接生成符合品牌規範的 Logo、社群素材或廣告主視覺，避免「藍色」這類模糊描述造成色差。

2. **電商產品圖與服飾配色**  
   線上零售商能依庫存或季節需求，指定 `#C26D3A` 外套、`#95B5B7` 耳環等顏色，批量生成或編輯商品圖；也可針對同一款商品快速產生多色版本，減少實拍成本。

3. **室內設計與空間渲染**  
   設計師可輸入「一張 `#A7C7E7` 床單、搭配 `#FFD580` 床頭燈」等提示，生成具有一致色調的室內情境圖，或將現有空間照片局部重新上色以比對配色方案。

4. **遊戲與動畫資產換色**  
   遊戲美術可將角色、道具或場景物件依企劃指定的十六進位色碼重新上色，例如把盔甲從 `#58626F` 改為 `#B1B1A8`，加速風格迭代與多陣營變體製作。

5. **廣告創意與個人化行銷**  
   行銷團隊可結合節慶調色盤（如 `#FF73B0`、`#BD9DDB`）生成海報，或根據用戶偏好色動態替換畫面中的物件顏色，實現大規模個人化素材。

### 實作前置條件

- **資料準備**
  - 數十萬張高品質真實影像，並附帶描述物件與顏色的文字說明。
  - 物件定位與分割能力（如 VLM 或現有分割模型），用於產生物件層級的遮罩。
  - 感知式顏色標註流程，例如在 CIELAB 空間執行 MeanShift 分群，以估計物件主色。
  - 編輯配對資料：成對的原始圖與目標圖，或透過遮罩合成重新上色的版本。
  - 純色錨點資料：每張圖僅含單一純色，並與對應十六進位色碼完全匹配。

- **運算資源**
  - 至少數張高階 GPU（如 NVIDIA A100/H100），記憶體需足以微調 FLUX.2-4B 等級的擴散模型。
  - 訓練時間依資料規模與解析度而定，通常需數天至一週。
  - 推論階段建議配備 GPU 以支援即時或批次生成。

- **技術能力**
  - 熟悉擴散模型／流匹配（flow matching）訓練與微調。
  - 能操作視覺語言模型、分割模型與色彩空間轉換（CIELAB ↔ RGB）。
  - 具備提示工程經驗，能設計 `<color>#AABBCC</color>` 這類結構化提示模板。
  - 有能力建立評測管線，例如使用 ACBench 測量物件層級十六進位顏色保真度。

### 實作步驟建議

1. **建構資料管線**  
   從真實影像出發，利用 VLM 進行物件定位，再透過分割模型取得物件遮罩；在 CIELAB 空間對遮罩內像素做 MeanShift 分群，提取主色並轉為十六進位色碼，形成 Paint-500K 風格的物件層級顏色監督資料。

2. **合成編輯配對**  
   針對編輯任務，建立「原始圖 + 編輯指令 + 目標圖」三元組。指令中明確標註要修改的物件與目標色碼，例如「把燈的顏色設為 `#10A9FF`」。

3. **製作純色錨點**  
   生成大量純色影像，每張影像的像素值與單一十六進位色碼完全一致。這些樣本將作為「乾淨」的低階顏色參考，幫助模型學習數字色碼到 RGB 統計的對應。

4. **時間步閘控訓練**  
   在微調 FLUX.2-4B 等流匹配模型時，讓純色錨點只出現在高雜訊時間步（如 `t ∈ [0.8, 1]`），真實影像則在完整時間步範圍內取樣。這樣可保留自然影像的低雜訊細節，同時強化高雜訊下的顏色對齊。

5. **統一提示介面**  
   將十六進位色碼以 `<color>#AABBCC</color>` 包裹，直接嵌入物件詞組或編輯指令中，讓單一微調模型同時支援文字轉影像生成與物件重新上色。

6. **評測與迭代**  
   使用 ACBench-T2I 與 ACBench-Edit 測量生成／編輯區域與目標色碼的差異，並搭配 CompColor、GenColorBench 與人工偏好研究進行交叉驗證，根據結果調整資料比例與訓練超參數。

7. **產品化封裝**  
   將模型包裝為 API 或插件，提供「調色盤輸入 → 影像生成／編輯 → 顏色保真度回報」的端到端服務，並整合品牌色庫與審核流程。

### 潛在風險與注意事項

- **陰影與光照造成的近似顏色**  
  真實影像標籤僅為近似色，可能導致模型學到「帶陰影的顏色」而非精確色碼。可透過純色錨點與高雜訊時間步閘控來緩解。

- **顏色滲透與物件邊界模糊**  
  若分割不精確，目標色可能溢出到背景或其他物件。建議搭配高品質遮罩，並在推論時使用額外的區域限制或後處理。

- **過度飽和或色調偏移**  
  模型可能傾向生成更鮮豔的顏色。可在訓練時加強顏色保真度損失，並以 ACBench 分數監控。

- **色域與顯示差異**  
  螢幕校色、sRGB 與其他色彩空間轉換會影響最終觀感。產品端應整合色彩管理（如 ICC 描述檔）並在使用者介面顯示預覽色塊。

- **提示注入與不當內容**  
  由於色碼以文字形式進入提示，需防範惡意提示注入。同時應部署內容安全過濾，避免生成違反品牌或法律規範的影像。

- **版權與資料偏見**  
  訓練資料可能包含受版權保護的影像或文化偏見。建議使用合法授權資料，並在產品說明中標示 AI 生成與潛在限制。

- **色彩管理系統**  
  與企業色彩管理系統對接，確保從設計稿、生成影像到印刷輸出的色碼一致性，必要時提供 Pantone 或 CMYK 轉換。

- **初學者**  
  建議先從「任意顏色控制」這個核心概念入手：想像你能像畫家調色盤一樣，把 `#10A9FF` 這種色碼直接寫進 AI 提示，讓模型畫出指定顏色的物件。接著再看「純色錨點」如何幫助模型學會精準對應數字色碼，最後透過圖 1 與圖 2 的範例建立直覺。

- **AI 工程師**  
  重點關注資料管線（物件定位、CIELAB 分群、編輯配對合成）與訓練配方（高雜訊時間步閘控、流匹配目標、提示模板 `<color>#AABBCC</color>`）。建議直接參考實驗章節與消融實驗，評估將此方法移植到 FLUX.2-4B 或其他骨幹模型所需的修改。

- **研究人員**  
  本工作的貢獻在於將物件層級十六進位監督、純色錨點與統一提示介面結合，並提出 ACBench 作為物件層級顏色保真度的評測基準。可進一步探討時間步閘控的理論基礎、擴展至影片或多物件獨立配色，或研究更細緻的材質—光照解耦。

- **產品經理**  
  請聚焦於商業價值與落地風險：Paint-Anything 能讓品牌以單一模型同時完成生成與編輯，降低維護多個任務專屬模型的成本。評估時應同時看 ACBench 的客觀分數與人工偏好研究，並規劇色彩管理、版權審核與設計工具整合，才能順利從技術原型走向產品化。
