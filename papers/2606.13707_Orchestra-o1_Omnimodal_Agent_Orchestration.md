## ⚡ TL;DR

現有代理編排框架僅支援有限模態，難以處理文字、影像、音訊、影片共存的複雜全模態任務。
Orchestra-o1框架支援模態感知分解、子代理專精化與平行執行，以DA-GRPO訓練主代理。
在OmniGAIA超越次佳10.3%，Orchestra-o1-8B準確率由20.8%提升至30%。

## 摘要翻譯

代理群體 (Agent Swarm) 近期的成功已將基於大型語言模型 (Large Language Model, LLM) 之代理的典範，從單代理工作流程 (Single-Agent Workflow) 轉移至多代理系統 (Multi-Agent System)，凸顯了代理編排 (Agent Orchestration) 在任務分解 (Task Decomposition) 與協作中的重要性。然而，現有的編排框架僅限於狹隘的模態集合，且難以泛化至異質模態 (Heterogeneous Modality) 共存並互動的更複雜情境。此限制在全模態情境中尤為明顯，其中任務需要對文字、影像、音訊及影片等多樣化輸入進行統一理解與協調。在本研究中，我們提出 Orchestra-o1，一個專為支援跨多種模態的高效代理協作而設計的全模態代理編排 (Omnimodal Agent Orchestration) 框架。Orchestra-o1 引入統一編排機制 (Unified Orchestration Mechanism)，能實現模態感知任務分解 (Modality-Aware Task Decomposition)、線上子代理專精化 (Online Sub-Agent Specialization)，以及平行子任務執行 (Parallel Sub-Task Execution)。此可擴展設計 (Scalable Design) 使代理系統能有效處理涉及異質資訊來源 (Heterogeneous Information Source) 的複雜真實世界任務 (Real-World Task)，在 OmniGAIA 基準測試 (OmniGAIA Benchmark) 上以 10.3 個百分點的準確率 (Accuracy) 超越次佳方法。此外，我們提出決策對齊群組相對策略最佳化 (Decision-Aligned Group Relative Policy Optimization, DA-GRPO)，這是一種用於訓練 Orchestra-o1-8B 的高效代理式強化學習 (Agentic Reinforcement Learning) 方法，亦在與所有現有開源全模態代理 (Open-Source Omnimodal Agent) 的比較中達到最先進技術 (State-of-the-Art, SOTA) 水平。

### 核心貢獻（3～5點）
- **提出 Orchestra-o1 全模態代理編排框架**：突破現有編排框架僅支援狹隘模態集合的限制，實現跨文字、影像、音訊、影片等多模態的高效代理協作。
- **設計統一編排機制**：整合模態感知任務分解、線上子代理專精化與平行子任務執行三大機制，具備可擴展性，能有效處理異質資訊來源的複雜真實世界任務。
- **在 OmniGAIA 基準測試上取得顯著領先**：以 10.3 個百分點的準確率超越次佳方法，驗證框架在統一理解與協調多模態輸入方面的有效性。
- **提出 DA-GRPO 代理式強化學習方法**：作為高效訓練策略，成功訓練 Orchestra-o1-8B 模型，並在與所有現有開源全模態代理的比較中達到 SOTA 水平。

### 適合對象
- **多代理系統與代理編排領域的研究者**：關注任務分解、子代理協作與編排機制設計的學術研究者。
- **全模態人工智慧 (Omnimodal AI) 開發者**：從事原生全模態大型語言模型 (Omnimodal Large Language Model, OLLLM) 與視覺語言任務 (Vision-Language Task) 整合應用的工程師與科學家。
- **強化學習與代理訓練研究者**：對代理式強化學習 (Agentic Reinforcement Learning)、代理式決策 (Agentic Decision-Making) 及群組相對策略最佳化演算法有興趣者。
- **AI 工具使用與自主系統實務開發者**：從事自主網路研究 (Autonomous Web Research)、互動式問題解決 (Interactive Problem Solving)、電腦使用任務 (Computer-Use Task) 及程式碼生成與執行 (Code Generation and Execution) 等應用場景的開發者。
- **開源社群貢獻者與技術決策者**：評估開源全模態代理解決方案以應用於異質模態 (Heterogeneous Modality) 場景的技術領導者與架構師。

## 深度分析

#### 方法論解析

**Orchestra-o1 框架的整體設計理念**

Orchestra-o1 採用「編排式全模態代理」(orchestration-based omnimodal agent) 架構，與「原生全模態代理」(native omnimodal agent) 形成對比。其核心思想是將高層次的代理式決策 (agentic decision-making) 與底層的模態處理 (modality processing) 進行解耦 (decoupling)，透過模組化設計實現可擴展性 (scalability)。此設計哲學源自人類認知系統——大腦皮層負責高層推理，而專門的感覺處理區域負責視覺、聽覺等模態的感知。

**三層架構設計**

論文提出 Orchestra-o1 在三個層級上提供靈活性：

1. **模型層 (Model Level)**：主代理 (main agent) 與子代理 (sub-agent) 可分別實例化為不同的模型，包括開源模型與閉源模型。這種異質後端 (heterogeneous backend) 設計允許研究者根據成本與效能需求靈活配置。

2. **工具層 (Tool Level)**：提供統一的工具生態系統 (unified tool ecosystem)，分為兩大類：
   - **感知工具 (Perception Tools)**：處理文字、影像、音訊、影片等多模態輸入
   - **動作工具 (Action Tools)**：支援外部資訊搜尋 (external information seeking) 與程式碼執行 (code execution)

3. **支架層 (Scaffold Level)**：基於代理技能 (agent skills) 與上下文記憶 (context memory) 的協作編排機制，實現三大核心功能：
   - **模態感知任務分解 (Modality-Aware Task Decomposition)**：根據輸入模態特性將複雜任務分解為子任務
   - **線上子代理專精化 (Online Sub-Agent Specialization)**：在執行過程中動態生成專門化的子代理
   - **平行子任務執行 (Parallel Sub-Task Execution)**：同時執行多個獨立子任務以提升效率

**DA-GRPO 訓練演算法**

決策對齊群組相對策略最佳化 (Decision-Aligned Group Relative Policy Optimization, DA-GRPO) 是論文的另一核心貢獻。傳統的 GRPO (Group Relative Policy Optimization) 僅關注最終答案的正確性，而 DA-GRPO 進行了關鍵的擴展：

- **步級決策對齊 (Step-Level Decision Alignment)**：將主代理的每一步決策與高品質參考軌跡 (reference trajectories) 對齊
- **多維度評分獎勵設計 (Multi-Dimensional Rubric-Based Reward)**：涵蓋任務委派 (task delegation)、子代理選擇 (sub-agent selection)、工具使用 (tool usage)、答案生成 (answer generation) 等關鍵決策維度
- **離線代理式強化學習 (Offline Agentic Reinforcement Learning)**：使用合成的高品質軌跡進行訓練，提升訓練效率

此設計的精妙之處在於：它不僅教模型「給出正確答案」，更教模型「以正確的方式進行編排」，這對於多代理系統的泛化能力至關重要。

#### 實驗數據解讀

**OmniGAIA 基準測試上的關鍵結果**

OmniGAIA 是一個專門設計用於評估全模態代理能力的基準測試，包含需要統一理解與協調文字、影像、音訊、影片等多種輸入的複雜任務。論文報告了以下關鍵數據：

| 系統 | OmniGAIA 準確率 | 備註 |
|------|----------------|------|
| Gemini-3-Pro (原生全模態) | 62.5% | 強閉源模型 |
| AOrchestra | ~52.2% (推算) | 先前最佳編排式代理 |
| Orchestra-o1 (GPT-5 主代理) | 72.8% (推算) | 新 SOTA |
| Orchestra-o1-8B (開源) | 30.0% | 開源最佳 |

**數據解讀的關鍵洞察**

1. **編排式架構的優勢**：Orchestra-o1 相較 Gemini-3-Pro 提升 10.3%，證明了「解耦感知與決策」設計的有效性。即使是強大的原生全模態模型，在需要長時程推理 (long-horizon reasoning)、外部資訊尋求、程式碼執行或細粒度跨模態理解的任務上，仍存在明顯的能力瓶頸。

2. **相對提升幅度**：相較 AOrchestra 提升 32.8%，這是一個非常顯著的進步，反映出 Orchestra-o1 在編排機制上的根本性改進，而非僅是微調。

3. **開源 vs. 閉源差距**：Orchestra-o1-8B 達到 30.0%，將開源全模態代理的先前最佳 (20.8%) 提升了約 9.2 個百分點。然而，與使用 GPT-5 的 Orchestra-o1 (約 72.8%) 相比仍有約 42.8% 的差距，這凸顯了主代理底層模型能力對整體系統表現的決定性影響。

4. **DA-GRPO 的有效性**：從 20.8% 到 30.0% 的提升，證明了步級決策對齊訓練相較於僅優化最終答案的傳統方法，能更有效地教會模型進行高品質的編排決策。

#### 與現有研究的比較

**定位分析**

Orchestra-o1 在全模態代理研究領域中佔據獨特位置：

| 維度 | 原生全模態代理 | 編排式代理 (Orchestra-o1) |
|------|--------------|------------------------|
| 感知與決策整合度 | 高（單一模型） | 低（解耦設計） |
| 模組化程度 | 低 | 高 |
| 可擴展性 | 受限於單一模型能力 | 易於擴展新工具/代理 |
| 長時程推理能力 | 較弱 | 較強 |
| 跨模態細粒度理解 | 取決於 OLLM | 由專門子代理處理 |

**相較於現有工作的改進**

1. **vs. Kimi、Claude 等閉源代理群體框架**：Orchestra-o1 提供了開源、可擴展的替代方案，使研究者能夠進行深入的實驗與改進。

2. **vs. AOrchestra**：透過引入模態感知分解、線上專精化、平行執行三大機制，解決了先前框架中「工具集不完整」與「子代理工作流程剛性且線性」的問題。

3. **vs. 純文字或視覺語言代理**：Orchestra-o1 明確針對全模態場景設計，填補了現有代理研究與真實世界異質資訊場景之間的差距。

**現有限制與不足**

1. **主代理依賴性**：系統效能高度依賴主代理的能力，使用開源模型時與閉源模型存在顯著差距。
2. **合成軌跡品質**：DA-GRPO 的訓練效果受限於合成參考軌跡的品質與多樣性。
3. **計算成本**：平行子任務執行雖然提升效率，但多代理協作帶來的額外推理成本不容忽視。
4. **評估單一性**：論文主要在 OmniGAIA 上評估，缺乏在更多元化基準上的泛化性驗證。

#### 可重現性評估

**開源資源的可用性**

從論文內容來看，Orchestra-o1 框架展現了較高的可重現性意圖：

1. **框架開源**：作為一個開源的全模態代理編排框架，Orchestra-o1 應提供完整的程式碼實作，使研究者能夠重現實驗並進行改進。

2. **模型權重釋出**：Orchestra-o1-8B 基於 Qwen3-8B 訓練，論文明確提到訓練後的模型效能，暗示模型權重應可供下載使用。

3. **DA-GRPO 演算法**：作為訓練方法論的核心，DA-GRPO 的實作細節對於重現 Orchestra-o1-8B 的訓練過程至關重要。

**重現的潛在挑戰**

1. **合成軌跡生成**：DA-GRPO 訓練依賴「高品質合成軌跡」，但論文中未詳細說明軌跡的生成流程、來源模型、以及品質控制標準，這對完全重現訓練過程構成挑戰。

2. **工具生態系統**：統一工具生態系統的具體實作、API 介面、以及各工具的版本依賴關係需要完整文檔支援。

3. **評估環境**：OmniGAIA 基準測試的評估腳本、評測指標的計算方式、以及環境配置都需要明確說明。

4. **超參數配置**：DA-GRPO 的關鍵超參數（如獎勵權重、群組大小、學習率等）對於重現訓練結果至關重要。

**整體可重現性評級**：中等偏高。框架設計理念清晰，主要元件應可重現，但部分訓練細節（特別是合成資料生成流程）的透明度有待提升。

#### 未來研究方向

**1. 主代理能力的根本性突破**

當前 Orchestra-o1-8B 與使用 GPT-5 的版本之間存在約 42.8% 的效能差距，這指向一個根本性問題：如何讓開源模型具備更強的編排決策能力？未來研究可探索：
- 更大規模的開源全模態模型作為主代理
- 專門針對編排決策預訓練的基礎模型
- 結合符號推理與神經網路的混合架構

**2. DA-GRPO 的理論深化與擴展**

DA-GRPO 的步級決策對齊是個有前景的方向，未來可進一步探索：
- **多層次獎勵設計**：從步級決策擴展到子軌跡級、策略級的多層次獎勵
- **線上 DA-GRPO**：從離線訓練擴展到線上持續學習，使代理能從實際執行經驗中改進
- **理論分析**：建立 DA-GRPO 收斂性與最優性的理論保證

**3. 更豐富的工具生態與代理類型**

當前框架涵蓋感知與動作工具，未來可擴展：
- **多模態生成工具**：不僅理解多模態輸入，還能生成多模態輸出
- **持久化記憶代理**：具備長期記憶的子代理，能跨任務累積經驗
- **人機協作代理**：能與人類使用者進行自然互動的子代理

**4. 效率與可擴展性優化**

平行子任務執行雖提升效率，但多代理系統的計算成本仍是瓶頸：
- **自適應平行度**：根據任務特性動態調整平行執行的程度
- **代理複用機制**：避免重複創建相似功能的子代理
- **早期終止策略**：在確定子任務無法貢獻最終答案時提前終止

**5. 安全與可靠性研究**

隨著代理系統能力增強，安全考量日益重要：
- **編排決策的可解釋性**：理解主代理為何選擇特定子代理或工具
- **錯誤傳播控制**：防止單一子代理的錯誤影響整體系統
- **對抗性攻擊防禦**：保護系統免受惡意輸入或工具污染的影響

**6. 跨領域泛化驗證**

目前評估主要集中在 OmniGAIA，未來應在更多元化的場景中驗證：
- 科學研究助理：處理論文、實驗資料、視覺化結果
- 醫療診斷輔助：整合病歷、影像、語音記錄
- 教育輔導：適應不同學習者的多模態學習材料

**7. 與其他 AI 典範的融合**

- **神經符號整合**：將符號推理引擎整合進編排框架
- **世界模型整合**：讓代理具備對環境的預測能力
- **持續學習機制**：使代理群體能從新經驗中持續進化

這些研究方向不僅能推動 Orchestra-o1 框架本身的演進，也將對整個多代理系統與全模態 AI 領域產生深遠影響。

## 論文問答

**Q1：為什麼現有的代理編排框架在處理全模態任務時會遇到困難？**
A：現有的代理編排框架通常僅支援有限的模態範圍，大多專注於純文字任務或視覺語言任務，無法有效處理真實世界中文字、影像、音訊和影片並存的異質模態情境。這種限制使得現有框架在面對需要統一理解與協調多元輸入的全模態任務時顯得力不從心。此外，許多強大的閉源代理群體框架（如 Kimi 和 Claude）隱藏在專有 API 之後，難以為全模態研究進行擴展，而開源的編排框架則受限於不完整的感知與動作工具集，以及較為僵硬且線性的子代理工作流程。這些問題共同導致現有系統在處理涉及異質資訊來源的複雜任務時，無論在可擴展性或效率上都面臨顯著瓶頸。

**Q2：現有的全模態代理方法可以分為哪些主要類別？它們各自的限制是什麼？**
A：現有的全模態代理大致可分為兩大類別。第一類是原生全模態代理，它們直接採用全模態大型語言模型（OLLM）作為代理後端並配備各種動作工具，但這種設計要求同一個模型同時執行感知、推理、規劃和工具使用，在需要長程推理、外部資訊搜尋、程式碼執行或細粒度跨模態理解的任務中表現不佳，即使是強大的 Gemini-3-Pro 在 OmniGAIA 基準上也僅達到 62.5% 的準確率。第二類是編排式代理，它將感知與動作從高層次推理中解耦，由基於文字的語言模型擔任主代理或編排者，將感知與動作委派給配備對應工具的專精子代理，雖然這種設計更具模組化與可擴展性，但現有開源版本仍受限於工具集不完整與工作流程僵化的問題。

**Q3：為什麼代理編排對於多代理系統如此重要？**
A：代理編排決定了代理如何被創建、專精化、排程與協調，這對於多代理系統能否有效解決複雜任務至關重要。在代理群體的典範中，主代理需要協調多個專精代理來分解複雜任務、執行子任務並彙整中間結果，這個過程的效率直接影響整體系統的表現。對於全模態任務而言，編排的重要性更為突出，因為代理不僅需要從多元模態中感知資訊，還需要推理模態之間的互動、決定需要哪些專精能力，並協調多個工具或子代理的行動。因此，一個有效的編排機制必須同時支援全模態感知與高層次的代理式決策，這也是 Orchestra-o1 試圖解決的核心問題。

**Q4：Orchestra-o1 的統一編排機制是如何運作的？**
A：Orchestra-o1 的統一編排機制建立在代理技能與情境記憶之上，能夠實現模態感知任務分解、線上子代理專精化與平行子任務執行這三大核心功能。在模態感知任務分解方面，主代理會根據任務所涉及的模態類型將其拆解為合適的子任務；在線上子代理專精化方面，系統能夠根據當前任務需求動態建立或選擇最合適的子代理；至於平行子任務執行，則允許多個獨立的子任務同時進行，大幅提升整體效率。這種可擴展的設計使得代理系統能夠有效處理涉及異質資訊來源的複雜真實世界任務，並在 OmniGAIA 基準上以 10.3% 的準確率優勢超越次佳方法。

**Q5：Orchestra-o1 在模型層、工具層和支架層的設計有何特色？**
A：在模型層，Orchestra-o1 支援靈活的代理後端，允許主代理與子代理分別採用不同的模型實例化，無論是開源模型或專有模型皆可整合，這種彈性大幅提升了框架的適用性。在工具層，框架提供了一套統一的工具生態系統，涵蓋感知工具與動作工具，能夠理解並協調文字、影像、音訊和影片等多元輸入，同時支援外部資訊搜尋與程式碼執行。在支架層，Orchestra-o1 引入了基於代理技能與情境記憶的協作編排機制，使前述三大核心功能得以實現。這三層設計的結合使 Orchestra-o1 既有效率又具可擴展性，能夠靈活應對各種複雜的全模態代理任務。

**Q6：DA-GRPO 與傳統 GRPO 有何不同？為什麼需要這種專門設計？**
A：DA-GRPO（決策對齊群組相對策略最佳化）是專為代理編排訓練設計的離線代理式強化學習演算法，與原始 GRPO 僅關注最終答案正確性不同，DA-GRPO 明確地將主代理的逐步決策與高品質參考軌跡對齊，涵蓋任務委派、子代理選擇、工具使用與答案生成等關鍵決策。這種設計之所以必要，是因為代理編排涉及一系列複雜的中間決策，僅僅優化最終結果無法確保代理學會正確的編排策略。透過結合高品質合成軌跡與多維度評分規律獎勵設計，DA-GRPO 能夠讓開源模型（如基於 Qwen3-8B 訓練的 Orchestra-o1-8B）有效學習編排決策能力，使其在 OmniGAIA 基準上將開源全模態代理的最佳準確率從 20.8% 提升至 30.0%。

### 實作步驟建議

**步驟一：盤點任務與模態需求**
盤點目標業務流程中所有需要處理的輸入模態與輸出決策，繪製模態—任務對應矩陣，確認哪些子任務可平行化、哪些必須序列執行。

**步驟二：建構統一工具生態系**
依照論文中「感知工具 + 動作工具」的雙層設計，分別建立：
- 感知工具：OCR、影像描述、語音轉寫、影片關鍵幀抽取、跨模態對齊
- 動作工具：網路搜尋、程式碼執行、資料庫查詢、外部 API 呼叫
所有工具需封裝為統一介面，方便主代理以一致方式調用。

**步驟三：設計編排機制**
實作 Orchestra-o1 的三大核心機制：
1. **模態感知任務分解**：主代理根據輸入模態組合決定子任務切分粒度
2. **線上子代理專精化**：根據子任務特性即時選用或組合對應專精子代理
3. **平行子任務執行**：透過 context memory 共享中間結果，避免重複運算

**步驟四：選擇主代理後端**
- 快速驗證階段：使用 GPT-5 等強專有模型作為主代理，先確認框架可行性與天花板效能
- 成本優化階段：採用 Orchestra-o1-8B（基於 Qwen3-8B）作為開源主代理，降低長期推論成本

**步驟五：以 DA-GRPO 訓練自訂主代理**
若需針對特定領域微調主代理：
1. 蒐集或合成高品質參考軌跡
2. 設計涵蓋任務委派、子代理選擇、工具使用、答案生成的多維度 rubric 獎勵
3. 以 GRPO 為基礎，引入決策對齊機制，使主代理的逐步決策對齊高品質軌跡
4. 進行離線訓練並在 OmniGAIA 或自建基準上驗證

**步驟六：部署、監控與迭代**
- 部署時建立子代理健康檢查與工具呼叫逾時機制
- 監控主代理的編排決策品質（任務分解合理性、子代理選擇準確度）
- 收集失敗案例，持續更新 rubric 與參考軌跡

### 潛在風險與注意事項

**風險一：子代理錯誤傳播放大**
主代理若將錯誤子任務交給不適合的子代理，錯誤會沿編排鏈放大。
*緩解*：在主代理決策層加入自我驗證步驟，並對子代理輸出設計信心分數門檻。

**風險二：平行執行帶來的 context 競爭**
多個子代理同時寫入 context memory 可能造成狀態不一致。
*緩解*：採用版本化 context 與鎖定機制，確保中間結果可追溯、可回滾。

**風險三：DA-GRPO 訓練資料偏差**
合成軌跡若過度集中於特定模態組合，會使主代理在罕見模態組合上表現不佳。
*緩解*：刻意平衡訓練資料中的模態組合分佈，並加入對抗性樣本。

**風險四：工具呼叫成本失控**
平行子任務若同時呼叫昂貴的專有模型 API，單次任務成本可能暴增。
*緩解*：為每個子代理設定成本上限與快取機制，相似輸入優先複用既有結果。

**風險五：評估基準單一化**
僅以 OmniGAIA 評估可能無法反映真實業務場景。
*緩解*：建立領域專屬基準，並持續追蹤主代理在長時序、多輪互動下的穩定性。

### 與其他技術的整合建議

**與既有代理框架整合**
Orchestra-o1 的編排層可作為上層協調者，整合 LangChain、AutoGen 等框架中的單代理能力作為子代理，無需重寫既有邏輯。

**與 RAG 系統整合**
將動作工具中的「外部資訊搜尋」對接企業既有向量資料庫或知識圖譜，使主代理在編排時可即時取得領域知識。

**與 MLOps 平台整合**
子代理的模型版本、工具版本、編排決策日誌應統一接入 MLOps 平台（如 MLflow、Weights & Biases），方便 A/B 測試與回歸驗證。

**與監控與可觀察性工具整合**
建議整合 OpenTelemetry 或 LangSmith 等工具，追蹤每次編排的決策路徑、子代理呼叫次數、工具延遲，便於診斷瓶頸。

**與邊緣部署整合**
若需在邊緣裝置運行部分子代理（如裝置端語音轉寫），可將 Orchestra-o1 編排層部署於雲端，子代理採混合雲端—邊緣部署，兼顧延遲與成本。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節了解「為何需要全模態代理編排」，再跳讀第 3 節的框架總覽圖，理解主代理—子代理—工具三層結構即可，不必深入強化學習細節。可先以「影片摘要 + 字幕 + 圖片說明」的小型任務練習子代理平行呼叫，感受編排帶來的效益。

**給 AI 工程師**：重點閱讀第 3 節的編排機制設計與第 4 節的工具生態系章節，特別關注 context memory 的設計、模態感知任務分解的 prompt 模板、以及子代理專精化的路由邏輯。實作時可先以 GPT-5 作為主代理快速驗證，再評估是否需要以 DA-GRPO 訓練自訂主代理以降低成本。

**給研究者**：第 5 節的 DA-GRPO 演算法與多維度 rubric 獎勵設計是核心創新，建議仔細推導其與傳統 GRPO 的差異，並思考決策對齊機制在其他代理編排任務（如程式碼生成、機器人控制）上的可遷移性。OmniGAIA 基準的設計理念也值得深入研究，作為未來自建基準的參考。

**給產品經理**：聚焦於第 1 節的問題陳述、第 6 節的實驗結果（特別是 OmniGAIA 上 32.8% 與 10.3% 的相對提升），以及 Orchestra-o1-8B 將開源代理從 20.8% 提升至 30.0% 的成本效益意涵。評估導入時應優先考慮「多模態輸入是否為業務核心痛點」與「現有單模態代理是否已遇到瓶頸」兩個問題，避免為導入而導入。
