## 摘要翻譯

僅以結果（Outcome）評估代理（Agent）可能會掩蓋產生這些結果的能力。此問題在演化環境中尤為明顯，在這些環境中，結果反映了代理行為（Agent Behavior）與變動外部條件（External Conditions）之間的閉環互動（Closed-Loop Interaction）。我們提出 LiveMACEBench，一個過程感知基準測試（Process-Aware Benchmark），利用實時金融市場作為持久化大型語言模型代理（Persistent LLM Agents）的自然演化測試平台（Testbed）。五個前沿大型語言模型（Frontier LLMs）在匹配的工具使用（Tool Use）、持久化記憶（Persistent Memory）、規則遵循（Rule Following）與多代理協作（Multi-Agent Collaboration）配置（Configuration）下，沿連續軌跡（Trajectory）持續運作。我們透過已實現結果（Realized Outcomes）與源自完整決策軌跡（Decision Traces）的機制專屬診斷（Mechanism-Specific Diagnostics）來評估它們。在 30 天的實時評估（Live Evaluation）中，我們發現一個突出的結果—能力差距（Outcome-Capability Gap）：已實現報酬常與能力專屬測量（Capability-Specific Measurements）背離，且相似的結果可能源自截然不同的機制使用（Mechanism Use）模式。軌跡層級診斷（Trace-Level Diagnostics）進一步揭示各能力間存在不同的瓶頸（Bottleneck），證明機制存取（Mechanism Access）、有效的機制使用（Effective Mechanism Use）與下游表現（Downstream Performance）並非可互換的代理能力（Agent Capability）衡量標準。LiveMACEBench 使此區別變得可衡量，將實時市場從表現排行榜（Performance Leaderboard）轉化為代理能力的診斷環境（Diagnostic Environment）。

### 核心貢獻（3～5點）
- 提出 LiveMACEBench，首個以實時金融市場作為自然演化測試平台（Testbed）的過程感知基準測試（Process-Aware Benchmark），用於評估持久化大型語言模型代理（Persistent LLM Agents）。
- 揭示「結果—能力差距」（Outcome-Capability Gap），證明僅以結果指標衡量代理能力會掩蓋真實的能力差異，尤其在演化環境中。
- 提供機制專屬診斷（Mechanism-Specific Diagnostics），從完整決策軌跡（Decision Traces）中區分機制存取（Mechanism Access）、有效的機制使用（Effective Mechanism Use）與下游表現（Downstream Performance）三個不可互換的能力維度。
- 透過 30 天實時評估與五個前沿大型語言模型（Frontier LLMs）的對比實驗，展現軌跡層級診斷（Trace-Level Diagnostics）如何揭示不同能力間的瓶頸（Bottleneck）差異。
- 將實時市場從單純的表現排行榜（Performance Leaderboard）轉化為代理能力的診斷環境（Diagnostic Environment），推動評估典範從「結果導向」轉向「過程感知」。

### 適合對象
從事大型語言模型代理（LLM Agent）研究與開發的學者與工程師，特別關注代理能力評估、過程診斷、工具使用與多代理協作等議題者；以及對金融市場中人工智慧應用、基準測試設計與演化環境下代理行為分析感興趣的研究人員。

## 深度分析

#### 方法論解析

LiveMACEBench 的方法論核心在於將「代理能力評估」從單純的結果測量轉變為多層次的過程感知診斷框架。其設計哲學建立在三個關鍵區分之上：**機制存取（Mechanism Access）**、**有效的機制使用（Effective Mechanism Use）**、以及**已實現任務效益（Realized Task Benefit）**——三者被論文明確指出為不可互換的能力測量維度。

**環境設計層面**，論文選擇即時金融市場（加密貨幣與美國股票市場）作為自然演化的測試平台，此選擇具有深層方法論意涵：市場價格與資訊持續受外部力量驅動而演化，創造出「閉環互動（Closed-Loop Interaction）」條件——代理行為與外部條件變化相互影響，使結果無法單純歸因於代理本身。論文採用模擬交易（Paper-Trading）環境，每個代理維護不可重置的帳戶狀態，確保動作具有跨時間的持續後果。

**時間結構設計**採用四小時為週期的決策輪（Decision Rounds），所有代理在共享的決策時間網格上同步運作。每個決策輪內，代理可執行多次推理與工具互動步驟，並在終止前發出零或多個交易動作。論文將輪內完整的模型回應、工具呼叫、工具輸出與動作序列記錄為**決策軌跡（Decision Traces）**，這是過程診斷的原始資料來源。值得注意的是，雖然實驗觀察於有限窗口內，但底層互動「無任務定義的終止狀態」，這與傳統基準測試的有限任務設定形成鮮明對比。

**配置設計層面**採用控制變量原則，在共同的 ReAct 框架（ReAct Scaffold）上構建五種匹配配置（Matched Configurations）：
1. **基礎配置（Base Configuration）**：標準 ReAct 流程，作為參照基準
2. **工具使用（Tool Use）**：透過動態路由存取大型異質工具空間，超越固定工具集
3. **持久化記憶（Persistent Memory）**：跨決策輪的經驗累積與檢索機制
4. **規則遵循（Rule Following）**：引入階層式交易規則，區分硬約束（R0、R1）與低優先級偏好（R2）
5. **多代理協作（Multi-Agent Collaboration）**：多個代理間的證據整合與協調

此設計的精妙之處在於「匹配骨幹模型、匹配環境、匹配互動協議」，使能力差異與失敗模式可被**定位（localized）**而非僅從聚合表現中推斷。

**評估訊號層面**整合三種互補測量：
- **任務結果（Task Outcomes）**：測量代理達成什麼
- **受控機制效應（Controlled Mechanism Effects）**：測量引入機制後產生什麼變化
- **過程診斷（Process Diagnostics）**：特徵化機制是否被使用以及如何被使用

此三層架構對應論文中反覆強調的「結果—能力差距（Outcome-Capability Gap）」問題——僅測量結果會混淆上述三個獨立維度。

#### 實驗數據解讀

實驗設置為五個前沿大型語言模型（Frontier LLMs）在 30 天實時評估窗口內的持續運作，橫跨加密貨幣與美國股票市場。雖然具體模型名稱與數值結果未在提供的文本中完整呈現，但論文摘要與引言揭示了幾項關鍵實驗發現：

**核心發現一：結果—能力差距的顯著性**。論文報告報酬排名（Return Rankings）隨時間大幅波動，且經常與能力專屬測量（Capability-Specific Measurements）出現分歧。這意味著單純以最終報酬排名評估代理會產生誤導——同一排名可能源自截然不同的能力組合與機制使用模式。

**核心發現二：相似結果的多重路徑**。論文明確指出「相似結果可能源自截然不同的機制使用模式」，這是過程感知評估的核心論證之一。具體而言，軌跡層級診斷（Trace-Level Diagnostics）揭示了不同代理即使達成相近的最終報酬，其內部決策過程——資訊蒐集（Information Gathering）、經驗重用（Experience Reuse）、約束遵循（Constraint Following）、協調（Coordination）——可能存在質性差異。

**核心發現三：跨能力的瓶頸異質性**。論文識別出四類具體瓶頸：
1. **冗餘的工具互動（Redundant Tool Interactions）**：在工具使用配置中，代理可能反覆呼叫相同或相似工具，未能有效整合證據
2. **無效的記憶重用（Ineffective Memory Reuse）**：在持久化記憶配置中，代理雖具備存取機制，但未能有效檢索或應用先前經驗
3. **不可稽核的規則執行（Unauditable Rule Execution）**：在規則遵循配置中，代理可能聲稱遵循規則但實際行為與規則不一致
4. **有限證據整合（Limited Evidence Integration）**：在多代理協作配置中，代理間未能有效整合多元證據

這些發現的方法論意義在於：它們證明了「機制可用性」、「機制使用率」與「已實現表現」捕捉了代理評估的不同維度，無法相互替代。

**評估指標的時間解析度**值得注意：雖然決策以四小時為週期，但交易結果（如報酬）以更細的時間間隔透過帳戶權益檢查點（Account-Equity Checkpoints）評估（參見附錄 B.1），這避免了「決策時刻」與「市場變化時刻」之間的時序錯位問題。

#### 與現有研究的比較

**相較於靜態任務基準測試**，LiveMACEBench 的核心改進在於從「封閉式任務」轉向「開放式、長時程、動態互動（Long-Horizon and Dynamic Interaction）」評估。論文引用文獻 [4–7] 指出近期代理基準測試已開始朝此方向演進，但 LiveMACEBench 的獨特貢獻在於將「過程感知」與「受控機制效應」結合，這在現有基準中並未系統性處理。

**相較於其他金融市場代理基準**（引用文獻 [8–10]），LiveMACEBench 採取「互補視角」：既有基準主要關注交易結果，而本文將演化互動本身視為診斷代理能力的工具。這種定位轉變使 LiveMACEBench 從「表現排行榜（Performance Leaderboard）」轉變為「診斷環境（Diagnostic Environment）」。

**相較於 ReAct 原始框架**（引用文獻 [11]），LiveMACEBench 並非提出新的代理架構，而是將 ReAct 作為共同骨幹，在其上系統性地引入四種機制變體。這種「控制變量」設計哲學使能力差異歸因更具因果可信度。

**方法論優勢**包括：
- **因果可歸因性**：透過匹配配置設計，能力差異可被定位而非僅推斷
- **生態有效性（Ecological Validity）**：使用真實即時市場，而非模擬環境
- **過程可追溯性**：完整決策軌跡支援細粒度診斷
- **持續性評估**：無任務定義的終止狀態，支援長期能力觀察

**潛在限制**包括：
- **領域特殊性**：金融市場特性（價格連續性、外部資訊衝擊、跨資產相關性）可能限制結論對其他領域的可推廣性
- **時間窗口有限**：30 天評估雖具統計意義，但對於「持續代理」的長期能力演化可能仍不足
- **模型數量有限**：僅五個前沿大型語言模型，未涵蓋開源模型或不同規模的模型
- **市場狀態依賴性**：30 天內的市場環境（牛市、熊市、波動率水準）可能影響結果的代表性
- **基準測試的基準問題**：缺乏「人類專家」或「已知最優策略」作為絕對參照

#### 可重現性評估

從提供的文本內容評估可重現性存在若干挑戰：

**正面因素**：
- 論文提供了詳細的設計說明，包括決策輪結構、配置定義、評估協議
- 附錄 B.3 承諾提供詳細的執行時實作（Detailed runtime implementations）
- 附錄 B.1 說明了帳戶權益檢查點的評估機制
- 共同 ReAct 框架與匹配配置設計降低了實作歧義

**挑戰因素**：
- **即時市場依賴性**：使用即時加密貨幣與美國股票市場數據意味著完全相同的實驗無法重現——市場狀態在每次實驗時都不同。這是「自然演化測試平台」的固有權衡：生態有效性 vs 可重現性
- **論文未明確聲明程式碼開源**：從提供的文本中無法確認程式碼、資料集或模型權重是否公開釋出
- **前沿大型語言模型的 API 變動**：實驗依賴的五個前沿大型語言模型可能隨時間更新，導致行為漂移
- **模擬交易環境的具體實作**：帳戶狀態管理、交易執行模擬、滑點與手續費處理等細節對結果有實質影響，需附錄完整說明

**可重現性建議**：
- 若程式碼開源，研究者應能重現配置設計與評估協議，但無法重現特定 30 天的具體結果
- 建議作者提供「歷史回放模式」，允許使用歷史市場資料重現特定時期的評估
- 過程診斷的具體計算方式需明確文檔化

#### 未來研究方向

**方向一：跨領域泛化**。將 LiveMACEBench 的過程感知評估框架從金融市場擴展至其他自然演化環境，例如：即時新聞環境、社交媒體演化、開源軟體專案演化、科學文獻發表流等。這將驗證「結果—能力差距」是否為代理評估的普遍現象。

**方向二：因果機制效應分析**。現有設計測量「引入機制後的變化」，但未深入分析「為何」某些機制在特定代理上產生效益而在其他代理上失效。未來可結合反事實推理（Counterfactual Reasoning）與介入式分析（Interventional Analysis），建立機制效應的因果模型。

**方向三：長期能力演化研究**。30 天窗口對於「持續代理」而言仍屬短期。未來可設計數月乃至跨年的評估，研究代理能力的時間演化、學習效應與能力衰退模式。

**方向四：過程診斷的自動化**。目前過程診斷依賴研究者對軌跡的人工分析與特徵工程。未來可發展基於大型語言模型的自動軌跡分析器，實現可擴展的過程感知評估。

**方向五：代理能力的理論建模**。基於 LiveMACEBench 揭示的「存取—使用—效益」三層結構，未來可發展代理能力的形式化理論模型，預測特定機制組合在特定環境下的表現邊界。

**方向六：人機協作基準**。將人類專家納入評估框架，比較人類與大型語言模型代理在相同演化環境下的能力差異，識別人類獨有的過程特徵（如直覺、風險感知、跨情境類比）。

**方向七：多代理系統的湧現行為**。現有多代理協作配置僅評估「證據整合」，未深入分析代理間湧現行為（Emergent Behavior）對集體能力的影響。未來可設計更複雜的多代理互動協議，觀察分工、競爭、學習傳遞等現象。

**方向八：安全性與對齊評估**。在金融市場等高風險環境中，代理的規則遵循不僅是能力問題，更是對齊問題。LiveMACEBench 的規則遵循配置可擴展為對齊評估工具，測量代理在追求績效時是否會繞過、誤解或策略性忽略約束。

**方向九：基準測試的基準校準**。發展標準化的「能力基準測試」（Capability Benchmarks），使不同 LiveMACEBench 實例的結果可被校準至共同尺度，支援跨研究、跨時期的比較。

這些方向共同指向一個核心願景：將代理評估從「誰贏了」轉變為「為什麼贏」、「如何贏」、「在何種條件下會輸」的深度診斷，最終建立可解釋、可預測、可信賴的代理能力科學。

## 論文問答

**Q1：LiveMACE 試圖解決的核心問題是什麼？**
A：LiveMACE 試圖解決「僅以結果評估代理所產生的能力歸因問題」。在演化中的環境（例如即時金融市場）中，觀察到的結果反映的是代理行為與外部變動條件之間的閉環互動，而非單純的代理能力本身。這使得我們難以判斷一個成功結果究竟來自於代理的哪些具體能力，也無法區分「機制存取」、「有效的機制使用」與「已實現任務效益」這三個本質上不同的概念。

**Q2：為何現有的代理評估方法在演化環境中會失效？**
A：現有方法主要依賴結果指標（如報酬率），但在動態環境中，外部條件會獨立於代理而變化，且早期行動的後果會持續累積。因此，觀察到的表現其實混合了代理能力、累積狀態、環境變異以及三者之間的交互作用，無法單獨歸因於代理本身。此外，當代理配備工具、持久化記憶、明確策略或多代理架構時，「擁有某個機制」並不等於「能有效使用該機制」，更不等於「能帶來更好的下游表現」，這三個層次在結果導向的評估中往往被混為一談。

**Q3：為何「結果—能力差距」的區分對整個領域至關重要？**
A：這個區分之所以重要，是因為隨著代理在長時程互動中變得更加複雜（配備工具、持久化記憶、明確策略、多代理架構），我們需要精確診斷瓶頸究竟出現在哪個環節。軌跡層級診斷能揭示如冗餘的工具互動、無效的經驗重用、不可稽核的規則執行，以及多代理系統中有限的證據整合等具體問題。若不區分這三個層次，領域將無法系統性地改進代理的特定能力，也無法理解為何表現相似的代理可能來自截然不同的機制使用模式。

**Q4：LiveMACE 的核心方法論是什麼？**
A：LiveMACE 的核心方法是將即時金融市場（加密貨幣與美國股票市場）作為自然演化的測試平台，讓五個前沿大型語言模型沿著連續的模擬交易軌跡運行。所有代理共享相同的 ReAct 框架與每四小時一次的決策週期排程，並透過三種互補訊號進行評估：任務結果（衡量達成什麼）、受控機制效應（衡量引入機制後產生什麼變化）、以及過程診斷（衡量該機制是否以及如何被使用）。這種設計將「機制存取」、「有效的機制使用」與「已實現任務效益」三個概念明確分離開來。

**Q5：LiveMACE 相較於既有方法的主要創新為何？**
A：主要創新在於提出「過程感知評估」框架，從完整的決策軌跡中萃取出機制專屬診斷，而非僅僅根據最終結果排名。透過匹配配置（在相同骨幹模型、環境與互動協定下比較基礎、工具使用、持久化記憶、規則遵循、多代理協作等變體），LiveMACE 能夠定位能力差異與失敗模式，而非從聚合表現中推測。這使得即時市場從單純的表現排行榜轉變為代理能力的診斷環境。

**Q6：LiveMACE 在設計上有哪些關鍵選擇？**
A：關鍵設計選擇包括：（1）採用即時金融市場作為自然演化環境，使外部條件持續變化且行動具有持久後果；（2）以四小時為週期的共享決策時間網格組織代理互動，確保所有代理面對相同的演化條件；（3）維持不可重設的帳戶狀態，使早期決策的後果延續至後續回合；（4）使用匹配配置實現受控比較，隔離各機制的獨立效應；（5）記錄完整的決策軌跡（包含觀察、推理、機制互動與行動），為過程診斷提供資料基礎。

**Q7：LiveMACE 在實驗中與哪些基準或方法進行比較？**
A：LiveMACE 並非以單一基準進行直接比較，而是將自身定位為與近期利用即時或實時市場的代理基準互補的研究。LiveMACE 採用五個前沿大型語言模型作為骨幹，並透過五種匹配配置（基礎、工具使用、持久化記憶、規則遵循、多代理協作）形成內部對照，使同一骨幹模型在不同機制下的表現得以直接比較，同時也允許跨骨幹模型在同一配置下的比較。

**Q8：LiveMACE 實驗中最關鍵的發現為何？**
A：橫跨 30 天即時評估的最關鍵發現是「結果—能力差距」極為顯著：報酬排名隨時間大幅波動，且經常與能力專屬測量結果分歧；相似的結果可能來自截然不同的機制使用模式。此外，過程診斷揭示了各能力的不同瓶頸，包括冗餘的工具互動、無效的記憶重用、不可稽核的規則執行，以及多代理系統中有限的證據整合，證實機制可用性、機制利用率與已實現表現捕捉的是代理評估的不同面向。

**Q9：LiveMACE 進行了哪些消融實驗或受控比較？**
A：LiveMACE 的匹配配置設計本身就構成系統性的消融實驗：透過在相同骨幹模型、環境與互動協定下比較基礎配置與各能力變體（工具使用、持久化記憶、規則遵循、多代理協作），可以隔離每個機制的獨立效應。這種受控診斷使能力差異與失敗模式能夠被精確定位，而非從聚合表現中推測，從而驗證了「機制存取」、「有效的機制使用」與「下游表現」三者確實是不可互換的代理能力測量。

**Q10：LiveMACE 的方法適用於哪些實際場景？**
A：LiveMACE 的過程感知評估方法適用於任何需要長時程互動且行動具有持久後果的場景，包括金融交易代理、自主系統、機器人控制、個人 AI 助理等。在這些場景中，僅看最終結果無法判斷代理是否有效運用了可用機制，而過程診斷能幫助開發者識別具體的能力瓶頸，進而針對性地改進。此外，任何外部條件持續演化且需要持續學習與適應的領域，都能從這種評估框架中受益。

**Q11：從產品開發角度，LiveMACE 帶來哪些重要啟示？**
A：從產品角度，LiveMACE 揭示了一個關鍵洞見：單純為代理增加更多機制（工具、記憶、規則、多代理架構）並不能保證更好的表現，必須評估代理是否真正有效地使用了這些機制。診斷框架幫助產品團隊識別哪些能力需要改進（例如某代理雖有記憶功能但未能有效重用經驗），從而更精準地分配研發資源。這也意味著產品設計應從「功能堆疊」轉向「能力驗證」，確保每個機制都帶來實質的已實現任務效益。

**Q12：LiveMACE 對整個 LLM 代理研究領域有何更廣泛的影響？**
A：LiveMACE 將領域的焦點從「哪個代理表現最好」轉向「每個代理具備哪些能力以及瓶頸在哪裡」，這種更細緻的評估框架可能影響代理的設計、訓練與部署方式。它促使研究者不再僅以報酬排名論英雄，而是關注機制使用的品質與效率。此外，將即時市場從表現排行榜轉變為診斷環境的思路，也可能啟發其他演化環境（如氣候模擬、交通系統、社會模擬）中的類似基準設計，推動代理評估走向更成熟、更具診斷性的方向。

**Q13：LiveMACE 存在哪些已承認的限制？**
A：已承認的限制包括：（1）評估僅涵蓋 30 天的有限視窗，可能無法完全捕捉長時程行為模式；（2）聚焦於金融市場，這一環境雖具自然演化特性，但未必能推廣至所有動態環境；（3）評估的五個前沿大型語言模型可能無法代表整個模型生態系；（4）模擬交易環境無法完全捕捉現實世界中的滑點、流動性限制與交易成本等摩擦因素；（5）過程診斷的設計仍依賴研究者對「有效使用」的定義，可能存在主觀性。

**Q14：LiveMACE 揭示了哪些具體的失敗案例？**
A：LiveMACE 透過軌跡層級診斷揭示了多類具體失敗模式：在工具使用方面，代理出現冗餘的工具互動，浪費運算資源卻未帶來更好的決策；在持久化記憶方面，代理未能有效重用過去的經驗，導致重複犯錯；在規則遵循方面，代理執行規則時缺乏可稽核性，難以判斷其推理是否符合約束；在多代理協作方面，代理在證據整合上表現有限，無法有效綜合多方資訊。這些失敗案例凸顯了「擁有機制」與「有效使用機制」之間的鴻溝。

**Q15：基於 LiveMACE 的發現，未來有哪些值得探索的方向？**
A：未來方向包括：（1）將過程感知評估框架擴展至金融市場以外的其他演化環境，如氣候模擬、交通系統或社會動態模擬；（2）開發更精緻的過程診斷指標，以更細粒度地衡量機制使用品質；（3）探索如何針對已識別的瓶頸進行能力導向的訓練與改進；（4）設計結合過程感知評估與更長時程的基準，以驗證能力的持續性與適應性；（5）研究不同代理配置之間的交互效應，例如工具使用與持久化記憶的組合是否產生非線性的能力提升。

## 實務應用指南

### 適用場景

**1. 金融機構的 AI 代理選型與能力盤點**
大型銀行、券商或資產管理公司在導入 LLM 代理輔助投資決策時，可採用 LiveMACEBench 的「匹配配置」方法，在統一的 ReAct 框架下比較不同前沿模型（GPT、Claude、Gemini 等）在工具使用、持久化記憶、規則遵循與多代理協作四個維度的實際能力，避免僅以報酬率排名誤判模型優劣。

**2. 內部代理研發團隊的迭代驗證平台**
AI 工程團隊在開發自有的交易代理時，可將 LiveMACEBench 的「決策軌跡診斷」機制移植到內部 CI/CD 流程中，每次模型或提示詞更新後自動跑 30 天模擬，透過軌跡層級診斷找出瓶頸（例如冗餘工具呼叫、無效記憶重用），而非僅看最終損益。

**3. 監理科技（RegTech）合規測試環境**
金融監理機關或合規部門可用此框架驗證 AI 代理在高層次偏好（R2）與硬性約束（R0、R1）之間的遵循行為，特別是「不可審計的規則執行」這類瓶頸，能在實際上線前量化代理對監管規則的遵守程度。

**4. 多代理投顧系統的協作能力評估**
針對正在興起的多代理投顧架構（例如研究代理、風控代理、執行代理分工），可利用 LiveMACEBench 的多代理協作配置，量化「證據整合不足」等瓶頸，評估不同模型在分散式決策下的資訊彙整能力。

**5. 學術界對長時程代理能力的基準研究**
研究人員可將 LiveMACEBench 作為「自然演化測試平台」的範本，擴展至其他動態環境（如即時新聞流、動態定價市場、網路安全攻防），研究結果—能力差距（outcome–capability gap）在不同領域的表現。

### 實作前置條件

**資料需求**
- 即時市場資料流：至少需接入一家加密貨幣交易所（如 Binance、Coinbase）的 WebSocket API，以及美國股票市場的即時報價（如 Polygon、IEX Cloud、Alpaca）。
- 歷史 K 線與訂單簿資料：用於回填背景上下文、計算技術指標，至少 90 天的 1 分鐘級資料。
- 外部資訊源：新聞 API（如 CryptoPanic、Benzinga）、社群情緒資料（可選），供代理在決策回合中蒐集證據。
- 帳戶狀態儲存：非可重置的持久化帳本（positions、cash、PnL），需用時序資料庫（如 TimescaleDB、InfluxDB）。

**運算資源**
- LLM 推論：每 4 小時一次的決策回合 × 5 個配置 × 5 個模型 × 30 天 ≈ 4,500 次完整推論；建議配備 A100/H100 等級 GPU 或使用 API（OpenAI、Anthropic、Google）。
- 軌跡儲存：每次決策的完整 trace（觀察、推理、工具呼叫、輸出）平均數 KB 至數 MB，30 天約需數十 GB 儲存空間。
- 排程與監控：需要穩定的 cron / Airflow 排程系統，確保 4 小時決策網格不漏點。

**技能門檻**
- LLM 工程：熟悉 ReAct 框架、工具呼叫（function calling）、提示詞工程。
- 金融市場知識：理解訂單類型、保證金、結算機制、技術指標。
- 評估方法論：能設計對照實驗、區分「機制存取」「有效使用」「下游表現」三個層次。
- 軌跡分析：具備從非結構化日誌中萃取結構化診斷指標的能力（正規表達式、LLM-as-judge 或規則引擎）。

### 實作步驟建議

**步驟 1：建立共享市場互動協議**
- 部署一個統一的「決策時間網格」服務，每 4 小時觸發一次所有代理的決策回合。
- 實作帳戶狀態服務，確保每個代理的持倉、現金、歷史成交在回合間持久化。
- 接入即時報價與新聞流，提供給所有代理相同的市場快照。

**步驟 2：實作 ReAct 基礎配置**
- 建立 Base 代理：標準 ReAct 循環（Thought → Action → Observation → … → Final Answer）。
- 固定工具集：行情查詢、技術指標計算、下單、查持倉等基礎工具。
- 完整記錄決策軌跡：每個回合的模型回應、工具呼叫、工具輸出、動作皆需結構化儲存。

**步驟 3：建構四個能力變體**
- **工具使用變體**：引入動態工具路由（tool retrieval），擴展工具空間至數十至數百個，評估代理的探索與選擇能力。
- **持久化記憶變體**：實作跨回合的經驗儲存與檢索（向量資料庫 + 摘要機制），追蹤記憶寫入、檢索、重用的頻率與品質。
- **規則遵循變體**：注入階層式規則（硬約束 R0/R1 + 偏好 R2），設計可審計的規則執行日誌。
- **多代理協作變體**：拆分為研究、風控、執行等子代理，設計訊息傳遞與共識機制。

**步驟 4：執行 30 天實時評估**
- 同步啟動所有配置，確保它們暴露在相同的市場條件下。
- 在更細的時間粒度（如每小時）記錄帳戶權益快照，用於計算報酬率。
- 監控排程穩定性、API 配額、模型錯誤率。

**步驟 5：建立三層評估訊號**
- **任務結果**：累計報酬、夏普比率、最大回撤、勝率等傳統指標。
- **受控機制效應**：比較「加入機制前後」的表現差異，量化機制本身的邊際貢獻。
- **過程診斷**：從軌跡中萃取機制專屬指標，例如工具呼叫的重複率、記憶檢索命中率、規則違規次數、代理間訊息整合度。

**步驟 6：產出診斷報告與迭代**
- 將三層訊號彙整為「能力瓶頸圖譜」，標示每個模型在每個維度的具體弱點。
- 針對瓶頸進行提示詞微調、工具集重設計、記憶架構優化。
- 將診斷指標納入版本控制，作為迴歸測試基準。

### 潛在風險與注意事項

**風險 1：將模擬交易結果誤認為實際能力**
- **現象**：30 天報酬排名波動劇烈，可能因短期市場行情而非模型能力造成排名翻盤。
- **緩解**：以能力專屬測量（軌跡診斷）為主要決策依據，報酬率僅作為下游表現的參考指標；延長評估窗口至 90 天以上以平滑雜訊。

**風險 2：軌跡資料洩漏與評估偏誤**
- **現象**：若評估者（LLM-as-judge）看過市場後續走勢，可能對代理的「當下決策」做出事後諸葛亮的評分。
- **緩隔**：嚴格隔離評估時點資訊；採用前瞻性指標（如決策時點的資訊比率）而非事後指標。

**風險 3：前沿模型 API 成本與配額限制**
- **現象**：5 模型 × 5 配置 × 30 天 × 每回合多次推論，API 成本可能達數千至數萬美元。
- **緩隔**：先用較小模型（如 Haiku、Mini）做煙霧測試；對高成本配置縮短評估天數；考慮自架開源模型（Llama、Qwen）作為對照組。

**風險 4：市場極端事件的倖存者偏差**
- **現象**：30 天內若未遭遇重大崩盤或暴漲，無法評估代理在壓力下的行為。
- **緩隔**：刻意選擇包含已知波動事件的歷史回放窗口；或注入合成衝擊事件測試穩健性。

**風險 5：規則遵循的「不可審計執行」瓶頸**
- **現象**：代理可能在推理中提及規則，但實際下單時未真正套用規則邏輯。
- **緩隔**：設計結構化規則檢查器（rule checker），在動作執行前強制驗證；將違規事件獨立計入診斷指標。

**風險 6：多代理系統的「證據整合不足」**
- **現象**：子代理各自產出結論，但缺乏有效的彙整機制，導致最終決策忽略部分證據。
- **緩隔**：設計明確的整合代理（integrator）或投票機制；追蹤每條證據是否被最終決策引用。

### 與其他技術的整合建議

**1. 與 MLOps / LLMOps 平台整合**
- 將 LiveMACEBench 的評估流程封裝為可重複執行的 pipeline（Kubeflow、Metaflow、LangSmith）。
- 軌跡資料接入特徵儲存（Feast、Tecton），支援跨實驗的指標對比與儀表板視覺化（Grafana、Weights & Biases）。

**2. 與既有交易系統整合**
- 將代理輸出對接至 OMS（Order Management System）或 EMS（Execution Management System），支援從模擬交易平滑過渡到小額實盤測試。
- 風控引擎（如自家風控模組或 Riskified 等）作為規則遵循變體的外部審計層。

**3. 與監控與可觀測性工具整合**
- 決策軌跡接入 OpenTelemetry，支援分散式追蹤與異常告警。
- 使用 Langfuse、Helicone 等 LLM 可觀測性工具記錄每次推論的延遲、成本、錯誤率。

**4. 與知識管理系統整合**
- 持久化記憶變體可對接企業知識庫（Notion、Confluence）作為長期記憶後端。
- 規則遵循變體可從合規政策管理系統（如 GRC 平台）自動同步規則定義。

**5. 與基準測試生態系整合**
- 將 LiveMACEBench 的診斷指標貢獻至 HELM、AgentBench 等開源基準，促進跨環境比較。
- 採用 lm-evaluation-harness 的介面標準化模型載入與評估流程。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節的「結果—能力差距」概念，理解為什麼僅看投資報酬率不足以評估 AI 代理。接著重點閱讀第 2.2 節的五種配置說明，把它們想像成「考試的五種題型」，每種題型考驗代理的不同能力。暫時跳過技術細節，先建立「過程比結果更重要」的直覺。

**給 AI 工程師**：重點閱讀第 2.1 節的決策回合設計與第 2.2 節的 ReAct scaffold 實作細節（附錄 B.3），理解如何在生產環境中部署持久化代理。特別注意「決策軌跡」的結構化記錄方式，這是後續所有診斷的基礎。建議直接動手實作 Base 配置，再逐步加入其他變體。

**給研究者**：第 1 節的歸因問題（attribution problem）與結果—能力差距是本論文的核心理論貢獻，值得深入推敲其在非金融領域的適用性。第 3 節的實驗結果（軌跡層級診斷與瓶頸分析）是方法論的具體展現，可作為設計新基準的範本。建議同時閱讀附錄中的評估指標定義與統計檢定方法。

**給產品經理**：聚焦於「為什麼我們不能只看排行榜」這個商業意涵。LiveMACEBench 將市場從「表現排行榜」轉化為「診斷環境」，這個定位轉換對產品差異化極具啟發。閱讀時請思考：你的 AI 產品目前是用「結果指標」還是「能力指標」在說故事？客戶買的是結果還是能力？這將直接影響你的產品定位與定價策略。
