## 深度分析

#### 方法論解析

WebRISE 的核心方法論是將 Multimodal Large Language Model（多模態大型語言模型, MLLM）生成的 Web Artifact（網頁產物）評估問題，重新框架為 Requirement-Induced State Evaluation（需求誘導狀態評估）。具體而言，其將 Task Requirement（任務需求）編譯為 Interaction Contract Graph（互動合約圖, ICG），該圖由三個基本要素構成：Observable State（可觀測狀態）、User-intent Transition（使用者意圖轉換），以及 DOM Assertion（DOM 斷言）與 Visual Assertion（視覺斷言）。

ICG 的設計體現了兩項關鍵選擇。第一，Requirement-conditioned State Modeling（以需求為條件的狀態建模）：每個任務被表示為一張有限狀態轉移圖，節點為需求所誘導的 Observable State，邊為使用者意圖驅動的 Transition。這使得評估對象從「局部動作是否產生回應」轉變為「需求所規範的狀態空間是否被完整覆蓋」。第二，Conformance-based Diagnostic Evaluation（基於符合性的診斷式評估）：透過 Implementation-agnostic（與實作無關）的 Browser Execution（瀏覽器執行），由合約導引的智慧體自適應地執行轉換，並將結果連結回 Explicit Check（顯式檢查）與 Implicit Check（隱式檢查）。顯式檢查對應 User-stated Function（使用者明述功能），隱式檢查則捕捉 Implicit Product-level Constraint（隱含產品層級限制），例如跨元件的狀態同步、分頁與篩選器的連動、刪除後計數更新等。

執行層面，WebRISE 採用 Adaptive Execution（自適應執行）。不同於 Script-based Evaluation（基於腳本的評估）使用固定選擇器，WebRISE 的 Agent 透過 Indexed DOM Element（索引化 DOM 元素）與 DOM Mutation（DOM 變異）觀察頁面變化，依據 ICG 的當前狀態動態決定下一步動作。這解決了傳統固定路徑無法適應不同實作的問題。最終，系統輸出 Transition-level Evaluation（轉換層級評估）的裁決，並以 Sequential Screenshot（序列截圖）與結構化證據記錄整個過程，實現 Behavior-level Evaluation（行為層級評估）而非僅止於外觀比對。

#### 實驗數據解讀

WebRISE 的規模涵蓋 442 個任務，橫跨五種 Input Modality（輸入模態）：Text（文字）、Markdown、Sketch（草圖）、Image（圖像）與 Video（影片），共計 5,495 個 Transitions 與 5,271 個 Requirement Check（需求檢查）。這樣的規模足以支撐對 14 個代表性 MLLM 的嚴格評測。

整體性能天花板顯著偏低：即便是最強的 GPT-5.5，在其最佳模態下也僅達到 Transition Validity（轉換有效性）T = 65.6% 與 Requirement Coverage（需求覆蓋率）R = 66.3%，顯示超過三分之一的必要轉換或需求檢查未被滿足。這說明互動式網頁生成距離實用化仍有極大落差。

數據中最具警示性的發現是 Visual Quality（視覺品質）並非行為的 Proxy（代理指標）。以 Qwen3.6-35B-A3B 在 Markdown 模態為例，其視覺分數 V = 80.8，但 Transition Validity T 僅 15.5。這強烈證明「看起來正確（Looks Right）」與「實際運作正確（Works Right）」存在結構性脫鉤，傳統 Appearance-based Evaluation（基於外觀的評估）無法發現深層行為缺陷。

模態比較方面，Video（影片）提供了最強的 Interaction Signal（互動訊號）。相較於 Text，Video 在 Transition Validity、Requirement Coverage 與 Implicit Coverage（隱含覆蓋率）上分別提升 8.8、8.3 與 10.6 個百分點（percentage points, pp）。這暗示動態的互動示範比靜態規格更能傳達隱含狀態約束。

進一步拆解 Explicit 與 Implicit 需求發現：Explicit Check（顯式檢查）在各模型間相對容易達成，而 Implicit Product-level Constraint（隱含產品層級限制）則是持續的瓶頸。困難任務的錯誤模式富含回饋、錯誤、邊緣狀態與邊界條件失敗，顯示模型在處理跨步驟、跨視圖的狀態一致性上仍顯脆弱。

最後，Defect Injection（缺陷注入）實驗驗證了 ICG-based Scoring（基於 ICG 的評分）的診斷力。在 25 個注入的狀態相關缺陷中，ICG 方法檢出 16 個，而 Checkpoint-style Evaluation（檢查點式評估）在寬鬆設定下僅檢出 8 個，嚴格設定下更只有 1 個。這代表 ICG 對 State Error（狀態錯誤）的偵測率達到 Checkpoint-style 的 2–16 倍，凸顯其行為層級診斷優勢。

#### 與現有研究的比較

現有網頁生成評估可大致分為四類：Exploration-based Evaluation（基於探索的評估）、Checkpoint-based Evaluation（基於檢查點的評估）、Script-based Evaluation（基於腳本的評估）與 Appearance-based Evaluation（基於外觀的評估）。這些方法共同的特徵是依賴 Local Evidence（局部證據），並呈現 Modality-fragmented（模態碎片化）、Shallow Oracle（淺層預言機）與 Weakly Diagnostic（弱診斷性）等缺陷。

具體而言，現有研究存在兩項結構性限制。其一，Event-centric Evaluation（以事件為中心的評估）：Screenshot、腳本步驟、影片軌跡或預期結果檢查點只能驗證局部動作是否產生回應，但無法明確定義哪些 Requirement-induced States 與 Transitions 應被覆蓋。這導致評估只能回答「有反應」，無法回答「反應是否正確且完整」。其二，State-consistency Gap（狀態一致性缺口）：局部回應可能通過，即使頁面違反了跨元件（cross-component）、跨視圖（cross-view）或跨步驟（cross-step）的限制，例如篩選器與分頁的同步、刪除後的計數更新、導航後的隱藏狀態保留等。傳統方法讓互動「可被觀察」，但尚未讓互動「可被列舉且可歸因於需求狀態空間」。

相較之下，WebRISE 提出 Requirement-driven（需求驅動）、Behavior-level Evaluation（行為層級評估）與 Implementation-agnostic（與實作無關）的範式。透過 ICG，WebRISE 將評估從「單一結果」提升為「狀態空間的符合性」；透過 Transition-level Evaluation，將診斷粒度從「頁面層級」細緻化到「轉換層級」；透過 Adaptive Execution，擺脫固定選擇器的束縛，真正實現「Works Right, not Looks Right」的評估哲學。

然而，WebRISE 目前聚焦於單一網頁產物的互動合約，對於涉及後端狀態持久化、多裝置同步或複雜異步流程的評估，其 ICG 的表達力可能仍有邊界。

#### 可重現性評估

論文提供了專案網址 https://iigroup.github.io/WebRISE，這是驗證與重現的基礎入口。不過，從提供的全文脈絡觀察，論文標註為 Under Review（審查中），這意味著完整的原始碼、資料集與模型權重之開放程度尚待正式出版後確認。

目前可推論的重現要素包括：評測框架中 ICG 的建構邏輯、DOM/visual assertions 的定義方式，以及 Contract-guided Agent 的執行流程已在方法論章節詳述；442 個任務與五種模態的具體數量為重現提供了量化基準；14 個 MLLM 的測試結果與 Defect Injection 的對照實驗設計，亦具備明確的 Protocol。

待釐清的項目則包括：ICG 是否以自動化方式從自然語言或影片生成，抑或需人工編纂；Requirement Check 的標註準則與 Implicit Constraint 的抽取規則是否公開；以及 Browser Execution 環境的具體版本與相依性。建議作者群遵循開源基準測試的標準實踐，釋出 Docker 化執行環境與 ICG 資料集，以確保社群能複製其 Transition-level 的評估結果。

#### 未來研究方向

基於 WebRISE 的發現與方法論，後續研究可沿以下方向展開。

第一，隱含限制的自動推論與增強訓練。既然 Implicit Product-level Constraint（隱含產品層級限制）是主要瓶頸，未來可探索從影片或高階規格自動推論隱含狀態約束的技術，並將其作為 MLLM 的訓練信號，以提升跨元件狀態同步的生成能力。

第二，動態模態融合策略。Video（影片）模態顯著優於 Text，但成本較高。研究可聚焦於如何設計動態模態選擇機制，或將 Video 的 Interaction Signal（互動訊號）蒸餾為輕量化的結構化提示，以兼顧效能與效率。

第三，視覺品質與行為一致性的對齊。視覺分數與轉換有效性嚴重脫鉤，暗示現有 MLLM 的視覺編碼器與互動邏輯模組間存在表徵斷層。未來可發展聯合訓練目標，讓視覺外觀的優化同時考量狀態轉移的語義正確性。

第四，ICG 的自動化建構與擴展。目前 ICG 可能涉及大量人工編纂。開發能從多模態需求自動生成 ICG 的模型，並將其擴展至更複雜的應用程式（如多頁面應用、漸進式網頁應用程式），是提升基準可擴展性的關鍵。

第五，診斷導向的模型微調。WebRISE 提供了細緻的 Transition-level 錯誤定位。利用這些結構化錯誤回饋進行強化學習或指令微調，有望直接改善 MLLM 在網頁生成上的 State Error（狀態錯誤）率。

第六，跨平台與跨裝置狀態評估。將 Requirement-Induced State Evaluation（需求誘導狀態評估）從單一瀏覽器頁面擴展至跨裝置互動、後端資料持久化與即時協作場景，建立更廣義的 Interaction Contract 理論框架。

## 論文問答

**Q1：WebRISE 旨在解決現有網頁產物評測中的什麼核心問題？**
A：WebRISE 針對的核心問題是，現有基準大多僅依賴局部證據（如外觀、腳本或檢查點）來評估互動，卻忽略了決定頁面是否真正可用的需求誘導狀態與轉換。傳統方法雖能觀察到局部動作是否產生回應，但無法明確列舉任務需求所隱含的可觀測狀態空間，導致評測結果與實際可用性脫節。這種侷限使得生成的網頁產物可能在視覺上合理，卻在跨元件或跨步驟的狀態一致性上出現嚴重缺陷。

**Q2：為何現有的評測方法無法充分評估多模態大型語言模型生成的網頁產物？**
A：現有方法主要存在兩大侷限：事件中心評測與狀態一致性缺口。事件中心評測僅能透過截圖、腳本步驟或檢查點軌跡驗證局部動作回應，卻無法定義需求所誘導的狀態與轉換應被完整覆蓋；狀態一致性缺口則使局部回應即使通過，頁面仍可能違反跨元件、跨視圖或跨步驟的限制，例如篩選器與分頁未同步。因此，現有基準雖讓互動變得可觀察，卻尚未達到可完全列舉且可歸因於需求的水準。

**Q3：相較於僅評估視覺外觀，為何評估需求誘導狀態更為重要？**
A：在實際使用中，網頁產物即使具備預期的控制項且視覺品質良好，仍可能因狀態轉換錯誤而無法正常運作，例如篩選條件未改變項目列表，或購物車更新未反映至總價。視覺品質並非行為的代理指標，例如 Qwen3.6-35B-A3B 在 Markdown 模態下視覺分數高達 80.8，轉換有效性卻僅有 15.5。透過評估需求誘導狀態，WebRISE 能同時檢驗使用者明述功能與隱含產品層級限制，確保頁面不僅「看起來對」，更「確實能用」。

**Q4：WebRISE 的核心方法論是什麼？**
A：WebRISE 的核心方法論是需求條件化狀態建模，即將任務需求編譯為互動合約圖（ICG），以可觀測狀態、使用者意圖轉換及 DOM／視覺斷言構成有限互動合約。此方法透過與實作無關的瀏覽器執行，驗證生成頁面是否符合該合約所定義的狀態轉換空間。相較於傳統的局部證據檢查，這種方法將評測重新定義為對需求誘導的可觀測狀態轉換一致性的系統性驗證。

**Q5：互動合約圖（ICG）的關鍵創新體現在哪些方面？**
A：ICG 的關鍵創新在於從模態碎片化、淺層預言機轉向需求驅動的行為層級評估，明確建模由任務需求衍生的狀態與轉換。它將使用者明述功能與隱含產品層級限制分離，使評測具備診斷性，能將轉換結果歸因於特定需求或限制。此外，ICG 支援自適應執行，透過合約導引的智慧體在瀏覽器中執行轉換，並以 DOM 變異與序列截圖驗證過程與結果證據，而非僅依賴固定腳本或單一檢查點。

**Q6：WebRISE 在設計上與傳統基準有何關鍵區別？**
A：WebRISE 的設計建立在兩大關鍵選擇之上：需求條件化狀態建模與基於一致性的診斷評估。前者將每項任務表示為互動合約圖，而非固定路徑的腳本或檢查點序列，從而實現與實作無關的狀態空間列舉；後者則將轉換結果連結回顯式需求與隱式狀態一致性限制，提供結構化證據說明網頁產物為何失敗。這種設計使評測不僅能判斷通過與否，更能精確定位狀態層級的錯誤根源。

**Q7：WebRISE 基準的規模與涵蓋範圍為何？**
A：WebRISE 涵蓋 442 項任務，橫跨文字、Markdown、草圖、圖像與影片五種輸入模態，共計 5,495 個轉換與 5,271 項需求檢查。此規模使研究者能系統性地比較不同豐富輸入對生成品質的影響，並同時檢驗顯式與隱式需求。透過將使用者明述功能與隱含產品層級限制分開處理，該基準能更細緻地診斷模型在功能實現與狀態一致性上的表現差異。

**Q8：實驗中 14 個多模態大型語言模型的關鍵結果為何？**
A：實驗顯示，即使是最強大的模型，在其最佳模態下也僅達到 65.6% 的轉換有效性與 66.3% 的需求覆蓋率，顯示互動式網頁生成仍是未解決的挑戰。多模態規格有助於提升互動品質，其中影片提供最強的互動訊號，相較於文字能將隱含覆蓋率提升 10.6 個百分點。然而，隱含限制仍是所有模型的一致瓶頸，且視覺品質無法作為行為的代理指標，證明僅憑外觀評分無法反映真實可用性。

**Q9：缺陷注入研究揭示了 ICG 評分的哪些優勢？**
A：缺陷注入研究顯示，基於 ICG 的評分在偵測狀態相關缺陷方面遠優於檢查點式評估，在 25 個注入缺陷中偵測到 16 個，而寬鬆的檢查點標準僅偵測到 8 個，嚴格標準更只有 1 個。這代表 ICG 評分對狀態錯誤的偵測率達到傳統方法的 2 至 16 倍。此結果證實，評估需求誘導的狀態轉換對於捕捉局部證據評測所系統性遺漏的細微錯誤至關重要。

**Q10：WebRISE 可應用於哪些實務場景？**
A：WebRISE 可應用於任何多模態大型語言模型從多樣規格生成可執行網頁產物的場景，例如將草圖或影片轉為功能原型、依據 Markdown 生成儀表板，或從文字描述建構互動介面。由於其與實作無關的設計，它能評測來自不同生成管線的輸出，無需針對特定模型進行調整。產品團隊與研究人員可利用 WebRISE 在部署前確認生成頁面不僅符合可見功能需求，也滿足隱藏的狀態一致性限制。

**Q11：WebRISE 對開發者揭示了哪些產品層級的考量？**
A：WebRISE 揭示產品層級的品質保證必須超越視覺迴歸測試或靜態檢查點驗證，涵蓋跨狀態轉換的行為一致性。開發者應特別注意隱含限制，例如篩選器與分頁的同步、或導覽後的狀態保留，因為這些往往是生成產物失敗之處，即使顯式功能看似正常運作。評測管線必須驗證 DOM 變異與視覺狀態序列，而非僅檢查最終截圖或孤立元素是否存在，才能確保網頁產品真正可用。

**Q12：WebRISE 可能對多模態網頁生成領域帶來什麼影響？**
A：WebRISE 透過將評測焦點從表面外觀指標轉向嚴謹的需求誘導行為驗證，為生成式網頁產物建立了新的評測標準。它證明即使頂尖模型仍有約三分之一的需求未被滿足，為領域提供了明確的改進路徑與共同的比較基準。此外，其對五種輸入模態的支援也鼓勵開發更強健的多模態理解與生成系統，使多樣規格能更可靠地轉換為可運作的程式碼。

**Q13：WebRISE 承認哪些侷限性？**
A：WebRISE 承認隱含限制仍是持續存在的瓶頸，所有模型在隱式檢查上的表現均遜於顯式檢查。儘管影片提供了最強的互動訊號，各模態之間仍存在顯著差距，顯示現有多模態大型語言模型對動態互動語義的理解仍不足。此外，目前的 442 項任務雖具代表性，但仍屬有限的網頁互動模式樣本，可能未涵蓋所有複雜的真實世界應用場景。

**Q14：受測模型最常見的失敗案例類型為何？**
A：最常見的失敗案例出現在富含回饋機制、錯誤處理、邊緣狀態與邊界條件的困難任務中，模型無法維持跨元件的狀態一致性。隱含產品層級限制——例如確保使用者操作正確傳遞至應用程式狀態——即使在局部視覺元素正確渲染時仍持續被違反。這些失敗顯示模型經常生成看似合理但功能上脆弱的網頁產物，無法符合完整的互動合約。

**Q15：WebRISE 對未來研究提出哪些方向？**
A：未來研究應著重提升多模態大型語言模型對隱含限制與動態狀態轉換的理解，特別是超越現有 442 項任務的複雜互動模式。擴展基準以涵蓋更進階的網頁應用——如即時資料同步或複雜驗證流程——將能進一步壓力測試生成能力。此外，開發更強大的合約導引智慧體與更豐富的多模態訓練訊號（尤其是影片）有助於縮小視覺合理性與功能正確性之間的落差。

## 實務應用指南

### 適用場景

1. **多模態 AI 網頁生成工具的內部驗收與模型選型**  
   當團隊導入或自研可接受文字、草圖、影片等輸入模態並輸出網頁產物的多模態大型語言模型時，可利用 WebRISE 的需求誘導狀態評估框架，建立標準化的互動合約圖（ICG），比較不同模型在轉換有效性與需求覆蓋率上的差異，避免僅憑視覺品質選型。

2. **低程式碼／無程式碼平台的 AI 產出驗證**  
   針對 Sketch-to-Code、Figma-to-HTML 或影片示範轉互動原型等場景，平台營運方可將使用者上傳的素材編譯為 ICG，透過瀏覽器執行驗證生成結果是否滿足使用者意圖轉換與隱含產品層級限制，例如篩選器與分頁同步、購物車金額即時更新等跨元件狀態一致性。

3. **電商與金融業互動式元件的回歸測試**  
   對於具有複雜狀態機的網頁應用（如多步驟表單、商品篩選、交易流程），可將產品需求文件（PRD）轉譯為可觀測狀態與 DOM／視覺斷言，取代傳統基於檢查點或腳本的局部驗證，以行為層級評估捕捉傳統截圖比對無法發現的狀態錯誤。

4. **第三方 AI 網頁生成服務的採購評估**  
   企業在評估外部供應商（如自動生成 Landing Page 的 SaaS）時，可採用 WebRISE 的與實作無關評測協定，統一以需求驅動的轉換層級指標驗收交付物，降低因供應商前端框架差異導致的測試碎片化。

5. **數位學習與政府服務的無障礙及功能合規檢查**  
   針對需符合法規或無障礙規範的網頁產物，除了靜態結構檢查外，可透過 ICG 驗證鍵盤操作、焦點管理與動態內容更新後的狀態可達性，確保功能正確性與合規性並重。

### 實作前置條件

**資料準備**
- 結構化任務需求庫：需具備明確的使用者明述功能與可列舉的隱含產品層級限制，作為編譯互動合約圖的來源。
- 基準真相（Ground Truth）頁面：用於缺陷注入驗證，確認評測系統對狀態錯誤的靈敏度。
- 多模態輸入資產：涵蓋文字、Markdown、草圖、圖像、影片五種輸入模態的標準化語料與前處理管線。

**運算資源**
- 瀏覽器自動化叢集：需部署基於 Playwright 或 Puppeteer 的無頭瀏覽器叢集，支援並行瀏覽器執行與序列截圖儲存。
- 多模態模型推論環境：具備 GPU 的叢集，用於執行受測多模態大型語言模型與輔助驗證用的視覺語言模型。
- 儲存與比對基礎設施：用於留存 DOM 變異紀錄、索引化 DOM 元素快照，以及執行視覺斷言所需的像素級或語意級比對。

**技能組合**
- 前端工程與瀏覽器自動化：熟悉 DOM 結構、事件傳遞與現代前端框架生命週期。
- 需求工程與形式化建模：能將產品需求轉譯為狀態空間與轉換規則，具備圖結構設計能力。
- 評測指標設計：理解轉換有效性、需求覆蓋率與隱含覆蓋率的統計邏輯，並能設計對應的儀表板。

### 實作步驟建議

**步驟一：需求解構與 ICG 建構**  
將產品需求文件或使用者故事拆解為可觀測狀態（如「篩選後列表為空」）與使用者意圖轉換（如「點擊清除按鈕後返回初始狀態」），繪製互動合約圖，並標註每個轉換對應的 DOM 斷言與視覺斷言。

**步驟二：顯式與隱式檢查分離**  
區分使用者明述功能（顯式檢查）與產品隱含限制（隱式檢查），例如「點擊加入購物車」為顯式，「購物車數量與總價同步更新」為隱式，確保兩類需求檢查獨立計分。

**步驟三：瀏覽器執行環境標準化**  
建立與實作無關的測試沙盒，統一瀏覽器視窗尺寸、網路延遲與裝置像素比，避免前端框架或 CSS 預處理器差異影響評測一致性。

**步驟四：自適應代理開發**  
建構合約導向的瀏覽器智慧體，使其能依據 ICG 的當前狀態動態選擇下一個轉換動作，而非沿固定腳本執行，以驗證網頁產物在多元操作路徑下的穩健性。

**步驟五：多模態輸入管線整合**  
針對五種輸入模態建立前處理標準：文字與 Markdown 直接進入結構化解析；草圖與圖像需進行版面與元件識別；影片需抽取關鍵影格與互動訊號，作為生成模型的提示（prompt）。

**步驟六：評測儀表板建置**  
設計視覺化儀表板，即時呈現轉換有效性、需求覆蓋率與隱含覆蓋率，並支援鑽取至單一轉換的 DOM 變異紀錄與序列截圖，作為除錯證據。

**步驟七：缺陷注入驗證**  
定期在基準真相頁面中注入已知狀態錯誤（如取消同步、遺漏邊界條件），驗證基於 ICG 的評分能否以高於檢查點式評估 2–16 倍的比率檢出，確保評測系統本身不失靈。

**步驟八：持續整合閘道化**  
將 WebRISE 接入 CI/CD 流程，設定轉換有效性與需求覆蓋率的門檻值，作為多模態大型語言模型微調後或網頁產物版本發布前的自動化品質閘道。

### 潛在風險與注意事項

- **視覺品質陷阱**：視覺品質並非行為正確性的代理指標。實務上應避免僅以靜態截圖或視覺問答（VQA）分數判斷網頁產物可用，必須搭配轉換層級的行為驗證。
- **狀態空間爆炸**：過度細分可觀測狀態將導致互動合約圖難以維護。建議採用「剛好夠用」的抽象層級，以使用者可感知的功能狀態為邊界，而非細究每個內部變數。
- **隱含需求遺漏**：隱含產品層級限制（如跨頁面狀態保留、錯誤後復原機制）最容易在需求訪談中被忽略。應建立領域知識庫，將常見隱式檢查範本化。
- **選擇器脆弱性**：DOM 斷言不應依賴固定 CSS selector 或 XPath，因前端框架改版易造成測試失效。建議採用語意化標記、ARIA 屬性或視覺特徵進行索引化 DOM 元素定位。
- **多模態語義落差**：影片與草圖雖提供強烈的互動訊號，但在轉譯為結構化任務需求時可能產生歧義。需加入人工校驗或輔助模型進行需求消歧（disambiguation），避免 ICG 本身即存在錯誤前提。

---

### 與其他技術的整合建議

- **CI/CD 管線**：將 WebRISE 嵌入 GitHub Actions、GitLab CI 或 Jenkins，在模型權重更新或網頁產物建置後自動執行互動合約驗證，並將轉換有效性低於門檻的版本標記為封鎖（block）。
- **現有端對端測試框架**：與 Playwright、Cypress 或 Selenium 共存，但將傳統的「檢查點式評估」升級為 ICG 導向的狀態轉換驗證。可複用現有瀏覽器自動化基礎設施，僅替換斷言層邏輯。
- **MLLM 訓練與微調**：將需求覆蓋率與隱含覆蓋率作為強化學習人類回饋（RLHF）或直接偏好最佳化（DPO）的獎勵訊號（reward signal），直接針對行為層級指標優化生成模型。
- **視覺回歸工具**：與 Percy、Chromatic 或 Applitools 整合，由後者負責像素級或組件級視覺比對，WebRISE 則補充互動狀態與功能正確性驗證，兩者互補而非取代。
- **需求管理與協作平台**：與 Jira、Notion 或 Linear 串接，開發外掛將使用者故事（user story）自動編譯為互動合約圖節點，縮短產品經理與測試工程師之間的需求轉譯落差。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議從圖 1 的傳統評估與 WebRISE 對照圖開始，先建立「外觀正常不代表功能正常」的核心直覺。接著聚焦互動合約圖的基本概念——將網頁想像成一台狀態機，每個使用者操作都是一次狀態轉換——不必急著深入 DOM 斷言的技術細節，重點是理解為何局部證據不足以評斷網頁產物是否可用。

**給 AI 工程師**  
請優先研讀多模態輸入管線的實作細節，以及自適應瀏覽器代理如何依據 ICG 進行動態探索。特別注意轉換有效性與需求覆蓋率的計算邏輯，這兩項指標可直接轉化為模型訓練的損失函數或評估閘道。同時留意影片輸入模態相較於文字能顯著提升隱含覆蓋率（+10.6 百分點）的實驗結論，作為設計模型提示策略的參考。

**給研究人員**  
建議深入分析隱含產品層級限制的形式化定義方式，以及缺陷注入實驗的統計設計。論文中 ICG 與傳統檢查點式評估的靈敏度比較（2–16 倍檢出率）是方法論貢獻的核心，可進一步探索將互動合約圖與時序邏輯（LTL）或模型檢測（model checking）結合的理論可能性，提升評估的完備性與自動化程度。

**給產品經理**  
請將注意力放在兩個關鍵結論：第一，即使是最強大的模型，在最佳輸入模態下轉換有效性僅達 65.6%，顯示現階段 AI 網頁生成尚無法直接上線而不經人工驗收；第二，影片作為輸入模態能提供最強的互動訊號，意味著在需求溝通階段，讓使用者錄製操作影片而非僅提供文字描述，可能顯著提升生成品質。這些發現應直接影響您對產品路線圖與風險緩衝期的規劃。
