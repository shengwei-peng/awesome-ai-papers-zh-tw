- **QA 監督**：來自 SightForge 獨立建構的訓練任務

這種設計的關鍵在於：僅答案監督（answer-only supervision）無法告訴模型「該往哪裡看」，而軌跡監督則提供了「如何搜尋」的學習信號。訓練資料量不到 6K 個範例，但產生了顯著的效果。

**方法論的精妙之處**

SightForge 的「盲驗證」（blind verification）設計解決了一個根本性的方法論問題：傳統的標註流程中，驗證者看到草稿答案後會傾向於確認而非獨立重建，這導致「確認偏差」（confirmation bias）。透過讓驗證者在不知道答案的情況下從原始影片重建，NexSight 確保了證據的獨立性與充分性。

#### 實驗數據解讀

**評測結果的關鍵發現**

| 指標 | 數值 | 意義 |
|------|------|------|
| SightLine 最強模型準確率 | 54.52% | 仍有近半任務未解決 |
| 給定標註證據時的準確率 | 79.35% | 揭示「獲取」是瓶頸 |
| 證據獲取帶來的差距 | ~25 個百分點 | 證據搜尋能力是核心瓶頸 |

這個 54.52% vs 79.35% 的對比極具說服力：當模型被直接給予正確證據時，準確率提升近 25 個百分點。這意味著**當前模型的主要失敗模式不是「推理錯誤」，而是「找不到證據」**。這是一個重要的診斷結果，將研究焦點從「更好的推理」轉向「更好的觀察」。

**時間證據召回率的提升**

代理式視窗選擇（agentic window selection）將時間證據召回率從 19.84% 提升至 40.63%，幾乎翻倍。然而，跨視窗計數（cross-window counting）和狀態變化（state change）並未相應改善。這揭示了一個微妙但重要的現象：**找到正確時刻還不夠，還需要整合它們**。單純的時間定位能力不足以解決需要跨時間推理的任務。

**訓練效果的量化分析**

Sight-35B 的訓練效果可從多個維度解讀：

- **互動準確率**：從基礎模型的 21.29% 提升至 42.26%，幾乎翻倍
- **超越同家族 397B 模型**：以 35B 參數量超越 397B 模型，展現了訓練策略的效率
- **能力湧現**：後訓練後開始使用明確的空間檢查（spatial inspection），平均每軌跡 0.72 次呼叫，而基礎模型從未使用此功能
- **最大增益任務類型**：跨視窗計數（+37.50）和狀態變化（+35.19）——恰好是「單純視窗選擇不足以改善」的任務類型

**遷移性評估**

在外部基準上的表現：
- Video-MME Long：+8.22 個百分點（訓練不相交子集上 +9.33）
- LVBench 子集：+8.13 個百分點

這個遷移性證明了 SightForge 建構的訓練任務具有泛化價值，而非僅在 SightLine 上過擬合。

**一個值得注意的負面發現**

文中提到：「允許搜尋時，35B 指令微調模型的分數反而降低（28.06% vs 33.23%）」。這說明**工具存取（tool access）本身並不能保證更好的表現**——模型需要學會「何時使用工具」以及「如何使用工具」，而非僅僅擁有工具。這反駐了「給模型更多能力就會更好」的簡單假設。

#### 與現有研究的比較

**與固定輸入方法的比較**

傳統的長影片理解方法（如 Video-MME、LongVideoBench、LVBench、EgoSchema、HourVideo、MLVU 等）採用固定輸入策略——給定一定數量的幀，讓模型一次性處理。NexSight 的貢獻在於揭示了這種評測方式的根本限制：**它無法區分「找不到證據」和「不理解證據」這兩種失敗模式**。

**與其他代理式方法的比較**

| 方法 | 特點 | NexSight 的差異化 |
|------|------|------------------|
| VideoAgent（Wang et al.） | 迭代式查詢適應觀察 | 缺乏可驗證的任務建構 |
| VideoTree | 樹狀搜尋結構 | 未提供觀察層級評測 |
| Active Video Perception | 主動觀察 | 缺乏軌跡級訓練監督 |
| T* | 高效關鍵幀搜尋 | 未解決驗證問題 |
| LongVT | 全域預覽+原生裁剪 | 缺乏答案隱蔽驗證 |
| VideoSIAH | 證據稀疏 QA+工具整合訓練 | 驗證機制不如 SightForge 嚴謹 |

**與證據評測方法的比較**

NExT-GQA 和 CG-Bench 評測答案紮根（answer grounding），但僅關聯稀疏支持幀。TRACE/VES-Bench 聯合審計解碼幀覆蓋率與答案正確性，但針對排序和計數。NexSight 的獨特之處在於：**將任務建構、評測、訓練統一在同一個「可驗證」原則下**，這是先前工作未嘗試的整合。

**方法論優勢**

1. **驗證的嚴謹性**：盲驗證+反例檢查的雙重機制，比現有方法更可靠
2. **觀察的可追溯性**：SightLoop 記錄所有觀察，使得「獲取」與「使用」可分離分析
3. **訓練的可學習性**：軌跡級監督提供了「如何搜尋」的學習信號，解決了僅答案監督的根本限制

**現有方法的侷限性**

- 大多數代理式評測只評分答案或里程碑，而非實際解碼的幀
- 現有標註流程中，驗證者看到草稿答案會傾向於確認
- 稀疏支持證據不足以驗證全局性宣稱（如計數）

#### 可重現性評估

**正面因素**

1. **方法論透明度**：論文詳細描述了 SightForge 的驗證流程、SightLoop 的介面設計、以及 Sight-35B 的訓練流程
2. **資料集規模可控**：310 個評測任務+不到 6K 個訓練範例，規模適中便於重現
3. **評測框架的模組化**：SightLoop 作為共享介面，便於整合不同模型

1. **SightForge 的實作細節**：雖然描述了「盲驗證」和「反例檢查」的原則，但具體的提示工程（prompt engineering）、驗證者的選擇標準、以及品質控制流程的細節未完全公開

5. **計算資源需求**：雖然訓練資料量小，但代理式評測可能需要大量 GPU 時間，這對資源有限的機構構成障礙

**可重現性建議**

- 公開 SightForge 的完整提示模板和驗證協議
- 釋出解題軌跡資料集（而非僅釋出最終的 QA 對）
- 提供 SightLoop 的開源實作
- 詳細記錄後訓練的所有超參數和消融實驗

#### 未來研究方向

**1. 觀察策略的理論化**

NexSight 展示了「代理式視窗選擇」能將時間證據召回率翻倍，但跨視窗整合仍是瓶頸。未來研究可以探索：
- 觀察決策的理論框架：何時該探索（explore）vs 何時該利用（exploit）？
- 觀察預算的最優分配策略
- 不確定性估計如何指導觀察決策

**2. 多模態觀察的擴展**

SightLoop 目前主要支援時間和空間觀察。未來可以整合：
- 音訊觀察：許多影片的關鍵資訊在音軌中
- 字幕/文字觀察：OCR 能力對於理解場景中的文字至關重要
- 多模態融合的觀察決策

**3. 驗證機制的強化**

SightForge 的盲驗證是一個重要起點，但可以進一步發展：
- 形式化驗證：對於計數類任務，能否提供數學嚴謹性的證明？
- 跨驗證者一致性：多個獨立驗證者的一致性如何？
- 動態難度調整：根據驗證難度自動調整任務品質標準

**4. 訓練效率的提升**

Sight-35B 用不到 6K 範例就達到了顯著效果，但仍有提升空間：
- 課程學習（curriculum learning）：從簡單到複雜的觀察任務
- 自我對弈（self-play）：模型生成自己的訓練軌跡
- 強化學習整合：將 Sight-35B 的軌跡監督與 RL 結合（如 Video-R1 的方向）

**5. 評測維度的擴展**

SightLine 涵蓋六種能力，但長影片理解的挑戰遠不止於此：
- 因果推理：事件之間的因果關係
- 角色追蹤：跨時間的實體識別與追蹤
- 意圖理解：行為背後的動機推斷
- 常識整合：需要世界知識的推理

**6. 實際應用的橋接**

學術評測與實際應用之間存在差距：
- 即時性需求：實際應用中觀察預算可能更嚴格
- 多輪互動：與使用者的對話式影片理解
- 錯誤恢復：當觀察失敗時如何調整策略

**7. 基礎模型的改進**

Sight-35B 的後訓練揭示了「空間檢查」能力的湧現，這暗示基礎模型的某些能力需要被「喚醒」而非「教授」。未來可以探索：
- 預訓練階段如何更好地支援代理式觀察
- 觀察能力與推理能力的解耦與整合
- 多任務預訓練對觀察能力的影響

**8. 倫理與偏誤考量**

代理式影片理解引發新的倫理問題：
- 觀察偏誤：模型可能系統性地忽略某些類型的內容
- 隱私問題：細粒度觀察可能侵犯影片中人物的隱私
- 公平性：不同類型影片（不同長度、領域、語言）的評測公平性

這些方向不僅能推動技術進步，也能確保這項技術的負責任發展。NexSight 的核心洞見——「驗證是主動觀察問題」——為整個領域提供了一個新的思考框架，其影響將超越具體的技術實作。

**Q10：這項研究適用於哪些實際應用場景？**
A：此研究對於任何需要從長影片中精準提取細粒度資訊的場景都有直接價值，例如：監控影片中的異常事件計數與時序分析、體育賽事的戰術時刻定位與動作次數統計、醫療手術影片的關鍵步驟識別與順序驗證、工業製程的瑕疵偵測時點記錄，以及教育影片中特定概念出現的時間點標記。這些場景的共同特徵是「答案依賴少數關鍵幀」，且錯誤的後果可能重大，因此對證據可追溯性與驗證嚴謹度有極高要求。

**Q11：將此技術產品化時需要考量哪些工程因素？**
A：產品化時首先需考量的是「推算預算」（inference budget）的可控性，因為 SightLoop 雖提供多尺度介面，但實際部署時必須在響應延遲、計算成本與準確率之間取得平衡。其次是「影片長度上限」的擴展性，雖然 SightLine 基於 108 部影片建構，但真實場景的影片可能更長，需要驗證代理式搜尋策略的可擴展性。此外，「錯誤歸因機制」對產品除錯至關重要——觀察層級的記錄能幫助工程團隊快速定位是「沒看到」還是「看到了卻理解錯」，這對持續改進模型極有幫助。

**Q12：這項研究對長影片理解領域的整體影響為何？**
A：此研究的深遠影響在於它重新定義了「評測」與「學習」之間的關係：透過 SightForge 將驗證流程本身變成可學習的代理任務，使得評測基準的建構與代理能力的訓練得以共享同一套嚴謹的證據標準。這種「以驗證驅動學習」的範式有望推動整個領域從「僅追求答案正確率」轉向「同時追求證據可追溯性」。此外，Sight-35B 在外部基準（Video-MME Long +8.22 分、LVBench 子集 +8.13 分）上的遷移表現證明了這種訓練範式的泛化價值，可能成為未來長影片代理的標準訓練方法之一。

**Q13：論文所承認的限制有哪些？**
A：論文坦承 SightLine 的規模相對有限——僅 310 個任務來自 108 部影片，這對於全面評估長影片理解的各種細粒度能力可能仍嫌不足。此外，雖然 Sight-35B 僅用不到 6K 個範例便展現顯著提升，但這個資料規模是否足以支撐更複雜的影片類型與任務變體，仍有待驗證。最後，代理式介面雖提供多尺度操作能力，但其設計選擇（如視窗大小、空間裁切的解析度等）對結果的影響尚未被系統性地探索，這些超參數的敏感度分析是未來工作的重要方向。

**Q14：目前方法仍會出現哪些失敗案例？**
A：從實驗結果可推論出幾類典型失敗案例：第一類是「跨視窗計數錯誤」，即使找到了正確的視窗，模型仍可能在整合多個視窗的證據時漏算或重複計數；第二類是「狀態變化時點判定錯誤」，模型可能誤判狀態何時開始或結束；第三類是「空間檢查失敗」，雖然後訓練後模型開始使用空間檢查，但每軌跡僅 0.72 次的低使用率暗示模型尚未充分掌握何時該進行空間細節檢查；第四類則是「搜尋預算耗盡」，當模型花費過多預算在錯誤區域時，可能在找到關鍵證據前就已用盡幀預算。

**Q15：未來的研究方向有哪些？**
A：未來研究可朝幾個方向延伸：首先，可將 SightForge 的驗證範式擴展至更多任務類型（如因果推理、跨實體追蹤）與更多影片領域（如醫療、科學影片）；其次，可探索更高效的代理介面設計，例如自適應視窗大小或學習式裁剪策略；再者，可將「證據獲取」與「證據整合」兩個子問題分別建模並聯合優化，以縮小 54.52% 與 79.35% 之間的差距；最後，可將此範式應用於多模態長序列（如長對話、長文件）的代理式理解，驗證其跨領域的普適性。這些方向都將有助於推動代理式長序列理解從「能動」走向「動得準」。

## 實作步驟建議

### 階段一：建構可驗證任務資料集（4–8 週）

**步驟 1：影片收集與預處理**
- 收集目標領域的長影片，確保時長與多樣性符合需求
- 使用 FFmpeg 統一格式、提取關鍵幀、建立時間索引

**步驟 2：任務提案生成**
- 由領域專家或 LLM 生成候選問題（計數、排序、狀態變化）
- 每個任務附帶「草稿答案」供後續驗證

**步驟 3：SightForge 驗證流程實作**
```
任務提案 → 盲驗證器（不看草稿答案）→ 從原始影片密集獲取證據
→ 反例檢查（搜尋可能推翻答案的片段）→ 獨立審查員覆核
→ 接受/拒絕
```
- 關鍵：驗證器必須「盲」（看不到草稿答案），避免確認偏誤
- 拒絕率預期約 60–70%，這是品質控制的正常現象

**步驟 4：證據鏈記錄**
- 為每個接受任務記錄：問題、草稿答案、驗證證據幀/區間、反例檢查結果
- 確保第三方可從證據獨立重建答案

### 階段二：SightLoop 評測框架部署（2–4 週）

**步驟 1：多尺度觀察介面實作**
- **時間探索**：模型可指定時間區間讀取稀疏幀
- **局部檢查**：模型可放大特定區域讀取高解析度細節
- **證據整合**：模型可記錄已觀察的證據並跨區間推理
- **重訪機制**：模型可回到先前觀察的區間

**步驟 2：預算控制機制**
- 設定幀預算（例如：64 幀總量）
- 記錄每次觀察的成本與回傳內容
- 提供「軌跡重播」功能供錯誤分析

**步驟 3：評測指標設計**
- 答案正確率
- 證據召回率（找到的相關幀 / 標註的相關幀）
- 觀察效率（正確答案所需幀數）
- 軌跡品質（搜尋路徑是否合理）

### 階段三：Sight-35B 後訓練（3–6 週）

**步驟 1：解題軌跡收集**
- 在「不相交影片」上執行 SightLoop，收集模型互動軌跡
- 過濾出最終答案正確的軌跡作為「步驟級監督」

**步驟 2：監督資料建構**
- 結合 QA 監督（問題→答案）與軌跡監督（問題→觀察序列→答案）
- 比例建議：QA 監督 40% + 軌跡監督 60%

**步驟 3：後訓練執行**
- 使用 SFT 或 DPO 進行微調
- 監控「空間檢查」呼叫率（目標：>0.5 次/軌跡）
- 監控「跨時段計數」與「狀態變化」任務的提升幅度

**步驟 4：泛化驗證**
- 在 Video-MME Long、LVBench 等外部基準測試
- 預期可獲得 +8 分左右的轉移提升

### 階段四：產品化整合（4–8 週）

**步驟 1：API 封裝**
- 將 SightLoop 介面封裝為 REST/gRPC API
- 提供同步（單次查詢）與非同步（批次分析）兩種模式

**步驟 2：使用者介面開發**
- 影片時間軸 + 證據標記視覺化
- 觀察軌跡重播功能（供審查員覆核）
- 信心分數與不確定性提示

**步驟 3：領域適配**
- 針對特定領域（醫療、自駕等）微調專用模型
- 建立領域專屬的任務模板庫

## 潛在風險與注意事項

### 風險 1：驗證偏誤（Verification Bias）
**問題**：即使驗證器「盲」於草稿答案，仍可能受到問題措辭的暗示。
**緩解**：
- 採用「雙盲」設計：驗證器與提案者完全隔離
- 引入「對抗驗證」：刻意尋找推翻答案的證據
- 計算標註者間一致性（IAA），目標 Cohen's κ > 0.7

### 風險 2：證據稀疏導致驗證失敗
**問題**：某些動作發生時間短，密集取樣仍可能遺漏。
**緩解**：
- 設定最低幀率（例如：每秒至少 1 幀）
- 對短暫事件使用滑動視窗重疊取樣
- 接受「無法驗證」為合法結果，不強行標註

### 風險 3：模型「假觀察」問題
**問題**：模型可能宣稱觀察了某個區間，實際上未真正處理。
**緩解**：
- SightLoop 強制記錄回傳的觀察內容（不可由模型虛構）
- 對比模型宣稱的觀察與實際解碼的幀
- 設定「觀察一致性」檢查

### 風險 4：後訓練過擬合到 SightLine 任務類型
**問題**：模型可能在 SightLine 上表現優異，但無法泛化到真實場景。
**緩解**：
- 訓練資料與 SightLine 保持「影片不相交」
- 定期在外部基準（Video-MME、LVBench）驗證
- 保留 20% 訓練資料作為內部驗證集

### 風險 5：計算成本過高
**問題**：SightLoop 的多尺度觀察介面可能導致推論成本是均勻取樣的 3–5 倍。
**緩解**：
- 設定嚴格的幀預算上限
- 對簡單任務使用較小預算
- 快取常見觀察結果

### 風險 6：領域知識缺口
**問題**：通用模型可能無法理解特定領域的細微差異（如醫療術語、自駕場景）。
**緩解**：
- 在領域資料上進行額外的 SFT
- 提供領域專屬的任務模板與範例
- 保留人類專家在迴圈中（human-in-the-loop）
