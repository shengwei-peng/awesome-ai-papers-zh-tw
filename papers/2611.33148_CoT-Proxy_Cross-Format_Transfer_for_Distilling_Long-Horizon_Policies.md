本文提出了一種名為 **CoT-Proxy** 的策略蒸餾方法，其核心洞見在於：對於長時程代理任務（long-horizon agentic tasks），學生模型（student model）可以僅從教師模型（teacher model）的動作軌跡中學習，而無需模仿其思維鏈（chain-of-thought, CoT）。這個方法挑戰了傳統的「全軌跡監督」（full-CoT supervision）範式。

**三種訓練目標的設計**

論文定義了三種訓練目標（training target），如 Figure 1 所示：

1. **Full-CoT 目標**：傳統做法，預填（prefill）推理區塊（reasoning block）的開頭標記 `<think>`，然後監督教師的完整思維與動作。這要求取得教師的完整推理內容。

2. **Action-only 目標**：將推理區塊留空（`<think></think>`），僅監督動作本身。這是本文最激進的設計——完全不監督任何推理內容。

3. **CoT-proxy 目標**：在空推理區塊之後加入一個 `<summary>` 標籤包圍的簡短摘要，該摘要是教師推理的濃縮版本，但並非完整模仿。這提供了一種「代理信號」（proxy signal），讓學生知道教師在想什麼，卻不要求學生複製其推理風格。

**關鍵的 KL 正則化機制**

為了防止學生在學習新策略時偏離其原有的單輪推理能力（single-turn capability），論文引入了基於回放緩衝區（replay buffer）的 KL 正則化（KL regularization）。具體而言，每個訓練批次（batch）除了包含教師軌跡的訓練目標外，還包含學生自身在另一領域提示詞（prompts）上的生成結果，並對這些生成計算 KL 散度，將學生拉回其初始檢查點（initial checkpoint）。這個設計借鑑了持續學習（continual learning）文獻中的經典做法（Li & Hoiem, 2017; Rolnick et al., 2019）。

**跨格式遷移的推論機制**

訓練時學生從未產生過任何推理內容，但在推論（inference）時卻啟用思考（thinking enabled），讓學生用自己的方式推理，同時遵循教師的策略。這種「訓練格式」與「推論格式」不一致卻仍能遷移的現象，被稱為**跨格式遷移**（cross-format transfer）。論文將此現象與 Chua et al. (2025) 在安全性領域觀察到的類似效應相連結——對推理模型在窄域數據上進行禁用 CoT 的微調，會產生在重新啟用 CoT 後仍持續的廣泛錯位。

**理論基礎的猜想**

論文提出一個有趣的猜想：長時程任務的失敗主要源於「執行」（execution）而非「推理」（reasoning），引用了 Sinha et al. (2026) 的研究。若此猜想成立，則僅需教導動作即可，學生自身的單輪推理能力（已通過後訓練獲得）足以勝任中間步驟的思考。

**CoT-proxy 的設計細節**

CoT-proxy 的設計有兩個關鍵約束（後續消融實驗驗證）：
- 摘要必須放在 `<think></think>` 區塊**之外**，而非嵌入其中
- 回放數據必須來自**目標環境之外**的領域

這兩個約束暗示了方法背後的機制：摘要作為「動作的解釋」而非「推理的替代」，而外部回放則防止學生過度擬合到目標環境的表面模式。

#### 與現有研究的比較

**與傳統策略蒸餾的對比**

傳統的代理蒸餾（Pan et al., 2025; Yang et al., 2026）採用全軌跡監督，要求學生模仿教師的完整 CoT 與動作。本文方法在兩個關鍵點上有所不同：

1. **可應用於封閉教師**：傳統方法需要取得教師的完整推理內容，但 OpenAI 等供應商刻意加密推理項目（encrypted reasoning items）以防止此類蒸餾。本文方法僅需動作與（可選的）摘要，因此繞過了這個限制。

2. **避免小模型學習強推理的困難**：Li et al. (2025) 發現小模型從強推理器的軌跡中學習效果不佳。本文方法刻意不讓學生模仿教師的推理風格，保留了學生自身的推理方式，這可能是其在小模型上表現優異的原因。

**與安全性研究的連結**

Chua et al. (2025) 在安全性領域觀察到「禁用 CoT 微調 → 啟用 CoT 後效果持續」的現象。本文將這個現象從負面（錯位）轉為正面（策略遷移），並提出了一個統一的解釋框架：跨格式遷移是語言模型的一個普遍特性。

**與單輪推理研究的對比**

本文假設長時程失敗主要源於執行而非推理（Sinha et al., 2026），這與 Kimi Team et al. (2026) 和 Luo et al. (2025) 等強調「推理能力是長時程代理核心」的工作形成對比。若本文猜想正確，則強化學習（reinforcement learning）可能並非唯一甚至最有效的長時程訓練路徑——監督式策略蒸餾在搭配適當的正則化後即可達到競爭性的效果。

**方法論的侷限性**

1. **依賴教師的動作品質**：若教師在某些動作上犯錯，學生會直接學到這些錯誤，因為沒有 CoT 來提供「為何這樣做」的解釋。CoT-proxy 部分緩解了這個問題，但無法完全消除。

2. **摘要品質的依賴**：CoT-proxy 的效果取決於摘要能否捕捉到教師推理的關鍵資訊。對於封閉模型，這個摘要由 API 提供，其品質與格式並非研究者可控。

3. **KL 正則化的超參數敏感度**：回放緩衝區的內容、KL 權重等超參數可能需要針對不同任務進行調整，論文中未深入探討。

4. **未與強化學習基線直接比較**：雖然論文聲稱這是「更便宜」的替代方案，但未提供與 RL 訓練（如 Kimi Team 等）的直接成本-效果對比。

3. **客服自動化代理**：將頂級客服模型的長時程處理流程（如查訂單、申請退貨、聯絡物流）蒸餾到邊緣部署的小模型，於客服系統中即時回應。

4. **DevOps 維運代理**：以大型模型示範的 shell 操作軌跡（如 log 排查、服務重啟、套件更新）蒸餾到本地小模型，作為內網維運工具。

5. **教育領域的解題代理**：以強模型示範的數理解題步驟蒸餾到小型學生模型，部署於學習平台作為個人家教。

### 實作前置條件

**資料面**
- 教師模型在目標任務上的成功軌跡（actions + observations），可由教師自行 rollout 蒐集
- 教師推理的摘要（CoT-proxy），可由教師自行產生或由 API 取得
- 與目標環境**不同領域**的回放資料，用於 KL 正則化（論文中明確指出 replay data 必須來自目標環境之外）

**算力面**
- 至少一張可容納學生模型全參數微調的 GPU（如 4B 模型約需 24GB 以上顯存，32B 模型需 80GB 等級）
- 教師推論的算力或 API 額度，用於蒐集軌跡
- 儲存空間保存軌跡與回放資料

**技能面**
- 熟悉 SFT 流程與 KL 正則化技巧
- 具備代理執行框架（harness）開發能力，能解析模型輸出並執行工具呼叫
- 具備評估管線，能在 AppWorld、SWE-bench 等基準上重現結果

### 實作步驟建議

1. **選定教師與學生模型**：挑選一個已是推理模型的學生（如 Qwen3 系列），以及一個在目標任務上表現優異的教師（封閉或開放皆可）。

2. **建立代理執行框架**：實作一個能接收模型輸出、解析 think block 與 action、執行工具呼叫、將 observation 回填到上下文的 harness。

3. **蒐集教師軌跡**：在目標環境中讓教師執行任務，記錄每個 turn 的 action 與 observation。若使用封閉模型，僅保留可見輸出與 API 回傳的推理摘要。

4. **產生 CoT-proxy**：對每個教師軌跡，請教師為其推理產生簡短摘要，作為訓練目標中 `<summary>` 標籤內的內容。

5. **建構訓練目標**：將每個 turn 渲染為 action-only 或 CoT-proxy 格式——`<think></think> action` 或 `<think></think> <summary>summary</summary> action`，其中 `<think></think>` 為預填前綴，不計算損失。

6. **準備回放資料**：從與目標任務不同的領域蒐集或合成提示詞，讓學生自行生成回應，存入 replay buffer。

7. **執行微調**：每個 batch 同時包含目標任務的訓練樣本與 replay 樣本，對前者計算 cross-entropy 損失，對後者計算 KL 散度，將學生拉回初始模型附近。

8. **以啟用思考模式推論**：部署時開啟學生的 thinking 模式，僅預填 `<think>` 開頭，讓學生自行生成推理後再產出 action。

9. **建立評估管線**：在目標基準上量測任務成功率，並監控學生在單輪推理任務上的表現是否退化。

### 潛在風險與注意事項

- **回放資料來源錯誤**：若 replay 資料來自目標環境內部，KL 項會干擾策略學習。務必使用**跨領域**的回放資料。

- **摘要位置錯誤**：CoT-proxy 必須放在 think block **之外**。若將摘要誤置於 `<think>...</think>` 內部，會被視為模仿 CoT，破壞跨格式遷移效果。

- **學生單輪能力退化**：KL 正則化不足時，學生可能在學會長時程策略的同時喪失原本的單輪推理能力。需監控單輪基準的表現。

- **封閉模型 API 變動**：教師 API 回傳格式（如 reasoning item 的加密方式、摘要的可用性）可能變動，影響資料管線的穩定性。

- **教師軌跡品質**：若教師在某些任務上成功率低，蒸餾出的策略也會繼承這些失敗模式。需對教師軌跡做品質過濾。

- **評估與部署格式不一致**：訓練時使用空 reasoning block，部署時卻關閉思考模式，會導致效果大幅下降。務必保持推論時啟用思考。

- **領域遷移限制**：論文結果集中在 AppWorld 與 SWE-bench，其他領域（如多輪對話、開放式問答）的有效性尚未驗證。

### 與其他技術的整合建議

- **與 RLHF / RLAIF 整合**：可將 CoT-Proxy 蒸餾視為冷啟動階段，先用 action-only 或 CoT-proxy 訓練建立基礎策略，再以環境回饋進行強化學習微調。

- **與 LoRA / QLoRA 整合**：對 32B 等級學生模型，可採用 LoRA 進行參數高效微調，降低硬體需求；但需驗證 KL 正則化在低秩設定下是否仍能有效防止漂移。

- **與代理框架整合**：可將訓練好的學生模型接入 LangChain、AutoGen、CrewAI 等現有代理框架，替換其中的 LLM 模組；需注意框架的 prompt 格式需與訓練時一致。

- **與模型合併整合**：可將 CoT-Proxy 訓練後的學生與其他經過不同任務微調的學生做模型合併（model merging），擴展能力範圍。

- **與線上學習整合**：部署後可蒐集線上軌跡，定期以新資料重做 CoT-Proxy 蒸餾，使策略隨環境演進。

### 給不同背景讀者的閱讀建議

**初學者**：先理解「思維鏈」與「代理」的基本概念，再閱讀第 1 節的問題動機，理解為何「不學推理只學行動」竟然有效。Figure 1 是理解三種訓練目標差異的關鍵圖表。

**AI 工程師**：重點放在第 2 節的訓練目標建構與 KL 正則化實作細節，並參考論文中關於 replay 資料來源與摘要位置的消融實驗，這些是實際落地時最容易踩坑的地方。

**研究者**：聚焦於「跨格式遷移」這個現象本身的理論意涵——為何空 reasoning block 訓練出的策略能在啟用思考時生效？這與 Chua et al. (2025) 的安全性研究形成有趣對照，是值得延伸探索的方向。

**產品經理**：關注商業價值——能用封閉模型的 API 蒸餾出本地部署的小模型，代表可以兼顧頂級模型的品質與資料隱私、成本控制。論文中 Qwen3-4B 從 7% 提升到 48% 的數字，是評估投入產出比時的關鍵參考。
