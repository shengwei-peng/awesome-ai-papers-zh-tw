Iris-Z 的核心方法論建立在「統一生成式訓練」(unified generative training) 的哲學之上，將語言模型領域的「慘痛教訓」(bitter lesson) 移植到視覺與空間智慧 (spatial intelligence) 領域。其技術架構可從以下幾個層面解析：

**1. 聯合 RGBD 去噪 (Joint RGBD Denoising)**

Iris-Z 採用擴散模型 (diffusion model) 框架，但關鍵創新在於將外觀 (RGB) 與幾何 (depth) 視為同一序列中的兩組詞元 (tokens)。具體而言，模型在去噪過程中同時處理：
- **外觀詞元 (appearance tokens)**：代表影像的 RGB 資訊
- **幾何詞元 (geometry tokens)**：代表場景的深度資訊

這種設計讓單一主幹網路 (single backbone) 能夠在一次前向傳遞中「理解」影像與其對應的深度圖，兩者共享同一組權重 (one set of weights)，而非傳統的雙階段 (two-stage) 或雙流 (two-stream) 設計。

**2. 多任務統一介面**

Iris-Z 透過同一架構支援四種任務：
- **提示詞→影像+深度 (prompt→image+depth)**：從文字生成 RGBD 輸出
- **照片→深度 (photographs→depth)**：從 RGB 影像估計深度
- **深度→影像 (depth→image)**：將影像「繪製」至給定深度圖上
- **聯合生成**：同時產生外觀與幾何

這種設計的關鍵在於**無需任務專用層 (specialized layers)**——所有任務都由同一個去噪過程的不同條件化方式實現，這與 Vision Banana 對 Nano Banana Pro 的指令微調 (instruction-tuning) 路線類似，但更為根本。

**3. 規模化訓練策略**

從圖 2b 的擴展曲線可看出，Iris-Z 採用三階段規模化路徑：
- **LoRA 微調階段**：9B 參數 + 0.2M 資料
- **全微調階段**：9B 參數 + 3.8M 資料（Iris-Z-small）
- **大規模階段**：32B 參數 + 3.6M 資料（Iris-Z-big）

值得注意的是，從 LoRA 到全微調的躍遷帶來了顯著改善（AbsRel 從 3.83 降至 3.11），而從 9B 到 32B 的擴展進一步降至 2.92。這顯示**資料量與參數規模的乘積效應**比單純擴展任一項更為關鍵。

**4. 深度表示方式**

從圖 1 的視覺化可推斷，Iris-Z 使用**對數距離著色** (log distance coloring) 來表示深度：近距離為紅色，遠距離為藍色，黑色代表無深度或天空區域。這種表示方式在數值上更穩定，且符合人類對距離的感知特性。

## 實務應用指南

### 適用場景

1. **AR/VR 內容生成與場景重建**：利用「提示詞 → 影像 + 深度」的能力，從文字描述直接生成帶有真實幾何結構的 3D 場景，省去傳統 photogrammetry 流程中昂貴的多視角拍攝與 SfM 重建。可應用於 VR 遊戲關卡雛型、虛擬展間快速搭建。

2. **機器人導航與操作**：機器人搭載單目相機時，可即時從 RGB 影像估計稠密深度圖（photo → depth），用於避障、3D 抓取點估測。相較於 LiDAR，視覺方案成本低、解析度高，且能處理無紋理表面。

3. **自動駕駛與 ADAS**：在缺乏 LiDAR 的車輛上，將 Iris-Z 作為單目深度估計模組，輸出 metric 或 affine-invariant 深度，搭配現有物件偵測模型可建構完整的 3D 感知 pipeline。

4. **電商與室內設計**：賣家提供單張商品照片或房間照片，系統自動估計深度並產生 3D 模型，支援 360° 旋轉瀏覽、AR 試擺、虛擬裝潢預覽。

5. **電影與遊戲特效**：將既有 2D 影片幀估計出深度後，套用景深、視差、重新對焦等電影級效果（depth-based bokeh / rack focus），或將演員「合成」到新場景中，無需綠幕拍攝。

### 實作步驟建議

**階段一：原型驗證（1–2 週）**
1. 從 `github.com/speridlabs/iris-z-sdk` 安裝 SDK，下載 Iris-Z-small 權重。
2. 用官方範例跑通四種任務：text→RGBD、image→depth、depth→image、純 text→image。

**階段二：領域微調（2–6 週）**
4. 準備領域資料，必要時以 LoRA（論文顯示 9B + LoRA 即可顯著提升）做輕量微調，避免全參數訓練成本。

6. 若需 metric depth（絕對尺度），需在微調資料中加入真實 metric 標註，並評估是否需要 affine alignment 後處理。

**階段三：產品化（4–12 週）**
7. 推論優化：量化（INT8/FP8）、快取 attention、batch 化；針對即時應用可蒸餾為較小模型。

9. 串接上下游：上游接 prompt 編輯器或影像輸入管線；下游接 3D 重建（NeRF / Gaussian Splatting）、AR 渲染（ARKit / ARCore）、或機器人控制 stack（ROS2）。

**階段四：迭代與監控**
10. 上線後持續蒐集失敗案例（特別是天空、透明物體、鏡面反射），建立回饋資料集做下一輪微調。
11. 監控深度估計的物理一致性（多幀間深度是否跳動），必要時加入 temporal smoothing。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解策略 |
|------|------|----------|
| **天空 / 無結構區域深度失效** | 論文中以黑色標示無深度或天空區域；下游若誤用會導致 3D 重建破洞 | 在 pipeline 中明確標記 invalid mask；對天空使用單獨的語意分割模型 |
| **尺度歧義（affine-invariant）** | 預設輸出為相對深度，metric 應用需額外校準 | 與已知尺寸物件（如車牌、家具）對齊；或微調為 metric depth |
| **反射、透明、低紋理表面** | Diffusion 模型對 specular / glass 區域易產生錯誤深度 | 結合多幀、光達或偏振相機做 sensor fusion |
| **推論成本過高** | 32B 模型單張影像需多次 transformer passes | 使用 Iris-Z-small 做即時任務、Iris-Z-big 做離線高質量任務；或蒸餾 |
| **生成內容的版權與偏見** | 影像生成能力繼承自基礎模型，可能產生偏見或抄襲爭議 | 加入內容審核、浮水印、拒絕清單；遵循當地 AI 法規 |
| **領域漂移** | 在與訓練分布差異大的場景（如醫療、衛星）表現下降 | 領域微調 + 嚴格評測；保留 fallback 至傳統 depth 模型 |
| **時序一致性** | 影片逐幀估計會閃爍 | 加入 temporal consistency loss 微調，或後處理光流引導 |

**給 AI 工程師**：重點讀第 1、6 節與 Fig. 2b 的 scaling 實驗。理解 joint RGBD denoising 的序列設計、token 化方式，以及 LoRA vs 全參數微調的取捨。實作上先以 Iris-Z-small 落地，評估自家資料後再決定是否升級到 big 版本或自訓。

**給研究者**：第 6 節的消融實驗與 Fig. 2b 的 scaling curve 是最值得深挖的部分——它證明了「規模勝過任務專用設計」這個 bitter lesson 在視覺領域同樣成立。可延伸的研究方向包括：加入 surface normal、segmentation、camera pose 等更多 modality token；探討 joint denoising 是否帶來 emergent 的 3D 理解能力；以及與世界模型、4D 生成的銜接。

**給產品經理**：核心訊息是「一個模型取代多個專家模型」帶來的商業意義——降低維護成本、統一資料飛輪、跨任務能力湧現。需評估的是：自家產品的瓶頸是否在「單一任務精度」還是「跨任務整合」；若是後者，Iris-Z 這類通用模型的 ROI 會遠高於持續堆疊專家模型。建議先以非關鍵路徑（如內容創作工具、內部標註加速）試點，再逐步推向核心功能。
