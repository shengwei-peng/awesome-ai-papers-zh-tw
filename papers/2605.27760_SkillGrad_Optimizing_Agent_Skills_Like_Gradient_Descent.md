## ⚡ TL;DR

現有智慧體技能常不可靠，且既有演化方法僅依賴啟發式反思，缺乏明確最佳化形式。
提出SkillGrad，將技能套件視為結構化參數，依執行診斷產生文字梯度，以動量與層級修補迭代更新。
於兩項基準中，SkillGrad平均超越最強基線6.7百分點，消融實驗亦證實動量與對比診斷皆具貢獻。

## 摘要翻譯

智慧體技能（agent skills）透過將可重複使用（reusable）的程序知識（procedural knowledge）儲存在結構化檔案（structured files）中，提供了一種輕量級（lightweight）的方式來使大型語言模型智慧體（LLM agents）適應專門領域。然而，無論是從第三方下載或是自生成（self-generated），這些技能往往不可靠、不完整或過時。現有的技能演化方法（skill-evolution methods）通常透過啟發式反思（heuristic reflections）來解決這些缺陷，而缺乏明確的最佳化形式（optimization formulation）。在本文中，我們提出 SkillGrad，一個用於最佳化智慧體技能的類梯度下降框架（gradient-descent-inspired framework）。SkillGrad 將技能套件（skill package）視為一個結構化參數（structured parameter），並以梯度下降（gradient descent）的方式進行最佳化：任務執行（task executions）提供軌跡層級損失證據（trajectory-level loss evidence），接著自動診斷（automatic diagnoses）提供文字梯度（text-based gradients），指出修正方向（correction directions）。為了在多次迭代中穩定最佳化過程，動量智慧體（momentum agent）將反覆出現的診斷模式（recurring diagnostic patterns）累積於持久記憶覆疊（persistent memory overlay）中。最後，基於大型語言模型的修補器（LLM-based patcher）透過對技能套件套用層級感知編輯（layer-aware edits）來執行參數更新（parameter update）。在 SpreadsheetBench Verified 與 WikiTableQuestions 上的評測顯示，SkillGrad 在兩個骨幹大型語言模型（backbone LLMs）上一致優於基於訓練的技能演化（training-based skill evolution）基線（baselines），平均而言相較於最強的基於訓練的基線提升了 6.7 百分點（percentage points）。消融實驗（Ablations）進一步顯示，動量（momentum）與對比診斷（contrastive diagnosis）皆對最終的技能品質（skill quality）有所貢獻。

### 核心貢獻（3～5點）
- 提出 SkillGrad 類梯度下降框架，將智慧體技能套件視為結構化參數進行明確最佳化，突破現有技能演化方法僅依賴啟發式反思而缺乏最佳化形式的侷限。
- 建立軌跡層級損失證據與自動診斷機制，生成文字梯度與具體修正方向，使技能更新具備可解釋的梯度訊號。
- 設計動量智慧體與持久記憶覆疊，累積反覆出現的診斷模式以穩定跨迭代最佳化；並以基於大型語言模型的修補器執行層級感知編輯，完成技能套件的參數更新。
- 在 SpreadsheetBench Verified 與 WikiTableQuestions 兩大評測基準上，於兩個骨幹大型語言模型均一致超越基於訓練的技能演化基線，平均提升 6.7 百分點，並透過消融實驗驗證動量與對比診斷對最終技能品質的關鍵貢獻。

### 適合對象
從事大型語言模型智慧體、技能演化與結構化知識表示相關研究的研究人員與工程師；特別適合關注如何以明確最佳化框架持續改進智慧體技能品質，並於試算表操作與表格問答等任務中尋求超越傳統訓練基線之高效能解決方案的讀者。

## 深度分析

#### 方法論解析

SkillGrad（類梯度下降框架）的核心貢獻在於將 agent skills（智慧體技能）視為可最佳化的結構化參數（structured parameter），從而為技能演化（skill evolution）建立明確的最佳化形式（optimization formulation）。具體而言，技能套件（skill package）在每一輪迭代 t 中被表示為 S_t = (H, B, Q)：H 為詮釋資料標頭（metadata header），B 為常駐載入的 SKILL.md 本體（body），Q 則為條件式載入的資源層（resources）。這種三層式結構迫使最佳化器必須同時回答「要加入什麼知識」以及「該知識應置於哪一層」的雙重問題，後者正是 layer-aware edits（層級感知編輯）的設計初衷——將狹隘的邊際案例放入 Q 可避免干擾 B 中的通用工作流。

在每一次迭代中，執行器（executor）將當前技能套用於一小批次（mini-batch）任務，產生任務執行（task executions）的結果與軌跡（trajectories），這些軌跡層級損失證據（trajectory-level loss evidence）構成了最佳化的損失證據（loss evidence）。與傳統僅檢視失敗軌跡（failed trajectories）的做法不同，SkillGrad 額外引入對比成功軌跡（contrastive successful trajectories）：即「初始技能失敗、但當前技能成功」的案例，用以標定值得保留的行為，防止過度修正。接著，診斷器（diagnoser）將這些觀察轉換為逐樣本層級的文字梯度（text-based gradients）d_{t,i}，提供具體的修正方向（correction directions）。

為了穩定跨迭代的最佳化過程，動量智慧體（momentum agent）維護一份持久記憶體（persistent memory）M_t 與當前覆疊（current overlay）O_t，將反覆出現的診斷模式（recurring diagnostic patterns）累積為動量（momentum）。最後，基於大型語言模型的修補器（LLM-based patcher）根據批次診斷、M_t 與 O_t 執行參數更新（parameter update），透過 layer-aware edits 產生 S_{t+1}。整體而言，這是一種概念類比而非數值微分，但其模組化設計（executor–diagnoser–momentum–patcher）為離散文字工件提供了系統性的收斂機制。

#### 實驗數據解讀

本研究在 SpreadsheetBench Verified（試算表任務評測基準）與 WikiTableQuestions（維基表格問答評測基準）上進行評估，並採用兩組不同的骨幹大型語言模型（backbone LLMs）以驗證泛用性。實驗設計的一大亮點是同時測試自生成技能（self-generated skills，由 LLM 產生的 xlsx 技能）與第三方技能（third-party skills，下載取得的技能）作為初始化（initialization）來源，證明 SkillGrad 並非綁定於特定技能來源，而是能在固定配置（fixed configuration）下持續提升任意初始技能套件的品質。

數據顯示，SkillGrad 平均較最強的基於訓練的技能演化（training-based skill evolution）基線（baseline）提升 6.7 百分點（percentage points）。這項增益在兩種資料集與兩種骨幹模型上皆保持一致，顯示其方法論的穩健性。消融實驗（ablation）進一步驗證：移除動量（momentum）或對比診斷（contrastive diagnosis）皆會顯著降低保留準確率（held-out accuracy），說明兩者對最終技能品質（skill quality）均有不可替代的貢獻。此外，作者針對批次大小（batch size）、迭代預算（iteration budget）與權杖成本（token cost）進行分析，揭示框架在運算資源與效能權衡上的行為特性，為實際部署提供了可預期的預算規劃依據。

#### 與現有研究的比較

相較於現有的技能演化方法（skill-evolution methods），SkillGrad 的主要差異在於以明確的最佳化形式（optimization formulation）取代啟發式反思（heuristic reflections）。以 EvoSkill（基線方法）為例，其採用失敗驅動更新策略（failure-driven update strategy），透過分析失敗執行產生新技能或修訂技能，再以基於驗證的選擇（validation-based selection）挑選候選人；這本質上是一種維護多版本技能池的離線策略。相對地，SkillGrad 直接對單一當前技能工件（skill artifact）進行反覆運算式最佳化，並同時利用失敗與對比成功軌跡作為損失證據（loss evidence），使每一輪更新都能改變後續迭代所觀察到的證據分布。

Trace2Skill（基線方法）則代表另一種典範：離線軌跡至技能蒸餾（offline trajectory-to-skill distillation）。它從大量執行軌跡（execution trajectories）中提取局部教訓，再層次式地整合為統一目錄。這種方法缺乏「執行—診斷—更新」的緊密回饋迴路，而 SkillGrad 的線上特性確保了技能演化能隨著當前參數狀態動態調整。至於 SkillX、SkillClaw、Memento-Skills 與 CoEvoSkills 等系統，則分別聚焦於技能庫建構、多使用者集體演化、持久記憶（persistent memory）讀寫，以及多檔案技能套件的生成器—驗證器架構。SkillGrad 的獨特定位在於將輕量級（lightweight）的結構化檔案（structured files）視為可最佳化產物（optimizable artifact），並透過類梯度下降的數學直覺來統整各模組。

然而，本方法亦存在侷限。由於智慧體技能（agent skills）本質為離散文字，所謂梯度僅為概念類比，缺乏數值收斂保證；此外，診斷器與修補器的表現高度依賴骨幹大型語言模型（backbone LLMs）的推理與遵循指令能力，若模型產生錯誤診斷，動量（momentum）反而可能放大偏差。權杖成本（token cost）在多輪迭代下亦可能累積至可觀規模。

#### 可重現性評估

就提供的文本脈絡而言，作者並未明確宣告釋出開放原始碼、模型權重或完整提示工程範本。不過，本研究採用的評測基準——SpreadsheetBench Verified 與 WikiTableQuestions——均為公開資料集，這為外部復現提供了客觀的比較基礎。文中提及附錄 E 收錄代表性技能節錄、附錄 B 說明 L3 資源的執行期檢索，暗示完整論文具備相當的技術細節披露。然而，由於 SkillGrad 屬於多智慧體（multi-agent）框架，涉及執行器、診斷器（diagnoser）、動量智慧體（momentum agent）與修補器（patcher）之間的複雜互動，若無官方實作，第三方研究者需投入較高工程成本重建整個流程。建議作者未來釋出原始碼與初始技能套件（skill package），以強化研究的可重現性與可比較性。

#### 未來研究方向

1. **多技能套件協同最佳化**：目前 SkillGrad 聚焦於單一技能套件（skill package）的精煉，未來可擴展至多檔案技能庫（skill libraries）的聯合最佳化，結合 CoEvoSkills 的生成器—驗證器架構或 SkillClaw 的多使用者生態系概念，實現跨工件的知識共享。
2. **可微分與離散混合架構**：雖然現階段僅為概念類比，但未來可探索在可微分模組（如神經檢索器或價值函數）與離散文字梯度之間建立橋樑，降低對純文字診斷的依賴。
3. **收斂性理論分析**：針對結構化參數（structured parameter）的離散最佳化，建立類似梯度下降（gradient descent）的收斂保證或複雜度上界，特別是納入動量（momentum）後的穩定性證明。
4. **成本效率提升**：透過將診斷器或修補器蒸餾為輕量級模型，或設計更積極的快取機制來壓縮權杖成本（token cost），使框架更適合高頻率的終端使用者部署。
5. **動態結構搜尋**：現有 L1/L2/L3 結構為固定，未來可讓修補器（patcher）在更新內容之餘，自動重組技能套件的層級架構（例如動態拆分或合併 L3 資源），實現結構與內容的聯合最佳化。
6. **跨領域遷移**：將驗證從試算表與維基表格擴展至網頁導航（web navigation）、長程決策（long-horizon decision-making）與規劃（planning）等更複雜的任務，驗證框架在高度動態環境中的泛化能力。

## 論文問答

**Q1：這篇論文試圖解決什麼核心問題？為什麼現有的智慧體技能需要被最佳化？**
A：這篇論文指出，無論是從第三方下載還是由模型自生成的智慧體技能，經常存在不可靠、不完整或過時的問題，導致大型語言模型智慧體在執行專業領域任務時表現不佳。由於這些技能以結構化檔案的形式儲存可重複使用的程序知識，其品質缺陷會直接影響智慧體的長程決策與任務執行成效。因此，如何將技能視為可最佳化的產物並進行系統性改進，成為本文欲解決的核心挑戰。

**Q2：現有的技能演化方法存在哪些主要缺陷？SkillGrad 如何克服這些限制？**
A：現有的技能演化方法大多依賴啟發式反思，缺乏明確的最佳化形式化表述，導致更新過程不夠系統化且難以穩定收斂。例如，EvoSkill 採用失敗驅動的更新策略並依賴保留驗證進行選擇，而 Trace2Skill 則屬於離線軌跡蒸餾，無法在迭代過程中動態調整觀察到的證據。SkillGrad 透過類梯度下降的框架，將技能套件視為結構化參數，利用任務執行軌跡作為損失證據、自動診斷作為文字梯度，並引入動量機制穩定跨迭代更新，從而提供更原則性且穩定的最佳化路徑。

**Q3：為什麼將技能最佳化類比為梯度下降是重要的概念貢獻？這個類比如何幫助理解 SkillGrad 的設計？**
A：將技能最佳化類比為梯度下降提供了一個原則性的設計透鏡，使離散的文字工件能被視為可迭代的結構化參數進行系統性改進。這個概念對應讓作者明確定義了「參數」（技能套件）、「損失證據」（任務結果與軌跡）、「梯度」（診斷訊號）、「動量」（反覆出現的模式記憶）以及「參數更新」（層級感知修補），讓整個框架不再是零散的啟發式規則，而是具有數學直覺的優化流程。這種形式化不僅提升了方法的可解釋性，也為未來在智慧體技能學習領域引入更多最佳化理論工具奠定了基礎。

**Q4：SkillGrad 的核心運作流程為何？請說明從任務執行到技能更新的完整迭代迴圈。**
A：SkillGrad 的運作流程包含五個關鍵步驟：首先，執行器將當前技能套用於一小批訓練任務，產生執行結果與軌跡作為損失證據；接著，診斷器分析失敗軌跡與對比成功軌跡，生成文字形式的診斷訊號，類比逐樣本梯度；然後，動量智慧體將反覆出現的診斷模式累積至持久記憶體，並為當前批次建立緊湊的記憶覆疊；最後，修補器根據這些訊號對技能套件進行層級感知編輯，產生下一代技能套件。這個迴圈在多次迭代中持續進行，使技能套件如同連續空間中的參數般逐步收斂至更高品質。

**Q5：SkillGrad 提出了哪些關鍵創新，使其有別於傳統的提示詞最佳化與其他技能演化基線？**
A：SkillGrad 的關鍵創新在於將技能套件視為具有內部層級結構（L1 標頭、L2 SKILL.md、L3 資源）的結構化參數，而非單純的平坦文字提示，因此更新時必須進行層級感知編輯以決定知識應該放置的位置。此外，框架同時利用失敗軌跡與對比成功軌跡作為損失證據，後者能識別出當前技能已學會且值得保留的行為，避免在修正錯誤時遺失既有能力。再者，動量機制透過持久記憶覆疊累積跨迭代的反覆診斷模式，有效穩定了離散文字空間中的最佳化過程，這是傳統提示詞最佳化與 EvoSkill、Trace2Skill 等基線所不具備的。

**Q6：為什麼 SkillGrad 需要設計三層式的技能結構（L1、L2、L3）？這種設計如何影響修補器的更新策略？**
A：三層式結構的設計反映了程序知識在實際使用中的不同載入頻率與重要性：L2 的 SKILL.md 會在技能啟動後始終載入，因此必須保持精簡且具廣泛適用性；L3 的資源檔案則是條件式載入，適合存放較長的程序、邊緣案例與詳細範例，以免干擾不相關的任務執行。這種區隔使得修補器在執行參數更新時，不僅要決定「加入什麼知識」，還要判斷「知識應該放在哪一層」，例如將狹隘的任務細節放入 L3 而非 L2，以避免分散執行器的注意力。因此，層級感知編輯不只是內容修改，更是對技能架構的路由決策，這是 SkillGrad 與一般提示詞最佳化的根本差異。

**Q7：SkillGrad 在哪些評測基準與設定下進行實驗？使用了哪些骨幹模型與初始技能來源？**
A：論文在 SpreadsheetBench Verified 與 WikiTableQuestions 兩個評測基準上進行實驗，這兩個基準分別測試智慧體在試算表操作與維基表格問答上的能力。實驗採用了兩種不同的骨幹大型語言模型，並針對兩種初始技能來源進行測試：一種是由大型語言模型自動生成的 xlsx 技能，另一種則是從第三方下載取得的技能。這樣的設計確保了評估結果能反映 SkillGrad 在不同技能品質起點與不同模型骨幹下的泛化能力與穩健性。

**Q8：SkillGrad 的主要實驗結果為何？與最強的基線相比表現如何？**

## 實務應用指南

### 適用場景

1. **企業試算表與財務報表自動化**：財會或營運部門常累積大量 xlsx 處理流程，無論是 LLM 自生成或從外部下載的試算表技能套件，往往無法正確處理邊際案例（edge cases）。SkillGrad 可透過迭代執行與對比診斷，將這些不可靠的初始技能最佳化為能穩定處理複雜公式的生產級智慧體技能。

2. **客服與維修標準作業程序（SOP）的持續演化**：客服智慧體的技能套件（如故障排除流程）會隨產品更新而過時。SkillGrad 能將真人對話或模擬執行產生的軌跡作為損失證據，自動診斷出流程缺口，並以層級感知編輯更新 SKILL.md 與條件式資源，實現免重新訓練的知識迭代。

3. **跨部門知識庫的第三方技能適配**：組織引入第三方結構化技能（如數據分析、維基表格問答）時，常因資料格式或領域術語差異導致執行失敗。SkillGrad 可將這些第三方技能視為可最佳化產物，利用保留驗證集進行小批次梯度下降式調校，使其適應內部資料環境。

4. **法規遵循與審查流程的動態維護**：合規檢查程序知識變動頻繁（如稅法或資安規範更新）。透過動量智慧體累積反覆出現的診斷模式，SkillGrad 能識別哪些規則需要寫入 L2（常駐主體）、哪些例外應歸入 L3（條件資源），避免智慧體載入過時指引。

5. **長流程數據分析代理的品質提升**：針對 WikiTableQuestions 類型的多步驟表格推理任務，初始技能可能遺漏特定聚合或篩選步驟。SkillGrad 透過對比成功與失敗軌跡，產生文字梯度來修正程序知識，並利用動量穩定跨迭代的更新方向。

### 實作前置條件

**資料準備**
- 一份結構化的初始技能套件 \(S_0\)：需包含 L1（Metadata）、L2（SKILL.md 主體）與 L3（Resources）三層，無論是 LLM 自生成或第三方技能皆可。
- 訓練任務小批次（mini-batch）：涵蓋常見與邊際案例的任務集，用於產生執行軌跡與損失證據。
- 保留驗證集（held-out split）：用於監控技能品質是否提升，防止過度擬合訓練任務。
- 任務成果評估器：能明確判定任務成功或失敗，並回傳軌跡層級證據。

**運算資源**
- 骨幹大型語言模型（backbone LLM）的 API 或本地部署端點：需同時支應執行器（executor）、診斷器（diagnoser）、動量智慧體（momentum agent）與修補器（patcher）的呼叫。
- 迭代預算（iteration budget）：每次迭代包含多次 LLM 推論與層級感知編輯，需預估 Token 與呼叫次數成本。
- 持久化儲存空間：用於存放動量智慧體的持久記憶體 \(M_t\) 與當前覆疊 \(O_t\)。

**技能與領域前提**
- 團隊需理解目標領域的程序知識，才能判斷自動診斷產生的文字梯度是否合理。
- 技能套件需採用 SkillGrad 支援的結構化格式，確保修補器能執行 L1/L2/L3 的差異化編輯。

---

### 實作步驟建議

**步驟 1：初始化技能套件與環境**
準備初始技能套件 \(S_0\)，確認 L2（SKILL.md）包含核心工作流程，L3（Resources）已預留邊際案例擴充空間。部署任務執行環境（如試算表操作介面或網頁導航模擬器）。

**步驟 2：設計小批次與評估協議**
將訓練任務分為多個小批次，並定義明確的成功準則（如試算表輸出正確性、表格問答準確率）。同時準備保留驗證集，用於每輪迭代後的品質把關。

**步驟 3：執行與收集損失證據**
於當前迭代 \(t\)，由執行器載入技能 \(S_t\) 並執行小批次任務。收集任務成果與完整執行軌跡 \(\tau_{t,i}\)，標記失敗軌跡，並透過對比機制找出「初始技能失敗、當前技能成功」的對比成功軌跡。

**步驟 4：自動診斷產生文字梯度**
將軌跡與成果餵入診斷器，針對失敗案例產生校正變更建議，針對對比成功案例標註值得保留的行為。彙整為批次層級的診斷報告，作為本輪的文字梯度 \(\{d_{t,i}\}\)。

**步驟 5：更新動量記憶**
動量智慧體分析本輪診斷，將反覆出現的診斷模式寫入持久記憶體 \(M_t\)，並產生當前覆疊 \(O_t\)。此步驟可穩定跨迭代的更新方向，避免單一批次異常導致技能震盪。

**步驟 6：層級感知修補（Parameter Update）**
修補器根據文字梯度與動量記憶，對技能套件執行層級感知編輯：
- 將通用原則與修正寫入 L2（SKILL.md），確保常駐載入；
- 將狹隘的邊際案例、長程序與詳細範例寫入 L3（Resources），避免干擾無關任務。

**步驟 7：驗證與收斂判斷**
以修補後的 \(S_{t+1}\) 在保留驗證集上測試。若準確率提升且未達迭代預算，則以 \(S_{t+1}\) 進入下一輪；若效能停滯或下降，可調整批次大小或診斷提示詞後重試。

**步驟 8：部署與持續監控**
將收斂後的最佳技能套件部署至生產環境。建立軌跡日誌管線，持續收集實際執行成果，作為下一輪 SkillGrad 最佳化的損失證據來源。

### 潛在風險與注意事項

- **層級錯置（Layer Misplacement）**：若將過於狹隘的任務細節寫入 L2（SKILL.md），會增加每次執行的上下文負擔並干擾無關任務；反之，若將核心工作流程誤放 L3，可能導致執行器未載入關鍵指引。建議在修補階段明確定義「通用性 vs. 條件性」的判斷準則。

- **動量記憶僵化**：持久記憶體 \(M_t\) 可能累積已過時的診斷模式，尤其在目標領域規則變動時。應定期實施消融實驗，或設定記憶覆疊的時效權重，避免舊模式壓制新知識。

- **對比診斷稀缺**：若訓練任務過於簡單或初始技能過差，可能難以產生「對比成功軌跡」，導致文字梯度僅包含負面訊號而缺乏值得保留的行為指引。可透過人工示範或資料增強補充成功案例。

- **Token 與成本失控**：每輪迭代需多次呼叫骨幹 LLM（執行、診斷、動量彙整、修補），在高批次大小或長軌跡情境下成本可觀。建議先以小批次與精簡軌跡進行概念驗證，再逐步擴大規模。

- **訓練任務過擬合**：技能可能過度適配訓練小批次的特定格式，導致保留驗證效能下降。應確保訓練集涵蓋足夠多樣性，並將驗證準確率（而非僅訓練成功率）作為早期停止依據。

- **第三方技能結構不相容**：外部下載的技能套件可能缺乏清晰的 L1/L2/L3 分層，導致修補器無法正確執行層級感知編輯。導入前需先進行結構正規化（normalization）或重新封裝。

### 與其他技術的整合建議

- **與 RAG（檢索增強生成）系統整合**：讓 SkillGrad 負責最佳化 L2 中相對穩定的程序知識，而將頻繁變動的參考資料（如最新產品規格、客戶歷史紀錄）保留在 RAG 向量庫中。執行時，L3 Resources 可透過檢索動態載入，形成「靜態技能最佳化 + 動態語境補充」的雙軌架構。

- **與傳統 MLOps / CI-CD 管線整合**：將技能套件視為版本化產物，每輪 SkillGrad 迭代產生的 \(S_{t+1}\) 作為一個 Git commit。透過 diff 審查與自動化保留驗證測試，確保技能更新符合上線標準，再部署至生產智慧體。

- **與多智慧體協作框架（如 LangGraph、AutoGen）整合**：將 SkillGrad 最佳化後的技能作為專業工具（Tool）或角色模組（Role）掛載至多智慧體系統。動量智慧體的持久記憶體可進一步提升為團隊共享的知識覆疊，讓多個智慧體受益於累積的診斷模式。

- **與可觀測性平台（Observability）整合**：將執行軌跡與任務成果導入現有監控工具（如 LangSmith、Langfuse），自動化產生損失證據 \(E_t(T_i)\)。當生產環境出現失敗軌跡時，可觸發新一輪 SkillGrad 增量最佳化，形成「執行—監控—診斷—修補」的閉環。

- **與低程式碼自動化平台整合**：對於已使用 RPA 或低程式碼工具的企業，SkillGrad 可專注於最佳化「決策與規劃層」的技能套件，而將具體的 UI 操作或 API 呼叫留給既有自動化引擎，降低導入門檻。

### 給不同背景讀者的閱讀建議

**給初學者**：請先聚焦「類梯度下降」的核心類比——把技能套件想像成一份可以反覆修改的員工手冊，而 SkillGrad 就是一位自動化教練，透過觀察員工執行任務的成敗軌跡，指出手冊哪裡寫錯、哪裡該補充。理解 L1/L2/L3 三層結構的差異（常駐指引 vs. 條件資源）是掌握本文的關鍵第一步。

**給 AI 工程師**：建議深入研讀第 3 節的方法論，特別是多智慧體架構中診斷器、動量智慧體與修補器的分工。實作時需特別注意層級感知編輯的提示詞設計，以及如何將持久記憶覆疊 \(M_t\) 與 \(O_t\) 高效地注入修補器的上下文，同時管控跨迭代呼叫的 Token 預算與延遲。

**給研究人員**：本文的價值在於將技能演化重新形式化為結構化參數的最佳化問題。建議關注對比診斷與動量機制對收斂穩定性的貢獻，並思考「文字梯度」的理論性質——例如其方向性是否具備某種形式的下降保證，以及與傳統梯度下降相比，離散文字空間中的更新步長如何量化。

**給產品經理**：請將重點放在商業價值與成本權衡。SkillGrad 解決了「第三方或 AI 生成技能無法直接上線」的痛點，能將不可靠的初始資產轉化為可持續演化的產品功能。評估時請注意 SpreadsheetBench Verified 與 WikiTableQuestions 的實驗設定，這些相當於企業自動化場景的代理指標；同時將迭代預算視為營運成本，與傳統人工寫規則或重新訓練模型的方案進行 ROI 比較。
