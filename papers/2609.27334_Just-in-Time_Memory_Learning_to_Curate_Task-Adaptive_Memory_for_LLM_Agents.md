# 即時記憶（JitMem）：學習為大型語言模型智慧體策展任務適應性記憶

**原文標題：** Just-in-Time Memory: Learning to Curate Task-Adaptive Memory for LLM Agents  
**作者：** Yefan Zhou、Yang Li、Zeyu Leo Liu 等 5 位作者  
**發布日期：** 2026-09-23

## ⚡ TL;DR

現有智慧體記憶多在寫入時策展，導致資訊過早遺失、摘要與查詢無關，並造成長期信用分配困難。
本文提出即時記憶JitMem，保留原始軌跡，並在讀取時由GRPO訓練的策展器生成任務適應性負載。
在三大基準上，JitMem成功率提升16.2、16.3、3.9點，並降低逾五成token與三成步數。

## 摘要翻譯

智慧體記憶（agentic memory）系統會重複利用過往經驗以提升未來表現，然而大多數現有設計在寫入時即進行記憶策展（write-time curation）：一旦任務完成，其軌跡（trajectory）便被提煉為固定產物（fixed artifact），例如反思（reflection）、工作流程（workflow）、技能（skill）或推理策略（reasoning strategy），之後再透過相似度搜尋（similarity search）加以檢索。這迫使系統在尚未知曉未來查詢（query）前，就必須決定哪些資訊值得記住；如此一來，資訊被不可逆地捨棄，並產生一個與查詢無關的摘要（query-independent summary），卻必須服務眾多可能的下游任務。學習這種寫入時策展器（write-time curator）也同樣困難，因為儲存決策（storage decision）的價值可能只有在相關查詢出現時才會顯現，而這可能是在許多任務之後，從而形成了長期信用分配問題（long-horizon credit-assignment problem）。我們改為保留原始軌跡（raw trajectories），並將策展延後至讀取時（read-time curation），也就是當前任務（current task）已知時再進行。給定檢索到的追蹤紀錄（trace）與當前任務，記憶策展器（memory curator）會針對當下需求合成一個精簡的任務適應性負載（task-adaptive payload）。由於此負載即用於該任務，策展器可以直接從即時任務成功與否（immediate task success）進行訓練，避免延遲效用訊號（delayed utility signal），也無需人為將相關任務分組。在 ALFWorld、WebShop 與 τ²-bench 上，我們的即時記憶（Just-in-Time Memory, JitMem）始終優於無記憶智慧體（no-memory agents），以及啟發式（heuristic）與學習式（learned）寫入時記憶方法，分別比最強基線（baseline）提升 16.2、16.3 與 3.9 絕對成功率點數（absolute success-rate points）。值得注意的是，即使是未經訓練的策展器，也已與這些基線相當，甚至超越它們，顯示出任務適應性的讀取時策展本身就是主要增益來源；進一步訓練策展器則能使增益進一步疊加。

### 核心貢獻（3～5點）
- 提出即時記憶（JitMem）架構，將記憶策展從寫入時延後至讀取時，依據當前任務生成任務適應性負載。
- 保留原始軌跡而非預先提煉為固定產物，避免寫入時不可逆的資訊損失與與查詢無關的摘要。
- 讓記憶策展器可直接利用即時任務成功與否作為訓練訊號，迴避長期信用分配問題與人為分組相關任務的需求。
- 在 ALFWorld、WebShop 與 τ²-bench 三個基準上，顯著優於無記憶、啟發式與學習式寫入時記憶基線。
- 顯示即使未經訓練的讀取時策展器已具競爭力，訓練後更能疊加增益。

### 適合對象
對大型語言模型智慧體、智慧體記憶系統、強化學習與自動化決策有興趣的研究者與工程師；特別適合關注如何設計能隨經驗持續改進、並適應新任務的智慧體系統之讀者。

## 深度分析

#### 方法論解析

##### 核心設計理念：從寫入時策展（write-time curation）轉向讀取時策展（read-time curation）

本文提出的 Just-in-Time Memory（即時記憶，JitMem）重新定義了智慧體記憶（agentic memory）的生命週期。傳統方法在任務完成後立即將軌跡（trajectory）濃縮成固定產物（fixed artifact），例如語言反思（verbal reflection）、可執行技能（executable skill）、工作流程（workflow）或可遷移推理策略（transferable reasoning strategy），並在之後透過相似度搜尋（similarity search）檢索。JitMem 則採用讀取時策展：記憶庫（memory bank）只被動地保存原始軌跡（raw trajectories），不進行任何不可逆的資訊丟棄；直到面對新任務時，才由記憶策展器（memory curator）根據當前任務（current task）即時合成一份任務適應性負載（task-adaptive payload）。

這種設計對應了認知科學中「情節記憶是重構而非重播」的觀點：回憶的內容會被當前目標與線索塑造。對 LLM 智慧體（LLM agents）而言，這意味著同一段過往軌跡可以針對不同下游查詢（query）提煉出不同教訓，例如同一段 household 互動軌跡，對一個任務可提煉狀態轉移模式（state-transition pattern），對另一個任務則可提煉物件放置策略。

##### 推論流程（inference pipeline）

如圖 1(a) 所示，JitMem 的推論流程包含四個主要模組：

1. **記憶庫（memory bank）**：以流式方式持續儲存原始軌跡。只有被執行器作為評判者（executor-as-judge）判定為成功的軌跡才會寫回，形成品質過濾（quality-filtered storage）。
2. **檢索器（retriever）**：根據當前任務 $x_t$ 從記憶庫中取出相關追蹤紀錄（relevant memories / traces）。
3. **記憶策展器（memory curator）**：同時閱讀取回的軌跡與當前任務，生成緊湊且任務條件化的任務適應性負載（task-adaptive payload），例如行動計畫（action plan）或針對性指引（guidance）。
4. **執行器（executor）**：將該負載注入上下文（context）後執行任務。

整個流程的關鍵在於「策展發生在讀取、而非寫入」。由於策展器看得到當前任務，它可以只保留對該任務有用的資訊，避免傳統寫入時摘要（query-independent summary）必須服務多種未來查詢的困境。

##### 訓練流程（training pipeline）

如圖 1(b) 所示，策展器的訓練完全建立在即時任務成功（immediate task success）上：

- 從固定的訓練庫（training bank）中抽樣一個任務，並檢索相關軌跡。
- 策展器針對該任務生成多個候選負載（candidate payloads）。
- 使用凍結執行器（frozen executor）分別嘗試這些負載，取得即時的任務獎勵（task reward）。
- 透過群相對策略優化（Group Relative Policy Optimization, GRPO）更新策展器。

這種設計把長期信用分配問題（long-horizon credit-assignment problem）壓縮成單一步驟：負載好不好，立刻由同一任務的成功與否判定。相較於學習式寫入時記憶（learned write-time memory）必須人為將相關任務分群（task grouping）以製造學習訊號，JitMem 的訓練目標更直接、訊號更乾淨。

##### 關鍵設計選擇

| 設計選擇 | 作用與優勢 |
|---|---|
| 保留原始軌跡（raw trajectories） | 避免過早且不可逆的資訊損失（premature and irreversible information loss），讓未來任務仍能取得所需細節（details）。 |
| 任務條件化策展 | 同一段軌跡可依不同任務產生不同負載，突破固定產物（fixed artifact）的查詢無關性。 |
| 成功軌跡過濾寫入 | 減少記憶庫雜訊，提升檢索與策展品質。 |
| 即時任務獎勵訓練 | 消除延遲效用訊號（delayed utility signal），簡化強化學習（RL）的信用分配。 |
| 凍結執行器 | 確保策展器學到的是「如何為該執行器準備有用記憶」，且訓練後可遷移到更強執行器。 |

#### 實驗數據解讀

##### 基準與整體表現

論文在三個互動式決策基準上評估：

- **ALFWorld**：文字式家庭環境，強調物件操作與導航。
- **WebShop**：網頁購物環境，強調多步驟資訊檢索與決策。
- **τ²-bench（tau-squared bench）**：第三個基準，推測涉及更複雜或更長程的任務規劃。

JitMem 在這三個基準上分別超越最強基線（baseline）**16.2、16.3、3.9 個絕對成功率點數（absolute success-rate points）**。這顯示讀取時策展在不同類型的智慧體環境中都具有穩健優勢。

##### 未訓練策展器已具競爭力

一個值得注意的發現是：**即使未經訓練的策展器（untrained curator）也已經能與、甚至超越現有寫入時方法**。例如，在 WebShop 上，未訓練的 JitMem-gemini 達到 **61.0% 成功率（success rate）**，而同樣使用 Gemini-2.5-Pro 作為策展器與執行器的 SkillOS 僅有 **41.0%**。這強烈說明：

1. **任務適應性讀取時策展本身就是主要增益來源**：單純把「在知道任務後才整理記憶」這件事做好，就能顯著提升表現。
2. **寫入時固定產物的查詢無關性是重大瓶頸**：即使背後是同一強大模型，提前濃縮成單一摘要仍會損失大量可用資訊。

在此基礎上，以 GRPO 訓練策展器則進一步放大優勢，顯示學習如何策展仍有額外價值。

##### 效率指標：Token 與步數雙降

除了成功率，JitMem 在推理成本上也有顯著改善：

- **輸入 token 減少 50.3%–56.3%**：相較於寫入時方法，JitMem 的任務適應性負載更緊湊，不會把對當前任務無用的通用反思或技能說明塞進上下文。
- **執行器步數（executor steps）減少 28.4%–31.4%**：更好的記憶負載讓執行器更快收斂到正確行動序列。

這兩項指標很重要，因為它們說明 JitMem 不僅提升最終成功率，也降低了每次任務的推理開銷，對實際部署更具吸引力。

##### 消融實驗（ablations）的啟示

論文指出三項設計各自獨立貢獻：

1. **任務條件化策展（task-conditioned curation）**：知道當前任務後再整理記憶。
2. **品質過濾儲存（quality-filtered storage）**：只保存成功軌跡。
3. **保留原始軌跡（retention of raw trajectories）**：不提前濃縮。

這三項缺一不可，共同支撐 JitMem 的優勢。其中任務條件化策展對應了方法論核心，而保留原始軌跡則是讓任務條件化成為可能的資料基礎。

##### 跨執行器遷移

訓練後的策展器能夠遷移到更強的執行器而無需重新訓練。這意味著 JitMem 學到的是一種相對通用的「記憶整理策略」，而非過度擬合特定執行器的行為模式，對於模型持續升級的場景特別實用。

#### 與現有研究的比較

##### 相對於啟發式寫入時記憶（heuristic write-time memory）

現有主流方法如 Reflexion（Shinn et al., 2023）產生語言反思、MemoryBank 與類似工作產生自然語言洞察（natural-language insight）、可執行技能（executable skills）、工作流程（workflows）、多粒度記憶項目，以及 ReasoningBank（Ouyang et al., 2026b）的可遷移推理策略，都屬於寫入時記憶。它們的共同特徵是：

- 在任務結束後立即產生固定產物；
- 推論時透過相似度搜尋檢索；
- 產物在產生時尚未見到未來查詢。

JitMem 的改進在於：

- **消除過早且不可逆的資訊損失**：原始軌跡完整保留，未來可依需求提取不同細節。
- **打破查詢無關性**：同一段軌跡可服務多種不同下游任務。
- **減少上下文浪費**：只把對當前任務有用的內容注入執行器。

##### 相對於學習式寫入時記憶（learned write-time memory）

近期研究如 Retroformer、Memory-R1、AgenticMemory、Memento 等嘗試以強化學習訓練記憶寫入策略。這些方法雖然增加了適應性，但仍面臨根本困難：

- **長期信用分配問題**：一個儲存決策（storage decision）的價值可能要很多任務後才顯現。
- **需要人為分群**：為了製造學習訊號，必須把相關任務湊在一起，這本身就是一種工程妥協。

JitMem 透過讀取時策展把獎勵訊號轉為即時任務成功，從而：

- 不需要人為任務分群；
- 信用分配僅限於單一互動；
- 訓練目標直接對應未來效用（future utility）的最終目標。

##### 定位與侷限

JitMem 的定位並非完全否定寫入時記憶，而是指出「在知道任務前就做不可逆濃縮」是主要瓶頸。然而，它也有一些潛在侷限：

- **檢索器品質依賴**：若檢索器（retriever）無法召回真正相關的軌跡，後續策展再強也難以彌補。
- **記憶庫規模與延遲**：長期保留原始軌跡會使記憶庫持續增長，雖然檢索可緩解，但儲存與檢索成本仍需管理。
- **策展器推理開銷**：每次任務都需即時生成負載，相較於直接檢索固定短摘要，會增加一次生成延遲。
- **執行器自我評判的誤差**：executor-as-judge 可能錯誤標記成功或失敗，影響訓練庫品質。
- **僅使用即時獎勵**：雖然簡化了訓練，但對於需要長期策略性抽象（例如跨領域遷移的通用原則）的記憶，可能仍需要額外的未來效用訊號。

#### 未來研究方向

##### 1. 混合式記憶架構：讀取時策展與語義摘要並存

JitMem 完全保留原始軌跡，雖然避免資訊損失，但長期儲存成本不可忽視。未來可探索**分層記憶（hierarchical memory）**：底層保留原始軌跡，上層維護輕量語義索引或抽象摘要，兼顧適應性與可擴展性。

##### 2. 聯合學習檢索器與策展器

目前檢索器與策展器似乎是分離模組。若能以端到端方式同時訓練檢索器與策展器，讓檢索決策也針對即時任務成功優化，可能進一步提升召回與策展品質。

##### 3. 從失敗軌跡中學習

JitMem 目前只儲存成功軌跡。未來可研究如何安全地納入失敗經驗，例如透過負面範例（negative examples）或對比學習，讓智慧體避免重複犯錯，同時不讓錯誤資訊污染記憶庫。

##### 4. 長期策略性記憶與未來效用訊號

雖然即時獎勵簡化了訓練，但某些高階能力（如跨任務通用推理策略）可能需要真正的未來效用估計。未來可設計**雙目標訓練**：同時優化即時任務成功與預測未來任務價值，結合 JitMem 的優勢與傳統寫入時方法的長期視角。

##### 5. 跨領域與終身學習（lifelong learning）

探討 JitMem 在任務分布持續變化的環境中是否會出現災難性遺忘或記憶庫膨脹，並設計遺忘機制、記憶合併（memory merging）或重要性採樣策略。

##### 6. 策展器模型輕量化與延遲最佳化

為了降低每次任務的生成延遲，可研究將訓練好的大型策展器蒸餾為小型專用模型，或設計快取機制，對相似任務直接重用過去生成的負載。

##### 7. 多智慧體共享記憶與個人化

在多智慧體系統中，不同智慧體可共享同一記憶庫，由各自的策展器提取適合自身角色的負載。此外，也可研究針對使用者偏好的個人化記憶策展。

##### 8. 隱私與安全

長期保留原始軌跡可能帶來隱私風險。未來可結合差分隱私（differential privacy）、軌跡去識別化，或可控遺忘機制，讓 JitMem 適用於敏感應用場景。

##### 9. 理論分析

從理論上刻劃「保留原始軌跡 + 任務適應性策展」相較於「固定摘要」的樣本複雜度與資訊理論優勢，有助於理解何種任務結構最能受益於讀取時策展。

##### 10. 與外部知識庫整合

除了智慧體自身經驗，未來可讓策展器同時檢索外部文件、API 文件或常識知識庫，生成結合內部經驗與外部知識的任務適應性負載。

## 論文問答

**Q1：JitMem 主要想解決智慧體記憶系統中的什麼根本問題？**
A：傳統的智慧體記憶大多在「寫入時」就進行策展，也就是任務一完成，便把整段軌跡濃縮成反思、技能、工作流程或推理策略等固定產物。這種做法迫使系統在還不知道未來查詢是什麼之前，就決定哪些資訊值得保留，導致過早且不可逆的資訊損失。JitMem 提出「即時記憶」的核心觀點，主張應該把策展延後到「讀取時」，讓記憶內容能夠根據當前任務動態重組，以真正提升未來任務的表現。

**Q2：為什麼現有的寫入時記憶方法難以最佳地服務未來任務？**
A：寫入時記憶會把原始軌跡蒸餾成單一且與查詢無關的摘要，但同一條過往軌跡對不同未來任務可能有不同的價值。例如，一次在家中移動物體的經驗，可能對某個任務提供「狀態轉移模式」，對另一個任務則提供「物件擺放策略」，固定產物無法同時滿足這兩種需求。此外，一旦細節在寫入時被丟棄，後續任務若需要這些細節，就再也無法恢復，造成不可逆的資訊缺口。

**Q3：學習一個寫入時策展器為什麼困難，讀取時策展又如何簡化這個問題？**
A：寫入時的儲存決策其效用可能要等到很多個任務之後、出現相關查詢時才會顯現，這形成了長期信用分配問題，讓訓練訊號變得稀疏且延遲。相對地，讀取時策展產生的任務適應性負載會立即被同一個任務消耗，因此策展器可以直接用「即時任務成功」作為獎勵訊號。這把信用分配壓縮成單次互動，也避免了學習式寫入時方法必須人為把相關任務分組才能製造學習訊號的做法。

**Q4：JitMem 的核心方法包含哪些元件與流程？**
A：JitMem 由記憶庫、檢索器、記憶策展器與執行器組成，記憶庫被動地保存未經濃縮的原始軌跡。在推論階段，檢索器根據當前任務取出相關追蹤紀錄，策展器再同時閱讀這些紀錄與當前任務，生成緊湊的任務適應性負載並注入執行器的上下文。執行完成後，由執行器作為評判者判斷正確性，成功的軌跡才會被存回記憶庫；訓練階段則從固定訓練庫取樣任務與軌跡，讓策展器產生多個候選負載，再由凍結的執行器回傳即時任務獎勵，透過 GRPO 更新策展器。

**Q5：相較於寫入時記憶，讀取時策展的關鍵創新是什麼？**
A：最大的創新在於「任務適應性」：同一條儲存的原始軌跡可以根據不同查詢產生不同的負載，而寫入時方法只能提供固定不變的產物。其次，讀取時策展保留了完整軌跡，不在寫入時丟棄任何資訊，讓後續任務有機會提取當下真正需要的細節。最後，這種設計把記憶的價值驗證從遙遠的未來移回到當前任務，使策展器能夠直接學習如何幫助執行器成功。

**Q6：JitMem 有哪些重要的設計選擇，讓它能夠發揮效果？**
A：JitMem 選擇無損保存原始軌跡，並透過執行器自我評判來進行品質篩選，只把成功的軌跡寫入記憶庫。它使用檢索器先縮小相關紀錄範圍，再由策展器根據當前任務進行條件式濃縮，並以群相對策略優化（GRPO）訓練策展器。消融實驗顯示，任務條件化策展、品質篩選儲存以及保留原始軌跡這三項設計各自都對整體表現有獨立貢獻。

**Q7：論文在哪些基準上進行評估，它們各自代表什麼樣的任務？**
A：論文選用了 ALFWorld、WebShop 與 τ²-bench 三個基準。ALFWorld 是文字式家庭環境，主要測試智慧體在室內空間中完成物件操作與導航的能力；WebShop 模擬網頁購物場景，要求智慧體根據商品描述在網頁上搜尋並下單；τ²-bench 則是另一個用來檢驗序列決策與經驗重用的測試環境。這三個基準涵蓋了不同的互動形式，能夠驗證 JitMem 在多樣任務上的通用性。

**Q8：JitMem 的主要實驗結果是什麼？**
A：在 ALFWorld、WebShop 與 τ²-bench 上，JitMem 分別比最強基線提升了 16.2、16.3 與 3.9 個絕對成功率點，並且穩定勝過無記憶智慧體、啟發式寫入時記憶與學習式寫入時記憶方法。值得注意的是，即使是未經訓練的策展器也已經具有競爭力或超越基線，例如在 WebShop 上，使用 Gemini-2.5-Pro 的未訓練 JitMem-gemini 達到 61.0% 成功率，而同樣模型的 SkillOS 僅有 41.0%。經過強化學習訓練後，表現還會進一步提升，同時輸入 token 比寫入時方法減少 50.3%–56.3%，執行步驟也減少 28.4%–31.4%。

**Q9：消融實驗揭示了哪些關鍵洞察？**
A：消融結果顯示，任務條件化的讀取時策展、品質篩選後的儲存機制，以及保留原始軌跡而非預先濃縮，這三項因素各自都對最終成功率有獨立且顯著的貢獻。這也證明了「任務適應性讀取時策展」本身就是進步的主要來源，而不是單純來自更強大的模型或更多的訓練資料。進一步來說，訓練策展器能夠在已經強大的未訓練讀取時策展基礎上再帶來額外增益，顯示學習如何策展仍有很大價值。

**Q10：哪些實際應用場景最能從 JitMem 受益？**
A：JitMem 特別適合需要長期運作、持續累積經驗的智慧體，例如個人助理、客戶服務機器人、網頁自動化代理以及家庭或服務型機器人。在這些場景中，同一段過往互動可能因使用者的新需求而需要以不同方式被利用，讀取時策展能讓系統針對當下請求給出最合適的指引。相較於預先把經驗固定成單一反思或技能，即時記憶能更靈活地應對多變且難以預測的未來任務。

**Q11：在產品化部署 JitMem 時需要考慮哪些實務問題？**
A：首先必須建立可持續擴充的串流記憶庫，並確保檢索器能夠在大量原始軌跡中快速找到相關紀錄，因為儲存未濃縮軌跡會隨時間增加儲存成本。其次，執行器作為評判者的準確性會直接影響記憶庫品質，若判斷錯誤就會把錯誤經驗保留下來，污染後續學習。此外，雖然讀取時策展增加了每次查詢的計算量，但它產生的緊湊負載能減少執行器步驟與上下文長度，因此需要在延遲、成本與準確度之間取得平衡，同時也要妥善處理軌跡中的隱私與敏感資訊。

**Q12：JitMem 可能對智慧體記憶與大型語言模型智慧體領域帶來什麼影響？**
A：JitMem 把領域焦點從「如何寫入更好的固定記憶」轉向「如何在讀取時根據任務重建最有用的記憶」，這與認知科學中「情節記憶是重構而非重播」的觀點相呼應。這種典範轉移可能催生新的記憶架構，例如結合更強大檢索器與策展器的分層記憶系統，以及以即時任務成功為導向的訓練目標。長遠來看，它也可能改變未來效用導向的評估方式，讓研究者更關注記憶在真實序列任務中的動態適應能力。

**Q13：這項研究有哪些可能的限制？**
A：JitMem 目前依賴執行器自行評判任務是否成功，若執行器判斷有偏誤，就會把錯誤或次佳軌跡存入記憶庫，影響後續策展品質。此外，長期保存原始軌跡雖然避免資訊遺失，卻也帶來儲存管理與檢索效率的挑戰，特別是在軌跡數量持續增長的開放環境中。訓練過程還需要一個凍結的執行器與固定訓練庫，這可能限制了它對執行器能力演進或全新任務分佈的即時適應。

**Q14：JitMem 在哪些情況下可能會失敗或表現不佳？**
A：如果檢索器取回的軌跡與當前任務不相關，策展器就可能基於錯誤脈絡生成誤導性的任務適應性負載，反而降低執行器成功率。當執行器作為評判者過度寬鬆，把失敗軌跡標記為成功時，記憶庫會累積雜訊，長期下來削弱系統表現。另外，對於完全沒有類似過往經驗的全新任務，JitMem 也無法憑空產生有效記憶，這時它的優勢就無法發揮。

**Q15：這項工作指出了哪些未來研究方向？**
A：未來可以探索同時訓練策展器與執行器，讓兩者互相適應，而不只是固定執行器來訓練策展器。另一個方向是發展更強大的學習式檢索器，讓它能根據當前任務主動找出真正有用的軌跡片段，而不僅依賴語意相似度。此外，把 JitMem 擴展到多模態軌跡、線上持續學習、階層式記憶結構，以及真實世界中的長期自主智慧體，都是值得進一步研究的路徑。

## 實務應用指南

### 適用場景

1. **企業內部流程自動化（如財務報銷、IT 工單處理）**  
   員工每天執行大量結構相似但細節不同的任務。JitMem 可保留原始執行軌跡，在面對新任務時即時萃取出符合當前表單、系統版本與審核規則的行動計畫，避免寫入時就把未來可能需要的例外處理細節丟掉。

2. **客服與銷售助理的長期對話記憶**  
   同一客戶在不同對話中可能詢問產品規格、退換貨、加購建議等。JitMem 讓智慧體在讀取時依當前問題重組過往對話，產生任務適應性負載，而不是用一份固定摘要應付所有後續查詢。

3. **軟體開發與維運（DevOps / SRE）**  
   過往的除錯軌跡、部署紀錄與事件回應步驟可存入記憶庫。當新警報發生時，策展器針對當前錯誤訊號與環境版本整理出可執行的排查流程，提升平均修復時間（MTTR）。

4. **醫療或法律文件輔助審查**  
   專家過往的審查軌跡包含大量脈絡。JitMem 可根據當前案件類型與法條或臨床指引，動態提取相關推理策略，同時保留原始文件細節以備需要追溯。

5. **遊戲與虛擬環境中的持續學習智慧體**  
   在開放世界或模擬環境中，智慧體會累積大量互動軌跡。JitMem 的讀取時策展能針對當前目標（例如「加熱物體」vs.「把書放到沙發」）從同一段軌跡中抽出不同教訓。

### 實作前置條件

**資料條件**

- 需要可收集並儲存的**原始軌跡**（觀察、動作、回饋、最終結果），而非僅有最終答案。
- 任務需具備可自動判斷的**任務獎勵**或正確性訊號，作為策展器訓練的即時回饋。
- 記憶庫規模會隨時間增長，需規劃儲存與檢索機制（向量資料庫 + 原始軌跡儲存）。

**運算條件**

- 推論時需額外呼叫一次**記憶策展器**（curator）來生成任務適應性負載，會增加延遲與 token 成本。
- 訓練策展器需要強化學習環境，建議準備可並行執行多個任務的運算資源，以支援 GRPO 的群組採樣與獎勵計算。
- 執行器（executor）與策展器可使用相同或不同模型；若採用分離模型，需確保兩者 API 與上下文長度相容。

**技能條件**

- 熟悉 LLM 代理系統設計（觀察—行動迴圈、工具呼叫、提示工程）。
- 具備強化學習基礎，尤其是策略梯度方法與 GRPO 或 PPO 的實作經驗。
- 能建立可重複的任務環境與評估指標（成功率、執行步驟、輸入 token 量）。
- 具備資料工程能力，以維護持續流入的原始軌跡與品質過濾邏輯。

---

### 實作步驟建議

1. **建立可記錄原始軌跡的執行器**  
   先讓智慧體在任務環境中運行，完整記錄每一步的觀察、動作、中間狀態與最終結果。不要在此階段做摘要或反思。

2. **設計記憶庫與檢索器**  
   將成功軌跡存入記憶庫，並建立檢索器（可用向量相似度或規則）根據當前任務取出相關軌跡。保留原始軌跡，避免過早丟失細節。

3. **實作讀取時策展器（curator）**  
   策展器的輸入為「當前任務 + 檢索到的相關軌跡」，輸出為緊湊的任務適應性負載（例如行動計畫、指引、策略）。可先使用提示工程建立未訓練版本作為基線。

4. **建立即時獎勵迴路**  
   讓執行器使用策展器產生的負載去執行當前任務，並根據任務成功與否給出立即獎勵。此獎勵直接用於更新策展器策略。

5. **以 GRPO 訓練策展器**  
   對每個抽樣任務，讓策展器生成多個候選負載，執行器分別執行後取得獎勵，再用群相對策略優化（GRPO）更新策展器。

6. **加入品質過濾與記憶維護**  
   只將執行器自我評判為正確的軌跡寫回記憶庫，並定期清理重複或低品質軌跡，避免記憶庫雜訊累積。

7. **評估與迭代**  
   同時追蹤成功率、輸入 token 量、執行步驟與延遲。比較未訓練策展器、訓練後策展器與寫入時記憶基線，確認讀取時策展帶來的增益。

### 潛在風險與注意事項

- **推論延遲增加**  
  讀取時策展需要額外生成步驟，可能拖慢首次回應。可透過快取常見任務的策展結果、限制檢索軌跡數量或縮短輸出長度來緩解。

- **記憶庫膨脹與檢索品質下降**  
  長期累積原始軌跡會使檢索難度上升。需搭配品質過濾、去重機制，並監控檢索到的軌跡對最終任務成功的貢獻。

- **策展器過度擬合訓練任務**  
  由於獎勵來自即時任務成功，策展器可能學會針對常見任務型態產生模板化負載。建議保留多樣化任務抽樣與跨環境評估。

- **執行器與策展器能力不匹配**  
  若策展器產生過於複雜的負載，而執行器模型較弱，可能無法有效執行。可根據執行器能力調整負載粒度，或讓兩者使用相近強度的模型。

- **獎勵訊號稀疏或難以自動判定**  
  若任務成功難以自動判斷，GRPO 訓練會不穩定。此時可先引入人工或模型輔助的評判機制，再逐步過渡到自動化評估。

### 與其他技術的整合建議

- **與 RAG 系統整合**  
  JitMem 的記憶庫可視為一種動態經驗 RAG。可將原始軌跡與文件知識庫分開管理：文件庫提供靜態知識，記憶庫提供動態執行經驗，策展器在讀取時決定如何融合兩者。

- **與現有寫入時記憶方法互補**  
  對於極少變動、高度可重用的技能（如常見 API 呼叫格式），仍可保留寫入時產生的技能庫；對於需要依任務調整的經驗，則使用 JitMem 的讀取時策展。

- **與觀察平台 / APM 整合**  
  在 DevOps 場景中，可將監控系統的警報與事件紀錄作為當前任務輸入，並把 JitMem 的記憶庫對接到現有日誌儲存（如 Elasticsearch、Splunk），透過檢索器撈取歷史軌跡。

- **與多智慧體框架整合**  
  可將策展器獨立為專門的「記憶智慧體」，由協調智慧體根據當前任務觸發；執行結果再由執行器回寫，形成持續學習的閉環。

- **與模型微調 / 持續預訓練整合**  
  JitMem 不改變執行器權重，因此可與週期性模型微調搭配：短期經驗透過記憶庫即時利用，長期穩定知識再蒸餾回模型參數中。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦在「為什麼讀取時策展比寫入時更好」這個核心直覺：想像你寫日記時，與其在當下決定哪段經驗對未來有用，不如等未來遇到問題時再回頭翻日記、只挑相關片段。掌握這個比喻後，再看圖 1 的推論與訓練流程，會更容易理解策展器、執行器與記憶庫三者的互動。

**AI 工程師**  
本論文提供了一個可落地的架構範本。閱讀時請特別留意 GRPO 訓練迴路的實作細節、原始軌跡的儲存格式、檢索器如何選取相關軌跡，以及執行器作為評判者的設計。這些是從論文原型轉為產品時最關鍵的工程決策，也直接影響延遲、成本與可維護性。

**研究人員**  
本文的核心貢獻在於重新定義記憶策展的時間點，並將長期信用分配問題轉化為單步即時獎勵。建議深入分析消融實驗，思考「任務條件化策展」、「品質過濾儲存」與「保留原始軌跡」三個因素各自的貢獻，並可進一步探索策展器與執行器之間的理論關係、泛化界限，以及在不同記憶規模下的擴展性。

**產品經理**  
這篇論文提供了一個強有力的產品差異化方向：讓 AI 助理「越用越聰明」，而且聰明的方式是針對當前問題動態學習，而非預先整理固定知識。評估導入時，請關注成功率提升、輸入 token 與執行步驟的下降幅度，以及推論延遲對使用者體驗的影響；同時規劃好資料隱私、軌跡儲存合規與錯誤經驗過濾的產品機制。
