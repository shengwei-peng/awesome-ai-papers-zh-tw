## ⚡ TL;DR

氛圍設計代理常重複產出相似介面，而調高詞元層級溫度會同時干擾美學與程式碼正確性。
本研究將設計方向變為明確中間決策，先以言語化取樣產出結構化規格，再由外部選擇器取樣，並以固定設定下游生成。
主題取樣擴大了選項覆蓋與截圖變化；線上逾三十萬任務顯示負面回饋減少、修正互動增加，但程式碼匯出增量尚不顯著。

## 摘要翻譯

Vibe 設計代理（Vibe design agents，氛圍設計代理）可將自然語言簡報（natural-language briefs）轉為渲染後的介面（rendered interfaces）與前端程式碼（frontend code）。然而，一個有用的設計代理（design agent）不應僅止於產生一個有效頁面：它應協助使用者探索連貫的替代方案（coherent alternatives）。提高詞元層級溫度（token-level temperature）是一種過於粗糙的解決方案，因為它同時變動美學決策（aesthetic decisions）與語法敏感的程式碼（syntax-sensitive code）。我們改以推論架構（inference architecture）將探索與實作分離，使設計方向（design direction）成為明確的中間決策（explicit intermediate decision）。受言語化取樣（Verbalized Sampling, VS）啟發，前置傳遞（pre-pass）會提出結構化設計規格（structured design specifications）並賦予典型性分數（typicality scores），外部選擇器（external selector）從中取樣一項，而下游生成器（downstream generator）則在固定設定（fixed settings）下，連同原始請求（original request）一起實現選定的規格。我們將此方法應用於 UI 主題（UI themes）與視覺素材提示（visual-asset prompts）。橫跨 168 個提示，針對每個溫度與每項干預措施（intervention）的組合各進行 1,255 次成對比較（paired comparisons），主題取樣（theme sampling）擴大了觀察到的選擇覆蓋範圍（selection coverage）與截圖變化度（screenshot variation），而 LLM 評審偏好（LLM-judge preferences）則因干預措施、提示複雜度（prompt complexity）與視埠（viewport）而異。在一項超過 300,000 個任務的線上實驗（online experiment）中，觀察到的程式碼匯出增量（code-export increase）在統計上仍不確定（statistically uncertain）；較少的負面回饋事件（negative feedback events）、較多的修正互動（correction interactions），以及適度的運作成本（operational costs）並存。綜合而言，這些發現指出，結構化設計規格可作為一個實際控制點（practical control point），在保持下游生成設定（downstream generation settings）固定的同時探索替代 UI 概念（alternative UI concepts）。

### 核心貢獻（3～5點）
- 提出一種將創意探索（creative exploration）與下游實作生成解耦的推論架構，使設計方向成為可獨立控制的明確中間決策。
- 借鏡言語化取樣（Verbalized Sampling），透過前置傳遞產生帶有典型性分數的結構化設計規格，再由外部選擇器取樣，並以固定設定的下游生成器實現規格。
- 將此方法應用於 UI 主題與視覺素材提示兩大設計維度，驗證其能擴大選擇覆蓋範圍與截圖變化度。
- 透過大規模線上實驗評估實務影響，發現負面回饋事件減少但修正互動增加，程式碼匯出增量則統計上不確定。
- 指出結構化設計規格是 Vibe 設計代理中一個可衡量且可控制的實際控制點，能在不影響下游生成設定的前提下支援替代 UI 概念探索。

### 適合對象
本論文最適合從事生成式使用者介面設計、AI 輔助創意工具、大型語言模型（LLMs）推論階段控制，以及人機互動研究的學者與工程師閱讀。對於正在開發 Vibe 設計代理、對話式網頁應用生成產品（如 v0、Bolt、Lovable），或關注如何在語法正確性與美學多樣性之間取得平衡的讀者，本文提供的解耦式創意探索架構與實證結果將特別具有參考價值。

## 深度分析

#### 方法論解析

本研究的核心貢獻在於提出一套「解耦式創意探索（decoupled creative exploration）」的推論架構，將「設計方向（design direction）」提升為明確的中間決策，從而與下游的程式碼實作分離。整體管線（pipeline）可分為四個階段：

1. **使用者請求（user request）**：代理接收自然語言簡報（natural-language briefs），並將其保留為任務規格。
2. **提案（proposal）**：透過言語化取樣（Verbalized Sampling, VS）進行前置傳遞（pre-pass），讓模型針對同一需求產生數個結構化設計規格（structured design specifications），每個規格附帶簡要理由與自我評估的典型性分數（typicality scores）。
3. **選擇（selection）**：外部選擇器（external selector）將典型性分數正規化為操作權重，再套用候選層級溫度（candidate-level temperature）進行取樣。
4. **生成（generation）**：下游生成器（downstream generator）在固定設定（fixed settings）下，同時接收原始請求（original request）與被選定的規格，產出最終介面與前端程式碼（frontend code）。

在具體實作上，作者針對兩種干預措施（interventions）進行實例化：

- **UI 主題（UI themes）**：規格包含種子色（seed color）、淺色或深色模式（light/dark mode）、標題與內文字型（headline/body fonts）、圓角程度（corner roundness）等屬性。選定一組屬性後，下游模型被指示必須以該組合實現設計系統。
- **視覺素材提示（visual-asset prompts）**：規格即為一條完整的圖像生成提示，涵蓋主體、構圖與視覺風格。選擇階段先決定圖像方向，再進入圖像生成器。

與單純提高詞元層級溫度（token-level temperature）不同，本方法將隨機性集中在「設計概念」這一語意層次，而非讓語法敏感的程式碼（syntax-sensitive code）與美學決策（aesthetic decisions）同時受到擾動。這創造了一個實際控制點（practical control point）：營運方可以在不改變下游生成設定（downstream generation settings）的前提下，調整候選層級溫度來控制探索廣度。

關於典型性分數，作者明確將其視為操作權重，而非經過校準的機率（calibrated probabilities）。當分數出現遺漏、負值、非數值或全零時，系統會重新提示（re-prompt）；若仍無法取得有效分數，則退回基線路徑。這種設計兼顧了穩健性，但也意味著分數的絕對數值不宜直接解釋為模型信心或人口偏好。

#### 實驗數據解讀

本研究的評估分為離線診斷與線上 A/B 實驗（online experiment）兩部分，並刻意採用多種指標，避免以單一「品質」分數概括創意探索的複雜性。

**離線實驗**涵蓋 168 個提示（prompts），針對每個溫度與每項干預措施進行 1,255 組成對比較（paired comparisons）。主要發現包括：

- **主題取樣（theme sampling）**顯著擴大了選擇覆蓋範圍（selection coverage）與截圖變化度（screenshot variation）。這表示在多次重複執行同一提示時，系統確實能產出更多樣的設計概念（alternative UI concepts），緩解了 UI 生成中的重複現象（repetition in UI generation）。
- **LLM 評審偏好（LLM-judge preferences）**並未呈現單一溫度全面勝出的情況，而是隨干預措施、提示複雜度（prompt complexity）與視埠（viewport）而變化。這呼應了 Human Creativity Benchmark 的觀點：專業判斷在遵循度、可用性與技術結構上容易收斂，但在視覺吸引力與美學方向上則可能分歧。

**線上實驗**規模超過 300,000 個使用者任務，結果呈現更細緻的權衡：

- **負面回饋事件（negative feedback events）**減少，暗示使用者對產出結果的不滿程度下降。
- **修正互動（correction interactions）**增加，可能代表使用者因看到不同方向而更願意進入迭代回饋（iterative feedback），也可能表示新方向帶來更多需要調整之處。
- **程式碼匯出增量（code-export increase）**在統計上不確定（statistically uncertain），因此尚無法斷言創意探索能直接轉化為更高的程式碼採用率。
- **運作成本（operational costs）**僅為適度增加，顯示該架構在生產環境中具有規模化可行性。

整體而言，數據支持「結構化設計規格可作為可控探索槓桿」的論點，但同時也指出：提升多樣性並不等同於提升偏好，設計代理（design agent）需要在探索廣度與輸出品質之間進行動態平衡（balance）。

#### 與現有研究的比較

本研究定位於多個相關領域的交會處，並針對既有方法的不足提出改進：

1. **相較於 RLHF 與 DPO**：人類回饋強化學習（Reinforcement Learning from Human Feedback, RLHF）與直接偏好最佳化（Direct Preference Optimization, DPO）能強化指令遵循（instruction following）與偏好對齊（preference alignment），但已知可能壓抑少數偏好（minority preferences），導致過度原型化輸出（overly prototypical outputs）。本研究並未將重複歸因於對齊本身，而是提供一個在推論階段（inference time）即可調節多樣性的機制，無需重新訓練模型。

2. **相較於言語化取樣（Verbalized Sampling, VS）**：VS 提出以模型自我報告的典型性分數來引發更廣泛的回應分布（response distribution）。本研究進一步將這些分數轉化為候選層級的取樣權重，並把選定的結構化規格注入下游生成器，使「探索」與「實作」成為可獨立控制的兩個階段。

3. **相較於現有 Vibe 設計產品**：Lovable、v0、Bolt、Replit Agent、Figma Make、Claude Design、Google Stitch 等產品多聚焦於從對話規格產出單一有效介面或可編輯原型（editable prototypes）。本研究則強調代理應協助使用者檢視多個連貫的替代方案（coherent alternatives），而非僅產生一個有效頁面。

4. **相較於截圖轉程式碼（screenshot-to-code）研究**：既有基準測試（benchmarks）多強調截圖轉程式碼保真度（screenshot-to-code fidelity）與互動正確性（interaction correctness）。本研究補充了「多樣性」與「可控探索」這兩項維度，並指出高保真 UI 轉程式碼工作流程（high-fidelity UI-to-code workflows）也需要納入創意探索的評估。

**限制方面**，本研究仍有若干待釐清之處：

- 未進行盲測的專業設計師評估，主要依賴 LLM 評審（LLM judge），其偏好可能與真實人類設計師不完全一致。
- 典型性分數未經校準，無法直接對應到使用者或群體機率。
- 線上實驗的指標多為代理指標，程式碼匯出增量不顯著，難以推論長期使用者滿意度。
- 僅針對主題與視覺素材兩項干預措施進行驗證，尚未涵蓋版面、互動、動畫等更廣泛的設計決策。

#### 可重現性評估

根據目前提供的全文脈絡，本研究並未釋出開源程式碼、資料集或模型權重。通訊作者隸屬 Google，且文中描述的管線涉及產品級設計代理，暗示其可能為內部專有系統。因此，從可重現性（reproducibility）角度來看，以下關鍵細節尚未公開：

- 前置傳遞（pre-pass）的確切提示模板與候選數量。
- 使用的基礎模型名稱、版本與下游生成器（downstream generator）配置。
- 候選層級溫度的具體數值與選擇政策（selection policy）的完整演算法。
- 截圖變化度與選擇覆蓋範圍的量化方式。
- LLM 評審的評分提示與成對比較（paired comparisons）的抽樣方式。
- 線上實驗的隨機分派、任務定義與事件追蹤規格。

若作者能釋出匿名化的提示集合、評估腳本與實驗紀錄，將大幅提升研究的可重複性，並有助於社群建立針對創意探索的公開基準測試（benchmarks）。

#### 未來研究方向

基於本研究的發現與限制，未來可朝以下方向延伸：

1. **擴展設計決策的覆蓋範圍**：將結構化設計規格從主題與視覺素材延伸至版面配置（layout）、互動模式、動畫曲線與元件架構，使代理能在更多維度上進行創意探索（creative exploration）。

2. **使用者可控的探索介面**：提供滑桿或選項讓使用者直接調整「典型性 vs. 多樣性」的權重，並在執行階段（runtime）即時檢視明確分布（explicit distribution），強化設計方向的可解釋性。

3. **典型性分數的校準與個人化**：研究如何將自我評估分數轉化為更可靠的機率估計，並結合使用者歷史偏好進行個人化取樣，以更好地保留少數偏好（minority preferences）。

4. **多輪探索與修正建模**：將修正互動（correction interactions）納入模型訓練或推論循環，讓代理能從使用者的迭代回饋中學習，逐步收斂到滿意的設計方向。

5. **與偏好最佳化的協同**：探索如何將本架構與 RLHF/DPO 結合，在維持語法正確性的同時，於獎勵函數中顯式鼓勵多樣且有用的回應（diverse useful responses）。

6. **跨視埠一致性**：由於 LLM 評審偏好會隨視埠（viewport）變化，未來可研究如何確保同一設計方向在不同裝置尺寸下仍保持連貫的視覺層級（visual hierarchy）。

7. **建立公開的人類評估基準**：設計包含專業設計師盲測的資料集，將視覺吸引力、美學方向、技術結構與可用性分開評分，以彌補目前僅依賴 LLM 評審的不足。

8. **長期使用者價值評估**：追蹤程式碼匯出後的實際採用率、後續編輯次數與任務完成率，以判斷創意探索是否真正提升設計代理（design agent）的長期實用價值。

## 論文問答

**Q1：Vibe 設計代理在創意探索上面臨什麼核心問題？**
A：Vibe 設計代理能將自然語言簡報轉換為渲染後的介面與前端程式碼，但一個真正有用的代理不應只產生一個有效頁面，而應協助使用者檢視多個連貫的替代方案。然而，現有管線在重複執行時常傾向回傳相似的常見 UI 模式，導致可探索的設計方向受到限制。因此，本研究關注如何讓重複執行探索變得可衡量且可控制，同時不犧牲程式碼生成的正確性。

**Q2：為什麼單純提高 token-level temperature 被視為一種粗糙的解決方案？**
A：提高詞元層級溫度會同時改變輸出中的美學決策與語法敏感的程式碼細節，無法選擇性地只控制設計方向。這會把需要多樣性的創意探索與需要穩定性的精確程式合成糾纏在一起，可能損害標記語言、樣式表與元件的連貫性。因此，這種做法缺乏一個明確且可操作的設計方向控制點。

**Q3：為什麼將創意探索與實作分離對設計代理很重要？**
A：探索受益於設計概念之間的變化，而程式碼生成則需要可預測性與語法正確性，兩者對解碼控制的需求不同。透過分離，使用者可以在定稿前比較多種有意義的方向，而下游生成仍維持固定設定以確保輸出品質。這也呼應了專業評估的觀察：人類對可用性與技術結構可能趨於一致，但對視覺吸引力與美學方向常有分歧。

**Q4：本文提出的核心方法是什麼？**
A：作者提出一種推論架構，將設計方向變成一個明確的中間決策：首先由前置傳遞產出結構化設計規格與典型性分數，接著由外部選擇器從中取樣一個，最後下游生成器在固定設定下實現選定的規格與原始請求。這個方法受到言語化取樣（Verbalized Sampling）的啟發，把典型性分數當作操作權重而非校準機率。如此一來，系統可以在不改變下游生成參數的情況下，改變所要追求的設計方向。

**Q5：這個架構的關鍵創新點有哪些？**
A：關鍵創新在於把結構化設計規格當作探索與實作之間的介面，使設計方向能獨立於解碼設定被改變。相較於傳統的 token-level 溫度，此處的溫度是作用在候選規格層級，因此只影響設計方向而不影響語法細節。此外，該架構可獨立套用在 UI 主題與視覺素材提示兩種不同的設計面向，展現其通用性。

**Q6：結構化設計規格包含哪些設計選擇？**
A：在主題實作中，規格綁定了種子顏色、淺色或深色模式、標題與內文字型，以及圓角程度，使下游設計系統生成必須使用選定的組合。在視覺素材實作中，規格則是一個圖像生成提示，描述主體、構圖與視覺風格。每個候選還包含簡短理由與典型性分數，若分數無效則會重新提示，仍無法取得時則退回基線管線。

**Q7：研究使用了哪些評估方式與數據規模？**
A：離線評估涵蓋 168 個提示，針對每個溫度與每項干預措施進行 1,255 次成對比較；線上則進行超過 300,000 個使用者任務的 A/B 實驗。評估指標包括選擇覆蓋範圍、截圖變化度、LLM 評審偏好，以及真實使用行為。由於創意品質難以用單一指標衡量，作者因此從多個面向分別報告結果。

**Q8：離線實驗的主要結果是什麼？**
A：主題取樣顯著擴大了觀察到的選擇覆蓋範圍與截圖變化度，代表系統確實產生了更多樣的設計方向。然而，LLM 評審偏好會隨著干預措施、提示複雜度與視埠而變化，並未出現一個 universally preferred 的取樣溫度。這說明探索廣度與評審偏好之間存在需要權衡的取捨。

**Q9：研究中有哪些消融或細部分析？**
A：作者比較了不同干預措施與溫度設定，並分析提示複雜度與視埠大小如何影響 LLM 評審的偏好。此外，UI 主題與視覺素材提示兩種實作被獨立評估，以確認架構在不同設計面向的效果。這些分析顯示，結果會隨著實驗條件而變，無法簡化為單一最佳設定。

**Q10：這項技術適合哪些實際應用場景？**
A：產品團隊或個人使用者在開發網頁應用程式時，可以在定稿前快速探索多種 UI 概念與視覺風格。例如，一個餐點規劃應用程式可以取樣不同的主題配色與食物圖片風格，再選擇最符合品牌調性的方向。這對 Lovable、v0、Bolt 等對話式設計工具特別有價值，能減少重複出現的傳統模式。

**Q11：線上實驗揭示了哪些產品層面的考量？**
A：線上實驗顯示負面回饋事件減少，但同時出現更多修正互動，且運作成本僅有適度增加。程式碼匯出增量在統計上仍不確定，因此無法斷言探索機制直接提升轉換行為。這意味著產品導入時需要權衡探索廣度與使用者操作摩擦，並持續監控修正行為是否帶來負擔。

**Q12：這項研究對設計代理領域可能帶來什麼影響？**
A：本研究指出結構化設計規格是一個實用的控制點，可用來探索替代 UI 概念，同時保持下游生成設定固定。它把可控制的探索連結到實際渲染介面與真實使用行為，為未來的設計代理提供了明確的架構參考。這也鼓勵後續研究將美學方向與程式碼生成進一步解耦，以兼顧創意與正確性。

**Q13：作者承認哪些限制？**
A：研究結果並未確立人類設計偏好，也未找到一個 universally preferred 的溫度，仍需要經過盲測的專業人工評估來驗證。此外，程式碼匯出增量在統計上不顯著，無法推論對商業指標的確切影響。LLM 評審偏好也僅是代理指標，不等同於真實使用者的審美判斷。

**Q14：系統可能出現哪些失敗或需要特別處理的情況？**
A：當典型性分數遺失、為負數、非數值或全為零時，系統會觸發重新提示，若仍無法取得有效分數則退回基線管線。過度探索可能導致更多修正互動，表示某些取樣方向需要使用者額外調整才能滿足需求。此外，在某些提示複雜度或視埠條件下，LLM 評審對生成結果的偏好可能較差。

**Q15：未來可以朝哪些方向延伸？**
A：未來可將此架構擴展到版面配置、互動行為與動態效果等更多設計維度，進一步豐富可探索的空間。也可以改進典型性分數的校準方式，並結合使用者回饋進行個人化的選擇策略。最後，進行大規模盲測的專業設計師評估，將是確認人類偏好與最佳溫度設定的關鍵下一步。

## 實務應用指南

## 適用場景

1. **對話式網站／應用程式生成工具**  
   當使用者輸入「幫我做一個咖啡廳訂位頁面」時，系統可先產生數組結構化 UI 主題規格（配色、字體、圓角、明暗模式），再固定下游生成參數實作，讓同一提示能穩定產出多種氛圍方向，而不會因 token-level temperature 調高而破壞語法正確性。

2. **電商或行銷活動的快速視覺探索**  
   行銷團隊需要為同一商品產生多種風格的著陸頁（Landing Page）。透過主題取樣與視覺素材提示分離，可在不改變前端程式碼生成設定的情況下，探索不同視覺層級與圖像風格，再交由設計師挑選後續細修。

3. **設計系統（Design System）的自動化變體生成**  
   企業已有既定元件庫，但需要為不同品牌活動或季節主題產生變體。可將「設計方向」抽離為明確的中間決策，讓下游生成器根據選定的結構化設計規格，輸出符合設計系統語法的前端程式碼。

4. **AI 輔助原型工具的「再來一個版本」功能**  
   在 Figma Make、v0、Bolt 等產品中，使用者常要求「給我另一個風格」。透過 Verbalized Sampling 先列出代表性替代方案並給出典型性分數，再由外部選擇器取樣，可讓每次重複執行探索都落在連貫的設計概念上，而非隨機雜訊。

5. **多語系或多裝置介面的視埠適配探索**  
   針對同一功能在不同視埠（viewport）呈現，可先產生設計方向規格，再分別以固定設定生成桌面版與行動版。這有助於研究提示複雜度與視埠對 LLM 評審偏好的影響，並找出較穩定的跨裝置設計策略。

## 實作前置條件

- **資料準備**  
  需要一組涵蓋不同複雜度與領域的 UI 生成提示（paper 使用 168 組提示），以及對應的評估資料：成對比較樣本、截圖、LLM 評審 prompt，以及線上實驗所需的回饋事件日誌（負面回饋、修正互動、程式碼匯出等）。

- **模型與運算資源**  
  需要可呼叫的大型語言模型（LLMs）或多模態模型作為前置傳遞（pre-pass）的提案模型，以及下游生成器（產生前端程式碼與渲染結果）。由於要執行多次重複執行探索與成對比較，離線評估建議具備可擴展的推論管線與截圖渲染環境（如 headless browser）。

- **技能需求**  
  團隊需熟悉提示工程（prompt engineering）、結構化輸出（JSON schema / function calling）、基本機率取樣與溫度縮放，以及前端技術棧（HTML/CSS/JS 或 React 等）。若要做線上 A/B 實驗，還需具備實驗設計、指標追蹤與統計分析能力。

## 實作步驟建議

1. **定義設計方向的可控維度**  
   先決定要分離哪些設計決策。以 UI 主題為例，可固定為：seed color、light/dark mode、headline font、body font、corner roundness；視覺素材則可固定為：subject、composition、visual style。這些維度將成為結構化設計規格的欄位。

2. **建立前置傳遞的提案模型**  
   使用 Verbalized Sampling 機制，要求模型針對使用者原始請求產出 3–7 組設計規格，每組包含規格內容、簡短理由，以及典型性分數。提示中應明確要求分數為非負數值，並設計重新提示（re-prompt）與 fallback 機制處理缺漏或異常分數。

3. **實作外部選擇器**  
   將典型性分數正規化為權重，再套用候選層級的溫度參數進行取樣。溫度可調：低溫偏向典型方案，高溫則鼓勵探索少見方向。此選擇器必須與下游生成器解耦，確保下游設定固定不變。

4. **串接下游生成器**  
   將被選定的規格與原始請求一起送入現有生成管線。提示中需明確指示生成器「必須使用選定的設計規格實作」，並保持解碼溫度、top-p、最大長度等參數在所有實驗條件下一致。

5. **建立離線評估儀表板**  
   追蹤選擇覆蓋範圍、截圖變化度、LLM 評審偏好，並按提示複雜度與視埠分層分析。建議使用成對比較與統計檢定，避免單一溫度被過度解讀為「最佳」。

6. **進行線上 A/B 實驗**  
   在實際產品中對照基線與干預措施，觀察負面回饋事件、修正互動、程式碼匯出增量與運作成本。由於 code-export increase 可能統計上不確定，建議設定足夠樣本數與長期追蹤週期。

7. **迭代規格欄位與取樣策略**  
   根據離線與線上結果，調整設計規格的粒度、候選數量、溫度範圍，以及重新提示條件。將「設計方向」視為產品控制點，持續優化而非一次性調整。

## 潛在風險與注意事項

- **典型性分數未經校準**  
  模型給出的分數是操作權重，而非真實機率。若直接視為機率進行解釋，可能導致取樣偏差或使用者誤解。建議在內部將其視為相對權重，並保留人工審核介面。

- **下游生成器忽略規格**  
  若提示設計不當，下游模型可能產出與選定設計方向不一致的介面。可透過強制結構化輸出、在 system prompt 中強調「必須使用選定規格」、以及自動驗證規格欄位是否出現在輸出中來降低風險。

- **過度探索導致可用性下降**  
  提高候選層級溫度雖能增加截圖變化度，但 LLM 評審偏好會隨提示複雜度與視埠改變。建議不要預設「溫度越高越好」，而應針對不同使用者族群提供預設檔（如保守／大膽／實驗性）。

- **線上指標解讀困難**  
  負面回饋減少與修正互動增加可能同時存在，未必代表整體體驗變好。建議搭配質性訪談與盲測的專業設計評估，避免僅以單一指標推論產品成效。

- **延遲與成本上升**  
  前置傳遞與多次候選生成會增加推論次數。需監控延遲與完成成本，並在候選數量、重新提示次數與使用者體驗之間取得平衡。

## 與其他技術的整合建議

- **與現有設計代理產品整合**  
  可將此架構作為現有 Lovable、v0、Bolt、Replit Agent 等產品的「風格探索層」，在不更動核心程式碼生成引擎的前提下，於輸入階段插入提案與選擇模組。

- **與強化學習與偏好最佳化搭配**  
  若已使用 RLHF 或 DPO 對齊模型，可將探索層產生的多樣設計方向納入後續偏好資料收集，特別是補足少數偏好的樣本，避免模型過度輸出常見 UI 模式。

- **與設計系統與元件庫銜接**  
  將結構化設計規格對應到企業設計 token（color token、typography scale、spacing scale），讓下游生成器直接引用 token，確保輸出符合內部設計規範。

- **與圖像生成模型銜接**  
  視覺素材提示可直接餵給 DALL·E、Midjourney、Imagen 等圖像生成器。建議在規格中加入構圖與風格關鍵字，並在生成後進行自動截圖比對，確保素材與 UI 主題一致。

- **與實驗平台與監控系統整合**  
  將候選層級溫度、選擇覆蓋範圍、規格欄位等 metadata 寫入事件日誌，搭配 A/B 測試平台與可視化監控，才能持續觀察不同干預措施在真實環境中的表現。

## 給不同背景讀者的閱讀建議

**初學者**：這篇論文的核心概念是「把設計風格選擇和寫程式碼分開做」。你可以先聚焦在圖 1 的管線：先讓 AI 提出幾種設計方向、選一個，再用固定設定生成網頁。不需要一開始就懂所有統計細節，重點是理解為什麼「調高 temperature」會同時讓畫面變化和程式碼變錯，而這個方法可以只讓設計變化。

**AI 工程師**：請特別關注 Verbalized Sampling 的實作細節、典型性分數的正規化與重新提示機制，以及候選層級溫度與 token-level 溫度的差異。論文強調將分數視為操作權重而非校準機率，這會影響你如何設計外部選擇器與 fallback 策略。線上實驗的指標設計與成本評估也值得參考。

**研究人員**：本文結合了創意探索、偏好對齊、資料層級典型性偏差與 UI 生成等多個議題。可深入探討為何 LLM 評審偏好會隨提示複雜度與視埠變化，以及「選擇覆蓋範圍」與「截圖變化度」作為探索指標的有效性。未來可延伸至多輪迭代回饋、人類設計師的盲測偏好，或將此方法應用於互動正確性要求更高的介面。

**產品經理**：這項技術提供了一個具體的產品控制點——「設計方向規格」。你可以把它想像成給使用者的「風格轉盤」或「再來一版」功能，但背後有結構化規格支撐，能讓團隊在創意與穩定之間取得平衡。請留意線上實驗顯示 code-export 增量統計上不確定，因此上線時應同時追蹤負面回饋、修正互動與設計師質性評估，避免過度優化單一指標。
