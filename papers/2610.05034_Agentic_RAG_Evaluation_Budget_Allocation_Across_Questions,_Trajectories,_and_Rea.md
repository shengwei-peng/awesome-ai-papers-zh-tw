## 摘要翻譯

代理式檢索增強生成（Agentic RAG）中的評估預算（Evaluation Budget）涵蓋題目、搜尋軌跡（Search Trajectory）與重複答案。我們使用 HotpotQA 與 MuSiQue 上的檢索回饋比較（Retrieval-Feedback Comparison）來衡量配置精確度（Allocation Precision）、讀取效率（Reading Efficiency）與成本邊界（Cost Boundary）。在 34.14–34.39M 模型 token 的條件下，相較於五次讀取，較廣的題目涵蓋範圍（Question Coverage）使標準誤（Standard Error）降低 33%；相較於三條軌跡，則降低 12.6%。封存的巢狀預測（Nested Forecast）與僅題目預測（Q-only Forecast）對這些配置的預測誤差分別在 4.0% 與 3.5% 以內。除了雙軌跡稽核（Two-Trajectory Audit）之外，深度子集（Depth Subset）並未展現明確的預測優勢。在相同 token 預算（Token Budget）下，相對於擬合最優值（Fitted Optimum）的單次讀取變異（One-Read Variance）懲罰為 0 至 9.9%，且 Pro 模型不確定性（Pro Uncertainty）顯著。在記錄的模型費用（Model Fee）下，當每千次請求的搜尋價格（Search Price）為 0 至 1 美元時，更多題目優於更多軌跡；題目與讀取的費用排名仍無法確定。溫度零（Temperature Zero）將答案歧異（Answer Disagreement）從 14.3% 降至 3.4%，而比較精確度（Comparison Precision）維持相近。

關鍵詞：代理式檢索增強生成（Agentic RAG）；評估預算（Evaluation Budget）；可概化理論（Generalizability Theory）；重複抽樣（Repeated Sampling）。

### 核心貢獻（3～5點）
- 系統量化代理式 RAG 評估預算在題目、軌跡與讀取三個維度的配置效率，證實擴大題目涵蓋範圍比增加讀取次數或軌跡數更能有效降低標準誤（分別降低 33% 與 12.6%）。
- 驗證巢狀預測與僅題目預測模型能以極小誤差（分別在 4.0% 與 3.5% 以內）預測最佳預算配置，為評估設計提供實用的事前規劃工具。
- 釐清成本邊界：在低搜尋價格（每千次請求 0 至 1 美元）下，擴展題目數量優於增加軌跡數量；但題目與讀取間的費用權衡仍未有定論。
- 證實溫度零（Temperature Zero）設定能將答案歧異從 14.3% 大幅降至 3.4%，同時維持相近的比較精確度，為提升評估穩定性提供明確指引。

### 適合對象
從事代理式檢索增強生成（Agentic RAG）系統研發與評估的研究者及工程師；關注大型語言模型評估方法論、可概化理論（Generalizability Theory）與統計檢力的學術界人士；以及需要設計兼顧成本效益與統計可靠性的高效 NLP 評估流程之實務工作者。

## 深度分析

#### 方法論解析

本論文提出一套系統化的預算配置框架，用於評估代理式檢索增強生成（Agentic RAG）系統在三個維度上的資源分配：題目數量（Q, Questions）、搜尋軌跡數（T, Trajectories）、以及重複讀取次數（R, Reads）。其方法論核心建立在**配對搜尋策略比較**（Paired Search Policy Comparison）與**可概化理論**（Generalizability Theory）的結合之上。

**配對搜尋策略設計**：論文採用兩種策略進行配對實驗——Open 策略在檢索前預先規劃全部四個查詢，僅基於題目與查詢歷史；Adaptive 策略則利用先前結果動態規劃第二至第四個查詢。兩種策略共用首個查詢與首次搜尋結果，最終由讀取器從五份文件中產生答案。這種設計巧妙地隔離了策略差異，使評估目標聚焦於答案 F1 對比值 ΔFB = F1_Adaptive − F1_Open 的標準誤，而非絕對效能。

**巢狀抽樣架構**：研究採用三因子巢狀設計（Q × T × R），其中題目為最高層級，軌跡嵌於題目內，讀取嵌於軌跡內。具體配置包含三個主要配置：A（446/2/1）、B（174/2/5）、C（298/3/1），加上稽核配置（96/2/5）、模型控制（96/2/2）與深度控制（48/5/2）。此設計允許在固定模型 token 預算（約 34.35M）下進行精確的資源取捨比較。

**變異數分解與預測**：論文採用可概化理論中的變異數分量估計（variance component estimation），將總變異分解為題目層（σ²Q）、軌跡層（σ²T/Q）與讀取層（σ²R/QT）。其變異數公式為：

V(Q,T,R) ≈ σ²Q/Q + σ²T/QT + σ²R/QTR

此公式的關鍵在於各分量有不同的縮放權重——題目變異以 1/Q 縮放，軌跡變異以 1/(QT) 縮放，讀取變異以 1/(QTR) 縮放。這解釋了為何增加題目數量比增加讀取次數更能有效降低標準誤。

**預測驗證機制**：研究使用預先保存的 96 題稽核資料作為預測基準，採用兩種預測模型：巢狀模型（nested model）允許 Q、T、R 變動；Q-only 基線則固定每題變異，僅以 1/√Q 縮放標準誤。這種「先稽核、後驗證」的設計避免了資料窺探（data snooping），所有參數在擴展實驗前即已固定。

**成本計算**：研究同時追蹤模型 token 成本與 API 費用，並考慮快取（caching）效應。共享儲存格（shared cells）僅執行一次，這在配對設計中能顯著降低實際運算成本。

#### 實驗數據解讀

**核心發現：題目覆蓋的優勢**：在 34.14–34.39M 模型 token 的等成本條件下，配置 A（446 題/2 軌跡/1 讀取）的標準誤比配置 B（174 題/2 軌跡/5 讀取）低 33%，比配置 C（298 題/3 軌跡/1 讀取）低 12.6%。這項結果量化了「廣泛題目覆蓋」相對於「重複讀取」與「多軌跡」的具體優勢——在固定預算下，將資源投入題目多樣性比投入單題的多次重複更能提升評估精確度。

**預測準確度**：巢狀預測與 Q-only 預測對實際配置的預測誤差分別僅為 4.0% 與 3.5%。這顯示即使使用簡單的 Q-only 縮放規則，也能達到接近完整巢狀模型的預測精確度。然而，深度子集（depth subsets，48 題/5 軌跡/2 讀取）相較於雙軌跡稽核（two-trajectory audit）並未展現明顯的預測優勢，這暗示在軌跡維度上擴展的邊際效益有限。

**單次讀取的變異懲罰**：在相同 token 預算下，單次讀取相對於擬合最優值的變異懲罰為 0–9.9%，但 Pro 模型配置存在顯著不確定性。這意味著 Flash 工作流程中單次讀取已具效率，但 Pro 模型因變異特性不同而難以得出確定結論。

**費用邊界分析**：在記錄的模型費用下，當搜尋價格介於 0–1 美元/千次請求時，「更多題目」優於「更多軌跡」。然而題目與讀取的費用排序仍未確定，這反映了實際部署中快取策略與搜尋計價方式的複雜性。

**溫度效應**：溫度從 0.7 降至 0 時，答案歧異率從 14.3% 大幅降至 3.4%，但比較精確度（comparison precision）維持相近。這項發現支持 Miller [7] 的論點：降低溫度會改變被評估的行為本身，而非單純提升一致性。在配對比較中，由於兩策略受相同溫度影響，溫度對 ΔFB 標準誤的影響有限。

**資料集平衡**：HotpotQA 與 MuSiQue 各佔 50% 權重，標準誤結合資料集內變異與相等權重，這避免了單一資料集偏差。配對 95% 百分位信賴區間透過 10,000 次題目層級自助重抽（bootstrap）產生，保留了 F1 分數的有界分佈特性。

#### 與現有研究的比較

**理論基礎的延伸**：本研究將 Sanderson 與 Zobel [2]、Webber 等人 [3] 在資訊檢索（Information Retrieval）領域建立的主題覆蓋原則延伸至代理式 RAG 評估。Sakai [4] 的基於檢力（power）與區間寬度（interval-width）的設計在此被具體實踐。論文特別引用 Bodoff 與 Li [5] 的成本導向配置法則（cost-based allocation rule）以及 Urbano 等人 [6] 對 D-study 預測敏感性的研究，後者提醒我們預測誤差本身需要被報告——這正是本論文的核心方法論貢獻。

**配對推論的應用**：Miller [7] 區分題目變異與答案變異並發展配對推論（paired inference）的工作在本研究中得到直接應用。論文也呼應了 IR 測試研究 [8–10]、重複執行分析 [11, 12] 與配對式 NLP 評估 [13, 14] 的方法論傳統。與 Same Agent, Different Answers [15] 不同，本研究的結果變數是配對四查詢策略比較的精確度，而非單輪策略下的答案相容性。

**代理式檢索的資源觀點**：論文將 RAG [1] 與 DeepResearchGym [16] 視為任務與存取設定的提供者，並引用語料庫與生成器取捨（corpus–generator trade-off）[17] 將檢索存取視為推論資源。搜尋日誌研究 [18]、相關性回饋（relevance feedback）[19, 20]、查詢擴展（query expansion）[21, 22] 與交錯搜尋（interleaved search）[23, 24] 為策略比較提供了動機。證據效用診斷（evidence-utility diagnostics）[25, 26] 則幫助區分檢索品質與下游效益。RRF [27]、集合式檢索（setwise retrieval）[28] 與上下文排序（context order）[29] 促使最終封包選擇的明確化。

**改進與侷限**：
- **改進**：相較於過往僅關注單一維度（題目或重複）的研究，本論文首次在代理式 RAG 情境下進行三維度的聯合預算分析，並提供實證預測誤差。
- **侷限**：(1) 僅使用兩個多跳問答資料集（HotpotQA、MuSiQue），推廣至其他領域（如開放領域 QA、對話系統）需驗證；(2) 模型僅限 DeepSeek-V4.1-Flash 與 DeepSeek-V4-Pro-0813，結論對其他模型的可移植性未經測試；(3) 缺乏不可變的模型或索引快照，這影響了完全可重現性；(4) 軌跡數僅測試至 5，更高軌跡數的擴展行為未知。

#### 可重現性評估

**程式碼與資料**：論文聲明提供「附隨成品」（accompanying artifact），包含計分結果與獨立分析。然而，從全文未能確認具體的開源儲存庫（如 GitHub URL）或資料釋出細節。讀者需透過論文附錄或作者機構管道取得實驗材料。

**資料集可及性**：HotpotQA [31] 與 MuSiQue [32] 為公開可取得的多跳問答資料集，FineWeb 透過 DeepResearchGym [16, 30] 存取，七個分割區與每查詢十個結果的設定在附錄 B 中有明確定義。RRF 與 RR 選擇器的精確公式亦在附錄 B 提供。

**模型權重與設定**：模型使用 DeepSeek-V4.1-Flash（deepseek-flash）與 DeepSeek-V4-Pro-0813（deepseek-v4-pro），透過 API 存取而非本地權重。論文坦承「不可變的模型或索引快照不可用」，這是商業 API 評估的固有限制。精確提示（prompts）與記錄的服務設定在附錄 A 中提供。

**配置固定性**：配置、ID、主要選擇器平均對比值與 34.35M 模型 token 目標在呼叫前即已固定。共享儲存格僅執行一次，所有計畫失敗保留零分。稽核參數與變異數公式在擴展前固定，數值預測為追溯計算，未使用新結果擬合或選擇參數——這是良好的預註冊（pre-registration）實踐。

**隨機性控制**：使用種子化洗牌（seeded shuffle）選擇巢狀子集，溫度控制實驗在相同 96 題上進行三次讀取抽樣。10,000 次自助重抽提供穩定的信賴區間估計。

**可重現性挑戰**：(1) 模型 API 行為可能隨時間變化；(2) 索引狀態非快照化，相同查詢可能返回不同結果；(3) 計價結構隨提供者政策調整。這些因素使得長期完全位元重現（bit-exact reproduction）困難，但統計層級的可重現性應可達成。

#### 未來研究方向

**多模型與多提供者比較**：將分析擴展至更多 LLM 提供者（如 GPT、Claude、Gemini）與不同規模模型，檢驗變異數結構是否隨模型能力變化。特別是 Pro 模型的「實質不確定性」是否反映模型特性或樣本不足，值得深入探討。

**領域與任務擴展**：將預算配置框架應用於單跳問答、開放領域 QA、長文件 QA、對話系統等不同任務類型。不同任務的變異數結構可能差異顯著，例如對話任務中軌跡變異可能比讀取變異更為關鍵。

**動態預算配置**：發展自適應預算配置演算法，根據初步稽核結果即時調整 Q、T、R 比例。這可結合序列分析（sequential analysis）與最佳停止（optimal stopping）理論，在達到預定精確度時停止實驗。

**成本模型精緻化**：納入更細緻的成本維度，如延遲成本、快取命中率、錯誤重試成本。將 token 預算轉換為實際美元成本時，需考慮企業級部署的批量折扣與承諾用量折扣。

**軌跡維度深探**：論文顯示深度子集（5 軌跡）相較雙軌跡稽核無明顯預測優勢，但這是否意味軌跡變異已飽和？未來可探索軌跡變異與問題難度、領域特性、規劃器品質的交互作用。

**溫度與多樣性的權衡**：溫度從 0.7 降至 0 將答案歧異從 14.3% 降至 3.4%，但改變了被評估行為。未來可研究「行為保留溫度」（behavior-preserving temperature）的概念——在不改變策略相對優勢的前提下最大化讀取一致性。

**預測誤差的元分析**：彙整多個研究的稽核-預測誤差資料，建立預測精確度的先驗分佈，幫助研究者在實驗前更準確估計所需樣本量。

**配對設計的統計檢力**：發展專為配對策略比較設計的統計檢力分析（power analysis），將 ΔFB 的最小可偵測效應（minimum detectable effect）與 Q、T、R 配置直接連結，提供實驗設計的實務指引。

**多策略與多維度比較**：將框架從兩策略配對擴展至多策略同時比較，並考慮策略間的相關結構。這在實際系統選擇中更具實用價值，但變異數分解將更為複雜。

## 論文問答

**Q1：這篇論文主要解決什麼核心問題？**
A：這篇論文聚焦於代理式檢索增強生成（Agentic RAG）系統評估中的預算配置問題。在固定的模型 token 預算下，研究者需要在三個維度間做取捨：題目涵蓋範圍（Q）、搜尋軌跡數（T）、以及重複讀取次數（R）。由於每個維度的變異來源不同，對策略比較精確度的影響也截然不同，因此如何將有限的評估資源做最佳分配，成為此領域的關鍵挑戰。論文透過 HotpotQA 與 MuSiQue 兩個多跳問答資料集，系統性地量化了不同配置下的標準誤與成本邊界。

**Q2：為什麼現有的評估方法無法直接套用於代理式 RAG？**
A：傳統資訊檢索評估主要關注主題涵蓋範圍與相關性判斷的變異，但代理式 RAG 額外引入了規劃、檢索與讀取三層成本，使得預算分配問題更為複雜。現有的可概化理論（Generalizability Theory）雖然提供了成本導向配置法則的數學框架，但其在代理式 RAG 場景下的預測準確度與不確定性尚未被實證檢驗。此外，語料庫與生成器之間的取捨（corpus–generator trade-off）使得單一維度的變異分析不足以反映真實的評估不確定性，這正是本論文試圖填補的研究缺口。

**Q3：這項研究為何重要？**
A：在實際部署代理式 RAG 系統時，評估成本往往是決定能否進行嚴格策略比較的瓶頸。若配置不當，可能導致研究人員在錯誤的維度上重複投入資源，卻無法有效降低比較的不確定性。本研究提供了具體的經驗法則：在 34.14–34.39M 模型 token 的預算下，更廣的題目涵蓋範圍比五次重複讀取降低 33% 的標準誤，這對實務上的評估設計具有直接指導意義。同時，論文也揭示了搜尋價格與模型費用如何影響「題目 vs. 軌跡」的相對優勢，為成本敏感的部署決策提供了量化依據。

**Q4：本研究的核心方法論是什麼？**
A：論文採用配對搜尋策略比較（paired search policies）作為基礎實驗設計，比較 Open（一次性規劃四個查詢）與 Adaptive（依先前結果調整後續查詢）兩種規劃策略。透過 DeepResearchGym 框架在 FineWeb 語料上執行，並使用 RRF 與 RR 兩種選擇器從共同候選池中挑選五份文件供讀取器生成答案。變異數估計上採用可概化理論的巢狀模型 V(Q,T,R) ≈ σ²Q/Q + σ²T/QT + σ²R/QTR，並以 10,000 次題目層級自助法（bootstrap）建構配對 95% 百分位信賴區間。

**Q5：本研究的關鍵創新點為何？**
A：本研究最重要的創新在於將可概化理論的 D-study 預測與實際執行的巢狀配置進行系統性對比，量化了「巢狀預測」與「僅題目預測（Q-only forecast）」兩種縮放基準的預測誤差（分別為 4.0% 與 3.5%）。此外，論文設計了共享儲存格（shared cells）的配置 A/B/C，使不同配置間能直接進行精確比較而非僅依賴理論推估。溫度控制實驗（temperature zero 將答案歧異從 14.3% 降至 3.4%）則提供了讀取效率的具體測量，這在過去的代理式 RAG 評估文獻中較為少見。

**Q6：在實驗設計上有哪些重要的選擇？**
A：研究團隊刻意將配置、題目 ID、主要選擇器平均對比值，以及 34.35M 模型 token 目標在執行新實驗前先行固定，以避免事後調整（post-hoc tuning）造成的偏差。共享儲存格僅執行一次以節省成本，並透過播種隨機（seeded shuffle）選取巢狀子集，確保 A/B/C 配置的可比較性。此外，所有規劃失敗的儲存格保留零分而非排除，以維持估計的無偏性。模型選擇上同時納入 DeepSeek-V4.1-Flash 與 DeepSeek-V4-Pro-0813，以檢驗不同模型規模下的配置穩健性。

**Q7：本研究使用了哪些基準資料集？**
A：研究採用兩個多跳問答領域的標準資料集：HotpotQA 與 MuSiQue，兩者在最終分析中各佔 50% 的權重。HotpotQA 與 MuSiQue 都要求模型整合多個段落才能回答，這正好契合代理式 RAG 的多步驟檢索特性。評估指標使用答案正規化的 token F1 與精確匹配（exact match），並以 F1 的差值 ∆F_B = F1_Adaptive − F1_Open 作為配對比較的核心結果變數。

**Q8：本研究最重要的實驗結果為何？**
A：在 34.14–34.39M 模型 token 的等成本條件下，配置 A（446 題 / 2 軌跡 / 1 讀取）的標準誤比配置 B（174 題 / 2 軌跡 / 5 讀取）低 33%，也比配置 C（298 題 / 3 軌跡 / 1 讀取）低 12.6%。這顯示在固定預算下，擴展題目覆蓋比增加重複讀取或軌跡數更能有效降低比較不確定性。此外，單次讀取評估在 Flash 工作流程中效率良好，但 Pro 配置仍存在實質不確定性，無法做出明確結論。

**Q9：本研究進行了哪些消融實驗？**
A：論文包含數項重要的消融分析：首先是溫度控制實驗，在 96 題上以相同證據封包進行三次讀取，比較溫度 0 與 0.7 下的答案歧異；其次是模型控制，使用 96 題、T=2、R=2 的配置比較 Flash 與 Pro 模型；再者是深度子集（depth subset）分析，使用 48 題、T=5、R=2 檢驗巢狀模型在更高軌跡數下的預測表現。這些消融實驗共同確立了「雙軌跡稽核（two-trajectory audit）」已足以支撐後續預測，更深的子集並未帶來明顯的預測優勢。

**Q10：本研究的成果適用於哪些實際場景？**
A：對於需要嚴格比較不同代理式 RAG 策略的研究團隊而言，本研究提供了具體的預算分配指引，特別是在雲端 API 計費的環境下。當搜尋價格落在 $0–1 per 1,000 requests 的範圍時，「更多題目」幾乎總是優於「更多軌跡」，這對中小型研究團隊的資源規劃至關重要。此外，對於部署階段的 A/B 測試，溫度零設定能將答案歧異從 14.3% 大幅降至 3.4%，這對需要穩定輸出的生產環境具有直接參考價值。

**Q11：在產品化考量上，本研究帶來哪些啟示？**
A：產品團隊在設計評估流水線時，應優先投資於擴展題目集的多樣性，而非在單一題目上反覆生成多次答案。本研究顯示五次重複讀取的投資報酬率遠低於將相同預算轉投入更多題目，這對評估成本最佳化具有實質意義。同時，快取機制（caching）的存在會改變題目與軌跡的相對成本優勢，因此產品定價模型需要將快取命中率納入考量。溫度參數的選擇則應根據應用場景對答案穩定性的要求來決定，溫度零適合需要可重現結果的場景。

**Q12：本研究對整個領域的影響為何？**
A：本研究將可概化理論從傳統資訊檢索評估延伸至代理式 RAG 場景，提供了經實證檢驗的預測模型與其不確定性邊界。這有助於建立更嚴謹的代理式 RAG 評估標準，使不同研究間的比較更具可信度。論文中關於「巢狀預測 vs. 僅題目預測」孰優的實證結果（兩者差距僅 0.5 個百分點），也為後續研究選擇簡化模型提供了依據。整體而言，本研究推動了領域從「經驗法則」走向「量化配置」的轉變。

**Q13：本研究承認哪些限制？**
A：作者明確指出模型與索引快照並非不可變（immutable），這意味著實驗結果可能受到底層基礎設施變動的影響。此外，Pro 配置的單次讀取變異懲罰存在 0–9.9% 的不確定性區間，使得該模型規模下的最佳配置仍無法確定。題目與軌跡的費用排名在快取與搜尋價格變動下仍未完全釐清，這限制了結論在極端成本情境下的可推廣性。

**Q14：本研究可能存在哪些失敗案例？**
A：在搜尋價格極高（例如超過 $1 per 1,000 requests）的情境下，「更多題目」的優勢可能會被逆轉，因為每個新題目都會觸發額外的搜尋成本。此外，若代理式 RAG 的規劃階段高度依賴軌跡間的累積證據，則雙軌跡稽核可能不足以捕捉規劃品質的完整變異。對於需要極高答案穩定性的應用（如醫療或法律領域），單次讀取的配置可能無法滿足品質要求，即使其統計效率較高。

**Q15：本研究的未來方向為何？**
A：未來研究可朝幾個方向延伸：首先是在更多模型與更大規模的代理式 RAG 系統上驗證配置結論的穩健性；其次是將預算分配問題擴展至包含人類評估成本的多目標最佳化；再者是發展線上（online）配置調整機制，使評估能根據初步結果動態重新分配剩餘預算。此外，結合語料庫與生成器取捨的聯合最佳化，以及探索非平衡巢狀設計下的變異數估計方法，都是值得深入的研究議題。

## 實務應用指南

### 適用場景

1. **企業 RAG 系統供應商選型與 A/B 測試**：當企業要在兩個或多個 RAG 服務（如內部自建 vs. 商用 API）之間做選擇時，可採用本文的配對策略比較框架，以四查詢配對設計搭配 96–446 題的題目集，在固定 token 預算下量化策略差異的標準誤，避免因題目太少或重複讀取不足而誤判方案優劣。

2. **學術基準與排行榜的可靠評估**：研究團隊在 HotpotQA、MuSiQue 等多跳問答基準上發表新方法時，可套用本文的巢狀抽樣配置（A: 446/2/1、B: 174/2/5、C: 298/3/1），在約 34M token 的預算下同時報告題目涵蓋、軌跡數、讀取次數三個維度的變異組成，提升排行榜比較的統計可信度。

3. **客服／知識庫 RAG 的成本敏感部署**：在客服場景中，搜尋 API 與 LLM 推論費用是主要成本變數。本文指出在搜尋價格介於 \$0–1／千次請求時，「更多題目」優於「更多軌跡」，可作為客服系統容量規劃的決策依據。

4. **法遵與審計場景的單讀取評估**：當評估結果需具備可重現性（例如法遵文件檢索、醫療問答），可採用溫度 0 + 單次讀取配置。實測顯示此配置在 Flash 工作流程下變異懲罰僅 0–9.9%，且能將答案歧異從 14.3% 降至 3.4%。

5. **內部模型升級決策（Flash vs. Pro）**：當團隊要在 DeepSeek-Flash 與 Pro 等不同等級模型間做遷移決策時，可利用本文的 96 題、雙軌跡、雙讀取控制組，在控制變異下比較兩種模型路由的精確度與成本邊界。

### 實作前置條件

**資料需求**
- 至少一個多跳問答評測集（HotpotQA、MuSiQue 或同類型資料集），建議題數 ≥ 96 以利變異數稽核。
- 對應的語料庫（本文使用 FineWeb 透過 DeepResearchGym 切分為七個分割區）。
- 每筆觀察的文件前綴長度上限 5,000 字元、每查詢最多 10 筆結果的擷取設定。

**運算資源**
- 約 34M model token 的推論額度（涵蓋三種配置 A/B/C 的合計）。
- 支援 non-thinking 模式、256-token 輸出上限的 LLM 端點（本文使用 DeepSeek-V4.1-Flash 與 DeepSeek-V4-Pro-0813）。
- 至少 12,824 個排程呼叫格（cells）的排程與紀錄基礎設施。

**技能前提**
- 熟悉可概化理論（G-theory）與 D-study 的變異數分解概念。
- 能撰寫 RRF（Reciprocal Rank Fusion）與 RR（Round Robin）等檢索融合選擇器。
- 具備配對推論（paired inference）與題目層級自助法（question-level bootstrap）的統計實作能力。
- 能區分並控制「題目變異」、「軌跡變異」、「讀取變異」三層巢狀結構。

### 實作步驟建議

1. **定義配對策略與評測目標**：選定兩個檢索策略（如 Open 與 Adaptive），共用第一個查詢與搜尋結果，最終以五份文件供讀取器作答。將評測目標鎖定為策略間的 F1 差值 ∆F1 及其標準誤，而非單一策略的絕對分數。

2. **執行先導變異數稽核（Variance Audit）**：以 96 題、雙軌跡、五讀取的小規模配置執行，估計 σ²Q、σ²T(QT)、σ²R(QTR) 三個變異分量，並將負值截斷為 0。將稽核參數封存，作為後續預測的固定輸入。

3. **設計三組預算等價配置**：依據稽核結果，在約 34M token 的等成本約束下，設計 A（446/2/1）、B（174/2/5）、C（298/3/1）三組巢狀配置。共用儲存格僅執行一次，並在執行前固定所有配置與題目 ID。

4. **執行主要評測並記錄完整成本**：跑完三組配置後，記錄每組的模型 token 數、搜尋 API 呼叫次數、實際費用。同步執行模型控制組（96/2/2）與深度控制組（48/5/2），以及溫度控制組（96 題 × 溫度 0 與 0.7）。

5. **以兩種模型預測精確度**：先用 Q-only 基線（僅縮放 1/√Q）預測三組配置的標準誤，再用巢狀模型（Eq. 1）預測。比較預測值與實際值，目標是巢狀模型誤差 < 4.0%、Q-only 誤差 < 3.5%。

6. **產出配置決策建議**：根據實測結果，在報告中明確標示「在何種搜尋價格區間（\$0–1／千次）下，更多題目優於更多軌跡」，以及「單讀取配置的變異懲罰區間（0–9.9%）」。對 Pro 配置的不確定性應誠實標示，不可強行收斂結論。

7. **封存與可重現**：將所有題目 ID、軌跡、讀取結果、變異分量、預測參數封存於 artifact；標註模型快照與索引版本限制（本文明確聲明無不可變快照），以便日後審計。

### 潛在風險與注意事項

1. **小軌跡數導致變異分量不穩**：當 T=2 時，σ²T 的估計可能極不穩定，進而放大預測誤差。**緩解方式**：在稽核階段使用較大的 T（如 T=5），或明確報告分量估計的信賴區間。

2. **模型與索引快照漂移**：本文坦言「無不可變的模型或索引快照」，這意味著跨時間重現實驗可能產生偏差。**緩解方式**：在報告中標註實驗日期與模型版本，並盡量在短時間窗口內完成 A/B/C 三組配置。

3. **負變異分量截斷的偏誤**：將負的變異分量截斷為 0 會低估總變異，導致標準誤預測過於樂觀。**緩解方式**：同時報告截斷前後的預測值，並以自助法檢驗截斷對結論的影響。

4. **Pro 配置的結論不確定性**：本文明確指出 Pro 配置的單讀取變異懲罰存在「實質不確定性」，不可直接套用 Flash 的結論。**緩解方式**：在產品決策中對 Pro 模型保留較大的安全邊際，或追加專屬的 Pro 變異稽核。

5. **題目與讀取費用的相對排序未定**：本文指出「題目與讀取的費用排序仍未解決」，單看 token 成本可能誤判真實費用。**緩解方式**：在採購決策前，向 LLM 與搜尋服務商取得最新的快取與批量折扣報價，並以實際費用而非 token 數做最終配置選擇。

6. **溫度控制的副作用**：溫度 0 雖降低答案歧異，卻也改變了模型的「被評估行為」，可能與生產環境的隨機抽樣脫鉤。**緩解方式**：在報告中同時呈現溫度 0 與 0.7 的結果，並說明哪一個對應實際部署溫度。

7. **共用儲存格僅執行一次的假設**：A/B/C 共用儲存格僅執行一次以節省成本，但若共用儲存格本身有錯誤，將同時污染三組配置。**緩解方式**：對共用儲存格加入獨立驗證子集，或在分析中加入儲存格層級的健全性檢查。

### 與其他技術的整合建議

1. **與 LLM 評測平台（如 LangSmith、LangFuse、Weights & Biases）整合**：將本文的巢狀抽樣配置（A/B/C）封裝為評測平台的「預算等價配置模板」，讓團隊在平台上直接選用並自動產生變異數稽核報告。

2. **與 CI/CD 流程整合**：把「96 題雙軌跡稽核」作為 RAG 系統上線前的必跑閘門（gate），當 σ²Q、σ²T、σ²R 任一分量超過閾值時自動阻擋部署，確保每次模型或索引變更都在統計可靠的前提下評估。

3. **與成本監控系統整合**：將搜尋 API 價格、LLM token 單價、快取命中率等參數接入成本監控儀表板，自動計算「在當前價格下，題目數 vs. 軌跡數 vs. 讀取數的最佳配置」，並隨價格變動即時更新建議。

4. **與資訊檢索基準（如 TREC、BEIR）整合**：將本文的配對策略比較框架擴展至傳統 IR 基準，評估檢索器升級（如 BM25 → 密集檢索）時的精確度與成本邊界。

5. **與可概化理論工具鏈整合**：本文的 Eq. 1 變異分解可整合至 genvar、gtheory 等開源套件，或自建內部工具，自動從巢狀實驗資料中估計三層變異分量並產出 D-study 預測。

6. **與 RAG 框架（如 LlamaIndex、Haystack）整合**：將 Open 與 Adaptive 兩種規劃器封裝為可插拔的策略模組，讓開發者在不改動評測程式碼的前提下，替換為自家業務策略並沿用相同的預算配置邏輯。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先跳過第 3 節的巢狀抽樣細節，專注閱讀第 1 節的摘要圖（Fig. 1）與結論——「在固定 token 預算下，擴大題目數比增加讀取次數更能降低標準誤」。理解這個核心取捨後，再回頭看第 4 節的變異分解公式會更容易掌握。

**給 AI 工程師**：重點關注第 3 節的配對策略設計（共用第一查詢、RRF/RR 選擇器）與第 4 節的變異數稽核流程。建議在自己的 RAG 系統中先跑一次 96 題的稽核，再依本文的 A/B/C 配置規劃正式評測；同時務必記錄完整的 token 與 API 費用，因為「題目 vs. 軌跡」的決策高度依賴搜尋價格區間。

**給研究者**：第 4 節的 Eq. 1 與分量截斷處理、第 5 節（若存在）的預測誤差分析是本文最具方法論貢獻的部分。建議仔細檢視「巢狀模型 vs. Q-only 基線」的預測誤差比較（4.0% vs. 3.5%），並思考在更複雜的多策略、多模型設定下，這兩種預測模型的相對表現是否仍成立。此外，本文坦誠標示 Pro 配置的不確定性，是值得效法的負面結果報告方式。

**給產品經理**：本文的實務意涵可濃縮為三條決策法則：(1) 在搜尋 API 價格 \$0–1／千次時，優先擴大題目集而非軌跡數；(2) 若需可重現的評估結果，採用溫度 0 + 單讀取配置，Flash 工作流程下變異懲罰僅 0–9.9%；(3) 模型升級決策（Flash vs. Pro）需獨立變異稽核，不可直接套用 Flash 的結論。建議在產品路線圖中將「評測預算配置」明確列為資源項目，而非附屬於開發工時。
