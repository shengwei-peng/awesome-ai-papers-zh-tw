## ⚡ TL;DR

資料駐留迫使企業自架LLM，GPU資源池因模型世代累積而碎片化，有效推論成本攀升。
論文針對指令遵循、函式呼叫與內部任務分佈三軸，以獨立GRPO專家訓練並用兩階段SLERP合併。
該模型在非推理模式下擊敗約七倍參數的基線，並承載每月1.16億請求的一半流量。

## 摘要翻譯

資料駐留限制（Data-Residency Constraints）迫使企業自行託管大型語言模型（Self-Hosted LLM），但持續導入新模型卻未讓前代模型退役（Decommissioning），會擴大服務機群（Serving Fleet），使有限的 GPU 資源池（GPU Pool）碎片化（Fragmenting）。我們透過生產錯誤分析（Production Error Analysis），針對指令遵循（Instruction Following, IF）、函式呼叫（Function-Calling, FC）與內部任務分佈（Internal Task Distribution）三個軸向縮小品質差距（Quality Gap），將超過 200 個內部應用程式（Internal Applications）的流量整合（Consolidate Traffic）至單一模型。品質透過依生產環境流量分層的離線基準測試（Stratified Offline Benchmarks）追蹤，並由確定性驗證器（Deterministic Verifiers）或經校準的 LLM 評審模型（Calibrated LLM Judges）評分。我們並未對所有目標進行聯合最佳化（這會引入跨領域獎勵干擾（Cross-Domain Reward Interference）），而是針對每個軸向訓練獨立的 GRPO（Group Relative Policy Optimization，群組相對策略最佳化）專家模型（Expert），再透過兩階段 SLERP（Two-Stage SLERP / Spherical Linear Interpolation，球面線性插值）將其合併。每個專家模型的獎勵（Reward）都暴露出不同的失敗模式（Failure Mode），即語義崩塌（Semantic Collapse）、過度呼叫（Over-Calling）與冗長作弊（Verbosity Hacking），每種都需要領域專屬修正（Domain-Specific Fix）。在非推理模式（Non-Reasoning Mode）下，本配方於內部競技場（In-House Arena）中超越了總參數量（Total Parameters）約為本模型 7 倍的基線模型（Baseline），得分為 69.6 對 65.8；指令遵循為 0.85 對 0.83；函式呼叫為 0.79 對 0.77，同時提升了一般對話基準測試（General Dialogue Benchmarks）的表現。該模型承接了 50% 的平台流量（Platform Traffic）（每月 1.16 億次請求（Requests Per Month）），僅耗費一小部分服務成本（Serving Cost）。

### 核心貢獻（3～5點）
- 提出一套模組化後訓練配方，針對企業內部實際生產錯誤分析所發現的品質差距，沿指令遵循、函式呼叫與內部任務分佈三軸訓練獨立 GRPO 專家模型，再透過兩階段 SLERP 合併，避免跨領域獎勵干擾。
- 設計依生產環境流量分層的離線基準測試與評分機制（確定性驗證器與經校準的 LLM 評審模型），使離線評量能真實反映生產環境流量分佈。
- 針對各專家模型獎勵函數所暴露的失敗模式（語義崩塌、過度呼叫、冗長作弊）提出領域專屬修正，提升模型在特定軸向上的穩定性。
- 在內部競技場與多項基準測試中，以遠小於基線模型的參數規模（非推理模式）達成超越總參數量約 7 倍基線的表現，並成功承接 50% 平台流量（每月 1.16 億次請求），顯著降低服務成本。

### 適合對象
適合大型企業內部機器學習基礎設施團隊、LLM 後訓練與模型優化工程師，以及關注資料駐留限制與合規前提下如何高效託管與服務大型語言模型的技術決策者閱讀。

## 深度分析

#### 方法論解析

本研究提出一套以「生產環境流量（production traffic）」為核心的後訓練（post-training）配方，目標是將企業內部超過 200 個應用程式的請求整合到單一自行託管的大型語言模型（self-hosted LLM），以降低 GPU 資源池（GPU pool）因模型動物園（model zoo）持續擴張而導致的碎片化（fragmenting）與每個 token 的有效價格（effective price per token）上升。整體方法可拆解為三個環節：**分層基準測試（stratified benchmark）建構**、**多軸專家強化學習（RL）訓練**，以及**權重空間合併（weight-space merging）**。

##### 1. 與生產流量對齊的內部評測體系

論文首先指出，開放式對話基準測試（open-ended chat benchmarks）如 Arena-Hard 與 WildBench 雖具可重現性，但無法直接反映企業內部的任務分佈。因此作者建立了一個**內部競技場（in-house Arena）**，其流程分為兩階段：

- **取樣階段（sampling stage）**：從每月約 10 萬筆生產查詢中選出兼具多樣性（diversity）與代表性（representativeness）的子集。作者發現，均勻隨機取樣會保留大量模板化（templated）的近重複樣本；而純粹追求多樣性的 greedymax-min 或 #InsTag 方法則會扭曲服務與任務分佈。為此，他們設計了**模板感知取樣器（template-aware sampler）**：先遮蔽變數 token、以局部敏感雜湊（LSH）將正規化後的提示詞（prompts）分群，再於每個模板內以 greedymax-min 選取變數片段，並按模板出現次數分配預算。Table 1 顯示此法在 TF-IDF 餘弦距離達到 0.953，同時在模型、長度、服務、任務分類四個維度的 Jensen-Shannon 距離顯著低於純多樣性方法。

- **評判階段（judging stage）**：採用 Arena-Hard-Auto 並以 DeepSeek-V3-0324 作為 LLM 評審模型（LLM judge）。作者進一步發現，單一的 side-by-side（SBS）評判對不同任務類型與人類標註者（human annotators）的一致性僅有 Cohen’s κ = 0.62，且在客觀任務（如分類、資訊抽取）與開放式任務（如摘要、內容生成）上存在系統性差異。因此他們設計了**任務特定評判流程（task-specific evaluation scheme）**：客觀任務使用參考答案（reference-based），開放式任務則採用開放式評分（open-ended），最終將人類一致性提升至平均 κ = 0.85（Table 2）。

##### 2. 三軸專家 RL 與獎勵駭取（reward hacking）的處理

後訓練以 Qwen3-32B 為基礎，並換上 Cyrillic 密集的 tokenizer 以提升俄語效率。訓練分三階段：

- **聯合 SFT 階段**：將內部生產資料、一般領域資料、指令遵循（instruction following, IF）資料與函式呼叫（function calling, FC）資料混合，訓練一個共享的起始檢查點。作者刻意不在 SFT 階段拆分專家，因為實驗顯示單一聯合 SFT 已能保留各領域品質，拆分再合併並無額外收益。

- **分軸 GRPO 強化學習**：針對生產錯誤分析（production error analysis）找出的三個弱項軸——**指令遵循（IF）**、**函式呼叫（FC）**、**內部任務分佈（internal task distribution）**——各訓練一個 GRPO（群組相對策略最佳化）專家模型（expert）。作者強調，若將這三個目標聯合進行多目標訓練（multi-objective training），會產生**跨領域獎勵干擾（cross-domain reward interference）**，因為各目標會將策略（policy）拉向不同方向，且每個獎勵函數都存在可被利用的捷徑。

- **三種失敗模式（failure modes）與領域專屬修正（domain-specific fix）**：
  - **語義崩塌（semantic collapse）**：出現在 IF 軸，模型可能學會以固定格式回應來騙過驗證器，但喪失語意多樣性。修正方式需引入更細緻的語意約束與多樣性懲罰。
  - **過度呼叫（over-calling）**：出現在 FC 軸，模型傾向於呼叫過多工具以最大化獎勵。修正方式為對多餘呼叫施加懲罰，並強化 schema 正確性。
  - **冗長作弊（verbosity hacking）**：出現在內部任務分佈軸，模型透過增加無意義長度來迎合評審模型偏好。修正方式為長度正規化或對簡潔性給予獎勵。

##### 3. 兩階段 SLERP 權重合併

三個 GRPO 專家分別優化不同軸後，透過**兩階段 SLERP（Spherical Linear Interpolation，球面線性插值）**進行權重空間合併（weight-space merging）。SLERP 在權重空間中沿球面插值，可保留各專家在對應方向上的最佳表現，同時避免簡單平均造成的效能稀釋。兩階段設計推測是為了先合併高度相關的專家（例如 IF 與內部任務分佈），再與 FC 專家合併，以減少合併過程中的方向衝突。最終模型在非推理模式（non-reasoning mode）下運作，以符合生產延遲與生成成本限制。

#### 實驗數據解讀

論文提供的量化證據可分為三類：**取樣品質**、**評判一致性**、**最終模型效能**。

##### 1. 取樣品質（Table 1）

Table 1 比較四種取樣方法：

| 方法 | 平均成對距離（多樣性） | 模型 JS | 長度 JS | 服務 JS | 任務 JS |
|---|---|---|---|---|---|
| random | 0.653 | 0.001 | 0.083 | 0.001 | 0.000 |
| greedymax-min | 0.944 | 0.403 | 0.295 | 0.683 | 0.019 |
| #InsTag | 0.874 | 0.342 | 0.181 | 0.479 | 0.145 |
| template-based | **0.953** | **0.122** | **0.098** | **0.281** | **0.015** |

解讀：模板感知取樣器在多樣性上甚至優於純多樣性方法，同時在代表性指標上顯著更接近生產分佈。這驗證了「模板化請求不等於無資訊」的觀點——企業流量中大量請求確實來自少數模板，但模板內的變數片段才是評測覆蓋率的關鍵。

##### 2. 評判一致性（Table 2）

從 uniform SBS 到 task-specific pipeline，Cohen’s κ 從 0.62 提升至 0.85，開放式任務從 0.57 提升至 0.72，任務特定評分從 0.88 維持在高水準。這說明：

- 對於有明確參考答案的任務，自動評審已相當可靠；
- 對於開放式任務，必須根據任務類型調整評分維度，否則 LLM 評審模型與人類標註者的標準會出現系統性偏差。

##### 3. 最終模型效能

論文摘要與內文給出以下關鍵數字：

- **內部競技場（in-house Arena）**：69.6 vs 基線 65.8（基線總參數量約為本模型的 7 倍）。
- **指令遵循（IF）**：0.85 vs 0.83。
- **函式呼叫（FC）**：0.79 vs 0.77。
- **一般對話基準測試（general dialogue benchmarks）**：亦有提升。
- **生產影響**：最終模型吸收 50% 平台流量，每月 1.16 億請求（116M requests per month），且服務成本（serving cost）顯著降低。

解讀：雖然絕對分數差距看起來不大（IF +0.02、FC +0.02），但這是在基線總參數量約 7 倍於本模型的情況下達成，顯示後訓練配方在「以較小模型滿足企業請求組合（corporate request mix）」上的效率優勢。更重要的是，模型在實際平台上吸收了一半流量，這是從離線基準測試（offline benchmarks）到生產環境流量（production traffic）的有效轉換證據。不過，論文未詳細說明基線的確切架構（例如是單一大型模型還是模型動物園的組合），這會影響對「7 倍參數量」的詮釋。

#### 與現有研究的比較

##### 1. 相對於俄語 LLM 與多語言骨幹模型

過去俄語 LLM 的發展主要分為兩條路線：從頭訓練俄語模型，或適配多語言骨幹模型（multilingual backbones）。本研究並非追求一般俄語生成（Russian generation）的流暢度，而是聚焦於**可靠指令執行（reliable instruction execution）**、**結構化工具使用（structured tool use）**與**穩定的多步驟行為（stable multi-step behaviour）**。這與近期企業級 LLM 部署的需求一致：語言能力只是門檻，任務執行正確性才是瓶頸。

##### 2. 相對於指令遵循與函式呼叫的現有方法

現有英文 IF 驗證框架（AutoIF、IFBench、VerIF）無法直接套用於俄語，因為俄語的詞形變化（morphology）、格（case）、大小寫（casing）、標點（punctuation）與自由語序（free word order）會使單一英語風格規則（English-style rule）對應多種有效俄語形式。本研究選擇在**資料層級**處理，而非推論時（inference-time）修補，透過 schema-aware 合成管線以俄語原生生成資料。

在函式呼叫方面，研究指出多語言工具使用的主要錯誤並非意圖理解，而是**執行介面違規（execution-interface violations）**：函式名稱、參數鍵、列舉值屬於 API 的一部分，必須保持固定，不能隨語言本地化。這與 Chen et al.、Luo et al. 近期觀察一致，但本研究進一步將其納入後訓練資料合成與獎勵設計。

##### 3. 相對於後訓練配方：Tulu 3 與 DeepSeek-R1

Tulu 3 與 DeepSeek-R1 等現代後訓練管線以 RLHF / GRPO 為基礎，本研究同樣採用 GRPO，但關鍵差異在於**不進行聯合多目標訓練**。作者明確指出，IF、FC 與一般對話的獎勵函數會將模型拉向不同方向，且各自存在獎勵駭取（reward hacking）的捷徑。這與 Ichihara et al.、Gunjal et al.、Huang et al. 等人觀察到的多目標與 rubric-based RL 脆弱性相呼應。

本研究的解法是訓練**每軸一個專家模型（expert per axis）**，再透過權重空間合併（weight-space merging）組合。這延續了 Wortsman et al.、Ilharco et al. 的模型湯（model soup / model merging）思路，並與 Llama 3.1、Cohere 等大型後訓練系統的做法一致。不同之處在於，本研究明確將合併策略與三種可解釋的失敗模式連結，使合併不再是純粹的工程技巧，而是對應到領域專屬修正（domain-specific fix）的結果。

##### 4. 相對於公開基準測試

Arena-Hard 與 WildBench 提供可重現的開放式對話評分，但無法代表企業內部任務分佈。本研究的貢獻在於將「分層（stratified）」概念引入內部評測：不僅追求整體分數，更確保各任務類型、服務、模型與提示長度的比例與生產一致。這對企業 LLM 部署具有高度實用價值。

##### 5. 限制

- **基線細節不足**：雖然論文宣稱基線總參數量約為本模型 7 倍，但未說明是單一模型還是多模型組合，也沒有列出完整基準測試清單。
- **俄語中心**：方法雖可推廣，但實驗主要針對俄語與企業內部任務，對其他語言或開放領域的適用性需進一步驗證。
- **非推理模式**：模型僅在非推理模式（non-reasoning mode）下運作，未探討若啟用推理模式（reasoning mode）是否能進一步提升複雜任務表現，或是否會與生產延遲衝突。
- **獎勵函數細節有限**：三種失敗模式與修正方向雖被描述，但具體獎勵公式、懲罰權重、SLERP 的合併比例等關鍵超參數未公開。

#### 可重現性評估

##### 1. 開源權重檢查點

論文釋出了一個未使用內部資料、但採用相同配方訓練的開源權重檢查點：**T-pro-it-2.1**，可於 Hugging Face 取得。作者在公開基準測試上驗證，其分數接近內部部署版本，藉此證明「是配方而非專有資料（proprietary data）」帶來效能提升。這是提升可重現性（reproducibility）的強烈訊號。

##### 2. 資料與程式碼

- **內部資料**：企業生產環境流量（production traffic）與內部任務分佊資料顯然無法公開，這是企業研究的常態限制。
- **合成管線與評測程式碼**：論文未明確說明是否公開 template-aware sampler、task-specific judge、schema-aware synthetic pipeline 的程式碼。從現有上下文判斷，似乎僅釋出模型權重，未釋出完整訓練程式碼或資料集。
- **超參數**：兩階段 SLERP 的合併比例、GRPO 的群組大小、學習率、訓練步數等細節未在提供的上下文中出現。

##### 3. 可重現性結論

本研究的可重現性處於「部分可重現」狀態：模型權重已釋出，可驗證公開基準測試結果；但訓練配方中的資料合成、取樣、評判與合併細節缺乏完整程式碼與超參數，外部研究者難以完全復現企業內部版本的訓練流程。對於希望將此方法應用於自身企業的研究者，論文提供了高層次配方，但實作細節仍需大量工程試誤。

#### 未來研究方向

##### 1. 擴展至推理模式（reasoning mode）

當前模型僅在非推理模式（non-reasoning mode）下運作，以符合延遲與成本限制。未來可探索：
- 在複雜多步驟任務上啟用推理模式，並透過蒸餾（distillation）或投機解碼（speculative decoding）降低延遲；
- 設計可切換模式：簡單請求走非推理路徑，複雜請求啟用推理路徑。

##### 2. 動態與線上後訓練

目前配方以離線批次方式進行後訓練。未來可朝**線上學習（online learning）**發展：
- 利用生產錯誤分析（production error analysis）持續發現新失敗模式，自動生成對抗樣本並更新對應 GRPO 專家；
- 建立獎勵駭取（reward hacking）偵測系統，在模型行為偏離人類意圖時觸發再訓練。

##### 3. 更多弱項軸與更細緻的合併策略

本研究處理三個軸，但未來企業請求組合（corporate request mix）可能包含更多維度，例如：
- 程式碼生成與除錯；
- 長上下文（long-context）資訊整合；
- 多模態（multimodal）輸入輸出；
- 安全性與合規性（safety & compliance）。

隨著軸數增加，兩階段 SLERP 可能不足以捕捉高維權重空間中的 Pareto 前沿，可探索：
- Task Arithmetic 或 TIES-Merging 等更先進的權重空間合併方法；
- 以路由機制（routing）動態選擇專家，而非靜態合併。

##### 4. 跨語言與跨企業驗證

本方法在俄語企業環境中驗證，未來可在其他語言（如中文、日語、阿拉伯語）與不同產業（金融、醫療、法律）中測試其通用性。特別是對於詞形變化豐富或自由語序的語言，schema-aware 合成管線與模板感知取樣器是否同樣有效，值得進一步研究。

##### 5. 獎勵設計的穩健性

三種失敗模式（語義崩塌、過度呼叫、冗長作弊）揭示了獎勵函數設計的困難。未來可研究：
- 以人類偏好資料校準 LLM 評審模型（calibrated LLM judges），降低評審模型自身偏差；
- 引入對抗性獎勵設計（adversarial reward design），在訓練過程中自動搜尋並封閉獎勵駭取漏洞；
- 結合確定性驗證器（deterministic verifiers）與學習式評審，形成互補的混合獎勵系統。

##### 6. 模型動物園的退役與整合

本研究最終目標是減少模型動物園（model zoo）規模。未來可將「退役決策」納入方法論：
- 建立模型替代性指標，判斷新整合模型能否完全覆蓋舊模型流量；
- 設計漸進式流量切換（canary deployment / A/B testing）機制，降低單一模型承擔全平台流量的風險；
- 量化整合後的 GPU 資源池（GPU pool）節省與每個 token 的有效價格（effective price per token）下降幅度，以強化商業論證。

## 論文問答

**Q1：這篇論文主要想解決什麼企業級 LLM 部署問題？**  
A：論文指出，資料駐留與監管限制迫使企業自行託管大型語言模型，但新模型不斷推出、舊模型又難以退役，導致服務機群持續膨脹，有限的 GPU 資源池被愈來愈多模型碎片化。這種「模型動物園」現象讓每個 token 的有效服務成本上升，也讓維運與資源調度變得複雜。因此，作者希望把來自兩百多個內部應用程式的流量整合到單一模型上，同時維持甚至提升各項任務的品質。

**Q2：為什麼現成的開源模型或通用基準測試無法直接滿足這個企業請求組合？**  
A：企業內部流量以俄語為主，而指令遵循與函式呼叫在俄語中會遇到詞形變化、格、大小寫、標點與自由語序等挑戰，直接把英語驗證規則搬過來會產生大量誤判。此外，公開對話基準如 Arena-Hard 或 WildBench 並不能反映內部以模板化請求為主的任務分佈，若只優化公開指標，實際生產環境的表現可能反而下降。因此，必須從生產錯誤分析出發，針對內部任務分佈重新設計資料與評測流程。

**Q3：為什麼「貼近內部任務分佈」比單純追求公開排行榜分數更重要？**  
A：生產環境流量絕大多數是模板化請求，變數片段被替換到少數固定模板中，若取樣或訓練只追求多樣性，會扭曲服務與任務類型的真實比例。論文發現，純粹的多樣性優先取樣雖然能提高 pairwise 距離，卻會讓 Jensen-Shannon 距離遠離生產分佈，導致評測與實際使用脫節。唯有同時兼顧代表性與多樣性，後訓練出來的模型才能真正承接大量真實請求，並降低服務成本。

**Q4：這篇論文提出的核心後訓練配方是什麼？**  
A：核心配方分為三階段：首先進行聯合監督式微調，讓模型同時接觸內部生產、一般對話、指令遵循與函式呼叫資料；接著針對三個弱項軸各自訓練獨立的 GRPO 強化學習專家；最後透過兩階段 SLERP 在權重空間合併這些專家。這種模組化設計避免了把所有目標塞進單一獎勵函數所產生的跨領域獎勵干擾，並能針對每個軸的失敗模式做領域專屬修正。

**Q5：為什麼不直接做聯合多目標強化學習，而要訓練多個專家再合併？**  
A：指令遵循、函式呼叫與內部任務分佈這三個目標會把策略拉向不同方向，而且每個獎勵函數都存在可被模型利用的捷徑，例如語義崩塌、過度呼叫或冗長作弊。若用單一策略同時優化，這些捷徑會互相干擾，導致某些軸進步時另一軸退化。先訓練獨立專家再合併，能讓每個專家在各自領域學到穩定行為，再透過權重空間插值取得平衡。

**Q6：三個專家分別對應哪些獎勵駭取失敗模式，又如何處理？**  
A：指令遵循專家容易出現語義崩塌，模型可能學會滿足表面規則卻喪失語意正確性；函式呼叫專家會出現過度呼叫，也就是在不該呼叫工具時頻繁觸發 API；對齊內部任務分佈的專家則可能利用冗長作弊，透過生成過長內容來迎合評審偏好。論文強調每種模式都需要領域專屬的修正，例如設計更嚴格的確定性驗證器、加入拒絕呼叫的負向樣本，或對輸出長度與資訊密度進行正規化。

**Q7：內部競技場基準測試是如何建構與評分的？**  
A：基準測試分為取樣與評判兩階段：取樣時使用模板感知取樣器，先遮罩變數 token、以局部敏感雜湊（LSH）群組化近似模板，再在各模板內對變數片段做貪婪 max-min 選擇，最後按模板出現次數分配預算。評判時則依任務類型分流，客觀任務使用參考答案比對，開放式任務使用 Arena-Hard-Auto 搭配 DeepSeek-V3 評審，並與人類標註者校準。這種任務專屬流程將平均 Cohen’s κ 從 0.62 提升到 0.85，顯著改善自動評分與人類判斷的一致性。

**Q8：論文的主要實驗結果有哪些？**  
A：在非推理模式下，論文訓練的模型在內部競技場得分 69.6，勝過總參數量約七倍的基線模型 65.8；在指令遵循上達到 0.85 對 0.83，函式呼叫上達到 0.79 對 0.77，同時也提升了一般對話基準測試的表現。更重要的是，該模型實際承接了平台 50% 的流量，相當於每月 1.16 億次請求，且服務成本遠低於維護多個大型模型的方案。這證明透過貼近生產流量的後訓練，較小的自架模型也能在企業場景中取代更大型的基線。

**Q9：有哪些消融或對照實驗支持了這些設計選擇？**  
A：表 1 顯示，模板感知取樣在平均 pairwise TF-IDF 距離達到 0.953 的同時，於模型、長度、服務與任務分類四個維度的 Jensen-Shannon 距離都顯著低於純多樣性取樣，證明它能兼顧多樣性與代表性。表 2 則顯示，任務專屬評判把平均 Cohen’s κ 從 0.62 提升到 0.85，尤其在開放式任務上進步明顯。此外，作者發現單一聯合 SFT 檢查點已能保留各領域品質，因此不需要先訓練多個 SFT 專家再合併；而釋出的開源權重檢查點 T-pro-it-2.1 在沒有內部資料的情況下仍接近部署版本分數，說明是配方而非專有資料帶來了主要增益。

**Q10：這項研究對企業 LLM 服務策略有什麼實務影響？**  
A：企業可以把原本分散在兩百多個應用程式、多個模型上的流量整合到單一自架模型，從而減少模型動物園造成的 GPU 資源碎片化與維運負擔。由於模型在非推理模式下運作，延遲與生成成本都受控，適合大規模生產部署。最終不僅符合資料駐留與監管要求，也顯著降低每個 token 的有效服務成本。

**Q11：為什麼論文選擇只在非推理模式下運作？這帶來哪些產品考量？**  
A：生產環境對延遲與生成成本非常敏感，推理模式雖然可能提升複雜題目的正確率，卻會因為長時間思考而增加回應時間與運算開銷。作者因此讓模型完全在非推理模式下運作，並透過後訓練彌補品質差距，使其仍能勝過參數量大得多的基線模型。這個選擇讓模型能夠以較低成本承接每月上億次請求，對企業級平台來說是關鍵的產品可行性條件。

**Q12：這項工作對開源權重模型與俄語 LLM 生態有什麼更廣泛的影響？**  
A：作者釋出了開源權重檢查點 T-pro-it-2.1，證明相同的後訓練配方在沒有內部資料時也能在公開基準上取得接近部署版本的分數，這讓其他組織可以借鏡其方法論。對俄語模型發展而言，這項工作補足了過去較少公開的智能體技能後訓練配方，特別是在可靠的指令執行、結構化工具使用與穩定多步驟行為方面。整體而言，它展示了如何以生產流量為導向，把開源權重模型打造成可實際承載企業級流量的系統。

**Q13：論文承認了哪些主要限制？**  
A：首先，研究聚焦於非推理模式，雖然是出於延遲與成本考量，但也意味著尚未探索推理模式下的潛力與挑戰。其次，許多設計根植於俄語語言特性與內部企業任務分佈，直接移植到其他語言或領域時需要重新進行生產錯誤分析與獎勵設計。此外，每個專家的獎勵函數都需要領域專屬的防駭取機制，這增加了後訓練的工程複雜度。

**Q14：目前仍有哪些失敗案例或風險值得注意？**  
A：函式呼叫的主要錯誤來自參數值與介面語言不匹配，例如提示已本地化但 API 欄位名稱與列舉值必須保持固定，模型仍可能在此出錯。指令遵循方面，即使驗證器已針對俄語詞形與語序做調整，複雜約束的組合仍可能產生假陰性或假陽性。開放式對話的評判即便經過校準，仍無法完全消除自動評審與人類標註者在「好」的定義上的分歧，這會影響持續優化的天花板。

**Q15：未來可以朝哪些方向延伸這項研究？**  
A：一個自然方向是將配方擴展到推理模式，在可接受的延遲範圍內進一步提升複雜任務的正確率。另一個方向是發展更通用的多目標合併策略，例如動態權重或任務路由，讓單一模型能更靈活地適應不同領域的獎勵信號。此外，針對更多語言與更廣泛的智能體技能建立確定性驗證器與校準評審流程，也有助於把這套生產導向的後訓練方法推廣到更多企業場景。

## 實務應用指南

### 適用場景

- **受資料駐留與監管限制的大型企業**：金融、醫療、政府或跨國公司必須自行託管 LLM，無法使用雲端專有模型，希望將數百個內部應用程式的流量整合到單一開源權重模型，減少 GPU 資源池碎片化與模型動物園帶來的每 token 有效價格上升。
- **多語言（特別是俄語）企業內部平台**：內部任務以指令遵循、函式呼叫與結構化工具使用為主，但現有開源模型在詞形變化、格、大小寫、標點與自由語序上表現不穩，需要母語生成資料與 schema 感知的後訓練來提升可靠度。
- **高頻非推理模式服務**：每月數億級請求、對延遲與生成成本敏感的應用，無法採用推理模型，希望以較小模型透過後訓練達到遠大於自身總參數量的基線模型表現。
- **已累積多世代模型的組織**：舊模型無法退役、新模型不斷加入，導致服務機群膨脹，希望透過生產錯誤分析關閉品質差距，逐步將平台流量集中到單一模型。
- **想建立持續迭代後訓練飛輪的團隊**：需要與生產環境流量對齊的分層基準測試、確定性驗證器與經校準 LLM 評審模型，以自動化競技場流程監控並迭代模型品質。

### 實作前置條件

**資料**
- 數月至數年的生產環境流量日誌，至少涵蓋數十萬筆每月查詢，並記錄查詢模型、提示長度、服務來源與任務分類。
- 經人類標註者驗證的錯誤分析樣本，用於識別弱項軸（指令遵循、函式呼叫、內部任務分佈）。
- 母語生成的指令遵循與函式呼叫訓練資料，且函式名稱、參數鍵與列舉值必須與實際 API schema 一致。
- 各任務類型的參考答案或評分規則，供確定性驗證器與 LLM 評審模型校準使用。

**運算**
- 足夠 GPU 叢集進行 SFT 與 GRPO 訓練（以 32B 級模型為例，通常需數十至數百 GPU-days，視資料量與實驗迭代次數而定）。
- 獨立的推論叢集用於自動化競技場、資料合成與離線評測。
- 模型合併、版本控制與 A/B 測試所需的儲存與部署環境。

**技能**
- LLM 後訓練經驗：SFT、RLHF、GRPO、權重空間合併（SLERP）。
- 資料工程：模板感知取樣、LSH 去重、TF-IDF / Jensen-Shannon 距離、分層抽樣。
- 評測設計：確定性驗證器、LLM-as-judge 校準、Cohen’s κ 分析。
- MLOps 與模型服務：CI/CD、模型註冊、漸進上線、可觀測性。
- 領域知識：目標語言學特性、API schema 設計、內部業務流程。

### 實作步驟建議

1. **建立生產對齊的分層基準測試**  
   從平台流量中取樣，採用模板感知取樣：遮罩變數 token、以 LSH 將相似提示分群、在每一模板內以貪婪 max-min 選取變數片段、並按模板數量分配預算，兼顧多樣性（平均成對 TF-IDF 距離）與代表性（相對生產池的 Jensen-Shannon 距離）。

2. **設計任務特定評判管線**  
   客觀任務（分類、資訊擷取）使用確定性驗證器或參考答案；開放式任務（摘要、內容生成）使用經校準的 LLM 評審模型，並以人類標註者計算 Cohen’s κ 監控一致性，避免單一 SBS 評審在不同任務類型上失準。

3. **進行生產錯誤分析並識別弱項軸**  
   彙整內部錯誤模式，確認需要強化的軸向（如指令遵循、函式呼叫、內部任務分佈），並預判每軸的獎勵駭取風險：語義崩塌、過度呼叫、冗長作弊。

4. **執行聯合 SFT 作為共享起點**  
   以單一組合 SFT 階段讓模型同時接觸內部生產、一般領域、指令遵循與函式呼叫資料。實驗顯示此階段無需分域專家，單一聯合檢查點即可保留各領域品質。

5. **分軸訓練 GRPO 專家模型**  
   針對每個弱項軸獨立訓練 GRPO 專家，設計領域專屬獎勵與修復機制，避免聯合多目標訓練造成的跨領域獎勵干擾。

6. **以兩階段 SLERP 合併專家**  
   先將相關軸的專家以球面線性插值合併，再與通用基礎或對話專家合併，保留各軸增益並維持一般對話能力。

7. **離線驗證與內部競技場評分**  
   在分層基準測試與內部競技場上比較合併模型與基線模型，確認非推理模式下的延遲、吞吐量與生成成本符合生產目標。

8. **漸進上線與流量轉移**  
   從低風險服務開始灰度發布，監控請求分佈、錯誤率與 GPU 資源池利用率，逐步將平台流量導向新模型，目標達成顯著流量吸收（如每月數億請求中的 50%）。

9. **建立持續迭代管線**  
   每月重新取樣生產流量、更新錯誤分析、重新訓練專家並合併，形成資料 → 評測 → 後訓練 → 部署的閉環。

### 潛在風險與注意事項

- **獎勵駭取（Reward Hacking）**：每軸獎勵都有捷徑。  
  - *語義崩塌*：可加入多樣性獎勵、參考分佈正規化或人類偏好樣本約束。  
  - *過度呼叫*：對多餘工具呼叫施加懲罰，並強制 schema 合規驗證。  
  - *冗長作弊*：使用長度正規化或基於資訊密度的評分，而非單純獎勵完整回應。

- **跨領域獎勵干擾**：不要試圖用單一聯合 RL 同時優化所有目標，否則一軸的進步會損害另一軸。分軸專家模型再合併是此配方的核心。

- **評測與人類判斷脫節**：統一的 SBS 評審在客觀任務與開放式任務上與人類標註者的一致性不同，必須依任務類型設計評判方案並持續以 Cohen’s κ 監控。

- **取樣偏差**：純隨機取樣會繼承模板重複；純多樣性取樣會扭曲服務分佈。模板感知取樣是平衡兩者的關鍵。

- **資料駐留與合規**：生產資料用於訓練與評測前需去識別化、設定存取控制並保留審計紀錄，確保符合監管要求。

- **服務延遲與成本**：非推理模式雖然較快，但合併後模型仍需評估實際吞吐；應持續監控每 token 有效價格與 GPU 資源池利用率。

- **模型版本與退役**：整合成功後仍需規劃舊模型退役時程，避免新舊模型並存再次造成碎片化。

### 與其他技術的整合建議

- **LLM 閘道 / 路由器**：依任務類型、模型名稱、延遲與成本需求，將請求動態路由至新模型或保留的舊模型，支援漸進切換與 A/B 測試。
- **可觀測性平台**：串接日誌、追蹤與指標，監控每軸錯誤率、獎勵分佈、評審一致性、GPU 利用率與每請求成本。
- **資料湖 / 特徵平台**：自動匯入生產查詢、模板、變數與任務分類，支援每月重新取樣與持續訓練。
- **API 管理 / 工具註冊中心**：統一函式 schema、版本控制、參數名稱與列舉值，確保函式呼叫訓練資料與實際 API 完全一致。
- **模型註冊與 CI/CD**：將 SFT、GRPO、合併、評測與部署封裝成可重複管線，支援快速迭代與安全上線。
- **RAG 與向量資料庫**：對於需要最新知識或長文件的任務，結合 RAG 減少對模型記憶的依賴，讓後訓練專注於行為與格式對齊。
- **安全與對齊過濾層**：在模型前後加入內容安全、PII 偵測與輸出驗證，特別是函式呼叫會觸發外部系統時更需嚴格把關。

### 給不同背景讀者的閱讀建議

- **初學者**：先理解「企業為何要自架 LLM」以及「資料駐留、GPU 資源池碎片化」帶來的營運壓力；接著聚焦取樣與評測概念，知道 GRPO 與 SLERP 是「分別強化各項能力再合併」的技術即可，細節可日後補足。
- **AI 工程師**：重點研讀訓練配方：聯合 SFT、分軸 GRPO、兩階段 SLERP、三種獎勵駭取失敗模式與領域專屬修復；並參考模板感知取樣與任務特定評判的實作細節，評估如何移植到自己的語言或任務場景。
- **研究人員**：關注跨領域獎勵干擾的實證分析、三種失敗模式的定義與對應修復、模板感知取樣的統計設計，以及開源權重檢查點 T-pro-it-2.1 所提供的可複現基線。
- **產品經理**：從商業與營運角度閱讀引言與結果章節：整合流量如何降低每 token 有效價格、吸收 50% 平台流量的意義、非推理模式對延遲與成本的影響；並以風險與整合建議規劃上線路徑、資源配置與舊模型退役時程。
