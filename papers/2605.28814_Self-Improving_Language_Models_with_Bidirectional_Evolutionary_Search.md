## 摘要翻譯

搜尋已被提出作為自我改進語言模型（Self-Improving Language Models）與智能體系統（agentic systems）的有效方法，無論是用於後訓練（post-training）的樣本生成（sample generation），還是用於推論（inference）。然而，廣泛使用的方法如 best-of-N 取樣（best-of-N sampling）與樹搜尋（tree search）面臨兩項根本限制：它們受稀疏驗證訊號（sparse verification signals）引導，且主要透過自迴歸擴展（autoregressive expansion）來建構候選方案（candidates），將探索限制在模型機率質量（model probability mass）較高的區域。為了解決這些問題，我們提出雙向演化式搜尋（Bidirectional Evolutionary Search, BES），一種將前向候選演化（forward candidate evolution）與反向目標分解（backward goal decomposition）結合的搜尋框架。在前向搜尋（forward search）中，BES 以演化運算子（evolution operators）增強標準擴展，這些運算子重組部分軌跡（partial trajectories），以生成難以從單次模型展開（model rollout）中獲得的候選方案。在反向搜尋（backward search）中，BES 遞迴地將原始任務分解為可檢查的子目標（subgoals），產生密集中間回饋（dense intermediate feedback）以引導前向搜尋。我們提供理論動機（theoretical motivation），證明僅由擴展生成的候選方案侷限於狹窄的熵殼（entropy shell），而演化運算子可以脫離該熵殼；此外，反向搜尋能夠指數級地減少找到正確答案所需的樣本數量。實驗顯示，在主流後訓練演算法無法提升的具挑戰性後訓練任務上，BES 能帶來穩定的增益；而在三個於推論階段（at inference time）使用的開放性問題解決基準（open problem solving benchmarks）上，BES 在平均效能（average performance）與最佳效能（best-case performance）上均優於現有的開源框架。程式碼與訓練完成的模型可於 https://github.com/Embodied-Minds-Lab/BES 取得。

### 核心貢獻（3～5點）
- 提出雙向演化式搜尋（BES）框架，透過耦合前向候選演化與反向目標分解，突破現有方法僅受稀疏驗證訊號引導且受限於自迴歸擴展的瓶頸。
- 設計前向搜尋中的演化運算子，藉由重組部分軌跡生成高品質候選方案，使搜尋能脫離熵殼並探索模型機率質量較低的區域。
- 建立反向搜尋的遞迴子目標分解機制，產生密集中間回饋以指數級提升樣本效率，並有效引導前向搜尋。
- 在具挑戰性的後訓練任務與三個開放性問題解決基準上，驗證 BES 相較於現有開源框架在平均效能與最佳效能上的穩定優勢。

### 適合對象
從事大型語言模型後訓練、測試時擴展、自我改進機制與開放性推理問題搜尋演算法研究的學者與工程師，特別是關注如何結合演化運算子與雙向搜尋策略以突破稀疏驗證訊號與機率質量侷限的研究者。

## 深度分析

#### 方法論解析

本研究將推理問題形式化為 \(T=(x,V)\)，其中 \(x\) 為問題描述，\(V(x,y) \in [0,1]\) 則是衡量軌跡（trajectory）\(y\) 解決問題程度的驗證器（verifier）。傳統方法如 best-of-N 取樣（best-of-N sampling）與樹搜尋（tree search）雖然廣泛應用於後訓練（post-training）與推論（inference），卻受制於兩項根本限制：其一，驗證訊號（verification signal）過於稀疏，常僅有二元回饋（binary feedback）或粗粒度回饋（coarse-grained feedback）；其二，候選方案（candidate）的建構完全依賴自迴歸擴展（autoregressive expansion），導致所有生成結果被侷限在模型自身分佈（model's own distribution）的支撐集（support）內，難以觸及低機率區域（low-probability regions）中正確解答所在的稀疏地帶。

為突破上述限制，作者提出雙向演化式搜尋（Bidirectional Evolutionary Search, BES），核心架構為耦合前向搜尋（forward search）與反向搜尋（backward search）。在前向候選演化（forward candidate evolution）階段，BES 並非僅對單一軌跡進行自迴歸延伸，而是引入四種演化運算子（evolution operators）：組合（combination）、易位（translocation）、刪除（deletion）與交叉（crossover）。這些運算子針對部分軌跡（partial trajectories）進行重組，將不同譜系中的有益片段拼接為新的候選方案。此設計的生物學隱喻十分鮮明：有性生殖透過染色體重組（chromosomal recombination）打破無性繁殖的基因瓶頸，而 BES 則藉由重組不同模型展開（model rollout）產生的軌跡片段，逃離單一 rollout 難以抵達的區域。

在反向目標分解（backward goal decomposition）階段，BES 遞迴地將原始任務拆解為可檢驗的子目標（subgoals）。每個子目標皆能對部分軌跡提供獨立的密集中間回饋（dense intermediate feedback），從而將原本稀疏的終端驗證訊號轉化為引導前向搜尋的密集訊號。理論上，作者證明僅使用擴展的搜尋會將候選方案侷限在一個狹窄的熵殼（entropy shell）之內（Theorem 4.4a），而演化運算子能夠逃逸此殼；同時，反向搜尋可指數級降低找到正確解答所需的樣本數。整體而言，BES 透過「前向探索—反向驗證」的雙向耦合，實現了對解空間更廣泛且更具導向性的探索。

#### 實驗數據解讀

實驗設計橫跨後訓練與推論兩大場景。在後訓練階段，研究團隊選擇了具挑戰性的邏輯推理（logical reasoning）與多跳推理（multi-hop reasoning）任務，這些任務對主流後訓練演算法如 GRPO、MaxRL 與 Tree-GRPO 構成嚴峻考驗。實證結果顯示，這些基線方法往往無法產生足夠多高品質的訓練樣本（sample generation），導致模型相較於基底模型未能改善甚至性能退化；相對地，BES 能持續發掘有效的訓練樣本，實現穩定的自我改進（self-improvement）。

在推論階段，研究於三個開放性問題解決基準（open problem solving benchmarks）上進行評測。結果表明，BES 無論在平均效能（average performance）或最佳效能（best-case performance）上，均優於現有開源框架如 OpenEvolve、GEPA 與 ShinkaEvolve。這暗示 BES 不僅提升了整體解題的穩定性，也具備發掘極端高品質解答的潛力。此外，論文提供了消融實驗（ablation studies）以驗證各元件的獨立貢獻，並透過案例研究（case studies）視覺化搜尋過程中前向與反向機制的互動。成本分析則進一步比較了 BES 與基線在 wall-clock time 與 API 開銷上的差異，顯示其在實際部署層面的可行性。

#### 與現有研究的比較

與 best-of-N 取樣相比，BES 不再受限於從單一模型機率質量（model probability mass）中獨立抽樣所導致的線性覆蓋率成長；當正確軌跡位於極低機率區域時，best-of-N 的採樣效率會急遽下降。與樹搜尋（如束搜尋 beam search、蒙地卡羅樹搜尋 Monte Carlo Tree Search、思維樹 Tree of Thoughts 或 Tree-GRPO）相比，雖然樹搜尋能利用軌跡的序列結構進行較有效率的剪枝，但其本質上仍是一條譜系一條譜系地透過順向擴展來具現化終端候選方案，且依賴的通常是稀疏的終端驗證訊號。BES 則透過演化運算子實現跨譜系的重組，直接突破模型自身分佈的邊界；同時藉由反向目標分解引入密集回饋，解決了傳統樹搜尋在訊號粒度上的不足。

相較於其他演化式框架（如 OpenEvolve、GEPA、ShinkaEvolve），BES 的獨特性在於明確引入「雙向」機制：現有方法多聚焦於前向的候選演化，而 BES 的反向搜尋提供了系統化的子目標分解與中間驗證，使搜尋具備層次化的導引結構。然而，BES 亦存在可預見的限制：雙向搜尋的交替執行意味著更高的系統複雜度與運算開銷；子目標分解的品質高度依賴語言模型對問題結構的理解，若分解不當，密集中間回饋可能反而引入雜訊；此外，演化運算子雖能逃逸熵殼，但在極高維度的離散序列空間中，重組後的軌跡語義一致性仍需額外驗證機制把關。

#### 可重現性評估

論文明確指出原始碼與訓練後的模型權重已公開於 GitHub 倉庫（https://github.com/Embodied-Minds-Lab/BES），這對可重現性（reproducibility）而言是極為正面的訊號。作者亦在文中提供虛擬碼（pseudocode，見附錄 A）與搜尋過程的案例視覺化（見附錄 E），降低了方法實作的門檻。不過，作為深度分析，仍有幾項細節值得後續追蹤：演化運算子的具體實作邏輯（如跨軌跡對齊與片段切割策略）、反向分解所使用的提示模板（prompt templates）、以及各基準測試上的超參數設定，這些都會顯著影響重現結果。所幸論文額外提供了 wall-clock time 與 API 成本的比較分析，使其他研究者能據以評估在不同運算預算下複現該方法的實際可行性。

#### 未來研究方向

從方法論延伸，未來研究可朝以下方向深化：

第一，**自適應演化運算子選擇**。當前四種運算子以固定或啟發式方式應用，未來可引入元學習（meta-learning）或 bandit 機制，依據問題類型與搜尋階段動態選擇最適合的重組策略，進一步提升逃逸熵殼的效率。

第二，**學習式子目標分解**。反向搜尋目前依賴模型進行遞迴分解，若能訓練專門的分解器（decomposer）或利用 RLVR（Reinforcement Learning with Verifiable Rewards）微調分解策略，可望在更複雜的領域（如長篇程式碼生成 code generation 或科學推理）中維持子目標的品質與可驗證性。

第三，**與測試時擴展（test-time scaling）的深度融合**。BES 在推論階段的優異表現顯示其具備作為測試時運算擴展機制的潛力。未來可探索將 BES 與自我改進語言模型（Self-Improving Language Models）的迭代訓練迴路結合，讓搜尋發現的高品質軌跡不只用於單次推論，更回流至後訓練階段持續提升基底模型能力。

第四，**多智能體與工具使用場景**。當前實驗主要聚焦於單一模型軌跡，將 BES 擴展至多智能體系統（agentic systems）或具備外部工具呼叫的環境中，讓演化運算子作用於不同智能體的策略軌跡，可能開啟更廣泛的應用空間。

第五，**理論刻畫的精細化**。本文已證明熵殼限制與樣本複雜度的指數級改善，未來可進一步分析不同演化運算子在特定分佈假設下的收斂速率，以及反向搜尋深度與前向搜尋廣度之間的最優權衡。

## 論文問答

**Q1：這篇論文針對語言模型取樣與搜尋提出了什麼根本挑戰？**
A：這篇論文針對大型語言模型與智能體系統在複雜推理問題上的取樣品質提出了根本挑戰，特別是在模型能力前沿的困難任務上。在這類問題中，天真的取樣方法可能需要過多樣本才能獲得正確答案，甚至可能完全失敗。核心挑戰在於現有搜尋方法受限於模型自身的機率分佈支撐集，並且僅能獲得稀疏的驗證訊號，導致難以發現最優解。

**Q2：為何 best-of-N 取樣與樹搜尋在具挑戰性的推理問題上表現不佳？**
A：Best-of-N 取樣與樹搜尋存在兩個根本限制，使其在困難問題上表現受限。首先，它們所依賴的驗證訊號通常是稀疏的，例如僅提供二元或粗粒度的回饋，無法在搜尋過程中提供足夠的指引。其次，這些方法主要透過自迴歸擴展來建構候選方案，將所有候選方案限制在模型自身分佈的狹窄熵殼內，因而難以觸及正確解答常所在的低機率區域。

**Q3：提升取樣品質對於訓練與推論為何至關重要？**
A：提升取樣品質之所以關鍵，是因為高品質樣本在模型生命週期的訓練與推論階段都扮演核心角色。在訓練階段，優質樣本能夠促進更有效的後訓練與迭代自我改進，直接增強模型的推理能力。在推論階段，更好的取樣機制作為測試時擴展的自然手段，能讓模型在不更新參數的情況下突破既有能力邊界，解決更困難的問題。

**Q4：雙向演化式搜尋（BES）的核心機制為何，它與傳統樹搜尋有何不同？**
A：雙向演化式搜尋（BES）是一個耦合前向候選演化與反向目標分解的搜尋框架，旨在克服傳統方法的限制。與僅透過自迴歸生成依序擴展候選方案的傳統樹搜尋不同，BES 同時透過演化運算子重組部分軌跡來進行前向探索，並透過遞迴分解問題來進行反向驗證。這種雙向設計使 BES 能夠逃脫僅靠擴展所被困的狹窄熵殼，並獲得密集的中間回饋以引導搜尋方向。

**Q5：BES 中的演化運算子如何實現超越模型原生分佈的探索？**
A：BES 引入了組合、轉位、刪除與交叉四種演化運算子，其靈感來自生物有性繁殖中的染色體重組，而非僅是單親的自迴歸延伸。這些運算子將來自不同候選方案的部分軌跡重新組合，以建構出單次模型展開極難產生的新穎候選方案。論文從理論上證明，僅靠擴展的搜尋會將候選方案限制在狹窄的熵殼中，而演化運算子能夠逃脫此殼，進而觸及包含正確解答的低機率區域。

**Q6：反向目標分解在 BES 框架中扮演什麼角色？**
A：反向目標分解負責將原始複雜任務遞迴地拆解為可檢驗的子目標，從而為部分軌跡提供密集的中間回饋。這種設計有效解決了傳統驗證器僅對完整方案提供稀疏二元回饋的問題，使搜尋過程中的每個前進節點都能獲得評估訊號。論文進一步從理論上說明，反向搜尋能夠指數級地減少找到正確答案所需的樣本數量，顯著提升搜尋效率。

**Q7：BES 在哪些任務與基準上進行了評估？**
A：BES 同時在後訓練與推論兩種設定下進行評估，以展示其廣泛的適用性。在後訓練方面，作者於具挑戰性的邏輯推理與多跳推理任務上進行測試，這些任務正是主流演算法難以提升的場景。在推論方面，則於三個開放性問題解決基準上進行評估，並與現有開源框架比較其產生穩定且高品質解答的能力。

**Q8：實驗的主要發現為何，BES 的效能表現如何？**
A：實驗結果顯示，在那些主流後訓練演算法如 GRPO、MaxRL 與 Tree-GRPO 無法找到足夠高品質訓練樣本甚至導致模型退化的困難任務上，BES 仍能持續發現有效的訓練樣本並帶來顯著改進。在推論階段，BES 在三個開放性問題解決基準上的平均效能與最佳效能，均優於所有現有開源框架，包括 OpenEvolve、GEPA 與 ShinkaEvolve。這些結果證實了雙向演化式搜尋在模型管線的不同階段皆具備實質優勢。

**Q9：作者提供了哪些額外分析來驗證 BES 的有效性？**
A：作者進行了詳盡的消融實驗，以驗證 BES 中各個元件的獨立貢獻。此外，他們提供了案例研究來視覺化搜尋過程，使前向演化與反向分解的互動關係更具可解釋性。論文還包含成本分析，比較 BES 與基線方法在實際執行時間與 API 花費上的差異，確保效能提升伴隨著實際部署層面的全面評估。

**Q10：BES 在哪些實際應用場景中最能發揮效益？**
A：BES 特別適用於需要深度推理的複雜問題求解場景，例如高等數學證明生成、多步驟科學推理以及複雜的程式碼生成任務。它可以部署在後訓練階段，用於生成高品質的合成資料以驅動模型自我改進，也可在推論階段用於增強面對超出基礎模型原生能力之使用者查詢時的表現。由於該框架同時適用於大型語言模型推理與智能體系統，因此也適合在結構化環境中運作的自主智能體。

**Q11：在生產系統中部署 BES 時應考慮哪些實務因素？**
A：在生產環境部署 BES 時，必須考量演化運算子與雙向搜尋所帶來的額外計算開銷，儘管論文已提供成本分析來協助權衡這些取捨。該方法依賴能夠同時評估最終解答與中間子目標的驗證器，針對特定領域可能需要額外工程設計。此外，由於 BES 涉及多次前向步驟與週期性的反向分解，系統設計者必須根據延遲需求與 API 呼叫預算，仔細評估其相較於簡單取樣方法的資源消耗。

**Q12：BES 可能對自我改進語言模型領域的未來研究產生何種影響？**
A：BES 透過展示演化重組與階層式目標分解的結合能夠克服自迴歸模型的根本分佈限制，為該領域引入了新的典範。這種雙向方法可能啟發超越單純 best-of-N 或樹狀樣本生成的新型訓練演算法，並重新定義具有可驗證獎勵之強化學習的標準實踐。透過將搜尋視為雙向演化過程，這項工作為將生物學洞見整合進人工智慧搜尋策略開闢了新的研究方向。

**Q13：根據論文描述，BES 方法存在哪些固有的限制或依賴條件？**
A：BES 的有效性本質上依賴於高品質驗證器的存在，該驗證器必須能夠準確評估最終解答與中間子目標，而這在部分領域可能難以取得或建構。演化運算子的效果可能因問題類型而異，特別是在部分軌跡難以有效重組或組合後語義一致性難以維持的任務中。此外，相較於簡單的平行取樣，雙向搜尋過程引入了額外的計算複雜度，這可能限制其在極度延遲敏感應用中的適用性。

**Q14：主流後訓練演算法在何種情況下會失敗，BES 如何解決這些問題？**
A：主流後訓練演算法如 GRPO 與 Tree-GRPO 在具挑戰性的邏輯與多跳推理任務上會失敗，因為它們無法發現足夠的高品質訓練樣本，經常導致微調後的模型相較於基礎模型不進反退。這些方法受困於稀疏獎勵與自迴歸生成所限制的狹窄熵殼，無法充分探索解空間。BES 透過演化運算子重組有潛力的部分解答，並透過反向分解提供密集指引，從而在基線方法失效的場景中持續發現有效的訓練樣本。

**Q15：這項研究暗示了哪些值得探索的未來方向？**
A：未來研究可針對特定領域開發更精緻的演化運算子，例如在程式碼或形式數學等軌跡重組需滿足嚴格結構限制的領域中設計專用運算子。另一個有前景的方向是將 BES 更緊密地整合進訓練循環，使模型能持續學習如何更好地輔助自身的演化搜尋。此外，將反向分解機制擴展至具備環境回饋的複雜階層式智能體任務，也有助於進一步推升測試時擴展所能解決的問題邊界。

## 實務應用指南

### 適用場景

1. **複雜數學證明與科學研究輔助**：針對需要多步推理且中間步驟可驗證的開放性問題，BES 的反向目標分解能將大型定理拆解為可檢查的子目標，並透過前向演化運算子重組不同證明嘗試，探索單一模型展開難以觸及的低機率區域。
2. **企業級程式碼生成與跨模組重構**：在需要組合多個程式碼片段或修復複雜邏輯錯誤的場景中，BES 可將現有程式軌跡視為部分軌跡，利用交叉與轉位等演化運算子產生新的候選方案，並以單元測試作為密集中間回饋，引導搜尋朝向可編譯且通過測試的解決方案。
3. **法律與醫療多跳邏輯問答**：面對需要長鏈條推理的領域，BES 能將最終答案的驗證訊號稀疏問題，轉化為多個子目標的密集中間回饋（例如「是否引用正確法條」「因果鏈是否連貫」），顯著提升推論時的穩定性與正確率。
4. **後訓練高品質樣本生成**：當主流後訓練演算法如 GRPO、Tree-GRPO 因稀疏驗證訊號而無法產生足夠高品質訓練樣本時，BES 可作為樣本生成引擎，持續發現基準模型難以自主產出的正確軌跡，供後續自我改進使用。
5. **智能體工作流程規劃與自動化**：在智能體系統中，BES 能將高層任務反向分解為可驗證的階段性子目標，並透過前向搜尋重組歷史執行軌跡，探索非典型但有效的行動序列，突破自迴歸擴展的侷限。

### 實作前置條件

- **資料準備**：每個推理問題需具備結構化的問題描述 x 與可輸出分數的驗證器 V(x,y)。若業務場景僅有最終答案的二元回饋，需額外投資於子目標標註或建立能自動進行反向目標分解的輔助模型／規則引擎。
- **運算資源**：需支援大量並行推論的 GPU 叢集或充足的 API 配額。前向搜尋需同時維護候選方案族群並執行多種演化運算子，反向搜尋則需額外呼叫模型進行目標分解，兩者皆顯著高於 best-of-N 取樣的運算需求。
- **技術能力**：團隊需熟悉樹搜尋與強化學習基礎（如蒙地卡羅樹搜尋、束搜尋）、具備大型語言模型微調經驗（若應用於後訓練），以及設計細粒度驗證器的能力。此外，需有能力開發狀態管理系統以追蹤部分軌跡與搜尋樹節點。

### 實作步驟建議

1. **驗證器與子目標設計**：將業務問題形式化為 (x, V) 結構。若原始驗證訊號稀疏，優先建立反向搜尋模組，將最終目標拆解為 3–5 個可獨立檢查的子目標，確保前向搜尋能獲得密集中間回饋。
2. **基線評估與熵殼診斷**：以 best-of-N 取樣或標準樹搜尋建立效能基線，觀察候選方案是否高度相似、集中於模型自身分佈的高機率區域。若出現此現象，代表系統受困於熵殼，適合導入 BES。
3. **漸進式導入演化運算子**：依序實作組合（combination）、刪除（deletion）、轉位（translocation）與交叉（crossover）。建議先從組合與刪除開始，因其實作門檻較低且能立即提升軌跡多樣性；待穩定後再加入轉位與交叉，以進一步探索低機率區域。
4. **雙向耦合排程**：設定前向搜尋與反向搜尋的交替頻率（例如每 3 次前向擴展執行 1 次子目標分解與驗證）。確保反向搜尋產生的回饋能及時修剪前向搜尋樹，避免運算資源浪費在低品質分支。
5. **推論驗證到後訓練部署**：先在推論階段驗證 BES 的平均效能與最佳效能；確認其能穩定發現正確解後，將高品質軌跡納入後訓練管線（如 GRPO 或 DPO），形成「雙向演化式搜尋 → 過濾 → 微調」的迭代自我改進迴路。

### 潛在風險與注意事項

- **計算成本與延遲膨脹**：演化運算子與反向目標分解會顯著增加 API 呼叫次數。需設定嚴格的候選方案數量上限、搜尋深度與預算閾值，並搭配非同步快取與重複軌跡去重機制。
- **驗證器偏誤與回饋誤導**：若子目標設計不良或驗證器存在偏誤，密集中間回饋反而會將前向搜尋導向局部最優。建議保留一定比例的隨機探索，並定期以人工或黃金標準審核子目標的有效性。
- **演化重組的語意不連貫**：前向演化運算子可能產生語法或邏輯上不連貫的混合軌跡。需在前向搜尋中增加硬性約束過濾器（如可執行性檢查、語意一致性評分），剔除無效候選方案。
- **系統維運複雜度**：相較於 best-of-N 取樣，BES 涉及複雜的搜尋樹狀態管理與多輪模型互動，無法直接套用標準推論框架。需預留工程資源開發專屬的狀態追蹤、日誌記錄與錯誤復原機制。

### 與其他技術的整合建議

- **與後訓練演算法整合**：將 BES 作為高品質樣本生成層，銜接至 GRPO、DPO 或 PPO 的訓練迴路，取代傳統的 best-of-N 取樣；亦可與 Tree-GRPO 結合，以 BES 的前向候選演化擴展其節點生成策略，突破自迴歸擴展的限制。
- **與推論服務框架整合**：在 vLLM、TensorRT-LLM 等服務化推論引擎外層部署 BES 的搜尋協調器，利用其批次處理能力同時展開多條軌跡；反向目標分解可交由獨立的輕量模型或規則引擎處理，避免阻塞主推論流。
- **與檢索增強生成（RAG）整合**：反向搜尋所需的領域知識可來自外部向量資料庫或知識圖譜，使子目標分解更貼近專業領域；前向搜尋產出的優秀軌跡亦可回流至資料庫，作為未來檢索的少樣本示例，形成知識閉環。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從圖 1 的直觀對照開始，理解「樹搜尋受限於熵殼」與「雙向演化式搜尋如何突破」的核心概念；可暫時略過第 4 節的定理證明，專注於第 3 節的演算法流程與附錄的案例研究，建立對前向演化運算子與反向子目標分解的具體想像。
- **AI 工程師**：請重點閱讀第 3 節的虛擬碼與第 4 節的理論動機，特別是演化運算子如何幫助候選方案逃離熵殼；實作時應優先關注驗證器的顆粒度設計與搜尋排程策略，並參考附錄中的成本分析來評估上線後的延遲與 API 開銷。
- **研究人員**：建議深入研讀第 4 節的理論分析，包含熵殼限制定理與反向搜尋的樣本複雜度指數級降低證明；可進一步思考如何將 BES 的雙向架構擴展至連續動作空間或多智能體協作場景，或探索更高效的演化運算子設計。
- **產品經理**：請聚焦於第 1 節的動機與第 5 節的實驗結果，評估 BES 在您負責的領域中解決「模型後訓練停滯」或「推論時最佳案例效能不足」的潛力；同時留意成本分析章節，將額外的運算開銷納入 ROI 評估，優先選擇驗證訊號稀疏且正確解落在低機率區域的高價值問題導入。
