現有 MLLM 導航器每步重複編碼過去幀，計算冗餘且歷史記憶短，且僅以單一標量獎勵學習錯誤。
GlanceNav 以混合 MLLM 建固定大小串流記憶體，並用反事實回溯從最接近目標處強化學習。

## 摘要翻譯

多模態大型語言模型 (MLLMs) 已成為視覺與語言導航 (VLN) 的強健策略。然而，大多數模型在每次決策時都會重新編碼過去幀的樣本，且僅在孤立的決策上進行訓練，因此計算冗餘且可用的歷史長度有限。它們也透過結果獎勵從自身錯誤中學習，而此獎勵僅對整個回合提供單一純量。我們探問：導航器是否能以每步固定成本僅編碼每幀一次，同時仍記住關鍵資訊並有效從錯誤中學習。我們提出 GlanceNav，一個建構於混合式多模態大型語言模型之上的串流導航器。其門控 DeltaNet (GDN) 層在整個回合中維持一個循環狀態，而其注意力層則保留一個近期觀察的滑動視窗，以及一個由各幀對循環狀態之變化量所選出的小型關鍵幀記憶庫。此固定大小記憶體使每步成本保持固定，並允許以與推理時相同的記憶體對整個回合進行訓練。由於整個記憶體也能以固定時間複製，我們進一步提出反事實回溯 (CoRe)，一個強化學習 (RL) 階段：將漂移推演軌跡回溯至最接近目標的位置，讓專家策略修正少數動作，並依據結果的變化對各決策進行功勞歸屬。僅在 R2R-CE 與 RxR-CE 訓練分割上訓練，並使用 1,000 條指令進行強化學習，4B 參數的 GlanceNav 在 R2R-CE 與 RxR-CE 未見驗證集上分別達到 71.9% 與 73.6% 的成功率。在 R2R-CE 上，其表現超越先前最強的、未使用外部資料訓練的單一 RGB 方法 9.1 個百分點，同時每步僅需 104 毫秒。

### 核心貢獻（3～5點）
- **串流記憶體架構**：提出結合門控 DeltaNet (GDN) 循環狀態、滑動視窗與關鍵幀記憶庫的固定大小記憶體設計，使每步編碼成本恆定，並能以與推理時相同的記憶體進行整個回合的訓練。
- **關鍵幀選擇機制**：以各幀對循環狀態的變化量（狀態變化分數）作為無參數評分指標，自動篩選並保留對導航決策最具影響力的關鍵幀。
- **反事實回溯強化學習階段 (CoRe)**：透過將漂移推演軌跡回溯至最接近目標的位置、由專家策略修正少數動作、再依結果變化進行功勞歸屬，實現對整個回合的高效強化學習。
- **優異的效率與效能平衡**：4B 參數的 GlanceNav 在 R2R-CE 與 RxR-CE 未見驗證集上分別達到 71.9% 與 73.6% 的成功率，每步僅需 104 毫秒，且無需使用任何外部資料。

### 適合對象
從事視覺與語言導航 (VLN)、具身人工智慧、多模態大型語言模型 (MLLMs) 應用、強化學習與模仿學習、邊緣裝置即時推論等領域的研究人員與工程師；以及對高效序列決策模型、記憶體架構設計與基於結果獎勵之策略最佳化感興趣的學者與研究生。

GlanceNav 的方法論核心在於解決視覺與語言導航 (Vision-and-Language Navigation, VLN) 中兩個根本性問題：記憶體冗餘與從錯誤中學習的低效率。其架構設計體現了「以最小成本保留最關鍵資訊」的工程哲學。

**混合式 MLLM 架構的選擇**

論文採用混合式多模態大型語言模型 (Hybrid MLLM) 作為骨幹，這是一個關鍵的設計決策。傳統的純 Transformer 架構在處理長序列時面臨計算成本二次方增長的問題，而純線性注意力或狀態空間模型 (State-Space Models) 雖然計算效率高，但對於精確的 token-level 資訊保留能力有限。GlanceNav 採用 Gated DeltaNet (GDN) 層作為主要組成，僅保留少量 Softmax 注意力層作為補充，這種設計在計算效率與資訊保真度之間取得了平衡。

GDN 層的核心特性是將每個 token 折疊 (fold) 進一個固定大小的循環狀態 (recurrent state)，這意味著整個回合 (episode) 的歷史資訊始終被壓縮在這個狀態中。然而，這種壓縮是有損的 (lossy)，因此需要少量注意力層來保留精確的 token 資訊作為補充。

**狀態變化分數 (State-Change Score) 的設計**

這是論文最具巧思的貢獻之一。傳統的關鍵幀選擇方法通常依賴於：
- 時間近因性 (recency)
- 注意力質量 (attention mass)
- 查詢相關性 (query relevance)

這些方法各有局限：近因性會遺失重要的早期資訊；注意力質量需要訓練後才能計算；查詢相關性則依賴於當前查詢。

GlanceNav 提出的狀態變化分數是無參數的 (parameter-free)，其核心洞見是：一幀如果已經被循環狀態「預測」到了（即狀態已經隱含了該幀的資訊），那麼它對狀態的改變就很小；反之，一幀若包含新內容（例如進入新房間），則會顯著改變狀態。這種設計的優點在於：
1. 不需要額外訓練
2. 直接利用模型本身的內部狀態作為資訊含量的度量
3. 計算成本極低

**固定大小記憶體的因果性**

記憶體的固定大小帶來兩個重要性質：
1. **每步固定成本 (constant cost per step)**：因為每幀只編碼一次，且記憶體大小不隨時間增長，所以推理成本是恆定的。這對於實際部署至關重要。
2. **因果性 (causality)**：關鍵幀僅從過去選擇，因此每一步的記憶體可以在一次前向傳遞 (forward pass) 中建構完成。這使得訓練與推理可以使用相同的記憶體結構，消除了訓練-推理不一致的問題。

論文特別強調「episode-level training」的概念——整個回合在訓練時使用與推理時相同的記憶體配置，這與傳統的「step-wise training」（每個決策獨立訓練）形成對比。據論文所述，這種設計使得編碼幀數減少了 8.6 倍。

**反事實回溯 (Counterfactual Rewind, CoRe) 的強化學習機制**

CoRe 是論文在強化學習階段的核心創新。傳統的基於結果的強化學習 (outcome-based RL) 如 GRPO 存在一個根本問題：它給整個回合（約 100 步決策）一個純量獎勵，這使得：
1. 信用分配 (credit assignment) 極其困難
2. 隨著策略改善，成功軌跡增多，失敗軌跡減少，學習信號變弱

CoRe 的設計巧妙地利用了固定大小記憶體的特性：因為整個記憶體可以在 O(1) 時間內複製（136 MiB，1.4 ms），所以可以在任何步驟「快照」完整的狀態。CoRe 的運作流程如下：

1. **偵測漂移**：當推演軌跡 (rollout) 開始偏離目標時觸發
2. **回溯到最接近點**：將模擬器與代理的記憶體恢復到軌跡中最接近目標的位置
3. **專家修正**：讓最短路徑專家重新執行幾個動作
4. **分支對比**：比較原始軌跡與修正後軌跡的結果差異
5. **信用分配**：根據結果差異對策略的延續動作與專家的修正動作進行信用分配

這種設計的關鍵優勢在於：漂移的軌跡產生的是同一狀態下兩個結果的對比，而非整個回合的單一純量。這使得學習信號更加密集且更具資訊性。

**三階段訓練流程**

論文採用三階段訓練：
1. **回合級監督微調 (Episode-level SFT)**：使用完整的回合記憶體進行監督學習
2. **DAgger**：在學習者訪問的狀態上進行專家標註
3. **CoRe**：在 1,000 條指令上進行反事實強化學習

值得注意的是，整個訓練僅使用 R2R-CE 與 RxR-CE 的訓練分割，沒有使用任何外部資料（如 ScaleVLN、VQA 或網路影片），這在當前追求規模化的 VLN 研究中是相當克制的。

#### 實驗數據解讀

**核心效能指標**

GlanceNav 使用 4B 參數的骨幹，在兩個主要基準上取得了顯著成果：
- **R2R-CE val-unseen**：71.9% 成功率 (Success Rate, SR)
- **RxR-CE val-unseen**：73.6% SR

在 R2R-CE 上，71.9% SR 比先前最佳單一 RGB 方法（不使用外部資料訓練）高出 9.1 個百分點。這個差距在 VLN 領域是相當顯著的，因為近年來該領域的進步通常以個位數百分點為單位。

**與使用外部資料的方法比較**

論文中提到，在所有比較的單一 RGB 方法中，僅有一個 8B 模型在使用額外資料時得分更高。這凸顯了 GlanceNav 的兩個優勢：
1. 在不使用外部資料的條件下達到最先進水平
2. 模型規模更小（4B vs 8B），但效能接近

**推理效率**

GlanceNav 的推理速度為每步 104 毫秒，論文聲稱這是同尺寸骨幹的逐步式導航器 (step-wise navigator) 的一半以下。這個效率提升來自於：
1. 每幀只編碼一次（而非每個決策重新編碼）
2. 固定大小的記憶體避免了 KV 快取的線性增長
3. 關鍵幀選擇的計算成本極低

**CoRe vs GRPO 的對比**

論文報告了一個關鍵的消融實驗結果：在相同的 1,000 條指令上，CoRe 為 DAgger 訓練後的策略增加了 8.2 SR，而 GRPO 僅增加 3.1 SR。這 5.1 個百分點的差距證明了 CoRe 在信用分配上的優勢。

**記憶體效率的量化**

論文提到「編碼幀數減少 8.6 倍」，這是相對於逐步式訓練的對比。考慮到典型的逐步式導航器在每個決策時重新編碼約 8 幀，而 GlanceNav 每幀只編碼一次，這個數字是合理的。

#### 與現有研究的比較

**與串流式導航器的比較**

GlanceNav 與三個主要的串流式導航器有直接關聯：

1. **StreamVLN**：使用滑動視窗與剪枝記憶體，但驅逐是最終的——一旦離開快取就永遠不可見。GlanceNav 的 GDN 狀態則始終保留所有歷史的壓縮表示。

2. **JanusVLN**：保留初始幀與最近幀的 KV 快取，但選擇策略是基於語義與幾何編碼器的啟發式。GlanceNav 的狀態變化分數更為通用且無參數。

3. **Efficient-VLN**：也重用 KV 快取，但將多個決策打包成一個訓練序列。GlanceNav 則採用回合級訓練，記憶體結構在訓練與推理間完全一致。

**與基於 Delta 規則的記憶體管理比較**

論文提到了兩個相關工作：
- **HOLA**：保留具有大承諾寫入 (committed write) 的 token
- **DeltaS**：通過狀態漂移驅逐影片區塊

GlanceNav 的狀態變化分數屬於同一家族，但有三個關鍵差異：
1. 目標任務不同：HOLA 與 DeltaS 針對語言與影片理解，GlanceNav 針對閉環控制
2. 訓練方式不同：GlanceNav 端到端訓練導航策略
3. 評估方式不同：閉環導航需要考慮動作的長期影響

**與強化學習方法的比較**

在從錯誤中學習的維度上：
- **GRPO**：給整個回合一個純量，學習信號稀疏
- **SACA**：從審計者找到的發散點重新取樣
- **SeekVLN**：在證據尋求步驟進行反事實分支
- **BudVLN**：從參考路徑上最遠的進度修正失敗

CoRe 的獨特之處在於：
1. 從「最接近目標」的位置分支（而非最遠進度或發散點）
2. 利用 O(1) 記憶體快照實現快速回溯
3. 使用 Q-filter（基於推演而非學習的評論家）來決定是否模仿專家

**方法論的侷限性**

儘管成果顯著，GlanceNav 仍有幾個潛在限制：

1. **GDN 狀態的壓縮損失**：雖然 GDN 提供了固定大小的記憶體，但壓縮本質上是有損的。對於需要精確空間推理的任務，這可能成為瓶頸。

2. **狀態變化分數的假設**：該分數假設「狀態變化大 = 資訊含量高」，但這在某些情況下可能不成立。例如，一幀包含重要的細節但與先前幀相似，可能被錯誤地驅逐。

3. **CoRe 的依賴性**：CoRe 需要一個可靠的專家策略（最短路徑），這在某些場景中可能不可用。

4. **單一 RGB 輸入**：雖然這是論文的設計選擇（強調效率），但放棄深度與幾何資訊可能在某些環境中限制表現。

GlanceNav 的串流記憶體與反事實回溯機制，特別適合以下幾類需要「長序列即時決策」與「從錯誤中快速學習」的應用：

1. **室內服務機器人（家庭、飯店、醫院導覽）**：機器人需根據自然語言指令（如「帶我到 302 病房，經過護理站」）穿越未見過的建築物。GlanceNav 每步 104 ms 的固定成本與單一 RGB 輸入，使其適合部署在搭載消費級 GPU（如 RTX 4090）的行動平台上，且不需要深度相機或全景相機等額外硬體。

2. **倉儲與物流 AMR（自主移動機器人）**：揀貨員用語音或文字下達指令（「去 A 區第三排取 12 號貨架」），機器人需在長走廊與重複貨架間維持方位感。GDN 層的循環狀態能持續壓縮整段路徑資訊，避免 KV 快取爆量。

3. **AR/VR 空間導引助理**：在頭戴裝置上，使用者說出「帶我走到剛才那個有紅色沙發的房間」，代理需記住先前觀察並在長時間閒置後仍能定位。固定大小記憶體讓記憶體預算可預估，不會因閒置時間拉長而耗盡 VRAM。

4. **工業巡檢機器人**：在工廠、變電站或資料中心，巡檢員下達多步驟指令（「檢查三號機房的冷卻系統並回報」），代理需在長任務中維持狀態並從錯誤路徑中自我修正（CoRe 的典型情境）。

5. **無障礙輔助導航**：視障輔具中，使用者給出口語指令，代理需在陌生建築中即時導航並在走錯時快速回退。CoRe 的「回到最接近點」機制正契合此類容錯需求。

### 實作前置條件

**資料需求**
- **VLN-CE 訓練資料**：必須取得 Room-to-Room（R2R-CE）與 Room-across-Room（RxR-CE）的訓練分割授權（透過 Matterport3D 模擬器授權流程申請）。論文僅使用這兩個資料集的訓練集，未引入 ScaleVLN、VQA 或網路影片等外部資料。
- **Habitat 模擬器**：需安裝 Habitat-Sim 與 Habitat-Lab，用於產生連續環境中的自我中心觀察與最短路徑專家。
- **強化學習階段的 1,000 條指令**：CoRe 階段僅需 1,000 條額外指令即可帶來 +8.2 SR 的提升，門檻極低。

**運算資源**
- **訓練**：4B 參數的混合 MLLM（如 Qwen2.5-VL 或類似 GDN 骨幹）進行三階段訓練（SFT → DAgger → CoRe）。建議至少 8× A100/H100 80GB 節點；GDN 層的循環狀態允許整段回合一次前向傳遞，但仍需足夠顯存容納 136 MiB 的記憶體快照。
- **推論**：單張消費級 GPU（如 RTX 4090、5090）即可達到 104 ms/步的即時速度；行動平台可考慮 4-bit 量化版本。
- **儲存**：每步記憶體快照僅 136 MiB、複製時間 1.4 ms，可忽略。

**技能前提**
- 熟悉混合式 MLLM 架構（GDN 層 + 稀疏 softmax 注意力層的交錯設計）。
- 具備 VLN 任務的領域知識：動作空間 {FORWARD, LEFT, RIGHT, STOP}、最短路徑專家介接、評估指標（SR、SPL、NE）。

- 具備分散式訓練經驗（回合級而非步級的訓練管線）。

### 實作步驟建議

**階段 0：環境與骨幹準備**
1. 安裝 Habitat-Sim/Lab，下載 Matterport3D 場景與 R2R-CE/RxR-CE 訓練分割。
2. 選定 4B 級混合 MLLM 骨幹（需含 GDN 層），確認其權重與 tokenizer。
3. 將動作空間與指令格式封裝成模型可讀的詞元序列。

**階段 1：回合級監督式微調（SFT）**
1. 實作「單一前向傳遞跑完整個回合」的訓練管線：每幀只編碼一次，GDN 狀態在回合內持續傳遞。
2. 實作**狀態變化分數**（state-change score）：計算每幀對 GDN 循環狀態造成的相對變化量，作為關鍵幀選取依據。此分數無可訓練參數。
3. 注意力層的輸入組合：最近 N 幀的滑動視窗 + 由狀態變化分數挑選的 K 個關鍵幀記憶庫。
4. 以專家示範路徑進行回合級 SFT，目標函數為動作預測的交叉熵。

**階段 2：DAgger 模仿學習**
1. 讓當前策略在模擬器中執行回合，於訪問過的狀態收集專家標註。
2. 將專家動作與策略動作一同納入訓練資料，繼續回合級微調。
3. 此階段記憶體配置需與推論時一致，確保訓練-推論一致性。

**階段 3：Counterfactual Rewind（CoRe）強化學習**
1. 為策略的每個回合實作**記憶體快照機制**：在任意步驟以 O(1) 時間複製整個串流記憶體（136 MiB / 1.4 ms）。
2. 偵測**漂移訊號**：當代理開始遠離目標（例如與目標距離單調增加超過閾值）時觸發回溯。
3. **回溯到最接近點**：從回合中找出與目標距離最小的步驟，還原模擬器狀態與代理記憶體。
4. **專家修正分支**：讓最短路徑專家從該點重新執行若干步，再交由策略完成。
5. **反事實信用分配**：比較原回合與分支回合的最終結果差異，作為策略延續動作的獎勵；專家動作僅在分支優於原回合時被模仿（Q-filter）。
6. 在 1,000 條指令上單趟訓練，預期可帶來 +8.2 SR 提升（vs. GRPO 同資料量僅 +3.1 SR）。

**階段 4：部署與監控**
1. 將模型匯出為可服務格式（TensorRT、vLLM 或 ONNX Runtime），確認每步延遲 ≤ 104 ms。
2. 在目標機器人平台上整合 RGB 相機驅動、動作執行介面與安全包絡（防碰撞、停止按鈕）。
3. 上線後持續收集失敗案例，定期以 CoRe 流程離線再訓練。

### 潛在風險與注意事項

**1. 骨幹架構依賴性**
- GlanceNav 的設計假設骨幹為「多數 GDN 層 + 少數 softmax 注意力層」的混合 MLLM。若骨幹不具備 GDN 層（如純 Transformer 或純 Mamba），狀態變化分數將無法計算，必須替換骨幹或重新設計關鍵幀選取機制。
- **緩解**：選用已驗證的混合骨幹（如 Qwen2.5-VL-4B 系列），或在自訂骨幹中明確保留至少一層 GDN 用於狀態變化分數計算。

**2. 訓練-推論一致性**
- 論文強調「用測試時的記憶體訓練」，若實作時改回步級訓練（每步重新編碼過去幀），將喪失 8.6× 的幀編碼效率優勢，且效能可能下降。
- **緩解**：建立單元測試，驗證訓練與推論時的記憶體配置（滑動視窗大小、關鍵幀數量、GDN 狀態維度）完全一致。

**3. CoRe 的分支成本**
- 雖然記憶體快照為 O(1)，但每個漂移回合仍需執行額外的專家分支與策略延續，會增加整體訓練時間。
- **緩解**：僅在偵測到明確漂移訊號時觸發；可調高漂移閾值以降低觸發頻率，或限制每回合最多分支一次。

**4. 模擬器到真實世界的轉移（Sim2Real）**
- 論文所有結果均在 Habitat 模擬器中取得，未涉及真實機器人實驗。視覺外觀、光照、動態障礙物的差異可能造成效能下降。
- **緩解**：在部署前進行領域隨機化（domain randomization）或收集少量真實環境資料進行微調；保留 STOP 動作作為安全閘。

**5. 指令理解限制**
- 結果顯示 RxR-CE（73.6%）略高於 R2R-CE（71.9%），但兩者均為英文指令。中文或多語言指令需額外微調。
- **緩解**：若目標市場為中文環境，可加入中文指令資料進行第二階段 SFT，或採用多語言骨幹。

**6. 評估指標單一性**
- 論文主要報告 SR（成功率），未深入分析 SPL（路徑效率）或 NE（導航誤差）。在路徑效率敏感的場景（如倉儲），需自行評估。
- **緩解**：在內部評估中加入 SPL 與 NE 指標，必要時調整獎勵函數鼓勵最短路徑。

### 與其他技術的整合建議

**1. 與大型語言模型（LLM）規劃器整合**
- GlanceNav 本身是端到端策略，可作為低階動作控制器，上層接入 LLM 規劃器（如 GPT-4、Claude）進行任務分解（「先去拿鑰匙，再去開門」）。
- 介接點：將 LLM 分解出的子目標轉為自然語言指令，餵入 GlanceNav；回合結束後將結果回報給 LLM。

**2. 與 SLAM / 視覺里程計整合**
- 雖然 GlanceNav 僅使用 RGB，但可選擇性融合 SLAM 估計的位姿作為輔助輸入（例如將相對座標編碼為詞元）。
- 注意：需評估是否會破壞單一 RGB 輸入的簡潔性優勢。

**3. 與語音輸入整合**
- 在無障礙輔助或服務機器人場景，整合 ASR（如 Whisper）將語音轉為指令。
- 建議在 ASR 與 GlanceNav 之間加入意圖解析層，處理模糊或部分指令。

**4. 與 ROS 2 整合**
- 將 GlanceNav 包裝為 ROS 2 節點，訂閱 `/camera/image_raw`、發布 `/cmd_vel`。
- 記憶體快照機制可對應到 ROS 2 的服務呼叫（rewind service），便於除錯與回放。

**5. 與監控與日誌系統整合**
- 每步 136 MiB 的記憶體快照可作為除錯利器：當機器人行為異常時，可載入快照重現當時的完整內部狀態。
- 建議將快照與感測器資料、動作日誌一併存入時序資料庫（如 InfluxDB），供事後分析。

**6. 與其他 VLN 方法的比較整合**
- 若現有系統已部署 StreamVLN、JanusVLN 或 Efficient-VLN，可將 GlanceNav 作為 A/B 測試的候選方案。
- 論文報告 GlanceNav 比同尺寸步級導航器的每步時間少一半以上，是明確的效能優勢。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的問題陳述，理解「為什麼現有 MLLM 導航器每步要重新編碼過去幀」這個核心痛點。接著跳到第 3.1 節的任務形式化，掌握動作空間與觀察的定義。圖 1（GlanceNav 與傳統方法的對比）是理解整篇論文的視覺入口。實作上可先從 Habitat 官方教學跑通最簡單的隨機策略，再逐步替換為 GlanceNav 的骨幹。

**給 AI 工程師**：重點關注第 3 節的串流記憶體設計與狀態變化分數的計算方式——這是無參數、可立即實作的關鍵創新。CoRe 的分支與 Q-filter 機制也相當工程友善：記憶體快照為 O(1)、分支僅在漂移時觸發、易於整合進現有 RL 訓練管線。建議先在小型骨幹（如 1B 等級）上重現 SFT 階段，驗證記憶體配置與訓練-推論一致性後再擴展到 4B。

**給研究者**：論文的兩個主要貢獻——狀態變化分數作為關鍵幀選取準則、以及 CoRe 作為基於結果 RL 的改進——都開啟了多個值得探索的方向。狀態變化分數屬於「從 delta rule 讀取驅逐決策」這一新興家族（與 HOLA、DeltaS 並列），可進一步研究其在影片理解、串流 LLM 等任務的適用性。CoRe 的「回到最接近點」策略與 SACA、SeekVLN、BudVLN 構成一個有趣的設計空間，可系統性比較不同分支點選擇準則的效益。此外，回合級訓練與測試時記憶體一致性的設計原則，對其他需要長序列決策的領域（如機器人操作、遊戲 AI）也具有借鏡價值。

**給產品經理**：GlanceNav 的商業價值在於「單一 RGB + 消費級 GPU + 無外部資料」即可達到 71.9% SR，這大幅降低了硬體與資料合規成本。104 ms/步的固定成本讓延遲可預估、便於 SLA 設計。三階段訓練流程（SFT → DAgger → CoRe）清晰且資料需求遞增，可分階段交付：先上線 SFT 版本驗證場景，再逐步迭代。需注意目前所有結果均來自模擬器，產品化前應預留 Sim2Real 驗證的時間與預算。建議將 GlanceNav 定位為「室內長任務導航的低成本基座」，上層再疊加領域專屬的指令理解與任務規劃。
