## 摘要翻譯

智能體能從過往執行經驗（past executions）中學習，但讓不同智能體重複使用（reuse）並在彼此經驗的基礎上持續累積，仍具挑戰性。我們提出 EpiCon，一個共享多模態記憶框架（Shared Multimodal Memory Framework），用於無需更新主模型參數（Host Model Parameters）的集體智能體學習（Collective Agent Learning）。EpiCon 透過兩個獨立訓練的 2B 模型（2B Models）——記憶控制器（Memory Controller）與樹狀自組織器（Tree Self-Organizer）——將問題層級記憶（Question-level Memory）的演化連結至持久化經驗庫（Persistent Experience Bank）。記憶控制器在多次嘗試間共同精煉文本引導（Textual Guidance）與視覺證據（Visual Evidence），並選擇性地納入視覺記憶（Visual Memory）。樹狀自組織器以層次化方式整合經驗教訓（Hierarchical Consolidation），並為新問題檢索（Retrieval）經驗與規則。我們在十一個涵蓋四個多模態任務領域（Multimodal Task Domains）的基準測試（Benchmarks）上評估 EpiCon，使用兩個記憶載具（Memory Harness）與多個骨幹模型（Backbones）。即使僅進行一次解題嘗試，凍結經驗庫（Frozen Bank）仍能提升其他系統的表現。第二個記憶載具在十一個基準測試上將原始系統的宏觀平均分數（Macro-average Score）提升了 2.6 分。在四種主模型配置下，EpiCon 相較於無記憶基線將宏觀平均分數提升了 1.7 至 4.9 分，並相較於與骨幹模型同等規模的記憶模型減少了 67% 至 74% 的記憶操作時間（Memory-operation Time）。

### 核心貢獻（3～5點）
- 提出 EpiCon，一個無需更新主模型參數的共享多模態記憶框架，使不同智能體能夠重複使用並累積彼此的執行經驗。
- 透過記憶控制器與樹狀自組織器兩個獨立訓練的 2B 模型，分別在問題層級共同演化文本引導與視覺證據，並以層次化方式整合與檢索長期經驗。
- 在十一個涵蓋四個多模態任務領域的基準測試上進行大規模評估，驗證凍結經驗庫可提升其他系統表現，且第二個記憶載具能將原始系統的宏觀平均分數提升 2.6 分。
- 相較於無記憶基線提升宏觀平均分數 1.7 至 4.9 分，同時相較於骨幹模型同等規模的記憶模型減少 67% 至 74% 的記憶操作時間。

### 適合對象
適合多模態人工智慧、多智能體系統、記憶增強型語言模型與智能體持續學習領域的研究者與工程師；特別是關注如何在不更新主模型參數的前提下，透過外部記憶實現跨智能體經驗共享、知識重複使用，以及降低記憶操作開銷的讀者。

## 深度分析

#### 方法論解析

EpiCon（Episodic Consolidation，情節整合）的核心設計是將「問題內的記憶演化」與「跨問題的經驗累積」解耦，並透過一個專屬的記憶載具（Memory Harness）把兩者串接起來。整體架構可視為三層：最上層是執行任務的多智能體系統（Multi-agent Systems, MAS）與其骨幹模型（Backbones）；中間是負責協調的 Memory Harness（記憶載具）；底層則是兩個獨立訓練的 2B 模型——Memory Controller（記憶控制器）與 Tree Self-Organizer（樹狀自組織器）——以及一個 Persistent Experience Bank（持久化經驗庫）。

在單一問題內部，Memory Controller（記憶控制器）負責 Question-level Memory（問題層級記憶）的共同演化。它會根據連續的嘗試（attempts）與外部回饋，同時修正 Textual Guidance（文本引導）與 Visual Evidence（視覺證據）。具體來說，文本引導是可執行的策略或提示（Actionable Guidance），而視覺證據則是與決策相關的 Image Regions（圖像區域）。控制器不僅更新這兩種記憶的內容，還會自適應地決定下一次嘗試是否納入 Visual Memory（視覺記憶），避免無關影像干擾推理。這種 Co-Evolving Multimodal Memory（共同演化的多模態記憶）機制讓文本與視覺線索在回饋驅動下同步收斂。

跨問題層面，Tree Self-Organizer（樹狀自組織器）負責把累積的教訓進行 Hierarchical Consolidation（層次化整合）。它將經驗組織成樹狀結構，便於後續 Retrieval（檢索）與 Reuse（重複使用）。這個經驗庫獨立於 MAS 維護，因此即使更換 Harness（載具）或 Backbone（骨幹模型），歷史經驗仍可被檢索。更重要的是，不同 Harness 在解題過程中既能 Reuse（重複使用）既有經驗，也能貢獻新教訓，形成 Collective Agent Learning（集體智能體學習）的閉環，且全程不更新 Host Model Parameters（主模型參數）。

#### 實驗數據解讀

論文在十一個 Benchmarks（基準測試）、橫跨四個 Multimodal Task Domains（多模態任務領域）上進行評估，並使用兩個 MAS Harness 與多個 Backbone。從摘要與引言可歸納出以下關鍵數據：

1. **相對於 No Memory 的整體提升**：在四種 Host 配置下，EpiCon 的 Macro-average Score（宏觀平均分數）比無記憶基線高出 1.7 至 4.9 點。這顯示無論在哪種骨幹或載具下，外部記憶都能穩定帶來增益。

2. **跨 Harness 的經驗遷移**：當一個 Harness 產生的經驗被另一個 Harness 使用時，原始系統的 Macro-average Score 提升了 2.6 點；若由另一個 Harness 貢獻經驗，則提升 2.1 至 3.2 點。這是 EpiCon 最具價值的結果之一，因為它證明 Experience Bank（經驗庫）不只是「同一系統內的快取」，而是可跨系統遷移的知識資產。

3. **Frozen Bank（凍結經驗庫）的單次嘗試效益**：即使在只進行一次嘗試的情況下，凍結的經驗庫仍能改善其他系統的表現。這意味著經驗的價值不仰賴多次試錯，而是能在首次推理時透過檢索直接發揮作用。

4. **效率優勢**：相較於使用 Backbone 同等規模的記憶模型，EpiCon 的 2B 模型將 Memory-operation Time（記憶操作時間）降低 67% 至 74%。這說明把記憶控制與組織交給小型專用模型，是兼顧效能與效率的設計。

不過，目前提供的上下文未給出各 Benchmark 的細項分數，也無法得知四個多模態領域的具體類別與難度分佈。Macro-average 雖能反映整體趨勢，但可能掩蓋某些領域進步較大、某些領域進步較小的差異，這是解讀時需要保留的空間。

#### 與現有研究的比較

在 Multi-agent Systems（MAS）領域，既有研究多聚焦於角色對話、工作流編排、多智能體辯論與自適應團隊生成等溝通協調機制。EpiCon 的差異在於把記憶視為一個持久的底層基質（persistent substrate），讓不同智能體的經驗能夠被組織與重複使用，而非僅在單次對話中傳遞。

在 Agent Memory（智能體記憶）方面，早期工作以儲存互動歷史或情節記錄為主，後續發展出萃取、整合、層次化組織與動態連結等方法。然而，大多數語言智能體記憶仍以文本為主。EpiCon 延續了 Multimodal Memory（多模態記憶）的方向，進一步把 Visual Evidence（視覺證據）與 Textual Guidance（文本引導）放在同一個回饋迴路中共同演化，並能選擇性地納入視覺記憶，這對需要參考圖表、文件區域或影像細節的任務尤為重要。

在 Reflection（反思）與 Self-Evolving Agents（自我演化智能體）的研究脈絡中，方法演進大致是「重試 → 反思 → 經驗整合」。EpiCon 把這條軸線再往前推：它不僅在單一問題內透過回饋精煉記憶，也透過 Tree Self-Organizer（樹狀自組織器）把經驗層次化地整合到共享經驗庫，並支援跨問題、跨 Harness、跨 Backbone 的 Reuse（重複使用）。

儘管如此，EpiCon 仍有若干限制。首先，由於不更新 Host Model Parameters（主模型參數），其上限可能受限於骨幹模型本身的推理能力；對於需要深層能力改變的任務，單靠外部記憶可能不足。其次，兩個 2B 模型雖然提升了效率，但其容量可能限制複雜經驗的表徵與組織。此外，樹狀結構的維護成本、回饋品質的依賴、經驗庫規模擴大後的檢索品質與陳舊性（staleness）問題，都是實際部署時需要考量的挑戰。

- 視覺記憶標註與回饋訊號的產生方式。

另外，文中引用出現若干 2025、2026 年的文獻，在當前時間點下屬於未來日期，這可能影響讀者對引用真實性與文獻脈絡的查證。無論如何，若作者群後續能釋出完整實作與模型權重，將大幅提升本研究的可重現性與社群影響力。

#### 未來研究方向

1. **擴展至多模態與多感官輸入**：目前 EpiCon 聚焦於文本與視覺，未來可納入音訊、影片、3D 場景甚至感測器訊號，形成更完整的 Multimodal Memory（多模態記憶）框架。

2. **持續學習與經驗遺忘機制**：經驗庫長期累積後可能出現衝突或過時知識，需要設計選擇性遺忘、更新與衝突消解機制，以支援真正的 Lifelong Learning（終身學習）。

3. **結合外部記憶與參數更新**：在不更新 Host Model Parameters（主模型參數）的前提下，可進一步研究如何把高頻使用的經驗蒸餾（distill）進骨幹模型，或透過低秩適配（LoRA）等輕量方式進行選擇性更新。

4. **跨語言與跨領域遷移**：驗證 Experience Bank（經驗庫）是否能在不同語言、不同任務領域間通用，並發展領域適應（domain adaptation）策略。

5. **動態樹狀結構與檢索最佳化**：Tree Self-Organizer（樹狀自組織器）的結構可能影響檢索品質，未來可探索可學習的樹狀生長、剪枝與語義索引方法。

6. **聯邦式共享記憶與隱私保護**：若多個獨立 MAS 要共享經驗，需考慮資料隱私、對抗樣本污染與聯邦學習（federated learning）機制。

7. **理論分析**：從學習理論角度分析 Collective Agent Learning（集體智能體學習）的收斂性、樣本複雜度與經驗庫規模對效能的影響。

8. **應用於具身智能體（embodied agents）**：將 EpiCon 擴展到機器人、導航與物理互動場景，讓視覺與文本經驗能指導長期行動規劃。

## 論文問答

**Q1：EpiCon 試圖解決多智能體系統中的什麼核心問題？**
A：EpiCon 針對的是不同智能體在執行任務後產生的經驗難以被彼此重複使用與累積的問題。雖然單一智能體可以從過去執行紀錄學習，但跨智能體、跨載具或跨骨幹模型共享這些經驗仍然困難。因此，EpiCon 提出一個共享多模態記憶框架，讓經驗能夠在不更新主模型參數的情況下被持續累積與重複使用。

**Q2：現有的多智能體記憶機制為何不足以支援集體學習？**
A：現有方法大多著重於智能體間的溝通協調或角色分工，對於長期記憶的設計仍偏向文字型互動歷史。這些記憶通常依附於特定智能體或特定框架，缺乏可跨系統共享的持久化經驗庫。此外，它們很少同時處理文本引導與視覺證據的共同演化，也無法根據回饋持續修正多模態記憶。

**Q3：為什麼共享多模態記憶對智能體學習如此重要？**
A：許多複雜任務同時需要語言推理與視覺資訊，例如圖表區域或文件細節往往是解題關鍵。透過共享多模態記憶，不同智能體可以避免重複犯錯，並把成功或失敗的經驗轉化為可執行引導。更重要的是，這種外部記憶機制讓主模型保持凍結，仍能在不同骨幹模型與載具之間轉移知識。

**Q4：EpiCon 的兩個核心模組各自負責什麼功能？**
A：記憶控制器負責在單一問題層級內共同演化文本引導與視覺證據，並根據每次嘗試的回饋決定是否納入視覺記憶。樹狀自組織器則負責跨問題地將累積的經驗以層次化方式整合進持久化經驗庫，並為新問題檢索相關經驗與規則。兩者透過記憶載具協同運作，分別處理短期問題記憶與長期共享經驗。

**Q5：相較於過往的智能體記憶研究，EpiCon 的主要創新在哪裡？**
A：EpiCon 首次將問題層級的多模態記憶演化與持久共享經驗庫連結起來，並透過兩個獨立訓練的 2B 模型實現。它不僅能根據回饋同步修正文字引導與對應圖像區域，還能讓凍結經驗庫在不同載具與骨幹模型之間被重複使用。這種設計突破了傳統記憶僅限於單一系統或單一模態的限制。

**Q6：為什麼 EpiCon 選擇使用兩個獨立訓練的 2B 模型來管理記憶？**
A：將記憶控制與經驗組織分離，可以讓兩個模組各自專精於不同的功能，提升整體效率與可維護性。使用 2B 參數量級的緊湊模型，能顯著降低記憶操作時間，相較於骨幹級記憶模型減少 67% 至 74% 的延遲。同時，獨立訓練確保主模型參數無需更新，讓整個框架更具模組化與可擴展性。

**Q7：EpiCon 在哪些基準測試與設定下進行評估？**
A：論文在十一個基準測試上進行評估，涵蓋四個多模態任務領域，並使用兩個多智能體載具與多種骨幹模型。實驗配置包括不同的主機設定，甚至涵蓋 Codex 搭配 GPT-5.6-Luna 這類組合。這樣廣泛的評估設計能驗證 EpiCon 在不同任務與系統環境下的泛化能力。

**Q8：EpiCon 的主要量化結果有哪些？**
A：在四種主機配置下，EpiCon 相較於無記憶基線可將宏觀平均分數提升 1.7 至 4.9 分。當使用另一個載具累積的經驗庫時，原始系統的宏觀平均分數提升了 2.6 分，顯示跨載具經驗轉移的有效性。此外，記憶操作時間相較於骨幹級記憶模型減少了 67% 至 74%。

**Q9：凍結經驗庫的重複使用實驗說明了什麼？**
A：凍結經驗庫能夠在單次解題嘗試下提升其他系統的表現，這說明累積的經驗具有跨系統的通用性。來自另一個載具的貢獻可讓原始系統的宏觀平均分數提升 2.1 至 3.2 分，證明經驗庫的價值不依賴額外嘗試。這也突顯了 EpiCon 在集體智能體學習中作為共享基礎設施的潛力。

**Q10：EpiCon 可應用於哪些實際場景？**
A：EpiCon 適用於需要多模態推理的智能體團隊，例如文件理解、圖表分析、視覺問答或機器人指令執行。在這些場景中，新加入的智能體可以直接繼承經驗庫中的教訓，減少重複試錯。這對客戶支援、科學文獻分析、教育輔導等需要持續累積領域知識的應用特別有價值。

**Q11：若將 EpiCon 部署為產品，需要考慮哪些工程議題？**
A：首先需要維護一個可擴展的持久化經驗庫，並有效管理文本與視覺資料的儲存與檢索。其次，記憶載具必須能與現有多智能體框架整合，同時控制經驗庫成長所帶來的檢索延遲與噪音累積。最後，由於經驗是跨系統共享的，還需考慮資料隱私、版本控制以及經驗品質的持續監控。

**Q12：EpiCon 可能對智能體學習研究領域帶來什麼影響？**
A：EpiCon 將研究焦點從單一智能體的微調轉向集體外部記憶的建構與共享。它證明小型專用模型即可高效管理複雜的多模態記憶，降低了對大型骨幹模型進行參數更新的依賴。這可能促進跨系統、可重複使用的經驗生態系統，並推動更多關於集體智能體學習的標準化評估。

**Q13：EpiCon 的設計隱含哪些限制？**
A：其表現高度依賴記憶控制器對視覺區域的定位能力，以及樹狀自組織器對經驗層次化整合的品質。經驗庫在長期累積過程中可能混入過時或錯誤的教訓，進而影響後續檢索效果。此外，目前評估主要集中於多模態任務領域，對於其他類型任務或更長期的連續學習仍需更多驗證。

**Q14：在什麼情況下 EpiCon 可能表現不佳？**
A：當回饋訊號稀疏或具有誤導性時，記憶控制器可能無法正確修正文本引導與視覺證據。如果新問題與經驗庫中的歷史案例差異過大，樹狀自組織器可能檢索到不相關的規則。此外，當不同載具的行動空間或輸入輸出格式差異過大時，跨系統經驗轉移的效果可能會下降。

**Q15：未來研究可以如何延伸 EpiCon？**
A：未來可將框架擴展至更多模態，例如音訊、影片或三維感知，並設計線上持續更新與遺忘機制以維持經驗庫品質。結合更強大的稠密檢索技術與跨語言、跨領域轉移學習，也能進一步提升經驗的重用效率。此外，對集體智能體學習的理論分析，以及建立開放式跨機構共享經驗庫，都是值得探索的方向。

## 實務應用指南

### 適用場景

1. **多模態客戶技術支援**  
   客服智能體在處理使用者上傳的產品照片、截圖與文字描述時，可透過 EpiCon 的共享經驗庫累積「常見故障圖像區域」與「對應排查步驟」。不同班次的智能體能重複使用相同記憶，並在多次嘗試後共同演化更精準的視覺證據與文本引導。

2. **工業設備巡檢與維護**  
   巡檢智能體拍攝機台影像並記錄異常。EpiCon 可將「異常影像區域」與「維修指引」一起存入經驗庫，後續不同廠區或不同型號骨幹模型的維護系統都能檢索歷史經驗，縮短診斷時間並降低重複失敗。

3. **醫療影像與病歷輔助決策**  
   在放射科或病理科輔助系統中，智能體可根據影像區域（如病灶位置）與臨床文本指引進行推理。EpiCon 能將成功案例的視覺證據與診斷規則層次化整合，供後續相似病例參考，同時不更新主醫療模型參數。

4. **STEM 教育解題輔導**  
   學生上傳幾何圖、實驗圖表或數學題目時，輔導智能體可利用共享經驗庫中的「圖像標記區域」與「解題策略」。不同學習路徑的智能體能共用錯誤案例與修正指引，形成持續演化的多模態教學記憶。

5. **跨團隊法律與合規文件審查**  
   合規智能體處理合約掃描件、表格與法規條文時，可將「關鍵條款影像區域」與「審查規則」存入經驗庫。不同團隊或不同 MAS 框架可重複使用凍結經驗庫，提升審查一致性並減少重複訓練。

### 實作前置條件

- **資料準備**
  - 歷史多模態執行軌跡：包含問題描述、輸入影像、多次嘗試的輸出、回饋訊號（成功／失敗／人工評分）。
  - 可執行引導與視覺證據的對應標註：例如「應關注的圖像區域」與「建議採取的步驟」。
  - 領域驗證資料：用於評估經驗庫重用後的宏觀平均分數與單一任務表現。

- **運算資源**
  - 主骨幹模型：可選用 GPT-5.6-Luna、Codex 或其他大型多模態模型作為智能體基礎。
  - 兩個獨立 2B 模型：分別用於記憶控制器與樹狀自組織器的訓練與推論。
  - 向量／圖譜儲存：支援多模態嵌入檢索與層次化經驗組織的資料庫。
  - GPU／TPU 推論資源：特別是視覺記憶的編碼與檢索階段。

- **技術與團隊能力**
  - 熟悉多智能體系統（MAS）設計與現有框架（如 LangGraph、AutoGen、CrewAI）。
  - 具備視覺語言模型（VLM）微調與檢索增強生成（RAG）經驗。
  - 領域專家參與：協助驗證經驗庫中的文本引導與視覺證據是否正確且可執行。

### 實作步驟建議

1. **定義記憶單元與任務邊界**  
   明確「問題層級記憶」的內容：問題描述、輸入影像、目標輸出格式、可執行引導與視覺證據。決定哪些回饋訊號會觸發記憶更新。

2. **建立 MAS 執行與回饋收集管線**  
   設計記憶載具（Memory Harness），讓智能體在每次嘗試後回傳結果與回饋。確保回饋能區分「文本指引錯誤」、「視覺證據不足」與「執行步驟失誤」。

3. **訓練記憶控制器（Memory Controller）**  
   使用 2B 模型學習如何根據回饋共同演化文本引導與圖像區域。重點在於讓模型學會「選擇性納入視覺記憶」，避免每次嘗試都強制攜帶影像區域。

4. **建構持久化經驗庫與樹狀自組織器**  
   將跨問題的經驗以樹狀結構層次化整合。設計檢索機制，使新問題能同時取得相似案例與高階規則。經驗庫應獨立於 MAS 與骨幹模型維護。

5. **串接記憶載具與主系統**  
   在智能體執行前檢索經驗庫，執行後將新經驗回寫。確保介面標準化，使不同 MAS 框架都能讀取與貢獻經驗。

6. **凍結經驗庫評估與跨系統遷移**  
   在特定階段凍結經驗庫，評估其對其他骨幹模型或框架的單次嘗試增益。記錄宏觀平均分數變化，確認集體學習效果。

7. **持續監控與增量更新**  
   定期擴充經驗庫，同時監控記憶操作時間與檢索品質。避免經驗庫膨脹導致雜訊增加，必要時進行版本控制與清理。

8. **部署與延遲優化**  
   利用 2B 模型降低記憶操作時間，相較於骨幹級記憶模型可減少 67%–74% 延遲。對延遲敏感場景可採用快取與非同步更新策略。

### 潛在風險與注意事項

- **記憶幻覺與過時指引**  
  經驗庫中的文本引導可能隨環境變化而失效。建議加入版本時間戳與適用條件標籤，並定期由領域專家抽樣審查。

- **視覺證據漂移**  
  圖像區域標記可能因資料分佈改變而不再準確。可透過回饋驅動的精煉機制持續修正，並在檢索時提供原始影像作為上下文。

- **跨智能體資料隱私與權限**  
  共享經驗庫可能暴露敏感執行軌跡。應實作權限控管、去識別化與領域隔離，避免不同客戶或部門的資料混用。

- **回饋品質依賴**  
  若回饋訊號稀疏或偏差，記憶控制器會學到錯誤模式。建議結合自動評估與人工標註，特別在初期建立高品質回饋資料。

- **經驗庫膨脹與檢索雜訊**  
  隨著經驗累積，檢索可能引入不相關內容。可透過樹狀自組織器的層次化整合與相似度門檻過濾來維持檢索精準度。

- **跨骨幹模型遷移落差**  
  凍結經驗庫雖可跨骨幹模型重用，但不同模型的指令遵循能力與視覺理解差異可能影響效果。建議在遷移後進行小規模適應性評估。

### 與其他技術的整合建議

- **RAG 與多模態檢索管線**  
  將 EpiCon 的經驗庫視為多模態 RAG 的知識來源，結合向量資料庫（如 Milvus、Pinecone）與圖譜資料庫（如 Neo4j）實現高效檢索與關聯推理。

- **現有 MAS 框架**  
  透過記憶載具適配器將 EpiCon 掛載到 LangGraph、AutoGen 或 CrewAI，讓既有智能體無需修改骨幹模型即可獲得共享記憶能力。

- **LLM 可觀測性工具**  
  整合追蹤平台（如 LangSmith、Weights & Biases）記錄每次嘗試的記憶檢索、更新與最終結果，便於除錯與效能分析。

- **CI/CD 與記憶庫版本控制**  
  將經驗庫視為模型資產進行版本管理，搭配 A/B 測試評估新版本經驗庫對宏觀平均分數的影響。

- **反思與自我修正模組**  
  EpiCon 可與現有的 reflection、critique 模組協作：反思模組產生回饋，EpiCon 負責將回饋沉澱為可重複使用的多模態記憶。

### 給不同背景讀者的閱讀建議

- **初學者**  
  把 EpiCon 想像成一本「會自己進化的共享筆記本」：裡面同時保存文字提示與圖片標記，不同智能體做完任務後把心得寫進去，下次遇到類似問題就能翻閱。重點理解「不修改主模型參數」與「跨系統共享經驗」這兩個核心價值。

- **AI 工程師**  
  請聚焦記憶載具的介面設計、兩個 2B 模型的訓練資料格式、視覺記憶的選擇性納入邏輯，以及經驗庫的檢索與更新管線。實作時優先確保回饋訊號的品質與延遲優化，再逐步擴展到多骨幹模型部署。

- **研究人員**  
  值得深入探討的問題包括：文本引導與視覺證據的共同演化機制、樹狀自組織器的層次化整合策略、凍結經驗庫跨框架泛化的理論條件，以及如何在更大規模或更長期的互動中維持記憶一致性。

- **產品經理**  
  優先評估哪些多模態任務領域最適合導入 EpiCon，並規劃分階段上線：先從單一團隊的單一任務建立經驗庫，驗證單次嘗試增益後，再推展到跨團隊共享。同時預留資料治理、隱私合規與人工審核的資源。
