## ⚡ TL;DR

現有自動化多智能體系統僅部分自適應，因凍結執行者而遭遇瓶頸，端到端聯合訓練亦未受探索。
提出MetaAgent-X，以端到端強化學習聯合優化設計與執行，並以分層展開和階段式共演化穩定訓練。
實驗顯示MetaAgent-X最高提升21.7%，且消融證實設計者與執行者於階段式共演化中持續進步。

## 摘要翻譯

自動化多智能體系統（Automatic Multi-Agent Systems, Automatic MAS）旨在無需依賴人工設計或固定編排（Fixed Orchestration）即可實例化智能體工作流程（Agent Workflows）。然而，現有的自動化多智能體系統方法仍僅為部分自適應（Partially Adaptive）：這些方法或者進行免訓練（Training-Free）的測試時搜尋（Test-Time Search），或者在最佳化元層級設計者（Meta-Level Designer）的同時凍結下游執行智能體（Downstream Execution Agents），從而形成凍結執行者上限（Frozen-Executor Ceiling），並使自我設計與自我執行之智能體模型（Self-Designing and Self-Executing Agentic Models）的端到端訓練仍處於未被探索的狀態。為了解決此問題，我們提出 MetaAgent-X，一個端到端強化學習（End-to-End Reinforcement Learning）框架，聯合最佳化（Jointly Optimizes）自動化多智能體系統的設計與執行。MetaAgent-X 實現基於腳本的多智能體系統生成（Script-Based MAS Generation）、執行展開收集（Execution Rollout Collection），以及對設計者軌跡（Designer Trajectories）與執行者軌跡（Executor Trajectories）的信用分配（Credit Assignment）。為了實現穩定且可擴展的最佳化（Scalable Optimization），我們提出執行者-設計者分層展開（Executor Designer Hierarchical Rollout）與階段式共同演化（Stagewise Co-Evolution），以提升訓練穩定性（Training Stability）並揭示設計者-執行者共同演化（Designer-Executor Co-Evolution）的動態。MetaAgent-X 持續優於現有的自動化多智能體系統基線方法（Baselines），實現高達 21.7% 的提升。全面的消融研究（Ablations）顯示，設計者與執行者在整個訓練過程中皆持續改善，且有效的自動化多智能體系統學習遵循階段式共同演化過程。這些結果確立了端到端可訓練（End-to-End Trainable）的自動化多智能體系統，作為建構自我設計與自我執行之智能體模型（Agentic Models）的實用典範。

### 核心貢獻（3～5點）
- 提出 MetaAgent-X，首個端到端強化學習框架，聯合最佳化自動化多智能體系統的設計與執行，打破現有方法的凍結執行者上限。
- 建立完整的端到端訓練機制，涵蓋基於腳本的多智能體系統生成、執行展開收集，以及針對設計者與執行者軌跡的信用分配。
- 提出執行者-設計者分層展開與階段式共同演化策略，顯著提升訓練穩定性並揭示設計者與執行者在訓練過程中的共同演化動態。
- 在標準基準上相較現有自動化多智能體基線方法實現高達 21.7% 的效能提升，並透過消融研究驗證設計者與執行者確實在訓練中同步改善。
- 確立端到端可訓練的自動化多智能體系統作為實用典範，為建構自我設計與自我執行的智能體模型提供可擴展的最佳化路徑。

### 適合對象
從事多智能體系統、強化學習、大型語言模型智能體應用，以及自動化機器學習（AutoML）相關研究的研究人員與工程師；特別適合關注如何透過端到端訓練自動設計與動態編排智能體工作流程，並尋求突破傳統固定編排瓶頸的進階讀者。

## 深度分析

#### 方法論解析

MetaAgent-X 的核心貢獻在於建立一個真正 End-to-End Trainable（端到端可訓練）的 Automatic MAS（自動化多智能體系統）學習範式。現有方法受限於 Frozen-Executor Ceiling（凍結執行者上限），即僅透過 Test-Time Search（測試時搜尋）或單獨最佳化 Meta-Level Designer（元層級設計者），卻將 Downstream Execution Agents（下游執行智能體）的參數固定，導致設計與執行之間僅存在提示層級的互動，而缺乏參數層級的梯度連結。MetaAgent-X 透過三項設計原則解決此問題。

首先，框架採用 Script-Based MAS Generation（基於腳本的多智能體系統生成），使 Designer（設計者）能針對輸入任務產生可執行的 MAS 腳本，而非僅輸出靜態的 Agent Workflows（智能體工作流程）描述。這些腳本被具現化後由 Executor（執行者）在環境中運行，系統同時進行 Execution Rollout Collection（執行展開收集），記錄 Designer Trajectories（設計者軌跡）與 Executor Trajectories（執行者軌跡），為後續的 Credit Assignment（信用分配）提供結構化資料。

其次，為了處理 Designer 與 Executor 之間複雜的互動結構，作者提出 Executor Designer Hierarchical Rollout（執行者-設計者分層展開）。此機制將互動過程組織為兩層樹狀結構：上層為設計決策（決定角色、溝通模式與執行流程），下層為依據該設計所產生的執行軌跡。這種分層結構不僅提升了 Rollout（展開）的生成效率，更關鍵的是實現了準確的 Credit Assignment（信用分配）——當最終任務獲得獎勵時，系統能夠區分該歸因於設計者的結構設計，還是執行者的操作決策，從而避免梯度訊號的混淆。

第三，針對端到端訓練固有的不穩定性，作者提出 Stagewise Co-Evolution（階段式共同演化）。此策略將 Designer 與 Executor 的學習階段解耦，避免兩者在訓練初期同時更新導致的策略崩潰。透過分階段的學習排程，系統先讓其中一方建立基礎能力，再逐步引入另一方的聯合更新，最終達成穩定的 Designer-Executor Co-Evolution（設計者-執行者共同演化）。這不僅改善了 Training Stability（訓練穩定性），也讓 Scalable Optimization（可擴展最佳化）成為可能，使框架能夠跨任務與領域進行靈活的最佳化。

整體而言，MetaAgent-X 的訓練循環可概括為：任務條件化的自動 MAS 設計 → 腳本具現化與執行 → 分層展開收集 → 角色感知的策略更新。這一流程使 Self-Designing and Self-Executing Agentic Models（自我設計與自我執行的智能體模型）首次在參數層級上實現 Jointly Optimizes（聯合最佳化）。

#### 實驗數據解讀

論文在六個數學與程式碼基準測試以及兩種不同的基底模型上進行評估。儘管文中未詳細列出所有基準名稱，但從領域分佈可推斷其涵蓋了需要多步推理的數學問題與軟體工程任務，這兩類任務恰好能凸顯 Multi-Agent Systems（多智能體系統）相較於 Single-Agent Approaches（單智能體方法）的優勢。

主要結果顯示，MetaAgent-X 相較於現有 Automatic MAS（自動化多智能體系統）Baselines（基線方法）取得最高達 21.7% 的效能提升。這一增益具有重要意義：它不僅是量的提升，更證明了打破 Frozen-Executor Ceiling（凍結執行者上限）後，系統能夠學習到更適配的執行策略。在 Partially Adaptive（部分自適應）方法中，即使 Meta-Level Designer（元層級設計者）產出理論上更優的工作流程，固定的 Downstream Execution Agents（下游執行智能體）仍會因為缺乏針對該設計的特化能力而表現受限。MetaAgent-X 的端到端訓練使 Executor 能夠配合 Designer 的輸出進行微調，從而釋放設計的潛在價值。

Ablations（消融研究）進一步揭示了訓練過程的內部動態。實驗顯示，Designer 與 Executor 在整個訓練過程中持續改善，而非僅有單方獲益。更重要的是，有效的自動 MAS 學習遵循一個 Stagewise Co-Evolution（階段式共同演化）過程：兩個元件並非從頭到尾以相同步調同步更新，而是在不同階段各自受益於解耦的最佳化。這暗示了在複雜的 Agentic Models（智能體模型）中，強制同步的端到端訓練可能導致次優收斂，而適度的階段性解耦反而能引導系統走向更穩定的共同演化軌跡。

從實務角度觀察，21.7% 的增益跨越多個基準與模型，顯示此範式具備良好的泛化性。這也意味著未來在建構 Adaptive Orchestration（自適應編排）系統時，Fixed Orchestration（固定編排）或僅優化設計者的半訓練方案將不再是效能上限。

#### 與現有研究的比較

現有自動化多智能體系統研究主要落入兩種 Partially Adaptive（部分自適應）範疇。第一類為 Training-Free（免訓練）的 Test-Time Search（測試時搜尋），例如透過提示搜尋、角色組合或 Agent Workflows（智能體工作流程）探索來適應任務，但不更新任何模型參數。這類方法雖具彈性，卻受限於預訓練知識，無法產生超越基礎模型分佈的新能力。第二類為 Semi-Trainable Adaptation（半可訓練適應），如 MAS-GPT、FlowReasoner 等，它們最佳化 Meta-Level Designer（元層級設計者）或控制器，但保持 Downstream Execution Agents（下游執行智能體）凍結。這正是 Frozen-Executor Ceiling（凍結執行者上限）的來源：設計者與執行者之間僅存在提示層級的耦合，缺乏基於執行結果的參數層級回饋。

MetaAgent-X 的範式轉移在於提出第一個真正 End-to-End Trainable（端到端可訓練）的自動 MAS 框架。透過 Jointly Optimizes（聯合最佳化）設計與執行，它解決了 Parameter-Level Disjunction（參數層級分離）問題：Designer 的更新能夠直接基於 Executor 在環境中獲得的回饋，而 Executor 也能針對 Designer 產生的特定工作流程發展出專門化的執行行為。這種雙向適應是過往方法無法達成的。

相較於現有基線，MetaAgent-X 的優勢可歸納為三點：（1）參數層級的聯合最佳化使設計決策與執行策略共同演化；（2）Executor Designer Hierarchical Rollout（執行者-設計者分層展開）提供了結構化的 Credit Assignment（信用分配），解決了多層次決策中的歸因難題；（3）Stagewise Co-Evolution（階段式共同演化）確保了端到端訓練的穩定性，使 Large Language Models（LLMs）（大型語言模型）作為基底時仍能穩定收斂。

然而，此框架亦存在可預見的限制。首先，End-to-End Reinforcement Learning（端到端強化學習）的訓練成本顯著高於 Training-Free（免訓練）或僅訓練單一模組的方法。其次，Script-Based MAS Generation（基於腳本的多智能體系統生成）雖然提升了可執行性與訓練穩定性，但可能在表達複雜拓撲（如動態圖結構或遞迴式 Meta-Agents（元智能體）組織）時不如完全自由形式的生成靈活。此外，目前評估集中於數學與程式碼領域，其在醫療決策、科學發現或金融交易等需要高風險決策的領域中的穩定性仍有待驗證。

#### 可重現性評估

從論文標頭處的「§Code | HF Model」標註可推斷，作者團隊已釋出原始碼與 HuggingFace 模型權重，這對於可重現性（reproducibility）是極為正面的訊號。釋出模型權重使其他研究者能夠直接驗證其在六個基準測試上的效能表現，而開源程式碼則有助於理解 Executor Designer Hierarchical Rollout（執行者-設計者分層展開）與 Stagewise Co-Evolution（階段式共同演化）的實作細節。

不過，由於目前提供的上下文未包含完整的實驗設定附錄，部分重現細節仍有不確定性。例如，基底模型的確切版本（如 7B、13B 或 70B 等級）、RL 訓練的樣本複雜度（sample complexity）、以及六個基準測試的完整清單與資料前處理流程，皆會影響重現難度。此外，End-to-End Reinforcement Learning（端到端強化學習）框架通常需要大量的運算資源（如多卡 GPU 叢集與長時間的 Rollout（展開）收集），這對於資源有限的學術實驗室構成實務上的重現門檻。

若作者已提供完整的訓練腳本、超參數設定與環境配置檔，則此研究應屬於高可重現性等級。建議後續釋出包含訓練日誌與 Ablations（消融研究）的詳細數據，以便社群驗證 Stagewise Co-Evolution（階段式共同演化）的各階段收斂行為。

#### 未來研究方向

MetaAgent-X 為自動化多智能體系統開啟了端到端訓練的大門，後續研究可沿多個軸線展開。

在方法論層面，目前的 Script-Based MAS Generation（基於腳本的多智能體系統生成）可擴展至更豐富的結構表達，例如動態圖（dynamic graphs）或遞迴式 Meta-Agents（元智能體）組織，使 Designer 能夠產生非固定深度的多層次系統。此外，現階段的 Stagewise Co-Evolution（階段式共同演化）採用階段性解耦策略，未來可探索更細緻的自適應切換機制，讓系統根據訓練損失或策略熵（policy entropy）自動決定 Designer 與 Executor 的更新時機，從而走向完全自適應的共同演化。

在應用層面，論文引言提及醫療決策、科學發現、金融交易與硬體設計等領域皆已展現 Multi-Agent Systems（多智能體系統）的價值。將 MetaAgent-X 的端到端訓練範式遷移至這些高風險、高專業領域，將是驗證其通用性的關鍵下一步。特別是在醫療與金融場景中，執行者的決策必須具備可解釋性與安全性，因此需要結合人類回饋強化學習（RLHF）或憲法式 AI（Constitutional AI）等對齊技術。

在理論層面，Designer-Executor Co-Evolution（設計者-執行者共同演化）的動態尚未被形式化理解。未來可建立賽局理論（game-theoretic）或最佳控制（optimal control）模型，分析兩者在聯合訓練下的收斂條件與納許均衡（Nash equilibrium）特性。同時，樣本效率（sample efficiency）仍是瓶頸：LLM-based Agentic Models（智能體模型）的每次 Rollout（展開）成本高昂，發展基於模型（model-based）的強化學習方法或離線策略（off-policy）修正技術，將有助於降低訓練資源需求。

最後，隨著 Self-Designing and Self-Executing Agentic Models（自我設計與自我執行的智能體模型）能力的增強，其安全性與可控性問題將日益凸顯。未來研究必須正視自動設計系統可能產生的未預期行為（emergent behaviors），並建立相應的監管與安全評估框架，確保 End-to-End Trainable（端到端可訓練）自動 MAS 的發展與人類價值對齊。

## 論文問答

**Q1：現有的自動化多智能體系統（Automatic MAS）面臨哪些根本性的限制，使得它們無法真正實現端到端的自我設計與自我執行？**
A：現有的自動化多智能體系統主要受限於「部分自適應」的設計範式，這些方法要麼僅在測試時進行免訓練的搜尋，要麼只優化元層級設計者卻凍結下游執行智能體，導致系統無法從執行結果中獲得反饋以更新底層策略。這種分離造成了參數層級的斷裂，使得設計者與執行者之間僅能透過提示層級互動，而無法基於下游執行成果進行聯合最佳化。因此，現有方法存在所謂的「凍結執行者上限」，嚴重限制了自動化多智能體系統的整體效能與適應能力。

**Q2：為什麼單純優化設計者而凍結執行者的做法會形成瓶頸，這種「凍結執行者上限」對系統表現有何具體影響？**
A：當執行智能體被凍結時，元層級設計者即使設計出更複雜或更精細的多智能體工作流程，下游執行者也無法發展出與之配合的專門化行為，導致設計與執行之間出現嚴重的策略錯配。這種參數層級的斷裂意味著設計者無法透過強化學習的信號來誘導執行者調整其決策策略，從而使得整體系統的表現被凍結的執行能力硬性限制住。此外，由於缺乏端到端的梯度傳播與信用分配，設計者難以判斷哪些設計決策真正導致了最終任務的成功或失敗，進一步阻礙了系統的協同演化。

**Q3：推動端到端可訓練的自動化多智能體系統為何對智能體模型的未來發展至關重要？**
A：端到端可訓練的自動化多智能體系統代表了從「人工設計工作流程」邁向「自我設計與自我執行的智能體模型」的關鍵典範轉移，這使模型能夠針對不同任務與領域動態調整其編排與執行策略。這種能力不僅能大幅提升模型在數學推理、程式編寫等複雜任務上的表現，還能減少對人類專家手動設計工作流程的依賴，從而實現更具規模化與通用性的智能體應用。更重要的是，理解設計者與執行者在聯合訓練中的共同演化動態，有助於開啟新一代能夠持續自我改進的自主智能體系統的研究方向。

**Q4：MetaAgent-X 的核心框架如何實現設計者與執行者的聯合最佳化，其主要訓練流程包含哪些關鍵步驟？**

## 實務應用指南

1. **複雜軟體工程與自動化維運**：在大型程式碼庫的開發、審查與除錯流程中，MetaAgent-X 可依據任務特性自動生成並執行多智能體協作流程（如規格分析、程式碼生成、測試與重構），突破傳統固定編排無法適應不同技術債或架構的瓶頸。
2. **動態金融風險分析與量化交易**：針對市場情境快速變化的交易與風控任務，系統可透過端到端強化學習自動設計資料收集、特徵工程、策略模擬與風險校正的智能體工作流程，並讓執行智能體隨設計者同步演化，提升對黑天鵝事件的反應能力。
3. **跨領域科學研究加速**：在藥物發現或材料科學中，MetaAgent-X 能自動編排文獻回顧、假設生成、實驗設計與結果分析的 MAS 流程。設計者與執行者的共同演化使系統能根據中期實驗回饋調整研究路徑，避免凍結執行者上限導致的探索僵化。
4. **企業級客戶服務與跨部門流程自動化**：面對申訴處理、供應鏈協調等需要多角色互動的業務，框架可自動實例化具備自適應編排能力的智能體工作流程，並依據實際對話與業務結果持續優化各角色的分工與溝通協議。
5. **個人化教育與適性學習系統**：依據學習者的即時表現，自動設計並執行由出題、提示、評量與回饋智能體組成的動態流程，透過階段式共同演化讓教學策略與內容生成能力同步精進。

### 實作前置條件

**資料層面**：需要具備明確獎勵訊號的任務資料集（如數學推理題組、程式碼測試案例、或帶有最終標註的領域任務），以及可供執行智能體互動的環境介面（如程式執行沙盒、交易模擬器或科學計算環境）。此外，需預先建立設計者輸出的腳本格式規範（如 JSON / DSL），以支援基於腳本的多智能體系統生成與後續解析。

**運算層面**：由於需進行大規模展開收集與端到端策略梯度更新，建議至少具備數十張高端 GPU（如 A100 / H100）的叢集，並搭配分散式 RL 訓練框架（如 Ray、OpenRLHF 或自研框架）。執行者-設計者分層展開會產生大量中間軌跡，需充足的記憶體與高速儲存以緩存設計者軌跡與執行者軌跡。

**技術與人才層面**：團隊需熟悉大型語言模型的微調與推理優化、強化學習中的信用分配機制（如 PPO、GRPO 或 REINFORCE 變體），以及多智能體系統的編排邏輯。具備分散式系統調校與獎勵工程（Reward Engineering）經驗的工程師尤為關鍵，因為聯合最佳化設計者與執行者時，訓練穩定性對超參數極度敏感。

### 實作步驟建議

1. **基礎環境與模型選型**：選定底層大型語言模型（如 Llama、Qwen 或 GPT 架構的開源版本），並建置支援腳本化 MAS 生成的執行環境（如 Docker 化的 Python 沙盒或特定領域 API）。確保環境能同時記錄設計者輸出的結構化腳本與執行者的環境互動日誌。
2. **定義設計者與執行者的動作空間**：將設計者的輸出定義為可解析的腳本（包含角色數量、系統提示、溝通拓撲與終止條件），執行者則依據腳本實例化為具體智能體。明確劃分兩者的觀察空間與動作邊界，是後續信用分配的前提。
3. **建置執行者-設計者分層展開管線**：實作兩層式樹狀展開結構——上層為設計者生成腳本的軌跡，下層為依腳本實例化後的執行者與環境互動軌跡。確保每個終端獎勵能透過分層結構回溯至對應的設計者決策與執行者動作。
4. **導入階段式共同演化訓練**：初期可先固定設計者、預訓練執行者以建立基礎互動模式；中期釋放設計者進行輕度聯合更新；後期進行完全的端到端可訓練聯合最佳化。此策略能避免初期訓練不穩定導致的模式崩潰。
5. **設計信用分配與獎勵歸因機制**：針對設計者軌跡，採用腳本層級的稀疏獎勵（如最終任務成功率）；針對執行者軌跡，則可結合密集獎勵（如中間步驟正確性）。使用重要性採樣或分層策略梯度，確保獎勵訊號能有效歸因至兩個層級。
6. **執行端到端 RL 訓練與監控**：啟動分散式訓練，持續監控設計者輸出腳本的語法有效性、執行者的任務完成率，以及兩者策略熵的變化。若發現設計者傾向產生無效腳本或執行者出現模式崩潰，應回調至上一階段並調整獎勵係數。
7. **評估、消融與產品化部署**：在內部驗證集上進行消融研究，確認設計者與執行者確實產生正向共同演化而非單方面過擬合。通過驗證後，將訓練完成的模型以 API 或微服務形式部署，並保留人機協同介面供高風險決策覆核。

### 潛在風險與注意事項

- **訓練不穩定與模式崩潰**：端到端聯合最佳化設計者與執行者時，任一方的策略劇烈變動都可能導致另一方梯度失效。強烈建議採用本文提出的階段式共同演化，並搭配學習率排程與梯度裁剪，避免雙方策略空間同時劇變。
- **獎勵竊取與信用分配模糊**：若設計者學會生成取巧腳本（如讓執行者重複輸出答案直到通過），或執行者將成功歸因於運氣而非設計，將導致虛假的共同演化。應設計細緻的獎勵塑形（Reward Shaping）與腳本合法性檢查，並定期以凍結執行者的基線方法驗證設計者品質。
- **運算成本與延遲爆炸**：執行展開收集涉及多輪智能體互動，相較單智能體方法或測試時搜尋，訓練階段的 token 消耗與 wall-clock time 可能高出數倍。建議先在小規模任務上驗證收斂性，再擴展至完整領域，並善用推論加速與軌跡快取。
- **安全與對齊風險**：自我設計與自我執行的特性意味著系統可能自動生成未預期的智能體互動模式（如資訊洩漏、角色衝突或有害內容循環放大）。部署前必須建立沙盒隔離、輸出過濾與緊急終止機制，並將人類反饋納入獎勵模型。
- **泛化能力過度樂觀**：論文雖在數學與程式碼基準上驗證，但遷移至開放式領域（如醫療或法律）時，固定編排的基線可能因領域知識嵌入而仍具優勢。建議採用混合式架構，保留領域專家設計的關鍵檢查點作為執行者的約束條件。

### 與其他技術的整合建議

- **現有 LLM 編排框架（如 AutoGen、AG2、LangGraph）**：可將 MetaAgent-X 訓練出的設計者視為「動態編排層」，輸出腳本給這些框架的執行引擎。這種分層整合能保留現有框架的工具呼叫、記憶體管理與除錯工具，同時注入端到端可訓練的自適應編排能力。
- **傳統固定編排與規則引擎**：在高度監管或高風險場景，不建議完全取代固定編排。可採用「設計者建議 + 規則引擎審查」的混合模式：由 MetaAgent-X 生成智能體工作流程草案，再經由規則引擎檢查合規性後執行，兼顧彈性與安全。
- **可觀測性與 MLOps 平台**：由於設計者-執行者共同演化的動態複雜，必須整合追蹤系統（如 LangSmith、Weights & Biases 或自研軌跡視覺化工具），以監控每個訓練步驟中腳本結構的變化、執行者的中間步驟獎勵，以及整體訓練穩定性指標。
- **人機協同（Human-in-the-Loop）介面**：在產品化階段，建議為設計者輸出的腳本建立視覺化編輯與覆核介面。當系統自動設計出非預期流程時，領域專家可即時介入修正，並將修正後的軌跡以離線強化學習或偏好學習方式回注模型，形成持續改進的閉環。

### 給不同背景讀者的閱讀建議

**初學者**：建議先從本文的圖一與摘要著手，理解「凍結執行者上限」這一核心問題——為何只優化設計者而讓執行者固定會限制整體表現。接著對照日常生活中「球隊教練（設計者）與球員（執行者）必須一起進步」的類比，建立對端到端訓練的直覺。技術細節如執行者-設計者分層展開與信用分配可暫時略過，重點掌握階段式共同演化的概念即可。

**AI 工程師**：請聚焦於方法論與實驗設定，特別是腳本化 MAS 生成的實作細節、分層展開的資料流設計，以及階段式共同演化的訓練管線配置。建議將本文視為一份系統設計參考書，對照你目前使用的 RLHF / DPO 管線，思考如何將「設計者策略」也納入策略梯度更新。消融研究中關於訓練穩定性的觀察，對你調校學習率與獎勵係數會有直接幫助。

**研究人員**：本文的核心貢獻在於提出端到端可訓練的自動化多智能體系統範式。建議深入分析設計者-執行者共同演化的動態機制，並思考信用分配理論在此雙層決策結構中的擴展性。未來工作可探索更複雜的獎勵塑形、將框架擴展至部分可觀察環境（POMDP），或結合世界模型（World Model）進行基於模型的規劃型元智能體學習。此外，安全對齊與可解釋性在自我設計系統中的理論保證仍待建立。

**產品經理**：請將閱讀重點放在適用場景與效能增益數據（21.7% 的提升）。理解 MetaAgent-X 並非取代現有單智能體或固定編排方案，而是在「任務變異度高、需要動態分工」的場景創造差異化價值。評估導入時，請優先盤點團隊是否具備足夠的運算資源與 RL 調校能力，並規劃「固定編排為主、自動編排為輔」的漸進式導入路徑，以降低上線風險與用戶預期管理的成本。
