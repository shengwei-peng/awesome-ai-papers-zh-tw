Jeveration 的核心方法論在於將「決策模型」(decision model) 的範式從離散選項推廣到「空間結構化的高維輸出」——也就是影像。其理論基礎建立在 System One models（系統一模型）之上，這類模型（如 Jev）能在單次前向傳遞（forward pass）中平行回傳多個具型別的決策（typed decisions），例如 Choices、Scores 或 Bounding Boxes。Jeveration 的關鍵洞察是：既然 Jev 能在單次平行查詢中對 2,048 個候選項目做出決策，那麼理論上也能在單次前向傳遞中為影像的每一個碼位置（code position）從碼本（codebook）中選出一個離散影像碼（discrete image code），從而構成一張完整的影像。

然而，這個直觀的構想面臨兩個根本性挑戰。第一個挑戰是**全域一致性**（global consistency）：一個文字提示（prompt）對應著許多合理的影像，但平行預測（parallel prediction）若各自獨立進行，不同位置的碼可能對應著互不相容的影像實現，導致局部區域無法拼合成一張連貫的影像。論文中 Fig. 2 清楚展示了這個失敗模式——直接從第一階段模型獨立取樣的碼無法拼合成合理的影像。第二個挑戰是**任務統一性**：要將此方法擴展到多樣的影像生成任務，需要一個能容納不同輸入與條件化需求的統一架構。

針對第一個挑戰，Jeveration 引入了一個**共享隨機狀態**（shared random state）來協調所有位置的平行預測。這個隨機狀態作為一個全域信號被注入到每個位置的決策中，使得同一個提示下的不同隨機狀態能產生「不同但一致」的影像。然而，僅僅引入隨機狀態並不夠——若模型僅以目標影像進行監督訓練，它傾向於忽略這個隨機狀態，因為模型可以從訓練資料中學到平均的影像分佈。為了解決這個問題，Jeveration 採用了一個**兩階段訓練策略**：

1. **第一階段**：訓練模型學習影像在離散碼空間中的分佈（即學習一個遮罩式碼預測模型，類似 MaskGIT 的訓練目標）。這個階段讓模型真正學會影像的條件機率分佈 $p(\text{code}_i | \text{context}, \text{masked codes})$。
2. **第二階段**：利用第一階段學到的影像分佈作為「教師」，來評判和引導單次前向傳遞中的平行碼選擇。具體而言，Jeveration 採用了類似 Di[M]O 的方法，將第一階段模型的 token-level conditionals 作為目標，並輔以信心引導的修正目標（confidence-guided correction target）來進一步引導平行碼選擇。

這個兩階段設計的精妙之處在於：第一階段確保了模型理解了影像的內在結構與一致性約束，第二階段則將這些知識蒸餾到一個單次前向傳遞的決策模型中，使得模型在推理時能夠在保持一致性的同時，利用共享隨機狀態產生多樣化的結果。

在**架構設計**上，Jeveration 以 Qwen3.5-4B 視覺語言模型（VLM）為基礎，該模型保持凍結（frozen），僅添加 LoRA 適配器（adapters）和任務特定的輸出頭（output heads）。每個輸出——無論是影像還是稠密預測圖——都是一次具型別的決策，在單次前向傳遞中完成。對於分割任務，每個位置輸出一個類別 Choice；對於深度和表面法向量估計，則輸出 Scores。這種設計使得一個模型權重檔（checkpoint）能同時覆蓋文字生成影像、影像生成影像和稠密預測三種任務。

#### 與現有研究的比較

Jeveration 在統一多模態模型（unified multimodal models）的譜系中佔據了一個獨特的位置。現有的統一模型大致可以分為以下幾類：

1. **自回歸統一模型**（如 Chameleon、Emu3、Janus/Janus-Pro、Unified-IO 2）：這些模型以自回歸方式逐符元（token-by-token）生成影像，雖然品質不錯，但需要大量的序列取樣步驟，導致推論延遲較高。Jeveration 的 122 倍加速正是相對於 Janus-Pro-7B 而言的。

2. **遮罩預測統一模型**（如 Show-o）：使用遮罩預測（masked prediction）的方式，但仍需要多輪取樣。

3. **連續潛變數統一模型**（如 Transfusion、BAGEL）：建模連續影像潛變數（continuous image latents），通常結合擴散過程。

4. **混合架構**（如 MetaQueries、BLIP3-o）：將理解表徵連接到獨立的擴散生成器。

Jeveration 與上述所有方法的核心區別在於：**它完全消除了序列取樣**，將影像生成視為一次聯合決策（joint decision）。這與一步生成（one-step generation）的研究路線（如 Consistency models、Mean-Flow、DMD/DMD2、SANA-Sprint、TwinFlow）有共通之處，但 Jeveration 是在離散碼空間中運作，並且是基於一個凍結的視覺語言模型。

在**稠密預測**方面，Jeveration 與 LENS（在凍結多模態模型上添加分割能力）和 DenseMLLM（以視覺符元監督稠密預測）有相似之處，但 Jeveration 將稠密預測統一到與影像生成相同的平行決策框架中，這是一個更為根本性的統一。

### 實作步驟建議

**步驟一：準備離散影像 tokenizer**
採用或自訓 VQ-VAE / VQGAN，將所有訓練影像編碼為離散碼序列；確保碼本大小與影像解析度（512×512）匹配，並驗證解碼重建品質（建議 PSNR > 28、LPIPS < 0.1）。

**步驟二：訓練第一階段遮罩碼模型**
在凍結的 Qwen3.5-4B 上加入 LoRA 與輸出頭，學習影像碼的分佈。採用類似 MaskGIT 的遮罩預訓練策略：隨機遮蓋部分碼位置，讓模型預測被遮蓋的碼。此模型將作為後續階段的「教師」提供條件分佈。

**步驟三：訓練 Jeveration 主模型**
- 為每張影像生成一個共享隨機狀態（random state），作為所有位置的條件輸入。
- 採用「信心引導修正目標」（confidence-guided correction target）讓模型學會利用此隨機狀態產生多樣且一致的影像。
- 同步訓練三類任務頭：文字生成影像、影像生成影像、稠密預測（語意分割 / 深度 / 法向量）。

**步驟四：多任務聯合微調**
以多任務損失加權方式聯合訓練三類任務，確保單一權重檔同時支援所有輸出；建議任務權重依資料量與難度調整，並監控各任務驗證指標避免任務間互相干擾。

**步驟五：推論優化與部署**
- 使用 vLLM 或 TensorRT-LLM 加速 VLM 主體推論。
- 將 LoRA 權重合併回主模型以減少推論時的額外開銷。
- 評估 FP16 / INT8 量化對影像品質的影響，於品質與速度間取得平衡。
- 封裝為 REST API 或 ONNX / TensorRT 引擎供前端呼叫。

**步驟六：建立評估管線**
整合 GenEval、T2I-CompBench 等基準測試，以及語意分割 mIoU、深度 AbsRel 等稠密預測指標，建立自動化回歸測試，確保後續迭代不致退化。

### 潛在風險與注意事項

**風險一：模型忽略共享隨機狀態**
若直接以目標影像監督訓練，模型容易學到「忽略隨機狀態、輸出平均影像」的捷徑，導致多樣性與一致性皆受影響。
**緩解**：嚴格遵循論文的兩階段訓練流程——先學影像分佈，再用其條件分佈引導單次決策；切勿跳過第一階段。

**風險二：全域一致性不足**
平行預測的本質風險是各位置獨立決策可能產生不協調的局部紋理。
**緩解**：保留信心引導修正機制，並在推論時可選擇性加入輕量後處理（如一致性檢查或單輪精修）。

**風險三：離散碼本品質上限**
最終影像品質受 tokenizer 重建能力限制，若碼本太小或訓練不足，會出現明顯量化瑕疵。
**緩解**：選用具備高保真重建的 tokenizer，或在最終輸出後串接一個輕量超解析度模組。

**風險四：解析度與任務彈性受限**
目前展示於 512×512，更高解析度需重新訓練 tokenizer 與輸出頭；稠密預測任務類型受限於訓練資料。
**緩解**：規劃階段性擴充計畫，先在 512×512 驗證流程，再逐步擴展至 1024×1024 與更多任務。

**風險五：公平性與偏誤**
繼承自 VLM 預訓練資料的偏誤（性別、種族、文化刻板印象）會直接反映在生成結果。
**緩解**：建立偏誤審核清單，於部署前以紅隊測試資料集驗證，並準備內容過濾機制。

**風險六：單卡推論的批次效率**
雖然單張延遲極低，但若需批次生成大量影像，仍須評估 GPU 記憶體與吞吐量。
**緩解**：採用連續批次（continuous batching）與動態 padding 提升 GPU 使用率。

### 與其他技術的整合建議

**與擴散模型互補**
Jeveration 適合作為「快速預覽生成器」，先用其產生構圖草稿，再交由 Stable Diffusion 3、FLUX 等高品質擴散模型做細部精修；可在產品中提供「快速模式 / 高品質模式」雙選項。

**與 ControlNet / IP-Adapter 整合**
Jeveration 本身已支援邊緣、深度、灰階等視覺條件，可進一步整合 ControlNet 的姿態、線稿控制，或 IP-Adapter 的風格參考，擴展可控生成能力。

**與既有 VLM 系統整合**
由於主體是凍結的 Qwen3.5-4B，可直接複用企業既有的 VLM 推論服務、監控與安全審核管線，僅需新增 LoRA 與任務頭的載入機制。

**與邊緣推論框架整合**
可將模型轉為 ONNX 或 CoreML 格式，部署至行動裝置；搭配 Apple Neural Engine 或 Qualcomm AI Engine，預期可在手機上達成次秒級生成。

**與 MLOps 平台整合**
將訓練流程接入 MLflow / Weights & Biases，記錄各任務的 GenEval、mIoU、AbsRel 等指標；推論服務接入 Kubernetes 自動擴縮，根據 QPS 動態調整 GPU 資源。

**與內容審核系統整合**
在生成結果回傳前端前，串接 NSFW 過濾、版權偵測、品牌安全審核等模組，確保輸出符合企業內容政策。
