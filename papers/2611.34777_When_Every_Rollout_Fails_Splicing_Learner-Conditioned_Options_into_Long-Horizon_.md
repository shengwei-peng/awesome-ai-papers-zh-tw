## ⚡ TL;DR

長時程代理任務中，群組式強化學習常出現全失敗群組，導致無獎勵梯度可用。
SPLICE從失敗軌跡選接合點，由提案模型產生有界選項，並以當前策略延續估計其價值。

## 摘要翻譯

基於群組的可驗證獎勵強化學習（RLVR）在長時程代理任務上經常產生全失敗群組（all-fail group）：每條採樣軌跡皆獲得零獎勵，使群組相對方法（group-relative method）缺乏基於獎勵的策略梯度。常見的補救方法是從更強大的模型提供任務層級解答，但完整軌跡成本高昂，並使學習者暴露於較長的異策略歷史中。我們提出 SPLICE，它在線上從失敗的當前策略軌跡建構局部訓練目標。對於每個全失敗群組，提案模型在當前策略軌跡中選擇一個接合點，並從該點生成數個有界選項。我們使用重複的當前策略延續來估計每個選項的價值，將正向估計轉換為回報加權局部目標，並在這些選項上擬合當前策略。我們在兩個長時程代理任務上並跨兩個策略家族評估 SPLICE：使用 SWE-bench Verified 的軟體工程，以及使用 BrowseComp-Plus 的深度研究。SPLICE 在全部四種實驗設定中皆優於 GRPO 與完整軌跡引導基準方法，相較於 GRPO 提升 2.8 至 9.8 個百分點。在最初失敗的 SWE 任務上，它將 GRPO 的通過率提高 10.8 個百分點。進一步的實驗顯示，SPLICE 在提升效能的同時減少了提案模型高昂的計算成本。

### 核心貢獻（3～5點）
- **問題界定**：明確指出基於群組的可驗證獎勵強化學習在長時程代理任務中常面臨「全失敗群組」困境，導致群組相對方法（如 GRPO）缺乏有效的策略梯度訊號。
- **方法創新**：提出 SPLICE，無需仰賴完整軌跡引導，而是在線上從失敗的當前策略軌跡中選取接合點，由提案模型生成有界選項，並以重複當前策略延續估計其價值，轉化為回報加權局部目標進行策略擬合。
- **理論優勢**：相較於完整軌跡引導基準方法，SPLICE 有效降低異策略歷史的暴露長度與提案模型的計算成本，同時保留對學習者有意義的局部訓練訊號。
- **實驗成果**：在軟體工程（SWE-bench Verified）與深度研究（BrowseComp-Plus）兩大長時程代理任務、跨兩個策略家族的四種設定中，SPLICE 全面優於 GRPO 與完整軌跡引導基準，相較 GRPO 提升 2.8 至 9.8 個百分點。
- **失敗任務復原能力**：在最初失敗的 SWE 任務上，SPLICE 將 GRPO 的通過率額外提升 10.8 個百分點，展現其對困難任務的補救效益。

### 適合對象
從事大型語言模型（LLM）代理強化學習（Agent RL）研究、尤其是關注長時程代理任務（如軟體工程、深度研究）訓練方法的學者與工程師；以及對可驗證獎勵強化學習（RLVR）、群組相對策略最佳化（GRPO）及其在稀疏獎勵與全失敗群組情境下改良策略感興趣的研究人員。

## 深度分析

#### 方法論解析

SPLICE 的核心設計動機源於一個在長時程代理強化學習 (Long-Horizon Agent RL) 中被低估的失敗模式：**全失敗群組 (All-Fail Group)**。在基於群組的強化學習 (Group-Based RL) 框架（如 GRPO）中，每個任務會採樣一組軌跡 (rollout)，並以群組內的相對獎勵計算優勢函數 (advantage)。當獎勵為二元結果獎勵 (binary outcome reward) 時，若群組內所有軌跡皆失敗，則獎勵變異為零，導致基於獎勵的策略梯度 (reward-based policy gradient) 完全消失。這在 SWE-bench Verified 等任務中尤其嚴重，因為單一任務可能需要數十至上百個代理回合 (agent turns)，單次採樣的成功率極低。

SPLICE 的方法論可拆解為三個關鍵設計決策：

**第一，局部化 (localization) 而非完整軌跡引導 (full-trajectory guidance)。** 傳統外部引導 (external guidance) 方法（如 RSTG、expert iteration）要求提案模型 (proposal model) 生成完整的任務級解答 (task-level solution)，再以監督式或異策略 (off-policy) 方式訓練當前策略 (current policy)。SPLICE 反其道而行：它觀察到長時程失敗往往是局部化的——一個短暫的修正片段 (corrective segment) 可能足以將軌跡從失敗狀態導向成功。因此，提案模型只需在當前策略軌跡中選擇一個接合點 (splice point)，並從該點生成數個有界選項 (bounded options)，而非完整軌跡。這大幅降低了提案模型的推論成本。

**第二，學習者條件化 (learner-conditioned) 的選項評估。** 這是 SPLICE 最具理論深度的設計。每個有界選項的價值並非由提案模型自身評估，而是透過「重複當前策略延續 (repeated current-policy continuations)」來估計：將選項接合到當前策略的歷史中，交還控制權給當前策略，並重複採樣至任務結束。這種設計有兩個重要意涵：(a) 評估反映的是「當前策略在接收此選項後能完成任務的機率」，而非選項本身的內在品質；(b) 這使得訓練目標自然地適配當前策略的能力分布，避免了異策略歷史 (off-policy history) 帶來的共變數偏移 (covariate shift) 與誤差累積 (compounding errors)。

**第三，回報加權局部目標 (return-weighted local target) 的構造。** 對於每個選項，僅保留正向估計 (positive estimate)，即當前策略在接合該選項後能成功完成任務的實例，並以其終端回報作為權重，構造局部訓練目標 (local training target)。負向估計則被丟棄，這與 GRPO 中只利用群組內正向軌跡的邏輯一致，但範圍被縮限到接合點之後的局部區段。

從演算法流程來看，SPLICE 採用分支式設計：僅當群組被判為全失敗群組時才進入接合分支 (splice branch)，其餘群組仍走標準 GRPO。這種「只在必要時介入」的策略避免了對簡單任務的過度干預，同時將寶貴的提案模型計算資源集中於當前策略的瓶頸點。

值得注意的是，SPLICE 對提案模型的形式幾乎沒有假設——它可以是任何能產生有界選項的模型，無需與學生策略共享 token 空間。這與 RSTG 所需的「對齊的教師與學生 token 空間 (aligned teacher and student token spaces)」形成鮮明對比，大幅放寬了適用範圍。

#### 實驗數據解讀

論文在四個設定中驗證 SPLICE 的有效性，橫跨兩個策略家族 (policy families) 與兩個長時程代理任務：

**SWE-bench Verified（軟體工程任務）**：此基準要求代理閱讀真實 GitHub issue、修改程式碼並通過測試套件，是典型的長時程、多回合互動任務。Qwen3.5-9B 的平均 rollout 長度達 83.7 個代理回合，凸顯了全失敗群組問題的嚴重性。SPLICE 在此任務上對 GRPO 的提升幅度落在 2.8–9.8 百分點 (percentage points) 區間。

**BrowseComp-Plus（深度研究任務）**：此基準要求代理進行多輪網頁瀏覽與資訊整合以回答複雜問題，同樣屬於長時程稀疏獎勵設定。SPLICE 在此任務上同樣穩定超越 GRPO 與完整軌跡引導基準。

**畢業率 (graduation rate) 提升**：這是論文中最具說服力的指標之一。在一組「初始即失敗的 SWE 任務」（即 GRPO 完全無法從中產生正向信號的子集）上，SPLICE 將 GRPO 的畢業率從 8.1% 提升至 18.9%，相對增幅超過一倍。這直接證明了 SPLICE 確實在 GRPO 完全失效的區域恢復了學習信號，而非僅在簡單任務上錦上添花。

**計算效率**：論文明確報告 SPLICE 使用的提案模型 rollout 回合數少於完整軌跡引導基準，同時達到更佳效能。這驗證了「局部接合」設計假設：失敗確實是局部化的，無需動用完整軌跡引導。

然而，實驗部分有幾個值得關注的細節：(1) 論文中提及「兩個策略家族」，但未在提供的文本中明確列出具體模型名稱（僅提及 Qwen3.5-9B 的一個數據點），讀者需參閱完整論文以確認是否涵蓋不同規模或架構的策略；(2) 提案模型的選擇（是否為同一系列更大模型或完全不同來源）會直接影響方法的實用性邊界；(3) 「有界選項」的長度上限 (bounded option length) 是關鍵超參數，其敏感度分析在提供的文本中未充分展開。

整體而言，數據呈現的 pattern 是穩健的：SPLICE 在所有四個設定中均優於 GRPO 與完整軌跡引導基準，且在「最困難的子集」（初始失敗任務）上展現最大相對增益，這正是該方法設計目標所在。

#### 與現有研究的比較

SPLICE 在方法論譜系上佔據一個獨特位置，可從三個軸向與現有研究比較：

**與 RSTG 的比較**：RSTG 同樣針對全失敗群組問題，採用 GRPO 加上線上策略蒸餾 (On-Policy Distillation, OPD) 的混合方案。RSTG 要求提案模型（教師）與學生策略共享 token 空間，並以教師生成的完整軌跡作為監督信號。SPLICE 的關鍵差異在於：(a) 不要求 token 空間對齊，提案模型可以是異質的；(b) 不使用完整軌跡，改用接合點後的有界選項；(c) 評估方式為當前策略延續而非教師自評。這使得 SPLICE 在異策略暴露 (off-policy exposure) 與計算成本兩個維度上均優於 RSTG。

**與 Expert Iteration / Expert Iteration 變體的比較**：此類方法（如 STaR、ReST）以專家模型生成完整解答並進行監督式微調 (supervised fine-tuning)。對於長時程代理，這意味著學生必須模仿完整的專家軌跡，導致嚴重的分布偏移 (distributional shift)。SPLICE 透過「接合 + 當前策略延續評估」將專家介入縮限到局部，且訓練目標反映的是學生自身的能力邊界。

**與 GRPO 變體（如 Dr. GRPO、Filter-Rejection）的比較**：此類方法透過過濾零變異群組或重新分配採樣來緩解全失敗問題，但無法從根本上恢復學習信號——若任務對當前策略過於困難，過濾後仍無可用軌跡。SPLICE 則透過外部引導主動注入學習信號，屬於互補而非替代的技術路線。

**與提示條件化方法（如 Hint-RL、Prefix-RL）的比較**：此類方法在 rollout 開始時注入提示或前綴，僅優化策略生成的延續部分。SPLICE 的接合點是線上選擇的，且可位於軌跡中段，這比固定前綴更具適應性。

**SPLICE 的侷限性**：(1) 依賴提案模型具備產生「有界且有意義的修正選項」的能力，若提案模型本身在該接合點也無能為力，則 SPLICE 退回到全失敗狀態；(2) 重複當前策略延續的採樣數量是準確性與成本的權衡，過少則價值估計雜訊大，過多則計算成本上升；(3) 對於失敗點極早或極晚的任務，接合點的選擇空間可能受限；(4) 論文未充分討論當提案模型與當前策略差異極大時（例如不同架構或訓練階段），接合選項的語意連貫性問題。

#### 未來研究方向

SPLICE 開啟了多條值得探索的研究路線：

**第一，自適應接合策略 (adaptive splicing strategy)**。當前 SPLICE 的接合點選擇由提案模型決定，未來可探索讓當前策略本身參與接合點選擇——例如根據狀態價值估計或失敗預測信心度，主動標記「需要外部介入」的時機。這將使介入更加精準，並可能減少對提案模型的依賴。

**第二，多提案模型集成 (multi-proposal-model ensemble)**。不同提案模型可能在不同接合點展現互補優勢。可研究如何根據接合點的狀態特徵，動態選擇最合適的提案模型，或融合多個提案模型的選項。

**第三，價值估計的樣本效率提升**。重複當前策略延續的採樣成本不容忽視。可借鑒 Monte Carlo Tree Search (MCTS) 的思想，在選項評估階段引入啟發式剪枝或分層採樣，以更少的 rollout 獲得更穩定的價值估計。

**第四，理論分析**。SPLICE 的收斂性與最優性目前缺乏理論保證。特別是「僅保留正向估計」的非對稱處理是否會引入偏差，以及接合點選擇對策略更新的影響，都是值得形式化的問題。

**第五，跨領域泛化**。SPLICE 在軟體工程與深度研究兩個領域驗證有效，但其在其他長時程代理任務（如機器人操作、對話代理、自動化科學實驗）中的表現仍待探索。不同領域的「失敗局部化程度」可能差異極大，這將影響方法的適用邊界。

**第六，與其他 RL 演算法的整合**。SPLICE 目前與 GRPO 結合，但其核心思想（局部接合 + 學習者條件化評估）可移植到其他基於群組的 RL 方法（如 GSPO、RLOO）或基於價值的方法（如 PPO）。探索這種通用化將擴大其影響範圍。

**第七，安全性與對齊考量**。當提案模型來自不同來源或訓練階段時，其生成的選項可能帶有偏見或不安全行為。SPLICE 的局部化設計在某種程度上限制了此風險（因為選項長度有界且評估基於當前策略），但仍需系統性的安全審查機制。

**第八，與人類回饋的結合**。在人類專家可介入的設定下，可將 SPLICE 的接合點選擇與人類回饋結合——讓人類在關鍵接合點提供示範，而非依賴另一個 LLM。這將把方法推向更廣泛的人機協作強化學習 (human-in-the-loop RL) 框架。

## 論文問答

**Q1：什麼是長時程代理強化學習中的「全失敗群組」（all-fail group）問題？為何它會造成學習訊號消失？**

A：全失敗群組指的是在同一任務下採樣的一整組軌跡中，每一條軌跡都獲得零獎勵的情況。在 GRPO 這類基於群組相對優勢的方法中，優勢值是透過比較同一群組內各軌跡的獎勵來估計的；當所有軌跡獎勵皆為零時，獎勵變異為零，導致基於獎勵的策略梯度完全消失。這對長時程代理任務特別致命，因為稀疏的二元結果獎勵加上任務的高難度，使得「整組都失敗」成為常態而非例外。即使某些中間決策其實是正確的、只要稍作修正就能成功，標準 GRPO 也無法從中萃取任何學習訊號。

**Q2：為何現有的「完整軌跡引導」（full-trajectory guidance）方法無法有效解決此問題？**

A：完整軌跡引導仰賴一個更強的提案模型（proposal model）產生完整的任務級解答，再讓學習者模仿或從中學習。然而在長時程代理任務中，一條完整軌跡可能包含數十甚至上百個代理互動回合（例如 Qwen3.5-9B 在 SWE 任務上平均需要 83.7 個回合），反覆產生這類長軌跡會帶來高昂的推論成本。更嚴重的是，學習者被迫暴露在與當前策略分布差異極大的長段異策略歷史中，容易產生協變量偏移（covariate shift）與誤差累積，使得訓練分布與當前策略實際行為出現嚴重落差。

**Q3：為何這個問題對代理強化學習領域至關重要？**

A：隨著 LLM 代理被部署到軟體工程、深度研究等真實長時程任務中，稀疏的可驗證獎勵成為主流監督形式，這使得全失敗群組在困難任務上幾乎無可避免。若無法從失敗中恢復學習訊號，代理將永遠無法跨越探索瓶頸，無法在「目前完全做不到」的任務上取得進步。因此，能否有效處理全失敗群組，決定了代理強化學習能否真正擴展到高難度、長時程的真實世界應用，是該領域能否突破探索瓶頸的關鍵課題。

**Q4：SPLICE 的核心方法是什麼？它如何從失敗軌跡中萃取學習訊號？**

A：SPLICE 的核心構想是「失敗局部化的選項接合」（failure-localized option splicing）搭配「當前策略延續評估」。對於每個全失敗群組，提案模型會在當前策略的某條失敗軌跡中選擇一個接合點（splice point），並從該點產生數個有界選項（bounded options）。接著將每個選項接合回當前策略的歷史中，把控制權交還給當前策略，並重複採樣其延續軌跡直到任務結束；這些延續的終端結果用來估計該選項在當前策略下的延續價值。正向的價值估計會被轉換為回報加權的局部訓練目標（return-weighted local target），讓當前策略學習在這個接合點之後選擇較好的選項。

**Q5：SPLICE 相較於既有方法最重要的創新點為何？**

A：SPLICE 最關鍵的創新在於把「外部引導」從「完整軌跡層級」重新定位為「學習者條件化的局部選項層級」。它只在線上、只在當前策略實際遭遇的瓶頸處（接合點）呼叫提案模型，並把提案模型的角色限制在產生短而有界的選項，而非整條解答。這種「學習者條件化」的設計讓提案模型的計算資源被精準分配到當前策略真正需要幫助的決策點上，同時透過在當前策略歷史中接合選項並以當前策略的延續來評估價值，大幅限制了異策略暴露的範圍。

**Q6：SPLICE 在設計上有哪些關鍵選擇？這些選擇各自解決了什麼問題？**

A：第一個關鍵選擇是「只在全失敗群組上啟動接合分支」，其他群組仍走標準 GRPO，這保留了原本有效的學習路徑並避免不必要的提案模型開銷。第二個關鍵選擇是「有界選項」而非完整軌跡，提案模型只需產生短片段，顯著降低推論成本。第三個關鍵選擇是「以當前策略的重複延續來估計選項價值」，而非直接用提案模型的信心或單一結果，這讓訓練目標反映當前策略實際完成任務的能力。第四個關鍵選擇是「回報加權的局部目標」，只把正向價值的選項納入訓練，避免被低品質選項污染。

**Q7：SPLICE 在哪些基準上進行評估？為何選擇這些任務？**

A：SPLICE 在兩個長時程代理任務上評估：軟體工程領域的 SWE-bench Verified 與深度研究領域的 BrowseComp-Plus。SWE-bench Verified 提供可執行的測試套件作為可驗證獎勵，能客觀衡量程式碼修改是否真正解決問題；BrowseComp-Plus 則衡量代理在多輪瀏覽與推理後能否找到正確答案。這兩個任務都具備長時程、稀疏二元獎勵、容易出現全失敗群組等特性，是檢驗 SPLICE 處理困難探索問題能力的理想場域。此外，作者也在兩種不同的策略家族上進行評估，以驗證方法的泛用性。

**Q8：SPLICE 的關鍵實驗結果為何？**

A：在四個設定（兩個任務 × 兩個策略家族）中，SPLICE 都優於 GRPO 與完整軌跡引導基準，相較 GRPO 提升了 2.8 至 9.8 個百分點。特別值得注意的是，在一組「一開始 GRPO 完全無法通過」的 SWE 任務上，SPLICE 將通過率（graduation rate）從 8.1% 提升到 18.9%，提升了 10.8 個百分點，顯示它確實能從原本完全失敗的任務中恢復學習。更重要的是，SPLICE 在達到更好效能的同時，使用了比完整軌跡引導基準更少的提案模型 rollout 回合數，證明了「局部接合」在計算效率上的優勢。

**Q9：SPLICE 進行了哪些消融實驗或進一步分析來驗證設計選擇？**

A：論文中進行了多項進一步實驗來驗證 SPLICE 的設計選擇，包括比較提案模型 rollout 回合數與效能的關係，證明 SPLICE 在更少的提案模型計算下仍能達到更佳表現。透過分析「畢業率」的提升，作者展示了 SPLICE 對原本失敗任務的恢復能力，這是直接針對全失敗群組問題設計的指標。這些實驗共同支持了 SPLICE 的兩個核心主張：局部接合比完整軌跡引導更有效率，且學習者條件化的選項評估能產生更貼近當前策略能力的訓練目標。

**Q10：SPLICE 適合應用於哪些實際場景？**

A：SPLICE 特別適合需要長時程多步推理、且只能取得稀疏二元結果回饋的代理應用，例如自動化軟體除錯與程式修復（類似 SWE-bench 場景）、多輪網頁瀏覽與資訊彙整的深度研究代理、複雜資料分析流程中的自動化決策鏈、以及需要多工具協調的企業級代理任務。在這些場景中，代理經常會在某個關鍵決策點卡住而導致整條軌跡失敗，SPLICE 能在這些瓶頸處精準注入局部引導，幫助代理跨越探索障礙。

**Q11：從產品部署角度，SPLICE 解決了哪些實務考量？**

A：從產品角度，SPLICE 同時解決了「成本」與「安全性」兩個關鍵問題。在成本上，由於提案模型只需產生短選項而非完整軌跡，雲端推論費用可大幅降低，這對於需要大規模訓練的商業部署尤其重要。在安全性上，由於學習只在當前策略實際遭遇的接合點附近進行，且評估來自當前策略的延續而非外部專家，模型行為偏移（behavior drift）的風險被顯著降低，部署後的代理行為更可預測、更貼近組織對齊目標。

**Q12：SPLICE 對代理強化學習領域的更廣泛影響為何？**

A：SPLICE 重新框架了「外部引導」在代理 RL 中的角色，從「提供完整示範」轉向「在瓶頸處提供局部協助」，這可能影響未來整個領域的演算法設計方向。它也凸顯了「學習者條件化」的重要性——任何外部引導都應該以當前策略的能力與分布為錨點，而非假設學習者能完整複製專家行為。這種思路可延伸到其他稀疏獎勵的代理學習問題，例如機器人操作、遊戲 AI 等，並促使研究者更系統地思考「何處需要引導」與「如何評估引導品質」這兩個問題。

**Q13：SPLICE 論文本身承認了哪些限制？**

A：雖然論文中 SPLICE 展現了強勁的結果，但方法本身仍仰賴一個夠強的提案模型能在接合點產生有用的有界選項；若提案模型在某些瓶頸處也無法產生有意義的選項，SPLICE 的恢復能力會受限。此外，SPLICE 目前只在兩個任務（軟體工程、深度研究）與兩個策略家族上驗證，對其他長時程代理領域（如機器人、遊戲、對話代理）的泛用性仍待確認。接合點的選擇策略與有界選項的長度上限也都是重要的超參數，其在不同任務下的最佳設定需要進一步研究。

**Q14：SPLICE 在哪些情況下可能會失敗？**

A：當任務失敗的原因並非「局部可修正」而是「需要全面重新規劃」時，SPLICE 的局部接合可能無法奏效，因為它預設存在一個接合點，從中插入短選項就能讓當前策略成功延續。此外，若提案模型本身在某些瓶頸狀態下也缺乏能力產生高品質選項（例如極度冷門的程式語言或高度專業的領域知識），SPLICE 將無法從外部引導中獲益。另一個潛在失敗情境是當任務的獎勵函數本身有雜訊或定義不清時，回報加權的局部目標可能會放大錯誤訊號。

**Q15：SPLICE 開啟了哪些值得探索的未來研究方向？**

A：未來值得探索的方向包括：自動學習接合點選擇策略而非依賴啟發式、將 SPLICE 擴展到多提案模型或工具輔助的接合、結合線上課程學習動態調整有界選項的長度上限、以及把「學習者條件化的局部引導」框架應用到其他稀疏獎勵的代理領域（如機器人操控、對話系統）。另一個有趣方向是研究 SPLICE 與其他探索增強方法（如好奇心驅動、課程學習）的互補關係，以及如何把接合點選擇本身變成一個可學習的策略，進一步降低對提案模型的依賴。

## 實務應用指南

### 適用場景

1. **企業內部程式碼維護代理**：在大型 monorepo 中自動修復 regression bug、調整 API 介面、或補齊缺失的測試案例。當現有策略在某些複雜 bug 上反覆失敗（全失敗群組）時，SPLICE 可在失敗軌跡的關鍵接合點注入由資深模型產生的修正片段，避免每次都要求提案模型生成完整修補流程。

2. **深度研究與市場情報代理**：用於 BrowseComp-Plus 類型的多輪瀏覽、擷取、整合任務。當代理在某個搜尋查詢或頁面解析步驟卡住時，SPLICE 能在該步驟插入由更強模型產生的「有界選項」（例如替代查詢詞、頁面摘要策略），再交由當前策略接手完成後續推理。

3. **客服與企業流程自動化代理**：在多輪對話、表單填寫、跨系統操作的工作流中，當代理在某個驗證步驟或 API 呼叫反覆失敗時，可使用 SPLICE 從失敗軌跡中找出接合點，由提案模型提供短暫的修正選項（如正確的欄位格式、替代 API 端點），讓當前策略繼續完成任務。

4. **資料庫與 ETL 維運代理**：當代理在處理複雜 SQL 查詢、schema 遷移或資料清洗時遇到瓶頸，SPLICE 可在失敗的查詢步驟插入由專家模型產生的查詢片段，並用當前策略的後續執行結果來評估該片段的價值。

5. **教育與程式教學代理**：在多輪互動教學中，當代理在某個解題步驟反覆失敗時，可使用 SPLICE 從失敗軌跡中選擇接合點，由更強模型提供解題提示選項，並讓當前策略嘗試完成剩餘步驟，以逐步提升教學品質。

### 實作前置條件

**資料需求**
- 一組長時程代理任務的訓練集，需具備可驗證的二元結果獎勵（例如單元測試通過與否、答案正確與否）。SWE-bench Verified 與 BrowseComp-Plus 是兩個已驗證的基準。
- 環境介面（執行環境、瀏覽器、API 端點）需支援中途狀態保存與還原，以便在接合點插入選項後能從該狀態繼續 rollout。
- 失敗軌跡的完整記錄（包含每一步的 prompt、回應、環境觀察），用於提案模型選擇接合點。

**計算資源**
- 一個「當前策略」模型（即要訓練的學生模型），以及一個「提案模型」（通常更強，例如更大的 LLM 或專家模型）。提案模型只需產生短片段，計算量遠低於完整軌跡。
- 足夠的 rollout 平行度，因為 SPLICE 需要在每個接合點進行多次「重複當前策略延續」以估計選項價值。
- 標準的 RL 訓練基礎設施（vLLM/SGLang 推論引擎、分散式訓練框架如 verl 或 OpenRLHF）。

**技能前提**
- 熟悉 GRPO 或其他群組相對 RL 演算法的實作細節。
- 具備 LLM agent 框架（如 LangGraph、OpenHands、AutoGen）的整合經驗，能在軌跡中途切換控制權。
- 理解 off-policy 風險與重要性取樣的概念，以便正確處理接合點前後的分布差異。
- 具備 prompt engineering 能力，能設計讓提案模型在給定接合點產生「有界選項」的指令。

### 實作步驟建議

1. **建立基礎 GRPO 訓練管線**：先實作標準的 GRPO 訓練流程，包含群組採樣、群組相對優勢計算、策略更新。確認管線能在長時程任務上正常運作，並能識別「全失敗群組」（群組內所有軌跡獎勵皆為零）。

2. **設計接合點選擇機制**：實作提案模型的 prompt，使其能接收一條失敗軌跡並輸出一個接合點位置（例如「第 N 步之後」）以及數個有界選項（每個選項是 1–5 步的動作序列）。接合點選擇可基於失敗跡象（如重複動作、錯誤訊息、停滯狀態）。

3. **實作選項價值估計模組**：對於每個候選選項，從接合點的環境狀態出發，先執行該選項，再交還控制權給當前策略，重複採樣 K 次（例如 K=4–8 次）直到任務結束。記錄每次的終端獎勵，用平均值或成功率估計該選項的「當前策略延續價值」。

4. **建構回報加權局部目標**：將價值估計為正的選項轉換成回報加權的目標分布（例如以 softmax 或指數加權方式根據估計價值分配機率），作為局部訓練目標。負價值的選項不進入訓練目標。

5. **整合分支邏輯**：在 GRPO 訓練迴圈中加入分支：若群組為全失敗，進入 SPLICE 分支（接合、估計、擬合）；否則走標準 GRPO 更新。確保兩條分支的損失函式與梯度流向一致。

6. **設定超參數與監控指標**：關鍵超參數包括每個接合點產生的選項數量、重複延續次數 K、選項長度上限、價值估計的折扣因子。監控「畢業率」（原本失敗的任務在訓練後變成功的比例）以及提案模型的 rollout 回合數，作為成本指標。

7. **離線評估與消融實驗**：先用固定測試集評估 SPLICE 相對於純 GRPO 與完整軌跡引導基線的表現。進行消融實驗以驗證接合點選擇、選項數量、重複延續次數等設計選擇的影響。

8. **部署與持續改進**：將訓練好的策略部署到目標環境，持續收集失敗案例，並定期用 SPLICE 流程進行增量訓練。監控提案模型的使用成本，確保其低於完整軌跡引導方案。

### 潛在風險與注意事項

**接合點選擇偏差**：若提案模型傾向選擇軌跡末端的接合點，會導致選項長度過長、退化為完整軌跡引導。緩解方式：在 prompt 中明確限制選項長度上限，並對接合點位置加入正則化（例如偏好軌跡中段）。

**價值估計的高方差**：重複延續次數 K 過小會導致價值估計不穩定，使訓練目標雜訊過大。緩解方式：使用足夠大的 K（建議 ≥4），並對價值估計加入信賴區間過濾，僅採用估計穩定的選項。

**off-policy 暴露**：接合點之前的歷史來自當前策略，接合點之後的選項來自提案模型，兩者分布不同。緩解方式：限制選項長度（建議 ≤5 步）、在損失函式中加入 KL 約束，或對接合點附近的 token 使用重要性取樣修正。

**提案模型成本失控**：若每個全失敗群組都觸發大量選項生成與重複延續，總計算量可能超過完整軌跡引導。緩解方式：限制每個群組的接合點數量、對選項數量設定上限、並監控提案模型每任務的平均 rollout 回合數。

**獎勵 hacking 風險**：當前策略可能學會「等待提案模型救援」而非真正提升能力。緩解方式：隨訓練進度逐漸降低 SPLICE 分支的觸發頻率，或對提案模型的使用加上預算限制。

**接合點環境狀態不一致**：某些環境在長時程 rollout 中狀態難以精確還原（例如瀏覽器的 cookie、暫存檔）。緩解方式：選擇支援狀態快照的環境，或在接合點設計「冪等」的選項（執行後不破壞環境狀態）。

### 與其他技術的整合建議

**與 GRPO 變體整合**：SPLICE 可作為外掛模組加入任何群組相對 RL 方法（如 GSPO、RLOO）。只需在群組優勢計算前插入「全失敗偵測 → SPLICE 分支」邏輯，其餘流程不需修改。

**與 on-policy distillation (OPD) 整合**：若提案模型與學生模型使用相同 tokenizer，可將 SPLICE 的選項擬合步驟與 OPD 的 token-level KL 蒸餾結合，在局部目標上同時學習選項分布與 token 級分布。

**與測試時擴展整合**：SPLICE 訓練的策略可與測試時的 Best-of-N、樹搜尋或自我修正機制結合。訓練時學會的「接受外部選項」能力，可讓代理在部署時更好地利用測試時的提示或工具。

**與 agent 框架整合**：在 LangGraph、AutoGen 等框架中，可在節點層級實作接合點：將代理流程建模為圖，SPLICE 在特定節點插入「提案模型分支」，並用條件邊決定是否切換回當前策略。

**與監控與可觀測性整合**：將接合點位置、選項價值估計、畢業率等指標接入現有的 MLOps 儀表板（如 Weights & Biases、MLflow），以便追蹤 SPLICE 在不同任務類型上的效益。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）了解「全失敗群組」問題的直覺——想像一群學生做同一題數學題但全部算錯，老師無法從中分辨誰比較好。SPLICE 的核心想法是：請一位更強的老師在學生卡住的地方給一個小提示，然後讓學生自己完成剩下的部分。閱讀時可先跳過公式，專注理解「接合點」、「有界選項」、「重複延續估計」三個概念。

**給 AI 工程師**：重點關注第 3 節（方法）與第 4 節（實驗）的實作細節。SPLICE 的工程價值在於：它把昂貴的提案模型呼叫從「完整軌跡」縮減為「短片段」，同時透過重複延續估計來校正 off-policy 偏差。建議直接閱讀演算法偽代碼，並思考如何將其整合到你現有的 GRPO 訓練管線中。接合點選擇的 prompt 設計與重複延續次數 K 是兩個最關鍵的工程決策。

**給研究者**：SPLICE 連結了 options framework（Sutton et al.）、hierarchical RL 與 LLM agent RL 三條脈絡。建議從第 2 節（Related Work）出發，比較 SPLICE 與 RSTG、expert iteration、stitching 等方法的差異。值得深入研究的方向包括：接合點選擇的理論依據、價值估計的樣本複雜度、以及 SPLICE 與測試時擴展方法的互補性。論文中關於「畢業率」的實驗設計也值得借鏡。

**給產品經理**：SPLICE 解決的是一個具體的商業問題——當 AI 代理在困難任務上反覆失敗時，如何用更少的成本提升成功率。關鍵數字：在 SWE-bench Verified 與 BrowseComp-Plus 上，SPLICE 比 GRPO 多解決 2.8–9.8 百分點的任務，並把原本失敗任務的「畢業率」從 8.1% 提升到 18.9%。在評估是否採用時，請關注三個指標：任務成功率提升幅度、提案模型成本佔比、以及「原本失敗任務的轉化率」。SPLICE 特別適合那些「任務價值高、但失敗成本也高」的場景，例如企業內部自動化與專業領域研究。
