## ⚡ TL;DR

針對視覺語言模型進行程序式三維建模，現有標準化基準不足且人工編寫難度高。
提出3DCodeBench基準與3DCodeArena平台，評估十二種視覺語言模型生成三維程式能力。
研究指出測試時擴展與迭代回饋顯著提升成效，然幾何斷裂及API不匹配仍為關鍵瓶頸。

## 摘要翻譯

透過程式碼進行程序式三維建模（Procedural 3D modeling）正逐漸成為一種多功能的範式，可提供確定性（deterministic）、引擎就緒（engine-ready）且可精確編輯（precisely editable）的資產（assets），而這些特性正是神經三維生成器（neural 3D generators）本質上所缺乏的。然而，創作這類程序式內容需要深厚的專業知識，涵蓋三維軟體的應用程式介面（API）、參數化設計（parametric design），以及程式碼層級的幾何推理（geometric reasoning）。在本論文中，我們提出 3DCodeBench，一個用於評測三維建模軟體中程序式三維生成之視覺語言模型（Vision-Language Model, VLM）代理的系統化基準測試（benchmark）。具體而言，3DCodeBench 評測 12 種先進的視覺語言模型如何有效地擔任程序式三維建模師，將文字與圖像參考轉譯為供三維建模軟體使用的程序式程式碼（procedural code）。鑑於自動化指標（automated metrics）可能無法充分捕捉三維形狀的感知品質（perceptual quality），我們建構了 3DCodeArena，一個基於成對人類偏好（pairwise human preferences）對生成三維成果進行排名的平台。從廣泛的評估與結果中，我們觀察到：（1）失敗主要源於應用程式介面（API）不匹配（API mismatch），而成功渲染的成果仍存在斷開元件（disconnected components）或浮動元件（floating components）等三維幾何部件的問題。（2）測試時擴展（test-time scaling），例如提高思考預算（thinking budgets）與多輪精進（multi-turn refinement），整體而言能提升表現。我們的研究發現凸顯了高品質程序式編碼資料對於推進商業視覺語言模型的迫切需求。此外，有效的程序式三維建模需要穩健的執行環境（execution environment），以提供高保真回饋（high-fidelity feedback），支援迭代精進（iterative refinement）。我們公開釋出 3DCodeBench，包含一個由多模態（文字／圖像）提示（multimodal prompts）、程序式程式碼與三維物體三元組（triplets）組成的精選大規模資料集（curated large-scale dataset），以及評估協定（evaluation protocol）與公開的 3DCodeArena 平台，作為探索基於視覺語言模型之程序式三維建模師的基礎工具包（foundational toolkit）。

### 核心貢獻（3～5點）
- 提出 3DCodeBench，首個針對視覺語言模型（VLM）代理在三維建模軟體中進行程序式三維生成的系統化基準測試。
- 建構 3DCodeArena 平台，採用成對人類偏好（pairwise human preferences）機制，以彌補自動化指標在感知品質評估上的不足。
- 揭示當前前沿 VLM 的主要失敗模式：應用程式介面（API）不匹配為首要原因，且成功渲染成果仍存在幾何結構缺陷（如斷開與浮動元件）。
- 驗證測試時擴展（test-time scaling）策略（如提高思考預算與多輪精進）對程序式三維建模任務的整體效益。
- 公開釋出包含多模態提示、程序碼與三維物體三元組的精選大規模資料集、評估協定與 3DCodeArena 平台，作為後續研究的基礎工具包。

### 適合對象
從事三維電腦圖學、程序式內容生成、視覺語言模型代理系統與數位創作工具開發的研究人員與工程師；亦適合關注多模態大型模型在工業設計、遊戲資產製作與參數化設計領域應用的學界與業界讀者。

## 深度分析

#### 方法論解析

Procedural 3D Modeling（程序式三維建模） via code 是本文的核心範式，旨在彌補 neural 3D generator（神經三維生成器）缺乏 determinism（確定性）與 precise editability（可精確編輯性）的短板。作者提出 3DCodeBench，一個針對 Vision-Language Model（VLM; 視覺語言模型）Agent 的標準化評估框架，其方法論可拆解為四個層次：

1. 資料建構層：透過從 Infinigen 提取 procedural factories，並以 agentic curation pipeline（代理式策展流程）搭配 human verification（人工驗證），建構出 26K 組 multimodal prompt（多模態提示，含 text/image）↔ standalone code（獨立程式碼）↔ 3D object（三維物體）triplets（三元組），涵蓋 212 個 semantic categories（語義類別）。相較於傳統靜態 mesh（網格）資料集，此資料集強調 seed-addressable（種子可定址）與真實幾何複雜度，例如 crab（螃蟹）、dragonfly（蜻蜓）等類別平均超過 400 lines of code（行程式碼），遠超簡單 primitive shapes（基本形狀）的組合難度。

2. 模型評估層：系統性評測 12 個 frontier VLMs（前沿視覺語言模型），包括 GPT-5.5、Gemini 3.1 Pro、Claude Opus 4.7 等。評估不採單一回合生成，而是將 VLMs 視為 active agents（主動代理），設計 controlled multi-turn scenarios（受控多輪情境），納入 execution-error feedback（執行錯誤回饋）、retries（重試）、visual self-critique（視覺自我批判）與 API documentation augmentation（API 文件增強）。

3. 自動化指標層：建立 comprehensive automated metrics（綜合自動化指標），涵蓋：
   - Executability（可執行性）：程式碼能否在 Blender 中無錯誤運行。
   - Perceptual view similarity（感知視角相似度）：以 SigLIP-2 與 DINOv3 比對渲染視圖。
   - 3D geometric alignment（三維幾何對齊）：以 Chamfer distance（倒角距離）與 Uni3D 衡量點雲或網格層級的幾何匹配。

4. 人類偏好層：鑒於 automated metrics（自動化指標）難以完全捕捉 perceptual quality（感知品質），作者推出 3DCodeArena，一個 public arena（公開競技場），透過 pairwise human preferences（成對人類偏好）進行比較，產生可靠的 Elo ranking（Elo 排名），補足自動指標與人類美學判斷之間的落差。

#### 實驗數據解讀

從 12 個 advanced VLMs（先進視覺語言模型）的 extensive evaluations（廣泛評估）中，可歸納出以下關鍵數據意涵：

首先，Executability（可執行性）雖是基本門檻，但並非主要瓶頸。實驗顯示，failures（失敗案例）大多源於 API mismatch（API 不匹配）——即模型生成的程式碼調用了錯誤或過期的 Application Programming Interface（API; 應用程式介面）參數。這反映出當前 commercial VLMs（商業視覺語言模型）在訓練資料中缺乏高品質的 domain-specific coding syntax（領域特定編碼語法），尤其是針對 Blender Python API 的版本敏感性。

其次，即使程式碼成功執行並產生 successful renders（成功渲染），physical plausibility（物理合理性）仍是最大短板。實驗觀察到大量 disconnected components（斷開元件）與 floating components（浮動元件），顯示模型缺乏對物理世界結構連貫性的深層理解。這意味著現有 VLMs 的 geometric reasoning（幾何推理）能力仍停留在「語法正確」而非「結構合理」的層次。自動化指標如 Chamfer distance 可能僅反映表面點雲的近似程度，卻無法偵測內部結構斷裂；而 perceptual metrics（感知指標）如 SigLIP-2 也可能因視角巧合而給予高分。這正是 3DCodeArena 的必要性所在——人類評判者能輕易識別這些結構性瑕疵。

第三，Test-time scaling（測試時擴展）顯著提升表現。數據顯示，higher thinking budgets（更高思考預算）與 multi-turn refinement（多輪精進）能透過 deterministic execution feedback（確定性執行回饋）逐步修正錯誤。這驗證了 iterative refinement（迭代精進）在 procedural 3D generation（程序式三維生成）中的有效性，也暗示設計適當的 agentic harness（代理式框架）以處理 environmental feedback（環境回饋）是釋放模型潛能的關鍵。然而，這也指出單一回合的 single-shot evaluation（單次評估）嚴重低估了 VLM 的真實能力。

最後，不同模型家族呈現明顯的幾何能力分野。Qualitative comparisons（定性比較）顯示，GPT-5.5、Gemini 3.1 Pro 與 Claude Opus 4.7 在處理高複雜度類別（如 volute、rotten tree）時，其拓樸結構完整性與 texture（紋理）映射準確度仍有顯著差異，這與 Elo ranking 中呈現的勝率分布一致。

#### 與現有研究的比較

相較於既有文獻，3DCodeBench 在四個核心面向填補了關鍵缺口：

1. 資料對齊：ShapeNet、Objaverse 等靜態資料集僅提供 mesh（網格），缺乏 underlying procedural code（底層程序碼），無法評量 generative agency（生成能動性）。3DCodeBench 的 26K triplets 是首批大規模、高品質且經人工驗證的程序式資料。

2. 幾何複雜度：BlenderGym 專注於 editing pre-built scenes（編輯預建場景），而非 from-scratch generation（從零生成）；VoxelCodeBench 則受限於 simplistic voxel grids（簡易體素網格）。本文資料集直接擷取 Infinigen 的 procedural factories，能測試模型處理精細 parametric design（參數化設計）與複雜拓樸的能力。

3. 評估範式：過往研究（如 Hu et al., Ling et al., Lu et al.）多採 ad hoc prompts（臨時提示）與 single-shot evaluation，缺乏 shared reference set（共享參考集）。本文建立標準化 evaluation protocol（評估協定），並首次將 multi-turn agentic refinement（多輪代理式精進）納入基準測試。

4. 指標完整性：既有工作缺乏 comprehensive perception metrics（綜合感知指標）與系統性人類偏好平台。3DCodeArena 透過 pairwise comparison（成對比較）與 Elo ranking，提供可重複的人類感知基準。

然而，本研究仍存在若干侷限。其一，目前僅聚焦於 Blender 的 Python API，尚未涵蓋 SideFX Houdini、Autodesk Maya 等其他工業級軟體的 API，限制了跨引擎 generalization（泛化性）的評估。其二，資料來源 Infinigen 偏重自然場景與有機物體，對於 industrial design（工業設計）中常見的硬表面建模（hard-surface modeling）與 CAD 級精度涵蓋不足。其三，雖然 3DCodeArena 提供人類偏好排名，但大規模 pairwise human preferences 的蒐集成本高昂，且評判者間的 aesthetic appeal（美學吸引力）標準可能存在變異。

#### 可重現性評估

可重現性（Reproducibility）是基準測試論文的核心價值。作者明確聲明 release（釋出）3DCodeBench，包含 curated large-scale dataset（精選大規模資料集）、evaluation protocol（評估協定）以及 public 3DCodeArena platform（公開平台）。這對社群是重大貢獻，因為標準化的 triplets 與 seed-addressable 測試案例能確保不同研究團隊在相同條件下比較模型表現。

不過，從提供的文本脈絡觀察，仍有幾點值得注意：

- 程式碼執行環境：論文強調需要 robust execution environment（強健執行環境）與 high-fidelity feedback（高保真回饋），但並未詳細說明是否釋出完整的 Docker 化執行腳本或 Blender 自動化管線的原始碼。若僅釋出資料集與 Arena 平台，重現完整評估流程仍需社群自行建置 compiler（編譯器）與回饋迴路。

- 模型權重與 API：評估對象均為 proprietary frontier VLMs（GPT-5.5、Gemini 3.1 Pro、Claude Opus 4.7），其模型權重未公開，且商業 API 存在版本漂移（version drift）風險。這意味著其他研究者雖可使用相同 prompts 測試，但模型內部行為可能隨時間改變，長期可重現性受限。

- 授權與資料使用：資料集源自 Infinigen，其授權條款是否允許大規模再發布，以及 3DCodeBench 本身的授權條款，在提供的片段中未明確交代，這可能影響學術與商業應用的後續使用。

整體而言，3DCodeBench 在資料與評估標準化的釋出上已達高標準，但執行環境的完整開源程度與 proprietary model 的不可控性，仍是實務重現時的潛在挑戰。

#### 未來研究方向

基於本文的發現與侷限，未來研究可沿以下方向展開：

1. 高品質程序式編碼資料擴充：論文明確指出 commercial VLMs 亟需 high-quality procedural coding data。未來可探索 synthetic data generation（合成資料生成）結合 human-in-the-loop verification，或從現有 3D software（三維軟體）的歷史專案檔案中逆向提取程序式邏輯，以擴充訓練語料。

2. 多引擎與跨平台執行環境：將執行環境從 Blender 擴展至 Houdini、Maya、Unreal Engine 等，建立統一的 execution environment 標準。這需要標準化的 API abstraction layer（API 抽象層），讓 VLM agent 能透過 Model Context Protocol（MCP; 模型上下文協定）或 function-calling agent（函式呼叫代理）無縫切換工具。

3. 物理合理性自動檢測：開發專門的 automated metrics 以偵測 disconnected/floating components，例如整合物理引擎（如 Bullet、PhysX）進行結構穩定性模擬，或利用 graph-based topology validation（基於圖論的拓樸驗證）自動懲罰不合理的幾何結構。

4. 進階測試時擴展策略：除了增加 thinking budget，可引入 Monte Carlo Tree Search（MCTS）、beam search over code syntax trees，或讓模型在生成過程中主動查詢 API documentation（API 文件），以降低 API mismatch 機率。

5. 神經與程序式混合生成：結合 neural 3D generator（神經三維生成器）與程序式後處理，利用 VLM 將神經網路生成的粗略 mesh 轉換為 precisely editable（可精確編輯）的 procedural code，兼顧生成速度與 engine-ready（引擎就緒）特性。

6. 專家導向的感知評估：擴充 3DCodeArena，引入專業 3D artist（三維藝術家）的 domain-specific 評分，並細分 perceptual quality 為幾何精確度、拓樸整潔度、UV 映射品質等子維度，建立更細緻的人類偏好模型。

7. 多模態提示的精細對齊：提升 VLM 對 image reference（圖像參考）的幾何細節理解，發展專門的 cross-modal alignment（跨模態對齊）技術，使模型能從多視角圖像中推導出正確的 parametric relationships（參數關係），而非僅依賴文字描述。

這些方向共同指向一個願景：建立具備深層 geometric reasoning、能與專業 3D software 深度整合，並透過 iterative refinement 持續自我修正的通用程序式建模代理（General Procedural Modeling Agent）。

## 論文問答

**Q1：程序式三維建模目前面臨的核心挑戰是什麼？**
A：程序式三維建模雖然能產生確定性且可直接匯入引擎的數位資產，但其創作過程極度依賴人類設計師具備深厚的領域專業知識，包括熟稔三維軟體的應用程式介面、參數化設計邏輯以及程式碼層級的幾何推理能力。這種高門檻使得從無到有地撰寫能生成複雜網格、紋理與物理合理結構的程序碼，成為一項勞力密集且艱鉅的任務。因此，如何讓先進的視覺語言模型自動化地擔任程序式建模者，並系統性地評估其能力，成為本研究試圖解決的核心問題。

**Q2：現有的評估方法或基準測試存在哪些根本性的不足？**
A：現有方法主要面臨四大限制：首先，嚴重缺乏對齊的程序式資料，例如 ShapeNet 或 Objaverse 僅提供靜態網格而缺少底層生成程式碼；其次，現有環境未能捕捉真實世界的幾何複雜度，如 BlenderGym 偏重編輯預建場景，而 VoxelCodeBench 僅限於簡單的體素網格。第三，現有框架忽略了三維設計的迭代本質，多採用單次評估而省略了對真實工作流至關重要的代理精進迴圈；最後，該領域缺乏標準化的評估指標與共享的參考提示集，導致模型僅在臨時提示上測試，無法進行嚴謹比較。

**Q3：相較於神經三維生成器，程序式三維建模為何具有不可替代的重要性？**
A：透過程式碼進行程序式三維建模能產生確定性、引擎就緒且可精確編輯的數位資產，這些特性是神經三維生成器所固有的缺乏之處。神經生成模型雖然能快速產生視覺結果，但其輸出往往難以在參數或程式碼層級進行細緻調整，也無法保證每次生成的一致性與可重複性。相較之下，程序式程式碼不僅允許設計師透過修改參數來迭代調整幾何形狀與紋理，更能直接整合至遊戲、工業設計與機器人訓練等商業管線中，具備極高的實用價值。

**Q4：3DCodeBench 的核心架構與組成要素為何？**
A：3DCodeBench 是一個針對視覺語言模型代理的程序式三維生成基準測試，其核心包含一個經由代理式策展管線與人工驗證精選而成的大規模資料集，涵蓋兩萬六千組多模態提示、獨立程式碼與三維物體三元組，橫跨兩百一十二個語義類別。該基準搭配了全面的自動化評估協定，從可執行性、感知視角相似度到三維幾何對齊等多個維度進行量化分析。此外，研究團隊還建構了 3DCodeArena 公開排名平台，透過成對人類偏好比較來建立可靠的 Elo 排名，以補足自動化指標在感知品質上的不足。

**Q5：3DCodeBench 相較於先前研究的主要創新之處為何？**
A：本研究的主要創新在於首次系統性地將視覺語言模型視為主動代理而非單次生成器，並在受控的多輪情境中評估其能力，包括執行錯誤回饋、重試、視覺自我批判與應用程式介面文件擴增。不同於僅測試簡單原始形狀或單次提示的現有基準，3DCodeBench 從 Infinigen 提取真實複雜的工廠級程序，例如飛鳥、螃蟹與蜻蜓等類別，平均程式碼長度超過四百行，能真正考驗模型的幾何推理深度。同時，結合自動化指標與 3DCodeArena 的人類偏好投票，建立了首個涵蓋客觀幾何對齊與主觀感知美學的標準化評估框架。

**Q6：為何研究團隊選擇採用多輪代理精進與人類偏好排名作為評估設計？**
A：研究團隊選擇多輪代理精進，是因為真實世界的三維設計本質上就是高度迭代的過程，設計師需要根據執行結果反覆調整參數與結構，單次評估無法反映模型在實際工作流中的真正潛力。透過引入執行環境的高保真回饋，例如 Blender 的確定性執行錯誤訊息與渲染結果，模型得以在測試時進行擴展，利用多輪對話修正程式碼。至於人類偏好排名，則是因為自動化指標雖能衡量幾何距離與視覺相似度，卻難以完整捕捉人類對三維形狀感知品質與美學吸引力的細微判斷，因此需要 3DCodeArena 的成對比較來建立更貼近人類感知的 Elo 排名。

**Q7：實驗中採用了哪些自動化指標與評估平台來衡量模型表現？**
A：實驗採用了多層次的自動化指標，包括基礎的可執行性評估、基於 SigLIP-2 與 DINOv3 的感知視角相似度，以及用於三維幾何對齊的 Chamfer 距離與 Uni3D 特徵比對。這些指標從語法正確性、二維渲染感知到三維空間結構等不同層面，提供了全面的量化分析。為了補充自動化指標的盲點，研究團隊進一步推出了 3DCodeArena 公開平台，該平台透過收集使用者對生成三維成果的成對偏好比較，計算出可靠的 Elo 積分排名，從而反映人類主觀的感知品質與幾何合理性。

**Q8：在評估十二個前沿視覺語言模型後，有哪些關鍵的整體發現？**
A：廣泛評估後發現，即使模型能成功執行程式碼，物理合理性仍然是超越可執行性之外的主要瓶頸，因為生成的三維物體經常出現斷開或浮動的幾何元件，顯示模型嚴重缺乏對物理世界結構連貫性的理解。此外，失敗案例大多源於應用程式介面不匹配，即模型生成的程式碼呼叫了錯誤或過時的函式，反映出高品質程序式編碼資料的不足。整體而言，不同模型在幾何推理能力上存在顯著差異，如 GPT-5.5、Gemini 3.1 Pro 與 Claude Opus 4.7 在處理複雜類別時展現出不同程度的結構完整性與細節掌握能力。

**Q9：關於測試時擴展與多輪精進的實驗揭示了什麼樣的結果？**
A：實驗明確顯示測試時擴展策略，例如提高思考預算與進行多輪迭代精進，能夠整體提升模型的程序式三維生成表現，這證明了設計適當的代理框架來處理環境回饋對於釋放模型潛能至關重要。具體而言，當模型獲得 Blender 的確定性執行回饋，並結合視覺自我批判與應用程式介面文件擴增時，其修正錯誤與改善幾何結構的能力顯著增強。這項發現凸顯了單次生成評估的侷限性，並強調在建構未來的編碼代理時，必須將高保真、可迭代的執行環境作為核心基礎設施。

**Q10：這項研究在哪些實際應用場景中具有潛在價值？**
A：程序式三維建模的自動化在遊戲開發、工業設計與高保真機器人訓練模擬環境等領域具有巨大的商業價值，因為這些產業迫切需要大量確定性且可精確編輯的數位資產。透過視覺語言模型代理直接驅動 Blender 等軟體的 Python 應用程式介面，設計師與開發者得以用自然語言快速原型化複雜的三維物件，大幅降低手動編寫領域特定語法的門檻。此外，在需要嚴格物理合理性與參數化控制的場景中，例如生成用於模擬的家具、生物或工業零件，本基準所驗證的多輪精進能力可確保產出符合管線需求的引擎就緒資產。

**Q11：對於現有的創意產品與生態系統，這項研究帶來了哪些產品層面的啟示？**
A：本研究直接呼應了 Anthropic 的 Claude for Creative Work 計畫以及日益活躍的模型上下文協定伺服器生態系統，這些產品試圖將前沿視覺語言模型轉化為三維軟體的自然語言驅動介面。研究結果指出，要讓這類產品真正實用，必須優先解決應用程式介面不匹配問題，並建立能即時提供高保真回饋的穩健執行環境，而非僅僅依賴模型的單次生成能力。對於商業視覺語言模型而言，這也意味著需要投入更多高品質的程序式編碼資料進行訓練，以提升模型在複雜幾何推理與物理結構理解上的表現，從而滿足專業創意工作流的需求。

**Q12：3DCodeBench 與 3DCodeArena 的釋出將如何影響相關研究領域的發展？**
A：3DCodeBench 與 3DCodeArena 的釋出為學界與業界提供了一個標準化且可復現的基礎工具包，填補了長期以來在評估視覺語言模型程序式三維生成能力上的空白。透過提供兩萬六千組經過驗證的多模態提示與程式碼三元組，以及涵蓋自動化指標與人類偏好排名的雙軌評估協定，後續研究得以在統一的基準上公平比較不同模型的進展。這不僅能加速演算法的迭代創新，更能引導社群聚焦於物理合理性、迭代精進與感知品質等關鍵挑戰，推動視覺語言模型從單純的程式碼生成器邁向真正可靠的創意代理。

**Q13：作者在論文中承認了哪些方法或評估上的侷限性？**
A：作者明確指出，自動化指標可能無法完全捕捉三維形狀的感知品質與美學細節，因此才需要透過 3DCodeArena 的人類偏好排名來補充客觀數據的不足。此外，儘管資料集涵蓋了兩百一十二個類別，但程序式三維建模的無限可能性意味著基準仍無法窮盡所有真實世界的幾何與語義複雜度。研究也暗示，目前對於多輪精進的評估雖然證明了其效益，但如何設計最優的代理框架與回饋機制，仍然是一個需要更多探索的開放問題。

**Q14：在實驗觀察到的失敗案例中，最主要的失敗模式為何？**
A：最主要的失敗模式可歸類為兩大類：首先是應用程式介面不匹配，即模型生成的 Python 程式碼呼叫了錯誤的函式名稱、參數或使用了已棄用的語法，導致程式無法在 Blender 中順利執行。其次，即使程式碼成功執行並渲染出視覺結果，生成的三維物體仍普遍存在物理不合理的結構缺陷，例如幾何部件之間彼此斷開、浮動未連接，或是整體結構對齊錯誤。這些失敗模式共同揭示了當前視覺語言模型在底層應用程式介面知識與高階物理世界幾何推理之間存在顯著的能力落差。

**Q15：根據研究發現，未來應該朝哪些方向推進以提升視覺語言模型的程序式三維建模能力？**
A：未來的首要方向是建構高品質的程序式編碼資料集，因為研究發現當前模型的許多錯誤根源在於缺乏足夠且準確的三維軟體應用程式介面與幾何推理訓練資料。其次，必須開發更穩健的執行環境，能夠提供高保真的視覺與幾何回饋，以支援模型在測試時進行有效的迭代精進與錯誤修正。最後，結合更強大的代理框架來整合執行錯誤、視覺自我批判與外部文件檢索，將是釋放商業視覺語言模型在程序式三維建模上全部潛力的關鍵路徑。

## 實務應用指南

### 適用場景

1. **遊戲資產快速原型開發**：美術團隊可透過自然語言或概念圖驅動 VLM 代理，自動產出 Blender Python 等程序式代碼，快速生成確定性且可精確編輯的 3D 網格與紋理，大幅縮短關卡白盒與迭代週期。
2. **機器人訓練與高保真模擬環境建置**：參考 3DCodeBench 從 Infinigen 提取資產的方法，自動批次生成具物理合理性的三維物體與場景，直接匯入模擬引擎作為引擎就緒的訓練資料。
3. **工業設計參數化建模**：將設計規格書轉為多模態提示，由代理生成參數化設計代碼，設計師可於程式碼層級微調幾何尺寸，確保製造可行性與結構對齊。
4. **電商與行銷 3D 內容自動化**：從商品圖片與文字描述生成端到端程序式模型，輸出輕量網格供網頁即時渲染，降低手動建模成本並確保品牌資產風格一致。
5. **建築與室內設計視覺化驗證**：設計師以文字或參考圖透過自然語言驅動介面觸發代理，生成 SketchUp 或 Blender 程序式物件進行空間配置與語義類別驗證，加速設計溝通。

### 實作前置條件

**資料需求**：
- 多模態提示資料：蒐集目標領域的文字描述與參考圖像對。
- 領域特定編碼語法與 API 文件：目標 3D 軟體（如 Blender）的 Python API 文件、MCP 伺服器規格，以及內部資產庫範例。
- 程序式編碼資料：建議參考 Infinigen 等現有程序式工廠，或整理內部歷史專案腳本，作為精選大規模資料集的基礎。

**運算需求**：
- 具備 GPU 的伺服器或工作站，用於 VLM 推論與 Blender 無頭模式（headless）執行、渲染。
- 支援多輪對話與視覺回饋的代理框架運算資源，以承載測試時擴展所需的思考預算。

**技能需求**：
- 熟悉 Blender 等 3D 軟體的 Python API 與幾何推理邏輯。
- 具備建置函式呼叫代理或 MCP 整合經驗，能設計執行環境與錯誤回饋迴路。
- 基礎參數化設計與三維幾何連通性檢查能力。

### 實作步驟建議

1. **建置高保真執行環境**：部署 Blender 等軟體的自動化執行容器，確保能批次執行生成代碼、捕捉 Traceback 錯誤、輸出多視角渲染圖，並將這些高保真回饋結構化供代理讀取。
2. **策展資料集**：仿照 3DCodeBench 的代理式策展流程，從 Infinigen 等來源提取程序式工廠，經人工驗證建立「多模態提示 ↔ 獨立程序碼 ↔ 三維物體」三元組，覆蓋目標應用的核心語義類別。
3. **開發多輪精進代理**：選定前沿視覺語言模型（如 GPT-5.5、Gemini 3.1 Pro 或 Claude Opus 4.7），設計包含「執行錯誤回饋 → 重試 → 視覺自我批判 → API 文件擴增」的迭代精進迴圈，而非僅做單次生成。
4. **建立雙軌評估機制**：導入自動化指標（可執行性、Chamfer 距離、Uni3D 幾何對齊、SigLIP-2 / DINOv3 感知相似度）進行批次篩選；同時針對商業關鍵應用，建置內部版 3DCodeArena，透過成對人類偏好建立 Elo 排名，校準感知品質。
5. **整合至生產管線**：將驗證後的編碼代理封裝為自然語言驅動介面，接入現有內容管理系統，並保留種子可定址的測試集與版本控制，確保後續模型更新時可追溯迴歸問題。

### 潛在風險與注意事項

1. **API 不匹配導致執行失敗**：模型常生成已棄用或參數錯誤的 API 呼叫。務必於提示中注入當前版本 API 文件，並在執行環境中即時回傳錯誤訊息給代理進行多輪修正。
2. **幾何結構缺陷**：成功渲染的結果仍可能出現浮動元件或斷開元件，缺乏物理合理性。建議於每輪渲染後自動執行幾何連通性與碰撞檢查，並將視覺化截圖納入代理的自我批判提示。
3. **過度依賴單輪生成**：複雜類別（如螃蟹、蜻蜓）平均需四百行以上代碼，單次提示難以到位。應規劃充足的思考預算與多輪精進機制，將測試時擴展視為核心策略而非選配。
4. **自動化指標與人類感知落差**：SigLIP-2 等指標無法完全捕捉美感與結構合理性。商業部署時，必須保留人工審核閘道，或建立領域專屬的成對偏好排名流程。
5. **軟體版本相依性**：Blender 版本更新可能導致既有程序碼失效。需建立持續整合流程，定期以種子可定址的測試集驗證代理輸出於新版本的相容性。

### 與其他技術的整合建議

1. **與神經三維生成器協作**：以 VLM 代理產出的程序式代碼作為可精確編輯的基礎骨架與 UV 結構，再透過神經網路生成高頻紋理與微表面細節，兼顧確定性與視覺豐富度。
2. **接入數位孿生與模擬引擎**：將代理輸出的引擎就緒資產直接匯入 Unity、Unreal 或 NVIDIA Omniverse，利用即時物理模擬提供高保真回饋，形成「生成 → 模擬 → 精進」的閉環。
3. **檢索增強生成（RAG）**：連接內部資產庫、API 文件與歷史成功範例，讓代理在生成前檢索相似結構與正確語法，顯著降低 API 不匹配率。
4. **MLOps 與版本控制**：將程序式代碼納入 Git 管理，並使用 MLflow 等工具追蹤不同 VLM 版本、提示策略與 Elo 排名的變化，實現代理效能的 A/B 測試與漸進式部署。
5. **低程式碼設計平台封裝**：將後端代理封裝為視覺化節點或對話式 UI，讓非程式背景的設計師透過自然語言驅動介面觸發複雜的參數化建模流程。

### 給不同背景讀者的閱讀建議

**初學者**：建議從圖一的系統架構與適用場景開始，先建立「多模態提示 → 程序碼 → 三維物體」的直覺流程，再透過 3DCodeArena 的 Elo 排名概念理解不同模型優劣，無需立即深入 Chamfer 距離或 Uni3D 等技術細節。

**AI 工程師**：重點關注多輪精進架構與執行環境的整合實作，包括如何將 Blender Traceback 與渲染截圖轉為結構化回饋、設計視覺自我批判的提示模板，以及測試時擴展（思考預算與重試機制）的參數調校。

**研究人員**：深入分析論文發現的兩大核心議題——物理合理性瓶頸與測試時擴展的顯著效益，並參考 3DCodeBench 的評估協定設計後續實驗。可延伸探討如何透過高品質程序式編碼資料與更強大的幾何推理能力來突破現有前沿視覺語言模型的天花板。

**產品經理**：聚焦商業價值與風險權衡，理解自動化指標與人類感知品質之間的落差，評估導入多輪代理流程對現有產品開發週期的影響，並規劃從概念驗證到生產環境所需的資料策展、執行環境建置與人工審核資源。
