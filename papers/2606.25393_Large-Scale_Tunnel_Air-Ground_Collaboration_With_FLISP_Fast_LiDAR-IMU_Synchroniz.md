## 摘要翻譯

水電隧道巡檢對於基礎設施完整性至關重要，然而採用人工方法仍顯低效且具危險性。我們提出 FLISP（快速 LiDAR-IMU 同步路徑規劃器），一種用於協作式 UGV-UAV 巡檢的無地圖規劃框架。與傳統基於地圖的典範不同，FLISP 具備三項核心貢獻：（1）統一架構，其中單一 UGV 搭載式 LiDAR-IMU（光達-慣性測量單元）套件可驅動兩個平台的同步路徑生成；（2）平台專用求解器，利用增強型螢火蟲演算法進行 UGV 避障，並使用動態迭代最佳化器進行 UAV 飛行規劃；以及（3）階層式細化策略，確保運動學可行性，同時避免狀態估計飄移。在長達 1.2 公里的營運中隧道所進行的基準測試顯示，FLISP 可規避基於地圖方法的結構性瓶頸，消除地圖柵格化開銷（Fast-LIO2 + A*）與取樣不穩定性（LIO-SAM + RRT*）。FLISP 達到 100% 成功率，延遲時間僅 7 ms，相較於基於網格的基線方法實現 7 倍加速，相較於基於取樣的基線方法則改善幅度達三個數量級。經過營運中水電隧道驗證，此方法為特徵退化線性基礎設施中的機器人巡檢提供可擴展的解決方案。展示影片與程式碼分別可於 https://youtu.be/Y_ezs1PfLJ4 及 https://github.com/ArchibaldGuo/FLISP.git 取得。

### 核心貢獻（3～5點）
- 統一架構：以單一 UGV 搭載式 LiDAR-IMU（光達-慣性測量單元）套件驅動雙平台同步路徑生成。
- 平台專用求解器：採用增強型螢火蟲演算法實現 UGV 避障，並以動態迭代最佳化器進行 UAV 飛行規劃。
- 階層式細化策略：確保運動學可行性，同時避免狀態估計飄移。

### 適合對象
從事機器人學、自主導航、基礎設施智慧巡檢，以及異質多機器人協同控制之研究人員與工程師；特別適合關注 GPS 拒止環境、感知退化場域（如隧道與線性基礎設施）即時路徑規劃與強健定位之讀者。

## 深度分析

#### 方法論解析

FLISP（Fast LiDAR-IMU Synchronized Path Planner，快速 LiDAR-IMU 同步路徑規劃器）的核心在於建立一套 Mapless Planning Framework（無地圖規劃框架），專為 Cooperative UGV-UAV Inspection（協作式 UGV-UAV 巡檢）設計。與傳統 Map-based Paradigms（基於地圖的典範）不同，FLISP 採用 Unified Architecture（統一架構），僅以單一 UGV-mounted LiDAR-IMU Suite（UGV 搭載式 LiDAR-IMU 套件）作為環境感知中樞，透過局部幾何資訊同時驅動 UGV（無人地面載具）與 UAV（無人飛行載具）的 Synchronized Path Generation（同步路徑生成）。這種設計從根源上消除了 SLAM 長期累積的 State Estimation Drift（狀態估計飄移），並將運算負載集中於地面端，使空中端僅需執行輕量化的軌跡追蹤，形成垂直整合的 Asymmetric Collaboration（非對稱協作）模型。

在求解器層級，FLISP 針對異質平台特性設計了 Platform-Specific Solvers（平台專用求解器）。對於 UGV，論文提出 Enhanced Firefly Algorithm（增強型螢火蟲演算法），將 Debris-Covered Surfaces（覆蓋碎屑的表面）、彎曲路徑與不平整地形等約束編碼為多目標最佳化問題，實現 UGV Obstacle Avoidance（UGV 避障）與路徑平滑的權衡。對於 UAV，則採用 Dynamic Iterative Optimizer（動態迭代最佳化器），在 UGV 提供的局部幾何邊界內，針對閘門等固定基礎設施進行 UAV Flight（UAV 飛行）路徑的即時修正。

為確保輸出軌跡可直接執行，FLISP 引入 Hierarchical Refinement Strategy（階層式細化策略）。該策略在路徑生成後進行多層級的 Kinematic Feasibility（運動學可行性）檢驗與細化，避免純反應式規劃常見的運動學不一致與拓撲死鎖。整體而言，FLISP 形成一條從感知、規劃到控制的統一管線，將「無地圖」理念從狀態估計延伸至 Multiple Agents（多智能體）協同控制層，並透過 Hierarchical Dependency 使地面感知層直接驅動輕量化的空中路徑生成。

#### 實驗數據解讀

論文在長達 1.2 km 的 Operational Tunnel（營運中隧道）進行全尺度部署，該場域具備典型的 GPS-Denied（GPS 拒止）、Repetitive Textures（重複紋理）與 Feature-Degraded Linear Infrastructure（特徵退化線性基礎設施）特性。實驗設計對照兩類 Structural Bottlenecks（結構性瓶頸）顯著的基線方法：其一為 Grid-Based（基於網格的）方法 Fast-LIO2 + A*，其瓶頸在於 Map Rasterization Overhead（地圖柵格化開銷）；其二為 Sampling-Based Baselines（基於取樣的基線方法）LIO-SAM + RRT*，其瓶頸在於 Sampling Instability（取樣不穩定性）。

數據顯示 FLISP 達到 100% Success Rate（成功率），且規劃 Latency（延遲時間）僅約 7 ms。相較於 Grid-Based 基線，FLISP 實現 7-fold Speedup（7 倍加速）；相較於 Sampling-Based Baselines，效能提升達 Three-Order-of-Magnitude Improvement（三個數量級的改善）。這些數據具有兩層深層意義：首先，7 ms 的延遲已遠低於一般機器人控制迴路的週期（通常為 10–20 ms 以上），代表規劃器可在硬即時（hard real-time）條件下運行，幾乎不對控制迴路造成相位延遲；其次，100% 成功率在 1.2 km 長距離驗證中，證明無地圖策略並未因缺乏全局拓撲而犧牲強健性，反而規避了地圖維護所帶來的累積誤差與計算抖動，顯示其在 Hydropower Tunnel Inspection（水電隧道巡檢）場景的實用成熟度。

#### 與現有研究的比較

在定位與規劃文獻中，現有方法大致可分為全局地圖中心與純反應式兩大類。傳統 Map-based Paradigms（如 DARPA SubT 中採用的 SLAM 方法）依賴全局一致性地圖，對於線性、重複幾何環境，維護全局地圖不僅 Computationally Prohibitive（計算成本高昂），更易因特徵退化而產生災難性建圖失敗。Özaslan et al. 雖針對單機 MAV 建立管線，但其地圖中心框架無法解決 Endurance（續航力）限制，亦不適用於 Collaborative Heterogeneous Robotic System（協作式異質機器人系統）。FLISP 透過 Mapless Planning Framework（無地圖規劃框架）與 Asymmetric Collaboration（非對稱協作）模型，直接繞過上述結構性瓶頸。

相較於純反應式局部規劃器（如 APF、DWA），FLISP 的 Hierarchical Refinement Strategy（階層式細化策略）有效解決了 Topological Deadlocks（拓撲死鎖）與運動學不一致問題，這在盲彎（blind curves）場景中尤為關鍵。與近年啟發式取樣法（如 HA-RRT）相比，FLISP 不屬於取樣基礎方法，因此不受 Sampling Instability（取樣不穩定性）影響，其 7 ms 延遲與三個數量級的效能優勢，顯示其計算複雜度已脫離傳統取樣法的機率收斂框架。

然而，FLISP 仍存在若干限制。首先，系統採用 UGV-centric 的集中式感知，單一 UGV-mounted LiDAR-IMU Suite（UGV 搭載式 LiDAR-IMU 套件）構成潛在單點故障；一旦地面端定位因劇烈顛簸或幾何退化而失效，UAV 的 Synchronized Path Generation（同步路徑生成）亦將中斷。其次，UAV 本身不具獨立環境感知能力，當 UGV 與 UAV 間存在嚴重視線遮蔽（如穿越閘門或進入支洞）時，空中路徑的即時性與安全性可能受限。此外，論文未明確探討動態障礙物（如水流、落石或維修人員）的處理機制，這在實際 Operational Tunnel（營運中隧道）環境中是不可忽視的安全議題。

#### 可重現性評估

論文於摘要與引言中明確承諾開源釋出：原始碼（source code）已公開於 GitHub（https://github.com/ArchibaldGuo/FLISP.git）；Demonstration Video（示範影片）提供 YouTube 連結（https://youtu.be/Y_ezs1PfLJ4）；並釋出 curated representative LiDAR-IMU Dataset，涵蓋隧道中關鍵幾何退化場景。

從可重現性角度評估，軟體層面的透明度較高，但硬體與場域門檻顯著。復現 FLISP 需具備 UGV-UAV 異質平台，且 UGV 需搭載特定 LiDAR-IMU（光達-慣性測量單元）硬體。對於僅有單一平台或不同感測器配置的研究者，硬體複現成本較高。此外，1.2 km 營運中隧道屬於特殊 Civil Infrastructure（民用基礎設施），一般實驗室難以複製相同場域；雖有資料集釋出，但目前尚不清楚該資料集是否包含完整 1.2 km 連續數據，或僅為離散代表性片段。論文未提及是否提供模擬器（simulator）設定檔（如 Gazebo/Unity 世界檔案），這對於無法進入實隧道的研究者至關重要。由於方法核心為傳統最佳化演算法而非深度學習，故無 model weights（模型權重）釋出之需求，理論上只要程式碼完整即可重現規劃邏輯。

#### 未來研究方向

基於 FLISP 的無地圖架構與其現有侷限，未來研究可沿以下方向展開：

1. **分散式感知與非對稱協作之平衡**：目前完全依賴 UGV 作為感知中樞，未來可讓 UAV 搭載輕量 LiDAR 或視覺感測器，形成分散式感知（distributed perception），在維持低 Latency（延遲時間）的同時降低單點故障風險。

2. **動態環境下的即時規劃**：將動態障礙物預測（如水流、落石、移動人員）整合至 Enhanced Firefly Algorithm（增強型螢火蟲演算法）與 Dynamic Iterative Optimizer（動態迭代最佳化器）中，發展時空聯合最佳化（spatio-temporal optimization）能力。

3. **Multiple Agents（多智能體）規模化擴展**：當前架構聚焦單一 UGV-UAV 配對，未來可擴展至多 UGV 與多 UAV 編隊，以覆蓋更寬廣的隧道斷面或執行並行巡檢任務，需解決通訊拓撲與任務分配問題。

4. **跨域線性基礎設施驗證**：將 FLISP 驗證於地下管廊、地鐵隧道、礦井巷道等不同 Feature-Degraded Linear Infrastructure（特徵退化線性基礎設施），評估其幾何泛化能力與參數自適應調整機制。

5. **邊緣運算與硬體在環整合**：進一步將 Latency（延遲時間）壓縮至亞毫秒級，或將規劃器部署於嵌入式邊緣運算單元（edge computing），並透過硬體在環（hardware-in-the-loop）模擬極端退化場景。

6. **人機協作與可解釋性介面**：整合數位孿生（digital twin）或擴增實境（AR）介面，使遠端工程師可視化無地圖規劃器的局部幾何決策邏輯，並在緊急狀況下進行人為介入（human-in-the-loop），提升 Hydropower Tunnel Inspection（水電隧道巡檢）的實務接受度。

## 論文問答

**Q1：FLISP 旨在解決水電隧道巡檢中的什麼核心問題？**
A：FLISP 主要針對傳統人工巡檢在大型水電隧道中效率低下且高度危險的問題，這類作業不僅勞力密集，還容易因人為主觀誤差而影響結構健康評估的準確性。論文指出，在狹窄、GPS 拒止且感知退化的隧道環境中，人員安全與資料品質皆難以保障。因此，亟需自動化機器人解決方案來取代人工方法，以提升安全性與檢測一致性。

**Q2：為何傳統的基於地圖路徑規劃方法在隧道環境中會失效？**
A：傳統基於地圖的典範必須維護全局一致性地圖，但在紋理重複、幾何特徵退化的長線性隧道中，這不僅容易產生狀態估計飄移，計算成本也極為高昂。以 Fast-LIO2 結合 A* 為例，其受困於地圖柵格化開銷；而 LIO-SAM 結合 RRT* 則存在取樣不穩定性。這些結構性瓶頸使得傳統方法難以勝任長距離、即時的隧道巡檢任務。

**Q3：協作式 UGV-UAV 巡檢對隧道環境為何特別重要？**
A：單一無人地面載具無法觸及隧道拱頂，而單一無人飛行載具則受限於續航力，且難以在覆蓋碎屑的崎嶇地面穩定移動。透過異質機器人系統的協作，可以結合 UGV 的地面機動性與 UAV 的空中作業能力，實現對隧道結構更全面的檢視。這種互補協同是確保大型基礎設施完整性評估完整性的關鍵。

**Q4：FLISP 的核心架構是什麼？它與傳統多機器人系統有何不同？**
A：FLISP 採用統一的 UGV 中心化非對稱協作模型，僅以一套搭載於 UGV 上的 LiDAR-IMU 套件驅動雙平台的同步路徑生成。不同於傳統鬆耦合多機器人系統各自獨立規劃或依賴全局地圖，FLISP 在 UGV 上集中處理局部幾何資訊，建立階層式依賴關係。這種無地圖規劃框架從根本上消除了 SLAM 固有的飄移累積，並顯著降低了整體運算負擔。

**Q5：FLISP 的三項核心貢獻為何？**
A：第一項是統一架構，以單一感測器套件實現雙平台同步路徑生成；第二項是平台專用求解器，針對 UGV 採用增強型螢火蟲演算法進行避障，並以動態迭代最佳化器處理 UAV 飛行軌跡；第三項則是階層式細化策略，在不依賴狀態估計飄移的前提下確保運動學可行性。這三項創新環環相扣，使系統能在特徵退化的惡劣環境中維持即時且強健的導航表現。

**Q6：作者為何選擇無地圖策略，而非傳統的基於地圖方法？**
A：作者選擇無地圖策略，是因為在長線性隧道中維護全局一致性地圖既容易產生飄移，計算量也大到難以負荷。若改採純反應式局部規劃，雖可省去建圖開銷，卻容易在盲彎處陷入拓撲死鎖或運動學不一致的困境。FLISP 的設計則透過局部幾何資訊與階層式細化，在迴避地圖維護成本的同時，確保多智能體協調與路徑可行性。

**Q7：FLISP 使用了哪些基線方法進行比較？實驗在何種環境中進行？**
A：FLISP 與兩類基於地圖的基線方法進行比較，分別是網格類的 Fast-LIO2 + A* 與取樣類的 LIO-SAM + RRT*。實驗於一條長達 1.2 公里的營運中水電隧道內進行，該環境具備真實的感知退化與結構挑戰。這些基線方法代表了 FLISP 試圖克服的結構性瓶頸，為評估無地圖架構的優勢提供了嚴謹的對照基礎。

**Q8：FLISP 的關鍵量化實驗結果為何？**
A：在 1.2 公里營運隧道的測試中，FLISP 達成了 100% 的成功率，且延遲時間僅約 7 毫秒。相較於網格類基線，這相當於 7 倍的速度提升；相較於取樣類基線，則達到三個數量級的效能躍進。這些結果證實 FLISP 成功消除了地圖柵格化開銷與取樣不穩定性，實現了真正的即時規劃。

**Q9：作者如何驗證 FLISP 在標準比較之外的強健性？**
A：除了與基線方法的比較，作者還透過大量模擬以及在真實 1.2 公里水電隧道中的全規模部署來驗證系統。此外，團隊公開了原始碼以及精心整理的 LiDAR-IMU 資料集，該資料集捕捉了隧道中關鍵的幾何退化情況。這種結合真實場域驗證與資料開放的策略，充分確保了研究成果的可重現性與實務可靠性。

**Q10：FLISP 在水電隧道內的哪些具體作業場景中最具效益？**
A：FLISP 特別適用於 GPS 拒止、感知退化且空間狹窄的輸水隧道，例如照明不足、紋理單調且地面崎嶇的區段。它在需要同時進行地面移動於淤泥堆積表面，以及空中檢視隧道拱頂或繞行閘門等結構障礙的任務中表現優異。系統的即時反應能力使其非常適合取代高風險、耗時的例行人工巡檢作業。

**Q11：在實際部署 FLISP 時，涉及哪些硬體與系統考量？**
A：FLISP 僅需在 UGV 上安裝一套 LiDAR-IMU 套件，無需為 UAV 額外配置複雜感測器，有效降低了整體硬體成本與載重負擔。非對稱協作模型意味著 UGV 同時扮演感知與運算中樞的角色，而 UAV 則執行輕量化的路徑生成。這種集中式架構簡化了現場部署的後勤需求，也便於日後在大型民用基礎設施中的維護與擴展。

**Q12：FLISP 可能如何改變基礎設施巡檢與維護領域？**
A：FLISP 提供了一個可擴展的機器人解決方案，能夠取代傳統勞力密集且危險的隧道人工巡檢。憑藉極低的延遲與高成功率，它使頻繁且一致的結構健康評估成為可能，同時避免人員暴露於惡劣環境的風險。這項技術將有助於永續能源管理，確保水電等關鍵基礎設施的長期完整性與營運安全。

**Q13：FLISP 的性能仍可能受到哪些已知的結構或環境限制？**
A：儘管 FLISP 迴避了全局地圖飄移，其性能仍高度依賴 UGV 搭載式 LiDAR-IMU 所獲取的局部幾何品質。在極端特徵退化的區段，即使局部幾何資訊也可能過於稀疏，進而影響避障與規劃的可靠性。此外，由於系統採用非對稱依賴架構，一旦 UGV 發生故障，整個團隊的路徑規劃能力將隨之癱瘓。

**Q14：文中討論或暗示了哪些潛在的失效案例或死鎖情境？**
A：作者指出，若缺乏適當同步機制，純反應式局部規劃器容易在盲彎處陷入拓撲死鎖與運動學不一致的問題。雖然 FLISP 的階層式細化策略大幅緩解了此風險，但面對嚴重幾何退化或突發動態障礙時，平台專用求解器仍可能遭遇挑戰。文中提及附錄進一步詳述這些情境，顯示作者已正視複雜隧道幾何中的邊緣案例。

**Q15：作者暗示了哪些未來研究方向或系統擴展的可能性？**
A：作者暗示未來可將 FLISP 擴展至應對動態障礙物，而不僅限於靜態隧道結構，並進一步提升在極端幾何退化下的強健性。引入額外感測模態，或從嚴格的 UGV 中心化感知轉向某種程度的分散式感知，也有助於增強系統韌性。將此無地圖協作典範推廣至更長的隧道網路，或適用於管線、礦井等其他線性基礎設施，亦是極具潛力的後續發展方向。

## 實務應用指南

### 適用場景

1. **水力發電輸水隧道結構巡檢**：適用於公里級、GPS 拒止且紋理單一的營運中隧道，由無人地面載具（UGV）搭載 LiDAR-IMU 套件於淤積或濕滑地面行進，並同步引導無人飛行載具（UAV）檢視拱頂與閘門等結構，取代傳統人工巡檢。
2. **城市地下綜合管廊維運**：針對電力、通信或燃氣管廊等線性基礎設施，利用 FLISP 的無地圖特性，避免在狹長空間中建置全域地圖所產生的累積飄移與儲存開銷，實現多艙室連續巡檢。
3. **礦井運輸巷道與通風隧道監測**：在粉塵遮蔽、光照不足且表面碎屑覆蓋的退化環境中，透過 UGV 端即時局部幾何提取，為 UAV 生成避開管線與支護結構的飛行軌跡，提升災害預警效率。
4. **交通隧道震後或火災後快速勘查**：災後結構可能產生變形或散落障礙物，FLISP 無需預先柵格化地圖即可在 7 ms 內生成避障路徑，適合分秒必爭的應急場景。
5. **大型工業管廊（石化、污水）內部檢測**：在特徵退化的圓形或馬蹄形管道中，以單一感測器套件驅動雙平台協作，降低防爆環境下的感測器數量與系統複雜度。

### 實作前置條件

**資料需求**
- UGV 搭載式 LiDAR-IMU 套件原始數據：建議採用機械式或多線光達（如 Livox、Ouster、Velodyne 系列），搭配六軸以上 IMU，並具備 PTP/gPTP 硬體時間同步能力。
- 平台運動學參數：UGV 輪距、最小轉彎半徑、最大爬坡角；UAV 最大俯仰角、偏航速率、旋翼動態響應限制。
- 場域先驗資訊：隧道設計斷面尺寸、閘門與避車洞位置、已知淤積區高程範圍，用於初始化與安全餘量設定。

**運算需求**
- UGV 邊緣運算單元：建議 NVIDIA Jetson AGX Orin 或同等算力，用於即時點雲處理、增強型螢火蟲演算法與動態迭代最佳化器運算。
- UAV 飛控硬體：需支援 offboard/offboard-like 控制模式，姿態控制頻率 ≥ 50 Hz，並預留頻寬接收 UGV 傳輸的局部路徑骨架。
- 機間通訊：5 GHz Wi-Fi、私有 LTE 或 5G 專網，端對端延遲須穩定低於 20 ms，以確保同步路徑生成時效。

**技能需求**
- 具備 ROS/ROS2 系統整合與節點除錯經驗。
- 熟悉 LiDAR-IMU 外參標定（手眼標定或基於運動的標定）與時間同步配置。
- 掌握非線性最佳化基礎、群體智慧演算法參數調校，以及 UAV 飛控韌體（PX4/ArduPilot）參數調整。

### 實作步驟建議

1. **感測器部署與時空標定**：將 LiDAR-IMU 套件剛性安裝於 UGV 前側上方，確保視野不受車體遮擋；執行外參標定與硬體時間同步，驗證點雲與 IMU 數據幀對齊誤差小於 5 ms。
2. **局部幾何管線建置**：實作 FLISP 前處理模組，從原始點雲提取地面高程、隧道軸線、側壁與障礙物邊界，建立輕量局部特徵表達（如掃描幀內的佔據邊界與可通行走廊），避免進行全域地圖柵格化。
3. **雙平台求解器實作與驗證**：於 UGV 端部署增強型螢火蟲演算法，以多目標適應度函數（避障、貼近隧道中線、能量消耗）生成地面路徑；於 UAV 端實作動態迭代最佳化器，接收 UGV 傳來的局部幾何與路徑骨架，生成具動態可行性的三維軌跡。先在 Gazebo/Unity 隧道模擬環境中驗證同步機制。
4. **階層式細化與運動學約束整合**：加入階層式細化策略，對 UGV 路徑施加非完整約束檢查（曲率、輪速限制），對 UAV 軌跡施加加速度與角速度限制；確保兩平台路徑在時空上無碰撞，並透過硬體在環（HIL）測試驗證。
5. **場域漸進式部署**：先在目標隧道進行 50–100 m 短距離閉環測試，驗證閘門與淤積區的避障表現；逐步擴展至公里級作業，根據現場結構特徵調整 Firefly 演算法族群大小與迭代次數，最終整合至維運排程系統。

### 潛在風險與注意事項

1. **光達視野遮擋與幾何退化**：隧道紋理單一且長距離結構重複，易導致點雲配準退化。建議選用寬視場光達或於 UGV 前方增設輔助照明，並在軟體層監控 IMU 預積分品質，作為感測器健康度指標。
2. **機間通訊中斷**：UAV 過度依賴 UGV 傳輸的局部幾何，通訊斷鏈將導致規劃依據遺失。建議設計降級策略：一旦偵測到封包遺失率超過閾值，UAV 立即切換至機載視覺慣性里程計（VIO）進入懸停或自主返航模式。
3. **運動學模型不匹配**：淤積地面或濕滑表面使 UGV 實際動態偏離理想模型。建議在增強型螢火蟲演算法的適應度函數中，即時納入輪速編碼器回授與滑移估計，動態調整路徑曲率限制。
4. **空氣動力學干擾與碰撞**：隧道狹窄空間內，UAV 旋翼下洗氣流與環境氣流耦合，可能導致位置飄移。建議 UAV 軌跡規劃保留至少 0.5 m 以上安全餘量，並在閘門等狹窄段限制最大飛行速度。
5. **縱向位置飄移累積**：雖 FLISP 為無地圖方法，但 UGV 編碼器與 IMU 在公里級運行中仍可能產生縱向飄移。建議每隔 500 m 或於已知結構標記（如閘門、里程樁）處，利用絕對位置觀測進行一次里程校正。

### 與其他技術的整合建議

1. **數位孿生與 BIM 模型**：將 FLISP 生成的即時軌跡與局部點雲片段注入既有隧道 BIM 模型，進行結構變形差異分析與資產定位，無需等待完整 SLAM 地圖建置即可產生視覺化報告。
2. **企業資產管理系統（CMMS）**：透過 MQTT 或 REST API 將 FLISP 偵測到的異常點位座標（如滲漏、裂縫位置）上傳至 IBM Maximo 或自研維運平台，直接銜接工單派發與維修排程流程。
3. **邊緣 AI 缺陷檢測**：在 UAV 或 UGV 搭載輕量級視覺模型（如 YOLOv8-seg），執行裂縫、滲漏或鏽蝕檢測；將缺陷像素座標透過 FLISP 的局部座標系反向映射至隧道里程，實現「規劃—檢測—定位」閉環。
4. **多機調度與任務分配平台**：若需擴展至多組 UGV-UAV 編隊，可將 FLISP 作為單組單元的局部規劃模組，上層對接 ROS2 Multi-Robot Task Allocation 或自研集中式調度系統，由中央伺服器依據隧道區段劃分協調各組巡檢範圍，避免重複覆蓋。

### 給不同背景讀者的閱讀建議

**初學者**：建議先從摘要與第 I 節的動機出發，理解「為何傳統基於地圖的方法在長隧道會失效」這一核心問題；接著對照圖 1 的系統架構，建立 UGV 負責感知與地面規劃、UAV 負責空中檢視的分工直覺。第 III 節的方法流程圖是理解全貌的關鍵，可暫時略過最佳化公式的數學推導，待熟悉整體管線後再回頭細讀。

**AI 工程師**：建議深入研讀第 II 節對地圖式方法結構性瓶頸的分析，以及第 IV 節增強型螢火蟲演算法與動態迭代最佳化器的實作細節。特別注意階層式細化策略如何將點雲特徵轉換為運動學約束，這是將論文轉化為可部署程式碼的關鍵；同時務必參考開源程式碼中的參數配置、launch 檔案結構與座標系定義。

**研究者**：應關注本文對「無地圖規劃」與「狀態估計飄移解耦」的論證邏輯。建議仔細分析第 VI 節與 Fast-LIO2+A*、LIO-SAM+RRT* 的基準測試設計，特別是取樣不穩定性與柵格化開銷在特徵退化環境下的量化結果。未來研究可延伸至動態障礙物（如水流、掉落碎石）的即時反應，或將此非對稱協作架構推廣至船艙、管道等其他線性基礎設施。

**產品經理**：請將閱讀重心放在摘要與第 I、VI 節的應用驗證。核心價值主張在於「以單一感測器套件驅動雙平台，在約 7 ms 內完成路徑規劃」，這直接對應硬體成本降低與系統複雜度簡化。評估導入時，請對照文中 1.2 km 營運隧道的測試條件，確認你的場景是否同樣具備 GPS 拒止、紋理單一、線性延伸等特徵，並據此估算與既有 SLAM 方案在總體擁有成本（TCO）與維運人力上的差異。
