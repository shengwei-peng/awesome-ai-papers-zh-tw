DetourBench 的核心方法論建立在對「終點評分」(endpoint scoring) 系統性缺陷的批判之上。傳統基準測試僅判斷代理是否抵達正確的最終狀態，這種二元判準無法區分「精準取得必要證據的代理」與「廣泛閱讀環境的代理」，更無法區分「從未找到證據的代理」與「僅差一步即完成的代理」。為解決此問題，作者提出了一套基於圖論 (graph theory) 的精確測量框架。

**轉移系統的形式化設計**

每個任務被定義為一個有限、部分可觀察的轉移系統 (partially observable transition system)，其中資源在被發現 (discovery) 之前處於部分可觀察狀態，一旦識別符 (identifier) 被揭示，該資源即變為全域可定址 (globally addressable)，代理可直接調用而無需導航 (navigation) 或回溯 (backtracking) 成本。這種設計巧妙地將「探索成本」與「使用成本」分離，使結構化互動 (structural interaction) 的計量化成為可能。所有存取動作均採用單位成本 (unit-cost accesses)，刻意排除異質工具價格、延遲或 token 消耗等變量，以純化「互動次數」此一測量標的。

**完全資訊最小動作數 L₀ 的計算**

透過對完整轉移圖 (transition graph) 進行窮舉搜尋 (exhaustive search)，系統計算出任務的完全資訊最小動作數 (full-information minimum action count)，記為 L₀，並產生一個可重播的最短路徑見證 (replayable shortest-path witness)。此 L₀ 為離線最佳值 (offline optimum)，即在已知完整轉移系統結構下的理論下限，而非部分可觀察性下的最佳策略 (optimal policy) 成本。作者明確指出此區別，並在第 3 節界定此測量範疇所遺漏的部分。

**剩餘工作量 R_T 與失敗感知評估**

對於失敗回合，若其終端狀態仍屬圖可還原 (graph-recoverable)，則可計算精確的剩餘工作量 (residual work) R_T，即從該狀態到達成功所需的最小額外存取數。此設計使評估能區分三種本質不同的失敗情境：(1) 僅差一步的近完成軌跡 (near-complete trajectories)；(2) 偏離目標甚遠的高成本未完成 (costly incompletion)；(3) 不可逆錯誤承諾 (irreversible wrong commitment)。第三種情境被明確表示為「無有限剩餘距離」(no finite residual distance)，而非被任意指派一個數值，這是對測量誠實性的重要堅持。

**四項獨立指標的分離報告**

DetourBench 將評估分解為四個獨立維度：(1) 成功率 (success)，即是否抵達正確終態；(2) 相對預言達成率 (oracle-relative attainment)，即代理實際步數與 L₀ 的比率；(3) 剩餘距離進度 (residual-distance progress)，即 R_T 相對於初始最佳值的比例；(4) 標準化繞路 (normalized detour)，即多餘互動的標準化測量。這種分離使研究者能從不同角度審視代理行為，而非被單一聚合分數所遮蔽。

**雙套件設計與驗證契約**

基準測試分為兩個互補套件：受控機制套件 (Controlled Mechanism Suite) 固定圖結構、目標與預言界限，僅變動局部資訊線索 (local information cue)；整合工作流程套件 (Integrated Workflow Suite) 則組合多筆記錄、限制條件與工作流程動作於更長的任務中。兩者共用相同的轉移語意 (transition semantics)、求解器 (solver)、評估器 (evaluator) 與產物版本化協定 (artifact-versioning protocol)。驗證契約包含機械式重播 (mechanical replay)、來源出處 (provenance)、必要性稽核 (necessity audits)、配對差異 (pair diffs) 與雜湊一致性 (hash consistency)，構成一個「失敗封閉」(fail-closed) 的檢查鏈，確保僅有通過所有驗證的產物與軌跡得以報告。

#### 實驗數據解讀

實驗規模涵蓋 375 個評分回合，橫跨 5 個模型端點 (model endpoints)、25 個整合任務，每任務重複 3 次。從摘要揭露的數據可觀察到幾個關鍵現象：

**成功率與達成率的解耦**

成功率介於 58.7% 至 96.0% 之間，呈現顯著的模型間差異。然而，條件式達成率 (conditional attainment) 僅介於 0.803 至 0.890，變異幅度相對收窄。更重要的是，條件式達成率對模型的排序與成功率排序不同——這正是終點評分無法揭示的資訊。當所有模型在某任務上皆成功時，成功率無法區分其優劣，但達成率仍能依據軌跡效率進行排序。

**飽和任務的鑑別力問題**

在 25 個任務中，有 8 個任務的每個模型在每次重複中皆成功，導致成功率在此 8 個任務上完全飽和，無法提供任何鑑別資訊。然而，條件式達成率在此 8 個任務上仍呈現 0.07 至 0.19 的模型間散布，約為同一模型跨重複變異的 3 至 9 倍。這凸顯了 DetourBench 的核心價值主張：在終點評分已飽和的區域，軌跡層級測量仍能提取有意義的模型差異。

**失敗側的分解能力**

在 5 個模型中的 3 個上，約三分之一的回合失敗。剩餘工作量 R_T 將這些失敗分解為三類：近完成軌跡、高成本未完成與不可逆承諾。傳統二元評分將這三類記錄為相同的失敗，但 R_T 使研究者能識別「代理幾乎成功但差一步」與「代理在預算耗盡時仍遠離目標」之間的本質差異。這對錯誤分析 (error analysis) 與模型改進方向具有直接指導意義。

**重複變異的控制**

每任務 3 次重複的設計使作者能區分「模型間變異」與「模型內變異」。條件式達成率 0.07 至 0.19 的模型間散布遠大於跨重複變異，證明所觀察到的差異具有統計意義而非隨機波動。

**測量範疇的誠實聲明**

作者明確指出 L₀ 為離線最佳值而非部分可觀察性下的最佳策略成本，並在第 3 節界定此測量範疇所遺漏的部分。這種對測量邊界的誠實聲明，避免了將「完全資訊下限」誤讀為「代理應達成的實際目標」。

#### 與現有研究的比較

DetourBench 在互動代理評估文獻中佔據一個獨特的位置，其設計選擇與既有方法形成明確的對比與互補。

**與 AgentBoard 及 CORE 的關係**

AgentBoard (Ma et al., 2024) 透過註解子目標測量進度，CORE (Michelakis et al., 2025) 將任務編碼為可接受工具使用路徑集合上的確定性自動機，並評估正確性、順序、前綴關鍵性、有害呼叫與效率。DetourBench 與兩者的關鍵差異在於參考的來源：AgentBoard 與 CORE 的參考為人工撰寫，僅能建立「某路徑可接受」，而 DetourBench 的參考為搜尋衍生，能建立「不存在更短路徑」。這是從「可接受性證明」到「最小性證明」的質變。

**與 SPL 的淵源與超越**

成功加權路徑長度 (Success weighted by Path Length, SPL) 由 Anderson 等人於具身導航 (embodied navigation) 領域提出，建立了「將觀察軌跡與實例特定最短路徑比較」的原則，DetourBench 的達成率繼承此原則。然而，SPL 對失敗回合記零，無法區分「差一步」與「從未找到證據」，且無「不可逆錯誤承諾」的概念表示。DetourBench 使用產生此界限的同一搜尋機制，在失敗側進行分解，這正是 SPL 所缺乏的維度。

此外，SPL 的最佳值為度量空間中的距離，而 DetourBench 的最佳值為組合狀態空間中的最小存取數，其中前置條件使可達性具歷史依賴性，且存在吸收態 (absorbing state) 轉移。這使得 DetourBench 能處理更複雜的資源獲取與認證取得邏輯。

**與 CostBench 的互補**

CostBench (Liu et al., 2026) 評估異質工具價格與動態失敗下的規劃，而 DetourBench 刻意採用統一存取成本以純化結構化互動計數。兩者測量不同面向：CostBench 關注經濟成本，DetourBench 關注互動次數。對於工具整合推理中減少不必要呼叫的工作 (Wang et al., 2025)，DetourBench 可作為結構效率的基準。

**與預言評估器可靠性的對話**

AgentRewardBench (Lù et al., 2025) 研究自動軌跡評估器的可靠性，DetourBench 則提供一個具有精確圖論界限的基準，使評估器的輸出可與已知最優值對照。這對評估器校準具有間接貢獻。

**基準有效性議題的呼應**

近期研究指出任務欠指定 (underspecification) 與評分捷徑威脅基準有效性 (Zhu et al., 2025; Shao et al., 2026; Tian et al., 2026; OpenAI, 2024)。DetourBench 透過可重播見證、來源出處、配對差異與加密清單 (cryptographic manifests) 回應此擔憂，將「基準有效性」從口頭聲明轉化為可機械驗證的契約。

**測量範疇的限制**

作者坦誠 DetourBench 並非自然工作流程的代表性樣本，而是受控診斷探針，設計目的在於隔離不必要與缺失的證據存取。此定位使其不適合作為通用代理能力的綜合測量，但適合作為軌跡效率的精確診斷工具。

## 潛在風險與注意事項

**風險 1：狀態空間爆炸**
若任務包含連續變數（如「讀取任意檔案」），狀態空間會無限大。緩解：限制資源為離散集合、將連續動作離散化、或僅對「關鍵決策點」建模。

**風險 2：部分可觀察性建模失真**
若「全域可定址」規則過於慷慨（例如代理只需知道檔名就能讀取），會低估真實成本。緩解：保留「探索成本」與「呼叫成本」的分離，僅對呼叫計費，探索仍需計入。

**風險 3：不可逆動作識別錯誤**
若將本可回復的動作誤標為不可逆，會錯誤地將可還原失敗歸類為「無有限剩餘距離」。緩解：對每個標記為不可逆的動作進行必要性稽核（necessity audit），確認其在所有最短路徑中都不會出現。

**風險 4：預言見證與實際環境不一致**
若求解器基於簡化模型，而實際環境有額外約束（如 API 速率限制、權限檢查），見證可能無法重播。緩解：採用「配對差異」機制，每次環境變更後自動比對求解器預期與實際執行的狀態序列。

**風險 5：基準過於人工化**
論文明確聲明 DetourBench 是「controlled diagnostic probe」，而非自然工作流程的代表。若直接用於宣稱「代理在真實任務上的效率」，會產生誤導。緩解：清楚標示基準的診斷性質，並搭配至少一個真實任務基準做交叉驗證。

**風險 6：條件式達成率的解讀陷阱**
條件式達成率僅在「成功」子集上計算，若某模型成功率極低但條件式達成率高，會被誤讀為「該模型效率好」。緩解：報告時必須同時呈現成功率與條件式達成率，並標註樣本數。

## 與其他技術的整合建議

**與 AgentBoard 整合**
AgentBoard 透過人工標註的子目標測量進度，DetourBench 提供圖論最小值。兩者可互補：用 AgentBoard 的子目標作為 DetourBench 的「資源探索里程碑」，使達成率的計算更具語意。

**與 CORE 整合**
CORE 編碼任務為確定性自動機，允許多條可接受路徑。DetourBench 的 L₀ 可作為 CORE 的「下界參考」——若 CORE 的最長可接受路徑遠大於 L₀，表示該任務存在顯著的捷徑，提示可重新設計任務規格。

**與 SPL（Success weighted by Path Length）整合**
SPL 適用於度量空間導航，DetourBench 適用於組合狀態空間。對於混合任務（如「先導航到資料夾，再呼叫 API」），可分階段評估：導航段用 SPL，API 呼叫段用 DetourBench。

**與 LangChain/AutoGen 整合**
在代理框架的 callback 機制中插入狀態記錄層，每個工具呼叫前後快照狀態。這使現有代理無需修改即可被 DetourBench 評估。

**與 LLM 評估器（如 AgentRewardBench）整合**
AgentRewardBench 評估「自動軌跡評分器的可靠性」，DetourBench 的可重播見證可作為「黃金標準」——用於訓練與驗證 LLM 評分器是否正確識別最短路徑。

**與 CI/CD 整合**
將 DetourBench 評估作為模型發版的必要關卡，搭配條件式達成率的趨勢監控——若新版本在特定任務類型上繞路增加，即使成功率不變也應阻擋合併。
