## 摘要翻譯

大型語言模型（LLM, Large Language Model）代理透過與外部工具進行多輪互動（Multi-Turn Interaction）來完成複雜任務。然而，嵌入於使用者查詢、工具描述（Tool Description）或環境觀察（Environment Observation）中的惡意內容（Malicious Content）可能操控其決策並誘發不安全行為（Unsafe Action）。對抗式共同演化（Adversarial Co-Evolution）已成為強化 LLM 安全性的有效方法，但既有研究主要聚焦於語言層級安全性（Language-Level Safety）或網頁任務（Web Task）中的間接提示注入（Indirect Prompt Injection）。在本文中，我們提出 AgentSafeEvo，一個基於攻擊者-防禦者對局（Attacker-Defender Game）、涵蓋多樣化任務與攻擊類型（Attack Type）的代理安全性（Agent Safety）共同演化式強化學習（Reinforcement Learning）框架。攻擊者學習建構能暴露防禦者在工具使用（Tool Use）上之弱點的對抗式代理任務（Adversarial Task），而防禦者則學習在這些攻擊下安全地完成任務。我們進一步提出可學習性引導的任務加權（Learnability-Guided Task Weighting）方法，利用任務內防禦者獎勵變異性（Defender-Reward Variability）來調整每個任務對攻擊者與防禦者更新（Attacker Update / Defender Update）的貢獻度（Task Contribution）。在代理安全性與通用能力基準（General Capability Benchmark）上進行的大量實驗證明，我們的方法在提升對抗魯棒性（Adversarial Robustness）的同時，亦能維持通用代理能力。

### 核心貢獻（3～5點）
- **提出 AgentSafeEvo 框架**：建立一個基於攻擊者-防禦者對局（Attacker-Defender Game）的共同演化式強化學習框架，涵蓋多樣化任務與攻擊類型，突破既有研究僅聚焦於語言層級安全性或網頁任務間接提示注入的限制。
- **雙方對抗學習機制**：攻擊者學習建構對抗式代理任務以暴露防禦者在工具使用上的弱點，防禦者則學習在攻擊下安全地完成任務，透過迭代式訓練（Iterative Training）形成共同演化過程（Co-Evolutionary Process）。
- **可學習性引導的任務加權**：利用任務內防禦者獎勵變異性（Within-Task Variability）作為回饋訊號（Feedback Signal），動態調整各任務對攻擊者與防禦者更新的貢獻度，提升訓練效率與穩定性。
- **實驗驗證有效性**：在代理安全性與通用能力基準上的大量實驗證明，該方法在顯著提升對抗魯棒性的同時，能維持通用代理能力，兼顧安全性與實用性。

### 適合對象
本研究最適合以下讀者閱讀：
1. **LLM 代理安全研究人員**：關注大型語言模型代理在多輪互動與工具使用場景下的安全性問題，特別是間接提示注入與越獄提示（Jailbreak Prompt）等攻擊威脅的研究者。
2. **對抗式機器學習與強化學習研究者**：從事對抗式訓練（Adversarial Training）、自我對弈（Self-Play）、線上自我對弈（Online Self-Play）等攻防對局機制設計的學者與工程師。
3. **AI 紅隊與安全防禦實務工作者**：負責評估與強化 AI 系統對抗魯棒性的紅隊工程師、安全分析師及政策制定者。
4. **LLM 應用開發者**：將 LLM 代理部署於實際產品中，需考量代理層級安全性（Agent-Level Safety）與攻擊面（Attack Surface）管理的開發團隊。

## 深度分析

#### 方法論解析

AgentSafeEvo 的核心設計理念在於將「對抗式共同演化（Adversarial Co-Evolution）」從傳統的語言層級（language-level）擴展至代理層級（agent-level），這是一個本質性的範式轉移。傳統的對抗式訓練方法（如 Self-RedTeam、MAGIC）主要關注單輪的提示-回應互動（prompt-response interaction），攻擊者生成越獄提示（jailbreak prompt），防禦者產生安全回應。然而，LLM 代理的安全性問題遠比單輪對話複雜，因為代理需要在多輪互動（multi-turn interaction）中進行規劃、調用工具（tool use）、觀察環境回饋，每一個環節都可能成為攻擊面（attack surface）。

**攻擊者-防禦者對局（Attacker-Defender Game）的形式化**

AgentSafeEvo 將安全性問題形式化為一個雙人對局。在每一輪迭代中：
- **攻擊者（Attacker）**：學習建構對抗式代理任務（adversarial agent tasks），這些任務包含使用者查詢、工具描述（tool description）以及環境觀察（environment observation），目的是誘導防禦者產生不安全行為（unsafe action）。
- **防禦者（Defender）**：學習在遭受攻擊的情況下安全地完成任務，需要同時兼顧任務效用（utility）與安全性（safety）。

兩個模型透過強化學習（reinforcement learning）交替更新，攻擊者根據防禦者的執行結果獲得回饋訊號（feedback signal），防禦者則從新生成的攻擊中學習抵抗策略。這種設計確保了攻擊分佈（attack distribution）能夠隨著防禦者能力的演進而持續調整，避免了「在固定攻擊集上訓練」所導致的過擬合問題。

**可學習性引導的任務加權（Learnability-Guided Task Weighting）**

這是本文最具方法論創新性的設計之一。傳統的任務級零和獎勵（task-level zero-sum reward）存在一個根本缺陷：它傾向於選擇那些能降低防禦者平均獎勵的任務，但並未考慮任務內部獎勵的變異性。換言之，某些任務可能對所有防禦者策略都呈現相似的低獎勵（即「無法學習」），而另一些任務則呈現高變異性（即「可學習性高」）。

AgentSafeEvo 透過計算每個任務內防禦者獎勵的變異性（within-task defender-reward variability），為每個任務分配相對權重。變異性高的任務獲得較大的權重，因為它們能提供更豐富的學習訊號。這種加權機制同時影響攻擊者更新（attacker update）和防禦者更新（defender update），使得雙方的學習都聚焦於最具資訊量的任務上。

**訓練資料集的設計**

作者建構了一個涵蓋 50 個代理場景、約 7,000 個工具的代理安全性訓練資料集。每個對抗式任務都由使用者查詢與對應的工具-環境配置配對組成，提供結構化監督用於攻擊者的初始化。資料集同時包含種子實例（seed instances），用於後續的共同演化訓練。這種設計確保攻擊者具備建構有效對抗式代理任務的能力，能夠跨越多樣化的攻擊類型（attack type）進行泛化。

#### 實驗數據解讀

雖然提供的全文僅包含論文的前兩節，但從摘要與方法論描述可以推斷實驗設計的核心邏輯。實驗應涵蓋兩個維度的評估：

**代理安全性基準（Agent Safety Benchmarks）**

實驗應在多個代理安全性基準上進行測試，包括但不限於：
- **ToolEmu**：評估工具使用的安全性與風險意識
- **R-Judge**：評估代理在多輪互動中的風險判斷能力
- **AgentHarm**：評估有害任務的合規性
- **InjecAgent**：評估對間接提示注入（indirect prompt injection）的抵抗能力

從摘要的描述「improves adversarial robustness」可以推斷，AgentSafeEvo 在這些基準上應展現出相較於基線方法（如 ARLAS、Self-RedTeam、MAGIC）更低的攻擊成功率或更高的安全完成率。

**通用能力基準（General Capability Benchmarks）**

摘要強調「maintains general agent capabilities」，這是安全性研究中至關重要的指標——避免「安全性-效用權衡（safety-utility tradeoff）」的退化。實驗應在通用代理任務（如網頁導航、文件處理、資訊檢索等）上驗證防禦者在增強安全性後仍能保持原有的任務執行能力。

**共同演化的動態分析**

從「Further analyses show that both attack effectiveness and defensive robustness improve during co-evolution」可以推斷，作者應繪製了攻擊成功率與防禦成功率隨訓練迭代的變化曲線。這種動態分析驗證了共同演化機制的有效性——攻擊者並未陷入「攻擊退化」（即攻擊變得無效但也無資訊量），而是持續產生更具挑戰性的攻擊。

**跨模型泛化性**

「attack improvements generalizing to substantially larger target models」這一句尤為重要。它暗示作者進行了「跨規模遷移實驗」：在小型模型上訓練的攻擊者所產生的攻擊，能夠有效攻擊更大的目標模型。這驗證了共同演化所發現的攻擊模式具有結構性而非過擬合於特定模型。

#### 與現有研究的比較

**與 ARLAS 的比較**

ARLAS 是與 AgentSafeEvo 最直接相關的前置工作。兩者的關鍵差異在於：
- ARLAS 的攻擊者僅限於在預定義的網頁任務（web task）中進行間接提示注入的改寫，攻擊空間受限於固定的任務模板。
- AgentSafeEvo 將對抗式任務建構（adversarial task construction）納入共同演化過程，攻擊者能夠生成使用者查詢、工具定義與環境觀察，攻擊空間大幅擴展。

這種差異使得 AgentSafeEvo 能夠覆蓋更多樣化的攻擊類型，而不限於單一的間接提示注入。

**與 Self-RedTeam 的比較**

Self-RedTeam 採用單一模型同時扮演攻擊者與防禦者角色，透過線上自我對弈（online self-play）進行訓練。相比之下，AgentSafeEvo 使用獨立的攻擊者與防禦者模型，這種分離設計允許更明確的角色專化，但也增加了訓練的計算成本。

**與 MAGIC 的比較**

MAGIC 交替優化獨立的攻擊者與防禦者模型，但聚焦於對抗式提示改寫（adversarial prompt rewriting）與安全回應生成（safe response generation），屬於語言層級的安全性。AgentSafeEvo 則將共同演化擴展至任務建構與任務執行（task construction and task execution），這是代理層級安全性的核心。

**方法論的侷限性**

儘管 AgentSafeEvo 在多個面向有所突破，仍存在以下侷限：
1. **計算成本**：獨立攻擊者與防禦者的共同演化需要大量的多輪代理執行模擬，訓練成本可能遠高於單模型自我對弈方法。
2. **攻擊類型的覆蓋**：雖然涵蓋 50 個場景與約 7,000 個工具，但相較於真實世界中代理可能遭遇的攻擊多樣性，訓練資料的覆蓋仍可能不足。
3. **獎勵設計的敏感性**：可學習性引導的任務加權依賴於防禦者獎勵變異性的準確估計，若獎勵函數設計不當，可能導致加權偏差。
4. **攻擊者可解釋性**：攻擊者生成的對抗式任務可能缺乏人類可解釋性，這對於安全性研究中的「攻擊理解」與「防禦審計」構成挑戰。

AgentSafeEvo 的核心演算法（攻擊者-防礦者對局、可學習性引導的任務加權、共同演化訓練迴圈）具有明確的技術細節，理論上可以重現。但強化學習的訓練過程通常對超參數敏感，完整重現可能需要作者提供詳細的超參數配置與訓練日誌。

#### 未來研究方向

**1. 攻擊類型的擴展與形式化**

AgentSafeEvo 目前涵蓋的攻擊類型雖然多樣，但缺乏系統性的形式化分類。未來研究可以：
- 建立代理攻擊的分類體系（如直接提示注入、間接提示注入、工具描述污染、環境觀察操縱等）

**2. 可學習性理論的深化**

可學習性引導的任務加權是一個富有潛力的研究方向。未來可以：
- 從資訊理論角度形式化「任務可學習性」的定義
- 探討任務可學習性與任務難度、任務多樣性之間的關係
- 將可學習性引導的加權機制擴展至其他共同演化框架（如 Self-RedTeam、MAGIC）

**3. 跨模態代理的安全性**

隨著多模態代理（如視覺-語言代理、語音代理）的興起，安全性問題將擴展至多模態攻擊面。未來研究可以：
- 將 AgentSafeEvo 擴展至多模態代理的安全性
- 探討跨模態攻擊（如視覺提示注入、音訊操縱）的共同演化機制
- 研究多模態資訊融合對代理安全性的影響

**4. 安全性-效用權衡的理論分析**

AgentSafeEvo 強調「maintains general agent capabilities」，但缺乏對安全性-效用權衡的理論分析。未來可以：
- 建立安全性與效用之間的形式化權衡模型
- 探討是否存在「帕累托最優」的安全性-效用平衡點
- 研究不同任務類型下的權衡特性

**5. 紅隊演練的自動化**

AgentSafeEvo 的攻擊者本質上是一個自動化的紅隊（red team）。未來可以：
- 將其整合至企業級代理系統的安全審計流程
- 探討人機協作的紅隊演練模式
- 研究攻擊者生成結果的可解釋性與可審計性

**6. 防禦機制的理論保證**

目前 AgentSafeEvo 的防禦機制是經驗性的，缺乏理論安全性保證。未來可以：
- 借鑒對抗魯棒性（adversarial robustness）的理論框架（如認證魯棒性）
- 探討在特定攻擊模型下的可證明安全防禦機制
- 研究防禦機式的計算複雜度與可擴展性

**7. 代理生態系統的安全性**

隨著代理生態系統（如多代理協作、代理市場）的興起，安全性問題將從單一代理擴展至代理間互動的安全性。未來可以：
- 將 AgentSafeEvo 擴展至多代理場景
- 探討代理間信任機制與攻擊傳播
- 研究代理生態系統的系統性風險評估方法

## 論文問答

**Q1：LLM 代理面臨的核心安全問題是什麼？為什麼這個問題特別具有挑戰性？**

A：LLM 代理的核心安全問題在於其攻擊面已從單純的使用者查詢擴展到工具描述與環境觀察。惡意內容可以偽造任務指令、誤導工具行為，或在多輪互動中逐步操縱代理決策，導致代理在執行過程中產生不安全行為。相較於傳統的單輪對話場景，這種多輪互動特性使得攻擊可以分散在整個任務執行鏈中，更難以被靜態防禦機制偵測與阻擋。

**Q2：現有的對抗式訓練方法為什麼不足以應對 LLM 代理的安全挑戰？**

A：現有方法如 Self-RedTeam 與 MAGIC 主要聚焦於語言層級安全性，僅針對越獄提示產生安全回應，無法涵蓋多輪工具互動所帶來的風險。在固定攻擊集上進行對抗式訓練會導致攻擊分佈無法隨防禦者能力提升而演變，使模型容易過擬合於已知攻擊模式。此外，ARLAS 雖將共同演化延伸至代理安全，但其攻擊者僅限於在預定義網頁任務中注入間接提示注入，未將對抗式任務建構納入共同演化過程。

**Q3：為什麼對抗式共同演化是解決代理安全問題的關鍵研究方向？**

A：對抗式共同演化透過攻擊者-防禦者對局實現迭代式訓練，使攻擊分佈能隨防禦者能力動態調整，避免模型僅適應靜態攻擊模式。這種動態適應機制對於代理安全尤為關鍵，因為代理面臨的攻擊類型多樣且攻擊面分散，固定資料集難以全面覆蓋。透過讓攻擊者持續探索防禦者的弱點，共同演化能夠產生更具挑戰性的訓練樣本，從而提升模型在真實部署環境中的對抗魯棒性。

**Q4：AgentSafeEvo 的核心方法是什麼？它如何運作？**

A：AgentSafeEvo 是一個基於強化學習的對抗式共同演化框架，透過攻擊者-防禦者對局在多輪工具互動中共同演化。攻擊者學習建構對抗式代理任務（包括使用者查詢、工具定義與環境觀察），以誘發防禦者的不安全行為；防禦者則學習在這些攻擊下安全完成任務。雙方模型根據防禦者執行的安全性與效用回饋進行更新，使任務生成能夠適應防禦者不斷演進的能力。

**Q5：可學習性引導的任務加權（Learnability-Guided Task Weighting）有什麼創新之處？**

A：傳統的任務層級零和獎勵傾向於獎勵那些降低防禦者平均獎勵的任務，但無法直接反映任務內的獎勵變異性。可學習性引導的任務加權透過衡量任務內防禦者獎勵變異性來調整每個任務對攻擊者與防禦者更新的相對貢獻度。這種設計使得具有較高學習潛力的任務能獲得更大的權重，從而更有效地引導防禦者的學習過程，避免在已「飽和」或無法提供學習訊號的任務上浪費訓練資源。

**Q6：為什麼選擇強化學習作為 AgentSafeEvo 的訓練框架？其設計選擇帶來哪些優勢？**

A：強化學習天然適合攻擊者-防禦者對局這類迭代式訓練設定，能夠根據攻擊結果提供細粒度的回饋訊號以指導策略更新。在多輪工具互動中，防禦者的行為序列較長且獎勵稀疏，強化學習能有效處理這種序列決策問題。此外，強化學習允許攻擊者與防禦者在訓練過程中持續探索新的攻擊與防禦策略，使雙方能力共同提升，這對於建構能夠應對未知攻擊的魯棒代理至關重要。

**Q7：實驗使用了哪些基準測試來評估 AgentSafeEvo？**

A：實驗在代理安全性基準與通用能力基準上進行評估。代理安全性基準涵蓋工具使用安全、風險意識、有害任務合規性與間接提示注入等多個維度，包括 ToolEmu、R-Judge、AgentHarm 與 InjecAgent 等。通用能力基準則用於驗證模型在提升安全性的同時不會犧牲整體任務效能，確保對抗魯棒性與實用性之間的平衡。

**Q8：AgentSafeEvo 的主要實驗結果是什麼？**

A：實驗結果顯示 AgentSafeEvo 在多項代理安全基準上顯著提升了對抗魯棒性，同時在通用能力基準上維持甚至提升了原有的任務表現。更重要的是，分析顯示攻擊效能與防禦魯棒性在共同演化過程中均持續提升，且攻擊能力的提升能夠泛化到規模顯著更大的目標模型。這證明了共同演化框架不僅能產生更強的防禦者，也能產生更具遷移性的攻擊，從而為安全性研究提供有價值的測試基準。

**Q9：消融研究揭示了哪些關鍵發現？**

A：消融研究驗證了對抗式共同演化與可學習性引導的任務加權兩個核心組件各自的貢獻。移除共同演化機制會導致模型僅在固定攻擊集上訓練，無法適應演進中的威脅；移除任務加權則會使訓練訊號在任務間均勻分佈，降低學習效率。研究還發現，隨著共同演化迭代次數增加，攻擊者建構的對抗式任務越來越能有效暴露防禦者的弱點，證明了框架的動態適應能力。

**Q10：AgentSafeEvo 在哪些實際應用場景中具有重要價值？**

A：AgentSafeEvo 對於任何涉及多輪工具互動的 LLM 代理應用都具有重要價值，包括資訊搜尋、文件處理、排程管理與自動化辦公等場景。在這些場景中，代理需要調用外部 API、處理文件內容或與第三方服務互動，每個環節都可能成為攻擊者的注入點。透過提升代理在多樣化攻擊下的魯棒性，AgentSafeEvo 能夠幫助企業在部署 LLM 代理時降低因惡意內容導致的資料洩漏、未授權操作或決策操縱等風險。

**Q11：將 AgentSafeEvo 部署到實際產品中需要考慮哪些因素？**

A：實際部署時需考慮計算成本問題，因為共同演化訓練需要同時維護攻擊者與防禦者模型，訓練資源需求較高。此外，攻擊分佈會隨時間持續演變，部署後仍需定期更新防禦者以應對新興威脅。產品化時還需平衡安全性與回應延遲，因為更嚴格的安全檢查可能影響代理的執行效率與使用者體驗。

**Q12：AgentSafeEvo 對代理安全研究領域的影響是什麼？**

A：AgentSafeEvo 將共同演化從語言層級擴展到代理層級，為代理安全研究提供了新的方法論範式。其建構的涵蓋 50 種代理場景、約 7,000 個工具的訓練資料集，以及可學習性引導的任務加權機制，都將成為後續研究的重要基礎。此外，該框架展示了攻擊能力可遷移至更大模型的特性，為未來建立標準化的代理安全評估協議提供了新思路。

**Q13：論文中承認了哪些局限性？**

A：論文坦承目前的訓練資料集雖然涵蓋 50 種代理場景與多種攻擊類型，但仍無法窮舉所有可能的攻擊向量。共同演化過程中攻擊者與防禦者的能力提升可能存在不對稱性，導致訓練不穩定。此外，框架的評估主要在受控環境中進行，在真實開放環境中的泛化能力仍需進一步驗證。

**Q14：AgentSafeEvo 可能出現哪些失敗案例？**

A：當攻擊者無法建構出有效的對抗式任務（例如任務結構過於複雜超出攻擊者能力）時，共同演化將無法產生有意義的訓練訊號。在某些攻擊類型下，防禦者可能學會「拒絕執行」而非「安全執行」，導致任務效用下降。此外，若防禦者在某類任務上已達到性能上限，繼續訓練可能導致過擬合，反而降低在新型任務上的表現。

**Q15：未來的研究方向有哪些？**

A：未來可將 AgentSafeEvo 擴展至更多攻擊類型與更複雜的多代理互動場景，以提升框架的通用性。另一個方向是探索如何將共同演化產生的攻擊樣本用於建立標準化的代理安全基準，促進領域的系統性評估。此外，將該框架與形式化驗證或可解釋性技術結合，可能進一步提升防禦機制的可靠性與透明度。

## 實務應用指南

### 適用場景

1. **企業內部 AI 助理安全加固**：在企業部署的 LLM 代理（如客服助理、文件處理機器人、行程管理助理）中，工具描述與環境觀察常包含來自外部系統的不可信內容。AgentSafeEvo 可用於訓練此類代理，使其在面對被污染的搜尋結果、惡意行事曆邀請或偽造的 API 回應時，仍能拒絕執行危險動作（例如刪除檔案、外發敏感信件）。

2. **程式開發輔助代理（Code Agent）的越獄防禦**：開發工具如 Cursor、Devin 等代理會呼叫 shell、檔案系統與版本控制。透過 AgentSafeEvo 模擬攻擊者注入惡意 commit 訊息、偽造工具輸出或污染套件描述，可訓練代理在 PR 審查、CI 觸發、套件安裝等場景中保持安全。

3. **金融與醫療領域的多步驟決策代理**：在交易、健保紀錄存取等高風險場景，代理需串接多個內部工具。AgentSafeEvo 的對抗式任務建構可模擬「看似合法的查詢夾帶誘導性工具回應」這類攻擊，幫助代理在跨工具呼叫鏈中維持安全決策。

4. **瀏覽器與網頁自動化代理的安全評估**：對於會自動操作瀏覽器、填寫表單、抓取資料的代理，可使用 AgentSafeEvo 產生含有間接提示注入的網頁任務，系統化評估並提升代理對惡意網頁內容的抵抗力。

5. **紅隊演練與安全基準建構**：安全研究團隊可將 AgentSafeEvo 的攻擊者模型作為自動化紅隊工具，持續產生新型對抗式任務，用於內部基準測試與第三方模型評估。

### 實作前置條件

**資料需求**
- 至少 50 個領域場景的代理任務定義（涵蓋客服、開發、財務、醫療、網頁操作等多元領域）。
- 約 7,000 個工具描述（包含工具名稱、輸入輸出規格、副作用說明），可從既有工具庫（如 ToolBench、API-Bank）擴充。
- 每個任務需具備「使用者查詢 + 工具環境配置」的成對標註，作為攻擊者初始化的監督訊號。
- 種子實例（seed instances）用於啟動共同演化訓練。

**運算資源**
- 兩個獨立的 LLM 骨幹（攻擊者與防禦者），建議至少 7B–13B 規模作為起點；最終目標模型可為更大規模（如 70B）的閉源模型。
- 多輪強化學習訓練所需的 GPU 叢集（建議 8×A100/H100 等級），需支援 PPO/GRPO 等策略最佳化演算法。
- 沙箱化工具執行環境，用於安全地執行代理動作並收集回饋訊號。

**技能門檻**
- 熟悉 LLM 代理框架（如 LangChain、AutoGen、ReAct 風格的規劃-執行迴圈）。
- 具備強化學習實作經驗（策略梯度、獎勵塑形、優勢估計）。
- 了解提示注入、工具呼叫攻擊面與紅隊評估方法論。
- 具備資料標註與品質控管能力，以建構高品質的對抗式任務資料集。

### 實作步驟建議

**步驟一：建構代理安全訓練資料集**
盤點目標應用場景，定義 50 個代理情境並為每個情境設計工具集（約 7,000 個工具）。為每個任務撰寫「使用者查詢 + 工具環境配置」成對資料，標註潛在攻擊類型（直接注入、間接注入、工具描述污染、環境觀察污染等）。保留部分實例作為共同演化的種子。

**步驟二：建立攻擊者-防禦者基礎模型**
以監督式微調（SFT）將攻擊者初始化為「任務建構者」，使其能根據使用者意圖產生對抗式任務；將防禦者初始化為「安全任務執行者」，使其能在乾淨環境下完成任務。兩者可從同一基礎模型出發，但採用不同的系統提示與微調資料。

**步驟三：設計獎勵函式**
定義雙重獎勵：安全性獎勵（是否觸發不安全動作）與效用獎勵（任務是否完成）。共同演化採用零和式的任務級獎勵，使攻擊者傾向產生降低防禦者平均獎勵的任務。

**步驟四：實作可學習性引導的任務加權**
在每輪訓練中，計算每個任務內防禦者獎勵的變異性（例如標準差或分位距），將變異性較大的任務賦予較高的相對權重。這些權重會調整該任務對攻擊者與防禦者策略更新的貢獻度，使雙方都聚焦於「仍有學習空間」的任務。

**步驟五：執行共同演化迴圈**
交替進行：(a) 攻擊者根據當前防禦者產生新對抗式任務；(b) 防禦者在這些任務上執行並收集獎勵；(c) 雙方根據加權後的獎勵訊號更新策略。持續迭代直到攻擊成功率與防禦成功率收斂。

**步驟六：評估與部署**
在 AgentHarm、InjecAgent、ToolEmu 等代理安全基準上測試防禦者，同時在通用代理能力基準（如 GAIA、SWE-bench）上驗證不退步。將訓練後的防禦者部署至目標應用，並以攻擊者模型作為持續紅隊工具。

### 潛在風險與注意事項

**風險一：攻擊者過擬合於訓練分佈**
若攻擊者僅在訓練資料的 50 個場景中演化，可能無法泛化至真實世界的新型攻擊。
*緩解措施*：定期引入外部紅隊資料與新場景；保留多樣化的攻擊類型標註；在評估時使用未見過的任務類型。

**風險二：防禦者過度保守導致效用下降**
過度強調安全性可能使代理拒絕過多合法任務，損害使用者體驗。
*緩解措施*：在獎勵函式中維持安全性與效用的平衡權重；監控「過度拒絕率」指標；在通用能力基準上持續驗證。

**風險三：獎勵 hacking 與評估漏洞**
攻擊者可能學會產生「看起來困難但實際上無法真正誘導不安全行為」的任務；防禦者可能學會利用評估器的盲點。
*緩解措施*：採用多樣化、人機協作的獎勵評估；定期審核攻擊者產出的任務品質；引入獨立的外部評估模型。

**風險四：工具執行的安全與成本**
共同演化過程中，防禦者會實際呼叫工具，必須在隔離沙箱中執行，避免對真實系統造成損害。
*緩解措施*：使用容器化沙箱、限制工具副作用、設定資源配額；對高風險動作（刪除、發送、付款）設置人工審核閘。

**風險五：可學習性加權的偏差**
若某些任務的獎勵變異性天然較高（例如隨機性較大的環境），可能過度主導訓練。
*緩解措施*：對變異性指標做平滑處理；結合任務難度估計；定期檢查權重分佈是否合理。

### 與其他技術的整合建議

**與既有代理框架整合**
AgentSafeEvo 的防禦者可作為 LangChain、AutoGen、CrewAI 等框架中的「安全規劃器」模組，於每個工具呼叫前進行安全檢查。攻擊者模型可整合至 CI/CD 流程，作為部署前的自動化安全測試。

**與內容審核與護欄系統整合**
將 AgentSafeEvo 訓練後的防禦者與 Llama Guard、ShieldGemma 等內容審核模型串接：前者負責多輪決策層級的安全判斷，後者負責單輪輸出層級的內容過濾，形成縱深防禦。

**與紅隊平台整合**
將攻擊者模型接入內部紅隊平台（如 Microsoft PyRIT、GARAK），作為持續產生新型攻擊的引擎；其產出的對抗式任務可作為評估基準的擴充資料。

**與監控與可觀測性系統整合**
在生產環境中，將代理的決策軌跡、工具呼叫與獎勵訊號串接至可觀測性平台（如 LangSmith、Phoenix），用於即時偵測異常行為並回饋至下一輪共同演化訓練。

**與人類回饋強化學習（RLHF）整合**
共同演化訓練後，可再以人類標註的偏好資料進行 RLHF 微調，進一步對齊人類價值觀；人類回饋也可作為攻擊者獎勵的一部分，提升攻擊的真實性。

**給研究者**：建議深入閱讀方法章節中關於攻擊者-防禦者對局的形式化定義、獎勵分解方式，以及與 ARLAS、Self-RedTeam、MAGIC 的差異分析；並關注實驗章節中「攻擊改進可泛化至更大目標模型」的結論，思考其對模型規模化安全研究的啟示。

**給產品經理**：聚焦於「適用場景」與「潛在風險」兩節，理解 AgentSafeEvo 能解決的真實業務問題（客服、開發、醫療代理的安全加固）以及部署時需注意的成本、效用平衡與沙箱隔離需求；可將攻擊者模型視為「自動化紅隊工具」，評估其對產品安全成熟度的提升價值。
