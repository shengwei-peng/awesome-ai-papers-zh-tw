## ⚡ TL;DR

現有影片世界模型缺乏持久狀態與可程式化規則，難以精確控制個別實體與長期互動。
本文提出可程式化世界模型，以狀態增強三維定向邊界框連結顯式狀態引擎與生成式渲染器。
於CombatStateBench達成94%計數與98%狀態準確率，支援長期連貫生成並優於現有方法。

## 摘要翻譯

近期的影片世界模型（video world models）能夠生成越來越逼真且可互動的視覺體驗，但仍缺乏可靠的機制來維護持久性世界狀態（persistent world state），並在長時間互動中強制執行可程式化規則（programmable rules）。我們提出可程式化世界模型（Programmable World Model），一個將世界狀態演化與視覺觀察生成（visual observation generation）解耦的框架。編碼代理（coding agent）將自然語言指令（natural-language instructions）轉譯為可執行程式（executable programs），用以指定實體狀態（entity states）與狀態轉換規則（state-transition rules），從而實現對個別實體及其互動的直接控制。輕量級引擎執行這些程式，以更新並維護一個明確且持久的全域世界狀態（global world state），包含螢幕外實體（off-screen entities）與非視覺屬性（non-visual attributes）。為了連結世界狀態與視覺生成，我們提出狀態增強三維定向邊界框（state-augmented 3D oriented bounding boxes, OBBs）作為中介表示法（intermediate representation）。此中介表示法會與目標相機軌跡（camera trajectory）一同被確定性編譯為像素對齊（pixel-aligned）的時空條件訊號（spatiotemporal conditioning signals），供作為生成式渲染器（generative renderer）的預訓練影片模型（pretrained video model）使用。此設計讓使用者能夠建立可遊玩遊戲（playable games），具備預定義機制（predefined mechanics）、對個別實體的直接控制，以及貫穿整場遊戲的持久性世界狀態。我們進一步提出 CombatStateBench，一個用於評估可程式化世界模型的評測基準。在 CombatStateBench 上，我們的方法達到 94% 的計數準確率（Count Accuracy）與 98% 的狀態準確率（State Accuracy），大幅超越現有的互動式影片世界模型，同時支援連貫的長期生成（long-horizon generation）。這些結果證明了將明確的世界狀態演化與生成式渲染分離，對於建構持久且可程式化的世界之有效性。

### 核心貢獻（3～5點）
- 提出可程式化世界模型（Programmable World Model）框架，將世界狀態演化與視覺觀察生成（visual observation generation）解耦，使狀態維護與視覺渲染分離。
- 設計編碼代理（coding agent），可將自然語言指令（natural-language instructions）轉譯為可執行程式（executable programs），以定義實體狀態（entity states）與狀態轉換規則（state-transition rules），實現對個別實體的直接控制。
- 引入狀態增強三維定向邊界框（state-augmented 3D OBBs）作為中介表示法（intermediate representation），並將其與相機軌跡（camera trajectory）確定性編譯為像素對齊的時空條件訊號（spatiotemporal conditioning signals），驅動預訓練影片模型（pretrained video model）作為生成式渲染器（generative renderer）。
- 建立 CombatStateBench 評測基準，用於評估可程式化世界模型在計數準確率（Count Accuracy）與狀態準確率（State Accuracy）等指標上的表現。
- 在 CombatStateBench 上達到 94% Count Accuracy 與 98% State Accuracy，顯著優於現有互動式影片世界模型，並支援連貫的長期生成（long-horizon generation）。

### 適合對象
適合對互動式世界引擎、生成式影片模型、可程式化遊戲機制，以及具持久狀態之虛擬環境有興趣的研究者與工程師，特別是從事世界模型、電腦視覺、自然語言指令執行與遊戲 AI 開發的讀者。

## 深度分析

#### 方法論解析

Programmable World Model（可程式化世界模型）的核心設計是將**世界狀態（world state）演化**與**視覺觀察生成（visual observation generation）**解耦。整體架構可視為三個主要模組的協作：

1. **編碼代理（coding agent）**：以視覺語言模型（Vision-Language Model, VLM）為基礎，接收單張參考影像與自然語言指令（natural-language instructions），負責建立初始實體佈局、賦予語義類別與動態狀態，並撰寫可執行程式（executable programs）。這些程式定義了實體狀態（entity states）、狀態轉換規則（state-transition rules）、事件觸發條件與遊戲目標，讓使用者能以自然語言間接「程式化」世界行為。

2. **狀態執行器（state executor）**：在互動過程中根據玩家動作與事件規則更新並維護一個**全域世界狀態（global world state）**。此狀態是顯式、持久且獨立於當前畫面的，能夠追蹤**螢幕外實體（off-screen entities）**與**非視覺屬性（non-visual attributes）**（如物品欄 inventory、任務進度 task progress、互動歷史 interaction history）。這是傳統影片世界模型難以達成的能力。

3. **狀態編譯器（state compiler）與生成式渲染器（generative renderer）**：狀態編譯器將世界狀態中的每個實體轉換為**狀態增強三維定向邊界框（state-augmented 3D oriented bounding boxes, OBBs）**，並沿著目標**相機軌跡（camera trajectory）**進行確定性投影與光柵化，產生像素對齊（pixel-aligned）的**時空條件訊號（spatiotemporal conditioning signals）**。這些訊號再輸入預訓練影片模型（pretrained video model），由後者補足細緻幾何、外觀、肢體動作與次級動態。

在表示法選擇上，作者明確比較了光譜兩端的極端：**文字描述（text descriptions）**雖易於撰寫但缺乏幾何約束；**二維邊界框與遮罩（2D boxes and masks）**僅提供與視角綁定的**影像空間控制（image-space control）**；而**詳細三維場景（detailed 3D scenes）**、**結構代理（structural proxies）**或 **G-buffers** 雖能提供強控制，卻需要昂貴的監督資料，並在訓練時從觀察動態（observed dynamics）提取的表示與推論時由程式建構的表示之間產生嚴重的訓練–推論不匹配（train-test mismatch）。

為此，作者採用 **OBB（定向邊界框）** 作為中介表示法：它以固定且緊湊的幾何參數（**位置、範圍、方向 position, extent, orientation**）描述實體，無需網格、材質、骨架或預設動畫；同時透過身份、語義類別、動態狀態與外觀資訊進行增強。這種設計保留了**共享世界座標（shared world coordinates）**下的顯式可控制性（explicit controllability），同時將細節生成留給生成模型，達到控制強度與建構成本之間的平衡。

此外，作者還發展了一套影片資料整理流程（video data curation pipeline），用於從影片中恢復空間與語義監督訊號，以支援上述介面的訓練擴展。

#### 實驗數據解讀

本文提出的評測基準 **CombatStateBench** 專注於衡量生成影片與引擎維護世界狀態之間的一致性。該基準設計了多樣化的相機與實體運動情境，並使用兩項核心指標：

- **Count Accuracy（計數準確率）**：評估生成影片中可見存活角色數量是否與世界狀態一致。
- **State Accuracy（狀態準確率）**：評估死亡狀態等關鍵實體狀態是否在視覺上被正確實現。

實驗結果顯示，Programmable World Model 在 CombatStateBench 上分別達到 **94% Count Accuracy** 與 **98% State Accuracy**，顯著優於現有的互動式影片世界模型（interactive video world models），並能支援連貫的**長期生成（long-horizon generation）**。

這些數字的意義可從以下角度解讀：

1. **State Accuracy 98%**：說明當世界狀態將某角色標記為死亡時，生成式渲染器能高度可靠地將此狀態轉化為視覺表現（例如角色倒地、消失或靜止）。這驗證了以 OBB 狀態作為條件訊號的有效性，也顯示預訓練影片模型能夠理解並執行高階狀態語義。

2. **Count Accuracy 94%**：顯示系統在動態相機與多實體運動下，仍能保持可見實體數量的穩定，減少傳統自迴歸影片生成中常見的實體幻覺（hallucination）或遺失問題。這主要歸功於世界狀態由外部引擎維護，而非完全依賴生成模型從像素中隱式記憶。

3. **長期連貫性**：由於狀態演化與視覺生成分離，系統不會因為生成誤差累積而導致世界狀態漂移（state drift），因此適合長時間互動與可遊玩遊戲（playable games）場景。

然而，CombatStateBench 的範疇仍相對集中於戰鬥與死亡狀態，對於更複雜的物理交互、物品欄變化、任務進度或多人同步等維度的評估仍有擴展空間。

#### 與現有研究的比較

現有影片世界模型（video world models）大多直接在生成式影片模型之上建立互動式世界引擎（interactive world engines），透過視覺歷史與使用者動作預測下一幀畫面。這類方法的控制介面（control interfaces）通常僅限於相機、動作或**高階提示（high-level prompts）**，存在幾項根本限制：

- **缺乏對個別實體的直接控制**：難以針對特定物件或角色進行尋址與操作。
- **無顯式持久狀態**：沒有獨立於當前視角的**持久性世界狀態（persistent world state）**，無法處理螢幕外實體與非視覺屬性。
- **無法程式化規則**：使用者只能提示期望結果，無法建立穩定執行的世界演化規則，導致互動結果不一致。
- **狀態漂移與幻覺**：長期互動中容易出現實體數量錯誤、狀態不一致或視覺細節矛盾。

相較之下，Programmable World Model 的優勢在於：

- **顯式可控制性（explicit controllability）**：透過可執行程式直接定義個別實體與其互動。
- **持久狀態管理**：由狀態執行器維護跨時間與視角的全域狀態。
- **使用者可程式化規則（programmable rules）**：自然語言可轉化為穩定執行的狀態轉換規則。
- **訓練–推論對齊**：OBB 作為中等粒度表示法，降低了從觀察動態提取與程式建構之間的表示差異。

不過，該方法也有其限制：

- **表示粒度有限**：OBB 無法精確控制身體姿態（body poses）、肢體軌跡（limb trajectories）或複雜形狀，這些細節必須依賴生成模型推斷，可能在需要精細動作控制時不足。
- **編碼代理的可靠性**：自然語言到可執行程式的轉譯若出錯，將直接導致世界行為錯誤，且目前尚不清楚其對複雜指令的泛化能力。
- **資料整理成本**：雖然 OBB 監督比完整三維重建便宜，但仍需從影片中恢復空間與語義資訊，規模化仍有挑戰。
- **確定性編譯的幾何假設**：OBB 投影與光柵化對遮擋、非剛性變形或複雜外觀的處理可能過於簡化。

#### 可重現性評估

根據目前提供的論文內容，**可重現性（reproducibility）**資訊相當有限：

- 文中並未明確說明是否釋出原始碼、CombatStateBench 資料集、預訓練影片模型權重或編碼代理的提示模板。
- 資料整理流程（data curation pipeline）的具體實作細節、訓練資料來源與規模、OBB 提取方法、以及生成式渲染器的模型架構與訓練超參數均未在摘要與引言中詳述。
- CombatStateBench 的評估腳本、基線模型實作與結果釋出狀態亦不得而知。

因此，就現有資訊判斷，本研究的可重現性仍屬**有限**。若要提升可重現性，作者至少需要公開：
1. 原始碼與模型權重；
2. CombatStateBench 資料集與評估指標實作；
3. 編碼代理的提示設計與程式生成範例；
4. 資料整理流程的詳細說明與訓練資料清單。

在缺乏這些資源的情況下，其他研究者難以直接複製 94% Count Accuracy 與 98% State Accuracy 的結果，也難以在此基礎上進行公平比較與後續改進。

#### 未來研究方向

基於 Programmable World Model 的架構與現有成果，未來研究可朝以下方向延伸：

1. **更豐富的中介表示法**：在 OBB 與完整三維場景之間探索更細緻的結構代理，例如加入骨架（skeleton）、粗略網格或姿態參數，以提升對肢體動作與非剛性物體的控制，同時避免過高的訓練與推論成本。

2. **整合物理模擬與傳統遊戲引擎**：將神經生成渲染與物理引擎或遊戲引擎結合，讓世界狀態演化具備真實物理一致性，並支援更複雜的碰撞、流體與破壞效果。

3. **擴展評測基準**：CombatStateBench 可從戰鬥場景擴展至解謎、製作合成、社交互動、物品欄管理與任務進度追蹤等多元情境，並加入因果規則遵循、長期敘事一致性與使用者可控性等指標。

4. **多人世界引擎（multiplayer world engine）**：探索多位使用者共享同一持久世界狀態時的同步機制、延遲處理與衝突解決策略。

5. **編碼代理的穩健性與可解釋性**：發展程式驗證、互動式除錯與錯誤修正機制，降低自然語言轉譯錯誤對世界行為的影響；並研究如何讓非程式背景使用者也能有效創作世界規則。

6. **即時與低延遲互動**：目前架構是否支援即時可遊玩遊戲仍有疑問，未來可優化狀態編譯與影片生成的效率，實現真正的互動式幀率。

7. **自動化資料整理規模化**：進一步發展從遊戲影片、模擬環境或網路影片中自動提取 OBB、語義狀態與相機軌跡的方法，以擴大訓練資料規模並提升泛化能力。

8. **與大型語言模型（LLM）及多模態代理的深層整合**：讓編碼代理具備規劃、反思與持續學習能力，使其能根據使用者回饋動態調整世界規則與實體行為。

## 論文問答

### 【背景與動機】

**Q1：這篇論文主要想解決什麼問題？**  
A：近年來的影片世界模型雖然能生成越來越逼真且可互動的視覺體驗，但它們缺乏可靠機制來維持持久性的世界狀態，也難以執行使用者可程式化的規則。具體來說，現有模型大多只能透過相機、動作或高階提示進行控制，無法直接操作個別實體，也無法追蹤螢幕外實體與非視覺屬性。因此，本文提出可程式化世界模型，將世界狀態演化與視覺觀察生成解耦，以建立更像互動式世界引擎的系統。

**Q2：為何現有的互動式影片世界模型難以直接充當世界引擎？**  
A：現有方法通常根據視覺歷史與使用者動作預測下一幀畫面，這種做法沒有獨立於當前視角的顯式全域狀態。它們無法記錄物品欄、任務進度或互動歷史等非視覺屬性，也無法保證螢幕外實體仍然存在並持續演化。此外，單純用提示詞描述期望結果並不能建立可執行且一致的狀態轉換規則，導致長期互動容易出現不一致。

**Q3：持久性的全域世界狀態為何對世界引擎至關重要？**  
A：持久性世界狀態讓系統能跨時間與視角維持一致性，即使實體暫時離開畫面，其狀態仍被保留。它還能記錄非視覺屬性，例如物品欄、任務進度與互動歷史，這些資訊對遊戲邏輯與多人協作不可或缺。透過顯式維護全域狀態，使用者才能對個別實體進行精細控制，並確保程式化規則在每次互動中都被一致執行。

### 【方法與創新】

**Q4：可程式化世界模型的核心架構包含哪些元件？**  
A：核心架構將世界狀態演化與生成式渲染分離：首先，編碼代理把自然語言指令轉譯成可執行程式，定義實體狀態與狀態轉換規則；接著，輕量級狀態引擎執行這些程式，維護顯式且持久的全域世界狀態；最後，狀態編譯器將狀態增強三維定向邊界框投影到相機軌跡上，產生像素對齊的時空條件訊號，供預訓練影片模型作為生成式渲染器使用。

**Q5：為什麼選擇狀態增強三維定向邊界框作為中介表示法？**  
A：定向邊界框以固定且緊湊的幾何參數描述實體在共享世界座標中的位置、範圍與方向，不需要網格、材質、骨架或預設動畫。透過額外嵌入身份、語義類別、動態狀態與外觀資訊，它能在控制強度與建構成本間取得平衡。相較於詳細三維場景，OBB 減少了訓練資料標註與推論時狀態演化的負擔，同時比文字或二維邊界框更能提供世界空間的顯式可控制性。

**Q6：確定性狀態編譯器如何連結世界狀態與影片生成？**  
A：狀態編譯器會沿著目標相機軌跡投影不斷更新的 OBB，並將其光柵化為像素對齊的時空條件訊號。這些訊號明確傳達實體身份、語義、方向、運動與狀態變化，讓預訓練影片模型知道每個物件應該出現在哪裡、處於什麼狀態。生成式渲染器則負責補足 OBB 未指定的細緻幾何、外觀、肢體動作與次級動態，從而產生連貫的視覺觀察。

### 【實驗與結果】

**Q7：CombatStateBench 是什麼？它評估哪些能力？**  
A：CombatStateBench 是本文提出的控制型評測基準，用於衡量生成影片與引擎維護的世界狀態之間的一致性。它設計了包含多樣相機與實體運動的戰鬥情境，並檢查生成影片是否能正確保留可見存活角色的數量，以及是否能在視覺上呈現死亡狀態。透過計數準確率與狀態準確率等指標，該基準能客觀比較不同可程式化世界模型的狀態一致性。

**Q8：本文方法在 CombatStateBench 上的主要量化結果為何？**  
A：在 CombatStateBench 上，本文方法達到 94% 的計數準確率與 98% 的狀態準確率，顯著優於現有的互動式影片世界模型。這些數字顯示，透過顯式狀態引擎維護世界狀態，能大幅降低長期生成中實體數量與狀態的錯誤。同時，該方法仍能支援連貫的長期生成，兼顧視覺品質與狀態一致性。

**Q9：實驗結果支持哪些設計選擇與消融見解？**  
A：實驗結果支持將世界狀態演化與生成式渲染解耦的設計，因為顯式狀態引擎能獨立於視覺模型維持正確狀態。狀態增強 OBB 與確定性編譯器的組合，能在控制粒度與訓練—推論一致性之間取得平衡，避免詳細三維代理或影像空間控制所帶來的資料標註成本與視角依賴問題。長期連貫性的提升也證明，持久性全域狀態對於長期互動至關重要。

### 【應用與影響】

**Q10：可程式化世界模型可應用於哪些實務情境？**  
A：最直接的情境是讓使用者透過自然語言創作可遊玩遊戲，定義預定義機制、直接控制個別實體，並在整場遊戲中維持持久世界狀態。此外，它也適用於互動式敘事、虛擬訓練與模擬，以及快速原型設計。使用者無需具備三維建模或動畫專業，就能創造具有複雜規則與長期一致性的虛擬世界。

**Q11：部署此類系統時需要考慮哪些產品層面問題？**  
A：首先，編碼代理必須能穩健地將自然語言指令轉譯為正確的可執行程式，並在規則有歧義或錯誤時提供除錯介面。其次，系統需要內容審核機制，避免使用者程式化產生不當內容。此外，影片生成的運算成本、延遲，以及自然語言模糊性導致的狀態不一致，都是在實際產品化時必須仔細處理的議題。

**Q12：這項研究可能對生成式世界模型領域帶來什麼影響？**  
A：它將研究焦點從單純的畫面預測轉向顯式狀態導向的世界引擎，強調可程式化規則、實體級控制與長期一致性。透過提供 CombatStateBench 與資料整理流程，本文為後續研究建立了評估標準與擴充訓練資料的可行路徑。這種典範轉移有助於催生更可靠、可編輯且可互動的生成式虛擬世界。

---

### 【限制與未來方向】

**Q13：本文方法有哪些已承認或隱含的限制？**  
A：OBB 僅描述粗略的幾何範圍，無法捕捉精細網格、材質與肢體動作，因此這些細節必須依賴生成式渲染器推論。對於可變形物體或複雜物理互動，單純的邊界框表示可能不足以精確控制。此外，整個系統的正確性高度依賴編碼代理產生的程式是否無誤，以及狀態引擎能否嚴格執行規則。

**Q14：可能出現哪些失敗案例？**  
A：即使引擎狀態正確標記角色死亡，生成式渲染器仍可能在視覺上未能呈現死亡狀態，導致狀態與畫面不一致。對於細長或被遮擋的物體，OBB 投影可能與實際像素對齊產生偏差。若編碼代理誤解指令或產生邏輯衝突的規則，也可能造成遊戲機制錯誤；長期互動中，狀態與渲染之間的微小偏差亦可能逐漸累積。

**Q15：未來可以朝哪些方向延伸？**  
A：未來可將 OBB 擴展為更豐富的結構代理或混合表示，以支援更細緻的幾何與物理互動。編碼代理也可強化複雜規則撰寫、自動除錯與多輪對話能力。此外，擴充資料整理流程、支援多人即時互動、引入物理模擬，以及開發涵蓋戰鬥以外情境的評測基準，都是值得探索的方向。最終目標是讓生成式世界模型同時具備高度可程式化、長期一致與視覺逼真的特性。

## 實務應用指南

### 適用場景

1. **可遊玩遊戲原型與關卡設計**  
   設計師可用自然語言描述遊戲機制（例如「敵人受到攻擊後進入死亡狀態，玩家靠近寶箱時開啟」），由編碼代理生成可執行程式與初始世界狀態，再透過生成式渲染器快速產出可互動的遊戲畫面，縮短原型迭代週期。

2. **互動式影視與廣告內容**  
   品牌或製作團隊可預先定義角色、物件與事件規則，讓觀眾透過選擇或操作改變劇情走向；持久性世界狀態確保角色狀態與物品位置在長時間互動中保持一致。

3. **機器人與自動駕駛模擬資料合成**  
   在受控環境中定義實體狀態與狀態轉換規則，生成多樣化、像素對齊的影片資料，用於訓練感知模型，同時維持螢幕外實體與非視覺屬性的正確性。

4. **教育訓練與虛擬演練**  
   建立可程式化的訓練情境（如醫療急救、消防演練），由狀態執行器根據學員操作更新世界狀態，並以生成式渲染器產生對應視覺回饋，支援長期連貫的模擬流程。

5. **多人協作世界與元宇宙體驗**  
   將可程式化世界模型作為後端引擎，統一維護全域世界狀態，讓多位使用者的互動結果透過相同規則演化，並由生成式渲染器為各自視角產出一致畫面。

### 實作前置條件

- **資料準備**
  - 一張或多張參考影像，用於定義初始視覺風格。
  - 目標領域的影片資料，用於訓練或微調生成式渲染器。
  - 狀態增強三維定向邊界框（OBB）與語義標註，可從現有 3D 資產、偵測模型或人工標註取得。

- **運算資源**
  - 具備足夠 VRAM 的 GPU，用於執行視覺語言模型（VLM）編碼代理、狀態執行器與預訓練影片生成模型。
  - 若需從頭訓練渲染器，需更大規模的運算叢集與影片資料儲存空間。

- **技術能力**
  - 熟悉 Python、3D 幾何與座標轉換。
  - 具備提示工程經驗，能引導 VLM 產出正確的可執行程式。
  - 了解影片擴散模型或生成式影片模型的微調與推論流程。
  - 具備基礎遊戲設計或系統設計能力，以定義實體狀態與狀態轉換規則。

### 實作步驟建議

1. **定義世界規則與實體狀態**  
   列出所有實體、屬性（位置、方向、外觀、生命值等）以及可觸發的狀態轉換規則，例如攻擊、開門、拾取物品等。

2. **使用編碼代理生成初始布局與程式**  
   以自然語言指令輸入給 VLM 編碼代理，讓其產生初始實體布局、屬性指派，以及描述互動、事件觸發與目標的可執行程式。

3. **建立狀態執行器與狀態編譯器**  
   實作狀態執行器以套用玩家動作與事件規則，更新持久性全域世界狀態；同時建立確定性的狀態編譯器，將 OBB 與相機軌跡轉換為像素對齊的時空條件訊號。

4. **訓練或微調生成式渲染器**  
   透過資料策展管線，從影片中萃取空間與語義監督訊號，微調預訓練影片模型，使其能根據 OBB 條件生成連貫、視覺合理的畫面。

5. **整合互動迴圈與使用者回饋**  
   將「使用者輸入 → 狀態更新 → 條件編譯 → 影片生成 → 視覺輸出」串接成即時或近即時迴圈，並允許使用者透過進一步自然語言指令修改世界規則。

6. **評估與迭代**  
   使用 CombatStateBench 或自訂基準，檢驗計數準確率、狀態準確率與長期生成一致性，針對訓練-推論不匹配或狀態飄移問題進行迭代優化。

### 潛在風險與注意事項

- **訓練-推論不匹配**  
  訓練時的表示通常從觀察到的動態萃取，而推論時則從高階狀態轉換程式化構造，兩者可能不一致。建議在資料策展階段盡量模擬推論時的 OBB 分佈，並進行領域適應微調。

- **OBB 表示粒度不足**  
  狀態增強三維定向邊界框雖然輕量，但無法精確控制肢體姿態、表情或細微幾何。若應用需要精細動作，可考慮在 OBB 外額外加入骨架或動作參數作為條件。

- **長期狀態飄移**  
  長期生成中，生成式渲染器可能逐漸偏離狀態執行器維護的世界狀態。建議定期以狀態編譯器輸出的條件訊號進行強制對齊，或引入回饋機制修正偏差。

- **可程式化規則的安全性與正確性**  
  由 VLM 自動生成的程式可能包含邏輯錯誤或邊界條件遺漏。建議加入沙箱執行環境、單元測試與人機協作審查流程。

- **運算與延遲成本**  
  影片生成模型推論成本高昂，即時互動可能受限。可透過模型量化、推論加速、降低解析度或採用關鍵影格生成搭配插值來緩解。

- **內容安全與版權**  
  生成內容可能涉及版權風格或有害場景，需建立內容過濾機制，並確保訓練資料與參考影像的使用符合授權規範。

### 與其他技術的整合建議

- **遊戲引擎（Unity / Unreal Engine）**  
  可將狀態執行器與世界狀態管理放在遊戲引擎中，利用其成熟的物理、碰撞與事件系統，再將 OBB 與相機軌跡輸出至生成式渲染器產生最終畫面。

- **3D 資產與場景庫**  
  結合現有 3D 模型庫（如 Sketchfab、Asset Store）初始化實體幾何與外觀資訊，再由 VLM 編碼代理自動轉換為狀態增強 OBB 與互動規則。

- **大型語言模型 / 視覺語言模型代理**  
  將 GPT-4V、Claude 或其他 VLM 作為編碼代理，負責自然語言到可執行程式的轉譯，並透過工具呼叫與狀態執行器互動。

- **影片生成模型 API 或自架模型**  
  根據延遲與品質需求，選擇使用預訓練影片生成 API，或在私有環境中微調開源影片擴散模型，以確保資料隱私與客製化控制。

- **資料標註與評測管線**  
  整合自動化 3D 偵測、追蹤與語義分割工具，建立從影片到 OBB 監督訊號的資料管線，並使用 CombatStateBench 類型的基準持續監控品質。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先從摘要與圖 2 的表示法權衡開始，理解「世界狀態」與「視覺生成」為何要分開，再透過適用場景中的遊戲與互動影片例子建立直覺，最後閱讀實作步驟建議以掌握整體流程，不必一開始深入數學細節。

- **研究人員**  
  可深入分析可程式化規則的表達能力、訓練-推論不匹配問題，以及 CombatStateBench 的評估指標設計；未來可探索更細緻的結構代理、多智能體互動、或將世界狀態與大型語言模型記憶機制結合的方向。

- **產品經理**  
  建議聚焦於適用場景與潛在風險，評估該技術能為哪些使用者創造差異化體驗，並規劃最小可行產品（MVP）範圍；同時留意運算成本、內容安全與人機協作審查流程，確保產品在可擴展性與合規性之間取得平衡。
