# LEAP：用於長時音視覺感知的學習式區塊證據檢索

## ⚡ TL;DR

長時音視覺問答面臨上下文困境：全錄影編碼超出長度限制，均勻壓縮則稀釋細粒度聲學與視覺證據。
LEAP 切分錄影為固定區塊，輕量定位評分候選窗，再編碼高分窗作答，轉錄稿定位、原始音視訊保留細節。
多項基準顯示，LEAP 較兩個全模態骨幹分別提升 4.5–16.8% 與 3.1–13.0%。

## 摘要翻譯

小時級別（hour-scale）的音視覺問答（audio-visual question answering, AVQA）面臨上下文困境（context dilemma）：密集式全錄影編碼（dense whole-recording encoding）會迅速耗盡上下文長度限制（context limits），而均勻時間壓縮（uniform temporal compression）則會嚴重稀釋細粒度聲學證據（fine-grained acoustic evidence）與細粒度視覺證據（fine-grained visual evidence）。我們提出 LEAP（學習式區塊證據檢索框架，Learned Block-wise Evidence Retrieval），一個使模型無需將整段錄影置於單一上下文（context）即可自行檢索證據（evidence）的框架。LEAP 將錄影劃分為固定時長區塊（fixed-duration blocks），並在每個區塊上執行輕量級定位階段（lightweight localization pass），對短暫候選時間窗（candidate windows）進行評分。分數最高的候選時間窗會被匯集（pool），並在單一有界回答階段（bounded answer pass）中重新編碼（re-encode）。因此，回答階段的輸入長度與峰值上下文（peak context）皆與錄影長度無關。藉由將證據定位（evidence localization）與推理（reasoning）解耦，我們的框架能夠在預先計算轉錄稿（pre-computed transcripts）上定位候選時間窗，而無需解碼媒體幀（decoding media frames）；同時透過將最終回答階段導向原始音視訊串流（raw audio-visual streams），保留細粒度視覺與非語音證據（non-speech evidence）。LEAP 同時訓練兩個階段：定位 LoRA（localization LoRA）提升所選時間窗的品質，回答 LoRA（answer LoRA）改善從相同時間窗讀出的答案。區塊網格（block grid）原生支援因果查詢（causal queries），使 LEAP 無需串流專屬訓練即可支援串流推論（streaming inference）。在多項 AVQA 基準測試（benchmarks）中，LEAP 相較於 Qwen3-Omni-30B-A3B 基線模型（baseline）提升 4.5–16.8%，並遷移（transfer）至第二個全模態骨幹模型（omni-modal backbone）MiniCPM-o 4.5，超越其已發表結果（published results）3.1–13.0%。

### 核心貢獻（3～5點）
- 提出 LEAP 框架，以學習式區塊證據檢索解決長時音視覺問答的上下文困境，使回答階段的輸入長度與峰值上下文皆與錄影長度無關。
- 將證據定位與推理解耦：定位階段可在輕量級預先計算轉錄稿上運作，回答階段則透過原始音視訊串流保留細粒度視覺與非語音證據。
- 設計雙 LoRA 訓練策略，分別以定位 LoRA 提升所選時間窗品質、以回答 LoRA 改善從相同時間窗讀出的答案。
- 區塊網格天然支援因果查詢，使 LEAP 無需串流專屬訓練即可進行串流推論。
- 在 Qwen3-Omni-30B-A3B 與 MiniCPM-o 4.5 兩個全模態骨幹模型上均顯著提升表現，展現良好的跨骨幹遷移能力。

### 適合對象
從事多模態學習、長影片理解、音視覺問答（AVQA）與全模態基礎模型研究的學者與工程師；特別適合關注長時音視訊推理效率、上下文長度限制、串流推論，以及希望結合語音轉錄文本與原始音視訊串流進行證據檢索的讀者。

## 深度分析

#### 方法論解析

LEAP（Learned Block-wise Evidence Retrieval，學習式區塊證據檢索框架）的核心設計是將「證據定位（evidence localization）」與「答案推理（answer reasoning）」解耦，並以固定時長區塊（fixed-duration blocks）建立時間網格（block grid），使模型無需將整段小時級別（hour-scale）錄影放入單一上下文（context），同時保留細粒度聲學證據（fine-grained acoustic evidence）與細粒度視覺證據（fine-grained visual evidence）。

**問題設定與整體流程。** 給定對齊的影片串流（video stream）V、音訊串流（audio stream）A、問題 q 與選項 O，LEAP 的目標是生成答案 y，且過程中任一階段的峰值上下文（peak context）與工作記憶體（working memory）皆與錄影長度無關，達到 O(1) context。整體推論分為兩個階段：

1. **Localization pass（定位階段）：** 將錄影劃分為不重疊區塊（non-overlapping blocks），每個區塊再細分為多個候選時間窗（candidate windows）。對每個區塊，模型在問題條件下為內部所有候選窗評分（score），並依區塊內最高分對區塊進行排序（rank）。最後只保留最高分的若干區塊與其高分窗。
2. **Answer pass（回答階段）：** 將被保留的候選窗（retained windows）從原始音視訊串流（raw audio-visual streams）重新編碼（re-encode），以固定且有限的每窗上下文進行密集推理，最終產生答案。

這種「先粗後細」的兩階段策略，本質上是把「覆蓋率（coverage）」與「密度（density）」這兩個在固定上下文（fixed context）下互相競爭的目標分開處理：Localization pass 負責大範圍覆蓋，Answer pass 則專注於少數證據窗的高解析度推理。

**區塊網格與候選時間窗的設計意義。** 將錄影切分為固定時長區塊後，每個區塊獨立處理，因此單次前向傳播的輸入長度被硬性限制。候選時間窗作為證據選擇的基本單位（basic units of evidence selection），讓模型能夠同時定位多個分散的證據（scattered evidence），避免傳統「只傳遞單一區間（single interval）」方法遺漏跨越多處的線索。區塊網格也天然支援因果查詢（causal queries）：在串流推論（streaming inference）中，只需處理查詢時刻之前的區塊，無需針對串流場景重新訓練。

**轉錄稿作為第二掃描通道。** LEAP 的一個關鍵創新是讓 Localization pass 可以選擇在預先計算轉錄稿（pre-computed transcripts）上運作，而不需要解碼媒體幀（decoding media frames）。這大幅降低了第一階段的計算成本，因為文字索引遠比原始音視訊便宜。然而，轉錄稿會遺漏非語音證據（non-speech evidence）與視覺細節，因此 Answer pass 會將被選中的窗從原始音視訊串流重新編碼，補回這些遺失的模態資訊。這種「文字定位、原始媒體回答」的路由（routing）策略，兼顧了效率與證據保真度（fidelity）。

**訓練策略。** LEAP 同時訓練兩組 LoRA（Low-Rank Adaptation，低秩適應）：

- **Localization LoRA（定位 LoRA）：** 學習如何根據問題為候選窗打分，使被選中的窗更接近真正包含答案的區域。
- **Answer LoRA（回答 LoRA）：** 學習如何從被選中的窗生成正確答案。

兩者各司其職，形成一個可微分的兩階段流程：定位品質提升會直接改善回答階段可見的證據，而回答階段的回饋也能間接反映定位好壞。這與過去僅在推理時提示通用模型（general-purpose models）去「自己找證據」的 Agentic methods（智能體方法）不同，LEAP 的證據定位能力是經過訓練的。

#### 實驗數據解讀

論文摘要與引言中報告的實驗結果可從兩個層次解讀：

**相對於強大基線的增益。** 在多個 AVQA（Audio-Visual Question Answering，音視覺問答）基準測試（benchmarks）上，LEAP 相較於 Qwen3-Omni-30B-A3B 基線模型（baseline）提升了 4.5%–16.8%。這個範圍顯示：

- 在部分資料集上，LEAP 帶來超過 15% 的顯著提升，說明當答案所需證據高度分散或包含非語音線索時，「先定位、再密集重讀」的策略遠勝於一次性全錄影編碼。
- 即使在提升較小的資料集上，也有穩定的 4.5% 增益，代表該框架不會因為兩階段設計而損害原本已較強的全模態骨幹模型（omni-modal backbone）表現。

**跨骨幹遷移能力。** LEAP 還轉移（transfer）到第二個全模態骨幹模型 MiniCPM-o 4.5，並超越其已發表結果（published results）3.1%–13.0%。這點特別重要，因為它顯示 LEAP 並非只對單一模型架構或 tokenizer 有效，而是一種可疊加在不同 omni-modal backbone 上的通用檢索—推理框架。跨模型的穩定提升也暗示，瓶頸主要來自「長時上下文中的證據稀釋」，而非特定骨幹的表達能力不足。

**整體意涵。** 實驗數據支持論文的核心主張：在長篇音視覺問答（long-form AVQA）中，將證據檢索（evidence retrieval）與答案生成解耦，並讓 Answer pass 重新讀取原始音視訊，能夠在控制上下文長度限制（context limits）的同時，保留回答所需的細節。不過，由於摘要未提供各資料集的絕對分數、樣本數與標準差，也無法判斷這些增益在統計上是否顯著，以及在不同問題類型（例如因果推論、事實查核、時間定位）上的分佈。

#### 與現有研究的比較

LEAP 在長篇音視覺問答的文獻中，處於 Selection methods（選擇方法）、Compression methods（壓縮方法）與 Agentic methods（智能體方法）三條軸線的交會處，但做出了明確區隔。

**相對於 Selection methods。** 既有選擇方法通常先從粗略視圖（coarse view）中保留若干時間區域，再進行推理。LEAP 的差異在於：(1) 使用固定時長區塊網格，避免粗階段本身受錄影長度影響而降低保真度；(2) 保留多個分散的候選時間窗，而非單一區間；(3) 定位階段本身經過訓練，而不是依賴啟發式或通用模型的提示。

**相對於 Compression methods。** 壓縮方法保留全錄影但減少 token 或記憶狀態（memory states），其風險是會稀釋關鍵窗內的細節。LEAP 不壓縮整段時間軸，而是直接丟棄無關內容（irrelevant content），並對保留下來的窗給予完整、固定的每窗上下文。這在理論上更能保護短暫但關鍵的聲學或視覺事件。

**相對於 Agentic methods。** 智能體方法讓模型反覆回到原始資料查找答案，雖然靈活，但每次問題都要重新執行媒體處理，計算成本高，且「該看哪裡」交由未經定位訓練的通用模型決定。LEAP 則把證據定位變成可學習模組，並透過區塊網格與轉錄稿索引降低重複解碼媒體幀的成本。

**相對於 Text-as-a-retrieval-channel 方法。** 許多研究使用字幕、轉錄稿或 OCR 作為檢索通道，但最終只把文字餵給回答模型，永遠不再讀取原始錄影。LEAP 的獨特之處是「文字僅用於定位，回答仍走原始音視訊」，因此能利用轉錄稿的效率，同時不犧牲非語音證據與視覺細節。

**限制。** LEAP 的成效仍受制於幾個因素：

- **ASR 品質：** 若使用轉錄稿通道，Localization pass 依賴自動語音辨識（ASR）的準確率；在口齒不清、背景嘈雜或多語言場景中可能漏掉關鍵線索。
- **固定區塊與窗長：** 固定時長區塊可能與真實事件邊界不對齊，導致證據被切分到兩個區塊；候選窗長度若過短，也可能無法涵蓋需要較長上下文才能回答的問題。
- **兩階段延遲：** Localization pass 需對每個區塊各做一次前向傳播，Answer pass 還要重新編碼保留窗，整體延遲可能高於單次壓縮方法。
- **LoRA 容量：** 定位與回答任務的複雜度可能超出低秩適應的表達能力，尤其在需要深層次多模態對齊時。
- **缺乏全局上下文：** 雖然 O(1) context 是優勢，但某些問題可能需要對整段錄影的全局結構（例如情節發展、人物關係演變）進行推理，此時丟棄大部分內容可能不利。

#### 未來研究方向

基於 LEAP 的設計與限制，可延伸的研究方向包括：

- **自適應時間階層：** 讓區塊長度與候選窗長度可依內容動態調整，例如對事件密集的區段使用較細粒度窗，對靜態場景使用較粗粒度窗，以減少邊界不對齊問題。
- **多層次檢索：** 在區塊與窗之間加入片段（segment）層級，形成更細緻的時間階層（temporal hierarchy），並以遞迴（recursively）方式逐步縮小證據範圍。
- **端到端聯合訓練：** 目前 Localization LoRA 與 Answer LoRA 雖然都經過訓練，但可進一步探索以強化學習或 Gumbel-Softmax 等方式進行端到端最佳化，使定位決策直接最大化最終答案正確率。
- **多模態索引融合：** 除了轉錄稿，可同時建立視覺事件、聲音事件與動作偵測的輕量索引，讓 Localization pass 能根據問題選擇最適合的檢索通道。
- **非語音與環境音建模：** 針對轉錄稿無法捕捉的非語音證據，發展專門的聲音事件嵌入，並在 Localization pass 中與文字線索共同打分。
- **串流場景最佳化：** 雖然 LEAP 已支援串流推論，但未來可設計線上區塊淘汰策略與記憶體預算管理，使其在真正的即時串流應用中更具效率。
- **更長與更複雜的基準：** 將方法擴展到數小時以上的錄影，並評估其在需要跨長距離因果推論（causal reasoning）與多輪對話上的表現。
- **與 Agentic methods 結合：** 讓 LEAP 成為智能體的「第一輪檢索器」，再由智能體根據初步答案決定是否需要進一步檢索其他區塊，兼顧效率與靈活性。

## 論文問答

**Q1：小時級音視覺問答面臨的「上下文困境」是什麼？**

A：小時級音視覺問答的上下文困境在於，若將整段錄影密集編碼後全部送入模型，會迅速耗盡上下文長度限制，同時讓輸入充斥大量無關內容；反之，若採用均勻時間壓縮，雖能保留全錄影的覆蓋範圍，卻會嚴重稀釋回答問題所需的細粒度聲學與視覺證據。這使得「覆蓋率」與「密度」成為固定上下文下互相競爭的兩個目標。LEAP 透過只檢索高相關性的短暫時間窗，讓輸入長度與峰值上下文都不再隨錄影長度增長。

**Q2：現有的選擇法、壓縮法與智能體法各自存在什麼缺陷？**

A：選擇法若僅從粗略視圖挑選區間，容易遺漏答案真正需要的短暫證據窗；壓縮法雖保留全錄影，卻會降低每個保留窗的細節保真度，使非語音線索或視覺細節變得模糊。智能體法雖能反覆回到原始資料查找，但通常依賴未經證據定位訓練的通用模型，並且每次問題都需要重新處理媒體，效率與定位準確度皆有限。因此，這三類方法都無法同時解決覆蓋、密度與可學習定位的問題。

**Q3：為何細粒度聲學與視覺證據對長篇 AVQA 至關重要，且傳統做法如何遺失它們？**

A：長篇錄影中的答案線索往往只是幾秒鐘的聲音事件或畫面細節，例如短暫的音效、動作或物件狀態，這些都是回答問題的關鍵證據。傳統的均勻壓縮會把這些短暫線索攤平到很長的時間軸上，導致模型難以辨識；而僅使用轉錄稿或字幕的檢索管道則會完全遺失非語音聲學資訊與視覺細節。LEAP 因此強調在最終回答階段重新編碼原始音視訊串流，以保留轉錄稿無法捕捉的證據。

**Q4：LEAP 的核心兩階段流程是什麼？**

A：LEAP 首先將錄影劃分為固定時長的不重疊區塊，每個區塊再細分為多個候選時間窗，作為證據選擇的基本單位。接著進行輕量級的以問題為條件定位階段，對每個區塊內的候選窗評分，並依分數對區塊進行排序與篩選。最後，LEAP 將少數高分保留時間窗匯集起來，在單次有界回答階段中重新編碼並進行推理，從而生成答案。

**Q5：將證據定位與推理解耦的關鍵創新是什麼？**

A：解耦後，定位階段可以直接在預先計算好的轉錄稿上進行，無需解碼原始媒體幀，大幅降低檢索成本與記憶體消耗。與此同時，回答階段則被路由到原始音視訊串流，只對被選中的少數時間窗進行密集重新編碼，因此能保留轉錄稿遺漏的細粒度視覺與非語音證據。這種設計讓轉錄稿成為第二條掃描通道，兼顧效率與多模態保真度。

**Q6：LEAP 為何能維持 O(1) 的上下文與工作記憶體複雜度？**

A：因為 LEAP 的每個階段都只處理固定數量且固定大小的區塊或候選窗，無論錄影長度是幾分鐘還是幾小時，每次送入模型的輸入長度都保持有界。定位階段逐區塊評分，每個區塊的上下文是固定的；回答階段只重新編碼被保留下來的少數窗口，總長度也受控。因此，LEAP 的峰值上下文與工作記憶體需求都不隨錄影時長增加而增長。

**Q7：LEAP 在哪些骨幹模型與基準測試上進行評估，主要結果為何？**

A：LEAP 首先在 Qwen3-Omni-30B-A3B 上進行實驗，並在多個 AVQA 基準測試上將準確率提升了 4.5% 至 16.8%。此外，LEAP 也能遷移到另一個全模態骨幹模型 MiniCPM-o 4.5，並超越其已發表結果 3.1% 至 13.0%。這顯示該框架不僅對單一骨幹有效，也具備跨骨幹的泛化能力。

**Q8：定位 LoRA 與回答 LoRA 各自負責優化什麼？**

A：定位 LoRA 負責微調證據定位階段，使模型能更準確地挑選出與問題相關的候選時間窗。回答 LoRA 則負責微調最終的回答階段，使模型在讀取相同保留窗時能產生更正確的答案。兩個 LoRA 分別對應檢索與推理兩個環節，並透過聯合訓練提升整體問答表現。

**Q9：從訓練階段的消融角度來看，兩個 LoRA 的貢獻說明了什麼？**

A：實驗結果顯示，定位訓練能改善檢索階段所選出的窗口品質，讓回答階段獲得更相關的證據；回答訓練則能提升模型從這些窗口中讀取並推理出正確答案的能力。兩者缺一不可，因為即使選到好窗口，若回答模型無法正確解讀，最終表現仍會受限。這也驗證了 LEAP 將定位與回答分開學習的設計是合理的。

**Q10：LEAP 如何支援串流推論，且為何無需串流專屬訓練？**

A：LEAP 的固定區塊網格天然具有因果性，因為在查詢時間點之前只會存在已經到達的區塊。定位階段可以針對截至查詢時刻的媒體區塊或線上轉錄稿索引進行評分與選窗，回答階段再從原始媒體中重新讀取這些窗口。由於區塊劃分與兩階段流程本身不違反因果約束，LEAP 無需額外的串流專屬訓練即可進行串流推論。

**Q11：在實際產品部署中，LEAP 有哪些值得考量的優勢與權衡？**

A：LEAP 允許預先計算轉錄稿並建立索引，讓多個問題能共享同一份輕量級檢索通道，降低重複解碼原始媒體的開銷。最終只對少數高分窗口重新編碼原始音視訊，能在計算成本與證據保真度之間取得平衡。此外，O(1) 的上下文複雜度意味著即使硬體上下文有限，也能處理小時級錄影，提升產品可擴展性。

**Q12：LEAP 對長篇音視覺問答領域可能帶來什麼影響？**

A：LEAP 證明了透過學習式區塊證據檢索，可以在不讀取整段錄影的情況下，同時兼顧長程覆蓋與局部細節密度。它為全模態骨幹模型處理小時級內容提供了一個可擴展的替代方案，並且能跨不同骨幹遷移。這可能促使未來更多研究將「檢索」與「推理」分離，並探索多通道檢索在長時多模態理解中的應用。

**Q13：LEAP 有哪些潛在或隱含的局限性？**

A：LEAP 在定位階段依賴自動語音辨識產生的轉錄稿，若轉錄品質不佳或問題證據主要來自非語音線索，定位準確度可能會下降。此外，固定時長區塊可能與真實事件邊界不對齊，導致關鍵證據被切分到相鄰區塊而得分降低。這些因素意味著 LEAP 的檢索品質仍會受到前端轉錄與區塊粒度設計的影響。

**Q14：LEAP 可能在哪些情況下出現失敗？**

A：如果回答某個問題所需的證據高度分散在許多短暫窗口中，超出有界回答階段能保留的數量，模型就會遺失部分線索。當問題表述模糊或需要跨很長時間範圍進行綜合推理時，定位階段也可能給出錯誤的窗口分數。在這些情況下，即使回答 LoRA 很強，也難以從不完整的證據中得出正確答案。

**Q15：未來可以從哪些方向進一步改進 LEAP？**

A：未來可以研究自適應區塊與候選窗大小，使區塊邊界更貼近事件發生範圍，減少證據被切分的問題。也可以探索定位階段與回答階段的聯合端到端訓練，或引入視覺、音訊等非文字檢索通道來輔助轉錄稿。此外，針對串流場景設計線上學習或持續更新機制，將是提升即時長篇音視覺問答能力的重要方向。

## 實務應用指南

### 適用場景

**長時會議與訪談回顧**：企業內部數小時的會議錄影、客戶訪談或焦點團體討論，常需要回答「誰在第三十分鐘反對這個預算？」「會中是否有人提到交期延後？」等問題。LEAP 可在不切完整錄影進上下文的前提下，先以轉錄稿快速定位相關區塊，再回頭細讀原始音視訊，保留語氣、表情與非語音線索。

**教育與線上課程問答**：針對一小時以上的教學影片，學生可詢問「老師在哪一段講到梯度消失？」「實驗示範時出現了什麼聲音？」。LEAP 的區塊網格能將課程切分為固定時長區塊，透過輕量級定位階段篩選候選時間窗，再以有界回答階段進行密集推理，避免將整堂課塞入模型。

**監控與安全事件調查**：數小時的監視器錄影需要回答「昨晚十一點後是否有異常聲響？」「可疑人物何時出現在走廊？」。LEAP 可先以轉錄稿或低解析度特徵進行區塊式證據檢索，再對保留時間窗重新編碼高畫質影像與原始音訊，兼顧覆蓋率與細節密度。

**直播與串流內容即時問答**：在新聞直播、運動賽事或線上研討會中，觀眾可能在進行中提問「剛才主播提到什麼數字？」。LEAP 的區塊網格天然支援因果查詢，可在不針對串流情境重新訓練的情況下，只處理查詢時間點之前的媒體前綴，實現串流推論。

**法律與合規影音審查**：律師或合規人員需要從數小時的聽證會、內部訓練影片或通話錄音中，找出特定陳述或事件發生的時間點。LEAP 能將證據定位與推理解耦，先以預先計算轉錄稿進行掃描，再對關鍵時間窗進行原始音視訊的精細驗證。

### 實作前置條件

**資料準備**：需要原始音視訊檔案以及對應的自動語音辨識（ASR）轉錄稿，轉錄稿最好帶有時間戳記以便對齊區塊網格。若任務涉及視覺細節，需保留原始影片而非僅使用壓縮後的低解析度版本。訓練資料方面，需要成對的問題、正確答案以及答案所對應的時間區間標註，才能訓練定位 LoRA 與回答 LoRA。

**運算資源**：推論階段需要能載入全模態骨幹模型（如 Qwen3-Omni-30B-A3B 或 MiniCPM-o 4.5）的 GPU 記憶體。由於 LEAP 將長錄影切分為固定時長區塊並逐區塊執行定位階段，整體計算量會高於單次全錄影編碼，但峰值上下文與工作記憶體維持 O(1)。訓練階段因使用 LoRA，所需顯存遠低於全模型微調，但仍需至少一張高階 GPU。

**技術能力**：團隊需熟悉大型多模態模型的推論與微調流程，具備 PyTorch 或相關框架經驗。需要能夠處理音視訊解碼、時間戳對齊、ASR 後處理，以及設計區塊劃分與候選時間窗的參數。此外，需理解檢索增強生成（RAG）與參數高效微調（PEFT）的基本概念，才能正確設定兩階段的 LoRA。

### 實作步驟建議

**步驟一：建立區塊網格與轉錄索引**。將長錄影劃分為不重疊的固定時長區塊，並為每個區塊產生帶時間戳的轉錄稿。區塊長度需在覆蓋率與定位粒度之間權衡，例如 1–5 分鐘。每個區塊再進一步劃分為短候選時間窗，作為證據選擇的基本單位。

**步驟二：建置基礎選擇器**。使用預先計算轉錄稿執行輕量級定位階段。將問題與每個區塊的轉錄文本送入模型，讓模型對該區塊內的候選時間窗評分，並依分數排序保留高分區塊與高分時間窗。此階段無需解碼媒體幀，可大幅降低初始檢索成本。

**步驟三：訓練定位 LoRA**。收集問題與正確時間區間的標註資料，微調定位 LoRA，使模型更擅長從轉錄稿或媒體中選出真正包含答案的候選時間窗。此步驟直接改善後續保留時間窗的品質。

**步驟四：執行有界回答階段**。將定位階段選出的高分時間窗匯集起來，從原始音視訊串流中重新編碼這些保留時間窗，並與問題一起送入模型。由於保留窗數量固定，回答階段的輸入長度與峰值上下文均與錄影總長度無關。

**步驟五：訓練回答 LoRA**。使用相同的高分時間窗標註資料，微調回答 LoRA，讓模型學會從已選定的時間窗中讀取答案。此階段專注於如何從密集音視訊證據中推理，而非如何定位。

**步驟六：部署與串流擴充**。將訓練好的兩個 LoRA 與基礎選擇器整合為推論管線。若需支援串流推論，只需確保定位階段僅搜尋查詢時間點之前的區塊，並從原始媒體中重新讀取對應前綴，無需額外的串流專屬訓練。

### 潛在風險與注意事項

**轉錄稿品質影響定位準確度**：若 ASR 錯誤率高、缺少時間戳或遺漏非語音事件，基礎選擇器可能漏掉關鍵區塊。建議使用高品質 ASR 模型，並在定位階段保留一條媒體路徑作為備援，對高不確定性區塊直接以原始音視訊評分。

**區塊長度設定造成權衡**：區塊過長會降低定位精度，區塊過短則會增加定位階段的呼叫次數與整體延遲。建議依據任務特性進行實驗，並考慮讓區塊長度與常見事件長度對齊。

**候選時間窗遺漏分散證據**：若答案線索分散在多個極短時間窗，而保留窗數量設得太少，可能遺漏部分證據。可透過增加保留窗數量上限，或在定位階段引入多樣性機制，避免所有保留窗都來自同一區塊。

**兩階段訓練資料不一致**：若定位 LoRA 與回答 LoRA 使用不同分佈的訓練資料，可能出現定位選得好但回答讀不懂，或回答訓練的窗與實際定位結果不一致的問題。建議兩個 LoRA 共用同一組時間區間標註，並在訓練時模擬真實推論流程。

**計算成本與延遲**：LEAP 雖然將峰值上下文控制在 O(1)，但總計算量因兩階段編碼而增加。在產品部署時需評估端到端延遲是否符合需求，並可透過快取常用區塊的轉錄特徵與媒體特徵來加速。

### 與其他技術的整合建議

**與向量資料庫結合**：可將每個區塊的轉錄稿與視覺摘要嵌入向量資料庫，先以語意搜尋縮小候選區塊範圍，再讓 LEAP 的區塊式定位階段在縮小後的集合上進行精細評分，進一步降低長錄影的檢索開銷。

**與現有 RAG 管線整合**：LEAP 可視為一種多模態 RAG，其中「檢索」對應定位階段，「生成」對應回答階段。可將其嵌入企業知識管理系統，與文件檢索、圖片檢索等模組並列，根據問題類型決定是否啟動音視訊證據檢索。

**與串流處理框架整合**：在 Kafka、Apache Flink 等串流平台上，可隨著錄影到達動態建立區塊與轉錄索引。當使用者提問時，系統只查詢已抵達的區塊，並從原始串流中截取對應時間窗，實現真正的即時長時音視覺問答。

**與模型服務化平台整合**：可將定位 LoRA 與回答 LoRA 部署為獨立服務或同一服務的兩個階段，透過 API 接收問題與錄影識別碼，回傳答案與對應時間戳。建議將轉錄稿與區塊特徵預先計算並儲存，減少重複處理。

### 給不同背景讀者的閱讀建議

**給初學者**：這篇論文處理的是「如何讓 AI 回答長達數小時影片的問題」。你可以把 LEAP 想像成先看目錄與摘要找出相關章節，再仔細閱讀那幾頁的讀書方法。重點在於它把「找證據」和「讀懂證據」分成兩個步驟，並且先用文字轉錄稿快速定位，再回頭看原始影片細節。閱讀時請先理解圖一的整體流程，再回頭看方法細節。

**給 AI 工程師**：論文的核心價值在於提供一個可落地的兩階段管線：區塊式定位階段與有界回答階段。你應特別關注如何將長錄影切分為固定時長區塊、如何設計候選時間窗的評分機制、以及如何分別訓練定位 LoRA 與回答 LoRA。實作時請注意轉錄稿與原始媒體的時間對齊、兩階段訓練資料的一致性，以及峰值上下文與總計算成本的權衡。

**給研究人員**：LEAP 的貢獻在於提出「學習式區塊證據檢索」框架，將證據定位與推理解耦，並展示轉錄稿可作為第二條掃描通道。值得進一步探索的方向包括：更彈性的區塊劃分策略、定位階段與回答階段的聯合訓練、跨骨幹模型的遷移機制，以及如何在串流情境下維持因果一致性。此外，非語音證據與視覺細節在轉錄稿遺漏時的補償機制也是有趣的研究點。

**給產品經理**：這項技術適合任何需要從長時音視訊內容中快速找答案的產品場景，例如會議助理、課程問答、監控調查與直播互動。它的商業價值在於突破了全模態模型上下文長度限制，讓小時級內容也能進行精細問答。評估導入時，請優先確認 ASR 品質、是否有時間區間標註資料可用於微調、以及終端使用者對延遲的容忍度。建議從轉錄稿品質較高、問題類型明確的場景開始試點。
