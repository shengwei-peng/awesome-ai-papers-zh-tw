## 論文問答

**Q1：為什麼歷史檔案的翻譯對學術研究如此重要？特別是朝鮮王朝實錄（AJD）和承政院日記（JRS）？**
A：歷史檔案是跨學科研究的珍貴資料來源，在人文學科中能幫助研究者分析政治動態與文化演變，在自然科學中則可追溯日食、超新星、地震活動等自然現象。朝鮮王朝實錄（AJD）與承政院日記（JRS）因其跨越五百多年的連續性與系統性記錄，被全球學術界視為極具價值的史料，內容涵蓋國政事務、行政、天文觀測、饑荒與流行病等多元主題。這些檔案的持續性管理使其特別適合用於分析宏觀的長期變遷，因此讓全球研究者能夠取用這些資料具有重大意義。

**Q2：為什麼直接套用現有的中英大型語言模型無法有效翻譯韓國漢文歷史檔案？**
A：直接使用中英大型語言模型會遭遇多重根本性障礙。首先是文字系統不匹配的問題，這些模型通常以簡體中文訓練，但韓國漢文保留的是繁體中文形式，造成字符不相容。其次，即使字符相同，同形異義詞在兩種語言中已演變出截然不同的語義，加上韓國漢文含有反映本土語法結構的特有用法，語序也經常偏離標準中文句法。最關鍵的是，這些模型會依據中文發音而非韓文發音來音譯專有名詞（如人名與地名），這不僅降低翻譯品質，更會引入事實錯誤。

**Q3：人工翻譯這些歷史檔案面臨哪些實際挑戰？為什麼迫切需要發展自動化方案？**
A：人工翻譯需要精通漢文與英語的專家，國史編纂委員會（NIKH）推動的AJD英譯計畫預估需耗時22年、預算約2,000萬美元，顯示其成本極為高昂。若將此模式套用於體積為AJD五倍的承政院日記（JRS），所需的時間與資源將更為驚人。此外，現有的人工翻譯英語語料不僅數量稀少，還嚴重偏向特定君王在位時期，造成時間偏差，使得模型在未見過的歷史時期上表現不佳，這凸顯出發展能夠泛化至不同朝代、緩解資料稀缺問題的自動化翻譯方法的迫切性。

**Q4：HERIT的核心方法是什麼？它採用怎樣的整體流程來解決問題？**
A：HERIT（Hanja-English RAG-based Intelligent Translation model）是一套系統性的領域適應流程，專門用於訓練適用於歷史檔案的漢文到英語翻譯模型。其核心策略是引入檢索增強的上下文學習方法進行資料擴增，從豐富的漢文-韓文語料庫中產生高品質的偽標註資料。這種做法能有效擴充訓練資料集的規模與多樣性，同時緩解資料稀缺與時間過擬合的問題，使模型能夠在不同歷史時期之間良好泛化。

**Q5：為什麼選擇使用檢索增強生成（RAG）來產生偽標註資料？這種方法有何獨特優勢？**
A：選擇RAG是因為它能結合大型語言模型的少樣本學習能力與檢索到的相關範例，在推論階段引入模型在預訓練或微調階段未曾見過的資訊。在資料稀缺的領域中，這種策略能有效擴增訓練資料，因為它可以利用豐富的漢文-韓文語料庫作為基礎，透過檢索相關上下文來引導模型產生更貼近目標領域風格的翻譯。相較於從零開始訓練或僅依賴少量人工標註語料庫，RAG產生的偽標註資料品質更高，且能涵蓋更多元的歷史時期，從而緩解時間偏差並提升模型的泛化能力。

- 對漢文/漢字文化圈語言特性有基本認識（繁簡差異、漢文訓讀、專有名詞音譯規則）。

### 實作步驟建議

1. **界定範圍與盤點資料**：先確認目標語料（AJD、JRS 或其他漢文檔案）、目標君王時期、預期翻譯量；盤點現有人工漢英平行句對的覆蓋時期，識別時間偏差。

2. **建立三語詞彙表**：從既有韓譯本與英譯本中萃取專有名詞（人名、地名、官職、曆日、制度名稱），建立 Hanja–Korean–English 對照表，作為後續檢索與提示工程的錨點。

3. **建構檢索索引**：將人工漢英平行句對與漢韓平行句對切成段落級 chunk，使用多語言嵌入模型（如 BGE-M3、E5-multilingual）建立向量索引；同時保留 metadata（君王時期、年代、來源）。

4. **設計 RAG 偽標註流程**：
   - 從大量漢韓語料中取句，以韓文譯本為輸入，透過 LLM 進行 in-context learning 生成英文翻譯。
   - 檢索階段同時回傳：① 相似的人工漢英例句、② 對應的漢韓句對、③ 相關詞彙表條目。
   - 採用 Best-of-N 或 Fusion-of-N 等策略取最佳候選，並以規則過濾（專有名詞韓式發音、曆法格式等）。

5. **領域適應微調**：以人工漢英資料為主、偽標註資料為輔，混合訓練；可採兩階段：先以偽標註資料做大範圍領域適應，再以人工資料做監督微調以避免漂移。

6. **評估與迭代**：
   - 自動指標：BLEU、chrF、COMET，並依君王時期分組觀察。
   - 人工評估：邀請漢學/韓學專家進行忠實度 (faithfulness)、流暢度 (fluency)、專有名詞正確性評分。
   - 特別檢查未見過時期的表現，確認時間偏差已緩解。

7. **部署與釋出**：以 vLLM、TGI 或 ONNX Runtime 部署推論服務；提供 CLI/Web UI；將模型與翻譯成果以開源形式釋出，附上詞彙表與評估報告。

8. **持續擴充**：將新翻譯的人工校對結果回流至訓練集與詞彙表，形成 active learning 閉環。

---

### 潛在風險與注意事項

- **專有名詞音譯錯誤**：中文 LLM 傾向以中文發音音譯人名地名（如將「世宗」誤為 Shìzōng 而非 Sejong）。**緩解**：在 prompt 中強制附上詞彙表，並以規則後處理比對韓文發音。

- **繁簡字符不相容**：韓國漢文使用繁體字，中文模型預訓練以簡體為主。**緩解**：微調前先以 Unicode 正規化與繁簡轉換工具預處理，並在訓練資料中保留繁體形式。

- **偽標註資料的幻覺與錯誤傳播**：LLM 生成可能捏造事實或語意偏移。**緩解**：採用 Best-of-N 多候選投票、以人工資料做 KL/對齊約束、保留人工資料的高權重。

- **時間過擬合**：若訓練資料集中於特定君王時期，模型在其他時期表現可能崩跌。**緩解**：依時期分層抽樣、加入時期標籤 embedding、定期以跨時期評估集驗證。

- **語意與句法偏差**：韓國漢文語序與中文不同，且同形異義詞語義分歧。**緩解**：在 prompt 中提供句法範例，並以對比學習強化漢文–韓文對齊。

- **評估指標失真**：BLEU 對歷史文體與專有名詞不敏感。**緩解**：搭配 COMET、人工評估，並建立領域專屬評估集。

- **文化敏感性與詮釋偏差**：歷史紀錄涉及政治評價、禮制用語，誤譯可能引發爭議。**緩解**：邀請歷史學者審閱關鍵段落，並在產品中標註「機器翻譯，建議人工核校」。

- **資料授權與版權**：AJD、JRS 的韓譯與英譯可能有不同授權。**緩解**：事前確認 NIKH 與相關機構的資料使用條款，於開源時附上授權聲明。

### 與其他技術的整合建議

- **OCR 流程**：與 Hanzi OCR（如 KRFinBERT-OCR、TrOCR）串接，建立「影像 → 漢文 → 英文」端到端管線；OCR 階段輸出的字符信心度可作為翻譯階段的提示。

- **知識圖譜**：將翻譯結果中的實體（人名、地名、事件）抽取後串接至 Neo4j 或 Wikidata，支援關聯查詢與時序分析。

- **RAG 與長上下文 LLM**：可將 HERIT 的檢索機制擴充為多模態 RAG，結合原文影像、註釋、研究論文作為上下文。

- **主動學習與人機協作**：整合 Prodigy、Label Studio 等標註平台，讓專家在校對 HERIT 輸出的同時回饋訓練資料。

- **多語言延伸**：以漢文為樞紐，將方法移植至日文漢文（候文）、越南漢文（漢喃），建立東亞漢文圈的統一翻譯框架。

- **搜尋與索引**：將翻譯後的英文文本導入 Elasticsearch 或 OpenSearch，提供全文檢索與高亮，支援研究者跨語言查詢。

- **API 與微服務**：以 FastAPI/gRPC 包裝翻譯服務，部署於 Kubernetes，配合 Prometheus/Grafana 監控吞吐量、延遲、詞彙命中率。

---

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節，了解「為什麼不能直接用中文模型翻韓國漢文」以及「什麼是時間偏差」；接著看圖 1 的整體流程圖，掌握「人工資料 + 偽標註 + 微調」三層概念即可，不必深陷技術細節。若對機器翻譯陌生，可先補充 BLEU 與 RAG 的基礎知識。

**給 AI 工程師**：重點放在第 2 節的相關工作與方法章節，特別是 RAG 偽標註的檢索設計、Best-of-N/Fusion-of-N 策略、領域適應微調的兩階段流程；建議直接重現作者的開源程式碼，並嘗試以 LoRA 替換全參數微調、評估不同基礎模型（Qwen3、Llama-3 等）的表現差異。

**給研究者**：關注「時間偏差」的診斷方法與跨時期評估設計，這是本論文對低資源歷史 NLP 的核心貢獻；可進一步思考如何將此框架應用於其他時間敏感領域（法律、醫學文獻演化、學術語料跨年代分析），並探索更嚴謹的因果式評估。

**給產品經理**：聚焦於商業價值與可行性——相較 2,000 萬美元、22 年的人工翻譯，HERIT 提供了數量級的成本壓縮；建議評估自身產品中是否存在「少量人工標註 + 大量單語資料」的低資源翻譯場景，並將 HERIT 的 RAG 偽標註視為可重複使用的範式，而非僅限於韓國漢文。同時務必將「專有名詞正確性」與「文化敏感性」列為上線前的強制驗收項目。
