## 摘要翻譯

大型視覺語言模型（Large Vision-Language Models, LVLMs）仍受限於龐大的運算足跡（computational footprint），使其難以部署於資源受限（resource-constrained）的邊緣裝置（edge devices）。雖然現有壓縮 LVLMs 的研究主要集中於視覺標記縮減（vision token reduction）或較小語言模型（smaller language models），但視覺編碼器（vision encoder）卻在很大程度上被忽視，通常被部署為單體式（monolithic）且運算量龐大的特徵提取器（feature extractor）。此外，過去並沒有專門為 LVLMs 設計、直接針對裝置端延遲（on-device latency）最佳化的視覺編碼器研究。在本文中，我們提出 UltraViT，一個專為 LVLMs 設計、明確針對裝置端效能（on-device performance）最佳化的視覺編碼器。具體而言，我們考量真實裝置端延遲（real on-device latencies），系統化地設計了一個金字塔架構（pyramidal architecture），在巨區塊層級（macro-block level）策略性地整合並調適異質空間混合器（heterogeneous spatial mixers）。此外，為了預訓練 UltraViT，我們提出了一種新穎的兩階段生成式預訓練（two-stage generative pre-training）策略：首先透過密集蒸餾（dense distillation）學習豐富的空間特徵，接著由容量混合凍結大型語言模型（capacity-mixed frozen LLM）提供直接的生成式監督（generative supervision）。相較於標準對比式訓練（contrastive training）與自監督式學習（self-supervised learning, SSL），我們證明本預訓練方法對於 UltraViT 達成高層次語義接地（high-level semantic grounding）更為有效，而這正是後續 LVLM 訓練中生成式多模態對齊（generative multimodal alignment）所需要的。大量實驗（extensive experiments）證明，我們以真實裝置端延遲資訊為導向的設計結合量身打造的訓練策略，為高效 LVLM 編碼建立了新的最佳水準（state-of-the-art），在顯著優於現有以編碼器為主之基線（encoder-centric baselines）的同時，於裝置端以快近 1.7 倍的速度運行。

### 核心貢獻（3～5點）
- 提出 UltraViT，首個專為 LVLMs 設計並針對真實裝置端延遲最佳化的視覺編碼器。
- 設計金字塔架構，在巨區塊層級策略性地整合異質空間混合器，以實現高效的裝置端執行。
- 提出兩階段生成式預訓練策略：先以密集蒸餾學習豐富空間特徵，再以容量混合凍結大型語言模型進行生成式監督。
- 證明所提預訓練方法相較於對比式與自監督式學習，更能有效達成高層次語義接地。
- 在裝置端達到近 1.7 倍加速，同時顯著優於現有以編碼器為主之基線。

### 適合對象
從事邊緣裝置上多模態模型部署與最佳化的研究者與工程師，特別是關注視覺編碼器設計、裝置端延遲最佳化、生成式預訓練，以及大型視覺語言模型壓縮與效率化的讀者。

## 深度分析

#### 方法論解析

##### 1. 設計動機與問題定位

UltraViT 的核心命題在於：現有大型視覺語言模型（Large Vision-Language Models, LVLMs）雖然在準確度與推理能力上表現卓越，但其巨大的參數量（parameter counts）與運算足跡（computational footprint）使其難以部署於資源受限（resource-constrained）的邊緣裝置（edge devices）。過去針對高效化 LVLMs 的研究主要聚焦於兩條路徑：

- **視覺標記縮減（vision token reduction）**：透過標記稀疏化（token sparsification）、訓練式壓縮模組或事後（post-hoc）剪枝來縮短視覺上下文（visual context）長度。
- **輕量語言模型（smaller language models）**：搭配參數更小的語言模型並設計更高效的跨模態互動機制（cross-modal interaction mechanisms）。

然而，這些方法大多將視覺編碼器（vision encoder）視為固定特徵提取器（fixed feature extractor），例如 CLIP-ViT-L 或 SigLIP-400M，這些單體式（monolithic）且運算僵化的模型在處理高解析度影像（high-resolution images）或影片（video）時會成為嚴重瓶頸（bottleneck）。UltraViT 因此主張應從源頭重新設計視覺編碼器，使其在架構層面即針對裝置端延遲（on-device latency）進行最佳化，而非僅在編碼器後端疊加壓縮模組。

##### 2. 異質金字塔架構

UltraViT 採用**金字塔架構（pyramidal architecture）**，其設計原則並非像傳統高效視覺 Transformer（Vision Transformers, ViTs）那樣在整個網路中均勻複製單一空間混合器（spatial mixer），而是根據不同階段的特徵解析度與語義需求，策略性地整合**異質空間混合器（heterogeneous spatial mixers）**。

具體而言：

- **巨區塊層級（macro-block level）設計**：UltraViT 在宏觀上以區塊為單位選擇最適合的運算元，而非微調單一區塊內的通道數或層數。這種「階段異質」策略能夠針對不同解析度階段分配最適合的運算資源。
- **底層運算（underlying operations）的 NPU/行動裝置執行（NPU/mobile execution）適配**：每個空間混合器的內部實作都經過調整，以配合神經處理單元（NPU）與行動裝置的記憶體頻寬與計算特性。這意味著 UltraViT 不僅追求理論 FLOPs 降低，更以**真實裝置端延遲（real on-device latencies）**作為架構搜尋與設計的依據。
- **規避事後視覺標記壓縮器（post-hoc vision token compressors）**：由於編碼器本身已經精簡（compact）且高效（efficient），UltraViT 不需要在編碼器輸出後額外加入壓縮模組，從而避免壓縮帶來的資訊損失與額外延遲。

這種設計與傳統「同質區塊設計（homogeneous block formulation）」形成鮮明對比。後者通常在整個網路中統一使用稀疏注意力（sparse attention）、深度可分卷積模組（depthwise convolutional modules）或標準注意力（vanilla attention），雖然在 ImageNet 影像分類（ImageNet classification）上表現良好，但對於 LVLMs 所需的密集影像理解（dense image understanding）與多模態推理（reasoning）並非最適。

##### 3. 兩階段生成式預訓練策略

UltraViT 的另一大貢獻在於提出專為其架構量身打造的**兩階段生成式預訓練（two-stage generative pre-training）**：

**第一階段：密集蒸餾（dense distillation）**

- 從一個強健的高解析度教師模型進行**密集特徵蒸餾**，以培養豐富的空間特徵。
- 這一步彌補了對比式訓練（contrastive training）過於粗糙的缺點，也彌補了遮罩影像建模（Masked Image Modeling, MIM）與 DINO 等自監督式學習（self-supervised learning, SSL）方法雖具備良好密集定位（dense localization）能力、卻缺乏高層次語義（high-level semantic）的問題。

**第二階段：容量混合凍結大型語言模型（capacity-mixed frozen LLM）的生成式監督（generative supervision）**

- 將 UltraViT 連接到一個**凍結大型語言模型（frozen LLM）**，透過直接的標記生成（token generation）目標進行監督。
- 為了在維持計算效率的同時獲得穩定的生成式多模態對齊（generative multimodal alignment）訊號，作者提出**動態 LLM 混合策略（dynamic LLM mixing strategy）**：在訓練過程中抽樣並混合不同容量（capacity）的 LLM。
- 由於 LLM 權重凍結，此階段主要更新視覺編碼器，使其學到的特徵更貼近後續 LVLMs 訓練所需的語義接地（semantic grounding）。

整體而言，這套預訓練策略試圖解決一個根本矛盾：標準對比式預訓練（如 CLIP）雖然能提供語義訊號，但與生成式標記生成目標存在錯位；而重建式 SSL 雖然保留空間細節，卻不利於高層次語義對齊。UltraViT 透過「先學空間、再學生成語義」的兩階段方式，試圖同時兼顧兩者。

- **新的最先進水準（state-of-the-art）**：在以編碼器為主的基線（encoder-centric baselines）中表現最佳。

- **裝置端速度提升近 1.7 倍**：相較於現有編碼器中心基線，UltraViT 在實際邊緣裝置上的執行延遲更低。

##### 2. 數據意涵

若上述宣稱成立，則代表：

- **延遲最佳化設計確實轉化為真實裝置端效能（on-device performance）**：1.7× 的速度提升並非僅來自理論 FLOPs 下降，而是來自以真實裝置端延遲為導向的架構選擇。這對於行動裝置部署具有實質意義，因為理論計算量與實際延遲之間常存在顯著落差。

#### 與現有研究的比較

##### 1. 相較於傳統高效 ViT 典範

現有高效視覺 Transformer 典範（efficient ViT paradigms），如 MobileViT、EfficientFormer、FastViT 等，雖然在行動裝置上表現優異，但其設計目標多為 ImageNet 影像分類，而非 LVLMs 所需的密集影像理解與高層次語義推理。UltraViT 的差異在於：

- **目標任務不同**：從一開始就以 LVLMs 的生成式多模態對齊為目標。
- **設計準則不同**：以真實裝置端延遲為導向，而非僅以降低 FLOPs 或參數量為目標。
- **架構異質性**：打破同質區塊設計，根據不同階段需求選擇最適空間混合器。

##### 2. 相較於 FastVLM

FastVLM 是目前少數同樣意識到視覺編碼器瓶頸並針對 LVLMs 進行設計的方法。UltraViT 相對於 FastVLM 的潛在優勢包括：

- **更徹底的異質化**：FastVLM 可能仍採用某種程度的同質區塊設計，而 UltraViT 強調在巨區塊層級進行異質空間混合器的策略性整合。
- **專屬預訓練策略**：FastVLM 可能沿用傳統對比式預訓練，而 UltraViT 提出兩階段生成式預訓練，試圖更貼近 LVLMs 的訓練目標。
- **更高的裝置端速度**：論文宣稱 UltraViT 比 FastVLM 快近 1.7 倍，同時維持更佳準確度。

##### 3. 相較於視覺標記壓縮方法

許多現有研究透過視覺標記壓縮器（vision token compressors）來降低視覺上下文長度。這類方法的優點在於可與現成編碼器搭配使用，但缺點包括：

- **資訊損失**：壓縮過程可能丟失細粒度空間資訊。
- **額外延遲與記憶體開銷**：壓縮模組本身需要計算與儲存。
- **非端到端最佳化**：壓縮器與編碼器分開設計，難以達到全局最佳。

UltraViT 透過從源頭設計精簡編碼器，完全規避了事後壓縮的需求，這是其核心差異化價值主張。

##### 4. 限制與潛在弱點

儘管 UltraViT 的設計理念具有說服力，但仍存在以下潛在限制：

- **設計與搜尋成本**：異質架構雖然效能佳，但其空間混合器組合與階段配置可能需要大量裝置端延遲測量與架構搜尋，這增加了重複設計與移植到新裝置的難度。
- **泛化性未明**：目前論文強調 LVLMs 任務，但 UltraViT 在傳統電腦視覺任務（如偵測、分割）上的表現尚不清楚。
- **對 LLM 的依賴**：第二階段預訓練需要凍結的容量混合 LLM，這些模型的選擇與混合策略可能影響最終表現，且對運算資源仍有要求。
- **可解釋性**：異質混合器在不同階段的角色與其對特徵表示的影響，可能需要更多視覺化與消融實驗來支撐。

#### 未來研究方向

基於 UltraViT 的設計理念與目前可見的內容，以下幾個方向值得進一步探索：

##### 1. 自動化異質架構搜尋

目前 UltraViT 的空間混合器選擇似乎是基於原則性設計與延遲測量。未來可發展針對裝置端延遲的**神經架構搜尋（Neural Architecture Search, NAS）**，自動在不同硬體目標上搜尋最適的異質混合器配置，進一步降低人工設計成本。

##### 2. 多解析度與動態輸入適應

LVLMs 在實際應用中常需處理不同解析度的影像。未來可研究如何讓 UltraViT 根據輸入解析度或任務難度動態調整計算路徑，實現自適應延遲與準確度權衡。

##### 3. 擴展至影片與多幀理解

論文已提及影片（video）處理是視覺編碼器的潛在瓶頸。未來可將 UltraViT 擴展至影片 LVLMs，設計具時間感知（temporal-aware）的異質空間-時間混合器，並針對影片串流的連續推論進行延遲最佳化。

##### 4. 與新興輕量 LLM 的協同設計

隨著邊緣部署的語言模型持續縮小（如 0.5B 或 1.5B 參數），視覺編碼器在總延遲中的佔比將進一步上升。未來可將 UltraViT 與極輕量 LLM 進行**聯合最佳化（joint optimization）**，而非僅將 LLM 視為凍結監督來源。

##### 5. 預訓練目標的進一步整合

兩階段預訓練雖然有效，但仍分為蒸餾與生成監督兩個獨立階段。未來可研究是否能將密集空間特徵學習與生成式語義對齊整合為單一統一目標，簡化訓練流程並可能提升效率。

##### 6. 開放生態與標準化評測

鑒於裝置端延遲測量高度依賴硬體與軟體堆疊，未來社群可建立標準化的**裝�置端視覺編碼器評測基準（on-device vision encoder benchmark）**，涵蓋不同 NPU、解析度與 LVLM 骨幹，以便公平比較 UltraViT 與後續方法。

## 論文問答

**Q1：大型視覺語言模型在邊緣裝置上部署時，主要的運算瓶頸是什麼？**
A：目前大型視覺語言模型（LVLMs）的推論成本極高，其中視覺編碼器往往被當作單體式且計算沉重的固定特徵提取器來部署，例如 CLIP-ViT-L 或 SigLIP-400M。這些龐大的編碼器在處理高解析度影像或影片時會造成嚴重的延遲，甚至在某些行動裝置配置中佔據近五成的端到端推論時間。相較於過去研究多聚焦於視覺標記縮減或縮小語言模型，視覺編碼器本身的架構設計長期被忽視，因此成為限制裝置端部署的關鍵瓶頸。

**Q2：為什麼現有針對 ImageNet 分類設計的高效 Vision Transformer 不適合直接用於 LVLM 的裝置端編碼？**
A：現有許多行動裝置友善的 ViT 架構主要是為了 ImageNet 影像分類任務進行最佳化，目標是辨識整張影像的類別，而非 LVLM 所需的密集影像理解與多模態推理。這些典範通常採用同質區塊設計，例如在整個網路中重複使用單一種稀疏注意力或深度可分卷積模組，這樣的設計無法根據不同階段的語義需求靈活調整空間資訊的混合方式。因此，當必須同時考量裝置端延遲與高層次語義接地能力時，同質化的空間混合器配置會顯得次優。

**Q3：隨著語言模型越來越小，為什麼視覺編碼器的最佳化變得更加重要？**
A：當語言模型骨幹縮小到 0.5B 或 1.5B 參數等級時，視覺編碼器在總推論延遲中的佔比會變得不成比例地高，例如 SigLIP-400M 搭配 1.5B Qwen2.5 的組合在 1024×1024 影像上，視覺特徵提取可佔近一半的行動裝置推論時間。這表示僅靠縮減語言模型或壓縮視覺標記已無法有效降低整體延遲，必須從源頭重新設計視覺編碼器。因此，針對裝置端延遲進行編碼器層級的最佳化，是實現真正可部署 LVLM 的關鍵步驟。

**Q4：UltraViT 的核心架構設計是什麼？**
A：UltraViT 是一個專為裝置端 LVLM 設計的金字塔型視覺編碼器，其最大特色是在巨區塊層級策略性地整合異質空間混合器。具體而言，它會根據網路不同階段的需求選擇並調整不同的空間混合器，同時針對 NPU 與行動裝置執行特性調整底層運算。這種設計不僅能降低實際裝置端延遲，也能保留密集影像理解所需的多尺度空間表徵。

**Q5：UltraViT 與傳統同質化 ViT 設計的主要差異為何？**
A：傳統高效 ViT 通常將單一種空間混合器均勻複製到整個網路，或僅與標準注意力簡單組合，而 UltraViT 則是依據模型所處位置與特徵解析度，有原則地選擇適合的混合器。這種異質配置讓網路在淺層可更有效地捕捉局部細節，在深層則能建模全局語義關聯。相較於同質區塊設計，UltraViT 能同時滿足裝置端延遲限制與 LVLM 對密集推理的嚴苛需求。

**Q6：UltraViT 提出了什麼樣的兩階段生成式預訓練策略？**
A：第一階段透過高解析度教師模型進行密集特徵蒸餾，以培養豐富的空間表徵能力；第二階段則將編碼器連接到凍結的大型語言模型，直接以生成式目標進行監督。為了在第二階段維持計算效率，作者提出容量混合凍結 LLM 策略，透過取樣並混合不同容量的語言模型來提供多樣化的生成訊號。這種預訓練方式能彌補對比式學習過於粗糙、以及遮罩影像建模過於低階的缺陷，使編碼器更適合後續的生成式多模態對齊。

**Q7：UltraViT 在實驗中展現了哪些關鍵結果？**
A：大量實驗顯示 UltraViT 在高效 LVLM 編碼任務上達到最先進水準，顯著優於以編碼器為主的基線方法如 FastVLM。在實際邊緣裝置上，UltraViT 的執行速度接近現有方法的 1.7 倍，同時維持甚至更進一步提升多模態推理表現。這些結果證明了以真實裝置端延遲為導向的架構設計，結合量身打造的預訓練策略，能夠在速度與準確度之間取得優異平衡。

**Q8：有哪些消融或比較證據支持 UltraViT 的設計選擇？**
A：作者指出，相較於標準對比式預訓練與自監督學習，UltraViT 的兩階段生成式預訓練更能有效學習高層次語義接地能力，而這正是 LVLM 訓練所需要的。此外，透過真實裝置端延遲來指導異質空間混合器的選擇，也顯示出在相同延遲預算下能達到更好的準確度。這些比較強調了「編碼器架構」與「預訓練目標」必須協同設計，而非單獨最佳化。

**Q9：為什麼真實裝置端延遲測量對 UltraViT 如此重要？**
A：理論上的浮點運算量（FLOPs）或參數量並不能完全反映模型在 NPU 或行動裝置上的實際執行速度，因為記憶體存取、運算元支援與平行度都會影響延遲。UltraViT 直接以真實邊緣裝置上測得的延遲作為設計依據，並針對 NPU 執行特性調整底層運算。這種做法確保了所報告的速度提升與效率增益能夠在實際部署中兌現，而不只是紙面上的理論值。

**Q10：UltraViT 適合哪些實際應用場景？**
A：UltraViT 特別適合需要即時視覺理解且運算資源受限的場景，例如行動智慧助理、擴增實境與虛擬實境裝置、無人機或自駕系統的邊緣感知模組。由於它能處理高解析度影像並顯著降低裝置端延遲，因此也適合需要快速反應的相機應用與互動式多模態對話系統。這些應用都能受益於無需依賴雲端、即可在本地完成視覺語言推理的能力。

**Q11：在產品化過程中，整合 UltraViT 時需要考量哪些因素？**
A：首先必須確認目標裝置的 NPU 支援與延遲特性，因為 UltraViT 的設計是針對特定硬體執行環境進行最佳化。其次，由於 UltraViT 本身已設計為精簡高效，產品端可以省去額外的事後視覺標記壓縮器，簡化部署流程。最後，預訓練資料與下游生成式多模態任務的對齊程度也會影響最終表現，因此需要根據應用場景調整兩階段預訓練的資料配比與語言模型容量。

**Q12：UltraViT 可能對高效 LVLM 領域帶來什麼影響？**
A：UltraViT 將研究焦點從單純的視覺標記縮減或語言模型縮小，轉移到視覺編碼器本身的架構與裝置端延遲協同設計。它證明了從頭為 LVLM 設計專用編碼器，能夠在速度與語義能力上同時超越沿用傳統分類導向編碼器的方法。這可能促使未來更多研究針對不同邊緣硬體，開發專屬的多模態視覺編碼器。

**Q13：UltraViT 可能存在哪些限制？**
A：雖然文中未明確列出所有限制，但從方法設計可推知，其異質空間混合器的選擇可能高度依賴目標裝置的延遲特性，換到不同硬體平台可能需要重新評估。此外，兩階段預訓練涉及高解析度教師模型與多個凍結 LLM，訓練流程與資源需求較為複雜。最後，為了追求裝置端延遲最佳化，UltraViT 在極端精細或需要超大容量的視覺任務上，可能仍與最大型的編碼器存在表現差距。

**Q14：UltraViT 在哪些情況下可能表現不佳？**
A：當輸入影像解析度極高或輸入為長影片序列時，即使編碼器已經過最佳化，整體計算量仍可能超出邊緣裝置負荷。此外，若下游任務需要非常細緻的像素級理解，而編碼器為了延遲考量過度壓縮空間表徵，則可能遺失關鍵細節。還有，若部署領域與預訓練資料分布差異過大，也可能出現語義接地不準確的情況。

**Q15：未來可以朝哪些方向延伸 UltraViT 的研究？**
A：未來可以將異質空間混合器的設計擴展到影片編碼器，加入時間維度的混合器以支援影片理解任務。也可以發展自動化的硬體感知搜尋方法，針對不同 NPU 平台自動決定最佳的混合器配置與模型縮放策略。此外，結合 UltraViT 與更進一步的視覺標記壓縮技術或更小的語言模型，並探索更大規模的容量混合 LLM 預訓練，也是值得深入的方向。

## 實務應用指南

### 適用場景

1. **行動裝置即時視覺問答**：在手機或平板相機中，使用者拍攝高解析度影像後立即進行「這是什麼？」、「怎麼修？」等問答互動。UltraViT 的裝置端延遲最佳化設計可顯著縮短視覺特徵提取時間，讓整體回應更接近即時。

2. **邊緣端文件理解與 OCR 輔助**：處理發票、合約、表格等高解析度文件影像時，傳統 SigLIP-400M 等重型編碼器會佔據近半推論時間。UltraViT 可在不犧牲密集語義理解的前提下，於邊緣裝置上加速文件解析與結構化資訊抽取。

3. **車載艙內視覺感知與駕駛輔助**：在運算資源有限的車載系統中，需要低延遲理解車內乘員動作、手勢或環境狀態。金字塔式異質架構有助於在不同解析度階段有效提取局部與全局特徵。

4. **AR 眼鏡與穿戴式裝置的視覺導引**：這類裝置對功耗與延遲極度敏感，且常需處理連續影像或影片串流。UltraViT 的精簡設計可減少 NPU 負擔，延長電池續航並降低暈眩感。

5. **物聯網攝影機的端側事件理解**：在智慧家居、零售或工廠場景中，攝影機需在本地判讀事件（如異常行為、貨架狀態），避免將原始影像上傳雲端。UltraViT 可作為端側 LVLM 的視覺前端，兼顧隱私與反應速度。

### 實作前置條件

**資料需求**：
- 大規模高解析度影像資料集，用於第一階段密集蒸餾預訓練。
- 具備影像–文字配對的多模態資料，用於第二階段生成式監督對齊。
- 強健教師模型（如高解析度 CLIP 或 SigLIP）所產出的密集特徵圖，作為蒸餾目標。
- 目標邊緣裝置上的真實延遲測量資料，用以指導異質空間混合器的選擇。

**運算需求**：
- 具備 NPU/GPU 的叢集，用於執行兩階段預訓練與知識蒸餾。
- 目標邊緣裝置（如智慧型手機、開發板）供延遲剖析與部署驗證。
- 足夠儲存空間存放教師模型特徵與容量混合凍結 LLM。

**技能需求**：
- 熟悉 Vision Transformer、金字塔架構與各類空間混合器（稀疏注意力、深度可分卷積等）。
- 具備知識蒸餾與大規模預訓練實作經驗。
- 了解裝置端部署流程，如量化（INT8/FP16）、編譯（ONNX、Core ML、QNN、TensorRT Lite）與記憶體最佳化。
- 能夠操作與微調凍結 LLM，並理解生成式多模態對齊機制。

### 實作步驟建議

1. **定義延遲目標與目標裝置**：先選定部署裝置（如特定手機 NPU），並設定可接受的端到端延遲上限。所有架構決策應以真實裝置端延遲為依歸，而非僅參考 FLOPs 或參數量。

2. **建立異質空間混合器搜尋空間**：根據網路不同階段（高解析度早期 vs. 低解析度後期）設計候選混合器，例如早期採用深度可分卷積捕捉局部特徵，後期採用稀疏注意力或單頭部分注意力建模全局關係。

3. **以真實延遲進行巨區塊層級選擇**：在目標裝置上測量各混合器組合的延遲，並結合準確度指標，選出符合延遲–準確度帕雷托前沿的異質區塊配置。

4. **執行第一階段密集蒸餾預訓練**：使用高解析度教師模型對 UltraViT 進行密集特徵蒸餾，培養豐富的空間表徵能力，彌補對比式預訓練過於粗糙的問題。

5. **執行第二階段生成式監督對齊**：將 UltraViT 接上凍結的容量混合 LLM，透過直接生成式目標進行監督，使編碼器產出適合後續 LVLM 訓練的高層次語義特徵。

6. **裝置端量化與編譯**：針對目標 NPU 進行量化與運算子融合，驗證異質混合器在裝置上的執行效率，必要時替換為硬體支援度更高的等效運算。

7. **整合至完整 LVLM 管線並評估**：將 UltraViT 與輕量語言模型（如 Qwen2.5 1.5B）組合，在視覺問答、文件理解等任務上進行端到端評估，確認延遲與準確度均達標。

### 潛在風險與注意事項

- **異質運算子的硬體支援差異**：不同 NPU 對稀疏注意力、深度可分卷積等運算子的支援與最佳化程度不一，可能導致理論延遲與實測延遲落差。建議在設計初期即於目標裝置上進行運算子級延遲剖析。

- **兩階段預訓練成本高昂**：密集蒸餾與生成式監督都需要大量運算資源。若資源有限，可考慮先在小規模資料上驗證配置，再擴大到完整預訓練。

- **解析度變化對延遲的影響**：高解析度影像會顯著增加早期階段計算量。需針對目標輸入解析度進行延遲測試，避免在實際使用解析度下延遲超標。

- **教師模型與目標 LLM 的語義落差**：第一階段教師模型產生的特徵未必直接適配第二階段的 LLM。應監控第二階段生成損失，必要時調整蒸餾目標或增加對齊資料。

- **缺乏事後 token 壓縮的權衡**：雖然 UltraViT 省去額外壓縮模組，但若輸出視覺標記數量仍多，後續 LLM 的上下文處理成本會上升。需綜合評估編碼器與語言模型的整體延遲佔比。

### 與其他技術的整合建議

- **搭配輕量語言模型**：UltraViT 特別適合與 0.5B 至 1.5B 等級的邊緣友好型 LLM（如 Qwen2.5、Phi 系列）搭配，讓視覺編碼器不再成為整體延遲瓶頸。

- **可選結合視覺標記剪枝**：雖然 UltraViT 設計上不需要事後壓縮，但在極端延遲敏感場景中，仍可結合輕量化的 token 剪枝或稀疏化技術作為第二層最佳化。

- **利用神經網路架構搜尋（NAS）**：可將異質空間混合器的選擇納入 NAS 流程，以真實裝置延遲作為搜尋目標之一，自動化探索最佳配置。

- **整合端側推論框架**：建議與 TensorRT Lite、Core ML、Qualcomm QNN 或 ONNX Runtime 等框架整合，並善用其運算子融合與記憶體管理功能，進一步降低裝置端延遲。

- **結合持續學習與領域適應**：針對特定應用領域（如醫療影像、工業檢測），可在第二階段後加入少量領域資料進行微調，提升語義接地能力。

### 給不同背景讀者的閱讀建議

**初學者**：你可以把 UltraViT 想像成專門為手機、AR 眼鏡等裝置設計的「快速眼睛」。它不像傳統視覺編碼器那樣用同一種方式處理整張圖，而是根據圖片不同區域的特性靈活選擇最省時的計算方式，並透過兩階段預訓練學會既能看懂細節、又能理解語義的表徵。

**AI 工程師**：本文最值得關注的是以真實裝置端延遲驅動的異質空間混合器設計，以及「密集蒸餾 → 生成式監督」的兩階段預訓練流程。實作時應特別注意不同混合器在目標 NPU 上的實際執行效率，並確保第二階段凍結 LLM 的容量混合策略不會引入訓練不穩定。

**研究人員**：這篇工作挑戰了「對比式預訓練適用於所有視覺編碼器」的預設，並指出其訊號對生成式 LVLM 過於粗糙。研究貢獻在於將編碼器設計從 ImageNet 分類導向轉向 LVLM 密集理解導向，同時以裝置延遲作為第一級設計約束，值得進一步探討異質架構的理論基礎與可擴展性。

**產品經理**：UltraViT 的核心價值在於讓高解析度影像理解能在邊緣裝置上接近即時運行，並減少對雲端運算的依賴。評估導入時，應優先確認目標裝置上的實際加速幅度、與現有語言模型的整合成本，以及是否能在你的應用場景中維持足夠的任務準確度。
