## ⚡ TL;DR

現有多模態代理搜尋基準將視覺證據視為答案端點，而非引導後續搜尋的樞紐。
作者提出InterLV-Search三層級基準與InterLV-Agent評測系統。

## 摘要翻譯

現有的多模態代理搜尋（Multimodal Agentic Search）基準測試評估多模態搜尋（Multimodal Search）與視覺瀏覽（Visual Browsing），但視覺證據（Visual Evidence）僅限於輸入內容，或被視為答案端點（Answer Endpoint），而非交錯式搜尋軌跡（Search Trajectory）的一部分。我們提出 InterLV-Search，一個用於交錯式語言-視覺代理搜尋（Interleaved Language-Vision Agentic Search）的基準測試，其中文本證據（Textual Evidence）與視覺證據被反覆作為後續搜尋的條件。該基準測試包含 2,061 個樣本，涵蓋三個層級：主動式視覺證據搜尋（Active Visual Evidence Seeking）、受控離線交錯式多模態搜尋（Controlled Offline Interleaved Multimodal Search），以及開放網路交錯式多模態搜尋（Open-web Interleaved Multimodal Search）。除了現有基準測試外，它還包含多模態多分支樣本（Multimodal Multi-branch Samples），涉及多個實體間的比較。我們以自動化流程（Automated Pipelines）建構 Level 1 與 Level 2，Level 3 則採用機器主導、人類監督（Machine-led, Human-supervised）的開放網路流程（Open-web Pipeline）。我們進一步提供 InterLV-Agent，用於標準化工具使用（Standardized Tool Use）、軌跡記錄（Trajectory Logging）與評估（Evaluation）。針對專有模型（Proprietary Models）與開源模型（Open-source Models）多模態代理（Multimodal Agents）的實驗顯示，現有系統距離解決交錯式多模態搜尋仍有相當大的差距，最佳模型的整體準確率（Overall Accuracy）低於 50%，凸顯了視覺證據搜尋、搜尋控制（Search Control）與多模態證據整合（Multimodal Evidence Integration）方面的挑戰。我們於 https://github.com/hbhalpha/InterLV-Search-Bench 釋出基準測試資料與評估程式碼。

### 核心貢獻（3～5點）
- 提出 InterLV-Search 基準測試，首次將視覺證據納入交錯式搜尋軌跡，使文本與視覺證據能反覆作為後續搜尋的條件，突破現有基準將視覺證據僅視為輸入或答案端點的限制。
- 建構涵蓋三個層級、總計 2,061 個樣本的多層次評測體系，並獨創性地納入「多模態多分支樣本」，要求模型在證據搜尋過程中進行多實體比較。
- 提供配套的 InterLV-Agent 系統，支援標準化工具使用、軌跡記錄與評估，促進不同多模態代理之間的可比較性與可重現性。
- 透過對專有與開源多模態代理的系統性實驗，揭示當前模型在交錯式多模態搜尋任務上的關鍵瓶頸：視覺證據搜尋、搜尋控制與多模態證據整合能力均亟待提升。

### 適合對象
從事多模態大型語言模型（MLLMs）、AI 代理（Agent）系統、資訊檢索（Information Retrieval）與深度研究（Deep Research）的研究者與工程師；尤其適合關注多模態代理搜尋、視覺問答（VQA）、工具使用（Tool Use）與自動化評測（Evaluation）框架開發的學術界與產業界人士。

## 深度分析

#### 方法論解析

InterLV-Search 的核心方法論圍繞「交錯式多模態代理搜尋」(Interleaved Multimodal Agentic Search) 這一新任務範式展開，其設計理念突破了現有基準測試的兩個關鍵限制。

**任務形式化與核心概念**

論文將「交錯式多模態搜尋」定義為：視覺證據不僅作為最終答案的來源，更作為**搜尋樞紐 (Search Pivot)**，引導後續的檢索動作。這與傳統的「端點導向視覺搜尋」(Endpoint-Oriented Visual Search) 形成對比——後者僅將視覺證據視為回答局部視覺問題的終點。具體而言，該任務要求**遞迴式視覺-文本交錯 (Recurrent Vision-Text Interleaving)**：在合併連續同模態步驟後，每條軌跡必須包含多個視覺片段，且片段之間穿插文本搜尋或推理，後續檢索必須以先前證據為條件。

**三層遞進式基準設計**

Level 1（主動式視覺證據搜尋）：評估從文本資訊需求出發，主動獲取視覺證據的原始能力。範例問題如「圖中所示海盜船所屬的虛擬實境遊戲名稱及其船舶物理模擬的主要引擎為何？」，需要先進行反向圖片搜尋 (Reverse Image Search) 識別遊戲，再進行文本搜尋獲取引擎資訊。

Level 2（受控離線交錯式多模態搜尋）：在受控環境中測試多跳交錯證據搜尋，避免真實環境中的排名不穩定、頁面變化、非唯一證據來源等混淆因素。範例涉及從電影海報出發，經過多個搜尋跳躍，最終識別城市地標的屋頂顏色。

Level 3（開放網路交錯式多模態搜尋）：在真實開放網路環境中評估相同機制，代理需面對嘈雜、動態的網頁、圖片與搜尋結果。此層級引入了**多模態多分支樣本 (Multimodal Multi-branch Samples)**，要求在證據搜尋過程中對多個實體進行比較。

**建構流程**

Level 1 與 Level 2 採用自動化流程 (Automated Pipelines) 建構，Level 3 則採用機器主導、人類監督 (Machine-led, Human-supervised) 的開放網路流程。這種分層建構策略兼顧了規模化效率與真實環境的複雜度。

**InterLV-Agent 系統**

論文同時提出 InterLV-Agent，提供標準化工具使用、軌跡記錄 (Trajectory Logging) 與評估機制，確保不同模型在統一介面下進行公平比較。

#### 實驗數據解讀

**整體表現**

實驗結果揭示了當前多模態代理在交錯式多模態搜尋任務上的嚴重不足：即使是表現最佳的模型，整體準確率 (Overall Accuracy) 仍低於 50%。這一結果具有重要意義，表明現有系統在視覺證據搜尋、搜尋控制 (Search Control) 與多模態證據整合 (Multimodal Evidence Integration) 三個維度上都面臨重大挑戰。

**層級間的難度梯度**

從 Level 1 到 Level 3，難度遞增反映了真實應用場景的複雜度：
- Level 1 測試基礎的視覺證據獲取能力
- Level 2 在受控環境中測試多跳推理與證據整合
- Level 3 引入開放網路的噪聲與不確定性，並加入多分支比較任務

**專有模型與開源模型的差距**

實驗涵蓋了專有模型 (Proprietary Models) 與開源模型 (Open-source Models) 兩類，雖然具體數字未在提供的文本中完整列出，但「最佳模型低於 50%」的結論暗示即使是 GPT-4V、Claude 等頂級專有模型也難以勝任此任務，凸顯了該領域的巨大改進空間。

**失敗模式分析**

從圖 1 的範例可推斷，主要失敗模式包括：
1. 無法將視覺證據轉化為有效的後續搜尋查詢

3. 在開放網路環境中受噪聲資訊干擾

**關鍵改進**

相較於 VisBrowse 與 BrowseComp-V 等近期視覺瀏覽基準，InterLV-Search 的三大突破在於：
1. **視覺證據的角色升級**：從「端點」擴展為「樞紐+端點」，承認視覺證據在搜尋軌跡中的雙重功能
2. **遞迴交錯機制**：首次將「遞迴視覺-文本交錯」作為必要條件納入評估
3. **多分支比較能力**：填補了現有基準在多實體比較任務上的空白

**局限性**

儘管貢獻顯著，該基準仍存在以下局限：
- Level 3 的開放網路環境存在時間敏感性問題，網頁內容可能隨時間變化
- 自動化建構流程可能引入系統性偏差
- 2,061 個樣本相較於某些大規模基準（如 FVQA-Test 的 1,800 個）規模相近，但多模態多分支樣本的比例與分佈需進一步驗證

#### 可重現性評估

**開源資源**

論文明確聲明釋出基準數據與評估程式碼，存放於 GitHub 倉庫（https://github.com/hbhalpha/InterLV-Search-Bench），這為可重現性提供了基礎保障。

**可重現性優勢**

1. **標準化評估框架**：InterLV-Agent 提供統一的工具介面與軌跡記錄機制，降低了不同實驗室間的實作差異
2. **三層級設計**：從受控到開放環境的漸進式評估允許研究者在不同條件下驗證結果
3. **明確的建構流程**：自動化流程（Level 1、2）與半自動化流程（Level 3）的描述為數據重建提供了指引

**潛在可重現性挑戰**

1. **開放網路環境的非確定性**：Level 3 的評估結果可能因網頁內容變化而波動，需要明確記錄評估時間點
2. **工具版本依賴**：反向圖片搜尋、網頁瀏覽等工具的 API 變更可能影響結果
3. **評估細節**：雖然提供了評估程式碼，但具體的評估指標計算細節（如部分正確的處理方式）需在程式碼中仔細審查

**模型權重**

論文未明確說明是否提供訓練好的模型權重，但作為基準測試論文，主要貢獻在於評估框架而非模型本身，因此這不構成重大缺陷。

#### 未來研究方向

**模型能力提升方向**

1. **視覺-文本交錯推理架構**：開發原生支援遞迴交錯推理的模型架構，而非簡單地將視覺與文本模態拼接
2. **搜尋樞紐識別能力**：強化模型從視覺證據中提取搜尋目標的能力，包括識別標誌、銘文、人物、空間關係等細粒度線索 (Fine-grained Cues)
3. **多分支搜尋策略**：研究在多實體比較場景下的高效搜尋策略，避免指數級的搜尋空間爆炸

**基準擴展方向**

1. **時序敏感評估**：開發能夠處理網頁內容隨時間變化的評估機制，例如使用網頁存檔或定期更新基準
2. **更多模態整合**：將音訊、影片等模態納入交錯式搜尋框架
3. **領域專項基準**：針對醫療、法律、工程等專業領域建構垂直領域的交錯式多模態搜尋基準

**應用探索方向**

1. **深度研究 (Deep Research) 整合**：將交錯式多模態搜尋能力整合到深度研究系統中，支援需要視覺證據的研究任務
2. **人機協作搜尋**：探索人類與 AI 代理在交錯式搜尋中的協作模式，人類提供視覺判斷，AI 執行搜尋
3. **教育與訓練應用**：利用該基準訓練下一代多模態代理，使其具備類似人類的視覺引導資訊搜尋能力

**理論研究方向**

1. **搜尋軌跡的資訊理論分析**：量化視覺證據作為搜尋樞紐時的資訊增益
2. **交錯式搜尋的計算複雜度**：分析在多分支、多跳場景下的搜尋空間特性
3. **視覺-文本對齊的因果分析**：研究視覺觀察如何因果性地決定後續搜尋動作

## 論文問答

**Q1：InterLV-Search 想要解決的核心問題是什麼？**
A：InterLV-Search 旨在解決現有多模態代理搜尋基準測試中視覺證據角色受限的問題。在傳統設定中，視覺資訊僅作為輸入或最終答案的端點，無法在搜尋過程中動態引導後續檢索動作。該基準測試主張視覺證據應扮演「搜尋樞紐」（Search Pivot）的角色，能根據當前觀察決定下一步該搜尋什麼、查詢什麼實體或切換到哪個工具。這種交錯式多模態代理搜尋（Interleaved Multimodal Agentic Search）更貼近真實世界中資訊尋求的動態特性。

**Q2：為什麼現有的多模態代理搜尋基準測試不足以評估真實能力？**
A：現有基準測試（如 MMSearch、VisBrowse、BrowseComp-V 等）大多將視覺證據限制在使用者輸入端，或僅作為最終答案推導的端點，未能評估視覺線索如何驅動後續搜尋決策。這類端點導向視覺搜尋（Endpoint-Oriented Visual Search）的設計忽略了視覺觀察中常見的細粒度線索（Fine-grained Cues），例如標誌、銘文、人物或空間關係，這些線索在真實情境中往往是決定下一步搜尋方向的關鍵。因此，現有基準無法衡量代理在異質來源間進行動態證據整合的能力。

**Q3：為何交錯式多模態搜尋在現實應用中如此重要？**
A：在開放世界（Open-world）的問答與深度研究任務中，所需證據往往超出輸入內容，必須透過外部資訊存取取得。實際資訊尋求過程中，使用者會反覆在文字與視覺模態間切換，例如先以圖片辨識實體，再以文字搜尋補充細節，或反之。這種反覆的視覺-文字交錯（Recurrent V–T Interleaving）反映了人類解決複雜問題的自然方式，也是深度研究（Deep Research）等高階任務的核心需求。

**Q4：InterLV-Search 的三層級架構是如何設計的？**
A：InterLV-Search 將交錯式多模態搜尋分解為三個漸進式難度的層級。Level 1 為主動式視覺證據搜尋（Active Visual Evidence Seeking），評估代理從文字需求出發、主動尋找視覺證據的基本能力。Level 2 為受控離線交錯式多模態搜尋（Controlled Offline Interleaved Multimodal Search），在受控環境中測試多跳交錯證據搜尋，避免真實網頁的排名不穩定與頁面變動等混淆因素。Level 3 則為開放網路交錯式多模態搜尋（Open-web Interleaved Multimodal Search），在真實且嘈雜的網路環境中評估同一機制。

**Q5：將視覺證據視為「搜尋樞紐」而非「答案端點」的關鍵創新是什麼？**
A：此一創新重新定義了視覺證據在搜尋軌跡（Search Trajectory）中的功能角色。傳統基準將新取得的視覺證據視為局部視覺問題（Local Visual Question）的終點，而 InterLV-Search 要求視覺證據能動態決定後續檢索動作，包括下一個查詢、實體、網頁或工具調用。這種搜尋控制性（Search-controlling）的設計使代理必須具備真正的多模態證據整合（Multimodal Evidence Integration）能力，而非僅是視覺問答（VQA）的延伸。

**Q6：InterLV-Search 的樣本是如何建構的？**
A：Level 1 與 Level 2 採用自動化流程（Automated Pipelines）建構，確保規模化與一致性；Level 3 則採用機器主導、人類監督（Machine-led, Human-supervised）的開放網路流程（Open-web Pipeline），以反映真實網路環境的複雜度。整個基準共包含 2,061 個範例，並特別納入多模態多分支樣本（Multimodal Multi-branch Samples），要求代理在證據搜尋過程中對多個實體進行比較。這種混合建構策略兼顧了規模、可控性與真實性。

**Q7：實驗中使用了哪些模型與評估方式？**
A：研究團隊在專有模型（Proprietary Models）與開源模型（Open-source Models）兩類多模態代理（Multimodal Agents）上進行評估，並透過 InterLV-Agent 提供標準化工具使用（Standardized Tool Use）、軌跡記錄（Trajectory Logging）與評估機制。這種統一介面使不同模型能在公平條件下比較其在視覺證據搜尋、搜尋控制與多模態證據整合等面向的表現。

**Q8：實驗的主要發現為何？**
A：實驗結果顯示，即使是表現最佳的多模態代理，整體準確率（Overall Accuracy）仍低於 50%，凸顯當前系統距離真正解決交錯式多模態搜尋仍有相當距離。這項結果揭示了現有模型在視覺證據搜尋、搜尋控制（Search Control）以及多模態證據整合三個面向均存在明顯不足。換言之，無論是專有或開源模型，都尚未具備成熟的交錯式推理能力。

**Q9：實驗結果對模型能力分析提供了哪些洞察？**
A：透過分層級評估，可看出模型在 Level 1 的主動視覺證據搜尋上表現相對較佳，但在 Level 2 與 Level 3 的多跳交錯搜尋中表現顯著下滑，顯示模型難以維持長程的跨模態推理。此外，多模態多分支樣本對所有模型都構成額外挑戰，反映出在多實體比較與分支決策上的弱勢。這些洞察共同指向未來模型需要在長程規劃與跨模態整合上進行強化。

**Q10：哪些實際情境最能受益於交錯式多模態搜尋？**
A：深度研究（Deep Research）是首要應用場景，使用者常需從一張圖片出發，逐步追溯到相關人物、地點或事件。另一典型情境為產品溯源與品牌調查，例如從商品圖片辨識品牌，再透過文字搜尋取得代言人、產品線等延伸資訊。此外，在學術研究、新聞查證與文化資產探索等領域，使用者也經常需要在視覺與文字證據間反覆切換以驗證資訊。

**Q11：從產品角度，InterLV-Search 帶來哪些設計啟示？**
A：產品設計者應意識到，視覺輸入不僅是查詢的起點，更可能在搜尋過程中反覆出現並引導下一步行動。這意味著介面設計需支援視覺證據的持續呈現與再利用，而非僅作為一次性輸入。此外，標準化工具使用（Standardized Tool Use）與軌跡記錄（Trajectory Logging）對除錯與可解釋性至關重要，能幫助開發者診斷代理在何處偏離正確的搜尋路徑。

**Q12：這項研究對多模態 AI 領域的整體影響為何？**
A：InterLV-Search 為多模態代理搜尋建立了新的評估標準，將研究焦點從「視覺問答」推向「視覺驅動的代理行為」。透過強調反覆視覺-文字交錯（Recurrent V–T Interleaving）與多分支決策，該基準鼓勵學界發展更具動態性與長程推理能力的模型。同時，公開的評估程式碼與資料有助於推動可重現性與跨團隊比較，加速整體領域的進展。

**Q13：InterLV-Search 存在哪些已承認的限制？**
A：Level 3 的開放網路設定本質上動態且不穩定，網頁內容可能隨時間變化，導致評估結果難以完全重現。此外，雖然樣本數達 2,061 個，但相較於真實使用情境的多元性，覆蓋範圍仍有限。Level 1 與 Level 2 的自動化建構雖具規模優勢，但可能在語意豐富度上不及完全人工標註的資料集。

**Q14：現有模型在哪些情境下特別容易失敗？**
A：模型在需要從視覺線索推斷下一步搜尋目標時表現不佳，例如從電影海報辨識演員後再追溯其出生城市的長鏈任務。在多分支比較情境中，模型也常難以正確篩選與保留符合條件的實體，例如在多部電影中比較並保留片長最長者。此外，面對開放網路的嘈雜網頁與不穩定排名，模型的搜尋控制能力明顯下降，顯示其在真實環境中的魯棒性仍待加強。

**Q15：這項工作為未來研究指出了哪些方向？**
A：未來可朝強化長程交錯推理、改進多分支決策機制，以及提升開放網路環境下的魯棒性等方向發展。具體而言，研究者可探索更有效的視覺-文字融合架構，使模型能在搜尋軌跡中靈活切換模態並保留關鍵證據。此外，結合人類監督的持續學習、主動詢問機制，以及更細粒度的評估指標，都將有助於推動交錯式多模態代理搜尋走向實用化。

## 實務應用指南

### 適用場景

**1. 電商視覺化商品研究助理**
消費者或市場分析師常需要從一張商品圖片出發，找出品牌、型號、上市時程、代言人活動等資訊。InterLV-Search 的 Level 1「主動式視覺證據搜尋」正是針對此情境：先以反向圖片搜尋定位商品，再以文本搜尋取得細節，最後再以視覺證據（如代言人海報）確認答案。適用於比價網站、選品工具、品牌監控平台。

**2. 調查報導與事實查核（OSINT）**
記者或查核組織常需從一張模糊的街景、文件截圖或人物照片出發，逐步追溯到地點、人物、事件脈絡。Level 3「開放網路交錯式多模態搜尋」模擬此流程：視覺證據作為搜尋樞紐（search pivot），決定下一個搜尋目標，符合真實調查中「看圖找線索、線索帶出新線索」的工作模式。

**3. 旅遊與文化資產研究**
從一張建築照片辨識城市、年代、風格，再串接該城市的歷史事件、開放時間、票價等資訊。Level 2「受控離線交錯式多模態搜尋」適合用於博物館、觀光局、導覽 App 的離線知識庫建構，避免開放網路的雜訊干擾。

**4. 醫療影像輔助決策支援**
醫師從影像（如 X 光、病理切片）出發，需查找相似案例、文獻、藥物交互作用。視覺證據可作為搜尋樞紐，引導至 PubMed 文本搜尋；多分支樣本（multi-branch）則對應鑑別診斷中「比較多個可能病因」的情境。

**5. 企業智財與品牌侵權偵測**
法務團隊從一張疑似抄襲的產品圖出發，需比對多個品牌、多個產品線的視覺與文本特徵。InterLV-Search 的多分支比較機制（比較多個 entity 的執行時間、屬性）正好對應此類「多候選、多屬性」的智財分析流程。

---

### 實作前置條件

**資料需求**
- **視覺資料庫**：至少數萬張涵蓋商品、地標、人物、文件的標註圖片（可用 LAION、CC3M 等開源資料集起步）
- **文本語料**：Wikipedia、產品評論、新聞語料，或領域專屬語料（如醫療、法律）
- **網頁快照**：Level 2 需要受控環境，建議預先爬取並凍結目標網頁；Level 3 需要即時網頁存取能力
- **標註資料**：用於訓練或評估的「問題—多模態搜尋軌跡—答案」三元組，可參考 InterLV-Search 的 2,061 筆範例格式

**運算資源**
- **推論端**：單張 A100/H100 等級 GPU 即可運行 7B–13B 等級的開源 MLLM；70B 等級模型建議多卡並行
- **訓練端**：若要微調自有模型，建議配備 8 張以上 A100，並使用 DeepSpeed ZeRO-3 或 FSDP
- **儲存**：網頁快照與圖片資料庫合計建議預留 1–10 TB（視領域規模而定）

**技能門檻**
- 熟悉 MLLM（如 GPT-4o、Qwen-VL、LLaVA）的 prompt 設計與 tool-use 介面
- 具備網頁爬蟲、HTML 解析、Playwright/Selenium 等瀏覽器自動化經驗
- 了解 agent 框架（LangChain、AutoGen、CrewAI）的 trajectory 記錄與重播機制
- 能撰寫評估腳本，處理多模態答案的模糊比對（如顏色、材質的同義詞對應）

---

### 實作步驟建議

**Step 1：釐清任務層級**
先決定產品要對應 Level 1、2 或 3。Level 1 門檻最低，適合 MVP；Level 2 適合內部知識庫；Level 3 適合開放式問答產品。

**Step 2：建構工具層**
依據 InterLV-Agent 的設計，標準化以下工具：
- 反向圖片搜尋（接入 Google Lens API 或自建 CLIP-based 檢索）
- 文本搜尋（接入既有搜尋引擎或 Elasticsearch）
- 圖片搜尋（基於 CLIP/SigLIP 的向量檢索）
- VQA（呼叫 MLLM 對局部影像提問）
- 網頁瀏覽（Playwright + 截圖 + OCR）

**Step 3：設計 agent 軌跡格式**
參考論文中「合併連續同模態步驟後，每條軌跡包含多個視覺段落與文本搜尋/推理」的格式，定義 JSON schema 記錄每一步的模態、工具、輸入、輸出、耗時。

**Step 4：建立評估管線**
使用論文的評估程式碼為基準，擴充領域專屬的答案比對規則（例如「紅磚」與「red brick」視為等價）。建議先在 Level 1 驗證，再逐步推進。

**Step 5：迭代 prompt 與工具組合**
從論文的失敗案例分析（最佳模型 < 50% 整體準確率）可知，視覺證據搜尋、搜尋控制、跨模態整合是三大瓶頸。建議針對這三項設計 A/B 測試。

**Step 6：部署與監控**
上線後持續記錄 trajectory，建立人類回饋機制（RLHF 或 RLAIF），並監控 API 成本、延遲、錯誤率。

### 潛在風險與注意事項

**1. 開放網路的不穩定性**
Level 3 面臨網頁變動、排名波動、非唯一證據來源等干擾。**緩解方式**：對關鍵網頁建立快照快取；設計 fallback 機制（搜尋失敗時切換工具）；在評估中加入「答案唯一性」檢查。

**2. 視覺幻覺與錯誤傳播**
MLLM 可能誤判圖片內容，導致後續搜尋方向錯誤。**緩解方式**：在關鍵節點加入人類審核（human-in-the-loop）；對視覺輸出做信心分數過濾；設計「回退」動作讓 agent 可回到前一步重新搜尋。

**3. 成本與延遲**
多模態搜尋軌跡通常需要 5–15 步，每步呼叫 MLLM 與搜尋 API，成本與延遲可能超出使用者預期。**緩解方式**：使用較小的開源模型處理簡單步驟；對常見查詢建立軌跡快取；採用 speculative execution 預測下一步。

**4. 隱私與法律風險**
爬取網頁、使用他人圖片可能涉及著作權與個資法。**緩解方式**：優先使用 CC 授權或自有資料；遵守 robots.txt；對人物影像做模糊化處理；保留資料來源審計紀錄。

**5. 多分支比較的複雜度**
論文指出多分支樣本涉及多個 entity 的比較，當前模型表現尤弱。**緩解方式**：將多分支任務拆解為多輪單一比較；設計專屬的「比較」工具而非依賴通用推理。

**6. 評估偏差**
論文的評估可能偏向特定模型架構或 prompt 風格。**緩解方式**：建立領域專屬的測試集；邀請多位標註者交叉驗證答案；定期檢視失敗案例的分布是否反映真實使用者痛點。

### 與其他技術的整合建議

**1. 與 RAG 系統整合**
InterLV-Search 的軌跡可作為「多模態 RAG」的檢索增強層：先用 agent 搜尋取得視覺與文本證據，再餵入 RAG 生成器產出最終答案。建議將 trajectory 序列化後存入向量資料庫，作為可追溯的證據鏈。

**2. 與既有 agent 框架整合**
InterLV-Agent 的工具介面可包裝為 LangChain Tool 或 AutoGen Function，供既有 agent 呼叫。建議保留 trajectory logging 機制，以便除錯與審計。

**3. 與搜尋引擎整合**
將反向圖片搜尋、文本搜尋的結果統一抽象為「證據物件」（包含來源、模態、信心分數），讓上層應用可靈活組合。

**4. 與知識圖譜整合**
視覺證據辨識出的實體（人物、地標、商品）可對接 Wikidata、Google Knowledge Graph，補強結構化資訊；多分支比較任務特別適合用知識圖譜的屬性查詢加速。

**5. 與人類專家系統整合**
在醫療、法律等高風險領域，將 agent 的 trajectory 即時呈現給專家審核，專家可標註錯誤步驟，作為後續微調的訓練資料。

**6. 與監控與可觀測性平台整合**
將 trajectory 串流至 Langfuse、Phoenix 等可觀測性平台，追蹤每一步的延遲、成本、錯誤率，建立 SLA 儀表板。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先讀摘要與 Figure 1，理解「視覺證據作為搜尋樞紐」這個核心概念，再跳到 Level 1 的範例觀摩軌跡流程。論文中的三個層級（Level 1 主動視覺搜尋、Level 2 離線交錯、Level 3 開放網路）剛好對應三種難度，可循序體驗。

**給 AI 工程師**：重點放在 InterLV-Agent 的工具介面設計、trajectory logging 格式、評估程式碼。建議直接 clone GitHub repo，在自己的資料集上跑一遍 baseline，找出當前模型在「視覺證據搜尋」「搜尋控制」「多模態整合」三項的瓶頸，作為優化方向的切入點。

**給研究者**：論文的價值在於揭示「交錯式多模態搜尋」這個新 benchmark 方向，並指出當前模型 < 50% 的顯著性能差距。建議從 Table 1 的 benchmark 比較、Level 3 的開放網路建構流程、以及失敗案例分析切入，思考如何設計更強的視覺-文本交錯推理機制，或探索多分支比較的新方法。

**給產品經理**：InterLV-Search 揭示的「視覺證據作為搜尋樞紐」能力，正是下一代 AI 助理差異化的關鍵。建議從三個層級對應的產品場景（Level 1：商品/品牌查詢、Level 2：內部知識庫、Level 3：開放式問答）思考自家產品的切入點，並關注論文中提到的成本、延遲、錯誤率等工程化議題，避免過度樂觀估計技術成熟度。
