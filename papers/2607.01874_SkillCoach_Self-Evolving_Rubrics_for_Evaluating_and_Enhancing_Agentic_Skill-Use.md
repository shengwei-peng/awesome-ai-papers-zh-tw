# SkillCoach：用於評估與增強智能體技能運用的自我演化評分規準

## ⚡ TL;DR

技能庫重疊干擾下，最終驗證結果難以評估智能體技能運用過程品質。
提出 SkillCoach，透過自我演化評分規準評估技能選擇、遵循、組合與反思四面向。
實驗顯示演化規準提升評估品質，揭露最終準確率隱藏的失敗，並強化訓練監督訊號。

## 摘要翻譯

技能正逐漸成為大型語言模型智能體（LLM agents）可重複使用的操作層，將標準作業程序（Standard Operating Procedures, SOPs）、領域規則（domain rules）、工具工作流程（tool workflows）、腳本及驗證常式（validation routines）編碼於其中。在真實的技能儲存庫（skill repositories）中，重疊技能（overlapping skills）使得可靠的技能運用變得困難。最終驗證器的成功（final verifier success）對於評估與訓練而言過於粗糙，因為智能體可能透過嘗試錯誤（trial and error）通過驗證，卻在過程中選擇干擾技能（distractor skills）、跳過必要步驟、錯誤地組合工作流程，或遺漏最終檢查。我們提出 SkillCoach，一個用於評估與增強智能體技能運用（agentic skill-use）的自我演化評分規準（self-evolving rubrics）框架。SkillCoach 從真實展開（real rollouts）中衍生出基於技能的過程評分規準（skill-grounded process rubrics），並從四個面向評估軌跡（trajectories）：技能選擇（skill selection）、技能遵循（skill following）、技能組合（skill composition），以及基於技能的反思（skill-grounded reflection）。它將外部驗證器（verifier）保留為獨立的結果訊號（outcome signal），使過程品質（process quality）能與偶然的任務成功（accidental task success）區分開來。演化後的評分規準進一步作為過程監督（process supervision），以篩選高品質的訓練軌跡（training trajectories）。實驗顯示，演化後的評分規準顯著提升了評估品質（evaluation quality），揭露被最終準確率（final accuracy）所隱藏的失敗，並相較於僅基於結果的篩選（outcome-only filtering），為增強智能體技能運用提供了更強的監督訊號。

### 核心貢獻（3～5點）
- 提出 SkillCoach 框架，透過自我演化評分規準（Self-Evolving Rubrics）評估並增強智能體技能運用（Agentic Skill-Use）。
- 從真實展開（Real Rollouts）衍生基於技能的過程評分規準（Skill-Grounded Process Rubrics），並從技能選擇、技能遵循、技能組合與基於技能的反思四個面向細粒度評估軌跡。
- 將外部驗證器（Verifier）保留為獨立的結果訊號（Outcome Signal），使過程品質（Process Quality）能與偶然的任務成功（Accidental Task Success）區分開來。
- 以演化後的評分規準作為過程監督（Process Supervision），篩選高品質訓練軌跡（Training Trajectories）；實驗證實其顯著提升評估品質（Evaluation Quality），並揭露最終準確率（Final Accuracy）隱藏的失敗。

### 適合對象
從事大型語言模型智能體（LLM Agents）、智能體評估與對齊，以及技能庫（Skill Libraries）系統開發的研究人員與工程師；特別適合關注過程監督（Process Supervision）、自動化評估規準生成，以及需要區分過程品質與最終任務成功之進階讀者。

## 深度分析

#### 方法論解析

智能體技能運用（Agentic Skill-Use）在本研究中被重新定義為一種軌跡層級（trajectory-level）的後設能力（meta-ability），而非僅以最终任務成功（Final task success）作為判準。SkillCoach 框架將此能力解構為四個可獨立評量的維度：技能選擇（skill selection）、技能遵循（skill following）、技能組合（skill composition），以及基於技能的反思（skill-grounded reflection）。

方法論的核心在於自我演化評分規準（Self-Evolving Rubrics）的建構與校準。針對每一項任務，系統首先從黃金技能（Gold skills）中抽繹出初始的過程評分規準（Process rubrics）。接著，透過真實展開（Real rollouts）收集智能體的執行軌跡（Trajectories），並依據可觀察的軌跡證據對四個維度進行評分。此處的關鍵設計在於將外部驗證器（External verifier）或最終驗證器（Final verifier）的結果訊號（Outcome signal）與過程品質（Process quality）分離：即使軌跡最終通過驗證，只要在技能運用行為（Skill-use behavior）上存在缺陷，仍會在過程評分規準中被識別。

為了使評分規準貼近實際部署情境，SkillCoach 在兩個現實條件下運作。第一，任務設定為技能相依（skill-dependent），即智能體在缺乏相關技能時表現不佳，但提供黃金技能後能力顯著提升，這確保了評估焦點在於「如何運用技能」而非「是否具備領域知識」。第二，技能庫（Skill libraries）經過干擾技能擴增（distractor-augmented），將黃金技能與干擾技能（Distractor skills）混雜，模擬企業級技能儲存庫（Skill repositories）中因業務邏輯（Business logic）重疊而導致的選擇困難。

在演化機制上，SkillCoach 採用驗證門控的局部修補（validation-gated local patches）。具體而言，系統會比對軌跡證據與初始規準之間的落差，透過局部仲裁（local arbitration）產生修補建議，並以驗證結果作為閘門，僅採納能提升評估準確性的修訂。最終演化完成的過程評分規準具備雙重用途：其一，作為診斷工具，揭露被最終準確率（Final accuracy）掩蓋的失敗模式，例如透過嘗試錯誤（Trial and error）通過驗證、跳過技能指定的檢查（Skill-specified checks）、或錯誤地組合工作流程；其二，作為訓練監督訊號，從通過驗證器的軌跡（Verifier-passing trajectories）中篩選出高品質的正向示範（Positive demonstrations），用於監督式微調（SFT），從而避免智能體學習到脆弱的行為捷徑。

#### 實驗數據解讀

由於提供的全文脈絡主要涵蓋摘要與引言，以下針對摘要所宣稱的實驗發現進行概念性解讀與方法論意涵分析。

首先，在評估品質（Evaluation quality）方面，自我演化後的評分規準能夠顯著提升對智能體技能運用行為的解析度。傳統僅基於結果的評估（Outcome-only evaluation）將所有通過最終驗證器（Final verifier）的軌跡視為等價，但 SkillCoach 的過程評分規準可區分出「真正的技能運用」與「偶然的任務成功（Accidental task success）」。如圖一所示，軌跡 A 與軌跡 B 皆通過外部驗證，但僅有軌跡 A 正確地進行了技能選擇與技能遵循；這意味著最終準確率（Final accuracy）作為單一指標時，其天花板效應會隱藏中間步驟的錯誤組合與干擾技能的誤選。

其次，實驗指出演化後的規準能夠揭露被最終準確率隱藏的失敗。這暗示在干擾技能擴增的環境中，智能體可能透過自我探索（Self explore）與反覆嘗試錯誤（Trial and error）最終提交正確答案，但其過程中可能遺漏了驗證常式（Validation routines）、誤讀領域規則（Domain rules），或將工具工作流程（Tool workflows）以錯誤順序拼接。過程評分規準透過四個維度的細粒度評分，將這些行為轉化為可量化的診斷訊號，使研究者得以識別技能庫（Skill libraries）中哪些業務邏輯（Business logic）最容易被忽略或誤用。

最後，在訓練監督（Process supervision）的層面，實驗主張以演化規準作為篩選機制，優於僅基於結果的篩選（Outcome-only filtering）。當所有通過驗證的軌跡都被視為正向示範時，模型會學到包含錯誤技能組合（Skill composition）與不完整技能反思（Reflection）在內的雜訊。SkillCoach 利用四個維度的分數作為可解離的監督訊號（dissociable supervision signals），從中挑選出在技能選擇、遵循、組合與反思上均表現優異的軌跡。這種基於技能的過程監督（Skill-grounded process supervision）能確保訓練資料不僅「結果正確」，更「過程可複用」，從而提升智能體在面對企業內部流程（Internal processes）與標準作業程序（SOPs）時的穩健性。

#### 與現有研究的比較

在定位上，SkillCoach 與現有文獻形成鮮明對比。現有研究大致可分為兩條主軸：其一為技能基準測試（Benchmarks）與技能生命週期管理（Lifecycle management），例如 SkillsBench、SkillLearnBench 與 SkillFlow，這些工作聚焦於技能工件（Skill artifact）的生成品質、檢索（Retrieval）準確度、持續發現與遷移能力；其二為技能工件本身的精進，包括失敗驅動的修補、軌跡合成與驗證門控的最佳化。這些方向雖然提升了技能庫的內容品質，但隱含假設一旦技能被檢索或生成，智能體便能正確使用。SkillCoach 直接挑戰此假設，將研究焦點從「技能是否存在」轉移至「技能是否被正確運用」。

相較於近期從最終結果轉向軌跡層級評估的研究，以及採用評分規準（Rubrics）提供任務適應性回饋的方法，SkillCoach 的獨特貢獻在於利用技能本身的結構來定義過程監督。過往的軌跡評估雖然能捕捉行為序列，但缺乏與技能儲存庫（Skill repositories）中具體標準作業程序（SOPs）、工具工作流程（Tool workflows）與驗證檢查（Validation checks）的明確對應。SkillCoach 的過程評分規準（Process rubrics）則是技能導向的，其四個維度直接映射到企業部署中智能體使用技能庫時的關鍵失敗模式。

然而，此方法亦存在可預見的限制。首先，初始規準的生成依賴黃金技能（Gold skills），這在實務上意味著仍需人工或高品質管道提供正確的技能檔案（Skill files）作為錨點。其次，自我演化過程涉及多次真實展開（Rollouts）與局部仲裁，對於計算資源與時間成本的要求可能高於靜態評分規準。第三，目前的框架主要針對技能相依（skill-dependent）任務設計，對於高度開放、難以預先定義技能邊界的任務，其四維分解是否仍具解析力，尚待驗證。最後，在干擾技能數量極其龐大的企業級技能儲存庫中，局部修補的收斂性與可擴展性（scalability）仍需更多實證。

#### 可重現性評估

就提供的全文脈絡而言，摘要與引言並未提及原始碼、資料集或模型權重的公開釋出計畫，因此無法確認本研究在開源層面的可重現性（Reproducibility）。從方法論描述推斷，若要完整重現 SkillCoach，至少需要以下元件：包含黃金技能與干擾技能（Distractor skills）的技能庫（Skill libraries）、環境預言機（Environment Oracle）與最終驗證器（Final verifier）的實作、用於產生真實展開（Real rollouts）的基礎大型語言模型智能體（LLM agents）、以及自我演化評分規準（Self-Evolving Rubrics）的演算法細節（如局部仲裁與驗證門控的具體邏輯）。

由於本研究明確鎖定企業場景中的技能運用，技能檔案（Skill files）往往內含特定領域的業務邏輯（Business logic）與內部流程（Internal processes），這類資料通常具有專屬性與敏感性，公開釋出的可能性較低。若作者未提供去識別化（de-identified）的基準測試資料或模擬環境，外部研究者將難以驗證其在干擾技能擴增（distractor-augmented）設定下的實驗結果。此外，過程評分規準的演化涉及對大型語言模型輸出的反覆評判，若未公開提示詞模板（prompt templates）與評分介面，重現演化軌跡本身亦存在相當挑戰。建議作者未來至少釋出評分規準的結構化格式與模擬驗證器的介面規格，以提升社群的驗證能力。

#### 未來研究方向

基於 SkillCoach 的框架設計與現有侷限，以下提出幾個具潛力的後續研究方向：

第一，放寬對黃金技能（Gold skills）的依賴，發展全自動化的技能規準發現機制。當前框架需以正確技能為錨點生成初始規準，未來可探索讓智能體從大量未標記的執行軌跡（Trajectories）中自行歸納出隱含的標準作業程序（SOPs）與驗證常式（Validation routines），進而生成初始規準。

第二，將自我演化評分規準（Self-Evolving Rubrics）從離線訓練擴展至線上部署。目前的規準演化似乎基於批次化的真實展開（Rollouts），未來可研究在持續學習（continual learning）或終身學習（lifelong learning）情境下，如何隨著技能庫（Skill libraries）擴增即時更新過程評分規準（Process rubrics），並避免災難性遺忘。

第三，探索多智能體協作場景中的技能運用評估。現有框架聚焦單一智能體的軌跡，但在企業環境中，內部流程（Internal processes）常需多個智能體分別呼叫不同技能並協調工具工作流程（Tool workflows）。如何將技能選擇（skill selection）與技能組合（skill composition）擴展為跨智能體的協議驗證，將是重要延伸。

第四，結合人類回饋強化學習（RLHF）或人類在迴路（human-in-the-loop）的仲裁機制。雖然 SkillCoach 已具備局部仲裁（local arbitration），但在高風險業務邏輯（Business logic）場景中，引入領域專家對演化規準的最終把關，可進一步提升過程監督（Process supervision）的安全性與可解釋性。

第五，發展跨領域的規準遷移。研究在某一領域（如金融工具工作流程）演化出的評分規準結構，是否能遷移至另一領域（如醫療驗證檢查），從而降低新領域的冷啟動成本，並促進技能生命週期管理（Lifecycle management）的標準化。

## 論文問答

**Q1：在真實的技能庫環境中，智能體運用技能時面臨哪些核心挑戰？**
A：在真實的企業級技能庫中，技能數量不斷增長且彼此重疊，使得智能體難以穩定地選擇正確的技能、遵循其標準作業程序、正確組合多個工作流程，並執行最終驗證檢查。研究指出，智能體經常透過嘗試錯誤來通過任務，過程中可能選用了干擾技能、遺漏關鍵步驟，或在未進行技能指定檢查的情況下就提交結果。這些問題導致最終驗證器的成功訊號過於粗糙，無法真實反映智能體是否具備可複用的技能使用行為。

**Q2：為何僅依賴最終驗證器（final verifier）的結果來評估智能體技能運用是不足的？**
A：僅仰賴最終驗證器的結果會產生「偶然的任務成功」問題，因為智能體可能透過自我探索或反覆嘗試錯誤碰巧通過驗證，卻未真正依循技能檔案所規範的流程。這種結果導向的評估無法區分「穩定且可複用的技能使用行為」與「僥倖成功」，導致訓練時可能將低品質軌跡誤認為正向示範。此外，現有的基準測試與技能生命周期管理研究多聚焦於技能本身的生成、檢索或優化，隱含假設只要技能存在，智能體就能正確使用，忽略了真實部署中複雜的技能運用過程。

**Q3：為何需要將「智能體技能運用」（Agentic Skill-Use）視為軌跡層級的後設能力（meta-ability）？**
A：將技能運用視為軌跡層級的後設能力，能夠讓我們從過程品質的角度全面檢視智能體的行為，而非僅看最終結果。這種視角強調智能體必須在整個任務過程中展現出選擇、遵循、組合與反思的能力，這些都是企業場景中穩定執行業務邏輯的關鍵。透過將此後設能力與外部驗證器訊號分離，研究者與開發者才能準確診斷智能體在哪些環節未能正確使用技能，並針對性地提升其操作層的可靠性。

**Q4：SkillCoach 框架的核心運作機制是什麼？它如何從真實展開（real rollouts）中生成評分規準？**
A：SkillCoach 是一個自我演化的評分規準框架，它首先從黃金技能檔案中衍生出初始的過程評分規準，再透過觀察真實展開中的可觀察證據對軌跡進行評分。接著，框架利用驗證門控的局部修補與基於證據的判斷，逐步校準與精煉這些規準，使其更貼近實際任務需求。最終演化出的評分規準能同時作為診斷工具與訓練監督訊號，用於篩選高品質的訓練軌跡。

**Q5：相較於現有的軌跡評估或評分規準方法，SkillCoach 的關鍵創新體現在哪些方面？**
A：SkillCoach 是首個利用技能本身的結構來定義過程監督訊號的自我演化評分規準框架，它將技能運用拆解為四個可解離的維度：技能選擇、技能遵循、技能組合與基於技能的反思。不同於傳統方法僅評估最終結果或通用軌跡品質，SkillCoach 透過證據導向的判斷與局部仲裁修補，讓評分規準能隨著真實展開資料自我演化，精準對齊技能檔案所編碼的業務邏輯。更重要的是，它將外部驗證器保留為獨立的結果訊號，從而首次實現了在干擾技能庫環境中，同時進行精細診斷與高品質訓練資料篩選的雙重目標。

**Q6：SkillCoach 在設計上為何特別針對「技能相依任務」（skill-dependent tasks）與「干擾增強技能庫」（distractor-augmented libraries）？**

**Q7：實驗設計如何驗證 SkillCoach 在評估與訓練上的有效性？**
A：實驗設置於技能相依任務場景中，並在技能庫內加入干擾技能以模擬真實企業環境的複雜度，從而測試 SkillCoach 是否能準確評估智能體的過程品質。研究團隊讓智能體進行真實展開，收集包含各種成功與失敗模式的軌跡，並比較 SkillCoach 與僅基於結果的篩選方法在評估與監督上的差異。這樣的設計能夠檢驗自我演化評分規準是否能揭露被最終準確率掩蓋的技能使用失敗，並驗證其作為過程監督訊號的訓練價值。

**Q8：實驗結果顯示，演化後的評分規準在評估品質與訓練監督方面帶來哪些具體改進？**

A：SkillCoach 特別適合應用於擁有大量標準作業程序、工具工作流程與驗證常式的企業環境，例如金融稽核、供應鏈管理或客戶服務自動化等領域。在這些場景中，智能體必須從龐大且技能彼此重疊的儲存庫中，準確選擇並嚴格遵循內部業務邏輯，任何步驟遺漏或順序錯誤都可能導致嚴重後果。SkillCoach 能夠作為持續的品質監控與訓練資料篩選層，確保部署的智能體不僅任務成功，更符合組織規範的操作流程。

A：目前的方法主要聚焦於具有明確標準作業程序與驗證步驟的技能相依任務，對於需要高度創造性、無固定流程的開放式任務，其四維度評估框架可能較難直接適用。此外，SkillCoach 依賴高品質的黃金技能檔案來生成初始評分規準，若企業儲存庫中的技能文件本身品質參差不齊或缺乏結構化描述，則演化的起點將受到限制。同時，框架目前的評估維度雖涵蓋選擇、遵循、組合與反思，但對於更複雜的動態環境適應或跨領域技能遷移行為，尚未深入探討其監督粒度。

## 實務應用指南

### 適用場景

1. **企業內部流程自動化**：當技能庫包含大量重疊的標準作業程序（SOP），例如財務報銷、人資到職、IT 派工等內部流程，智能體必須正確執行技能選擇與技能遵循，而非透過嘗試錯誤偶然完成任務。SkillCoach 可診斷其是否誤用干擾技能或遺漏關鍵步驟。

2. **金融合規與風控審查**：法規與內部控制技能高度相似且彼此重疊，需要精確的技能組合與基於技能的反思，並執行技能指定的檢查（如 KYC、反洗錢驗證常式）。最終驗證器通過並不代表過程合規，過程評分規準能暴露隱藏風險。

3. **軟體開發維運（DevOps）**：智能體操作多個工具工作流程（如部署、監控、日誌分析），需評估其是否正確組合技能、是否遺漏關鍵驗證檢查，而非僅看最終服務是否上線。SkillCoach 可過濾出高品質訓練軌跡，避免將僅基於結果的篩選所得到的脆弱行為當成正向示範。

4. **醫療診斷輔助系統**：不同科別或病徵的診斷技能存在重疊，SkillCoach 可確保智能體依據正確的黃金技能進行技能遵循與反思，避免僅因最終結果正確而忽略過程中的誤判風險。

5. **客戶服務智能體**：在大型技能儲存庫中，客服話術、退換貨流程、客訴升級等技能彼此干擾，需透過基於技能的過程評分規準篩選高品質訓練軌跡，提升智能體技能運用的可靠性。

### 實作前置條件

- **資料層面**：結構化的技能檔案（建議 Markdown 或 YAML 格式，含適用條件、步驟、預期產出及驗證常式）、已標註的黃金技能與任務指令對應關係、真實展開軌跡（含環境預言機互動記錄）、最終驗證器的判定邏輯（可為單元測試、規則引擎或人工準則）。
- **運算層面**：具備呼叫大型語言模型（LLM）進行評分規準演化與軌跡評判的 API 配額；收集真實展開與執行局部修補所需的運算資源。
- **技能層面前置**：技能庫需已達一定規模且存在重疊技能（干擾技能），任務必須為技能相依型，即智能體在無相關技能時表現顯著較差、提供黃金技能後則明顯提升，以確保過程監督訊號具有區辨度。

### 實作步驟建議

1. **技能庫盤點與結構化**：將現有 SOP、工具工作流程與領域規則轉換為統一格式的技能檔案，明確定義每個技能的輸入、步驟、預期產出及驗證檢查點。
2. **建立任務與驗證器**：設計技能相依型任務，並建置最終驗證器作為獨立的結果訊號，刻意保留部分干擾技能於技能庫中，模擬企業儲存庫的真實重疊情境。
3. **收集真實展開軌跡**：部署智能體於目標環境，收集大量包含成功與失敗的真實展開，記錄其技能選擇、中間步驟、工具呼叫與最終輸出。
4. **初始化基於技能的過程評分規準**：從黃金技能自動抽取四維度檢核點——技能選擇、技能遵循、技能組合、基於技能的反思——形成初始評分規準。
5. **證據導向評分與局部修補**：使用 LLM 依據可觀察證據對軌跡進行四維度評分，針對評分不一致或邊界案例，生成局部仲裁修補以細化規準。
6. **驗證閘道更新**：將修補後的評分規準套用至保留驗證集，僅當評估品質提升且未過度擬合時才合併至主規準，完成自我演化。
7. **雙軌應用**：將演化後的評分規準同時用於診斷（暴露被最終準確率隱藏的失敗）與訓練監督（篩選高品質軌跡作為監督式微調的正向示範，取代僅基於結果的篩選）。

### 潛在風險與注意事項

- **黃金技能標註成本**：建議先從高價值、高頻率的核心流程開始，逐步擴展，避免一次性盤點全部業務邏輯。
- **干擾技能過度相似**：若技能庫中重疊技能差異極小，初始評分規準可能難以區分，需額外注入領域專家的人工仲裁案例作為冷啟動。
- **偶然的任務成功干擾**：最終驗證器通過但過程品質低劣的軌跡若被誤當成正向示範，會強化脆弱行為；務必將結果訊號與過程訊號分離使用。
- **評分規準演化過度擬合**：局部修補可能過度適配已收集的歷史軌跡，建議保留獨立的驗證閘道軌跡集，並定期以新展開進行規準壓力測試。
- **運算與延遲成本**：LLM 作為評判者的多輪評分與修補會增加延遲，生產環境可改採輕量模型或快取常見軌跡的評分結果。

### 與其他技術的整合建議

- **技能檢索與 RAG 系統**：將 SkillCoach 的過程評分規準作為回饋訊號，動態調整技能檢索排序，優先推薦過去展現高遵循率的技能。
- **現有 LLM Agent 框架**：可嵌入 LangChain、AutoGen 或自有 Agent 框架的後處理管線，在不更動原有工具呼叫邏輯的前提下，增加軌跡診斷與訓練資料過濾層。
- **LLMOps 監控平台**：將四維度評分（技能選擇、技能遵循、技能組合、基於技能的反思）作為可觀測指標匯入監控儀表板，補足僅追蹤最終任務成功的盲點。
- **企業知識管理與 SOP 系統**：直接從現有 SOP 庫與領域規則匯出技能檔案，並將演化後的評分規準回寫為品質檢核清單，形成雙向閉環。
- **現有驗證與測試框架**：將最終驗證器對接既有 CI/CD 或自動化測試腳本，而過程評分規準則作為新的品質閘道（Quality Gate）。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先聚焦圖一與四維度概念（技能選擇、技能遵循、技能組合、基於技能的反思），理解「最終驗證器通過不等於正確使用技能」這一核心命題，暫時略過局部修補與驗證閘道的技術細節。
- **AI 工程師**：請重點研讀實作步驟與提示工程設計，關注如何從技能檔案自動生成初始評分規準、如何設計證據導向的評判提示，以及驗證閘道的合併條件與版本控制。
- **研究人員**：建議深入分析自我演化機制的收斂性、過程監督訊號與結果訊號的解耦設計，以及四維度作為可分解監督訊號在增強智能體技能運用上的理論意涵。
- **產品經理**：請優先閱讀適用場景與潛在風險章節，評估導入 SkillCoach 對現有業務流程的品質提升空間與標註成本，並將「過程品質可視化」視為新的產品差異化指標。
