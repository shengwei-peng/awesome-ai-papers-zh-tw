## 摘要翻譯

程式碼世界模型（code world models）將世界表示為可執行程式（executable programs），但僅有這種表徵並不足以決定如何建構複雜世界（complex world）。我們提出遞迴程式碼世界模型（Recursive Code World Models, RCWM），一個從單張參考影像（single reference image）以程式碼重建複雜三維世界（complex 3D worlds）的框架。RCWM 結合了遞迴場景程式（Recursive Scene Program, RSP）表徵與一個可遞迴自我呼叫（recursively calls itself）的建構求解器（construction solver）。RSP 將可執行世界（executable world）表示為組合式場景程式碼（compositional scene code），而每次求解器呼叫（solver call）都遵循相同的完整流程：建立整體（establish the whole）、遞迴重建未解決部分（recursively reconstruct unresolved parts），並重訪整體（revisit the whole）以精煉整體的組合。這種全域-局部-全域遞迴（global-local-global recursion）讓精細尺度結構（fine-scale structures）擁有各自的感知與編輯迴路（perception-and-editing loops），同時保留全場景幾何（scene-wide geometry）與關係。參考對齊視角（reference-aligned views）在各層級間傳遞共享的相機投影（shared camera projection），而父層重訪（parent revisitation）則處理局部精煉（local refinement）後產生的邊界（boundaries）、空間關係（spatial relations）與共享誤差（shared errors）。視覺-語言程式設計代理（vision-language coding agent）直接比較參考影像（reference image）與場景渲染圖（scene renders），以引導精煉、遞迴下降（recursive descent）與返回（return）。在多個複雜場景中，RCWM 優於先前基於程式碼的影像到場景重建方法（prior code-based image-to-scene reconstruction methods）。消融研究（ablation studies）進一步支持遞迴式建構（recursive construction）的效益，並顯示更深的呼叫（deeper calls）有助於改善更精細尺度的重建（finer-scale reconstruction）。RCWM 提供了一個遞迴建構原則（recursive construction principle），用以從視覺證據（visual evidence）建構複雜的可執行世界。

### 核心貢獻（3～5點）
- 提出遞迴程式碼世界模型（RCWM）框架，將遞迴場景程式（RSP）表徵與可遞迴自我呼叫的建構求解器結合，實現從單張參考影像以程式碼重建複雜三維世界。
- 設計全域-局部-全域遞迴流程：建立整體、遞迴重建未解決部分、重訪整體以精煉組合，使精細尺度結構擁有獨立的感知與編輯迴路，同時保留全場景幾何與關係。
- 透過參考對齊視角與父層重訪機制，在跨層級共享相機投影的同時，處理局部精煉後的邊界、空間關係與共享誤差。
- 以視覺-語言程式設計代理直接比較參考影像與場景渲染圖，引導遞迴下降、局部重建與返回過程。
- 在複雜場景中驗證 RCWM 優於先前基於程式碼的影像到場景重建方法，並透過消融研究證明更深的遞迴呼叫有助於更精細尺度的重建。

### 適合對象
適合對電腦視覺、三維場景重建、程式生成（program generation）與世界模型（world models）有興趣的研究者與工程師，特別是關注如何以可執行程式碼表徵複雜世界、並透過遞迴機制處理多尺度結構與精細幾何的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心問題意識：從「可執行表徵」到「可建構原則」

程式碼世界模型（code world models）將世界表徵為可執行程式（executable programs），其優勢在於幾何（geometry）、材質（materials）與空間關係（spatial relationships）皆以程式元素（program elements）顯式存在，支援目標式編輯（targeted editing）、元件重複使用（component reuse）以及與物理模擬（physical simulation）整合。然而，單一表徵並未回答「如何組織計算（organize computation）」的問題：當場景包含多尺度精細結構（fine-scale structures）時，單一重建軌跡（reconstruction trajectory）難以同時解析全域佈局（layout）與局部細節。

遞迴程式碼世界模型（Recursive Code World Models, RCWM）提出的核心原則是：複雜世界建構應是遞迴的。每個部件（parts）不是被生成後插入的靜態資產，而是擁有自己完整重建流程的子世界（subworld）。

##### 2. 遞迴場景程式（Recursive Scene Program, RSP）

RCWM 的輸出表徵（output representation）為 RSP，其將可執行世界（executable world）組織為巢狀子世界（nested subworlds）的組合式場景程式碼（compositional scene code）。形式上：

\[
S_R = \text{Exec}(P), \quad \hat{I} = \mathcal{R}(S_R; \kappa)
\]

其中 \(P\) 為參數化場景程式，\(\kappa\) 為參考視角相機設定（reference-view camera configuration），包含相機姿態、投影與視埠尺寸。RSP 不僅描述幾何與材質，還包含原始程序（source procedures）、可編輯參數（editable parameters）、子元件引用（component references）以及共享相依性（shared dependencies），因此具備顯式結構與狀態，可供直接檢查與操作。

##### 3. 建構求解器（Construction Solver）的「全域–局部–全域」遞迴

RCWM 的建構求解器（construction solver）在每一層級（level）執行相同的三階段循環：

1. **建立整體（Establish the whole）**：為當前層級建立共享空間情境（shared spatial context），決定相機投影與空間慣例。
2. **遞迴重建未解決部分（Recursively reconstruct unresolved parts）**：辨識尚未解析的視覺子問題，對每個子世界（subworld）進行一次完整的求解器呼叫（solver call）。
3. **重訪整體並精煉組合（Revisit the whole and refine their composition）**：將子世界返回的結果重新組合，檢查並修正邊界（boundaries）、空間關係（spatial relations）與共享誤差（shared errors）。

這形成「全域–局部–全域遞迴（global-local-global recursion）」：

\[
\text{Level } k \xrightarrow{\text{建立整體}} \text{Level } k+1 \xrightarrow{\text{返回}} \text{Level } k
\]

關鍵在於「每層級使用相同求解器（same solver at every level）」：無論是場景（scene）、村落（village）、建築（building）或立面（facade），皆經歷同樣完整的感知與編輯迴路（perception-and-editing loops）。

##### 4. 參考對齊視角（Reference-aligned Views）與父層重訪（Parent Revisitation）

為了讓遞迴中的每個子世界都能獲得聚焦的視覺證據（focused visual evidence），RCWM 採用參考對齊視角（reference-aligned views）：子世界繼承父層的相機投影（shared camera projection），但將視錐（frustum）縮窄至對應區域，產生與參考影像局部裁切對齊的視角。這確保跨層級（across levels）的渲染圖（scene renders）與參考影像（reference image）具有一致的投影幾何。

當子世界完成並返回後，父層重訪（parent revisitation）會再次檢視組合結果。此步驟專門處理局部精煉（local refinement）後才浮現的問題，例如：

- 招牌（sign）與鄰近窗戶（window）發生重疊錯誤；
- 精煉後的橋樑（bridge）不再與河岸（riverbanks）相接；
- 多個子世界共享的因果錯誤（shared causes of error）。

這種「先分後合」的機制使精細尺度結構（fine-scale structures）擁有獨立的重建迴路，同時維持全場景幾何（scene-wide geometry）與部件間關係（relationships among parts）的一致性。

##### 5. 視覺-語言程式設計代理（Vision-language Coding Agent）

RCWM 以視覺-語言程式設計代理（vision-language coding agent）作為求解器的實作核心。該代理直接比較參考影像（reference image）與場景渲染圖（scene renders），並據此指導：

- **遞迴下降（recursive descent）**：判斷哪些區域仍有未解決結構，需要進入下一層級；
- **局部重建**：在子世界內生成或修改程式碼；
- **返回與精煉（return and refinement）**：評估子世界返回後的整體一致性，決定是否需要進一步編輯。

透過渲染回饋（visual feedback），代理能夠在需要時持續向更深層級探索，從而實現更精細尺度的重建（finer-scale reconstruction）。

##### 6. 與「固定場景–物件管線」的區別

作者強調 RCWM 並非「固定場景–物件管線（fixed scene-object pipeline）」加上最終清理（final cleanup）。在傳統管線中，物件一旦被產生並插入，往往只在最後做一次全域調整；而 RCWM 的每個子世界都經歷「建立整體 → 遞迴呼叫 → 重訪整體」的完整週期，錯誤可以在其發生的層級被發現並修正，並透過父層重訪處理跨層級衝突（conflicts）。

#### 實驗數據解讀

由於提供的全文片段僅包含摘要、引言與方法概述，具體的量化實驗數據（如數值指標、圖表、標準差、樣本數）並未出現。因此以下僅能根據文中敘述進行詮釋，並指出需要進一步檢視的項目。

##### 1. 主實驗宣稱

文中指出，RCWM 在複雜場景（complex scenes）上優於先前基於程式碼的影像到場景重建方法（prior code-based image-to-scene reconstruction methods），且消融研究（ablation studies）支持以下結論：

- **遞迴式建構（recursive construction）** 本身具有效益；
- **更深的呼叫（deeper calls）** 有助於更精細尺度的重建；
- **父層重訪（parent revisitation）** 對處理邊界與空間關係至關重要。

##### 2. 消融研究的設計邏輯

文中提到消融研究檢驗了：

- **建構順序（construction order）**：驗證「先建立整體、再進入局部、最後重訪整體」的順序是否必要；
- **遞迴深度（recursive depth）**：探討更深的遞迴層級是否確實提升細節重建；
- **父層重訪（parent revisitation）**：比較有無重訪機制時，邊界與空間關係的表現差異。

這些消融在「相同局部視覺存取（same local visual access）」與「相同基礎模型（same base model）」下進行，因此效能差異可歸因於 RCWM 的遞迴結構本身，而非更強大的視覺模型或更多輸入資訊。

##### 3. 評估指標的推測

雖然文中未明列指標，但基於影像到場景重建的常見做法，可合理推測其評估包含：

- **全場景相似度**：渲染圖與參考影像在整體佈局、顏色、結構上的相似性（如 LPIPS、SSIM、CLIP 相似度）；
- **局部重建品質**：對精細區域（如窗戶、招牌、裝飾）進行裁切後的比較；
- **幾何一致性**：物件間的空間關係是否正確；
- **程式可執行性與可編輯性**：RSP 是否能正確執行、參數是否可調整。

##### 4. 結果詮釋與限制

若主實驗宣稱成立，則代表「組織計算的方式」對複雜場景重建具有顯著影響：在相同基礎模型與相同視覺輸入下，僅透過遞迴分解與父層重訪即可提升表現。這與近期視覺-語言程式設計代理（vision-language coding agents）的研究趨勢一致，即「如何將問題結構化」往往比「使用更強大的單次生成模型」更重要。

然而，由於缺乏具體數據，無法判斷：

- 提升幅度是否在所有場景類別都一致；
- 遞迴深度是否存在收益遞減或成本暴增的臨界點；
- 失敗案例主要來自於感知錯誤、幾何推理錯誤，還是程式編譯錯誤。

#### 與現有研究的比較

##### 1. 與其他程式碼世界模型（Code World Models）的關係

近期研究如 Yin et al. (2026)、He et al. (2026) 與 img2threejs contributors (2026) 已開始利用視覺-語言模型（vision-language models）進行程式生成（program generation）與基於渲染的視覺檢查（render-based visual inspection）。RCWM 與這些方法共享以下基礎：

- 以可執行程式碼作為場景表徵；
- 透過渲染圖與參考影像比較來迭代修正；
- 利用視覺-語言模型作為程式設計代理（coding agent）。

RCWM 的差異在於引入**遞迴建構原則（recursive construction principle）**：不是一次性生成整個場景程式，而是將複雜世界遞迴分解為子世界，並在每個層級執行完整的求解器循環。

##### 2. 主要改進

| 面向 | 先前方法 | RCWM |
|---|---|---|
| 計算組織 | 通常為單次或序列式生成，可能輔以迭代修正 | 遞迴自我呼叫（recursively calls itself），每層級皆為完整求解 |
| 局部細節 | 全場景檢視（whole-scene review）容易忽略小結構 | 子世界擁有聚焦的重建任務（focused reconstruction tasks）與獨立感知迴路 |
| 一致性 | 局部編輯（local edits）可能產生衝突 | 父層重訪（parent revisitation）主動處理邊界與空間關係 |
| 視覺證據 | 單一視角或簡單裁切 | 參考對齊視角（reference-aligned views）繼承共享相機投影（shared camera projection） |
| 輸出結構 | 扁平或固定層級的程式碼 | 巢狀子世界（nested subworlds）的 RSP，具顯式父子引用 |

##### 3. 與傳統 3D 重建方法的區別

傳統基於多視角幾何或神經輻射場（NeRF/3DGS）的方法通常輸出隱式或網格表徵，難以直接編輯。RCWM 輸出的是參數化、可執行的場景程式碼，支援：

- 直接檢查與操作（direct inspection and manipulation）；
- 目標式編輯（targeted editing）；
- 元件重複使用（component reuse）；
- 與物理模擬（physical simulation）整合。

然而，RCWM 目前以單張參考影像（single reference image）為輸入，缺乏多視角幾何約束，這在幾何精確性上可能不如傳統多視角方法。

##### 4. 限制

- **單一視角輸入**：僅憑單張參考影像難以推斷被遮擋區域的幾何與結構；
- **依賴視覺-語言模型能力**：代理的程式生成、錯誤診斷與遞迴決策皆受限於基礎模型的視覺推理與程式設計能力；
- **計算成本**：遞迴呼叫與多次渲染可能帶來顯著的時間與 API 成本；
- **終止條件**：如何決定「何時停止遞迴下降」需要可靠的判斷機制，否則可能過度分解或遺漏細節；
- **評估主觀性**：影像到場景的評估可能高度依賴視覺相似度指標，難以完全捕捉幾何正確性與可編輯性。

#### 未來研究方向

##### 1. 多視角與影片輸入

目前 RCWM 以單張參考影像（single reference image）為輸入。未來可擴展至多視角影像或影片，利用多視角幾何約束提升被遮擋區域與深度估計的準確性，同時保留程式碼表徵的可編輯性。

##### 2. 學習式遞迴決策

當前的遞迴下降與返回決策可能由視覺-語言代理啟發式地判斷。未來可訓練專門的策略網路或利用強化學習（reinforcement learning）來學習「何時分解」、「分解到多細」、「何時重訪」，以提升效率與重建品質。

##### 3. 混合神經-符號表徵

將 RSP 與神經輻射場（NeRF）、3D 高斯潑濺（3D Gaussian Splatting）或神經網路材質結合，可在保留程式碼可編輯性的同時，提升外觀與幾何的真實感，特別是對於難以用參數化程式描述的細節（如植被、布料、不規則地形）。

##### 4. 與物理模擬的緊密整合

RSP 的顯式結構使其天然適合與物理模擬（physical simulation）結合。未來可研究如何自動生成具備物理屬性（質量、剛性、流體行為）的場景程式，並透過模擬回饋進一步修正幾何與空間關係。

##### 5. 互動式與目標導向編輯

RCWM 的輸出為可執行程式，未來可發展互動式介面，讓使用者透過自然語言或視覺操作指定編輯目標，並由代理在適當的子世界層級進行局部修改，同時自動維持父層一致性。

##### 6. 不確定性驅動的遞迴

引入不確定性估計（uncertainty estimation）可讓求解器優先對高不確定性區域進行更深的遞迴呼叫，而非均勻分解場景，從而節省計算資源並提升關鍵區域的重建品質。

##### 7. 自動終止與錯誤恢復

設計更穩健的終止條件與錯誤恢復機制，例如當子世界重建失敗時自動回退（rollback）並嘗試不同分解策略，將使 RCWM 在更廣泛的場景類別上可靠運作。

##### 8. 跨領域泛化

目前評估聚焦於複雜三維世界（complex 3D worlds），如村落與建築。未來可探索 RCWM 在室內場景、機械裝置、分子結構或抽象資料視覺化等領域的適用性，並發展領域專用的子世界分解原則。

## 論文問答

**Q1（背景與動機）：RCWM 試圖解決的核心問題是什麼？**
A：RCWM 旨在從單張參考影像重建複雜三維世界，並將其表示為可執行的組合式場景程式碼。現有的程式碼世界模型雖然能表達幾何、材質與空間關係，卻沒有說明如何系統化地建構具有多尺度結構的複雜世界。因此，RCWM 的核心挑戰在於同時處理精細尺度的局部細節，並維持部件之間的全域空間關係。

**Q2（背景與動機）：先前的基於程式碼的影像到場景重建方法為何在複雜場景上表現不足？**
A：先前方法通常依賴單一重建軌跡或固定的場景—物件管線，反覆檢視全場景時容易忽略窗戶、招牌等精細結構。即使將小結構獨立出來進行局部重建，這些局部編輯也並非相互獨立，容易在邊界或空間關係上產生衝突。由於缺乏從父層繼承情境、完成自身重建後再返回父層精煉組合的機制，這些方法難以同時兼顧局部細節與整體一致性。

**Q3（背景與動機）：為何遞迴式建構比單純改進表徵更為關鍵？**
A：複雜世界蘊含的結構遠超過單一重建軌跡所能解析，僅擁有表達力強的程式碼並不足以決定如何建構它。遞迴式建構將每個部件視為值得完整重建流程的子世界，使其能繼承父層的共享空間情境與相機投影，並在聚焦的視覺證據上進行感知與編輯。這種「建立整體—遞迴下降—返回重訪」的循環，能夠在城鎮、建築、立面到窗戶等每個尺度重複運作，從而同步解決局部細節與跨部件一致性。

**Q4（方法與創新）：RCWM 中建構求解器的三個階段是什麼，它們如何協同運作？**
A：每個求解器呼叫都遵循相同的三階段流程：建立整體、遞迴重建未解決部分，以及重訪整體以精煉其組合。第一階段為子世界提供共享的空間情境與參考對齊視角；第二階段將尚未解析的視覺子問題委派給下一層級的相同求解器；第三階段則在局部精煉完成後，重新檢視並修正邊界、空間關係與共享誤差。這三個階段形成全域—局部—全域的遞迴模式，使每個尺度都能獲得完整的感知與編輯迴路。

**Q5（方法與創新）：什麼是遞迴場景程式（RSP），它如何支援可執行與可編輯的世界表示？**
A：遞迴場景程式（RSP）將可執行世界表示為以巢狀子世界組織的組合式場景程式碼，包含原始程序、可編輯參數、子部件引用以及共享相依性。每個子世界可以獨立執行、渲染與修改，並透過 part.json、model.js 等模組返回給父層進行組合。這種結構不僅讓使用者能直接檢查與操作世界的結構與狀態，也支援目標式編輯、元件重複使用以及與物理模擬的整合。

**Q6（方法與創新）：參考對齊視角與父層重訪為何是 RCWM 的關鍵設計選擇？**
A：參考對齊視角透過共享相機投影（如 K' = H·K）與對應的參考裁切影像，將父層的觀測幾何傳遞給子世界，確保局部視覺證據與整體空間情境一致。父層重訪則在子世界返回後，再次檢視組裝好的整體，以處理單獨局部檢視可能遺漏的邊界問題、空間關係錯位與共享誤差。兩者結合，使 RCWM 能夠在賦予精細結構獨立重建迴路的同時，仍維持全場景幾何與關係的一致性。

**Q7（實驗與結果）：RCWM 使用什麼樣的評估設定與基線進行比較？**
A：作者以參數化的 Three.js 編譯器實例化 RCWM，並在複雜場景上與先前的基於程式碼的影像到場景重建方法進行比較，所有方法使用相同的基礎模型以確保公平性。評估同時檢視全場景與局部的重建品質，並透過消融研究探討建構順序、遞迴深度與父層重訪的貢獻。這樣的設定能夠在相同局部視覺存取條件下，驗證遞迴建構機制本身所帶來的效益。

A：實驗顯示，RCWM 在複雜場景上的整體與局部重建表現均優於先前的程式碼式基線方法。透過視覺—語言程式設計代理直接比較參考影像與場景渲染圖，RCWM 能夠更準確地捕捉精細結構與空間佈局。這些結果說明，將遞迴建構原則引入程式碼世界模型，能顯著提升從單張影像重建複雜三維世界的品質。

A：消融研究進一步支持遞迴式建構與父層重訪對於維持跨部件一致性具有顯著助益，缺少這些機制時，局部精煉容易產生邊界衝突與空間關係錯位。研究也指出更深的遞迴呼叫能夠改善更精細尺度的重建品質，因為更深的層級能為小結構提供專屬的感知與編輯迴路。此外，建構順序的消融顯示，先建立整體再進行局部重建、最後返回重訪的順序，對於最終組合的一致性至關重要。

A：RCWM 可應用於從概念藝術或單張照片快速生成可執行的三維場景原型，例如遊戲關卡設計、建築視覺化、虛擬製作與數位孿生建構。由於輸出是結構化的場景程式碼，設計師可以直接調整參數、替換材質或重複使用建築立面等元件。遞迴的子世界結構也讓大型場景能夠模組化地管理與協作編輯。

A：產品化時必須管理遞迴呼叫樹所帶來的運算成本、延遲與語言模型呼叫次數，並確保渲染器與相機投影在各層級保持一致。使用者介面需要清楚呈現巢狀子世界的層級關係，讓使用者能夠追蹤與編輯每個 part.json 或 model.js 模組。此外，當參考影像存在遮擋、解析度不足或語意模糊時，系統應提供適當的介入機制或預設策略，以避免錯誤在遞迴樹中放大。

**Q12（應用與影響）：RCWM 對影像到場景重建領域可能帶來什麼樣的影響？**
A：RCWM 將研究焦點從「如何表達世界」轉向「如何以遞迴原則建構世界」，強調程式碼世界模型需要系統化的建構流程。它展示了視覺—語言程式設計代理可以作為可重複呼叫的求解器，透過渲染回饋進行階層式重建。這種全域—局部—全域的遞迴框架，可能啟發未來結合神經符號方法與可執行程式碼的複雜場景重建研究。

**Q13（限制與未來）：RCWM 有哪些已顯現或隱含的限制？**
A：RCWM 高度依賴視覺—語言程式設計代理的程式生成與視覺判斷能力，當參考影像中的結構被嚴重遮擋或語意模糊時，重建品質可能下降。遞迴層級越深，運算與模型推論成本也隨之增加，且相機標定與渲染器的任何系統性誤差都可能沿著層級傳播。此外，單張參考影像所能提供的視覺證據有限，難以推斷不可見的背面或內部結構。

**Q14（限制與未來）：RCWM 可能出現哪些典型的失敗案例？**
A：子世界可能誤解局部裁切影像，返回與鄰近部件在邊界上衝突的幾何，例如招牌與窗戶重疊錯誤。若父層重訪時代理的全局理解不足，可能無法發現由共同原因引起的共享誤差，導致整體場景仍不一致。另外，當遞迴在過淺的深度停止時，非常細緻或紋理豐富的結構可能被省略；而過度反覆精煉則可能使局部細節偏離參考影像的全局佈局。

**Q15（限制與未來）：未來研究可以從哪些方向延伸 RCWM？**
A：未來可以結合可微分渲染或最佳化技術，在程式碼層級進行數值精煉，以補強視覺—語言代理的離散編輯。引入學習過的形狀先驗與三維資產庫，能夠在證據不足時提供更合理的預設幾何。此外，將輸入擴展至多視角影像或影片，並自動決定每個子世界的遞迴深度，將有助於提升重建的完整性與效率。

### 實作步驟建議

1. **定義場景層級與子世界結構**  
   先將目標世界依空間尺度拆解為巢狀子世界，例如：全場景 → 區域 → 建築 → 立面 → 細部裝飾，並為每個子世界準備對應的參考裁切影像與 view.json。

2. **建立參考對齊視角與相機投影**  
   為每個層級產生共享相機投影，讓父層與子世界的渲染圖能與參考影像在同一視角下比較。可使用 homography 或已知相機參數計算 `K' = H·K`。

3. **實作遞迴建構求解器**  
   設計一個統一的求解器，使其在每個節點執行相同三步驟：建立整體、遞迴重建未解決部分、重訪整體並精煉組合。確保求解器能自我呼叫，並將父層情境繼承給子世界。

4. **整合視覺-語言程式設計代理**  
   讓代理直接比較參考影像與場景渲染圖，判斷哪些區域仍需遞迴下降、哪些邊界或空間關係需要在父層重訪時修正。

5. **產生遞迴場景程式並編譯執行**  
   將輸出組織為 RSP，包含 model.js、part.json、view.json 等檔案，並透過 Three.js 編譯器執行，產生可渲染、可編輯的最終場景。

6. **迭代驗證與消融測試**  
   針對不同遞迴深度、建構順序與父層重訪機制進行消融研究，確認更深的呼叫確實改善更精細尺度的重建，並避免過度分割導致的邊界不一致。

### 潛在風險與注意事項

- **邊界與空間關係不一致**  
  子世界經局部精煉後，可能出現招牌遮住鄰窗、橋樑未接河岸等問題。必須透過父層重訪機制，在組合後再次檢視並修正。

- **遞迴深度與成本權衡**  
  更深的呼叫可提升精細尺度重建，但會顯著增加運算量與 API 呼叫次數。建議根據場景複雜度設定最大深度，並在細節收益遞減時停止。

- **相機投影錯位導致比較失準**  
  若子世界的參考對齊視角不準確，視覺-語言代理會做出錯誤判斷。需確保每層級的 view.json 與裁切區域正確對應。

- **過度擬合單張參考影像**  
  模型可能過度複製參考視角下的外觀，導致從其他角度觀看時幾何不連貫。建議在產品階段加入多視角驗證或人工檢查。

- **程式碼可維護性下降**  
  隨著遞迴層級增加，RSP 的巢狀結構會變得複雜。應建立清晰的命名規範、模組化元件與版本控制，避免後續編輯困難。

### 與其他技術的整合建議

- **與傳統 3D 建模工具整合**  
  可將 RSP 輸出轉換為 glTF / OBJ 格式，匯入 Blender、Maya 或 Unreal Engine，供美術進行後續細修與材質調整。

  可將 RCWM 作為中間層：上游使用圖像生成模型產生概念圖，下游使用 RCWM 轉為可執行場景程式，再結合 NeRF 或 Gaussian Splatting 補充真實感紋理。

- **與版本控制與協作平台整合**  
  場景程式碼可直接納入 Git 管理，並與 CI/CD 管線結合，自動執行渲染比對測試，確保每次修改不會破壞全場景幾何或空間關係。

請重點閱讀遞迴建構求解器的設計、視覺-語言代理如何比較參考影像與場景渲染圖，以及參考對齊視角與父層重訪的實作細節，這些是將論文轉為可部署系統的關鍵。

**研究人員**  
建議深入分析消融研究部分，特別是建構順序、遞迴深度與父層重訪對重建品質的影響，並思考如何將此遞迴原則擴展到其他表徵形式，如神經場景表徵或程式化生成模型。

**產品經理**  
請關注適用場景與實作前置條件，評估貴團隊是否具備足夠的參考影像資料、GPU 運算資源與 Three.js 工程能力；同時留意潛在風險中的成本與邊界一致性問題，以規劃合理的產品化路徑。
