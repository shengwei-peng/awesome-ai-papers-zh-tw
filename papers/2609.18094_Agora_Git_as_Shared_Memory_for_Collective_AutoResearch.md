# Agora：用於集體自動研究（Collective AutoResearch）的 Git 共享記憶體（Git as Shared Memory）

## ⚡ TL;DR

多個自動研究代理各自為政，導致重複探索且無法累積共享知識。
Agora 以 Git 作為追加式 DAG 共享記憶體，每項貢獻皆為可檢出重現的不可變提交。
13 代理 12 天發表 1,703 項貢獻，bpb 從 3.39 降至 1.899，165次重現。

## 摘要翻譯

諸如 AutoResearch（自動研究）這類自主研究迴路顯示，單一程式設計代理（coding agent）無需人工監督即可改進一項訓練設定（training setup）。同時執行多個這類代理時，每個工作階段都從頭開始，因此增加代理數量往往意味著更多重複搜尋，而非更多發現。Agora 是這類代理的共享記憶體（shared memory）：研究被記錄為以僅限附加（append-only）有向無環圖（DAG, directed acyclic graph）形式儲存於 Git 中，因此每個宣稱（claim）都是一筆提交（commit），任何人都能檢出（check out）並重新執行（rerun）。每個結果、洞察、假設、驗證與報告都是一筆不可變（immutable）的提交，其父邊（parent edges）標示其所建基之處；一個衍生索引（derived index）會揭露前沿（frontier）、被忽略的分支（neglected branches），以及每個宣稱的驗證狀態（verification status），而多樣性感知選擇規則（diversity-aware selection rule）則避免社群（community）收斂到單一領導者。我們描述此系統，並報告其首次持續運作：一場為期近 12 天的運行（run），期間 13 個語言模型工作程序（language-model workers）在沒有指派任務、也沒有中央規劃者的情況下，處理一個權重遷移問題（weight-transfer problem）。在給定 141 個預訓練捐贈模型（pretrained donor models），以及一個凍結（frozen）的 119.6M 參數（parameters）注意力-SSM 混合模型（attention-SSM hybrid）——其維度與任何捐贈模型均不匹配——的情況下，這些工作程序必須在沒有訓練資料（training data）或梯度更新（gradient updates）的條件下初始化目標（target）。它們發布了 1,703 項貢獻（contributions），並將評估器（evaluator）的每位元組位元數（bpb, bits per byte）從 3.39 降至 1.899，縮短了與一個已訓練 GPT-2 124M 之間 62% 的差距。勝出的做法將捐贈模型的下一個詞元統計資料（next-token statistics）壓縮到目標模型的嵌入（embedding）與輸出頭（output head），再透過對注意力（attention）、前饋（feed-forward）與狀態空間區塊（state-space blocks）進行稀疏編輯（sparse edits），加入短程上下文訊號（context signal）。其 145 筆提交的譜系（ancestry）橫跨 15 個帳號（accounts），並發布了 165 次獨立重現（reproductions），且無一失敗。我們描述了唯一一次執行中期的人類介入（human intervention），它使社群脫離單一文化（monoculture）；也說明這段軌跡（trace）能確立與無法確立的事項，以及一項對照比較，用以判定共享研究狀態（shared research state）是否能提升每單位運算（compute）的發現量。

### 核心貢獻（3～5點）
- 提出 Agora，一個以 Git 為基礎的共享記憶體架構，將研究記錄為僅限附加的有向無環圖（DAG），使每項宣稱皆可檢出、重新執行與獨立驗證。
- 設計衍生索引與多樣性感知選擇規則，讓多個語言模型工作程序能自動發現前沿、探索被忽略的分支，並避免社群收斂至單一文化。
- 首次長時間運行：13 個無中央規劃的代理在近 12 天內於權重遷移任務發布 1,703 項貢獻，將每位元組位元數從 3.39 降至 1.899，縮短與已訓練 GPT-2 124M 之間 62% 的差距。
- 發現有效的權重遷移策略：壓縮捐贈模型的下一個詞元統計資料到目標模型的嵌入與輸出頭，並以稀疏編輯注入短程上下文訊號；該結果具有 145 筆提交的譜系、橫跨 15 個帳號，且獲得 165 次獨立重現而無一失敗。
- 坦誠討論限制：記錄唯一一次執行中期的人類介入、說明軌跡能與不能確立之事，並提出對照比較以驗證共享研究狀態對每單位運算發現量的影響。

### 適合對象
對多代理協作、自動化機器學習研究、開放科學與可重現性，以及以 Git／DAG 為基礎之分散式知識系統感興趣的研究者與工程師；特別適合關注如何讓多個自主語言模型代理共享狀態、避免重複搜尋，並提升集體發現效率的讀者。

## 深度分析

#### 方法論解析

Agora 的核心命題是將「集體自動研究（Collective AutoResearch）」建模為一個僅限附加（append-only）的有向無環圖（Directed Acyclic Graph, DAG），並以 Git 作為共享記憶體（Shared Memory）。在這個設計中，每一項研究貢獻都是一個 Git commit（提交），而 commit 之間的 parent edge（父邊）則明確表達「建基於（builds on）」的知識依賴關係。這使得整個研究狀態成為不可變（immutable）且內容定址（content-addressed）的：任何人都可以檢出（check out）特定 commit 並重新執行（rerun）以驗證其宣稱。

系統的狀態層僅由 Git 歷史構成，worker（工作程序）之間不共享對話、不共享執行環境、也不存在中央規劃者（central planner）。它們讀取共享的 DAG，選擇一個或多個父節點作為起點，執行實驗後再將新的 artifacts（成品）、metrics（指標）、claims（宣稱）與 provenance（來源）寫回成新的 commit。這種設計把「研究過程」本身變成了可被版本控制的資料結構。

為了讓這個 DAG 能被有效導航，Agora 在 Git 之上建立了一個衍生索引（derived index），通常以 SQLite 實作。該索引暴露幾個關鍵視角：

- **Frontier（前沿）**：目前表現最好或最新的貢獻集合，讓 worker 知道該從哪裡繼續推進。
- **Neglected branches（被忽略的分支）**：長時間沒有後繼 commit 的路線，用於提醒社群某些假設尚未被充分探索。
- **Verification status（驗證狀態）**：每個 claim 是否已被獨立重現（reproduction），以及重現是否成功。

第三個設計重點是多樣性感知注意力分配（diversity-aware attention allocation）。由於多個 language-model workers（語言模型工作程序）若只追逐當前最佳分數，容易快速收斂到單一研究方向，形成 monoculture（單一文化）。Agora 透過 diversity-aware selection rule（多樣性感知選擇規則）在推薦下一個要檢出的 commit 時，同時考量表現與路線多樣性，試圖讓社群維持並行的探索。這個機制並不保證最佳規劃，而是作為啟發式（heuristic）來平衡探索（exploration）與利用（exploitation）。

整體而言，Agora 把研究社群需要的幾項基礎設施—— durable public memory（持久公共記憶）、attribution（歸因）、lineage（譜系）、negative results（負面結果）、independent verification（獨立驗證）——濃縮到一個統一的 Git-backed DAG 中。它不干預研究者的內部推理流程，只提供足夠透明的共享狀態，讓人類與代理能夠圍繞相同的 frontier、neglected branches 與 verification status 進行協調。

#### 實驗數據解讀

論文報告了 Agora 的第一次持續運行：13 個 coding agents（程式設計代理）在將近 12 天內，沒有被指派任務、沒有中央規劃者，僅憑一份兩頁 brief、一個 evaluator（評估器）與共享 DAG，共同解決一個 weight-transfer problem（權重遷移問題）。

任務設定相當具有挑戰性：目標是一個凍結（frozen）的 119.6M 參數 attention-SSM hybrid（注意力-SSM 混合模型），其維度與 141 個 pretrained donor models（預訓練捐贈模型）皆不匹配；worker 無法使用任何訓練資料或 gradient updates（梯度更新），只能把捐贈模型的知識轉移到目標模型中。評估指標為 bits per byte（bpb，每位元組位元數），越低代表壓縮能力越好。

主要結果如下：

- **指標進展**：從 random baseline（隨機基線）的 3.39 bpb 降至 1.899 bpb。
- **相對進步**：相較於 trained GPT-2 124M 的表現，worker 們縮小了約 62% 的差距。
- **貢獻規模**：共發布 1,703 個 contributions（貢獻）。
- **譜系與重現**：最終獲勝方法的 ancestry（譜系）長達 145 個 commit，橫跨 15 個 accounts（帳號）；社群另外張貼了 165 次 independent reproductions（獨立重現），且無一失敗。
- **協調動態**：在運行中期出現了一次 human intervention（人類介入）——研究者向 worker 展示它們自身集中度（concentration）的地圖，隨後一個持續五天的 monoculture 在一天內瓦解。

從這些數據可以得出幾點解讀：

1. **共享狀態確實能產生累積性進展**：如果每個 worker 都從零開始，很難想像能在 12 天內透過 1,703 個小步驟達成 1.899 bpb。parent edge 所記錄的 lineage 讓後續 worker 能直接繼承前人成果，避免重複搜尋。

2. **獨立重現是強而有力的驗證訊號**：165 次成功 reproductions 顯示 Agora 的 immutable commit 與 content-addressed artifacts 在實務上能支撐 reproducibility（可重現性）。這比單一實驗腳本更進一步，因為每次重現都伴隨一個新的 commit，留下可稽核的驗證紀錄。

3. **最終方法具有可解釋的結構**：獲勝配方分兩階段——先把 donor 的 next-token statistics（下一個詞元統計資料）壓縮到 target 的 embedding（嵌入）與 output head（輸出頭），再透過 sparse edits（稀疏編輯）對 attention（注意力）、feed-forward（前饋）與 state-space blocks（狀態空間區塊）注入短程 context signal（上下文訊號）。這與單純的權重複製不同，更像是一種「知識蒸餾式」的初始化策略。

4. **人類介入的效果顯著但帶來詮釋限制**：雖然這次 intervention 成功打破 monoculture，但它也意味著目前系統尚無法完全自主地維持多樣性。論文坦承這是「單次」介入，因此無法確定若無人類提示，社群是否會自行恢復多樣性。

5. **指標單一性**：bpb 是語言建模壓縮能力的標準指標，但實驗僅以此為目標，未報告下游任務（如 perplexity 在不同領域的泛化、zero-shot 能力等）。因此這 62% 的 gap closure 應被理解為在特定評估器上的進展，而非全面證明該初始化方法優於其他方法。

#### 與現有研究的比較

Agora 的定位並非取代現有的自動研究代理，而是填補它們之間的「共享狀態層」空缺。以下從幾個文獻脈絡進行比較：

**相較於單一自主研究代理（AutoResearch）**  
Karpathy（2026）的 AutoResearch 證明單一 coding agent 可以在無人看管的情況下改善 training setup（訓練設定）。然而，多個這樣的 session 並行時，每個都從頭開始，導致 duplicated search（重複搜尋）而非更多發現。Agora 透過 Git-backed DAG 讓經驗跨 session 累積，把「單一代理的長期運行」擴展為「多代理的集體記憶」。

**相較於現有多代理框架**  
Hong et al.（2023）、Li et al.（2023）、Wu et al.（2023）等人提出的系統通常透過 roleplay（角色扮演）、programmable conversations（可程式化對話）、standard operating procedures（標準作業程序）或 staged dialogues（分階段對話）來協調代理。AgentVerse（Chen et al., 2023）探討團隊組成與湧現協作，Magentic-One（Fourney et al., 2024）則使用 orchestrator（編排器）來規劃與重定向專業代理。這些系統協調的是「同一應用或同一 episode 內的團隊」。Agora 服務的是異步、無共享執行環境、無中央管理者的參與者，其協調單位是 DAG 而非對話。

**相較於端到端自動科學家（AI Scientist、ResearchAgent、Agent Laboratory）**  
ResearchAgent（Baek et al., 2025）利用 reviewer agents 迭代精煉研究構想；The AI Scientist（Lu et al., 2024）自動化 idea generation、實作、實驗、論文撰寫與模擬審查；Agent Laboratory（Schmidgall et al., 2025）則以分階段 workflow 組織文獻回顧、實驗與報告。Agora 並不規定端對端的研究流程，而是專注於跨研究者的 durable state（持久狀態），包括 negative results、lineage 與 verification。兩者可互補：未來的 AI Scientist 可以作為 Agora 上的一個 worker，而 Agora 提供它所需的共享記憶。

**相較於可重現性與工作流程追蹤工具**  
DataLad（Halchenko et al., 2021）、ReproZip（Chirigati et al., 2013）、Whole Tale（Brinckman et al., 2019）、RO-Crate（Soiland-Reyes et al., 2022）、Nextflow / Snakemake / MLflow 等工具分別在資料版本控制、執行環境打包、可執行研究物件與 workflow lifecycle 上做出貢獻。Agora 把同樣的「版本化」概念往上提升一層：它的基本單位不是檔案或實驗，而是「claim（宣稱）」及其在 DAG 中的位置。這使得 reproducibility 與 scientific attribution 成為系統的一等公民。

**相較於探索與品質多樣性方法**  
多臂拉霸機（Auer et al., 2002）、UCT（Kocsis and Szepesvári, 2006）、novelty search（Lehman and Stanley, 2011）、MAP-Elites（Mouret and Clune, 2015）、POET（Wang et al., 2019）等方法提供了探索—利用權衡與品質多樣性的理論基礎。Agora 借鑑了這些直覺來設計 diversity-aware attention allocation，但明確指出其 DAG 既不是靜態拉霸機也不是遊戲樹，相關建議只是啟發式，而非最佳規劃保證。

**主要限制**  
論文本身也承認，目前缺乏一個「matched, preregisterable evaluation（配對、可預先註冊的評估）」來確立 shared research state（共享研究狀態）是否真的能在相同計算量下提升 discovery（發現）。此外，實驗僅在一個 weight-transfer 任務上進行，且只有一次 human intervention，因此關於 scalability（可擴展性）、跨領域泛化與完全自主協調的結論仍屬初步。

#### 可重現性評估

從內部可重現性來看，Agora 的設計本身具有優勢：每個 commit 都是 immutable 且 content-addressed，並伴隨 parent edge 記錄 provenance。165 次成功的 independent reproductions 顯示，在同一系統內，其他 worker 可以檢出特定 commit 並重新執行以獲得一致結果。這種「以重現作為驗證」的機制，比傳統論文僅附程式碼更進一步，因為它把驗證行為也記錄進 DAG。

然而，從外部可重現性（external reproducibility）的角度，目前論文並未明確說明以下項目是否公開：

- Agora 系統本身的 source code（Git / SQLite / API / CLI / web prototype）。
- 141 個 pretrained donor models 的權重與配置。
- 目標 attention-SSM hybrid 的完整架構與 frozen weights。
- evaluator 的實作細節與測試資料。
- 12 天運行產生的完整 DAG 與 commit 歷史。

論文僅描述系統架構與實驗結果，未提供公開下載連結或開源授權資訊。因此，在論文發表當下，外部研究者難以完全複製該實驗。若 NVIDIA 未來釋出上述資源，Agora 將成為一個極具價值的可重現研究平台；反之，其貢獻將主要停留在概念驗證與架構設計層面。

此外，可重現性也受限於執行環境：即使 artifacts 被 content-addressed，若實驗依賴特定硬體、驅動程式或私有資料，外部重現仍可能失敗。論文未詳細討論環境封裝（如 container、ReproZip 等）是否與 Git commit 綁定，這是未來需要補強之處。

#### 未來研究方向

Agora 開啟了幾條值得後續探索的研究路線：

1. **受控對照實驗**  
   論文在 Appendix C 提出了一個 matched、preregisterable 的評估設計。未來研究應比較「使用 Agora 的多代理社群」與「相同數量的孤立 AutoResearch session」在相同計算預算下的 discovery rate，以量化 shared research state 的真實價值。

2. **跨領域驗證**  
   目前實驗僅限於 weight-transfer 與語言建模。將 Agora 應用於電腦視覺、科學模擬、化學合成（如 ChemCrow、Coscientist）或軟體工程任務，可檢驗其 DAG 設計與 diversity-aware attention allocation 的泛化能力。

3. **更強大的驗證機制**  
   現行系統主要依賴 rerun 來驗證。未來可引入統計檢定、環境指紋（environment fingerprinting）、形式化證明輔助或 peer-review 代理，以減少 false positives 並提升 claim 的可信度。

4. **多樣性與注意力分配的理論基礎**  
   目前的 diversity-aware selection rule 是啟發式。未來可結合 multi-armed bandits、Bayesian optimization、quality-diversity 或資訊幾何方法，為 DAG 上的注意力分配建立更嚴謹的理論保證。

5. **衝突解決與 DAG 合併**  
   當多個 worker 對同一 frontier 提出互相矛盾的 claim 時，系統需要更明確的衝突解決機制。研究如何將「合併（merge）」、「rebase」或「fork」語義引入研究 DAG，將是擴大規模的關鍵。

6. **歸因與激勵設計**  
   隨著參與者增加，如何公平歸因貢獻、避免 free-riding、並激勵探索高風險路線，將需要結合機制設計（mechanism design）與社會選擇理論。

7. **人機混合社群**  
   本次實驗以語言模型 worker 為主，僅有一次人類介入。未來可研究人類研究者作為常態參與者時，Agora 如何支援人機協作、審查與創意引導。

8. **安全性與信任**  
   共享記憶體可能成為攻擊目標（例如惡意 commit、資料污染）。研究如何透過簽章、沙箱執行、聲譽系統與異常偵測來保障 DAG 的完整性，是實際部署前不可或缺的課題。

## 論文問答

**Q1：Agora 試圖解決什麼核心問題？**  
A：Agora 針對的是多個自主研究代理（coding agents）各自獨立運作時，每次都得從頭開始搜尋，導致重複勞動多於真正發現的問題。現有的多代理框架多數只協調單一任務或對話，無法讓實驗知識、失敗紀錄與驗證狀態跨回合保存。Agora 透過把研究過程記錄成 Git 上的僅限附加有向無環圖（append-only DAG），讓所有代理都能檢出、重跑並接續彼此的貢獻，從而建立持久的共享記憶體。

**Q2：為什麼現有的多代理系統無法直接滿足集體自動研究的需求？**  
A：現有系統通常以角色扮演、可程式化對話或標準作業流程來協調同一應用程式內的團隊，適合完成單一任務，但缺乏跨會話的公共前沿、不可變譜系、負面結果與獨立驗證機制。下一個工作階段無法知道哪個學習率曾發散、哪條分支被放棄、哪個結果還需要重現，因此增加代理只會加劇重複搜尋與過早收斂。Agora 把協調層從對話與中央規劃者移轉到共享的 Git DAG，使不同執行環境、不同帳號的代理都能非同步協作。

**Q3：為什麼「持久且共享的研究狀態」對代理社群如此重要？**  
A：科學研究本質上是社會與制度活動，研究者繼承前人成果、共用工具與程式碼，並在公共前沿上競爭與合作；群體產出並不等於最強成員的個人產出。對語言模型工作程序而言，若沒有共享記憶體，每個代理都只能在本地暫存的工作目錄（worktree）或對話紀錄中學習，無法累積負面結果、譜系與驗證紀錄。Agora 讓這些資訊成為公共且不可變的圖結構，使社群能夠分配注意力、避免單一文化，並持續推進前沿。

**Q4：Agora 的核心方法架構是什麼？**  
A：Agora 把研究視為一個不斷增長的貢獻 DAG，其中每個節點都是一筆 Git 提交（commit），攜帶成品、宣稱、指標與來源（provenance），父邊（parent edge）代表「建基於」的依賴關係。Git 提供不可變且內容定址（content-addressed）的儲存，SQLite 資料庫則建立可搜尋的索引視圖，用來暴露前沿、被忽略的分支以及每個宣稱的驗證狀態。系統不直接判定何者為真，而是讓宣稱、依賴、驗證與未嘗試替代方案變得足夠可見，使人類與代理能據此協調。

**Q5：Agora 相較於先前工作的關鍵創新在哪裡？**  
A：Agora 的關鍵創新在於把 Git 當作多個自主研究代理之間的共享記憶體，將每一次實驗、假設、驗證與報告都變成可檢出、可重跑的不可變提交。它把不可變儲存、下游證據與多樣性感知注意力分配拆開，讓圖結構本身成為協調與品質訊號，而非依賴中央規劃者或固定角色流程。這種設計讓沒有共同執行環境、檔案系統或對話歷史的代理，也能透過讀寫同一個 Git 歷史來協作。

**Q6：Agora 有哪些重要的設計選擇？**  
A：首先，採用僅限附加的 DAG，確保研究紀錄不會被覆蓋或竄改，並保留完整的譜系與歸因。其次，使用 Git 作為底層儲存，利用其內容定址與分支能力，讓任何人都能檢出特定提交並重新執行實驗。第三，透過多樣性感知選擇規則來分配運算注意力，避免社群過度追隨單一領先路線而陷入單一文化（monoculture）。

**Q7：論文使用的實驗任務與評估設定是什麼？**  
A：實驗任務是一個權重遷移問題：給定 141 個預訓練捐贈模型（pretrained donor models），以及一個凍結的 1.196 億參數注意力–狀態空間混合模型（attention-SSM hybrid），目標是在沒有訓練資料、也不進行梯度更新的情況下初始化目標模型。評估指標為每位元組位元數（bits per byte, bpb），隨機基線為 3.39，而訓練過的 GPT-2 124M 作為比較基準。13 個語言模型工作程序在將近 12 天內，只憑兩頁簡報、評估器與共享圖譜，自主進行研究。

**Q8：實驗取得了哪些關鍵結果？**  
A：代理們共發布了 1,703 項貢獻，將評估指標從 3.39 bpb 降至 1.899 bpb，縮短了與訓練後 GPT-2 124M 之間 62% 的差距。最終勝出的方法先把捐贈模型的下一個詞元統計資料壓縮到目標模型的嵌入層（embedding）與輸出頭（output head），再透過對注意力、前饋與狀態空間區塊的稀疏編輯加入短程上下文訊號。這個最佳解法的譜系橫跨 15 個帳號、共 145 個提交，並獲得了 165 次獨立重現，且沒有任何一次失敗。

**Q9：論文如何驗證結果與進行消融分析？**  
A：驗證主要來自社群內的獨立重現：其他代理可以檢出任何宣稱的提交並重新執行，165 次重現全部成功，提供了強烈的下游證據。最佳解法的 145 個祖先提交來自 15 個不同帳號，顯示成果並非單一代理的偶然產物，而是集體累積的結果。此外，實驗中只有一次人類介入：當社群陷入長達五天的單一文化時，研究者向代理展示它們自身注意力集中的地圖，社群在一天內便恢復多樣性，這也間接驗證了多樣性感知機制的重要性。

**Q10：Agora 適合哪些實際應用場景？**  
A：Agora 適合需要多個獨立代理長期協作的開放式研究任務，例如大規模機器學習架構搜尋、超參數探索、文獻驅動的研究構想迭代，以及需要高度可重現性的計算科學實驗。任何「工作階段結束後知識不應遺失」的場景，都能受益於其不可變譜系與獨立驗證機制。由於它不依賴中央規劃者，也特別適合地理或組織上分散的研究社群。

**Q11：若要將 Agora 產品化，需要考慮哪些工程與設計因素？**  
A：產品化時需要穩定的 Git 後端來儲存不斷增長的 DAG，以及 SQLite 索引來支援快速搜尋前沿、被忽略分支與驗證狀態。代理必須能夠自動檢出特定提交、重建執行環境並重跑實驗，因此需要搭配容器化或相依性打包工具。此外，多樣性感知選擇規則與單一文化偵測最好能整合進排程器，並保留適度的人類監督介面，以便在必要時進行類似實驗中的人類介入。

**Q12：Agora 可能對 AI 研究領域帶來什麼影響？**  
A：Agora 把多代理 AI 的焦點從「單一對話或任務內的協調」轉向「持久的研究社群與制度設計」，呼應了將代理式 AI 視為社會系統的觀點。它與 AutoResearch、AI Scientist 等端到端自主研究代理互補，專注於提供跨代理、跨回合的耐用記憶體。長遠來看，這種設計有助於加速可重現的開放式發現，並為「機構化 AI」的實作提供一個具體的技術層。

**Q13：作者承認了哪些主要限制？**  
A：作者明確指出，目前只報告了一次持續運行與單一權重遷移任務的結果，尚不足以進行因果推論。實驗並非嚴格的對照比較，因此無法確定「共享研究狀態」本身是否真的提高了單位運算下的發現效率。此外，實驗中出現了一次人類介入，這也意味著目前系統尚未達成完全無人監督的長期自主運作。

**Q14：Agora 可能出現哪些失敗案例或風險？**  
A：實驗本身就出現了長達五天的單一文化：社群過度集中於同一研究方向，直到人類介入才恢復多樣性，顯示若多樣性感知機制不足，系統可能過早收斂。僅限附加的 DAG 會持續增長，可能帶來儲存與檢索成本的挑戰；而被忽略分支的啟發式規則也可能遺漏真正重要的研究方向。此外，驗證仰賴其他代理主動選擇重現，若沒有足夠誘因或注意力分配，某些宣稱可能長期缺乏獨立確認。

**Q15：未來有哪些值得探索的研究方向？**  
A：作者建議進行預先註冊的對照實驗，以確定共享研究狀態是否真能提升單位運算下的發現效率。未來也可擴展到更多代理、更多任務領域，並發展更自動化的獨立驗證與更豐富的宣稱類型（例如理論推導、文獻綜述）。另外，改進多樣性指標、讓單一文化偵測與介入自動化，以及與文獻回顧代理更深度的整合，都是值得持續發展的方向。

## 實務應用指南

## 適用場景

1. **分散式自動化機器學習探索**  
   當團隊想同時跑多個程式設計代理（Coding Agent）來搜尋模型初始化、訓練設定或架構組合時，Agora 可作為共享的實驗日誌。每個代理的嘗試都成為 Git 提交，後續代理能直接檢出（Check Out）最佳前沿（Frontier）並繼續延伸，避免重複搜尋同一條死路。

2. **開放式協作研究專案**  
   適合跨實驗室或開源社群的長期研究：每個結果、負面結果（Negative Results）、驗證與報告都寫成不可變的提交，並透過譜系（Ancestry）保留來源。新成員加入時，只要讀取 DAG 就能掌握目前 frontier、被忽略的分支（Neglected Branches）與各宣稱的驗證狀態（Verification Status）。

3. **多代理程式重構與系統優化**  
   不只是模型訓練，也可用於集體改進大型程式碼庫。例如多個語言模型工作程序（Language-model Workers）各自提出效能優化補丁，透過父邊（Parent Edge）標示「建基於」哪個補丁，並由獨立重現（Reproductions）確認是否真的提升效能。

4. **可重現的基準競賽或排行榜**  
   舉辦長期競賽時，Agora 能讓每個參賽者的提交都附帶完整執行環境與上游依賴。評估器（Evaluator）自動測量指標，社群則可對高分結果進行獨立驗證，降低單一隊伍造假或環境不一致的風險。

5. **機構知識庫與決策紀錄**  
   企業內部可將 Agora 當成研究與決策的共享記憶體（Shared Memory）。每個假設、實驗、驗證與最終報告都成為 DAG 節點，方便日後追蹤「當初為何選這條路線」，並減少人員異動造成的知識流失。

## 實作前置條件

- **資料與問題定義**  
  必須先有一個明確的任務簡報（Brief）、可重現的評估器與統一的指標。例如論文中的權重遷移問題就定義了 bpb、141 個預訓練捐贈模型（Pretrained Donor Models）與凍結目標模型（Frozen Model）。若指標模糊，代理會快速收斂到錯誤的優化目標。

- **運算資源**  
  需要能同時執行多個語言模型工作程序的運算環境，以及執行評估器與重現實驗的算力。論文使用 13 個工作程序跑近 12 天；實際規模可依問題調整，但至少要有能持續執行代理迴圈的機器或容器叢集。

- **Git 倉儲與儲存空間**  
  建立一個中央 Git 倉儲（建議使用 bare repo）作為唯一共享狀態。由於每個提交都包含成品（Artifacts），長期下來倉儲會變大，需規劃儲存空間與大檔案管理策略（例如 Git LFS 或外部內容定址儲存）。

- **索引與查詢資料庫**  
  論文使用 SQLite 建立衍生索引，用來暴露 frontier、neglected branches 與 verification status。實作時需要熟悉 SQL 或選用類似的輕量資料庫，並設計能即時反映 Git DAG 的同步機制。

- **技術能力**  
  團隊需熟悉 Git 操作、Python 或類似腳本語言、容器化（Docker/Singularity）、LLM API 呼叫，以及基本的圖論與多代理系統概念。若沒有這些基礎，建議先從單一 AutoResearch 迴路開始。

## 實作步驟建議

1. **定義任務與評估器**  
   撰寫一頁到兩頁的簡報，說明輸入、輸出、成功指標與限制條件。同時建立一個確定性的評估器，讓任何代理都能對自己的提交取得客觀分數。

2. **建立 Git 共享倉儲與貢獻格式**  
   初始化 bare repo，規範每個提交必須包含：程式碼/設定、執行日誌、指標檔案、簡短宣稱（claim）與父提交清單。使用內容定址（Content-addressed）特性確保提交不可變（Immutable）。

3. **設計 DAG 索引層**  
   用 SQLite 或其他資料庫建立衍生索引，定期從 Git 解析 DAG。索引應至少包含：每個提交的指標、 frontier、neglected branches、驗證狀態，以及多樣性分數。

4. **實作工作程序迴圈**  
   每個 Language-model Worker 的迴圈為：查詢索引 → 選擇 frontier 或 neglected branch → 檢出父提交 → 執行實驗 → 產生新提交 → 推送回共享倉儲。選擇策略需內建多樣性感知注意力分配（Diversity-aware Attention Allocation），避免全部擠向同一條路線。

5. **加入獨立驗證機制**  
   讓部分工作程序專門負責 Reproductions：隨機挑選高分或關鍵提交，重新執行並比對指標。只有通過獨立驗證的宣稱才標記為可信，並影響 frontier 計算。

6. **部署監控儀表板**  
   透過網頁原型或 CLI 視覺化 DAG，讓人類能即時看到社群是否陷入單一文化（Monoculture）。論文中的單次人類介入（Human Intervention）正是透過這張「集中度地圖」讓代理重新分散探索。

7. **持續迭代與收斂**  
   定期檢視 DAG 結構，刪除或標記無效分支，調整多樣性權重與評估器。最終從 DAG 中萃取最佳譜系（Ancestry），形成可發布的方法與報告。

## 潛在風險與注意事項

- **單一文化（Monoculture）**  
  即使有多個代理，若選擇規則過度獎勵當前最高分，所有工作程序會迅速複製同一條路線。應持續監控 DAG 集中度，並保留對 neglected branches 的最低探索配額。

- **評估器被鑽漏洞（Reward Hacking）**  
  代理可能找到提升指標但無意義的捷徑。建議設計多項輔助指標、人工抽查關鍵提交，並要求獨立驗證（Independent Verification）通過後才納入 frontier。

- **Git 倉儲膨脹與效能**  
  每個實驗都產生提交與成品，長期會讓 clone 與索引變慢。可將大型成品外置到物件儲存，只在提交中保留雜湊與中繼資料；並定期壓縮或封存舊分支。

- **安全性：任意程式碼執行**  
  代理會自動檢出並執行他人提交的程式碼，存在惡意或意外破壞風險。應在沙箱容器、權限受限的環境中執行，並對網路與檔案系統存取加以隔離。

- **重現性漂移**  
  即使使用 Git，軟硬體環境、隨機種子或相依套件版本不同都可能導致重現失敗。建議每個提交都附上容器映像檔或 lockfile，並記錄隨機種子。

- **歸因與噪音管理**  
  多代理同時推送可能產生衝突或重複貢獻。需設計清晰的命名規則、帳號（Accounts）識別與重複偵測機制，讓 DAG 保持可讀。

## 與其他技術的整合建議

- **CI/CD 與自動化測試**  
  將 Agora 的 Git 倉儲接到 CI/CD 流程，每次推送自動觸發語法檢查、單元測試與評估器執行，確保只有通過基本門檻的提交才進入 DAG。

- **DVC / DataLad / Git LFS**  
  對於大型模型權重或資料集，不要直接塞進 Git。使用 DVC、DataLad 或 Git LFS 管理大檔，Git 中只保留版本指標與雜湊，兼顧不可變性與儲存效率。

- **MLflow / Weights & Biases**  
  實驗指標可同步寫入 MLflow 或 W&B 進行視覺化，但 Agora 的 Git DAG 仍是唯一權威狀態。資料庫索引與這些工具互補，而非取代 Git。

- **容器化（Docker / Apptainer）**  
  每個提交都應參照一個固定的容器映像檔或 Dockerfile，確保重現時環境一致。可結合 ReproZip 打包執行依賴，進一步提升可重現性。

- **現有 LLM 多代理框架**  
  Agora 不取代 LangGraph、AutoGen、CrewAI 等框架，而是作為它們之間的持久層。單一代理內部可用這些框架規劃任務，但跨代理的狀態透過 Agora 的 DAG 交換。

- **議題追蹤與文件系統**  
  可將 neglected branches 或待驗證宣稱同步到 GitHub Issues / Jira，讓人類研究員能介入指派任務，形成人機混合的研究社群。

建議先聚焦在論文的「為什麼」：理解為何多個代理需要共享記憶體，以及 Git 提交如何變成研究貢獻。可以跳過技術細節，把 Agora 想像成一個「所有人都能看到的實驗日誌」，並試著用單一代理跑出一個簡單的基準任務，再逐步加入第二、第三個代理。

**AI 工程師**  
重點閱讀第 3 節的系統設計與第 4 節的實作細節，特別是 DAG 索引、多樣性感知選擇規則與獨立驗證機制。實作時請優先處理 Git 倉儲效能、容器沙箱安全，以及評估器的確定性；這三項是系統能否穩定跑多天的關鍵。

**研究人員**  
請關注論文對科學機構、集體智慧與多重發現的文獻連結，以及實驗中「單次人類介入打破單一文化」的社會動態。Agora 的價值不只是自動化，而是提供可分析的公開研究軌跡；你可以從 DAG 結構、重現網絡與注意力分配中提煉出新的科學計量學問題。

**產品經理**  
把 Agora 視為一種「可擴展的研究協作基礎建設」。評估是否導入時，請先確認團隊是否有明確的評估指標與可重現的任務；沒有好的評估器，再多代理也只是噪音。建議從一個封閉的內部問題開始試點，驗證 DAG 能否真的減少重複工作、加速收斂，再考慮開放給外部社群。
