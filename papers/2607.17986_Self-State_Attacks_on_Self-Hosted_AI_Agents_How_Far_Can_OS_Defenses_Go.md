## 摘要翻譯

自託管 AI 代理（self-hosted AI agents）會讀寫自身的記憶檔案（memory files）與組態檔案（configuration files）以運作。代理可能因自身狀態遭受破壞而被入侵——此種入侵是透過合法的作業系統系統呼叫（OS system call）來實現。我們將這類威脅稱為自我狀態攻擊（self-state attacks）。本文探討作業系統（OS）對此類攻擊的韌性。形式上，我們刻畫一個四軸攻擊空間（attack space）（目標（Target）、機制（Mechanism）、粒度（Granularity）、時間維度（Temporal））；探討預防（prevention）、偵測（detection）與復原（recovery）的結構性限制；並提出工作負載條件化可偵測性（workload-conditioned detectability）的觀點。為了具體化此框架，我們從一個具代表性的自託管代理在不同工作負載設定檔（workload profiles）下運行時，收集即時活動追蹤（live activity traces），並將攻擊空間實現為一個 23 格的矩陣、43 項針對真實自我狀態檔案（self-state files）的具體操作，再將這些操作注入追蹤中。接著我們評估典型與工作負載條件化的防禦策略。實證結果顯示，分層防禦堆疊（layered defense stack）（在指令層（instruction layer）與組態層（configuration layer）實施存取控制預防（access-control prevention）、在記憶層（memory layer）實施工作負載條件化偵測，並以定期備份（periodic backup）進行復原）對大多數攻擊單元有效，但仍有一小部分殘留攻擊面（residual attack surface）在作業系統層級（OS level）屬結構上不可區分（structurally indistinguishable）。這些發現指出，面對新確立的自我狀態攻擊類別，作業系統層級防禦（OS-level defense）需要重新審視，並可能為該領域開啟新的研究方向。

### 核心貢獻（3～5點）
- 確立「自我狀態攻擊（self-state attacks）」為針對自託管 AI 代理的新興威脅類別，並說明其可透過合法的作業系統系統呼叫達成。
- 形式化一個四軸攻擊空間（attack space）（目標 Target、機制 Mechanism、粒度 Granularity、時間維度 Temporal），以系統化地分類與分析此類攻擊。
- 深入探討預防（prevention）、偵測（detection）與復原（recovery）在結構上的限制，並提出「工作負載條件化可偵測性（workload-conditioned detectability）」作為新的偵測視角。
- 透過真實自託管代理的即時活動追蹤，將攻擊空間具體化為 23 個攻擊單元與 43 項實際操作，並評估典型與工作負載條件化防禦策略的成效。
- 提出並驗證分層防禦堆疊（layered defense stack）的有效性，同時指出仍有小部分殘留攻擊面（residual attack surface）在作業系統層級屬結構上不可區分。

### 適合對象
本論文適合作業系統安全、AI 代理安全與系統防禦領域的研究人員與工程師閱讀；對於部署或開發自託管 AI 代理（如 Claude Code、OpenClaw 等工具）的資安實務工作者、系統管理員，以及關注代理計算（agentic computing）新興攻擊面的學術與產業讀者，亦具高度參考價值。

## 深度分析

#### 方法論解析

本研究的核心方法論是將 self-hosted AI agents（自託管 AI 代理）的持久狀態（persistent state）視為一個與傳統跨邊界攻擊截然不同的威脅表面。自託管代理為了運作，必須持續讀寫本地的 memory files（記憶檔案）、identity documents（身份文件）與 configuration files（組態檔案），這些檔案共同構成其 self-state（自我狀態）。由於代理本身必須修改這些行為決策相關的檔案，它們永久位於代理自己的 write set（寫入集合）內，而非任何沙箱或唯讀區域。這種「自我可變性」是產品需求，而非實作細節，因此一旦攻擊者透過 indirect prompt injection（間接提示注入）等方式操控代理的 decision process（決策過程），後續的狀態破壞就會經由 legitimate write paths（合法寫入路徑）完成，表現為完全合法的 OS system call（系統呼叫），例如 write、rename、unlink 或 mode change。

作者用形式化方式區分兩類攻擊：cross-boundary attacks（跨邊界攻擊）滿足 \(A(R) \not\subseteq L(R)\)，即攻擊操作超出合法操作集合，因此傳統 OS isolation（作業系統隔離，如 sandbox、seccomp、netns）可以阻擋；而 self-state attacks（自我狀態攻擊）滿足 \(A(R) \subseteq L(R)\)，攻擊與合法寫入在 VFS 層收斂為相同的節點操作，OS 無法單純透過結構比對區分兩者。這正是 confused deputy problem（混淆代理人問題）在 LLM 代理情境下的放大版本：一個具特權的元件被誘騙濫用其既有權限。

為了系統化研究，作者提出四軸 attack space（攻擊空間）：Target（目標）、Mechanism（機制）、Granularity（粒度）與 Temporal（時間維度）。Target 對應 self-state 的不同層次，例如 instruction layer（指令層）、configuration layer（組態層）與 memory layer（記憶層）；Mechanism 涵蓋檔案內容覆寫、重新命名、刪除、權限變更等具體系統呼叫；Granularity 區分整檔、區塊或位元組層級的修改；Temporal 則描述攻擊是即時發生或延遲生效。透過這四軸的組合，作者將攻擊空間實例化為一個 23-cell matrix（23 格矩陣），並設計 43 個 concrete operations（具體操作）作用於真實的 self-state files（自我狀態檔案）上。

在防禦方法論上，作者從 prevention（預防）、detection（偵測）、recovery（復原）三個維度分析其結構性極限：prevention 無法區分同一檔案上的合法與攻擊寫入；detection 無法從系統呼叫推論語意上的惡意意圖；recovery 以 detection 為前提，並需付出與 backup interval（備份間隔）成正比的資料遺失成本。為了突破傳統 anomaly detection（異常偵測）的限制，作者提出 workload-conditioned detectability（工作負載條件化可偵測性）的觀點，即偵測能力應以不同 workload profiles（工作負載設定檔）為條件進行評估，而非使用單一全域基線。最終，作者建構一個 layered defense stack（分層防禦堆疊）：在 instruction layer 與 configuration layer 使用 access-control prevention（存取控制預防），在 memory layer 使用 workload-conditioned detection，並以 periodic backup（定期備份）作為 recovery 機制。

#### 實驗數據解讀

為了實例化上述框架，作者從一個具代表性的 self-hosted agent（自託管代理）在不同 workload profiles（工作負載設定檔）下收集 live activity traces（即時活動追蹤），並將 43 個 concrete operations（具體操作）注入這些追蹤中，形成一個 23-cell matrix（23 格矩陣）的攻擊實例集合。這樣的設計讓實驗能夠同時評估 canonical defense strategies（典型防禦策略）與 workload-conditioned defense strategies（工作負載條件化防禦策略）在真實系統呼叫序列上的表現。

實驗結果顯示，所提出的 layered defense stack（分層防禦堆疊）在大多數 attack cells（攻擊格）上有效，但仍存在一小部分 residual attack surface（殘留攻擊面）在 OS level（作業系統層級）是 structurally indistinguishable（結構上不可區分）的。這個結果可以從三個層次解讀：

1. **Instruction layer 與 Configuration layer 的 prevention 效果較佳**：這兩層的檔案通常具有較穩定的存取模式，例如組態檔只在初始化或明確更新時被寫入，指令檔的內容變動頻率低且來源可控。因此 access-control prevention（存取控制預防）可以透過限制寫入主體、時間或上下文來阻擋大部分攻擊。

2. **Memory layer 需要 workload-conditioned detection**：記憶檔案會被代理頻繁讀寫，其內容變化高度依賴當前對話與任務語境。若使用單一全域異常基線，容易產生大量誤報；但若以 workload profiles（工作負載設定檔）為條件，則可以將「在特定任務下應該出現的寫入行為」與「異常寫入行為」區分開來，顯著提升偵測率。

3. **Recovery 受 detection 與備份間隔雙重限制**：periodic backup（定期備份）只能在攻擊被偵測到後將狀態回復到最近一次乾淨備份。若攻擊發生於兩次備份之間且未被偵測，則回復會造成與備份間隔成正比的資料遺失。這也說明了為何 recovery 無法單獨作為主要防線。

殘留攻擊面的存在具有重要意義：它代表任何僅依賴 OS-level defense（作業系統層級防禦）的方案都無法完全消除自我狀態攻擊。當攻擊者完全模仿合法工作負載的寫入模式——包括目標檔案、寫入大小、時間間隔與系統呼叫類型——OS 層無法區分其惡意意圖。

#### 與現有研究的比較

現有的 AI agent security（AI 代理安全）研究大多集中在 semantic layer（語意層），例如 LLM-as-judge（LLM 作為裁判）或 guard agents（守護代理），在動作執行前檢查其是否惡意。這類 semantic defenses（語意防禦）雖然不可或缺，但本質上是機率性的：它們與攻擊者處於同一個開放式自然語言空間，攻擊者可以透過間接表達、改寫或語境重構來規避。adaptive attacks（適應性攻擊）持續利用這個缺口，使得單純依賴語意層防禦難以提供確定性保證。

相較之下，OS 是任何 self-state corruption（自我狀態破壞）提交到磁碟前最後一個確定性的執行點，因為所有狀態變更最終都會轉換為具體的 system call（系統呼叫）。然而，過去對於 self-hosted agents（自託管代理）的 OS defenses（作業系統防禦）缺乏系統性研究。傳統 OS isolation（作業系統隔離）對於 cross-boundary attacks（跨邊界攻擊）非常有效，因為這類攻擊會觸及代理範圍外的資源；但對於 self-state attacks（自我狀態攻擊），由於攻擊操作完全落在合法寫入集合內，傳統隔離機制會失效。

本研究的主要貢獻在於首次提出一個形式化的攻擊空間、明確界定 OS 層防禦的結構性極限，並透過實證評估驗證 layered defense stack（分層防禦堆疊）的有效性。其限制也同樣明顯：OS-level defense（作業系統層級防禦）無法處理語意層的惡意意圖，也無法消除所有殘留攻擊面；此外，實驗僅針對一個代表性代理與若干工作負載設定檔，結果是否能推廣到 Claude Code、OpenClaw 以外的架構，仍需更多驗證。

#### 可重現性評估

根據目前提供的全文脈絡，作者並未明確提及公開釋出原始碼、資料集或模型權重。因此，從可重現性角度來看，本研究屬於「方法論與實驗設計描述完整，但實作 artifact 尚未公開」的類型。要獨立重現這項研究，至少需要以下元件：

- 與文中類似的 self-hosted agent（自託管代理）實作，例如基於 OpenClaw 或 Claude Code 架構的代理；
- 不同 workload profiles（工作負載設定檔）的腳本與輸入資料；
- live activity traces（即時活動追蹤）的收集機制，包括 system call（系統呼叫）擷取與檔案層級事件記錄；
- 43 個 concrete operations（具體操作）的攻擊注入程式；
- access-control prevention（存取控制預防）、workload-conditioned detection（工作負載條件化偵測）與 periodic backup（定期備份）的防禦實作；
- 明確的評估指標與統計方法。

由於 live activity traces（即時活動追蹤）可能包含使用者敏感資訊或私有工作流，公開完整追蹤資料會有隱私疑慮。建議作者未來可釋出「去識別化後的追蹤樣本、攻擊操作規格、防禦配置檔與評估腳本」，以在保護隱私的同時提升可重現性。若這些 artifact 能夠公開，將有助於社群驗證 23-cell matrix（23 格矩陣）與 43 個操作的覆蓋完整性，並比較不同防禦策略在更多代理架構上的表現。

#### 未來研究方向

1. **語意層與 OS 層的混合防禦**：將 LLM-as-judge（LLM 作為裁判）或 guard agents（守護代理）與 system call（系統呼叫）監控結合，讓語意層負責意圖判斷，OS 層負責確保任何狀態變更都可被追蹤與回滾。

2. **細緻化的自我狀態完整性保護**：針對 memory files（記憶檔案）設計 append-only（僅附加）日誌、針對 configuration files（組態檔案）使用不可變快照或版本控制，並透過加密雜湊鏈偵測未授權修改。

3. **適應性工作負載條件化偵測**：發展能夠在線學習的 workload-conditioned detection（工作負載條件化偵測），自動隨著代理行為演進調整基線，並結合因果推論或語意特徵，降低誤報率。

4. **時間維度上的長期一致性檢查**：針對 Temporal（時間維度）設計 state drift detection（狀態漂移偵測），識別代理決策行為在長期互動中是否逐漸偏離原始目標，以捕捉延遲生效的攻擊。

5. **政策導向的存取控制**：為 self-state files（自我狀態檔案）建立 formal policy（形式化政策），規定哪些主體、在何種語境下、以何種粒度可以修改哪些狀態層，並透過 provenance tracking（來源追蹤）強制執行。

6. **使用者介入機制**：對於 instruction layer（指令層）與 configuration layer（組態層）的高風險變更，引入 user-in-the-loop（使用者在環）確認，作為 OS 層無法區分時的最後防線。

7. **標準化評測基準**：建立開放的 self-state attacks（自我狀態攻擊）資料集與評測框架，涵蓋多種 self-hosted agents（自託管代理）與 workload profiles（工作負載設定檔），讓不同防禦方案能夠公平比較。

8. **超越週期性備份的復原機制**：研究 continuous replication（持續複寫）、differential backup（差異備份）或 semantic merge（語意合併）技術，在偵測到攻擊後以最小資料遺失恢復代理狀態。

9. **硬體輔助隔離的可行性**：探討 TEE（Trusted Execution Environment，可信執行環境）等硬體機制是否能在不違反代理自我可變性需求的前提下，將狀態修改與決策邏輯分離，以降低 residual attack surface（殘留攻擊面）。

## 論文問答

**Q1：什麼是自我狀態攻擊，它為何構成一個獨立的威脅類別？**

A：自我狀態攻擊指的是攻擊者透過誘導自託管 AI 代理，使其利用合法的作業系統系統呼叫來竄改自己的記憶檔案、身份文件或組態檔案，進而破壞代理的持久狀態。這類攻擊之所以獨特，是因為惡意寫入與代理正常運作所需的合法寫入在虛擬檔案系統層看起來完全相同，傳統的作業系統隔離機制難以區分兩者。由於代理必須持續讀寫自身狀態才能學習與適應，這種「自我可變性」成為產品需求，卻也同時成為攻擊者可濫用的通道。

**Q2：現有的語義層防禦為何無法單獨有效阻止自我狀態攻擊？**

A：現有方法如 LLM-as-judge 或守衛代理主要在自然語言語義空間中判斷意圖，但這個空間與攻擊者使用的空間相同，具有開放性與高度可繞過性。間接提示注入、語意轉述或情境重構等手法，能讓惡意指令以看似無害的方式通過語義檢查，導致這類防禦本質上是機率性的。因此，作業系統作為最後一個確定性執行點，成為補強語義防禦、在資料寫入磁碟前攔截異常的必要層級。

**Q3：為何作業系統層級防禦對自託管 AI 代理特別重要？**

A：自託管代理直接在使用者機器上執行，需要完整的 shell 與檔案系統權限來處理私人程式碼、機密文件或個人工作流程，這是雲端沙箱無法滿足的需求。每一次自我狀態的竄改最終都必須透過具體的系統呼叫完成，例如寫入、重新命名、刪除或權限變更，而作業系統能觀察到這些呼叫。正因為作業系統位於資料提交到磁碟前的最後一道關卡，它提供了結構上確定的攔截與記錄機會，是保護代理持久狀態不可或缺的防線。

**Q4：本文提出的四維度攻擊空間如何結構化自我狀態攻擊問題？**

A：作者以目標、機制、粒度與時間四個軸線刻畫攻擊空間，其中目標區分記憶層、指令層與組態層等自我狀態組件，機制涵蓋寫入、附加、刪除、權限變更等不同操作方式，粒度與時間則進一步描述攻擊影響的範圍與發生時機。透過這個框架，研究團隊將攻擊空間具體化為一個包含 23 個單元的矩陣，並對應設計出 43 個針對真實自我狀態檔案的具體操作。這種結構化方法讓防禦評估能夠系統性地覆蓋不同攻擊變體，而不僅僅停留在概念性討論。

**Q5：什麼是工作負載條件化可偵測性，為何對偵測自我狀態攻擊至關重要？**

A：工作負載條件化可偵測性是指某個系統呼叫或檔案操作是否異常，必須視代理當前所處的工作負載情境而定，而非僅用全域統計規則判斷。同樣的記憶檔案寫入行為，在某一工作負載下可能是正常學習更新，在另一工作負載下卻可能是惡意竄改，傳統的異常偵測若忽略此差異容易產生誤判。本文將此觀點應用於記憶層偵測，證明結合工作負載設定檔能顯著提升偵測準確度，並降低誤報與漏報。

**Q6：預防、偵測與復原這三種防禦維度各自存在哪些結構性限制？**

A：預防機制無法區分針對同一檔案的合法寫入與攻擊寫入，因為兩者在作業系統層產生相同的虛擬檔案系統操作；偵測機制只能觀察到系統呼叫的結構特徵，無法直接推斷背後的語意意圖是否有害；復原機制則以偵測為前提，並且必須付出與備份間隔成正比的資料遺失成本。這三項限制共同說明，單靠作業系統層無法完全消除自我狀態攻擊，必須採取分層且互補的防禦策略。

**Q7：實驗是如何設計與執行的？**

A：研究團隊先從一個具代表性的自託管代理在不同工作負載設定檔下收集即時活動追蹤，建立真實的系統呼叫與檔案操作基線。接著，他們將 43 個針對真實自我狀態檔案的具體攻擊操作注入這些追蹤中，形成可重複的評估資料集。最後，作者同時評估傳統的典範偵測方法與本文提出的工作負載條件化偵測方法，並比較各種防禦組合在不同攻擊單元上的效果。

**Q8：本文的主要實證結果是什麼？**

A：實證結果顯示，一個分層防禦堆疊能夠在大多數攻擊單元上發揮效用：在指令層與組態層使用存取控制預防，在記憶層使用工作負載條件化偵測，並輔以定期備份進行復原。這種組合對絕大多數自我狀態攻擊變體都有效，能顯著降低成功攻擊的機率。然而，仍有少數殘留攻擊面在作業系統層結構上不可區分，意味著部分攻擊無法僅靠作業系統機制偵測或阻止。

**Q9：實驗中有哪些類似消融研究的比較，說明了什麼？**

A：作者比較了單純的典範異常偵測與工作負載條件化偵測，結果顯示後者在記憶層能更準確地辨識出與當前工作負載不符的寫入行為。此外，實驗也證明單獨使用預防或單獨使用偵測都無法覆蓋所有攻擊單元，必須將存取控制、條件化偵測與定期備份結合。這些比較凸顯了分層防禦的必要性，並量化各層對整體防禦效果的貢獻。

**Q10：自我狀態攻擊在哪些實際場景中特別值得關注？**

A：這類攻擊對於 Claude Code、OpenClaw 等直接存取本機程式碼庫的程式開發助理尤其危險，因為攻擊者可透過間接提示注入竄改代理的記憶或目標設定。在企業環境中，處理機密文件或內部工作流程的代理若被篡改，可能持續做出錯誤決策或洩漏敏感資訊。個人使用者場景亦然，例如管理電子郵件、健康紀錄或財務資料的自託管代理，一旦狀態被污染，後果可能長期且難以察覺。

**Q11：產品開發與部署時應如何考量自我狀態攻擊的防禦？**

A：產品設計應將指令層與組態層的檔案納入嚴格的存取控制，限制代理只能在必要時以最小權限修改這些檔案。記憶層則建議部署工作負載條件化監控，根據不同使用情境動態調整異常判斷閾值，並搭配定期備份以縮短復原時的資料遺失窗口。由於作業系統層無法消滅所有殘留風險，產品仍須保留語義層守衛或使用者確認機制作為最後一道防線。

**Q12：這項研究對 AI 代理安全領域可能帶來什麼影響？**

A：本文首次系統性地將自我狀態攻擊界定為獨立威脅類別，並量化作業系統防禦能達到與無法達到的邊界，為後續研究提供了清晰的問題框架。它提醒學界與產業，單靠語義層或單靠作業系統層都不足以保護自託管代理，必須發展跨層協同的防禦架構。這項工作也開啟了代理計算安全的新研究方向，例如設計代理感知的檔案系統、狀態變更溯源機制，以及結合確定性與機率性防禦的混合系統。

**Q13：本文承認哪些主要限制？**

A：作者明確指出，仍有小部分攻擊面在作業系統層是結構上不可區分的，因為這些攻擊完全模仿合法寫入路徑與系統呼叫模式。此外，工作負載條件化偵測的效果受限於訓練或收集到的工作負載覆蓋範圍，若出現未見過的使用情境，偵測準確度可能下降。復原機制也無法做到零損失，備份間隔越長，攻擊發生後可復原的資料就越少。

**Q14：哪些情況下現有防禦可能會失效？**

A：當攻擊者精心設計的寫入模式與當前工作負載中的正常更新完全一致時，工作負載條件化偵測可能無法察覺異常。若攻擊只進行極細粒度的語意竄改，例如修改記憶檔案中的特定詞句而不改變檔案大小或寫入頻率，作業系統層也難以辨識。此外，攻擊若發生在正常備份週期之間並迅速自我掩蓋，定期備份復原可能無法回復到未被污染的狀態。

**Q15：未來研究可以朝哪些方向發展？**

A：未來可探索將作業系統層觀測與語義層 LLM-as-judge 深度整合，讓系統在偵測到可疑狀態變更時觸發語意層的二次審查。另一方向是設計代理感知的檔案系統或不可變的審計日誌，以記錄狀態變更的因果關係與決策依據，提升溯源與復原能力。此外，針對殘留攻擊面，可研究關鍵狀態變更的使用者確認機制、形式化驗證代理狀態轉換，以及更細緻的應用層存取政策，以彌補作業系統層的結構性限制。

## 實務應用指南

## 適用場景

**企業內部程式碼助手部署**：當組織將 Claude Code 或類似自託管 AI 代理部署於開發者工作站時，代理持續讀寫記憶檔案、身份文件與組態檔案。本指南適用於建立作業系統層級防禦，防止間接提示注入透過合法寫入路徑腐蝕代理持久狀態。

**個人生產力代理**：處理電子郵件、行事曆、健康紀錄與本地工作流程的個人 AI 代理，其記憶層與組態層位於使用者可寫入區域。本框架可協助識別哪些自我狀態攻擊可由作業系統偵測或預防。

**自動化工作流程代理**：長時間執行、持續學習並調整偏好的自主代理，會頻繁覆寫記憶檔案。此場景下時間維度攻擊（如緩慢污染記憶）特別難以偵測，需要工作負載條件化可偵測性分析。

**多使用者共享代理伺服器**：當單一代理實例服務多個使用者或專案時，不同工作負載設定檔交錯，合法寫入集合擴大，傳統異常偵測誤報率上升，需採用本文的分層防禦堆疊。

**邊緣裝置上的自主代理**：資源受限裝置運行自架式代理，無法依賴雲端安全服務，必須在本地作業系統層實作輕量級預防、偵測與復原機制。

## 實作前置條件

**資料需求**：需收集代理在正常運作下的即時活動追蹤，包含所有針對自我狀態檔案的系統呼叫（如 open、write、rename、unlink、chmod）。同時需要完整盤點記憶檔案、身份文件與組態檔案的位置、格式與更新頻率，並定義數個具代表性的工作負載設定檔。

**運算需求**：核心分析可在一般伺服器或工作站上執行，無需 GPU。但需要足夠儲存空間保存追蹤資料與定期備份，以及執行 eBPF 或 auditd 等系統呼叫監控框架的權限。若進行大規模工作負載條件化建模，則需要日誌分析與異常偵測的運算資源。

**技能需求**：團隊需具備作業系統安全知識（檔案系統權限、強制存取控制、系統呼叫追蹤）、代理內部運作理解（記憶如何更新、組態如何解析），以及基礎資料分析能力以建立工作負載基線。若整合 LLM-as-judge 等語義層防禦，則需要提示工程與模型評估經驗。

## 實作步驟建議

**步驟一：盤點自我狀態資產**：識別所有屬於代理持久狀態的檔案，區分記憶層、指令層與組態層。記錄每個檔案的合法寫入集合，包括哪些程序、在何種工作負載下、以何種粒度進行更新。

**步驟二：建立工作負載基線**：在數個代表性的工作負載設定檔下收集即時活動追蹤，涵蓋日常對話、程式碼編輯、長期專案學習等情境。從追蹤中提取每個自我狀態檔案的寫入頻率、位元組範圍、時間分佈與內容特徵。

**步驟三：建構攻擊空間矩陣**：依據目標（Target）、機制（Mechanism）、粒度（Granularity）、時間維度（Temporal）四軸，列出所有可能的自我狀態攻擊實例。將每個攻擊對應到具體的系統呼叫操作，並評估其在作業系統層是否結構上不可區分。

**步驟四：部署分層防禦堆疊**：在指令層與組態層實作存取控制預防，限制非預期程序或使用者修改關鍵檔案；在記憶層部署工作負載條件化偵測，比對當前寫入行為與基線；全層實作定期備份以支援復原。

**步驟五：驗證殘留攻擊面**：針對無法被作業系統區分的攻擊細胞，標記為殘留攻擊面，並補強語義層防禦（如 LLM-as-judge 或守衛代理）。持續根據新工作負載更新基線，避免基線漂移導致誤判。

## 潛在風險與注意事項

**誤報與誤判風險**：工作負載條件化偵測依賴基線準確性。若代理行為演化或使用者切換新任務，基線可能過時，導致合法寫入被標記為異常。建議定期重新訓練基線，並保留人工覆核機制。

**備份窗口資料遺失**：定期備份無法復原最近一次備份後發生的合法更新。備份間隔越長，潛在資料遺失越大。對於高頻更新的記憶檔案，需權衡復原能力與資料新鮮度。

**結構上不可區分的限制**：當攻擊操作與合法操作收斂為相同的虛擬檔案系統寫入時，作業系統層級防禦無法單獨判斷意圖。此時必須承認殘留攻擊面存在，並輔以語義層或人機協同審查。

**效能開銷**：系統呼叫追蹤、存取控制檢查與即時異常分析會增加代理回應延遲。在資源受限環境中，應採用取樣或輕量級 eBPF 程式，避免影響使用者體驗。

**過度依賴單一防禦層**：僅靠預防、偵測或復原任一層都不足以覆蓋所有攻擊細胞。必須將三種策略視為互補機制，並明確記錄每個攻擊細胞由哪一層負責處理。

## 與其他技術的整合建議

**eBPF 與系統呼叫監控**：使用 eBPF 程式擷取針對自我狀態檔案的即時活動追蹤，具備低開銷與高解析度優勢。可將追蹤資料餵入工作負載條件化偵測模型，實現記憶層異常偵測。

**強制存取控制（MAC）**：透過 SELinux 或 AppArmor 限制代理程序對指令層與組態層檔案的寫入集合，將存取控制預防落實到作業系統層。特別適合防止跨邊界攻擊與非預期程序修改關鍵狀態。

**備份與版本控制系統**：將定期備份與現有備份基礎設施整合，並對組態檔案使用版本控制。如此可在偵測到狀態腐蝕後快速回滾，同時保留變更歷史以進行事件調查。

**LLM-as-judge 與守衛代理**：對於作業系統層無法區分的攻擊，整合語義層防禦作為最後一道閘門。由獨立模型審查即將執行的寫入操作內容，判斷是否存在惡意意圖。

**SIEM / SOAR 平台**：將偵測結果與企業安全資訊和事件管理系統整合，統一呈現自我狀態攻擊警報，並自動化隔離、備份回滾與事件通報流程。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從「自我狀態攻擊」的核心概念入手，理解為何代理寫入自己的記憶檔案會成為攻擊管道，以及為什麼作業系統無法單純透過權限控管解決問題。可略過形式化符號，專注於圖一所示的跨邊界攻擊與自我狀態攻擊對比，以及最後提出的分層防禦堆疊。

**AI 工程師**：請重點閱讀攻擊空間的四維度模型與 23 個攻擊細胞的實例化方式，思考如何將這些細胞對應到您所開發或部署的代理架構。特別關注工作負載條件化可偵測性，因為它直接影響如何在實際產品中降低誤報並提升偵測覆蓋率。

**研究人員**：本文的結構性限制分析值得深入探討，包括預防、偵測、復原三個維度各自的理論邊界。建議將殘留攻擊面作為未來研究方向，例如結合形式化驗證、語義不變量或人機迴路機制，進一步縮小結構上不可區分的攻擊集合。

**產品經理**：請將本文視為風險評估與產品設計的參考框架。重點在於理解哪些攻擊可由作業系統層級防禦覆蓋、哪些必須仰賴語義層或人為介入，並據此規劃安全功能優先順序、使用者體驗取捨與合規敘事。
