# CausalDS：資料科學代理中的因果推理基準測試

## ⚡ TL;DR

現有基準測試多割裂符號因果與資料分析，且易淪為因果鸚鵡。
本文提出 CausalDS，合成 SCM 場景與觀察資料，涵蓋三層因果任務及棄權機制。
評估顯示當代代理在五項能力上表現不一，難以單一維度衡量。

## 摘要翻譯

大型語言模型（LLM）日益扮演整合式資料科學代理（integrated data-science agents）的角色，結合抽象推理（abstract reasoning）與進階工具使用（advanced tool use）。然而，相關的基準測試格局（benchmark landscape）大致可區分為兩類：缺乏真實資料分析（realistic data analysis）的符號因果推理基準測試（symbolic causal reasoning benchmarks），以及缺乏原則性因果資料生成結構（principled causal data-generating structure）的資料分析基準測試（data analysis benchmarks）。此外，現有的因果評估資料集通常受限於取自現有來源的精選範例（curated examples），其多樣性僅來自有限的模板化變體（templatized variations），而非新穎合成因果結構（novel synthetic causal structures）的系統性生成（systematic generation）。本文提出 CausalDS，一個用於評估代理式資料科學工作流程（agentic data-science workflows）中因果推理（causal reasoning）的基準測試（benchmark）。每個基準測試實例（benchmark instance）都是一個場景（scene），由一個抽樣的結構因果模型（SCM）、生成的觀測資料（observational data），以及一個基於真實領域（realistic domain）的附帶合成自然語言故事（synthetic natural-language story）所組成。我們可選擇將各基準測試組件的組成奠基於從真實世界資料集（real-world datasets）取得的實證分布（empirical distributions），從而在保留實證結構（empirical structure）的同時，透過完全合成生成（completely synthetic generation）降低「因果鸚鵡」風險（causal parrot risk）。我們從每個場景衍生出涵蓋皮爾的因果階梯（Pearl's rungs）全部三層的任務，其中典型的資料科學預測任務（prediction tasks）對應至第一層（Rung 1）。大多數任務包含資料科學程式編寫組件（data-science coding component），由於觀測模型（observation model）經常產生不完美觀測（imperfect observations），模型通常需要使用多個工具才能得出最終答案。此外，當問題缺乏有依據的答案（warranted answer）時能夠識別並選擇棄權（abstention），被視為一項正式計分結果（first-class scored outcome）。因此，本基準測試聯合評估（jointly evaluates）符號因果推理、資料科學、不確定性量化（uncertainty quantification）、棄權，以及工具使用／程式編寫（tool use/coding）。

### 核心貢獻（3～5點）
- 提出 CausalDS，首個針對代理式資料科學工作流程中因果推理的綜合基準測試，彌補現有符號因果推理基準測試與資料分析基準測試之間的鴻溝。
- 每個基準測試實例均為一個場景，包含抽樣的結構因果模型（SCM）、生成的觀測資料，以及基於真實領域的合成自然語言故事。
- 可選擇將場景組件奠基於真實世界資料集的實證分布，在保留實證結構的同時，透過完全合成生成降低「因果鸚鵡」風險。
- 從每個場景衍生涵蓋皮爾因果階梯全部三層的任務，並將典型資料科學預測任務對應至第一層（Rung 1）。
- 將棄權機制視為正式計分結果，聯合評估符號因果推理、資料科學執行、不確定性量化、棄權判斷與工具使用／程式編寫能力。

### 適合對象
本論文適合從事大型語言模型代理、自動化資料科學、因果推論與基準測試設計的研究人員與實務工作者；特別是關注如何評估 AI 系統在貼近真實資料分析情境下進行因果推理、不確定性量化與適當棄權的讀者。對於欲建構或改進結合符號推理與程式編寫工具之代理式系統的開發者亦具高度參考價值。

## 深度分析

#### 方法論解析

CausalDS（因果資料科學基準測試）的核心設計是將「隱藏的因果資料生成結構（causal data-generating structure）」與「代理式資料科學工作流程（agentic data-science workflow）」結合，形成一個可重複生成、可確定評分的場景（scene）導向基準測試（benchmark）。其方法論可拆解為以下環節：

1. **場景生成：以 Structural Causal Model（結構因果模型，SCM）為中心**
   每個 benchmark instance（基準測試實例）都是一個 scene，內部包含：
   - 一個隨機採樣的有向無環圖（Directed Acyclic Graph，DAG）作為因果圖形結構（graph structure）。
   - 在 DAG 上為每個節點指定結構方程式 \(V_i = f_i(\mathrm{Pa}_i, U_i)\)，其中 \(\mathrm{Pa}_i\) 為圖形上的父節點，\(U_i\) 為外生擾動項；這些機制（mechanism）與擾動項的聯合分布共同誘導出觀察分布 \(P(V)\)（Pearl et al., 2021）。
   - 由此生成觀測資料（observational data），並私下保留由 SCM 計算而來的 ground truth（真實值），用於後續確定性評分。

2. **經驗錨定（empirical anchoring）與完全合成生成**
   為了兼顧真實性與避免「因果鸚鵡（causal parrot）」風險，CausalDS 在場景組成上可選擇性地依據真實世界資料集（real-world dataset）所估計的實證分布（empirical distribution）進行錨定。具體而言，生成器會沿著變數類型（variable type）、圖形結構、可識別性（identifiability）、機制輪廓（mechanism profile）與觀測複雜度（observation complexity）等軸向進行經驗校準；但實際的 SCM、資料與故事仍為完全合成生成（completely synthetic generation）。這樣既能保留實證結構（empirical structure），又能確保模型無法透過記憶既有範例來作答。

3. **圖形忠實的自然語言故事化（graph-faithful verbalization）**
   抽象圖節點會被映射到連貫的領域變數，部分變數名稱與語義種子來自 CauseNet（Heindorf et al., 2020）。接著系統生成合成自然語言故事（synthetic natural-language story），描述該因果情境（causal scenario）。這個映射與最終故事會經過稽核，確認其與隱藏圖形結構及整體敘事一致性相符，因此能同時具備真實領域（realistic domain）的語言質感與受控的因果結構。

4. **觀測層分離：引入觀測模型（observation model）**
   CausalDS 刻意將概念上的 SCM 變數與釋放給代理的資料視圖（data view）分離。除了乾淨觀測外，系統可將概念變數替換為帶雜訊的觀測變數組合，產生不完美觀測（imperfect observation）。這讓基準測試能夠獨立調控資料科學難度（例如遺漏變數、測量誤差、代理變數），而不改變底層因果問題的可識別性（identifiability）或目標因果估計量（target causal estimand）。

5. **跨 Pearl 因果階梯（Pearl’s rungs）的任務設計**
   從每個 scene 可衍生出涵蓋三層因果推理的任務：
   - **Rung 1（第一層）**：關聯性目標（associational target），包含典型資料科學預測任務（prediction task），如以表格資料（tabular data）進行預測。
   - **Rung 2（第二層）**：介入性目標（interventional target），例如估計 \(P(Y \mid do(X=x))\)、進行效果估計（effect estimation）與識別性診斷（identification）。
   - **Rung 3（第三層）**：反事實目標（counterfactual target），涉及平行世界比較與反事實推理。
   此外還包含圖形恢復（graph recovery）、偏差診斷（bias diagnostics）等任務。由於這些任務共享同一個隱藏 SCM，它們能夠串連語言理解、統計估計與形式因果推理。

6. **資料科學程式編寫組件（data-science coding component）與工具使用**
   多數任務要求模型在具備檔案系統的代理環境中撰寫程式碼，使用標準分析工具（standard analysis tool）處理表格資料。由於不完美觀測普遍存在，模型通常需要組合多種工具（tool use）才能得出最終答案，這同時評估了其程式編寫（coding）能力與多步驟推理能力。

7. **棄權（abstention）作為正式計分結果**
   CausalDS 將「認識性棄權（epistemic abstention）」視為 first-class scored outcome（正式計分結果）。當題目所問的因果宣稱無法由釋放的資料與假設所保證時，正確行為是拒絕回答（decline to answer）而非強行給出數值。這要求模型具備不確定性量化（uncertainty quantification）與可識別性判斷能力。

整體而言，CausalDS 的方法論創新在於把「符號因果推理（symbolic causal reasoning）」、「資料科學執行（data-science execution）」、「不確定性量化（uncertainty quantification）」、「認識性棄權（epistemic abstention）」與「工具使用／程式編寫（tool use / coding）」五個軸向整合進同一個可重複、可確定評分的框架中。

#### 實驗數據解讀

由於目前提供的全文片段未包含完整的數值表格，本節先從評量設計與已報告的質性發現進行解讀。

1. **評量軸向的分離現象**
   作者指出，在 CausalDS 的考試組成（exam composition）上，當代代理的表現會沿著五個軸向出現分離（dissociate）：內容正確性（content correctness）、校準不確定性（calibrated uncertainty）、棄權識別（abstention recognition）與工具使用效率（tool-use efficiency）並非同一件事。這意味著：
   - 擅長生成正確數值的模型，未必能正確判斷何時應該棄權；
   - 能產生不確定性區間的模型，其區間未必經過良好校準；
   - 能寫出可執行程式碼的模型，未必能選對因果估計策略。

2. **可識別性（identifiability）作為關鍵診斷**
   CausalDS 刻意設計部分非可識別（non-identifiable）的因果查詢。對這類題目，正確答案是棄權而非給出估計值。若模型在這類題目上仍強行輸出數字，則顯示其缺乏對 do-calculus 與可識別性判斷的理解；反之，若模型過度保守、在可識別題目上也棄權，則反映其不確定性量化過於悲觀。這種設計讓我們能區分「知道答案」與「知道自己不知道」兩種能力。

3. **觀測模型對難度的影響**
   透過觀測模型（observation model）引入不完美觀測後，模型必須先進行資料清理、特徵工程或代理變數校正，才能進入因果估計階段。實驗結果預期會顯示：當觀測複雜度提高時，即使底層 SCM 與目標估計量不變，模型正確率與工具使用效率也會顯著下降。這驗證了「資料科學難度」與「因果推理難度」應該被分開測量。

4. **跨 Pearl 階梯的難度梯度**
   從 Rung 1 的預測任務，到 Rung 2 的介入效果估計，再到 Rung 3 的反事實推理，所需的假設強度逐漸增加。實驗應能觀察到模型在 Rung 1 表現最佳，Rung 2 次之，Rung 3 最具挑戰性。若某些模型在 Rung 2 或 Rung 3 上表現相對較好，則可能暗示其具備較強的符號因果推理能力，而非僅依賴統計關聯。

5. **需要留意的解讀限制**
   由於目前片段未提供詳細的數值結果，我們無法判斷各模型在各子任務上的絕對表現與統計顯著性。未來在閱讀完整論文時，應特別關注：
   - 棄權題目的精確率（precision）與召回率（recall）；
   - 數值估計的絕對誤差、相對誤差與覆蓋率（coverage）；
   - 不同觀測複雜度設定下的表現衰減曲線；
   - 程式執行成功率與最終答案正確率之間的關聯。

#### 與現有研究的比較

1. **相較於資料科學代理基準測試**
   現有資料科學代理基準測試（如 DS-1000、AgentBench、MLAgentBench 等相關文獻）強調程式編寫、開放式分析與工具使用，但通常缺乏隱藏的因果資料生成結構（causal data-generating structure）。這意味著它們無法區分模型是進行了正確的因果推理，還是僅找到統計關聯。CausalDS 透過 SCM 提供明確的 ground truth，並要求模型在回答前進行可識別性判斷，彌補了這一缺口。

2. **相較於符號因果推理基準測試**
   許多因果推理基準測試（如 CLADDER、CausalBench 等）專注於圖形推理、介入邏輯或反事實邏輯，但多在純符號層面進行，缺乏真實的表格資料與資料科學執行要求。CausalDS 將這些符號任務嵌入自然語言故事與觀測資料中，使評量更貼近真實的資料科學工作流程。

3. **相對於基於真實資料集的因果評量**
   從已發表資料集或熟悉因果範例建構的資料集雖然具備真實性，但容易出現資料污染（contamination）與「因果鸚鵡（causal parrot）」問題：模型可能透過記憶既有範例或語義聯想來回答，而非進行結構敏感（structure-sensitive）推理。Yu & Zhou（2026）的並行研究顯示，僅對語義變數名稱進行匿名化就能大幅降低因果基準測試的準確率，凸顯了這個問題的嚴重性。CausalDS 採用完全合成生成，並以經驗分布進行組成錨定，既保留實證結構，又避免污染。

4. **相對於互動式因果發現環境**
   近期互動式發現環境（Yang et al., 2026）透過採樣隱藏 SCM 並讓代理進行介入實驗，目標是恢復實驗機制。這類環境與 CausalDS 的差異在於：前者聚焦於主動實驗設計與機制發現，後者則聚焦於針對已釋放觀測檔案進行因果資料科學分析。兩者互補，分別對應科學發現流程中的「資料收集／實驗」與「資料分析／推論」階段。

5. **主要限制**
   - **合成與真實的差距**：雖然場景經過經驗錨定與故事稽核，但合成資料仍可能無法完全捕捉真實世界中的測量誤差結構、遺漏混淆變數或樣本選擇偏差。
   - **生成與稽核成本**：要確保每個 scene 的圖形結構、自然語言故事與因果問題彼此一致，需要複雜的生成與稽核流程，可能限制規模擴展與領域多樣性。
   - **評分門檻設計**：棄權機制的閾值（例如何謂「無法保證」）需要謹慎設計，過嚴會懲罰合理推論，過鬆則無法區分真正的認識性棄權。
   - **程式輸出的評分挑戰**：雖然 CausalDS 採用確定性評分，但代理的程式碼可能以不同路徑達到正確答案，也可能因環境差異而失敗，評分系統需要足夠穩健。

#### 可重現性評估

1. **開源資源**
   論文已提供 GitHub 儲存庫連結：`github.com/andleb/causalds`。作為一個基準測試（benchmark），其可重現性主要取決於：
   - 場景生成器（scene generator）的程式碼是否完整釋出；
   - 從 SCM 衍生任務與計算 ground truth 的腳本是否公開；
   - 自然語言故事生成與稽核的提示詞（prompts）與檢查邏輯是否可取得；
   - 評分器（scorer）與代理環境（agentic environment）的設定是否開源。

2. **資料集與模型權重**
   CausalDS 本身是一個生成式基準測試，不需要釋出固定的大型資料集；只要釋出生成器，研究者就能重新產生具有相同分布但不同實例的考試。這對避免資料污染特別有利。由於評量對象是現成的大型語言模型（LLM）與資料科學代理，而非訓練新模型，因此不涉及模型權重（model weights）的釋出問題。

3. **確定性評分的優勢**
   相較於需要人工判斷的開放式基準測試，CausalDS 採用確定性評分（deterministic scoring）：每個答案都與隱藏 ground truth 比較。這大幅提升了跨研究團隊比較結果的一致性，也降低了主觀評分帶來的變異。

4. **可重現性的潛在風險**
   - 若故事生成依賴專有的大型語言模型 API，則不同時間、不同模型版本可能產生不同故事，影響場景一致性。
   - 若觀測模型或機制採樣涉及隨機種子，論文需清楚記載種子設定與超參數，才能讓他人復現相同考試。
   - 代理環境（例如檔案系統、可用工具套件、Python 套件版本）的差異可能導致程式執行結果不一致，需要容器化（containerization）或詳細環境說明。

#### 未來研究方向

1. **擴展至動態與縱貫資料**
   當前 CausalDS 主要處理橫斷面（cross-sectional）SCM。未來可加入時間序列 SCM、面板資料（panel data）與動態處理效果（dynamic treatment effects），以評估代理在縱貫因果推理中的能力。

2. **強化未觀察混淆（unobserved confounding）的測試**
   可進一步設計存在隱藏混淆變數的場景，測試代理是否能正確使用工具變數（instrumental variables）、敏感度分析（sensitivity analysis）或部分識別（partial identification）方法，並在無法點識別時給出區間估計或棄權。

3. **結合主動因果發現**
   將 CausalDS 的觀測分析任務與互動式介入環境結合，讓代理在觀測資料不足時主動設計實驗或提出額外資料需求，形成從「觀察→提問→實驗→分析」的完整因果發現流程。

4. **多代理協作與人機互動**
   真實資料科學常涉及多角色協作（例如領域專家、資料工程師、統計學家）。未來可設計多代理（multi-agent）場景，評估模型如何透過對話澄清領域描述、請求額外變數或解釋因果假設。

5. **更豐富的工具生態與視覺化**
   除了 Python 資料分析工具，可納入 SQL 查詢、因果發現套件（如 gCastle、pcalg）、視覺化工具與報告生成，評估代理在複雜資料科學工具鏈中的整合能力。

6. **校準與不確定性量化的細緻評估**
   未來可引入更嚴格的 calibration（校準）指標，如預測區間覆蓋率、Brier score、expected calibration error，並區分「偶然不確定性（aleatoric uncertainty）」與「認識不確定性（epistemic uncertainty）」。

7. **自動化故事稽核與品質保證**
   目前故事生成後需經過稽核以確保圖形忠實性。未來可開發自動化的圖形—文本一致性檢查器，降低人工稽核成本，並提升場景規模。

8. **應用於高風險領域的決策支援**
   將 CausalDS 的框架擴展至醫療、經濟、教育等政策相關領域，評估代理在給出因果建議時是否能正確量化不確定性並適時棄權，這對於可信賴 AI（trustworthy AI）具有重要意義。

9. **對抗式與分布偏移測試**
   可設計對抗式場景，測試代理在分布偏移（distribution shift）、選擇偏差（selection bias）或違反 SCM 假設時的穩健性，並評估其是否能偵測到假設失效。

10. **與人類分析師的對照研究**
    最終，可進行人類基準研究，比較專業資料科學家與 LLM 代理在 CausalDS 各任務上的表現，以確定當前模型的能力缺口與實用價值。

## 論文問答

**Q1：CausalDS 旨在填補什麼樣的評測缺口？**

A：現有的基準測試大致分成兩類：一類是只測符號因果推理但缺乏真實資料分析情境，另一類是測資料分析卻沒有原則性的因果資料生成結構。CausalDS 把符號因果推理、資料科學執行、不確定性量化、認識性棄權與工具使用／程式編寫整合在同一個評測框架中。它要求代理不只要回答因果問題，還要根據領域描述、觀察資料與可識別性判斷，決定要估計目標量還是拒絕回答。

**Q2：為什麼現有的因果推理基準測試容易淪為「因果鸚鵡」問題？**

A：許多現有資料集是從已發表的資料集或精選範例建構而來，模型可能靠記憶或表面語言線索進行「攤銷式因果推論」，而非真正對結構敏感地推理。同期研究顯示，只要將語意變數名稱匿名化、但保持因果任務不變，模型表現就會大幅下降，這正說明了因果鸚鵡風險。CausalDS 透過完全合成生成新穎合成因果結構與自然語言故事，降低資料污染與記憶風險，迫使模型必須根據給定的結構進行推理。

**Q3：為什麼同時評估因果推理與資料科學執行能力很重要？**

A：真實的因果資料科學工作流程需要解讀領域描述、推理因果圖形結構、分析表格資料，並在資訊不足時拒絕回答。如果把這些軸向分開測試，可能會高估代理能力，例如擅長符號邏輯的模型仍可能在程式編寫或不確定性校準上失敗。CausalDS 因此採用聯合評估，讓代理必須在代理式資料科學工作流程中完成從語言理解到程式執行的完整過程。

**Q4：CausalDS 的「場景」核心構成是什麼？**

A：每個基準測試實例都是一個場景，由抽樣得到的隱藏結構因果模型、生成的觀察資料，以及一段 grounded 在真實領域的合成自然語言故事組成。場景的組成可以沿著變數類型、圖形結構、可識別性、機制輪廓與觀測複雜度等軸向，錨定在真實世界資料集的實證分布上。從同一個場景中，CausalDS 再衍生出橫跨皮爾的因果階梯三層的多元任務。

**Q5：CausalDS 在設計上的關鍵創新有哪些？**

A：它的關鍵創新包括以 SCM 為基礎的合成場景、圖形忠實的自由形式語言化，以及獨立的觀測層。觀測層把概念上的 SCM 變數與代理實際收到的不完美觀測區分開來，讓資料科學難度可以獨立於因果結構進行調控。此外，CausalDS 把棄權視為正式計分結果，鼓勵代理在問題沒有有依據的答案時選擇不回答。

**Q6：CausalDS 為什麼要把概念 SCM 與釋出的觀測層分開？**

A：這樣的分離讓基準測試能夠在不改變目標因果估計量或可識別性狀態的前提下，加入測量誤差、遺漏值或雜訊代理變數等不完美觀測。這貼近真實分析情境：分析師通常只能看到真實變數的雜訊版本，而非 SCM 中的乾淨概念變數。因此，代理必須同時處理因果推理與真實資料清理、估計的挑戰。

**Q7：CausalDS 涵蓋哪些橫跨皮爾因果階梯的任務？**

A：第一層（Rung 1）包含關聯性預測與典型資料科學任務；第二層（Rung 2）包含介入性查詢，如效果估計、可識別性判斷與偏差診斷；第三層（Rung 3）則涉及反事實推理。此外，場景也衍生出圖形恢復等任務。大部分任務都包含資料科學程式編寫組件，因為釋出的資料常是透過觀測模型產生的不完美觀測。

**Q8：在 CausalDS 上評估當代代理時，主要發現了什麼？**

A：研究發現模型在五個軸向上的表現並不會收斂成單一能力，不同模型在內容正確性、不確定性量化、棄權識別與工具使用效率上各有強弱。這表示一個代理可能在符號推理上表現優異，卻在不確定性校準或拒答非可識別查詢上失敗。這種解離現象凸顯了多軸向聯合評估的必要性。

**Q9：CausalDS 是否進行了消融或診斷分析？**

A：雖然全文未詳盡列出所有消融實驗，但其設計本身就支援對因果結構、觀測複雜度與領域故事進行獨立操控。例如，作者指出可以改變觀測複雜度來調整資料科學難度，同時固定因果目標。未來可進一步釋出控制組拆分，以隔離符號推理、程式編寫與棄權決策各自的貢獻。

**Q10：CausalDS 在哪些實務情境下最有用？**

A：它特別適合評估在醫療、經濟、教育或政策領域協助分析師的資料科學代理，因為這些領域常需從觀察資料中做出因果宣稱。例如，代理可能被問到某種治療效果是否能從電子病歷中被識別，並進行估計或在資訊不足時棄權。CausalDS 提供確定性評分與隱藏真值，適合這類高風險決策支援系統的評測。

**Q11：在產品層面，使用 CausalDS 進行評估時應考慮什麼？**

A：產品團隊應要求代理不只會產出程式碼與估計值，還要能報告校準不確定性，並識別問題是否無法回答。把棄權視為正式計分結果，有助於避免代理對不可識別的因果查詢進行幻覺式回答。相較於只看孤立準確率，CausalDS 能幫助團隊比較模型在整合工作流程中的綜合表現。

**Q12：CausalDS 可能對因果推理評估領域帶來什麼影響？**

A：它把評估焦點從靜態符號測試或純粹程式編寫基準，轉移到整合性的因果資料科學工作流程。透過系統性生成新穎合成因果結構，它減少了資料污染與因果鸚鵡風險。同時，它也將棄權與不確定性量化確立為可信因果代理不可或缺的評估軸向。

**Q13：CausalDS 承認哪些限制？**

A：目前的版本主要針對釋出的觀察資料進行評估，尚未包含讓代理主動進行實驗性介入的互動式發現環境。場景雖然 grounded 在真實領域，但仍是合成生成，因此真實資料收集、領域專業與倫理考量等細節被簡化。此外，以確定性隱藏真值評分也預設了 SCM 正確指定，這在極度混亂的真實系統中未必成立。

**Q14：代理在 CausalDS 上可能出現哪些失敗案例？**

A：代理可能會對不可識別的因果查詢貿然回答，而不是正確地棄權；也可能給出過度自信但校準不良的區間估計；或是在撰寫程式時忽略隱含的因果圖形結構。此外，當故事用語微妙時，代理可能混淆關聯性、介入性與反事實目標。這些失敗案例都顯示單一軸向基準測試難以捕捉的整合性推理缺口。

**Q15：CausalDS 指出了哪些未來研究方向？**

A：未來可以擴充基準，加入互動式介入、更豐富的觀測模型，以及經真實世界驗證的機制。提升代理的棄權策略與校準不確定性仍是核心挑戰。此外，涵蓋更廣泛領域、大規模場景生成，以及建立標準化排行榜，都有助於加速發展可信賴的因果資料科學代理。

## 實務應用指南

### 適用場景

**1. 企業內部資料科學代理的因果能力驗收**
當組織部署會自動讀取表格資料、撰寫分析程式並產出決策建議的資料科學代理時，CausalDS 可作為出廠測試與持續迴歸測試的考題庫。例如金融業的風險模型代理、零售業的促銷效果評估代理，都需要同時檢驗其「會不會把相關當因果」「能否判斷介入效果」「會不會在資訊不足時棄權」。

**2. 生成式 AI 醫療或政策顧問系統的安全評估**
在醫療建議、公共衛生政策或教育介入等場景，錯誤的因果宣稱代價高昂。CausalDS 可用來評估模型是否能從觀察資料中正確區分第一層預測、第二層介入效果與第三層反事實推論，並在不可識別的查詢上選擇拒答，降低誤導決策的風險。

**3. 因果推論教學與認證測驗**
大學或企業培訓單位可利用 CausalDS 的場景生成機制，自動產生大量新穎的合成因果結構與對應故事，設計程式化的因果資料科學考題。由於場景是系統性合成而非摘錄現有資料，可減少學生背答案或模型靠記憶取勝的問題。

**4. 觀測模型與資料品質對代理表現的影響研究**
產品團隊可透過 CausalDS 的觀測層設計，刻意加入雜訊、遺漏變數或代理變數，測試代理在「不完美觀測」下的穩健性。這適用於評估資料管線品質、特徵工程策略或異常資料清洗流程對因果結論的影響。

**5. 基礎模型因果推理能力的橫向比較**
模型開發者或採購單位可用 CausalDS 作為標準化評測，比較不同 LLM 或代理框架在符號因果推理、資料科學執行、不確定性量化、認識性棄權與工具使用等五個軸線上的差異，避免單一指標造成的偏頗選型。

### 實作前置條件

**資料需求**
- 若僅使用 CausalDS 預設的合成場景，無須準備真實資料即可開始評測。
- 若希望場景組成貼近特定領域，需準備真實世界資料集以估計實證分布，並據此錨定變數類型、圖形結構、可識別性、機制輪廓與觀測複雜度等軸線。
- 建議額外準備領域詞表或 CauseNet 風格的概念對照表，以提升變數命名與故事語境的真實感。

**運算需求**
- 場景生成與結構因果模型抽樣需要可執行 Python 的環境，並安裝因果推論相關套件（如 `networkx`、`pgmpy`、`dowhy`、`ananke` 等）。
- 對 LLM 代理進行大規模評測時，需準備足夠的 API 配額或本地 GPU 資源，並預留程式執行沙箱（container 或虛擬環境）以安全執行模型產生的分析程式。
- 若包含反事實推論與不確定性量化任務，計算成本會顯著高於純文字問答，需預留額外運算預算。

**技能需求**
- 團隊中至少需有一名熟悉因果推論（SCM、do-calculus、可識別性、Pearl 三層階梯）的成員，負責審核場景與評分邏輯。
- 需具備資料科學程式編寫與代理系統整合經驗，能將 CausalDS 的輸出轉換為代理可讀取的任務格式。
- 建議具備評測設計與計量心理學基礎，以便正確解讀棄權率、校準度與正確率之間的權衡。

### 實作步驟建議

**步驟一：定義評測目標與軸線權重**
先決定本次評測要強調哪些能力：是驗證代理能否正確估計介入效果，還是檢驗其在不可識別查詢上的棄權行為？根據目標設定五個軸線的權重，並決定是否需要加入不完美觀測。

**步驟二：選擇或生成場景**
從 CausalDS 提供的場景生成器出發，決定是否以真實世界資料集的實證分布錨定場景組成。若為企業內部應用，建議用領域資料進行經驗校準；若為通用能力評測，可直接使用完全合成生成以降低因果鸚鵡風險。

**步驟三：設計任務組合**
針對每個場景，從 Pearl 三層階梯中衍生任務：第一層可包含預測與關聯估計；第二層可包含效果估計、偏差診斷與可識別性判斷；第三層可包含反事實推理。確保部分查詢在給定圖形與資料下不可識別，以測試認識性棄權。

**步驟四：建置代理執行環境**
為受測代理提供檔案支援的執行環境，使其能讀取表格資料、呼叫標準分析工具、撰寫並執行程式。環境應記錄所有工具呼叫與中間輸出，以便後續分析工具使用效率。

**步驟五：建立評分與棄權機制**
針對每個任務設定隱藏的真實答案與可接受的數值誤差範圍。將「棄權」設為正式計分結果，並明確定義哪些問題允許棄權、哪些問題必須回答。避免將棄權視為單純的零分，而是與錯誤回答區別計分。

**步驟六：執行評測與分析**
執行大規模評測後，除了總正確率，還應分軸線報告表現：符號因果推理、資料科學執行、不確定性量化、認識性棄權、工具使用／程式編寫。特別注意模型是否在某些軸線上表現突出但在其他軸線上明顯薄弱。

**步驟七：迭代改善場景與代理**
根據評測結果調整場景難度、觀測模型複雜度或任務設計，並將發現回饋給代理開發團隊，作為微調提示詞、增加工具或改進拒答策略的依據。

### 潛在風險與注意事項

**風險一：過度依賴單一總分**
CausalDS 的價值在於多軸線評估，若僅報告總正確率，可能掩蓋模型在棄權或反事實推理上的嚴重缺陷。建議始終以五軸線分開呈現結果，並搭配混淆矩陣式的棄權分析。

**風險二：場景故事語意洩漏因果結構**
若合成自然語言故事寫得過於明確，模型可能透過語言模式直接猜出因果圖，而非進行結構推理。應審核故事與隱藏圖形的一致性，避免在敘述中無意間透露父節點或方向。

**風險三：棄權策略被濫用**
模型可能學會「不確定就棄權」以提高分數，但過度棄權會降低實用性。建議同時監控棄權率與正確率，並在必要時對無正當理由的棄權施加懲罰。

**風險四：觀測模型設定失當**
不完美觀測的難度若與真實任務脫節，可能導致評測過難或過易。應先以小型先導實驗校準觀測雜訊程度，確保資料科學難度與因果難度可獨立調整。

**風險五：真實資料錨定帶來的污染**
即使使用合成資料，若場景組成過度貼近公開資料集，仍可能讓模型靠記憶取勝。應定期更新場景生成參數，並對受測模型進行污染檢測。

### 與其他技術的整合建議

**與 LLM 代理框架整合**
CausalDS 可輸出標準化的任務描述與資料檔案，直接餵給 ReAct、LangChain、AutoGen 或 OpenAI 的 Code Interpreter 等代理框架。建議將棄權機制設為代理動作空間中的一個正式工具，讓模型能主動選擇「拒絕回答」。

**與 MLOps 與持續評測管線整合**
將 CausalDS 納入 CI/CD 流程，每次模型更新後自動抽樣場景進行迴歸測試。可與 Weights & Biases、MLflow 或自製儀表板整合，追蹤五軸線表現隨時間的變化。

**與因果推論函式庫整合**
在評分端可串接 `dowhy`、`econml`、`causalnex` 或 `Ananke` 以計算真實介入效果與反事實量，作為隱藏真值的參考。在代理端也可允許模型呼叫這些函式庫，但需注意其假設是否與場景圖形一致。

**與資料品質與可解釋性工具整合**
將 CausalDS 的觀測層與資料品質檢測工具（如 Great Expectations、TensorFlow Data Validation）結合，可同時評估代理對髒資料的處理能力。再搭配 SHAP、LIME 或因果圖視覺化工具，可進一步分析模型的推理路徑是否符號正確。

**與領域知識庫整合**
對於醫療、法律或政策應用，可將 CausalDS 的變數對照與領域本體知識庫連結，確保合成故事使用的術語與領域慣例一致，同時維持因果結構的新穎性。

### 給不同背景讀者的閱讀建議

**給初學者**
如果你剛接觸因果推論與 LLM 評測，建議先從本文的「引言」與「背景」章節讀起，理解 Pearl 三層階梯、可識別性與結構因果模型的基本概念。接著把重點放在 CausalDS 的「場景」設計與「棄權」機制上，不必急著深入觀測模型或評分演算法的細節。你可以把 CausalDS 想像成一個「會自動出考題的因果資料科學老師」，它的核心貢獻是讓機器必須同時會讀故事、會寫程式、會判斷能不能回答。

**給 AI 工程師**
對於正在建置資料科學代理的工程師，本文最重要的部分是場景生成器、觀測層設計與五軸線評估框架。你應該關注如何將 CausalDS 的輸出格式對接到你的代理執行環境，以及如何實作「棄權」作為一個可被選擇的動作。此外，請特別留意觀測模型如何讓資料科學難度與因果難度解耦，這對設計可調難度的測試集非常有用。

**給研究者**
研究者應聚焦在 CausalDS 的方法論貢獻：以結構因果模型為基礎的合成場景生成、圖形忠實的自由形式語言化、以及對因果鸚鵡風險的處理。建議深入閱讀場景生成與審核機制，並思考如何將此框架擴展到動態因果模型、未觀察混淆因子更複雜的設定，或與互動式發現環境進行比較。棄權評分與不確定性量化的結合也是值得延伸的理論議題。

**給產品經理**
產品經理應把 CausalDS 視為一個「因果資料科學代理的驗收標準」。閱讀時請著重於適用場景、五軸線評估與潛在風險，並思考你的產品最在意哪幾個軸線：是預測準確度、介入效果估計、還是安全拒答？本文的實作步驟與整合建議可幫助你規劃評測時程、資源配置與與現有 MLOps 管線的銜接。請記得，CausalDS 的價值不在於一個總分，而在於幫助團隊發現模型能力的具體缺口。
