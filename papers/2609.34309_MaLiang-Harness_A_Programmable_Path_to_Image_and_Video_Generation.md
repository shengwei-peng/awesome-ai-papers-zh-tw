## 摘要翻譯

可執行程式能對圖像與影片的建構方式提供明確的控制，但生成可執行的程式碼只是視覺創作的起點。一個程式可能正確執行，卻違反了所要求的構圖、外觀或動作。我們將此差距定義為程式到視覺 (P2V) 差距，並提出 MaLiang-Harness，一個將多模態大型語言模型 (MLLM) 驅動的視覺生成組織為持續的建構、檢查與修訂過程的統一框架。其核心設計在於使演進中的視覺程式、其建構歷史與其驗證共享同一個修訂參考。我們將持久可執行生成 (PEG) 狀態定義為保留程式與任務脈絡；可追溯生成過程 (TGP) 將編輯與渲染證據相連結；而修訂感知編輯與驗證 (REV) 支援還原並在完成前檢查當前修訂。這些機制共同協調跨渲染後端的規劃、執行與視覺回饋。我們在 MaLiang-IBench 上評估 11 個強大的閉源多模態大型語言模型，並在 MaLiang-VBench 上評估 4 個，衡量生成成功率、視覺品質與計算成本。GPT-6-Astra 在兩個基準測試上皆達到 100% 的生成成功率，其中 96.0% 的圖像任務與 76.9% 的影片任務滿足所有品質門檻。比較結果亦揭示了通用能力評分與視覺生成效能之間的不匹配，評分相近的模型在滿足視覺需求的能力上存在顯著差異。MaLiang-Harness 提供了研究 MLLM 如何將可執行程式碼轉化為視覺成果的系統性基礎，揭示了可程式化生成的潛力，同時也點出了通用基準測試作為此能力預測指標的局限性。專案可於 https://github.com/gulucaptain/MaLiang-Harness 取得。

### 核心貢獻（3～5點）
- 定義「程式到視覺 (P2V) 差距」概念，指出程式可正確執行卻仍可能違反構圖、外觀或動作等視覺需求。
- 提出 MaLiang-Harness 統一框架，將 MLLM 驅動的視覺生成組織為持續的建構、檢查與修訂過程。
- 設計三項核心機制：持久可執行生成 (PEG) 保留程式與任務脈絡、可追溯生成過程 (TGP) 連結編輯與渲染證據、修訂感知編輯與驗證 (REV) 支援還原與完成前檢查。
- 建立 MaLiang-IBench 與 MaLiang-VBench 兩套基準測試，系統性評估 11 個與 4 個閉源 MLLM 的生成成功率、視覺品質與計算成本。
- 揭示通用能力評分與視覺生成效能之間的不匹配現象，凸顯通用基準測試作為視覺生成能力預測指標的局限性。

### 適合對象
從事多模態大型語言模型、視覺生成（文字生成圖像／影片）、可程式化生成、視覺推理與編輯等領域研究的學者與工程師；以及對 MLLM 評測基準設計、生成式 AI 系統化框架開發感興趣的研究人員。

## 深度分析

#### 方法論解析

MaLiang-Harness 的方法論核心在於正視一個被既有視覺生成研究普遍忽略的問題：**程式層級的正確性與視覺需求的滿足度之間存在系統性落差**，作者將其命名為「程式到視覺 (Program-to-Visual, P2V) 差距」。此一架構性洞見源自一個簡單但深刻的觀察——一個可執行的視覺程式 (executable visual program) 即使語法正確、邏輯無誤，仍可能產出違反使用者意圖的圖像或影片，例如物件位置錯誤、動畫時序偏差、外觀與構圖 (composition) 不符等。這意味著傳統的「程式碼生成 → 渲染 (rendering)」單次性管線不足以支撐高品質的可程式化生成 (programmable generation)。

**框架的整體設計哲學**

MaLiang-Harness 將視覺生成重新定義為一個**持續性的建構、檢查與修訂 (Construction, Inspection, and Revision) 迴圈**，而非一次性產出。其設計哲學有三個關鍵轉變：

1. **從「生成」到「建構」**：視覺作品被視為一個隨時間演化的物件，而非單一時間點的輸出。這要求系統必須具備狀態管理能力。

2. **從「黑箱渲染」到「可追溯過程」**：每一次程式碼變更都應留下視覺證據，使模型與使用者能夠回溯「哪個操作導致了哪個視覺結果」。

3. **從「單次驗證」到「修訂感知驗證」**：每次修訂後，必須重新評估所有需求，因為新變更可能破壞先前已滿足的條件。

**三大核心機制的技術內涵**

**(1) 持久可執行生成 (Persistent Executable Generation, PEG) 狀態**

PEG 是整個框架的「記憶體」，負責在跨迭代過程中維持視覺作品的可執行定義。其資料結構包含五個關鍵元素：
- **可執行程式碼**：當前版本的視覺程式 (visual program)
- **圖像資產 (image assets)**：當程式碼難以表達豐富外觀時的補充素材
- **時空組織 (spatiotemporal structure)**：空間構圖與時間動態的結構化描述
- **任務需求 (task context)**：原始使用者意圖的持久化記錄
- **修訂索引 (revision index)**：版本編號，支援後續的還原 (restoration) 與回溯

PEG 的設計意義在於提供一個「穩定物件」供 MLLM 檢查與修改，避免每次迭代都需要從零開始重建脈絡。

**(2) 可追溯生成過程 (Traceable Generation Process, TGP)**

TGP 將建構過程透明化，透過兩種機制實現：
- **顯式程式記錄**：所有編輯操作以可讀形式留存，形成建構歷史 (construction history)
- **中間渲染 (intermediate renderings)**：暴露每一步操作的視覺效果

TGP 的核心價值在於建立「程式碼變更 ↔ 視覺結果」的雙向連結，使 MLLM 能夠診斷 P2V 差距的根源——是空間參數錯誤？動畫時序偏差？還是渲染後端 (rendering backend) 選擇不當？

**(3) 修訂感知編輯與驗證 (Revision-aware Editing and Verification, REV)**

REV 是框架的「品管機制」，包含三項功能：
- **修訂還原 (restoration)**：允許模型回到先前的修訂版本，同時保留當前任務需求
- **修訂關聯觀察**：將觀察結果與驗證結果綁定到特定修訂版本
- **完成前重新評估 (completion check)**：每次提交更新前，必須對所有需求進行重新驗證

REV 解決了一個微妙但關鍵的問題：修訂可能引入新的視覺缺陷，因此不能僅驗證「本次變更是否正確」，而需驗證「本次變更後整體是否仍滿足所有需求」。

**統一介面的設計意涵**

MaLiang-Harness 作為「統一介面」連接創作意圖與多種可執行視覺表徵，其設計選擇具有深遠意義：
- **多渲染後端支援**：MLLM 可根據任務特性選擇合適的渲染後端（如 SVG、Manim、Three.js 等），而非受限於單一引擎
- **圖像與影片共享框架**：在固定程式修訂下，圖像是在指定內容時間點的渲染，影片則是對程式編碼的時序行為進行取樣——這種統一性簡化了模型推理
- **可選圖像資產**：當程式碼難以表達複雜外觀時，可引入預先生成的圖像作為補充，兼顧程式化控制的精確性與神經渲染的表現力

**與既有範式的根本差異**

傳統的擴散模型 (diffusion model)、流匹配模型 (flow-based model) 等直接視覺合成 (direct visual synthesis) 範式，其生成過程是隱式的——使用者無法精準控制空間構圖或時間動態。MaLiang-Harness 則將控制權交還給程式碼，使 MLLM 的語意理解 (semantic understanding)、推理與程式碼生成 (code generation) 能力得以直接轉化為視覺控制力。

#### 實驗數據解讀

**評估設計的嚴謹性**

MaLiang-Harness 的實驗設計展現了對「視覺生成評測」這個棘手問題的深度思考。作者建構了兩個專屬基準測試 (benchmark)：
- **MaLiang-IBench**：圖像生成基準
- **MaLiang-VBench**：影片生成基準

評測維度涵蓋三個層面：
1. **生成成功率 (generation success)**：程式能否成功執行並產出有效輸出
2. **視覺品質 (visual quality)**：從提示詞對齊 (prompt alignment)、美學 (aesthetics)、構圖 (composition) 三個面向評估
3. **計算成本 (computational cost)**：時間效率與 token 效率

這種多維度設計避免了單一指標的偏誤，特別是「生成成功率」與「品質門檻 (quality threshold)」的分離——一個程式可能成功執行但品質不佳，反之亦然。

**模型規模與結果分層**

實驗涵蓋 11 個閉源多模態大型語言模型 (closed-source MLLM)，橫跨三個家族：
- **GPT-5.6 系列**：Luna、Terra、Sol 三個變體
- **GPT-6 系列**：Luna、Sol、Astra 三個變體
- **DeepSeek 系列**：V4.1-Flash、V4-Pro
- **Kimi 系列**：K2.6、K2.7-Code、K3

從圖 2 的排名資料可解讀出幾個關鍵發現：

**(1) 世代差距顯著**

GPT-5.6 與 GPT-6 系列在生成成功率上呈現壓倒性優勢（92–100%），而 DeepSeek 與 Kimi 系列僅 12–40%。這暗示視覺程式生成對 MLLM 的程式碼能力、視覺推理 (visual reasoning) 能力與長脈絡理解有極高要求，並非所有通用 MLLM 都能勝任。

**(2) GPT-6-Astra 的標竿表現**

GPT-6-Astra 在兩個基準測試上均達到 100% 生成成功率，且：
- 96.0% 的圖像任務滿足所有品質門檻
- 76.9% 的影片任務滿足所有品質門檻

相較之下，次佳模型僅 86.0%（圖像）與 38.5%（影片）。影片任務的品質落差尤其值得注意——這反映了影片生成在時序一致性、動作 (motion) 準確性上的額外難度。

**(3) 通用能力與視覺生成效能的脫鉤**

這是實驗中最具啟發性的發現：**通用能力評分 (general capability score) 與視覺生成效能 (visual generation performance) 之間存在顯著錯位**。具體而言：
- 評分相近的模型在視覺需求滿足度上可能差異極大
- 這意味著現有 MLLM 排行榜（如 MMLU、HumanEval 等）無法有效預測視覺生成能力

此一發現對學界與業界的模型選用具有重要警示：選擇視覺生成用途的 MLLM 時，必須進行專門評測，而非依賴通用基準。

**(4) 成本與品質的權衡**

圖 2 同時呈現了時間效率與 token 效率排名，但作者特別提醒：
- 「早期失敗可降低成本」——生成成功率低的模型可能因快速失敗而排名較前
- 不同模型的預算與回饋機制不同，跨模型比較成本需謹慎

這種誠實的數據呈現方式值得肯定，避免了「又快又好」的過度解讀。

**實驗設計的侷限**

儘管實驗規模可觀（11 個模型、兩個基準），仍有幾個侷限值得注意：
- **僅評估閉源模型**：缺乏開源模型的對比，無法判斷框架對模型規模的依賴程度
- **基準測試的代表性**：MaLiang-IBench 與 MaLiang-VBench 的任務分佈是否充分覆蓋真實應用場景，仍需更多驗證
- **缺乏人類主觀評測**：品質評估依賴自動化指標，可能無法完全捕捉美學與創意價值

#### 與現有研究的比較

**在視覺生成領域的定位**

MaLiang-Harness 處於一個獨特的研究交匯點：它既不同於純粹的擴散模型路線（如 Stable Diffusion、Sora），也不同於純粹的程式碼生成路線（如早期的 SVG 生成研究）。其定位可從表 1 的比較中清晰看出：

| 維度 | 傳統 T2I/T2V | MaLiang-Harness |
|------|-------------|-----------------|
| 線條與平面藝術 (Line and Flat Art) | 部分支援 | 支援 |
| 2D 卡通 (2D Cartoon) | 部分支援 | 支援 |
| 像素藝術 (Pixel Art) | 不支援 | 支援 |
| 風格化 3D (Stylized 3D) | 部分支援 | 支援 |
| 混合媒材與手工藝 (Mixed Media and Craft) | 不支援 | 部分支援 |
| 照片寫實主義 (Photorealism) | 支援 | 部分支援 |
| 可控性 (Controllability) | 有限 | 支援 |
| 可編輯性 (Editability) | 有限 | 支援 |
| 可追溯性 (Traceability) | 不支援 | 支援 |

這個比較揭示了 MaLiang-Harness 的核心優勢：**在可控性、可編輯性與可追溯性三個維度上實現了質的突破**。傳統 T2I/T2V 模型即使能產出高品質圖像，也難以支援精準的空間控制（如「將第三行第二列的圓盤改為紅色」）或過程追溯。

**與程式化視覺生成先驅工作的關係**

MaLiang-Harness 並非憑空出現，其思想脈絡可追溯至多個先驅領域：
- **Creative Coding**（如 Processing、p5.js）：強調程式碼作為創作媒介
- **程式碼驅動的動畫**（如 Manim）：數學動畫的程式化生成
- **神經符號視覺生成**：結合神經網路與符號推理的混合方法

然而，MaLiang-Harness 的創新在於將這些思想**整合到一個以 MLLM 為核心的統一框架**，並正視 P2V 差距這個先前被忽略的問題。

**相較於擴散模型的優勢與劣勢**

**優勢**：
1. **精準可控性**：程式碼可直接指定空間座標、時間點、動畫曲線等參數
2. **可重現性**：相同程式碼產生相同輸出，便於版本控制與協作
3. **可編輯性**：可針對特定元素進行修改，無需重新生成整張圖
4. **過程透明**：使用者可審查每一個視覺決策的依據

**劣勢**：
1. **表現力受限**：對於照片寫實等高度複雜的視覺風格，程式化表達仍有困難（這也是表 1 中「部分支援」的原因）
2. **依賴 MLLM 能力**：框架效能高度依賴底層 MLLM 的程式碼生成與視覺推理能力
3. **計算成本**：迭代式的建構-檢查-修訂迴圈可能消耗大量 token 與時間

**與近期 MLLM 視覺生成工作的對比**

近期如 GPT-4V、Gemini 等 MLLM 已開始整合視覺生成能力，但多數仍採用「一次性生成」範式。MaLiang-Harness 的迭代式設計在概念上更接近人類藝術家的創作過程——草稿、檢查、修改、再檢查——這使其在需要精準控制的場景中具有獨特優勢。

**框架的侷限性**

作者坦誠指出，MaLiang-Harness 並非萬能解方：
- 對於需要高度真實感的場景，程式化方法的表現力仍不足
- 框架的成功率高度依賴 MLLM 的能力，跨模型泛化性需更多驗證
- 影片生成的成功率（76.9%）顯著低於圖像（96.0%），顯示時序建模仍是挑戰

#### 可重現性評估

**程式碼與資源的開放程度**

從論文提供的資訊來看，MaLiang-Harness 展現了良好的開放科學態度：
- **專案網址公開**：https://github.com/gulucaptain/MaLiang-Harness
- **預印本形式發表**：便於學界快速迭代與驗證

**可重現性的關鍵要素評估**

**(1) 框架實作的可重現性**

作為一個整合性框架，MaLiang-Harness 的可重現性取決於：
- 程式碼是否完整實作 PEG、TGP、REV 三大機制
- 渲染後端的介面是否標準化
- 狀態管理的資料結構是否清晰定義

從論文描述來看，框架設計具有清晰的模組化結構，理論上應支援獨立重現。

**(2) 基準測試的可重現性**

MaLiang-IBench 與 MaLiang-VBench 是評估的關鍵，但論文未明確說明：
- 基準測試的任務集是否公開
- 評估指標的具體計算方式
- 品質門檻的判定標準

這些資訊的透明度將直接影響其他研究者重現實驗結果的能力。

**(3) 模型評估的可重現性**

實驗涉及 11 個閉源 MLLM，這帶來根本性的可重現性挑戰：
- **閉源模型的不透明性**：無法控制模型版本、API 行為、隱藏的系統提示等變數
- **API 變動風險**：閉源模型的更新可能導致實驗結果無法重現
- **成本考量**：完整重現實驗需要大量 API 呼叫，經濟成本不低

**對開源社群的影響**

MaLiang-Harness 的開放釋出對開源社群具有積極意義：
- 提供了一個標準化的視覺程式生成框架
- 促進了 MLLM 視覺生成能力的系統性評測
- 為後續研究提供了可擴展的基礎設施

然而，若缺乏配套的開源基準測試與評測工具鏈，其學術影響力將受限。

**整體可重現性評級**

- 框架本身可重現性高

## 論文問答

**Q1：什麼是「程式到視覺 (P2V) 差距」，為何它構成視覺生成的根本性挑戰？**

A：P2V 差距指的是可執行程式雖然能正確執行，卻仍可能產生不符合使用者意圖的視覺成果——例如物件位置錯誤、構圖偏差，或動畫事件發生在錯誤的時間點。這種差距之所以根本，是因為它揭示了「程式語法正確」與「視覺語意滿足」之間存在一道鴻溝，僅靠程式碼生成無法跨越。要彌補此差距，模型必須能推理其程式碼所帶來的視覺後果，並在初始規劃時就考量視覺表徵與渲染後端的選擇，進而依據渲染輸出反覆修訂程式與計畫。這使得視覺生成從單純的「寫程式」轉變為一個需要持續視覺回饋的狀態化過程。

**Q2：為何既有以擴散模型與 GAN 為代表的直接視覺合成方法，難以勝任可程式化生成的需求？**

A：直接視覺合成方法（包含 GAN、擴散模型與流匹配模型）雖然在像素品質上表現卓越，但其生成過程本質上是隱含的——模型學習的是視覺資料的分布，並直接合成像素或潛在視覺表徵，使用者難以介入中間步驟。這種隱含性使得控制空間構圖、時序動作或精準編輯變得困難，也無法追溯生成過程中的具體決策。相對地，可程式化生成要求模型以可執行的視覺程式明確表達創作意圖，並透過渲染器轉換為影像或影片，這需要的是語意理解、推理與程式碼生成能力，而非單純的視覺分布擬合。因此，MLLM 的崛起為這條新路徑提供了可行性，但同時也帶來了 P2V 差距的新問題。

**Q3：為何彌合 P2V 差距對 AI 視覺內容生成的未來至關重要？**

A：彌合 P2V 差距意味著 AI 不僅能「畫出東西」，更能「按需求精準地畫出東西」，這對創意產業、教育、設計等需要高度可控性的場域意義重大。若無法跨越此差距，即便程式碼生成能力再強，產出的視覺成品仍可能與使用者期待落差甚大，限制了可程式化生成在實務中的應用價值。此外，P2V 差距的解決也代表著 AI 從「模仿視覺分布」邁向「理解並執行視覺意圖」的典範轉移，這是邁向更通用視覺智慧的關鍵一步。MaLiang-Harness 透過建構、檢查與修訂的循環，正是為了系統性地處理這個差距。

**Q4：MaLiang-Harness 的核心方法是什麼？它如何組織整個創作流程？**

A：MaLiang-Harness 是一個統一框架，將 MLLM 驅動的視覺生成組織成一個持續的「建構、檢查與修訂」過程，並透過共享介面連接創作意圖與多種可執行視覺表徵。在這個框架中，MLLM 負責規劃與生成程式碼，渲染後端負責執行並產出視覺成果，而框架本身則管理狀態、記錄建構歷史並支援修訂感知驗證。具體而言，圖像與影片共享同一創作框架：在固定的程式修訂版本下，圖像於指定內容時間渲染，而影片則取樣程式所編碼的時序行為。這種統一性使得同一套機制能同時處理靜態與動態視覺生成任務。

**Q5：MaLiang-Harness 的三大核心機制（PEG、TGP、REV）是如何協同運作的？**

A：三大機制各司其職並相互協作：持久可執行生成 (PEG) 狀態負責在跨迭代過程中維持演進中藝術品的可執行定義，整合程式、資產、時空組織、任務需求、當前計畫與修訂索引，提供模型一個穩定可檢查與修改的物件；可追溯生成過程 (TGP) 則透過明確的程式與記錄的操作使藝術品的建構可被檢視，中間渲染結果暴露了這些操作的視覺效果，幫助模型與使用者將觀察到的差異關聯到可能造成問題的元件或變更；修訂感知編輯與驗證 (REV) 允許模型在保留當前任務需求的前提下將藝術品內容還原至較早版本，並要求每次提交的更新在完成前都必須經過重新評估。三者共同協調規劃、執行與視覺回饋，使 MLLM 能將視覺回饋轉化為對演進中藝術品的精準修訂。

**Q6：為何 MaLiang-Harness 選擇讓演進中的視覺程式、建構歷史與驗證共用同一個修訂參考？**

A：共用修訂參考的設計是為了確保在反覆修訂的過程中，所有相關資訊——程式碼、視覺成果、任務需求與驗證結果——都能保持一致地指向同一個版本狀態，避免因資訊錯位而導致錯誤的修訂決策。這種設計解決了多版本管理中的核心難題：當模型嘗試還原或修改某個先前版本時，必須能準確知道該版本對應的程式、渲染結果與評估紀錄。透過將這些元素綁定在同一修訂索引下，框架支援了可靠的還原機制，也使得每次修訂後的重新驗證能正確評估「當前版本」是否滿足所有需求，而非殘留地參考過時的評估結果。

**Q7：MaLiang-IBench 與 MaLiang-VBench 是什麼？它們各自衡量哪些面向？**

A：MaLiang-IBench 與 MaLiang-VBench 是 MaLiang-Harness 團隊設計的兩個基準測試，分別用於評估圖像與影片的可程式化生成能力，涵蓋生成成功率、視覺品質與計算成本等面向。在視覺品質方面，兩個基準都評估提示詞對齊度、美學品質與構圖等維度；在效率方面，則衡量時間效率與 token 效率。這些基準的設計目的是系統性地檢驗 MLLM 將可執行程式碼轉化為視覺成果的能力，彌補了現有通用基準測試在這個特定能力上的不足。

**Q8：在 11 個閉源 MLLM 的評估中，最關鍵的發現是什麼？**

A：最關鍵的發現是 GPT-6-Astra 在兩個基準上都達到了 100% 的生成成功率，其中 96.0% 的圖像任務與 76.9% 的影片任務滿足所有品質門檻，展現了頂尖模型在可程式化視覺生成上的強大能力。相對地，DeepSeek 與 Kimi 系列模型的生成成功率僅在 12% 至 40% 之間，顯示出不同 MLLM 在這項任務上的能力差距極為懸殊。此外，影片任務的品質門檻達成率普遍低於圖像任務（GPT-6-Astra 在影片上僅 76.9%，而圖像為 96.0%），這反映出時序生成比靜態生成更具挑戰性。

**Q9：實驗結果揭示了通用能力評分與視覺生成效能之間怎樣的落差？**

A：實驗揭示了一個重要現象：通用能力評分相近的模型，在視覺生成任務上的實際表現可能存在巨大差異，這意味著通用基準無法有效預測模型的可程式化視覺生成能力。這個落差凸顯了針對性基準測試的必要性——若僅依賴通用評分來選擇模型，可能會嚴重誤判其在特定視覺生成任務上的適用性。MaLiang-IBench 與 MaLiang-VBench 的價值正是在於提供了一個專門衡量「將可執行程式碼轉化為視覺成果」這項能力的標準化評估工具。

**Q10：MaLiang-Harness 支援哪些實際應用場景？**

A：MaLiang-Harness 支援多元的實際應用場景，包括卡通角色生成、海報與流程圖生成、視覺推理與編輯，以及創意影片生成等。在視覺推理與編輯方面，框架能處理如「將頭髮從黑色改為金色」、「加入手錶」、「圈出所有圓盤」或「將第 3 欄第 2 列改為紅色」這類精準的局部修改指令。在創意影片生成方面，則能產出如水墨山水從墨漬展開、像素藝術小貓在鍵盤上搬運星星，或手繪小貓將真實物品變成運輸工具等富有想像力的敘事內容。這些場景橫跨線條與平面藝術、2D 卡通、像素藝術、風格化 3D、混合媒材與手工藝，以及照片寫實主義等多種視覺風格。

**Q11：從產品化角度來看，MaLiang-Harness 解決了哪些關鍵的工程問題？**

A：從產品化角度，MaLiang-Harness 解決了多項關鍵工程問題：首先是多渲染後端的統一介面，使模型能依任務需求選擇最適合的渲染方式；其次是狀態管理，確保跨迭代過程中藝術品的完整性與可恢復性；第三是視覺回饋的整合，讓模型能依據渲染結果進行精準修訂而非盲目重來。這些設計使得將 MLLM 整合到實際的視覺創作工具中變得可行，使用者能獲得可控、可編輯且可追溯的創作體驗，而非僅得到一次性的黑箱輸出。

**Q12：MaLiang-Harness 對視覺 AI 領域可能產生哪些更廣泛的影響？**

A：MaLiang-Harness 對視覺 AI 領域的影響可能體現在三個層面：在研究層面，它為「MLLM 如何將可執行程式碼轉化為視覺成果」提供了系統性的研究基礎；在技術層面，它展示了可程式化生成相較於直接視覺合成在可控性、可編輯性與可追溯性上的優勢；在產業層面，它為需要精準視覺控制的應用（如設計自動化、教育內容生成、創意工具）開啟了新的可能性。此外，框架所揭示的「通用能力評分無法預測視覺生成效能」現象，也可能促使學界與業界重新思考 MLLM 能力評估的方式。

**Q13：這篇論文坦承了哪些限制？**

A：雖然論文並未在所提供段落中詳列所有限制，但從實驗設計與結果可推論出若干限制：首先是影片任務的品質門檻達成率（即使是最佳模型 GPT-6-Astra 也僅 76.9%）明顯低於圖像任務（96.0%），顯示時序生成仍是較大的挑戰；其次是評估僅涵蓋 11 個閉源 MLLM 與其中 4 個在影片基準上的測試，模型覆蓋面有限；第三是框架的效能高度依賴 MLLM 的程式碼生成與視覺推理能力，對能力較弱的模型（如 DeepSeek 與 Kimi 系列）效果不佳。

**Q14：實驗中揭示了哪些失敗案例或弱點？**

A：實驗揭示了幾類明顯的失敗案例與弱點：DeepSeek 與 Kimi 系列模型在 MaLiang-IBench 上的生成成功率僅 12% 至 40%，遠低於 GPT 系列的 92% 至 100%，顯示這些模型在將可執行程式碼轉化為視覺成果時存在根本性困難。即使是表現最佳的 GPT-6-Astra，在影片任務上仍有 23.1% 的任務未能滿足所有品質門檻，說明時序視覺生成——尤其是動作的精確性與時序對齊——仍是未完全解決的難題。此外，影片任務的品質門檻達成率（38.5% 至 76.9%）普遍低於圖像任務（86.0% 至 96.0%），反映出影片生成在可控性與精確度上的更高難度。

**Q15：這項工作為未來研究指出了哪些方向？**

A：這項工作為未來研究指出了多個方向：首先是如何進一步提升影片任務的品質門檻達成率，特別是動作的時序精確性與視覺一致性；其次是如何降低對頂尖 MLLM 的依賴，使框架在中等能力的模型上也能產生可用結果；第三是如何擴展框架以支援更多渲染後端與視覺風格；第四是 P2V 差距的理論分析——目前框架提供了工程性的解決方案，但對「程式碼如何決定視覺結果」的系統性理解仍有待深化；最後，論文也暗示了需要發展更專門的視覺生成評估基準，因為通用能力評分已被證明無法有效預測這項能力。

## 實務應用指南

### 適用場景

1. **品牌行銷素材自動化生成**：電商或內容行銷團隊可透過 MaLiang-Harness 批次生成風格一致的產品海報、社群圖卡與短影音腳本。視覺程式能精準控制構圖、配色與版面，後續若需調整文案或替換產品圖，可透過 REV 機制回到特定修訂版本進行局部修改，避免每次重新生成導致風格漂移。

2. **教育與教材視覺化**：教師或教科書編輯可將抽象概念（如數學幾何、物理運動、化學反應）撰寫為可執行的視覺程式，自動產生示意圖與教學動畫。TGP 機制保留了完整的建構歷程，學生可逐步檢視每個視覺元素是如何被程式碼建構出來的，達到「看圖學程式」或「看程式學概念」的雙向學習。

3. **遊戲與動畫前期概念設計**：獨立遊戲開發者或動畫工作室可利用框架快速產出 2D 卡通、像素藝術、風格化 3D 等多樣風格的概念圖與動態分鏡。設計師能在同一個視覺程式上反覆迭代角色動作與場景配置，並透過渲染後端切換快速預覽不同美術風格。

4. **資料視覺化與資訊圖表生成**：研究機構或新聞媒體可將資料餵入 MLLM，由其生成對應的可執行視覺程式，自動產出符合出版品質的資訊圖表、長條圖、流程圖與示意動畫。PEG 狀態確保資料更新時圖表能同步修訂，且每次修改都有視覺驗證紀錄。

5. **創意短影音與社群內容產製**：內容創作者可輸入敘事腳本（如「水墨山水從墨漬暈開，漁船與涼亭逐漸浮現」），由 MLLM 生成對應的程式化動畫邏輯，渲染為帶有手繪風、像素風或混合媒材風格的短影片，並支援後續逐格修訂。

### 實作前置條件

**資料準備**
- 領域任務集：需蒐集欲生成視覺內容的提示詞範本、參考圖資產、版面規範文件（用於風格約束）。
- 評估資料集：建議參考 MaLiang-IBench 與 MaLiang-VBench 的任務設計，建立內部品質門檻（提示對齊度、美學、構圖、生成成功率）。
- 渲染後端資產：依目標風格準備 SVG、Canvas、Three.js、Manim、Blender 等渲染器的素材庫與字型檔。

**運算資源**
- MLLM API 額度：實驗顯示 GPT-6-Astra 在 50 個影像任務中需多次修訂迭代，建議預留足夠 token 與 API 成本預算。
- 渲染環境：本地或雲端需部署對應的渲染後端（瀏覽器、Python 環境、GPU 加速節點），影片生成另需較長的渲染時間。
- 儲存空間：每次修訂都會保留視覺程式、中介渲染結果與驗證紀錄，需規劃版本化儲存。

**技能門檻**
- 提示工程：熟悉如何引導 MLLM 產出結構化、可執行的視覺程式碼。
- 渲染器操作：至少熟悉一種渲染後端（SVG、Canvas、WebGL、Manim 等），以便診斷渲染失敗與調整視覺輸出。
- 視覺設計基礎：理解構圖、色彩、動態節奏等設計原則，才能有效設定品質門檻與修訂指引。
- 基礎程式能力：能閱讀 MLLM 生成的程式碼並進行除錯，特別是在 P2V 差距發生時介入修正。

### 實作步驟建議

1. **釐清任務範圍與風格需求**：先盤點目標視覺內容的類型（靜態圖、動畫、影片）、風格（線條、卡通、像素、3D、寫實）與品質指標。對照論文的創意風格覆蓋表，選定欲支援的渲染後端組合。

2. **建置 MaLiang-Harness 介接層**：依 GitHub 專案部署框架，串接欲使用的 MLLM API（GPT-6-Astra、GPT-5.6 系列等）與渲染後端。確認 PEG 狀態、TGP 紀錄、REV 驗證三個機制皆已啟用，並設定共同的修訂參考索引。

3. **設計提示詞與任務模板**：為不同視覺任務（海報、流程圖、動畫、編輯任務）撰寫結構化提示詞模板，明確指定構圖、外觀、動作需求，並提供必要參考圖資產。提示詞應引導 MLLM 在生成程式碼前先說明計畫。

4. **執行生成與視覺驗證**：啟動建構—檢查—修訂迴圈。讓 MLLM 先生成視覺程式並渲染，再透過視覺回饋判斷是否符合需求。對未達標項目，呼叫 REV 機制回到合適的修訂版本進行局部修改，每次提交前皆須通過完成檢查。

5. **建立品質評估管線**：導入 MaLiang-IBench 與 MaLiang-VBench 的評估指標（提示對齊、美學、構圖、生成成功率、時間效率、token 效率），定期評估所選 MLLM 在自家任務上的表現。論文顯示通用能力評分與視覺生成效能並非完全正相關，務必以視覺任務實測為準。

6. **迭代優化與成本控管**：根據評估結果調整提示詞、渲染後端與修訂策略。論文指出早期失敗會降低計算成本但也降低產出，可依任務重要性設定最大修訂次數與 token 上限，平衡品質與成本。

7. **導入版本管理與協作流程**：將 PEG 狀態中的視覺程式、建構歷史與驗證紀錄整合進團隊的版本控制系統（Git），讓設計師、工程師與專案經理能共同檢視每次修訂的視覺證據與決策依據。

### 潛在風險與注意事項

- **P2V 差距導致「程式對、視覺錯」**：即使 MLLM 產出可執行的程式碼，渲染結果仍可能違反構圖、外觀或動作需求。緩解方式：每次渲染後強制進行視覺驗證，並在 REV 機制下要求 MLLM 針對未達標項目提出具體修訂計畫，而非盲目重寫。

- **修訂過程中的連鎖破壞**：修改一個視覺元素可能影響先前已通過驗證的項目。緩解方式：每次提交修訂前皆執行完整的品質門檻檢查（不只檢查本次修改的項目），並善用 REV 的還原功能回到穩定版本。

- **模型選擇與成本落差**：論文實測顯示 GPT-6-Astra 達 100% 生成成功率，而 DeepSeek 與 Kimi 系列僅 12–40%。若預算有限而選用較弱模型，需預期更高的修訂次數與 token 消耗，整體成本未必較低。建議先以小樣本評估再決定主力模型。

- **渲染後端相容性問題**：不同渲染器對程式碼的支援範圍不同（例如 SVG 不支援 3D、Manim 偏向數學動畫），MLLM 生成的程式碼可能超出所選後端能力。緩解方式：在提示詞中明確告知可用後端與其限制，並在渲染失敗時自動切換至相容後端。

- **創意風格覆蓋不均**：論文表 1 顯示框架在「混合媒材與手工藝」與「照片寫實主義」僅部分支援。若業務高度仰賴這兩類風格，需評估是否需要額外整合擴散模型或專門的風格遷移模組作為補充。

- **評估指標的侷限性**：論文的排名圖表提醒讀者，排名不顯示效應大小，且早期失敗會降低成本數字。緩解方式：解讀評估結果時同時關注絕對分數與樣本覆蓋率，避免僅憑排名做決策。

- **可執行資產的資安風險**：視覺程式可能包含外部資源引用或動態載入邏輯，若用於商業產品需進行程式碼審查，避免引入惡意依賴或洩漏內部資產。

### 與其他技術的整合建議

- **與擴散模型互補**：MaLiang-Harness 擅長精確控制構圖與時空結構，但對細膩紋理與照片寫實風格支援有限。可將框架作為「版面與動作骨架」，再以 Stable Diffusion、FLUX 等擴散模型生成高擬真材質或背景，兩者透過 PEG 狀態中的資產層整合。

- **與設計工具串接**：將框架輸出的 SVG、Canvas 或 Three.js 程式碼匯入 Figma、Adobe Illustrator 等設計工具進行後製，或反向從設計工具匯入版面規範作為 MLLM 的約束條件。

- **與內容管理系統（CMS）整合**：透過 API 將 MaLiang-Harness 嵌入 WordPress、Webflow 等 CMS，讓行銷團隊在後台直接觸發視覺生成流程，並將每次修訂的視覺程式與渲染結果存入 DAM（Digital Asset Management）系統。

- **與工作流程自動化平台整合**：透過 n8n、Airflow 或 Zapier 等工具串接 MLLM API、渲染後端與審核流程，建立「提示輸入 → 程式生成 → 渲染 → 視覺驗證 → 人類審核 → 發布」的自動化管線。

- **與版本控制與 CI/CD 整合**：將視覺程式與渲染結果納入 Git 儲存庫，搭配 GitHub Actions 自動執行 MaLiang-IBench 評估，確保每次模型或提示詞變更皆經過品質門檻驗證後才能合併。

- **與多代理人系統整合**：可將 MaLiang-Harness 作為視覺生成代理人，與文案、企劃、審核等其他代理人組成多代理人協作系統，由規劃代理人下達需求、視覺代理人執行程式生成、審核代理人比對品質門檻。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節，理解「可程式化生成」相較於「直接視覺合成」的差異，以及 P2V 差距的概念。圖 1 展示了框架能處理的任務類型（角色、海報、推理編輯、創意影片），可作為想像應用場景的起點。技術細節可先跳過，專注於理解「建構—檢查—修訂」這個核心迴圈如何讓 AI 透過視覺回饋逐步改善作品。

**給 AI 工程師**：重點閱讀 PEG、TGP、REV 三個機制的設計細節，理解框架如何以「共同的修訂參考」串接程式、歷史與驗證。圖 2 的模型排名與品質數據值得仔細分析，特別是 GPT-6-Astra 與其他模型在生成成功率、token 效率上的落差，這對實際部署時的模型選型與成本估算至關重要。建議直接 clone GitHub 專案，從最小任務開始實作，逐步體驗修訂迴圈的行為。

**給研究者**：論文的關鍵貢獻在於將「程式到視覺的差距」形式化為 P2V gap，並提出可量化的評估基準（MaLiang-IBench、MaLiang-VBench）。可進一步探索的方向包括：不同渲染後端對 P2V 差距的影響、修訂次數與品質提升的邊際效益、多模態評估指標與人類判準的相關性，以及如何將框架擴展至 3D 場景或互動式媒體生成。表 1 的創意風格覆蓋矩陣也提示了尚未被充分研究的風格類型。

**給產品經理**：本框架的核心價值在於「可控、可編輯、可追溯」的視覺生成流程，這對需要大量視覺素材且要求風格一致的產品特別有用。建議先評估自家視覺任務中，有多少比例能以「構圖明確、動作可描述」的程式化方式表達，這將決定框架的適用範圍。論文的成本與效率數據（時間效率、token 效率排名）可作為預算規劃的參考，但務必以自家任務實測為準，因為通用能力評分與視覺生成效能之間存在落差。
