## 摘要翻譯

區塊擴散語言模型（Block Diffusion Language Models, BD-LMs）透過 KV 快取（KV Caching）與可變長度生成來改善基於擴散的文本生成。一個自然的後續步驟是將其從單區塊擴散（Single-Block Diffusion, SingleBD）延伸至多區塊擴散（Multi-Block Diffusion, MultiBD），其中連續區塊的運行集（running-set）會被並行解碼以實現區塊間並行（inter-block parallelism）。然而，現有的區塊擴散語言模型大多在教師強制（Teacher Forcing, TF）下進行訓練，模型僅觀察到一個以乾淨前綴（clean prefix）為條件的帶噪區塊（noisy block）。雖然近期的擴散強制（Diffusion Forcing）策略引入了多個帶噪區塊之間的可見性，其訓練狀態仍與多區塊擴散推論有所不同，其中解碼在具有異質槽位噪聲模式（heterogeneous slot-wise noise patterns）的有界運行集（bounded running-set）上運作。為彌合此差距，我們提出多區塊擴散語言模型（Multi-Block Diffusion Language Models, MBD-LMs），其係以多區塊教師強制（Multi-block Teacher Forcing, MultiTF）對區塊擴散語言模型進行後訓練（post-training）而得。多區塊教師強制整合了教師強制與擴散強制，透過在以乾淨前綴為條件的有界噪聲群組（noise-group）上進行訓練，並使用隨機化噪聲排程器（noise-scheduler）以更契合多區塊擴散推論狀態。為使多區塊擴散在實務上可執行，我們進一步提出一個基於區塊緩衝區機制（Block Buffer mechanism）的最佳化解碼演算法（decoding algorithm），該演算法保留前綴快取複用（prefix-cache reuse）、保持輸入形狀（input shapes）靜態，並將提升的解碼並行度（decoding parallelism）轉化為實際時間加速（wall-clock acceleration）。實證上，MBD-LLaDA2-Mini 將平均每次前向傳遞的詞元數（Tokens Per Forward pass, TPF）從 3.47 提升至 6.19，並將平均準確率（accuracy）從 79.95% 提升至 81.03%；當與 DMax 結合時，MBD-LLaDA2-Mini-DMax 在數學與程式碼基準測試（math and code benchmarks）上達到平均每次前向傳遞的詞元數 9.34，準確率僅下降 1.02%。

### 核心貢獻（3～5點）
- **統一框架的提出**：將區塊擴散語言模型（BD-LMs）從單區塊擴散（SingleBD）推廣至多區塊擴散（MultiBD），實現區塊間並行解碼，並提出多區塊擴散語言模型（MBD-LMs）作為統一視角。
- **訓練策略的整合**：提出多區塊教師強制（MultiTF），整合教師強制與擴散強制，透過在以乾淨前綴為條件的有界噪聲群組上訓練並使用隨機化噪聲排程器，有效解決訓練-推論不匹配（train-inference mismatch）問題。
- **實用化解碼演算法**：設計基於區塊緩衝區機制（Block Buffer mechanism）的最佳化解碼演算法，兼顧前綴快取複用、靜態輸入形狀與解碼-儲存重疊（decode-store overlap），使解碼並行度切實轉化為實際時間加速。
- **顯著的實證效能**：MBD-LLaDA2-Mini 將平均 TPF 從 3.47 提升至 6.19，準確率由 79.95% 提升至 81.03%；結合 DMax 後的 MBD-LLaDA2-Mini-DMax 更達到平均 TPF 9.34，且在數學與程式碼基準測試上僅損失 1.02% 準確率。

### 適合對象
從事擴散語言模型（Diffusion Language Models, DLMs）、區塊擴散語言模型（BD-LMs）、高效推論與平行解碼演算法研究的研究人員與工程師；對後訓練（post-training）策略、KV 快取機制最佳化及大型語言模型加速推論感興趣的學者；以及希望了解擴散式文本生成最新進展（特別是原生並行解碼與動態長度生成）的機器學習領域研究生與實務開發者。

## 深度分析

#### 方法論解析

本文提出了一套完整的技術方案，將傳統的區塊擴散語言模型（Block Diffusion Language Models, BD-LMs）從單區塊擴散（Single-Block Diffusion, SingleBD）範式擴展至多區塊擴散（Multi-Block Diffusion, MultiBD）範式。整體方法論可拆解為三個相互耦合的核心組件：

**1. 統一框架 MBD-LMs 的形式化**

作者將現有的 BD-LMs 重新表述為由「運行集」（running-set）參數化的統一框架。在這個視角下，傳統的教師強制（Teacher Forcing, TF）訓練得到的 BD-LMs 對應於運行集大小為 1 的極端情況，而 D2F（Discrete Diffusion Forcing）訓練得到的模型則對應於運行集覆蓋整個序列的極端情況。本文論證，實際可執行的 MultiBD 應處於這兩個極端之間的「有界中間區域」（bounded intermediate regime），即運行集大小受限且槽位間噪聲比率（noise-ratio）呈異質分佈（heterogeneous slot-wise noise patterns）。這個形式化框架的價值在於揭示了訓練-推論不匹配（train-inference mismatch）的本質——D2F 雖然引入了多個帶噪區塊的可見性，但其訓練狀態與推論時的運行集動態特性並不一致。

**2. MultiTF 後訓練策略**

多區塊教師強制（Multi-block Teacher Forcing, MultiTF）是本文的核心訓練方法，其設計動機是讓訓練狀態精確匹配 MultiBD 推論狀態。具體而言：

- **有界噪聲群組（bounded noise-group）**：訓練時將乾淨前綴（clean prefix）與一組連續的帶噪區塊（noisy block）拼接，使模型在單次前向傳遞中同時觀察到多個帶噪區塊。
- **群組感知雙流遮罩（Group-Aware Dual-Stream Mask）**：允許同一噪聲群組內的帶噪區塊互相注意（attend to each other），同時維持區塊因果（block-causal）的結構約束。
- **隨機化噪聲排程器（randomized noise-scheduler）**：在每個噪聲群組內採用更激進且隨機化的噪聲排程，以模擬推論時觀察到的異質槽位噪聲模式。圖 2 的 (A) 與 (B) 對比清楚展示了 D2F 風格的單調遞增噪聲排程器與本文提出的鏈式均勻（chain-uniform）排程器之間的差異——後者能更好地匹配圖 2(C) 所示的推論時遮罩比率分佈。
- **群組大小與相對位置的多樣化**：訓練時區塊被劃分為大小不同的群組，以涵蓋推論時可能出現的各種運行集大小與群組內相對位置。

**3. 基於區塊緩衝區的解碼引擎**

MultiBD 的動態運行集對 CUDA Graph 的捕獲與重播（capture and replay）不友善，因為輸入形狀（input shapes）會隨運行集變動而改變。為解決此問題，本文提出區塊緩衝區（Block Buffer）機制：

- **固定槽位數量**：Block Buffer 維持固定數量的區塊槽位，未來區塊透過啟動現有閒置槽位進入，而非擴展物理輸入。
- **前綴快取複用（prefix-cache reuse）**：完成的區塊在被提交至 KV 快取（KV Cache）後離開 Block Buffer，保留 KV 快取與前綴快取的複用能力。
- **靜態輸入形狀（static input shapes）**：由於槽位數量固定，輸入張量維度保持不變，使 CUDA Graph 能有效運作。
- **解碼-儲存重疊（decode-store overlap）**：透過雙層管線化（2-Level Pipelining），將已完成區塊的 KV 快取儲存與未來區塊的精煉過程重疊執行，消除 SingleBD 中的「儲存氣泡」（storing bubble）。

這三個組件形成一個閉環：MultiTF 解決訓練端的匹配問題，Block Buffer 解決推論端的執行效率問題，兩者共同使 MultiBD 從理論構想變為可實際部署的系統。

#### 實驗數據解讀

本文的實驗結果從三個維度驗證了所提方法的有效性：

**1. 解碼效率提升**

每次前向傳遞的詞元數（Tokens Per Forward pass, TPF）是衡量擴散語言模型並行解碼能力的核心指標。MBD-LLaDA2-Mini 將平均 TPF 從 3.47 提升至 6.19，增幅達 +78.4%。這個數字的意義在於：TPF 直接反映了模型在單次前向計算中能並行處理的詞元數量，提升近一倍意味著硬體利用率（特別是 GPU 的平行計算能力）獲得了顯著改善。當進一步結合 DMax 解碼策略時，MBD-LLaDA2-Mini-DMax 達到平均 TPF 為 9.34，相較於 LLaDA2-Mini-DMax 在 SingleBD 設定下提升 +47.1%。

**2. 生成品質維持**

效率提升若以犧牲品質為代價則意義有限。實驗顯示 MBD-LLaDA2-Mini 不僅未損失品質，反而將平均準確率（accuracy）從 79.95% 提升至 81.03%。這表明 MultiTF 的訓練-推論對齊策略不僅沒有引入負面偏差，反而透過更精確的訓練信號改善了模型表現。MBD-LLaDA2-Mini-DMax 在數學與程式碼基準測試（math and code benchmarks）上僅有 1.02 個百分點的準確率下降，這在效率大幅提升的背景下屬於可接受的權衡。

**3. 實際吞吐量增益**

更關鍵的是牆鐘時間（wall-clock time）層面的驗證。MBD-LLaDA2-Mini-DMax 在自建的推論引擎上達到平均 951.41 TPS（tokens per second），相比 LLaDA2-Mini-DMax 的 781.50 TPS 提升約 21.7%。這個數據證明了 Block Buffer 機制成功將 TPF 的理論提升轉化為實際的 TPS 增益——這在系統優化領域並非理所當然，因為動態運行集帶來的 CUDA Graph 不相容性往往會抵消理論上的並行優勢。

**4. 訓練-推論對齊的統計驗證**

圖 2 的 (D) 與 (E) 展示了推論時活躍區塊數量的均值與標準差範圍，以及取樣軌跡。在緩衝區大小為 4 的設定下，活躍區塊數量偶爾會超過 2，這說明 MultiBD 的運行集動態特性比 D2F 假設的更為複雜。圖 2(C) 比較了 MultiTF 後訓練前後的推論遮罩比率分佈，顯示後訓練使模型更好地適應了推論時的噪聲分佈，這從統計層面驗證了 MultiTF 設計的合理性。

#### 與現有研究的比較

**相較於 LLaDA2-Mini（Bie et al., 2025）**

LLaDA2-Mini 是當前 BD-LMs 的代表性工作，採用標準的 TF 訓練策略，僅支援 SingleBD。本文的核心改進在於將其擴展至 MultiBD 範式，在不犧牲品質的前提下大幅提升解碼效率。值得注意的是，本文採用後訓練（post-training）而非從頭訓練的方式，這大幅降低了將現有 BD-LMs 升級為 MBD-LMs 的成本。

**相較於 D2F（Wang et al., 2025）**

D2F 首次引入了多個帶噪區塊的可見性，是 MultiBD 概念的先驅。然而，本文精確指出了 D2F 的兩個關鍵缺陷：（1）訓練時處理整個帶噪後綴在效率與效能上均不可行；（2）D2F 的單調遞增噪聲排程器產生的訓練噪聲分佈與推論時的異質槽位噪聲模式不匹配。MultiTF 透過有界噪聲群組與隨機化噪聲排程器系統性地解決了這些問題。

**相較於 DMax（Chen et al., 2026）**

DMax 是一種解碼策略，本文將其與 MBD-LMs 結合使用，展示了兩種技術的互補性。值得注意的是，TPF 從 6.19 進一步提升至 9.34 表明 DMax 與 MultiBD 之間存在正向的乘法效應，而非簡單的疊加。

**相較於其他 BD-LMs（Arriola et al., 2025; Cheng et al., 2025）**

這些工作同樣基於區塊因果生成（block-causal generation）的範式，但未涉及多區塊並行解碼。本文提出的統一 MBD-LM 框架在概念上涵蓋了這些工作作為特例，同時識別出實際可部署的中間區域。

**侷限性**

- 本文僅在 LLaDA2-Mini 規模上進行驗證，更大規模模型（如 7B、70B 參數）的可擴展性尚未確認。
- 緩衝區大小（buffer-size）目前是固定超參數，缺乏自適應機制。
- 噪聲排程器的隨機化策略雖然有效，但其理論最優性尚未嚴格論證。
- 評測集中在數學與程式碼基準測試，在開放式生成任務上的表現有待驗證。

## 論文問答

**Q1：現有的區塊擴散語言模型（BD-LMs）面臨什麼核心問題？**
A：現有的 BD-LMs 主要在「教師強制」（Teacher Forcing, TF）下訓練，因此僅支援單區塊擴散（SingleBD）推論。在 SingleBD 中，模型每次前向傳遞只能解碼一個帶噪區塊，前面的區塊必須先完成解碼並儲存 KV 快取後，後續區塊才能開始處理。這種循序執行的方式會產生所謂的「儲存氣泡」（storing bubble），也就是在儲存 KV 快取期間完全沒有詞元被生成，造成 GPU 資源的閒置浪費。此外，區塊間的並行性也被鎖住，無法充分利用現代硬體的平行計算能力，使得擴散語言模型相較於自回歸模型的效率優勢大打折扣。

**Q2：為什麼 D2F（離散擴散強制）策略會產生訓練-推論不匹配的問題？**
A：D2F 雖然引入了多個帶噪區塊的可見性，使模型具備多區塊擴散（MultiBD）能力，但其訓練狀態與實際 MultiBD 推論時的狀態存在明顯落差。具體而言，D2F 在訓練時對整個帶噪後綴施加單調遞增的噪聲比率，但實務上不可能將整個帶噪後綴作為單一運行集（running-set）一次處理，因為這在效率與效能上都不可行。實際 MultiBD 推論時，運行集大小通常僅約為二，且相鄰槽位之間的噪聲比率差距很大，而 D2F 的訓練分布無法對應這種「有界運行集」與「異質槽位噪聲模式」的推論特性，導致模型在推論時表現不穩定。

**Q3：為什麼實現可靠的 MultiBD 對於擴散語言模型的實用化至關重要？**
A：可靠的 MultiBD 是擴散語言模型能否真正取代或補充自回歸模型的關鍵，因為它直接決定了模型的吞吐量與部署成本。透過區塊間並行與解碼-儲存重疊（decode-store overlap），MultiBD 能將每次前向傳遞生成的詞元數（TPF）大幅提升，進而轉化為實際的牆鐘時間加速（wall-clock acceleration）。如果無法解決訓練-推論不匹配問題，模型即使在訓練時學會了多區塊可見性，也會在推論時因為狀態分布差異而產生品質下降或效率損失，使得擴散語言模型的「原生並行解碼」優勢無法兌現。

**Q4：Multi-block Teacher Forcing（MultiTF）的核心設計理念是什麼？**
A：MultiTF 的核心設計理念是將教師強制與擴散強制整合起來，透過在「有界噪聲群組」（noise-group）上進行訓練，使訓練狀態更貼近實際 MultiBD 推論時的狀態分布。具體而言，MultiTF 將乾淨前綴與一組大小有界的連續帶噪區塊串接起來，並使用「群組感知雙流遮罩」（Group-Aware Dual-Stream Mask）讓帶噪區塊之間可以互相注意。同時，MultiTF 在每個噪聲群組內採用更積極且隨機化的噪聲排程器（noise-scheduler），以模擬推論時觀察到的異質槽位噪聲模式，並透過變動的群組大小與群組相對位置來涵蓋所有可能的運行集大小。

**Q5：什麼是「區塊緩衝區」（Block Buffer）機制，它為什麼對 MultiBD 推論至關重要？**
A：區塊緩衝區機制是一種專為 MultiBD 設計的最佳化解碼演算法，其核心思想是維持固定數量的區塊槽位，而非動態擴展實體輸入長度。當未來的區塊進入時，它們會啟用既有的閒置槽位；當前方的區塊完成後，它們會在被提交至 KV 快取後離開緩衝區。這種設計帶來三項關鍵優勢：保留前綴快取複用（prefix-cache reuse）、保持輸入形狀靜態（static input shapes）以便 CUDA Graph 的擷取與重播，以及將增加的解碼並行度轉化為實際的牆鐘時間加速。如果沒有這個機制，MultiBD 的動態運行集會與 CUDA Graph 不相容，導致 TPF 的提升無法反映在真實的 TPS 增益上。

**Q6：本文提出的統一 MBD-LM 框架如何涵蓋現有的 BD-LM 變體？**
A：統一 MBD-LM 框架以「運行集」（running-set）中的連續區塊數量作為參數化變數，將所有 BD-LM 變體視為此參數的不同設定。當運行集大小為一時，框架退化為 TF 訓練的傳統 BD-LM（即 SingleBD）；當運行集大小趨近於整個帶噪後綴時，框架則對應 D2F 訓練的極端情況。而實務上可靠的 MultiBD 落在這個參數空間的中間區域——即「有界中間狀態」——這正是 MultiTF 所瞄準的訓練目標。這種統一視角不僅釐清了不同 BD-LM 變體之間的關係，也明確指出哪些訓練設定能對應到實際可部署的推論行為。

**Q7：本文的主要實驗結果為何？**
A：在數學與程式碼基準測試上，MBD-LLaDA2-Mini 將平均 TPF 從 3.47 提升至 6.19（+78.4%），同時將平均準確率從 79.95% 提升至 81.03%。當與 DMax 解碼策略結合後，MBD-LLaDA2-Mini-DMax 進一步達到平均 TPF 為 9.34，相較於 SingleBD 下的 LLaDA2-Mini-DMax 提升了 47.1%，且僅有 1.02 個百分點的準確率下降。在實際吞吐量方面，使用本文推論引擎後，MBD-LLaDA2-Mini-DMax 達到平均 951.41 TPS，相較於 LLaDA2-Mini-DMax 的 781.50 TPS 有顯著提升，證明了 TPF 的提升能有效轉化為真實的部署效率改善。

**Q8：MBD-LLaDA2-Mini 相較於基礎模型 LLaDA2-Mini 有哪些具體改進？**
A：MBD-LLaDA2-Mini 透過 MultiTF 後訓練將 LLaDA2-Mini 升級為 MBD-LM，在不犧牲生成品質的前提下大幅提升解碼並行度。具體而言，平均 TPF 從 3.47 增加到 6.19，意味著每次前向傳遞能生成近兩倍的詞元；同時平均準確率從 79.95% 微幅上升至 81.03%，證明了 MultiTF 不僅沒有損害模型品質，反而略有改善。這顯示 MultiTF 透過更好的訓練-推論對齊，不僅提升了效率，也讓模型在異質槽位噪聲模式下的生成更加穩定。

**Q9：訓練-推論對齊分析（圖 2）揭示了哪些關鍵現象？**
A：圖 2 的分析顯示，D2F 風格的單調排程器所產生的槽位噪聲分布（圖 2A）與實際推論時的遮罩比率分布（圖 2C）之間存在顯著落差，特別是相鄰槽位之間的噪聲差距過大。相比之下，本文提出的「鏈式均勻」（Chain Uniform）排程器（圖 2B）能更好地匹配推論時的噪聲分布。圖 2D 與 2E 進一步顯示，在緩衝區大小為四的設定下，運行集中的活躍區塊數平均約為二，但偶爾會超過二，這說明了 MultiBD 推論時的運行集大小具有動態性與異質性，需要訓練時涵蓋多種可能的群組大小才能可靠支援。

**Q10：MBD-LMs 在實際應用場景中適合哪些任務？**
A：MBD-LMs 特別適合需要高吞吐量與低延遲的批次生成任務，例如數學推理、程式碼生成與長文本摘要等，這些正是本文實驗所聚焦的基準測試。在這些場景中，模型需要在保持生成品質的同時最大化 GPU 利用率，而 MultiBD 的解碼-儲存重疊與區塊間並行正好能滿足此需求。此外，由於 MBD-LMs 保留了 KV 快取與動態長度生成能力，也適用於對話系統、文件生成等需要可變輸出長度的應用，使其在實際部署中比傳統的雙向擴散語言模型更具彈性。

**Q11：這項研究對語言模型部署領域有什麼更廣泛的影響？**
A：本研究最重要的影響在於證明了擴散語言模型可以同時兼顧效率與品質，挑戰了「擴散模型必然比自回歸模型慢」的傳統印象。透過 MultiTF 與區塊緩衝區機制，MBD-LMs 展示了訓練-推論對齊的重要性，這個原則也適用於其他生成式模型的設計。更廣泛地說，這項工作為擴散語言模型在工業級部署中的可行性提供了實證基礎，可能促使更多服務提供商考慮將 DLMs 作為自回歸模型的補充或替代方案，特別是在需要大量平行生成的場景中。

**Q12：從產品化的角度，這項工作帶來哪些考量？**
A：從產品化角度，MBD-LMs 提供了在不增加硬體成本的前提下提升服務吞吐量的途徑，這對於成本敏感的雲端推論服務特別有吸引力。區塊緩衝區機制對 CUDA Graph 的相容性意味著現有的推論服務框架可以相對容易地整合這項技術。然而，產品化時也需要考慮 MultiTF 後訓練所帶來的額外訓練成本，以及不同任務領域可能需要重新進行後訓練以達到最佳效果。此外，動態運行集大小雖然提升了效率，但也增加了系統監控與資源調度的複雜度，需要相應的工程支援。

**Q13：本文所提及的方法有哪些已知的限制？**
A：本文坦誠地指出，MultiTF 雖然改善了訓練-推論對齊，但仍屬於後訓練方法，需要在預訓練的 BD-LM 基礎上進行額外的訓練，這增加了整體的訓練成本。此外，雖然平均 TPF 達到 9.34，但相較於完全雙向擴散語言模型的理論上限仍有差距，且在某些任務上會出現 1.02 個百分點的準確率下降，說明效率與品質之間仍存在取捨。緩衝區大小作為關鍵超參數，其最佳值可能因任務與序列長度而異，目前缺乏自動調整的機制。

**Q14：在什麼情況下 MBD-LMs 可能會失敗或表現不佳？**
A：當輸入序列極短或極長時，MBD-LMs 的表現可能不如預期，因為緩衝區大小是針對中等長度序列進行最佳化的；極短序列可能無法充分利用區塊間並行，而極長序列則可能因為噪聲分布的異質性更為顯著而影響品質。此外，在需要嚴格邏輯一致性或長程依賴的任務中，異質槽位噪聲模式可能導致某些區塊的解碼品質不穩定，進而影響整體輸出的連貫性。當任務領域與訓練資料分布差異極大時，後訓練的 MultiTF 可能無法完全遷移，導致效率提升但品質下降的情況。

**Q15：基於這項工作，未來有哪些值得探索的研究方向？**
A：未來值得探索的方向包括：將 MultiTF 的訓練-推論對齊原則擴展到其他類型的擴散模型（如連續空間的擴散模型或多模態擴散模型）；研究自適應的緩衝區大小調整機制，以根據任務與序列特性動態最佳化並行度；探索 MultiTF 與其他解碼策略（如 DMax）的更深層整合，進一步突破效率-品質的取捨邊界。此外，也可以研究如何將 MBD-LMs 與投機解碼（speculative decoding）或蒸餾技術結合，在更廣泛的部署場景中實現效率與品質的雙重提升。

## 實務應用指南

### 適用場景

1. **長篇幅文件批次生成**：新聞報章、技術文件、研究報告等需要數千詞元連續輸出的場景。MBD-LMs 將平均 TPF 從 3.47 提升至 6.19（+78.4%），可在維持品質的前提下大幅縮短批次生成時間，特別適合新聞媒體後台、內容農場與自動化報告系統。

2. **程式碼補全與多檔案重構**：IDE 插件或 CI/CD 流程中需要同時生成多個函式、類別或檔案區塊的情境。區塊間並行（inter-block parallelism）讓模型能在同一個前向傳遞中推進多個程式碼區塊的草稿，特別適合 Copilot 類工具的多游標補全與重構建議。

3. **即時對話與串流客服**：對延遲敏感的聊天機器人、語音助理後端。MBD-LLaDA2-Mini-DMax 達到 951.41 TPS（相較 LLaDA2-Mini-DMax 的 781.50 TPS 提升約 21.7%），可在不犧牲太多準確率（僅下降 1.02 個百分點）的情況下提供更流暢的回應體驗。

4. **數學推理與競程式解題服務**：教育科技、競賽訓練平台需要即時生成多步驟解題過程。實驗在數學與程式碼基準上驗證 MBD-LMs 在維持解題正確率的同時提升吞吐量，適合 AoPS 類解題助手與 LeetCode 風格的練習平台。

5. **邊緣部署與低資源推論**：在單張消費級 GPU 上提供高品質文字生成的服務。透過 Block Buffer 機制保持靜態輸入形狀，可充分利用 CUDA Graph 加速，降低單次推論成本，適合本地化 LLM 服務、小型 SaaS 與隱私敏感場景。

### 實作前置條件

**資料需求**
- 預訓練完成的 BD-LM 權重（如 LLaDA2-Mini 或同等規模的區塊擴散模型），作為後訓練起點。
- 用於 MultiTF 後訓練的文本或程式碼語料，建議規模在數十億詞元等級，並具備清晰的區塊切分結構（如自然段落、函式邊界）。
- 評測資料集：數學基準（如 GSM8K、MATH）與程式碼基準（如 HumanEval、MBPP）以驗證準確率變化。

**運算資源**
- 後訓練階段：建議至少 8 張 A100/H100 等級 GPU，支援 bf16/fp16 混合精度與 Flash Attention。
- 推論階段：單張 GPU 即可部署 MBD-LMs，但需支援 CUDA Graph capture/replay 以發揮 Block Buffer 的靜態輸入優勢。
- 記憶體規劃：KV 快取加上 Block Buffer 的額外槽位會增加常駐記憶體，需預留至少 1.3–1.5 倍於原 BD-LM 的 KV 快取空間。

**技能門檻**
- 熟悉擴散語言模型的訓練流程（遮罩排程、雜訊注入、損失函數設計）。
- 具備 CUDA Graph、KV 快取管理與推論引擎優化經驗（熟悉 vLLM、SGLang 或自研推論框架者尤佳）。
- 了解區塊因果遮罩（block-causal masking）與注意力模式設計，能正確實作 Group-Aware Dual-Stream Mask。

### 實作步驟建議

1. **盤點現有 BD-LM 並建立基準**：選定一個 TF 訓練的 BD-LM（如 LLaDA2-Mini），先以 SingleBD 推論跑完整基準測試，記錄 TPF、TPS 與各任務準確率，作為後續比較的對照組。

2. **設計 MultiTF 訓練管線**：
   - 將訓練樣本切成區塊，定義 `running-set` 大小範圍（例如 2–4 個區塊）。
   - 實作 Group-Aware Dual-Stream Mask，使同一噪聲群組內的帶噪區塊可互相看見，但僅以前方的乾淨前綴為條件。
   - 採用 chain-uniform 或更激進的隨機化噪聲排程器，模擬推論時的異質槽位噪聲模式（slot-wise mask ratio），避免 D2F 單調遞增排程造成的訓練-推論落差。

3. **執行後訓練**：以中等學習率（例如 1e-5 至 5e-5）對 BD-LM 進行數千步的 MultiTF 微調，監控損失曲線與下游任務準確率，避免過度擬合到特定區塊大小。

4. **實作 Block Buffer 推論引擎**：
   - 預先配置固定數量的區塊槽位（buffer size），輸入張量形狀保持靜態。
   - 設計槽位啟用/釋放邏輯：完成的區塊提交至 KV 快取後釋放槽位，後續區塊填入閒置槽位而非擴充實體輸入。
   - 整合 CUDA Graph capture，確保整個解碼管線可在靜態輸入下重播。

5. **整合解碼策略**：可選擇性加入 DMax 等進階解碼策略以進一步提升 TPF；同時保留 prefix-cache reuse 機制，避免重複計算已完成的區塊。

6. **建立 2-Level Pipelining**：將「KV 快取儲存」與「下一輪解碼」重疊執行，消除 storing bubble，使解碼並行度真正轉化為牆鐘時間加速。

7. **全面評測與調校**：在數學、程式碼與開放式生成任務上比較 MBD-LM 與原 BD-LM 的 TPF、TPS 與準率，繪製準確率-吞吐量 Pareto 曲線，選定符合產品需求的運行點。

8. **部署與監控**：將推論引擎包裝為 API 服務，加入請求排隊、動態 buffer size 調整與延遲監控，確保線上穩定性。

### 潛在風險與注意事項

- **訓練-推論不匹配（train-inference mismatch）**：若直接採用 D2F 的單調遞增噪聲排程，會造成訓練時的槽位噪聲分布與推論時差異過大，導致品質下降。緩解方式：採用 chain-uniform 等隨機化排程器，並在訓練時覆蓋多個 running-set 大小與群組相對位置。

- **過度激進的並行導致品質崩塌**：buffer size 過大或噪聲排程過於激進時，平均準確率可能顯著下滑。緩解方式：以小 buffer（如 2）起步，逐步放大並監控準確率-吞吐量權衡；必要時退回 SingleBD。

- **CUDA Graph 相容性陷阱**：動態輸入形狀會破壞 CUDA Graph 的 capture 與 replay。緩解方式：嚴格遵守 Block Buffer 的靜態輸入設計，所有動態行為（槽位啟用、KV 提交）都應在固定張量維度內完成。

- **KV 快取記憶體膨脹**：區塊緩衝區會讓多個區塊同時佔用 KV 快取空間，長序列場景下可能觸發 OOM。緩解方式：實作 KV 快取分頁（paged KV cache）或在長度超過閾值時自動降級為 SingleBD。

- **後訓練成本與資料偏差**：MultiTF 需要重新訓練，資料若與原 BD-LM 預訓練分布差異過大，可能引發災難性遺忘。緩解方式：混入原預訓練資料、控制後訓練步數，並保留完整的預訓練權重以便回退。

- **解碼策略耦合風險**：DMax 等策略對噪聲排程敏感，與 MultiTF 結合時可能產生非預期交互。緩解方式：先在 SingleBD 上驗證 DMax 增益，再逐步切換到 MultiBD 並重新校準超參數。

### 與其他技術的整合建議

- **自回歸語言模型混合架構**：在需要強 KV 快取與動態長度的場景，可將 MBD-LMs 部署為「草稿生成器」，搭配自回歸模型做精修；或在長序列開頭使用自回歸、結尾切換到 MBD-LMs 以兼顧品質與速度。

- **現有推論框架**：vLLM、SGLang、TensorRT-LLM 等框架已對 BD-LMs 有初步支援。建議在其基礎上擴充 Block Buffer 模組與 Group-Aware Dual-Stream Mask 注意力核，避免從零打造推論引擎。

- **強化學習與偏好對齊**：MBD-LMs 可與 DPO、PPO 等對齊方法結合，但需注意擴散模型的獎勵信號設計與區塊級信用分配（credit assignment），避免在異質噪聲槽位間產生偏差。

- **檢索增強生成（RAG）**：將 MBD-LMs 作為生成器，前置檢索結果作為乾淨前綴輸入。由於 prefix-cache reuse 機制可保留，重複檢索的相同前綴不會造成額外計算成本。

- **多模態擴展**：Block Diffusion 的概念可延伸至圖文交錯生成，MBD-LMs 的多區塊並行機制適合處理多個圖片區塊或影片幀的並行去噪。

- **分散式推論**：在多 GPU 環境中，可將不同區塊分配到不同裝置並行解碼，Block Buffer 的靜態輸入設計有助於張量平行（tensor parallelism）與管線平行（pipeline parallelism）的實作。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的動機與圖 1，理解「為什麼區塊擴散語言模型需要多區塊並行」這個核心問題。接著看圖 2 的訓練-推論噪聲分布對比，直觀感受 train-inference mismatch 的影響。數學細節可先跳過，重點掌握 TPF、TPS 與準確率三個指標的權衡關係即可。

**給 AI 工程師**：應聚焦於第 1 節的 Block Buffer 機制設計與 MultiTF 訓練流程。建議直接閱讀論文中關於 Group-Aware Dual-Stream Mask、chain-uniform 噪聲排程器與 2-Level Pipelining 的章節，並嘗試在現有 BD-LM 推論框架中實作 Block Buffer 的靜態輸入管理與 CUDA Graph 整合。

**給研究者**：第 2 節的統一 MBD-LM 框架與噪聲排程器分析是重點。建議仔細推導 running-set 大小、槽位噪聲異質性與推論可靠性的理論關係，並將 MultiTF 與 D2F、傳統擴散強制等方法做嚴格比較。圖 2 的 (D)(E) 軌跡圖提供了進一步分析動態行為的素材，值得深入探究。

**給產品經理**：重點關注實驗結果段落中的 TPF 提升（3.47 → 6.19）、TPS 提升（781.50 → 951.41）與準確率變化（79.95% → 81.03%，結合 DMax 時僅下降 1.02 個百分點）。這些數字可直接轉化為成本估算與使用者體驗改善的論據，並用於評估在自家產品線中的導入優先順序。
