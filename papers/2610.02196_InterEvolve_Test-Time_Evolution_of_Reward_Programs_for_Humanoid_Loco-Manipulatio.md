## 摘要翻譯

我們研究人形機器人移動操作（humanoid loco-manipulation）的測試時演化（test-time evolution）：在無需重新訓練（without retraining）的情況下，透過重新利用（repurposing）控制器（controller）的現有技能（existing skills）、從自身嘗試中學習改進，並保留所學，以解決控制器從未受過訓練的任務。我們的核心洞察是，一個廣泛能力控制器（broad controller）已具備新任務所需的大部分運動能力（motor competence），而此能力可透過規劃與控制介面（interface between planning and control）加以調用；該介面具備足夠強的表達能力（expressive）以描述接觸豐富（contact-rich）、多階段互動（multi-stage interactions），同時又足夠可執行（executable）且可衡量（measurable），使執行回饋（execution feedback）能從經驗引導規劃（guide planning from experience）。InterEvolve 透過兩個元件實現此介面。首先，我們開發了一個物件感知前向-反向（FB）行為基礎模型（object-aware forward-backward (FB) behavioral foundation model），其在凍結身體先驗（frozen body prior）上學習的物件殘差（object residuals），能於測試時將關於身體（body）或物件（objects）的新獎勵（new reward）轉化為移動操作行為（loco-manipulation behavior）。其次，我們將任務指定為獎勵程式（reward programs）：具有完成條件（completion conditions）與可調常數（tunable constants）的分階段獎勵（staged rewards）。一個大型語言模型（LLM）智慧體（LLM agent）依情境（in context）修訂程式結構（program structure），參酌執行回饋與儲存已驗證程式（verified programs）的技能庫（skill library），同時數值最佳化器（numerical optimizer）調整其常數。每個候選程式（candidate）皆於平行模擬情境（parallel simulation scenarios）中驗證，藉此探索誘導（induce）、重新利用與組合（compose）控制器現有運動能力以完成當前任務的新方法，並在迭代過程中持續改進。實驗顯示，人類設計的獎勵（human-designed rewards）讓 FB 模型的移動操作能力仍有許多未被發揮（untapped competence），而 InterEvolve 演化出的獎勵程式則能釋放這些能力，有時甚至透過新穎策略（novel strategies）實現。它更在模擬（simulation）中產生適用於多樣化任務（diverse tasks）、複雜場景（complex scenes）與長時程組合任務（long-horizon compositions）的行為，且演化出的技能可在實體 Unitree G1（physical Unitree G1）上，僅憑自我中心機載感知（egocentric onboard perception）即自主運行（run autonomously）。

### 核心貢獻（3～5點）
- 提出測試時演化（test-time evolution）框架 InterEvolve，使廣泛能力控制器（broad controller）無需重新訓練（without retraining）即可透過重新利用（repurposing）與組合（compose）現有技能（existing skills）來解決新任務。
- 設計兼具表達能力（expressive）、可執行性（executable）與可衡量性（measurable）的規劃與控制介面（interface between planning and control），以獎勵程式（reward programs）描述接觸豐富（contact-rich）的多階段互動（multi-stage interactions），並以執行回饋（execution feedback）引導規劃。
- 開發物件感知前向-反向（FB）行為基礎模型（object-aware forward-backward behavioral foundation model），利用凍結身體先驗（frozen body prior）與物件殘差（object residuals）將關於身體或物件的新獎勵（new reward）轉化為移動操作行為（loco-manipulation behavior）。
- 結合大型語言模型（LLM）智慧體（LLM agent）與數值最佳化器（numerical optimizer），在平行模擬情境（parallel simulation scenarios）中迭代演化並驗證獎勵程式，釋放控制器未發揮的運動能力（untapped motor competence）。
- 在模擬（simulation）中驗證多樣化任務、複雜場景與長時程組合任務，並將演化出的技能部署於實體 Unitree G1（physical Unitree G1），僅憑自我中心機載感知（egocentric onboard perception）自主運行。

### 適合對象
對人形機器人、移動操作、測試時適應、獎勵設計、大型語言模型（LLM）與強化學習有興趣的研究者與工程師；特別適合關注如何在不重新訓練的情況下讓機器人從自身嘗試中學習、將模擬技能遷移至真實機器人，以及處理接觸豐富、長時程複合任務的讀者。

## 深度分析

#### 方法論解析

InterEvolve 的核心主張是將「任務專屬計算（task-specific compute）」從傳統的重新訓練（retraining）轉移到測試時演化（test-time evolution）：面對一個從未訓練過的新任務時，固定不動的控制器（controller）仍能透過不斷嘗試與回饋，重新利用（repurposing）其既有的運動能力（motor competence），並把驗證過的經驗保留到技能庫（skill library）中供後續任務使用。整個方法可以拆解為兩大支柱：一個可執行新獎勵（reward）的物件感知前向-反向行為基礎模型（object-aware forward-backward (FB) behavioral foundation model），以及一套由大型語言模型（LLM）與數值最佳化器共同演化的獎勵程式（reward programs）。

**1. 物件感知 FB 行為基礎模型**

傳統的 humanoid FB 模型通常只觀察機器人身體狀態，因此當獎勵僅在物件目標上有所不同時，容易坍縮成相同的行為。InterEvolve 的解決方式是在凍結的身體先驗（frozen body prior）之上附加可訓練的物件殘差（object residuals），這些殘差讀取場景物件特徵，並且在大規模人類-物件互動（human-object interaction, HOI）資料上訓練。這樣一來，模型可以在測試時把一個關於身體或物件的新獎勵轉換成對應的潛在變數（latent），再從固定策略中誘導出全身移動操作行為（loco-manipulation behavior），無需重新訓練策略網路。這相當於在規劃（planning）與控制（control）之間建立了一個「可執行且可衡量」的介面：規劃層提出獎勵目標，控制層透過 FB 模型立即產生行為，並回傳執行回饋（execution feedback）。

**2. 獎勵程式與測試時演化**

獎勵程式並非單一純量函數，而是由多個階段（stages）組成，每個階段包含一個分階段獎勵（staged reward）、完成條件（completion condition），以及可調常數（tunable constants，如權重與閾值）。這種結構讓任務描述既具備表達能力（expressive）——能夠刻畫接觸豐富（contact-rich）與多階段互動（multi-stage interactions）——又具備可衡量性，讓執行結果可以明確告訴規劃器哪裡失敗。

演化流程採用雙層搜尋：

- **外層結構搜尋**：由 LLM agent 負責。它根據任務意圖與來自平行模擬情境（parallel simulation scenarios）的執行回饋，在上下文情境中（in context）修訂程式結構（program structure），例如新增、刪除或重排階段、改變獎勵項、參考技能庫中已驗證程式（verified programs）的經驗。
- **內層常數搜尋**：對每一個 LLM 提出的結構，使用 CMA-ES（covariance matrix adaptation evolution strategy）調整其可調常數。由於一個好的結構仍可能因權重或閾值不佳而失敗，因此結構與常數必須共同搜尋。

每個候選程式（candidate）都會在多個平行模擬情境中驗證，確保其對初始條件與擾動具有穩健性。成功的程式會被摘要並存入技能庫（skill library），後續新任務可以檢索這些經驗，避免從頭探索。這整個過程體現了測試時規模化（test-time scaling）的精神：花費更多推論階段的計算來換取更好的任務解決方案。

#### 實驗數據解讀

從摘要與引言可以歸納出實驗設計的三個層次：與人類設計獎勵的比較、多樣化與長時程任務的模擬驗證，以及真實機器人部署。

**1. 人類設計獎勵 vs. 演化後獎勵程式**

論文指出，人類設計的獎勵（human-designed rewards）往往無法充分發揮 FB 模型的移動操作潛能。以「將箱子翻轉到另一個面（box tip）」為例，這個行為並未出現在訓練資料中，但控制器其實已經具備推、抬、搬運等相關動作單元。人類手工設計的獎勵容易流於「駭取」（hacking）特定行為，結果失敗；而 InterEvolve 演化出的獎勵程式則能誘導出新的身體使用方式（novel body use）並成功完成任務。這說明關鍵不只是控制器的能力，而是「如何透過獎勵介面把潛能釋放出來」。

**2. 多樣化任務、複雜場景與長時程組合**

實驗進一步展示 InterEvolve 能處理多樣化任務（diverse tasks）、複雜場景（complex scenes）以及長時程組合（long-horizon compositions），例如「搬運箱子、放置、再踢開」這類由多個子任務串接的序列。由於獎勵程式天然支援階段分解（stage decomposition），這類長期任務可以透過組合（compose）與重新利用（repurpose）既有技能來完成，而不需要為每個新任務重新收集示範或重新訓練。

**3. 真實機器人部署**

最值得注意的是，演化後的技能能夠在實體 Unitree G1 上自主運行（run autonomously），僅依靠自我中心機載感知（egocentric onboard perception）。這顯示模擬中演化出的獎勵程式具備一定程度的模擬到真實（sim-to-real）遷移能力，也驗證了整個介面在真實硬體上的可執行性。

**4. 結果意義**

整體而言，實驗結果支持兩個核心論點：第一，成功機率隨著演化迭代而提升，顯示測試時演化確實能從自身嘗試中學習；第二，累積的技能庫能夠指導未來任務，說明跨任務經驗保留（experience retained across tasks）具有實際價值。雖然摘要中未提供詳細數值表格，但從「reference tracking 與 goal-conditioned tasks 的成功率隨演化增長」這一描述可以推斷，論文應該有量化曲線展示演化過程中的進步。

#### 與現有研究的比較

**1. 相較於傳統任務介面**

現有人形機器人控制常見的任務介面包括動作參考（motion references）、目標狀態（goal states）與技能標籤（skill labels）。這些介面各有侷限：motion references 需要為每個新任務準備參考軌跡；goal states 難以表達接觸豐富的細膩互動；skill labels 則受限於預先定義的技能集合。相較之下，reward programs 提供了更高的表達能力，同時透過完成條件與可調常數保留了可執行性與可衡量性。

**2. 相較於需要重新訓練的獎勵設計**

許多獎勵塑造（reward shaping）方法雖然表達力強，但每一次修改獎勵都需要重新訓練一個策略，迭代成本高昂。InterEvolve 透過 FB 行為基礎模型把獎勵直接映射到固定策略的行為，使得「嘗試-回饋-修正」的迴路可以在測試時快速進行，這是方法論上最大的區別。

**3. 相較於單獨使用 LLM 設計獎勵**

近期也有研究利用 LLM 自動撰寫獎勵函數，但多數仍搭配 RL 訓練。InterEvolve 的獨特之處在於把 LLM 的角色限定在「結構搜尋」，而將常數調整交給 CMA-ES，並透過平行模擬提供結構化回饋。這種分工讓 LLM 的語言推理能力與數值最佳化器的局部搜尋能力互補，也減少了單純依賴 LLM 產生可執行程式時常見的幻覺（hallucination）風險。

**4. 相較於現有 FB 模型**

現有 humanoid FB 模型多僅觀察身體狀態，無法區分僅在物件目標上不同的獎勵。InterEvolve 引入物件殘差（object residuals）與 HOI 資料訓練，使 FB 模型具備物件感知能力，這是將 FB 框架擴展到移動操作任務的關鍵改進。

**5. 侷限性**

儘管如此，InterEvolve 仍有明顯限制。首先，整個方法的上限受困於凍結控制器的既有運動能力；如果新任務所需動作根本不在控制器的能力範圍內，則無法透過獎勵程式彌補。其次，物件殘差的訓練依賴大規模 HOI 資料，資料品質與多樣性會直接影響泛化能力。第三，雖然論文展示了真實機器人部署，但模擬到真實的遷移仍可能受限于物理差異與感知誤差。第四，LLM 的結構搜尋需要足夠的計算預算與良好的提示工程（prompt engineering），且對於極度抽象或難以量化的任務，獎勵程式的設計仍具挑戰。最後，安全性（safety）與約束條件在摘要與引言中並未明確討論，這對於真實機器人長期自主運行至關重要。

#### 可重現性評估

從提供的文本來看，論文僅給出專案頁面（project page）連結，並未明確說明是否開源程式碼、資料集或模型權重。因此，目前可重現性（reproducibility）處於「待確認」狀態。若要完整重現 InterEvolve，研究者至少需要以下資源：

- 物件感知 FB 行為基礎模型的權重與推論程式；
- 用於訓練物件殘差的人類-物件互動（HOI）資料集；
- 平行模擬環境（parallel simulation scenarios）與任務設定；
- LLM agent 的提示模板（prompt templates）與技能庫（skill library）檢索機制；
- CMA-ES 的搜尋參數與可調常數範圍；
- 真實機器人 Unitree G1 的部署配置與機載感知（onboard perception）介面。

建議作者釋出上述關鍵元件，特別是預訓練的 FB 模型權重與標準化任務集合，以促進社群驗證與後續研究。若僅有專案頁面而無程式碼，則可重現性會相對有限。

#### 未來研究方向

**1. 真實世界線上適應**

目前的演化主要在模擬中進行，再遷移到真實機器人。未來可以研究如何直接在真實環境中進行安全的測試時演化（safe test-time evolution），結合少量真實回饋來微調獎勵程式，而不完全依賴模擬。

**2. 階層式技能庫與語意檢索**

現有的技能庫可以進一步發展為階層式結構，支援更細緻的語意檢索與組合。例如，結合 vision-language model（VLM）讓機器人根據自然語言指令或視覺觀察檢索最相關的已驗證程式。

**3. 世界模型加速內層搜尋**

目前每個候選程式都需要在平行模擬中驗證，計算成本較高。引入學習式世界模型（learned world model）可以在內層常數搜尋階段提供更快速的預測回饋，顯著降低演化所需的模擬量。

**4. 多機器人與人機協作**

將 InterEvolve 擴展到多智能體（multi-agent）場景或人機協作任務，讓機器人不僅能重新利用自身技能，還能預測並適應人類夥伴的行為。

**5. 跨載具遷移**

研究獎勵程式與 FB 潛在空間的跨載具（cross-embodiment）泛化能力，例如將在 Unitree G1 上演化出的程式遷移到其他人形機器人平台，進一步提升方法的通用性。

**6. 安全約束與可解釋性**

未來應在獎勵程式中明確納入安全約束（safety constraints），例如關節限制、接觸力上限與穩定性條件。同時，對 LLM 修訂程式的決策過程進行可解釋性分析，將有助於理解演化出的新穎策略（novel strategies）並提升系統可信度。

## 論文問答

**Q1：InterEvolve 想要解決的核心問題是什麼？**
A：這篇論文研究的是人形機器人在測試階段遇到全新移動操作任務時，如何在不重新訓練控制器的前提下，把既有的運動能力重新組合並持續改進。現實中的開放式環境充滿了訓練時未曾列舉的任務，例如把箱子翻倒到另一個面，而這些動作所需的能力往往已經潛藏在廣泛訓練過的控制器裡。InterEvolve 的目標就是透過測試時演化，讓機器人從自己的嘗試中學習、保留經驗，並把學到的策略用於後續更長程的組合任務。

**Q2：為什麼現有的任務介面（動作參考、目標狀態、技能標籤）不足以解決這類問題？**
A：這些介面通常要求給定期望動作、目標狀態或預定義行為，但對於「把箱子翻倒」這類接觸豐富且多階段的細膩互動，很難直接轉換成參考軌跡或新技能。相較之下，獎勵函數的表達能力更強，可以描述接觸目標與失敗訊號，但傳統上每次修改獎勵都需要重新訓練一個策略，迭代成本非常高。因此現有方法既難以表達新任務，又無法快速從執行回饋中修正，限制了人形機器人的泛化能力。

**Q3：測試時演化對人形機器人的實際部署為什麼重要？**
A：真實場景中的任務無法在訓練時全部列舉，機器人必須具備面對未知任務的適應能力。測試時演化讓機器人把控制器裡已經具備、但未被發掘的運動能力釋放出來，並透過嘗試與回饋不斷改進任務策略。此外，成功經驗可以被收錄到技能庫中，供未來類似或更複雜的長時程任務檢索與複用，形成持續累積的學習循環。

**Q4：InterEvolve 的核心方法由哪兩個主要元件組成？**
A：第一個元件是物件感知前向-反向（FB）行為基礎模型，它能把關於身體或物件的新獎勵轉換成具體的移動操作行為；第二個元件是獎勵程式的測試時演化機制，由大型語言模型（LLM）智慧體負責修訂程式結構，並由數值最佳化器調整可調常數。FB 模型讓獎勵可以被凍結的控制器直接執行，而獎勵程式則提供了表達能力強、又易於根據回饋修改的規劃與控制介面。兩者結合後，機器人就能在測試時不斷提出、驗證並改進獎勵程式。

**Q5：什麼是物件感知 FB 模型，為什麼需要特別強調「物件感知」？**
A：FB 模型是一種行為基礎模型，能將獎勵對應到潛在變數，再從固定的策略中誘發出相應行為。現有的人形 FB 模型通常只觀察自身身體狀態，因此當獎勵的差異只在於物件目標時，不同任務可能會坍縮成同一種行為。InterEvolve 在凍結的身體先驗網路上附加可訓練的物件殘差，讓模型讀取物件特徵，並在大規模人類-物件互動資料上訓練，從而讓獎勵能精確地驅動涉及物件的全身互動。

**Q6：獎勵程式的演化流程是如何運作的？**
A：任務被表示為一連串分階段獎勵，每個階段包含獎勵函數與完成條件，並有可調的權重與閾值等常數。LLM 智慧體根據任務意圖與平行模擬產生的執行回饋，在上下文情境中修訂程式的結構，例如增加、刪除或重排階段；同時，CMA-ES 等數值最佳化器對每個候選結構的常數進行調整。每個候選程式都會在多個平行模擬情境中驗證，確保策略在不同條件下都可靠，成功的程式則會被加入技能庫供後續任務使用。

**Q7：論文在哪些任務與場景上進行了實驗驗證？**
A：實驗涵蓋了多樣化的移動操作任務、複雜場景以及長時程組合任務，例如原地旋轉箱子、搬運並放置箱子後再踢開、把箱子翻倒到另一個面等。這些任務中有些是控制器訓練資料裡完全沒有的行為，用來測試系統能否把既有技能重新組合。除了模擬環境外，演化後的技能還被直接部署到真實的 Unitree G1 人形機器人上，並僅依靠自我中心機載感知自主運行。

**Q8：實驗的主要結果與發現是什麼？**
A：實驗顯示，人類手工設計的獎勵往往無法充分發揮 FB 模型的移動操作潛能，甚至會出現獎勵駭取而失敗；相較之下，InterEvolve 演化出的獎勵程式能釋放這些未被發掘的能力，有時還會產生意想不到的新穎策略。隨著演化迭代次數增加，任務成功率持續提升，顯示更多測試時計算確實能帶來更好的解決方案。最重要的是，這些在模擬中演化出來的程式能直接轉移到真實機器人上執行，展現了良好的模擬到真實遷移能力。

**Q9：論文進行了哪些消融或分析來驗證設計選擇？**
A：作者分析了獎勵設計與累積經驗對參考追蹤與目標條件任務的影響，發現程式結構與可調常數必須一起搜尋，單獨調整常數無法彌補糟糕的結構設計。透過平行模擬情境驗證候選程式，系統能獲得更穩定的執行證據，避免單次隨機結果造成的誤判。此外，技能庫的存在讓後續任務可以檢索已驗證程式，顯著減少從頭探索的需求，這也驗證了跨任務保留經驗的價值。

**Q10：這項技術最適合應用在哪些實際場景？**
A：InterEvolve 特別適合倉儲物流、家庭服務、搜救等需要頻繁面對新物件互動的開放式環境。在這些場景中，機器人不可能為每個新任務都收集示範資料並重新訓練策略，而測試時演化讓它只需消耗計算資源就能適應新任務。這種方式大幅降低了部署成本，也讓同一個固定控制器能夠持續處理多樣化且動態變化的操作需求。

**Q11：若要把 InterEvolve 產品化，需要考慮哪些工程與系統問題？**
A：首先需要有足夠的平行模擬計算資源來快速驗證大量候選程式，並確保模擬器能準確反映真實物理。其次，真實部署時必須處理自我中心機載感知的雜訊與延遲，並在有限試驗次數內安全地嘗試新行為。最後，技能庫需要有效的檢索與組織機制，讓 LLM 能根據新任務語意快速找到相關的已驗證程式，並避免庫中累積過多低品質或重複的經驗。

**Q12：這項研究可能對人形機器人領域帶來什麼樣的影響？**
A：InterEvolve 把「為每個新任務訓練專用策略」的典範，轉移為「在測試時演化任務規格以驅動固定控制器」，這與大型語言模型中測試時縮放的概念相呼應。它證明了只要控制器具備廣泛的運動先驗，就可以透過獎勵程式的搜尋與組合來解決多樣化任務。這種框架有助於發展更通用的人形機器人系統，並為終身學習與跨任務技能累積提供新的研究方向。

**Q13：這項方法有哪些已經存在或潛在的限制？**
A：InterEvolve 的成效高度依賴模擬器的準確性，若模擬與真實物理差距過大，演化出的程式在真實機器人上可能表現不佳。此外，整個演化過程受限於試驗預算，對於與現有技能差距過大的任務，可能需要非常多嘗試才能找到可行解。LLM 智慧體的提案品質也會影響收斂速度，若其產生的結構始終偏離任務需求，系統可能陷入局部最佳。

**Q14：哪些情況可能導致 InterEvolve 演化失敗？**
A：如果新任務需要控制器完全不具備的運動能力，例如某種全新的全身協調模式，那麼無論獎勵程式如何設計都無法誘發出該行為。獎勵設計不良也可能導致機器人找到捷徑或獎勵駭取，例如只滿足部分目標而忽略了任務真正的物理要求。另外，對於未見過的物件幾何形狀或動力學特性，物件殘差可能無法準確建模，長時程組合任務也可能因為階段轉換失誤而累積錯誤。

**Q15：未來可以朝哪些方向延伸這項研究？**
A：未來可以結合更豐富的感知模態，例如觸覺、深度相機或語音指令，讓獎勵程式能處理更複雜的環境觀測。也可以研究如何在真實世界中直接進行安全的線上演化，減少對模擬器的依賴，並在演化過程中加入安全性約束。此外，技能庫可以進一步結合語意檢索與組合推理，並在控制器確實缺乏必要能力時，自動觸發學習新的控制器技能，最終擴展到多人互動或多機器人協作的場景。

## 實務應用指南

### 適用場景

1. **倉儲物流的動態搬運與重新堆疊**  
   在物流中心或工廠倉儲中，人形機器人需要把箱子從 A 點搬到 B 點、翻轉箱體以騰出標籤面，或依序執行「搬運—放置—推開」等長時程組合。InterEvolve 可在不重新訓練控制器的情況下，把現有推、抬、搬運等技能重新組合，應對訓練時未見過的箱體姿態或堆疊方式。

2. **居家協助的多階段整理任務**  
   例如要求機器人「把椅子推到桌邊、把地上的書撿起來放到桌上、再把垃圾桶踢到門口」。這類接觸豐富、多階段互動的任務難以用單一軌跡或目標狀態描述，透過獎勵程式的分階段獎勵與完成條件，可以逐步誘導出合適的全身行為。

3. **災害現場的障礙清除與通道開闢**  
   在搜尋救援或災後復原場景中，機器人可能需要推開瓦礫、傾倒障礙物、或把管線拖到一旁。這些任務的接觸模式與物體屬性在訓練時難以窮舉，測試時演化能讓機器人根據現場回饋即時調整策略。

4. **製造產線的彈性上下料與治具調整**  
   當產線換線或引入新工件時，機器人可能需要以新的角度傾斜料箱、把零件推入定位槽，或組合數個現有動作完成新工序。獎勵程式可快速迭代，無需為每個新工序重新收集示範資料並訓練新策略。

5. **零售或展場的互動展示與導覽**  
   例如機器人需要「拿起展示品、轉向觀眾、輕放回原位」，並根據現場人群位置調整行走路徑與操作節奏。透過技能庫累積已驗證程式，後續類似任務可直接檢索並微調，縮短上線時間。

### 實作前置條件

**資料準備**
- 大量人類示範的人體—物件互動（HOI）資料，用於訓練或取得具備廣泛運動能力的基礎控制器。
- 高品質的物件模型與場景描述，包含幾何、質量、摩擦係數等物理屬性，供物件感知 FB 模型計算物件殘差。
- 任務意圖的自然語言描述與對應的獎勵程式範本，作為 LLM 智慧體的上下文學習素材。

**運算資源**
- 具備 GPU 的推理環境，用於執行凍結身體先驗與物件殘差網路。
- 可平行運行的物理模擬叢集，用於同時驗證多個候選獎勵程式。
- LLM API 或本地部署的大型語言模型，以及執行 CMA-ES 等數值最佳化的運算資源。

**技術與人力先備條件**
- 熟悉強化學習 / 模仿學習、全身人形控制與模擬到真實（sim-to-real）轉移。
- 具備獎勵設計與階段分解經驗，能判斷 LLM 產出程式的合理性。
- 機器人系統整合能力，包含機載感知、狀態估計與安全監控。

### 實作步驟建議

1. **建立可重複使用的行為基礎控制器**  
   先訓練或取得一個廣泛能力的全身控制器，並在其上加入物件殘差模組，形成物件感知 FB 模型。身體先驗保持凍結，僅讓物件殘差學習如何把新獎勵轉換為移動操作行為。

2. **定義獎勵程式的結構與常數空間**  
   設計分階段獎勵、完成條件與可調常數（權重、閾值）的程式化表示法，並明確每個階段可觀測的狀態變數，例如物件位置、姿態、接觸力、機器人重心等。

3. **建置平行模擬驗證環境**  
   搭建可批次執行多個模擬情境的環境，加入領域隨機化與擾動，確保每個候選程式都能在足夠多樣的場景中被驗證。

4. **開發 LLM 智慧體與技能庫**  
   讓 LLM 根據任務描述、執行回饋與技能庫中已驗證程式，迭代修訂獎勵程式的結構；同時以 CMA-ES 調整每個候選結構的常數。

5. **執行測試時演化迴圈**  
   對每個新任務，反覆進行「提出候選程式 → 平行模擬驗證 → 收集執行回饋 → 修訂結構與常數」的迴圈，直到達成可接受的任務成功率。

6. **模擬到真實的部署與監控**  
   將演化出的獎勵程式部署到實體機器人，搭配自我中心機載感知與狀態估計；初期保留緊急停止與人類監督機制，並持續收集真實執行資料。

7. **持續維護技能庫**  
   把驗證成功的程式摘要存入技能庫，未來遇到相似任務時優先檢索並微調，避免從頭重新探索。

### 潛在風險與注意事項

| 風險 | 說明 | 建議緩解方式 |
|---|---|---|
| **獎勵駭入（reward hacking）** | LLM 可能產生在模擬中取巧、但不符合真實任務語義的獎勵程式。 | 在平行模擬中加入多樣化擾動與語義檢查，並以人類可讀的完成條件進行二次審核。 |
| **模擬到真實落差** | 模擬中成功的行為在實體機器人上可能因感知雜訊、執行器延遲而失敗。 | 使用領域隨機化、硬體在環測試，並保留傳統控制器作為安全回退（fallback）。 |
| **LLM 產出結構不穩定** | 大型語言模型可能產生語法錯誤或邏輯矛盾的程式。 | 建立嚴謹的程式 schema 與單元測試，並讓 LLM 在上下文情境中參考已驗證範例。 |
| **運算成本高昂** | 每次迭代都需要平行模擬與數值最佳化，長期任務尤其耗時。 | 善用技能庫減少重複探索，並設定明確的試驗預算與早期停止條件。 |
| **安全與硬體損傷** | 接觸豐富的移動操作可能導致機器人或環境受損。 | 在獎勵中加入關節限制、自碰撞與接觸力懲罰，並於實機測試時使用保護框架與遠端急停。 |
| **任務描述模糊** | 自然語言任務意圖可能有多種解讀，導致演化方向偏離使用者期望。 | 提供具體的成功指標與失敗案例，必要時讓人類在迴圈中確認階段分解是否符合預期。 |

### 與其他技術的整合建議

- **視覺語言模型（VLM）**：將 VLM 用於從自我中心影像中產生任務描述或偵測物件狀態，再把結果交給 LLM 智慧體產生初始獎勵程式，降低人工撰寫任務規格的成本。
- **傳統運動規劃與軌跡最佳化**：把 InterEvolve 視為高階策略產生器，下層仍可使用軌跡最佳化或全身控制器來確保動態可行性與安全性。
- **遙操作與示教學習**：對於特別困難或危險的任務，可先由人類透過遙操作提供少數示範，轉換為獎勵程式的初始結構，再由演化進行微調。
- **數位孿生（Digital Twin）**：把平行模擬環境與真實場景的數位孿生同步，讓演化出的程式先在孿生環境中預演，再部署到實體機器人。
- **ROS2 / 機器人中介軟體**：將獎勵程式、FB 模型推理與模擬驗證封裝為 ROS2 節點，方便與現有的感知、導航與控制堆疊整合。
- **現有基礎控制器**：若已有人形機器人的全身策略，可保留其凍結身體先驗，僅訓練物件殘差模組，降低導入門檻。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從圖 1 與摘要開始，理解「不重新訓練控制器，而是在測試時透過獎勵程式演化出任務行為」這個核心概念。遇到 FB 模型、CMA-ES 等技術名詞時，不必立刻深入數學細節，重點放在「為什麼獎勵程式比軌跡或目標狀態更適合描述接觸豐富的任務」。

**給 AI 工程師**  
請聚焦於第二節之後的系統架構：物件感知 FB 模型如何透過物件殘差擴展凍結身體先驗、LLM 智慧體與 CMA-ES 如何分工搜尋程式結構與常數，以及平行模擬驗證如何形成回饋迴路。實作時需特別注意獎勵程式的 schema 設計、LLM 提示工程，以及 sim-to-real 的感知與控制介接。

**給研究人員**  
本文的貢獻在於把測試時縮放（test-time scaling）的概念從語言模型延伸到人形機器人控制，並提出「規劃與控制介面」的設計原則。可進一步探討的問題包括：獎勵程式的表達完備性、技能庫的檢索與組合理論、演化過程的樣本效率，以及如何在更複雜的真實環境中保證穩定性與安全性。

**給產品經理**  
這項技術最適合「任務種類多、但每種任務初期資料少」的場景，例如倉儲、居家服務或彈性製造。評估導入時，請同時考慮平行模擬與 LLM 推理帶來的運算成本、實機安全規範，以及技能庫長期累積後對部署速度的加速效果。短期可從單一、定義清楚的任務開始驗證，再逐步擴展到長時程組合任務。
