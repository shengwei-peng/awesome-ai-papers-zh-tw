## 摘要翻譯

理解圖表與表格影像對於將視覺語言模型（VLMs）應用於真實世界文件理解至關重要。雖然英文基準測試進展迅速，但非英文基準測試仍然稀少，使得這項進展是否能跨語言泛化尚不明確。一個關鍵障礙在於難以大規模收集真實且多樣化的非英文圖表與表格影像。為了解決這個問題，我們利用政府白皮書作為建構非英文基準測試的可擴展來源，因為它們包含跨多種格式和領域自然產生的圖表與表格，且在許多國家均可免費取得。作為首個具體實例，我們介紹 HakushoBench，這是一個具挑戰性的日文圖表視覺問答基準測試，由 33 份政府白皮書建構而成。HakushoBench 包含 2,053 張影像，涵蓋超過 10 種圖像類型，並附有人工標註的問答對，旨在評估對圖表與表格的深入且整體的理解，而非僅依賴局部視覺線索。針對多種視覺語言模型所進行的實驗表明，HakushoBench 對開源權重模型仍具挑戰性：表現最佳的開源權重模型僅達到 58.6% 的準確率，而開源權重模型與閉源模型之間存在 34.9 個百分點的差距，凸顯了在複雜圖表與表格理解方面仍有大幅改進空間。我們將釋出資料集與程式碼。

### 核心貢獻（3～5點）
- 提出以政府白皮書作為非英文圖表與表格基準測試的可擴展建構來源，解決真實且多樣化非英文影像難以大規模收集的問題。
- 發布 HakushoBench——首個源自 33 份日本政府白皮書的日文圖表視覺問答基準測試，包含 2,053 張影像、逾 10 種圖像類型及人工標註的問答對。
- 強調評估目標為對圖表與表格的深入且整體理解，而非僅依賴局部視覺線索，提升基準測試的鑑別度。
- 透過跨多種視覺語言模型的實驗，揭示開源權重模型與閉源模型之間存在 34.9 個百分點的性能差距，指出複雜圖表與表格理解仍有顯著改進空間。
- 公開釋出資料集與程式碼，以促進後續非英文視覺語言任務的研究發展。

### 適合對象
從事視覺語言模型（VLM）研究與開發的學者與工程師，特別關注多語言（尤其是日文）圖表與表格理解、文件理解、基準測試設計及模型性能評估的研究人員；亦適合政府文件數位化、自然語言處理及人工智慧應用領域的實務工作者參考。

## 深度分析

#### 方法論解析

HakushoBench 的方法論核心在於提出一個可擴展的非英語圖表視覺問答（Chart and Table VQA）基準建構範式，並以日本政府白皮書（白書，Hakusho）作為首例實作。

**資料來源選擇策略**

作者選擇政府白皮書作為資料來源具有多重策略性考量：(1) 可擴展性（Scalability）——白皮書在多數國家以官方語言免費公開，跨語言複製成本低；(2) 領域多元性——涵蓋安全、經濟、社會等政策面向，自然產生多樣化的圖表類型；(3) 真實性（Real-world）——相較於程式生成的合成圖表，白皮書中的圖表反映真實文件設計慣例，包括日語特有的混合書寫方向（直書與橫書並用）、語言特定術語及資訊密度差異。

**建構流程解析**

整體流程可分為三階段（如圖 3 所示）：

1. **影像收集與篩選階段**：從 33 本日本政府白皮書中初步收集 5,903 張候選影像，經人工篩選過濾後保留 2,053 張高品質影像。篩選標準未在摘要中詳述，但從圖 2 的多樣性展示可推斷包含影像清晰度、資訊豐富度及類型代表性等條件。

2. **問答對標註階段**：21 位人工標註員為每張影像建立一組高難度問答對。題目設計刻意避免僅依賴局部視覺線索（Local Visual Cue）的簡單提取題，而是要求：(a) 全局資訊整合（Global Reasoning）；(b) 多跳推理（Multi-hop Reasoning）；(c) 計數任務（Counting）；(d) 外部知識運用（External Knowledge）；(e) 視覺感知任務（Visual Perception）。此設計直接回應早期基準（如 ChartQA、PlotQA）飽和的問題。

3. **交叉驗證階段**：採用雙標註員獨立作答比對機制，僅當兩位標註員答案一致時才納入最終資料集。此設計有效控制標註品質，但也限制了題目難度的上限——過於主觀或開放性的題目會因標註員分歧而被排除。

**題目設計哲學**

HakushoBench 強調「深度且整體的理解」（Deep and Holistic Understanding），這與 CharXiv 的設計理念相近，但特別針對日語視覺慣例進行調整。例如，日文圖表中常見的縱向標籤、漢字數值單位（萬、億、兆）以及複合式圖表（圖中嵌表、表中嵌圖）都構成獨特的視覺理解挑戰。

#### 實驗數據解讀

**模型評估範圍**

實驗涵蓋廣泛的視覺語言模型（VLM）光譜，包括：
- 開源權重模型（Open-weight Model）：Sarashina2.2-V 3B、Qwen3-VL 4B/8B、InternVL 3.5 4B/8B、LLM-jp-4-VL 9B beta
- 旗艦開源模型：Qwen3.5-397B-A17B
- 閉源模型（Proprietary Model）：GPT-4o、GPT-5.1、Gemini 3 Pro

評估採用「Direct/CoT 最佳分數」（Best of Direct/CoT）策略，允許模型在直接提示（Direct Prompting）與思維鏈（Chain-of-Thought, CoT）提示間擇優。

**關鍵數據解讀**

從圖 1 的基準比較可得出以下重要觀察：

1. **HakushoBench 的鑑別力顯著優於 JGraphQA**：在 JGraphQA 上，所有模型得分集中在 81%–98% 區間，差距僅 17.2 分；而在 HakushoBench 上，得分跨度達 56.3 分（37.7%–93.9%），呈現明顯的難度梯度。

2. **開源與閉源模型存在巨大性能差距（Performance Gap）**：最佳開源權重模型 Qwen3-VL 8B 僅達 58.6% 準確率（Accuracy），與閉源模型存在 34.9 分的差距。這一差距遠超 ChartQA（22.6 分）和 JGraphQA（17.2 分），顯示 HakushoBench 對開源模型構成實質性挑戰。

3. **旗艦開源模型仍落後頂級閉源模型**：Qwen3.5-397B-A17B 在 JGraphQA 和 ChartQA 上能匹配或超越 Gemini 3 Pro，但在 HakushoBench 上落後 8.1 分（85.8% vs. 93.9%）。此現象暗示 HakushoBench 捕捉到現有模型在日語複雜圖表理解上的特定弱點，而非僅是整體能力差異。

4. **模型規模與性能的關係**：從 3B 到 397B-A17B 的開源模型中，規模擴大帶來顯著性能提升（37.7% → 85.8%），但仍未跨越閉源模型的水準，顯示單純的規模擴展不足以解決此類任務。

**基準飽和度比較**

相較於 ChartQA（已被早期模型達到 86.1%）和 ChartQAPro（67.4%），HakushoBench 的最高分 93.9% 看似較高，但這僅由 Gemini 3 Pro 達成；對於開源模型而言，58.6% 的天花板顯示基準尚未飽和，仍具備持續推動模型改進的價值。

#### 與現有研究的比較

**相較於英文基準的定位**

HakushoBench 在表 1 的比較中展現明確的差異化定位：

| 維度 | ChartQA/ChartQAPro/CharXiv | HakushoBench |
|------|---------------------------|--------------|
| 語言 | 英語 | 日語 |
| 影像來源 | 線上平台/學術論文 | 政府白皮書 |
| 影像類型 | 3 至 >10 | >10 |
| 真實性 | 是 | 是 |
| 規模 | 較大 | 2,053 張 |

相較於 ChartQAPro 和 CharXiv 等近期英文基準，HakushoBench 的規模較小，但這反映的是品質優先於數量的設計哲學——每張影像僅配一組高難度問答對，而非大量簡單題目。

**相較於 JGraphQA 的改進**

JGraphQA 作為現有唯一的日語圖表 VQA 基準，存在三大限制：(1) 僅約 200 個實例，規模不足；(2) 視覺多樣性有限，僅 5 種影像類型；(3) 題目相對簡單，導致 3B 規模模型已達 80% 以上準確率，基準飽和（Saturated Benchmark）。HakushoBench 在這三個維度均有顯著提升：規模擴大 10 倍、影像類型翻倍、題目難度大幅提升。

**方法論的可遷移性**

本文最大的方法論貢獻在於提出「政府白皮書作為基準建構來源」的可複製範式。這一策略可應用於：(1) 其他語言版本（中文、韓文、法文等國家的白皮書）；(2) 其他文件類型（年報、統計年鑑、政策報告）；(3) 其他視覺理解任務（版面分析、資訊提取）。然而，作者也坦誠此方法的限制——白皮書的視覺風格可能偏向特定設計慣例，未必能完全代表所有真實世界的日語圖表。

**與 CharXiv 設計哲學的對話**

CharXiv 強調「需要博士級別推理」（PhD-level reasoning）的圖表理解，HakushoBench 採用類似的「深度且整體理解」理念，但更聚焦於日語特有的視覺與語言挑戰。兩者共同推動了圖表 VQA 從「簡單數值提取」向「複雜推理」的典範轉移。

**模型權重可用性**

實驗涵蓋的模型中，開源權重模型（Qwen3-VL、InternVL 3.5、Sarashina2.2-V、LLM-jp-4-VL）均可從原始團隊取得；閉源模型（GPT-4o、GPT-5.1、Gemini 3 Pro）則透過 API 存取。Qwen3.5-397B-A17B 雖為開源，但 397B 規模的部署對硬體要求極高，可能限制中小型研究團隊的重現實驗。

**潛在的可重現性風險**

1. **白皮書版本變動**：政府白皮書可能因政策更新而修訂，若資料集未固定引用特定版本，可能導致影像來源失效。
2. **API 模型版本漂移**：閉源模型的 API 行為可能隨時間變化，導致歷史實驗結果無法重現。
3. **標註員主觀性**：即使有交叉驗證，不同標註員群體仍可能產生不同的題目風格。

#### 未來研究方向

**基準擴展方向**

1. **多語言白皮書基準建構**：將本文提出的方法論應用於中文、韓文、阿拉伯文等語言，建立跨語言圖表 VQA 基準套件，系統性評估 VLM 的多語言圖表理解能力。
2. **跨文化視覺慣例研究**：利用多語言版本的白皮書基準，研究不同文化背景下圖表設計的差異（如色彩使用、圖示符號、資訊密度），並探討這些差異如何影響模型泛化。
3. **時間演進分析**：政府白皮書通常按年度發布，可建構時間序列基準，追蹤 VLM 在不同時期圖表設計風格上的表現穩定性。

**模型改進方向**

1. **日語特定預訓練**：現有開源模型在 HakushoBench 上的表現不佳，部分原因可能是日語圖表視覺 token 的預訓練不足。未來可探索針對日語文件的大規模預訓練策略。
2. **多模態推理增強**：HakushoBench 的高難度題目需要多跳推理，未來可研究如何將外部知識、符號推理與視覺理解更緊密結合。
3. **小樣本學習與微調**：鑑於開源模型表現欠佳，可探索如何透過少量高品質的日語圖表 QA 資料進行微調，縮小與閉源模型的差距。

**任務擴展方向**

1. **細粒度錯誤分析**：未來工作可對 HakushoBench 上的模型錯誤進行系統分類（如數值計算錯誤、單位混淆、視覺錯位、語言理解錯誤），以指導模型改進。
2. **互動式圖表問答**：將靜態 VQA 擴展為多輪對話式問答，要求模型在對話中逐步澄清問題並整合資訊。
3. **可解釋性評估**：不僅評估答案正確性，還應評估模型推理過程的可解釋性，例如要求模型指出其依據的圖表區域。

**方法論反思**

1. **白皮書偏見的量化**：政府白皮書可能存在特定的視覺風格偏見，未來應研究此偏見如何影響基準的外部效度（External Validity）。
2. **題目難度的客觀量化**：目前題目難度依賴標註員主觀判斷，未來可探索基於模型表現的難度校準方法（如 Item Response Theory）。
3. **基準生命週期管理**：隨著模型能力提升，HakushoBench 終將面臨飽和問題，需要建立動態更新機制以維持基準的鑑別力。

**跨領域應用**

1. **教育評量自動化**：政府白皮書常作為教育素材，HakushoBench 的方法可應用於自動化評量學生的圖表理解能力。
2. **政策文件分析**：將 VLM 應用於大規模政策文件的自動化分析，支援政策研究與決策輔助。
3. **無障礙技術**：為視障人士開發圖表內容的語音描述系統，需要 VLM 具備精確的圖表理解能力，HakushoBench 可作為此類系統的評估基準。

## 論文問答

**Q1：為什麼現有的圖表視覺問答（VQA）基準測試在非英語場景中存在明顯不足？**
A：現有的圖表與表格 VQA 基準測試（如 ChartQA、ChartQAPro、CharXiv 等）幾乎完全以英語為中心，採用英語圈特有的視覺慣例與文件風格。然而，真實世界的圖表理解會因語言與文化而異，包括地圖式圖表中的地理慣例、表格中的語言專有術語、書寫方向（如日文常見的縱橫混排），以及整體資訊密度與版面結構的差異。因此，在英語基準測試上表現優異的模型，並不代表具備穩健的多語言圖表理解能力，這正是非英語基準測試亟需被建立的核心動機。

**Q2：日語領域現有的 JGraphQA 基準測試為何無法有效區分視覺語言模型（VLM）的性能差異？**
A：JGraphQA 雖然是目前日語圖表理解的主要基準測試，但其規模僅約 200 個實例，視覺多樣性有限，且題目設計相對簡單。這導致基準測試出現嚴重的性能飽和現象——即使是 3B 規模的小型 VLM 也能達到超過 80% 的準確率，所有模型的得分集中在 81% 到 98% 之間，無法有效區分模型之間的細部能力差異，也無法反映真實世界中複雜圖表所帶來的挑戰。

**Q3：為什麼政府白皮書（白書）是建構多語言圖表 VQA 基準測試的理想資料來源？**
A：政府白皮書具有三大關鍵優勢，使其成為極具價值的資料來源：第一，白皮書包含大量真實世界的圖表與表格，橫跨多元領域與視覺格式；第二，白皮書在許多國家與語言中皆為公開且可自由取得的資源，具有高度的可擴展性；第三，白皮書中的圖表通常由專業設計，資訊豐富且對一般讀者易於理解，能自然呈現真實文件的複雜度。這些特性使白皮書成為突破英語中心基準測試限制、推動多語言圖表理解研究的重要媒介。

**Q4：HakushoBench 的建構流程包含哪些主要階段？**
A：HakushoBench 的建構流程分為三個主要階段：首先，從 33 份日本政府機構出版的白皮書中收集圖表與表格影像，涵蓋安全、經濟、社會等多元領域；接著，經過人工影像篩選，從原始資料中挑選出 5,903 張候選影像；最後，由 21 位人工標註者為每張影像建立一道高難度的問答對，並透過跨標註者獨立驗證機制確保答案一致性，最終產出 2,053 個高品質的 VQA 範例。

**Q5：HakushoBench 在問題設計上與早期基準測試有何本質差異？**
A：早期基準測試（如 ChartQA、PlotQA）主要聚焦於相對簡單的圖表類型與問題，僅需直接擷取數值或標籤即可作答。相較之下，HakushoBench 刻意設計為需要「深度且整體性理解」的問題，涵蓋全域性推理、多跳推理（multi-hop reasoning）、計數、需要外部知識以及視覺推理等題型。這意味著模型不能僅依賴局部視覺線索作答，而必須整合整張影像的資訊進行更複雜的推論，這也是為什麼該基準測試對現有 VLM 構成顯著挑戰。

**Q6：HakushoBench 在影像多樣性方面有哪些具體設計考量？**
A：HakushoBench 包含超過 10 種影像類型，涵蓋了真實政府白皮書中常見的各種圖表與表格形式。為了確保多樣性，研究團隊從 33 份不同主題與機構的白皮書中取材，而非集中於單一領域或單一視覺風格。這種設計使得基準測試能夠反映日語文件中特有的視覺慣例，包括縱橫混排的文字、密集的資訊呈現，以及複雜的版面結構，從而對模型的真實跨語言圖表理解能力提出更全面的考驗。

**Q7：HakushoBench 在實驗中如何與現有基準測試進行比較？**
A：研究團隊在 HakushoBench 上評估了廣泛的開源權重模型與閉源模型，並與現有的日語基準測試 JGraphQA 以及英語基準測試 ChartQA、ChartQAPro、CharXiv 進行比較。比較採用每個模型在「直接提示」與「思維鏈（CoT）」兩種設定下的最佳準確率，以確保評估的公平性與全面性。這樣的跨基準測試比較設計，使研究者能清楚看出 HakushoBench 在難度與鑑別度上的獨特優勢。

**Q8：HakushoBench 上各模型的關鍵實驗結果為何？**
A：實驗結果顯示 HakushoBench 對開源權重模型構成極大挑戰：表現最佳的開源權重模型 Qwen3-VL 8B 僅達到 58.6% 的準確率；開源權重模型與閉源模型之間存在高達 34.9 個百分點的性能差距，凸顯出在複雜圖表理解上仍有大幅改進空間。此外，旗艦級開源模型 Qwen3.5-397B-A17B 雖在 JGraphQA 與 ChartQA 上能匹配甚至超越 Gemini 3 Pro，但在 HakushoBench 上卻落後 8.1 個百分點（85.8% vs. 93.9%），顯示該基準測試能有效區分高階模型的細部能力差異。

**Q9：HakushoBench 在鑑別度上相較於 JGraphQA 有何具體優勢？**
A：在 JGraphQA 上，所有模型的得分集中在 81% 到 98% 之間，差距僅約 17 個百分點，已呈現嚴重的飽和現象；而在 HakushoBench 上，模型的得分分布呈現高達 56 個百分點的跨度（從最低到最高），能夠清楚區分不同規模與架構的模型能力。這意味著 HakushoBench 不僅是一個更具挑戰性的基準測試，也是一個更具診斷價值的評估工具，能幫助研究者精準定位模型在複雜圖表理解上的瓶頸。

**Q10：HakushoBench 對實際文件理解應用有何直接價值？**
A：HakushoBench 所使用的政府白皮書圖表與真實世界中公共報告、財務文件、科學文章中的圖表高度相似，因此該基準測試的評估結果能直接反映模型在實際文件理解場景中的表現。對於需要處理日語政府文件、企業財報或學術資料的應用場景而言，HakushoBench 提供了一個貼近真實使用情境的評估基準，有助於開發者選擇或改進適合日語複雜文件處理的 VLM。

**Q11：在產品開發層面，HakushoBench 的發布會帶來哪些具體影響？**
A：透過釋出資料集與程式碼，HakushoBench 讓產品開發者能直接評估自家模型在日語複雜圖表理解上的表現，並與最先進的開源權重模型與閉源模型進行基準比較。特別是 34.9 個百分點的開源與閉源差距，為開發者提供了明確的技術差距參考，有助於規劃模型改進路線、決定是否採用閉源 API 或投入資源訓練更強的開源模型。此外，跨基準測試的比較結果也能幫助產品團隊判斷模型在不同語言與任務上的泛化能力。

**Q12：HakushoBench 對圖表理解研究領域的整體影響為何？**
A：HakushoBench 的推出填補了非英語（特別是日語）圖表 VQA 基準測試的關鍵空白，促使研究者正視跨語言圖表理解的挑戰。其建構方法論——以政府白皮書作為可擴展的真實資料來源——也為其他語言（如中文、韓語、法語等）建立類似基準測試提供了可複製的範本。這種「以政府公開資料建構多語言基準測試」的思路，有望推動整個領域朝著更公平、更全面的多語言評估生態系統發展。

**Q13：HakushoBench 在資料來源上存在哪些已知的侷限性？**
A：HakushoBench 的影像完全來自 33 份日本政府白皮書，雖然涵蓋多元主題，但本質上仍受限於政府文件的視覺風格與領域範疇。這意味著該基準測試可能無法完全代表其他類型的日語文件（如商業報告、學術論文、媒體圖表等）的視覺特性。此外，政府白皮書的設計通常較為正式與保守，可能缺少社群媒體圖表、資訊圖表（infographics）等更具視覺創意或非標準化的圖表類型。

**Q14：在實驗結果中，HakushoBench 揭示了哪些值得關注的失敗案例模式？**
A：從實驗數據可觀察到幾個明顯的失敗模式：開源權重模型在 HakushoBench 上的表現遠低於其在 JGraphQA 與 ChartQA 上的表現，顯示其在處理需要全域性推理、多跳推理與外部知識整合的問題時存在明顯弱點；即使是旗艦級開源模型 Qwen3.5-397B-A17B 也在 HakushoBench 上落後 Gemini 3 Pro 達 8.1 個百分點，暗示高階模型在日語特有的視覺慣例（如縱橫混排文字、密集表格結構）上仍有顯著不足。這些失敗案例凸顯了現有 VLM 在跨語言複雜圖表理解上的核心瓶頸。

**Q15：基於 HakushoBench 的發現，未來研究有哪些值得探索的方向？**
A：未來研究可朝多個方向延伸：首先，可將「以政府白皮書建構基準測試」的方法論應用至其他語言，建立跨語言的圖表 VQA 基準測試矩陣，以系統性評估多語言泛化能力；其次，可深入分析模型在 HakushoBench 上失敗的具體原因，例如是視覺編碼不足、語言理解瓶頸，還是推理能力欠缺，以指導模型架構與訓練方法的改進；最後，可探索如何將外部知識整合、多模態推理等技術引入圖表理解任務，以縮小開源權重模型與閉源模型之間 34.9 個百分點的顯著性能差距。

## 實務應用指南

### 適用場景

1. **政府文件自動化分析系統**：建構能自動解析日本政府白皮書（如經濟、安全、社會等領域）的圖表與表格內容，提取關鍵數據與政策指標，輔助政策研究員快速掌握跨年度、跨領域的趨勢比較。

2. **跨語言文件理解產品本地化**：將以英語為主的圖表問答能力（如 ChartQA、ChartQAPro）擴展至日語市場，特別針對含有混合書寫方向（直書與橫書混用）、高資訊密度排版的日文文件進行模型微調與評估。

3. **金融與企業年報智慧助理**：開發能理解日文企業財報、IR 文件中複雜圖表的問答系統，協助分析師、投資人快速回答「哪一季的營收成長率最高？」、「各部門利潤佔比如何變化？」等需要整體推理的問題。

4. **學術研究與論文圖表解析工具**：建構輔助研究者解析日文社會科學論文中圖表的工具，特別是處理需要多跳推理（multi-hop reasoning）與跨圖整合資訊的問題。

5. **VLM 模型能力評估平台**：作為模型開發團隊評估自家 VLM 在日文複雜圖表理解能力的標準測試，避免僅依賴已飽和的 JGraphQA（200 題、3B 模型即可達 80% 以上）而誤判模型真實能力。

### 實作前置條件

**資料需求**
- 33 份日本政府白皮書原始 PDF（可自日本數位廳 Japanese Digital Agency 公開取得）
- 圖表與表格影像抽取工具（PDF 解析、影像切割）
- 至少 21 位熟悉日文的標註人員（用於 QA 對建立與交叉驗證）
- 預訓練 VLM 模型權重（如 Qwen3-VL、InternVL 3.5、Sarashina2.2-V 等）

**運算資源**
- 影像預處理階段：一般 GPU 即可（如單張 A100）
- 模型評估階段：依模型規模差異極大
  - 3B–8B 模型：單張 A100/H100 即可推論
  - 397B-A17B 模型：需多節點 H100 叢集（建議 8 卡以上）
- 標註階段：無需特殊 GPU，但需版本控制與標註平台（如 Label Studio）

**技能需求**
- 日文閱讀能力（N1 級以上為佳）
- PDF 影像處理經驗（pdfplumber、PyMuPDF 等）
- VLM 推論框架使用經驗（vLLM、HuggingFace Transformers）
- 熟悉 prompt engineering（Direct Prompting 與 Chain-of-Thought 兩種模式）
- 基本的統計分析能力以評估模型表現

### 實作步驟建議

**步驟一：資料蒐集與影像抽取**
從日本數位廳等政府網站下載 33 份白皮書 PDF，使用 PDF 解析工具（如 PyMuPDF）抽取所有嵌入的圖表與表格影像。預期可蒐集約 5,903 張候選影像。

**步驟二：影像品質過濾**
人工篩選掉模糊、截斷、重複或非圖表類型的影像，最終保留 2,053 張高品質影像。建議建立影像類型分類系統（涵蓋 10 種以上類型，如長條圖、折線圖、圓餅圖、地圖、表格、儀表板等）。

**步驟三：QA 對設計與標註**
為每張影像設計一道高難度 QA 對，重點涵蓋：
- 整體性問題（需綜觀全圖）
- 多跳推理（需整合多個視覺元素）
- 計數問題（精確計算數量）
- 外部知識問題（需結合領域知識）
- 純視覺推理問題

**步驟四：交叉驗證機制**
採用「標註者 A 與標註者 B 獨立作答」流程，僅保留答案一致的 QA 對，確保標註品質與答案唯一性。

**步驟五：模型評估**
使用兩種 prompting 模式評估：
- **Direct Prompting**：直接給出答案
- **Chain-of-Thought (CoT)**：要求模型逐步推理

取兩者中較佳分數作為最終成績，並與 ChartQA、ChartQAPro、CharXiv、JGraphQA 等基準做橫向比較。

**步驟六：產品化整合**
將評估結果作為模型選型依據，選擇在 HakushoBench 上表現最佳且符合成本考量的模型，部署至實際應用場景。

### 潛在風險與注意事項

**風險一：標註偏誤與文化語境落差**
- **問題**：日文圖表含有大量專業術語與文化特定視覺慣例（如地圖投影方式、書寫方向），非日語母語標註者可能誤判。
- **緩解**：聘請具備領域知識的日籍標註者，並建立標註指南（annotation guideline）統一標準。

**風險二：模型評估的隨機性**
- **問題**：VLM 在相同問題上可能產生不同答案，特別是開放式問題。
- **緩解**：採用封閉式答案設計（如同義詞集合比對），並多次取樣平均。

**風險三：基準測試的時效性衰退**
- **問題**：隨著模型快速演進，HakushoBench 也可能在數年後飽和。
- **緩解**：定期擴充題目、引入新白皮書來源，並追蹤模型表現趨勢。

**風險四：開源與閉源模型差距過大**
- **問題**：實驗顯示開源模型最高僅 58.6%，與閉源模型有 34.9 點差距，部署開源模型可能無法滿足品質需求。
- **緩解**：採用混合策略——以閉源模型處理高難度問題，開源模型處理簡單問題以控制成本。

**風險五：影像版權與使用限制**
- **問題**：政府白皮書雖公開，但部分影像可能含有第三方授權內容。
- **緩解**：僅使用明確標示為公共領域（public domain）的影像，並在資料集中附上來源聲明。

**風險六：領域偏移風險**
- **問題**：白皮書涵蓋安全、經濟、社會等多元領域，模型在未見過的領域可能表現不佳。
- **緩解**：在部署前針對目標領域進行額外微調（fine-tuning）或 few-shot 評估。

### 與其他技術的整合建議

**與 OCR 技術整合**
HakushoBench 涵蓋表格影像，建議整合專門的日文 OCR 引擎（如 PaddleOCR 的日文模型、Tesseract + 日文語言包）作為前處理，將影像中的文字先抽取為結構化資料，再交由 VLM 進行視覺推理，可顯著提升表格理解準確率。

**與 RAG（Retrieval-Augmented Generation）系統整合**
將 HakushoBench 的 QA 對作為 RAG 系統的評估基準，測試系統在「圖表影像 + 文字上下文」混合檢索場景下的表現。建議使用多模態嵌入模型（如 Japanese-CLIP）建立跨模態索引。

**與文件解析管線整合**
可將 HakushoBench 整合至企業級文件理解平台（如 Unstructured.io、LayoutLMv3 等），作為日文文件處理模組的品質驗證層。建議在 ETL 管線中加入 HakushoBench 風格的合成測試集，持續監控模型表現。

**與多語言 VLM 整合**
若產品需支援多語言，建議以 HakushoBench 評估候選模型在日文上的表現，並與中文、英文基準（如 ChartQAPro）做交叉比較，選擇跨語言表現均衡的模型。

**與 Agent 框架整合**
對於需要多步驟推理的複雜問題，可將 HakushoBench 的題目作為 Agent 系統的測試案例，評估 Agent 在「視覺觀察 → 推理 → 行動」循環中的表現。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與圖 1，理解 HakushoBench 的核心動機——為何現有日文圖表基準（JGraphQA）已不足以評估現代 VLM。接著瀏覽圖 3 的建構流程，建立「資料蒐集 → 標註 → 驗證」的基準測試建構概念。實作上可從下載小型開源 VLM（如 Qwen3-VL 4B）開始，嘗試在 HakushoBench 上跑 Direct Prompting，感受其難度。

**給 AI 工程師**：重點關注實驗結果與模型表現差距（開源 vs. 閉源 34.9 點差距），這對模型選型至關重要。建議深入閱讀 Direct 與 CoT 兩種 prompting 模式的比較章節，並嘗試將 HakushoBench 整合至現有的模型評估管線中，作為日文圖表能力的標準測試。實作上可參考其資料集釋出，建立 CI/CD 流程中的迴歸測試。

**給研究者**：HakushoBench 揭示了 VLM 在跨語言、跨文化圖表理解上的顯著落差，是極具價值的研究議題。建議從「為何開源模型在日文圖表上表現遠遜於英文」切入，探索書寫方向、視覺慣例、訓練資料分布等因素的影響。圖 2 展示的影像多樣性也提供了豐富的研究素材，可進一步分析不同圖表類型對模型表現的影響。

**給產品經理**：HakushoBench 的核心訊息是「現有日文圖表 VLM 能力尚未成熟」，這對產品規劃有直接影響——若產品涉及日文文件理解，需評估是否接受較高的錯誤率，或預留人工覆核機制。建議將 HakushoBench 的 58.6% 數字作為內部技術評估的參考基準，並據此規劃 MVP 範圍與迭代路線。
