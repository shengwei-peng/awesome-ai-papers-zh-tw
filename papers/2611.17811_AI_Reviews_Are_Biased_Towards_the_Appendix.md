本研究採用系統化的三階段流程（pipeline），如 Figure 2 所示，旨在量化並定性分析大型語言模型（LLM）在審查學術論文時對附錄（appendix）的偏誤程度。

**第一階段：論文採樣與匿名化處理。** 作者從 ACL 2026、EMNLP 2026、COLM 2026 與 ICLR 2027 四個頂級會議中各抽取 200 篇論文（共 800 篇），並從 ICLR 2021 至 ICLR 2026 額外抽取 1,200 篇以進行縱向比較。篩選條件為附錄長度至少 15 頁，這一閾值的設定至關重要——它確保了附錄中確實存在足夠的可批評素材，避免因附錄過短而無法產生有意義的批評分布。接著進行匿名化處理，包括移除作者姓名、機構資訊與程式碼儲存庫連結（repo links），以排除作者身分對審查結果的潛在偏誤。

**第三階段：弱點歸屬標註。** 這是方法論中最具技術挑戰性的環節。作者要求 LLM 對其生成的每個弱點（weakness）標註對應的論文段落，例如「W1 - Section 4 - Theoretical Analysis; Appendix A - Rigorous Theory and Proofs」。此步驟本質上是讓 LLM 進行自我歸因（self-attribution），存在一個值得關注的方法論疑慮：LLM 是否能準確回溯自身批評的來源？若模型對自身生成內容的歸因能力有限，則後續的「附錄偏誤」量化結果可能存在系統性偏差。然而，作者透過跨模型、跨存取方式的一致性結果，間接驗證了這一歸因機制的可靠性。

**存取方式的多樣性測試。** 研究涵蓋三種 LLM 使用方式：API、CLI 代理（coding-agent，如 Codex 與 Claude Code）以及網頁介面（web access）。這種設計排除了「特定介面導致附錄偏誤」的替代解釋（alternative explanation），強化了結論的穩健性。

#### 實驗數據解讀

**核心量化發現。** 在四個近期會議的論文中，幾乎所有模型超過 50% 的弱點源自附錄相關素材。具體而言，GPT-6-Astra 與 GPT-6.1-Sol 的附錄弱點比例約為 60-70%，較早期模型 GPT-5 的不到 30% 顯著上升。這一時間序列上的躍升暗示附錄偏誤並非 LLM 的固有特性，而是隨模型能力增強而湧現的新行為——可能與較新模型具備處理長上下文（long context）的能力有關，使其能夠「讀到」並「批評」附錄深處的細節。

**人類審查的對照基準。** 在 ICLR 2021 至 ICLR 2027 的人類審查中，僅 8.4% 的弱點源自附錄，遠低於 LLM 的 50%+。然而，新模型發布後，人類審查中的附錄弱點比例急劇攀升至 27.60%。這一現象極具警示意義：它暗示人類審查者正在被 LLM 的審查模式所「感染」，其審查行為因 LLM 輔助而發生漂移。這是一個間接但強烈的證據，說明 LLM 不僅自身存在附錄偏誤，還正在改變人類審查者的批評分布。

**質性差異：批評內容的本質區別。** 數量差異之外，更值得關注的是批評內容的質性差異。人類從附錄提取的弱點主要圍繞論文的表述與內容（presentation and content），且與核心概念（core idea）相關——例如論點的清晰度、實驗設計的合理性等。相對地，LLM 從附錄提取的弱點聚焦於細粒度技術細節（fine-grained technical details），如「Appendix A.7 未報告信賴區間（confidence intervals）」、「附錄中的某個表格與正文數據矛盾」等。這些批評雖然技術上可能成立，但往往不涉及論文的核心貢獻，對作者改進論文的指導價值有限。

**Figure 1 的縱向趨勢。** 圖中顯示人類審查的附錄弱點比例從早期的 8.4% 上升至近期的 27.60%，這一趨勢與 LLM 使用率上升的時間線高度吻合。這種共時性（synchronicity）為「LLM 影響人類審查行為」的因果假說提供了相關性證據，儘管嚴格的因果推斷仍需更精細的實驗設計。

#### 與現有研究的比較

**與既有 AI 審查研究的定位。** 現有文獻主要聚焦於三個面向：（1）LLM 審查與人類審查的一致性（alignment），如 Fichtl et al.（2026）與 Camelo-Guerrero and Diaz-Rodriguez（2026）；（2）AI 審查的基準測試（benchmarking），如 Li et al.（2026）與 Nguyen et al.（2026）；（3）AI 審查的可操縱性（manipulability），如 Lin（2026）與 Kaneko（2026）發現 LLM 可被隱藏提示詞或論文改寫所影響。本研究的獨特貢獻在於揭示了一個先前未被探討的維度——批評的空間分布（spatial distribution of criticism），而非僅關注批評的內容或品質。

**與 Vasu et al.（2026）的互補性。** 該研究指出 LLM 偏好自信的寫作風格而非實質內容，本研究則揭示 LLM 偏好批評附錄而非核心概念。兩者共同描繪出一幅 LLM 審查的「形式重於實質」的圖像：LLM 不僅容易被表面特徵迷惑，其批評焦點也偏向非核心的補充素材。

**方法論優勢。** 相較於僅使用 API 介面的研究，本研究涵蓋 CLI 代理與網頁介面，增強了結論的外部效度（external validity）。此外，縱向時間序列分析（從 ICLR 2021 到 2027）提供了行為演變的歷史視角，這在既有文獻中較為罕見。

**侷限性與未解問題。** 首先，自我歸因（self-attribution）方法的有效性未經獨立驗證——若由人類標註者重新歸屬弱點，結果是否一致？其次，研究僅關注弱點的「來源段落」，未深入分析弱點的「嚴重程度」——附錄弱點是否在整體評分中佔有更高權重？第三，提示詞的簡化設計雖提升了生態效度，但未測試不同提示策略（如明確指示「請專注於核心貢獻」）是否能緩解附錄偏誤，這將是重要的後續研究方向。

**程式碼與資料的開放性。** 作者於 GitHub 公開程式碼（https://github.com/cincynlp/review_appendix），這是可重現性的基礎。然而，需注意以下幾點：

#### 未來研究方向

**提示詞工程的干預效果。** 一個直接的延伸是測試不同提示策略對附錄偏誤的緩解程度。例如，明確指示「請優先評估論文的核心貢獻，而非附錄中的補充細節」是否能將附錄弱點比例從 60% 降至接近人類的 10%？這將為實務中的 LLM 審查使用提供可操作的建議。

**因果機制的深入探究。** 附錄偏誤的根源是什麼？是因為較新模型的長上下文處理能力使其「讀到」了附錄細節，還是因為訓練資料中人類審查者的附錄批評比例被放大？透過消融實驗（ablation study），例如限制模型僅能讀取正文，可驗證「讀得到」是否為必要條件。

**跨學科領域的泛化性。** 本研究聚焦於 NLP 與機器學習會議（ACL、EMNLP、COLM、ICLR），附錄偏誤是否同樣存在於其他學科？例如，醫學或物理學論文的附錄通常包含大量數據與方法細節，LLM 是否會呈現相同的批評模式？

8.4% 的人類附錄弱點比例來自特定會議與年份，可能不具普遍性。緩解措施：擴大基準資料來源，涵蓋更多會議與年份，並對人類審查者進行背景分析（如資深 vs. 新手）。

### 與其他技術的整合建議

**與 OpenReview API 整合**
透過 OpenReview 官方 API 自動抓取會議的審查記錄與論文元資料，建立持續更新的資料管線。可設定 webhook 在新審查提交時觸發分析，實現即時監控。

**與學術搜尋引擎整合**
將分析結果與 Semantic Scholar、OpenAlex 等學術搜尋引擎連結，提供「論文審查偏誤分析」作為論文的附加中繼資料，幫助讀者理解該領域的審查生態。

**與 LLM 評估框架整合**
整合至 HELM、lm-evaluation-harness 等開源評估框架，將「附錄偏誤率」作為審查任務的新評估指標，推動社群對此現象的關注。

**與文獻管理工具整合**
與 Zotero、Mendeley 等文獻管理工具整合，在使用者閱讀論文時自動標記「此論文在 AI 審查中常被忽略的核心章節」，引導讀者關注主體內容。

**與會議管理系統整合**
與 EasyChair、CMT、HotCRP 等會議管理系統整合，在審查者提交審查意見時提供「AI 輔助程度自評」與「附錄偏誤提醒」功能，形成完整的審查品質生態系。

**與提示工程工具整合**
整合至 LangChain、LlamaIndex 等 LLM 應用開發框架，提供專門的「學術審查提示詞模板庫」，內建附錄偏誤緩解機制（如「請優先評估主體章節的核心貢獻」）。
