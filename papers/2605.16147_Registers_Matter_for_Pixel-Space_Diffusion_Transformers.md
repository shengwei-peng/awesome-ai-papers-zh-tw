## ⚡ TL;DR

研究寄存器 token 在像素空間 DiT 的功效，發現即使無離群值仍能提升生成品質。
提出 Register Guidance，以無寄存器模型為負向方向，強化視覺結構與連貫性。
實驗顯示像素空間 DiT 的 FID 顯著下降，且高雜訊層級特徵圖更平滑清晰。

## 摘要翻譯

視覺 Transformer（Vision Transformers, ViT）已知會出現高範數圖塊 token 離群值（high-norm patch-token outliers），進而降低特徵圖品質（feature map quality），而寄存器 token（register tokens）能有效緩解此問題。隨著擴散模型（diffusion models, DMs）日益採用 Transformer 架構（transformer architectures），並朝向像素空間訓練（pixel-space training）發展，其形式與 ViT 越來越接近，這也引發一個問題：寄存器 token 對擴散 Transformer（Diffusion Transformers, DiT）是否同樣有用？本研究顯示，DiT 與 ViT 在一項關鍵特徵上有所差異：DiT 並未出現圖塊 token 離群值（patch-token outliers），但仍能從寄存器 token 中獲益。有趣的是，寄存器 token 在像素空間 DiT（pixel-space DiTs）中比在潛空間 DiT（latent-space DiTs）中更有效。透過分析中間表徵（intermediate representations），我們發現寄存器 token 在高雜訊層級（high noise levels）下能產生更乾淨的特徵圖，這可能有助於其在像素空間生成（pixel-space generation）中的有效性。我們進一步觀察到，近期像素空間 DiT 架構隱式地整合了類寄存器機制（register-like mechanisms），這可能部分解釋了它們優異的實證表現（empirical performance）。基於這些觀察，我們提出 Register Guidance（寄存器引導），一種強化對改善視覺結構（visual structure）與連貫性（coherence）有貢獻之寄存器 token 作用的技術。

### 核心貢獻（3～5點）
- 揭示 DiT 與 ViT 的關鍵差異：DiT 雖無圖塊 token 離群值問題，但仍能從寄存器 token 中獲益，且寄存器 token 在像素空間 DiT 中比在潛空間 DiT 中更有效。
- 透過中間表徵分析，發現寄存器 token 在高雜訊層級下能產生更乾淨的特徵圖，從而解釋其在像素空間生成中的有效性。
- 指出近期像素空間 DiT 架構已隱式整合類寄存器機制，部分說明其強大的實證表現。
- 提出 Register Guidance（寄存器引導）技術，可放大負責改善視覺結構與連貫性之寄存器 token 的貢獻。

### 適合對象
本論文適合對擴散模型、視覺 Transformer 架構，以及生成模型中注意力機制與特徵表徵分析有興趣的研究者與工程師。特別是關注像素空間擴散 Transformer、影像生成品質提升，以及自監督式學習中寄存器 token 相關機制如何遷移至生成模型領域的讀者，將能從中獲得啟發。

## 深度分析

#### 方法論解析

##### 1. 寄存器 token（register tokens）在 DiT 中的基本設置
本研究延續 DINOv2 [12] 的作法，將寄存器 token 視為額外的可學習 token（learnable tokens），直接附加在圖塊 token（patch tokens）序列之後，並不參與訓練目標的計算。換言之，它們不是透過重建損失（reconstruction loss）或流匹配損失（flow matching loss）被顯式監督，而是藉由自注意力（self-attention）與梯度回傳，自發性地承擔特定功能。在像素空間 DiT（pixel-space DiT，簡稱 pDiT）的實作中，作者採用標準 DiT 架構 [20] 並加入常見的 Transformer 改進 [37, 24]，以 flow matching [38, 39] 在 ImageNet [40] 256×256、patch size 16 的設定下訓練。

##### 2. 與 ViT 的關鍵差異：無圖塊 token 離群值
在 ViT（如 DINOv2）中，高範數圖塊 token 離群值（high-norm patch-token outliers）常出現在低資訊區域（例如背景），導致注意力圖（attention maps）出現偽影（artifacts）。本研究發現，無論是像素空間或潛空間（latent-space）的 DiT，在沒有寄存器 token 的情況下，並不會出現類似的圖塊 token 離群值；其注意力仍集中於主要物體（見 Figure 1）。然而，一旦加入寄存器 token，這些寄存器 token 本身會發展出高範數（high norm），成為「範數匯點」（norm sinks）。這顯示 DiT 中寄存器 token 的作用機制與 ViT 並不完全相同：在 ViT 中，寄存器主要是「吸收」原本出現在圖塊上的異常；在 DiT 中，寄存器則是主動創造出新的高範數結構，並透過此結構改善生成品質。

##### 3. 像素空間與潛空間的不對稱性
研究進一步比較像素空間 DiT（pDiT、PixelDiT [25]）與潛空間 DiT（SiT [21]、RAE [41]）。結果顯示，寄存器 token 對像素空間模型的幫助遠大於潛空間模型；後者僅有溫和增益，甚至有時會略微劣化。這促使作者將分析焦點放在像素空間 DiT。透過中間表徵（intermediate representations）分析，作者發現寄存器 token 在高雜訊層級（high noise levels）下能顯著降低圖塊 token 的特徵範數，並產生更平滑的特徵圖（feature maps）。這暗示寄存器 token 在像素空間生成中的價值，可能來自於對高雜訊階段特徵的「清理」與結構化，而非單純吸收離群值。

##### 4. 寄存器 token 的功能分工
作者觀察到寄存器 token 會自然分化成兩種角色：
- **範數匯點（norm sinks）**：少數寄存器 token 承擔高範數，穩定訓練動態。
- **語義編碼器（semantic encoders）**：其他寄存器 token 編碼全域語義資訊（global semantic information），協助維持物體結構與連貫性（visual structure and coherence）。

##### 5. Register Guidance（RG）的提出
基於上述觀察，作者提出 **Register Guidance（寄存器引導）**。其核心概念是：將「沒有寄存器 token 的模型預測」視為較弱模型（weak model）的預測，並將其作為負向方向（negative direction）；再與分類器無引導（Classifier-Free Guidance, CFG）[36] 結合，強化那些由寄存器 token 負責改善的視覺結構與連貫性。具體而言，RG 可視為在取樣階段對寄存器貢獻的放大：透過比較「有寄存器」與「無寄存器」兩個模型的輸出差異，提取出寄存器所帶來的結構性改進，並沿此方向對生成結果進行修正。這種作法不需要重新訓練主模型，僅在推論（inference）階段引入額外的前向傳播，因此具有較高的實用彈性。

#### 實驗數據解讀

##### 1. 生成品質：FID 的比較
Table 1 報告了 pDiT-B/16、pDiT-L/16、pDiT-H/16 與 PixelDiT-XL/16 在不同訓練週期（epochs）下的 FID（Fréchet Inception Distance）↓ 分數。數據顯示：

| 模型 | 無寄存器（w/o regs.） | 有寄存器（w/ regs.） | 上下文類別條件（IC） |
|---|---|---|---|
| pDiT-B/16 @ 200 epochs | 7.39 | 5.30 | 4.71 |
| pDiT-B/16 @ 600 epochs | 4.80 | 3.80 | 3.71 |
| pDiT-L/16 @ 200 epochs | 4.13 | 3.17 | 2.95 |
| pDiT-L/16 @ 600 epochs | 2.80 | 2.47 | 2.47 |
| pDiT-H/16 @ 200 epochs | 3.52 | 2.69 | 2.38 |
| pDiT-H/16 @ 600 epochs | 2.35 | 2.02 | 1.90 |
| PixelDiT-XL/16 @ 80 epochs | 2.74 | 2.24 | 2.28 |
| PixelDiT-XL/16 @ 120 epochs | 2.25 | 2.12 | 2.12 |

**解讀重點：**
- **寄存器 token 帶來穩定且顯著的 FID 改善**：從 pDiT-B 到 pDiT-H，加入寄存器後 FID 平均下降約 0.9–2.1 點，顯示其效益跨尺度一致。
- **像素空間模型受益最大**：相較於潛空間 DiT（SiT、RAE）僅有溫和增益，像素空間模型的改善幅度更大，支持本文核心論點。
- **與上下文類別條件（in-context class conditioning, IC）的關係**：IC 欄位顯示，使用額外的類別條件 token 也能達到與寄存器相近甚至更好的效果。作者認為這些類別條件 token 實際上扮演了類寄存器（register-like）的角色，其性能提升可能來自寄存器機制，而非額外的類別資訊本身。

##### 2. Token 範數行為分析
Figure 2 比較了 DINOv2 ViT-B/14 與 pDiT-B/16 在有無寄存器 token 時的 token 範數分佈：
- **DINOv2 無寄存器**：少數圖塊 token 出現明顯高範數離群值。
- **DINOv2 有寄存器**：高範數離群值轉移至寄存器 token，符合原始設計動機。
- **pDiT 無寄存器**：圖塊 token 範數分佈均勻，無明顯離群值。
- **pDiT 有寄存器**：雖然原本無離群值，但寄存器 token 仍發展出高範數。

這組實驗強化了「DiT 與 ViT 的寄存器機制不同」的論點。在 DiT 中，寄存器並非被動吸收既有異常，而是主動創造新的功能結構。

##### 3. 高雜訊層級的特徵圖改善
作者進一步分析中間表徵，發現寄存器 token 在高雜訊層級（high noise levels）下能產生更乾淨、更平滑的特徵圖（cleaner feature maps）。這與擴散模型（diffusion models）的取樣動態密切相關：在取樣早期，影像仍處於高雜訊狀態，此時模型需要建立正確的全域結構；寄存器 token 似乎在此階段發揮了穩定結構、抑制雜訊干擾的作用。

##### 4. Register Guidance 的效果
雖然提供的上下文未給出 RG 的詳細數據表，但根據摘要與引言，RG 結合 CFG 後能「持續改善近期像素空間 DiT 的表現」。這表示 RG 是一種推論階段的增強技術，對已訓練好的模型具有即插即用（plug-and-play）的潛力。

#### 與現有研究的比較

##### 1. 與 DINOv2 / ViT 寄存器研究的關係
DINOv2 [12] 提出寄存器 token 是為了解決 ViT 中的高範數圖塊 token 離群值問題。本文發現 DiT 並不繼承此問題，但寄存器 token 仍然有效，且作用機制不同。這挑戰了「寄存器僅在存在離群值時才有用」的直覺，並將寄存器研究從判別式 ViT 延伸至生成式 DiT。

##### 2. 與潛在擴散模型（Latent Diffusion Models）的關係
傳統潛在擴散模型（latent diffusion models）[27, 28] 依賴預訓練自編碼器（pretrained autoencoders）將影像壓縮至潛空間。近期研究重新探討像素空間訓練 [24, 25, 26]，並引入額外的上下文條件 token。本文指出，這些設計的強大實證表現（empirical performance）可能部分來自於類寄存器機制（register-like mechanisms），而非單純來自額外條件資訊。這為像素空間 DiT 的設計提供了新的理論視角。

##### 3. 與注意力匯點（Attention Sinks）研究的關係
近期研究探討 Transformer 中的注意力匯點（attention sinks）與特殊 token 行為 [29, 30, 31, 32, 33, 34]。本文將此議題帶入影像擴散 Transformer（image diffusion transformers）領域，並具體分析寄存器 token 在生成模型中的角色分工（norm sinks vs. semantic encoders）。

##### 4. 與 Classifier-Free Guidance（CFG）的關係
Register Guidance 並非要取代 CFG，而是與之互補。CFG 透過有條件與無條件預測的差異來提升條件生成品質；RG 則進一步利用「有寄存器」與「無寄存器」預測的差異，強化視覺結構與連貫性。這種雙重引導策略可視為對 CFG 框架的自然延伸。

##### 5. 限制與待釐清之處
- **機制解釋仍屬現象層面**：雖然作者觀察到寄存器 token 在高雜訊層級改善特徵圖，但背後的數學機制（例如為何像素空間比潛空間更受益）仍有待更深入理論分析。
- **實驗範圍集中於 ImageNet**：所有主要實驗均在 ImageNet 256×256 上進行，尚未驗證於更高解析度、更複雜場景或其他資料集。
- **潛空間模型的負面結果**：潛空間 DiT 加入寄存器後僅有溫和增益或略微劣化，這限制了寄存器 token 的通用性，也暗示其效益與訓練空間（像素 vs. 潛在）高度相關。
- **計算成本**：RG 在推論階段需要額外執行一次無寄存器模型的前向傳播，會增加約一倍的計算開銷，對於即時應用可能構成挑戰。

#### 可重現性評估

##### 1. 資料集與訓練設定
本研究主要使用 ImageNet [40] 256×256 解析度進行訓練與評估，採用 flow matching [38, 39] 作為訓練目標。對於 pDiT，patch size 為 16，模型尺寸涵蓋 B、L、H；對於 PixelDiT [25] 則遵循原始設定。潛空間模型 SiT [21] 與 RAE [41] 也使用其原始骨幹與訓練流程。這些設定與現有文獻一致，理論上具備可重現性。

##### 2. 開源資源與程式碼
根據提供的上下文，作者提及「Project page」，但未明確說明是否釋出原始碼、模型權重（model weights）或訓練腳本。附錄（App. B）應包含進一步實作細節，但具體開放程度需查閱專案頁面確認。對於可重現性而言：
- **正向因素**：使用的架構（DiT、PixelDiT、SiT、RAE）多為已公開模型；訓練目標（flow matching）與資料集（ImageNet）為標準配置；FID 評估指標亦為業界標準。
- **不確定因素**：若未釋出完整程式碼與預訓練權重，其他研究者需自行實作寄存器 token 的插入方式、Register Guidance 的推論邏輯，以及再現 Table 1 的訓練流程，這會增加重現難度。

##### 3. 建議的重現步驟
對於希望驗證本文結果的研究者，建議依以下順序進行：
1. 取得 ImageNet 256×256 資料集與標準預處理流程。
2. 基於公開 DiT 程式碼實作 pDiT，並在 patch token 序列後附加可學習的寄存器 token。
3. 使用 flow matching 訓練模型，記錄不同 epoch 的 FID。
4. 對已訓練模型實作 Register Guidance：同時執行「有寄存器」與「無寄存器」兩個前向傳播，計算其差異並結合 CFG 進行取樣。
5. 比較有無 RG 的 FID 與視覺品質。

#### 未來研究方向

##### 1. 理論機制的深入剖析
目前對於「為何像素空間 DiT 特別受益於寄存器 token」的解釋仍偏向經驗性。未來可從以下角度深入研究：
- 建立數學模型描述寄存器 token 在高雜訊層級的動態行為。
- 分析像素空間與潛空間的特徵分佈差異，解釋為何寄存器在兩者中效果不同。
- 探討寄存器 token 數量、位置、初始化方式對生成品質的影響。

##### 2. 寄存器 token 的動態與自適應設計
現有作法使用固定數量的可學習寄存器 token。未來可探索：
- **自適應寄存器數量**：根據輸入影像複雜度或雜訊層級動態調整寄存器數量。
- **可學習的寄存器角色分配**：透過正則化或輔助任務，明確區分 norm sinks 與 semantic encoders 的角色。
- **跨層共享 vs. 獨立寄存器**：研究寄存器 token 是否應在每層獨立或跨層共享參數。

##### 3. 擴展至其他生成模態
本文聚焦於影像生成，但寄存器 token 的概念可延伸至：
- **影片生成（video generation）**：在時空圖塊（spatio-temporal patches）中加入寄存器 token，穩定長序列的時間連貫性。
- **3D 生成**：在點雲（point clouds）或體素（voxels）的 Transformer 中引入寄存器 token。
- **多模態生成**：進一步研究文字序列中某些 token 成為 sinks 的現象，並設計更穩定的跨模態條件機制。

##### 4. Register Guidance 的進一步發展
RG 目前僅使用「有/無寄存器」的預測差異。未來可探索：
- 結合多個不同配置的弱模型（weak models），形成更豐富的負向方向。
- 將 RG 與其他推論階段增強技術（例如動態閾值、取樣器改進）結合。
- 降低 RG 的計算成本，例如透過知識蒸餾（knowledge distillation）將無寄存器模型的行為壓縮至單一模型中。

##### 5. 與近期像素空間 DiT 設計的整合
本文指出 in-context class conditioning 可能本質上是類寄存器機制。未來可重新審視其他像素空間 DiT 的設計選擇（例如額外的條件 token、特殊的位置編碼），判斷其中是否隱含寄存器效應，並據此設計更精簡、更有效的架構。

## 論文問答

**Q1：在視覺 Transformer（ViT）中，寄存器 token 原本是用來解決什麼問題？為什麼研究者會想把它們應用到擴散 Transformer（DiT）上？**  
A：在 ViT 中，自注意力層常會出現少數「高範數圖塊 token 離群值」，這些離群值通常落在背景或低資訊區域，導致特徵圖與注意力圖出現偽影，並損害密集預測任務的表現。寄存器 token 的引入可以把這些異常的全域資訊「吸收」進額外的可學習 token 中，從而改善特徵圖品質。隨著擴散模型逐漸採用 Transformer 架構，並從潛空間回到像素空間訓練，DiT 在形式與輸入表示上越來越接近 ViT，因此自然會問：這種離群值問題是否也存在於 DiT，而寄存器 token 是否同樣有效？

**Q2：為什麼不能直接把 ViT 上「有離群值才需要寄存器」的邏輯套用到 DiT？**  
A：本研究發現，無論是像素空間還是潛空間的 DiT，在沒有加入寄存器 token 的情況下，圖塊 token 的範數分布都相對均勻，並未出現 ViT 那種明顯的高範數離群值。這表示 DiT 並非因為「需要修正離群值」而受益於寄存器，其增益來自與 ViT 不同的機制。因此，若僅以「是否存在離群值」作為是否加入寄存器的判準，會錯失在像素空間 DiT 中透過寄存器改善生成品質的機會。

**Q3：研究像素空間 DiT 中的寄存器行為有什麼實務重要性？**  
A：近期許多高效能的影像生成模型重新轉向像素空間訓練，這使得理解該設定下的 Transformer 行為變得至關重要。如果寄存器 token 能穩定提升像素空間 DiT 的視覺結構與連貫性，就能在不大幅改動架構的前提下改善生成品質。此外，這些觀察也能解釋為何某些新穎架構（如加入額外類別條件 token）表現出色，並為後續設計提供理論依據。

**Q4：本文最核心的發現是什麼？DiT 與 ViT 在 token 範數行為上有何關鍵差異？**  
A：本文最核心的發現是：DiT 雖然沒有 ViT 常見的圖塊 token 離群值，但加入寄存器 token 後仍能在像素空間模型中帶來顯著增益。具體而言，未加寄存器時，DiT 的注意力圖與 token 範數都未出現背景異常；然而一旦加入寄存器，高範數現象會轉移到這些額外 token 內部，形成類似「規範匯點」的角色。這說明寄存器在 DiT 中的作用並非單純「修正」既有離群值，而是主動重新組織模型內部的資訊流與語義分工。

**Q5：寄存器 token 在像素空間 DiT 中發揮作用的機制，與在 ViT 中有何不同？**  
A：在 ViT 中，寄存器主要用來承接原本出現在圖塊 token 上的高範數離群值，從而減少特徵圖偽影；而在像素空間 DiT 中，寄存器則更傾向於降低整體圖塊 token 的特徵範數，並在高雜訊層級產生更平滑、更清晰的中間表徵。進一步觀察發現，DiT 中的寄存器會分化成不同功能：一部分成為 norm sink，另一部分則編碼全域語義資訊。這種分工讓模型在生成過程中更能維持物體結構與影像連貫性，而不只是處理離群值。

**Q6：什麼是 Register Guidance（RG）？它如何具體利用寄存器 token 的貢獻？**  
A：Register Guidance 是本文提出的一種推論階段技術，它把「沒有寄存器的模型預測」視為較弱或較差的生成方向，並將其作為負向引導。透過與分類器無條件引導（CFG）結合，RG 放大那些負責改善視覺結構與連貫性的寄存器 token 之貢獻，使最終輸出更銳利、結構更完整。由於 RG 不需要重新訓練模型，僅在取樣時額外做一次無寄存器模型的前向傳播，因此能方便地應用於已訓練好的像素空間 DiT。

**Q7：實驗使用了哪些模型與設定來評估寄存器 token 的效果？**  
A：研究主要聚焦於像素空間 DiT，包括基於標準架構並結合近期改進的 pDiT（以 flow matching 在 ImageNet 256×256、patch size 16 上訓練），以及更先進的 PixelDiT-XL/16。同時也分析了潛空間架構 SiT 與 RAE，其中 RAE 使用 DINOv2 作為骨幹。所有模型都設置了多種尺寸（如 B/16、L/16、H/16），並比較「無寄存器」、「有寄存器」以及「in-context 類別條件」三種設定，以 FID 作為生成品質指標。

**Q8：表 1 的主要定量結果顯示了什麼趨勢？**  
A：表 1 顯示，加入寄存器 token 後，像素空間 pDiT 與 PixelDiT 的 FID 在多個模型尺寸與訓練週期下均明顯下降，例如 pDiT-B/16 在 200 epoch 時從 7.39 降至 5.30，pDiT-H/16 在 600 epoch 時從 2.35 降至 2.02，PixelDiT-XL/16 在 120 epoch 時從 2.25 降至 2.12。相較之下，潛空間模型的改善幅度較小，甚至有時會略微退化，凸顯寄存器對像素空間 DiT 的特別重要性。此外，in-context 類別條件（IC）的表現與加入寄存器相近，暗示其增益可能來自類寄存器行為，而非額外的類別資訊本身。

**Q9：對中間表徵與 token 範數的分析揭示了哪些現象？**  
A：透過視覺化 token 範數與注意力圖，作者發現未加寄存器的 DiT 並未像 ViT 那樣在背景區域出現高範數離群值，注意力仍集中於主要物體。加入寄存器後，高範數現象轉移到寄存器 token 本身，而圖塊 token 的整體範數則被壓低，中間特徵圖變得更平滑，尤其在高雜訊層級效果更明顯。這些現象說明寄存器在 DiT 中扮演了「資訊調節者」的角色，有助於在強雜訊條件下維持清晰的語義結構。

**Q10：在實際應用中，Register Guidance 可以如何被整合到現有的生成流程？**  
A：Register Guidance 可以在不修改模型權重或重新訓練的情況下，直接套用在已訓練好的像素空間 DiT 的取樣階段。開發者只需額外執行一次「移除寄存器」的模型前向傳播，將其輸出視為負向方向，再與 CFG 結合即可提升視覺結構與連貫性。這種低成本的推論增強特別適合需要高品質影像生成的產品，例如影像編輯、內容創作工具或互動式生成系統。

**Q11：從產品部署的角度，加入寄存器 token 會帶來哪些考量？**  
A：加入寄存器 token 會略微增加序列長度與計算量，但由於數量通常很少，對訓練與推論開銷的影響相對有限。在部署時，需要確認模型權重與推論框架支援額外的可學習 token，並評估延遲與記憶體預算。另一方面，Register Guidance 雖然需要額外一次前向傳播，但能顯著改善結構完整性，對於重視視覺品質的應用而言，這樣的取樣成本通常是可接受的。

**Q12：這些發現對未來 DiT 架構設計可能產生什麼影響？**  
A：研究結果暗示，近期像素空間 DiT 中加入額外 in-context 類別條件 token 的設計，其實可能是在利用類寄存器機制來提升表現，這提醒設計者應區分「條件資訊」與「結構調節 token」的不同作用。未來架構可以更有意識地配置專門的寄存器 token，並根據訓練空間（像素空間 vs. 潛空間）調整其數量與角色。此外，將寄存器概念延伸到文字生成影像、影片生成或其他模態的擴散 Transformer，也可能成為提升全域一致性的新方向。

**Q13：本文承認哪些限制？**  
A：本文主要針對影像生成任務進行分析，且大部分實驗集中在 ImageNet 256×256 的條件生成設定，對於其他解析度、資料集或無條件生成的泛化性仍需更多驗證。此外，研究發現寄存器在潛空間 DiT 中的效益有限，有時甚至會造成輕微退化，這表示寄存器並非對所有擴散 Transformer 都適用。最後，Register Guidance 雖然有效，但仍需額外計算無寄存器模型的前向傳播，對延遲極度敏感的場景可能不是最佳選擇。

**Q14：在哪些情況下，寄存器 token 可能不會帶來明顯幫助，甚至可能有害？**  
A：當模型在潛空間訓練時，由於潛在表示已經過自編碼器壓縮與結構化，圖塊 token 的動態與像素空間不同，加入寄存器可能只帶來邊際效益或輕微干擾。如果任務本身不需要強調全域結構或物體連貫性，例如某些風格化或抽象生成，寄存器的語義調節作用可能不那麼重要。此外，若寄存器數量過多或初始化不當，也可能導致部分 token 無法有效分工，反而浪費參數容量。

**Q15：未來研究可以朝哪些方向延伸？**  
A：未來可以進一步探討寄存器 token 在不同解析度、不同資料規模以及文字生成影像等設定中的行為，以確認其普遍性。另一個方向是設計自適應或動態的寄存器機制，讓模型根據雜訊層級或輸入內容自動調整寄存器的作用。最後，將 Register Guidance 與其他推論階段增強技術結合，並深入理解寄存器作為 norm sink 與語義編碼者之間的最佳平衡，將有助於開發更穩定、更高品質的像素空間擴散 Transformer。

## 實務應用指南

### 適用場景

1. **高解析度像素空間影像生成產品**  
   適合直接以像素空間訓練的 DiT（如 pDiT、PixelDiT）作為基底的文生圖、類別條件生成或風格合成服務，特別是當團隊希望避免潛在擴散模型（latent diffusion）對預訓練自編碼器的依賴時。

2. **需要強化物體結構與連貫性的生成任務**  
   例如商品圖生成、角色一致性渲染、建築或室內設計草圖轉影像，這類應用對「視覺結構」與「空間連貫性」敏感，Register Guidance 可作為推論階段的輔助手段。

3. **影像編輯與修復工具**  
   在像素空間 DiT 上加入寄存器 token 後，高雜訊層級的中間特徵圖更平滑，有助於提升修復（inpainting）、外推（outpainting）或區域重繪結果的邊界一致性。

4. **自研基礎生成模型的內部研究與微調**  
   若企業正在從頭訓練影像擴散 Transformer，可透過寄存器 token 與 Register Guidance 進行架構層級實驗，以理解特殊 token 對生成品質的影響。

5. **結合文字條件生成（text-to-image）的進階應用**  
   論文觀察到文字序列中某些 token 也會形成類似「注意力匯點」的行為，因此相關洞察可應用於改善文字編碼器與像素空間 DiT 的互動設計。

---

### 實作前置條件

- **資料**：需要大規模高品質影像資料集（如 ImageNet 等級或更大），解析度建議至少 256×256，並具備對應的類別標註或文字描述。資料品質與多樣性對像素空間訓練的穩定性影響極大。
- **運算資源**：訓練像素空間 DiT 需要大量 GPU 記憶體與運算力，建議使用多張高階 GPU（如 A100/H100）並搭配分散式訓練框架；推論階段 Register Guidance 需要同時載入「有寄存器」與「無寄存器」兩個模型，記憶體需求會顯著增加。
- **技術能力**：團隊需熟悉 Transformer、擴散模型／flow matching、自注意力機制，以及至少一種深度學習框架（如 PyTorch）。此外，需要具備分析 token 範數與注意力圖的能力，以驗證寄存器 token 是否正確發揮作用。
- **程式碼與模型基礎**：建議先準備可運作的像素空間 DiT 程式碼庫（如參考 pDiT、PixelDiT 或 SiT 的開源實作），並確認已能正常訓練與評估 FID 等指標。

---

### 實作步驟建議

1. **選定像素空間 DiT 基線**  
   優先選擇像素空間架構（pDiT-B/L/H 或 PixelDiT-XL），因為論文顯示寄存器 token 在像素空間的效益明顯高於潛空間 DiT。

2. **加入寄存器 token**  
   在輸入序列的圖塊 token 後追加數個可學習的寄存器 token（常見數量為 4 個，可視模型大小調整）。這些 token 不參與重建目標，僅透過自注意力與其他 token 互動。

3. **訓練與監控**  
   使用 flow matching 進行訓練，同時監控各層 token 的 L2 範數與注意力圖。重點觀察：  
   - 圖塊 token 是否仍維持較均勻的範數分布（無離群值）；  
   - 寄存器 token 是否出現高範數，並確認部分寄存器編碼全域語義、部分成為範數匯點。

4. **評估生成品質**  
   以 FID 為主要指標，比較「無寄存器」、「有寄存器」以及「in-context class conditioning」等變體。若像素空間模型顯著受益，則繼續下一步；若為潛空間模型，則需審慎評估是否值得引入。

5. **導入 Register Guidance**  
   在推論時同時載入「有寄存器」與「無寄存器」兩個模型。將無寄存器模型的預測視為弱模型，沿著有寄存器模型相對於弱模型的方向進行加強，並與 CFG（Classifier-Free Guidance）結合。公式可參考：  
   \[
   \hat{\epsilon} = \epsilon_{\text{reg}} + \lambda_{\text{RG}}\,(\epsilon_{\text{reg}} - \epsilon_{\text{no-reg}})
   \]
   其中 \(\lambda_{\text{RG}}\) 為 Register Guidance 強度，需透過驗證集調整。

6. **部署與迭代**  
   將調校後的模型與 Register Guidance 整合至推論管線，持續監控生成結果的結構一致性、記憶體消耗與延遲，並針對特定應用場景進行微調。

---

### 潛在風險與注意事項

- **不適用於所有 DiT 變體**  
  寄存器 token 對像素空間 DiT 效果較佳，對潛空間 DiT（如 SiT、RAE）可能僅有微幅提升甚至輕微劣化，導入前應先進行對照實驗。

- **記憶體與運算成本增加**  
  每增加一個寄存器 token，序列長度與自注意力計算量都會上升；Register Guidance 更需要同時執行兩個模型，建議評估模型壓縮或快取策略。

- **超參數敏感**  
  寄存器數量與 Register Guidance 強度 \(\lambda_{\text{RG}}\) 需要仔細調校，過強可能導致過度平滑或細節遺失，過弱則無法發揮結構改善效果。

- **高範數寄存器 token 的穩定性**  
  雖然論文觀察到寄存器會形成高範數 token，但訓練初期可能出現不穩定，建議搭配梯度裁剪、學習率預熱與範數監控。

- **資料規模不足時效果有限**  
  像素空間 DiT 本身就需要大量資料才能穩定訓練，若資料集過小，寄存器 token 可能無法學到有意義的全域語義，反而淪為多餘參數。

- **與現有條件機制的重疊**  
  若模型已使用 in-context class conditioning 或文字條件 token，這些 token 可能已具備類寄存器行為，額外加入寄存器時需避免功能重疊與干擾。

---

### 與其他技術的整合建議

- **與 CFG 結合**  
  Register Guidance 並非取代 CFG，而是與其互補。建議在推論管線中將兩者串接：先套用 CFG 獲得條件化預測，再疊加 Register Guidance 強化結構與連貫性。

- **與控制式生成方法搭配**  
  可將寄存器強化後的像素空間 DiT 作為主幹，再結合 ControlNet、IP-Adapter 或 T2I-Adapter 等控制機制，進一步提升生成結果的可控性。

- **與微調與輕量化技術並用**  
  針對特定領域資料，可在已加入寄存器的預訓練模型上使用 LoRA、DoRA 或 Adapter 進行高效微調，避免從頭訓練整個模型。

- **與加速採樣技術整合**  
  Register Guidance 會增加每步推論成本，可搭配蒸餾模型、少步數採樣器（如 DPM-Solver++、Flow Matching 的 ODE solver）或推論快取來降低延遲。

- **與 MLOps 管線銜接**  
  建議將「有寄存器／無寄存器」兩個模型版本納入模型倉庫管理，並在 A/B 測試框架中比較 Register Guidance 對使用者感知品質的影響。

### 給不同背景讀者的閱讀建議

- **初學者**：這篇論文探討的是在影像生成模型中加入額外的「寄存器 token」是否能讓生成結果更穩定、結構更清晰。你可以先理解「Vision Transformer 會出現高範數離群 token」這個現象，再對照論文發現「擴散 Transformer 雖然沒有這個問題，但加入寄存器仍然有用」這個反直覺結論。重點看摘要、圖 1、圖 2 與表 1，不必急著深入 Register Guidance 的數學細節。

- **AI 工程師**：建議聚焦第 2 節的實作細節與 Register Guidance 的推論流程。你應該關注如何在現有像素空間 DiT 程式碼中插入可學習寄存器 token、如何監控 token 範數與注意力圖，以及如何將「有／無寄存器」兩個模型的預測整合到 CFG 管線中。論文對潛空間與像素空間的差異分析，能幫助你判斷這個方法是否適合你的模型。

- **研究人員**：本研究的核心貢獻在於挑戰「寄存器 token 僅用於解決高範數離群值」的既有觀點，並提出像素空間 DiT 中寄存器透過「平滑高雜訊層級特徵圖」與「分化為語義編碼器／範數匯點」來發揮作用。建議深入分析中間表徵實驗，並思考這些發現對其他生成架構（如影片、3D 生成）的泛化性。

- **產品經理**：這項技術適合已經在投入自研像素空間生成模型的團隊，作為提升影像結構一致性與 FID 的潛在優化手段。需要評估的是額外的訓練與推論成本、對現有產品延遲的影響，以及是否能與現有的 CFG、ControlNet 等機制無縫整合。建議以小型實驗驗證使用者感知品質提升後，再決定是否投入大規模部署。
