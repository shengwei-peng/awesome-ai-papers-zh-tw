## 摘要翻譯

從三維模型（3D shape）重建可編輯的 CAD 模型仍是一項具挑戰性的工程任務。現有方法雖能提出 CAD 操作（CAD Operation），但沒有任何單一提案來源能在不同的零件幾何與重建階段中同樣表現良好。我們提出 CADFather，一個自主代理系統（Agentic System），透過協調互補的工具，從三維網格（3D Mesh）中恢復參數化 CAD 程式（Parametric CAD Program）。一個視覺語言助理（Vision-Language Assistant）檢視目標渲染圖（Target Render）與中間重建結果（Intermediate Reconstruction），然後決定要延伸哪些候選 CAD 程式（Candidate Program）、呼叫哪些工具、產生多少提案，以及何時結束。學習式方法（Learned Approach）與演算法方法（Algorithmic Approach）工具提出 CAD 操作，而數值參數最佳化（Numerical Parameter Optimization）則精修（Refinement）現有程式的參數。提案或精修後的程式會被執行並評估，以提供回饋（Feedback）供後續決策使用。代理為每個目標零件維護多組候選程式，並在整個重建過程中保留最佳的有效結果。CADFather 使用預訓練的生成模型（Generation Model）與助理模型（Assistant Model），無需額外訓練。我們在完整的 DeepCAD、Fusion360 與 MCB 測試集，以及 CADENA-Bench、CADBench 與 BenchCAD 上評估重建品質（Reconstruction Quality）與執行有效性（Execution Validity）。我們另外分析了計算成本（Computational Cost），以及成本與重建品質之間的取捨（Trade-Off）。

### 核心貢獻（3～5點）
- 提出 CADFather，一個自主代理系統（Agentic System），透過協調式工具使用（Coordinated Tool Use）從三維網格恢復參數化 CAD 程式，無需額外訓練即可運作
- 整合學習式方法（Learned Approach）、演算法方法（Algorithmic Approach）與數值參數最佳化（Numerical Parameter Optimization）三類互補工具，由視覺語言助理（Vision-Language Assistant）統一調度決策
- 設計多候選程式（Candidate Program）維護機制與回饋（Feedback）驅動的迭代式重建（Iterative Reconstruction）流程，於每個零件保留最佳有效結果
- 在 DeepCAD、Fusion360、MCB 完整測試集及 CADENA-Bench、CADBench、BenchCAD 等多個基準上進行系統性評估，並分析計算成本（Computational Cost）與重建品質（Reconstruction Quality）之間的取捨（Trade-Off）

### 適合對象
從事 CAD 重建（CAD Reconstruction）、電腦輔助設計自動化、三維幾何處理、視覺語言模型代理應用等領域的研究人員與工程師；以及對 AI 驅動工程設計工具與代理系統（Agentic System）感興趣的產業界實務工作者。

## 深度分析

#### 方法論解析

CADFather 的核心設計理念在於將 CAD 重建（CAD Reconstruction）視為一個**代理驅動的搜尋過程**（agent-driven search process），而非單一模型的端到端預測任務。系統採用三層架構：候選程式池（candidate program pool）、視覺語言助理（vision-language assistant）作為決策中樞，以及三類互補工具（learned proposal、algorithmic proposal、parameter optimization）。

**候選程式池管理機制**：系統為每個目標零件（target part）維護多個替代候選程式（alternative candidate programs），而非僅追蹤單一重建路徑。這種設計的關鍵優勢在於：當某個候選程式的後續操作失敗或品質下降時，系統可隨時回退至先前保留的最佳有效結果（best valid result）。此機制類似於搜尋演算法中的 beam search 或 best-first search，但決策由視覺語言助理根據渲染回饋動態做出，而非依賴固定的啟發式函數。

**視覺語言助理的決策迴圈**：在每個重建步驟中，助理接收四類輸入資訊：(1) 目標渲染圖（target render）與中間重建結果（intermediate reconstruction）的視覺對比；(2) 幾何評分（geometric score）反映當前擬合程度；(3) 可用動作集合（available actions）；(4) 已執行請求的歷史記錄（history of executed requests）。基於這些資訊，助理需做出四類決策：選擇要延伸或精修的候選、決定呼叫哪個工具、指定學習式提案的採樣數量（how many learned proposals to sample）、以及判斷何時終止重建。這種設計將高層次的策略選擇與低層次的幾何操作解耦，使每個元件可獨立替換。

**三類工具的互補設計**：
- **學習式提案生成**（learned proposal generation）：採用預訓練的操作生成器（pretrained operation generator），能提出符合訓練分布的合理建模操作（modeling operations），但可能遺漏特定特徵或使用不精確的尺寸。
- **演算法式提案生成**（algorithmic proposal generation）：直接從目標幾何推導操作，不依賴學習模型，提供幾何導向的替代方案。
- **數值參數最佳化**（numerical parameter optimization）：保留現有程式的操作結構，僅調整參數以改善擬合度。

此三類工具透過**統一介面**（common tool interface）整合，使助理可在同一決策框架下靈活調度。值得注意的是，CADFather 不需要對操作生成器或助理進行額外訓練（without additional training），這大幅降低了部署成本並提升了泛化潛力。

**回饋驅動的迭代流程**：每個被提出的程式都會被執行（executed）並測量其幾何擬合度，助理再根據渲染結果決定是否將其納入候選池。這形成一個 closed loop：執行 → 評估 → 決策 → 執行，與 CADENA 的逐步延伸策略類似，但 CADFather 進一步引入了多候選管理與工具協調機制。

#### 實驗數據解讀

論文在六個資料集上進行了全面評估：**DeepCAD**、**Fusion360**、**MCB** 的完整測試集，以及 **CADENA-Bench**、**CADBench**、**BenchCAD** 三個基準測試。這種跨資料集評估策略對於驗證方法的泛化能力至關重要，因為不同資料集在零件複雜度、建模風格與操作類型上存在顯著差異。

**評估指標的設計意涵**：論文同時關注三類指標——**重建品質**（reconstruction quality）、**執行有效性**（execution validity）與**計算成本**（computational cost）。這種多面向評估反映了 CAD 重建任務的特殊性：僅追求幾何擬合可能產生無法執行的程式，而僅追求執行性則可能犧牲編輯價值。三者的平衡是實務應用的關鍵。

**消融實驗的設計價值**：論文透過移除演算法式提案、參數最佳化或兩者同時移除的消融實驗（ablation），驗證了各工具模組的貢獻。這種設計能清楚區分各元件的邊際效益，特別是能揭示在何種零件類型或重建階段下，特定工具最具價值。例如，演算法式提案可能在處理標準幾何特徵（如圓柱、平面）時特別有效，而學習式提案在處理複雜自由形狀時更具優勢。

**成本與品質的取捨分析**（trade-off between cost and reconstruction quality）：論文特別分析了計算成本與重建品質的關係，這對於實際部署至關重要。代理系統的迭代特性意味著品質提升伴隨著計算成本增加，助理需要在探索（exploration）與利用（exploitation）之間取得平衡。學習式提案的採樣數量（how many proposals to sample）是關鍵的控制參數——更多提案增加找到優質解的機會，但也提高計算開銷。

**跨資料集泛化表現**：在 DeepCAD、Fusion360、MCB 三個差異顯著的資料集上同時取得競爭性結果，顯示了 CADFather 框架的適應性。值得注意的是，CADFather 使用預訓練模型而無需微調（without additional training），這與需要針對特定資料集微調的 CAD-Recode、cadrille 等方法形成對比，凸顯了代理方法在跨資料集遷移上的優勢。

#### 與現有研究的比較

CADFather 的定位可從三個維度理解：**重建範式**、**工具整合**、**決策機制**。

**與單次生成方法的比較**：CAD-Recode、cadrille、CADEvolve 採單次生成（single pass）策略，從幾何觀察直接預測完整 CAD 程式。這類方法的優勢在於推理速度快，但缺乏錯誤修正機制——若預測結果與目標偏差，無法在後續步驟中調整。CADFather 的迭代式重建（iterative reconstruction）透過逐步延伸與回饋修正，在理論上具有更高的品質上限，但代價是更高的計算成本。

**與迭代重建方法的比較**：CADReasoner 對完整程式進行迭代修訂，CADENA 採用逐步延伸策略。CADFather 與 CADENA 的設計哲學最為接近，但關鍵差異在於：(1) CADFather 維護多個候選程式而非單一路徑，提供更強的探索能力；(2) CADFather 整合了演算法式提案與參數最佳化，超越純學習式提案的限制；(3) CADFather 的決策由視覺語言助理驅動，而非固定策略。

**與演算法方法的比較**：CADFit 採用基於最佳化的搜尋（optimization-based search），透過幾何擬合與候選操作驗證進行重建。CADFather 將此類演算法能力整合為工具之一，與學習式提案並存。這種整合避免了「單一提案來源」（single source of proposals）的限制——論文明確指出，沒有單一提案來源能在不同零件幾何與重建階段下都表現優異。

**與視覺代理方法的比較**：CAD-Assistant 與 IterCAD 已展示視覺代理使用可執行 CAD 環境的模式。CADFather 將此模式擴展至多候選重建，並引入專門的提案與精修工具。其核心貢獻在於**整合**（integration）而非單一元件的創新——將既有能力在共享表示與搜尋過程中協調運作。

**主要限制**：
1. **計算成本較高**：迭代式代理方法本質上比單次生成更耗時，雖然論文分析了成本-品質取捨，但在資源受限的場景下可能不具競爭力。
2. **視覺語言助理的可靠性**：決策品質高度依賴助理的視覺理解與推理能力，若助理誤判渲染差異，可能導致錯誤的延伸或終止決策。
3. **候選池管理策略**：保留最佳有效結果的策略簡單有效，但可能錯過需要多步精修才能達到高品質的候選。
4. **工具介面限制**：三類工具的整合雖然互補，但其能力邊界仍受各自底層方法的限制——例如參數最佳化無法改變操作結構。

#### 可重現性評估

從論文提供的資訊評估可重現性（reproducibility）：

**有利因素**：
- 系統使用**預訓練模型**（pretrained models）而無需額外訓練，這大幅降低了重現門檻——無需重現訓練流程或資料準備。
- 評估在**六個公開資料集**上進行，包括 DeepCAD、Fusion360、MCB 等 CAD 領域的標準基準，提升了比較的公平性與可驗證性。
- 論文同時評估**完整系統與消融版本**，使後續研究者能針對特定元件進行深入分析。
- 提供了**計算成本分析**，有助於評估實際部署的可行性。

**潛在挑戰**：
- **視覺語言助理的選擇**：論文未明確說明使用的具體助理模型（assistant model），不同助理的能力差異可能顯著影響結果。雖然聲稱「無需額外訓練」，但助理本身的預訓練品質仍是關鍵變數。
- **工具的具體實作**：演算法式提案與參數最佳化的具體演算法細節需要從附錄或程式碼中確認，僅從方法描述可能難以完整重現。
- **候選池大小與採樣策略**：助理決定「採樣多少學習式提案」的策略對結果有直接影響，但具體的提示工程（prompt engineering）或決策規則需要更詳細的說明。
- **執行環境**：CAD 程式的執行需要特定的 CAD 內核（如 CadQuery），環境配置可能影響執行有效性（execution validity）的評估。

**建議**：為提升可重現性，論文應釋出程式碼、助理提示模板、以及各資料集上的詳細評估結果。特別是消融實驗的具體數值，能幫助研究者理解各元件的邊際貢獻。

#### 未來研究方向

基於 CADFather 的設計理念與實驗結果，可識別以下值得探索的方向：

**1. 助理決策機制的強化**：當前助理依賴視覺語言模型（vision-language model）的通用推理能力，未來可探索：(a) 針對 CAD 領域微調的助理模型，提升對幾何特徵與建模操作的專業理解；(b) 引入結構化推理（如 chain-of-thought）使決策過程更可解釋；(c) 結合符號推理與神經推理，兼顧靈活性與可靠性。

**2. 工具集的擴展與自適應選擇**：現有三類工具的整合已展現互補價值，未來可考慮：(a) 引入更多幾何分析工具（如曲面擬合、特徵識別）作為輔助提案來源；(b) 開發基於學習的工具選擇策略，根據當前重建狀態自動決定最佳工具組合；(c) 探索工具鏈的自動化組合，而非預先定義固定集合。

**3. 效率優化**：代理方法的計算成本是主要瓶頸，可從以下方向優化：(a) 早期終止機制，當候選品質收斂時自動結束；(b) 候選程式的優先級排序，避免在低潛力候選上浪費資源；(c) 平行化執行多個候選的評估；(d) 快取與重用中間結果，減少重複計算。

**4. 編輯價值的顯式建模**：當前評估主要關注幾何擬合，但 CAD 重建的終極價值在於**可編輯性**（editability）。未來可：(a) 定義衡量編輯價值的指標（如參數暴露程度、修改影響範圍）；(b) 在助理決策中引入編輯價值考量，偏好產生結構清晰、參數語義明確的程式；(c) 研究如何從重建結果中自動提取語義標註。

**5. 跨領域遷移與泛化**：CADFather 在六個資料集上的表現已展現泛化能力，但工業場景的 CAD 模型往往更複雜且包含領域特定知識。未來可探索：(a) 整合領域知識庫（如機械設計手冊、製造約束）；(b) 支援非標準建模操作（如曲面、放樣、掃掠）；(c) 處理多零件組裝關係，而非僅限於單一零件重建。

**6. 互動式重建**：當前系統完全自主，未來可引入人類專家的互動：(a) 允許使用者指定偏好（如「使用更多圓角」）；(b) 在關鍵決策點請求人類確認；(c) 從人類修正中學習改進助理策略。這將使系統從純自主代理（autonomous agent）演進為人機協作系統。

**7. 不確定性量化與風險管理**：代理系統的決策具有不確定性，未來可：(a) 為每個候選程式估計品質分布而非單一評分；(b) 開發風險感知的探索策略，優先發展高置信度的延伸方向；(c) 提供重建結果的可信度標註，幫助使用者判斷是否需要人工審查。

**8. 與其他 CAD 能力的整合**：CADFather 專注於重建任務，但 CAD 工作流程包含設計、模擬、製造等多個環節。未來可探索將重建代理與設計助手、模擬驗證、製造性分析等代理整合，形成完整的 CAD 智慧生態系統。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？為什麼從三維網格重建 CAD 模型是一個困難的工程任務？**

A：這篇論文的核心問題是從三維網格（3D mesh）重建出可編輯的參數化 CAD 模型。三維網格雖然能描述形狀的外觀，但本身並不包含建模過程中所使用的操作序列與特徵參數，例如孔徑或壁厚等可編輯參數都無法直接從網格中取得。這個任務之所以困難，是因為重建出來的程式必須同時具備可執行性、結構一致性，以及作為可編輯模型的實用性。當元件僅以掃描結果、舊有網格或缺乏建構歷史的模型形式存在時，如何恢復其完整的建構歷史便成為工程上的關鍵挑戰。

**Q2：現有的 CAD 重建方法為什麼無法單獨勝任這個任務？它們各自的侷限是什麼？**

A：現有方法可分為學習式方法與演算法方法兩大類，但沒有任何單一來源的提案能夠在不同零件幾何與重建階段都同樣表現良好。學習式方法（例如 CAD-Recode、cadrille、CADEvolve）雖然能提出合理的建模操作，但其提案可能會遺漏某些特徵或使用不準確的尺寸。演算法方法（例如 CADFit）透過幾何擬合與最佳化搜尋來重建目標，但對於複雜結構的處理能力有限。此外，單次生成（single pass）的方法無法根據中間結果進行修正，而迭代式方法（如 CADReasoner、CADENA）雖然能逐步改進，但各自也有其適用的場景限制。

**Q3：為什麼這項研究在工程實務上具有重要價值？哪些情境特別需要這種技術？**

A：這項研究的價值在於它能讓僅以網格形式存在的元件重新獲得可編輯性，這對於許多工程實務場景至關重要。當一個零件只有掃描結果、舊有網格或缺乏建構歷史的模型時，工程師無法直接修改其特徵參數，而重建出可執行的 CAD 程式能將這些參數暴露出來供檢查與修改。這種能力在逆向工程、舊有零件的設計迭代、以及需要從實體物件恢復設計意圖的場景中特別有用。透過恢復建構歷史，設計師可以更有效率地對既有元件進行修改、再製造或設計變更。

**Q4：CADFather 的核心方法是什麼？它如何協調不同的工具來完成重建任務？**

A：CADFather 是一個自主代理系統（agentic system），透過視覺語言助理（vision-language assistant）來協調三種互補的工具：學習式提案生成、演算法提案生成，以及參數最佳化。在每一步中，助理會檢視目標與候選程式的渲染圖、幾何評分、可用動作以及已執行請求的歷史，然後選擇要延伸或精修的候選、選擇工具、指定學習式提案的取樣數量，或決定結束重建。每個被提出的程式都會被執行並測量，助理再根據渲染結果決定是否接受進入候選池，從而形成一個持續回饋的搜尋過程。

**Q5：CADFather 的關鍵創新是什麼？它與現有方法相比有何獨特之處？**

A：CADFather 的關鍵創新在於它建立了一個共享的重建框架，將學習式提案、演算法提案、參數最佳化整合在同一個搜尋過程中，並透過視覺與執行回饋來動態選擇工具與候選。與現有方法最大的不同在於，它維護一個替代候選程式的池（pool），並在整個搜尋過程中保留最佳的有效結果，這使得系統能夠探索多條不同的建構路徑而不會遺失已有的成果。此外，CADFather 不需要對操作生成器或助理進行額外的訓練，完全依賴預訓練模型，這在實務部署上具有重要優勢。

**Q6：CADFather 在設計上有哪些重要的選擇？為什麼採用視覺語言助理而非純粹的演算法決策？**

A：CADFather 採用視覺語言助理來引導重建過程，這個設計選擇反映了「有用的動作取決於當前重建狀態」的觀察——有時需要新增操作，有時需要精修參數，有時則需要回到先前的候選。視覺語言助理能夠檢視渲染圖並做出這類情境式的判斷，這是純粹演算法難以取代的能力。在工具組合上，選擇學習式提案、演算法提案與參數最佳化三者的結合，是因為它們各自提供互補的能力：學習式模型提供合理的操作提案、演算法從幾何直接衍生操作、參數最佳化則在保留操作結構的前提下調整尺寸。這種設計讓系統能夠靈活應對不同零件幾何與重建階段的需求。

A：CADFather 在六個資料集上進行評估，包括 DeepCAD、Fusion360、MCB 的完整測試集，以及 CADENA-Bench、CADBench、BenchCAD 三個基準。這些資料集的選擇涵蓋了不同類型的 CAD 模型與重建場景，能夠全面評估系統的泛化能力。DeepCAD 與 Fusion360 提供豐富的 sketch-extrude 建構序列，MCB 則包含多種類別的模型，而 CADENA-Bench、CADBench、BenchCAD 作為專門的基準能夠與現有方法進行公平比較。這種多資料集的評估策略有助於驗證系統在不同領域與複雜度下的表現。

## 實務應用指南

### 適用場景

1. **逆向工程與舊有零件數位化**：工廠中常有僅存三維掃描網格、缺乏原始建模歷史的舊零件或模具。導入 CADFather 可自動從網格重建出可編輯的參數化 CAD 程式，後續即可調整孔徑、壁厚等特徵參數，無需從零繪製。

2. **客製化設計與快速迭代**：在消費性產品（如手機殼、家電外殼）開發流程中，設計師常基於既有網格進行變體設計。CADFather 能在保留幾何外觀的同時，輸出可微調的建構程式，使 A/B 變體設計與尺寸微調的週期大幅縮短。

3. **CAD 教學與設計審查輔助**：教育訓練場景中，學員可從掃描模型或既有網格出發，透過 CADFather 觀察系統如何逐步拆解並重建零件，協助理解「建模操作序列」與「幾何結果」之間的對應關係。

4. **跨工具格式轉換與 IP 保護**：當外部供應商僅提供 STL/OBJ 網格而未提供原始 CAD 檔時，採購端可使用 CADFather 重建出可編輯的 CadQuery 程式，後續再匯入 SolidWorks、Fusion 360 等主流 CAD 系統，兼顧設計可追溯性與智慧財產管理。

5. **品質檢測與公差分析前置處理**：在量測領域，常需將掃描網格與設計意圖對齊。CADFather 重建出的參數化程式可作為「設計基準」，方便後續比對實際量測結果與設計公差。

### 實作前置條件

**資料面**
- 目標三維網格（STL、OBJ 或 PLY 格式），需經網格修復（填洞、法向一致化、去除孤立面）以避免執行階段錯誤。
- 對應的訓練/評估資料集可選用 DeepCAD、Fusion360 Gallery、MCB，或 CADENA-Bench、CADBench、BenchCAD 等公開基準。
- 候選程式的執行環境需具備 CadQuery 或同等 Python 幾何引擎，並能將程式渲染為多視角影像供視覺語言助理檢視。

**運算資源**
- 視覺語言助理（如 GPT-4V、Gemini 或開源替代方案）的推論需要 GPU 或高效能 API 配額；單一零件重建可能涉及數十至數百次助理呼叫。
- 學習式提案生成器（如 CADENA 預訓練模型）需具備推論 GPU；演算法提案與參數最佳化可在 CPU 上執行，但參數最佳化階段若採大量取樣仍建議配置多核心 CPU。
- 渲染管線需支援多視角光線追蹤或光柵化渲染，以產生目標與中間重建的對比影像。

**技能門檻**
- 熟悉 Python 與 CadQuery 語法，能撰寫與除錯 CAD 建構程式。
- 具備三維幾何處理經驗（網格清理、點雲取樣、ICP 對齊）。
- 對視覺語言模型的提示工程（prompt engineering）有基本理解，能設計助理決策所需的結構化輸入。
- 對代理系統（agentic system）設計概念有基礎認識，理解工具呼叫、回饋迴圈與候選池管理。

### 實作步驟建議

1. **建立基礎環境與工具介面**：安裝 CadQuery、Trimesh 與選定之視覺語言模型 API；定義三類工具的統一介面——學習式提案生成器（呼叫預訓練模型）、演算法提案生成器（基於幾何擬合，如 CADFit 風格的搜尋）、參數最佳化器（Cascaval 等數值方法）。

2. **設計候選程式池與狀態管理**：為每個目標零件維護多個候選程式，每個候選記錄其建構歷史、幾何評分、執行有效性旗標。實作「保留最佳有效結果」機制，確保搜尋過程中即使新提案失敗也不會遺失先前最佳解。

3. **建立視覺語言助理的決策迴圈**：將目標渲染圖、候選渲染圖、幾何評分、可用動作清單、執行歷史組合成結構化提示，讓助理輸出包含「選擇哪個候選、呼叫哪個工具、生成幾個學習式提案、或結束重建」的決策。

4. **串接工具執行與回饋**：每個工具呼叫後，執行產生的 CAD 程式、計算與目標網格的幾何差異（如 Chamfer Distance、IoU）、渲染結果影像，並將這些資訊回傳給助理作為下一輪決策依據。

5. **設定終止條件與預算控制**：定義最大迭代次數、最大 API 呼叫次數、幾何評分門檻等終止條件；同時實作「成本—品質取捨」機制，例如動態調整每輪學習式提案的取樣數量。

6. **評估與消融實驗**：在六個公開資料集上量測重建品質與執行有效性，並進行消融實驗（移除演算法提案、移除參數最佳化、同時移除兩者），以驗證各工具的實質貢獻。

7. **部署與監控**：將系統包裝為 API 服務，提供網格上傳、進度查詢、結果下載介面；記錄每次重建的工具呼叫序列與評分，用於後續分析與模型改進。

### 潛在風險與注意事項

- **執行失敗率**：CadQuery 程式對參數極為敏感，學習式提案可能產生無法執行的程式碼。緩解方式：為每個候選加上執行有效性旗標，僅將有效程式納入候選池；對失敗案例進行錯誤訊息回傳，讓助理在下一輪避開類似操作。

- **視覺語言助理的幻覺與不一致決策**：助理可能反覆選擇同一工具或陷入無效迴圈。緩解方式：設定單一工具的最大連續呼叫次數、引入隨機性鼓勵探索、記錄決策歷史並在提示中呈現以避免重複。

- **計算成本失控**：每個零件可能需要數十次 API 呼叫與多次渲染，整體成本可能快速累積。緩解方式：實作早期停止機制（當評分收斂即結束）、限制每輪提案數量、提供「快速模式」與「高品質模式」兩種預算選項。

- **幾何評分與視覺評估不一致**：Chamfer Distance 等數值指標可能與人類視覺判斷有落差，導致助理依據評分選擇的候選在視覺上仍有明顯缺陷。緩解方式：將目標與候選的並排渲染圖作為助理的主要輸入，而非僅依賴數值評分。

- **領域偏移**：在訓練資料集（DeepCAD、Fusion360）表現良好的模型，套用至工業零件或有機形狀時可能失效。緩解方式：在部署前以領域內樣本進行小規模驗證，並準備人工介入的 fallback 流程。

- **智慧財產疑慮**：重建出的程式可能與原始設計高度相似，需確認使用情境符合當地法規與授權條款。

### 與其他技術的整合建議

- **與 PLM/PDM 系統整合**：將重建出的 CadQuery 程式與參數中繼資料推送至 Teamcenter、Windchill 等產品生命週期管理平台，使下游工程師可在統一介面中檢視與修改。

- **與三維掃描硬體整合**：搭配手持式掃描儀（如 Artec、Shining 3D）或結構光掃描設備，建立「掃描 → 網格清理 → CADFather 重建」的自動化管線，縮短從實體到可編輯模型的時間。

- **與生成式設計（Generative Design）整合**：將 CADFather 的參數化輸出作為生成式設計的起點，使最佳化演算法能在保留設計意圖的前提下探索變體。

- **與 CAD 模擬軟體整合**：將重建程式匯入 ANSYS、COMSOL 等模擬工具前處理流程，自動產生網格與邊界條件，縮短「設計 → 分析」循環。

- **與 ERP/MES 整合**：在製造執行階段，從重建程式中萃取關鍵尺寸（孔徑、壁厚）作為製程參數，自動帶入 CNC 加工或 3D 列印的工序設定。

- **與版本控制系統整合**：將每次重建的程式碼、評分與決策歷史存入 Git，使設計變更可追溯、可回退。

### 給不同背景讀者的閱讀建議

**給入門者**：建議先閱讀第 1 節的問題描述與動機，理解「為什麼需要從網格重建 CAD 程式」這個核心問題；接著重點閱讀第 1 節中對三類工具（學習式提案、演算法提案、參數最佳化）的介紹，建立對系統組成的直觀認識。實作細節可暫時略過，待熟悉概念後再回頭研讀。

**給 AI 工程師**：重點關注第 1 節中對代理決策迴圈、候選池管理與工具介面設計的描述，並仔細閱讀實驗章節中的消融實驗，理解各工具對最終品質的實質貢獻。建議實際部署一個最小可行版本（MVP），先以單一工具（如學習式提案）驗證流程，再逐步加入其他工具。

**給研究者**：除主文外，建議深入閱讀相關工作章節，理解 CAD-Recode、CADENA、CADFit、CADReasoner 等方法在表示方式與搜尋策略上的差異；實驗章節中的六個資料集評估與成本—品質取捨分析，是定位未來研究空白的關鍵起點。亦可思考如何將更強的視覺語言模型或新的搜尋演算法整合進此框架。

**給產品經理**：聚焦於第 1 節的應用動機、貢獻列表與實驗章節中的成本—品質取捨段落，理解系統能解決的痛點、適用的場景，以及在不同預算下的表現差異。建議將「保留最佳有效結果」「無需額外訓練」等特性視為導入決策的關鍵優勢，並與內部設計、製造流程對接，評估實際投資報酬率。
