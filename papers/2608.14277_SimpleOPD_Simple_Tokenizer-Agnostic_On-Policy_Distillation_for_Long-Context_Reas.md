## 摘要翻譯

同策略蒸餾（On-policy distillation, OPD）為從更強大的教師模型（teacher model）轉移推理能力提供了一種具前景的方法，但將其應用於長上下文推理（long-context reasoning）教師模型與短上下文推理（short-context reasoning）學生模型（student model）時，會帶來實務上的挑戰，包括分詞器不匹配（tokenizer mismatch）、師生分布不匹配（teacher-student distribution mismatch）、回應長度爆炸（response length explosion）以及訓練不穩定（training instability）。本研究透過將證明推理能力（proof-reasoning capability）從長上下文推理模型 SU-01 轉移至短上下文學生模型，來探討此設定。為處理分詞器差異，我們在共享文字空間（shared text space）中執行 OPD，並僅對在學生與教師分詞器（tokenizers）下對應到相同文字片段（text spans）的符記（tokens）進行對齊。為了緩解生成長度過度增長與頻繁截斷的問題，我們引入學生參考 KL 散度損失（student reference KL loss），並對特殊終止符記（special termination tokens，例如 `<end_of_thinking>` 與 `<end_of_solution>`）的優勢（advantages）進行遮罩（mask）。此策略限制學生過度偏離其初始策略（initial policy），從而緩解師生分布不匹配問題，並使長度穩定增長。在同系列（same-family）與跨系列（different-family）學生模型（包括 Qwen3、Qwen3.5、Intern-S2、GLM-4.7、Gemma-4）上的實驗顯示，數學推理（mathematical reasoning）能力有穩定提升，特別是自然語言數學證明（natural-language math proving）。值得注意的是，Intern-S2-Preview 在 ProofBench 上提升了 21.2 分，達到 55.2，並超越 Gemini-2.5-Pro。它在 HLE 與 HiPhO 等科學基準測試（science benchmarks）上也有所提升，顯示 OPD 所轉移的推理能力能夠泛化（generalize）至數學訓練領域（training domain）之外。

### 核心貢獻（3～5點）
- 提出 SimpleOPD，一個簡單且分詞器無關（tokenizer-agnostic）的同策略蒸餾框架，可將長上下文教師模型的證明推理能力轉移至短上下文學生模型。
- 在共享文字空間（shared text space）中執行 OPD，並僅對應到相同文字片段的符記進行對齊，以解決分詞器不匹配問題。
- 引入學生參考 KL 散度損失（student reference KL loss）並遮罩特殊終止符記的優勢，以緩解回應長度爆炸、訓練不穩定與師生分布不匹配問題。
- 在同系列與跨系列學生模型上進行廣泛驗證，顯示數學推理與科學基準測試均有穩定提升，證明 OPD 轉移的能力可泛化至數學訓練領域之外。

### 適合對象
從事大型語言模型（LLM）後訓練（post-training）、知識蒸餾（distillation）、長上下文推理與數學推理研究的學者與工程師，特別是關注跨分詞器對齊（cross-tokenizer alignment）、強到弱蒸餾（strong-to-weak distillation），以及自然語言數學證明能力轉移的讀者。

## 深度分析

#### 方法論解析

##### 問題設定與核心挑戰
SimpleOPD 處理的是一個極具實務難度的蒸餾（distillation）場景：將具備長上下文推理（long-context reasoning）能力的教師模型（teacher model）SU-01 的推理能力，轉移到上下文長度較短的學生模型（student model）。此設定同時面臨四項挑戰：(1) tokenizer mismatch（分詞器不匹配）——教師與學生使用不同分詞器（tokenizer）與 chat template（對話模板）；(2) teacher-student distribution mismatch（師生分布不匹配）——模型容量與上下文長度差異造成輸出分布落差；(3) response length explosion（回應長度爆炸）——長上下文教師傾向產生超過學生上下文預算的回應；(4) training instability（訓練不穩定）——直接進行 On-policy distillation（OPD，同策略蒸餾）會引發快速長度增長（length growth）、頻繁截斷（truncation）與推理軌跡（trajectory）不完整。

##### 共享文字空間與跨分詞器對齊
為了規避不同詞彙表（vocabulary）之間強制建立人工對應的風險，SimpleOPD 將蒸餾過程搬移到共享文字空間（shared text space）。具體流程為：學生模型在其自身 tokenizer 下，依據 chat template \(C_\theta\) 建構輸入上下文 \(c_\theta\)，並由 rollout engine \(\pi_{\theta}^{\text{roll}}\) 取樣回應符記序列 \(y_{1:n}\)；接著透過學生 tokenizer 的解碼器 \(D_\theta\) 將 \(y_{1:n}\) 還原為表面字串 \(s\)。教師模型則使用自己的 chat template \(C_\phi\) 重新建構上下文 \(c_\phi\)，再將同一個字串 \(s\) 拼接於後，以教師 tokenizer 編碼器 \(E_\phi\) 進行編碼，得到 \(z_{1:m}\)。如此一來，教師評估的是與學生完全相同的回應文字，只是各自使用原生 tokenizer。

在 token-level supervision（符記級監督）的對齊上，SimpleOPD 只對「佔據完全相同文字片段（text span）」的符記進行對齊。設 \(\tau_\theta(y_i)\) 與 \(\tau_\phi(z_j)\) 分別代表學生符記 \(y_i\) 與教師符記 \(z_j\) 所對應的增量文字片段，則僅當兩者文字片段一致時，才將教師對該位置的監督信號傳遞給學生。這種 cross-tokenizer alignment（跨分詞器對齊）策略避免了 subword 切分差異帶來的雜訊，並能在不同模型家族（cross-family model）間提供穩定的 token-level supervision。

##### 同策略蒸餾目標函數與穩定化機制
SimpleOPD 的 OPD objective（同策略蒸餾目標函數）沿用了 OPD 的核心精神：主動查詢教師模型來評估學生自己生成的軌跡，並給出每個符記的優勢（advantage）。與 off-policy approach（異策略方法）使用固定教師資料不同，OPD 的監督信號根植於學生當前策略（policy），因此能減少遺忘（forgetting）並提升泛化（generalization）。

為了抑制 response length explosion 與 training instability，作者引入兩項關鍵設計：

1. **Student reference KL loss（學生參考 KL 散度損失）**：在學生當前策略與其 initial policy（初始策略）之間加入 KL divergence（KL 散度）正則化。此舉限制學生策略過度偏離初始分布，避免教師的長上下文偏好將學生推入產生超長回應的區域，從而緩解 teacher-student distribution mismatch。

2. **Termination-token advantage masking（終止符記優勢遮罩）**：對特殊終止符記（special termination token），例如  與 `<|im_end|>`，將其 advantage 遮罩（mask）掉。這防止教師因傾向繼續推理而反覆抑制學生終止思考或最終回應，降低 truncation 與不完整軌跡的發生率。

兩者協同作用下，學生回應長度呈現穩定增長（steady length growth），並能維持在學生上下文預算內。實驗亦發現，教師與學生差距越大，所需的 KL 正則化強度通常越高。

#### 實驗數據解讀

##### 實驗設置與評估基準
論文在 same-family model（同系列模型）與 cross-family model（跨系列模型）兩種設定下進行驗證，學生模型涵蓋 Qwen3、Qwen3.5、Intern-S2、GLM-4.7 與 Gemma-4。教師模型主要為 SU-01，並在分析章節額外探討從 DeepSeek-V4-Flash 進行蒸餾的效果。評估基準包括：

- **ProofBench**：自然語言數學證明（natural-language math proving）基準測試，衡量證明推理能力（proof-reasoning capability）。
- **AIME25 / AnswerBench**：數學競賽與問答基準測試。
- **HLE / HiPhO**：科學基準測試（science benchmark），用於檢驗領域外泛化（out-of-domain generalization）。

##### 主要結果與意涵
最引人注目的結果是 Intern-S2-Preview 在 ProofBench 上從 34.0 提升至 55.2，進步 21.2 分，不僅超越 Gemini-2.5-Pro，也逼近更強大的推理模型。這顯示 SimpleOPD 能夠有效將長上下文教師的證明推理能力轉移到短上下文學生，即使兩者屬於不同模型家族。

跨模型家族的一致性增益說明，cross-tokenizer alignment 並不需要完整的 token-level alignment，只要鎖定相同 text span 即可提供足夠監督。特別在自然語言數學證明任務上，SimpleOPD 的進步尤為顯著，暗示此類長形式推理（long-form reasoning）任務最能從長上下文教師的軌跡中受益。

##### 領域外泛化
儘管訓練資料僅來自數學推理領域，蒸餾後的學生在 HLE 與 HiPhO 等科學基準測試上仍有提升。這支持了論文的核心主張：OPD 轉移的是可泛化的推理能力，而非單純的數學領域記憶。此現象對後訓練（post-training）的啟示在於，高品質的數學長上下文軌跡可作為通用科學推理能力的訓練來源。

##### 訓練不穩定與長度控制
論文透過案例研究（case study）展示了直接 OPD 的失敗模式：AIME25 中出現 correct answer, then 972 exact self-check repeats（正確答案後進行 972 次精確自我檢查重複），以及 AnswerBench 中 reasoning collapses into a one-token loop（推理崩潰成單符記迴圈）。這些現象正是 response length explosion 與 training instability 的具體表現。SimpleOPD 透過 student reference KL loss 與 termination-token masking 顯著減少此類異常行為，使學生能產生完整且長度合理的推理軌跡。

##### 消融分析要點
- **Student-reference KL loss**：對於較大的師生差距，強化 KL 正則化可有效抑制過度漂移與 truncation。
- **OPD length**：適度增加蒸餾長度（distillation length）有助於長形式推理表現，但過長仍可能觸及上下文預算。
- **Training data**：儘管細節未完全揭露，結果顯示數學證明資料的質量與多樣性對最終泛化至關重要。

#### 與現有研究的比較

##### 相對於傳統 OPD
既有 OPD 研究（Gu et al., 2024；Agarwal et al., 2024）多聚焦於同系列模型與相同詞彙表，無法直接處理 tokenizer mismatch。SimpleOPD 將 OPD 擴展到 cross-family model 與不同 tokenizer，並針對長→短上下文蒸餾提出穩定化機制，填補了該領域的實務空白。

##### 相對於異策略蒸餾
Off-policy approach（異策略方法）通常使用固定教師生成資料進行監督式微調，容易面臨分布偏移與遺忘問題。SimpleOPD 維持 OPD 的優勢：監督信號來自學生自身軌跡，並進一步透過 KL 正則化與終止符記遮罩解決長度爆炸問題，達到更穩定的知識轉移。

##### 相對於其他跨分詞器方法
過去處理 tokenizer mismatch 的研究（Zhang et al., 2024；Chen et al., 2025b；Singh et al., 2026）常採用詞彙表對齊、映射或合併策略。SimpleOPD 選擇在 shared text space 中對齊 identical text spans，避免強制建立不自然的人工對應，對於 subword 切分差異較大的模型家族更具魯棒性。

##### 定位於後訓練生態
SimpleOPD 也與 strong-to-weak distillation（強到弱蒸餾）、multi-teacher distillation（多教師蒸餾）與 self-distillation（自蒸餾）等後訓練趨勢相容。其 tokenizer-agnostic（分詞器無關的）特性使其特別適合於整合來自不同開源或專有教師的知識。

##### 限制
- **對齊覆蓋率**：僅在 text span 完全一致的符記上傳遞監督，當教師與學生 tokenizer 切分方式高度不同時，可能損失部分 token-level supervision。
- **KL 係數調整**：student reference KL loss 的強度需隨 teacher-student gap 調整，目前仍仰賴經驗調參。
- **教師可取得性**：方法假設能夠頻繁查詢教師模型以取得每個 token 的優勢，對於 API 成本與延遲是實務考量。
- **訓練領域單一**：雖然在科學基準測試上展現泛化，但主要訓練資料仍集中於數學，對其他領域的適用性有待驗證。

#### 可重現性評估

根據目前提供的全文脈絡，論文並未明確說明是否公開原始碼、訓練資料或模型權重。附錄雖然包含 cross-tokenizer scoring and alignment（跨分詞器評分與對齊）的技術細節、ProofBench 的 model solution（模型解答）以及 case study（案例研究），對於理解方法與驗證現象有幫助，但距離完整可重現仍有差距。

要重現 SimpleOPD，研究者至少需要：

1. 取得教師模型 SU-01（或 DeepSeek-V4-Flash）與各學生模型（Qwen3、Qwen3.5、Intern-S2-Preview、GLM-4.7、Gemma-4）的推論權限。
2. 取得論文使用的數學證明訓練資料，並復現其資料篩選與 prompt 設計。
3. 實作 cross-tokenizer alignment 邏輯，包括 text span 比對、advantage masking 與 KL loss。
4. 具備足夠的運算資源以執行大規模 OPD rollout 與梯度更新。

若作者能進一步釋出程式碼、資料處理流程與超參數設定，將大幅提升社群驗證與後續改進的可能性。在目前資訊下，可重現性評估為「中等偏低」：方法描述足夠理解，但實作細節與資源取得門檻較高。

#### 未來研究方向

##### 1. 自適應 KL 正則化
未來可探索根據訓練階段或即時監控的 response length、truncation 率動態調整 student reference KL loss 的權重，以減少人工調參負擔，並在更大師生差距下維持穩定。

##### 2. 多教師與多領域蒸餾
SimpleOPD 的 tokenizer-agnostic 特性使其天然適合 multi-teacher distillation。未來可研究如何同時從數學、科學、程式碼等不同領域的長上下文教師中蒸餾，並處理教師間的知識衝突。

##### 3. 長度預算感知獎勵
除了 KL 正則化，可引入顯式的長度預算約束或漸進式長度課程（curriculum），讓學生從較短軌跡開始，逐步學習更長的推理鏈，進一步抑制 length explosion。

##### 4. 跨分詞器對齊的理論分析
目前對齊策略基於直覺與實證，未來可從理論上分析 text-span alignment 的偏差—變異數權衡（bias-variance trade-off），並探討在何種 tokenizer 差異程度下會出現監督信號損失。

##### 5. 開源工具鏈與標準化基準
建立開源的 cross-tokenizer OPD 工具鏈，並設計專門衡量長上下文推理轉移效果的標準化基準，將有助於降低研究門檻並促進方法比較。

##### 6. 推理崩潰模式的診斷與修復
針對 exact self-check repeat 與 one-token loop 等 reasoning collapse 現象，未來可發展自動偵測與早期停止機制，或結合 self-correction（自我修正）訓練，使學生學會在適當時機終止並驗證答案。

##### 7. 擴展至多語言與多模態
SimpleOPD 的 shared text space 概念可進一步延伸至多語言模型或多模態場景，例如在不同語言或視覺—語言 tokenizer 之間進行知識轉移，開拓更廣泛的應用範疇。

## 論文問答

**Q1：為什麼要將長上下文教師模型的推理能力蒸餾到短上下文學生模型？現有的異策略蒸餾方法為何不足以解決這個問題？**

A：長上下文推理模型（如 SU-01）在奧林匹亞級數學證明與複雜推理任務上展現出強大能力，但其推理過程通常需要極長的上下文預算，這使得部署成本高昂且難以應用於資源受限的場景。相較之下，短上下文學生模型雖然效率較高，卻缺乏同等級的長鏈推理與證明建構能力，因此需要透過蒸餾來轉移教師的推理策略。異策略方法雖然能從固定的教師軌跡中學習，但由於學生與教師在模型容量、上下文長度與分詞器上的差異，直接模仿教師生成的靜態資料容易導致嚴重的分布偏移與遺忘問題，無法提供針對學生自身策略的密集符記級監督。

**Q2：在跨分詞器與跨上下文長度的設定下，同策略蒸餾面臨哪些核心挑戰？**

A：第一項挑戰是分詞器不匹配，因為不同模型家族使用各自的詞彙表與分詞規則，教師與學生的符記序列無法直接對齊，傳統的符記級 KL 散度計算會變得不可行。第二項挑戰是師生分布不匹配，長上下文教師傾向生成遠超過學生上下文預算的回應，導致學生在訓練過程中出現回應長度爆炸、頻繁截斷與推理軌跡不完整等現象。第三項挑戰是訓練不穩定，特別是特殊終止符記（如 `</think>` 與 `<|im_end|>`）會因教師監督而反覆被抑制，使學生難以適時結束思考或最終回應，進一步加劇優化過程的震盪。

**Q3：SimpleOPD 的研究動機與實務重要性為何？**

A：SimpleOPD 旨在證明即使不進行完整的符記級對齊，也能透過共享文字空間實現穩定的跨系列模型蒸餾，這對於實際部署具有重大意義，因為企業與研究機構經常需要將大型閉源或長上下文教師模型的能力轉移到更小、更高效的開源學生模型。此方法避免了昂貴的教師軌跡監督式微調，並能在學生自身策略的軌跡上提供密集回饋，從而降低遺忘並提升泛化。此外，由於它不依賴特定分詞器或模型家族，SimpleOPD 為強到弱蒸餾、多教師蒸餾與自蒸餾等後訓練應用提供了一個更具擴展性的基礎框架。

**Q4：SimpleOPD 如何處理教師與學生使用不同分詞器的問題？**

A：SimpleOPD 將蒸餾過程建立在共享文字空間之上，學生首先使用自己的分詞器與對話模板生成回應，再將該回應的字串形式傳遞給教師。教師則使用自身的分詞器與聊天模板重新編碼該回應，並在原生分詞環境下評估學生軌跡。在計算損失時，只有當教師與學生的符記佔據完全相同的文字片段時才進行對齊與監督，這種跨分詞器對齊方式無需建立人工對應關係，即可提供可靠的符記級監督。

**Q5：學生參考 KL 散度損失與終止符記優勢遮罩各自解決什麼問題？兩者如何協同作用？**

A：學生參考 KL 散度損失透過約束學生策略不要過度偏離其初始策略，有效抑制了回應長度的快速膨脹與頻繁截斷，使長度增長更為平穩且落在學生的上下文預算內。終止符記優勢遮罩則防止教師監督直接壓制 `</think>` 或 `<|im_end|>` 等特殊終止符記，避免學生因反覆被懲罰而無法結束推理。兩者協同運作：KL 損失穩定整體策略更新並緩解師生分布不匹配，而遮罩機制確保終止決策不會被不當干擾，共同促成穩定且可持續的長形式推理學習。

**Q6：SimpleOPD 與傳統同策略蒸餾在目標函數設計上有何不同？為何選擇不對完整教師軌跡進行監督式微調？**

A：傳統同策略蒸餾通常要求教師與學生共享相同詞彙表，並直接在學生生成的軌跡上計算教師與學生分布之間的差異，而 SimpleOPD 透過文字片段對齊與選擇性符記監督，將這一框架擴展到不同分詞器與模型家族之間。作者選擇不對完整教師軌跡進行監督式微調，是因為教師生成的證明與推理過程往往遠超學生上下文長度，直接複製會導致截斷與資訊遺失；同時，學生在自己的策略軌跡上學習能獲得更貼近其決策邊界的密集回饋，減少簡單模仿帶來的分布偏移與遺忘。

**Q7：實驗涵蓋哪些學生模型與基準測試？最關鍵的量化結果是什麼？**

A：實驗涵蓋同系列與跨系列蒸餾設定，學生模型包括 Qwen3、Qwen3.5、Intern-S2-Preview、GLM-4.7 與 Gemma-4，教師模型主要為長上下文推理模型 SU-01。評估基準包含數學證明測試 ProofBench、數學競賽 AIME25、問答測試 AnswerBench，以及科學基準 HLE 與 HiPhO。最關鍵的結果是 Intern-S2-Preview 在 ProofBench 上從 34.0 分提升至 55.2 分，進步幅度達 21.2 分，不僅超越 Gemini-2.5-Pro，也逼近更強大推理模型的表現。

**Q8：消融實驗與對照分析揭示了哪些關於訓練穩定性與設計選擇的洞見？**

A：消融實驗顯示，直接使用未經修改的同策略蒸餾會導致回應長度快速增長、頻繁截斷與訓練崩潰，而加入學生參考 KL 損失後，長度增長變得平穩且截斷率顯著下降。終止符記優勢遮罩進一步防止了學生無法結束思考的現象，兩者結合才能達到最佳收斂。此外，實驗發現師生能力差距越大，所需的 KL 正則化強度通常越高，而適度增加蒸餾長度則能進一步提升長形式推理表現，顯示方法在效率與效能之間具有可調節性。

**Q9：SimpleOPD 在領域外泛化方面的表現如何？這說明了什麼？**

A：儘管 SimpleOPD 僅使用數學推理資料進行訓練，蒸餾後的學生模型在科學基準 HLE 與 HiPhO 上仍出現明顯進步，顯示所轉移的不只是特定數學知識，而是可泛化的推理策略與問題解決能力。這項發現挑戰了「蒸餾僅能複製訓練領域內模式」的直覺，並暗示長上下文教師模型中的高階推理結構具有跨領域遷移潛力。對於希望以有限領域資料提升模型通用推理能力的應用而言，這是一個重要的實務啟示。

**Q10：SimpleOPD 在實際產品部署中有哪些潛在應用場景？**

A：SimpleOPD 可應用於將昂貴的長上下文推理 API 能力壓縮到可在邊緣裝置或低成本伺服器上執行的短上下文模型，從而降低延遲與推理成本。在教育科技領域，它能讓輕量級輔導助手具備逐步數學證明與科學問題解析能力；在企業知識管理與法律文件分析中，則可將長文件推理能力轉移到更適合大規模佈署的模型。由於方法分詞器無關，產品團隊可以靈活選擇最符合成本與效能需求的學生模型架構，而無需受限於教師模型的技術棧。

**Q11：在產品化過程中，採用 SimpleOPD 需要考慮哪些工程與營運因素？**

A：首先，教師模型需要能夠評估學生生成的軌跡，這可能涉及額外的 API 呼叫成本與延遲，因此需要設計高效的採樣與批次策略來控制開銷。其次，學生的上下文長度與教師的推理長度之間存在張力，產品團隊必須根據目標使用場景調整 KL 正則化強度與最大回應長度，以平衡推理深度與使用者體驗。最後，由於跨系列蒸餾可能改變學生的輸出風格與終止行為，必須進行充分的對齊評估與安全測試，避免產生過度冗長、重複或無法結束的回應。

**Q12：SimpleOPD 對大型語言模型後訓練與蒸餾研究領域可能帶來什麼影響？**

A：SimpleOPD 拓展了同策略蒸餾的適用範圍，證明跨分詞器、跨模型家族與跨上下文長度的蒸餾是可行的，這可能促使更多研究探索異質教師—學生配對的潛力。它也強調了穩定性技術（如參考 KL 損失與終止符記遮罩）在長形式推理蒸餾中的關鍵角色，為未來的強到弱蒸餾與多教師蒸餾方法提供了設計範本。此外，其在科學基準上的領域外泛化表現，可能激發更多關於「推理能力是否可泛化轉移」的理論與實證研究。

**Q13：論文中提到了哪些 SimpleOPD 的失敗案例或異常行為？它們反映了什麼限制？**

A：案例研究顯示，即使答案正確，模型有時會進入長達 972 次的精確自我檢查重複，浪費大量上下文預算；另一個案例則是推理崩潰成單符記迴圈，無法產出有意義的後續內容。這些現象反映出學生雖然學會了模仿教師的表面行為，卻未必真正掌握何時該停止反思或如何維持推理的多樣性。它們也凸顯了在短上下文預算下進行長形式推理時，終止機制與重複抑制仍然是未完全解決的難題。

**Q14：SimpleOPD 有哪些明確的研究限制？**

A：首先，本研究主要聚焦於數學證明與科學推理領域，方法在其他需要長上下文推理的任務（如長文件摘要、多輪對話規劃或程式碼生成）上的有效性仍需驗證。其次，實驗中的教師模型以 SU-01 為主，雖然也補充了 DeepSeek-V4-Flash 的初步結果，但對於不同推理風格與架構的教師模型，最佳超參數（特別是 KL 強度）可能需要重新調整。最後，論文未深入探討蒸餾後模型在安全性、偏見與事實性方面的變化，這些都是實際部署前不可忽視的評估面向。

**Q15：未來研究可以從哪些方向延伸 SimpleOPD？**

A：未來可以探索更智慧的動態長度控制機制，例如讓模型根據問題難度自適應決定推理深度，而非依賴固定的上下文預算與 KL 強度。另一個方向是結合多教師蒸餾，讓學生同時從擅長不同推理風格的長上下文教師中學習，進一步提升泛化能力與穩健性。此外，研究者可以發展更細緻的終止與重複抑制技術，並將 SimpleOPD 應用到程式碼、法律與醫療等更多長形式推理領域，同時建立更完整的對齊與安全評估框架。

## 實務應用指南

### 適用場景

1. **長文件法律／財務推理落地到輕量模型**  
   以長上下文教師模型（如 SU-01）分析合約、法條或財報，再透過 SimpleOPD 將「長鏈推理」能力蒸餾到短上下文學生模型，讓邊緣或成本較低的模型也能進行多步驟法規比對與風險摘要。

2. **數學證明輔助教學系統**  
   把擅長自然語言數學證明的長上下文教師，蒸餾到參數較小、可部署於教育平台的學生模型，讓學生獲得逐步證明與自我檢查的解題過程，同時降低推理成本。

3. **醫療病歷長上下文推理的本地化部署**  
   利用長上下文教師處理多份病歷與檢驗報告的跨文件推理，再透過 SimpleOPD 轉移給短上下文學生模型，供院內終端或私有雲使用，兼顧隱私與運算效率。

4. **程式碼倉庫級程式理解助手**  
   教師模型具備長上下文程式分析能力（如跨檔案依賴、長函式推導），蒸餾後的短上下文學生可部署於 IDE 外掛，提供即時但較輕量的程式碼審查與除錯建議。

5. **科學文獻綜合分析助手**  
   將長上下文教師在科學文獻上的綜合與推論能力，透過數學證明資料進行 SimpleOPD 訓練，使學生模型在 HLE、HiPhO 等科學基準測試上獲得領域外泛化能力。

### 實作前置條件

**資料條件**
- 具備高品質的數學證明或長鏈推理訓練資料（類似 ProofBench、Olympiad-level 題目），用於產生學生軌跡與教師評分。
- 教師模型可取得逐 token 對數機率（logits）或具備 API／本地部署能力，能對學生回應進行同策略評分。
- 學生與教師的對話模板（chat template）與分詞器定義必須可取得，以便建立共享文字空間。

**運算條件**
- 支援大規模語言模型訓練的多 GPU 環境（建議至少數十 GB 顯存，視學生模型規模而定）。
- 可執行 on-policy rollout 的推理引擎，用於產生學生回應並即時餵給教師評分。
- 足夠的儲存空間保存中間軌跡、教師分數與對齊對照表。

**技術能力**
- 熟悉強化學習／蒸餾框架（如 TRL、veRL 或自研框架）。
- 理解分詞器運作、chat template 與跨分詞器對齊邏輯。
- 具備監控訓練穩定性（長度增長、截斷率、KL 散度）與除錯能力。

### 實作步驟建議

1. **選定師生模型與上下文預算**  
   選擇長上下文教師（如 SU-01）與目標短上下文學生（如 Qwen3、Intern-S2-Preview、GLM-4.7、Gemma-4）。明確學生的最大上下文長度，作為後續長度控制的硬上限。

2. **建立共享文字空間與跨分詞器對齊管線**  
   將學生回應解碼為文字後，再用教師分詞器重新編碼。僅對「佔據完全相同文字片段」的符記進行對齊，避免強制建立不相容詞彙表之間的人工對應。

3. **建構同策略蒸餾訓練迴圈**  
   學生在其自身策略下生成回應；教師以自身分詞器與模板評估同一段文字，計算教師監督訊號（如教師 logits 與獎勵）。只對已對齊的符記計算損失。

4. **加入穩定化機制**  
   引入學生參考 KL 散度損失，將學生策略與其初始策略綁定；同時對 `</think>`、`<|im_end|>` 等特殊終止符記的優勢進行遮罩，防止教師反覆抑制終止行為導致長度爆炸與迴圈。

5. **採用漸進式長度課程**  
   初期限制生成長度，隨訓練穩定逐步放寬；持續監控平均回應長度、截斷率、KL 散度與獎勵曲線，必要時調高 KL 權重。

6. **多維度評估**  
   在數學推理基準（ProofBench、AIME25）與科學基準（HLE、HiPhO）上評估，並檢查領域外泛化與詞彙重疊現象，避免單純模仿教師用語。

7. **部署與持續監控**  
   蒸餾後的學生模型可搭配量化、推測解碼或快取機制部署；上線後持續追蹤長度分布、重複生成與終止行為，必要時回滾或重新正規化。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **回應長度爆炸與頻繁截斷** | 學生為模仿教師而產生過長回應，超出上下文預算。 | 使用學生參考 KL 損失、終止符記優勢遮罩，並採漸進式長度課程。 |
| **訓練不穩定** | 師生分布不匹配導致梯度劇烈震盪、獎勵崩潰。 | 提高 KL 正則化強度，尤其師生差距大時；使用較小學習率與梯度裁剪。 |
| **終止行為被抑制** | 教師監督可能讓學生不敢輸出終止符記，造成無限自我檢查或單符記迴圈。 | 對特殊終止符記的優勢進行遮罩，保留學生原本的終止傾向。 |
| **跨分詞器對齊錯誤** | 不同 chat template 或特殊符記導致文字片段對應錯誤。 | 嚴格驗證對齊區間是否為完全相同的文字片段，並對未對齊區段排除損失。 |
| **過度擬合教師風格** | 學生僅複製教師詞彙或證明格式，而非真正學會推理。 | 檢查詞彙重疊指標，搭配領域外測試與多樣性評估。 |
| **遺忘通用能力** | 長時間 OPD 可能削弱學生原有的一般對話或知識問答能力。 | 保留部分通用資料進行混合訓練，或定期進行通用能力評估。 |
| **教師查詢成本高** | 同策略蒸餾需反覆呼叫教師評分，運算開銷大。 | 快取教師分數、使用較小教師模型或批次化評分，並評估 API 成本。 |

### 與其他技術的整合建議

- **與監督式微調（SFT）銜接**  
  可先以少量高品質教師軌跡進行 SFT 暖開機，讓學生具備基本格式與詞彙能力，再進入 SimpleOPD 階段強化推理行為。

- **接入現有 RLHF／RLAIF 管線**  
  將 SimpleOPD 的教師監督訊號視為一種「過程獎勵」，與人類偏好模型或結果獎勵模型結合，進一步對齊輸出風格與安全性。

- **搭配推論加速與壓縮技術**  
  蒸餾後的短上下文學生可進一步量化（INT8/INT4）、使用推測解碼或 vLLM 等服務框架部署，降低上線延遲與成本。

- **整合評估與監控平台**  
  將 ProofBench、HLE、HiPhO 等基準測試與長度、截斷率、KL 散度等指標納入 MLOps 監控，設定自動告警與模型回滾機制。

- **與多教師蒸餾結合**  
  當單一長上下文教師不足以覆蓋所有領域時，可將 SimpleOPD 擴展至多教師設定，對不同教師的共享文字空間分別對齊後聚合監督訊號。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從摘要與圖 2 的整體流程開始，理解「為什麼要把長上下文教師的能力傳給短上下文學生」，以及「共享文字空間」如何解決不同分詞器的問題；技術細節可先略過數學式，重點掌握長度爆炸、KL 正則化與終止符記遮罩這三個核心概念。

**AI 工程師**  
請聚焦第 2 節的跨分詞器對齊（2.1）與同策略蒸餾目標函數（2.2），並參考附錄 A 的跨分詞器評分與對齊實作；實作時需特別注意 chat template 的重建、對齊區間驗證、KL 損失權重調校，以及 rollout 引擎與教師評分之間的批次化效率。

**研究人員**  
建議深入閱讀第 4 節的實驗結果與第 5 節的分析，特別是與 OPD 基線方法的比較、詞彙重疊分析、領域外泛化、訓練資料與長度效應，以及 DeepSeek-V4-Flash 的補充蒸餾實驗；這些內容有助於理解 SimpleOPD 為何能穩定跨系列模型並泛化到科學領域。

**產品經理**  
請優先關注適用場景、主要貢獻與風險章節：SimpleOPD 能讓較小模型在數學證明與科學推理上接近甚至超越更大模型（如 Intern-S2-Preview 在 ProofBench 超越 Gemini-2.5-Pro），但需權衡教師查詢成本、訓練不穩定風險與部署後的長度監控；建議將其定位為「高價值推理任務的成本優化方案」，而非萬用替代方案。
