# SePO：用於系統提示詞優化的自演化提示詞智慧體

**原文標題：** SePO: Self-Evolving Prompt Agent for System Prompt Optimization  
**作者：** Wangcheng Tao、Han Wu、Weng-Fai Wong  
**發布日期：** 2026-06-03  
**HF 連結：** [https://huggingface.co/papers/2606.04465](https://huggingface.co/papers/2606.04465)  
**arXiv：** [https://arxiv.org/abs/2606.04465](https://arxiv.org/abs/2606.04465)  

---

## ⚡ TL;DR

現有方法僅優化任務智慧體，卻固定提示詞智慧體的系統提示詞為人工設計，限制優化上限與經驗累積。
本文提出SePO自參照框架，透過開放式演化同時優化兩類智慧體的系統提示詞，並分預訓練與微調兩階段。
於五項測試中，SePO平均準確率較基線提升4.49分，且預訓練習得之優化能力可泛化至新任務。

## 摘要翻譯

系統提示詞優化（System prompt optimization）在不修改底層模型的情況下改進智慧體（Agent）行為，產生人類可讀、模型無關的指令。現有方法雖建立提示詞智慧體（Prompt agent）以精煉任務智慧體（Task agent）的系統提示詞（System prompt），卻讓提示詞智慧體自身的系統提示詞維持人工設計且固定不變。我們提出自演化提示詞優化（Self-Evolving Prompt Optimization, SePO），將提示詞智慧體自身的系統提示詞與任務智慧體的系統提示詞一同視為優化目標。SePO 採用自參照設計（Self-referential design）：單一提示詞智慧體在開放式演化搜尋中同時改進任務智慧體與自身的系統提示詞，並維護候選提示詞庫作為演化的踏腳石。訓練分為兩階段：預訓練階段在多任務池上演化提示詞智慧體，微調階段則將其應用於目標任務。橫跨數學（AIME'25）、抽象推理（ARC-AGI-1）、研究所級科學（GPQA）、程式碼生成（MBPP）與邏輯謎題（Sudoku）五項基準測試，SePO 始終優於 Manual-CoT、TextGrad 與 MetaSPO，相較於 Manual-CoT 平均準確率提升 4.49 個百分點。預訓練所得的提示詞優化能力亦能泛化至預訓練任務混合之外的任務，而非僅記憶各任務的提示詞。

### 核心貢獻（3～5點）
- 提出自參照設計，將提示詞智慧體自身的系統提示詞與任務智慧體的提示詞並列為優化目標，突破現有方法僅手動固定提示詞智慧體設定的局限。
- 以開放式演化搜尋維護候選提示詞庫作為踏腳石，使單一提示詞智慧體能同時改進任務智慧體與自身的系統提示詞。
- 採用兩階段訓練策略：先於多任務池預訓練以習得通用的提示詞優化能力，再針對目標任務微調，實現跨領域泛化而非單純記憶。
- 在數學、抽象推理、研究所級科學、程式碼生成與邏輯謎題五項基準測試上，一致優於 Manual-CoT、TextGrad 與 MetaSPO，平均準確率較 Manual-CoT 提升 4.49 個百分點。

### 適合對象
適合關注提示詞工程、智慧體自動化與開放式演化學習的研究者與工程師，特別是希望在不修改底層模型的前提下，利用自參照機制與兩階段訓練提升跨任務提示詞優化效能的讀者。

## 深度分析

#### 方法論解析

SePO 的核心貢獻在於將**提示詞智慧體（prompt agent）**自身的**系統提示詞（system prompt）**也納入**最佳化（optimization）**目標，從而打破過往方法中「最佳化器固定不變」的瓶頸。具體而言，SePO 採用**自參照設計（self-referential design）**：提示詞智慧體將自身視為一個特殊的任務智慧體（task agent），因此用於改進任何任務智慧體系統提示詞的相同程序，也同時適用於改進提示詞智慧體自身的系統提示詞。

在演算法層面，SePO 將此問題建模為**開放式演化搜尋（open-ended evolutionary search）**。系統維護一個**檔案庫（archive）**，儲存歷代候選提示詞（candidate prompts），讓早期較弱的提示詞成為後續改進的踏腳石（stepping stones）。這種設計避免了貪婪搜尋過早收斂到區域最佳解，並保留了探索不同提示詞結構的空間。

訓練流程模仿標準的**預訓練（pre-training）**與**微調（fine-tuning）**典範，分為兩階段：
1. **預訓練階段**：在多元的**多工資料池（multi-task pool）**上執行自參照迴圈，演化出具備跨情境通用能力的強健提示詞智慧體。此階段的成本可攤提（amortized）到後續多個下游任務。
2. **微調階段**：將預訓練後的提示詞智慧體應用於特定的目標任務智慧體，針對單一任務進行提示詞精修。

這種分離確保了**提示詞最佳化技能（prompt optimization skill）**是在預訓練階段習得的一般性能力，而非對特定任務提示詞的記憶。相較於 PromptBreeder 等前作僅進行有界（bounded）的自我參照——其**超變異提示詞（hyper-mutation prompt）**仍為人工設計且固定——SePO 徹底封閉了迴圈，使同一套程序能同時覆蓋任務層與後設（meta）層，消除了為提示詞智慧體單獨設計最佳化器的需求。

#### 實驗數據解讀

作者在橫跨數學（AIME'25）、抽象推理（ARC-AGI-1）、研究所等級科學問答（GPQA）、程式碼生成（MBPP）與邏輯謎題（Sudoku）的五項**基準測試（benchmarks）**上進行評估。與三組基線方法——**手動思維鏈（Manual-CoT）**、**TextGrad** 與 **MetaSPO**——相比，SePO 在每一項任務上都取得最佳準確率（accuracy），相較於 Manual-CoT 平均提升 4.49 個百分點。

這項結果具有幾層意義：
- **跨域一致性（cross-domain consistency）**：提升並非侷限於單一領域（例如僅在數學推理有效），而是在需要不同認知模式的任務上皆表現優異，顯示預訓練階段習得的提示詞最佳化技能具備強健的**遷移性（transferability）**。
- **絕對優勢（dominance across baselines）**：SePO 不僅勝過基於人工設計的 Manual-CoT，也優於基於文字梯度（textual gradient）的 TextGrad 與基於**跨任務後設學習（cross-task meta-learning）**的 MetaSPO。這說明單純引入自動化梯度或後設學習並不足以突破瓶頸，關鍵在於讓驅動最佳化的提示詞智慧體本身也能持續演化。
- **泛化而非記憶（generalization vs. memorization）**：作者特別指出，預訓練所得的技能可推廣至預訓練資料混和（pre-training mixture）之外的任務。這項發現支援了 SePO 確實學到了可複用的後設認知策略，而非僅記憶一組任務特定提示詞。

然而，從提供的脈絡中，我們無法取得各基準測試的逐項數據分布、標準差或統計顯著性檢定結果，也尚未得知 SePO 在不同運算預算（inference-time compute budget）下的表現曲線，這些都是後續深入分析所需的關鍵資訊。

#### 與現有研究的比較

**相較於早期黑箱與演化方法**
早期的**黑箱最佳化（black-box optimization）**方法（如 Zhou et al., Yang et al.）將提示詞搜尋視為由評估回饋驅動的純粹最佳化問題，但在優質提示詞稀疏時容易陷入困境。後續的**群體演化（evolutionary）**方法（如 Fernando et al., Guo et al.）透過維護候選群體與變異／選擇機制緩解此問題，但其驅動搜尋的提示詞智慧體仍為人工設計，累積經驗無法回饋至最佳化器本身。

**相較於 PromptBreeder**
PromptBreeder 是 SePO 最接近的前作，它透過**共演化（co-evolution）**同時改進任務提示詞與產生它們的變異提示詞，已具備自我參照的雛形。然而其自我參照是有界的：頂層的超變異提示詞始終固定，**後設堆疊（meta-stack）**頂端仍為人工設計，迴圈從未真正封閉（圖 1b）。此外，PromptBreeder 的每次演化皆為任務特定（task-specific），任務提示詞與變異提示詞耦合為單一單元，每個新任務都需重新初始化。SePO 則透過徹底的自參照與兩階段訓練，解開了任務層與後設層的耦合。

**相較於 TextGrad 與 MetaSPO**
TextGrad 利用**文字梯度框架（textual-gradient framework）**將自然語言批評反向傳播至智慧體計算圖，提供元件層級回饋，但依賴梯度傳播的區域線性假設，且其最佳化器提示詞同樣固定。MetaSPO 將提示詞最佳化形式化為跨任務後設學習，產生共享的跨任務提示詞，但其**後設最佳化器（meta-optimizer）**仍位於學習迴圈之外。SePO 的獨特之處在於將後設最佳化器本身納入演化，使提示詞最佳化從「固定工具」轉變為「可學習技能」。

**相較於程式碼層級的自我演化**
近期研究如 Zhang et al. 與 ADAS 將演化搜尋應用於智慧體的程式碼或架構，雖能達到開放式自我改進，但犧牲了可解釋性與**模型無關性（model-agnosticity）**。SePO 僅操作自然語言層級的系統提示詞，不改變**權重（weights）**、程式碼或工具，保留了人類可讀性與跨模型遷移的彈性。

**限制**
儘管設計優雅，SePO 的開放式演化搜尋意味著較高的**推論運算成本（inference compute cost）**；檔案庫的維護與多工預訓練需要大量 API 呼叫或本機運算資源。此外，由於僅最佳化提示詞，其效能上限仍受限於底層**大型語言模型（LLM）**的固有能力，無法彌補模型在特定推理模式上的結構性缺陷。

#### 可重現性評估

**程式碼與資料可用性**
作者在論文註腳中提供了公開的 GitHub 儲存庫連結（https://github.com/taowangcheng/SePO），這為方法的可重現性奠定了基礎。所使用的五項基準測試——AIME'25、ARC-AGI-1、GPQA、MBPP 與 Sudoku——皆為公開資料集，降低了資料取得的門檻。

**再現挑戰**
然而，作為一篇預印本（preprint），目前提供的脈絡未詳細說明：
- 底層模型確切版本（例如 GPT-4、Claude 或開源模型）及其**溫度參數（temperature）**設定；
- 檔案庫的具體篩選與**多樣性維護（diversity maintenance）**機制；
- 預訓練多工資料池的確切組成與規模；
- 演化過程的隨機種子（random seed）與重複實驗的變異程度。

由於 SePO 依賴**開放式演化搜尋（open-ended evolutionary search）**，其結果本質上具有隨機性，若未完整記錄超參數與檔案庫管理細節，不同團隊的重現結果可能出現顯著差異。此外，預訓練階段涉及大量模型查詢，對於運算資源有限的研究者而言，完整重現的成本可能相當高昂。期待正式發表版本或技術報告能補充這些實作細節，並釋出預訓練後的提示詞智慧體系統提示詞（即其「權重」），以便社群直接進行微調階段的驗證。

#### 未來研究方向

**1. 多模態與工具使用擴展**
當前 SePO 聚焦於純文字系統提示詞。未來可將自參照框架擴展至**多模態智慧體（multimodal agents）**，同時最佳化描述視覺輸入或工具呼叫格式的提示詞片段，甚至讓提示詞智慧體學會設計新的工具使用範本。

**2. 與權重學習的協同**
SePO 僅操作提示詞層級，未觸及模型權重。一個自然的前進方向是將 SePO 與**參數高效微調（parameter-efficient fine-tuning, PEFT）**或**強化學習（reinforcement learning）**結合，形成「提示詞—權重」聯合最佳化，以突破純提示詞調整的效能天花板。

**3. 檔案庫機制的理論化**
目前檔案庫作為踏腳石的機制仍屬**啟發式（heuristic）**。未來研究可引入**品質多樣性（quality diversity, QD）**演算法或**新奇性搜尋（novelty search）**的理論框架，量化分析何種類型的歷史提示詞最能促進後續演化，並設計自適應的檔案庫壓縮策略。

**4. 封閉迴圈的安全性與對齊**
當提示詞智慧體具備修改自身指令的能力時，必須防範其為了最大化評估分數而學會**獎勵駭取（reward hacking）**或產生誤導性、有害的自我提示詞。建立**紅隊測試（red-teaming）**機制與演化過程中的**對齊約束（alignment constraints）**將是實際部署前的必要課題。

**5. 規模化預訓練的湧現行為**
本文已顯示多工預訓練可帶來泛化，但預訓練資料池的規模效應尚不明朗。未來可系統性地將預訓練任務從數十項擴展至數千項，觀察提示詞智慧體是否會湧現出更高階的後設策略，例如自動判斷任務類型並選擇對應的最佳化軌跡。

**6. 動態與終身學習情境**
目前的兩階段訓練將預訓練與微調分離。未來可探索**終身學習（lifelong learning）**設定，讓提示詞智慧體在部署後持續與新任務互動，即時更新自身系統提示詞，並防止對舊任務的**災難性遺忘（catastrophic forgetting）**。

## 論文問答

**Q1：系統提示詞優化是什麼，為何它在當前智慧體發展中扮演重要角色？**
A：系統提示詞優化是一種在不修改底層模型權重的情況下，透過改進智慧體的系統提示詞來提升其行為表現的方法。這種方法能夠產生人類可讀且模型無關的指令，使得優化結果具有高度的可解釋性與跨模型遷移能力。相較於重新訓練模型或設計複雜工作流程，系統提示詞優化提供了一種成本更低、部署更靈活的替代方案，因此成為提升智慧體效能的關鍵技術之一。

**Q2：現有的提示詞優化方法存在什麼根本性的缺陷，導致其優化潛力受到限制？**
A：現有方法雖然建立了提示詞智慧體來精煉任務智慧體的系統提示詞，但這些提示詞智慧體自身的系統提示詞仍然依賴人工設計且保持固定不變。這意味著優化迴圈僅針對任務智慧體，而負責優化的智慧體本身從未隨著任務經驗累積而改進，導致整個優化過程被人類手工程度的上限所束縛。無論是早期的黑箱優化、演化式搜尋，或是近期的文字梯度框架，都未能讓提示詞智慧體從中學習並持續進化，因此無法累積跨任務的優化經驗。

**Q3：為何將提示詞智慧體自身的系統提示詞也視為優化目標，對突破現有瓶頸至關重要？**
A：將提示詞智慧體視為特殊的任務智慧體，使其系統提示詞成為優化目標，能夠打破「優化者固定不變」的瓶頸，讓整個系統具備自我參照與持續演化的能力。這種設計讓提示詞智慧體在處理更多樣化的任務時，能夠不斷累積並提煉出更有效的提示詞優化策略，而非重複依賴人類預設的固定規則。如此一來，提示詞優化從一種靜態的工具轉變為可學習的技能，並能隨著接觸的任務增加而持續提升泛化能力與優化效能。

**Q4：SePO 的核心方法架構為何，它與傳統的提示詞優化框架有何根本差異？**
A：SePO（自演化提示詞優化）採用自我參照設計，將提示詞智慧體與任務智慧體置於同一個優化框架中，使同一套程序能夠同時精煉兩者的系統提示詞。不同於傳統框架僅針對任務智慧體的提示詞進行搜尋或梯度更新，SePO 透過開放式演化搜尋維護一個候選提示詞檔案庫，讓早期的提示詞成為後續改進的踏腳石。這種設計消除了為提示詞智慧體單獨設計優化器的需求，形成一個封閉的、能夠自我改進的優化迴圈。

**Q5：SePO 的「自參照設計」具體如何運作，它如何解決 PromptBreeder 等前作未能閉合優化迴圈的問題？**
A：SePO 的自參照設計將提示詞智慧體視為一個特殊的任務智慧體，因此用來優化任務提示詞的相同演化程序也直接應用於優化提示詞智慧體自身的系統提示詞。相較於 PromptBreeder 雖然共同演化任務提示詞與變異提示詞，但其最頂層的超變異提示詞仍為人工設計且固定不變，導致自參照存在邊界、迴圈未能真正閉合。SePO 則徹底移除了這個固定的人工頂層，讓同一個程序涵蓋兩個層級，從而實現真正無邊界的開放式自我演化。

**Q6：SePO 為何採用「預訓練—微調」兩階段流程，以及基於檔案庫的開放式演化搜尋？**
A：兩階段流程的設計模仿了標準的機器學習範式：第一階段在多元任務池上進行預訓練，讓提示詞智慧體發展出跨情境的通用提示詞優化能力；第二階段則針對特定目標任務進行微調，將已習得的優化技能遷移應用，從而攤提自我演化的成本。基於檔案庫的開放式演化搜尋則透過保存歷史候選提示詞作為踏腳石，避免搜尋過程遺失有潛力的中間結果，並促進持續累積式的改進。這種組合不僅提升了優化技能的泛化性，也確保了在特定任務上的高效應用。

**Q7：SePO 在哪些基準測試上進行評估，這些測試涵蓋了哪些不同類型的認知能力？**
A：SePO 在五個涵蓋多元認知領域的基準測試上進行評估，包括數學推理的 AIME'25、抽象推理的 ARC-AGI-1、研究生等級科學問答的 GPQA、程式碼生成的 MBPP，以及邏輯謎題 Sudoku。這些測試橫跨了數學演繹、抽象規則推論、專業領域知識、程式設計能力與邏輯結構化解題等截然不同的認知面向。如此廣泛的評估設計能夠嚴格檢驗 SePO 的提示詞優化技能是否具備跨領域的通用性與穩健性。

**Q8：SePO 與基線方法相比取得了哪些關鍵量化成果？**
A：在五項基準測試中，SePO 的表現均優於 Manual-CoT、TextGrad 與 MetaSPO 等三個基線方法，在每個任務上都達到了最佳準確率。與 Manual-CoT 相比，SePO 平均提升了 4.49 個百分點的準確率，顯示其自動化優化顯著超越了人工設計的思維鏈提示。這些結果證明了 SePO 的自我參照式演化搜尋能夠持續發掘比現有方法更有效的高品質系統提示詞。

**Q9：SePO 如何證明其在預訓練階段習得的是可泛化的提示詞優化技能，而非單純記憶各任務的特定提示詞？**
A：研究顯示，經過多任務池預訓練後的提示詞智慧體，其優化能力能夠延伸至預訓練混合任務之外的全新任務，這直接證明了它習得的是可遷移的優化技能而非死記硬背。這種泛化能力與標準機器學習中「多樣化訓練數據可提升穩健性與泛化性」的原則一致，顯示預訓練階段確實提煉出了跨任務的通用原則。若僅是記憶特定提示詞，則智慧體在面對未見過的任務類型時應無法表現出顯著的優化效果，但實驗結果否定了這一假設。

**Q10：在實務應用中，SePO 適合部署在哪些需要頻繁調整智慧體行為的場景？**
A：SePO 特別適合需要大規模部署智慧體且必須針對不同任務快速調整行為的企業級應用場景，例如客戶服務、專業領域問答、程式碼輔助生成與教育輔導系統。由於 SePO 產生的系統提示詞具有人類可讀與模型無關的特性，企業可以在不更換底層模型的情況下，僅透過優化提示詞來適應新業務需求或不同客戶族群。此外，預訓練階段一次性培養出的提示詞智慧體可在多個下游任務中重複使用，大幅降低為每個新任務從頭設計提示詞的人力與時間成本。

**Q11：從產品開發與維運的角度來看，SePO 僅修改自然語言系統提示詞而不觸動模型權重或程式碼，帶來哪些具體優勢？**
A：僅修改自然語言提示詞意味著產品團隊無需具備模型重新訓練或架構修改的專業能力，即可持續改進智慧體表現，這大幅降低了技術門檻與基礎設施成本。由於不涉及權重變更，系統提示詞的更新可以即時部署與回滾，提供了極高的營運靈活性與可解釋性，開發者能夠直接檢視並理解智慧體被賦予的指令內容。這種設計也確保了跨模型平台的可攜性，同一組優化後的提示詞可在不同廠商的模型間遷移使用，減少對單一供應商的依賴。

**Q12：SePO 對自動化提示詞優化與自我演化智慧體這兩個研究領域帶來了什麼樣的深遠影響？**
A：SePO 首次在提示詞優化領域實現了完全閉合的自我參照迴圈，將「優化者本身也應被優化」這一概念從理論落實到自然語言層面的實作，為後續研究樹立了新的設計典範。在自我演化智慧體的脈絡中，SePO 證明了即使不修改智慧體的程式碼、權重或工具，僅透過系統提示詞的演化也能實現開放式的自我改進，拓展了自我演化機制的應用邊界。這項工作也架起了提示詞工程與開放式演化搜尋之間的橋樑，啟發未來研究探索更高層級、更具解釋性的元學習與自我改進系統。

**Q13：SePO 採用開放式演化搜尋與兩階段訓練，這帶來了哪些固有的限制或運算上的挑戰？**
A：SePO 依賴維護一個候選提示詞檔案庫並執行開放式演化搜尋，這需要大量的模型查詢與評估迭代，因此在運算資源與時間成本上較單輪梯度更新方法更高。由於提示詞智慧體的優化完全發生在自然語言層面，其最終效能天花板仍受限於底層語言模型固有的推理與知識能力，無法透過提示詞調整來彌補模型本身的根本缺陷。此外，目前的兩階段設計將預訓練與微調分離，尚未探討在持續互動的動態環境中，提示詞智慧體如何即時線上自我演化而不產生行為漂移或災難性遺忘。

**Q14：在什麼樣的任務條件下，SePO 的開放式演化搜尋可能難以收斂或失效？**
A：當任務的評估回饋極為稀疏、雜訊過高或需要極長時間才能取得時，開放式演化搜尋可能因缺乏明確的適應度訊號而難以有效篩選出優質的提示詞變異。若優秀提示詞在廣大的搜尋空間中分佈極為稀疏，且早期候選提示詞之間的差異對任務表現影響微弱，演化過程便可能陷入隨機漂流的困境，無法建立穩定的改進路徑。此外，如果底層模型對於提示詞用詞的細微變化過度敏感，導致評估結果不穩定，那麼作為踏腳石的檔案庫提示詞可能難以可靠地傳遞到後續世代，進而阻礙持續累積式的自我改進。

**Q15：基於 SePO 的自我參照框架，未來研究可以朝哪些方向進一步延伸與拓展？**
A：未來研究可探索將 SePO 的自我參照機制擴展至多層級元智慧體架構，使提示詞智慧體不僅演化自身的系統提示詞，還能同時優化其內部的推理策略或工具選擇邏輯。另一個重要方向是發展持續學習與線上自我演化的變體，讓提示詞智慧體在與真實環境互動的過程中即時更新其系統提示詞，而非僅限於離線的預訓練與微調階段。此外，將 SePO 應用於多模態智慧體或與其他自我演化範式（如演化智慧體程式碼）結合，並深入研究自我演化過程中的安全性、可控性與對齊性，亦是極具潛力的後續課題。

## 實務應用指南

### 適用場景

1. **跨部門企業知識助手**：當組織需同時部署客服、技術支援、法務審查等多種內部智慧體，且各領域的系統提示詞難以由單一提示詞工程師手工維護時，SePO 的預訓練階段可讓提示詞智慧體累積跨領域優化經驗，微調階段再快速適配到特定部門的任務智慧體，降低逐案手工調校的成本。

2. **適性化教育科技平台**：針對數學推論、程式碼生成、邏輯解謎等不同科別的 AI 家教，SePO 可在多任務預訓練中同時演化「解題策略提示詞」與「提示詞優化器自身」，使平台能依學生答對率與回饋持續自動精進各科教學提示，而非仰賴教師手動迭代。

3. **金融法規動態遵循系統**：在金融或醫療等法規頻繁變動的場域，任務智慧體需持續更新其推理與報表生成提示。SePO 的自我參照設計讓負責優化提示的智慧體也能隨新法規資料自我演化，避免「優化器本身過時」導致系統性偏誤。

4. **軟體開發輔助工具（AI Coding Agent）**：面對跨語言、跨框架的程式生成與除錯任務，開發團隊可利用 SePO 先於多種編程任務（如 MBPP 類型的題庫）預訓練提示詞智慧體，再針對企業內部特定程式碼庫微調，使編碼智慧體的系統提示詞隨程式審查回饋持續自動優化。

### 實作前置條件

**資料與評估基礎設施**
- 多任務評估池：至少 5–10 個與目標領域相關、具備明確評分函數的任務（參考論文中的數學、邏輯、程式、科學推理等組合），用於預訓練階段的開放式演化。
- 目標任務資料：目標任務的訓練/驗證樣本與穩定的自動評估指標（如 pass@k、準確率、單元測試結果）。
- 提示詞譜系追蹤：需記錄每個候選提示詞的親代關係與適應度分數，作為檔案庫（archive）的踏腳石。

**運算資源**
- LLM API 預算：開放式演化搜尋需大量呼叫底層模型進行提示詞生成與評估，預訓練階段需預留數千至數萬次 API 呼叫的預算。
- 並行評算能力：需可平行化執行多個候選提示詞的評估環境，以加速族群適應度計算。
- 檔案庫儲存：低成本物件儲存即可，但需支援版本化與快速檢索歷代提示詞。

**技術與團隊能力**
- 提示詞工程經驗：能設計合理的初始系統提示詞（包含提示詞智慧體與任務智慧體），作為演化的起點。
- 演化演算法基礎：理解族群初始化、變異、選擇與踏腳石檔案庫的運作邏輯。
- LLM 系統設計：具備將提示詞優化流程封裝為自動化管線的能力，並能處理 API 速率限制與錯誤重試。

### 實作步驟建議

**步驟一：建立多任務基準與初始族群**
收集涵蓋目標領域的多樣化任務（如數學、程式、邏輯推理），為每個任務建立 Manual-CoT 基準線。同時設計提示詞智慧體的初始系統提示詞（負責讀取評估回饋並產生改良提示）以及各任務智慧體的初始提示詞，形成第一代族群。

**步驟二：建構踏腳石檔案庫（Archive）**
建立一個結構化檔案庫，儲存歷代候選提示詞及其適應度分數。此檔案庫不僅保存精英個體，也保留多樣化的中間版本，供後續變異操作作為踏腳石使用。

**步驟三：執行預訓練階段（Pre-training）**
在多任務池上運行自我參照式開放演化。每一輪中，提示詞智慧體讀取任務評估回饋後，同時產生：(1) 各任務智慧體的改良系統提示詞；(2) 自身的改良系統提示詞。透過多輪變異與選擇，演化出具備跨任務通用優化能力的提示詞智慧體。

**步驟四：凍結並驗證泛化能力**
預訓練收斂後，凍結提示詞智慧體的系統提示詞。在預訓練混合資料以外的保留任務上測試，確認其表現提升來自「提示詞優化技能」的學習，而非單純記憶各任務的特定提示詞模板。

**步驟五：微調階段（Fine-tuning）部署至目標任務**
將凍結的提示詞智慧體部署到目標任務環境。此時僅讓任務智慧體的提示詞持續演化，提示詞智慧體本身不再改變，以確保優化行為穩定。視生產環境回饋週期，可排程定期觸發新一輪演化。

**步驟六：建立持續監控與人機協作閘道**
生產環境中追蹤任務準確率與使用者滿意度。設定自動化閾值：當效能衰退或法規/業務邏輯改變時，將新任務樣本注入檔案庫，觸發提示詞智慧體的再演化（可選擇性解凍提示詞智慧體進行區域性更新）。

### 潛在風險與注意事項

**演化成本與延遲爆炸**
開放式族群搜尋可能產生遠超預期的 API 呼叫量。建議設定嚴格的預算上限與早期停止條件（early stopping），並採用階層式評估：先用輕量模型或少量樣本篩選族群，僅讓頂尖候選者進入完整評估。

**過度擬合預訓練任務**
檔案庫可能使提示詞智慧體記憶預訓練任務的特定提示詞結構，而非學到通用優化策略。務必在預訓練混合資料之外的保留任務上驗證泛化性，並監控微調階段是否出現「直接複製預訓練模板」的跡象。

**提示詞漂移與可解釋性退化**
演化後的提示詞可能累積人類難以理解的冗餘修飾或特定模型導向的「提示詞駭客」。建議在檔案庫中定期執行可讀性檢查（如長度懲罰、語意一致性評分），並在部署前加入人工審核閘道，確保系統提示詞仍符合品牌語調與安全規範。

**自我參照迴路的收斂風險**
當提示詞智慧體優化自身提示詞時，可能陷入自我強化的局部最佳或產生偏誤放大。維持族群多樣性至關重要，可定期注入人工設計的變異操作，或限制提示詞智慧體自我修改的頻率（例如每 N 輪才允許更新一次自身提示詞）。

**底層模型相依性**
雖然系統提示詞標榜模型無關，但 SePO 演化出的提示詞可能過度適配特定 LLM 的指令遵循風格。若未來需更換底層模型（如從 GPT-4 遷移至 Claude 或開源模型），應保留一部分族群進行多模型驗證，避免提示詞失效。

### 與其他技術的整合建議

**與 RAG（檢索增強生成）整合**
將 SePO 演化後的提示詞用於 RAG 管線中的「查詢重寫」與「檢索後摘要」角色定義。當知識庫更新時，不僅重新索引文件，也可觸發 SePO 微調階段，讓任務智慧體的提示詞同步學會如何更好地引用新知識。

**與 LLMOps / CI-CD 管線整合**
將預訓練與微調封裝為標準化管線任務。提示詞版本應視為與模型權重同級的產物（model artifact），透過工具如 MLflow 或 DVC 進行版本控制，並搭配 A/B 測試框架漸進式部署至生產環境，比較新世代提示詞與舊版的業務指標。

**與多智慧體協作框架（如 LangGraph、AutoGen）整合**
SePO 特別適合優化多智慧體系統中的協調者（orchestrator）提示詞。可將提示詞智慧體視為「元協調者」，專門優化各專家智慧體間的溝通協定與任務分派邏輯，使多智慧體工作流程隨互動資料自我精進。

**與現有提示詞管理工具整合**
將 SePO 的檔案庫與 LangSmith、Weights & Biases Prompts 等實驗追蹤平台對接，視覺化每個提示詞世系的譜系樹與適應度曲線。這有助於團隊在大量演化世代中快速定位「效能躍升」的關鍵變異節點。

### 給不同背景讀者的閱讀建議

**給初學者**：請先聚焦「為什麼要讓 AI 自己改自己的指令」這個核心直覺，對照圖 1 理解三種架構的差異——尤其是 SePO 如何透過自我參照把優化迴路封閉起來。不必急著理解演化演算法的數學細節，重點掌握「預訓練學通用優化能力、微調專攻特定任務」這兩階段的分工邏輯，就能建立正確的應用想像。

**給 AI 工程師**：建議深入檢視檔案庫（archive）的實作細節與兩階段訓練的計算成本分配。評估如何將 SePO 嵌入現有的 LLM 服務架構時，請特別注意 API 呼叫預算、平行評估的延遲，以及提示詞版本在分散式系統中的同步機制。論文中與 TextGrad、MetaSPO 的比較數據可作為選型依據。

**給研究人員**：請關注自我參照設計的理論邊界與開放式演化搜尋的收斂特性。值得思考的是：SePO 與 Prompt Breeder、Gödel Machine 的根本界線何在？跨任務泛化能力的來源究竟是「技能學習」還是「記憶重組」？此外，檔案庫作為踏腳石的機制是否可延伸至智慧體程式碼或工具層級的自我修改？

**給產品經理**：請將 SePO 理解為一套將「提示詞工程」從一次性手工勞動轉化為可累積自動化資產的框架。評估導入時，不應只看單一任務的準確率提升，更要計算跨任務遷移時節省的人力成本、提示詞維護的長期開銷，以及因提示詞可讀性下降可能帶來的治理與品牌風險。論文中的 4.49 點平均準確率提升與跨任務泛化證據，是向技術團隊爭取資源的有力依據。
