## 摘要翻譯

一份能無誤編譯的 LaTeX 稿件未必已達發表標準。其產生的 PDF 經常出現浮動物件錯置、方程式溢位、表格縮放不一致、寡行與孤行，以及頁面平衡不佳等問題，迫使作者陷入編譯–檢查–修改循環。規則式工具無法感知渲染後的視覺結果，僅能基於原始碼與日誌檔案運作。純文字大型語言模型 (LLM) 執行的是開迴路文字編輯，無法預測或驗證其二維版面配置的後果。因此，可靠的排版優化需要視覺閉迴路，並在每次修改後進行驗證。我們將此問題形式化為視覺排版優化 (Visual Typesetting Optimization, VTO)，其任務是透過反覆式視覺驗證與原始碼層級修訂，將一份可編譯的 LaTeX 論文轉化為視覺上精美完善且符合頁數預算的 PDF，並提出一套五類排版缺陷分類法以輔助診斷。我們提出 PaperFit，一個視覺在環 (Vision-in-the-Loop) 代理，能反覆式渲染頁面、診斷缺陷，並執行受約束修復。為建立 VTO 的評測基準，我們建構了 PaperFit-Bench，收錄橫跨 10 種會議範本、涵蓋 13 種不同難度缺陷類型的 200 篇論文。大量實驗顯示，PaperFit 以大幅差距超越所有基準方法，證明了從可編譯的 LaTeX 原始碼到達發表標準的 PDF 之間的鴻溝，必須透過視覺在環優化方能跨越，且 VTO 構成文件自動化流程中一個關鍵且缺失的環節。

### 核心貢獻（3～5點）
- **問題形式化**：將「從可編譯 LaTeX 原始碼到達發表標準 PDF」的轉化過程定義為視覺排版優化 (VTO)，並提出五類排版缺陷分類法，作為系統性診斷的基礎。
- **方法創新**：提出 PaperFit——一個視覺在環代理，透過反覆式渲染、缺陷診斷與受約束修復的閉迴路機制，克服純文字大型語言模型 (LLM) 開迴路編輯無法預測版面後果的根本限制。
- **基準建構**：發布 PaperFit-Bench 評測基準，收錄 200 篇論文，橫跨 10 種會議範本與 13 種不同難度的缺陷類型，為 VTO 任務提供標準化評測平台。
- **實驗驗證**：實驗結果顯示 PaperFit 以大幅差距超越所有基準方法，確立視覺在環優化為跨越「可編譯原始碼」與「達發表標準 PDF」之間鴻溝的必要條件，並論證 VTO 為文件自動化流程中關鍵且缺失的環節。

### 適合對象
本論文最適合以下讀者閱讀：(1) 從事學術寫作與投稿的研究人員與學生，特別是關注 LaTeX 排版品質與會議頁數限制合規性的作者；(2) 文件理解、文件自動化與排版字體學 (Typography) 領域的研究者；(3) 大型語言模型 (LLM) 與視覺–語言代理 (Vision-Language Agent) 的開發者，特別是研究閉迴路控制、視覺在環決策與反覆式驗證機制的研究團隊；(4) 學術出版工具鏈的工程師，包括會議範本維護者、arXiv 預印本平台技術人員，以及開發格式轉換工具 (如 Pandoc) 與規則式排版工具的工程實務者。

## 深度分析

#### 方法論解析

PaperFit 提出了一套完整的「視覺在環」(Vision-in-the-Loop) 排版優化框架，其方法論核心在於將 LaTeX 排版優化重新定義為一個閉迴路控制問題 (Closed-Loop Control Problem)，而非傳統的開迴路文字編輯任務。整個系統架構可從問題形式化、缺陷分類法、以及三大設計元件三個層面進行剖析。

**問題形式化：視覺排版優化 (VTO)**

作者將 VTO 明確定義為：將一份「可編譯的 LaTeX 論文」轉化為「視覺精緻且符合頁數預算 (Page-Budget-Compliant) 的 PDF」，其手段為「反覆式視覺驗證 (Iterative Visual Verification) 與原始碼層級修訂 (Source-Level Revision)」。此定義的關鍵在於強調三個不可妥協的條件：(1) 輸入必須是已可編譯的 LaTeX，而非任意格式；(2) 輸出必須通過視覺品質檢驗，而非僅通過編譯；(3) 過程必須是閉迴路，每一步修改都需經過渲染驗證。這種形式化將過去模糊的「排版優化」概念轉化為可量化、可基準化 (benchmarkable) 的研究問題。

**五類缺陷分類法 (Five-Category Taxonomy)**

作者提出涵蓋五個面向的缺陷分類體系，這是方法論的重要基石：

1. **空間利用 (Space Utilization)**：處理頁面留白 (White Space) 分布不均、頁面平衡 (Page Balance) 不佳等問題；
2. **浮動物件配置 (Float Placement)**：處理圖片配置 (Figure Placement) 錯置、浮動物件 (Floats) 與正文分離等問題；
3. **排版字體一致性 (Typographic Consistency)**：處理字型、字級、行距在不同段落或章節間的不一致；
4. **溢位 (Overflow)**：處理方程式溢位 (Overflowing Equations)、表格縮放不一致 (Inconsistent Table Scaling)、過滿水平框 (Overfull hbox) 等問題；
5. **跨範本遷移 (Cross-Template Migration)**：處理從一個會議範本 (Venue Templates) 切換到另一個時產生的格式衝突。

此分類法的價值在於將「視覺缺陷」這個模糊概念結構化，使診斷過程可系統化、可審計，並為後續的基準測試提供標註框架。

**三大設計元件解析**

**(1) 多源證據整合 (Multi-Source Evidence Integration)**

此元件解決「可觀察性不足 (Incomplete Observability)」的限制。傳統規則式工具僅能讀取 LaTeX 原始碼 (Source Code) 與編譯日誌 (Log Files)，這是一維的、程式碼層級的訊號。PaperFit 同時融合四種證據來源：原始碼、編譯日誌、PDF 結構、以及頁面影像 (page images)，並將其整合為結構化的缺陷記錄 (defect records)。這種融合策略的關鍵洞見在於：單一證據來源皆有盲點，例如編譯日誌能偵測 overfull hbox 警告，但無法判斷該溢位在視覺上是否顯著；頁面影像能呈現二維版面配置 (Two-Dimensional Layout)，但無法定位對應的原始碼行數。多源融合使診斷從「猜測」轉變為「證據導向」。

**(2) 受約束修復策略 (Constrained Repair Policy)**

此元件解決「無約束修復空間 (Unconstrained Repair Space)」的限制。LaTeX 提供了大量命令，但其中許多屬於「虛假修復 (Pseudo-Fixes)」——例如 \vspace、\resizebox、\newpage 雖然能產生可編譯的輸出，但會扭曲排版字體學 (Typography)、掩蓋問題、或將缺陷轉移到其他位置。受約束修復策略明確劃分三類操作：允許的操作、禁止的虛假修復、以及受保護的內容 (Protected Content)。此設計借鑑了控制理論中的動作空間約束思想，將無限的編輯可能性縮減到符合「隱性排版規範 (Implicit Typesetting Norms)」的子空間。

**(3) 檢查表閘控多輪驗證 (Checklist-Gated Multi-Round Validation)**

此元件解決「未驗證的連鎖效應 (Unverified Cascading Effects)」的限制。LaTeX 編輯具有高度非局部性 (non-locality)：一個圖片寬度的微小改變可能觸發整份文件的分頁重新排列 (Page-Break Rearrangements)。純文字大型語言模型 (Text-only LLM) 在開迴路 (Open Loop) 下運作，無法預測渲染結果。PaperFit 在每次編輯後強制執行「重新編譯 → 重新渲染 → 重新檢查」的完整流程，並以檢查表 (checklist) 作為閘門 (gate)，只有當所有視覺品質指標通過後才接受該修改。這種設計將人類的「編譯–檢查–修改循環 (Compile–Inspect–Edit Cycle)」形式化為自動化協議。

**整體方法論的系統論觀點**

從系統論角度，PaperFit 實際上構建了一個「感知–行動–驗證」(sense–act–verify) 的閉迴路控制系統：VLM 同時扮演感測器 (解讀頁面影像) 與控制器 (生成 LaTeX 修改)；受約束修復策略定義了控制器的動作空間；閘控驗證則是回授機制。這種架構的優勢在於將「視覺品質」這個難以形式化的目標，透過反覆迭代與結構化檢查表，轉化為可收斂的優化問題。

#### 實驗數據解讀

雖然提供的全文僅至第 2.1 節，但從摘要與引言可推導出實驗設計的核心要素與其意義。

**基準測試規模與多樣性**

PaperFit-Bench 包含 200 篇論文、10 種會議範本 (Venue Templates)、13 種缺陷類型，並劃分為三個難度等級。此規模在文件自動化領域屬於中大型基準。10 種會議範本的多樣性尤為關鍵，因為不同會議 (例如 NeurIPS、ICML、IEEE、ACM) 在欄數、字型、邊界 (Margins)、標題 (Headings) 樣式上差異極大，這使得基準能夠測試方法的泛化能力，而非僅在單一範本上過擬合。13 種缺陷類型對應五類缺陷分類法的細化，難度分級則使基準能區分「簡單單一缺陷修復」與「複雜多缺陷交互」的能力差異。

**六種基準線的漸進式設計**

作者設計了六種基準線 (baselines)，從「僅規則」逐步增加能力至「多輪視覺修復」。這種漸進式設計是實驗方法論上的重要選擇，因為它能夠進行「消融式因果分析」：透過逐步添加能力 (例如先加入視覺感知、再加入受約束修復、最後加入閘控驗證)，可以分離每個元件的獨立貢獻。這比單純比較最終效能更能揭示「為何有效」。

**關鍵比較：樸素多輪視覺代理 vs. PaperFit**

作者特別強調最具資訊量的比較是「共享相同頁面影像、但缺乏結構化診斷、受約束修復、與閘控驗證的樸素多輪視覺代理」。PaperFit 在視覺品質與頁數預算滿足度上皆大幅超越此基準線。這一比較的深層意義在於：它證明了「視覺回授是必要條件，但非充分條件」。換言之，僅僅將頁面影像丟給 VLM 並進行多輪對話是不夠的，必須搭配結構化的診斷框架與動作約束，才能避免引入新缺陷或忽略頁數預算約束。

**編譯與渲染成功率**

PaperFit 達到「完美的編譯與渲染成功率」，這在基準測試中是一個強烈訊號：它意味著系統在所有 200 篇論文中皆未產生破壞性修改。這對於實際部署至關重要，因為一個會偶爾破壞編譯的系統在投稿截止期限 (Submission Deadlines) 情境下是不可接受的。

**效能指標的設計意涵**

從引言可推斷，評估指標至少包含：(1) 編譯成功率；(2) 視覺品質分數 (可能由人類評審或 VLM 評審給出)；(3) 頁數預算合規率 (是否在會議頁數限制 (Conference Page Limits) 內)。這三個指標分別對應「功能性」、「美學」、「合規性」三個維度，構成完整的品質評估三角。

**實驗結果的理論意涵**

實驗結果支持了兩個核心論點：(1) VTO 是文件自動化流程 (Document Automation Pipeline) 中「缺失的關鍵階段」——介於結構化排版 (Structural Formatting) 與最終發表之間；(2) 結構化的視覺閉迴路控制是產出達發表標準的 PDF (Publication-Ready PDF) 的決定性因素。這兩個論點共同將 PaperFit 從「一個工具」提升至「一個新研究方向的奠基」。

#### 與現有研究的比較

**在文件自動化光譜中的定位**

文件自動化研究可大致分為三個階段：(1) 結構化排版 (Structural Formatting)，代表工作包括 Pandoc 的格式轉換、文件理解模型 (Document Understanding Models) 如 LayoutLM 系列 [214, 215]、DocFormer [11]、DONUT [100] 的逆向重建、以及 LLM 驅動的 LaTeX 生成器如 Rxiv-Maker [164]；(2) 排版優化 (Typesetting Optimization)，目前幾乎完全依賴人工；(3) 視覺品質評估，目前缺乏系統化方法。PaperFit 精準切入第 (2) 階段的自動化空白，並為第 (3) 階段提供基準。

**與規則式工具的比較**

規則式工具 (Rule-Based Tools) 的根本限制在於「視覺盲性 (Visual Blindness)」：它們僅能讀取原始碼與日誌，無法判斷二維版面配置的視覺後果。例如，overfull hbox 警告僅告訴我們「某處水平空間超出 1pt」，但無法告訴我們「這個溢位是否會破壞閱讀流暢度 (Reading Flow)」或「是否會導致圖表與正文分離」。PaperFit 透過頁面影像的視覺感知徹底克服此限制。

**與純文字 LLM 的比較**

純文字大型語言模型 (Text-only LLM) 雖然能理解 LaTeX 語法並生成修改，但它們在開迴路下運作——修改原始碼後無法預測渲染結果。這導致兩個問題：(1) 無法驗證修改是否真的改善視覺品質；(2) 無法預警連鎖效應 (Cascading Effects)。PaperFit 的閉迴路設計從根本上解決這兩個問題，並透過受約束修復策略防止 LLM 傾向使用 \vspace、\resizebox 等虛假修復。

**與文件理解模型的比較**

LayoutLM 系列、DocFormer、DONUT 等文件理解模型擅長從 PDF 影像中提取結構並重建標記，但它們的輸出是「識別出的版面」或「重建的標記」，而非「視覺優化後的原始碼」。PaperFit 與這些工作形成互補：文件理解模型負責「從 PDF 到原始碼」的方向，PaperFit 負責「從原始碼到優化 PDF」的方向。

**與 VTLayout 等版面分析模型的比較**

VTLayout [110] 透過整合深層與淺層視覺特徵改善內容區塊識別。PaperFit 與此類工作的差異在於目標函數：VTLayout 追求「識別準確度」，PaperFit 追求「視覺品質優化」。前者是被動的感知，後者是主動的決策與行動。

**方法論的優勢**

相較於現有研究，PaperFit 的核心優勢在於：(1) **問題形式化的清晰度**——首次將 VTO 定義為獨立研究任務；(2) **缺陷分類法的結構化**——五類分類法使診斷可系統化；(3) **閉迴路架構的完整性**——同時解決可觀察性、行動空間、與驗證三個限制；(4) **基準的可比較性**——PaperFit-Bench 與六種漸進式基準線使後續研究有明確的比較對象。

**現有論文的侷限性**

從引言對現有方法的批評可推斷，PaperFit 承認以下侷限性：(1) 系統依賴 VLM 的視覺理解能力，若 VLM 在某些版面配置上判斷錯誤，系統仍可能產生次優結果；(2) 受約束修復策略的「約束」本身需要預先定義，這引入了「誰來定義規範」的元問題；(3) 多輪迭代的計算成本較高，每次修改都需要重新編譯與渲染，對長篇論文可能耗時；(4) 基準測試的 200 篇論文與 10 種範本雖具多樣性，但相對於真實學術出版的長尾分布仍屬有限。

#### 可重現性評估

**程式碼與模型權重的可用性**

從提供的全文片段中，未明確提及程式碼開源、模型權重釋出、或基準資料集的公開情況。然而，考慮到本論文屬於 cs.AI 領域且發表於 arXiv (編號 2605.10341v1)，並建立了完整的基準測試 PaperFit-Bench，合理的期待是作者會在最終版本中提供以下資源：(1) PaperFit 系統的原始碼；(2) PaperFit-Bench 的 200 篇論文資料集 (可能需考量版權)；(3) 六種基準線的實作；(4) 評估協議的詳細規範。

**基準的可重現性要素**

PaperFit-Bench 的設計本身有利於可重現性：(1) 10 種會議範本為公開可得的 LaTeX 範本；(2) 13 種缺陷類型有明確分類法可依循；(3) 三個難度等級提供分層評估；(4) 六種漸進式基準線使消融研究可重複。然而，可重現性的潛在障礙在於：(1) 缺陷的「注入方式」若涉及人工標註，可能存在標註者偏誤；(2) 視覺品質評估若依賴人類評審，可能存在評審間信度問題；(3) VLM 的版本更新可能導致結果不可直接比較。

**資料集規模的適切性**

200 篇論文、10 種範本、13 種缺陷類型的組合提供了約 2600 個缺陷實例 (假設每篇論文平均含 1.3 種缺陷)，此規模對於深度學習基準屬於中等。雖然不足以訓練大型模型，但對於評估與基準化已足夠。值得注意的是，若缺陷類型在 200 篇論文中分布不均，某些罕見缺陷類型可能僅有少量實例，影響統計顯著性。

**實驗細節的透明度**

從引言可知，實驗設計強調「漸進式基準線」與「消融式分析」，這是良好的可重現性實踐。然而，具體的評估指標計算方式、視覺品質的評分標準、頁數預算的容差設定等細節，需待全文其餘部分 (第 3-5 節) 才能完整評估。

**整體可重現性評估**

基於現有資訊，PaperFit 的可重現性處於「中等偏上」的水準：問題形式化清晰、基準設計結構化、基準線漸進式設計有利於消融研究；但具體的程式碼、資料、與權重釋出情況需待確認。對於學術界跟進此研究方向，PaperFit-Bench 的存在本身已是重要貢獻——它為後續研究提供了共同的比較基礎。

#### 未來研究方向

**方向一：VLM 視覺感知能力的專門化**

PaperFit 的效能上限受制於底層 VLM 的版面理解能力。未來研究可探索：(1) 針對學術版面微調 (fine-tune) 專用的 VLM，使其能更精準地識別浮動物件錯置、寡行與孤行 (Widow and Orphan Lines) 等細微缺陷；(2) 引入「版面感知預訓練」(layout-aware pretraining)，使 VLM 在預訓練階段即學習排版規範；(3) 結合符號推理 (symbolic reasoning) 與神經感知，彌補 VLM 在精確空間測量上的不足。

**方向二：缺陷分類法的擴展與標準化**

五類缺陷分類法是良好的起點，但可進一步擴展：(1) 納入「跨語言排版缺陷」(例如 CJK 字型與拉丁字型的混排問題)；(2) 納入「無障礙排版缺陷」(例如對螢幕閱讀器的相容性、色彩對比度)；(3) 與學術出版界的實際審稿意見對齊，使分類法能反映真實的審稿標準；(4) 推動成為 IEEE/ACM 等組織的標準分類法。

**方向三：受約束修復策略的學習化**

當前的受約束修復策略可能採用預定義規則，未來可探索：(1) 從大量已發表論文中學習「隱性排版規範」的機率模型；(2) 引入強化學習 (Reinforcement Learning)，使修復策略能從編輯結果中自我優化；(3) 結合人類排版專家的領域知識，構建可解釋的修復策略庫。

**方向四：效率與可擴展性優化**

多輪迭代的計算成本是實際部署的瓶頸。未來方向包括：(1) 增量式編譯 (incremental compilation)，僅重新渲染受影響的頁面；(2) 預測性編輯 (predictive editing)，在修改前預測連鎖效應，避免無效迭代；(3) 平行化診斷，多個缺陷同時處理；(4) 將 PaperFit 整合至雲端編譯服務，提供即時反饋。

**方向五：跨範本遷移的深度研究**

五類缺陷中的「跨範本遷移」目前可能僅被初步處理，未來可深入：(1) 構建範本之間的「格式映射圖」(format mapping graph)，使遷移過程可追溯；(2) 處理範本衝突時的「最小代價變換」(minimum-cost transformation)；(3) 支援使用者自定義範本，擴展至會議、期刊、學位論文等多元場景。

**方向六：人機協作排版**

完全自動化的排版優化可能不適用於所有情境。未來可探索：(1) 「建議式 PaperFit」，僅標記缺陷並建議修改，由人類作者決定是否採用；(2) 「解釋式 PaperFit」，為每個修改提供視覺化的前後對比與理由；(3) 「協作式 PaperFit」，在人類編輯過程中即時提供視覺品質反饋。

**方向七：評估方法的標準化**

視覺品質的評估本身是開放問題。未來方向：(1) 建立大規模的人類評審資料集，作為視覺品質的「 ground truth」；(2) 探索「視覺品質的計算度量」(例如留白分布的熵、版面平衡的對稱性)；(3) 將 PaperFit-Bench 擴展為持續更新的「排行榜」(leaderboard)，追蹤領域進展。

**方向八：應用場景的拓展**

PaperFit 的核心思想——視覺閉迴路優化——可應用於：(1) 簡報軟體 (PowerPoint、Keynote) 的版面優化；(2) 書籍排版 (InDesign 自動化)；(3) 網頁設計的視覺一致性檢查；(4) 海報與學術牆報的版面優化。這些場景共享「視覺品質難以形式化、修改具有連鎖效應」的核心挑戰，PaperFit 的方法論具有跨領域遷移潛力。

**方向九：理論基礎的深化**

VTO 的閉迴路控制框架可進一步理論化：(1) 證明在受約束修復空間下的收斂性；(2) 分析不同缺陷類型之間的交互作用 (例如「溢位」與「頁面平衡」的耦合)；(3) 探討視覺品質的「帕累托前沿」(Pareto frontier)，例如「視覺品質 vs. 頁數」的多目標優化。這些理論工作將使 VTO 從「經驗方法」提升為「有理論支撐的學科」。

## 論文問答

**Q1：什麼是視覺排版優化（VTO）？為什麼作者認為這是文件自動化流程中缺失的關鍵環節？**

A：視覺排版優化（Visual Typesetting Optimization, VTO）是作者所形式化的一項新任務，其目標是將一份「可編譯的 LaTeX」文件，透過反覆式視覺驗證與原始碼層級修訂，轉化為視覺精緻且符合頁數預算的達發表標準 PDF。作者之所以將 VTO 定位為文件自動化流程中的關鍵缺失環節，是因為現有的結構化排版階段（從 Pandoc 等格式轉換工具到文件理解模型、大型語言模型生成 LaTeX 框架）僅止於產出可編譯的 .tex 檔案，卻無法保證最終 PDF 的視覺品質。換言之，從「可編譯的 LaTeX」到「達發表標準的 PDF」之間存在一道鴻溝，而 VTO 正是填補這道鴻溝所不可或缺的階段。

**Q2：現有的文件自動化方法（如規則式工具和純文字大型語言模型）在處理排版優化時面臨哪些根本性限制？**

A：作者歸納出三項根本性限制：第一是「可觀察性不足」，規則式工具與編譯日誌僅提供一維、原始碼層級的訊號（例如過滿水平框警告），無法判斷輕微溢位是否在視覺上顯著、圖片配置如何影響閱讀流暢度、或留白如何分佈於頁面。第二是「無約束修復空間」，當模型識別出問題時，面對的動作空間極其龐大，但其中多數選項屬於虛假修復——例如 \vspace、\resizebox、\newpage 等指令雖能產出可編譯的結果，卻會扭曲排版字體學、掩蓋問題或將缺陷轉移至他處。第三是「未驗證的連鎖效應」，LaTeX 編輯具有高度非局部性，調整圖片寬度可能觸發整份文件的分頁重新排列，而純文字大型語言模型處於開迴路狀態，無法在修改後渲染並驗證結果，因此無法確認編輯究竟是改善還是惡化全域版面配置。

**Q3：為什麼「可編譯的 LaTeX」並不等於「達發表標準的 PDF」？請舉例說明常見的排版缺陷類型。**

A：編譯成功僅代表語法與結構有效，卻無法保證視覺呈現的品質；一份語法正確的 LaTeX 專案仍可能產出充斥浮動物件錯置、方程式溢位、表格縮放不一致、寡行與孤行、以及頁面平衡不佳等問題的 PDF。常見缺陷包括：圖表被推到與本文不相關的位置（misplaced floats）、數學公式超出頁邊界（overflowing equations）、表格大小不一致影響閱讀（inconsistent table scaling）、段落首末行單獨留在頁首或頁尾（widow and orphan lines）、以及頁面留白過多或內容溢出至額外的半頁而違反會議頁數限制。這些缺陷的共同特徵在於，它們都屬於二維版面配置的空間判斷，無法僅從原始碼或日誌檔案中推導出來，必須仰賴視覺判斷才能正確診斷與修復。

**Q4：PaperFit 的核心設計理念是什麼？它如何實現「視覺在環」的閉迴路控制？**

A：PaperFit 的核心設計理念是將人類「編譯–檢查–修改循環」的工作流程形式化為一個「感知–行動–驗證」的視覺閉迴路代理，使排版優化從開迴路的文字編輯轉變為具備視覺感測、受約束動作與全域驗證的閉迴路控制問題。具體而言，PaperFit 在每一輪迭代中先反覆式渲染頁面、診斷缺陷，再透過受約束的修復引擎產生 LaTeX 修改，最後以品質閘控重新編譯、重新渲染並重新檢視整份文件，確保每次編輯後的結果都經過視覺驗證。這種設計模仿了人類研究者反覆編譯、檢視渲染結果、調整原始碼、再編譯的工作模式，從而克服純文字大型語言模型無法預測二維版面配置後果的根本缺陷。

**Q5：PaperFit 如何透過三大設計元件（多源證據整合、受約束修復政策、檢查表閘控多輪驗證）來克服現有方法的三大限制？**

A：針對「可觀察性不足」，PaperFit 採用多源證據整合，將原始碼、編譯日誌、PDF 與頁面影像等多重訊號融合為結構化的缺陷紀錄，使診斷能同時考量程式碼層級與視覺層級的證據。針對「無約束修復空間」，PaperFit 引入受約束修復政策，明確界定允許的操作、禁止的虛假修復（如 \vspace、\resizebox、\newpage 等表面性變通手段）以及受保護的內容，從而馴化龐大的動作空間並避免違反隱性排版規範。針對「未驗證的連鎖效應」，PaperFit 透過檢查表閘控多輪驗證，在每次編輯後重新編譯、重新渲染並重新檢視整份文件，於連鎖效應擴散前即時攔截，確保全域版面配置的穩定性。

**Q6：作者提出的五類排版缺陷分類法涵蓋哪些類別？這個分類法如何指導診斷過程？**

A：作者提出的五類排版缺陷分類法涵蓋空間利用（space utilization）、浮動物件配置（float placement）、排版字體學一致性（typographic consistency）、溢位（overflow）以及跨範本遷移（cross-template migration）。這個分類法為診斷過程提供了結構化的指引：當 PaperFit 檢視渲染頁面時，能依據這五個類別系統性地掃描缺陷，而非以無差別的方式處理所有視覺異常，從而提升診斷的完整性與效率。此外，分類法也使缺陷紀錄得以標準化，便於後續的受約束修復引擎對症下藥，並讓檢查表閘控驗證能針對各類別設定對應的通過條件。

**Q7：PaperFit-Bench 基準測試是如何建構的？包含哪些會議範本、論文數量和缺陷類型？**

A：PaperFit-Bench 涵蓋 10 種會議範本、200 篇論文以及 13 種缺陷類型，並依難度分為三個等級。這個基準測試的設計目的在於系統性地評估視覺排版優化任務，因為現有的文件自動化評測多聚焦於結構化排版階段（如 LaTeX 原始碼生成或文件理解），缺乏針對「從可編譯 LaTeX 到達發表標準 PDF」這一中間階段的標準化測試。透過涵蓋多元的會議範本與缺陷類型，PaperFit-Bench 能夠全面檢驗模型在不同排版規範、不同視覺缺陷下的泛化能力，並提供難度分層以區分模型在簡單與複雜情境下的表現差異。

**Q8：PaperFit 在實驗中相較於基準方法取得了哪些關鍵成果？為什麼與「天真多輪視覺代理」的比較特別具有啟發性？**

A：PaperFit 達到了完美的編譯與渲染成功率，並在視覺品質與頁數預算合規性兩個面向均取得最高分，大幅超越所有基準方法。其中與「天真多輪視覺代理」的比較特別具有啟發性，因為該代理雖然同樣具備多輪視覺能力並接收相同的頁面影像，卻缺乏結構化診斷、受約束修復與閘控驗證等設計；PaperFit 在視覺品質與頁數預算滿足度上均以顯著差距勝過該代理。這項對照實驗有力地證明了「視覺回饋是必要條件但非充分條件」——單純將頁面影像丟給視覺語言模型並反覆迭代是不夠的，必須搭配結構化的閉迴路控制才能產出真正達發表標準的文件。

**Q9：實驗中設計了哪六種基準方法？它們如何以漸進式方式加入不同能力？**

A：作者設計了六種基準方法，以漸進式方式從僅有規則能力逐步擴展至多輪視覺修復能力。這種漸進式設計使研究者能夠拆解每項能力對最終表現的貢獻：例如，僅有規則式工具的基準無法處理視覺缺陷；加入純文字大型語言模型後可進行開放式原始碼編輯但缺乏視覺回饋；進一步加入視覺語言模型後可觀察渲染結果但仍可能產生虛假修復；唯有當結構化診斷、受約束修復政策與閘控驗證三者齊備時，才能達到 PaperFit 的水準。這種層層遞進的基準設計不僅驗證了各元件的必要性，也清晰呈現了從「盲目規則」到「視覺閉迴路」的演進路徑。

**Q10：PaperFit 在實際應用場景中能為研究者帶來哪些具體幫助？特別是在投稿截止期限前的關鍵時刻？**

A：在實際應用中，PaperFit 能自動化處理研究者手動進行的編譯–檢查–修改循環，大幅縮短從可編譯 LaTeX 到達發表標準 PDF 所需的時間與精力。對於面臨投稿截止期限的研究者而言，PaperFit 的價值尤為顯著：它能在最後數小時內自動偵測並修復浮動物件錯置、頁面平衡不佳、頁數超出會議頁數限制等緊迫問題，使研究者能將心力集中於內容修訂而非版面微調。此外，PaperFit 的受約束修復政策確保所有修改都符合隱性排版規範，避免了「趕時間亂改」所導致的表面性變通與新缺陷，從而提升投稿文件的整體品質與被接受的機會。

**Q11：從產品化角度來看，PaperFit 這類系統需要考量哪些實際部署因素？**

A：從產品化角度來看，PaperFit 的部署需考量多項實際因素：首先，系統需要可靠的 LaTeX 編譯環境與 PDF 渲染基礎設施，以支援反覆式渲染與視覺驗證的密集運算需求；其次，視覺語言模型的推理成本與延遲必須控制在合理範圍內，否則多輪迭代的時間成本將抵消自動化所帶來的效益；第三，系統需支援多元的會議範本與自訂範本檔案，並能正確解析各範本對字型、邊界、標題等格式化元素的隱性規則；最後，產品需提供清晰的使用者介面與缺陷診斷報告，讓研究者能理解系統所做的修改並保留最終決策權，避免「黑箱自動化」所帶來的不信任感。

**Q12：PaperFit 對文件自動化、學術出版和 AI 輔助寫作領域可能產生哪些更廣泛的影響？**

A：PaperFit 的影響可從三個層面來看：在文件自動化領域，它確立了視覺排版優化作為結構化排版與最終發表之間的關鍵中間階段，為未來的文件自動化流程提供了完整的參考架構；在學術出版領域，它有潛力降低投稿文件的格式相關退稿率，使審稿資源能更集中於內容品質的評估；在 AI 輔助寫作領域，PaperFit 展示了「視覺在環」閉迴路控制的重要性，證明了單純的文字生成能力不足以處理涉及空間與視覺判斷的任務，這對未來整合視覺感測的寫作輔助工具具有方法論上的啟示意義。

**Q13：PaperFit 目前存在哪些已知的限制？特別是在處理複雜 LaTeX 專案或特殊會議範本時？**

A：PaperFit 目前的限制主要體現在以下幾個方面：對於高度複雜的 LaTeX 專案（如包含大量自訂巨集、跨檔案引用或特殊套件的論文），其受約束修復政策可能無法涵蓋所有合法的編輯操作，導致部分缺陷無法被自動修復；對於極為特殊的會議範本或非標準的排版規範，系統可能缺乏足夠的範本檔案資訊來正確推導修復偏好；此外，視覺語言模型本身的感知能力仍有上限，對於極為細微的排版字體學差異或跨頁面的全域版面配置問題，診斷的準確性可能受到影響。這些限制意味著 PaperFit 目前更適合作為研究者的輔助工具而非完全自動化的替代方案。

**Q14：在什麼情況下 PaperFit 可能會失敗或產生新的缺陷？「虛假修復」的概念如何體現這種風險？**

A：PaperFit 可能失敗的情境包括：當診斷階段誤判缺陷的嚴重程度或位置時，後續的修復可能反而引入新的視覺缺陷；當受約束修復政策未能完整涵蓋某個特殊情境時，系統可能退而採用次優的修復方案；當連鎖效應超出閘控驗證的檢查範圍時，局部修復可能對遠端頁面產生未預期的影響。「虛假修復」的概念正體現了這種風險——例如，使用 \vspace 手動調整留白雖能消除某一頁的留白過多問題，卻可能破壞整體的頁面平衡；使用 \resizebox 縮小溢位表格雖能避免方程式溢位，卻可能造成字型與其他表格不一致；使用 \newpage 強制分頁雖能解決孤行問題，卻可能導致後續頁面出現新的留白異常。這些表面性變通手段正是 PaperFit 透過受約束修復政策試圖系統性避免的陷阱。

**Q15：未來的研究方向有哪些？視覺在環的概念可以如何擴展到其他文件自動化任務？**

A：未來的研究方向可從幾個維度展開：在方法層面，可探索更強大的視覺語言模型與更精細的缺陷分類法，以提升診斷的準確性與修復的細緻度；在範本適應性方面，可研究如何讓系統從少量範本檔案中自動推導修復偏好，降低對人工定義受約束修復政策的依賴；在任務擴展方面，「視覺在環」的概念可進一步應用於簡報排版、書籍版面配置、跨語言文件格式轉換等涉及二維版面配置判斷的場景。此外，將 PaperFit 與結構化排版階段（如 LaTeX 框架生成）整合為端到端的文件自動化流程，以及探索其在協作寫作環境中的多代理人協作模式，都是值得深入探索的方向。

## 實務應用指南

### 適用場景

1. **學術投稿前的最後一哩自動化**：研究團隊在 NeurIPS、ICML、CVPR、ACL 等會議截稿前 24–72 小時，可將已可編譯的 LaTeX 原始碼交給 PaperFit 自動處理寡行與孤行、浮動物件錯置、表格縮放不一致等排版缺陷，減少人工 compile–inspect–edit 循環次數。

2. **期刊與會議編輯部的初審排版檢查**：出版單位可將 PaperFit 部署為投稿系統的閘道器，自動驗證稿件是否符合頁數預算、字型與邊界規範，並產出視覺品質報告供編輯參考，降低退稿往返成本。

3. **跨範本遷移服務**：當期刊改版或作者需將稿件從 IEEEtran 遷移至 ACM 範本時，PaperFit 的五類缺陷分類法（涵蓋跨範本遷移類別）可協助自動調整章節編號、引用樣式與圖片寬度，縮短轉檔時間。

4. **企業內部技術文件品質控管**：研發機構撰寫白皮書、技術報告或專利文件時，可整合 PaperFit 確保多份文件視覺風格一致，避免不同作者產出排版品質落差過大的 PDF。

5. **AI 寫作輔助工具的後處理管線**：搭配 Pandoc 等格式轉換工具與文件理解模型，PaperFit 可作為文件自動化流程的最後一站，將「可編譯 LaTeX」升級為「達發表標準的 PDF」，補上結構化排版之後的關鍵缺口。

### 實作前置條件

**資料前置條件**
- 至少數百份涵蓋目標會議範本（如 IEEE、ACM、Springer、arXiv 樣式）的可編譯 LaTeX 範本檔案與對應 PDF，用於建立 PaperFit-Bench 風格的缺陷樣本與評估集。
- 各類排版缺陷的標註資料：浮動物件錯置、寡行與孤行、方程式溢位、表格縮放不一致、頁面平衡不佳等 13 種缺陷類型的範例。
- 目標會議的官方樣式檔（`.cls`、`.sty`）與頁數預算規範文件，作為受約束修復策略的規則來源。

**算力前置條件**
- 一台或多台配備充足 GPU 的機器，用於託管視覺語言模型（VLM）進行頁面影像理解；建議至少 A100 等級或同等算力。
- LaTeX 編譯環境（TeX Live 或 MiKTeX）與 PDF 轉影像工具鏈（pdftoppm、pdf2image）。
- 容器化基礎設施（Docker / Kubernetes）以便水平擴展，處理大量稿件時的批次渲染與驗證。

**技能前置條件**
- 熟悉 LaTeX 編譯流程、log 檔案解析與常見警告（如 overfull hbox）的意義。
- 具備視覺語言模型 prompt 工程與閉迴路控制系統設計經驗。
- 了解會議範本的隱性排版規範，能將其編碼為受約束修復策略中的允許操作與禁止操作清單。
- 具備軟體工程能力以建構多輪驗證管線與品質閘門。

### 實作步驟建議

1. **問題界定與基準建立**：先在內部挑選 20–50 份真實稿件，依 PaperFit-Bench 的五類缺陷分類法（空間利用、浮動物件配置、字體一致性、溢位、跨範本遷移）標註缺陷類型與嚴重度，作為初期評估基準。

2. **多源證據整合模組開發**：實作「多源證據整合」元件，融合 LaTeX 原始碼、編譯日誌、PDF 文字層與頁面影像四種訊號，產出結構化缺陷紀錄。可先以規則式解析器處理 log 警告，再串接 VLM 進行視覺診斷。

3. **受約束修復策略制定**：盤點目標範本的隱性排版規範，明確定義允許操作（如 `\FloatBarrier`、`\enlargethispage`）、禁止的虛假修復（如任意 `\vspace`、`\resizebox`、`\newpage`）以及受保護內容（公式、引用、圖表標題）。

4. **閉迴路代理主迴圈建構**：依循 sense–act–verify 模式組裝 PaperFit 主迴圈：渲染頁面影像 → VLM 診斷缺陷 → 修復引擎套用受約束操作 → 重新編譯並重新渲染 → 品質閘門驗證改善或退回。

5. **檢查清單閘門的多輪驗證**：為每類缺陷設計通過條件（如「頁數預算符合」、「無新增 overfull hbox」、「圖片未被裁切」），並實作多輪迭代直到所有條件通過或達到上限。

6. **基準測試與消融實驗**：以 PaperFit-Bench 風格的評估集比較六種由簡至繁的基準（純規則、純文字 LLM、無約束視覺代理等），量化視覺品質、頁數預算符合率與編譯成功率，驗證三項設計元件的必要性。

7. **產品化與 CI/CD 整合**：將系統包裝為 API 或 CLI 工具，串接投稿平台、GitHub Actions 或企業文件管理系統，建立監控儀表板追蹤缺陷修復率與人工覆核比例。

### 潛在風險與注意事項

- **虛假修復的蔓延**：模型可能傾向使用 `\vspace`、`\resizebox`、`\newpage` 等表面性變通手段製造可編譯但違反排版規範的結果。**緩解方式**：在受約束修復策略中明確列為禁止操作，並在品質閘門中加入「字型未扭曲」、「圖片未變形」等視覺檢查。

- **連鎖效應難以預測**：LaTeX 編輯具有高度非局部性，調整一張圖片寬度可能引發全文件的分頁重新排列。**緩解方式**：每次編輯後必須重新編譯、重新渲染並重新檢查所有頁面，採用檢查清單閘門的多輪驗證機制。

- **頁數預算的硬約束**：會議頁數限制是剛性條件，過度緊縮或過度擴張都會被退稿。**緩解方式**：將頁數符合度列為最高優先級閘門，並允許在多輪迭代中動態調整 `\textfloatsep`、`\intextsep` 等參數。

- **VLM 視覺幻覺導致誤判**：視覺語言模型可能將正常版面誤判為缺陷，導致不必要的修改。**緩解方式**：結合 log 檔案與 PDF 文字層的多源證據交叉驗證，並設置「修改需有證據支撐」的門檻。

- **範本多樣性帶來的維護成本**：10 種會議範本各有獨特規範，持續新增範本會擴大規則庫。**緩解方式**：將規範抽象為可組合的規則模組，並建立範本變更時的迴歸測試套件。

- **編譯環境不一致**：不同機器上的 TeX Live 版本差異可能導致同一原始碼產生不同 PDF。**緩解方式**：使用容器化固定版本的編譯環境，並在 CI 中驗證可重現性。

### 與其他技術的整合建議

- **與 Pandoc 等格式轉換工具串接**：在 Markdown 或 Word 轉 LaTeX 的管線末端加入 PaperFit，補上結構化排版之後的視覺優化階段，形成「Markdown/Word → Pandoc → LaTeX → PaperFit → 達發表標準的 PDF」完整鏈路。

- **與文件理解模型互補**：LayoutLM、DONUT 等文件理解模型擅長從 PDF 重建 LaTeX 原始碼，可作為 PaperFit 的逆向入口；當作者僅有 PDF 時，先重建原始碼再交由 PaperFit 優化。

- **與大型語言模型協作**：純文字大型語言模型擅長生成內容與調整章節結構，但屬於開迴路操作；建議將其用於內容層級修改，將版面層級的視覺優化完全交給 PaperFit 的視覺閉迴路代理，避免職責混淆。

- **與投稿管理系統整合**：透過 API 將 PaperFit 嵌入 OpenReview、EasyChair 等投稿平台，作為作者提交後的自動預檢服務，並將視覺品質報告回傳給編輯。

- **與版本控制系統整合**：在 GitHub Actions 或 GitLab CI 中加入 PaperFit 檢查步驟，於每次 commit 或 pull request 自動驗證排版品質，防止缺陷在開發過程中累積。

- **與企業內容管理平台整合**：在 Confluence、Notion 或內部 Wiki 匯出 PDF 的流程中加入 PaperFit，確保對外發布文件的視覺一致性。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的問題動機，理解「為什麼可編譯的 LaTeX 不等於達發表標準的 PDF」，並透過 Figure 1 的三種方法對比圖直觀感受規則式工具的視覺盲性、純文字大型語言模型的開迴路限制，以及 PaperFit 視覺閉迴路的差異；接著瀏覽五類缺陷分類法，建立對排版缺陷的基本認知，再回頭細讀方法細節。

**給 AI 工程師**：重點關注第 1 節末段與方法章節中描述的三項設計元件——多源證據整合、受約束修復策略、檢查清單閘門的多輪驗證——如何分別回應可觀察性不足、無約束修復空間、未驗證的連鎖效應這三大限制；並仔細研讀實驗章節中六種基準的消融設計，理解每個元件對最終視覺品質與頁數預算符合率的邊際貢獻，作為建構自身閉迴路代理系統的藍圖。

**給研究者**：本文將排版優化形式化為視覺排版優化（VTO）問題，並提出五類缺陷分類法與 PaperFit-Bench 基準，是文件自動化領域的重要概念貢獻；建議從抽象問題定義出發，思考 VTO 與既有文件版面分析、文件理解任務的本質差異，並探索將閉迴路控制理論、強化學習或規劃演算法引入排版優化的可能性，同時關注 13 種缺陷類型在三種難度下的分布，挑選值得深挖的子問題。

**給產品經理**：PaperFit 定位為文件自動化流程中「結構化排版」與「最終發表」之間的關鍵缺失環節，商業價值在於縮短投稿週期、降低編輯部審稿成本、提升文件視覺一致性；建議從適用場景章節評估自身產品的整合切入點（如投稿平台、CI/CD、內容管理系統），並透過 PaperFit-Bench 的量化指標（編譯成功率、視覺品質、頁數預算符合率）作為導入後的成效衡量基準，同時將「虛假修復」與「連鎖效應」列為產品上線後需持續監控的風險指標。
