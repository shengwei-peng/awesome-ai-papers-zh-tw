## ⚡ TL;DR

現有強化學習難以區分工具呼叫的實際貢獻，且常受冗餘或誤導性操作干擾。
本文提出TACO，結合差分答案探測獎勵與結果閘控優勢路由，精準評估並分配各工具呼叫的信用。
實驗顯示該方法在多項基準測試中穩定提升準確率，並學會僅於必要時呼叫工具。

## 摘要翻譯

代理式多模態模型（agentic multimodal models）透過程式碼對影像執行多樣的操作，並針對回傳的視圖進行推理，此為細粒度視覺問答（fine-grained visual question answering）的一種有效典範。然而，程式碼操作可能是有用的、多餘的，或是具有誤導性的。純結果獎勵（outcome-only rewards）無法精確區分這些情況，而現有的過程獎勵（process rewards）若非無法將最終正確性歸因於個別工具呼叫（tool call），便是需要外部裁判模型（external judge model）。為了解決此問題，我們提出工具增強式信用最佳化（Tool-Augmented Credit Optimization, TACO），這是一個針對程式碼工具代理（code-tool agents）、基於兩個耦合優勢通道（advantage channels）所建構的 GRPO（Group Relative Policy Optimization）變體。第一個是差分答案探測獎勵（Differential Answer-Probe Reward, DAPR），這是一種自監督（self-supervised）、無需裁判模型（judge-free）的工具貢獻優勢（tool-contribution advantage），它依據每個工具呼叫本身對正確回答的影響來分配信用。插入模型推理過程中的探測詞元（probe tokens）會引出模型在有工具與無工具時的預測，而結果獎勵的差異即被視為該次呼叫的價值：有用的呼叫為正值、誤導性的呼叫為負值，而未造成任何改變的呼叫則為零。這種方法重複使用現有的答案檢查器（answer checker），無需輔助裁判模型，且由於它是差分值而非絕對的探測分數，因此自然具備對探測破解（probe-hacking）的穩健性。第二個是來自最終答案的結果優勢（outcome advantage），透過結果閘控優勢路由（Outcome-Gated Advantage Routing, OGAR）進行分配：這是一個無參數的規則，視該次呼叫的結果而定，僅將此信用傳遞給應負責的片段，無需任何成本項即可抑制無用的工具呼叫。我們透過兩階段的 SFT+RL 流程（SFT+RL pipeline）來訓練 TACO。在感知、推理與通用多模態基準測試（perception, reasoning, and general multimodal benchmarks）上進行的大量實驗顯示，它能帶來穩定的準確度提升，並學會只在有幫助時才呼叫工具。

## 深度分析

#### 方法論解析

TACO（Tool-Augmented Credit Optimization，工具增強式信用最佳化）是一套針對程式碼工具代理（code-tool agents）的 GRPO（Group Relative Policy Optimization，群組相對策略最佳化）變體，其核心在於將「工具呼叫」視為軌跡（trajectory）的明確分叉點，並透過兩條耦合的優勢通道（advantage channels）解決信用分配（credit assignment）問題。

**差分答案探測獎勵（Differential Answer-Probe Reward, DAPR）**
DAPR 的設計建立在「工具呼叫將軌跡分割為乾淨的前後狀態」這一觀察上。具體而言，當代理在推理過程中即將執行程式碼操作（code operation）前，研究者插入探測詞元（probe tokens）以引出「工具關閉」（tool-off）狀態的答案 a₁；待工具執行完畢並完成後續推理後，再引出「工具開啟」（tool-on）狀態的答案 a₂。兩者皆由既有的規則型答案檢查器（answer checker）評分，其差值 Δ = R(a₂) − R(a₁) 即為該次工具呼叫的價值。由於 a₁ 與 a₂ 共享相同的問題、圖像與前置推理，此差分操作本質上取消了模型在呼叫前已具備的先驗知識，從而精確隔離出工具分支（tool branch）——包含程式碼本身、工具回傳的觀察值與後置推理——對最終正確性的邊際貢獻。根據 Δ 的符號與大小，可將呼叫分類為：有用（useful, Δ > 0）、誤導（misleading, Δ < 0）或無效／冗餘（Δ = 0）。值得注意的是，DAPR 屬於自監督（self-supervised）機制，無需外部裁判模型（external judge model），僅複用原本就用於最終答案驗證的答案檢查器，因此不產生額外 API 成本。此外，由於 DAPR 採用差分而非絕對探測分數，對探測破解（probe-hacking）具有天然的穩健性：模型難以透過操縱探測詞元的絕對輸出來獲利，因為任何對 a₁ 與 a₂ 的同步操縱會在差分中被抵消。

**結果閘控優勢路由（Outcome-Gated Advantage Routing, OGAR）**
僅獲得純量工具價值仍不足夠，關鍵在於將信用傳遞至正確的詞元（tokens）。OGAR 是一項無參數（parameter-free）的詞元級別（token-level）規則，依據工具呼叫的結果來路由最終答案優勢（final-answer advantage）。其邏輯可歸納為四種情境：
1. **有用呼叫（useful call）**：a₂ 正確且 Δ ≥ 0，將正向優勢賦予工具分支（程式碼與後置推理 T₂）。
2. **誤導呼叫（misleading call）**：Δ < 0，將負向優勢（懲罰）賦予工具分支。
3. **正確但冗餘（right-but-redundant）**：a₂ 正確但 Δ = 0，表示即使不呼叫工具亦能答對，此時扣押（withhold）對工具分支的信用，從而抑制浪費性呼叫。
4. **必要但失敗（necessary-but-failed）**：a₂ 錯誤且 Δ = 0，表示呼叫是合理的嘗試但工具未能解決難題，此時扣押對工具分支的責備（blame），避免打擊代理在困難樣本上的合理嘗試。

OGAR 的關鍵在於無需任何工具呼叫成本項（tool-call cost term），僅透過結果條件閘控即可達成選擇性強化，這與傳統透過顯式懲罰項抑制過度呼叫的方法有本質區別。

**訓練流程**
TACO 採用兩階段 SFT+RL 流程（SFT+RL pipeline）：第一階段以監督式微調（Supervised Fine-Tuning, SFT）建立基本的工具使用格式與推理模式；第二階段以結合 DAPR 與 OGAR 的強化學習（Reinforcement Learning, RL）進行信用分配的最佳化。目標函數結合了 DAPR 提供的工具貢獻優勢（tool-contribution advantage）與經 OGAR 閘控後的最終結果優勢（outcome advantage），形成單一最佳化目標。

#### 實驗數據解讀

根據摘要與引言所述，TACO 在感知（perception）、推理（reasoning）與通用多模態基準測試（general multimodal benchmarks）上進行了廣泛實驗。儘管提供的上下文未包含具體數值表格，但從作者強調的「一致的準確率提升」（consistent accuracy gains）與「僅在工具有所助益時才發起呼叫」（invoke its tools only when they help）這兩項行為指標，可進行以下解讀：

首先，「一致性」意味著 DAPR 的差分評分機制並非僅在特定視覺領域（如單純的裁切縮放 crop-zoom）有效，而是能泛化至需要不同類型程式碼操作（如數值運算、圖像轉換、細節放大）的多元任務。這暗示 Δ 作為工具邊際貢獻的估計量，其訊號品質足夠穩定，能跨越感知型與推理型任務的差異。

其次，「選擇性呼叫」是 OGAR 成功運作的最直接行為證據。在現有的純結果獎勵（outcome-only rewards）強化學習中，代理常出現過度呼叫（over-call）現象，因為冗餘工具呼叫不會降低最終分數，甚至可能因模型內在改進（intrinsic improvement）而被錯誤獎勵。TACO 能學會抑制浪費性呼叫，代表 OGAR 的「正確但冗餘」閘控確實將負向或零信號傳遞給了無貢獻的工具分支，從而改變了代理的工具使用策略。這不僅提升準確率，也隱含降低了推理時的計算與 API 開銷。

最後，作者指出過往研究的準確率增益大多被混淆訊號（confounded signal）所主導——即模型自身的內在改進掩蓋了工具的真實效用。TACO 的實驗結果能展現「純粹由工具貢獻驅動」的增益，說明 DAPR 成功將內在能力提升與工具邊際價值解耦。

#### 與現有研究的比較

TACO 與現有文獻的差異可從三個維度定位：獎勵訊號的粒度、對外部裁判的依賴，以及訓練與推論階段的角色。

**相較於純結果獎勵（Outcome-only Rewards）與 RLVR**
現有的可驗證獎勵強化學習（RLVR, Reinforcement Learning with Verifiable Rewards）僅對最終答案給予獎勵，其信用附著於整條軌跡（whole trajectory）。如 Ma et al. (2026) 所指出的，此類方法的準確率提升往往來自模型內在改進而非工具本身，形成混淆訊號。TACO 透過 DAPR 的 before/after 差分，首次在訓練階段實現對「單次工具呼叫自身效用」的無偏估計，無需假設工具必然有貢獻。

**相較於文字導向的過程獎勵（Process Rewards）**
MIG、PACR、SPAE 等逐步獎勵（step-wise rewards）方法針對單鏈文字推理設計，運作於對數機率空間（log-probability space）。它們無法隔離外部工具觀察（external tool observation），也難以區分「有助益的步驟」與「有害的步驟」。TACO 則專門處理程式碼工具代理中「外部工具產生新觀察」這一特殊結構，利用工具呼叫造成的軌跡分叉進行精確歸因。

**相較於多輪代理與視覺工具獎勵**
SIOP 與 HISR 雖針對多輪 LLM 代理提供回合級或事後調整的獎勵，但並未聚焦於單次視覺工具呼叫的粒度。CodeV（Hou et al. 2026）雖能評分視覺工具使用，卻依賴外部 GPT-4o 裁判模型，帶來 API 成本與裁判偏見（judge biases）。TACO 的 DAPR 完全無需裁判模型（judge-free），屬於自監督信號；OGAR 則是無參數的詞元級路由規則，不增加模型參數或推理成本。

**相較於測試時訊號**
Zoom-Consistency（Kim and Chelikavada 2026）與 RTWI（Li et al. 2026a）將中間訊號作為測試時（test-time）的可靠性線索，而非訓練獎勵。TACO 則將類似概念轉化為訓練時的穩定獎勵來源，直接塑造策略。

**局限性**
1. **結構依賴**：DAPR 假設工具呼叫能明確劃分「前／後」狀態，對於交錯式（interleaved）或串流式工具使用可能需重新設計探測機制。
2. **答案檢查器限制**：DAPR 依賴規則型答案檢查器產生 R(a₁) 與 R(a₂)。對於開放式生成（open-ended generation）或無明確對錯的視覺任務，差分信號可能難以定義。
3. **探測開銷**：訓練時需額外計算 tool-off 與 tool-on 兩條路徑，增加記憶體與計算負擔，儘管這是獲得歸因精確度的必要代價。
4. **離散閘控**：OGAR 的四分類邏輯雖具可解釋性，但對於「部分有貢獻」的模糊情境可能過於粗糙。

#### 可重現性評估

從提供的全文脈絡來看，作者並未明確提及是否開源訓練程式碼、資料集或模型權重。在可重現性（reproducibility）方面，這構成一項顯著的不確定性。

就方法論本身而言，TACO 的組件——GRPO（群組相對策略最佳化）、規則型答案檢查器、探測詞元插入——皆屬於可複現的標準技術。然而，實際重現面臨以下挑戰：
- **探測詞元的具體格式**：文中僅以概念圖示意 probe token 的插入位置，但未詳細說明其模板化提示（prompt template）與解碼策略，這對穩定引出 a₁ 與 a₂ 至關重要。
- **超參數設定**：DAPR 與 OGAR 在總目標中的權重（如圖示中的 α₁、α₂）、GRPO 的群組大小與 clip ratio 等細節未於摘要與引言中揭露。
- **兩階段銜接**：SFT 階段使用的示範資料（demonstration data）規模與篩選標準，以及過渡到 RL 的時機，均會顯著影響最終策略的穩定性。
- **答案檢查器實作**：不同基準測試（benchmarks）的答案檢查器邏輯差異甚大，若未公開其具體規則，難以確保 DAPR 差分計算的一致性。

建議作者群釋出原始碼、訓練配置檔，以及至少一個中小型檢查點（checkpoint），以便社群驗證 DAPR 的探測穩健性與 OGAR 的閘控行為。

#### 未來研究方向

TACO 為代理式工具使用的信用分配建立了新範式，其後續延伸可從以下五個方向展開：

**1. 組合式多工具信用分配（Compositional Multi-Tool Credit Assignment）**
當前 DAPR 主要針對單次工具呼叫的前後比較。未來可探索「工具鏈」情境，其中多次呼叫相互依賴（例如先裁切再 OCR）。此時需設計遞迴或累積式的差分探測，以處理組合爆炸的邊際貢獻歸因問題。

**2. 非程式碼工具與模糊前後界線的擴展**
將 TACO 應用於檢索增強生成（Retrieval-Augmented Generation, RAG）、API 呼叫或資料庫查詢等「非程式碼工具」情境。這些場景中，tool-off 狀態可能難以定義（例如檢索前後的知識狀態界線模糊），需要發展更廣義的探測框架。

**3. 軟性閘控與可學習路由（Soft Gating and Learnable Routing）**
OGAR 目前的四分類離散閘控雖具可解釋性，但未來可研究「軟性」或基於注意力機制的可學習路由，同時保留 DAPR 的差分信號作為監督。這可能在部分貢獻情境下提供更細緻的梯度。

**4. 探測破解的動態防禦（Adaptive Defense against Probe-Hacking）**
雖然 DAPR 的差分設計對探測破解具穩健性，但隨著模型能力增強，可能出現針對性差分攻擊。未來可建立線上監控機制，偵測 a₁ 與 a₂ 的異常相關性模式，並動態調整探測詞元的隨機化策略。

**5. 理論分析與收斂保證**
對 OGAR 的參數自由特性與 DAPR 的差分估計進行形式化分析，證明其在特定馬可夫決策過程（Markov Decision Process, MDP）變體下的收斂性與方差界限，並探討其與反事實信用分配（counterfactual credit assignment）的理論關聯。

## 實務應用指南

### 適用場景

1. **工業視覺檢測與維修輔助**：在精密製造或設備維護場景中，代理需要透過裁切、縮放或熱力圖分析來定位微小瑕疵。TACO 能訓練模型只在真正需要放大細節時呼叫視覺工具，避免過度操作導致延遲與算力浪費。
2. **金融文件與醫療影像細粒度問答**：處理發票、合約或 X 光、病理切片時，模型需執行 OCR 或對比度增強等程式碼操作。DAPR 可精確判斷某次影像處理是否真正改變了答案正確性，抑制誤導性的濾波或冗餘的旋轉。
3. **自動化地理空間與遙測分析**：無人機或衛星影像的目標識別任務中，代理可能呼叫地理標記、測量或變化偵測工具。OGAR 確保最終答案的優勢只流向負責的正確工具鏈，避免將功勞錯誤歸給無關的軌跡片段。
4. **科學實驗數據視覺化推理**：在材料科學或生物資訊領域，代理需生成繪圖程式碼並觀察輸出圖表以回答問題。TACO 的兩階段 SFT+RL 流程適合將領域專家的示範軌跡轉化為懂得「適時停手」的自主代理。
5. **智慧零售與倉儲盤點**：透過貨架影像進行庫存計數或商品辨識時，模型可能過度呼叫放大工具檢視標籤。TACO 能學習僅在標籤模糊時啟用放大，降低 API 或邊緣裝置上的工具執行成本。

### 實作前置條件

- **資料**：需要具備可驗證獎勵的多模態問答資料集，每筆資料包含圖像、問題與明確答案；若採用兩階段流程，還需收集高品質的程式碼工具使用軌跡作為 SFT 冷啟動資料。建議至少數千筆帶有細粒度視覺細節的樣本。
- **運算**：需要支援大規模強化學習的 GPU 叢集。GRPO 本身需維護群組採樣與相對優勢估計，加上 TACO 的探測詞元需額外前向傳播，建議配置 A100／H100 等級顯卡，並預留比標準 RLVR 多約 20–30% 的記憶體與運算預算。
- **技能**：團隊需熟悉視覺語言模型的微調、強化學習流程（特別是 GRPO 或 PPO 變體），以及沙箱環境的程式碼執行與安全隔離。此外需具備設計規則式答案檢查器的能力，以支援 DAPR 的差分計算。

### 實作步驟建議

1. **環境與沙箱建置**：先建立安全的程式碼執行沙箱，整合影像處理工具（如裁切、縮放、對比度調整、OCR），並確保工具回傳的視圖能被模型讀取。同時實作規則式答案檢查器，作為可驗證獎勵的來源。
2. **冷啟動監督式微調（SFT）**：收集領域專家或強大教師模型產生的工具使用軌跡，進行 SFT。此階段重點在讓模型學會正確的程式碼生成格式與基礎推理模式，不必過度擔心工具呼叫頻率。
3. **探測機制植入**：在模型推理鏈中插入探測詞元，實作 DAPR 所需的 tool-off（呼叫前）與 tool-on（呼叫後）答案讀取邏輯。確保探測不影響原始推理流程，且能與答案檢查器自動比對。
4. **TACO 強化學習訓練**：以 GRPO 為基底，耦合 DAPR 與 OGAR。對每個工具呼叫計算差分答案探測獎勵（Δ = R(a₂) − R(a₁)），並透過 OGAR 將最終答案優勢按呼叫結果閘控路由到對應詞元片段。監控探測破解現象，必要時調整探測詞元位置。
5. **評估與迭代**：在感知、推理與通用多模態基準測試上評估準確率與工具呼叫效率。觀察四種 OGAR 情境（有用、誤導、正確但冗餘、必要但失敗）的分佈，針對冗餘或誤導呼叫進行資料增強或獎勵係數微調。
6. **部署與持續監控**：上線後持續追蹤工具呼叫頻率、延遲與最終答案正確性。建立回饋迴路，將生產環境中答案可驗證的樣本重新注入訓練管線，進行週期性微調。

### 潛在風險與注意事項

- **探測破解（Probe-hacking）**：模型可能學會操縱探測詞元以獲得虛高的差分獎勵。由於 DAPR 採用「差分」而非「絕對探測分數」，本身具備一定抵抗力，但仍建議定期稽核探測輸出，並將探測詞元置於模型難以直接控制的結構化位置。
- **獎勵稀疏與延遲**：在複雜多步工具呼叫任務中，單次呼叫的貢獻可能難以被立即捕捉。建議從單工具呼叫場景開始驗證，再擴展到多輪對話，並確保答案檢查器的規則足夠細緻。
- **沙箱安全與成本**：程式碼工具代理需執行外部程式碼，存在資安風險。沙箱必須嚴格隔離檔案系統與網路；同時，頻繁的影像處理與探測前向傳播會增加運算成本，需在邊緣部署時評估延遲容忍度。
- **OGAR 閘控誤判**：若答案檢查器本身有雜訊，可能導致 OGAR 錯誤地抑制「必要但失敗」的呼叫，使模型變得過於保守。可引入輕量級的置信度門檻或人類回饋緩衝區作為輔助。
- **領域遷移挑戰**：在醫療或金融等高風險領域，可驗證獎勵的定義可能模糊。需與領域專家共同設計答案檢查器，避免將「部分正確」的答案粗暴地標記為錯誤，導致 DAPR 訊號失真。

### 與其他技術的整合建議

- **與現有 VLM 服務整合**：TACO 可疊加於現有的視覺語言模型（如 Qwen-VL、InternVL 或 GPT-4V 的微調版本）之上，無需修改底層架構，只需在訓練階段加入探測詞元與 OGAR 邏輯。推論時可關閉探測以節省成本。
- **與外部知識庫（RAG）協作**：當代理需要同時查詢結構化資料庫與執行視覺程式碼時，可將資料庫查詢視為另一類「工具呼叫」，擴展 DAPR 的差分邏輯至非視覺工具，統一信用分配框架。
- **與測試時擴展（Test-time Scaling）結合**：TACO 訓練出的模型在部署時可搭配多軌跡採樣與投票機制（如 Best-of-N）。由於 OGAR 已教會模型辨識高貢獻呼叫，測試時的採樣會更聚焦於高品質工具鏈，提升擴展效率。
- **與 MLOps 管線整合**：將沙箱執行日誌、DAPR 差分數值與 OGAR 閘控紀錄匯入監控儀表板（如 Weights & Biases 或 MLflow），以便追蹤每次訓練步驟中工具使用的信用分佈，快速定位冗餘呼叫的樣本。
- **與邊緣運算框架搭配**：若需在資源受限裝置上執行，可將 TACO 訓練後的模型進行量化或蒸餾，並將輕量級影像工具（如 OpenCV 操作）封裝為本地函式庫，僅保留核心 OGAR 邏輯於推論引擎中。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先從「純結果獎勵」與「過程獎勵」的直觀差異開始理解。把 TACO 想像成一位嚴格的教練：它不只看最終答案對錯，還會比較「使用工具前」與「使用工具後」的答案變化，給予每一次工具呼叫具體的評價。閱讀時可聚焦於圖 2 的四種情境分類，暫時跳過 GRPO 的數學推導。
- **AI 工程師**：請重點關注 DAPR 的探測詞元實作細節與 OGAR 的詞元級路由邏輯。論文的核心價值在於提供一個無需外部裁判模型、可自監督運作的訓練流程，這對降低生產環境的 API 成本與延遲至關重要。建議對照論文中的演算法描述，思考如何將其移植到你現有的 RLVR 管線。
- **研究人員**：請深入分析 DAPR 作為「差分估計量」的統計特性，以及 OGAR 與現有逐步獎勵（如 MIG、PACR）在信用分配上的根本差異。論文對探測破解的診斷與防禦提供了有趣的實證觀察，可作為未來設計更強健的過程獎勵的切入點。此外，兩階段 SFT+RL 的收斂行為也值得在更廣泛的代理任務中驗證。
- **產品經理**：請將 TACO 視為一個「提升工具投資報酬率」的訓練方案。它的商業價值在於讓視覺代理學會「精準下刀」——只在有助於答案正確性時才呼叫昂貴的影像處理或程式碼執行。閱讀時請關注實驗章節中關於準確率提升與工具呼叫頻率下降的數據，這些是評估是否值得投入研發資源的關鍵指標。
