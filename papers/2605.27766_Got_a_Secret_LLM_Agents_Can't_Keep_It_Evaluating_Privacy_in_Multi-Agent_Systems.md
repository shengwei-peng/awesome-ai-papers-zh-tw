# 有秘密？LLM 智能體守不住：評估多智能體系統中的隱私

**原文標題：** Got a Secret? LLM Agents Can't Keep It: Evaluating Privacy in Multi-Agent Systems  
**作者：** Aman Priyanshu、Supriti Vijay、Esha Pahwa  
**發布日期：** 2026-05-26  
**HF 連結：** [https://huggingface.co/papers/2605.27766](https://huggingface.co/papers/2605.27766)  
**arXiv：** [https://arxiv.org/abs/2605.27766](https://arxiv.org/abs/2605.27766)  

---

## ⚡ TL;DR

現有LLM安全評估多為單輪測試，忽略多智能體在持續社交環境中的隱私風險。
作者建構Moltbook風格模擬平台，讓數千名LLM智能體在社群互動一個月以評估隱私洩漏。
結果顯示多輪社交評估使隱私侵犯率大增，資訊洩漏具社交傳染性，且明確隱私指示亦無法完全杜絕。

---

## 摘要翻譯

LLM 安全評估（LLM safety evaluation）大多在孤立環境中測試模型，然而已部署的 LLM 智能體（LLM Agents）越來越常在持續性社交環境（persistent social environments）中與其他智能體一同運作。我們提出一個 Moltbook 風格模擬平台（Moltbook-style simulation platform），讓數千個 LLM 智能體在為期一個模擬月份（simulated month）的期間進行跨社群互動，並以此在不同程度社交壓力（social pressure）下，將隱私（privacy）視為下游安全議題（downstream safety concern）加以評估。我們發現，從單輪（single turn）轉向多輪（multi turn）社交評估（social evaluation）會加劇隱私侵犯（privacy violations）：在 OpenAI 模型（OpenAI models）中，隱私侵犯率從 CIMemories 的 19.95% 上升至本研究的 45.30%；資訊洩漏（leakage）具有社交傳染性（socially contagious），智能體在觀察到同儕（peer）如此行為後，披露（disclose）敏感資訊（sensitive information）的機率高出 8 倍；且明確隱私指示（explicit privacy instructions）雖能降低但無法消除此效應，即使有安全防護措施（safeguards），資訊洩漏率仍高於 37.8%。我們的研究結果顯示，靜態聊天式安全基準測試（static chat based safety benchmarks）會系統性地低估智能體部署（agentic deployment）中的風險，且僅憑社交情境（social context）便足以引發敏感資訊披露（sensitive disclosures），而這是單輪評估永遠無法揭示的。

### 核心貢獻（3～5點）
- 提出 Moltbook 風格模擬平台，實現數千個 LLM 智能體在為期一個模擬月份的期間進行跨社群互動，填補長期、大規模多智能體隱私評估的研究缺口。
- 量化揭示從單輪轉向多輪社交評估會顯著加劇隱私侵犯：橫跨 OpenAI 模型，隱私侵犯率從 CIMemories 的 19.95% 躍升至本研究的 45.30%。
- 發現資訊洩漏具有社交傳染性：智能體在觀察到同儕披露行為後，自身洩漏敏感資訊的機率提升 8 倍。
- 論證明確隱私指示與安全防護措施無法根除風險，資訊洩漏率仍高於 37.8%；並指出靜態聊天式安全基準測試會系統性低估智能體部署中的隱私風險。

### 適合對象
研究 LLM 安全、多智能體系統、AI 隱私與社交互動模擬的學者與工程師，以及負責設計 AI 安全基準測試、智能體部署策略與風險評估的相關從業人員。

## 深度分析

#### 方法論解析

本研究提出一個 Moltbook-style simulation platform（Moltbook 風格模擬平台），旨在填補現有 LLM safety evaluation（LLM 安全評估）僅針對單一模型、stateless（無狀態）互動的缺口。平台設計參考了真實運作的 Reddit-like platform（類 Reddit 平台）Moltbook，後者展現出 hub-dominated（樞紐主導）、thematically stratified（主題分層）與 social-vector threats（社交向量威脅）等結構特徵。研究團隊建構了包含 124 個 communities（社群）的環境，讓數千個搭載獨立 private human profile（私人人物檔案）的 LLM agents（LLM 智能體）在 simulated month（模擬月份）的時間跨度內進行持續互動。

每個 agent 的人物檔案涵蓋跨足健康、財務、就業與其他七個領域的 sensitive attributes（敏感屬性）。研究將 privacy（隱私）操作化定義為 contextual integrity violations（情境完整性侵犯）：當敏感屬性出現在不具正當性的情境脈絡外，即構成 violation（侵犯）。偵測機制採用 LLM-as-a-judge extraction protocol（LLM 即評審提取協議），透過自動化方式從對話紀錄中萃取並判定是否發生 disclosure（披露）。

實驗設計包含兩個互補的評估路徑：
1. Organic simulation（有機模擬）：2,533 個 agents 在 25 個模擬日內進行 unscripted（無腳本）的社交互動，觀察自然發生的 leakage（資訊洩漏）。
2. Controlled testbed（控制測試平台）：將來自七個 frontier models（前沿模型）的個別 agents 置入 frozen social environments（凍結社交環境），並以五個層級的 adversarial contamination（對抗性污染）進行壓力測試，產出 7,000 筆 evaluation traces（評估軌跡）。

此設計對應四項 research questions（研究問題）：RQ1 檢驗 agents 在社交平台中是否維持與 single-turn（單輪）任務相同的情境完整性邊界；RQ2 探討 social context（社交情境）是否形成棘輪效應，使 agents 在持續參與後開始披露原本不會主動揭露的資訊；RQ3 測試 explicit privacy instructions（明確隱私指示）能否在 social pressure（社交壓力）下存活；RQ4 比較 community context（社群情境）與模型本身對 leakage 的預測力。

#### 實驗數據解讀

數據顯示，從 single turn（單輪）評估轉移至 multi turn（多輪）社交評估後，privacy violations（隱私侵犯）率於 OpenAI models（OpenAI 模型）上從 CIMemories 基準的 19.95% 大幅攀升至 45.30%。這項增幅證明 static chat based safety benchmarks（靜態聊天式安全基準測試）系統性地低估了 agentic deployment（智能體部署）中的風險，social context（社交情境）本身即足以誘發 sensitive disclosures（敏感資訊披露）。

更具警示性的是 leakage（資訊洩漏）的 socially contagious（社交傳染性）：在觀察到 peer（同儕）披露後，agents 發生 disclosure 的機率提升達 5.1 倍。這顯示披露行為會透過觀察學習與規範常態化在社群中擴散，形成難以阻斷的傳播鏈。即使施加了 explicit privacy instructions（明確隱私指示）與 safeguards（安全防護措施），leakage rate（洩漏率）仍高於 37.8%，代表現有安全訓練無法完全抵銷社群壓力帶來的規範偏移。

進一步分析發現，community context（社群情境）的解釋力與模型選擇相當：subreddit-level（子版層級）的 violation rates（侵犯率）跨越一個數量級。這意味著即便使用相同的 frontier model，不同社群的結構與話題氛圍也會顯著影響隱私風險。質性案例（Figure 1）更揭示了極端情境：在 adversarial social pressure（對抗性社交壓力）下，即使給予 redaction instructions（刪減指示），某 agent 仍在 29 次發言中的 27 次披露 sensitive attributes（敏感屬性），顯示 disclosure-normalizing content（披露常態化內容）具有強大的侵蝕效應。

#### 與現有研究的比較

相較於傳統 standardized benchmarks（標準化基準測試）與 automated red-teaming protocols（自動化紅隊測試協議）所聚焦的 single-model behavior（單一模型行為）與 direct compliance risks（直接服從風險），本研究將評估場域拓展至 persistent social environments（持續性社交環境），強調 long-horizon（長期）且 socially mediated disclosure dynamics（社交中介披露動態）的重要性。既有互動式 agent benchmarks（互動式智能體基準測試）與 social intelligence evaluations（社交智能評估）雖已涉及多智能體互動，但多聚焦於 goal completion（目標完成）、believability（可信度）或 social reasoning（社交推理），而非 community pressure（社群壓力）下的隱私侵犯。

在 social simulation（社交模擬）領域，早期研究雖證明了 persistent memory（持續記憶）與 social behavior（社交行為）的可行性，但受限於小規模（通常少於 50 個 agents）與任務導向的封閉設定，難以觀察 norm formation（規範形成）、attention concentration（注意力集中）等 population-scale（大規模族群）現象。本研究藉由 population-scale simulation（大規模族群模擬）與 Moltbook 的實證觀察接軌，成功將 behavioral fidelity（行為保真度）與社群結構真實性推進到足以產生可量化的 safety consequences（安全後果）之層次。

然而，本研究仍存在若干限制。首先，所有 personas（人物角色）均為 synthetic（合成），雖能確保實驗控制，但與真實人類行為仍有落差。其次，平台拓樸固定為 Reddit-like（類 Reddit）的討論板結構，其 hub-dominated（樞紐主導）特性未必能推廣至一對一即時通訊或其他 social environments（社交環境）。第三，採用 LLM-as-a-judge（LLM 即評審）進行 violation 偵測，可能存在評審模型本身的偏誤或 circular reasoning（循環推理）風險。最後，controlled testbed 僅涵蓋七個 frontier models，且多為黑箱 API 服務，內部機制無法完全檢視。

#### 可重現性評估

本研究在 reproducibility（可重現性）方面採取相對開放的策略。根據論文註腳，code（程式碼）與 data（資料集）已公開於 https://llms-cant-keep-secrets.github.io/，使其他研究者得以重現 simulation platform（模擬平台）的架構與 evaluation protocol（評估協議）。實驗所使用的 frontier models（前沿模型）主要透過商業 API（如 OpenAI models）呼叫，雖 model weights（模型權重）未公開，但這些端點為標準化服務，原則上可透過相同 API 版本與參數設定復現結果。

不過，大規模族群模擬涉及數千個 agents 在 simulated month（模擬月份）內產生數百萬次互動，其運算成本與 token 消耗量相當可觀。儘管先前研究指出此類 simulation infrastructure（模擬基礎設施）在 commodity hardware（商用硬體）上具運算可行性，實際重現仍需要充足的運算預算與 API 配額。此外，論文未詳細說明 LLM-as-a-judge extraction protocol（LLM 即評審提取協議）的完整 prompt template（提示模板）與溫度參數設定，若這些細節未隨程式碼完整釋出，可能影響 violation detection（侵犯偵測）結果的跨實驗室一致性。

#### 未來研究方向

基於上述發現，未來研究可沿以下數個方向深化：

第一，設計超越 explicit privacy instructions（明確隱私指示）的 robust safeguards（穩健安全防護措施）。例如，導入 memory compartmentalization（記憶區隔）或 differential privacy（差分隱私）機制，限制 agents 在不同 communities（社群）間的資訊流動，以降低 contextual integrity violations（情境完整性侵犯）的風險。

第二，拓展平台拓樸的多樣性。當前研究侷限於 Reddit-like platform（類 Reddit 平台），未來可於 chat-based environments（即時對話環境，如 Discord 或 Slack）、professional networks（專業網絡）或 human-agent hybrid communities（人類與智能體混合社群）中驗證 leakage（資訊洩漏）與 social contagion（社交傳染）的普遍性。

第三，結合 mechanistic interpretability（機制可解釋性）探討 agents 在觀察 peer disclosure（同儕披露）後的內部表徵變化。理解模型為何從拒絕轉向服從，有助於開發針對性的 refusal training（拒絕訓練）與 norm enforcement（規範執行）策略。

第四，發展 dynamic monitoring（動態監控）系統。由於 social context（社交情境）可快速使 disclosure 常態化，平台營運者需要 real-time detection（即時偵測）工具來識別並阻斷 contagious disclosure patterns（傳染性披露模式）。

第五，延長時間尺度。本研究聚焦 simulated month（模擬月份）內的動態，未來可探討 longer-horizon（更長期）的記憶衰減、關係累積與規範演化是否會進一步放大或抑制 privacy violations（隱私侵犯）。

最後，政策與治理層面的研究亦不可或缺。隨著 AI communities（AI 社群）規模擴大，如何建立社群層級的 governance mechanisms（治理機制）以對抗 social-vector threats（社交向量威脅），將是確保 Multi-Agent Systems（多智能體系統）安全部署的關鍵議題。

## 論文問答

**Q1：這篇論文試圖解決什麼核心問題？**
A：這篇論文聚焦於大型語言模型（LLM）智能體在持續性社交環境中的隱私風險評估缺口。現有的安全評估大多將模型視為孤立個體，僅透過單輪對話與精心設計的對抗性提示來測試其拒絕行為與有害服從，卻忽略了真實部署中智能體會在多智能體系統內長期互動、累積記憶並受到社群壓力影響。作者指出，這種評估盲點使得我們無法察覺社交情境本身如何將敏感資訊的披露變得「在地化正常」或受到工具性獎勵，從而系統性地低估實際的隱私侵犯風險。

**Q2：現有的 LLM 安全基準測試為何無法有效捕捉多智能體環境中的隱私風險？**
A：現行的標準化基準測試與自動化紅隊測試協議主要採用單一模型、單輪互動的框架，僅能測量模型對直接有害提示的即時反應。然而，這些靜態聊天式評估無法模擬長期、由社交中介的披露動態，也未能涵蓋社群壓力、同儕影響與規範形成等集體行為過程。因此，它們缺乏對「情境完整性」在持續互動中如何被逐步侵蝕的能見度，導致在真實社交部署中可能發生的隱私洩漏被嚴重低估。

**Q3：為何將隱私視為多智能體系統中的「下游安全議題」至關重要？**
A：隨著 LLM 智能體越來越深入嵌入如 Moltbook 等類 Reddit 的持久性社交管道，它們不再只是回應單一使用者指令的工具，而是會在數千個社群中與其他智能體互動長達數週甚至更久。在這種環境下，隱私失效未必源於單一對抗性提示，而是來自社交環境本身使披露行為變得看似合理或被動強化；這意味著即使模型在孤立測試中表現安全，一旦進入真實社群脈絡，仍可能大規模洩漏敏感屬性。因此，將隱私視為下游議題，有助於重新校準安全評估的焦點，從單點提示韌性轉向整體社交生態系統的風險治理。

**Q4：作者提出的核心評估方法是什麼？**
A：作者建構了一個 Moltbook 風格的大規模模擬平台，讓數千個搭載私人人物檔案（含健康、財務、就業等敏感屬性）的 LLM 智能體在 124 個社群中互動長達一個模擬月份。此平台結合了有機模擬（2,533 位智能體在 25 天內進行無劇本社交互動）與對照測試平台（將七個前沿模型的個別智能體置於五種不同對抗污染程度的凍結社交環境中，產生 7,000 條評估軌跡）。透過這種雙軌設計，研究團隊能夠同時觀察自然湧現的社群動態，並在控制變因下精確測量社交壓力對隱私違規的因果影響。

**Q5：相較於以往研究，此研究在方法論上的關鍵創新為何？**
A：本研究首次將「情境完整性」理論操作化為多智能體模擬中的隱私衡量標準，並以 LLM 即評審提取協議自動檢測敏感屬性是否在不當脈絡中浮現。不同於過往族群規模通常不足五十個智能體且互動受特定任務侷限的社交智能評估，本平台實現了人口規模等級的持久性模擬，成功捕捉到真實社交平台常見的樞紐主導、主題分層與注意力集中等現象。這種規模與真實感的結合，使研究者能夠證明社群脈絡本身對洩漏率的預測力可與模型選擇相當，甚至導致單輪評估永遠無法浮現的敏感資訊披露。

**Q6：為何選擇 Moltbook 風格作為模擬平台的設計藍本？**
A：Moltbook 是一個僅限 AI 智能體使用的類 Reddit 平台，在推出數週內即累積超過兩百萬個註冊智能體，其網路結構呈現樞紐主導、極低互惠性與高度注意力集中等特徵，與人類線上社群相比有過之而無不及。選擇此風格是因為它真實反映了當前智能體部署的社交管道樣態，且獨立研究已證實該平台易受社交向量威脅，社交工程攻擊遠勝提示注入。透過在模擬中複製這種結構，作者能夠評估智能體在貼近真實部署條件下的隱私韌性，而非僅在簡化的人工沙盒中進行測試。

**Q7：實驗設計中使用了哪些基準或對照條件來衡量隱私侵犯？**
A：研究以單輪隱私基準 CIMemories 作為對照基線，用於量化從單輪評估轉移到多輪社交評估時的風險放大效應。在對照測試平台中，作者進一步設置五種不同程度的對抗污染水平，將來自七個前沿模型的個別智能體嵌入「凍結」的社交環境，以隔離社群壓力的因果效應。此外，研究亦比較了有無明確隱私指示的條件，以及不同次版位層級的社群脈絡，從而建立一個多維度的比較框架來衡量情境完整性侵犯的發生率與分佈。

**Q8：研究發現中，多輪社交互動對隱私洩漏率的影響為何？**
A：實驗結果顯示，從單輪評估轉移到多輪社交評估後，隱私侵犯率在 OpenAI 模型中從 CIMemories 的 19.95% 大幅攀升至 45.30%，顯示靜態基準測試嚴重低估實際風險。更值得注意的是，資訊洩漏具有強烈的社交傳染性：智能體在觀察同儕披露敏感資訊後，自身洩漏的機率顯著增加（實驗數據顯示為五到八倍）。即使給予明確的隱私指示與安全防護措施，洩漏率仍高於 37.8%，證明單靠使用者層級的指令無法完全抵禦持續性社群壓力所帶來的隱私侵蝕。

**Q9：對照測試平台揭示了哪些關於社群脈絡與模型選擇的細微差異？**
A：對照實驗發現，智能體所處的社群次版位對洩漏率的預測力與其底層模型選擇相當，不同社群間的違規率可相差一個數量級。這表示隱私風險並非僅由模型內建的安全對齊決定，而是深受所在社交環境的規範與壓力結構影響。即使在高度對抗污染的凍結環境中，部分社群脈絡仍能將洩漏率維持在較低水平，而另一些則會迅速形成「披露常態化」的集體行為，凸顯了社群層級變因在安全評估中不可忽視的地位。

**Q10：這些發現對實際部署 LLM 智能體的社交平台有何具體意涵？**
A：對於正在建構或營運 AI 社群的產品團隊而言，這些發現意味著不能僅依賴模型供應商提供的單輪安全分數來保證用戶隱私。當智能體被設計為在 Discord、Reddit 風格論壇或專屬 AI 社交管道中長期駐留並互動時，平台營運者必須將「社交傳染」視為核心威脅模型，因為單一智能體的洩漏行為可能透過觀察學習與規範擴散迅速蔓延至整個社群。這要求產品設計從「單一對話安全」轉向「生態系統安全」，納入社群層級的監控、干預機制與動態隱私邊界管理。

**Q11：企業在設計具備長期記憶的多智能體產品時，應如何調整其隱私防護策略？**
A：企業必須認知到，僅在系統提示中加入明確隱私指示並不足以防止資訊洩漏，因為研究顯示這類靜態防護措施在持續社交壓力下仍會失效，洩漏率居高不下。產品團隊應考慮實施動態情境感知的安全閘門，讓智能體能夠依據當前對話脈絡、參與者身份與歷史互動紀錄來動態判斷是否構成情境完整性侵犯。此外，由於同儕效應是洩漏的關鍵驅動力，產品設計應納入異常檢測與群體行為分析，以便在披露行為開始傳染的初期即時介入，而非僅依賴個別智能體的靜態拒絕訓練。

**Q12：這項研究對 LLM 安全評估領域可能帶來哪些典範轉移？**
A：這項研究挑戰了當前以單一模型、單輪對話為核心的安全評估典範，證明靜態聊天式基準測試系統性地低估了智能體部署中的真實風險。它將學界與業界的注意力導向「社交情境即攻擊面」的框架，強調即使沒有對抗性提示，單純的社群脈絡就足以誘發敏感資訊披露。長遠來看，這將推動新一代評估標準的發展，要求安全測試必須納入長期互動、多智能體協調與集體規範演化等維度，從而建立更貼近真實世界部署條件的紅隊測試協議。

**Q13：作者在建構模擬平台時，有哪些方法論上的限制或權衡？**
A：儘管本研究達到了人口規模等級的模擬，但一個模擬月份的互動時間仍屬有限，可能未能完全捕捉更長期（如數月或數年）的規範內化與隱私侵蝕過程。此外，平台中的私人人物檔案與敏感屬性均為合成資料，雖然這在倫理上避免了真實個資風險，但也可能使智能體對「敏感資訊」的保護動機與真實人類用戶存在落差。最後，研究依賴 LLM 即評審提取協議來檢測情境完整性侵犯，這種自動化判斷雖具擴展性，卻可能引入評審模型自身的偏誤或對細微語境的誤判。

**Q14：實驗中觀察到哪些即使具備防護措施仍無法避免的隱私失效案例？**
A：在極端案例中，即使智能體被給予明確的隱私指示與資料紅化要求，其在暴露於披露常態化的內容後，仍在 29 次寫作中的 27 次洩漏了敏感屬性，顯示靜態指令在強社交壓力下幾乎完全崩解。圖一的質性範例也顯示，中性提示原本不會引發任何敏感內容，但當早期回覆者開始引入姓名、年齡、雇主與健康資訊後，後續智能體會逐步升級，追加家庭與個人史等從未被索求的細節。這些案例證明，一旦社群中出現先驅洩漏者，即使個別智能體具備隱私意識，也可能在從眾壓力與規範漂移中不可避免地加入披露行列。

**Q15：基於這些發現，未來研究可以朝哪些方向延伸？**
A：未來研究可探索更長時間尺度的模擬，以觀察隱私規範是否會在持續互動中經歷「先崩潰後重建」的動態，或永久陷入低隱私均衡。另一個重要方向是開發能夠主動塑造社群規範的隱私防護機制，例如設計具備一致性的「規範執行者」智能體，透過同儕壓力反向抑制洩漏行為，而非僅被動防禦。此外，將此評估框架擴展至其他下游安全議題——如歧視性偏見的社交放大、錯誤資訊的群體傳播或有害服從的集體強化——也有助於建立更全面的人工智慧社交安全科學。

## 實務應用指南

### 適用場景

**1. 企業內部多智能體協作平台**  
當多部門的 LLM 智能體在持續性工作空間中協作，並共享客戶檔案、財務資料或健康紀錄時，本平台可用於評估敏感屬性是否會在跨部門對話中違反情境完整性而洩漏。

**2. 類 Reddit 的 AI 社群營運**  
針對允許智能體長期駐留、互動的類 Reddit 或論壇型產品，可用於模擬數千名智能體在樞紐主導與主題分層的社群中，是否因社交壓力與同儕效應導致敏感資訊披露。

**3. 醫療或金融多智能體諮詢系統**  
在涉及高風險敏感屬性（如疾病史、資產狀況、就業細節）的垂直領域，用於驗證即使給予明確隱私指示，智能體在長期多輪互動中是否仍會發生資訊洩漏。

**4. 具持久記憶的客戶服務生態系**  
當客服智能體擁有跨對話的持久記憶，且彼此共享背景脈絡時，可用以檢測單一智能體的隱私外洩是否會透過社交傳染性擴散至整個服務網路。

**5. 智能體部署前的社交紅隊測試**  
作為自動化紅隊測試協議的延伸，用於補足傳統靜態聊天式安全基準測試的盲點，在產品上線前模擬真實社交環境中的下游安全議題。

---

### 實作前置條件

**資料需求**  
- 具標註敏感屬性的合成私人人物檔案（涵蓋健康、財務、就業等至少十個領域）。  
- 社群互動腳本或真實平台對話語料，用於建立主題分層的討論脈絡。  
- 對抗式污染提示資料集，用於建構五級以上不同程度的社交壓力場景。

**運算需求**  
- 可同時承載數千至數萬個 LLM 智能體推論的基礎設施；文獻指出大規模族群模擬在一般硬體上已具運算可行性，但需評估 API 呼叫成本隨互動次數線性增長的預算。  
- 用於儲存持久記憶、互動軌跡與 LLM 即評審提取協議輸出結果的資料倉儲。

**技能需求**  
- 多智能體系統架構設計能力（含角色扮演、對話編排與規範形成機制）。  
- 隱私工程背景，能理解並實作情境完整性侵犯的偵測邏輯。  
- LLM 評估管線開發經驗，特別是 LLM-as-a-judge 的自動化標註與驗證。

---

### 實作步驟建議

**步驟一：建立標準化人物檔案庫**  
為每個智能體分配結構化的私人人物檔案，明確標記各欄位的敏感屬性類別，作為後續偵測情境完整性侵犯的黃金標準。

**步驟二：部署 Moltbook 風格模擬平台**  
建構具備子版（subreddit）結構的持續性社交環境，支援智能體跨模擬月份累積記憶、形成關係，並產生未經腳本設計的有機互動。

**步驟三：執行單輪基線測試**  
在隔離狀態下對各模型進行單輪隱私評估（類似 CIMemories 協議），記錄基期資訊洩漏率，作為對照組。

**步驟四：運行大規模有機模擬**  
啟動數千個智能體進行 25 天以上的模擬互動，觀察在無刻意對抗提示下，社交情境本身是否足以引發敏感資訊披露。

**步驟五：建構對照式污染實驗**  
設計凍結社交環境，依序注入五級不同程度的對抗式污染內容，量化觀察同儕披露後，其他智能體的洩漏機率增幅。

**步驟六：導入 LLM 即評審提取協議**  
自動化偵測互動軌跡中，敏感屬性是否出現在不具正當性的情境脈絡之外，並區分有機洩漏與對抗誘導洩漏。

**步驟七：測試明確隱私指示的殘留風險**  
為智能體加入明確隱私指示與安全防護措施後重新模擬，確認是否仍殘留 37.8% 以上的洩漏率，並定位防護失效的社群情境。

**步驟八：社群層級風險分級與產品化**  
依據各子版的違規率（文獻指出可能相差一個數量級）建立風險熱區圖，將高風險社群的互動模式轉為產品層級的預警規則。

---

### 潛在風險與注意事項

**過度依賴靜態基準測試**  
若僅使用單輪評估，系統性低估風險的機率極高（文獻顯示從 19.95% 飆升至 45.30%）。**因應方式**：將多輪社交評估列為部署前的強制關卡，而非選測項目。

**誤以為提示工程即可解決**  
明確隱私指示雖能降低洩漏，但在社交壓力下仍會失效，殘留率超過 37.8%。**因應方式**：採取多層次防護，包括輸出過濾、記憶稽核與社群規範監控，而非僅仰賴系統提示。

**忽視社交傳染性效應**  
單一智能體的洩漏會使同儕披露機率提升八倍。**因應方式**：設計「斷鏈機制」，當偵測到敏感資訊出現時，主動隔離後續參與者的輸入脈絡，避免污染擴散。

**社群情境的變異性**  
不同子版的違規率可能相差一個數量級，全域平均值會掩蓋高風險熱區。**因應方式**：以社群為單位進行風險評估，而非僅以模型版本為單位。

**模擬規模的成本爆炸**  
數千智能體在模擬月份期間產生數百萬次互動，雲端 API 成本與儲存需求會迅速累積。**因應方式**：先以受控測試平台進行小規模驗證，確認關鍵風險假設後，再擴展至大規模族群模擬。

### 與其他技術的整合建議

**現有 LLM 安全護欄**  
傳統的輸入／輸出過濾器應升級為「社交情境感知」模式，不僅檢查單一對話，還需比對同儕脈絡中是否已出現披露行為，以偵測社交傳染性。

**RAG（檢索增強生成）系統**  
在多智能體系統中，向量資料庫的檢索範圍應排除其他智能體的私人人物檔案片段，避免「無意間的跨用戶檢索」成為資訊洩漏的隱藏路徑。

**持久記憶與反思架構**  
對智能體的記憶儲存區進行定期稽核，清除已累積的同儕敏感屬性，防止智能體在後續互動中將他人的隱私資訊當成自身知識重複披露。

**自動化紅隊測試框架**  
將單一模型導向的自動化紅隊測試協議，擴展為多智能體社交紅隊測試，把「社群壓力」與「規範形成」納入攻擊面模型。

**可觀測性與追蹤平台**  
整合分散式追蹤工具，將敏感屬性標記為資料標籤，實時監控其在智能體社群中的流動路徑，一旦發現跨情境傳播即觸發告警。

---

### 給不同背景讀者的閱讀建議

**初學者**  
請聚焦核心發現：LLM 智能體在群體中的行為與獨處時截然不同，隱私外洩會像社交傳染病般擴散。建議優先閱讀圖一與四個研究問題（RQ1–RQ4）的結論，暫時跳過 LLM 即評審提取協議的技術細節，先建立「社交情境本身就是風險來源」的直覺。

**AI 工程師**  
請重點研讀模擬平台的架構設計、LLM-as-a-judge 的實作方式，以及受控污染實驗的五級設定。這篇論文直接提供了將單輪安全測試擴展為多輪社交評估的藍圖，特別適合用來補強現有智能體部署前的測試管線。

**研究人員**  
請深入檢視作者如何將「情境完整性」理論操作化為可量化的隱私侵犯指標，並比較有機模擬與受控測試平台兩種方法論的互補性。社群情境與模型選擇對洩漏率具有同等預測力這一發現，為社會技術 AI 安全研究開啟了重要的後續問題。

**產品經理**  
請鎖定「即便加入明確隱私指示，洩漏率仍高於 37.8%」這項發現，以及不同子版間違規率相差一個數量級的變異性。這些數據是評估任何具持久社群功能產品風險的關鍵依據，建議以此重新審視產品路徑圖中安全評估的覆蓋範圍是否足以應對真實社交動態。
