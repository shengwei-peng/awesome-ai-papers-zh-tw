## ⚡ TL;DR

現有多模態設計系統無法將回饋轉化為可複用的設計知識，難以持續自我改進。
提出 AutoDesign，以雙層迴圈讓程式碼代理依試跑回饋遞迴最佳化設計 Harness。
PosterBench獲78.32分，勝過Claude Design，人類盲測偏好度最高。

## 摘要翻譯

將多模態來源轉換為濃縮且結構化的媒體輸出，本質上可視為一個以模型-Harness 系統（Model-Harness System）為核心的長期程代理式設計（Long-Horizon Agentic Design）過程。雖然理想的 Harness 系統應與人類設計先驗（Human Design Priors）對齊，並透過經驗探索（Empirical Exploration）累積可重複使用經驗（Reusable Experience），以推動遞迴自我改進（Recursive Self-Improvement），但現有典範仍屬靜態（Static Paradigms），難以滿足此要求。本論文提出 AutoDesign，一個與人類設計先驗對齊的框架，其中 Meta-Harness 最佳化器（Meta-Harness Optimizer）引導程式碼代理（Code Agent）根據 Rollout 回饋（Rollout Feedback）遞迴改進 Harness。為了具體實現並評估此框架，我們聚焦於學術論文轉海報生成（Paper-to-Poster Generation）任務，並提出 PosterBench，其包含一個涵蓋五個學科領域（Five Disciplines）、共 100 篇論文的主賽道（Main Track），以及用於受控評估（Controlled Evaluation）的共享 10 篇論文子集 PosterBench-mini。在 PosterBench 主賽道上，AutoDesign 獲得最高分 78.32，領先封閉原始碼商業系統 Claude Design 達 7.45 分。在七種受控的程式碼代理–模型配置中，整合學習得到的 DesignHarness 一致地提升效能，將平均 PosterBench 分數（PosterBench Score）從 54.99 提升至 67.39（+12.4%）。在完全自主的長期程代理式設計迴圈中，系統於 40 分鐘內執行 253 次工具呼叫與 11 輪編輯，花費低於 3 美元，並在人類評估中達到平均會議海報品質。一項系統盲測的人類研究進一步顯示，AutoDesign 在所有受評系統中獲得最高的人類偏好。

### 核心貢獻（3～5點）
- 提出 AutoDesign 框架，透過 Meta-Harness 最佳化器（Meta-Harness Optimizer）引導程式碼代理（Code Agent）依 Rollout 回饋（Rollout Feedback）遞迴改進 Harness，使模型-Harness 系統（Model-Harness System）能對齊人類設計先驗（Human Design Priors）並累積可重複使用經驗（Reusable Experience）。
- 建立論文轉海報生成（Paper-to-Poster Generation）評測基準 PosterBench，包含涵蓋五個學科領域（Five Disciplines）、共 100 篇論文的主賽道（Main Track），以及用於受控評估（Controlled Evaluation）的 PosterBench-mini。
- 在 PosterBench 主賽道上取得 78.32 分，超越 Claude Design 7.45 分；在七種受控配置中，整合學習得到的 DesignHarness 使平均 PosterBench Score 從 54.99 提升至 67.39（+12.4%）。
- 展示完全自主的長期程代理式設計（Long-Horizon Agentic Design）迴圈可在 40 分鐘、253 次工具呼叫、11 輪編輯與低於 3 美元成本下達到平均會議海報品質，並獲得最高人類偏好。

### 適合對象
適合對自動化設計、多模態內容生成、長期程代理式 AI、模型-Harness 系統、版面與海報生成，以及人機協同設計有興趣的研究者與工程師；亦特別適合希望建構可透過經驗持續自我改進之程式碼代理系統的開發者。

## 深度分析

#### 方法論解析

AutoDesign 的核心貢獻在於將「人類對齊的設計先驗（human-aligned design priors）」轉化為一個可遞迴自我改進（recursive self-improvement）的 **meta-harness optimization** 問題。具體而言，系統並非僅針對單一輸入產出單一海報，而是把「設計 harness」本身視為最佳化標的，透過外層迴圈持續改進內層的設計代理流程。整體架構可拆解為以下幾個關鍵機制：

1. **雙層迴圈架構（two nested loops）**
   - **內層迴圈（inner loop）**：即 **DesignHarness**，負責將多模態來源（此處為論文 PDF）轉換成可編輯的中間產物（如 HTML），並在 **critic feedback** 的引導下迭代修訂，最終輸出可視、可讀的最終成品。
   - **外層迴圈（outer loop）**：即 **meta-harness optimizer**，負責在多個設計任務上執行內層 harness、收集 rollout feedback、評估輸出品質，並指導 **code agent** 對 DesignHarness 的某個功能元件提出有界更新（bounded update）。

2. **以人類偏好為基礎的評估器初始化（evaluator initialization）**
   外層迴圈首先利用「已標註的參考成品（annotated reference artifacts）」建立一個與人類偏好對齊的評估器。這個評估器後續作為自動化回饋來源，讓整個最佳化過程無需持續人工介入即可進行。

3. **有界更新與接受閘門（acceptance gate）**
   為避免過度擬合（overfitting）與災難性更新，每一次 code agent 提出的 harness 修改都必須通過接受閘門：只有在訓練集（training set）上表現提升，且未在開發集（development set）上退化的更新才會被採納。這種機制類似於軟體工程中的回歸測試（regression testing），確保經驗累積是穩定且可重複使用（reusable experience）的。

4. **DesignHarness 的功能元件**
   雖然論文未詳盡列出所有元件，但從圖 3 與描述可推知 DesignHarness 至少包含：
   - **Context & Memory（上下文與記憶）**：儲存 rollout trajectory 與歷史回饋。
   - **Orchestration（編排）**：調度工具與規格（tools & specs）。
   - **Execution Runtime（執行環境）**：將中間產物渲染為可視成品。
   - **Evaluator & Feedback Anchors（評估與回饋錨點）**：涵蓋 faithfulness（忠實度）、readability（可讀性）、aesthetics（美學）、layout（版面）、coverage（覆蓋率）、density（資訊密度）等維度。

5. **程式碼代理作為最佳化器（code agent as optimizer）**
   不同於傳統 prompt engineering 或人工調整 workflow，AutoDesign 讓 code agent 直接讀寫 harness 的程式碼。這使得改進不僅限於提示詞層級，而是可以觸及工具選擇、編排邏輯、後處理規則等結構性設計。

整體而言，AutoDesign 的方法論把「設計」從一次性生成任務提升為「系統層級的長期程代理式設計（long-horizon agentic design）」：透過經驗探索（empirical exploration）累積可重複使用的設計知識，並以人類設計先驗為導向進行遞迴自我改進。

#### 實驗數據解讀

論文在 **PosterBench** 上進行評估，該基準包含：
- **Main Track**：100 篇論文，橫跨五個學科領域。
- **PosterBench-mini**：10 篇論文的共享子集，用於受控評估（controlled evaluation）。

評估採用七維評分標準（seven-dimensional rubric），結合規則式演算法檢查、VLM（vision-language model）判斷，以及兩者並用的混合方法。以下針對關鍵數據進行解讀：

1. **PosterBench-mini 上的受控實驗**
   - 在七種不同的 **code agent / model** 配置下，加入學習得到的 **DesignHarness** 後，平均 **PosterBench Score** 從 54.99 提升至 67.39，進步幅度達 **+12.40 分**。
   - 這表示 DesignHarness 所累積的設計先驗具有跨模型遷移性：無論底層 code agent 為何， harness 的改進都能穩定提升輸出品質。這驗證了「可重複使用經驗」的價值，而非僅是特定模型與提示詞的組合。

2. **PosterBench Main Track 上的整體表現**
   - AutoDesign 獲得 **78.32** 的最高分。
   - 在相同配置（Claude Code + Claude 4.8）下，領先封閉源商業系統 **Claude Design** 達 **7.45 分**。
   - 這顯示 AutoDesign 不僅在學術基準上表現優異，也能超越現有商業產品，特別是在需要長期程規劃與迭代修訂的論文轉海報任務上。

3. **成本與效率**
   - 在完全自主的長期程迴圈中，AutoDesign 可在 40 分鐘內執行 **253 次 tool calls** 與 **11 次編輯回合（editing turns）**，每張海報成本低於 **3 美元**。
   - 使用 **LongCat-2.0** 搭配 DesignHarness 時，每張海報僅約 **0.27 美元**，即可達到 55.13 分。
   - 這說明該框架在實務部署上具有可接受的經濟性與時間效率，對於需要大量產出海報的研究機構或會議而言具吸引力。

4. **人類偏好研究（system-blind human study）**
   - 在 933 份有效成對比較中，AutoDesign 的 **Bradley–Terry** 偏好估計值為 **64.0%**（95% 信賴區間：55.2–77.8%），為所有受測系統中最高。
   - 當兩張海報的 PosterBench 分數差距超過 20 分時，受試者選擇 PosterBench 較高分海報的比例達 **74.4%**。
   - 這兩項結果共同說明：PosterBench 的自動評分與人類偏好具有高度一致性，且 AutoDesign 的優勢不僅反映在自動指標上，也獲得真實人類的青睞。

5. **長期程最佳化的規模**
   - 論文提到在 7 天的演化軌跡中，AutoDesign 呼叫了 **224 個 subagents**，記錄至少 **123 次遞迴迭代**，並累積 **54 次 harness 更新**。
   - 這顯示 meta-harness optimization 是一個需要大量計算與試錯的過程，但也證明系統能持續從 rollout feedback 中提煉出持久的設計知識。

綜合來看，實驗數據強而有力地支持了 AutoDesign 的三項主張：(1) 學習得到的 harness 可跨模型提升品質；(2) 自動評估與人類偏好高度一致；(3) 整體流程在成本與時間上具備實用性。

#### 與現有研究的比較

AutoDesign 與現有多模態設計系統相比，主要差異在於它把「設計知識」從短暫回饋轉化為持久、可執行的系統能力。以下從幾個面向進行比較：

1. **相較於單次生成與修訂系統**
   現有許多系統（如 Madaan et al., 2023）僅在回應層級進行修訂：針對當前輸出產生一次改進。這類方法缺乏跨樣本的記憶累積，無法將「這次失敗的經驗」轉化為「下次遇到類似情況時的預防機制」。AutoDesign 透過外層迴圈把這些經驗寫入 harness，實現真正的可重複使用經驗。

2. **相較於具備記憶的代理系統**
   近年來的 agentic 系統（如 Shinn et al., 2023；Wang et al., 2023）開始保留 reflections、skills 或任務經驗。然而，這些記憶通常以自然語言或向量記憶形式存在，未必能直接轉化為可執行的設計策略。AutoDesign 則讓 code agent 直接修改 harness 程式碼，使累積的知識具備可執行性與結構性。

3. **相較於商業系統 Claude Design**
   Claude Design 是封閉源商業系統，雖然具備強大的生成與編輯能力，但其設計 workflow 本質上是靜態典範（static paradigm）：不會因為處理更多論文而持續自我改進。AutoDesign 在相同模型配置下超越 Claude Design 7.45 分，顯示 meta-harness optimization 能帶來顯著的結構性優勢。

4. **相較於現有 paper-to-poster 基準**
   現有基準（如 Wang et al., 2024；Jaisankar et al., 2025；Pang et al., 2025；Sun et al., 2026；Vinaykumar et al., 2026）多聚焦於版面、抽取、忠實度或視覺品質等單一面向。PosterBench 則提出七維綜合評估，並結合規則檢查與 VLM 判斷，填補了任務層級評估的缺口。

**限制與潛在弱點**

儘管成果顯著，AutoDesign 仍存在若干限制：
- **對參考成品與評估器的依賴**：外層迴圈需要高品質的 annotated reference artifacts 來初始化 evaluator。若參考成品本身有偏誤或涵蓋不足，學習到的設計先驗也可能帶有偏誤。
- **過度擬合開發集的風險**：雖然有 acceptance gate 把關，但長期程最佳化仍可能在開發集上過度調整，特別是當 harness 更新次數多達 54 次時。
- **計算與時間成本**：7 天、224 個 subagents、123 次迭代對於一般研究團隊而言門檻不低，雖然單次海報生成成本低，但 harness 學習階段的成本可能相當可觀。
- **任務特定性**：論文以論文轉海報為實例，雖然框架宣稱可泛化至多模態設計，但其他領域（如影片、網頁）的設計先驗與評估維度差異甚大，尚需更多實證。
- **VLM 評判的局限性**：部分評分依賴 VLM 判斷，而 VLM 對於細微排版、學術正確性或文化差異的感知可能不如人類敏銳。

#### 可重現性評估

可重現性（reproducibility）是評估任何 AI 研究的重要面向。根據目前提供的摘要與引言，論文對於以下項目的公開程度尚不明確：

1. **原始碼（source code）**
   目前未提及是否公開 AutoDesign 的實作程式碼、code agent 的提示詞模板，或 meta-harness optimizer 的具體演算法細節。若未開源，其他研究者將難以完全重現其 harness 學習流程。

2. **資料集（datasets）**
   PosterBench 與 PosterBench-mini 的論文來源、授權狀態、參考海報標註方式，以及評分腳本是否公開，目前資訊有限。由於涉及學術論文 PDF，版權與授權問題可能影響資料集的開放程度。

3. **模型權重與學習產物**
   論文提到最終產出為 **DesignHarness**，這是一套可執行的程式碼/規則/流程，而非傳統神經網路權重。因此「模型權重」在此脈絡下較不適用，但 harness 的最終版本是否釋出，仍是可重現性的關鍵。

4. **評估協定（evaluation protocol）**
   PosterBench 的七維評分標準與評分流程若能公開，將有助於社群進行公平比較。目前僅知結合規則檢查與 VLM 判斷，但具體 prompt、權重、閾值等細節未明。

5. **成本與執行日誌**
   論文提供了 tool calls 數量、editing turns、時間與成本等數據，這對於評估實用性很有幫助。若能進一步公開 rollout trajectory 或 harness 更新日誌，將大幅提升研究的可檢驗性。

**綜合評估**：目前 AutoDesign 的可重現性處於「中等不確定」狀態。方法論描述相對完整，但實作細節、資料集與最終 harness 的公開與否，將決定社群能否快速跟進與驗證。建議作者未來釋出：
- 核心 framework 的開源實作；
- PosterBench 的評估腳本與至少部分公開論文子集；
- DesignHarness 的最終版本或更新歷史；
- 詳細的超參數與 acceptance gate 設定。

#### 未來研究方向

AutoDesign 為長期程代理式設計開啟了多條值得探索的研究路徑：

1. **跨設計任務的泛化**
   將框架從論文轉海報擴展至網頁、簡報、影片、資訊圖表（infographics）等其他多模態設計任務。不同任務的設計先驗差異極大，需要發展任務無關的 meta-harness optimization 機制，或設計可遷移的跨任務設計元件。

2. **線上持續學習（online continual learning）**
   目前 AutoDesign 似乎以離線批次方式進行 harness 學習。未來可研究如何在實際部署中持續收集使用者回饋，並即時更新 harness，同時避免災難性遺忘（catastrophic forgetting）與偏誤累積。

3. **人機協同的最佳化迴圈**
   雖然 AutoDesign 已支援 optional human guidance，但未來可強化 human-in-the-loop 機制，例如讓設計師標註局部偏好、提供風格參考，或介入 acceptance gate 的決策，使系統更符合個人化與組織化需求。

4. **多目標最佳化與可解釋性**
   設計品質涉及忠實度、美學、可讀性、資訊密度等多個可能互相衝突的目標。未來可引入 Pareto 最佳化或明確的權重學習機制，並提升每一次 harness 更新的可解釋性，讓使用者理解「為何系統做了這項改變」。

5. **降低學習階段的成本與延遲**
   7 天、224 個 subagents 的學習過程成本高昂。未來可研究更高效的搜尋策略，例如利用 surrogate model、少量樣本學習（few-shot learning）或模擬環境，以減少真實 rollout 的次數。

6. **結合生成式視覺模型**
   目前 DesignHarness 主要輸出 HTML 等結構化媒介。未來可整合 diffusion models 或 layout generative models，讓 harness 能直接操作像素級視覺元素，進一步提升美學表現與排版多樣性。

7. **設計倫理與偏誤審計**
   隨著系統自動累積設計先驗，必須審計這些先驗是否內含文化偏誤、性別偏誤或學術領域偏誤。建立設計 harness 的公平性評估與偏誤矯正機制，將是實務部署前不可或缺的環節。

8. **開放生態系與標準化基準**
   推動 PosterBench 成為社群標準，並建立開源的 harness 更新交換格式，讓不同研究團隊能共享學習到的設計元件，加速整個領域的累積式進步。

總結而言，AutoDesign 不僅提出了一個具體的論文轉海報系統，更重要的是確立了「以 meta-harness optimization 進行遞迴自我改進」的研究典範。未來若能解決可重現性、成本與跨任務泛化等挑戰，該框架有望成為多模態代理式設計領域的重要基礎建設。

## 論文問答

**Q1：AutoDesign 試圖解決的核心問題是什麼？**

A：AutoDesign 要解決的是如何將多模態輸入轉換為結構化、人類對齊的設計成品這類長期程代理式設計問題。現有系統雖然能透過生成、批評與修改來產出結果，卻往往把每次的人類回饋當成一次性訊號，無法累積成可重複使用的設計知識。AutoDesign 因此提出一個能夠遞迴自我改進的框架，讓系統在試跑與評估中持續學習人類設計先驗，並把這些經驗轉化為生產系統的持久能力。

**Q2：為什麼現有的多模態設計系統被認為不足？**

A：現有典範大多停留在靜態的生成—批評—修改循環，雖然能在單次任務中修正輸出，卻無法把成功或失敗的經驗保留下來供未來任務使用。換句話說，它們把人類對齊的設計先驗當成短暫訊號，而不是可累積的設計知識。這導致系統無法像人類創作者一樣，隨著實作經驗不斷成長，最終限制了長期程設計任務的品質與效率。

**Q3：為什麼選擇「論文轉海報生成」作為實例化任務？**

A：論文轉海報生成是一個具有代表性的長期程設計任務，因為它需要從長篇、多模態的科學文獻中萃取證據、組織結構，並濃縮成單張可讀且視覺連貫的海報。這個任務同時考驗來源忠實度、資訊密度與版面美學，正好涵蓋了人類設計先驗的多個面向。此外，海報有明確的評估維度與人類偏好標準，適合用來驗證 AutoDesign 是否能持續學習並產出符合會議品質的成品。

**Q4：什麼是 Meta-Harness Optimization，AutoDesign 如何實現它？**

A：Meta-Harness Optimization 是把設計 harness 本身當成最佳化對象，而不是只最佳化單一輸出成品。AutoDesign 透過外層的 meta-harness optimizer 在多個任務上收集 rollout 回饋，辨識重複出現的失敗模式，再指導程式碼代理對當前 harness 的某一功能元件提出有限度的更新。為了避免過擬合，每次更新都會經過 acceptance gate 檢驗，只有在訓練集表現提升且開發集未下降時才會被納入 DesignHarness。

**Q5：AutoDesign 的兩個巢狀迴圈各自扮演什麼角色？**

A：內層迴圈是 DesignHarness，負責把來源內容轉換成可編輯的設計成品，並在批評者回饋下反覆修訂。外層迴圈是 meta-harness，負責在多個設計任務上執行內層 harness、評估其輸出，並根據評估結果改進 harness 本身。這種雙層結構讓系統既能針對單一樣本進行精修，也能跨樣本累積可重複使用的設計經驗，並可選擇性地加入人類引導。

**Q6：Acceptance Gate 在系統中的作用是什麼？**

A：Acceptance Gate 是一道防止過擬合的守門機制，用來決定程式碼代理提出的 harness 更新是否應該被接受。它要求更新必須同時提升訓練集表現，且不能損害開發集表現，確保學到的設計先驗具有跨樣本的泛化能力。透過這道閘門，AutoDesign 能把穩定且有用的修改累積成最終可執行的 DesignHarness，而不是盲目堆疊針對特定樣本的捷徑。

**Q7：PosterBench 是什麼，為什麼需要建立這個基準？**

A：PosterBench 是專為論文轉海報任務設計的綜合評測基準，包含 100 篇論文的主賽道與 10 篇論文的 PosterBench-mini 受控子集。它的七維評分規則結合了規則式演算法檢查、視覺語言模型判斷以及兩者並用的混合方法，能同時衡量來源忠實度、科學資訊密度與渲染可用性。現有基準往往只關注版面、萃取或視覺品質等單一面向，PosterBench 填補了全面性任務級評估的缺口。

**Q8：AutoDesign 在實驗中取得了哪些關鍵量化結果？**

A：在 PosterBench Main Track 上，AutoDesign 獲得 78.32 分，比同配置下的商業系統 Claude Design 高出 7.45 分。在 PosterBench-mini 上，把學習到的 DesignHarness 接到七種不同的程式碼代理模型配置後，平均 PosterBench Score 從 54.99 提升到 67.39，進步了 12.40 分。此外，使用 DesignHarness 的 LongCat-2.0 每張海報成本僅約 0.27 美元，顯示該方法在高效能的同時也具備實用成本優勢。

**Q9：受控實驗告訴我們什麼？**

A：受控實驗顯示，無論在七種程式碼代理模型配置中的哪一種，整合學習到的 DesignHarness 都能穩定提升表現。這說明 DesignHarness 中累積的設計先驗具有跨模型遷移性，並非只依賴特定底層模型。同時，這也證明了 meta-harness optimization 確實能從 rollout 回饋中萃取出可重複使用的設計知識，並轉化為系統層級的持續改進。

**Q10：AutoDesign 在實際海報製作中的可行性如何？**

A：在完全自主的長期程迴圈中，AutoDesign 能在 40 分鐘內執行 253 次工具呼叫與 11 輪編輯，整體花費不到 3 美元，並達到人類評估中平均會議海報的品質。這大幅降低了高品質海報製作所需的時間與手動工作量。對於研究者與設計師而言，這代表未來可以快速從論文產出可使用的海報草稿，並把精力集中在更高層次的創意決策上。

**Q11：人類評估如何驗證自動評分指標？**

A：系統盲測研究顯示，AutoDesign 在 933 份有效成對比較中獲得最高的 Bradley–Terry 偏好估計值 64.0%，95% 信賴區間為 55.2% 至 77.8%。當兩張海報的 PosterBench 分數差距超過 20 分時，參與者有 74.4% 的機率偏好 PosterBench 分數較高的那一張。這說明 PosterBench 的自動評估指標與人類偏好高度一致，也進一步確認 AutoDesign 產出的海報確實更符合人類設計先驗。

**Q12：AutoDesign 對多模態設計領域可能帶來什麼更廣泛的影響？**

A：AutoDesign 的框架不僅適用於海報生成，也可擴展到網頁、簡報、影片等其他需要多模態輸入轉換為人類面向成品的设计任務。它把傳統靜態的模型-harness 系統轉變為能遞迴自我改進的系統，讓設計知識可以隨著使用持續累積。長遠來看，這有助於降低專業設計門檻、減少重複勞動，並讓更多領域的使用者能夠產出高品質、人類對齊的設計成品。

**Q13：AutoDesign 有哪些已經存在或可以推論的限制？**

A：首先，評估器的初始化依賴於人工標註的參考成品或自然語言引導，這在某些領域可能取得不易。其次，meta-harness optimization 需要多次 rollout 與子代理呼叫，整體計算成本與時間雖然已經壓低，但對於即時應用仍可能偏高。最後，acceptance gate 依賴訓練集與開發集的表現，若開發集規模不足或分佈代表性有限，可能會拒絕真正有用的更新。

**Q14：AutoDesign 可能出現哪些失敗案例？**

A：當論文中包含複雜圖表、特殊數學式或高度領域專屬的視覺慣例時，DesignHarness 可能無法正確理解或渲染。此外，若某些設計先驗在訓練資料中過度集中，系統可能會過度擬合評分規則，產生分數高但視覺上不自然的海報。還有一種情況是，跨學科的美學偏好差異很大，從某一領域學到的版面策略未必能直接轉移到另一領域。

**Q15：未來可以朝哪些方向延伸 AutoDesign？**

A：未來可以把 AutoDesign 應用到更多設計任務與模態，例如互動式網頁、簡報動畫或影片分鏡，進一步驗證其通用性。另一方面，可以強化 meta-harness optimizer 的信用分配機制，讓它更精準地判斷哪一個 harness 元件導致了成功或失敗。此外，整合即時線上人類回饋、建立更大規模的可重複使用設計知識庫，以及讓系統能夠主動詢問人類設計師以解決歧義，都是值得探索的方向。

## 實務應用指南

### 適用場景

1. **學術會議海報自動生成**  
   將投稿論文 PDF、補充圖表與表格轉換為符合會議規格、可列印的海報 HTML／PDF，適用於大型學術活動或實驗室內部海報日，減少研究生手動排版時間。

2. **企業技術文件視覺化摘要**  
   把技術白皮書、產品規格書或專案報告濃縮成單頁視覺摘要（one-pager）、投影片或展場海報，協助業務與解決方案架構師快速對外溝通。

3. **教育教材與課程海報製作**  
   從教科書章節、講義與參考文獻生成課程主題海報或學習單，讓教師能依據教學目標快速產出結構化、視覺一致的教材。

4. **研究計畫與募資提案視覺化**  
   將計畫書、文獻回顧與預期成果轉為補助機構或投資人取向的視覺摘要，強調證據鏈與可讀性。

5. **行銷內容多格式改編**  
   把部落格文章、產品說明與使用者評論改寫為社群貼文圖卡、活動海報或展場看板，並依品牌設計準則自動調整風格。

---

### 實作前置條件

**資料條件**
- 多模態來源資料：論文 PDF、圖片、表格、圖表與相關文字。
- 人類設計先驗（Human Design Priors）：高品質參考海報或設計範本，用於初始化評估器（Evaluator）。
- 偏好註釋：至少數十筆人工標註或專家評分，涵蓋忠實度（Faithfulness）、版面（Layout）、美學（Aesthetics）、可讀性（Readability）等維度。

**運算條件**
- 程式碼代理（Code Agent）環境：支援讀寫程式碼、執行工具呼叫（Tool Calling）與渲染 HTML 的運行環境。
- 多模態模型 API：具備視覺理解能力的 VLM，用於評判與回饋；並需一個強大的語言模型用於 harness 更新。
- 評估與渲染基礎設施：可將輸出渲染為圖片、執行規則檢查、儲存 rollout 軌跡與版本紀錄。

**技能條件**
- 熟悉 Python、HTML／CSS 與前端排版基礎。
- 具備提示工程（Prompt Engineering）與代理編排（Agent Orchestration）經驗。
- 能設計多維度評測指標與人類偏好對齊的評估流程。
- 了解版本控制與持續整合，以便管理 DesignHarness 的遞迴更新。

---

### 實作步驟建議

1. **定義任務與輸出規格**  
   明確輸入（如 paper.pdf）、輸出格式（HTML 海報、PDF、投影片）、尺寸限制、字體與品牌規範，並列出必須保留的結構元素（標題、作者、方法、實驗、圖表）。

2. **建立人類對齊的評估器**  
   使用參考海報與人工標註初始化 Evaluator，設計結合規則檢查與 VLM 評分的七維度評測標準（如 Coverage、Density、Layout、Aesthetics、Readability、Faithfulness、Visual Evidence）。

3. **建構初始 DesignHarness**  
   開發第一版 harness，包含內容擷取、結構規劃、視覺生成、排版渲染與評論家回饋（Critic Feedback）等模組，並確保每個模組可被單獨更新。

4. **執行 Meta-Harness 最佳化迴圈**  
   在訓練集上反覆試跑（Rollout），收集分數與失敗模式；由 Meta-Harness Optimizer 指導 Code Agent 針對單一模組提出有界更新（Bounded Update），再經 Acceptance Gate 檢查訓練集提升且開發集未退化後才合併。

5. **開發集驗證與人類研究**  
   在 PosterBench-mini 或自製開發集上驗證 DesignHarness，並進行系統盲測（System-Blind Human Study）確認自動分數與人類偏好一致。

6. **部署為可服務化產品**  
   將學習到的 DesignHarness 封裝為 API 或批次處理管線，整合上傳、預覽、人工微調與匯出功能，並記錄每次生成的軌跡供後續審查。

7. **持續監控與遞迴更新**  
   上線後收集使用者回饋與新參考設計，定期重新執行外層最佳化迴圈，讓系統持續累積可重複使用經驗（Reusable Experience）。

---

### 潛在風險與注意事項

- **過度擬合訓練集**  
  若 Meta-Harness Optimizer 只針對少數樣本調整，容易學到特定排版捷徑。應透過 Acceptance Gate 同時監控開發集表現，並保留多學科、多風格的測試集。

- **評估器偏差**  
  VLM 評分可能偏好特定視覺風格或對文字密度過度敏感。建議結合規則檢查、人類標註與週期性重新校正 Evaluator。

- **生成成本與延遲**  
  長期程代理式設計涉及大量工具呼叫與編輯回合，單張海報可能耗時數十分鐘。可設定預算上限、快取常見模組，並對簡單任務使用輕量版 harness。

- **渲染與跨裝置一致性**  
  HTML／CSS 在不同瀏覽器或列印環境下可能出現排版錯位。需建立標準化渲染管線與截圖比對測試。

- **內容幻覺與版權風險**  
  系統可能生成未出現在原文的聲稱，或誤用參考範本的視覺素材。應加入來源追溯（Traceable Evidence）機制，並使用授權明確的設計資產。

- **人機協作邊界模糊**  
  全自動迴圈可能產出不符合品牌或文化脈絡的結果。關鍵節點保留 Human-in-the-Loop，例如最終審核與風格把關。

---

### 與其他技術的整合建議

- **文件解析與 RAG 管線**  
  將 AutoDesign 接在 PDF 解析器（如 Nougat、Marker）與向量檢索系統之後，先抽取結構化證據再進入 DesignHarness，提升 Faithfulness 與 Coverage。

- **設計系統與範本庫**  
  與現有設計系統（Design System）或 Figma／Canva 範本整合，把品牌色、字體、元件規範編碼為 harness 的約束條件，確保輸出符合企業識別。

- **CI／CD 與版本控制**  
  把 DesignHarness 的每次更新視為程式碼版本，透過 Git 與自動化測試管線管理 Acceptance Gate，讓 harness 的遞迴演進可追蹤、可回滾。

- **人機協作編輯器**  
  在生成後接入所見即所得（WYSIWYG）編輯器，讓使用者能微調版面、文字與圖表，並將修改結果回饋給 Meta-Harness Optimizer 作為新訓練訊號。

- **MLOps 監控儀表板**  
  建立評分趨勢、成本、延遲與人類偏好的監控面板，協助產品團隊判斷何時該觸發新一輪 Meta-Harness Optimization。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦於「論文轉海報生成」這個具體任務，理解 AutoDesign 如何透過「內層生成海報、外層改進 harness」的雙迴圈運作。可先略過數學符號與評估細節，重點看圖 3 與實驗結果，建立對長期程代理式設計的直覺。

**AI 工程師**  
請深入閱讀 Meta-Harness Optimizer、Acceptance Gate 與 DesignHarness 的模組設計，關注如何將 Code Agent、VLM Evaluator 與渲染執行環境串接成穩定管線。實作時可優先複製 PosterBench-mini 的受控實驗，再擴展到自身資料。

**研究人員**  
本論文的核心貢獻在於把設計對齊問題重新框架為 meta-harness optimization，並提出可累積可重複使用經驗的機制。建議檢視其與現有 reflection、skill learning 及 self-improvement 研究的關聯，並思考如何將此框架推廣到網頁、投影片、影片等其他多模態設計任務。

**產品經理**  
請把重點放在適用場景、成本效益與人類偏好結果：AutoDesign 能在 40 分鐘內以低於 3 美元的成本產出接近會議海報品質的輸出，並在盲測中獲得最高偏好。評估導入時，請優先確認資料資產（參考海報、品牌規範）與人機協作流程是否到位。
