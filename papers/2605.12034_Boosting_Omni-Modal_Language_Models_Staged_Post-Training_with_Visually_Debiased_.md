## 摘要翻譯

全模態語言模型（omni-modal language model）旨在同時理解音訊、視覺輸入與語言，但當僅憑視覺證據便足以回答查詢時，基準測試增益（benchmark gains）可能被人為膨脹。我們探討當前的全模態基準測試（omni-modal benchmarks）是否能區分視覺捷徑（visual shortcuts）與真正的音訊-視覺-語言證據整合（genuine audio-visual-language evidence integration），以及後訓練（post-training）在視覺去偏評估（visually debiased evaluation）設定下的表現。我們以純視覺探測（visual-only probing）審查九項全模態基準測試，移除視覺可解查詢（visually solvable queries），並在篩選條件未定義或將導致比較不穩定時保留完整子集。由此建構出 OmniClean，一個從 16,968 筆受審查詢（audited queries）中保留 8,551 筆保留查詢（retained queries）的淨化評測集。在 OmniClean 上，我們評估 OmniBoost，一個基於 Qwen2.5-Omni-3B 的三階段後訓練（staged post-training）流程：混合雙模態監督式微調（mixed bi-modal supervised fine-tuning, SFT）、混合模態可驗證獎勵強化學習（mixed-modality Reinforcement Learning with Verifiable Rewards, RLVR），以及以自蒸餾資料（self-distilled data）進行監督式微調（SFT）。平衡雙模態監督式微調（balanced bi-modal SFT）帶來有限且不均衡的增益，RLVR 首次帶來廣泛的改善，而自我蒸餾（self-distillation）則重塑基準測試的表現輪廓。在以自蒸餾資料進行監督式微調後，該 3B 模型達到可與 Qwen3-Omni-30B-A3B-Instruct 媲美的表現，且總體上略高於後者，無需使用更強的全模態教師模型（stronger omni-modal teacher）。這些結果顯示，當評估控制視覺洩漏（visual leakage）時，全模態進展更容易詮釋，且小型全模態模型可受益於採用自蒸餾全模態查詢監督（self-distilled omni-query supervision）的分階段後訓練（staged post-training）。專案頁面：https://cheliu-computation.github.io/omni/

### 核心貢獻（3～5點）
- 提出 OmniClean 視覺去偏淨化評測集：透過純視覺探測審查 16,968 筆查詢，移除視覺可解題目，保留 8,551 筆保留查詢，建立排除視覺捷徑的全模態評估架構。
- 提出 OmniBoost 三階段後訓練方法：設計混合雙模態 SFT、混合模態 RLVR 與自蒸餾資料 SFT 的遞進流程，驗證各階段對全模態能力的不同影響。
- 驗證階段性訓練效果：平衡雙模態 SFT 僅帶來有限且不均勻的增益；RLVR 首次帶來廣泛改善；自我蒸餾則重塑模型的基準測試表現輪廓。
- 實現小型模型的高效擴展：經 OmniBoost 後，Qwen2.5-Omni-3B 在總體表現上可與 Qwen3-Omni-30B-A3B-Instruct 媲美甚至略優，且無需依賴更強的全模態教師模型。

### 適合對象
全模態學習與多模態基準測試研究者、從事後訓練與模型對齊的工程師，以及關注評估方法論與視覺偏差問題的語音－視覺－語言整合領域學者。

## 深度分析

#### 方法論解析

本文的核心方法論可分為兩大支柱：OmniClean (視覺去偏淨化評測集) 的建構，以及 OmniBoost (三階段後訓練方法) 的設計。兩者共同回應一個根本問題：現有 Omni-modal language model (全模態語言模型) 的 benchmark gains (基準測試增益) 是否真正反映 audio-visual-language (音訊-視覺-語言) 的整合能力，抑或僅是 visual shortcut (視覺捷徑) 的產物。

在 OmniClean 的建構上，作者採取操作性 (operational) 而非因果性的去偏策略。針對九個現有全模態基準中的 16,968 筆 audited query (受審查詢)，研究團隊執行 visual-only probing (純視覺探測)：保留影像或影片與文字問題，但隱藏音訊輸入，並以強模型測試是否仍能回復正確的可驗證答案（多選或數值目標）。若查詢在純視覺設定下可解，則標記為 visually solvable query (視覺可解查詢) 並剔除；反之則列為 retained query (保留查詢)。對於過濾條件未定義或剔除後將導致分數比較不穩定的子集，則採完整保留例外處理。最終從 16,968 筆查詢中保留 8,551 筆，形成 OmniClean。探測協定具高度細節：影片以 2fps 取樣，超過 60 秒者均勻抽取 120 幀，影像短邊調整為 448 像素（圖片則以 768 像素為上限）；每題進行 16 次 rollouts (獨立抽樣)，temperature (溫度) 設為 1.0，最大生成长度 8192 tokens (詞元)，且不額外加入系統提示或模態暗示。這種設計確保 visually debiased evaluation (視覺去偏評估) 在固定協定下可重複，而非宣稱保留查詢在絕對意義上必然因果依賴音訊。

OmniBoost 則是一個基於 Qwen2.5-Omni-3B (通義千問系列 3B 全模態模型) 的 staged post-training (分階段後訓練) 配方，旨在檢驗「強化雙模態能力是否足以構成全模態理解」的假設。第一階段為 balanced bi-modal SFT (平衡雙模態監督式微調)：均等混合 vision-language understanding (視覺-語言理解) 與 audio-language understanding (音訊-語言理解) 資料，遵循常見的 instruction-tuning (指令微調) 實務，作為對照基線。第二階段導入 mixed-modality RLVR (混合模態可驗證獎勵強化學習)，利用可自動驗證的答案給予跨模態最佳化訊號。第三階段則執行 SFT (supervised fine-tuning / 監督式微調) on self-distilled data (自蒸餾資料)，其資料來源並非仰賴 stronger omni-modal teacher (更強的全模態教師模型)，而是透過 entity-based procedure (實體導向流程) 自主建構 synthetic omni-modal query (合成全模態查詢)。具體而言，該流程從 LLaVA-Video 的 seed clip (種子片段)、Step-Audio-R1 的 audio caption (音訊描述)、Qwen3-VL 的 video caption (影片描述) 與 gpt-oss-120b 的 entity scaffold (實體鷹架) 中，萃取 spatial and temporal relations (空間與時間關係)，轉換為 hard-matchable question (可嚴格比對問題)，再過濾模型生成的 reasoning trace (推理軌跡) 以產生訓練資料。這種 self-distillation (自我蒸餾) 策略的關鍵在於，它無需外部更強大的全模態教師，即可產生 omni-query supervision (全模態查詢監督)。

#### 實驗數據解讀

OmniClean 的數據分佈本身即揭示了現有評測的重大結構性問題：在 16,968 筆受審查詢中，僅 8,551 筆被保留，代表超過四成的查詢存在 visual leakage (視覺洩漏)。這意味著在傳統基準上觀察到的分數提升，很可能大量混雜了 visual shortcut (視覺捷徑) 的利用，而非 genuine omni-modal integration (真正的全模態整合)。因此，任何聲稱在全模態任務上取得進展的模型，都應優先在 visually debiased evaluation (視覺去偏評估) 下重新檢視。

在 OmniBoost 的三階段實驗中，各階段呈現截然不同的能力形塑效果。balanced bi-modal SFT (平衡雙模態監督式微調) 僅帶來有限且不平均的增益，這項結果直接挑戰了「視覺-語言與音訊-語言能力可自然組合為全模態能力」的直覺假設。換言之，單純堆疊雙模態資料並無法有效遷移至需要同時整合三種模態的場景。相對地，mixed-modality RLVR (混合模態可驗證獎勵強化學習) 首次帶來廣泛且全面的性能提升，顯示 Reinforcement Learning with Verifiable Rewards (RLVR / 可驗證獎勵強化學習) 所提供的明確最佳化訊號，是突破雙模態組合瓶頸的關鍵。然而，最能「重塑基準輪廓 (reshape the benchmark profile)」的仍是第三階段的 self-distilled data (自蒸餾資料) 監督式微調。

最引人注目的結果是，經過三階段 post-training (後訓練) 的 3B 模型，在 OmniClean 的 aggregate summary (彙總摘要) 上，不僅可與 open-source reference (開源參考模型) 媲美，更在總體表現上略勝 Qwen3-Omni-30B-A3B-Instruct (通義千問 30B 全模態指令模型)。這項結果具有雙重意涵：其一，在排除視覺洩漏後，小模型透過精緻的後訓練配方即可挑戰大十倍的模型，顯示全模態能力的評估與提升在「去偏」後更為透明；其二，self-distillation (自我蒸餾) 所產生的 synthetic omni-modal query (合成全模態查詢) 具備極高的訓練效率，無需蒸餾自更強的全模態教師即可達成顯著的規模顛覆效果。

#### 與現有研究的比較

相較於近期 Omni-modal language model (全模態語言模型) 如 Qwen3-Omni、HumanOmniV2、NEXUS-O 與 Nemotron3NanoOmni 等研究，本文的貢獻不在於提出全新架構，而在於重新校準評估與後訓練的因果邏輯。現有 audio-visual-language (音訊-視覺-語言) 基準——包括 Daily-Omni、WorldSense、OmniBench、IntentBench、AV-Odyssey、VideoHolmes、UNO-Bench、CG-AV-Counting 與 OmniVideoBench——雖然涵蓋時間對齊、意圖推理、計數與開放式問答等多元任務，但普遍缺乏對視覺捷徑的系統性審計。本文將「可驗證答案」與「模態洩漏探測」分離，指出 verifiability alone 並不足以保證評估的有效性，這一觀點延續並具體化了先前多模態評估中對偏差與捷徑效應的討論。

在後訓練方法上，OmniBoost 與近期多模態強化學習研究形成對話。不同於僅針對單一模態對進行 RL 最佳化的工作，mixed-modality RLVR 明確將可驗證獎勵應用於跨模態場景，並證明其是雙模態 SFT 後的必要銜接。而自蒸餾階段則與傳統知識蒸餾 (distillation) 形成鮮明對比：過往方法通常仰賴更強的全模態教師模型 (stronger omni-modal teacher) 生成監督訊號，本文卻展示僅透過 entity-based procedure (實體導向流程) 與現成的雙模態/單模態資源（LLaVA-Video、Step-Audio-R1、Qwen3-VL、gpt-oss-120b），即可建構高品質的 omni-query supervision (全模態查詢監督)。這降低了大規模全模態後訓練的資料門檻。

然而，本文亦存在可進一步釐清的局限。首先，OmniClean 被明確定位為操作性評估視圖 (operational evaluation view)：它僅在固定協定下降低視覺偏差，而非證明 retained query (保留查詢) 在所有可能設定下都因果依賴音訊。其次，對於部分子集因「過濾未定義」或「比較不穩定」而採取的完整保留例外，可能使 OmniClean 仍殘留少量視覺可解查詢。第三，OmniBoost 的實驗僅基於 Qwen2.5-Omni-3B 單一規模，其在其他參數量級或架構上的泛化性尚待驗證。最後，合成資料的建構仰賴多個外部模型的輸出，這些模型自身的偏差可能透過 audio caption (音訊描述)、video caption (影片描述) 與 entity scaffold (實體鷹架) 傳遞至自蒸餾資料中。

#### 可重現性評估

在開放科學層面，本文已釋出若干關鍵資產與協定細節。OmniClean (視覺去偏淨化評測集) 已上架 HuggingFace (https://huggingface.co/datasets/che111/OmniClean)，使研究者可直接取得經審計後的 8,551 筆保留查詢與對應的篩選邏輯。專案頁面 (https://cheliu-computation.github.io/omni/) 亦提供集中式入口。在評估協定上，作者詳盡記載了視覺前處理參數：影片取樣率 2fps、長影片 120 幀預算、短邊 448 像素（圖片上限 768 像素）、16 次 rollouts (獨立抽樣)、temperature (溫度) 1.0、最大生成长度 8192 tokens (詞元)，以及不使用額外系統提示或模態暗示的原則。這些細節大幅提升了 visual-only probing (純視覺探測) 的可重複性。

儘管如此，可重現性仍存在明顯缺口。首先，提供的文本未明確說明訓練程式碼、OmniBoost 微調後的模型權重，或完整的合成資料生成腳本是否公開。其次，純視覺探測中作為判斷基準的「強模型」並未指明具體 checkpoint (檢查點)，不同模型選擇可能導致保留查詢集合的差異，進而影響 OmniClean 的絕對數值比較。第三，雖然 entity-based procedure (實體導向流程) 的概念架構已描述，但從 seed clip (種子片段)、audio caption (音訊描述)、video caption (影片描述) 與 entity scaffold (實體鷹架) 轉換為 hard-matchable question (可嚴格比對問題) 的具體模板、閾值與 reasoning trace (推理軌跡) 過濾規則，在節錄文本中尚未達到可完全復現的顆粒度。這些遺漏使得外部研究者難以精確複製 OmniBoost 的完整訓練管線。

#### 未來研究方向

基於本文所建立的 visually debiased evaluation (視覺去偏評估) 與 staged post-training (分階段後訓練) 框架，未來研究可沿以下數個方向深化與擴展。

第一，擴充去偏維度以邁向因果全模態評估。OmniClean 目前僅針對 visual leakage (視覺洩漏) 進行操作性排除，未來可發展音訊洩漏 (audio-only leakage) 或純語言洩漏探測，甚至透過 interventional data generation (介入式資料生成) 或對抗式範例，嚴格證明 retained query (保留查詢) 對特定模態的因果依賴性，而非僅止於排除 visually solvable query (視覺可解查詢)。

第二，規模化與架構泛化驗證。OmniBoost 在 3B 模型上展現了驚人的規模效率，但未來需將相同配方套用於 7B、30B 乃至更大規模的 Omni-modal language model (全模態語言模型)，以檢視 mixed-modality RLVR (混合模態可驗證獎勵強化學習) 與 self-distillation (自我蒸餾) 的增益是否隨規模遞減或浮現新的瓶頸。同時，驗證該方法是否適用於非 Qwen 系列的架構（如基於 Diffusion 或 MoE (混合專家模型) 的全模態模型）亦是重要課題。

第三，精進自我蒸餾迴圈以降低外部依賴。目前的 entity-based procedure (實體導向流程) 仰賴 LLaVA-Video、Step-Audio-R1、Qwen3-VL 與 gpt-oss-120b 等外部模型輸出。未來可探索完全內循環的自我蒸餾機制，例如讓模型自身迭代生成並驗證 spatial and temporal relations (空間與時間關係)，逐步減少對外部 entity scaffold (實體鷹架) 與描述模型的依賴，從而降低偏差傳遞並提升資料規模化效率。

第四，動態難度調控與適應性監督。未來可根據模型在訓練過程中的即時表現，動態調整 hard-matchable question (可嚴格比對問題) 的複雜度與模態交織程度，建構適應性全模態查詢監督 (adaptive omni-query supervision)。這類 curriculum learning (課程學習) 策略可能進一步放大 RLVR 與自蒸餾資料的協同效應。

第五，跨語言與開放域全模態評估。將 OmniClean 的審計協定擴展至多語言 audio-visual-language (音訊-視覺-語言) 基準，檢視 visual shortcut (視覺捷徑) 在不同語言與文化脈絡下的分佈差異，並開發對應的去偏評測集。此外，針對開放域生成式任務（如全模態故事生成或跨模態摘要），如何設計去偏的自動評估指標，亦是值得探索的開放問題。

## 論文問答

**Q1：當前全模態基準測試存在什麼核心問題，使得分數提升難以真實反映模型能力？**

A：現有的全模態基準測試中，許多查詢僅憑視覺證據與問題文字即可得出正確答案，導致模型即使完全未處理音訊也能獲得高分。這種現象使得基準測試的增益往往反映的是視覺捷徑的利用，而非真正的音訊-視覺-語言整合能力。因此，研究者無法單純從原始分數判斷模型是否具備跨模態的深度理解。

**Q2：為何傳統的評估方法無法準確衡量全模態理解？**

A：傳統評估通常只檢驗答案是否可驗證，卻未審查該答案是否可由單一模態獨立推導出來。由於視覺資訊在許多音訊-視覺場景中佔據主導地位，模型可以輕易繞過音訊處理，僅靠強大的視覺-語言能力取得亮眼成績。如此一來，標準的彙總指標會高估全模態能力，並掩蓋跨模態整合不足的問題。

**Q3：建構像 OmniClean 這樣的視覺去偏評估視角為何重要？**

A：若不控制視覺洩漏，研究者將無法分辨性能提升是來自更好的單模態視覺推理，還是貨真價實的多模態融合。OmniClean 透過固定協議排除視覺可解的查詢，使基準測試的增益更具可解釋性。這讓學術界能夠隔離出真正的音訊-視覺-語言證據整合，並公平地比較不同的後訓練方法。

**Q4：OmniClean 的核心建構方法是什麼？**

A：作者針對九個基準測試中的 16,968 道查詢進行純視覺探測，僅提供影像或影片與問題文字，並隱藏音訊輸入。若強大模型在此純視覺設定下仍能正確回答，該查詢即被標記為視覺可解並從淨化視角中排除。最終保留的 8,551 道查詢構成 OmniClean，在固定且可複現的協議下降低了視覺捷徑的影響。

**Q5：OmniBoost 分階段後訓練配方的關鍵創新為何？**

A：OmniBoost 設計了三階段漸進流程——混合雙模態監督式微調、混合模態可驗證獎勵強化學習，以及自蒸餾資料上的監督式微調——用以驗證顯式的全模態訊號是否必要。與一般假設視覺-語言和音訊-語言能力可自然組合的做法不同，此配方在視覺去偏的評估下隔離了每個階段的貢獻。其自蒸餾階段尤其創新，因為它在不依賴更強外部全模態教師模型的情況下，合成出可嚴格比對的全模態查詢。

**Q6：自蒸餾資料建構的設計選擇受到什麼動機驅動？**

A：作者希望在不借助更大全模態教師模型的前提下生成合成全模態監督資料，因為強大的外部教師可能無法取得，或會引入自身偏差。他們採用實體導向流程，從 LLaVA-Video 種子片段、Step-Audio-R1 音訊描述、Qwen3-VL 影片描述與 gpt-oss-120b 實體鷹架中萃取空間與時間關係，進而建構音訊-視覺-文字問題。這些問題隨後被轉換為可嚴格比對的格式，並透過模型生成的推理軌跡進行篩選，確保訓練訊號瞄準真正的跨模態推理。

**Q7：實驗審查了哪些基準測試，OmniClean 的規模為何？**

A：本研究審查了九個現有全模態基準測試，涵蓋時間對齊、意圖與社交推理、計數、複雜影片推理，以及開放世界音訊-視覺問答等任務。從總計 16,968 道受審查詢中，排除視覺可解題目並針對特定基準保留完整子集後，最終保留了 8,551 道查詢。這產生了一個規模可觀且操作上淨化的評估視角，在降低視覺洩漏的同時維持了分數比較的穩定性。

**Q8：OmniBoost 三階段訓練的關鍵量化發現是什麼？**

A：平衡的混合雙模態監督式微調僅帶來有限且不平均的增益，顯示單純混合視覺-語言與音訊-語言監督並不足以促成全模態遷移。混合模態可驗證獎勵強化學習則在淨化後的基準套件上首次帶來廣泛的改善，說明可驗證獎勵最佳化有助於對齊跨模態推理。最後，在自蒸餾資料上進行監督式微調重塑了基準輪廓，使 3B 基礎模型在彙總表現上足以媲美甚至略勝 Qwen3-Omni-30B-A3B-Instruct。

**Q9：研究中有哪些類似消融實驗的比較，能釐清改進來源？**

A：研究明確將平衡雙模態監督式微調與完整 OmniBoost 配方進行比較，前者作為遵循常見指令微調慣例的對照組。此對照組觀察到的有限遷移證明，組成雙模態能力並不會自動轉化為強大的全模態性能。透過依序引入強化學習與自蒸餾全模態查詢監督，研究隱式地進行了消融，顯示是顯式的全模態最佳化訊號——而非僅有更多雙模態資料——驅動了最終的競爭力。

**Q10：在實際應用場景中，產品團隊為何應關注視覺去偏評估？**

A：在影片輔助或智慧監控等真實應用中，使用者期望模型能整合語音、音效或環境音等音訊線索與視覺內容，以做出正確判斷。若模型依賴視覺捷徑，當音訊攜帶關鍵的消歧資訊時，模型可能無聲地產生嚴重錯誤。採用 OmniClean 這類視覺去偏評估協議，能幫助產品團隊在部署前驗證模型是否真正動用了所有模態。

**Q11：OmniBoost 配方可能如何影響小規模全模態產品的開發？**

A：OmniBoost 證明，一個 3B 參數模型在經過分階段後訓練與自蒸餾全模態資料的訓練後，能夠與 30B 參數的對照模型抗衡。這意味著資源有限的團隊無需託管巨大模型或依賴專有大型教師，即可達到具競爭力的全模態能力。此做法降低了建構高效能、可部署於裝置端的全模態應用門檻，同時維持嚴謹的跨模態推理標準。

**Q12：這項工作對多模態研究領域可能產生什麼更廣泛的影響？**

A：透過提出可操作的審查協議與公開的淨化評估視角，本文鼓勵學術界從膨脹的基準分數轉向更嚴謹的模態整合指標。無需更強教師模型即可成功的自蒸餾全模態查詢監督，可能將研究重心轉向合成資料工程與分階段最佳化。長遠來看，這有望使視覺去偏評估成為未來全模態基準設計中的標準健全性檢查。

**Q13：作者對 OmniClean 的純視覺探測協議承認了哪些限制？**

A：作者強調 OmniClean 是一個在固定協議下降低視覺捷徑的操作性評估視角，而非證明每道保留查詢在所有可能情境下都因果依賴音訊。某些查詢可能仍透過其他形式的洩漏或背景知識被解開，而這些情況未被純視覺探測捕捉。因此，該資料集提升了結果的可解釋性，但無法保證音訊-視覺-語言整合的絕對純淨度。

**Q14：在哪些失效案例中，OmniBoost 的分階段訓練仍可能表現不佳？**

A：當過濾未定義或移除視覺可解查詢會使分數比較不穩定時，研究保留了完整子集，這意味著部分基準角落仍存在殘留的視覺洩漏。此外，自蒸餾流程依賴種子片段與描述的品質和多樣性；若這些種子缺乏複雜的跨模態互動，蒸餾出的監督訊號可能無法涵蓋完整的推理頻譜。以此方式訓練的模型，在合成分布之外的罕見或高度細膩的音訊-視覺情境中仍可能失敗。

**Q15：這些發現為全模態後訓練與評估指出了哪些未來方向？**

A：未來研究可將去偏協議從視覺洩漏擴展到音訊專屬或語言專屬的捷徑審查，以建構更為純淨的評估視角。研究者亦可探索更進階的強化學習目標，或迭代式的自蒸餾迴圈，以逐步提升全模態查詢的難度。另一個有前景的方向是整合因果介入技術，以驗證模型預測確實依賴音訊-視覺互動，而非僅依賴相關的單一模態線索。

## 實務應用指南

### 適用場景

1. **智慧安防與異常事件偵測**：同時分析監視器畫面與環境音（如玻璃碎裂、呼救聲），排除「只看畫面就能判斷」的誤報，確保模型真正整合音訊與視覺線索。
2. **多模態內容審核平台**：在短影片或直播場景中，判斷畫面與旁白／背景音是否一致（例如詐騙影片使用盜用畫面搭配虛假語音），需依賴真正的全模態理解而非僅靠視覺文字辨識。
3. **視障輔助與空間導覽**：透過穿戴式裝置接收周遭聲音與影像，回答「我前方那個發出滴滴聲的物體是什麼」這類必須同時使用音訊與視覺的查詢。
4. **智慧教育互動系統**：在遠距教學中分析學生的視訊畫面與語音提問，判斷其困惑點是否來自板書內容（視覺）或講解邏輯（音訊），並給出需要跨模態推理的回應。
5. **自動化客服與多模態助理**：處理用戶上傳的產品運作影片與異音描述，診斷機械故障原因，避免模型僅憑影片畫面中的品牌標籤就給出制式答案。

### 實作前置條件

- **資料**：需備有音訊-視覺-語言配對的原始資料，包括影片片段（如 LLaVA-Video 等開源資料）、音訊描述（audio caption）與視覺描述（video caption）。若進行自我蒸餾，需準備種子片段與實體鷹架（entity scaffold）作為合成全模態查詢的基礎。
- **運算**：以 3B 參數規模為例，混合雙模態 SFT 與自我蒸餾 SFT 可在單張 A100／H100 80GB 上執行；混合模態 RLVR 階段需額外 VRAM 支援多組 rollout 與可驗證獎勵計算，建議至少 4–8 張 A100 或同等算力。推論端需支援同時載入音訊編碼器與視覺編碼器。
- **技術能力**：團隊需熟悉 PyTorch／Transformers 生態、多模態資料前處理（影片抽幀、音訊特徵提取）、RLVR（Reinforcement Learning with Verifiable Rewards）流程實作，以及能自行建構視覺去偏評估協定（visual-only probing）與答案驗證器。

### 實作步驟建議

1. **建立視覺去偏評估基線**：先對現有全模態基準測試集執行「純視覺探測」，移除僅憑視覺與問題文本即可回答的查詢，保留視覺不可解的題目作為內部 OmniClean 評測集。此步驟可避免後續訓練優化方向被視覺捷徑誤導。
2. **執行平衡混合雙模態 SFT**：將視覺-語言（V-L）與音訊-語言（A-L）的指令微調資料依等量比例混合，對基礎全模態模型（如 Qwen2.5-Omni-3B）進行第一階段微調。此階段目的是對齊各雙模態能力，但預期增益有限且不平均。
3. **導入混合模態 RLVR**：使用可驗證獎勵（如多選題正確性、數值答案比對）對模型進行跨模態強化學習。讓模型在同一批次中同時接收純視覺、純音訊與音訊-視覺混合查詢，透過獎勵訊號強化真正的全模態整合行為。
4. **合成全模態查詢並執行自我蒸餾**：以實體導向流程從種子影片提取空間與時間關係，結合音訊描述與實體鷹架，產生可嚴格比對答案的合成 omni-modal 查詢。讓現階段模型生成推理軌跡，過濾錯誤後作為下一輪 SFT 的監督資料。
5. **以去偏評估驅動迭代驗證**：每個階段結束後，在內部 OmniClean 評測集上測試，確認分數提升來自全模態整合而非視覺捷徑。若視覺去偏分數未提升，應回頭檢查資料混合比例或 RLVR 獎勵設計。

### 潛在風險與注意事項

- **過度過濾導致評測失真**：若審查標準過嚴，可能移除大量有效查詢，使評測集過小或分布偏移。建議僅排除高置信度的視覺可解題目，並保留基準測試定義不清或過濾後會破壞比較穩定性的完整子集。
- **合成資料品質參差不齊**：自我蒸餾過程中，模型自身生成的推理軌跡可能包含錯誤鏈條。必須建立嚴格的答案比對與邏輯一致性過濾機制，避免「自己教自己錯誤答案」的退化現象。
- **殘留視覺偏差與虛假相關性**：即使經過視覺去偏審查，部分查詢仍可能存在語言先驗或統計捷徑。建議定期以不同視覺編碼器或抽幀策略進行交叉驗證，確認模型確實使用了音訊特徵。
- **分階段訓練的成本遞增**：RLVR 與自我蒸餾會顯著延長訓練時程。建議在初期以較小資料量驗證每階段的邊際效益，確認 RLVR 帶來廣泛改善後，再投入大規模自我蒸餾。
- **模態對齊失敗**：音訊與視覺編碼器的特徵空間可能未充分對齊，導致模型在推論時忽略其中一個模態。可透過強制模態缺失訓練（modality-dropout）作為輔助任務，確保單一模態輸入時模型仍能運作。

### 與其他技術的整合建議

- **檢索增強生成（RAG）**：將全模態模型與多模態向量資料庫整合，用於儲存歷史音訊-視覺事件紀錄。當模型遇到需要外部知識的 omni-modal 查詢時，可先檢索相似片段作為上下文，再進行推理。
- **現有視覺或音訊專家模型管線**：若已有成熟的視覺語言模型（VLM）或音訊語言模型（ALM）服務，可將 OmniBoost 的後訓練流程視為「整合層」：先分別凍結 VLM 與 ALM 的編碼器，僅訓練全模態投影層與 LLM 主幹，降低遷移成本。
- **邊緣裝置部署最佳化**：3B 級全模態模型適合透過量化（INT4／INT8）與編解碼器輕量化後部署於邊緣。建議將視覺抽幀與音訊特徵提取前置於裝置端，僅將壓縮特徵上傳至模型進行語言推理。
- **MLOps 與多模態資料管線**：整合資料標註平台，自動標記新進影片的音訊描述與視覺實體，並定期觸發視覺洩漏審查與模型再訓練，形成持續學習閉環。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦「視覺捷徑」與「視覺去偏評估」的核心概念。理解為何「基準測試分數高」不等於「模型真的會聽聲音」，是進入全模態領域最重要的批判性思維。實作上可從使用現成的 OmniClean 評測集檢視開源模型開始。
- **AI 工程師**：建議深入閱讀第 3 節的視覺洩漏審查協定與第 4 節的三階段後訓練流程。重點關注混合模態 RLVR 的獎勵設計、自我蒸餾的資料建構腳本（實體導向流程與 hard-matchable 問題轉換），以及如何在不依賴更強教師模型的情況下產生合成監督訊號。
- **研究人員**：本文的方法論貢獻在於 OmniClean 的建構邏輯與「分階段後訓練」的對照實驗設計。建議仔細檢視視覺探測的 pass@16 設定、過濾例外條件，以及為何平衡雙模態 SFT 無法自動湧現全模態能力——這對未來設計更嚴謹的音訊-視覺-語言評測與訓練策略具有直接啟發。
- **產品經理**：請優先參考「適用場景」與「實作前置條件」。關鍵在於評估：您的應用場景是否真的有「必須同時理解音訊與視覺」的查詢？若是，則 OmniClean 式的去偏評估能幫助團隊避免被虛高的基準數字誤導；同時注意 3B 模型經後訓練後可逼近 30B 模型的去偏表現，這對邊緣部署與成本控管極具商業價值。
