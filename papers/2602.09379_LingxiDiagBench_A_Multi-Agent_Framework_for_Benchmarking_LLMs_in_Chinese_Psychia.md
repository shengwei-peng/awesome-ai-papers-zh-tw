# LingxiDiagBench：一個用於評測大型語言模型在中文精神科會診與診斷的多智能體框架

## ⚡ TL;DR

現行精神科AI缺乏真實病患模擬與動態多輪會診評測基準，難以有效評估大型語言模型輔助診斷能力。
LingxiDiagBench以萬六筆電子病歷對齊中文合成對話評估十二類精神科診斷靜態與動態表現。
實驗顯示模型擅長二元分類，但共病與十二類鑑別診斷表現差，動態會診常遜於靜態評估，資料集已公開釋出。

## 深度分析

#### 方法論解析

本研究提出之 **LingxiDiagBench** 為一個針對中文精神科領域設計之大規模多智能體框架 (Multi-Agent Framework)，其核心目標在於同時評估大型語言模型 (Large Language Models, LLMs) 於靜態診斷推論 (Static Diagnostic Inference) 與動態多輪會診 (Dynamic Multi-Turn Consultation) 兩大情境下的表現。方法論可拆解為資料建構、任務設計、智能體系統與評估指標四個層面。

在資料建構層面，作者群以真實臨床門診案例 (Clinical Outpatient Cases)、專家填寫之電子病歷 (Electronic Medical Records, EMR) 與手動謄寫之轉錄稿 (Manual Transcriptions) 為基礎，透過模式萃取 (Pattern Extraction) 歸納出 158 種獨特診斷類別，進而生成 **LingxiDiag-16K** 資料集。該資料集包含 16,000 筆與電子病歷對齊 (EMR-Aligned) 之合成會診對話 (Synthetic Consultation Dialogues)，並在臨床人口統計 (Clinical Demographic) 與語言分佈上貼近真實世界，涵蓋 12 項國際疾病分類第十版 (International Classification of Diseases, ICD-10) 精神科類別 (Psychiatric Categories)。此設計解決了過往樣板化合成資料缺乏對話變異性之問題，同時確保診斷標籤經過臨床醫師驗證 (Clinician-Verified)。

任務設計採階梯式難度規劃，由簡至繁分為三類：(1) 二元憂鬱–焦慮分類 (Binary Depression–Anxiety Classification)，即區分憂鬱症 (F32) 與焦慮症 (F41.1)；(2) 四向分類，納入憂鬱–焦慮共病識別 (Depression–Anxiety Comorbidity Recognition) 與其他類別；(3) 12 類鑑別診斷 (12-Way Differential Diagnosis)，進行多標籤 ICD-10 編碼預測。此階層式設計能精確定位模型能力邊界，從基礎區辨能力過渡至真實臨床最常見之鑑別診斷 (Differential Diagnosis) 情境。

智能體系統由三個角色構成：**Patient Agent** 為以電子病歷驅動 (EMR-Driven) 之患者模擬 (Patient Simulation) 模組，負責依據病史自動生成擬真回應；**Doctor Agent** 採標準作業程序引導之提問策略 (SOP-Guided Questioning)，實現多樣化資訊收集策略 (Information-Gathering Strategies)；**Diagnostic Agent** 則扮演證據導向之診斷角色，應用 ICD 準則進行下游診斷推理 (Downstream Diagnostic Reasoning)。三者的解耦設計使研究者能獨立評估「會診過程品質」與「最終診斷正確性」。

評估指標分為靜態與動態兩大軌道。靜態評估 (LingxiDiagBench - Static) 以固定合成對話為輸入，進行醫師提問預測（採 BLEU、ROUGE-L、BERT-Score）與輔助診斷（2/4/12 類別）；動態評估 (LingxiDiagBench - Dynamic) 則讓 Doctor Agent 與 Patient Agent 即時互動，透過端到端 (End-to-End) 會診與診斷流程，以準確率 (Accuracy)、宏觀 F1 (Macro F1)、加權 F1 (Weighted F1)、Top-1/Top-3 準確率衡量診斷表現，並輔以 LLM 作為評審 (LLM-as-a-Judge) 評量多輪對話品質。

#### 實驗數據解讀

實驗結果揭示了三項值得深入探討之現象。首先，模型表現隨任務複雜度呈現斷崖式衰退：在二元憂鬱–焦慮分類上，最先進模型可達 92.3% 之診斷準確率 (Diagnostic Accuracy)，顯示 LLMs 對於單一、互斥之表徵區辨具備高度模式匹配能力；然而一旦進入憂鬱–焦慮共病識別，表現即驟降至 43.0%；在貼近真實臨床之 12 類鑑別診斷任務中，Top-1 準確率更僅餘 28.5%。此數據強烈暗示，當前 LLMs 尚未掌握精神科診斷 (Psychiatric Diagnosis) 所需之細緻因果推理與多標籤共現關係，尤其對於高盛行率之共病情境（如憂鬱合併焦慮）幾乎不具臨床可用性。

第二項關鍵發現為動態會診 (Dynamic Consultation) 表現普遍劣於靜態評估。此結果違反直覺——理論上多輪互動應能透過澄清提問補足資訊缺口，但實際上卻因資訊收集策略 (Information-Gathering Strategies) 效率不彰，導致下游診斷推理受損。這凸顯了「提問能力」本身即為重大瓶頸：模型可能提出冗餘、誘導性或偏離鑑別核心之問題，反而遮蔽關鍵症狀軌跡。對於會談式診斷 (Interview-based Diagnosis) 而言，此發現意味著僅具備醫學知識不足以保證良好臨床表現，「如何問」與「問什麼」之策略優化與診斷知識同等重要。

第三，會診品質 (Consultation Quality) 與診斷準確率僅呈現中度相關。LLM 作為評審 (LLM-as-a-Judge) 給予高分之對話——例如結構完整、用語專業、遵循標準會談流程——並無法保證最終診斷正確。這項發現具有雙重意涵：一方面，現有自動評分機制可能過度偏重話語、對話與語用學 (Discourse, Dialogue and Pragmatics) 表面特徵，而忽略隱含之診斷邏輯缺陷；另一方面，也警示開發者勿將「對話流暢度」誤作為「醫療正確性」之代理指標。在心理健康評估 (Mental-Health Assessment) 場景中，此兩者之脫鉤可能導致過度信賴 AI 輔助精神科診斷 (AI-Assisted Psychiatric Diagnosis) 系統之安全風險。

#### 與現有研究的比較

相較於既有精神科 AI 基準測試，LingxiDiagBench 在三大層面實現顯著躍進。相較於 PsychiatryBench 等早期工作，本框架突破靜態問答之限制，首次於中文語境提供大規模、多疾病、動態多輪之臨床對話基準測試 (Clinical Dialogue Benchmark)。過往資料集多依賴樣板化生成，缺乏真實患者模擬 (Patient Simulation) 之對話變異性，且鮮少納入臨床醫師驗證的診斷標籤 (Clinician-Verified Diagnostic Labels)；本研究則直接從真實電子病歷 (EMR) 萃取分佈，確保診斷分佈 (Diagnostic Distributions) 與人口特徵之臨床真實性。此外，透過 Patient/Doctor/Diagnostic Agent 之三角色分離，本研究得以獨立檢視資訊收集與診斷決策之因果鏈，而非僅評估最終答案正確與否。

然而，本研究仍存在若干侷限。其一，雖強調 EMR 對齊，合成會診對話 (Synthetic Consultation Dialogues) 終究無法完全複製真實病患之情緒波動、抗拒會談或非字面溝通（如反諷、沉默）等精神科常見之語用特徵。其二，12 項 ICD-10 精神科類別 (ICD-10 Psychiatric Categories) 雖已涵蓋情緒障礙、焦慮、強迫、創傷相關及睡眠障礙等，但仍未覆蓋人格障礙、思覺失調症全光譜或器質性精神疾病等更複雜領域，限制其對於廣義精神障礙 (Mental Disorders) 之推論效度。其三，評估機制高度仰賴 LLM 作為評審 (LLM-as-a-Judge)，其評分標準可能內建特定模型之偏好偏差，且與診斷準確率之中度相關亦暴露此評量方式之天花板。最後，本框架聚焦中文語境，雖填補了非英語精神科評測之空白，但跨文化適用性仍有待驗證。

#### 可重現性評估

本研究在可重現性 (Reproducibility) 方面採取相對開放之策略。作者群已於 GitHub 釋出 LingxiDiag-16K 資料集、完整評估框架 (Evaluation Framework) 與原始碼，使其他研究者得以複製靜態與動態兩軌道之實驗流程。靜態評估因採用固定對話紀錄，具備高度可重複性；動態評估雖涉及即時互動，但由於 Patient Agent 之行為係由電子病歷 (EMR) 驅動且具確定性規則，理論上仍可重現相同互動軌跡。

不過，完全之重現仍面臨實務挑戰。論文中測試之最先進模型 (State-of-the-Art LLMs) 多為閉源商業 API（如 GPT-4 系列），其模型權重 (Model Weights) 未公開，且版本更新可能導致輸出漂移。此外，雖然合成資料規避了真實病歷之隱私法規限制，但從原始 EMR 到合成對話之生成管線（如去識別化細節、專家審核門檻、對話長度截斷規則）若未於公開文件中鉅細靡遺地揭露，仍可能產生再現落差。整體而言，本研究已達到「資料與評測工具公開」之基準，但「端對端訓練流程」與「臨床驗證細節」之透明度仍有精進空間。

#### 未來研究方向

基於 LingxiDiagBench 所揭示之性能缺口，後續研究可沿以下數個軸線展開。第一，針對資訊收集策略 (Information-Gathering Strategies) 之瓶頸，可引入強化學習 (Reinforcement Learning) 或人類/臨床醫師回饋之強化學習 (RLHF/RLCF) 來訓練 Doctor Agent，使其學會主動澄清、適時追問高鑑別度症狀，而非僅依賴靜態標準作業程序。第二，共病識別之低準確率提示需發展顯式多標籤架構或圖神經網絡 (Graph Neural Networks) 以建模症狀間之共現結構，而非將共病視為獨立類別。

第三，當前框架僅仰賴文本，未來應朝向多模態 (Multimodal) 精神科 AI 邁進，整合語音韻律、臉部表情、行為觀察等非語言線索——這些在會談式診斷中常為關鍵診斷依據。第四，會診品質與診斷準確率之脫鉤現象呼籲建立更貼近臨床之評量架構，例如改採結構化臨床會談 (Structured Clinical Interview) 衍生之標準化評分準則 (Rubric)，或引入真人精神科醫師於迴路中 (Human-in-the-Loop) 進行盲評，以降低 LLM 作為評審 (LLM-as-a-Judge) 之偏差。

第五，資料集可擴展至縱向追蹤 (Longitudinal) 會診情境，因精神科診斷常需數週至數月之病程觀察方能確立。最後，跨語言與跨文化驗證亦為當務之急——將 LingxiDiagBench 之方法論遷移至其他語言與醫療體系，檢驗精神障礙表現之文化特異性，將有助於建立真正具全球適用性之 AI 輔助精神科診斷系統。

## 論文問答

**Q1：本研究旨在解決精神科診斷領域中的哪些核心問題？**
A：全球精神障礙的盛行率持續攀升，但精神科醫師的嚴重短缺與會談式診斷固有的主觀性，導致許多患者難以及時獲得一致且準確的心理健康評估。現行醫療體系在面對龐大診斷需求時力不從心，使得發展可擴展的 AI 輔助診斷工具成為當務之急。然而，該領域的技術進展長期受限於缺乏能同時模擬真實臨床互動、提供專業驗證標籤，並支援動態多輪評估的高品質基準。

**Q2：為何現有的精神科 AI 評測基準被認為不足以支持技術發展？**
A：現有基準大多依賴模板化生成的合成對話，缺乏真實臨床場景中的對話多樣性與自然語言變異。這些資料集經常遺漏鑑別診斷所需的關鍵患者資訊，且鮮少包含經臨床醫師驗證的診斷標籤，導致評測結果難以反映真實醫療情境的複雜度。更重要的是，絕大多數基準不支援動態多輪會診，因此無法評估模型在長期互動中進行策略性資訊收集與即時診斷推理的能力。

**Q3：建立 LingxiDiagBench 這樣的評測框架對學界與臨床界有何重要性？**
A：LingxiDiagBench 填補了中文精神科 AI 領域長期缺乏大規模、多疾病標準化評測的關鍵空白，為研究者提供了一個可重現的嚴謹測試平台。透過同時涵蓋靜態診斷推論與動態多輪會診，該基準能夠更全面地檢視大型語言模型在貼近真實臨床流程中的表現。這不僅有助於加速具臨床實用價值的 AI 診斷模型研發，也為未來在醫療資源不足地區部署可擴展的心理健康評估工具奠定了堅實基礎。

**Q4：LingxiDiagBench 的核心方法論為何？其系統架構如何運作？**
A：本研究提出的 LingxiDiagBench 是一個以大規模多智能體框架為核心的評測系統，其核心為包含一萬六千筆對話的 LingxiDiag-16K 資料集，這些合成會診對話均與真實電子病歷的臨床人口統計及診斷分佈對齊。該框架整合了三類智能體：患者智能體負責模擬真實病患行為，醫師智能體執行多樣化的問診策略，診斷智能體則進行基於證據的診斷決策。透過此一模組化設計，系統得以在受控環境中同時評估模型的靜態文本推理能力與動態互動過程中的端到端表現。

**Q5：相較於先前研究，LingxiDiagBench 的主要創新之處為何？**
A：與以往依賴固定模板或靜態問答的評測方法不同，LingxiDiagBench 首創以真實電子病歷為基礎建構大規模多疾病精神科診斷基準，並精確再現臨床族群與疾病的真實分佈。其重大創新在於引入動態多輪會診機制，使評測不再局限於單次文本輸入的推理，而是涵蓋了從問診到診斷的完整臨床流程。此外，研究團隊設計了基於 ICD-10 的三階段漸進式診斷任務，並結合 LLM-as-a-Judge 機制評估會診品質，提供了更細緻且具臨床意義的多維度效能指標。

**Q6：作者為何選擇建構與電子病歷對齊的合成會診對話，而非直接使用真實轉錄資料？**
A：研究團隊採用電子病歷對齊的合成資料策略，是為了在嚴格保護患者隱私的前提下，最大化保留真實臨床資料的統計特性與語言分佈。這種設計使合成對話能夠準確反映真實世界中的年齡、性別等族群特徵，以及十二類 ICD-10 精神疾患的盛行率比例，從而提升評測結果的外部效度。同時，透過從真實門診病歷與專家轉錄資料中萃取臨床模式，確保了生成內容在醫學上的合理性，並保留了鑑別診斷所需的關鍵資訊完整性。

**Q7：實驗中評估了哪些診斷任務與模型？評估指標包含哪些？**
A：本研究設計了三個難度遞增的診斷任務，分別為二元憂鬱–焦慮分類、四類憂鬱–焦慮共病與其他疾病識別，以及十二類 ICD-10 精神科多標籤鑑別診斷。實驗涵蓋了多個最先進的大型語言模型，並同時在靜態診斷推論與動態多輪會診兩種情境下進行全面評測。評估指標包含準確率、Macro F1、Weighted F1 以及 Top-1/Top-3 準確率，從多個維度檢視模型在不同疾病複雜度與互動模式下的診斷效能。

**Q8：實驗結果中最值得關注的三項發現為何？**
A：首先，雖然大型語言模型在二元憂鬱與焦慮分類上可達到 92.3% 的高準確率，但在憂鬱–焦慮共病識別上的表現大幅滑落至 43.0%，而十二類鑑別診斷更僅有 28.5% 的準確率，顯示模型處理複雜臨床情境的能力仍相當有限。其次，動態多輪會診的整體表現往往不如靜態評估，這表明模型在互動過程中採用的資訊收集策略存在明顯缺陷，進而嚴重損害了下游的診斷推理品質。第三，由 LLM-as-a-Judge 評估的會診品質與實際診斷準確率之間僅呈現中度相關，意味著對話結構看似完整或提問邏輯良好，並不保證最終能導出正確的診斷決策。

**Q9：靜態評估與動態會診的對比分析揭示了什麼樣的關鍵洞察？**
A：靜態與動態評估的對比揭示了一個重要警訊：模型在固定文本上的優異診斷能力無法直接遷移至真實的互動式會診場景。在動態多輪對話中，模型必須自主決定提問的順序、深度與方向以收集關鍵病史，但實驗顯示許多模型在此資訊收集階段表現不佳，導致後續診斷效能顯著下降。這項發現強調了未來精神科 AI 的研發重點，不應僅限於提升單次推理的正確率，更必須強化多輪對話中的策略性探詢與臨床資訊整合能力。

**Q10：LingxiDiagBench 在實務上可以應用於哪些真實場景？**
A：此評測框架可直接應用於 AI 輔助精神科診斷系統的開發與上市前驗證，特別適合作為基層醫療機構或心理健康資源匮乏地區的篩檢與初步評估工具。醫療科技公司與醫院資訊部門能利用此基準測試不同大型語言模型在中文臨床對話中的穩健性，以選擇最適合整合至電子病歷系統或遠距醫療平台的模型。此外，該框架亦可應用於醫學教育領域，作為訓練實習醫師問診技巧、鑑別診斷思維與醫病溝通能力的虛擬病人模擬環境。

**Q11：若要將此類 AI 診斷工具實際產品化並部署於臨床，需考量哪些關鍵因素？**
A：產品開發者必須正視模型在共病識別與多類別鑑別診斷上的顯著性能落差，避免在複雜病例上過度信賴單一模型輸出而導致誤診風險。由於研究發現會診品質與診斷準確率僅有中度相關，系統設計應強制納入人機協作機制，確保精神科醫師能夠覆核 AI 的問診過程與最終診斷建議。此外，動態會診中暴露出的策略缺陷顯示，產品化過程應整合標準作業程序引導的提問流程或決策輔助模組，以確保資訊收集的完整性與臨床使用的安全性。

**Q12：這項工作可能對精神科 AI 領域帶來什麼樣的深遠影響？**
A：本研究為中文精神科 AI 建立了首個大規模、涵蓋多種疾病且同時評估動態互動的標準化評測典範，有望引導整個領域從靜態知識測驗轉向真實臨床對話模擬的研究範式。透過公開釋出 LingxiDiag-16K 資料集與完整評測框架，研究團隊大幅促進了可重現研究，降低了其他研究者進入此高門檻領域的障礙。長遠而言，這項工作將推動更具臨床實用價值與可靠性的診斷模型發展，並可能顯著改善全球心理健康服務的可近性、一致性與及時性。

**Q13：LingxiDiagBench 本身存在哪些固有的限制？**
A：儘管 LingxiDiag-16K 在統計分佈上與真實電子病歷高度對齊，但其本質仍為合成資料，可能無法完全捕捉真實患者在會診中的所有情緒細微差異、非語言線索或非預期反應。目前的評測框架主要聚焦於十二類 ICD-10 精神科疾病，對於更罕見、更複雜或跨科共病的精神疾患覆蓋仍顯不足。此外，LLM-as-a-Judge 的自動化評估方式雖然提升了評分效率，但其評分標準與人類資深精神科醫師的臨床直覺之間可能存在尚未被充分探討的系統性偏差。

**Q14：根據實驗結果，大型語言模型在哪些類型的病例上最容易失敗？**
A：模型最明顯的失敗案例出現在憂鬱症與焦慮症的共病情形，實驗顯示模型往往難以同時識別兩種並存的精神狀態，導致診斷遺漏或片面判斷。在十二類鑑別診斷任務中，模型對於症狀表現相似但病因與治療方針迥異的疾病區分能力特別薄弱，顯示其深層醫學推理與細粒度辨識能力仍有重大侷限。另外，在動態會診情境下，模型經常因為提問策略不當、過早下結論或未能追問關鍵病史，而未能收集到足夠的診斷證據，進而在後續階段做出錯誤判斷。

**Q15：基於本研究的發現，未來有哪些值得探索的研究方向？**
A：未來研究可優先發展更先進的多輪資訊收集策略，使醫師智能體能夠像資深精神科醫師一樣，在開放式探詢與聚焦式提問之間靈活切換，以提升關鍵線索的獲取效率。其次，針對共病識別與細粒度鑑別診斷設計專門的訓練目標、知識圖譜增強機制或神經符號推理架構，將是彌補現有模型在複雜病例上性能缺口的關鍵路徑。最後，將評測框架擴展至更多語言、更廣泛的精神疾患類別，並結合真實臨床試驗進行前瞻性驗證，將是確認 AI 系統在實際醫療場景中有效性、安全性與倫理合規性的必要下一步。

## 實務應用指南

### 適用場景

1. **精神科 AI 輔助診斷系統上線前驗證**：利用 LingxiDiagBench 的靜態診斷推論與動態多輪會診任務，對大型語言模型進行二元憂鬱–焦慮分類、憂鬱–焦慮共病識別及 12 類鑑別診斷的壓力測試，確保模型在部署至臨床決策支援系統前，已通過電子病歷對齊的標準化評測。
2. **醫學教育與住院醫師虛擬會談訓練**：以 Patient Agent 模擬具備真實臨床人口統計與診斷分佈的患者，讓醫師在無風險環境中練習資訊收集策略，並由 Diagnostic Agent 依據 ICD-10 精神科類別提供即時回饋，強化會談式診斷能力。
3. **醫院電子病歷系統之鑑別診斷建議模組**：將合成會診對話的生成邏輯與院內電子病歷串接，自動提取病史特徵並輸出鑑別診斷建議，作為精神科醫師撰寫病歷時的輔助參考。
4. **跨模型或跨院區診斷能力基準比較**：透過 LingxiDiag-16K 建立可重現研究標準，定期評比不同大型語言模型版本或不同院區 AI 系統的診斷準確率與會診品質，作為採購與持續優化的客觀依據。
5. **遠距醫療平台之智能病史收集前導**：在正式會診前部署 Doctor Agent 進行自動化多輪問診，收集結構化主訴與症狀史，縮短精神科醫師的重複性問診時間，提升心理健康評估效率。

### 實作前置條件

- **資料面**：須取得 LingxiDiag-16K 或具備同等規模的電子病歷對齊之中文精神科對話資料，並確保具備 ICD-10 精神科類別標註；若使用院內真實電子病歷，需完成去識別化與倫理審查。
- **運算資源**：靜態評測至少需要可執行大型語言模型推論的 GPU 叢集（如 A100 80GB）或商用 API 額度；動態多智能體框架需額外配置多輪對話狀態管理與並行運算資源。
- **技術與領域知識**：團隊需具備 Python 自然語言生成實作能力、多智能體框架（如 LangChain、AutoGen）開發經驗，以及至少一名精神科醫師參與驗證臨床醫師驗證的診斷標籤與會診品質評分標準。

### 實作步驟建議

1. **環境建置與資料對齊**：複製 LingxiDiagBench 開源框架，下載 LingxiDiag-16K，確認資料集的人口統計與語言分佈與目標部署場域一致。
2. **靜態診斷推論基線建立**：先以固定合成會診對話執行 2／4／12 類分類任務，記錄 Top-1／Top-3 診斷準確率與 Macro F1，作為後續動態評測的對照基線。
3. **多智能體框架開發**：依據論文架構實作 Patient Agent（模擬患者行為）、Doctor Agent（執行病史詢問）與 Diagnostic Agent（進行證據導向診斷），並以 ICD-10 準則作為診斷決策的知識錨點。
4. **動態多輪會診模擬**：啟動 Doctor Agent 與 Patient Agent 的即時互動，記錄每輪對話內容，評估資訊收集策略是否有效覆蓋鑑別診斷所需的關鍵症狀。
5. **聯合評估與臨床驗證**：同時採用 LLM 作為評審（評分會談品質）與臨床醫師驗證的診斷標籤（評分診斷準確率），特別注意兩者僅具中度相關性，應分別設定通過門檻。
6. **部署上線與持續監控**：將通過評測的模型整合至醫院資訊系統或遠距平台，並針對憂鬱–焦慮共病識別等弱項設置人機協作覆核機制，定期以新進電子病歷回測模型表現。

### 潛在風險與注意事項

- **共病識別瓶頸**：論文顯示憂鬱–焦慮共病識別率僅 43.0%，實務上若遇到多重精神障礙患者，系統極易漏診，必須設計強制轉介精神科醫師複核的流程。
- **動態資訊收集策略失效**：動態多輪會診表現可能劣於靜態評估，代表 Doctor Agent 的提問邏輯若設計不良，將直接損害下游診斷推理，建議導入臨床標準作業程序（SOP）引導提問順序。
- **LLM 作為評審之局限性**：會談品質與診斷準確率僅中度相關，切勿僅因對話結構良好就放行上線，需以診斷標籤為最終依歸。
- **資料隱私與倫理**：即使使用合成會診對話，若訓練資料源自真實電子病歷，仍需確認去識別化完整，並通過醫院倫理委員會審查。
- **文化與語言特異性**：本框架針對中文精神科會診設計，語言風格、症狀描述與社會文化脈絡均具特異性，逕直翻譯為其他語言使用可能導致診斷分佈偏移。
- **臨床責任歸屬**：AI 輔助精神科診斷僅能作為支援工具，最終會談式診斷與處置決策仍須由精神科醫師負責，產品設計應明確標示輔助性質並留存決策軌跡。

### 與其他技術的整合建議

- **電子病歷與醫院資訊系統（HIS）**：透過 HL7 FHIR API 將 LingxiDiagBench 的評測模組與院內電子病歷串接，使合成會診對話的格式與實際病歷欄位對齊，降低部署時的資料轉換成本。
- **臨床決策支援系統（CDSS）**：將 Diagnostic Agent 作為 CDSS 的鑑別診斷外掛模組，在醫師書寫病歷時即時提示 ICD-10 精神科類別可能性，並提供對應的證據鏈。
- **檢索增強生成（RAG）**：串接中文精神科臨床指引、藥物資料庫與 ICD-10 準則，彌補大型語言模型在專業知識上的幻覺問題，提升靜態診斷推論的穩健性。
- **遠距醫療與線上會診平台**：將 Patient Agent 與 Doctor Agent 的互動邏輯嵌入線上諮詢流程，作為初診前的自動化心理健康評估，並將對話摘要回寫至後端電子病歷。
- **人機協作介面**：為精神科醫師設計可即時覆寫 AI 建議、標註錯誤診斷的回饋介面，讓臨床醫師驗證的診斷標籤能持續回流至訓練資料，形成模型迭代閉環。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從圖一框架總覽與三項核心任務（二元憂鬱–焦慮分類、四類分類、12 類鑑別診斷）入手，理解「為何需要動態多輪會診而非單輪問答」即可；技術細節如 BLEU、ROUGE-L、BERT-Score 與 LLM 作為評審的設計可先略過，待熟悉臨床對話基準測試的基本概念後再回頭細讀。
- **AI 工程師**：請重點關注多智能體框架的實作細節、從電子病歷到合成會診對話的資料生成管線，以及動態評測低於靜態評測的實驗發現；建議先復現靜態診斷推論的程式碼基線，再逐步擴展至多輪對話狀態管理與 Patient Agent 的行為模擬。
- **研究人員**：論文對現有臨床對話基準測試的三項限制（缺乏真實對話變異性、缺少臨床醫師驗證的診斷標籤、不支援動態多輪會診）是重要的研究缺口；此外，電子病歷對齊的資料建構方法、動態與靜態評測的效能落差，以及會談品質與診斷準確率的不對稱性，均適合做為後續醫療 AI 評測文獻的引用與延伸研究方向。
- **產品經理**：請聚焦三大實證發現：模型在簡單二元分類表現優異（92.3%），但在憂鬱–焦慮共病識別（43.0%）與 12 類鑑別診斷（28.5%）大幅衰退；同時，良好的會談品質不等同於正確診斷。這些數據應直接轉化為產品路徑圖中的風險控管點，例如優先鎖定單一疾病篩查場景、強制保留人類醫師最終決策權，並避免以對話流暢度作為上線指標。
