# R^3-Bench：大型語言模型在共享預算下的資源理性推理困境

## ⚡ TL;DR

現有基準多為獨立預算，無法衡量 LLM 在共享預算下實現單題能力的資源理性推理。
本文提出 R^3-Bench，以六題題組橫跨數學、競技程式與抽象推理，並以配對單題反應曲線建立離線經驗神諭。
結果顯示模型展現能力與共享預算表現間存在持續落差，策略更新有限且失敗模式隨壓力而變。

## 摘要翻譯

在認知科學（cognitive science）中，資源理性（resource rationality）探討智能體（agent）應如何分配有限計算資源（limited computational resources）以最大化期望價值（expected value）。大多數推理基準測試（reasoning benchmark）與智能體基準測試（agent benchmark）採用獨立的每項任務預算（per-task budget）；現有的共享預算（shared budget）研究亦未將題組表現（suite performance）與同一模型展現出的單題能力（single-problem competence）進行校準。我們提出 R^3-Bench，於無工具（tool-free）與智能體設定（agentic settings）兩種設定中，在數學（mathematics）、競技程式設計（competitive programming）與抽象推理（abstract reasoning）領域評估共享預算下的六題題組（six-problem suites）。配對單題反應曲線（matched single-problem response curves）根據觀察到的成功（observed successes），定義出一個離線經驗神諭（offline empirical oracle）。在六個模型的 72 個主表單元格（main-table cells）中，神諭平均值（oracle mean）在所有單元格皆達到或超過競賽平均值（contest mean），並在 71 個單元格中嚴格更高。在中等無工具壓力（tool-free pressure）下，對六個模型中的四個，均等分配重播（equal-allocation replay）亦優於競賽表現。軌跡診斷（trajectory diagnostics）顯示策略更新（strategy updating）有限，並呈現隨壓力變化的失敗模式（pressure-dependent failure patterns）。在強智能體壓力（strong agentic pressure）下的三模型診斷（three-model diagnostic）中，至少有一個固定排程器（fixed scheduler）在九個單元格中的六個超過競賽平均值，但沒有任何策略（policy）跨領域（domains）佔據主導地位。這些結果凸顯出展現出的能力（demonstrated competence）與共享預算實現（shared-budget realization）之間存在持續落差。

### 核心貢獻（3～5點）
- 提出 R^3-Bench，首個將題組表現與單題能力進行校準的共享預算推理基準測試，涵蓋數學、競技程式設計與抽象推理三大領域。
- 建立離線經驗神諭（offline empirical oracle），透過配對單題反應曲線量化模型在共享預算下應有的最佳表現。
- 發現大型語言模型在共享預算下的實際表現遠低於其展現出的單題能力，存在持續的資源理性推理落差。
- 透過軌跡診斷揭示模型在壓力下的策略更新有限與隨壓力變化的失敗模式。
- 顯示即使簡單的固定排程器（fixed scheduler）與均等分配重播（equal-allocation replay）策略，也常能超越現有模型的競賽表現，凸顯資源分配策略的重要性。

### 適合對象
適合對大型語言模型評估、認知科學中的資源理性、多工資源分配策略，以及 AI 推理與智能體系統設計感興趣的研究人員與工程師。特別是關注測試時擴展（test-time scaling）、推論時間運算（inference-time computation）與真實智能體工作流程（real agent workflows）中資源競爭問題的讀者。

## 深度分析

#### 方法論解析

R^3-Bench（Resource-Rational Reasoning Benchmark，資源理性推理基準測試）的核心設計目標，是將「單題能力（single-problem competence）」與「題組表現（suite performance）」分離，從而檢驗大型語言模型（LLMs）在共享預算（shared budget）下能否實現其已展現的能力。傳統推理基準測試（reasoning benchmark）與智能體基準測試（agent benchmark）通常為每道題目分配獨立的每項任務預算（per-task budget），模型可以無須考慮機會成本地將全部資源投入單一問題。R^3-Bench 則將六道題目組成六題題組（six-problem suites），所有題目共享同一計算預算，形成明確的資源分配問題（resource-allocation problem）。

在題組層級，R^3-Bench 橫跨三個領域（domains）：奧林匹克風格數學（mathematics）、競技程式設計（competitive programming）與抽象推理（abstract reasoning），並同時評估無工具（tool-free）與智能體設定（agentic settings）兩種情境。每個 episode 為一場六題競賽，模型必須在固定預算內決定：對每道題目投入多少 token（詞元）、牆鐘時間（wall-clock time）、工具呼叫（tool calls）與驗證器互動（verifier interactions），以及何時切換題目或停止。這種設計直接對應真實智能體工作流程（real agent workflows）中多個並行任務（concurrent tasks）爭奪有限 API 配額（API quotas）、推論容量（inference capacity）與外部端點（external endpoints）的場景。

為了區分「會不會解」與「會不會分配」，作者提出三項關鍵方法論工具：

1. **配對單題反應曲線（matched single-problem response curves）**：針對同一模型，在與題組相同設定下單獨執行每道題目，記錄不同資源投入下的成功機率。這些曲線構成模型在隔離條件下已展現能力的經驗基準。

2. **均等分配重播（equal-allocation replay）**：將題組總預算平均分配給六道題目，並依據單題反應曲線重播模型表現。這是一個簡單但強大的對照策略，用於檢驗「只要平均分配」是否能超越模型在實際競賽中的策略。

3. **離線經驗神諭（offline empirical oracle）**：在已知單題反應曲線與題組總預算的前提下，離線選擇一組觀察到的成功（observed successes），使其在預算限制下最大化期望價值（expected value）。該神諭並非可執行策略（policy），而是一個診斷性上界，用於衡量模型「理論上能達到」的題組表現。

透過這三項工具，R^3-Bench 能夠量化「展現出的能力（demonstrated competence）」與「共享預算實現（shared-budget realization）」之間的落差。此外，作者還定義了行為層級指標，包括題目覆蓋率（problem coverage，即模型對題目槽位產生可見且實質的題目專屬工作的比例）與資源理性策略更新率（resource-rational strategy-update rate，即策略改變能回應新證據與剩餘共享預算的比例），以診斷模型在軌跡（trajectory）層級的適應行為。

#### 實驗數據解讀

主實驗涵蓋六個旗艦模型（flagship models）：DS-Pro、Opus（Claude Opus）、Qwen（通義千問）、GLM、Hy 與 GPT，並在 72 個模型–設定–壓力–領域單元格（main-table cells）中進行比較。結果顯示，離線經驗神諭平均值（oracle mean）在所有 72 個單元格中都等於或高於競賽平均值（contest mean），並在 71 個單元格中嚴格更高。這意味著：若模型能根據自身單題能力進行理想分配，其題組表現幾乎必然優於它在實際共享預算競賽中的表現。換言之，現有 LLM 在共享預算下的行為並未充分實現其已展現的能力。

更具體地，在中度無工具壓力（moderate tool-free pressure）下，單純的均等分配（equal allocation）對六個模型中的四個已能超越其競賽策略（contest policy）。這是一個強烈的診斷訊號：模型在題組層級的資源分配甚至不如「平均分配」這一簡單基線。無論是給予較大預算（larger budget）或提供工具（tools），都無法一致地彌合此落差，顯示問題根源不在於絕對計算量，而在於跨題目的資源配置決策。

圖 1 的行為觀點（behavioral view）進一步補充了這一結論：六個模型中有五個的題目覆蓋率超過 50%，表示它們大多會嘗試處理大部分題目；然而只有 DS-Pro 的資源理性策略更新率超過 50%。這說明「廣泛接觸題目」並不等價於「資源理性行為」——模型雖然會看很多題，卻鮮少根據剩餘預算與解題進展動態調整策略。

軌跡診斷（trajectory diagnostics）揭示了隨壓力變化的失敗模式（pressure-dependent failure patterns）。在強壓力（strong pressure）下，被神諭選中但競賽中錯失的題目，最常見原因是模型將共享預算耗盡（exhausting the shared budget）在其他題目上；而在中度壓力下，則更常見於模型在部分進展後就停止。這兩類失敗都發生在模型「已經能在單題情境下解出」的題目上，因此問題歸因於分配（allocation）——哪些題目獲得預算、獲得多少——而非基礎能力限制。

作者還進行了三模型診斷（three-model diagnostic），在強智能體壓力（strong agentic pressure）下測試固定排程器（fixed scheduler）。結果顯示，在九個模型–領域單元格中，至少存在一種固定排程器能在六個單元格中超越競賽平均值；但沒有任何單一策略（policy）能在所有領域中同時占優。這指出跨領域轉移（cross-domain transfer）的排程策略仍具挑戰性，資源理性行為具有領域依賴性（domain-dependent effects）。

值得注意的是，作者以超過五十個基準測試的綜合能力分數作為控制變項，發現能力分數相差僅兩分的模型，其 Gap Ratio（衡量能力與共享預算實現之間落差的指標）可相差高達 60.6 個百分點。這強烈說明 R^3-Bench 測量到的並非一般能力（general capability）的重新表述，而是一種獨立的資源理性推理能力。

#### 與現有研究的比較

現有研究主要可分為兩大類：獨立每項任務預算的推理與智能體評估，以及部分考慮預算意識（budget-aware）或資源分配的研究。

第一類包括數學、科學問答、圖問題等推理基準測試（如 Hendrycks et al., 2021；Rein et al., 2023；Tang et al., 2025；Zheng et al., 2025），以及智能體基準測試（如 Liu et al., 2024；Jimenez et al., 2024；Mialon et al., 2024；Zhang et al., 2025）。這些工作雖然推動了單題推理與工具使用能力，但皆未將多個題目置於同一共享預算下，因此無法觀察跨題目資源分配的決策行為。

第二類是預算意識相關研究，例如 Wang et al. (2024)、TALE（Han et al., 2025）、SelfBudgeter（Li et al., 2025）、BATS（Liu et al., 2025）、GeneralAgentBench（Li et al., 2026）、ZEBRA（Hamri & Talgam-Cohen, 2026）、USACOArena（Zhou et al., 2026）與 CLEAR（Wan et al., 2026）。根據文中表 1，這些研究大多僅涵蓋單一設定（tool-free 或 agentic）、單一領域（數學或程式），或未採用真正的共享預算。R^3-Bench 的獨特之處在於同時具備：評估（evaluation）、無工具與智能體雙設定、數學／程式／抽象推理三領域，以及真正的共享預算。

相較於這些先驅工作，R^3-Bench 的主要貢獻與改進包括：

- **以同一模型的單題能力作為校準基準**：過往共享預算研究未將題組表現與模型自身在隔離條件下的單題能力進行對照。R^3-Bench 透過配對單題反應曲線與離線經驗神諭，首次系統性地分離「能力」與「實現」。
- **橫跨多領域與雙設定**：不同於僅聚焦數學或僅聚焦程式競賽的工作，R^3-Bench 同時納入抽象推理，並比較無工具與智能體情境，使結論更具一般性。
- **揭示非能力因素的落差**：透過 Gap Ratio 與綜合能力分數的控制分析，證明共享預算下的表現落差無法被一般能力解釋，而是一種獨立的資源理性推理缺陷。

然而，R^3-Bench 也存在若干限制。首先，實驗僅涵蓋六個模型與三個領域，樣本規模有限；其次，六題題組的結構雖然靈感來自競技程式設計競賽（如 ICPC、IOI），但是否能推廣到更長、更動態的真實智能體工作流程仍需驗證。再者，離線經驗神諭雖然提供了強有力的診斷上界，但它並非可執行策略，無法直接轉化為線上決策演算法。最後，實驗中的預算壓力（budget pressure）是研究者預設的，模型在真實部署中面對的資源競爭（resource contention）可能更為複雜。

#### 可重現性評估

就本文提供的上下文而言，R^3-Bench 目前為 preprint 形式，尚未明確提及原始碼、資料集、提示詞（prompts）、模型 API 版本或完整軌跡日誌的公開連結。因此，從可重現性（reproducibility）角度評估，現階段仍屬「待補強」狀態。

要達成高品質可重現性，作者未來應釋出以下項目：

- **R^3-Bench 資料集**：包含所有六題題組、題目難度標註、預期資源需求與參考解答。
- **評估腳本與原始碼**：涵蓋題組生成、共享預算執行、配對單題反應曲線估計、離線經驗神諭計算、Gap Ratio 與覆蓋率等指標的實作。
- **模型版本與 API 設定**：明確記錄 DS-Pro、Opus、Qwen、GLM、Hy、GPT 等旗艦模型的具體版本、溫度參數、最大輸出長度與工具呼叫介面。
- **提示詞與智能體框架**：公開無工具與智能體設定下使用的系統提示、工具描述、停止條件與切換邏輯。
- **軌跡資料**：釋出部分或全部模型在競賽中的軌跡（trajectory），以便其他研究者進行軌跡診斷與策略更新分析。

由於實驗涉及多個商業 API 模型，完全重現可能需要相當的計算成本與 API 費用；但透過釋出標準化腳本與資料集，社群至少能在相同或類似模型上進行對照實驗。若作者能參照如 BIG-Bench、SWE-bench 等基準測試的開源模式，將大幅提升 R^3-Bench 的影響力與可信度。

#### 未來研究方向

R^3-Bench 所揭示的資源理性推理缺口，為多個後續研究方向開闢了道路：

1. **可執行的線上資源理性策略（online resource-rational policies）**：目前離線經驗神諭僅作為上界，未來可發展能根據解題進度、中間結果與剩餘預算動態調整的線上策略，例如基於強化學習（reinforcement learning）或元推理（meta-reasoning）的排程器。

2. **資源理性能力的訓練與對齊**：探索透過成本感知 RLHF（cost-aware RLHF）、課程學習（curriculum learning）或專門的資源分配資料集，提升模型在共享預算下的動態停止、切換與工具使用決策。

3. **多智能體共享預算（multi-agent shared budgets）**：將單一模型擴展至多個並行智能體（concurrent agents），研究智能體間的資源競爭、協作與任務委派機制，更接近真實程式設計智能體工作流程。

4. **跨領域轉移的通用排程器**：由於固定排程器呈現領域依賴效應，未來可研究如何學習跨數學、程式與抽象推理領域泛化的通用資源分配策略。

5. **信心度校準與預算分配**：發展能準確估計「再投入多少資源可提高成功機率」的信心度模型，並將其整合進預算分配決策。

6. **真實世界成本模型**：將 token 數、牆鐘時間、工具呼叫次數與金錢成本統一納入成本函數，設計更符合商業部署情境的評估與最佳化目標。

7. **人類資源理性行為對照**：比較人類參與者在相同題組與時間壓力下的分配策略，借鏡認知科學（cognitive science）中的理性分析（rational analysis）與資源理性分析（resource-rational analysis），為 LLM 設計提供理論基礎。

8. **更大規模與更長期的工作負載**：將六題題組擴展至數十甚至數百個任務的長期工作負載，研究預算耗盡、任務優先順序與動態到達任務對資源理性行為的影響。

總結而言，R^3-Bench 不僅提出了一個新的評估框架，更重要的是它將「資源理性推理」從認知科學概念轉化為可量化的 LLM 能力缺口。未來研究若能針對此缺口發展可執行、可訓練且跨領域泛化的資源分配機制，將對真實智能體系統的效率與可靠性帶來顯著提升。

## 論文問答

**Q1：什麼是「共享預算下的資源理性推理」，為什麼對現代大型語言模型很重要？**
A：資源理性推理（resource-rational reasoning）指智能體在有限計算資源下，權衡額外推論或工具呼叫的預期收益與機會成本，以最大化整體期望價值。當多個題目或任務共享同一預算時，花費在一題上的 token、牆鐘時間或工具呼叫會直接減少其他題目可用的資源，因此模型不僅要會解題，還要決定何時停止、切換或繼續投入。這對現代大型語言模型非常重要，因為真實智能體工作流程（如程式設計智能體同時進行建置、除錯、測試）常面臨 API 配額與推論容量的資源競爭，單題能力強並不保證能在共享預算下有效發揮。

**Q2：現有的推理與智能體基準測試為什麼無法評估這種能力？**
A：現有推理基準測試通常對每道題目給予獨立的每項任務預算，模型可以全力解每一題，無須考慮其他題目的資源需求。智能體基準測試也多半將每個任務單獨計費，因此跨題分配資源的問題從未被真正檢驗。即使有少數共享預算的研究，也未將題組表現與同一模型在單題上的展現能力進行校準，導致無法區分「模型不會解」與「模型不會分配」。

**Q3：為什麼區分「單題能力」與「共享預算實現」對評估與應用至關重要？**
A：若只看單題表現，我們會高估模型在真實多工情境下的效能，因為它無法反映資源競爭帶來的機會成本。許多失敗並非源於解題能力不足，而是源於錯誤的資源分配——例如在部分題目上過早放棄，或在其他題目上耗盡預算。只有將兩者分離，才能診斷出模型是否具備資源理性行為，並據此設計更好的停止規則、排程器與智能體工作流程。

**Q4：R^3-Bench 的核心方法架構是什麼？**
A：R^3-Bench 將每場評估設計為一個六題題組的競賽，所有題目共享單一計算預算，涵蓋數學、競技程式設計與抽象推理三個領域，並分別在無工具與智能體設定下進行。為了分離能力與實現，作者使用配對單題反應曲線，記錄同一模型在單獨解題時不同預算下的成功機率。基於這些曲線，再建立離線經驗神諭與均等分配重播兩種診斷工具，以比較模型在共享預算下的實際競賽表現與其可達成的上限。

**Q5：這項研究的方法創新主要體現在哪裡？**
A：主要創新在於首次以「同一模型的單題反應曲線」作為校準基準，把題組表現對照到模型已經展現出的單題能力，從而量化共享預算實現缺口。離線經驗神諭並非可執行策略，而是一種事後診斷：它在給定總預算下，從觀察到的成功紀錄中挑選最佳組合，告訴我們模型「理論上」能解多少題。這種設計讓研究者能明確區分「能力缺陷」與「分配缺陷」，而不會把資源配置錯誤誤判為推理能力不足。

**Q6：為什麼選擇六題題組、三個領域，以及同時評估無工具與智能體設定？**
A：六題題組的規模足以產生有意義的資源競爭，同時保持實驗可控，便於分析跨題分配決策。選擇數學、競技程式設計與抽象推理三個領域，是因為它們對計算資源的需求差異大，能測試模型是否依題目難易與剩餘預算調整策略。同時納入無工具與智能體設定，則可檢驗工具呼叫與外部驗證器互動是否會改變資源分配行為，並觀察在真實智能體工作流程中預算壓力的影響。

**Q7：實驗涵蓋哪些模型、設定與預算壓力條件？**
A：主實驗涵蓋六個旗艦模型，包括 DS-Pro、Opus、Qwen、GLM、Hy 與 GPT，並在無工具和智能體兩種設定下進行。每個設定又區分為中度與強烈的預算壓力，總共形成 72 個主表單元格，橫跨模型、設定、壓力與領域的組合。這樣的設計讓作者能系統性地比較不同模型在資源緊縮程度與工具可用性變化時的表現差異。

**Q8：實驗的主要結果是什麼？**
A：結果顯示，在全部 72 個主表單元格中，離線經驗神諭的平均值都等於或高於實際競賽平均值，且在 71 個單元格中嚴格更高，顯示存在持續的共享預算實現缺口。在中度無工具壓力下，單純的均等分配重播也能在四個模型中勝過實際競賽策略，說明模型連基本的固定分配都未能達成。此外，軌跡診斷發現模型在解題過程中很少根據新證據與剩餘共享預算進行資源理性策略更新，失敗模式也會隨壓力強弱而改變。

**Q9：軌跡診斷與排程器實驗進一步揭示了什麼？**
A：軌跡分析顯示，五個模型能覆蓋超過一半的題目槽位，但只有 DS-Pro 的資源理性策略更新率超過 50%，可見「有看到題目」不等於「會理性分配」。在強烈智能體壓力下，固定排程器在三模型診斷中於九個模型—領域單元格中的六個勝過實際競賽平均值，但沒有任何單一策略能在所有領域中同時稱霸。這表示簡單的預設分配規則就能帶來部分改善，但跨領域轉移的通用資源分配策略仍是未解挑戰。

**Q10：這項研究對哪些真實應用場景最具啟發？**
A：最典型的場景是程式設計智能體工作流程，例如同時進行建置、除錯、測試與部署，這些並行任務會競爭有限的 API 配額與推論容量。另一個場景是多智能體系統，當多個並行智能體共享同一推理預算時，某個任務過度呼叫工具會排擠其他任務的可用資源。此外，任何需要在固定 token 或時間預算內處理多份文件、多個查詢或多次驗證的線上服務，都可視為共享預算問題。

**Q11：對 LLM 產品與系統設計有哪些具體啟示？**
A：產品設計者不應只追求更大的單題預算或更多工具，因為研究顯示預算增加與工具可用性並未均勻縮小共享預算缺口。系統需要內建動態預算監控與停止規則，讓模型能根據已花費資源、當前進展與剩餘題目難度決定是否繼續。此外，應提供任務切換與重新排程的機制，並在智能體框架中將工具呼叫與驗證器互動納入整體資源成本計算，避免單一任務耗盡共享配額。

**Q12：R^3-Bench 對整個 LLM 研究領域可能帶來什麼影響？**
A：它將評估焦點從「單題正確率」轉移到「資源理性行為」，促使研究者正視測試時擴展與工具使用背後的機會成本。透過提供可重現的共享預算題組與離線神諭校準方法，R^3-Bench 為未來的推理基準測試與智能體基準測試樹立了新的評估維度。長遠來看，這有助於發展出更能適應真實資源限制、並在並行任務間做出明智取捨的下一代語言智能體。

**Q13：作者承認哪些方法上的限制？**
A：離線經驗神諭是一種事後診斷工具，並非可執行的線上策略，因此不能直接部署為智能體的決策機制。均等分配重播同樣不具適應性，無法根據解題過程中的新證據動態調整。此外，實驗目前聚焦於六題題組與三個特定領域，雖然已具代表性，但尚不能完全涵蓋真實世界中更長、更動態、且任務間相依性更強的工作流程。

**Q14：模型在共享預算下主要出現哪些失敗模式？**
A：在強烈預算壓力下，許多本可解決的題目之所以失敗，是因為模型把共享預算耗盡在其他題目上，導致後續題目無資源可用。在中度壓力下，失敗則更常來自過早停止——模型在取得部分進展後放棄，未能繼續投入足夠資源完成證明或程式。這兩種模式都指向資源分配問題，而非基本解題能力不足，因為這些題目在單題設定中已被模型成功解出。

**Q15：未來研究可以朝哪些方向延伸？**
A：未來可發展真正可執行的線上資源分配策略，例如基於模型自信度、中間驗證結果與剩餘預算進行即時停止與切換決策。也可以將 R^3-Bench 擴展到更多領域、更長的任務序列，以及具有真實相依關係的並行智能體工作流程。另一個重要方向是結合從反饋中學習與元推理，讓模型在多次共享預算經驗後自動改進其資源理性策略，並縮小展現能力與共享預算實現之間的缺口。

## 實務應用指南

## 適用場景

1. **多工並行的程式設計智能體工作流程**  
   當單一智能體需要同時處理建置、除錯、測試與部署等多個子任務，且共享同一 API 配額或推論容量時，可運用 R³-Bench 的共享預算框架診斷資源是否被錯誤配置。

2. **有限 token 或工具呼叫額度下的數學 / 科學推理服務**  
   例如線上解題助手、自動批改或競賽輔導系統，需要在多道題目之間分配推論時間運算與驗證器互動次數，避免在單一難題上耗盡整體預算。

3. **多步驟研究與分析管線**  
   市場分析、法律文件審閱或醫學文獻綜整等場景中，模型必須決定要深入處理哪些文件、哪些僅需淺層掃描，並在共享預算下最大化整體產出價值。

4. **客戶支援與工單分類系統**  
   面對大量湧入的工單，系統需在固定回應時間或成本預算內，決定哪些案件需要深度推理、哪些可快速結案，以提升平均解決率。

5. **模型選型與部署前的資源理性評估**  
   在採購或上線新模型前，可用 R³-Bench 的題組評估比較不同旗艦模型在共享預算下的實際表現，避免僅憑單題能力或綜合基準分數下決策。

## 實作前置條件

- **資料準備**：需要一組可控制的六題題組（或自訂大小的題組），涵蓋目標領域（如數學、競技程式設計、抽象推理），並具備可驗證的成功標準（例如單元測試、答案比對）。
- **單題反應曲線**：必須先收集每個模型在「無工具」與「智能體設定」下、不同預算水準的單題能力數據，作為後續均等分配重播與離線經驗神諭的基礎。
- **計算資源**：需有足夠的 API 配額或本地推論容量來重複執行題組；若要做軌跡診斷，還需要儲存與分析大量中間步驟的日誌。
- **評測基礎建設**：需具備可重現的共享預算執行環境，能統一追蹤 token 消耗、牆鐘時間、工具呼叫次數與驗證器互動次數。
- **團隊技能**：需要熟悉提示工程、智能體框架、基準測試設計，以及基礎的實驗設計與統計分析能力。

---

## 實作步驟建議

1. **定義任務題組與預算單位**  
   依產品場景選定 3–6 個代表性任務，並決定共享預算的計量單位（token 數、推論步驟、工具呼叫次數或牆鐘時間）。

2. **建立單題能力基線**  
   對每個任務執行多種預算水準的單題運行，記錄成功與否，繪製配對單題反應曲線。

3. **建構共享預算評測環境**  
   開發一個可強制中斷或限制總預算的執行器，讓模型在題組內自行決定每題分配多少資源。

4. **實作對照策略**  
   至少實作兩種基線：均等分配重播（將總預算平均分配給每題）與離線經驗神諭（根據單題反應曲線挑選可達成的成功組合）。

5. **執行題組競賽與診斷**  
   在「無工具」與「智能體設定」、不同預算壓力下執行多次，記錄軌跡，分析題目覆蓋率與資源理性策略更新率。

6. **設計並測試線上排程器**  
   根據診斷結果嘗試固定排程器或輕量級線上策略，觀察是否能在特定領域縮小 Gap Ratio。

7. **迭代與部署監控**  
   將表現最佳的策略整合進產品，並持續監控實際運行中的預算耗用模式與失敗案例。

## 潛在風險與注意事項

- **混淆能力與分配問題**  
  共享預算下的低分可能不是模型能力不足，而是資源分配錯誤。建議同時呈現單題能力、神諭平均值與競賽平均值，避免誤判。

- **離線神諭不可直接執行**  
  離線經驗神諭是診斷上限，不是可部署策略；產品中仍需設計可線上運作的排程器或元認知機制。

- **領域差異大，策略難以跨域遷移**  
  論文發現沒有單一策略能在所有領域稱霸，因此應針對每個領域單獨調校，或採用領域感知的路由器。

- **預算壓力設定失準**  
  壓力過強會導致模型耗盡共享預算於其他題目；壓力過弱則無法顯現分配問題。建議使用多個壓力水準進行測試。

- **工具成本異質性**  
  在智能體設定中，不同工具呼叫的成本差異很大，需將工具呼叫次數與延遲一併納入預算計算，而非只看模型輸出 token。

- **過度擬合特定題組**  
  若題組過小或題型過於單一，可能會高估或低估實際表現，建議使用多組獨立題組並報告平均與變異。

## 與其他技術的整合建議

- **智能體框架（如 LangChain、AutoGen、OpenAI Agents SDK）**  
  可將 R³-Bench 的共享預算執行器包裝成上層協調器，在每次決定「繼續思考、呼叫工具或切換任務」前檢查剩餘共享預算。

- **可觀測性平台（如 LangSmith、Weights & Biases、OpenTelemetry）**  
  透過統一追蹤 token 消耗、工具呼叫與驗證器互動，將軌跡診斷自動化，並在生產環境中持續監控 Gap Ratio。

- **成本與速率限制閘道**  
  在 API 閘道層設定動態預算上限與配額分配，避免單一任務耗盡整體配額，並與 R³-Bench 的預算單位對齊。

- **強化學習或微調**  
  可將 R³-Bench 的題組執行結果轉化為獎勵訊號，訓練模型學習何時停止、切換或呼叫工具，以提升資源理性策略更新率。

- **檢索增強生成（RAG）與驗證器**  
  在智能體設定中，可將外部驗證器與 RAG 模組視為需要消耗預算的工具，並根據剩餘預算決定是否進行檢索或驗證。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從摘要與圖 1 開始，理解「共享預算」與「單題能力」的區別，接著閱讀第 3 節的方法論，掌握六題題組、均等分配重播與離線經驗神諭的基本概念，暫時跳過複雜的軌跡診斷細節。

**AI 工程師**：應重點閱讀方法論與實驗設計，特別是預算單位、題組執行環境與軌跡診斷的實作細節，並參考論文附錄中的完整定義，將評測流程移植到自身的智能體產品中。

**研究人員**：建議深入分析主表中的 72 個模型–設定–壓力–領域單元格，以及 Gap Ratio 的計算方式，進一步探討為何在 71/72 的單元格中神諭平均值嚴格高於競賽平均值，並思考如何設計可學習的線上資源分配策略。

**產品經理**：可聚焦於適用場景、圖 1 的行為觀點，以及潛在風險與注意事項，將 R³-Bench 視為評估模型在真實多工工作流程中「性價比」的工具，並用 Gap Ratio 與題目覆蓋率作為上線前的決策依據。
