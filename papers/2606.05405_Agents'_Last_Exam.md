## ⚡ TL;DR

AI基準測試與實際經濟效益脫節，缺乏對真實專業工作流程的持續評估。
本文提出「代理人期末考驗」，涵蓋千項真實任務與可驗證成果，由兩百多位專家協作建構。
當前最強代理人在最難層級通過率不足一成，均分僅二點六％，顯示其能有效衡量AI與經濟影響的差距。

## 摘要翻譯

近期 AI 系統雖在眾多基準測試（benchmark）上取得優異成果，然而這些進展並未轉化為諸多專業領域中具經濟意義的實際部署。我們認為，此差距很大程度上屬於評估問題（evaluation problem）：現行基準測試（benchmark）缺乏針對真實且具經濟價值工作流程的持續效能衡量（sustained performance measurement）。本文提出代理人期末考驗（Agents' Last Exam, ALE），此基準測試（benchmark）旨在評估 AI 代理人（AI agents）於長程（long-horizon）、具經濟價值且結果可驗證之真實世界任務上的表現。ALE 與超過 250 位產業專家合作開發，涵蓋參照 O*NET / SOC 2018（美國聯邦職業分類系統）所定義的非實體產業。該基準測試（benchmark）以任務分類架構（task taxonomy）為核心，包含 55 個子領域（subfields），並歸類為 13 個產業群集（industry clusters），涵蓋逾 1,000 項任務。目前的結果顯示，最高難度等級仍遠未達飽和：在主流測試框架（harness）與骨幹模型（backbone）配置下，平均完全通過率（full pass rate）僅為 2.6%。ALE 被設計為持續演進的基準測試（living benchmark）：隨著新工作流程與產業的納入，其任務池將持續擴充。更廣義而言，ALE 不僅旨在成為另一個排行榜（leaderboard），更是縮小基準測試成果與 GDP 相關影響（GDP-relevant impact）之間差距的工具。

### 核心貢獻（3～5點）
- 指出當前 AI 系統在基準測試（benchmark）上的成功與實際經濟部署之間的落差，很大程度上屬於評估問題（evaluation problem），即缺乏針對真實且具經濟價值工作流程的持續效能衡量（sustained performance measurement）。
- 提出代理人期末考驗（Agents' Last Exam, ALE），專為評估 AI 代理人（AI agents）在長程（long-horizon）、具經濟價值且結果可驗證之真實世界任務上的表現而設計。
- 與超過 250 位產業專家協作，依據 O*NET / SOC 2018 建構涵蓋 55 個子領域、13 個產業群集、逾 1,000 項任務的大規模任務分類架構（task taxonomy），聚焦非實體產業。
- 實證結果顯示，目前主流測試框架（harness）與骨幹模型（backbone）在最難等級的平均完全通過率（full pass rate）僅 2.6%，顯示最高難度仍遠未飽和。
- 將 ALE 設計為持續演進的基準測試（living benchmark），並以縮小基準測試成果與 GDP 相關影響（GDP-relevant impact）之間的差距為目標，而非僅作為排行榜（leaderboard）。

### 適合對象
AI 與機器學習研究者、基準測試（benchmark）設計者、關注 AI 經濟影響與生產力轉化的政策制定者，以及非實體產業中欲評估 AI 代理人（AI agents）實務應用潛能的產業專家與企業決策者。

## 深度分析

#### 方法論解析

Agents' Last Exam（ALE，代理人期末考驗）的核心方法論在於解決現有 benchmark（基準測試）在 realism（真實性）、breadth（廣度）與 verifiability（可驗證性）三者之間的權衡困境。為此，作者群與超過 250 位產業專家合作，以 O*NET / SOC 2018（美國聯邦職業分類系統）為錨點，建構出包含 13 個 industry clusters（產業群集）與 55 個 subfields（子領域）的 task taxonomy（任務分類架構），涵蓋 1,000 個以上的 task instances（任務實例）。

任務來源並非 synthetic（合成）情境，而是直接取材自專家實際完成過的專案。每項任務在納入資料集前，須經過多輪 Quality Control（品質控管，QC）：包含 first-pass review（初審）、engineer dry-runs（工程師乾跑測試），以及專家委員會的 final peer review（最終同儕審查）。這確保了 workflow（工作流）不僅在領域知識上正確，也能在標準化的 Virtual Machines（虛擬機器，VMs）——目前支援 Linux 與 Windows——中穩定執行。

在評估設計上，ALE 針對 heterogeneous output space（異質輸出空間）的挑戰，採用 deliverable-based verification（交付物驗證）或 milestone-based verification（里程碑驗證）。具體而言，系統輸出可能是檔案、試算表、媒體成品、報告、設計或模型，評分時則對照專家預先提供的參考答案與 rubrics（評分標準），從而免除對 human judgment（人類判斷）的依賴。這使得 ALE 得以標準化地測量 long-horizon（長期）且 economically valuable（具經濟價值）的真實工作流。

ALE 的目標評估對象是 Generalist Computer-Use Agent（通用電腦使用代理人，GCUA），例如 Claude Code 或 Codex。這類代理人需在單一 action loop（行動迴路）中整合 visual perception（視覺感知）、code execution（程式碼執行）、tool use（工具使用）與 long-horizon planning（長期規劃）。task surface（任務表面）要求交錯進行 GUI interaction（圖形使用者介面互動）——包含桌面應用程式、瀏覽器與領域專用軟體——以及 CLI operations（命令列介面操作），例如 shell scripting、程式碼執行與檔案操作。這使 ALE 在能力覆蓋上構成 GUI-only 基準測試（如 OSWorld）與 CLI-only 基準測試（如 Terminal-Bench）的 superset（超集）。

#### 實驗數據解讀

當前 ALE 資料集包含 1,490 個 task instances，橫跨全部 55 個 subfields，其中 Engineering & Architecture（工程與建築，368 例）、Computing & Math Sci.（運算與數學科學，237 例）與 Visual & Media Arts（視覺與媒體藝術，226 例）為數量最多的三大領域。所有子領域均獲得非零覆蓋，且任務區分為 fully-implemented（已完整實作）與尚待品質控管（unverified）兩類，顯示其作為 living benchmark（動態基準測試）的持續擴張性。

實驗結果顯示，ALE 的 hardest tier（最難層級）遠未 saturated（飽和）。在主流 harness（測試框架）與 backbone（骨幹模型）配置下，average full pass rate（平均完整通過率）僅 2.6%。即便是最強配置——Codex 搭配 GPT-5.5——在 Terminal-Bench 上可達 82% 通過率，但在 ALE 的 easiest tier（最簡單層級）仍低於 50%，在 hardest tier 則低於 10%。主流代理人如 Claude Code 在 hardest tier 的通過率接近零。這組數據傳達了兩項關鍵訊息：其一，現有前沿模型在抽象能力測試（如數學奧林匹亞或競技程式設計）上的優異表現，並未直接轉化為 sustained performance measurement（持續性績效測量）下的專業工作流執行能力；其二，ALE 確實位於當前 AI 系統的 difficulty frontier（難度邊界），具備足夠的鑑別度以區分不同世代與架構的代理人。

從產業分布觀之，ALE 不僅涵蓋 Software Engineering（軟體工程）、Accounting & Finance（會計與金融）等數位化程度較高的領域，亦納入 Clinical Diagnostics & Imaging（臨床診斷與影像）、Aerospace & Mech. Eng.（航太與機械工程）、Fire Science & Public Safety（消防科學與公共安全）等需要深度領域知識的專業。這意味著 2.6% 的平均通過率反映的是跨產業的普遍瓶頸，而非單一領域的極端難題。

#### 與現有研究的比較

透過圖 3 的 benchmark positioning map（基準測試定位圖）可清晰看出 ALE 的獨特位置。若以 ALE 的 55 個 subfields 為共同座標系，現有基準測試的覆蓋率顯得相對侷限：GDP-VAL 僅覆蓋 16/55，Remote Labor Index（RLI）14/55，XBench 11/55，而 SWE-bench、RE-Bench、MLE-bench 等雖具備 verified technical task completion（可驗證的技術任務完成）機制，但聚焦於狹窄的技術領域。

在光譜的另一端，static answer evaluation（靜態問答評估）如 MMLU、MATH、GPQA、HLE 等，雖能測量抽象知識與推理能力，但缺乏 interactive environments（互動式環境）與長期工作流執行的評估維度。interactive agent environments（互動式代理人環境）如 OSWorld、WebArena、WorkArena++ 主要聚焦 GUI 互動；Terminal-Bench 則僅限 CLI 操作。ALE 同時涵蓋 GUI 與 CLI，並要求兩者無縫整合，因此在 task surface 上構成前述基準測試的 superset。

相較於同樣關注經濟價值的 GDP-VAL 與 Remote Labor Index，ALE 的關鍵改進在於以結構化交付物與里程碑檢查取代 human judges（人類評分者）。這解決了真實工作流輸出異質性所導致的規模化瓶頸，使 benchmark 得以在維持 GDP-relevant impact（與 GDP 相關之影響）的同時，實現自動化、可重複的評分。然而，這也意味著 ALE 必須為每項任務設計專屬的 rubrics，在 setup cost（建置成本）上高於通用型選擇題基準測試。

#### 可重現性評估

ALE 在 reproducibility（可重現性）上的設計體現於兩個層面：執行環境的標準化與評分機制的客觀化。所有任務均於 Linux 或 Windows VMs 中執行，這消除了底層系統環境差異所帶來的變異性。評分則完全依據專家預先提供的參考答案與 rubrics 進行結構化比對，理論上可確保不同時間、不同實驗室執行相同任務時，獲得一致的評估結果。

然而，作為一個 living benchmark，ALE 的 task pool（任務池）持續成長，新 workflows 與產業不斷加入。這對 version control（版本控制）與 snapshot（快照）機制提出了嚴格要求——若缺乏明確的資料集版本標示，長期追蹤進展可能出現 baseline drift（比較基準漂移）。根據目前提供的文本，尚未明確說明 source code（原始碼）、dataset weights（資料集權重）或 model weights（模型權重）的開源釋出策略；此外，由於任務源自真實商業軟體與組織情境，部分領域可能涉及 software licensing（軟體授權）或 proprietary data（專有資料）限制，這可能構成外部研究者重現的門檻。持續的專家協作需求亦意味著，維持 benchmark 的品質與經濟相關性需要穩定的領域專家網絡，而非僅靠自動化流程即可維運。

#### 未來研究方向

首先，在演算法層面，如何將當前 2.6% 的 average full pass rate 提升至可 industrial adoption（工業部署）的水準，是 AI agents（AI 代理人）研究的核心挑戰。這需要突破 long-horizon planning 中的錯誤累積問題，以及 multi-modal perception（多模態感知）在複雜 GUI 與 CLI 交錯情境下的精準決策。

其次，ALE 作為 living benchmark，其持續擴展方向值得關注。目前資料集中已出現 Quantum Computing（量子計算）、AI Engineering & CS Res.（AI 工程與電腦科學研究）等新興領域，但未來需建立系統性的 workflow onboarding（工作流程上架）與 QC 自動化機制，以降低對 250+ 專家人力的依賴。

第三，驗證機制本身可進一步演化。雖然當前以專家制定的 rubrics 進行結構化驗證已屬創舉，但對於設計、創意或策略類輸出，未來可探索結合自動化驗證與少量 human feedback（人類回饋）的混合模式，或發展專門用於評估 heterogeneous deliverables（異質交付物）的 AI evaluator models（AI 評判模型）。

第四，在宏觀影響層面，本文明確將 ALE 定位為連結 benchmark success（基準測試成功）與 GDP-relevant impact 的工具。未來研究可建立從 ALE 通過率到實際勞動生產力或產業附加價值的因果推論框架，使 benchmark 的進步能直接對應到可量測的 economic transformation（經濟轉型）。

最後，GCUA 的架構設計仍有大量優化空間，特別是在 perception-action loop（感知-行動迴路）中如何高效切換 GUI 與 CLI 操作、如何利用 tool use 擴展能力邊界，以及如何在 cross-cluster（跨群集）間實現 knowledge transfer（知識遷移），皆是值得深入探索的技術方向。

## 論文問答

**Q1：ALE 旨在解決的核心問題是什麼？**
A：近年來 AI 系統雖然在眾多基準測試上取得亮眼成績，但這些進展並未轉化為實際的經濟產出與專業領域的廣泛部署。本文指出，這種落差本質上是一個評估問題：現行廣泛使用的基準測試缺乏對真實且具經濟價值的工作流程進行持續性績效衡量。ALE 的提出正是為了評估 AI 代理人在長期規劃、真實世界且具經濟價值的任務上的表現，從而縮小基準測試成功與實際經濟影響之間的鴻溝。

**Q2：現有的基準測試為何無法有效衡量真實的經濟價值？**
A：現有基準測試通常在真實性、廣度或可驗證性之間做出權衡，難以同時兼顧三者。許多研究採用較易收集的短期電腦使用任務、合成環境或純問答設定，這些都無法反映真實專業環境中長期且複雜的工作流程。此外，真實工作流程的產出空間極為異質，可能涉及檔案、試算表、媒體成品、報告或設計模型，使得自動化驗證變得極為困難，導致現有評估往往只能依賴人工判斷，難以規模化。

**Q3：為何縮小基準測試成功與經濟影響之間的落差如此重要？**
A：基準測試不僅記錄能力，更會形塑研究注意力、定義工程目標，並決定哪些領域能夠快速取得進展，因此選擇適當的評估方式對 AI 發展方向至關重要。過去如 ImageNet 在電腦視覺領域的經驗顯示，一旦某個領域被可驗證且廣泛使用的評估所涵蓋，該領域的進展便會加速，隨之而來的是實際部署。對於金融、法律、電機工程與製造等經濟核心部門，若能建立類似的評估標準並最終達到飽和，將意味著 AI 系統已具備在真實產業環境中執行專業工作流程的能力，從而帶來可衡量的經濟轉型。

**Q4：ALE 的核心設計方法是什麼？它如何評估 AI 代理人？**
A：ALE 是一個包含超過一千個任務實例的基準測試，涵蓋 55 個子領域與 13 個產業群集，並與超過 250 位產業專家合作開發。其任務工作流程源自真實的專業實踐，由專家貢獻他們已完成的實際專案，而非仰賴合成情境。評估方式採用結構化的可交付成果檢查或里程碑檢查，對照專家提供的參考答案與評分標準，從而在無需人工評審的情況下，驗證異質的真實世界產出。

**Q5：相較於以往的基準測試，ALE 的關鍵創新為何？**
A：ALE 的關鍵創新在於它同時兼顧真實性、廣度與可驗證性，並以「期末考驗」的雙重願景定位自身：既是能力門檻，也是難度前沿。作為一個「活的基準測試」，其任務池會隨著新工作流程與產業的加入而持續擴充，而非一成不變。更重要的是，它被設計為縮小基準測試成功與 GDP 相關影響之間落差的工具，而非僅僅是另一個排行榜，這使其在經濟意義上與現有評估有著本質區別。

**Q6：作者為何選擇採用真實專業專案與 O*NET/SOC 職業分類系統？**
A：作者選擇從真實專業實踐中取得任務，是因為長期且真實的工作流程極為昂貴且難以建構，而專家已完成的專案能確保任務的經濟價值與真實性。為確保廣泛且具代表性的產業覆蓋率，ALE 參照美國聯邦職業分類系統 O*NET/SOC 2018，並由領域諮詢委員會對映各領域的工作流程樣貌，識別出具經濟意義的工作流程家族。這種設計選擇使得 ALE 能夠系統性地涵蓋非實體產業的專業工作，避免僅侷限於少數幾個容易評估的領域。

**Q7：ALE 在覆蓋範圍與難度上與現有基準測試相比有何不同？**
A：ALE 以 55 個子領域作為共同座標系統，將先前各基準測試的主題、應用或職業對映其上，結果顯示多數現有基準僅覆蓋其中一小部分領域。相較於僅測試圖形使用者介面（GUI）或命令列介面（CLI）的現有基準，ALE 的任務表面在設計上即為二者的超集，要求同時具備視覺感知、程式碼執行、工具使用與長期規劃能力。在難度上，ALE 定位於當前系統能可靠完成的邊界，其最困難層級遠未達飽和，與許多已被高分突破的現有基準形成鮮明對比。

**Q8：當前 AI 代理人在 ALE 上的主要實驗結果為何？**
A：實驗結果顯示，無論是主流測試框架或骨幹模型配置，在最困難層級的平均完全通過率僅有 2.6%，顯示該基準仍遠未被攻克。即使是目前最強的配置，在 Terminal-Bench 上可達 82% 的表現，但在 ALE 最簡單的層級得分仍低於 50%，在最困難層級則不到 10%。包括 Claude Code 在內的多數主流代理人在最高難度層級的通過率接近零，這清楚揭示了當前系統在執行真實長期專業工作流程上的能力缺口。

**Q9：ALE 的不同難度層級如何揭示當前代理人的能力邊界？**
A：ALE 透過分層設計，區分出從基礎到高階的專業工作流程，使得研究人員能夠精確定位當前技術的瓶頸所在。實驗數據顯示，現有代理人在需要單一命令列操作的任務上或許表現優異，但一旦進入需要長期規劃、圖形介面與命令列交錯操作、並產出異質可交付成果的層級，表現便急遽下降。這種難度梯度不僅提供了清晰的改進路標，也證明了真實經濟價值的工作流程與現有基準測試之間存在著一道目前仍難以跨越的能力鴻溝。

**Q10：ALE 可應用於評估哪些專業領域的代理人準備度？**
A：ALE 涵蓋了工程與建築、商業與金融、生命科學、健康醫療、法律、運輸安全等 13 個產業群集，專注於非實體產業的專業工作。這些領域包括會計與財務分析、軟體工程、臨床診斷影像、生物分子結構設計、訴訟支援與法律研究等，都是對 GDP 具有重要貢獻的核心部門。透過在這些真實且具經濟價值的領域中進行評估，ALE 能夠判斷 AI 代理人是否已準備好執行持續性的專業工作，而非僅僅回答相關領域的問題。

**Q11：AI 代理人要具備哪些技術能力才能在 ALE 上表現良好？**
A：ALE 的目標評估對象是通用型電腦使用代理人（GCUA），這類系統必須在單一行動迴路中結合視覺感知、程式碼執行、工具使用與長期規劃能力。由於任務要求交錯使用圖形使用者介面與命令列操作，代理人必須能夠同時處理桌面應用程式、瀏覽器、領域特定軟體以及 Shell 指令碼與檔案操作。這意味著僅具備純文字推理或單一介面操作能力的系統將難以應付，成功的代理人需要整合多模態感知與複雜的長期任務執行能力。

**Q12：ALE 將如何影響 AI 研究與產業部署的方向？**
A：ALE 被設計為不僅是另一個排行榜，而是縮小基準測試成功與 GDP 相關影響之間落差的工具，這將引導研究社群將注意力轉向具有真實經濟價值的長期工作流程。一旦前沿 AI 代理人能夠通過這項「期末考驗」，基準測試上的進展將開始對應到真實的經濟轉型，類似 ImageNet 曾推動電腦視覺的發展與部署。這種以經濟影響為導向的評估框架，有望加速 AI 在金融、法律、工程等核心產業的實際採用，並重新定義何謂「具有通用能力的 AI 系統」。

**Q13：作者在建構 ALE 時面臨哪些結構性挑戰與限制？**
A：建構 ALE 面臨三大結構性挑戰：首先，長期且真實的工作流程取得成本高昂，必須從真實的軟體與組織情境中取得；其次，廣泛的產業覆蓋率需要持續接觸各領域專家並深入理解產業樣貌，這在規模化上極為困難；第三，真實工作流程的產出空間異質性極高，使得自動化驗證本質上就很困難，這也是為何許多現有基準只能依賴人工判斷或退而求其次使用合成任務。這些限制意味著 ALE 的建構與維護需要持續的專家合作與資源投入，無法僅靠自動化資料生成完成。

**Q14：主流代理人在 ALE 上的接近零通過率揭示了哪些當前限制？**
A：主流代理人在最困難層級接近零的通過率，顯示當前系統在整合多種能力以完成長期專業任務上仍存在根本性的不足。這些失敗案例表明，僅僅在孤立環境中擅長回答問題、執行單一命令或操作特定介面，並不足以應對真實世界中交錯複雜的工作流程。這也凸顯了現有訓練範式與評估標準的侷限：它們過度優化於短期、靜態、可預測的任務，卻未能培養出代理人持續執行具經濟價值工作所需的專業判斷與長期規劃能力。

**Q15：ALE 作為「活的基準測試」，其未來發展方向為何？**
A：ALE 的任務池將持續擴充，隨著新的工作流程與產業不斷加入，確保其能夠反映不斷演變的專業實踐與經濟需求。未來的發展方向包括持續納入更多產業領域、更新現有任務以符合最新的軟體與組織環境，並可能擴展到目前尚未涵蓋的實體產業相關工作流程。長遠而言，ALE 期望成為衡量 AI 系統是否準備好帶來廣泛經濟轉型的標準工具，當前沿代理人最終能夠通過這項考驗時，將標誌著 AI 從基準測試的成功正式邁入 GDP 相關的實質影響。

## 實務應用指南

### 適用場景

**1. 企業級專業流程自動化評估**
金融、法律、電機工程、製造業等核心產業在導入 AI 代理人前，可利用 ALE 的任務分類架構（13 大產業群集、55 子領域）評估現有代理人在真實軟體環境（GUI 結合 CLI）中完成長期經濟價值任務的能力，避免「基準測試高分、實際上線低分」的落差。

**2. 通用型電腦使用代理人（GCUA）的研發驗證**
針對結合視覺感知、程式碼執行、工具使用與長期規劃的 GCUA（如 Claude Code、Codex 類系統），ALE 提供超越純 GUI 或純 CLI 基準測試的綜合考驗場域，適合作為模型迭代時的端到端回歸測試標準。

**3. 專業人才訓練與認證模擬**
ALE 的任務源自 250 位以上領域專家貢獻的真實已完成專案，經多輪品質控管後入庫。教育機構或企業內訓單位可將其改編為高擬真度的專業認證考場，測試學員在跨軟體、跨檔案格式交付的完整工作流程表現。

**4. AI 經濟影響力量化研究**
政策制定者或經濟學研究者可透過 ALE 的 O*NET／SOC 2018 職業分類對照，將代理人的通過率與實際 GDP 相關產業連結，建立「基準測試飽和度」與「實質經濟轉型」之間的量化橋樑。

**5. 跨領域能力基線建立**
對於需要同時涵蓋臨床診斷影像、半導體設計、供應鏈物流等多樣場景的通用 AI 平台，ALE 提供 1,000 項以上可執行任務的統一坐標系，協助團隊識別能力盲點並排定產業擴充優先順序。

### 實作前置條件

**資料條件**
- 領域專家網絡：需持續接觸各產業實務工作者，取得其「已完成的真實專案」作為任務藍本，而非合成情境。
- 職業分類對照表：建議備妥 O*NET／SOC 2018 或同等國家級職業分類系統，作為任務分類與產業覆蓋率檢核的錨點。
- 參考交付物與評分 rubric：每項任務需附專家提供的標準交付物（檔案、試算表、媒體成品、設計稿等）以及可結構化比對的評量準則。

**運算條件**
- 虛擬機叢集：需準備 Linux 與 Windows VM 作為任務執行沙盒，支援桌面應用程式、瀏覽器、領域專用軟體與命令列操作。
- 代理人推論資源：GCUA 通常需呼叫多模態大型語言模型，需配置足夠的 GPU／TPU 叢集以支援長期規劃（long-horizon）過程中的多次視覺感知與工具呼叫。

**技能條件**
- 品質控管工程師：能執行 first-pass review、engineer dry-runs 與最終同儕審查，確保任務在無人為介入下可重複執行且評分一致。
- 代理系統整合工程師：熟悉將視覺輸入、程式碼直譯器、檔案系統操作整合為單一行動迴路（action loop）的技術棧。
- 領域顧問委員會：各子領域需有專家組成顧問群，負責定義「具有經濟意義的工作流程家族」並審核定價值。

---

### 實作步驟建議

**步驟一：產業映射與工作流程盤點**
依據 O*NET／SOC 2018 職業分類，由顧問委員會盤點目標產業的實際工作流程家族，確保覆蓋 13 大群集與 55 子領域，並標註各任務的經濟價值權重。

**步驟二：真實任務採集與文件化**
邀請領域專家提交其近期完成的真實專案，轉化為標準化任務敘述，包含初始狀態（檔案、環境設定）、執行過程中允許使用的軟體與工具，以及最終交付物規格。

**步驟三：多輪品質控管與可執行化**
依序執行：(1) 初審確認任務敘述完整性；(2) 工程師乾跑（dry-run）確認在 VM 中可無人為介入執行；(3) 專家同儕審查確認經濟價值與難度分級正確。

**步驟四：結構化評估機制建置**
針對異質輸出空間，建立以「可交付成果（deliverable-based）」或「里程碑（milestone-based）」為核心的自動化評分系統，比對代理人輸出與專家參考答案，避免依賴人工主觀判斷。

**步驟五：代理人測試與難度分級驗證**
使用現有主流 GCUA（如 Claude Code、Codex）進行試測，依據通過率將任務分級（例如簡單／中等／困難），確保最困難等級對當前系統仍具挑戰性（參考目標：平均完整通過率低於 10%）。

**步驟六：持續擴充與生命週期維運**
將基準測試設計為「活文件（living benchmark）」，隨新產業、新軟體、新工作流程出現持續 onboarding，並定期檢視舊任務是否因軟體版本更新而失效。

### 潛在風險與注意事項

**真實工作流程採集成本高昂**
真實長期任務需取自實際組織脈絡與軟體環境，蒐集與去識別化成本遠高於合成題目。建議採用滾動式擴充，先聚焦 2–3 個高經濟價值產業驗證模式，再橫向擴展。

**異質輸出的驗證複雜度**
交付物可能是檔案、模型、報告或媒體成品，自動化評分容易流於表面比對。建議採用專家預先定義的 rubric 與多維度里程碑檢查，而非單一二進位比對。

**沙盒安全風險**
任務執行涉及真實瀏覽器、命令列與檔案系統操作，VM 隔離必須嚴格，防止代理人於測試過程中意外存取外部網路或敏感資料。

**產業覆蓋偏差**
專家網絡易集中於軟體工程或數據分析領域，導致傳統產業（如採礦、石油、地質工程）任務不足。需主動依 SOC 分類反向檢核，確保各子領域皆有非零覆蓋。

**對基準測試過擬合，而非對真實經濟價值過擬合**
若研究社群過度針對 ALE 的特定任務格式優化，可能出現「考試技巧」而非通用能力提升。建議定期輪換任務池，並搭配 GDP-relevant 的外部指標交叉驗證。

### 與其他技術的整合建議

**與現有代理人框架整合**
ALE 的任務表面（task surface）本質上涵蓋了 OSWorld（純 GUI）與 Terminal-Bench（純 CLI）的任務類型，建議直接將 Claude Code、Codex、OpenAI Operator 等 GCUA 接入 ALE 的統一測試 harness，作為端到端能力評估的標準管線。

**與靜態評估基準互補**
ALE 測量的是長期工作流程執行力，可與 MMLU、GPQA、MATH 等靜態問答基準測試並行使用，形成「抽象知識 + 實作能力」的雙軌評估矩陣，避免單一指標誤導研發方向。

**與經濟影響指標串接**
建議將 ALE 各產業群的通過率與 GDP-val、Remote Labor Index 等經濟導向指標建立連動分析，當特定產業任務通過率顯著提升時，可預警或驗證該產業即將出現可測量的 AI 生產力轉型。

**與企業 CI/CD 整合**
對於持續開發 GCUA 的團隊，可將 ALE 的任務子集納入夜間回歸測試（nightly regression），作為模型更新後的專業能力衰退／提升警報器，特別關注 GUI 與 CLI 混合操作場景的穩定性。

### 給不同背景讀者的閱讀建議

**給初學者**
請先聚焦論文的「為何而測」而非「如何測」。理解 AI 領域長期存在「考試高分但經濟影響低落」的評估問題，ALE 的核心貢獻在於把測試場景拉回真實職場的長期工作流程，而非另一個問答題庫。建議從圖 2 的產業分類圖與圖 3 的基準測試定位圖入手，快速建立對整體架構的直覺。

**給 AI 工程師**
請重點閱讀基準測試設計原則與任務執行環境章節，特別關注 GCUA 的任務表面設計：如何同時支援桌面應用程式、瀏覽器、領域專用軟體與命令列操作。建議深入評估 harness 的實作細節，思考如何將現有代理人的行動迴路（action loop）對接至 ALE 的 deliverable-based 評分機制，並留意多模態輸入在長期規劃中的延遲與錯誤累積問題。

**給研究人員**
請聚焦方法論層面：ALE 如何以 O*NET／SOC 2018 建立可擴充的任務分類學、如何透過專家委員會與多輪品質控管解決「真實性、廣度、可驗證性」的三難困境，以及如何設計結構化評分以取代人工判斷。此外，論文將 ALE 定位為「living benchmark」，其持續擴充機制與避免過擬合的策略，對於未來建構動態評估環境的研究具有高度參考價值。

**給產品經理**
請將 ALE 視為「產業就緒度儀表板」。閱讀時請對照圖 2 的 13 大產業群集與自身產品路線圖，識別哪些子領域已達可部署的通過率門檻、哪些仍處於近零通過率的紅海。論文中「最困難等級平均完整通過率僅 2.6%」的數據，可作為向高階主管說明「為何 AI 代理人尚未在核心產業大規模落地」的有力佐證，同時協助團隊設定務實的產業擴充優先順序。
