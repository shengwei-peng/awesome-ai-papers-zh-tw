## ⚡ TL;DR

現有語音語言模型採用固定幀率，忽略語音資訊密度的時變性，無法彈性權衡品質與推論速度。
本文提出FlexiSLM，首個支援動態可控幀率語音輸入與輸出的語音語言模型，可直接控制輸出幀率。
實驗顯示FlexiSLM高品質點優於固定幀率7B模型；6.25Hz推論時間減半且品質良好。

## 摘要翻譯

語音語言模型（Spoken Language Model, SLM）將大型語言模型（Large Language Model, LLM）擴展至語音輸入／輸出（speech input / output）。現有 SLM 以固定幀率（fixed frame rate）（例如 25 或 12.5 Hz）表示語音，忽略了語音的時變（time-varying）資訊密度（information density），且缺乏在推論時（inference time）權衡（trade off）品質與速度的彈性。近期的音訊分詞器（audio tokenizer）研究提出了動態幀率語音編碼（dynamic frame rate speech coding），利用這種非均勻性（non-uniformity），實現了兩項新能力：極低的平均幀率（average frame rate）與幀率可控性（frame rate controllability）。然而，這項技術尚未應用於 SLM。我們提出靈活語音語言模型（Flexible Spoken Language Model, FlexiSLM），這是首個在語音輸入與輸出皆支援動態與可控幀率（dynamic and controllable frame rates）的 SLM。利用動態幀率（dynamic frame rate）表示法，FlexiSLM 在其高品質運作點（high-quality operating points）上優於固定幀率 7B 模型（包括 Qwen2.5-Omni 與 Kimi-Audio）。我們進一步驗證 FlexiSLM 可精確調降至 4.0 Hz；在 6.25 Hz 時，相較於 12.5 Hz，其推論時間（inference time）約可減半，同時保持優異的語音到語音品質（speech-to-speech quality）。音訊樣本請見 https://flexislm.github.io。

### 核心貢獻（3～5點）
- 首次將動態幀率語音編碼技術應用於語音語言模型，提出 FlexiSLM，並同時支援語音輸入與輸出的動態與可控幀率。
- 在高品質運作點上，FlexiSLM 的表現優於現有 7B 固定幀率基線模型（包括 Qwen2.5-Omni 與 Kimi-Audio）。
- 實現推論階段的幀率可控性，可精確調降至 4.0 Hz；於 6.25 Hz 時，推論時間相較 12.5 Hz 約可減半，同時維持優異的語音到語音品質。
- 驗證動態幀率表示法能有效利用語音的時間稀疏性與非均勻資訊密度，在品質與速度間提供靈活的權衡空間。

### 適合對象
從事語音語言模型、端到端語音到語音對話系統、音訊編解碼與標記化技術，以及大型語言模型高效推論與異構部署相關研究之學者與工程師。

## 深度分析

#### 方法論解析

FlexiSLM（Flexible Spoken Language Model / 靈活語音語言模型）的核心方法論在於將動態幀率（dynamic frame rate / 動態幀率）與可控幀率（controllable frame rate / 可控幀率）機制首次引入端到端（end-to-end / 端到端）語音語言模型（SLM / Spoken Language Model）。其技術架構可分為輸入端的動態速率語音編碼（Dynamic-Rate Speech Encoding）與輸出端的直接幀率條件化生成（direct frame rate conditioning）兩大創新。

在輸入端，FlexiSLM 採用 FlexiCodec 作為音訊分詞器（audio tokenizer / 音訊分詞器），該分詞器以 12.5 Hz 的語義特徵（semantic features / 語義特徵）為基底，透過幀合併模組（frame merging module / 幀合併模組）動態壓縮語音序列。具體而言，系統計算相鄰幀之 ASR 特徵（ASR feat.）的餘弦相似度（cosine similarity / 餘弦相似度），當相似度超過合併閾值（merging threshold / 合併閾值）時，即將冗餘幀合併為單一表示。此機制充分利用了語音的時間稀疏性（temporal sparsity / 時間稀疏性）與非均勻資訊密度（non-uniform information density / 非均勻資訊密度），使輸入表示的平均幀率（average frame rate / 平均幀率）可自適應降至約 6.25 Hz，甚至更低，而非傳統模型的固定幀率（fixed frame rate / 固定幀率）。

在輸出端，作者提出直接幀率條件化（direct frame rate conditioning），這是與既有動態編碼研究最關鍵的差異。過往方法（如 FlexiCodec 原始論文）僅能透過間接調整合併閾值來影響幀率，而 FlexiSLM 讓使用者直接指定目標平均輸出幀率（average output frame rate / 平均輸出幀率），模型即能在無需重新訓練（without retraining / 無需重新訓練）的情況下，將該條件訊號融入 LLM Backbone（骨幹網路）的生成過程，輸出對應幀率的語音標記（speech tokens）。從圖示架構觀察，輸出端同樣基於 12.5 Hz 特徵進行動態合併，並透過 Talker prediction target（說話者預測目標）與 FlexiCodec Decoder 還原波形，其幀率控制精確度可穩定達至 4.0 Hz 的極低運作點（operating point / 運作點）。

此外，論文圖示揭示模型在 LLM 內部採用 Local Attention（局部注意力）機制處理交錯（interleave / 交錯）後的動態長度序列，這對於處理可變長度的動態幀序列至關重要。整體而言，FlexiSLM 的方法論並非僅是將音訊分詞器替換為動態版本，而是重新設計了 SLM 的輸入輸出介面，使幀率成為可微調或可由使用者操控的顯式變數，從而實現品質與速度之間的連續權衡（trade off / 權衡）。

#### 實驗數據解讀

論文在實驗設計上選擇與兩個 7B 參數等級的固定幀率基線模型進行對比：Qwen2.5-Omni（運作於 25 Hz）與 Kimi-Audio（運作於 12.5 Hz）。實驗結果顯示，FlexiSLM 在高品質運作點（high-quality operating points / 高品質運作點）——即 12.5 Hz 設定下——能夠超越這兩個固定幀率模型。這項結果具有雙重意義：首先，它證明動態幀率壓縮並未因資訊丟失而犧牲上限性能；其次，說明 FlexiSLM 的語義特徵相似度合併策略在保留語音理解（speech understanding / 語音理解）與生成（speech generation / 語音生成）所需之關鍵聲學細節上，優於或至少不亞於傳統固定幀率表示法。

更具實務價值的是中低幀率區間的表現。當模型被導引至 6.25 Hz 時，推論時間（inference time / 推論時間）相較於 12.5 Hz 基線大幅減半，同時仍維持強勁的語音到語音品質（speech-to-speech quality / 語音到語音品質）。這顯示 6.25 Hz 是一個極具性價比的運作點，尤其適合運算資源受限但仍需端到端語音互動的場景。進一步將幀率下調至 5.0 Hz 與 4.0 Hz 時，模型呈現 graceful degradation（優雅退化），即性能隨幀率降低而平滑下降，而非斷崖式崩潰。這種可預測的退化曲線對於異構部署預算（heterogeneous deployment budgets / 異構部署預算）極為重要，開發者可依據即時負載動態選擇運作點。

值得注意的是，論文強調「準確操控」（accurately steered）低至 4.0 Hz。這暗示模型不僅在客觀指標（如語音可懂度、說話者相似度）上表現穩定，其幀率條件化機制在數值層面也具備高保真度，不會出現條件訊號與實際輸出幀率大幅偏離的問題。這驗證了直接幀率條件化作為控制介面的有效性，遠優於間接調整合併閾值所可能帶來的非線性與不穩定性。

#### 與現有研究的比較

在定位上，FlexiSLM 明確填補了「動態幀率語音編碼」與「端到端語音語言模型」之間的空白。既有研究如 FlexiCodec 雖已驗證動態速率編碼（dynamic-rate coding / 動態速率編碼）在 0.3B 參數 TTS（Text-to-Speech / 文字轉語音）管線中的可行性，但並未擴展至運算密集（compute-intensive / 運算密集）的 SLM 場景。其他動態幀率相關工作，包括 Dynamic-Codec、TFC 與 VARSTok，其探索的平均幀率多落在 18.75 Hz 至 41.2 Hz 區間，屬於中高幀率範疇；相較之下，FlexiSLM 專注於 12.5 Hz 以下的低平均幀率，並證明此區間對於降低推論成本具有更大的實務效益。

與固定幀率 SLM 相比，Qwen2.5-Omni 採用 Thinker–Talker 架構並以 25 Hz 處理語音標記，Kimi-Audio 則以 12.5 Hz 並行建模語音與文字。這類模型無法在推論階段調整幀率，缺乏幀率可控性（frame rate controllability / 幀率可控性）。FlexiSLM 不僅在 12.5 Hz 高品質點勝出，更提供了這些模型完全不具備的彈性：使用者可依據當前延遲需求即時切換品質等級。

另一方面，Fun-Audio-Chat 與 Mimo-Audio 等系統採用分塊（patching / 分塊）技術，在 LLM 端達到 5 Hz 或 6.25 Hz 的有效幀率（effective LLM-side frame rate / 有效的 LLM 端幀率）。然而，分塊是將連續幀群組為單一標記，與 FlexiSLM 基於語義相似度的自適應幀合併本質上屬於互補（complementary / 互補）技術。論文指出未來可將兩者結合，意味著 FlexiSLM 的動態幀率框架具有與現有壓縮策略疊加的潛力。

現有語音標記化（speech tokenization / 語音標記化）研究另一分支為單一碼本（single-codebook / 單一碼本）與語義增強編解碼器（semantic-enhanced codec / 語義增強編解碼器），其幀率通常仍固定於 50–75 Hz 或 12.5–50 Hz。FlexiSLM 的貢獻在於將「幀率」從模型架構的靜態超參數轉變為動態可控變數，這在 SLM 領域尚屬首創。

#### 可重現性評估

論文明確承諾將釋出程式碼（code / 程式碼）、重現資料（reproduced data / 重現資料）與模型權重（model weights / 模型權重），並提供兩個公開網址：音訊樣本展示頁（https://flexislm.github.io）與程式碼倉儲（https://github.com/AmphionTeam/FlexiSLM）。這對於可重現性（reproducibility / 可重現性）而言是正面訊號，尤其考慮到訓練 7B 等級 SLM 所需的高運算成本，開源釋出能大幅降低後續研究的進入門檻。

然而，截至論文發表時，釋出狀態仍標註為「plan to release」（計畫釋出），而非「已釋出」。這意味著目前社群尚無法立即驗證其數據與模型行為，僅能透過作者提供的音訊樣本進行主觀評估。此外，動態幀率訓練需要特定的資料前處理管線（如 FlexiCodec 的幀合併邏輯與條件標註），若開源釋出不包含完整的資料處理腳本與訓練配置，重現難度仍將顯著提高。建議後續釋出應包含：
1. 預訓練與微調的完整訓練腳本；
2. FlexiCodec 與 FlexiSLM 的整合推論範例，展示如何注入目標幀率條件；
3. 客觀評估指標（如 ASR 錯誤率、MOS 相關數據）的評測程式碼。

#### 未來研究方向

基於 FlexiSLM 所建立的動態可控幀率框架，後續研究可沿以下數個方向深化：

第一，**與分塊（patching / 分塊）策略的整合**。論文已指出 Fun-Audio-Chat 與 Mimo-Audio 的分塊方法與動態幀率互補。未來可探索「雙重壓縮」架構：先在聲學層以動態幀合併降低基底幀率，再於 LLM 層進行分塊，進一步壓縮序列長度，目標是將有效 LLM 端幀率降至 3 Hz 以下，同時維持可接受的語音到語音對話（speech-to-speech dialogue / 語音到語音對話）品質。

第二，**全雙工（full-duplex / 全雙工）與交錯語音文字序列（interleaved speech-text sequences / 交錯語音文字序列）的擴展**。現有 SLM 研究已開始探索全雙工能力與語音文字交錯建模（如 GLM-4-Voice）。將動態幀率引入這些場景，可使模型在聆聽與生成雙向都具備幀率彈性，例如在高認知負載時降低輸出幀率以減少自迴歸延遲。

第三，**極低幀率（< 4.0 Hz）的語義保留機制**。雖然 FlexiSLM 已能運作於 4.0 Hz，但更低幀率（如 2–3 Hz）對於邊緣裝置部署極具吸引力。未來研究可探討結合更強大的語義特徵提取器（如大規模自監督學習模型）或引入顯式的語音內容摘要模組，以彌補極低幀率下的細粒度聲學資訊損失。

第四，**異構部署預算（heterogeneous deployment budgets / 異構部署預算）下的自適應幀率調度**。目前幀率由使用者顯式指定，未來可發展自動化幀率調度器，根據即時網路頻寬、裝置電量或使用者任務類型（如 ASR / 自動語音辨識 對比 語音生成）動態選擇最佳運作點，實現真正的資源感知型 SLM（resource-aware SLM）。

最後，**動態幀率的可解釋性與理論分析**仍有待加強。例如，幀合併決策與語音學事件（如音素邊界、停頓）的對應關係為何？動態幀率是否會對特定語言或方言的韻律建模產生偏見？這些問題需要更細緻的語言學與聲學分析，以確保動態壓縮的穩健性與公平性。

## 論文問答

**Q1：現有語音語言模型（SLM）在語音表示法上面臨的根本限制是什麼？**
A：現有的 SLM 通常採用固定幀率（例如 25 Hz 或 12.5 Hz）來表示語音，這種做法忽略了語音資訊密度隨時間變化的非均勻性。無論語音片段包含豐富的語言內容還是相對靜音的段落，模型都使用相同數量的離散語音編碼幀來處理每一秒音訊。因此，這些系統無法根據實際的聲學內容調整計算資源，導致在資訊稀疏的時段浪費過多的運算成本。

**Q2：為何當前固定幀率的 SLM 無法有效平衡品質與推論速度？**
A：固定幀率架構以恆定的離散語音編碼幀數量來編碼每一秒音訊，未能利用語音在時間軸上的稀疏性與非均勻的資訊分佈。由於幀率在訓練後即被鎖定，使用者無法在推論階段指示模型以犧牲部分重建保真度為代價來換取更低的延遲。這種缺乏幀率可控性的設計迫使部署時只能採用一體適用的配置，經常導致在聲學冗餘的幀上過度分配計算資源。

**Q3：為何將動態幀率語音編碼擴展到端到端 SLM 特別具有價值？**
A：與先前僅在 0.3B 參數文字轉語音（TTS）管線中驗證動態速率編碼的研究相比，SLM 的運算密集程度顯著更高，因此在大規模推論時節省的成本會被大幅放大。此外，SLM 涵蓋了語音到語音對話、自動語音辨識（ASR）、文字轉語音（TTS）與音訊理解等更廣泛的能力，使得幀率可控性對於異構部署預算下的多樣化任務更具實用價值。透過讓同一個模型在資源充足時以高品質運作點運行、在需要速度時降低幀率，動態幀率技術能顯著提升實際部署的靈活性與效益。

**Q4：FlexiSLM 實現動態幀率處理的核心技術方法是什麼？**
A：FlexiSLM 採用 FlexiCodec 作為其動態幀率語音編解碼器，該分詞器透過計算相鄰 12.5 Hz 語義特徵的餘弦相似度，自適應地合併資訊密度較低的語音幀。在語音輸入端，模型應用類似的幀合併策略，將原始音訊轉換為動態速率的語音表示法後送入 LLM 骨幹網路；在輸出端則引入一個條件訊號，讓使用者直接指定目標平均幀率。這種設計使得模型無需重新訓練，即可在推論時產生不同時間解析度的語音標記。

**Q5：FlexiSLM 與先前動態幀率音訊分詞器研究的主要區別為何？**
A：雖然 FlexiCodec 等先前工作已在小型 TTS 系統中展示動態幀率的可行性，但 FlexiSLM 是首個在端到端語音語言模型中同時支援輸入與輸出動態幀率且具備可控性的框架。其關鍵創新在於將可變速率標記化整合到完整的 SLM 技術堆疊中，並以直接幀率條件取代間接調整合併閾值的操作方式。這使得幀率成為推論階段可由使用者明確操控的控制變數，而非僅由內部聲學啟發式規則決定的衍生屬性。

**Q6：作者為何選擇直接幀率條件控制，而非讓使用者調整合併閾值？**
A：直接幀率條件控制提供了一個直覺且精確的介面，讓使用者能明確指定目標平均幀率；相對地，調整合併閾值只能間接且模糊地影響最終的輸出位元率。這項設計選擇將幀率從內部超參數轉變為第一類的推論時間控制變數，使其更適用於異構部署預算下的各種場景。透過在生成過程中條件化目標幀率，FlexiSLM 能夠被精準導引至 6.25 Hz 或 4.0 Hz 等特定運作點，而無需使用者理解底層的語義特徵相似度機制。

**Q7：實驗中選用了哪些基線模型來評估 FlexiSLM，它們代表了什麼？**
A：作者將 FlexiSLM 與 Qwen2.5-Omni 和 Kimi-Audio 這兩個 7B 參數的固定幀率模型進行比較，它們分別代表了在 25 Hz 與 12.5 Hz 下運行的最先進統一語音語言模型。這些基線體現了當前主流的先以語音編碼器提取特徵、再以解碼器專用大型語言模型進行建模的典範架構。透過與這些領先系統比較，論文證明了動態幀率表示法不僅能達到同等的品質水準，更能在高品質運作點上實現超越。

**Q8：關於推論速度與品質，實驗取得了哪些最關鍵的量化與質化發現？**
A：在高品質運作點上，FlexiSLM 的語音到語音品質超越了固定幀率的 7B 基線模型，證實動態壓縮在適當的幀率設定下不會犧牲保真度。當模型被導引至 6.25 Hz 時，推論時間相較於 12.5 Hz 大致減半，同時仍維持強健的語音到語音品質，顯示出顯著的延遲降低效益。即使在 5.0 Hz 與 4.0 Hz 等更激進的設定下，模型也呈現出優雅的品質衰減而非災難性崩潰，確認了此方法在品質與速度權衡光譜上的穩健性。

**Q9：作者如何驗證 FlexiSLM 的幀率控制是準確且可靠的？**
A：作者透過系統性地將模型導引至不同目標幀率，明確驗證了 FlexiSLM 能準確運作在低至 4.0 Hz 的設定，且行為具有可預測性。他們在 12.5 Hz、6.25 Hz、5.0 Hz 與 4.0 Hz 等多個運作點上評估效能，以描繪品質衰減曲線並確保降低幀率不會引入不規則的異常瑕疵。這種全面的掃描實驗證明了條件機制能可靠地調節輸出標記的時間密度，而非僅是對模型提供粗略的提示建議。

**Q10：動態幀率可控性在哪些真實世界的部署場景中最具效益？**
A：動態幀率控制對於運算資源有限的邊緣裝置特別有益，同一個模型可以在進行語音到語音對話時降至 6.25 Hz 或 4.0 Hz，以確保可接受的即時延遲。雲端服務提供商在面對異構部署預算時，也能利用此能力為不同層級的客戶提供差異化品質，而無需維護多個獨立的模型檢查點。此外，即時通訊應用可根據網路擁塞狀況或裝置電量動態調整幀率，即使在資源受限的環境下也能維持連續的語音服務。

**Q11：產品團隊可能如何將 FlexiSLM 的可控幀率整合到商業語音 AI 管線中？**
A：產品團隊可以將幀率設計為使用者可見的品質滑桿，或是根據裝置溫度與網路頻寬自動調適的後台設定。由於幀率控制僅需透過簡單的條件訊號即可達成，整合過程不需要針對每個目標幀率單獨微調或部署不同的模型架構，大幅降低了工程維護成本。這使得單一部署端點就能同時服務需要高保真互動的頂級用戶，以及追求高吞吐量與低成本的用量密集型工作負載。

**Q12：FlexiSLM 可能如何影響語音語言模型領域未來的研究與發展？**
A：FlexiSLM 證明了端到端 SLM 能夠原生地在動態速率標記上運作，這為研究者探索更激進的時間壓縮方案開闢了道路，無需放棄現有的 LLM 骨幹網路典範。它也將幀率可控性確立為下一代語音分詞器與 SLM 的標準需求之一，促使領域關注的焦點從單純的重建保真度轉向兼顧效率的表示學習。未來的架構可能會越來越傾向於將語音幀率視為與文字生成中溫度或 top-p 取樣類似的第一類推論時間變數。

**Q13：作者對於目前 FlexiSLM 框架承認了哪些限制？**
A：作者指出，作為基礎的音訊分詞器 FlexiCodec 先前僅在 0.3B 參數的 TTS 管線中獲得驗證，將其動態速率機制擴展到完整的 7B SLM 需要相當程度的架構整合工作。他們也承認目前的方法尚未結合 Fun-Audio-Chat 或 Mimo-Audio 等系統所採用的分塊策略，這些策略能進一步降低有效的 LLM 端幀率，因此仍有潛在的效率提升空間未被開發。此外，儘管品質衰減是優雅的，但在低於 6.25 Hz 的運作點下仍會產生可測量的品質權衡，這對於要求極高音質的應用而言可能仍不夠理想。

**Q14：FlexiSLM 在哪些運作點會出現明顯的品質退化，這意味著什麼？**
A：雖然模型在 6.25 Hz 時仍維持強健的品質，但在 5.0 Hz 時開始出現可感知的退化，到了 4.0 Hz 則更為明顯，這顯示當語義壓縮過度時會遺失過多的聲學細節。這意味著極低的幀率可能難以保留細緻的韻律資訊或微妙的說話者特徵，而這些資訊原本在高時間解析度的表示法中才能被自然編碼。這類限制暗示需要廣播級合成品質的應用可能必須維持在 6.25 Hz 或更高的運作點，而 4.0 Hz 則更適合對延遲極度敏感或頻寬嚴重受限的情境。

**Q15：作者建議哪些未來研究方向以推進動態幀率語音語言模型？**
A：作者建議將動態幀率編碼與分塊技術相結合，例如 Fun-Audio-Chat 與 Mimo-Audio 所採用、能產生 5 Hz 或 6.25 Hz 有效 LLM 端幀率的策略，以追求更大的壓縮率與效率。他們也計畫公開釋出程式碼與重現的資料，以促進學界對可變速率 SLM 架構的後續研究。展望未來，將動態幀率的輸入與輸出整合到全雙工語音到語音對話以及交錯語音文字序列中，將是邁向真正具備資源感知能力、能夠自我調適的語音語言代理的重要途徑。

## 實務應用指南

### 適用場景

1. **邊緣裝置即時語音助理**：在智慧音箱、車載系統或穿戴裝置上，利用 4.0–6.25 Hz 低幀率模式將推論時間減半，於運算受限環境中實現低延遲的語音到語音對話。
2. **多層級雲端語音客服**：依據時段負載與客戶等級動態切換運作點，尖峰時段以 6.25 Hz 確保吞吐量，離峰或 VIP 場景切換至 12.5 Hz 以上提供高品質服務，單一模型即可滿足異構部署預算。
3. **全雙工低延遲互動系統**：在即時口譯、線上會議助理等需要雙向語音流的場景，動態幀率可依據當前發言資訊密度自動壓縮靜音與停頓段落，降低端到端延遲。
4. **高品質離線內容生成**： Podcast 後製、有聲書合成等離線任務採用高品質運作點（12.5 Hz 或更高），充分利用 FlexiSLM 超越固定幀率 7B 基線模型的語音理解與生成品質。
5. **跨裝置統一模型服務**：透過幀率條件訊號，同一組模型權重可在手機（低幀率）、PC（中幀率）與雲端伺服器（高幀率）間無縫遷移，簡化模型版本管理。

### 實作前置條件

- **資料**：需具備數千小時以上的高品質語音-文字配對資料，且涵蓋多樣語境與聲學環境；若從頭訓練動態編碼器，需額外準備用於計算語義特徵相似度的 HuBERT 或 ASR 特徵。
- **運算**：7B 等級模型訓練至少需要 32 卡 A100/H100 等級 GPU 並搭配分散式訓練框架；推論端若部署完整 7B 模型，建議單節點配置 80GB 顯存，或採用量化與模型並行策略。
- **技術能力**：團隊需熟悉 LLM 微調（如 LoRA/Full Fine-tuning）、語音前處理（採樣率轉換、特徵提取）、分散式訓練（DeepSpeed/Megatron）以及 CUDA 層級的推論加速；需有能力修改現有 SLM 的輸入層以接入動態長度序列。

### 實作步驟建議

1. **Tokenizer 與編碼管線建置**：部署 FlexiCodec，驗證其動態幀率編解碼能力；建立從原始波形到動態幀表示的完整前處理管線，包含 12.5 Hz 語義特徵提取與餘弦相似度計算模組。
2. **資料重新標記化（Re-tokenization）**：將既有固定幀率語音資料集轉換為動態幀長度序列，記錄每段音訊的實際幀率分佈，並為每個樣本產生對應的目標平均幀率條件標記。
3. **模型架構適配**：以現有 decoder-only SLM（如 Qwen2.5-Omni 或 Kimi-Audio 架構）為基礎，將輸入層替換為支援可變長度的 Dynamic-Rate Speech Encoder；在 LLM 輸入端新增幀率條件嵌入（frame rate conditioning embedding）。
4. **兩階段訓練策略**：第一階段以固定 12.5 Hz 預訓練確保模型收斂與基礎能力；第二階段引入動態幀率資料與合併閾值變化進行微調，同步優化語音理解與可控生成目標。
5. **推論排程器開發**：實作幀率控制器（Frame Rate Scheduler），依據系統負載、使用者指令或電池狀態動態設定目標平均幀率，並確保輸出層能正確解碼變長序列。
6. **評估與漸進上線**：建立涵蓋 4.0 Hz、5.0 Hz、6.25 Hz 與 12.5 Hz 的品質-速度權衡矩陣，透過 A/B 測試驗證語音到語音品質與延遲指標，再逐步導入生產環境。

### 潛在風險與注意事項

- **語音品質不一致**：動態壓縮可能在資訊稀疏處（如停頓、氣音）過度合併幀，導致輸出出現金屬雜音或語義遺失。建議設定最小幀率保護機制，並在訓練時加入重建正規化項。
- **目標幀率與實際輸出偏差**：直接幀率條件輸入若未與自迴歸生成長度充分對齊，可能產生實際輸出長度與預期不符的情況。可在訓練 loss 中增加長度預測輔助任務，或於推論時採用束搜尋（beam search）約束。
- **訓練不穩定**：動態幀率導致輸入序列長度變異大，容易造成 GPU 記憶體碎片與梯度不穩。需採用 dynamic batching、padding-free 資料流水線（如 FlashAttention 的 variable length 支援）以及 gradient checkpointing。
- **時間對齊複雜度**：既有語音資料集的時間標註（如音素邊界、說話者轉換點）多基於固定幀率設計，轉換為動態表示時需重新計算時間對齊，否則可能影響多輪對話中的輪次偵測準確率。

### 與其他技術的整合建議

- **與分塊（Patching）策略互補**：可將 FlexiSLM 的動態幀率與 Fun-Audio-Chat、Mimo-Audio 等系統的 patching 技術疊加使用，在降低聲學幀率的同時進一步壓縮 LLM 端有效幀率，達到更大程度的加速。
- **結合自適應推論框架**：整合 vLLM、SGLang 或 TensorRT-LLM 的 speculative decoding 與 chunked prefill，在幀率已降低的基礎上進一步壓縮首 token 延遲與解碼步數。
- **對接既有 ASR/TTS 生態**：若企業已有成熟 ASR 管線，可將 FlexiSLM 的 Dynamic-Rate Speech Encoder 替換為現有特徵提取器，輸出層則透過 API 橋接至既有 TTS 服務，實現從固定幀率到動態幀率的漸進式遷移。
- **雲端邊緣協同部署**：利用同一模型檢查點與幀率條件訊號，在雲端以 12.5 Hz 處理複雜查詢，邊緣裝置則依據當地算力動態切換至 4.0–6.25 Hz，統一模型版本管理並降低邊際部署成本。

### 給不同背景讀者的閱讀建議

- **初學者**：先建立「語音語言模型（SLM）」與「固定幀率」的基本概念，再聚焦圖 1 的動態幀率示意圖。不必深究 L2 loss、RVQ 或 FSQ 的數學細節，核心直覺在於「資訊密度高的語音段落保留較多幀，密度低處則合併幀以節省計算」。
- **AI 工程師**：著重閱讀幀合併模組（Frame Merging Module）與 direct frame rate conditioning 的實作細節，評估將 FlexiCodec 整合進現有 LLM 推論管線的工程量。建議對照論文附錄確認 dynamic batching、可變長度序列處理與你的 serving framework（如 vLLM、TGI）之間的相容性。
- **研究人員**：關注動態幀率對 LLM 序列建模的理論影響，特別是不同幀率條件下語音-文字對齊（speech-text alignment）與長程依賴（long-range dependency）的變化。論文提出的 direct frame rate conditioning 可作為未來可控制生成（controllable generation）的基線，值得延伸至多模態或即時互動場景。
- **產品經理**：將本文視為「同一模型滿足多層級運算預算」的技術可行性證明。重點參考 6.25 Hz 與 12.5 Hz 的品質-速度權衡數據，用於規劃產品分級（如免費快速版、標準版、高品質版語音對話），並量化異構部署帶來的邊際成本節省與使用者體驗影響。
