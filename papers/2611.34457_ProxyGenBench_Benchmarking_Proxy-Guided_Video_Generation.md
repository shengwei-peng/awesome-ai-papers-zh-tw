## 摘要翻譯

現有影片生成器（Video generators）雖能產出逼真影片，但如何控制場景的展開方式仍是一大挑戰。結構代理（Structural proxies），例如動畫化 3D 粗模（Animated 3D blockouts），透過指定場景佈局（Scene layout）、動作（Motion）、相機行為（Camera behavior）與事件順序（Event order）來引導生成。然而，此類粗略輸入留有未指定的細節，且可能包含不應重現的代理瑕疵（Proxy artifacts）。因此，成功的代理引導式生成（Proxy-guided video generation）必須保留（Preserve）預期結構、補完（Complete）缺失內容並修正代理瑕疵，以及將文字、圖像與音訊條件（Text / Image / Audio conditions）綁定（Bind）至正確的實體（Entities）與事件（Events）。我們提出 ProxyGenBench 以探討這些相互影響的需求，涵蓋 60 個場景中橫跨三項場景任務（Scene tasks）的 312 個評測案例（Evaluation cases），並控制代理精細度（Proxy fidelity）、文字細節度（Text detail）與多模態輸入（Multimodal inputs）等變項。我們使用經驗證的案例專屬檢核表（Checklists）評測五款影片生成器。實驗顯示，代理有助於提升時空控制（Spatiotemporal control），但更高的代理細節度可能伴隨較差的補完表現，而高度的結構遵循度（Structural adherence）並不保證綁定的正確性。

### 核心貢獻（3～5點）
- **提出新基準測試**：系統性地定義並評測代理引導式影片生成中「保留（Preserve）／補完（Complete）／綁定（Bind）」三項核心能力的交互作用，填補現有基準測試的缺口。
- **建構大規模評測資料集**：涵蓋 60 個場景、312 個評測案例，橫跨三項場景任務——動態動作（Dynamic action）、多鏡頭敘事（Multi-shot storytelling）、多視角一致性（Multi-view consistency），並對代理精細度、文字細節度與多模態輸入進行控制變項設計。
- **採用案例專屬檢核表**：為每個評測案例設計經驗證的檢核表，確保評分標準與各案例的具體需求精確對應，提升評測的可信度與細緻度。
- **揭示關鍵實驗發現**：代理能有效提升時空控制，但更高的代理細節度可能伴隨較差的補完表現；此外，高度結構遵循度並不保證綁定的正確性，凸顯三項能力之間的張力。

ProxyGenBench 的方法論核心在於系統性地拆解「代理引導式影片生成 (proxy-guided video generation)」這個任務，並建立可量化、可驗證的評測框架。

**任務形式化與三項核心能力定義**

論文將代理引導式影片生成形式化為一個多條件約束滿足問題，並提出三項互補但可能衝突的核心能力：

1. **保留 (Preserve)**：模型必須遵循代理 (proxy) 所指定的場景佈局 (scene layout)、物體軌跡 (object trajectories)、相機行為 (camera behavior) 與事件順序 (event order)。這是代理引導的基本前提。
2. **補完 (Complete)**：模型必須填補代理中未指定的細節內容，並修正代理瑕疵 (proxy artifacts)，例如低多邊形 (low-poly) 幾何所造成的視覺缺陷。
3. **綁定 (Bind)**：模型必須將額外的文字條件 (text conditions)、圖像條件 (image conditions)、音訊條件 (audio conditions) 正確對應到場景中的實體 (entities) 與事件 (events)。

這三項能力的拆解具有重要的理論意義：它揭示了代理引導式生成並非單純的「結構遵循」問題，而是一個涉及取捨 (trade-off) 的多目標最佳化問題。

**結構代理 (Structural Proxies) 的設計哲學**

論文採用「動畫化 3D 粗模 (animated 3D blockouts)」作為結構代理的主要形式。這種設計的關鍵在於：

- **刻意保留不完整性**：代理刻意不指定最終視覺細節，迫使模型進行補完。
- **刻意引入瑕疵**：低精細度代理 (low-fidelity proxies) 包含應被修正的幾何錯誤，測試模型的修正能力。
- **多層級精細度控制**：透過控制代理精細度 (proxy fidelity)，可以系統性地研究「保留—補完」張力。

**評測案例的受控變因設計**

312 個評測案例來自 60 個場景，每個場景提供多個變體 (variants)，系統性地控制三個維度：

#### 實驗數據解讀

**實驗設置**

論文評測了 5 個影片生成器 (video generators)，涵蓋三類場景任務：動態動作 (dynamic action)、多鏡頭敘事 (multi-shot storytelling)、多視角一致性 (multi-view consistency)。評測採用三個維度分數（保留、補完、綁定）以及一個結構敏感的嚴格分數。

**核心實驗發現**

1. **代理確實改善時空控制 (spatiotemporal control)**

實驗結果證實，代理引導在動作轉換 (action transitions) 與跨鏡頭空間一致性 (cross-shot spatial consistency) 上帶來顯著改善。這驗證了結構代理作為控制信號的價值，特別是在純文字生成容易產生不連續性 (discontinuities) 的場景中。

2. **「保留—補完」張力 (Preservation-Completion Tension)**

這是論文最重要的發現之一：在場景配對比較中，從粗略代理過渡到精細代理時，5 個模型的保留分數都上升，但補完分數都下降。這揭示了一個根本性的權衡：

- 高精細度代理提供更強的結構信號，但也「鎖定」了更多細節，限制了模型的補完空間。
- 低精細度代理給予模型更多自由度，但可能不足以提供充分的結構引導。

這個發現對實務應用具有重要指導意義：使用者需要根據任務需求選擇合適的代理精細度。

3. **強結構遵循不等於正確綁定**

在 Studio 3D 代理上的實驗顯示，模型可以達到高結構遵循度 (structural adherence)，但仍無法正確綁定額外條件。這意味著「結構遵循」與「條件整合」是兩個相對獨立的能力，模型可能在其中一個表現優異而在另一個失敗。

4. **平均保留分數的局限性**

論文指出，高平均保留分數並不保證所有關鍵結構約束都被同時滿足。這凸顯了使用案例專屬檢核表（而非聚合指標）的必要性，因為聚合指標可能掩蓋個別約束的失敗。

**評測指標的設計意涵**

嚴格分數 (Strict score) 的引入反映了論文對「代理引導式生成」任務本質的理解：結構控制是不可妥協的基本要求。這個設計避免了「模型在視覺品質上表現優異但結構完全錯誤」的情況被誤判為成功。

**VLM 判斷的可靠性**

雖然論文未深入討論 VLM 判斷的可靠性，但這是評測方法論的關鍵環節。檢核表設計為「可驗證」的形式（基於視覺/音訊證據）有助於提高 VLM 判斷的一致性，但仍需關注 VLM 本身的偏見與錯誤率對評測結果的影響。

ProxyGenBench 的獨特價值在於：它是首個系統性地研究「不完美結構代理」場景的基準測試，要求模型同時處理保留、補完、綁定三項互動需求。

## 論文問答

**Q1：為什麼現有的影片生成模型在「控制場景如何展開」這方面仍然困難？**
A：現有的影片生成模型雖然在單幀畫面的真實度上已有長足進步，但在控制場景如何展開方面仍面臨挑戰，因為僅靠文字提示與參考圖像往往無法明確指定物體的運動軌跡、相機行為與事件發生的時序。這些語意與外觀上的引導雖然能描述「場景中應該有什麼」，卻難以精準規範「物件如何移動、鏡頭如何運動、事件如何依序發生」，導致生成的影片可能出現不正確的互動、不一致的空間關係，或跨鏡頭的不連續現象，即使個別幀看起來相當合理。

**Q2：結構代理（structural proxy）為何被引入來解決控制問題？它本身又帶來了哪些新的挑戰？**
A：結構代理（例如動畫化的 3D 粗模）被引入是因為它能以粗略但明確的方式表示場景佈局、物體運動、相機行為與事件順序，補足了文字與圖像條件在時空控制上的不足。然而，結構代理本身並非完整的最終畫面，其低精細度的幾何與動作可能誤導生成器，甚至將低多邊形等瑕疵直接轉移到生成結果中。因此，模型必須學會判斷哪些代理資訊應被保留、哪些應被修正或補完，這使得代理引導式生成成為一個比單純遵循條件更為複雜的任務。

**Q3：為什麼現有的影片生成基準測試無法充分評估代理引導式生成的需求？**
A：現有的基準測試如 VBench、EvalCrafter、VBench-2.0、VideoPhy 等主要聚焦於視覺品質、時間一致性、語意對齊、物理真實性或組合性需求，較少關注「不完美的結構代理」所帶來的獨特挑戰。T2V-CompBench 雖探討屬性綁定與物件互動，TC-Bench 關注時序狀態變化，但都未系統性地研究代理引導下「保留結構、補完缺失、綁定條件」三項能力如何交互作用。因此，ProxyGenBench 的提出正是為了填補這個缺口，專門檢驗模型在面對粗略且可能含有瑕疵的結構代理時的綜合表現。

**Q4：ProxyGenBench 的核心方法論是什麼？它如何系統性地評估代理引導式生成？**
A：ProxyGenBench 的核心方法論是圍繞三項互補能力——保留（Preserve）、補完（Complete）、綁定（Bind）——來設計評測案例與評分標準。具體而言，它從 60 個場景中衍生出 312 個評測案例，涵蓋動態動作、多鏡頭敘事與多視角一致性三類場景任務，並透過控制代理精細度、文字細節度與多模態輸入的變體，系統性地檢驗模型在不同條件配置下的表現。每個案例都配有一套經過驗證、案例專屬的檢核表（checklist），由視覺語言模型依據視覺或音訊證據進行判斷，確保評估結果與生成器實際接收的輸入條件一致。

**Q5：ProxyGenBench 在評分設計上有什麼關鍵創新？為何採用「結構敏感型嚴格分數（Strict score）」？**
A：ProxyGenBench 在評分設計上的關鍵創新是將 32 個細粒度標準組織為保留、補完、綁定三大維度下的八項能力，並為每個案例實例化為專屬的檢核表問題，使評估能貼合具體場景需求。此外，它還提出「結構敏感型嚴格分數（Strict score）」，對關鍵的保留約束給予額外權重，因為結構控制是代理引導式生成的基本前提。這種設計不僅能反映平均表現，還能揭露「高分但關鍵結構約束未同時滿足」的情況，避免模型在表面上表現良好卻在核心需求上失分。

**Q6：ProxyGenBench 在案例設計上做了哪些關鍵的選擇，以確保評估的公平性與深入性？**
A：在案例設計上，ProxyGenBench 採用了「匹配且針對性的配置」策略，針對同一場景提供多個變體，系統性地改變代理精細度（低至高）、文字細節度（簡單至詳細）以及是否加入圖像、音訊等模態條件。這種設計讓研究者能在控制其他變數的前提下，單獨檢驗某一條件變化對模型行為的影響，從而深入理解「代理精細度提升是否總是帶來更好的控制」、「詳細文字是否會分散模型對代理的注意力」等細緻問題。同時，每個案例的檢核表都固定且與輸入條件對齊，確保跨模型比較的公平性。

**Q7：ProxyGenBench 實驗中評估了哪些影片生成模型？主要的實驗結果為何？**
A：實驗評估了五個影片生成模型，涵蓋當前代理引導式生成領域的主要方法。整體結果顯示，代理引導確實能改善時空控制，特別是在動作轉換與跨鏡頭空間一致性方面表現突出。然而，實驗也揭露了幾項重要發現：在場景匹配的比較中，從粗略代理轉向詳細代理時，五個模型的保留分數提升但補完分數下降，呈現明顯的「保留—補完張力」；在 Studio 3D 代理上的結果更顯示，強結構遵循度並不能保證條件綁定的正確性，模型可能在結構上表現優異，卻將文字、圖像或音訊條件綁定到錯誤的實體或事件上。

**Q8：ProxyGenBench 揭露了哪些傳統基準測試難以察覺的細微失敗模式？**
A：ProxyGenBench 透過其細粒度的檢核表揭露了多項細微失敗模式，例如：模型可能在平均保留分數上表現良好，但無法同時滿足所有關鍵結構約束；高精細度代理雖然提升了結構遵循度，卻可能將代理中的瑕疵（如低多邊形幾何）直接複製到生成結果中，導致補完能力下降；此外，模型即使在結構上高度遵循代理，仍可能將額外的文字、圖像或音訊條件錯誤地綁定到不相關的實體或事件上。這些失敗模式說明，代理引導式生成需要的是「選擇性保留」而非「盲目複製」，並需在結構遵循與內容補完之間取得平衡。

**Q9：ProxyGenBench 的「保留—補完張力（preservation–completion tension）」現象意味著什麼？**
A：「保留—補完張力」指的是當代理精細度提升時，模型在保留結構約束方面的表現提升，但在補完缺失內容與修正代理瑕疵方面的表現卻下降的現象。這意味著更詳細的代理雖然提供了更明確的結構指引，卻也讓模型更傾向於「照搬」代理內容，而較少發揮自身的補完與修正能力。這項發現對實務應用具有重要意涵：使用者不能假設「代理越詳細、結果越好」，而需根據任務需求在結構控制與內容豐富度之間做取捨，也提示未來的模型設計應明確教導模型區分「應保留的結構」與「應修正的瑕疵」。

**Q10：ProxyGenBench 所探討的代理引導式生成有哪些實際應用場景？**
A：根據論文，代理引導式生成涵蓋四個潛在應用場景：第一是強化參考圖到影片的工作流程，讓使用者能從單張參考圖出發，透過代理指定場景動態；第二是支援程式碼驅動的代理編製，讓開發者能透過程式碼生成結構代理，再由影片模型補完細節；第三是支援類遊戲世界建模，使遊戲開發者能快速將粗略的 3D 場景轉化為具體影片內容；第四是輔助 3D 動畫補完，協助動畫師將粗略的 3D 動畫擴展為完整的視覺成品。這些應用顯示代理引導式生成在創意產業與內容製作流程中具有廣泛的實用價值。

**Q11：在實際產品開發中，採用 ProxyGenBench 的評估方法應注意哪些產品層面的考量？**
A：在產品開發中採用 ProxyGenBench 的評估方法時，應注意以下產品層面考量：首先，需根據目標使用者的工作流程決定代理精細度的預設值——若使用者偏好快速迭代，應提供低精細度代理並強調補完能力；若使用者需要精確控制，則應提供高精細度代理並輔以明確的瑕疵修正機制。其次，產品應設計直覺的方式讓使用者表達「哪些代理內容應被保留、哪些應被修正」，因為這直接影響生成結果是否符合使用者意圖。此外，多模態條件（文字、圖像、音訊）的整合介面也需謹慎設計，避免使用者提供的補充資訊被模型錯誤綁定到不相關的實體或事件。

**Q12：ProxyGenBench 對影片生成領域的長遠影響是什麼？**
A：ProxyGenBench 對影片生成領域的長遠影響在於它將研究焦點從「生成逼真影片」轉向「生成可控且符合意圖的影片」，並系統性地提出了「保留—補完—綁定」的三維評估框架。這促使未來的研究者不再僅追求視覺品質的提升，而是關注模型如何在多條件、多模態輸入下進行選擇性遵循與智慧補完。同時，ProxyGenBench 揭露的「保留—補完張力」與「結構遵循不等於正確綁定」等現象，將引導學界發展新的模型架構與訓練目標，以更細緻地處理結構代理中的不完美資訊。

**Q13：ProxyGenBench 本身存在哪些已知的限制？**
A：ProxyGenBench 雖是迄今最全面的代理引導式生成基準測試之一，但仍存在若干限制：首先，其評估依賴視覺語言模型（VLM）進行判斷，雖然檢核表經過驗證且案例專屬，但 VLM 的判斷仍可能受到模型偏差影響，特別是在細粒度的時序與音訊評估上。其次，312 個評測案例雖然涵蓋三類場景任務，但相較於真實世界中代理引導式生成的應用場景仍屬有限，可能無法完全代表所有使用情境。此外，基準測試目前主要評估五個影片生成模型，未來若有新模型加入，評估結果的相對排序可能改變。

**Q14：ProxyGenBench 實驗中揭露了哪些典型的失敗案例？**
A：實驗中揭露了幾類典型失敗案例：第一類是「代理瑕疵轉移」失敗，例如在 bakery 場景中，模型將低多邊形的甜甜圈幾何直接複製到生成結果，未能將其修正為更逼真的形狀；第二類是「條件錯誤綁定」失敗，模型在結構上高度遵循代理，卻將文字描述中的物件綁定到場景中錯誤的位置或實體；第三類是「跨鏡頭不連續」失敗，即使代理指定了明確的空間佈局，模型在多鏡頭敘事中仍可能產生空間跳躍或物件細節變化。這些失敗案例凸顯了代理引導式生成在「選擇性保留」與「跨條件一致性」上的核心難題。

**Q15：基於 ProxyGenBench 的發現，未來的研究方向有哪些？**
A：基於 ProxyGenBench 的發現，未來研究可朝以下幾個方向推進：第一，發展能明確區分「應保留的結構」與「應修正的瑕疵」的模型架構，例如透過注意力機制或條件分離模組，讓模型對代理的不同部分採取不同的處理策略；第二，設計新的訓練目標以緩解「保留—補完張力」，例如引入多任務學習或對比學習，使模型在提升結構遵循度的同時不犧牲補完能力；第三，強化多模態條件綁定能力，確保文字、圖像與音訊條件能被正確對應到場景中的特定實體與事件；第四，將 ProxyGenBench 的評估框架擴展至更廣泛的應用場景與更多模型，以持續推動代理引導式生成的技術進步。

## 實務應用指南

### 適用場景

**1. 遊戲過場動畫的快速原型製作**
遊戲開發團隊可使用 ProxyGenBench 的方法論，以低精細度的 3D 粗模（blockout）作為結構代理，快速生成符合關卡設計意圖的過場影片。設計師先在遊戲引擎中擺放物件位置與相機路徑，再透過文字提示補充細節（如材質、光照、角色動作），由影片生成器產出可評估的預覽片段，用於內部審查或對外募資展示。

**2. 電影與廣告分鏡的視覺化預演（Pre-visualization）**
導演與攝影指導可在前期製作階段，以動畫化 3D 粗模定義鏡頭運動、角色走位與事件順序，再透過參考圖像指定演員外觀或場景風格。生成結果用於與客戶溝通分鏡節奏、空間關係與情緒氛圍，大幅降低傳統 pre-vis 的人力成本。

**3. 動畫工作室的場景補完（3D Animation Completion）**
動畫師完成關鍵鏡頭的 3D 動態分鏡後，可將其作為結構代理，輔以文字描述與風格參考圖，讓生成器補完中間幀、背景細節或次要角色動作，縮短從 layout 到最終成品的時間。

**4. 建築與室內設計的沉浸式導覽影片**
建築師將 BIM 或 SketchUp 模型轉為低多邊形代理，搭配材質參考圖與旁白音訊，生成具備正確空間關係與相機動線的導覽影片，用於業主提案或行銷素材。

**5. 教育訓練與工業模擬的場景生成**
教育內容創作者可將標準作業流程的 3D 動畫（如機械操作、化學實驗）作為代理，透過文字提示強調安全步驟，生成符合教學邏輯的示範影片，並透過音訊條件綁定旁白時機。

### 實作前置條件

**資料準備**
- **3D 結構代理**：需具備動畫化的 3D 場景（支援 Blender、Maya、Unity、Unreal 等工具匯出），包含物件佈局、相機路徑與關鍵幀動畫。代理可以是低多邊形粗模或高精細度模型，端看應用需求。
- **文字提示**：針對每個場景準備至少兩種細節度的文字描述——簡短版（僅描述主體與動作）與詳細版（包含材質、光照、風格、情緒等）。
- **參考圖像（選用）**：用於指定角色外觀、場景風格或物件細節，建議準備 1–4 張高解析度圖像。
- **音訊素材（選用）**：用於綁定特定事件（如爆炸聲、對話、環境音），格式建議為 WAV 或 MP3，長度需對齊目標影片時長。
- **評測檢核表**：依據 ProxyGenBench 的方法，為每個案例設計 8 項能力（保留、補完、綁定）下的具體檢核問題。

**運算資源**
- **GPU**：建議至少單張 NVIDIA A100（80GB）或 H100，用於運行現有影片生成模型（如論文評測的 5 個模型）。若需微調或自訓練，則需多卡並行（如 4×A100）。
- **儲存**：每段 5–10 秒的 1080p 影片約佔 2–5 GB，312 個評測案例的完整生成結果需預留 1–2 TB。
- **VLM 評估**：需部署視覺語言模型（如 GPT-4V、Gemini、Qwen-VL）作為評審，建議使用 API 或自架開源模型。

**技能門檻**
- **3D 建模與動畫基礎**：能使用 Blender 或類似工具建立場景、設定相機與關鍵幀。
- **提示工程（Prompt Engineering）**：熟悉文字生成影片模型的提示詞撰寫技巧，理解如何平衡結構代理與文字描述的權重。
- **影片生成模型操作經驗**：了解至少一個開源或商用影片生成模型的輸入介面與參數設定。
- **VLM 評估設計能力**：能設計可驗證的檢核問題，並解讀 VLM 的判斷結果。

### 實作步驟建議

**步驟一：定義場景任務與應用目標**
明確選擇三種場景任務之一（動態動作、多鏡頭敘事、多視角一致性），並對應到實際產品需求。例如，若目標是遊戲過場動畫，則以「多鏡頭敘事」為主；若為建築導覽，則以「多視角一致性」為核心。

**步驟二：建立結構代理**
在 3D 軟體中建立場景粗模，設定物件位置、動畫關鍵幀與相機路徑。建議先以低精細度版本開始，驗證流程可行性後再逐步提升細節。代理需匯出為影片生成器支援的格式（如 RGB 影片、深度圖、光流等）。

**步驟三：準備多模態條件**
為每個場景準備：
- 簡短與詳細兩版文字提示
- 1–4 張參考圖像（若適用）
- 對齊時長的音訊素材（若適用）

**步驟四：設計評測檢核表**
依據 ProxyGenBench 的 8 項能力（保留、補完、綁定），為每個案例撰寫具體、可驗證的檢核問題。例如：「鏡頭是否從左向右平移？」「甜甜圈的顏色是否為粉紅色？」「爆炸聲是否在第 3 秒出現？」

**步驟五：執行生成與批次評測**
使用選定的影片生成器批次生成所有變體（不同代理精細度 × 不同文字細節度 × 是否加入圖像/音訊）。記錄每個案例的生成時間、失敗率與初步觀察。

**步驟六：VLM 評估與人工抽檢**
以 VLM 對每段生成影片執行檢核表評分，並對至少 20% 的案例進行人工抽檢，驗證 VLM 判斷的可靠性。計算 Preserve、Complete、Bind 三項分數與 Strict 分數。

**步驟七：分析保留–補完張力與綁定錯誤**
依據論文發現，繪製「代理精細度 vs. 補完分數」的散佈圖，識別哪些場景出現保留–補完張力。同時檢驗高 Preserve 分數的案例是否仍存在綁定錯誤，據此調整條件配置策略。

**步驟八：迭代優化與產品化封裝**
根據評測結果，調整代理設計、提示詞模板或條件組合，將最佳實踐封裝為可重複使用的 pipeline（例如：Blender 腳本 + 影片生成 API + VLM 評估模組）。

### 潛在風險與注意事項

**風險一：代理瑕疵被原樣複製**
高精細度代理可能包含低多邊形幾何、簡化動畫或錯誤的物理行為，生成器可能將這些瑕疵視為「應保留的結構」而原樣重現。
**緩解策略**：在代理設計階段刻意保留「需被修正」的區域（如低多邊形甜甜圈），並在文字提示中明確指示「請將此物件替換為真實材質」。評測時加入「瑕疵修正」專項檢核。

**風險二：保留與補完的張力（Preservation–Completion Tension）**
論文實驗顯示，從低精細度代理切換到高精細度代理時，所有 5 個模型的 Preserve 分數上升但 Complete 分數下降。這意味著更詳細的代理反而限制了生成器的「想像空間」。
**緩解策略**：採用「分層代理」策略——主體結構使用高精細度代理以確保遵循度，次要細節（如背景、材質）使用低精細度代理以保留補完彈性。

**風險三：條件綁定錯誤（Binding Failure）**
即使結構遵循度高，模型仍可能將文字、圖像或音訊條件綁定到錯誤的實體或事件。例如，將參考圖中的角色外觀套用到錯誤的人物，或將爆炸音訊對應到錯誤的時間點。
**緩解策略**：在檢核表中為每個條件設計「綁定正確性」專項問題，並在生成後以 VLM 逐一驗證。必要時在提示詞中使用明確的實體標籤（如「角色 A」「角色 B」）以減少混淆。

**風險四：跨鏡頭不一致**
多鏡頭敘事任務中，即使單一鏡頭結構正確，跨鏡頭的空間關係、角色外觀或事件順序仍可能出現斷裂。
**緩解策略**：在評測中加入跨鏡頭一致性檢核（如「角色 A 在鏡頭 1 與鏡頭 3 的相對位置是否一致」），並考慮使用具備跨鏡頭記憶機制的影片生成模型。

**風險五：VLM 評估的可靠性限制**
視覺語言模型可能對細節判斷錯誤，或對抽象概念（如「情緒氛圍」）的評分不一致。
**緩解策略**：將檢核問題設計為「是/否」或「具體物件/時間點」的可驗證形式，避免開放式評分。對關鍵案例保留人工複審。

### 與其他技術的整合建議

**與遊戲引擎整合（Unity / Unreal Engine）**
透過引擎的 Python API 或 Blueprint 腳本，將場景物件位置、相機動畫即時匯出為結構代理影片，再呼叫雲端影片生成 API。生成結果可匯回引擎作為過場動畫的參考層或最終輸出。建議使用 Unity 的 Recorder 或 Unreal 的 Movie Render Queue 來產出代理。

**與傳統動畫流程整合（Blender / Maya）**
將 Blender 的 Grease Pencil 或 Maya 的 Playblast 作為代理來源，搭配 ComfyUI 或 Stable Video Diffusion 等開源影片生成 pipeline，形成「layout → proxy → final」的自動化工作流。可使用 Blender 的 Python 腳本批次處理多個場景。

**與 VLM 評估系統整合**
將 ProxyGenBench 的檢核表邏輯封裝為獨立的評估服務，支援 GPT-4V、Gemini、Claude 或開源模型（如 Qwen2-VL）。評估結果可寫入資料庫或儀表板，供團隊追蹤模型版本迭代的效果變化。

**與文字生成影片模型整合**
若使用商用 API（如 Sora、Veo、Kling），可將結構代理影片作為「起始幀序列」或「控制信號」輸入；若使用開源模型（如 Wan2.1、HunyuanVideo），則可透過 ControlNet 或類似的條件控制機制整合代理資訊。

**與音訊生成模型整合**
對於需要音訊綁定的場景，可先以音訊生成模型（如 AudioLDM、Stable Audio）產生對齊的音效或音樂，再將其作為條件輸入影片生成器，確保視音訊時序一致。

**與版本控制與實驗管理整合**
將每個場景的代理、文字提示、參考圖像、音訊與生成結果納入 Git LFS 或 DVC（Data Version Control），以便追蹤不同條件組合的實驗結果，支援 A/B 測試與回歸分析。

**給初學者**：建議先閱讀摘要與第 1 節的「三項核心能力」（保留、補完、綁定）框架，理解代理引導式影片生成的基本概念。可嘗試使用 Blender 建立一個簡單的 3D 粗模，搭配任何可用的影片生成工具（如 Runway、Pika）體驗「結構代理 + 文字提示」的輸入方式，觀察生成結果如何回應不同的代理精細度。

**給 AI 工程師**：重點閱讀第 2 節的相關工作（特別是 Proxy2World 與 PROWBench）以掌握技術脈絡，並深入第 3 節的問題設定與評測方法。實作上可從重現論文的檢核表評估流程開始，使用開源影片生成模型與 VLM 建立自動化評測 pipeline，再逐步擴展到自有的應用場景。注意論文中「保留–補完張力」的發現對模型設計的啟發。

**給研究者**：第 3 節的場景設計與變體控制（代理精細度 × 文字細節度 × 多模態）是本論文最具方法論貢獻的部分，建議仔細分析其如何隔離變因。第 4 節的實驗結果（特別是圖表與消融實驗）揭示了現有模型的系統性限制，可作為後續研究的切入點，例如：如何設計能動態平衡保留與補完的模型架構、如何改善多模態條件的綁定機制。

**給產品經理**：聚焦於第 1 節的應用場景（參考圖到影片工作流程、程式碼驅動代理編製、類遊戲世界建模、3D 動畫補完）與第 4 節的關鍵發現（代理提升時空控制但可能降低補完品質、結構遵循度高不等於綁定正確）。這些洞察有助於評估代理引導式影片生成在實際產品中的可行性與限制，並規劃合理的 MVP 範圍——建議從「低精細度代理 + 簡短文字提示」的組合開始驗證，再逐步引入多模態條件。
