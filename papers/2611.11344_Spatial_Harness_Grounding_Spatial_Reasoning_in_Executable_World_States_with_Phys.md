Spatial Harness 的核心設計理念是將空間推理從「模型內部隱式推理」轉變為「可執行的顯式世界狀態推理」。這個方法論的創新點在於它認識到傳統視覺語言模型 (VLM) 在空間推理任務中存在兩個根本性缺陷：場景表示錯誤與空間轉換錯誤。傳統方法將這兩個步驟都封裝在模型內部，即使最終答案錯誤，也無法區分是場景理解出了問題，還是空間轉換邏輯出了問題。

**Perceiver 的設計**：Perceiver 模組負責將問題中的語言約束與視覺估計整合到統一座標系中。從圖 4 可以看出，Perceiver 接收兩個通道的輸入：
- **文字通道**：從問題中解析出實體 (entities)、關係 (relations)、視點 (viewpoints) 與查詢需求 (query needs)
- **視覺通道**：使用多個專門化的視覺模型進行估計
  - **LocateAnything-3B**：物體偵測與定位
  - **MoGe-2**：深度估計
  - **Orient Anything V2**：物體朝向估計
  - **Reloc3r**：相機姿態估計

Perceiver 的關鍵創新在於它不僅僅是被動地接收視覺估計，而是主動地將問題中陳述的約束（如「左轉」、「相機移動關係」）作為先驗條件，用來對齊 (align)、融合 (fuse) 觀測，並強制執行 (enforce) 陳述的約束。這種「語言約束指導視覺估計」的設計哲學，使得估計出的世界狀態能夠與問題語義保持一致。

**世界狀態的表示**：世界狀態 $s = (\mathcal{L}, \Omega, \mathcal{C})$ 由三部分組成：
- $\mathcal{L}$：佈局 (Layout)，包含物體位置、朝向與相機位置、朝向
- $\Omega$：每個視角的觀測
- $\mathcal{C}$：陳述的約束

這個 JSON 格式的表示是可檢查的 (inspectable)，使得研究者可以驗證估計的場景是否符合問題描述。

**Reasoner 的執行機制**：Reasoner 是一個 VLM，它通過 Python 工具呼叫與 MuJoCo 物理引擎互動。可用的操作包括：
- `set_camera()`：設定相機位置與朝向
- `turn_left()` / `turn_around()`：執行視點變換
- `get_distances()`：獲取幾何測量
- `capture_image()`：渲染視圖

Reasoner 的工作流程是「檢查 → 選擇操作 → 更新上下文」的循環。重要的是，物理引擎在整個推理過程中保持一個共享的世界狀態，這意味著所有後續操作都基於同一個場景假設，避免了傳統思維鏈 (Chain-of-Thought) 方法中場景可能「漂移」的問題。

**與思維鏈方法的本質區別**：傳統的思維鏈方法在文字層面進行推理，每一步推理都依賴前一步的文字描述，容易產生累積誤差。而 Spatial Harness 的推理是「具身的」(embodied)，每一步操作都會產生具體的幾何測量或渲染視圖作為回饋，這些回饋來自物理引擎的精確計算，而非模型的想像。

#### 實驗數據解讀

**主要實驗結果**：在 MindCube 基準測試上，Spatial Harness 展現了顯著的改進：
- Qwen3.5-27B：從 52.70% 提升至 71.14%（提升 18.44 百分點）
- 超越 pySpatial 7.52 百分點
- GPT-5.4-mini：從 64.06% 提升至 72.67%（提升 8.61 百分點）
- Kimi K2.5：從 50.67% 提升至 59.62%（提升 8.95 百分點）

**控制變量實驗的深層意義**：圖 3 展示了一個極為重要的控制實驗——當提供相同的真實標註 (GT) 物件與相機姿態時：
- Qwen3.5-27B：Base 71.81% vs Spatial Harness 98.25%（提升 26.44 百分點）
- Qwen2.5-VL-72B：Base 81.27% vs Spatial Harness 94.10%（提升 12.83 百分點）
- GPT-5.4-mini：Base 83.78% vs Spatial Harness 89.68%（提升 5.90 百分點）

這個實驗的關鍵洞見是：**即使場景估計完全正確，模型內部推理仍然會出錯**。這證明了 Spatial Harness 的增益不僅來自更好的場景估計，更來自於「執行」本身帶來的推理能力提升。換言之，空間推理的瓶頸不僅在於「看」，更在於「轉換」。

**GT 地圖對 Base 方法的負面效應**：值得注意的是，提供 GT 地圖並未一致地提升 Base 方法的表現。這說明僅僅提供「正確的場景資訊」並不能幫助模型更好地進行空間轉換——模型仍然可能在內部推理中錯誤地應用轉換。這進一步凸顯了「可執行」設計的必要性。

**多基準測試的泛化性**：除了 MindCube，Spatial Harness 還在 SAT、MMSI-Bench、SpatialRGPT-Bench 上進行了評估，涵蓋了不同類型的空間推理任務（靜態空間關係、多步驟空間推理、空間參考框架等），展現了方法的泛化能力。

#### 與現有研究的比較

**與 pySpatial 的比較**：pySpatial 是在重建的 3D 幾何上執行程式的方法。Spatial Harness 與其相比有兩個關鍵差異：
1. **約束來源**：pySpatial 主要處理查詢的參考框架，而 Spatial Harness 使用問題中陳述的物件關係與相機運動來約束世界狀態本身
2. **狀態構建**：Spatial Harness 強調語言約束與視覺幾何的聯合優化，而非僅僅是查詢時的參考框架形式化

**與 MindJourney 的比較**：MindJourney 使用視訊世界模型合成額外視角，但它僅提供視覺證據，並不強制場景估計與後續空間轉換之間的一致性。Spatial Harness 則通過物理引擎的執行強制了這種一致性。

**與 SpatialRGPT、SpatialVLM 的比較**：這些方法通過訓練或幾何輸入增強空間理解，但仍然依賴模型內部推理。Spatial Harness 採用了正交的方法論——不改變模型本身，而是改變推理的執行環境。

**與 DeepEyes、THYME 的比較**：這些方法學習視覺工具的使用，但 Spatial Harness 專注於空間工具共享的幾何狀態，提供了工具呼叫之間的一致性保證。

**方法論的局限性**：
1. **依賴專門化視覺模型**：需要多個視覺專家模型（偵測、深度、朝向、相機姿態），這些模型的誤差會累積
2. **靜態場景假設**：當前設計假設場景是靜態的，不支持動態物理過程的推理
3. **2D 簡化**：從圖 4 的 JSON 範例可以看出，目前的表示似乎是 2D 的（位置為 [3, 6]），這可能限制了在複雜 3D 場景中的表現
4. **計算成本**：每個推理步驟都需要物理引擎執行，雖然比純模型推理更可靠，但計算成本更高

### 潛在風險與注意事項

**風險一：視覺估計錯誤傳播**
- **現象**：物件偵測、深度估計或相機姿態估計的誤差會直接影響世界狀態品質
- **緩解**：在 Perceiver 中加入約束一致性檢查；對不確定估計標註信心分數；提供 ground-truth 注入介面供高風險場景使用

**風險二：物理引擎座標系語意不一致**
- **現象**：MuJoCo 預設座標系（Y-up、Z-forward）與視覺模型輸出（常為 Z-up）衝突，導致渲染方向錯誤
- **緩解**：建立明確的座標系轉換層；所有視覺估計輸出前統一轉換；單元測試覆蓋常見視角變換

**風險三：推理迴圈無限循環或成本爆炸**
- **現象**：Reasoner 反覆呼叫工具而無收斂，每次呼叫都觸發 VLM 推理，延遲與成本急升
- **緩解**：設定最大步數上限（建議 8–15 步）；加入「已嘗試動作」記憶；對簡單問題提供捷徑模板

**風險四：渲染品質不足以支援視覺判斷**
- **現象**：MuJoCo 預設渲染為簡化幾何，缺少紋理、光照，導致 Reasoner 無法從渲染圖識別物體
- **緩解**：使用高品質紋理資產；對關鍵物體加入語意標註（如顏色標籤疊加）；在工具描述中明確告知模型渲染限制

**風險五：領域轉移時效能下降**
- **現象**：在 MindCube（室內抽象場景）表現優異，但應用到戶外、醫療等場景時效能下滑
- **緩解**：建立領域適配評估套件；保留場景估計與推理分離的架構以便單獨優化；準備領域專屬的視覺專家模型

**風險六：基準測試的 ground-truth 偏誤**
- **現象**：MindCube 等基準的 ground-truth 假設簡化，可能與真實物理場景不一致
- **緩解**：在部署前進行小規模人工驗證；對關鍵決策保留人類審核環節

### 與其他技術的整合建議

**與 Agent 框架整合（LangChain、AutoGen）**
Spatial Harness 的 Perceiver-Reasoner 架構可作為 LangChain 的 custom agent 或 AutoGen 的 conversable agent。將 MuJoCo 工具包註冊為 tool list，讓上層 orchestrator 統一調度。建議保留 Spatial Harness 的世界狀態物件作為共享 context，避免多 agent 系統中狀態不一致。

**與 3D 重建管線整合（NeRF、Gaussian Splatting）**
若場景已有高品質 3D 重建結果（如 NeRF 或 3DGS），可將其作為視覺專家模型的替代輸入，提供更精確的幾何資訊。Spatial Harness 的世界狀態可作為重建結果的「查詢介面」，而非從零估計。

**與機器人作業系統（ROS）整合**
將 MuJoCo 替換或橋接為 ROS 環境中的 Gazebo/Isaac Sim，使空間推理直接作用於真實機器人狀態。Reasoner 的工具呼叫可映射為 ROS service calls，渲染視圖可來自機器人實際相機。

**與視覺問答（VQA）系統整合**
Spatial Harness 可作為 VQA pipeline 的「空間推理模組」，當問題涉及空間關係時啟用，否則走標準 VQA 路徑。透過路由器（router）根據問題類型分流，兼顧效率與準確度。

**與檢索增強生成（RAG）整合**
將世界狀態序列化為結構化文件，存入向量資料庫。當使用者查詢歷史場景時，可檢索過去的世界狀態並進行差異比較，支援「上次 vs 這次」的空間問答。

**與多模態大型模型（MLLM）升級路徑**
當新版本 VLM 釋出時，只需替換 Reasoner 的骨幹模型，Perceiver 與工具介面可保持不變。建議設計模型抽象層，避免硬編碼特定 VLM 的 prompt 格式。
