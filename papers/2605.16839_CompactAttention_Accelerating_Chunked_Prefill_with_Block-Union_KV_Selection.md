# CompactAttention：透過區塊聯集 KV 選擇加速分塊預填充

## ⚡ TL;DR

現有稀疏注意力在分塊預填充中效率低落，且查詢子採樣易遺漏關鍵KV並產生複製開銷。
CompactAttention以區塊聯集將二維稀疏遮罩轉為GQA感知KV表，實現分頁零複製存取。
在128K分塊預填充中，於RULER基準維持近密集注意力準確率，並達2.72倍注意力加速。

## 摘要翻譯

分塊預填充（chunked prefill）已成為長上下文大型語言模型（long-context large language models）廣泛採用的服務策略（serving strategy），但在此機制下實現高效的注意力計算（attention computation）仍具挑戰性。現有的稀疏注意力（sparse attention）方法主要為單次預填充（one-shot prefill）設計，無法有效適用於分塊預填充：當查詢長度（query length）受限於區塊大小（chunk size）時，區塊稀疏核心（block-sparse kernels）會失去效率；而在每個區塊處理時反覆針對累積 KV 快取（accumulated KV cache）進行細粒度模式搜尋（fine-grained pattern search），則將導致高昂成本。近期提出的 QUOKA 方法直接針對分塊預填充設計，雖避免了稀疏核心開銷，但依賴查詢子採樣詞元級 KV 選擇（query-subsampled, token-level KV selection），可能遺漏查詢特定的 KV 項目（KV entries），並引入顯式 KV 複製開銷（KV-copy overhead）。為解決這些限制，我們提出 CompactAttention，一種基於區塊聯集 KV 選擇（Block-Union KV Selection）的分塊預填充注意力機制。CompactAttention 將二維區塊稀疏遮罩（2D block-sparse masks）視為 KV 選擇訊號，而非直接的稀疏核心執行計畫，並透過 Q 區塊聯集（Q-block union）與群組內聯集（intra-group union），將其轉換為 GQA 感知每群組 KV 區塊表（GQA-aware per-group KV block tables）。此建構過程生成最小的區塊表，在分頁執行（paged execution）限制下保留輸入遮罩所選取的所有 KV 區塊

## 深度分析

#### 方法論解析

CompactAttention 的核心設計在於提出 Block-Union KV Selection（區塊聯集 KV 選擇），其根本哲學是將「KV 區塊的選擇邏輯」與「注意力計算（attention computation）的執行方式」徹底解耦。在分塊預填充（chunked prefill）的場景中，輸入序列被切割為固定大小區塊（fixed-size chunks）依序處理，每一輪迭代僅產生少量查詢詞元，卻必須面對隨著迭代不斷增長的累積 KV 快取（accumulated KV cache）。本文方法並不直接將二維區塊稀疏遮罩（2D block-sparse masks）作為稀疏執行（sparse execution）的計畫，而是將其視為 KV 選擇信號，再透過兩階段聯集運算轉換為可在分頁執行（paged execution）架構下直接使用的資料結構。

具體而言，CompactAttention 首先沿用現有的輕量級稀疏模式搜尋（sparse pattern search）機制（例如 SeerAttention 或 FlashPrefill 的選擇器），為每個查詢區塊（query block）與每個注意力頭產生輸入相關的 2D block-sparse masks。接著，系統執行 Q-block union（Q 區塊聯集）：將同一群組內不同查詢區塊所選中的 KV 區塊取聯集，確保只要任一查詢區塊認為某個 KV 區塊重要，該區塊就會被保留，從而避免遺漏特定查詢所需的 KV 項目（KV entries）。第二步則進行 intra-group union（群組內聯集）：在分組查詢注意力（Grouped Query Attention, GQA）的架構下，將同一群組內所有注意力頭的選擇結果再次聯集，產生每群組一份精簡的 GQA 感知每群組 KV 區塊表（GQA-aware per-group KV block tables）。

這兩步聯集的關鍵意義在於產生「最小」的區塊表（minimal block tables）——即在分頁執行限制（paged execution constraints）下，恰好保留所有被輸入遮罩選中的 KV 區塊，同時不引入任何冗餘。這些區塊表最終被傳遞給分頁注意力核心（paged attention kernel），讓被選中的 KV 區塊在原地（in place）被存取，完全不需要進行顯式的 KV 壓實（KV compaction）或資料搬移。換言之，CompactAttention 以密集注意力（dense attention）的後端執行經過區塊級篩選後的 KV 子集，既規避了區塊稀疏核心（block-sparse kernels）在 Q ≪ KV 情境下因查詢區塊（query blocks）過少而導致的低平行度（parallelism）與不規則記憶體存取開銷（irregular memory-access overheads），也消除了詞元級選擇所帶來的 KV 複製開銷（KV-copy overhead）。

#### 實驗數據解讀

本文在 LLaMA-3.1-8B-Instruct 上針對 128K 上下文長度（context length）進行評估，並以 RULER 基準測試（RULER benchmark）檢驗長上下文任務的準確率。圖 1(a) 顯示，CompactAttention 達成了所有基線方法中最佳的準確率–加速比權衡（accuracy–speedup trade-off）：在維持接近密集注意力（dense attention）準確率的同時，於 H200 上最高可達到 2.72× 的注意力加速比（attention speedup）。

圖 1(b) 具體揭示了現有區塊稀疏注意力（block-sparse attention）方法在分塊預填充下的核心效率瓶頸。在名義稀疏度（nominal sparsity）為 90%、KV 長度為 64K 的設定下，單次預填充（one-shot prefill）因查詢長度（query length）與鍵值長度（key-value length）相當（Q = KV），區塊稀疏核心能接近理想加速比（ideal speedup，約 10×）；然而在分塊預填充且區塊大小（chunk size）僅 1024 的 Q ≪ KV 情境下，實際核心加速比（kernel speedup）大幅滑落至約 3×–4.5×。這證實了當查詢區塊數量過少時，稀疏執行的固定開銷無法被攤銷，導致平行度不足，使得名義稀疏度與實際效能嚴重脫鉤。

圖 1(c) 進一步量化了模式搜尋成本（pattern search cost）的累積效應。在 64K 上下文、chunk size = 1024 的設定下，分塊預填充需重複執行 64 次搜尋，使得總開銷成為首要考量（first-order concern）。XAttention 的累積開銷高達 65.4 ms，遠高於單次預填充（one-shot）模式下的約 2.9 ms；即使是相對輕量的 SeerAttention 與 FlashPrefill，其總模式搜尋成本也分別達到 39.5 ms 與 22.5 ms。這凸顯了 CompactAttention 採用「選擇器不可知（selector-agnostic）」設計的價值：它可相容於現有最輕量的模式搜尋機制，並將搜尋結果轉化為零複製（zero-copy）的執行計畫，避免重複支付高昂的稀疏核心調度代價。

#### 與現有研究的比較

現有稀疏注意力（sparse attention）研究主要針對單次預填充（one-shot prefill）設計。諸如 XAttention、SeerAttention、FlashPrefill、MInference 與 FlexPrefill 等方法，皆透過線上細粒度模式搜尋（fine-grained pattern search）來決定注意力圖（attention map）中哪些區塊可以跳過。這些方法在 Q = KV 時能有效攤銷不規則記憶體存取開銷，但在分塊預填充的 Q ≪ KV 情境下，由於查詢區塊數量受限，區塊稀疏核心難以有效隱藏延遲，導致實際加速比遠低於名義稀疏度所預期。此外，任何輸入相關的稀疏模式搜尋都必須在每一個 chunk 重複執行於累積 KV 快取之上，使得模式搜尋成本（pattern search cost）隨迭代次數線性累積。

QUOKA 是首個直接針對分塊預填充提出的替代方案，它捨棄稀疏核心，改以查詢子採樣詞元級 KV 選擇（query-subsampled, token-level KV selection）來縮減 KV 規模，再執行密集注意力。然而，這種設計有兩項根本限制：其一，由於僅對部分查詢進行子採樣，非採樣查詢所需的 KV 項目可能被遺漏，導致在需要分散式資訊存取的任務上準確率下降（如圖 2(b) 所示）；其二，詞元級選擇必須在注意力執行前進行顯式的 KV 複製（gather），產生隨上下文長度與批次大小線性增長的 KV 複製開銷（KV-copy overhead）。

CompactAttention 透過以下三點突破上述限制：
1. **區塊級選擇與執行解耦**：保留輕量級稀疏模式搜尋作為選擇信號，但將其「降級」為區塊表，而非直接驅動稀疏核心。這使其能規避 Q ≪ KV 下的核心效率陷阱。
2. **零複製分頁執行（zero-copy paged execution）**：利用 Q-block union 與 intra-group union 產生最小化的 GQA 感知每群組 KV 區塊表，讓分頁注意力核心直接原地（in place）存取被選中的 KV 區塊，無需 KV 壓實（KV compaction）。
3. **GQA 感知的最小化區塊表**：透過群組內聯集，在分組查詢注意力（Grouped Query Attention, GQA）架構下最大化 KV 區塊的跨頭共享，減少區塊表體積與記憶體間接存取成本。

儘管如此，CompactAttention 仍存在若干限制。其選擇粒度為區塊而非個別詞元（token），在極端稀疏情境下可能不如細粒度方法來得精準；此外，區塊表的建構成本雖然低於稀疏核心執行，但在超大批次或多群組情境下的絕對開銷與同步成本仍有待更細緻的分析。

#### 可重現性評估

本文標示為預印本（preprint），實驗採用已開放權重的 LLaMA-3.1-8B-Instruct 模型，並在公開的 RULER 基準測試（RULER benchmark）上進行評估。分塊預填充（chunked prefill）的實驗設定與主流服務框架（serving framework）如 vLLM 與 SGLang 一致，這些框架均為開源專案，有助於理解實驗脈絡與系統假設。

然而，從提供的全文脈絡觀察，作者並未明確宣告釋出 CompactAttention 的原始碼、Block-Union KV Selection（區塊聯集 KV 選擇）的實作細節，或完整的評估腳本。雖然分頁執行（paged execution）與分頁注意力核心（paged attention kernel）可基於現有開源後端（如 FlashAttention 系列）進行修改，但「最小區塊表」的建構演算法、GQA 感知每群組 KV 區塊表（GQA-aware per-group KV block tables）的確切資料結構，以及與現有服務框架的整合方式，仍需依賴論文所述細節重新實作。因此，在作者正式開源實現之前，完整重現該研究的門檻屬於中等偏高；社群若要驗證其結果，需自行推導聯集邏輯並修改現有分頁注意力排程器。

#### 未來研究方向

1. **更輕量的選擇器整合**：CompactAttention 的設計為選擇器不可知（selector-agnostic），未來可整合無需線上搜尋的靜態或學習式稀疏模式，進一步壓低模式搜尋成本（pattern search cost），甚至實現近乎零開銷的 KV 區塊篩選。
2. **跨架構擴展**：當前方法針對分組查詢注意力（Grouped Query Attention, GQA）設計，未來可探索將 Block-Union KV Selection（區塊聯集 KV 選擇）擴展至多查詢注意力（MQA）或更激進的 KV 快取（KV cache）壓縮架構（如 MLA），並研究其區塊表建構邏輯的適應性與最小化理論。
3. **超大規模與超長上下文驗證**：本文僅在 8B 參數模型與 128K 上下文長度（context length）下驗證。未來需在數百億參數模型與百萬級詞元（token）的上下文視窗（context window）下，檢驗區塊表建構與分頁執行（paged execution）的擴展性，特別是當 KV 快取跨越多層記憶體階層時的效能表現。
4. **動態區塊大小（chunk size）調適**：目前的評估基於固定大小區塊（fixed-size chunks）。結合動態 chunk size 與 CompactAttention 的區塊表最小化機制，可能在服務等級目標（SLOs）與詞元間時間（TBT）敏感的線上服務系統（online serving systems）中獲得更佳的延遲–吞吐量權衡。
5. **與 KV 量化及壓縮的協同**：將區塊級選擇與 KV 量化、低秩近似等方法結合，在已篩選的 KV 區塊上進一步壓縮，可能成為極長上下文推理的下一個效能前沿。
6. **解碼階段（decode phase）的延伸**：目前 CompactAttention 聚焦於預填充（prefill）階段。將類似的區塊聯集邏輯應用於解碼請求（decode requests），以加速自迴歸生成中的 KV 快取存取，並減少解碼與預填充請求在批次處理中的相互干擾，是值得探索的方向。

## 論文問答

**Q1：分塊預填充策略為何會讓長上下文大型語言模型的注意力計算變得困難？**
A：分塊預填充透過將長輸入序列切分為固定大小的區塊依序處理，雖然能避免全序列注意力的二次方計算成本，並防止過長的預填充階段阻塞解碼請求、違反詞元間時間的服務等級目標，但每個區塊的查詢長度受限於區塊大小，而鍵值長度卻隨著累積 KV 快取不斷增長。這種查詢長度遠小於鍵值長度的執行環境，使得原本為單次預填充設計的稀疏注意力方法難以有效攤銷不規則記憶體存取的開銷。此外，稀疏模式搜尋必須在每一個區塊重複執行，導致搜尋成本隨著上下文長度累積，成為首要的性能瓶頸。

**Q2：現有的區塊稀疏注意力方法直接套用於分塊預填充時，會暴露哪些關鍵限制？**
A：現有區塊稀疏注意力方法主要針對單次預填充設計，其查詢與鍵值長度通常相當，足以讓稀疏核心透過大量查詢區塊來攤銷固定開銷；然而在分塊預填充中，查詢長度僅有數百到一千個詞元，活躍查詢區塊數量過少，使得稀疏核心的不規則記憶體存取與遮罩解讀成本無法被有效掩蓋，實際加速比遠低於名義稀疏度。另一方面，輸入相關的稀疏模式搜尋必須在每一個區塊針對不斷累積的 KV 快取重新執行，任何線上搜尋機制的成本都會被放大數十倍甚至更多。這使得只有極輕量級的模式搜尋機制在分塊預填充下才具實用性，嚴重限制了方法的選擇空間。

**Q3：QUOKA 作為直接針對分塊預填充的方法，存在哪些根本性的缺陷？**
A：QUOKA 透過查詢子採樣來評分 KV 項目的重要性，並對選出的詞元執行密集注意力，雖然避開了稀疏核心開銷，但其子採樣策略無法保證未採樣查詢所需的重要 KV 項目被保留，導致在需要分散式資訊存取的任務上準確率顯著下降。其次，QUOKA 採用詞元級 KV 選擇，必須在注意力執行前進行顯式的 KV 收集與複製，這項複製開銷會隨著上下文長度與批次大小線性增長。因此，QUOKA 在長上下文與高吞吐量的服務場景中，會面臨準確性與記憶體搬移成本的雙重挑戰。

**Q4：CompactAttention 的核心設計理念是什麼？它如何解決現有方法的困境？**
A：CompactAttention 的核心在於將區塊稀疏遮罩從「稀疏核心執行計畫」重新定位為「KV 選擇信號」，從而解耦區塊級 KV 選擇與稀疏核心執行。它將二維區塊稀疏遮罩轉換為 GQA 感知每群組 KV 區塊表，透過 Q 區塊聯集與群組內聯集產生最小化的區塊表，並利用現有的密集分頁注意力後端原地存取被選中的 KV 區塊。這種設計同時規避了區塊稀疏核心在查詢長度受限時的平行度不足問題，也消除了詞元級選擇所帶來的顯式 KV 複製開銷。

**Q5：何謂「區塊聯集 KV 選擇」（Block-Union KV Selection）？其具體運作流程為何？**
A：區塊聯集 KV 選擇是 CompactAttention 提出的遮罩轉換機制，用於將每個查詢區塊、每個注意力頭的稀疏遮罩壓縮成符合分頁執行限制的最小區塊表。首先，Q 區塊聯集會將同一群組內不同查詢區塊所選中的 KV 區塊進行聯集，確保該群組所有查詢所需的 KV 區塊都被涵蓋；接著，群組內聯集進一步合併同一 GQA 群組中不同頭的選擇結果，產生每群組一份精簡的 KV 區塊表。最終產出的區塊表在保留所有被選中 KV 區塊的前提下，將分頁執行所需的後設資料降至最少。

**Q6：CompactAttention 為何選擇使用密集分頁注意力後端，而非直接呼叫區塊稀疏核心？**
A：在分塊預填充的查詢長度遠小於鍵值長度的情境下，區塊稀疏核心因查詢區塊數量不足，無法產生足夠的平行度來攤銷稀疏遮罩解讀與不規則記憶體存取的固定成本，導致實際加速比大幅低於理想值。CompactAttention 透過將稀疏選擇結果轉換為 KV 區塊表，讓密集分頁注意力核心僅針對被選中的區塊執行計算，並利用分頁執行機制原地存取資料。這種方式既保留了密集核心在記憶體存取規則性上的優勢，又透過區塊級選擇達成了稀疏加速，無需承擔稀疏核心的執行效率損失。

**Q7：論文使用了哪些模型與基準測試來評估 CompactAttention 的效能？**
A：論文選用 LLaMA-3.1-8B-Instruct 模型作為主要評估對象，並在 RULER 基準測試上驗證其長上下文能力。RULER 是一項專門設計來評估模型在極長序列中進行檢索與推理任務表現的基準，能夠檢驗注意力機制是否保留了關鍵的遠距離依賴資訊。實驗特別關注在 128K 上下文長度下，CompactAttention 相較於密集注意力與其他基線方法在準確率與加速比上的權衡表現。

**Q8：CompactAttention 在實驗中達成了哪些關鍵量化成果？**
A：在 LLaMA-3.1-8B-Instruct 上針對 128K 上下文長度的分塊預填充測試中，CompactAttention 最高可達到 2.72 倍的注意力加速比，同時在 RULER 基準測試上維持接近密集注意力的準確率。如圖 1(a) 所示，相較於 XAttention、SeerAttention、FlashPrefill 與 QUOKA 等基線方法，CompactAttention 達成了最佳的準確率–加速比權衡。這些結果證明區塊聯集 KV 表建構與零複製分頁執行能夠直接解決現有分塊預填充注意力方法的執行瓶頸。

**Q9：與區塊稀疏核心和 QUOKA 相比，CompactAttention 在效率與準確性上的具體優勢為何？**
A：相較於區塊稀疏核心，CompactAttention 避免了在查詢長度受限時加速比嚴重衰退的問題，因為後者在分塊預填充下的實際核心加速比遠低於單次預填充與理想值。與 QUOKA 相比，CompactAttention 不依賴查詢子採樣，因此不會遺漏對未採樣查詢至關重要的 KV 項目，在需要分散式資訊存取的任務上能維持與密集注意力相近的準確率。此外，CompactAttention 透過區塊表實現原地存取，徹底消除了 QUOKA 詞元級選擇所帶來的顯式 KV 複製開銷。

**Q10：CompactAttention 在哪些實際的線上服務場景中最具應用價值？**
A：CompactAttention 特別適用於需要處理長上下文且將預填充與解碼請求混合批次的線上服務系統，例如文件理解、程式碼分析與智慧體工作負載。在這些場景中，服務框架必須採用分塊預填充來防止長序列預填充阻塞解碼流程，以滿足詞元間時間的服務等級目標。CompactAttention 在不犧牲準確率的前提下顯著加速注意力計算，使其能夠無縫整合至 vLLM、SGLang 等主流生產級服務框架中。

**Q11：CompactAttention 如何與現有的服務框架（如 vLLM 與 SGLang）整合？**
A：CompactAttention 的設計充分考慮到現代服務框架普遍採用的分頁 KV 快取管理機制，其產生的 GQA 感知每群組 KV 區塊表完全符合分頁執行限制。服務框架可以直接將這些區塊表傳遞給現有的密集分頁注意力核心，讓被選中的 KV 區塊在原地被存取，無需額外的 KV 壓實或自定義稀疏核心。這意味著 CompactAttention 能夠以極低的整合成本部署為即插即用的注意力後端，僅需在現有流程中加入輕量級的遮罩轉換邏輯。

**Q12：這項工作對長上下文大型語言模型服務領域可能帶來什麼影響？**
A：這項工作確立了「將稀疏模式選擇與稀疏核心執行解耦」的新範式，為未來的長上下文服務系統設計提供了重要參考。它證明透過區塊級選擇結合密集分頁執行，可以同時解決區塊稀疏核心效率不足與詞元級選擇複製開銷這兩大痛點。隨著上下文視窗持續擴展至數十萬甚至數百萬詞元，像 CompactAttention 這樣相容於輕量級模式搜尋、具備選擇器不可知特性的設計，將對可擴展的線上服務愈發關鍵。

**Q13：論文暗示或承認了 CompactAttention 的哪些限制？**
A：CompactAttention 仍需依賴外部的輕量級稀疏模式搜尋方法來產生初始的二維區塊稀疏遮罩，因此其整體效率與成本仍與所選模式搜尋機制的品質與開銷息息相關。雖然執行階段避免了累積搜尋成本的放大效應，但模式搜尋本身仍須在每個區塊重複進行，這是設計上未完全消除的開銷來源。此外，目前的評估主要集中於 LLaMA-3.1-8B-Instruct 模型與 RULER 基準測試，對於更多樣的模型架構與任務類型的廣泛驗證仍有待後續研究補充。

**Q14：在什麼樣的條件或任務下，CompactAttention 可能仍會面臨挑戰或表現不佳？**
A：若任務所需的最佳注意力模式極為細粒度，無法被區塊級選擇有效近似，則 CompactAttention 可能面臨準確率下降或加速比受限的兩難。當任務需要存取大量分散在整個上下文中的稀疏 KV 位置時，遮罩可能選中過多的區塊，導致有效稀疏度過低而趨近密集執行。在這種情況下，區塊聯集所產生的最小區塊表仍可能過大，使得分頁密集核心的執行時間無法顯著優於全密集注意力。

**Q15：這項工作為未來的研究與開發指出了哪些方向？**
A：未來研究可進一步探索與 CompactAttention 選擇器不可知設計相容的更快模式搜尋機制，以從源頭降低跨區塊累積的搜尋成本。另一個方向是將區塊聯集方法擴展至分組查詢注意力以外的更多樣注意力架構，或根據輸入複雜度動態調整稀疏度。此外，在更大規模模型、超過 128K 的極長上下文，以及更多真實世界長程推理工作負載上進行全面評估，將有助於鞏固此方法在下一代長上下文服務系統中的適用性。

## 實務應用指南

### 適用場景

1. **長文件即時問答與分析系統**：法律、醫療或金融領域需要處理 128K 以上詞元的長篇報告，並在分塊預填充過程中維持低詞元間時間（TBT），避免解碼請求被長篇預填充阻塞。
2. **程式碼倉庫級智慧體工作負載**：開發助手需一次性理解整個程式碼庫（多檔案、長上下文），透過分塊預填充逐步建立累積 KV 快取，CompactAttention 可加速每次 chunk 的注意力計算而不遺漏跨檔案的關聯語意。
3. **多輪對話中的長期記憶維護**：客服或教育機器人在多輪互動中累積大量歷史 KV 快取，利用區塊聯集 KV 選擇在每一輪新 chunk 中快速篩選相關歷史上下文，降低延遲同時保持對話連貫性。
4. **批次化長文檔摘要與比較服務**：新聞聚合或研究助理平台批次處理多篇長文，在固定大小區塊的限制下（Q ≪ KV），避免傳統區塊稀疏核心因查詢區塊過少而效率低落。
5. **即時串流長文本推理**：語音轉文字或直播字幕生成等串流場景，輸入以 chunk 形式持續抵達，需要對不斷增長的累積 KV 快取執行輕量級稀疏模式搜尋與零拷貝分頁執行。

### 實作前置條件

- **資料**：需準備長上下文評估資料集（如 RULER、Needle-in-Haystack）以及領域特定驗證資料，用以確認區塊稀疏遮罩轉換後的準確率損失在可接受範圍內。
- **運算**：需配備高記憶體頻寬的 GPU（如 H200、H100），且推論框架必須原生支援分組查詢注意力（GQA）與分頁執行（PagedAttention）；建議以 vLLM 或 SGLang 作為底層服務框架。
- **技術能力**：團隊需具備 CUDA/Triton 核心開發經驗，熟悉 FlashAttention 的記憶體配置與分頁管理邏輯，並能修改或擴充現有 paged attention kernel 以支援非連續 KV 區塊表的原地存取。

### 實作步驟建議

1. **基線建立與瓶頸分析**：在現有服務框架中建立密集注意力基線，針對分塊預填充階段量測注意力延遲、記憶體頻寬利用率與 TBT，確認瓶頸確實來自 Q ≪ KV 時的注意力計算。
2. **輕量級區塊稀疏模式搜尋整合**：選用輕量級 selector（如 SeerAttention 或 FlashPrefill）產生每個查詢區塊、每個注意力頭的二維區塊稀疏遮罩，避免細粒度模式搜尋在累積 KV 快取上產生過高的重複開銷。
3. **Block-Union KV 區塊表建置**：實作 Q 區塊聯集與群組內聯集邏輯，將 2D 遮罩轉換為 GQA 感知每群組 KV 區塊表。此步驟需確保在分頁執行限制下保留所有被選中的 KV 區塊，並產生最小化的區塊表以降低記憶體管理負擔。
4. **零拷貝分頁核心整合**：擴充現有 paged attention kernel，使其能直接透過區塊表原地存取被選中的 KV 區塊，完全避免顯式的 KV 壓實或詞元級複製操作。
5. **準確率與延遲驗證**：在 RULER 基準測試與領域特定任務上驗證準確率，確保接近密集注意力；同時在 128K 等長度下量測端到端注意力加速比與 TBT 改善幅度。
6. **生產環境部署與監控**：整合至線上服務系統，監控每個 chunk 的模式搜尋開銷與累積 KV 快取下的記憶體使用，動態調整區塊大小與稀疏度閾值，並針對不同請求長度實施分桶（bucketing）以減少批次內分歧。

### 潛在風險與注意事項

- **查詢特定 KV 遺漏風險**：若上游模式搜尋過度依賴全局平均注意力（mean received attention），可能遺漏僅對少數查詢至關重要的 KV 區塊。建議採用 max received attention 與 mean received attention 混合評分，並保留動態備援區塊。
- **模式搜尋累積開銷**：雖然 CompactAttention 將搜尋與執行解耦，但每個 chunk 仍需重新評分累積 KV 快取。需確保搜尋複雜度為亞線性，避免在超長上下文（1M+ 詞元）下成為首要考量。
- **分頁記憶體碎片化**：非連續的 KV 區塊選取可能與現有分頁配置器互動不良。需確認區塊表與底層物理頁面映射一致，避免額外的記憶體對齊開銷或頁面碎片化。
- **批次內異質性**：當批次內請求的上下文長度與稀疏模式差異大時，統一的區塊表可能導致記憶體存取分歧與核心效率下降。建議在排程層實施長度分桶或稀疏模式相似性分群。

### 與其他技術的整合建議

- **與 vLLM/SGLang 整合**：CompactAttention 原生相容於分頁執行語義，建議以 vLLM 的 Attention Backend Plugin 或 SGLang 的 RadixAttention 擴充形式實作，直接複用現有的 block table 與 page manager，降低整合成本。
- **與推測解碼（Speculative Decoding）整合**：在分塊預填充階段應用 CompactAttention 降低預填充延遲，同時保留標準推測解碼路徑加速解碼階段，兩者在執行階段互不干涉且效益互補。
- **與 KV Cache 量化整合**：區塊表可與 INT8/FP8 KV Cache 量化疊加使用，但需注意稀疏選取後的區塊存取模式可能降低量化後記憶體存取的規則性，建議以區塊為單位進行量化而非逐詞元，以維持記憶體共同體（memory coalescing）效率。
- **與 Prefix Caching 整合**：若服務框架支援 prefix caching，CompactAttention 的區塊表可直接指向已快取的前綴頁面，避免對共享前綴重複執行區塊聯集計算，進一步提升快取命中率。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先理解「分塊預填充」與「KV 快取」的基本概念，再聚焦論文的圖 1 與圖 2，掌握「為何現有稀疏注意力在分塊場景失效」這一核心動機；技術細節如 Q 區塊聯集可先略過，重點理解「把遮罩當訊號而非執行計畫」的設計哲學。
- **AI 工程師**：請仔細研讀 Block-Union KV Selection 的演算法流程與 GQA 感知區塊表的建構邏輯，評估自身服務框架的 paged attention kernel 是否支援原地非連續存取；同時參考論文中與 QUOKA、SeerAttention 的對比，評估導入後的準確率維護成本。
- **研究人員**：關注論文如何將「稀疏模式搜尋」與「稀疏核心執行」解耦的設計思路，以及 Q-block union 與 intra-group union 在理論上如何保證最小化區塊表；可進一步探索動態稀疏度調整、更激進的區塊壓縮策略，或將此框架擴展至線性注意力與狀態空間模型。
- **產品經理**：重點閱讀摘要與圖 1(a) 的準確率–加速比權衡，理解 CompactAttention 在 128K 上下文達到 2.72 倍加速的同時維持接近密集注意力的準確率；評估導入時需確認現有模型是否採用 GQA、服務框架是否為 vLLM/SGLang，並將「降低 TBT」與「支援更長上下文視窗」作為核心產品價值主張。
