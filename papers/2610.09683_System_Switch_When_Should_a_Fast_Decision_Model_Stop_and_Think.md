# 系統切換：快速決策模型何時該停止並思考？

## 摘要翻譯

雙過程代理（Dual-process agents）將快速策略（fast policy）與慢速審議模型（slow deliberative model）配對。在即時設定（real-time settings）中，慢速模型通常持續運行；在回合制代理（turn-based agents）與機器人規劃器（robot planners）中，它會在不確定性（uncertainty）或偵測到失敗（detected failure）等事件發生時被呼叫。我們研究一個快速的學習型行動者（actor），它負責做出每一個決策，僅在閘門（gate）開啟時將控制權交給推理型視覺語言模型（vision-language model），而遊戲持續運行。我們使用閉環式（closed-loop）Doom（毀滅戰士）以及新開放的 System One 類型化決策模型（typed-decision models），透過通用的 llama.cpp 介面提供服務。

在 900 個留出的題目上：(i) 從 0.15B 到 9B 參數的零樣本決策模型（zero-shot decision models），在任何選項順序下，於其所犯的錯誤中，選擇收集物品的頻率為隨機機率（chance）的 1.6 至 1.8 倍，雖然順序會改變某些模型的準確率（accuracy）；(ii) 準確率、校準度（calibration）與敏感度（sensitivity，置信度區分正確與錯誤答案的能力）是截然不同的：相似準確率的模型在 ROC 曲線下面積（AUROC）上差異甚大，而最敏感模型的置信度（confidence）對應的是它在哪類情境中失敗，而非哪些答案是錯誤的；(iii) 在離線情況下，將置信度最低的 30% 決策委託（deferral）給推理模型所帶來的增益，與行動者的 ROC 曲線下面積成正比（秩相關 [rank correlation] 0.87）；在留出測試遊戲上選擇行動者與比率時，使用 doomLaya 的選項順序可獲得 +0.13 [0.08, 0.18] 的增益，使用打亂的選項則為 +0.08 [0.02, 0.14]，其中約一半的增益來自推理；(iv) 在閉環中（33 場遊戲，三個隨機種子 [seeds]），沒有任何變體能抵達出口。執行推理器（reasoner）或固定探索規則（fixed explore rule）的計畫，能開啟更多門，並使原本靜止不動的行動者開始行動；使用該規則時，代理的死亡率更高。當被告知某些門需要鑰匙時，推理器會將普通門誤認為上鎖的門，而狀態無法區分兩者；若無此知識，則會恢復收集物品。我們釋出程式碼、提示詞（prompts）、資料與日誌（logs）。

### 核心貢獻（3～5點）
- **揭示零樣本決策模型的系統性錯誤偏差**：在 900 個留出題目上，0.15B–9B 參數的零樣本決策模型於其所犯的錯誤中，選擇收集物品的頻率為隨機機率的 1.6–1.8 倍，且此偏差不受選項順序影響。
- **區分準確率、校準度與敏感度三項指標的獨立性**：相似準確率的模型在 AUROC 上差異甚大；最敏感模型的置信度反映的是其失敗的情境類型，而非具體答案的正誤。
- **量化離線委託增益與其來源**：將置信度最低的 30% 決策委託給推理模型，所得增益與行動者 AUROC 成正比（秩相關 0.87），其中約一半來自推理模型本身。
- **閉環實務觀察與失敗模式分析**：在 33 場遊戲、三個隨機種子的閉環測試中，無變體能抵達出口；執行推理器或固定探索規則的計畫可開啟更多門並使靜止的行動者開始行動，但推理器在缺乏鑰匙知識時會將普通門誤判為上鎖的門。

### 適合對象
從事雙過程認知建模、視覺語言代理、即時遊戲 AI、強化學習中元推理與委託策略研究，以及對大型語言模型置信度校準、錯誤分析與閉環決策系統感興趣的研究者與工程師。

## 深度分析

#### 方法論解析

本文提出了一種**事件閘控雙過程代理架構 (event-gated dual-process agent architecture)**，其核心設計理念源自人類認知的第一人稱觀察：當動作有效時，大腦「關閉」並直接行動；當射擊不再有效（門打不開、敵人不斷重生）時，便會停下來思考，而正是思考讓行動得以繼續。這種「即時事件閘控思考 (event-gated thinking in real time)」的設計與既有方法有本質差異。

**架構組成：**
- **快速類型化決策行動者 (fast typed-decision actor)**：採用 2026 年 9 月發布的開源 System One 模型家族（Laya、Kev、Lev、Julia、Clef、OpenJev、Strands Decider、CLM），參數規模從 0.15B 到 9B。這些模型透過單次前向傳遞 (forward pass) 加上線性讀出 (linear readout) 回答類型化問題（choice、score、yes/no），並輸出機率值。
- **視覺推理器 (vision reasoner)**：在閘門開啟時被異步 (asynchronously) 調用，於背景執行緒中思考。
- **閘門機制 (gate mechanism)**：包含兩種觸發條件——不確定性觸發 (uncertainty trigger) 與進度觸發 (progress trigger)，本文於閉環實驗中比較了這兩種觸發方式。

**環境與介面：**
- 使用 Freedoom 2 透過 ViZDoom 1.3.1 與 doomLaya（commit b25edd3）建構環境。
- 每 0.5 秒遊戲時間接收文字狀態（血量、防彈衣、物品、可見敵人、可見物品、門）與兩個選擇題：command（攻擊敵人、收集物品、開門、前往出口、撤退、探索、等待）與 weapon。
- 選項以固定順序呈現（敵人、物品、門、出口、撤退、探索、等待），此順序對部分模型的準確率有影響。
- 透過 llama.cpp 的 `common/v1/systemone` 端點統一服務所有模型，實現單一橋接器 (bridge) 服務多模型。

**時鐘設計：**
ViZDoom 以同步模式運行，由 doomLaya 控速至真實時間（35 tics/秒），每場遊戲的牆鐘時間等於遊戲時間。決策請求每 0.5 秒發出一次，**異步處理**：當答案待回時，遊戲以先前指令繼續運行。切換機制讓行動者立即回答，推理器在背景執行緒思考，因此一個耗時 12 秒的思考實際佔用 12 秒的遊戲時間——這是本文與既有即時代理（如 DPT-Agent、AgileThinker）持續運行慢速元件的關鍵差異。

**標籤機制：**
doomLaya 的 oracle（基於規則的專家標註者）以規則標記遊戲狀態，提供 ground truth 用於離線評估。

#### 實驗數據解讀

**離線評估（900 個留出問題）：**

(i) **錯誤模式分析**：零樣本決策模型在錯誤中選擇「收集物品」的頻率比隨機機率 (chance) 高出 1.6–1.8 倍，且此現象在任何選項順序下皆成立，顯示這是模型家族的系統性偏差而非順序效應。然而，順序變更確實會影響部分模型的準確率。

(ii) **三種性質的區分**：本文最重要的概念貢獻之一是明確區分**準確率 (accuracy)、校準度 (calibration) 與敏感度 (sensitivity)**：
- 準確率相似的模型在 AUROC 上差異極大。
- 最敏感模型的置信度 (confidence) 追蹤的是「它會失敗的**情境類型**」而非「哪些答案錯誤」。
- 這意味著傳統上將置信度等同於「答對機率」的假設過於簡化。

(iii) **離線委託增益 (offline deferral gain)**：
- 將最不置信的 30% 決策委託給推理模型所獲得的增益，與行動者的 AUROC 成正比（秩相關 0.87）。
- 在留出遊戲上選定行動者與委託率後：
  - doomLaya 選項順序下增益為 **+0.13 [0.08, 0.18]**
  - 隨機選項順序下增益為 **+0.08 [0.02, 0.14]**
- 推理器本身承擔約一半的增益，顯示推理確實有實質貢獻而非僅是過濾器。

(iv) **閉環實驗（33 場遊戲，三個隨機種子）**：
- **無變體到達出口**——這是個關鍵的負面結果，凸顯離線增益與線上表現的巨大落差。
- 承諾執行計畫（無論是推理器的計畫或固定探索規則）能開啟更多門，並讓原本靜止不動的行動者開始行動。
- 使用固定探索規則時，代理死亡頻率更高。
- 告知推理器「部分門需要鑰匙」後，推理器會將普通門誤判為上鎖的門（因為狀態無法區分）；無此知識時則回到收集物品行為。

**關鍵洞察：**
離線 AUROC 與線上表現的脫鉤是最值得深思的發現。AUROC 衡量的是置信度區分對錯的能力，但閉環中代理面對的是序列決策問題——單一決策的正確性不等於長期獎勵的提升。此外，推理器的「思考」在閉環中可能引入新錯誤（如將普通門當作上鎖門），這是離線評估無法捕捉的。

#### 與現有研究的比較

**與雙過程代理的定位：**

| 既有方法 | 運作模式 | 本文差異 |

| SwiftSage [20]、CogniWeb [21] | 回合制，啟發式觸發（缺乏獎勵、無效動作、重複失敗） | 本文為即時制 |
| FAST [32]、Talker-Reasoner [7]、CogRouter [36]、Pangu Embedded [5] | 每步選擇推理深度 | 本文閘控而非深度選擇 |
| SOFAI [3] | 元認知模組逐題選擇，使用置信度與思考成本 | 本文處理即時序列決策 |
| Inner Monologue [16]、DoReMi [15] | 機器人規劃，語言模型規劃每一步 | 本文快速行動者處理每步 |
| DPT-Agent [37]、AgileThinker [35] | 即時制，慢速元件持續運行 | 本文慢速元件僅在閘門開啟時運行 |
| GR00T N1 [24] | 雙系統機器人策略，慢速元件以固定速率運行 | 本文為事件驅動而非固定速率 |

**與委託/選擇性預測的比較：**
- ReDAct [27] 讓小型 LLM 在不確定性超過校準閾值時委託給大型 LLM，約 15% 委託率在 ALFWorld 與 MiniGrid 上匹配大型模型。
- 本文差異在於：(1) 行動者為非生成的類型化決策模型，置信度需先證明具資訊性；(2) 同時閘控於進度與不確定性；(3) 在即時環境中運作。

**與基準測試的關係：**
- Jev Decision Index [23] 與 JevBench [31] 評分單一決策，本文加入閉環維度。
- 這些基準指出 System One 模型的弱點在於「需要多步驟推論、算術或權衡競爭性考量」，而本文驗證了此觀察：離線委託確實有增益，但閉環中推理器的錯誤（如將普通門當作上鎖門）正是此類弱點的體現。

**改進與限制：**
- **改進**：首次系統性地在即時環境中實現事件閘控雙過程代理，並明確區分準確率、校準度與敏感度三種性質。
- **限制**：(1) 閉環中無變體到達出口，顯示離線到線上的轉譯仍有巨大鴻溝；(2) 推理器的錯誤模式（將普通門誤判為上鎖門）暴露了視覺推理在部分可觀察環境中的脆弱性；(3) 樣本數（33 場遊戲、三個種子）相對有限。

#### 未來研究方向

**1. 閘門機制的精進：**
- 結合不確定性與進度的多模態閘門：本文已比較兩種觸發方式，但更複雜的組合（如「不確定性高且進度停滯」）可能更有效。
- 學習式閘門：透過強化學習或監督學習自動學習閘門開啟策略，而非依賴人工設計的啟發式。

**2. 推理器的錯誤修正：**
- 針對「將普通門誤判為上鎖門」的問題，可研究：(a) 更好的狀態表示以區分普通門與上鎖門；(b) 推理器的自我驗證機制；(c) 多模態融合（視覺+文字）以提升感知準確度。

**3. 離線到線上的轉譯：**
- 本文最關鍵的發現是離線 AUROC 與線上表現的脫鉤。未來研究可探索：(a) 序列決策評估指標（如 regret、cumulative reward）與單步 AUROC 的關係；(b) 模擬環境中的大規模線上評估；(c) 線上學習的閘門參數調整。

**4. 類型化決策模型的改進：**
- 解決「收集物品偏差」：所有模型在錯誤中都傾向選擇收集物品，這暗示訓練資料或架構有系統性偏差。
- 提升敏感度：開發能更好區分「會失敗的情境類型」與「會答錯的問題」的模型。

**5. 計算成本與延遲管理：**
- 本文假設推理時間佔用遊戲時間，但實際部署中可考慮：(a) 預測性推理（在閘門開啟前預先思考）；(b) 推理結果快取；(c) 分層推理（先快速推理，必要時升級到深度推理）。

**6. 跨領域泛化：**
- 將此架構從 Doom 推廣到其他即時環境（如自動駕駛、機器人導航、遊戲 AI），驗證事件閘控雙過程代理的通用性。

**7. 認知科學的深度連結：**
- 本文的人類認知類比（第一人稱觀察）頗具啟發性，未來可與認知科學的元推理理論 (rational metareasoning) 更緊密結合，例如將預期思考價值 (expected value of thinking) 與閘門決策形式化對應。

**8. 多代理協作：**
- 探索多個快速行動者共享一個推理器的架構，或多個推理器之間的協商機制，以處理更複雜的任務。

總結而言，本文在即時雙過程代理領域提出了重要的架構創新（事件閘控而非持續運行），並透過嚴謹的離線與閉環實驗揭示了「置信度追蹤情境類型而非答案正確性」這一深刻洞察，同時誠實地呈現了離線增益無法完全轉化為線上表現的現實挑戰，為後續研究提供了清晰的方向指引。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**
A：這篇論文探討的是雙過程代理（dual-process agents）中的「切換時機」問題——也就是快速反應的系統一（System 1）應該在什麼時候停下來、將控制權交給慢速審議的系統二（System 2）進行思考。作者從第一人稱射擊遊戲 Doom 的玩家經驗出發，觀察到當動作有效時大腦會「自動關閉」純粹反應，但當射擊不再有用（例如門打不開、敵人反覆出現）時，就會停下來思考，而正是這個思考讓玩家重新動起來。這種「事件閘控思考」（event-gated thinking）在即時環境中尤其關鍵，因為遊戲不會等待代理完成計算。論文的目標是將這種人類認知模式形式化，並透過實證研究找出最佳的切換策略。

**Q2：現有的雙過程代理設計在即時環境中為何表現不佳？**
A：現有的雙過程代理大致可分為兩類，但都存在明顯限制：第一類是即時代理（如 DPT-Agent、AgileThinker、GR00T N1），它們讓慢速組件持續運行，不論是否需要，這造成了不必要的計算成本與延遲；第二類是回合制代理（如 SwiftSage、CogniWeb、SOFAI）與機器人規劃器（如 Inner Monologue、DoReMi），它們雖然採用事件觸發，但通常在每個高層次決策上都依賴語言模型，無法在即時環境中持續運作。此外，現有方法多將慢速組件視為「每步驟的規劃器」，而非「只在必要時介入的顧問」，這使得它們在計算預算與反應速度之間難以取得平衡。本論文正是為了填補這個「即時環境中事件閘控思考」的研究空缺。

**Q3：為什麼這項研究在當前時點特別重要且成本低廉？**
A：這項研究的時效性來自三個技術發展的匯聚：第一，2026 年 9 月出現了一系列開源的「System One」類型化決策模型（如 Laya、Kev、Lev、Julia、Clef、OpenJev、Strands Decider、CLM），它們能以單次前向傳遞回答類型化問題並提供看起來已校準的機率；第二，llama.cpp 新增了 common/v1/systemone 端點，使得同一個橋接器能在相同硬體上服務所有模型；第三，獨立基準測試（如 Jev Decision Index、JevBench）已指出這些模型的弱點在於需要多步驟推論、算術或權衡競爭性考量的題目，而這正是推理模型的強項。這三項發展意味著研究者可以用極低的成本系統性地研究「切換 vs. 替代」的設計選擇，並將模型放入閉環中實際測試，而非僅評分單一決策。

**Q4：這篇論文提出的核心方法是什麼？**
A：論文提出的核心方法是一種「閘控式雙過程架構」：一個快速的類型化決策行動者（fast typed-decision actor）負責在每個 0.5 秒的決策點做出選擇，而視覺語言推理模型（vision-language model）僅在「閘門開啟」時才被呼叫。閘門的觸發條件包括不確定性（信心度低於某閾值）與缺乏進展（進度觸發），這兩種觸發條件會在論文的閉環實驗中進行比較。關鍵設計在於推理過程是異步進行的——當推理器在背景執行緒思考時，遊戲仍以先前命令繼續運行，因此一個耗時 12 秒的思考實際上佔據了 12 秒的遊戲時間。這種設計讓快速行動者保有即時反應能力，同時讓慢速推理器得以在必要時介入。

**Q5：本研究的關鍵創新點為何？**
A：本研究的關鍵創新在於三個層面：第一，它首次系統性地將「信心度閘控委託」（confidence-gated deferral）從回合制設定擴展到即時、連續運作的環境中，並證明了在閉環中事件閘控思考的可行性；第二，它揭示了準確率、校準度與敏感度（AUROC）是三種截然不同的屬性——即使兩個模型的準確率相近，它們的 AUROC 可能差異極大，這對選擇委託策略有直接影響；第三，它發現最敏感模型的信心度追蹤的是「它會失敗的情境類型」，而非「它會給出的具體錯誤答案」，這是一個對選擇性預測文獻有重要意義的觀察。這些發現挑戰了將信心度簡化為「答案正確性指標」的常見假設。

**Q6：在設計閘門時有哪些重要的設計選擇？**
A：閘門設計涉及多項關鍵選擇：第一，觸發條件的選擇——論文中比較了「不確定性觸發」（信心度低於閾值）與「進展觸發」（偵測到卡住或失敗），並發現進展觸發在閉環中能讓代理更積極地開門，但也導致更高的死亡率；第二，委託率的選擇——在離線實驗中，將最少 30% 的信心度決策委託給推理器能獲得最大增益，這個最佳比率與行動者的 AUROC 高度相關（秩相關 0.87）；第三，選項順序的影響——doomLaya 的固定選項順序（敵人、物品、門、出口、撤退、探索、等待）會影響某些模型的準確率，隨機打亂順序後增益從 +0.13 降至 +0.08；第四，背景執行緒的設計讓推理時間與遊戲時間解耦，避免了同步等待造成的卡頓。

**Q7：論文中使用了哪些基準測試與環境？**
A：論文使用了兩個層次的評估：在離線評估中，使用 900 個留出問題（held-out questions）測試 0.15B 到 9B 參數的零樣本決策模型；在閉環評估中，使用 Freedoom 2 搭配 ViZDoom 1.3.1 透過 doomLaya（commit b25edd3）將 Doom 暴露為類型化問題。環境以真實時間運行（每秒 35 個 tic），每 0.5 秒遊戲時間請求一次決策，包含兩個選擇題：命令（攻擊、收集、開門、前往出口、撤退、探索、等待）與武器。doomLaya 的神諭（oracle）是一個基於規則的專家，用於標記遊戲狀態。閉環實驗跑了 33 個遊戲、三個隨機種子，並與固定探索規則（fixed explore rule）進行對照實驗。

**Q8：論文最重要的實驗結果為何？**
A：最重要的結果可歸納為四點：第一，零樣本決策模型在錯誤中選擇「收集物品」的頻率是隨機機率的 1.6 到 1.8 倍，無論選項順序如何，這顯示出系統性的行為偏差；第二，準確率、校準度與敏感度是三種獨立屬性，相似準確率的模型在 AUROC 上差異極大，且最敏感模型的信心度追蹤的是失敗情境類型而非具體錯誤答案；第三，離線委託實驗中，將最少 30% 的決策委託給推理模型所獲得的增益與行動者 AUROC 高度相關（秩相關 0.87），在留出遊戲上選擇行動者與委託率後，增益為 +0.13 [0.08, 0.18]（doomLaya 選項順序）或 +0.08 [0.02, 0.14]（隨機順序），其中推理貢獻了大約一半的增益；第四，在閉環中（33 個遊戲、三個種子），沒有任何變體能到達出口，但承諾執行計畫（推理器的或固定探索規則的）能開啟更多門，並讓原本靜止不動的行動者開始行動。

**Q9：論文中進行了哪些消融實驗？**
A：論文進行了多項消融實驗來釐清各元件的貢獻：第一，比較了「閘門開啟時呼叫推理器」與「閘門開啟時執行固定命令」（如固定探索規則），結果顯示推理器版本能開啟更多門，但固定探索規則版本死亡率更高；第二，進行了圖像消融（ablation of the image），測試移除視覺輸入對推理器決策的影響；第三，進行了遊戲知識消融（ablation of game knowledge），特別是測試告訴推理器「有些門需要鑰匙」這項知識的效果——結果發現被告知後推理器會把普通門當成上鎖的門處理（因為狀態無法區分），而未被告知時則會回到收集物品的行為；第四，比較了不同選項順序（doomLaya 預設順序 vs. 隨機打亂）對模型準確率與委託增益的影響，揭示了評估協議對結果的敏感性。

**Q10：這項研究的實際應用場景有哪些？**
A：這項研究的應用場景相當廣泛：第一，即時遊戲 AI 代理，特別是第一人稱射擊、即時策略與動作遊戲，其中代理需要在毫秒級做出反應但又需要在關鍵時刻進行長程規劃；第二，機器人控制，特別是需要在動態環境中持續運作的服務機器人與自主移動機器人，例如家庭助理機器人在遇到重複失敗時需要停下來重新規劃路徑；第三，自動駕駛系統，其中快速反應層負責即時避障，而慢速推理層在偵測到複雜場景（如施工區、異常交通）時介入規劃；第四，即時網頁代理與對話助手，在使用者操作過程中持續監控並在必要時進行深度推理。這些場景的共同特徵是「環境不會等待」，因此事件閘控思考比持續運行慢速組件更有效率。

**Q11：產品團隊在實作這類系統時應考慮哪些因素？**
A：產品團隊需要考量多項實務因素：第一，計算預算的分配——必須決定推理器的最大思考時間、背景執行緒的數量，以及在推理器超時時的降級策略（fallback policy）；第二，信心度閾值的調校——論文中 AUROC 與委託增益的高相關性（0.87）意味著選擇 AUROC 較高的行動者比單純追求高準確率更重要；第三，狀態可觀察性的限制——論文中發現推理器因為無法區分普通門與上鎖門而犯錯，這凸顯了「狀態資訊完整性」對推理品質的關鍵影響；第四，使用者體驗——在人類與 AI 協作場景中，需要設計視覺或聽覺提示來告知使用者「AI 正在思考」，避免使用者誤以為系統當機；第五，模型選擇的彈性——透過 llama.cpp 的通用介面，產品可以在不同硬體上無縫切換不同大小的模型，根據裝置能力動態調整。

**Q12：這項研究對學術與產業領域的影響為何？**
A：這項研究的影響可分為三個層面：在學術上，它將「選擇性預測」（selective prediction）與「學習委託」（learning to defer）的文獻從回合制擴展到即時環境，並提出了「信心度追蹤失敗情境而非錯誤答案」的新觀察，挑戰了現有理論；在方法論上，它建立了一個可重現的閉環評估協議（doomLaya + System One 模型 + 視覺推理器），讓未來研究能在統一基準上比較不同切換策略；在產業上，它提供了一個務實的設計藍圖——與其用大型推理模型取代所有決策，不如用小型快速模型處理日常決策，僅在必要時升級到推理模型，這能大幅降低部署成本與延遲。這種「分層智慧」的設計哲學也呼應了邊緣運算與裝置端 AI 的趨勢。

**Q13：論文承認哪些研究限制？**
A：論文坦承多項限制：第一，閉環實驗中沒有任何變體能到達出口，這意味著結果主要展示了「相對行為差異」而非「絕對任務完成度」，限制了對實用性的直接評估；第二，遊戲環境的單一性——所有實驗都在 Doom 上進行，雖然是經典的即時環境基準，但結果是否能泛化到其他即時環境（如自動駕駛模擬器、機器人模擬器）仍待驗證；第三，模型範圍的限制——雖然測試了 0.15B 到 9B 參數的模型，但這些都是「System One」類型化決策模型，未涵蓋其他類型的快速代理（如小型生成式語言模型）；第四，閘門設計的簡化——論文中只比較了不確定性與進展兩種觸發條件，未探索更複雜的組合觸發或學習式觸發策略；第五，評估的隨機性——33 個遊戲與三個種子雖然足以觀察趨勢，但對於細微差異的統計檢定力有限。

**Q14：論文中觀察到哪些失敗案例？**
A：論文中記錄了幾個值得注意的失敗案例：第一，推理器在「被告知有些門需要鑰匙」後，反而將普通門誤認為上鎖的門，這是因為狀態無法區分兩者，而推理器過度依賴了給定知識；第二，未被告知鑰匙知識時，推理器會回到「收集物品」的預設行為，顯示出缺乏主動探索的傾向；第三，固定探索規則版本雖然能開啟更多門，但死亡率更高，這凸顯了「無腦探索」的風險；第四，某些模型在選項順序改變後準確率顯著下降，顯示出對提示格式的脆弱性；第五，在閉環中，行動者經常「靜止不動」（stand still），這可能是因為信心度持續低於閾值導致過度委託，或因為缺乏進展觸發而陷入無動作迴圈。這些失敗案例都指向未來需要更細緻的閘門設計與狀態表示。

**Q15：未來研究方向有哪些？**
A：基於論文的發現與限制，未來研究可朝以下方向探索：第一，更智慧的閘門設計——結合不確定性、進展、預期改善等多重信號，甚至使用學習式閘門（如小型分類器）來決定何時呼叫推理器；第二，狀態表示的改進——解決「普通門 vs. 上鎖門」這類不可區分狀態的問題，可能需要整合視覺推理或記憶機制；第三，推理品質的提升——目前推理器貢獻了大約一半的委託增益，未來可探索如何讓推理器在即時環境中更有效率，例如使用更快的推理模型或蒸餾技術；第四，跨環境泛化——將此框架應用於自動駕駛、機器人操作、網頁代理等其他即時環境，驗證設計原則的普適性；第五，理論分析——深入研究「信心度追蹤失敗情境而非錯誤答案」這一現象的理論基礎，並探討其對選擇性預測理論的啟示；第六，人機協作——將此架構擴展到人類與 AI 共同決策的場景，研究如何讓人類介入與 AI 推理互補。

## 實務應用指南

### 適用場景

1. **即時遊戲 AI 代理**：在第一人稱射擊遊戲、MOBA 或即時戰略遊戲中部署雙層代理，快速決策模型負責常規操作（射擊、撿拾物品），當偵測到卡關（門打不開、反覆死亡）時才呼叫推理模型規劃下一步路徑。

2. **自動駕駛決策系統**：在自駕車控制迴圈中，快速策略模型以低延遲處理常規駕駛（車道維持、定速巡航），僅在偵測到不確定路況（施工、突發障礙物）或長時間無進展時，才將控制權交給視覺語言推理模型進行場景理解與路徑重規劃。

3. **工業機器手臂協作**：在工廠自動化場景中，快速模型持續執行重複性抓取與放置任務，當力回饋感測器顯示異常或視覺檢測發現工件錯位時，閘門開啟並呼叫推理模型分析失敗原因並重新規劃動作序列。

4. **客服對話系統中的升級路由**：在客服聊天機器人中，快速意圖分類模型處理常見問題，僅在置信度低於閾值或對話停滯（用戶反覆表達不滿）時，將對話升級給具備多步推理能力的大型語言模型接手。

5. **金融交易監控與人工介入**：在高頻交易監控系統中，快速異常偵測模型持續掃描訂單流，當偵測到低置信度訊號或市場長時間無預期變化時，閘門開啟並呼叫推理模型分析新聞事件並建議人工交易員介入。

### 實作前置條件

**資料需求**
- 領域專屬的「類型化決策」資料集：每筆樣本需包含結構化狀態描述（如健康值、庫存、可見物件清單）與多選項標籤（指令、武器等），類似 doomLaya 將環境轉為選擇題的形式。
- 留出測試集（held-out games/questions）以評估 AUROC 與校準度，避免在訓練環境中選擇閘門閾值。
- 失敗情境日誌：記錄代理在哪些「情境類型」（非具體答案）上犯錯，用以驗證置信度是否對應失敗模式。

**運算資源**
- 一張消費級 GPU（如 RTX 4090 等級）即可同時服務 0.15B–9B 參數的快速決策模型與視覺語言推理模型，透過 llama.cpp 的 `common/v1/systemone` 端點統一橋接。
- 推理模型需以背景執行緒異步呼叫，確保主迴圈不被阻塞；建議設定思考時間上限（例如 12 秒）以避免無限等待。
- 同步模式環境（如 ViZDoom synchronous mode）需以真實時間節奏（35 tics/秒）驅動，確保遊戲時間與牆鐘時間一致。

**技能前提**
- 具備強化學習或模仿學習基礎，能訓練或微調小型類型化決策模型。
- 熟悉 LLM 服務化部署（llama.cpp、vLLM 或類似框架）與異步 API 設計。
- 具備提示詞工程（prompt engineering）能力，能為推理模型設計包含遊戲知識、影像與當前狀態的輸入格式。
- 理解選擇性預測（selective prediction）與學習延遲（learning to defer）的概念，能正確解讀 AUROC 與校準度指標。

### 實作步驟建議

1. **將領域問題轉為類型化決策任務**：參考 doomLaya 的設計，將業務場景抽象為「狀態文字描述 + 多選項問題」。例如自駕車場景可設計為「前方狀態 + 動作選項（減速、變換車道、維持）」，每 0.5 秒輸出一個決策。

2. **部署快速決策行動者**：選用 System One 系列模型（Laya、Kev、Lev、Julia、Clef、OpenJev、Strands Decider、CLM）之一，透過 llama.cpp 的統一端點提供服務。零樣本評估其在留出測試集上的準確率、校準度與 AUROC，特別注意選項順序對準確率的影響。

3. **設計閘門觸發邏輯**：實作兩種觸發機制並比較：
   - **不確定性觸發**：當行動者置信度低於閾值時開啟閘門。
   - **進度觸發**：當代理長時間無進展（如未開啟新門、未撿拾新物品）時開啟閘門。
   建議同時實作兩種並做消融實驗。

4. **整合異步推理器**：將視覺語言推理模型部署為背景執行緒服務。當閘門開啟時，主迴圈繼續以先前指令執行遊戲，推理結果完成後再覆寫指令。設定最大思考時間以避免延遲失控。

5. **離線評估委託策略**：在留出測試集上模擬「將最低置信度 30% 的決策委託給推理模型」，計算相對於隨機委託的增益。驗證增益是否與行動者 AUROC 成正比（論文中秩相關達 0.87），以此選擇最佳行動者與委託率。

6. **閉環部署與規則對照**：在實際環境中部署完整代理，並加入「固定探索規則」作為對照組（取代推理模型，僅輸出固定指令）。記錄每個變體的開門數、死亡次數與是否到達終點。

7. **閱讀與審查推理過程**：記錄推理模型每次輸出的「想法」，人工審查其邏輯是否合理。特別注意論文中發現的失敗模式：推理器在不知道「某些門需要鑰匙」時，會把普通門當作上鎖的門處理——這類領域知識缺口需透過提示詞補強。

8. **持續監控與迭代**：上線後持續追蹤三項獨立指標（準確率、校準度、AUROC），因為它們是不同性質的屬性，模型可能在其中一項表現優異但其他項不佳。定期以新資料重新校準閘門閾值。

### 潛在風險與注意事項

1. **選項順序偏差（option order bias）**：論文中明確指出「選項順序會改變部分模型的準確率」，且同一模型在不同順序下的增益差異顯著（+0.13 vs +0.08）。**緩解措施**：在留出測試集上以多種順序評估，選擇對順序最不敏感的模型；或在推理模型提示詞中固定選項順序。

2. **置信度追蹤「情境類型」而非「答案正確性」**：論文的關鍵發現是，最敏感行動者的置信度對應的是「它會在哪些情境失敗」，而非「哪些答案會錯」。**緩解措施**：不要將置信度直接當作答案正確性的代理指標；應以 AUROC 評估置信度對正確/錯誤的分離能力，並分析失敗情境的共同特徵。

3. **推理模型產生幻覺路徑**：論文中推理器在缺乏「某些門需要鑰匙」知識時，會把普通門當作上鎖的門處理，導致無效動作。**緩解措施**：在提示詞中明確列出領域規則與限制；實作「執行回饋」機制，將「抵達/受阻/不可用」的狀態回傳給推理器以糾正後續計畫。

4. **固定探索規則導致死亡增加**：論文中以固定探索規則取代推理模型時，代理開門更多但死亡次數也增加。**緩解措施**：閘門觸發應同時考慮「進度」與「生存」訊號；當健康值過低時強制觸發撤退指令。

5. **閉環中無變體能到達終點**：論文的 33 場遊戲、三個種子中，沒有任何變體成功到達出口。**緩解措施**：不要將離線增益直接外推為閉環表現；上線前必須進行閉環測試，並設定合理的成功指標（如開門數、存活時間）而非僅看終點到達率。

6. **異步推理的時序錯位**：當推理耗時 12 秒時，遊戲已推進 24 個決策週期，推理結果可能基於過時狀態。**緩解措施**：為推理結果附加時間戳，若延遲超過閾值則捨棄；或在推理提示詞中包含「自上次決策以來發生的事件」摘要。

7. **AUROC 與準確率脫鉤**：論文中「相似準確率的模型 AUROC 差異極大」。**緩解措施**：選擇行動者時不能只看準確率，必須同時評估 AUROC，因為委託增益與 AUROC 的秩相關高達 0.87。

### 與其他技術的整合建議

1. **與選擇性預測（Selective Prediction）框架整合**：本研究的閘門機制本質上是選擇性預測的應用。可整合 `libselect` 或類似函式庫提供的風險-覆蓋率曲線（risk-coverage curve）工具，系統化選擇最佳委託率。

2. **與 LLM Cascade 系統整合**：可將本研究的雙層架構擴展為多層級聯，例如：0.15B 模型 → 1B 模型 → 9B 模型 → 視覺語言推理模型，每層有不同延遲與成本特性。llama.cpp 的統一端點使多模型部署成本降低。

3. **與元認知模組（如 SOFAI）整合**：論文的離線委託分析（§5.3）正是 SOFAI 的「選擇快速或慢速解題器」問題。可將 SOFAI 的成本-效益決策邏輯作為閘門的元層，動態決定是否開啟閘門。

4. **與機器人執行回饋系統整合**：參考 Inner Monologue 與 DoReMi 的設計，將本研究的「抵達/受阻/不可用」執行回饋擴展為更豐富的場景描述與成功偵測訊號，使推理器能更準確地判斷失敗原因。

5. **與現有 RL 政策整合**：論文中提到「1.3M 參數專用模型在即時控制上勝過通用 LLM」。可將本研究的快速決策行動者替換為領域專用的 RL 政策（如 GR00T N1），保留推理器作為高層規劃器，形成「RL 政策 + LLM 規劃器」的混合架構。

6. **與日誌與可觀測性系統整合**：論文中釋出了程式碼、提示詞、資料與日誌。建議整合 OpenTelemetry 或類似框架，記錄每次閘門開啟的原因、推理耗時、委託前後的決策變化，以便後續分析與除錯。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的「第一人稱觀察」段落，理解「事件閘控思考」的核心直覺——當動作有效時大腦會「關閉」，當射擊不再有用（門打不開）時才開始思考。接著閱讀第 3 節的「環境與問題」部分，了解如何將遊戲轉為類型化選擇題，這是理解整篇論文的基礎。最後跳讀第 5.4 節的閉環實驗結論，記住「離線增益不等於閉環表現」這個關鍵警示。

**給 AI 工程師**：重點閱讀第 5.1–5.3 節的離線實驗，特別是「準確率、校準度與敏感度是不同性質的屬性」這項發現——這直接影響你選擇行動者模型的標準。實作時務必實作 AUROC 評估，因為委託增益與 AUROC 的秩相關高達 0.87。第 5.4 節的閉環實作細節（特別是「固定探索規則」對照組的設計）是寶貴的工程參考。

**給研究者**：第 2 節的相關工作分類（快速/慢速代理、委託與級聯、System One 模型基準、Doom）提供了完整的文獻地圖。建議深入分析第 5.1 節中「置信度追蹤失敗情境類型而非答案正確性」的實驗設計，這是一個值得延伸的研究問題。此外，論文中「無變體到達終點」的負面結果同樣具有發表價值，應思考如何設計更結構化的閉環評估指標。

**給產品經理**：理解三個關鍵商業意涵：(1) 雙層架構的成本效益來自「只在必要時呼叫昂貴模型」，離線分析顯示委託 30% 決策即可獲得顯著增益；(2) 選項順序會影響模型表現，這對 UI 設計（如按鈕排列、推薦順序）有直接影響；(3) 閉環實驗中「沒有任何變體到達終點」提醒我們：單一指標（如離線準確率）的提升不等於使用者體驗提升，上線前必須進行端到端測試。建議將論文的程式碼與日誌納入技術盡調流程。
