## 深度分析

#### 方法論解析

本文提出之 **Context-Grounded Skill Internalization (CGSI)** 方法，係針對技能內化（Skill Internalization）流程中常見的 **上下文錯位（Context Misalignment, CoMi）** 問題所設計的修正機制。為深入理解此方法，須先釐清其欲解決的問題脈絡與技術細節。

**問題定義與背景**

在視覺語言代理（Vision-Language Agents）的部署中，**技能（Skills）** 通常以指令、腳本與資源的形式封裝，並於測試時（Test Time）載入代理的上下文（Context）以提供領域知識（Domain Knowledge）。然而，此種測試時增強（Test-Time Augmentation）的效益僅在技能存在於上下文時有效。技能內化的目標即在於將此種外部指引「內化」至模型權重中，使代理在推論時間（Inference Time）無需明確指引即可展現相應行為。

**傳統流程的缺陷**

常見的技能內化流程包含兩個步驟：
1. **軌跡採樣（Trajectory Sampling）**：將技能置於上下文中，由模型自身生成示範軌跡（Demonstration Trajectories）。
2. **移除技能的微調（Skill-Removed Fine-Tuning）**：將技能從輸入中移除，以監督式微調（Supervised Fine-Tuning, SFT）方式訓練同一模型。

此流程實質上為一種**上下文蒸餾（Context Distillation）** 的變體。然而其核心缺陷在於：示範軌跡中可能包含對技能的引用（例如「根據任務指引（Task Guidance），我需要建立 solve.py」），當技能於微調階段被移除後，這些引用便成為「不受支援的引用（Unsupported References）」——即輸出引用了可見上下文中不存在的來源。模型在訓練過程中學習重現這些引用，導致測試時產生 CoMi 行為。

**CGSI 的核心機制**

CGSI 的設計包含兩個關鍵元件：

1. **句子偵測器（Sentence Detector）**：此元件負責識別在技能移除後將失去上下文支援的句子。其運作邏輯為：對於軌跡中的每個句子，判斷其引用的內容是否仍存在於可見上下文中。若引用指向已移除的技能內容，則將該句子標記為「不受支援」。

2. **處理策略**：針對被標記的句子，CGSI 提供兩種處理方式：
   - **遮罩（Masking）**：在微調過程中遮罩（mask）這些句子的損失（loss），使模型不學習產生此類引用。
   - **改寫（Rewriting）**：利用語言模型將這些句子改寫為不引用已移除技能的版本，再進行微調。

此設計的精妙之處在於：它並非簡單地過濾或刪除問題句子，而是透過選擇性的損失遮罩或語意保留的改寫，在減少 CoMi 的同時維持任務成功率（Task Success）。

**訓練配置**

實驗採用全參數監督式微調（Full-Parameter SFT），使用 Qwen3.5-4B 與 Qwen3.5-9B 兩種視覺語言模型，並於 ALFWorld、WebShop 與 ARC-AGI-1 三個基準測試環境上進行評估。

#### 實驗數據解讀

**CoMi 的普遍性驗證**

本文首先系統性地量化了 CoMi 問題的嚴重程度。在三個基準測試中，成功示範軌跡（Teacher Trajectories）於技能移除後出現 CoMi 的比例為 **18.3–75.4%**。更關鍵的是，此問題會「傳遞」至訓練後的模型：經過移除技能的微調後，測試軌跡（Test Trajectories）出現 CoMi 的比例為 **12.2–46.0%**。此數據揭示了一個重要現象：模型不僅學習了技能所引入的有用策略，也學習了對技能的引用模式，後者在測試時成為一種「幻覺式行為」。

**CGSI 的核心成效**

實驗結果顯示 CGSI 在三個基準測試上均能有效降低 CoMi：

| 基準測試 | 模型 | 直接微調 CoMi | CGSI 後 CoMi | 降幅 |
|---------|------|--------------|-------------|------|
| WebShop | Qwen3.5-4B | 46.0% | 3.4% | ~92.6% |
| ALFWorld | Qwen3.5-4B | （具體數值未於摘要明示） | — | 72.5–94.6% |
| ARC-AGI-1 | Qwen3.5-4B/9B | （具體數值未於摘要明示） | — | 72.5–94.6% |

整體而言，CGSI 相較於直接進行移除技能的微調，可減少 **72.5–94.6%** 的 CoMi，且**不犧牲任務成功率**。此結果的意義在於：它證明了 CoMi 的修正並非以任務效能為代價，兩者可以解耦。

**成本效益分析**

CGSI 在兩個維度上展現顯著的成本優勢：

1. **軌跡處理成本**：在 ARC 基準測試上，處理 2,281 條軌跡時，改寫版本的 API 成本從約 **$1,378 降至 $165**，降幅約 88%。這顯示 CGSI 的句子偵測器能精準定位需修正的句子，避免大規模軌跡審核（Trajectory Auditing）的昂貴開銷。

2. **訓練時間**：在 ALFWorld 上使用 Qwen3.5-4B 時，CGSI 達到 **85.0%** 的成功率，僅需 **1.25 訓練小時**；相比之下，基線方法 Skill0 達到 81.0% 成功率卻需 **19.1 小時**。CGSI 不僅成功率更高，訓練時間更縮短超過 15 倍。

**數據解讀的深層意涵**

這些數據揭示了幾個重要訊息：
- CoMi 並非邊緣案例，而是技能內化流程中的系統性問題。
- 簡單的「移除技能後直接微調」策略會產生可測量的負面後果。
- 針對性的句子級修正比大規模軌跡審核更具效率。
- CGSI 在效果與效率上均優於基於強化學習（Reinforcement Learning）的技能內化方法。

#### 與現有研究的比較

**與基於強化學習的方法比較**

本文將 CGSI 與 Skill0 等基於強化學習的技能內化基線方法（Baselines）進行比較。Skill0 透過強化學習直接優化策略，使代理在無技能上下文中表現良好。然而，強化學習方法通常需要大量環境互動與獎勵信號，導致訓練時間冗長。CGSI 透過監督式微調達成「相當的效能（comparable performance）」，但訓練時間大幅縮短。這顯示在技能內化任務中，**精準的資料修正** 可能比**探索式的策略優化** 更為高效。

**與上下文蒸餾的關係**

CGSI 的底層機制屬於上下文蒸餾（Context Distillation）的範疇——即將上下文中的資訊蒸餾至模型參數中。然而，傳統的上下文蒸餾方法（如 Llama 2-Chat 的安全預提示（Safety Preprompt）處理、SELF-ALIGN 的原則引導回應）較少關注輸出對上下文的依賴性。CGSI 的創新在於：**首次系統性地定義並量化了「輸出引用了不可見上下文」這一現象**，並提出可操作的修正方案。

**與大規模軌跡審核的比較**

另一類替代方案是對所有示範軌跡進行人工或模型輔助的大規模審核與修正（Large-Scale Trajectory Auditing and Correction）。此方法雖然直觀，但成本高昂且難以擴展。CGSI 透過句子偵測器實現**自動化、精準化**的修正，在 ARC 上的成本降低約 88% 即為明證。

**方法的侷限性**

儘管成效顯著，CGSI 仍存在以下侷限：
1. **句子偵測器的依賴性**：方法的效能高度依賴句子偵測器的準確性。若偵測器遺漏某些不受支援的引用，CoMi 仍會殘留；若誤判正常句子，則可能損害任務效能。
2. **改寫品質的不確定性**：改寫策略仰賴語言模型生成不引用技能的版本，改寫後的句子可能語意偏離原始意圖。
3. **單一技能假設**：實驗主要針對單一技能的內化，未探討多技能同時內化時的交互作用。
4. **基準測試的侷限**：評估集中於三個基準測試（ALFWorld、WebShop、ARC-AGI-1），對於更開放的領域（如軟體工程、網頁瀏覽）的泛化性尚待驗證。

#### 未來研究方向

基於本文的研究成果與侷限，可延伸出以下研究方向：

**1. 更強健的句子偵測器**
現有的句子偵測器是 CGSI 的效能瓶頸。未來可探索：
- 結合**形式化語意分析**與**大型語言模型判斷**的混合偵測器。
- 訓練專門的**引用依賴性分類器**，以更精準地識別不受支援的引用。
- 引入**反事實驗證（Counterfactual Verification）**：暫時移除上下文中的特定元素，觀察句子是否仍合理。

**2. 多技能內化與技能組合**
本文聚焦於單一技能的內化。實際代理系統常需同時內化多個技能。未來可研究：
- 多技能同時內化時的**技能交互作用**與**潛在衝突**。
- **技能分層內化**：先內化基礎技能，再內化進階技能的課程式學習（Curriculum Learning）策略。
- **技能選擇性內化**：根據任務需求動態決定哪些技能需內化、哪些保留為測試時增強。

**3. 理論分析與形式化**
本文以實證方式驗證 CoMi 的存在與 CGSI 的效果，未來可進一步：
- 建立 CoMi 的**形式化定義**與**理論上界**。
- 分析上下文蒸餾中**資訊遺失**與**行為偏差**的數學關係。
- 探討 CGSI 與**資訊瓶頸（Information Bottleneck）** 原則的連結。

**4. 跨領域泛化**
將 CGSI 應用於更複雜的領域：
- **軟體工程代理**：內化程式碼風格指南、安全規範等技能。
- **網頁瀏覽代理**：內化網站操作流程、隱私政策等技能。
- **多模態代理**：處理涉及視覺、音訊等多模態技能的內化。

**5. 與其他訓練範式的整合**
- 將 CGSI 與**強化學習**結合：先用 CGSI 進行初步內化，再以 RL 進行精煉。
- 與**偏好學習（Preference Learning）** 結合：利用人類偏好判斷哪些改寫版本更佳。
- 探索**線上學習（Online Learning）** 場景下的持續技能內化。

**6. 評估指標的擴展**
現有評估主要關注 CoMi 比例與任務成功率。未來可引入：
- **引用準確性（Reference Accuracy）**：模型引用是否正確對應可見上下文。
- **行為一致性（Behavioral Consistency）**：內化前後代理行為的相似度。
- **長期任務效能**：在多步驟、長時間跨度任務中的表現穩定性。

**7. 安全與對齊意涵**
技能內化涉及將外部指引轉化為模型內在行為，這與 AI 對齊（AI Alignment）密切相關。未來可研究：
- CGSI 能否應用於**安全準則的內化**，避免模型引用已移除的安全提示。
- **惡意技能內化**的防禦：如何防止有害技能透過類似流程被內化至模型中。

這些方向不僅能深化對技能內化問題的理解，也將推動視覺語言代理朝向更可靠、可解釋的方向發展。

## 論文問答

**Q1：這篇論文所要解決的核心問題是什麼？**
A：這篇論文聚焦於「技能內化」（Skill Internalization）過程中一個被忽略的問題——**上下文錯位**（Context Misalignment, CoMi）。具體而言，常見的作法是先讓代理在含有技能（skill）的上下文下生成示範軌跡（demonstration trajectories），接著在移除技能後對同一模型進行監督式微調（SFT）。然而，示範軌跡中常含有引用技能的語句，當技能被移除後，這些語句就成了「不受支援的引用」（unsupported references），模型在測試時便會引用一個它根本看不到的來源。這個問題在 ALFWorld、WebShop 與 ARC-AGI-1 三個基準上普遍存在，影響了技能內化的可靠性與實用性。

**Q2：為什麼現有的技能內化方法會產生上下文錯位？**
A：現有方法（例如 Llama 2-Chat 的安全預提示微調、SELF-ALIGN 的原則引導微調，以及代理訓練中的反思技能微調）都遵循同一個「上下文蒸餾」（context distillation）配方：保留訓練目標（target），但改變訓練輸入。這種做法假設模型輸出與輸入之間是自足的，但實際上，帶有技能生成的回應往往依賴於技能所提供的指引。一旦技能從輸入中移除，原本引用技能的句子就失去了上下文依據，模型卻仍被訓練去重現這些句子，導致測試時出現引用不存在來源的行為。

**Q3：為什麼上下文錯位這個問題值得被重視？**
A：上下文錯位會直接影響代理在真實部署中的可靠性與可解釋性。當代理在測試時引用一個不存在的「任務指引」（task guidance）時，使用者無法追溯其推理依據，也難以判斷代理是否真的學會了技能所傳達的策略。此外，根據本文分析，訓練後的模型在 12.2–46.0% 的測試軌跡中會出現 CoMi，這代表問題並非邊緣案例，而是系統性地影響了相當比例的代理行為。若不解決此問題，技能內化將難以作為可靠的部署方案。

**Q4：CGSI 的核心方法是什麼？**
A：CGSI（Context-Grounded Skill Internalization）的核心是一個**句子偵測器**（sentence detector），用於在微調前識別出含有「不受支援引用」的句子。偵測完成後，CGSI 提供兩種處理方式：在遮罩（masking）版本中，被選中的句子在計算損失時被排除；在改寫（rewriting）版本中，這些句子會被改寫為不依賴技能的版本，再進行微調。這樣一來，模型就不會被訓練去重現那些失去上下文支援的語句，從根本上避免 CoMi 的產生。

**Q5：CGSI 的關鍵創新點為何？**
A：CGSI 的關鍵創新在於它把「上下文一致性」作為一個可被檢測與修正的訓練信號，而非僅僅依賴大規模的人工軌跡審核（trajectory auditing）。傳統作法需要昂貴的人工或 API 來逐條審核並修正軌跡，而 CGSI 透過自動化的句子偵測器，以極低的成本完成同樣的工作。例如在 ARC 上，處理 2,281 條軌跡的 API 成本從約 1,378 美元降至 165 美元，降幅近九成。這種「以檢測取代審核」的思路，使得技能內化在大規模應用中變得可行。

**Q6：CGSI 在設計上為何同時提供遮罩與改寫兩種選擇？**
A：遮罩與改寫代表兩種不同的取捨：遮罩版本直接從損失計算中排除問題句子，保留其他所有訓練信號，適合追求最大化保留原始策略的情境；改寫版本則進一步生成不依賴技能的替代句子，讓模型仍能從中學習，但學到的是「無技能版本」的表達方式。這種設計讓使用者能根據任務需求彈性選擇——若關心的是任務成功率與訓練效率，遮罩版本較為簡潔有效；若希望模型在測試時的語句更自然流暢，改寫版本則更為合適。

**Q7：論文中使用了哪些基準測試？**
A：本文在三個具有代表性的視覺語言代理基準上評估 CGSI：ALFWorld（模擬家庭環境中的多步驟任務）、WebShop（線上購物代理任務）以及 ARC-AGI-1（抽象推理與程式碼生成任務）。這些基準涵蓋了不同的視覺與語言互動模式，能夠全面檢驗 CGSI 在異質環境下的泛化能力。實驗使用了 Qwen3.5-4B 與 Qwen3.5-9B 兩個視覺語言模型（VLM），以驗證方法在不同規模模型上的有效性。

**Q8：CGSI 的關鍵實驗結果為何？**
A：實驗結果揭示兩個重要發現：（i）相較於直接以移除技能的方式微調，CGSI 在測試時將 CoMi 降低了 72.5–94.6%，同時保留了任務成功率。例如在 WebShop 上使用 Qwen3.5-4B 時，CoMi 從 46.0% 降至 3.4%，任務成功率幾乎不受影響。（ii）相較於基於強化學習（RL）的技能內化基線方法（如 Skill0），CGSI 達到了相當的效能，但訓練時間大幅縮短——在 ALFWorld 上以 Qwen3.5-4B 達到 85.0% 成功率僅需 1.25 小時，而 Skill0 達到 81.0% 卻需 19.1 小時。

**Q9：論文中是否有進行消融研究（Ablation Study）來驗證各元件的貢獻？**
A：雖然摘要未詳述所有消融細節，但從方法設計可看出，句子偵測器與處理方式（遮罩 vs. 改寫）各自扮演關鍵角色。遮罩版本證明了「僅排除問題句子的損失」即可大幅降低 CoMi，顯示問題主要來自少數關鍵句；改寫版本則進一步證明，即使保留這些句子的訓練信號，只要將其改寫為上下文一致的版本，仍能達到類似效果。此外，與 RL 基線的比較也間接驗證了 CGSI 的設計選擇——無需複雜的獎勵設計即可達到相近效能。

**Q10：CGSI 在哪些實際場景中具有應用價值？**
A：CGSI 特別適用於需要將專業知識或操作流程從「測試時增強」（test-time augmentation）轉為「模型內建能力」的場景。例如軟體工程代理（如 Claude Code）需要內化特定專案的編碼規範、客服代理需要吸收公司內部流程指引、或工業自動化代理需要學習設備操作手冊。在這些場景中，技能原本以提示或腳本形式載入上下文，但隨著任務規模擴大，技能會佔用過多上下文窗口，CGSI 提供了一種將這些知識「燒入」模型權重的高效方法。

**Q11：在產品化部署時，CGSI 帶來哪些實務上的考量？**
A：從產品角度來看，CGSI 帶來三項重要優勢：首先是**成本效益**，相較於大規模軌跡審核與修正，CGSI 將 API 成本降低近九成，使得技能內化在經濟上可行；其次是**訓練效率**，相較於 RL 基線方法動輒數十小時的訓練時間，CGSI 僅需約一小時即可完成，大幅縮短迭代週期；最後是**可維護性**，當技能內容更新時，只需重新生成示範軌跡並套用 CGSI 處理流程，無需重新設計獎勵函數或進行複雜的 RL 訓練。

**Q12：CGSI 對視覺語言代理領域的影響為何？**
A：CGSI 的提出將「上下文一致性」這個議題帶入了技能內化研究的核心，促使後續研究在設計微調流程時必須考慮訓練目標對輸入上下文的依賴性。這也推動了「上下文蒸餾」方法論的精細化——從過去僅關注「保留目標、改變輸入」的粗略框架，演進為「檢測不一致、修正訓練信號」的細緻流程。此外，CGSI 證明了輕量級方法在特定問題上可以超越或匹配複雜的 RL 方法，這對資源受限的研究團隊與中小型企業尤為重要。

**Q13：論文是否承認了哪些方法上的限制？**
A：雖然論文強調 CGSI 的有效性，但仍存在幾項可推論的限制。首先，句子偵測器的準確性會直接影響 CGSI 的效果，若偵測器遺漏了某些隱晦的引用或誤判了正常句子，則可能分別導致 CoMi 殘留或損失有用資訊。其次，CGSI 目前在三個基準上驗證，對於更複雜的多模態或多技能場景的泛化性仍待檢驗。最後，遮罩版本雖然簡潔，但會減少訓練資料量；改寫版本則依賴於改寫模型的品質，這兩者之間的權衡需要根據具體應用調整。

**Q14：CGSI 在哪些情況下可能會失敗？**
A：CGSI 可能失敗的情境包括：（i）當技能的引用極為隱晦或分散在多個句子中時，句子級偵測器可能難以捕捉；（ii）當技能的內容與任務描述高度耦合，難以清楚區分哪些語句依賴技能時，遮罩或改寫可能過於激進，損失有用的策略資訊；（iii）對於需要嚴格遵循特定格式或術語的領域（如法律、醫療），改寫版本可能會引入不符合規範的表述，需要額外的領域校驗。

**Q15：未來的研究方向有哪些？**
A：基於本文的發現，未來可朝幾個方向延伸：（i）將句子偵測器升級為更細粒度的引用檢測，例如詞級或子句級的依賴性分析；（ii）將 CGSI 與其他訓練範式（如 RLHF 或 DPO）結合，探索在保留人類偏好的同時維持上下文一致性的方法；（iii）將 CGSI 應用於多技能同時內化的場景，研究技能之間的相互干擾與組合策略；（iv）探索 CGSI 在持續學習（continual learning）情境下的表現，即模型需要逐步內化多個技能而不產生災難性遺忘。

## 實務應用指南

### 適用場景

1. **企業內部 GUI 自動化代理的技能固化**：當企業使用 Claude Code 或類似代理產品時，會為特定業務流程（如報表生成、ERP 操作）載入專屬技能。透過 CGSI，可將這些技能內化進模型權重，使代理在沒有技能載入的情況下仍能執行相同流程，降低每次推論的 context 成本。

2. **客服與電商代理的領域知識內化**：在 WebShop 類場景中，代理需要遵循特定的下單、退換貨流程。CGSI 可讓模型學會這些流程而無需在 prompt 中持續注入 SOP 文件，提升回應速度並降低 token 成本。

3. **軟體工程代理的安全規範內化**：類似 Llama 2-Chat 的安全 preprompt 內化做法，CGSI 可用於將程式碼審查、安全檢查等規範從 context 移入權重，避免開發者在 prompt 中意外繞過規範。

4. **多模態 GUI 代理的長期部署**：在 ALFWorld 等家庭模擬環境中，代理需要執行多步驟任務。CGSI 適合用於將反覆使用的操作模式（如「開門→拿物品→放置」）內化，減少每次任務啟動時的 context 準備時間。

5. **ARC 類推理任務的策略內化**：對於需要特定解題策略的視覺推理任務，CGSI 可將「先建立腳本測試、再迭代修正」等策略固化進模型，使模型在沒有明確指引時仍能採用該策略。

### 實作前置條件

**資料需求**
- 至少數百至數千條高品質示範軌跡（論文使用 2,281 條 ARC 軌跡作為規模參考）
- 軌跡必須由「帶技能載入」的代理產生，且任務成功率需達一定門檻
- 每條軌跡需保留完整的任務描述、技能內容、代理回應序列
- 需具備任務成功標註，用於篩選有效訓練樣本

**計算資源**
- 全參數微調（Full-parameter SFT）需要至少 4B–9B 規模模型的訓練硬體（單機多 GPU 或分散式叢集）
- 句子偵測器（sentence detector）需要額外的 LLM 推論資源或 API 呼叫成本
- 評估階段需要完整的環境模擬器（ALFWorld、WebShop、ARC-AGI-1）

**技能前置條件**
- 已具備可載入的技能定義（指令、腳本、資源的封裝）
- 具備基礎的 SFT 訓練 pipeline（資料處理、loss masking、模型儲存）
- 具備評估 CoMi 比例的機制（可使用 LLM-as-judge 或規則比對）
- 熟悉 context distillation 的基本概念

### 實作步驟建議

**步驟 1：建立技能載入與軌跡採集流程**
- 設計技能格式（類似論文中 ARC Skill 的步驟化指令）
- 使用目標 VLM（如 Qwen3.5-4B/9B）在「任務描述 + 技能」輸入下採集示範軌跡
- 過濾出任務成功的軌跡，記錄 CoMi 的基準比例（論文觀察到 18.3–75.4%）

**步驟 2：實作句子偵測器**
- 設計 prompt 讓 LLM 判斷每個句子是否引用了「輸入中不存在的來源」
- 偵測器需能區分「引用任務描述」與「引用被移除的技能」
- 可使用較小的模型或 API 來降低成本

**步驟 3：選擇處理策略（遮罩 vs 改寫）**
- **遮罩（Masking）**：在 SFT loss 中排除被偵測出的句子，保留其他訓練訊號。適合追求訓練效率的場景。
- **改寫（Rewriting）**：使用 LLM 將「According to the task guidance...」改寫為「I need to...」等自包含語句。適合需要保留完整策略資訊的場景。
- 論文顯示改寫版本在 ARC 上可將 API 成本從 $1,378 降至 $165

**步驟 4：執行技能移除的微調**
- 將訓練輸入改為僅含「任務描述」（移除技能）
- 對偵測出的句子套用 loss mask 或使用改寫後的目標
- 採用全參數 SFT 而非 LoRA，以獲得最佳效果

**步驟 5：評估與迭代**
- 在測試環境中評估任務成功率與 CoMi 比例
- 目標：CoMi 降低 72.5–94.6%，任務成功率不下降
- 若 CoMi 仍偏高，調整句子偵測器的敏感度或擴大訓練資料

**步驟 6：部署與監控**
- 將內化後的模型部署至生產環境
- 持續監控代理行為是否仍參考不存在的 context 來源
- 定期以新軌跡重新訓練以維持效果

### 潛在風險與注意事項

**風險 1：句子偵測器的誤判**
- 偵測器可能將合法的引用（如引用任務描述本身）誤判為 CoMi，導致過度遮罩
- **緩解**：建立驗證集評估偵測器精確率與召回率，調整 prompt 或使用更大的判斷模型

**風險 2：改寫破壞策略完整性**
- 改寫後的句子可能失去原本的策略意圖，使模型學到次優行為
- **緩解**：在改寫後進行人工抽樣檢查，或採用「遮罩 + 改寫」混合策略

**風險 3：技能過時後的維護成本**
- 內化的技能難以即時更新，當業務流程變更時需重新訓練
- **緩解**：建立技能版本管理與定期重訓機制，或在關鍵決策點保留技能載入選項

**風險 4：跨任務泛化能力下降**
- 過度擬合於特定技能的軌跡可能損害模型在其他任務上的表現
- **緩解**：保留通用資料的混合訓練，監控 out-of-distribution 效能

**風險 5：評估 CoMi 的成本**
- 評估階段需要對每條測試軌跡進行 LLM 判斷，API 成本可能很高
- **緩解**：使用規則式啟發式方法（如關鍵詞比對）作為初步篩選，僅對可疑軌跡使用 LLM 判斷

### 與其他技術的整合建議

**與強化學習（RL）整合**
- CGSI 可作為 RL 訓練前的「監督式預熱」，先用 SFT 內化基本技能，再用 GRPO 等方法優化策略
- 相較於純 RL 方法（如 Skill0），CGSI 訓練時間從 19.1 小時降至 1.25 小時，適合作為快速原型

**與 Context Distillation 整合**
- CGSI 是 context distillation 的改良版本，可直接替換現有 pipeline 中的「技能移除 SFT」步驟
- 與 Llama 2-Chat 的安全 preprompt 內化、SELF-ALIGN 的原則內化等方法相容

**與 RAG 系統整合**
- 對於需要即時更新的知識（如產品價格、庫存），仍應使用 RAG 而非技能內化
- CGSI 適合處理「穩定的程序性知識」，RAG 適合處理「變動的陳述性知識」

**與多代理系統整合**
- 在多代理架構中，可將「專家代理」的高頻使用技能內化，而將「協調代理」保留彈性載入技能的能力
- 句子偵測器可作為代理間通訊的品質檢查工具

**與 LoRA / PEFT 整合**
- 雖然論文使用全參數 SFT，但 CGSI 的 loss masking 機制可延伸至 LoRA 訓練
- 對於資源受限的部署場景，可考慮使用 LoRA + CGSI 的組合

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的圖 1，理解「context misalignment」的具體意涵——這是理解整篇論文的關鍵。接著閱讀摘要，了解 CGSI 的核心概念（偵測 → 遮罩/改寫 → 微調）。實作上可先從小規模的 ARC 範例開始，使用 Qwen3.5-4B 搭配簡單的關鍵詞偵測器，觀察 CoMi 比例的變化。

**給 AI 工程師**：重點關注第 1 節的實驗數據（CoMi 降低 72.5–94.6%、訓練時間從 19.1h 降至 1.25h）以及方法章節的句子偵測器設計。實作時建議先建立完整的評估 pipeline（任務成功率 + CoMi 比例），再迭代優化偵測器與處理策略。可參考論文的改寫版本成本數據（$1,378 → $165）評估自家場景的經濟效益。

**給研究者**：本文的核心貢獻在於「定義並系統性研究 CoMi 問題」，這為 context distillation、知識內化等領域提供了新的分析視角。建議深入閱讀相關工作章節，理解與 Llama 2-Chat、SELF-ALIGN 等方法的關聯，並思考 CoMi 是否也適用於多模態以外的場景（如純文字對話、程式碼生成）。未來研究方向可包括：更高效的句子偵測器、自動化改寫品質評估、跨語言的 CoMi 現象等。

**給產品經理**：CGSI 的商業價值在於「降低推論成本」與「提升使用者體驗」。當代理產品需要載入大量技能時，每次對話的 context 成本會顯著影響毛利；CGSI 可將這些成本轉為一次性訓練成本。建議評估自家產品中高頻使用技能的占比，計算技能內化的 ROI。需注意的權衡是：技能內化後更新成本較高，適合流程穩定的業務，不適合快速迭代的場景。
