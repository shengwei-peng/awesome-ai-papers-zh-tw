## ⚡ TL;DR

針對非同步智能體強化學習的訓練不穩定與離策略問題，解決群組取樣不適配的挑戰。
提出單次推論軌跡非同步最佳化，以單軌跡取樣、嚴格雙邊詞元裁剪與改進的價值模型穩定訓練。

## 摘要翻譯

強化學習（Reinforcement Learning, RL）在大型語言模型（Large Language Models, LLMs）的後訓練（post-training）中日益重要。過往用於 LLMs 的 RL 流程大多為同步式（synchronous）且批次交錯（batch-interleaved），對於長期智能體任務而言效率不彰。近期，非同步強化學習（Asynchronous RL）藉由在推論軌跡（rollout）生成後即時更新模型，成為更具效率的替代方案。然而，現有的非同步 RL 系統往往強調吞吐量（throughput），卻使訓練穩定性（training stability）與任務有效性（task effectiveness）在很大程度上未受充分探討。例如，一項關鍵挑戰在於，廣泛使用的群組相對策略最佳化（Group Relative Policy Optimization, GRPO）框架中的群組取樣（group-wise sampling），並不易自然套用於非同步智能體訓練。本文提出單次推論軌跡非同步最佳化（Single-rollout Asynchronous Optimization, SAO），以解決非同步 RL 中的穩定性與離策略（off-policy）挑戰。為降低離策略效應（off-policy effects）並提升泛化能力（generalization），我們以單次推論軌跡取樣（single-rollout sampling）取代群組取樣，亦即每個提示（prompt）使用一條推論軌跡。我們進一步透過實用的價值模型訓練（value-model training）設計來改進此單次推論軌跡策略。為提升最佳化穩定性，我們引入了嚴格雙邊詞元級裁剪（strict double-side token-level clipping）策略。SAO 能夠穩定訓練一千個訓練步驟，並在智能體程式設計（agentic coding）與智能體推理（agentic reasoning）基準測試（如 SWE-Bench Verified、BeyondAIME 與 IMOAnswerBench）上持續優於 GRPO 及其變體。我們亦證明，單次推論軌跡 RL 在模擬線上學習（simulated online learning）設定中特別有效，此時模型必須適應持續變化且不斷演化的環境（changing evolving environments）。為此，SAO 已成功部署於訓練開放模型（open model）GLM-5.2（750B-A40B）的智能體強化學習（agentic RL）流程中。

### 核心貢獻（3～5點）
- 提出單次推論軌跡非同步最佳化（SAO），以單次推論軌跡取樣（single-rollout sampling）取代 GRPO 的群組取樣（group-wise sampling），降低離策略效應並提升泛化能力。
- 設計實用的價值模型訓練（value-model training）機制，強化單次推論軌跡策略的學習效果。
- 引入嚴格雙邊詞元級裁剪（strict double-side token-level clipping）策略，顯著提升非同步 RL 的最佳化穩定性。
- 在 SWE-Bench Verified、BeyondAIME、IMOAnswerBench 等智能體程式設計與推理基準上穩定訓練一千步，並持續優於 GRPO 及其變體。
- 驗證 SAO 在模擬線上學習（simulated online learning）與持續演化環境中的適應性，並已成功部署於開放模型 GLM-5.2（750B-A40B）的智能體 RL 訓練流程。

### 適合對象
從事大型語言模型後訓練、強化學習系統設計、智能體（agent）推理與程式設計任務的研究者與工程師，特別是關注非同步訓練穩定性、吞吐量與長期智能體任務效率最佳化的讀者。

## 深度分析

#### 方法論解析

SAO（Single-rollout Asynchronous Optimization，單次推論軌跡非同步最佳化）的核心目標，是在保留非同步強化學習（Asynchronous RL）高牆鐘效率（wall-clock efficiency）的前提下，同時解決**訓練穩定性（training stability）**與**離策略效應（off-policy effects）**兩大問題。其方法論可拆解為四個相互支撐的設計：

1. **直接雙邊詞元級重要性取樣（Direct Double-Sided Importance Sampling, DIS）**  
   在傳統的解耦式 PPO（Proximal Policy Optimization，近端策略最佳化）中，為了修正離策略偏差，通常需要同時維護當前策略（current policy）$\pi_\theta$、舊策略（old policy）$\pi_{\theta_{\text{old}}}$ 與推論軌跡策略（rollout policy）$\pi_{\text{rollout}}$。然而非同步場景下，一條軌跡（trajectory）在生成過程中可能已經歷多次模型更新，若要精確追蹤行為機率，就必須保存大量歷史檢查點（model checkpoints），實作上不可行。SAO 採取更激進但簡化的做法：直接使用**推論軌跡引擎（rollout engine）**當下輸出的對數機率（log-probabilities）作為行為代理（behavior proxy），並對當前策略 $\pi_\theta$ 進行詞元級（token-level）重要性取樣。為了抑制策略延遲（policy lag）造成的重要性比率劇烈波動，SAO 引入**嚴格雙邊詞元級裁剪（strict double-side token-level clipping）**，同時對比率上下界進行限制，並輔以遮罩（masking）處理無效詞元，從而降低極端離策略樣本對梯度更新的衝擊。

2. **單次推論軌跡取樣（single-rollout sampling）取代群組取樣（group-wise sampling）**  
   GRPO（Group Relative Policy Optimization，群組相對策略最佳化）為每個提示（prompt）取樣一組回應（response group），並以群組層級平均（group-level average）作為優勢估計（advantage estimation）的基準。這種設計在非同步環境中會產生**延遲驅動的離策略行為（latency-driven off-policy behavior）**：整個群組必須等待最慢的推論軌跡（straggler）完成後才能進入訓練，導致較早完成的樣本與當前策略之間的延遲加劇。SAO 改為每個提示只取樣**一條推論軌跡（single rollout）**，軌跡一旦完成即可立即投入訓練，無需等待群組同步。這不僅減少了策略延遲，也讓方法能自然適應**每提示單一軌跡回饋（single trajectory feedback per prompt）**的線上學習（online learning）與複雜智能體設定（complex agentic settings）。

3. **價值模型（value model）訓練的實用化設計**  
   單次推論軌跡取樣放棄了 GRPO 的群組相對基準，因此需要可靠的評論家模型（critic）來估計優勢。SAO 提出兩項實作細節：第一，**評論家模型（critic）的更新頻率（update frequency）高於行動者模型（actor）**，使價值函數能更快跟上非同步資料的分布變化；第二，在微調（fine-tuning）價值模型時**凍結注意力層（frozen attention）**，保留預訓練的語義抽取能力，同時只調整較上層的價值預測頭，以降低過擬合與訓練不穩定的風險。

4. **跳過觀察的詞元級 GAE 估計器（skip-observation token-level GAE estimator）**  
   智能體任務常涉及多回合軌跡（multi-turn agent trajectories），其中動作（action）與環境回饋（environment feedback）/觀察（observation）交錯出現。觀察詞元並非由模型生成，若將其納入廣義優勢估計（Generalized Advantage Estimation, GAE）的計算，會把環境雜訊誤傳為策略梯度訊號。SAO 的 GAE 只在**動作到動作邊界（action-to-action boundaries）**之間計算優勢，跳過觀察詞元，從而實現更乾淨的信用分配（credit assignment）。

綜合來看，SAO 並非單純將 PPO/GRPO 非同步化，而是針對非同步帶來的**多版本舊策略（multiple versions of old rollout model）**、**交錯的環境回饋（interleaved environment feedback）**與**可變軌跡長度（variable rollout lengths）**等特性，從取樣策略、重要性取樣裁剪、價值模型訓練到優勢估計進行全鏈路重新設計。

#### 實驗數據解讀

根據摘要與引言，SAO 的實驗覆蓋了**智能體程式設計（agentic coding）**與**智能體推理（agentic reasoning）**兩大類基準測試（benchmarks）：

- **SWE-Bench Verified**：評估模型能否自動解決真實 GitHub issue，是長期智能體任務（long-horizon agentic tasks）的代表。
- **AIME2025、BeyondAIME、HMMT、IMOAnswerBench**：數學競賽等級的推理任務，強調多步驟邏輯與測試時計算（test-time compute）。

作者宣稱 SAO 能夠穩定訓練約一千個步驟（around one thousand steps），並在這些基準上**持續優於 GRPO 及其變體（consistently outperform GRPO and its variants）**。從方法論角度解讀，這項結果的意義可分成三個層次：

1. **穩定性指標**：非同步 RL 過往研究多強調吞吐量（throughput），但常因策略延遲導致訓練發散。SAO 能穩定訓練到千步級別，說明 DIS 裁剪與單次推論軌跡取樣確實抑制了離策略效應，使策略更新不會因舊版推論模型（old rollout model）的累積偏差而崩潰。

2. **有效性指標**：在 SWE-Bench Verified 等需要長軌跡的任務上勝過 GRPO，意味著單次推論軌跡取樣並未因失去群組相對基準而損失最終效能；相反地，透過價值模型（value model）與更及時的策略更新，SAO 在長期智能體任務中達到更好的泛化能力（generalization）。

3. **線上適應性**：SAO 在**模擬線上學習設定（simulated online learning setting）**中表現突出，顯示單次推論軌跡取樣特別適合**持續演化環境（evolving environments）**。因為每個提示只需一條軌跡回饋即可更新，模型能更快適應環境分布的動態變化，而不受群組等待延遲拖累。

不過，由於提供的上下文未包含具體數值表格、學習曲線、標準差或運算資源配置，我們無法進一步量化「穩定」與「更好」的細節。例如：SAO 相較 GRPO 在 SWE-Bench Verified 上的絕對提升幅度、訓練收斂所需的牆鐘時間、以及在不同策略延遲程度下的穩健性，都需要完整論文才能評估。

#### 與現有研究的比較

| 研究方向 | 主要特徵 | 與 SAO 的關係 |
|---|---|---|
| **同步式批次交錯 RL（synchronous batch-interleaved RL）**<br>如 PPO、RLHF 管線 | 等待整批推論軌跡完成後才更新，容易因軌跡長度不均造成 GPU 叢集（GPU cluster）閒置 | SAO 改為非同步消費 rollout，提升牆鐘效率，並透過裁剪與價值模型維持穩定 |
| **GRPO / 群組相對策略最佳化** | 以群組取樣（group-wise sampling）的群組平均作為優勢基準，無需訓練 critic | SAO 以單次推論軌跡取樣取代群組取樣，避免延遲驅動的離策略行為，並引入價值模型訓練設計來補償基準估計 |
| **非同步 RL 系統研究**<br>如 Fu et al., 2025; Noukhovitch et al., 2024 | 聚焦吞吐量與效率最佳化（efficiency optimization），對訓練穩定性與任務有效性探討較少 | SAO 在效率之外，系統性地處理穩定性與有效性，並成功部署於大規模開放模型 GLM-5.2（750B-A40B） |
| **解耦式 PPO for LLM** | 維護多個舊策略檢查點以精確追蹤行為機率 | SAO 簡化為直接使用 rollout engine 的對數機率，並以嚴格詞元級裁剪處理剩餘離策略偏差，降低實作複雜度 |

**SAO 的主要改進**在於它是一種**演算法與系統共同設計（algorithm-system co-design）**：它不是單純把 GRPO 改成非同步版本，而是辨識出群組取樣與非同步管線的根本衝突，並用單次推論軌跡取樣加以解決；同時透過 DIS、價值模型凍結注意力層與 skip-observation GAE，補強單次取樣可能帶來的方差與信用分配問題。

**限制與待釐清之處**包括：

- **方差代價**：單次推論軌跡取樣放棄了 GRPO 的群組內對照基準，可能提高優勢估計的方差；雖然價值模型可部分補償，但在獎勵稀疏或雜訊大的環境中是否仍穩定，需要更多驗證。
- **記憶體與計算開銷**：相較 GRPO 不訓練 critic，SAO 需要維護價值模型，理論上會增加記憶體佔用與計算成本；論文雖提到凍結注意力層等最佳化，但未給出具體開銷數據。
- **適用範圍**：目前實驗集中在智能體程式設計與數學推理，對於一般對話對齊（alignment）、多模態智能體或具連續動作空間的任務，SAO 的設計是否同樣有效仍未知。
- **理論分析不足**：摘要與引言未提供收斂保證或離策略偏差上界，嚴格裁剪的閾值選擇也缺乏系統性指引。

#### 可重現性評估

從目前提供的上下文來看，SAO 的**可重現性（reproducibility）**存在以下幾個層次的問題：

1. **開源程式碼與訓練腳本**：文中並未明確提及是否釋出 SAO 的實作程式碼、分散式非同步訓練框架或超參數設定。非同步 RL 的實作細節（如 rollout engine 的更新頻率、緩衝區大小、actor/critic 的同步策略）對結果影響極大，若無開源程式碼，其他研究者難以完全復現。

2. **模型權重**：雖然論文提到 SAO 已部署於開放模型 GLM-5.2（750B-A40B），但「開放模型」是否代表已公開訓練後的權重、訓練中間檢查點或僅是推理權重，仍需進一步確認。若只有最終權重而無訓練過程資料，則難以驗證 SAO 對模型能力的貢獻。

3. **資料集與獎勵函數**：SWE-Bench Verified、AIME2025、BeyondAIME 等基準測試多為公開資料，但智能體 RL 的實際表現高度依賴獎勵設計（reward shaping）、提示模板（prompt template）與環境互動介面。這些細節若未公開，重現門檻會顯著提高。

4. **硬體與分散式設定**：非同步訓練的牆鐘效率與穩定性與 GPU 叢集規模、網路延遲、rollout worker 數量密切相關。論文若未詳細說明這些基礎設施參數，則其他團隊難以判斷結果是否可推廣到不同規模的叢集。

總結來說，SAO 的可重現性目前屬於**中等偏低**：基準資料與部分模型可能公開，但核心演算法的實作、超參數與分散式設定尚不明朗。若作者後續釋出訓練程式碼與詳細配置，將大幅提升社群驗證與跟進研究的可能性。

#### 未來研究方向

基於 SAO 的設計與現有侷限，以下幾個方向值得進一步探索：

1. **單次推論軌跡與群組基準的混合策略**  
   未來可研究如何在非同步管線中動態組成「無等待」的迷你群組，或利用重要性加權的群組基準，在保留單次推論軌跡低延遲優勢的同時，降低優勢估計方差。

2. **自適應裁剪與策略延遲感知學習**  
   SAO 的嚴格雙邊裁剪對訓練穩定性至關重要，但固定閾值可能限制學習速度。可發展根據當前策略延遲（policy lag）或重要性比率分布自動調整裁剪範圍的機制，並建立相應的收斂理論。

3. **更強大的非同步評論家模型架構**  
   針對長期智能體任務，可嘗試引入循環神經網路（RNN）、狀態空間模型（SSM）或基於記憶體的 critic，以更好地處理多回合軌跡中的長程依賴；同時探索 off-policy critic correction 技術，進一步降低價值估計偏差。

4. **線上與持續學習場景的系統化評估**  
   SAO 在模擬線上學習中展現潛力，未來可建立標準化的**持續演化環境（evolving environments）**基準，系統比較單次推論軌跡 RL、群組 RL 與傳統持續學習方法在分布漂移下的適應能力。

5. **與測試時計算（test-time compute）的協同**  
   將 SAO 與推理時搜尋、自我修正（self-correction）與多輪驗證機制結合，研究非同步 RL 是否能更有效率地學習「何時該增加測試時計算」的策略。

6. **開源非同步 RL 訓練框架與標準化協定**  
   為了提升可重現性，社群需要一個統一的開源框架，標準化 rollout engine、策略延遲度量、優勢估計與裁剪實作，讓不同演算法能在相同基礎設施下公平比較牆鐘效率與最終效能。

7. **擴展到多模態與真實世界智能體**  
   SAO 目前聚焦於程式碼與數學文字任務。將其應用於需要視覺觀察、工具呼叫或與真實環境互動的多模態智能體，將是驗證其通用性的重要下一步。

## 論文問答

**Q1：為什麼傳統同步式強化學習流程在長期智能體任務中效率低落？**

A：在傳統同步式流程中，策略會先產生一整批推論軌跡，等到整個批次收集完畢後才開始最佳化。然而，在智能體程式設計或推理等長期任務中，不同軌跡的長度差異極大，短軌跡很快完成，卻必須等待少數生成緩慢的長軌跡（即「落後樣本」）。這種等待會造成 GPU 叢集中大量運算資源閒置，顯著降低牆鐘效率與整體吞吐量。

**Q2：非同步強化學習雖然能提升效率，但帶來了哪些訓練穩定性與任務有效性的挑戰？**

A：非同步訓練允許 rollout 在完成後立即被用於更新，但同一條軌跡可能由多個不同版本的舊策略生成，導致嚴重的策略延遲與離策略效應。現有非同步系統大多聚焦於吞吐量最佳化，對訓練穩定性和最終任務表現探討不足。此外，廣泛使用的 GRPO 採用群組取樣，與非同步環境中常見的「每提示單一軌跡回饋」並不相容，進一步加劇了延遲驅動的離策略行為。

**Q3：為什麼 GRPO 的群組取樣不適合非同步智能體訓練？**

A：GRPO 需要針對同一提示取樣一組回應，並以群組層級平均來估計優勢，這意味著必須等待群組內所有 rollout 都生成完畢才能開始訓練。在非同步環境中，群組內的慢速樣本會讓其他已完成的樣本等待，形成額外的延遲與離策略偏差。更重要的是，許多線上或複雜智能體環境只對每個提示提供單一軌跡回饋，根本無法組成 GRPO 所需的群組。

**Q4：SAO 的核心設計是什麼？**

A：SAO 提出以「單次推論軌跡取樣」取代 GRPO 的群組取樣，也就是每個提示只使用一條 rollout 進行更新，讓軌跡完成後即可立刻進入訓練。為了讓這種設定在實務上可行，SAO 同時引入有效的價值模型訓練策略，例如更頻繁地更新 critic 以及在微調價值模型時凍結注意力層。此外，SAO 採用嚴格的雙邊詞元級裁剪策略，以抑制非同步訓練中因策略延遲所帶來的劇烈更新。

**Q5：SAO 如何處理非同步訓練中的策略延遲與離策略問題？**

A：SAO 提出直接雙邊詞元級重要性取樣（DIS），直接使用 rollout 引擎的對數機率作為行為代理，並以當前策略與 rollout 策略之間的機率比率進行重要性取樣。為了避免過度離策略的詞元對訓練造成破壞，SAO 對這個比率施加嚴格的雙邊詞元級裁剪與遮罩。這種設計不需要維護大量舊策略檢查點，卻能有效限制更新幅度，從而提升非同步訓練的穩定性。

**Q6：SAO 在價值模型與優勢估計上有哪些實務設計？**

A：SAO 讓 critic 的更新頻率高於 actor，使價值模型能更快跟上策略變化，減少價值估計的偏差。在微調價值模型時，SAO 凍結注意力層，以降低記憶體與計算開銷，同時保留足夠的價值估計能力。針對多回合智能體軌跡中交錯的環境回饋，SAO 提出跳過觀察的詞元級 GAE 估計器，只在動作到動作邊界之間計算優勢，避免將雜訊傳播到非模型生成的觀察詞元。

**Q7：SAO 在哪些基準測試上進行評估？**

A：論文在多個智能體程式設計與數學推理基準上評估 SAO，包括 SWE-Bench Verified、AIME2025、BeyondAIME、HMMT 與 IMOAnswerBench。這些基準涵蓋了程式碼修改、競賽級數學推理與長期問題求解等不同面向的任務。透過這些多樣化的測試，作者能夠驗證 SAO 在真實智能體場景中的泛化能力與有效性。

**Q8：相較於 GRPO 及其變體，SAO 的實驗結果呈現什麼趨勢？**

A：實驗結果顯示，SAO 能夠穩定訓練約一千個步驟，並在多個基準上持續優於改進版 GRPO 與其變體。這表示 SAO 不僅解決了非同步訓練的穩定性問題，也在任務有效性上取得了實質提升。整體而言，單次 rollout 的非同步設計在牆鐘效率與最終模型表現之間取得了更好的平衡。

**Q9：單次推論軌跡取樣在什麼設定下特別有效？**

A：單次推論軌跡取樣在模擬線上學習設定中特別有效，因為此類環境通常持續演化，且每個提示只提供單一軌跡回饋。SAO 能夠在 rollout 完成後立即更新模型，使策略快速適應動態變化的環境。這種隨到隨用的特性讓 SAO 在需要持續學習與線上適應的場景中展現出獨特優勢。

**Q10：SAO 在實務上如何被應用於 GLM-5.2 的訓練流程？**

A：SAO 已成功部署於開放 MoE 模型 GLM-5.2（750B-A40B）的智能體強化學習流程中，作為其後訓練階段的一部分。透過 SAO，GLM-5.2 能夠在非同步環境中穩定地進行大規模策略更新，提升模型在智能體任務上的表現。這項部署驗證了 SAO 不僅是理論方法，也具備在大型開放模型生產流程中實際運作的能力。

**Q11：從產品與系統角度，SAO 的非同步設計帶來哪些好處？**

A：SAO 的非同步設計能顯著減少 GPU 因等待落後 rollout 而造成的閒置時間，從而提升整體牆鐘效率與資源利用率。同時，SAO 的穩定性機制讓大規模模型能夠持續更新數千步而不發散，降低生產環境中的訓練風險與調參成本。對於需要長期軌跡的智能體應用而言，這意味著可以用更短的實際時間訓練出更可靠的模型。

**Q12：SAO 對大型語言模型後訓練領域可能產生什麼影響？**

A：SAO 顯示非同步強化學習不僅能加速訓練，也能透過單次 rollout 與嚴格裁剪達到比同步 GRPO 更好的任務表現。這可能改變過去以同步批次訓練為主的典範，推動更多長期智能體任務採用非同步訓練架構。隨著 LLM 後訓練越來越依賴強化學習，SAO 為兼顧效率與穩定性提供了一條可行的技術路徑。

**Q13：SAO 目前有哪些潛在限制？**

A：SAO 直接使用 rollout 引擎的對數機率作為行為代理，這是一種激進的簡化，可能無法完全捕捉多版本舊策略所形成的複雜離策略分佈。此外，價值模型在微調時凍結注意力層，雖然能降低開銷，但也可能限制其在某些高難度任務上的表達能力。這些設計在實務上有效，但在極端離策略或需要精細價值估計的情境中可能需要進一步調整。

**Q14：在哪些情況下 SAO 可能表現不佳或需要調整？**

A：若 rollout 引擎與訓練策略之間的策略延遲極大，單次 rollout 的重要性取樣比率可能會被過度裁剪，導致有效更新資訊不足。同樣地，若環境回饋高度稀疏且雜訊大，單次 rollout 的優勢估計可能變得不穩定，影響收斂。在這些情況下，可能需要調整裁剪範圍、critic 更新頻率，或引入額外的方差縮減技術。

**Q15：未來研究可以朝哪些方向延伸 SAO？**

A：未來可以探索更精確的多版本策略機率追蹤方法，在降低記憶體成本的同時減少離策略偏差。另一個方向是結合線上與離線資料進行混合訓練，以提升樣本效率與泛化能力。此外，將 SAO 擴展到多智能體協作、持續學習或更複雜的動態環境，也是值得進一步研究的重要課題。

## 實務應用指南

### 適用場景

1. **長期智能體程式設計後訓練**  
   適合需要讓大型語言模型在 SWE-Bench Verified 等程式設計基準上持續學習的場景。SAO 的單次推論軌跡取樣能處理長短不一的程式碼生成軌跡，避免群組取樣等待落後樣本造成的 GPU 空閒與延遲驅動的離策略行為。

2. **多回合數學推理與工具使用**  
   當模型需要與環境進行多輪互動（例如呼叫計算工具、搜尋、驗證）時，SAO 的跳過觀察詞元級 GAE 估計器可在動作到動作邊界之間計算優勢，避免環境回饋的觀察詞元污染策略梯度。

3. **持續演化環境中的模擬線上學習**  
   若任務環境會隨時間改變（例如動態測試案例、對手策略更新、即時使用者回饋），單次推論軌跡 RL 能讓模型更快適應變化，而不受群組層級平均的延遲限制。

4. **大規模後訓練 RL 流程加速**  
   對於需要將 RL 計算規模放大到數千步、數百顆 GPU 的開放模型訓練（如 GLM-5.2），SAO 的非同步設計可提升牆鐘效率與吞吐量，同時維持訓練穩定性。

5. **離策略嚴重的分散式推論訓練**  
   當推論軌跡引擎與訓練節點分離、且 rollout 過程中策略可能多次更新時，SAO 的直接雙邊詞元級裁剪能有效抑制策略延遲帶來的梯度偏差。

### 實作前置條件

**資料條件**
- 高品質提示資料集：每個 prompt 應能產生可評分的單一軌跡回饋。
- 明確的獎勵訊號：可以是單一最終獎勵（如測試通過與否）或稀疏的過程獎勵。
- 環境介面：支援多回合互動，能回傳觀察與獎勵，並能區分模型生成的動作詞元與環境提供的觀察詞元。

**運算條件**
- GPU 叢集：建議至少具備數十至數百顆 GPU，用於並行推論軌跡生成與策略更新。
- 非同步訓練基礎建設：需能將推論軌跡引擎（rollout engine）與訓練節點解耦，並支援隨到隨用的資料流。
- 模型檢查點與版本管理：由於非同步訓練中可能出現多個舊版策略，需要記錄每條軌跡對應的生成模型版本與對數機率。

**技術能力**
- 熟悉 PPO / GRPO 與詞元級重要性取樣。
- 具備分散式訓練經驗（如 PyTorch FSDP、Megatron-LM、DeepSpeed）。
- 能客製化優勢估計與價值模型訓練流程。
- 具備強化學習除錯與獎勵設計經驗，能處理訓練不穩定與獎勵駭取問題。

---

### 實作步驟建議

1. **建立同步基線**  
   先以標準 GRPO 或 PPO 在目標任務上建立同步式基線，確認獎勵函式、提示資料與評估指標合理。

2. **導入非同步推論軌跡引擎**  
   將 rollout 引擎獨立於訓練程序，讓軌跡完成後立即送入訓練佇列，無需等待整批樣本。

3. **改用單次推論軌跡取樣**  
   每個 prompt 只取樣一條 rollout，取代 GRPO 的群組取樣。這能減少離策略效應，並讓每條軌跡完成後即可訓練。

4. **實作直接雙邊詞元級重要性取樣（DIS）**  
   使用 rollout 引擎的對數機率作為行為代理，對當前策略與 rollout 策略之間的比率進行嚴格雙邊詞元級裁剪與遮罩，抑制策略延遲造成的梯度爆炸。

5. **強化價值模型訓練**  
   讓評論家模型（critic）的更新頻率高於行動者模型（actor），並在微調價值模型時凍結注意力層，以提升單次推論軌跡設定下的優勢估計品質。

6. **實作跳過觀察的詞元級 GAE**  
   針對多回合智能體軌跡，只在動作詞元上計算 GAE，跳過由環境產生的觀察詞元，避免將環境雜訊傳播到策略更新。

7. **漸進式規模化與監控**  
   從小規模實驗開始，監控訓練損失、重要性取樣比率、價值模型誤差與評估基準表現，逐步放大到數百步乃至一千步以上的穩定訓練。

8. **部署至生產 RL 流程**  
   將 SAO 整合進模型後訓練管線，搭配定期評估、檢查點回滾與線上監控，確保模型在持續演化環境中維持有效性。

### 潛在風險與注意事項

| 風險 | 說明 | 因應方式 |
|---|---|---|
| **訓練不穩定** | 非同步訓練中策略延遲可能導致離策略比率劇烈波動。 | 使用 SAO 的嚴格雙邊詞元級裁剪，並設定合理的裁剪閾值；監控每個詞元的重要性取樣比率。 |
| **價值模型崩潰** | 單次推論軌跡取樣下，critic 估計的變異數較大。 | 提高 critic 更新頻率、凍結注意力層微調，並適當調整 GAE 的 λ 與折扣因子 γ。 |
| **獎勵駭取** | 稀疏或設計不良的獎勵可能讓模型學到捷徑。 | 引入過程獎勵、人工審核軌跡、設置多樣化測試案例與對抗性驗證。 |
| **長軌跡落後樣本** | 雖然非同步減少等待，但極長軌跡仍可能佔用大量推論資源。 | 設定最大長度限制、動態批次調度，並將超長軌跡視為異常樣本處理。 |
| **裁剪過度抑制學習** | 過嚴的裁剪會讓策略更新幅度過小，收斂變慢。 | 從較寬鬆閾值開始，再根據訓練穩定性逐步收緊；同時監控策略熵與 KL 散度。 |
| **環境非穩定性** | 線上學習中環境持續變化，可能導致模型遺忘舊能力。 | 保留代表性驗證集、定期重放歷史提示、使用彈性評估指標追蹤長期表現。 |

### 與其他技術的整合建議

- **推論引擎**：可與 vLLM、SGLang 或自訂分散式推論服務整合，作為 SAO 的 rollout engine。重點是必須回傳每個生成詞元的對數機率與對應模型版本資訊。
- **訓練框架**：建議在 PyTorch FSDP、Megatron-LM 或類似框架上實作 actor-critic 非同步訓練，並將資料載入改為基於佇列的隨到隨用模式。
- **獎勵模型與驗證器**：可串接程式執行環境、單元測試框架、數學答案驗證器或學習過程獎勵模型（PRM），為每條軌跡提供即時回饋。
- **實驗追蹤與監控**：整合 Weights & Biases、TensorBoard 或 MLflow，持續記錄訓練步數、離策略比率、價值損失、基準分數與生成軌跡樣本。
- **模型部署與服務**：訓練完成後，可將策略模型直接匯出至標準推論服務；若使用 MoE 架構（如 GLM-5.2），需確認匯出與量化流程支援對應模型結構。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先理解強化學習基礎概念，特別是 PPO、優勢估計與離策略問題，再回來看 SAO 如何將「群組取樣」改成「單次推論軌跡取樣」。重點放在圖 2 的對比與為何非同步訓練能減少 GPU 等待時間，技術細節如詞元級裁剪可先略讀。

**AI 工程師**  
請聚焦第 3 節的實作細節：直接雙邊詞元級重要性取樣、價值模型凍結注意力與更高更新頻率、跳過觀察的 GAE。這些是將 SAO 落地到現有 RL 管線的關鍵，建議同時評估你目前 rollout engine 是否能提供足夠精確的對數機率與版本資訊。

**研究人員**  
值得深入探討 SAO 在訓練穩定性與離策略修正上的設計選擇，特別是單次推論軌跡取樣如何改變優勢估計的變異數結構，以及嚴格裁剪與標準 PPO/GRPO 的信任區域理論關聯。模擬線上學習實驗也提供了未來研究動態環境適應的好起點。

**產品經理**  
請將本文視為一個「效率與穩定性兼備」的後訓練 RL 方案。核心商業價值在於縮短長期智能體任務的訓練時間、提升模型在程式設計與推理基準上的表現，並能適應持續變化的環境。評估導入時，請優先確認團隊是否具備非同步分散式訓練基礎建設與可擴展的獎勵驗證流程。
