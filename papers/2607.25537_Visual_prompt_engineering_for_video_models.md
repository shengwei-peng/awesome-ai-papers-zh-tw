## ⚡ TL;DR

現有影片模型的視覺提示常被固定，本文探討修改視覺提示能否提升視覺推理表現。
提出視覺提示工程（VIPE），利用影像編輯模型自動轉換任務影像，例如將草圖風格改為照片級真實場景。
實驗顯示VIPE提升多項影片推理表現，效果常優於文字提示工程或測試時縮放，且模型偏好照片級真實情境。

## 摘要翻譯

在基礎模型（foundation models）時代，模型的好壞取決於其提示（prompt）。因此，提示工程（prompt engineering）已成為提升語言模型表現（language model performance）的關鍵技術。由於影片模型（video models）正逐漸成為視覺任務（visual tasks）（例如視覺推理（visual reasoning））的基礎模型，我們在此探問它們是否同樣能受益於 VIPE（Visual Prompt Engineering，視覺提示工程）：自動修改任務影像（task image）以提升模型表現（model performance）。例如，在一個視覺物理推理任務（visual physics reasoning task）（「球在通過一組障礙物後會落在哪裡？」）中，只需簡單呼叫影像編輯模型（image editing model），就能將抽象草圖風格場景（abstract sketch-like scene）轉換為照片級真實（photorealistic）的版本。我們發現 VIPE 能提升各項任務的影片推理（video reasoning）表現。事實上，對於影片模型而言，視覺提示工程甚至比傳統的文字提示工程（text-based prompt engineering）或測試時縮放（test-time scaling）更有效。總結來說，正如文字提示工程能系統性地提升語言模型表現，視覺提示工程也能作為一種簡單且節省計算資源（compute-efficient）的方法，引導影片模型展現出更好的視覺推理表現。更多範例影片請見我們的專案頁面：https://visual-prompt-engineering.github.io/。

### 核心貢獻（3～5點）
- 提出視覺提示工程（VIPE）概念，將傳統以文字為主的提示工程延伸至視覺領域，透過自動修改任務影像來提升影片模型的推理表現。
- 在視覺物理推理等多項視覺任務上驗證，VIPE 能有效提升影片模型（video models）的影片推理（video reasoning）表現。
- 發現對於影片模型而言，視覺提示工程比傳統文字提示工程（text-based prompt engineering）與測試時縮放（test-time scaling）更具優勢。
- 證明 VIPE 是一種簡單且節省計算資源（compute-efficient）的方法，可系統性地激發影片模型更好的視覺推理（visual reasoning）能力。

### 適合對象
本論文適合對生成式影片模型（generative video models）、視覺推理（visual reasoning）、提示工程（prompt engineering）及基礎模型（foundation models）應用有興趣的研究者與工程師，特別是關注如何以低成本、視覺導向的方式提升影片模型下游任務（downstream tasks）表現的讀者。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**
A：在基礎模型時代，提示工程已成為提升語言模型表現的關鍵技術，但對於同樣作為視覺任務基礎模型的影片模型，其視覺提示卻長期被視為固定不變的輸入。本研究提出「視覺提示工程」（Visual Prompt Engineering, VIPE），探討是否能透過自動修改任務影像來提升影片模型的視覺推理表現。這個問題挑戰了過去只重視文字提示、忽略視覺提示最佳化的不對稱現象。

**Q2：為什麼現有方法無法充分發揮影片模型的潛力？**
A：現有研究大多針對大型語言模型或視覺語言模型進行文字提示工程，而針對影片模型「視覺輸入」的系統性最佳化幾乎未被探索。此外，許多視覺推理基準採用抽象草圖風格場景，與影片模型在照片級真實影像上預訓練的分布不一致，導致模型能力被低估。單靠調整文字提示難以彌補視覺情境中空間佈局、物體與限制條件所帶來的影響。

**Q3：視覺提示工程為何重要？**
A：在視覺推理任務中，視覺提示往往佔據大量 token，是影片模型的主要條件訊號，決定了模型必須推理的空間佈局、物體與限制條件。透過視覺提示工程，我們可以在不重新訓練模型的情況下，系統性地激發更好的視覺推理表現。它同時是一種節省計算資源的測試時縮放策略，並能揭示影片模型在更自然視覺風格下的真實能力。

**Q4：VIPE 的核心方法流程是什麼？**
A：VIPE 的目標是將原始任務影像替換為一個語義等價、但視覺呈現更適合模型推理的變體。整個流程分為三步：首先由「構想器」（ideator）根據構想提示產生自然語言的影像編輯指令；接著「編輯器」（editor，例如 NanoBanana 等影像編輯模型）依指令生成多個候選影像；最後可選的「篩選器」（filter，例如視覺語言模型）評估候選影像的品質與對原始提示的忠實度，選出最佳視覺提示。經過轉換的影像會作為影片模型的第一幀，讓模型生成解題影片。

**Q5：這項研究的主要創新之處在哪裡？**
A：本研究首次將「提示工程」的概念從文字領域系統性地延伸到影片模型的視覺輸入，提出視覺提示工程這個全新問題與可自動化的解決框架。關鍵創新在於將視覺提示視為可最佳化的變數，而非固定給定的任務影像。研究也發現，對影片模型而言，精煉視覺情境有時比最佳化文字指令更有效，並揭露了模型對照片級真實視覺情境的系統性偏好。

**Q6：為什麼要採用「構想器—編輯器—篩選器」這樣的設計？**
A：構想器負責在保留核心任務邏輯的前提下，提出多樣化的視覺改寫方向，例如將草圖風格的球與斜坡改為真實的撞球與木製層架。編輯器則把這些自然語言指令轉換成實際影像，並透過隨機採樣產生多個候選，增加找到高品質視覺提示的機會。篩選器利用視覺語言模型進行自動品質與忠實度評分，避免人工挑選，也讓整個流程易於擴展與重複執行以進行集成。

**Q7：論文在哪些任務與資料集上進行實驗？**
A：研究首先在 VPCT 視覺物理推理資料集上進行評估，任務要求模型預測白球經過一系列斜坡後會落入哪個桶子。此外也測試了排序數字的視覺推理任務，模型需要讓數字按大小順序逐一消失。這些任務都需要模型理解空間佈局、物理因果或數值順序，並常以抽象草圖風格場景呈現，適合用來檢驗視覺提示工程的效果。

**Q8：實驗的主要結果是什麼？**
A：實驗顯示 VIPE 能穩定提升影片模型在多項視覺推理任務上的表現。更重要的是，對影片模型來說，視覺提示工程甚至比傳統文字提示工程或單純增加測試時計算的測試時縮放更有效。將抽象草圖轉為照片級真實場景後，模型準確率顯著提升，顯示現有以草圖為主的基準可能大幅低估影片模型的能力。

**Q9：有哪些消融實驗或比較分析？**
A：作者比較了 VIPE 與文字提示工程以及測試時縮放，結果發現精煉視覺情境帶來的增益通常高於單純調整文字提示或增加生成樣本數。加入篩選器後，能從多個候選中選出品質較高且忠於原始任務的影像，進一步提升下游表現。此外，透過重複執行管線產生多個變體並進行集成，也能作為有效的測試時縮放策略。

**Q10：視覺提示工程有哪些實際應用場景？**
A：VIPE 可應用於任何以影片模型進行視覺推理的場景，例如物理教學模擬、機器人動作規劃、邏輯謎題求解或產品設計原型驗證。使用者只需提供草圖或示意圖，系統就能自動將其轉換為照片級真實場景，讓模型產生更可靠的預測影片。這大幅降低了手動建置高品質視覺情境的成本，讓影片模型更容易落地到真實世界任務。

**Q11：在產品化時需要考慮哪些因素？**
A：實際部署時必須考量影像編輯模型與視覺語言模型篩選器所帶來的延遲與計算成本，因為每個任務都需要額外生成並評估多個候選影像。同時，必須確保編輯後的影像不會改變任務的底層邏輯或關鍵限制條件，例如斜坡角度、桶子位置或數字順序。此外，建議保留人工監督與品質控制機制，以避免自動化流程產生語義偏移或誤導性的視覺提示。

**Q12：這項研究對整個領域可能帶來什麼影響？**
A：VIPE 將研究焦點從單純的文字提示最佳化，擴展到多模態基礎模型中視覺輸入的最佳化，促使學界重新檢視視覺提示的角色。它也提醒研究者，以抽象草圖風格建立的視覺推理基準可能無法反映影片模型在真實影像上的潛力，進而推動更多樣化、貼近真實視覺分布的評估標準。未來這套框架還可能啟發生成式影片模型、視覺語言模型乃至機器人領域的自動化提示設計工具。

**Q13：論文承認了哪些限制？**
A：VIPE 的成效高度依賴影像編輯模型與篩選器的能力，若編輯器產生低品質或不忠實的影像，反而可能損害模型表現。並非所有任務都能從照片級真實化中獲益，某些高度符號化或抽象邏輯的任務可能缺乏適合的視覺轉換方式。此外，自動化流程雖然方便，但仍可能在不經意間引入語義偏移，改變原始任務的意義。

**Q14：可能出現哪些失敗案例？**
A：影像編輯模型可能會改變關鍵的物理限制條件，例如把斜坡角度或桶子位置調錯，導致模型做出錯誤的落點預測。篩選器也可能偏好視覺上吸引人但與原始草圖不一致的變體，進而降低任務忠實度。對於排序數字這類依賴符號結構的任務，過度強調照片級真實外觀有時無法幫助模型理解正確的數值順序。

**Q15：未來可以朝哪些方向發展？**
A：未來可以發展可學習的視覺提示最佳化器，甚至可微分的像素級提示調整，以取代目前依賴影像編輯模型的離散編輯流程。也可以將視覺提示工程擴展到動態的影片提示，而不僅限於第一幀影像。最後，結合視覺提示工程與文字提示工程的聯合最佳化，並建立涵蓋多種視覺風格的穩健基準，將是提升影片模型視覺推理能力的重要方向。

## 實務應用指南

### 適用場景

1. **工業設備異常預測**：將產線上的機台示意圖或熱影像轉換為照片級真實的模擬畫面，讓影片模型預測零件磨損、液體洩漏或溫度異常的演變過程，輔助維修排程。
2. **教育與科學模擬**：把課本中的物理示意圖（如斜面、拋體、電路）轉為擬真動畫，讓影片模型生成可解釋的因果過程，幫助學生理解力學、光學或化學反應。
3. **自動駕駛與機器人規劃**：將簡化的場景草圖或模擬器畫面轉換為真實街景風格，提升影片模型對物體運動軌跡、碰撞與避障路徑的預測準確率。
4. **電商與產品展示**：把 2D 產品設計圖或線稿轉為擬真使用情境影片，讓模型生成開箱、組裝或動態效果預覽，縮短行銷素材製作週期。
5. **醫療影像輔助判讀**：將低解析度或抽象化的醫學掃描示意圖轉為高擬真度的結構化視覺提示，協助影片模型模擬病灶發展或手術預演。

### 實作前置條件

- **資料準備**：需要一組原始任務影像（視覺提示）與對應的文字提示，影像格式通常為常見圖檔（PNG/JPG），並清楚標示任務邏輯中不可更動的元素（如物體位置、空間佈局、限制條件）。
- **模型與計算資源**：至少需具備一個生成式影片模型（如 Veo）與一個影像編輯模型（如 NanoBanana 或類似的 diffusion-based 編輯模型），並可選用視覺語言模型（VLM）作為篩選器。建議配備 GPU 或雲端推論環境以批次生成與評分。
- **技能需求**：團隊需熟悉提示工程、影像生成模型操作，以及基礎的視覺評估流程；若要走自動化管線，還需具備 Python 與 API 整合能力。

### 實作步驟建議

1. **定義任務與不變元素**：明確寫出文字提示，並標註哪些視覺元素（物體、空間關係、物理規則）在編輯後必須保留。
2. **設計 ideation prompt**：讓語言模型根據任務情境產生多種視覺改寫方向，例如「將草圖風格球體改為撞球，障礙物改為木質層架，但保持運動路徑不變」。
3. **批次生成視覺變體**：使用影像編輯模型對同一張原始任務影像生成多個候選版本（𝑚 個變體），並可重複多次以取得 𝑛 組最終候選。
4. **品質與忠實度篩選**：以 VLM 或自訂評分函數評估每個候選影像的品質，以及是否忠實於原始任務的邏輯與佈局，選出最佳視覺提示。
5. **餵入影片模型並評估**：將篩選後的視覺提示與文字提示一起輸入影片模型，生成影片並以 pass/fail 或自訂指標評估視覺推理表現。
6. **迭代與擴充**：根據失敗案例調整 ideation prompt、篩選條件或編輯模型參數，並可結合多個最佳視覺提示進行集成推理（ensembling）。

### 潛在風險與注意事項

- **任務邏輯被改變**：影像編輯模型可能無意間移動物體、改變材質物理意義或遮擋關鍵線索，導致任務本身被扭曲。建議在篩選階段加入「結構忠實度」檢查。
- **過度擬真反而誤導**：並非所有任務都適合照片級真實風格，某些抽象任務加入過多細節可能讓模型分心。應保留原始風格與多種視覺風格的對照實驗。
- **計算成本被低估**：雖然 VIPE 比單純測試時縮放更節省計算資源，但生成與篩選多個影像變體仍會增加延遲與費用，需評估端對端成本。
- **評分函數偏差**：VLM 篩選器可能偏好「看起來漂亮」而非「任務正確」的影像，建議結合任務導向指標與人工抽樣驗證。
- **版權與倫理問題**：將真實場景、人臉或醫療影像轉為擬真畫面時，需注意資料使用授權與生成內容的可解釋性。

### 與其他技術的整合建議

- **與文字提示工程搭配**：先以傳統文字提示工程優化任務描述，再將優化後的文字提示作為 VIPE 的輸入，可進一步提升影片模型表現。
- **與測試時縮放（test-time scaling）結合**：VIPE 可作為第一階段的提示最佳化，再搭配多次影片生成與投票機制，形成多層次的推論階段擴展策略。
- **與視覺語言模型（VLM）管線整合**：使用 VLM 自動檢查影像編輯前後的一致性，並在影片生成後自動評分，實現端到端自動化。
- **與模擬器或數位孿生系統對接**：將模擬器輸出的抽象場景直接餵入 VIPE 管線，產生擬真視覺提示後再由影片模型進行預測，縮短模擬到真實部署的落差。
- **與 MLOps 平台整合**：將 VIPE 的 ideator、editor、filter 與 video model 封裝為可重複執行的管線，納入版本控制、A/B 測試與監控系統。

### 給不同背景讀者的閱讀建議

- **初學者**：這篇論文提出一個直覺概念——就像調整問句能讓 ChatGPT 回答得更好，調整輸入影像也能讓影片模型表現更好。建議先理解「視覺提示工程」與「文字提示工程」的類比，再透過圖 1 的管線圖掌握 ideator、editor、filter 三個步驟即可。
- **AI 工程師**：重點放在如何將 VIPE 落地為可擴展的推論管線，包括影像編輯模型的選型、VLM 篩選器的 prompt 設計、批次生成與評分的成本控管，以及如何與現有的影片生成 API 整合。
- **研究人員**：論文的核心貢獻在於揭示影片模型對照片級真實視覺情境的系統性偏好，以及視覺提示工程可能比文字提示工程更有效的現象。建議深入檢視實驗設計、任務選擇與評估指標，並思考其背後的機制與泛化性。
- **產品經理**：這是一個低門檻、高槓桿的技術——不改模型、只改輸入影像，就能提升視覺推理準確率。建議評估哪些產品場景（如模擬預測、內容生成、教育展示）最能受益，並規劃從單一任務試點到自動化管線的產品路徑。
