## 摘要翻譯

我們提出 SANA-Video 2.0，一個以統一架構實例化為 5B 與 14B 兩種規模的混合式影片擴散 Transformer（Video Diffusion Transformer, Video DiT）。SANA-Video 2.0 目標是在單張 GPU 上生成最高達 720p 的高品質影片，在品質上可媲美全軟最大影片 DiT（full-softmax video DiTs），同時保留線性注意力（linear attention）良好的長序列擴展性（long-sequence scaling）。為了全程避免二次注意力（quadratic attention），混合線性-軟最大注意力（Hybrid Linear-Softmax Attention）採用門控線性注意力（Gated Linear Attention）進行以 O(N) 複雜度為主導的詞元混合（token mixing），並以 3:1 的比例週期性插入門控軟最大錨點（Gated Softmax Anchors），恢復純線性注意力（pure linear attention）所缺乏的全秩詞元交互作用（full-rank token interactions）。為了將這些更新後的表徵傳播至深層，區塊注意力殘差（Block Attention Residuals, AttnRes）將完成後的區塊摘要傳遞至後續線性層，實現錨點特徵的重複使用，並將深層有效秩（effective rank）提升約 12%。透過從頭訓練（from-scratch training），SANA-Video 2.0 直接學習完整的混合模型，而非將預訓練模型線性化；透過降解析度代理研究（reduced-resolution proxy studies），我們確立 25% 的軟最大注意力（softmax attention）比例為品質與效率的最佳權衡。在 40 步取樣（sampling steps）下，SANA-Video 2.0 於單張 H100 上生成 480p 影片僅需 13.2 秒，VBench 分數（VBench score）達 84.30，僅以遠低於對手的延遲即可與規模大得多的軟最大影片 DiT 競爭。其編譯後的 DiT 前向傳遞（forward pass）在 720p/60 秒設定下，比對應的全軟最大基線（full-softmax baseline）快 3.2 倍，且隨影片長度增加，差距會進一步擴大。此外，全端 Sol-Engine 優化（Sol-Engine optimization，包含核心融合 kernel fusion、快取 caching 與稀疏注意力 sparse attention）使這個對硬體友善的骨幹再加速 3.58 倍，使 5B 規模流程在 720p/5 秒設定下僅需 13.06 秒，在單張 H100 上比 Wan 2.2-A14B 快 120 倍。總體而言，我們的混合設計以大幅降低的成本恢復了軟最大層級的表現力，開啟可擴展的長影片與高解析度影片生成。

### 核心貢獻（3～5點）
- 提出混合線性-軟最大注意力（Hybrid Linear-Softmax Attention）機制，以 3:1 比例結合門控線性注意力（Gated Linear Attention）與門控軟最大錨點（Gated Softmax Anchors），在維持 O(N) 複雜度優勢的同時恢復全秩詞元交互作用。
- 設計區塊注意力殘差（Block Attention Residuals, AttnRes），將錨點區塊摘要傳遞至深層線性層，提升深層有效秩約 12%。
- 採用從頭訓練（from-scratch training）策略與降解析度代理研究（reduced-resolution proxy studies），確立 25% 軟最大注意力比例為最佳品質-效率權衡。
- 透過 Sol-Engine 全端優化（核心融合、快取、稀疏注意力），在單張 H100 上實現 720p 高解析度影片的高效生成，5B 模型於 720p/5 秒僅需 13.06 秒。
- 在 480p 設定下以 40 步取樣達到 VBench 84.30 分，與規模更大的全軟最大影片 DiT 競爭，同時顯著降低延遲。

### 適合對象
適合對影片生成、擴散模型（diffusion models）、注意力機制（attention mechanisms）及高效能深度學習推理感興趣的研究人員與工程師，特別是關注長序列、高解析度影片生成，以及線性注意力與軟最大注意力混合設計的讀者。

## 深度分析

#### 方法論解析

SANA-Video 2.0（混合注意力影片生成模型）的核心目標，是在維持線性注意力（Linear Attention，O(N) 複雜度）長序列擴展性（long-sequence scaling）的同時，恢復全 softmax 影片 DiT（Video Diffusion Transformer，影片擴散 Transformer）的表達力。其方法論可拆解為四個層次：**混合注意力骨幹**、**跨層殘差路由**、**從頭訓練流程** 與 **全端推論優化**。

##### 1. Hybrid Linear-Softmax Attention（混合線性-軟最大注意力）

SANA-Video 2.0 以 **gated linear attention（門控線性注意力）** 作為主要的詞元混合（token mixing）運算。該運算將序列互動壓縮到固定大小的狀態矩陣 \(S \in \mathbb{R}^{d \times d}\)，使序列複雜度從 softmax attention 的 \(O(N^2)\) 降至 \(O(Nd^2)\)。具體而言，每個頭部採用雙向門控雙線性形式：

\[
S_n = \sum_n v_n(\beta_n k_n^r)^\top,\quad
o_n = W_o\left[\mathrm{RMSNorm}\left(\frac{S_n q_n^r}{\sum_n \varphi(k_n)^\top\varphi(q_n)+\epsilon}\right)\odot \sigma(g_n)\right]
\]

其中 \(q_n^r, k_n^r\) 為經 RoPE（旋轉位置編碼）旋轉後的查詢與鍵，\(\varphi(\cdot)=\mathrm{ReLU}(\cdot)\)，\(\beta_n\) 控制寫入狀態的閘門，\(g_n\) 控制輸出閘門。此設計為雙向、非因果，且捨棄 delta-rule 遞迴，使其未來可自然銜接因果 Gated DeltaNet 等方向。

然而，純線性注意力的固定狀態矩陣具有 **rank-constrained（秩受限）** 瓶頸，無法表達所有詞元—詞元交互作用，容易削弱精細的時空對應與細節。為此，模型以 **3:1 比例** 定期插入 **gated softmax anchors（門控軟最大錨點）**，即 25% 的層使用完整 softmax attention。這些錨點採用雙向 SDPA（縮放點積注意力）並搭配 QK normalization、RoPE 與 sigmoid 輸出閘門，能週期性地恢復 **full-rank token interactions（全秩詞元交互作用）**，而剩餘 75% 的線性層則保留長序列的 \(O(N)\) 計算優勢。

##### 2. Block Attention Residuals（AttnRes，區塊注意力殘差）

標準加性殘差 \(h_l = h_{l-1} + f_l(h_{l-1})\) 會迫使深層重新推導上游已計算的資訊。SANA-Video 2.0 引入 **Block Attention Residuals（AttnRes）**，將「完成的區塊摘要」（completed block summaries）直接路由到後續層，使深層的線性層能夠重複使用 softmax 錨點所產生的 **rank-refreshed updates（秩刷新更新）**。

在影片擴散場景中，作者對原始 Attention Residuals 做了兩項關鍵調整：

- **跨深度共享 routing queries（路由查詢）**：簡化參數並穩定訓練。
- **移除 diffusion timestep（擴散時間步）條件**：因為 AdaLN-style 調變已經內含時間資訊，額外條件變得多餘。

實驗顯示，在相同檢查點下開啟 AttnRes，可將深層狀態的 **effective rank（有效秩）** 提升約 **12%**，驗證了跨層路由確實能傳播更豐富的表徵。

##### 3. 整體架構與訓練設計

SANA-Video 2.0 運作於 **LTX-VAE 2.3** 產生的 **latent tokens（潛在詞元）** 上，並以 **Gemma-2-2B-IT** 作為文字編碼器，於每一層透過 cross-attention（交叉注意力）注入文字特徵。模型完全去除卷積，將 SANA-Video 前代的 temporal-convolution FFN 替換為 **SwiGLU FFN**，因為實測顯示前者隨影片長度增加的開銷會持續放大。

訓練策略上，作者強調 **from-scratch training（從頭訓練）**，而非對預訓練 softmax 模型進行 post-hoc linearization（事後線性化）。流程包括：

- 以 **reduced-resolution proxy studies（降解析度代理研究）** 搜尋最佳 softmax 比例，確立 **25% softmax** 為品質—效率拐點（quality–efficiency knee）。
- 多階段資料策展與過濾。
- 由低解析度、短影片到高解析度、長影片的課程式訓練（curriculum training）。
- 結構化字幕（structured captioning）、self-distillation（自我蒸餾）。
- 偏好式後訓練：DPO 與 ReFL。

##### 4. Sol-Engine 全端推論優化

在推論端，SANA-Video 2.0 搭配 **Sol-Engine** 進行全端優化，包括 **kernel fusion（核心融合）**、**caching（快取）** 與 **sparse attention（稀疏注意力）**。此外，透過 **quantization-aware training（量化感知訓練）**，模型可在 **MXFP4 weights** 與 **MXFP8 activations** 下達到與 BF16 相近的品質。

#### 實驗數據解讀

論文提供的實驗數據主要圍繞三個維度：**生成品質**、**推理延遲** 與 **架構消融驗證**。

##### 1. 品質與延遲的綜合表現

在單張 **H100** 上，SANA-Video 2.0（5B 規模）以 **40-step sampling（40 步取樣）** 生成 \(480 \times 832 \times 81\) 影片時，達到：

- **VBench Total（VBench 總分）84.30**
- 耗時僅 **13.2 秒**

這一成績已能與規模大得多的全 softmax 影片 DiT 競爭，但延遲僅為其一小部分。這說明混合注意力並未因犧牲部分 softmax 層而顯著損失品質，反而在效率上取得大幅領先。

##### 2. 與全 softmax 基線的速度比較

在 **720p/60s** 的設定下，SANA-Video 2.0 的 compiled DiT forward pass（編譯後 DiT 前向傳遞）相較於匹配的 full-softmax baseline（全軟最大基線）快 **3.2×**。由於 softmax attention 的 \(O(N^2)\) 成本會隨影片長度急遽放大，而線性層維持 \(O(N)\)，因此這個差距會隨 duration（影片長度）進一步擴大。

在生產級分析中，即使是 **1080p/121f** 的設定，25% 混合模型在雙方皆以最佳核心編譯的情況下，仍比全 softmax 骨幹快 **2.01×**。這證實了高解析度、長影片場景下，混合設計的優勢更加明顯。

##### 3. Sol-Engine 的端到端加速

Sol-Engine 在 **B200** 上帶來額外的 **3.58× end-to-end speedup（端到端加速）**。結合硬體友善的混合骨幹後，5B 管線在 **720p/5s** 設定下僅需 **13.06 秒**，並且在單張 H100 上比 **Wan 2.2-A14B** 快 **120×**。這顯示出「演算法設計」與「系統優化」的乘積效應：單靠混合注意力可獲得數倍加速，再疊加核心融合、快取與稀疏注意力後，才能達到數量級的延遲縮減。

##### 4. 架構消融：25% softmax 與 AttnRes

- **25% softmax anchors**：透過降解析度代理研究確立為品質與效率的最佳平衡點。過少則無法恢復足夠表達力，過多則侵蝕線性注意力的速度優勢。
- **AttnRes**：在控制變因下開啟後，深層狀態的 effective rank 提升約 **12%**。這量化了跨層特徵重用的價值，也解釋了為何混合模型能接近全 softmax 的品質。

整體而言，實驗數據描繪出一條清晰的帕雷托前沿：SANA-Video 2.0 在品質維度與大型 softmax 模型重疊，在延遲維度則顯著左移。

#### 與現有研究的比較

##### 1. 相較於全 softmax 影片 DiT

現有開源影片生成模型如 **Wan 2.1（14B）**、**HunyuanVideo（13B）** 與 **Seedance 2.0**，以及閉源系統如 **Veo3**、**Kling**，大多採用全 3D softmax attention。這類方法雖能產出高保真影片，但 \(O(N^2)\) 的注意力成本在 1080p 下已達數萬個 latent tokens，對單張 GPU 極具懲罰性。SANA-Video 2.0 以 25% softmax + 75% linear 的混合設計，在品質可與之競爭的前提下，將 DiT forward 提升 3.2×，並隨影片長度進一步放大優勢。

##### 2. 相較於長影片生成模型

即使是專注於長影片的 **MAGI-1**，仍受限於 vanilla attention（原始注意力）。SANA-Video 2.0 的 \(O(N)\)-dominated 骨幹則為超過 10 秒的長影片提供更具擴展性的基礎。

##### 3. 與大語言模型中混合注意力的關聯

近期大型語言模型如 **Qwen3-Next**、**Kimi-Linear** 與 **Kimi K3** 已驗證「以線性注意力為主、定期插入 softmax 錨點」並搭配 Attention Residuals 的有效性。SANA-Video 2.0 將此概念遷移至影片生成領域，並針對雙向擴散模型進行調整：共享 routing queries、移除多餘的 diffusion timestep 條件、採用無卷積的 SwiGLU FFN。這不僅是領域遷移，也證明了混合注意力在連續、高維視覺訊號上的通用性。

##### 4. 相較於 SANA-Video 1.0

前代 SANA-Video 已展示純線性 Video DiT 的速度潛力，但受限於 rank-constrained 表徵。SANA-Video 2.0 透過 softmax anchors 恢復 full-rank interactions，並以 AttnRes 跨層傳播這些更新；同時以 SwiGLU FFN 取代 temporal-convolution FFN，降低隨影片長度增長的開銷。

##### 5. 限制與待釐清之處

- 即使僅 25% softmax，在極長序列下仍會佔據可觀記憶體與計算。
- **AttnRes** 雖提升有效秩，但額外的跨層路由會增加記憶體流量，需與核心融合技術搭配才能發揮效益。
- 論文摘要與引言主要強調 5B 模型的推論數據，14B 模型的完整 VBench 與延遲數據在提供的片段中較少。
- 模型仍依賴外部文字編碼器（Gemma-2-2B-IT）與 VAE（LTX-VAE 2.3），這些組件的最佳化空間尚未被充分探討。

#### 未來研究方向

基於 SANA-Video 2.0 的設計與實驗結果，以下幾個方向值得進一步探索：

##### 1. 動態與自適應混合比例

目前採用固定的 3:1 softmax 比例。未來可研究依據輸入長度、解析度或內容複雜度動態調整 softmax 錨點密度，以在極短片段進一步加速、在複雜場景保留更多表達力。

##### 2. 因果與串流影片生成

現有設計為雙向，適合離線生成。將門控線性注意力延伸至 **Gated DeltaNet** 等因果遞迴形式，可支援串流、即時或互動式影片生成。

##### 3. 更長影片與更高解析度

雖然 \(O(N)\) 骨幹已具擴展性，但極長影片（數分鐘）仍面臨記憶體與時間一致性挑戰。結合原生 3D sparse attention、分層式 latent 表示或記憶體機制，是自然的延伸。

##### 4. 文字編碼器與 VAE 的聯合最佳化

目前文字與視覺壓縮模組為外部固定組件。對 Gemma-2-2B-IT 進行蒸餾或對 LTX-VAE 進行聯合微調，可進一步降低延遲並提升對齊品質。

##### 5. 多 GPU 與邊緣部署

論文聚焦單 GPU 效率。未來可研究在不破壞線性注意力優勢的前提下，進行 tensor/pipeline parallelism，以及將量化後的 5B 模型部署至消費級 GPU。

##### 6. 理論分析

對混合注意力的 **effective rank**、資訊傳播動態與訓練穩定性進行更嚴謹的理論分析，有助於設計更高效的錨點配置與殘差路由策略。

##### 7. 跨模態遷移

SANA-Video 2.0 的混合注意力與 AttnRes 框架可遷移至 3D 生成、音訊-視訊聯合生成或其他高維序列任務，成為高效能生成模型的通用基礎模組。

## 論文問答

**Q1：全軟最大影片DiT在生成長影片或高解析度影片時，根本的計算瓶頸是什麼？**
A：傳統的3D軟最大注意力具有 𝑂(𝑁²) 的二次複雜度，當影片經過VAE壓縮後，單一1080p片段就可能產生數萬個潛在詞元，使得注意力矩陣與活化工作空間的記憶體與計算成本急遽上升。這種成本在長影片（>10秒）情境下會變得更加難以負擔，因為序列長度增加時，二次成本會主導整個前向傳播時間。因此，全軟最大影片DiT雖然品質優異，卻難以在單張GPU上實現可擴展的長序列、高解析度生成。

**Q2：為什麼單純使用純線性注意力無法完全取代軟最大注意力？**
A：純線性注意力將詞元間的交互作用壓縮到一個固定大小的狀態矩陣，雖然能將序列複雜度降到 𝑂(𝑁)，但這個狀態矩陣是秩受限的，無法表達所有詞元與詞元之間的完整交互。這會削弱模型對精確時空對應關係與細節的建模能力，導致生成品質下降。因此，線性注意力雖然高效，卻必須透過額外機制來恢復軟最大注意力的表達力。

**Q3：發展混合線性—軟最大注意力骨幹對高效能影片生成為何重要？**
A：混合設計能同時兼顧線性注意力的 𝑂(𝑁) 長序列擴展性，以及軟最大錨點所提供的全秩詞元交互作用，讓模型在單張GPU上生成720p甚至更高解析度的影片。這不僅能顯著降低延遲與記憶體佔用，也能讓較小規模的模型與遠大於自身的全軟最大模型競爭。對整個領域而言，這代表可以從單純擴大二次注意力模型，轉向更節省資源、可普及的影片生成架構。

**Q4：SANA-Video 2.0 的混合線性—軟最大注意力核心設計是什麼？**
A：該模型以門控線性注意力作為主要的詞元混合操作，因為它具有線性複雜度且適合長序列；同時以固定深度、固定比例定期插入門控軟最大錨點，採用的是3:1的混合配置，也就是25%的軟最大注意力。這些錨點能週期性地恢復純線性注意力無法表達的較低秩受限交互作用，而大部分線性層則保留了長序列擴展性。文本條件透過跨注意力注入，並以無卷積的SwiGLU FFN取代原本帶有時序卷積的FFN，進一步降低隨影片長度增長的開銷。

**Q5：區塊注意力殘差（AttnRes）的作用是什麼，它如何強化混合骨幹？**
A：傳統的加性殘差會迫使後層重新推導前面已經計算過的資訊，而AttnRes則是將已完成區塊的特徵摘要直接傳遞到後續深度，讓後面的線性層能重複使用軟最大錨點所刷新過的表徵。在相同檢查點的開關對照實驗中，啟用AttnRes可讓深層狀態的有效秩提升約12%。為了適應雙向影片擴散，作者讓路由查詢在深度間共享，並發現擴散時間步條件可由AdaLN取代，因此移除了額外的時間步輸入。

**Q6：作者為何選擇25%的軟最大錨點比例，並採用從頭訓練而非事後線性化預訓練模型？**
A：透過降解析度代理研究，作者發現25%軟最大錨點是品質與效率之間的最佳折衷點，能夠在顯著降低計算成本的同時維持接近全軟最大模型的品質。從頭訓練則讓整個混合架構直接學習運動與外觀資訊，而不必依賴預訓練軟最大模型或影像先驗，這也避免了線性化過程中可能出現的表達損失。完整的訓練流程包含多樣化資料篩選、由低解析度到高解析度的課程學習、結構化標註、自我蒸餾，以及基於偏好的後訓練（DPO與ReFL）。

**Q7：論文使用了哪些評測基準與指標來驗證SANA-Video 2.0？**
A：主要採用VBench總分作為影片生成品質的綜合指標，並在單張H100與B200上測量推理延遲。對比對象包括Wan 2.1、HunyuanVideo、Wan 2.2-A14B等全軟最大或更大規模的模型。此外，作者也進行了有效秩分析、AttnRes消融實驗，以及不同軟最大比例的代理研究，以驗證設計選擇。

**Q8：SANA-Video 2.0 的關鍵量化結果有哪些？**
A：5B模型在單張H100上以40步取樣，於480×832×81的設定下達到VBench總分84.30，僅耗時13.2秒，可與規模大得多的軟最大模型競爭。在720p/60秒的設定下，其編譯後的DiT前向傳播比對應的全軟最大基線快3.2倍，且隨影片長度增加差距會進一步擴大。結合Sol-Engine的全端優化後，在B200上可再獲得3.58倍的端到端加速，使5B管線在720p/5秒設定下僅需13.06秒，比Wan 2.2-A14B快120倍。

**Q9：有哪些消融或診斷證據支持這些設計選擇？**
A：AttnRes的開關對照實驗顯示，啟用後深層狀態的有效秩提升約12%，證明殘差路由確實能傳播並重複使用錨點特徵。降解析度代理研究確立了25%軟最大錨點為品質—效率的膝點，過少會損失表達力，過多則降低速度優勢。秩與路由分析也揭示了明確的分工：線性層負責低成本的全域詞元混合，軟最大錨點注入精確的全秩交互作用，而AttnRes則跨深度搬運區塊層級特徵。

**Q10：SANA-Video 2.0 在哪些實際應用場景中最具優勢？**
A：該模型特別適合在單張GPU上快速生成720p/5秒或480p等級的影片，可應用於創意內容製作、虛擬產品展示與直播等需要即時回饋的場景。由於其延遲遠低於大型全軟最大模型，設計師與開發者能進行更快速的迭代與互動式原型製作。此外，對於超過10秒的長影片生成，其 𝑂(𝑁) 主導的骨幹能避免二次成本爆炸，展現出顯著的擴展性優勢。

**Q11：論文提到了哪些產品與部署上的考量？**
A：SANA-Video 2.0 的骨幹設計對硬體友善，容易進行效能分析並與現成的核心進行融合，這對實際部署非常重要。作者進一步提出Sol-Engine全端優化，包含核心融合、快取與稀疏注意力等技術，以最大化推理效率。此外，量化感知訓練可在MXFP4權重與MXFP8激活的設定下達到接近BF16的品質，有助於降低部署時的記憶體與頻寬需求。

**Q12：SANA-Video 2.0 可能對整個影片生成領域帶來什麼影響？**
A：它證明了以線性注意力為主的骨幹，只要搭配適當的軟最大錨點與跨層殘差路由，就能恢復甚至逼近全軟最大模型的表達力。這可能促使研究社群重新思考影片DiT的設計方向，從單純擴大二次注意力模型轉向更高效的混合架構與全端優化。對一般使用者與研究者而言，這也降低了取得高品質影片生成能力的門檻，推動技術的普及與應用創新。

**Q13：論文承認了哪些限制或約束？**
A：14B模型是在384×B200的規模下進行訓練，因此極長或極高解析度的影片生成能力仍有待更廣泛驗證。部分設計決策，例如25%軟最大比例，是透過降解析度代理研究得出的，雖然在實驗中表現良好，但未必能直接外推到所有解析度與長度設定。此外，論文主要與開源模型進行比較，對於Veo3、Kling等閉源系統的完整對照仍有限。

**Q14：使用者應該注意哪些潛在的失敗案例或風險？**
A：如果軟最大錨點過於稀疏，後續的線性層在處理極精細的時空對應關係時仍可能出現不足，導致動作或細節不一致。在極長影片生成中，雖然計算成本降低，但運動連貫性與長期一致性仍可能受到限制。量化與稀疏注意力的引入雖然能加速推理，但在某些複雜場景下可能對品質造成細微影響，需要根據應用需求進行權衡。

**Q15：作者提出了哪些未來研究方向？**
A：未來可以將混合線性—軟最大注意力的設計擴展到更長、更高解析度的影片，並探索不同的錨點排程與比例配置。作者也提到可將目前的雙向門控線性注意力進一步發展為因果性的Gated DeltaNet，以支援串流或遞迴式影片生成。此外，結合更強大的文本編碼器與VAE、將AttnRes應用到其他模態，以及持續推進核心融合與量化優化，都是值得深入探索的方向。

## 實務應用指南

## 適用場景

1. **社群媒體與行銷短影片生成**  
   品牌與創作者可依文字腳本快速產出 480p–720p、5–10 秒的產品展示或廣告片段，在單張 H100 上 13 秒級完成 40 步取樣，適合需要大量迭代與 A/B 測試的內容管線。

2. **電商虛擬商品展示**  
   將靜態商品圖或描述轉為動態 360° 展示影片，利用 SANA-Video 2.0 的線性注意力擴展性生成較長、高解析度的服飾／家具展示，降低拍攝與後製成本。

3. **遊戲與互動敘事原型**  
   遊戲開發者可用於快速生成過場動畫、NPC 動作預覽或動態背景，並透過 Sol-Engine 的稀疏注意力與快取機制在單 GPU 環境下反覆試驗不同鏡頭與動作。

4. **教育與培訓素材製作**  
   根據課程腳本自動生成示範動畫或流程說明影片，適合需要多語言、多版本內容的企業內訓或線上課程平台。

5. **即時直播與虛擬製作輔助**  
   雖然目前尚難做到真正的 frame-by-frame 即時串流，但可在預製階段快速生成 B-roll、轉場或背景循環影片，並與現有剪輯工具整合。

## 實作前置條件

- **資料準備**  
  需要大規模、版權清晰且經過結構化描述（structured captioning）的影片–文字配對資料。論文強調多來源資料策展、低解析度到高解析度的課程式訓練、自我蒸餾與偏好後訓練（DPO / ReFL），因此產品化時至少需準備數百萬筆高品質配對，並建立清洗與去重管線。

- **運算資源**  
  5B 模型可在單張 H100 進行高效推理；14B 模型與 384×B200 規模的訓練則需要多節點 GPU 叢集。若要走完整 from-scratch 訓練，需準備數十到數百張 H100 / B200 等級的加速器，以及高速儲存與網路。

- **技術能力**  
  團隊需熟悉影片擴散 Transformer（Video DiT）、flow matching、線性注意力與 softmax 注意力的實作差異，並具備 CUDA kernel fusion、量化（MXFP4／MXFP8）與分散式訓練經驗。產品化時還需具備 VAE（LTX-VAE 2.3）、文字編碼器（Gemma-2-2B-IT）整合與推理引擎部署能力。

## 實作步驟建議

1. **需求對焦與解析度選擇**  
   先決定目標解析度與長度（例如 480p/5s 或 720p/60s）。若追求極致延遲，優先採用 5B 模型；若追求最高品質，則評估 14B 模型。

2. **建立資料與標註管線**  
   建構影片收集、去重、過濾與結構化描述生成流程。可先用降解析度代理研究（reduced-resolution proxy studies）驗證資料品質與訓練策略，再放大到完整解析度。

3. **選擇混合注意力配置**  
   論文建議 25% softmax 錨點（3:1 比例）作為品質–效率甜蜜點。實作時以此為起點，並根據目標任務微調錨點深度與 AttnRes 路由設定。

4. **From-scratch 訓練**  
   不要採用事後線性化預訓練 softmax 模型，而是直接從頭訓練混合線性–softmax 骨幹。依序執行低解析度預訓練、高解析度與長影片課程學習、自我蒸餾，最後進行 DPO / ReFL 偏好後訓練。

5. **推理優化與部署**  
   整合 Sol-Engine 進行核心融合、快取與稀疏注意力優化，並搭配 MXFP4 權重與 MXFP8 活化量化。在 H100 或 B200 上進行端對端延遲與 VBench 品質評測。

6. **產品介面與後製整合**  
   將模型包裝成 API 或插件，輸出潛在詞元後接 VAE 解碼，再匯入剪輯工具進行後製、配音與合規審查。

## 潛在風險與注意事項

- **品質與效率的權衡**  
   雖然 25% softmax 在論文中是最佳平衡點，但特定場景（如精細人臉表情或複雜物理運動）可能需要更多 softmax 錨點，需透過代理實驗驗證。

- **長影片的一致性**  
   線性注意力雖具 O(N) 擴展性，但長序列仍可能出現動作漂移或場景不一致。建議搭配分鏡腳本、關鍵影格條件或後製拼接來提升長影片穩定度。

- **版權與倫理風險**  
   訓練資料必須具備合法授權，並建立內容過濾與浮水印機制，避免生成侵權、深偽或不當內容。

- **硬體相依性**  
   Sol-Engine 的最佳效能高度依賴 H100 / B200 與特定 kernel 實作。若部署於其他硬體，需重新評估延遲與量化相容性。

- **AttnRes 路由調校**  
   跨層共享 routing queries 雖可簡化設計，但若任務與論文預設差異過大，可能需要重新驗證 AttnRes 對有效秩與收斂的影響。

## 與其他技術的整合建議

- **與現有剪輯軟體整合**  
   將 SANA-Video 2.0 作為背景生成或 B-roll 產生模組，透過 API 輸出標準影片格式，再匯入 Premiere、DaVinci Resolve 或 Final Cut Pro 進行剪輯。

- **與 LLM 腳本生成管線結合**  
   先由大型語言模型將使用者需求轉為結構化描述（structured caption），再餵入 SANA-Video 2.0，形成「文字腳本 → 影片」全自動管線。

- **與即時互動系統搭配**  
   雖然目前尚非即時，但可將生成結果預先快取為素材庫，供遊戲引擎（Unity / Unreal）或直播軟體在執行期呼叫。

- **與多模態模型協作**  
   結合圖像生成模型（如 FLUX、SDXL）產生首幀或關鍵影格，再以 SANA-Video 2.0 進行影片化，提升視覺一致性與可控性。

- **與企業 MLOps 平台整合**  
   將訓練、微調與推理流程納入 Kubernetes / Triton / vLLM 風格的部署架構，並監控 VBench 分數、延遲與 GPU 使用率。

## 給不同背景讀者的閱讀建議

- **初學者**  
   建議先聚焦「為什麼需要混合注意力」與「實際能做多快」：理解傳統 softmax 的 O(N²) 成本會讓長影片變慢，而 SANA-Video 2.0 透過大部分線性注意力加少量 softmax 錨點，在單張 GPU 上做到 720p 影片生成。可略過公式細節，直接看適用場景與效能數字。

- **AI 工程師**  
   重點閱讀 Hybrid Linear-Softmax Attention、Block Attention Residuals 與 Sol-Engine 優化章節，並關注 from-scratch 訓練管線、LTX-VAE 2.3 與 Gemma-2-2B-IT 的整合方式。實作時建議先復現 5B 模型的推理流程，再評估 14B 與量化部署。

- **研究人員**  
   建議深入分析有效秩（effective rank）、注意力殘差路由與 3:1 錨點比例的理論基礎，並思考如何將此混合設計推廣到更長影片、因果生成或多模態模型。論文提供的降解析度代理研究方法與訓練配方也值得作為後續研究的基線。

- **產品經理**  
   請優先掌握「品質 vs. 延遲」的商業權衡：VBench 84.30、13.2 秒生成 480p 影片、720p/5s 僅 13.06 秒等關鍵數字。接著評估資料取得成本、授權風險、硬體需求與後製整合難度，以決定是自建模型、微調開源權重，或採用 API 優先的產品策略。
