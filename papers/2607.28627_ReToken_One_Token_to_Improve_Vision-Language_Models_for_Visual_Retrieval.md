## ⚡ TL;DR

長視覺上下文中的干擾項使視覺語言模型難以檢索相關標記，且全量推理受GPU記憶體限制。
本文提出ReToken，將單一可學習嵌入附加於問題作為檢索目標，在值空間中對視覺KV快取做稀疏選取。
僅以影像問答訓練，在VisualHaystacks與LVBench上顯著提升，H100可推論長影片。

## 摘要翻譯

長視覺上下文（Long Visual Context）為視覺語言模型（Vision-Language Models, VLMs）帶來挑戰：隨著干擾項（Distractors）數量增加，模型效能隨之下降，且在 GPU 記憶體限制（GPU Memory Constraints）下，同時處理所有標記（Tokens）在計算上並不可行。我們提出 ReToken，這是一個以明確檢索目標（Explicit Retrieval Target）訓練而成的單一可學習嵌入（Single Learnable Embedding），能從預填充（Pre-filled）的視覺 KV 快取（Visual KV Cache）中，選取由與查詢相關的視覺標記（Query-relevant Visual Tokens）所組成的稀疏集合（Sparse Set）。ReToken 僅以小型影像問答（Image-QA）資料集訓練，便在影像與影片的各項基準測試（Benchmarks）中帶來一致的增益（Consistent Gains）：在 Visual Haystacks 上，它使 Qwen3VL-8B 提升 13.4 個百分點、InternVL3.5 提升 12.4 個百分點（相對增益（Relative Gain）超過 20%）；在 LVBench 上，它可零樣本（Zero-shot）轉移至長影片理解（Long-video Understanding）任務，使 Qwen3VL-8B 獲得 8.0 個百分點的增益。由於其輕量化設計（Lightweight Design），訓練與長影片推論皆可在單張 H100 上完成。程式碼可於以下網址取得：https://github.com/avaxiao/ReToken

### 核心貢獻（3～5點）
- 提出 ReToken，以單一可學習嵌入作為明確檢索目標，從預填充的視覺 KV 快取中選取與查詢相關的稀疏視覺標記集合。
- 僅以小型影像問答資料集訓練，便在多影像與長影片基準測試上帶來一致且顯著的效能增益。
- 展現強大的零樣本遷移能力：從影像問答訓練直接轉移至長影片理解任務（如 LVBench）。
- 具備輕量化設計，訓練與長影片推論皆可在單張 H100 GPU 上完成，兼顧效能與硬體可行性。

### 適合對象
本論文適合從事視覺語言模型、長上下文理解、視覺檢索與高效能推論的研究者與工程師；特別是關注多影像問答（Multi-image QA）、長影片理解（Long-video Understanding）、視覺 KV 快取壓縮，以及如何在有限 GPU 記憶體下擴展視覺語言模型應用的讀者。

## 深度分析

#### 方法論解析

##### 1. 問題設定與核心觀察

ReToken 處理的是**長視覺上下文（long visual context）**下的檢索問題：當輸入包含大量影像或長影片時，VLM（視覺語言模型）必須從眾多**視覺標記（visual tokens）**中找出與問題真正相關的少數證據，同時避免被**干擾項（distractors）**淹沒。作者首先指出，直接沿用 NLP 中常見的**注意力訊號（attention signals）**——即以 query 與 key 的相似度作為檢索依據——在 VLM 中並不可靠。在 QAEgo4D 上，基於注意力的檢索器（attention-based retriever）對 Qwen3VL-8B 的平均 **Recall@1（前 1 召回率）**僅有 5.1%，顯示文字與視覺特徵間的注意力權重與真實相關性之間的相關性（correlation）很弱。

相對地，作者發現一個非對稱現象：將一個精確的目標片語與**值投影（value projections）**的平均向量比對，而非與 key 比對，在受控雙影像設定（controlled two-image setting）中能把 Qwen3VL 的 Recall@1 從 65.7 提升到 78.0，InternVL3.5 則從 78.8 提升到 83.8。這暗示 **value 空間**比 **query-key 空間**更適合承載「以文字為基礎的視覺檢索」所需資訊，因為 value 正是經注意力傳播的內容（content propagated through attention）。然而，單純對所有**問題標記（question tokens）**做 value-value pooling 會引入雜訊（noise），導致優勢被逆轉。因此，需要一個更穩定、專門化、且能動態對齊問題語意的檢索目標。

##### 2. ReToken 的設計

ReToken 的核心是一個**單一可學習嵌入（single learnable embedding）**，在推論時被附加到問題文字之後，作為**明確檢索目標（explicit retrieval target）**。整體流程可分為三個階段：

1. **預填充視覺 KV 快取（pre-filled visual KV cache）**：  
   所有影格（frames）的視覺特徵先被編碼並存入 KV cache，避免每次檢索都重新計算視覺編碼器。

2. **第一階段前向傳播產生 ReToken**：  
   將問題文字與可學習的 ReToken 一起輸入已凍結的 VLM。ReToken 在模型最後一層（final layer）產生一個輸出表示，再經由一個額外的**投影矩陣（projection matrix）**映射到與視覺 value 相同維度的空間。

3. **Value 空間檢索**：  
   對每一個影格，計算其**平均 value 向量（mean value vector）**與投影後的 ReToken 嵌入之間的**餘弦相似度（cosine similarity）**。根據相似度排序，選出前 K 個最相關的影格，形成**稀疏集合（sparse set）**，再將這些影格的視覺標記送入 VLM 進行最終答案生成。

##### 3. 訓練目標與參數規模

ReToken 使用**類別平衡二元交叉熵損失（class-balanced binary cross-entropy loss）**，以真實相關性標籤（ground-truth relevance labels）監督每一影格是否與問題相關。這是一個純粹的**檢索損失（retrieval loss）**，而非生成損失，因此 ReToken 被明確訓練成「檢索目標」而非「答案生成輔助標記」。

整個方法僅新增兩組參數：
- 一個可學習的 ReToken 嵌入；
- 一個將 ReToken 輸出投影到 value 空間的投影矩陣。

VLM 本身預設為**凍結的視覺語言模型（frozen VLM）**，因此訓練成本極低，且能輕易遷移到不同架構的預訓練模型。這種**輕量化設計（lightweight design）**使得整個訓練與長影片推論都能在一張 H100 GPU 上完成。

##### 4. 方法論上的關鍵創新

與傳統「先由外部檢索器選圖、再由 VLM 重新編碼」的兩階段流程不同，ReToken 直接在 VLM 內部運作，並利用已預填充的視覺 KV cache，避免重複編碼。與 Q-Former、Perceiver Resampler 等學習標記方法相比，ReToken 的差異在於：
- **動態性**：ReToken 由問題文字動態生成，不是靜態、與查詢無關（query-agnostic）的軟提示（soft prompts）。
- **監督訊號**：直接以檢索損失監督最終層 value 向量，而非以對齊或生成損失訓練視覺壓縮器。
- **容量**：僅需**單一標記（single token）**，而非 32–64 個學習標記。

#### 實驗數據解讀

##### 1. 主要基準測試（benchmarks）與結果

論文報告了兩大類實驗：多影像問答（multi-image QA）與長影片理解（long-video understanding）。

| 基準測試 | 模型 | ReToken 提升 | 意義 |
|---|---|---|---|
| Visual Haystacks | Qwen3VL-8B | +13.4 分 | 絕對與相對增益均顯著 |
| Visual Haystacks | InternVL3.5 | +12.4 分 | 跨架構一致性 |
| LVBench | Qwen3VL-8B | +8.0 分 | 零樣本（zero-shot）遷移至長影片 |

Visual Haystacks 是專為長視覺上下文設計的**多影像問答**基準，測試模型在大量干擾影像中定位證據的能力。ReToken 在兩種不同 VLM 架構上都帶來超過 12 分的提升，相對增益超過 20%，顯示方法對於「影像集合」這類靜態長視覺上下文具有強健的泛化能力。

LVBench 則是長達數小時影片的問答基準，平均影片長度超過一小時。值得注意的是，ReToken 僅在影像問答資料上訓練，卻能**零樣本遷移**到長影片任務，並帶來 8.0 分的提升。這說明 ReToken 學到的並非特定於影像集合的捷徑，而是某種更通用的「文字-視覺相關性」表示，能夠跨靜態影像與動態影片兩種模態運作。

##### 2. 診斷性實驗的意義

論文中受控雙影像設定的實驗雖然數字較小，卻是方法論的基石：
- **Query-key vs. value**：value 空間比 query-key 空間更適合視覺檢索，這挑戰了「注意力權重即相關性」的直覺。
- **平均問題標記的雜訊**：單純對所有 question tokens 做 pooling 會引入雜訊，凸顯了學習一個專門檢索目標的必要性。
- **QAEgo4D 的 Recall@1 僅 5.1%**：進一步證明現成 VLM 的注意力並非可靠的檢索訊號。

這些診斷結果意味著，ReToken 的增益並非來自更強大的生成模型，而是來自「更準確地選出相關視覺內容」。在長視覺上下文中，瓶頸往往不在答案生成，而在檢索品質；ReToken 直接針對這個瓶頸。

##### 3. 效率與實用性

作者強調 ReToken 的**資源佔用（footprint）**極小：訓練與長影片推論皆可在一張 H100 上完成。這在實務上非常重要，因為長影片的 full-context inference 通常因 GPU 記憶體限制（GPU memory constraints）而無法進行。透過預填充視覺 KV cache 並只選取稀疏集合，ReToken 同時解決了「準確性」與「可擴展性」兩個問題。

##### 4. 結果的潛在限制

雖然數據亮眼，但論文目前主要展示的是 Qwen3VL-8B 與 InternVL3.5 兩個模型。對於更大規模（例如 30B 以上）或不同視覺編碼器架構的 VLM，ReToken 是否仍能保持類似增益，仍需更多實驗驗證。此外，Visual Haystacks 與 LVBench 的任務型態仍以問答為主，對於需要細粒度定位或跨影格時序推理的任務，ReToken 的價值空間相似度是否足夠，也值得進一步探討。

#### 與現有研究的比較

##### 1. 與外部視覺檢索器的比較

傳統視覺檢索多依賴雙編碼器（dual encoders）如 CLIP、Perception Encoder、SigLIP2，或將 VLM 改裝為通用嵌入模型如 E5-V、LamRA。這些方法雖然有效，但屬於「外部檢索器」：必須先選出相關影像，再重新由 VLM 編碼生成答案。ReToken 的優勢在於：
- **單一模型、單一表示空間**：檢索與生成共享同一個 VLM 的 value 空間，避免外部嵌入器與 VLM 之間的表示落差。
- **無需重新編碼**：利用預填充視覺 KV cache，選出的影格可直接用於後續生成，降低延遲與計算成本。

##### 2. 與長影片 QA 的 localizer-answerer 架構比較

SeViLA、VideoAgent、VideoTree 等研究採用「先定位、再回答」的兩階段或代理式流程。這些方法通常需要額外的 captioning、物件偵測或迭代式檢索模組，系統複雜度較高。ReToken 則將檢索目標內化為一個可學習標記，流程更簡潔，且不需要針對影片任務額外設計代理策略。

##### 3. 與注意力式上下文選擇的比較

InfLLM、EM-LLM、ReKV 等研究在 NLP 或視覺領域使用 query-key 注意力來選擇 KV block。ReToken 與這些方法的根本差異在於檢索空間：ReKV 直接將 NLP 機制搬到視覺領域，但作者證明 VLM 的 query-key 注意力與真實相關性相關性很弱；ReToken 改在 value 空間進行檢索，並透過學習標記提供更穩定的目標表示。

##### 4. 與記憶體 / 標記壓縮方法的比較

MovieChat、MA-LMM、Chat-UniVi、LLaMA-VID、LongVU、Video-XL 等方法透過固定大小記憶體或壓縮視覺標記來處理長輸入。這些方法通常**與查詢無關（query-agnostic）**，即不論問題為何，都對所有視覺內容做相同壓縮。ReToken 則是**查詢相關（query-relevant）**的稀疏選擇，能保留更細緻的證據，特別適合需要精確定位的問答任務。

##### 5. 與其他可學習視覺聚合標記的比較

Q-Former、Perceiver Resampler、InstructBLIP 使用數十個學習標記將視覺特徵壓縮成固定表示；Video-XL 的視覺摘要標記（visual summarization token）則將一塊視覺 KV 壓縮成單一標記。ReToken 與它們的區別可歸納為：

| 面向 | Q-Former / Perceiver / Video-XL | ReToken |
|---|---|---|
| 機制 | 靜態軟提示或視覺壓縮 | 由問題動態生成的檢索目標 |
| 監督 | 對齊或生成損失 | 明確檢索損失，直接對 value 向量監督 |
| 容量 | 32–64 個標記 | 單一標記 |
| 目的 | 視覺壓縮與對齊 | 選取相關視覺內容 |

##### 6. 限制與未解決的挑戰

儘管 ReToken 在設計上簡潔有效，仍有幾個相對於現有研究的限制：
- **僅針對影格層級檢索**：目前方法以影格為單位選取稀疏集合，對於需要更細粒度 token-level 檢索的任務（例如小物件定位），可能還需要進一步擴展。
- **依賴最終層 value**：作者使用最終層 value 向量作為檢索表示，雖然實證有效，但是否存在更優的中間層組合或跨層 value 聚合，仍有探索空間。
- **訓練資料規模小**：ReToken 僅在小型影像問答資料上訓練，雖然展現了零樣本遷移能力，但在更大規模、更多樣化的檢索資料上訓練，可能進一步提升泛化性。

#### 可重現性評估

##### 1. 程式碼開放程度

論文明確指出程式碼已公開於 GitHub：`https://github.com/avaxiao/ReToken`。這為重現提供了基礎，包括 ReToken 的訓練流程、檢索邏輯與推論腳本。然而，從摘要與內文無法判斷倉庫是否已包含預訓練的 ReToken 權重、完整的資料前處理流程、以及各基準測試的評估腳本。理想的可重現性應包含：
- 訓練資料的下載與處理說明；
- 各模型（Qwen3VL-8B、InternVL3.5）對應的 ReToken 檢查點；
- 在 Visual Haystacks、LVBench、QAEgo4D 上的評估指令；
- 環境相依性與 H100 上的記憶體配置建議。

##### 2. 資料集與模型可取得性

- **Visual Haystacks**：已公開的長視覺上下文基準，用於多影像問答。
- **LVBench**：長影片理解基準，平均影片長度超過一小時。
- **QAEgo4D**：第一人稱視角影片問答資料集，用於診斷注意力式檢索。
- **Qwen3VL-8B、InternVL3.5**：均為開源 VLM，可透過 Hugging Face 等管道取得。

由於基礎模型與主要評估資料集皆已公開，重現的主要門檻在於 ReToken 的實作細節與訓練超參數。若 GitHub 倉庫提供完整腳本，則重現難度相對低。

##### 3. 計算資源門檻

作者強調訓練與長影片推論皆可在一張 H100 上完成，這對學術界與中小型研究團隊相當友善。相較於需要多卡訓練或大型叢集的方法，ReToken 的硬體門檻較低，有利於後續研究者進行擴展與比較。

##### 4. 可重現性建議

為進一步提升可重現性，建議作者補充：
- ReToken 嵌入與投影矩陣的初始化方式；
- 類別平衡二元交叉熵損失中的正負樣本權重設定；
- 影格選取數量 K 對效能與記憶體的影響曲線；
- 不同層數 value 向量的消融實驗細節。

#### 未來研究方向

##### 1. 擴展至更細粒度的 Token-level 檢索

目前 ReToken 以影格為單位進行選擇，未來可探索直接在 token-level 上計算 value 空間相似度，讓模型能夠在單一影格內進一步篩選與問題相關的區域或物件，適用於需要精細空間定位的任務。

##### 2. 跨層與多尺度 Value 聚合

論文使用最終層 value 向量作為檢索依據。後續研究可探討：
- 結合多層 value 表示，捕捉低階視覺特徵與高階語意；
- 引入多尺度影格取樣（例如關鍵影格與密集影格混合），在效率與準確性間取得更好平衡。

##### 3. 與生成任務的聯合訓練

ReToken 目前以純檢索損失訓練，VLM 保持凍結。未來可嘗試將檢索損失與答案生成損失結合，進行端到端微調，讓檢索目標與生成目標相互適應，可能進一步提升最終問答正確率。

##### 4. 線上串流與動態 KV Cache 管理

ReToken 已利用預填充視覺 KV cache 提升效率。未來可將其擴展到串流場景：隨著影片持續輸入，動態決定哪些影格應保留、哪些可淘汰，並結合 ReToken 的相關性分數進行**可擴展的長上下文（scalable long-context）**管理。

##### 5. 多模態與多語言擴展

ReToken 的設計原則可應用於其他模態，例如音訊、3D 點雲或文件圖像；也可探討其在多語言問題下的穩定性，以及是否需要針對不同語言學習不同的檢索目標。

##### 6. 理論理解與可解釋性

為何 value 空間比 query-key 空間更適合視覺檢索？這背後可能涉及 VLM 預訓練時視覺-文字對齊的幾何結構。未來可從表示學習與注意力機制的角度進行理論分析，並發展可視化工具來解釋 ReToken 選取特定影格的依據。

##### 7. 與代理式流程的結合

VideoAgent、VideoTree 等代理式方法透過迭代式檢索與 captioning 提升長影片理解。ReToken 可作為這些代理系統中的「快速初篩模組」，先以低成本選出高相關影格，再由代理進行深度分析，形成更強大且高效的混合架構。

## 論文問答

**Q1：ReToken 主要想解決視覺語言模型在什麼情境下的問題？**

A：ReToken 主要針對長視覺上下文（long visual context）帶來的挑戰，例如同時輸入大量影像集合或長達數小時的影片。在這些情境中，只有少數影格或影像與使用者的問題真正相關，其餘都是干擾項（distractors），導致模型效能隨著無關內容增加而下降。此外，一次性處理所有視覺標記會超出 GPU 記憶體限制，因此如何從中稀疏地檢索出與查詢相關的視覺內容，成為一個關鍵的檢索問題。

**Q2：為什麼現有的基於注意力（attention-based）檢索方法在視覺語言模型中效果不佳？**

A：論文發現，在視覺語言模型中，文字與視覺特徵之間的注意力權重與實際相關性之間的關聯很弱。以 Qwen3VL-8B 在 QAEgo4D 上的實驗為例，基於注意力的檢索器在不同層的平均 Recall@1 僅有 5.1%，顯示其訊號相當不可靠。這與大型語言模型在文字處理上能透過長上下文訓練產生選擇性注意力的情況形成對比，因此需要尋找更穩定的檢索訊號。

**Q3：為什麼長視覺上下文檢索對視覺語言模型的發展很重要？**

A：隨著模型能處理的輸入長度增加，影像集合與小時級影片已經成為實際應用中的常見輸入形式。如果模型無法在這些長視覺上下文中準確定位相關證據，就會被大量干擾項淹沒，導致問答或推理效能大幅下降。因此，發展有效的視覺檢索機制是讓視覺語言模型能夠擴展到真實世界長上下文多模態任務的關鍵一步。

**Q4：ReToken 的核心方法是什麼？**

A：ReToken 引入了一個單一的可學習嵌入（single learnable embedding），將它附加在問題文字之後，並作為明確的檢索目標（explicit retrieval target）進行訓練。這個標記會與視覺 KV 快取中每一個影格的最終層平均 value 向量進行餘弦相似度比對，從而選出與查詢最相關的少數視覺標記。整個過程中，底層的視覺語言模型權重預設是凍結的，只更新 ReToken 本身與一個投影矩陣，因此參數量極小。

**Q5：ReToken 與先前視覺檢索方法的主要創新差異是什麼？**

A：與傳統外部檢索器（如 CLIP 或 E5-V）需要先選出影像再重新編碼不同，ReToken 直接在預填充的視覺 KV 快取中進行檢索，統一了檢索與生成過程。相較於 Q-Former 等使用數十個可學習標記作為靜態視覺壓縮器的方法，ReToken 只用一個動態生成的標記，並透過明確的檢索損失進行監督。更重要的是，它發現 value 空間比傳統 query-key 空間更適合進行文字導向的視覺檢索，這是方法設計上的核心洞見。

**Q6：為什麼 ReToken 選擇在 value 空間進行檢索，而不是傳統的 query-key 空間？**

A：論文在受控雙影像實驗中發現，將精確的目標片語與平均視覺 value 投影進行比對，能將 Qwen3VL 的 Recall@1 從 65.7 提升到 78.0，顯示 value 空間攜帶了更適合文字檢索的內容訊號。這是因為 value 向量承載了實際透過注意力機制傳播的內容，而 key 空間則更偏向於計算注意力權重本身。然而，簡單對問題標記做 value-value 池化會引入雜訊，因此 ReToken 透過一個可學習的單一標記來學出穩定的檢索目標，避免直接平均問題標記所帶來的噪音。

**Q7：ReToken 在哪些基準測試上進行評估，主要結果為何？**

A：ReToken 在 Visual Haystacks 與 LVBench 等長視覺上下文基準上進行評估。在 Visual Haystacks 上，它讓 Qwen3VL-8B 提升 13.4 分、InternVL3.5 提升 12.4 分，相對增益超過 20%。在 LVBench 這個平均影片長度超過一小時的長影片理解任務上，ReToken 僅用多影像問答資料訓練後零樣本轉移，就讓 Qwen3VL-8B 獲得 8.0 分的提升。

**Q8：有哪些控制實驗或消融研究支持 ReToken 的設計選擇？**

A：論文首先在雙影像設定中比較了 query-key 與 value-value 檢索策略，證明 value 空間在精確目標片語比對下表現更好。此外，研究也顯示若直接對所有問題標記做平均會引入雜訊，反而抵消 value 空間的優勢，這說明了使用單一可學習檢索標記的必要性。最後，ReToken 僅增加一個標記與一個投影矩陣，就能在凍結視覺語言模型的情況下達成顯著增益，證明其輕量化設計的有效性。

**Q9：ReToken 為何能從多影像問答任務零樣本轉移到長影片理解任務？**

A：ReToken 學到的是一種通用的「查詢—視覺相關性」檢索訊號，而非特定於影像或影片任務的表面特徵。由於影像集合與長影片在本質上都可以被視為一連串視覺影格的序列，檢索目標在 value 空間中學到的相關性判斷能力可以跨模態遷移。這項結果顯示，即使只在相對小規模的多影像問答資料上訓練，ReToken 也能捕捉到可擴展的長上下文多模態推理模式。

**Q10：ReToken 在實際應用場景中可能發揮什麼作用？**

A：ReToken 可應用於需要從大量視覺資料中快速定位證據的場景，例如監控影片分析、醫學影像批次檢閱、法律或新聞影像資料庫搜尋等。在這些應用中，使用者通常提出具體問題，而系統必須從數百甚至數千個影格中找出關鍵畫面。透過 ReToken，視覺語言模型可以在不重新編碼整段影片的情況下，直接從預填充的視覺 KV 快取中檢索相關內容，大幅提升推理效率。

**Q11：從產品與工程部署的角度，ReToken 有哪些優勢與考量？**

A：ReToken 的輕量化設計使其訓練與長影片推論都能在一張 H100 GPU 上完成，這對於資源有限的產品團隊來說非常具有吸引力。由於底層視覺語言模型可以凍結，企業無需對大型模型進行昂貴的全參數微調，只需訓練一個標記與投影矩陣即可。不過，在實際部署時仍需考慮預填充視覺 KV 快取的儲存成本、檢索標記與不同模型架構的相容性，以及檢索結果的可解釋性與錯誤追溯機制。

**Q12：ReToken 對視覺語言模型研究領域可能帶來什麼影響？**

A：ReToken 提供了一個實用且可擴展的長上下文多模態推理途徑，顯示單一可學習標記就能顯著改善預訓練視覺語言模型的檢索能力。它也挑戰了傳統上以 query-key 注意力作為檢索訊號的慣例，將研究焦點轉向 value 空間的潛力。未來這類輕量級、可插拔的檢索模組可能成為長視覺上下文系統的標準元件，推動更多低成本、高效率的多模態應用發展。

**Q13：ReToken 目前有哪些可能的限制？**

A：ReToken 的效能仍然受限於底層視覺語言模型本身的表現，如果模型對某些視覺概念的理解不足，檢索標記也難以彌補。此外，雖然訓練資料需求相對較小，但仍需要具備真實相關性標籤的影像問答資料進行監督。論文也尚未深入探討 ReToken 在極端長度、多語言提示或高度開放式生成任務中的穩定性與泛化能力。

**Q14：ReToken 在哪些情況下可能會失敗？**

A：當問題需要綜合多個分散影格的資訊才能回答時，僅選取 top-K 相關影格的稀疏檢索策略可能會遺失關鍵上下文。此外，如果視覺內容與文字問題之間的關聯非常隱晦或需要高階推理，value 空間的相似度分數可能無法準確捕捉。還有一種可能是，當訓練資料中的相關性標籤本身有偏誤或定義不清時，ReToken 會學到錯誤的檢索目標，進而影響下游問答表現。

**Q15：未來可以朝哪些方向延伸 ReToken 的研究？**

A：未來可以探索將 ReToken 擴展到多模態檢索以外的任務，例如長文件中的圖表定位、多輪對話中的視覺記憶管理等。也可以研究如何讓 ReToken 與不同架構的視覺語言模型更緊密整合，或結合外部記憶機制以支援更長的輸入序列。另一個值得探索的方向是發展無監督或弱監督的訓練方式，減少對真實相關性標籤的依賴，使這類檢索標記能更容易應用到各種領域。

## 實務應用指南

### 適用場景

1. **長影片問答與內容稽核**：處理數小時的監控錄影、會議記錄或直播存檔，讓使用者用自然語言詢問「第三小時有誰進入實驗室」，ReToken 可先從預填充的視覺 KV 快取中檢索出關鍵影格，再由 VLM 生成答案，避免一次性載入全部影格。
2. **多影像資料庫檢索**：在電商、設計或醫學影像庫中，面對數十到數百張候選圖片，ReToken 可依問題挑選與查詢相關的少數影像，例如「找出所有紅色皮革沙發的正面圖」，提升多影像問答準確度。
3. **長文件與圖表理解**：將掃描文件、簡報或論文頁面視為一連串視覺標記，ReToken 可針對問題檢索相關頁面或圖表區域，輔助財報分析、法律文件審閱或學術文獻問答。
4. **第一人稱視角影片助理**：應用於 Egocentric 影片（如 QA Ego4D），協助使用者從長時間穿戴裝置錄影中定位「我在哪個時段把鑰匙放在桌上」等事件。
5. **互動式教育與培訓**：在長篇教學影片或操作手冊影像集中，根據學生提問動態檢索對應示範片段，實現個人化學習路徑。

### 實作前置條件

- **資料**：需要一個多影像問答資料集，並且每筆樣本需標註「哪些影像／影格與問題相關」的真實相關性標籤。論文使用小型影像問答資料集即可訓練，因此資料量不必極大，但標註品質會直接影響檢索目標的學習效果。
- **運算資源**：訓練與長影片推論可在單張 NVIDIA H100 上完成。若使用較小模型或較短影片，也可嘗試 A100 等級 GPU，但需確認視覺 KV 快取能完整放入 GPU 記憶體。
- **基礎模型**：需支援視覺 KV 快取預填充的視覺語言模型，例如 Qwen3VL-8B 或 InternVL3.5。論文採用 decoder-only 架構的 VLM。
- **技術能力**：熟悉 PyTorch、Transformer 注意力機制、KV cache 管理；具備視覺語言模型微調經驗；能處理類別不平衡損失與餘弦相似度檢索邏輯。

### 實作步驟建議

1. **選定基礎 VLM 並凍結權重**：以 Qwen3VL-8B 或 InternVL3.5 為起點，預設凍結整個視覺語言模型，只新增 ReToken 嵌入與一個投影矩陣。
2. **建立視覺 KV 快取**：對所有候選影像或影片影格預先通過 VLM 的視覺編碼器與前幾層，計算並儲存每個影格的 value 向量，形成預填充視覺 KV 快取。
3. **實作 ReToken 模組**：新增一個可學習的標記嵌入，將其附加在問題標記之後；再透過一個投影矩陣將該嵌入映射到 value 空間。推論時，用第一階段前向傳播產生 ReToken 的輸出表示。
4. **計算檢索分數**：對每個影格，將投影後的 ReToken 嵌入與該影格在最後一層的平均 value 向量做餘弦相似度，作為該影格的相關分數。
5. **訓練檢索目標**：使用類別平衡二元交叉熵損失，以真實相關性標籤監督每個影格的分數。只更新 ReToken 嵌入與投影矩陣。
6. **稀疏檢索與生成**：推論時先選出 top-K 相關影格，只將這些影格的視覺標記送入 VLM 進行第二階段生成，達到節省記憶體與加速的目的。
7. **評估與迭代**：在 Visual Haystacks、LVBench 或自製資料上評估 Recall@1 與最終問答準確度；若轉移到長影片出現分佈偏移，可補充少量影片標註進行微調。

### 潛在風險與注意事項

- **標註成本與品質**：ReToken 依賴明確的影格級相關標籤，若標註模糊或遺漏關鍵影格，檢索目標會學偏。建議採用多輪標註與一致性檢查，並使用類別平衡損失緩解正負樣本不平衡。
- **兩階段推論延遲**：雖然 ReToken 輕量，但仍需先做一次前向傳播取得檢索分數，再做第二次生成。對即時性要求高的場景，可將 KV 快取常駐 GPU、使用非同步預取，或限制候選影格數量。
- **分佈偏移**：論文顯示僅用多影像 QA 訓練即可零樣本轉移到長影片，但不同領域（如醫學影像、監控畫面）的視覺分佈可能差異極大，建議在目標領域上進行少量微調或對抗式驗證。
- **檢索遺漏導致幻覺**：若 ReToken 漏掉真正關鍵的影格，後續生成模型可能憑藉語言先驗產生錯誤答案。可結合 top-K 擴充、重排序（re-ranking）或讓模型在答案中標註所依據的影格，方便人工稽核。
- **Value 空間的模型相依性**：論文發現 value 空間比 query-key 空間更適合檢索，但這一結論基於特定模型。若更換 VLM，建議重新進行受控雙影像實驗，確認 value-based 檢索仍然有效。

### 與其他技術的整合建議

- **向量資料庫與索引**：可將預填充的視覺 KV 快取或影格級 value 向量存入向量資料庫（如 FAISS、Milvus），先以傳統 CLIP/SigLIP 嵌入做粗排縮小候選範圍，再用 ReToken 做精排，兼顧效率與準確度。
- **RAG 管線**：ReToken 可視為多模態 RAG 中的「視覺檢索器」。搭配 ASR、OCR 或物件偵測產生的輔助文字（如 Video-RAG），能進一步提升長影片問答的召回率。
- **串流影片處理**：對於持續輸入的直播或監控串流，可採用滑動視窗方式分批預填充 KV 快取，並讓 ReToken 動態選取最近期與歷史最相關的影格，避免記憶體無限增長。
- **現有 VLM 服務**：若已部署 Qwen3VL 或 InternVL 的 API，可將 ReToken 訓練為外掛模組，在不改動主模型權重的情況下，於請求層先執行檢索，再把篩選後的視覺內容送進既有生成服務。
- **快取與排程策略**：結合 KV cache 壓縮技術（如 token merging、量化）與 ReToken 的稀疏選擇，可進一步延長單張 GPU 能處理的影片長度。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先理解「視覺語言模型如何將影像變成標記」以及「注意力機制中的 query、key、value 各自代表什麼」，再聚焦論文的圖 1 與表 1，這些實驗清楚說明為何 value 空間比 attention 分數更適合做視覺檢索。不必一開始就深入數學推導，先掌握「加一個可學習標記來挑選關鍵影格」的核心概念即可。

- **AI 工程師**：重點閱讀第 3 節的方法與實作細節，特別是 ReToken 如何附加到問題標記、投影矩陣的設計、類別平衡二元交叉熵損失，以及兩階段推論的 KV cache 管理。建議直接參考作者釋出的程式碼，並在自有資料上重現 Visual Haystacks 的受控實驗，驗證 value-based 檢索在你的模型上是否同樣有效。

- **研究人員**：請關注論文的診斷性貢獻——為何預訓練 VLM 的 query-key attention 對視覺檢索不可靠，而 value 空間卻蘊含更強的相關性訊號。這裡有許多可延伸的方向，例如將 ReToken 擴展到多層 value 聚合、結合對比學習、或探討在不同視覺編碼器與架構下的泛化性。長影片零樣本轉移的結果也值得進一步分析其背後機制。

- **產品經理**：這篇論文提供了一個「輕量外掛即可顯著提升長視覺上下文表現」的實例。評估時請注意：它不需要重新訓練整個 VLM，只需少量標註資料與單張 H100，適合做為現有產品的增量功能。關鍵決策在於能否取得高品質的影格級相關標籤，以及你的應用場景是否能接受兩階段推論帶來的額外延遲。
