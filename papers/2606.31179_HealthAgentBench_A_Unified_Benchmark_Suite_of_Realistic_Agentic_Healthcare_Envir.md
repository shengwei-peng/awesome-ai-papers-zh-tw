## ⚡ TL;DR

現有醫療基準測試過於片段且靜態，難以評估前沿AI代理在複雜臨床工作流程上的真實能力。
本文提出HealthAgentBench，設計54項跨7類代理醫療任務，以終端環境評估全程臨床推理。
評測顯示前沿代理成功率偏低，最強模型Codex GPT-5.5僅約42%，醫學影像與組合推理是瓶頸。

## 摘要翻譯

隨著 AI 代理（AI agents）在複雜的長程推理（long-horizon reasoning）方面能力日益提升，嚴謹且全面的評估對於衡量其在真實世界醫療應用的進展至關重要。我們提出 HealthAgentBench，這是一套包含 54 項代理式醫療任務（agentic healthcare tasks）的基準測試套件（benchmark suite），橫跨 7 個類別，每個類別皆具備獨特的環境。此基準測試套件涵蓋病患就醫旅程（patient journey）中的多樣化臨床工作流程（clinical workflow），以及廣泛的模態（modalities）。每項任務皆設計為重現端對端臨床工作流程：僅給予極少指示下，代理必須探索原始醫療資料（raw healthcare data）、在複雜環境中運作，並執行無法僅靠簡易提示（naive prompting）完成的多步驟解決方案（multi-step solutions）。我們以最終任務成功率（task success rate）作為單一且可解釋的指標，衡量各代理在 HealthAgentBench 上的整體表現。在 HealthAgentBench 上評估前沿 AI 代理（frontier AI agents）後，我們發現整體任務成功率仍然偏低，凸顯了此套件的難度。最強且最具成本效益的代理 Codex GPT-5.5，其成功率僅約 42%。除了整體表現之外，HealthAgentBench 也揭示了不同任務類別間細微的優勢與劣勢。前沿 AI 代理在自動開發基於電子健康紀錄（EHR）資料的研究建模管線（research modeling pipelines）方面展現潛力，但醫學影像（medical imaging）仍然特別具有挑戰性，尤其對 Claude Code 模型（Claude Code models）而言，而 Codex GPT-5.5 則展現出初步能力。對於所有現有代理而言，結合大型搜尋空間（search spaces）與組合式推理（compositional reasoning）需求的任務仍然困難。綜合而言，這些結果顯示 HealthAgentBench 提供了一個具挑戰性且擬真的基準測試，未來仍有大幅進步空間。我們在 https://github.com/microsoft/HealthAgentBench 公開釋出此基準測試。

### 核心貢獻（3～5點）
- 提出 HealthAgentBench，一套包含 54 項任務、橫跨 7 個類別的統一基準測試套件，涵蓋病患就醫旅程中多樣化的臨床工作流程與廣泛模態，以評估代理在擬真醫療環境中的端對端表現。
- 設計需探索原始醫療資料、在複雜環境中運作，並執行多步驟解決方案的任務，超越簡易提示所能達成的範疇，以嚴謹衡量前沿 AI 代理的長程推理能力。
- 發現目前最強大的 Codex GPT-5.5 代理整體成功率僅約 42%，顯示現有前沿系統在真實醫療代理任務上仍有極大進步空間。
- 揭示不同任務類別的細微優劣勢：前沿代理在基於電子健康紀錄的研究建模管線展現潛力，但醫學影像與結合大型搜尋空間及組合式推理的任務對所有現有代理仍具高度挑戰性。
- 提供單一且可解釋的任務成功率指標，作為衡量各代理整體表現的標準化依據，並公開釋出基準以促進未來研究。

### 適合對象
從事醫療人工智慧、AI 代理系統、臨床決策支援與多模態醫療資料分析的學術研究者與工程師；特別適合關注長程推理、端對端臨床工作流程自動化，以及需要嚴謹評估前沿語言模型在真實醫療場域應用表現的跨領域團隊。

## 深度分析

#### 方法論解析

HealthAgentBench 的核心方法論在於建構一套統一的代理式醫療環境（agentic healthcare environments），以評估前沿 AI 代理（frontier AI agents）執行端對端醫療任務（end-to-end healthcare tasks）的能力。不同於傳統基準測試（benchmark）僅提供靜態輸入（static inputs）與固定上下文提示（fixed-context prompting），本研究設計了 54 項任務，橫跨 7 大類別，每一類別皆配置獨立的執行環境（execution environment）。

**任務設計原則與類別組成**
研究團隊依循系統化流程篩選任務，確保其具備真實性、挑戰性、可驗證性與多樣性。七大類別涵蓋病患就醫旅程（patient journey）中的關鍵階段：
1. **X-ray Report Correction（X 光報告校正）**：代理需檢視病患縱向胸部 X 光歷史與損毀的放射科報告（radiology reports），透過縮放、裁切影像並交叉比對先前研究（prior studies）以撰寫修正報告。
2. **Pathology Tumor Area Selection（病理腫瘤區域選取）**：在十億像素病理切片（gigapixel pathology slides）中定位腫瘤區域。
3. **CT Abnormality Classification（CT 異常分類）**：代理需探索 3D CT 容積資料（3D CT volumes），可能採取逐層檢視、安裝影像處理工具、預先篩選區域或裁切候選病灶等策略後進行預測。
4. **Clinical Trial Matching（臨床試驗配對）**：基於異質性臨床文件（heterogeneous clinical documents）與試驗方案（trial protocols）進行配對。
5. **EHR Data Quality Auditing（EHR 資料品質稽核）**
6. **EHR Event Modelling（EHR 事件建模）**：要求代理在縱向電子健康紀錄資料庫（longitudinal EHR databases）上自動開發研究建模管線（research modeling pipelines）。
7. **EHR Format Conversion（EHR 格式轉換）**

這些任務橫跨資料管理、診斷、研究與治療規劃，並涵蓋 2D 放射影像、3D 容積資料、全切片病理影像、自由文本與結構化臨床資料等多種模態（modalities）。

**環境架構**
每項任務皆封裝於 Docker 容器（Docker container）中，提供終端機環境（terminal-based environment）。代理僅獲得極簡指令與原始醫療資料（raw healthcare data），必須自主探索環境、規劃策略、呼叫工具並執行多步驟解決方案（multi-step solutions）。此設計刻意避免簡易提示（naive prompting）即可求解的捷徑，強制要求代理展現長程推理（long-horizon reasoning）、工具使用與環境互動能力。

**評估機制**
為達成跨任務的一致性比較，研究團隊建立統一的評估模組，針對每項任務定義明確的成功/失敗準則，對照人類表現或專家標籤（expert labels）。最終以單一的任務成功率（task success rate）作為 HealthAgentBench 整體表現的量化指標。此外，研究人員進行人工審查，確認所有成功準則皆為可達成（reachable），避免任務設計瑕疵導致評估偏差。

#### 實驗數據解讀

本研究對多個前沿系統（frontier systems）進行實證評估，結果顯示 HealthAgentBench 整體難度顯著高於傳統靜態基準，目前代理表現遠未達飽和。

**整體表現**
最強大的模型 Codex GPT-5.5 僅達到約 42% 的任務成功率（task success rate），且被視為最具成本效益（most cost effective）的解決方案。這項數據凸顯了代理式系統（agentic systems）在真實醫療場域中的能力缺口——即便是最先進的 LLM 代理（LLM agents），在面對需要多模態（multimodal）整合與長期規劃的臨床工作流程（clinical workflow）時，仍有超過一半的任務無法成功完成。

**類別差異與模型家族特性**
實驗數據揭示兩大瓶頸：
1. **醫學影像（medical imaging）任務**：CT、X 光與病理切片對所有模型皆具挑戰性，但不同模型家族呈現顯著差異。Claude Code 模型（Claude Code models）在醫學影像領域表現特別吃力，而 Codex GPT-5.5 則展現出新興能力（emerging capability），暗示程式碼生成與視覺空間推理之間可能存在正向遷移。
2. **大搜尋空間（large search spaces）與組合式推理（compositional reasoning）**：需同時探索廣泛解空間並進行多層次邏輯組合的任務，對目前所有代理而言皆極為困難。這類任務要求代理不僅要「看見」資料，更要「規劃」一系列相互依賴的操作步驟。

**相對優勢領域**
相對地，前沿代理在 EHR 事件建模（EHR Event Modelling）等結構化資料任務上展現較高潛力，特別是在自動開發研究建模管線（research modeling pipelines）方面。這可能歸因於 EHR 資料的表格化特性與代理在程式碼生成、資料處理上的既有優勢較為匹配。

#### 與現有研究的比較

**相對於傳統基準的典範轉移**
傳統醫療 AI 評測（如 MedQA）主要將大型語言模型（LLMs）視為孤立任務求解器（isolated task solvers），透過臨床病例摘要（clinical vignette）進行問答（question-answering）。這類評測仰賴靜態輸入（static inputs），且受限於上下文視窗（context window）長度，無法反映真實臨床工作中醫師必須整合病理切片、CT 掃描、放射科報告等多源異質資訊的決策過程。HealthAgentBench 的貢獻在於將評測典範從固定上下文提示（fixed-context prompting）轉移至端對端醫療任務（end-to-end healthcare tasks），要求代理直接操作原始醫療資料，而非僅回答預處理後的問題。

**相對於既有代理基準的擴展**
近期雖有代理導向的醫療評測問世，但多數仍侷限於特定任務、單一模態或預設工作流程（predefined workflows）。HealthAgentBench 則提供統一的基準測試套件（benchmark suite），橫跨病患就醫旅程（patient journey）中的多元階段與資料模態。這種整體性設計使研究者能夠在相同基準上比較不同代理的跨領域泛化能力，並識別特定臨床工作流程中的強項與弱點。

**侷限性**
儘管 HealthAgentBench 在範疇上大幅擴展，仍有若干限制值得討論。首先，目前評測主要聚焦於終端機環境（terminal-based environment）中的檔案與資料庫操作，尚未涵蓋圖形化臨床資訊系統（如 PACS 或 EHR 前端介面）的複雜互動。其次，54 項任務雖已涵蓋七大類別，但相對於真實醫療場域的無限多樣性，仍屬有限樣本；未來版本需持續擴充。此外，由於任務成功準則部分依賴專家標籤與人工審查，在極大規模自動化評測時可能面臨擴展性（scalability）挑戰。

#### 可重現性評估

**開源釋出與環境標準化**
研究團隊已將 HealthAgentBench 完整釋出於 GitHub，包含任務定義、Docker 容器（Docker container）環境設定與統一評估模組。這種標準化的容器化部署大幅降低環境設定的變異性，使其他研究者能夠在一致的執行環境（execution environment）中複現實驗結果。

**資料與模型權重的可取得性**
然而，可重現性面臨兩項挑戰。第一，本研究評測的對象多為商業化前沿模型，其模型權重（model weights）並未公開，且 API 行為可能隨時間更新而變化，導致相同提示在不同時間點可能產生不同結果。第二，雖然論文提及使用真實臨床產物，但基於隱私法規（如 HIPAA），公開釋出的資料集極可能為去識別化資料或基於公開資料集改編。研究者在復現時需確認所用資料與原始評測的一致性。此外，論文未詳細說明人工審查的評分者間一致性（inter-annotator agreement）與完整評分手冊，這可能影響主觀性較高任務的跨實驗室比較。

#### 未來研究方向

**突破醫學影像（medical imaging）瓶頸**
當前代理在 3D CT 容積資料（3D CT volumes）與十億像素病理切片（gigapixel pathology slides）上的表現顯示，視覺-語言模型仍需針對高解析度、大尺度的醫療影像進行專門最佳化。未來研究可探索分層注意力機制、多尺度特徵擷取或專用醫療影像工具鏈的自主整合，以降低代理在影像導航上的認知負荷。

**強化組合式推理（compositional reasoning）與搜尋策略**
針對大搜尋空間（large search spaces）與複雜邏輯組合的任務，未來可發展具備後設認知（metacognition）能力的代理架構，使其能夠在執行過程中動態評估子目標達成度，並在錯誤時進行回溯（backtracking）。結合蒙特卡洛樹搜尋（Monte Carlo Tree Search）或啟發式規劃（heuristic planning）的代理框架，可能是提升任務成功率（task success rate）的關鍵。

**多代理協作與人機互動**
真實臨床工作流程（clinical workflow）通常涉及多位專科醫師協作。未來可擴展 HealthAgentBench 至多代理系統，模擬放射科醫師、病理科醫師與臨床醫師之間的資訊交換。此外，開發人機協作介面，讓代理在不確定時主動查詢人類專家，將是縮短 42% 成功率與臨床可用性之間差距的重要路徑。

**擴展病患就醫旅程（patient journey）與模態（modalities）**
現有七大類別雖已涵蓋診斷與研究，但未來版本可納入藥物調劑、術後追蹤、基因體資料分析與即時生理訊號監測等階段。同時，支援更多異質性臨床文件（heterogeneous clinical documents）與多模態（multimodal）輸入，將使基準測試套件（benchmark suite）更貼近真實醫療場域的複雜度。

**開源模型的追趕與成本最佳化**
鑒於目前僅有商業化閉源模型達到可觀表現，未來研究應致力於開發開源權重（open weights）的醫療代理，降低評測與部署成本。同時，針對任務成功率與 API 呼叫成本之間的權衡進行系統性分析，將有助於在資源受限的臨床場景中實際落地。

## 論文問答

**Q1：HealthAgentBench 旨在解決的核心問題是什麼？**
A：HealthAgentBench 主要解決的是現有醫療 AI 評測方法無法有效衡量代理式系統（agentic systems）在真實臨床環境中表現的問題。傳統基準測試多採用靜態輸入與固定上下文提示，僅能評估孤立的大型語言模型問答能力，無法反映臨床工作流程所需的端對端推理與多步驟互動。隨著 AI 代理逐漸具備在複雜環境中執行長程推理的能力，醫療領域迫切需要一套能夠評估其探索原始資料、操作工具並完成完整臨床任務的統一基準測試套件。

**Q2：為何傳統醫療基準測試與現有的代理導向評測無法充分評估前沿 AI 代理？**
A：傳統基準測試如 MedQA 僅提供簡短的臨床病例摘要，要求模型在固定提示下給出單一答案，這與真實臨床中必須整合病理切片、CT 掃描與放射科報告等異質性資料的動態決策過程相去甚遠。現有的代理導向研究則往往侷限於特定任務、單一模態或預設工作流程，缺乏跨模態與跨階段的整體評估。因此，這些方法無法測試代理在面對超出上下文視窗限制的原始醫療資料時，是否具備規劃、工具使用與環境探索等關鍵能力。

**Q3：開發像 HealthAgentBench 這樣的統一基準測試套件為何至關重要？**
A：醫療領域的高價值應用通常需要對複雜、多模態且大規模的資料進行端對端推理，而這些資料往往無法被壓縮在簡短的提示中。建立統一的代理式醫療環境評測標準，能夠為研究社群提供共同的比較基礎，使研究者可靠地識別前沿系統的優勢與弱點。此外，這有助於追蹤 AI 代理在真實病患就醫旅程——從資料管理、診斷到治療規劃——中的長期進展，確保技術發展方向符合臨床實務需求。

**Q4：HealthAgentBench 的核心方法論是什麼？**
A：HealthAgentBench 包含 54 個任務，橫跨 7 個類別，每個類別都擁有獨立的終端機式 Docker 執行環境，內含真實的臨床資料與輔助資源。代理僅獲得極簡任務說明，必須自主探索環境中的原始醫療資料——例如 3D CT 容積資料或縱向電子健康紀錄——並設計多步驟解決方案。最後，透過統一的評估模組，將代理的最終輸出與人類專家表現或專家標籤進行比對，以二元成功或失敗的標準計算整體任務成功率，提供單一且可解釋的效能指標。

**Q5：相較於既有基準測試，HealthAgentBench 的關鍵創新為何？**

## 實務應用指南

### 適用場景

1. **醫學影像品質管控與報告校正**：部署代理自動檢視胸部 X 光、3D CT 容積資料與十億像素病理切片，交叉比對放射科報告與歷史影像，協助醫師標註病灶並修正報告中的臨床錯誤。
2. **電子病歷資料治理與研究管線自動化**：利用代理執行 EHR 資料品質稽核、格式轉換與事件建模，將縱向電子健康紀錄轉換為可分析的研究資料集，加速臨床研究建模管線建置。
3. **臨床試驗智慧篩選與病患配對**：讓代理讀取異質性臨床文件與試驗方案，自動比對病患的結構化病歷與自由文本紀錄，縮短收案前的繁複人工篩選流程。
4. **多模態臨床決策輔助系統**：整合影像、自由文本與結構化資料，打造端對端臨床工作流程代理，在診斷與治療規劃階段輔助醫師整合跨模態資訊。
5. **醫療 AI 代理能力評估與選型平台**：供醫院資訊部或醫療軟體廠商作為內部標準，評測不同前沿 AI 代理在真實臨床環境的任務成功率與成本效益。

### 實作前置條件

**資料需求**：原始醫療資料（DICOM 影像、全切片病理圖、縱向電子健康紀錄、放射科報告、臨床試驗方案等）、專家標註或人類表現基準作為黃金標準、經去識別化的測試資料集，以及用於建置任務環境的 Docker 映像檔與設定檔。

**運算需求**：具備 GPU 的運算節點（處理 3D CT 容積資料與高解析度病理切片）、充足的儲存空間（單一任務可能涉及 GB 級影像與大型資料庫）、以及能支撐 LLM 代理長期推理與多步驟互動的 API 配額與網路頻寬。

**技能需求**：醫療資料工程（熟悉 DICOM、HL7 FHIR、PACS 系統）、AI 代理開發（LLM 工具呼叫、環境互動設計、容器化部署）、臨床領域知識（確保任務設計貼近真實臨床工作流程），以及醫療資安法規遵循能力（個資法、HIPAA、醫療器材管理法）。

### 實作步驟建議

1. **需求盤點與任務範圍界定**：從病患就醫旅程中，挑選高價值且無法以簡易提示解決的端對端臨床工作流程，優先納入涉及多模態資料與長程推理的場景。
2. **環境與資料準備**：建置 Docker 容器化的代理式醫療環境，置入原始醫療資料與臨床文件，確保資料已去識別化，並提供最小化指令，讓代理自由探索。
3. **任務設計與難度校準**：為每項任務定義明確的成功/失敗準則，對照專家標籤或人類表現，並透過人工審查確認目標確實可達，避免過度困難或模糊。
4. **代理工具鍊建置**：賦予代理檢視、縮放、裁切醫學影像，查詢資料庫，安裝影像處理工具，以及讀寫異質性臨床文件的能力。
5. **評測與瓶頸分析**：以任務成功率作為單一可解釋指標，進行跨類別細緻分析，識別當前代理的弱點（如醫學影像判讀、大型搜尋空間下的組合式推理）。
6. **產品化與人機協作部署**：將驗證後的代理整合至醫院臨床資訊系統，設置醫師覆核介面，並建立持續監控機制，確保長期運作品質與安全。

### 潛在風險與注意事項

1. **資料隱私與資安洩漏**：原始醫療資料極度敏感，代理在探索環境時可能不當存取或輸出個資。必須落實去識別化、傳輸加密、環境隔離，並設置嚴格的存取稽核日誌。
2. **幻覺與錯誤累積**：長程推理過程中，代理可能在影像判讀或 EHR 解析時產生幻覺，且多步驟錯誤會隨時間放大。任何輸出都應經過人類專家覆核，不可直接採納為臨床決策。
3. **成本與效能瓶頸**：前沿 AI 代理在處理大型搜尋空間與多模態任務時，可能消耗大量 token 與運算資源。建議設定預算上限，並定期評估任務成功率與成本效益比。
4. **泛化落差與過度擬合**：代理可能在特定基準測試套件中表現良好，但無法泛化至真實臨床場域的多樣性。應持續擴充任務類別、模態與機構資料，避免評測與實務脫節。
5. **監管合規與責任歸屬**：醫療 AI 產品需符合當地醫療器材法規（如 TFDA、FDA）。代理的自主決策特性可能挑戰現有責任歸屬框架，產品定位應以輔助為主，並保留完整決策軌跡供查驗。

### 與其他技術的整合建議

1. **醫療資訊系統（HIS/PACS）**：透過標準化 API（如 DICOM、HL7 FHIR）讓代理式環境與醫院現有影像存檔系統及電子病歷平台對接，直接讀取第一線原始醫療資料。
2. **專用電腦視覺模型**：針對醫學影像任務，將 U-Net、Vision Transformer 等傳統機器學習模型封裝為代理可呼叫的工具，彌補純 LLM 在空間推理上的不足。
3. **醫學知識圖譜**：整合 SNOMED CT、ICD-10 等醫學術語本體，強化代理在臨床試驗配對與 EHR 事件建模時的語義理解，提升組合式推理的正確性。
4. **檢索增強生成（RAG）**：針對異質性臨床文件與試驗方案建立向量資料庫，協助代理在大型搜尋空間中快速定位相關段落，降低長程推理的複雜度。
5. **人機協作與回饋閉環**：開發供臨床醫師使用的審查介面，讓代理的每一步探索與決策都可被追蹤、中斷與修正，並將專家回饋用於後續代理策略迭代。

### 給不同背景讀者的閱讀建議

**初學者**：本文描繪了 AI 從「回答固定問題」邁向「在醫院自主執行任務」的轉變。建議你先聚焦「適用場景」與「潛在風險」，理解為何代理需要「看」X 光片、「翻」病歷，而非僅靠簡易提示完成工作，以此建立對端對端醫療 AI 的整體認知。

**AI 工程師**：請重點參考「實作步驟建議」與「與其他技術的整合建議」。本文的 Docker 環境設計、最小化指令原則，以及對醫學影像與 EHR 任務瓶頸的分析，對你設計工具呼叫策略、規劃代理架構與成本控管有直接幫助。

**研究人員**：建議深入本文的方法論貢獻，特別是任務選取原則與統一評估模組的設計。HealthAgentBench 作為尚未飽和的基準測試套件，提供了長程推理與多模態研究的明確方向，可延伸探討如何提升醫學影像任務成功率與複雜組合式推理能力。

**產品經理**：請優先閱讀「適用場景」與「潛在風險與注意事項」。本文清楚指出目前最強代理僅達約 42% 任務成功率，提醒你醫療 AI 產品在短期內應定位為「輔助」而非「替代」，並需預留法規審查、人機協作介面開發與臨床驗證的充足時程。
