# 根本原因歸因是一個搜尋問題：針對長期任務中 AI 智能體失敗的持續搜尋（Continual Search）

## ⚡ TL;DR

長期任務執行日誌龐大，現有單次LLM根因歸因易遺漏稀疏分散的關鍵證據。
本文提出「持續搜尋」框架，透過多輪迭代促使評審持續挖掘未解決的診斷證據。

## 摘要翻譯

AI 智能體（AI agents）在長期任務（long-horizon tasks）中的部署日益增加，產生大量執行日誌（execution logs）。診斷這些日誌中的失敗對可靠性至關重要，因為它能將結果層級訊號（outcome-level signals）轉化為可行的介入措施（actionable interventions）。資料規模龐大，使得人工審查不切實際，因而催生了自動化根本原因歸因（Root-Cause Attribution, RCA）的需求。然而，使用大型語言模型（Large Language Models, LLMs）的自動化 RCA 方法診斷準確率偏低，尤其在執行軌跡（execution traces）變長時更是如此。這些方法之所以困難，在於相關資訊通常稀疏（sparse）、分散於遙遠的動作之間（distributed across distant actions），且與可見的失敗（visible failure）脫節，使根本原因歸因成為一個大規模的搜尋問題（search problem）。現有的 RCA 方法通常仰賴單次 LLM 判斷（one-shot LLM judgments），從執行軌跡中診斷失敗。雖然對較短的軌跡有效，這些判斷器往往過早採納看似合理的診斷（plausible diagnosis），導致較長軌跡中的關鍵證據未被檢視。我們提出持續搜尋（Continual Search），這是一個迭代框架（iterative framework），透過連續回合（successive turns）引導判斷器持續搜尋尚未解決的診斷證據（diagnostic evidence）。我們在四個現有的 RCA 基準測試（benchmark suites）上評估持續搜尋。鑑於現有基準缺乏大規模執行軌跡，我們提出 MegaRCA-Mix，以進行大規模 RCA 評估。MegaRCA-Mix 提供了一個具挑戰性的測試平台，包含 50 個人工標註（human-annotated）的失敗試驗（failure trials），涵蓋長期且執行動作繁重的任務。在多個基準測試套件與模型家族（model families）中，持續搜尋皆能一致地提升歸因表現（attribution performance）。例如在 MegaRCA-Mix 上，它將 GPT-5.5 的 F1 分數（F1 score）提升了超過 40%，從 0.349 提高到 0.498。更值得關注的是，在同一模型家族中，較低階模型（lower-tier models）甚至可以超越其較高階對應模型（higher-tier counterparts），顯示有效的搜尋凌駕於單純的模型規模（raw model scale）。

### 核心貢獻（3～5點）
- 重新定位 RCA 本質：指出長期任務中的根本原因歸因是一個大規模搜尋問題，因為關鍵診斷證據稀疏、分散於遙遠的動作之間，且常與可見的失敗脫節。
- 提出持續搜尋（Continual Search）框架：透過連續回合迭代引導 LLM 判斷器，避免過早收斂於看似合理的診斷，持續挖掘尚未解決的診斷證據。
- 建立大規模 RCA 基準測試集 MegaRCA-Mix：提供 50 個人工標註的失敗試驗，涵蓋長期且執行動作繁重的任務，彌補現有基準缺乏大規模執行軌跡的不足。
- 驗證搜尋策略可超越原始模型規模：實驗顯示 Continual Search 在多個基準與模型家族中一致提升歸因表現，且較低階模型搭配有效搜尋甚至可超越較高階對應模型。

### 適合對象
本論文適合從事 AI 智能體可靠性、自動化故障診斷、LLM 輔助除錯、以及長期任務執行軌跡分析的研究人員與工程師閱讀。對於關注如何提升大型語言模型在複雜、多步驟任務中診斷準確率，或希望建構可解釋、可介入之智能體失敗分析系統的讀者尤其具有參考價值。

## 深度分析

#### 方法論解析

本文將 Root-Cause Attribution（RCA，根本原因歸因）重新定位為一個 **search problem（搜尋問題）**：在長期任務（long-horizon tasks）產生的執行日誌（execution logs）中，關鍵的診斷證據（diagnostic evidence）往往是稀疏（sparse）、分散於遙遠動作之間（distributed across distant actions）、且與最終可見的失敗（visible failure）脫節的。因此，單次 LLM（Large Language Model，大型語言模型）判斷（one-shot LLM judgments）雖然在短軌跡（trajectories）上有效，卻容易過早接受一個看似合理的診斷（plausible diagnosis），而忽略後續或更早的關鍵證據。

為此，作者提出 **Continual Search（持續搜尋）**，一個迭代框架（iterative framework）。其核心設計可歸納為以下幾點：

1. **多回合挑戰現有診斷**：不同於被動延續（Passive Continuation）僅要求模型「再想想」，Continual Search 在每一回合（successive turns）都明確要求評審（judge）挑戰當前最佳答案，尋找尚未解決或尚未檢視的證據。
2. **強制探索而非重複確認**：框架要求模型搜尋「支持現有診斷之外的證據」，也就是主動尋找可能推翻或修正當前根因假設的資訊，以降低確認偏誤（confirmation bias）。
3. **擴大有效證據覆蓋率**：實驗顯示，在 TRAIL 上經過四回合後，Continual Search 讓模型讀到的去重複證據 token 從 42K 增加到 58K，而被動延續只增加到 48K。這說明 Continual Search 真正促使模型觸及新的執行軌跡區段，而非僅在同一區域打轉。
4. **與現有歸因分類法整合**：診斷結果仍對應到 Raj et al. (2026) 提出的互動中心分類法，將根因歸因到 model（模型）、harness（控制架構）、environment（環境）或 grader（評分器）等責任元件，使診斷能轉化為可行的介入措施（actionable interventions）。

整體而言，Continual Search 並非單純增加採樣次數或擴大上下文長度，而是透過結構化的自我質疑與證據搜尋指令，把推理過程從「一次性判斷」轉變為「逐步排除與驗證」。

#### 實驗數據解讀

作者在 **四個現有 RCA 基準測試套件（benchmark suites）** 與新提出的 **MegaRCA-Mix** 上進行評估：

- **TRAIL** 與 **TELBench**：屬於執行軌跡較長的資料集。
- **AgentRx** 與 **Who&When**：軌跡相對較短。
- **MegaRCA-Mix**：本文新貢獻，包含 50 個人工標註（human-annotated）的失敗試驗（failure trials），取自 Harbor Index 執行日誌，中位數執行規模達 286K tokens，遠大於現有基準測試。

主要結果如下：

| 資料集 / 指標 | 單次判斷或基線 | Continual Search | 觀察 |
|---|---|---|---|
| TRAIL（GPT-5.5 Weighted F1） | 0.426 | 0.500（四回合） | 相較被動延續的 0.451 仍有顯著提升 |
| MegaRCA-Mix（GPT-5.5 F1 score） | 0.349 | 0.498 | 相對提升超過 40% |
| AgentRx / Who&When | 原本已高 | 額外回合無明顯增益，甚至下降 | 短軌跡證據已飽和 |

數據透露幾個重要訊息：

1. **搜尋的收益與軌跡長度正相關**：在 TRAIL 與 MegaRCA-Mix 這類長軌跡、執行繁重的任務中，Continual Search 能持續發掘新證據，因此歸因表現（attribution performance）穩定提升。
2. **被動延續不足以解決問題**：單純讓模型在多回合中「重新考慮」只能帶來有限進步（TRAIL 上從 0.426 到 0.451），因為它缺乏強制探索機制。
3. **過度搜尋在短軌跡上有害**：在 AgentRx 與 Who&When 上，初始診斷已涵蓋大部分證據，額外回合反而對模型施加壓力，使其翻轉到錯誤標籤。這顯示 Continual Search 並非萬靈丹，其效益取決於證據空間是否仍有未開發區域。
4. **搜尋能力可彌補模型規模差距**：作者發現，在同一模型家族（model families）內，較低階模型（lower-tier models）搭配 Continual Search 有時能超越較高階對應模型（higher-tier counterparts）的單次判斷。這意味著有效的 inference-time search（推論時搜尋）可能比單純增加原始模型規模（raw model scale）更具成本效益。

#### 與現有研究的比較

本文在方法定位上與數條研究路線形成對比：

- **單次 LLM 評審（one-shot LLM judgments）**：Deshpande et al. (2025)、Barke et al. (2026)、Wang et al. (2026a) 等方法透過單一 rubric-guided pass 進行歸因。這類方法在短軌跡上表現尚可，但隨著執行日誌增長，模型傾向過早收斂。Continual Search 透過迭代挑戰機制彌補此缺陷。
- **Agent-as-a-Judge（Zhuge et al., 2024）**：允許評審透過工具使用（tool use）檢視中間執行證據，但仍屬於單輪或有限輪次的互動，未強調持續搜尋與排除替代假設。未來可與 Continual Search 結合，讓工具呼叫也具備主動探索目標。
- **自我一致性（self-consistency, Wang et al., 2022）**：透過多次獨立採樣並取多數決來降低變異。然而每次採樣仍是一趟單獨的 one-shot 判斷，無法在回合間累積新發現的證據或進行針對性反駁。
- **異質評審團（judge panel, Verga et al., 2024; Kohli, 2026）**：集合不同評審的觀點進行投票，可提升可靠性，但本質上仍是多個單次判斷的聚合，而非單一推理軌跡上的深度搜尋。
- **被動延續（Passive Continuation）**：作為本文最強的對照基線，它讓模型在同一對話中持續重新考慮診斷，但不強制進一步探索。結果顯示其證據覆蓋率與表現均落後於 Continual Search，證明「多回合」本身不如「有目標的持續搜尋」重要。

**主要貢獻與限制**：

- 貢獻：明確指出長期 RCA 的瓶頸在於搜尋，並提出可具體提升長軌跡診斷準確率（diagnostic accuracy）的迭代框架；同時推出 MegaRCA-Mix，填補大規模執行日誌 RCA 評估的缺口。
- 限制：Continual Search 在短軌跡上可能適得其反；額外回合會增加 token 消耗與延遲；評審是否能正確識別「未解決證據」仍高度依賴模型自身的後設認知能力；目前評估主要集中於文字型執行日誌，對多模態或極大規模（數百萬 tokens）日誌的擴展性尚未充分驗證。

#### 可重現性評估

就現有論文上下文而言，**可重現性（reproducibility）目前偏低**，原因如下：

- **未提及開源釋出**：文中沒有說明是否公開原始碼、提示詞模板、模型權重或 MegaRCA-Mix 資料集。ScaleAI 作為商業機構，其執行日誌與模型存取可能受授權限制。
- **MegaRCA-Mix 來源受限**：該基準測試集來自 Harbor Index 執行日誌，並經人工標註，若原始日誌未公開，研究者難以複製實驗條件或進行公平比較。
- **GPT-5.5 非公開模型**：實驗核心模型 GPT-5.5 並非一般研究者可取得的公開權重，這使得「較低階模型超越較高階模型」等發現難以由外部驗證。
- **關鍵實作細節未詳述**：例如每回合的具體提示詞、停止條件、如何定義「未解決證據」、去重複證據 token 的計算方式等，都會影響重現結果。

若要提升可重現性，建議作者至少公開：(1) MegaRCA-Mix 的匿名化執行日誌與人工標註；(2) Continual Search 與各基線的提示詞與程式碼；(3) 評估腳本與計分邏輯。在這些釋出之前，本研究更像是一個由內部資料與模型支撐的概念驗證。

#### 未來研究方向

基於本文的發現，可延伸出以下數個研究方向：

1. **與 Agent-as-a-Judge 結合**：讓 Continual Search 的每一回合不僅重新閱讀上下文，還能主動呼叫工具（如檢索特定時間區段、對比環境狀態、查詢 grader 輸出），將「被動閱讀」轉為「主動取證」。
2. **自適應停止準則（adaptive stopping）**：設計根據證據飽和度、診斷不確定性或置信度變化來決定何時終止搜尋的機制，避免在短軌跡上過度搜尋，並降低長軌跡的計算成本。
3. **階層式摘要與檢索**：面對數百萬 tokens 的執行日誌，可先用高層摘要定位可疑區段，再於 Continual Search 中針對這些區段深入檢視，以兼顧規模與細節。
4. **多智能體搜尋架構**：將「命題者（proposer）」、「批判者（critic）」、「驗證者（verifier）」分離為不同智能體（AI agents），讓搜尋過程更具結構性，並減少單一模型自我確認的風險。
5. **因果推理與反事實分析**：目前的 RCA 仍偏向證據匹配，未來可引入更明確的因果推論，例如判斷「若某動作未發生，失敗是否仍會出現」，以區分真正根因與相關但非關鍵的事件。
6. **成本效益分析**：系統化比較「增加模型規模」與「增加搜尋回合數」在準確率、延遲與費用之間的權衡，為實際部署提供決策依據。
7. **多模態執行日誌**：將方法擴展至包含截圖、API 呼叫記錄、系統日誌等多模態資料的安全事件取證場景。
8. **RCA 驅動的持續學習**：把歸因結果回饋到模型後訓練、harness 設計或 benchmark 修復流程，形成「失敗 → 診斷 → 改進」的閉環。
9. **更大規模的開放基準測試**：建立公開、標準化、涵蓋多種任務長度與根因類型的 RCA benchmark suites，降低社群進入門檻並促進方法比較。

## 論文問答

**Q1：這篇論文指出長期任務中自動化根本原因歸因（RCA）面臨什麼核心問題？**

A：隨著 AI 智能體被部署在長期任務上，執行日誌的規模變得極為龐大，人工審查已經不切實際，因此需要自動化的根本原因歸因。然而，現有使用大型語言模型進行 RCA 的方法在執行軌跡變長時診斷準確率會顯著下降，因為關鍵證據往往稀疏、分散在遙遠的動作之間，且與可見的失敗結果沒有直接連結。這使得 RCA 在本質上更像是一個大規模搜尋問題，必須在龐大的證據空間中尋找並驗證真正的根因。

**Q2：為什麼現有的單次 LLM 判斷方法在處理長執行軌跡時會失效？**

A：單次 LLM 判斷通常只對執行日誌進行一次基於評分標準的檢視，雖然對較短的軌跡有效，但在軌跡變長時，模型傾向過早接受一個看似合理的診斷。這種過早收斂會讓模型忽略後續或更早出現的關鍵證據，導致關鍵線索未被檢視。由於長期任務的失敗機制可能隱藏在大量不相關動作之中，單次判斷難以全面探索證據空間。

**Q3：為什麼根本原因歸因不僅僅是判斷任務成功或失敗那麼簡單？**

A：結果層級的訊號只能告訴我們任務失敗，但無法說明失敗的潛在機制或應該介入哪個元件。RCA 能將這些訊號轉化為可行的介入措施，例如區分是模型、工具鏈、環境還是評分器的問題，從而指引後續的修正方向。這對智能體系統的持續自我改進以及安全事件的事後調查都至關重要，例如 Hugging Face 安全事件就需要反覆檢視超過七萬筆智能體訊息才能重建入侵時間軸。

**Q4：什麼是 Continual Search，它與單次判斷的根本差異在哪裡？**

A：Continual Search 是本文提出的一種迭代式框架，它會在多個連續回合中持續推動評審模型去尋找尚未解決的診斷證據。與單次 LLM 判斷只做一次證據通讀不同，Continual Search 要求模型在每一回合都挑戰自己目前的答案，並主動搜尋支持或反駁該答案的新證據。這種設計讓模型不會過早停留在初步診斷，而是持續擴展對執行軌跡的理解。

**Q5：Continual Search 與 Passive Continuation 有什麼關鍵區別？**

A：Passive Continuation 雖然也會提示模型在持續對話中反覆重新考慮診斷，但它並不強制要求進一步探索新的證據。相對地，Continual Search 在每一回合都明確要求評審挑戰現有答案，並搜尋超越原本支持該答案的證據範圍。因此，Continual Search 能真正促使模型閱讀更多去重複後的證據，而不只是重複確認既有結論。

**Q6：Continual Search 的關鍵設計選擇有哪些？**

A：首先，它採用多回合對話機制，讓評審有機會在每次迭代中重新審視與更新診斷。其次，它明確指示模型挑戰當前診斷並尋找尚未檢視或尚未解決的證據，避免過早收斂。最後，它鼓勵模型在每一回合擴大證據覆蓋範圍，這點可從實驗中去重複證據閱讀量顯著增加得到驗證。

**Q7：論文在哪些基準測試上評估了 Continual Search？**

A：論文在四個現有 RCA 基準測試上進行評估，包括 TRAIL、TELBench、AgentRx 與 Who&When，並保留各自原本的評分與定位方式。此外，為了彌補現有基準缺乏大規模執行日誌的不足，作者還提出了 MegaRCA-Mix。MegaRCA-Mix 包含 50 個來自 Harbor Index 執行日誌的人工標註失敗試驗，中位數執行大小達 286K tokens，是更具挑戰性的大規模測試平台。

**Q8：Continual Search 的主要實驗結果是什麼？**

A：在 TRAIL 上，Continual Search 將 GPT-5.5 的 Weighted F1 從單次判斷的 0.426 提升到四回合後的 0.500，明顯優於 Passive Continuation 的 0.451。在 MegaRCA-Mix 上，GPT-5.5 的 F1 分數更從 0.349 提升至 0.498，成長超過 40%。更有趣的是，在同一模型家族中，較低階模型搭配 Continual Search 有時能超越未使用該方法的高階模型，顯示有效的搜尋策略可以彌補甚至超越原始模型規模。

**Q9：從消融與比較實驗中，可以觀察到什麼關於證據覆蓋的現象？**

A：實驗顯示，Continual Search 在四回合內將去重複後的證據閱讀量從 42K tokens 增加到 58K tokens，而 Passive Continuation 只增加到 48K tokens，這說明效能提升與閱讀到新證據密切相關。然而，在軌跡較短的 AgentRx 與 Who&When 上，初始判斷已涵蓋大部分證據，額外回合反而會迫使模型重新檢視已有預測，導致標籤被翻轉成錯誤答案。這顯示 Continual Search 的效益主要來自於長軌跡中仍有大量未被探索的證據空間。

**Q10：哪些實際應用場景最能從 Continual Search 受益？**

A：任何涉及長期執行、大量互動紀錄的 AI 智能體系統都能受益，例如自動化客服、程式碼生成代理、科學實驗規劃代理等。特別是在安全事件調查中，調查人員需要反覆檢視長時間跨度的執行日誌，Continual Search 能協助自動化這種多輪證據發掘過程。此外，對於希望從失敗軌跡中學習並持續自我改進的系統，準確的根因歸因能提供可靠的回饋訊號。

**Q11：在產品化部署 Continual Search 時需要考慮哪些因素？**

A：首先，迭代搜尋會增加推理成本與延遲，因此需要根據任務長度與錯誤代價來權衡回合數。其次，系統需要能區分長軌跡與短軌跡，因為在後者上增加回合可能適得其反。最後，應設計適當的停止條件與穩定性機制，避免模型在缺乏新證據時仍不斷翻轉診斷，造成歸因結果不穩定。

**Q12：這項研究可能對整個領域帶來什麼影響？**

A：這篇論文將 RCA 重新定位為搜尋問題，強調在長期任務中，問題核心不在於模型是否聰明，而在於是否能持續、系統地探索證據空間。它證明了有效的搜尋策略可以讓較小模型超越較大模型，這可能改變未來研究對模型規模與推理策略相對重要性的看法。未來的 RCA 系統可能會更廣泛地採用迭代式、主動式的證據探索架構，而非依賴單次判斷。

**Q13：論文承認了哪些限制？**

A：作者指出，在軌跡較短的任務中，額外的搜尋回合並無法帶來新的證據，反而可能因為壓力而翻轉正確答案。此外，現有基準普遍缺乏真正大規模的執行日誌，因此需要額外建立 MegaRCA-Mix 來補足這一缺口。迭代式方法也會帶來更高的計算成本與延遲，這在實際部署時必須納入考量。

**Q14：在什麼樣的失敗案例中，Continual Search 可能無法提供幫助？**

A：當執行軌跡很短，且初始單次判斷已經涵蓋了幾乎所有可用證據時，Continual Search 沒有額外的證據可以發掘。此時持續要求模型挑戰自己的答案，容易讓它過度反應，把原本正確的診斷改成錯誤標籤。另外，如果關鍵證據根本不存在於日誌中，或日誌本身品質低落，再好的搜尋策略也無法憑空產生正確診斷。

**Q15：未來可以朝哪些方向延伸這項研究？**

A：未來可以發展自適應停止機制，讓系統在沒有新證據時自動結束迭代，避免不必要的計算與翻轉。結合主動式檢索或工具使用，選擇性地深入探查高潛力區段，也有助於提升效率。此外，將方法擴展到多智能體系統中分散於不同智能體的證據，以及建立更大規模、更多元領域的人工標註資料集，都是值得探索的方向。

## 實務應用指南

## 適用場景

1. **長期自主智能體的線上維運監控**  
   當 AI 智能體執行數百至數千步的任務（如軟體開發、資料分析、科學實驗規劃）並產生數十萬到數百萬 token 的執行日誌時，持續搜尋可用於自動定位首次偏離正確執行路徑的根因，減少人工翻閱整份軌跡的負擔。

2. **多智能體協作系統的故障歸因**  
   在多智能體環境中，關鍵證據常分散於不同角色的對話與工具呼叫之間。持續搜尋能跨回合追蹤未解決的診斷證據，協助判斷是模型決策錯誤、工具使用不當，還是環境或評分器異常。

3. **AI 安全事件的事後鑑識與稽核**  
   針對涉及安全後果的失敗事件（如越權操作、評估環境被繞過），持續搜尋可反覆檢視執行軌跡，逐步排除看似合理但實際矛盾的診斷，最終收斂到真正的入侵或失敗時間軸。

4. **自動化基準測試與模型迭代回饋**  
   在持續評估與後訓練流程中，將持續搜尋嵌入評估管線，可把結果層級訊號轉為可行的介入措施，例如區分是模型能力不足、提示工程缺陷，還是評測題目本身的標註錯誤。

5. **企業流程自動化（RPA / Agentic Workflow）的異常診斷**  
   對於長時間執行的業務流程自動化任務，持續搜尋能協助維運團隊從大量執行日誌中找出導致流程中斷或結果錯誤的關鍵步驟，縮短平均修復時間（MTTR）。

## 實作前置條件

### 資料條件
- **結構化執行軌跡**：需保留完整的動作—觀察序列，包括工具呼叫、環境狀態、重試記錄與中間輸出，而不只是最終輸入與輸出。
- **根因標註或歸因分類法**：至少需有初步的分類框架（如 model / harness / environment / grader），以便設計評審提示與評估指標。
- **負面案例樣本**：建議蒐集數十到數百筆失敗試驗，涵蓋不同長度與不同根因類型，用於校正搜尋策略與停止條件。

### 運算條件
- **大型語言模型 API 或自建推理端點**：需支援多輪對話與長上下文（數萬至數十萬 token），並能負擔每筆失敗軌跡多次迭代的推理成本。
- **提示快取與 token 管理機制**：由於持續搜尋會在連續回合中重複讀取部分執行日誌，建議使用 prompt caching、滑動視窗或區塊索引來控制成本。
- **評估與比對基礎建設**：需能自動計算 F1 分數、加權 F1 或自訂歸因指標，並與單次 LLM 判斷、被動延續等基線進行比較。

### 技能條件
- **提示工程與評審設計經驗**：能設計強制「挑戰現有診斷並搜尋新證據」的迭代提示，而非僅要求模型重新考慮。
- **資料工程能力**：能將原始執行日誌清洗、分塊、建立索引，並支援模型依據診斷需求檢索特定區段。
- **領域知識**：理解目標任務的正確執行流程，才能判斷何謂「首次偏離」與合理的根因分類。

## 實作步驟建議

1. **建立執行日誌的結構化索引**  
   將原始執行軌跡依時間或功能模組切分為可檢索區塊，並記錄每個區塊的動作類型、工具呼叫、回傳結果與異常標記，作為後續搜尋的證據空間。

2. **設計單次評審基線**  
   先以單次 LLM 判斷建立基準，使用明確的歸因分類法與評分標準，確認模型在短軌跡上的表現，並找出常見的過早收斂模式。

3. **實作持續搜尋的迭代提示**  
   在每一回合中，要求評審：(a) 列出目前診斷所依賴的證據；(b) 找出尚未解釋或矛盾的觀察；(c) 主動搜尋可支持替代假設的新證據；(d) 決定是否維持、修正或推翻現有診斷。

4. **設定停止條件與證據去重機制**  
   當連續數回合未讀取到新的去重後證據，或診斷穩定超過門檻時停止。避免無限制迭代導致成本飆升或模型被強迫翻轉到錯誤標籤。

5. **在長軌跡基準上驗證效益**  
   使用 MegaRCA-Mix 或內部蒐集的長期任務失敗試驗，比較持續搜尋與被動延續、自我一致性、評審團等基線，確認證據覆蓋率與 F1 分數是否同步提升。

6. **整合至維運或評估管線**  
   將持續搜尋封裝為可呼叫的歸因服務，輸入失敗軌跡後輸出根因分類、關鍵證據區段與置信度，並與問題追蹤系統或後訓練資料管線對接。

## 潛在風險與注意事項

- **過度搜尋導致診斷翻車**  
  在較短的執行軌跡中，證據本已有限，額外回合可能迫使模型為了「找新證據」而放棄正確診斷。應根據軌跡長度動態調整最大回合數，或只在軌跡超過一定 token 數時啟用持續搜尋。

- **成本隨回合數線性增長**  
  每增加一回合都會產生額外的推理費用。建議監控去重後證據 token 的增長曲線，當新增證據趨緩時提前停止，而非固定跑完預設回合。

- **提示設計不當淪為被動延續**  
  若僅提示模型「再想想」而未要求主動搜尋未檢視區段，模型容易重複檢視相同證據。必須在提示中明確要求挑戰現有診斷並指出下一個待查區域。

- **幻覺與虛構證據**  
  長上下文下模型可能引用不存在的步驟。可要求每個診斷都附上對應的軌跡區段編號或引用，並由後處理模組驗證引用是否存在。

- **領域分類法不一致**  
  若團隊對 model、harness、environment、grader 等類別的定義模糊，會降低歸因結果的可行動性。建議在導入前先與維運、研究、產品團隊對齊分類標準。

## 與其他技術的整合建議

- **與檢索增強生成（RAG）結合**  
  將執行日誌預先建立向量索引，讓持續搜尋在每一回合先檢索與當前假設相關的區段，再交由 LLM 評審判斷，降低長上下文壓力並提升證據定位精度。

- **與 Agent-as-a-Judge 框架整合**  
  讓評審智能體不僅閱讀文字軌跡，還能透過工具查詢環境狀態、重跑特定步驟或比對預期輸出，使持續搜尋具備主動驗證能力。

- **與監控與可觀測性平台對接**  
  將持續搜尋的輸出（根因分類、關鍵區段、置信度）寫入可觀測性儀表板，並與告警系統連動，讓維運人員能快速從結果層級訊號下鑽到具體根因。

- **與後訓練與資料飛輪整合**  
  把高置信度的歸因結果自動標註為訓練資料，用於 SFT 或 RLHF；對於歸因為 grader 或 environment 錯誤的案例，則回饋至基準測試修復流程。

- **與多評審投票機制互補**  
  持續搜尋可與評審團或自我一致性搭配：先讓單一評審透過多輪搜尋產出候選診斷，再交由異質評審團進行最終投票，兼顧深度探索與意見多樣性。

## 給不同背景讀者的閱讀建議

**初學者**：可以先聚焦在「為什麼長軌跡的根因歸因很難」這個直覺問題，理解單次 LLM 判斷為何會過早停在看似合理的診斷；接著把持續搜尋想像成「讓 AI 鑑識人員不要只看第一眼證據，而是反覆回到現場找新線索」，不必一開始就深入提示細節。

**AI 工程師**：建議重點閱讀持續搜尋與被動延續、自我一致性、評審團的比較實驗，特別注意 TRAIL、TELBench 與 MegaRCA-Mix 上證據覆蓋率與 F1 的關聯；實作時請優先處理提示設計、停止條件與引用驗證，這三項最影響上線後的穩定性。

**研究人員**：本文把根因歸因重新定位為搜尋問題，值得從理論層面思考其與主動學習、假設檢驗、長上下文推理的連結；MegaRCA-Mix 的設計與人工標註流程也提供了未來建構更大規模 RCA 基準的參考，可進一步探索搜尋策略的最佳化與可解釋性。

**產品經理**：請把這篇論文視為「如何將失敗訊號轉為可行動介入」的設計參考，重點關注適用場景、成本權衡與歸因分類法對團隊協作的影響；在規劃產品路線時，建議先從最長、最貴、最難人工排查的失敗案例切入，驗證 ROI 後再擴大到其他任務類型。
