# 勇闖 Gauntlet：重新評估智慧體在熟悉環境之外的能力

**原文標題：** Running the Gauntlet: Re-evaluating the Capabilities of Agents Beyond Familiar Environments  
**作者：** Mykola Vysotskyi、Runqi Lin、Grzegorz Biziel 等 25 位作者  
**發布日期：** 2026-06-25

## ⚡ TL;DR

現有基準測試多聚焦熱門應用的簡單任務，性能已趨飽和，無法真實評估智慧體在複雜情境下的泛化與侷限。
提出 GauntletBench，以專業網頁應用與百項視覺任務，評估時序感知、圖形理解與三維推理。
實證顯示最先進智慧體成功率僅19.1%，遠低於人類的80%，現有系統在複雜情境中仍遠不及人類水準。

## 摘要翻譯

隨著智慧體系統（agentic systems）持續演進並廣泛部署於真實世界情境（real-world scenarios），忠實評估（faithful evaluation）其能力的需求日益增長。然而，現有的基準測試（benchmarks）通常建構於任務相對簡單的熱門應用程式（popular applications）之上，且聚焦於狹窄的能力集合，同時忽視更廣泛的面向，導致現代智慧體（agents）性能飽和（saturated performance），且無法探究其侷限性（limitations）。為此，我們提出 GauntletBench，一個用於在具挑戰性的情境（challenging scenarios）中評估智慧體泛化（agent generalisation）的網頁式基準測試（web-based benchmark），聚焦於三項未被充分探索的能力（underexplored capabilities）——時序感知（temporal perception）、圖形理解（graphical understanding）與三維推理（3D reasoning）——橫跨五項較少被涵蓋的專業應用程式（less-covered professional applications）：影片編輯器（Video Editor）、工作流程建構器（Workflow Builder）、三維建模器（3D Modeller）、航班分析器（Flight Analyser）與電路設計器（Circuit Designer），每項包含 20 個視覺密集型任務（vision-intensive tasks）（總計 100 個）。我們的基準測試提供一個模組化流程（modular pipeline），包含一個相容於開源與閉源智慧體框架（open- and closed-source agent frameworks）的環境（environment）、一個受控的網頁應用程式（controlled web-based application）、一個結構良好的任務套件（task suite），以及一個具備多樣化指標（diverse metrics）的自動化評估引擎（automated evaluation engine）。與廣泛預期相反，我們的實證結果顯示，前沿智慧體系統（frontier agentic systems）仍遠未達到人類水準表現（human-level performance）。即使是最先進的智慧體（state-of-the-art agent），在我們的 GauntletBench 上僅達到 19.1% 的成功率（success rate），凸顯了這些被忽視的能力（overlooked capabilities）與泛化方面的侷限性。相較之下，非專家級人類標註者（non-expert human annotators）在我們具挑戰性但可行的任務上達到超過 80% 的成功率，揭示了現有智慧體的能力與複雜真

## 深度分析

#### 方法論解析

GauntletBench 的核心方法論在於建立一個模組化流程（modular pipeline），將智慧體（agents）置於統一的網頁式環境（web-based environment）中進行評估。該環境形式化定義為 E = (S, A, O, T, R)，其中 S 為狀態空間（state space），A 與 O 分別代表動作空間（action space）與觀察空間（observation space），T 為轉移函數（transition function），R 則是獎勵函數（reward function）。此設計確保了與開源智慧體框架（open-source agent frameworks）及閉源智慧體框架（closed-source agent frameworks）的相容性（compatibility）。

在觀察空間（observation space）的設計上，為了強迫智慧體依賴視覺感知（visual perception），作者刻意限制僅提供高階介面（如 Playwright），而不暴露低階瀏覽器 API（如 Chrome DevTools Protocol）。針對三維建模器（3D Modeller）、航班分析器（Flight Analyser）與電路設計器（Circuit Designer），系統僅提供畫布式介面（canvas-based interfaces），智慧體必須透過螢幕截圖（screenshots）來理解網頁狀態；而影片編輯器（Video Editor）與工作流程建構器（Workflow Builder）則額外提供無障礙樹（Accessibility Tree）以補充語意資訊，但單靠結構化元素並不足以完成任務，視覺資訊（visual information）仍是必要條件。

動作空間（action space）採用高階指令集，模擬標準使用者互動（standard user interactions），包含點擊（click）、輸入（type）、選取（select）、捲動（scroll）與導航（navigation）等操作，並透過瀏覽器自動化層（browser automation layer，如 Playwright）執行。這種設計避免了直接操作 DOM 的捷徑，確保評估貼近真實世界情境（real-world scenarios）中的人機互動模式。

在應用程式層面，GauntletBench 建構了五個較少被涵蓋的專業應用程式（less-covered professional applications），分別為影片編輯器（Video Editor）、工作流程建構器（Workflow Builder）、三維建模器（3D Modeller）、航班分析器（Flight Analyser）與電路設計器（Circuit Designer）。每個應用包含 20 個視覺密集型任務（vision-intensive tasks），總計 100 個任務，並分為簡易（easy）、中等（medium）、困難（hard）三個難度等級。任務結構標準化，包含應用程式背景（application background）、任務描述（task description）與結果格式（result format），以確保評估的一致性。

評估引擎（evaluation engine）採用自動化設計，整合客製化客觀評估器（tailored objective evaluators），並提供多樣化指標（diverse metrics）：包含成功率（success rate）、多模態大型語言模型評斷的進度率（MLLM-judged progress rate），以及效率指標（efficiency measures）。此設計特別針對三項被忽視的能力（overlooked capabilities）——時序感知（temporal perception）、圖形理解（graphical understanding）與三維推理（3D reasoning）——進行探測，填補了現有基準測試（benchmarks）在這些維度上的空白。

#### 實驗數據解讀

實驗結果揭示了當前前沿智慧體系統（frontier agentic systems）與人類水準表現（human-level performance）之間存在顯著落差。在 GauntletBench 上，多數開源多模態大型語言模型（MLLMs）智慧體，如 Qwen-3-VL 與 Llama-4-Maverick，僅取得接近零的表現；而基於 API 的 MLLM 智慧體，其成功率（success rate）最高也未超過 13.2%。

即便是最先進的閉源智慧體框架（closed-source agent frameworks），表現同樣遠低於預期：GPT Computer Use 僅達 4.3%，Gemini Enterprise 為 13.7%，而表現最佳的 Claude Opus Computer Use 也僅有 19.1%。這項數據強烈顯示，現有智慧體在面對不熟悉介面與複雜視覺推理時，其泛化能力（generalisation）與被忽視的能力（overlooked capabilities）仍存在嚴重侷限性（limitations）。

相對地，非專家級人類標註者（non-expert human annotators）在未具備特定領域知識的情況下，成功率（success rate）超過 80%，且所需步驟較最佳智慧體減少 30%。這項對比具有雙重意涵：首先，GauntletBench 的任務設計屬於「具挑戰性但可行」（challenging yet feasible），並非過度艱澀而無法完成；其次，當前智慧體在真實世界情境（real-world scenarios）中的實用性仍大幅落後於人類，尤其是在需要時序感知（temporal perception）、圖形理解（graphical understanding）與三維推理（3D reasoning）的專業應用程式（professional applications）中。

從效率指標（efficiency measures）觀察，人類不僅正確率更高，行動也更為精簡，暗示現有智慧體可能存在過度探索（excessive exploration）或錯誤規劃的問題。整體而言，19.1% 的性能天花板（performance ceiling）清楚表明，現有基準測試（benchmarks）的性能飽和（saturated performance）並不代表智慧體已接近通用人工智能，而是反映了舊有評估框架未能觸及的盲點。

#### 與現有研究的比較

相較於現有基準測試（benchmarks），GauntletBench 的主要差異在於刻意迴避熱門應用程式（popular applications）如 Amazon、Booking 或 CRM 系統，這些環境往往具有高度同質性（homogeneous settings）與幾乎相同的複製品（near-identical replicas），導致任務相似度過高且過於簡單。現有基準通常聚焦於狹隘的能力集合，如使用者介面理解（UI understanding）、工具使用（tool use）與長期推理（long-term reasoning），卻忽略了更廣泛且關鍵的智慧體表現（agentic performance）面向。

GauntletBench 透過引入較少被涵蓋的應用程式（less-covered applications）與視覺基礎任務（visually grounded tasks），成功突破了性能飽和（saturated performance）的困境，提供了一個能夠真正探測智慧體極限的評估場域。此外，其模組化流程（modular pipeline）解決了現有基準在支援新智慧體框架時常見的繁複流程（intricate pipelines）、有限相容性（limited compatibility）與僵化配置（rigid configurations）等問題，同時支援開源與閉源系統的無縫整合。

然而，本研究仍存在若干侷限性（limitations）。首先，五個專業應用程式（professional applications）雖涵蓋了三維推理（3D reasoning）等關鍵能力，但應用領域仍屬有限，尚未擴展至更多元的產業情境。其次，部分評估指標依賴多模態大型語言模型（MLLMs）作為評判者，雖然提升了自動化程度，但可能引入模型自身的偏誤。第三，所有應用均為網頁式（web-based），雖然確保了可控性（controllability）與可重現性（reproducibility），但與原生桌面應用程式（native desktop applications）相比，互動模式仍存在差異，可能無法完全反映某些真實世界情境（real-world scenarios）的複雜度。

#### 可重現性評估

GauntletBench 在可重現性（reproducibility）方面採取了相對開放的策略。根據論文所述，其首頁（homepage）、程式碼（code）與任務（tasks）均已公開釋出，使其他研究者能夠復現完整的模組化流程（modular pipeline）。受控的網頁應用程式（controlled web-based applications）採用現代網頁技術建構，可在標準瀏覽器環境中執行，降低了部署門檻。

自動化評估引擎（automated evaluation engine）的設計進一步確保了評估結果的一致性，其客製化客觀評估器（tailored objective evaluators）減少了人工評分的主觀變異。然而，可重現性仍面臨若干挑戰：雖然基準測試（benchmark）本身開源，但部分受測的閉源智慧體框架（closed-source agent frameworks）——如 GPT Computer Use、Gemini Enterprise 與 Claude Opus Computer Use——並未公開模型權重（model weights），且其 API 行為可能隨時間更新，導致長期復現存在變數。此外，使用多模態大型語言模型（MLLMs）作為進度評判者時，不同模型版本或提示詞（prompt）設計的差異，可能影響 MLLM-judged progress rate 的一致性。

整體而言，GauntletBench 在環境與任務層面提供了良好的可重現性基礎，但針對閉源商業模型的評估結果，研究者應詳細記錄 API 版本與實驗時間戳，以確保結果的可比較性。

#### 未來研究方向

基於 GauntletBench 所揭示的性能落差，未來研究可朝以下方向推進。首先，在能力強化方面，亟需發展針對時序感知（temporal perception）、圖形理解（graphical understanding）與三維推理（3D reasoning）的專門訓練方法，例如透過強化學習（reinforcement learning）或合成資料生成（synthetic data generation）來縮小人類與智慧體（agents）間的表現鴻溝。

其次，在介面泛化（interface generalisation）上，當前智慧體在畫布式介面（canvas-based interfaces）與專業應用程式（professional applications）中的表現顯示，視覺感知（visual perception）與精細動作控制仍有極大進步空間。未來可探索更強大的視覺編碼器（visual encoders）或結合無障礙樹（Accessibility Tree）與視覺資訊（visual information）的多模態融合策略，以提升在複雜網頁環境中的操作精準度。

第三，在評估方法論上，應擴展基準測試（benchmark）的覆蓋範圍，納入更多元的專業領域與原生應用程式（native applications），並開發更穩健的自動化評估指標，減少對多模態大型語言模型（MLLMs）評判者的依賴，例如引入基於規則的驗證（rule-based verification）或像素級比對（pixel-level comparison）等客觀機制。

第四，在效率最佳化方面，由於人類標註者（human annotators）使用的步驟較前沿智慧體（frontier agents）減少 30%，未來研究可聚焦於發展更高效的探索策略（exploration strategies）與任務規劃演算法，避免智慧體在執行過程中產生冗餘動作。最後，隨著智慧體系統（agentic systems）持續演進，建立動態擴展的基準測試框架，使其能持續納入新興應用與能力維度，將是維持評估忠實度（faithful evaluation）的關鍵。

## 論文問答

**Q1：GauntletBench 旨在解決智慧體系統評估中的什麼核心問題？**
A：隨著智慧體系統日益部署於複雜的真實世界情境，現有基準測試大多建構於熱門應用程式之上，任務相對簡單且同質性過高，導致性能飽和，無法忠實反映智慧體的侷限性。這種評估上的落差使得研究者難以準確掌握智慧體在面對不熟悉環境時的泛化能力。因此，GauntletBench 的提出正是為了填補這一缺口，針對更具挑戰性的情境提供嚴謹且真實的評估架構。

**Q2：為何現有的基準測試方法無法忠實評估現代智慧體的能力？**
A：現有基準測試通常運作於高度同質性的環境中，使用幾乎相同的複製品或熱門應用程式，任務設計過於簡單且相似度高，不足以探測當前智慧體系統的極限。此外，這些測試往往僅聚焦於狹隘的能力面向，例如使用者介面理解、工具使用與長期推理，卻忽略了時序感知、圖形理解與三維推理等更廣泛且關鍵的面向。再加上繁複的流程、有限的相容性與僵化的配置，使得這些基準測試難以持續支援新興的智慧體框架，最終導致不準確的評估結果。

**Q3：為何超越熟悉環境來重新評估智慧體能力變得越來越重要？**
A：現代智慧體系統已從被動型助理轉變為能夠自主互動與執行的智慧型智慧體，並廣泛部署於從面向消費者到企業應用程式的多元領域。隨著這些系統需要處理日益複雜的真實世界情境，評估方式也必須相應提升，才能準確衡量其在實際應用中的表現。若評估僅限於簡單且熟悉的環境，將無法揭露智慧體在複雜場景中的關鍵侷限性，進而導致對其能力過度樂觀的錯誤認知。

**Q4：GauntletBench 的核心設計是什麼，包含哪些主要組成部分？**
A：GauntletBench 是一個網頁式基準測試，採用模組化流程設計，由四大核心組件構成：環境、受控的網頁應用程式、任務套件以及自動化評估引擎。該平台建構了五個較少被涵蓋的專業應用程式，包含影片編輯器、工作流程建構器、三維建模器、航班分析器與電路設計器，共計一百個視覺密集型任務。整體設計旨在透過視覺基礎任務，針對時序感知、圖形理解與三維推理等三項被忽視的能力，評估智慧體在具挑戰性情境中的泛化表現。

**Q5：與現有基準測試相比，GauntletBench 的關鍵創新之處為何？**
A：GauntletBench 的關鍵創新在於首次系統性地將評估焦點放在代表性不足的能力與較少被涵蓋的專業應用程式上，而非僅限於常見的消費型平台。其模組化架構同時支援開源智慧體框架與閉源智慧體框架，並配備自動化評估引擎與多樣化指標，大幅提升相容性與可擴展性。此外，所有任務均經過難度校準，涵蓋從基礎視覺理解到高階三維推理的連續光譜，能夠更精確地探測智慧體的泛化極限。

**Q6：GauntletBench 在觀察空間與動作空間的設計上做出了哪些關鍵選擇？**
A：為了確保智慧體必須依賴視覺感知完成任務，GauntletBench 僅提供高階觀察介面（如 Playwright），不開放低階瀏覽器 API，並強制以螢幕截圖作為主要觀察來源。在部分應用程式中雖輔以無障礙樹提供語意資訊，但單靠結構化元素無法完成視覺密集型任務，因此視覺資訊仍是成功的必要條件。動作空間則模擬標準使用者互動，包含點擊、輸入、選取與捲動等高階指令，透過瀏覽器自動化層執行，確保互動模式貼近真實人類操作。

**Q7：GauntletBench 由哪些應用程式與任務組成，其結構如何設計？**
A：GauntletBench 包含五個專業應用程式：影片編輯器、工作流程建構器、三維建模器、航班分析器與電路設計器，每個應用程式設有二十個任務，總計一百個具挑戰性但人類可完成的任務。任務難度分為簡單、中等與困難三個等級，並遵循標準化結構，包含應用程式背景、任務描述與結果格式。這種設計不僅能系統性地評估智慧體在不同難度下的表現，也確保了評估的可重現性與可比較性。

**Q8：關於前沿智慧體在 GauntletBench 上的表現，有哪些關鍵實證發現？**

**Q10：GauntletBench 測試的能力在哪些真實世界情境中最為關鍵？**
A：GauntletBench 所評估的時序感知、圖形理解與三維推理能力，在許多專業領域的企業應用程式中至關重要，例如影片後製、自動化工作流程設計、三維建模與模擬、航空數據分析以及電路設計等。這些情境遠比常見的消費型應用複雜，要求智慧體不僅能理解使用者介面，還必須具備跨模態感知與空間推理能力。隨著智慧體系統逐漸從簡單的客服或購物助理擴展至工業與創意產業，能否在這類視覺密集型任務中穩定運作，將成為決定其商業落地價值的關鍵因素。

**Q13：論文中描述了 GauntletBench 哪些固有的侷限性或範圍邊界？**
A：GauntletBench 目前主要聚焦於時序感知、圖形理解與三維推理這三項被忽視的能力，並且僅在五個特定的專業網頁應用程式中進行評估，尚未涵蓋所有可能的真實世界領域。其任務設計雖然視覺密集且具挑戰性，但互動方式仍限制於高階指令集，例如點擊與輸入，而非更低階的底層操作。此外，由於應用程式均為受控的網頁環境，對於需要與桌面原生軟體或實體世界感測器互動的情境，其評估範圍仍存在一定邊界。

## 實務應用指南

### 適用場景

1. **多媒體內容自動化審查與編輯**：在影視後製或社群媒體營運中，利用具備時序感知能力的智慧體，自動執行影片剪輯、片段插入與時間軸對齊等視覺密集型任務，減少人工逐格檢視的成本。
2. **企業流程視覺化驗證與自動化**：將工作流程建構器整合至企業應用程式中，透過圖形理解能力驗證複雜業務流程圖的邏輯正確性，並自動修正節點連結或使用者權限配置。
3. **工業設計原型快速驗證**：在三維建模器與電路設計器等專業應用程式中，部署智慧體進行初步的幾何推理與電路圖形分析，協助工程師在進入實際生產前完成設計瑕疵的篩選。
4. **航運與物流監控決策支援**：運用航班分析器類型的受控環境，結合時序感知與圖形理解，讓智慧體從大量航班動態圖表中識別關鍵時序事件（如最後進場航班），輔助調度人員進行即時決策。
5. **智慧體能力回歸測試平台**：將 GauntletBench 的模組化流程嵌入產品開發週期，作為持續評估前沿智慧體系統在複雜真實世界情境中是否出現性能飽和或泛化落差的內部基準測試工具。

### 實作前置條件

**資料需求**：
- 目標專業應用程式的視覺基礎任務定義，包含應用程式背景、任務描述與結果格式標準化文件。
- 用於校準難度的人類標註資料（建議涵蓋非專家級人類標註者的執行軌跡與成功率，作為人類水準表現基準）。
- 應用程式截圖、無障礙樹（Accessibility Tree）結構資料，以及用於評估引擎的參考答案或驗證規則。

**運算需求**：
- 具備瀏覽器自動化層（如 Playwright）的伺服器環境，用於執行受控的網頁應用程式。
- 執行多模態大型語言模型（MLLMs）的 GPU 叢集或 API 配額，需支援開源與閉源智慧體框架的呼叫。
- 自動化評估引擎的後端運算資源，用於執行客觀評估器與 MLLM-judged 進度率計算。

**技能需求**：
- 熟悉網頁前端技術與瀏覽器自動化，能建構僅提供畫布（canvas-based）或混合無障礙樹的觀察空間。
- 具備設計多樣化指標與自動化評估引擎的能力，能處理閉源智慧體框架的黑箱評估需求。
- 對目標領域（如影片編輯、三維建模、電路設計）有基礎認知，以確保任務設計符合「具挑戰性但人類可完成」的標準。

### 實作步驟建議

**步驟一：建構受控的網頁應用程式環境**
依據目標能力（時序感知、圖形理解、三維推理）選定 3–5 個較少被涵蓋的專業應用程式，使用現代網頁技術開發，確保僅透過高階觀察介面（截圖為主，輔以無障礙樹）與高階動作指令（點擊、輸入、捲動等）進行互動，避免暴露低階瀏覽器 API。

**步驟二：設計視覺基礎任務套件**
針對每個應用程式設計約 20 個任務，橫跨簡單、中等、困難三個難度等級。任務必須強制智慧體依賴視覺資訊才能完成，避免僅靠結構化元素即可推導答案。每個任務需包含標準化的背景說明、任務描述與結果格式。

**步驟三：整合智慧體框架**
開發統一環境介面 `E = (S, A, O, T, R)`，支援開源智慧體框架（如 Qwen-3-VL、Llama-4-Maverick）與閉源智慧體框架（如 GPT Computer Use、Gemini Enterprise）的無縫接入。確保觀察空間 `O` 與動作空間 `A` 的定義與所有框架相容。

**步驟四：開發自動化評估引擎**
建置包含客觀評估器（Objective Evaluator）與 MLLM-judged 進度率的混合評估系統，輸出成功率、效率指標（如執行步驟數）與細部能力維度分數。針對閉源框架，確保評估流程無需人工介入即可自動化運行。

**步驟五：人類基準校準與難度驗證**
邀請非專家級人類標註者執行任務，確認人類成功率超過 80% 且執行步數顯著低於智慧體，以此驗證任務的「挑戰性但可行」屬性。若人類表現過低，需簡化任務；若智慧體表現過高，需增加視覺推理複雜度。

**步驟六：部署至產品測試或研究流程**
將 GauntletBench 模組化流程整合至 CI/CD 或模型釋出前的回歸測試，定期檢視前沿智慧體系統是否在人類水準表現上取得進展，或是否仍在特定能力維度存在侷限性。

### 潛在風險與注意事項

**過度依賴結構化觀察導致評估失真**
若智慧體可僅透過 Accessibility Tree 或 DOM 結構完成任務，將無法真實評估視覺感知能力。**緩解措施**：對三維建模器、航班分析器等應用強制僅提供畫布介面；對影片編輯器等應用確保視覺資訊為完成任務的必要條件。

**任務同質性造成性能飽和**
若任務設計過於相似或僅基於熱門應用，智慧體可能透過記憶或簡單模式匹配達成高成功率，無法探測泛化侷限。**緩解措施**：選擇較少被涵蓋的專業應用程式，並在任務中引入跨應用的視覺與推理變異。

**自動化評估引擎的偏差**
單一指標（如僅看最終成功率）可能掩蓋智慧體的局部進展或特定失敗模式。**緩解措施**：採用多樣化指標，結合客觀評估與 MLLM-judged 進度率，並針對不同能力維度（時序、圖形、三維）拆解評分。

**泛化落差與真實世界情境脫節**
在受控網頁環境中表現良好的智慧體，面對實際企業應用程器的非預期狀態時可能失效。**緩解措施**：定期將受控環境的評估結果與真實世界情境的試點測試進行對照，並保留人機協作（Human-in-the-loop）的容錯機制。

### 與其他技術的整合建議

**瀏覽器自動化與網頁技術棧**
直接基於 Playwright 或 Selenium 建構環境層，確保與現代網頁應用程式的自然互動模式。若需評估閉源智慧體框架，可透過 Docker 化部署隔離不同版本的瀏覽器環境，保證可重現性。

**多模態大型語言模型 API**
在評估引擎中整合 GPT-4V、Gemini、Claude 等 API 作為評判模型（Judge Model），用於計算進度率與語意層面的任務完成度。同時在智慧體端支援透過統一介面切換不同 MLLM 後端，便於進行 A/B 測試。

**企業內部系統（CRM / ERP / 設計軟體）**
將 GauntletBench 的模組化流程視為評估即服務（Evaluation-as-a-Service），透過 API 閘道與企業內部系統對接。針對內部客製化應用，可替換論文中的五個專業應用程式為企業自有工具，保留相同的任務結構與評估邏輯。

**持續整合 / 持續部署（CI/CD）**
將自動化評估引擎嵌入模型釋出流程，設定成功率閾值（如低於 20% 即阻擋釋出），作為智慧體表現回歸測試的閘道。搭配日誌記錄系統，追蹤每次迭代在特定能力維度的提升或衰退。

### 給不同背景讀者的閱讀建議

**初學者**：請聚焦於論文揭示的核心訊息——即使最先進的智慧體在複雜真實世界情境中，其成功率仍遠低於非專業人類。建議從圖一與各應用程式的任務範例開始，理解為何現有基準測試無法反映此差距，並思考「視覺密集型任務」對智慧體的難度所在。

**AI 工程師**：請深入研讀第 2.1 節至 2.4 節的模組化流程實作細節，特別是觀察空間與動作空間的設計取捨（例如為何限制低階瀏覽器 API、如何平衡截圖與 Accessibility Tree）。評估引擎的多樣化指標設計與跨框架相容性策略，可直接作為您建構內部評測平台的參考架構。

**研究人員**：本文的貢獻在於重新定義了智慧體泛化的評估維度。建議關注三種被忽視能力（時序感知、圖形理解、三維推理）的任務設計邏輯，以及為何現有基準測試在同質性環境中導致性能飽和。可進一步探討將此框架延伸至其他未被充分探索的感知模態或推理範疇。

**產品經理**：請將本文視為一份「技術可行性風險評估報告」。論文數據明確指出，在影片編輯、電路設計等專業領域，當前前沿智慧體系統尚不適合全自動化部署。建議據此規劃人機協作的产品路線圖，優先投資於智慧體輔助而非完全替代人類的應用場景，並將 GauntletBench 作為評估供應商模型能力的標準化工具。
