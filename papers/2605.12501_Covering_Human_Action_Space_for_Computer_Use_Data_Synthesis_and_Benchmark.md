## 摘要翻譯

電腦使用代理（CUAs）自動化螢幕上的工作，以 GPT-5.4 和 Claude 為例。然而，它們在複雜、低頻互動上的可靠性仍然不佳，限制了使用者信任。我們對先進模型失敗案例的分析顯示，GUI 操作中存在長尾模式：相對少數的複雜且多樣化互動，佔了不成比例的任務失敗。我們假設此問題主要源自於複雜互動資料的稀缺。為解決此問題，我們提出新的基準測試 CUActSpot，用於評估模型在五種模態（GUI、文字、表格、畫布和自然影像）以及各種動作（點擊、拖曳、繪製等）上的複雜互動能力。此基準測試涵蓋範圍更廣的互動類型，比先前以點擊為中心、主要專注於 GUI 小工具的基準測試更為全面。我們也設計了基於渲染器的資料合成管線：為每種模態自動生成場景，記錄螢幕截圖與元素座標，並由 LLM 產生匹配指令與動作軌跡。在此語料庫上訓練後，我們的 Phi-Ground-Any-4B 超越了參數少於 32B 的開源模型。我們將於下列網址釋出基準測試、資料、程式碼與模型：https://github.com/microsoft/Phi-Ground.git

### 核心貢獻（3～5點）
- **問題診斷**：透過分析先進模型的失敗案例，揭示 GUI 操作中的長尾模式——少數複雜且多樣化的互動佔據了不成比例的任務失敗比例，凸顯複雜互動資料稀缺的核心問題。
- **新基準測試 CUActSpot**：涵蓋五種模態（GUI、文字、表格、畫布、自然影像）與多元動作類型（點擊、拖曳、繪製等），突破既有以點擊為中心之基準測試的侷限。
- **資料合成方法**：提出基於渲染器的資料合成管線，能自動為各模態生成場景、記錄螢幕截圖與元素座標，並由 LLM 產生對應指令與動作軌跡。
- **模型實證成果**：所訓練的 Phi-Ground-Any-4B 在效能上超越參數少於 32B 的開源模型，驗證了資料合成策略的可行性。
- **開源釋出**：將基準測試、資料、程式碼與模型於 GitHub 公開釋出，促進後續研究發展。

### 適合對象
本論文最適合以下讀者閱讀：

## 深度分析

#### 方法論解析

本論文的核心方法論圍繞「長尾失敗模式」（long-tail pattern）的觀察展開，並提出雙軌解決方案：基準測試建構與資料合成管線。

**1. 失敗模式分析框架**

作者首先透過使用者研究（user study），在 Azure OpenAI 平台上對 GPT-5.4 的電腦使用能力進行系統性評估。實驗設計涵蓋三大場景：工作（Work）、網頁使用（Web）、遊戲（Game），共收集近 200 個任務，並在 Windows 虛擬機（VM）中執行。失敗案例被分類為兩大類：定位錯誤（Grounding Error, GE）與規劃錯誤（Planning Error, PE），並排除系統錯誤（System Error）——後者源於虛擬機或互動工具（如 PyAutoGUI）的隨機不穩定性（stochastic instability）。

關鍵發現是：在工作場景中，定位錯誤佔絕對主導（2837 例 vs. 規劃錯誤的 13 例），且複雜互動（drag & other）的失敗率遠高於簡單點擊（click）。這一觀察揭示了 GUI 動作定位（GUI Action Grounding）領域的結構性偏差：現有基準測試與訓練資料均以「小工具為中心、點擊為中心」（widget-centric, click-centric）為主，導致模型在拖曳、繪製等複雜操作上表現不佳。

**2. CUActSpot 基準測試設計**

CUActSpot 的設計理念是「降低領域特定知識要求、提升互動類型多樣性」。其涵蓋五種模態（modalities）：
- **GUI**：傳統的小工具互動
- **Text**：文件中的文字操作
- **Table**：表格中的儲存格定位
- **Canvas**：畫布上的繪製與拖曳
- **Natural Image**：自然影像中的物件邊界追蹤

動作類型從單一的點擊（click）擴展到拖曳（drag）、繪製（draw）等。這種設計直接挑戰了 ScreenSpot-Pro 等既有基準測試的「高解析度專業軟體 + 單擊小工具」範式。

**3. 基於渲染器的資料合成管線（renderer-based data-synthesis pipeline）**

這是本文最具技術創新性的部分。管線分為三階段：
1. **場景自動生成**：透過程式碼為每種模態生成場景
2. **截圖與座標記錄**：渲染過程中自動擷取螢幕截圖（screenshots）與元素座標（element coordinates）
3. **指令與動作軌跡合成**：利用大型語言模型（LLM）產生匹配指令（matching instructions）與動作軌跡（action traces）

此方法的優勢在於：相較於網路爬蟲與無障礙樹（accessibility tree）為基礎的傳統管線，渲染器管線能夠精確控制座標資訊，並支援非小工具模態（如畫布、自然影像）。最終生成 5000 萬筆樣本（50M samples），可用於預訓練或中期訓練（mid-training）。

**4. 訓練策略與「多樣性擴展」現象**

作者在消融研究（ablation studies）中發現一個重要現象——「多樣性擴展」（variety scaling）：相較於在單一模態內單純擴增資料量，提升資料多樣性能更顯著改善模型的通用互動能力。這一發現對資料擴增策略具有指導意義。

#### 實驗數據解讀

**1. 失敗案例統計的意涵**

圖 2 的數據揭示了幾個關鍵訊號：
- 工作場景的定位錯誤（2837）遠超網頁（1812）與遊戲（168），反映專業軟體操作的複雜性
- 遊戲場景中規劃錯誤（47）相對突出，暗示遊戲需要更強的長期策略規劃
- 「GE included success」指標顯示，即使最終任務成功，仍可能存在定位層面的不精確，這對穩健性（robustness）評估至關重要

**2. CUActSpot 與既有基準測試的相關性**

作者聲稱 CUActSpot 與端到端代理基準測試（如 OSWorld）的一致性高於傳統 GUI 定位基準測試。這意味著 CUActSpot 能更好地反映真實電腦使用場景中的失敗模式，而非僅僅測量「在小工具上點對位置」這種狹隘能力。

**3. Phi-Ground-Any-4B 的效能定位**

模型在參數量少於 32B 的開源模型中達到最先進效能（state-of-the-art）。雖然具體數字未在提供的文本中給出，但「4B vs. 32B」的參數效率比暗示了資料合成管線的價值——透過高品質合成資料，小模型可逼近更大模型的表現。

**4. 消融研究的啟示**

「多樣性擴展」現象的發現挑戰了傳統的「資料量至上」觀點。在 GUI 動作定位領域，橫向擴展（更多模態與動作類型）可能比縱向擴展（更多同類樣本）更具效益。

#### 與現有研究的比較

**1. 與模組化 CUA 的比較**

模組化 CUA（如 UGround、SeeClick、OS-Atlas）將規劃與定位分離，由前沿視覺語言模型（VLM）擔任規劃器，專門的定位模型負責低階動作。這種架構的瓶頸在於自然語言介面會損失空間與上下文資訊。本文的 Phi-Ground-Any-4B 屬於定位模型，但其訓練資料涵蓋更廣泛的互動類型，可作為模組化 CUA 的更強定位組件。

**2. 與端到端 CUA 的比較**

端到端 CUA（如 Claude Computer Use、OpenAI CUA、UI-TARS、OpenCUA、MAI-UI、EvoCUA）將感知、推理與定位統一於單一模型，支援聯合最佳化但需要大量訓練資料。本文並未直接提出端到端模型，而是透過改善定位能力間接促進端到端系統的表現。

**3. 與既有定位基準測試的比較**

| 基準測試 | 互動類型 | 模態範圍 | 領域知識要求 |
|---------|---------|---------|------------|
| ScreenSpot-Pro | 單擊 | GUI 小工具 | 高（專業軟體） |
| 既有基準測試 | 單擊 | GUI 小工具 | 中 |
| CUActSpot | 點擊、拖曳、繪製 | 五種模態 | 低 |

CUActSpot 的差異化定位在於「降低領域知識要求 + 提升互動複雜度」，這與 ScreenSpot-Pro 的「提升領域知識難度」路線形成互補。

**4. 局限性**

- **資料合成的真實性差距**：渲染器生成的場景與真實螢幕內容存在分布差距（distribution gap），可能影響模型在真實環境中的泛化能力
- **基準測試規模**：作為手動建構的基準測試，CUActSpot 的規模可能有限，難以支撐大規模自動化評估
- **遊戲場景覆蓋不足**：從失敗分析來看，遊戲是規劃錯誤的高發區，但 CUActSpot 主要聚焦於工作場景的互動類型

#### 可重現性評估

本文在可重現性方面表現優異：

1. **完整開源承諾**：作者明確聲明將釋出基準測試（CUActSpot）、訓練資料、程式碼與模型權重，託管於 GitHub（https://github.com/microsoft/Phi-Ground.git）
2. **資料規模透明**：5000 萬筆樣本的規模已公開，便於研究者估算訓練成本
3. **管線可重複**：基於渲染器的合成管線具有確定性，相同程式碼可重現相同資料
4. **模型規模明確**：Phi-Ground-Any-4B 的 4B 參數規模便於在消費級硬體上部署與驗證

潛在的可重現性風險包括：
- 渲染器管線依賴特定的軟體環境與函式庫版本，需注意環境配置
- LLM 合成指令的隨機性可能導致資料不完全可重現
- 評估指標的具體計算方式需在程式碼中仔細核對

#### 未來研究方向

**1. 渲染器管線的擴展**

當前管線涵蓋五種模態，但人類電腦使用的動作空間遠不止於此。未來可探索：
- 三維互動（如 3D 建模軟體中的視角操作）
- 多手指觸控手勢（平板電腦場景）
- 跨應用拖放（drag-and-drop between applications）

**2. 與端到端 CUA 的整合**

Phi-Ground-Any-4B 作為定位組件，可進一步研究如何與規劃器無縫整合，減少自然語言介面的資訊損失。或可探索將定位能力蒸餾（distill）到端到端模型中。

**3. 真實場景的領域適應（domain adaptation）**

渲染器資料與真實螢幕的分布差距是關鍵挑戰。未來可研究：
- 風格遷移（style transfer）技術縮小差距
- 少量真實資料的微調策略
- 合成-真實混合訓練的最佳比例

**4. 規劃錯誤的深入分析**

本文聚焦於定位錯誤，但遊戲場景的規劃錯誤同樣值得關注。未來可建構專門評估長期規劃能力的基準測試，與 CUActSpot 形成互補。

**5. 「多樣性擴展」現象的理論解釋**

為何橫向多樣性比縱向資料量更有效？這涉及模型的泛化理論、損失函式的幾何結構等基礎問題，值得從理論角度深入分析。

**6. 多模態大型語言模型的原生支援**

隨著 GPT-5.4、Claude 等模型原生支援電腦使用，未來可研究如何將 Phi-Ground-Any-4B 的定位能力整合到這些模型的訓練流程中，或作為其定位子系統的替代方案。

**7. 安全性與可控性**

電腦使用代理的部署涉及安全性風險（如誤刪檔案、隱私洩漏）。未來可研究如何在 CUActSpot 等基準測試中加入安全性評估維度，確保模型在提升能力的同時維持可控性。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？為什麼這個問題對電腦使用代理（CUA）的實際部署至關重要？**
A：這篇論文聚焦於電腦使用代理（CUA）在複雜、低頻率互動上的可靠性低落問題。作者透過對 GPT-5.4 的失敗案例分析，發現 GUI 操作中存在明顯的長尾模式——相對少數的複雜且多樣的互動行為，卻佔據了不成比例的任務失敗比例。這項問題直接影響使用者對 CUA 的信任，因為在 Word、PPT、Excel、Photoshop 等真實工作場景中，代理必須處理拖曳、繪製、跨模態操作等非單擊動作。若無法解決此瓶頸，即使頂尖模型也難以在實際部署中取代人類完成數位工作，因此這個問題對 CUA 從實驗室走向生產環境具有決定性的意義。

**Q2：現有的 GUI 定位基準測試為什麼無法反映 CUA 在真實場景中面臨的挑戰？**
A：現有的基準測試（如 ScreenSpot-Pro 等）雖然刻意提高難度，但難度來源主要是高解析度專業介面或軟體特定知識，且任務幾乎都侷限於單擊動作，目標也以 GUI 小工具為主。然而作者透過實證觀察發現，CUA 在真實工作中經常需要操作表格、文件、圖表、自然影像等非小工具物件，並透過拖曳、繪製等更複雜的互動完成任務。這種基準測試與實際需求之間的錯位，導致模型開發方向也被誤導——業界普遍以「小工具中心、點擊中心」為前提進行訓練與評估，使得複雜互動在訓練與評測兩端都遭到忽視。

**Q3：作者如何從 GPT-5.4 的使用者研究中歸納出「動作定位」是 CUA 失敗的最關鍵因素？**
A：作者在 Azure OpenAI 平台上對 GPT-5.4 進行了一項使用者研究，收集了近 200 個涵蓋工作、網頁使用、遊戲三種情境的任務，並在 Windows 虛擬機中執行，系統性地分析所有排除系統錯誤後的失敗案例。結果顯示，在使用者最關心的「工作」情境中，定位錯誤（GE）佔絕大多數（2837 次），遠高於規劃錯誤（PE，僅 13 次）。這項數據強烈表明，無論是高階的規劃能力或語言理解能力，若底層的螢幕座標定位不準確，整個端到端任務仍會失敗，因此動作定位被認定為 CUA 部署的核心瓶頸。

**Q4：CUActSpot 基準測試的核心設計理念是什麼？它與傳統基準測試的根本差異為何？**
A：CUActSpot 的核心設計理念是「涵蓋人類在電腦上的完整動作空間」，因此它橫跨五種模態——GUI、文字、表格、畫布、自然影像——並納入點擊、拖曳、繪製等多樣動作類型，例如在 Photoshop 中描繪物件輪廓以進行影像去背。這與傳統以點擊為中心、聚焦 GUI 小工具的基準測試形成鮮明對比，因為後者只涵蓋了人類動作空間中的一小部分。更重要的是，作者刻意降低任務對軟體特定知識的需求，使基準測試更能反映通用的互動能力，而非特定領域的記憶與專業知識。

**Q5：作者提出的「基於渲染器的資料合成管線」是如何運作的？為什麼這種設計比傳統方法更有效？**
A：這條管線的核心思路是「以程式碼取代人工」：系統會針對每種模態自動生成場景，透過渲染器記錄螢幕截圖與元素座標，再由大型語言模型產生對應的自然語言指令與動作軌跡。這種設計的優勢在於可擴展性與一致性——相較於仰賴網路爬蟲與無障礙樹（accessibility tree）的傳統方法，它能產生精確的座標標註並涵蓋非小工具模態（如畫布、自然影像），而這些模態在真實網頁中根本無法透過 DOM 取得。最終這條管線產生了 5000 萬筆樣本，足以支援模型預訓練或中期訓練。

**Q6：作者提出的「多樣性擴展（variety scaling）」現象指的是什麼？它對資料策略有何啟示？**
A：「多樣性擴展」是作者在消融實驗中觀察到的關鍵現象：相較於在單一模態內單純放大資料量，提升跨模態、跨動作類型的資料多樣性，更能顯著改善模型的整體互動能力。這項發現挑戰了傳統「資料越多越好」的縮放定律直覺，提示研究者在設計訓練語料時，應優先考慮覆蓋率的廣度而非單一領域的深度。對整個領域而言，這意味著未來的 CUA 訓練資料應朝向異質性、多模態整合的方向發展，而非僅聚焦於網頁小工具的點擊資料。

**Q7：Phi-Ground-Any-4B 在哪些評估中展現出競爭力？具體的效能數字為何？**
A：Phi-Ground-Any-4B 在參數量低於 32B 的開源模型中達到了最先進的效能。雖然具體數字需參考論文實驗表格，但作者強調該模型在 CUActSpot 基準測試上表現出色，且其效能分數與端到端代理基準（如 OSWorld）的結果更為一致，這顯示 CUActSpot 確實能反映真實的電腦使用場景。值得注意的是，Phi-Ground-Any-4B 僅有 40 億參數，卻能與更大的開源模型競爭，這歸功於其訓練資料的品質與多樣性，而非單純的模型規模擴張。

**Q8：作者如何驗證 CUActSpot 比傳統 GUI 定位基準測試更能反映真實 CUA 表現？**
A：作者進行了一項關鍵的相關性分析：他們比較了多個模型在 CUActSpot 上的表現與其在 OSWorld（端到端代理基準）上的表現，發現兩者之間存在高度一致性。相較之下，模型在傳統 GUI 定位基準（如 ScreenSpot-Pro）上的表現，與其在真實端到端任務中的表現關聯性較弱。這項驗證實驗說明，CUActSpot 不只是一個更困難的學術測試，而是真正能預測模型在實際電腦使用任務中成敗的代理指標，這對基準測試的設計選擇具有重要的方法論意義。

**Q9：作者在資料組成上進行了哪些消融研究？有哪些具體的實驗結論？**
A：作者針對不同資料組成進行了系統性的消融研究與實證分析，其中最重要的發現是「多樣性擴展」效應——跨模態、跨動作類型的資料多樣性，比單一模態內的資料量擴張更能提升模型的泛化互動能力。這項結論顛覆了傳統的資料縮放直覺，提示研究者在預算有限時應優先投資於資料多樣性而非單一領域的資料深度。此外，這些消融實驗也幫助作者確定最終訓練 Phi-Ground-Any-4B 的最佳資料混合比例，使其在僅 40 億參數的情況下仍能達到領先效能。

**Q10：Phi-Ground-Any-4B 在哪些實際工作場景中可能產生最大價值？**
A：Phi-Ground-Any-4B 在需要精細視覺定位的辦公室軟體操作中價值最大，例如在 Word 中選取特定段落、在 Excel 中框選表格範圍、在 PPT 中拖曳物件對齊，以及在 Photoshop 中描繪選取範圍進行影像去背。這些場景正是 GPT-5.4 等頂尖模型失敗率最高的「工作」情境，也是使用者最關注的應用領域。由於 Phi-Ground-Any-4B 僅有 40 億參數，它特別適合部署在資源受限的環境（如邊緣裝置或企業內部部署），使中小型組織也能享有高品質的電腦自動化能力，而無需依賴昂貴的雲端 API。

**Q11：從產品化的角度，這項研究對 CUA 的模組化設計與端到端設計之爭提供了什麼啟示？**
A：這項研究強烈支持模組化 CUA 架構的價值，因為它揭示了「動作定位」是整個系統中最關鍵、最容易失敗的環節。透過將 Phi-Ground-Any-4B 作為專門的定位模型與頂尖視覺語言模型（VLM）作為規劃器相結合，系統可以在不損失空間與上下文資訊的前提下，獲得精確的低階動作執行能力。相較之下，端到端 CUA 雖然能進行聯合優化，但需要海量訓練資料，且難以單獨診斷與改進定位錯誤。這項工作為「規劃—定位」分離的模組化路線提供了強而有力的實證支持。

**Q12：這項研究對整個 CUA 領域的長期影響是什麼？**
A：這項研究的長期影響體現在四個層面：基準測試層面，CUActSpot 將引導後續研究從「點擊中心」轉向「完整動作空間」；資料層面，渲染器管線為合成高品質、多樣化的訓練資料提供了可複製的範本；模型層面，Phi-Ground-Any-4B 證明了小型開源模型在定位任務上可以媲美甚至超越更大模型；方法論層面，「多樣性擴展」的概念將影響未來資料策略的設計。整體而言，這項工作有望加速 GUI 型 CUA 追趕 CLI 型 CUA 的實用化進度，推動混合型 CUA 系統的實現。

**Q13：作者坦承這項工作有哪些限制？**
A：雖然論文中具體的限制聲明需參考全文，但從方法論可推知幾項潛在限制：首先，CUActSpot 雖然涵蓋五種模態，但每種模態的任務設計仍受限於作者對「複雜互動」的定義，可能無法窮舉所有真實工作場景；其次，渲染器管線雖然能產生精確座標，但合成資料與真實使用者介面之間仍存在領域差距（domain gap），模型在面對真實軟體的視覺風格時可能表現下降；最後，Phi-Ground-Any-4B 的 40 億參數規模雖然高效，但在極度複雜的多步驟推理任務中，可能仍不及更大的專有模型。

**Q14：在什麼情況下 Phi-Ground-Any-4B 或 CUActSpot 涵蓋的場景仍會失敗？**
A：Phi-Ground-Any-4B 可能在以下情境中表現不佳：極高解析度螢幕上的微小目標、需要跨多個應用程式協調的工作流程、依賴即時視覺回饋的動態任務（如遊戲中的快速反應），以及需要深厚軟體特定知識的進階操作。CUActSpot 也未涵蓋需要長時間記憶或跨任務狀態維持的情境，這類任務更適合由端到端代理基準（如 OSWorld）來評估。此外，當面對訓練資料中未出現過的全新 UI 設計風格或非英語介面時，模型的泛化能力仍可能受到挑戰。

**Q15：作者指出哪些值得未來探索的研究方向？**
A：作者暗示了幾個值得延伸的研究方向：第一，將 CUActSpot 擴展至更多模態（如 3D 介面、擴增實境）或更多動作類型（如多點觸控、語音手勢）；第二，將渲染器管線與真實使用者互動資料結合，縮小合成與真實資料之間的領域差距；第三，探討「多樣性擴展」現象的理論基礎，理解為何跨模態多樣性比單一模態的資料量更具威力；第四，將 Phi-Ground-Any-4B 與規劃器結合，構建完整的混合型 CUA 系統；最後，將這項技術應用於無障礙輔助、機器人流程自動化（RPA）等更廣泛的場景，釋放電腦使用代理在數位工作中的真正潛力。

## 實務應用指南

### 適用場景

1. **企業內部流程自動化（RPA 強化）**：在 Windows 環境中自動執行 Word、Excel、PPT、Photoshop 等軟體的進階操作，例如批次處理圖片去背、跨檔案資料搬移、複雜表格格式化等傳統 RPA 難以處理的視覺化任務。

2. **客服與技術支援輔助**：當使用者遇到需要操作特定軟體介面的問題時，CUA 可即時示範或代為執行操作，例如在 Photoshop 中圈選物件、在 Excel 中繪製樞紐分析圖表，降低客服人力成本。

3. **無障礙輔助工具**：為身心障礙使用者提供 GUI 操作代理，特別是處理需要精細拖曳、繪製軌跡的任務（如繪圖軟體、影像編輯），彌補現有無障礙工具在複雜互動上的不足。

4. **遊戲自動化與測試**：在遊戲（Sokoban、FIFA、Minecraft 等）中執行需要精確座標定位的動作，例如滑鼠軌跡繪製、拖曳操作，可用於遊戲測試、QA 自動化或無障礙遊玩。

5. **教育訓練與操作教學**：建置互動式教學代理，能在螢幕上演示跨應用程式的工作流程（如 PPT 製作、文件排版），並根據學生操作給予即時修正建議。

### 實作步驟建議

1. **問題診斷與場景界定**：先在目標 Windows VM 中執行約 200 個任務，記錄失敗案例並分類為定位錯誤（GE）、規劃錯誤（PE）、系統錯誤等，確認「複雜互動失敗率」是否為主要瓶頸。

2. **基準測試先行**：採用 CUActSpot 評估現有模型在五種模態與多種動作（點擊、拖曳、繪製）上的表現，建立 baseline，並與 OSWorld 等端到端基準對照，驗證評估結果與實際部署表現的相關性。

3. **資料合成管線建置**：
   - 為每種模態設計基於渲染器的場景生成器，自動產生螢幕截圖與元素座標中繼資料。
   - 串接 LLM 為每個場景生成匹配的自然語言指令與動作軌跡。
   - 建立品質過濾機制，剔除低品質或不一致的合成樣本。

4. **多樣性優先的訓練策略**：根據論文的「variety scaling」洞察，優先擴展跨模態資料多樣性，而非單一模態的資料量；建議在預訓練階段混合五種模態資料，並在中期訓練階段針對目標場景加權。

5. **模型訓練與消融實驗**：以 Phi-Ground-Any-4B 為起點進行微調，針對不同資料組成（單一模態 vs. 多模態混合、不同動作類型比例）進行消融實驗，找出最佳資料配比。

6. **整合與部署**：將訓練後的定位模型與規劃模型（如 GPT-5.4）組合成模組化 CUA 架構，或進一步微調為端到端模型；部署時需考量 VM 環境的隨機不穩定性，加入重試與錯誤恢復機制。

7. **持續監測與迭代**：上線後持續收集失敗案例，特別關注座標錯誤與規劃錯誤的比例變化，定期以 CUActSpot 重新評估並迭代訓練資料。

### 潛在風險與注意事項

1. **VM 環境不穩定性**：論文指出系統錯誤（如 PyAutoGUI 的隨機不穩定性）會干擾評估與部署。**緩解措施**：在評估流程中區分系統錯誤與模型錯誤，建立重試機制，並在資料收集階段過濾系統錯誤樣本。

2. **合成資料的領域偏移**：渲染器生成的場景可能與真實軟體介面存在視覺差異，導致模型在實際部署時表現下降。**緩解措施**：在合成資料中混入一定比例的真實螢幕截圖，並進行領域適應微調。

3. **基準測試與實際表現的脫節**：CUActSpot 雖比傳統基準更貼近真實場景，但仍可能無法完全反映端到端任務表現。**緩解措施**：同時採用 OSWorld 等端到端基準進行交叉驗證，避免單一指標誤導開發方向。

4. **資料多樣性陷阱**：盲目擴增資料量但忽略模態與動作類型的多樣性，可能無法有效降低失敗率。**緩解措施**：遵循「variety scaling」原則，在資料配比上優先確保跨模態、跨動作類型的均衡覆蓋。

5. **座標預測的精度限制**：對於極小目標（如高解析度專業軟體中的細小按鈕），純視覺定位模型可能仍有困難。**緩解措施**：結合縮放裁切、多尺度推理，或在關鍵場景輔以無障礙樹等結構化資訊。

6. **安全與權限風險**：CUA 自動操作可能誤觸敏感操作或存取未授權資料。**緩解措施**：在動作執行前加入規劃層的權限檢查與人工確認機制，特別是高風險操作（如刪除、提交）。
