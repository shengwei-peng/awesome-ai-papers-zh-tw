## ⚡ TL;DR

現有三維基準僅評文字回應或單一物體操作，難以衡量智慧體對完整多物體場景的動作能力。
本文提出 SceneActBench，以統一智慧體-環境迴路評估五項視覺條件化三維動作任務。
十一種專有 VLM 整體得分介於 38.6 至 50.2，且無任一配置能在各任務穩定表現優異。

## 摘要翻譯

視覺語言模型（Vision-language model, VLM）智慧體（agents）日益運用工具對三維場景（3D scenes）執行動作，而非僅止於描述場景。現有的三維基準測試（3D benchmarks）僅對文字回應（textual responses）或單一物體操作（single-object operations）評分，使得智慧體在完整多物體三維場景（complete multi-object 3D scenes）上的動作仍缺乏充分評估。我們提出 SceneActBench，一個在跨任務共享的統一智慧體-環境迴路（unified agent-environment loop）下、涵蓋五項三維任務的視覺條件化動作（visually conditioned action）基準測試（benchmark）。給定 PNG 圖片（PNG images）或取樣影片幀（sampled video frames），並視任務需求提供三維資產（3D assets），智慧體即對三維環境（3D environment）執行動作。我們以任務專屬幾何指標（task-specific geometric metrics），將每個最終輸出（final output）與隱藏真實標註（hidden ground truth）進行比對評估。SceneActBench 包含五項任務，由 210 個來源實例（source instances）建構而成，共產生 520 個任務案例（task cases），其中包含成對輸入條件（paired input conditions）。所有任務均採用相同的固定智慧體迴路（fixed agent loop）執行，以確保公平比較。在十一種專有 VLM 配置（proprietary VLM configurations）中，整體分數（Overall scores）介於 38.6 至 50.2 之間，且沒有任何配置能在各項任務中均表現良好。我們進一步分析失敗於何處、以何種形式呈現。

### 核心貢獻（3～5點）
- 提出 SceneActBench，一個針對視覺條件化三維動作（visually conditioned 3D action）的可執行基準測試，涵蓋五項不同三維任務，填補現有基準僅評估文字回應或單一物體操作的缺口。
- 建立統一智慧體-環境迴路（unified agent-environment loop），使所有任務在相同的固定智慧體迴路（fixed agent loop）下執行，確保跨任務與跨模型比較的公平性。
- 設計任務專屬幾何指標（task-specific geometric metrics），將智慧體的最終輸出與隱藏真實標註（hidden ground truth）進行幾何層級的比對評估。
- 在十一種專有 VLM 配置（proprietary VLM configurations）上進行大規模評估，發現整體分數（Overall scores）介於 38.6 至 50.2 之間，且沒有任何模型能在所有任務中穩定表現良好。
- 進行案例層級診斷（case-level diagnostics）與失敗分析（failure analysis），探討模型於何處、以何種形式出錯。

### 適合對象
本論文適合對視覺語言模型（VLM）、三維理解（3D understanding）、具身智慧（embodied AI）及智慧體（agent）評估有興趣的研究者與工程師，特別是關注如何讓模型不僅「理解」三維場景，更能主動「對場景執行動作」（acting on a scene）的學術與產業界人士。對於從事三維視覺問答（3D VQA）、機器人模擬、三維場景編輯與基準測試設計的讀者亦具高度參考價值。

## 深度分析

#### 方法論解析

SceneActBench（視覺條件化三維動作基準）的核心貢獻在於將「看見場景後執行動作」這件事，轉化為一個可執行、可重複評量的標準化問題。整個流程圍繞一個統一的智慧體-環境迴路（unified agent-environment loop）運作：VLM（視覺語言模型）agent（智慧體）透過 MCP 工具介面與 headless Blender 互動，依序進行 Inspect（檢視場景）、Act（執行程式碼）、Render（渲染驗證）、Revise（在步數預算內修正）。最終輸出會被一次性地與隱藏真實標註（hidden ground truth）比對，agent 在過程中不會收到任何 evaluator（評分器）回饋，這確保了評量的是最終三維產出，而非對評分訊號的過擬合。

整個 benchmark（基準測試）由 210 個 source instances（來源實例）組成，衍生出 520 個 task cases（任務案例），並涵蓋五項任務：

1. **Layout task（佈局任務）**：使用 3D-FRONT 的 100 個已佈置房間，每個房間含 3–7 件、來自 27 個 furniture categories（家具類別）的物件。輸入為 1 張或約 11 張 calibrated views（已標定視圖），輸出是將 canonical GLBs（標準化三維資產）擺放到正確位置的 GLB 場景，評量指標為 ADD-S（對稱平均距離誤差）。
2. **Camera task（相機任務）**：同樣基於 3D-FRONT 房間，給定單張視圖與已知 FOV（視野角），agent 必須輸出 6-DoF camera pose（六自由度相機姿態）JSON，評量指標為 PE（position error，位置誤差，單位公尺）與 AE（angular error，角度誤差，單位度）。
3. **Articulated task（關節式物體任務）**：使用 S2OACD 的 100 個 articulated objects（關節式物體），輸入為 32 張有序影格，agent 必須輸出 32 個 GLB scene states（場景狀態），評量指標為 MPE（mean pose error，平均姿態誤差）。
4. **Reconstruction task（重建任務）**：給定約 11 張 calibrated views，從空 Blender 場景重建出完整佈置房間的 furnished-scene GLB，評量指標為 F@5%（在 5% 閾值下的 F-score）。
5. **Dynamic task（動態任務）**：使用 10 組 Kenney kits 的多物體動態場景（multi-object dynamic scenes），輸入為 144 帧取樣影片與相機資訊，agent 從 component GLB library（元件資產庫）組合出 animated GLB（帶動畫的三維場景），評量指標為 MME（motion matching error，動作匹配誤差）與 LE（location error，位置誤差）。

Layout task 與 Dynamic task 特別設計了 paired input conditions（成對輸入條件），讓同一 source instance 在不同視覺輸入豐富度下被測試，從而觀察 agent 對單張圖片、多視圖或影片幀的敏感度。所有任務共用同一 fixed agent loop（固定智慧體迴路）與步數預算（Layout/Camera 各 30 步、Reconstruction 35 步、Articulated 60 步、Dynamic 80 步），這讓不同 VLM 配置之間的比較更為公平。

#### 實驗數據解讀

作者評估了十一組 proprietary VLM configurations（專有 VLM 配置），Overall scores（整體分數）介於 38.6 至 50.2 之間。這個分數區間傳達了幾個重要訊息：

- **天花板仍低**：即使表現最好的配置，整體分數也僅約 50.2，顯示現有 VLM agent 在「看見場景後執行三維動作」這件事上仍有極大成長空間。
- **沒有單一霸主**：沒有任何一組配置在所有任務上都表現穩定優異。stacked task contributions（堆疊任務貢獻）顯示，領先配置在不同任務上的強項各異，暗示目前模型能力偏向任務專精，而非通用三維行動能力。
- **失敗模式多元**：透過 case-level diagnostics（案例層級診斷），作者進一步指出失敗不只發生在 aggregate scores（聚合分數）上，而是在個別案例中呈現出具體的幾何錯誤，例如物件位置偏移、關節角度估計錯誤、相機深度尺度失真、動態時序不一致等。

從任務設計來看，各項指標都屬於 geometric metrics（幾何指標），直接比對最終輸出與 hidden ground truth 的空間一致性，而非僅用 task success（任務成功）這類二元指標。這種設計讓我們能區分「大致做對」與「精確匹配」的差異。例如 Camera task 同時看 PE 與 AE，可區分位置估計準但角度偏，或角度準但距離錯；Articulated task 的 MPE 則能量化關節運動軌跡的整體偏差。

值得注意的是，由於評分時不給 agent 任何回饋，這些分數反映的是「單向視覺條件化動作（visually conditioned action）」的能力，而非透過試錯學習的互動式強化學習表現。因此，50.2 的上限也部分說明了：在沒有外部回饋的情況下，僅靠視覺輸入與內部推理來精確操控完整三維場景，對現有 VLM 仍是艱難挑戰。

#### 與現有研究的比較

SceneActBench 在現有文獻中的定位非常明確。傳統 3D VQA（三維視覺問答）基準如 ScanQA、SQA3D、Spatial457 只要求模型輸出 textual responses（文字回應），並不改變三維環境（3D environment），因此無法評量 acting on a scene（對場景執行動作）的能力。另一方面，近期的 code-driven 3D agents（程式碼驅動三維智慧體）與 embodied agents（具身智慧體）如 BlenderGym、3DCodeBench、GameDevBench、EmbodiedBench，雖然讓 agent 能在三維環境中操作，但大多聚焦 single-object operations（單一物體操作）、static edit（靜態編輯）或僅報告 task success，缺乏對完整多物體三維場景（complete multi-object 3D scenes）的 coordinated action（協調動作）評量。

相較之下，SceneActBench 同時涵蓋了 Table 1 所列的全部八項評估屬性：spatial grounding（空間定位）、egocentric spatial reasoning（自我中心空間推理）、kinematic reasoning（運動學推理）、shape imagination（形狀想像）、dynamic reasoning（動態推理）、geometric score（幾何分數）、multi-object（多物體）與 interactive（互動性）。這使其成為首個在統一 agent-environment loop 下，要求單一 agent 對完整場景執行多樣化三維動作，並以 hidden ground truth 進行幾何評分的 benchmark。

此外，過去許多 specialist models（專家模型）如 ATISS、DiffuScene、Zero-1-to-3、COLMAP 等，各自解決 layout generation（佈局生成）、image-to-3D reconstruction（圖像到三維重建）或 camera estimation（相機估計）等單一問題。SceneActBench 則把這些能力整合到同一個 VLM agent 的測試框架中，強調通用智慧體而非單一任務專家。

然而，SceneActBench 也有其限制。首先，所有互動都發生在 headless Blender 中，未納入真實物理引擎、材質光照變化或真實世界感測雜訊。其次，目前僅評估 proprietary VLM，缺乏對開源模型的系統性比較。第三，210 個 source instances 雖已能支撐初步診斷，但相較於大型視覺基準仍屬小型，且場景來自合成資料集，與真實室內掃描（scans）仍有差距。最後，fixed agent loop 雖然公平，但未必是每項任務的最佳互動策略，例如 Reconstruction task 可能受益於更專門的 multi-view stereo pipeline，而 Dynamic task 可能需要專門的 motion planning 工具。

#### 可重現性評估

從提供的內容來看，SceneActBench 的 reproducibility（可重現性）取決於幾個層面：

- **資料來源公開**：benchmark 使用的 3D-FRONT、S2OACD、Kenney kits 均為公開資料集，理論上其他研究者可以重新建立相同來源實例。作者也說明將場景標準化為自有格式，並記錄 camera matrix（相機矩陣）與 angle of view（視野角）等資訊。
- **評估規則透明**：Appendix A.3 詳列 exact evaluator rules（精確評分規則）與所有 diagnostic metrics（診斷指標），這有助於第三方複製評分邏輯。
- **工具介面標準化**：統一的 MCP 工具介面與 Blender 執行環境若對外釋出，能大幅降低重現門檻。

但目前文本中並未明確提及是否會公開 source code（原始碼）、prompts（提示詞）、MCP tool specifications（MCP 工具規格）、hidden ground truth splits（隱藏真實標註切分）或預處理腳本。若這些關鍵資產未釋出，研究者將難以完全重現十一組 VLM 配置的測試條件。此外，proprietary VLM 的 API 版本、溫度參數與非確定性輸出，也會讓 exact score reproduction（精確分數重現）變得困難。

整體而言，SceneActBench 在方法論與資料來源上具備可重現的基礎，但實際可重現性仍高度依賴作者後續是否釋出完整的 evaluation harness（評估框架）、GLB assets（三維資產）與 ground truth。建議未來版本提供容器化執行環境與公開 leaderboard（排行榜），以強化社群信任與比較基準。

#### 未來研究方向

SceneActBench 揭示的低落天花板與任務間不一致性，為後續研究開啟了多條路徑：

1. **開源 VLM 與視覺-動作模型**：目前僅測試 proprietary VLM，未來應納入開源模型，並發展專為三維行動設計的 vision-action architectures（視覺-動作架構）。
2. **模組化 agent 設計**：在統一迴路中整合專家工具，例如將 reconstruction（重建）、layout generation（佈局生成）、articulated pose estimation（關節姿態估計）、motion planning（動作規劃）等模組作為可呼叫工具，讓 VLM 負責高階協調。
3. **引入物理與真實世界**：將 headless Blender 擴展到具備物理模擬的環境，並使用真實掃描資料或 NeRF / 3D Gaussian Splatting（3DGS）場景，縮短與真實應用的差距。
4. **互動式與語言條件化動作**：除了視覺參考（reference），未來可加入自然語言指令，評估 agent 是否能根據「把沙發移到窗邊」這類高階指令執行 coordinated action。
5. **更細緻的失敗分析與診斷指標**：針對深度尺度、遮擋、對稱性、關節軸方向、時序一致性等設計更細的 diagnostic metrics，並建立可視化失敗案例庫。
6. **利用 evaluator 回饋進行訓練**：目前評分對 agent 隱藏，未來可研究如何在不洩漏 ground truth 的前提下，提供中間幾何回饋以進行 iterative refinement（迭代精修）或 reinforcement learning（強化學習）。
7. **擴大資料規模與多樣性**：增加 source instances 數量、物件類別、動作類型與相機視角分佈，並納入室外場景與非剛性物體。
8. **結合人類感知指標**：除了 geometric metrics，可加入基於人類判斷的 perceptual metrics（感知指標），評估輸出是否在人眼看來合理且美觀。
9. **跨模態輸入穩健性**：深入探討 paired input conditions 下的表現差異，發展能同時善用單張圖片、多視圖與影片幀的統一表徵學習方法。
10. **長期記憶與場景圖推理**：對於包含多個物件的場景，agent 需要維護場景圖（scene graph）與長期記憶，未來可研究如何讓 VLM 在多次 inspect-act-render 循環中保持全局一致性。

總結來說，SceneActBench 不僅提出了一個嚴謹的評量框架，更重要的是它把「VLM agent 能否對其所見的三維場景採取行動」這個問題，轉化為可量化、可診斷、可比較的科學問題，為下一代通用三維智慧體的發展奠定了重要基礎。

## 論文問答

**Q1：SceneActBench 主要想解決什麼問題？**

A：SceneActBench 旨在解決現有基準測試無法評估視覺語言模型（VLM）智慧體「對完整三維場景執行動作」能力的問題。過去多數三維基準只要求模型描述場景或回答文字問題，而程式碼驅動的三維基準又多半只涉及單一物體操作或靜態編輯，缺乏對多物體協調動作的測試。因此，本文提出一個可執行的統一評估框架，讓智慧體根據視覺輸入在 Blender 三維環境中實際操作，並以隱藏真實標註進行幾何評分。

**Q2：為什麼現有的三維基準無法充分評估智慧體的場景級動作能力？**

A：現有基準如 ScanQA、SQA3D 與 Spatial457 主要屬於三維視覺問答，只評分文字回應，智慧體並未真正改變場景狀態。另一方面，BlenderGym、3DCodeBench、GameDevBench 與 EmbodiedBench 雖然讓智慧體在三維環境中操作，但通常只涵蓋單一物體、單一靜態編輯或僅報告任務成功與否。這些設計無法檢驗智慧體是否能協調多個物體、理解空間關係並產生符合幾何真值的完整場景輸出。

**Q3：為什麼讓智慧體對完整多物體三維場景執行動作很重要？**

A：在實際三維應用中，例如室內設計、機器人操作或遊戲場景生成，往往需要同時協調多個物體的位置、姿態與動態行為，而非僅處理單一物件。僅能描述場景或操作單一物體的智慧體，難以應對需要整體空間推理與多物體互動的真實任務。因此，評估智慧體能否「看到場景後動手改變三維環境以匹配參考」，是衡量其真正三維理解能力的重要標準。

**Q4：SceneActBench 的核心方法與評估流程是什麼？**

A：SceneActBench 採用統一的「觀察—行動—渲染」智慧體-環境迴路，所有任務都透過相同的 MCP 工具介面與 Blender 互動。智慧體接收 PNG 圖片或取樣影片幀作為視覺輸入，必要時會提供三維資產，然後在 headless Blender 中執行程式碼、檢查場景狀態並反覆修正。最終輸出會被轉換為任務專屬格式，並與隱藏真實標註比較，使用幾何指標進行一次性評分，過程中智慧體不會收到評估回饋。

**Q5：SceneActBench 相較於先前工作的關鍵創新是什麼？**

A：其關鍵創新在於首次將「視覺條件化三維動作」視為可執行的統一評估問題，並在五種不同能力上共用同一個固定智慧體迴路。不同於過去各任務使用專屬模型或特殊介面，SceneActBench 要求單一智慧體同時處理佈局、相機姿態、關節式物體、形狀重建與多物體動態場景。此外，它使用隱藏三維真實標註與任務專屬幾何指標，能夠超越二元任務成功指標，提供更細緻的幾何相似度評估。

**Q6：SceneActBench 在設計上做了哪些重要選擇？**

A：首先，作者選擇以 Blender 作為統一的三維執行環境，並透過 MCP 工具介面標準化智慧體與環境的互動方式。其次，所有任務都使用相同的固定智慧體迴路與步數預算，確保不同 VLM 配置之間的比較公平。第三，評估時採用隱藏真實標註與幾何指標，避免智慧體透過評估回饋投機取巧，並能診斷失敗發生在哪些環節。

**Q7：SceneActBench 包含哪些任務與資料來源？**

A：SceneActBench 包含五個任務：佈局任務（Layout）、相機任務（Camera）、關節式物體任務（Articulated）、重建任務（Reconstruction）與動態任務（Dynamic）。資料來自 3D-FRONT、S2O Articulated Containers Dataset 與 Kenney kits，共 210 個來源實例，經成對輸入條件擴展後產生 520 個任務案例。其中佈局與動態任務還包含成對輸入條件，例如單張圖片與多張校準視圖，或不同取樣方式的影片幀。

**Q8：實驗中的關鍵結果是什麼？**

A：研究團隊評估了十一種專有 VLM 配置，整體分數介於 38.6 到 50.2 之間，顯示目前模型在視覺條件化三維動作上仍有很大進步空間。更重要的是，沒有任何一種配置在所有任務上都表現一致良好，不同領先配置在不同任務上各有強項。透過堆疊任務貢獻分析可以清楚看出，某些模型擅長空間定位與佈局，但在動態推理或形狀想像上表現較弱。

**Q9：作者進行了哪些診斷或消融分析？**

A：作者使用案例層級診斷來分析失敗發生的位置與方式，而不僅止於報告整體分數。這些診斷檢視智慧體在空間定位、自我中心空間推理、運動學推理、形狀想像與動態推理等能力上的具體失敗模式。透過這種細粒度分析，研究人員能夠辨識出哪些任務步驟或認知能力最為薄弱，例如物體姿態估計錯誤、關節軸判斷失準或動態時序不一致等問題。

**Q10：SceneActBench 的評估能力可應用於哪些實際場景？**

A：此基準的能力可直接應用於室內設計自動化，讓智慧體根據參考圖片自動擺放家具並調整相機視角。在機器人與具身智慧領域，它有助於評估機器人是否能根據視覺觀察操作關節式物體或理解多物體動態場景。此外，遊戲開發、虛擬實境內容生成與三維資產重建等產品，也能受益於這種能夠「看到場景後動手執行」的智慧體技術。

**Q11：從產品開發角度，SceneActBench 帶來哪些考量？**

A：產品團隊在設計三維智慧體時，必須意識到單一 VLM 配置難以同時勝任所有三維任務，因此可能需要根據應用場景選擇或組合不同模型。由於評估採用幾何指標而非僅任務成功與否，產品開發者能更精確地量化使用者體驗中的視覺與空間錯誤。此外，為了在實際產品中部署，仍需解決執行效率、工具穩定性以及與現有三維軟體管線整合等工程挑戰。

**Q12：SceneActBench 對整個研究領域可能產生什麼影響？**

A：SceneActBench 為視覺語言模型智慧體提供了一個標準化的三維動作評估平台，有助於推動從「描述三維場景」走向「操作三維場景」的研究典式轉移。它強調幾何準確度與多物體協調能力，可能促使未來模型更重視空間推理與可執行輸出，而非僅產生流暢的文字描述。長遠來看，這類基準將加速通用三維智慧體的發展，並為機器人、電腦圖學與人工智慧的跨領域整合奠定基礎。

**Q13：SceneActBench 有哪些已知的限制？**

A：首先，目前基準主要使用 Blender 作為模擬環境，與真實世界的物理互動仍有差距，因此結果不一定能直接遷移到實體機器人。其次，五個任務雖然涵蓋多種三維能力，但來源實例數量與場景類型仍有限，例如動態任務僅使用 10 個來源實例。此外，評估只針對最終輸出進行一次性幾何評分，無法完全捕捉智慧體在執行過程中的中間決策品質。

**Q14：作者觀察到哪些典型的失敗案例？**

A：常見失敗包括智慧體無法準確估計多物體之間的相對位置與方向，導致佈局任務中家具擺放錯誤。在關節式物體任務中，智慧體經常誤判關節軸位置或旋轉方向，使得開合動作不符合真實標註。動態任務則容易出現時序不一致或物體運動軌跡不合理的問題，顯示現有模型在理解與生成多物體動態行為方面仍相當脆弱。

**Q15：未來研究可以朝哪些方向發展？**

A：未來可以擴大資料規模與場景多樣性，納入更複雜的真實世界環境與物理模擬，以縮小模擬與現實之間的差距。研究者也可以開發能夠在執行過程中獲得回饋並自我修正的互動式智慧體，而非僅依賴最終輸出評分。此外，結合專門的三維幾何模型與通用 VLM，設計具備更強空間推理、運動學理解與長期規劃能力的混合架構，也是值得探索的方向。

## 實務應用指南

### 適用場景

1. **室內設計與家具佈局自動化**  
   使用者上傳一張或數張房間照片，VLM 智慧體即可在 Blender 中自動擺放三維家具資產，輸出與參考影像幾何一致的佈局 GLB。適用於電商「看圖擺家具」、室內設計師快速提案、房地產虛擬看屋等場景。

2. **擴增實境（AR）與機器人相機定位**  
   在已知場景中，智慧體根據單張視角與相機內參推斷六自由度（6-DoF）相機姿態，輸出 JSON 姿態。可整合至 AR 導航、無人機/機器人重定位，或將現場照片對齊到既有 BIM/CAD 模型。

3. **關節式物體狀態估計與數位孿生**  
   針對冰箱、抽屜、筆電等關節式物體，智慧體從 32 幀開合影片推斷每幀的關節狀態，輸出 32 個 GLB 場景狀態。適用於工業巡檢、設備維護數位孿生，以及倉儲機器人判斷容器開合程度。

4. **多視角三維重建與資產還原**  
   給定約 11 張標定視角影像，智慧體在空 Blender 場景中逐步擺放完整家具佈局，輸出 furnished-scene GLB。可用於遊戲關卡快速搭建、影視預覽（previs），或將產品照片轉為可互動三維場景。

5. **動態場景動畫生成**  
   從 144 幀取樣影片與元件 GLB 資產庫出發，智慧體組合多物體並產生動畫 GLB。適用於廣告動畫、遊戲過場、教育模擬，或將現實運動影片轉為可編輯的三維動畫資產。

---

### 實作前置條件

**資料準備**
- 參考視覺輸入：PNG 圖片或取樣影片幀，部分任務需要相機內參（FOV、相機矩陣）的 JSON 標註。
- 三維資產：依任務提供 canonical GLB、關節式 GLB，或元件 GLB 資產庫。
- 隱藏真實標註：用於離線評分的 ground-truth 場景、姿態或動畫，產品化時可由人工審核或感測器資料替代。

**運算資源**
- Blender 3.x/4.x headless 執行環境（CPU 即可渲染，GPU 可加速）。
- VLM 推理端點：建議具備視覺語言模型 API 存取權限，並預留足夠 token 預算（動態任務預算可達 80 步）。
- MCP（Model Context Protocol）伺服器與工具註冊環境，用於讓智慧體呼叫 Blender 程式碼執行、場景查詢與渲染。

**技能需求**
- 熟悉 Python 與 Blender Python API（bpy）。
- 理解 GLB/glTF、JSON 相機姿態、三維幾何變換（旋轉、平移、縮放）。
- 具備 VLM 智慧體開發經驗，能設計 inspect → act → render 的固定智慧體迴路。
- 能解讀任務專屬幾何指標（ADD-S、PE/AE、MPE、F@5%、MME/LE）並據此除錯。

---

### 實作步驟建議

1. **任務定義與範圍收斂**  
   從五項任務中選擇一項優先落地（建議從 Layout 或 Camera 開始，資料與評分較成熟），明確輸入條件（單張圖、多視角、影片幀）與輸出格式（GLB、JSON 姿態、動畫 GLB）。

2. **建立標準化資料管線**  
   將來源實例轉換為統一格式的三維資產與參考影像；記錄相機矩陣、FOV、物件類別與初始狀態。確保資產原點、比例、座標軸一致，避免智慧體在擺放時出現系統性偏差。

3. **部署 Blender + MCP 評估框架**  
   架設 headless Blender 執行個體，並透過 MCP 工具暴露「查詢場景狀態」、「執行 bpy 程式碼」、「渲染當前視角」等介面。此共享智慧體-環境迴路是確保跨模型公平比較與穩定產品輸出的核心。

4. **選擇與設定 VLM 智慧體**  
   選用支援多輪工具呼叫的視覺語言模型，設計 system prompt 強調：只能透過工具觀察與修改場景、必須在步數預算內完成、最終輸出須符合指定格式。建議加入自我檢查步驟，例如渲染後與參考圖比對。

5. **實作幾何評分與案例層級診斷**  
   依任務實作對應的幾何指標，並保留每個案例的中間渲染結果與動作日誌。透過案例層級診斷定位常見失敗模式：空間定位錯誤、關節軸判斷錯誤、動態時序漂移、形狀想像不完整等。

6. **迭代優化與產品化封裝**  
   根據診斷結果調整 prompt、增加示範案例（few-shot）、引入資產語意標籤或物件偵測前處理。最後將整個流程封裝為 API，提供 GLB/JSON 輸出與可視化預覽，並加入人工覆核閘道。

---

### 潛在風險與注意事項

- **視覺幻覺導致幾何錯誤**  
  VLM 可能誤判深度、比例或遮擋關係，導致家具穿牆、相機姿態反向、關節方向錯誤。建議在智慧體迴路中加入「執行後渲染驗證」步驟，並對異常結果觸發重試或人工審核。

- **資產格式與座標系不一致**  
  不同來源的三維資產原點、縮放單位、座標軸可能不同，會直接影響 ADD-S、MPE 等幾何指標。實作前應建立資產標準化腳本，並在 prompt 中明確告知智慧體座標系規則。

- **步數預算與成本控管**  
  動態任務預算可達 80 步，每步都會呼叫 VLM 與 Blender，雲端成本可能快速累積。建議設定 early-stop 條件、快取中間渲染結果，並對生產環境設定每日呼叫上限。

- **隱藏真實標註的依賴**  
  學術評分需要 hidden ground truth，但產品上線後難以取得。可改用感測器資料、CAD 比對或人工抽樣評分作為替代，並持續收集使用者回饋以校正幾何指標。

- **版權與授權風險**  
  3D-FRONT、S2O-ACD、Kenney kits 等資料集與資產庫各有授權條款，商業使用前必須確認允許範圍，必要時替換為自有資產或取得商用授權。

---

### 與其他技術的整合建議

- **與攝影測量/視覺定位管線整合**  
  在 Camera 與 Reconstruction 任務中，可先用 COLMAP 或 DUSt3R 產生稀疏點雲與相機初估，再交由 VLM 智慧體進行語意層級的場景擺放與精修，彌補純幾何方法缺乏語意理解的缺點。

- **與 CAD/BIM 與遊戲引擎整合**  
  將智慧體輸出的 GLB 匯入 Revit、SketchUp、Unity 或 Unreal Engine，作為設計初稿或遊戲關卡原型。可再透過 DCC 工具人工調整，形成「AI 生成初稿 + 設計師精修」的工作流。

- **與具身智慧模擬器整合**  
  將 Layout 與 Articulated 任務的輸出銜接到 Habitat、Isaac Sim 或 MuJoCo，讓機器人在還原後的場景中執行導航與操作任務，縮短從視覺觀察到實體動作的落差。

- **與資產管理系統整合**  
  將元件 GLB 資產庫接上企業內部的 DAM（Digital Asset Management）或 PDM 系統，讓智慧體根據專案規範自動選用正確型號、材質與比例的資產。

- **與多模態評測平台整合**  
  將 SceneActBench 的幾何指標與標準化評估框架嵌入 MLOps 管線，對每次模型更新進行回歸測試，確保 VLM 版本升級不會在特定三維能力上退化。

---

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從「適用場景」與圖 2 的智慧體-環境迴路開始，理解「智慧體看到圖片後，透過工具操作 Blender」這個核心概念；接著閱讀第 3 節的任務說明與表 2，對五項任務的輸入輸出有整體認識即可，技術細節可暫時略過。

**給 AI 工程師**  
重點關注第 3 節的標準化評估框架、固定智慧體迴路設計，以及附錄 A.3 的幾何指標實作；建議直接參考 MCP 工具介面與 Blender headless 的整合方式，並留意第 4 節對十一種專有 VLM 配置的失敗分析，以快速複製到自家產品管線。

**給研究人員**  
請仔細閱讀第 2 節的相關工作比較與表 1，理解 SceneActBench 相較於 3D VQA、BlenderGym、EmbodiedBench 等基準在多物體與幾何評分上的差異；第 4 節的案例層級診斷與失敗模式可作為設計新模型或新任務的切入點。

**給產品經理**  
建議聚焦「適用場景」、整體分數區間（38.6–50.2）以及「潛在風險與注意事項」；理解目前沒有任何 VLM 能在所有任務上穩定表現，因此產品設計應保留人工覆核機制，並優先選擇單一任務 MVP 而非一次支援全部五項能力。
