# 文件檢索感知分塊（D-RAC）：透過 PDF 正規化與多模態 Markdown 轉換實現企業文件的通用檢索感知匯入

## ⚡ TL;DR

企業文件格式各異，傳統抽取破壞閱讀順序與表格結構，代理式分塊成本高昂且易幻覺。
提出D-RAC，將文件正規化為PDF後，以多模態模型轉為檢索優化Markdown，再用ID規劃分塊。

## 摘要翻譯

運作於企業知識庫（enterprise knowledge base）的檢索增強生成（Retrieval-Augmented Generation, RAG）系統，必須攝取異質文件格式（heterogeneous document formats）——PDF、Word 文件、簡報與掃描影像（scans / scanned images）——其內容往往被鎖定在複雜的視覺版面（visual layout）、多欄頁面（multi-column pages）與密集表格（dense tables）之中。基於規則的提取（rule-based extraction）與光學字元辨識（Optical Character Recognition, OCR）會破壞閱讀順序（reading order）、壓平表格並遺失標題層級（heading hierarchy）；而完全代理式分塊（agentic chunking）直接處理提取後的文字，則會帶來高昂的權杖成本（token cost）與幻覺風險（hallucination risk）。我們提出文件檢索感知分塊（Document Retrieval-Aware Chunking, D-RAC），將先前提出的網頁檢索感知分塊（Web Retrieval-Aware Chunking, W-RAC）框架擴展至任意文件格式。D-RAC 首先將任何輸入文件正規化為 PDF（PDF normalization），利用幾乎所有格式皆可忠實且確定性地渲染為 PDF 的特性。接著，單次多模態大型語言模型（multimodal large language model, multimodal LLM）推論即將渲染後的頁面轉換為檢索優化的 Markdown（retrieval-optimized Markdown）——將表格改寫為自包含的散文陳述（self-contained prose statements）並保留標題層級——之後的分塊流程與 W-RAC 完全相同：先進行確定性解析（deterministic parsing）以產生 ID 可定址單元（ID-addressable units），再由輕量級 LLM 基於識別碼（identifiers, IDs）而非文字進行分塊規劃（chunk planning）。分塊過程中無需重新生成原始文字，因此保留了 W-RAC 在成本、確定性（determinism）與可觀測性（observability）上的優勢，同時讓所有可渲染格式都成為第一類輸入（first-class inputs）。在橫跨五個企業領域（enterprise domains）、包含 236 份文件與 795 頁的 RAG 多語料庫基準測試（RAG-Multi-Corpus benchmark）的 PDF 子集上，D-RAC 於 72 分鐘內零錯誤地完成完整語料庫的轉換與分塊，產出 1,748 個檢索就緒分塊（retrieval-ready chunks）。相較於使用前沿大型語言模型（frontier LLMs）進行代理式分塊，D-RAC 的分塊階段輸出權杖（output tokens）減少 95.7%，分塊成本降低 77.8%（按 GPT-4.1 計價）至 85.6%（按 Gemini 2.5 Pro 計價），分塊時間則縮短 75%。D-RAC 可線性擴展至 500 頁以上的文件。

### 核心貢獻（3～5點）
- 提出 D-RAC，將 W-RAC 從網頁擴展至任意企業文件格式，透過 PDF 正規化與多模態 Markdown 轉換實現格式無關的檢索感知匯入。
- 以單次多模態 LLM 將渲染頁面轉為檢索優化的 Markdown，保留標題層級並將密集表格改寫為自包含散文陳述，解決傳統 OCR 與規則提取破壞文件結構的問題。
- 分塊階段不重新生成原始文字，而是採用確定性解析產生 ID 可定址單元，再由輕量級 LLM 基於識別碼進行分塊規劃，兼顧低成本、高確定性與可觀測性。
- 在 RAG-Multi-Corpus 基準測試的 PDF 子集上驗證：72 分鐘內零錯誤完成 236 份、795 頁文件的轉換與分塊，產出 1,748 個檢索就緒分塊；相較前沿 LLM 代理式分塊，輸出權杖減少 95.7%、成本降低 77.8%–85.6%、時間縮短 75%，並可線性擴展至 500 頁以上文件。

### 適合對象
從事 RAG 系統、企業知識庫建置、文件理解與資訊檢索的研究人員與工程師，特別是關注異質文件分塊、多模態文件轉換、檢索效能與系統成本權衡的讀者。

## 深度分析

#### 方法論解析

D-RAC 的核心設計可視為 W-RAC（Web Retrieval-Aware Chunking，網頁檢索感知分塊）在任意企業文件上的「格式無關（format-agnostic）」延伸。其方法論由四個階段組成：**PDF 正規化（PDF normalization）與頁面渲染**、**多模態 Markdown 轉換（multimodal Markdown conversion）**、**解析與分段（parse and section）**、**規劃與重建（plan and reconstruct）**。整體哲學是：讓多模態大型語言模型（multimodal LLM）只負責一次「結構復原」任務，之後的分塊規劃（chunk planning）完全回到 W-RAC 的確定性解析（deterministic parsing）與 ID 可定址單元（ID-addressable unit）機制，避免在每次分塊時都重新生成原始文字。

**第一階段：PDF 正規化與頁面渲染**  
D-RAC 將 PDF 視為通用視覺交換格式（universal visual interchange format）。無論輸入是 DOCX、PPTX、XLSX、HTML 或掃描影像（scanned image），都先以標準工具轉換為 PDF，例如以無頭 LibreOffice 處理 Office 文件、以列印成 PDF 處理網頁、以影像包裝處理掃描檔。這一步是確定性渲染（deterministic rendering），不涉及 LLM，並將異質文件格式（heterogeneous document formats）的視覺內容統一到單一表示。隨後每頁以 200 DPI 渲染為 PNG，並將長邊縮放至不超過 1,568 像素，以符合常見視覺編碼器的輸入限制，同時保留細字與表格的可讀性。

**第二階段：多模態 Markdown 轉換**  
渲染後的頁面影像以每批 5 頁的方式送入多模態 LLM（論文評估了 Gemma-3 27B 與 Gemma-3 12B），最多 5 批並行處理。此階段並非通用光學字元辨識（generic OCR），而是檢索感知（retrieval-aware）的結構復原：  
- 表格被重寫為列級散文陳述（row-level prose statement），每個事實成為自包含散文陳述（self-contained prose statement），欄位標題（column header）作為語境嵌入陳述中，避免傳統表格嵌入時「單一儲存格失去行列語境」的問題。  
- 裝飾性圖像（decorative imagery）被抑制，減少雜訊。  
- 標題層級（heading hierarchy）被明確重建，使後續確定性 W-RAC 解析器（deterministic W-RAC parser）能直接消費。

這一步的關鍵在於：多模態模型讀取的是像素（pixels）而非格式專屬標記（format-specific markup），因此單一管線即可處理企業知識庫（enterprise knowledge base）中的各種文件類型，將每種格式的工程成本降為通用 PDF 轉換（commodity-to-PDF conversion）。

**第三階段：解析與分段**  
轉換後的檢索優化 Markdown（retrieval-optimized Markdown）被 W-RAC 的確定性解析器拆解為結構化、ID 可定址單元。針對大型文件，D-RAC 引入可擴展分段演算法（scalable sectioning algorithm）：遞迴地在標題邊界（header boundaries）處切分文件，並將父標題語境帶入每一次 LLM 規劃呼叫。這使得分塊規劃可以橫跨 500 頁以上的文件，而不會因上下文長度爆炸而失效。

**第四階段：規劃與重建**  
LLM 不再輸出區塊文字，而是輸出元素 ID 的有序陣列，決定哪些 ID 可定址單元應被合併為一個檢索就緒分塊（retrieval-ready chunk）。原始文字（source text）在分塊過程中絕不被重新生成，因此保留了 W-RAC 的成本、確定性（determinism）與可觀測性（observability）優勢。這種「語意規劃問題（semantic planning problem）」而非「文字生成問題（text generation problem）」的設計，是 D-RAC 相較於代理式分塊（agentic chunking）成本大幅降低的根本原因。

總結來說，D-RAC 的方法論是一種「一次昂貴但可控的視覺理解 + 多次廉價且確定的結構操作」的架構。它將企業文件攝取中最困難的「版面與結構復原」交給多模態模型一次性解決，而將「如何切分以利檢索」保留為可由小型模型或甚至規則完成的規劃任務。

#### 實驗數據解讀

論文在 RAG 多語料庫基準測試（RAG-Multi-Corpus benchmark）的 PDF 子集上進行評估，該子集包含 236 份文件、795 頁，橫跨五個企業領域（enterprise domain）。主要結果如下：

- **吞吐量與穩健性**：D-RAC 在 72 分鐘內完成整個語料庫的轉換與分塊，產生 1,748 個檢索就緒分塊，且「零錯誤（zero errors）」。這顯示該管線在真實企業文件上具有高度的實用穩定性，而非僅在乾淨資料上有效。
- **輸出權杖（output token）削減**：與使用前沿大型語言模型（frontier LLM）的代理式分塊相比，D-RAC 在分塊階段減少 **95.7%** 的輸出權杖。這是因為代理式分塊需要 LLM 同時修復提取損壞並重新生成完整文件文字，而 D-RAC 只需輸出 ID 陣列。
- **成本降低**：以 GPT-4.1 計價，分塊階段成本降低 **77.8%**；以 Gemini 2.5 Pro 計價，降低 **85.6%**。成本差異來自兩個模型輸入/輸出權杖（input/output token）的相對定價不同，但無論哪種定價，D-RAC 都顯著便宜。
- **延遲降低**：分塊時間（chunking time）減少 **75%**。這與 W-RAC 先前報告的端到端延遲（end-to-end latency）降低約 60% 一致，並進一步證明將分塊從文字生成轉為 ID 規劃對延遲的正面影響。
- **可擴展性**：D-RAC 可線性擴展至 500 頁以上的文件。這歸功於可擴展分段演算法將長文件在標題邊界處遞迴切分，避免單次 LLM 呼叫過長。

這些數字需要從幾個角度理解：

1. **成本結構的轉移**：D-RAC 並非完全不用 LLM，而是將 LLM 的使用從「每個區塊都生成文字」轉移到「一次性多模態轉換 + 輕量 ID 規劃」。因此成本降低主要來自輸出權杖的劇減，符合論文先前觀察到的「輸出權杖成本約為輸入權杖的 4 倍」這一事實。
2. **零錯誤的意義**：在 795 頁的異質企業文件上達到零錯誤，暗示多模態模型在版面理解與 Markdown 轉換上的可靠性已足以支撐生產級攝取管線。但讀者應注意，「零錯誤」的定義可能僅指管線未崩潰或產生無效輸出，未必代表轉換內容 100% 無幻覺（hallucination）。
3. **規模線性**：線性擴展至 500+ 頁對法律合約、技術手冊、年度報告等長文件場景特別重要，這正是企業知識庫中常見但現有系統經常失敗的領域。

#### 與現有研究的比較

D-RAC 的定位介於四類現有方法之間，並試圖結合它們的優點、迴避缺點：

**相較於基於規則的提取（rule-based extraction）**  
PyMuPDF、pdfminer、pdfplumber 等工具雖然快速且無 LLM 成本，但深受 PDF 呈現格式（presentation format）病理影響：多欄版面（multi-column layout）的閱讀順序（reading order）錯亂、頁首頁尾夾雜內文、連字號殘留、表格變成幾何位置（geometric position）曖昧的碎片。D-RAC 以多模態視覺理解取代啟發式規則，從根本上解決了版面復原問題。

**相較於版面分析與 OCR 管線（layout-analysis and OCR pipelines）**  
LayoutLM、LayoutLMv2、Docling 等系統能偵渊版面區域並重建閱讀順序，但它們需要專屬模型部署，對行銷型企業文件（如保險手冊、產品單頁）的少見版面適應不佳，且仍將表格輸出為網格。D-RAC 的檢索感知表格正規化（table normalization）策略將表格轉為列級散文陳述，解決了「儲存格脫離行列語境後語意無意義」的經典失敗模式。

**相較於代理式分塊（agentic chunking）**  
代理式分塊讓 LLM 直接對提取文字進行分塊，但同時承擔「修復提取損壞」與「重新生成全文」兩大任務，導致輸出權杖、延遲與幻覺風險（hallucination risk）最大化。D-RAC 的洞察是：只讓多模態模型做一次格式轉換，之後的分塊規劃在 ID 上進行，將文字生成成本從「每次分塊或重新分塊都付費」變為「只付一次」。

**相較於視覺引導分塊（vision-guided chunking）**  
近期研究顯示多模態模型讀取頁面影像（page images）在文件理解上優於文字提取管線，但若直接用大型視覺模型同時負責理解與區塊生成，仍保留代理式分塊的全部輸出權杖成本。D-RAC 的區別在於嚴格區分「轉換」與「規劃」：視覺模型只做轉換，分塊由輕量規劃完成。

**主要改進**  
- 格式無關：任何可渲染為 PDF 的格式都能攝取，無需每種格式寫專屬解析器。  
- 檢索感知輸出：表格轉為自包含散文陳述、標題層級明確重建，直接優化嵌入與檢索精確度（retrieval precision）。  
- 成本與延遲：輸出權杖減少 95.7%，分塊成本降低 77.8–85.6%，時間降低 75%。  
- 可擴展性：透過遞迴分段與父標題語境攜帶，支援 500+ 頁文件。

**潛在限制**  
- 多模態轉換的品質仍是瓶頸：若視覺模型誤讀表格、忽略小字或產生幻覺，後續確定性分塊無法修正內容錯誤，只能忠實地切分錯誤內容。  
- 表格被重寫為散文陳述雖然提升檢索，但可能損失某些需要精確行列對應的下游任務（如數值比較、結構化問答）。  
- PDF 正規化依賴現有工具鏈，對於極少數無法正確渲染為 PDF 的格式或動態互動文件，D-RAC 可能失效。  
- 實驗僅報告了分塊階段的成本與延遲，未深入報告最終 RAG 系統在問答準確率上的端到端提升，雖然這可能受限於基準測試設計。

#### 可重現性評估

根據目前提供的論文內容，**開源程式碼、模型權重與資料集的可用性並未明確說明**。以下從幾個層面評估：

**資料集**  
RAG-Multi-Corpus benchmark 是論文使用的評測基準，但其是否公開、授權方式與取得管道在摘要與前段內容中未提及。若該基準為公開資料集，則實驗結果在原則上可重現；若為內部或受授權限制的企業文件集合，則外部研究者難以完全複製。

**模型與工具**  
- 多模態轉換使用 Gemma-3 27B 與 Gemma-3 12B，透過 AWS Bedrock 提供。Gemma 系列模型權重通常可公開取得，但 Bedrock 託管版本的行為可能與自行部署略有差異。  
- PDF 正規化使用 headless LibreOffice、列印成 PDF、影像包裝等標準工具，這些都是現成可取得的開源或作業系統內建工具，可重現性高。  
- W-RAC 的確定性解析器與分段演算法是否開源，取決於前作是否釋出程式碼；若未釋出，則 D-RAC 的完整重現仍有障礙。

**實驗細節**  
論文提供了部分關鍵超參數：200 DPI 渲染、長邊 1,568 像素、每批 5 頁、最多 5 批並行、Gemma-3 模型。轉換提示詞（prompt）放在附錄 A.1，若附錄完整公開，將有助於重現。然而，諸如溫度（temperature）、top-p、重試策略、錯誤判定標準等細節尚未在摘要中揭露，這些都會影響「72 分鐘、零錯誤」結果的可重現性。

**整體評估**  
D-RAC 的方法論本身描述得相當清楚，核心概念（PDF 正規化 → 多模態 Markdown 轉換 → W-RAC 分塊）可在擁有適當模型與工具的情況下重新實作。但若論文未伴隨開源程式碼與完整提示詞，外部研究者要達到論文宣稱的精確成本與延遲數字仍有挑戰。建議作者釋出：  
1. 完整原始碼（含 W-RAC 解析器與 D-RAC 轉換管線）。  
2. 附錄中的完整提示詞與系統提示。  
3. 評估腳本與成本計算方式。  
4. 若資料集無法公開，至少提供合成或去識別化的範例文件與預期輸出。

#### 未來研究方向

D-RAC 雖然在企業文件攝取上邁出重要一步，仍有若干值得延伸的方向：

**1. 下游 RAG 效能的端到端評估**  
目前實驗強調分塊階段的成本、延遲與穩健性，但未深入探討轉換後的檢索就緒分塊在實際問答任務上的表現。未來可在公開問答基準（如 DocVQA、InfographicsVQA、企業財報問答）上測量最終檢索精確度與答案正確率，驗證「檢索感知 Markdown」確實優於傳統 OCR 或表格網格表示。

**2. 表格表示的權衡與自適應策略**  
將表格轉為列級散文陳述雖提升檢索，但可能不利於需要精確行列關係的任務。未來可研究混合表示：對簡單事實表使用散文陳述，對複雜數值表保留結構化 Markdown 表格或附加元資料，並由模型根據表格特性自適應選擇表示方式。

**3. 更小、更專精的多模態模型**  
Gemma-3 27B/12B 已屬輕量，但對超大規模企業知識庫而言，轉換成本仍可能累積。未來可探索針對「PDF → 檢索優化 Markdown」任務微調的更小視覺語言模型（VLM），例如 4B–8B 等級，以進一步降低延遲與成本，同時保持結構復原品質。

**4. 動態與互動文件的攝取**  
D-RAC 假設輸入可靜態渲染為 PDF。對於動態儀表板、互動式網頁應用、嵌入式影片或動畫簡報，現有 PDF 正規化會遺失互動語意。未來可研究如何將這些動態內容擷取為時間序列或互動腳本，再整合進檢索框架。

**5. 多語言與手寫文件**  
企業知識庫常包含多語言文件與手寫批註。多模態模型在這些場景的表現可能不如印刷體英文穩定。未來可針對多語言版面、手寫字跡、低品質掃描影像進行資料增強與模型調適。

**6. 可解釋的錯誤偵測與人機協作校正**  
雖然 D-RAC 達到零錯誤，但生產環境中仍可能出現轉換幻覺。未來可加入「轉換品質評分」模組，自動標記低信心度的頁面或表格，並將其提交給人類或更強大的模型進行二次驗證，形成人機協作（human-in-the-loop）的攝取管線。

**7. 與 W-RAC 的統一框架**  
D-RAC 與 W-RAC 目前仍是兩個針對不同輸入格式的框架。未來可將兩者統一為單一的「檢索感知攝取平台」，根據輸入是網頁、PDF、Office 文件或掃描檔，自動選擇最適合的正規化路徑與轉換模型，並共享同一套 ID 可定址單元與分塊規劃引擎。

**8. 持續更新與增量分塊**  
企業文件經常修訂。未來可研究增量式 D-RAC：當文件更新時，只重新轉換與重新規劃變更的頁面或章節，而非從頭處理整份文件，以進一步降低長期維運成本。

## 論文問答

**Q1：D-RAC 主要想解決企業 RAG 系統在文件攝取時的什麼核心問題？**

A：D-RAC 旨在解決企業知識庫中異質文件格式（如 PDF、Word、PPT、Excel 與掃描檔）難以被有效攝取並轉為檢索就緒分塊的問題。這些文件的內容常被鎖定在複雜的視覺版面、多欄排版與密集表格中，傳統方法難以恢復正確的閱讀順序與標題層級。由於企業文件並非語意格式而是呈現格式，直接抽取文字會導致結構破碎，進而影響後續檢索增強生成的品質。

**Q2：傳統的規則抽取、OCR 與代理式分塊方法為何難以處理企業 PDF 文件？**

A：規則式抽取工具（如 PyMuPDF、pdfplumber）雖然快速且無需 LLM 成本，但會繼承 PDF 格式的各種病徵，例如多欄版面打亂閱讀順序、頁首頁尾穿插於內文、表格被壓平為以空白分隔的權杖，且標題層級僅能透過字型大小進行啟發式推測。OCR 與版面分析模型雖然能改善結構恢復，但仍需額外部署專屬模型，對行銷型企業文件（如保險手冊、產品單頁）的奇特版面適應不佳，且仍將表格輸出為網格，導致儲存格脫離欄位標題後語意不明。代理式分塊則讓 LLM 同時修復抽取損壞並重新生成全文，這會最大化輸出權杖數量、延遲與幻覺風險，使分塊成本與錯誤率同步上升。

**Q3：為什麼解決企業文件的結構恢復問題對 RAG 系統特別重要？**

A：企業知識庫是 RAG 系統最主要的知識來源之一，若文件內容無法被正確解析，檢索器就難以找到與使用者查詢真正相關的片段。錯誤的閱讀順序與扁平化的表格會讓嵌入模型產生語意失準的向量表示，進而降低檢索精確度與生成答案的可信度。因此，能夠忠實保留文件結構並產出檢索就緒分塊的攝取流程，是企業級 RAG 能否落地的關鍵基礎建設。

**Q4：D-RAC 的核心流程包含哪幾個階段，各自扮演什麼角色？**

A：D-RAC 的管道分為四個階段：PDF 正規化與頁面渲染、多模態 Markdown 轉換、解析與分段、以及規劃與重建。第一階段利用標準工具將各種輸入格式統一轉為 PDF，並將每頁渲染為 PNG 圖像；第二階段透過多模態大型語言模型將渲染頁面轉為檢索優化 Markdown，並將表格重寫為列級散文陳述。第三階段以確定性解析器將 Markdown 轉為 ID 可定址單元，第四階段則由輕量級 LLM 僅輸出識別符陣列來規劃分塊邊界，原始文字在分塊過程中絕不重新生成。

**Q5：相較於直接使用多模態模型進行視覺導引分塊，D-RAC 的關鍵創新在哪裡？**

A：D-RAC 的關鍵創新在於將多模態 LLM 的使用限制在「格式轉換」這單一階段，而非讓它同時負責理解與生成區塊內容。轉換完成後，所有下游操作皆為確定性解析或基於識別符的分塊規劃，這大幅減少了輸出權杖數量與推理呼叫次數。這種設計讓 D-RAC 能同時享有視覺理解對複雜版面的優勢，以及 W-RAC 在成本、確定性與可觀測性上的好處。

**Q6：D-RAC 為何選擇將所有輸入先正規化為 PDF，而不是為每種格式開發專屬解析器？**

A：PDF 被視為通用視覺交換格式，因為幾乎所有企業文件格式（DOCX、PPTX、XLSX、HTML、掃描影像）都能透過標準工具以忠實且確定性的方式渲染為 PDF。將各種異質格式統一轉為 PDF 後，後續只需一套以像素為輸入的多模態轉換管道，無需為每種格式維護專屬解析器。這種格式無關的設計大幅降低了工程複雜度，並讓任何可渲染格式都能成為第一類輸入。

**Q7：D-RAC 的實驗使用了哪個基準測試，其規模與組成為何？**

A：實驗在 RAG 多語料庫基準測試（RAG-Multi-Corpus benchmark）的 PDF 子集上進行，該子集包含 236 份文件、共 795 頁，橫跨五個企業領域。這個資料集能夠評估方法在不同產業領域文件上的泛化能力與穩健性。論文測量了轉換吞吐量、分塊效率、穩健性，以及對 500 頁以上文件的可擴展性。

**Q8：D-RAC 在分塊效率與成本上取得了哪些關鍵量化結果？**

A：在 795 頁的 PDF 子集上，D-RAC 僅用 72 分鐘就完成整個語料庫的轉換與分塊，且未發生任何錯誤，共產生 1,748 個檢索就緒分塊。與使用前沿 LLM 的代理式分塊相比，D-RAC 在分塊階段的輸出權杖減少 95.7%，分塊成本降低 77.8%（GPT-4.1 計價）至 85.6%（Gemini 2.5 Pro 計價），分塊時間也減少 75%。這些數據顯示 D-RAC 在保持品質的同時顯著提升了經濟性與速度。

**Q9：D-RAC 在可擴展性與穩健性方面表現如何？**

A：D-RAC 在 236 份、795 頁的語料庫上達到零錯誤轉換與分塊，證明其對真實企業文件具有高度穩健性。此外，論文指出 D-RAC 可線性擴展至 500 頁以上的文件，這得益於其可擴展分段演算法會在標題邊界遞迴拆分大型文件，並將父標題上下文帶入每次 LLM 規劃呼叫。這種設計讓單次規劃呼叫無需處理過長內容，從而避免上下文長度限制與成本爆炸。

**Q10：哪些實際企業場景最適合導入 D-RAC？**

A：D-RAC 特別適合需要攝取大量異質企業文件的場景，例如金融業的法規遵循文件、保險業的產品手冊與保單條款、醫療業的病歷與研究報告，以及法律業的合約與訴訟資料。這些領域的文件常包含多欄排版、密集表格與複雜標題層級，傳統抽取方法容易破壞語意結構。由於 D-RAC 能將表格轉為可獨立檢索的散文陳述，對於需要精確檢索表格事實的應用尤其有價值。

**Q11：從產品化與維運角度來看，D-RAC 有哪些優勢？**

A：D-RAC 的確定性解析與 ID 可定址設計讓整個流程具備高度可觀測性，工程團隊可以清楚檢視每個解析元素、分段與分塊規劃的產出。由於分塊階段不重新生成原始文字，輸出結果穩定且可重現，便於除錯、稽核與版本控制。此外，單一多模態轉換管道即可處理多種格式，減少了為每種文件類型維護專屬解析器的營運負擔。

**Q12：D-RAC 對文件攝取與 RAG 領域可能帶來什麼樣的影響？**

A：D-RAC 示範了將「視覺理解」與「檢索感知規劃」分離的設計典範，可能促使更多研究與產品採用「單次多模態轉換 + 確定性下游處理」的架構。它降低了企業將各種文件格式納入 RAG 系統的門檻，讓掃描檔、簡報、試算表等過去難以處理的格式都能成為高品質知識來源。長遠來看，這種方法有助於推動企業 RAG 從「僅能處理乾淨文字」走向「真正理解任意企業文件」。

**Q13：D-RAC 目前有哪些可能的使用限制或能力邊界？**

A：D-RAC 依賴輸入文件能夠被忠實渲染為 PDF，若原始格式在轉 PDF 過程中遺失重要視覺資訊（如動態內容或特殊字型），則後續轉換品質可能受影響。此外，多模態 LLM 的轉換品質與其視覺編碼器解析度有關，過小或過度壓縮的字體可能導致辨識錯誤。雖然論文報告零錯誤，但這仍是在特定基準與模型配置下的結果，極端複雜或低品質掃描文件可能需要額外處理。

**Q14：在哪些情況下 D-RAC 可能出現失敗或表現不佳？**

A：當文件版面極度不規則、包含大量裝飾性圖像與文字重疊，或掃描影像解析度過低導致文字難以辨識時，多模態轉換可能產生不準確的 Markdown。若表格結構極為複雜（如巢狀表格、跨欄跨列合併儲存格），將其轉為列級散文陳述也可能遺失部分結構資訊。此外，若文件內容需要頁面間的強烈語意連貫（如跨頁的數學推導或圖表說明），僅依賴頁面級轉換可能難以完整保留上下文。

**Q15：未來研究可以從哪些方向進一步擴展 D-RAC？**

A：未來可以探索更細緻的多模態轉換策略，例如針對複雜表格、圖表與公式設計專門的檢索感知表示，而不僅限於列級散文陳述。另一個方向是結合頁面間的跨頁上下文，讓轉換模型在處理當前頁面時能參考前後頁資訊，以改善連續性內容的品質。此外，也可以研究如何將 D-RAC 與主動學習或人機協作回饋機制結合，讓系統能從實際檢索錯誤中持續改進轉換與分塊策略。

## 實作前置條件

**資料準備**
- 原始文件集合：PDF、DOCX、PPTX、XLSX、HTML 或掃描影像皆可。
- 儲存空間：需保留原始檔、正規化後 PDF、渲染頁面 PNG、轉換後 Markdown 與分塊結果。
- 評估資料：建議準備 50–200 組問答對，用於驗證檢索精確度與轉換正確性。

**運算資源**
- PDF 正規化與渲染：可於 CPU 執行（本研究約 1–7 秒／文件），建議安裝 headless LibreOffice、poppler 或類似工具。
- 多模態大型語言模型：可使用 Gemma-3 27B／12B（透過 AWS Bedrock）或其他可接收圖像輸入的多模態 LLM。
- 向量資料庫與嵌入模型：用於儲存與索引檢索就緒分塊。
- 記憶體與網路：批次處理 5 頁、平行 5 批次時，需足夠記憶體與穩定 API 連線。

**技能需求**
- 熟悉 Python、RAG 流程與 LLM API 呼叫。
- 了解 PDF 渲染工具與 Markdown 結構化解析。
- 具備基礎評測能力，能計算檢索精確度、分塊成本與延遲。

## 實作步驟建議

1. **文件盤點與 PDF 正規化**  
   統計現有格式分布，使用標準工具將各類文件轉為 PDF：headless LibreOffice 處理 Office 格式、列印為 PDF 處理 HTML、影像包裝處理掃描檔。此步驟為確定性渲染，無需 LLM。

2. **頁面渲染與畫質設定**  
   將 PDF 每頁轉為 200 DPI 的 PNG，並將長邊縮放至不超過 1,568 像素，以符合常見視覺編碼器限制，同時保留小字與表格內容清晰可讀。

3. **多模態 Markdown 轉換**  
   以每批 5 頁、平行 5 批次的方式送入多模態 LLM，提示模型輸出檢索優化 Markdown：表格改寫為列級散文陳述、重建標題層級、抑制裝飾性圖像。此為整個流程中唯一接觸文件內容的 LLM 階段。

4. **確定性解析與分段**  
   將轉換後的 Markdown 餵入 W-RAC 確定性解析器，產生 ID 可定址單元。對於 500 頁以上大型文件，使用可擴展分段演算法沿標題邊界遞迴切割，並將上層標題脈絡帶入每次分塊規劃呼叫。

5. **分塊規劃（僅輸出識別碼）**  
   由輕量級 LLM 僅輸出元素識別碼陣列來決定區塊邊界，不重新生成原始文字。這保留了 W-RAC 的成本、確定性與可觀測性優勢。

6. **嵌入、索引與上線**  
   為每個檢索就緒分塊產生嵌入向量，連同來源文件 ID、頁碼、標題路徑等後設資料寫入向量資料庫，並對接生成模型與檢索介面。

7. **評估與持續監控**  
   追蹤轉換錯誤率、分塊數量、輸出權杖量、分塊階段成本與端到端延遲；定期抽樣人工審查表格轉換與標題層級正確性。

## 潛在風險與注意事項

- **PDF 正規化可能遺失非視覺資訊**  
  互動表單、影片、音訊或文件內嵌結構化資料在轉為靜態 PDF 後可能遺失，需評估是否需額外提取這些元素。

- **多模態轉換仍有誤讀與幻覺風險**  
  極小字體、模糊掃描或複雜圖表可能被誤判。建議保留高 DPI 渲染、在提示中加上格式約束，並對關鍵文件進行抽樣人工稽核。

- **表格正規化可能弱化數值關係**  
  將表格改寫為散文陳述雖提升檢索性，但可能讓跨列比較或精確數值關係變得不明顯。對於高度數值導向的應用，可考慮同時保留原始表格結構作為後備。

- **大型文件需特別注意上下文限制**  
  雖然 D-RAC 可擴展至 500 頁以上文件，但仍需正確執行遞迴分段與上層標題脈絡傳遞，否則分塊規劃可能遺漏跨章節語意。

- **輸出 Markdown 品質影響下游解析**  
  若多模態模型產生格式不一致的 Markdown，確定性解析器可能失敗。建議加入 Markdown 驗證與錯誤重試機制。

- **合規與隱私**  
  將企業文件頁面送至第三方多模態 API 前，應確認資料處理協議；敏感場景建議採用地端部署模型。

## 與其他技術的整合建議

- **上游文件連接器**  
  將 D-RAC 接在現有 CMS、SharePoint、S3 或企業檔案系統之後，作為統一的文件攝取層，取代多種格式專屬解析器。

- **向量資料庫與檢索器**  
  轉換後的分塊可直接寫入 Pinecone、Weaviate、Milvus 或 pgvector，並搭配稀疏檢索、重排模型與後設資料過濾器提升檢索精確度。

- **OCR 與版面分析作為後備**  
  對於渲染品質極差的掃描檔，可保留 LayoutLM、Docling 或傳統 OCR 作為降級方案，並以 D-RAC 為主要路徑。

- **可觀測性工具**  
  將每個階段（正規化、轉換、解析、規劃）產生的工件與識別碼陣列記錄到 Langfuse、LangSmith 或自架日誌系統，方便除錯與審計。

- **持續評估 CI**  
  在部署流程中加入 RAG 多語料庫基準測試子集，自動比較 D-RAC 與既有分塊方法的檢索精確度、成本與延遲。

## 給不同背景讀者的閱讀建議

**給初學者**  
請先掌握 RAG 的基本概念，再把重點放在 D-RAC 的四個階段：PDF 正規化、多模態 Markdown 轉換、確定性解析、識別碼導向分塊規劃。核心要理解「分塊是規劃問題，不是文字生成問題」，這正是成本降低與幻覺風險減少的關鍵。

**給 AI 工程師**  
建議深入閱讀多模態轉換提示設計、每批 5 頁的批次策略、200 DPI／1,568 像素的渲染參數，以及 W-RAC 解析器如何產生 ID 可定址單元。同時留意可擴展分段演算法在長文件中的實作細節與錯誤處理機制。

**給研究人員**  
可關注本研究與代理式分塊、版面分析模型及通用 OCR 的對照實驗，特別是表格正規化對嵌入與檢索的影響、多模態轉換的結構保真度，以及 500 頁以上文件的擴展性分析。這些都是後續可延伸的研究方向。

**給產品經理**  
請聚焦在適用場景與投資報酬：D-RAC 在分塊階段可減少 95.7% 輸出權杖、降低 77.8–85.6% 成本並縮短 75% 時間，同時維持可觀測性。評估時請同時考量多模態轉換的單次成本、掃描檔品質風險，以及與現有知識庫系統的整合複雜度。
