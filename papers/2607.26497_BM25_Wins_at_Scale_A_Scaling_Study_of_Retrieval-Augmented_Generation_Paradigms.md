# BM25 在規模化下勝出：檢索增強生成（Retrieval-Augmented Generation, RAG）典範的擴展性研究

**原文標題：** BM25 Wins at Scale: A Scaling Study of Retrieval-Augmented Generation Paradigms  
**作者：** Pengyu Wang、Benfeng Xu、Shaohan Wang 等 7 位作者  
**發布日期：** 2026-07-30

## ⚡ TL;DR

現有RAG典範多在單一語料規模評估，準確率與成本的擴展性仍不明確。
本研究以企業級基準建立28層嚴格巢狀語料，統一閱讀模型與評判協定，量測準確率、建構與查詢詞元及延遲。
檔案系統智慧體在小規模領先，約千萬詞元時BM25反超並持續領先，全規模領先近20點且成本最低。

## 摘要翻譯

檢索增強生成（Retrieval-Augmented Generation, RAG）涵蓋詞彙檢索（lexical retrieval）、稠密檢索（dense retrieval）、基於圖的索引（graph-based indexing）與智慧體搜尋（agentic search），但這些典範通常在不同基準測試中，各自僅於單一語料庫規模（corpus size）下進行評估，導致其準確率–成本擴展性（accuracy-cost scaling）仍不明確。為彌補此缺口，我們提出一項對照研究（controlled study），在 28 個嚴格巢狀（strictly nested）的層級（tiers）上變動語料庫規模，規模跨度約達 450 倍，同時保持問題以及由固定之相關文件（relevant documents）與對抗文件（adversarial documents）所構成的基礎層（bedrock）不變。在單一閱讀模型（reader model）與單一評判協定（judging protocol）下，我們測量官方準確率（official accuracy）、建構詞元（construction tokens）與查詢詞元（query tokens），以及延遲（latency）。結果呈現的是一種依規模變化的反超現象（scale-dependent crossover），而非無條件的領先者。檔案系統智慧體（File-System Agent）在最小共享層級（shared tiers）中領先，但其在基礎層的循序探索所耗查詢詞元為其他方法的 39 倍之多，且隨著搜尋空間（search space）擴大而效果遞減。在語料庫詞元（corpus tokens）數約達一千萬時，BM25 超越它，並在每個更大的共享層級中領先，在完整規模（full scale）下領先幅度接近 20 個百分點。BM25 亦在無需基於大型語言模型（Large Language Model, LLM）建構（LLM-based construction）的情況下，穩居帕雷托前沿（Pareto frontier）的低成本端。稠密檢索仍具效率但準確率較低；相對地，基於圖的檢索增強生成（graph-based RAG）在達到部署規模（deployment scale）前即遭遇建構瓶頸（construction walls），且其可擴展變體（scalable variants）在共享層級中仍落後於 BM25。整體而言，語料庫增長愈來愈有利於全局候選排序（global candidate ranking）：詞彙檢索是最強的可擴展預設方法（scalable default），而智慧體推理（agentic reasoning）最適合在排序後發現（ranked discovery）的基礎上運作，而非取而代之。

### 核心貢獻（3～5點）
- 提出一項在 28 個嚴格巢狀層級上變動語料庫規模（約 450 倍跨度）的對照研究，固定問題與基礎層文件，以統一評估多種 RAG 典範的準確率–成本擴展性。
- 發現規模化下存在依規模變化的反超現象：檔案系統智慧體在小規模領先但查詢成本極高；BM25 在約一千萬語料庫詞元後反超，並於更大規模持續領先，完整規模領先近 20 個百分點。
- 顯示 BM25 無需基於大型語言模型的建構即可位於帕雷托前沿的低成本端，是強健且可擴展的預設方法；稠密檢索效率佳但準確率較低，圖式 RAG 則在部署規模前遭遇建構瓶頸。
- 指出語料庫增長愈發有利於全局候選排序，智慧體推理應作為排序後發現的後續強化，而非取代排序檢索。

### 適合對象
從事 RAG 系統設計、企業知識庫檢索、以及關注大規模部署下準確率–成本權衡的研究人員與工程師；特別適合需要選擇可擴展預設檢索策略的實務工作者。

## 深度分析

#### 方法論解析

##### 研究目標與核心設計
本研究旨在解決檢索增強生成（Retrieval-Augmented Generation, RAG）領域中一個長期被忽視的問題：不同典範（paradigms）的**準確率–成本擴展性（accuracy-cost scaling）**幾乎從未被在同一基準、同一語料庫規模（corpus size）梯度下進行對照。既有研究通常各自在單一語料庫規模、不同評測基準上比較詞彙檢索（lexical retrieval）、稠密檢索（dense retrieval）、基於圖的檢索增強生成（graph-based RAG）與智慧體搜尋（agentic search），導致方法之間的優劣難以歸因於檢索機制本身，而非閱讀模型（reader model）、問題集（question set）、評判協定（judging protocol）或語料庫難度（corpus difficulty）等混淆因子（confounding factors）。

為此，作者採用**對照研究（controlled study）**設計，在 Enterprise RAG-Bench（Sun et al., 2026）這個企業級 RAG 評測基準上，建構一條由 28 個**嚴格巢狀（strictly nested）**層級組成的語料庫階梯（corpus ladder），文件數從 1,144 層遞增至 511,959，語料庫詞元（corpus tokens）從約 1.7M 擴展到 601M，增幅約 450 倍。關鍵在於：每一層都保留相同的問題、**相關文件（relevant documents）**與**對抗干擾文件（adversarial distractors）**，額外加入的文件則依固定、來源與噪音分層（source-and-noise-stratified）的順序遞增。這種設計讓「語料庫規模變大」成為唯一被操弄的變項，從而能夠觀察各典範在規模化（scaling）過程中的表現軌跡。

##### 四種典範與七條管線
研究統一評估了四個 RAG 典範、共七條管線：

1. **詞彙檢索（lexical retrieval）**：以 BM25 為代表，建立倒排索引後進行全局候選排序（global candidate ranking）。
2. **稠密檢索（dense retrieval）**：使用輕量區塊嵌入向量（chunk embeddings）進行相似度檢索。
3. **基於圖的檢索增強生成（graph-based RAG）**：包含 MS-GraphRAG（Edge et al., 2025）、LightRAG（Guo et al., 2025）、HippoRAG 2（Gutiérrez et al., 2025a,b），以及 LinearRAG（Zhuang et al., 2025）。前三者依賴大型語言模型（Large Language Model, LLM）抽取實體（entities）與關係（relations），後者則以命名實體識別器（Named-Entity Recognizer, NER）與嵌入向量建構實體共現圖。
4. **智慧體搜尋（agentic search）**：以**檔案系統智慧體（File-System Agent）**為代表，透過迭代工具迴圈（iterative tool loop）對原始每來源檔案樹（per-source file tree）執行檔案系統工具呼叫（file-system tool calls），屬於循序檢索策略（sequential retrieval policy）。

##### 統一閱讀模型與評判協定
為避免閱讀模型與評判方式成為混淆因子，所有管線共用同一個底層閱讀模型（reader model），並以 Enterprise RAG-Bench 的**官方準確率（official accuracy）**為主要指標。此外，作者還引入獨立評判者與二元評判協定（binary protocol）進行交叉驗證，以降低評判協定依賴（judge dependence）對結論的影響。

##### 成本計量框架
本研究將成本區分為**離線成本（offline cost）**與**線上成本（online cost）**：
- **離線成本**：索引建構（indexing）階段消耗的**建構詞元（construction tokens）**，包括生成詞元（generative tokens）與嵌入詞元（embedding tokens）。
- **線上成本**：查詢階段消耗的**查詢詞元（query tokens）**與**延遲（latency）**。

透過詞元層級（token-level）計量，研究得以描繪各典範在**帕雷托前沿（Pareto frontier）**上的位置，並回答「準確率提升是否值得相應成本」這一部署導向問題。

#### 實驗數據解讀

##### 規模化反超現象（scale-dependent crossover）
本研究最核心的發現是存在**依規模變化的反超現象（scale-dependent crossover）**，而非某個典範在所有規模下都勝出。在最小共享層級（shared tiers）上，**檔案系統智慧體（File-System Agent）**的官方準確率點估計最高；然而當語料庫詞元達到約 1,000 萬（10M corpus tokens）時，BM25 開始反超，並在之後每一個更大的共享層級都保持領先。在完整規模（full scale）的 601M 詞元語料庫上，BM25 相對於 File-System Agent 的領先幅度接近 20 個百分點。

這個反超現象具有重要的方法學意義：它說明「在小規模評測上表現最好的方法」未必能推廣到企業級部署規模（deployment scale）。對於正在評估 RAG 架構的工程團隊而言，這意味著必須在接近實際語料庫規模的環境中進行測試，否則容易選錯基線。

##### BM25 的規模不變查詢成本與準確率優勢
BM25 的強勢來自兩個互補特性：
1. **查詢成本幾乎與語料庫規模無關**：由於倒排索引的結構，BM25 在語料庫擴大時，線上查詢詞元（query tokens）與延遲（latency）並未顯著增長，呈現接近規模不變（scale-invariant）的查詢成本。
2. **全局候選排序（global candidate ranking）的擴展性**：隨著語料庫變大，BM25 仍能對所有候選文件進行一次性排序，並將相關文件與對抗文件區分開來。相較於需要逐步探索的智慧體策略，這種全局排序在搜尋空間（search space）擴大時反而更具優勢。

因此，BM25 不僅在準確率上領先，還錨定了**帕雷托前沿（Pareto frontier）**的低成本端，成為「最強可擴展預設方法（strongest scalable default）」。

##### File-System Agent 的早期優勢與後期成本爆炸
File-System Agent 在小規模時表現較好，原因在於其**循序檢索策略（sequential retrieval policy）**能夠根據前期工具呼叫結果調整下一步探索方向，對於文件數量有限、路徑可窮舉的情境相當有效。然而，當語料庫規模擴大時：
- **搜尋空間（search space）成指數級膨脹**，循序探索越來越容易遺漏關鍵文件；
- 在**基礎層（bedrock）**上，其查詢詞元消耗是 BM25 的 39 倍；
- 隨著規模增加，其查詢成本持續上升，而準確率卻相對下滑。

這顯示「以智慧體推理（agentic reasoning）取代排序」在企業級規模下並不具成本效益；智慧體推理更適合作為**排序後發現（ranked discovery）**之後的補強，而非獨立承擔大規模檢索任務。

##### 稠密檢索（dense retrieval）的定位
稠密檢索在實驗中展現出良好的效率，但其官方準確率（official accuracy）始終低於 BM25 與 File-System Agent。這可能與以下因素有關：
- 企業級文件包含大量專有名詞、縮寫、表格與非自然語言片段（如程式碼審核、CRM 記錄），詞彙匹配在這些情境下比語義嵌入更穩健；
- 輕量區塊嵌入向量可能無法充分捕捉長文件中的細粒度事實；
- 未使用查詢改寫（query rewriting）或重排序（reranking）等強化機制。

因此，稠密檢索在本研究中呈現「高效率但低天花板」的特性，適合作為成本極度敏感場景的備選，而非追求最高準確率的首選。

##### Graph-Based RAG 的建構瓶頸
基於圖的檢索增強生成（graph-based RAG）面臨的主要問題是**建構瓶頸（construction walls）**：
- MS-GraphRAG、LightRAG、HippoRAG 2 等依賴 LLM 抽取實體與關係的方法，在語料庫擴大到大規模之前，離線建構詞元（construction tokens）就已達到無法負擔的程度，未能完成所有共享層級；
- LinearRAG 雖然以輕量 NER 與嵌入向量取代生成式建構（LLM-based construction），成功避開建構瓶頸，但在所有它能完成的共享層級上，準確率仍低於 BM25。

這項結果對 Graph RAG 社群具有警示意義：「以圖結構組織知識」的構想在理論上很有吸引力，但若建構成本隨語料庫規模線性甚至超線性增長，則在真實企業知識庫（enterprise knowledge bases）部署前就可能被成本擊敗。

##### 帕雷托前沿（Pareto frontier）與成本—準確率權衡
綜合準確率、建構詞元與查詢詞元來看：
- **BM25** 位於帕雷托前沿的低成本高效能端；
- **File-System Agent** 位於高成本端，但在大規模時並未取得相應的準確率回報；
- **Graph-based RAG** 在離線成本上最高，卻未能在準確率上超越 BM25；
- **Dense retrieval** 成本適中，但準確率偏低。

這張帕雷托圖譜為實務選型提供了清晰依據：若目標是在大規模企業語料上取得穩健且可負擔的效能，BM25 應作為預設方法（default）；若願意支付額外成本，則應考慮「BM25 + 智慧體後處理」這類混合架構，而非單純放大智慧體或圖式索引的規模。

#### 與現有研究的比較

##### 相較於單一規模評測的進步
既有 RAG 研究大多在固定語料庫規模下比較方法，並且經常使用不同評測基準，導致結果難以橫向比較。本研究的主要進步在於：
1. **統一語料庫階梯（corpus ladder）**：28 個嚴格巢狀層級讓規模化效應可以被獨立觀察；
2. **統一閱讀模型與評判協定**：排除 reader model 與 judging protocol 的差異；
3. **詞元層級成本計量**：將離線與線上成本納入比較，避免只看準確率而忽略部署成本；
4. **固定相關與對抗文件**：確保問題難度不隨語料庫擴大而改變，從而將效能變化真正歸因於檢索典範本身。

##### 與各典範既有文獻的對照
- **BM25**：長期被視為強基線，但近年常被 Dense Retrieval 或 Graph RAG 文獻在小型語料上超越。本研究指出，當語料庫規模達到千萬詞元級別後，BM25 的擴展性優勢會重新浮現。
- **Dense Retrieval**：過去研究多在 Wikipedia 或 MS MARCO 等相對乾淨的語料上展示優勢；本研究則顯示在包含九種來源、充斥噪音的企業語料中，稠密檢索的準確率天花板較低。
- **Graph-based RAG**：MS-GraphRAG、LightRAG、HippoRAG 2 等先前多在可負擔的小規模語料上展示結構化檢索的優勢。本研究首次系統性地指出其**建構瓶頸（construction walls）**在企業級規模前的嚴重性。
- **Agentic Retrieval**：程式設計智慧體系統（coding-agent systems）如 ClaudeCode、Codex 在程式碼任務上表現出色，但本研究將相同檔案與命令介面（file-and-command interface）應用於企業文件檢索時，發現其循序檢索策略在大規模下效率不彰。

##### 限制與外部效度
儘管實驗設計嚴謹，本研究仍存在若干限制：
- **單一閱讀模型**：所有管線共用同一 reader model，雖然控制了變異，但無法得知不同閱讀模型（例如更強或更小的模型）是否會改變各典範的相對排序。
- **單一評測基準與語言**：Enterprise RAG-Bench 是虛構企業的英文語料，結論能否推廣到多語言、多模態或真實企業知識庫仍需驗證。
- **固定的對抗干擾文件**：雖然這有助於控制實驗，但真實世界中的對抗文件可能隨語料庫擴大而動態變化。
- **特定的智慧體介面**：File-System Agent 採用程式設計智慧體常見的檔案系統工具呼叫介面，其他智慧體架構（例如具備網頁搜尋、資料庫查詢或強化學習檢索策略的 agent）可能表現不同。
- **建構瓶頸可能受預算限制**：Graph-based RAG 未能完成某些層級，部分原因可能是實驗設定的成本預算或計算資源上限，而非方法本身在無限資源下必然失敗。

#### 可重現性評估

##### 資料集與程式碼釋出狀況
根據本文提供的片段，研究使用 Enterprise RAG-Bench（Sun et al., 2026）作為評測基準，該基準包含 511,959 份文件、500 道問題、每題的黃金文件、黃金答案與原子答案事實。然而，文中並未明確提及是否公開釋出原始程式碼、模型權重或完整實驗腳本。若該基準與相關程式碼未來能夠開源，將大幅提升本研究的可重現性；反之，其他研究者僅能依賴文中描述的管線架構與超參數進行近似復現。

##### 實驗設定與超參數透明度
本研究在方法論部分詳細說明了語料庫階梯的建構方式、各典範的管線組成、統一閱讀模型與評判協定，以及詞元層級成本計量框架。這些資訊對於重現實驗至關重要。不過，若要完全重現，仍需要以下細節：
- 各管線的確切提示詞（prompts）與工具迴圈（tool loop）預算；
- BM25 與稠密檢索的區塊大小（chunk size）、top-k 設定與重排序策略；
- Graph-based RAG 的實體抽取與社群聚類參數；
- File-System Agent 的模型選擇、最大迭代次數與檔案瀏覽策略。

##### 評判與成本計量的可重現性
本研究採用官方評判協定（official judging protocol）並輔以獨立評判者與二元協定進行穩健性檢查，這是提升評判可重現性的良好做法。成本計量方面，由於所有管線都使用相同的 token-level 計量機制，只要 API 日誌或內部計數器一致，成本數據便具有可比性。然而，不同 LLM 供應商的計費方式、快取機制與並行延遲（latency under concurrency）可能導致實際部署成本與實驗室測量存在差異，這是未來重現時需要額外控制的變項。

---

#### 未來研究方向

##### 1. 混合式「排序後發現 + 智慧體推理」架構
本研究結論指出，智慧體推理（agentic reasoning）最適合作為**排序後發現（ranked discovery）**的補強，而非取代全局排序。未來可探索「BM25 或稠密檢索先產生候選，再由 File-System Agent 針對少數候選文件進行深度驗證與整合」的混合管線，並在不同預算下尋找最佳切換點。

##### 2. 規模化法則（scaling laws）的理論分析
本研究以實證方式發現 BM25 在約 10M 詞元處反超 File-System Agent，但未提供理論解釋。未來可建立數學模型，描述「循序檢索的錯誤累積」與「全局排序的召回–精確權衡」如何隨語料庫規模演變，從而預測不同典範的交叉點。

##### 3. 成本感知與自適應檢索策略
本研究採用固定預算與固定策略。未來可發展根據問題類型、語料庫規模與即時成本估計動態選擇檢索典範的路由器（router），例如對簡單查詢使用 BM25，對需要多步推理的查詢啟動智慧體，並在成本超過門檻時提前終止。

##### 4. 輕量且可擴展的圖式索引
Graph-based RAG 的建構瓶頸主要來自 LLM-based construction。未來可研究更輕量的圖建構方法，例如結合稀疏詞彙特徵、對比學習或增量圖更新，以降低離線成本，同時提升大規模下的準確率。

##### 5. 多語言、多模態與動態語料
本研究僅使用英文企業文件。未來應在中文、多語言及多模態（如圖表、音訊會議記錄）語料上重複類似規模化研究，並探討語料庫持續更新（dynamic corpora）時各典範的維護成本與效能漂移。

##### 6. 多閱讀模型與多評判協定的穩健性驗證
未來研究可系統性地更換 reader model（例如從強大但昂貴的模型換成較小模型），觀察各典範的相對排序是否改變；同時引入更多評判協定與人類評估，進一步降低 judging protocol 對結論的影響。

##### 7. 真實企業部署下的延遲與並行性研究
本研究測量的延遲（latency）主要來自單一查詢的端到端時間。未來可在真實企業環境中評估高並發查詢下的吞吐量、快取命中率與總擁有成本（Total Cost of Ownership, TCO），以補足實驗室規模化研究的不足。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**  
A：這篇論文聚焦於檢索增強生成（RAG）在不同語料庫規模下的「準確率–成本擴展性」問題。現有的 RAG 典範——包括詞彙檢索、稠密檢索、基於圖的索引與智慧體搜尋——通常只在各自選定的基準上、以單一語料庫規模進行評估，因此無法回答「當語料庫持續成長時，哪種方法在準確率與成本上最具優勢」這個核心問題。本研究透過控制變因的對照實驗，系統性地比較這些典範在 28 個嚴格巢狀層級上的表現，填補了規模化評估的缺口。

**Q2：為什麼現有的 RAG 比較方法難以揭示真正的規模化行為？**  
A：現有研究往往固定語料庫規模，卻同時更換閱讀模型、評判協定、問題集或語料庫難度，這些混淆因子會讓準確率差異難以歸因於檢索典範本身。此外，不同典範的成本發生在不同的階段——例如基於圖的 RAG 在離線建構時消耗大量生成詞元，而檔案系統智慧體則在線上查詢時進行循序檔案系統工具呼叫——若未統一計算離線與線上成本，就無法公平比較。由於缺乏固定工作負載與統一度量，過去文獻無法觀察到規模相關的交叉與反超現象。

**Q3：為什麼在改變語料庫規模時，必須固定問題、相關文件與對抗干擾文件？**  
A：只有將問題集、相關文件與對抗干擾文件從最小層級起就保持不變，才能確保觀察到的性能變化真正來自語料庫規模擴大，而非題目難度或證據分布的改變。這種設計讓研究者能夠隔離「規模」這個單一變因，從而判斷每種檢索典範在搜尋空間變大時的穩健性。若同時更動這些因素，就無法區分是方法本身更強，還是只是遇到了較簡單或較相關的語料。

**Q4：本研究提出的「28 層巢狀語料庫階梯」是什麼，有何特色？**  
A：研究團隊以 Enterprise RAG-Bench 為基礎，建立了一個從 1,144 份文件到 511,959 份文件、語料庫詞元從約 170 萬到 6.01 億的 28 層嚴格巢狀層級，每層之間以約 1.25 倍遞增。這些層級嚴格巢狀，意味著較小層級的所有文件都包含在較大層級中，並且新增的額外文件遵循固定的來源與雜訊分層順序。如此設計讓所有 RAG 管線在完全相同、逐步放大的語料上回答同一組問題，實現了規模化行為的精確對照。

**Q5：研究評估了哪四種 RAG 典範與哪些具體管線？**  
A：研究統一評估了四種 RAG 典範，共七條管線：詞彙檢索以 BM25 為代表；稠密檢索使用輕量區塊嵌入；基於圖的 RAG 包括 MS-GraphRAG、LightRAG、HippoRAG 2 與 LinearRAG；智慧體搜尋則以檔案系統智慧體為代表。所有管線共用同一個閱讀模型與同一套評分協定，只有檢索與索引方式不同。這種設計讓比較能夠聚焦於檢索介面與索引策略本身，而非背後語言模型的差異。

**Q6：為了確保公平比較，研究在實驗設計上做了哪些關鍵選擇？**  
A：研究固定了閱讀模型、評判協定與問題集，並對所有管線進行詞元層級的成本計量，包括離線建構詞元與線上查詢詞元。此外，研究還使用官方評分協定，並以獨立評判與二元協定進行穩健性檢查，以降低評判者依賴帶來的偏差。這些控制措施讓準確率、延遲與各類詞元成本能夠在同一基準上直接比較。

**Q7：實驗最核心的發現是什麼？所謂的「規模相關反超現象」如何呈現？**  
A：核心發現是沒有任何一種典範在所有規模下都獲勝，而是出現規模相關的交叉與反超。在最小共享層級，檔案系統智慧體的官方準確率點估計最高；但當語料庫規模達到約 1,000 萬詞元時，BM25 開始反超，並在之後的每一個較大共享層級都保持領先。到了 6.01 億詞元的完整規模，BM25 的領先幅度接近 20 個百分點，顯示語料庫越大，全局候選排序的優勢越明顯。

**Q8：各典範的成本結構有何差異？BM25 與檔案系統智慧體的對比為何重要？**  
A：BM25 幾乎不需要 LLM 參與建構，離線成本極低，且查詢詞元消耗幾乎不隨語料庫規模增加而上升，因此穩坐帕雷托前沿的低成本端。相對地，檔案系統智慧體在基礎層的查詢詞元消耗是 BM25 的 39 倍，因為它必須透過循序檔案系統工具呼叫逐步探索語料；當搜尋空間擴大時，這種循序檢索策略的效率與效益都會下降。這說明在大型企業知識庫中，單純依賴智慧體推理進行探索會帶來高昂的線上成本，卻不一定換來更高的準確率。

**Q9：稠密檢索與基於圖的 RAG 在規模化實驗中表現如何？**  
A：稠密檢索在效率上表現不錯，但準確率始終低於 BM25 與檔案系統智慧體，未能成為最強的預設方法。基於圖的 RAG 則面臨嚴重的建構瓶頸：MS-GraphRAG、LightRAG 與 HippoRAG 2 等需要在索引階段對每個區塊呼叫 LLM 抽取實體與關係，導致在達到部署規模前就遇到離線成本或完成度限制。即使是使用輕量命名實體識別器與嵌入向量的 LinearRAG 等可擴展變體，在共享層級上的表現仍低於 BM25。

**Q10：對於實際的企業知識庫應用，這篇論文給出了什麼建議？**  
A：研究建議將詞彙檢索——特別是 BM25——視為大規模企業知識庫最強的可擴展預設方法，因為它在語料庫成長時仍能保持低離線成本、低查詢成本與高準確率。智慧體推理最適合在「排序後發現」的階段發揮作用，也就是在 BM25 等全局排序方法先縮小候選範圍後，再由智慧體進行深入分析，而不是直接取代排序檢索。這種分層設計能在控制成本的同時，保留智慧體處理複雜證據的能力。

**Q11：從產品與成本效益的角度，這些發現有什麼啟示？**  
A：BM25 錨定了帕雷托前沿的低成本端，對於需要快速上線、預算有限或語料持續增長的產品來說，是極具吸引力的選擇。基於圖的 RAG 雖然可能提供結構化知識的優勢，但其高昂的 LLM 建構成本與建構瓶頸，使其在大型部署中必須審慎評估投資報酬率。檔案系統智慧體在小規模或高度複雜、需要多步推理的場景可能有價值，但在大規模通用檢索中，其線上查詢成本會迅速膨脹。

**Q12：這項研究對 RAG 領域可能帶來什麼影響？**  
A：這項研究挑戰了「最新、最複雜的方法總是更好」的直覺，強調語料庫規模是選擇檢索典範時不可忽略的關鍵變因。它也提醒學界與業界，單一規模的基準評測可能誤導方法選擇，因為在小語料上領先的智慧體或圖方法，未必能擴展到真實企業知識庫。整體而言，研究推動了以規模化、成本意識為核心的 RAG 評估典範，並重新確立了全局候選排序在大規模場景中的價值。

**Q13：這項研究有哪些主要限制？**  
A：研究只使用了一個閱讀模型與一套主要評判協定，雖然有獨立評判進行穩健性檢查，但不同閱讀模型或評分標準可能改變各典範的相對排名。此外，實驗僅基於 Enterprise RAG-Bench 這個英文企業語料庫，結果是否能推廣到其他語言、領域或文件類型仍需驗證。最後，檔案系統智慧體的政策模型、提示、工具迴圈與預算都被固定，因此無法排除更先進的智慧體設計可能改變規模化曲線。

**Q14：在哪些情境下，檔案系統智慧體或基於圖的 RAG 仍可能是較佳選擇？**  
A：在語料庫規模較小、問題需要大量多步推理或檔案間隱含關係難以透過關鍵字匹配捕捉時，檔案系統智慧體可能仍有優勢。基於圖的 RAG 則適合實體與關係結構明確、且離線建構成本可被攤提的場景，例如需要頻繁回答「某實體與哪些實體有何關係」的應用。然而，本研究顯示在持續成長的企業知識庫中，這些方法若未與全局排序結合，容易在規模擴大時失去競爭力。

**Q15：未來研究可以朝哪些方向延伸？**  
A：未來可以探索將 BM25 等全局排序與智慧體推理或圖結構結合的混合架構，讓智慧體在已排序的候選文件上進行深入分析，以兼顧準確率與成本。另一個方向是建立更廣泛的規模化法則，涵蓋多語言、多領域與動態更新的語料庫，並納入更豐富的智慧體政策與讀者模型。最後，發展標準化的成本意識評估框架，讓離線建構詞元、線上查詢詞元與延遲都能被統一報告，將有助於 RAG 方法在真實部署中的公平比較與選型。

## 實務應用指南

### 適用場景

1. **企業內部知識庫問答（>10M 語料庫詞元）**  
   當文件量達到數萬至數十萬份、總詞元超過約 1,000 萬時，論文顯示 BM25 在準確率與查詢成本上均佔優。適合 wiki、工單、郵件、會議紀錄、CRM 紀錄等異質來源的統一檢索問答。

2. **法規 / 合約 / 技術文件漸進擴充的 RAG 系統**  
   語料庫會持續成長、但問題集與核心證據文件相對穩定的場景，例如法規追蹤、產品手冊、程式碼審查紀錄。BM25 的索引成本低廉、查詢延遲幾乎不隨規模增長，能隨語料擴充維持穩定效能。

3. **小規模、高複雜度的探索性查詢（<10M 語料庫詞元）**  
   在語料較小、問題需要多步推理或跨文件拼湊答案時，檔案系統智慧體（File-System Agent）可透過循序檔案系統工具呼叫進行深度探索。適合早期原型、小型專案知識庫或需要靈活導航的調查型任務。

4. **成本敏感且需快速上線的 RAG 服務**  
   若團隊無法負擔大型語言模型（LLM）逐區塊抽取實體關係的高額建構詞元，BM25 與輕量稠密檢索是更務實的起點，可避免基於圖的檢索增強生成（Graph-based RAG）在部署規模前遭遇的建構瓶頸。

5. **混合檢索與智慧體後處理的進階問答**  
   對於需要高準確率又需處理模糊或衝突資訊的場景，可先以 BM25 做全局候選排序，再將排序後發現（ranked discovery）的結果交給智慧體推理，結合兩者的規模化優勢與靈活性。

### 實作前置條件

**資料條件**
- 已清理、可切分為區塊（chunk）的純文字或半結構化文件。
- 文件來源與格式相對穩定，能建立「每來源檔案樹」或至少統一的文字欄位。
- 若要做對照研究，需固定問題集、相關文件與對抗干擾文件（adversarial distractors），避免規模變化時引入混淆因子。

**運算條件**
- **BM25**：幾乎可在單機 CPU 完成索引與查詢，適合低成本部署。
- **稠密檢索（Dense Retrieval）**：需要嵌入模型與向量資料庫，建構階段需一次嵌入遍歷（embedding pass），查詢階段需向量相似度搜尋。
- **Graph-based RAG**：需準備大量 LLM 呼叫以抽取實體與關係，建構詞元隨語料線性甚至超線性成長，建議先評估完整語料庫的建構預算。
- **檔案系統智慧體**：查詢階段需反覆呼叫 LLM 進行工具迴圈，延遲與查詢詞元較高，需準備足夠的線上推理配額。

**技能條件**
- 熟悉 Python、RAG 管線與至少一種檢索引擎（如 Pyserini、Elasticsearch、Lucene）。
- 具備評估基準操作經驗，能執行官方評判協定（judging protocol）與成本計量。
- 若導入智慧體，需具備提示工程（prompt engineering）與工具呼叫迴圈設計能力。

---

### 實作步驟建議

1. **建立可重複的規模化階梯（scaling ladder）**  
   從最小語料子集開始，以嚴格巢狀（strictly nested）方式逐層放大，例如每層增加 1.25 倍文件數。固定問題集、相關文件與對抗干擾文件，確保規模是唯一的變因。

2. **優先部署 BM25 作為基線**  
   使用現成詞彙檢索引擎建立索引，無需 LLM 建構。先取得官方準確率、查詢詞元與延遲基線，作為後續所有方法的比較錨點。

3. **加入輕量稠密檢索作為對照**  
   選用小型嵌入模型對區塊做一次嵌入遍歷，觀察其在準確率–成本帕雷托前沿（Pareto frontier）上的位置。通常效率較高但準確率低於 BM25。

4. **評估 Graph-based RAG 的建構可行性**  
   在小語料子集上試跑 MS-GraphRAG、LightRAG 或 LinearRAG，測量建構詞元與時間。若完整語料會觸及建構瓶頸，應考慮 LinearRAG 等輕量變體，或暫緩導入。

5. **在小型共享層級試驗檔案系統智慧體**  
   將檔案與命令介面套用到原始企業語料，觀察其在 <10M 語料庫詞元的表現。記錄查詢詞元與延遲，作為規模放大時的成本預測依據。

6. **尋找規模反超點並決策架構**  
   比較各方法在共享層級（shared tiers）的表現。若語料預計超過約 1,000 萬詞元，將主力切換為 BM25；若需智慧體的推理彈性，則讓智慧體在 BM25 排序後發現的候選上運作，而非直接探索原始檔案樹。

7. **持續監控與成本計量**  
   在生產環境中埋設詞元計量（construction / query tokens）與延遲追蹤，定期以官方協定重新評估，確保語料成長不會讓成本或準確率失控。

---

### 潛在風險與注意事項

- **規模反超點被忽略**  
  許多團隊在小型語料上驗證智慧體或 Graph-based RAG 後直接上線，未發現語料成長後準確率下降。建議在設計階段就規劃 28 層級式的對照實驗，觀察規模化行為。

- **Graph-based RAG 的建構瓶頸**  
  隨語料擴大，LLM 抽取實體與關係的建構詞元會快速累積，可能在達到部署規模前就無法負擔。應先估算完整語料的建構成本，並準備輕量替代方案（如 LinearRAG 或 BM25）。

- **智慧體的查詢成本與延遲膨脹**  
  檔案系統智慧體的循序檢索策略會隨搜尋空間變大而增加查詢詞元，論文顯示在基礎層（bedrock）可達 39 倍之多。高頻查詢場景需設定嚴格預算與最大步數限制。

- **評估指標與評判協定不一致**  
  不同閱讀模型、評判協定或問題集會造成混淆。產品上線前應使用官方協定，並以獨立評判與二元協定進行穩健性檢查，避免單一評分標準誤導決策。

- **過度依賴單一檢索方式**  
  BM25 雖在規模化後領先，但對於需要跨文件推理或高階摘要的問題，單純詞彙檢索可能不足。建議保留與智慧體或稠密檢索的混合整合空間。

---

### 與其他技術的整合建議

- **與向量資料庫整合**  
  將 BM25 與稠密檢索並行部署，利用混合分數（hybrid scoring）取長補短。BM25 負責大規模全局候選排序，稠密檢索強化語意相似但詞彙不同的查詢。

- **與 LLM 推理層整合**  
  讓檔案系統智慧體或通用智慧體在 BM25 回傳的候選區塊上進行重排序、衝突偵測與多步推理，而非從零開始探索原始檔案樹。這樣可兼顧規模化準確率與智慧體靈活性。

- **與企業現有搜尋基礎設施整合**  
  若組織已使用 Elasticsearch、OpenSearch 或 Solr，可直接在其上實作 BM25，降低導入門檻；Graph-based RAG 則可作為特定小語料子圖的加值模組。

- **與 MLOps / 成本監控整合**  
  將建構詞元、查詢詞元與延遲納入現有監控儀表板，設定預算告警。對於 Graph-based RAG 與智慧體，特別需要追蹤 LLM API 呼叫次數與費用。

- **與資料管線整合**  
  語料新增時，BM25 與稠密檢索只需增量索引；Graph-based RAG 則可能需要局部或全量重抽實體關係。設計資料流時應預留不同索引的更新策略。

---

### 給不同背景讀者的閱讀建議

**給初學者**  
這篇論文比較了四種 RAG 方法在不同語料庫大小下的表現。核心結論是：當文件量變大時，最簡單的 BM25 反而最強；聽起來很聰明的智慧體或圖索引，在小語料可能有用，但隨規模成長會變貴或變弱。建議先理解「規模化」與「成本」這兩個概念，再回頭看各方法的實驗曲線。

**給 AI 工程師**  
論文提供了可複製的 28 層級對照框架與成本計量方式，適合直接借鑑到內部評測。重點在於：BM25 在約 10M 語料庫詞元後反超，且查詢成本幾乎不隨規模增加；Graph-based RAG 與檔案系統智慧體則分別在建構階段與查詢階段面臨規模瓶頸。建議將此結果作為架構選型與容量規劃的依據，並優先實作「BM25 + 智慧體後處理」的混合管線。

**給研究人員**  
本文的貢獻在於控制語料規模、問題集、相關與對抗文件不變，從而分離出「規模」本身對不同 RAG 典範的影響。未來研究可延伸至多個閱讀模型、多語言、動態語料更新，或探討智慧體在排序後發現上的最佳策略。此外，Graph-based RAG 的建構瓶頸與可擴展變體設計仍是值得深入的最佳化方向。

**給產品經理**  
這是一篇直接影響產品路線的論文：若你的企業知識庫預計超過數萬份文件，BM25 是最穩健的預設方法，能以最低成本提供最高準確率；智慧體與 Graph-based RAG 適合做為加值功能，而非核心檢索引擎。決策時應同時看準確率、建構成本、查詢延遲與維護成本，避免被單一示範案例誤導。
