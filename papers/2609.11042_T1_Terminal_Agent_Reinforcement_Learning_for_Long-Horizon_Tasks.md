## 摘要翻譯

智慧體（Agent）的使用正轉向長期任務（Long-Horizon Tasks），例如程式編寫與科學發現，其中終端任務尤為重要。我們提出 T1，一個總參數達 122B 的混合專家模型（Mixture-of-Experts, MoE），以強化學習（Reinforcement Learning, RL）訓練，在雲端沙盒（Cloud Sandbox）中操作真實 Shell（命令列殼層），每項任務可進行超過 300 次工具呼叫回合（Tool-call Turns），並以執行各任務專屬驗證器（Verifier）的結果作為獎勵。我們提出一套完整方法：首先，以積極熱啟動（Aggressively Warm-Started）的模型穩定行動者-評論者訓練（Actor-Critic Training），並以密集過程獎勵（Dense Process Reward）依通過驗證器（Verifier）的絕對數量為軌跡（Trajectory）評分。第二，藉由 TITO（Token-In, Token-Out，逐詞元進出）機制實現穩定最佳化：訓練時使用與推論時完全相同的取樣詞元識別碼（Sampled Token Identifiers），並在回合邊界（Turn Boundaries）進行漂移修復（Drift Repair）；以及 R3（Rollout Routing Replay，推出路由重播），記錄取樣器（Sampler）在每個混合專家層（MoE Layer）中對各詞元的專家選擇（Per-Token Expert Choices），並於訓練時重播。第三，完全分布外（Out-of-Distribution, OOD）的訓練語料庫（Training Corpus）：與 Terminal-Bench 2.1 不相交的隔離種子（Isolated Seeds）與合成任務（Synthesized Tasks），確保效能提升反映真實的能力遷移（Capability Transfer），而非基準測試過擬合（Benchmark Overfitting）。TITO 與 R3 共同將訓練與推論之間的對數機率差異（Log-Probability Difference）從 0.021 降至 0.013，並在損失區域（Loss Region）中達到完全對齊的零詞元漂移（Zero Token Drift）。在 Terminal-Bench 2.1 上，我們的後訓練流程（Post-Train Pipeline）使初始基礎模型（Base Model）從 43.8% 提升至 T1 的 64.0% 解決率（Resolved Rate）。在長期終端基準測試（Long-Horizon Terminal Bench）上，T1 達到 27.9%，並超越 GPT-5.4 與 GLM-5.1。

### 核心貢獻（3～5點）
- 提出 T1，一個總參數達 122B 的混合專家模型，透過強化學習在真實 Shell 環境中執行長期終端任務，每項任務可進行超過 300 次工具呼叫回合。
- 採用積極熱啟動與密集過程獎勵穩定行動者-評論者訓練，以通過驗證器的絕對數量評分軌跡。
- 提出 TITO 與 R3 技術解決訓練-推論不匹配問題：TITO 確保訓練時使用與推論完全相同的取樣詞元識別碼並在回合邊界進行漂移修復；R3 重播取樣器在每層 MoE 的逐詞元專家選擇。
- 建構完全分布外的訓練語料庫，透過隔離種子與合成任務避免基準測試過擬合，確保效能提升來自真實能力遷移。
- 在 Terminal-Bench 2.1 與長期終端基準測試上取得顯著進展，T1 分別達到 64.0% 與 27.9% 的解決率，並超越 GPT-5.4 與 GLM-5.1。

### 適合對象
適合對強化學習、大型語言模型智慧體、終端機/命令列環境中的長期任務規劃，以及混合專家模型訓練穩定性有興趣的研究人員與工程師。特別是關注訓練-推論一致性、分布外泛化，以及後訓練流程設計的讀者。

## 深度分析

#### 方法論解析

T1 的核心定位是將一個 122B 規模的 Mixture-of-Experts（MoE，混合專家模型）——以 Qwen3.5-122B-A10B 為 base model（基礎模型）——透過純粹的 reinforcement learning（RL，強化學習）後訓練，轉化為能在真實 shell（命令列殼層）環境中執行長期任務的 terminal agent（終端智慧體）。整個 post-train pipeline（後訓練流程）面對兩大難題：一是 MoE 在 RL 下的 training-inference mismatch（訓練-推論不匹配），二是長期任務中 sparse outcomes（稀疏結果）獎勵訊號過於微弱。

**整體 RL 框架與資料來源**  
T1 在 cloud sandbox（雲端沙盒）中與真實終端互動，每個任務可長達 300+ 個 tool-call turns（工具呼叫回合）。獎勵並非來自人工偏好，而是直接執行每個任務自帶的 verifier（驗證器）。訓練資料採用 fully out-of-distribution（OOD，分布外）的設計：透過 recursive synthesis（遞迴合成）產生與 Terminal-Bench 2.1 完全不相交的 isolated seeds（隔離種子）與 synthesized tasks（合成任務），再經品質篩選得到 T1-15k 訓練集。這種設計確保後續在 benchmark（基準測試）上的提升反映的是 genuine capability transfer（真實能力遷移），而非 benchmark overfitting（基準測試過擬合）。

**TITO：逐詞元進出的一致性建構**  
TITO（Token-In, Token-Out，逐詞元進出）是針對自迴歸 RL 中訓練樣本與推論軌跡不一致的問題。傳統做法在訓練時可能使用模型自身生成的分布或教師強制輸入，導致訓練時看到的 token identifiers（詞元識別碼）與 rollout（推出）時取樣的 token 不完全相同；再加上 multi-turn harness 會在 turn boundaries（回合邊界）插入工具回傳結果，微小的 tokenization 差異會隨長期軌跡放大。TITO 的做法是：訓練時直接使用 rollout 階段 sampler（取樣器）產生的 exact sampled token identifiers，並在回合邊界進行 drift repair（漂移修復）。結果顯示，TITO 能將 training-to-inference 的 log-probability difference（對數機率差異）降低，並在 loss region（損失區域）達到 zero token drift（零詞元漂移）。

**R3：MoE 路由決策的重播**  
R3（Rollout Routing Replay，推出路由重播）處理 MoE 層級的不一致。T1 的 121.4B 參數中有 116.0B 是 expert weights（專家權重），每個 token 在每層 MoE layer（混合專家層）中只啟動 8 of 256 experts。router（路由器）的 top-k 選擇對數值精度極度敏感：推論與訓練若使用不同 kernel、批次大小或平行策略，per-token expert choices（逐詞元專家選擇）可能翻轉，導致 gradient（梯度）更新到「沒有產生該行為」的專家上。R3 在 rollout 時記錄取樣器在每一層的專家選擇，訓練時直接重播這些 routing（路由）決策。結合 TITO 與 R3 後，log-probability difference 從 0.021 降至 0.013，顯著提升 MoE RL 的穩定性。

**Dense Verification Reward（密集驗證獎勵）**  
作者早期使用 binary outcome reward（二元結果獎勵）的實驗發現，即使 rollout batch 耗費數百沙盒小時，每條 trajectory（軌跡）只得到一個 bit 訊號，結果無法超越 supervised baseline（監督式基線）。因此他們改用 dense process reward（密集過程獎勵）：以 fixed global scale 上「通過的 assertion（斷言）絕對數量」作為 test-count reward（測試數量獎勵）。這讓模型在長期軌跡中獲得部分進展訊號，改善 credit assignment（信用分配）。為防止 reward hacking（獎勵駭取），設計上採用 held-out verifier、固定計分尺度，並避免讓模型直接操縱驗證程式碼。

**Critic 的積極熱啟動**  
T1 採用 actor-critic training（行動者-評論者訓練），其中 critic（評論者）被 aggressively warm-started（積極熱啟動），並以 actor 30 倍的學習率訓練。這是因為長期軌跡的 value estimation（價值估計）誤差會被放大，穩定的 critic 對 PPO 的 advantage estimation 至關重要。不過作者也在 lessons learned 中指出，critic calibration（評論者校準）本身並不保證 policy improvement（策略改進），還需配合資料與獎勵設計。

**基礎設施設計**  
為了支撐 122B actor-critic pair 的長期訓練，論文設計了 co-resident actor-critic pairs（共置的行動者-評論者對）、context parallelism（上下文平行）處理 recurrent operator（遞迴運算子）、liveness（活性）機制應對 hour-scale steps、處理 environment concurrency（環境並行）中的 straggler tail（落後者尾部），以及 publication barrier（發布屏障）來平衡 rollout/training（推出/訓練）的吞吐量。

#### 實驗數據解讀

**Terminal-Bench 2.1 主結果**  
在 89 個 held-out tasks 上，base model 的 resolved rate（解決率）為 43.8%，經過 supervised fine-tuning（SFT）後的 checkpoint 達到 49.4%，再經過三個 epoch 的 PPO（Proximal Policy Optimization，近端策略最佳化）訓練後，T1 達到 64.0%。從 SFT checkpoint 到 T1 的絕對提升為 14.6 個百分點，相對提升達 28.5%，顯示 RL 階段本身帶來了顯著的 terminal agency 能力。在相同 harness（測試框架）下，T1 超過 GPT-5.4（54.8%）、DeepSeek-V4-Flash（56.9%）與 GLM-5.1，並接近 Claude Opus 4.7（66.1%）。這代表一個經過專門 RL 後訓練的 122B MoE 模型，在終端任務上能與更強大的通用 frontier model 競爭。

**類別表現與能力遷移**  
T1 的進步集中在真正考驗終端操作能力的類別：debugging（除錯）達到 100.0，system administration（系統管理）達到 88.9，且兩者都超過了更強大的通用模型。這與「訓練語料與測試集完全 OOD」的設計相互呼應，說明提升並非來自於記憶特定 benchmark 題目，而是來自於對 terminal environment、工具使用與錯誤修復策略的 general capability transfer。

**Long-Horizon Terminal Bench**  
在長期終端基準測試上，T1 達到 27.9%，雖然超過 GPT-5.4 與 GLM-5.1，但絕對數值仍然偏低。這反映出即使具備 300+ turns 的執行能力，長期規劃、錯誤恢復與持續狀態追蹤仍是未解決的難題。

**訓練穩定性指標**  
TITO 與 R3 將 training-to-inference 的 log-probability difference 從 0.021 降至 0.013，並在 loss region 達到 zero token drift。這些數字雖小，但對於 122B MoE 的 RL 訓練具有關鍵意義：它們量化了 off-policy 誤差與 routing 不一致的程度，直接關係到 gradient 是否更新到正確的參數。

**訓練動態與獎勵設計的影響**  
Binary reward 的實驗從未超越 SFT baseline，這是論文強調 dense verification reward 必要性的重要證據。僅需三個 epoch 的 PPO 就能從 49.4% 提升到 64.0%，也暗示 T1-15k 資料品質與 TITO/R3 穩定性讓訓練效率相當高。

#### 與現有研究的比較

**相對於通用 frontier model**  
GPT-5.4、GLM-5.1、DeepSeek-V4-Flash 與 Claude Opus 4.7 都是大規模通用語言模型，主要依賴大規模預訓練與一般 RLHF，而非針對 terminal 環境的執行結果進行 RL。T1 的優勢在於：它直接將 verifier 的執行結果作為 reward signal，並針對 shell 環境的長期互動進行後訓練。這使得 T1 在 terminal-specific 類別（debugging、system administration）上能超越更強大的通用對手。

**相對於現有 terminal agent 研究**  
多數現有 terminal agent 仍依賴 SFT、prompt engineering 或少量示範軌跡。T1 的貢獻在於規模化：將 RL 應用到 122B MoE，並處理了 MoE 在 RL 下的 training-inference mismatch。TITO 與 R3 是針對 MoE RL 的專門穩定化技術，這在過去較少被系統性討論。此外，dense verification reward 與完全 OOD 的 recursive synthesis 資料建構方式，也為長期 agent RL 提供了可複製的配方。

**技術優勢總結**  
1. **MoE RL 穩定性**：TITO + R3 同時解決 token-level 與 expert-level 的不一致，顯著降低 log-probability gap。  
2. **密集執行獎勵**：以 assertion 通過數量取代二元結果，提供長期軌跡中的中間訊號。  
3. **OOD 訓練語料**：確保 benchmark 上的提升反映真實能力遷移。  
4. **基礎設施**：支撐 122B actor-critic 共置訓練與長期沙盒互動的工程設計。

**限制**  
1. **任務範圍**：目前僅針對 shell/terminal 環境，未涵蓋 GUI、網頁或真實生產系統。  
2. **需要 verifier**：獎勵設計依賴可執行的驗證器，對於開放式或無明確驗證標準的任務難以直接套用。  
3. **長期任務仍困難**：Long-Horizon Terminal Bench 的 27.9% 顯示長期規劃與錯誤恢復仍有很大進步空間。  
4. **與最強通用模型仍有差距**：Claude Opus 4.7 的 66.1% 仍高於 T1，顯示通用能力與專門 RL 之間存在權衡。  
5. **計算成本**：每個 rollout batch 耗費數百沙盒小時，基礎設施門檻極高。

#### 可重現性評估

根據目前提供的論文內容，**並未明確提及開放原始碼、訓練資料集或模型權重**。雖然 Terminal-Bench 2.1 與 Long-Horizon Terminal Bench 可能是公開 benchmark，但 T1-15k 訓練語料、recursive synthesis 流程、cloud sandbox harness、TITO/R3 的實作細節，以及 122B actor-critic 共置訓練的基礎設施程式碼，都未在摘要與目錄中標示已釋出。

**再現門檻**  
即使論文釋出部分資源，重現 T1 仍需：  
- 122B MoE 的 actor 與 critic 模型，並能共置於相同運算節點；  
- 大規模 cloud sandbox 環境，支援數百個並行 shell session 與 verifier 執行；  
- TITO 與 R3 的底層實作，需深入 MoE router 與 tokenizer 的訓練-推論對齊；  
- 品質篩選後的 T1-15k 等價訓練資料，或至少 recursive synthesis 的完整流程；  
- 長期訓練的 liveness 與容錯機制。

因此，在缺乏開放資源的情況下，本研究的直接可重現性偏低。建議作者未來釋出模型權重、訓練資料子集、harness 與關鍵穩定化模組，以降低社群復現門檻。

#### 未來研究方向

1. **擴展至其他 agent 環境**  
   將 TITO/R3 與 dense verification reward 的框架遷移到 GUI agent、網頁瀏覽、API 工具使用或多模態環境，驗證其是否為通用的 MoE RL 穩定化方案。

2. **更精細的 credit assignment**  
   長期軌跡中單一 assertion 的通過難以歸因到特定 turn。未來可結合 hierarchical RL（階層式強化學習）、intermediate verifier（中間驗證器）或 trajectory decomposition（軌跡分解）來改善信用分配。

3. **自動 verifier 與獎勵模型合成**  
   當人工設計的 verifier 不足時，可研究如何自動生成或學習 dense reward model（密集獎勵模型），同時避免 reward hacking。

4. **更長的 horizon 與成本降低**  
   將任務長度從 300+ turns 擴展到 1000+ turns，並透過環境模擬、軌跡蒸餾或推論時搜尋來降低 sandbox 成本。

5. **結合推理與規劃**  
   將 T1 與 tree search（樹狀搜尋）、MCTS（蒙地卡羅樹搜尋）或 reasoning model（推理模型）結合，提升長期規劃與錯誤恢復能力。

6. **安全性與穩健性**  
   研究如何防止 terminal agent 在真實或生產環境中造成不可逆 side effects（副作用）、sandbox escape（沙盒逃逸）或利用 verifier 漏洞。

7. **開源與標準化**  
   釋出 T1 模型權重、T1-15k 資料、harness 與基礎設施設計，建立 terminal RL 的開放研究平台。

8. **多 agent 協作**  
   將單一 terminal agent 擴展為多 agent 系統，讓不同專家模型分別負責規劃、執行、驗證與除錯，以處理更複雜的軟體工程任務。

## 論文問答

**Q1：T1 要解決什麼問題？為何長期終端任務特別困難？**  
A：T1 針對的是自主智慧體在真實 Linux 終端機上執行長期任務的挑戰，例如除錯、系統管理與科學發現等需要數百個工具呼叫回合的任務。這類任務不僅要求模型理解命令語法，還必須具備環境感知、任務分解、從部分失敗中恢復，以及維持數百回合狀態一致性的能力。與傳統的單輪程式碼補全或偏好式評分不同，終端任務的後果會持續存在於狀態環境中，並由任務自有的執行驗證器來裁決，因此對錯誤極為嚴苛。

**Q2：現有的強化學習方法為何在終端任務上效果不佳？**  
A：傳統的稀疏結果獎勵只在軌跡結束時給予二元回饋，但一個 rollout 可能耗費數百個沙盒小時，卻只提供一個位元的訊號，導致信用分配困難且訓練訊號極弱；作者指出他們第一次使用二元獎勵的訓練從未超越監督式基線。此外，終端環境中的動作會產生不可逆的副作用，模型很容易利用獎勵函式的漏洞或陷入局部最優。因此，僅依賴最終成敗無法穩定地學習到多步規劃與環境操作所需的細粒度策略。

**Q3：為何訓練-推論一致性對 MoE 終端智慧體至關重要？**  
A：T1 基於 Qwen3.5-122B-A10B，其中 1160 億參數屬於專家權重，每個詞元在每層會從 256 個專家中離散選出 8 個；推論與訓練之間的微小數值差異就可能翻轉專家選擇，使梯度更新落到未實際生成行為的參數上。再加上多回合終端測試框架會在每個回合邊界擾動詞元序列，進一步放大了訓練-推論不匹配。這種不一致會造成詞元漂移與路由漂移，嚴重削弱大規模稀疏模型在強化學習中的穩定性。

**Q4：TITO 的設計原理與作用是什麼？**  
A：TITO（Token-In, Token-Out）要求訓練時使用的輸入與目標詞元，必須與推論階段取樣器實際產生的詞元識別碼完全一致，而不是使用教師強制或重新取樣的序列。同時，TITO 在工具呼叫回合邊界進行漂移修復，以處理多回合 harness 在邊界處對序列的擾動。透過這種方式，損失函數計算所依賴的條件分布與實際 rollout 的分布對齊，從而降低訓練-推論之間的對數機率差距。

**Q5：R3 如何解決 MoE 的路由對齊問題？**  
A：R3（Rollout Routing Replay）會在 rollout 過程中記錄取樣器在每一層 MoE 對每個詞元所做的專家選擇，並在訓練時重播這些逐詞元的路由決策。由於 MoE 的路由是離散的，推論與訓練若使用不同的浮點環境或批次配置，專家指派就可能改變，導致梯度流向錯誤的專家；R3 確保訓練階段使用與生成行為完全一致的路由。結合 TITO 後，整體的訓練-推論對數機率差異從 0.021 降至 0.013，並在損失區域達到零詞元漂移。

**Q6：密集驗證獎勵如何設計，為何比二元獎勵更有效？**  
A：作者將獎勵從最終成敗改為「在固定全局尺度上通過的斷言數量」，也就是以絕對通過驗證器數量來評分整條軌跡，使模型在每次更新都能獲得細粒度的執行訊號。為了穩定訓練，評論者採用積極熱啟動，並以行動者 30 倍的學習率進行訓練，以快速適應密集的過程獎勵。這種設計顯著改善了信用分配，讓 PPO 能夠在長期軌跡中學習到逐步接近正確解決方案的行為，而非僅在軌跡結束時獲得單一訊號。

**Q7：T1 在哪些基準測試上進行評估，測試框架有何特色？**  
A：T1 主要在 Terminal-Bench 2.1 的 89 個保留任務上進行評估，這些任務完全由任務自有的驗證器透過執行來裁決；此外也在 Long-Horizon Terminal Bench 上測試更長期的能力。測試框架讓模型在雲端沙盒中操作真實 shell，每個任務可進行超過 300 次工具呼叫回合，並由執行結果決定分數。這種設計確保評估的是真實的終端操作能力，而非僅是文字生成或靜態程式碼比對。

**Q8：T1 的主要實驗結果為何？**  
A：在 Terminal-Bench 2.1 上，基礎模型從 43.8% 的解決率經過後訓練流程提升到 T1 的 64.0%；若從監督式檢查點 49.4% 出發，三個 epoch 的 PPO 訓練在 T1-15k 資料上達到 64.0%，相對提升 28.5%。在 Long-Horizon Terminal Bench 上，T1 達到 27.9%，超越 GPT-5.4 與 GLM-5.1。特別值得注意的是，T1 在除錯與系統管理類別分別取得 100.0 與 88.9 的高分，顯示強化學習在需要終端代理能力的任務上帶來顯著遷移。

**Q9：有哪些消融或穩定性測量支持 T1 的設計？**  
A：作者測量了訓練與推論之間的對數機率差距，TITO 與 R3 共同將其從 0.021 降至 0.013，並在損失區域實現零詞元漂移，直接驗證了穩定化堆疊的效果。相較之下，僅使用二元結果獎勵的訓練從未超越監督基線，證明密集驗證獎勵的必要性。此外，訓練語料庫與 Terminal-Bench 2.1 完全分布外，使用隔離種子與合成任務，因此性能提升反映的是真實能力遷移而非基準過擬合。

**Q10：T1 可應用於哪些實務場景？**  
A：T1 可應用於自主軟體工程，例如根據問題描述在真實程式碼庫中定位 bug、修復缺陷、重建目標並通過測試驗證；也適用於系統管理，如設定伺服器、安裝相依套件、診斷日誌與恢復服務。更廣泛地，任何需要長期規劃與執行驗證的知識工作，例如科學實驗自動化、資料處理管線建置與基礎設施維運，都可能受益於這種能在真實 shell 中操作的終端智慧體。

**Q11：若將 T1 產品化，需要考量哪些因素？**  
A：產品化時必須確保沙盒環境的安全隔離，避免模型執行破壞性指令或接觸敏感資料；驗證器的設計必須嚴謹，防止獎勵駭取與投機行為。由於每個 rollout 可能長達數小時並涉及數百次工具呼叫，需要處理長時間步驟的活性、落後者尾部與環境並行度，以維持訓練與服務的吞吐量。此外，共置的 122B 行動者-評論者對與 MoE 路由一致性也對基礎設施容量與版本管理提出高要求。

**Q12：T1 對強化學習與智慧體研究領域有何影響？**  
A：T1 證明了在千億級 MoE 模型上，可以透過真實執行結果進行穩定的強化學習，並在長期終端任務上超越多個強大的通用模型。它提出的 TITO 與 R3 為稀疏模型在訓練-推論一致性問題上提供了可操作的解決方案，而密集驗證獎勵則展示了如何從執行中萃取豐富的學習訊號。這些貢獻為自主軟體代理、基礎設施操作代理，以及更廣泛的「行動後果由執行驗證」的代理系統奠定了技術路徑。

**Q13：作者承認哪些主要限制？**  
A：訓練過程中的單一步驟可能長達數小時，對系統活性與容錯構成挑戰；少數特別慢的環境實例會形成落後者尾部，影響整體 rollout 效率與訓練分布。此外，上下文管理決定了模型能夠學習的任務範圍，若上下文無法容納長期軌跡，則策略難以掌握跨回合的依賴關係。作者也指出，評論者校準並不保證策略改進，因此仍需要謹慎設計獎勵與訓練流程。

**Q14：訓練過程中有哪些失敗經驗？**  
A：作者坦承第一次使用二元結果獎勵的強化學習從未超越監督基線，顯示稀疏獎勵在長期終端任務上不足以驅動學習。此外，有兩種獎勵塑形變體也未能成功，說明設計密集獎勵時容易出現獎勵駭取或訓練不穩定的問題。另一個教訓是 rollout 吞吐量會改變訓練分布，而單純校準評論者並不能自動帶來策略改進；作者也因此選擇 PPO 搭配熱啟動評論者，而非無評論者的群組基線。

**Q15：未來可以朝哪些方向改進？**  
A：未來可進一步改善長期軌跡的信用分配機制，讓模型更精確地辨識哪些動作對通過特定斷言有貢獻；也可擴大合成任務的規模與難度，並延長可學習的時間跨度。另一方面，可探索更強大的驗證器與防範獎勵駭取的方法，並將 TITO/R3 的穩定化技術推廣到其他離散動作空間的 MoE 代理。最終，朝向安全部署於生產環境、支援多人協作或多代理互動的終端智慧體，將是這條研究路線的重要下一步。

## 實務應用指南

## 適用場景

1. **雲端維運事件自動修復（SRE Auto-Remediation）**  
   讓 T1 這類終端智慧體在隔離沙盒中讀取監控告警、查詢日誌、重啟服務、調整設定，並以驗證器確認服務恢復。適合重複性高、容錯窗口明確的故障，例如磁碟滿載清理、憑證過期更新、容器重啟鏈。

2. **大型程式碼庫重構與遷移**  
   將跨模組的 API 遷移、相依套件升級、測試框架替換等長期任務拆解為多回合工具呼叫。智慧體可依序修改檔案、執行編譯、跑單元測試，並用「通過斷言數量」作為密集獎勵，逐步收斂到可合併的 PR。

3. **CI/CD 失敗診斷與修補**  
   串接持續整合管線，讓代理在失敗的 build 環境中執行 `git bisect`、檢視 diff、修復語法或設定錯誤，再重新跑驗證。適合需要反覆試誤、跨檔案推理的編譯或測試失敗。

4. **資安稽核與合規檢查自動化**  
   在沙盒中掃描設定檔、檢查權限、比對基準線，並產出修復指令。由於每個檢查項目都可對應一個斷言，能直接轉換為逐斷言驗證的密集獎勵，降低誤報與獎勵駭取風險。

5. **資料科學與研究管線執行**  
   自動下載資料、清理、執行實驗腳本、繪圖、比對指標，並在偏離預期時嘗試調整參數。適合需要長時間執行、步驟可驗證的批次研究流程。

## 實作前置條件

### 資料
- **隔離種子任務**：與正式評估基準不相交的初始任務集合，避免基準測試過擬合。
- **可執行驗證器**：每個任務必須附帶能客觀評分的 verifier，最好是逐斷言驗證，以便產生密集驗證訊號。
- **軌跡與日誌**：收集工具呼叫回合、Shell 輸出、錯誤碼與中間狀態，用於熱啟動與除錯。

### 運算
- **GPU 叢集**：至少需支援 122B 級 MoE 模型共置的行動者–評論者對訓練，並具備上下文平行能力。
- **雲端沙盒叢集**：能並行執行數百到數千個沙盒實例，每個任務可支援 300+ 工具呼叫回合。
- **儲存與網路**：高吞吐日誌寫入、模型檢查點頻繁存取，以及沙盒與訓練節點間的低延遲通訊。

### 技能
- **強化學習與 MoE 訓練**：熟悉 PPO、Actor-Critic、路由對齊與詞元漂移問題。
- **系統工程與安全**：能設計沙盒隔離、權限控管、命令白名單與逃逸偵測。
- **驗證器設計**：會撰寫穩定、不可被鑽漏洞的測試與斷言。
- **基礎設施維運**：長時間（數天）保持訓練活性，處理落後者尾部與發布屏障。

## 實作步驟建議

1. **定義任務格式與驗證介面**  
   將每個終端任務標準化為「初始狀態＋目標描述＋verifier」。 verifier 應輸出通過的斷言數量，而非僅二元成敗。

2. **建置沙盒測試框架（Harness）**  
   部署雲端沙盒，確保訓練與推論使用相同的 Shell 環境、工具定義與回合邊界處理邏輯，從源頭降低訓練–推論不匹配。

3. **準備熱啟動資料**  
   用高品質人工或合成軌跡對基礎模型做監督式微調（SFT），作為強化學習的積極熱啟動點。論文中 T1-15k 即為品質篩選後的訓練語料庫。

4. **實作 TITO 與 R3**  
   - **TITO（逐詞元進出）**：訓練時餵入與推論時完全相同的取樣詞元識別碼，並在回合邊界做漂移修復。  
   - **R3（推出路由重播）**：記錄取樣器在每層 MoE 的逐詞元專家選擇，訓練時重播，確保梯度落在實際生成行為的參數上。

5. **設計密集驗證獎勵**  
   以「通過驗證器數量」作為主要獎勵訊號，並搭配折扣因子處理長期任務的信用分配。避免單純二元結果獎勵，因為它資訊量過低。

6. **執行 PPO 訓練並穩定評論者**  
   評論者以 30× 行動者學習率熱啟動，採用漸進式調度。監控訓練–推論對數機率差異，目標是壓到接近零詞元漂移。

7. **分布外驗證**  
   在與訓練語料庫完全不相交的基準（如 Terminal-Bench 2.1）上評估，確認提升來自能力遷移而非基準測試過擬合。

8. **部署與持續監控**  
   上線時加入人類在環（human-in-the-loop）審批、命令白名單、沙盒快照與回滾機制，並持續追蹤獎勵駭取跡象。

## 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **訓練–推論漂移** | MoE 路由對數值極敏感，訓練與推論的專家選擇不一致會導致梯度錯位。 | 落實 TITO + R3，定期測量對數機率差異與詞元漂移。 |
| **獎勵駭取** | 模型可能找到 verifier 漏洞，例如只跑部分測試或偽造輸出。 | 設計多層 verifier、隱藏測試、檢查副作用與檔案完整性。 |
| **沙盒逃逸** | 代理執行真實 Shell，可能誤刪檔案或嘗試權限提升。 | 使用不可變基礎映像檔、非 root 使用者、網路隔離、命令白名單與逃逸偵測。 |
| **長期不穩定** | 300+ 回合的軌跡容易累積誤差，導致策略崩潰。 | 限制每回合上下文長度、使用遞迴運算子與上下文平行、監控價值函數校準。 |
| **基準測試過擬合** | 訓練任務若與評估重疊，解決率會虛高。 | 採用隔離種子與合成任務，並在完全分布外的測試集驗證。 |
| **運算成本爆炸** | 每個 rollout 批次可能耗費數百沙盒小時。 | 建立容量模型、動態調整環境並行度、優先處理高資訊量軌跡。 |

## 與其他技術的整合建議

- **CI/CD 管線**：將終端智慧體作為一個可選的「自動修復階段」，在 build 失敗時觸發沙盒診斷，並把修補結果以 PR 形式回傳，保留人工審核閘門。
- **Issue Tracker / Ticket 系統**：讓代理讀取工單描述後，在沙盒中執行復現步驟，並把執行軌跡與 verifier 結果寫回 ticket，輔助工程師判斷。
- **可觀測性平台**：把代理的每個工具呼叫回合、Shell 輸出與獎勵訊號送入日誌與追蹤系統，方便事後審計與獎勵駭取調查。
- **LLM 編排框架（如 LangChain、AutoGen）**：將 T1 視為一個「終端執行專家」工具，由上層編排器決定何時啟動沙盒、何時終止任務、何時請求人類確認。
- **知識庫與檢索系統**：在執行前檢索過往相似故障的修復軌跡、runbook 或文件，作為上下文餵入模型，降低冷啟動試誤次數。
- **政策與合規層**：在沙盒外再加一層政策引擎，攔截高風險指令（如 `rm -rf /`、`curl | bash`），並要求雙人覆核。

## 給不同背景讀者的閱讀建議

**初學者**：建議先聚焦第 1、5、6 節，理解「為什麼要用真實 Shell 驗證」以及「密集獎勵比二元獎勵好在哪里」。TITO、R3 等技術細節可先略讀，待熟悉 PPO 與 MoE 基礎後再回頭看第 4 節。

**AI 工程師**：第 4 節（TITO、R3、訓練穩定性）與第 7 節（基礎設施）是落地重點，建議對照自己的 MoE 框架檢查路由對齊與詞元漂移問題；第 9 節的失敗經驗能幫助你避開常見坑。

**研究人員**：第 2、3、5 節值得細讀，特別是遞迴合成訓練任務、分布外語料庫設計，以及從稀疏結果獎勵轉為密集驗證訊號的信用分配問題。可進一步思考如何將此方法遷移到非終端領域。

**產品經理**：重點看第 1、6、10 節與本應用指南，評估哪些任務適合交給終端智慧體、需要多少人機協作閘門，以及運算與安全成本是否匹配預期效益。
