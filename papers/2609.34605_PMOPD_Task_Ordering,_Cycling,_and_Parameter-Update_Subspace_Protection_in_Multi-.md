## ⚡ TL;DR

多教師同策略蒸餾在共享參數中整合多種專門能力時，會出現能力蹺蹺板與跨任務干擾。

## 摘要翻譯

多教師同策略蒸餾（Multi-Teacher On-Policy Distillation, MOPD）已成為一種廣受歡迎的訓練後範式（Post-training Paradigm），用於整合前沿語言模型（Frontier Language Models）中的專門能力（Specialized Capabilities）。現有的同策略蒸餾（On-Policy Distillation, OPD）研究主要透過目標函數設計（Objective Design）、蒸餾範圍（Distillation Scope）與教師訊號建構（Teacher Signal Construction）來最佳化單任務蒸餾（Single-Task Distillation），而 MOPD 則必須在共享參數（Shared Parameters）中聚合多種能力，並解決隨之而來的能力蹺蹺板（Capability Seesaw，即提升某一領域（Domain）的能力會壓抑從其他領域習得的能力）。受 OPD 獨特更新幾何（Update Geometry）的啟發，我們發現在 MOPD 過程中，不同任務的參數更新（Parameter Updates）會迅速集中於各自的低維子空間（Low-Dimensional Subspaces）；這為識別與控制跨任務干擾（Cross-Task Interference）提供了直接的幾何基礎。因此，我們提出 PMOPD（Projection-based Multi-Teacher On-Policy Distillation，基於投影的多教師同策略蒸餾），它從不同任務的累積參數位移（Cumulative Parameter Displacements）建構子空間記憶（Subspace Memories），並將梯度（Gradients）與優化器更新（Optimizer Updates）投影（Project），以移除會干擾受保護任務方向（Protected Task Directions）的成分。我們進一步開發輕量衝突探針（Lightweight Conflict Probe）來刻畫任務間的互動並引導任務排序（Task Ordering），並搭配循環調度（Cycling）策略，以平衡子空間估計（Subspace Estimation）與及時任務重訪（Timely Task Revisitation）。在具代表性的程式碼任務（Code Tasks）、推理任務（Reason Tasks）與數學任務（Math Tasks）上的實驗顯示，PMOPD 在每一項受評估能力（Capability）上均有提升，在 Qwen2.5-7B 上將三項任務的平均得分（Average Score）提高 2.54 分（Points），在 Llama-3.1-8B 上提高 2.09 分。這些一致的提升確立了幾何感知最佳化（Geometry-Aware Optimization）作為一種有效且可轉移的平衡多教師蒸餾（Balanced Multi-Teacher Distillation）方法。

### 核心貢獻（3～5點）
- 提出 PMOPD，利用 OPD 獨特的更新幾何，從不同任務的累積參數位移建構子空間記憶，並透過投影梯度與優化器更新來保護已習得能力，有效抑制跨任務干擾。
- 開發輕量衝突探針以刻畫任務間互動，並據此引導任務排序，輔以循環調度策略，在子空間估計品質與及時任務重訪之間取得平衡。
- 在 Qwen2.5-7B 與 Llama-3.1-8B 上針對程式碼、推理與數學任務進行驗證，顯示 PMOPD 能全面提升各項能力，平均得分分別提升 2.54 分與 2.09 分。
- 確立幾何感知最佳化為一種有效且可轉移至不同基礎模型的平衡多教師蒸餾方法。

### 適合對象
本論文適合從事大型語言模型訓練後增強、多教師蒸餾、多任務學習與持續學習的研究者與工程師，特別是關注如何在共享參數中整合多種專門能力、同時緩解能力蹺蹺板與災難性遺忘問題的讀者。

## 深度分析

#### 方法論解析

PMOPD（Projection-based Multi-Teacher On-Policy Distillation，基於投影的多教師同策略蒸餾）的核心假設是：在同策略蒸餾（OPD，On-Policy Distillation）過程中，不同任務（task）對共享參數（shared parameters）產生的**累積參數位移（cumulative parameter displacements）**會迅速收斂到各自低維的**參數更新子空間（parameter-update subspaces）**。這些子空間在任務內部高度一致，但跨任務之間重疊很低，因此可以作為「哪些方向已經屬於某個教師（teacher）」的幾何標記，並用來控制後續更新對它們的干擾。

具體來說，方法包含三個互相配合的元件：

1. **每矩陣子空間記憶（per-matrix subspace memories）**  
   每完成一個任務區塊（task block）後，PMOPD 會計算該區間內每個權重矩陣的累積位移，並對其進行奇異值分解（SVD），保留前 k 個主導奇異子空間（dominant singular subspaces）。這些子空間構成了該任務的「記憶」。與儲存大量梯度樣本或激活值（activations）不同，這裡只保留一組緊湊的正交基底，因此記憶體開銷相對可控。記憶在每個循環（cycle）結束後會重建，讓受保護的幾何能夠隨著當前軌跡（trajectory）演進，而不會無限制地累積歷史檔案。

2. **雙重投影：梯度與優化器更新（gradients and optimizer updates）**  
   當學生模型（student）學習新任務時，PMOPD 會把**梯度（gradient）**投影到與已保護任務方向（protected task directions）正交的子空間上，移除會干擾先前能力的分量。但僅投影梯度並不足夠，因為像 Adafactor 這類逐元素自適應預處理優化器（element-wise adaptive preconditioners）可能會把已經投影過的梯度重新旋轉回受保護子空間。因此 PMOPD 進一步對**優化器更新（optimizer update）**再做一次投影，確保最終施加到參數上的更新不會破壞先前任務的幾何成果。這是方法中非常關鍵的細節，也是它與傳統多任務梯度投影方法的主要區別之一。

3. **輕量衝突探針（lightweight conflict probe）與循環調度（cycling strategy）**  
   由於成對干擾具有方向性（directional），PMOPD 在正式訓練前先用一個輕量探針測量任務之間的雙向衝突，並據此決定**任務排序（task ordering）**。在本文設定的三個領域中，探針選出的順序是 Code → Reason → Math。訓練時則採用**循環調度（cycling）**：反覆走訪所有教師，一方面讓每個任務都能及時重訪（timely task revisitation），防止遺忘；另一方面也讓每個區塊累積到足夠的位移，從而可靠估計子空間。實驗顯示四個循環（four cycles）效果最好。

從幾何角度看，圖 1 說明了為何需要這樣的保護：在相同的參考檢查點（reference checkpoint），Math、Code、Reason 的偏好的下一步更新方向（preferred next-update direction）差異很大，因此單純沿著當前任務梯度下降，很可能在聯合損失景觀（joint landscape）上來回震盪；PMOPD 透過修正更新方向，使軌跡更穩定地進入共享低損失區域（shared low-loss region）。

#### 實驗數據解讀

論文在兩個 8B 等級的語言模型上進行評估：Qwen2.5-7B 與 Llama-3.1-8B，涵蓋 Code、Reason、Math 三個代表性能力領域。主要結果顯示：

- **Qwen2.5-7B**：PMOPD 相較於 MOPD（Multi-Teacher On-Policy Distillation，多教師同策略蒸餾）基線，在三項任務的平均得分（average score）上提升 **2.54 分**，而且**每一項被評估的能力都獲得改善**。
- **Llama-3.1-8B**：平均得分提升 **2.09 分**，同樣在所有評估任務上都優於 MOPD。

這組數據有幾個值得注意的意涵：

1. **均勻增益而非能力重分配**  
   過去許多多任務方法雖然能提升平均表現，卻經常是以犧牲某個領域為代價。PMOPD 的結果強調「每個任務都進步」，這支持了它的設計目標：不是簡單地在不同目標之間做權衡（trade-off），而是透過幾何感知最佳化（geometry-aware optimization）找到能同時降低多個 OPD 損失（OPD loss）的參數區域。

2. **跨模型族群的遷移性**  
   Qwen 與 Llama 具有不同的架構細節與預訓練分佈，但 PMOPD 在兩者上都帶來一致增益。這暗示子空間保護機制對於模型結構並不過度敏感，具有某種程度的可遷移性（transferability）。

3. **循環次數的選擇**  
   文中提到四個循環（four cycles）表現最佳，這說明「及時重訪」與「可靠子空間估計（subspace estimation）」之間存在權衡：循環太少會讓後期任務沒有機會被重新保護，循環太多則可能讓每個區塊的位移估計變得不可靠。這也呼應了方法論中「cycling strategy」的設計動機。

4. **任務排序 Code → Reason → Math 的合理性**  
   雖然論文沒有詳細給出每種排序的完整比較，但探針選出的順序與最終結果一致，暗示不同領域之間的干擾確實具有方向性：某些任務先學會後，其更新方向較不容易被後續任務破壞，或後續任務的更新較容易與之正交化。

不過，由於目前可見的上下文未提供標準差、個別任務絕對分數、訓練步數、學習率等細節，我們無法進一步判斷這些增益的統計顯著性，也難以評估不同元件（例如只投影梯度 vs. 同時投影優化器更新）各自的邊際貢獻。

#### 與現有研究的比較

PMOPD 與相關文獻的關係可以從三個層次來定位：

**1. 與單任務 OPD 研究的區別**  
現有 OPD 研究大多聚焦於單任務蒸餾（single-task distillation），透過目標函數設計（objective design）、蒸餾範圍（distillation scope）或教師訊號建構（teacher signal construction）來改進。PMOPD 則把問題轉移到**多教師共享參數**的情境，核心挑戰變成能力蹺蹺板（capability seesaw）：提升一個領域會壓抑另一個領域。這使得它不能直接使用單任務 OPD 的最佳實踐，而必須引入跨任務干擾控制。

**2. 與多任務梯度協調方法的區別**  
PCGrad、GradNorm、MGDA 等方法通常對**即時梯度（instantaneous gradients）**進行操作，例如移除成對衝突分量或平衡任務尺度。PMOPD 的不同之處在於：
- 它儲存的是**已實現的區塊位移（realized block displacements）**，而非單步梯度，因此包含了裁剪（clipping）、自適應預處理等優化器動態。
- 它同時投影梯度與優化器更新，解決了自適應預處理會「旋轉回」受保護子空間的問題。
- 它為每個權重矩陣維護獨立的子空間記憶，而不是對整個參數向量做單一投影，這在大型語言模型（LLM）中更具可擴展性。

**3. 與持續學習（continual learning）及參數合併方法的區別**  
GPM 等持續學習方法從激活值（activations）中提取受保護基底，而 PMOPD 從**參數更新（parameter updates）**本身提取基底，這更貼近 OPD 的更新幾何（update geometry）。相較於模型湯（model soups）或任務算術（task arithmetic）這類在參數空間中合併獨立訓練檢查點的方法，PMOPD 的優勢在於整個整合過程都在**同策略監督（on-policy supervision）**下進行，學生模型始終暴露在自己生成的軌跡（trajectories）中，因此能避免合併後才發現衝突的問題。

**主要限制**  
- 目前只驗證了三個任務與兩個模型家族，對於更多任務、更大規模（例如 70B+）或更多樣領域（例如多語言、工具使用）的適用性仍需驗證。
- 方法依賴於「低維子空間鎖定」這一幾何現象，若在某些模型或訓練設定中該現象不成立，則保護效果可能下降。
- 任務排序由衝突探針預先決定，這在任務數量增加時會帶來組合複雜度，且未探討動態調整排序的可能性。

#### 可重現性評估

根據目前提供的上下文，論文尚未提及是否公開原始碼、資料集或模型權重。文中引用了多個未來或並行的工作（例如 Ma et al., 2026; DeepSeek-AI, 2026; Li et al., 2026 等），但這些引用本身並不能作為可重現性的保證。

要完整重現 PMOPD，研究者至少需要以下資訊：

- **教師模型（teachers）與學生基礎模型（base model）的確切檢查點**：包括 Qwen2.5-7B 與 Llama-3.1-8B 的起始權重，以及各領域專家教師的訓練方式。
- **提示分佈（prompt distributions）**：每個任務的訓練提示來源、抽樣方式與資料規模。
- **超參數**：學習率、優化器選擇（Adafactor 的具體設定）、區塊長度、子空間維度 k、循環次數、投影實作的數值細節等。
- **評估基準與指標**：Code、Reason、Math 各自的測試集、評分方式（例如 pass@k、exact match、模型評判等）以及標準差或信賴區間。
- **演算法偽代碼或開源實作**：特別是「對優化器更新再做投影」這一步，需要清楚說明是在優化器內部還是外部進行，以及如何與現有框架（例如 PyTorch、Hugging Face Trainer）整合。

在缺乏上述細節的情況下，目前只能將 PMOPD 視為一個概念清晰、幾何動機強烈的方法，但距離「可獨立重現」還有一段距離。建議作者後續提供開源倉庫與訓練腳本，以促進社群驗證與改進。

#### 未來研究方向

基於 PMOPD 的框架，可以延伸出幾個有潛力的研究方向：

1. **動態子空間維度與自適應記憶**  
   目前子空間記憶的維度似乎是固定或經驗選取。未來可以研究如何根據每個任務的「有效內在維度（intrinsic dimension）」或當前訓練階段動態調整維度，在保護強度與可塑性（plasticity）之間自動權衡。

2. **理論分析干擾與收斂**  
   論文主要從經驗幾何出發，尚未提供 PMOPD 在多任務 OPD 設定下的收斂保證或干擾上界。未來可以建立更嚴謹的理論框架，說明在什麼條件下，投影後的更新能保證所有任務損失同時下降。

3. **與模組化架構或推論時路由結合**  
   PMOPD 目標是單一學生模型整合多種能力，但當任務數量持續增加時，共享參數的壓力也會上升。可以探索將子空間保護與稀疏專家模型（MoE）、LoRA 適配器或推論時路由（inference-time routing）結合，兼顧整合與擴展性。

4. **自動化任務排序與循環策略**  
   目前的衝突探針在訓練前給出固定排序。未來可以發展線上版本，在訓練過程中持續監測子空間重疊度，並動態決定下一個要學習的任務或調整循環頻率。

5. **擴展到更多領域與多模態**  
   除了 Code、Reason、Math，也可以檢驗 PMOPD 在多語言、工具使用、視覺語言模型（VLM）等多教師蒸餾情境的表現，並研究不同模態之間的更新子空間是否同樣具有低重疊特性。

6. **與其他優化器或蒸餾目標的整合**  
   本文特別提到 Adafactor 的自適應預處理會旋轉梯度。未來可以檢驗 PMOPD 與 AdamW、Sophia、Schedule-Free 優化器，或是與 DPO、KTO、RLHF 等訓練目標結合時的行為，進一步確認其通用性。

## 論文問答

**Q1：MOPD 面臨的核心問題是什麼？**

A：MOPD 必須在共享參數中同時整合多個專門領域的能力，因而不同教師的目標函數會互相競爭，產生所謂的「能力蹺蹺板」現象，也就是提升某一領域時會壓抑另一領域已習得的能力。這種跨任務干擾源於不同任務偏好的參數更新方向並不一致，甚至彼此衝突。傳統的任務混合雖然縮短了各領域的訓練間隔，卻無法辨識或保護已經學到的重要更新方向。

**Q2：為什麼現有的單任務 OPD 方法無法直接解決 MOPD 的挑戰？**

A：現有 OPD 研究大多聚焦於單任務蒸餾，透過目標函數設計、蒸餾範圍或教師訊號建構來提升單一能力，但這些方法並未處理多個教師同時作用於同一組學生參數時的衝突。MOPD 需要在學習新任務的同時保留先前任務已建立的幾何結構，單任務方法缺乏對「已習得能力」的保護機制。因此，即使每個教師單獨都能有效蒸餾，直接輪流訓練仍會導致參數在聯合損失景觀上震盪，而非穩定收斂到共享低損失區域。

**Q3：作者為何選擇從「更新幾何」的角度來處理 MOPD 的干擾？**

A：作者發現 OPD 在訓練過程中，累積參數位移會快速鎖定到各自任務的低維子空間，而且同一任務內部高度一致、跨任務之間重疊很低。這種幾何特性提供了一個直接且可計算的依據，讓我們能具體指出哪些更新方向屬於哪個任務，並判斷後續更新是否會干擾已保護的方向。相較於只看瞬間梯度，累積位移更能反映真實優化器（包含裁剪與自適應預處理）所造成的參數運動，因此更適合作為干擾控制的基礎。

**Q4：PMOPD 的核心方法是什麼？**

A：PMOPD 會針對每個參數矩陣，從已完成任務區塊的累積參數位移中建立「子空間記憶」。在學習下一個任務時，它會把梯度以及經過自適應優化器預處理後的更新都投影到與受保護任務方向正交的空間，從而移除會造成跨任務干擾的分量。這些子空間記憶會在每個循環重新估計，使保護的幾何結構能隨著當前軌跡更新，而不會累積無限大的歷史檔案。

**Q5：PMOPD 相較於傳統多任務梯度投影方法的主要創新在哪裡？**

A：傳統方法如 PCGrad 通常只在單一步驟的梯度上進行成對衝突投影，PMOPD 則儲存並保護整個任務區塊的「實現位移」，因此能涵蓋裁剪與自適應預處理帶來的影響。更重要的是，PMOPD 發現僅投影梯度並不足夠，因為像 Adafactor 這類元素級自適應優化器會把已投影的梯度重新旋轉回受保護子空間，所以它進一步對「優化器更新」也做投影。此外，PMOPD 採用每矩陣子空間記憶與循環重建機制，兼顧了保護的精細度與記憶體開銷的可控性。

**Q6：PMOPD 中的衝突探針與循環調度策略扮演什麼角色？**

A：由於成對干擾具有方向性，作者設計了一個輕量衝突探針，在正式訓練前測量任務間的雙向干擾程度，並據此對任務進行排序。接著透過循環調度在多次週期中輪流學習各任務，一方面讓每個區塊累積足夠的位移以穩定估計子空間，另一方面也確保各能力能及時被重訪、避免遺忘。在實驗設定中，探針選出的順序為 Code→Reason→Math，且四個循環的表現最佳。

**Q7：論文在哪些任務與模型上進行實驗？**

A：實驗選用了具有代表性的程式碼（Code）、推理（Reason）與數學（Math）三個任務，並在 Qwen2.5-7B 與 Llama-3.1-8B 兩個模型家族上驗證。這三個領域各自需要不同的專門能力，且容易在共享參數中產生明顯的能力蹺蹺板，因此很適合評估多教師蒸餾的平衡性。透過跨模型家族的測試，也能檢驗 PMOPD 幾何感知最佳化方法的通用性與可遷移性。

**Q8：PMOPD 相較於基線 MOPD 取得了什麼關鍵結果？**

A：在 Qwen2.5-7B 上，PMOPD 將三個任務的平均分數提升了 2.54 分；在 Llama-3.1-8B 上則提升了 2.09 分。更重要的是，PMOPD 在兩個模型家族中「每一個」被評估的能力都優於 MOPD，顯示它確實強化了聯合能力整合，而非僅僅把性能從某個領域重新分配到另一個領域。這樣的均勻優勢為幾何感知最佳化在多教師蒸餾中的有效性提供了強而有力的實證支持。

**Q9：從文中可以推論出哪些消融或設計選擇的重要性？**

A：首先，對梯度與優化器更新都進行投影是必要的，因為自適應預處理會把僅投影過的梯度旋轉回受保護子空間，忽略第二階投影將削弱干擾控制效果。其次，循環次數與任務排序並非隨意設定：四個循環在穩定子空間估計與及時任務重訪之間取得最佳平衡，而衝突探針選出的 Code→Reason→Math 順序也優於任意排序。最後，每個循環重建子空間記憶可避免無界累積，同時讓保護方向能跟隨當前軌跡演進。

**Q10：PMOPD 在實務上可以應用在哪些場景？**

A：PMOPD 特別適合需要把多個領域專家（例如數學、程式碼、推理）整合成單一可部署模型的場景，避免維護專家集成與推論時路由的複雜度。由於它屬於訓練後範式，可從同一個基礎模型出發，分別針對不同能力進行多教師蒸餾，最終得到一個通用且專精的學生模型。這對於希望降低多模型服務成本、同時保留各領域前沿表現的產品來說非常具有吸引力。

**Q11：在產品落地時需要考慮哪些因素？**

A：PMOPD 省去了推論時路由與多模型服務的成本，但訓練階段需要額外儲存與更新每矩陣子空間記憶，好在每個循環重建機制讓記憶體開銷保持有界。此外，任務排序與循環次數需要透過輕量衝突探針預先估計，這會增加少量前置實驗成本，但相較於完整訓練仍可忽略。最後，產品團隊應確認目標能力之間確實呈現低維、可分離的更新子空間，否則投影保護可能過度限制模型學習新能力。

**Q12：這項研究對整個領域可能帶來什麼影響？**

A：PMOPD 把「幾何感知最佳化」確立為解決平衡多教師蒸餾的有效且可遷移途徑，為後續研究提供了一個新的分析視角。它連結了同策略蒸餾、多任務學習、持續學習與低維更新幾何等領域，顯示參數位移的子空間結構可以被主動利用來控制干擾。未來這套框架也可能啟發模型合併、專家路由與其他訓練後範式的設計，推動單一模型整合更多樣化專門能力的發展。

**Q13：論文有哪些可能的限制？**

A：實驗目前只涵蓋 Code、Reason、Math 三個領域，對於更多任務或更細粒度能力組合的適用性仍需進一步驗證。此外，衝突探針與循環次數是根據經驗選擇，尚缺乏針對任意任務集合的自動化理論保證。最後，方法假設不同任務的累積更新會形成低重疊的低維子空間，若此假設在某些模型或資料設定下不成立，PMOPD 的保護效果可能會下降。

**Q14：PMOPD 在什麼情況下可能失效或表現不佳？**

A：如果多個任務的更新子空間高度重疊，那麼投影掉重疊分量可能會同時削弱所有相關任務的學習能力，導致更新空間過度受限。當任務區塊長度不足時，累積參數位移的估計會過於嘈雜，難以穩定提取主導奇異子空間，進而影響保護方向的準確性。另外，若衝突探針估計的任務排序與真實干擾結構不符，也可能放大而非抑制跨任務干擾。

**Q15：未來可以朝哪些方向延伸這項工作？**

A：未來可以將 PMOPD 擴展到更多教師與更多任務的設定，並發展動態或線上任務排序機制，讓衝突探針在訓練過程中持續更新。也可以進一步從理論上分析 OPD 更新子空間鎖定的條件與收斂性質，為投影保護提供更強的保證。此外，把幾何感知保護與模型合併、專家路由或混合專家架構結合，或許能在保持單一模型部署優勢的同時，進一步提升極大規模多能力整合的效率與表現。

## 實務應用指南

### 適用場景

1. **企業專屬多能力助手**：將程式碼生成、數學推理與邏輯分析等專家教師整合進單一模型，避免推論時路由與多模型服務成本，適合需要統一 API 的企業內部助手。
2. **開源模型後訓練增強**：在 Qwen、Llama 等基礎模型上，透過多教師同策略蒸餾注入領域專長，例如法律、醫療、財務等專家教師的知識融合。
3. **取代專家集成（ensemble）的邊緣部署**：資源受限場景下，用單一學生模型承載多個專家能力，降低記憶體與推論延遲。
4. **持續性模型迭代**：當新領域教師持續加入時，利用子空間記憶保護已習得能力，減少災難性遺忘。
5. **多能力評測導向的模型調優**：針對同時評量 Code、Reason、Math 等能力的 benchmark，平衡各領域表現而非犧牲某項能力換取另一項。

### 實作前置條件

- **資料**：每個任務需有對應的提示分布（prompt distribution）$D_t$，以及能產生詞元級目標的專家教師 $\pi_t$；建議準備獨立分片以驗證子空間穩定性。
- **運算資源**：至少具備多張高記憶體 GPU 的叢集，因為 PMOPD 需在訓練過程中對每個矩陣進行奇異值分解或 PCA 以估計子空間。
- **技術能力**：
  - 熟悉 PyTorch 分散式訓練與自訂優化器（如 Adafactor）的 hook；
  - 能實作梯度投影與優化器更新投影；
  - 具備 SVD/PCA、低維子空間分析與檢查點位移可視化的經驗；
  - 能建立每任務評估管線，追蹤能力蹺蹺板現象。

### 實作步驟建議

1. **定義任務與教師**：選定要整合的領域（如 Code、Reason、Math），為每個任務訓練或準備專家教師，並確保學生模型可從教師取得 on-policy 監督訊號。
2. **執行輕量衝突探針**：在少量步驟內測量任務間的雙向干擾，量化「學習 A 會如何影響 B」，並據此決定任務排序（例如 Code → Reason → Math）。
3. **建立子空間記憶機制**：在每個任務區塊結束後，計算該矩陣的累積參數位移，並用 SVD 擷取主導低維子空間作為受保護任務方向。
4. **整合投影訓練迴圈**：在學習新任務時，先對梯度投影，再對經過元素級自適應預處理後的優化器更新投影，移除會干擾已保護子空間的分量。
5. **設計循環調度策略**：規劃多個循環，每個循環結束後重建子空間記憶，讓受保護幾何能追蹤當前軌跡，同時確保及時任務重訪。
6. **持續監控與迭代**：每個循環後評估各任務得分與平均得分，若出現能力蹺蹺板，調整子空間維度、任務排序或循環次數。

### 潛在風險與注意事項

- **子空間維度選擇過高或過低**：維度過小會遺失重要更新方向，過大則過度限制新能力學習；建議從主導奇異值能量比例（如 80–90%）開始實驗。
- **記憶過時**：若循環太長，子空間記憶可能無法反映當前參數狀態；應透過循環調度在「子空間估計穩定性」與「及時任務重訪」間取得平衡。
- **過度保護導致可塑性喪失**：保護過多方向會使模型難以吸收新任務，需保留足夠的自由參數空間。
- **任務排序敏感**：雖然衝突探針可提供指引，但最終順序仍可能影響結果，建議以小型實驗比較 2–3 種排序。
- **計算開銷**：每矩陣 SVD 與雙重投影會增加訓練成本，需評估是否可透過低秩近似或分層選擇性投影來降低負擔。
- **教師品質不一致**：若某教師訊號品質較差，投影保護反而會把錯誤方向鎖定，需先確認教師品質與評估指標對齊。

### 與其他技術的整合建議

- **與 LoRA / QLoRA 結合**：可在適配器權重上建立子空間記憶，減少可訓練參數與 SVD 開銷，適合資源受限場景。
- **作為 RLHF / DPO 的前置階段**：先以 PMOPD 整合多領域專長，再進行對齊訓練，避免對齊過程壓抑已習得的專門能力。
- **與模型合併技術互補**：可用 task arithmetic 或 model soups 的結果作為 PMOPD 的初始化檢查點，再透過 on-policy 蒸餾精修聯合能力。
- **與推論路由搭配**：雖然 PMOPD 目標是單一模型，但仍可保留輕量路由器作為後備，當單一模型在特定領域表現不足時切換至專家教師。
- **整合現有資料管線**：將衝突探針與子空間估計嵌入現有的實驗追蹤系統（如 Weights & Biases、MLflow），方便比較不同任務排序與循環策略。

### 給不同背景讀者的閱讀建議

- **初學者**：先聚焦「能力蹺蹺板」這個直覺問題，理解 PMOPD 如何透過「記住每個任務的更新方向，並在新任務學習時避開這些方向」來達成平衡；圖 1 的聯合損失景觀與軌跡對比是很好的入門切入點。
- **AI 工程師**：重點閱讀子空間記憶的實作細節，特別是「對梯度投影後，還要對優化器更新再投影」這一點，因為 Adafactor 等自適應優化器會旋轉已投影的梯度；同時留意循環調度與衝突探針的工程實踐。
- **研究人員**：關注更新幾何的分析貢獻，包括累積 OPD 更新會早期鎖定低維子空間、同任務一致性高、跨任務重疊低等現象；可進一步探索子空間維度理論、動態記憶重建頻率，以及與持續學習方法的理論聯繫。
- **產品經理**：把 PMOPD 視為「用單一模型取代專家集成」的技術選項，評估其對推論成本、維運複雜度與多領域評測表現的影響；同時預留實驗預算，因為任務排序與循環次數仍需依產品場景調校。
