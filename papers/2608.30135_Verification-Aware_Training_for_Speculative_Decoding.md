## ⚡ TL;DR

現有草稿訓練僅模仿目標輸出，忽略依序驗證與首次拒絕後丟棄的特性。
本文提出驗證感知訓練，以驗證頭預測接受與否，並依首次拒絕位置調整損失權重。
在EAGLE-3與DFlash上，平均接受長度提升達11.4%，實際加速比提升達8.7%。

## 摘要翻譯

推測解碼（Speculative Decoding）透過草稿模型（Draft Model）生成候選詞元（Candidate Tokens），再由目標模型（Target Model）於單次前向傳播（Forward Pass）中驗證（Verification），以加速大型語言模型（Large Language Models, LLMs）推論。驗證按順序進行，並自首次拒絕位置（First Rejection Point）起丟棄其後所有位置；然而現有草稿模型訓練仍仰賴對目標模型進行詞元級模仿（Token-Level Imitation），並採用固定逐位置加權（Fixed Per-Position Weighting），未能反映上述任一特性。我們提出驗證感知訓練（Verification-Aware Training, VAT），一個即插即用框架（Plug-In Framework），能在每個訓練步驟中模擬驗證過程，並將產生的接受（Acceptance）與拒絕（Rejection）模式轉化為監督訊號。VAT 包含兩個元件：（i）驗證頭（Verification Head），一個輕量級且與草稿模型聯合訓練的二元分類器（Binary Classifier），用於監督草稿模型學習每個位置是否能通過循序驗證；（ii）驗證自適應加權（Verification-Adaptive Weighting），取代固定逐位置加權排程，在到達每個樣本的首次拒絕位置前維持完整權重，並將衰減起點重新錨定於該位置。VAT 僅修改訓練目標（Training Objective），因此可疊加於現有方法之上，無需更動草稿模型架構、目標模型或推論流程。將 VAT 套用於 EAGLE-3 與 DFlash，並以 Qwen3-4B、Qwen3-8B 與 LLaMA-3.1-8B 進行測試，VAT 最高可將平均接受長度（Acceptance Length）提升 11.4%、實際加速比（Wall-Clock Speedup）提升 8.7%，且在數學、程式與對話基準測試中均有穩定增益。程式碼將公開於 https://github.com/naver-ai/vat。

### 核心貢獻（3～5點）
- 提出驗證感知訓練（VAT），將推測解碼的驗證機制納入草稿模型訓練，使訓練目標更符合推論時的實際行為。
- 設計驗證頭（Verification Head），以二元分類器預測每個位置是否會被目標模型接受，提供額外的監督訊號。
- 提出驗證自適應加權（Verification-Adaptive Weighting），根據首次拒絕位置動態調整損失權重，取代傳統固定逐位置加權。
- 作為即插即用框架（Plug-In Framework），VAT 僅修改訓練目標，可無縫整合至 EAGLE-3、DFlash 等現有推測解碼方法，無需更動模型架構或推論流程。
- 在 Qwen3-4B、Qwen3-8B 與 LLaMA-3.1-8B 上驗證，於數學、程式與對話基準均達成平均接受長度與實際加速比的穩定提升。

### 適合對象
適合對推測解碼、大型語言模型推論加速與草稿模型訓練有興趣的研究人員與工程師，特別是關注如何透過訓練目標設計提升推論效率、或希望將現有草稿訓練方法無縫升級的讀者。

## 深度分析

#### 方法論解析

##### 1. 問題設定：現有草稿訓練與驗證機制的錯位

Speculative Decoding（推測解碼）的加速效果取決於兩個環節的協同：Draft Model（草稿模型）低成本生成 Candidate Tokens（候選詞元），再由 Target Model（目標模型）在一次 Forward Pass（前向傳播）內依序進行 Verification（驗證）。驗證遵循 Acceptance Rule（接受規則），一旦某個位置被拒絕，從該位置起所有後續 Candidate Tokens 都會被丟棄，並從最後被接受的位置重新開始新一輪草稿。因此，推論時真正決定 Wall-Clock Speedup（實際加速比）的是 **Acceptance Length（接受長度）**，也就是每輪驗證中連續被接受的詞元數量。

然而，現有 Draft Model 的訓練幾乎都採用 Token-Level Imitation（詞元級模仿）：以 Target Model 的輸出作為每個位置的標籤，最小化 Cross-Entropy Loss（交叉熵損失）。這種訓練方式存在兩個與驗證過程脫節的問題：

1. **缺乏驗證信號**：模型只學習「每個位置應該輸出什麼詞元」，卻沒有學習「該詞元是否會被 Target Model 接受」。即使某個位置的預測與 Target Distribution（目標分佈）接近，只要前面任一位置被拒絕，它對 Acceptance Length 的貢獻就是零。
2. **固定逐位置權重**：現有方法常採用 Fixed Per-Position Weighting（固定逐位置加權），例如對較早位置給予較高權重。但這種排程是預先設定、所有樣本共享的，無法根據每個樣本的 First Rejection Point（首次拒絕位置）動態調整。

##### 2. Verification-Aware Training（驗證感知訓練）的整體架構

本文提出的 VAT（Verification-Aware Training，驗證感知訓練）是一個 Plug-In Framework（即插即用框架），核心想法是在每次訓練步驟中 **模擬 Target Model 的驗證過程**，並將產生的接受／拒絕模式轉化為額外的監督信號。整體訓練目標可寫成：

\[
\mathcal{L} = \sum_{k} \hat{w}_k \, \ell_k + \beta \, \mathcal{L}_{\text{VH}}
\]

其中 \(\ell_k\) 是第 \(k\) 個位置的 Cross-Entropy Loss，\(\hat{w}_k\) 是 VAT 重新調整後的位置權重，\(\mathcal{L}_{\text{VH}}\) 是 Verification Head（驗證頭）的損失，\(\beta\) 為平衡係數。VAT 只修改 Training Objective（訓練目標），不改變 Draft Model 架構、Target Model 或推論流程，因此可疊加在 EAGLE-3、DFlash 等現有方法之上。

##### 3. 驗證模擬與接受標籤

在每次訓練時，VAT 比較 Draft Model 與 Target Model 在每個位置 \(k\) 的預測，產生二元 Acceptance（接受）標籤 \(v_k\)：

- 若兩者在位置 \(k\) 的預測一致（依據驗證規則可被接受），則 \(v_k = 1\)；
- 一旦出現第一個不一致的位置 \(k^*\)，則 \(v_{k^*} = 0\)，且所有 \(k > k^*\) 的位置都被標記為拒絕。

這個模擬過程不需要額外的推論開銷，因為 Target Model 的輸出在知識蒸餾或模仿學習中通常已經需要計算。

##### 4. Verification Head（驗證頭）

Verification Head 是一個輕量級的 Binary Classifier（二元分類器），接在 Draft Model 的 Hidden States（隱藏狀態）之上，負責預測每個位置是否會被 Target Model 接受。其損失為：

\[
\mathcal{L}_{\text{VH}} = \sum_{k} \text{BCE}(\hat{v}_k, v_k)
\]

由於該分類器直接作用於 Draft Model 的中間表示，其梯度會反向傳播回 Draft Model，促使模型學習那些能夠預測「與 Target Model 是否一致」的特徵。這與傳統的 Token-Level Imitation 形成互補：後者告訴模型「應該生成什麼」，而 Verification Head 告訴模型「生成結果能否通過驗證」。

##### 5. Verification-Adaptive Weighting（驗證自適應加權）

VAT 的第二個元件是動態調整每個位置的 Cross-Entropy 權重。具體而言：

- 對於 First Rejection Point \(k^*\) 之前的所有位置，保持完整權重（例如 1.0），因為這些位置直接決定 Acceptance Length；
- 對於 \(k^*\) 及之後的位置，權重從該點開始重新錨定並遞減，而非使用預先固定的全局排程。

換句話說，VAT 將原本固定的權重曲線 \(w_k\) 轉換為樣本相關的 \(\hat{w}_k\)，其衰減起點對齊每個樣本的實際 First Rejection Point。這樣做的好處是：

- **聚焦關鍵位置**：學習信號集中在真正影響 Acceptance Length 的前段位置；
- **保留後段信號**：後續位置雖然在推論時會被丟棄，但仍獲得較小的學習信號，避免模型完全忽略長程依賴；
- **樣本自適應**：不同樣本的難度與拒絕位置不同，權重隨之調整，比 Fixed Per-Position Weighting 更靈活。

#### 實驗數據解讀

##### 1. 實驗設置

論文在兩種代表性的推測解碼方法上驗證 VAT：

- **EAGLE-3**：自迴歸（Autoregressive）草稿模型，複用 Target Model 的 Hidden States，並透過多層特徵融合與多步 Rollout 訓練提升草稿品質。
- **DFlash**：基於 Block Diffusion Model（區塊擴散模型）的非自迴歸草稿模型，可並行生成所有 Candidate Tokens。

Target Model 涵蓋 Qwen3-4B、Qwen3-8B 與 LLaMA-3.1-8B。評估任務橫跨數學、程式碼與對話等多個 Benchmark（論文中以 [14, 28, 12, 5, 22, 40, 33] 標示）。評估指標為：

- **Average Acceptance Length（平均接受長度）**：每輪驗證中被接受的平均詞元數；
- **Wall-Clock Speedup（實際加速比）**：端到端推論時間相對於無推測解碼的加速倍數。

##### 2. 主要結果

論文報告 VAT 在 Acceptance Length 上最高提升 **11.4%**，在 Wall-Clock Speedup 上最高提升 **8.7%**。其中一組具體數據如下（Qwen3-4B）：

| 方法 | 基線 Speedup | +VAT Speedup | 基線 Acceptance Length | +VAT Acceptance Length |
|---|---|---|---|---|
| EAGLE-3 | 4.07× | 4.39× (+7.9%) | 6.28 | 6.78 (+8.0%) |
| DFlash | 4.54× | 4.81× (+5.9%) | 5.73 | 6.08 (+6.1%) |

##### 3. 結果意涵

- **增益跨架構一致**：無論是自迴歸的 EAGLE-3 還是擴散式的 DFlash，VAT 都能帶來提升，顯示「讓訓練對齊驗證」這一原則具有通用性，並不依賴特定的 Draft Model 設計。
- **Acceptance Length 與 Speedup 的對應關係**：Acceptance Length 的提升通常會轉化為 Wall-Clock Speedup，但兩者並非線性對應。例如 EAGLE-3 的 Acceptance Length 增加 8.0%，Speedup 增加 7.9%，幾乎是 1:1；而 DFlash 的 Acceptance Length 增加 6.1%，Speedup 增加 5.9%。這說明 VAT 的額外計算開銷（Verification Head 與模擬驗證）在訓練時發生，不影響推論時的開銷結構。
- **高基線仍有進步空間**：DFlash 在 Qwen3-4B 上已達到 4.54× 的加速，VAT 仍能進一步提升到 4.81×，顯示即使在強基線上，訓練目標的對齊仍有顯著優化空間。
- **跨領域穩定性**：數學、程式碼、對話三類任務均觀察到一致增益，暗示 VAT 不會過度擬合單一領域的分佈特性。

##### 4. 可進一步分析的面向

論文摘要與引言未提供完整的標準差、顯著性檢定或各 Benchmark 的細分數據。若未來能補充：

- 各領域（math / code / chat）單獨的 Acceptance Length 與 Speedup；
- 不同 Draft Length（草稿長度）下的增益曲線；
- Verification Head 單獨貢獻與 Verification-Adaptive Weighting 單獨貢獻的消融實驗；

將有助於更精確地判斷兩個元件的相對重要性。

#### 與現有研究的比較

##### 1. 與推測解碼架構研究的定位

近年推測解碼研究主要聚焦於 Draft Model 的架構創新：

- **EAGLE 系列** [25, 26, 27] 透過複用 Target Model Hidden States、動態 Draft Tree、多步 Rollout 等方式提升草稿品質；
- **DFlash** [11] 則以 Block Diffusion Model 實現並行草稿生成。

這些工作雖然在模型結構上差異很大，但訓練目標大多仍停留在標準的 Token-Level Imitation，並輔以 Fixed Per-Position Weighting。VAT 的貢獻在於 **不改變上述架構，而是重新設計訓練目標**，因此與這些方法處於正交（orthogonal）位置，可直接疊加。

##### 2. 與知識蒸餾與目標函數研究的比較

部分研究探討以 Knowledge Distillation（知識蒸餾）訓練 Draft Model [41, 17, 30]，讓草稿分佈更接近 Target Distribution。這類方法仍著重於「分佈相似度」，而非「驗證結果」。VAT 進一步將 Target Model 的驗證行為顯式納入訓練：

- **Verification Head** 提供的是「接受與否」的監督，比單純的機率匹配更貼近推論時的目標；
- **Verification-Adaptive Weighting** 則根據每個樣本的 First Rejection Point 動態調整，比固定權重更能反映 Sequential Verification（循序驗證）的結構。

##### 3. 優勢總結

1. **即插即用**：不修改 Draft Model、Target Model 或推論流程，降低部署門檻。
2. **訓練與推論對齊**：直接優化影響 Acceptance Length 的因素，而非間接透過分佈相似度。
3. **樣本自適應**：權重根據每個樣本的實際驗證結果調整，比 Fixed Per-Position Weighting 更精細。
4. **跨範式通用**：在自迴歸與擴散式草稿模型上均有效。

##### 4. 限制與潛在弱點

1. **依賴 Target Model 輸出**：模擬驗證需要 Target Model 在每個訓練位置的預測，這在現有模仿學習中通常已可取得，但仍增加訓練時的記憶體與計算需求。
2. **超參數 \(\beta\)**：Verification Head 的權重需要調整，若過大可能壓過 Token-Level Imitation，過小則信號不足。
3. **衰減排程仍為啟發式**：雖然起點自適應，但拒絕後的權重衰減形狀（線性、指數等）仍由人為設計，未必是理論最優。
4. **未處理 Draft Tree 的複雜驗證**：EAGLE-2/3 使用動態 Draft Tree，驗證可能涉及多條路徑與樹狀結構；本文的模擬似乎針對線性序列，未明確討論樹狀驗證下的擴展。
5. **接受規則的假設**：訓練時模擬的 Acceptance Rule 需與推論時一致，若推論時使用不同的溫度採樣或修正規則，可能產生 Train-Test Mismatch（訓練測試不一致）。

#### 未來研究方向

##### 1. 擴展至樹狀與動態草稿結構

EAGLE-2/3 使用 Draft Tree 同時驗證多條候選路徑。未來可將 VAT 的「首次拒絕」概念擴展為 **路徑級或樹節點級的接受機率預測**，讓 Verification Head 學習更複雜的樹狀驗證結構，並設計對應的 Verification-Adaptive Weighting。

##### 2. 直接優化 Wall-Clock Speedup

VAT 目前仍間接透過提升 Acceptance Length 來改善 Speedup。未來可嘗試以強化學習（Reinforcement Learning）或可微分代理目標，**直接以端到端延遲作為優化目標**，同時考慮 Draft Model 本身的推論成本與 Target Model 的驗證成本。

##### 3. 硬體感知與動態草稿長度

將硬體特性（如 GPU 記憶體頻寬、Batch Size、KV Cache 大小）納入 Training Objective，學習在不同硬體上最適的 Acceptance Length 與 Draft Length 權衡。VAT 的 Verification Head 可進一步用於 **動態決定每輪應生成多少草稿詞元**。

##### 4. 與其他草稿範式結合

除了 EAGLE-3 與 DFlash，VAT 也可應用於：

- **Medusa / Hydra** [9, 3]：在平行解碼頭上加入 Verification Head；
- **Lookahead Decoding** 等無需獨立 Draft Model 的方法：預測未來 n-gram 的接受機率；
- **多模態推測解碼**：將驗證感知訓練擴展至影像、語音或影片生成模型。

##### 5. 理論分析最優權重排程

目前的 Verification-Adaptive Weighting 使用啟發式衰減。未來可從理論上推導，在給定 Draft Model 容量與 Target Model 分佈下，**最優的逐位置權重函數**應具備什麼形式，例如是否與位置上的接受機率乘積或資訊增益相關。

##### 6. 不確定性量化與拒絕預測

Verification Head 目前輸出點估計的接受機率。可進一步引入不確定性估計（Uncertainty Estimation），讓模型知道「哪些位置即使預測為接受也仍具風險」，從而在高風險區域主動縮短 Draft Length，提升穩定性。

##### 7. 線上適應與領域遷移

VAT 的模擬驗證依賴 Target Model 在訓練資料上的行為。未來可探索 **線上適應機制**：在部署後根據實際推論的接受／拒絕統計，持續微調 Verification Head 與權重排程，以適應新領域或使用者分佈漂移。

## 論文問答

**Q1：推測解碼中，草稿模型訓練與驗證流程之間存在什麼核心問題？**

A：核心問題在於兩者的目標並不一致：推測解碼的實際加速效果取決於每次驗證能通過多少詞元，也就是接受長度，但現有草稿模型訓練通常只要求草稿逐詞元模仿目標模型的輸出分佈。這種詞元級模仿把每個位置視為獨立任務，忽略了「一旦某個位置被拒絕，後續所有詞元都會被丟棄」的序列特性。因此，模型可能在優化一個與最終推論速度無直接關係的目標，導致訓練損失下降卻未必帶來牆上時鐘加速比的提升。

**Q2：為什麼傳統的固定逐位置加權無法有效對齊驗證流程？**

A：固定逐位置加權在訓練前就已預先決定，並且所有樣本共用同一套權重排程，無法根據每個樣本實際發生首次拒絕的位置進行調整。然而，在推論時，只有首次拒絕位置之前的詞元才真正影響接受長度與加速比，後續詞元無論個別品質如何都不會被採用。這種「樣本無關」的加權方式使得模型無法針對決定驗證成敗的關鍵區段集中學習，造成訓練與推論之間的目標錯位。

**Q3：將訓練目標與驗證流程對齊，為什麼對推論加速至關重要？**

A：因為推測解碼的牆上時鐘加速比幾乎完全由接受長度決定，而不是由每個詞元單獨與目標模型有多接近決定。如果訓練目標只關注詞元級模仿，草稿模型可能學會生成看起來合理的序列，卻在關鍵位置頻繁被目標模型拒絕。透過把驗證結果轉化為監督訊號，模型能直接優化影響速度的核心指標，使訓練損失的下降更有效地轉化為實際推論延遲的縮短。

**Q4：驗證感知訓練（VAT）由哪兩個主要元件組成？**

A：VAT 包含兩個協同運作的元件：第一是驗證頭，它是一個輕量級的二元分類器，架構上接在草稿模型的隱藏狀態之後，負責預測每個位置是否能通過目標模型的序列驗證；第二是驗證自適應加權，它取代傳統固定權重排程，根據模擬驗證得到的首次拒絕位置，對該位置之前保持完整權重、之後則重新錨定並遞減權重。這兩個元件都依賴訓練時比較草稿與目標模型預測所產生的接受／拒絕標籤，從而將驗證訊號引入草稿模型的學習過程。

**Q5：驗證自適應加權的關鍵洞見是什麼？**

A：關鍵洞見在於「首次拒絕位置之後的詞元在推論時不會被採用」，因此它們的訓練權重應該根據每個樣本實際的拒絕點動態降低，而不是按照預先設定的固定曲線衰減。這種樣本自適應的機制能把學習焦點集中在真正決定接受長度的前段位置，同時保留後段位置的部分梯度以避免完全切斷學習訊號。相較於固定排程，它讓損失函數更貼近推論時的價值分佈，使梯度下降更有效率地優化驗證通過率。

**Q6：為什麼驗證頭要接在草稿模型的隱藏狀態上，而不是獨立訓練？**

A：將驗證頭接在草稿隱藏狀態上並與草稿模型聯合訓練，可以讓輔助損失的梯度反向傳播回草稿模型，進而塑造那些能預測與目標模型一致性的表徵。這創造了一個雙重學習訊號：草稿模型不僅要學會生成正確的下一詞元，還要學會產生能通過目標驗證的內部特徵。此外，驗證頭本身非常輕量，只在訓練時使用，因此不會增加推論階段的計算負擔或改變部署架構。

**Q7：論文採用了什麼實驗設定來評估 VAT？**

A：論文選用了兩種代表性的推測解碼方法：自迴歸式的 EAGLE-3 與基於區塊擴散的 DFlash，並在三個目標模型上測試，包括 Qwen3-4B、Qwen3-8B 與 LLaMA-3.1-8B。評估涵蓋數學、程式碼與對話等多類型基準，能夠檢驗 VAT 在不同領域與不同草稿典範下的泛化能力。這樣的設定特別有意義，因為它證明 VAT 並非只適用於特定架構，而是一種可跨方法套用的訓練框架。

**Q8：VAT 的主要實驗結果是什麼？**

A：VAT 在所有基線與目標模型的組合上都穩定提升了平均接受長度與牆上時鐘加速比，其中接受長度最高提升 11.4%，加速比最高提升 8.7%。舉例來說，在 Qwen3-4B 上，EAGLE-3 的加速比從 4.07× 提升至 4.39×，DFlash 則從 4.54× 提升至 4.81×；對應的平均接受長度也分別從 6.28 增加到 6.78、從 5.73 增加到 6.08。這些結果顯示，即使在不改變草稿架構或推論流程的前提下，僅調整訓練目標就能帶來顯著且一致的效能增益。

**Q9：從實驗結果可以推論出 VAT 的什麼特性？**

A：實驗結果顯示 VAT 的效益與底層草稿機制無關，無論是自迴歸的 EAGLE-3 還是擴散式的 DFlash 都能獲得一致提升。這強烈暗示「驗證感知訓練」是一種通用原則，而非針對特定架構設計的技巧。由於 VAT 只修改訓練目標、不改變模型架構或推論流程，它可以作為即插即用的外掛元件，與未來各種新的草稿模型設計結合使用。

**Q10：VAT 在哪些實際部署場景中最具價值？**

A：VAT 特別適合對延遲敏感的互動式應用，例如即時聊天機器人、程式碼自動補全、數學推理輔助系統等，這些場景都廣泛採用推測解碼來降低推論延遲。由於 VAT 不需要修改既有的推論管線或目標模型，企業可以在不更動已優化部署架構的情況下，透過重新訓練草稿模型獲得加速效益。這種「訓練時改進、推論時零負擔」的特性，使其在生產環境中具有高度的實用性與採用彈性。

**Q11：從產品化角度來看，VAT 有哪些實作優勢？**

A：VAT 最大的實作優勢在於它只改變訓練目標，不改變草稿模型架構、目標模型權重或推論程序，因此可以無縫疊加在現有方法之上。驗證頭僅在訓練階段使用，推論時不會帶來額外記憶體或計算開銷，這對資源受限的部署環境非常重要。此外，由於目標模型保持不變，產品團隊無需重新評估輸出品質或調整服務層級協議，就能直接享受更快的回應速度。

**Q12：VAT 可能對推測解碼領域的未來研究產生什麼影響？**

A：VAT 將研究焦點從單純改進草稿模型架構，擴展到「如何設計與推論流程對齊的訓練目標」這一更深層的問題。它證明了即使不改變模型結構，僅透過更符合驗證機制的監督訊號就能顯著提升加速比，這可能啟發更多針對推論行為設計的損失函數研究。長遠來看，這種「推論感知訓練」的思維也可能影響其他生成模型加速技術，例如推論時擴展或投機式取樣的變體。

**Q13：VAT 可能存在哪些限制或隱含挑戰？**

A：雖然論文提供的上下文未明確列出限制，但從方法設計可推知，VAT 的效果部分依賴訓練時模擬驗證標籤的準確性，若草稿與目標模型在訓練初期的分佈差異過大，模擬標籤可能不穩定。此外，聯合訓練驗證頭會增加訓練階段的記憶體與計算開銷，對於超大規模草稿模型可能需要額外的工程優化。最後，若基線草稿模型已經與目標模型高度對齊，則 VAT 能帶來的邊際增益可能相對有限。

**Q14：在什麼情況下 VAT 可能無法顯著改善效能？**

A：當基線草稿模型已經非常貼近目標模型時，模擬驗證產生的拒絕點可能很少且穩定，此時驗證自適應加權與驗證頭能提供的額外訊號就會變弱。另一種情況是訓練時的模擬驗證與實際推論驗證存在系統性差異，例如溫度、取樣策略或動態草稿樹結構不同，導致學到的驗證訊號在部署時不準確。此外，若資料中首次拒絕位置高度分散或雜訊過大，自適應權重可能無法穩定地將學習焦點集中在關鍵區段。

**Q15：VAT 開啟了哪些未來研究方向？**

A：未來研究可以將 VAT 擴展到更複雜的驗證機制，例如 EAGLE-2 的樹狀草稿驗證或多草稿同時驗證策略，進一步提升其適用範圍。另一個方向是設計更精細的模擬驗證方法，例如考慮目標模型的不確定性或動態調整驗證頭的監督強度。更廣泛地說，VAT 提出的「將推論行為納入訓練目標」的框架，也可以應用到其他生成加速技術，例如推論時運算預算分配或投機式編輯生成，成為一個跨領域的研究主題。

## 實務應用指南

## 適用場景

**高頻互動式聊天機器人與客服系統**  
對話式應用對首詞元延遲（time-to-first-token）與整體回應速度極為敏感。VAT 可提升推測解碼的平均接受長度，讓目標模型在單次前向傳播中驗證更多候選詞元，適合每日承載數百萬輪對話的客服機器人、語音助理與即時聊天介面。

**程式碼輔助與自動完成（Copilot 類產品）**  
程式碼生成通常需要連續產出多個詞元（例如函式簽章、括號、縮排與邏輯區塊）。VAT 的驗證感知訓練能讓草稿模型更準確預測目標模型會接受的程式碼片段，減少開發者等待建議完成的時間，特別適合 IDE 外掛與雲端程式碼助理。

**數學推理與思維鏈（Chain-of-Thought）應用**  
數學與邏輯推理任務的輸出較長，且中間推理步驟必須連貫。透過 VAT 強化草稿模型對「哪些位置會通過目標模型驗證」的感知，可在不犧牲答案正確性的前提下，加速多步推理過程，適用於教育輔導、科學計算與自動證明等場景。

**邊緣裝置或雲端 API 服務的成本優化**  
在資源受限的邊緣裝置上，目標模型每次前向傳播成本高昂；在雲端則直接影響 GPU 利用率與計費。VAT 提升接受長度後，可在相同硬體上服務更多請求，或降低單一請求的計算量，適合手機端助理、地端企業知識庫與高併發 API 閘道。

**多輪對話與 RAG 檢索增強生成**  
RAG 系統常需先檢索長篇文件，再由模型根據上下文生成答案。VAT 可與現有推測解碼管線結合，加速後續生成階段，並在多輪對話中維持穩定的低延遲，適合企業內部搜尋、法律文件問答與醫療知識助手。

## 實作前置條件

**資料準備**  
需要與推論場景分佈相近的訓練語料，且能取得目標模型在每個訓練樣本上的輸出分佈（logits）。若採用 EAGLE-3 類架構，還需能提取目標模型的隱藏狀態作為草稿模型輸入。建議準備至少數十萬筆高品質樣本，並涵蓋目標領域（如數學、程式碼、對話）的多樣化查詢。

**運算資源**  
訓練過程需同時載入目標模型與草稿模型以模擬驗證，因此需要具備足夠 VRAM 的 GPU（如 A100 / H100）。若目標模型較大，可考慮將目標模型以 eval 模式置於單一節點，草稿模型與驗證頭進行分散式訓練。推論階段則無需額外硬體，VAT 不改變原有推論流程。

**技術能力**  
團隊需熟悉 PyTorch 或 JAX、Transformer 模型訓練管線、推測解碼實作（如 EAGLE / Medusa / DFlash），以及效能分析工具。此外，需具備損失函式客製化與梯度監控經驗，以便正確實作驗證自適應加權與二元分類頭。

## 實作步驟建議

**步驟一：建立基線推測解碼流程**  
先以現有方法（如 EAGLE-3 或 DFlash）在目標任務上建立基線，測量平均接受長度、實際加速比與輸出品質。確認草稿模型與目標模型可正常協同運作，並記錄當前損失函式與固定逐位置加權設定。

**步驟二：產生驗證標籤**  
在每次訓練迭代中，讓目標模型對草稿模型生成的候選序列進行前向傳播，依接受規則逐位置比較目標分佈與草稿分佈，產生每個位置的接受／拒絕標籤，並記錄首次拒絕位置。

**步驟三：加入驗證頭與自適應權重**  
在草稿模型頂端新增輕量級二元分類器作為驗證頭，輸入為草稿隱藏狀態，輸出為各位置接受機率。同時將固定逐位置加權替換為驗證自適應加權：首次拒絕位置之前維持完整權重，之後依預設衰減函數重新錨定並遞減。

**步驟四：訓練草稿模型**  
聯合最佳化兩項損失：重新加權的交叉熵損失（引導草稿模型生成目標模型更可能接受的詞元）與驗證頭損失（讓隱藏狀態學會預測驗證結果）。建議使用較小的驗證頭損失權重係數 β，並監控兩項損失的收斂情況。

**步驟五：驗證與部署**  
在驗證集上比較 VAT 與基線的接受長度、實際加速比與任務指標（如數學正確率、程式碼通過率）。確認無品質衰退後，將訓練好的草稿模型部署至推論服務；由於 VAT 僅修改訓練目標，無需更動推論程式碼。

**步驟六：線上監控與迭代**  
上線後持續追蹤首次拒絕位置分佈、接受長度與端到端延遲。當目標模型或資料分佈改變時，重新收集驗證標籤並微調草稿模型，避免分佈偏移導致加速效果下降。

## 潛在風險與注意事項

**訓練成本顯著增加**  
模擬驗證需要目標模型在每次訓練迭代進行前向傳播，可能使訓練時間與記憶體需求倍增。建議採用目標模型凍結、梯度檢查點、混合精度訓練，或將目標模型置於獨立推理節點以批次產生標籤。

**首次拒絕位置估計不穩定**  
在訓練初期，草稿模型品質較差，首次拒絕位置可能過早，導致多數位置權重被衰減。可考慮在訓練前幾個 epoch 使用固定加權暖機，待草稿模型具備基本能力後再切換至驗證自適應加權。

**驗證頭過擬合**  
輕量級驗證頭可能記憶訓練樣本的驗證模式，而非學到可泛化的特徵。建議加入 dropout、限制驗證頭參數量，並在驗證集上監控接受預測的 AUC 與校準度。

**分佈偏移與領域遷移**  
若推論時的查詢分佈與訓練資料差異過大，VAT 學到的驗證模式可能失效。應定期使用線上流量採樣重新訓練，並在跨領域部署前進行領域適應微調。

**與現有推論框架的相容性**  
雖然 VAT 不改變草稿架構與推論流程，但部分推論引擎對自訂損失或輔助頭的支援有限。建議在訓練前確認框架（如 vLLM、TensorRT-LLM）能否正確載入帶有驗證頭的草稿模型，並在推論時忽略該頭。

## 與其他技術的整合建議

**與 vLLM / TensorRT-LLM / TGI 等推論引擎整合**  
VAT 訓練完成的草稿模型可直接匯出為標準格式，並於支援推測解碼的推論引擎中載入。建議先確認引擎對 EAGLE-3 或 DFlash 的支援版本，再將 VAT 微調後的權重替換原有草稿權重。

**與 KV Cache 優化搭配**  
推測解碼的效益高度依賴 KV Cache 管理。可將 VAT 與PagedAttention、連續批次（continuous batching）及 KV Cache 量化結合，進一步提升高併發場景下的吞吐量。

**與模型量化技術結合**  
若目標模型已進行 INT8 / INT4 量化，訓練時仍建議使用全精度目標模型產生驗證標籤，以確保標籤品質；推論時則可維持量化目標模型與 VAT 草稿模型，達到延遲與記憶體的雙重優化。

**與推論服務編排層整合**  
在 API 閘道或負載平衡層中，可依請求優先級動態調整草稿長度與接受閾值。VAT 提升的平均接受長度可作為設定草稿長度的依據，並與投機式批次（speculative batching）策略協同運作。

**與持續學習 / RLHF 管線結合**  
當目標模型經過 RLHF 或持續微調後，草稿模型應同步使用 VAT 重新訓練。可將 VAT 納入模型釋出流程的標準步驟，確保草稿模型始終對齊最新目標模型的驗證行為。

## 給不同背景讀者的閱讀建議

**給初學者**  
建議先理解「推測解碼」的基本概念：一個小模型（草稿模型）先快速猜測接下來的詞元，再由大模型（目標模型）一次檢查這些猜測對不對。本文提出的 VAT 則是讓小模型在訓練時就學會「大模型會接受哪些猜測」，並把學習重點放在首次被拒絕之前的詞元。閱讀時可聚焦圖一與實驗結果，暫時略過數學推導。

**給 AI 工程師**  
本文提供了一個可直接套用的訓練目標修改方案：新增一個輕量二元分類頭，並將固定位置權重改為依首次拒絕位置自適應衰減。建議重點閱讀方法章節的實作細節，評估是否能整合進現有的 EAGLE-3 或 DFlash 訓練管線，並留意訓練時目標模型前向傳播所帶來的記憶體與速度開銷。

**給研究人員**  
VAT 的核心貢獻在於將推測解碼的「驗證動態」明確納入草稿模型訓練目標，彌補了傳統詞元級模仿與推論時序驗證之間的錯位。建議深入分析驗證頭損失與自適應加權的交互作用，並思考是否能延伸至其他推測解碼變體（如樹狀草稿、自適應草稿長度）或與強化學習結合。

**給產品經理**  
VAT 是一個「僅修改訓練、不更動推論」的即插即用框架，能在不影響輸出品質與服務架構的前提下提升推論速度。建議關注實驗中不同模型與任務的加速數據，評估導入後對延遲敏感產品（如即時對話、程式碼輔助）的使用者體驗與雲端成本效益，並規劃與工程團隊的試點驗證時程。
