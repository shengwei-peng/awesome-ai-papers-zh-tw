## ⚡ TL;DR

擴散模型生成難編輯點陣圖，程式碼生成又缺美學與複雜素材能力。
提出可編輯視覺設計範式，由VLM擔任創意大腦、圖像模型擔任視覺模擬器協作。
產出可獨立編輯圖層與真實文字的海報與資訊圖表，兼顧美感與生產級可編輯性。

## 摘要翻譯

儘管 GPT-Image-2 與 Nano-Banana 等擴散基礎模型（diffusion base models）展現出卓越的視覺表現力，其端到端生成（end-to-end generation）本質上會產生帶有容易出錯文字（error-prone text）的扁平化點陣圖（flattened bitmaps），因而無法進行分層後製編輯（layer-wise post-editing）。相對地，透過編碼智慧體（Coding Agent）進行的基於程式碼的視覺生成（code-based visual generation），雖能提供精確的版面配置控制（layout control）與解耦圖層（decoupled layers），但仍受限於缺乏全域美學直覺（global aesthetic intuition），以及難以用程式碼實現複雜視覺素材（visual assets）。

為解決上述問題，我們提出可編輯視覺設計（Editable Visual Design），這是一種由編碼智慧體（Coding Agent）驅動的新範式。我們將視覺語言模型（Vision-Language Model, VLM）指定為負責需求理解（requirement comprehension）、任務規劃（task planning）與美學判斷（aesthetic judgment）的「創意大腦（creative brain）」，同時將圖像生成模型（image generation model）用作隨選的「視覺世界模擬器（visual world simulator）」，以合成獨立的視覺素材（isolated assets）。在「先想像，再行動（imagine first, then act）」的閉環工作流程（closed-loop workflow）下，該智慧體生成獨立素材、撰寫原生 HTML/CSS（native HTML/CSS），並根據視覺渲染回饋（visual rendering feedback）迭代地細化設計（iterative refinement）。

此外，Agent Design Replay 能忠實重現近似專業人類設計師（professional human designers）的創意與推理軌跡（creative and reasoning trajectory）。最終，本系統可交付具備解耦圖層與真實文字（real text，可編輯文字）的可編輯成品（editable artifacts），讓使用者能夠在圖形使用者介面（graphical user interface）上進行直覺的滑鼠拖曳（mouse dragging）與版面調整（layout adjustments）。在海報（posters）、資訊圖表（infographics）及其他情境上的驗證顯示，此範式同時成功達成了精緻的美學與生產級可編輯性（production-grade editability）。

### 核心貢獻（3～5點）
- 提出「可編輯視覺設計（Editable Visual Design）」新範式，結合擴散基礎模型的視覺表現力與編碼智慧體的結構化輸出能力，同時兼顧精緻美學與生產級可編輯性。
- 明確分工視覺語言模型（VLM）作為「創意大腦」負責需求理解、任務規劃與美學判斷，圖像生成模型作為「視覺世界模擬器」合成獨立視覺素材，再以編碼智慧體整合為原生 HTML/CSS。
- 建立「先想像，再行動」的閉環工作流程，透過視覺渲染回饋迭代地細化設計，提升最終成品的視覺品質與結構正確性。
- 提出 Agent Design Replay 機制，可忠實重現近似專業人類設計師的創意與推理軌跡，增強設計過程的可解釋性與可複現性。
- 產出具備解耦圖層與真實可編輯文字的可編輯成品，支援使用者在圖形使用者介面上以滑鼠拖曳等方式直覺調整版面。

### 適合對象
本論文適合對視覺人工智慧、生成式模型、人機互動與自動化設計系統有興趣的研究者與工程師閱讀；特別是關注如何結合大型語言模型（LLM）／視覺語言模型（VLM）與圖像生成模型、以程式碼為媒介實現可編輯視覺內容生成的讀者。此外，從事海報、資訊圖表、網頁視覺設計等應用的專業設計師與產品開發者，也能從中獲得關於生產級可編輯生成系統的實務啟發。

## 深度分析

#### 方法論解析

本文提出的 **Editable Visual Design（可編輯視覺設計）** 是一個以 **Coding Agent（編碼智慧體）** 為核心驅動的設計範式，其本質是將「創意」與「工程」解耦後再重新協作。整體架構可視為一個雙腦系統：

- **Creative Brain（創意大腦）**：由 **VLM（視覺語言模型）** 擔任，負責 **requirement comprehension（需求理解）**、**task planning（任務規劃）**、版面決策、風格判斷與結果的 **aesthetic judgment（美學判斷）**。在文中實作裡，此角色對應的是由 **GPT-5.6 Sol** 驅動的 Codex。
- **Visual World Simulator（視覺世界模擬器）**：由 **image generation model（圖像生成模型）** 擔任，作為隨需呼叫的視覺素材產生器，負責將抽象概念轉為具體影像。文中使用 **GPT Image 2**。

整個流程遵循 **「imagine first, then act（先想像，再行動）」** 的 **closed-loop workflow（閉環工作流程）**，可細分為五個階段：

1. **Understanding & Design Planning（理解與設計規劃）**  
   Agent 先解析使用者提示，決定內容、尺寸、載體形式與視覺調性。接著呼叫圖像模型產生一張 **imagined visual（想像圖）**，這不是結構草圖，而是一張接近最終成品的參考圖。此步驟的關鍵在於：設計計畫只有在「有東西可看」之後才算真正定案；同時這也是使用者介入成本最低的一點，可在尚未產生任何程式碼前調整方向。

2. **Visual Simulation（視覺模擬）**  
   VLM 對想像圖進行視覺解析，萃取 **color tone（色調）**、**composition（構圖）** 分布與整體 **style（風格）**，將這些高階美學先驗轉化為後續編碼可使用的結構化資訊。

3. **Structural Coding & Generation（結構化編碼與生成）**  
   Agent 根據規劃與視覺參考，產生 **isolated assets（獨立素材）**，並撰寫 **native HTML/CSS（原生 HTML/CSS）** 與 **SVG（可縮放向量圖形）**。這裡強調「原生」是為了確保最終成品具備乾淨的 **DOM tree（DOM 樹狀結構）** 與可編輯的圖層，而非被壓平成點陣圖。

4. **Verification & Visual Self-Healing（驗證與視覺自我修復）**  
   系統對產出的程式碼進行 **deterministic checks（確定性檢查）**，並根據 **visual rendering feedback（視覺渲染回饋）** 進行多輪 **iterative refinement（迭代細化）**。這個 render-and-reflect 機制讓 agent 能發現排版錯位、色彩不一致、素材衝突等問題並自動修復。

5. **Editable Design Delivery（可編輯設計交付）**  
   最終輸出為 **editable artifacts（可編輯成品）**：文字、素材與版面 **layers（圖層）** 完全 **decoupled（解耦）**，使用者可在 **graphical user interface（圖形使用者介面）** 上進行 **mouse dragging（滑鼠拖曳）**、文字編輯與 **layout adjustments（版面調整）**。

此外，**Agent Design Replay** 記錄了從意圖規劃、素材生成、程式碼撰寫到反思修復的完整 **creative and reasoning trajectory（創意與推理軌跡）**，讓設計過程變得可視、可追溯、可重現，類似專業人類設計師的工作流。

#### 實驗數據解讀

從目前提供的全文脈絡來看，本文的驗證主要採用**質性案例展示**，涵蓋 **posters（海報）**、**infographics（資訊圖表）**、長文排版與活動海報等典型場景。作者主張該範式能同時達成 refined aesthetics（精緻美學）與 production-grade editability（生產級可編輯性）。

然而，就方法論評估的嚴謹度而言，目前可見的內容存在以下缺口：

- **缺乏量化指標**：未見諸如文字正確率（OCR accuracy）、視覺品質分數（如 FID、CLIP score）、版面對齊誤差、編輯操作成功率、生成時間或使用者滿意度等量性數據。
- **無對照實驗**：未與純 **diffusion models（擴散模型）** 端到端生成、純 **code-based visual generation（基於程式碼的視覺生成）** 或其他多 agent 設計系統進行系統性比較。
- **無使用者研究**：雖然強調「直覺式滑鼠拖曳編輯」，但未提供使用者操作效率、學習曲線或主觀評分的實證。
- **案例選擇可能具挑選性**：展示的案例多為旅遊海報、資訊圖表等結構相對明確的設計，對於更複雜的商業視覺（如品牌識別、動態排版、多語言混排）的泛化能力尚待驗證。

因此，現階段可將其視為一個**概念驗證與範式提案**：它成功地展示了「程式碼 + 擴散模型」協作的可能性，但在學術上仍需更嚴格的實驗設計來支撐「生產級」這一宣稱。

#### 與現有研究的比較

現有視覺生成研究大致可歸為兩條「偏側化」路線，本文試圖在兩者之間建立橋樑：

| 路線 | 代表方法 | 優勢 | 劣勢 | 本文的改進 |
|---|---|---|---|---|
| **Left-brain（左腦）純程式碼生成** | GPT-5.6 Sol、Claude Fable 5、Kimi K3 等 **code LLMs（程式碼大型語言模型）** | 具備 **engineering logic（工程邏輯）**、**clean layers（乾淨圖層）**、**interactive text（可互動文字）**、易於後續修改 | 缺乏 **two-dimensional spatial sense（二維空間感）** 與 **visual intuition（視覺直覺）**；難以生成複雜 **visual assets（視覺素材）**，常流於「大標題 + 卡片 + 圓角陰影」的模板化結果 | 引入 VLM 作為創意大腦，並以圖像模型補強素材生成，突破美學與資產瓶頸 |
| **Right-brain（右腦）純擴散生成** | **diffusion base models（擴散基礎模型）** 如 GPT-Image-2、Nano-Banana | 具備強大 **artistic priors（藝術先驗）**，可產生高品質 **composition（構圖）**、**lighting（光影）**、**texture（質感）** | 輸出為 **flattened bitmaps（扁平化點陣圖）**，文字 **error-prone（容易出錯）**，元素 **deeply entangled（深度糾纏）**，無法進行 **layer-wise post-editing（分層後製編輯）** | 以原生 HTML/CSS/SVG 作為交付格式，確保 **real text（真實文字）** 與 **decoupled layers（解耦圖層）** |

相較於既有研究，本文的主要貢獻在於：

1. **雙腦協作架構**：明確區分「創意大腦」與「視覺模擬器」，讓兩種模型各司其職，避免讓單一模型同時承擔美學想像與工程實作。
2. **Imagine-first 閉環**：先建立視覺參考再進行結構化編碼，降低純程式碼生成的美學漂移。
3. **可編輯交付物**：不同於擴散模型的點陣圖輸出，最終成品是可在 GUI 中直接操作的結構化文件。
4. **Agent Design Replay**：提供可解釋的設計軌跡，對於設計審查、教育與協作具有潛在價值。

但本文也存在明顯限制：

- **高度依賴專有模型**：核心能力來自 GPT-5.6 Sol 與 GPT Image 2，成本、延遲與可取得性都是實務門檻。
- **未處理複雜互動與動態設計**：目前聚焦於靜態海報與資訊圖表，對於動態網頁、互動式儀表板或動畫的支援未明。
- **渲染一致性風險**：原生 HTML/CSS 在不同瀏覽器與匯出格式（PNG/PDF/PPTX）間可能出現排版差異，文中未詳述如何確保跨平台一致性。
- **素材與版面整合挑戰**：雖然素材獨立生成，但如何確保多張生成圖像在風格、透視、光影上完全一致，仍是未解難題。

#### 可重現性評估

就 **reproducibility（可重現性）** 而言，目前提供的內容並不理想：

- **無開源資源**：文中未提及原始碼、資料集、模型權重或系統提示詞（system prompts）是否公開。
- **依賴封閉 API**：核心組件 GPT-5.6 Sol 與 GPT Image 2 均為商業模型，即使釋出程式碼，其他研究者仍需取得相應 API 權限才能復現。
- **實作細節不足**：諸如「視覺解析」如何將想像圖轉為結構化設計參數、「確定性檢查」包含哪些規則、迭代修復的停止條件、以及 Agent Design Replay 的儲存格式等關鍵細節，均未在摘要與引言中揭露。
- **無標準化評測協議**：缺乏公開的測試提示集、評分標準或基準模型，使得外部難以驗證其宣稱。

簡言之，本文目前處於「範式展示」階段，若要達到學術與工業界普遍可重現的水準，至少需要釋出：（1）系統實作與提示詞模板；（2）涵蓋多種設計類別的標準化測試集；（3）客觀評估指標與對照實驗腳本。

#### 未來研究方向

基於上述分析，後續研究可朝以下方向延伸：

1. **建立量化評估基準**  
   設計針對可編輯視覺設計的專屬指標，例如文字正確率、圖層分離度、視覺風格一致性、版面對齊誤差、使用者編輯效率等，並與純擴散模型、純程式碼生成方法進行系統比較。

2. **開源化與模型替代**  
   降低對 GPT-5.6 Sol / GPT Image 2 等專有模型的依賴，探索以開源 VLM（如 Qwen-VL、LLaVA）與開源擴散模型（如 Stable Diffusion、Flux）實現同等能力，並釋出完整程式碼與資料集。

3. **多 Agent 專業分工**  
   將單一 Coding Agent 擴展為多 agent 協作系統，例如分設版面設計師、字體排版師、插畫師、審查員等角色，以提升複雜設計的品質與可解釋性。

4. **跨格式與跨平台交付**  
   除了 HTML/CSS/SVG，進一步支援 **PPTX**、**PDF**、Figma、Adobe 等專業設計格式，並確保跨瀏覽器、跨裝置的渲染一致性。

5. **強化驗證與自我修復機制**  
   引入更嚴謹的視覺檢查，包括 OCR 驗證、色彩對比度與無障礙規範檢查、版面重疊偵測、以及基於渲染差異的自動修復。

6. **人機協作與即時編輯**  
   將 Agent Design Replay 與即時 GUI 編輯結合，讓使用者在任何階段介入並引導 agent 調整方向，實現真正的人機共創。

7. **風格一致性與資產協調**  
   研究如何讓多個獨立生成的視覺素材在風格、色調、透視與細節層次上保持一致，避免「拼貼感」。

8. **設計知識學習與風格遷移**  
   讓 agent 從大量專業設計作品中學習排版規則與品牌風格，實現針對特定客戶或領域的風格遷移與設計自動化。

9. **語義化圖層與智慧群組**  
   不僅產生可編輯圖層，更進一步賦予圖層語義標籤（如「標題」、「主視覺」、「行動呼籲按鈕」），並支援智慧群組與自動版面重排。

10. **動態與互動設計延伸**  
    將此範式擴展至動態海報、網頁互動元件、資料視覺化儀表板與微動畫，探索程式碼生成在動態視覺設計中的潛力。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**
A：本文指出現有端到端擴散基礎模型（diffusion base models）雖然能產生高品質的視覺效果，但輸出的是扁平化點陣圖，文字容易出錯且元素深度糾纏，無法進行分層後製編輯。另一方面，基於程式碼的視覺生成雖然具備工程結構與解耦圖層，卻缺乏全域美學直覺，也難以用純程式碼繪製複雜視覺素材。因此，論文提出「可編輯視覺設計（Editable Visual Design）」範式，試圖同時突破美學瓶頸與不可編輯的結構限制。

**Q2：為什麼純粹的擴散模型不適合做可編輯設計？**
A：擴散模型生成的是光柵圖像，其中的文字、圖形與背景元素被壓縮在同一張點陣圖中，無法分離成獨立的可編輯圖層。這導致文字經常出現拼寫錯誤與扭曲，也無法進行局部修改或下游交付。對於需要文字正確性、局部編輯與工程交付的場景，這種結構性缺陷使其難以成為真正的生產級設計產出。

**Q3：現有的編碼智慧體（Coding Agent）在視覺設計上又有什麼弱點？**
A：現有程式碼大型語言模型擅長語法、DOM 樹狀結構與 Flexbox 版面配置，但本質上仍是一維符號序列，缺乏二維空間感與視覺直覺。因此直接生成版面程式碼往往只能做出「大標題、卡片、圓角陰影」等高度模板化的設計，難以從「結構正確」跨越到「視覺精緻」。此外，要求模型用純 HTML、SVG 或 CSS 手繪電影感背景、3D 主視覺或精緻插畫，成本高昂且結果僵硬，常只能用漸層、色塊或表情符號充當佔位符。

**Q4：論文提出的核心方法是什麼？**
A：核心方法是「可編輯視覺設計（Editable Visual Design）」，由一個編碼智慧體（Coding Agent）驅動，並將視覺語言模型（VLM）定位為「創意大腦」，負責需求理解、設計規劃與美學判斷。圖像生成模型則作為隨需呼叫的「視覺世界模擬器（visual world simulator）」，把抽象想法轉換為具體視覺效果。兩者協作完成從需求到可編輯程式碼成品的完整流程。

**Q5：這個方法最關鍵的創新點是什麼？**
A：最關鍵的創新在於「先想像，再行動（imagine first, then act）」的閉環工作流程：智慧體先呼叫模擬器生成一張想像視覺，建立構圖、光影與色調的先驗，再獨立進行素材生成與原生 HTML/CSS 撰寫。此外，論文提出 Agent Design Replay，能完整重現從意圖規劃、素材生成到程式碼反思與修復的創意與推理軌跡。這讓設計過程變得可視、可追溯且可重現，類似專業人類設計師的工作軌跡。

**Q6：系統在設計上做了哪些重要選擇？**
A：系統選擇以原生 HTML/CSS/SVG 作為輸出格式，確保文字是真實可編輯文字、圖層是解耦的，並支援後續匯出為 PPTX、PDF、PNG 等多種格式。視覺素材採用獨立生成而非內嵌於點陣圖，讓使用者可以單獨選取、拖曳與調整。想像視覺被納入設計規劃的一部分，讓使用者在撰寫任何程式碼之前就能以最低成本介入並修正方向。

**Q7：論文在哪些情境下驗證了這個範式？**
A：論文在多個典型設計案例中進行驗證，包括行銷素材、資訊圖表、長文排版與活動海報等。這些場景同時考驗視覺美感、資訊層次與後續可編輯性。驗證方式結合確定性檢查與視覺審查，確認最終成品在結構與外觀上都達到可用水準。

**Q8：這個系統達成了什麼關鍵成果？**
A：系統成功產出具有解耦圖層與真實文字的可編輯成品，使用者可以在圖形使用者介面中以滑鼠拖曳並調整版面。相較於純擴散模型，它保留了生產級編輯能力；相較於純程式碼生成，它達到了更精緻的全域美學與更豐富的視覺素材。整體而言，該範式同時實現了高品質視覺與完整可編輯性。

**Q9：如果移除系統中的某些元件，預期會出現什麼問題？**
A：若移除視覺模擬階段，VLM 缺乏構圖與色調先驗，生成的版面容易流於模板化且視覺層次薄弱。若移除迭代式的渲染與反思修復，程式碼中的對齊錯誤、素材比例或文字渲染問題將難以被自動修正。若改為讓模型直接手繪所有複雜素材而不使用獨立素材生成，結果會變得僵硬且像未完成草稿，無法達到生產級視覺品質。

**Q10：這項技術最適合應用在哪些實務場景？**
A：最適合需要文字正確性與後續編輯的設計場景，例如活動海報、旅遊導覽圖、產品行銷素材與資訊圖表。這些應用通常包含大量真實文字、圖示與插畫，且經常需要根據客戶回饋進行局部調整。由於輸出是原生程式碼與獨立素材，設計師或使用者可以直接在圖形介面中修改，而不用重新生成整張圖。

**Q11：從產品化角度來看，這個系統有哪些重要特性？**
A：系統提供可編輯畫布（Editable Canvas），讓使用者能選取、拖曳與調整各個圖層，並支援匯出為 HTML/CSS/SVG、PPTX、PDF 與 PNG 等格式。Agent Design Replay 則讓整個設計決策與修改過程透明可見，便於審查、協作與學習。此外，由於文字是真實文字而非圖像中的像素，產品能自然支援搜尋、複製與無障礙輔助功能。

**Q12：這項研究對視覺生成領域可能帶來什麼影響？**
A：它橋接了「左腦」程式碼生成與「右腦」擴散視覺生成這兩條原本偏頗的路徑，提出了一種兼顧工程邏輯與藝術直覺的協作範式。這使得 AI 設計不再只是生成靜態圖片，而是能產出可交付、可編輯的工程級設計成品。長遠來看，這有助於建立更可追溯、可協作且符合專業設計流程的自動化視覺設計系統。

**Q13：作者承認這個方法有哪些限制？**
A：系統的表現高度依賴底層 VLM 與圖像生成模型的能力，若基礎模型對特定風格或語言理解不足，最終成品品質會受限。對於極度複雜的 3D 主視覺、電影感背景或高度客製化的精緻插畫，即使使用模擬器也可能仍有挑戰。此外，閉環迭代與多輪反思會增加生成時間與計算成本，對於需要即時輸出的應用仍需最佳化。

**Q14：在什麼情況下系統可能會失敗？**
A：當使用者提示過於模糊或風格極為小眾時，視覺模擬器可能產生與預期不符的參考圖，導致後續程式碼方向偏離。若生成的獨立素材在解析度、比例或透明背景上與版面不匹配，即使經過反思修復也可能殘留對齊問題。另外，若 VLM 對某些語言的字型或排版慣例掌握不足，文字層仍可能出現間距或換行錯誤。

**Q15：未來可以朝哪些方向繼續發展？**
A：未來可整合更強大的世界模型或視覺模擬器，以提升複雜素材與動態效果的生成能力。也可以加入更緊密的人機協作機制，讓使用者在設計過程中即時給予風格與版面回饋。此外，支援多頁文件、企業設計系統規範、品牌一致性檢查以及即時協作編輯，都是值得探索的延伸方向。

## 實務應用指南

## 適用場景

**1. 行銷素材快速產出與迭代**
電商、品牌與廣告代理商可利用此範式生成活動海報、社群圖文與產品介紹頁。由於成品具備解耦圖層與真實文字，行銷人員可在圖形使用者介面中直接拖曳調整版面、替換文案與商品圖，無需重新生成整張圖像。

**2. 新聞與長文資訊圖表製作**
媒體與內容團隊可將長篇報導、研究數據或旅遊攻略轉換為結構化資訊圖表。編碼智慧體負責規劃視覺層級與資訊架構，視覺世界模擬器則產出插畫、圖示與背景等獨立素材，最終交付可編輯成品以利編輯室後續校稿與更新。

**3. 活動與會議視覺設計**
企業活動、研討會與展覽主視覺常需多次修改時間、地點與講者資訊。透過原生 HTML/CSS/SVG 建構的成品，主辦單位能精確調整文字內容與版面配置，並輸出為 PDF、PNG 或 PPTX 等多種格式。

**4. 教育與簡報視覺化**
教師與簡報設計者可將課程大綱、流程圖或數據概念轉為視覺化教材。系統的「先想像，再行動」閉環工作流程有助於在編碼前先確立整體構圖、色彩與風格，降低反覆試錯的成本。

**5. 設計系統與模板資產庫建置**
設計團隊可將此範式用於批量生成風格一致、結構清晰的設計模板。Agent Design Replay 記錄了從需求理解到程式碼修復的完整創意與推理軌跡，便於團隊審查、複用與建立內部設計規範。

## 實作前置條件

**資料準備**
- 明確的設計需求文件，包含目標尺寸、必要文案、品牌色彩、字體規範與參考風格。
- 高品質的參考圖像或風格範例，用於引導視覺世界模擬器產出符合預期的獨立素材。
- 結構化的內容資料，例如行程表、數據表格、產品規格等，便於編碼智慧體進行版面配置與資訊層級規劃。

**運算資源**
- 可呼叫的視覺語言模型（VLM）API，作為創意大腦負責需求理解、任務規劃與美學判斷。
- 可呼叫的圖像生成模型 API，作為視覺世界模擬器，用於產出想像視覺與獨立素材。
- 具備網頁渲染能力的執行環境，用於驗證視覺渲染回饋並執行迭代細化。
- 足夠的 API 呼叫預算，因為閉環工作流程涉及多輪生成、渲染與反思修復。

**技能需求**
- 熟悉 HTML、CSS、SVG 與基礎 JavaScript，能夠審查與調整編碼智慧體產出的程式碼。
- 具備視覺設計基礎，能夠評估構圖、色彩、字體排版與整體美學品質。
- 了解 API 整合與自動化流程設計，能夠將各模組串接為可重複執行的產品級管線。

## 實作步驟建議

**步驟一：需求解析與設計規劃**
將使用者需求轉化為結構化設計簡報，明確內容、尺寸、風格與交付格式。由視覺語言模型擔任創意大腦，產出初步的版面策略、色彩計畫與字體層級。

**步驟二：生成想像視覺**
呼叫圖像生成模型產出「想像視覺」，作為整體美學參考。此階段應著重構圖、光影、質感與色彩調性，而非精確結構。這是使用者介入與修正方向成本最低的時機。

**步驟三：視覺解析與素材生成**
視覺語言模型解析想像視覺，提取色調、構圖分佈與整體風格，並規劃需要哪些獨立素材。接著呼叫視覺世界模擬器分批產出背景、插畫、圖示、主視覺等獨立素材。

**步驟四：原生 HTML/CSS/SVG 建構**
編碼智慧體根據設計規劃與素材，撰寫原生 HTML/CSS/SVG 程式碼。此時應確保文字、素材與版面圖層解耦，避免將文字轉為圖像，以維持後續可編輯性。

**步驟五：渲染驗證與視覺自癒**
將程式碼渲染為實際畫面，與想像視覺進行比對。針對版面錯位、色彩偏差、素材品質不足等問題，進行多輪 render-and-reflect 修復，直到通過確定性檢查與視覺審查。

**步驟六：交付可編輯成品**
輸出具備解耦圖層與真實文字的可編輯成品，並提供圖形使用者介面讓使用者進行滑鼠拖曳與版面調整。同時記錄 Agent Design Replay，完整保存從提示到成品的創意與推理軌跡。

**步驟七：產品化整合**
將上述流程封裝為可重複執行的服務，整合版本控制、審核機制與多格式匯出功能，並建立使用者回饋迴路以持續改善生成品質。

## 潛在風險與注意事項

**風險一：視覺語言模型缺乏二維空間感**
編碼智慧體雖擅長語法與 DOM 樹狀結構，但容易產出「大標題、卡片、圓角陰影」等模板化設計。建議透過想像視覺提供強烈美學先驗，並在渲染驗證階段加入明確的構圖與風格評分標準。

**風險二：圖像生成模型產出不可編輯的點陣圖**
若過度依賴端到端生成，成品將變回扁平化點陣圖，喪失分層後製編輯能力。應嚴格區分「想像視覺」與「獨立素材」的角色，並確保最終成品以原生 HTML/CSS/SVG 為主體。

**風險三：複雜素材以程式碼繪製成本過高**
電影感背景、3D 主視覺或精緻插畫若純以程式碼繪製，結果容易顯得僵硬。應善用視覺世界模擬器產出這類素材，再以程式碼進行精確定位與排版。

**風險四：文字正確性與可編輯性流失**
需確保所有文案以真實文字形式存在於 HTML 中，而非嵌入圖像。可加入文字正確性的確定性檢查，避免出現拼寫錯誤與扭曲文字。

**風險五：多輪迭代導致成本與延遲上升**
閉環工作流程涉及多次 API 呼叫與渲染驗證，可能推高運算成本與回應時間。建議設定迭代次數上限、快取常用素材，並在關鍵節點引入人工審核閘門。

## 與其他技術的整合建議

**與設計工具整合**
可將可編輯成品匯出至 Figma、Sketch 或 Adobe Express 等設計工具，讓專業設計師在既有工作流程中進行精修。透過 SVG 與 HTML 轉換外掛，可實現無縫銜接。

**與內容管理系統（CMS）整合**
將編碼智慧體接入企業 CMS，讓行銷人員直接從資料庫拉取產品資訊、活動文案與品牌素材，自動生成對應的視覺成品，並回寫至 CMS 供發布使用。

**與自動化測試與 CI/CD 整合**
在渲染驗證階段引入視覺回歸測試、無障礙檢查與跨裝置預覽，確保每次生成的成品符合生產級設計標準。可將整個流程納入 CI/CD 管線，實現設計資產的自動化產出與品質控管。

**與向量資料庫與檢索增強生成（RAG）整合**
建立品牌設計規範、過往優秀案例與素材庫的向量索引，讓視覺語言模型在規劃階段能檢索相關參考，提升風格一致性與設計品質。

**與多模態評估模型整合**
引入獨立的多模態評估模型，對想像視覺、獨立素材與最終成品進行美學判斷與結構檢查，減少對單一模型自我評估的依賴。

## 給不同背景讀者的閱讀建議

**給初學者**
本文提出的可編輯視覺設計範式，核心概念是讓 AI 像專業設計師一樣「先想像畫面，再動手製作」，並且最終產出可以像簡報或網頁一樣被修改的成品。建議從「先想像，再行動」的閉環工作流程開始理解，並觀察圖 2 的整體流程圖，不必急著深入程式碼細節，重點在於認識這種結合視覺生成與程式碼建構的新可能性。

**給 AI 工程師**
本論文展示了一個值得參考的系統架構：以視覺語言模型作為創意大腦，以圖像生成模型作為視覺世界模擬器，並透過原生 HTML/CSS/SVG 實現可編輯性。建議關注其多輪 render-and-reflect 修復機制、Agent Design Replay 的軌跡記錄方式，以及如何將擴散模型的美學先驗與程式碼的工程邏輯有效結合，這對於建構生產級視覺生成系統極具啟發。

**給研究人員**
本文指出的兩大瓶頸——程式碼生成缺乏全域美學直覺、擴散模型缺乏工程邏輯與可編輯性——是視覺生成領域的重要研究問題。建議深入分析其協作機制設計、視覺模擬與結構編碼的介面定義，以及可編輯成品的評估指標。未來可延伸的方向包括更細緻的版面規劃演算法、多模態一致性驗證，以及人機協作的設計流程建模。

**給產品經理**
這項技術適合需要「高品質視覺」與「可後續編輯」並存的應用場景，例如行銷素材、資訊圖表與活動視覺。建議評估導入時的 API 成本、迭代延遲與人工審核節點，並思考如何與現有設計工具、CMS 與品牌規範整合。關鍵成功因素在於讓非技術使用者也能透過圖形使用者介面直覺地調整成品，而非僅僅獲得一張無法修改的圖片。
