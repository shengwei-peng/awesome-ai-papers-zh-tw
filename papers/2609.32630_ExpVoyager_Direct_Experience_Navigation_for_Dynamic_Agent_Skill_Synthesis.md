# ExpVoyager：以直接經驗導航（Direct Experience Navigation）實現動態智能體技能合成（Dynamic Agent Skill Synthesis）

**原文標題：** ExpVoyager: Direct Experience Navigation for Dynamic Agent Skill Synthesis

**發布日期：** 2026-09-26

## ⚡ TL;DR

現有方法預先將經驗抽象為固定技能，易遺失未來關鍵知識並保留無關細節。
ExpVoyager 將技能合成轉為原始經驗的動態導航，藉多視角介面與導航狀態隨選提煉程序知識。
實驗顯示 ExpVoyager 持續提升下游任務表現，隨經驗空間擴大而進步，並能與現有技能協同運作。

## 摘要翻譯

LLM 智能體（LLM agents）從經驗中學習（learning from experience），已成為發展能持續學習並擴展能力的自我演化智能體（self-evolving agents）的關鍵典範。在此典範中，智能體技能合成（agent skill synthesis）被視為一項具前景的解決方案，可將累積經驗轉化為可重複使用的程序性知識（reusable procedural knowledge），並作為配套系統（harness system）的重要層次，於執行階段（runtime）為智能體提供所需知識。儘管潛力顯著，現有方法大多在下游需求（downstream demands）尚未明確之前，便將過往經驗抽象為固定程序性知識（fixed procedural knowledge），此舉可能導致日後變得關鍵的知識被捨棄，同時卻保留了與未來任務無關的實例特定細節（instance-specific details）。在本文中，我們將智能體技能合成重新定義為一個在過往經驗上的動態導航問題（dynamic navigation problem），使智能體得以針對當前任務（current task）主動隨選（on demand）探索累積軌跡（accumulated trajectories），並以具針對性且細粒度的方式存取經驗知識（experience knowledge）。為此，我們提出 ExpVoyager，一個新穎框架，其中的技能策展者（skill curator）會在不同視角與解析度（views and resolutions）下導航原始經驗（raw experience），持續從觀察中辨識出可重複使用的程序性知識，同時追蹤剩餘的知識需求（knowledge needs），以指引下一步的導航方向。大量實驗驗證了 ExpVoyager 的有效性與泛用性，顯示其在下游任務表現（downstream task performance）上持續提升、隨經驗空間（experience space）擴展而不斷增益，並能在高效率經驗存取（efficient experience access）的前提下於實務上與現有技能相容。

### 核心貢獻（3～5點）
- 提出直接經驗導航（Direct Experience Navigation）的新視角，將智能體技能合成重新定義為在過往經驗上的動態導航問題（dynamic navigation problem），使智能體能主動隨選（on demand）探索累積軌跡（accumulated trajectories）。
- 設計 ExpVoyager 框架，透過技能策展者（skill curator）在不同視角與解析度（views and resolutions）下導航原始經驗（raw experience），持續辨識可重複使用的程序性知識（reusable procedural knowledge）。
- 引入知識需求（knowledge needs）追蹤機制，動態指引導航方向，避免預先抽象造成的關鍵知識遺失與無關細節保留。
- 在下游任務表現（downstream task performance）上展現持續提升，並隨經驗空間（experience space）擴展而不斷增益，同時具備與現有技能實務相容的特性。

### 適合對象
適合對 LLM 智能體（LLM agents）、自我演化智能體（self-evolving agents）、智能體技能合成（agent skill synthesis）及長程多步驟任務（long-horizon agents / multi-step tasks）有興趣的研究者與工程師，特別是關注如何從過往執行經驗（past execution experience）中動態提煉可重複使用程序性知識、設計配套系統（harness system）以支援執行階段（runtime）知識供給的讀者。

## 深度分析

#### 方法論解析

ExpVoyager（直接經驗導航框架）將傳統的 agent skill synthesis（智能體技能合成）重新定義為一個 dynamic navigation problem（動態導航問題）：在面對當前任務時，由一個 skill curator（技能策展者）主動探索 accumulated trajectories（累積軌跡），從 raw experience（原始經驗）中隨選提煉可重複使用的程序性知識（reusable procedural knowledge），而非事先把過往經驗壓縮成 fixed procedural knowledge（固定程序性知識）後再供下游使用。

整體架構可拆解為三個核心元件：

1. **Navigable Interface（可導航介面）**  
   該介面讓 curator 能夠以多種 views and resolutions（視角與解析度）存取經驗。例如，curator 可以只檢視某個局部決策片段（高解析度、局部視角），也可以拉遠到整條 trajectory（軌跡）的執行模式（低解析度、全域視角）。這種設計源於一個直覺：對當前任務有用的 procedural knowledge（程序性知識）往往散落在軌跡的不同層面——有時是整體策略，有時是某個關鍵步驟的局部上下文。透過在介面中選擇 navigation actions（導航行動）並指定適當的 action arguments（動作參數），curator 能決定「要看哪裡」以及「要看多細」。

2. **Navigation State（導航狀態）**  
   這是 curator 在每一輪觀察後維護的內部狀態，負責把新取得的 observation（觀察）詮釋為兩類資訊：  
   - 已經可以 reuse（重複使用）的 procedural knowledge；  
   - 仍然不足的 knowledge needs（知識需求），用來指引下一輪該往哪裡導航。  
   這形成了一個「觀察—詮釋—再導航」的迴路，讓 experience access（經驗存取）與知識解讀持續互相引導，而不是一次性檢索後就固定下來。

3. **Frozen Executor（凍結執行者）與 Task-Specific Skill（任務特定技能）**  
   Curator 並不改變 executor 的模型權重，而是根據當前任務動態合成一段 task-specific guidance（任務特定指引），供 executor 在 runtime（執行階段）使用。這讓整個 harness system（配套系統）可以在不重新訓練基礎模型（foundation models）的情況下擴展智能體能力。

與傳統「先抽象、後使用」的範式相比，ExpVoyager 的關鍵差異在於把 skill construction（技能建構）從「離線預處理」轉為「任務時刻（task-time）的主動決策過程」。它不再依賴 similarity-based access（基於相似度的存取）去撈取 top-k trajectories（top-k 軌跡），因為這種被動檢索介面（passive retrieval interface）容易包含無關知識，也可能遺漏表面上不相關、但實際含有 localized critical cues（局部關鍵線索）的軌跡。

#### 實驗數據解讀

論文在 ALFWorld（家庭互動）、線上購物與科學推理三個 agent benchmarks（智能體基準）上進行評估，重點檢驗兩件事：(1) 對 downstream task performance（下游任務表現）的改善；(2) 在可擴展與高效率經驗存取（efficient experience access）上的通用性。

**初步分析 I：預先建構的技能遺失大量未來有用的知識**  
圖 1 比較了數種現有方法所保留的 oracle knowledge（神諭知識，即經驗中真正對未來任務有幫助的知識）比例：

- AWM：僅保留約 12.7%  
- Trace2Skill：約 31.5%  
- Rbank：約 40.9%  
- Raw Exp（原始經驗）：100%

這個結果非常直觀卻也很關鍵：即使表現最好的現有方法，也只能留住不到一半的未來可用知識。換句話說，現有方法在 skill construction 階段就因為不知道 downstream demands（下游需求）而丟棄了大量可能後來變得關鍵的知識，同時又可能保留過多 instance-specific details（實例特定細節）。這為 ExpVoyager 的動態導航提供了強烈的動機——既然預先抽象必然造成知識流失，那麼讓 curator 在任務當下按需檢視原始經驗，就能更接近 100% 的知識覆蓋。

**主要實驗結果**  
雖然完整表格未在提供的片段中出現，但摘要與引言已指出以下趨勢：

1. **一致的效能提升**：ExpVoyager 在三個領域都持續優於現有的 skill-based approaches（基於技能的方法），並在多種 curator–executor 配置下改善 base agents（基礎智能體）的表現。這說明動態導航不僅對特定模型有效，而是具有跨配置通用性。

2. **線上自我演化**：ExpVoyager 能在沒有 pre-collected experience（預先收集經驗）的情況下驅動 online self-evolution（線上自我演化）。這意味著智能體可以在執行新任務的同時累積經驗，並立即把這些經驗轉化為可重複使用的技能，形成持續學習的閉環。

3. **隨經驗空間擴大而持續進步**：當 experience space（經驗空間）變大時，ExpVoyager 相較於現有方法的領先幅度會逐漸拉開。這與傳統固定技能方法形成對比——後者在經驗增加時可能因為雜訊與過時知識而收益遞減，而 ExpVoyager 的隨選導航能夠從更多資料中精準挑選當前任務需要的部分。

4. **與現有技能的協同與預算效率**：ExpVoyager 可以與已存在的 skills（技能）協同，透過 on-demand refinement（隨選精煉）來補強既有知識；同時在有限的 experience-access budgets（經驗存取預算）下仍能有效運作，這對實際部署非常重要。

#### 與現有研究的比較

**定位**  
ExpVoyager 屬於「從經驗中學習（learning from experience）」這個大範疇，特別聚焦在 agent skill synthesis（智能體技能合成）這一層。它與近期如 AWM、Trace2Skill、Rbank 等方法同樣試圖把 task experience（任務經驗）轉換成 procedural knowledge，但採取了截然不同的時間點與互動方式。

**相較於現有方法的改進**

| 面向 | 現有方法 | ExpVoyager |
|---|---|---|
| 知識抽象時機 | 在下游需求未知前，離線抽象成固定技能 | 任務時刻隨選導航，按需提取 |
| 經驗存取方式 | 被動檢索 top-k trajectories，依賴相似度 | 主動決策過程，選擇視角與解析度 |
| 知識保留 | 遺失大量未來有用的知識（圖 1） | 直接檢視 raw experience，保留度高 |
| 雜訊控制 | 容易保留實例特定細節 | 透過 Navigation State 持續聚焦當前 knowledge needs |
| 可擴展性 | 經驗增加後收益可能遞減 | 經驗空間越大，優勢越明顯 |

**主要限制**

1. **計算與推理成本**：動態導航是迭代式的，每一輪都需要 curator 進行推理並選擇 action。雖然論文強調 efficient experience access，但與一次性檢索相比，latency（延遲）與 API 呼叫次數仍可能較高。

2. **Curator 的錯誤會放大**：如果 curator 對某段經驗的詮釋錯誤，或選擇了不適當的 view/resolution，後續導航可能偏離正軌。Navigation State 雖然有自我修正機制，但仍依賴 LLM 的推理品質。

3. **Action space 的設計依賴**：Navigable Interface 需要人工設計合理的 views 與 resolutions。對於更複雜的環境（例如多模態、連續動作空間），如何自動化或擴展這個介面仍是開放問題。

4. **可解釋性與驗證**：雖然 curator 會產生 task-specific skill，但這些技能是動態生成的，如何確保其正確性、一致性，以及與現有技能的相容性，需要更多機制來驗證。

#### 可重現性評估

根據目前提供的文本，論文並未明確給出 open-source code（開源程式碼）、datasets（資料集）或 model weights（模型權重）的下載連結。實驗主要使用公開可取得的 benchmark，例如 ALFWorld，因此資料面本身並非封閉。然而，以下幾點會影響可重現性：

- **實作細節**：Navigable Interface 的 action space、Navigation State 的更新 prompt、curator 與 executor 的模型選擇等關鍵細節，目前僅在摘要與引言中概略描述。雖然論文提到 Appendix B.4 有更詳細的實驗設定，但完整重現仍需這些細節。

- **LLM 隨機性**：由於 curator 與 executor 都仰賴 LLM，temperature、sampling 策略與模型版本會顯著影響結果。論文需要清楚說明使用的模型版本與參數。

- **Oracle skill 標註**：初步分析中使用了 generate-then-verify（生成後驗證）的方式收集 80 個 oracle skills，並人工標註 300 條 source trajectories 中的相關知識。這個標註過程若未公開，會讓其他研究者難以完全複製該分析。

- **計算資源**：動態導航涉及多輪 LLM 呼叫，重現實驗需要足夠的 API 額度或本地 GPU 資源。

總結來說，這篇論文目前處於 preprint（預印本）階段，若作者後續能釋出程式碼、prompt 模板與標註資料，將大幅提升可重現性與社群跟進的速度。

#### 未來研究方向

1. **多模態與連續環境的導航**  
   目前的經驗形式主要仍是文字軌跡。未來可將 ExpVoyager 擴展到視覺、感測器資料等多模態經驗，並應用於機器人或連續控制等更真實的 long-horizon agents（長程智能體）。

2. **學習導航策略，而非僅靠 LLM 推理**  
   目前 curator 的導航行動似乎由 LLM 根據 prompt 決策。未來可以引入 reinforcement learning（強化學習）或 imitation learning（模仿學習），讓導航策略本身從經驗中學習，進一步提升效率與準確度。

3. **與長期記憶系統的整合**  
   把 Navigation State 與更結構化的 memory system（記憶系統）結合，例如知識圖譜或向量資料庫，可以讓經驗導航在超大 experience space 中仍保持高效率。

4. **跨任務與跨領域遷移**  
   研究如何讓在某個領域學到的導航策略與技能，遷移到不同但相關的 downstream tasks，並處理領域差異與分佈轉移問題。

5. **自動化 view 與 resolution 的設計**  
   目前的 views and resolutions 可能需要人工設計。未來可探索自動發現最適合的經驗表示層級，讓框架能適應不同任務與環境。

6. **處理失敗與雜訊經驗**  
   真實經驗常包含失敗軌跡與雜訊。如何讓 curator 辨識負面範例、避免學到錯誤程序，並從失敗中提煉有用教訓，是值得深入的方向。

7. **人機協作的技能策展**  
   引入 human-in-the-loop（人類在迴路）機制，讓人類專家可以在 curator 導航過程中給予回饋，特別適用於高風險或需要專業知識的領域。

8. **理論分析與可解釋性**  
   對動態導航過程進行更嚴謹的理論分析，例如 sample complexity（樣本複雜度）或收斂保證，並提供可解釋的導航路徑，讓使用者理解技能是如何從哪些經驗中產生的。

## 論文問答

**Q1：ExpVoyager 主要想解決什麼問題？**
A：ExpVoyager 針對的是 LLM 智能體如何從累積的過往執行經驗中，動態地合成可重複使用的程序性知識，也就是智能體技能。傳統做法往往在下游需求尚未明朗前，就把經驗抽象成固定程序性知識，導致許多未來可能關鍵的知識被丟棄，卻又保留了對未來任務無用的實例特定細節。因此，本文的核心問題是：如何讓智能體在面對當前任務時，能夠隨選且精細地從原始經驗中提煉出真正有用的技能。

**Q2：現有的預先建構技能方法為何會失敗？**
A：現有方法通常是對單一軌跡做摘要，或對多條軌跡整合模式，然後把產出的技能儲存起來以備將來使用。然而，未來下游任務的需求在本質上是未知的，這種「先抽象、後使用」的策略很容易把後來變得關鍵的知識排除在外，同時又保留過多與未來應用無關的細節。結果就是預先建構的技能無法精準對應到當前任務的程序相關性，造成知識遺失與雜訊並存。

**Q3：為什麼「隨選動態合成技能」對自我演化智能體很重要？**
A：隨選動態合成讓智能體不必依賴靜態、預先整理好的技能庫，而是根據當前任務主動探索原始經驗，這對持續學習與能力擴展至關重要。由於執行情境不斷變化，固定技能難以涵蓋所有可能需求，動態導航能夠在執行階段提供針對性的程序性知識。這也讓配套系統能更靈活地在 runtime 供應智能體所需的指導，推動真正的自我演化。

**Q4：ExpVoyager 的核心方法論是什麼？**
A：ExpVoyager 把智能體技能合成重新框架為一個「動態導航問題」，讓技能策展者在累積軌跡中主動搜尋與當前任務相關的程序性知識。策展者會透過可導航介面，以不同的視角與解析度檢視原始經驗，並為凍結的執行器建構任務特定技能。整個過程不是一次性摘要，而是根據當前需求持續決定下一步要看哪裡、看多細。

**Q5：什麼是 Navigable Interface 與 Navigation State，它們各自扮演什麼角色？**
A：Navigable Interface 提供多種視角與解析度來存取原始經驗，讓技能策展者可以從整體執行模式看到局部決策情境，也能在需要時把局部記錄擴展成更廣泛的軌跡脈絡。Navigation State 則記錄策展者已經觀察到什麼、已識別出哪些可重複使用的程序性知識，以及還有哪些知識需求尚未滿足。這兩者互相配合，使經驗存取與知識詮釋能夠持續引導彼此，形成有效的動態導航迴路。

**Q6：為什麼主動導航比單純檢索 top-k 相似軌跡更好？**
A：基於相似度的存取往往難以捕捉真正的程序相關性，因為與當前任務相似的軌跡可能夾雜大量無關知識，而表面上不相關的軌跡卻可能包含局部關鍵線索。相較於這種被動檢索介面，ExpVoyager 的主動決策過程能決定檢視的位置與粒度，並在必要時深入局部或拉回整體脈絡。這種針對性、細粒度的經驗存取方式，更能提煉出對當前任務真正有用的程序性知識。

**Q7：實驗在哪些基準上進行，主要評估哪些面向？**
A：實驗涵蓋了三個熱門的智能體基準，包括家庭互動環境 ALFWorld、線上購物以及科學推理任務。評估重點分為兩大面向：一是 ExpVoyager 提升下游任務表現的有效性，二是其在可擴展與高效率經驗存取上的通用性。透過這些多樣化場景，作者希望驗證方法在不同任務類型與 curator–executor 配置下的穩健表現。

**Q8：ExpVoyager 的關鍵實驗結果有哪些？**
A：在所有基準上，ExpVoyager 都持續優於現有的技能導向方法，並且能顯著提升基礎智能體的表現。隨著經驗空間擴大，它的優勢會持續擴大，顯示出良好的規模化特性。此外，它還能在不依賴預先收集經驗的情況下進行線上自我演化，並能在有限的經驗存取預算內與現有技能協同運作。

**Q9：初步分析揭示了什麼現象，如何支撐 ExpVoyager 的動機？**
A：初步分析顯示，預先建構的技能只能保留少數對未來任務有用的程序性知識，例如表現最好的方法也僅覆蓋約 40.9% 的 oracle 知識，而部分方法甚至只有 12.7%。這證明了把經驗提前抽象成固定程序性知識會造成大量知識流失。同時，分析也指出單純的相似度檢索無法有效浮現當前任務所需的程序性知識，因此需要像 ExpVoyager 這樣的動態導航機制。

**Q10：ExpVoyager 在實際的智能體配套系統中可以怎麼應用？**
A：ExpVoyager 可以作為配套系統中的動態知識層，在執行階段為智能體提供隨選的任務特定技能。它能與現有的人工撰寫技能或預先建構的技能庫協同，透過隨選精煉來補強既有技能的不足。由於它支援高效率經驗存取，因此即使在成本或延遲受限的產品環境中，也能有效利用累積軌跡來提升智能體表現。

**Q11：部署 ExpVoyager 時需要考慮哪些產品化因素？**
A：首先必須管理經驗存取的成本，因為動態導航涉及多次檢視原始經驗，需要在效能與開銷之間取得平衡。其次，策展者與執行器的模組化設計讓系統可以獨立迭代，但也需要穩定的介面與錯誤處理機制。最後，實際部署時應考慮與現有技能庫、監控系統與持續學習流程的整合，以確保累積經驗能持續轉化為高品質的程序性知識。

**Q12：ExpVoyager 對自我演化智能體領域可能帶來什麼影響？**
A：它把研究焦點從靜態技能庫轉移到對原始經驗的動態導航，讓智能體能更靈活地利用過往經驗來擴展能力。這種範式有助於減少對人工撰寫指令的依賴，並讓智能體在面對新任務時能持續學習與適應。長遠來看，它為建構更自主、更具泛化能力的長程智能體提供了一條新的技術路徑。

**Q13：ExpVoyager 有哪些可能的方法限制？**
A：它的效果在很大程度上取決於累積經驗的品質與覆蓋範圍，如果經驗空間過於稀疏或充滿失敗軌跡，導航可能難以找到有用的程序性知識。此外，策展者的導航決策並非完美，可能在複雜任務中選錯檢視位置或粒度，導致資源浪費或技能品質下降。動態導航本身也帶來額外的推理與存取成本，這在資源受限的場景中需要特別考量。

**Q14：ExpVoyager 可能在什麼情況下表現不佳？**
A：當當前任務與過往經驗在程序層面差異很大時，策展者可能無法識別出有效的可重複使用知識，甚至會被表面相似但實質無關的軌跡誤導。如果導航過程過度聚焦於局部細節而忽略整體執行模式，也可能產生片段化或衝突的技能。另外，當經驗存取預算過低時，策展者可能來不及探索到關鍵線索，導致合成的技能不足以支撐任務完成。

**Q15：未來可以朝哪些方向延伸 ExpVoyager？**
A：未來可以結合強化學習來訓練更強大的導航策略，讓策展者能從成功與失敗中學習如何更有效地探索經驗空間。另一個方向是建立層次化的經驗組織結構，使智能體能在更高抽象層次上快速定位相關領域，再逐步深入細節。此外，也可以研究跨領域遷移、與模型微調結合，以及為動態導航提供理論保證，進一步提升方法的泛化性與可靠性。

## 實務應用指南

### 適用場景

1. **企業流程自動化（RPA 2.0）**  
   適合需要處理多變表單、跨系統操作或異常處理的長程任務，例如財務對帳、供應鏈追蹤或 HR 入職流程。ExpVoyager 能讓智能體在執行當前任務時，動態導航過往成功與失敗的軌跡，隨選合成最相關的程序性知識，而非依賴預先寫死的 SOP。

2. **客戶服務與售後支援智能體**  
   當使用者問題涉及多步驟排查（如退換貨、技術故障排除）時，系統可根據當前對話與任務目標，主動檢視歷史服務軌跡的不同視角與解析度，提煉出適用於當前案例的處理策略，減少人工撰寫大量 FAQ 與腳本的負擔。

3. **軟體開發與維運助手（DevOps / SRE Agent）**  
   適用於需要參考過往部署紀錄、除錯軌跡或事故應變流程的場景。ExpVoyager 可讓智能體在面對新的部署失敗或告警時，動態探索相似但不完全相同的歷史經驗，合成針對當前環境的修復指引。

4. **科學研究與實驗設計助理**  
   在文獻綜述、實驗規劃或數據分析管線中，研究人員可累積過往實驗軌跡。當面對新假設時，智能體透過經驗導航找出可重複使用的分析程序、參數設定或失敗教訓，協助設計更穩健的實驗流程。

5. **遊戲、模擬與實體機器人訓練**  
   適合 ALFWorld 這類互動式模擬環境的延伸應用，例如家用機器人任務、倉儲物流模擬。智能體可在執行新任務時，動態檢視過往軌跡的整體執行模式與局部決策情境，逐步累積可重複使用的技能。

### 實作前置條件

**資料準備**
- 累積足夠的原始經驗軌跡（raw experience），建議同時包含成功與失敗案例，並記錄每個步驟的觀察、動作與環境回饋。
- 每筆軌跡需附帶任務描述、執行情境與最終結果，以便後續進行程序相關性判斷。
- 建議建立軌跡後設資料（metadata），例如任務類型、環境狀態、使用工具、執行長度，方便 Navigable Interface 做多視角索引。

**運算資源**
- 可呼叫的 LLM API（作為 skill curator 與 frozen executor），需支援長上下文與函式呼叫（function calling）以實作導航行動。
- 向量資料庫或結構化儲存系統，用於支援不同解析度的經驗存取。
- 評估環境與模擬器（如 ALFWorld、自訂網頁環境或內部沙箱），用於驗證合成技能的下游任務表現。

**技能與團隊前提**
- 熟悉智能體配套系統（harness system）設計，能將技能注入執行階段（runtime）。
- 具備提示工程（prompt engineering）與軌跡資料清理經驗。
- 建議已有基礎的 executor 與評估指標，再疊加 ExpVoyager 的動態技能合成層。

---

### 實作步驟建議

1. **建立經驗收集管線**  
   讓 base agent 在目標環境中執行任務，記錄完整軌跡，包括觀察、動作、推理鏈與環境回饋。同時記錄任務目標與情境資訊，作為後續導航的基礎。

2. **設計 Navigable Interface**  
   將原始經驗組織成多種視角與解析度，例如：高階任務摘要、子目標序列、關鍵決策片段、完整逐步軌跡。提供 curator 可呼叫的導航行動，如 `summarize`、`zoom_in`、`expand_context`、`compare_trajectories`。

3. **實作 Navigation State**  
   讓 curator 在每一輪更新「已觀察到的可重用程序性知識」與「仍待調查的知識需求」。這個狀態應連結經驗存取與知識解讀，避免被動檢索導致的資訊遺漏。

4. **建構 skill curator 與 frozen executor 的分工**  
   curator 負責動態導航與合成任務特定技能；executor 則固定不變，僅接收 curator 產生的指引並執行任務。這樣可隔離學習層與執行層，降低系統複雜度。

5. **設計隨選合成與驗證迴圈**  
   針對每個當前任務，curator 在經驗空間中主動探索，產出技能後交給 executor 驗證。根據執行結果回饋，更新經驗庫與導航策略，形成線上自我演化（online self-evolution）。

6. **評估與迭代**  
   從下游任務表現、經驗存取效率、與現有技能的相容性三個維度進行評估。逐步擴大經驗空間，觀察是否持續獲得效能提升，並調整導航行動與解析度設計。

---

### 潛在風險與注意事項

- **過度擬合歷史軌跡**  
  若經驗庫中實例特定細節過多，curator 可能把特定案例的解法誤認為通用程序。建議在 Navigation State 中明確區分「可重複使用的程序性知識」與「僅限當次任務的細節」。

- **檢索與導航成本膨脹**  
  動態導航雖比固定技能更靈活，但可能增加 LLM 呼叫次數與延遲。應設定經驗存取預算（experience-access budget），並在 curator 中內建停止條件與成本監控。

- **幻覺與錯誤知識累積**  
  當 curator 從失敗或低品質軌跡中提煉知識時，可能合成出錯誤指引。建議搭配執行驗證與人工審核閘門，避免錯誤技能進入經驗空間並被後續任務重複使用。

- **相似度檢索的局限**  
  基於相似度的 top-k 軌跡檢索可能遺漏表面不相似但含局部關鍵線索的經驗。實作時應讓 curator 能主動擴展軌跡上下文，而非僅依賴初始檢索結果。

- **資料隱私與安全**  
  若軌跡包含敏感操作紀錄（如客戶資料、內部系統狀態），需對經驗庫進行去識別化、存取控管與審計追蹤。

---

### 與其他技術的整合建議

- **與現有技能庫協同**  
  ExpVoyager 不必然要取代已有人工撰寫技能，可作為隨選精煉層。當現有技能不足以解決當前任務時，curator 再動態導航原始經驗進行補充或修正。

- **結合 RAG 與向量資料庫**  
  將多視角、多解析度的經驗表示向量化，可加速初始定位，再由 curator 進行主動細粒度探索。這能兼顧檢索效率與動態導航的靈活性。

- **接入可觀測性與人機協作平台**  
  將 curator 的導航路徑、合成的技能與 executor 的執行結果記錄到可觀測系統，讓工程師能審查「為何選擇這段經驗」並在關鍵決策點引入人工確認。

- **與持續學習機制搭配**  
  將驗證後的成功技能回寫至經驗空間或技能庫，形成閉環。可與其他自我演化智能體框架（如經驗回放、模型微調）並行，分別處理程序性知識與參數更新。

---

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦在「為什麼需要動態技能合成」這個核心動機：想像智能體面對新任務時，不是翻閱一本預先寫好的手冊，而是像偵探一樣在主動探索過往案例。讀懂圖 1 與初步分析後，再回頭理解 Navigable Interface 與 Navigation State 的設計直覺即可。

**AI 工程師**  
請重點關注 curator 與 executor 的分工、導航行動的設計，以及 Navigation State 如何連結經驗存取與知識解讀。實作時可優先從一個既有 agent 框架出發，加入動態軌跡探索層，並用執行驗證確保合成技能可用。

**研究人員**  
本文的貢獻在於將技能合成重新框架為動態導航問題，並提出主動決策式的經驗存取機制。建議深入分析它與被動檢索、預先抽象方法的差異，並思考如何擴展到更複雜的環境，例如多智能體協作、連續學習與開放世界探索。

**產品經理**  
這篇論文提供了一個降低長期維護成本的願景：減少人工持續撰寫與更新 SOP 的需求，讓系統從實際執行中自動提煉可用知識。評估導入時，請同時關注「下游任務表現提升」與「經驗存取成本」，並規劃人工審核與安全閘門，確保自動化技能不會帶來營運風險。
