## 摘要翻譯

我們提出一個可複現流程（reproducible pipeline），能根據自由文本漏洞描述（free-text vulnerability descriptions），將通用漏洞與暴露（CVE）對應至 MITRE ATT&CK Enterprise（企業版）技術。我們不仰賴 CWE→CAPEC→ATT&CK 推導鏈（CWE→CAPEC→ATT&CK derivation chain）（其表格擴展偽影（table-expansion artifacts）已於本文量化），而是使用由 MITRE 威脅知情防禦中心（CTID）專家所對應、包含 1,207 筆 CVE 的人工精選黃金資料集（curated gold dataset），訓練一個多標籤分類器（multi-label classifier）。所得模型相較於零樣本嵌入相似度基線（zero-shot embedding-similarity baseline），recall@5（前 5 召回率）約提升一倍，並改善所有排序指標（ranking metric）。

接著我們探討 LLM 輔助標註（LLM-assisted labeling）是否能擴充黃金資料集。初步實驗顯示相互矛盾的結論：單一種子執行（single-seed run）顯示效能下降，而對五個隨機種子（random seeds）取平均則顯示小幅提升。然而，一項獨立復現（independent replication）與擴充規模研究（expansion-size study）（額外 100 至 984 筆 CVE）顯示，此表面改善（apparent improvement）實為評估假象（evaluation artifact）。LLM 生成標籤（LLM-generated labels）與專家標註（expert annotations）的一致性（agreement）約為 0.39，在任何擴充規模下皆未帶來可靠改善，且在加入約 1,000 筆 CVE 時降低稀有技術覆蓋率（rare-technique coverage）（macro-F1（宏觀 F1）下降 0.04）。

根本原因在於評估雜訊（evaluation noise）：在小型測試分割（small test split）上選擇檢查點（checkpoints），實際上會在多個雜訊評估中過度最大化（maximize over noisy evaluations），導致其餘條件相同的執行間 recall@5 差異高達 0.05。採用基於驗證分割檢查點選擇（validation-split checkpoint selection）的修正後協定（corrected protocol），僅使用黃金集合（gold set）資料的模型 recall@5 達到 (0.673 ± 0.019)，而重複執行決定性實驗（decisive experiment）也確認了 LLM 擴充的無顯著結果（null result）。最後一項規模擴展研究（scaling study）顯示，額外的專家整理資料（expert-curated data）能穩定提升效能，而 LLM 標註資料（LLM-labeled data）則無法，顯示該分類器的限制在於標籤品質（label quality），而非資料集規模（dataset size）。所有資料集、模型、程式碼與訓練日誌（training logs）均已公開釋出（openly released）。

### 核心貢獻（3～5點）
- 提出一個可複現的 CVE 對應 ATT&CK 流程，並以人工精選黃金資料集訓練多標籤分類器，相較零樣本嵌入相似度基線顯著提升 recall@5 與各項排序指標。
- 量化 CWE→CAPEC→ATT&CK 推導鏈中的表格擴展偽影，說明為何不採用此確定性對應路徑，而選擇專家整理的黃金標籤作為訓練目標。
- 透過獨立復現與擴充規模研究，證明 LLM 輔助標籤擴充的表面改善實為評估假象；LLM 生成標籤與專家標註一致性僅約 0.39，無法穩定提升效能。
- 揭示小型測試分割檢查點選擇所造成的評估雜訊問題，並提出基於驗證分割檢查點選擇的修正後協定，使黃金集合模型達到 recall@5 = 0.673 ± 0.019。
- 規模擴展研究顯示：增加專家整理資料可穩定提升效能，但 LLM 標註資料無法，指出分類器的瓶頸在於標籤品質而非資料集規模。

### 適合對象
本論文適合從事威脅知情防禦（Threat-Informed Defense）、漏洞情報分析、ATT&CK 技術對應，以及資安領域機器學習應用的研究人員與實務工作者。特別推薦給需要建立 CVE-to-ATT&CK 對應模型、評估 LLM 輔助標註可靠性，或關注資料品質與評估協定設計的資安資料科學家與威脅情報分析師。

## 深度分析

#### 方法論解析

本研究的核心方法論可視為一條「可複現流程（reproducible pipeline）」，從資料建構、監督式模型訓練到 LLM 輔助標註（LLM-assisted labeling）的嚴格驗證，形成一個封閉的實驗迴路。整體可分為三個層次：黃金資料集（gold set）的來源分層建構、多標籤分類器（multi-label classifier）的訓練與評估，以及 LLM 標籤擴充（LLM label expansion）的「先驗證再信任協定（validate-before-trust protocol）」。

##### 1. 資料建構：專家黃金標籤與弱自動衍生標籤的嚴格區分

作者從 MITRE 威脅知情防禦中心（CTID）的兩份專家整理（expert curation）成果取得黃金標籤（gold labels）：2021 年的 attack to cve mapping（約 840 個 CVE）以及透過 CTID Mappings Explorer 發布的 Known-Exploited-Vulnerabilities（KEV）對應資料。這些標籤遵循「Mapping ATT&CK to CVE for Impact」方法論，將每個通用漏洞與暴露（CVE）對應到最多三個槽位：觸發漏洞所需的利用（exploitation）技術、直接造成的首要影響（primary impact），以及由首要影響衍生的次要影響（secondary impact）。最終形成 1,207 筆黃金集合（gold set）樣本。

與之相對，作者也保留了 CWE→CAPEC→ATT&CK 推導鏈（CWE→CAPEC→ATT&CK derivation chain）所產生的弱自動衍生標籤（weak automatically derived labels），但刻意將其視為獨立的來源分層（provenance-tiered dataset），不與黃金標籤混淆。這個設計至關重要：過去研究常把跨框架連結（cross-framework links）直接當作訓練目標（training target），但本文後續量化指出，該推導鏈充斥表格擴展偽影（table-expansion artifacts），不適合作為監督式學習的標籤。

##### 2. 模型架構：以 RoBERTa 為骨幹的多標籤 BCE 分類器

在 Phase 2a，作者採用 `roberta-base` 作為編碼器，並在其上堆疊多標籤二元交叉熵（multi-label BCE）分類頭。輸入為自由文本漏洞描述（free-text vulnerability descriptions），輸出則是 MITRE ATT&CK Enterprise（企業版）中 697 個現行技術與子技術（techniques and sub-techniques）的機率分布。由於單一 CVE 可對應多個 ATT&CK 技術，因此任務本質上是多標籤（multi-label）排序問題，而非單一分類問題。

訓練流程採用標準的 train/validation/test 分割，但關鍵在於「最佳檢查點選擇（best-checkpoint selection）」的對象：作者後來發現，若在小型測試分割（small test split）上挑選檢查點（checkpoints），會導致在雜訊評估中過度最大化（maximize over noisy evaluations），因此修正後的協定改以驗證分割（validation split）作為選點依據，測試集僅用於最終報告。

##### 3. 基線比較：零樣本嵌入相似度基線

為了證明監督式學習的價值，作者建立了一個零樣本嵌入相似度基線（zero-shot embedding-similarity baseline），概念上延續 SMET 的語義相似度（semantic-similarity）做法：將 CVE 描述與各 ATT&CK 技術描述分別編碼成嵌入（embedding），再依餘弦相似度排序。這個基線不需要任何黃金標籤進行訓練，因此是衡量「專家標籤是否值得收集」的重要對照。

##### 4. LLM 標籤擴充：先驗證再信任

Phase 2b 是本研究最具方法論警示意義的部分。作者並未直接使用 LLM 生成標籤來擴充訓練資料，而是先讓 LLM（Ollama 上的 Qwen 與 Claude）在黃金集合上產生標籤，計算其與專家標註（expert annotations）的一致性（agreement）。結果顯示 LLM 生成標籤（LLM-generated labels）與專家標註的吻合度僅約 0.39，屬於中等偏低。

在此基礎上，作者設計了擴充規模研究（expansion-size study）：從 100 到 984 個額外 CVE，逐步將 LLM 標註資料（LLM-labeled data）併入黃金集合進行再訓練。整個過程嚴格區分黃金標籤與 LLM 標籤的來源，並透過多隨機種子（multi-seed）與多規模（multi-size）實驗來降低評估雜訊（evaluation noise）的影響。

##### 5. 方法論上的關鍵修正

本文最重要的方法論貢獻之一，是揭示了「在小型測試分割上挑選最佳檢查點」所造成的評估假象（evaluation artifact）。作者發現，即便其他條件完全相同，僅因隨機種子（random seeds）不同，recall@5（前 5 召回率）可能出現高達 0.05 的跨執行雜訊（run-to-run noise），遠大於 LLM 擴充的真實效應大小（effect size）。因此他們提出修正後協定（corrected protocol）：以驗證分割檢查點選擇（validation-split checkpoint selection）取代測試分割選點，並以多種子平均來穩定評估。這個修正直接改變了實驗結論，從「LLM 擴充似乎有小幅提升」轉為「無顯著結果（null result）」。

#### 實驗數據解讀

本研究的實驗設計圍繞四個核心問題：(1) 監督式分類器相較於零樣本基線是否有顯著優勢？(2) CWE→CAPEC→ATT&CK 推導鏈的雜訊有多嚴重？(3) LLM 標籤擴充是否真的能提升模型？(4) 資料規模與標籤品質何者才是瓶頸？

##### 1. 監督式分類器顯著優於零樣本基線

實驗結果顯示，以黃金資料集訓練的多標籤分類器（multi-label classifier）在各項排序指標（ranking metrics）上均擊敗零樣本嵌入相似度基線（zero-shot embedding-similarity baseline）。最具代表性的指標 recall@5（前 5 召回率）幾乎翻倍，這對實務應用極具意義：資安分析師在審查 CVE 時，通常只會看模型推薦的前幾個 ATT&CK 技術，因此前 5 召回率直接決定了工具能否減輕人工對應負擔。

這個結果也驗證了本文的核心假設：對於「從自由文本漏洞描述推論攻擊者行為（attacker behavior）」這類主觀（subjective）且長尾分布（long-tailed distribution）的任務，單純的語義相似度不足以捕捉專家對應知識，而專家整理資料（expert-curated data）所提供的監督訊號能顯著改善排序品質。

##### 2. CWE→CAPEC→ATT&CK 推導鏈充斥表格擴展偽影

作者直接量化跨框架連結（cross-framework links）所產生的雜訊。雖然具體數值在提供的摘要中未詳列，但結論非常明確：該推導鏈的輸出被表格擴展偽影（table-expansion artifacts）主導，無法作為可信賴標籤（trustworthy labels）。這解釋了為何 CVE2CAPEC 與 BRON 等工具雖然覆蓋率高，卻不適合直接訓練監督式模型——它們的標籤過於寬鬆或過度推導，與專家對 CVE 實際影響（impact）的判斷存在系統性偏差。

##### 3. LLM 標籤擴充：從矛盾結論到無顯著結果

LLM 擴充實驗的歷程是本研究最發人深省的部分。作者經歷了三個階段的「判決」：

- **單一種子執行（single-seed run）**：顯示加入 LLM 標註資料後效能下降。
- **五種子比較（five-seed comparison）**：平均後似乎顯示小幅提升。
- **獨立復現（independent replication）與擴充規模研究（expansion-size study）**：在 100 至 984 個額外 CVE 的範圍內，未觀察到任何可靠改善；當擴充至約 1,000 個 CVE 時，稀有技術覆蓋率（rare-technique coverage）反而下降，macro-F1（宏觀 F1）降低 0.04。

進一步的診斷指出，前兩個階段的矛盾結論（contradictory conclusions）其實是評估假象（evaluation artifact）。由於在小型測試分割（small test split）上挑選檢查點，模型選擇過程會放大跨執行雜訊（run-to-run noise），使得 recall@5 在相同實驗條件下可波動達 0.05。這個波動幅度已超過 LLM 擴充可能帶來的真實效應大小（effect size），因此任何觀察到的「改善」都不可信。

採用修正後協定（corrected protocol）後，純黃金資料模型在 recall@5 上達到 (0.673 ± 0.019)，而 LLM 擴充的重複決定性實驗（decisive experiment）確認為無顯著結果（null result）。換言之，LLM 生成標籤雖然便宜且可擴展，但其約 0.39 的專家一致性（agreement）不足以轉化為模型效能提升。

##### 4. 規模擴展研究：瓶頸在標籤品質而非資料量

最後的規模擴展研究（scaling study）進一步鞏固了上述結論：增加專家整理資料（expert-curated data）能穩定提升效能，但增加 LLM 標註資料（LLM-labeled data）則不能。這說明分類器的限制不在資料集規模（dataset size），而在標籤品質（label quality）。對於長尾分布的 ATT&CK 技術而言，LLM 的低品質標註反而會稀釋稀有類別的學習訊號，導致 macro-F1 下降。

#### 與現有研究的比較

本研究在自動化 CVE 對應 ATT&CK 的文獻中佔據一個清晰的位置：它介於「完全無監督的語義相似度方法」與「大規模自動衍生標籤方法」之間，並以嚴格的標籤來源分層與評估協定取勝。

##### 1. 相較於 CVE2CAPEC / BRON 等確定性推導方法

CVE2CAPEC 與 BRON 透過 CWE→CAPEC→ATT&CK 推導鏈（derivation chain）提供近乎完整的覆蓋率，但本文證明這些跨框架連結（cross-framework links）存在嚴重的表格擴展偽影（table-expansion artifacts）。過去研究常將這些推導結果視為訓練目標（training target）或對照標準，而本文明確指出其不適合作為監督式學習的黃金標準。這是方法論上的重要進步。

##### 2. 相較於 SMET 等零樣本語義相似度方法

SMET 刻意迴避監督式分類，理由是標籤稀缺。本文採用了類似的零樣本嵌入相似度基線（zero-shot embedding-similarity baseline），但證明只要擁有約 1,200 筆專家標註（expert annotations），監督式多標籤分類器（multi-label classifier）就能在 recall@5 等關鍵指標上大幅超越基線。這對「標籤稀缺是否必然走向無監督」的論點提出了反例。

##### 3. 相較於 CVE2ATT&CK 等監督式方法

CVE2ATT&CK 使用數千筆 CVE 與 BERT 進行微調，但技術集合受限，且未明確區分標籤來源。本文的差異在於三點：堅持使用 CTID 專家標籤、採用多標籤排序評估（而非單標籤準確率）、並且系統性研究 LLM 標籤擴充的可行性。此外，本文針對 ATT&CK 版本變動（techniques 會被撤銷或替換）進行了標準化處理，使用 STIX 資料中的 revoked-by 關係將所有 ID 對齊到單一參考版本（version 19.1），這在長期維運上更為穩健。

##### 4. 相較於 TRAM 等威脅報告對應工具

TRAM 同樣來自 CTID，但輸入是威脅報告（threat reports）而非簡短的 CVE 描述。兩者的輸入分布（input distribution）截然不同：威脅報告通常包含豐富的攻擊者行為（attacker behavior）脈絡，而 CVE 描述則偏向技術缺陷（flaw）與影響（impact）的客觀陳述。因此 TRAM 的經驗無法直接遷移到 CVE→ATT&CK 任務。

##### 5. 研究限制

儘管方法論嚴謹，本研究仍有若干限制。首先，黃金集合僅 1,207 筆，雖然足以訓練出優於基線的模型，但對於長尾分布中的稀有技術（rare techniques）覆蓋仍然有限。其次，LLM 實驗僅測試了 Qwen 與 Claude，未涵蓋更新或更大的模型（例如 GPT-4 後續版本或其他專門調校的開源模型），因此「LLM 標註無用」的結論應理解為「在當前設定下無顯著助益」，而非普遍否定。第三，評估指標以 recall@k 與 macro-F1 為主，雖然貼近分析師使用情境，但未深入探討不同技術類別（例如利用技術 vs. 影響技術）的個別表現。最後，模型輸入僅使用 CVE 描述，未納入 CVSS、CWE、參考連結等結構化資訊，這些資訊未來可能進一步提升效能。

#### 可重現性評估

可重現性（reproducibility）是本研究反覆強調的價值。作者將所有資料、模型權重、程式碼與訓練日誌（training logs）公開釋出於 CIRCL 組織（CIRCL organisation）下，並以 VulnTrain 工具包（VulnTrain toolkit）封裝整個流程。

##### 1. 資料集釋出

黃金資料集以「來源分層資料集（provenance-tiered dataset）」形式釋出，明確標示每一筆標籤是來自 CTID 專家整理（expert curation）還是 CWE→CAPEC→ATT&CK 推導鏈（derivation chain）。這種嚴格區分（strictly separate）避免了後續研究者無意間將弱自動衍生標籤（weak automatically derived labels）與黃金標籤（gold labels）混淆（conflated）。

##### 2. 模型與程式碼

微調後的 `roberta-base` 多標籤分類器、各階段 LLM 擴充模型（標記為 `-llm-<model>`）以及零樣本嵌入相似度基線（zero-shot embedding-similarity baseline）均發布於 Hugging Face。VulnTrain 工具包則提供從資料前處理、訓練、評估到 LLM 標註的完整命令列介面，讓其他研究者能夠重現每一個實驗階段。

##### 3. 訓練日誌與實驗歷程

尤其值得稱道的是，作者公開了「三判決」擴充實驗的完整訓練日誌（training logs），包括單一種子執行（single-seed run）、五種子比較（five-seed comparison）、獨立復現（independent replication）以及修正後協定（corrected protocol）下的決定性實驗（decisive experiment）。這種透明度對於方法論教訓的傳播極為重要：它不僅讓人驗證最終結論，也讓人理解為何早期結論是錯誤的。

##### 4. 可重現性建議

對於希望延伸此工作的研究者，建議優先採用作者提出的修正後訓練協定（corrected training protocol）：以驗證分割（validation split）選擇最佳檢查點（best-checkpoint selection），以多隨機種子（multi-seed）平均報告指標，並明確區分黃金標籤與任何自動衍生標籤。這些措施能顯著降低評估雜訊（evaluation noise）導致的假陽性結論。

#### 未來研究方向

本研究在方法論與實證上都留下了豐富的延伸空間，以下從資料、模型、評估與應用四個面向提出可能的後續方向。

##### 1. 更高品質的標籤擴充策略

既然 LLM 生成標籤（LLM-generated labels）因品質不足而無法提升模型，未來可探索「人機協作」的半監督標註流程。例如，讓 LLM 產生候選標籤後，再由領域專家進行快速審核與修正；或者使用主動學習（active learning）策略，優先標註模型最不確定的樣本，以有限專家預算最大化資訊增益。另一個方向是設計更精細的提示工程（prompt engineering）或讓 LLM 參考 ATT&CK 技術描述與範例進行鏈式思考（chain-of-thought）推理，以提高與專家標註的一致性（agreement）。

##### 2. 多模態與結構化資訊融合

目前模型僅使用自由文本漏洞描述（free-text vulnerability descriptions）。未來可納入 CWE 類別、CVSS 分數、受影響產品資訊、參考連結中的攻擊程式碼（proof-of-concept）文本，甚至漏洞相關的威脅情報報告。這些結構化與半結構化訊號可能彌補純文本描述的不足，特別是在判斷「利用技術（exploitation technique）」與「影響（impact）」時提供更明確的線索。

##### 3. 長尾技術與類別不平衡處理

ATT&CK 技術分布呈現長尾分布（long-tailed distribution），少數技術頻繁出現，多數技術極為稀有。未來可針對稀有技術覆蓋率（rare-technique coverage）設計專門的損失函數（例如 focal loss、類別重加權）或資料增強策略，並以 macro-F1（宏觀 F1）與 per-technique recall 作為主要優化目標，而非僅追求整體 recall@5。

##### 4. 跨版本與持續學習

ATT&CK 是動態知識庫，技術會被撤銷、新增或替換。未來研究可發展持續學習（continual learning）或版本對齊機制，使模型能在新 ATT&CK 版本發布時自動遷移，同時保留舊版本的對應知識。這對於實務部署至關重要，因為防禦者需要長期維護 CVE→ATT&CK 對應關係。

##### 5. 更嚴謹的評估協定與人工研究

本文揭示了評估雜訊（evaluation noise）與最佳檢查點選擇（best-checkpoint selection）對結論的影響，未來可進一步建立 CVE→ATT&CK 任務的標準化基準測試（benchmark），包括固定資料分割、標準評估腳本與顯著性檢定流程。此外，可進行更多專家間一致性（inter-annotator agreement）研究，以量化這項任務的主觀性（subjective）程度，並為 LLM 標註品質設定更合理的門檻。

##### 6. 應用於威脅知情優先排序與偵測覆蓋評估

最後，從應用角度，可將此分類器整合至漏洞管理流程，自動從漏洞資訊來源（vulnerability feed）推薦 ATT&CK 技術，進而支援威脅知情優先排序（threat-informed prioritisation）、偵測覆蓋率（detection coverage）評估與風險評估（risk assessment）。未來工作可量化這類自動對應工具在實際資安營運（SOC）中減少人工審查工時的效益。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？為什麼將 CVE 對應到 MITRE ATT&CK 很重要？**

A：這篇論文要解決的是如何自動把自由文本的 CVE 漏洞描述對應到 MITRE ATT&CK Enterprise 的技術（techniques）。對防禦者來說，單知道「哪裡壞了」還不夠，還必須理解對手會「如何利用」這個漏洞、造成什麼影響，而 ATT&CK 正是描述攻擊者行為的共用詞彙。透過這條對應關係，資安團隊能直接從漏洞資訊來源（vulnerability feed）轉到偵測覆蓋率評估、威脅知情優先排序（threat-informed prioritisation）與風險評估，但目前已發布的 CVE 數量龐大，無法全部靠人工標註。

**Q2：現有的 CWE→CAPEC→ATT&CK 推導鏈為什麼不適合當作訓練目標？**

A：CWE→CAPEC→ATT&CK 推導鏈雖然是確定性對應，但論文量化發現它受到嚴重的表格擴展偽影（table-expansion artifacts）與雜訊主導，導致產生的標籤品質低落。這條跨框架連結把軟體弱點、攻擊模式與對手行為硬串起來，過程中會引入許多不精確或過度泛化的對應。因此，若直接用它產生的弱自動衍生標籤（weak automatically derived labels）來訓練模型，反而會讓模型學到錯誤的對應關係。

**Q3：為什麼 CVE 對應 ATT&CK 這項任務即使對專家來說也很困難？**

A：這項任務本質上是多標籤（multi-label）問題，單一 CVE 可能同時啟用多種 ATT&CK 技術，而且技術分布呈現長尾（long-tailed），少數技術頻繁出現、多數技術非常稀有。此外，CVE 描述的是軟體缺陷（flaw），而 ATT&CK 描述的是攻擊者行為（attacker behavior），兩者層次不同，因此對應過程帶有主觀性，連專家分析師之間都可能意見不一致。這些特性讓自動對應既難以取得單一正解，也難以保證對稀有技術的覆蓋率。

**Q4：作者提出的核心監督式方法是什麼？**

A：作者以 RoBERTa-base 搭配多標籤二元交叉熵（multi-label BCE）訓練一個多標籤分類器（multi-label classifier），輸入是 CVE 的自由文本描述，輸出是排序後的 ATT&CK 技術預測。訓練標籤來自 MITRE CTID 專家整理的黃金資料集（curated gold dataset），共 1,207 筆 CVE，並嚴格排除自動衍生的弱標籤。這種設計讓模型直接學習專家對「漏洞如何被利用、造成什麼影響」的行為層判斷，而不是學習有雜訊的跨框架推導結果。

**Q5：資料集建構上的關鍵創新是什麼？**

A：關鍵創新是建立一個來源分層（provenance-tiered）的資料集，把專家黃金標籤（gold labels）與弱自動衍生標籤嚴格區分（strictly separate），絕不混在同一個訓練目標中。黃金集合來自 CTID 的「attack to cve」對應與 Known-Exploited-Vulnerabilities（KEV）對應，並遵循「利用技術、主要影響、次要影響」三個欄位的標註方法論。這樣的分層設計確保了監督式學習的上限由可信賴標籤（trustworthy labels）決定，而不是被低品質標籤污染。

**Q6：這項研究與先前的自動化 CVE→ATT&CK 方法有何不同？**

A：與 CVE2CAPEC、BRON 等確定性推導方法不同，本研究採用監督式學習並以專家標註為訓練目標；與 SMET 等零樣本語義相似度基線（zero-shot semantic-similarity baseline）不同，本研究訓練專屬分類器並進行多標籤排序評估。相較於 CVE2ATT&CK 使用自動衍生標籤並限制技術集合，本研究堅持使用 CTID 專家黃金標籤，並設計以分析師審查為導向的排序指標。此外，本研究還系統性地檢驗 LLM 輔助標註（LLM-assisted labeling）是否能擴充資料集，這是過去較少深入探討的議題。

**Q7：監督式分類器與基線相比表現如何？**

A：在修正後的評估協定下，黃金集合訓練的模型 recall@5 達到 0.673 ± 0.019，大約是零樣本嵌入相似度基線（zero-shot embedding-similarity baseline）的兩倍，並且在所有排序指標（ranking metrics）上都有提升。這顯示即使黃金資料集規模不大，高品質的專家標籤仍能訓練出優於無訓練語義比對的方法。相較之下，單純靠 CVE 描述與 ATT&CK 技術描述的語義相似度，難以捕捉漏洞與攻擊行為之間的細緻對應。

**Q8：LLM 輔助標籤擴充實驗得到了什麼結論？**

A：實驗經歷了「三種判決」：單一種子執行（single-seed run）顯示效能下降，五種子平均（five-seed comparison）顯示小幅提升，但獨立復現（independent replication）與 100–984 筆的擴充規模研究（expansion-size study）最終證明所謂改善只是評估假象（evaluation artifact）。LLM 生成標籤與專家標註的一致性僅約 0.39，在任何擴充規模下都沒有帶來可靠提升，當加入約 1,000 筆 LLM 標註時甚至降低稀有技術覆蓋率（rare-technique coverage），使 macro-F1 下降 0.04。因此最終結論是保留僅使用黃金標籤的模型，不採用 LLM 擴充。

**Q9：為什麼 LLM 擴充實驗會先後得出相互矛盾的結論？根本原因為何？**

A：根本原因是評估雜訊（evaluation noise）：在小型測試分割（small test split）上挑選最佳檢查點（best-checkpoint selection），會讓模型在雜訊中過度最大化（maximize over noisy evaluations），導致相同設定的不同執行間 recall@5 可相差高達 0.05。這種跨執行雜訊（run-to-run noise）大到足以掩蓋或偽裝 LLM 擴充的真實效應大小（effect size）。作者提出的修正協定（corrected protocol）改以驗證分割（validation split）選擇檢查點，才讓結果穩定下來，並確認 LLM 擴充的無顯著結果（null result）。

**Q10：這個分類器在實務上可以怎麼應用？**

A：資安營運中心（SOC）或漏洞管理團隊可將模型整合進漏洞資訊來源（vulnerability feed）流程，自動為新發布的 CVE 產生候選 ATT&CK 技術排序，供分析師快速判斷偵測覆蓋率缺口。風險評估人員則能依據對應的攻擊者行為與影響，進行威脅知情優先排序（threat-informed prioritisation），決定哪些漏洞需要優先修補。由於模型輸出是排序過的技術建議，它適合作為分析師審查的決策輔助工具，而非完全自動化的最終判定。

**Q11：在產品化或部署時需要考慮哪些因素？**

A：首先，ATT&CK 是持續演進的知識庫，技術會被廢止、撤銷或替換，因此部署時必須使用 STIX 資料中的 revoked-by 關係將技術 ID 正規化到單一參考版本。其次，由於對應本身具有主觀性且為多標籤，模型輸出應保留人工確認環節，特別是對稀有技術（rare techniques）的預測。最後，產品應避免把 CWE→CAPEC→ATT&CK 推導鏈的輸出直接當成訓練目標或最終答案，因為其雜訊會顯著降低結果可信度。

**Q12：這項研究對學術界與資安領域可能帶來什麼影響？**

A：作者公開釋出 VulnTrain 工具包、資料集、模型與訓練日誌（training logs），讓整個流程可複現，有助於建立 CVE→ATT&CK 對應任務的公開基準。研究也明確指出高品質專家標籤的價值，並對「LLM 標註一定能放大資料集」的直覺提出警示。此外，修正後的評估協定為未來多標籤排序任務提供了一個更誠實、更穩定的評估範本，減少因檢查點選擇不當而產生的假性改善。

**Q13：作者承認哪些主要限制？**

A：最主要的限制是黃金資料集規模仍然偏小（1,207 筆 CVE），相較於數十萬筆已發布 CVE 只是很小一部分。其次，LLM 輔助標註在本任務上未能提升效能，顯示目前 LLM 生成標籤的品質還不足以取代專家標註。第三，稀有技術覆蓋率仍是挑戰，尤其在加入雜訊標籤後 macro-F1 會下降，代表模型對長尾類別的學習相當脆弱。

**Q14：使用者應該注意哪些失敗案例？**

A：當 CVE 的利用路徑與訓練資料分布差異很大時，模型可能遺漏正確的稀有技術；若誤把 LLM 生成標籤加入訓練，可能進一步稀釋稀有技術的表現，使 macro-F1 下降。此外，若採用 CWE→CAPEC→ATT&CK 推導鏈作為訓練目標或評估標準，會因表格擴展偽影而產生大量錯誤對應。最後，如果在小型測試集上挑選最佳檢查點，可能會因評估雜訊而誤以為模型改善，實際上只是隨機波動。

**Q15：這項研究指出了哪些未來研究方向？**

A：未來首要方向是持續收集更多專家整理資料（expert-curated data），因為規模擴展研究顯示專家標籤增加能穩定提升效能，而 LLM 標註資料則不能。其次，可以探索如何透過更好提示工程、人在迴路（human-in-the-loop）驗證或更強大的模型，把 LLM 與專家標註的一致性從約 0.39 顯著提高，才可能真正發揮擴充效益。此外，也可將方法延伸到 ATT&CK 子技術（sub-techniques）以及其他領域（如 ICS、Mobile），並進一步發展能降低評估雜訊的穩健評估協定。

## 實務應用指南

### 適用場景

1. **漏洞優先排序與威脅知情修補**  
   資安團隊每日收到數以千計的 CVE，但修補能量有限。將 CVE 自動對應到 MITRE ATT&CK Enterprise 技術後，可立即判斷該漏洞會啟用哪些對手戰術（例如權限提升、橫向移動、憑證竊取），並結合現有偵測覆蓋率決定修補順序。

2. **SOC 偵測規則缺口分析**  
   把新公開 CVE 映射到 ATT&CK 技術後，與現有 SIEM／EDR 偵測規則覆蓋的技術集合做比對，快速找出「有漏洞但無偵測」的缺口，優先補強相關偵測邏輯。

3. **威脅情報 enrichment（豐富化）**  
   在漏洞情報平台或資安 Orchestration 流程中，對每筆 CVE 自動附加 ATT&CK 技術標籤，讓分析師無需手動查閱 CWE→CAPEC→ATT&CK 推導鏈，即可在威脅獵捕與事件調查時直接以共同語言進行關聯。

4. **紅隊／滲透測試劇本設計**  
   根據目標環境中存在的 CVE，自動推薦可能適用的 ATT&CK 技術與子技術，協助紅隊規劃利用路徑，並驗證藍隊對應的偵測與緩解措施。

5. **供應鏈與資產風險評估**  
   將軟體物料清單（SBOM）中的元件漏洞批次映射到 ATT&CK，評估不同資產面臨的對手行為風險，並產出技術導向的風險熱圖。

### 實作前置條件

**資料條件**
- 必須能取得 CVE 自由文本描述（建議使用 NVD、CIRCL vulnerability-scores 或內部漏洞資料源）。
- 若要走監督式路線，需要高品質的專家整理標籤；本文證明 LLM 生成標籤無法穩定提升效能，不應直接取代專家黃金標籤。
- 需準備 ATT&CK Enterprise STIX 資料，並處理 revoked／deprecated 技術的標準化對應。

**運算條件**
- 微調 RoBERTa-base 等級的多標籤分類器：單張中階 GPU（如 NVIDIA A10G / RTX A6000）即可在數小時內完成訓練。
- 推論階段可批次執行，CPU 亦可應付低頻查詢；若需每日處理數萬筆 CVE，建議使用 GPU 推論服務。
- 零樣本嵌入相似度基線僅需預訓練語言模型與 ATT&CK 技術描述的向量索引，運算成本更低，但 recall@5 約為監督模型的一半。

**技能條件**
- 熟悉 Python、Hugging Face Transformers 與多標籤分類評估指標（recall@k、MRR、macro-F1）。
- 理解 MITRE ATT&CK 的戰術／技術／子技術結構，以及 revoked-by 關係的標準化處理。
- 具備資料工程能力，能維護「黃金標籤」與「弱自動衍生標籤」的來源分層，避免兩者混淆。

### 實作步驟建議

1. **建立來源分層的黃金資料集**  
   收集 MITRE CTID 的 `attack-to-cve` 與 KEV Explorer 對應資料，嚴格區分專家黃金標籤與 CWE→CAPEC→ATT&CK 推導鏈產生的弱標籤。後者僅供參考，不可混入訓練目標。

2. **標準化 ATT&CK 版本與 ID**  
   使用 ATT&CK STIX 資料將所有 revoked 技術透過 revoked-by 關係對應到單一參考版本（本文使用 Enterprise v19.1），避免不同版本技術 ID 混用。

3. **訓練監督式多標籤分類器**  
   以 RoBERTa-base 為骨幹，採用 multi-label BCE loss，輸入為 CVE 描述，輸出為 697 個 Enterprise 技術／子技術的機率。務必使用獨立的驗證分割（validation split）進行最佳檢查點選擇，切勿直接在小型測試分割上挑選檢查點。

4. **以零樣本基線進行最低門檻檢驗**  
   在部署前，先與 SMET 風格的零樣本嵌入相似度基線比較。若監督模型無法在 recall@5、MRR 等排序指標上全面勝過基線，應回頭檢查標籤品質或訓練流程。

5. **謹慎評估 LLM 輔助標註**  
   若標籤不足而考慮使用 LLM 擴充，必須先測量 LLM 與黃金標籤的一致性。本文發現即使使用 Qwen／Claude 等級模型，一致性僅約 0.39，且無法在任何擴充規模（100–984 筆）帶來穩定增益，反而會降低稀有技術覆蓋率。建議優先投入專家整理資料。

6. **部署與持續監控**  
   將模型包裝為 API，對新 CVE 輸出 top-k ATT&CK 技術與信心分數。定期以新 CVE 的專家標註重新評估 recall@5 與 macro-F1，並監控稀有技術的預測表現是否隨時間衰退。

---

### 潛在風險與注意事項

- **評估雜訊導致的假性改善**  
  在小型測試分割上挑選最佳檢查點，會放大跨執行雜訊，使 recall@5 出現高達 0.05 的虛假差異。務必以驗證集選點，並使用多個隨機種子確認結果。

- **LLM 標籤無法穩定提升模型**  
  不要因為單一種子執行看似有進步就採用 LLM 擴充。本文顯示這種「改善」是評估假象，擴充到約 1,000 筆 LLM 標註資料時 macro-F1 反而下降 0.04。

- **稀有技術覆蓋率不足**  
  ATT&CK 技術分布為長尾，模型容易偏向常見技術。評估時必須同時看 macro-F1 與 recall@5，避免只追整體 recall 而忽略少見技術。

- **CWE→CAPEC→ATT&CK 推導鏈的雜訊**  
  該推導鏈存在嚴重的表格擴展偽影，不適合作為訓練目標。若內部系統仍使用此鏈，應將其視為弱訊號，並逐步以專家黃金標籤取代。

- **主觀性與版本漂移**  
  CVE 到 ATT&CK 的對應本質上帶有主觀性，且 ATT&CK 版本會更新。產品應保留預測信心分數與人工覆核機制，並隨 ATT&CK 版本更新重新標準化技術 ID。

---

### 與其他技術的整合建議

- **SIEM／SOAR**：將模型輸出的 ATT&CK 技術標籤寫入 CVE enrichment pipeline，讓 SOC 劇本可依技術 ID 自動觸發對應的偵測規則或補償控制檢查清單。
- **漏洞管理平臺（如 Kenna、ServiceNow VRM）**：把 top-k 技術與信心分數作為漏洞優先排序的額外特徵，與 CVSS、EPSS、CISA KEV 等指標並行使用。
- **威脅情報平台（TIP）**：以 ATT&CK 技術為共同鍵值，將 CVE 與威脅行為者、攻擊活動、MITRE D3FEND 緩解措施進行關聯。
- **偵測工程工具（如 Sigma、Splunk、Elastic）**：針對模型標出的高風險技術，自動檢索對應偵測規則是否存在，並產出缺口報告。
- **LLM 應用**：可將模型預測作為 RAG 系統的上下文，輔助分析師理解「為何這個 CVE 可能對應到某技術」，但應避免讓 LLM 直接產生訓練標籤。

### 給不同背景讀者的閱讀建議

**初學者**：建議先聚焦「適用場景」與「實作步驟建議」前四步，理解 CVE、ATT&CK、多標籤分類的基本關係。不必立刻處理 LLM 擴充爭議，重點是建立「標籤品質決定模型上限」的觀念，並學會用 recall@5 與 macro-F1 評估模型。

**AI 工程師**：請仔細閱讀「潛在風險與注意事項」與「實作步驟建議」的訓練細節，特別是驗證集選點、多隨機種子評估、以及為何 LLM 標籤無法穩定提升效能。建議直接參考 VulnTrain 工具包與釋出的訓練日誌，復現三種不同結論的擴充實驗，以掌握評估雜訊的實際影響。

**研究人員**：本文核心貢獻在於量化 CWE→CAPEC→ATT&CK 推導鏈的雜訊、提出可複現的黃金資料集流程，並對 LLM 輔助標註進行嚴謹的多種子／多規模檢驗。建議深入檢視修正後協定與規模擴展研究，思考如何將「先驗證再信任」協定推廣到其他知識庫對應任務。

**產品經理**：請把重點放在「適用場景」與「與其他技術的整合建議」。關鍵取捨是：監督式模型需要持續投入專家整理標籤，LLM 標註雖然便宜但無法穩定提升效能。規劃產品路線圖時，應將標籤品質與人工覆核機制視為必要成本，而非可壓縮的開支。
