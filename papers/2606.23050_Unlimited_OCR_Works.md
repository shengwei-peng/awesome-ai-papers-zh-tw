## ⚡ TL;DR

現有端到端OCR因KV快取隨輸出增長，難以長程解析多頁文件。
本文提出UnlimitedOCR，以R-SWA取代解碼器注意力層，讓KV快取維持恆定。
單次解析數十頁文件，OmniDocBench達93%超越基線6%，且適用於ASR與翻譯。

## 摘要翻譯

近期，以 DeepSeek OCR 為代表的端到端 OCR 模型，再次使 OCR 受到矚目。普遍認為，採用大型語言模型（LLM）作為解碼器，能讓模型借助語言先驗分佈，從而提升 OCR 表現。然而，其缺點也同樣明顯：隨著輸出序列增長，累積的 KV 快取會導致記憶體消耗增加，並逐漸減緩生成速度。這與人類形成鮮明對比：在長程抄寫任務中，人類並不會出現這種效率下降。在本技術報告中，我們提出 Unlimited OCR，該模型旨在模擬人類解析工作記憶。以 DeepSeek OCR 為基線，我們將解碼器中所有的注意力層替換為本文提出的參考滑動視窗注意力機制（R-SWA），從而降低注意力計算成本，同時在整個解碼過程中維持恆定的 KV 快取。透過結合 DeepSeek OCR 編碼器的高壓縮率與我們的恆定 KV 快取設計，Unlimited OCR 能在 32K 標準最大長度限制下，僅需單次前向傳遞即可轉錄數十頁的文件。更重要的是，R-SWA 是一種通用解析注意力機制——其應用不僅限於 OCR，亦適用於自動語音辨識（ASR）、翻譯等任務。原始碼與模型權重已公開釋出，詳見 http://github.com/baidu/Unlimited-OCR。

### 核心貢獻（3～5點）
- 提出 Unlimited OCR 模型，以模擬人類解析工作記憶為設計核心，解決長序列轉錄中的效率衰退問題。
- 提出參考滑動視窗注意力機制（R-SWA），在降低解碼器注意力計算成本的同時，於整個解碼過程中維持恆定 KV 快取。
- 結合高壓縮編碼器與恆定 KV 快取設計，使 Unlimited OCR 能在 32K 標準最大長度限制下，僅需單次前向傳遞即可轉錄數十頁文件。
- 驗證 R-SWA 作為通用解析注意力機制的跨領域適用性，可擴展至自動語音辨識（ASR）、翻譯等序列轉換任務。
- 公開釋出原始碼與模型權重，供學術界與產業界後續研究與應用。

### 適合對象
從事 OCR、文件理解、多模態學習，以及專注於大型語言模型解碼效率與長序列處理之研究人員與工程師；此外，由於 R-SWA 為通用解析注意力機制，對自動語音辨識（ASR）與翻譯領域的從業者亦具高度參考價值。

## 深度分析

#### 方法論解析

本文提出的核心創新為參考滑動視窗注意力機制（Reference Sliding Window Attention, R-SWA），其設計理念源於對人類解析工作記憶（parsing working memory）的類比。在長程抄寫任務（long-horizon copying tasks）中，人類並不會持續回溯檢視所有已產出的內容，而是僅仰賴鄰近上下文（nearby context）以追蹤進度，同時讓遠端輸出逐漸淡出記憶。R-SWA 正是為了模擬此認知狀態（cognitive state）而設計，並以此解決端到端 OCR 模型（end-to-end OCR models）在解碼器（decoder）端因輸出序列（output sequence）增長所導致的 KV 快取（KV cache）線性膨脹問題。

具體而言，R-SWA 將注意力運算拆分為兩個非對稱路徑。第一路徑針對參考標記（reference tokens），包含視覺標記（visual tokens）與提示詞（prompt）：每個生成標記均對全部參考標記執行全注意力（full attention），確保模型在整個生成過程中持續感知完整圖像資訊。第二路徑則針對輸出標記（output tokens）：每個新標記僅關注其前序 𝑛 個標記（預設 𝑛=128），形成因果滑動視窗（causal sliding window）。此設計使得輸出端的 KV 快取無需隨序列長度累積，而可維持恆定大小（constant KV cache），從而將記憶體消耗（memory consumption）與注意力計算成本（attention computation costs）從線性複雜度降為常數級（就輸出歷史而言）。

值得注意的是，作者刻意區分 R-SWA 與線性注意力（linear attention）的差異。在 OCR 場景中，視覺標記若經歷遞迴狀態更新（recurrent state updates），其特徵將逐漸模糊，進而降低辨識準確率。R-SWA 透過對參考標記保留全注意力、對輸出標記採用固定視窗，避免了視覺特徵的遞迴退化，同時維持了解碼效率。

在架構（Architecture）層面，Unlimited OCR 以 DeepSeek OCR 為基線，保留其深度編碼器（Deep Encoder）——該編碼器透過級聯視窗注意力 ViT 與全局注意力模組，實現 16× 的標記壓縮率（token compression ratio），有效縮短前綴長度。隨後，作者將解碼器中的所有注意力層（attention layers）替換為 R-SWA。此組合使得 Unlimited OCR 能在標準最大長度（standard maximum length）32K 的限制下，於單次前向傳遞（forward pass）中完成數十頁文件的轉錄，無需採用逐頁處理（page-by-page processing）的 for 迴圈範式（for-loop paradigm）。

從 KV 快取管理（KV cache management）角度分析，R-SWA 的恆定快取設計意味著推論延遲不會隨文件頁數增加而遞減，這與人類在長時間抄寫中效率不衰減的特性一致。此外，論文提及針對 R-SWA 進行了 Kernel 研究（Kernel study），顯示作者不僅在演算法層面提出創新，亦針對 GPU Kernel 之設計與優化進行工程實作，以確保理論上的計算節省能真正轉化為牆上時鐘時間（wall-clock time）的加速。

#### 實驗數據解讀

在評估（Evaluation）階段，作者採用 OmniDocBench v1.5 作為主要基準測試與指標（Benchmark and Metrics）。Unlimited OCR 在此基準上達到 93% 的分數，相較於 DeepSeek OCR 基線提升 6%。在文件解析領域，6% 的絕對增益屬於顯著進步，顯示 R-SWA 不僅是效率優化手段，其本身亦具備更適配結構化輸出生成的歸納偏置（inductive bias）。這項「適度的通用 OCR 準確率提升」（modest improvement in general OCR accuracy）暗示：限制輸出端注意力範圍反而能減少長程生成中的累積雜訊與注意力分散，使模型更專注於局部上下文與全局視覺參照的協同。

長程解析（Long-horizon Parsing）實驗是本文最具區別性的成果。作者宣稱 Unlimited OCR 可在單次前向傳遞中解析數十頁文件。此能力來自兩項技術的乘數效應：其一為編碼器端的高壓縮率（high compression rate），將多頁圖像壓縮為有限的視覺標記；其二為解碼器端的恆定 KV 快取，使生成過程不受輸出長度牽制。在標準最大長度 32K 的設定下達成此目標，意味著該模型已具備商業級長文件處理的潛力，無需依賴外部排程器（external scheduler）進行分段處理。

關於子類別研究（Subcategory Study）與效率分析（Efficiency Analysis），雖然本文提供的節錄未揭露詳細數據，但從架構設計可推論：R-SWA 將自注意力運算從 𝑂(𝐿²) 降為輸出端的 𝑂(𝑛·𝐿)（其中 𝑛=128 為固定視窗，𝐿 為輸出長度），實質上等價於線性複雜度。當輸出長度達到數萬個標記時，此設計在記憶體佔用與生成速度（generation）上的優勢將呈指數級放大。作者指出這是對多模態大型語言模型（MLLMs）線性複雜度注意力在 OCR 長程場景中的初步驗證（preliminary validation），顯示未來在更長上下文（如整本書籍或數小時音訊）的應用值得期待。

#### 與現有研究的比較

本文將現有 OCR 方法劃分為管線式框架（Pipeline-based Framework）與端到端模型（End-to-end Model）兩大範式。管線式方法雖具靈活性，但依賴檢測模型、多個辨識運算子與各種啟發式策略（heuristic strategies）的拼接，其 for 迴圈範式本質上將連貫的長程過程碎片化為外部排程器管理的孤立短任務。Unlimited OCR 則屬於端到端範式，將文字檢測與辨識合併為單一統一函數，並透過 R-SWA 維持連續的內部認知狀態，這在概念上更接近 AGI 導向智慧（AGI-purpose intelligence）所需的長程依賴建模能力。

與直接基線 DeepSeek OCR 相比，兩者共享相同的高壓縮編碼器（High-compression Encoder）與混合專家（MoE）架構（啟動值僅 500M），但關鍵差異在於解碼器（High-efficiency Decoder）的注意力機制。DeepSeek OCR 雖透過 MoE 降低了啟動參數量，但其 KV 快取仍隨解碼上下文持續增長，這正是 Unlimited OCR 著力解決的核心瓶頸。R-SWA 的提出，使得模型在保持語言先驗分佈（prior distribution of language）優勢的同時，擺脫了長序列生成的記憶體詛咒。

然而，本文亦坦承若干限制。首先，R-SWA 目前主要針對參考型任務（reference-based tasks）設計，其通用性雖在理論上可延伸至自動語音辨識（ASR）與翻譯（translation），但尚未在這些領域提供大規模實證。其次，6% 的準確率提升雖顯著，但作者自評為「適度」（modest），暗示在模型容量（當前仍低於 3B 參數）或訓練資料規模上仍有向上空間。此外，固定視窗大小 𝑛=128 雖在 OCR 中有效，但對於需要更長輸出依賴的任務（如跨段落邏輯推理）是否足夠，仍待驗證。

#### 可重現性評估

在開源與可重現性方面，作者明確聲明程式碼與模型權重（codes and model weights）已公開於 http://github.com/baidu/Unlimited-OCR，此舉大幅提升了研究的可重現性（reproducibility）。對於端對端 OCR 這類工程導向的領域，模型權重的釋出允許研究者直接驗證 OmniDocBench v1.5 上的 93% 表現，並在相同硬體環境下比較長程解析的記憶體佔用曲線。

不過，論文中提及的資料引擎（Data Engine）與實作細節（Implementation Details）在提供的節錄中著墨有限。端到端 OCR 模型的訓練往往高度依賴大規模合成資料與清洗管線，若訓練資料集或資料引擎的具體構建流程未完整開源，第三方研究者雖可進行推論復現，但在從頭訓練（training from scratch）或微調（fine-tuning）時可能面臨資料落差。此外，R-SWA 涉及客製化 GPU Kernel 之設計與優化（Kernel study），其效能增益高度依賴底層 CUDA 實作；若 Kernel 程式碼未隨論文一併釋出，則其他框架（如 PyTorch 原生實作）可能無法完全複製其效率分析（Efficiency Analysis）中的牆上時鐘加速比。

整體而言，Unlimited OCR 在模型權重與推論程式碼的開放程度上已達社群期待，但若要達成「完全可重現」的標準，訓練配方（training recipe）、資料混合策略（data mixture strategy）與底層 Kernel 實作仍是未來可進一步透明的環節。

#### 未來研究方向

R-SWA 作為通用解析注意力機制（general-purpose parsing attention mechanism），其應用潛力遠超過光學字元辨識（OCR）。最直接的研究延伸是將其遷移至自動語音辨識（ASR）與翻譯（translation）等參考型長程任務。在 ASR 中，聲學特徵可視為參考標記，而文字轉錄則為輸出標記；R-SWA 的恆定 KV 快取設計可望解決數小時音訊轉錄中的記憶體瓶頸。在翻譯場景中，源語言編碼可作為固定參考，目標語言生成則透過滑動視窗維持線性複雜度。

在方法論層面，未來研究可探索動態視窗機制。當前 R-SWA 採用固定 𝑛=128 的輸出注意力視窗，但不同任務或不同生成階段對工作記憶長度的需求可能不同。引入可學習或輸入適應性（input-adaptive）的視窗大小，或設計層級式滑動視窗（hierarchical sliding window），可能在保持效率的同時進一步提升準確率。此外，將 R-SWA 與其他線性複雜度注意力變體（如狀態空間模型 State Space Models 或線性注意力）結合，針對輸出標記設計更複雜的狀態轉換函數，亦是值得探索的方向。

在系統層面，Kernel 研究（Kernel study）仍有深化空間。針對 R-SWA 的非對稱注意力模式（全參考注意力 + 局部輸出注意力）設計專用 FlashAttention 風格的記憶體排程與分塊策略，可進一步壓榨 GPU 利用率。同時，隨著上下文長度持續擴展，超越目前 32K 標準最大長度、邁向數百萬標記的「整本書籍」解析，將考驗編碼器端的壓縮極限與解碼器端的恆定快取設計之協同效應。

最後，從認知科學與 AGI 導向智慧（AGI-purpose intelligence）的視角，R-SWA 提供了一個具體的計算模型來模擬人類的有限工作記憶。未來研究可藉由認知實驗比較人類抄寫行為與 R-SWA 的注意力熱區分佈，進而設計出更符合生物可解釋性（biologically plausible）的長程生成架構，使多模態大型語言模型（MLLMs）在面對簡單卻漫長的解析任務時，真正逼近人類的認知效率。

## 論文問答

**Q1：Unlimited OCR 旨在解決的核心問題是什麼？**
A：現有的端到端 OCR 模型在採用大型語言模型作為解碼器時，隨著輸出序列增長，KV 快取會線性累積，導致記憶體消耗劇增且生成速度逐漸下降。這使得當前模型無法在單次前向傳遞中處理長達數十頁的文件，只能退而求其次使用逐頁處理的 for 迴圈範式。Unlimited OCR 透過提出參考滑動視窗注意力機制（R-SWA），在整個解碼過程中維持恆定的 KV 快取，從根本解決了長程解析時的效率與記憶體瓶頸。

**Q2：為何現有的端到端 OCR 方法在長程文件解析任務中會失敗？**
A：現行模型普遍在解碼器中使用標準全注意力機制，這使得每生成一個新詞元都必須保留並計算所有歷史鍵值，造成 KV 快取隨序列長度持續膨脹。此外，現有系統通常採用逐頁重置記憶體的 for 迴圈處理方式，這種做法將連貫的長程任務切割成彼此孤立的短任務，完全喪失了人類在抄寫時維持的連續認知狀態。這種工程上的權宜之計不僅效率低落，也與人類僅需參考鄰近上下文即可持續工作的自然機制背道而馳。

**Q3：解決長程 OCR 問題對於邁向 AGI 導向智慧有何重要性？**
A：對人類而言，抄寫數百頁書籍或翻譯數小時音訊這類長程任務看似簡單，卻是當前人工智慧系統的明顯短板，凸顯了模型在持續性認知處理上的根本缺陷。逐頁重置記憶體的 for 迴圈範式僅是工程上的變通方案，無法讓模型建立並維持跨頁的連貫語境與認知狀態。唯有突破此限制，多模態大型語言模型才能處理真正連貫的長時程任務，朝通用人工智慧所需的自主、持續且一致的理解能力邁進。

**Q4：Unlimited OCR 提出的核心方法是什麼？**
A：本文提出參考滑動視窗注意力機制（Reference Sliding Window Attention, R-SWA），並以 DeepSeek OCR 為基線，將其解碼器中所有的注意力層全面替換為此機制。R-SWA 的設計讓每個生成詞元都能完整感知所有參考詞元（包含視覺詞元與提示），但僅對先前生成的輸出詞元維持一個固定大小的因果滑動視窗（預設為 128 個詞元）。這種架構確保了推論過程中的 KV 快取大小保持恆定，同時大幅降低注意力計算成本，使模型得以在標準 32K 最大長度內單次解析數十頁文件。

**Q5：與標準全注意力及線性注意力相比，R-SWA 的關鍵創新何在？**
A：標準全注意力需要回溯整個輸出歷史，導致 KV 快取與計算量隨序列長度線性增長，而 R-SWA 透過限制輸出詞元間的自注意力僅在局部滑動視窗內進行，從根本上解決了記憶體膨脹問題。相較於線性注意力機制，R-SWA 避免了對視覺或參考詞元進行遞迴狀態更新，因為這類更新會逐漸模糊視覺特徵並降低辨識準確度。此設計更貼近人類的解析工作記憶：在抄寫時不會反覆檢視已寫下的全部內容，僅需瞥視鄰近上下文即可掌握進度，從而在效率與視覺保真度之間取得平衡。

**Q6：Unlimited OCR 在架構設計上做出了哪些關鍵選擇？**
A：作者保留了 DeepSeek OCR 的 Deep Encoder，因為其具備 16 倍的高壓縮率，能將多頁文件的視覺資訊壓縮為極短的詞元序列，這對多頁長程解析的解碼效率至關重要。在解碼器端，則全面採用 R-SWA 取代原有的全注意力機制，直接針對當前端到端模型中最影響推論成本與最大生成长度的 KV 快取瓶頸進行攻擊。這種「高效編碼器＋恆定記憶體解碼器」的組合，讓 Unlimited OCR 無需暴力擴展訓練上下文長度，即可在單次前向傳遞中完成整本書籍的轉錄。

**Q7：Unlimited OCR 在哪些基準測試上進行評估，關鍵量化結果為何？**
A：Unlimited OCR 在 OmniDocBench v1.5 基準測試上進行評估，達到了 93% 的準確率，較 DeepSeek OCR 基線顯著提升了 6 個百分點。這項結果證明 R-SWA 不僅解決了長程生成的效率問題，還能帶來一般 OCR 準確率的實質進步。此表現也打破了「縮小注意力範圍必然損害效能」的直覺，顯示適當的局部注意力設計反而能提升文件解析的整體表現。

**Q8：作者如何驗證 R-SWA 在長程解析情境中的有效性？**
A：論文展示 Unlimited OCR 能在標準 32K 最大長度限制下，於單次前向傳遞中轉錄數十頁的文件內容，這是現有 OCR 模型無法達成的能力。此成就歸功於 R-SWA 的恆定 KV 快取設計，它徹底消除了過去迫使模型採用逐頁 for 迴圈處理的記憶體障礙。這項驗證不僅是對 Unlimited OCR 本身的實證，更是對線性複雜度注意力架構在多模態大型語言模型中處理長程解析任務的初步概念驗證。

**Q9：關於 R-SWA 的影響，文中是否提及消融實驗或子類別分析？**
A：雖然提供的文本中目錄包含子類別研究一節，但主要結果明確指出 R-SWA 在效率提升之外，也為一般 OCR 準確率帶來了「適度的進步」。在 OmniDocBench v1.5 上超越基線 6% 的表現，可作為間接的消融證據，說明滑動視窗限制並未損害細粒度辨識性能，甚至可能對解碼過程產生規則化效果。作者將此視為架構修改成功平衡計算效率與任務準確度的佐證，涵蓋了多樣化的文件解析場景。

**Q10：Unlimited OCR 在哪些實際應用場景中能發揮最大優勢？**
A：Unlimited OCR 特別適合需要一次性數位化整本書籍、冗長法律合約或數十頁學術論文的場景，能免除外部排程器逐頁拼接所帶來的錯誤累積與流程碎片化。由於 KV 快取恆定，即便生成數千個詞元後，推論速度與記憶體佔用也不會惡化，因此對延遲與資源敏感的即時應用也極具價值。此外，任何需要跨頁維持語境一致性（例如專業術語統一或章節間邏輯連貫）的工作流程，都能因其連續認知狀態而顯著受益。

**Q11：部署 Unlimited OCR 時應考量哪些產品化因素？**
A：部署時需注意 Unlimited OCR 仍仰賴高壓縮編碼器與 MoE 解碼器架構，其底層運算（如文中提及的 Kernel 研究）可能需要特定的硬體加速與優化才能發揮完整效益。R-SWA 的滑動視窗大小（預設 128）是一個可調整的超參數，產品團隊應根據文件類型與局部上下文需求的權衡進行調校。另一方面，由於模型權重與程式碼已公開，企業可在繼承其長程處理能力的基礎上，針對特定領域文件進行微調與落地部署。

**Q12：R-SWA 可能對 OCR 以外的多模態 AI 領域帶來何種影響？**
A：作者明確將 R-SWA 定位為通用解析注意力機制，指出其同樣適用於自動語音辨識（ASR）、翻譯等以參考序列為基礎的長程任務，因為這些任務的輸入可作為穩定參照，而輸出則需持續延伸。此研究證明了線性複雜度注意力在密集預測任務上能媲美甚至超越全注意力基線，促使學界重新思考多模態大型語言模型中無限制 KV 快取是否真的必要。長遠來看，這項成功可能推動視覺-語言與語音-語言模型朝向更記憶體高效的解碼器設計發展，讓各類長程多模態任務變得更可擴展且易於部署。

**Q13：作者承認 Unlimited OCR 與 R-SWA 存在哪些限制？**
A：論文坦承此研究目前僅是對線性複雜度注意力在 OCR 任務上的初步驗證，更廣泛的跨基準與跨模態實證仍有待後續補充。滑動視窗的設計本質上限制了解碼器對遙遠輸出詞元的直接存取，對於需要超出局部視窗之長程輸出依賴的任務，理論上可能存在侷限。此外，現有評估主要聚焦於解析性能與效率，針對版面極度複雜或罕見字體的文件，R-SWA 的視覺參考機制是否會面臨壓力，尚需更深入的分析。

**Q14：在哪些失敗案例或情境中，R-SWA 的表現可能不如全注意力機制？**
A：若文件內容需要頻繁回顧數百個詞元前生成的文字才能正確理解當前語境（例如結構繁複的數學證明或具有遠距條款呼應的法律文件），R-SWA 的 128 詞元局部視窗可能無法提供足夠的輸出間全域依賴資訊。雖然視覺與參考詞元保持完全可及，但輸出端的嚴格局部自注意力使得模型難以透過輸出-輸出關係建立全局連貫性。此外，若編碼器的高壓縮率在極複雜版面中損失了細微的空間細節，解碼器有限的局部上下文也可能缺乏足夠資訊來糾正視覺歧義。

**Q15：作者對此研究的未來方向有何展望？**
A：作者計畫將 R-SWA 擴展至 ASR、翻譯等其他長程參考型任務，驗證恆定 KV 快取設計是否能跨不同模態與輸出詞彙空間通用化。他們也暗示將持續投入 Kernel 層級的優化與架構精進，以在生產環境中極大化 R-SWA 的效率優勢。展望未來，他們期望將這種記憶體高效的注意力典範整合到更通用的多模態大型語言模型中，推動模型朝向能夠連貫、持續處理任意長度輸入與輸出的 AGI 導向智慧邁進。

## 實務應用指南

### 適用場景

1. **整本書籍與長篇檔案的一次性數位化**  
   圖書館、出版社或法律事務所常有將數百頁紙本掃描檔轉為可編輯電子檔的需求。Unlimited OCR 可在單次前向傳遞中解析數十頁文件，無需逐頁 for 迴圈處理，能顯著簡化批次數位化管線並降低排程複雜度。

2. **金融與醫療多頁表單的結構化萃取**  
   保險理賠申請書、病歷報告或財務揭露文件通常跨頁且具連貫格式。利用 R-SWA 的恆定 KV 快取設計，模型可在不重置記憶體的情況下維持跨頁上下文，適合需要長程相依性的表格與段落還原任務。

3. **即時會議與法庭紀錄的長時段語音轉寫（ASR）**  
   論文明確指出 R-SWA 是通用解析注意力機制，可遷移至自動語音辨識。對於數小時的會議逐字稿生成，R-SWA 能避免傳統解碼器因序列增長而導致的記憶體膨脹與生成降速。

4. **技術文件與論文的多語言翻譯管線**  
   學術或工程文件常含圖表標註與跨頁公式說明。將 Unlimited OCR 作為前端解析器，搭配後端翻譯模型，可在單一推理流程中完成「影像 → 結構化原文 → 目標語言」的端到端處理。

5. **邊緣裝置上的有限記憶體長文件閱讀**  
   由於 KV 快取在整個解碼過程中保持恆定，記憶體佔用可預測且遠低於傳統 LLM 解碼器。這使得在具備 24GB 顯存的單卡工作站甚至高階邊緣伺服器上處理長篇文件成為可行。

### 實作前置條件

**資料準備**
- 多頁文件影像資料：建議準備解析度 300 DPI 以上的 PDF 或 TIFF 掃描檔，並依據 Deep Encoder 的輸入規格進行裁切與正規化。
- 結構化標註資料：對應的 Ground Truth 需包含 Markdown、HTML 或 JSON 格式的版面資訊（標題、表格、段落），以便訓練或評估端到端輸出品質。
- 領域詞表：針對金融、醫療或法律場景，建議收集專有名詞對照表以輔助後處理校正。

**運算資源**
- **推理**：至少一張具備 24GB VRAM 的 GPU（如 NVIDIA A10 或 RTX 4090）。雖然 R-SWA 將 KV 快取壓制為恆定，但編碼器仍需一次性處理高壓縮前的多頁視覺特徵，輸入序列長度仍會隨頁數增加。
- **微調**：若需進行領域適應，建議配置 4×A100 80GB 或同等級多卡叢集，並啟用 DeepSeek OCR 基線中的 MoE 訓練框架。
- **儲存**：模型權重與數十頁高解析度影像暫存需預留至少 200GB 高速 SSD 空間。

**技術能力**
- 熟悉 PyTorch 與 Hugging Face Transformers 生態，具備修改 Decoder Attention Mechanism 的能力。
- 具備 CUDA Kernel 基礎調校經驗（論文第 3.4.3 節提及 Kernel study），因 R-SWA 並非標準 Full Attention，現成推理框架（如 vLLM）可能需客製化 Plugin。
- 了解視覺語言模型（VLM）的訓練流程，特別是 Encoder-Decoder 架構中的視覺 Token 壓縮與對齊。

### 實作步驟建議

**步驟一：環境建置與基線驗證**  
從官方倉庫取得 Unlimited OCR 程式碼與權重，先以單頁文件復現 OmniDocBench v1.5 的 93% 準確率基線，確認 Deep Encoder 的 16× Token 壓縮率與 R-SWA 模組運作正常。

**步驟二：多頁資料前處理與編碼器壓力測試**  
將目標文件依頁面順序拼接為單一影像張量（或依模型支援的格式堆疊），觀察在 32K 標準最大長度下，編碼器能否將數十頁內容壓縮為固定長度的視覺 Token。此階段需特別檢查微小字體或細線表格是否因高壓縮而遺失。

**步驟三：R-SWA 推理管線搭建**  
設定 R-SWA 的滑動視窗大小（預設 𝑛=128），確保解碼器在生成每個新 Token 時，僅對前 128 個輸出 Token 與全部參考 Token（視覺特徵與 Prompt）進行注意力計算。驗證 KV 快取佔用在第 1 頁與第 30 頁時保持一致。

**步驟四：領域適應微調（選用）**  
若基礎模型在特定字體或版面表現不佳，可凍結 Deep Encoder，僅以 LoRA 或全參數微調 R-SWA Decoder。由於 KV 快取恆定，可嘗試較大的批次大小（batch size）以加速訓練。

**步驟五：Kernel 層級優化**  
參考論文第 3.4.3 節，針對 R-SWA 的非標準注意力模式（Reference Token 全可見、輸出 Token 局部滑動）撰寫或編譯客製化 FlashAttention Kernel，降低記憶體搬移與計算延遲。

**步驟六：產品化整合與監控**  
將模型封裝為 gRPC/REST API，並建立「頁數 → 預估延遲」的監控儀表板。由於 R-SWA 的計算成本與生成長度呈近似線性而非二次增長，延遲預測會比傳統 LLM 解碼器更穩定。

### 潛在風險與注意事項

- **跨頁長程語意斷裂**：R-SWA 的輸出端僅關注前 𝑛（預設 128）個 Token，若文件存在跨頁表格、章節標題與內文相隔過遠的邏輯關聯，模型可能遺失對齊資訊。**緩解措施**：對於結構極度複雜的文件，可先以 Unlimited OCR 進行段落級分頁標記，再以外部輕量排程器進行二次組裝，而非完全依賴單次 32K 生成。
- **編碼器壓縮失真**：Deep Encoder 的 16× 高壓縮率雖是長程解析的關鍵，但對低解析度影像或特殊字體（如篆書、手寫體）可能造成特徵混疊。**緩解措施**：在正式導入前，先以領域樣本測試編碼器重建品質，必要時於資料引擎階段加入超解析度增強。
- **生態工具鏈相容性**：R-SWA 並非標準的 Full Attention 或 GQA，現有推理加速框架（如 TensorRT-LLM、vLLM）可能無法直接支援。**緩解措施**：預留 2–4 週工程人力進行客製化 Kernel 移植，或優先採用論文官方實作作為初期部署基底。
- **恆定 KV 快取的誤解**：雖然 Decoder 的 KV 快取恆定，但 Encoder 端的視覺特徵長度仍與輸入頁數成正比。若一次餵入過多頁面，首階段編碼器計算仍可能觸發 OOM。**緩解措施**：設定單次請求的上限頁數（如 20–30 頁），或採用分層編碼策略。

### 與其他技術的整合建議

- **與 RAG（檢索增強生成）系統整合**：將 Unlimited OCR 作為文件攝取層的前置解析器，把多頁掃描檔轉為帶版面標記的結構化文字後，直接送入向量資料庫（如 Milvus、Pinecone）。由於輸出品質優於傳統管線式 OCR，後續檢索的召回率通常可提升。
- **與傳統管線式 OCR 形成混合架構**：對於 Unlimited OCR 較不擅長的極複雜公式或印章識別，可保留傳統「檢測 → 裁切 → 專家模型」作為 Fallback 路徑。透過信心分數閘道自動分流，兼顧端到端效率與極端案例準確率。
- **與通用 LLM 服務串接**：Unlimited OCR 的解碼器輸出為純文字，可直接作為 GPT-4、Claude 或內部 LLM 的上下文輸入。特別適合「整本書摘要」或「跨章節問答」產品，省去過往需多次呼叫頁面級 OCR 的成本。
- **遷移至 ASR 與翻譯後端**：若企業已建置語音或翻譯產品，可將 R-SWA 機制抽換為解碼器的通用注意力模組。這能統一長序列任務的後端架構，降低維護多種注意力實作的工程負擔。

### 給不同背景讀者的閱讀建議

**給初學者**：請從第 1 節「人類抄寫行為」的類比開始讀起，把 R-SWA 想像成「邊看原文邊抄寫，但只回頭看最近寫的幾個字來確認進度」的工作記憶模式。先建立「為何傳統模型處理長文件會越來越慢」的直覺，再回頭對照論文圖一，技術細節如 Kernel study 可暫時略過。

**給 AI 工程師**：請聚焦第 3.4 節「Reference Sliding Window Attention」與 3.4.2 節「KV cache management」。這是將理論轉為產品的核心——您需要理解如何把現有 Transformer Decoder 的 Attention Layers 替換為 R-SWA，並確認在推理階段 KV 快取確實維持恆定。強烈建議邊讀邊對照官方程式碼中的 Attention Mask 建構邏輯。

**給研究人員**：請深入比較 R-SWA 與 Linear Attention、Sliding Window Attention 的理論邊界，特別注意論文強調「視覺／參考 Token 不進入遞迴狀態更新」的設計動機——這是避免視覺特徵模糊化的關鍵。第 5.4 節的長程解析實驗與第 6 節效率分析，是驗證此機制能否推廣至 ASR、翻譯等任務的主要依據。

**給產品經理**：請掌握「單次前向傳遞處理數十頁」的商業價值：這代表系統無需外部頁面排程器與記憶體重置機制，能顯著降低延遲與架構複雜度。同時留意論文提及 R-SWA 可擴展至 ASR 與翻譯，這為產品路線圖從「文件 OCR」延伸至「長時段語音轉寫」與「整書翻譯」提供了明確的技術槓桿。
