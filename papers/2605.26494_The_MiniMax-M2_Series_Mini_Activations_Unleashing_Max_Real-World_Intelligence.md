## 摘要翻譯

我們提出 MiniMax-M2 系列（MiniMax-M2 Series），這是一系列基於「精簡啟動（mini activations）能夠釋放最大真實世界智慧」原則所建構的混合專家模型（Mixture-of-Experts, MoE）語言模型。旗艦版 M2 的總參數量（total parameters）達 229.9B，每詞元啟動參數量（activated parameters per token）僅 9.8B。M2 系列專為代理式部署（agentic deployment）進行端對端設計，基於三大核心組件：（i）智慧代理驅動資料管線（agent-driven data pipelines），在代理式程式編寫（agentic coding）與代理式協同工作（agentic cowork）中產生大規模可驗證軌跡（verifiable trajectories），每項均基於可執行工作空間（executable workspace）與產出對齊獎勵（artifact-aligned reward）；（ii）Forge，一套可擴充的代理原生強化學習系統（agent-native RL system），能適應長程智慧代理軌跡（long-horizon agent trajectories），並搭配視窗式先進先出排程（windowed-FIFO scheduling）、前綴樹合併（prefix-tree merging）、推論最佳化（inference optimization）等機制，以及簡潔的訓練-推論-代理解耦（training-inference-agent decoupling），同時支援白箱智慧代理（white-box agents）與黑箱智慧代理（black-box agents）；（iii）最新的 M2.7 檢查點（M2.7 checkpoint）初步邁向自我演化（self-evolution）——能夠自主為訓練執行（training runs）除錯，並自行修改其腳手架（scaffold）。從 M2 到 M2.7，這樣的組合將精簡啟動足跡（mini-activation footprint）轉化為代理式程式編寫（agentic coding）、深度搜尋（deep search）、辦公任務（office-task）與推理基準測試（reasoning benchmarks）上的前沿級性能（frontier-tier performance）。

### 核心貢獻（3～5點）
- 提出 MiniMax-M2 系列，以「精簡啟動」為核心設計理念，僅以 9.8B 每詞元啟動參數量駕馭 229.9B 總參數量，並專為代理式部署進行端對端設計。
- 建立智慧代理驅動資料管線，透過可執行工作空間與產出對齊獎勵，產生代理式程式編寫與代理式協同工作的大規模可驗證軌跡。
- 開發 Forge 可擴充代理原生強化學習系統，採用視窗式先進先出排程、前綴樹合併、推論最佳化與訓練-推論-代理解耦，支援長程智慧代理軌跡與白箱／黑箱智慧代理。
- 最新 M2.7 檢查點展現自我演化雛形，可自主為訓練執行除錯並修改自身腳手架

## 深度分析

#### 方法論解析

**1. 精簡啟動（Mini Activations）的稀疏架構設計**
MiniMax-M2 系列的核心設計原則在於以極小的每詞元啟動參數量（activated parameters per token）換取最大的真實世界智慧。旗艦模型 M2 採用 62 層 decoder-only Transformer，總參數量（total parameters）達 229.9B，但每詞元僅啟動 9.8B 參數，形成極為精簡的啟動足跡（mini-activation footprint）。其前饋層使用混合專家模型（Mixture-of-Experts, MoE）架構，具備三項關鍵修改：首先，採用 256 個精細化專家（fine-grained experts），透過增加專家總數並縮小單一專家的 FFN 規模，提升路由組合多樣性並降低跨裝置的專家利用率變異；其次，以 sigmoid 門控（sigmoid gating）取代傳統 softmax top-k 路由，消除零和競爭限制，使多個專家可同時以高置信度被啟動，平滑訓練動態；第三，引入可學習的專家偏置項（expert bias）作為每個專家的路由分數偏移，與模型參數聯合優化，從而大幅降低對輔助損失（auxiliary losses）的依賴。注意力機制方面，M2 在所有層採用完整多頭注意力（full multi-head attention）搭配分組查詢注意力（Grouped-Query Attention, GQA），使用 48 組查詢頭與 8 組鍵值頭，並以旋轉位置編碼（Rotary Position Embeddings, RoPE）處理最長 192K 詞元的原生上下文。此外，預訓練階段納入多詞元預測（Multi-Token Prediction, MTP）模組，該模組在持續預訓練時透過權重複製擴展，於推論階段兼作多步推測解碼（speculative decoding）的草稿路徑，實現訓練與推論的協同設計。

**2. 代理驅動資料管線與可驗證獎勵**
M2 系列的後訓練（post-training）能力並非來自靜態語料，而是建立在智慧代理驅動資料管線（agent-driven data pipelines）之上。該管線針對代理式程式編寫（agentic coding）、代理式協同工作（agentic cowork）、推理與通用知識任務，大規模產出可驗證軌跡（verifiable trajectories）。每條軌跡都對應具備執行能力的可執行工作空間（executable workspace），並以產出對齊獎勵（artifact-aligned reward）作為訊號。研究團隊強調，提升每條被採納軌跡的獎勵品質與可信度——無論是透過可執行驗證訊號或法官模型（judge-model）的證據檢查——對於釋放基座模型潛能至關重要。這種設計將資料建構從「靜態標註」轉向「動態環境互動」，使模型學習的是可執行、可驗證的真實世界決策序列，而非僅是文字模式複製。

**3. Forge：代理原生強化學習系統**
為了支撐長程智慧代理軌跡（long-horizon agent trajectories）的大規模強化學習，作者提出 Forge，一套代理原生強化學習系統（agent-native RL system）。Forge 的核心創新在於訓練-推論-代理解耦（training-inference-agent decoupling）：將訓練流程、推論服務與代理本體分離，使系統能無縫接納白箱智慧代理（white-box agents）與黑箱智慧代理（black-box agents, API-only）於統一訓練迴路中。演算法層面，Forge 採取穩健性優先（robustness-first）的設計，並建構精細的獎勵系統以實現穩定的 RL 規模化（RL-time scaling）。系統層面，Forge 引入視窗式先進先出排程（windowed-FIFO scheduling）以吸收軌跡長度變異，並透過前綴樹合併（prefix-tree merging）與和部署堆疊共同設計的推論核心（inference kernels），顯著提升 RL 訓練效率與可擴展性。這種系統-演算法-代理的垂直整合，解決了傳統 RLHF 框架難以處理長期互動、工具呼叫與外部 API 代理的瓶頸。

**4. 自我演化與推論最佳化**
在 M2.7 檢查點（checkpoint）中，作者展示了自我演化（self-evolution）的早期運作形式：模型能夠在自有基礎設施上自主分類（triage）失敗的訓練運行、編輯自身的腳手架（scaffold），並在具代表性的機器學習工程任務上執行多輪自我改進。這標誌著模型開始關閉「人類在迴路」（human-in-the-loop）中最昂貴的瓶頸之一。推論端則受益於 MTP 模組的雙重用途：預訓練時作為輔助目標提升表徵品質，推論時則作為推測解碼（speculative decoding）的草稿模型，降低長上下文代理任務的生成延遲。

#### 實驗數據解讀

**1. 代理式程式編寫（Agentic Coding）**
M2.7 在 SWE-bench Pro 達到 56.2、SWE-bench Multilingual 達到 76.5、Multi-SWE-bench 達到 52.7、Terminal-Bench 2.0 達到 57.0。這些數字顯示，僅以約 10B 啟動參數，模型已能處理生產級軟體工程任務，包含多語言程式碼維護、多儲存庫協作與終端機環境操作。SWE-bench 系列向來是區分「程式輔助模型」與「真正代理式工程模型」的試金石，M2.7 的分數已逼近最強閉源前沿系統（closed-weight frontier systems），證明精簡啟動足跡並未犧牲複雜程式推理能力。

**2. 代理式協同工作（Agentic Cowork）**
在辦公任務（office-task）與工具使用場景中，M2.7 於 MM Claw 取得 62.7、BrowseComp 77.8、GDPval-AA 50.0、Toolathlon 46.3。BrowseComp 與 Toolathlon 分別衡量開放網頁導航與異質工具操作能力，這些任務需要數百個交錯推理與行動步驟。M2.7 的表現顯示其長程規劃與環境互動軌跡已達實用門檻，足以支撐知識密集的辦公室自動化流程。

**3. 推理與知識（Reasoning & Knowledge）**
M2.7 在 AIME 2026 達到 94.2、GPQA-Diamond 達到 89.8。AIME 與 GPQA-Diamond 是數學推理與專家級科學問答的黃金標準，94.2 與 89.8 的成績表明模型在抽象符號推理與深度領域知識上同樣具備前沿級性能（frontier-tier performance）。這打破了「稀疏模型僅擅長記憶與檢索」的刻板印象，顯示精細化專家路由與高品質代理後訓練能共同催生強大的通用推理。

**4. 消融實驗趨勢**
雖然提供的表格片段有限，但 Baseline、加入 MTP、以及加入 Fine-Grained Experts 的比較顯示，MATH、MMLU 等基準測試（reasoning benchmarks）上，精細化專家與多詞元預測具有協同增益。這驗證了架構設計空間中「更多小型專家」與「多步預測」對於釋放模型潛能的必要性。

#### 與現有研究的比較

**1. 相較於傳統混合專家模型與稠密模型**
傳統 MoE 通常採用 softmax top-k 門控（Shazeer et al., 2017），其零和競爭特性容易導致路由崩潰（routing collapse）與負載不均。M2 的 sigmoid 門控配合可學習專家偏置，獨立計算每個專家的啟動分數，顯著改善負載平衡並減少輔助損失依賴。相較於總參數量相近的稠密模型，M2 僅啟動不到 5% 的參數，卻能在代理基準上與最強閉源模型並駕齊驅，展現了稀疏架構在生產部署中的效率優勢。

**2. 相較於 MiniMax-Text-01 與其他長上下文模型**
M2 明確捨棄了 MiniMax-Text-01 中的混合注意力機制（hybrid attention），轉而在大規模設定中採用全層完整注意力。這反映作者認為在 192K 上下文與大規模代理訓練場景下，完整注意力的表徵能力優於稀疏或局部注意力模式，即使其計算成本較高，也可透過 MoE 的稀疏前饋層與推論最佳化抵消。

**3. 相較於標準 RLHF 與代理強化學習**
現有 RLHF 框架多針對單輪或短對話優化，且通常假設模型為白箱。Forge 的訓練-推論-代理解耦設計允許黑箱智慧代理僅透過 API 參與訓練迴路，並以視窗式先進先出排程處理長度差異極大的軌跡，這是傳統 PPO/RLHF 難以企及的。此外，產出對齊獎勵與可執行驗證訊號的結合，也比基於人類偏好排序的獎勵模型更適合程式編寫與工具使用等可驗證領域。

**4. 限制（Limitations）**
首先，自我演化（self-evolution）在 M2.7 中僅被描述為「早期步驟」（early step），模型尚無法完全自主地設計新架構或發現全新訓練演算法，其自主除錯與腳手架修改範圍仍受限於人類預設的實驗空間。其次，資料管線高度依賴可驗證軌跡與產出對齊獎勵，這對於創意寫作、開放式對話或缺乏明確驗證器的任務可能難以直接套用。第三，192K 詞元上下文雖大，但面對極端長期的代理工作流程（如數週的專案管理），仍可能需要外部記憶機制或分層摘要架構輔助。最後，全文未提及其他模態（如視覺或音訊），顯示 M2 系列目前仍聚焦於純文字代理任務。

#### 可重現性評估

根據提供的文本，本文未提及任何開源釋出計畫，包括模型權重、訓練程式碼、Forge 系統原始碼或智慧代理驅動資料管線的資料集。M2.7 的自我演化實驗更是在「我們自己的基礎設施」（our own infrastructure）上執行，意味著外部研究者難以複製其完整的訓練與代理互動環境。雖然論文詳細描述了 MoE 架構、sigmoid 門控與 MTP 模組等技術細節，但缺乏超參數、訓練硬體配置、資料過濾流程與獎勵函數的完整規格。因此，就學術社群的標準而言，本研究的可重現性（reproducibility）偏低，其成果目前較接近工業界前沿技術報告，而非可完全獨立驗證的開放科學研究。

#### 未來研究方向

**1. 自我演化的安全性與可控性框架**
M2.7 已展現自主修改腳手架（scaffold）與訓練運行的能力，未來亟需建立形式化的安全護欄（safety guardrails）與可控性機制，確保模型在自我改進過程中不會引入不可預期的行為偏差或獎勵駭取（reward hacking）。

**2. 多模態代理軌跡與跨模態獎勵設計**
當前資料管線聚焦於代理式程式編寫與代理式協同工作。未來可將可驗證軌跡與產出對齊獎勵擴展至多模態場景（如圖形介面操作、視覺導航、多媒體內容生成），並設計跨模態的執行環境與驗證器。

**3. 動態計算分配與自適應專家路由**
sigmoid 門控已使多專家高置信度並行啟動成為可能。後續研究可探索依據任務複雜度動態調整每詞元啟動專家數量或層數，進一步壓縮簡喣任務的推論成本，同時為高難度推理保留計算預算。

**4. 黑箱智慧代理的強化學習理論基礎**
Forge 支援黑箱智慧代理的訓練，但現有 RL 理論多針對白箱設定。未來可發展針對 API-only 代理的樣本效率界限、信用分配（credit assignment）理論與收斂性保證。

**5. 超越 192K 的終身代理記憶機制**
對於需要數千步甚至跨週期執行的終身代理（lifelong agents），原生上下文長度終將遇到瓶頸。研究方向包括分層記憶架構、事件摘要與外部知識庫的無縫整合，以維持長期一致性。

**6. 開放式任務的獎勵模型泛化**
目前系統高度依賴可執行驗證訊號。對於無明確答案的開放式任務，可結合過程獎勵模型（Process Reward Models, PRM）與自動化法官模型，將 Forge 的適用範圍從可驗證領域擴展至創意與人文領域。

## 論文問答

**Q1：當前大型語言模型從單輪對話轉向長程代理式工作流時，面臨哪兩大核心挑戰？**
A：第一，代理式任務固有的超長上下文特性，在訓練與推論階段都帶來嚴重的效率與成本瓶頸，尤其難以滿足大規模高可用性生產部署的嚴苛需求。第二，真實場景部署需要解決本質上極為複雜且高風險的任務，例如生產級軟體工程與知識密集的辦公室自動化流程。這兩項挑戰使得現有模型架構與訓練範式必須重新設計，才能在實際應用中同時兼顧效能與可行性。

**Q2：為何傳統的密集模型或現有方法難以有效應對代理式部署的需求？**
A：傳統密集模型在處理超長上下文時，訓練與推論成本會隨序列長度急劇上升，難以支撐動輒數百個交錯推理與行動步驟的代理式工作流。此外，現有強化學習系統通常未針對長程代理軌跡進行最佳化，也缺乏對白箱與黑箱代理的統一支援，更無法有效整合可執行工作空間與產出對齊獎勵等代理原生需求。因此，既有方法在面對生產級程式編寫與開放網頁導航等高風險任務時，往往因效率不足與訓練不穩定而難以規模化部署。

**Q3：「精簡啟動釋放最大真實世界智慧」這一設計原則為何重要？**
A：該原則讓模型得以在維持極低每詞元運算成本的前提下，大幅擴充總參數容量，例如 M2 擁有 229.9B 總參數卻僅啟動 9.8B。這不僅緩解了代理式任務中超長上下文所帶來的推論與訓練成本壓力，也證明稀疏啟動架構足以支撐前沿級的代理式編碼、深度搜尋與推理能力。對於需要高可用性與大規模部署的真實應用而言，這種以精簡啟動足跡換取頂尖性能的策略，是兼顧經濟性與智慧密度的關鍵。

**Q4：M2 系列在代理原生後訓練管線中，主要包含哪三大核心元件？**
A：第一個元件是智慧代理驅動資料管線，專為代理式程式編寫、協同工作、推理與通用知識任務設計，每項任務都配備可執行環境、可驗證獎勵或可信回饋訊號。第二個元件是 Forge，這是一套可擴展的代理原生強化學習系統，透過訓練-推論-代理解耦、視窗式先進先出排程與前綴樹合併等技術，穩定吸收長程軌跡的長度變異並提升訓練效率。第三個元件則體現在最新的 M2.7 檢查點中，模型展現出早期自我演化能力，能夠自主診斷失敗的訓練執行並修改自身的腳手架。

**Q5：Forge 與傳統大型語言模型強化學習系統相比，其關鍵創新何在？**
A：Forge 是專為智慧代理設計的原生強化學習系統，能夠在統一訓練迴路中無縫接納白箱與黑箱代理，這是傳統系統難以做到的。它透過將訓練、推論與代理本身進行架構解耦，並搭配穩健優先的演算法設計與精細的獎勵系統，實現了高度穩定的 RL 時間規模擴展。此外，Forge 引入視窗式先進先出排程來吸收軌跡長度變異，並結合前綴樹合併與和部署堆疊共同設計的推論核心，顯著提升了大規模代理強化學習的訓練效率與可擴展性。

**Q6：M2 在混合專家模型的設計上，為何選擇細粒度專家與 Sigmoid 門控，而非傳統的 Softmax top-k 路由？**
A：細粒度專家設計透過增加專家總數並縮小每個專家的前饋網路尺寸，提升了路由的組合多樣性，同時降低了跨裝置的專家利用率變異。相較於 Softmax 的零和約束，Sigmoid 門控讓每個專家獲得獨立的啟動分數，使多個專家能同時以高信心度被啟動，從而帶來更平滑的訓練動態。再加上可學習的專家偏置項，系統能在減少輔助損失依賴的情況下改善負載平衡，整體而言這些選擇在數學推理與程式設計等基準測試上都展現出顯著的性能增益。

**Q7：M2.7 在哪些基準測試上達到前沿級表現，其關鍵成績為何？**
A：在代理式程式編寫方面，M2.7 在 SWE-bench Pro 獲得 56.2 分、SWE-bench Multilingual 獲得 76.5 分、Multi-SWE-bench 獲得 52.7 分，以及 Terminal-Bench 2.0 獲得 57.0 分。在代理式協同工作方面，則在 MM Claw 取得 62.7 分、BrowseComp 取得 77.8 分、GDPval-AA 取得 50.0 分、Toolathlon 取得 46.3 分。至於推理與知識領域，M2.7 在 AIME 2026 達到 94.2 分，在 GPQA-Diamond 達到 89.8 分，顯示其僅以約 100 億啟動參數便逼近最強閉源前沿系統的水準。

**Q8：從實驗結果來看，M2.7 的精簡啟動足跡與其性能之間呈現什麼樣的關係？**
A：M2.7 每個詞元僅啟動約 98 億參數，卻能在多項代理式與推理基準測試上達到與最強閉源前沿系統相媲美的成績。這項結果直接驗證了「精簡啟動釋放最大真實世界智慧」的核心假設，即模型總容量可以透過稀疏啟動大幅擴展，而不必付出全參數啟動的昂貴計算代價。這也意味著在生產環境中，開發者得以用更低的推論成本部署具備頂尖智慧的模型，對大規模高可用性應用具有重大實務意義。

**Q9：表一的消融實驗揭示了細粒度專家與多詞元預測模組的哪些設計價值？**
A：消融實驗顯示，相較於基線模型，加入多詞元預測模組與細粒度專家設計後，在 MATH、MMLU、ARC-Challenge、KorBench 與 HumanEval 等測試上均有明顯進步。特別是採用 128 個專家並啟動 top-8 的細粒度配置，在 MATH 四樣本測試中將分數從 19.6 提升至 24.1，表現優於僅使用 32 個專家的對照組。這證明了增加專家數量並降低單一專家規模的策略，能有效釋放模型潛能，而多詞元預測模組也為後續推論階段的推測解碼提供了加速基礎。

**Q10：M2 系列主要針對哪些真實世界場景進行設計與部署？**
A：M2 系列專為長程代理式工作流設計，涵蓋代理式程式編寫、代理式協同工作、深度搜尋與複雜推理等場景。具體而言，模型能夠撰寫並交付生產級程式碼、在開放網頁中導航、操作異質工具，並在數百個交錯推理與行動步驟中產出結構化的辦公產出物。這些場景的共同特徵是任務跨度長、上下文需求極高，且往往涉及可執行環境中的驗證與回饋，因此需要模型具備穩定的長程規劃與工具使用能力。

**Q11：從產品與生產部署的角度，M2 的架構設計如何滿足大規模高可用性的需求？**
A：M2 採用混合專家架構，將每詞元啟動參數控制在約 98 億，顯著降低大規模部署時的推論運算成本與記憶體頻寬壓力。模型具備 192K 詞元的原生上下文窗口，能直接處理長文件與多輪代理軌跡，無需額外的分段或壓縮機制。此外，多詞元預測模組在推論階段可兼作推測解碼的草稿路徑，搭配 Forge 系統中的推論最佳化與前綴樹合併技術，進一步提升了服務的吞吐量與反應速度。

**Q12：M2.7 展現的自我演化能力，可能對前沿模型開發領域帶來什麼樣的衝擊？**
A：M2.7 能夠自主分類失敗的訓練執行、編輯自身的代理腳手架，並在具代表性的機器學習工程任務上執行多輪自我改進，這大幅降低了人類工程師介入例行訓練維護的需求。這項能力被論文視為「關閉了前沿模型開發中最昂貴的人類在環瓶頸之一」，意味著未來模型的迭代週期可能從數週縮短至數天甚至更短。長遠來看，這將推動業界朝向更自主的訓練管線發展，使模型能夠持續自我優化，減少對人工監督與手動除錯的依賴。

**Q13：論文對於 M2 系列目前的侷限性有何暗示或承認？**
A：論文將 M2.7 的自我演化能力描述為「早期操作形式」，暗示該能力尚處於起步階段，尚未達到完全自主或跨領域通用的成熟水準。此外，從 M2 到 M2.5 再到 M2.7 的系列演進軌跡來看，模型能力仍在持續建構與提升之中，顯示現有檢查點並非最終形態。這些表述提醒研究者與實務工作者，雖然 M2 系列已展現強勁性能，但在長程穩定性、自我演化的泛化程度以及更複雜的真實世界任務上，仍有持續精進的空間。

**Q14：儘管 M2.7 在多項基準測試表現優異，哪些類型的任務或情境仍可能對其構成挑戰？**
A：由於 M2 系列的後訓練高度依賴可驗證軌跡與產出對齊獎勵，對於缺乏明確可執行驗證機制或難以定義客觀獎勵訊號的開放式任務，模型可能較難透過現有強化學習管線穩定提升。此外，雖然模型在程式編寫與辦公自動化表現突出，但涉及真實世界物理互動、高度主觀判斷或訓練分佈外領域的任務，仍可能超出其目前的能力邊界。這些限制意味著在部署於高風險且回饋稀疏的環境時，仍需要謹慎的人類監督與額外的安全對齊措施。

**Q15：基於 M2 系列的技術路線，未來研究可以朝哪些方向進一步拓展？**
A：未來研究可進一步深化自我演化能力，使模型不僅能除錯訓練執行，更能自主設計新任務、生成訓練資料並優化自身的強化學習獎勵函數。同時，可將代理原生強化學習系統 Forge 的應用範圍擴展至更多超越程式編寫與辦公任務的領域，例如科學實驗設計或複雜的多模態代理工作流。此外，如何在維持精簡啟動足跡的前提下進一步擴大總參數規模與上下文長度，並提升長程強化學習的穩定性，將是持續推動稀疏模型邁向更廣泛真實世界智慧的關鍵課題。

## 實務應用指南

### 適用場景

1. **大規模軟體工程代理**：利用 M2.7 在 SWE-bench Pro 與 Terminal-Bench 2.0 的表現，部署可自主讀取程式碼庫、撰寫並提交生產級程式碼的代理，處理跨檔案重構、多語言程式碼維護與終端機操作。
2. **深度研究與知識密集型協作**：結合 192K 長上下文與 BrowseComp 能力，建構能執行開放網頁瀏覽、多輪檢索與綜合分析的深度搜尋代理，用於市場情報、法律文件審閱與學術研究。
3. **企業辦公自動化（Agentic Cowork）**：透過 MM Claw、GDPval-AA 與 Toolathlon 能力，串接試算表、簡報、郵件與異質工具，自動生成結構化辦公產出物並執行跨系統工作流程。
4. **自主機器學習工程與基礎設施維運**：借鏡 M2.7 自我演化能力，部署可自主監控訓練任務、診斷失敗執行並修改自身腳手架（scaffold）的維運代理，降低人工介入的迴圈成本。

### 實作前置條件

- **資料與環境**：需準備可執行工作空間（executable workspace）與靜態／執行期環境，以產生大規模可驗證軌跡（verifiable trajectories）。獎勵信號必須可透過執行驗證或裁判模型證據檢查，確保軌跡品質。
- **運算資源**：雖然每詞元僅啟動 9.8B 參數，但總參數量達 229.9B，推論與訓練仍需高記憶體 GPU 叢集。Forge RL 系統需支援長程軌跡的視窗式 FIFO 排程與前綴樹合併（prefix-tree merging）的運算基礎設施。
- **技術能力**：團隊需具備 MoE 模型部署與推論最佳化經驗（含 MTP 投機解碼）、強化學習（RL）演算法調校能力，以及建構代理腳手架與工具整合的工程實力。若整合黑箱代理，需熟悉 API 抽象與統一訓練迴路設計。

### 實作步驟建議

1. **基礎建設與環境封裝**：先建立可執行且可重現的任務空間（如容器化開發環境、瀏覽器模擬器、Office 工具鏈），並定義產出對齊獎勵（artifact-aligned reward）的驗證邏輯。
2. **基座模型部署**：採用 M2 系列作為基座，利用其 192K 原生上下文處理長文件與多輪軌跡；啟用 Multi-Token Prediction（MTP）模組作為投機解碼路徑，降低推論延遲。
3. **代理腳手架開發**：設計模組化腳手架，將訓練、推論與代理本體解耦（training-inference-agent decoupling），預留未來讓模型自主編輯腳手架的擴充介面。
4. **Forge RL 後訓練**：導入 Forge 系統進行大規模代理原生強化學習。採用視窗式 FIFO 排程吸收軌跡長度變異，啟用前綴樹合併與共設計的推論核心以提升 RL 訓練效率。
5. **獎勵品質提升**：優先提升每條被接受軌跡的獎勵可信度——透過執行期驗證訊號（如單元測試、網頁渲染結果）或裁判模型證據檢查，避免雜訊獎勵壓制基座模型潛能。
6. **持續演化與自我改進**：參考 M2→M2.5→M2.7 的演進路徑，建立多輪自我改進迴圈。在 M2.7 階段可試行讓模型自主分類失敗訓練任務、除錯並修改自身腳手架，逐步關閉人工介入瓶頸。

### 潛在風險與注意事項

- **長程軌跡不穩定**：智慧代理任務動輒數百個交錯推理與行動步驟，RL 訓練易發生梯度爆炸或策略崩潰。建議採用 Forge 的穩健性優先演算法設計，並嚴格監控長序列的獎勵分布。
- **獎勵駭客（Reward Hacking）**：可驗證獎勵可能被代理找到捷徑規避。必須多層次驗證（執行結果 + 裁判模型 + 人工抽樣），並持續更新驗證邏輯。
- **運算成本錯覺**：雖然「精簡啟動」降低單詞元成本，但長上下文與多輪代理互動會顯著放大總計算量。需精算每個任務的端到端成本，並利用 MTP 投機解碼與前綴樹合併壓縮延遲。
- **自我演化安全邊界**：M2.7 展示的自我除錯與腳手架修改能力若未加限制，可能導致訓練基礎設施被非預期更動。建議在獨立沙箱中執行自主修改，並保留人工核准閘門與版本控制。
- **黑箱代理整合風險**：Forge 雖支援黑箱代理，但 API 延遲與輸出不可控性會影響 RL 訓練穩定性。需設計超時重試與回退（fallback）機制，並監控 API 成本。

### 與其他技術的整合建議

- **企業 CI/CD 與版本控制**：將代理式程式編寫能力整合至 Git 流程與自動化測試管線，讓 M2 系列代理直接提交 PR、觸發單元測試與程式碼審查工具。
- **向量資料庫與 RAG**：針對深度搜尋場景，將 192K 長上下文與外部向量檢索結合，由模型自主決定何時檢索外部知識、何時依賴內部上下文，避免過度檢索造成的雜訊。
- **辦公軟體與異質工具 API**：透過 Toolathlon 與 MM Claw 能力，串接試算表、簡報、CRM、ERP 等既有系統，使用標準化工具描述格式（如 JSON Schema）讓 Forge RL 訓練能動態適應新工具。
- **可觀測性平台**：整合分散式追蹤與日誌系統，記錄每條長程軌跡的中間步驟與獎勵訊號，便於後續分析代理決策路徑與診斷失敗模式。
- **API 閘道與服務網格**：若同時部署白箱與黑箱代理，建議透過統一 API 閘道管理請求路由、速率限制與成本配額，並利用 Forge 的解耦設計隔離不同代理的訓練與推論負載。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從「精簡啟動」的核心概念出發，理解 Mixture-of-Experts（MoE）如何在啟動極少參數的情況下達到大型密集模型的效能，並聚焦於「智慧代理」與「可驗證軌跡」的應用場景，暫時略過 Forge 系統的 RL 演算法與前綴樹合併等工程細節。
- **AI 工程師**：應深入研讀 Forge 的訓練-推論-代理解耦架構、視窗式 FIFO 排程與前綴樹合併的實作細節，同時評估 MTP 模組作為投機解碼路徑在自家推論堆疊中的整合方式，並留意 MoE 負載平衡與專家偏置（expert bias）的部署調校技巧。
- **研究人員**：請聚焦於 sigmoid gating 與細粒度專家（fine-grained experts）的消融實驗設計、獎勵可信度對基座模型潛能釋放的影響，以及 M2.7 自我演化機制中「自主除錯訓練執行」與「修改自身腳手架」的技術邊界與可擴展性分析。
- **產品經理**：著重理解 MiniMax-M2 系列在 SWE-bench、BrowseComp、AIME 等基準測試的商業意義，評估「每詞元僅 9.8B 啟動參數」帶來的邊際成本優勢，並規劃如何將 agentic coding、cowork 與深度搜尋能力封裝為可收費的企業級代理服務，同時預留自我演化功能降低長期維運人力。
