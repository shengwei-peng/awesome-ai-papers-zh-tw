## ⚡ TL;DR

可複用技能庫雖讓 LLM 智能體跨任務重用知識，但現有檢索難以兼顧成本與技能間程序關聯。
本文提出 CaSKG，以反事實因果探針校準技能圖邊置信度，再離線建構狀態過濾加權圖供檢索擴展。
於六個 LLM 骨幹與兩大基準上，CaSKG 全獲最高任務分，並降低平均環境步數。

## 摘要翻譯

可複用技能庫（reusable skill libraries）使大型語言模型（LLM）智能體（LLM agents）能夠跨任務重複使用程序性知識（procedural knowledge），卻也讓記憶體存取（memory access）成為一項具挑戰性的檢索問題。全庫提示（full-library prompting）雖能維持覆蓋率，但伴隨高昂的上下文成本（context cost）；向量檢索（vector retrieval）可返回緊湊鄰域（compact neighborhoods），卻將技能視為獨立文本；而基於圖的檢索（graph-based retrieval）只有在承載相關性的邊足夠可靠時，才能恢復工作流程上下文（workflow context）。本研究提出 CaSKG（Counterfactual-Causal Skill Graphs，反事實因果技能圖），一種能在檢索前校準程序關係（procedural relations）的反事實因果技能圖框架。CaSKG 首先根據語義、詞彙、輸入／輸出與結構證據（semantic, lexical, input/output, and structural evidence）建立一個高召回率的有向候選圖（directed candidate graph），並以修復證據（repair evidence）與可選的 LLM 評判器（LLM judge）進一步精煉候選分數（candidate scores）。接著，它應用方向條件化文字反事實探針（direction-conditioned textual counterfactual probes），對技能對（skill pairs）進行移除、替換與重排（remove, substitute, and reorder），再以貝葉斯平滑（Bayesian smoothing）聚合證據，並發布一個狀態過濾加權圖（state-filtered weighted graph）以進行任務條件化擴展（task-conditioned expansion）。該圖於離線階段預先建構（offline construction），且無需改變下游智能體策略（downstream agent policy）或任務介面（task interface）即可使用。在 ALFWorld ID-140 與 ScienceWorld U211 上，針對六個 LLM 骨幹模型（LLM backbones）進行實驗，結果顯示 CaSKG 在全部十二種模型與基準測試組合中均取得最高的任務分數（task score）。相較於技能圖（Graph-of-Skills, GoS），CaSKG 將六個模型在 ScienceWorld 上的宏觀平均（macro-average）分數從 72.62 提升至 80.50，並將 ALFWorld 成功率（success rate）從 80.01% 提升至 86.79%，同時降低兩個基準測試上的平均環境步數（mean environment steps）。質性分析（qualitative analyses）與消融分析（ablation analyses）進一步顯示，經校準的邊（calibrated edges）有助於檢索時保留前置條件（prerequisites）、改變狀態的動作（state-changing actions）、驗證程序（verification routines）與最終完成步驟（final completion steps）。這些結果顯示，邊置信度校準（edge-confidence calibration）是實現大規模、緊湊且可執行的技能檢索（compact and executable skill retrieval at scale）的有效途徑。程式碼可於以下網址取得：https://github.com/ZhiyuanLi218/Caskg。

### 核心貢獻（3～5點）
- 提出 CaSKG 框架，在檢索前透過反事實因果推理（counterfactual reasoning）校準技能之間的程序關係，提升圖檢索邊的可靠性。
- 整合語義、詞彙、輸入／輸出與結構等多種證據，並結合修復證據與可選的 LLM 評判器，建立高召回率的有向候選圖。
- 設計方向條件化文字反事實探針，對技能對執行移除、替換與重排操作，再以貝葉斯平滑聚合證據，發布狀態過濾加權圖。
- 在 ALFWorld ID-140 與 ScienceWorld U211 的六個 LLM 骨幹模型上，於全部十二種模型—基準組合中取得最高任務分數，並相較 GoS 顯著提升成功率、降低平均環境步數。
- 質性與消融分析證實，經校準的邊有助於檢索保留前置條件、改變狀態的動作、驗證程序與最終完成步驟，使檢索結果更緊湊且可執行。

### 適合對象
本論文適合對 LLM 智能體、可複用技能庫、檢索增強生成（RAG）、以及基於圖結構之程序知識檢索有興趣的研究者與工程師；特別是關注如何透過因果／反事實方法校準技能圖邊置信度、並在 ALFWorld、ScienceWorld 等互動式任務基準上驗證檢索效果的讀者。從事自動化規劃、智能體記憶體設計與大規模技能管理相關研究的學術與產業人士亦能從中獲益。

## 深度分析

#### 方法論解析

CaSKG（Counterfactual-Causal Skill Graphs，反事實因果技能圖）將「可擴展智能體技能檢索（Scalable Agent Skill Retrieval）」重新定義為一個**預算受限的邊置信度校準（budgeted edge-confidence calibration）**問題：在離線階段先建立高召回率（high recall）的候選關係集合，再透過反事實因果驗證（counterfactual causal validation）決定哪些程序關係（procedural relations）值得被發布到最終的技能圖（skill graph）中，從而避免圖傳播時被弱關聯邊污染。整體流程可分為四個階段：

1. **多訊號候選圖歸納（multi-signal candidate graph induction）**  
   CaSKG 首先建立一張**有向候選圖（directed candidate graph）**，節點為可複用技能庫（reusable skill library）中的技能，邊則代表潛在的程序性先後或依賴關係。為了兼顧覆蓋率，系統同時納入四類證據：
   - **語義證據（semantic evidence）**：利用技能描述的向量相似度捕捉主題相關性；
   - **詞彙證據（lexical evidence）**：透過詞彙重疊補足語義模型可能遺漏的關鍵實體或動作；
   - **輸入／輸出證據（input/output evidence）**：根據技能的介面簽名（例如所需物件、產生物件）判斷銜接可能性；
   - **結構證據（structural evidence）**：利用技能在既有軌跡或任務解決過程中的相對位置（如先後共現）建立結構關聯。  
   此外，**修復證據（repair evidence）**會針對錯誤或失敗軌跡進行修正，並可選擇性地引入 **LLM 評判器（LLM judge）** 對候選分數（candidate scores）進行二次精煉。此階段的目標是「寧濫勿缺」，確保真正有用的程序關係不會在初期被剪除。

2. **方向條件化文字反事實探針（direction-conditioned textual counterfactual probes）**  
   候選圖雖然召回率高，但許多邊僅反映相關性而非因果可操作性。CaSKG 因此對技能對（skill pairs）進行三種反事實操作：**移除（remove）**、**替換（substitute）**與**重排（reorder）**。這些探針是「方向條件化」的，因為程序關係具有不對稱性：技能 A 是技能 B 的前置條件（prerequisite），並不意味 B 也能反過來前置 A。透過 LLM 模擬這些反事實情境（例如「若把 A 從流程中移除，B 是否仍能成功執行？」），系統可以估計某條邊對於完成任務的因果貢獻，而非僅憑共現次數決定邊權重。

3. **貝葉斯平滑與狀態過濾圖發布（Bayesian smoothing & state-filtered weighted graph publication）**  
   反事實探針的結果通常稀疏且帶有雜訊，CaSKG 使用**貝葉斯平滑（Bayesian smoothing）**整合語義、詞彙、輸入／輸出、結構、修復以及反事實探針等多源證據，產生較穩定的邊置信度。隨後，系統根據環境狀態進行**狀態過濾（state filtering）**，只保留在當前或預期狀態下可執行的邊，最終發布一張**狀態過濾加權圖（state-filtered weighted graph）**。這張圖在評估前即被凍結，下游智能體無法也不會修改它。

4. **任務條件化擴展（task-conditioned expansion）**  
   在執行階段，CaSKG 不改變下游智能體策略（downstream agent policy）或任務介面（task interface）。它僅以任務指令為查詢，透過詞彙與語義匹配取得種子節點，再於狀態過濾後的圖上進行類似 **Personalized PageRank** 的擴展，產生一個緊湊且具備程序結構的技能子集。由於邊權重已經過置信度校準，傳播過程較不容易被主題相似但操作無關的技能帶偏。

這套設計的核心哲學是**將「關聯發現」與「關係可靠性評估」分離**：先用低成本訊號建立高召回候選池，再用較高成本但更具因果解釋力的反事實探針進行選擇性驗證，從而在可擴展性（scalability）與檢索精確度之間取得平衡。

#### 實驗數據解讀

論文在兩個互動式基準測試（interactive benchmarks）上進行評估：**ALFWorld ID-140** 與 **ScienceWorld U211**，並使用六個不同的 **LLM 骨幹模型（LLM backbones）**。評估指標包括任務分數（task score）／成功率（success rate）以及平均環境步數（mean environment steps）。

**主要量化結果：**
- CaSKG 在全部 12 個「模型 × 基準」組合中都取得最高任務分數，顯示方法對不同模型能力具有穩健性。
- 相較於 **Graph-of-Skills（GoS，技能圖）**：
  - **ScienceWorld** 的六模型宏觀平均（macro-average）分數從 72.62 提升至 80.50；
  - **ALFWorld** 成功率從 80.01% 提升至 86.79%；
  - 兩個基準的平均環境步數均下降。

**結果意涵：**
1. **成功率與分數提升** 說明經校準的邊（calibrated edges）能幫助檢索保留真正需要的程序知識，例如前置條件（prerequisites）、改變狀態的動作（state-changing actions）、驗證程序（verification routines）以及最終完成步驟（final completion steps）。這些元素往往是純文字相似度難以捕捉的。
2. **步數減少** 反映檢索到的技能子集更為精準，智能體不需要反覆試錯或執行無關動作，規劃效率因此提高。
3. **跨模型一致領先** 暗示 CaSKG 的增益主要來自檢索層的結構改進，而非單純依賴某個強大模型的推理能力；這對實務部署具有重要價值，因為它能在不同成本與效能的模型上提供穩定增益。

**需注意的解讀限制：**  
雖然摘要宣稱「完整封存比較（complete archived comparison）」中 CaSKG 全勝，但提供片段未包含每個模型的個別分數、標準差或統計顯著性檢定。若某些任務類型的樣本數較小，單純的宏觀平均可能掩蓋變異。此外，實驗未說明 LLM 評判器（LLM judge）與反事實探針的呼叫次數與成本，這些因素會影響方法在更大規模技能庫上的實用性。

#### 與現有研究的比較

CaSKG 的定位處於「程序記憶檢索」這一研究軸線，與以下幾類方法形成對比：

| 方法類型 | 核心限制 | CaSKG 的改進 |
|---|---|---|
| **全庫提示（Full-library prompting）** | 上下文成本（context cost）高，並將選擇負擔轉嫁給智能體 | 只提供緊湊鄰域（compact neighborhoods），降低上下文長度與干擾 |
| **向量檢索／RAG（Vector retrieval / RAG）** | 將技能視為獨立文字單位，忽略程序依賴 | 透過圖結構保留工作流程上下文（workflow context） |
| **Graph-of-Skills（GoS）** | 邊的品質依賴語義與共現等關聯訊號，弱邊可能污染傳播 | 引入反事實因果驗證與貝葉斯平滑，對邊置信度（edge-confidence）進行校準 |
| **Voyager / ReAct / Toolformer** | 聚焦於技能學習、工具呼叫或推理行動交錯 | CaSKG 專注於**檢索層**，可與上述智能體框架正交整合，不改變其策略 |

**相對於 GoS 的具體優勢：**  
GoS 已經證明圖檢索能彌補純向量檢索的不足，但它並未系統性地處理「邊是否可靠」的問題。CaSKG 透過多源證據歸納、LLM 模擬反事實探針、貝葉斯平滑與狀態過濾，將圖檢索從「基於關聯強度的傳播」提升為「基於因果可操作性的傳播」。實驗中 ScienceWorld 與 ALFWorld 的雙雙提升，特別是步數同步下降，顯示這不只是分數上的小幅進步，而是檢索品質的結構性改善。

**限制與潛在弱點：**
- **LLM 模擬的因果估計仍屬「文字層」**：反事實探針由 LLM 模擬，而非在真實環境中執行，因此對於需要精確物理或化學狀態變化的任務，探針結果可能與實際環境動力學（environment dynamics）存在落差。
- **成本與規模權衡**：雖然論文強調預算受限校準，但對超大技能庫而言，即使候選邊已經過篩選，LLM 探針與 LLM 評判器的呼叫量仍可能相當可觀。
- **離線建構（offline construction）的靜態性**：一旦圖被凍結，新增技能或任務分佈改變時需要重新建構或增量更新，論文對此著墨較少。
- **狀態過濾的依賴**：狀態過濾需要技能具備狀態前提與效果資訊，若技能庫缺乏這類結構化標註，則需額外抽取或人工設計。

#### 可重現性評估

**開源資源：**
- 論文已公開程式碼：https://github.com/ZhiyuanLi218/Caskg。這為重現圖建構、反事實探針、狀態過濾與檢索流程提供了基礎。
- 使用的基準 **ALFWorld** 與 **ScienceWorld** 均為公開資料集，任務分割 ID-140 與 U211 若於論文或倉庫中詳細說明，則可重現實驗設定。

**重現所需條件：**
- **模型權重與 API**：六個 LLM 骨幹模型（LLM backbones）在提供片段中未具名，但若使用公開 API（如 OpenAI GPT 系列）或開源權重（如 Llama、Qwen 等），原則上可重現。需要確認倉庫是否提供模型名單、版本與溫度（temperature）等推論參數。
- **提示模板（prompt templates）**：反事實探針與 LLM 評判器的效果高度依賴提示設計。倉庫若包含完整提示，將大幅提升可重現性。
- **計算資源**：圖建構階段涉及向量編碼、候選邊生成與多次 LLM 呼叫，需要足夠的 GPU 與 API 預算；執行階段則相對輕量。
- **環境相依性**：ALFWorld 與 ScienceWorld 的模擬器版本、Python 套件版本可能影響結果，倉庫應提供 `requirements.txt` 或 Docker 映像檔。

**可重現性評級：**  
基於程式碼已公開且使用公開基準，初步可重現性為**良好**。但最終評級取決於倉庫是否完整釋出：（1）資料前處理腳本、（2）超參數設定、（3）LLM 評判器與反事實探針的提示、（4）六個骨幹模型的確切身份與版本。若缺少任一項，其他研究者可能只能重現部分流程，難以完全複製論文宣稱的 12 組最佳分數。

#### 未來研究方向

1. **線上增量圖更新（online incremental graph update）**  
   目前 CaSKG 採離線建構，未來可研究如何在智能體執行新任務時動態新增節點、合併相似技能，並針對新觀察到的失敗軌跡更新邊置信度，使技能圖隨時間演化。

2. **環境接地反事實驗證（environment-grounded counterfactual validation）**  
   以 LLM 模擬反事實雖具擴展性，但可透過輕量世界模型（world model）或實際 rollout 抽樣來驗證關鍵邊，特別適用於 ScienceWorld 這類需要精確狀態轉移的任務。

3. **層次化與多粒度技能圖（hierarchical multi-granularity skill graphs）**  
   將低階原子技能組合成高階複合技能，並在不同抽象層級上進行反事實校準，可進一步提升大規模技能庫的檢索效率與可解釋性。

4. **邊不確定性量化與解釋（edge uncertainty quantification & explanation）**  
   除了給出加權邊，未來可輸出每條邊的置信區間與支持證據摘要，讓下游智能體或人類使用者理解「為何檢索到這個技能」。

5. **跨領域遷移與領域適應（cross-domain transfer & domain adaptation）**  
   研究如何將一個領域（如家庭任務）校準好的圖結構遷移到另一個領域（如科學實驗），並透過少量反事實探針快速適應新領域的因果結構。

6. **與技能學習的閉環整合（closed-loop integration with skill learning）**  
   將 CaSKG 的檢索回饋用於指導新技能生成或課程學習（curriculum learning），讓智能體主動填補技能圖中置信度低或缺失的區域。

7. **更激進的邊預算控制與近似演算法**  
   對於數萬甚至數十萬技能的超大庫，可結合近似最近鄰搜尋（approximate nearest neighbor search）、學習式邊評分器（learned edge scorer）或主動學習（active learning）策略，在有限預算內選擇最值得驗證的候選邊。

總體而言，CaSKG 將「邊置信度校準」確立為大規模技能檢索的關鍵槓桿，未來研究可在其框架上進一步結合真實環境反饋、動態更新與層次化抽象，推動 LLM 智能體（LLM agents）的程序記憶系統朝向更可靠、更可解釋的方向發展。

## 論文問答

**Q1：CaSKG 主要想解決什麼問題？**
A：CaSKG 針對的是 LLM 智能體在面對可複用技能庫時的「技能檢索」問題：當程序性知識越累積越多，如何在不淹沒上下文的前提下，為當前任務找出真正有用且可執行的技能子集。這個問題之所以困難，是因為有用的任務脈絡往往不只包含一個與任務文字最相似的程序，還涉及前置條件、狀態改變動作、驗證步驟與收尾步驟等彼此相依的技能。CaSKG 把焦點放在「邊置信度校準」，透過離線建構可靠的技能圖，讓檢索能同時兼顧覆蓋率與精確性。

**Q2：全庫提示與向量檢索為何不足以解決技能檢索？**
A：全庫提示雖然能保留最大覆蓋率，卻會把選擇負擔全部丟給智能體，並造成上下文成本飆升與大量無關選項干擾。向量檢索與 RAG 雖然能回傳語義相近的緊湊鄰域，但它們通常把技能視為彼此獨立的文字單元，忽略了程序性知識中「一個技能的效用常取決於另一個技能」的特性。因此，某些在操作上不可或缺的技能，可能因為文字描述與任務指令不重疊，就被向量檢索遺漏。

**Q3：為什麼圖檢索的關鍵瓶頸在於「邊的可靠性」？**
A：圖檢索透過邊傳播查詢相關性，能讓工作流程相關的技能進入檢索結果，但前提是承載相關性的邊必須可信；若邊是由主題相似、共現或鬆散介面相容性所誘發，就可能把替代方案、無序鄰居或不適合當前程序的技能一起帶入。過度保留這些弱邊會污染技能上下文，過度修剪又會切斷有用路徑，使部分技能庫無法觸及。CaSKG 因此將圖建構重新定義為「預算受限的邊置信度校準問題」，在離線階段決定哪些候選關係值得評估、該給多少信心分數，以及如何讓分數控制傳播。

**Q4：CaSKG 的核心方法流程是什麼？**
A：CaSKG 首先從語義、詞彙、輸入／輸出與結構等多種證據建立一個高召回率的有向候選圖，並利用修復證據與可選的 LLM 評判器進一步精煉候選分數。接著，它對有序技能對施加方向條件化的文字反事實探針，包括移除、替換與重排，以判斷兩技能之間是否存在真正的程序因果關係。最後，CaSKG 使用貝葉斯平滑聚合各項證據，發布一個經狀態過濾的加權圖，供執行時依任務條件進行圖擴展檢索。

**Q5：什麼是「方向條件化文字反事實探針」，它為何重要？**
A：方向條件化文字反事實探針是 CaSKG 用來驗證兩個技能之間程序關係的因果測試，它會假設性地移除、替換或重排某個技能，觀察另一個技能的執行結果是否因此改變。這種探針特別強調「方向」，因為程序關係通常是非對稱的：A 可能是 B 的前置條件，但 B 不一定是 A 的前置條件。透過這類探針，CaSKG 能區分單純的文字關聯與真正的操作依賴，從而提升圖邊的可靠性。

**Q6：CaSKG 為何選擇離線建構圖，並保留高召回候選圖再進行校準？**
A：採用離線建構可以讓複雜的因果校準與 LLM 評判在執行前就完成，執行時只需在已發布的狀態過濾加權圖上進行任務條件化擴展，無需改變下游智能體策略或任務介面。先建立高召回候選圖是為了確保潛在有用的程序關係不會在初期就被遺漏，而後續的邊置信度校準則負責剔除弱邊與假關聯。這種「先廣泛收錄、再嚴格校準」的設計，讓系統能在覆蓋率與精確性之間取得平衡。

**Q7：CaSKG 在哪些基準測試與模型上進行評估？**
A：論文在 ALFWorld ID-140 與 ScienceWorld U211 兩個互動式基準測試上進行實驗，並使用了六個不同的 LLM 骨幹模型。對比方法包括全庫提示、向量檢索，以及圖檢索基線 Graph-of-Skills（GoS）。這樣的設計能同時檢驗 CaSKG 在不同任務領域與不同模型能力下的泛化性。

**Q8：CaSKG 取得了哪些關鍵量化結果？**
A：在六個模型與兩個基準測試的全部十二種組合中，CaSKG 都取得了最高的任務分數。與 GoS 相比，六模型宏觀平均的 ScienceWorld 分數從 72.62 提升至 80.50，ALFWorld 成功率則從 80.01% 提升至 86.79%。此外，CaSKG 在兩個基準上都降低了平均環境步數，顯示檢索到的技能子集不僅更準確，也更能引導智能體高效完成任務。

**Q9：消融分析與質性分析揭示了什麼？**
A：消融與質性分析顯示，經過校準的邊能幫助檢索保留前置條件、改變狀態的動作、驗證程序以及最終完成步驟，這些都是程序性任務中不可或缺的元素。論文進一步從任務類型、軌跡範例、技能庫規模與圖建構組件等角度分析，證實增益與「提升邊可靠性」的設計機制一致。這些結果說明，邊置信度校準確實能讓檢索出的技能包更加緊湊且可執行。

**Q10：CaSKG 可應用在哪些實務場景？**
A：CaSKG 適用於任何需要管理大量程序性記憶的 LLM 智能體場景，例如家庭機器人執行多步驟家務、科學實驗智能體操作儀器與化學流程、客服自動化系統處理複雜問題排查，以及軟體工程智能體在大型 API 庫中尋找可組合函式。在這些場景中，單靠文字相似度往往無法找到正確的操作順序與相依關係。CaSKG 透過因果校準的技能圖，能為智能體提供結構化且可執行的技能上下文。

**Q11：若要把 CaSKG 落地到產品，需要考慮哪些因素？**
A：由於 CaSKG 的圖是在離線階段建構，執行時不會改變下游智能體策略或任務介面，因此整合門檻相對較低，適合嵌入現有智能體框架。產品化時需要權衡可選 LLM 評判器帶來的建構成本與準確度提升，並在技能庫更新時重新校準或增量更新圖結構。此外，還需監控狀態過濾與圖擴展的延遲與儲存開銷，確保檢索仍符合線上服務的效能需求。

**Q12：這項研究對技能檢索領域可能帶來什麼影響？**
A：CaSKG 將「邊置信度校準」確立為大規模可執行技能檢索的有效路徑，把傳統的關聯式圖檢索推向因果推理層次。它提醒研究者，程序性記憶的檢索不應只看單一技能的語義相似度，而應重視技能之間的操作因果關係。這種思維可望影響未來工具檢索、規劃與長期記憶系統的設計，促使更多研究關注如何驗證與量化技能間的因果依賴。

**Q13：CaSKG 有哪些可預見的限制？**
A：CaSKG 的因果驗證仰賴文字形式的反事實探針與可選的 LLM 評判器，這會增加離線建構階段的計算成本，且對 LLM 的推理品質有一定依賴。方法目前主要針對有序技能對進行評估，對於更複雜的多技能交互或隱藏變數所造成的因果關係，可能無法完全捕捉。此外，雖然論文在兩個基準上驗證了可擴展性，但面對數百萬級動態更新的技能庫時，校準預算與增量維護策略仍需進一步研究。

**Q14：CaSKG 在什麼情況下可能表現不佳？**
A：當兩個技能在文字描述上高度相似但實際互為替代方案時，多種文字證據可能讓它們獲得過高的關聯分數，導致錯誤的邊殘留。對於出現頻率低、證據稀少的稀有技能，CaSKG 可能因缺乏足夠的探針樣本而無法建立穩定的連結。另外，若狀態過濾過於嚴格，也可能排除某些在特殊狀態下仍然合理的程序路徑，影響罕見任務的成功率。

**Q15：未來可以朝哪些方向延伸 CaSKG？**
A：未來可以探索動態或增量式圖更新機制，使技能庫在新增或刪除技能時不必從頭重建整張圖。也可以結合更豐富的狀態表示，例如視覺或多模態訊號，來輔助判斷技能間的真實因果關係。此外，將學習式因果模型與符號規則結合、設計主動學習策略以最低預算選擇最值得評估的邊，以及把 CaSKG 擴展到開放式工具使用與多智能體協作，都是值得深入的研究方向。

## 實務應用指南

### 適用場景

**企業流程自動化與 RPA 技能庫**
當組織累積數百至數千個可複用技能庫（例如開票、對帳、請假審批、報表產生）時，CaSKG 可在離線階段校準技能間的前置條件、狀態改變與驗證程序，讓 LLM 智能體在面對新任務時，只收到與當前流程相關的緊湊鄰域，而非整份技能手冊。

**多工具客戶服務智能體**
客服場景常同時擁有查訂單、改地址、申請退貨、升級方案、發送驗證碼等工具。CaSKG 能透過輸入／輸出證據與結構證據，辨識「先驗證身份才能改地址」這類程序關係，避免智能體跳過必要步驟或呼叫順序錯誤的工具。

**軟體開發輔助代理**
在大型程式碼庫或 DevOps 工具鏈中，技能可能對應到「執行單元測試」、「部署至預發環境」、「回滾版本」、「發送 Slack 通知」等動作。CaSKG 可將這些程序性知識組織成狀態過濾加權圖，協助開發代理依任務條件化擴展最合適的動作序列。

**科學實驗與實驗室自動化**
ScienceWorld 的實驗任務可對應到真實實驗室中的儀器操作、試劑添加、溫度控制、數據記錄與安全檢查。CaSKG 的邊置信度校準有助於保留「先穿戴防護裝備再操作」或「先歸零再量測」等關鍵前置條件。

**智慧家庭與物聯網場景**
當家庭自動化系統擁有大量裝置動作（開燈、調溫度、啟動掃地機器人、檢查門窗感測器）時，CaSKG 可建立離線技能圖，讓語音助理在執行「我要出門」這類複合指令時，自動帶出關燈、關冷氣、確認門鎖等相關動作，而非遺漏驗證程序。

### 實作前置條件

**資料準備**
- 技能庫需包含每個技能的自然語言描述、輸入／輸出規格、執行前後狀態（pre/post condition），以及可選的執行軌跡日誌。
- 若要有結構證據，建議保留歷史任務的成功與失敗軌跡，以便觀察技能在真實流程中的共現與順序。
- 若使用 LLM 評判器，需準備少量高品質的邊標註樣本做為校準參考。

**運算資源**
- 離線建構階段需要執行向量編碼、候選圖生成、反事實探針與 LLM 裁判模型推理，建議配置可呼叫商用 LLM API 的環境，並保留足夠的批次處理配額。
- 圖的規模若達數千個技能，候選邊數量可能達百萬級，需準備圖資料庫（如 Neo4j）或支援稀疏鄰接矩陣的儲存方案。
- 線上檢索階段主要執行個人化 PageRank 風格的任務條件化擴展，運算成本相對低，可佈署在常見的檢索服務中。

**技能與團隊前置條件**
- 團隊需熟悉 LLM 智能體、向量檢索與圖檢索的基本概念。
- 需具備將技能抽象為可重複使用單元的工程能力，包括定義清晰的輸入輸出與狀態轉換。
- 建議至少有一位成員能理解因果驗證與反事實推理的設計邏輯，以便調校反事實探針與貝葉斯平滑參數。

### 實作步驟建議

**步驟一：技能盤點與結構化**
將現有工具、API、腳本或流程抽象為統一技能格式，每個技能至少包含名稱、描述、輸入參數、輸出結果、執行前狀態、執行後狀態。若已有 OpenAPI 規格或函式定義，可直接轉換為技能描述。

**步驟二：收集多源證據**
針對每對技能，計算語義證據（向量相似度）、詞彙證據（描述文字重疊）、輸入／輸出證據（參數與回傳值相容性），以及結構證據（歷史軌跡中的共現與順序）。這些證據將用於建立高召回率的有向候選圖。

**步驟三：建立高召回候選圖**
將上述證據整合為候選分數，保留足夠多的邊以確保覆蓋率，但不必在此階段過度剪枝。此時的目標是「寧可錯殺，不可遺漏」，後續再由反事實因果校準決定邊的可靠性。

**步驟四：執行方向條件化文字反事實探針**
對候選技能對進行移除、替換與重排三種反事實操作，並以 LLM 模擬執行結果。例如：「若移除技能 A，技能 B 是否仍能有效執行？」或「若將 A 與 B 的順序對調，結果是否仍合理？」根據反事實結果調整邊的因果強度。

**步驟五：聚合證據並進行貝葉斯平滑**
將多源證據與反事實探針結果透過貝葉斯平滑聚合，產生穩定的邊置信分數。若資源允許，可引入 LLM 評判器對高分候選邊進行二次確認，特別是涉及狀態改變與驗證程序的關鍵邊。

**步驟六：狀態過濾與圖發布**
根據技能執行前後狀態，過濾掉與實際狀態轉換不一致的邊，發布為狀態過濾加權圖。此圖在離線階段凍結，不隨任務改變而重新建構。

**步驟七：整合線上任務條件化擴展**
在下游智能體運行時，先以詞彙與語義匹配找到種子技能，再於已發布的圖上進行個人化 PageRank 風格的擴展，返回緊湊的技能子集給智能體。此步驟不改變下游智能體策略或任務介面。

**步驟八：持續評估與迭代**
定期比較 CaSKG 與全庫提示、純向量檢索、GoS 等基線的任務分數、成功率與平均環境步數，並針對失敗案例進行質性分析，修正技能描述或反事實探針模板。

### 潛在風險與注意事項

**反事實探針的幻覺風險**
LLM 模擬的反事實結果可能與真實環境不一致，特別是涉及物理狀態改變或外部 API 副作用時。建議將反事實探針視為輔助證據，並與真實軌跡的結構證據進行貝葉斯平滑，而非單獨作為邊置信度的唯一依據。

**離線建構成本**
當技能庫規模擴大時，候選邊數量呈平方增長，反事實探針與 LLM 評判器的呼叫成本可能相當可觀。建議先以高召回率的啟發式規則篩選候選邊，再對高分邊執行精細的因果校準，以控制預算。

**圖的時效性問題**
技能庫會隨時間新增、修改或淘汰，離線建構的圖可能逐漸過時。建議建立定期重建機制，並在新增技能時，只針對與新技能相關的局部區域進行增量校準，而非每次都重建全圖。

**過度剪枝導致覆蓋率下降**
若邊置信度門檻設得太高，可能移除一些雖然弱但實際有用的程序路徑。建議透過消融分析觀察不同門檻下的任務分數變化，在覆蓋率與精確度之間取得平衡。

**對技能描述品質的依賴**
CaSKG 的多源證據與反事實探針都高度依賴技能描述的準確性。若技能描述過於籠統或缺少輸入／輸出資訊，候選圖的品質會下降。建議在導入 CaSKG 前先進行技能描述的標準化與補全。

### 與其他技術的整合建議

**與 RAG 系統整合**
CaSKG 可視為 RAG 檢索層的增強模組。向量資料庫負責初步語義召回，CaSKG 負責在程序關係上進行圖檢索與任務條件化擴展，兩者結合可同時保留語義相關性與工作流程上下文。

**與現有智能體框架整合**
CaSKG 的設計原則是不改變下游智能體策略與任務介面，因此可較容易地嵌入 LangChain、AutoGen、Semantic Kernel 等框架中，作為工具選擇前的技能檢索層。

**與向量資料庫和圖資料庫整合**
建議將技能向量儲存在向量資料庫（如 Milvus、Pinecone、Weaviate）中，用於語義證據與線上種子檢索；將狀態過濾加權圖儲存在圖資料庫（如 Neo4j、Amazon Neptune）中，用於程序關係的儲存與擴展。

**與現有工具註冊表整合**
若組織已有 OpenAPI 規格、函式呼叫定義或內部工具市場，可將這些規格自動轉換為 CaSKG 的技能描述與輸入／輸出證據，降低資料準備成本。

**與可觀測性平台整合**
將 CaSKG 檢索出的技能子集、邊置信度與反事實探針結果記錄到可觀測性平台，有助於後續除錯、審計與圖品質監控，特別是在任務失敗時可追溯是否因弱邊導致錯誤的技能選擇。

### 給不同背景讀者的閱讀建議

**給初學者**
這篇論文的核心概念是：當 LLM 智能體擁有很多可重複使用的技能時，如何聰明地挑出當前任務真正需要的技能。你可以把 CaSKG 想像成一本「會自己校準步驟順序的食譜索引」——它不只根據關鍵字找食譜，還會判斷哪些步驟必須先做、哪些步驟可以替換或省略。建議先從摘要與適用場景讀起，理解問題動機後，再回頭看技術細節。

**給 AI 工程師**
論文提供了一個可落地的離線圖建構流程，從多源證據生成、反事實探針設計到貝葉斯平滑與狀態過濾都有具體步驟。建議重點關注第 3 節的方法論與實作步驟建議，並思考如何將你現有的工具註冊表或 RAG 管線替換為 CaSKG 的圖檢索層。特別注意反事實探針的批次實作與成本控管，這是從論文走向產品的關鍵。

**給研究人員**
CaSKG 將技能圖建構重新定義為「預算化的邊置信度校準問題」，並以反事實因果推理取代單純的共現或語義關聯。建議深入閱讀方法論中的方向條件化文字反事實探針與貝葉斯平滑設計，並思考如何將此框架擴展到動態圖、多智能體協作或更複雜的狀態空間。消融分析與質性分析也提供了豐富的研究啟發。

**給產品經理**
這篇論文提供了一個能顯著提升多技能智能體任務成功率、同時減少無效環境步數的技術方案。建議從適用場景與實驗結果讀起，評估它是否適合你的產品線——特別是當你面臨技能庫膨脹、提示過長、或智能體經常選錯工具順序的問題時。實作前置條件與潛在風險章節可幫助你評估導入成本與時程。
