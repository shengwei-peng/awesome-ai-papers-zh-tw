## 摘要翻譯

基於多模態大型語言模型（MLLM-based）的分割面臨一個核心的分割三難困境（segmentation trilemma）：高效能的分割表現、保留對話能力（dialogue ability），以及快速推理。嵌入預測（embedding-prediction）方法可能透過像素級目標（pixel-level objectives）干擾語言建模，而下一個詞元生成（next-token generation）對於稠密遮罩（dense masks）則效率不彰。我們提出全遮罩預測（All-Mask Prediction），將自迴歸（autoregressive）對話與非自迴歸（non-autoregressive）遮罩預測解耦。其二元實例化 STAMP（Simultaneous Textual All-Mask Prediction，同步文本全遮罩預測）會產生一個詞彙內（in-vocabulary）`<SEG>` 觸發詞元（trigger），融合與圖像對齊的遮罩詞元（mask tokens）與相應的圖塊特徵（patch features），並使用混合注意力（hybrid attention）於單次傳遞中將所有詞元分類為前景（foreground）或背景（background）。因此，它結合了強大的指稱分割（referring segmentation）與推理分割（reasoning segmentation），同時保留多模態能力並實現高效推理。然而，二值遮罩（binary masks）若未針對各目標反覆預測，便無法保留多個語義或實例身份。因此，我們提出結構化全遮罩預測（Structured All-Mask Prediction），並開發 STAMPlus。它會生成一個包含明確 ID 與可選邊界框的目標列表（target list），將這些 ID 綁定至共享的多類別遮罩空間（multi-class mask space），並在一次非自迴歸過程中聯合預測所有目標。單一且統一的檢查點（checkpoint）保留了 STAMP 的指稱與推理能力，同時擴展至開放詞彙語義分割（open-vocabulary semantic segmentation）、實例感知分割（instance-aware segmentation）與遙感小目標分割（remote-sensing small-target segmentation），其中高解析度遮罩詞元縮放（high-resolution mask-token scaling）保留了更精細的空間證據。在這些設定中，STAMPlus 達到最先進的（state-of-the-art）分割表現，保留通用的多模態指令遵循（multimodal instruction following）能力，並將 12 類別延遲從重複執行 STAMP 推理的 13.50 秒降至 5.16 秒。進一步分析顯示，準確的目標線索（target cues）可改善分割，而學習到的空間定位（spatial grounding）有助於再次審視推理（look-twice reasoning）。總體而言，STAMPlus 超越單一目標預測，解決了此三難困境。

### 核心貢獻（3～5點）
- 提出全遮罩預測（All-Mask Prediction）框架，將自迴歸對話生成與非自迴歸遮罩預測解耦，避免像素級目標干擾語言建模，並提升稠密遮罩推理效率。
- 設計 STAMP（同步文本全遮罩預測），以詞彙內 `<SEG>` 觸發詞元、圖像對齊遮罩詞元與混合注意力，單次完成二值前景/背景分類，兼顧指稱分割、推理分割與多模態對話能力。
- 提出結構化全遮罩預測（Structured All-Mask Prediction）並發展 STAMPlus，透過目標列表、ID 綁定與共享多類別遮罩空間，於單次非自迴歸過程中聯合預測多目標與多類別。
- 以單一統一檢查點將能力擴展至開放詞彙語義分割、實例感知分割與遙感小目標分割，並藉由高解析度遮罩詞元縮放保留精細空間證據。
- 在多項設定中達到最先進分割表現，保留通用多模態指令遵循能力，並將 12 類別推理延遲從 13.50 秒降至 5.16 秒。

### 適合對象
本論文適合多模態大型語言模型、電腦視覺與影像分割領域的研究者與工程師，特別是關注指稱分割、推理分割、開放詞彙語義分割、實例感知分割、遙感小目標分割，以及希望在建構高效能 MLLM 分割系統同時保留多模態對話與指令遵循能力之讀者。

## 深度分析

#### 方法論解析

本文的核心貢獻在於提出 **All-Mask Prediction（全遮罩預測）**，並進一步將其擴展為 **Structured All-Mask Prediction（結構化全遮罩預測）**，對應模型分別為 **STAMP（Simultaneous Textual All-Mask Prediction，同步文本全遮罩預測）** 與 **STAMPlus**。其設計動機來自於 **MLLM-based segmentation（基於多模態大型語言模型的分割）** 所面臨的 **segmentation trilemma（分割三難困境）**：同時達成高 **segmentation performance（分割效能）**、保留 **dialogue ability（對話能力）**、以及維持 **fast inference（快速推理）**。

現有方法大致可分為兩大典範。第一類是 **embedding-prediction（嵌入預測）**，例如 LISA、GSVA、M2SA、READ 等，這類方法透過微調 MLLM 產生目標專屬的 **embeddings（嵌入向量）**，再交由外部 **mask decoder（遮罩解碼器）** 生成二值遮罩。雖然分割品質較佳，但由於引入了 **pixel-level objectives（像素級目標函數）**，偏離了語言模型原本的 **token-generation interface（詞元生成介面）**，可能損害一般對話能力，且需要外部解碼器，並非 **decoder-free（無解碼器）**。第二類是 **next-token generation（下一個詞元生成）**，例如 VisionLLM、Seg-Zero、Text4Seg 等，將分割視為純語言建模任務，透過 **autoregressive（自迴歸）** 方式生成座標或 **patch-wise（圖塊級）** 前景／背景標籤。這類方法雖然能保留對話能力且無需外部解碼器，但生成 **dense masks（稠密遮罩）** 所需的序列長度過長，導致 **inference latency（推理延遲）** 過高。

為了突破上述困境，作者提出將對話生成與遮罩預測解耦的兩階段架構：

1. **Phase 1：自迴歸語言生成階段**  
   MLLM 負責理解指令並生成自然語言回應。在 STAMP 中，此階段會輸出一個 **in-vocabulary trigger（詞彙內觸發詞元）**，即 `<SEG> trigger（<SEG> 觸發詞元）`，用於啟動後續的遮罩預測分支。在 STAMPlus 中，Phase 1 進一步擴展為生成一份 **target list（目標列表）**，其中每個目標都帶有明確的 ID，並可選擇性地附上 **boxes（邊界框）**。這份結構化列表為後續的多類別遮罩預測提供了語義與實例的對齊依據。

2. **Phase 2：非自迴歸全遮罩預測階段**  
   此階段與語言生成解耦，採用 **non-autoregressive（非自迴歸）** 方式一次性預測所有目標的遮罩。STAMP 的做法是將 **image-aligned mask tokens（與圖像對齊的遮罩詞元）** 與對應的 **patch features（圖塊特徵）** 進行融合，並透過 **hybrid attention（混合注意力）** 機制，將所有圖塊詞元分類為 **foreground（前景）** 或 **background（背景）**。由於所有圖塊一次分類完成，因此對單一目標而言，遮罩生成是單步驟的。

STAMPlus 則進一步將此機制擴展至多目標場景。它將 Phase 1 產生的 ID 綁定到一個共享的 **multi-class mask space（多類別遮罩空間）**，使得每個前景類別對應到一個語義類別或實例身份。Phase 2 的多類別分類頭（multi-class head）會同時為所有目標預測遮罩，達成 **joint prediction（聯合預測）**。這樣一來，無論是 **open-vocabulary semantic segmentation（開放詞彙語義分割）**、**instance-aware segmentation（實例感知分割）**，或是 **remote-sensing small-target segmentation（遙感小目標分割）**，都能在同一個統一模型中處理。

針對遙感影像中的小目標，STAMPlus 引入了 **high-resolution mask-token scaling（高解析度遮罩詞元縮放）** 機制，透過保留更細緻的空間證據來提升對小物體的定位能力。整體而言，STAMPlus 的設計哲學是：讓 MLLM 專注於它擅長的語言理解與結構化目標列舉，而將需要密集空間推理的遮罩預測交由專門的 **non-autoregressive（非自迴歸）** 模組完成，從而同時兼顧效能、對話能力與速度。

#### 實驗數據解讀

由於提供的摘要與引言片段並未包含完整的實驗表格，以下主要針對論文宣稱的結果進行解讀，並指出需要進一步檢視的細節。

作者主張 STAMPlus 在多種分割設定下達到 **state-of-the-art（最先進的）** 表現，同時保留一般性的 **multimodal instruction following（多模態指令遵循）** 能力。這意味著模型不僅在傳統的 **referring segmentation（指稱分割）** 與 **reasoning segmentation（推理分割）** 上表現優異，也能處理開放詞彙語義與實例分割任務。若此宣稱成立，則顯示單一統一架構確實能跨越多種分割範式，而不需要針對每種任務訓練獨立的模型。

在效率方面，論文給出了一個具體數字：對於 12 個類別的預測，重複執行 STAMP 推論需要 13.50 秒，而 STAMPlus 僅需 5.16 秒。這代表延遲降低了約 61.8%，約為 2.6 倍的加速。值得注意的是，STAMP 的複雜度為 O(N)，其中 N 為目標數量，而 STAMPlus 則將遮罩生成步驟降為 O(1)。然而，實際加速比並未達到理論上的 12 倍，這可能是因為 Phase 1 的語言生成、影像編碼、以及後處理等開銷佔了相當比例，並非所有時間都花在遮罩解碼上。這也說明在實際系統中，單純降低遮罩步驟數並不一定線性反映為總延遲的降低。

論文進一步進行了兩項分析：第一，**accurate target cues（準確的目標提示）** 能改善分割品質，這支持了 Phase 1 結構化目標列表的重要性；第二，**learned spatial grounding（學習到的空間定位）** 有助於 **look-twice reasoning（再次審視推理）**，暗示模型透過遮罩預測分支獲得的空間對齊能力，能回過頭來強化需要反覆檢視空間關係的推理任務。

不過，由於缺乏各基準測試的具體數值（例如 mIoU、AP、AR、準確率等），我們無法獨立判斷這些宣稱的統計顯著性。建議讀者進一步檢視完整論文中的實驗表格，特別是與 LISA、Text4Seg、Seg-Zero 等方法的直接比較，以及在不同解析度與目標數量下的延遲拆解分析。

#### 與現有研究的比較

從表 I 可以清楚看出本文方法在現有典範中的定位：

| 典範 | 代表方法 | Mask Steps（N 個目標） | Token-only Supervision | Decoder-free |
|---|---|---|---|---|
| Embedding Prediction | LISA、GSVA、M2SA、READ | O(N) | ✗ | ✗ |
| Next-token Prediction | VisionLLM、Seg-Zero、Text4Seg、Text4Seg++ | O(N×Npoints) 或 O(N×Npatches) | ✓ | ✓/✗ |
| All-Mask Prediction | STAMP、STAMPlus | O(N) / O(1) | ✓ | ✓ |

相較於 **embedding-prediction（嵌入預測）** 方法，STAMP 與 STAMPlus 的最大優勢在於完全在 **token interface（詞元介面）** 內進行監督，不需要外部 **mask decoder（遮罩解碼器）**，因此避免了像素級損失對語言建模的干擾，更有可能保留 MLLM 的通用對話能力。相較於 **next-token prediction（下一個詞元生成）** 方法，STAMP 將單一目標的遮罩預測從自迴歸的多步驟生成改為一次性圖塊分類，STAMPlus 更進一步將多目標場景的遮罩步驟從 O(N×Npatches) 或 O(N×Npoints) 降為 O(1)，在效率上具有明顯優勢。

具體來說，Text4Seg 與 Text4Seg++ 雖然也採用 **patch classification（圖塊分類）**，但它們仍針對每個目標分別生成序列，導致複雜度隨目標數量與圖塊數量增長。STAMPlus 則透過 **Structured All-Mask Prediction（結構化全遮罩預測）**，將所有目標的語義身份在 Phase 1 中結構化，並在 Phase 2 中一次性聯合預測，這是方法論上的關鍵躍進。

然而，本文方法也存在一些潛在限制。首先，整個流程高度依賴 Phase 1 產生的 **target list（目標列表）** 正確性；若 ID 分配錯誤或遺漏目標，則 Phase 2 無法補救。其次，對於高度重疊或密集排列的實例，單靠可選邊界框與多類別分類可能仍難以精確區分個體。第三，**high-resolution mask-token scaling（高解析度遮罩詞元縮放）** 雖有助於小目標，但同時會增加記憶體與計算成本，如何在解析度與效率之間取得最佳平衡仍需探討。最後，雖然作者宣稱使用單一統一檢查點，但不同任務之間可能存在容量競爭，特別是當訓練資料分布差異極大時。

#### 未來研究方向

STAMPlus 所提出的 **Structured All-Mask Prediction（結構化全遮罩預測）** 為 MLLM-based segmentation 開啟了多個值得探索的方向：

1. **擴展至全景分割與影片分割**：目前 STAMPlus 已涵蓋語義與實例分割，未來可進一步統一 **panoptic segmentation（全景分割）**，並將框架延伸至時序維度，處理影片中的目標追蹤與分割。
2. **提升目標列表生成的穩健性**：針對複雜場景中目標遺漏、ID 錯誤或重疊實例的問題，可引入迭代式驗證機制或與檢測分支更緊密的互動，減少對可選邊界框的依賴。
3. **更高解析度與層級化圖塊特徵**：為了進一步改善小目標與邊界品質，可結合 **hierarchical patch features（層級化圖塊特徵）** 或輕量級的像素級精修模組，但需小心避免重新引入像素級損失對語言建模的干擾。
4. **與推理鏈的結合**：雖然 STAMPlus 強調速度，但某些 **reasoning segmentation（推理分割）** 任務可能需要多步推理。未來可研究如何在保持非自迴歸效率的前提下，選擇性地引入 **chain-of-thought（思維鏈）** 或反覆精煉機制。
5. **多語言與長尾類別泛化**：目前開放詞彙能力主要仰賴 MLLM 的語言理解，未來可在更多語言與長尾類別上進行評估與微調，提升實用性。
6. **模型壓縮與邊緣部署**：為了讓統一分割模型能在資源受限裝置上運行，可探索知識蒸餾、量化與輕量化架構設計。
7. **可解釋性與空間定位分析**：論文發現學習到的空間定位有助於推理，未來可更深入探討遮罩預測分支與語言生成分支之間的資訊流動，並發展可解釋的視覺推理工具。

總結來說，STAMPlus 透過結構化的全遮罩預測，有效地將 MLLM-based segmentation 從單一目標推向更廣泛的多目標場景，並在理論上同時滿足效能、對話能力與效率三大目標。後續研究若能解決目標列表穩健性、高解析度效率與更複雜推理場景等挑戰，將有機會進一步鞏固此一典範的影響力。

## 論文問答

**Q1：基於多模態大型語言模型的分割面臨什麼核心困境？為什麼難以同時滿足？**  
A：基於多模態大型語言模型的分割面臨「分割三難困境」，即同時達成高分割效能、保留一般對話能力與快速推理這三項目標難以兼得。這是因為傳統嵌入預測方法為了產生精確遮罩，常在語言模型之外加入像素級目標函數，進而干擾詞元生成介面；而下一個詞元生成方法雖然保留語言介面，卻必須以自迴歸方式逐點或逐圖塊產生稠密遮罩，導致推理速度極慢。因此，現有方法往往只能在效能、對話能力或速度中犧牲至少一項。

**Q2：嵌入預測方法如何運作，為何會損害多模態對話能力？**  
A：嵌入預測方法透過微調多模態大型語言模型，使其輸出目標專屬的嵌入向量，再交由外部二值遮罩解碼器產生遮罩。為了讓嵌入能準確對應到像素級遮罩，訓練時會引入輔助的像素級損失，但這種目標偏離了原生語言建模任務，可能削弱模型對一般指令的遵循能力。例如，LISA 在面對「圖中有幾個物體？」這類簡單問題時，可能會直接輸出分割結果而非正確回答，顯示其對話泛化性受到影響。

**Q3：下一個詞元生成方法如何避免對話能力退化，卻又在效率上受限？**  
A：下一個詞元生成方法將分割重新框架為純語言建模任務，讓模型自迴歸地生成座標、思維鏈引導座標或圖塊級前景／背景標籤，因此不需要像素級損失，能較好保留對話介面。然而，稠密遮罩需要很長的詞元序列才能表達，模型必須逐個生成每個點或每個圖塊，造成推理延遲隨遮罩解析度與目標數量快速增加。特別是在多目標或需要豐富內容的場景中，這種自迴歸生成會變得難以實用。

**Q4：全遮罩預測的核心思想是什麼？STAMP 如何具現化這個想法？**  
A：全遮罩預測的核心是將自迴歸對話生成與非自迴歸遮罩預測解耦，讓語言模型負責理解與回應，而遮罩預測則以單次前向傳播完成。STAMP 作為二值實例，會在文本中發出詞彙內的 `<SEG>` 觸發詞元，隨後將影像對齊的遮罩詞元與對應圖塊特徵融合，並利用混合注意力機制一次性對所有圖塊進行前景或背景分類。這樣的設計讓模型在保留多模態對話能力的同時，也能以較高效率完成指稱分割與推理分割。

**Q5：結構化全遮罩預測與 STAMPlus 如何突破 STAMP 的二值限制？**  
A：STAMP 產生的二值遮罩無法同時保留多個語義類別或實例身份，因此需要針對每個目標重複預測，效率與表達力都受限。為此，本文提出結構化全遮罩預測並發展出 STAMPlus，讓第一階段生成帶有明確 ID 與可選邊界框的目標列表，再將這些 ID 綁定到共享的多類別遮罩空間，最後以單次非自迴歸傳播聯合預測所有目標。這種結構化設計讓單一統一檢查點不僅保留 STAMP 的指稱與推理能力，還能擴展到開放詞彙語義分割、實例感知分割與遙感小目標分割等更廣泛的任務。

**Q6：STAMPlus 有哪些關鍵設計選擇，使它兼顧準確性、對話能力與速度？**  
A：STAMPlus 首先利用結構化目標列表為每個語義類別或物件實例分配專屬 ID，並可搭配邊界框來解決實例間的歧義，從而為後續遮罩預測提供明確的目標線索。其次，它採用共享的多類別遮罩空間與多類別預測頭，讓所有目標能在一次前向傳播中同時輸出，避免重複計算。此外，高解析度遮罩詞元縮放機制能保留更精細的空間證據，對於遙感小目標等需要細節的場景特別重要，而整個流程仍維持僅詞元監督與無外部遮罩解碼器的優勢。

**Q7：本文在哪些實驗設定與基準上評估 STAMPlus？**  
A：本文在多元的設定下驗證 STAMPlus，包括傳統的指稱分割與推理分割、開放詞彙語義分割、實例感知分割，以及遙感小目標分割等挑戰性場景。這些設定涵蓋了從單一目標到多目標、從自然影像到專業遙感影像的不同需求，能夠檢驗方法的泛化能力。除了分割準確度外，作者也測量了多類別推理延遲，以評估方法在實際應用中的效率。

**Q8：STAMPlus 取得了哪些關鍵量化結果？**  
A：STAMPlus 在上述多種設定下達到最先進的分割效能，同時仍保留一般多模態指令遵循能力，顯示它並未為了分割任務犧牲對話表現。在效率方面，對於 12 個類別的預測，重複執行 STAMP 需要 13.50 秒，而 STAMPlus 僅需 5.16 秒，顯著降低推理延遲。這些結果說明 STAMPlus 確實在效能、對話能力與速度之間取得了更好的平衡。

**Q9：消融實驗與進一步分析揭示了哪些重要發現？**  
A：本文的分析顯示，準確的目標提示能顯著提升後續分割品質，這凸顯了結構化目標列表與可選邊界框的重要性。此外，學習到的空間定位能力對於需要再次審視推理的任務特別有幫助，因為模型能藉由空間線索反覆確認目標關係。高解析度遮罩詞元縮放也被證實有助於保留小目標的細節證據，進而改善遙感影像等場景的分割表現。

**Q10：STAMPlus 可應用於哪些實際場景？**  
A：STAMPlus 適合需要同時理解自然語言指令並產生精確遮罩的互動式應用，例如機器人根據口語指令抓取特定物體、自動駕駛系統辨識並標註道路使用者，或遙感影像分析中自動提取建築物與車輛等小目標。由於它支援開放詞彙語義分割與實例感知分割，使用者能以自由文字描述任意類別，而不受限於預先定義的類別清單。這種靈活性使其在智慧監控、地理資訊系統與互動式影像編輯等領域都具有潛力。

**Q11：從產品部署角度，STAMPlus 有哪些優勢與考量？**  
A：STAMPlus 採用單一統一檢查點，同時具備對話與多種分割能力，可簡化模型維護並降低部署多個專用模型的成本。其非自迴歸的全遮罩預測讓多目標遮罩生成步驟從與目標數量相關降為常數級，顯著改善使用者體驗所需的回應時間。不過，產品化時仍需考量高解析度遮罩詞元帶來的記憶體需求，以及在極端密集場景下目標列表生成錯誤可能影響最終遮罩品質的風險。

**Q12：這項研究對多模態大型語言模型與分割領域有何更廣泛影響？**  
A：本研究證明，稠密分割任務可以在不引入像素級損失、也不依賴緩慢自迴歸生成的情況下，整合進多模態大型語言模型，從而為統一視覺—語言模型提供了一條新途徑。它突破了過去僅適用於單一目標預測的限制，將全遮罩預測擴展到語義、實例與專業遙感領域，拓展了 MLLM 可處理的任務廣度。這樣的範式轉變可能啟發後續研究在更多密集預測任務中採用解耦式、非自迴歸的設計。

**Q13：本文承認哪些限制？**  
A：雖然 STAMPlus 顯著擴展了應用範圍，但其效能仍部分依賴第一階段目標列表的準確性，若 ID 分配或邊界框估計出錯，後續多類別遮罩預測也會受到影響。此外，對於高度重疊或數量極多的實例，結構化目標列表可能難以清楚區分每個目標，進而限制分割品質。高解析度遮罩詞元雖然提升細節，但也可能增加計算與記憶體開銷，需要在解析度與效率之間權衡。

**Q14：哪些情況可能是 STAMPlus 的失敗案例？**  
A：當場景中存在大量外觀相似且緊密相鄰的實例時，STAMPlus 可能因目標列表中的 ID 分配或邊界框歧義而產生錯誤或合併的遮罩。對於尺寸遠小於圖塊解析度的極小目標，即使採用高解析度遮罩詞元縮放，仍可能因空間證據不足而遺漏細節。另外，若使用者的指令需要先進行複雜推理才能決定目標集合，而第一階段未能正確產生結構化目標列表，則後續分割也會失敗。

**Q15：未來可以朝哪些方向延伸這項工作？**  
A：未來可將結構化全遮罩預測擴展到影片分割與三維場景理解，讓模型在時序或立體空間中追蹤並標註多個目標。另一方面，可進一步強化目標列表生成模組，例如結合更強大的空間定位或物件偵測先驗，以降低 ID 分配錯誤。此外，探索更輕量且可擴展的高解析度遮罩詞元機制，並將此範式應用於全景分割、醫學影像分析等更廣泛的密集預測任務，也是值得研究的方向。

## 實務應用指南

### 適用場景

1. **智慧醫療影像標註與病灶勾畫**  
   在放射科或病理影像中，醫師可透過自然語言指令（如「標出所有疑似腫瘤的區域」）讓模型一次產生多個語義或實例遮罩，減少逐區手動描繪的負擔，並保留問答對話能力以說明判斷依據。

2. **遙感影像小目標解析**  
   應用於衛星或空拍影像時，STAMPlus 可透過高解析度遮罩詞元縮放，對道路、車輛、建物、農地等細小目標進行開放詞彙語義分割與實例感知分割，支援災害評估、城市規劃與環境監測。

3. **自動駕駛與機器人視覺理解**  
   車載或機器人系統可接收「請分割前方所有行人與車輛」這類指令，模型在單次非自迴歸前向傳遞中同時輸出多目標遮罩，降低感知延遲，並能與駕駛決策模組進行多輪對話確認。

4. **電商與內容創作的智慧去背 / 物件分離**  
   使用者以口語描述（如「把畫面中所有紅色鞋子和背景分開」）觸發分割，模型一次完成多實例去背，適用於商品圖生成、影片剪輯與擴增實境內容製作。

5. **工業品質檢測**  
   在生產線上，以語言指令指定缺陷類型（如「標出所有刮痕與污點」），模型可同時輸出多類別缺陷遮罩，並透過對話介面回報檢測結果與統計數量。

### 實作前置條件

**資料需求**
- 具備影像–指令–遮罩配對的多模態資料集，例如指稱分割（refCOCO 系列）、推理分割（ReasonSeg）、開放詞彙語義分割（ADE20K、COCO-Stuff）以及遙感小目標資料。
- 若應用於特定領域，需準備領域專屬的目標列表格式資料，包含類別 ID、可選邊界框與像素級標註。
- 建議同時保留一般多模態指令遵循資料，以維持模型的對話能力。

**運算需求**
- 至少具備 24GB 以上 VRAM 的 GPU（如 A100 / H100）用於微調與推論。
- 高解析度遮罩詞元縮放會增加記憶體與計算量，處理高解析度遙感或醫療影像時需評估記憶體配置與批次大小。
- 推論階段雖比逐詞元生成快，但仍需為 Phase 1 語言生成與 Phase 2 全遮罩預測預留足夠的計算資源。

**技能需求**
- 熟悉多模態大型語言模型（MLLM）架構、注意力機制與微調流程。
- 具備影像分割資料前處理與評估指標（mIoU、AP、PQ 等）的實作經驗。
- 能夠設計結構化目標列表的解析與後處理管線，並將遮罩輸出轉換為產品所需的格式（如 JSON、PNG、RLE）。

### 實作步驟建議

1. **環境建置與模型初始化**  
   從 STAMPlus 提供的統一檢查點出發，準備支援混合注意力與多類別分割頭的程式碼環境，並載入預訓練的 MLLM 骨幹與視覺編碼器。

2. **資料格式對齊**  
   將領域資料轉換為兩階段訓練格式：Phase 1 產生結構化目標列表（含 ID 與可選邊界框），Phase 2 對應多類別遮罩空間的像素級標註。

3. **第一階段：結構化目標列表生成訓練**  
   微調語言模型部分，使其能根據影像與指令輸出正確的目標 ID 與邊界框。此階段重點在於讓模型學會將開放詞彙語義或實例身份對應到離散 ID。

4. **第二階段：多類別全遮罩預測訓練**  
   固定或輕微調整語言模型，訓練多類別遮罩分類頭。將遮罩詞元與對應圖塊特徵融合，以非自迴歸方式一次預測所有目標的前景類別。

5. **高解析度遮罩詞元縮放調校**  
   針對小目標或高解析度場景，調整遮罩詞元的空間解析度，確保細微空間證據得以保留，同時監控記憶體用量。

6. **聯合微調與對話能力保留**  
   混合分割任務資料與一般多模態指令遵循資料進行聯合訓練，避免像素級目標干擾語言建模，維持對話能力。

7. **推論管線部署**  
   部署時先執行 Phase 1 取得結構化目標列表，再將 ID 綁定至多類別遮罩空間，執行單次 Phase 2 前向傳遞取得所有遮罩，最後進行後處理與視覺化。

8. **評估與迭代**  
   在目標任務上評估分割效能、指令遵循能力與推理延遲，並根據錯誤案例回頭改善目標列表準確度或遮罩解析度。

### 潛在風險與注意事項

- **目標列表錯誤會放大遮罩錯誤**  
  Phase 1 若產生錯誤的 ID 或遺漏目標，Phase 2 會繼承這些錯誤。建議加入目標列表驗證機制，並在關鍵應用中保留人工確認步驟。

- **高解析度帶來的記憶體壓力**  
  高解析度遮罩詞元縮放雖能提升小目標表現，但會顯著增加 VRAM 消耗。建議採用漸進式解析度測試，並考慮梯度檢查點或模型平行策略。

- **開放詞彙類別的歧義性**  
  使用者指令中的類別描述可能模糊，導致 ID 綁定錯誤。可透過 few-shot 提示、類別詞表限制或對話澄清來降低風險。

- **多目標遮罩重疊與實例混淆**  
  在語義與實例並存的場景中，需特別注意重疊區域的類別分配與實例 ID 一致性，必要時加入後處理（如 NMS、遮罩合併規則）。

- **對話能力退化**  
  過度強調分割目標可能削弱一般對話表現。應持續監控通用多模態指令遵循基準，並保留適量的純語言與視覺問答訓練資料。

- **延遲與即時性權衡**  
  雖然 STAMPlus 已將 12 類別延遲從 13.50 秒降至 5.16 秒，但對於極低延遲場景（如自動駕駛）仍需進行模型量化、快取或邊緣部署優化。

### 與其他技術的整合建議

- **與現有 MLLM 服務整合**  
  可將 STAMPlus 作為視覺理解後端，透過 API 接收自然語言指令，並回傳結構化目標列表與遮罩，前端維持原有的對話介面。

- **與傳統電腦視覺管線互補**  
  對於需要極高精度的任務，可將 STAMPlus 的輸出作為 SAM、Mask R-CNN 或 U-Net 的初始提示，再進行細部精修。

- **與向量資料庫 / 知識庫結合**  
  在醫療或工業應用中，可將分割結果與領域知識庫連結，讓模型在對話中引用結構化診斷標準或缺陷分類規範。

- **與 3D 重建或數位孿生平台對接**  
  將多實例遮罩輸出轉換為點雲或網格標註，支援三維場景重建、機器人導航與虛擬環境生成。

- **與 MLOps 監控系統整合**  
  部署時記錄 Phase 1 目標列表與 Phase 2 遮罩品質指標，建立漂移偵測與自動再訓練機制，確保長期穩定性。
