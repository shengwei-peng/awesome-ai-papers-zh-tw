# 蒸餾防禦在強化學習後輕易失效

**原文標題：** Distillation Defenses Easily Break After Reinforcement Learning  
**作者：** Shidan Javaheri、Alexander Panfilov、Oliver Britton 等 5 位作者  
**發布日期：** 2026-09-28  
**HF 連結：** [https://huggingface.co/papers/2609.35699](https://huggingface.co/papers/2609.35699)  
**arXiv：** [https://arxiv.org/abs/2609.35699](https://arxiv.org/abs/2609.35699)  

---

## ⚡ TL;DR

現有蒸餾攻擊威脅模型忽略攻擊者後續強化學習，造成虛假安全感。
本文提出納入蒸餾後強化學習的真實威脅模型，並以摘要重建軌跡進行簡單攻擊。
實驗顯示強化學習能破解現行防禦，簡單攻擊即可達到複雜攻擊的推理能力提升效果。

---

## 摘要翻譯

蒸餾攻擊（Distillation attacks）會複製閉源大型語言模型（closed-source large language models）的推理能力（reasoning capabilities），使惡意行為者（bad actors）得以以低成本複製最先進的效能（state-of-the-art performance）。攻擊者（attackers）系統化地收集大量前沿模型（frontier model）的推理軌跡（reasoning traces），並在這些軌跡上訓練（即「蒸餾」（distill））自己的模型。現有的蒸餾防禦（distillation defenses）通常於蒸餾（distillation）完成後立即評估，隱含假設攻擊者不會再進一步訓練（train）其模型。在本文中，我們主張一個更貼近現實的威脅模型（threat model）應包含蒸餾後以強化學習（reinforcement learning, RL）進行的進一步訓練。設定錯誤的威脅模型（misspecified threat model）會帶來虛假的安全感（false sense of security）——某些在蒸餾後看似有效的防禦，可能在後續的強化學習（reinforcement learning）後被破解。實務上，強化學習（reinforcement learning）降低了蒸餾攻擊（distillation attacks）生效的門檻。我們證明，簡單攻擊（simple attacks）僅需利用現行 API（current APIs）即可輕易取得的資料，就能從現有閉源大型語言模型（closed-source language models）中竊取推理能力，並達到與提取完整隱藏軌跡（hidden traces）的更複雜攻擊（sophisticated attacks）相當的推理能力提升（reasoning improvements）。結果顯示，任何洩漏足夠資訊（leak sufficient information）以重建近似推理軌跡（approximate reasoning traces）的蒸餾防禦（distillation defense），很可能都無效。最後，我們討論更廣泛的影響（broader implications），以及可能更有效的批次級蒸餾防禦（batch-level distillation defenses）。

### 核心貢獻（3～5點）
- 提出更貼近現實的威脅模型：蒸餾後再以強化學習進行進一步訓練。
- 指出設定錯誤的威脅模型會造成虛假的安全感，部分防禦在蒸餾後看似有效，卻會在後續強化學習後被破解。
- 證明簡單攻擊僅需利用現行 API 可取得的資料，就能達到與提取完整隱藏軌跡的複雜攻擊相當的推理能力提升。
- 指出任何洩漏足夠資訊以重建近似推理軌跡的蒸餾防禦很可能無效。
- 討論更廣泛的影響，並提出可能更有效的批次級蒸餾防禦。

### 適合對象
AI 安全研究者、大型語言模型開發者、前沿實驗室（frontier labs）政策與安全團隊，以及關注模型智慧財產保護與對齊（alignment）的學術與產業讀者。

## 深度分析

#### 方法論解析

本研究的核心方法論在於重新界定蒸餾攻擊（distillation attacks）的威脅模型（threat model）：傳統評估假設攻擊者在取得前沿模型（frontier model）的輸出後，僅進行一次蒸餾（distillation）訓練便停止；然而作者主張，真實且具能力的攻擊者極可能在蒸餾後繼續執行強化學習（reinforcement learning, RL），因為 RL 正是當前大型語言模型（large language model, LLM）後訓練（post-training）管線中提升推理能力（reasoning capabilities）的關鍵且運算最密集的階段。整體攻擊流程（attack pipeline）可概括為：攻擊者（adversary）透過合法 API 存取（legitimate API access）向閉源大型語言模型（closed-source large language models）發送大量提示（prompts），系統化擷取（systematic extraction）推理軌跡（reasoning traces）與答案，存入資料儲存庫（data store），先用這些資料蒸餾自己的模型，再於可驗證任務上進行 RL 訓練，最終得到具備強大推理能力的蒸餾模型（distilled models）。

在方法設計上，作者對比了三種訓練設定：僅強化學習基線（RL Only baseline）、僅蒸餾（distillation only），以及蒸餾後接續 RL。這樣的對照能夠分離「模仿教師輸出」與「透過獎勵訊號自我增強」兩種機制的貢獻。更具體地，RL 階段通常讓模型對困難問題生成多個回答，並根據正確性給予獎勵，從而放大正確推理路徑的機率、壓抑錯誤路徑。由於蒸餾提供了不錯的初始策略（policy），後續 RL 能夠在教師模型輸出的基礎上進一步探索，彌補防禦機制造成的資訊損失。

本研究還提出一種極為簡單的攻擊變體：不直接提取完整隱藏軌跡（hidden traces），而是利用現行 API 中可輕易取得的推理軌跡摘要（reasoning trace summaries）與最終答案，重建近似推理軌跡（approximate reasoning traces）。這種方法無需訓練額外的擴展模型（expander），大幅降低攻擊門檻。作者進一步將此簡單攻擊與現有部署中的蒸餾防禦（distillation defenses）——例如反蒸餾取樣（anti-distillation sampling）以及 GPT、Claude、Gemini 等模型所採用的摘要式推理輸出——進行對抗測試，從而檢驗「在蒸餾後看似有效」的防禦是否能在 RL 後仍然成立。

#### 實驗數據解讀

根據摘要與引言所述，實驗結果呈現幾個值得深入解讀的現象。首先，在訓練管線的比較中，作者發現僅使用強化學習的模型往往優於僅使用蒸餾的模型，而「蒸餾 + RL」的組合表現最佳。這意味著蒸餾並非攻擊的終點，而是為後續 RL 提供良好起點；對於擁有足夠運算資源的惡意行為者（malicious actors）而言，蒸餾後接 RL 是理性且高效的選擇。

其次，針對反蒸餾取樣這類廣為人知的防禦，實驗顯示若在蒸餾後立即評估，防禦似乎有效——模型性能因教師輸出被干擾而下降；然而一旦對蒸餾模型進行額外的強化學習，性能便顯著恢復，防禦隨之被破解。這說明防禦效果的評估時點至關重要：僅在蒸餾後檢測會產生虛假的安全感（false sense of security），因為 RL 能夠從受損但仍可學習的資料中提煉出有用的推理策略。

第三，簡單攻擊與複雜攻擊（sophisticated attacks）在 RL 後達到相近的推理能力提升（reasoning improvements）。具體而言，利用摘要重建近似推理軌跡所訓練出的模型，在經過 RL 後，其表現與直接使用完整未摘要軌跡蒸餾的模型相當。這項結果的含義極為廣泛：任何會洩漏足夠資訊以重建近似推理軌跡的蒸餾防禦，都很可能無效。換句話說，防禦的成敗取決於資訊洩漏量是否低於「可學習閾值」，而非是否完全隱藏軌跡。

在評估指標方面，雖然提供的摘錄未列出詳細數字，但可以合理推測作者使用了數學推理（如 MATH、AIME、GSM8K）與程式碼生成（如 HumanEval）等可驗證任務的準確率（accuracy）或 pass@k 作為主要指標。這類指標與 RL 的獎勵函數天然對齊，因此能夠清楚呈現 RL 對蒸餾模型的增益。未來若能看到完整實驗數據，應特別關注樣本數、變異數、不同模型規模與不同 RL 演算法（如 PPO、GRPO、REINFORCE）之間的差異，以判斷結論的穩健性。

#### 與現有研究的比較

本研究與先前文獻最關鍵的差異在於對威脅模型的設定。既有研究（如 Savani et al., 2025; Xu et al., 2026; Zhang et al., 2026; Li et al., 2025; Libon et al., 2026）以及前沿實驗室（frontier labs）的內部評估（Anthropic, 2026e, Sec. 5.1.1）幾乎都在蒸餾結束後立即評估防禦效果，隱含假設攻擊者不會進一步訓練。本文則指出這是一種設定錯誤的威脅模型（misspecified threat model），並用實證說明加入 RL 後許多防禦會失效。

在攻擊方法上，Zhang et al.（2026）曾展示透過訓練擴展模型將摘要映射回完整軌跡以竊取推理能力；相較之下，本文提出的簡單攻擊無需訓練擴展模型，僅利用摘要與答案即可重建近似推理軌跡，操作上更為簡便，也更貼近公開報導中描述的攻擊樣態（Anthropic, 2026b）。因此，本研究不僅在理論上擴展了威脅模型，也在實務上降低了攻擊門檻，對防禦設計提出更嚴峻的挑戰。

然而，本研究也存在若干限制。首先，實驗主要聚焦於可驗證的推理任務，對於開放式生成、創意寫作或需要細微價值判斷的任務，RL 後的蒸餾效果可能不同。其次，研究假設攻擊者具備執行 RL 的運算資源與技術能力，雖然這對國家級或大型商業對手而言合理，但未必適用於所有惡意行為者。第三，文中測試的防禦主要來自現行商業 API 的輸出格式，對於未來可能出現的批次級蒸餾防禦（batch-level distillation defenses）或其他機制（如水印、異常偵測）的適用性仍需進一步驗證。最後，法律與倫理邊界並未納入威脅模型，實際攻擊還涉及服務條款、資料使用授權與責任歸屬等複雜問題。

#### 可重現性評估

從提供的摘錄來看，作者並未明確說明是否公開原始碼、資料集或模型權重。考量到本研究涉及對 Google、OpenAI、Anthropic 等商業模型的攻擊性評估，且已完成負責任揭露（responsible disclosure），完整實驗素材很可能基於安全與濫用風險而僅部分釋出或完全未公開。這在學術上是可以理解的，但對可重現性（reproducibility）確實造成挑戰。

若要重現本研究，研究者至少需要：(1) 能夠穩定存取目標閉源模型的 API，並在大量查詢下維持輸出一致性；(2) 取得與作者相同的提示設計、取樣參數與資料篩選流程；(3) 擁有足夠的運算資源執行蒸餾與 RL；(4) 使用相同的基礎模型（base model）、RL 演算法與獎勵函數。由於商業 API 的輸出可能隨時間更新，且存在速率限制與成本問題，即使釋出程式碼，完全重現原始結果仍有困難。

為提升可重現性，建議作者至少公開：(a) 經去識別化或合成的查詢資料集與提示模板；(b) 訓練與評估的程式碼框架（不含實際 API 金鑰）；(c) 詳細的超參數與 RL 獎勵設計；(d) 評估指標的計算方式與原始結果表格。如此一來，其他研究團隊可以在不同模型與環境下驗證核心發現，同時降低技術被直接濫用的風險。

#### 未來研究方向

本研究為蒸餾攻擊與防禦領域開啟了多條值得探索的路徑：

1. **批次級蒸餾防禦（batch-level distillation defenses）**：作者已指出單一查詢層級的防禦可能不足，未來可設計能偵測跨查詢、跨帳號異常行為的批次級防禦，例如偵測系統化擷取（systematic extraction）模式或大量相似提示的聚集。

2. **資訊洩漏的理論刻畫**：建立「要讓 RL 成功恢復推理能力，摘要或輸出至少需要洩漏多少資訊」的量化框架，有助於在設計防禦時明確可接受的資訊揭露上限。

3. **強化學習感知防禦設計**：現有防禦多針對蒸餾階段優化，未來應將 RL 階段納入對抗訓練目標，尋找既能維持正常使用者（normal users）體驗，又能最小化 RL 可學習訊號的輸出格式。

4. **API 使用監控與異常偵測**：結合機器學習方法分析 API 呼叫模式，及時標記潛在的蒸餾攻擊行為，並與輸出層防禦形成多層次防護。

5. **輸出溯源與浮水印技術**：為推理軌跡（reasoning traces）與最終答案嵌入難以移除的浮水印，便於事後追蹤與舉證，並抑制大規模未授權蒸餾。

6. **安全護欄與有害能力的轉移研究**：除了推理能力，未來應探討蒸餾加 RL 是否也會複製或增強教師模型的安全護欄繞過能力，以及如何避免 guardrail-free 模型被用於惡意目的。

7. **攻擊與防禦的經濟分析**：量化蒸餾攻擊加上 RL 的總成本，並與開發同等能力模型的成本比較，為政策制定者與平台營運商提供決策依據。

8. **跨語言與多模態蒸餾**：將威脅模型擴展至多語言與多模態情境，檢視 RL 後蒸餾是否同樣能夠複製視覺推理、程式碼理解等更廣泛的能力。

9. **動態防禦與適應性攻擊的競賽**：建立持續演進的紅隊（red teaming）機制，讓防禦方根據最新攻擊樣態動態調整輸出策略，並評估其長期有效性。

總結而言，這篇論文提醒我們：在評估蒸餾防禦時，必須將強化學習視為攻擊管線的標準環節，否則容易高估防禦效果。未來無論是學術研究或產業部署，都應以「蒸餾後接 RL」為基本假設，重新檢視並設計更具韌性的防禦機制。

## 論文問答

**Q1：什麼是蒸餾攻擊，為什麼它對閉源大型語言模型構成威脅？**  
A：蒸餾攻擊是指惡意行為者系統化地收集專有大型語言模型所產生的高品質推理軌跡，並利用這些軌跡來訓練自己的模型，從而以低成本複製前沿模型的推理能力。這種攻擊不僅能讓攻擊者取得接近最先進的效能，還可能繞過原始模型內建的安全防護機制，產生沒有安全護欄的強大模型。隨著能自主執行行動的 AI 代理日益普及，這類無護欄模型可能帶來更高的網路安全與濫用風險。

**Q2：現有的蒸餾防禦為何會給人一種虛假的安全感？**  
A：現有防禦幾乎都只在蒸餾訓練結束後立即評估效果，預設攻擊者不會再對模型進行後續訓練。然而，這種威脅模型設定過於狹隘，因為有能力的攻擊者很可能在蒸餾之後再加上強化學習來進一步提升模型。結果就是某些防禦在蒸餾後看起來有效，但在經過強化學習後卻輕易被破解，使防禦者誤以為系統已經安全。

**Q3：為什麼把強化學習納入威脅模型如此重要？**  
A：強化學習是現代大型語言模型後訓練管線中運算成本最高、也最能提升解題能力的階段，它透過對正確答案給予較高權重來強化推理表現。研究顯示，單獨使用強化學習的模型通常優於單純蒸餾的模型，而結合蒸餾與強化學習的模型表現最佳。因此，真實且有能力發動攻擊的對手極有可能採用「先蒸餾、再強化學習」的完整流程，忽略這一點會嚴重低估攻擊風險。

**Q4：本研究的核心方法是什麼？**  
A：本研究將蒸餾攻擊的評估從「僅蒸餾後」延伸到「蒸餾後再進行強化學習」的完整管線，並比較不同訓練策略下的模型表現。作者設計了簡單的攻擊方式，利用現行 API 就能取得的推理軌跡摘要與答案，重建近似的推理軌跡來訓練模型。透過這種貼近真實攻擊者的設定，研究檢驗了多種現有防禦在更完整威脅模型下的有效性。

**Q5：本研究的主要創新點是什麼？**  
A：本研究首次系統性地指出，現有蒸餾防禦的威脅模型設定錯誤，因為它們忽略了攻擊者會在蒸餾後使用強化學習。研究進一步證明，即使只洩漏推理軌跡摘要這類看似不完整的資訊，攻擊者也能在強化學習後達到與提取完整隱藏軌跡相近的效能提升。這項發現挑戰了「只要隱藏完整推理軌跡就能有效防止蒸餾」的直覺，並強調資訊洩漏量的重要性。

**Q6：研究在實驗設計上做了哪些關鍵選擇？**  
A：作者選擇使用 GPT、Claude 與 Gemini 等現行閉源模型所回傳的推理軌跡摘要，而非直接取得完整隱藏軌跡，以模擬真實 API 可獲得的資訊。他們刻意採用無需額外訓練「擴展器」的簡單攻擊，降低攻擊門檻並貼近實際可行的場景。此外，實驗在可驗證的困難問題上進行強化學習，以衡量推理能力的真實提升幅度。

**Q7：實驗使用了哪些評估方式或任務？**  
A：實驗主要針對可驗證的困難推理問題進行評估，例如數學推理與程式編寫等需要多步驟思考才能得出正確答案的任務。這類問題特別適合用強化學習進行後訓練，因為可以明確判斷答案正確與否並給予獎勵。研究透過比較不同訓練條件下的推理能力提升，來判斷蒸餾攻擊是否成功以及防禦是否失效。

**Q8：本研究有哪些關鍵實驗結果？**  
A：結果顯示，結合蒸餾與強化學習的模型表現優於單獨蒸餾或單獨強化學習的模型，證實完整攻擊管線的威脅性。更重要的是，僅用推理軌跡摘要重建出的近似軌跡，在經過強化學習後能達到與使用完整未摘要軌跡相近的效能提升。此外，知名的反蒸餾取樣防禦在蒸餾後看似有效，但在強化學習後卻被輕易破解。

**Q9：研究進行了哪些對照或消融分析？**  
A：作者設立了「僅強化學習基線」、「僅蒸餾」以及「蒸餾後再加強化學習」三種條件，以確認強化學習在攻擊管線中的貢獻。他們也比較了簡單攻擊與更複雜、需要訓練擴展器才能還原完整軌跡的攻擊，發現兩者在強化學習後效果相近。這些對照說明強化學習顯著降低了蒸餾攻擊的門檻，並凸顯現有評估方式的不足。

**Q10：這項研究在實際應用場景中有何意義？**  
A：在實務上，惡意行為者可以透過合法 API 存取大量收集推理軌跡摘要與答案，再以低成本蒸餾並強化學習出具有強大推理能力的模型。這些模型可能缺少原始供應商設置的安全護欄，進而被用於網路攻擊、詐騙或其他有害用途。隨著自主 AI 代理的能力持續增強，這類無護欄模型的風險將變得更加嚴重。

**Q11：對於產品開發與模型供應商，本研究帶來哪些啟示？**  
A：模型供應商不應假設只要回傳摘要或隱藏完整推理軌跡，就能有效防止蒸餾攻擊，因為摘要仍可能洩漏足夠資訊讓攻擊者重建近似軌跡。開發防禦時需要考慮雙重用途的兩難：過度刪除推理內容會損害正常使用者的研究與學習體驗，但保留內容又可能助長攻擊。因此，供應商應評估更進階的防禦策略，例如批次級蒸餾防禦，並在完整攻擊管線下進行測試。

**Q12：這項研究對整個 AI 安全領域可能產生什麼影響？**  
A：本研究促使學界與業界重新審視蒸餾攻擊的威脅模型，將評估標準從「蒸餾後」推進到「蒸餾加強化學習後」。這將帶動新一輪針對資訊洩漏量、軌跡重建難度與批次級防禦的研究。同時，它也凸顯了防禦設計與攻擊方法之間持續的軍備競賽，提醒防禦者必須採取更貼近真實對手行為的評估方式。

**Q13：作者承認哪些研究限制？**  
A：作者指出，真實世界中攻擊者的完整訓練管線並不公開，因此實驗只能根據合理推測來設計威脅模型。此外，研究主要聚焦於可驗證的推理任務，對於其他類型的能力或防禦機制可能無法完全涵蓋。實驗所使用的資料來自現行 API，未來模型或 API 政策改變後，攻擊難度與防禦效果也可能隨之變化。

**Q14：在哪些情況下現有防禦會失效？**  
A：只要防禦機制洩漏了足夠讓攻擊者重建近似推理軌跡的資訊，無論是摘要、部分步驟或答案，就可能在強化學習後被破解。反蒸餾取樣防禦就是一個明顯例子，它在蒸餾後看似能降低攻擊效果，但經過強化學習後防禦效果便消失。此外，任何試圖透過刪除推理內容來防禦的做法，都會因為同時損害正常使用者而難以實際部署。

**Q15：未來有哪些值得深入研究的方向？**  
A：未來可以進一步發展批次級蒸餾防禦，從整體資料分布與互動模式著手，而非僅針對單一輸出進行遮蔽。研究者也可以從資訊理論角度探討，究竟需要隱藏多少推理資訊才能有效阻止近似軌跡的重建。此外，在不同模型規模、任務類型與更長期的強化學習設定下驗證防禦效果，也是提升實務安全性的重要方向。

## 實務應用指南

### 適用場景

1. **保護閉源前沿模型的推理能力**：前沿實驗室與專有大型語言模型提供者，希望防止惡意行為者透過 API 系統化擷取推理軌跡後進行蒸餾攻擊。
2. **設計 API 輸出策略**：需要在「提供足夠資訊給正常使用者」與「避免洩漏可重建近似推理軌跡的資訊」之間取捨的產品團隊。
3. **紅隊演練與防禦驗證**：安全團隊針對自家模型進行蒸餾攻擊模擬，驗證現行蒸餾防禦在強化學習後是否仍有效。
4. **第三方模型風險評估**：企業或監管機構評估市場上疑似經蒸餾取得的模型，是否複製了閉源前沿模型的推理能力。
5. **安全釋出推理資料集**：開源專案或研究機構在公開推理資料時，評估資料是否足以被用於後續強化學習並複製模型能力。

### 實作前置條件

- **資料**：
  - 可驗證的困難推理任務資料集（例如數學證明、程式競賽題、邏輯謎題）。
  - 從目標專有模型取得的各種輸出形式：完整推理軌跡、摘要版推理軌跡、僅答案。
  - 用於強化學習的獎勵訊號（正確性檢查器、單元測試、形式化驗證器）。
- **運算**：
  - 可執行監督式微調（SFT）的 GPU/TPU 叢集。
  - 可執行強化學習（RL）的訓練基礎設施，例如支援 PPO、GRPO、DPO 或 REINFORCE 的框架。
  - 自動化評估管線，能在蒸餾後與強化學習後分別測量模型能力。
- **技能**：
  - 熟悉大型語言模型微調與強化學習。
  - 具備威脅模型建構與對抗式評估經驗。
  - 了解 API 輸出政策、使用者體驗設計與資料治理。
  - 能夠設計與維護獎勵函數與可驗證基準。

### 實作步驟建議

1. **重新定義威脅模型**：將攻擊流程視為「蒸餾＋強化學習」兩階段，而非僅評估蒸餾後的模型。
2. **盤點資訊洩漏點**：分析 API 輸出中哪些內容可被用來重建近似推理軌跡，例如摘要、部分步驟、錯誤訊息或置信度分數。
3. **設計多種防禦變體**：實作不同層級的輸出限制，如完整軌跡、摘要軌跡、反蒸餾取樣（anti-distillation sampling）、批次級防禦等。
4. **建立兩階段評估管線**：先對基礎模型進行蒸餾，再對蒸餾模型進行強化學習，並在每個階段後測量能力。
5. **執行簡單攻擊作為基線**：使用摘要重建的近似推理軌跡或僅答案資料進行蒸餾，觀察強化學習後是否仍能複製推理能力。
6. **量化能力差距**：比較「僅強化學習基線」、「僅蒸餾」、「蒸餾＋強化學習」與「完整軌跡蒸餾」的效能差異。
7. **迭代防禦設計**：根據評估結果調整輸出策略，目標是在不嚴重損害正常使用者體驗的前提下，降低可重建推理軌跡的資訊量。
8. **部署監控與異常偵測**：在 API 閘道層監控大規模、系統化擷取行為，並結合速率限制與使用條款。
9. **建立負責任揭露流程**：在公開研究成果或部署新防禦前，與相關模型提供者進行協調與揭露。

### 潛在風險與注意事項

- **虛假的安全感**：只在蒸餾後評估防禦可能會高估防禦效果，因為後續強化學習可能輕易破解原本看似有效的防禦。
- **雙重用途困境**：過度刪除推理步驟雖可降低蒸餾風險，但同時會損害研究人員、教育工作者與正常使用者的體驗。
- **簡單攻擊即可奏效**：即使只洩漏摘要或答案，攻擊者仍可能透過強化學習恢復相當程度的推理能力。
- **成本與延遲**：批次級蒸餾防禦或更嚴格的輸出控制可能增加推理延遲與營運成本。
- **法律與合規風險**：使用 API 輸出進行蒸餾可能違反服務條款；防禦設計也應符合資料保護與智慧財產權規範。
- **獎勵函數設計失當**：強化學習階段的獎勵若過於狹隘，可能導致評估結果不穩定或產生過擬合現象。

### 與其他技術的整合建議

- **MLOps 與實驗追蹤**：將兩階段評估（蒸餾後、強化學習後）整合進持續訓練與模型發布管線，並記錄每次實驗的威脅模型假設。
- **API 閘道與可觀測性**：在 API 層結合速率限制、異常偵測與輸出政策控制，即時阻擋系統化擷取行為。
- **安全評估框架**：與現有紅隊工具、模型卡（model cards）與安全基準整合，定期執行蒸餾攻擊模擬。
- **RLHF 與對齊管線**：將抗蒸餾目標納入強化學習人類回饋（RLHF）訓練，避免防禦措施與模型對齊目標衝突。
- **資料治理與存取控制**：對內部推理資料集實施分級管理，限制可接觸完整推理軌跡的人員與系統。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦於核心概念——蒸餾攻擊不只是「複製答案」，而是透過系統化擷取推理軌跡來複製推理能力；本文最重要的結論是，如果只評估蒸餾後的模型，會產生虛假的安全感，因為後續強化學習可能讓原本看似安全的防禦失效。
- **AI 工程師**：建議重點閱讀實驗設計與評估管線，特別是如何在蒸餾後接續強化學習、如何重建近似推理軌跡，以及如何實作摘要軌跡與反蒸餾取樣等防禦；這些內容可直接轉化為內部紅隊與防禦驗證腳本。
- **研究人員**：請關注威脅模型設定、理論推論與未來工作，尤其是「任何會洩漏足夠資訊以重建近似推理軌跡的防禦都可能無效」這一結論，以及批次級蒸餾防禦的潛力；可進一步探索資訊理論下防禦有效性的上界。
- **產品經理**：請著重理解使用者體驗與智慧財產保護之間的權衡，例如提供推理摘要對正常使用者有幫助，但同時也可能被攻擊者利用；本研究提醒產品團隊在設計 API 輸出政策時，必須以「蒸餾＋強化學習」的完整攻擊流程作為假設情境。
