## ⚡ TL;DR

現有搜尋代理訓練資料過易，且推論框架影響難以區分。
提出Iris搜尋代理，從網頁圖反向建構改寫實體的多跳問題，並以SFT-RL爬升與即時搜尋訓練。
啟用上下文管理後，Iris在四項基準測試中達到同規模開源搜尋代理的最佳表現。

## 摘要翻譯

我們提出 Iris-mini 與 Iris-pro，兩個分別在 35B-A3B 與 397B-A17B 規模下訓練的 search agent（搜尋代理），以及其背後的 data pipeline（資料流程）與 training recipe（訓練配方）。任務是從 web corpus（網頁語料庫）的 hyperlink structure（超連結結構）reverse-constructed（反向建構）而來：我們在從 seed page（種子頁面）及其 out-link（外部連結）抽取出來的 entity graph（實體圖）上，撰寫 multi-hop chain（多跳鏈）；將每個 non-answer entity（非答案實體）改寫為 descriptive reference（描述性引用），使任何線索都無法透過 string matching（字串匹配）破解；並且只採納 reference model（參考模型）在 closed-book（閉卷）設定下無法回答，但給予 supporting evidence（支持證據）後即可解決的問題。這些問題接著被轉換為 trajectory（軌跡），在 SFT（Supervised Fine-Tuning，監督式微調）前同時以 trajectory-level filtering（軌跡層級過濾）與 turn-level filtering（回合層級過濾）進行篩選。接著，策略透過 RL（Reinforcement Learning，強化學習）在 live search（即時搜尋）環境中進行最佳化，reward judge（獎勵評判器）與 observation summarizer（觀察摘要器）部署於 training cluster（訓練叢集）內，over-long rollout（過長軌跡）會在 request level（請求層級）中斷，並於下一步從其 committed prefix（已確認前綴）繼續執行。我們將這兩個階段交替進行，稱之為 SFT-RL climbing（SFT-RL 爬升），並將每輪 RL 中的 hardest solved rollout（最難解出的軌跡）與 most efficient rollout（最有效率的軌跡）回傳至下一輪監督式訓練。

由於在這些 benchmark（基準測試）上，inference-time context management（推論時上下文管理）所帶來的效益，高於多數系統間已報告的差異，我們對每個 benchmark 都分別在啟用與未啟用它的情況下進行評估，同時固定 tool set（工具集）、context limit（上下文限制）與 judge（評判器）。所有結果均來自單一 ReAct agent（ReAct 代理），未使用 sub-agent（子代理），也沒有 test-time verification（測試時驗證）。在啟用上下文管理的情況下，兩個模型在 BrowseComp、BrowseComp-ZH、DeepSearchQA 與 HLE 上分別達到 82.2/84.8/86.9/52.3 與 88.6/85.1/92.9/56.4，在各自 parameter range（參數範圍）內，均為 open-source search agent（開源搜尋代理）中最強的整體表現。我們計畫釋出 model weights（模型權重），以及資料建構、訓練與評估的完整 recipe。

### 核心貢獻（3～5點）
- 提出從網頁超連結結構反向建構困難多跳問答任務的資料流程：透過實體圖、描述性引用與閉卷篩選，確保問題無法透過字串匹配或記憶直接回答。
- 設計 SFT-RL 爬升訓練配方，結合軌跡層級與回合層級過濾、即時搜尋強化學習、叢集內獎勵評判器與觀察摘要器，以及過長軌跡的中斷與續行機制。
- 系統性評估推論時上下文管理的影響，在固定工具集、上下文限制與評判器下，以單一 ReAct 代理達成多項基準測試的開源最佳表現。
- 計畫完整釋出模型權重與資料建構、訓練、評估配方，促進後續研究復現與擴展。

### 適合對象
從事大型語言模型代理、網頁搜尋與檢索增強生成、強化學習，以及開源模型訓練與評估的研究人員與工程師；對於希望建構或評估具備深度多跳推理與即時網頁搜尋能力之代理的讀者尤具參考價值。

## 深度分析

#### 方法論解析

Iris 系列的核心方法論可視為一條「從網頁結構反向生成任務 → 高品質軌跡（trajectory）監督 → 即時搜尋強化學習（RL）→ 迭代 SFT-RL 爬升」的端到端（end-to-end）配方。以下分階段說明。

**1. 以網頁圖（web-graph）為基礎的任務合成**

資料流程（data pipeline）並非直接收集自然網頁問題（naturally occurring web question），而是從網頁語料庫（web corpus）的超連結結構（hyperlink structure）反向建構（reverse-constructed）多跳（multi-hop）任務。具體步驟為：

- **種子頁面（seed page）選取與局部子圖（local subgraph）擴展**：從語料庫中以 answer-anchored 模式選取種子頁面 v₀，並沿其外部連結（out-link）擴展為局部子圖 G_sub。為了彌補渲染後頁面常遺失內嵌錨點的問題，作者結合 RDF triples 語義鏡像與頁面標記來最大化連結召回率。
- **實體圖（entity graph）萃取**：將 G_sub 壓縮為僅保留與種子主題相關、且位於多跳路徑上的實體與關係，形成緊湊的關聯骨架 G_e。
- **問題生成與錨點抽象化（anchor abstraction）**：以種子主題 y 為答案，在 G_e 上生成至少 N 跳的路徑 P 與初始問題 q₀。接著對所有非答案實體（non-answer entity）進行實體改寫（entity rewriting），將其具體名稱替換為描述性引用（descriptive reference），使得問題無法透過字串匹配（string matching）直接搜尋到答案。最終得到抽象化問題 q̃。

這一設計的關鍵在於「遮蔽易搜尋錨點（easily searchable anchor）」：若問題中保留實體原名，代理（agent）可能僅靠搜尋表面文字即可破解，無法訓練出真正的多步推理與證據組合能力。

**2. 雙準則驗證（dual-criteria verification）**

為確保題目既困難又可解，作者使用參考模型（reference model）M_ref 進行兩道檢驗：

- **困難度準則（difficulty criterion）**：M_ref 在閉卷（closed-book）設定下無法答對，即 c_diff = 1。
- **可解性準則（solvability criterion）**：當把實體圖 G_e 作為支持證據（supporting evidence）提供時，M_ref 能正確答對，即 c_solv = 1。

只有同時滿足兩者的題目才會進入訓練集 D。這種做法自動過濾掉記憶型問題與語意模糊、答案不唯一的問題，確保訓練資料客觀可驗證（objectively verifiable）。

**3. 軌跡層級與回合層級過濾（trajectory-level and turn-level filtering）**

在取得抽象化問題後，作者使用強教師模型（strong teacher）收集互動軌跡，並進行多階段過濾（multi-stage filtering）：

- **軌跡層級過濾**：剔除整體無法導向正確答案、過長或重複搜尋的軌跡。
- **回合層級過濾**：檢視單一步驟（turn）是否包含無效動作、錯誤推理或冗餘觀察，進一步提升監督式微調（SFT）資料的品質。

這兩層過濾的目標是避免模型在 SFT 階段模仿低品質行為，為後續 RL 奠定良好初始策略。

**4. 即時搜尋強化學習與 SFT-RL 爬升**

SFT 後的策略並非靜態，而是進入與真實線上環境互動的 RL 階段：

- **獎勵評判器（reward judge）與觀察摘要器（observation summarizer）** 皆部署於訓練叢集（training cluster）內，降低延遲並穩定訓練。
- **過長軌跡（over-long rollout）的中斷與續接**：當軌跡超過長度限制時，會在請求層級（request level）中斷，並於下一步從已確認前綴（committed prefix）繼續生成。這讓代理能在有限上下文內進行長期探索，同時保留已做出的承諾。
- **SFT-RL 爬升（SFT-RL climbing）**：每輪 RL 結束後，將「最難解出的軌跡（hardest solved rollout）」與「最有效率的軌跡（most efficient rollout）」回注到下一輪 SFT。這種交替機制讓 RL 發現的成功行為在下一輪探索前被鞏固，形成「探索 → 固化 → 再探索」的螺旋上升。

**5. 推論時上下文管理（context management, CM）的獨立評估**

作者特別強調，推論時框架（inference-time harness）中的上下文管理（CM）對長期搜尋至關重要。為了區分「策略本身能力」與「框架加成」，所有基準測試（benchmark）都在「啟用 CM」與「停用 CM」兩種設定下進行，並固定工具集（tool set）、上下文限制（context limit）與評判器（judge）。這種設計讓 CM 的影響可被直接測量，也避免過度高估模型本身的能力。

#### 實驗數據解讀

論文在四個高難度基準測試上評估 Iris-mini（35B-A3B）與 Iris-pro（397B-A17B）：

| 基準測試（benchmark） | Iris-mini（啟用 CM） | Iris-pro（啟用 CM） |
|---|---|---|
| BrowseComp | 82.2 | 88.6 |
| BrowseComp-ZH | 84.8 | 85.1 |
| DeepSearchQA | 86.9 | 92.9 |
| HLE | 52.3 | 56.4 |

**1. 整體趨勢：參數規模與任務難度的交互作用**

- **DeepSearchQA 進步最顯著**：從 Iris-mini 的 86.9 提升至 Iris-pro 的 92.9，顯示該基準測試對模型容量與長程證據整合能力高度敏感，更大的 397B-A17B 規模能顯著受益。
- **BrowseComp-ZH 幾乎持平**：Iris-mini 已達 84.8，Iris-pro 僅微升至 85.1。這可能意味著中文瀏覽任務在輕量模型上已接近飽和，或該測試的瓶頸更多來自檢索覆蓋率與語言理解，而非參數規模。
- **HLE 絕對值較低**：兩模型分別為 52.3 與 56.4，顯示 Humanity’s Last Exam（HLE）仍是極具挑戰的前沿領域。儘管相對提升約 4%，但距離人類水準或完全解決仍有明顯差距。

**2. 上下文管理（CM）的影響**

雖然論文未在摘要中列出無 CM 的詳細數字，但明確指出「inference-time context management is worth more on these benchmarks than most reported differences between systems」。這句話具有兩層含義：

- CM 對最終分數的貢獻可能大於許多系統間的差異，忽略 CM 會導致比較失真。
- 不同研究在工具介面、上下文限制與評判器上的差異，可能會被 CM 放大或掩蓋。

因此，作者堅持「雙設定報告」是此研究在評估協定（evaluation protocol）上的重要貢獻。

**3. 單一 ReAct 代理（single ReAct agent）的設計意涵**

所有結果均來自單一 ReAct 代理，無子代理（sub-agent）與測試時驗證（test-time verification）。這代表：

- 性能提升主要來自訓練後的策略品質與上下文管理，而非推論時的額外計算預算（computation budget）或多代理協作。
- 相較於使用測試時驗證或專門驗證模組的系統，Iris 的設計更簡潔，也更易於分析與重現。

#### 與現有研究的比較

**1. 相對於早期工具使用與 ReAct 研究**

早期工作如 ReAct [14, 17, 26] 開創了交錯推理與行動（interleaved reasoning and acting）的範式，但多依賴監督式或自監督式訓練，且任務相對簡短。Iris 的貢獻在於將此範式擴展到長期、多跳、即時網頁搜尋，並透過 RL 與 SFT-RL 爬升持續提升策略。

**2. 相對於靜態語料庫與即時網頁 RL 研究**

文獻 [11, 8, 19, 29] 等已將 RL 應用於檢索，從靜態語料庫（static corpus）逐步轉向即時網頁（live web）。Iris 的差異在於：

- 獎勵評判器與觀察摘要器皆置於訓練叢集內，減少對外部 API 的依賴與延遲。
- 提出 request-level 中斷與 committed prefix 續接機制，解決長軌跡在有限上下文視窗（nominal context window）下的訓練穩定性問題。

**3. 相對於合成任務與遮蔽實體的方法**

[23, 10, 20, 12] 等研究已利用知識圖譜（knowledge graph）遍歷與遮蔽實體（masking entity）來提升難度。Iris 的創新在於：

- 從真實網頁圖結構（web-graph structure）出發，而非預先建構的知識圖譜，使任務更貼近真實網頁瀏覽場景。
- 採用描述性引用（descriptive reference）進行實體改寫，而非單純遮蔽名稱，迫使代理進行語意消歧（disambiguation-by-reasoning）而非字串匹配。
- 透過雙準則驗證同時保證困難度與可解性，避免生成過於牽強或無法驗證的題目。

**4. 相對於近期端到端搜尋代理**

[21, 6, 13, 2, 4, 9, 3, 1, 25, 18] 等近期系統已將合成問題生成、軌跡監督、RL 與長上下文推理（long-context inference）整合為標準流程。Iris 在以下方面有所改進：

- 強調推論時框架（inference-time harness）與上下文管理（CM）的獨立貢獻，避免將框架能力誤歸於模型能力。
- 採用 SFT-RL 爬升，將 RL 發現的高品質軌跡回注 SFT，形成持續學習循環。
- 在相同參數範圍（parameter range）內達到開源搜尋代理（open-source search agent）最強整體表現。

**5. 限制與潛在弱點**

- **資料流程依賴網頁語料庫品質**：若種子頁面或外部連結分布有偏，可能導致任務類型集中於特定領域。
- **參考模型 M_ref 的能力決定過濾門檻**：若 M_ref 過強或過弱，可能分別過度刪除可訓練樣本或保留過多記憶型問題。
- **觀察摘要器可能遺失細節**：雖然有助於上下文管理，但摘要過程可能壓縮掉回答高難度問題所需的關鍵資訊。
- **HLE 分數仍偏低**：顯示即使是大規模模型，在極端困難的開放領域問答上仍有顯著瓶頸。

#### 可重現性評估

**1. 開源承諾**

作者明確表示計畫釋出：

- 模型權重（model weights）：包含 Iris-mini 與 Iris-pro。
- 完整的資料建構（data construction）、訓練（training）與評估（evaluation）配方。

這對研究社群極具價值，因為搜尋代理的訓練流程涉及大量工程細節（如工具介面、觀察摘要器、評判器、上下文管理策略），單靠論文難以完全重現。

**2. 評估協定的透明性**

論文強調所有基準測試都在固定工具集、上下文限制與評判器下進行，並同時報告啟用與停用 CM 的結果。這種標準化有助於未來研究進行公平比較，減少「不同 harness 導致不可比」的問題。

**3. 仍待釐清的細節**

儘管承諾開源，目前摘要與引言尚未揭露以下細節：

- 網頁語料庫的具體來源與規模。
- 參考模型 M_ref 的確切型號與提示設計。
- 強教師模型（strong teacher）的身份與取樣策略。
- RL 的獎勵函數形式、折扣因子與訓練步數。
- 觀察摘要器與獎勵評判器的架構與訓練資料。

這些細節將在完整釋出後決定可重現性的高低。

#### 未來研究方向

**1. 更細緻的上下文管理（CM）機制**

本研究已證明 CM 對長期搜尋的關鍵性。未來可探索：

- 基於資訊價值的選擇性歷史移除（selective history removal），而非單純長度截斷。
- 分層式狀態壓縮（state compression），在不同抽象層次保留事實、推理鏈與行動歷史。
- 可學習的摘要策略，讓代理自行決定何時、如何壓縮觀察。

**2. 動態與對抗式網頁環境**

目前的即時搜尋（live search）雖是真實環境，但網頁內容可能隨時間變化。未來可研究：

- 如何讓代理處理過時、矛盾或故意誤導的網頁資訊。
- 在網頁結構變化（如連結失效、內容更新）下的穩健性。
- 對抗式任務生成，進一步測試代理的批判性檢索能力。

**3. 多代理與測試時驗證的整合**

Iris 刻意避免使用子代理（sub-agent）與測試時驗證（test-time verification）以突顯單一策略的強度。未來可研究：

- 在保持可解釋性的前提下，引入專門的驗證代理（verifier agent）進行事實查核。
- 使用多代理分工（如規劃代理、檢索代理、摘要代理）來處理更複雜的開放任務。
- 探索測試時計算擴展（test-time compute scaling）與訓練時 RL 的最佳組合。

**4. 跨語言與跨領域泛化**

BrowseComp-ZH 的結果顯示 Iris 具備中文能力，但未來可進一步探討：

- 在低資源語言網頁上的表現。
- 從一般網頁問答遷移到專業領域（法律、醫學、科學文獻）的能力。
- 多語言混合任務，例如需要用多種語言來源組合答案的場景。

**5. 資料流程的自我改進**

目前的 SFT-RL 爬升已將成功軌跡回注訓練。未來可進一步讓資料流程本身也參與 RL：

- 根據代理在 RL 中的失敗案例，自動生成更困難的訓練題目。
- 使用對抗式或課程式（curriculum）任務生成，持續推動搜尋前沿（search frontier）。
- 結合人類回饋（human feedback）來提升獎勵評判器的可靠性，特別是在 HLE 這類主觀性較高的基準測試上。

**6. 推論效率與成本優化**

更大規模的 Iris-pro 雖然性能更強，但推論成本也更高。未來研究方向包括：

- 開發更小的模型，使其在啟用 CM 後能接近大模型的性能。
- 設計早期停止機制，讓代理在證據充分時自動終止搜尋。
- 將部分推理與摘要卸載至更輕量的專家模組，降低整體計算預算（computation budget）。

## 論文問答

**Q1：搜尋代理與傳統語言模型評估相比，面臨的核心挑戰是什麼？**

A：搜尋代理必須在動態環境中決定「搜尋什麼」「如何詮釋檢索證據」「何時繼續探索」以及「何時停止並回答」，這與傳統語言模型評估中任務、上下文與計算預算大致固定的設定截然不同。由於代理需要與外部工具反覆互動，推理過程不再是閉式推理，而是長期、多步驟的決策序列。因此，評估與訓練搜尋代理時，必須同時考慮策略本身與圍繞策略的推論時框架，例如上下文管理與工具介面。

**Q2：為什麼現有方法難以訓練出真正強大的開源搜尋代理？**

A：自然網頁問題往往過於簡單，無法迫使代理進行多跳推理或有效使用搜尋工具，導致訓練資料缺乏挑戰性。此外，許多研究報告的效能差異其實來自推論時框架的不同，例如上下文管理、軌跡摘要或狀態壓縮，而非底層策略的差異。這使得社群難以判斷進步究竟來自模型能力，還是來自工程上的包裝與提示技巧。

**Q3：為什麼上下文管理（CM）在搜尋代理中特別重要，卻又需要謹慎評估？**

A：長期搜尋很容易耗盡名義上下文視窗，使有效搜尋預算遠小於理論上限，因此良好的上下文管理能顯著延長可用推理長度並提升成功率。然而，若只報告啟用 CM 的結果，會混淆「策略本身的能力」與「框架帶來的增益」，因為部分效能可能來自選擇性歷史移除或軌跡摘要等外部機制。Iris 的研究因此堅持在固定工具集、上下文限制與評判器的前提下，同時報告啟用與未啟用 CM 的結果，以隔離兩者的貢獻。

**Q4：Iris 的資料流程如何從網頁結構反向建構出高難度的多跳任務？**

A：研究團隊先從種子頁面出發，沿外部連結擴展出局部網頁圖，再將其蒸餾為緊湊的實體圖，保留朝向種子主題的多跳路徑。接著在實體圖上撰寫問題，並透過實體改寫把所有非答案實體替換成描述性引用，使代理無法透過字串匹配直接找到答案。最後只保留同時滿足「閉卷困難」與「給予證據後可解」雙重準則的題目，確保任務既具挑戰性又客觀可驗證。

**Q5：Iris 訓練配方的核心創新「SFT-RL 爬升」是什麼？**

A：SFT-RL 爬升是一種交替進行監督式微調與強化學習的迭代程序，每輪 RL 在真實即時搜尋環境中探索後，會把最難解出且最有效率的成功軌跡回饋到下一輪 SFT。這樣做的好處是讓模型先透過 RL 發現新行為，再透過 SFT 將這些行為穩定地內化為策略，避免單純 RL 的不穩定或單純 SFT 的資料瓶頸。此過程結合了軌跡層級與回合層級的過濾，確保進入下一輪訓練的資料品質足夠高。

**Q6：為什麼 Iris 要將非答案實體改寫為描述性引用，並採用雙重準則驗證？**

A：如果問題中保留原始實體名稱，代理可能直接搜尋該名稱並透過字串匹配繞過多跳推理，因此描述性引用強迫代理進行消歧與語義推理。雙重準則中的困難準則確保參考模型在閉卷情況下無法答對，避免任務過於簡單；可解準則則確保在提供支持證據後模型能正確回答，避免任務本身有歧義或無解。兩者交集保證了訓練資料既需要搜尋，又能被搜尋後的證據客觀驗證。

**Q7：Iris 在哪些基準測試上進行評估，這些測試各自測量什麼能力？**

A：Iris 評估了 BrowseComp、BrowseComp-ZH、DeepSearchQA 與 Humanity’s Last Exam（HLE）四個高難度基準。BrowseComp 與其中文版 BrowseComp-ZH 測量代理在網頁上進行多步瀏覽與資訊整合的能力；DeepSearchQA 聚焦深度檢索與多源證據合成；HLE 則涵蓋極具挑戰性的學術與專業問題，檢驗代理在長程推理與高階知識上的極限。這四個測試共同覆蓋了英文、中文與高難度知識推理等不同維度。

**Q8：Iris-mini 與 Iris-pro 在主要基準上的關鍵結果為何？**

A：在啟用上下文管理的情況下，Iris-mini 在 BrowseComp、BrowseComp-ZH、DeepSearchQA 與 HLE 分別達到 82.2、84.8、86.9 與 52.3；Iris-pro 則達到 88.6、85.1、92.9 與 56.4。這些成績使其成為各自參數範圍內整體表現最強的開源搜尋代理。值得注意的是，所有結果都來自單一 ReAct 代理，沒有使用子代理或測試時驗證，顯示策略本身已具備強大的端到端搜尋能力。

**Q9：Iris 如何透過對照實驗揭示上下文管理與策略本身的貢獻？**

A：研究團隊在固定工具集、上下文限制與評判器的前提下，分別測量啟用與未啟用上下文管理時的表現，從而直接量化 CM 帶來的增益。這種設計避免了將框架進步誤歸為模型進步，也讓其他研究者能更公平地比較不同策略。結果顯示，在長程搜尋基準上，推論時上下文管理往往比系統間多數已報告的差異更具影響力。

**Q10：Iris 這類搜尋代理在實務上可以應用於哪些場景？**

A：Iris 可應用於需要跨多個網頁或資料來源進行事實查核的場景，例如新聞驗證、法律研究或醫學文獻綜述。在中文與英文雙語環境下，它也能協助處理多語言的深度問答與市場情報蒐集。由於模型能自主決定搜尋策略，它特別適合問題本身複雜、答案分散且需要動態驗證的專業知識工作。

**Q11：若將 Iris 部署為產品，需要考慮哪些工程與營運因素？**

A：首先必須整合穩定的即時搜尋後端，並在訓練或推理叢集中部署獎勵評判器與觀察摘要器，以控制延遲與成本。其次，上下文管理策略會直接影響使用者體驗與每次查詢的 token 消耗，需要在準確率、回應速度與費用之間權衡。此外，由於代理會接觸動態網頁內容，必須建立內容安全、來源可信度與錯誤答案責任歸屬的機制。

**Q12：Iris 的開源釋出對搜尋代理領域可能帶來什麼影響？**

A：作者計畫釋出模型權重以及資料建構、訓練與評估的完整配方，這將大幅提升該領域的可重現性與研究透明度。透過公開端到端流程，其他研究者可以複製高難度多跳任務的生成方法，並在相同基準上公平比較不同策略。這也有助於建立「區分策略與推論時框架」的評估文化，推動開源搜尋代理從工程技巧競賽走向系統性的科學進步。

**Q13：Iris 的方法存在哪些已知的限制？**

A：資料品質高度依賴種子頁面與外部連結所構成的網頁圖，若語料庫有偏頗或連結稀疏，生成的任務可能無法涵蓋某些知識領域。雙重準則驗證仰賴參考模型，若參考模型對特定領域過於強大或過於弱小，可能導致題目被錯誤地剔除或保留。此外，在即時網頁上進行強化學習需要大量計算資源，且網頁內容會隨時間變化，可能影響訓練穩定性與結果的可比較性。

**Q14：在哪些情況下 Iris 可能會失敗或表現不佳？**

A：當問題需要超越實體圖結構的常識推理、數值計算或因果推斷時，僅依賴網頁連結反向建構的任務可能不足以訓練出對應能力。若描述性引用過於模糊或存在多種合理解釋，代理可能在消歧過程中迷失方向。另外，過長軌跡在請求層級被中斷後，雖然可以從已確認前綴恢復，但頻繁中斷仍可能導致上下文碎片化並降低最終答案的準確率。

**Q15：未來研究可以從哪些方向延伸 Iris 的工作？**

A：未來可以探索更智慧的自適應上下文管理，讓代理根據問題難度與當前證據狀態動態決定保留或丟棄哪些歷史資訊。也可以將資料流程擴展到更多語言、更多類型的結構化資料，以及真實使用者提出的開放式問題，而不僅限於從網頁圖反向建構的任務。此外，結合測試時驗證、多工具協作或更強大的基礎模型，或許能進一步推升搜尋代理在更廣泛知識前沿上的表現。

## 實務應用指南

### 適用場景

1. **企業級市場情報與競爭分析**：Iris 系列適合需要跨越多份財報、新聞、產業報告與公司官網進行多跳推理的場景。例如分析「某供應鏈上游廠商在特定地緣事件後，對下游品牌毛利率的影響」，代理必須依序檢索供應商名單、產能分布、財務數字並綜合判斷，無法靠單次搜尋完成。

2. **法律與合規盡職調查**：在併購或訴訟準備中，律師團隊需要追蹤公司股權結構、關鍵人關係網、歷史判決與監管裁罰。Iris 的實體圖反向建構與描述性引用機制，可協助代理在不能直接搜尋當事人姓名的情況下，透過關係鏈逐步定位目標資訊。

3. **學術研究與文獻綜述**：研究人員可讓代理針對跨領域主題進行深度檢索，例如「比較兩種不同機制在特定疾病模型中的實驗結果」。代理需在論文、資料集、方法論之間跳躍，並透過上下文管理維持長期檢索脈絡，最終產出附引用來源的摘要。

4. **複雜技術支援與故障排除**：面對多步驟錯誤訊息或跨系統整合問題，客服代理可依序查閱文件、版本紀錄、社群討論與原始碼倉庫，逐步縮小根因。SFT-RL 爬升訓練讓代理從成功解決案例持續學習更有效率的排查路徑。

5. **金融投資研究**：分析師可部署 Iris 進行跨來源的多跳驗證，例如追蹤「某 ETF 成分股中，同時符合特定 ESG 評級與區域營收門檻的標的」。代理需結合即時網頁、財經資料庫與評級機構報告，並在長軌跡中避免上下文耗盡。

### 實作前置條件

**資料需求**
- 具備超連結結構的網頁語料庫，並能從中抽取種子頁面與外部連結。
- 語義鏡像（如 RDF 三元組）與渲染後頁面標記，用於恢復真實 out-link 集合。
- 高品質的實體抽取與關係抽取管線，能將頁面蒸餾為緊密連通的實體圖。
- 參考模型（reference model）用於雙準則驗證：閉卷無法回答、給定證據後可正確回答。

**運算需求**
- 訓練叢集需支援 35B-A3B 或 397B-A17B 規模的語言模型微調與強化學習。
- 叢集內需部署獎勵評判器（reward judge）與觀察摘要器（observation summarizer），並能低延遲服務。
- 即時搜尋環境需穩定，並支援中斷過長軌跡與從已確認前綴恢復的機制。
- 評估階段需固定工具集、上下文限制與評判器，以進行有無上下文管理（CM）的對照實驗。

**技能需求**
- 熟悉監督式微調（SFT）、強化學習（RL）與 ReAct 代理架構。
- 具備分散式訓練、模型服務與訓練叢集維運經驗。
- 能設計客觀可驗證的評估協定與語義匹配評判器。
- 了解網頁結構、知識圖譜與資訊檢索基礎。

### 實作步驟建議

1. **建立網頁圖與語義鏡像**：從目標網頁語料庫建構有向圖 \(G=(V,E)\)，並透過 RDF 三元組與渲染標記恢復種子頁面的完整 out-link，確保連結召回率。此為後續反向建構任務的基礎。

2. **反向建構多跳任務**：採用 answer-anchored 模式選定種子頁面與目標答案實體，沿 out-link 展開局部子圖，抽取實體圖後生成至少 \(N\) 跳的多跳問題，再將所有非答案實體改寫為描述性引用，消除字串匹配捷徑。

3. **雙準則驗證與軌跡生成**：利用參考模型進行閉卷難度測試與給證據可解性測試，僅保留同時滿足兩者的題目。接著使用強教師模型針對合格題目生成互動軌跡。

4. **軌跡層級與回合層級過濾**：先以整條軌跡為單位篩除失敗或低品質案例，再針對單一步驟檢查動作合理性、觀察相關性與推理一致性，產出高品質 SFT 資料。

5. **SFT-RL 爬升訓練**：先以過濾後軌跡進行監督式微調，再於即時搜尋環境中執行強化學習。每輪 RL 結束後，將最難解出且最有效率的成功軌跡回餵至下一輪 SFT，反覆交替以穩定提升策略。

6. **部署推論框架與上下文管理**：在產品環境中固定工具集、上下文限制與評判器，提供「啟用 CM」與「未啟用 CM」兩種模式。啟用時需謹慎設計軌跡摘要與選擇性歷史移除策略，避免過度壓縮關鍵證據。

7. **持續評估與迭代**：在 BrowseComp、BrowseComp-ZH、DeepSearchQA、HLE 等基準測試上定期評估，並針對失敗案例更新資料流程與獎勵函數，形成資料—訓練—評估的閉環。

### 潛在風險與注意事項

- **上下文管理過度壓縮**：軌跡摘要或選擇性歷史移除可能誤刪關鍵證據，導致代理在後續步驟遺失已確認事實。建議保留已確認前綴與核心實體關係，並對摘要結果進行可解性驗證。

- **即時搜尋的延遲與成本**：RL 訓練期間需大量呼叫即時搜尋，可能產生高額費用與長時間等待。建議在叢集內部署快取層、限制每輪 rollout 長度，並於請求層級中斷過長軌跡。

- **獎勵評判器偏差**：若 judge 對答案正確性的判斷標準過鬆或過嚴，會直接影響 RL 收斂方向。建議使用多個 judge 進行交叉驗證，並定期以人工標註校準。

- **實體改寫後的歧義**：描述性引用雖能防止字串匹配，但若改寫不夠精確，可能使問題出現多重合理解答。需確保 \(A(e)\) 能唯一識別實體，並在驗證階段檢查答案唯一性。

- **動態網頁內容漂移**：訓練時使用的網頁內容可能在推論時變更，導致預期證據消失。建議記錄檢索時間戳、建立靜態快照備援，並在產品中設計降級策略。

- **錯誤累積與幻覺**：多跳推理中單步錯誤會沿軌跡放大。建議在關鍵節點引入事實檢查機制，並保留代理對每個結論的引用來源，便於追溯與人工審核。

### 與其他技術的整合建議

- **與 RAG 系統整合**：Iris 可作為 RAG 的上層推理引擎，負責決定檢索策略與多跳證據組合；底層向量資料庫則提供快速初篩，減少對即時網頁搜尋的依賴。

- **與知識圖譜整合**：將訓練階段產生的實體圖與企業內部知識圖譜對齊，可提升特定領域任務的準確率，並在上下文管理中提供更結構化的狀態表示。

- **與工作流程編排工具整合**：透過 LangChain、LlamaIndex 或自研 workflow engine 呼叫 Iris 代理，將其嵌入更長的業務流程（如盡職調查報告生成、客服工單處理）。

- **與可觀測性平台整合**：記錄每條軌跡的動作、觀察、獎勵與 judge 決策，並接入監控儀表板，以便即時發現檢索失敗、成本異常與效能衰退。

- **與人機協作驗證整合**：在關鍵決策點或高風險場景中，將代理的中間結論與最終答案提交人工確認，尤其適用於法律、醫療與金融領域。

---

### 給不同背景讀者的閱讀建議

**給初學者**：這篇論文展示了一個完整的搜尋代理訓練流程，從網頁結構產生題目、教導模型如何搜尋，到讓模型在真實網路上透過強化學習持續進步。建議先理解「多跳推理」與「ReAct 代理」的基本概念，再聚焦第 2 節的資料流程與第 3 節的 SFT-RL 爬升，不必一開始就深入數學細節。

**給 AI 工程師**：本論文的核心價值在於可複現的端到端配方，特別是軌跡層級與回合層級過濾、叢集內 judge 與 summarizer 的部署，以及請求層級中斷與前綴恢復的 RL 實作。建議仔細研究第 3 節的訓練配方，並評估如何將上下文管理模組移植到現有推論框架中。

**給研究人員**：論文在資料建構與評估協定兩方面均有貢獻，包括以實體改寫消除字串匹配捷徑、雙準則驗證確保題目難度與可解性，以及固定工具集與 judge 下對照有無上下文管理的實驗設計。建議關注這些方法論細節，並思考如何延伸至其他動態環境與多模態任務。

**給產品經理**：這份研究強調「推論時框架」與「底層策略」同樣重要，尤其是上下文管理對實際效能的顯著影響。建議將論文視為技術選型與產品設計的參考：在評估搜尋代理時，務必確認供應商是否固定了工具集、上下文限制與 judge，否則效能數字可能無法直接比較。
