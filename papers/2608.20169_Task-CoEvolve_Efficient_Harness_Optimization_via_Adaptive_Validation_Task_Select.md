## ⚡ TL;DR

現有 harness 優化每次迭代都評估完整固定驗證集，成本高昂且缺乏鑑別力。
本文提出 Task-CoEvolve，以變異數加權取樣動態選擇具鑑別力的驗證任務，並估計全集合效能。
實驗顯示，該方法僅用 20% 評估量即可媲美全集合搜尋，整體搜尋成本降低 67–80%。

## 摘要翻譯

我們提出一種透過自適應驗證任務選擇（adaptive validation task selection）來達成高效率 LLM harness 優化（harness optimization）的新方法。Harness 優化會依據驗證效能（validation performance）迭代重寫（iterative rewriting）harness 程式碼，在不更新底層模型權重（underlying model weights）的情況下實現顯著的效能提升。然而，現有方法在每次迭代都會完整評估一個固定驗證集（fixed validation set），即便某些任務會隨 harness 演化而變得較不具鑑別力，仍須付出可觀的評估成本（evaluation cost）。我們提出 Task-CoEvolve，透過解決兩項挑戰——選擇具資訊量的任務（informative tasks），以及從部分評估（partial evaluations）估計全集合效能（full-set performance）——使驗證任務與 harness 協同演化（co-evolve）。Task-CoEvolve 基於以下觀察：候選 harness（candidate harnesses）之間結果不一致的任務，比持續成功或持續失敗的任務更具資訊量，更能區分不同候選 harness。它根據過往結果使用變異數加權取樣（variance-weighted sampling），將評估聚焦於能力前沿（capability frontier）附近的任務，並隨 harness 演化調整取樣分佈（sampling distribution）。接著，它考量被抽樣任務的取樣機率（sampling probabilities），從中估計全集合效能分數（full-set scores），使得即使在不同迭代中評估不同子集，仍能進行一致的比較。在線上文字分類（online text classification）與 Terminal-Bench 2.1 上的實驗顯示，Task-CoEvolve 始終優於基於子集合的基線方法（subset-based baselines），並在最終效能上與全集合搜尋（full-set search）相當，同時將優化過程中的評估次數減少 80%。程式碼將於 https://github.com/Agent4Science-UTokyo/Task-CoEvolve 釋出。

### 核心貢獻（3～5點）
- 提出 Task-CoEvolve，讓驗證任務與 harness 協同演化，突破傳統固定驗證集在每次迭代都需完整評估所造成的成本瓶頸。
- 基於候選 harness 之間的結果分歧，使用變異數加權取樣動態聚焦能力前沿附近的任務，並隨 harness 演化持續調整取樣分佈。
- 透過考量被抽樣任務的取樣機率，從部分評估中估計全集合效能分數，確保不同迭代間的評估結果具有一致可比性。
- 在線上文字分類與 Terminal-Bench 2.1 上驗證，相較於全集合搜尋可減少 80% 的評估次數，同時達到相當的最終效能。

### 適合對象
對 LLM harness 優化、自動化程式碼生成、模型評估效率與基準測試設計感興趣的研究人員與工程師，特別是關注如何在迭代優化過程中降低評估成本、同時維持驗證準確性與比較一致性的讀者。

## 深度分析

#### 方法論解析

Task-CoEvolve 的核心目標是在 **harness 優化（harness optimization）** 的每一次迭代中，只評估一部分 **驗證任務（validation tasks）**，同時仍能正確比較不同 **候選 harness（candidate harnesses）** 並估計它們在完整驗證集上的 **全集合效能（full-set performance）**。這可以視為一個「驗證任務與 harness 協同演化（co-evolve）」的過程：隨著 harness 不斷被重寫，哪些任務最能區分候選 harness 也會改變，因此驗證任務的 **取樣分佈（sampling distribution）** 必須動態調整。

##### 問題形式化

假設底層大型語言模型（LLM）與其權重固定不變，優化的對象是圍繞模型的 **harness**（即控制資料儲存、檢索與呈現給模型的程式碼）。令驗證集為 \(T=\{1,\dots,N\}\)，對於某個 harness \(h\)，其在任務 \(i\) 上的結果可視為二元成功／失敗變數 \(x_i(h)\in\{0,1\}\)。傳統 **全集合搜尋（full-set search）** 在每次迭代都計算

\[
\bar x(h)=\frac{1}{N}\sum_{i=1}^N x_i(h),
\]

這雖然是無偏估計，但當 \(N\) 很大、單一任務執行成本高昂（例如 **長程終端機任務（long-horizon terminal tasks）** 需在 **沙箱環境（sandbox environment）** 中執行數十分鐘）時，整體 **評估成本（evaluation cost）** 會成為瓶頸。

Task-CoEvolve 改為在每次迭代抽取子集 \(S\subseteq T\)，並根據抽樣機率對結果進行加權，以估計全集合分數。這對應於抽樣調查中的 Horvitz–Thompson 估計思想：若任務 \(i\) 被納入子集的機率為 \(\pi_i\)，則全集合分數的估計量為

\[
\hat{\bar x}(h)=\frac{1}{N}\sum_{i\in S}\frac{x_i(h)}{\pi_i}.
\]

此估計量在期望上是無偏的，前提是 \(\pi_i>0\) 且我們知道每個任務的 **任務納入機率（task inclusion probabilities）**。這正是 Task-CoEvolve 解決「跨迭代可比較性」的關鍵：即使不同迭代使用了不同的子集 \(S\)，只要以納入機率進行逆機率加權，就能將部分評估轉換為對全集合效能的一致估計。

##### 自適應任務選擇：以伯努利變異數衡量資訊量

為了決定每次要評估哪些任務，Task-CoEvolve 使用 **變異數加權取樣（variance-weighted sampling）**。其直覺來自資訊理論與鑑別力：若某個任務對所有候選 harness 而言都是「全對」或「全錯」，則它幾乎無法區分好壞，**資訊量（informativeness）** 很低；反之，若候選 harness 在該任務上結果分歧，則該任務處於當前 harness 的 **能力前沿（capability frontier）**，能提供強烈的 **優化訊號（optimization signal）**。

具體而言，對於任務 \(i\)，Task-CoEvolve 追蹤其在過去迭代中的 **歷史成功率（historical success rate）** \(p_i\)，並計算 **伯努利變異數（Bernoulli variance）**

\[
v_i = p_i(1-p_i).
\]

當 \(p_i\approx 0.5\) 時，\(v_i\) 最大，表示成功與失敗平衡，任務最具鑑別力；當 \(p_i\approx 0\) 或 \(1\) 時，\(v_i\) 接近零，表示任務已經被所有 harness 穩定解決或穩定失敗。抽樣時，任務 \(i\) 的權重與 \(v_i\) 成正比（或經過某種平滑與正規化），從而將有限的 **評估預算（evaluation budget）** 集中在最具鑑別力的任務上。

隨著 harness 持續演化，各任務的歷史成功率會改變，因此 **取樣分佈（sampling distribution）** 也會自動調整：原本太難的任務可能在 harness 改進後逐漸被部分解決，變得具有鑑別力；原本已經被完全掌握的任務則會被降低抽樣機率。這種動態機制避免了傳統 **固定驗證集（fixed validation set）** 方法中「無效任務持續消耗預算」的問題。

##### 結合選擇與估計的完整流程

綜合來看，Task-CoEvolve 的每次迭代可描述為：

1. **根據歷史結果更新每個任務的 Bernoulli variance**，作為其當前鑑別力的代理指標。
2. **依 variance-weighted sampling 抽取子集** \(S\)，並記錄每個任務的納入機率 \(\pi_i\)。
3. **僅在子集上執行候選 harness 評估**，取得部分結果 \(x_i(h)\)。
4. **以逆機率加權估計全集合分數** \(\hat{\bar x}(h)\)，作為跨迭代比較與選擇候選 harness 的共同準則。

這個設計有兩個重要特性。第一，它將「選擇具資訊量的任務」與「估計全集合效能」分開處理但緊密結合：選擇機制決定預算投向何處，估計機制則確保選擇偏差不影響最終比較。第二，由於估計量使用了真實的納入機率，即使高資訊量任務被過度抽樣，也不會系統性地高估或低估全集合效能。

##### 與主動學習及課程學習的區別

雖然 Task-CoEvolve 與 **課程學習（curriculum learning）** 和 **主動測試（active testing）** 都涉及「選擇性使用任務」，但其目標有本質差異。課程學習選擇的是**訓練任務**，目的是改善模型權重；而 Task-CoEvolve 選擇的是**評估任務**，目的是在固定 LLM 權重下比較與篩選 harness。因此，Task-CoEvolve 的取樣標準不是「哪些任務能讓模型學得最好」，而是「哪些任務能最有效區分當前候選 harness」。

#### 實驗數據解讀

論文在兩個差異顯著的領域進行評估：**線上文字分類（online text classification）** 與 **Terminal-Bench 2.1**。前者任務相對輕量、樣本數多；後者屬於 **長程終端機任務（long-horizon terminal tasks）**，單一任務執行時間長、成本高。這樣的設計能檢驗 Task-CoEvolve 在不同成本結構下的適用性。

##### 線上文字分類：極低預算下仍具競爭力

在文字分類實驗中，Task-CoEvolve 在僅使用 **7% 評估預算（evaluation budget）** 時，已能接近 **全集合搜尋（full-set search）** 的效能；當預算提升至 **20%** 時，甚至**超越**全集合搜尋。這個結果有幾層意涵：

- **評估雜訊反而可能帶來正則化效果**：全集合搜尋雖然使用了所有任務，但驗證集中可能包含大量對當前 harness 已無鑑別力的任務。這些任務雖然提供了穩定的分數，卻可能讓優化過程過度擬合到「容易但無區分性」的任務上。Task-CoEvolve 透過聚焦高資訊量任務，反而引導 harness 朝向真正需要突破的能力前沿改進。
- **Variance-weighted sampling 的有效性**：在文字分類這類任務結果相對穩定的場景，歷史成功率能較準確地預測未來鑑別力，因此少量抽樣即可捕捉關鍵差異。
- **成本效益極高**：7% 預算已接近全集合表現，顯示在許多實際應用中，可以大幅縮短優化週期。

##### Terminal-Bench 2.1：高成本任務下的成本削減

在 Terminal-Bench 2.1 上，Task-CoEvolve 使用 **20% 評估預算** 即可達到與全集合搜尋相當的最終效能，同時將整體搜尋成本降低 **67–80%**。這對於長程終端機任務特別重要，因為單一任務可能佔用沙箱環境數十分鐘，評估成本往往主導整個優化迴路。

此處的數據說明：

- **任務選擇的動態適應至關重要**：在 Terminal-Bench 2.1 這類困難基準測試中，不同候選 harness 的能力差異可能集中在少數複雜任務上。固定子集方法若未能涵蓋這些關鍵任務，會嚴重誤判 harness 好壞；Task-CoEvolve 透過持續追蹤 Bernoulli variance，能自動將預算轉移到這些高價值任務。
- **全集合分數估計的穩定性**：即使只評估 20% 任務，逆機率加權估計仍能維持與全集合搜尋相近的最終選擇品質，顯示其估計機制在長程、高變異任務上具有足夠穩健性。
- **成本結構的影響**：67–80% 的成本降低並非單純來自減少 80% 的任務評估，而是因為評估成本在整體搜尋成本中佔比極高，因此減少評估次數對總成本的槓桿效應極大。

##### 與基於子集合的基線方法比較

論文指出 Task-CoEvolve「持續優於 **基於子集合的基線方法（subset-based baselines）**」。這暗示單純隨機抽樣或固定子集並不足以達到相同效果。隨機抽樣雖然也能進行無偏估計，但無法將預算集中在最具資訊量的任務上；固定子集則可能在 harness 演化後變得不具代表性。Task-CoEvolve 的雙重機制——自適應選擇與逆機率加權估計——正是其勝過這些基線的關鍵。

#### 與現有研究的比較

##### 相對於自動 harness 優化

近年來的自動 harness 優化研究，例如 Meta-Harness（Lee et al., 2026），通常採用「**後設層級智慧體（meta-level agent）** 迭代重寫 harness，並在完整 **驗證集（validation set）** 上評估候選版本」的框架。這些方法雖然證明了 harness 設計的重要性，但普遍假設每次評估都必須使用完整驗證集，導致 **評估成本（evaluation cost）** 隨迭代次數線性增長。

Task-CoEvolve 與這些方法正交：它不改變候選 harness 的生成或選擇策略，而是降低「每次評估一個候選 harness」的成本。因此它可以與 Meta-Harness、HarnessCompass（Zhang et al., 2026b）等搜尋端改進方法結合，進一步放大整體效率提升。

##### 相對於搜尋端效率方法

DemoEvolve、ShinkaEvolve、TurboEvolve、HarnessCompass 等方法主要從「減少候選數量」或「改進候選生成與篩選」著手。例如 DemoEvolve 引入人類示範以改善稀疏獎勵環境中的回饋；ShinkaEvolve 與 TurboEvolve 改進 LLM 驅動的演化搜尋效率；HarnessCompass 則透過約束式、回饋導向的模組化優化來改進 harness 演化。

Task-CoEvolve 的差異在於它處理的是「每個候選的評估成本」而非「候選數量」。這兩個方向互補：一個減少需要評估的候選數，一個減少評估每個候選所需的任務數。未來將兩者結合，可能實現數量級的效率提升。

##### 相對於主動測試與樣本高效評估

主動測試（Kossen et al., 2021）、tinyBenchmarks（Maia Polo et al., 2024）、AcTracer（Huang et al., 2026）等研究也探討了如何從部分測試樣本估計模型效能。然而，這些方法主要針對「固定模型」的評估，目標是準確估計某個已訓練完成模型的分數。

Task-CoEvolve 的場景更為動態：候選 harness 在每次迭代都會改變，因此任務的鑑別力也會改變。這要求取樣分佈必須隨 harness 演化而調整，並且估計方法必須能處理不同迭代間的非均勻抽樣。從這個角度看，Task-CoEvolve 將「樣本高效評估」擴展到了「動態候選集合」的設定。

##### 相對於課程學習

課程學習與自適應任務選擇關注的是「學什麼」，而 Task-CoEvolve 關注的是「評什麼」。這個區別在 harness 優化中尤為重要，因為 harness 不改變模型權重，只改變模型運作時的上下文與工具使用方式。因此，選擇訓練任務的標準（例如難度漸進）並不直接適用於選擇評估任務（例如鑑別力最大化）。

##### 限制與潛在弱點

儘管 Task-CoEvolve 在實驗中表現出色，仍有幾點值得注意：

1. **對歷史成功率的依賴**：Bernoulli variance 的有效性仰賴歷史結果能反映未來鑑別力。在任務結果高度隨機、或 harness 改動導致能力分佈劇烈變化的情況下，歷史估計可能滯後。
2. **冷啟動問題**：在優化初期，歷史成功率可能不穩定或樣本不足，此時 variance-weighted sampling 的選擇可能不夠準確。論文未詳細說明如何處理初期的探索與利用權衡。
3. **二元結果假設**：方法以任務成功／失敗作為基本單位，對於具有連續或部分分數的任務，需要額外設計適合的變異數指標。
4. **納入機率的準確性**：逆機率加權估計要求準確知道每個任務的納入機率。在實作中，若抽樣過程涉及複雜條件或近似，估計偏差可能累積。

#### 可重現性評估

##### 程式碼釋出

論文明確表示「Code will be released at https://github.com/Agent4Science-UTokyo/Task-CoEvolve」，這對 **可重現性（reproducibility）** 是正面訊號。然而，截至論文發表時，程式碼是否已完整釋出、是否包含執行腳本與設定檔，仍需實際檢視該儲存庫。

##### 資料集與基準測試

實驗使用的兩個領域分別為：

- **線上文字分類（online text classification）**：引用了 Fei et al. (2024)、Gretel AI (2023)、Schneider et al. (2016) 等資料集。這些多為公開資料集，理論上可取得。
- **Terminal-Bench 2.1**：這是公開的長程終端機任務基準測試，用於評估終端機代理。

由於資料集與基準測試均為公開資源，資料層面的重現門檻相對較低。

##### 模型權重

Task-CoEvolve 的設計前提是「固定 LLM，不更新 **模型權重（model weights）**」。這意味著實驗結果應可在任意固定模型上複現，只要使用相同的底層模型與 harness 初始化。論文未明確說明使用的具體模型版本，但這類資訊通常會在實驗設定中提供。若論文完整版有詳細記載模型名稱、版本與 API 參數，則重現性更高。

##### 重現挑戰

最大的重現障礙可能來自 **長程終端機任務（long-horizon terminal tasks）** 的執行環境。這類任務需要穩定的 **沙箱環境（sandbox environment）**、正確的作業系統狀態、網路與檔案系統設定，任何環境差異都可能導致任務成功與失敗的判定不同。此外，harness 優化本身涉及 LLM 生成程式碼，具有隨機性，因此即使使用相同設定，不同執行也可能得到略有不同的結果。建議未來釋出程式碼時一併提供：

- 固定的隨機種子與 LLM 取樣參數。
- 沙箱環境的 Docker 映像檔或設定腳本。
- 每個實驗的詳細超參數（例如子集大小、variance smoothing 常數、探索比例等）。

---

#### 未來研究方向

##### 1. 結合搜尋端與評估端的雙重效率提升

Task-CoEvolve 專注於降低每次評估的成本，而 DemoEvolve、TurboEvolve、HarnessCompass 等方法則降低候選數量或改進生成品質。未來可將兩者整合，形成「更少候選 × 每候選更少任務」的雙重加速框架，並研究兩種機制之間的交互作用（例如當候選數量減少時，variance-weighted sampling 的歷史估計是否會更不穩定）。

##### 2. 理論保證與最佳取樣策略

目前 Task-CoEvolve 使用 Bernoulli variance 作為資訊量的代理指標，並以逆機率加權進行估計。未來可進一步建立理論框架，分析在給定評估預算下，何種取樣分佈能最小化全集合分數估計的變異數，或最大化正確選出最佳 harness 的機率。這可能涉及貝葉斯最佳實驗設計（Bayesian optimal experimental design）或強盜問題（multi-armed bandit）的視角。

##### 3. 處理連續與結構化回饋

現有方法主要假設任務結果為二元成功／失敗。未來可擴展到連續分數、部分分數、執行軌跡（execution traces）等更豐富的回饋形式。例如，可利用 harness 在任務上的執行時間、API 呼叫次數、中間步驟正確率等資訊，設計更細緻的資訊量指標。

##### 4. 動態預算分配與早期停止

目前每次迭代使用固定比例的評估預算。未來可研究根據當前候選 harness 之間的差異程度，動態調整子集大小：當候選之間差異大時使用較小子集即可區分；當差異小時則增加評估量以降低不確定性。此外，可引入早期停止機制，在評估過程中即時判斷某個候選是否已顯著優於或劣於其他候選。

##### 5. 跨任務遷移與元學習

Task-CoEvolve 在每個優化過程中從頭學習任務的鑑別力。未來可探索「元學習」方法：從多個過往的 harness 優化過程中學習哪些任務特徵（例如任務長度、所需工具類型、難度指標）預示著高鑑別力，從而在新優化任務中更快收斂。

##### 6. 多目標與成本感知優化

在實際部署中，除了任務正確率，harness 的推理成本、延遲、記憶體使用量也是重要考量。未來可將 Task-CoEvolve 擴展為多目標設定，在選擇驗證任務時同時考慮評估成本與資訊量，並在 harness 選擇時權衡效能與開銷。

##### 7. 與人類回饋結合

雖然 Task-CoEvolve 完全自動化，但在某些應用中，人類對於「哪些任務真正重要」具有先驗知識。未來可研究如何將人類偏好或領域知識融入取樣分佈中，例如透過先驗權重調整或互動式任務標註，以進一步提升樣本效率。

##### 8. 應用於其他代理系統

除了文字分類與終端機代理，Task-CoEvolve 的原則可應用於網頁代理、機器人控制、科學實驗規劃等需要昂貴評估的領域。未來可驗證其在不同任務型態與成本結構下的泛化能力，並針對各領域設計專用的資訊量指標。

## 論文問答

**Q1：什麼是 harness 優化，為什麼它在部署 LLM 代理時很重要？**

A：Harness 指的是圍繞大型語言模型、決定「儲存什麼資料、檢索什麼資訊、呈現什麼內容給模型」的控制程式碼框架。研究顯示，僅僅改變 harness 而固定底層模型權重，就能讓同一基準測試的表現相差高達六倍，這說明 harness 的重要性幾乎可與模型本身相比。因此，自動化 harness 優化透過後設層級智慧體反覆重寫 harness 程式碼，成為提升 LLM 代理實際效能的關鍵途徑。

**Q2：現有方法採用「每次迭代都評估完整固定驗證集」的策略，會帶來哪些主要問題？**

A：這種策略的第一個問題是成本高昂，因為每個候選 harness 都必須在整個驗證集上執行推論，尤其當任務是長程終端機任務、需要在沙箱環境中執行數十分鐘時，評估成本會主導整個優化迴圈。第二個問題是它過於靜態，隨著 harness 不斷演化，原本能區分候選版本的任務可能變得人人會解或無人可解，卻仍然持續消耗評估預算。結果是大量資源花在資訊量低的任務上，削弱了優化訊號並拖慢整體搜尋效率。

**Q3：為什麼需要「自適應驗證任務選擇」來解決上述問題？**

A：因為在 harness 優化過程中，真正具有鑑別力的任務會隨著候選 harness 的能力變化而改變，固定子集無法持續對準當前能力前沿。自適應驗證任務選擇能夠把有限的評估預算集中在最能區分候選 harness 的任務上，從而提供更強的優化訊號。這不僅能降低每次迭代的評估成本，也能避免在已經過於簡單或過於困難的任務上浪費資源。

**Q4：Task-CoEvolve 主要面對並解決哪兩個核心挑戰？**

A：第一個挑戰是如何選出最能區分不同候選 harness 的任務，也就是提升評估的資訊豐富度；第二個挑戰是如何在每次迭代使用不同任務子集的情況下，仍然讓評估結果具有跨迭代的可比性。Task-CoEvolve 透過變異數加權取樣來聚焦於高鑑別力任務，同時利用任務納入機率來估計全集合效能，使不同迭代間的分數能夠公平比較。這兩個機制相輔相成，讓方法在減少評估量的同時仍維持優化品質。

**Q5：Task-CoEvolve 如何判斷哪些任務最具資訊量？**

A：它觀察到當不同候選 harness 在某個任務上的結果分歧時，該任務對於排序候選版本最有幫助；反之，總是成功或總是失敗的任務資訊量很低。具體來說，Task-CoEvolve 使用每個任務歷史成功率的伯努利變異數作為指標，當成功與失敗比例接近平衡時，變異數會變大，代表該任務位於能力前沿附近。隨著 harness 演化，這個取樣分佈也會動態調整，持續把評估資源導向當前最具鑑別力的任務。

**Q6：Task-CoEvolve 如何從部分評估中估計完整驗證集的效能？**

A：由於每次迭代評估的任務子集是根據變異數加權取樣得來，直接平均會產生偏差，因此 Task-CoEvolve 在估計全集合分數時會納入每個任務的取樣機率進行加權校正。這種基於納入機率的估計方式能夠從部分評估推論出整體表現，並確保不同迭代間的分數有一致的衡量基準。如此一來，即使每次只評估一小部分任務，也能進行公平的候選比較與最終 harness 選擇。

**Q7：論文在哪些實驗領域與基準測試上驗證 Task-CoEvolve？**

A：實驗涵蓋了線上文字分類任務，以及 Terminal-Bench 2.1 這個針對長程終端機代理設計的基準測試。線上文字分類代表相對低成本的評估情境，而 Terminal-Bench 2.1 的任務通常需要在沙箱環境中執行較長時間，屬於高成本評估情境。這兩個領域的組合能夠檢驗 Task-CoEvolve 在不同評估成本與任務特性下的適用性與效益。

**Q8：Task-CoEvolve 在實驗中取得了哪些關鍵量化結果？**

A：在線上文字分類上，Task-CoEvolve 僅使用 7% 的評估預算就能逼近全集合搜尋的表現，而當預算提高到 20% 時甚至能超越全集合搜尋。在 Terminal-Bench 2.1 上，它只使用 20% 的評估量就能達到與全集合搜尋相當的最終效能，同時將整體搜尋成本降低 67% 到 80%。這些結果顯示 Task-CoEvolve 能在大幅減少評估開銷的前提下，維持甚至提升 harness 優化的最終成效。

**Q9：與基於子集合的基線方法相比，Task-CoEvolve 為何表現更好？**

A：基於子集合的基線方法通常使用固定或隨機選取的任務子集，無法隨著 harness 演化而調整，導致子集中的任務可能很快失去鑑別力。Task-CoEvolve 則是根據歷史結果動態更新取樣分佈，持續把焦點放在當前能力前沿附近的任務。因此，它在相同評估預算下能夠收集到更多有助於區分候選 harness 的訊號，從而穩定優於靜態子集基線。

**Q10：Task-CoEvolve 在哪些實際應用場景中最具價值？**

A：它特別適合評估成本高昂的場景，例如長程終端機任務、複雜工具使用流程，或需要反覆呼叫外部 API 與沙箱環境的代理任務。在這些情境中，每次完整評估都可能耗費大量時間與計算資源，自適應選擇能顯著縮短優化週期。此外，任何採用迭代式 harness 優化的產品或研究流程，都可以透過 Task-CoEvolve 降低實驗成本並加速迭代。

**Q11：在實際產品化部署 Task-CoEvolve 時，需要考慮哪些工程與維運議題？**

A：首先需要穩定地記錄每個任務在每次迭代中的成功與失敗結果，以便計算伯努利變異數與更新取樣分佈。其次，必須精確追蹤每個任務被納入子集的機率，確保全集合效能估計的無偏性與可重現性。最後，產品團隊應根據實際成本與優化進展動態調整評估預算，並將 Task-CoEvolve 與現有的候選生成與選擇流程無縫整合。

**Q12：Task-CoEvolve 對整個自動化 harness 優化領域可能帶來什麼影響？**

A：它將效率提升的焦點從「如何產生更少或更好的候選 harness」轉向「如何用更少任務準確評估每個候選 harness」，與現有搜尋端效率方法形成互補。這種評估端的成本削減能讓更多研究團隊與產品在有限資源下進行大規模 harness 優化。長遠來看，它有助於推動自動化 harness 設計的普及，並降低 LLM 代理開發的整體環境與計算足跡。

**Q13：論文中有哪些可能被視為限制或需要額外假設的地方？**

A：方法假設歷史任務結果能夠反映未來的鑑別力，若 harness 能力發生劇烈跳躍，過去的變異數可能暫時無法準確預測當前資訊量。此外，在優化初期歷史資料較少時，伯努利變異數的估計可能不穩定，需要一定的暖身迭代。最後，部分評估估計本身仍存在抽樣變異，可能在某些迭代中影響候選選擇的穩健性。

**Q14：在什麼樣的失敗案例或極端條件下，Task-CoEvolve 可能表現不佳？**

A：如果驗證集中所有任務都同樣簡單或同樣困難，那麼幾乎沒有任務能提供高鑑別力，變異數加權取樣的優勢將難以發揮。另外，若任務難度在少數迭代內突然改變，例如 harness 學會了一項全新能力，歷史成功率可能來不及更新，導致取樣分佈短暫失準。最後，若任務納入機率估計不準確，全集合效能估計可能產生偏差，進而影響最終 harness 的選擇。

**Q15：未來可以朝哪些方向延伸或改進 Task-CoEvolve？**

A：一個方向是將 Task-CoEvolve 與搜尋端效率方法結合，同時減少候選數量與每候選評估量，以達到更大程度的整體加速。另一個方向是擴展到多目標 harness 優化，例如同時考量效能、延遲與成本，並設計對應的多維度任務資訊量指標。此外，也可以探索更進階的線上學習機制，讓任務選擇能更快適應 harness 能力的突變，並將框架應用到程式生成、多模態代理等其他領域。

## 實務應用指南

### 適用場景

1. **長程終端機智慧體開發**  
   當 LLM agent 需要在沙箱環境中執行數分鐘到數十分鐘的終端機任務（如 Terminal-Bench 2.1）時，每次完整評估所有驗證任務的成本極高。Task-CoEvolve 可將評估預算集中在最具鑑別力的任務上，顯著降低 harness 優化的時間與運算開銷。

2. **線上分類與檢索增強系統**  
   在需要頻繁調整 prompt、檢索策略或資料前處理流程的線上文字分類產品中，可利用 Task-CoEvolve 在僅評估 7%–20% 資料的情況下，快速比較不同 harness 設計，並維持與全集合搜尋相近的最終效能。

3. **多候選 harness 的 A/B 評估平台**  
   當後設層級智慧體每次迭代產生多個候選 harness 時，傳統全集合評估會造成瓶頸。Task-CoEvolve 適合做為持續整合（CI）中的評估引擎，動態挑選能區分候選版本的任務，加速迭代。

4. **資源受限的邊緣或企業內部部署**  
   對於無法負擔完整基準測試反覆推論的場景（如私有模型、API 計費高昂、GPU 時數有限），可透過變異數加權取樣與全集合效能估計，在有限評估預算下完成 harness 優化。

5. **自動化 prompt / 工具鏈調校服務**  
   在 MLOps 或 AgentOps 平台中，Task-CoEvolve 可作為「智慧評估排程器」，根據歷史成功與失敗紀錄，持續將驗證資源導向能力前沿附近的任務，提升自動調校效率。

### 實作前置條件

- **資料準備**
  - 一份固定或可擴充的驗證集，每個任務需能產生明確的成功／失敗結果（伯努利變異數計算所需）。
  - 每個任務的執行成本（時間、金額、GPU 資源）需可量化，以便設定評估預算。
  - 建議保留一小部分「全集合黃金任務」用於最終驗證與校準估計誤差。

- **運算資源**
  - 能並行執行多個 harness 候選版本的推論環境。
  - 沙箱或隔離執行環境（若涉及長程終端機任務）。
  - 用於記錄歷史成功率與動態維護取樣分佈的輕量資料庫或快取層。

- **技術與團隊能力**
  - 熟悉 LLM harness 的程式碼結構（資料儲存、檢索、呈現邏輯）。
  - 具備機率取樣與重要性加權（importance weighting）的基礎知識，以正確估計全集合效能。
  - 能夠設計後設層級智慧體，負責迭代重寫 harness 並根據回饋選擇改進方向。

---

### 實作步驟建議

1. **定義評估目標與成功指標**  
   決定 harness 優化的最終指標（例如準確率、通過率、平均回報），並確認每個驗證任務可輸出對應的二元或連續結果。

2. **建立初始 harness 與候選生成機制**  
   從現有 harness 出發，設計後設層級智慧體，在每次迭代中產生若干候選 harness（可透過 mutation、LLM 改寫或組合現有元件）。

3. **初始化歷史成功率紀錄**  
   對所有驗證任務執行一輪基線 harness，記錄每個任務的成功或失敗，作為後續變異數加權取樣的初始依據。

4. **實作變異數加權取樣**  
   對每個任務計算歷史成功率的伯努利變異數，並依此建構取樣分佈。隨著 harness 演化，持續更新該分佈，使抽樣機率集中在成功與失敗比例接近的能力前沿任務。

5. **執行部分評估並估計全集合效能**  
   每次迭代僅評估被抽中的任務子集，並利用任務納入機率進行重要性加權，估計每個候選 harness 在完整驗證集上的分數，確保跨迭代比較的一致性。

6. **選擇並保留進步的 harness**  
   根據估計的全集合效能挑選最佳候選，更新當前 harness，並將新結果回寫歷史紀錄，供下一次取樣分佈更新使用。

7. **定期全集合校準與最終驗證**  
   雖然日常迭代使用部分評估，但建議每隔數輪或最終收斂時執行一次全集合搜尋，校準估計誤差並確認最終 harness 品質。

---

### 潛在風險與注意事項

- **估計偏差與變異數陷阱**  
  若某些任務長期被所有候選解決或長期失敗，其伯努利變異數會趨近於零，導致這些任務永遠不被抽樣。建議設定最小抽樣機率或定期進行探索性全集合評估，避免遺漏邊緣案例。

- **歷史紀錄的時效性問題**  
  隨著 harness 大幅演進，早期迭代結果可能不再反映當前能力。可引入指數衰減加權，讓近期結果對取樣分佈的影響更大。

- **候選 harness 間差異過小**  
  若候選版本差異不大，變異數加權取樣可能難以找到具鑑別力的任務。此時應檢查後設層級智慧體的生成策略，或適度增加每輪候選數量與多樣性。

- **任務執行成本不均**  
  部分長程終端機任務可能特別昂貴。可在取樣分佈中納入成本權重，或將高成本任務保留給最終驗證，避免能力前沿任務恰好都是高成本任務時造成預算超支。

- **全集合效能估計的實作細節**  
  重要性加權需要精確記錄每個任務在每次迭代的納入機率。若取樣機率計算有誤，會導致跨迭代分數不可比，進而選錯 harness。

---

### 與其他技術的整合建議

- **與現有 harness 優化框架搭配**  
  Task-CoEvolve 可與 Meta-Harness、ShinkaEvolve、TurboEvolve 等搜尋端優化方法互補：這些方法負責產生更好的候選 harness，Task-CoEvolve 則負責降低每個候選的評估成本。

- **整合至 MLOps / AgentOps 管線**  
  將 Task-CoEvolve 封裝為評估排程服務，與模型版本控制、實驗追蹤（如 MLflow、Weights & Biases）及 CI/CD 系統串接，自動觸發 harness 優化與效能回報。

- **結合主動測試與 tinyBenchmarks**  
  若驗證集極大，可先以 tinyBenchmarks 建立精簡核心子集，再於其上套用 Task-CoEvolve 的動態取樣，形成兩階段的評估加速策略。

- **與人類回饋機制協作**  
  對於難以自動判斷成功與失敗的開放式任務，可將 Task-CoEvolve 抽樣出的任務優先送交人工標註或 DemoEvolve 式示範回饋，提升標註資源使用效率。

- **作為 API 計費控管元件**  
  在呼叫外部 LLM API 的產品中，可將 Task-CoEvolve 的評估預算與成本上限綁定，動態決定每輪應評估哪些任務，避免非預期的高額帳單。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先理解「harness 是圍繞 LLM 的程式碼框架」這個核心概念，再聚焦本文的兩個直覺：「會讓不同候選 harness 有不同意見的任務最有價值」，以及「用抽樣機率加權可以從部分評估推回完整表現」。實作時可從小型文字分類任務開始，觀察變異數加權取樣如何隨迭代改變。

- **AI 工程師**  
  請重點檢視第 3 節的方法與實作細節，特別是伯努利變異數的更新邏輯、重要性加權的全集合估計公式，以及與現有 harness 優化迴圈的整合方式。建議直接參考作者釋出的程式碼，將 Task-CoEvolve 封裝成可替換的評估模組。

- **研究人員**  
  本文的貢獻在於將「驗證任務選擇」視為與 harness 協同演化的問題，而非靜態子集選擇。可進一步探討取樣分佈的收斂性、與主動學習理論的連結，或將此方法延伸至非二元結果、多目標優化與線上學習設定。

- **產品經理**  
  本技術的商業價值在於「用更少的評估成本達到與全集合搜尋相同的效能」。評估時請關注實驗中的成本降低數字（80% 評估次數、67–80% 整體搜尋成本），並思考如何將其包裝為產品中的「智慧評估預算」功能，以縮短上線前的 harness 調校週期並降低基礎設施支出。
