#### 與現有研究的比較

**相對於影片世界模型**

影片世界模型（如 Infinite-World、Yume-1.5、Matrix-Game 系列、LingBot-World）將世界狀態隱含於生成器上下文，**串流變體（streaming variant）**雖延伸至長序列互動推演，但每次回訪皆需重新合成，無法保證**回訪一致性（return）**。WM^MLLM 透過狀態外存與修訂歷史查找，從根本上解決此問題。

**相對於三維世界模型**

三維世界模型（如以**網格（mesh）**或**高斯面片（Gaussian surfel）**建構的系統）具備顯式場景表示，支援區域編輯與新視角渲染。然而如表 1 所示，現有系統中無一同時具備四項特性：MLLM 規劃器、物件編輯、精確回訪、編輯前檢查。WM^MLLM 是首個整合全部四者的系統。

**相對於控制型世界模型**

視覺-語言-動作模型（VLA models）與聯合嵌入預測架構（JEPAs）輸出動作或嵌入向量，不產生可編輯影像，因此不適用於本文的可編輯世界生成任務。

- 仰賴 GPT-6.1-sol 與 GPT-Image 等閉源模型，可重現性受限
- 全景圖表示在處理極大場景或動態拓撲變化時可能面臨擴展性挑戰

#### 未來研究方向

**1. 開源化與可重現性提升**

將 MLLM 規劃器與影像生成器替換為開源替代品，並釋出訓練流程與評測基準，將大幅提升研究的可累積性。具體方向包括：以開源 MLLM（如 LLaVA 變體）取代 GPT-6.1-sol，以 Stable Diffusion 變體取代 GPT-Image。

**2. 動態場景與時間持續性**

當前架構主要處理靜態場景的空間編輯。延伸至動態物件（行人、車輛、動物）與時間維度的持續性，將是重要的下一步。這需要擴展狀態表示以納入時間軸與動態物件追蹤。

**3. 物理一致性整合**

結合物理模擬引擎（如基於**網格（mesh）**的物理模擬）與 WM^MLLM 的狀態管理，可在保持可編輯性的同時引入物理合理性，適用於機器人模擬與遊戲開發。

**4. 多使用者協作編輯**

將狀態的修訂歷史擴展為支援多使用者並行編輯的版本控制系統，類似 Git 的分支與合併機制，將開啟協作世界建構的可能性。

**5. 高效全景圖表示**

當前以原生解析度全景圖儲存狀態，對於大場景可能造成記憶體壓力。研究壓縮表示（如神經輻射場隱式表示）與稀疏更新策略，將提升可擴展性。

**6. 自動化評測與基準擴充**

現有評測仰賴人工盲測（258 項 WBench/MBench-A 項目）。發展自動化評測指標（如基於 CLIP 的語意一致性、基於深度估計的幾何一致性）將加速大規模實驗。

**7. 跨模態狀態擴展**

將狀態從視覺擴展至音訊、觸覺、嗅覺等多模態，將使世界模型更接近人類感知體驗，適用於虛擬實境與沉浸式敘事應用。

**8. 安全性與偏誤檢查**

MLLM 規劃器可能引入偏誤或不安全的編輯決策。研究如何在狀態寫入前進行更嚴格的安全性檢查，將是負責任部署的關鍵。

### 實作步驟建議

1. **定義狀態結構**：先固定世界狀態的最小欄位——基礎全景圖、本回合的合成全景、補丁（patch）、場景關係圖、修訂歷史。論文中每個回合都會把候選結果 commit 進狀態，因此狀態層的不可變性與可追溯性是後續所有保證的基礎。

2. **建立 MLLM 規劃器介面**：將使用者請求（文字 + 可選邊界框）映射到五種操作——rotate（純渲染，不呼叫生成器）、revisit（從修訂歷史取回舊視角）、local（局部編輯）、global（全域改變，如光照）、walk（走到新地點）。建議先用規則式路由器分流，再逐步換成 MLLM 決策。

3. **串接影像生成器作為候選提案者**：影像生成器只負責「提議」下一個視角，不直接寫入狀態。對於 local 編輯，要求生成器同時輸出原始主體與新主體的 footprint（輪廓遮罩），這是後續選擇「寫入區域」的依據。

4. **實作寫入區域選擇**：MLLM 比對來源影像與候選影像，選出舊 footprint 與新 footprint 的聯集，並納入必要的光影／反射等連帶影響區域，作為本回合的 support 區域 $A_t$。論文的關鍵發現是「先生成、後選區域」可將局部編輯完成率從 34.8% 提升到 83.0%。

6. **整合影片生成器作為轉場呈現層**：影片生成器只負責播放兩個狀態之間的轉場，不寫入狀態。這樣可以把「世界的一致性」與「畫面的流暢度」兩個責任清楚分離。

### 潛在風險與注意事項

- **MLLM 規劃錯誤的成本**：若 MLLM 將「走到陽台」誤判為「全域改變」，可能會觸發不必要的影像生成並破壞狀態。緩解方式：所有操作在 commit 前都必須通過檢查關卡；規劃器輸出應附帶理由與信心分數，低信心時退回人工確認。

- **影像生成器的偽影與主體漂移**：生成器可能在 support 區域外產生細微變化（例如背景紋理被改寫），導致 locality 檢查失敗。緩解方式：將 support 外的像素以原始狀態強制覆蓋（論文的 blending 步驟），並對生成器加上「只在指定區域內改動」的 prompt 約束。

- **全景圖累積誤差**：每次 walk 與 rotate 都會把新視角拼回全景，長期下來可能產生接縫或幾何不一致。緩解方式：定期以原始輸入影像重新校正全景基準；為每個地點儲存多張重疊影像以利後續最佳化。

- **狀態儲存膨脹**：每次 commit 都會留下修訂歷史與補丁，長期使用後儲存成本快速上升。緩解方式：對不再被引用的舊修訂做垃圾回收；對補丁做去重與壓縮。

- **延遲與成本**：每個回合都會呼叫 MLLM 與影像生成器，單次成本與延遲明顯高於純影片世界模型。緩解方式：rotate 與 revisit 不呼叫生成器（這也是論文的設計重點）；對可預測的操作（如固定角度的 rotate）快取結果。

- **評測基準的侷限**：論文的強結果集中在 MBench-A、CompBench、WBench，這些基準偏向室內與有限規模的場景。部署到戶外、大尺度或高度動態的場景前，應自行擴充評測集。

### 與其他技術的整合建議

- **與 NeRF / Gaussian Splatting 等 3D 表示互補**：可將 WM^MLLM 的全景狀態作為 3D 重建的初始化或校正來源；反之，3D 表示可提供更精準的幾何資訊，協助 MLLM 規劃器判斷「走到下一個地點」時的相機軌跡。

- **與 VLA（Vision-Language-Action）模型整合**：在機器人或 embodied AI 場景中，WM^MLLM 可作為「世界預測器」，讓代理人在執行動作前先在世界模型中試跑並驗證結果，再將通過檢查的動作送到真實環境。

- **與 RAG 與知識庫整合**：場景關係圖與修訂歷史可被檢索，讓使用者用自然語言查詢「這個房間經歷過哪些變更」「上次的光線設定是什麼」，適合用於設計審查與版本管理。
