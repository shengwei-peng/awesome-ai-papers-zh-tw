# 模型適應性工具必要性揭示 LLM 工具使用中的知行落差

**原文標題：** Model-Adaptive Tool Necessity Reveals the Knowing-Doing Gap in LLM Tool Use

## ⚡ TL;DR

現行工具必要性評估忽略模型能力差異，且存在認知與行為脫節的問題。
本研究提出基於實證表現的模型適應性必要性定義，並以探針解構認知與執行階段。
實驗顯示工具呼叫存在顯著知行落差，多數失誤源於認知未能有效轉化為行動。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）日益扮演自主智能體（autonomous agents）的角色，必須決定何時直接回答、何時呼叫外部工具（external tools）。過去研究在探討適應性工具使用（adaptive tool use）時，大多將工具必要性（tool necessity）視為模型無關（model-agnostic）的屬性，由人工標註者（human annotator）或 LLM 評判模型（LLM judge）標註，且多半涵蓋答案顯而易見的案例（例如取得即時天氣資料（real-time weather data）相較於改寫（paraphrasing）文字）。然而，實際情境中的工具必要性（tool necessity）更為細緻，因為不同模型的能力邊界（capability boundaries）存在差異：對於強模型可自行解決的問題，弱模型可能仍須借助工具（tools）。在本研究中，我們提出模型適應性（model-adaptive）的工具必要性（tool necessity）定義，以各模型的實證表現（empirical performance）為基礎。依據此定義，我們針對算術（arithmetic）與事實問答（factual QA）資料集，在四個模型上比較工具必要性（tool necessity）與觀察到的工具呼叫行為（tool-call behavior），分別發現 26.5–54.0% 與 30.8–41.8% 的大幅不匹配（mismatch）。為診斷此失效情形，我們將工具使用（tool use）拆解為兩個階段：反映模型是否認為工具為必要的內部認知（internal cognition）階段，以及決定模型是否實際做出工具呼叫動作（tool-call action）的執行階段（execution stage）。透過探測 LLM 的隱藏狀態（hidden states），我們發現兩種訊號通常均為線性可解碼（linearly decodable），但其探測方向（probe directions）在驅動下一詞元動作（next-token action）的深層網路層（late-layer）與最末詞元情境（last-token regime）中幾乎變為正交（orthogonal）。透過追蹤樣本在兩階段流程中的軌跡（trajectory），我們進一步發現，大多數不匹配情形（mismatch）集中於認知到行動的轉換（cognition-to-action transition），而非認知（cognition）本身。這些結果揭示了 LLM 工具使用中的知行落差（knowing-doing gap）：提升工具使用的可靠性，不僅需要更準確地辨識何時需要工具，還需要將此辨識更好地轉化為行動。

### 核心貢獻（3～5點）
- 提出以各模型實證表現（empirical performance）為基礎的模型適應性（model-adaptive）工具必要性（tool necessity）定義，突破過去模型無關（model-agnostic）的標註框架。
- 在算術（arithmetic）與事實問答（factual QA）資料集上量化四個模型的工具必要性（tool necessity）與實際工具呼叫行為（tool-call behavior）間的大幅不匹配（mismatch），比例分別高達 26.5–54.0% 與 30.8–41.8%。
- 將工具使用（tool use）拆解為內部認知（internal cognition）與執行（execution）兩階段，並發現兩階段訊號雖皆可從隱藏狀態（hidden states）線性解碼（linearly decodable），但其探測方向（probe directions）在深層網路層（late-layer）與最末詞元情境（last-token regime）幾乎正交（orthogonal）。
- 追蹤樣本軌跡（trajectory）後發現，大多數不匹配集中於認知到行動的轉換（cognition-to-action transition），揭示 LLM 工具使用中存在「知行落差」（knowing-doing gap）。

### 適合對象
從事大型語言模型（LLMs）工具使用、自主智能體（autonomous agents）設計、可解釋性（interpretability）與模型對齊（alignment）研究的學者與工程師；特別適合關注模型適應性評估、工具呼叫失敗診斷，以及希望透過隱藏狀態探測（hidden state probing）理解模型內部決策機制的讀者。

## 深度分析

#### 方法論解析

本研究的核心方法論創新在於提出 model-adaptive (模型適應性) 的 tool necessity (工具必要性) 定義，並建立一套從 internal cognition (內部認知) 到 execution stage (執行階段) 的兩階段分析框架。

首先，在必要性定義上，作者群挑戰傳統 model-agnostic (模型無關) 的 static annotation (靜態標註) 範式。過往研究通常仰賴 human annotator (人工標註者) 或 LLM judge (LLM 評判模型) 來判定 query (查詢) 是否需要工具，這實際上反映的是評判者的 capability boundary (能力邊界)，而非受測模型的 intrinsic capability (內在能力)。本文提出的實證性定義則是：針對特定模型，在 temperature (溫度) T 下進行 N 次獨立 inference (推論)，若該模型能全部正確回答，則將該查詢標記為 unnecessary (不必要)；反之則為 necessary (必要)。這種以 empirical performance (實證表現) 為基礎的定義，使得工具必要性成為相對於特定模型內部權重與架構的動態屬性，能夠精確捕捉不同模型間 capability boundary (能力邊界) 的自然發散。

其次，為了診斷 necessity-action mismatch (必要性與行為不匹配)，作者將工具使用解構為兩個階段：
1. cognition stage (認知階段)：對應模型的 metacognition (後設認知)，即模型是否在其內部表徵中「相信」工具是必要的。研究透過 probe (探針) 從 hidden state (隱藏狀態) h 中訓練出一個 cognition direction (認知方向) wc，用以區分 necessary (必要) 與 unnecessary (不必要) 的查詢。
2. execution stage (執行階段)：對應實際的 next-token action (下一詞元動作)，即模型是否產生工具觸發詞元。研究同樣訓練探針 wa 來預測實際的 tool-call behavior (工具呼叫行為)。

關鍵的技術細節在於 probe direction (探測方向) 的幾何分析。作者發現，雖然必要性與執行意圖在多數層級皆為 linearly decodable (線性可解碼)，但在 late-layer (深層) 的 last-token regime (最末詞元情境) 中，wc 與 wa 的 probe direction (探測方向) 幾乎呈現 orthogonal (正交)。這意味著驅動實際動作產生的表徵空間，與編碼內部認知的表徵空間發生了幾何上的分離。最後，透過 trajectory (軌跡) 追蹤樣本在兩階段間的轉換，研究進一步將失誤定位於 cognition-to-action transition (認知到行動的轉換)，而非認知本身。

#### 實驗數據解讀

實驗橫跨四個不同模型，於 arithmetic (算術) 與 factual QA (事實問答) 資料集上進行評估。數據揭示的現象極為顯著：在算術任務中，necessity-action mismatch (必要性與行為不匹配) 比例高達 26.5%–54.0%；在事實問答中則為 30.8%–41.8%。這表示模型並非偶發性地誤判，而是系統性地出現兩類錯誤：一是在具備充足內部知識（以參數化知識解題全對為判準）時仍 redundant (冗餘的) 呼叫 external tool (外部工具)；二是在缺乏內部能力時卻嘗試直接回答，導致錯誤。

probe (探針) 實驗的結果提供了更深層的洞察。首先，必要性與執行意圖均能從 hidden state (隱藏狀態) 中以線性方式解碼，這說明 Large Language Model (LLM, 大型語言模型) 的內部確實編碼了關於自身 capability boundary (能力邊界) 的 metacognition (後設認知) 訊號。然而，這些訊號並未有效轉化為行動。在 late-layer (深層) 的 last-token regime (最末詞元情境) 中，cognition direction (認知方向) wc 與執行方向 wa 幾近 orthogonal (正交)，暗示模型在生成最終決策的表徵空間中，「知道」與「做到」的神經基礎發生了解離。

trajectory (軌跡) 追蹤進一步指出，大多數不匹配並非源於 cognition stage (認知階段) 的失敗——模型內部往往已經「知道」自己需要工具——而是集中在 cognition-to-action transition (認知到行動的轉換) 過程。這正是作者所稱的 knowing-doing gap (知行落差)。換言之，LLM 作為 autonomous agent (自主智能體)，其失敗模式並非單純的「無知」（缺乏自我評估），而是「行動障礙」：即使內部表徵正確識別了 tool necessity (工具必要性)，最終的 next-token action (下一詞元動作) 卻未能忠實反映此認知。

#### 與現有研究的比較

相較於既有文獻，本研究在概念框架與方法學上均有明確推進。

在 tool necessity (工具必要性) 的定義上，過往研究如 [8, 22, 13] 普遍將其視為查詢本身的靜態屬性，透過人工或強大 LLM 進行二元標註，聚焦於 polarized case (極端案例)（例如擷取 real-time weather data (即時天氣資料) 相對於 paraphrasing (改寫) static paragraph (靜態段落)）。這種 model-agnostic (模型無關) 的視角忽略了不同模型間 capability boundary (能力邊界) 的自然發散。雖然 Wang et al. [27] 已倡議模型依賴的必要性，但本文首次建立完整管線，將必要性奠基於受測模型自身的 empirical performance (實證表現)，而非外部評判者的主觀標準。

在 metacognition (後設認知) 的研究脈絡中，早期工作多聚焦於顯性自我評估，例如教導模型表達知識邊界 [2, 31] 或口語化信心程度 [15]。然而，近期研究指出模型將內部活化 verbalize 的能力有限 [17, 9]，且顯式自我評估與實際解題屬於不同任務，類似 System I and System II thinking [14] 的區別。本文接續 [13, 28] 使用內部狀態探測的路線，但進一步將其置於「認知—執行」的兩階段框架中，並與其他領域的 knowing-doing gap (知行落差) 研究（如 Zhao et al. [34] 對有害查詢的拒絕失敗、Zhang et al. [32] 對數學問題的無效推理）建立連結，證明此現象在 adaptive tool use (適應性工具使用) 中同樣存在，甚至可能更為嚴重。

此外，現有工具使用研究多聚焦於功能呼叫協定（如 MCP [1] 與 A2A [6]）、工具使用準確度 [12, 21]、hallucinated calls (幻覺呼叫) [33, 23] 或工具描述穩健性 [25, 5]，這些均屬於「如何使用工具」的範疇。本文則填補了「何時使用工具」這一相對欠缺的診斷視角。

#### 可重現性評估

從方法論描述來看，本研究的實驗設計具備原則上的可重現性。model-adaptive (模型適應性) 必要性的判定流程（N 次採樣、temperature (溫度) T、全對準則）以及線性探針的訓練目標（以邏輯迴歸區分必要性與執行行為）均有明確的演算法定義。然而，根據目前提供的 preprint (預印本) 內容，仍存在若干限制重現的資訊缺口：

首先，四個受測模型的具體名稱、版本、參數規模與 model weights (權重) 取得方式並未在摘要與引言中詳列；arithmetic (算術) 與 factual QA (事實問答) 資料集的確切來源、前處理方式與樣本數亦未揭露。其次，probe (探針) 訓練的細節——例如正則化強度、訓練/驗證集劃分、層級選擇的具體範圍，以及用於判定「近乎 orthogonal (正交)」的量化閾值（如餘弦相似度或角度值）——仍有待補充。最後，作者提及附錄 B 中有關顯式提示自我評估的對照實驗，但完整 open-source code (開源程式碼) 與資料釋出狀態在現有片段中並未說明。

綜合而言，雖然核心概念與高階流程清晰，足以讓其他研究者復現概念驗證，但要達到嚴格的數值重現 (numerical reproduction)，仍需等待作者群釋出完整的實作細節、超參數設定與原始資料。

#### 未來研究方向

本研究揭示的 knowing-doing gap (知行落差) 與 probe direction (探測方向) 正交性，為後續研究開啟了多條具體路徑：

第一，representation engineering (表徵工程) 的介入。既然 cognition direction (認知方向) wc 與執行方向 wa 在 late-layer (深層) last-token regime (最末詞元情境) 中趨於 orthogonal (正交)，未來可探索如何透過 supervised fine-tuning (監督式微調) 或 RLHF (強化學習人類回饋) 來校準這兩個方向，使內部 metacognition (後設認知) 能更直接地影響 next-token action (下一詞元動作)。具體而言，可在訓練目標中引入正交性懲罰項，或設計以探針分數為獎勵的強化學習訓練。

第二，model-adaptive (模型適應性) benchmark (基準) 的建立。本文的必要性定義可依據模型的 empirical performance (實證表現) 動態調整，未來可將此框架擴展至多樣化的工具生態系（如 search engine (搜尋引擎)、calculator (計算機)、API (應用程式介面)），並探討不同 temperature (溫度) T 與採樣次數 N 對必要性邊界判定的影響，從而建立標準化的模型適應性評估協定。

第三，解碼階段的即時干預。若 probe (探針) 能可靠地從中間層讀取必要性訊號，未來可發展 classifier-guided decoding (分類器引導解碼) 或 early-stopping (早期停止) 機制，在生成過程中強制或抑制工具觸發詞元，直接彌補 cognition-to-action transition (認知到行動) 的轉換斷層。

第四，跨領域與跨語言的知行落差檢驗。目前實驗集中於 arithmetic (算術) 與 factual QA (事實問答)，未來可檢視在多步驟推理、程式碼生成或跨語言查詢中，模型的 capability boundary (能力邊界) 與 tool necessity (工具必要性) 判定是否呈現同樣的幾何分離現象。此外，探討此 orthogonal (正交) 性是模型架構的固有屬性，抑或來自現有預訓練與對齊過程的產物，亦具有重要的理論價值。

最後，從認知科學角度，可將此框架類比至人類的「意圖—行動」缺口，進一步研究 LLM 作為 autonomous agent (自主智能體) 的決策機制，並發展結合顯式與隱式 metacognition (後設認知) 的混合架構，以提升 external tool (外部工具) 使用的可靠性與安全性。

## 論文問答

**Q1：這篇論文指出大型語言模型在適應性工具使用上面臨什麼核心挑戰？**
A：這篇論文指出，大型語言模型作為自主智能體時，核心挑戰在於如何準確判斷「何時應該直接回答」與「何時需要呼叫外部工具」。過往研究通常將工具必要性視為靜態、模型無關的屬性，僅依賴人工標註或強大的評判模型來標記查詢是否需要工具，忽略了不同模型間能力邊界的自然差異。這種傳統做法導致我們無法精確捕捉特定模型在面對不同查詢時的真實需求，因為對先進模型而言簡單的問題，對較弱模型可能必須仰賴工具才能解決。

**Q2：為什麼傳統「模型無關」的工具必要性定義在實際應用中會失效？**
A：傳統模型無關的定義將工具必要性視為查詢本身的固定屬性，認為無論由哪個模型處理，特定查詢都同樣需要或不需要工具。然而，這種定義忽略了不同模型的內在能力與參數知識存在顯著差異：一個最先進模型能僅憑內部權重正確解答的問題，對於較小或能力較弱的模型而言可能完全超出其能力範圍。因此，靜態標註無法反映真實世界中模型能力邊界的分歧，導致對特定模型而言工具必要性被錯誤地歸類，進而產生冗餘呼叫或應叫未叫的情況。

**Q3：建立「模型適應性」的工具必要性定義為何對自主智能體的可靠性至關重要？**
A：建立模型適應性的定義能將工具必要性與特定模型的實證表現緊密連結，從而準確判斷該模型在何時真正需要尋求外部協助。這種以模型內在能力為基礎的定義，避免了用評判者的能力取代被測模型能力的問題，使得工具使用的決策更符合該模型的實際限制。唯有如此，自主智能體才能在減少不必要工具呼叫以降低延遲與成本的同時，確保在能力不足時正確求助，全面提升系統的可靠性與效率。

**Q4：這篇論文提出的「模型適應性工具必要性」是如何具體定義與量測的？**
A：論文將模型適應性的工具必要性定義為：針對特定查詢，在給定溫度參數下進行多次獨立推論，若該模型無法每次都正確回答，則視該查詢對此模型為「必要使用工具」；反之，若所有推論皆正確，則視為「不必要」。這種定義完全奠基於模型自身的實證表現，而非外部評判者的主觀標註，因此能精確反映該模型在特定任務上的能力邊界。透過這種可重複的實驗流程，研究者得以為每個模型建立專屬的必要性標籤，作為後續與實際工具呼叫行為比較的黃金標準。

**Q5：論文提出的「認知—執行」兩階段分解框架有何創新之處？**
A：該框架創新地將工具使用過程拆解為「內部認知階段」與「執行階段」，前者探測模型隱藏狀態中是否編碼了「需要工具」的信念，後者則觀察模型是否實際輸出觸發工具呼叫的詞元。這種分解超越了過往僅從輸入行為評估工具使用的表層分析，深入模型內部表徵來診斷失敗根源。透過分別訓練探針來解碼這兩個階段的訊號，研究者得以區分模型是「不知道需要工具」還是「知道但做不到」，為理解 LLM 的後設認知與行動落差提供了全新的機制性視角。

**Q6：為什麼研究者選擇使用線性探針在隱藏狀態上進行分析，而非僅依賴模型的顯式自我評估？**
A：研究者選擇線性探針是因為近期研究顯示，模型顯式口語化其內部啟動的能力有限，且直接詢問模型進行自我評估會改變其注意力焦點，使其從任務導向轉為評估導向，無法反映真實問題解決時的隱性後設認知。相較之下，探測隱藏狀態能直接擷取模型在處理查詢時的內部表徵，這些表徵在模型進行下一詞元預測的最末詞元情境與深層網路中，蘊含了與工具必要性相關的潛在訊號。這種方法更貼近模型實際運作時的潛意識處理過程，從而提供更忠實於內部認知的測量方式。

**Q7：實驗選用了哪些任務與模型來驗證框架？**
A：實驗選用了算術與事實問答這兩類資料集，並在四個不同的模型上進行評估，涵蓋了需要精確計算與需要外部知識檢索的場景。算術任務考驗模型在數學運算上的內在能力邊界，而事實問答則檢驗模型對參數化知識的掌握程度與對外部搜尋引擎的需求。透過跨模型與跨任務的比較，研究得以系統性地觀察工具必要性與實際行為之間的匹配程度，並驗證模型適應性定義在不同能力層級模型上的適用性。

**Q8：實驗發現工具必要性與實際工具呼叫行為之間存在多大的不匹配？**
A：實驗結果顯示，模型在算術任務上呈現出 26.5% 至 54.0% 的必要性與行為不匹配，而在事實問答任務上則有 30.8% 至 41.8% 的落差。這些數據顯示，無論是在需要精確計算還是知識檢索的情境中，模型都頻繁地在有能力直接回答時仍呼叫工具，或在缺乏內部知識時卻嘗試直接作答。如此顯著的不匹配率凸顯了當前 LLM 在適應性工具使用上的可靠性危機，也證明了僅依賴模型自行決策並無法有效對齊其真實能力邊界。

**Q9：探針分析揭示了認知階段與執行階段的表徵有何關鍵差異？**
A：探針分析發現，雖然工具必要性的認知訊號與工具呼叫的執行意圖在模型隱藏狀態中通常都具有線性可解碼性，但在深層網路的最末詞元情境下，兩者的探測方向幾乎呈現正交。這意味著模型內部「知道需要工具」的表徵方向，與「實際執行呼叫動作」的表徵方向在關鍵決策點上發生了幾何分離。這項發現是解釋知行落差的關鍵機制證據，說明即使模型的內部認知正確，其表徵在轉化為下一詞元動作時仍可能走向截然不同的方向。

**Q10：這項研究對開發實際的 LLM 自主智能體與工具生態系統有何具體啟示？**
A：這項研究提醒開發者，在設計如 MCP 或 A2A 等標準化工具生態系統時，不能假設所有模型對同一查詢都有相同的工具需求，而應根據部署模型的實證能力動態調整必要性閾值。產品團隊需要建立模型專屬的評估管線，以判斷特定模型在何時真正需要呼叫搜尋引擎、計算機或 API，從而避免不必要的延遲與成本。此外，框架揭示的知行落差意味著智能體設計不應僅強化模型的後設認知，還必須透過架構或訓練手段確保內部認知能可靠地轉化為正確的工具呼叫語法。

**Q11：論文發現的「知行落差」對 LLM 產品的工具呼叫可靠性改進有何指導意義？**
A：「知行落差」指出，改進工具使用可靠性的關鍵不僅在於提升模型識別自身限制的能力，更在於強化將這種識別轉譯為實際行動的機制。對產品而言，這意味著即使模型在內部表徵上「知道」自己需要查詢天氣或進行複雜計算，系統仍可能在最後一刻輸出錯誤的動作。因此，開發者應考慮在模型架構或推論流程中引入額外的對齊機制，例如在深層網路中增強認知與執行表徵的耦合，或設計後處理驗證步驟來檢查模型的內部狀態與輸出動作是否一致。

**Q12：這項研究如何挑戰了工具使用領域中依賴靜態標註的傳統範式？**
A：這項研究直接挑戰了將工具必要性視為查詢固有屬性的傳統範式，證明靜態標註無論是由人工標註者還是強大的評判模型產生，都無法反映被測模型的真實能力邊界。研究顯示，傳統範式不僅在理論上忽略了模型間的能力分歧，更在實證上導致了高達五成以上的行為不匹配。這促使領域重新思考評估基準的設計邏輯，推動未來研究從「一刀切」的靜態分類轉向以模型為中心、動態且實證導向的必要性定義，從而建立更公平的跨模型比較基礎。

**Q13：這項研究在方法論或實驗範圍上有哪些已知的限制？**
A：研究目前主要聚焦於算術與事實問答這兩類相對明確的任務，尚未涵蓋需要多步推理、創意生成或複雜工具鏈組合的開放式場景，因此其結論在更複雜的應用中的普遍適用性仍需進一步驗證。此外，模型適應性的必要性定義需要對每個模型進行多次獨立推論來建立標籤，這在計算資源與時間成本上較為昂貴，可能限制其在快速迭代或模型數量龐大的情境下的實用性。同時，研究主要透過線性探針分析靜態表徵，對於動態推論過程中表徵如何隨時間演變的細緻機制，仍有深入挖掘的空間。

**Q14：根據軌跡追蹤分析，工具使用失敗的主要模式為何？這反映了什麼樣的內在機制缺陷？**
A：根據軌跡追蹤分析，絕大多數的必要性與行為不匹配並非來自模型內部認知的錯誤，而是集中在「認知到行動的轉換」階段，即模型內部已生成需要工具的表徵，卻未能輸出對應的工具呼叫動作。這種失敗模式反映了模型雖具備某種程度的後設認知，但其內部信念與最終的詞元生成機制之間存在結構性的斷裂。這項發現暗示，LLM 的下一詞元預測目標可能並未充分優化以將自我認知的限制轉化為適當的外部求助行為，導致內部知識與外部行動之間的協調失靈。

**Q15：基於這些發現，未來研究可以從哪些方向著手來縮小 LLM 工具使用中的知行落差？**
A：未來研究可以探索表徵工程或微調方法，以增強深層網路中認知方向與執行方向的對齊程度，減少兩者在最末詞元情境下的正交分離。另一個方向是開發能夠即時監測模型內部隱藏狀態的推論時介入機制，當探針偵測到需要工具的認知訊號時，主動引導或強制模型輸出工具呼叫詞元。此外，將研究擴展到更廣泛的任務類型與多模態工具使用情境，並結合顯式與隱式的後設認知訓練，將有助於建立更全面且可靠的適應性工具使用框架。

## 實務應用指南

### 適用場景

1. **企業級智慧客服與知識路由**：當組織內部同時部署多種規模的大型語言模型處理客戶查詢時，依據各模型在特定領域的實證表現，動態決定是否呼叫外部知識庫或搜尋引擎，避免最先進模型進行冗餘檢索，同時確保較小模型不會因過度自信而遺漏必要查詢。

2. **財務稽核與精算代理**：在算術密集型工作流程（如稅務計算、風險模型驗證）中，判斷當前模型能否僅靠內部權重正確完成運算，抑或必須呼叫計算機或試算表應用程式介面，以降低數值錯誤率。

3. **醫療與法律專業問答系統**：針對事實問答情境，區分模型已內化的靜態知識與需要即時外部驗證的資訊（如最新法規、藥品交互作用），建立模型適應性的工具觸發閘道。

4. **邊緣裝置與雲端混合智能體**：於資源受限的邊緣設備上運行較小模型時，透過內部認知探針偵測查詢是否超出能力邊界，自動決定是否將任務上送至雲端大型模型或外部資料庫。

5. **程式碼生成與自動除錯工具**：判斷模型應直接生成程式碼，或需呼叫直譯器、編譯器與靜態分析工具來驗證語法正確性與執行結果，特別針對複雜邏輯或陌生程式語言。

### 實作前置條件

- **資料**：目標領域的查詢資料集（需涵蓋極端案例與模糊案例）、模型獨立回答的正確性標註、各層各詞元的隱藏狀態抽取紀錄。
- **運算**：可支援目標模型進行多次採樣（溫度 T × N 次）的 GPU 叢集、訓練線性探針的額外運算資源。
- **技術**：熟悉 Transformer 隱藏狀態分析、線性探針方法、工具呼叫應用程式介面整合、統計評估指標設計。

### 實作步驟建議

1. **建立模型適應性基準**：針對目標模型，在不使用外部工具的情況下重複推論 N 次（固定溫度 T），依據正確率將各查詢標註為「工具必要」或「工具非必要」。
2. **抽取並標註隱藏狀態**：在內部認知階段與執行階段，分別抽取深層與最末詞元情境的隱藏狀態，建立對應標籤。
3. **訓練雙探針系統**：分別訓練認知探針（預測工具必要性）與行動探針（預測實際工具呼叫行為），驗證兩者在淺層的線性可解碼性，並監測深層的正交性。
4. **部署認知-行動對齊閘道**：當認知探針顯示「必要」但行動探針未觸發時，啟動強制工具呼叫或重新提示機制，直接縮小知行落差。
5. **建立持續校準迴路**：隨模型版本更新、微調或溫度參數調整，定期重新評估能力邊界與探針方向，避免靜態標註過時。

### 潛在風險與注意事項

- **避免模型無關標註陷阱**：勿僅依賴人工標註或 LLM 評判模型，必須以目標模型的實證表現為依歸，否則會反映評判者的能力邊界而非受測模型。
- **探針正交性問題**：深層中認知方向與執行方向趨於正交，直接疊加探針分數或簡單閾值判斷可能無效，需設計獨立的轉換機制。
- **採樣參數敏感性**：工具必要性定義受溫度與採樣次數影響，產品環境中需固定推論參數，或建立參數感知的必要性對照表。
- **延遲與成本權衡**：抽取隱藏狀態與執行探針推論會增加延遲，建議評估採用離線監控分析（用於後續微調）而非即時攔截。
- **過擬合與遷移風險**：探針可能在特定資料集過擬合，從算術遷移至事實問答時需重新驗證探針泛化性。

### 與其他技術的整合建議

- **整合 MCP / A2A 標準化工具生態**：將模型適應性判斷層嵌入現有工具協定，作為前置路由閘道，統一管理外部工具註冊與呼叫。
- **結合 RAG 系統**：以模型適應性必要性取代固定的檢索觸發規則，減少最先進模型的冗餘檢索次數，同時提升較小模型的召回率。
- **搭配 Guardrails 框架**：將探針輸出作為安全護欄的輸入訊號，當偵測到知行落差時強制介入，避免模型在缺乏內在能力時直接回答。
- **銜接 RLHF / DPO 訓練管線**：利用認知探針發現的「知道卻不做」樣本作為偏好資料，微調模型以縮小知行落差，而非僅仰賴提示工程。
- **匯入可觀測性平台**：將探針分數與工具呼叫軌跡寫入 LangSmith、Weights & Biases 等系統，建立視覺化監控儀表板，追蹤必要性與行為不匹配的長期趨勢。

### 給不同背景讀者的閱讀建議

- **初學者**：聚焦「不同模型的能力邊界不同」與「知行落差」這兩個核心概念。不必深入探針數學細節，重點理解為何不能統一規定「哪些查詢一定要呼叫工具」，而應根據模型實際表現動態調整決策邏輯。

- **AI 工程師**：著重實作雙階段探針系統與隱藏狀態抽取管線。關注深層與最末詞元情境下的正交性現象，並設計認知探針與行動探針之間的轉換機制（如閘控邏輯或額外輕量模型），以解決「知道卻不做」的問題。

- **研究者**：深入分析深層網路中認知方向與執行方向趨於正交的機制意涵。可進一步探討此現象是否普遍存在於其他後設認知任務（如拒絕有害查詢、數學問題放棄決策），並發展更細緻的機械可解釋性方法。

- **產品經理**：關注論文量化的不匹配比例（算術 26.5–54.0%、事實問答 30.8–41.8%），評估這些落差對使用者體驗與 API 成本的具體影響。重點思考如何將「模型適應性必要性」轉化為產品規格，例如動態工具呼叫策略或模型選擇路由器的設計。
