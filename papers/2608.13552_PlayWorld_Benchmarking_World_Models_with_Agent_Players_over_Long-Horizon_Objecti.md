# PlayWorld：以 Agent Players（智慧型玩家代理）達成長程目標的世界模型基準測試

## ⚡ TL;DR

現有基準的固定動作軌跡難以對應長程目標與不同動作粒度，無法公平比較世界模型。
本文提出PlayWorld，智慧玩家代理依長程目標自適應互動，評測幾何、互動、視線外與洞察演化。
實驗顯示九個最先進模型在長程互動目標上仍不可靠，尤其空間一致性與持續狀態演化。

## 摘要翻譯

影片世界模型（Video world models）會以當前觀測（current observations）與使用者動作（user actions）為條件來模擬未來狀態（future states）。近期系統已在長序列中展現出令人印象深刻的影片一致性（video consistency）與動作可控性（action controllability）。然而，公平比較這些互動式模型仍具挑戰性。實務上，人類玩家（human player）通常透過互動來追求長程目標（long-horizon objectives），進而評估世界模型（world model）。例如，使用者可能原地轉身 360 度以檢視環境是否保持一致，或走進水中檢查是否生成逼真的水波紋。達成相同目標所需的動作序列（action sequence）在不同模型之間可能差異甚大，使得固定動作條件式評估（fixed action-conditioned evaluation）不適合進行跨模型比較（cross-model comparison）。為了解決此問題，我們採用多模態 Agent Players（智慧型玩家代理）與世界模型互動，以達成指定的長程目標。基於此一典範（paradigm），我們提出 PlayWorld 基準測試（benchmark），包含 171 個情境（scenarios），每個情境皆有一個指定目標（objective）。為了全面評估模型表現，我們從四個核心維度（core dimensions）評估模型：幾何一致性（geometry consistency）、互動逼真度（interaction fidelity）、視線外演化（out-of-sight evolution）與洞察演化（insight evolution）。此外，我們也納入影片品質（video quality）與可控性（controllability）等基礎能力指標（basic ability metrics）。針對九個最先進（state-of-the-art）世界模型的實驗顯示，現有模型在長程互動目標上仍然不可靠，特別是在維持空間一致性（spatial consistency）與持續狀態演化（persistent state evolution）方面。程式碼與資料可於 https://github.com/kxding/PlayWorld 取得。

### 核心貢獻（3～5點）
- 提出以多模態 Agent Players（智慧型玩家代理）與世界模型互動、達成長程目標的自動化評估典範，解決固定動作條件式評估難以公平進行跨模型比較的問題。
- 建立 PlayWorld 基準測試，包含 171 個具明確目標的情境，並從幾何一致性、互動逼真度、視線外演化與洞察演化四個核心維度，輔以影片品質與可控性等基礎能力指標，全面評估世界模型。
- 對九個最先進世界模型進行大規模實驗，揭示現有模型在長程互動目標上仍不可靠，尤其在維持空間一致性與持續狀態演化方面存在明顯不足。

### 適合對象
適合對世界模型、互動式影片生成、自動化模型評估與長程決策有興趣的研究者與工程師，特別是關注如何公平比較不同世界模型、設計基準測試，以及開發能穩定維持因果一致演化的互動式世界模型之讀者。

## 深度分析

#### 方法論解析

##### 1. 核心問題意識：從固定動作條件式評估（fixed action-conditioned evaluation）轉向長程目標導向評估
PlayWorld 指出，現有世界模型基準測試（world-model benchmarks）大多採用「預先定義的客製化軌跡（customized trajectories）」來驅動模型：對每個評估案例（evaluation case）給定固定的相機軌跡（camera trajectory）或動作序列（action sequence），再檢查生成結果。這種做法在跨模型比較（cross-model comparison）時存在根本缺陷，因為不同模型的動作粒度（action granularity）與回應動態（response dynamics）不同。同樣的「向右轉三次」指令，在模型 A 可能完成 360° 環視，在模型 B 只轉了 120°，導致幾何一致性分數（geometry consistency scores）無法公平比較。更複雜的動作模式（action patterns），例如環繞（orbiting）雕塑並保持固定視向，幾乎不可能用單一固定軌跡在所有模型上達成相同評估狀態。

因此，PlayWorld 將評估單位從「動作軌跡是否被正確執行」轉換為「人類玩家（human player）是否能透過互動達成高層級長程目標（long-horizon objectives）」。這與實際使用者體驗更貼近：人類不會記住精確的按鍵次數，而是根據畫面回饋即時調整操作。

##### 2. Agent Player（智慧型玩家代理）的閉環自適應機制
PlayWorld 的技術核心是 Agent Player，一個多模態（multi-modal）代理，模擬人類玩家與世界模型互動。其運作流程可拆解為：

- **共享初始參考（shared initial reference）**：每個情境（scenario）提供一條基本動作序列（basic action sequence），作為所有受測模型的共同起點。這確保了評估的初始條件一致，但並不要求模型嚴格遵循。
- **觀察與決策**：在每一步，Agent Player 觀察當前觀測（current observations，即生成影格 generated frames）與動作歷史（action history），然後從五種決策中選擇：
  - Keep（保持）：繼續執行目前動作。
  - Stop（停止）：終止目前動作，避免過度移動。
  - Extend（延長）：因模型反應較慢，延長動作持續時間。
  - Correct（修正）：當軌跡偏離目標時進行補償。
  - End（結束）：判定目標已達成或無法達成，結束 rollout（展開執行）。

這五種決策構成閉環自適應調整（adaptive adjustment），使 Agent Player 能根據每個模型的實際回應，動態調整動作數量與持續時間。如此一來，不同模型雖然對相同指令的物理回應不同，卻能在「達成同一長程目標」的語義層次上被公平比較。

##### 3. VQA 評分標準（VQA rubric）與四大核心維度（core dimensions）
為了評估開放式互動情境，PlayWorld 引入 VQA rubric verifier，以視覺問答（Visual Question Answering, VQA）形式的評分準則對 rollout 進行判斷。評估涵蓋四個核心維度：

- **幾何一致性（geometry consistency）**：檢查長程移動後場景幾何是否保持一致，例如 360° 環視後是否能回到初始視角、物體相對位置是否穩定。
- **互動逼真度（interaction fidelity）**：評估模型對使用者動作（user actions）的回應是否真實，例如走進水中是否產生合理水波、碰撞後物體反應是否符合物理。
- **視線外演化（out-of-sight evolution）**：測試物體離開畫面後，其狀態是否持續合理演化，而非被遺忘或隨機改變。
- **洞察演化（insight evolution）**：檢視模型對情境理解的演變，例如隨著探索進行，模型是否能維持語義一致的情境脈絡。

此外，PlayWorld 還包含基礎能力指標（basic ability metrics），涵蓋影片品質（video quality）與動作可控性（action controllability），以確保模型不僅在長程目標上表現良好，也具備基本的視覺品質與控制回應能力。

##### 4. 控制空間與評估規模
PlayWorld 使用連續的 W/A/S/D、方向鍵（↑/↓/←/→）以及 WAIT 控制，模擬常見的鍵盤操作。評估 rollout 長度約 10 至 60 秒，遠超過許多現有基準的 2–10 秒，這對持續狀態演化（persistent state evolution）與長期記憶一致性（memory consistency）構成更嚴苛的測試。基準共包含 171 個人工標註情境（human-annotated scenarios），每個情境都有明確的長程目標。

#### 實驗數據解讀

##### 1. 受測模型與整體發現
論文在 171 個情境上評估了九個最先進（state-of-the-art）的世界模型。雖然提供的摘要與前文未包含詳細數值表格，但從摘要與引言可歸納出兩項關鍵結論：

- **當前模型在長程互動目標上仍不可靠**：即使個別模型在短片段中展現出令人印象深刻的視覺品質（visual quality）與動作可控性（action controllability），一旦進入需要多步互動、長時間維持狀態的任務，整體表現便明顯下降。
- **空間一致性（spatial consistency）與持續狀態演化（persistent state evolution）是最大弱點**：這與現有文獻中對世界模型記憶一致性（memory consistency）的質疑一致。模型容易在相機繞行、物體離開視線後重新出現、或長時間互動後發生幾何漂移（geometric drift）與狀態遺忘。

##### 2. 指標設計的診斷價值
PlayWorld 的四個核心維度具有明確的診斷分工：

- 若模型在 **geometry consistency** 得分低，問題較可能出在 3D 場景表示、相機姿態估計或動作到幾何變換的映射。
- **interaction fidelity** 低，則暗示物理模擬、動作條件式（action-conditioned）生成機制或互動語義理解不足。
- **out-of-sight evolution** 低，代表模型缺乏長期記憶機制，或隱狀態（hidden state）在物體不可見時無法持續更新。
- **insight evolution** 低，則可能反映模型對高層級情境語義的追蹤能力有限。

這種細分有助於研究者定位模型缺陷，而非僅獲得一個籠統的分數。

##### 3. 對「動作粒度」差異的量化意義
由於 Agent Player 會自適應調整，最終評估結果更能反映模型在「語義目標達成」上的能力，而非「對固定指令的執行精度」。這意味著：

- 一個動作回應較慢但穩定的模型，可能透過 Extend 決策獲得與回應快模型相同的評估狀態。
- 相反，一個動作回應不穩定、容易過衝或漂移的模型，即使視覺品質高，也會在長程目標上被正確懲罰。

這種設計減少了傳統基準中常見的「軌跡失敗（trajectory failure）」與「幾何不穩定（geometric inconsistency）」被混淆的問題。

#### 與現有研究的比較

##### 1. 相較於通用影片生成基準
VBench 等通用影片生成基準測試（general video generation benchmarks）聚焦美學（aesthetics）、時序連貫性（temporal coherence）與文本對齊（text alignment），但不評估模型對使用者動作（user actions）的回應。PlayWorld 則專注於互動式環境（interactive environments）中的因果一致演化（causally consistent evolution），填補了這一空白。

##### 2. 相較於現有世界模型基準
從 Table 1 可清楚看出 PlayWorld 的差異化定位：

| 基準測試 | 輸入形式 | 閉環自適應（closed-loop adaptation） | 長程重訪（long-horizon revisit） | 幾何一致性（geometry consistency） | 狀態演化（state evolution） | 互動逼真度（interaction fidelity） | rollout 長度 |
|---|---|---|---|---|---|---|---|
| WorldScore | Text+Image+camera | ✗ | ✗ | ✓ | ✗ | ✗ | ∼2–10s |
| WorldMark | Image+action | ✗ | ∼ | ✓ | ✗ | ✗ | 20/40/60s |
| WBench | Text+Image+camera/action | ✗ | ∼ | ✓ | ∼ | ✓ | 10–45s |
| WorldRoamBench | Image+action | ✗ | ∼ | ✓ | ∼ | ✓ | 10–60s |
| MemoBench | Text+Image+camera | ✗ | ✗ | ✓ | ✓ | ✗ | 4–6s |
| Omni-WorldBench | Text+Image+camera | ✗ | ✗ | ∼ | ✓ | ✓ | 3–6s |
| **PlayWorld** | **Text+Image+Objective** | **✓** | **✓** | **✓** | **✓** | **✓** | **10–60s** |

PlayWorld 是唯一同時具備閉環適應、長程重訪、並完整覆蓋 geometry / state / interaction 三大能力的基準。

##### 3. 主要改進
- **公平性提升**：透過 Agent Player 的目標導向操作，消除了因動作粒度差異造成的比較偏差。
- **自動化與可擴展性**：相較於 Genie 3、Happy Oyster 等基於網頁的閉源世界模型（web-based closed-source world models）需要人工操作，PlayWorld 提供自動化評估協定（automated evaluation protocol），降低人力成本與主觀偏差。
- **長程與開放式評估**：171 個情境與 10–60 秒的 rollout，能測試現有短片段基準無法觸及的持續狀態演化與記憶一致性。

##### 4. 限制與潛在偏見
- **Agent Player 本身的限制**：Agent Player 的決策品質取決於底層多模態模型的視覺理解與規劃能力。若 Agent 對目標理解錯誤，可能導致不公平的評估。
- **VQA verifier 的可靠性**：開放式互動情境的評分仰賴 VQA rubric verifier，其判斷可能受提示詞設計（prompt engineering）與模型幻覺影響。
- **控制空間有限**：目前僅支援鍵盤式連續控制（W/A/S/D、方向鍵、WAIT），尚未涵蓋滑鼠、遊戲手把或語言指令等更豐富的互動形式。
- **閉源模型的可及性**：雖然 PlayWorld 提供自動化協定，但對於僅能透過網頁介面（web interface）操作的閉源模型，仍需模擬瀏覽器互動，可能受 API 限制、速率限制與介面變更影響。

#### 可重現性評估

##### 1. 開放資源
論文明確指出程式碼與資料可在 https://github.com/kxding/PlayWorld 取得，這為可重現性（reproducibility）奠定良好基礎。研究者原則上可以下載：
- 171 個評估案例（evaluation cases）與對應的長程目標（long-horizon objectives）。
- 基本動作序列（basic action sequences）作為共享初始參考。
- Agent Player 的實作與 VQA rubric verifier。

##### 2. 可重現性的實際挑戰
儘管 PlayWorld 本身的程式碼與資料開放，完整重現論文實驗仍面臨以下障礙：

- **受測世界模型的權重與介面**：九個受測模型中，Genie 3、Happy Oyster 等為閉源（closed-source）且僅提供網頁介面（web interface），無法本地執行。重現者需自行處理網頁自動化、帳號權限與 API 限制。
- **多模態 Agent 與 VQA verifier 的底層模型**：Agent Player 與 verifier 很可能依賴大型多模態語言模型（如 GPT-4V、Claude 等），這些模型本身並非開源，且其輸出可能隨版本更新而變化，影響結果穩定性。
- **運算成本**：對 171 個情境進行 10–60 秒的 rollout，並在每步呼叫多模態模型進行決策與評分，整體成本與延遲相當可觀，對資源有限的研究團隊構成門檻。
- **隨機性與種子**：世界模型生成通常具有隨機性，若論文未詳細記錄種子、取樣參數與重複次數，數值結果可能難以完全一致。

##### 3. 整體評價
PlayWorld 在「基準測試（benchmark）本身的開放性」上表現良好，但在「端到端重現九個最先進模型的完整比較」上，仍受限於閉源模型與商業多模態 API。建議未來版本提供：
- 輕量級的開源世界模型作為標準受測對照。
- Agent Player 與 verifier 的詳細提示詞與版本紀錄。
- 預先生成的 rollout 資料與評分結果，供無法負擔完整運算成本的社群使用。

#### 未來研究方向

##### 1. 擴展動作空間與互動模態
未來可將控制空間從鍵盤擴展至滑鼠、遊戲手把、觸控、語言指令（language instructions）甚至眼動追蹤，使評估更貼近真實人機互動。這也能測試世界模型對多模態輸入的整合能力。

##### 2. 動態與對抗性目標設計
目前 PlayWorld 使用預先定義的長程目標。未來可引入動態目標（dynamic objectives）或對抗性目標（adversarial objectives），例如根據模型弱點即時生成更困難的測試，以更有效發現模型邊界。

##### 3. 多 Agent 與社會互動情境
將單一 Agent Player 擴展為多個 Agent Player（multi-agent），模擬多人協作或競爭情境，可評估世界模型在社會互動、長期因果規劃與群體行為模擬上的能力。

##### 4. 結合真實模擬器進行混合評估
世界模型可與傳統物理模擬器（如 MuJoCo、Habitat、Isaac Sim）結合，利用模擬器提供 ground-truth 狀態，彌補 VQA verifier 在主觀判斷上的不確定性，特別是在 out-of-sight evolution 與 interaction fidelity 的量化上。

##### 5. 自動化情境生成與難度分級
目前 171 個情境為人工標註。未來可發展自動化情境生成（automatic scenario generation）與難度分級機制，根據模型能力動態調整測試難度，並持續擴大基準規模。

##### 6. 診斷式與因果式評估指標
除了 VQA 分數，未來可設計更細緻的診斷指標，例如量化幾何漂移（geometric drift）幅度、記憶遺忘時間、互動反應延遲等，並透過介入式因果分析（causal intervention）判斷模型失敗的根本原因。

##### 7. 標準化世界模型 API 與開放生態
為了改善可重現性，社群可推動標準化世界模型 API，使閉源與開源模型都能以統一介面被 Agent Player 呼叫。這將大幅降低跨模型比較的技術門檻，並促進世界模型領域的良性競爭。

## 論文問答

**Q1：PlayWorld 試圖解決的核心問題是什麼？**
A：PlayWorld 試圖解決現有影片世界模型在公平比較上的困難，特別是當不同模型對相同動作指令產生不同反應幅度時，固定軌跡評估無法真實反映模型能力。傳統基準測試通常依賴預先定義的動作軌跡，但這些軌跡無法適應各模型在動作粒度與回應動態上的差異。因此，PlayWorld 提出以長程目標為導向的評估方式，讓多模態 Agent Player 像人類玩家一樣與世界模型互動，從而在相同高層級目標下進行更公平的跨模型比較。

**Q2：為什麼現有的世界模型基準測試無法公平比較不同模型？**
A：現有基準測試大多使用預先定義的客製化軌跡或固定動作序列來驅動模型，但不同世界模型對相同控制訊號的執行幅度與反應速度並不一致。例如，同樣的三個旋轉指令在某些模型中可能完成 360 度轉身，但在其他模型中只轉了部分角度，導致評估狀態無法對齊。這種動作粒度的差異會使幾何一致性或狀態演化等分數產生混淆，無法區分是模型能力不足還是軌跡本身不適合該模型。

**Q3：為什麼透過長程目標而非固定動作軌跡來評估世界模型很重要？**
A：在實際使用中，人類玩家通常是透過追求高層級目標來判斷世界模型的好壞，例如繞行雕塑一圈或走進水中觀察漣漪，而非檢查是否遵循某個預設指令序列。長程目標能更貼近真實互動情境，因為達成目標所需的路徑會因模型特性而自然調整。這種評估方式能夠區分模型在空間一致性、互動逼真度與持續狀態演化等核心能力上的真正差異，避免將軌跡執行失敗誤判為模型品質問題。

**Q4：PlayWorld 的核心方法是什麼？**
A：PlayWorld 的核心方法是使用多模態 Agent Player 作為智慧型玩家代理，讓它在每個步驟觀察生成影格與動作歷史，並根據模型反應自適應調整執行策略。Agent Player 會在基本動作序列的基礎上，透過 Keep、Stop、Extend、Correct、End 五種決策來動態調整動作數量與持續時間，確保各模型都能朝相同的長程目標前進。此外，PlayWorld 還引入 VQA 評分標準驗證器，對開放式互動情境進行自動化評分，涵蓋幾何一致性、互動逼真度、視線外演化與洞察演化四個核心維度。

**Q5：Agent Player 的關鍵創新是什麼？**
A：Agent Player 的關鍵創新在於它將評估從「固定動作條件式」轉變為「目標導向的閉環適應」，能夠根據世界模型實際產生的畫面即時調整動作執行。不同於傳統基準要求所有模型遵循同一條預設軌跡，Agent Player 會針對每個模型的動作粒度與回應特性，決定是否延長、停止或修正動作，使最終到達的評估狀態具有可比性。這種設計特別適合處理複雜動作模式，例如環繞雕塑同時保持固定視角，因為所需動作持續時間與停止點在不同模型間差異很大。

**Q6：PlayWorld 為何採用 VQA 評分標準驗證器，其四個核心評估維度各代表什麼？**
A：PlayWorld 採用 VQA 評分標準驗證器，是因為開放式互動情境難以用單純的像素或軌跡比對來評分，需要透過視覺問答的方式檢驗模型是否達成語意層級的目標。四個核心維度中，幾何一致性檢視空間結構與視角變化是否穩定；互動逼真度衡量模型對使用者動作產生的反應是否真實合理；視線外演化評估物體離開畫面後狀態是否持續一致；洞察演化則檢視模型對情境理解與高層級語意關係的演變能力。這些維度共同構成對世界模型長程互動能力的全面檢驗。

**Q7：PlayWorld 基準測試包含哪些內容？**
A：PlayWorld 基準測試包含 171 個由人工標註的評估情境，每個情境都設有一個明確的長程目標與作為初始參考的基本動作序列。評估框架支援連續的 W/A/S/D、方向鍵與 WAIT 控制，並讓 rollout 持續約 10 到 60 秒，以測試模型在長時間互動下的表現。除了四個核心維度外，PlayWorld 還納入影片品質與動作可控性等基礎能力指標，從多個層面評估世界模型的整體水準。

**Q8：PlayWorld 的主要實驗結果是什麼？**
A：PlayWorld 對九個最先進的世界模型進行評估，結果顯示現有模型在長程互動目標上仍然不夠可靠，尤其在維持空間一致性與持續狀態演化方面存在明顯弱點。實驗發現，即使部分模型在短期影片品質或視覺真實感上表現良好，一旦進入需要多步互動與狀態記憶的長程情境，就容易出現場景漂移、物體消失或互動反應不一致等問題。這些結果凸顯了目前世界模型與真正可自由探索的開放世界之間仍有顯著差距。

**Q9：PlayWorld 的實驗分析揭示了哪些模型能力的邊界？**
A：PlayWorld 的實驗分析揭示，當前世界模型在處理需要重訪、長時記憶與複雜互動的任務時能力邊界明顯，例如繞行後回到原點或視線外物體重新出現時狀態不一致。不同模型在動作粒度與回應速度上的差異，也會直接影響它們達成長程目標的成功率。透過 Agent Player 的閉環適應，PlayWorld 能夠將這些差異從評估分數中分離出來，更精確地定位各模型在幾何、互動、記憶與語意理解上的具體強項與弱點。

**Q10：PlayWorld 的評估方式可應用於哪些實際場景？**
A：PlayWorld 的評估方式可應用於開放世界遊戲、虛擬實境探索、機器人模擬訓練以及自動駕駛場景模擬等需要長期互動一致性的領域。在這些場景中，使用者或代理不會只執行單一指令，而是會在環境中持續探索、互動並期望世界狀態因果一致地演化。透過 PlayWorld 的目標導向評估，開發者能夠更準確地判斷模型是否適合部署在需要長程決策與狀態記憶的應用中。

**Q11：PlayWorld 對世界模型產品開發有何影響？**
A：PlayWorld 為世界模型產品開發提供了一套更貼近真實使用者經驗的評估標準，有助於開發者在產品上線前發現長程互動中的潛在問題。對於網頁式閉源模型如 Genie 3 或 Happy Oyster，PlayWorld 的自動化評估協定也能減少人工測試的成本與主觀偏差。此外，透過明確的幾何一致性、互動逼真度與狀態演化指標，產品團隊可以更有系統地追蹤版本迭代對使用者體驗的影響。

**Q12：PlayWorld 對世界模型研究領域可能帶來什麼影響？**
A：PlayWorld 推動世界模型研究從單純追求視覺品質，轉向更重視長程互動一致性、因果合理性與開放式探索能力。它提供了一個標準化的長程目標導向評估框架，讓研究者能夠在相同基準上比較不同架構與控制格式的模型。這將有助於識別目前方法的共同瓶頸，並引導未來研究針對空間記憶、物理互動與持續狀態演化等關鍵能力進行突破。

**Q13：PlayWorld 有哪些可能的限制？**
A：PlayWorld 的一個可能限制是 Agent Player 的決策品質依賴於多模態模型的能力，若代理本身對生成畫面的理解有偏誤，可能會影響評估結果的準確性。此外，雖然 171 個情境已涵蓋多種長程目標，但相較於真實開放世界的無限可能性，基準測試仍無法窮盡所有互動情境。另外，部分閉源模型僅能透過網頁介面互動，可能會限制自動化評估的規模與可重複性。

**Q14：PlayWorld 揭示了哪些當前模型的典型失敗案例？**
A：PlayWorld 揭示當前模型常見的失敗案例包括：執行 360 度旋轉後無法回到初始視角、環繞物體時場景幾何發生漂移、走進水中未產生合理漣漪，以及視線外物體重新出現時狀態改變。這些失敗顯示模型雖然能生成高品質單幀畫面，但缺乏穩定的三維空間記憶與持續的物理狀態追蹤能力。在需要長程目標達成的情境中，這類問題會顯著降低使用者對世界模型真實感與可信度的評價。

**Q15：PlayWorld 指出了哪些未來研究方向？**
A：PlayWorld 指出未來研究應優先提升世界模型的長程空間一致性、視線外狀態記憶與複雜互動的物理合理性。研究者可以探索更強大的世界模型架構，例如結合顯式三維表徵、神經場景圖或記憶模組，以支援持續的狀態演化。此外，發展更聰明的 Agent Player、擴充更多元的情境與目標，以及建立與人類主觀評價更緊密對齊的自動化評分方法，也是值得持續投入的方向。

## 實務應用指南

### 適用場景

1. **互動式世界模型選型與採購評估**  
   企業或遊戲工作室在導入 Genie 3、Happy Oyster、Matrix-Game 等閉源或開源世界模型前，可利用 PlayWorld 的長程目標與 Agent Player 自動化比較各模型在幾何一致性、互動逼真度、視線外演化等面向的表現，避免被單一影片品質指標誤導。

2. **開放世界遊戲與虛擬場景的品質保證（QA）**  
   在遊戲原型或元宇宙場景開發中，可將 PlayWorld 的 171 個情境轉化為回歸測試案例，自動檢查玩家繞行 360°、走進水中、離開視線後再返回等長程互動是否仍保持空間一致與狀態持續演化。

3. **機器人與自動駕駛模擬器的真實性驗證**  
   當世界模型被用來生成訓練資料或模擬環境時，可用 PlayWorld 的評估框架驗證模型對連續動作（W/A/S/D、方向鍵、WAIT）的反應是否穩定，特別是物體離開畫面後的狀態是否仍合理演化。

4. **多模態 Agent 的能力基準測試**  
   研究團隊若開發自己的 Agent Player 或視覺問答（VQA）評分模型，可將 PlayWorld 作為標準測試床，比較不同 Agent 在「根據畫面與動作歷史自適應調整執行」的能力。

5. **閉源網頁介面模型的自動化評測**  
   針對僅提供網頁介面的閉源模型，可透過 PlayWorld 的 Agent Player 模擬人類玩家操作，降低人工逐案測試的成本與主觀偏差。

### 實作前置條件

**資料需求**
- 取得 PlayWorld 提供的 171 個人類標註情境，每個情境包含文字描述、初始影像與長程目標（Objective），以及作為 Agent Player 初始參考的基本動作序列。
- 若需評估自有模型，須準備對應的 API 端點或本地推論環境，並能回傳連續生成影格與接受連續動作輸入。
- 建議額外收集模型特定的動作粒度校正資料，以便 Agent Player 的 Keep / Stop / Extend / Correct / End 決策能更快收斂。

**運算需求**
- 世界模型推論本身需要大量 GPU 資源（視模型而定，通常需高階 NVIDIA GPU 或雲端 API 配額）。
- Agent Player 通常由多模態大型語言模型（MLLM）擔任，每次決策需處理多張影格與動作歷史，建議預留足夠的 API 呼叫預算與快取空間。
- VQA 評分標準 verifier 可獨立部署，需支援影像輸入的視覺問答模型或專用評分模型。

**技能需求**
- 熟悉 Python、深度學習推論流程，以及世界模型的動作介面（鍵盤控制、相機軌跡或 API 參數）。
- 具備多模態模型提示工程經驗，能調整 Agent Player 的系統提示與決策邏輯。
- 了解評估指標設計，能依產品需求調整 VQA rubric 的評分權重。

---

### 實作步驟建議

1. **環境建置與資料載入**  
   從 PlayWorld 官方倉庫下載資料集，建立評估環境，並確認每個情境的初始影像、目標描述與基本動作序列可正確讀取。

2. **對接目標世界模型**  
   為每個待測模型建立統一介面，將連續動作（W/A/S/D、方向鍵、WAIT）轉換為模型可接受的輸入格式。對於閉源網頁介面，可透過瀏覽器自動化工具或官方 API 封裝。

3. **設定 Agent Player**  
   選擇或訓練多模態 Agent Player，使其在每個時間步觀察生成影格與動作歷史，並根據長程目標輸出 Keep、Stop、Extend、Correct 或 End 決策。針對不同模型的動作粒度進行初步校正。

4. **執行 Rollout 並記錄軌跡**  
   讓 Agent Player 與各模型互動，產生約 10–60 秒的 rollout。記錄完整影格序列、實際執行的動作軌跡，以及 Agent Player 的決策理由，便於後續除錯。

5. **執行 VQA Rubric 評分**  
   針對每個 rollout，依四個核心維度（幾何一致性、互動逼真度、視線外演化、洞察演化）與基礎能力指標（影片品質、動作可控性）執行視覺問答評分。

6. **彙整結果並產出報告**  
   將各模型在不同情境與維度的分數視覺化，識別弱項（例如長程空間一致性不足），並根據產品需求決定模型選型或改進方向。

### 潛在風險與注意事項

- **動作粒度差異導致評分失真**  
  不同模型對相同按鍵的反應幅度可能不同，若 Agent Player 未自適應調整，可能將「動作執行不足」誤判為「模型幾何不穩定」。建議在正式評測前，先以簡單動作（如 360° 旋轉）校正各模型的動作映射。

- **Agent Player 本身的偏差與錯誤**  
  Agent Player 可能因提示設計或視覺理解限制而做出錯誤決策。可透過人機協作抽查、設定決策可解釋性日誌，以及使用多個 Agent 投票來降低風險。

- **閉源模型的介面變動**  
  網頁式閉源模型的介面或 API 可能更新，導致自動化腳本失效。建議將介面封裝層與評估核心分離，並定期維護適配器。

- **長程 rollout 的運算成本與時間**  
  10–60 秒的互動序列涉及大量推論與 API 呼叫，成本可能快速累積。可先以抽樣情境進行試跑，再擴大到完整 171 個案例。

- **過度聚焦單一指標**  
  影片品質高並不代表世界模型可靠。建議同時檢視四個核心維度與基礎能力指標，避免以偏概全。

### 與其他技術的整合建議

- **與通用影片基準（如 VBench）互補**  
  PlayWorld 專注於互動與長程目標，VBench 則衡量美學、時序連貫性與文本對齊。兩者可並行使用，前者驗證「世界是否可互動」，後者驗證「畫面是否好看」。

- **與機器人模擬器（如 Isaac Sim、NVIDIA Cosmos）整合**  
  可將 PlayWorld 的評估情境轉換為機器人任務，驗證世界模型生成的場景是否足以支援下游策略學習與規劃。

- **與 MLOps / 持續整合（CI）管線結合**  
  將 PlayWorld 包裝為自動化測試腳本，在每次模型更新後執行關鍵情境的回歸測試，並將幾何一致性、互動逼真度等分數納入模型發布閘道。

- **與人類回饋（RLHF）資料管線串接**  
  Agent Player 的決策記錄與 VQA 評分結果可作為偏好資料，用於進一步微調世界模型或 Agent Player 本身。

- **與可解釋性工具搭配**  
  結合注意力視覺化或場景圖（scene graph）工具，分析模型在視線外演化或洞察演化失敗時的內部表徵，協助定位問題根源。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從摘要與適用場景開始，理解「世界模型」與「通用影片生成模型」的差別，再透過圖表與範例情境（如 360° 旋轉、走進水中）掌握長程目標評估的概念。技術細節如 Agent Player 的決策邏輯與 VQA rubric 可暫時略讀，重點放在「為什麼固定動作軌跡不適合跨模型比較」。

**給 AI 工程師**  
請聚焦於 Agent Player 的設計、動作粒度校正、以及 VQA verifier 的實作細節。建議直接參考官方程式碼，並嘗試將 PlayWorld 對接到你正在使用的世界模型 API。特別注意 rollout 過程中的錯誤處理、快取策略與成本控管。

**給研究人員**  
本文的核心貢獻在於提出以「長程目標」取代「固定動作軌跡」的評估典範，並定義四個核心維度。建議深入閱讀方法論與實驗設計，思考如何擴展情境數量、設計更困難的視線外演化與洞察演化測試，或將 Agent Player 的決策機制形式化為強化學習問題。

**給產品經理**  
請將本文視為一份互動式世界模型的「採購與品質檢查清單」。重點不在技術細節，而在於理解：影片品質只是門檻，真正的產品價值取決於模型能否在長時間互動中維持空間一致、狀態持續演化與動作可控。可據此與技術團隊討論 MVP 應優先驗證哪些情境。
