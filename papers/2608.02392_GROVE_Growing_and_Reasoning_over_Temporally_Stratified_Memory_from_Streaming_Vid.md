## ⚡ TL;DR

現有影片記憶系統多僅支援問題條件式召回，難以同時滿足反應式問答與主動式協助的需求。
GROVE是免訓練框架，從連續影片串流建立時刻、片段與跨日模式等時序分層記憶，並以各層檢索技能存取。
在多項基準測試中，GROVE表現最佳，消融實驗亦顯示各時序層級與檢索技能互補，跨日模式貢獻最大。

## 摘要翻譯

穿戴式助理（Wearable assistant）應該既能回答關於其視覺歷史（Visual history）的問題，也能辨識該視覺歷史何時對當前情境（Current situation）有助益。現有的影片記憶系統（Video-memory systems）主要支援問題條件式召回（Question-conditioned recall），而主動式助理（Proactive assistant）通常使用獨立的記憶與控制機制。我們提出 GROVE（Growing and Reasoning over Temporally Stratified Memory），這是一個免訓練框架（Training-free framework），僅憑單一個從連續影片串流（Continuous video stream）中因果增長的記憶，同時支援這兩種行為。GROVE 保留細粒度感知證據（Fine-grained perceptual evidence），並將其遞增式鞏固（Incrementally consolidate）為時間戳記時刻（Time-stamped moment）、連貫片段（Coherent episode），以及跨日重複模式（Recurring cross-day pattern）。每個時序層級（Temporal stratum）都搭配一項尺度原生檢索技能（Scale-native retrieval skill），分別用於定位觀察（Locate an observation）、重播活動（Replay an activity），或遍歷長程規律性（Traverse long-range regularities）。反應式問答（Reactive QA）與主動式協助（Proactive assistance）共享此記憶與存取介面，兩者的差異在於檢索（Retrieval）是由使用者查詢（User query）還是當前情境所觸發。在多個基準測試中，包括具挑戰性的 MM-lifelong 與 EgoServe，GROVE 在所有比較方法中取得最佳結果。受控消融實驗（Ablation）顯示，時序分層（Temporal strata）與其檢索技能具有互補性（Complementary），當證據橫跨多日時，模式層級帶來最大的效益。程式碼將公開於 https://github.com/SitongGong/GROVE。

### 核心貢獻（3～5點）
- 提出 GROVE 免訓練框架，以單一時序分層記憶統一支援反應式問答（Reactive QA）與主動式協助（Proactive assistance）。
- 設計從連續影片串流因果增長的記憶結構，將細粒度感知證據遞增式鞏固為時間戳記時刻、連貫片段與跨日重複模式三個時序層級。
- 為每個時序層級配備尺度原生檢索技能，分別支援定位觀察、重播活動與遍歷長程規律性。
- 在 MM-lifelong、EgoServe 等多個基準測試中取得最佳表現，並透過消融實驗驗證各層級與檢索技能的互補效益。

### 適合對象
適合對穿戴式裝置、第一人稱視角影片理解、長期記憶建模、主動式人工智慧助理，以及串流影片分析有興趣的研究人員與工程師；特別是關注如何以統一記憶架構同時支援反應式問答與主動式協助的讀者。

## 深度分析

#### 方法論解析

GROVE（Growing and Reasoning over Temporally Stratified Memory）的核心設計，是將「時間尺度」作為記憶儲存與讀取之間的介面。傳統影片記憶系統（video-memory systems）通常把連續影片串流（continuous video stream）壓縮成同質化的索引，再透過單一檢索（retrieval）操作回答問題；GROVE 則主張不同時間尺度的證據具有本質差異，應該分層儲存，並為每一層配備尺度原生檢索技能（scale-native retrieval skill）。

##### 雙通道感知編碼

每一個到達的影片視窗（video window）會同時經過兩條互補的感知通道：

1. **敘事字幕（narrative caption）**：以多模態大型語言模型（MLLM）產生自然語言描述，捕捉語意脈絡與活動內容。
2. **結構化感知登錄（structured perceptual registry）**：抽取實體（entities）、屬性（attributes）、明確數量（explicit counts）、動作（actions）與畫面文字（on-screen text）等細粒度感知證據（fine-grained perceptual evidence）。

這種雙通道設計讓系統既能回答高階語意問題（例如「我昨天做了什麼」），也能處理需要精確數值或物件狀態的問題（例如「桌上還有幾顆蘋果」）。

##### 時序分層記憶（Temporally Stratified Memory）

GROVE 將感知證據逐步鞏固（incrementally consolidate）為三個時間層級：

- **時刻（moments）**：帶時間戳記（time-stamped）的最小單位，保留細粒度觀察。
- **片段（episodes）**：由連續時刻組成的連貫事件（coherent episodes），對應數分鐘到數小時的活動。
- **跨日模式（cross-day patterns）**：從多個片段中歸納出的重複規律（recurring regularities），對應長期行為模式。

所有更新都是因果地（causally）進行，也就是說記憶只使用已經觀察到的影片，不會在事後重新處理整段歷史，因此能夠在串流持續到來的同時保持可用性。

##### 尺度原生檢索技能（Scale-Native Retrieval Skills）

GROVE 提供四種檢索技能，讓多輪代理（multi-round agent）可以組合使用：

1. **感知查詢（Perception Lookup）**：在時刻層級定位特定觀察（locate an observation）。
2. **時刻召回（Moment Recall）**：檢索特定時間點的細節。
3. **片段重播（Episode Replay）**：回顧完整活動（replay an activity）。
4. **模式遍歷（Pattern Traversal）**：探索長期規律（traverse long-range regularities）。

代理會根據問題或當前情境決定需要哪一層的證據，並在多輪檢索中累積非冗餘資訊。

##### 反應式與主動式控制策略

GROVE 讓反應式問答（reactive QA）與主動式協助（proactive assistance）共用同一套記憶與存取介面：

- **反應式問答**：由使用者查詢（user query）觸發，進入「決定—檢索—回答」（decide–retrieve–answer）迴圈。
- **主動式協助**：由當前情境（current situation）或前向請求（forward-looking request）觸發，先檢索相關時刻、片段與模式，再決定是否以及何時介入。

這種統一介面是 GROVE 與既有研究最關鍵的區別：過去系統通常把「問題驅動召回」與「主動服務觸發」視為兩個獨立機制，而 GROVE 證明兩者可以從同一個因果增長的記憶中讀取。

#### 實驗數據解讀

論文在多個基準測試（benchmarks）上進行評估，涵蓋超長期記憶（ultra-long memory）、即時感知（real-time perception）與主動服務（proactive services）三大能力：

- **MM-Lifelong**：長期影片理解基準，測試跨日甚至跨週的記憶。
- **EgoServe**：主動服務與第一人稱影片基準，評估系統在適當時機提供協助的能力。
- **OVOBench**：開放式影片問答基準，包含 OVO-FW（forward）、OVO-BW（backward）與 OVO-RT（real-time）三類子任務。
- **StreamingBench**：串流影片理解基準，包含 SB-CQ（contextual query）與 SB-RT（real-time）等子任務。

根據論文宣稱，GROVE 在這些基準上相較於 GPT、Gemini、Qwen、ReMA、EgoMemo、EPT、MiniCPM-V、IPT、StreamBridge 等對比方法取得最佳結果。這代表：

1. **分層記憶對超長期任務至關重要**：在 MM-Lifelong 這類需要回溯數日證據的任務中，單一層級的檢索難以同時兼顧效率與精確度。
2. **模式層級提供最大增益**：消融實驗（ablation）顯示，當證據橫跨多日時，跨日模式（cross-day patterns）帶來最大效益。這驗證了「長期規律必須顯式建構」的假設，因為這類規律無法從單一畫面或事件中推得。
3. **時刻與片段層級互補**：缺少任何一層都會降低整體表現，顯示三個時序層級（temporal strata）與其對應檢索技能並非可互相替代，而是各司其職。
4. **主動式與反應式可共用記憶**：在 EgoServe 上的表現說明，統一記憶介面不會犧牲主動服務的時機判斷能力。

值得注意的是，由於 GROVE 是免訓練框架（training-free framework），其性能主要來自記憶結構與檢索策略，而非額外的模型微調。這也意味著它的上限與所採用的凍結 MLLM 品質密切相關。

#### 與現有研究的比較

##### 相對於影片記憶系統

現有影片記憶系統大多採用「問題條件式召回」（question-conditioned recall）典範：使用者必須先提出明確查詢，系統才從索引中檢索相關片段。例如：

- **VAM** 使用去重時刻與年齡分層儲存。
- **StreamRAG** 線上分割事件以支援查詢自適應檢索。
- **MemDreamer / MAGIC-Video** 建立階層式或多模態記憶圖，並搭配代理工具庫。
- **ReMA** 強調在終身尺度（lifelong horizon）下動態記憶管理的重要性。

這些方法改善了儲存效率與檢索準確度，但大多仍維持「查詢優先」（query-first）的契約。GROVE 的突破在於讓記憶也能被「當前情境」讀取，從而支援主動式協助（proactive assistance）。

##### 相對於主動式助理

既有主動式助理（proactive assistants）通常使用獨立的記憶與控制機制來決定是否介入，例如根據當前狀態觸發服務。然而，這些機制主要為「服務觸發」設計，而非開放式回憶（open-ended recall）。GROVE 把兩種行為整合到單一記憶中，讓主動介入也能基於豐富的歷史證據，而不只是當前感知。

##### 與人類記憶理論的呼應

GROVE 的三層結構與人類記憶的片段式—語意式區分（episodic–semantic distinction）有概念上的相似性：時刻與片段對應片段記憶，跨日模式則接近語意化規律。但 GROVE 的差異在於：

- 長期規律是**顯式建構**的，而非從單一畫面隱式推論。
- 所有更新都是**因果地**進行，適合串流場景。
- 提供**尺度原生檢索技能**，讓不同時間尺度的資訊有專屬讀取方式。

##### 限制

儘管設計新穎，GROVE 仍存在若干限制：

1. **依賴凍結 MLLM 的感知品質**：字幕與結構化登錄的錯誤會向上傳播到片段與模式層級。
2. **線上鞏固的計算成本**：雖然論文強調因果更新，但持續執行事件分割、模式挖掘與記憶整理仍需可觀運算資源。
3. **模式提取的啟發式本質**：跨日模式如何定義、何時合併或分裂，可能受限於手工設計規則。
4. **隱私與儲存問題**：長期儲存第一人稱影片的細粒度感知證據涉及嚴重隱私風險。
5. **無法從回饋學習**：作為免訓練框架，GROVE 不會根據使用者回饋調整記憶組織方式。

#### 可重現性評估

論文指出原始碼將公開於 `https://github.com/SitongGong/GROVE`，這對可重現性（reproducibility）是正面訊號。由於 GROVE 是免訓練框架，不需要釋出額外的模型權重；重現主要取決於：

- 所採用的凍結 MLLM（如 GPT、Gemini、Qwen 等）是否可取得。
- 公開基準測試資料集（MM-Lifelong、EgoServe、OVOBench、StreamingBench、EgoMemo 等）是否可下載。
- 記憶建構與檢索流程的實作細節是否完整釋出。

目前這些資料集大多已公開或即將公開，因此理論上具備高度可重現性。然而，若實作仰賴特定商業 API（例如 GPT-4V / Gemini Pro），則不同 API 版本或提示詞（prompt）細微差異可能導致結果波動。建議作者一併釋出：

- 完整的提示詞模板。
- 事件分割與模式挖掘的參數設定。
- 各基準測試的評估腳本與預處理流程。

---

#### 未來研究方向

GROVE 開啟了數個值得後續探索的方向：

1. **學習式記憶鞏固**：目前為免訓練設計，未來可引入輕量適應機制，讓系統從使用者回饋中學習如何分割事件、合併模式。
2. **多模態記憶擴展**：整合音訊、慣性測量單元（IMU）、生理訊號等，讓記憶不僅限於視覺。
3. **個人化與隱私保護**：研究如何在裝置端（on-device）執行記憶建構，並透過差分隱私或聯邦學習保護長期個人資料。
4. **主動介入的評估方法論**：現有基準多聚焦於問答正確率，未來需要更細緻的指標來衡量「何時提醒」與「是否打擾」之間的權衡。
5. **因果與反事實推理**：讓系統不只能回憶「發生了什麼」，還能推論「如果當時做了不同選擇會如何」。
6. **跨使用者模式遷移**：在保護隱私前提下，利用群體層級的跨日模式來輔助新使用者的記憶初始化。
7. **與機器人執行整合**：將 GROVE 的記憶介面擴展到實體助理，讓主動協助不僅是提醒，還能驅動實際動作。

## 論文問答

**Q1：GROVE 旨在解決什麼核心問題？**

A：GROVE 旨在解決穿戴式助理同時需要「回答過去視覺歷史」與「主動判斷何時該提供協助」的雙重需求。現有影片記憶系統大多只能被動等待使用者查詢，而主動式助理又常使用獨立的記憶與控制機制，兩者無法共享同一套經驗。GROVE 提出一個免訓練框架，讓單一個連續影片串流所長成的記憶，能同時支撐反應式問答與主動式協助，從而讓助理的過去經驗真正變得可搜尋且可付諸行動。

**Q2：為什麼現有的影片記憶系統無法滿足穿戴式助理的需求？**

A：現有系統大多遵循「問題條件式召回」的契約，也就是必須等到使用者明確提問才會去檢索過往證據，這使得它們難以主動察覺當前情境是否需要介入。另一方面，現有的主動式助理雖然能依據當前情境觸發服務，但其記憶與控制機制通常是分開設計，並非為開放式回憶所打造。因此，這些方法無法讓「被動回答」與「主動提醒」共享同一個結構化、可推理的記憶介面，限制了助理在長時間尺度上的連貫性與實用性。

**Q3：為什麼「時間尺度」是 GROVE 設計的關鍵出發點？**

A：穿戴式助理所需的證據本質上具有不同的時間尺度：物體狀態或計數可能只持續數秒，活動會延續數分鐘，而跨日重複模式則需要數天才能浮現。若將所有觀察視為同質記錄，就會迫使單一檢索操作去恢復性質截然不同的證據，效率與準確度都會下降。GROVE 因此以時序分層作為記憶組織原則，讓每個尺度對應不同的資訊類型與最適合的存取方式，使檢索能夠對準正確的時間粒度。

**Q4：GROVE 的核心方法架構是什麼？**

A：GROVE 是一個免訓練框架，會從連續影片串流中因果地增長出一套時序分層記憶。每個到達的影片視窗會經過兩條互補的感知通道：一條產生敘事式字幕，另一條建立結構化的感知登錄，包含實體、屬性、明確計數、動作與畫面文字。這些觀察會被遞增式鞏固為時間戳記時刻、連貫片段，以及跨片段的跨日重複模式，並為每個層級配備尺度原生檢索技能。

**Q5：GROVE 的主要創新之處有哪些？**

A：GROVE 的主要創新在於將時間尺度直接作為記憶儲存與讀取之間的介面，而非僅把分層當作壓縮手段。它提出了四種尺度原生檢索技能——感知查詢、時刻召回、片段重播與模式遍歷——讓多輪代理能根據問題或情境組合這些技能，並累積非冗餘證據。此外，反應式問答與主動式協助共享同一個記憶與存取介面，這種統一設計突破了過去必須分開建構記憶與控制機器的做法。

**Q6：GROVE 如何讓反應式問答與主動式協助共用同一套記憶？**

A：兩種行為的差異只在於檢索是由使用者查詢還是由當前情境所觸發，底層記憶與存取介面完全相同。在反應式問答中，代理會執行「決定—檢索—回答」迴圈，選擇需要哪種尺度與類型的證據；在主動式協助中，則由前向請求或當前感知狀態啟動相關時刻、片段與模式的檢索，再決定是否以及何時介入。這種設計讓同一個不斷成長的視覺歷史，能同時服務於「拉取」過去證據與「推送」及時服務兩種需求。

**Q7：GROVE 在哪些基準測試上進行評估？**

A：GROVE 在 MM-lifelong、EgoServe、OVO-Bench、StreamingBench、StreamBridge 與 ESTP-Bench 等多個基準上進行評估。這些測試涵蓋了超長期記憶、即時感知、向後追溯、前向主動回應、情境式查詢以及主動服務等不同能力。透過這些多樣化的測試，論文驗證了 GROVE 在長時間跨度的影片理解與主動協助上的綜合表現。

**Q8：GROVE 取得了哪些關鍵實驗結果？**

A：在包含極具挑戰性的 MM-lifelong 與 EgoServe 在內的多個基準上，GROVE 相較於 GPT、Gemini、Qwen、ReMA、EgoMemo、EPT、MiniCPM-V 與 IPT 等對比方法取得了最佳結果。這顯示單一個時序分層記憶不僅能支撐反應式問答，也能有效支援主動式協助。整體而言，GROVE 證明了以時間尺度組織串流經驗，是提升長期影片理解與實用助理能力的有效途徑。

**Q9：消融實驗揭示了什麼？**

A：受控消融實驗顯示，各個時序層級與其對應的尺度原生檢索技能具有互補性，移除任一層都會導致性能下降。其中，跨日重複模式在證據橫跨多天時帶來最大的效益，因為這類長程規律性無法從單一畫面或事件中直接觀察到。這些結果強調了時序分層並非多餘的設計，而是讓系統能根據問題所需的時間範圍，精準調用不同記憶層級的關鍵機制。

**Q10：GROVE 可應用於哪些實際情境？**

A：GROVE 可應用於智慧眼鏡等穿戴式裝置，協助使用者尋找遺失物品，例如回答「我昨天把鑰匙放在哪裡？」這類問題。它也能根據跨日重複模式主動提醒日常慣例，或在使用者即將重複過去錯誤時發出警示。此外，在即時感知層面，GROVE 能結合當前情境與過去經驗，提供及時且脈絡相關的協助，讓穿戴式助理從被動工具轉變為主動的生活夥伴。

**Q11：若將 GROVE 產品化，需要考慮哪些因素？**

A：產品化時首先必須面對連續錄影所帶來的隱私與資料安全問題，需要讓使用者能清楚掌控哪些內容會被記憶與檢索。其次，長時間維護多層級記憶會帶來儲存與計算成本，必須設計高效的增量更新與壓縮機制。不過，GROVE 的免訓練特性降低了部署門檻，使其更容易整合到現有的多模態大型語言模型或穿戴式裝置平台中。

**Q12：GROVE 對相關研究領域可能帶來什麼影響？**

A：GROVE 展示了反應式檢索與主動式協助可以在單一架構中統一，這可能改變未來影片記憶系統的設計範式。它強調時間尺度應成為串流經驗組織的核心原則，而非僅將記憶視為均勻的片段集合。這種以尺度為介面的思路，也可延伸至具身智慧代理、長期機器人記憶，以及其他需要持續學習與回憶的互動式 AI 系統。

**Q13：GROVE 目前可能存在哪些限制？**

A：作為一個免訓練框架，GROVE 的表現在很大程度上仰賴底層多模態感知模型的品質，若感知登錄或字幕產生錯誤，後續的記憶組織與檢索也會受到影響。此外，雖然它能線上建構跨日重複模式，但對於極度不規律或罕見的事件，模式挖掘可能不夠穩健。目前架構也較少討論如何隨著使用者互動進行個人化適應，這可能是進一步提升實用性的重要方向。

**Q14：GROVE 在哪些情況下可能會失敗？**

A：當畫面中物體被嚴重遮蔽、光線不足，或場景中存在外觀極為相似的物品時，感知登錄可能產生錯誤，導致後續檢索失準。在主動式協助方面，若當前情境與過去經驗的相似度判斷過於寬鬆，可能出現不必要的打擾或錯誤提醒。另外，對於剛建立不久、尚未形成穩定跨日重複模式的新習慣，系統也難以依賴長期模式層級進行有效推理。

**Q15：GROVE 未來可以朝哪些方向發展？**

A：未來可以探索在保持免訓練優勢的前提下，加入輕量化的使用者適應機制，使記憶更能反映個人化的生活模式。也可以進一步強化跨日重複模式的挖掘演算法，讓系統在面對不規律行程時仍能保持穩健。此外，將 GROVE 擴展到更多模態輸入，例如音訊、生理訊號或環境感測器，並加強隱私保護與使用者控制介面，將有助於打造更完整、更值得信賴的長期穿戴式助理。

## 實務應用指南

### 適用場景

**1. 智慧眼鏡日常生活助理**
使用者配戴智慧眼鏡數小時至數週，GROVE 可回答「我昨天把鑰匙放哪了？」等反應式問題，也能在使用者即將重複遺忘動作時主動提醒。時刻層級保留細粒度觀察、片段層級重播活動流程、模式層級捕捉跨日習慣，三者互補支撐超長期視覺歷史問答。

**2. 工業維修與製造 SOP 遵循**
從技術人員第一人稱視角串流擷取作業畫面，系統可於當下主動提示「此步驟上週曾導致異常」或「螺絲鎖附順序與標準流程不符」。片段層級重播過往維修紀錄，模式層級則彙整跨班次重複出現的作業規律，降低人為疏失。

**3. 長期照護與用藥提醒**
針對銀髮族或慢性病患，GROVE 可追蹤「今天是否已服藥」「上週跌倒發生在何處」等事件，並於固定作息時間主動發出提醒。跨日重複模式能學習個人作息，減少無效打擾，同時保留關鍵時刻供照護者回溯。

**4. 技能學習與訓練回顧**
在烹飪、運動教學或醫學訓練中，學員可事後詢問「老師示範切菜手法的片段」，系統透過片段重播與時刻定位快速找出對應畫面；教練端則可透過模式層級觀察學員反覆出現的錯誤模式。

**5. 零售與客戶服務現場支援**
門市人員透過穿戴裝置串流店面狀況，GROVE 可主動提示「此貨架昨日已盤點」或「該顧客上週詢問過的商品規格」。反應式查詢與主動協助共用同一記憶介面，減少重複勞動。

### 實作前置條件

**資料條件**
- 連續第一人稱或固定視角影片串流，建議具備時間戳記與基本中繼資料。
- 領域知識：需預先定義常見實體、屬性、動作與文字類別，用於結構化感知登錄。
- 隱私合規資料治理：因涉及長期個人影像，需具備去識別化、留存期限與使用者授權機制。

**運算條件**
- 多模態大型語言模型（MLLM）推論能力：論文使用 GPT、Gemini、Qwen 等級模型進行敘事字幕生成與推理。
- 向量資料庫與檢索系統：用於時刻、片段、模式三層級的語意索引。
- 串流處理管線：需支援視窗化擷取、線上記憶鞏固與因果更新，避免等新影片到齊後才批次處理。
- 邊緣—雲端混合部署：即時感知與主動提醒對延遲敏感，建議邊緣執行輕量感知；長期模式學習與複雜推理可放雲端。

**技能條件**
- 熟悉 MLLM 提示工程與結構化輸出（JSON / schema）。
- 具備 Agent 編排經驗，能設計多輪檢索與非冗餘證據累積邏輯。
- 了解向量檢索、時間序列分群與事件偵測。
- 具備隱私與安全工程實務，尤其是生物特徵與場所影像的保護。

### 實作步驟建議

**步驟一：界定場景與記憶需求**
先決定目標使用者會問什麼、系統應在何時主動介入。據此劃分哪些資訊屬於「時刻」（秒級觀察）、「片段」（分鐘級活動）、「模式」（跨日規律）。

**步驟二：建立影片擷取與視窗化管線**
將連續串流切分為不重疊或滑動視窗，每個視窗同步輸出敘事字幕與結構化感知登錄（實體、屬性、數量、動作、畫面文字）。

**步驟三：設計雙通道感知模組**
- 敘事字幕通道：描述「誰在做什麼、在哪裡、發生什麼事」。
- 結構化登錄通道：抽取可驗證的事實，例如物體名稱、顏色、位置、數量變化。
兩者互補，前者利於語意檢索，後者利於精確定位與防幻覺。

**步驟四：建構三層級記憶與因果鞏固**
- 時刻層：保留每個視窗的字幕、結構化登錄與時間戳。
- 片段層：依活動連貫性將相鄰時刻合併為事件，產生摘要與關鍵影格。
- 模式層：跨片段偵測重複行為、地點、時間或物件組合，並以摘要形式儲存。
所有更新必須因果進行：新影片到達時只增量更新，不可事後重算歷史。

**步驟五：實作四種尺度原生檢索技能**
- 感知查找（Perception Lookup）：在時刻層定位特定觀察。
- 時刻召回（Moment Recall）：找出符合條件的單一畫面或短片段。
- 片段重播（Episode Replay）：回顧完整活動流程。
- 模式遍歷（Pattern Traversal）：探索跨日規律並回答「通常」「習慣」類問題。
每種技能應對應不同的索引與提示模板。

**步驟六：設計反應式與主動式控制策略**
- 反應式：使用者查詢 → 判斷所需證據尺度 → 呼叫對應檢索技能 → 生成答案。
- 主動式：當前情境輸入 → 檢索相關時刻、片段、模式 → 判斷是否介入、何時介入、以何種形式提醒。
兩者共用同一記憶與檢索介面，差異僅在觸發訊號。

**步驟七：評估與迭代**
先在 MM-Lifelong、EgoServe、OVO-Bench、StreamingBench 等公開基準驗證核心能力，再於真實場域進行 A/B 測試，特別關注主動提醒的精確率與打擾率。

### 潛在風險與注意事項

**隱私與資料安全**
第一人稱長期影片極度敏感，可能記錄他人面容、對話、醫療行為與私人空間。建議採用端上處理、差分隱私、聯邦學習或本地優先儲存，並提供使用者一鍵刪除與檢視記憶內容的功能。

**幻覺與記憶污染**
MLLM 在生成字幕、摘要與模式時可能產生虛構事實，並在後續檢索中被當成證據反覆引用。應保留原始結構化登錄作為可驗證來源，並在答案生成時標註證據來源的時間戳與原始影格。

**即時延遲**
主動協助對延遲敏感，若每次觸發都遍歷長期模式，可能錯過介入時機。建議將即時感知與短期時刻保留在邊緣，模式層推理採非同步背景更新，並設計快速路徑（fast path）處理高優先提醒。

**儲存與運算成本**
數日甚至數週的影片與多層級記憶會快速膨脹。需設計壓縮、去重與遺忘機制，例如只保留關鍵影格與摘要，原始影片依政策定期刪除。

**模式漂移與過時規律**
使用者習慣會改變，跨日模式可能過時。應為每個模式記錄最後觀察時間與置信度，並定期降權或淘汰久未出現的規律。

**主動打擾與信任**
過度主動提醒會降低使用者信任。建議引入明確的介入門檻與使用者回饋迴路，讓系統學習個人對提醒頻率與時機的偏好。

### 與其他技術的整合建議

**與現有 RAG 系統整合**
GROVE 的三層級記憶可視為具時間結構的 RAG 資料來源。將時刻、片段、模式分別索引為不同集合，檢索時依查詢類型路由至對應集合，再透過 MLLM 生成答案。

**與 LLM Agent 框架整合**
可將四種檢索技能封裝為 Agent 工具（Tools），由 ReAct、LangGraph 或類似框架統一排程。反應式與主動式控制策略則對應不同的 Agent 工作流。

**與穿戴式作業系統整合**
建議將感知擷取與短期記憶部署於裝置端或邊緣閘道，長期模式學習與複雜問答放雲端。透過作業系統通知 API 發送主動提醒，並利用裝置感測器（GPS、加速度計）輔助事件分段。

**與企業知識庫整合**
在工業或醫療場景，可將 SOP、藥品資料、設備規格等外部知識與 GROVE 的個人經驗記憶結合，形成「個人經驗＋組織知識」的混合檢索架構。

**與隱私增強技術整合**
結合同態加密、安全多方計算或可信執行環境，讓雲端能檢索與推理加密後的記憶，降低資料外洩風險。

### 給不同背景讀者的閱讀建議

**給初學者**
先從「為什麼需要分層記憶」開始理解：人類記憶本來就有片段與語義之分，GROVE 把這個概念搬到影片助理上。重點看三層級（時刻、片段、模式）與兩種行為（反應式問答、主動協助）如何對應日常生活場景，技術細節可暫時略過。

**給 AI 工程師**
請聚焦於雙通道感知設計、四種檢索技能的實作細節，以及多輪 Agent 如何組合技能並累積非冗餘證據。特別注意「因果更新」在串流系統中的工程意義，以及主動式控制策略的延遲與觸發門檻設計。

**給研究人員**
本文核心貢獻在於以「時間尺度」作為記憶組織與檢索的介面，並將反應式與主動式行為統一於同一記憶架構。建議深入探討時序分層的理論基礎、跨日模式抽取方法，以及 MM-Lifelong 與 EgoServe 等基準所揭示的長期記憶挑戰。

**給產品經理**
本框架的價值在於用單一記憶同時支援「使用者問了才回答」與「系統主動提醒」兩種高價值互動。評估時請同時看準確率與使用者體驗指標（打擾率、信任度），並優先處理隱私合規、儲存成本與邊緣延遲等商業化落地議題。
