# TRACE：MoE 語言模型 FP4 強化學習之推出引導式量化感知訓練

**原文標題：** TRACE: Rollout-Guided Quantization-Aware Training for FP4 Reinforcement Learning of MoE Language Models

## ⚡ TL;DR

現有 FP4 強化學習方法獨立優化兩條量化路徑，無法降低訓練與推出差異，導致 MoE 策略不匹配。
本文提出 TRACE，以推出端量化結果引導訓練端 FP4 捨入，並選擇性快取深層資訊以降低通訊開銷。
TRACE 在四款 MoE 模型上以 FP4 推出，效能逼近 BF16 並達 5.4 倍加速。

## 摘要翻譯

大型語言模型 (LLMs) 後訓練的強化學習 (RL) 在推出生成過程中帶來大量的計算和記憶體開銷，這促使採用低精度推出以實現高效的強化學習訓練。然而，現有的 FP4 強化學習方法存在一個關鍵限制：它們主要獨立優化訓練和推出路徑上的量化精度，而非直接減少兩條量化執行路徑之間的差異。在本工作中，我們提出了 TRACE（透過緊湊引導實現訓練-推出量化對齊），這是一個用於混合專家模型 (MoE) 語言模型強化學習訓練的 FP4 量化框架，克服了現有 FP4 強化學習方法的局限性。TRACE 採用推出引導式量化感知訓練，利用推出端量化結果來指導訓練端 FP4 捨入決策，直接減少訓練-推出差異。此外，TRACE 採用了一種高效的量化資訊快取方案，選擇性地保留較深層的尾數和縮放因子資訊，以減少推出引導所帶來的儲存和通訊開銷。我們在四個大規模 MoE 語言模型上，針對推理、程式碼及長時程強化學習任務評估 TRACE。實驗結果顯示，TRACE 能夠實現聯合 FP4 權重/激活和 FP4 KV 快取推出，其強化學習效能與 BF16 推出相當，同時相比於 BF16 訓練策略的後置式 FP4 量化，達到高達 5.4 倍的推出加速比，並具有優異的最終 FP4 效能。

### 核心貢獻（3～5點）
- **問題釐清**：指出現有 FP4 強化學習方法的根本缺陷——僅獨立優化訓練與推出路徑上的量化精度，未直接減少兩條量化執行路徑之間的差異。
- **TRACE 框架**：提出專為 MoE 語言模型強化學習訓練設計的 FP4 量化框架，實現訓練-推出量化對齊（Train-Rollout Quantization Alignment via Compact GuidancE）。
- **推出引導式量化感知訓練**：利用推出端量化結果指導訓練端 FP4 捨入決策，直接降低訓練-推出差異，提升策略一致性。
- **量化資訊快取機制**：透過選擇性保留較深層的尾數與縮放因子資訊，有效降低推出引導所引入的儲存與通訊開銷。
- **實驗驗證**：在四個大規模 MoE 模型上，於推理、程式碼及長時程強化學習任務中實現聯合 FP4 權重/激活與 FP4 KV 快取推出，效能媲美 BF16 推出，並達到最高 5.4 倍推出加速比。

### 適合對象
- 從事大型語言模型量化與高效推論研究的學者與工程師
- 專注於混合專家模型 (MoE) 訓練與部署最佳化的研究人員
- 投入後訓練強化學習（特別是長時程推理與程式碼任務）的實務工作者
- 關注低精度（FP4）訓練與推論一致性、數值穩定性議題的硬體與系統研究者
- 尋求降低強化學習推出階段計算與記憶體成本之業界團隊

## 深度分析

#### 方法論解析

TRACE 的方法論核心在於解決一個被既有 FP4 RL 方法忽略的根本性問題：**量化精度（quantization accuracy）與訓練-推出差異（train-rollout discrepancy）之間的錯位（misalignment）**。傳統方法（如 vanilla QAT、QaRL、QUADS、Rollout-ResQ）雖然在訓練路徑與推出路徑上各自降低量化誤差，但兩條量化執行路徑（quantized execution paths）之間的數值分歧仍然可能很大，導致策略不匹配（policy mismatch）甚至訓練崩潰（training collapse）。

**核心機制一：推出引導式量化感知訓練（Rollout-Guided Quantization-Aware Training）**

此機制的關鍵在於「直接對齊」而非「間接對齊」。具體做法是：在推出階段（rollout phase）使用 FP4 MoE Kernel 與 FP4 KV 量化產生 rollout-side quantization outcomes（量化結果），將其量化後的尾數（mantissa）與縮放因子（scale）資訊「傾印（dump）」出來；在訓練階段（training phase）載入（load）這些資訊，並透過 Fake Quant 與 Adjust Rounding 機制調整訓練端的 FP4 捨入決策（rounding decisions），使訓練端的量化值主動向推出端的量化值靠攏。這是一種「以推出端為錨點（anchor）」的設計哲學，與傳統 QAT「以高精度表示為錨點」形成鮮明對比。

從 Figure 2 的架構圖可看出，TRACE 在 rollout 階段採用 FP4 MoE Kernel 與 FP4 KV Quant，但在 attention 部分仍保留 BF16 Attention Kernel 搭配 BF16 KV（這暗示 KV cache 的量化可能僅在 decode 階段或特定層進行，需注意此細節）。訓練階段則透過 BF16 MoE Kernel 配合 BF16 Activation，但在線性運算前插入 Fake Quant 與 Adjust Rounding 模組，使前向傳播的數值軌跡與 rollout 階段對齊。

**核心機制二：量化資訊快取（Quantization-Information Caching）**

若將每一層、每一個 token 的尾數與縮放因子全部保留，會帶來巨大的儲存開銷（storage overhead）與通訊開銷（communication overhead），這在分散式 RL 訓練中尤其致命。TRACE 的解法是**選擇性保留（selective retention）較深層（deeper layers）的資訊**。此設計背後的假設是：較淺層的特徵較為通用、冗餘度高，捨入決策對最終策略影響較小；而較深層的特徵與任務高度相關，其捨入邊界（rounding boundary）的微小偏移會被 MoE 路由器（router）放大，造成專家路由（expert routing）的分歧。因此保留深層資訊能以較低的儲存成本換取最大的對齊效益。

此設計呼應了 MoE RL 訓練中已知的「路由敏感性」問題——Zheng et al. (2025a) 指出，MoE 模型中微小的數值差異會改變路由器評分，啟動不同的專家，進而放大策略不匹配。TRACE 透過深層資訊保留與推出引導，恰好在最容易出錯的環節進行對齊。

**方法論的理論意涵**

TRACE 隱含了一個重要的觀點：對於 RL 後訓練（post-training）場景，**訓練-推出一致性（train-inference consistency）比單純的量化精度更重要**。這與監督式訓練的 QAT 哲學不同——在監督學習中，我們關心模型輸出與真實標籤的差距；但在 RL 中，我們關心 rollout 收集的軌跡（trajectories）所估計的優勢（advantage）是否與訓練時的策略一致。Figure 1 的實驗結果支持此觀點：TRACE 在初期表現略遜於 BF16 rollout，但隨著訓練進行，策略逐漸「適配（adapt）」FP4 rollout，最終在 step 240 達到與 BF16 rollout 匹配的表現，甚至在某些指標上反超。

#### 實驗數據解讀

**模型與任務覆蓋面**

論文在四個大規模 MoE 語言模型上進行評估：Qwen3.5-35B-A3B、Qwen3.5-122B-A10B、Qwen3.8-Flash-Next、Qwen3.8-2.4T-A95B，涵蓋推理（reasoning）、程式碼（coding）與長時程 RL 任務（long-horizon RL tasks）。模型規模從 35B 參數（啟動 3B）一路擴展到 2.4T 參數（啟動 95B），展現了方法在不同 MoE 稀疏度下的可擴展性。

**Figure 1 的關鍵發現**

(a) 訓練-推出對數機率差異（Train-Rollout Log-Prob Diff）：傳統 NVFP4 QAT 的 Max Log-prob Diff 隨訓練步驟持續上升至約 2.0，而 TRACE 始終維持在 1.2 左右，差距顯著。(b) Terminal-Bench 2.1 測試分數：QAT 的 Mean Score 在訓練過程中從 0.60 退化至 0.45，而 TRACE 穩定維持在 0.60 附近。(c) 低精度適配（Low-Precision Adaptation）：TRACE 在 step 240 首次匹配 BF16 rollout 的表現，證明了「先經歷暫時性退化、再逐步適配」的訓練動態（training dynamics）。

**加速比與效率**

TRACE 達到最高 **5.4× rollout speedup** 相比 BF16 rollout，這對於 RL 訓練中 rollout generation 佔據主要計算與記憶體開銷的場景意義重大。值得注意的是，TRACE 在引入推出引導機制後仍能維持此加速比，說明其量化資訊快取設計有效控制了演算法開銷。

**與後置式量化的比較**

論文聲稱 TRACE 在最終 FP4 任務效能（final FP4 task performance）上優於「先以 BF16 rollout 訓練、再施加後置式 FP4 量化（post-hoc FP4 quantization）」的管線。這暗示了一個反直覺的結論：**在 RL 場景中，從一開始就以 FP4 rollout 訓練並透過 TRACE 對齊，可能比先用 BF16 訓練再量化部署更有效**。這可能是因為 RL 的策略分佈會在訓練過程中持續演化，後置式量化無法捕捉訓練過程中的動態特性。

**實驗設計的侷限（從可見內容推斷）**

由於完整文本未提供所有 baseline 的具體數值表格，無法精確量化 TRACE 相對於 QaRL、QUADS、Score Centering 的改進幅度。此外，論文未明確說明 RL 演算法的具體變體（GRPO、GSPO 或其他），也未揭露獎勵設計（reward design）細節，這些對重現性至關重要。

#### 與現有研究的比較

**與 FP8/INT8 RL 方法的比較**

QuRL（Li et al., 2026）採用自適應裁剪（adaptive clipping）與更新感知量化（update-aware quantization）來減少訓練-推出不匹配，但僅限於 8-bit 精度。Jet-RL（Xi et al., 2026）採用統一 FP8 計算流。TRACE 將此思路推向更激進的 4-bit 精度，並透過推出引導機制實現更精細的對齊。

**與既有 FP4 RL 方法的比較**

- **QeRL（Huang et al., 2025）**：主要考慮 4-bit 權重量化搭配更高精度激活值，屬於較保守的路徑。TRACE 進一步將激活值也量化至 FP4，並加入 KV cache 量化，覆蓋面更廣。
- **QUADS（Zhuge et al., 2026）**：結合非對稱 QAT 與推出端激活補償（rollout-side activation compensation）。TRACE 與之不同在於直接對齊兩條執行路徑，而非分別補償。
- **Rollout-ResQ（Mak et al., 2026）**：以稀疏殘差（sparse residuals）修正 FP4 rollout 誤差。TRACE 不引入額外殘差運算，而是從捨入決策層面對齊。
- **QaRL（Gu et al., 2026）**：透過匹配的 low-precision kernels 對齊訓練與推出。TRACE 與之最為接近，但 QaRL 屬於「kernel-level matching」，TRACE 屬於「rounding-level guidance」，後者的對齊粒度更細。

**與 MoE RL 路由對齊方法的比較**

R3（Ma et al., 2025）透過 replay rollout routing decisions 來緩解路由不匹配；PR2（Dong et al., 2026）進一步考慮跨策略更新的路由器演化。TRACE 與這些方法正交——R3/PR2 處理的是「路由決策一致性」，TRACE 處理的是「路由前的數值一致性」。兩者可互補：TRACE 從源頭減少數值分歧，R3/PR2 在路由層面提供額外保障。

**與優化層級修正方法的比較**

Score Centering（Marek and Ryabinin, 2026）透過修正訓練-推論不匹配引起的優化漂移（optimization drift）來穩定 RL，但並不直接對齊底層的低精度運算。TRACE 屬於「運算層級對齊」，Score Centering 屬於「優化層級修正」，兩者解決問題的層次不同。

**TRACE 的獨特優勢**

1. **直接對齊而非間接補償**：從捨入決策層面消除分歧，而非事後修正。
2. **深層選擇性保留**：在儲存成本與對齊效益間取得平衡。
3. **覆蓋 W/A + KV 的聯合 FP4**：比僅量化權重或僅量化激活的方法更激進。
4. **適配動態的發現**：揭示了 RL 策略可逐步適配 FP4 rollout 的現象，這對實務部署有重要啟示。

**潛在限制**

- 推出引導需要 rollout 階段與訓練階段之間的額外通訊，可能在某些分散式架構下引入同步瓶頸。
- 深層選擇性保留的啟發式（heuristic）設計缺乏理論保證，最優保留策略可能因模型而異。
- 對於非 MoE 的 dense 模型，TRACE 的效益可能較不明顯（因為缺少 MoE 路由放大效應）。

**超參數與訓練細節**

論文未提供完整的超參數（hyperparameter）清單，包括：

FP4 量化需要 NVIDIA Hopper 或更新架構的 GPU（如 H100、B200）以利用 Tensor Core 的原生 FP4 支援。5.4× 加速比的實現高度依賴特定硬體與 kernel 最佳化，這限制了結果在不同硬體平台間的可移植性。

**重現性評等**

基於上述因素，TRACE 的完整重現屬於「中等難度」：方法論概念清晰，但實作細節（特別是分散式 rollout-training 同步、量化資訊快取的具體實作、與特定 RL 框架的整合）需要作者提供更多技術細節或開源程式碼才能可靠重現。

#### 未來研究方向

**1. 理論分析：訓練-推出差異的量化界**

目前 TRACE 的設計主要基於經驗觀察（深層保留、推出引導），缺乏對「訓練-推出差異」與「RL 收斂性」之間的理論刻畫。未來可探索：
- 在 FP4 量化下，train-rollout discrepancy 如何影響策略梯度（policy gradient）的偏差與方差？
- 是否存在最小的對齊粒度（alignment granularity），低於此粒度後對齊效益遞減？
- MoE 路由器的量化敏感性是否有可量化的理論上界？

**2. 動態適配機制**

Figure 1 揭示的「策略逐步適配 FP4 rollout」現象值得深入研究：
- 是否可以設計自適應的推出引導強度，在訓練初期提供強對齊、訓練後期逐步放鬆？
- 適配過程是否可透過課程學習（curriculum learning）加速？
- 不同 RL 階段（探索 vs. 利用）對推出引導的需求是否不同？

**3. 跨架構泛化**

TRACE 目前專注於 MoE 與 NVFP4 格式，未來可探索：
- 將推出引導機制擴展至 dense 模型、混合架構（hybrid architecture）或多模態模型
- 支援其他 FP4 格式（如 MXFP4、FP4 E2M1 的不同區塊大小）
- 與 INT4、INT8 等其他低精度格式的兼容性

**4. 與其他 RL 優化技術的整合**

TRACE 與多項正交技術有整合潛力：
- 結合 R3/PR2 的路由對齊機制，形成「數值對齊 + 路由對齊」的雙重保障
- 與 GSPO 的序列級重要性比率（sequence-level importance ratio）結合，進一步穩定訓練
- 整合分散式 RL 框架（如 verl、OpenRLHF）的通訊最佳化

**5. 硬體協同設計**

TRACE 的推出引導需要 rollout 與訓練階段之間的資訊交換，這對硬體與系統設計提出新需求：
- 設計支援 FP4 量化資訊高效傳遞的互連拓撲（interconnect topology）
- 探索 NVLink、RDMA 等高速互連下的最佳快取策略
- 與 NVIDIA Transformer Engine、DeepSpeed 等框架的深度整合

**6. 應用拓展：線上 RL 與持續學習**

TRACE 的對齊機制可能對線上 RL（online RL）與持續學習（continual learning）特別有價值：
- 在持續學習場景中，策略分佈持續漂移，train-rollout 一致性更難維持
- 線上 RL 中 rollout 與訓練交錯進行，TRACE 的快取機制需要重新設計以適應此節奏

**7. 可解釋性研究**

推出引導機制提供了觀察「哪些層、哪些 token 對量化最敏感」的工具。未來可利用此機制進行：
- FP4 量化的敏感性分析（sensitivity analysis）
- MoE 路由器在不同量化精度下的行為研究
- 量化誤差在模型中的傳播路徑分析

這些方向不僅能深化對 FP4 RL 的理解，也將推動整個低精度機器學習（low-precision machine learning）領域的理論與實務進展。

## 論文問答

**Q1：為什麼在 MoE 語言模型的強化學習後訓練中，rollout 階段的計算與記憶體開銷會成為關鍵瓶頸？**
A：強化學習後訓練需要反覆生成大量長軌跡（trajectories）來收集獎勵訊號，這個 rollout 階段在整體訓練流程中往往佔據最大的計算與記憶體負擔。對於 MoE 模型而言，雖然每次推論只啟動部分專家，但其總參數量極大，導致 KV 快取與權重的記憶體佔用非常高昂。因此，若能在 rollout 階段採用低精度（如 FP4）量化，就能同時降低計算量與記憶體佔用，進而提升整體 RL 訓練效率，這也是 TRACE 聚焦於 rollout 端量化的根本動機。

**Q2：現有的 FP4 RL 方法為何無法有效降低訓練與推出之間的策略不匹配？**
A：現有方法（如 vanilla QAT、QaRL、QUADS、Score Centering 等）主要分別優化訓練路徑與推出路徑各自的量化精度，使其各自逼近高精度表示。然而，量化精度高並不等於兩條量化執行路徑之間的差異小——即使兩者各自的量化誤差都很低，其量化後的數值仍可能因為 FP4 粗粒度的量化空間而產生顯著分歧。這種 train-rollout discrepancy 會導致重要性比率估計失準，進而引發策略不匹配、效能退化，甚至訓練崩潰，這正是 TRACE 欲解決的核心問題。

**Q3：為什麼 MoE 模型的 train-rollout 量化對齊問題比稠密模型更為嚴峻？**
A：在 MoE 模型中，路由器（router）會根據激活值的微小數值差異決定啟動哪些專家，因此即使是非常細微的量化誤差也可能改變專家路由決策，進而放大訓練與推出之間的策略差異。這種路由敏感性使得 MoE 模型在低精度 rollout 下特別容易出現效能不穩定的現象，也凸顯了 TRACE 這類直接對齊兩條量化路徑方法的重要性。

**Q4：TRACE 的核心方法「Rollout-Guided Quantization-Aware Training」是如何運作的？**
A：TRACE 的核心想法是利用 rollout 端的量化結果來引導訓練端的 FP4 捨入決策。具體而言，在 rollout 階段會記錄每一層量化後的尾數（mantissa）與縮放因子（scale），並在訓練階段將這些資訊回傳，用以調整訓練端的捨入邊界，使訓練端的量化結果盡可能對齊 rollout 端的量化結果。這種做法直接最小化兩條量化執行路徑之間的差異，而非僅僅最小化各自對 BF16 的誤差，從根本上解決了現有方法的對齊盲點。

**Q5：TRACE 的「Quantization-Information Caching」機制為何重要？其設計選擇的理由是什麼？**
A：若將每一層 rollout 端的量化資訊（尾數與縮放因子）全部儲存並回傳給訓練端，將會帶來巨大的儲存與通訊開銷，反而抵銷 FP4 rollout 帶來的效率優勢。TRACE 採用選擇性保留策略，只保留較深層（deeper layers）的量化資訊，因為這些層對最終策略行為的影響較大。這種「緊湊引導」（compact guidance）設計在維持對齊效果的同時，大幅降低了額外的演算法開銷，使 FP4 rollout 的加速效益得以保留。

**Q6：TRACE 在 rollout 階段採用 FP4 KV 快取，這個設計選擇帶來什麼權衡？**
A：FP4 KV 快取能進一步降低 rollout 階段的記憶體佔用，對於長序列、長時程任務尤其重要，因為 KV 快取的大小隨序列長度線性增長。然而，KV 快取的量化會引入額外的數值誤差，因此 TRACE 必須透過 rollout-guided QAT 來對沖這個誤差。實驗結果顯示，TRACE 能成功實現 joint FP4 W/A + FP4 KV rollout，並維持與 BF16 rollout 相當的 RL 效能，證明了這個權衡是值得的。

**Q7：TRACE 在哪些基準測試與模型上進行了評估？涵蓋哪些任務類型？**
A：TRACE 在四個大規模 MoE 語言模型上進行了評估，包括 Qwen3.5-35B-A3B、Qwen3.5-122B-A10B、Qwen3.8-Flash-Next 與 Qwen3.8-2.4T-A95B，涵蓋了不同規模的 MoE 架構。任務類型橫跨推理（reasoning）、程式碼（coding）以及長時程 RL 任務（long-horizon RL tasks，例如 Terminal-Bench 2.1），這樣的設計能全面驗證 TRACE 在不同應用場景下的泛化能力。

**Q8：TRACE 的關鍵實驗結果為何？它相較於 baseline 有哪些具體優勢？**
A：實驗結果顯示三項關鍵發現：第一，TRACE 能實現 joint FP4 W/A + FP4 KV rollout，並維持與 BF16 rollout 相當的訓練動態與最終任務效能；第二，TRACE 達到最高 5.4× 的 rollout 加速比，同時僅引入有限的演算法開銷；第三，TRACE 的最終 FP4 任務效能優於「先以 BF16 rollout 訓練、再後置式 FP4 量化」的管線，顯示其在低精度適應上的優勢。

**Q9：圖 1 所展示的「低精度適應」（Low-Precision Adaptation）現象有何啟示？**
A：圖 1 顯示 TRACE 雖然在訓練初期因量化而效能略低於 BF16 rollout，但隨著訓練進行，效能差距逐漸縮小並最終被追平甚至反轉。這說明一旦 train-rollout 差異被有效控制，策略模型能夠逐步「學會」在 FP4 rollout 下運作，展現出 RL 對低精度環境的自我適應能力。這是一個相當重要的觀察，意味著 FP4 rollout 不僅是節省成本的工具，也可能成為提升最終模型在低精度部署環境下表現的訓練策略。

**Q10：TRACE 適用於哪些實際部署場景？對產業應用有何價值？**
A：TRACE 特別適合需要大量 RL 後訓練來提升推理或程式碼能力的 MoE LLM 服務，例如程式碼助理、複雜任務代理（agent）以及長鏈推理應用。在這些場景中，rollout 成本往往是總訓練成本的主要組成部分，TRACE 提供的 5.4× 加速比能直接降低雲端 GPU 租用成本與訓練時間。此外，由於最終模型能在 FP4 精度下維持高效能，也為邊緣部署或低功耗推論場景提供了更流暢的部署路徑。

**Q11：將 TRACE 整合到現有 RL 訓練框架時，需要注意哪些工程考量？**
A：首先，TRACE 需要在 rollout 引擎與訓練引擎之間建立量化資訊（尾數與縮放因子）的傳輸通道，這對分散式訓練架構的通訊拓樸提出了額外要求。其次，選擇性保留較深層資訊的策略需要根據具體模型架構進行調整，淺層與深層的相對重要性可能因模型而異。此外，FP4 MoE kernel 與 BF16 attention kernel 的混合執行（如圖 2 所示）需要精細的記憶體管理，以避免量化資訊的 dump/load 成為新的瓶頸。

**Q12：TRACE 對低精度 RL 與高效 LLM 訓練領域的整體影響為何？**
A：TRACE 揭示了一個重要的方法論轉變：低精度 RL 的研究焦點應從「各自路徑的量化精度」轉向「跨路徑的量化對齊」。這個觀點不僅適用於 FP4，也可能推廣到 FP6、FP8 等其他低精度格式的 RL 訓練。此外，TRACE 證明了 aggressive quantization（如 W4A4 + FP4 KV）在 RL 場景下是可行的，這為未來更大規模、更低成本的 LLM 後訓練開闢了道路。

**Q13：TRACE 存在哪些已知的限制？**
A：根據論文描述，TRACE 的量化資訊快取策略僅保留較深層的資訊，這個選擇可能不適用於所有模型架構——某些模型可能在淺層就對量化敏感。此外，TRACE 主要針對 NVIDIA NVFP4 格式設計，其硬體假設可能限制在其他加速器（如 AMD 或自研晶片）上的可移植性。最後，雖然 TRACE 在四個 MoE 模型上驗證了泛化性，但對於極大規模（如超過兆級參數）的 MoE 模型，其有效性仍待進一步驗證。

**Q14：TRACE 在哪些情況下可能會失效或表現不佳？**
A：若 rollout 與訓練之間的硬體配置差異過大（例如使用不同架構的 GPU 或不同的並行策略），rollout 端的量化結果可能無法準確代表訓練端的執行環境，導致引導失效。此外，對於路由決策極度敏感的 MoE 模型，即使經過對齊，仍可能因為 FP4 的極粗粒度而無法完全避免專家路由分歧。在這種情況下，可能需要結合路由重放（routing replay，如 R3）或路由器演化追蹤（如 PR2）等技術來進一步穩定訓練。

**Q15：基於 TRACE 的研究成果，未來有哪些值得探索的研究方向？**
A：未來可探索的方向包括：將 TRACE 的對齊理念推廣到 FP6、FP8 等其他精度格式；研究自適應的層級選擇策略，根據模型敏感度動態決定哪些層需要保留量化資訊；將 TRACE 與路由器穩定化技術（如 R3、PR2）結合，以同時解決數值與路由兩個層面的不一致；以及探索 TRACE 在線上 RL（online RL）或多輪對話 RL 等更複雜訓練場景下的應用。這些方向都有望進一步推動高效 LLM 後訓練的發展。

## 實務應用指南

### 適用場景

1. **大型 MoE 模型的 RL 後訓練加速**：適用於 Qwen3.5-35B-A3B、Qwen3.8-Flash-Next 等百億至兆級參數 MoE 模型的 GRPO 等 RL 後訓練流程，特別是當 rollout 階段佔據整體訓練時間 60% 以上時，可透過 FP4 W/A + FP4 KV 量化獲得最高 5.4× 的推出加速。

2. **長時程程式碼生成代理訓練**：Terminal-Bench 2.1 等長時程程式碼任務中，模型需要生成數千個 token 的軌跡。TRACE 在這類場景下能維持 BF16 等級的訓練穩定性，避免傳統 FP4 QAT 造成的訓練崩潰。

3. **多專家路由敏感的推理模型微調**：當模型對專家路由決策極為敏感時（例如數學推理、競賽程式設計），TRACE 透過訓練-推出對齊減少路由不一致導致的策略不匹配，特別適合需要精細路由控制的場景。

4. **GPU 叢集資源受限的 RL 訓練環境**：在單節點或多節點 GPU 記憶體受限的情況下，FP4 量化可顯著降低 rollout 的記憶體佔用與通訊開銷，使原本需要 8 張 H100 的訓練可在 4 張上完成。

5. **需要快速迭代的 RL 實驗平台**：對於需要頻繁嘗試不同 reward function、prompt 或演算法變體的研究團隊，TRACE 提供的 5.4× 加速可將單次實驗週期從數天縮短至數小時，加速研究迭代。

### 實作前置條件

**資料需求**
- 高品質 RL 訓練資料集（如數學題、程式碼題、長時程任務），建議至少數萬至數十萬條 prompt-rollout 配對
- 預訓練好的 MoE 語言模型權重（BF16 格式），需支援 NVFP4 量化格式
- 評估基準（如 Terminal-Bench 2.1、程式碼基準、推理基準）用於驗證最終效能

**計算資源需求**
- NVIDIA Hopper 或更新架構 GPU（如 H100、B200），因為 NVFP4 量化仰賴 Tensor Core 原生支援
- 建議至少 4× H100 80GB 起步；訓練 Qwen3.8-2.4T-A95B 等兆級模型需要多節點叢集
- 高頻寬互連（NVLink、InfiniBand）以支援分散式 rollout 與訓練

**技能前提**
- 熟悉 PyTorch、Transformer 架構與 MoE 路由機制
- 具備 RL 後訓練經驗（GRPO、PPO 等演算法）
- 理解量化感知訓練（QAT）原理，包括 fake quantization、STE（Straight-Through Estimator）等概念
- 具備分散式訓練框架（Megatron、DeepSpeed）的使用經驗
- 熟悉 NVIDIA Transformer Engine 或類似的低精度訓練函式庫

### 實作步驟建議

**階段一：環境與基準建立（1-2 週）**
1. 在目標 MoE 模型上建立 BF16 rollout 的基準線，記錄 rollout 吞吐量、平均分數與訓練動態
2. 整合 NVFP4 量化 kernel（透過 Transformer Engine 或自訂 CUDA kernel），驗證 FP4 W/A 與 FP4 KV-cache 的正確性
3. 實作基本的 FP4 QAT pipeline 作為對照組

**階段二：TRACE 核心模組實作（3-4 週）**
1. 實作「推出引導式量化感知訓練」：在 rollout 階段收集量化後的尾數（mantissa）與縮放因子（scale），將其傳遞至訓練階段
2. 設計「捨入決策調整」機制：根據 rollout 端的量化結果調整訓練端的 FP4 捨入，使兩者的量化值對齊
3. 實作「量化資訊快取」：僅保留深層（deeper layers）的 mantissa 與 scale，淺層則重新計算，以降低儲存與通訊開銷
4. 設計快取選擇策略：透過消融實驗決定哪些層需要保留快取、保留的頻率為何

**階段三：整合與驗證（2-3 週）**
1. 將 TRACE 整合進 GRPO 訓練流程，確保 rollout 與訓練階段的資料流暢通
2. 在小型 MoE 模型（如 Qwen3.5-35B-A3B）上驗證訓練-推出對數機率差異（Log-prob Diff）是否收斂
3. 在 Terminal-Bench 2.1 等基準上驗證最終分數是否接近 BF16 rollout
4. 進行 rollout 速度基準測試，確認達到預期加速比

**階段四：規模化與優化（2-4 週）**
1. 將驗證成功的配置擴展至更大模型（Qwen3.8-Flash-Next、Qwen3.8-2.4T-A95B）
2. 優化通訊模式：將量化資訊快取與 rollout 結果打包傳輸，減少額外同步成本
3. 與其他 FP4 RL 方法（QaRL、QUADS、Score Centering）進行比較，建立內部基準
4. 與後置式 FP4 量化（vanilla NVFP4、4over6、H-Scale）比較最終 FP4 效能

**階段五：生產部署（持續）**
1. 建立監控儀表板，追蹤訓練-推出差異、rollout 吞吐量、模型分數等關鍵指標
2. 設定自動化回歸測試，確保模型更新後效能不退步
3. 將成功配置沉澱為內部標準流程，供後續模型訓練重複使用

### 潛在風險與注意事項

**風險一：訓練-推出差異控制失敗導致訓練崩潰**
- 緩解措施：密切監控 Log-prob Diff 指標，若差異持續擴大應立即回退至 BF16 rollout；可設定自動告警閾值
- 設計「安全模式」：當差異超過閾值時自動切換至 BF16 rollout，避免整個訓練 run 報廢

**風險二：量化資訊快取引入額外通訊開銷**
- 緩解措施：嚴格控制快取層數與保留頻率；只在深層保留關鍵資訊；使用壓縮傳輸
- 進行通訊 profiling，確認快取引入的開銷不超過 rollout 加速所節省的時間

**風險三：NVFP4 硬體依賴性**
- 緩解措施：保留 BF16 與 FP8 作為 fallback 路徑；在不支援 NVFP4 的硬體上自動降級
- 關注 NVIDIA 新一代 GPU 的 FP4 支援進度，適時更新 kernel

**風險四：MoE 路由不一致放大效應**
- 緩解措施：結合 R3（replay rollout routing）或 PR2（router evolution）等路由對齊技術
- 在訓練初期使用較保守的量化策略，隨訓練穩定後逐步放開

**風險五：與其他 RL 演算法的相容性**
- 緩解措施：TRACE 主要針對 GRPO 設計，若使用 PPO、DPO 等演算法需重新驗證
- 對 importance ratio clipping 等機制進行壓力測試，確保低精度不會破壞優勢估計

**風險六：評估基準的代表性不足**
- 緩解措施：除了論文中使用的基準外，應在內部業務場景的測試集上額外驗證
- 警惕「基準過擬合」：FP4 量化可能在某些基準上表現良好，但在真實分佈上失效

### 與其他技術的整合建議

**與分散式訓練框架整合**
- Megatron-LM：將 TRACE 的量化 kernel 整合進 Megatron 的 MoE 實作，利用其 tensor/pipeline/expert parallelism
- DeepSpeed：透過 DeepSpeed-MoE 結合 ZeRO-3，最佳化記憶體使用
- 建議：將 TRACE 設計為可插拔的量化後端，不修改原有訓練框架的核心邏輯

**與 RL 演算法整合**
- GRPO：原生相容，TRACE 可直接套用
- PPO：需驗證 critic 的低精度推導是否穩定，建議 critic 維持 BF16
- DPO：偏好學習對量化較不敏感，但仍需驗證
- 建議：將 rollout 量化與訓練量化解耦，rollout 端可積極使用 FP4，訓練端視演算法需求調整

**與推理引擎整合**
- vLLM、SGLang、TensorRT-LLM：將 TRACE 訓練出的 FP4 模型部署至這些推理引擎
- 建議：確保推理引擎支援 NVFP4 格式，否則需要轉換至其他 FP4 格式（如 MXFP4）

**與監控與可觀測性整合**
- 整合 Weights & Biases、MLflow 或 TensorBoard，追蹤訓練-推出差異隨時間的變化
- 建議：建立「量化健康度儀表板」，即時反映 rollout 與訓練的一致性

**與模型版本管理整合**
- 將 BF16 基準模型、FP4 QAT 模型、TRACE 模型統一管理
- 建議：使用 DVC 或類似工具追蹤不同量化策略的模型版本與對應效能

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的問題陳述，理解為什麼 RL 訓練中的 rollout 階段成本高昂，以及 FP4 量化為何能加速 rollout。重點關注 Figure 1 的訓練動態對比，直觀感受「訓練-推出差異」如何影響最終效能。暫時跳過技術細節，先建立「量化會引入訓練與推論不一致」這個核心概念，再回頭理解 TRACE 如何解決這個問題。

**給 AI 工程師**：直接從第 2 節的相關工作切入，了解現有 FP4 RL 方法（QaRL、QUADS、Rollout-ResQ、Score Centering）的設計取捨與限制。接著重點研讀 Figure 2 的系統架構圖，理解 rollout 與訓練階段的資料流（量化歷史、KV 快取、scale/mantissa 的 dump/load）。實作時應先建立 FP4 QAT baseline，再逐步加入 rollout-guided 機制與量化資訊快取，並透過 Log-prob Diff 指標驗證對齊效果。

**給研究者**：本論文的核心 insight 是「最小化各路徑的量化誤差 ≠ 最小化路徑間的量化差異」，這對量化研究社群有方法論上的啟發。建議深入分析 rollout-guided rounding 的理論基礎，探討是否可推廣至其他低精度格式（FP6、INT4）。此外，量化資訊快取的「選擇性保留」策略值得進一步研究，例如可嘗試基於層敏感度、token 重要性或路由熵的動態選擇機會。論文中觀察到的「policy 逐步適應 FP4 rollout」現象也值得從 RL 理論角度深入分析。

**給產品經理**：TRACE 的商業價值在於「用更低的硬體成本達成相同的模型品質」。具體而言，5.4× 的 rollout 加速意味著同樣的 GPU 叢集可以服務 5 倍以上的 RL 訓練任務，或將訓練成本降低 80%。在評估導入時，應關注三個關鍵指標：rollout 加速比、最終模型品質（與 BF16 baseline 的差距）、以及導入複雜度（是否需要更換硬體或大幅修改訓練流程）。建議先在非核心業務上小規模試點，驗證穩定性後再推廣至核心 RL 訓練 pipeline。
