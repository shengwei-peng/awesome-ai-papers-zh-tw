## 摘要翻譯

本文提出 ReactVAU，一個用於即時串流影片異常理解（streaming Video Anomaly Understanding, VAU）任務的快慢解耦架構（Slow-Fast Decoupled Framework）。現有的 VAU 方法採用離線推理（offline inference）並對整段影片進行全域時間取樣（global temporal sampling），違反因果性（causality），因而無法部署於即時監控串流（live surveillance streams）。相反地，通用串流影片模型（streaming video models）雖然滿足因果存取（causal access），但在記憶體壓縮（memory compression）過程中會稀釋罕見短暫異常（rare transient anomalies），並且常在漫長的正常區間（normal intervals）內均勻地呼叫重型多模態大型語言模型（heavyweight Multimodal Large Language Models, MLLMs）。ReactVAU 透過三個協同運作的元件彌補此缺口：一個基於空間網格折疊（Spatial Grid Folding, SGF）的輕量快速偵測模組（Fast Detection Module），以持續進行異常過濾（anomaly filtering）；一個異常感知持續記憶體（Anomaly-Aware Persistent Memory, AAPM），用於保護關鍵視覺線索（visual cues），避免其隨時間衰減（temporal decay）；以及一個重型的慢速推理模組（Slow Reasoning Module），在正常串流（normal streams）期間保持休眠，僅於可疑事件（suspicious events）發生時被喚醒，以進行語義驗證（semantic verification）與因果描述（causal description）。在多個基準資料集（benchmarks）上的大量實驗結果顯示，ReactVAU 能在嚴格的串流限制（streaming constraints）下運作，同時在異常偵測（anomaly detection）與因果推理（causal reasoning）兩方面均達到具競爭力的表現，並藉由最小化重型 MLLM 呼叫（heavyweight MLLM invocations），顯著提升運算效率（computational efficiency）。專案頁面（project page）請見 https://huiyuiui.github.io/React_VAU/。

### 核心貢獻（3～5點）
- 提出 ReactVAU，首個針對串流影片異常理解（VAU）任務的快慢解耦架構，可在嚴格串流限制下運作。
- 設計輕量快速偵測模組（Fast Detection Module）與空間網格折疊（SGF）技術，實現連續異常過濾。
- 提出異常感知持續記憶體（AAPM），主動保護關鍵視覺線索免於時間衰減。
- 採用事件閘控（event-gated）的重型慢速推理模組，僅於可疑事件發生時喚醒，顯著降低重型 MLLM 呼叫次數。
- 在多個基準資料集上達成具競爭力的異常偵測與因果推理表現，並顯著提升運算效率。

### 適合對象
從事智慧監控、影片異常偵測與理解、串流影片分析，以及多模態大型語言模型應用之研究者與工程師；特別適合關注即時性、因果性與可解釋性之讀者。

## 深度分析

#### 方法論解析

ReactVAU 的核心設計是一個 **Slow-Fast Decoupled Framework（快慢解耦架構）**，透過 **reactive event-gated mechanism（反應式事件閘控機制）** 將「高頻率、低語義」的異常過濾與「低頻率、高語義」的因果推理分離。整體架構可拆解為三個協同運作的元件：**Fast Detection Module（快速偵測模組）**、**Anomaly-Aware Persistent Memory（AAPM，異常感知持續記憶體）**，以及 **Slow Reasoning Module（慢速推理模組）**。

##### 1. Fast Detection Module 與 Spatial Grid Folding（SGF，空間網格折疊）

Fast Detection Module 的任務是對每一個進入系統的 **frame（影格）** 進行連續、輕量的異常分數估計。為了避免傳統方法中昂貴的 3D temporal modeling（時間建模），ReactVAU 提出 **Spatial Grid Folding（SGF，空間網格折疊）**，將短時間內的時序資訊重新編排成一個二維空間結構，從而把 **temporal anomaly detection（時間異常偵測）** 轉換為 **2D spatial reasoning（二維空間推理）** 問題。

具體而言，SGF 可能將連續數個影格的局部特徵按照空間位置攤平或折疊到一個網格中，使得模型能夠在單一前向傳播中同時觀察「哪裡」以及「最近是否出現異常動態」。這種設計的好處在於：

-  bypass heavy temporal modeling（避開重型時間建模），顯著降低每幀運算成本；
-  保留空間局部性，有利於定位異常發生的區域；
-  輸出連續的 **anomaly probability（異常機率）**，作為後續觸發 Slow Module 的依據。

當 Fast Module 偵測到的分數超過預設的 **trigger threshold（觸發閾值）** 時，系統才會將該事件標記為 **suspicious events（可疑事件）**，並喚醒沉睡中的 Slow Reasoning Module。

##### 2. Anomaly-Aware Persistent Memory（AAPM，異常感知持續記憶體）

在真實的 **live surveillance streams（即時監控串流）** 中，異常事件通常是 **rare transient anomalies（罕見短暫異常）**，而正常背景佔據絕大多數時間。一般 **streaming video models（串流影片模型）** 為了維持固定的記憶體上限，會對歷史上下文進行 **memory compression（記憶體壓縮）** 或 **token merging（詞元合併）**，導致稀疏的異常 **visual cues（視覺線索）** 被大量正常資訊稀釋，進而損害 **downstream threat perception（下游威脅感知）**。

AAPM 的設計目標是主動保護這些關鍵線索。它包含兩個核心機制：

- **Anomaly Priority Score（異常優先分數）**：根據 Fast Module 的異常分數、事件持續時間、與當前時刻的距離，以及可能的威脅等級，為每個記憶單元計算優先權重。分數越高的片段越不容易被壓縮或遺忘。
- **Threat-based Anomaly Pool（基於威脅的異常池）**：一個專門用於保存高優先級異常證據的記憶池。當系統進行連續的 **continuous context updates（連續上下文更新）** 時，正常背景會被常規壓縮，但異常池中的關鍵影格或特徵會被保留，避免 **temporal decay（時間衰減）** 造成的資訊遺失。

AAPM 讓 Slow Reasoning Module 在需要進行 **semantic verification（語義驗證）** 時，仍然能夠取得足夠的視覺證據，從而生成精細的 **causal description（因果描述）**。

##### 3. Slow Reasoning Module（慢速推理模組）

Slow Reasoning Module 是一個 **heavyweight MLLMs（重型多模態大型語言模型）**，負責高階語義理解與語言生成。與一般串流模型對每幀都呼叫 MLLM 不同，ReactVAU 的 Slow Module 在 **normal streams（正常串流）** 期間處於 **dormant（休眠）** 狀態，只有在 Fast Module 觸發後才會被 **awakened（喚醒）**。

被喚醒後，Slow Module 會接收：

- 當前可疑事件的視覺輸入；
- AAPM 中保存的相關歷史異常證據；
- 可能包含的任務提示，例如「判斷是否異常」或「描述事件原因」。

由於整個流程只依賴當前與過去的資訊，ReactVAU 在設計上即滿足 **causality（因果性）** 與 **causal access（因果存取）**，無需觀察 **future frames（未來幀）**。這是它能夠部署於真實 **real-world streaming surveillance environments（真實世界串流監控環境）** 的關鍵。

##### 4. 整體推論流程

在 **streaming inference（串流推理）** 階段，ReactVAU 的運作可概括如下：

1. 每一新進影格首先進入 Fast Detection Module，透過 SGF 快速計算異常分數；
2. 若分數低於 trigger threshold，則僅更新 AAPM 中的正常背景記憶，Slow Module 保持休眠；
3. 若分數超過閾值，則將該事件及其前後上下文寫入 AAPM 的 Anomaly Pool；
4. 系統喚醒 Slow Reasoning Module，對可疑事件進行 semantic verification 與 causal description；
5. 輸出異常判斷與自然語言解釋，並繼續監控後續串流。

這種 **event-gated（事件閘控）** 的設計大幅減少 **heavyweight MLLM invocations（重型 MLLM 呼叫）**，從而提升 **computational efficiency（運算效率）** 與 **real-time responsiveness（即時回應性）**。

#### 實驗數據解讀

由於提供的全文脈絡在 Method 章節後即截斷，未包含實驗表格與數值，因此本節先根據摘要與相關文獻慣例，說明 ReactVAU 可能採用的評估方式與數據意涵。

##### 1. 可能使用的基準資料集與設定

ReactVAU 聲稱在 **multiple benchmarks（多個基準資料集）** 上進行廣泛實驗。考量 Video Anomaly Understanding 領域的常見資料集，可能包含：

- **UCF-Crime**：長時未修剪影片，包含多種真實異常類別，常用於 frame-level anomaly detection（影格級異常偵測）；
- **XD-Violence**：大規模暴力與異常行為資料集，常搭配語言描述任務；
- **ShanghaiTech Campus**：校園監控場景，適合評估細粒度定位；
- 可能還包含針對 streaming 場景重新切分的 causal evaluation protocol，確保模型在測試時無法存取未來影格。

##### 2. 評估指標

實驗可能同時報告 **anomaly detection（異常偵測）** 與 **causal reasoning（因果推理）** 兩類指標：

- 偵測指標：**frame-level AUC-ROC**、**AP（Average Precision）**、**AR（Average Recall）**，衡量模型定位異常區間的能力；
- 語義指標：**BLEU-4**、**METEOR**、**CIDEr**、**ROUGE-L**，評估生成描述與人工標註的相似度；
- 效率指標：**latency（延遲，ms/frame）**、**FLOPs**、**GPU memory usage**、**heavyweight MLLM invocation frequency（重型 MLLM 呼叫頻率）**、**average trigger interval（平均觸發間隔）**。

##### 3. 結果意涵

摘要指出 ReactVAU 在嚴格 **streaming constraints（串流限制）** 下仍能達到與 **state-of-the-art offline models（最先進離線模型）** 相當的效能。這一點特別重要，因為離線模型可以觀察完整影片並進行 **global temporal sampling（全域時間取樣）** 或計算 **holistic anomaly density distributions（整體異常密度分佈）**，而 ReactVAU 僅能使用過去與當前資訊。若其偵測 AUC 與離線方法接近，代表 Fast Module 與 AAPM 有效地彌補了無法使用未來資訊的劣勢。

在效率方面，由於 Slow Module 只在異常觸發時運作，**normal intervals（正常區間）** 佔多數的監控影片中，實際 MLLM 呼叫次數會顯著低於 dense processing（密集處理）的基線。這意味著平均運算成本大幅下降，適合長時間運作的 **intelligent surveillance（智慧監控）** 系統。

不過，實驗數據也可能揭示一些權衡：

- 當異常事件密集發生時，Slow Module 被頻繁喚醒，可能出現延遲峰值；
- trigger threshold 的選擇會影響 false positive（誤觸發）與 false negative（漏觸發）之間的 trade-off；
- 語言生成品質可能受限於 AAPM 能保留的視覺證據量，若異常過於短暫，仍可能影響因果描述的完整性。

#### 與現有研究的比較

##### 1. 相較於傳統 Video Anomaly Detection（VAD）

傳統 **VAD（影片異常偵測）** 方法如基於重建或 **Multiple Instance Learning（MIL，多實例學習）** 的模型，主要輸出單一 **scalar（純量）** 的 **anomaly probability（異常機率）**。這類方法雖然能進行 **anomaly localization（異常定位）**，但本質上是 **black boxes（黑箱）**，缺乏 **semantic context（語義上下文）** 與 **semantic explainability（語義可解釋性）**。

ReactVAU 透過整合 MLLM，將偵測結果進一步轉化為自然語言的因果描述，實現從 VAD 到 **VAU（影片異常理解）** 的 **paradigm shift（典範轉移）**。

##### 2. 相較於離線 Video Anomaly Understanding（VAU）

現有頂尖 VAU 方法如 Holmes-VAU、VADER、VERA、PANDA、Unified 等，雖然在語言生成與因果推理上表現優異，但它們依賴 **offline inference（離線推理）**，必須觀察完整影片後才能進行 **global temporal sampling（全域時間取樣）** 或計算整體統計分佈。這種對 **future frames（未來幀）** 的 **absolute dependence（絕對依賴）** **breaks causality（破壞因果性）**，使其無法應用於 **real-world streaming surveillance environments（真實世界串流監控環境）**。

ReactVAU 的最大優勢在於：它在架構上即保證因果存取，無需等待未來資訊，因此可直接部署於 **live surveillance streams（即時監控串流）**。

##### 3. 相較於通用串流影片理解框架

近年來的 **streaming video understanding frameworks（串流影片理解框架）** 如 StreamForest、Dispider、StreamMind、MoniTor 等，透過 **KV-cache compression（KV 快取壓縮）**、**persistent memory（持續記憶體）** 或 **token merging（詞元合併）** 來處理 **infinite video streams（無限影片串流）**。然而，這些方法直接套用於異常領域時存在兩個 **critical flaws（關鍵缺陷）**：

- **異常特徵稀釋**：由於 **transient anomalies（短暫異常）** 的 **sparse visual features（稀疏視覺特徵）** 在連續記憶壓縮中容易被正常背景淹沒；
- **運算瓶頸**：對每個影格都呼叫 heavyweight MLLM 會造成 **prohibitive computational overhead（過高的運算開銷）**。

ReactVAU 透過 AAPM 主動保護異常證據，並以 event-gated 機制避免對正常區間進行昂貴推理，同時解決了這兩個問題。

##### 4. 相較於近期解耦與事件閘控架構

Dispider 與 StreamMind 等作品已提出 **decoupled and event-gated architectures（解耦且事件閘控架構）**，將感知與反應分離。ReactVAU 的差異在於：它專門針對異常領域設計了異常感知的記憶保護機制（AAPM）與將時序偵測轉為空間推理的 SGF，使 Fast Module 不僅是「觸發器」，更是一個具備異常過濾能力的輕量元件。

##### 5. 限制與潛在弱點

儘管設計巧妙，ReactVAU 仍存在一些值得注意的局限：

- **Trigger threshold 敏感度**：閾值過低會增加誤觸發與 MLLM 開銷；閾值過高則可能漏掉 subtle anomalies（細微異常）。
- **Fast Module 的召回率上限**：若 SGF 無法偵測到某類異常，後續 Slow Module 根本不會被喚醒，造成無法挽回的 false negatives。
- **異常密集時的延遲**：雖然正常區間效率高，但若短時間內連續發生異常，Slow Module 可能成為瓶頸。
- **領域泛化能力**：在訓練資料未涵蓋的異常類型或攝影機視角上，Fast Module 與 MLLM 的表現可能下降。
- **AAPM 容量限制**：異常池大小固定時，如何在長時間串流中維持重要證據仍是一個設計挑戰。

#### 未來研究方向

ReactVAU 為串流異常理解開闢了一條新途徑，未來研究可從以下幾個方向延伸：

##### 1. 自適應觸發機制

目前的 trigger threshold 可能是固定或人工調整的。未來可引入 **adaptive thresholding（自適應閾值）**，根據場景的長期統計特性、時間段（例如夜間異常機率較高）或模型對自身預測的不確定性，動態調整觸發標準，以平衡 recall 與運算成本。

##### 2. 多尺度 Spatial Grid Folding

現有 SGF 可能使用單一時間窗口與網格解析度。未來可發展 **multi-scale SGF（多尺度空間網格折疊）**，同時捕捉短暫突發異常與較長時間的異常趨勢，提升對不同速度異常的偵測能力。

##### 3. 輕量 Slow Reasoning Module

雖然 ReactVAU 已減少 MLLM 呼叫次數，但每次喚醒仍可能耗費大量資源。未來可透過 **knowledge distillation（知識蒸餾）** 或設計專屬的 lightweight MLLM，讓 Slow Module 在保持語義能力的同時降低延遲，適合邊緣裝置部署。

##### 4. 跨攝影機與多模態串流

真實監控系統通常包含多個攝影機與其他感測器（如音訊、門禁紀錄）。未來可將 ReactVAU 擴展為 **multi-camera streaming VAU（多攝影機串流 VAU）**，並結合 **spatial-temporal graph reasoning（時空圖推理）** 追蹤異常目標在不同攝影機間的移動。

##### 5. 長尾異常與持續學習

真實世界的異常類型具有高度長尾分佈。未來可結合 **few-shot learning（少樣本學習）** 或 **continual learning（持續學習）**，讓 ReactVAU 在部署後能夠逐步適應新出現的異常類型，而不需要從頭訓練。

##### 6. 更深層的因果推理

目前的 causal description 主要描述「發生了什麼」。未來可朝向 **root cause analysis（根本原因分析）** 與 **counterfactual reasoning（反事實推理）** 發展，例如預測「若行人未闖紅燈，事故是否會發生」，以支援更高階的安全決策。

##### 7. 真實部署環境評估

現有基準多為離線資料集。未來應建立專門的 **real-world live stream benchmarks（真實世界即時串流基準）**，考量網路延遲、頻寬限制、硬體資源與人機協作需求，進行更貼近實際應用的評估。

##### 8. 記憶體管理策略最佳化

AAPM 的 Anomaly Pool 容量與更新策略仍有改進空間。未來可探索 **dynamic memory allocation（動態記憶體分配）**、**importance sampling（重要性取樣）** 或 **learnable forgetting mechanisms（可學習遺忘機制）**，在有限記憶體下最大化保留對推理有幫助的視覺證據。

## 論文問答

**Q1：ReactVAU 旨在解決什麼核心問題？**

A：ReactVAU 旨在解決即時串流環境下的影片異常理解（Streaming Video Anomaly Understanding, VAU）問題。現有的頂尖 VAU 方法大多採用離線推理，必須觀察完整影片序列才能進行全域時間取樣或計算整體異常密度分佈，這違反了串流應用所需的因果性原則。ReactVAU 的目標是在不依賴未來幀的前提下，同時實現異常偵測與語義因果推理，並降低運算成本。

**Q2：為什麼現有的離線 VAU 方法無法直接應用於串流場景？**

A：現有離線 VAU 方法在生成語言描述前，必須先觀察整段影片以進行全域時間取樣或計算整體異常密度分佈。這種對未來幀的絕對依賴破壞了因果性（causality），使得模型無法在即時監控串流中即時做出判斷。此外，這些方法需要等待影片完整錄製後才能推理，根本無法滿足即時回應的需求。

**Q3：串流 VAU 在真實應用中為何重要？**

A：真實世界的監控系統會產生連續且不間斷的影片串流，而異常事件通常罕見且短暫。安全人員需要能夠即時偵測異常並提供因果解釋的系統，而不是等到影片結束後才獲得分析結果。串流 VAU 能夠在維護公共安全的同時提供語義可解釋性，對智慧監控與交通監控等場景至關重要。

**Q4：ReactVAU 的核心架構是什麼？**

A：ReactVAU 採用快慢解耦架構（Slow-Fast Decoupled Framework），包含三個協同運作的組件：輕量的快速偵測模組（Fast Detection Module）、異常感知持續記憶體（Anomaly-Aware Persistent Memory, AAPM），以及重型的慢速推理模組（Slow Reasoning Module）。快速模組透過空間網格折疊（Spatial Grid Folding, SGF）持續監控串流，而慢速模組則在偵測到可疑事件前保持休眠。AAPM 負責在慢速模組休眠期間保護關鍵的異常視覺線索，避免被時間衰減稀釋。

**Q5：空間網格折疊（SGF）的創新之處為何？**

A：SGF 將短期時間異常偵測轉換為高效的二維空間推理任務，從而繞過繁重的時間建模。這使得快速偵測模組能夠以極低的運算成本持續處理每個影格。透過將時間資訊折疊到空間網格中，ReactVAU 可以在不對每個影格呼叫重型 MLLM 的情況下完成密集的異常過濾。

**Q6：異常感知持續記憶體（AAPM）如何保護短暫異常特徵？**

A：AAPM 利用異常優先分數（Anomaly Priority Score）與基於威脅的異常池（Anomaly Pool），在連續記憶體壓縮過程中主動保護異常視覺線索。與一般串流模型為維持固定記憶體上限而懲罰較舊事件不同，AAPM 會優先保留可疑證據。這確保了當慢速推理模組被喚醒時，仍有足夠的上下文資訊進行語義驗證與因果描述。

**Q7：ReactVAU 在哪些基準資料集上進行評估？**

A：論文在多個標準基準資料集上進行了廣泛實驗，雖然提供的摘要與前言未詳細列出各資料集名稱，但強調了與最先進離線模型在嚴格串流約束下的比較。這些基準涵蓋了異常偵測與因果推理兩方面的評估。實驗設計特別著重於驗證模型在僅能存取當前與過去影格時的表現。

**Q8：ReactVAU 的關鍵實驗結果為何？**

A：ReactVAU 在嚴格串流約束下仍能達到與最先進離線模型相當的競爭力表現。由於慢速推理模組僅在偵測到可疑事件時才被喚醒，模型大幅減少了重型 MLLM 的呼叫次數，顯著提升運算效率。實驗結果顯示，該框架能夠同時兼顧異常偵測準確度與因果推理品質。

**Q9：哪些消融研究對驗證 ReactVAU 的設計至關重要？**

A：重要的消融研究包括移除 AAPM 以驗證保護短暫異常特徵的必要性、將 SGF 替換為傳統時間建模以衡量效率增益，以及關閉事件閘控機制以量化多餘的 MLLM 運算。這些研究有助於證明每個組件對效能與效率的貢獻。整體而言，消融結果應能說明快慢解耦設計對於平衡即時回應性與語義理解是不可或缺的。

**Q10：ReactVAU 適合哪些實際部署場景？**

A：ReactVAU 特別適用於智慧監控、交通監控與公共安全等需要即時異常理解的系統。其因果串流設計使其能夠處理即時攝影機串流，而無需緩衝未來影格，因此可部署於邊緣或雲端監控基礎設施。降低的運算成本也使其能夠擴展到大規模攝影機網路。

**Q11：部署 ReactVAU 時需要考慮哪些產品層面因素？**

A：產品團隊需要權衡快速模組的偵測靈敏度與慢速模組的觸發頻率，因為這會同時影響延遲與運算成本。觸發閾值必須根據特定部署環境調整，以平衡誤報與漏檢。此外，異常池的大小與記憶體管理策略也需要依據可用硬體資源進行配置。

**Q12：ReactVAU 可能對影片異常理解領域帶來什麼影響？**

A：ReactVAU 將 VAU 的研究典範從離線批次處理轉向線上串流推理，開啟了因果且高效的異常理解新方向。透過證明重型 MLLM 無需處理每個影格，它鼓勵更多事件閘控與解耦架構的發展。這可能促使學術界與產業界開發出更實用、可擴展的智慧監控系統。

**Q13：ReactVAU 可能存在哪些限制？**

A：ReactVAU 的效能高度依賴快速偵測模組能否正確標記可疑事件，若輕量模組漏檢，慢速模組便無法進行語義驗證。此外，在不同真實場景中設定適當的觸發閾值可能需要領域專屬的調整。目前的設計主要採取反應式觸發，而非主動預測異常的發生。

**Q14：ReactVAU 在哪些失敗案例中可能表現不佳？**

A：ReactVAU 可能在視覺訊號極微弱的微妙異常上表現不佳，因為這些異常不足以觸發快速模組。當異常在視覺上與正常活動非常相似時，異常優先機制也可能忽略關鍵證據。此外，若短時間內連續發生多個異常，異常池容量管理不當可能導致重要線索被覆蓋。

**Q15：ReactVAU 啟發了哪些未來研究方向？**

A：未來研究可探索能夠根據部署回饋自動調整的適應性觸發閾值，以及能在異常完全發生前預測的機制。將 ReactVAU 與音訊或動作感測器等多模態資訊整合，也有助於提升系統穩健性。另一個方向是開發更輕量的慢速推理模組，或將 MLLM 知識蒸餾到適合邊緣部署的小型模型中。

## 實務應用指南

## 適用場景

1. **24 小時智慧監控中心**  
   適合需要即時掌握異常事件、但畫面大多為正常狀態的場景。ReactVAU 的輕量快速偵測模組可持續過濾正常串流，僅在偵測到可疑事件時才喚醒重型 MLLM，降低監控中心即時分析的運算負擔。

2. **交通事件即時通報**  
   例如路口車禍、違規停車、行人闖入車道等短暫異常。空間網格折疊（SGF）能把短時間的時序異常轉為 2D 空間推理，異常感知持續記憶體（AAPM）則保護事故發生瞬間的視覺線索，避免被後續正常車流畫面稀釋。

3. **工廠與工地安全監控**  
   可用於偵測未佩戴安全帽、人員闖入危險區域、機台異常震動等事件。由於異常事件稀少且短暫，ReactVAU 的事件閘控機制能減少對正常作業畫面的冗餘推理，延長邊緣設備的穩定運行時間。

4. **零售賣場損防與異常行為理解**  
   例如貨架破壞、偷竊、顧客跌倒等。慢速推理模組可在觸發後提供語義驗證與因果描述，協助保全人員快速判斷事件性質，而不只是收到一個異常機率數值。

5. **大眾運輸與公共場所安全**  
   月台、車廂、機場航廈等場所人流密集，異常事件罕見。ReactVAU 可在嚴格因果存取限制下持續監控，並在發現可疑行為時生成自然語言說明，輔助營運人員決策。

## 實作前置條件

### 資料準備
- **歷史影片資料**：目標場景的長時間監控影片，需包含足夠的正常畫面與異常樣本。
- **異常標註**：至少具備片段級或影格級的異常區間標註，用於訓練或校正快速偵測模組。
- **語義標註（建議）**：若希望慢速推理模組輸出因果描述，需準備異常事件的語言描述或 instruction-tuning 資料。
- **串流來源**：支援 RTSP、ONVIF 或 WebRTC 的攝影機或錄影系統。

### 運算資源
- **邊緣端**：具備 CUDA 支援的輕量 GPU 或 NPU，用於部署快速偵測模組與 AAPM。
- **推理伺服器**：可部署重型 MLLM 的 GPU 伺服器，建議具備足夠 VRAM 以支援多路串流的事件觸發推理。
- **記憶體與儲存**：需配置持續記憶體緩衝區與事件剪輯儲存空間，保留觸發前後的關鍵視覺線索。

### 技術能力
- 熟悉深度學習模型部署（PyTorch/TensorRT/ONNX）。
- 具備串流處理與即時系統開發經驗（GStreamer、Kafka、Redis Stream 等）。
- 了解 MLLM 的提示工程與微調流程。
- 具備監控系統整合經驗（VMS、警報派發、權限管理）。

## 實作步驟建議

1. **定義異常分類與觸發條件**  
   先與場域專家確認需要偵測的異常類型、嚴重程度與可接受的誤判率，並據此設計觸發閾值與 AAPM 的異常優先分數。

2. **建立因果串流資料管線**  
   確保系統僅能使用當前與過去影格，不可預讀未來幀。建議以固定長度的滑動視窗處理輸入，並記錄每個推論決策的時間戳。

3. **訓練或微調快速偵測模組**  
   採用 Spatial Grid Folding（SGF）將短時間的時序資訊折疊為 2D 空間表示，訓練輕量模型進行連續異常過濾。此步驟可大幅減少後續重型 MLLM 呼叫次數。

4. **設計 AAPM 記憶策略**  
   根據異常優先分數與威脅等級建立異常池（Anomaly Pool），在記憶體壓縮過程中主動保護高分異常特徵，避免短暫異常被正常背景稀釋。

5. **整合慢速推理模組**  
   將重型 MLLM 配置為休眠狀態，僅在快速模組輸出超過閾值時喚醒。設計提示模板，讓模型基於 AAPM 保留的視覺線索進行語義驗證與因果描述。

6. **建立事件回饋與閾值調校機制**  
   收集誤觸發與遺漏案例，定期調整觸發閾值與異常優先分數。可引入人類回饋迴路（Human-in-the-Loop）持續優化模型。

7. **部署與效能監控**  
   在邊緣端與伺服器端分別部署對應模組，監控每路串流的端到端延遲、MLLM 呼叫頻率、GPU 使用率與異常偵測準確率。

## 潛在風險與注意事項

| 風險 | 說明 | 建議緩解方式 |
|---|---|---|
| **過度觸發重型 MLLM** | 觸發閾值過低會導致正常畫面頻繁喚醒慢速模組，抵消運算效率優勢。 | 採用動態閾值與冷卻時間（cool-down），並依場景調整異常優先分數。 |
| **短暫異常被遺漏** | SGF 或記憶體壓縮可能遺失極短暫的異常視覺線索。 | 縮短快速模組的處理視窗、提高 AAPM 對高變化區域的保留權重。 |
| **因果描述不準確** | MLLM 可能對保留的片段產生幻覺或錯誤因果推論。 | 結合物件追蹤與場景上下文，並在關鍵決策保留人工覆核流程。 |
| **延遲抖動** | 慢速模組喚醒時可能產生不可預測的推理延遲。 | 設定最大等待時間與逾時降級機制，優先確保異常警報即時發出。 |
| **隱私與資料安全** | 監控影片涉及個人隱私，持續記憶體可能保留敏感畫面。 | 實施去識別化、存取稽核、資料保留期限與邊緣端本地處理。 |
| **模型漂移** | 場景光照、攝影機角度或行為模式改變會降低偵測效能。 | 建立持續學習與定期重新校準流程，並監控異常分數分佈變化。 |

## 與其他技術的整合建議

- **現有影像管理系統（VMS）**：透過 RTSP/ONVIF 接入攝影機串流，並將 ReactVAU 的異常事件與剪輯片段回傳至 VMS 時間軸，方便保全人員回放。
- **SIEM / SOAR 平台**：將異常事件、置信度與因果描述以結構化格式（如 JSON/Syslog）送出，串接安全資訊事件管理與自動化回應流程。
- **現有 VAD 模型**：可保留既有幀級異常偵測模型作為快速模組的輔助特徵，或將其輸出納入 AAPM 的異常優先分數計算。
- **邊緣 NVR 與雲端 MLLM 服務**：在 NVR 上執行 SGF 與 AAPM，僅把觸發事件上傳至雲端 MLLM，兼顧即時性與成本。
- **儀表板與行動通知**：將慢速模組產生的因果描述推送至監控儀表板或即時通訊工具，縮短事件反應時間。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從摘要與圖 1 開始，理解 ReactVAU 為何要把「輕量快速偵測」和「重型慢速推理」分開，並掌握「因果存取」「異常被稀釋」「事件閘控」這三個核心概念。技術細節可先略過，重點放在它解決了什麼問題、適合什麼應用。

**AI 工程師**：請聚焦第 3 節的方法與實驗設定，特別是 Spatial Grid Folding 的實作方式、AAPM 的記憶體更新策略，以及慢速模組的觸發條件與提示設計。建議同時評估 TensorRT 或 ONNX 對快速模組的加速效果，以及 MLLM 服務化時的批次與快取配置。

**研究人員**：可深入比較 ReactVAU 與現有離線 VAU、通用串流影片理解框架在因果性與記憶機制上的差異。值得進一步探討的問題包括：SGF 在更長時間尺度上的表現、AAPM 的理論遺忘上界、以及事件閘控機制對罕見異常召回率的影響。

**產品經理**：重點閱讀適用場景與效率分析，評估 ReactVAU 能否在現有監控產品中取代離線分析流程。關鍵決策在於觸發閾值對使用者體驗與運算成本的權衡，以及如何在產品中設計人工覆核與隱私合規機制。
