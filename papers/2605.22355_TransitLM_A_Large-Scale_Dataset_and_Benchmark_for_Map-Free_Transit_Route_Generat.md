## ⚡ TL;DR

傳統公共運輸規劃依賴地圖與複雜引擎，現有資料集不足且通用模型易產生幻覺站點與斷裂路線。
提出 TransitLM 資料集，收錄逾一千三百萬筆四城路線紀錄，作為預訓練語料與三項任務基準。
實驗顯示模型可生成結構有效路線，隱式對應 GPS 至站點，並泛化不同目標，實現無地圖端到端路線生成。

## 摘要翻譯

公共運輸路線規劃（Public transit route planning）傳統上仰賴結構化地圖基礎設施（Structured map infrastructure）與複雜的路徑規劃引擎（Routing engines），且現有資料集均無法支援訓練模型以擺脫此依賴。我們提出 TransitLM，一個大規模資料集，收錄來自四個中國城市、涵蓋 120,845 個站點與 13,666 條路線，超過 1,300 萬筆的公共運輸路線規劃紀錄（Route planning logs）。該資料集同時發布為持續預訓練語料庫（Continual pre-training corpus），以及包含三項評估任務（Evaluation tasks）與互補指標（Complementary metrics）的基準測試（Benchmark）資料。實驗顯示，於 TransitLM 上訓練的大型語言模型（LLM）能夠以高準確度生成結構有效路線（Structurally valid routes），並將任意 GPS 座標（GPS coordinates）隱式對應（Implicitly grounds）至適當站點，無需任何顯式對應（Explicit mapping）。這些結果顯示，公共運輸路線規劃可以完全從資料中學習，從而實現直接依據起訖點資訊（Origin-destination (OD) information）進行端到端（End-to-end）、無地圖（Map-free）的路線生成（Route generation）。資料集與基準測試可於 https://huggingface.co/datasets/GD-ML/TransitLM 取得，評估程式碼則可於 https://github.com/HotTricker/TransitLM 取得。

### 核心貢獻（3～5點）
- 建構 TransitLM 大規模資料集，收錄超過 1,300 萬筆來自四個中國城市的公共運輸路線規劃紀錄，涵蓋 120,845 個站點與 13,666 條路線。
- 將資料集同時發布為持續預訓練語料庫與包含三項評估任務及互補指標的基準測試，填補無地圖路線生成領域的標準化評測缺口。
- 驗證於 TransitLM 上訓練的大型語言模型能以高準確度生成結構有效路線，並將任意 GPS 座標隱式對應至適當站點，無需任何顯式對應。
- 證明公共運輸路線規劃可完全從資料中學習，實現直接依據起訖點資訊的端到端、無地圖路線生成。

### 適合對象
從事公共運輸路線規劃、城市移動性研究、空間資訊科學與大型語言模型應用之研究者，以及需要建構無地圖路線生成系統或評估語言模型在結構化規劃任務上表現的工程師與開發者。

## 深度分析

#### 方法論解析

TransitLM 的核心方法論可拆解為「資料建構」與「兩階段模型訓練」兩大支柱。首先，研究團隊從北京、上海、深圳、成都四座城市的公共運輸平台蒐集超過 1,300 萬筆路線規劃紀錄（route planning logs），涵蓋 120,845 個站點（stations）與 13,666 條路線（lines）。每筆紀錄並非僅有起訖點（origin-destination, OD）資訊，而是包含完整的規劃會話（planning session）：GPS 座標（GPS coordinates）、站點序列（station sequences）、轉乘點（transfer points）、路線識別碼（line identifiers）、路段層級時間（segment-level timing）以及路線類型標註（route-type annotations）。這種設計使得資料同時具備結構化拓撲（topology）與使用者行為標註（behavioral annotations），彌補了過往資料集僅具備單一面向的缺陷。

資料釋出分為兩個互補資源：

1. **持續預訓練語料庫（continual pre-training corpus）**：包含 1,390 萬筆文字化路線描述，用於 next-token prediction 的持續預訓練（continual pre-training）。透過此語料庫，模型得以內化公共運輸網路的拓撲結構與空間關係。
2. **基準測試專用 SFT 資料（benchmark-specific SFT data）**：針對三項核心評估任務（evaluation tasks）提供標準化提示（prompts）與標籤（labels），包括：**最適路線生成（optimal route generation）**、**偏好感知規劃（preference-aware planning）**，以及**多路線生成（multi-route generation）**。

訓練流程採用先持續預訓練（pre-train）再監督式微調（supervised fine-tuning, SFT）的兩階段策略。在預訓練階段，模型透過大量真實 OD 軌跡（real OD trajectories）學習路線描述的生成機率；在微調階段，則對齊特定任務的輸入輸出格式。值得注意的是，此流程完全摒棄傳統的結構化地圖基礎設施（structured map infrastructure）與路徑規劃引擎（routing engines），僅依靠起訖點資訊（origin-destination information）即可進行端到端（end-to-end）的無地圖（map-free）路線生成（route generation）。

最關鍵的方法論創新在於**隱式空間對應（implicit spatial grounding）**的湧現。模型僅接收任意 GPS 座標作為輸入，卻能將其解析為適當的上車站點（boarding stations）與下車站點（alighting stations），過程中未使用任何顯式的座標-站點對照表或地理資料庫。這意味著模型從文字序列中自主編碼了空間拓撲，將地理空間關係隱式地嵌入於語言模型的參數空間中，形成一種「參數化地圖（parametric map）」。

#### 實驗數據解讀

論文報告了三項關鍵發現，其背後的實驗意涵值得深入剖析：

**（1）端到端無地圖路線生成的可行性**
實驗顯示，經過 TransitLM 訓練的模型能夠以高準確率產生結構有效路線（structurally valid routes），即路線在拓撲網路（topological networks）中確實連通、轉乘點有效、且無斷裂連接（broken connections）。這項結果直接挑戰了傳統「地圖資料檢索（map data retrieval）→ 路徑演算法（如 Dijkstra、A\*、RAPTOR）→ 排序模型（ranking model）」三階段工程流程（engineering pipelines）的必要性。數據顯示，豐富的軌跡資料本身足以替代顯式圖結構，使候選檢索（candidate retrieval）與排序（ranking）的過程被隱式地編碼於模型內部。

**（2）隱式空間對應的湧現**
給定僅包含 GPS 座標的使用者查詢（user query），模型展現出將任意座標對應至適當站點的能力。這並非透過顯式的最近鄰搜尋或地理圍欄演算法達成，而是從 1,300 萬筆紀錄中學習到的統計規律。這暗示自迴歸大型語言模型（autoregressive LLMs）在具備充足領域語料時，能夠內建類似「空間索引」的功能。然而，摘要未提供座標解析錯誤率（例如偏遠地區或新建站點的對應失敗率），這是解讀時需注意的保留之處。

**（3）單一模型跨目標泛化**
聯合訓練（jointly trained）的單一模型在三項基準測試（benchmark）上均達到或超越各任務專屬模型（task-specific counterparts），且未出現負遷移（negative transfer）。這證明 TransitLM 所編碼的公共運輸知識具有任務無關性（task-agnostic），支援統一部署於多樣規劃情境。互補指標（complementary metrics）涵蓋連通性（connectivity）、接取可行性（access feasibility）、路線重疊（route overlap）與數值欄位準確率（numeric field accuracy），從多維度確保生成品質，避免單一指標過度樂觀的偏差。

整體而言，實驗數據支持了「公共運輸規劃可完全從資料中學習」的核心命題，但具體的數值表現（如各項互補指標的絕對分數、與傳統演算法的量化差距）在提供的摘要中尚未揭露，需參照完整論文的實驗表格方能進行更細緻的效度評估。

#### 與現有研究的比較

**相較於傳統方法**
古典公共運輸路徑規劃方法（如 Dijkstra、A\*、RAPTOR、Connection Scan Algorithm、Transfer Patterns）皆運作於顯式圖表徵（explicit graph representations）之上，本質上需要結構化地圖基礎設施與即時時刻表資料。TransitLM 徹底移除了這項依賴，將候選檢索、拓撲推理與排序壓縮為單一生成步驟。然而，傳統方法在可解釋性（interpretability）與最優性保證（optimality guarantees）上仍具優勢，這是生成式方法難以完全取代之處。

**相較於 LLM 輔助方法**
近期研究嘗試以通用大型語言模型（general-purpose LLMs）降低對地圖的依賴，但皆未達成真正的無地圖生成。例如：**LLM-A\*** 將 LLM 生成的啟發式函數嵌入 A\* 搜尋，但仍需輸入圖結構；**GridRoute** 僅在合成網格環境中評估路徑推理；**MapBench** 與 **MapTrace** 聚焦於像素層級地圖導航（pixel-level map navigation）；**ReasonMap** 針對運輸地圖閱讀，但視覺推理準確率有限；**TraveLLM** 應用於公共運輸中斷情境，仍依賴外部地圖資料。

相較之下，TransitLM 是首個實現僅憑起訖點資訊即可端到端生成連續路線（continuous routes）的框架，並透過隱式空間對應解決了通用 LLM 常見的幻覺站點（hallucinated stations）與無效上下車站點（invalid boarding/alighting stations）問題。

**相較於現有資料集**
現有資料集各自僅捕捉問題的局部面向：**車輛軌跡資料集（vehicle trajectory datasets）**（如 T-Drive、Porto Taxi、GeoLife）具備 GPS 軌跡但缺乏站點結構、轉乘邏輯與路線識別碼；**靜態網路資料集（static network datasets）**（如 GTFS、OpenStreetMap、CPTOND-2025）提供完整拓撲與時刻表，但無使用者行為或真實旅行軌跡。TransitLM 首次結合了完整路線結構（route structures）與行為標註，為資料驅動的端到端公共運輸規劃（end-to-end transit planning）提供了必要條件。

**相較於現有基準測試**
現有旅行規劃基準（如 TravelPlanner、NATURALPLAN、TripCraft、ChinaTravel、TripTailor、TravelBench、TRIP-Bench）聚焦於多日行程排程（multi-day itinerary scheduling），評估高層級約束滿足度而非站點層級路線準確率。CityBench 與 USTBench 雖涵蓋多樣城市任務，但排除或邊緣化公共運輸路徑規劃。MobilityBench 雖最接近本研究設定，但其評估重點在於模型編排地圖 API 的能力，而非無地圖生成能力。

**限制（Limitations）**
儘管 TransitLM 填補了重要空白，仍存在若干限制：目前僅涵蓋四座中國城市，對於不同拓撲結構（如歐洲放射狀路網或北美低密度郊區路網）的泛化能力尚待驗證；資料來自中文語境，路線偏好（line preference）與便利性（convenience）的定義可能具有地域特殊性；資料集主要反映歷史規劃紀錄，對於即時路網變動（如臨時封站、班次延誤）的動態適應能力未在摘要中討論；此外，生成式模型無法保證輸出路徑在旅行時間或轉乘次數上為全域最優（globally optimal），這在關鍵基礎設施應用中可能構成隱憂。

#### 可重現性評估

TransitLM 在開放科學（open science）層面採取了積極步驟：資料集已於 Hugging Face（https://huggingface.co/datasets/GD-ML/TransitLM）公開釋出，包含持續預訓練語料庫與基準測試資料；GitHub 倉庫（https://github.com/HotTricker/TransitLM）則提供標準化評估流程與互補指標的實作。

然而，根據提供的全文脈絡，仍有若干可重現性缺口：**基礎模型（base model）未指明**——論文提及「訓練一個 LLM」，但未說明所使用的基礎模型架構（如 Qwen、LLaMA、GPT 系列等）與參數規模，這使得其他研究者難以完全復現從預訓練到微調的完整實驗條件；**模型權重（model weights）**——摘要與引言未提及是否公開釋出微調後的模型權重，若僅釋出資料與評估程式碼，研究者需自行承擔從頭訓練的運算成本，可能降低大規模驗證的可及性；此外，持續預訓練的學習率、訓練步數、SFT 的資料配比等關鍵後設參數（hyperparameters），以及訓練所需的 GPU 時數或記憶體配置，在提供的片段中闕如。

綜合而言，TransitLM 在資料與評估層面已達到高度可重現，但在模型訓練的完整技術細節與權重釋出方面，仍有提升空間以符合最嚴格的開放科學標準。

#### 未來研究方向

基於 TransitLM 的貢獻與現有限制，以下為具潛力的後續研究方向：

**1. 跨城市與跨語言遷移學習（Cross-city Transfer Learning）**
當前資料集僅限於四座中國城市。未來研究可探索將 TransitLM 預訓練所得之隱式空間對應能力，遷移至其他具有不同拓撲結構的城市（如東京、紐約、倫敦），甚至發展「零樣本（zero-shot）」或「少樣本（few-shot）」的城市適應框架，驗證模型所學之公共運輸規劃知識是否具備通用幾何與拓撲不變性。

**2. 動態與即時資料整合（Dynamic & Real-time Integration）**
現有資料集本質上為靜態歷史紀錄。將動態 GTFS 饋送（GTFS-realtime）、臨時路網中斷、班次延誤與擁塞資訊納入訓練與推論流程，可使模型從「靜態路線生成」進化為「動態旅程規劃」。這可能需結合檢索增強生成（Retrieval-Augmented Generation, RAG）或工具使用（tool use），在維持無地圖生成優勢的同時注入即時情境。

**3. 多模態空間對應（Multimodal Spatial Grounding）**
目前隱式空間對應僅依賴文字化 GPS 座標。未來可引入衛星影像、街景圖或像素層級地圖（pixel-level maps），發展視覺-語言聯合預訓練，使模型能夠處理「最近的公車站在那棟紅色建築旁」這類結合視覺線索與地理資訊的查詢，進一步強化結構對應（structural grounding）的穩健性。

**4. 可解釋的隱式地圖（Interpretable Implicit Maps）**
模型內部究竟編碼了何種空間表徵？未來可透過探針（probing）或視覺化技術，解構語言模型隱藏層中的「虛擬地圖」，分析其是否形成了類似網格細胞（grid cells）或距離矩陣的內部結構。這不僅具有學術價值，也能診斷模型在偏遠地區或座標邊界案例（edge cases）上的失效模式。

**5. 強化學習與人類回饋（RLHF）的偏好對齊**
TransitLM 已包含偏好訊號（preference signals）（如速度、便利性、路線偏好）。後續可引入強化學習與人類回饋（Reinforcement Learning from Human Feedback, RLHF）或偏好最佳化（如 DPO、PPO），讓模型學習更細緻的個人化權衡，例如「寧願多轉乘一次也要避開尖峰時段擁擠路線」。

**6. 計算效率與系統部署**
生成式模型在推論延遲（inference latency）上通常難以與毫秒級的傳統路徑規劃引擎競爭。未來研究可聚焦於模型蒸餾（distillation）、推論加速（如 speculative decoding）或混合架構（hybrid architecture），在必要時退回到輕量級傳統演算法，以兼顧無地圖生成的靈活性與工業級回應速度。

**7. 對抗穩健性（Adversarial Robustness）**
針對極端 OD 對（如距離極遠、橫跨多個行政區、或起訖點附近無站點）進行對抗測試，評估模型是否會產生看似合理但實際無效的幻覺路線。建立此類壓力測試基準，對於將 TransitLM 部署於真實公共運輸應用至關重要。

## 論文問答

**Q1：TransitLM 旨在解決的核心問題是什麼？**
A：傳統的公共運輸路線規劃長期依賴結構化地圖基礎設施與複雜的工程流程，包括候選檢索、拓撲網路計算與排序模型，導致系統建置與維護成本高昂。TransitLM 試圖回答一個根本問題：是否能直接從大規模路線規劃紀錄中學習，完全繞過地圖與專用路徑規劃引擎。這個資料集的誕生正是為了填補現有資料來源無法支援端到端公共運輸規劃學習的關鍵缺口。

**Q2：為何通用大型語言模型在公共運輸路線規劃上表現不佳？**
A：通用大型語言模型雖具備廣泛的世界知識與推理能力，但缺乏針對公共運輸拓撲結構的專門訓練資料，無法建立穩固的結構對應。由於沒有適當的領域語料，這些模型在面對較冷門的起訖點對時，經常產生幻覺站點與斷裂連接，導致路線在實際網路中無法通行。近期研究也指出，自迴歸大型語言模型本身難以獨立完成可靠的規劃任務，更遑論生成結構有效且連續的完整路線。

**Q3：TransitLM 這類新資料集對該領域為何重要？**
A：現有的車輛軌跡資料集如 T-Drive 與 Porto Taxi 缺乏站點結構、轉乘邏輯與路線識別碼，而靜態網路資料集如 GTFS 與 CPTOND-2025 則缺少真實使用者行為與實際旅行軌跡。沒有任何現有資料來源能同時提供完整路線結構與行為標註，這使得資料驅動的端到端學習幾乎不可能實現。TransitLM 透過收錄超過一千三百萬筆涵蓋真實起訖點軌跡、轉乘點與偏好訊號的紀錄，首次為無地圖路線生成提供了完整的訓練與評估基礎。

**Q4：TransitLM 釋出了哪兩種互補的資源？**
A：研究團隊釋出了持續預訓練語料庫與基準測試專用的監督式微調資料，兩者相輔相成。前者包含一千三百九十萬筆文字化的路線描述，供模型進行次詞元預測訓練，從而內化公共運輸網路的拓撲與空間關係。後者則針對三項核心評估任務提供標準化的提示與標籤，使模型能學習生成符合特定需求與使用者偏好的路線。

**Q5：TransitLM 定義了哪三項核心評估任務？**
A：基準測試包含最佳路線生成、偏好感知規劃與多路線生成這三項任務，涵蓋不同層次的規劃需求。最佳路線生成著重於給定起訖點後產生最適路徑；偏好感知規劃則需根據使用者對速度、便利性或路線偏好的指示進行調整；多路線生成則要求模型提供多樣化的可行選項。每項任務都透過涵蓋連通性、進出可行性、路線重疊度與數值欄位準確率的互補指標進行全面評估。

**Q6：與傳統方法相比，TransitLM 的核心創新是什麼？**
A：TransitLM 的核心創新在於實現了端到端、無地圖的路線生成，僅需起訖點的 GPS 座標即可直接輸出結構有效的完整路線。傳統流程必須經過地圖資料檢索、路徑演算法計算與排序模型篩選等多個階段，而 TransitLM 訓練出的模型將這一切濃縮為單一語言模型的推論過程。最關鍵的是，模型能從資料中學會隱式空間對應，自動將任意 GPS 座標解析為適當的上下車站點，無需依賴任何明確的地理資料庫或座標映射表。

**Q7：驗證實驗中得到了哪三項關鍵發現？**
A：第一，端到端的無地圖路線生成確實可行，訓練後的模型能以高準確率產生結構有效且連續的路線，證明豐富的軌跡資料足以取代傳統引擎。第二，隱式空間對應會從大量資料中自然湧現，模型僅憑 GPS 座標就能將其對應到正確的站點，無需額外的座標到站點映射或地理資料庫。第三，單一聯合訓練的模型即可在三項基準測試上匹配甚至超越專任務模型，且沒有負遷移現象，證明資料集中蘊含的運輸知識具有任務無關性。

**Q8：聯合訓練的單一模型與任務專用模型相比表現如何？**
A：實驗顯示，單一聯合訓練的模型在三項基準測試上的表現皆能匹配或超越各自獨立訓練的任務專用模型。這項結果有力地證明了 TransitLM 所編碼的公共運輸知識並不侷限於單一任務，而是具有高度的遷移與泛化能力。這也意味著在實際部署時，可以用單一模型統一服務多樣化的規劃情境，大幅降低系統複雜度與維護成本。

**Q9：評估生成路線時使用了哪些互補指標？**
A：評估指標橫跨連通性、進出可行性、路線重疊度與數值欄位準確率等多個維度，形成互補的評估體系。連通性檢查路線是否為連續不斷開的有效路徑；進出可行性確認上下車站點是否真實存在且可抵達；路線重疊度衡量生成路線與參考答案的相似程度；數值欄位準確率則驗證時間、路線編號等細節的正確性。這些互補指標確保模型輸出不僅拓撲正確，也具備實用價值與可執行性。

**Q10：TransitLM 可在哪些實際場景中部署應用？**
A：此技術特別適合尚未建立完整結構化地圖基礎設施的新興城市或開發中區域，因為它僅需 GPS 座標即可運作。在偏遠地區、臨時活動場域或緊急應變情境等缺乏詳細公共運輸地圖的環境中，模型仍能根據歷史軌跡資料提供可行路線。此外，端到端的架構也讓快速原型驗證與偏鄉交通服務等需要即時部署的情境變得更加容易，無需等待複雜的地圖工程建置。

**Q11：這項研究可能如何改變大眾運輸應用程式的產品設計思維？**
A：產品團隊未來有機會降低對昂貴地圖資料授權與複雜路徑規劃引擎的依賴，轉而採用單一大型語言模型處理核心路由邏輯。由於單一模型即可同時勝任標準路線生成、偏好感知規劃與多路線推薦，後端架構將大幅簡化，減少不同模組間的維護負擔。這不僅能壓低營運成本，也能加快新功能迭代速度，並更容易針對不同城市進行規模化複製與在地化調整。

**Q12：這項研究對城市移動性與人工智慧領域有何更廣泛的影響？**
A：TransitLM 證明了豐富的歷史軌跡資料本身足以取代傳統依賴地圖的路徑規劃引擎，為資料驅動的城市智慧開闢了新路徑。這也驗證了只要給予適當的領域專屬語料庫，大型語言模型確實能內化複雜的網路拓撲與空間關係，突破以往被認為無法可靠規劃的限制。此範式未來可望擴展到其他需要結構化空間推理的領域，如物流路徑規劃、緊急疏散路線設計或無人機空域導航。

**Q13：TransitLM 目前有哪些已知的限制？**
A：目前資料集僅涵蓋北京、上海、深圳與成都四個中國城市，地理與文化脈絡的侷限可能影響模型在其他地區的泛化能力。此外，研究主要基於歷史規劃紀錄，並未明確探討模型面對即時路線中斷、班次延誤或新開通路線時的應變能力。這表示在快速變化的動態環境中，模型可能會生成過時或無法反映當下營運狀況的路線，仍需額外機制進行補強。

**Q14：無地圖生成可能出現哪些失效案例？**
A：對於歷史資料稀疏的冷門起訖點對或新開發區域，模型可能因缺乏足夠訓練樣本而產生次佳或過時的路線。由於沒有即時地圖資料進行驗證，模型難以自動察覺臨時封路、施工改道或班次取消等突發狀況，導致建議路線在現實中無法執行。此外，在都會峽谷等 GPS 訊號易受干擾的區域，座標解析的誤差可能導致隱式空間對應失準，進而選錯上下車站點。

**Q15：未來有哪些有前景的研究方向？**
A：一個重要方向是將資料集擴展到更多城市，並納入多元運具如自行車、計程車或共乘服務，以支援真正的多模式路線規劃。另一個方向是引入即時資料串流，讓模型具備動態路線規劃能力，而非僅依賴靜態歷史模式。未來也可探索如何以少量本地資料進行少量樣本適應，使模型能快速部署到資料稀少的新城市，進一步提升其全球適用性。

## 實務應用指南

### 適用場景

1. **缺乏結構化地圖基礎設施的新興城市或偏鄉地區**：在無法長期維護高成本路徑規劃引擎與即時地圖資料庫的場景下，可直接利用 TransitLM 的無地圖、端到端路線生成能力，為當地居民提供基於歷史軌跡的公共運輸路線規劃服務。
2. **車載系統與智慧音箱的語音導航**：駕駛或乘客僅需提供起訖點資訊（甚至口述 GPS 座標），模型即可直接輸出連續路線與轉乘點，無需後端呼叫地圖 API，降低延遲並提升離線可用性。
3. **結合路線偏好的個人化通勤助手**：針對「偏好公車優先」「少轉乘」或「快速抵達」等偏好訊號，利用偏好感知規劃任務，生成符合個人習慣的結構有效路線，而非僅有單一最短路徑。
4. **大規模活動或緊急疏散的多路線備援**：在演唱會、體育賽事或災害疏散情境中，透過多路線生成任務同時輸出多條互補路線，並以互補指標評估路線重疊與連接強度，分散人流壓力。
5. **交通營運商的歷史數據資產活化**：將累積的路線規劃紀錄轉化為持續預訓練語料庫，用於內部路線優化、新線路開通模擬，或作為傳統路徑規劃引擎的生成式前端。

### 實作前置條件

- **資料**：需蒐集當地真實 OD 軌跡，包含起訖點 GPS 座標、上車站點與下車站點序列、轉乘點、路線識別碼、分段時距與路線類型標註。若無現成資料集，須自行建構至少百萬級的文本化路線描述，並劃分為持續預訓練語料庫與三項評估任務的標準化提示詞與標籤。
- **運算資源**：持續預訓練階段建議配置 8× NVIDIA A100 80GB 或同等級 GPU，並使用 DeepSpeed 等框架加速；微調階段可降至 1–2× A100，或採用 LoRA／QLoRA 在單張 RTX 4090 24GB 等消費級顯卡執行。推論部署則建議配備 vLLM 或 TensorRT 以確保低延遲。
- **技術能力**：團隊需熟悉自迴歸大型語言模型的預訓練與微調流程（Hugging Face Transformers）、資料清洗與結構化、公共運輸拓撲網路知識（站點、路線、轉乘邏輯），以及設計互補指標（連通性、進出站可達性、數值欄位準確率）的評估流程。

### 實作步驟建議

1. **資料探勘與語料建構**：將原始路線規劃紀錄清洗後，轉換為自然語言序列格式（例如：「從 GPS(39.9,116.4) 到 GPS(39.8,116.3)，先搭乘地鐵 1 號線至轉乘點…」），同步建立千萬筆等級的持續預訓練語料庫，以及對應最適路線生成、偏好感知規劃、多路線生成三項評估任務的標準化提示詞與標籤。
2. **領域持續預訓練**：選定通用大型語言模型（如 Qwen3、LLaMA 系列）為基底，在持續預訓練語料庫上執行 next-token prediction，使模型內化公共運輸網路拓撲與空間關係，建立隱式空間對應能力。
3. **監督式微調（SFT）**：依序或聯合針對三項評估任務進行微調，讓模型學會依據使用者查詢生成結構有效路線，並處理偏好訊號與多路線輸出格式。
4. **評估與對齊**：以互補指標驗證生成結果，確保無幻覺站點、斷裂連接與無效上下車站點；必要時引入 RLHF 或 DPO，針對連續路線與有效連接進行偏好對齊，降低生成失誤率。
5. **部署與監控**：將模型匯出為 ONNX 或透過 vLLM 建立推論服務，封裝為 REST API 整合至 APP、車機或聊天機器人；同時設立後驗驗證層，對輸出站點與路線進行輕量規則檢查，並持續收集線上回饋資料用於迭代微調。

### 潛在風險與注意事項

- **幻覺站點與斷裂連接**：模型可能生成不存在的站點或無法銜接的轉乘。建議增設後驗規則引擎，驗證每一個生成站點是否確實存在於對應路線上，並檢查相鄰路段的連接強度。
- **隱式空間對應偏差**：對於訓練資料中少見的起訖點對或城市邊緣區域，模型可能將 GPS 座標錯誤對應至遠端站點。可透過在訓練語料中強化冷門區域與邊界案例的採樣權重來緩解。
- **靜態知識限制**：模型權重無法即時反映臨時封路、班次異動或新開通路線。實務上應保留與即時交通資訊系統的介接能力，作為動態修正層，或結合檢索增強生成（RAG）補充最新路網資訊。
- **資料隱私與分佈偏誤**：歷史軌跡涉及使用者行為，去識別化處理為必要程序；此外，熱門路線過度採樣可能導致冷門區域規劃品質低落，需在資料建構階段進行分層抽樣與分佈校正。
- **任務間負遷移**：雖論文驗證單一聯合模型可泛化，但若實際應用場景的任務差異極大（例如同時處理通勤最短路徑與觀光多點規劃），仍可能出現負遷移。建議先以小型實驗驗證聯合訓練成效，必要時採用任務適配器（Adapter）或專家混合架構隔離不同目標。

### 與其他技術的整合建議

- **與傳統路徑規劃引擎互補**：將 TransitLM 作為主要生成器，提供快速、無地圖的端到端路線；當模型輸出置信度低、涉及臨時改道，或使用者要求絕對最優解時，再將結果作為初始解 fallback 至 RAPTOR、Dijkstra 或 A* 等傳統演算法進行精修。
- **與檢索增強生成（RAG）結合**：建立即時路網與班次向量資料庫，在生成前檢索當前有效路線、站點狀態與營運異動資訊，彌補模型靜態權重的知識缺口，減少因路網變動導致的無效上下車站點。
- **與多模態感知系統整合**：搭配街景影像、車站出入口照片或像素級地圖（如 ReasonMap、MapBench 方向），強化模型對實體空間的理解，提升無地圖場景下的可解釋性與使用者信任度。
- **與推薦與排序系統串接**：將 TransitLM 生成的多路線選項接入現有排序模型（Ranking Model），依據即時擁擠度、票價、碳排放或個人化偏好訊號進行二次排序，形成「生成—排序—呈現」的完整產品流程。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦論文圖一與第一章，理解傳統方法（需要結構化地圖基礎設施與複雜工程流程）與 TransitLM（無地圖、端到端）的核心差異；把 TransitLM 想像成「從歷史軌跡中學會認路」的資料集，重點在於它提供了真實 OD 軌跡與行為標註，讓模型不需要查地圖就能規劃出連續路線。
- **AI 工程師**：建議深入閱讀資料集建構方式與三項評估任務的設計細節，特別注意持續預訓練語料庫如何將拓撲網路與 GPS 座標轉為文本序列；實作時請參考 Hugging Face 上的語料格式與 GitHub 的評估程式碼，並留意隱式空間對應的實驗設定，這是部署時能否正確將任意座標對應到上車站點的關鍵。
- **研究人員**：請關注論文對現有資料缺口的分析（車輛軌跡資料集缺乏站點結構、靜態網路資料集缺乏使用者行為），以及「隱式空間對應」與「任務無關的遷移學習」兩項發現；這些結果挑戰了「自迴歸大型語言模型無法獨立規劃」的既有觀點，並為端到端公共運輸規劃提供了新的研究基線。
- **產品經理**：這篇論文的商業價值在於大幅降低路線規劃服務的基礎設施成本——無需維護昂貴的地圖資料檢索與路徑規劃引擎即可提供即時查詢；三項評估任務分別對應「一般導航」「個人化偏好」「多路線備援」三大使用者場景。但請注意，幻覺站點與斷裂連接仍是生成式模型的固有限制，產品上線時必須設計傳統演算法的 fallback 機制與人工覆核流程。
