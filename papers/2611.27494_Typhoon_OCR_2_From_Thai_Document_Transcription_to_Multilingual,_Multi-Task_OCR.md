## 摘要翻譯

<mm:think>The user wants me to produce the final translation in a specific format. Let me compile the translation based on my review and present it in the requested format.

The format requires:
1. 繁體中文標題 (Traditional Chinese title)
2. 摘要翻譯 (Abstract translation, with English terms preserved and annotated)
3. 核心貢獻 (Core contributions, 3-5 points)
4. 適合對象 (Target audience)

Let me produce this carefully.</mm:think>
Typhoon OCR 1.5 專注於讀取泰文文件。然而，在實際工作流程中，使用者經常需要擷取特定資訊，或保留整個頁面的結構以供後續處理。Typhoon OCR 2 以單一模型處理這兩項任務，具備提示驅動擷取（prompt-driven extraction）與結構化全頁解析（structured full-page parsing）功能。全頁解析涵蓋泰文、英文與中文。我們釋出精簡的 2B 與 0.8B 模型，這些模型改編自開放文件解析器（open document parsers），透過在策展泰文資料（curated Thai data）與公開多語言資料（public multilingual data）上進行監督式微調（supervised fine-tuning），接著採用群組相對策略最佳化（Group Relative Policy Optimization, GRPO），並搭配任務獎勵（task rewards）以及一條懲罰未完成回應的規則（rule penalizing unfinished responses）。在所評測的開放模型中，Typhoon OCR 2 2B 在 Thai MDPBench 上獲得最高分（80.7，對比 Typhoon OCR 1.5 的 68.9），在 ThaiOCRBench 上同樣最高（59.91 對比 40.45），該基準測試涵蓋辨識、擷取與文件理解。2B 模型在英文 olmOCR-bench 上仍接近其基礎模型（84.7 對比 84.4），在 OmniDocBench 上亦然，該基準測試同時評測英文與中文（90.97 對比 91.03）。在 MDPBench 上，GRPO 將 2B 模型出現重複迴圈（repetition loops）的頁面平均占比從 3.2% 降至 0.7%，而 0.8B 模型的分數提升幅度較小，且在統計上不確定。我們釋出模型權重、Python 套件與評測套件。

### 核心貢獻（3～5點）
- 提出單一模型同時支援「提示驅動擷取」與「結構化全頁解析」兩種任務，涵蓋泰文、英文與中文三語，滿足真實文件工作流程中資訊擷取與版面保留的雙重需求。
- 釋出精簡的 2B 與 0.8B 開放權重模型，改編自開放文件解析器，並透過監督式微調結合 GRPO 策略最佳化進行訓練，搭配任務獎勵與懲罰未完成回應的規則，有效降低重複迴圈問題。
- 在多項基準測試中表現領先：Thai MDPBench 達 80.7 分（超越 Typhoon OCR 1.5 的 68.9）、ThaiOCRBench 達 59.91 分（超越 40.45），同時在英文 olmOCR-bench（84.7）與中英雙語 OmniDocBench（90.97）上維持與基礎模型相近的水準。
- 完整釋出模型權重、Python 套件與評測套件，方便研究社群與開發者重現結果並進行後續應用。

### 適合對象
從事文件理解、OCR 技術研發或文件自動化工作流程設計的研究人員與工程師；尤其適合需要處理泰文文件、或需建構多語言文件擷取與解析系統的開發者；以及對開放權重 OCR 模型、監督式微調與 GRPO 策略最佳化技術感興趣的學術界人士。

## 深度分析

#### 方法論解析

Typhoon OCR 2 的方法論核心在於將「單一模型、雙重任務」的概念落實於文件光學字元辨識 (OCR) 領域。相較於前一代 Typhoon OCR 1.5 僅專注於泰文文件轉錄，Typhoon OCR 2 透過提示驅動 (prompt-driven) 的方式，讓同一個模型能夠根據使用者輸入的指令，動態切換兩種截然不同的輸出模式：目標式擷取 (targeted extraction) 與結構化全頁解析 (structured full-page parsing)。

**任務定義與輸出格式設計**

在全頁解析任務中，模型回傳一個 JSON 陣列，內含按閱讀順序排列的版面元素 (layout elements)。每個元素包含三項關鍵資訊：正規化後的邊界框 (bounding boxes)、語意類別 (semantic category)，以及轉錄內容。值得注意的是，模型對於不同類型的內容採用不同的標記語言：表格以 HTML 表示、公式以 LaTeX 表示、一般內文則以 Markdown 表示。這種異質化的標記策略反映了對文件多模態特性的深度理解——表格需要保留結構關係、公式需要精確的數學語法、內文則需要輕量化的排版標記。這樣的設計讓下游應用能夠根據版面元資料 (layout metadata) 進行索引、搜尋、視覺化標註，或將個別表格送往資料處理流程。

在擷取任務中，使用者可透過自然語言提示要求模型回傳特定資訊，例如圖表中的數值、表單中的欄位，或針對文件內容的問答。這種設計將傳統的「OCR + 大語言模型 (LLM) 兩階段流程」壓縮為單一步驟 (single step)，直接從頁面影像 (page image) 提取結構化資訊，大幅降低延遲與錯誤傳播風險。

**基礎模型選擇與適配策略**

研究團隊採用「站在巨人肩膀上」的策略，從兩個專門的開放文件解析器 (open document parsers) 進行初始化：2B 模型源自 Infinity-Parser2-Flash (Huang et al., 2026)，0.8B 模型源自 OvisOCR2 (Lu et al., 2026)。選擇 Infinity-Parser2-Flash 作為 2B 模型的基礎，是因為其採用與 Typhoon OCR 2 相同的版面 JSON 格式，這種格式一致性大幅降低了適配成本。OvisOCR2 則提供了更精簡的架構選項，適合資源受限的部署場景。

**訓練資料組成**

訓練資料混合策略呈現明確的「泰文為主、多語言為輔」原則。總計 420,327 筆訓練樣本中，泰文相關資料佔 34.9%（146,647 筆），其中包含兩部分：經規則過濾的 Typhoon OCR 1.5 資料（99,616 筆，23.7%）與新標註的內部泰文資料集（47,031 筆，11.2%）。其餘 65.1%（273,680 筆）為公開多語言資料，主要涵蓋英文與中文，包括多任務文件資料（237,000 筆，56.4%）以及視覺問答與純文字指令資料（36,680 筆，8.7%）。

**泰文標籤建構流程**

由於公開泰文語料庫極少包含細粒度的版面與閱讀順序標註，研究團隊設計了一套多階段策展流程。首先對 Typhoon OCR 1.5 的訓練語料進行規則式過濾，檢查語法、token 重複、LaTeX 與表格格式、邊界框以及重複樣本。接著針對新收集的泰文文件池（PDF、網頁影像、報紙、電子書、Typhoon OCR 1.5 頁面樣本），採用自動化標註、規則檢查與 LLM 驗證的迭代流程：較大的視覺語言模型（如 Infinity-Parser2-Pro）產生初始版面 JSON 標註，其他大型模型產生 Markdown 與關鍵資訊擷取標註；接著以確定性規則檢查候選標註，並由 LLM 評審根據頁面影像為每個版面標註打分數。

**GRPO 強化學習階段**

在監督式微調 (SFT) 完成後，研究團隊採用群組相對策略最佳化 (Group Relative Policy Optimization, GRPO) 進行第二階段訓練。GRPO 的設計包含兩個關鍵要素：任務獎勵 (task rewards) 與懲罰未完成回應的規則 (rule penalizing unfinished responses)。任務獎勵根據不同任務類型（如版面解析的編輯距離、擷取任務的欄位準確率）給予回饋；未完成懲罰則針對模型產生重複迴圈 (repetition loops) 或提前停止等失敗模式進行負面回饋。這種設計直接針對序列層級的表現進行最佳化，而非僅僅是 token 層級的損失。

#### 實驗數據解讀

**泰文基準測試的顯著進步**

在 Thai MDPBench 上，Typhoon OCR 2 2B 模型達到 80.7 分，相較 Typhoon OCR 1.5 的 68.9 分提升 11.8 分（相對提升約 17.1%）。這個進步幅度在 OCR 領域屬於相當顯著的突破，反映了從純轉錄到結構化解析的任務擴展所帶來的價值。在 ThaiOCRBench 上，2B 模型達到 59.91 分，相較前代的 40.45 分提升 19.46 分（相對提升約 48.1%）。ThaiOCRBench 涵蓋辨識 (recognition)、擷取 (extraction) 與文件理解 (document understanding) 三個面向，這個基準上的大幅躍升直接證明了多任務設計的有效性——單一模型不僅保留了轉錄能力，還獲得了擷取與理解能力。

**多語言能力的保持**

在英文 olmOCR-bench 上，2B 模型達到 84.7 分，與基礎模型 Infinity-Parser2-Flash 的 84.4 分幾乎持平（差距僅 0.3 分）。在 OmniDocBench（同時評估英文與中文）上，2B 模型達到 90.97 分，與基礎模型的 91.03 分同樣接近（差距僅 0.06 分）。這些結果顯示，雖然 Typhoon OCR 2 的訓練資料以泰文為主（34.9%），但並未犧牲對英文與中文的處理能力。這對於實際部署至關重要——泰國的商業環境中，文件經常混合泰文、英文與中文內容。

**GRPO 的失敗模式改善效果**

在 MDPBench 上，GRPO 將 2B 模型出現重複迴圈的頁面平均占比 (mean share of pages) 從 3.2% 降至 0.7%，降幅達 78.1%。這個指標衡量的是模型陷入無限重複生成特定 token 序列的失敗模式，是視覺語言模型常見的退化症狀。然而，對於 0.8B 模型，GRPO 帶來的分數提升較小且統計上不確定 (statistically uncertain)，這暗示 GRPO 的效益可能與模型容量有關——較小的模型可能缺乏足夠的策略空間來從獎勵信號中學習有意義的行為調整。

**實驗結果的整體意涵**

這些數據共同描繪出一個清晰的價值主張：Typhoon OCR 2 在泰文任務上實現了質的飛躍，同時在多語言任務上保持了與專門解析器相當的水準。這種「泰文專精、多語言通用」的定位，對於以泰國為主要市場、但需要處理跨語言文件的企業用戶而言，具有極高的實用價值。

#### 與現有研究的比較

**相較於 Typhoon OCR 1.5 的定位演進**

Typhoon OCR 1.5 是一個純粹的泰文轉錄模型，其設計目標是將頁面影像轉換為文字序列。Typhoon OCR 2 則代表了任務範式的根本轉變：從「看圖轉文字」進化為「看圖理解並回應」。這種演進反映了文件處理領域的整體趨勢——從 OCR 引擎轉向文件智能 (document intelligence)，類似於 Azure Form Recognizer、Amazon Textract 等商業服務的演進路線。然而，Typhoon OCR 2 的差異化在於其開放權重 (open-weight) 特性，以及對泰文的深度優化。

**相較於基礎解析器的改進**

Typhoon OCR 2 並非從零訓練，而是從 Infinity-Parser2-Flash 與 OvisOCR2 進行適配。這種「基於專家模型進行領域特化」的策略，在資料效率與最終效能之間取得了良好平衡。相較於直接使用基礎解析器，Typhoon OCR 2 在泰文任務上的優勢顯著（Thai MDPBench 提升 11.8 分、ThaiOCRBench 提升 19.46 分），同時在英文與中文任務上幾乎沒有退化。這種「領域特化不犧牲通用能力」的現象，在遷移學習文獻中稱為「災難性遺忘的緩解」，其成功可能歸功於多語言資料的混合訓練（65.1% 的非泰文資料）。

**相較於商業 OCR 服務的定位**

雖然論文中未直接與 Google Document AI、Azure Form Recognizer 等商業服務進行比較，但 Typhoon OCR 2 的開放權重策略提供了商業服務無法比擬的優勢：資料隱私（無需將文件上傳至第三方 API）、客製化能力（可針對特定領域微調）、以及成本可控性（無按次計費）。對於泰國的金融機構、政府機關或醫療院所等需要處理敏感文件的組織，這種部署模式具有實質吸引力。

**限制與不足**

儘管成果亮眼，論文也存在若干限制值得關注。首先，0.8B 模型的 GRPO 效益不確定，這暗示小型模型在強化學習階段可能需要不同的超參數或獎勵設計。其次，雖然涵蓋泰文、英文、中文三種語言，但對於其他東南亞語言（如越南文、印尼文、馬來文）的支援付之闕如，而這些語言在泰國的商業環境中同樣常見。再者，論文中對於「未完成回應」的具體定義與偵測方式著墨不多，這使得重現 GRPO 訓練流程存在一定困難。

#### 可重現性評估

Typhoon OCR 2 在可重現性方面展現了極為積極的態度，這在學術界與產業界的交界處尤為難得。

**模型權重與部署格式**

研究團隊釋出了兩個模型尺寸（2B 與 0.8B）的完整權重，並提供多種部署格式以適應不同的硬體環境與使用情境：GGUF 格式適合 CPU 推理與 llama.cpp 生態系；MLX（8-bit）格式針對 Apple Silicon 最佳化；Ollama 格式則提供一鍵部署的便利性。這種多格式策略大幅降低了實際部署的門檻。

**軟體工具鏈**

團隊提供了完整的 Python 套件（可透過 `pip install typhoon-ocr2` 安裝），這意味著開發者只需數行程式碼即可調用模型。此外，OCR 遊樂場 (OCR playground) 提供了無需編程的互動式體驗，API 文件則詳細說明了程式化介面的使用方式。

**評測程式碼與基準**

評測程式碼 (evaluation code) 已在 GitHub 開源，這對於學術界進行公平比較至關重要。然而，論文中提及的 Thai MDPBench 與 ThaiOCRBench 等基準測試的具體建構細節、評分標準、以及資料授權狀態，在提供的文本中未完整說明，這可能對完全重現實驗結果構成挑戰。

**訓練資料的限制**

雖然論文中描述了訓練資料的組成比例（泰文 34.9%、多語言 65.1%），但具體的資料來源、標註流程、以及資料授權狀態在提供的文本中僅有部分揭露。內部泰文資料集（47,031 筆）似乎未公開，這限制了對泰文特化效果的深入分析。

**整體可重現性評級**

綜合考量，Typhoon OCR 2 在「模型部署」與「推論使用」層面具有高度可重現性，但在「完整訓練流程重現」層面存在中等程度的困難——尤其是 GRPO 階段的獎勵設計與泰文標籤建構流程的具體細節。

#### 未來研究方向

**多語言擴展的策略性機會**

泰國作為東南亞的區域樞紐，與越南、印尼、馬來西亞、緬甸、柬埔寨、寮國等國有密切的經貿往來。將 Typhoon OCR 2 擴展至這些東南亞語言，將創造巨大的商業價值。技術上，可以借鑒現有的多語言混合訓練策略，但需要解決低資源語言標註資料稀缺的問題。潛在的研究方向包括：跨語言遷移學習、零樣本或少樣本擷取能力、以及多語言版面解析的統一表示。

**獎勵設計的深化研究**

0.8B 模型在 GRPO 階段表現出的「統計上不確定」效益，揭示了小型視覺語言模型強化學習的開放問題。未來研究可以探索：模型容量與 GRPO 效益的關係曲線、針對小型模型的獎勵塑形 (reward shaping) 策略、以及課程式學習 (curriculum learning) 在 GRPO 中的應用。此外，「未完成回應」的偵測與懲罰機制本身也值得深入研究——是否可以設計更細粒度的失敗模式分類（如重複、提前停止、幻覺內容），並為每類設計專門的懲罰？

**結構化擷取的能力邊界**

雖然 Typhoon OCR 2 展示了從圖表擷取數值、從表單擷取欄位的能力，但對於更複雜的結構（如多層嵌套表格、跨頁表格、帶有註解的圖表）的處理能力仍待探索。此外，擷取任務的「幻覺」問題——模型在無法從影像中找到答案時編造內容——是文件智能系統的關鍵風險，需要專門的偵測與緩解機制。

**與大型推理模型的整合**

近期大型推理模型（如 OpenAI o1、DeepSeek-R1）在複雜推理任務上展現驚人能力。將 Typhoon OCR 2 作為這類模型的「視覺前端」，讓大型推理模型負責多步驟的文件理解與推理，可能是一個有前景的研究方向。例如，使用者可以上傳一份複雜的財報，要求模型進行跨表格的趨勢分析與異常偵測。

**效率與部署的最佳化**

雖然 0.8B 模型已經相當精簡，但對於邊緣裝置（如手機、嵌入式系統）部署仍有挑戰。未來研究可以探索：知識蒸餾 (knowledge distillation) 將 2B 模型的能力轉移至更小的模型、量化感知訓練 (quantization-aware training) 以支援 4-bit 或更低精度推理、以及專門的硬體加速器設計。

**評測基準的標準化**

ThaiOCRBench 與 Thai MDPBench 的釋出是重要的貢獻，但文件智能領域仍缺乏統一的跨語言評測標準。未來可以推動建立涵蓋多語言、多任務、多文件類型的綜合基準，並引入「人類專家對齊」作為終極評估標準，以更全面地衡量實用價值。

## 論文問答

**Q1：Typhoon OCR 2 試圖解決 Typhoon OCR 1.5 無法處理的什麼核心問題？**
A：Typhoon OCR 1.5 僅專注於泰文文件的純轉錄任務，但在真實的文件工作流程中，使用者往往需要的不只是文字內容，而是兩種更高層次的處理：針對性的資訊擷取（例如從圖表中讀取特定數值、從表單中取出特定欄位），以及保留整頁版面結構的結構化解析。Typhoon OCR 2 透過單一模型同時支援這兩種任務，使用提示詞（prompt）來選擇任務模式，讓使用者能直接從頁面影像中取得所需資訊，而無需先做 OCR 再交給另一個語言模型處理。這樣的設計大幅簡化了工作流程，並提升了在多語言、混合文件環境中的實用性。

**Q2：為什麼傳統的「先 OCR 再用 LLM 擷取」兩步驟流程在實務上效率不佳？**
A：兩步驟流程需要先將整份文件完整轉錄為文字，再將文字傳遞給語言模型進行資訊擷取，這不僅耗費大量運算資源，也增加了錯誤累積的風險——OCR 的錯誤會直接影響後續 LLM 擷取的準確度。此外，這種流程無法保留版面資訊（如邊界框、閱讀順序、表格結構），對於需要視覺對齊的應用場景（例如高亮來源、索引章節）來說是不足的。Typhoon OCR 2 將這兩個步驟合併為單一步驟，直接從頁面影像產生結構化輸出，既減少延遲與成本，也保留了版面元資料供下游應用使用。

**Q3：為什麼泰文文件理解是一個特別具有挑戰性且值得重視的研究方向？**
A：泰文具有複雜的書寫系統，包括聲調標記、特殊的字元組合規則，以及缺乏詞間空格的特性，這使得泰文 OCR 一直比英文困難。此外，公開的泰文文件版面標註資料非常稀少，多數現有的多語言文件解析模型在泰文上的表現明顯不佳，這對泰國的數位化轉型與政府、企業文件自動化造成了實際障礙。Typhoon OCR 2 將泰文視為核心焦點，並透過策展高品質的泰文標註資料來填補這個空缺，對泰國在地 AI 應用生態系具有重要意義。

**Q4：Typhoon OCR 2 的核心架構與訓練方法是什麼？**
A：Typhoon OCR 2 採用兩種規模的精簡模型（2B 與 0.8B 參數），分別從兩個專門的開放文件解析器初始化：較大的 2B 模型來自 Infinity-Parser2-Flash，較小的 0.8B 模型來自 OvisOCR2，兩者皆使用相同的版面 JSON 輸出格式。訓練流程分為兩個階段：首先在策展的泰文資料與公開多語言資料上進行監督式微調（SFT），接著使用群組相對策略最佳化（GRPO）並搭配任務獎勵與懲罰未完成回應的規則來進一步優化。這樣的設計讓模型能同時具備多語言版面解析能力與任務特定的擷取能力。

**Q5：GRPO 在 Typhoon OCR 2 中扮演什麼角色？它解決了哪些具體問題？**
A：GRPO 是一種序列層級的策略最佳化方法，在 Typhoon OCR 2 中用於改善模型的整體表現並減少特定失敗模式。最顯著的成果是將 2B 模型在 MDPBench 上出現重複迴圈（repetition loops）的頁面平均占比從 3.2% 大幅降低至 0.7%，這代表模型不再陷入無限重複生成相同內容的退化行為。此外，GRPO 也透過任務獎勵引導模型產生更符合任務需求的輸出，並透過懲罰未完成回應的規則避免模型提前停止生成。值得注意的是，對於 0.8B 模型，GRPO 帶來的分數提升在統計上並不確定，這顯示 GRPO 的效果可能與模型容量有關。

**Q6：在缺乏公開泰文版面標註資料的情況下，Typhoon OCR 2 如何建構高品質的泰文訓練資料？**
A：研究團隊設計了一個多階段的策展流程來處理泰文標註資料稀缺的問題。首先，他們對 Typhoon OCR 1.5 的原始訓練語料進行規則式過濾，檢查語法、token 重複、LaTeX 與表格格式、邊界框與重複項目，以去除損壞檔案與標註雜訊。接著，他們從 PDF、網頁影像、報紙、電子書與 Typhoon OCR 1.5 的頁面樣本中收集新的泰文文件，並使用更大的視覺語言模型（如 Infinity-Parser2-Pro）產生初始版面 JSON 標註，再由其他大型模型產生 Markdown 與關鍵資訊擷取標註。最後，透過確定性規則檢查與 LLM 評審（將候選版面標註與頁面影像比對並給予品質分數）來過濾低品質樣本，必要時進行人工審查。

**Q7：Typhoon OCR 2 在主要基準測試上的關鍵結果為何？**
A：在泰文任務上，Typhoon OCR 2 2B 模型在 Thai MDPBench 上取得 80.7 分，遠高於 Typhoon OCR 1.5 的 68.9 分；在涵蓋辨識、擷取與文件理解的 ThaiOCRBench 上則取得 59.91 分，相較於 Typhoon OCR 1.5 的 40.45 分有顯著進步。在所有評測的開放模型中，2B 模型在這兩個泰文基準上都取得了最高分，確立了其在泰文文件處理上的領先地位。這些結果顯示 Typhoon OCR 2 不僅繼承了前代模型的轉錄能力，還大幅擴展了任務範圍與準確度。

**Q8：Typhoon OCR 2 2B 模型在英文與中文任務上的表現如何？是否犧牲了多語言能力來強化泰文？**
A：Typhoon OCR 2 2B 模型在英文 olmOCR-bench 上取得 84.7 分，與其基礎模型 Infinity-Parser2-Flash 的 84.4 分幾乎持平；在同時評估英文與中文的 OmniDocBench 上取得 90.97 分，與基礎模型的 91.03 分也幾乎相同。這顯示模型在大幅強化泰文能力的同時，並未犧牲其在英文與中文上的版面解析表現，成功維持了多語言的泛化能力。這樣的結果對於需要在泰文、英文、中文混合環境中工作的使用者來說特別有價值，因為他們可以使用單一模型處理多語言文件而無需切換工具。

**Q9：GRPO 的消融實驗顯示了哪些關鍵發現？**
A：最關鍵的消融發現是 GRPO 對於減少重複迴圈有顯著效果：2B 模型的頁面平均占比從 3.2% 降至 0.7%，這代表 GRPO 的規則懲罰機制確實有效解決了模型陷入退化生成的問題。然而，對於 0.8B 模型，GRPO 帶來的分數提升在統計上並不確定，這暗示 GRPO 的效益可能與模型容量有關——較大的模型有更多能力從策略最佳化中獲益，而較小的模型可能因為容量限制而難以充分利用 GRPO 的獎勵訊號。這項發現對於未來在資源受限環境中部署小型模型時的訓練策略選擇具有重要參考價值。

**Q10：哪些實際應用場景最能受益於 Typhoon OCR 2？**
A：Typhoon OCR 2 特別適合需要從文件中快速擷取特定資訊的工作流程，例如金融機構從發票、合約中自動擷取金額、日期與簽署人欄位；政府機關從表格化文件中讀取身分證號碼、地址等資料；以及研究人員從圖表中直接取得數據而無需手動記錄。此外，對於需要保留版面結構的應用（如文件索引、章節搜尋、將個別表格送入資料處理流程），結構化全頁解析功能也提供了極大的便利。單一模型同時支援擷取與解析的特性，讓使用者可以用同一個工具處理多元任務，降低了整合多個系統的複雜度。

**Q11：Typhoon OCR 2 在產品化部署上做了哪些考量？**
A：研究團隊釋出了兩種模型規模（2B 與 0.8B）以滿足不同的部署需求：較大的 2B 模型提供最佳效能，較小的 0.8B 模型則適合資源受限的環境。在模型格式方面，他們提供了多種選擇，包括 GGUF（便於本地 CPU/GPU 部署）、MLX 8-bit 量化（適合 Apple Silicon）、Ollama 整合（便於快速啟動）以及 Python 套件（pip install typhoon-ocr2），讓不同技術背景的使用者都能輕鬆採用。此外，他們也提供了 OCR 遊樂場（playground）作為線上展示、完整的 API 文件、評測程式碼與基準測試套件，這種全方位的釋出策略大幅降低了採用門檻並促進了社群參與。

**Q12：Typhoon OCR 2 對泰國 AI 生態系與更廣泛的研究社群有什麼影響？**
A：對泰國在地 AI 社群而言，Typhoon OCR 2 提供了一個專為泰文最佳化的開放權重模型，填補了現有開源工具在泰文支援上的不足，這對於推動泰國的數位轉型、文件自動化與政府服務現代化具有實質貢獻。對更廣泛的研究社群而言，該工作展示了如何透過策展高品質的在地語言資料、結合 SFT 與 GRPO 的訓練策略，將通用的多語言模型適配到資源較少的語言上，這套方法論可應用於其他低資源語言。此外，釋出的評測套件（如 ThaiOCRBench）也為未來的泰文 OCR 研究提供了標準化的評估基準，有助於促進可比較的研究進展。

**Q13：Typhoon OCR 2 存在哪些已知的限制？**
A：根據論文的實驗結果，0.8B 模型在 GRPO 訓練後的分數提升在統計上並不確定，這意味著小型模型可能無法完全從 GRPO 中獲益，在某些任務上的表現可能不如 2B 模型。此外，雖然模型在泰文、英文、中文的全頁解析上表現優異，但論文中並未明確說明對於其他語言（如日文、韓文、阿拉伯文等）的支援程度，這可能限制了其在更廣泛多語言場景中的應用。另一個潛在限制是模型對於極度複雜或非標準版面（如手寫文件、低品質掃描件、特殊排版的歷史文件）的處理能力，這些場景在論文中並未深入探討。

**Q14：Typhoon OCR 2 還有哪些失敗案例或弱點值得注意？**
A：雖然 GRPO 大幅降低了重複迴圈的發生率（從 3.2% 降至 0.8B 模型的 0.7%），但這個問題並未完全消除，代表在某些輸入下模型仍可能產生退化輸出。此外，對於需要極高精度邊界框預測的應用（如需要像素級對齊的版面分析），模型輸出的是標準化邊界框，可能需要後處理才能用於精細的視覺任務。另一個值得關注的弱點是模型在處理極長文件或多欄複雜版面時的表現，論文的評估主要集中在單頁文件上，對於跨頁結構（如表格跨越多頁、章節連續性）的處理能力尚未明確驗證。

**Q15：基於這項研究，未來有哪些值得探索的方向？**
A：未來的一個重要方向是將 Typhoon OCR 2 的方法論擴展到更多低資源語言，特別是東南亞地區的其他語言（如越南文、印尼文、緬甸文），這些語言同樣面臨公開版面標註資料稀缺的問題。另一個方向是探索如何讓小型模型（如 0.8B）更有效地從 GRPO 中獲益，可能需要設計更適合小模型的獎勵函數或訓練策略。此外，將模型能力擴展到跨頁文件理解、手寫文件辨識、即時串流處理等更複雜的場景，也是值得投入的研究方向。最後，結合視覺語言模型進行更深層次的文件推理（如文件摘要、跨文件資訊整合）將是 Typhoon OCR 系列未來發展的自然延伸。

## 實務應用指南

### 適用場景

1. **泰國金融與保險業的文件自動化**：銀行開戶表單、保險理賠文件、貸款申請書等泰文表單，可直接以 prompt 要求模型回傳欄位值（如「提取此頁的客戶姓名、身分證字號、申請日期」），省去 OCR 後再串接 LLM 抽取資訊的兩階段流程。

2. **跨國企業的多語言文件歸檔**：東南亞總部常見泰英中三語並陳的合約、報告、報紙。單一模型即可批次處理，輸出統一 JSON 版面元素（含邊界框與閱讀順序），方便後續索引、搜尋與翻譯 pipeline。

3. **政府與研究機構的圖表數位化**：從泰國統計年報、研究報告中擷取圖表資料（chart_type、x 軸年份、y 軸數值），直接轉為結構化資料供 Excel、BI 工具或資料庫使用。

4. **法律與合規文件的版面保留**：律師事務所需要保留原始版面（標題、條文、表格、簽章位置）以供引用與比對。模型回傳的 bounding box 與閱讀順序可讓應用程式高亮原始位置、輸出可重排的 Markdown。

5. **出版業與數位典藏**：泰文報紙、舊書、e-book 的結構化轉錄，支援以 HTML 表示表格、LaTeX 表示公式，方便後續轉 EPUB、生成無障礙版本、或建立全文檢索系統。

### 實作前置條件

**資料準備**
- 泰文文件影像（PDF 轉圖、掃描文件、網頁截圖），建議解析度 200–300 DPI
- 針對性任務的 prompt 範本與少量標註樣本（用於評估與驗證）
- 領域詞彙表（人名、地名、機構名）以提升後處理準確率

**計算資源**
- 0.8B 模型：單張消費級 GPU（如 RTX 3090/4090，約 8–12 GB VRAM）即可推論；亦可走 MLX 8-bit 或 Ollama 在 Apple Silicon 上執行
- 2B 模型：建議 16 GB 以上 VRAM（如 A100、RTX 4090），或使用 GGUF 量化版本部署於 CPU 伺服器
- 批次處理大量頁面時，建議準備 24 GB 以上 VRAM 的 GPU 以提升吞吐量

**技能需求**
- Python 程式設計（讀寫 JSON、呼叫 API）
- Prompt engineering 基礎（理解任務導向 prompt 設計）
- 文件版面概念（閱讀順序、bounding box 座標系統）
- 基本的 OCR 後處理（正則表達式、欄位驗證）

### 實作步驟建議

1. **安裝與環境設定**：透過 `pip install typhoon-ocr2` 安裝官方套件，或下載 GGUF/MLX 權重以 Ollama 部署。準備 Python 3.10+ 環境與必要的影像處理套件（Pillow、pdf2image）。

2. **選擇模型規模**：先以 0.8B 模型做概念驗證與 prompt 迭代；若品質不足或需要處理複雜版面，再升級至 2B 模型。建議在自有資料上跑 ThaiOCRBench 與 MDPBench 子集做基準比較。

3. **設計任務導向 prompt**：根據使用情境撰寫 prompt。擷取任務需明確指定輸出格式（如「回傳 JSON 字典，鍵為 chart_type、years、values」）；全頁解析則使用官方提供的版面解析 prompt（見論文附錄 A）。

4. **建立輸出後處理 pipeline**：解析模型回傳的 JSON，驗證 bounding box 座標範圍、檢查必填欄位、將 HTML 表格轉為 DataFrame、將 LaTeX 公式轉為可渲染格式。建議加入 schema 驗證（如 Pydantic）以攔截格式錯誤。

5. **建立評估與監控機制**：使用官方評測套件（GitHub 開源）建立內部 benchmark，持續追蹤重複迴圈比例、未完成回應比例、欄位抽取準確率。設定告警閾值（例如重複迴圈 > 2% 時觸發人工抽檢）。

6. **部署與整合**：以 REST API 或批次任務形式部署；高併發場景建議加上佇列（如 Redis、Celery）與快取層。針對延遲敏感場景可考慮 0.8B 模型 + 量化部署。

7. **持續優化**：蒐集失敗案例，針對特定文件類型微調 prompt 或準備領域專屬的 SFT 資料。論文顯示 GRPO 訓練能將重複迴圈從 3.2% 降至 0.8B 模型的 0.7%，可作為品質基準。

### 潛在風險與注意事項

- **重複迴圈殘留風險**：雖然 GRPO 已將 2B 模型的重複迴圈比例降至 0.7%，但 0.8B 模型的改善在統計上不顯著。生產環境仍需加入「最大輸出長度限制」與「重複偵測後備援機制」（如偵測到重複字串超過 N 次則切換至備用模型或人工處理）。

- **未完成回應**：GRPO 訓練中加入懲罰未完成回應的規則，但長文件或複雜版面仍可能發生。建議設定輸出長度下限檢查，並對關鍵欄位為空的情況觸發重試。

- **邊界框精度限制**：模型回傳的是標準化座標，應用於高精度的版面重建（如 PDF 重排）時可能不夠細緻。對版面敏感的場景，建議結合版面分析後處理或人工抽檢。

- **多語言混排的閱讀順序**：泰英中三語並陳時，閱讀順序可能與人類直覺不同。建議在關鍵流程加入人工抽樣驗證，特別是合約、法律文件等順序敏感的場景。

- **領域偏移**：模型在訓練資料外的特殊文件（如手寫表格、古泰文、特殊符號）表現可能下降。建議準備領域專屬的 few-shot 範例，或在 prompt 中加入領域提示。

- **資料隱私**：處理含個人資訊的文件時，務必確認部署環境符合當地法規（如泰國 PDPA）。建議優先採用本地部署而非雲端 API。

### 與其他技術的整合建議

- **與 LLM 整合做進階理解**：將 Typhoon OCR 2 的結構化輸出（特別是版面元素 JSON）作為 LLM（如 GPT-4、Claude）的輸入，可進一步做摘要、問答、跨文件關聯分析。版面元素的位置資訊能讓 LLM 的回答附帶來源引用。

- **與 RAG 系統整合**：將文件以版面元素為單位切塊（chunking），bounding box 可作為視覺化引用來源，閱讀順序保證檢索結果的連貫性。適合建構可追溯的企業知識庫。

- **與文件管理系統（DMS）整合**：將 JSON 輸出中的 category 欄位映射為 DMS 的中繼資料標籤，bounding box 用於縮圖標註，HTML 表格直接匯入資料庫。

- **與 ETL pipeline 整合**：在資料工程流程中，將 OCR 階段輸出的結構化資料直接寫入資料湖或資料倉儲，省去傳統 OCR + 規則抽取 + LLM 抽取的多階段架構。

- **與表單辨識（Form Recognition）系統互補**：若已有專門的表單辨識系統，可將 Typhoon OCR 2 用於非表單文件（合約、報告、報紙），形成互補的雙軌架構。

- **與翻譯工作流整合**：版面元素的閱讀順序與位置資訊可讓翻譯後的內容正確回流到原始版面，支援「保留版面的多語言文件生成」。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先從官方 OCR playground（opentyphoon.ai）開始，親手測試不同 prompt 對同一張泰文文件的影響，理解「同一模型、不同任務」的運作方式。接著安裝 Python 套件，跑幾個官方範例，觀察 JSON 輸出的結構。不需要深入理解 GRPO 或訓練細節，重點放在「如何設計好的 prompt」與「如何處理輸出」。

**給 AI 工程師**：重點關注模型部署選型（GGUF/MLX/Ollama/vLLM）、推論效能優化（量化、批次、prefix caching）、以及與現有系統的整合架構。建議在自有資料上重現論文的評估方法，特別是重複迴圈比例與未完成回應率，作為上線前的品質門檻。論文的附錄 A（prompt 範本）與附錄 B（資料混合比例）對工程實作有直接參考價值。

**給研究人員**：論文的價值在於「小型開放模型 + GRPO + 領域資料」的可複製配方。建議深入閱讀第 2.4 與 2.5 節的訓練細節，特別是 GRPO 的任務獎勵設計與未完成回應懲罰規則，這對其他領域（如表格問答、文件摘要）的 RL 微調有借鑑意義。ThaiOCRBench 與 Thai MDPBench 的建構方式也值得參考，可作為建立其他低資源語言 benchmark 的模板。

**給產品經理**：核心訊息是「一個模型、兩種任務、三種語言」，這大幅簡化了產品架構——不需要分別採購 OCR 引擎、版面分析工具、欄位抽取 LLM。建議評估自家文件流程中「OCR + 後處理」環節的痛點（特別是泰文相關），將 Typhoon OCR 2 作為整合方案。論文的 benchmark 數字（ThaiOCRBench 59.91 vs 1.5 的 40.45）是評估投資報酬率的關鍵指標，但也要注意 0.8B 模型的統計不確定性，建議先做小規模 POC 再決定部署規模。
