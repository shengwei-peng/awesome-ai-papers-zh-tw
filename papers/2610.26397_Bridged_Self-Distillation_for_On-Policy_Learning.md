## ⚡ TL;DR

同策略蒸餾中，較強教師的解法對小學生過難，且詞元機率在跨分詞器或封閉 API 下不可用。
本文提出橋接自蒸餾（BSD），以教師推理軌跡作為特權上下文，由學生副本在自身詞元空間評分引導訓練。
在十二組師生配對與三個數學基準上，BSD 於共享分詞器、跨分詞器及封閉 API 情境皆優於基線。

## 摘要翻譯

同策略蒸餾（On-Policy Distillation, OPD）能將強教師模型的推理能力轉移至較小的學生模型。然而，從更強的教師模型進行蒸餾面臨兩種不匹配：其解題方法對較小的學生模型而言可能難以模仿，且其詞元層級機率（token-level probabilities）可能與學生模型不相容，甚至無法取得。現有方法透過不同形式的監督來處理這些情境。為此，我們提出橋接自蒸餾（Bridged Self-Distillation, BSD），一個用於從任何提供推理軌跡（reasoning traces）的教師模型進行蒸餾的統一框架（unified framework）。作為蒸餾來源的模型（稱為外部教師，external teacher）首先以離線（offline）方式產生一條推理軌跡作為特權上下文（privileged context）。學生模型在沒有此上下文的情況下產生 rollout（推演軌跡），而條件化於該上下文的學生模型副本（作為自教師，self-teacher）則在學生模型自身的詞元空間（token space）中對相同的 rollout 評分。BSD 利用所得的詞元層級引導（token-level guidance）來調整失敗的 rollout（unsuccessful rollouts）上的更新，並由驗證器（verifier）提供結果訊號（outcome signal）。由於外部教師僅用於產生文字，因此同一訓練流程（training procedure）適用於所有教師情境：共享分詞器（shared tokenizer）、跨分詞器（cross-tokenizer）及封閉 API（closed API）教師模型。在這些情境中，BSD 均優於基礎模型（base model），並超越為各情境量身打造的基線方法（baseline），為蒸餾提供了一條新穎且統一的途徑（unified pathway）。程式碼公開於：https://github.com/TUMLegalTech/Bridged-Self-Distillation

### 核心貢獻（3～5點）
- **問題識別**：系統性地指出從更強教師模型進行蒸餾時存在的兩種不匹配——解題難度不匹配（教師解法對小學生過於困難）與詞元層級機率不匹配（教師詞元機率可能與學生不相容或不可得，如封閉 API 情境）。
- **統一框架 BSD**：提出橋接自蒸餾（Bridged Self-Distillation），透過「外部教師提供推理軌跡作為特權上下文 → 自教師在學生自身詞元空間評分」的橋接設計，將不同蒸餾情境統一於單一訓練流程之下。
- **跨情境通用性**：BSD 適用於共享分詞器、跨分詞器及封閉 API 三種教師情境，無需為各情境設計專屬方法，大幅簡化了蒸餾系統的工程複雜度。
- **實驗優勢**：在上述三種情境中，BSD 均穩定優於基礎模型，並超越各情境專屬的基線方法，驗證了統一途徑的實證有效性。

### 適合對象
從事大型語言模型（LLM）知識蒸餾、推理能力壓縮、強化學習後訓練（post-training）研究的研究者與工程師；尤其適合關注跨分詞器蒸餾、黑盒/封閉 API 教師蒸餾，以及希望以統一方法處理多種蒸餾場景的實務團隊。此外，對可驗證獎勵強化學習（RLVR）與推理模型小型化感興趣的學術讀者亦能從中獲益。

## 深度分析

#### 方法論解析

**核心問題與動機**

本文聚焦於同策略蒸餾 (On-Policy Distillation, OPD) 在面對強教師時的兩個核心失配 (mismatch) 問題：(1) 教師解題路徑對小學生模型而言過於困難，難以直接模仿；(2) 教師的詞元層級機率 (token-level probabilities) 可能與學生不相容，甚至在封閉 API 情境下根本無法取得。傳統 OPD 方法因此被迫針對不同教師存取場景設計不同的訓練訊號——共享分詞器 (shared tokenizer) 採詞元層級分佈匹配 (token-level distribution matching)、跨分詞器 (cross-tokenizer) 採詞彙映射 (vocabulary mapping)、封閉 API (closed API) 採基於回應的回饋 (response-based feedback，如評分標準 rubric 或採樣延續 sampled continuations)。這種場景特定 (scenario-specific) 的設計不僅工程複雜，也限制了蒸餾方法的通用性。

**BSD 框架設計**

橋接自蒸餾 (Bridged Self-Distillation, BSD) 的關鍵洞見在於：將外部教師的角色從「提供詞元機率分佈」轉變為「提供推理軌跡 (reasoning trace) 作為特權上下文 (privileged context)」。具體而言：

1. **離線推理軌跡生成**：外部教師 (external teacher) 為每個問題 $x$ 產生推理軌跡 $z$，此步驟可離線 (offline) 完成，僅需文字輸出，不需任何機率資訊。

2. **同策略 rollout 生成**：學生模型 $\pi_\theta$ 在沒有 $z$ 的條件下，自行產生 rollout $y$，這保留了同策略學習 (on-policy learning) 的本質。

3. **自教師評分**：學生的一個凍結副本 (frozen copy) 在條件化於 $z$ 下扮演自教師 (self-teacher) 角色，對相同 rollout 的詞元進行評分。由於自教師與學生使用完全相同的詞元空間 (token space)，所有評分都在學生自身的詞元空間中完成，徹底迴避了跨分詞器對齊問題。

4. **詞元層級引導計算**：核心訊號為兩個條件機率之比：
$$u_t = \frac{\pi_\theta(y_t \mid x, z, y_{<t})}{\pi_\theta(y_t \mid x, y_{<t})}$$
此比值衡量「獲得特權上下文 $z$ 後，學生對同一詞元的預測信心如何變化」。當 $u_t > 1$ 表示有 $z$ 後預測更確定，$u_t < 1$ 則表示反而更不確定。

5. **優勢函數調整**：BSD 沿用 RLSD 的設計，將 rollout 層級的優勢 $A$ 透過 $u_t$ 進行詞元層級的重新加權：
$$\hat{A}^t_{BSD} = A \cdot \left[(1-\lambda) + \lambda \cdot \text{clip}_{1\pm\epsilon}(u_t)\right]$$
其中 $\lambda \in [0,1]$ 控制詞元層級引導的強度，$\epsilon$ 為 PPO 風格的裁剪參數。由於乘數為正，重新加權保留了 $A$ 的正負號——驗證器 (verifier) 仍決定更新方向，詞元層級引導僅調整失敗 rollout 上的懲罰強度。

**方法論的精妙之處**

BSD 的設計有三個值得強調的精妙之處：

- **統一性**：因為外部教師僅被查詢以產生文字，無論是同系列 (Same Family)、跨系列 (Cross Family) 還是封閉 API 教師，訓練流程完全一致。這消除了場景特定 OPD 的工程負擔。
- **避免模仿陷阱**：不同於 SFT 直接要求學生模仿教師解法，BSD 將教師軌跡作為「提示」而非「標籤」，學生仍生成自己的解題路徑，避免了「小模型模仿大模型推理時的嚴重性能退化」問題。
- **聚焦不確定詞元**：分析顯示 BSD 的引導集中在學生不確定的詞元上，這正是最需要外部知識介入的位置，符合「知識蒸餾應聚焦於資訊量最大處」的直覺。

#### 實驗數據解讀

**實驗設計**

論文在三種教師存取場景下評估 BSD：(1) 共享分詞器、(2) 跨分詞器、(3) 封閉 API，共涵蓋 12 對師生配對，並在三個數學推理基準上進行測試。這種大規模、多場景的實驗設計對於驗證「統一框架」的宣稱至關重要。

**關鍵結果**

- **跨場景有效性**：BSD 在三種場景下均優於基礎模型 (base model)，證明了統一框架的可行性。
- **超越場景特定基線**：BSD 在多數配對中優於為各場景量身打造的基線方法，這是相當強的結果——意味著統一方法不僅方便，性能也具競爭力。
- **避免 SFT 退化**：在若干師生配對中，SFT 出現嚴重性能退化，而 BSD 維持穩定訓練。這印證了「直接模仿強教師推理對小學生過於困難」的假設。
- **引導集中於不確定詞元**：分析顯示 BSD 的詞元層級引導 $\delta_t$ 集中在模型預測不確定的位置，且更強的引導與更大的性能增益相關聯。

**結果的深層意涵**

實驗數據揭示了幾個重要現象：(1) 推理軌跡的品質（完整性）對 BSD 效果有正面影響，這與「更好的提示帶來更好的引導」的直覺一致；(2) 訓練過程穩定，沒有出現策略崩潰跡象，這得益於裁剪機制和驗證器提供的穩定訊號方向；(3) BSD 的成功驗證了「特權上下文 + 自蒸餾」範式的有效性，為後續研究開闢了新方向。

#### 與現有研究的比較

**定位**

BSD 處於三條研究路線的交匯點：(1) 傳統 OPD（共享分詞器下的詞元層級分佈匹配）；(2) 跨分詞器 OPD（詞彙映射方法如 Zhang et al., 2024; Minixhofer et al., 2025; Boizard et al., 2025; Niu et al., 2026; Sun et al., 2026）；(3) 黑盒 OPD（基於評分標準或採樣延續的方法如 Jiang et al., 2023; Ye et al., 2026a; Fang et al., 2026; Xiong et al., 2026; Zhou et al., 2026）。此外，BSD 與同策略自蒸餾 (OPSD) 系列工作（Zhao et al., 2026; Zhang et al., 2026; Yang et al., 2026a）密切相關，特別是 RLSD（Yang et al., 2026a）提供了詞元層級重新加權的數學基礎。

**改進之處**

相對於現有方法，BSD 的主要貢獻在於：

- **統一性 vs. 場景特定**：現有方法需要為不同場景設計不同訓練訊號，BSD 用單一框架覆蓋所有場景，大幅簡化工程實現。
- **避免詞彙映射的誤差**：跨分詞器 OPD 的詞彙映射不可避免地引入對齊誤差，BSD 因在學生自身詞元空間中運作而完全避免此問題。
- **比黑盒方法更精細**：黑盒 OPD 僅能獲得 rollout 層級回饋，BSD 透過自教師獲得詞元層級引導，提供了更細粒度的訓練訊號。
- **比 SFT 更穩定**：SFT 在強弱差距大的師生配對中容易退化，BSD 透過同策略生成避免了此問題。

**侷限性**

- **仍需推理軌跡**：BSD 要求外部教師能產生推理軌跡，對完全無法產生文字的「純黑盒」場景（如僅返回標量分數的 API）不適用。
- **軌跡品質依賴**：BSD 效果依賴於推理軌跡的品質，若教師軌跡本身有誤或過於冗長，可能引入雜訊。
- **計算成本**：雖然外部教師僅需離線產生軌跡，但自教師的評分仍需額外的前向傳播，增加了訓練計算量。
- **領域泛化**：實驗僅在數學推理基準上驗證，其他領域（如程式碼生成、開放域問答）的有效性有待確認。

#### 未來研究方向

**方法論延伸**

- **多軌跡融合**：當前 BSD 使用單一推理軌跡作為特權上下文，未來可探索多軌跡融合或軌跡選擇機制，以處理教師產生多樣化解法的情況。
- **動態特權上下文**：推理軌跡的哪些部分對學生最有幫助？可研究動態選擇或壓縮軌跡的機制，降低計算成本同時提升引導效率。
- **跨領域泛化**：將 BSD 從數學推理擴展到程式碼生成、開放域問答、多模態推理等領域，驗證統一框架的通用性。
- **與其他 RL 演算法結合**：BSD 目前基於 GRPO，可探索與 PPO、DPO、RLHF 等其他強化學習範式的結合。

**理論分析**

- **收斂性分析**：BSD 的詞元層級重新加權如何影響策略優化的收斂速度與穩定性？嚴格的理論分析將加深方法理解。
- **引導強度的最優化**：$\lambda$ 的選擇目前可能是經驗性的，可研究自適應調整 $\lambda$ 的理論基礎。
- **特權上下文的資訊理論分析**：從資訊理論角度分析推理軌跡提供了多少「有用訊號」，以及如何衡量學生對這些訊號的利用效率。

**應用拓展**

- **多語言蒸餾**：BSD 的統一性使其天然適合跨語言蒸餾場景，可探索將強英語推理模型的能力遷移到其他語言的小模型。
- **聯邦式或隱私敏感場景**：BSD 僅需教師的文字輸出，符合資料最小化原則，在隱私敏感場景下有應用潛力。
- **持續學習**：BSD 可作為持續學習框架的一環，使模型能從不同教師持續吸收新知識而不產生災難性遺忘。
- **人機協作**：BSD 的「特權上下文」概念可推廣到人類專家提供的提示或反饋，實現更自然的人機協作蒸餾。

**長期願景**

BSD 代表了從「場景特定 OPD」向「統一 OPD」的重要一步，其核心思想——將外部知識轉化為特權上下文，再透過自蒸餾在自身詞元空間中提取引導——具有深遠的通用性。未來研究可探索這一範式在更廣泛的知識遷移場景中的應用，最終目標是實現「任何教師、任何學生、任何場景」皆可蒸餾的通用框架。

## 論文問答

**Q1：BSD 試圖解決什麼核心問題？**
A：BSD 主要解決的是「同策略蒸餾（OPD）」在面對不同教師存取情境時缺乏統一框架的問題。當學生模型試圖從更強的教師模型蒸餾推理能力時，傳統 OPD 需要取得教師的下一詞元分佈並對齊學生的分詞器，但在跨分詞器或封閉 API 的情境下，這些資訊往往無法取得或難以對齊。BSD 透過只要求教師提供「推理軌跡文字」的方式，將不同情境下的蒸餾問題統一為同一套訓練流程，從而大幅降低了對教師內部資訊的依賴。

**Q2：為什麼現有的場景特定 OPD 方法在跨情境時會失效？**
A：現有方法依賴於不同的訓練訊號：共享分詞器時使用詞元層級分佈匹配，跨分詞器時需要建構詞彙映射，封閉 API 時則只能依賴回應評分標準或採樣延續等回饋。這意味著每一種教師存取情境都需要設計專屬的蒸餾演算法，無法跨情境通用。此外，當學生模型遠小於教師時，直接模仿教師的解法（如同 SFT）往往過於困難，導致學生無法有效學習。

**Q3：為什麼統一的蒸餾框架在實務上很重要？**
A：在實務部署中，教師模型可能來自不同來源——同一系列、跨系列、甚至只能透過封閉 API 存取——若每一種情境都需要重新設計訓練流程，將大幅增加研發成本與部署複雜度。一個統一的框架不僅簡化了工程實作，也讓研究者能在不同教師間公平比較蒸餾效果。此外，統一框架有助於累積跨情境的實證經驗，加速小型推理模型的普及。

**Q4：BSD 的核心機制是什麼？**
A：BSD 的核心機制是引入一個「自教師（self-teacher）」，它是學生模型的一份凍結副本，但以教師提供的推理軌跡作為特權上下文進行條件化。學生在沒有此軌跡的情況下產生 rollout，而自教師則在擁有軌跡的情況下對同一 rollout 進行評分。由於兩者使用相同的詞元空間，自教師與學生之間的詞元機率比即可作為詞元層級引導訊號，用來調整失敗 rollout 上的懲罰強度。

**Q5：BSD 相較於既有方法的關鍵創新為何？**
A：關鍵創新在於將「外部教師的推理軌跡」與「學生自身的詞元空間」透過特權上下文橋接起來，避免了直接對齊詞元分佈或建構詞彙映射的需求。這使得同一套訓練流程可以無縫應用於共享分詞器、跨分詞器與封閉 API 三種情境。此外，BSD 將引導訊號集中在「不確定詞元」上，並透過驗證器決定更新方向，使訓練訊號更精準且穩定。

**Q6：BSD 在設計上有哪些重要的選擇？**
A：首先，BSD 選擇只要求教師輸出文字而非內部機率，這大幅降低了對教師的依賴並提升了通用性。其次，BSD 採用「同策略 rollout」而非模仿教師解法，避免了學生因能力差距過大而無法學習的問題。再者，BSD 透過 λ 參數控制詞元層級引導的強度，並使用 clip 機制避免更新幅度過大，這些設計共同保證了訓練的穩定性。

**Q7：BSD 在哪些基準上進行了評估？**
A：BSD 在三個數學推理基準上進行了評估，並涵蓋了十二組教師—學生配對，橫跨共享分詞器、跨分詞器與封閉 API 三種情境。這種大規模、多情境的評估設計使結果具有高度的可信度與泛化性。透過同時比較基礎模型與各情境專屬的基線方法，BSD 能清楚展示其在不同存取條件下的相對優勢。

**Q8：BSD 的關鍵實驗結果為何？**
A：BSD 在所有三種情境下都優於基礎模型，並普遍超越各情境專屬的基線方法。特別值得注意的是，在某些教師—學生配對中，SFT 會出現嚴重的效能退化，而 BSD 則能維持穩定的訓練並持續改進。這顯示 BSD 不僅在通用性上勝出，在個別情境的效能上也具備競爭力。

**Q9：BSD 進行了哪些消融實驗與分析？**
A：分析顯示 BSD 的訓練過程穩定，且能從更完整的推理軌跡中獲益更多。此外，研究發現 BSD 的引導訊號會集中在模型不確定的詞元上，且引導強度與效能提升呈正相關。這些分析不僅驗證了 BSD 設計的合理性，也提供了關於「何時詞元層級引導最有用」的深入洞見。

**Q10：BSD 適用於哪些實務情境？**
A：BSD 特別適用於需要將大型推理模型部署到資源受限環境的場景，例如邊緣裝置、行動應用或即時回應系統。在這些情境下，無法直接使用大型模型，但又希望保留其推理能力，因此需要有效的小型化方案。此外，BSD 也適用於教師模型來自不同供應商或無法取得內部權重的情況，例如透過 API 呼叫商業模型。

**Q11：在產品化 BSD 時需要考量哪些工程因素？**
A：產品化時需考量推理軌跡的產生成本與儲存需求，因為 BSD 需要為每個問題預先生成教師的推理軌跡。此外，自教師與學生共享參數但需要分別進行條件化推論，這會增加訓練時的計算開銷。在部署階段，由於學生模型不再需要特權上下文，因此推理成本與一般小型模型相同，這是 BSD 的一大優勢。

**Q12：BSD 對蒸餾研究領域的影響為何？**
A：BSD 提出了一種「以文字為介面」的蒸餾範式，打破了過去 OPD 對詞元分佈的依賴，這可能啟發後續更多以文字或結構化輸出為基礎的蒸餾研究。同時，BSD 將特權上下文與自蒸餾結合的思路，也可能被推廣到其他需要外部知識引導的學習任務中。整體而言，BSD 為蒸餾研究提供了一條更通用、更實用的新路徑。

**Q13：BSD 存在哪些已知的限制？**
A：BSD 的效能依賴於外部教師所提供推理軌跡的品質，若軌跡本身有誤或過於冗長，可能會影響引導效果。此外，BSD 目前主要在數學推理任務上驗證，對於其他類型的推理任務（如常識推理、程式碼生成）的適用性仍需進一步研究。最後，BSD 需要為每個問題預先產生推理軌跡，這在訓練初期會帶來額外的資料準備成本。

**Q14：BSD 在哪些情況下可能會失敗？**
A：當學生模型與教師模型的差距過大時，即使有推理軌跡作為特權上下文，學生仍可能難以從中提取有用的引導訊號。此外，若任務的正確解法高度多樣化，單一的推理軌跡可能無法涵蓋所有合理的解題路徑，導致引導過於偏頗。在封閉 API 情境下，若 API 對輸出長度或內容有限制，也可能影響推理軌跡的可用性。

**Q15：BSD 未來有哪些值得探索的方向？**
A：未來可探索將 BSD 推廣至多模態推理任務，例如結合視覺或程式碼執行的推理。此外，研究如何讓 BSD 在訓練過程中動態選擇或組合多個推理軌跡，而非依賴單一軌跡，也是值得嘗試的方向。更長期來看，可以探討 BSD 與其他訓練範式（如 curriculum learning 或 self-play）的結合，以進一步提升小型推理模型的能力上限。

## 實務應用指南

### 適用場景

1. **企業內部部署的小型推理模型建置**：當企業希望將雲端大型推理模型（如 GPT、Claude、Gemini 等封閉 API）的推理能力轉移到可在本地端或邊緣裝置部署的小型開源模型時，BSD 統一框架能直接處理「僅能取得文字輸出」的封閉 API 場景，無需詞彙映射或內部 logits 存取。

2. **跨廠商模型家族的知識遷移**：組織同時使用 Llama、Qwen、Mistral 等不同系列模型時，傳統 OPD 因分詞器不同而無法直接對齊分佈。BSD 透過自教師在學生自身詞元空間中產生引導，可無縫處理跨分詞器情境。

3. **教育科技與數學解題助理**：在數學競賽、程式競題、邏輯推理等需要多步推理的應用中，可使用 BSD 將大型解題模型（如 DeepSeek-R1、QwQ）的解題軌跡蒸餾到小型學生模型，使部署成本降低、回應延遲縮短。

4. **領域專屬推理模型微調**：在法律、醫療、金融等垂直領域，可先用領域專家模型或大型通用模型產生高品質推理軌跡作為特權上下文，再以 BSD 訓練小型領域模型，兼顧專業度與推論效率。

5. **多教師協作與持續學習**：當組織希望從多個不同來源（內部大型模型 + 外部 API + 開源強模型）整合知識時，BSD 的統一介面讓所有教師只需提供推理軌跡文字即可參與訓練，簡化多教師管線設計。

### 實作前置條件

**資料需求**
- 訓練題庫：需準備一批具備可驗證答案的問題（如數學題、程式題、邏輯題），建議至少數千至數萬題，並搭配可程式化檢驗正確性的驗證器。
- 推理軌跡資料集：由外部教師針對每道題目產生的逐步推理文本（reasoning trace），可離線批次生成，無需即時互動。
- 學生模型自身的 rollout 資料：在訓練過程中由學生策略即時產生。

**運算資源**
- 學生模型規模建議在 1B–8B 參數區間（論文涵蓋此範圍），需具備一張以上中高階 GPU（如 A100、H100）以支援 RLVR 訓練迴圈。
- 自教師為學生模型的凍結副本，需額外一份與學生等量的記憶體（可透過 gradient checkpointing 或共享權重降低開銷）。
- 外部教師僅在離線階段被呼叫一次產生軌跡，訓練主迴圈不需持續查詢，因此 API 成本可控。

**技能前提**
- 熟悉 PyTorch 與分散式訓練框架（如 DeepSpeed、FSDP）。
- 具備 RLHF/RLVR 經驗，理解 GRPO 等策略梯度演算法。
- 能撰寫或整合題目驗證器（rule-based 或程式化判斷）。
- 對分詞器、詞元空間、logits 對齊等概念有基礎理解。

---

### 實作步驟建議

1. **階段一：資料準備**
   - 蒐集或建構具備可驗證答案的題庫。
   - 選定外部教師（共享分詞器、跨分詞器或封閉 API 皆可），離線為每題產生一條推理軌跡 $z$，儲存為 `(question, reasoning_trace)` 配對。

2. **階段二：基礎建設**
   - 選定學生模型與其凍結副本（自教師）的初始化權重。
   - 實作驗證器介面，輸出二元獎勵 $r \in \{0, 1\}$。
   - 準備 GRPO 訓練管線（rollout 採樣、群組獎勵標準化、clipped policy gradient）。

3. **階段三：BSD 訓練迴圈實作**
   - 對每個問題 $x$，學生在無 $z$ 條件下採樣一組 rollout $\{y^{(i)}\}$。
   - 自教師（學生副本，條件化於 $z$）對相同 rollout 的每個詞元計算機率比 $u_t = \pi_\theta(y_t \mid x, z, y_{<t}) / \pi_\theta(y_t \mid x, y_{<t})$。
   - 計算群組相對優勢 $A$，並依 RLSD 公式重塑為 $\hat{A}_t^{\text{RLSD}} = A \cdot [(1-\lambda) + \lambda \cdot \text{clip}_{1\pm\epsilon}(u_t)]$。
   - 將此詞元層級優勢套用於策略梯度更新，僅在失敗 rollout 上產生實質懲罰調整。

4. **階段四：超參數調校**
   - 調整 $\lambda$（詞元引導強度）與 $\epsilon$（clip 範圍），監控訓練穩定性。
   - 觀察不同 rollout 群組大小 $G$ 對收斂速度與最終效能的影響。
   - 評估推理軌跡品質（完整性、正確性）對 BSD 效果的影響。

5. **階段五：評估與部署**
   - 在保留測試集上評估學生模型（無 $z$ 條件下的純推理效能）。
   - 與 SFT 基線、場景特定 OPD 基線比較，確認 BSD 在目標場景的優勢。
   - 將訓練後的學生模型匯出為標準格式（如 HuggingFace、GGUF），部署至目標環境。

6. **階段六：持續監控**
   - 監控 rollout 成功率、詞元引導幅度、KL 散度等指標。
   - 定期以新資料或新教師軌跡進行增量訓練。

### 潛在風險與注意事項

- **推理軌跡品質低落**：若外部教師產生的軌跡含有錯誤步驟或過於冗長，自教師的條件化引導可能誤導學生。**緩解方式**：對軌跡進行品質過濾（如以驗證器篩選正確軌跡），或採用多數決/重抽樣機制。

- **訓練不穩定**：詞元層級重塑後的優勢可能放大某些位置的梯度，導致策略崩潰。**緩解方式**：謹慎設定 $\lambda$（建議從小值開始，如 0.1–0.3）並使用 clip 機制；監控 KL 散度與獎勵曲線。

- **驗證器繞過風險**：學生可能學會產出通過驗證器但推理不正確的捷徑。**緩解方式**：使用更嚴謹的驗證器（包含步驟檢查），或在獎勵中加入格式與過程約束。

- **API 成本與延遲**：即使 BSD 訓練主迴圈不需即時查詢教師，初始軌跡生成階段仍可能消耗大量 API 額度。**緩解方式**：採用快取、批次處理，並考慮以較便宜的教師產生初稿、再以強教師精修。

- **跨分詞器語意偏移**：自教師雖在學生詞元空間運作，但條件化於不同分詞器產生的軌跡仍可能引入語意偏差。**緩解方式**：對軌跡進行語言正規化，或在訓練初期以較小 $\lambda$ 讓學生逐步適應。

- **過度依賴特權上下文**：若學生在訓練中過度擬合 $z$ 提供的條件，部署時（無 $z$）效能可能下降。**緩解方式**：BSD 設計本身即讓學生在無 $z$ 條件下產生 rollout，已緩解此問題；仍應監控部署後的效能落差。

### 與其他技術的整合建議

- **與 SFT 串接**：可先用 SFT 在高品質軌跡上做初步微調，再以 BSD 進行同策略精煉，兼顧模仿效率與探索能力。

- **與 RLVR 整合**：BSD 本身即建立在 GRPO/RLVR 框架上，可直接替換或增強現有 RLVR 管線，無需大幅改動基礎設施。

- **與模型合併（Model Merging）**：BSD 訓練後的學生模型可與其他任務專精模型進行權重合併，擴展多任務能力。

- **與推論加速技術相容**：訓練完成後可搭配 speculative decoding、KV cache 壓縮、量化（INT8/INT4）等技術進一步降低部署成本。

- **與 MLOps 平台整合**：BSD 的離線軌跡生成 + 線上訓練兩階段架構，適合以 pipeline 形式整合到既有 MLOps 系統（如 Kubeflow、MLflow、Vertex AI），並支援教師軌跡的版本管理與 A/B 測試。

- **與多模態延伸**：若將推理軌跡擴展為多模態（如圖文混合推理），BSD 的「特權上下文 + 自教師評分」框架仍可適用，只需將條件介面從文字擴展為多模態輸入。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解「知識蒸餾」與「強化學習」的基本概念，再閱讀本文。BSD 的核心創意在於「讓學生自己當自己的老師」——透過把外部教師的推理軌跡當作提示，學生模型在有提示與無提示兩種狀態下的預測差異，就是訓練的引導訊號。閱讀時可先聚焦於第 1 節的問題動機與第 2 節的 RLSD 公式，建立直覺後再深入實驗細節。

**給 AI 工程師**：重點關注第 2 節的 RLSD 數學推導與第 3 節後的實作細節，理解詞元層級優勢重塑如何與 GRPO 結合。實作時可先復現共享分詞器場景（最簡單），再逐步擴展到跨分詞器與封閉 API 場景。注意監控 $\lambda$ 與 clip 範圍對訓練穩定性的影響，並善用梯度檢查點降低自教師的記憶體開銷。

**給研究者**：本文的關鍵貢獻在於提出一個「教師無關」的統一蒸餾介面，將不同場景的 OPD 統一為同一訓練流程。值得深入探討的方向包括：(1) 推理軌跡品質與 BSD 效果的因果關係；(2) 自教師機率比 $u_t$ 的理論性質；(3) BSD 與 imitation learning、RLHF 的形式化連結；(4) 將 BSD 擴展到多模態或多輪對話蒸餾的可能性。論文中關於「引導集中在不確定詞元」的觀察，是後續理論分析的有趣切入點。

**給產品經理**：BSD 讓企業能用「任何能產生文字的 AI」作為教師，大幅降低對特定模型供應商的依賴。實務上，這意味著：(1) 可靈活選擇最具成本效益的教師組合；(2) 部署的小型模型可離線運作，保護資料隱私；(3) 訓練流程統一，減少維護多套管線的工程負擔。評估導入時，建議先以單一場景（如封閉 API → 小型開源模型）驗證效益，再逐步擴展至跨分詞器與多教師協作。
