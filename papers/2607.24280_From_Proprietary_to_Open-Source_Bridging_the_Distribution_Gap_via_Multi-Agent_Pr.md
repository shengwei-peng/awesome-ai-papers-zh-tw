# 從專有模型到開源模型：在代理式搜尋（Agentic Search）中透過多代理協定蒸餾（MAPD）彌合分佈落差（Distribution Gap）

## ⚡ TL;DR

解決專有模型蒸餾至開源模型時，異質分詞器與隱藏logit難以對齊，且自然語言軌跡模仿易致風格飄移。
提出MAPD，以結構化JSON協定為中間表徵，離線合成後於訓練時經特權分支提供密集蒸餾訊號輔助RL。
在七項問答基準中，Qwen3-1.7B與4B達39.4%與44.4%，跨專家教師泛化並抑制風格飄移。

## 摘要翻譯

代理式搜尋（Agentic Search）使大型語言模型（Large Language Model, LLM）得以透過交錯執行多步驟推理（Multi-step Reasoning）與檢索（Retrieval）來解決知識密集型任務（Knowledge-intensive Task），然而以基於結果的強化學習（Outcome-based Reinforcement Learning, RL）對此進行最佳化僅能提供稀疏監督（Sparse Supervision）。知識蒸餾（Knowledge Distillation）能夠提供更密集的引導，而具備強大推理能力的先進專有模型（Proprietary Model）更是極具潛力的教師模型（Teacher Model）。儘管從專有模型進行蒸餾可使此監督訊號（Supervisory Signal）更為密集，但傳統的 logit 匹配（Logit-matching）因隱藏 logit（Hidden Logits）與不匹配的分詞器（Mismatched Tokenizers）而無法實現；相對地，原始自然語言軌跡模仿（Raw Natural Language Trajectory Imitation）僅能轉移表面的風格性特徵（Stylistic Artifact），而非核心推理能力（Core Reasoning Competence）。為了解決異質蒸餾問題（Heterogeneous Distillation Problem）並彌合分佈落差（Distribution Gap），我們提出多代理協定蒸餾（Multi-Agent Protocol Distillation, MAPD），這是一個聯合蒸餾與強化學習框架（Joint Distillation and RL Framework），使用結構化風格正規化協定（Structured Style-normalized Protocol）作為中間表徵（Intermediate Representation）。一個離線多代理系統（Offline Multi-Agent System, MAS）會進行查詢分解（Query Decomposition）、檢索支持證據（Supporting Evidence）、進行失敗搜尋修復（Failed Search Repair），並將產生的探索軌跡（Exploration Trace）轉換為包含任務類型（Task Type）、推理計畫（Reasoning Plan）與抽取式依據事實（Extractive Grounding Facts）的 JSON 協定（JSON Protocol）。在訓練過程中，該協定僅提供給學生策略（Student Policy）的特權分支（Privileged Branch），其詞元分佈（Token Distribution）在稀疏強化學習目標（Sparse RL Objective）之外額外提供密集蒸餾訊號（Dense Distillation Signal）。橫跨七個問答基準測試（QA Benchmark）的廣泛評估顯示，MAPD 始終優於具競爭力的蒸餾與強化學習基線，在 Qwen3-1.7B 上達到平均成功率（Success Rate）39.4%，在 Qwen3-4B 上達到 44.4%。尤為關鍵的是，此框架能夠穩健地泛化至多樣的專有教師模型（Proprietary Teacher），同時有效緩解學生策略的風格飄移（Style Drift）與冗長退化（Verbosity Degeneration）。

### 核心貢獻（3～5點）
- 提出 MAPD 框架，結合知識蒸餾與強化學習，以結構化協定作為中間表徵，解決專有模型與開源學生模型之間的異質蒸餾問題。
- 設計離線多代理系統，自動執行查詢分解、證據檢索、失敗搜尋修復，並將探索軌跡轉換為標準化的 JSON 協定。
- 在訓練時僅將協定提供給學生策略的特權分支，使詞元級分佈能夠提供密集蒸餾訊號，彌補稀疏 RL 目標的不足。
- 在七個 QA 基準測試上驗證 MAPD 的有效性，並展現其對不同專有教師模型的穩健泛化能力。
- 有效緩解學生策略在蒸餾過程中常見的風格飄移與冗長退化問題。

### 適合對象
本論文適合對大型語言模型、代理式搜尋、知識蒸餾、強化學習，以及開源模型效能提升有興趣的研究人員與工程師。特別是關注如何將專有模型的推理能力轉移至開源小模型，並希望解決異質模型蒸餾與風格飄移問題的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心問題設定：為何需要 MAPD？

本文將**代理式搜尋（agentic search）**形式化為一個多輪互動過程：給定問題 \(x\)，語言模型策略 \(\pi_\theta\) 與檢索環境進行最多 \(K\) 輪互動，最終產生完整詞元序列 \(y=(y_1,\dots,y_T)\)。整個軌跡（trajectory）僅在結尾透過**嚴格完全匹配（exact-match, EM）**獲得二元獎勵 \(R(x,y)\in\{0,1\}\)。這種**基於結果的強化學習（outcome-based RL）**（例如 **GRPO**）雖然能驅動探索，但對中間推理步驟僅提供**稀疏監督（sparse supervision）**，難以指導複雜的多步驟檢索與推理。

為了補充密集訊號，近期研究採用**線上策略蒸餾（Online Policy Distillation, OPD）**，透過**詞元級分佈對齊（token-level distribution alignment）**來引導中間決策。然而，當教師是**專有模型（proprietary model）**、學生是**開源模型（open-source model）**時，出現兩大瓶頸：

1. **異質分詞器（heterogeneous tokenizer）**與**隱藏 logit（hidden logits）**使傳統 **logit 匹配（logit-matching）**與 **KL 散度對齊（KL divergence alignment）**數學上不可行。
2. 退而求其次的**原始自然語言軌跡模仿（raw natural language trajectory imitation）**會強迫學生複製專有模型特殊的語言風格，導致**風格飄移（style drift）**、**冗長退化（verbosity degeneration）**與**幻覺（hallucination）**，反而擴大**分佈落差（distribution gap）**。

##### 2. MAPD 的兩階段架構

**多代理協定蒸餾（Multi-Agent Protocol Distillation, MAPD）**透過一個**結構化風格正規化協定（structured style-normalized protocol）**作為中間表徵（intermediate representation），將離線的專家教師知識轉換為可在線上使用的密集監督。整體分為兩階段：

**（1）離線協定合成（Offline Protocol Synthesis）**

由專有模型驅動的**離線多代理系統（offline multi-agent system, MAS）**執行以下步驟：

- **查詢分解（query decomposition）**：將複雜問題拆解為子目標。
- **檢索支持證據（supporting evidence retrieval）**：取得相關段落。
- **失敗搜尋修復（failed search repair）**：對檢索失敗的步驟進行補救。
- **探索軌跡（exploration trace）轉換**：將上述過程整理成一份 **JSON 協定（JSON protocol）**，內含：
  - **任務類型（task type）**
  - **推理計畫（reasoning plan）**
  - **抽取式依據事實（extractive grounding facts）**

此協定刻意去除專有模型的語言外殼，只保留認知策略與事實依據，因此具有**風格正規化（style-normalized）**特性。

**（2）線上聯合訓練（Online Joint Training）**

在訓練時，JSON 協定被當作**特權資訊（privileged information, PI）** \(p\)，僅輸入到學生策略的**特權分支（privileged branch）**；另一條**學生分支（student branch）**則只看原始問題 \(x\) 與已生成前綴 \(y_{<t}\)。兩分支共享同一模型參數，因此可透過**線上策略自蒸餾（Online Policy Self-Distillation, OPSD）**進行對齊：

\[
\mathcal{L}_{\text{OPSD}}^{(t)} = D_{\mathrm{KL}}\!\left(\pi_{\theta_k}(\cdot \mid s_t) \,\|\, \pi_{\theta_k}(\cdot \mid s_t^+)\right),
\]

其中 \(s_t=(x,y_{<t})\) 為學生分支狀態，\(s_t^+=(x,p,y_{<t})\) 為帶協定的特權狀態。反向 **KL 散度（reverse KL divergence）**確保學生分支的詞元分佈（token distribution）向「看過協定後」的分佈靠近，但梯度只回流到學生路徑，避免特權資訊直接洩漏到推理時的行為。

與此同時，模型仍接受 **GRPO** 的稀疏結果獎勵：

\[
\mathcal{L}_{\text{GRPO}} = -\frac{1}{G}\sum_{i=1}^{G}\frac{1}{|y^{(i)}|}\sum_{t=1}^{|y^{(i)}|}\left[J_t^{(i)} - \beta D_{\mathrm{KL}}(\pi_\theta \| \pi_{\text{ref}})\right].
\]

最終目標結合兩者：

\[
\mathcal{L}_{\text{MAPD}} = \mathcal{L}_{\text{GRPO}} + \lambda \mathcal{L}_{\text{OPSD}}.
\]

這樣的設計有幾個關鍵優勢：

- **無需教師 logit**：因為對齊發生在學生模型內部兩個分支之間，完全規避異質分詞器與隱藏 logit 的問題。
- **避免風格飄移**：學生學到的是結構化協定中的計畫與事實，而非專有模型的冗長語句。
- **零推理開銷**：專有模型與 MAS 僅在離線階段使用，部署時學生模型獨立運作。

##### 3. 協定在訓練中的角色

協定在此並非直接用來生成答案，而是作為一種「認知提示」。特權分支因為能看到協定，會產生更合理的下一詞元分佈；學生分支則透過 **OPSD** 模仿這個「知情版」的自己。這相當於把專有教師的**核心推理能力（core reasoning competence）**——例如動態任務分解（dynamic task decomposition）、多跳推理（multi-hop reasoning）、資訊整合（information synthesis）——蒸餾進開源學生，而不是複製其表面語言風格。

#### 實驗數據解讀

##### 1. 主要結果

作者在七個 **QA 基準測試（QA benchmark）**上進行評估，使用 **Qwen3-1.7B** 與 **Qwen3-4B** 作為開源學生模型。主要數據如下：

- **Qwen3-1.7B**：平均成功率（success rate）達 **39.4%**
- **Qwen3-4B**：平均成功率達 **44.4%**

在與競爭性的蒸餾方法與 RL 方法比較時，MAPD 在多數設定下均取得穩定提升。

##### 2. 數據意涵

首先，這些絕對數值看似不高，但必須放在兩個背景下理解：

1. **評估指標嚴格**：採用 **exact-match（EM）**作為成功標準，任何用詞、格式或標點差異都會被視為錯誤，對小模型而言天花板本來就低。
2. **模型規模極小**：1.7B 與 4B 參數量遠小於專有教師，能在多步驟代理式搜尋任務達到近四成成功率，已顯示方法具有顯著的知識轉移效率。

此外，實驗顯示 MAPD 能夠：

- **跨專有教師泛化**：使用 **Claude-Opus-4.6**、**GPT-5.5**、**Gemini-3.1-Pro** 三種不同專有模型作為教師，均獲得穩定增益，且無需針對個別教師重新調整流程。
- **抑制風格飄移與冗長退化**：相較於直接模仿自然語言軌跡，MAPD 有效減少學生產生無關贅述與教師特定表達的傾向。

##### 3. 數據解讀的限制

由於提供的摘要與前文未列出各基準測試的詳細分數，也沒有呈現標準差或顯著性檢定，我們無法判斷：

- 提升是否集中在特定類型的問題（例如事實型 vs. 多跳推理型）。
- 小模型（1.7B）與較大模型（4B）之間的增益差距是否呈線性。
- 與直接使用更大開源模型（如 Qwen3-14B/32B）相比，MAPD 的性價比如何。

因此，雖然整體趨勢正面，但仍需完整實驗表格才能做更細緻的因果推論。

#### 與現有研究的比較

##### 1. 相對於 RLVR / GRPO

傳統 **可驗證獎勵強化學習（RLVR）**與 **GRPO** 僅依賴最終答案正確性，對長軌跡中的中間檢索與推理步驟缺乏引導。MAPD 透過協定引入**密集監督（dense supervision）**，補強了 GRPO 的稀疏訊號，使學生能學到「如何規劃與檢索」，而不只是「猜對最終答案」。

##### 2. 相對於 OPD（Online Policy Distillation）

標準 **OPD** 需要教師與學生共享可對齊的詞元空間，通常要求取得教師 **logit**。對於專有模型而言，這在技術與法律上均不可行。MAPD 改為在學生內部進行自蒸餾，完全不需要跨模型對齊，從而解決了**異質蒸餾問題（heterogeneous distillation problem）**。

##### 3. 相對於 OPSD（Online Policy Self-Distillation）

MAPD 的訓練目標繼承了 **OPSD** 的同源（homologous）形式，但關鍵差異在於**特權資訊的來源**。標準 OPSD 通常從學生自己的正確軌跡中抽取 PI，其監督品質受限于學生現有能力；而 MAPD 的 PI 來自專有教師經 MAS 提煉後的協定，能突破學生原有的推理上限。

##### 4. 相對於自然語言軌跡模仿

直接行為複製（behavior cloning）專有模型的自然語言軌跡，會把教師的**特殊推理風格（idiosyncratic reasoning style）**與冗長表達一併轉移，造成**風格飄移（style drift）**與**幻覺（hallucination）**。MAPD 透過結構化協定將**認知策略（cognitive strategy）**與**語言外殼（linguistic shell）**解耦，是針對此問題的根本性改進。

##### 5. 方法定位與局限

MAPD 的定位介於「黑箱示範學習」與「白箱 logit 蒸餾」之間：它不需要白箱，但仍能提供接近詞元級的密集監督。然而，其成效高度依賴：

- **MAS 的品質**：協定若包含錯誤分解或錯誤事實，會直接污染訓練訊號。
- **協定 schema 的設計**：目前主要針對 QA 任務設計，對於更廣泛的代理式任務（如工具使用、網頁瀏覽、程式生成）可能需要重新設計欄位。
- **專有模型的可取得性**：雖然推理時無需專有模型，但離線協定合成仍需呼叫專有 API，存在成本與資料隱私考量。

#### 可重現性評估

##### 1. 公開資源現況

根據目前提供的摘要與前文，作者並未明確提及是否釋出：

- 原始碼（training framework、MAS pipeline）
- 預訓練或微調後的模型權重
- 生成的 JSON 協定資料集
- 完整的超參數設定與訓練配置

因此，從現有資訊判斷，本研究的可重現性仍屬「中等偏低」：理論上方法可被復現，但實作細節（尤其是 MAS 的角色設計、自動化品質檢查、協定解析與格式化）若未公開，將大幅增加重現難度。

##### 2. 有利於重現的要素

- **學生模型公開**：Qwen3-1.7B 與 Qwen3-4B 為開源模型，社群可取得。
- **基準測試公開**：七個 QA benchmark 若為常見公開資料集（如 HotpotQA、Natural Questions、TriviaQA 等），評估環境可重建。
- **訓練目標明確**：GRPO 與 OPSD 的數學形式已在前文完整給出，損失函數實作相對直接。

##### 3. 不利於重現的要素

- **專有教師 API**：雖可透過商業 API 取得，但不同版本、提示工程與取樣參數會影響協定品質，難以完全複製。
- **MAS 複雜度**：多代理系統包含多個專業角色與自動化檢查，若未釋出 agent 定義與協作流程，重現者需自行設計。
- **缺乏數據與模型釋出**：沒有釋出協定資料與微調權重，意味著重現者必須從頭生成資料並訓練，成本高昂。

建議作者未來至少釋出協定資料集與 MAS 配置，以提升社群驗證與後續研究的可能性。

#### 未來研究方向

##### 1. 擴展協定至更廣泛的代理式任務

目前 MAPD 的 JSON 協定主要服務於 QA 任務。未來可將協定 schema 擴展至：

- **工具使用（tool use）**：加入工具選擇、參數填寫、執行結果判讀等欄位。
- **程式生成與執行**：納入偽碼計畫、測試案例與執行追蹤。
- **多模態代理**：整合圖像、表格、影片等非文字資訊的 grounding。

##### 2. 降低對專有模型的依賴

可探索以開源大模型或專門訓練的「協定生成器」取代專有教師，例如：

- 使用較大開源模型（如 Qwen3-72B、Llama-4）作為 MAS 骨幹。
- 透過迭代自監督，讓學生模型自己生成並驗證協定，逐步減少對外部 API 的需求。

##### 3. 結合過程獎勵模型（Process Reward Model, PRM）

MAPD 的協定提供了結構化中間目標，但未對每個中間步驟給予顯式獎勵。未來可訓練 PRM 來評估「檢索查詢品質」、「推理計畫合理性」等，進一步稠化監督訊號。

##### 4. 線上協定適應與錯誤修復

目前協定在離線階段固定。未來可研究：

- **線上協定更新**：根據學生訓練過程中的錯誤案例，動態修正或擴充協定。
- **對抗式協定驗證**：引入驗證 agent 檢查協定內部一致性，減少錯誤傳播。

##### 5. 量化風格飄移與冗長度

未來工作可建立更細緻的評估指標，例如：

- 測量學生輸出與各教師語言風格的相似度，驗證 MAPD 是否真正達成風格解耦。
- 分析輸出長度、重複性、無關 token 比例，進一步抑制冗長退化。

##### 6. 開放協定標準與跨模型生態

若 MAPD 的 JSON 協定能發展為社群通用的中間表徵標準，將有助於：

- 不同專有教師與開源學生之間的知識互通。
- 建立可共享的「協定資料市場」，降低重複呼叫專有 API 的成本。

##### 7. 與推論效率技術結合

由於 MAPD 在推理時無額外開銷，可進一步結合推論加速技術，例如：

- **推測解碼（speculative decoding）**
- **提前退出（early exiting）**
- **協定引導的搜尋剪枝**

使小模型在代理式搜尋中的延遲與成本更接近實際部署需求。

## 論文問答

**Q1：代理式搜尋在使用可驗證獎勵強化學習（RLVR）訓練時，核心困難是什麼？**  
A：代理式搜尋的互動軌跡通常包含多個推理步驟與檢索動作，但 RLVR 只會在軌跡結束時依據最終答案是否正確給出二元獎勵，因此屬於稀疏監督。這種稀疏訊號難以指導模型在漫長的中間決策中學習何時該檢索、如何分解查詢或整合資訊。結果，學生策略容易在龐大的動作空間中低效探索，難以穩定收斂到高品質的多步驟推理行為。

**Q2：為什麼現有的線上策略蒸餾（OPD）無法直接套用在專有模型教師與開源學生之間？**  
A：傳統 OPD 依賴詞元級 KL 散度對齊，需要取得教師模型的 logit 並假設師生使用相同分詞器，但專有模型的隱藏 logit 與異質分詞器使這種對齊在數學上無法定義。若改採原始自然語言軌跡模仿，開源學生會被迫複製專有模型冗長且特殊的推理風格，反而加劇分佈落差。這不僅無法轉移核心推理能力，還會引發風格飄移與幻覺，使代理式任務表現下降。

**Q3：為何將專有模型的能力遷移到開源模型對代理式搜尋領域很重要？**  
A：頂尖專有模型在動態任務分解、多跳推理與資訊整合方面表現卓越，但部署成本高、延遲大且無法離線使用，因此開源替代方案具有實務價值。然而開源模型本身缺乏高品質的中間監督，單靠稀疏強化學習難以學會複雜的代理式行為。MAPD 透過結構化協定作為橋樑，讓開源學生能在不接觸教師 logit 的情況下內化專家的認知策略，有助於推動開源生態的發展。

**Q4：MAPD 的核心方法架構是什麼？**  
A：MAPD 是一個聯合蒸餾與強化學習框架，核心在於以結構化、風格正規化的 JSON 協定作為專有教師與開源學生之間的中間表徵。在離線階段，由專有模型驅動的多代理系統會分解查詢、檢索支持證據、修復失敗搜尋，並將探索軌跡轉換成包含任務類型、推理計畫與抽取式依據事實的 JSON 協定。在訓練階段，該協定僅作為特權資訊餵給學生策略的特權分支，與學生分支共享同一模型並提供密集蒸餾訊號，同時搭配稀疏的 GRPO 目標進行聯合訓練。

**Q5：結構化 JSON 協定在 MAPD 中扮演什麼關鍵創新角色？**  
A：JSON 協定將專家行為中的認知策略與語言外殼解耦，只保留任務類型、推理計畫與抽取式依據事實等核心內容，從而避免學生模仿教師特定的冗長或格式特徵。由於協定是風格正規化的中間表徵，無論背後教師是 Claude、GPT 還是 Gemini，產出的監督訊號都具有統一語義。這種設計有效降低分佈落差，抑制風格飄移與冗長退化，使學生專注於學習真正可泛化的推理結構。

**Q6：為什麼 MAPD 選擇使用「特權分支」與自我蒸餾，而不是直接對齊專有教師的輸出分布？**  
A：特權分支與學生分支來自同一組當前策略參數，因此兩者的詞元分佈位於相同詞彙空間，自然迴避了異質分詞器與無法取得教師 logit 的問題。訓練時透過最小化學生分支與協定條件下特權分支之間的反向 KL 散度，可產生密集的詞元級監督，且反向傳播時只更新學生路徑。這種同質自我蒸餾既能補充稀疏強化學習目標，又不需要在推理時引入任何額外開銷。

**Q7：MAPD 在哪些基準測試上進行評估，主要結果為何？**  
A：論文在七個問答基準測試上進行廣泛評估，涵蓋不同難度與領域的知識密集型任務。實驗顯示 MAPD 平均成功率達到 Qwen3-1.7B 的 39.4% 與 Qwen3-4B 的 44.4%，穩定優於競爭性的蒸餾方法與純強化學習基線。這些結果顯示，即使學生模型規模較小，透過協定蒸餾也能顯著提升代理式搜尋的表現。

**Q8：MAPD 的跨教師泛化能力與風格控制表現如何？**  
A：研究使用 Claude-Opus-4.6、GPT-5.5 與 Gemini-3.1-Pro 三種頂尖專有模型作為教師，結果顯示 MAPD 在不同教師下都能帶來可靠增益。更重要的是，這些改進能夠跨不同專有模型遷移，而無需重新調整整個流程。此外，框架有效抑制學生策略的風格飄移與冗長退化，避免學生輸出變得過度囉嗦或偏離任務目標。

**Q9：從消融比較的角度，MAPD 相較於純 GRPO、純自然語言軌跡模仿或學生自身生成的特權資訊有何優勢？**  
A：純 GRPO 僅依賴稀疏的最終答案獎勵，難以指導中間推理步驟；純自然語言軌跡模仿則會把專有模型的風格性特徵一併轉移，導致風格飄移與幻覺。若特權資訊來自學生自己的正確軌跡，則監督品質受限于學生現有推理上限，無法突破瓶頸。MAPD 透過專有模型生成的結構化協定提供高品質密集訊號，並與 GRPO 聯合訓練，同時解決了監督稀疏與品質不足的問題。

**Q10：MAPD 在實務上可以應用於哪些產品或場景？**  
A：MAPD 特別適合需要多跳推理與證據引用的企業知識庫問答、法律與醫療文獻檢索、研究助理與客戶支援系統。在這些場景中，模型必須先分解複雜查詢、檢索多份文件、再整合資訊給出可信答案。透過 MAPD，企業可以在地部署較小的開源模型，同時保留接近專有模型的推理品質，降低延遲與 API 成本。

**Q11：在產品落地時，MAPD 的系統設計有哪些實務考量？**  
A：專有模型與多代理系統只用於離線協定合成，不會增加推理階段的延遲或計算開銷，這對生產環境非常重要。協定合成成本可以透過一次性離線處理攤提，並可透過自動化品質檢查確保 JSON 協定的正確性。此外，由於協定是風格正規化的中間表徵，產品可以彈性替換背後的專有教師模型，而無需修改學生模型的訓練流程。

**Q12：MAPD 對整個大型語言模型與代理式系統領域可能帶來什麼影響？**  
A：MAPD 為異質蒸餾問題提供了一個不依賴 logit 匹配的新範式，證明結構化中間表徵可以有效橋接不同模型家族之間的分佈落差。這有助於降低開發者對專有 API 的依賴，並促進開源模型在複雜代理式任務中的採用。未來這種「協定蒸餾」思路也可能啟發更多將黑箱專家能力轉化為可學習結構知識的研究。

**Q13：MAPD 有哪些已知的限制或依賴？**  
A：協定品質高度依賴離線多代理系統中專有教師的推理與檢索能力，若教師本身在某領域表現不佳，生成的協定也會帶有錯誤。對於極度複雜、語意模糊或需要大量常識的查詢，自動化協定合成與品質檢查可能無法完全覆蓋所有失敗模式。此外，若應用領域與訓練資料差異過大，可能需要額外調整多代理系統的角色設計與檢查規則。

**Q14：在什麼情況下 MAPD 可能會失敗或表現不佳？**  
A：當檢索環境本身品質低落時，即使協定正確規劃了推理步驟，抽取式依據事實仍可能來自錯誤文件，導致最終答案錯誤。對於對抗性、超出分布或需要世界知識而非文件檢索的問題，結構化協定也可能無法提供足夠指導。若多代理系統在查詢分解或失敗搜尋修復階段產生偏差，這些錯誤會沿著協定傳遞給學生策略。

**Q15：未來可以朝哪些方向延伸 MAPD？**  
A：未來可將協定蒸餾擴展到工具使用、程式生成或具身代理等更廣泛的代理式任務，設計對應的領域專用協定格式。也可以引入多教師協定融合或線上協定精煉機制，讓學生在訓練過程中持續改善協定品質。此外，探索更輕量的學生模型、多模態協定，以及將協定與更先進的強化學習演算法結合，都是值得深入研究的方向。

## 實務應用指南

### 適用場景

1. **企業內部知識問答與多跳檢索**  
   如法務、客服、研發知識庫，查詢常需**查詢分解**、多輪**檢索**與**資訊整合**。MAPD 可將專有模型（如 GPT、Claude、Gemini）的推理過程轉成結構化 JSON 協定，再蒸餾到開源小模型，降低線上延遲與 API 成本。

2. **醫療與法規文獻輔助查詢**  
   這類場景要求高正確性、可稽核且需降低**幻覺**。JSON 協定中的**抽取式依據事實**能明確標示答案來源，便於後續事實查核與合規報告。

3. **金融研究與投資報告生成**  
   分析師需從財報、新聞、市場數據進行**多步驟推理**與**動態任務分解**。MAPD 讓開源學生模型學習專家教師的核心策略，而非模仿其冗長或特殊的語言風格。

4. **教育與學術搜尋助手**  
   協助學習者進行**多跳推理**，透過**推理計畫**與**支持證據**展示思考過程。結構化協定也便於前端介面以步驟化方式呈現答案。

5. **技術文件與程式碼問答**  
   面對跨版本 API、函式庫差異等複雜問題時，代理式搜尋需反覆檢索文件。MAPD 的**失敗搜尋修復**機制可提升檢索失敗後的恢復能力。

---

### 實作前置條件

**資料**
- 領域問答對與可驗證答案（支援 exact-match 或規則評分）。
- 檢索語料庫與檢索器（向量資料庫、關鍵字檢索或混合檢索）。
- 專有模型 API 存取權，用於離線**協定合成**。
- 開源學生模型權重（如 Qwen3-1.7B / Qwen3-4B）與參考模型權重。

**運算**
- 訓練階段需 GPU 資源（建議 A100 / H100 等級）以執行 GRPO + OPSD 聯合訓練。
- 離線 MAS 推理可透過 API 平行呼叫，需評估速率限制與成本。
- 儲存與管理 JSON 協定資料集的空間。

**技能**
- 熟悉強化學習（GRPO / PPO）與**知識蒸餾**。
- LLM 微調經驗（LoRA 或全參數微調）。
- **多代理系統**設計、prompt 工程與角色分工。
- JSON schema 設計與自動化品質檢查。
- 檢索系統建置與評估能力。

---

### 實作步驟建議

1. **定義結構化 JSON 協定 schema**  
   根據任務設計欄位，例如 `task_type`（任務類型）、`reasoning_plan`（推理計畫）、`extractive_grounding_facts`（抽取式依據事實）、`search_queries`（檢索查詢）、`repair_steps`（修復步驟）等，確保協定**風格正規化**且與領域對齊。

2. **建構離線多代理系統（MAS）**  
   設計具專門角色的代理：查詢分解、證據檢索、**失敗搜尋修復**、協定轉換。以專有模型為後端，並加入自動化檢查（schema 驗證、事實一致性、答案正確性）與人工抽樣審核。

3. **產生協定資料集**  
   對訓練查詢執行 MAS，收集**探索軌跡**並轉換為 JSON 協定。過濾低品質樣本，將協定作為**特權資訊（privileged information）**。

4. **設計學生策略架構**  
   同一開源模型具備兩個輸入分支：**學生分支**僅見查詢與歷史軌跡；**特權分支**額外見 JSON 協定。兩分支共享模型參數。

5. **聯合訓練**  
   結合 GRPO（利用**可驗證獎勵**的稀疏監督）與 OPSD（以反向 KL 讓學生分佈對齊特權分支的**詞元分佈**）。加入 KL 懲罰防止偏離參考模型，並監控**風格飄移**與**冗長退化**。

6. **評估與迭代**  
   在領域 QA 基準測試上量測成功率、幻覺率、延遲與輸出長度。根據錯誤案例更新 MAS prompt、協定 schema 與訓練資料。

7. **部署上線**  
   離線 MAS 與專有模型不再參與推論，僅使用微調後的開源學生模型。可選擇保留協定日誌以支援可解釋性與稽核。

---

### 潛在風險與注意事項

- **專有模型 API 成本與速率限制**  
  離線協定合成需大量呼叫專有模型。建議使用快取、批次處理，並以較低成本模型進行初步過濾。

- **協定品質瓶頸**  
  錯誤的 JSON 協定會成為錯誤監督訊號。必須建立嚴格的自動化檢查與人工抽樣機制，必要時引入人類回饋。

- **風格飄移與冗長退化**  
  雖然 MAPD 已降低對教師表面形式的暴露，仍需監控輸出長度與格式。可加入長度懲罰與格式正則化。

- **獎勵駭入（reward hacking）**  
  GRPO 可能學會欺騙可驗證獎勵。應搭配多樣化評估、嚴格 exact-match，以及定期人工評估。

- **領域泛化風險**  
  論文在七個 QA 基準測試上表現穩健，但進入全新領域時通常需重新產生協定與微調。建議持續收集領域資料。

- **安全與隱私**  
  JSON 協定可能包含敏感資訊。訓練資料應去識別化，並對協定資料集實施存取控制。

---

### 與其他技術的整合建議

- **檢索系統**  
  與向量資料庫（如 Milvus、Pinecone）、混合檢索（BM25 + dense retrieval）及重排序模型整合。MAS 與線上學生策略可共用同一檢索 API。

- **LLM 推論服務**  
  將 MAPD 微調後的開源模型部署於 vLLM 或 TGI，作為低成本、低延遲的推論節點；專有模型僅保留於離線協定合成。

- **MLOps 與資料管線**  
  使用 MLflow、Weights & Biases 追蹤協作品質與訓練指標；以 DVC 管理 JSON 協定資料集版本。

- **可解釋性與稽核**  
  將 JSON 協定與**抽取式依據事實**存入日誌，支援後續事實查核、錯誤追溯與合規報告。

- **人類回饋強化學習（RLHF）**  
  MAPD 可作為冷啟動方案，後續加入人類偏好標註，進一步以 DPO 或 RLHF 微調輸出風格與安全性。

- **多模態擴展**  
  可將協定擴展至圖表、表格等模態，結合 OCR 與多模態檢索，處理更豐富的知識密集型任務。

---

### 給不同背景讀者的閱讀建議

**初學者**  
建議先掌握**代理式搜尋**、**知識蒸餾**與**強化學習**的基本概念，再把 MAPD 理解為「用結構化大綱把專家經驗教給小模型」；可優先閱讀適用場景與實作步驟，建立整體輪廓。

**AI 工程師**  
請重點關注 GRPO 與 OPSD 的聯合目標實作、**特權分支**的程式碼設計、JSON schema 與 MAS prompt 工程，以及訓練穩定性、推論部署與監控細節。

**研究人員**  
可著重探討**異質蒸餾問題**、結構化協定作為**中間表徵**的理論動機，以及與傳統 logit 匹配、原始自然語言軌跡模仿的差異；跨專有教師的泛化實驗也值得深入分析。

**產品經理**  
請聚焦 MAPD 如何降低對專有模型的線上依賴與成本，同時提升開源模型在知識密集型任務的可靠性；評估資料準備、品質控管與領域遷移所需的資源與時程。
