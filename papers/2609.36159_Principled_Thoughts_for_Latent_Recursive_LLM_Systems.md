## ⚡ TL;DR

潛在遞迴 LLM 系統僅以交叉熵訓練思維表示，會導致思維塌縮並保留無關資訊，降低正確答案機率。
本文提出 REST，將因果性、最小性、可分離性、穩定性轉為可微分損失加入交叉熵，無需架構變更。
在七項數學、科學、醫學與程式碼基準測試中，REST 準確率最高提升 7.5 百分點，收斂率提升 30%。

## 摘要翻譯

大型語言模型可在連續空間中進行推理，而非透過解碼文字，方式為在其自身的隱藏狀態上遞迴，或在代理之間傳遞這些狀態，而訓練僅監督最終解碼答案的交叉熵（CE），並未對思維施加約束。理論與實證分析確立並驗證了僅 CE 訓練的四項缺陷，這些缺陷會導致正確答案的機率降低，例如跨不同問題的思維塌縮以及保留不相關資訊。我們提出 REST（表示監督思維），一項將有效思維表示的四項屬性——因果性、最小性、可分離性與穩定性——轉化為附加於 CE 之可微分損失的訓練目標。我們將其實例化於潛在單代理與多代理系統中，無需架構變更或在推論時新增參數。在涵蓋數學、科學、醫學與程式碼生成的 7 個基準測試上，使用相同的訓練資料、計算資源與潛在預算，REST 相較於僅 CE 訓練，在各代理設定與模型規模上提升了最高達 7.5 個百分點的準確率，並使最終答案的收斂率提升 30%。此外，REST 思維編碼了更多達成正確答案所需的內容，將其解碼能更好地還原代理的預期輸出，這使得潛在通訊更易於解讀。專案網站：https://fard-lab.github.io/REST

### 核心貢獻（3～5點）
- 識別並驗證僅 CE 訓練的四項缺陷（思維塌縮、保留不相關資訊等），證明其會降低正確答案的機率
- 提出 REST 訓練目標，將思維表示的四項理想屬性（因果性、最小性、可分離性、穩定性）轉化為附加於 CE 的可微分損失
- 在潛在單代理與多代理系統中實例化，無需架構變更或推論時新增參數
- 在 7 個跨領域基準測試上，於相同訓練資料、計算資源與潛在預算下，最高提升 7.5 個百分點準確率，並使最終答案收斂率提升 30%
- REST 思維更具可解釋性，解碼後能更好地還原代理的預期輸出，使潛在通訊更易於解讀

### 適合對象
從事大型語言模型推理機制、潛在空間推理、訓練目標設計或多代理系統研究的研究者與工程師，特別關注如何以可微分損失監督思維表示、提升推理效率與可解釋性者。

## 深度分析

#### 方法論解析

REST（REpresentation-Supervised Thoughts，表示監督思維）的核心方法論建立在對現有潛在遞迴 LLM 系統（Latent Recursive LLM Systems）訓練目標缺陷的批判性分析之上。傳統方法僅以最終解碼答案的交叉熵（Cross-Entropy, CE）作為監督訊號，這種「CE-only」訓練存在四個系統性失敗：思維塌縮（Collapsing Thoughts）、保留不相關資訊（Irrelevant Information）、無法區分語意不同的輸入，以及無法反映輸出分布。

**四個理論屬性的形式化**

REST 將 Seddik & Fard（2026）提出的四個思維表示屬性轉化為可微分損失（Differentiable Losses）：

1. **因果性（Causality）**：思維 T 必須保留重現輸出所需的所有資訊。形式上，這要求 T 能夠「替代」（substitute）其對應的文字，使下游代理能從 T 重構出與從原始文字相同的輸出分布。

2. **最小性（Minimality）**：T 必須丟棄與輸出無關的輸入資訊。這防止隱藏狀態（Hidden States）作為「資訊垃圾場」，避免錯誤在多輪遞迴（Recursion）中累積。

3. **可分離性（Separability）**：不同問題對應的思維在表示空間中應可區分。CE-only 訓練下，不同問題的思維會塌縮到相似的區域，導致代理無法根據接收到的思維判斷任務內容。

4. **穩定性（Stability）**：T 應編碼輸出的完整分布，而非單一樣本。這避免了思維對特定解碼路徑的過擬合。

**系統架構整合**

REST 在潛在遞迴系統中無需架構變更（Architectural Changes）或新增參數（Added Parameters）。系統由兩個關鍵組件構成：

- **內連結（Inner-Link, R_in）**：將代理的隱藏狀態映射回其自身的輸入嵌入空間，使代理能進行潛在步驟而非解碼詞元。R_in 透過對齊隱藏狀態與真實文字的嵌入進行訓練。
- **外連結（Outer-Link, R_ψ）**：將 R_in 的輸出映射到另一個代理的輸入空間，實現代理間通訊（Inter-Agent Communication）。所有外連結透過最終答案的 CE 進行訓練。

思維 T = R_ψ(R_in(H_u)) ∈ R^(m'×d_h) 是兩個連結的組合，其中 H_u 是生產者代理在 m 個詞元上的最後一層隱藏狀態。

**損失函數設計**

總損失為 L_total = L_CE + β · L_REST，其中 β 為超參數權重。L_REST 由四個對應屬性的可微分項組成，每個項都設計為可加到現有 CE 目標上。這種設計的關鍵優勢在於：

- **理論保證**：四個屬性共同下界正確答案的機率（Section A.2），提供了 CE-only 訓練所缺乏的表示層級監督（Representation-Level Supervision）。
- **即插即用**：可應用於單代理（Single-Agent）和多代理（Multi-Agent）設定，無需修改推論（Inference）流程。
- **可解釋性**：訓練後的思維可解碼回文字，使潛在通訊（Latent Communication）更易於理解。

**從多代理到單代理的擴展**

論文將 Zou 等人（2026a）的多代理潛在遞迴系統擴展到單代理設定，其中 Sys 1 = Sys 2，模型遞迴於自身的隱藏狀態。這一擴展使 REST 能夠在更廣泛的場景中驗證其有效性。

#### 實驗數據解讀

**基準測試覆蓋面**

實驗在 7 個基準測試（Benchmarks）上進行，橫跨四大領域：
- **數學（Mathematics）**：MATH500、AIME2025、AIME2026
- **科學（Science）**：GPQA-Diamond
- **醫學（Medicine）**：MedQA
- **程式碼生成（Code Generation）**：LiveCodeBench-v6、MBPP+

這種跨領域設計驗證了 REST 的泛化能力，而非僅在特定任務上過擬合。

**核心結果**

| 設定 | 平均增益 | 最佳配置增益 |
|------|---------|------------|
| 多代理（Multi-Agent） | +3.5 百分點 | +7.5 百分點 |
| 單代理（Single-Agent） | +3.3 百分點 | +6.5 百分點 |

這些結果在相同的訓練資料（Training Data）、計算資源（Compute）和潛在預算（Latent Budget）下取得，確保了比較的公平性。值得注意的是，REST 在多代理設定下的增益略高於單代理，這與多代理設定中錯誤累積（Error Compounds）更嚴重的理論預期一致——更多的代理和輪次（Rounds）放大了 CE-only 訓練的缺陷，而 REST 的表示監督能更有效地緩解此問題。

**收斂性改善**

REST 將收斂到最終答案的機率提高了 30%，這是一個重要的實用指標。在潛在遞迴系統中，模型可能無法在預定的輪次內產出確定答案，需要額外的解碼步驟。30% 的收斂改善意味著：

- **效率提升**：平均解碼多 15.4% 的詞元，但這被歸因於更高的收斂率——即模型更傾向於產出最終答案而非繼續探索。
- **穩定性**：更高的收斂率反映了思維表示的穩定性（Stability）屬性，使模型對輸出分布的編碼更可靠。

**PCA 可視化證據**

圖 2 展示的 PCA（主成分分析）可視化提供了直觀證據：CE-only 訓練的思維在表示空間中塌縮，而 REST 訓練的思維保持可分離性。答案率從 73%（CE-only）提升至 95%（REST），這是 +3.3 百分點單代理增益的具體體現。

**屬性驗證**

論文透過分析確認訓練後的思維確實展現了被目標化的四個屬性。這形成了一個完整的論證鏈：理論屬性 → 可微分損失 → 訓練後的屬性體現 → 正確答案機率的下界提升 → 實際準確率（Accuracy）改善。

#### 與現有研究的比較

**與 CODI 的比較**

CODI（Shen et al., 2025）透過對齊隱藏狀態與文字誘導的隱藏狀態來進行表示層級監督。然而，CODI 僅匹配隱藏狀態到目標文字，未約束兩個思維之間的關係或模型可生成的輸出分布。REST 的四個屬性框架更全面：因果性確保思維可替代文字，最小性防止資訊冗餘，可分離性保證跨問題的區分性，穩定性反映輸出分布而非單一樣本。

**與 SIM-COT 的比較**

SIM-COT（Wei et al., 2026）透過從思維解碼回文字來進行監督。這種方法僅約束思維到文字的單向映射，未考慮思維應丟棄哪些資訊或如何區分不同輸入。REST 的最小性和可分離性屬性填補了這些空白。

**與 Chain-of-Thought 的比較**

CoT（Wei et al., 2022）將每個推理步驟（Reasoning Step）生成為顯式文字（Explicit Text）。REST 的優勢在於：
- **效率**：避免將每個步驟表達為離散詞彙（Discrete Vocabulary）中的詞元，減少推理軌跡（Reasoning Traces）的長度。
- **表達力**：不受限於「可被文字寫出的路徑」（Li et al., 2025），允許在連續空間（Continuous Space）中更靈活的推理。
- **計算分配**：避免對簡單問題分配過多計算（Chen et al., 2025a）。

**與其他潛在推理方法的比較**

Hao 等人（2026）、Zhang 等人（2025）、Butt 等人（2026）等方法同樣在潛在空間（Latent Space）中進行推理，但缺乏 REST 的理論指導和系統性的屬性約束。REST 的貢獻在於將「什麼是有效的思維表示」這一問題形式化為可優化的目標。

**局限性**

1. **超參數 β 的敏感性**：雖然論文聲稱增益在不同損失權重下保持穩健，但 β 的選擇仍需調整。
2. **計算開銷**：四個額外的損失項增加了訓練時的計算成本，儘管推論時無需額外參數。
3. **審查範圍**：論文的審查（Audit）評估了現有方法，但未訓練以目標化這些屬性，這意味著 REST 的優勢部分來自於「首次系統性地強制這些屬性」。
4. **模型規模**：雖然涵蓋了不同的模型規模（Model Sizes），但具體的規模範圍和是否在更大模型上驗證仍需確認。

**潛在的可重現性優勢**

1. **無架構變更**：REST 不需要架構變更或新增參數，這降低了實作的複雜性。
2. **無推論修改**：現有的潛在遞迴系統可直接整合 REST，無需修改推論流程。
3. **標準基準**：使用的 7 個基準測試（MATH500、GPQA-Diamond、MedQA、AIME2025/2026、LiveCodeBench-v6、MBPP+）都是公開的標準基準。
4. **公平的比較設定**：相同的訓練資料、計算資源和潛在預算確保了結果的可驗證性。

**潛在的可重現性挑戰**

1. **損失權重 β 的選擇**：雖然論文聲稱對 β 穩健，但具體的調參過程和最佳值需要明確記錄。

4. **內連結和外連結的預訓練**：R_in 和 R_ψ 的初始化和預訓練策略。
5. **凍結基礎模型**：基礎 LLM 是凍結的（Frozen），但具體的模型選擇和版本需要明確。

- 研究 REST 在異構代理（不同架構或規模的代理）間的潛在通訊中的表現。

REST 可以與其他訓練範式結合：
- **強化學習（RL）**：將四個屬性作為獎勵函數的一部分。
- **對比學習（Contrastive Learning）**：直接優化可分離性屬性。
- **蒸餾（Distillation）**：將 REST 訓練的模型的思維能力蒸餾到更小的模型。

**4. 理論分析深化**

- **收斂性分析**：REST 訓練的收斂性理論保證。
- **泛化界**：四個屬性如何影響模型的泛化能力。
- **資訊理論視角**：從互資訊（Mutual Information）的角度分析四個屬性。

**5. 應用領域擴展**

- **多模態推理**：將 REST 擴展到視覺-語言模型的潛在推理。
- **工具使用（Tool Use）**：在代理使用外部工具的場景中應用 REST。
- **長上下文推理**：在需要處理長上下文的任務中驗證 REST。

**6. 效率優化**

- **損失項的近似**：四個損失項的計算成本是否可以透過近似降低？
- **稀疏思維**：是否可以只對關鍵的思維步驟應用 REST 監督？
- **動態 β**：根據訓練階段動態調整 β，而非使用固定值。

**7. 與人類認知的對齊**

REST 的四個屬性（因果性、最小性、可分離性、穩定性）與人類推理的某些特徵相似。未來工作可以探索：
- 人類推理中的思維表示是否也滿足這些屬性？
- 將人類推理的特徵編碼為額外的監督訊號。

**8. 安全性和對齊**

潛在空間推理的可解釋性為安全研究提供了新機會：
- REST 訓練的思維更容易解碼，可能有助於檢測不良推理。
- 思維的穩定性屬性可能與對抗魯棒性相關。

## 論文問答

**Q1：思維鏈（CoT）提示法存在哪些根本性的限制，促使研究者必須在連續潛在空間中進行推理？**

A：思維鏈（CoT）提示法要求模型將每一步中間推理都以離散詞彙的形式顯式生成，這使得推理路徑被限制在「可以用文字表達」的範圍內，無法利用連續空間中更豐富的表達能力。此外，這種文字化的推理軌跡通常非常冗長，不僅大幅增加推論成本，也導致模型在面對簡單問題時浪費過多的計算資源。這些限制促使研究者探索讓模型直接在隱藏狀態（hidden states）的連續空間中進行推理的方法，以突破文字表達的瓶頸並提升效率。

**Q2：為什麼現有的潛在推理方法（如 CODI、SIM-COT）即使在連續空間中運作，仍然無法保證產生有效的思維表示？**

A：現有方法如 CODI 透過比對隱藏狀態與目標文字所誘導的隱藏狀態來進行監督，而 SIM-COT 則是嘗試從思維中解碼回原始文字，但這些方法都僅僅監督「思維所取代的文字內容」，並未規範兩個思維之間的關係，也未限制模型可生成的輸出分布。換言之，只要最終解碼答案的交叉熵（CE）夠低，模型對於中間思維的內部結構完全沒有受到約束，因此無法保證思維表示具備語意上的有效性。這正是 REST 論文所指出「CE-only 訓練的四大失敗」的核心問題。

**Q3：為什麼僅僅監督最終解碼答案的交叉熵（CE）不足以訓練出高品質的潛在推理系統？**

A：交叉熵損失只關注最終答案的機率分布是否正確，只要正確答案維持高機率，模型對於中間思維如何編碼資訊完全沒有收到任何訓練訊號。這種「無約束的思維」會導致嚴重的問題：不同問題的思維可能塌縮成相似的表示（破壞可分離性）、保留與輸出無關的輸入資訊（破壞最小性）、無法反映所有可能的輸出分布（破壞穩定性），以及無法真正替代其所要取代的文字（破壞因果性）。在多代理、遞迴的系統中，這些缺陷會隨著代理數與遞迴輪次增加而產生錯誤累積，最終大幅降低正確答案的機率。

**Q4：REST 所定義的「有效思維表示」四大屬性（因果性、最小性、可分離性、穩定性）分別代表什麼意義？**

A：因果性（Causality）要求思維表示必須保留重現輸出所需的資訊，使其能真正「替代」原本的文字內容；最小性（Minimality）則要求思維應丟棄與輸出無關的輸入資訊，避免冗餘；可分離性（Separability）要求不同語意輸入所產生的思維必須彼此可區分，避免不同問題的思維塌縮成一團；穩定性（Stability）則要求思維應反映所有可能輸出的分布，而非僅僅是某一個樣本。這四個屬性共同構成一個理論上完備的框架，確保思維表示在語意上既充分又精簡。

**Q5：REST 如何將這四個理論屬性轉化為可微分的損失函數，並整合進訓練流程？**

A：REST 將每個屬性分別設計成一個可微分的損失項，並以超參數 β 加權後加到原有的交叉熵損失之上，形成總訓練目標。這意味著 REST 不需要改變模型架構，也不會在推論時新增任何參數，僅僅是在訓練階段對思維表示施加額外的監督訊號。這種設計的優點在於：既保留了原有 CE 訓練的簡潔性，又能引導模型學會符合四大屬性的思維編碼方式，實現「表示層級監督」與「輸出層級監督」的雙重目標。

**Q6：REST 在系統架構上有哪些關鍵設計選擇，使其能同時適用於單代理與多代理設定？**

A：REST 採用潛在遞迴系統的設計，基礎 LLM 全部保持凍結（frozen），僅訓練內連結（inner-link）與外連結（outer-link）兩個小型映射模組。內連結 Rin 將某個代理的隱藏狀態映射回自身的輸入空間，使其能進行潛在步而非解碼詞元；外連結 Rψ 則將內連結的輸出映射到另一個代理的輸入空間，實現代理間通訊。論文更將原本僅用於多代理的此一架構延伸至單代理設定，讓單一模型能遞迴地處理自己的隱藏狀態，這種統一性使 REST 能在不修改架構的前提下靈活部署。

**Q7：REST 在哪些基準測試上進行了實驗評估，這些基準涵蓋了哪些領域？**

A：REST 在七個基準測試上進行了全面評估，包括 MATH500（數學）、GPQA-Diamond（科學）、MedQA（醫學）、AIME2025/2026（競賽數學）、LiveCodeBench-v6 與 MBPP+（程式碼生成）。這些基準橫跨了數學、科學、醫學與程式碼生成四大領域，能夠全面檢驗 REST 在不同類型推理任務上的泛化能力。這種跨領域的評估設計避免了僅在單一領域過擬合的疑慮，也更能反映真實應用場景的多樣性。

**Q8：REST 相較於僅使用交叉熵訓練的基線，在準確率上取得了哪些具體的提升？**

A：在相同的訓練資料、計算資源與潛在預算下，REST 在多代理設定中平均提升 +3.5 個百分點，在單代理設定中平均提升 +3.3 個百分點；最佳配置下更可達到 +7.5 與 +6.5 百分點的大幅進步。此外，REST 在推論時平均多解碼 15.4% 的詞元，這被歸因於模型對最終答案的收斂率提升了 30%。這些結果顯示 REST 不僅提升了準確率，也讓模型在潛在空間中的思考更有效率、更容易收斂到正確答案。

**Q9：有哪些實驗分析證實了 REST 訓練出的思維確實具備所宣稱的四大屬性？**

A：論文透過主成分分析（PCA）視覺化思維表示，發現 CE-only 訓練的思維在不同問題間會發生塌縮，而 REST 訓練的思維則保持良好的可分離性。同時，REST 訓練的思維在解碼回文字時能更好地還原代理原本的預期輸出，證實其因果性與最小性。此外，分析也顯示 REST 的思維編碼了更多達成正確答案所需的資訊，並且其屬性表現與正確答案機率的下界直接相關，從理論與實證兩方面驗證了四大屬性的有效性。

**Q10：在實際應用場景中，哪些任務最能受益於 REST 所帶來的潛在推理改進？**

A：需要多步驟、長鏈推理的任務最能受益，例如數學競賽題、複雜科學問題、醫學診斷推理以及多檔案程式碼生成等。這些任務在傳統 CoT 設定下需要產生大量中間文字，不僅成本高昂且容易出錯，而 REST 透過連續空間的潛在推理能更有效率地處理這類問題。對於需要多個專門代理協作的場景（如多專家會診系統、模組化程式設計助手），REST 的多代理設定更能發揮其錯誤累積控制與代理間通訊清晰的優勢。

**Q11：在將 REST 部署到實際產品時，需要考量哪些工程與系統層面的因素？**

A：首先，由於 REST 需要在訓練階段加入多個額外的損失項並調整 β 超參數，訓練流程會比單純 CE 訓練更為複雜，需要仔細調參以避免某一屬性過度主導。其次，雖然推論時無需新增參數，但潛在遞迴系統本身的記憶體與計算需求較高，部署時需評估硬體資源是否能支撐多輪遞迴。最後，REST 訓練出的思維更容易解碼回可解讀的文字，這對產品除錯與可解釋性是加分項，但團隊仍需建立相應的監控機制以追蹤潛在通訊的品質。

**Q12：REST 對大型語言模型推理研究領域帶來了哪些更廣泛的影響？**

A：REST 最重要的貢獻在於將「思維表示的品質」從一個模糊的概念轉化為四個可量化、可監督的具體屬性，為潛在推理研究提供了理論基礎。這種「表示層級監督」的思路可望啟發後續更多研究，不再僅僅追求最終答案的正確性，而是關注中間表徵的語意結構。此外，REST 展示了在不修改架構的前提下，僅透過訓練目標的改進即可獲得顯著效能提升，這對產業界與學術界都是一個具吸引力的設計哲學。

**Q13：REST 存在哪些已被論文承認的限制？**

A：REST 的有效性依賴於四大屬性損失項的權重 β 設定，不同任務或模型規模可能需要不同的 β 值，論文中雖顯示增益在不同權重下仍具穩健性，但最佳配置仍需實驗調整。此外，REST 目前主要在潛在遞迴系統上驗證，對於其他類型的潛在推理架構（如非遞迴式的單次潛在思考）是否同樣有效，仍有待進一步研究。基礎 LLM 必須保持凍結的設定也限制了 REST 與其他需要微調模型本身的方法的兼容性。

**Q14：在哪些情境下 REST 可能無法帶來預期的改進，甚至產生新的失敗案例？**

A：當任務的「正確輸出分布」本身非常模糊或開放時（例如創意寫作、開放式問答），穩定性屬性的監督可能難以定義，因為不存在單一明確的目標分布。此外，若訓練資料中不同問題的語意差異極小（例如僅有微小數值差異的數學題），可分離性損失可能難以有效拉開思維表示的距離。對於極短的簡單問題，潛在遞迴的多輪推理反而可能過度設計，帶來不必要的計算開銷。

**Q15：基於 REST 的研究成果，未來有哪些值得探索的研究方向？**

A：未來可將 REST 的四大屬性框架擴展到更多潛在推理架構，例如非遞迴式的單次潛在思考或層次化潛在表示，以驗證其通用性。另一個方向是探索如何自動化學習 β 等超參數，甚至讓模型自行調整各屬性的權重，以減少人工調參成本。此外，將 REST 與其他表示學習技術（如對比學習、資訊瓶頸理論）結合，或許能進一步強化思維表示的語意純度與泛化能力，這都是值得深入的研究課題。

## 實務應用指南

### 適用場景

1. **教育科技中的數理自動解題系統**：REST 在 MATH500 與 AIME2025/2026 等高難度數學基準上展現顯著提升，特別適合建置 K-12 至大學程度的智慧家教、解題批改助理，以及競賽訓練平台，能在不增加推論成本的情況下提升解題正確率。

2. **臨床決策支援與醫學問答系統**：MedQA 基準的改善顯示 REST 可應用於醫療問答機器人，例如症狀初步分流、醫學考試訓練輔助、住院醫師決策查詢工具，在維持隱私（無需解碼中間推理文字）的同時提升答案可靠性。

3. **程式碼生成與除錯助手**：LiveCodeBench-v6 與 MBPP+ 的成果代表 REST 適合用於 IDE 內建的程式碼助理、競賽程式設計輔導、自動化測試案例生成等場景，特別是在需要多步推理的演算法題目上。

4. **多代理協作的研究助理**：對於需要多個專門模型分工的研究工作（例如文獻回顧、假說生成、實驗設計），REST 的多代理設定可讓各代理以潛在通訊方式協作，避免冗長文字交換造成的延遲與成本。

5. **邊緣裝置與成本敏感的推論服務**：由於 REST 在推論時不增加參數也不改變架構，特別適合將現有雲端 LLM 蒸餾為高效潛在推理版本，部署於行動裝置、嵌入式系統或大規模客服自動化場景。

### 實作前置條件

**資料需求**：
- 任務配對資料集（問題與最終答案），需涵蓋目標領域（數學、科學、醫學、程式碼等）
- 對於多代理設定，需準備可拆分為子任務的資料，或設計代理分工協議
- 評估資料集應涵蓋語意多樣性，以驗證「可分離性」與「穩定性」是否真正改善

**計算資源**：
- 訓練階段：需具備足夠 VRAM 的 GPU（建議 A100/H100 等級），因為要同時保存凍結的基礎 LLM 與可訓練的內/外連結模組
- 推論階段：與基礎模型相當，無需額外參數
- 訓練資料量與計算量應與 CE-only 基線匹配，以確保公平比較

**技能門檻**：
- 熟悉 Transformer 架構、隱藏狀態與詞元嵌入之間的對齊機制
- 理解交叉熵損失與表示學習損失的組合調校
- 具備多代理系統設計經驗（若採用多代理設定）
- 具備超參數搜尋能力，特別是 β 權重與各屬性損失之間的平衡

### 實作步驟建議

1. **選擇基礎模型並凍結**：挑選一個表現良好的預訓練 LLM 作為基礎代理，將所有參數凍結。這是 REST 的核心前提——只訓練連結模組而非整個模型。

2. **建立內連結與外連結模組**：
   - 內連結（R_in）：將隱藏狀態映射回輸入嵌入空間，使代理能以潛在步驟取代解碼
   - 外連結（R_ψ）：將一個代理的輸出映射到下一個代理的輸入空間
   - 兩者皆為輕量模組，可採用線性投影或多層感知器

3. **實作 REST 的四項可微分損失**：
   - **因果性損失**：確保思維可替代產生對應文字的隱藏狀態
   - **最小性損失**：懲罰保留與最終答案無關的輸入資訊
   - **可分離性損失**：使不同問題的思維在潛在空間中可區分
   - **穩定性損失**：讓思維反映輸出分布而非單一樣本
   - 每項損失需設計為可微分，並可獨立加權

4. **組合總損失並訓練**：總損失 = CE 損失 + β × (四項 REST 損失加總)。建議從小 β 值開始，透過消融實驗確定各項的最佳權重。論文顯示增益在不同權重下仍具穩健性。

5. **驗證思維屬性**：訓練後應檢查四項屬性是否真正成立——例如透過 PCA 視覺化思維分布、嘗試從思維解碼預期文字、測量不同問題間的思維距離。

6. **基準測試與部署**：在目標領域的基準上評估（建議至少包含 3-5 個不同領域），確認相較 CE-only 基線有實質改善後即可部署。推論時無需任何架構變更。

### 潛在風險與注意事項

**風險 1：超參數 β 設定不當**
- 現象：β 過大可能壓過 CE 訊號導致答案正確率下降；β 過小則 REST 損失幾乎無作用
- 緩解：採用網格搜尋或貝氏最佳化；論文指出增益在合理範圍內具穩健性，但仍建議在驗證集上系統性調校

**風險 2：錯誤累積效應**
- 現象：在多代理或多輪遞迴設定中，後續代理建立在先前代理的思維上，錯誤會逐層放大
- 緩解：REST 的可分離性與穩定性損失有助於緩解此問題，但仍應限制遞迴輪數，並在關鍵節點插入文字解碼檢查點

**風險 3：領域轉移失效**
- 現象：在訓練領域表現良好，但轉移到新領域時四項屬性可能不再成立
- 緩解：準備領域適應資料進行微調；監控思維的可分離性指標作為領域漂移的早期警訊

**風險 4：可解釋性誤導**
- 現象：REST 改善了從思維解碼文字的能力，但解碼出的文字不等於模型真實的推理過程
- 緩解：將解碼文字視為「近似說明」而非「真實推理」，在敏感應用中保留人類審查環節

**風險 5：潛在預算限制**
- 現象：思維長度 m' 直接影響計算量與記憶體需求
- 緩解：在訓練前明確設定潛在預算上限，並在預算內最佳化；論文已展示在相同潛在預算下 REST 仍優於 CE-only

### 與其他技術的整合建議

**與思維鏈（CoT）提示整合**：REST 不取代 CoT，而是其連續空間的對應物。可設計混合系統——簡單問題用 CoT 快速處理，複雜問題路由至 REST 潛在推理代理。

**與檢索增強生成（RAG）整合**：將 REST 應用於 RAG 流程中的「重排序」或「答案合成」階段，可讓模型在潛在空間中整合多段檢索結果，避免冗長的引用文字堆疊。

**與既有潛在推理方法整合**：CODI 與 SIM-COT 等方法專注於監督目標文字，REST 則監督思維表示的屬性。可將 REST 的損失項加入這些方法，形成混合訓練目標。

**與多代理框架整合**：REST 的多代理設定可整合至 LangGraph、AutoGen 等框架，將其通訊層從文字替換為潛在向量傳遞，大幅降低通訊成本。

**與模型蒸餾整合**：REST 適合作為大型模型向小型模型蒸餾時的訓練目標——學生模型學習的不只是最終答案，還包括符合四項屬性的中間思維表示。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節的動機部分，理解「為什麼要在連續空間中推理」以及「CE-only 訓練的四大失敗」。重點掌握四項屬性（因果性、最小性、可分離性、穩定性）的直觀意義，不必深究數學推導。Figure 2 的視覺化是最佳入門點。

**給 AI 工程師**：直接進入第 2 節的設定與符號定義，並仔細閱讀附錄 A.1 中四項損失的具體數學形式。實作時應特別關注內連結與外連結的架構選擇、β 權重的調校策略，以及如何在現有推理管線中無縫替換為 REST 版本。建議先在單代理設定上驗證，再擴展至多代理。

**給研究者**：第 2.1 節對 CE-only 失敗的理論分析是核心貢獻之一，值得仔細推敲。附錄 A.2 提供了四項屬性如何下界正確答案機率的證明，這是後續理論工作的基礎。可進一步探索的方向包括：四項屬性是否完備、放寬某些屬性的代價、與資訊瓶頸理論的關聯。

**給產品經理**：重點關注三個數字——最高 +7.5 百分點的準確率提升、30% 的收斂改善、以及「推論時無需新增參數」。這代表 REST 是一個「訓練成本換推論品質」的方案，特別適合對延遲敏感但願意投資訓練的產品。建議在評估導入時，將 REST 視為現有 LLM 服務的「升級選項」而非替代方案，並優先在錯誤成本高的場景（醫療、法律、程式碼）試行。
