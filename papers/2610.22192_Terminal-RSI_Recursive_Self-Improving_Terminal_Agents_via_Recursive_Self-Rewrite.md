## ⚡ TL;DR

終端代理難將驗證器結果轉為有效策略更新，部分進展難以達成完整任務解析。
本文提出Terminal-RSI，交替遞迴自我改寫與評論繼承式策略精煉，整合TB-GAE與獎勵設計。
Terminal-RSI-27B於TB 4.0達19.84%，長程任務完成數從0升至5。

## 摘要翻譯

將驗證器結果（verifier outcomes）轉化為有用的策略更新（policy updates），以及將部分進展轉化為完整任務解決，對終端代理（Terminal Agents）而言至關重要。我們提出 Terminal-RSI，它在已驗證軌跡（verified trajectories）的遞迴自我改寫（Recursive Self-Rewrite, RSR）與評論繼承（critic-inheriting）的遞迴策略精煉（Recursive Policy-Refine, RPR）之間交替進行。我們制定了回合邊界跳過觀測 GAE（Turn-Boundary Skip-Observation GAE, TB-GAE），以保留詞元特定基線（token-specific baselines），同時跨互動回合（interaction turns）進行衰減（decay across interaction turns）。家族密集獎勵（Family Dense Reward, FDR）在任務家族（task families）之間校準語意進展（semantic progress）；成功優先獎勵（Success-Prioritized Reward, SPR）將嚴格成功（strict success）與有界部分信用（bounded partial credit）區分開來。預熱評論模型（Warm-up Critic Model）、遞迴評論交接（recursive critic handoff）以及階段特定學習率（stage-specific learning rates）協調兩個精煉階段。以 Qwen3.8-27B 基礎模型為起點，經過 RSR-1、RPR-1、RSR-2 與 RPR-2 的五階段序列（five-stage sequence），最終得出 Terminal-RSI-27B：在 Terminal-Bench 4.0 上達到 19.84%，在 Terminal-Bench 2.1 上達到 86.52%，在 Terminal-Bench 3.0 上達到 16.95%，Terminal-Bench Hard 上則為 79.00%。在長程終端基準（Long-Horizon Terminal-Bench, LHTB）上，過程獎勵（process reward）從 0.21 提升至 0.37，嚴格完成（strict completion）從 0/46 提升至 5/46；SWR100 成功率從 3.00% 翻倍至 6.00%。透過遞迴耦合已驗證軌跡改寫與評論繼承的策略精煉，每個保留階段（retained stages）鞏固已發現的行為，並使代理從部分局部修復（partial local repairs）逐步推進至嚴格終端驗證（strict terminal verification）。

### 核心貢獻（3～5點）
- 提出 Terminal-RSI 框架，透過遞迴自我改寫（RSR）與評論繼承的遞迴策略精煉（RPR）交替進行，實現終端代理的遞迴自我改進（Recursive Self-Improving）。
- 設計回合邊界跳過觀測 GAE（TB-GAE）演算法，在保留詞元特定基線的同時，於互動回合間施加衰減，以更精準地估計優勢函數。
- 提出家族密集獎勵（FDR）與成功優先獎勵（SPR）兩種獎勵設計機制，前者校準跨任務家族的語意進展，後者區分嚴格成功與有界部分信用。
- 建立包含預熱評論模型、遞迴評論交接與階段特定學習率的協調機制，並以五階段序列（RSR-1 → RPR-1 → RSR-2 → RPR-2）從 Qwen3.8-27B 訓練出 Terminal-RSI-27B。
- 在多項基準測試上取得顯著成果：Terminal-Bench 4.0 達 19.84%、Terminal-Bench 2.1 達 86.52%、Terminal-Bench 3.0 達 16.95%、Terminal-Bench Hard 達 79.00%；LHTB 過程獎勵與嚴格完成率均有提升，SWR100 成功率翻倍。

### 適合對象
本論文最適合以下讀者閱讀：從事強化學習（特別是基於過程獎勵與驗證器回饋的訓練方法）研究的研究人員與工程師；關注大型語言模型代理（LLM Agent）在終端環境中自主執行與自我改進的研究者；對遞迴自我改進（Recursive Self-Improving）機制設計感興趣的 AI 安全與對齊領域學者；以及從事程式碼生成、系統管理自動化等長程任務求解的實務開發者。讀者宜具備強化學習基礎概念與 Transformer 架構的預訓練知識，方能充分理解 TB-GAE 演算法細節與五階段訓練流程的設計動機。

## 深度分析

#### 方法論解析

Terminal-RSI 提出了一個遞迴自我改進框架，核心在於將「已驗證軌跡的監督式重寫」與「評論繼承式的策略精煉」交替耦合，以解決終端代理（terminal agents）訓練中兩個根本性障礙：**時間膨脹（temporal dilation）** 與 **遞迴監督下的價值漂移（value drift across recursive supervision）**。

**1. 雙階段遞迴架構：RSR 與 RPR 的交替**

整體訓練流程為五階段序列：Base（Qwen3.8-27B）→ RSR-1 → RPR-1 → RSR-2 → RPR-2，最終產出 Terminal-RSI-27B。

- **遞迴自我改寫（Recursive Self-Rewrite, RSR）**：屬於純演員（actor-only）階段，透過 runbook 規劃、洩漏審查與全新公開執行，將互補測試框架的發現轉移至代理的軌跡中。RSR 改變的是演員偏好的動作分布，進而改變評論所遭遇的歷史分布。
- **遞迴策略精煉（Recursive Policy-Refine, RPR）**：屬於評論繼承（critic-inheriting）階段，保留前一階段的評論權重，並透過階段局部價值校準與獎勵演化進行聯合最佳化。RPR 在第二循環採用五倍演員學習率縮減，以穩定遞迴更新。

**2. 信用指派：回合邊界跳過觀測 GAE（TB-GAE）**

傳統 GAE 在處理「數百詞元表達一個 shell 動作、數千觀測詞元卻不引入新策略決策」的交錯鏈時，會因重複折扣與追蹤因子而依文本長度而非實質互動來衰減遠距信用。TB-GAE 的設計理念是：

- **詞元特定基線（token-specific baselines）保留**：在動作詞元上維持精細的價值估計。
- **跨互動回合衰減（decay across interaction turns）**：將衰減單位從詞元層級提升至回合層級，避免觀測冗餘造成的信用衰減扭曲。
- **固定輸入延續（fixed-input continuation）**：支援未變鏈的精確邊界傳輸，與摘要操作（會改變條件歷史）做出明確區隔。

論文進一步分析了截斷誤差（truncation error）與條件變異數（conditional variance），為 TB-GAE 提供理論基礎。

**3. 獎勵設計：FDR 與 SPR 的雙層結構**

- **家族密集獎勵（Family Dense Reward, FDR）**：校準跨任務家族（task families）的語意進展（semantic progress），避免單一全域尺度過度強調擁有大量驗證器的家族。
- **成功優先獎勵（Success-Prioritized Reward, SPR）**：將嚴格成功（strict success）與有界部分信用（bounded partial credit）分離。固定軌跡分析顯示，在早期獎勵下失敗仍佔總獎勵質量的 50.09%，部分失敗甚至通過所有執行場景檢查卻未通過終端閘門。SPR 的目標並非消除部分信用（部分信用支持探索），而是使其在訓練後期從屬於已驗證完成。

**4. 評論管理：預熱評論模型與遞迴評論交接**

- **預熱評論模型（Warm-up Critic Model）**：在 RPR-1 開始前先進行評論專屬的預熱 epoch，建立初步的結果結構理解。
- **遞迴評論交接（recursive critic handoff）**：每次演員轉換後，評論權重被保留並進行階段局部校準，而非完全重置。重置會丟失已學結果結構；不校準的轉移則會保留系統性預測誤差，進而污染詞元優勢與價值自助法（value bootstraps）。
- **階段特定學習率（stage-specific learning rates）**：協調兩個精煉階段，避免強演員無法為新歷史、獎勵或執行視野提供可靠價值。

**5. 異步執行的考量**

論文特別區分管線排程（pipeline scheduling）與策略更新及訓練-推理實作差異所引發的似然性錯配（likelihood mismatch），這在實際大規模訓練中是不可忽視的工程問題。

#### 實驗數據解讀

**1. 基準測試表現（Terminal-Bench 系列）**

| 基準 | Base | RSR-1 | RPR-1 | RSR-2 | RPR-2（最終） |
|------|------|-------|-------|-------|--------------|
| Terminal-Bench 4.0 | 0.00% | 6.10% | 16.67% | 17.46% | **19.84%** |
| Terminal-Bench 3.0 | 0.00% | 6.80% | 14.29% | 15.00% | **16.95%** |
| Terminal-Bench 2.1 | 51.70% | 70.10% | 77.53% | 86.52% | **86.52%** |
| Terminal-Bench Hard | 31.00% | 54.00% | 69.50% | 76.00% | **79.00%** |

**關鍵觀察**：

- **遞迴改進的單調性**：在所有基準上，每個保留階段都帶來提升或持平，證實了遞迴耦合機制的有效性。
- **基準難度差異化表現**：在較舊且較易的 Terminal-Bench 2.1 上，Base 已達 51.70%，最終達到 86.52%；而在最新的 Terminal-Bench 4.0 上，Base 完全無法解決（0.00%），最終僅達 19.84%。這顯示 Terminal-RSI 並非「解決所有問題」，而是將基礎模型從零成功率提升至有意義的水平。
- **RSR 與 RPR 的互補性**：RSR 階段帶來監督式躍升（如 RSR-1 將 TB 2.1 從 51.70% 提升至 70.10%），RPR 階段則透過強化學習進一步鞏固與精煉（如 RPR-1 將 TB 4.0 從 6.10% 提升至 16.67%）。
- **第二循環的邊際效應**：RSR-2 與 RPR-2 的提升幅度普遍小於第一循環（如 TB 4.0 從 16.67% 到 19.84%），暗示遞迴改進存在收益遞減，但也證明並未出現災難性退化。

**2. 長程基準（LHTB）表現**

- **過程獎勵（process reward）**：從 0.21 提升至 0.37（提升約 76%）。
- **嚴格完成（strict completion）**：從 0/46 提升至 5/46（從完全無法完成到解決約 10.9% 的任務）。

這是論文最具說服力的結果之一，因為 LHTB 強調的是「大量局部進展未必產生單一完整解決方案」的長依賴鏈挑戰。Terminal-RSI 不僅提升了過程品質，更實現了從「零嚴格完成」到「有意義的嚴格完成數量」的質變。

**3. SWR100 表現**

成功率從 3.00% 翻倍至 6.00%，雖然絕對值不高，但對於一個以 27B 規模模型挑戰 SWE-bench 類任務而言，仍顯示了遞迴機制的有效性。

#### 與現有研究的比較

**1. 定位**

Terminal-RSI 建立在 T1 終端基礎設施、PPO、GAE 與價值準備（value-preparation）的先驅工作之上，並非聲稱這些基礎元件的原創性，而是聚焦於**它們的遞迴耦合**。這是一個務實的定位：承認領域累積，重在組合創新。

**2. 相較於單階段自我改進的優勢**

- **vs. 純監督式自我改進**：單純的 RSR 雖能帶來顯著提升（如 TB 2.1 從 51.70% 到 70.10%），但缺乏強化學習的價值精煉。
- **vs. 純 RL 自我改進**：若僅使用 RL 而無 RSR 的監督式過渡，則會面臨冷啟動與稀疏獎勵問題。
- **vs. 評論重置策略**：完全重置評論會丟失已學結果結構；Terminal-RSI 的評論繼承與階段局部校準提供了中間路徑。

**3. 相較於其他遞迴改進框架**

- **STaR、V-STaR、ReST 等**：這些方法多聚焦於單一循環的自我生成與過濾，Terminal-RSI 的雙階段交替與評論繼承設計更精細。
- **RLHF 後續工作**：Terminal-RSI 將 RLHF 思想延伸至「代理對代理」的遞迴改進，但聚焦於可執行環境而非人類偏好。

**4. 局限性**

- **規模限制**：基於 27B 模型，與更大規模模型（如 70B、100B+）的比較未涵蓋。
- **領域特定性**：聚焦於終端任務，對其他類型代理（如網頁代理、GUI 代理）的泛化性未驗證。
- **計算成本**：五階段序列需要大量計算資源，實際部署成本可能限制其可及性。
- **基準天花板**：在 Terminal-Bench 4.0 上僅達 19.84%，距離實用部署仍有相當距離。
- **捨棄方案的細節**：圖 1 提及灰色分支但未充分說明，可能影響對方法選擇依據的理解。

#### 未來研究方向

**1. 規模化探索**

- **更大基礎模型**：將 Terminal-RSI 應用於 70B、100B+ 規模模型，驗證遞迴改進的規模效應。
- **多語言與多領域延伸**：將框架從終端任務延伸至網頁代理、GUI 代理、機器人代理等領域。

**2. 理論深化**

- **TB-GAE 的收斂性分析**：提供更嚴格的截斷誤差與條件變異數界限。
- **評論繼承的理論保證**：分析在何種條件下評論繼承優於重置，以及階段局部校準的必要性。
- **獎勵演化的最優性**：研究 FDR 與 SPR 的組合是否在更廣泛的任務分布上仍是最優的。

**3. 方法擴展**

- **更多循環**：探索 RSR-3、RPR-3 等更深層遞迴，分析收益遞減的邊界。
- **自適應學習率**：取代固定的階段特定學習率，改為基於驗證器回饋的動態調整。
- **多評論家架構**：引入多個專門化評論家（如針對不同任務家族），透過評論交接實現知識遷移。

**4. 獎勵設計創新**

- **階層式獎勵**：將 FDR 與 SPR 擴展為多層次結構，支援更細粒度的進展建模。
- **對比式獎勵**：利用成功與失敗軌跡的對比學習更穩健的價值函數。
- **不確定性感知獎勵**：將驗證器的不確定性納入獎勵計算，避免過度自信的信用指派。

**5. 應用拓展**

- **程式修復**：將 Terminal-RSI 應用於更廣泛的程式修復任務，包括跨語言、跨框架。
- **系統管理**：探索在 DevOps、雲端配置管理等系統管理任務上的應用。
- **教育與訓練**：利用 Terminal-RSI 的遞迴改進機制建構自適應學習代理。

**6. 安全與對齊**

- **遞迴改進的安全性**：隨著代理能力遞迴提升，如何確保行為與人類意圖對齊成為關鍵問題。
- **價值漂移監控**：開發監控評論價值漂移的機制，及早發現遞迴過程中的異常。
- **可解釋性**：提升遞迴改進過程的可解釋性，使研究者能理解每個階段的具體改進來源。

**7. 基準與評測**

- **新基準建構**：隨著 Terminal-Bench 系列快速演進（2.1 → 3.0 → 4.0），需要更穩定、更全面的評測基準。
- **過程評測**：除了最終成功率，應更重視過程品質的評測，如同論文中 LHTB 的過程獎勵指標。
- **跨基準泛化**：研究在某一基準上訓練的代理是否能泛化至其他基準，這對實際部署至關重要。

Terminal-RSI 的核心貢獻在於揭示了「監督式重寫」與「評論繼承式強化學習」的遞迴耦合能有效推動終端代理的能力邊界。隨著該領域的快速發展，這種遞迴自我改進的範式有望成為構建更強大代理的標準方法之一。

## 論文問答

**Q1：終端代理面臨的核心挑戰是什麼？為什麼傳統方法難以解決？**

A：終端代理的核心挑戰在於其評估方式是基於對可執行環境的持久性改變，而非回應的表面合理性，這使得學習必須將成功的探索連接到可重現的執行。論文指出兩個主要障礙：首先是時間膨脹（temporal dilation）問題，即詞元生成的時鐘與環境變化的時鐘不一致，數百個詞元可能表達一個 shell 動作，而數千個觀測詞元卻不引入額外策略決策。其次是遞迴監督中的價值漂移問題，重寫改變了演員偏好的動作，進而改變評論遇到的历史，後續強化學習又再次改變這些分佈。傳統 GAE 在處理交錯詞元鏈時，會根據文本長度而非關鍵互動來衰減遠距信用，導致相同決策與終端結果的執行可能因日誌冗長度不同而獲得不同信用。

**Q2：為什麼將驗證器結果轉化為有用的策略更新如此困難？**

A：驗證器結果轉化為策略更新的困難來自於獎勵對齊的多層次挑戰：失敗軌跡可能累積許多通過的檢查但未滿足完整執行契約，使得部分進展與嚴格成功難以區分。單一全域獎勵尺度可能過度強調具有大量驗證器的任務家族，而純粹按比例分配的進展獎勵在策略已具備嚴格成功能力後仍可能偏袒不完整行為。論文透過固定軌跡分析具體展示了此問題：在早期獎勵下，失敗案例獲得 50.09% 的總獎勵質量，部分失敗案例甚至通過所有執行情境檢查卻錯過終端閘門，凸顯了獎勵設計需要隨訓練進展而演進。

**Q3：為什麼部分進展難以轉化為完整任務解決？**

A：部分進展難以轉化為完整任務解決的根本原因在於長程依賴鏈中，實質性的局部進展未必產生單一完整解決方案，這在 Long-Horizon Terminal-Bench 中尤為明顯。學習必須同時連接兩個迴圈：將成功的探索連接到可重現的執行，以及將延遲驗證連接到使其成為可能的早期決策。流暢的計畫或增加的局部通過檢查數量本身都無法單獨閉合這個迴圈，因為它們缺乏將驗證器結果、軌跡重寫與策略精煉遞迴耦合的機制，這正是 Terminal-RSI 試圖解決的核心問題。

**Q4：Terminal-RSI 的核心方法是什麼？**

A：Terminal-RSI 的核心方法是交替進行僅涉及演員的遞迴自我改寫（RSR）與評論繼承的遞迴策略精煉（RPR），形成一個五階段序列（Base、RSR-1、RPR-1、RSR-2、RPR-2）。從 RSR-1 演員與預熱評論模型開始，RPR 協調階段局部價值校準與獎勵演進，並在第二循環中將演員學習率降低五倍以穩定訓練。監督式轉換保留評論權重，每個新的策略精煉階段在聯合優化前先調整繼承的價值，這種遞迴耦合是該框架的設計重點，而非聲稱底層 PPO、GAE 等基本元件的獨立性。

**Q5：Turn-Boundary Skip-Observation GAE (TB-GAE) 的關鍵創新是什麼？**

A：TB-GAE 的關鍵創新在於保留詞元特定基線的同時，跨互動回合施加衰減，從而解決了傳統 GAE 將文本長度誤認為環境互動的問題。當 GAE 穿越交錯詞元鏈時，重複的折扣與追蹤因子會根據文本長度而非關鍵互動來衰減遠距信用，而僅遮罩觀測詞元並未消除其在遞迴節點中的影響。TB-GAE 進一步表徵了固定輸入延續、截斷誤差與條件變異數，使信用分配更貼近實際的環境互動結構。對於長上下文，分塊允許精確邊界傳輸，而摘要則會改變條件歷史，兩者在本質上是不同的操作。

**Q6：為什麼需要 Family Dense Reward (FDR) 與 Success-Prioritized Reward (SPR)？**

A：FDR 與 SPR 的設計是為了解決獎勵對齊的相關困難，因為終端任務家族暴露不同數量的語意檢查，且失敗軌跡可能累積許多通過的檢查。FDR 校準跨任務家族的語意進展，避免單一全域尺度過度強調具有大量驗證器的家族，從而防止獎勵分佈失衡。SPR 將嚴格成功與有界部分信用區分開來，其設計目標並非消除支持探索的部分信用，而是隨著訓練進展保持此類信用從屬於已驗證的完成，使獎勵結構能夠隨代理能力提升而演進。

**Q7：Terminal-RSI-27B 在各基準測試上的關鍵結果為何？**

A：Terminal-RSI-27B 在四個 Terminal-Bench 變體上展現了顯著提升：Terminal-Bench 4.0 達到 19.84%，Terminal-Bench 2.1 達到 86.52%，Terminal-Bench 3.0 達到 16.95%，Terminal-Bench Hard 達到 79.00%。在長程任務 LHTB 上，過程獎勵從基礎模型的 0.21 提升至 0.37，嚴格完成任務數從 0/46 提升至 5/46，顯示從完全無法完成到能夠解決部分長程任務的質變。SWR100 成功率從 3.00% 翻倍至 6.00%，驗證了遞迴自我改進機制在多樣化基準測試上的泛化能力。

**Q8：五階段序列如何影響模型表現？**

A：五階段序列（Base、RSR-1、RPR-1、RSR-2、RPR-2）展示了遞迴耦合的累積效應，每個保留階段都鞏固已發現行為並推進至下一階段。從 Base 到 RPR-2，Terminal-Bench 4.0 從 0% 提升至 19.84%，Terminal-Bench 3.0 從 0% 提升至 16.95%，Terminal-Bench 2.1 從 51.70% 提升至 86.52%，Terminal-Bench Hard 從 31.00% 提升至 79.00%。值得注意的是，Terminal-Bench 2.1 在 RSR-2 階段已達到 86.52%，RPR-2 維持相同表現，顯示在某些基準上策略精煉已接近飽和；而 LHTB 嚴格完成數從 RPR-1 的 2/46 持續提升至 RPR-2 的 5/46，則展示了遞迴機制在長程任務上的持續進步空間。

**Q9：捨棄的替代方案提供了哪些洞見？**

A：圖中灰色分支顯示了捨棄的替代方案，包括 RPR、RSR、Process Discard 等變體，這些消融實驗支持了最終保留的五階段序列設計。Process Discard 變體的比較顯示了過程獎勵設計的重要性，移除該組件會導致表現下降，凸顯 FDR 與 SPR 在獎勵演進中的關鍵角色。不同 RPR 步數（20 步 vs 18 步）的比較則顯示了階段特定超參數的影響，第二循環採用較少步數反映了學習率降低後的收斂特性。這些捨棄方案共同驗證了遞迴耦合機制中每個組件的必要性。

**Q10：Terminal-RSI 的實際應用場景有哪些？**

A：Terminal-RSI 適用於需要持久性環境變更的自動化任務，特別是軟體工程領域的程式碼修復、依賴管理與儲存庫維護等場景，如 SWE-bench 所代表的基準測試。這些場景的共同特點是任務完成需要通過受保護的驗證器，而非僅憑回應的表面合理性，這對代理的可重現執行能力提出了嚴格要求。在長程依賴鏈場景中，如 LHTB 所模擬的多步驟系統管理任務，Terminal-RSI 透過遞迴耦合機制將部分進展逐步轉化為完整解決方案，這對於實際的 DevOps 自動化、CI/CD 流程優化等應用具有直接價值。

**Q11：從產品角度考慮，Terminal-RSI 有哪些部署考量？**

A：部署 Terminal-RSI 需要考慮幾個關鍵的工程因素：首先是異步執行的管線排程問題，需要區分管線排程本身與策略更新引起的似然不匹配，以及訓練-推理實作差異帶來的影響。其次是評論繼承機制的穩定性，監督式轉換後必須重新校準價值以避免系統性預測誤差進入詞元優勢與價值引導。此外，五階段序列與階段特定學習率需要精細的訓練協調，預熱評論模型與遞迴評論交接增加了系統複雜度，這在實際部署中需要可靠的 MLOps 基礎設施支援。

**Q12：Terminal-RSI 對該領域的影響是什麼？**

A：Terminal-RSI 透過遞迴耦合驗證軌跡重寫與評論繼承策略精煉，為終端代理的自我改進提供了新範式，突破了傳統靜態訓練的局限。它建立了從部分局部修復到嚴格終端驗證的漸進式進步路徑，並透過 TB-GAE、FDR、SPR 等組件系統性地解決了時間膨脹、價值漂移與獎勵對齊等核心挑戰。這項工作推動了終端代理從單次訓練轉向遞迴自我改進的範式轉移，對於構建能夠在複雜可執行環境中持續學習的自主系統具有重要意義，也為未來更大規模的自我改進代理研究奠定了方法論基礎。

**Q13：Terminal-RSI 存在哪些已承認的限制？**

A：論文承認的限制包括獎勵設計仍有改進空間：固定軌跡分析顯示在早期獎勵下失敗案例獲得 50.09% 的總獎勵質量，顯示部分進展與嚴格成功之間的區分仍不夠精確。評論繼承機制雖保留了已學習的結果結構，但若無校準則可能保留系統性預測誤差，這些誤差會進入詞元優勢與價值引導。時間膨脹問題雖透過 TB-GAE 緩解，但觀測遮罩並未消除其在遞迴節點中的影響；長上下文處理中，分塊與摘要有本質取捨——分塊允許精確邊界傳輸，而摘要會改變條件歷史並可能移除未來決策所需的細節。

**Q14：Terminal-RSI 可能面臨哪些失敗案例？**

A：潛在的失敗案例包括幾種情境：當任務家族的語意檢查數量差異極大時，FDR 校準可能仍不足以完全平衡獎勵分佈，導致某些家族被過度或不足強調。當代理在 RSR 階段產生看似合理但實際有漏洞的軌跡時，評論繼承可能放大這些錯誤，因為監督式轉換保留了可能不準確的價值估計。當環境變化極為稀疏或延遲極長時，TB-GAE 的跨回合衰減可能無法有效傳遞信用，使得早期關鍵決策的影響被過度衰減。此外，在異步執行環境中，管線排程與似然不匹配的交互可能導致訓練不穩定，特別是在快速迭代的 RSR-RPR 循環中。

**Q15：未來的研究方向有哪些？**

A：未來研究方向包括多個層面：在獎勵設計方面，可探索更精細的方法以區分部分進展與嚴格成功，例如引入階層化獎勵或對比學習機制。在評論繼承方面，可研究更高效的價值校準技術，例如基於軌跡品質的動態權重調整，或結合不確定性估計的保守更新策略。TB-GAE 可推廣到更複雜的多代理或層次化互動場景，研究如何在多層決策結構中保持信用分配的準確性。此外，將摘要與分塊操作更智慧地結合，例如透過學習式摘要保留關鍵決策資訊，是另一個有前景的方向。最終，Terminal-RSI 框架可應用於更廣泛的可執行環境，如機器人控制、系統管理、自動化科學實驗等領域，推動通用自主代理的發展。

## 實務應用指南

### 適用場景

1. **企業內部 DevOps 與 SRE 自動化**：在大型基礎架構中，終端代理可自動執行依賴修復、套件升級、配置回滋與服務重啟等任務。Terminal-RSI 的遞迴自我改進機制特別適合需要長期累積修復經驗的場景，例如分散式系統中常見的「部分本地修復」逐步收斂至「嚴格終端驗證」的故障排除流程。

2. **CI/CD 流水線中的失敗測試自動修復**：當 CI 流水線因環境差異、依賴版本衝突或資源限制而失敗時，Terminal-RSI 可作為修復代理，透過 RSR 從已驗證的成功軌跡中學習，並以 RPR 持續精煉策略，特別適合處理需要多輪互動才能定位根因的整合測試失敗。

3. **程式碼遷移與重構專案**：在跨版本升級（如 Python 2→3、Java 8→17、框架大版本遷移）時，Terminal-RSI 可在沙箱環境中反覆嘗試、驗證並累積修復經驗，逐步將「部分通過編譯」推進至「完整測試套件通過」。

4. **安全漏洞修補與 CVE 應急回應**：面對已知漏洞需要快速修補並驗證修復有效性時，Terminal-RSI 的 FDR/SPR 獎勵設計能區分「部分檢查通過」與「嚴格驗證通過」，避免代理在多個獨立檢查中累積偽陽性信用而忽略真正的修復完整性。

5. **教育與訓練環境中的程式設計助教**：在程式設計課程中，Terminal-RSI 可作為自動評測代理，根據學生提交的程式碼在終端環境中執行、診斷錯誤並提供漸進式提示，從「部分測試通過」逐步引導至「完整解決方案」。

### 實作前置條件

**資料需求**
- 已驗證的終端任務軌跡資料集（建議至少數萬條），涵蓋多個任務家族以支援 FDR 的家族校準
- 對應的驗證器（verifier）輸出，包含嚴格成功、部分通過與失敗三類標記
- 任務家族的語意分組標註，用於 FDR 的家族密集獎勵計算
- 乾淨的執行環境映像（Docker 容器或沙箱），確保可重現性

**計算資源**
- 至少 8 顆以上的高階 GPU（如 H100 或 A100），用於 27B 規模模型的 PPO 訓練與評論模型更新
- 大容量高效能儲存（建議 NVMe SSD，數 TB 等級），用於儲存軌跡、回放緩衝區與檢查點
- 分散式訓練框架支援（如 DeepSpeed、FSDP 或 Megatron），以處理評論模型與策略模型的並行更新
- 異步執行基礎設施（任務排程器、容器編排系統），區分管線排程與策略更新造成的 likelihood mismatch

**技能前提**
- 熟悉強化學習基礎（PPO、GAE、優勢估計）
- 具備大型語言模型微調經驗（SFT、RLHF 或 RLAIF）
- 理解終端環境的沙箱化與驗證器設計
- 能閱讀並實作論文中的 TB-GAE、FDR、SPR 等客製化組件
- 具備分散式訓練除錯能力，特別是評論模型繼承時的價值校準問題

### 實作步驟建議

**階段一：基礎建設（2-4 週）**
1. 部署 T1 終端基礎設施或等效的沙箱執行環境，確保任務可重現且驗證器輸出穩定。
2. 準備 Qwen3.8-27B（或等效規模的開源模型）作為基礎模型，並完成初步的指令微調。
3. 建立任務家族分類體系，定義每個家族的語意檢查數量與嚴格成功條件，作為 FDR 的輸入。

**階段二：RSR-1 遞迴自我改寫（3-5 週）**
1. 收集基礎模型在終端任務上的執行軌跡，篩選通過驗證器的成功軌跡。
2. 實作 RSR 的 runbook 規劃、洩漏審查與全新公開執行流程，將成功軌跡重寫為高品質監督資料。
3. 使用 RSR-1 資料對基礎模型進行監督微調，產出 RSR-1 演員模型。
4. 同步訓練 Warm-up Critic Model，使其熟悉 RSR-1 演員的歷史分佈與獎勵結構。

**階段三：RPR-1 遞迴策略精煉（4-6 週）**
1. 實作 TB-GAE，確保回合邊界的衰減正確應用，同時保留詞元特定基線。
2. 設計 FDR 與 SPR 獎勵函數，校準家族間的語意進展並區分嚴格成功與有界部分信用。
3. 啟用評論繼承機制，將 Warm-up Critic 的權重傳遞至 RPR-1 的評論模型。
4. 執行 PPO 訓練，採用階段特定學習率，進行評論模型專屬的初始 epoch 與四輪相位局部校準。
5. 評估 RPR-1 在 Terminal-Bench 系列基準上的表現，確認部分局部修復能力已建立。

**階段四：RSR-2 與 RPR-2 第二輪遞迴（4-6 週）**
1. 以 RPR-1 為基礎再次執行 RSR，從新一輪已驗證軌跡中提取更高品質的監督信號。
2. 在 RPR-2 中將演員學習率降低為前一週期的五分之一，保留評論繼承但加強相位局部校準。
3. 持續監控過程獎勵（process reward）與嚴格完成率的變化趨勢，確保從部分修復穩定收斂至嚴格驗證。
4. 產出最終的 Terminal-RSI-27B 模型，並在 LHTB、SWR100 等長程基準上驗證泛化能力。

**階段五：部署與監控（2-3 週）**
1. 將模型封裝為可呼叫的終端代理服務，設計 API 介面與權限控管。
2. 建立軌跡記錄與驗證器回饋迴路，收集真實環境中的失敗案例作為下一輪 RSR 的素材。
3. 設定漂移監控指標（過程獎勵分佈、嚴格完成率、平均互動回合數），定期觸發再訓練流程。

### 潛在風險與注意事項

**風險一：評論模型價值漂移**
- 問題：當 RSR 改變演員偏好的歷史分佈後，繼承的評論模型可能保留系統性預測誤差，導致詞元優勢與價值引導點不準確。
- 緩解：嚴格執行「評論模型專屬初始 epoch」與「四輪相位局部校準」，不要為了加速而跳過校準階段；在每輪 RPR 開頭監控價值預測誤差，若誤差未收斂則延長校準步數。

**風險二：時間膨脹導致的信用錯配**
- 問題：GAE 在交錯的詞元鏈上以文本長度衰減信用，而非以互動回合衰減，導致冗長日誌的軌跡獲得不當的信用分配。
- 緩解：完整實作 TB-GAE，確保觀測詞元從策略損失中遮罩後，其遞迴節點也被正確處理；對觀測詞元進行截斷或分塊時，優先選擇「不變鏈分割」而非摘要，以保留未來決策所需的細節。

**風險三：部分信用掩蓋嚴格失敗**
- 問題：在 FDR 下，失敗軌跡可能累積大量家族檢查通過分數，掩蓋其未通過終端閘門的事實，造成代理傾向「部分通過多項檢查」而非「嚴格完成單一任務」。
- 緩解：使用 SPR 明確分離嚴格成功與有界部分信用，確保部分信用在訓練後期處於從屬地位；定期審查失敗軌跡的獎勵分佈，若失敗軌跡獲得的總獎勵質量超過閾值（如論文中提及的 50.09%），則需重新校準獎勵權重。

**風險四：異步執行造成的 likelihood mismatch**
- 問題：管線排程、策略更新與訓練-推論實作差異會引入 likelihood 不一致，破壞 PPO 的重要性取樣假設。
- 緩解：明確區分管線排程延遲與策略更新延遲，使用 KL 散度監控兩者；若 mismatch 過大，則降低非同步程度或採用同步訓練。

**風險五：遞迴改進的停滯或退化**
- 問題：超過兩輪的遞迴可能因評論誤差累積或獎勵黑客（reward hacking）而導致性能停滯甚至退化。
- 緩解：保留每個階段的模型檢查點，設定嚴格的階段保留準則（如 Terminal-Bench 4.0 必須有絕對提升）；若新階段未達標，則捨棄並回退至前一保留階段（論文中以灰色分支表示捨棄替代方案）。

### 與其他技術的整合建議

**與既有 RLHF/RLAIF 流程整合**
- Terminal-RSI 的 RPR 階段可作為 RLHF 流程的延伸，將人類偏好資料替換為驗證器輸出與 FDR/SPR 設計的獎勵信號。
- 評論模型可與既有獎勵模型共享底層表示，但需為終端任務重新訓練價值頭（value head）。

**與程式碼專屬模型整合**
- 將 Terminal-RSI-27B 與程式碼補全模型（如 CodeLlama、DeepSeek-Coder）串接，前者負責高層決策與環境互動，後者負責具體程式碼生成。
- 在 RSR 階段引入程式碼專屬模型作為軌跡重寫的輔助，提升重寫品質。

**與 Agent 框架整合**
- 將 Terminal-RSI 包裝為符合 OpenAI Function Calling 或 MCP（Model Context Protocol）規範的工具，使其可被其他 Agent 框架（如 LangGraph、AutoGen）呼叫。
- 提供標準化的軌跡回傳介面，讓上層 Agent 能根據 Terminal-RSI 的部分完成狀態決定是否介入。

**與 MLOps 平台整合**
- 將五階段訓練流程編排為 MLflow 或 Kubeflow Pipeline，每個階段的評估結果自動觸發下一階段或回退。
- 將驗證器、軌跡儲存、評論模型檢查點統一納入特徵 store（feature store），支援跨專案復用。

**與監控與可觀測性系統整合**
- 將過程獎勵、嚴格完成率、平均回合數等指標匯入 Prometheus/Grafana，設定異常告警。
- 使用 OpenTelemetry 追蹤每條軌跡的決策路徑，便於除錯與獎勵函數迭代。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）以理解「終端代理」與「遞迴自我改進」的核心動機，特別是「時間膨脹」與「價值漂移」兩個障礙的直觀解釋。圖 1 的五階段性能曲線是理解整體框架的最佳入口，無需深入數學即可掌握「RSR 提供監督、RPR 精煉策略」的交替節奏。建議搭配閱讀 PPO 與 GAE 的基礎教學，再回頭看 TB-GAE 的設計動機。

**給 AI 工程師**：重點關注第 2 節的方法細節，特別是 TB-GAE 的數學推導、FDR/SPR 的獎勵公式，以及評論繼承時的相位局部校準流程。實作時應先搭建最小可運行版本（單任務家族、單輪 RSR+RPR），驗證 TB-GAE 的正確性後再擴展至多家族與多輪遞迴。建議參考論文中關於異步執行與 likelihood mismatch 的討論，這是工程實作中最容易踩坑的部分。

**給研究者**：本論文的遞迴演員-評論框架與獎勵演化設計值得深入研究。建議從「為何需要評論繼承而非重置」、「FDR 如何避免家族間的獎勵不平衡」、「SPR 如何在探索與嚴格驗證間取得平衡」三個問題切入。論文中提及的固定軌跡分析（失敗軌跡獲得 50.09% 總獎勵質量）是理解獎勵設計的關鍵實證，可作為後續工作的基準線。此外，TB-GAE 對觀測詞元遞迴節點的處理方式，對其他長上下文 RL 場景同樣具有參考價值。

**給產品經理**：Terminal-RSI 的核心價值在於讓終端代理從「能做部分修復」逐步進化到「能完成嚴格驗證」，這對需要高可靠性的自動化場景（如金融結算系統、醫療資料處理）尤其重要。產品設計時應將「過程獎勵」與「嚴格完成率」作為對外可見的進度指標，讓使用者理解代理當前的能力邊界。遞迴改進的特性意味著模型會隨時間持續進化，產品需設計相應的版本管理與回退機制，避免新版本在特定場景退化時影響線上服務。
