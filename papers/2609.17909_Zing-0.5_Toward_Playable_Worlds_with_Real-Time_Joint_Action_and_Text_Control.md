## ⚡ TL;DR

解決可遊玩生成世界中鍵盤導航與線上文字事件控制難以即時整合的問題。
提出Zing-0.5，統一動作與文字條件，並以片段對區塊的分佈匹配蒸餾及四步串流推論達成即時互動。

## 摘要翻譯

我們提出 Zing-0.5，一個以可遊玩性（playability）為核心設計的 50 億參數（5B parameters）自迴歸世界模型（autoregressive world model）：使用者可探索生成世界（generated worlds），透過聯合鍵盤控制（joint keyboard control）與線上文字控制（online text control）影響正在展開的事件（unfolding events），並對隨之而來的回饋（feedback）做出回應。本方法整合三項技術貢獻：（1）統一動作與文字條件化（unified action and text conditioning），結合幅度感知鍵盤輸入（magnitude-aware keyboard inputs）、時間對齊文字指令（temporally aligned text instructions）與聯合標註影片（jointly annotated videos），在同一序列中學習導航（navigation）與事件控制（event control）；（2）用於增量式生成（incremental generation）的事件尺度監督（event-scale supervision），利用以連接的多提示影片（connected multi-prompt videos）訓練的片段層級教師模型（segment-level teacher），透過分佈匹配蒸餾（distribution-matching distillation）監督區塊層級因果學生模型（block-level causal student）；（3）低成本即時互動（low-cost real-time interaction），結合四步生成（four-step generation）與保留上下文串流（context-preserving streaming），支援 832×480 推論（inference）、每秒 24 影格（24 FPS）的生成，估計伺服器租賃成本（server rental cost）約為每串流分鐘（stream-minute）0.009 美元。Zing-0.5 在 158 個 WBench 導航基準（WBench Navigation）案例中，取得整體分數（overall score）81.0 與一致性分數（consistency score）88.5。一項聯合控制展示（joint-control demonstration）顯示，在持續導航過程中無需重新啟動生成（restarting generation），即可發生文字導向的事件變更（text-directed event change）。我們釋出模型權重（model weights）、推論程式碼（inference code）與 Zing-SGLang 服務部署實作（serving implementation），以支援後續針對可遊玩生成世界（playable generated worlds）的研究。

### 核心貢獻（3～5點）
- **統一動作與文字條件化（Unified Action and Text Conditioning）**：結合幅度感知鍵盤輸入與時間對齊文字指令，讓模型能在同一序列中同時學習導航與事件控制。
- **事件尺度監督用於增量式生成（Event-Scale Supervision for Incremental Generation）**：透過片段層級教師模型對區塊層級因果學生模型進行分佈匹配蒸餾，解決事件學習與增量生成之間的時間尺度差異。
- **低成本即時互動（Low-Cost Real-Time Interaction）**：結合四步生成與保留上下文串流，在 832×480 解析度下達到每秒 24 影格，估計成本僅每串流分鐘 0.009 美元。
- **開源釋出**：公開模型權重、推論程式碼與 Zing-SGLang 服務部署實作，促進可遊玩生成世界的後續研究。

### 適合對象
對生成式世界模型、互動式影片生成、即時人機互動、知識蒸餾與串流推論系統有興趣的研究人員與工程師；特別適合關注如何以低成本實現可即時操控之生成世界的開發者與學術研究者。

## 深度分析

#### 方法論解析

Zing-0.5 的核心目標是打造一個「可遊玩世界（playable worlds）」，讓使用者能夠在單一且持續的互動階段（interactive session）中，同時進行鍵盤導航（keyboard navigation）與線上文字控制（online text control）。為此，作者提出三大技術貢獻：統一動作與文字條件化（unified action and text conditioning）、事件尺度監督（event-scale supervision）下的增量式生成（incremental generation），以及低成本即時互動（low-cost real-time interaction）。

首先，在條件化機制上，Zing-0.5 以 Wan2.2-TI2V-5B 為基礎模型（base model），將鍵盤輸入與文字指令整合到同一個自迴歸世界模型（autoregressive world model）中。不同於過去許多互動式世界模型（interactive world models）僅支援離散的動作標籤，Zing-0.5 採用幅度感知鍵盤輸入（magnitude-aware keyboard inputs），也就是保留連續動作強度（continuous action strengths），讓使用者能進行細緻移動與視角控制（fine-grained movement and view control）。與此同時，文字指令（text instructions）並非只在序列開頭給定，而是沿著時間軸與影片對齊的時間對齊文字指令（temporally aligned text instructions）。為了讓模型學會「導航（navigation）」與「事件控制（event control）」在同一序列中同時發生，訓練資料採用聯合標註影片（jointly annotated videos），每段影片同時標註動作與文字，從而讓模型學習兩種條件如何共同影響視覺結果。

其次，為了處理事件學習（event learning）與增量式生成之間的時間尺度（temporal scales）差異，作者設計了教師—學生架構。文字導向的事件變更（text-directed event change）可能橫跨多個生成區塊（generation blocks），但即時互動又需要模型能夠快速產出短延續（short continuations）。因此，他們先訓練一個片段層級教師模型（segment-level teacher），該教師在連接的多提示影片（connected multi-prompt videos）上學習，能夠聯合建模每個提示片段（prompt segment）並學習跨提示變更的延續（continuation across prompt changes）。接著，透過分佈匹配蒸餾（distribution-matching distillation），讓區塊層級因果學生模型（block-level causal student）在僅能使用過去資訊的因果（causal）設定下，仍能獲得橫跨多個學生區塊的事件尺度監督（event-scale supervision）。此外，學生還透過推出與回放（rollout and replay）在自己的生成歷史（generated histories）上訓練，並結合長序列適應（long-sequence adaptation）與歷史擾動（history perturbation），以提升長時間互動（extended interaction）的穩定性。

最後，在推論與部署層面，Zing-0.5 採用四步生成（four-step generation）與保留上下文串流（context-preserving streaming）來達成低成本即時互動。具體而言，模型以 832×480 解析度（resolution）達到每秒 24 影格（24 FPS）的影格率（frame rate），估計伺服器租賃成本（server rental cost）約為每串流分鐘（stream-minute）0.009 美元。串流執行環境（streaming runtime）透過視覺上下文保留（visual context retention）、快取重用（cache reuse）、輕量本地解碼（lightweight local decoding）與有界媒體佇列（bounded media queues），在文字提示更新（prompt updates）時保留視覺上下文（visual context），從而實現不中斷的持續生成。

#### 實驗數據解讀

論文在 WBench Navigation（WBench 導航基準）上進行評估，這是一個針對導航條件化生成（navigation-conditioned generation）的評測基準。Zing-0.5 在 158 個圖像條件化案例中取得整體分數（overall score）81.0，以及一致性分數（consistency score）88.5。這兩項數據顯示，在純鍵盤導航任務上，模型能夠在維持視覺一致性的同時，準確回應方向性控制。一致性分數高達 88.5，意味著模型在長時間接續生成中，對場景外觀、物件位置與相機運動的保持能力相當出色；這對於可遊玩世界而言至關重要，因為任何明顯的視覺跳變都會破壞沉浸感。

然而，需要留意的是，WBench Navigation 主要衡量的是導航能力，而非聯合動作與文字控制（joint action and text control）的綜合表現。論文中關於文字導向事件變更的證據，主要來自質性展示，例如圖 2 中使用者操控雪橇並透過文字指令讓騎士歡呼與撐傘。這個聯合控制展示（joint-control demonstration）說明模型確實能在不中斷生成的情况下回應文字指令，但目前缺乏針對事件控制（event control）的量化基準。因此，81.0 的整體分數雖然在導航面向具有說服力，卻無法直接推論到「文字導向事件變更」的準確率、延遲或語義忠實度。

此外，成本數據「每串流分鐘 0.009 美元」是一個重要的工程指標，顯示即時互動在經濟上已經接近可部署規模。但該數字是估計值，實際成本會受到 GPU 租賃價格、批次大小、快取命中率、網路延遲與負載波動等因素影響。若未來能釋出更詳細的延遲分解與成本模型，將有助於社群評估其在不同雲端環境下的可行性。

#### 與現有研究的比較

在互動式世界模型領域，Zing-0.5 與 GameNGen、Matrix-Game、LingBot-World、WorldPlay 與 ABot-World-0 等研究處於同一光譜。這些工作大多聚焦於鍵盤或相機控制，讓使用者在生成場景中移動或操控角色。Zing-0.5 的差異在於同時支援鍵盤導航與線上文字控制，並強調「探索–介入–回饋迴路（exploration–intervention–feedback loop）」的閉環體驗。相較於 ABot-World-0 使用原始鍵盤動作進行場景漫遊與第三人稱角色控制，Zing-0.5 進一步引入連續動作強度與時間對齊文字指令，讓控制粒度更細緻、語義更豐富。

在語言引導互動方面，GameGen-X、GameCraft-2 與 LingBot-World-Infinity 已經探索文字驅動的事件與行為控制。H3-World 則進一步研究時間對齊語言動作作為控制表示。Zing-0.5 的貢獻在於將動作與文字條件放在分離的時間軸上，允許兩者在互動過程中獨立變化，並從現有視覺上下文（visual context）繼續生成，而非每次重新取樣。這種設計更貼近真實的遊戲或互動應用場景。

在多提示影片生成方面，Gen-L-Video 與 CausalCine 透過將提示指派給不同片段來組織連續事件。Zing-0.5 的教師模型同樣利用多提示影片，但額外強調「線上」特性：未來的使用者輸入在當前預測時不可見，因此學生模型必須是因果（causal）的。這與傳統多提示影片生成中可事先看到全部提示的設定不同。

在長序列訓練技術上，Diffusion Forcing、Self Forcing、Self Gradient Forcing 與 ABot-World-0 的 Long Forcing 都嘗試解決生成歷史誤差累積問題。Zing-0.5 的獨特之處在於教師與學生使用不同的時間劃分：教師在片段層級聯合建模，學生在區塊層級因果生成，並透過分佈匹配蒸餾（distribution-matching distillation）橋接兩者。這種設計讓事件尺度監督能夠跨越多個學生區塊，有助於學習長時間跨度的語義事件。

在即時生成效率方面，CausVid、CMT、Causal Forcing 與 Decoupled DMD 等研究提供了少步數生成與分佈匹配的不同路徑。Zing-0.5 結合 ODE 初始化、局部一致性訓練與分佈匹配，並進一步將其整合到串流執行環境中，實現 480p 推論（480p inference）下的 24 FPS。這在工程整合層面領先許多僅聚焦於演算法的先驅研究。

儘管如此，Zing-0.5 仍存在一些限制。首先，目前的量化評估僅涵蓋導航，缺乏針對文字事件控制的標準化指標。其次，480p 解析度雖然足以展示概念，但距離高畫質遊戲體驗仍有差距。第三，長時間互動中的錯誤累積、語義漂移與場景狀態一致性仍需更多研究。最後，聯合標註影片（jointly annotated videos）的取得與標註成本可能限制模型規模化。

#### 可重現性評估

論文明確表示將釋出模型權重（model weights）、推論程式碼（inference code）以及 Zing-SGLang 服務部署實作（serving implementation）。這對於可重現性（reproducibility）是極大的加分，因為研究者可以直接下載模型、執行推論，甚至部署自己的即時串流服務。Zing-SGLang 的釋出也意味著作者已經將模型服務化，降低了其他團隊在工程整合上的門檻。

然而，根據目前提供的摘要與前言內容，訓練資料集是否公開、聯合標註影片（jointly annotated videos）的規模與取得方式、以及教師—學生蒸餾的詳細超參數，尚未完全揭露。若僅釋出模型權重與推論程式碼，研究者可以複製推論結果與互動體驗，但難以從頭訓練或進行大規模的消融實驗。因此，可重現性在「推論與部署」面向相當高，但在「完整訓練流程」面向仍有資訊缺口。建議作者未來補充資料處理流程、訓練腳本與硬體配置，以便社群進行更深入的驗證與改進。

#### 未來研究方向

第一，建立聯合控制的量化評測基準。目前 WBench Navigation 僅評估導航能力，未來需要設計針對文字導向事件變更（text-directed event change）的指標，例如事件發生率、語義忠實度、時間對齊準確度，以及人類主觀評分。這將有助於客觀比較不同模型在可遊玩性（playability）上的差異。

第二，提升解析度與視覺品質。480p 推論雖然已能實現即時互動，但若要接近商業遊戲體驗，需要朝 720p、1080p 甚至更高解析度發展。這可能需要在模型架構、蒸餾效率與快取管理之間取得新的平衡。

第三，擴展動作空間與互動模態。除了鍵盤與文字，未來可整合滑鼠、遊戲手把、語音指令，甚至是眼動追蹤。多模態輸入將使可遊玩世界更加自然，也對統一條件化框架提出更高要求。

第四，強化長期記憶與世界狀態一致性。目前的視覺 KV 快取（visual KV cache）雖能保留短期上下文，但對於跨分鐘甚至跨小時的互動，模型需要更明確的場景狀態表示、物件追蹤機制與記憶模組，以避免語義漂移與矛盾。

第五，降低成本與延遲。雖然每串流分鐘 0.009 美元已具競爭力，但若要支援大規模多人同時互動，仍需進一步壓縮模型、減少去噪步數，或發展自適應解析度與自適應步數策略。

第六，結合遊戲引擎與物理模擬。生成模型擅長視覺多樣性，但在物理一致性與可玩機制上仍不如傳統遊戲引擎。未來可探索「神經生成 + 引擎約束」的混合架構，讓可遊玩世界既具視覺豐富度，又具可預測的互動規則。

第七，安全性與內容治理。隨著使用者能透過文字即時改變生成內容，如何避免不當內容、版權問題與幻覺事件，將是實際部署時不可忽視的議題。未來研究可發展即時內容過濾、意圖對齊與使用者行為監控機制。

## 論文問答

**Q1：Zing-0.5 想要解決的核心問題是什麼？**
A：Zing-0.5 旨在打造真正的「可遊玩世界」（playable worlds），讓使用者不僅能在生成的世界中自由探索，還能透過鍵盤與文字即時介入事件，並根據世界的回饋決定下一步行動。現有的互動式世界模型大多只能支援單一類型的控制，例如純鍵盤導航或純文字條件生成，難以把「探索—介入—回饋」整合在同一段持續的互動階段中。因此，Zing-0.5 的核心挑戰在於如何同時處理連續的動作控制與語意層級的文字指令，並在不中斷生成的情況下即時回應使用者。

**Q2：為什麼現有的互動式世界模型或語言引導系統無法滿足可遊玩性的需求？**
A：現有以鍵盤或相機為主的互動世界模型雖然能提供細緻的移動與視角控制，但缺乏對角色行為、事件或環境變化的語意控制能力。另一方面，語言引導的生成系統雖然能改變內容與行為，卻往往無法在持續生成過程中接受線上文字指令，也難以提供連續、細緻的導航體驗。此外，多提示影片生成方法通常假設未來的所有提示在生成前就已確定，無法適應互動過程中不可預測的使用者輸入，因此無法形成真正的即時回饋迴路。

**Q3：聯合動作與文字控制對可遊玩性為何重要？**
A：聯合動作與文字控制讓使用者能夠像玩遊戲一樣，一邊用鍵盤進行連續移動與視角調整，一邊用文字表達意圖、改變當前情境，例如讓角色歡呼或打開雨傘。這種設計把探索、介入與回饋連結在同一個持續的互動階段中，使使用者擁有更高的主導權與沉浸感。同時，它也帶來了技術上的挑戰，因為動作控制的時間粒度很細，而文字導向的事件可能橫跨多個生成區塊，兩者需要在同一序列中協調一致。

**Q4：Zing-0.5 的核心方法與整體架構是什麼？**
A：Zing-0.5 是一個基於 Wan2.2-TI2V-5B 的 50 億參數自迴歸世界模型，透過統一動作與文字條件化，將幅度感知鍵盤輸入與時間對齊文字指令整合到同一框架中。訓練資料使用聯合標註影片，讓動作、文字與視覺結果互相同步對齊。為了兼顧事件尺度學習與增量式生成，論文採用片段層級教師模型與區塊層級因果學生模型，並透過分佈匹配蒸餾、推出與回放、長序列適應以及歷史擾動等技術，讓學生模型能在短區塊生成中保持長事件的一致性。

**Q5：Zing-0.5 在條件化設計上的關鍵創新是什麼？**
A：關鍵創新在於將鍵盤動作與文字指令放在各自獨立的時間軸上進行統一條件化，並且支援連續動作強度與線上文字更新。這表示使用者可以在持續導航的過程中隨時輸入新的文字指令，而生成會從現有的視覺上下文繼續延伸，不需要重新啟動。聯合標註影片進一步確保了動作與文字都能對應到正確的視覺結果，使導航與事件控制能夠在同一序列中自然共存。

**Q6：為什麼要採用片段層級教師模型與區塊層級因果學生模型的設計？**
A：文字導向的事件通常會橫跨多個生成區塊，但即時互動要求模型每次只生成短延續，以便快速回應新的使用者輸入。片段層級教師模型在連接的多提示影片上訓練，能夠聯合建模整個提示片段並學習跨提示變更的延續；區塊層級因果學生模型則負責實際的增量式生成。透過分佈匹配蒸餾，教師模型的事件尺度監督可以傳遞給學生模型，讓短區塊生成仍能維持長事件的語意一致性。此外，學生模型還會在自己的生成歷史上進行訓練，並搭配歷史擾動，以減少長時間互動中的錯誤累積。

**Q10：Zing-0.5 可能應用在哪些實際場景？**

**Q11：論文強調了哪些產品與工程上的考量？**

A：Zing-0.5 展示了在自迴歸世界模型中同時實現鍵盤導航與線上文字控制的可行性，為互動式世界模型與語言引導生成之間搭起了橋樑。透過開源模型權重與服務化實作，這項工作有望促進更多關於可遊玩世界、即時互動介面設計與長序列生成穩定性的研究。它也為未來的遊戲、虛擬實境與互動媒體提供了一個新的技術基準，推動生成式 AI 從被動觀看走向主動可遊玩的應用。

**Q13：論文已承認或暗示了哪些限制？**
A：論文目前主要使用 480p 解析度進行即時互動，畫質與細節仍有提升空間。WBench Navigation 主要評估導航能力，對於聯合文字控制的量化評估仍較有限，多數文字導向事件控制是透過質化展示呈現。此外，儘管模型透過歷史擾動與生成歷史訓練來減緩錯誤累積，長時間互動中的視覺一致性與事件連貫性仍然是開放挑戰。

**Q14：Zing-0.5 可能出現哪些失敗案例？**
A：在長時間互動中，模型可能會逐漸累積視覺與動態上的誤差，導致場景漂移或物體行為不一致。當文字指令與鍵盤動作同時發生時，模型可能會忽略或誤解部分語意指令，例如未能正確讓角色執行特定動作。此外，過於突然的文字提示更新、快速劇烈的視角變化，或涉及複雜物理互動的場景，都可能造成視覺不連續或生成品質下降。

## 實務應用指南

### 適用場景

1. **開放世界遊戲原型與互動敘事 Demo**  
   利用 Zing-0.5 的鍵盤導航與線上文字控制，快速製作可遊玩世界原型：玩家一邊探索場景，一邊用文字觸發角色行為或環境事件，例如「舉手歡呼」「打開雨傘」，無需重新啟動生成即可持續互動。

2. **虛擬製作與動態分鏡預覽（Previs）**  
   導演或美術人員以鍵盤控制鏡頭移動，並以文字指令即時改變場景氛圍、角色動作或天氣，適合在拍攝前快速迭代分鏡與事件節奏。

3. **沉浸式教育與訓練模擬**  
   用於需要探索—介入—回饋迴路的訓練情境，例如安全疏散演練、導覽解說或程序訓練：學員移動視角並下達文字指令，觀察世界反應並調整下一步決策。

4. **使用者生成內容（UGC）與輕量元宇宙體驗**  
   讓一般使用者以低門檻方式創造可遊玩片段：透過鍵盤與自然語言共同控制，生成個人化的互動影片或小型世界，並以低成本串流部署分享。

### 實作前置條件

**資料條件**
- 具備**聯合標註影片**：每段影片需同時包含鍵盤動作軌跡（含**幅度感知鍵盤輸入**與**連續動作強度**）以及**時間對齊文字指令**。
- 用於訓練教師模型的**連接的多提示影片**，能學習**跨提示變更的延續**。
- 評估資料：至少需準備類似 WBench Navigation 的導航條件生成基準，以及針對文字導向事件變更的質性測試案例。

**運算條件**
- 訓練：建議使用高記憶體 GPU（如 A100 / H100）以微調 5B 影片生成模型並進行知識蒸餾。
- 推論：需支援 832×480 解析度、24 FPS 的即時推論伺服器；可參考 Zing-SGLang 服務部署實作，並預留 VRAM 給視覺上下文快取與文字條件快取。
- 串流：穩定的網路頻寬與低延遲媒體佇列，以支援**保留上下文串流**。

**技能條件**
- 熟悉擴散模型／自迴歸影片生成架構（如 Wan2.2-TI2V-5B）。
- 具備知識蒸餾與分佈匹配（Distribution Matching Distillation）實作經驗。
- 能建立資料標註管線、處理鍵盤輸入編碼與文字對齊。
- 具備串流推論與前端互動開發能力（如 WebRTC、遊戲引擎整合）。

### 實作步驟建議

1. **環境與基礎模型準備**  
   下載 Zing-0.5 模型權重與推論程式碼，確認 Wan2.2-TI2V-5B 基礎模型可正常載入，並安裝 Zing-SGLang 服務部署實作所需的相依套件。

2. **建立聯合標註資料集**  
   收集或錄製影片，同步記錄鍵盤輸入強度與時間對齊文字指令；對於事件控制場景，需特別標註文字指令開始與結束的影格區間。

3. **訓練片段層級教師模型**  
   在**連接的多提示影片**上訓練**片段層級教師模型**，讓模型聯合建模每個提示片段並學習提示變更時的延續行為。

4. **蒸餾為區塊層級因果學生模型**  
   使用**分佈匹配蒸餾**將教師模型監督轉移到**區塊層級因果學生模型**，並結合推出與回放（rollout and replay）、**長序列適應**與**歷史擾動**，使學生能穩定進行增量式生成。

5. **推論最佳化**  
   啟用**四步生成**、視覺 KV 快取重用、輕量本地解碼與**有界媒體佇列**，以達成 480p、24 FPS 的低成本即時互動。

6. **開發互動前端**  
   整合鍵盤輸入擷取與文字指令輸入框，將使用者輸入轉換為模型條件；設計提示更新機制，確保**無需重新啟動生成**即可切換文字指令。

7. **評估與迭代**  
   在 WBench Navigation 上測量整體分數與一致性分數，同時進行聯合控制展示，驗證文字導向的事件變更能否在持續導航中穩定發生。

8. **部署與成本監控**  
   以 Zing-SGLang 部署到雲端 GPU，估算每串流分鐘的伺服器租賃成本，設定成本上限與併發數限制。

### 潛在風險與注意事項

| 風險 | 說明 | 因應方式 |
|---|---|---|
| **長期誤差累積** | 增量式生成會讓生成歷史中的錯誤隨時間放大，導致場景漂移或物件不一致。 | 使用歷史擾動、生成歷史訓練與長序列適應；必要時定期以關鍵影格重新初始化視覺上下文。 |
| **文字與動作錯位** | 文字指令時間軸與鍵盤動作時間軸未對齊，可能產生角色動作與指令不符。 | 強化聯合標註品質，並在訓練時使用時間對齊文字指令與動作條件化。 |
| **延遲抖動** | 四步生成雖快，但快取更新或提示變更時仍可能出現影格率波動。 | 採用保留上下文串流、快取重用與有界媒體佇列，並預留 GPU 餘裕。 |
| **內容安全與偏見** | 使用者文字可能觸發不當內容；生成資料中的偏見也可能被放大。 | 加入輸入過濾、輸出內容審核與人工回饋機制；對公開部署設定明確使用規範。 |
| **成本低估** | 雖然論文估計每串流分鐘約 0.009 美元，實際成本會隨併發數、解析度與快取策略變動。 | 建立成本監控儀表板，先以小規模 A/B 測試驗證真實流量下的伺服器租賃成本。 |
| **資料標註昂貴** | 聯合標註影片需要大量人力與時間。 | 優先使用現有遊戲錄影或模擬器自動產生動作軌跡，再輔以人工文字標註。 |

### 與其他技術的整合建議

- **遊戲引擎（Unity / Unreal）**  
  將引擎中的鍵盤與相機輸入轉為幅度感知鍵盤輸入，並把 Zing-0.5 的生成結果以紋理或串流方式回傳到引擎畫面，實現「生成即場景」的互動迴路。

- **大型語言模型（LLM）代理**  
  讓 LLM 負責解析複雜自然語言指令，轉換為簡潔、時間對齊的文字指令後再送入 Zing-0.5，降低模型直接理解長篇意圖的負擔。

- **雲端 GPU 服務與 Kubernetes**  
  使用 Zing-SGLang 作為推論後端，搭配 Kubernetes 自動擴展與 GPU 排程，根據串流分鐘數動態調整實例數量，控制伺服器租賃成本。

- **即時媒體串流（WebRTC / RTMP）**  
  將四步生成的 832×480、24 FPS 輸出透過 WebRTC 低延遲傳送到瀏覽器，並在客戶端處理鍵盤輸入與文字指令，減少往返延遲。

- **資產與角色一致性資料庫**  
  結合角色描述、場景風格與物件資料庫，在文字條件化中注入一致性標籤，減少長時間互動中角色外觀或場景風格的漂移。
