## 摘要翻譯

機器人學習（robot learning）領域正分裂為兩大路線：一種是將能力固化於凍結權重（frozen weights）中的策略（policy），即視覺-語言-動作模型（vision-language-action, VLA, models）；另一種則是會以程式碼形式撰寫並改進自身可執行技能（executable skills）的智能體（agent）。本綜覽圍繞「權重」與「技能」這條軸線來組織整個領域。其核心分析貢獻是一項深入探討，按照自我改進程度（degree of self-improvement）來排列程式碼即策略（code-as-policy）方法，從零樣本程式合成（zero-shot program synthesis），經過閉環自我修復（closed-loop self-repair）與持久技能記憶（persistent skill memory），到達一個鮮有系統佔據的區格——在該區格中，執行回饋（execution feedback）、技能記憶（skill memory）與演化搜尋（evolutionary search）結合成一個開放式迴路（open-ended loop）；僅有少數非常近期的系統（例如 ASPIRE、ENPIRE 與 RoboClaw）佔據該區格。我們描繪了與之互補的「技能」一端，從無監督強化學習技能發現（unsupervised reinforcement-learning skill discovery）到大型語言模型技能庫（large-language-model skill libraries），並指出「skill」一詞至少有五種不同意義（skill senses），其中只有程式碼意義（code sense）能夠無需梯度更新（gradient updates）即可自我改進。接著我們將此分類架構（taxonomy）與新興的技能經濟（skill economy）連結起來：商業機器人技能市集（robot-skill marketplaces）現在會跨機器人分發一鍵技能（one-tap skills），但實際交付的僅是靜態回放（static playback），因而浮現出適應性（adaptation）、跨本體可移植性（cross-embodiment portability）、來源追溯（provenance）、安全性驗證（safety verification）、組合性（composition）與標準化（standardisation）等開放問題。這是一篇刻意聚焦的綜覽。與其窮盡式地羅列整個領域，本文透過一個分類架構（taxonomy）與一組對照表（contrast tables），檢視了橫跨六個技術家族（technique families）的 77 個代表性系統（representative systems），並提供自我改進機制（self-improvement mechanisms）的操作型定義（operational definitions），以及說明各技術家族的限制。

### 核心貢獻（3～5點）
- 提出以「權重 vs. 技能」為主軸的分類架構，系統化整合機器人學習的兩大技術路線。
- 深入剖析程式碼即策略方法的自我改進光譜，並定位極少數達到開放式迴路的最新系統。
- 釐清「skill」一詞的五種語義，指出僅有程式碼意義可在無梯度更新的情況下自我改進。
- 將分類架構與新興技能經濟連結，揭示商業機器人技能市集在適應性、可移植性與安全性等方面的開放問題。
- 提供自我改進機制的操作型定義，並明確各技術家族的能力邊界。

### 適合對象
適合機器人學習、具身智能（embodied AI）、程式合成與自主智能體領域的研究者與工程師，以及關注機器人技能商業化生態（如技能市集、跨機器人部署）的產品經理與政策制定者閱讀。

## 深度分析

#### 方法論解析

本調查（survey）的核心方法並非提出一個新的端到端模型，而是建立一套以「權重（weights）相對於技能（skills）」為單一組織軸的分類架構（taxonomy）。作者將機器人學習（robot learning）領域中近年的代表性系統，依其「出貨內容」區分為兩極：一極是**凍結網路權重（frozen network weights）**，即視覺-語言-動作（Vision-Language-Action, VLA）模型；另一極是**可執行程式（executable programs）**，即**程式碼即策略（code-as-policy）**智能體。這條分界線（fault line）貫穿全文，並在圖 1 與圖 2 中以 77 個真實系統具體呈現。

在此主軸下，作者進一步劃出六大技術家族（technique families）：

1. **程式碼即策略（code-as-policy）**（§3.1）：依自我改進（self-improvement）程度細分為五個細胞（cell）。
2. **端到端 VLA（end-to-end VLA）**（§3.2）：以凍結權重直接映射觀測（observation）到動作（action）。
3. **獎勵合成（reward synthesis）**（§3.3）：利用大型語言模型（Large Language Model, LLM）設計獎勵函數。
4. **技能庫（skill libraries）**（§3.4）：包含無監督強化學習技能發現（unsupervised reinforcement-learning skill discovery）、LLM 技能庫與開放世界智能體。
5. **模擬到真實與遷移（sim-to-real & transfer）**（§3.5）。
6. **基準與模擬器（benchmarks & simulators）**（§3.6）。

其中最具分析價值的是對 **code-as-policy** 的深度拆解。作者將其自我改進程度排列成階梯：

- **零樣本程式合成（zero-shot program synthesis）**：LLM 直接根據指令生成程式，無執行回饋（execution feedback）。
- **閉環自我修復（closed-loop self-repair）**：根據執行結果修正程式，但無持久記憶。
- **持久技能記憶（persistent skill memory）**：能跨任務儲存與複用技能。
- **演化搜尋（evolutionary search）**：透過演化演算法（evolutionary search）探索並改進程式。
- **完整自我改進迴路（full self-improving loop）**：結合執行回饋、技能記憶（skill memory）與演化搜尋，形成開放式迴路（open-ended loop）。

作者強調，他們為每一層級提供了**操作型定義（operational definitions）**與**充分必要條件（necessary-and-sufficient conditions）**，這使分類不僅是描述性，更具可檢驗性。例如，要歸入最頂層的 §3.1.5 細胞，系統必須同時具備：(1) 來自真實或模擬執行的回饋機制（feedback mechanisms）；(2) 可累積的記憶機制（memory mechanisms）；(3) 能主動搜尋或演化新技能的搜尋機制（search mechanisms）。目前僅有 ASPIRE、ENPIRE、RoboClaw 等極少數最新系統佔據此細胞，顯示該方向仍處於前沿。

另一項方法論貢獻是對「skill」一詞進行語義澄清。作者指出「skill」在文獻中至少有五種不同意義，包括低階動作原語、策略權重、獎勵函數、LLM 提示詞庫，以及**程式碼意義（code sense）**。只有最後一種能在不進行**梯度更新（gradient updates）**的情況下自我改進，這也是本調查將「skills」與「weights」對立的理論基礎。

在系統收錄上，作者明確提出**收錄標準（placement criteria）**（§2.1），從而選出 77 個代表性系統（representative systems），並排除純感知（perception）、導航（navigation）與移動（locomotion）研究，除非其直接關乎操作技能（manipulation skill）的編寫與改進。這種聚焦式調查（focused survey）方法，輔以多張**對照表（contrast tables）**與「每個家族無法做到什麼」的陳述，使讀者能快速定位各技術的邊界與缺口。

#### 實驗數據解讀

作為一篇調查論文，本文並未進行傳統意義上的新實驗，而是採用文獻計量與概念分析的方式呈現「實驗數據」。其數據主體包括：納入分類的 77 個系統、附錄 A 中額外比較的 225 項代表性工作，以及橫跨 2016–2026 年的時間線（timeline）。總涵蓋量超過三百篇文獻，並以六個軸向進行對照。

從圖 1 與圖 2 的分布可觀察到幾個重要模式：

- **凍結權重（frozen weights）端極度擁擠**：RT-1、RT-2、Octo、OpenVLA、π0、GR00TN1、Gemini Robotics 等 VLA 模型佔據左側，顯示近年學術界與產業界大量資源投入於端到端多模態策略模型。
- **程式碼即策略（code-as-policy）端相對稀疏但成長快速**：從 ProgPrompt、VoxPoser、Instruct2Act 等零樣本系統，到 REFLECT、DoReMi 等閉環修復系統，再到 ASPIRE、ENPIRE、RoboClaw 等完整迴路系統，呈現明顯的演進軌跡。
- **最頂層的 §3.1.5 細胞幾乎空白**：這意味著同時整合執行回饋、技能記憶與演化搜尋的開放式自我改進系統仍處於萌芽階段，是當前研究的「稀疏前沿」。

在商業數據方面，作者以 **Unitree UniStore** 為例，指出機器人技能市集（robot-skill marketplaces）已經出現「一鍵跨模型動作下載（one-tap, cross-model motion downloads）」的服務。然而，這些技能本質上只是**靜態回放（static playback）**，對應到分類架構中能力最弱的點。作者提出的**技能堆疊（skill stack）**三層——建立（Build）、分發（Distribute）、適應（Adapt）——顯示 UniStore 僅實現了第二層，而第三層「裝置端自我改進（on-device self-improvement）」至今尚未有商業化產品真正交付。

這些數據的解讀意義在於：學術研究與商業落地之間存在明顯斷層。學術界已開始探索高度自我改進的程式碼技能，但市場上販售的仍是靜態第一層技能（static layer-1 skills）。這也暗示，未來誰能率先將 **layer 3** 的能力產品化，誰就可能掌握技能經濟（skill economy）的關鍵價值。

不過，這些數據也有其局限性。由於是聚焦式調查，選樣難免偏向操作任務與程式碼生成方向；純導航、移動與感知領域的進展被刻意排除。此外，作者並未提供各系統在統一基準上的量化比較，因此讀者無法從本文直接判斷哪一技術在特定任務上表現最佳，而只能獲得概念定位與能力邊界。

#### 與現有研究的比較

表 1 清楚呈現本文與其他相關調查的差異。現有文獻多聚焦於世界模型（world models）、具身智能（embodied intelligence）、語言模型導航（language-model navigation）或 VLA 模型與操作基礎模型（foundation models for manipulation）。這些調查雖然涵蓋了部分相關主題，但沒有任何一篇同時做到以下三點：

1. 以「權重（weights）相對於技能（skills）」作為單一組織軸；
2. 將 **code-as-policy** 方法按自我改進（self-improvement）程度進行系統性分層，並明確命名 §3.1.5 細胞；
3. 將技術分類與新興的機器人技能經濟（skill economy）與商業市集連結起來。

相較於 VLA 調查強調規模化、泛化能力與網路知識遷移，本文更關注**可解釋性（interpretability）**、**適應性（adaptation）**與**程式層級的技能表徵**。這是一種互補而非取代的視角：VLA 模型適合處理高維感知動作映射，而 code-as-policy 智能體則適合需要組合性（composition）、人類可讀計畫與持續自我改進的場景。

本文的另一項改進在於對「skill」一詞的語義梳理。過去文獻常將技能發現（skill discovery）、技能庫（skill library）與程式碼技能混用，導致比較基準不一致。作者明確指出，只有「程式碼意義（code sense）」的技能能夠在無梯度更新的情況下自我改進，這為後續研究提供了更清晰的概念基礎。

然而，本文也有其限制。作為**聚焦式調查（focused survey）**，它並非全面普查（census），因此對於純導航（navigation）、移動（locomotion）與感知（perception）的讀者而言，覆蓋範圍有限。此外，由於機器人學習領域演變極快，任何以特定時間點收錄的 77 個系統為基礎的分類，都可能迅速被新系統挑戰或填補空白細胞。最後，作者對各家族「無法做到什麼」的陳述雖具啟發性，但部分操作型定義仍可能引發學界爭議，例如「演化搜尋」與「簡單提示工程」之間的界線。

#### 可重現性評估

對於一篇調查論文而言，可重現性（reproducibility）主要體現在其分類標準是否透明、引用是否完整、以及讀者是否能依相同準則重新歸類新系統。本文在這方面表現良好：作者於 §2.1 明確提出**收錄標準（placement criteria）**，並透過圖 2、表 2–6 與附錄 A 的六軸對照表，提供可追蹤的分類依據。操作型定義（operational definitions）與充分必要條件（necessary-and-sufficient conditions）的引入，也使讀者能夠檢驗某個新系統是否屬於某一細胞（cell）。

然而，本文本身並未釋出新的程式碼、資料集或模型權重（至少從提供的上下文未見相關說明）。其所有論證與結論都依賴所引用的原始論文，因此整體可重現性受制於這些原始工作的開放程度：

- **VLA 端**：近年開源進展顯著，OpenVLA、Octo、RT-X 系列透過 Open X-Embodiment 資料集與模型權重釋出，可重現性較高。
- **Code-as-policy 端**：開放程度參差不齊。ProgPrompt、VoxPoser、REFLECT 等系統多數有公開程式碼或演示，但部分最新系統如 ASPIRE、ENPIRE、RoboClaw 可能僅釋出部分資源或仍處於預印階段。
- **商業技能市集**：Unitree UniStore 屬於封閉/專有生態，作者對其的分析主要基於公開產品資訊，難以由外部獨立驗證。

為提升未來調查與整個領域的可重現性，建議推動以下措施：公開**技能庫（skill library）**的標準格式、版本化技能儲存、**來源追溯（provenance）**後設資料、以及可重複執行的技能驗證環境。這些基礎建設不僅有助於學術比較，也是技能經濟（skill economy）能夠規模化的前提。

#### 未來研究方向

基於本文提出的分類架構與開放問題議程（open-problems agenda），未來研究可沿以下方向推進：

1. **實現技能堆疊第三層——裝置端自我改進（on-device self-improvement）**  
   當前商業技能市集僅提供靜態回放（static playback），未來應發展能夠在真實機器人上根據執行回饋持續調整的**可執行技能（executable skills）**，讓「調整夾爪（gripper）力道以免水果受損」這類承諾真正落地。

2. **跨本體可移植性（cross-embodiment portability）**  
   發展硬體無關的技能表徵與中介介面，使同一套程式碼技能能在不同機器人載具間遷移，並結合一鍵跨模型動作下載（one-tap, cross-model motion downloads）進行參數適配。

3. **安全性驗證（safety verification）與來源追溯（provenance）**  
   對於由 LLM 自動生成並可在實體世界執行的程式碼技能，必須建立形式化驗證、沙箱測試、數位簽章與來源追蹤機制，以降低部署風險。

4. **組合性（composition）與標準化（standardization）**  
   設計可組合的技能描述語言與互通標準，使不同來源的技能能夠像軟體元件一樣被組裝、版本控制與交易，支撐機器人技能市集（robot-skill marketplaces）的規模化。

5. **混合典範：凍結權重（frozen weights）與程式碼技能（code skills）的結合**  
   未來系統可能採用分層架構：以 VLA 模型作為低階感知動作控制器，同時以 LLM 生成的程式碼技能擔任高階規劃與組合層，兼取兩者之長。

6. **開放式自我改進迴路（open-ended loop）的擴展**  
   目前 §3.1.5 細胞僅有少數系統佔據。未來需探索如何將執行回饋、技能記憶與演化搜尋穩定地結合於真實世界長期運作中，並發展對應的終身學習（lifelong learning）與技能發現（skill discovery）演算法。

7. **技能經濟專用基準（benchmarks for the skill economy）**  
   現有基準多評估單一任務成功率，未來需要能評量適應性、可移植性、組合性、安全性與使用者客製化能力的新基準，以反映技能市集的實際需求。

8. **資料與能源效率、人機協作與倫理法規**  
   隨著機器人技能開始自我演化，如何讓人類有效監督、介入與設定邊界，並建立對應的法律與倫理框架，將是長期且關鍵的研究議題。

## 論文問答

**Q1：這篇調查認為機器人學習領域目前面臨的核心分歧是什麼？**
A：該調查指出，當前機器人學習正圍繞「權重」與「技能」兩條路線分裂：一端是將能力烘焙進凍結權重的視覺—語言—動作（VLA）模型，另一端則是會撰寫並持續改進可執行程式碼的程式碼即策略（code-as-policy）智能體。這條分界線不僅是表徵形式的差異，更牽涉到策略是否可檢視、可修改、可隨經驗自我改進。作者以此單一軸線重新組織 77 個代表性系統，並主張這個對比在商業技能市集興起的當下變得格外關鍵。

**Q2：為何純粹的凍結權重 VLA 策略難以滿足開放式、長期運作的機器人應用？**
A：VLA 模型將觀測到動作的映射封裝在固定神經網路權重中，部署後無法根據新環境或失敗經驗進行非梯度式的自我修正，導致遇到分佈外情境時只能重複相同錯誤。相對地，程式碼即策略智能體產生的是人類可讀、可執行的程式，能透過執行回饋、記憶累積與搜尋機制不斷迭代。因此，當任務需要持續適應與長期改進時，凍結權重策略的靜態本質成為其主要瓶頸。

**Q3：機器人技能市集（如 Unitree UniStore）的出現，為何使「權重 vs. 技能」的討論更具時效性？**
A：Unitree UniStore 已實現一鍵跨模型動作下載，代表技能堆疊的第二層「分發」已經商業化，但目前所有上架技能都僅是靜態回放，缺乏第三層「適應」能力。這意味著使用者被承諾的「調整夾爪力道以免水果受損」等適應性功能，在現有市集中並不存在。因此，如何讓技能從靜態回放進化為可自我改進的可執行程式，成為學術與產業必須共同面對的問題。

**Q4：本文提出的分類架構如何組織 77 個代表性系統？**
A：作者以「權重—技能」作為單一組織軸，將 77 個系統劃分為六大技術家族，左叉為凍結權重的 VLA 策略，右叉為可檢視的程式碼與技能方法。在程式碼即策略這一側，又依自我改進程度細分為零樣本程式合成、閉環自我修復、持久技能記憶、演化搜尋，以及結合回饋、記憶與搜尋的完整開放式迴路。這種安排讓讀者能清楚看見各方法在「能否自我改進」光譜上的確切位置，而非僅是技術名詞的堆砌。

**Q5：程式碼即策略方法的自我改進階梯包含哪些層級，其判定條件為何？**
A：該階梯從最基礎的零樣本程式合成開始，經過能根據執行結果修正程式的閉環自我修復，再到可跨任務保留並複用技能的持久技能記憶，進一步透過演化搜尋探索更優程式，最後達到同時具備執行回饋、技能記憶與演化搜尋的完整開放式迴路。作者為每一層提供操作型定義與充分必要條件，使「自我改進程度」不再是模糊形容詞，而是可檢驗的系統屬性。目前只有極少數最新系統（如 ASPIRE、ENPIRE、RoboClaw）佔據最高層級的細胞。

**Q6：調查指出「skill」一詞至少有五種不同意義，這對理解自我改進有何影響？**
A：作者發現「skill」在文獻中可指低階動作原語、潛在動作空間、強化學習發現的行為、LLM 管理的功能庫，或以程式碼形式存在的可執行策略。在這五種語義中，只有「程式碼意義」能夠在不進行梯度更新的情況下，透過執行回饋與符號搜尋持續自我改進。這項區分凸顯了為何許多所謂的「技能庫」其實並不具備真正的自我改進能力，因為它們仍依賴凍結網路或靜態資料。

**Q7：本文在實驗與評估層面涵蓋哪些指標性基準與模擬器？**
A：調查納入 robosuite、RLBench、Meta-World、BEHAVIOR-1K、ManiSkill2、CALVIN、LIBERO 以及 Open X-Embodiment 等代表性模擬環境與資料集，這些平台覆蓋了從單項操作到長期語言條件任務的多樣需求。選擇它們的原因在於能支撐六大技術家族的比較，並凸顯從模擬到真實、從單一本體到跨本體轉移的挑戰。透過這些共同基準，作者得以對照 VLA、程式碼即策略、獎勵合成與技能發現等方法的可擴展性與泛化能力。

**Q8：對照表揭示了 VLA 與程式碼即策略之間哪些關鍵能力落差？**
A：對照結果顯示，VLA 模型通常在資料規模化與端到端泛化上表現強勁，但缺乏可解釋性、可組合性與非梯度適應能力；程式碼即策略則在可檢視性、符號組合與閉環修復上佔優，卻可能受限於高階規劃與低階控制之間的介面品質。這種互補性意味著兩極並非簡單替代關係，而是分別適合不同應用場景。調查進一步以「每個家族不能做的事」明確標示這些限制，避免讀者過度推論。

**Q9：佔據「完整自我改進迴路」這一稀疏細胞的系統（如 ASPIRE、ENPIRE、RoboClaw）有何共同特徵？**
A：這些系統同時整合執行回饋、持久技能記憶與演化搜尋，形成能持續發現、評估並改進自身技能的開放式迴路。它們不僅能在失敗後修復單一程式，更能跨多次執行累積可複用的技能單元，並透過搜尋機制探索新的行為變體。正因為需要協調真實世界回饋、記憶管理與大規模搜尋，這一細胞目前仍極少被佔據，也代表機器人自我改進研究的前沿。

**Q10：「技能堆疊」的三層架構如何對應到實際的商業機器人產品？**
A：技能堆疊的第一層「建立」對應研究與開發階段產生技能的各種技術；第二層「分發」則對應 Unitree UniStore 等市集，讓使用者能一鍵下載跨模型的動作。然而，第三層「適應」——即在裝置端根據現場回饋自我改進——目前仍停留在願景階段，尚未有商業化技能真正實現。這三層的落差說明，產品化進度領先於能讓技能持續演化的底層技術。

**Q11：要讓機器人技能經濟真正運作，必須解決哪些開放問題？**
A：作者列出適應性、跨本體可移植性、來源追溯、安全性驗證、組合性與標準化六大開放問題。適應性確保技能能因應不同環境與硬體差異；來源追溯與安全性驗證則是建立使用者信任與責任歸屬的基礎；組合性與標準化則決定技能能否像軟體模組一樣被重複組合與交易。這些問題環環相扣，任何一項缺失都可能阻礙技能市集從靜態內容商店轉型為可持續演化的生態系。

**Q12：跨本體可移植性與安全性驗證對技能市集的採用會產生什麼影響？**
A：跨本體可移植性讓同一技能能在不同機器人硬體上執行，是降低開發成本與擴大市場規模的關鍵；安全性驗證則確保下載的技能在真實物理環境中不會造成人身或財產損害。若缺乏可驗證的安全保證，企業與消費者將難以接受來自第三方的可執行技能，市場也會因此受限於少數封閉生態。因此，這兩項能力不僅是技術挑戰，更是決定技能經濟能否規模化的治理與商業門檻。

**Q13：作者承認本調查有哪些範圍上的限制？**
A：作者明確指出這是一項「聚焦調查」而非全面普查，僅選取 77 個符合明確收錄標準的代表性系統，並排除純感知、導航與移動研究，除非其直接關乎操作技能的建立與改進。附錄雖額外收錄 225 項工作以提供更廣脈絡，但核心分析仍圍繞單一分類軸線進行。這種刻意聚焦有助於深入比較，但也意味著某些相關領域僅被間接提及。

**Q14：各技術家族有哪些典型的限制，是讀者應避免的過度期待？**
A：VLA 家族雖然在端到端泛化上強大，卻難以進行非梯度適應、可解釋性與符號組合；程式碼即策略家族具備可檢視與可修復優勢，但低階控制精確度與規劃—執行介面仍可能出錯；LLM 技能庫與無監督強化學習發現的技能則常面臨語義對齊、評估標準與長期組合性的挑戰。作者透過「每個家族不能做的事」提醒讀者，沒有任何單一方法能同時滿足泛化、適應、安全與可解釋性的全部需求。

**Q15：針對未來研究，調查特別強調哪個方向的突破最為關鍵？**
A：作者最強調的是技能堆疊第三層「裝置端自我改進」的實現，也就是讓下載的技能能在真實機器人上根據執行回饋持續演化。這需要結合程式碼即策略、可靠的真實世界回饋、持久記憶與安全的演化搜尋，並建立跨本體標準與驗證框架。若能突破此層，機器人技能將從靜態商品轉變為可持續學習的數位資產，從而釋放技能經濟的全部潛力。

## 實務應用指南

### 適用場景

1. **高變異家庭服務（整理、清潔、備餐）**  
   環境與物品擺放每日不同，靜態回放無法應付。適合採用 **程式碼即策略（code-as-policy）** 搭配 **閉環自我修復** 與 **持久技能記憶**，讓機器人根據當下觀測重寫動作流程，例如 TidyBot、REFLECT 的應用方向。

2. **少量多樣的工業組裝與品檢**  
   產線換線頻繁、需要可解釋與可驗證的行為。以 LLM 生成可執行程式碼技能，再透過形式化驗證或約束檢查（Code-as-Monitor 概念）確保安全，比單純端到端 **凍結權重 VLA** 更容易通過品管與法規審查。

3. **物流倉儲跨機型搬運**  
   不同廠牌機器人需要共用「搬運」「堆疊」等技能。透過 **技能庫（skill library）** 與跨本體抽象層（CrossFormer、RoboCat 思路），可把同一個程式碼技能移植到不同載具，並在市集分發。

4. **易損農產品採摘與分級**  
   例如「夾爪力道依水果成熟度調整」。靜態動作會造成損傷，必須有 **執行回饋** 驅動的 **裝置端自我改進**；這正是技能堆疊第三層 Adapt 的價值，也是目前 Unitree UniStore 等一鍵技能市集尚未提供的功能。

5. **長期開放式探索任務（科研、搜救、行星探測）**  
   任務目標無法預先窮舉，需要 **執行回饋 + 技能記憶 + 演化搜尋** 的完整迴路。可參考 ASPIRE、ENPIRE、RoboClaw 這類佔據 §3.1.5 細胞的最新系統。

### 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **資料** | 若走 VLA 路線：大量多模態示範資料（RGB、深度、本體感覺、語言指令），如 Open X-Embodiment 格式。若走 code-as-policy：API 文件、環境回饋紀錄、失敗案例語料、可執行程式與執行軌跡的配對資料。 |
| **運算** | VLA 訓練需 GPU 叢集；推論可用邊緣 GPU。程式碼即策略主要消耗 LLM/VLM 推論成本，可先用雲端 API 驗證，再逐步轉為本地或邊緣模型。演化搜尋與模擬器需額外運算資源。 |
| **技能與基礎建設** | 機器人中介軟體（ROS 2）、感知堆疊、硬體抽象層、安全監控層、技能版本控制、標準化技能描述格式（如行為樹或 Python API 規格）。 |
| **安全與法規** | 風險評估流程、程式碼沙箱、緊急停止機制、來源追溯（provenance）與授權管理，特別是從第三方 **機器人技能市集** 下載技能時。 |

### 實作步驟建議

1. **任務分類與選邊**  
   重複性高、感知動作耦合強的任務優先試 **凍結權重 VLA**（如 RT-2、OpenVLA、π0）；需要組合、解釋、適應的任務則走 **程式碼即策略**。

2. **建立最小可執行技能**  
   從 **零樣本程式合成** 開始，利用 LLM 根據自然語言與 API 文件生成 Python 或行為樹技能，先在模擬器（ManiSkill2、RLBench、robosuite）驗證。

3. **加入閉環回饋與自我修復**  
   參考 REFLECT、DoReMi、AHA，讓系統在執行失敗後自動總結原因並重寫程式碼，而非僅回報錯誤。

4. **累積持久技能記憶**  
   將驗證過的技能存入 **技能庫**，建立索引、標籤與版本紀錄，支援跨任務檢索與複用（RoboCoder、Voyager、LOTUS 思路）。

5. **視需求引入演化搜尋**  
   若任務開放且需要持續成長，加入 **演化搜尋**（CaP-X、GEAR）探索新技能變體，並與回饋、記憶形成完整迴路。

6. **跨本體封裝與分發**  
   將技能包裝成具備硬體抽象、來源 metadata、授權與安全憑證的單元，再上架到 **機器人技能市集** 或內部中樞。

7. **裝置端適應與安全驗證**  
   在真實機器人上執行 **裝置端自我改進**，同時部署執行期監控、沙箱與形式化驗證，避免 LLM 生成程式碼的潛在風險。

8. **持續評估與資料飛輪**  
   建立真實世界評估指標，收集失敗案例回流技能庫，定期重新訓練或演化技能。

### 潛在風險與注意事項

| 風險 | 說明與因應 |
|---|---|
| **靜態回放陷阱** | 市售一鍵技能多為固定動作，無法適應環境變化。因應：務必規劃 **Adapt** 層，讓技能具備執行回饋與自我修復。 |
| **LLM 幻覺與不安全程式碼** | 生成程式可能呼叫錯誤 API 或產生危險動作。因應：沙箱執行、靜態分析、單元測試、人機協同審查，以及形式化安全驗證。 |
| **跨本體可移植性不足** | 技能常綁定特定夾爪、臂長或座標系。因應：建立硬體抽象層與標準化技能介面，分離「高層意圖」與「低層控制」。 |
| **資料與計算成本** | VLA 需要大量示範資料與訓練算力。因應：先用模擬器與少量真實資料驗證概念，再擴充；或採用 code-as-policy 降低資料需求。 |
| **來源追溯與責任歸屬** | 第三方技能出錯時難以追蹤。因應：每個技能附帶版本、作者、訓練資料、安全憑證與授權條款。 |
| **技能庫膨脹與衝突** | 長期累積可能產生重複或互相衝突的技能。因應：定期去重、語意相似度檢查、衝突偵測與版本治理。 |
| **延遲與即時性** | LLM 推論延遲高，不適合直接控制高頻迴路。因應：採階層式架構，高層由 LLM 規劃技能，低層由 VLA 或傳統控制器執行。 |

### 與其他技術的整合建議

- **凍結權重 VLA 作為低階動作模組**  
  讓 RT-2、Octo、π0 等負責感知-動作映射，而 code-as-policy 負責高層技能選擇、組合與異常處理，形成「大腦 + 小腦」架構。

- **數位孿生與模擬器**  
  利用 DrEureka、CrossFormer 的 sim-to-real 方法，在 Isaac Sim、ManiSkill2 等環境中快速迭代與驗證技能，再部署到真實機器人。

- **ROS 2 與機器人中介軟體**  
  將每個技能封裝為 ROS 2 Action/Service，統一介面後無論底層是 VLA 或程式碼技能，上層調度邏輯都能一致呼叫。

- **LLM/VLM 服務**  
  程式合成使用 GPT-4、Claude 或開源模型；視覺理解使用 VLM 進行失敗解釋與場景摘要（如 Inner Monologue、REFLECT）。

- **雲端技能市集 + 邊緣執行**  
  市集負責 **Distribute**，邊緣 runtime 負責 **Adapt** 與安全驗證，避免把未經檢查的程式碼直接放到實體機器人。

- **MLOps 與持續整合**  
  對技能實施版本控制、CI/CD 測試、A/B 評估與資料飛輪，讓機器人從現場失敗中持續改進。

### 給不同背景讀者的閱讀建議

**初學者**  
先聚焦圖 1 與圖 2，建立「權重派 = 凍結神經網路直接輸出動作；技能派 = 可執行程式且能自我改進」的直覺。把「skill」想成「機器人會自己改寫的程式碼」，不必急著理解 §3.1.5 的開放式迴路，先掌握零樣本程式合成與閉環自我修復即可。

**AI 工程師**  
重點閱讀 §3.1 的自我改進層級與操作型定義，對照你手邊任務判斷該用凍結 VLA（§3.2）還是 code-as-policy。§4 的開放問題——尤其是安全性驗證、跨本體可移植性與標準化——會直接影響系統架構與技術選型。

**研究人員**  
關注 §3.1.5 這個「稀疏細胞」與 ASPIRE、ENPIRE、RoboClaw，這是開放式自我改進的前沿；同時仔細檢視 §3.4 對「skill」五種語義的區分，避免在論文與實驗設計中混淆概念。附錄 A 的 225 篇比較可協助定位研究缺口。

**產品經理**  
把論文的「技能堆疊」對應到產品路線圖：第一層 Build 決定內容供應，第二層 Distribute 對應市集與生態，第三層 Adapt 才是差異化價值。請注意目前市售一鍵技能多為靜態回放，產品競爭力來自能否提供裝置端適應、來源追溯與安全驗證。
