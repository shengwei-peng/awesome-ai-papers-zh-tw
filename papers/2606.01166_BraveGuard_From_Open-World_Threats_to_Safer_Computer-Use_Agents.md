## ⚡ TL;DR

現有防護難以偵測電腦使用智慧體的多步驟執行風險，因為危害常由局部無害動作累積且威脅持續演變。
BraveGuard發掘開放世界威脅並合成任務，收集智慧體軌跡，建立自我演化的軌跡層級防護訓練迴圈。
AgentHazard準確率自38.79%提升至82.38%，軌跡層級監督顯著強化智慧體安全監控。

## 摘要翻譯

電腦使用智慧體（Computer-use agents）將語言模型（language models）從文字生成擴展到與檔案、終端機、瀏覽器和外部工具（external tools）的持續互動（sustained interaction）。這種轉變產生了難以從孤立提示（isolated prompts）或最終回應（final responses）中偵測的安全風險（safety risks），因為危害往往僅透過多步驟執行軌跡（multi-step execution traces）才會顯現，而其個別動作看似局部無害（locally benign）。我們提出 BraveGuard，一個從開放世界威脅訊號（open-world threat signals）與真實智慧體軌跡（realistic agent trajectories）中訓練防護模型（guard models）的自我演化防禦框架（self-evolving defense framework）。BraveGuard 探勘近期研究來源（recent research sources）以識別新興風險（emerging risks）與攻擊模式（attack patterns），將其具體化為可執行的電腦使用任務（executable computer-use tasks），收集智慧體展開（agent rollouts），並推導出用於防護模型訓練的軌跡層級監督訊號（trajectory-level supervision）。隨著新威脅（new threats）與驗證失敗（validation failures）出現，該管線（pipeline）可重複執行，形成適應性防禦迴圈（adaptive defense loop），而非靜態的基準測試驅動訓練（benchmark-driven training）流程。我們透過訓練多個防護模型骨幹（guard backbones），包括 Qwen3-Guard 與 Llama-Guard 變體（variants），並在軌跡層級智慧體安全基準測試（trajectory-level agent-safety benchmarks）上評估所產生的防護模型。BraveGuard 在電腦使用軌跡（computer-use trajectories）方面穩定提升安全偵測（safety detection）能力。在 AgentHazard 上，BraveGuard 相較於現成防護模型（off-the-shelf guard models）大幅提升了偵測準確率（detection accuracy），在平均防護模型設定（averaged guard-model setting）下，準確率從 38.79% 提升至 82.38%。這些結果顯示，基於開放世界威脅發現（open-world threat discovery）與真實智慧體執行（realistic agent execution）的防護模型監督訊號，能夠突破固定分類法（fixed taxonomies）與合成提示層級資料（synthetic prompt-level data）的限制，進而改善安全監控（safety monitoring）。BraveGuard 為面對不斷演變的真實世界風險（evolving real-world risks）的電腦使用智慧體，提供一條通往適應性防禦（adaptive defenses）的可擴展途徑（scalable path）。

### 核心貢獻（3～5點）
- 提出 BraveGuard，一個從開放世界威脅訊號與真實智慧體軌跡中訓練防護模型的自我演化防禦框架，突破傳統靜態、基準測試驅動的訓練範式。
- 建立可持續迭代的適應性防禦迴圈：自動探勘研究文獻以識別新興風險與攻擊模式，產生可執行的電腦使用任務並收集智慧體展開，從中推導軌跡層級監督訊號。
- 在軌跡層級智慧體安全基準測試 AgentHazard 上，相較於現成防護模型，將偵測準確率從 38.79% 大幅提升至 82.38%。
- 證明基於開放世界威脅發現與真實智慧體執行的監督訊號，能有效超越固定分類法與合成提示層級資料的侷限，顯著強化安全監控。
- 為面對不斷演變的真實世界風險之電腦使用智慧體，提供一條可擴展的適應性防禦途徑。

### 適合對象
從事人工智慧安全、智慧體框架開發、防護模型研究

## 深度分析

#### 方法論解析

BraveGuard 的核心洞見在於：computer-use agents（電腦使用智慧體）的危害並非總是顯現在 isolated prompts（孤立提示）或 final responses（最終回應）中，而是往往透過 multi-step execution traces（多步驟執行軌跡）逐步累積。individually plausible actions（個別看似合理的動作）在 locally benign（局部無害）的表象下，經由 cumulative effect（累積效應）導致 sensitive data exposure（敏感資料外洩）、unauthorized operations（未授權操作）或 policy constraints（政策限制）被規避。因此，BraveGuard 將 safety monitoring（安全監控）的單位從單一提示提升至 complete executions（完整執行）層級，提出一套 self-evolving defense framework（自我演化防禦框架）。

整體 defense pipeline（防禦管線）可分為四個階段。第一階段為 open-world threat discovery（開放世界威脅發現）。不同於依賴 fixed taxonomies（固定分類法）或 predefined risk taxonomies（預定義風險分類法）的傳統做法，BraveGuard 將 threat space（威脅空間）視為 non-stationary（非靜態）。系統以關鍵字集合 Q0 與分類狀態 Z0 初始化，從 open research sources（公開研究來源）持續挖掘 emerging risks（新興風險）、attack patterns（攻擊模式）與 failure modes（失效模式）。初始種子詞彙來自廣泛的 computer-use agents（電腦使用智慧體）安全概念與既有文獻，而非來自評估基準的標籤或任務實例，確保威脅知識不會被人為情境所侷限。

第二階段將結構化威脅知識實例化為 executable computer-use tasks（可執行的電腦使用任務）。這些任務並非 synthetic adversarial prompts（合成對抗性提示），而是能夠在真實 digital environments（數位環境）中執行的操作序列，涵蓋 filesystems（檔案系統）、terminals（終端機）、browsers（瀏覽器）與 external tools（外部工具）的互動。

第三階段透過 OpenClaw 收集 agent rollouts（智慧體展開），產生 realistic agent trajectories（真實智慧體軌跡）。每一條 execution trajectories（執行軌跡）都會被標註 safety labels（安全標籤）、risk categories（風險類別）與 supporting rationales（支持性理由），從而形成 trajectory-level supervision（軌跡層級監督）。這種 supervision（監督訊號）要求 guard models（防護模型）必須同時考量 user intent（使用者意圖）、environment state（環境狀態）、tool affordances（工具可供性）與 intermediate actions（中介動作）的時序互動，而非僅判斷 final responses（最終回應）是否 harmful（有害）。

第四階段是 adaptive defense loop（適應性防禦迴圈）。BraveGuard 在 held-out validation split 上偵測 validation failures（驗證失敗）與新發現的威脅，將這些 hard cases 反饋回第一階段，擴充 risk taxonomies（風險分類法）、合成額外任務並更新訓練分布。這使得訓練資料與 guard model（防護模型）能夠共同演化（co-evolve），而非停留在 one-shot data generation（一次性資料生成）所產生的 static corpora（靜態語料庫）。

在模型實例化上，論文以多個 guard backbones（防護模型骨幹）進行驗證，包括 Qwen3-Guard（Qwen3-Guard，防護模型變體）與 Llama-Guard（Llama-Guard，防護模型變體），顯示此框架具備跨架構的通用性。

#### 實驗數據解讀

論文選用 AgentHazard（AgentHazard，軌跡層級 Agent 安全基準測試）作為主要評估場域，該 benchmark 專注於 computer-use agents（電腦使用智慧體）在 long-horizon trajectories（長程軌跡）中的 harmful behavior（有害行為）。實驗結果顯示，在 averaged guard-model setting（平均防護模型設定）下，off-the-shelf guard models（現成防護模型）的 detection accuracy（偵測準確率）僅為 38.79%，而經過 BraveGuard 訓練後的 guard model（防護模型）提升至 82.38%。

這組數據具有三層意義。首先，38.79% 的低落基線證實了傳統防禦的結構性缺陷：當 harmful behavior（有害行為）透過 tool-mediated failures（工具媒介失效）與 multi-step execution traces（多步驟執行軌跡）實現時，僅依賴 static corpora（靜態語料庫）或 synthetic prompt-level data（合成提示層級資料）訓練的模型幾乎無法識別 locally benign（局部無害）但整體危險的動作鏈。其次，超過兩倍的準確率提升表明，trajectory-level supervision（軌跡層級監督）能有效捕捉 cumulative effect（累積效應）與跨步互動。第三，結果在 Qwen3-Guard 與 Llama-Guard 等不同 guard backbones（防護模型骨幹）上呈現一致性，暗示此 supervision（監督訊號）的品質高於特定架構的歸納偏置，具備跨模型的遷移價值。

值得注意的是，82.38% 雖顯著優於基線，但在安全關鍵場域中仍代表近兩成的漏檢率。這也說明 computer-use agents（電腦使用智慧體）的 open-world threats（開放世界威脅）具有高度複雜性，即便採用 realistic agent trajectories（真實智慧體軌跡）進行訓練，trajectory-level agent-safety benchmarks（軌跡層級智慧體安全基準測試）仍有足夠的困難度保留給未來研究。

#### 與現有研究的比較

現有 safety defenses（安全防禦）大多繼承自 chatbot LLMs（聊天機器人大型語言模型）的內容審核傳統，聚焦於偵測 unsafe prompts（不安全提示）或 harmful responses（有害回應）。這類方法在 short conversations（簡短對話）中尚能應付，但面對 computer-use agents（電腦使用智慧體）時，由於無法處理 long-horizon trajectories（長程軌跡）與 tool calls（工具呼叫）的時序組合，往往失效。

近期研究如 AgentHazard 與 ATBench 已開始將評估單位從單輪對話轉向 complete executions（完整執行），defense pipelines（防禦管線）也出現過濾注入指令、檢查任務對齊或歸因工具使用等機制。然而，這些防禦的 supervision（監督訊號）仍主要來自 predefined risk taxonomies（預定義風險分類法）、manually curated scenarios（人工策劃情境）或 synthetic adversarial prompts（合成對抗性提示），本質上仍屬 benchmark-driven training（基準測試驅動訓練）。一旦攻擊者利用 newly discovered attack strategy（新發現的攻擊策略）、陌生工具或 evolving real-world risks（不斷演變的真實世界風險），這些靜態防禦便會產生分布外失效。

BraveGuard 的差異化貢獻在於將防禦視角從「基準測試內的已知風險」轉向「open-world threat signals（開放世界威脅訊號）」。透過持續挖掘 open research sources（公開研究來源）中的 emerging risks（新興風險）與 threat patterns（威脅模式），並將其轉化為 executable computer-use tasks（可執行的電腦使用任務），BraveGuard 突破了 fixed taxonomies（固定分類法）的邊界。其 adaptive defense loop（適應性防禦迴圈）更讓防禦系統能隨 software ecosystem（軟體生態系）與 deployment practices（部署實務）共同演化，而非在訓練後即成為 static corpora（靜態語料庫）的產物。

然而，從提供文本可推論若干限制。第一，BraveGuard 依賴 OpenClaw 作為執行環境以收集 agent rollouts（智慧體展開），若目標 agent frameworks（智慧體框架）與 OpenClaw 的動作空間或觀測格式差異過大，可能產生領域落差。第二，open-world threat discovery 的品質受限于初始關鍵字集合 Q0 與可檢索到的公開文獻，對於尚未被學術界或開源社群記錄的 zero-day 攻擊，框架仍難以主動預測。第三，自我演化迴圈的計算成本顯著高於 one-shot data generation（一次性資料生成），持續重複管線所需的運算與標註資源在實際部署中可能成為瓶頸。

#### 可重現性評估

根據提供的全文脈絡，BraveGuard 目前並未明確提及原始碼、資料集或模型權重的公開釋出計畫。論文雖詳細描述管線邏輯——從關鍵字集合 Q0 與分類狀態 Z0 的初始化、OpenClaw 上的 agent rollouts（智慧體展開），到 trajectory-level supervision（軌跡層級監督）的建構——但缺乏下列關鍵重現要素：第一，用於威脅發現的結構化 risk taxonomies（風險分類法）與對應的任務模板；第二，OpenClaw 執行環境的具體實作細節與版本資訊；第三，收集到的 execution trajectories（執行軌跡）資料集及其 safety labels（安全標籤）的開放下載連結；第四，訓練 Qwen3-Guard 與 Llama-Guard 變體的超參數與程式碼。

在當前大型語言模型與智慧體安全的研究慣例中，僅憑論文描述而無開源釋出，會顯著降低獨立驗證的可能性。特別是 BraveGuard 的自我演化特性仰賴多輪次的任務合成、軌跡收集與 validation failures（驗證失敗）反饋，任何實作上的細微差異——例如關鍵字擴展策略、軌跡過濾閾值或停止條件——都可能導致不同的 threat space（威脅空間）覆蓋率與模型效能。若作者群後續能釋出 BraveGuard 的開源實作，將有助於社群驗證 38.79% 至 82.38% 的 detection accuracy（偵測準確率）提升是否能在異質環境中複現，並促進針對 computer-use agents（電腦使用智慧體）的 adaptive defense loop（適應性防禦迴圈）研究。

#### 未來研究方向

BraveGuard 為 computer-use agents（電腦使用智慧體）的適應性防禦開闢了新路徑，但仍有多個值得延伸的方向。首先，目前的自我演化迴圈似乎以離線批次方式運作，未來可探索即時線上適應，使 guard models（防護模型）在部署階段能根據即時的 validation failures（驗證失敗）與 emerging risks（新興風險）動態更新，縮短從威脅發現到防禦部署的延遲。

其次，現有框架主要聚焦單一智慧體的 execution trajectories（執行軌跡），未來可擴展至多智慧體協作場景，研究跨智慧體的 unauthorized operations（未授權操作）與 permission changes（權限變更）如何透過 trajectory-level supervision（軌跡層級監督）進行歸因與攔截。

第三，BraveGuard 的威脅發現依賴 open research sources（公開研究來源），後續可結合主動式對抗性探索，例如以紅隊自動生成尚未被文獻記錄的 attack patterns（攻擊模式），進一步降低對既有關鍵字集合 Q0 的依賴。

第四，目前 82.38% 的 detection accuracy（偵測準確率）顯示仍有進步空間。未來研究可聚焦於軌跡的因果推理，讓 guard model（防護模型）不僅判斷「是否 harmful（有害）」，更能解釋「在哪一步、透過哪個 tool calls（工具呼叫）導致了何種 cumulative effect（累積效應）」，從而提升可解釋性與人機協同審核的效率。

最後，將 BraveGuard 的 adaptive defense loop（適應性防禦迴圈）與更廣泛的 agent frameworks（智慧體框架）——例如具備 persistent state（持久狀態）的複雜生產環境——進行整合，並釋出標準化資料集與開源工具，將是推動此領域從研究原型走向實際 deployment practices（部署實務）的關鍵。

## 論文問答

**Q1：電腦使用智慧體與傳統聊天機器人大型語言模型相比，其核心安全問題有何根本不同？**
A：電腦使用智慧體透過終端機、檔案系統、瀏覽器與外部工具進行持續互動，使其有害行為往往透過多步驟執行軌跡顯現，而非侷限在單一提示或最終回應中。在這類數位環境裡，個別看似合理的動作—例如工具呼叫、檔案編輯或權限變更—可能在累積效應下導致敏感資料外洩、未授權操作或不安全程式碼執行。因此，安全監控不能僅偵測惡意提示或不安全的最終答案，而必須對整段執行軌跡進行推理，評估使用者意圖、環境狀態與中介動作隨時間的交互作用。

**Q2：為何現成的防護模型與傳統防禦管線難以有效保護電腦使用智慧體？**
A：現有防護模型通常以靜態語料庫訓練，內容多為不安全提示、有害回應或簡短對話，無法涵蓋長程軌跡中工具媒介失效的複雜性。多數防禦管線依賴預定義風險分類法、人工策劃情境或合成對抗性提示，這些資源僅能覆蓋威脅空間的有限部分。由於真實世界的風險會隨軟體生態系不斷演變，新發現的攻擊策略與新工具持續出現，僅在固定基準測試分布上訓練的防護模型面對陌生執行模式時將變得脆弱。

**Q3：軌跡層級推理對電腦使用智慧體的安全為何至關重要？**
A：在電腦使用情境中，危害通常源於一連串局部無害動作的組合，而非單一明顯的惡意輸入，因此必須審視完整執行過程才能判斷是否違反政策限制。若只檢查孤立提示或最終輸出，安全系統將無法察覺那些經過長期互動才顯現的累積效應。唯有透過軌跡層級監督，才能追蹤智慧體與持久狀態環境之間的互動，確保每個中介動作在整體脈絡下都符合安全規範。

**Q4：BraveGuard 的核心運作管線包含哪些主要階段？**
A：BraveGuard 首先從公開研究來源萃取結構化威脅知識，將新興風險、攻擊模式與失效模式組織成動態的風險分類法。接著，它將這些威脅模式具體化為可執行的電腦使用任務，並透過智慧體展開收集真實智慧體軌跡，再對這些軌跡標註安全標籤、風險類別與支持性理由。最後，驗證失敗與新發現的威脅會被回饋至下一輪，用以擴充分類法、合成新任務並更新訓練分布，形成適應性防禦迴圈。

**Q5：相較於基準測試驅動訓練，BraveGuard 的關鍵創新是什麼？**
A：BraveGuard 的關鍵創新在於建立自我演化防禦框架，使訓練分布與防護模型能隨著不斷演變的真實世界風險共同演化，而非依賴一次性資料生成。它不再受限於固定分類法或合成提示層級資料，而是持續挖掘開放世界威脅訊號，並將其轉化為基於真實執行的軌跡層級監督訊號。這種閉環設計確保每當出現新的攻擊模式或驗證失敗時，防護模型都能透過反覆迭代獲得更新，從而提供可擴展途徑以實現動態防禦。

**Q6：BraveGuard 在威脅發現與監督訊號設計上有哪些重要設計選擇？**
A：在威脅發現階段，BraveGuard 使用源自廣泛電腦使用智慧體安全概念與先前公開文獻的小型種子詞彙來初始化，刻意避免直接採用現有基準標籤或任務實例，以降低對已知分布的偏誤。作者將威脅空間視為非靜態，並持續以最新公開研究證據為基礎維護結構化分類法。在監督訊號方面，它捨棄傳統的提示層級標註，改為對完整執行軌跡進行判讀，使防護模型學會評估一連串工具呼叫與環境狀態隨時間交互作用的整體安全性。

**Q7：作者在哪類基準測試上評估 BraveGuard，這些基準測試衡量什麼能力？**
A：作者主要在軌跡層級智慧體安全基準測試上進行評估，其中最具代表性的是 AgentHazard，它專門研究電腦使用智慧體在長程真實互動中的有害行為。這類基準測試衡量的是防護模型偵測多步驟執行軌跡中潛在危害的能力，而非僅僅標記惡意提示或有害回應。透過強調工具媒介失效與持久狀態環境中的互動過程，這些測試能更忠實地反映安全監控在實際部署情境中所面臨的挑戰。

**Q8：BraveGuard 取得了哪些關鍵量化成果，證明其有效性？**
A：在 AgentHazard 上，BraveGuard 在平均防護模型設定下將偵測準確率從 38.79% 大幅提升至 82.38%，顯著優於現成防護模型。這項結果證明，奠基於開放世界威脅發現與真實智慧體執行的軌跡層級監督，遠比固定分類法或合成資料更能強化安全監控。此外，當以 Qwen3-Guard 與 Llama-Guard 等多種防護模型骨幹進行實例化時，BraveGuard 皆能持續提升對電腦使用軌跡的安全偵測表現。

**Q9：BraveGuard 的實驗結果如何凸顯靜態或提示層級訓練典範的侷限？**
A：BraveGuard 與現成防護模型在 AgentHazard 上的巨大效能差距顯示，僅依賴預定義風險分類法或提示層級語料庫進行訓練，無法有效偵測長程智慧體執行中顯現的危害。由於 BraveGuard 的監督訊號來自完整且真實的執行軌跡，而非孤立提示，它能辨識出傳統內容審核模型無法察覺的累積效應與複合風險。驗證失敗驅動的迭代擴展機制也進一步說明，缺乏適應性防禦迴圈的基準測試驅動訓練將使防護模型在面對新攻擊策略與陌生工具組合時暴露弱點。

**Q10：BraveGuard 在哪些實際部署情境中最具應用價值？**
A：BraveGuard 對於部署於持久數位環境中的電腦使用智慧體最具價值，例如具備終端機與檔案系統存取權限的自動化程式編寫助理、資料分析智慧體，或能操作瀏覽器的個人生產力助理。這些情境的軟體生態系持續演變，新工具、智慧體框架與攻擊向量透過開源開發與研究文獻不斷湧現。透過自動挖掘這些開放世界威脅訊號並更新訓練分布，BraveGuard 無需依賴頻繁的人工策劃，即可持續維護安全監控的有效性。

**Q11：產品團隊在將 BraveGuard 整合至智慧體系統時，應考量哪些產品層面的因素？**
A：產品團隊必須建立相應基礎設施，以持續收集智慧體展開、執行合成任務，並在閉環管線中處理驗證失敗，而非僅部署一次性訓練的模型。由於框架依賴公開研究來源與真實執行軌跡，任務具現化與展開收集階段必須在嚴格的沙箱環境中進行，避免資料生成過程造成實際損害。此外，選擇 Qwen3-Guard 或 Llama-Guard 等防護模型骨幹時，應綜合考量延遲、成本與系統整合限制，同時保留隨威脅分類法擴展而重新訓練或微調的彈性。

**Q12：BraveGuard 可能對智慧體安全與內容審核的廣泛研究領域帶來什麼影響？**
A：BraveGuard 將研究重心從靜態內容審核與固定基準測試評估，轉向與真實威脅共同演化的動態、執行導向安全監控。透過證明開放世界威脅發現與軌跡層級監督能顯著提升偵測準確率，它促使未來研究將智慧體安全視為非靜態問題，需要持續適應而非一次性建構資料集。這種典範可能為防護模型訓練樹立新標準，讓適應性防禦迴圈取代合成提示層級資料，成為電腦使用智慧體的主要監督來源。

**Q13：BraveGuard 框架在現階段存在哪些固有侷限？**
A：其一，威脅分類法的品質與覆蓋範圍高度依賴所挖掘公開研究來源的豐富度與即時性，對於尚未被文獻記錄的零日攻擊模式可能存在盲點。其二，將威脅具現化為可執行任務並收集完整智慧體展開的過程運算成本高昂，且需要強大的沙箱機制以避免資料生成期間的意外副作用。其三，框架假設能可靠識別驗證失敗以引導後續擴展，但從細微的長程軌跡中區分有害與無害行為本身就可能需要高品質的自動化或人工判斷，而這類資源未必總是充足。

**Q14：在哪些條件下，BraveGuard 可能無法偵測或阻止有害的智慧體行為？**
A：當攻擊策略過於新穎，導致其不符合當前已挖掘研究來源中的任何威脅模式或已合成任務分布時，防護模型將缺乏相關訓練訊號而失效。若驗證階段未能發現某些涉及罕見工具組合或長期延遲累積效應的失效模式，自我演化迴圈便無法在後續迭代中擴充分類法以填補缺口。此外，若軌跡層級標註未能充分掌握環境狀態與使用者意圖的脈絡細節，那些極度模仿正常工作流程的個別看似合理動作也可能逃過偵測。

**Q15：有哪些未來方向可以延伸或改進 BraveGuard 框架？**
A：未來研究可整合更多樣的開放世界訊號，例如即時漏洞披露、威脅情資饋流與部署中智慧體的實際日誌，以加速新興風險的發現。開發更精細的自動標註機制，自動生成更豐富的理由與反事實解釋，也有助於提升軌跡層級監督訊號的可解釋性與穩健性。另一個有潛力的方向是將適應性防禦迴圈擴展至接近即時運作，使防護模型在真實部署過程中面對新風險時，能持續更新偵測能力，而非僅透過離線批次重新訓練。

## 實務應用指南

### 適用場景

1. **企業級自動化助理**：部署於具備檔案系統、終端機與瀏覽器權限的電腦使用智慧體，用於偵測跨檔案操作與多步驟網頁互動中的累積效應，防止敏感資料外洩或未授權操作。
2. **軟體開發與維運自動化（DevOps Agents）**：監控具備程式碼執行與基礎設施管理能力的智慧體，識別個別看似合理的指令序列如何組合成不安全程式碼執行或環境狀態破壞。
3. **金融與醫療資料處理智慧體**：在需嚴格遵守政策限制與合規規範的領域，透過軌跡層級監督確保智慧體在長期互動中不會透過工具呼叫間接繞過資料存取控管。
4. **多智慧體協作平台**：當多個智慧體透過外部工具與共享記憶體協作時，BraveGuard 可作為集中式安全監控層，追蹤跨智慧體的執行軌跡並偵測新興的攻擊模式。
5. **第三方工具整合的客戶服務或分析智慧體**：針對連接瀏覽器、檔案系統與外部 API 的智慧體，持續從公開研究來源挖掘與工具媒介失效相關的威脅模式，降低固定分類法無法覆蓋的風險。

### 實作前置條件

- **資料**：需具備目標智慧體的歷史執行軌跡紀錄（包含工具呼叫、檔案編輯、終端機輸出與瀏覽器行為）；可取得公開研究來源（資安論文、漏洞資料庫、智慧體框架更新日誌）作為開放世界威脅訊號；建議備有基準測試資料集（如 AgentHazard）以建立評估基線。
- **運算**：用於微調防護模型骨幹（如 Qwen3-Guard 或 Llama-Guard 變體）的 GPU 叢集；可執行大規模智慧體展開的隔離運算環境（容器或沙箱），以收集完整執行軌跡；儲存空間需足以保留多輪迭代產生的軌跡層級監督資料。
- **技術能力**：熟悉電腦使用智慧體框架（如 OpenClaw 或同等環境）、大型語言模型微調與推理部署；具備資安威脅建模能力，能將攻擊模式與失效模式轉譯為可執行的電腦使用任務；具備資料工程能力以維護非靜態的威脅空間與適應性防禦迴圈。

### 實作步驟建議

1. **建立開放世界威脅發現管線**：設定初始關鍵字種子集（涵蓋間接提示注入、記憶體污染、工具濫用等概念），定期爬取公開研究來源與漏洞情資，萃取結構化的風險分類法、攻擊模式與失效模式，而非依賴人工策劃情境。
2. **威脅模式可執行化**：將新發現的威脅模式轉換為可執行的電腦使用任務，設計能觸發多步驟執行軌跡的測試案例，特別針對「局部無害但整體有害」的累積效應進行壓力測試。
3. **收集真實智慧體軌跡**：在隔離環境中運行目標智慧體，執行上述任務並收集智慧體展開結果，確保軌跡包含中介動作、環境狀態變更與最終回應，避免僅使用合成提示層級資料。
4. **軌跡層級標註與監督生成**：為每筆執行軌跡標註安全標籤、風險分類與判斷依據，明確記錄使用者意圖、工具可供性與環境狀態如何交互導致有害行為，形成高品質的軌跡層級監督訊號。
5. **訓練防護模型**：使用收集到的軌跡層級監督訊號微調防護模型骨幹，目標是讓模型學會從完整執行脈絡中判斷安全性，而非僅從孤立提示或最終回應進行內容審核。
6. **驗證與困難案例回饋**：在保留驗證集上評估偵測準確率，將驗證失敗案例與新發現的威脅模式回饋至下一輪威脅擴充與任務合成，啟動自我演化防禦框架的適應性防禦迴圈。
7. **部署與持續監控**：將訓練完成的防護模型部署為線上安全監控服務，持續分析生產環境的智慧體軌跡，並定期重新觸發威脅發現與資料生成流程，避免模型退化為靜態語料庫驅動的防禦管線。

### 潛在風險與注意事項

- **誤殺合法長程任務**：軌跡層級偵測可能將正常的多步驟批次處理或複雜檔案編輯誤判為有害行為，建議保留人類回饋校準機制，並針對邊界案例建立覆核流程。
- **威脅分類法覆蓋率缺口**：若公開研究來源遺漏特定領域攻擊（如內部威脅或零時差漏洞），防護模型將存在盲點，應搭配內部紅隊演練與生產環境異常紀錄補強，而非完全依賴外部文獻。
- **運算成本與擴展性**：持續性的智慧體展開與模型重訓練成本高昂，建議採用主動學習策略，優先針對高風險類別與驗證失敗案例進行展開，以降低平均防護模型設定下的資源消耗。
- **軌跡資料隱私**：執行軌跡可能包含敏感資料或機密環境狀態，去識別化與嚴格存取控管必須在資料收集階段即納入設計，避免監督訊號本身成為外洩來源。
- **對抗式迴避**：攻擊者可能利用未被研究文獻記載的全新策略繞過偵測，因此威脅空間應視為非靜態，需將真實攻擊事件與驗證失敗持續注入適應性防禦迴圈。

### 與其他技術的整合建議

- **與現成防護模型串接**：將 BraveGuard 作為軌跡層級的後置分析層，與現有的提示層級防護模型（如 Llama-Guard）形成縱深防禦；前者負責多步驟執行脈絡，後者負責單輪輸入輸出的初步過濾。
- **嵌入智慧體框架**：整合至 OpenClaw 或其他電腦使用智慧體框架的執行環境，在每次工具呼叫、權限變更或狀態更新後即時取得軌跡片段進行評分，實現近乎即時的安全監控。
- **資安營運中心（SOC）聯動**：將偵測結果以標準格式（如 Syslog 或 STIX）輸出至 SIEM/SOAR 平台，銜接現有資安事件回應流程，使智慧體安全監控成為整體防禦管線的一環。
- **人機協同審查**：對於高風險或模型信心度低的案例，觸發人類審查工作流程而非直接阻斷，以平衡安全性與可用性，特別是在關鍵業務流程中。
- **動態授權系統**：將防護模型的風險分類輸出與屬性基礎存取控制（ABAC）結合，依據即時偵測到的威脅模式動態調整智慧體對檔案系統、終端機或外部工具的權限。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先聚焦於「提示層級安全」與「軌跡層級安全」的核心差異，理解為何單一看似無害的工具呼叫在長期互動中會產生危害；可從論文的風險示意圖與 BraveGuard 的高層次流程圖入手，暫時略過模型訓練細節，建立對電腦使用智慧體風險輪廓的直覺。
- **AI 工程師**：請重點閱讒第三節的實作管線與論文中關於軌跡收集、標註與防護模型微調的技術細節，特別關注如何將智慧體展開結果轉換為適合 Qwen3-Guard 或 Llama-Guard 的訓練格式，並評估自身基礎建設是否足以支撐持續性的資料生成與迭代訓練。
