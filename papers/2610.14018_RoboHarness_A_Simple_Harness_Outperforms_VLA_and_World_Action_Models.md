RoboHarness 的核心論點是：與其訓練大型模型來直接生成機器人動作，不如為現成的大型語言模型（LLMs）提供一套「視覺幾何控制面板」（visual-geometric control panel），讓編碼代理（coding agent）能夠透過工具呼叫（tool calling）來完成具身操作（embodied manipulation）任務。這是一個典範轉移——從「訓練模型輸出動作」轉向「設計介面讓模型呼叫動作」。

**核心架構設計：**

RoboHarness 由三個關鍵元件組成：

1. **視覺點擊介面（Visual Click Interface）**：允許 LLM 代理透過座標指定場景中的物件位置，將視覺感知抽象為可程式化的點擊操作。這解決了 LLM 處於「文字空間」（textual space）而物理世界處於「視覺空間」之間的介面鴻溝。

2. **關鍵點追蹤器（Geometry Tracker）**：持續追蹤場景中感興趣的關鍵點（keypoints），例如鑰匙、鎖孔、夾爪（gripper）中心等。這些追蹤點會隨時間更新其三維座標與距離資訊（如論文中所示：`Key: coord=(0.29, 0.18, 0.02), distance=0.57m`）。

3. **幾何約束工具集（Geometric Constraint Toolset）**：提供最小化的動作原語（minimal toolset），包括：
   - `transition(x, y, z)`：控制末端執行器（end-effector）的平移
   - `rotation(roll, pitch, yaw)`：控制末端執行器的旋轉
   - `linear(A, B, C)`：強制三點共線（collinear），用於對齊操作

**方法論的關鍵洞察：**

論文的核心論證是：現有方法的瓶頸不在於 LLM 的能力，而在於「動作介面」（action interface）的設計。傳統的 VLA 模型將動作編碼進詞彙表（vocabulary）進行自回歸生成（autoregressive generation），或透過流匹配（flow-matching）的動作頭（action head）產生連續動作——這些方法都需要大量機器人動作資料（robot-action data）且難以擴展。RoboHarness 則主張：只要提供足夠完整的幾何工具介面，LLM 本身的任務分解（task decomposition）、規劃（planning）、空間推理（spatial reasoning）與工具使用（tool use）能力就能被直接利用。

**與編碼代理框架的整合：**

RoboHarness 被設計為可隨插即用（plug-and-play）地接入現有的編碼代理框架（如 Claude Code），這意味著它繼承了編碼代理已有的規劃、除錯、重試機制。這種「代理推演」（agent rollout）模式讓 LLM 在閉環（closed loop）中持續驗證執行結果並修正策略。

#### 與現有研究的比較

**與 VLA 模型的比較：**

VLA 模型（如 RT-2、OpenVLA、FAST、π0、π0.7、GR00T N1、Galaxea G0.5）採用「訓練模型輸出動作」的典範：

- **自回歸動作詞彙（Autoregressive Action Tokens）**：RT-2、OpenVLA 將動作離散化並透過下一詞預測（next-token prediction）生成；FAST 則使用頻域分詞器壓縮動作塊（action chunks）。
- **連續動作專家（Continuous Action Experts）**：π0 使用流匹配動作頭，GR00T N1 使用擴散 Transformer（diffusion transformer），π0.7 則進一步以子任務指令、子目標圖像等豐富上下文作為條件。

RoboHarness 的優勢在於：完全跳過了「動作監督學習」階段，避免了資料收集成本與知識遺忘問題。論文中特別提到「知識隔離」（knowledge insulation）技術（Driess et al., 2025）正是為了解決 VLA 訓練中保留預訓練知識的困難——而 RoboHarness 從根本上不需要面對這個問題，因為它不改變 LLM 本身。

**與世界動作模型（WAMs）的比較：**

世界動作模型（World Action Models，如 Zhao et al., 2026; Wang et al., 2026; Li et al., 2026）試圖透過學習「動作條件下的世界變化模型」來提升泛化能力。RoboHarness 的論點是：LLM 已經具備強大的世界知識（world knowledge），不需要額外學習世界模型，只需要正確的介面來表達動作。

**與 LLM 規劃方法的比較：**

先前工作如 SayCan（Ahn et al., 2023）、Inner Monologue（Huang et al., 2023b）、Code as Policies（Liang et al., 2023）、CaP-X（Fu et al., 2026）、ASPIRE（Lu et al., 2026）已證明了將具身子任務封裝為可呼叫函數的可行性。然而，RoboHarness 指出這些方法的限制在於「動作介面不完整」：可用函數的覆蓋範圍由預定義的任務、物件與策略決定，每個新物件或任務都可能需要新增函數。RoboHarness 透過視覺幾何控制面板提供了更通用的介面，不受限於預定義的動作空間。

**與 HarnessVLA 的比較：**

HarnessVLA（Zhang et al., 2026）結合凍結的 VLA 處理接觸豐富的操作，搭配分析型原語（analytic primitives）。RoboHarness 則更激進——完全不需要 VLA，僅靠 LLM 本身的推理能力加上幾何工具。

**論文的侷限：**

## 實作步驟建議

**Step 1：環境建置**
```bash
git clone https://github.com/BinceQu/RoboHarness
conda create -n roboharness python=3.10
pip install -r requirements.txt
```
下載 BEHAVIOR-1K 資料集並設定 `OMNIGIBSON_PATH`。

**Step 2：選擇 LLM 後端**
- 開源路線：本地部署 Qwen3.8-Flash-Next（vLLM 或 SGLang）
- 閉源路線：透過 Claude Code / OpenAI API 接入
- 評估延遲與成本，決定是否需要快取常見子任務

**Step 3：熟悉最小工具集（Minimal Toolset）**
重點理解以下原語：
- `transition(x, y, z)`：末端執行器平移
- `rotation(roll, pitch, yaw)`：末端執行器旋轉
- `linear(obj_a, obj_b)`：建立共線幾何約束
- `move_tracked_points()`：依關鍵點移動
- `close_gripper()` / `open_gripper()`：夾爪控制

**Step 4：建立幾何追蹤器（Geometry Tracker）**
設定視覺點擊介面，讓 LLM 能：
1. 在 RGB 影像上點選物件關鍵點
2. 自動建立 3D 對應
3. 持續追蹤跨影格的關鍵點位置

**Step 5：設計閉環驗證機制**
- 每次動作執行後，截取新影像並回傳給 LLM
- 設定失敗偵測條件（例如夾爪未閉合、目標位移超過閾值）
- 實作 retry / replan 邏輯

**Step 6：在 BEHAVIOR Challenge 2025 前 10 個任務上驗證**
從單一任務開始，逐步擴展到多任務，記錄 q-score 與成功率。

**Step 7：迭代 Prompt 與工具集**
根據失敗案例，補強工具（例如新增「對齊到平面」原語）或調整 system prompt。

## 潛在風險與注意事項

**風險 1：LLM 空間幻覺（Spatial Hallucination）**
LLM 可能誤判物件相對位置或距離。
*緩解對策*：強制要求 LLM 在執行前先呼叫 `get_3d_coord()` 取得精確座標，而非憑視覺直覺猜測。

**風險 2：推論延遲導致閉環失效**
LLM 單次決策可能耗時數秒，期間環境可能已改變。
*緩解對策*：對短時序子任務（如抓取）採用傳統控制器，僅在需要高階推理時呼叫 LLM；或使用更小的專用模型。

**風險 3：分布外泛化失敗**
BEHAVIOR 訓練過的物件組合可能無法涵蓋真實世界的多樣性。
*緩解對策*：保留 VLA 模型作為 fallback；對陌生物件啟用「探索模式」，讓 LLM 先嘗試簡單動作再規劃。

**風險 4：真實世界安全性**
模擬器中失敗僅損失時間，真實機器人可能損壞物品或傷人。
*緩解對策*：部署前必須在模擬器中完成大量 rollout；真實環境加入安全圍籬、力矩限制、緊急停止按鈕。

**風險 5：API 成本失控**
若每步都呼叫雲端 LLM，長任務成本可能飆升。
*緩解對策*：建立技能庫（類似 ASPIRE）快取成功子程序；對常見子任務使用規則式控制器。

**風險 6：幾何追蹤器漂移**
長時間操作後，關鍵點可能因遮擋或光線變化而丟失。
*緩解對策*：定期重新初始化追蹤；融合深度資訊提升穩定性。

## 與其他技術的整合建議

**與 VLA 模型互補**
對接觸豐富（contact-rich）子任務（如精細插銷、柔性物件操作），可呼叫 VLA 模型處理；對需要長程規劃的任務，由 RoboHarness 負責高階決策。建議設計一個「任務路由器」根據子任務特性分配。

**與經典運動規劃整合**
LLM 輸出高階意圖後，可丟給 MoveIt、Drake 或 OMPL 求解具體軌跡，避免 LLM 直接處理運動學細節。

**與世界模型整合**
若部署了世界動作模型（WAM），可在 LLM 規劃前先讓 WAM 預測動作結果，過濾明顯會失敗的方案。

**與多模態感知整合**
將 RoboHarness 的視覺點擊介面擴充為支援 SAM-2、Grounded-SAM 等開放詞彙偵測器，提升物件辨識的泛化能力。

**與 ROS 2 整合**
將工具集封裝為 ROS 2 服務 / Action，使其能與現有的機器人軟體生態互通，方便在真實硬體上部署。

**與技能庫系統整合**
參考 ASPIRE 的設計，將成功執行的子程序累積為可重用技能，逐步縮小 LLM 介入的頻率。
