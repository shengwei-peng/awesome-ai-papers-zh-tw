## ⚡ TL;DR

現有行動GUI代理程式基準測試缺乏真實性與複雜長期任務，且評估效率低落。
本文提出SimuWoB，以大型語言模型生成高擬真無後端網頁環境與自動獎勵驗證。

## 摘要翻譯

由大型語言模型（Large Language Model, LLM）驅動的行動 GUI 代理程式（Mobile GUI Agent）發展迅速，產生了對擬真且全面評估的迫切需求。現有的基準測試（Benchmark）雖優先考量可複現性（Reproducibility），但由於在真實應用程式上建構獎勵（Reward）的困難，常受限於開源應用程式（Open-Source App）或檔案操作任務（File-Operation Task），導致基準測試設定與真實世界使用之間存在落差。此外，大多數基準測試聚焦於基礎視覺定位（Vision Grounding）與導航（Navigation），對複雜長期互動（Long-Horizon Interaction）的涵蓋範圍有限。

為了因應這些限制，我們提出 SimuWoB，一個針對行動 GUI 代理程式的全合成基準測試（Synthetic Benchmark），包含 120 項涵蓋多種類型與難度等級的具挑戰性任務。我們建構了一個穩健的虛擬環境生成框架（Virtual Environment Generation Framework），能夠合成高保真（High-Fidelity）任務與環境，並為每項任務自動提供有效的獎勵（Reward）。每個環境均部署為可透過 URL 存取的無後端網頁（Backend-Free Webpage），實現高效且可複現的評估。

我們針對數個最先進的行動 GUI 代理程式進行全面實驗。平均成功率（Success Rate）僅有 27.92%，在長期任務（Long-Horizon Task）中更下降至 17.82%，顯示出現有代理程式在複雜情境下存在重大弱點。與真實世界樣本任務的評估結果比較顯示，基於我們合成環境的代理程式評估泛化效果良好。我們進一步針對關鍵能力面向提供診斷洞見，並探討對未來行動 GUI 代理程式發展的啟示。

### 核心貢獻（3～5點）
- 提出 SimuWoB，一個針對行動 GUI 代理程式的全合成基準測試，包含 120 項涵蓋多種類型與難度等級的具挑戰性任務，有效銜接基準測試與真實世界應用之間的落差。
- 建構穩健的虛擬環境生成框架，可自動合成高保真任務與環境，並為每項任務提供有效的獎勵，解決在真實應用程式上建構獎勵的困難。
- 將環境部署為可透過 URL 存取的無後端網頁，兼顧高擬真度與評估效率，並確保實驗的可複現性。
- 透過大規模實驗揭示現有最先進代理程式的重大弱點（平均成功率 27.92%，長期任務降至 17.82%），驗證合成環境評估可泛化至真實世界任務，並提供關鍵能力面向的診斷洞見。

### 適合對象
從事行動 GUI 代理程式、大型語言模型 / 視覺語言模型應用、人機互動與自動化測試研究的學者與工程師；特別是需要高保真、可複現且涵蓋長期互動之評估環境的基準測試研究者，以及希望診斷並提升代理程式在複雜多步驟任務上表現的開發者。

## 深度分析

#### 方法論解析

SimuWoB 的核心貢獻在於提出一套可擴展的虛擬環境生成框架（Virtual Environment Generation Framework），利用大型語言模型（Large Language Model, LLM）的程式碼生成（LLM Code Generation）能力，將自然語言描述的任務轉化為可執行、可驗證的合成應用程式（Synthetic App）環境。如圖 1 所示，整體流程採用迭代式生成與自動回饋迴圈：系統首先接收真實世界任務描述與選擇性的目標流程截圖，接著依序進行產品需求文件生成（Product Requirements Document Generation, PRD Generation）、頁面結構（Page Structure）設計、資源資料實體（Resource Data Entity）與模擬資料（Mock Data）建構，最終產出以無後端網頁（Backend-Free Webpage）形式部署的合成應用程式，並同步建立任務獎勵驗證器（Reward Validator）。

與傳統依賴開源應用程式（Open-Source App）或檔案操作任務（File-Operation Task）的基準測試（Benchmark）不同，此框架透過環境內部獎勵計算（Environment Internal Reward Calculation）自動產生可執行的獎勵函數（Reward Function），從而解決在真實世界行動應用程式（Real-World Mobile App）上建構獎勵（Reward）訊號的困難。在生成過程中，系統會驗證任務可解性（Task Solvability），確保自主代理程式（Autonomous Agent）能透過觀察（Observation）、動作（Action）與環境回饋（Environment Feedback）構成的閉環互動來完成目標。

最終部署的每個環境皆為可透過網址（URL）直接存取的無後端網頁，無需模擬器（Emulator）、虛擬裝置（Virtual Device）或 Docker 化系統（Dockerized System）即可運行。這種設計大幅消除了狀態載入（State Loading）與環境重置的運行開銷，使大規模平行評估與線上強化學習訓練（Online Reinforcement Learning Training）成為可能。在任務設計上，SimuWoB 將 120 個任務分為三大類：簡單任務、長期任務（Long-Horizon Task）與數學相關任務，其中半數任務需要超過 20 次互動步驟，最具挑戰性的任務甚至超過 50 步，顯著強化了對長期互動（Long-Horizon Interaction）、多步驟推理（Multi-Step Reasoning）與中間資訊管理（Intermediate Information Management）的壓力測試。

#### 實驗數據解讀

SimuWoB 共收錄 120 個任務，涵蓋 63 個合成應用程式環境，觸及 33 個 Google Play Store 類別中的 20 個。這些任務並非憑空設計，而是基於一項涵蓋 86 位參與者、橫跨 77 個產業的使用者研究，確保任務分布貼近真實使用場景。實驗評估了數個最先進（State-of-the-Art）的行動 GUI 代理程式（Mobile GUI Agent），結果顯示整體成功率（Success Rate）僅為 27.92%，而在長期任務子集上更降至 17.82%。

這組數據揭示了當前代理程式在複雜情境下的顯著弱點。首先，長期任務的表現落差（近 10 個百分點的下降）表明現有模型在處理超過 20 步的互動時，面臨嚴重的錯誤累積與規劃失效問題。其次，為了驗證合成環境的效度，作者選取 20 個真實世界樣本任務進行對比，證實基於合成環境的代理程式評估能夠良好地泛化（Generalize）到真實應用情境，這支持了 SimuWoB 作為真實世界代理程式能力代理指標（Proxy Metric）的可靠性。最後，論文針對關鍵能力維度提供診斷性見解，暗示當前代理程式在視覺定位（Vision Grounding）、導航（Navigation）之外的進階能力——如跨頁面資訊整合與長期記憶——仍有極大的提升空間。

#### 與現有研究的比較

現有的行動 GUI 代理程式基準測試大致可分為靜態資料集（Static Datasets）與互動式環境（Interactive Environments）兩類。靜態資料集雖具備可擴展性，但無法捕捉閉環互動動態（Closed-Loop Interaction Dynamics），例如從錯誤中恢復或狀態依賴的多步驟執行。互動式環境雖能量測端到端（End-to-End）成功與否，但多數依賴模擬器、虛擬裝置或 Docker 化系統來維持可複現性（Reproducibility），導致系統複雜度與運行開銷高昂，限制了評估速度與並行度。

更重要的是，既有研究為了確保獎勵函數的可靠性，往往受限於開源應用程式（可存取內部狀態）或檔案操作任務，抑或採用需要大量人工工程的執行模式匹配（Execution-Pattern Matching）。這些限制窄化了任務覆蓋率，並使基準測試任務與真實世界應用使用情境產生落差。SimuWoB 透過合成框架同時解決了這三大痛點：在真實性與多樣性上，它以高保真（High-Fidelity）方式模擬真實應用程式的互動邏輯；在任務複雜度上，它明確強調長期任務、複合式流程與重度推理工作負載；在評估效率上，無後端網頁的設計實現了近乎零設置成本的高速平行評估。

然而，SimuWoB 也存在固有的權衡與限制。由於環境是以前端網頁形式合成，而非原生作業系統層級的應用程式，某些系統層級互動（如通知欄操作、權限對話框、感測器事件）可能無法完整模擬。此外，雖然論文驗證了與 20 個真實任務的泛化一致性，但合成環境的資料分布仍由 LLM 生成，可能存在隱性的生成偏誤（Generation Bias），與真實世界行動應用程式的長尾分布（Long-Tail Distribution）存在差距。

#### 可重現性評估

SimuWoB 在可重現性（Reproducibility）方面的最大優勢來自其部署架構：每個環境皆為獨立的無後端網頁（Backend-Free Webpage），可透過統一資源定位器（URL）直接存取。這消除了傳統互動式基準測試中繁複的環境建置、系統依賴安裝與狀態重置流程，理論上只要具備瀏覽器即可復現評估結果。對於需要大規模反覆試驗的線上強化學習訓練（Online RL Training）而言，這種輕量化部署特性極具吸引力。

不過，根據目前提供的論文內容，尚未明確提及生成框架的原始碼、120 個任務的完整資料集、獎勵驗證器（Reward Validator）的實作細節，以及受測代理程式的模型權重（Model Weights）是否公開。若作者群後續開源虛擬環境生成框架與任務定義，將能讓研究社群不僅復現實驗結果，更能基於此框架擴充新的應用類別與任務，進一步放大 SimuWoB 的影響力。目前可確認的是，其「網頁即環境」的設計哲學在技術上已經大幅降低了第三方研究者進入的門檻。

#### 未來研究方向

基於 SimuWoB 的架構與實驗發現，未來研究可沿以下數個方向展開：

第一，**規模化與程序化生成（Procedural Generation）**。當前框架已展示利用大型語言模型（LLM）自動生成環境的可行性，未來可進一步發展為動態、無限擴展的任務產生器，自動創造涵蓋邊緣案例（Edge Cases）與對抗樣本（Adversarial Examples）的任務，以持續壓力測試代理程式的穩健性。

第二，**原生作業系統層級的模擬**。將合成環境從無後端網頁延伸至原生行動應用程式框架（如 Android/iOS 模擬層），納入系統通知、權限管理、多工切換等真實世界行動應用程式的複雜互動，縮小剩餘的模擬落差。

第三，**線上強化學習（Online RL）與自主改進**。SimuWoB 的高速評估特性非常適合作為線上強化學習訓練的環境。未來研究可探索代理程式在此合成環境中進行大規模試錯學習，並研究如何將學到的策略遷移至真實應用程式。

第四，**多模態觀察與可及性樹（Accessibility Tree）融合**。目前代理程式主要基於視覺觀察（Visual Observation）進行決策，未來可在 SimuWoB 中整合可及性樹、HTML DOM 結構或甚至自然語言的介面描述，評估不同觀察模態對長期任務與視覺定位（Vision Grounding）的影響。

第五，**跨平台擴展與多代理協作**。將虛擬環境生成框架從行動介面擴展至桌面圖形使用者介面（Desktop GUI）或網頁應用程式，並探索多個自主代理程式（Autonomous Agent）在同一合成環境中的協作與競爭行為，開啟更廣泛的人機互動研究。

## 論文問答

**Q1：SimuWoB 旨在解決現有行動 GUI 代理程式基準測試中的哪些核心問題？**

A：現有基準測試為了維持可複現性，往往只能使用開源應用程式或檔案操作任務，導致與真實世界行動應用程式的使用情境產生巨大落差。此外，多數基準測試僅聚焦於基礎的視覺定位與導航，缺乏對長期互動、多步驟推理與中間資訊管理等複雜能力的壓力測試。這些限制使得現有評估方式難以有效衡量代理程式在真實且複雜情境下的表現，也無法指引下一階段的技術發展。

**Q2：為何現有的互動式基準測試難以同時兼顧高擬真度與評估效率？**

A：許多現有的互動式基準測試依賴模擬器、虛擬裝置或 Docker 化系統來進行狀態載入與重置，這些設定雖然有效，卻大幅增加了系統複雜度與執行開銷。同時，在真實應用程式上建構自動化的獎勵函數極具挑戰性，因此研究者往往只能選擇內部狀態可取得的開源環境，或耗費大量人力進行執行模式匹配。這種工程上的權衡導致評估速度緩慢、任務覆蓋率狹隘，且難以大規模擴展至高保真的真實工作流程。

**Q3：為什麼建立能夠評估長期任務與複雜互動的基準測試對行動 GUI 代理程式的發展至關重要？**

A：隨著大型語言模型與視覺語言模型的能力快速進步，基準測試的難度必須相應提升，才能準確衡量代理程式的極限並提供有價值的評估結果。如果評估僅停留在簡單操作與短期任務，將無法辨識出強大代理程式的差異，也會讓長期執行中的失敗模式長期被忽視。SimuWoB 透過引入超過 50 步的長期任務，迫使代理程式展現長期規劃、記憶與穩定執行的能力，從而為未來的技術改進提供明確方向。

**Q4：SimuWoB 的核心技術框架如何生成高保真的合成應用程式環境？**

A：SimuWoB 建構了一個以大型語言模型程式碼生成能力為基礎的虛擬環境生成框架，能夠根據自然語言任務描述與目標流程的截圖，迭代地生成並精煉無後端網頁。這些網頁模擬真實行動應用程式的互動邏輯，並在模擬資料上運作，同時確保任務可解性與自動產生可執行的獎勵驗證器。整個過程無需連接真實應用程式的後端，就能創造出可透過 URL 存取、具備完整互動邏輯與狀態持久化的合成環境。

**Q5：SimuWoB 相較於傳統基準測試，在獎勵函數的設計與評估效率上有何關鍵創新？**

A：SimuWoB 最大的創新在於能夠自動為每個任務產生有效的獎勵函數，從而迴避了在真實應用程式上建構獎勵訊號的固有難題，顯著提升獎勵的可擴展性與可靠性。同時，由於每個環境都是無後端網頁並可透過 URL 部署，評估過程無需依賴笨重的模擬器或 Docker 容器，實現了近乎零設定成本的輕量化部署。這種設計不僅大幅提升了評估速度與平行化能力，也降低了大規模評估與線上強化學習訓練的運營成本。

**Q6：SimuWoB 在任務設計上為何區分簡單、長期與數學相關任務，且特別強調長期互動？**

A：這樣的分類是為了有系統地探測代理程式在不同能力維度上的表現，從基礎操作到需要多步驟推理與中間資訊管理的複雜流程。在 120 個任務中，有一半需要超過 20 次互動步驟，最困難的任務甚至超過 50 步，這對現有代理程式的長期規劃與記憶能力構成嚴峻考驗。透過明確區分任務類型，SimuWoB 能夠更精確地診斷代理程式的失敗模式，並針對長期任務中暴露的結構性弱點提供改進依據。

**Q7：SimuWoB 評估了哪些類型的行動 GUI 代理程式，其整體表現如何？**

A：研究團隊針對數個近期的最先進行動 GUI 代理程式進行了全面評估，這些代理程式涵蓋了模組化管線與端到端策略等不同架構。實驗結果顯示，所有代理程式在 120 個任務上的平均成功率僅有 27.92%，顯示即使在合成環境中，現有技術仍面臨巨大挑戰。這個低成功率凸顯了當前代理程式在處理多樣化且高保真任務時存在顯著的弱點，尤其是在需要複雜決策的情境下。

**Q8：在長期任務中，目前最先進的代理程式表現為何？這揭示了什麼樣的技術瓶頸？**

A：在長期任務子集上，代理程式的平均成功率進一步下降至僅 17.82%，顯示步驟數的增加對現有模型造成極大的壓力。這項結果揭示了當前代理程式在長期規劃、跨步驟的狀態追蹤與錯誤恢復能力上存在嚴重的結構性缺陷。由於長期互動正是真實世界應用中最常見且最具價值的場景之一，這樣的效能落差意味著現有技術距離實際部署仍有相當大的進步空間。

金融、電商、物流等產業常有複雜的多步驟操作流程（例如：預算內選購特定品牌商品、跨頁面填寫申請表）。透過合成框架生成對應的無後端網頁，可在數小時內建立可複現的評估環境，並自動產出獎勵函數，大幅降低建構真實後台與清理測試資料的工程成本。

### 實作步驟建議

**步驟一：需求收斂與任務定義**  
從目標產業收集真實任務，依照難度與類型分類（簡單操作、長期任務、數學推理等）。針對每項任務撰寫明確的自然語言描述，並標註預期完成狀態，作為後續獎勵函數的設計依據。

**步驟二：虛擬環境生成與迭代**  
將任務描述與可選截圖輸入 SimuWoB 的合成框架。利用大型語言模型進行程式碼生成，產出初始的無後端網頁。透過自動化回饋迴路檢查頁面結構、互動邏輯與模擬資料一致性，反覆精修直至高保真。

**步驟三：獎勵驗證器建置與任務可解性確認**  
針對每項任務開發自動化的獎勵驗證器，確認代理程式完成任務後能取得明確回饋。同時以人工或腳本執行「黃金路徑」測試，驗證任務可解性，避免環境本身存在邏輯死結。

**步驟四：代理程式整合與平行評估**  
將待測行動 GUI 代理程式對接至各合成應用程式的 URL。由於環境無需模擬器，可透過容器編排或無伺服器架構大規模平行執行評估，記錄觀察、動作軌跡與成功率。

**步驟五：真實世界對齊與泛化驗證**  
從真實世界行動應用程式中挑選 10–20 個對照任務，比較代理程式在合成環境與真實環境的表現差異。若發生顯著落差，回頭調整模擬資料的分布或互動細節，提升泛化能力。

**步驟六：持續維運與版本控制**  
將合成應用程式、獎勵函數與評估腳本納入版本控制。隨著真實 App 改版或業務流程異動，定期重新執行生成管線，確保基準測試與時俱進。

### 潛在風險與注意事項

**1. 合成環境與真實應用的語義落差**  
LLM 生成的無後端網頁可能在視覺風格、動畫過渡或異常處理上過度簡化，導致代理程式學到不具泛化性的捷徑。建議在生成階段加入真實 App 的截圖作為參考，並在評估後進行 sim-to-real 的樣本比對。

**2. 程式碼生成的穩定性與安全性**  
大型語言模型可能產生包含無窮迴圈、跨站腳本（XSS）漏洞或不相容前端框架的程式碼。實務上應將生成結果限制在純 HTML/CSS/JS 沙箱內，並於部署前執行靜態掃描與隔離測試。

**3. 獎勵函數過度擬合特定路徑**  
若獎勵驗證器僅檢查單一執行順序，可能將合法但非預期的替代路徑誤判為失敗。設計時應採用「狀態終態驗證」為主、「過程模式匹配」為輔的策略，保留合理的操作彈性。

**4. 長期任務的錯誤累積與評估雜訊**  
在超過 50 步的長期互動中，代理程式的微小失誤可能因環境狀態不可逆而被放大。建議為合成環境加入「狀態重置檢查點」與「復原機制」，以便區分「環境缺陷」與「代理程式能力不足」。

**5. 資料隱私與版權合規**  
若任務來自真實使用者行為日誌或第三方應用程式，需確保去識別化，且模擬資料不包含受版權保護的素材（如品牌商標、真實使用者頭像），避免法律風險。

### 與其他技術的整合建議

**與 CI/CD 管線整合**  
將 SimuWoB 環境部署為自動化測試階段的一環，每次代理程式版本更新後，平行執行 120 項標準任務，產出成功率與回歸報告，作為合併請求（Merge Request）的閘道條件。

**與容器編排平台整合**  
雖然合成環境為無後端網頁，仍可封裝於輕量容器（如 Nginx Alpine 映像檔）中，透過 Kubernetes 自動擴展，滿足夜間批次評估或強化學習的高併發需求。

**與現有代理程式框架整合**  
SimuWoB 的 URL 化設計使其能無縫對接現有開源行動 GUI 代理程式（如 AppAgent、SeeAct for Mobile）。只需將這些框架的觀察模組從「模擬器截圖」改為「網頁截圖」，動作模組從「ADB 指令」改為「網頁點擊/輸入」即可。

**與真實裝置農場（Device Farm）整合**  
建議採用「雙軌驗證」策略：先在 SimuWoB 合成環境中快速篩選代理程式版本，再將表現最佳的版本部署至真實裝置農場進行最終確認，兼顧評估效率與真實性。

**與資料分析平台整合**  
將代理程式的動作軌跡、中間資訊管理行為與獎勵訊號匯入資料倉儲，搭配視覺化儀表板，協助產品團隊定位代理程式在視覺定位、多步驟推理或導航上的具體弱點。
