## ⚡ TL;DR

自迴歸Transformer的垂直回饋通道狹窄，頂層隱藏狀態被丟棄，限制了非言語化計算。
提出全頻寬Transformer，透過GLU將頂層隱狀態與採樣token融合回傳，採排程多輪訓練。
1B模型訓練400B token，數學、程式與指令任務提升，且推理軌跡更短，逼近1.5倍資料標準模型。

## 摘要翻譯

自迴歸 Transformer（autoregressive transformer）沿著兩個軸向運算：水平跨越已生成的 token，垂直貫穿模型深度（model depth）。密集注意力（dense attention）使每個 token 能廣泛地水平存取（horizontal access）過去資訊，但解碼步驟之間的垂直回饋通道（vertical feedback channel）仍然狹窄：僅有採樣 token（sampled token）被送回堆疊底部，而頂層隱藏狀態（top-layer hidden state）則被捨棄。我們提出全頻寬 Transformer（full-bandwidth transformer），透過潛在回饋（latent feedback）來拓寬此通道：在每個解碼步驟中，前一步的頂層隱藏狀態會透過門控線性單元（gated linear unit, GLU），與採樣 token 嵌入（sampled token embedding）融合，並回饋作為下一個輸入。潛在回饋讓非言語化計算（non-verbalized computation）得以重新進入堆疊，並獲得重新獲得的深度預算（depth budget），同時保留標準 Transformer 架構、KV 快取（KV cache）與語言建模目標（language-modeling objective）。為了在不喪失並行教師強制（teacher forcing）訓練的前提下訓練全頻寬 Transformer，我們採用排程多輪目標（scheduled multi-pass objective），在預訓練（pretraining）後期引入潛在回饋，並混入少量較深的回饋傳遞（feedback pass）以確保穩定性。我們訓練了 10 億參數（1B-parameter）的全頻寬 Transformer，最多達 4000 億訓練 token（400B training tokens），並發現潛在回饋能改善驗證損失（validation loss）、5-shot 語言模型評估（5-shot language-model evaluation）、數學與程式碼生成，以及指令微調效能（instruction-tuned performance）。在每個 token 解碼開銷（per-token decoding overhead）可忽略的情況下，全頻寬 Transformer 能夠媲美或接近使用約 1.5 倍訓練 token（training tokens）量訓練的標準 Transformer，並在相同或更高的準確率下產生更短的推理軌跡（reasoning trace）。

### 核心貢獻（3～5點）
- 指出自迴歸 Transformer 在解碼步驟間的垂直回饋通道狹窄：僅有採樣 token 被回傳，頂層隱藏狀態遭丟棄，限制了非言語化計算的利用。
- 提出全頻寬 Transformer，透過潛在回饋將前一步頂層隱藏狀態經門控線性單元與採樣 token 嵌入融合後回饋為下一輸入，擴寬垂直通道，同時保留標準架構、KV 快取與語言建模目標。
- 設計排程多輪目標，在預訓練後期引入潛在回饋並混入少量較深回饋傳遞，使模型能在不喪失並行教師強制訓練的情況下學習潛在回饋。
- 在 10 億參數、4000 億訓練 token 規模上驗證，潛在回饋可改善驗證損失、5-shot 語言模型評估、數學與程式碼生成及指令微調效能，且每個 token 解碼開銷可忽略，能媲美約 1.5 倍 token 訓練的標準 Transformer，並產生更短的推理軌跡。

### 適合對象
適合對大型語言模型架構、自迴歸解碼機制、推論效率與隱式推理感興趣的研究者與工程師；特別是關注如何在不改變標準 Transformer 主體與 KV 快取的前提下，透過擴寬垂直回饋通道來提升模型能力並縮短推理軌跡的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心問題：垂直回饋通道（vertical feedback channel）過窄
自迴歸 Transformer（autoregressive transformer）在解碼時同時沿兩條軸線運算：**水平方向（horizontal access）**透過 dense attention（密集注意力）讓當前 token 存取過去所有位置的 key/value；**垂直方向（vertical feedback channel）**則把上一個解碼步驟的資訊送回模型底部。然而，現有標準解碼的垂直通道極度狹窄：頂層隱藏狀態（top-layer hidden state）\(h^L_{t-1}\) 被丟棄，僅保留採樣 token（sampled token）的嵌入（token embedding）\(e_{t-1}\) 作為下一步輸入。這相當於把一個 \(D\) 維的豐富狀態壓縮成 \(\log |V|\) bits 的離散符號，導致非言語化計算（non-verbalized computation）無法回到模型底部重新獲得深度預算（depth budget），只能「凍結」在 KV 快取（KV cache）中對應層級以上的位置。

##### 2. Latent feedback（潛在回饋）機制
Full-bandwidth transformer（全頻寬 Transformer）透過 **latent feedback（潛在回饋）** 把垂直通道擴展到完整隱藏狀態寬度。具體而言，在每一步解碼時，模型將上一個頂層隱藏狀態（top-layer hidden state）與當前採樣 token（sampled token）的嵌入（token embedding）透過一個門控線性單元（gated linear unit, GLU）融合，再作為下一個輸入：

\[
\tilde{e}_t = \text{GLU}(h^L_{t-1}, e_{t-1})
\]

其中 token 嵌入作為 gate，頂層狀態走在 value 路徑上。這個融合是維度保留（dimension-preserving）的，因此不會改變 Transformer 主體架構，也不影響 KV 快取（KV cache）的結構。由於採樣 token 仍然保留，模型依舊輸出普通文字，並可使用標準語言建模目標（language-modeling objective）進行訓練。

此設計帶來兩項關鍵能力：
- **非言語化狀態可再次進入淺層**：不確定性、部分結果、規劃等資訊可隨 hidden state 回到模型底部，獲得新的深度預算（depth budget）進行跨步驟處理。
- **每一層都能看見「完整堆疊處理過的過去」**：標準解碼中，淺層只能看到過去經由更淺層處理的表徵；latent feedback（潛在回饋）讓淺層也能接觸到頂層對歷史的抽象。

##### 3. 訓練：Scheduled multi-pass objective（排程多輪目標）
直接對遞迴結構做 teacher forcing（教師強制）會喪失平行訓練的優勢。作者提出 **scheduled multi-pass objective（排程多輪目標）**：
- 每一輪（pass）把上一輪的隱藏狀態向右平移一個位置，與 token 嵌入融合後，再平行地重新跑完整個堆疊。
- 序列性成本被轉移到少數幾輪回饋傳遞（feedback pass）上，而非橫跨整個序列長度。

為了讓訓練穩定，設計了兩個關鍵技巧：
- **Progressive schedule（漸進排程）**：訓練前期使用普通單輪目標，讓模型先學到標準語言模型表徵；後期才引入額外的 feedback pass（回饋傳遞）。這也意味著可以從標準預訓練（pretraining）檢查點繼續訓練。
- **Prefix mixin（前綴混合）**：隨機決定序列中哪些位置開始使用融合輸入，以模擬推論時「先 prompt、後生成」的結構。

值得注意的是，作者發現 **feedback pass（回饋傳遞）數量的組合** 對穩定性有非直觀影響：僅用兩輪回饋訓練時，遞迴在超過訓練深度後會發散；但只要混入約 3% 的三輪批次，學到的映射就會變成收斂到固定點（contraction toward a fixed point），在超過訓練深度時仍保持穩定。這暗示 latent feedback（潛在回饋）的動態行為對訓練分布非常敏感。

##### 4. 推論開銷
方法對標準 Transformer 架構的改動極小：
- 每生成一個 token 僅增加兩個矩陣乘法（融合 gate）。
- Attention 與 KV 快取（KV cache）完全保留。
- Prefill（前綴編碼）可只跑一次，或選擇跑兩次以獲得更好表現。

因此 per-token decoding overhead（每個 token 解碼開銷）幾可忽略，這是相較於許多遞迴或迭代方法的重要優勢。

#### 實驗數據解讀

##### 1. 設定與規模
作者訓練了 **1B 參數（parameter）** 的 full-bandwidth transformer（全頻寬 Transformer），訓練量高達 **400B tokens（training token）**。對照組為相同大小的標準 Transformer，但使用約 1.5×、2×，甚至最高 5× 的訓練 token 數量。這樣的設計直接檢驗「以少量額外計算換取資料效率」的假說。

##### 2. Validation loss（驗證損失）
實驗顯示，使用多次 forward pass 進行 prefill 的 full-bandwidth transformer（全頻寬 Transformer），其 validation loss（驗證損失）可與訓練了 **2× tokens** 的標準 Transformer 相當。這表示 latent feedback（潛在回饋）確實讓模型從相同資料中提取到更豐富的學習訊號，或等價地說，達到相同 loss 所需的資料量大幅減少。

##### 3. 下游任務
在 5-shot language-model evaluation（5-shot 語言模型評估）、數學生成（GSM8K、Math500）、程式生成（HumanEval、MBPP）以及指令微調（instruction tuning）後的表現上，latent feedback（潛在回饋）均帶來提升：
- 與相同權重的標準解碼相比，free-form generation（自由形式生成）在每個任務上都有進步。
- 可與 **2× token** 的標準 Transformer 基線匹敵。
- 在某些任務上甚至接近 **5× token** 基線。

這說明 latent feedback（潛在回饋）的優勢不僅反映在 perplexity 上，也轉化為實際的推理與生成能力。

##### 4. 推理軌跡（reasoning trace）長度
在 base model（基礎模型）上，latent feedback（潛在回饋）經常能在維持或提升準確率的同時，產生**更短的 reasoning trace（推理軌跡）**。這與方法論的預測一致：當非言語化計算（non-verbalized computation）可以透過 hidden state 傳遞時，模型就不需要把每個中間步驟都 verbalize（言語化）成 token。這對降低推論延遲與改善可讀性都有潛在價值。

##### 5. 綜合意義
整體而言，實驗呈現出一條清晰的「計算換資料」曲線：full-bandwidth transformer（全頻寬 Transformer）以幾乎可忽略的額外推論計算，達到需要 1.5×–2× 資料訓練的標準 Transformer 效果。在資料品質與獨特資料日益稀缺的背景下，這種提升資料效率的方向極具吸引力。

#### 與現有研究的比較

##### 1. 相較於標準自迴歸 Transformer（autoregressive transformer）
標準 Transformer 的 dense attention（密集注意力）已經提供強大的水平存取（horizontal access），但垂直回饋通道（vertical feedback channel）被限制在單一 token。Full-bandwidth transformer（全頻寬 Transformer）在不改變 attention、KV 快取（KV cache）與語言建模目標（language-modeling objective）的前提下，把垂直通道擴展到完整 hidden-state 寬度，屬於「最小侵入式」的改進。

##### 2. 相較於 Chain-of-Thought（CoT）解碼
思維鏈解碼（chain-of-thought decoding）透過生成更多 token 來增加有效模型深度（model depth），但本質上仍依賴 verbalization（言語化）作為跨步驟資訊傳遞媒介。Full-bandwidth transformer（全頻寬 Transformer）讓部分計算「隱藏」在 hidden state 中傳遞，因此能在更短的 reasoning trace（推理軌跡）下達到相同或更好的準確率。這可視為對 CoT 的補充，而非取代。

##### 3. 相較於 RNN 與 State-Space Model（SSM）
RNN 與 SSM 透過固定大小的 recurrent state（遞迴狀態）壓縮歷史，但通常犧牲 dense attention（密集注意力）帶來的豐富水平存取（horizontal access）。Full-bandwidth transformer（全頻寬 Transformer）保留了完整的 attention 與 KV 快取（KV cache），同時只增加一條輕量的頂層回饋路徑，因此在記憶體與表達能力之間取得了不同權衡。

##### 4. 相較於其他迭代/多輪計算方法
許多研究透過多次 forward pass 或 depth recursion 來增加每個位置的計算量，但往往伴隨顯著的訓練或推論成本，且需要特殊損失函式或架構改動。Full-bandwidth transformer（全頻寬 Transformer）的優勢在於：
- 幾乎不改變標準 Transformer 架構。
- 每個 token 的額外計算極小。
- 可使用標準預訓練（pretraining）檢查點作為起點。

##### 5. 限制
- **規模**：目前僅在 1B 參數（parameter）模型上驗證，尚未證明在更大規模（如 7B、70B）上仍保持相同效率。
- **訓練複雜度**：Scheduled multi-pass objective（排程多輪目標）需要仔細安排 feedback pass（回饋傳遞）數量與比例，否則可能出現發散。
- **理論理解有限**：雖然觀察到混入三輪批次可帶來收斂（contraction），但對固定點動態、長期穩定性與泛化邊界仍缺乏嚴謹分析。
- **應用範圍**：目前僅針對 decoder-only 語言模型，對多模態或編碼器-解碼器架構的適用性未知。

#### 未來研究方向

##### 1. 規模化驗證
在 1B 參數（parameter）上觀察到的資料效率優勢，是否能在 7B、70B 甚至更大模型上維持，是最優先的問題。特別是當模型容量增加時，latent feedback（潛在回饋）帶來的邊際效益可能上升也可能遞減。

##### 2. 自適應回饋深度
目前使用固定或排程的 feedback pass（回饋傳遞）數量。未來可探索**自適應**機制：讓模型根據輸入難度或當前不確定性，動態決定是否需要額外的 latent feedback（潛在回饋）輪數，以在簡單樣本上節省計算、在困難樣本上增加推理。

##### 3. 與推論加速技術結合
Full-bandwidth transformer（全頻寬 Transformer）的額外計算極小，可與 speculative decoding（推測解碼）、KV 快取（KV cache）量化、early exiting 等技術疊加，進一步降低推論成本。

##### 4. 理論分析
需要更深入理解 latent feedback（潛在回饋）的動態：
- 固定點（fixed point）存在的條件。
- 長序列穩定性與收斂速率（contraction rate）。
- 與標準 Transformer 在表達能力上的形式化關係。

##### 5. 應用於推理模型與長上下文
由於 latent feedback（潛在回饋）能縮短 reasoning trace（推理軌跡），可進一步研究其在需要多步規劃、工具使用或長上下文推理任務上的效果。此外，長上下文擴展（long-context extension）後的表現也值得持續追蹤。

##### 6. 多模態與其他架構
目前僅限於文字 decoder-only 模型。未來可將 full-bandwidth transformer（全頻寬 Transformer）的概念延伸至視覺-語言模型、語音模型或編碼器-解碼器架構，探索跨模態的 latent feedback（潛在回饋）。

##### 7. 替代融合機制
除了 GLU，可研究其他融合頂層隱藏狀態（top-layer hidden state）與 token 嵌入（token embedding）的方式，例如 cross-attention、low-rank fusion 或學習型 gate，以進一步優化效率與表現。

## 論文問答

**Q1：標準自迴歸 Transformer 在解碼過程中的「垂直回饋通道」存在什麼根本問題？**
A：標準自迴歸 Transformer 雖然透過密集注意力機制讓每個 token 能水平存取過去序列，但跨解碼步驟的垂直回饋通道卻非常狹窄：只有採樣 token 的嵌入會回到模型最底層，而頂層隱藏狀態則被直接丟棄。這意味著模型必須將所有中間計算結果壓縮到單一 token 中，才能讓資訊重新進入堆疊獲得新的深度預算。因此，非言語化的計算狀態會被「深度凍結」在 KV 快取中，無法回到底層進行進一步處理。

**Q2：為什麼單純增加 KV 快取無法解決上述問題？**
A：KV 快取雖然保存了過去 token 的鍵值狀態，但這些中間活化具有層級限制：在層 ℓ 產生的狀態只能被其上方的層讀取，永遠無法回到最底層重新處理。頂層輸出更是從未被快取，導致最深的計算結果無法跨步驟傳遞。因此，模型若要讓過去計算重新進入處理流程，只能透過 verbalization（即生成額外 token），這會浪費詞彙容量並增加序列長度。

**Q3：在資料品質逐漸受限的背景下，全頻寬 Transformer 為何重要？**
A：傳統縮放法則主要依賴增加參數與訓練 token 數量，但高品質獨特資料的稀缺性使得單純堆疊資料變得不可持續。全頻寬 Transformer 提供了一條新的縮放軸線：在不大幅改變架構的前提下，從每個 token 中提取更多計算與學習訊號。這讓模型能夠透過潛在回饋進行非言語化的深度推理，而不必完全依賴更多訓練資料。

**Q4：全頻寬 Transformer 的核心機制「潛在回饋」是如何運作的？**
A：潛在回饋在每次解碼步驟中，將前一步的頂層隱藏狀態與當前採樣 token 的嵌入進行融合，並透過門控線性單元將結果回饋為下一步的輸入。具體而言，頂層狀態作為 value 路徑，採樣 token 作為 gate，兩者結合後維持與殘差流相同的維度。這樣一來，完整的隱藏狀態資訊得以回到模型底層，使後續計算能夠存取經過完整堆疊處理後的過去表徵。

**Q5：相較於標準 Transformer，潛在回饋帶來了哪兩項關鍵優勢？**
A：首先，非言語化的計算狀態（如不確定性、部分結果、計畫）可以重新進入堆疊底層並獲得新的深度預算，而不必凍結在原本產生的層級。其次，包括最淺層在內的每一層都能看見經過完整模型深度處理後的過去，而非僅能存取其下方層次的資訊。這兩項優勢讓模型能夠在隱藏狀態中進行更豐富的跨步驟計算，減少對額外生成 token 的依賴。

**Q6：為什麼訓練全頻寬 Transformer 需要「排程多輪目標」，而非直接使用教師強制？**
A：潛在回饋定義了一個跨位置的遞迴關係，若直接訓練會喪失 Transformer 引以為傲的平行教師強制效率。排程多輪目標透過將前一轮的隱藏狀態向右平移一個位置，再與 token 嵌入融合後重新平行運行整個堆疊，把序列性成本分散到少數幾輪傳遞中。此外，漸進式排程讓模型先以標準單輪目標預訓練，後期才引入回饋傳遞，並透過前綴混合隨機化融合輸入的起始位置，以貼近推論時的提示到生成結構。

**Q7：實驗中發現，訓練穩定性與回饋傳遞輪數的組合有何意外關聯？**
A：研究發現單純使用兩輪回饋傳遞訓練時，模型一旦在推論時展開超過訓練深度的步數就會發散。然而，只要在批次中混入僅 3% 的三輪傳遞，學習到的映射就會轉變為朝向固定點收縮的動態，從而在訓練深度之外仍保持穩定。這顯示回饋深度的組合對學習穩定遞迴至關重要，並非單純增加傳遞輪數就一定更好。

**Q8：全頻寬 Transformer 在哪些基準測試上展現了顯著改進？**
A：研究團隊訓練了 10 億參數的模型達 4000 億 token，發現潛在回饋改善了驗證損失、5-shot 語言模型評估、數學與程式碼生成任務，以及指令微調後的表現。在 GSM8K、Math500、HumanEval 與 MBPP 等自由形式生成任務上，潛在回饋不僅優於相同權重的標準解碼，還能匹配使用兩倍 token 訓練的基線，部分任務甚至接近五倍 token 基線。這些增益也會延續到長上下文擴展與指令微調之後。

**Q9：全頻寬 Transformer 的推理軌跡長度與準確度之間呈現什麼關係？**
A：實驗顯示，在基礎模型上啟用潛在回饋後，模型經常能產生明顯更短的推理軌跡，同時維持相同甚至更好的準確度。這與機制設計的預測一致：當非言語化計算可以透過隱藏狀態傳遞時，模型就不需要將每個中間步驟都 verbalize 成 token。這項特性對於降低服務延遲與減少冗長輸出特別有價值。

**Q10：在實際部署中，全頻寬 Transformer 的額外推論開銷為何？**
A：全頻寬 Transformer 的每個 token 解碼開銷幾乎可以忽略不計，因為融合操作僅增加兩個矩陣乘法，而注意力機制與 KV 快取都保持不變。Prefill 階段可以只運行一次，也可以選擇運行兩次以獲得更好的表現。這使得該方法在生產環境中易於部署，不會像許多遞迴或迭代方法那樣帶來顯著的延遲或記憶體負擔。

**Q11：從產品化角度來看，全頻寬 Transformer 相較於其他回饋式或迭代式模型有何優勢？**
A：全頻寬 Transformer 保留了標準 Transformer 的架構、KV 快取與語言建模目標，因此可以從現有的預訓練檢查點開始訓練，並與現有的推論基礎設施高度相容。它不需要設計特殊的狀態壓縮機制或改變注意力結構，降低了整合門檻。對於已經投資大量標準 Transformer 基礎設施的產品團隊而言，這是一種低風險的效能提升途徑。

**Q12：全頻寬 Transformer 對大型語言模型領域的縮放策略可能帶來什麼影響？**
A：這項工作挑戰了「提升效能只能依靠更多參數與更多資料」的傳統假設，開啟了「每個 token 分配更多計算」這條新的縮放軸線。透過潛在回饋，模型能夠在固定資料量下提取更豐富的學習訊號，這對於資料日益稀缺的未來尤其重要。長遠來看，這可能促使社群重新思考自迴歸架構中計算與通訊通道的設計權衡。

**Q13：本文承認全頻寬 Transformer 有哪些主要限制？**
A：本研究主要在 10 億參數規模與最多 4000 億 token 的設定下進行驗證，尚未在更大規模模型上確認效果是否同樣顯著。此外，排程多輪目標的訓練流程比標準預訓練更複雜，需要仔細調整回饋傳遞的引入時機與比例。這些因素意味著在將方法推廣到更大模型或不同領域時，仍需進一步研究與工程驗證。

**Q14：訓練過程中出現了什麼具體的失敗案例，作者如何解決？**
A：當模型僅以兩輪回饋傳遞訓練時，在推論階段一旦展開超過訓練所見深度就會出現發散現象，這是一個明確的失敗案例。作者發現只要在訓練批次中混入少量三輪傳遞（約 3%），就能讓遞迴動態轉變為收縮映射，從而穩定地外推到更長序列。這個發現凸顯了設計訓練目標時，必須同時考慮訓練穩定性與推論時的動態行為。

**Q15：未來研究可以從哪些方向延伸全頻寬 Transformer？**
A：未來可以將潛在回饋機制擴展到更大規模的模型，並探索不同的融合函數或門控設計是否能進一步提升表現。另一個方向是研究如何與其他推論效率技術（如推測解碼、量化或稀疏注意力）結合，以在保持低開銷的同時獲得更大增益。此外，深入理解潛在回饋在長上下文、多輪對話與複雜規劃任務中的動態行為，也是值得探索的課題。

## 實務應用指南

### 適用場景

1. **數學與程式輔助系統**  
   全頻寬 Transformer 能將部分中間計算「藏」在潛在回饋中，產生更短的推理軌跡卻維持甚至提升正確率，特別適合 GSM8K、Math500、HumanEval、MBPP 等需要多步推論的數學與程式生成場景。

2. **長文件摘要與多輪對話**  
   透過頂層隱藏狀態回傳到輸入層，模型可在不同解碼步驟間持續壓縮與更新非言語化語境，減少重複贅述，適合長上下文摘要、客服對話與個人助理。

3. **資料稀缺領域的預訓練**  
   論文顯示潛在回饋可達到約 1.5× 訓練 token 的資料效率，對於高品質領域資料有限（如法律、醫療、科學文獻）的場景，可在不顯著擴增資料下提升模型能力。

4. **邊緣或低延遲推論服務**  
   每個 token 的解碼開銷極低（僅增加兩次矩陣乘法），且 KV 快取與標準 Transformer 相同，適合在延遲敏感或記憶體受限的部署環境中取代標準解碼。

5. **指令微調後的對話模型**  
   潛在回饋的增益可延續到指令微調階段，適合已經過 SFT/RLHF 的產品級聊天機器人，用來改善跟隨指令、減少冗長回覆並提升多輪一致性。

---

### 實作前置條件

- **資料**：需要大規模高品質預訓練語料（論文使用 400B token 等級），並保留標準語言建模目標；若要做指令微調，需準備常見的指令對與偏好資料。
- **運算**：至少需能執行 1B 參數模型預訓練的叢集；由於採用排程多輪目標，後期會引入額外回饋傳遞，需預留約 10–30% 的訓練 FLOPs 彈性。
- **模型起點**：建議從已預訓練好的標準 Transformer 檢查點出發，因為潛在回饋必須在訓練後期才引入，避免模型從未見過隱藏狀態輸入。
- **技術能力**：需熟悉 Transformer 解碼迴路、KV 快取實作、門控線性單元（GLU）、分散式訓練框架（如 Megatron-LM、FSDP），以及能修改推論引擎（vLLM、TGI 或自研引擎）的工程能力。
- **評估工具**：需準備 5-shot 語言模型評估、數學/程式生成基準（GSM8K、Math500、HumanEval、MBPP）與推理軌跡長度監控。

---

### 實作步驟建議

1. **建立基座與資料流程**  
   從標準自迴歸 Transformer 預訓練檢查點開始，確認資料管線支援教師強制與多輪前向傳播。

2. **修改解碼迴路：加入潛在回饋**  
   在每一步解碼時，將上一個頂層隱藏狀態與採樣 token 的嵌入透過門控線性單元融合，作為下一個輸入。公式可寫為：  
   \[
   e_t = \text{GLU}(h_{t-1}^{\text{top}}, \text{Embed}(x_{t-1}))
   \]  
   保持維度不變，KV 快取與注意力機制完全保留。

3. **實作排程多輪目標**  
   前段訓練使用標準單輪目標；後期逐步引入第二輪回饋傳遞，並混合約 3% 的三輪批次，以確保遞迴在超過訓練深度時仍收斂。

4. **加入 Prefix Mix-in**  
   在序列中隨機決定融合輸入從何處開始，模擬真實推論時「先 prompt、後生成」的結構，避免訓練與推論分佈不一致。

5. **穩定性與收斂監控**  
   除了驗證損失，還要監控超過訓練深度時的隱藏狀態發散情形；若發現遞迴不穩定，增加三輪批次比例或降低回饋學習率。

6. **推論優化**  
   Prefill 可選擇執行一次或兩次以提升效能；解碼階段僅增加兩個矩陣乘法，幾乎無額外開銷。確保 KV 快取管理程式無需大幅改動。

7. **評估與產品化迭代**  
   在基座模型上比較驗證損失、5-shot 準確率、數學/程式生成與推理軌跡長度；接續進行指令微調，並在真實使用者查詢上進行 A/B 測試。

---

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **遞迴發散** | 僅用兩輪回饋訓練時，模型在超過訓練深度的序列上可能發散。 | 混合至少 3% 的三輪批次，讓隱藏狀態映射趨向固定點。 |
| **訓練/推論分佈偏移** | 預訓練模型從未在輸入中見過頂層隱藏狀態，直接開啟回饋會失效。 | 從標準檢查點出發，後期才引入潛在回饋，並使用 prefix mix-in。 |
| **可解釋性下降** | 部分計算改走非言語化通道，難以透過生成文字追蹤。 | 保留採樣 token 通道，並在關鍵應用中保留可選的思維鏈輸出。 |
| **與現有推論優化衝突** | 潛在回饋改變了解碼迴路，可能影響投機解碼、量化或連續批處理。 | 在修改的推論引擎上重新驗證正確性與延遲，必要時對隱藏狀態與嵌入使用相同量化策略。 |
| **調度過早引入回饋** | 過早使用多輪目標會喪失平行教師強制的效率並造成不穩定。 | 嚴格執行「後期引入、少量深層傳遞」的排程。 |

---

### 與其他技術的整合建議

- **現有 Transformer 服務框架**：可在 vLLM、TGI 或自研 C++ 推論引擎中，於解碼迴路層插入 GLU 融合模組；KV 快取管理與連續批處理邏輯幾乎無需改動。
- **參數高效微調（PEFT）**：潛在回饋的額外參數極少，可與 LoRA、DoRA 等技術並用；建議在指令微調時同時微調回饋閘控權重。
- **思維鏈與工具使用**：可將潛在回饋視為「內部草稿」，外部仍保留選擇性思維鏈或工具呼叫；對於需要可稽核性的場景，可設定閾值切換回標準文字化推理。
- **推論加速技術**：投機解碼需適配回饋狀態的傳遞；建議先在小規模驗證其正確性，再部署到生產環境。
- **評估與監控平台**：將隱藏狀態範數、回饋固定點距離與推理軌跡長度納入持續監控，作為模型漂移的早期指標。

### 給不同背景讀者的閱讀建議

- **初學者**：先聚焦圖 1 的直覺——標準 Transformer 每次只能把「一個 token」傳回輸入層，而全頻寬 Transformer 把「整層隱藏狀態」傳回去，讓模型可以「用想的」而不必「全部說出來」。理解這個比喻後，再回頭看門控線性單元與排程多輪目標。

- **AI 工程師**：重點閱讀潛在回饋的實作細節（第 3.1 節）、排程多輪目標與 prefix mix-in（第 3.3 節），以及推論開銷分析。實作時優先修改解碼迴路與訓練腳本，並確保三輪批次比例足夠以避免發散。

- **研究人員**：深入探討遞迴穩定性與固定點行為，特別是「兩輪發散、三輪收斂」的現象。可進一步研究潛在回饋與縮放法則的關係、在不同模型規模與上下文長度下的動態，以及與迴圈/迭代計算模型的理論聯繫。

- **產品經理**：關注成本效益與使用者體驗——全頻寬 Transformer 以極低推論開銷換取約 1.5× 訓練資料的效能，並能縮短推理軌跡。評估時應同時看準確率、延遲、輸出長度與可解釋性需求，優先在數學、程式與長對話場景試點。
