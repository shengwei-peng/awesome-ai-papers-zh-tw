本文提出 NESTONE 框架，核心目標是將大型語言模型（LLM）轉化為高效的系統一（System One）決策模型，並透過自適應計算（Adaptive Computation）降低推論成本。以下從問題動機、關鍵發現、與方法設計三個層面進行解析。

**問題動機與核心觀察**

傳統做法是將 LLM 的語言模型頭（Language Modeling Head）替換為決策頭（Decision Head），但保留完整的骨幹網路（Backbone），導致每次決策都必須遍歷所有層。以 Qwen3.5-4B 為例，32 層模型在批次大小為 1 時每層延遲約 1.45 毫秒，總延遲相當可觀。本文的核心問題是：系統一決策究竟需要多少計算深度（Computational Depth）？

**關鍵發現（Section 3）**

作者透過兩類分析揭示決策資訊的分佈特性：

1. **層級歸因分析（Layer Attribution）**：使用整合梯度（Integrated Gradient）歸因法定位決策資訊在骨幹網路中的分佈。結果顯示，50% 的決策資訊在第 20 層已建立，80% 在第 23 層完成，證明決策計算高度集中於中間層（Intermediate Layers）。

2. **消融實驗（Ablation Study）**：移除第 24–29 層（最終層）不影響準確率，但消融第 15–23 層則完全消除決策邊際（Decision Margin），說明早期層（Early Layers）負責建立基礎特徵，而最終層（Final Layers）對決策而言是冗餘的。

3. **獨立訓練小模型分析**：獨立訓練的較小模型有 89–92% 的正確決策已被完整模型做出，且其獨特勝出僅比完整模型的種子（Seed）不一致高出 2–3 個百分點，主要集中在低信心度決策。這意味著獨立訓練的小模型並未發展出專門化決策能力（Specialized Decision Capabilities），而是傾向於複製完整模型的行為。

**NESTONE 框架設計**

基於上述發現，作者提出三項設計原則：

1. **巢狀多深度訓練（Nested Multi-Depth Training）**：在單一訓練過程中，同時訓練完整模型與多個前綴子模型（Prefix Sub-models），這些子模型共享最終層與決策頭，實現共享計算（Shared Computation）。

2. **自蒸餾（Self-Distillation）**：完整模型作為教師，將決策監督（Decision Supervision）與自蒸餾損失結合，使子模型在較淺深度即可逼近完整模型的決策分佈。

3. **輕量級停止閘（Lightweight Stop Gate）**：在每個出口（Exit）位置，閘控機制（Gate）讀取隱藏狀態（Hidden State）並判斷是否需要繼續計算，從而支援自適應深度分配（Adaptive Depth Allocation）。

此設計的關鍵優勢在於：一次訓練即可產出多個深度的有效模型，並透過閘控機制在推論時動態選擇計算深度，避免固定深度推論（Fixed-Depth Inference）對所有輸入施加相同計算預算（Computational Budget）的浪費。

Jeva、Prism-1、Consider-then-Choose 等方法改變選項讀取方式以提升決策品質，但同樣保留完整深度。NESTONE 與這些方法正交，可與之組合使用。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於將大型語言模型（LLM）轉化為系統一（System One）決策模型時所產生的效率問題。現有的做法是將語言模型頭替換為決策頭，但保留完整的骨幹網路，導致每一次決策都必須跑完整個模型的所有層次，造成不必要的推論成本。論文的核心問題在於探問：對於單次決策而言，究竟需要多少計算深度？這是一個在先前文獻中未被系統性檢視的根本問題。

**Q2：為什麼現有方法（單純截斷骨幹或訓練更小的模型）無法有效解決這個問題？**
A：單純截斷骨幹網路會造成效能急劇下降，例如從 32 層縮減到 24 層尚可維持效能，但進一步縮減到 16 層或 12 層時，準確率會從 84.3% 驟降至 72.8% 甚至 61.5%。另一方面，獨立訓練較小的模型並不會發展出專門化的決策能力，反而傾向於模仿完整模型的行為——其 89–92% 的正確決策已被完整模型做出，且相較於完整模型的種子差異僅多出 2–3 個百分點的差異化勝率。這顯示僅靠縮小模型或截斷骨幹並不足夠，真正的效率提升需要讓模型能在不同深度下都做出可靠的決策。

**Q3：為什麼這項研究在實務上很重要？**
A：基於 LLM 的代理在執行長思維鏈推理的同時，也需要頻繁進行輕量級決策，例如路由請求、工具選擇、標記不安全提示與意圖識別等。這些任務通常在嚴格的延遲限制下執行，而固定深度推論對所有輸入施加相同的計算預算，無論該決策是簡單或困難。因此，自適應深度分配不僅能降低推論成本，也能在維持準確率的前提下提升整體系統的回應速度，對於實際部署的 LLM 代理系統具有關鍵意義。

**Q4：NESTONE 方法的核心機制是什麼？**
A：NESTONE 是一個巢狀多深度訓練框架，它將完整的模型與多個前綴子模型聯合訓練，這些子模型共享最終層與決策頭，並透過自蒸餾（self-distillation）從完整模型學習。具體而言，訓練過程結合了決策監督與自蒸餾訊號，使單次訓練即可在單一檢查點中產生多個出口（exit）。在推論時，一個輕量級閘（gate）會讀取每個出口的隱藏狀態，判斷是否需要繼續計算，從而實現自適應的早期退出。

**Q5：NESTONE 相較於先前研究的關鍵創新是什麼？**
A：NESTONE 的關鍵創新在於「共享計算」的概念——它不是訓練多個獨立模型或單一固定深度的模型，而是讓不同深度的子模型共享最終層與決策頭。這與傳統的層剪枝（layer pruning）方法截然不同，後者僅產生一個固定深度的較小模型，且剪枝標準通常針對生成任務而非決策任務。此外，NESTONE 透過自蒸餾讓淺層出口學習模仿深層的決策行為，這是先前 System One 模型研究中未曾探討的方向。

**Q6：NESTONE 在設計上有哪些重要的選擇？**
A：NESTONE 的設計選擇包含三個關鍵要素：第一，採用巢狀結構而非獨立訓練，使淺層模型能繼承深層模型的知識；第二，使用自蒸餾而非傳統的監督式訓練，讓模型在不同深度都能產生與完整模型一致的決策；第三，引入輕量級閘作為停止機制，根據隱藏狀態動態決定是否提前退出。這些設計共同實現了「一個模型、多個深度」的效果，避免了為每個深度單獨訓練模型所帶來的計算浪費。

**Q7：實驗使用了哪些基準測試？**
A：實驗在七個決策基準測試上評估 NESTONE 的效能，這些基準涵蓋了 System One 決策模型常見的應用場景。所有模型均以 Qwen3.5-4B 為基礎，並使用相同的訓練資料，以確保比較的公平性。實驗結果以基準測試平均（benchmark average）為主要指標，並以宏觀準確率（macro accuracy）作為效能衡量標準。

**Q8：NESTONE 的關鍵實驗結果為何？**
A：在七個決策基準測試上，NESTONE 在每個深度都匹配或優於獨立訓練的模型，同時透過自適應計算實現更好的準確率－效率權衡。具體而言，當簡易流量占比為 100%、90%、75%、50% 時，平均執行層數分別為 17.5、18.1、19.1、20.7 層，而準確率仍保持在固定 24 層出口的 0.1 分以內。這顯示 NESTONE 能根據輸入難度動態調整計算量，在維持高準確率的前提下顯著降低推論成本。

**Q9：論文中進行了哪些消融研究？**
A：論文的消融研究主要包含兩個層面：第一，透過整合梯度歸因（integrated-gradient attribution）分析決策資訊在層次中的分佈，發現 50% 的決策資訊集中在第 20 層之前，80% 在第 23 層之前；第二，透過消融實驗驗證，移除第 24–29 層不會影響準確率，但移除第 15–23 層會消除決策邊界。此外，論文中也比較了「Nested」與「Nested + gate」兩種配置，展示了閘機制對自適應計算的貢獻。

**Q10：NESTONE 適用於哪些實際應用場景？**
A：NESTONE 特別適合需要大量輕量級決策的 LLM 代理系統，例如即時路由請求、自動化工具選擇、內容安全審查（標記不安全提示）以及意圖識別等。這些場景的共同特徵是延遲敏感且決策頻率高，傳統的固定深度推論會造成不必要的計算浪費。此外，NESTONE 也適用於資源受限的部署環境，例如邊緣裝置或需要控制成本的雲端服務，能在不犧牲準確率的前提下降低硬體需求。

**Q11：在產品化部署 NESTONE 時需要考慮哪些因素？**
A：產品化部署時需考慮以下因素：首先，閘的設計需要在額外計算成本與節省的層次之間取得平衡，輕量級閘雖增加少量開銷，但能顯著降低整體推論時間；其次，訓練階段需要同時最佳化多個出口，這對訓練資源與時間的要求較高；最後，部署時需要根據實際流量分佈調整閘的閾值，以達到最佳的準確率－效率權衡，例如在簡易決策占比較高的場景中可設定更積極的提前退出策略。

**Q12：這項研究對領域的影響是什麼？**
A：這項研究對 System One 決策模型領域的影響主要體現在三個方面：第一，它挑戰了「更大骨幹 = 更好決策」的傳統假設，揭示了決策資訊集中在中間層的現象；第二，它提出了「共享計算」的新範式，為未來設計多深度模型提供了方法論基礎；第三，它將自適應計算引入決策模型，使其能根據輸入難度動態調整資源分配，這對整個 LLM 代理系統的效率最佳化具有示範意義。

**Q13：論文承認了哪些限制？**
A：論文的標題註明為「預印本，進行中工作」，這暗示研究仍在發展中，可能存在尚未完善的面向。從內容來看，論文的實驗主要基於 Qwen3.5-4B 模型，雖然這是合理的起點，但對於其他規模或架構的 LLM 是否同樣適用仍需驗證。此外，論文的分析集中在七個決策基準測試，對於更廣泛的決策類型（如多步推理決策或極長上下文決策）的適用性尚未充分探討。

**Q14：NESTONE 在哪些情況下可能會失敗？**
A：NESTONE 在以下情況可能表現不佳：第一，當決策任務需要極深的語意理解時，淺層出口可能無法捕捉足夠的決策資訊，導致提前退出造成錯誤；第二，當輸入分佈與訓練資料差異極大時，閘可能無法準確判斷是否需要繼續計算；第三，對於需要多步推理或長程依賴的決策任務，僅靠中間層的特徵可能不足以做出可靠決策，這些場景可能仍需完整的深度推論。

**Q15：未來的研究方向有哪些？**
A：未來研究方向可從以下幾個角度展開：首先，可以探索將 NESTONE 擴展到更大的模型規模（如 9B 或更大）或不同的骨幹架構，驗證方法的泛化性；其次，可以研究更精緻的閘設計，例如基於不確定性估計或強化學習的動態閾值調整；最後，可以將自適應深度與其他效率技術（如量化、稀疏注意力）結合，進一步降低推論成本，並探索在多語言或多模態決策任務中的應用可能性。

## 實務應用指南

### 適用場景

1. **客服系統中的意圖識別與請求路由**：在客服平台中，每秒可能有數千筆請求需要即時分類（帳務問題、技術支援、退換貨等），並路由到對應的處理流程。NESTONE 的自適應深度特性可讓簡單明確的請求在 12–16 層即完成分類，僅有模糊或多意圖的請求才會走完整 32 層，將平均延遲從 1.45 ms × 32 ≈ 46 ms 降至 20–25 ms。

2. **內容安全審核與不安全提示過濾**：在 LLM 應用入口部署 System One 模型判斷 prompt 是否涉及暴力、隱私洩漏、越獄攻擊等。對於 90% 以上的常見安全模式可在中間層提早退出，僅對低信心或新型攻擊樣本使用完整深度，兼顧吞吐量與安全性。

3. **AI 代理中的工具／函式選擇**：在 function-calling 代理中，每個回合都需要從數十個工具描述中選出最合適的工具。NESTONE 可在淺層即對「明顯匹配」的工具組合做出決策，僅在工具描述相似或需要長上下文推理時才加深計算，降低代理整體的回合時間。

4. **推薦系統的即時候選篩選**：在電商或影音推薦中，從數百個候選項目快速篩選到前 10 名。對於使用者歷史明確、偏好集中的請求可在較淺層完成，僅在冷啟動或行為稀疏時使用完整深度。

5. **邊緣部署的低延遲決策**：在資源受限的邊緣裝置（如手機、IoT 閘道器）上，無法承載完整 4B 模型的推論成本。透過 NESTONE 訓練出的多深度單一模型，可在裝置上根據電量與即時負載動態選擇出口深度，達到單一模型、多種部署模式的效果。

### 實作前置條件

**資料需求**
- 至少數萬筆至數十萬筆標註的決策資料三元組：`(狀態, 問題, 候選選項列表) → 正確選項`。論文使用七個決策基準測試，實務上需蒐集或合成符合自身業務的資料。
- 建議準備一份「難度分層」的驗證集：將資料依信心度或模型表現分為簡易、中等、困難三層，用以評估閘在不同深度下的分配是否合理。
- 若採用自蒸餾，需確保全模型在訓練集上已收斂，否則蒸餾訊號會帶有雜訊。

**運算資源**
- 全模型微調（4B 參數）至少需要 4–8 張 A100/H100 GPU，每張 80GB 記憶體；批次大小受限於序列長度。
- 若僅做 NESTONE 框架的 prefix 子模型訓練，可考慮 LoRA 化以降低顯存需求，但需驗證是否影響多深度表現。
- 推論階段需支援動態圖（dynamic graph）或具備 early-exit 友善的執行環境（如 vLLM、TensorRT-LLM 的客製化外掛）。

**技能門檻**
- 熟悉 PyTorch 與 Hugging Face Transformers，能修改 forward pass 以支援多出口與閘的邏輯。
- 具備分散式訓練（DeepSpeed / FSDP）經驗，以處理 4B 模型的微調。
- 了解 self-distillation 的損失設計（KL 散度、溫度參數）以及如何與監督式交叉熵聯合優化。
- 具備基本的延遲與吞吐量 profiling 能力（nsys、torch profiler），用以驗證自適應深度的實際加速效果。

### 實作步驟建議

1. **確認決策任務與候選選項結構**
   - 明確定義「狀態」、「問題」、「候選選項」的 schema。System One 模型要求選項為封閉集合，這與開放式生成不同。
   - 將既有 LLM 應用中的單步決策盤點出來，標註每個決策的延遲預算與錯誤成本。

2. **建立基準線**
   - 先以「全模型微調 + 固定深度」訓練一個 baseline（類似 Intern-Decision-4B 的做法），記錄其在七個（或自選）基準上的準確率與每層延遲。
   - 同時訓練 12、16、24 層的獨立截斷模型，繪製「層數 vs 準確率」曲線，確認是否如論文所述在 24 層附近出現拐點。

3. **分析決策資訊分佈**
   - 使用 integrated-gradient attribution 找出決策 token 的歸因集中在哪些層。預期結果：50% 歸因落在第 20 層之前、80% 落在第 23 層之前。
   - 對第 24–29 層做 ablation 實驗，確認移除後準確率不下降，作為 NESTONE 出口設計的依據。

4. **設計 NESTONE 訓練流程**
   - 決定出口深度集合（例如 {12, 16, 20, 24}），每個出口共享最終層與決策頭。
   - 損失函數 = `λ₁ × 監督交叉熵(全模型) + λ₂ × Σᵢ KL(子模型ᵢ ‖ 全模型)`，其中 λ₁、λ₂ 需在驗證集上調整。
   - 閘的設計：輕量級 MLP 讀取該出口的隱藏狀態，輸出「繼續／停止」二分類 logits。閘的訓練訊號可來自「再加深是否改變最終決策」的標籤。

5. **單一訓練取得多深度模型**
   - 一次訓練產出多個出口的可用模型，無需為每個深度單獨訓練。
   - 訓練完成後，分別評估每個固定出口的準確率，預期每個深度都優於或等於獨立訓練的同深度模型。

6. **部署自適應推論路徑**
   - 在推論服務中實作 early-exit 邏輯：依序經過各出口，閘決定是否提前返回。
   - 設定「簡易流量占比」目標（例如 75%），觀察平均執行層數是否符合預期（論文圖 1 右側顯示 75% 簡易流量下平均約 19 層）。
   - 監控每個出口的決策分布，避免閘學到「全部提前退出」或「全部走到底」的退化行為。

7. **上線後持續監控與再訓練**
   - 追蹤各出口的決策信心分布、延遲分佈、錯誤率。
   - 當業務選項或資料分布改變時，重新進行 integrated-gradient 分析，確認決策資訊是否仍集中在中間層，必要時調整出口集合。

### 潛在風險與注意事項

**閘的訓練不穩定**
- 風險：閘可能在訓練初期學到「全部走到底」或「全部提前退出」的捷徑，導致自適應機制失效。
- 緩解：使用 warm-up 階段先固定閘輸出為「繼續」，待主模型收斂後再啟用閘的訓練；或在損失中加入鼓勵合理深度的正則項。

**自蒸餾訊號的偏差**
- 風險：若全模型本身在某些樣本上信心不足，自蒸餾會把這種不確定性傳遞給子模型，導致淺層出口在困難樣本上表現更差。
- 緩解：對低信心樣本降低蒸餾權重，或僅在子模型與全模型預測一致時計算 KL 損失。

**領域遷移後的層數假設失效**
- 風險：論文結論（決策資訊集中在中間層、末六層可移除）來自 Qwen3.5-4B 與七個基準。在其他領域（如醫療、法律）或不同基礎模型上，拐點位置可能不同。
- 緩解：每次更換基礎模型或領域時，重新執行層數 ablation 與歸因分析，不要直接套用 24 層的出口設定。

**早期退出的錯誤成本不對稱**
- 風險：在內容安全、醫療診斷等場景，淺層出口的錯誤成本遠高於延遲節省的收益。
- 緩解：對高風險決策強制走完整深度，僅在低風險決策啟用自適應；或在閘的決策中加入業務規則的硬約束。

**單一 checkpoint 的維運複雜度**
- 風險：相較於訓練多個獨立模型，NESTONE 的單一 checkpoint 雖減少儲存成本，但除錯時較難隔離問題。
- 緩解：保留訓練過程中各出口的獨立評估紀錄與日誌，建立「出口 → 樣本 → 預測」的追溯鏈。

**與硬體加速器的相容性**
- 風險：早期退出破壞了靜態圖的 batch 整齊性，可能降低 GPU 利用率。
- 緩解：在服務層將請求依預估深度分桶（shallow bucket / deep bucket），同桶內 batch 處理以維持 throughput。

### 與其他技術的整合建議

**與 LoRA / 參數高效微調整合**
- NESTONE 的多出口設計可與 LoRA 結合：每層掛載 LoRA adapter，淺層出口使用較少 adapter，深層出口使用全部。訓練成本可顯著降低，但需驗證多深度表現是否仍優於獨立訓練。

**與 RAG（檢索增強生成）整合**
- 在需要外部知識的決策任務中，可將檢索結果作為「狀態」的一部分輸入 System One 模型。NESTONE 的自適應深度特別適合：簡單問題在淺層即可決策，僅在需要長上下文整合時走完整深度。

**與快取機制整合**
- 對於重複出現的相似請求，可快取淺層出口的隱藏狀態與決策結果。NESTONE 的 prefix 子模型結構天然支援 KV-cache 的部分重用，進一步降低重複請求的延遲。

**與思維鏈推理（System Two）整合**
- 在混合架構中，System One 模型可作為 System Two 的「快速篩選器」：先用 NESTONE 在淺層判斷是否需要昂貴的思維鏈推理，僅對高難度樣本啟動完整推理流程。這與論文中提到的「long chain-of-thought reasoning + lightweight decisions」場景直接對應。

**與監控與可觀測性工具整合**
- 將每個出口的決策分布、平均深度、閘的啟用率等指標接入 Prometheus / Grafana。設定 alert 閾值，例如「平均深度突然上升」可能代表資料分布漂移。

**與多模型路由整合**
- 在大型系統中，可將 NESTONE 與不同尺寸的模型（如 0.8B、2B、4B）組合：先用小模型做粗篩，NESTONE-4B 做精篩，最終決策再路由到對應業務模組。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先讀第 1 節的動機部分，理解「為什麼 LLM 做單步決策時不需要走完整個骨幹網路」，並重點看圖 1 的左側曲線——它直觀展示了「層數 vs 準確率」的非線性關係，這是理解整篇論文的視覺錨點。技術細節可先跳過，直接記住三個結論：決策資訊在中間層、末六層可砍掉、淺層模型學不到專門化能力。

**給 AI 工程師**：重點關注第 3 節的層數分析與 NESTONE 的訓練流程。實作上最大的工程挑戰是「如何讓單一 forward pass 支援多個出口且不破壞計算圖」，建議先在小型模型（如 0.5B）上重現論文的層數 ablation 實驗，確認拐點位置後再擴展到 4B。部署階段要特別注意 early-exit 對 batch 效率的影響，這是論文未深入討論但實務上很關鍵的議題。

**給研究者**：論文的兩個分析（第 3.1 節的歸因實驗、第 3.2 節的子模型行為分析）是值得延伸的方向。具體可探索：(1) 拐點位置是否與基礎模型的預訓練目標、規模存在可預測的關係；(2) NESTONE 的自蒸餾損失設計是否是最優的，是否能用更原則性的方法（如資訊瓶頸）取代；(3) 閘的設計是否能從「二元決策」擴展到「連續深度分配」，實現更細粒度的自適應。

**給產品經理**：核心訊息是「同一個模型可以同時服務多種延遲預算」。這代表在產品設計上，可以為不同付費等級或不同場景提供差異化的響應速度，而無需維護多套模型基礎設施。建議盤點自家產品中所有「單步分類／選擇」類型的決策點，估算它們的延遲敏感度與錯誤成本，優先挑選錯誤成本低、流量大的場景作為 NESTONE 的試點。
