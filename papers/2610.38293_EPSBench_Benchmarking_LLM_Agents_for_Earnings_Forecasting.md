EPSBench 的核心方法論在於將「季度盈利預測」這項任務從傳統的端到端數值預測，重構為一個**結構化的驅動因子估計問題**。此設計理念源自人類分析師的實務工作流程：分析師並非直接猜測 EPS 數字，而是從損益表的底層項目（drivers）逐層往上推估，最終透過會計恆等式彙整為 EPS。

**三階段流程架構：**

1. **離線架構抽取（Schema Extraction）**：研究團隊利用歷史申報文件（SEC 10-K/10-Q filings）為每家公司建構專屬的會計架構，包含三個關鍵元素：
   - **去年同期基線（Year-ago baseline）**：作為預測的錨點
   - **驅動因子清單（Drivers）**：需由代理估計的損益表項目，例如營收（Revenue）、銷貨成本（Cost of sales）、營業費用（Op. expenses）、非營業項目（Non-op. items）、稅額（Tax）、攤薄股數（Diluted shares）等
   - **會計有向無環圖（Accounting DAG）**：定義驅動因子之間的會計恆等式關係，例如「營業利益 = 毛利 − 營業費用」、「稅前淨利 = 營業利益 + 非營業項目」、「EPS = 淨利 ÷ 攤薄股數」

2. **線上代理預測（Agent Forecasting）**：在截止日 τ（即盈餘公布前一天）之前，代理僅能存取已公開的資訊來源：
   - 申報文件（Filings）
   - 業績電話會議逐字稿（Earnings-call transcripts）
   - 新聞報導（News）
   
   代理透過 MCP 工具（Model Context Protocol tools）進行讀取與搜尋，估計每個驅動因子並提供引用證據（cited evidence）。此設計強制要求每個估計值都能追溯到具體證據，大幅提升預測過程的可審計性。

3. **評測（Evaluation）**：代理提交的驅動因子估計值透過共享的會計計算器（Accounting Calculator）執行 DAG，產生：
   - **點預測（Point forecast）**：GAAP 攤薄每股盈餘
   - **80% 預測區間（Prediction interval）**：以 [p10, p90] 表示的不確定性區間

**方法論的關鍵創新點：**

- **可分解的誤差歸因（Decomposable Error Attribution）**：由於會計恅等式是固定的，每個分數都附著於產生該分數的驅動因子估計值與引用證據。這使得誤差能被追溯到損益表的特定階段——研究發現模型間的誤差差距幾乎完全來自營業利益（Operating Income）估計。
- **日期匹配的公平比較**：使用 IBES（Institutional Brokers' Estimate System）在截止日 τ 的分析師共識作為參考基準，避免了「事後偏差」（hindsight bias）。
- **GAAP vs. 非 GAAP 的嚴格區分**：EPSBench 僅評測 GAAP 攤薄 EPS，要求代理在使用調整後盈餘（adjusted earnings）作為證據時必須區分其與目標的差異。

#### 實驗數據解讀

**評測指標體系：**

研究採用多維度指標評估代理表現：

| 指標類別 | 具體指標 | 意義 |
|---------|---------|------|
| 點預測 | 價格平減誤差（Price-Deflated Error, PDE） | 消除股價波動影響的誤差衡量 |
| 點預測 | 對抗共識的勝率（Win rate vs. consensus） | 與專業分析師比較的相對表現 |
| 點預測 | 驚喜方向準確率（Surprise-direction accuracy） | 預測方向是否正確 |
| 區間 | 涵蓋率（Coverage） | 實際值落入預測區間的比例 |
| 區間 | 區間寬度（Width） | 不確定性估計的精確度 |
| 區間 | 區間分數（Interval score） | 結合寬度與涵蓋率的綜合指標 |
| 成本 | 輸入 tokens、工具呼叫次數、格式合規率 | 資源使用效率 |

**核心實驗結果：**

1. **點預測表現分組**：在六個受測模型中：
   - **領先組（3 個模型）**：與分析師共識的配對差異在統計上不可偵測，意即表現與專業分析師相當
   - **落後組（3 個模型）**：誤差顯著高於共識

2. **區間校準嚴重不足**：所有六個模型的 80% 名目區間（nominal 80% intervals）僅涵蓋 37–70% 的實際結果，遠低於預期的 80%。這顯示 LLM 代理在量化不確定性方面存在系統性缺陷。

3. **系統性低估偏差**：未涵蓋的案例（misses）大多落在區間上界之上，意即實際 EPS 高於代理預測的上界。這與分析師共識的低估傾向一致——兩者都呈現「預測偏低」的特徵。

4. **誤差來源定位**：驅動因子記錄（Driver records）顯示，模型間的誤差差距幾乎完全來自營業利益（Operating Income）估計的差異，而非稅務、股數或非營業項目等其他驅動因子。

5. **資訊來源的互補性**：新聞與申報文件承載部分不同的資訊內容，結合使用能提升預測品質。

6. **框架與推理努力的影響**：評測框架（harness）與推理努力（reasoning effort）的調整對涵蓋率的影響大於對點預測誤差的影響，顯示區間校準對這些因素更為敏感。

**結果的深層意涵：**

實驗數據揭示了一個重要現象：LLM 代理在「方向判斷」與「量值估計」上可能已達到專業分析師水準，但在「不確定性量化」上仍存在顯著差距。37–70% 的涵蓋率意味著代理傾向於給出過於自信的窄區間，這在金融決策中可能導致嚴重的風險管理問題。

#### 與現有研究的比較

**與同類預測基準的定位：**

| 基準 | 焦點 | 與 EPSBench 的差異 |
|------|------|-------------------|
| **ForecastBench**（Karger et al., 2025） | 未決事件的機率預測，與人類預測者比較 | 僅要求機率，不要求數值分解；EPSBench 要求結構化驅動因子估計 |
| **FutureX**（Zeng et al., 2026） | 具備搜尋能力的代理在多元未來事件上的表現 | 涵蓋廣泛事件，EPSBench 專注於盈利預測的會計結構 |
| **FinDeepForecast**（Li et al., 2026） | 即時企業與總體經濟預測任務 | 兩者皆包含 EPS，但 FinDeepForecast 要求代理直接輸出預測數字，EPSBench 要求分解為驅動因子 |
| **FinQA**（Chen et al., 2021） | 對已提供報告的數值推理 | 處理已揭露資訊，EPSBench 預測未揭露結果 |
| **FinAgentBench**（Choi et al., 2025） | 財務文件檢索評測 | 聚焦於檢索能力，EPSBench 聚焦於預測能力 |

**EPSBench 的獨特貢獻：**

1. **可追溯性（Traceability）**：相較於 FutureX 與 FinDeepForecast 直接要求預測數字，EPSBench 透過驅動因子分解使每個誤差都能歸因到損益表的特定行項目，這是首個提供此層級可審計性的盈利預測基準。

2. **會計結構的內建**：利用 GAAP 損益表的會計恆等式作為「真理來源」，避免了評測中對預測數字的純黑箱評分。

3. **嚴格的資訊截止**：明確限制代理只能使用截止日 τ 之前的資訊，模擬真實的預測情境，避免資料洩漏。

**限制與不足：**

1. **樣本規模**：149 個公司季度來自 86 家公司，雖然涵蓋多家公司，但相較於真實分析師覆蓋的數千家公司，樣本仍屬有限。

2. **僅限美國 GAAP**：架構設計基於美國 GAAP，無法直接適用於 IFRS 或其他會計準則的市場。

3. **未涵蓋非 GAAP 預測**：實務中市場更關注調整後盈餘（adjusted EPS），但 EPSBench 僅評測 GAAP 攤薄 EPS。

4. **靜態資訊環境**：資訊來源是預先建構的固定集合，未模擬真實世界中資訊持續更新的動態特性。

5. **未評測多季度預測**：僅針對單一季度進行預測，未涵蓋跨季度的趨勢預測與修正。

#### 未來研究方向

EPSBench 開啟了多個值得深入探索的研究方向：

**1. 驅動因子層級的模型改進**

37–70% 的涵蓋率顯示區間校準是亟待解決的問題：

- 研究如何讓代理區分「證據不足」與「證據充分但結果不確定」

**3. 跨會計準則的擴展**

- 研究不同會計準則下驅動因子定義的差異化處理
- 探索跨國比較分析，檢驗 LLM 代理在不同市場的表現差異

**4. 動態資訊環境的模擬**

- 設計增量資訊更新機制，模擬真實世界中資訊持續湧入的情境
- 研究代理在資訊過載與資訊不足兩種極端下的表現
- 探索即時預測（nowcasting）與前瞻預測（forecasting）的差異

**5. 多季度預測與預測修正**

- 擴展至跨季度的預測序列，研究代理如何利用前期預測誤差進行修正
- 探索貝氏更新（Bayesian updating）式的預測框架
- 評估代理在預測「預測修正」（forecast revision）方面的能力

**6. 推理框架與工具使用的最佳化**

研究發現框架與推理努力對涵蓋率影響大於點誤差，這提示：
- 系統性地探索不同的推理策略（思維鏈、反思、辯論等）對預測品質的影響
- 開發專門的金融推理工具，超越通用的搜尋與讀取功能
- 研究多步推理中錯誤累積的機制與緩解方法

**7. 與人類分析師的深度協作**

- 研究 LLM 代理作為分析師助手的使用模式
- 探索「人機協作預測」相較於純人類或純 AI 預測的優勢
- 設計能解釋自身推理過程的代理，增強人類對 AI 預測的信任

**8. 領域特化模型的訓練**

- 研究如何將通用 LLM 的推理能力與領域知識有效結合

### 實作前置條件

**資料需求**
- SEC EDGAR 的 10-K、10-Q 申報文件（至少需回溯 4–8 季以建立 year-ago baseline）
- 業績電話會議逐字稿（可來自 Seeking Alpha、FactSet、Refinitiv 或公司 IR 網站）

- IBES 或 FactSet 的分析師共識資料，且必須以「截止日 τ 前一日」為對齊基準
- 公司股票價格資料，用於計算 price-deflated error (PDE)

**運算與基礎設施**
- 至少支援 100K token 上下文窗口的 LLM API（GPT-4 級以上或 Claude Opus 級）
- MCP（Model Context Protocol）工具伺服器，用於檔案讀取與全文搜尋
- 排程與日期過濾管線，確保代理只能存取 τ 之前的證據
- 儲存空間：149 個公司季度的完整 trajectory 平均需數 GB

**技能門檻**
- 熟悉美國 GAAP 損益表結構與攤薄 EPS 計算
- 能撰寫 DAG 形式的會計恆等式（從營收一路到 EPS）
- Prompt engineering 經驗，特別是要求「逐驅動因子引用證據」的格式約束
- 基本統計知識：paired test、預測區間校準、PDE 指標解讀

### 實作步驟建議

**Step 1：建立公司專屬 Schema**
從歷史 10-K/10-Q 抽取損益表，識別 year-ago baseline、列出需預測的 drivers（營收、銷貨成本、營業費用、營業外項目、稅率、攤薄股數等），並以 DAG 形式定義會計恅等式。此步驟離線完成，可批次處理所有 86 家公司。

**Step 2：建構資訊環境**
將申報文件、逐字稿、新聞統一索引到一個可搜尋的儲存庫，加上嚴格的日期過濾層（cutoff τ = 財報發布前一日）。這是 EPSBench 強調的「固定資訊環境」原則，避免代理在測試時取得未來資訊。

**Step 3：部署 MCP 工具與代理 Harness**
實作 read_file 與 search 兩個 MCP 工具，包裝成統一的代理介面。Harness 需管理上下文、追蹤工具呼叫次數、強制格式合規（每個 driver 必須附引用）。

**Step 4：執行預測**
代理依序估計每個 driver 並引用證據，送入共享會計計算器得到 EPS 點估計，再產出 80% 預測區間 [p10, p90]。建議每家公司季度至少跑 3 次以評估穩定性。

**Step 5：評估與診斷**
- 點預測：計算 PDE、對共識勝率、surprise-direction accuracy
- 區間：涵蓋率、平均寬度、interval score
- 成本：input tokens、tool calls、格式合規率
- 診斷：將誤差拆解到各 driver，定位主要誤差來源（本研究發現幾乎都落在營業利益）

**Step 6：迭代改進**
依診斷結果調整 prompt、增加 reasoning effort、或更換資訊來源組合（新聞 vs. 申報文件）。EPSBench 顯示 harness 與推理努力主要影響區間校準，而非點預測誤差。

### 潛在風險與注意事項

**系統性低估偏差**
所有六個模型的 80% 區間未涵蓋案例中，絕大多數落在上界以上，代表預測普遍偏低。實作上若用於投資決策，需對點估計加上方向性修正，或要求代理在低基期季度主動上調。

**營業利益估計為主要誤差源**
模型間的誤差差距幾乎完全來自營業利益相關驅動因子。建議在 prompt 中特別強調成本結構、毛利率變動、營業槓桿等線索，並提供歷史毛利率區間作為錨點。

**格式合規與幻覺引用**
代理可能編造不存在的引用或漏填 driver。務必在 harness 中加入引用驗證步驟（檢查引用是否真實出現在證據庫中），並對未通過驗證的預測降權或剔除。

**資訊截止日洩漏**
若日期過濾管線有 bug，代理可能讀到 τ 之後的資訊，造成「預測」其實是「偷看」。建議加入單元測試，隨機注入未來文件並驗證代理無法存取。

**區間校準嚴重不足**
37–70% 的涵蓋率遠低於名目 80%。若下游應用依賴區間（例如風險值計算），必須自行重新校準，或改用 conformal prediction 等事後調整方法。

**成本控制**
長上下文加上多次工具呼叫會快速消耗 token。建議設定單次預測的 token 上限，並在 harness 中實作早期停止機制。

### 與其他技術的整合建議

**與傳統量化模型互補**
將 LLM 代理的「質化判斷」（管理層語氣、指引變化）與傳統時間序列模型（ARIMA、Prophet）的「量化基準」結合，可降低單一方法的盲點。EPSBench 的 driver-level 記錄正好提供融合介面。

**與 Bloomberg/FactSet 終端機整合**
透過 API 將 EPSBench 的 schema 與終端機的歷史財務資料對接，可自動化 schema 抽取步驟，並把預測結果回寫到終端機的觀察清單中。

**與 RAG 系統共用基礎設施**
EPSBench 的 MCP 工具與日期過濾層可作為企業內部 RAG 系統的範本，特別是「證據必須可追溯」這項要求，可直接套用至法遵、盡職調查等場景。

**與人類分析師工作流並行**
不要直接取代分析師，而是作為「第二意見」或「盲測對照組」。EPSBench 的 paired evaluation 設計（與日期匹配共識比較）正好適合這種人機協作模式。

**與模型監控平台對接**
將每次預測的 driver 記錄、引用、區間送入 ML monitoring 平台（如 Arize、WhyLabs），長期追蹤模型在不同產業、不同季度的表現漂移。

### 給不同背景讀者的閱讀建議

**給初學者**：先讀第 1 節的 Figure 1，理解 EPSBench 的三階段流程（schema 抽取 → 代理預測 → 評估），再回頭看摘要。重點掌握「為什麼要從損益表驅動因子出發，而不是直接問模型 EPS 數字」這個核心設計動機。

**給 AI 工程師**：直接跳到第 5 節的實驗結果，特別是 5.4 與 5.5 對資訊來源、harness、推理努力的消融實驗。這些結論對設計你自己的金融代理有直接指導意義：harness 與推理努力主要影響區間校準，點預測誤差則更依賴模型本身的財務推理能力。

**給研究者**：第 3 節的 schema 抽取方法與第 4 節的評估指標定義是方法論核心。建議仔細閱讀 paired evaluation 的統計設計（如何處理共識缺失、如何定義 PDE），並思考如何將此框架推廣到非 GAAP 指標或非美國市場。

**給產品經理**：聚焦在「系統性低估」這個發現——所有模型都低估 EPS，且低估集中在營業利益。這意味著任何直接採用 LLM EPS 預測的產品都需要內建修正機制。同時，37–70% 的區間涵蓋率提醒我們：LLM 的「信心」表達目前還不可靠，不應作為風險控管的唯一依據。
