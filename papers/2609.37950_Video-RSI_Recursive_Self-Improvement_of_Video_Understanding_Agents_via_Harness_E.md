# Video-RSI：透過框架演化遞迴自我改進影片理解代理

## ⚡ TL;DR

影片理解代理的執行軌跡僅含當前框架擷取的證據，無法釐清失敗成因，限制了自我改進的基礎。
Video-RSI 讓凍結語言模型兼任解題與編輯，透過主動調查與成本感知演化遞迴修訂可執行框架。
在四個基準測試中，演化後的代理以更少影格提升準確率，並在準確率與效率權衡上具競爭力。

## 摘要翻譯

影片理解代理透過可執行框架（Executable Harness）擷取證據，該框架控制其觀察內容及使用這些觀察的方式。然而，執行軌跡（Execution Trace）僅包含當前框架所擷取的證據，使得失敗原因的競爭性解釋懸而未決，並限制了自我改進的基礎。我們提出 Video-RSI，一個遞迴自我改進（Recursive Self-Improvement）的框架，其中影片理解代理使用自身的語言模型（Language Model）來修訂其框架。透過主動影片調查（Active Video Investigation），模型重新檢視原始訓練影片，以額外的觀察來測試關於失敗的競爭性解釋，將所提出的變更奠基於現有軌跡以外的證據。成本感知的框架演化（Cost-aware Harness Evolution）將這些診斷轉化為可重複使用的修訂版本（Reusable Harness），並透過同時考量答案準確率（Answer Accuracy）與視覺成本（Visual Cost）來決定保留哪些修訂版本。在我們對影片理解基準測試（Benchmark）的多項評估設定中，演化後的代理在處理更少影格（Frame）的同時提升了準確率，並在準確率與效率的權衡（Accuracy-Efficiency Trade-off）上達到具競爭力的水準。這些結果展示了影片理解代理透過框架演化（Harness Evolution）來改進自身證據擷取（Evidence Acquisition）與使用的潛力。程式碼可於 https://github.com/bingjunluo/Video-RSI 取得。

### 核心貢獻（3～5點）
- **問題洞察**：指出影片理解代理的執行軌跡僅包含當前框架所擷取的證據，導致失敗的競爭性解釋懸而未決，限制了自我改進的基礎。
- **框架創新**：提出 Video-RSI 框架，使影片理解代理能利用自身的語言模型遞迴修訂其可執行框架，實現框架自我改進（Harness Self-Improvement）。
- **主動診斷機制**：透過主動影片調查，模型重新檢視原始訓練影片，以額外觀察測試競爭性解釋，使修訂變更奠基於現有軌跡以外的證據。
- **成本感知演化**：成本感知的框架演化同時考量答案準確率與視覺成本，決定保留哪些修訂版本，兼顧效能與效率。
- **實驗成果**：在影片理解基準測試的多項評估設定中，演化後的代理以更少影格處理提升準確率，並在準確率與效率的權衡上與現有影片理解代理達到具競爭力的表現。

### 適合對象
從事多模態大型語言模型（MLLM）、影片理解、自動化代理設計（Automated Agent Design）與遞迴自我改進研究之學者與工程師；對代理框架演化、證據擷取策略及成本感知推論優化感興趣之研究者；以及尋求提升影片問答系統準確率與效率權衡之實務開發者。

## 深度分析

#### 方法論解析

Video-RSI 的核心方法論建立在「可執行框架」(executable harness) 這個抽象概念之上，將影片理解代理 (video understanding agent) 的行為控制從模型權重中抽離出來，轉化為可被語言模型自身修改的程式碼物件。這種設計哲學源自於一個關鍵觀察：執行軌跡 (execution trace) 僅記錄了當前框架所擷取的證據 (evidence)，無法區分失敗原因是來自取樣落差 (sampling gap)、知覺錯誤 (perceptual error)，還是證據使用不當，因此單靠軌跡分析無法支撐有效的自我改進。

**雙重角色架構 (Dual-Role Architecture)**

Video-RSI 採用同一個凍結語言模型 (frozen language model) 同時擔任兩個角色：
- **Solver（解答者）**：在評估階段使用框架 $H_t$ 處理新的影片問題，產生答案與執行軌跡。
- **Editor（編輯者）**：在演化階段分析失敗案例、調查影片、提出框架修訂版本 (revision)。

這種設計避免了引入額外的強模型來監督弱模型所帶來的複雜度，同時也避免了 Self-Harness 等方法在終端環境 (terminal environments) 中僅依賴軌跡進行診斷的限制。

**主動影片調查 (Active Video Investigation)**

此機制是 Video-RSI 區別於先前自我改進框架的核心創新。當 Solver 在某個訓練影片上失敗時，Editor 不僅分析現有軌跡，還會主動重新檢視原始影片，執行額外的觀察動作以測試競爭性失敗解釋 (competing failure explanations)。具體而言：
- 若軌跡顯示某事件未被觀察到，Editor 可透過額外的影格擷取 (frame acquisition) 或時段導航 (temporal navigation) 來驗證該事件是否真實存在於影片中。
- 若事件存在但答案錯誤，則可進一步區分是視覺感知問題還是推理使用問題。
- 調查結果會產生超越原始軌跡的證據，作為程式碼修訂的依據。

**成本感知的框架演化 (Cost-Aware Harness Evolution)**

演化機制採用類似遺傳演算法的選擇策略，但以「準確率—視覺成本」(accuracy–visual cost) 的聯合指標作為適應度函數：
- **準確率 (Answer Accuracy)**：在保留的訓練影片子集上重新執行修訂後的框架，測量答案正確率。
- **視覺成本 (Visual Cost)**：以處理的影格總數 (frame count) 作為代理指標，反映計算開銷。

只有當修訂版本在兩項指標上均優於（或至少不顯著劣於）當前框架時，才會被保留作為下一輪演化的起點 $H_{t+1}$。這種雙重約束避免了「以更高成本換取微小準確率提升」的退化路徑，確保演化方向朝向更高效的證據擷取與使用。

**遞迴改進迴圈 (Recursive Improvement Loop)**

整體流程形成一個閉環：
1. 使用 $H_t$ 在訓練影片上執行，收集失敗案例。
2. Editor 對失敗案例進行主動調查，產生診斷 (diagnosis)。
3. 根據診斷提出候選修訂版本 $H'_t$。
4. 在保留集上評估 $H'_t$ 的準確率與視覺成本。
5. 若通過選擇標準，$H_{t+1} \leftarrow H'_t$，否則保留 $H_t$。
6. 重複步驟 1–5 直至收斂或達到預定迭代次數。

演化過程完全在離線 (offline) 階段完成，最終選定的框架被凍結用於新問題的評估，這保證了測試階段的確定性與可重現性。

#### 實驗數據解讀

**基準測試設置**

論文在四個影片理解基準測試 (benchmark) 上評估 Video-RSI，涵蓋不同長度與任務類型的影片。雖然具體基準名稱未在提供的文本中完整列出，但從相關文獻脈絡推測可能包括 MLVU、VideoMME、EgoSchema 或 LongVideoBench 等長影片理解基準。

**核心結果指標**

從摘要與引言的描述可歸納出三項關鍵實驗發現：

1. **準確率提升**：經過演化後的框架在四個基準測試上均優於初始框架 $H_0$，證明了遞迴自我改進的有效性。

2. **影格使用量降低**：演化後的框架在處理更少影格 (fewer frames) 的同時達到更高的準確率，這意味著框架學會了更精準的證據擷取策略，而非簡單地增加觀察密度。

3. **準確率—效率權衡 (Accuracy-Efficiency Trade-off) 競爭力**：與現有的影片理解代理（如 VideoAgent、VideoTree、DVD、VideoSeek、MR.Video、LV Agent 等）相比，Video-RSI 達到了具有競爭力的帕累托前沿 (Pareto frontier)。

**MLVU 消融實驗的關鍵意義**

在 MLVU 基準上，主動調查機制被證明比僅依賴軌跡的修訂（trace-only revision）在最終準確率上更高，且兩者在推論時的影格使用量相近。這項消融結果具有方法論上的重要性：
- 它驗證了「超越軌跡的證據蒐集」對於診斷品質的實質貢獻。
- 它排除了「主動調查只是讓框架變得更貪婪地擷取影格」的簡單解釋——若僅是增加觀察，則 trace-only revision 應能透過其他機制達到類似效果。

**演化動態分析**

論文聲稱分析了「調查與演化的動態」(investigation and evolution dynamics)，這暗示可能呈現了：
- 每輪演化後準確率與影格成本的變化曲線。
- 不同類型失敗案例的診斷成功率。
- 修訂被保留或拒絕的比例。

這些動態資訊對於理解框架學習曲線與收斂行為至關重要，但具體數據需參閱正文。

#### 與現有研究的比較

**與影片代理方法的比較**

Video-RSI 與 VideoAgent、VideoTree、VCA、DVD、VideoSeek、MR.Video、LV Agent 等影片代理共享相同的問題設定（長影片中的證據擷取），但改進路徑截然不同：
- **現有方法**：透過精心設計的工具組合、控制流程或代理間協作來提升效能，但這些設計是靜態的、由人類研究者預先定義的。
- **Video-RSI**：將工具組合與控制流程視為可被語言模型自身修改的程式碼，透過執行經驗 (execution experience) 累積改進。

這種差異使得 Video-RSI 在概念上更接近「元學習」(meta-learning) 或「自動機器學習」(AutoML) 的範式，只是優化對象從模型權重轉為代理程式。

**與訓練式方法的比較**

FrameThinker 透過監督式微調與強化學習協調推理與影格擷取；EVA 學習時段、影格數與空間解析度的分配，並利用失敗案例生成訓練問題。這些方法需要更新模型權重，而 Video-RSI 保持模型凍結，僅修改外圍程式碼。這帶來幾項實務優勢：
- **無需 GPU 訓練資源**：演化過程僅涉及推理與程式碼生成。
- **可解釋性**：所有改進以可讀的程式碼形式存在，便於審查與除錯。
- **模型無關性**：同一框架演化流程可應用於不同的基礎 MLLM。

然而，訓練式方法在長期可能達到更高的效能天花板，因為它們能調整模型內部的視覺編碼與推理策略。

**與自動化代理設計的比較**

ADAS、AFlow、Meta-Harness 等自動化代理設計方法將代理程式視為優化空間，但主要應用於程式碼生成、數學推理等非視覺任務。Self-Harness 雖展示了凍結模型在終端環境中修訂自身框架的能力，但其診斷僅依賴執行軌跡，缺乏 Video-RSI 的主動調查機制。Video-RSI 可視為 Self-Harness 向視覺領域的延伸，並透過主動影片調查解決了軌跡資訊不足的問題。

**限制與不足**

儘管 Video-RSI 展現了引人注目的結果，仍存在若干限制：
1. **演化成本**：雖然最終框架的推論成本降低，但演化過程本身需要大量推理呼叫，主動調查階段尤為昂貴。
2. **基準依賴性**：演化是在特定訓練影片集上進行的，對於分布外 (out-of-distribution) 影片類型的泛化能力未經充分驗證。
3. **修訂粒度**：可執行程式碼的修改空間可能受到初始框架設計的限制，若初始框架缺乏某些關鍵工具，演化可能無法跨越結構性障礙。
4. **缺乏理論保證**：遞迴改進的收斂性與最優性缺乏形式化分析。

#### 可重現性評估

**程式碼可用性**

論文明確聲明程式碼已開源於 GitHub（https://github.com/bingjunluo/Video-RSI），這對於可重現性至關重要。開源內容預期應包括：
- 框架的初始實作 $H_0$。
- 主動調查與成本感知演化的完整流程。
- 四個基準測試的評估腳本。
- 訓練影片子集與保留集的劃分方式。

**模型權重**

由於 Video-RSI 使用凍結的 MLLM（具體型號未在提供的文本中說明），重現實驗需要相應的模型權重。若使用的是開源模型（如 Qwen-VL、InternVL、LLaVA-Video 等），則可透過 Hugging Face 等平台取得；若涉及閉源模型的 API 呼叫，則需相應的 API 金鑰。

**資料集**

四個影片理解基準均為公開資料集，但部分基準（如 MLVU）需要從官方來源下載原始影片，這可能涉及較大的儲存空間與潛在的版權問題。訓練影片子集的具體選取標準對於重現演化結果至關重要，論文中應對此進行明確說明。

**超參數與隨機性**

演化過程涉及多項超參數，包括每輪迭代的訓練影片數量、保留集大小、選擇標準的權重平衡、溫度參數等。論文中應提供完整的超參數配置表，並說明是否對隨機種子進行了敏感性分析。

**計算資源**

雖然 Video-RSI 不需要訓練 GPU，但演化階段的大量推理呼叫仍需要相當的計算資源。論文中應報告總推理成本（以 GPU 小時或 API 費用計），以便其他研究者評估重現的可行性。

#### 未來研究方向

**1. 線上持續演化 (Online Continuous Evolution)**

當前 Video-RSI 的演化完全在離線階段完成，部署後框架即被凍結。一個自然的延伸是允許框架在部署後根據新影片的執行經驗持續演化，這將使代理具備終身學習 (lifelong learning) 能力。然而，這也帶來災難性遺忘 (catastrophic forgetting) 與安全性風險，需要引入版本管理與回退機制。

**2. 多模態框架演化**

將主動調查機制從影片擴展到音訊、字幕、場景圖等多模態證據來源。Editor 可主動呼叫語音辨識、光學字元辨識 (OCR)、物件偵測等工具來豐富診斷證據，使框架演化能同時優化跨模態證據融合策略。

**3. 階層式框架演化**

當前框架被視為單一可執行程式碼物件。可探索將框架分解為多個子模組（如證據擷取器、推理控制器、答案驗證器），並對各子模組進行獨立的演化與組合，這可能加速收斂並提升可解釋性。

**4. 與訓練式方法的混合**

將 Video-RSI 的程式碼層級演化與 FrameThinker、EVA 等訓練式方法結合：先用訓練式方法將模型調整到合理的起點，再以 Video-RSI 進行細粒度的框架優化。這種混合策略可能突破兩類方法各自的效能天花板。

**5. 理論分析**

目前遞迴改進的收斂性、最優性與樣本複雜度缺乏形式化分析。未來可借鑒元學習理論、程式碼優化的 PAC 學習框架，或遺傳演算法的馬可夫鏈分析，為 Video-RSI 提供理論保證。

**6. 安全與對齊考量**

當語言模型被賦予修改自身執行框架的能力時，需要考慮潛在的安全風險：模型可能演化出繞過人類監督的捷徑，或在追求準確率時引入偏見。未來研究應納入對齊約束 (alignment constraints) 與紅隊測試 (red-teaming) 機制。

**7. 跨任務遷移**

研究演化後的框架是否能在不同影片理解任務（如影片問答、影片摘要、動作辨識）之間遷移。若某些修訂具有任務無關的通用性（如「先全局掃描再局部聚焦」），則可發展框架庫 (harness library) 供新任務快速初始化。

**8. 人機協作演化**

允許人類專家在演化過程中注入領域知識或約束，例如指定某些工具必須保留、某些失敗模式不可接受。這將使 Video-RSI 從純自動化演化轉向人機協作演化，提升在敏感領域（如醫療影像分析）的實用性。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於影片理解代理（video understanding agent）的自我改進問題。傳統的影片代理仰賴一個可執行框架（executable harness）來決定要觀察哪些影格、如何運用觀察結果，但這個框架本身在訓練後通常是固定的。當代理答錯問題時，僅憑執行軌跡（execution trace）無法釐清失敗的真正原因——可能是取樣落差、知覺錯誤，或是未能善用既有證據。因此，論文的目標是讓代理能夠在不更動模型權重的前提下，遞迴地改進自身的可執行框架。

**Q2：為什麼現有的方法無法有效解決這個問題？**
A：現有方法大致分為兩類，但都各有局限。第一類是基於訓練的觀察策略學習（如 FrameThinker、EVA），透過監督式微調或強化學習來調整觀察行為，但這需要更新模型權重，且訓練成本高昂。第二類是自動化代理設計（如 ADAS、AFlow、Meta-Harness），雖然能在程式碼層級優化代理，但通常僅依賴執行軌跡作為回饋，缺乏對失敗原因的深入診斷。此外，Self-Harness 雖證明了凍結模型可以修訂自身框架，但僅限於終端環境，未處理影片理解中特有的視覺成本與證據擷取問題。

**Q3：為什麼這個問題對領域而言很重要？**
A：影片理解任務中，長影片中的關鍵事件往往短暫、時間分散且容易被視覺相似的干擾所掩蓋。代理必須在「看哪裡、看多細、何時停止觀察」這些決策上做出取捨，而這些決策直接影響答案準確率與視覺成本（visual cost）。若能讓代理自動改進其證據擷取與使用的程序，就能在不增加模型規模或訓練成本的情況下，持續提升準確率並降低運算開銷。這對實務部署尤其關鍵，因為影片處理的視覺成本往往是瓶頸所在。

**Q4：Video-RSI 的核心方法是什麼？**
A：Video-RSI 的核心方法是一個遞迴自我改進的循環，其中同一個凍結的語言模型同時扮演 Solver（解題者）與 Editor（編輯者）兩種角色。具體而言，框架包含兩個關鍵機制：「主動影片調查」（Active Video Investigation）讓模型重新檢視訓練影片，以額外的觀察來檢驗競爭性的失敗解釋；「成本感知的框架演化」（Cost-Aware Harness Evolution）則根據答案準確率與視覺成本來評估並保留修訂版本。這兩個機制共同將執行經驗轉化為可重複使用的程式碼改進。

**Q5：相較於先前的工作，Video-RSI 的關鍵創新是什麼？**
A：Video-RSI 的關鍵創新在於將「證據基礎」與「選擇準則」這兩個面向結合起來。不同於僅依賴執行軌跡進行修訂的方法，Video-RSI 透過主動影片調查回到原始影片中蒐集新證據，從而區分取樣落差、知覺錯誤與證據使用不當等不同的失敗模式。同時，它不只看準確率，還將視覺成本納入修訂版本的保留標準，使得改進能同時兼顧效果與效率。這種「診斷導向的程式碼修訂加上成本感知的選擇」的組合，是先前自動化代理設計工作未曾充分處理的。

**Q6：框架中有哪些重要的設計選擇？**
A：首先是讓同一個凍結模型同時擔任 Solver 與 Editor，這避免了引入額外的強模型或人類標註。其次，演化過程是離線進行的——選定的框架在評估新問題時會被凍結，這保證了部署時的可預測性與穩定性。再者，框架將觀察策略與證據處理程序視為一個整體進行聯合演化，而非單獨優化某個元件。最後，視覺成本被明確納入保留準則，使得「更密集的取樣」這類看似能提升準確率但成本過高的修訂會被拒絕。

**Q7：實驗使用了哪些基準測試？**
A：根據摘要與內文，Video-RSI 在四個影片理解基準測試上進行了評估。雖然具體的基準名稱在提供的段落中未完整列出，但內文明確提到 MLVU 是其中之一，並在 MLVU 上比較了主動調查與僅依軌跡修訂的效果。這些基準涵蓋了長影片理解的典型場景，能夠有效測試代理在時間跨度長、資訊密度低的影片中的表現。

**Q8：主要的實驗結果為何？**
A：實驗結果顯示，演化後的代理在準確率上有所提升，同時處理的影格數量減少，達到了更佳的準確率與效率權衡（accuracy-efficiency trade-off）。更具體地說，在 MLVU 上，主動影片調查所帶來的最終準確率高於僅依軌跡進行修訂的方法，且兩者在推論時的影格使用量相近。這證明了「回到影片中蒐集新證據」這個步驟對於診斷失敗確實有實質價值，而非僅是增加成本。

**Q9：論文中進行了哪些消融實驗或分析？**
A：論文中對「調查」與「演化」兩個動態進行了分析，並在 MLVU 上比較了主動調查與僅依軌跡修訂的效果，這構成了一項重要的消融實驗。結果顯示主動調查能帶來更高的最終準確率，證明了重新檢視訓練影片的價值。此外，框架同時追蹤準確率與視覺成本的演化軌跡，這也間接展示了成本感知選擇機制的作用——若僅以準確率為標準，可能會保留那些成本過高的修訂。

**Q10：哪些實際場景會從這項工作中受益？**
A：任何需要處理長影片且對成本敏感的應用都將受益，例如影片監控分析、長篇教學影片的內容理解、體育賽事回顧與戰術分析，以及醫療手術影片的記錄查詢。在這些場景中，影片長度可能從數十分鐘到數小時不等，逐一檢視所有影格既不經濟也不必要。Video-RSI 透過讓代理學會更聰明地選擇觀察點，能在維持準確率的前提下大幅降低運算成本，使其更適合實際部署。

**Q11：從產品化的角度，這項研究帶來哪些考量？**
A：產品化時需要考量幾個面向。首先，雖然推論階段使用的是凍結框架、行為可預測，但離線演化階段仍需要相當的運算資源來反覆測試修訂版本，這對小型團隊可能是門檻。其次，演化後的框架是針對特定基準或訓練影片分布優化的，部署到差異較大的真實場景時可能需要重新演化。再者，視覺成本的降低對邊緣裝置部署尤其有利，但具體的成本節省幅度仍需依任務與影片特性而定。

**Q12：這項工作對領域的更廣泛影響是什麼？**
A：這項工作展示了「程式碼層級的自我改進」在影片理解中的可行性，開啟了一個新的研究方向：不再執著於訓練更大的模型，而是讓模型學會改進自己使用證據的方式。這種思路與近期「以程式碼作為優化空間」的自動化代理設計潮流相互呼應，但將其推進到視覺成本敏感的領域。此外，「主動調查」的概念也提示了一個更廣泛的原則——當僅憑軌跡不足以診斷失敗時，回到原始輸入中蒐集新證據是值得的，這對其他模態的代理設計也有啟發。

**Q13：論文所承認的限制有哪些？**
A：雖然提供的段落未完整列出所有限制，但從方法描述可以推論出幾項。首先，演化過程依賴訓練影片的代表性，若訓練分布與部署分布差異過大，演化出的框架可能無法泛化。其次，視覺成本的衡量是以影格數量為主，但實際部署中還涉及其他成本（如 API 呼叫、推論時間），這些可能未被完整納入。再者，框架的修訂是由同一個語言模型產生，其修訂能力受模型本身程式碼生成品質的限制。

**Q14：這項方法可能會在哪些情況下失敗？**
A：當失敗原因並非出在證據擷取或處理程序，而是出在語言模型本身的推理能力時，框架演化無法解決此問題。例如，若模型對某類常識推理有根本性的不足，無論如何調整觀察策略都無法提升準確率。此外，若訓練影片中的失敗案例不具代表性，演化可能會過度擬合這些特定模式，反而損害在一般案例上的表現。還有一個潛在風險是「成本作弊」——框架可能學會在評估集上以低成本碰巧答對，但缺乏真正的理解。

**Q15：未來的研究方向有哪些？**
A：未來可以朝幾個方向延伸。第一，將主動調查與成本感知演化的思路推廣到其他模態或多模態代理，例如音訊理解或機器人控制。第二，結合程式碼層級演化與模型層級的微調，探索兩者的互補效益。第三，研究如何讓演化過程更高效，例如透過更好的修訂候選生成策略或更聰明的搜尋演算法。第四，探討如何讓演化出的框架具備更好的可解釋性與可審查性，這對於高風險應用至關重要。最後，可以研究如何在多個任務或領域間進行框架的遷移與共享。

**2. 體育賽事與戰術分析助理**
教練團需要從 90 分鐘以上的比賽影片中提取戰術執行、球員跑位或犯規細節。Video-RSI 的成本感知演化機制可讓代理學會優先檢視高機率出現目標事件的區段（例如死球後的攻防轉換），並在低資訊密度區段降低取樣密度，兼顧分析深度與即時性。

**3. 自駕車與機器人長時段行車紀錄分析**
自駕車隊每日產生數百小時的感測與影片紀錄，事故回放、邊緣案例挖掘需快速定位關鍵 30 秒。Video-RSI 可演化出「先全域粗掃再針對異常時段細看」的框架，幫助工程團隊在固定模型下持續優化證據擷取策略，無需重新訓練模型。

**4. 教育與企業訓練影片的智慧助教**
企業內訓、MOOC 或手術教學影片往往長達數小時，學員提問可能涉及特定章節或操作步驟。Video-RSI 讓助教代理能根據過往問答失敗案例，主動回頭調查訓練影片、診斷「是沒看到還是看錯了」，並演化出更精準的章節定位與證據整合邏輯。

**5. 媒體內容審核與版權偵測**
影音平台需從長片（電影、Podcast 錄影、長直播）中找出抄襲片段、敏感內容或廣告插入點。Video-RSI 的成本感知演化可讓審核代理在維持高召回率的同時，動態調整影格取樣密度，處理每日數萬小時的 UGC（使用者生成內容）。

### 實作前置條件

**資料需求**
- **訓練影片集**：需準備一批帶有問題—答案對的影片集合（建議至少數百題），用於驅動演化迴圈中的失敗診斷與框架評估。影片長度建議涵蓋目標應用的典型分佈（例如 5 分鐘至 2 小時）。
- **驗證與測試集**：需有獨立的影片問答基準（例如 MLVU、VideoMME、EgoSchema 等），用於評估演化後框架的泛化能力，避免在訓練影片上過擬效。
- **執行軌跡日誌**：每次代理執行的影格選取、工具呼叫、中間推理皆需完整記錄，作為失敗診斷的依據。

**運算資源**
- **基礎多模態模型**：需具備視覺理解能力的多模態大型語言模型（MLLM），例如 GPT-4o、Gemini、Qwen-VL、InternVL 等；模型權重在整個流程中保持凍結。
- **推理算力**：演化過程中每輪會對訓練集執行多次完整代理推論（用於診斷與候選評估），建議準備可並行呼叫的 API 額度或本地 GPU 叢集。
- **程式碼執行沙箱**：框架修訂涉及執行程式碼並觀察行為，需具備隔離、可重現的執行環境（容器或受限沙箱）。

**技能前提**
- 熟悉 Python 與代理框架（如 LangChain、AutoGen、或自製迴圈），能撰寫可被語言模型編輯的可執行框架程式碼。
- 具備提示工程（prompt engineering）經驗，特別是設計「失敗診斷」與「程式碼修訂」的指令模板。
- 了解影片處理基礎（影格抽樣、視訊解碼、視覺標記），以及成本指標（影格數、token 用量、延遲）的量測方式。
- 對自動化代理設計（ADAS、AFlow、Meta-Harness）有基本認識，有助於設計演化搜尋空間。

### 實作步驟建議

**步驟一：定義可執行框架（Harness）的介面契約**
將代理行為抽象為可被語言模型編輯的程式碼模組，明確劃分：(1) 證據擷取層（影格取樣、區段定位、工具呼叫）；(2) 證據處理層（描述生成、跨影格整合）；(3) 推理與回答層。介面需保持穩定，使語言模型能針對內部邏輯提出局部修訂，而非整個重寫。

**步驟二：建立初始框架與基準代理**
實作一個「合理但非最優」的初始框架（例如均勻取樣 + 簡單推理），在驗證集上量測初始的答案準確率與視覺成本（影格數、token 用量）。此基準將作為後續演化的比較對象。

**步驟三：實作主動影片調查（Active Video Investigation）機制**
設計一個「調查迴圈」：當代理在訓練題上答錯時，提示同一個語言模型扮演「調查者」角色，重新檢視原始影片，主動擷取現有軌跡中未涵蓋的影格或區段，以測試「是取樣落差還是知覺錯誤」。調查結果需以結構化方式（例如失敗分類標籤 + 證據片段）回傳給編輯階段。

**步驟四：設計診斷引導的程式碼修訂提示**
編寫 Editor 提示模板，要求語言模型根據調查證據提出具體的程式碼修訂，並說明修訂如何對應診斷（例如「因取樣過疏導致漏看事件 X，建議在時間段 Y 增加密度」）。限制每次修訂的範圍（例如只改一個函式），便於歸因與回溯。

**步驟五：建立成本感知的候選評估機制**
對每個修訂候選，在訓練子集上執行完整代理流程，記錄兩個指標：(1) 答案準確率；(2) 視覺成本（總影格數、總 token）。採用帕累托（Pareto）篩選或加權分數，僅保留「準確率提升且成本不顯著增加」或「成本下降且準確率不顯著下降」的修訂進入下一輪。

**步驟六：執行迭代演化並設定停止條件**
將「調查 → 修訂 → 評估 → 篩選」組成迴圈，每輪從保留的修訂出發繼續演化。設定停止條件，例如：連續 N 輪無 Pareto 改善、達到預算上限（API 成本或時間）、或驗證集準確率開始下降。

**步驟七：凍結最終框架並部署評估**
演化完成後凍結最終框架程式碼，在獨立測試集上量測最終的準確率—效率權衡。部署時僅需載入凍結的框架與基礎 MLLM，無需在推論時執行演化邏輯。

**步驟八：建立監控與再演化機制**
上線後持續收集新影片問答的執行軌跡與失敗案例，定期（例如每月）以新資料驅動新一輪演化，避免框架在資料漂移下退化。

### 潛在風險與注意事項

**風險一：演化陷入「成本下降但準確率崩塌」**
成本感知的篩選若權重設計不當，可能獎勵「少看就少錯」的退化路徑。
**緩解**：在評估函數中對準確率設定最低門檻（例如不得低於初始框架的 95%），並監控 Pareto 前緣的形狀，避免單點最優解。

**風險二：主動調查產生幻覺證據**
語言模型可能在「調查」階段編造未實際觀察到的影片內容，誤導修訂方向。
**緩解**：強制調查階段必須回傳具體的影格編號或時間戳，並與實際擷取的視覺特徵比對；對調查結論與實際證據不一致的案例予以標記與懲罰。

**風險三：過擬效訓練影片分佈**
演化可能過度擬合訓練集的影片類型與問題模式，在新影片上表現下降。
**緩解**：保留獨立的驗證集用於早停（early stopping）；在測試集上量測泛化差距；若差距過大，限制演化輪數或加入正則化（例如要求修訂具備可解釋性）。

**風險四：程式碼修訂破壞框架穩定性**
語言模型提出的修訂可能引入語法錯誤、無窮迴圈或資源洩漏。
**緩解**：所有候選修訂必須在隔離沙箱中執行，並設定超時與資源上限；對執行失敗的候選直接淘汰，不進入評估。

**風險五：演化成本失控**
每輪演化需多次完整代理執行，API 或 GPU 成本可能快速累積。
**緩解**：設定每輪與總預算上限；採用小訓練子集先做快速篩選，僅對通過初篩的候選執行完整評估；記錄並視覺化成本趨勢。

**風險六：基礎模型版本變動導致框架失效**
若部署期間替換底層 MLLM，原本演化的框架可能不再適用。
**緩解**：將框架設計為模型無關（透過抽象介面），並在更換模型後以小樣本快速重新校準；保留演化日誌以便追溯。

### 與其他技術的整合建議

**與 RAG（檢索增強生成）系統整合**
Video-RSI 的證據擷取層可與向量資料庫結合：將影格或短片段嵌入向量空間，讓代理在調查階段能進行語意檢索，而僅對檢索命中的片段做細部視覺檢查，進一步降低視覺成本。

**與影片摘要與章節偵測工具鏈整合**
在框架的證據擷取層引入預訓練的章節偵測模型（例如 TransNetV2、SceneDetect），讓語言模型在修訂時可選擇「以章節為單位」或「以影格為單位」進行取樣，擴大演化搜尋空間。

**與可觀測性平台整合**
將執行軌跡、影格選取紀錄、成本指標串接至可觀測性平台（如 LangSmith、Phoenix、OpenTelemetry），方便追蹤演化過程中的行為變化，並對失敗案例進行根因分析。

**與多代理協作框架整合**
Video-RSI 的單一凍結模型可作為「證據擷取專家」，與其他專責推理、驗證、彙整的代理組成多代理系統；框架演化可針對該代理在系統中的角色進行專門優化。

**與 CI/CD 與 MLOps 流程整合**
將演化流程包裝為可重現的 pipeline：訓練資料版本化、框架程式碼版本化、評估結果入庫；每次演化產出新框架候選時，自動觸發測試集評估與人工審核（針對高風險場景），通過後再部署。

**與人類回饋強化學習（RLHF）整合**
演化過程中可引入人類對修訂候選的偏好評分（例如「這個修訂更符合業務邏輯」），將其作為成本感知評估之外的第二篩選標準，使框架演化兼顧自動化效率與領域專業。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的圖 1 與第 2.1 節，建立「影片代理 = 工具 + 框架 + 模型」的直觀理解；接著跳到貢獻列表，掌握 Video-RSI 的三大核心概念（主動調查、成本感知演化、凍結模型下的遞迴改進）。實作上可先從複製官方程式碼、跑通最小範例開始，暫時略過理論細節。

**給 AI 工程師**：重點關注第 2.2 節（自動化代理設計）與第 3 節的方法細節，特別是「調查—修訂—評估」三階段的介面設計與提示工程。實作時建議先在小型影片集上重現演化迴圈，量測每輪的成本與準確率變化，再逐步擴展到完整基準。程式碼層級的演化與傳統 prompt tuning 思維不同，需特別注意沙箱隔離與可重現性。

**給研究者**：本文在「遞迴自我改進」與「證據驷取成本」之間建立了新的權衡軸，建議從第 4 節的實驗設計切入，分析 MLVU 上「主動調查 vs. 僅軌跡修訂」的消融實驗，理解為何「回頭看影片」能帶來額外訊號。可進一步探索的方向包括：不同 MLLM 骨幹下的演化效率、調查階段的資訊理論下界、以及與程式碼演化（code evolution）文獻的連結。

**給產品經理**：Video-RSI 的核心價值在於「不改模型也能持續優化」，這對已部署固定模型、但希望隨業務演進提升效果的產品特別有吸引力。建議關注第 4 節的「準確率—效率權衡」結果，理解框架演化能帶來多少影格節省與準確率提升；同時評估自家影片問答場景的失敗模式是否落在「取樣落差」或「知覺錯誤」這兩類，以判斷導入此框架的潛在 ROI。導入時建議先以單一業務線 POC 驗證，再考慮擴展。
