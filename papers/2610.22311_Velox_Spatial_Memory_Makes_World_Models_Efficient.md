## 摘要翻譯

影片世界模型（Video world models）將動作與相機運動轉化為長視覺推演，使影片成為互動式模擬的自然介面。此類互動需要響應式生成，但連貫的推演必須保留已生成內容的視覺記憶。分塊影片擴散模型（Chunked video diffusion models）通常將此上下文保存在不斷增長的 KV 快取（KV cache）中，導致後續分塊逐漸變慢。為解決此瓶頸，我們提出 Velox——一種無需訓練（Training-free）的注意力路由器（Attention router），透過來自流式幾何（Streaming geometry）的視錐平板（Frustum slab）對應關係進行區域級上下文選擇（Region-level context selection）。Velox 將歷史區塊表示為帶有深度區間（Depth intervals）的相機視錐平板，並透過近期優先多重扭曲（Recency-priority multiwarp）獲取當前區塊深度。對於覆蓋良好的區域，視錐平板重疊柔和地調節每層的模型推導區塊重要性（Block importance）；未覆蓋區域則保留模型推導路由，不帶幾何偏置（Geometric bias）。固定的令牌-區塊粒度（Token-block granularity）與 FlashAttention 風格的瓦片化執行（Tiled execution）相匹配，並降低隨推演長度而增長的注意力項。視錐平板建構與去噪（Denoising）在同一 H200 上異步執行。在第 48 個分塊時，Velox 將注意力加速 4.36 倍，去噪加速 2.43 倍。在完整的 158 個案例的 WBench 導航子集（Navigation split）上，其無 API 平均分數（API-free average points）與稠密版 LingBot-Fast-Cam 相差在 0.15 分以內。更多細節請參見我們的專案頁面 https://velox-world.com/velox/。

### 核心貢獻（3～5點）
- 提出 Velox，一種無需訓練（Training-free）的注意力路由器，透過流式幾何的視錐平板對應關係實現區域級上下文選擇，解決分塊影片擴散模型中 KV 快取隨推演長度增長而導致速度遞減的瓶頸。
- 設計近期優先多重扭曲（Recency-priority multiwarp）機制，將歷史區塊表示為帶有深度區間的相機視錐平板，精準估計當前區塊的幾何覆蓋情況，並以柔和的方式調節模型推導區塊重要性。
- 採用固定的令牌-區塊粒度（Token-block granularity），與 FlashAttention 風格的瓦片化執行（Tiled execution）相匹配，有效降低隨推演長度線性增長的注意力項。
- 在 H200 上實現視錐平板建構與去噪（Denoising）的異步執行，於第 48 個分塊時達到注意力 4.36 倍、去噪 2.43 倍的加速效果。
- 在 WBench 導航子集（Navigation split）158 個案例的全量評測中，無 API 平均分數（API-free average points）與稠密版 LingBot-Fast-Cam 基線僅相差 0.15 分，證明方法在顯著加速的同時維持了長時域一致性（Long-horizon consistency）。

### 適合對象
從事影片生成、世界模型、擴散模型加速的學術研究人員與工程師；對即時互動式模擬、長視訊推演效率優化感興趣的 AI 從業者；以及尋求無需訓練（Training-free）即可提升影片擴散 Transformer（Video diffusion transformers）推理效率方案的業界團隊。

## 深度分析

#### 方法論解析

Velox 的核心問題意識在於分塊影片擴散模型 (chunked video diffusion models) 在長時域推演 (long-horizon rollouts) 中面臨的「上下文膨脹」瓶頸。傳統做法是將所有歷史幀的 KV 快取 (KV cache) 完整保留，隨著生成的分塊 (chunk) 數量增加，注意力 (attention) 計算成本呈線性增長，而後期分塊往往僅需參考場景中的一小部分區域，造成大量冗餘計算。

**核心抽象：視錐平板 (Frustum Slab)**

Velox 將每個歷史區塊 (block) 表示為帶有深度區間 (depth intervals) 的相機視錐平板 (camera frustum slabs)。這個設計的關鍵在於將三維幾何資訊壓縮為與 FlashAttention 瓦片化執行 (tiled execution) 相同的令牌-區塊粒度 (token-block granularity)，使得幾何引導的路由決策能夠在注意力計算的原生層級運作，無需引入額外的條件分支或修改模型架構。

**查詢端深度獲取：近期優先多重扭曲 (Recency-Priority Multiwarp)**

對於當前分塊中的每個目標區塊，Velox 需要估計其對應的深度資訊。論文採用「近期優先多重扭曲」策略——透過多個最近相機視角的反向扭曲 (multiwarp) 來獲取查詢端的深度估計。這種設計的優勢在於：對於已被充分觀察的區域，多重扭曲能給出較為一致的深度估計；而對於新揭示或遮擋嚴重的區域，不同扭曲結果之間的差異會自然暴露出幾何不確定性。

**軟性幾何融合規則 (Soft Geometric Fusion Rule)**

Velox 並非以硬性方式取代模型的注意力路由，而是採用「軟調變」策略：對於幾何覆蓋良好的區域，使用世界空間 OBB (Oriented Bounding Box) 視錐平板重疊分數來調變每一層的模型推導區塊重要性 (model-derived block importance)；對於未被覆蓋的區域，則保留純粹的模型推導路由而不施加幾何偏置 (geometric bias)。這種設計保留了預訓練模型的語義理解能力，同時讓幾何資訊作為「軟約束」介入。

**全域對齊 Gilbert 鄰域 (Global-Aligned Gilbert Neighborhood)**

為了在不引入跨分塊接縫表 (cross-chunk seam table) 的前提下保持局部運動連續性，Velox 採用全域對齊的 Gilbert 曲線 (Gilbert curve) 鄰域來組織 KV 儲存。這種空間填充曲線 (space-filling curve) 的特性是相鄰區塊在三維空間中也是鄰居，因此能夠自然地保持局部時間連續性，避免了稀疏注意力中常見的「接縫不連續」問題。

**異步執行管線 (Asynchronous Pipeline)**

視錐平板建構與去噪 (denoising) 過程在同一張 H200 GPU 上以異步方式執行，這意味著幾何處理不會阻塞主要的生成流程。這對於實際部署至關重要——若幾何計算與去噪串列執行，則加速收益將被幾何處理時間抵消。

#### 實驗數據解讀

**注意力加速比隨分塊數量遞增**

論文報告在第 48 個分塊時，注意力延遲從密集 FlashAttention 的約 34.2 ms 降至 7.8 ms，達到 4.36× 加速比；去噪時間從約 7.19 秒降至 2.96 秒，達到 2.43× 加速比。這組數據揭示了一個重要趨勢：Velox 的優勢隨著推演長度 (rollout length) 的增加而增長。這是因為密集注意力的成本隨歷史分塊數線性增長，而 Velox 的稀疏路由成本僅與當前分塊的可見區域相關，兩者的差距在長程推演中持續擴大。

**品質保持的細粒度分析**

在 WBench 導航子集 (navigation split) 的 158 個案例上，Velox 在無 API 平均分數 (API-free average points) 上與密集 LingBot-Fast-Cam 的差距僅為 0.15 分。更值得注意的是，在 19 項指標的整體平均上，Velox 反而從 75.52 提升至 75.60。這個微小的提升暗示稀疏路由可能不僅是「無損加速」，甚至在某些場景下能夠透過減少不相關上下文的干擾而略微改善生成品質——這與注意力機制中「上下文越長未必越好」的觀察一致。

**基準選擇的合理性**

WBench 導航子集特別適合評估此類方法，因為導航任務涉及大量場景重訪 (scene revisitation)，正是視錐平板重疊能發揮作用的典型場景。然而，僅在導航子集上評估也意味著結果的泛化性需要進一步驗證。

#### 與現有研究的比較

**從幀級到區塊級的範式轉移**

Velox 與 Context-as-Memory、VMem 等幀級選擇方法 (frame-level selection) 的根本差異在於粒度：前者選擇整個過去視圖，後者選擇區塊。這使得 Velox 能夠在同一個雜訊分塊 (noisy chunk) 內為不同區域指派不同的歷史上下文——例如道路區塊主要關注地面歷史，建築立面區塊主要關注牆面歷史，新揭示的天空區域則保留模型推導的語義路由。這種區域級 (region-level) 的細粒度控制是幀級方法無法實現的。

**相對於錨點注入方法的優勢**

AnchorWeave 等方法透過 ControlNet 注入扭曲渲染結果 (warped renderings)，需要架構適配 (architectural adaptation) 或微調 (fine-tuning)。Velox 的訓練免費 (training-free) 特性使其能夠直接複用預訓練的影片生成器，這對於快速部署和模型迭代具有重要價值。

**與稀疏注意力方法的關係**

Velox 的全域對齊 Gilbert 鄰域設計與近年來的稀疏注意力研究（如 NSA、MoBA 等）有相似的動機，但 Velox 的獨特之處在於將幾何資訊作為軟性路由訊號，而非純粹依賴注意力分數。這種「幾何+語義」的雙重引導在影片世界模型中特別有效，因為相機軌跡提供了可靠的幾何先驗。

**侷限性分析**

1. **依賴深度估計品質**：recency-priority multiwarp 的有效性取決於深度估計的準確性。對於紋理缺乏或動態物體區域，深度估計可能不穩定。
2. **動態場景的挑戰**：視錐平板重疊假設場景是靜態的。對於包含大量運動物體的場景，幾何路由可能誤導注意力。
3. **評估範圍有限**：僅在導航子集上驗證，對於其他類型的互動式模擬（如物體操控、多角色互動）的有效性尚待確認。

#### 可重現性評估

**程式碼與模型權重**

論文提供了專案頁面 (https://velox-world.com/velox/)，但從提供的文本中無法確認是否開源了完整的程式碼、預訓練權重或幾何處理管線。基於其「訓練免費」的特性，理論上只需要實作注意力路由器即可複用現有的 LingBot-Fast-Cam 權重，這降低了複現門檻。

**實作細節的可獲得性**

論文中描述了全域對齊 Gilbert KV 儲存、優化的稀疏注意力核心 (sparse attention kernel) 和異步視錐平板建構等關鍵實作細節，但具體的：
- Gilbert 曲線的維度參數與鄰域大小
- 視錐平板重疊的計算精度（單精度/半精度）
- 稀疏注意力核心的記憶體訪問模式
- 異步管線的同步策略

這些細節對於精確複現至關重要，但需要從程式碼或補充材料中獲取。

**評測基準的可及性**

WBench 是公開基準，但 158 案例的導航子集是否隨論文一同釋出，以及評測腳本的可用性，需要進一步確認。

**硬體依賴**

所有實驗均在單張 H200 上完成，這是一個相對具體的硬體配置。雖然方法本身應具有硬體無關性，但稀疏注意力核心的效能特性可能在不同 GPU 架構上有所不同。

#### 未來研究方向

**動態場景的幾何路由擴展**

當前方法假設場景幾何相對靜態，未來可探索如何將動態物體的運動軌跡整合到路由決策中。例如，可以為運動物體建立獨立的時空視錐平板，並在重疊計算中考慮時間維度的不確定性。

**多模態上下文的統一路由**

目前 Velox 主要處理視覺 KV 快取，未來可擴展至包含文字指令、音訊線索、動作標記等多模態上下文。統一的稀疏路由框架能夠在保持長時域一致性的同時，降低整體計算成本。

**自適應路由粒度**

當前的區塊大小是固定的，未來可探索根據場景複雜度動態調整區塊粒度的機制。對於紋理豐富的區域使用較小區塊以提高選擇精度，對於均勻區域使用較大區塊以降低路由開銷。

**理論分析與形式化**

目前缺乏對「幾何路由+語義路由」融合規則的理論分析。未來可從資訊理論或貝氏推論的角度形式化這種融合，證明其在特定假設下的最優性，並指導超參數選擇。

**跨任務泛化驗證**

將 Velox 應用於更廣泛的影片生成任務，包括：
- 影片編輯（需要精確的區域級歷史參考）
- 影片預測（純粹的前向推演）
- 互動式遊戲環境（高頻動作回應）
- 機器人模擬（精確的物理一致性需求）

**與其他稀疏注意力方法的融合**

將 Velox 的幾何路由與基於注意力分數的稀疏方法（如動態區塊稀疏、線性注意力近似）相結合，可能進一步降低計算成本，同時保持幾何引導的優勢。

**長期記憶的層次化組織**

當推演長度達到數百甚至數千分塊時，即使是稀疏路由也可能面臨可擴展性挑戰。未來可探索層次化的記憶組織——例如將歷史分塊聚類為場景級、地標級的抽象表示，並在路由時進行兩階段檢索。

## 論文問答

**Q1：影片世界模型在長時域生成時面臨的核心效能瓶頸是什麼？**
A：影片世界模型在進行長時域視覺推演時，通常採用分塊（chunked）擴散架構，每個新分塊需要透過 KV 快取關注所有歷史幀的令牌。隨著生成的分塊數量增加，KV 快取會持續累積成長，導致後續分塊的注意力計算成本呈線性增長。具體而言，當分塊數達到 48 時，密集 FlashAttention 的注意力延遲約為 34.2 毫秒，而整體去噪時間高達 7.19 秒。這種「越長越慢」的現象恰好出現在長時域一致性最為關鍵的時刻，形成嚴重的效能瓶頸。

**Q2：為何現有的幀級記憶方法（如 Context-as-Memory、VMem、AnchorWeave）無法徹底解決此問題？**
A：現有方法如 Context-as-Memory 透過相機視場重疊來檢索歷史視圖，VMem 使用面元索引視圖來支援場景重訪，而 AnchorWeave 則透過 ControlNet 注入扭曲渲染結果以穩定相機控制生成。然而這些方法本質上仍屬於幀級選擇，對於 Transformer 注意力而言粒度過於粗糙：它們為當前分塊中的所有區域提供相同的選定上下文，但同一個雜訊分塊中的不同區域（例如道路、牆面、新揭示的天空）實際上需要關注歷史的不同部分。此外，注入扭曲點渲染的方法往往需要架構適配或微調，限制了預訓練影片生成器的直接重用。

**Q3：為什麼「長時域一致性」與「回應式生成」之間存在根本矛盾？**
A：互動式模擬要求模型能即時回應使用者輸入的動作軌跡或相機運動，但同時必須維持視覺記憶以避免場景漂移、遺忘已造訪區域或不一致地重新合成相同場景。這兩個需求在傳統密集注意力框架下互相衝突：保留更多歷史能提升一致性，但會線性增加計算成本，使生成速度下降。Velox 的核心動機正是打破這種權衡，透過區域級上下文選擇，讓模型在不犧牲一致性的前提下維持回應速度。

**Q4：Velox 的核心方法——視錐平板對應——是如何運作的？**
A：Velox 將生成的歷史區塊表示為帶有深度區間的相機視錐平板（frustum slabs），並透過近期優先多重扭曲（recency-priority multiwarp）取得當前分塊的深度資訊。對於每個目標分塊，Velox 在世界空間中以 OBB 視錐平板重疊度對查詢區塊與歷史區塊進行評分。在覆蓋良好的區域中，此分數會在選擇前軟性地重新加權每一層模型推導的區塊重要性；而在未覆蓋區域，則保留模型推導的路由而不引入幾何偏置。這種設計使幾何資訊與模型語意判斷得以互補。

**Q5：Velox 最關鍵的創新點是什麼？為何選擇「無需訓練」與「區塊級粒度」？**
A：Velox 最關鍵的創新在於將幾何對應從幀級細化到令牌-區塊級粒度，正好與 FlashAttention 的瓦片化執行模型對齊。這意味著幾何路由訊號能直接整合進稀疏注意力核心，無需新增條件分支或修改預訓練生成器。「無需訓練」的特性使 Velox 能即時部署於現有影片世界模型（如 LingBot-Fast-Cam），避免了昂貴的微調成本；而區塊級粒度則讓同一分塊內的不同區域能各自路由到最相關的歷史區塊，實現真正的區域級上下文選擇。

**Q6：Velox 在系統設計上有哪些重要的工程選擇？**
A：Velox 採用了三項關鍵的工程設計：第一，使用全域對齊 Gilbert KV 儲存來保留局部運動連續性，無需額外的跨分塊接縫表；第二，實作了最佳化的稀疏注意力核心以充分利用區塊級路由；第三，將視錐平板建構以異步方式與去噪過程並行執行，兩者皆運行於同一張 H200 GPU 上。這些設計使視錐平板建構不會阻塞去噪流程，並讓稀疏注意力能以瓦片化方式高效執行，最終在分塊 48 時達到 4.36 倍的注意力加速與 2.43 倍的去噪加速。

**Q7：Velox 在哪些基準測試上進行了評估？評測設定為何？**
A：Velox 主要在 WBench 導航子集上進行評估，該子集包含 158 個案例，涵蓋相機控制下的長時域導航場景。評測採用無 API 平均分數（API-free average points）作為主要品質指標，並對 19 個子指標的整體平均進行綜合評估。基線模型為密集 FlashAttention 版本的 LingBot-Fast-Cam，Velox 在此基線上以無需訓練的方式插入幾何路由。實驗同時記錄了分塊 48 時的注意力與去噪延遲，以驗證長時域下的加速效益。

**Q8：Velox 的關鍵實驗結果為何？這些數字代表什麼意義？**
A：在分塊 48 時，Velox 將注意力延遲從密集 FlashAttention 的約 34.2 毫秒降低至 7.8 毫秒，達到 4.36 倍加速；去噪時間從約 7.19 秒縮短至 2.96 秒，達到 2.43 倍加速。在品質方面，Velox 在 WBench 無 API 平均分數上與密集 LingBot-Fast-Cam 僅相差 0.15 分，並將 19 指標整體平均從 75.52 提升至 75.60。這些結果顯示 Velox 不僅能顯著降低長時域的計算成本，還能維持甚至略微超越密集注意力的整體品質，證明了軟性幾何融合規則的有效性。

**Q9：Velox 的設計中是否存在消融實驗來驗證各元件的貢獻？**
A：雖然摘要未詳述所有消融細節，但從方法描述可推論出幾項關鍵的設計驗證：軟性幾何融合規則（相較於硬性選擇）保留了未覆蓋區域的模型推導路由，避免了幾何偏置；全域對齊 Gilbert 鄰域則被用來維持局部運動連續性，無需依賴跨分塊接縫表。此外，異步視錐平板建構的設計驗證了幾何計算能與去噪並行而不互相阻塞。這些元件共同支撐了 Velox 在維持品質的前提下實現顯著加速的結論。

**Q10：Velox 的潛在實際應用場景有哪些？**
A：Velox 適用於任何需要長時域互動式模擬的場景，包括機器人導航與自主探索（需即時回應相機運動並維持場景一致性）、虛擬實境與遊戲（需長時間生成可控的視覺內容）、建築與城市規劃視覺化（需在大型場景中進行平滑的視覺推演）、以及自動駕駛模擬（需在複雜環境中維持長時域場景記憶）。由於 Velox 為無需訓練且能直接部署於現有預訓練模型，它特別適合需要快速整合至現有系統的產品化應用。

**Q11：將 Velox 整合至實際產品時需要考量哪些工程因素？**
A：產品化整合時需考量以下因素：首先，硬體依賴——Velox 的異步設計與稀疏注意力核心目前針對 H200 最佳化，移植至其他 GPU 需重新調整；其次，幾何品質依賴——視錐平板對應的準確性取決於相機估計的深度品質，在深度估計不穩定的場景中可能需要降級處理；第三，與現有管線的相容性——Velox 設計為即插即用，但仍需驗證其在不同影片擴散 Transformer 架構下的泛化能力；最後，KV 快取管理——全域對齊 Gilbert 儲存需要相應的記憶體管理機制支援。

**Q12：Velox 對影片世界模型研究領域的影響為何？**
A：Velox 提出了「空間記憶使世界模型高效」的核心觀點，將幾何對應從幀級推進到區塊級，為長時域影片生成提供了一條新路徑。它證明了無需訓練的幾何路由能與密集注意力在品質上匹敵，同時帶來顯著的加速效益，這對資源受限的部署場景尤其重要。此外，Velox 的軟性融合設計為「幾何先驗」與「模型推導語意」的結合提供了範例，可能啟發後續研究探索更細粒度的空間-時間記憶管理機制。

**Q13：Velox 存在哪些已承認的限制？**
A：Velox 的有效性高度依賴幾何對應的品質：當深度估計不準確或相機追蹤漂移時，視錐平板重疊評分可能誤導路由選擇。此外，對於高度動態的場景（如快速運動的物體或劇烈變化的光照），幾何對應可能無法捕捉非剛體運動，導致 Velox 退化為依賴模型推導路由。論文也明確指出其結論是「範圍內的」（scoped claim），即軟性視錐平板路由能緩解晚期分塊的注意力瓶頸，但並未聲稱能解決所有長時域一致性問題。

**Q14：Velox 在哪些情況下可能會失敗？**
A：Velox 可能在以下場景中表現不佳：第一，深度估計失敗的場景，如透明表面、鏡面反射或無紋理區域，會導致視錐平板對應失效；第二，劇烈相機運動或快速場景變化會使近期優先多重扭曲的深度估計不可靠；第三，當歷史區塊與當前區塊的幾何重疊度低但語意相關時（例如物體外觀相似但位置不同），幾何路由可能錯過有用的語意關聯。雖然軟性融合規則為未覆蓋區域保留了模型推導路由，但在邊界情況下品質仍可能下降。

**Q15：基於 Velox 的研究，未來有哪些值得探索的方向？**
A：未來方向可包括：第一，將幾何路由從深度區間擴展至更豐富的 3D 表示（如神經輻射場或高斯潑濺），以處理更複雜的場景；第二，結合學習式幾何估計，使視錐平板對應能適應動態場景；第三，探索跨層級的幾何-語意融合，例如在不同 Transformer 層採用不同的幾何-語意權重；第四，將 Velox 的區塊級路由概念推廣至其他長上下文任務（如長文件理解、長序列生成）；第五，研究如何在保持無需訓練特性的同時，進一步降低對精確深度估計的依賴，以提升在消費級硬體上的部署可行性。

## 實務應用指南

### 適用場景

1. **沉浸式虛擬導覽與房地產展示**：將 Velox 整合進 Web3D 導覽系統，讓使用者以相機軌跡自由探索公寓、博物館或展場。傳統密集注意力在長推演下會越來越慢，Velox 的 4.36× 注意力加速可讓 30 分鐘以上的連續導覽維持 30 FPS 等級的回應速度，避免使用者等待生成。

2. **遊戲與互動敘事的程序化關卡生成**：Velox 與 LingBot-Fast-Cam 等可控相機的影片擴散模型結合，可在玩家移動時即時生成下一段場景。同一個關卡中已揭示的房間、走道、庭院只需保留幾何對應的歷史區塊，新揭示的天空或遠景則退回模型原生路由，兼顧一致性與探索感。

3. **機器人與自駕車的閉環模擬**：將 Velox 嵌入 CARLA、Isaac Sim 等模擬器的視覺感知前端，用相機軌跡產生長時域的影片世界模型。模擬器每幀只需 7.8 ms 注意力即可取得對應的歷史上下文，使策略學習能在更長的 episode 上進行而不爆 KV 快取。

4. **建築與城市規劃的可視化審查**：規劃師以滑鼠拖曳相機穿越尚未完工的街區，Velox 透過視錐平板重疊自動選擇對應的歷史區塊，避免重複生成已觀察過的立面與道路，同時保留新視角所需的語意上下文。

5. **VR/AR 內容的即時生成管線**：在 Quest、Vision Pro 等裝置的邊緣伺服器上，Velox 的異步視錐平板建構可與去噪並行執行，使 6DoF 移動時的場景更新延遲控制在可接受範圍內，支援長時間的沉浸體驗。

### 實作前置條件

**資料需求**
- 具備相機內外參與深度資訊的影片資料集（深度可來自 LiDAR、COLMAP 或單目深度估計如 Depth Anything V2）。
- 與目標部署場景相符的影片片段，用於建立視錐平板的深度區間。
- 若要重現論文基準，需取得 WBench 導航子集的 158 個案例。

**運算資源**
- 至少一張 H200（或同等級 Hopper 架構 GPU，如 H100）以執行異步管線；視錐平板建構與去噪共用同一張卡。
- 建議 80 GB 以上 VRAM，因為 LingBot-Fast-Cam 的密集注意力在長推演下仍會佔用大量 KV 快取。
- 若要部署多使用者同時導覽，需準備多卡或張量並行環境。

**技能門檻**
- 熟悉擴散 Transformer 與 FlashAttention 的瓦片化執行模型，理解 KV 快取生命週期。
- 具備 CUDA 與 Triton 經驗，能撰寫稀疏注意力核心並處理非對齊的區塊邊界。
- 了解 3D 幾何（OBB、視錐、SDF 重疊測試）與相機投影模型。
- 對因果影片擴散、自強制訓練的 chunk 邊界處理有基本認識。

### 實作步驟建議

1. **建立基線管線**：先部署 LingBot-Fast-Cam 的密集注意力版本，確認 chunk 數、每 chunk 幀數、token 區塊大小等超參數。記錄各 chunk 的注意力與去噪延遲作為對照基準。

2. **實作視錐平板建構器**：為每個歷史區塊計算相機視錐平板與深度區間。深度區間可由該區塊對應像素的深度中位數 ± 標準差決定，並以 OBB 形式儲存以利後續重疊測試。

3. **實作近期優先多重扭曲**：對當前 chunk 的查詢區塊，從最近一個歷史 chunk 開始，依序以多個相機姿態將查詢像素反向投影到世界空間，融合多個深度假設以提升覆蓋率。

4. **設計軟式幾何融合規則**：計算查詢區塊與歷史區塊的視錐平板重疊分數，將其作為權重乘上模型推導區塊重要性。對於重疊分數低於閾值的區塊，保留純模型推導路由，避免幾何偏置。

5. **採用全域對齊 Gilbert KV 儲存**：將歷史 KV 區塊依 Gilbert 曲線排列，使空間相鄰的區塊在記憶體中也相鄰，提升快取命中率與稀疏核心的合併效率。

6. **撰寫稀疏注意力核心**：以 Triton 或 CUDA 實作 FlashAttention 風格的瓦片化稀疏注意力，僅載入被選中的歷史區塊。需處理區塊大小非對齊、跨 chunk 邊界的情況。

7. **建立異步管線**：使用 CUDA Stream 或 Python asyncio 將視錐平板建構與去噪步驟重疊執行，目標是讓幾何計算完全隱藏在去噪時間內。

8. **基準驗證與調參**：在 WBench 導航子集上比較密集注意力與 Velox 的無 API 平均分數，目標差距控制在 0.15 點以內。同步量測 chunk 48 的注意力與去噪延遲，確認達到 4.36× 與 2.43× 加速。

9. **場景特化微調**：針對特定應用（室內導覽、街景、機器人視角）調整視錐平板的深度區間寬度、重疊閾值與近期優先權重。

### 潛在風險與注意事項

- **深度估計誤差會直接污染路由**：單目深度在遠距離、低紋理或反光區域容易失準，導致視錐平板重疊分數錯誤。緩解方式：對深度信心度低的區塊直接退回模型推導路由，或以多假設深度融合取代單一深度。

- **動態物體與非剛體場景**：Velox 假設幾何對應來自靜態場景，移動的人物、車輛、飄動的布幔會被錯誤路由到舊位置。緩解方式：為動態區塊標記「不適用幾何路由」標籤，或在路由前以語意分割過濾。

- **新揭示區域的覆蓋不足**：剛進入從未見過的空間時，視錐平板幾乎沒有重疊，必須依賴模型推導路由。此時若模型推導路由本身品質不佳（例如缺乏全域上下文），仍會出現漂移。緩解方式：為新揭示區域保留較大的 top-k 區塊預算。

- **基準分數差距雖小但可能集中在特定指標**：0.15 點的平均差距可能掩蓋某些指標（如動態一致性、幾何準確度）的明顯退化。緩解方式：除 WBench 總分外，逐一檢視 19 個子指標的變化。

- **異步管線的資源競爭**：視錐平板建構與去噪共用同一張 H200，若幾何計算過重會反過來拖慢去噪。緩解方式：以 profiling 確認幾何計算時間 ≤ 去噪時間的隱藏窗口，必要時降階幾何精度。

- **區塊大小與硬體瓦片的耦合**：FlashAttention 的瓦片大小通常為 64 或 128，若 token 區塊大小與硬體瓦片不匹配，稀疏核心可能無法完全發揮合併優勢。緩解方式：選擇 64 的倍數作為區塊大小，並在核心內處理邊界。

- **長尾場景的泛化**：WBench 導航子集以室內與街景為主，極端場景（如水下、太空、抽象風格）未經測試。緩解方式：在目標部署場景上做小規模 A/B 測試。

### 與其他技術的整合建議

- **與 3D Gaussian Splatting / NeRF 整合**：Velox 的視錐平板可由 3DGS 或 NeRF 的幾何直接供應，省去單目深度估計的誤差。整合時可將 3DGS 的高斯點雲投影回相機平面，建立更精確的區塊級深度區間。

- **與 Context-as-Memory、VMem 等幀級記憶方法整合**：Velox 是區塊級路由器，可作為幀級檢索的下游。先用幀級方法選出候選幀，再用 Velox 在這些幀內做區塊級精煉，兼顧召回率與效率。

- **與 ControlNet / AnchorWeave 整合**：對於需要穩定相機控制的場景，可先用 AnchorWeave 注入扭曲渲染結果穩定全域結構，再用 Velox 在區塊層級做注意力路由，避免兩者在同一層級競爭。

- **與遊戲引擎整合**：將 Velox 封裝為 Unreal Engine 5 的 Niagara Module 或 Unity 的 ScriptableRenderPipeline，讓玩家相機變動時觸發下一 chunk 的生成。視錐平板可由引擎的深度緩衝區直接讀取。

- **與機器人模擬器整合**：在 Isaac Sim 或 CARLA 中，將 Velox 作為視覺預測模型的注意力後端，使策略網路在 rollout 時能取得長時域一致的影片上下文。

- **與影片編碼與串流整合**：將生成的 chunk 以 H.266/VVC 編碼後串流給前端，Velox 的異步管線可與編碼器並行，進一步降低端到端延遲。

### 給不同背景讀者的閱讀建議

**初學者**：先讀摘要與第 1 節的動機，理解「為什麼長推演的影片世界模型會越來越慢」這個問題。圖 1 展示了從密集歷史、幀級檢索到區塊級路由的演進，是建立直覺的好切入點。技術細節可先跳過，專注於 Velox 想解決的痛點與最終的加速數字。

**研究者**：聚焦於視錐平板重疊作為路由訊號的理論基礎，以及「軟式融合 vs. 硬式選擇」的設計選擇。仔細分析 WBench 上 19 個指標的逐項變化，理解 Velox 在哪些場景類型上表現接近密集注意力、在哪些場景上仍有差距。延伸思考：是否能將視錐平板推廣到非相機控制的影片生成，或與其他稀疏注意力方法（如 Sliding Window、StreamingLLM）做理論比較。
