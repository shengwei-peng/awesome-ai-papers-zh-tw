本文提出**多尺度策略優化 (Multiscale Policy Optimization, MPO)**，其核心動機來自一個關鍵的實證觀察：在長視野 LLM 代理 (long-horizon LLM agents) 的互動中，評論器 (critic) 的價值變化主要發生在回合 (turn) 之間，而非回合內部。具體而言，在 2,048 條軌跡 (trajectory)、16,323 個回合、來自一個搜尋代理 (search-agent) 訓練的 8 個檢查點批次 (checkpoint batch) 中，**回合均值差異佔評論器詞元加權軌跡內價值變異數 (token-weighted within-trajectory value variance) 的中位數達 89.5%**，且在 93.8% 的軌跡中，**回合間變異數 (between-turn variance) 超過回合內變異數 (within-turn variance)**。這個統計結構直接挑戰了現有方法將每個詞元 (token) 視為獨立動作的假設。

MPO 的方法論建立在兩個互補的數學洞察之上：

**第一，理論層面的改善界 (improvement bound) 分析。** 作者將完整的助手回合 (assistant turn) 視為**巨觀動作 (macro action)**，並推導出回合級的策略改善界。這個界揭示了一個重要的理論缺陷：當使用詞元級替代目標 (token-level surrogate) 時，在相同的 KL 約束 (KL constraint) 下，會產生一個額外的**回合內分布偏移懲罰 (within-turn distribution-shift penalty)**。這個懲罰源於詞元級重要性比率 (importance ratio) 在回合內的累積誤差——當策略更新時，每個詞元的條件分布都在改變，但傳統方法只考慮了單一詞元的比率，忽略了回合整體分布的漂移。

**第二，多尺度優勢估計 (Multiscale Advantage Estimation, MAE) 的構造。** MAE 採用兩階段設計：
1. **回合級 GAE (turn-level GAE)**：在回合尺度上執行廣義優勢估計 (Generalized Advantage Estimation, GAE)，將終端獎勵 (terminal reward) 沿著回合序列傳播，捕捉長程信用 (long-range credit)。
2. **中心化局部修正 (centered local correction)**：在每個回合內部，保留詞元級的價值差異，但通過減去回合均值 (turn mean) 來中心化，確保局部修正不改變回合級的總信用分配。

這種構造被作者推導為**單一評論器 (single critic) 下的約束投影 (constrained projection)**，具有清晰的幾何直覺：在價值估計空間中，將詞元級估計投影到滿足回合均值約束的可行集上。

**第三，回合級重要性加權 (turn-level importance weighting)。** 這是 MPO 與現有方法最關鍵的差異。傳統的詞元級方法對每個詞元獨立計算重要性比率，而 MPO 使用**完整回合的機率比率 (complete-turn probability ratio)**，即 $\pi_\theta(a_t|h_t) / \pi_{\theta_{\text{old}}}(a_t|h_t)$。通過**停止梯度 (stop-gradient)** 構造，這個回合級比率被應用於策略梯度的整體權重，而每個詞元的 MAE 優勢保留在梯度方向中。這確保了策略更新在回合尺度上是一致的，避免了詞元級更新可能導致的回合內分布不一致問題。

整個方法論的優雅之處在於：它不是簡單地在回合級和詞元級之間做加權平均，而是通過嚴格的數學構造，讓兩個尺度**互補而非競爭**——回合級處理信用傳播的長程結構，詞元級保留生成過程的局部細節。

#### 與現有研究的比較

MPO 的定位精準地填補了現有 RL 方法譜系中的一個空白。作者將現有方法劃分為兩個家族：

**第一家族：無評論器、群組相對方法 (critic-free, group-relative methods)**，包括 GRPO、DAPO、GSPO。這些方法從群組相對結果獎勵 (group-relative outcome reward) 推導出**每條生成序列共享一個優勢值**。儘管它們在更新目標 (update objective) 上有所不同（如重要性加權方式、信任區域 (trust region) 控制），但共同的信用信號 (credit signal) 無法區分同一 rollout 中不同回合或詞元的貢獻。這個限制在長視野代理任務中尤為嚴重——一個軌跡可能包含 10-20 個回合，每個回合對最終結果的貢獻差異巨大，但共享優勢將它們等同視之。

**第二家族：基於評論器、詞元級方法 (critic-based, token-level methods)**，包括 PPO、VC-PPO、VAPO、SAO。這些方法使用學習的價值函數 (value function) 沿詞元序列估計優勢。其共同公式將每個生成的詞元視為動作，提供更細粒度的信用，但**未明確分離回合內生成與回合級環境互動**。這個缺陷在代理場景中產生了具體問題：環境互動發生在回合邊界（工具呼叫後等待環境回應），而詞元級方法將整個序列視為均勻的動作序列，忽略了互動的離散結構。

MPO 的核心貢獻在於**同時利用兩個尺度**：回合級用於信用傳播和重要性加權，詞元級用於保留局部生成細節。這不是簡單的「回合級 + 詞元級」混合，而是一個有理論支撐的統一框架——通過約束投影和停止梯度構造，確保兩個尺度的信號互補而非冗餘。

**相較於 GRPO 系列**：MPO 引入了評論器來捕捉回合間的價值結構，這增加了計算成本（需要訓練價值網路），但換來了更精確的信用分配。對於長視野任務，這個權衡通常是值得的，因為信用分配的改善直接影響樣本效率 (sample efficiency)。

**相較於 PPO 系列**：MPO 的回合級重要性加權避免了詞元級更新可能導致的回合內分布不一致問題。理論上，這應該帶來更穩定的訓練動態，特別是在策略更新幅度較大時。

## 適用場景

MPO 特別適合以下幾類長視野代理任務，這些任務的共同特徵是「多輪互動 + 稀疏終端獎勵」：

**1. 企業級自動化工作流代理**
例如自動處理客服工單（讀取工單 → 查詢 CRM → 調用退款 API → 撰寫回覆 → 送出確認）。每個回合都是一次完整的工具呼叫或回應生成，終端獎勵僅在工單結案時才給定。MPO 的回合級信用分配能正確歸因「哪一次工具呼叫真正解決了問題」。

**2. 深度研究與多跳問答代理**
例如學術研究助理需要依序搜尋多個來源、閱讀 PDF、交叉比對、產出報告。MPO 觀察到的「回合間變異數佔 89.5%」現象在此場景特別明顯——搜尋查詢的品質決定成敗，詞元級細節相對次要。

**3. 程式碼修復與 DevOps 代理**
SWE-bench 類任務：代理需在多個回合中編輯檔案、執行測試、根據錯誤訊息調整。MPO 的回合級重要性加權可避免「整個回合被一個錯誤的早期詞元拖累」。

**4. 瀏覽器自動化與網頁操作代理**
WebArena、Mind2Web 等基準：代理需在多輪中點擊、輸入、捲動、解析頁面。回合邊界清楚（每次動作結束後等待頁面回應），正好對應 MPO 的回合定義。

**5. 多步推理 + 工具鏈代理**
數學解題代理需要呼叫計算器、執行程式碼驗證、迭代修正。MPO 適合此場景因為它能區分「策略選擇」（呼叫哪個工具）與「執行品質」（工具呼叫的具體格式）。

## 潛在風險與注意事項

### 理論層面風險

**風險 1：價值結構假設不成立**
MPO 的有效性依賴「回合間變異數 >> 回合內變異數」。若你的任務中每個回合很短（< 20 tokens）或回合內決策極為關鍵（例如精確的程式碼編輯），此假設可能不成立。**緩解**：先做論文的 Figure 2 類統計分析，若比例 < 70%，考慮改用純 token-level 方法。

**風險 2：回合邊界定義模糊**
若代理在一個回合中混合了「思考」與「工具呼叫」，回合定義會影響 credit 分配。**緩解**：明確區分 reasoning tokens 與 action tokens，或將每個獨立動作視為一個回合。

**風險 3：改善界的緊度**
論文的 turn-level improvement bound 是理論保證，實際差距可能很大。**緩解**：監控 KL 散度，若超過閾值則提早停止更新。

### 工程層面風險

**風險 4：訓練不穩定**
MoE 模型（30B-A3B）在 RL 訓練中容易出現 router collapse 或負載不均。**緩解**：使用 auxiliary load-balancing loss、監控 expert utilization、定期重置 router。

**風險 5：rollout 收集瓶頸**
長視野任務的 rollout 時間遠超訓練時間。**緩解**：使用非同步 rollout 收集、提前終止明顯失敗的軌跡、批次化環境互動。

**風險 6：評論器漂移**
隨著策略更新，critic 可能過時或預測偏差擴大。**緩解**：定期重新初始化 critic、限制 critic 與 policy 的更新步長比例。

### 部署層面風險

**風險 7：過擬訓練任務**
MPO 在特定任務上表現優異，但可能犧牲通用能力。**緩解**：保留通用 SFT 資料的混合訓練、定期在通用基準（MMLU、HumanEval）上評估。

**風險 8：獎勵 hacking**
代理可能學會「快速完成任務以避免負面獎勵」而非真正解決問題。**緩解**：設計多維度獎勵（正確性、效率、安全性）、加入人類偏好資料。

## 與其他技術的整合建議

### 與既有 RL 框架整合

- **Speculative decoding**：用小模型 draft、大模型 verify，可與 MPO 訓練的小 critic 結合

### 與代理框架整合
- **LangGraph / AutoGen**：將 MPO 訓練的策略作為節點嵌入工作流圖
- **ReAct / Reflexion 模式**：MPO 訓練的策略可作為 ReAct 的 actor，Reflexion 的反思機制作為額外獎勵信號
- **Toolformer 風格工具**：MPO 訓練的代理可學習何時呼叫哪個工具，回合級信用分配特別適合此決策

### 與其他 RL 方法組合
- **MPO + Process Reward Model (PRM)**：在回合內加入 PRM 提供的細粒度獎勵，與 MAE 的中心化修正互補
- **MPO + Curriculum Learning**：從短 horizon 任務開始，逐步增加回合數
- **MPO + Distillation**：將 30B-A3B 訓練的策略蒸餾到 4B 模型，保留多尺度信用分配的優勢
