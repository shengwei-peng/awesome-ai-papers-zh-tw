## 深度分析

#### 方法論解析

ForceHarness 的核心設計理念在於解決「凍結前沿模型（frozen frontier models）」無法直接處理力感測資訊的根本矛盾。論文中明確指出兩個關鍵挑戰：第一，接觸力（contact forces）的演化速度遠快於 API 模型能做出決策的速度，因此必須在模型之下（beneath the model）完成力控制的閉迴路（closed loop）；第二，凍結模型無法解讀原始力串流（raw force streams），必須將力資訊轉化為模型可推理的形式。

**三層架構設計：**

**第一層：力感測與校正層（Force sensing and calibration layer）**
此層負責將機器人原始訊號轉換為環境施加於手部的校正後力估計值。值得注意的是，該層支援兩種模式：使用腕部力感測器（wrist force sensor）或僅依靠關節扭矩（joint torques）進行估測，並移除感測器偏移（sensor offsets）。這種設計的實用意義在於，許多實際機器人平台並未配備昂貴的六軸力感測器，僅靠關節電流/扭矩即可推算外力，這大幅降低了部署門檻。

**第二層：自終止力基元（Self-terminating force primitives）**
這是整個系統最具創新性的設計。基元（primitives）將常見的接觸技能——如防護移動（guarded moves）、滑動（sliding）、插入（insertion）——封裝成可呼叫的工具。一旦被呼叫，每個基元會自主調節力（regulate force on their own），並在接觸事件（contact event）發生時自動返回。這種設計巧妙地將高速力控制迴路與低速模型決策迴路解耦：模型以秒級頻率決定「做什麼」，基元以控制器頻率決定「怎麼做」。這是處理「接觸演化速度遠快於決策速度」問題的關鍵架構選擇。

**第三層：物理轉譯層（Physics translation layer）**
此層將每個基元產生的力軌跡（force trace）轉換為帶有不確定性估計（uncertainty estimates）的物理量（physical quantities）及狀態旗標（status flags），例如負載質量（payload mass）、接觸高度（contact height）、摩擦（friction）等。這層解決了第二個挑戰——讓凍結模型能「理解」力。論文中消融實驗（ablations）的結果顯示，較小的模型在獲得物理量而非原始力數值時，決策品質顯著提升，這證實了物理轉譯的必要性。

**整體運作流程：**
模型在每個回合呼叫一個基元，讀取返回的物理量，再決定下一步行動。這種「呼叫-讀取-決策」的循環類似於 LLM agent 使用工具的模式，但特別針對力感測的時序特性進行了優化。

#### 實驗數據解讀

論文的實驗設計相當全面，涵蓋真實機器人與兩個模擬基準測試，並與多類基線方法進行比較。

**真實機器人實驗：**
在無腕部力感測器的真實機械手臂上，設計了六個接觸豐富的任務。GPT-6 Astra 的零樣本（zero-shot）成功率從無力回饋時的 **3.3%** 提升至使用 ForceHarness 後的 **90.0%**，提升幅度高達 86.7 個百分點（percentage points）。這個數據極具說服力，因為它證明了：(1) 對於需要接觸力的任務，純視覺模型幾乎無法完成；(2) ForceHarness 能在不更新模型權重的前提下，徹底改變模型在接觸任務上的表現。

**ForceBench 模擬實驗：**
在公開的 ForceBench 套件上，GPT-6 Astra 從 **70.0%** 提升至 **87.5%**（+17.5 百分點），並超越了該基準上經過示範訓練（trained on demonstrations）的力感知策略（force-aware policies）。這個結果的意義在於，ForceHarness 不僅讓凍結模型「能用」力，還讓它「用得比專門訓練的模型更好」。

**HiddenPhys 基準測試：**
這是論文自建的七任務 MuJoCo 基準測試，特色在於包含隱藏物理變量（hidden physical variables），並提供專家力控制器（expert force controllers）與學習式策略（learned policies）在相同種子下的評估。GPT-6 Astra 從 **62.1%** 提升至 **96.4%**（+34.3 百分點），不僅匹配了手寫專家控制器，還遠超 Diffusion Policy、π0.5 與 ForceVLA（在每個任務約 200 次示範下訓練）。這個結果特別重要，因為 HiddenPhys 提供了「相同條件下的公平比較」——這在機器人學習領域是相當稀缺但極具價值的實驗設計。

**消融實驗的關鍵發現：**
「較小模型在獲得物理量而非原始力數值時決策品質顯著提升」這項發現，對於理解 LLM 處理數值資訊的機制具有重要意義。它暗示凍結模型並非缺乏處理數值的能力，而是缺乏將原始感測數據映射到語意概念的橋樑——這正是物理轉譯層所提供的。

**數據的侷限性：**
雖然結果亮眼，但需注意：(1) 真實機器人實驗未說明任務的具體細節與統計顯著性檢定；(2) HiddenPhys 雖有七個任務，但每個任務的試驗次數與變異性未在摘要中披露；(3) 與 π0.5、ForceVLA 的比較基於約 200 次示範，這在當前機器人學習領域屬於較小規模的訓練集。

#### 與現有研究的比較

**與力感知學習式策略的比較：**
傳統的力感知策略（force-aware policies）如文獻 [15, 18, 39] 將腕部力作為網路輸入整合至視覺運動策略（visuomotor policies）或視覺-語言-動作模型（VLA models）。ForceBench [14] 即是這類方法的代表評測平台。這些方法的共同限制在於：每個任務都需要示範資料（demonstrations），且必須更新模型權重，因此無法應用於僅透過 API 存取的凍結模型（API-only frozen model）。ForceHarness 的核心優勢正是突破了這個限制——無需示範、無需微調（finetuning）。

**與現有凍結模型框架的比較：**
現有框架（harness）主要從三個維度擴展凍結模型：動作空間（語義動作單元 semantic action units、代理編寫的工具 agent-written tools）、感知空間（虛擬相機視角 virtual camera views、校正感知工具）、記憶與技能編排（低階 VLA 技能 low-level VLA skills）。然而，這些框架「幾乎沒有考慮力」：多數缺乏力通道，其餘則僅傳遞原始讀數或力上限。ForceHarness 是首個圍繞力構建的框架——在模型之下調節力，並以物理量形式回報。

**與基於 LLM 的力控制方法的比較：**
近期研究嘗試讓 LLM 在推理時使用力：將感測屬性讀為句子 [45]、生成帶力回饋的程式碼 [4, 22]、調整基礎策略的阻抗 [40, 41]、在訓練技能之上選擇恢復動作 [25]。FORCA [28] 讓編碼代理在 rollout 之間編寫並修訂力回饋程式。也有研究直接將觸覺或力讀數傳遞給 GPT-6 Astra [29, 34, 35, 38, 46]。ForceHarness 的差異化在於「控制與感知整合且無需訓練」：基元在模型之下調節力，模型在每次呼叫後讀取校正後的物理量。

**論文承認的限制：**
從摘要與引言可推知，ForceHarness 依賴於：(1) 存在可定義為基元的接觸技能；(2) 力資訊可從關節扭矩或腕部感測器估測；(3) 物理量可從力軌跡推算。對於極度非結構化的接觸場景或缺乏明確接觸事件的任務，基元設計可能難以覆蓋。

## 實務應用指南

### 適用場景

1. **螺絲鎖附與拆解**：在 3C 產品、半導體設備或家電組裝線上，鎖附螺絲需要同時施加垂直壓力與旋轉扭矩，直到螺紋嚙合產生阻力變化。ForceHarness 可讓凍結模型根據回傳的「接觸高度」與「摩擦」物理量，自動判斷何時停止下壓、何時切換為旋轉動作。

2. **重量/材質分揀**：在物流倉儲或食品加工現場，外觀相同的瓶罐、包裹或零件需要靠重量或摩擦係數區分。透過物理轉譯層回報的「負載質量」與不確定性，模型可在無示範資料下決定分揀路徑。

3. **精密插配（peg-in-hole / connector mating）**：電子連接器、汽車線束或醫療器材的插接，常因公差極小而需要滑動找孔與微調。ForceHarness 的「guarded move」與「insertion」基元可在模型決策週期外自行調節接觸力，解決 API 延遲無法即時反應的問題。

4. **拋光、研磨與表面處理**：需要維持恆定接觸壓力同時沿曲面滑動的加工任務，可由自終止力基元維持力恆定，再由模型根據回報的摩擦變化調整路徑。

5. **柔性物件操作（布料、泡棉、線材）**：處理形變大的物件時，視覺回饋不可靠，必須依賴力軌跡判斷張力與滑動狀態。ForceHarness 可將力軌跡轉為張力、接觸面積等物理量供模型推理。

**軟體與資料**
- 目標凍結模型的 API 存取權（GPT-6 Astra 或同級多模態模型），並確認其支援影像輸入與工具呼叫（function calling）。

- 校正用的靜態負載與已知重量砝碼，用於力感測器偏移補償與物理量換算。
- 評估用的接觸豐富任務定義（任務目標、成功條件、隱藏物理變量）。

- 即時控制層：邊緣裝置（如工業 PC、NVIDIA Jetson Orin）即可。
- 模型推理：仰賴雲端 API，需評估網路延遲（單次決策通常需 1–3 秒）。
- 模擬驗證：MuJoCo 授權與運算資源，用於 HiddenPhys 類基準測試。

**技能門檻**
- 控制理論基礎：混合位置/力控制、阻抗控制。
- 機器人學：座標系轉換、順逆運動學、感測器標定。
- 提示工程（prompt engineering）與工具呼叫設計。
- 不確定性量化（uncertainty quantification）以設計物理轉譯層。

### 實作步驟建議

**階段一：力感測與校正層（2–4 週）**
1. 確認感測來源：腕部六軸力感測器或關節扭矩推算。
2. 在多個靜態姿態下量測零點偏移，建立偏移補償模型。
3. 以已知砝碼進行負載質量校正，驗證從原始訊號到「手部力」的換算誤差（目標 <5%）。

**階段二：自終止力基元（4–6 週）**
1. 盤點目標任務所需的接觸技能（guarded move、sliding、insertion、press、twist 等）。
2. 為每個基元設計接觸事件偵測條件（力突變、力門檻、力斜率變化）。
3. 實作基元內部的閉迴路控制器（PID、阻抗或自適應控制），確保在模型決策週期外仍能穩定調節力。
4. 定義每個基元的輸入參數（如目標力、速度上限）與回傳結構（力軌跡摘要、終止原因）。

**階段三：物理轉譯層（3–4 週）**
1. 為每個基元設計從力軌跡到物理量的換算邏輯（例：恆力下壓的位移變化 → 接觸高度；旋轉扭矩積分 → 摩擦係數）。
2. 加入不確定性估計（貝氏推論、蒙地卡羅或簡化的高斯傳播）。
3. 將結果格式化為模型可讀的結構化工具回傳（含狀態旗標與信心區間）。

**階段四：模型整合與提示設計（2–3 週）**
1. 設計工具呼叫 schema：基元名稱、參數、回傳欄位。
2. 撰寫系統提示：說明可用基元、回傳物理量的意義、決策原則。
3. 實作多輪決策迴圈：模型呼叫基元 → 執行 → 回傳物理量 → 模型推理 → 下一個基元。
4. 加入安全護欄：力上限、單次基元時長上限、重試策略。

**階段五：評估與迭代（持續）**
1. 在 HiddenPhys 或自建基準上量測成功率、決策步數、力軌跡品質。
2. 進行消融實驗：比較「物理量回傳」vs「原始力數值」對小型模型的決策品質差異。
3. 收集失敗案例，分析是基元設計、物理量換算或模型推理的問題。
4. 部署到真實手臂前，先在模擬中做長時間穩定性測試。

|------|------|----------|
| **感測器偏移漂移** | 溫度變化或機械磨耗會讓零點偏移，造成力估計偏差 | 定期自動重新校正；加入偏移監控指標；任務開始前做空載驗證 |
| **API 延遲導致失控** | 模型決策需 1–3 秒，若無基元保護，期間可能發生過大力碰撞 | 所有接觸動作必須透過自終止基元執行；硬體層加入獨立的安全監控（safety PLC） |
| **物理量換算誤差** | 從力軌跡反推質量、摩擦等物理量時，模型假設可能不成立 | 提供不確定性區間；讓模型在信心不足時呼叫額外探測基元；避免單一物理量做關鍵決策 |
| **模型幻覺與錯誤推理** | 凍結模型可能誤讀物理量或選擇不合適的基元 | 限制基元參數範圍；對關鍵決策加入規則式後備方案；記錄決策日誌供離線分析 |
| **任務泛化失敗** | 物理轉譯層的換算邏輯可能只對訓練過的接觸型態有效 | 為新任務類型擴充基元與換算器；保留「未知物理量」狀態旗標讓模型可要求更多資訊 |
| **安全與法規** | 接觸豐富任務常涉及人機協作，需符合 ISO/TS 15066 等規範 | 設定絕對力上限；加入碰撞偵測與立即斷電；進行風險評估 |

### 與其他技術的整合建議

1. **與視覺-語言-動作（VLA）模型整合**：ForceHarness 可作為 VLA 模型的「力感知外掛」，讓現有 π0.5、OpenVLA 等模型在不重新訓練下獲得力覺能力。建議將基元設計為 VLA 的低階技能庫。

2. **與 Diffusion Policy 等學習式策略整合**：對於需要示範學習的高變異任務，可讓 ForceHarness 負責粗略的接觸階段（接近、對位），再交棒給 Diffusion Policy 執行精細操作。

3. **與傳統力控制器整合**：ForceHarness 的基元內部可採用成熟的阻抗控制或混合位置/力控制演算法，無需從零開始；專家控制器可作為基元實作的參考基準。

4. **與多模態感知整合**：將力資訊與視覺、觸覺、聽覺融合時，建議以物理轉譯層的「物理量」作為統一介面，避免不同感測通道的原始數值直接拼接。

5. **與任務規劃系統整合**：在高層任務規劃（如 LLM 規劃器）與低層控制之間，ForceHarness 可作為「接觸技能執行器」，由高層決定任務順序，由 ForceHarness 處理接觸細節。

6. **與模擬器整合**：在部署到真實機器人前，先在 MuJoCo 或 Isaac Sim 中建立任務數位孿生，用於基元參數調校與物理量換算器的初步驗證。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）了解「為什麼需要把力交給凍結模型」這個核心問題，再看第 3.1 節的三層架構圖，建立整體概念。技術細節可先跳過，重點理解「自終止力基元」與「物理轉譯層」分別解決了什麼問題。可搭配閱讀相關詞條：混合位置/力控制、阻抗控制、視覺-語言-動作模型。

**給 AI 工程師**：重點關注第 3 節的實作細節，特別是自終止力基元的接觸事件偵測條件與物理轉譯層的不確定性估計方法。實作時建議先在模擬器中復現 HiddenPhys 的部分任務，驗證工具呼叫 schema 與提示設計的可行性，再部署到真實機器人。注意評估 API 延遲對整體任務節奏的影響，並設計合適的超時與重試機制。

**給研究者**：本文的核心貢獻在於提出「讓凍結模型使用力」的系統性框架，並透過 HiddenPhys 基準提供了公平比較凍結模型、學習式策略與專家控制器的實驗環境。建議深入分析：(1) 為何物理量回傳對小型模型的決策品質有顯著提升（消融實驗）；(2) 自終止基元的設計空間與泛化性；(3) 不確定性估計在模型推理中的角色。可考慮延伸方向：多接觸點力融合、與觸覺感測的整合、跨任務的物理量換算器泛化。

**給產品經理**：ForceHarness 的商業價值在於「讓通用 AI 模型直接處理接觸豐富任務」，無需為每個新任務收集示範資料與訓練模型，大幅降低部署成本與時間。適合導入的場景包括：高度混線的小批量製造、倉儲物流的分揀、3C 產品的精密組裝。導入前需評估：(1) 任務的接觸複雜度是否在基元覆蓋範圍內；(2) API 延遲是否影響產線節拍；(3) 安全法規要求。建議先從單一工作站試點，驗證成功率與 cycle time 後再擴展。
