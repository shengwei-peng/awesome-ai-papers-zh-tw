## 摘要翻譯

人們向對話式人工智慧（Conversational AI）模型詢問其法律權利、義務、程序，以及可能產生法律後果的個人處境。為了研究此行為，我們首先需要區分法律指引請求與其他法律主題討論及無關對話。我們貢獻了法律查詢的多軸分類法（multi-axis taxonomy），涵蓋是否尋求法律指引、請求的表述方式，以及涉及的法律領域；將其應用於 2,122 筆自然產生的 WildChat-1M 對話；並建立一個包含 200 筆對話的人工審核黃金評估集（gold evaluation set）。所有標註、模型權重檔（model checkpoints）及評估程式碼（evaluation code）均公開可得。在此豐富化樣本中，71.1% 包含法律內容的對話尋求個人化或實務的指引。權利與選項建議（rights-and-options advice）是法律內容對話中最常見的主要請求類型，且 25.3% 的指引正向（guidance-positive）對話涵蓋多個法律主題。黃金評估集支援 ModernBERT-base 與 ModernBERT-large 對比 TF-IDF 串接分類器（TF-IDF cascade）的兩階段比較（two-stage comparison）。我們的框架支援對話式人工智慧中法律指引的大規模研究，而標註資料的公開釋出有助於可重現研究（reproducible research）及未來模型開發。

### 核心貢獻（3～5點）
- 提出一套涵蓋「是否尋求指引」、「請求表述方式」與「涉及法律領域」三個軸向的法律查詢多軸分類法，可系統性區分法律指引請求與其他法律主題討論。
- 將上述分類法應用於 2,122 筆自然產生的 WildChat-1M 對話，並建立 200 筆人工審核的黃金評估集，作為後續研究的基準資源。
- 實證揭示法律內容對話的分布特性：71.1% 尋求個人化或實務指引、權利與選項建議為最常見的主要請求類型、25.3% 的指引正向對話橫跨多個法律主題。
- 透過兩階段比較實驗，評估 ModernBERT-base、ModernBERT-large 與 TF-IDF 串接分類器於法律指引偵測任務上的相對效能。
- 公開釋出所有標註資料、模型權重檔與評估程式碼，支援可重現研究並促進未來模型開發。

### 適合對象
從事法律自然語言處理（Legal NLP）、對話式人工智慧安全防護、LLM 行為分析或法律科技（LegalTech）研究的學者與工程師；關注公開使用的大型語言模型於專業領域（特別是法律協助場景）應用風險與品質特性的政策制定者與利害關係人；以及設計法律協助人工智慧（Legal-help AI）產品或評估其資格審查與指引偵測流程的實務開發團隊。

## 深度分析

#### 方法論解析

本論文提出了一套系統化的方法論來研究使用者在真實 LLM 對話中尋求法律指引的行為模式，其方法設計具有幾個值得深入剖析的特點。

**多軸分類法（Multi-axis Taxonomy）的設計**

論文核心貢獻在於建構一個三軸分類法來刻畫法律對話：

1. **法律相關性軸（Legal Relevance Axis）**：區分「含有法律內容」與「尋求個人化或實務法律指引」這兩個概念。這個區分至關重要，因為含有法律內容的對話未必等同於指引尋求——使用者可能要求法條翻譯、討論虛構爭議、請求學術解釋，或僅描述個人處境而不尋求具體的權利、選項或後續步驟。

2. **互動軸（Interaction Axis）**：記錄使用者脈絡、起草意圖、指引出現時機，以及六種請求類型——權利與選項建議（rights-and-options advice）、資訊或解釋、程序協助、文件起草、文件審閱，以及其他請求。

3. **領域軸（Domain Axis）**：指派 13 個實質法律主題與一個「其他（OTHER）」殘餘類別。每個對話接收一個主要主題代表其主導法律議題，並可選用次要主題記錄額外議題。

**兩階段階層式分類架構**

論文採用階層式分類設計：第一階段預測使用者是否尋求個人化或實務法律指引，第二階段將每個正向案例指派至 14 個主要法律主題之一。這種設計的優勢在於：(1) 將複雜的多標籤問題分解為可管理的子任務；(2) 允許在第一階段使用較簡單的模型過濾大量非指引對話；(3) 領域軸為扁平結構，降低分類難度。

**標註流程的雙模型設計**

論文採用了精心設計的雙模型標註流程：
- **GPT-5.6 Terra**（高推理 effort）：用於初步篩選，識別明顯不相關的素材與可能含有法律內容的對話。
- **GPT-5.6 Sol**（中等推理 effort）：對所有保留的 2,122 個對話進行完整分類標註，形成銀標資料集（silver-labeled dataset）。

值得注意的是，Terra 的篩選標籤僅用於樣本組成，並非最終銀標籤；Sol 的標註才是分析與訓練的依據。這種設計避免了將篩選偏誤混入訓練標籤。

**資料集組成策略**

保留樣本包含 2,122 個對話，結合「初始被識別為含有法律內容」的對話與「Terra 分類為非法律」的等量隨機樣本。這種設計支援分類模型建構，但作者明確指出此標籤分布無法估計 WildChat 中的真實盛行率（prevalence）——這是方法論上的誠實聲明。

**分類器比較設計**

論文在黃金評估集（gold evaluation set）上比較了三種方法：
- **TF-IDF 串接分類器（TF-IDF cascade）**：作為詞彙基準
- **ModernBERT-base**：較小的 Transformer 編碼器
- **ModernBERT-large**：較大的 Transformer 編碼器

關鍵的方法論嚴謹性在於：所有模型決策（modeling decisions）都使用獨立的銀標開發資料定案，黃金評估集僅在最後用於評估，避免了資料洩漏（data leakage）。

**只使用使用者訊息的設計選擇**

論文刻意僅以時間順序呈現使用者訊息，排除助理訊息。這項設計選擇的理由是研究焦點在於「使用者如何表述法律請求」，而非模型的回應品質。這也避免了將模型的幻覺（hallucination）或錯誤回應混入訓練訊號。

#### 實驗數據解讀

**核心統計數據**

在 2,122 個保留對話中：
- 1,367 個含有法律內容
- 972 個尋求法律指引（佔 45.8%）
- 在含有法律內容的對話中，**71.1%** 尋求個人化或實務指引

這個 71.1% 的數字極具意義：它表明在真實 LLM 使用場景中，當使用者帶著法律議題前來時，絕大多數並非出於學術或資訊目的，而是尋求具體的行動指引。這對 LLM 服務提供者的安全設計有直接意涵。

**請求類型分布**

權利與選項建議（rights-and-options advice）是最常見的主要請求類型。這意味著使用者最常問的問題是「我有什麼權利？」、「我可以怎麼做？」、「有哪些選項？」——而非單純的「法律是什麼？」。這個發現與 Kuk 和 Harašta 對 GPT-4 法律助理查詢的研究形成對話，後者也區分了「法律資訊請求」與「行動建議請求」。

**多主題對話的比例**

**25.3%** 的指引正向對話跨越多個法律主題。這是一個重要的發現，因為它揭示了真實法律諮詢的複雜性：使用者面臨的法律問題往往不是單一領域的，而是交織的（例如，住房問題可能同時涉及租約、歧視、移民身分等）。這對分類系統的設計有直接影響——單標籤分類可能無法充分捕捉這種複雜性。

**黃金評估集的設計**

200 個對話的黃金評估集使用初始指引標籤進行分層抽樣，包含 100 個指引案例與 100 個非指引案例（從文獻脈絡推測）。這種平衡設計支援公平的分類器比較，但作者強調此分布不等於真實盛行率。

**兩階段分類的意涵**

兩階段分類的設計意味著：
- 第一階段（指引偵測）是二元分類問題
- 第二階段（主題分類）是 14 類多類別分類問題

這種分解允許研究者在每個階段選擇最適合的模型複雜度。例如，第一階段可以使用輕量模型處理大量對話，第二階段則可在較小的子集上使用更複雜的模型。

**與健康資訊研究的平行**

論文明確將其框架與 *What's Up, Doc?*（研究使用者如何向對話系統尋求健康資訊）進行類比。這個平行很重要，因為它暗示了法律領域可以借用健康領域已建立的使用者中心研究方法論。

#### 與現有研究的比較

**與 Kuk 和 Harašta 的研究比較**

Kuk 和 Harašta 研究提交至 GPT-4 法律助理的查詢，區分「法律資訊請求」與「行動建議請求」。本論文採取了更廣泛的視角：不是分析單一法律助理系統的查詢，而是分析自然產生的多 LLM 對話（WildChat-1M）。這擴展了研究的生態效度（ecological validity），因為 WildChat 反映了使用者在沒有專門法律介面時的真實行為。

**與 Hagan 的質性研究比較**

Hagan 透過訪談與設計工作坊（design sessions）研究使用者何時會使用法律協助 AI 以及期望的品質特性與安全防護措施。本論文則採用大規模量化方法，兩者形成互補：質性研究提供深度脈絡，量化研究提供廣度證據。

**與 Steenhuis 和 Westermann 的比較**

Steenhuis 和 Westermann 使用 LLM 支援民事法律援助（civil legal-aid）受理，進行資格審查（eligibility checking）與生成後續追問（follow-up questions）。本論文處理的是更上游、更廣泛的任務：在自然對話中識別指引尋求行為，而非在專門的受理流程中運作。

**與法律 NLP 基準的比較**

BSARD（將法語問題對應至比利時法規）、Finding the Law、LLeQA（專家標註問題與基於立法的長篇答案）、GerLayQA（德國民法問題與律師撰寫的答案）都屬於「固定問題設定」的研究。本論文的差異化在於：研究自然產生的多輪對話中指引意圖、請求類型與法律主題的分布，而非預先策劃的問題集。

**與 Dahl 等人關於法律幻覺的研究**

Dahl 等人記錄了 LLM 頻繁的法律幻覺（legal hallucination）與對錯誤前提的自信接受。本論文並不評估答案正確性，而是識別「需要更強安全防護、專門路由或人工升級（human escalation）的對話」。兩者形成互補：Dahl 等人揭示問題的嚴重性，本論文提供大規模識別此類對話的工具。

**方法論優勢**

相較於現有研究，本論文的優勢在於：
1. **規模與生態效度**：2,122 個自然對話 vs. 專門系統的查詢日誌
2. **公開可重現性**：釋出標註、模型權重檔（checkpoints）與評估程式碼
3. **階層式設計**：分離指引偵測與主題分類
4. **嚴格的評估協議**：黃金集僅在最後用於評估，避免資料洩漏

**方法論限制**

1. **英語限制**：僅使用 WildChat-1M 的英語對話，無法推論至其他語系
2. **單一資料來源**：僅 WildChat-1M，可能無法代表所有 LLM 使用場景
3. **銀標標註的偏誤**：使用 LLM 標註可能繼承該模型的偏誤
4. **盛行率無法估計**：樣本設計不支援 WildChat 中法律對話的真實盛行率估計
5. **未評估答案品質**：分類器不評估回應正確性，僅識別需要安全措施的對話

#### 可重現性評估

**公開釋出的產出物**

論文明確聲明釋出以下資源（透過 GitHub 倉庫 `Amir-Mohseni/Legal-Guidance-in-the-Wild`）：
1. **標註資料（annotations）**：完整的銀標與黃金標註
2. **模型權重檔（model checkpoints）**：ModernBERT-base 與 ModernBERT-large 的訓練後權重
3. **評估程式碼（evaluation code）**：支援黃金集上的模型評估
4. **標註提示（annotation prompt）**：用於 Sol 標註的完整提示
5. **JSON 結構描述（JSON schema）**：標註輸出的格式規範
6. **執行配置（run configurations）**：模型訓練與評估的參數設定

**可重現性優勢**

1. **完整的標註透明度**：釋出標註提示意味著其他研究者可以使用相同提示重現銀標資料集，或將其應用於新資料
2. **模型權重公開**：無需重新訓練即可使用模型進行推論
3. **黃金評估集**：200 個人工審核對話作為標準化評估基準
4. **JSON 結構描述**：便於其他研究者整合至自己的標註流程

**可重現性的潛在挑戰**

1. **GPT-5.6 模型版本依賴**：標註依賴於 OpenAI 的 GPT-5.6 Terra 與 Sol，這些是閉源模型（closed-source），未來可能無法取得或行為已改變
2. **API 變動風險**：透過 OpenAI API 存取意味著標註結果可能因 API 版本更新而無法完全重現
3. **黃金標註者資訊未詳述**：論文中未詳細說明黃金標註者的背景、培訓流程或標註者間一致性（inter-annotator agreement，如 Cohen's kappa 或 Krippendorff's alpha）
4. **WildChat-1M 的可取得性**：依賴 WildChat-1M 資料集的持續可用性

**對可重現研究的貢獻**

儘管有上述挑戰，本論文在法律 NLP 社群的可重現性標準上邁出了重要一步。相較於許多僅釋出程式碼或僅釋出資料的研究，本論文同時釋出了資料、模型權重、提示與配置，這對未來模型開發（future model development）極為有利。

#### 未來研究方向

**1. 多語言與跨司法管轄區擴展**

當前研究僅限於英語對話與（隱含的）單一司法管轄區。未來可擴展至：
- 多語言 WildChat 對話（如中文、西班牙語、阿拉伯語等）
- 跨司法管轄區的法律主題分布比較
- 翻譯不變性（translation invariance）的指引偵測模型

**2. 即時指引偵測與介入**

論文明確提及「精簡指引偵測器（compact guidance detector）」可用於觸發提示通知（notice），告知使用者「生成內容非專業建議之替代品」。未來方向包括：
- 即時串流分類（streaming classification）以在使用者輸入過程中提早偵測
- 經過校準（calibration）與使用者測試（user testing）後的部署研究
- 不同提示通知設計對使用者行為的影響

**3. 專門路由與人工升級**

論文提及「更強安全防護、專門路由（specialized routing）或人工升級（human escalation）」。未來可探索：
- 將偵測到的指引對話路由至法律專家審查的流程
- 與法律援助機構整合的混合系統
- 升級觸發條件的最佳化（何時升級、如何升級）

**4. 答案品質評估的整合**

當前分類器不評估答案正確性。未來可結合：
- Dahl 等人風格的法律幻覺偵測
- 對指引正向對話的回應進行事實性（factuality）評估
- 對比不同 LLM 在相同指引請求上的回應差異

**5. 使用者意圖的縱貫研究**

WildChat-1M 包含時間戳記，未來可進行：
- 法律指引請求隨時間的趨勢分析
- 重大法律事件（如新法通過、重大判決）後的請求模式變化
- 季節性或事件驅動的法律諮詢模式

**6. 多模態擴展**

當前僅分析文字對話。未來可探索：
- 使用者上傳文件（如租約、僱傭合約）的場景
- 結合視覺資訊的法律指引請求
- 語音輸入的法律諮詢模式

**7. 公平性與偏誤分析**

未來應評估：
- 不同人口統計群體（種族、性別、社經地位）的指引請求模式差異
- 分類器在不同群體對話上的效能差異
- 偏誤（bias）對法律指引可及性的影響

**8. 與專業法律服務的比較研究**

未來可進行：
- LLM 法律指引與真人律師諮詢的品質比較
- 使用者對兩種來源的信任度與遵循度調查
- 成本效益分析

**9. 對話結構與指引尋求的動態分析**

論文提及「指引出現時機（guidance onset）」。未來可深入：
- 多輪對話中指引意圖如何演變
- 助理回應如何影響後續指引請求
- 對話長度與指引深度的關聯

**10. 跨領域平行研究**

論文已與健康資訊研究（*What's Up, Doc?*）建立平行。未來可擴展至：
- 財務建議、醫療建議、心理諮詢等其他高風險領域
- 跨領域指引尋求行為的共通模式
- 通用「高風險領域指引偵測器」的設計可能性

這些研究方向不僅能深化對法律 LLM 使用的理解，也能為整個對話式 AI 的安全設計提供方法論基礎。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於一個在法律自然語言處理領域中被忽略的基礎問題：如何在使用者與大型語言模型（LLM）的真實對話中，區分「尋求法律指引」的請求與其他法律相關但非指引性質的討論。作者指出，含有法律內容的文字並不等同於指引尋求，使用者可能要求翻譯法條、討論虛構爭議、請求學術解釋，或描述個人處境以尋求具體的權利、選項或後續步驟。為了系統性地處理這個問題，研究團隊將其形式化為一個階層式分類任務：第一階段預測使用者是否尋求個人化或實務性的法律指引，第二階段則將正向案例指派至 14 個主要法律主題之一。這種區分對於理解真實世界中公眾如何向 AI 尋求法律協助至關重要。

**Q2：為什麼現有的法律 NLP 基準測試無法有效處理這個問題？**
A：現有的法律 NLP 基準測試（如 BSARD、Finding the Law、LLeQA、GerLayQA 等）主要評估法律文件理解、檢索、答案生成或專家定義的推理任務，它們揭示的是模型在專業法律任務上的表現，而非一般用途助理所面對的更基本問題。也就是說，這些基準無法告訴我們「一位普通使用者在真實對話中究竟何時在尋求法律指引，以及這些請求是如何被表述的」。此外，現有資源多採用固定的問題設定（fixed-question settings），而非自然產生的多輪對話，因此難以捕捉使用者真實的提問模式與意圖分布。

**Q3：為什麼這項研究對 LLM 安全性與使用者保護具有重要性？**
A：公開使用的大型語言模型可能會自信地產生不可靠的法律資訊，Dahl 等人的研究已記錄了頻繁的法律幻覺與對錯誤前提的自信接受。這意味著當使用者帶著真實的法律困擾向 AI 求助時，可能會得到具有嚴重後果的錯誤建議。本研究提出的精簡指引偵測器（compact guidance detector）可支援大規模擷取以進行實證研究，或在校準與使用者測試後，觸發提示通知告知使用者「生成內容並非專業建議的替代品」。這種框架與近期關於使用者如何在對話系統中尋求健康資訊的研究平行對應，凸顯了領域特定安全防護措施的必要性。

**Q4：這篇論文提出的核心方法——多軸分類法——是如何設計的？**
A：研究團隊設計了一個三軸分類法來全面刻畫對話中的法律指引請求。第一個軸是「法律相關性」，區分法律內容與個人化／實務性指引尋求；第二個軸是「互動」，記錄使用者脈絡、起草意圖、指引首次出現的時機，以及請求類型（包括權利與選項建議、資訊或解釋、程序協助、文件起草、文件審閱等）；第三個軸是「領域」，將對話指派至 13 個實質法律主題加上一個「其他」殘餘類別。每個對話會收到一個代表其主要法律議題的主要主題，以及可選的次要主題，使分類法能同時支援描述性分析與下游分類器的訓練。

**Q5：本研究相較於過往文獻的關鍵創新為何？**
A：本研究的關鍵創新在於將「法律內容」與「指引尋求」明確分離，並採用階層式分類架構處理真實世界的多輪對話。相較於 Kuk 與 Harašta 僅區分資訊請求與行動建議，以及 Hagan 透過訪談與設計工作坊探討使用者期望，本研究直接從自然產生的 WildChat-1M 對話日誌中進行大規模分析。此外，研究團隊採用與「What's Up, Doc?」相同的使用者中心視角，但將其應用於法律領域，並加入了階層式主題分類，使小型分類器能在不反覆調用前沿模型的情況下套用該分類法。另一項創新是釋出了完整的標註資料、模型權重檔與評估程式碼，促進可重現研究。

**Q6：在兩階段分類管線的設計上有哪些重要的選擇？**
A：研究團隊在設計上採取了多項謹慎的選擇。首先，領域軸採用扁平結構，分類管線先偵測指引尋求再預測主要主題，避免主題分類受到指引與否的混淆。其次，篩選階段使用 GPT-5.6 Terra 進行初步篩選以辨識明顯不相關的素材，但最終的銀標標註則由 GPT-5.6 Sol 在中等推理強度下獨立完成，Terra 的篩選標籤僅用於樣本組成而非最終分析。此外，研究刻意只向模型呈現使用者訊息（依時序排列），排除助理訊息，因為研究焦點在於使用者如何表述法律請求。最後，所有模型決策都在獨立的銀標開發資料上完成定案，僅在黃金評估集上進行最終評估，以避免資料洩漏。

**Q7：本研究使用了哪些資料集與評估資源？**
A：本研究的對話資料源自 WildChat-1M 互動日誌中的英語對話，經過 GPT-5.6 Terra 的初步篩選後保留了 2,122 個對話，結合了被識別為含有法律內容的對話與等量的隨機非法律對話。為了進行模型評估，研究團隊從中保留了固定的 200 個對話子集作為人工審核的黃金評估集，該子集根據初步指引標籤進行抽樣，刻意納入 100 個指引案例。所有標註、模型權重檔、評估程式碼，以及標註提示、JSON 結構描述與執行配置皆透過專案資源公開釋出，使其他研究者能完整重現實驗並進行未來模型開發。

**Q8：本研究在資料分析上揭示了哪些關鍵發現？**
A：在豐富化樣本中，71.1% 含有法律內容的對話實際上是在尋求個人化或實務性的法律指引，顯示真實使用者向 AI 求助時多數帶有具體的法律困擾。在請求類型方面，「權利與選項建議」是最常見的主要請求類型，反映出使用者最關切的並非單純的法律知識，而是「我該怎麼辦、我有什麼選擇」。此外，25.3% 的指引正向對話橫跨多個法律主題，凸顯了真實法律問題的跨領域特性，也對單一主題分類的簡化假設提出了挑戰。這些發現為理解公眾法律資訊需求提供了實證基礎。

**Q9：ModernBERT 模型與 TF-IDF 串接分類器的比較結果為何？**
A：本研究在黃金評估集上進行了 ModernBERT-base、ModernBERT-large 與詞彙串接分類器（TF-IDF cascade）的兩階段比較。雖然具體數字需參考完整論文，但研究設計的重點在於評估較小的、可本地部署的模型是否能有效替代需要反覆調用前沿模型的方法。詞彙串接分類器作為基準，提供了可解釋性強但表達能力有限的對照組；ModernBERT 系列則代表了現代預訓練編碼器在領域特定分類任務上的能力。這種比較對於決定實際部署時該使用輕量級方案還是更強的模型具有重要參考價值。

**Q10：這項研究能支援哪些實際應用情境？**
A：本研究的框架支援多種實際應用情境。首先，大規模擷取功能可讓研究者從海量對話資料中系統性地萃取出法律指引請求，用於實證研究公眾法律資訊需求。其次，精簡指引偵測器可整合至對話式 AI 系統中，作為觸發安全防護措施的依據，例如在使用者提出法律指引請求時自動附加免責聲明或建議諮詢專業律師。此外，該分類法也可用於法律協助受理（legal-aid intake）系統，自動分流不同法律領域的案件，提升法律援助機構的效率。對於學術界而言，公開的標註資料集也成為法律 NLP 研究的寶貴資源。

**Q11：在產品設計與安全考量上，這項研究帶來哪些啟示？**
A：這項研究對產品設計的核心啟示在於：通用助理需要根據使用者意圖的性質調整回應策略。當偵測到使用者正在尋求具體的法律指引時，系統不應僅僅生成答案，還應主動提示「這不是專業法律建議，建議諮詢律師」。在安全考量方面，校準後的指引偵測器可作為一道防線，避免模型在缺乏可靠依據的情況下自信地產生法律幻覺。此外，產品設計者也應考慮到 25.3% 的對話橫跨多個法律主題，這意味著單一領域的回應可能不足以滿足使用者的真實需求，系統應具備識別跨領域問題並適當升級處理的能力。

**Q12：這項研究對法律 NLP 領域的更廣泛影響為何？**
A：這項研究對法律 NLP 領域的影響體現在三個層面。在方法論上，它示範了如何將使用者中心視角引入法律 NLP 研究，從「模型能做什麼」轉向「使用者實際需要什麼」。在資源建設上，公開釋出的標註資料、模型權重檔與評估程式碼大幅降低了後續研究的門檱，促進可重現研究與未來模型開發。在學術定位上，本研究填補了現有法律基準測試（多為專家定義的推理任務）與真實世界使用者需求之間的鴻溝，為法律 NLP 開啟了一個新的研究方向——理解並支援普通公民的法律資訊需求，而非僅僅服務於法律專業人士。

**Q13：本研究承認哪些研究限制？**
A：本研究存在多項重要限制。首先，2,122 個對話的樣本來自 WildChat-1M 的英語對話，且經過 GPT-5.6 Terra 的初步篩選，因此標籤分布無法用來估計 WildChat 中的真實法律指引請求普遍率。其次，銀標標註依賴 GPT-5.6 Sol 的自動標註，雖然黃金評估集經過人工審核，但整體分析的品質仍受限於模型的標註能力。此外，分類法的主題軸採用扁平結構，可能無法充分捕捉法律領域之間的階層關係。最後，研究僅分析使用者訊息而排除助理訊息，雖然這是刻意的設計選擇，但也意味著無法從對話互動的演變中觀察指引需求的浮現過程。

**Q14：本研究可能面臨哪些失敗案例或挑戰？**
A：本研究可能面臨的挑戰包括：當使用者以模糊或間接方式表述法律需求時（例如以虛構故事包裝真實處境），指引偵測器可能難以正確辨識。鑑於 25.3% 的指引正向對話橫跨多個法律主題，主要主題的單一指派可能會遺失重要的次要議題，造成下游應用的資訊損失。此外，黃金評估集僅有 200 個對話，雖然足以進行模型比較，但對於評估罕見法律主題或邊界案例的表現可能樣本數不足。另一個挑戰在於，模型在不同司法管轄區或語言下的泛化能力尚未驗證，本研究的結論是否能推廣至非英語系國家仍屬未知。

**Q15：本研究的未來研究方向為何？**
A：本研究的未來發展方向可從多個層面展開。在資料層面，可擴展至多語言對話與不同司法管轄區，以驗證分類法的跨文化適用性。在模型層面，可探索更大規模的預訓練模型、領域特定微調，或結合檢索增強生成（RAG）以提升指引偵測的準確性與可解釋性。在應用層面，可將偵測器整合至實際的對話系統中進行使用者測試，評估安全提示通知對使用者行為與滿意度的影響。此外，也可進一步研究對話中指引需求的演變模式——例如使用者在多輪互動中如何逐步揭露其法律處境——以設計更細緻的介入策略。最後，將此框架與健康資訊、金融建議等其他高風險領域的類似研究進行比較，將有助於建立跨領域的對話式 AI 安全防護通用原則。

## 實務應用指南

### 適用場景

1. **通用對話助理中的法律諮詢路由**：在 ChatGPT、Claude、Gemini 等公開大型語言模型前端部署「精簡指引偵測器」，當偵測到使用者正在尋求個人化或實務法律指引時，自動觸發免責聲明、調整回應語氣，或將請求路由至具備法律領域微調的模型分支。

2. **法律援助聊天機器人的意圖分流**：民事法律援助機構（legal-aid intake）可將此分類法作為第一層篩選器，先判斷使用者是否真的在尋求指引，再依 14 個主要法律主題（移民與公民身分、僱傭與勞動、住房與財產、商業與貿易、消費者與個人財務等）分流給對應領域的律師助理或專業代理人。

3. **對話資料集的合規稽核與脫敏**：企業內部累積大量客服或 AI 助理對話紀錄時，可使用此框架批次掃描，自動標記出涉及法律後果的對話，協助法務團隊進行個資審查、GDPR 合規檢查，以及判斷哪些對話需進入律師—當事人保密特權（attorney-client privilege）流程。

4. **公開 LLM 的安全防護觸發**：當模型即將輸出具體法律建議時，可串接此偵測器作為 guardrail，自動插入「本回答不構成法律建議，建議諮詢執業律師」等提示通知（notice），降低使用者因誤信幻覺內容而採取行動的風險。

5. **法律 NLP 基準測試的資料前置處理**：學術界在建構法律領域問答、檢索或答案生成基準時，可先用此分類法從大型對話資料集中萃取「真實使用者意圖」的子集，避免僅依賴專家定義的推理任務而忽略真實場景中的請求分布。

### 實作前置條件

**資料需求**
- 對話來源：WildChat-1M 或具備多輪對話結構的公開／內部對話紀錄（須含 `user` 與 `assistant` 訊息欄位與時間戳）。
- 銀標資料：透過 GPT-5.6 Sol 等前沿模型依多軸分類法批次標註，建議至少 1,000–2,000 筆以涵蓋 14 個法律主題。
- 黃金評估集：邀請具法律背景的標註者人工審核 200 筆左右對話，用於最終模型評估。
- 標註規範文件（codebook）：明確定義「法律內容」與「尋求指引」的邊界，例如翻譯法條、虛構爭議、學術解釋屬於前者，詢問自身權利、後續步驟則屬後者。

**運算資源**
- ModernBERT-base / ModernBERT-large 微調：單張消費級 GPU（如 RTX 4090 或 A6000）即可完成；large 模型建議使用 A100 40GB。
- TF-IDF 串接分類器：僅需 CPU，數分鐘內可完成訓練與推論，適合作為 baseline 或低資源環境的部署選項。
- 推論延遲目標：ModernBERT-base 在單句輸入下應低於 50 ms，可支援即時對話路由。

**技能門檻**
- 自然語言處理：熟悉 BERT 家族微調、TF-IDF 特徵工程、階層式分類管線設計。
- 法律領域素養：能區分「法律資訊」與「法律建議」、理解 14 個法律主題的內涵與重疊情境。
- 標註品質管理：熟悉 Cohen's kappa、Krippendorff's alpha 等標註者間一致性指標，能處理類別不平衡與多標籤情境。
- MLOps：模型權重檔版本管理、評估程式碼封裝、CI/CD 串接以支援可重現研究。

### 實作步驟建議

**步驟一：定義分類法與標註指引**
採用論文的三軸分類法——法律相關性軸（legal relevance）、互動軸（interaction）、領域軸（domain）。將 14 個法律主題（含 OTHER 殘差類別）與 6 種請求類型（權利與選項建議、資訊或解釋、程序協助、文件起草、文件審閱、其他）寫成編碼手冊，並以 30–50 筆對話進行先導研究以迭代修正。

**步驟二：建立銀標資料集**
以 GPT-5.6 Sol（或同等前沿模型）對 2,000 筆以上對話進行批次標註，僅餵入使用者訊息（依時序排列），排除助理回應以聚焦「使用者如何表述請求」。輸出 JSON 結構須符合論文中釋出的 schema，並記錄 reasoning effort 與 prompt 版本以便重現。

**步驟三：訓練兩階段分類管線**
- 第一階段（指引偵測）：以 ModernBERT-base 為預設選項，在銀標資料上微調，預測「是否尋求個人化或實務法律指引」。
- 第二階段（主題分類）：僅對指引正向樣本訓練 ModernBERT-large，預測 14 個主要法律主題；可選擇性加入次要主題（multi-label）以處理 25.3% 的多主題對話。
- 同步訓練 TF-IDF 串接分類器作為詞彙基準，比較兩種架構在黃金評估集上的精確率、召回率與 F1 分數。

**步驟四：建立黃金評估集並凍結模型決策**
從銀標資料中分層抽樣 200 筆，由法律專家或受過訓練的標註者人工審核。**重要原則**：所有模型決策（超參數、類別合併策略、門檻值）必須在獨立的銀標開發資料上完成定案後，才能在黃金評估集上做最終評估，以避免資料洩漏。

**步驟五：部署與監控**
將第一階段模型封裝為低延遲推論服務（ONNX 或 TensorRT 加速），串接至對話系統前端。輸出包含機率分布與門檻值判斷（例如指引機率 > 0.7 觸發路由）。上線後持續監控分布偏移、類別不平衡與幻覺率，並定期以新對話重新標註以更新模型。

**步驟六：釋出與可重現性**
將標註資料、模型權重檔、評估程式碼、prompt 與 JSON schema 全部公開（如同論文釋出至 GitHub），附上資料使用條款與隱私脫敏聲明，促進可重現研究與未來模型開發。

### 潛在風險與注意事項

**法律幻覺與誤導風險**
大型語言模型可能自信地產生不可靠的法律資訊（Dahl et al., 2024）。本分類器僅判斷「使用者是否在尋求指引」，並未評估答案正確性。**緩解措施**：偵測到指引請求後，必須搭配免責聲明、引用法條來源、或路由至律師審閱流程，不可單獨作為可信度背書。

**類別不平衡與多主題重疊**
論文中 25.3% 的指引正向對話橫跨多個法律主題，且 14 個主題的分布並不均勻。**緩解措施**：採用分層抽樣、class weighting 或 focal loss；對多主題案例使用 multi-label 分類頭而非強制單標籤。

**隱私與個資洩漏**
對話中常包含姓名、地址、案件細節等個人識別資訊（PII）。**緩解措施**：標註階段即進行資料匿名化；遵循 GDPR 與在地隱私法規；對外釋出資料時僅保留使用者訊息、移除助理回應以降低再識別風險。

**標註者間一致性低**
「尋求指引」與「討論法律內容」的邊界模糊，例如「我想了解離婚程序」可能介於資訊請求與指引請求之間。**緩解措施**：建立清楚的標註指引、進行標註者訓練、以 Cohen's kappa 監控一致性，並對歧異案例進行裁定（adjudication）。

**分布偏移與領域漂移**
法律本身隨法規修訂而演進，使用者的提問模式也會隨社會事件波動。**緩解措施**：建立定期再標註與再訓練機制；監控 out-of-distribution 輸入；保留人工 escalation 通道。

**誤觸發的負面體驗**
若對非法律對話誤觸發法律免責聲明，會干擾使用者體驗。**緩解措施**：提高指引偵測的精確率權重、調整門檻值、進行 A/B 測試以平衡召回率與使用者滿意度。

### 與其他技術的整合建議

**與檢索增強生成（RAG）整合**
將第一階段指引偵測器作為 RAG 管線的前置過濾器：偵測到指引請求後，從法律知識庫（如法規向量資料庫）檢索相關條文，再交由 LLM 生成附引用的回答。可使用 FAISS、Pinecone 或 Weaviate 作為向量儲存，搭配 LangChain 或 LlamaIndex 編排流程。

**與警示系統（Guardrails）整合**
將分類器輸出串接至內容安全層，例如 NeMo Guardrails、Guardrails AI 或自製規則引擎。當指引機率超過門檻值，自動注入「我不是律師，以下僅為一般資訊」等系統提示，並限制模型不得給出具體行動建議。

**與人類專家路由整合**
在民事法律援助場景中，可將 14 個法律主題的預測結果直接路由至對應領域的律師助理或值班律師，形成「AI 分流 → 人類專業判斷」的混合流程，兼顧可擴展性與專業判斷品質。

**與對話分析平台整合**
將分類器封裝為 API 端點，串接至內部對話分析儀表板（如基於 Pandas、Matplotlib 的自製報表或商業產品），讓法務、產品與合規團隊即時掌握使用者法律需求的分布與趨勢。

**與模型監控（MLOps）整合**
使用 Hugging Face Inference Endpoints 或自建 Kubernetes 部署，搭配 Prometheus 監控延遲、吞吐量與預測分布；當分布偏移超過預設閾值時觸發告警，啟動再訓練流程。

**與多模態擴展整合**
未來可將分類法擴展至語音轉文字對話、客服錄音轉錄等場景，僅需將輸入改為對話文字流，模型架構不變；亦可加入文件附件（如租約、傳票）的多模態分類。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與緒論，理解「為什麼法律內容不等於尋求指引」這個核心區分；接著瀏覽第 3 節的分類法三軸說明，試著用身邊的真實對話範例比對 14 個法律主題與 6 種請求類型；不必急於理解模型細節，重點是建立「使用者意圖分析」這個問題意識。

**給 AI 工程師**：直接聚焦第 3 節的資料建構流程與第 4 節（推論）的兩階段分類管線設計；特別注意作者強調的「在銀標開發資料上定案所有模型決策後，才能在黃金評估集上做最終評估」這個實驗嚴謹性原則；可參考 GitHub 釋出的程式碼與模型權重檔，將 ModernBERT-base/large 與 TF-IDF 串接分類器整合至現有對話系統的路由層。

**給研究者**：本論文在方法論上最值得借鏡之處是「使用者中心」的分類法建構與「銀標 + 黃金」的雙層評估設計；可與近期健康資訊對話分析（What's Up, Doc?）做方法論對照，並思考如何將此框架擴展至金融、稅務、教育等其他高風險領域；亦可進一步研究 25.3% 多主題對話的處理策略，以及分類器在分布外輸入下的穩健性。

**給產品經理**：本研究的商業價值在於「精簡指引偵測器」可作為公開 LLM 產品的合規與安全防護基礎建設；71.1% 的法律內容對話涉及個人化指引這個數字，凸顯了市場對「可信賴法律 AI 助理」的潛在需求；建議評估將此分類器整合至現有產品的免責聲明觸發、法律援助路由、客服合規稽核等場景，並關注法律幻覺、使用者體驗與隱私保護三者間的取捨。
