# ReVision：透過時序視覺冗餘縮減擴展電腦使用智慧體

**原文標題：** ReVision: Scaling Computer-Use Agents via Temporal Visual Redundancy Reduction

**發布日期：** 2026-06-05  
**HF 連結：** [https://huggingface.co/papers/2605.11212](https://huggingface.co/papers/2605.11212)

## ⚡ TL;DR

電腦使用智慧體在處理連續截圖時，視覺標記因時序冗餘而急劇增加，導致歷史紀錄難以擴展且效能停滯。
ReVision透過學習式區塊選擇器比對連續截圖，濾除冗餘視覺區塊並保留空間結構，無須修改模型架構。
於三項基準測試中，ReVision平均減少46%標記並提升3%成功率，使智慧體得以處理更長互動軌跡。

## 摘要翻譯

電腦使用智慧體（Computer-use agents, CUAs）依賴圖形使用者介面（graphical user interfaces, GUIs）的視覺觀察（visual observations），其中每張螢幕截圖（screenshots）均被編碼為大量視覺標記（visual tokens）。隨著互動軌跡（interaction trajectories）增長，標記成本（token cost）迅速增加，限制了在固定上下文預算（context budget）與計算預算（compute budget）下可納入的歷史資訊量。這導致在使用歷史時，效能幾乎沒有或僅有極為有限的提升，有別於其他領域。我們提出 ReVision 以解決此效率不彰的問題：利用學習式區塊選擇器（learned patch selector）比較連續截圖（consecutive screenshots）間的區塊表示法（patch representations），在保留模型所需空間結構（spatial structure）的前提下移除冗餘視覺區塊（redundant visual patches），並於過濾後的軌跡（filtered trajectories）上訓練多模態語言模型（multimodal language models）。橫跨 OSWorld、WebTailBench 與 AgentNetBench 三個基準測試，在使用 Qwen2.5-VL-7B 處理包含 5 張歷史截圖（history screenshots）的軌跡時，ReVision 平均減少 46% 的標記使用量（token usage），相較於無刪減基線（no drop baseline）提升 3% 的成功率（success rate）。這確立了顯著的效率增益（efficiency gain），使智慧體能夠以更少標記處理更長的軌跡。藉由這項提升的效率，我們重新審視歷史在 CUAs 中的角色，並發現在移除冗餘後，隨著納入更多過往觀察（past observations），效能持續改善。

### 核心貢獻（3～5點）
- 揭示電腦使用智慧體在納入視覺歷史時的效率瓶頸：隨著互動軌跡增長，視覺標記成本迅速攀升，導致在固定上下文與計算預算下難以利用歷史資訊，且效能幾乎無法提升。
- 提出 ReVision 方法，透過學習式區塊選擇器比較連續截圖間的區塊表示法，在保留空間結構的前提下移除冗餘視覺區塊，並於過濾後的軌跡上訓練多模態語言模型。
- 於 OSWorld、WebTailBench 與 AgentNetBench 三個基準測試驗證，使用 Qwen2.5-VL-7B 處理含 5 張歷史截圖的軌跡時，平均減少 46% 標記使用量，同時相較無刪減基線提升 3% 成功率，確立顯著效率增益。
- 發現在移除時序視覺冗餘後，隨著納入更多過往觀察，電腦使用智慧體的效能持續改善，重新確立歷史資訊在視覺代理中的價值。

### 適合對象
從事多模態大型語言模型、電腦使用智慧體、圖形使用者介面自動化與視覺網頁代理相關研究的研究人員與工程師，以及關注模型推論效率、標記縮減與長上下文視覺理解之系統性最佳化的學者與實務工作者。

## 深度分析

#### 方法論解析

Computer-use agents（電腦使用智慧體, CUAs）在操作 graphical user interfaces（圖形使用者介面, GUIs）時，通常將每一張 screenshots（螢幕截圖）編碼為大量 visual tokens（視覺標記）。隨著 interaction trajectories（互動軌跡）增長，token cost（標記成本）快速上升，導致在固定的 context budget（上下文預算）與 compute budget（計算預算）下，模型難以納入充足的 history screenshots（歷史截圖）。ReVision 的核心洞見在於：consecutive screenshots（連續截圖）之間存在高度的 temporal visual redundancy（時序視覺冗餘），平均有 45.4% 的 patches 在步驟間並未改變，卻仍被重複編碼與處理。

為解決此問題，ReVision 引入 learned patch selector（學習式區塊選擇器），透過比較跨時間的 patch-level representations（區塊級表示法），篩選出 visually redundant regions（視覺冗餘區域）。與單純在推論階段丟棄標記不同，ReVision 將模型（本研究使用 Qwen2.5-VL-7B）直接在 filtered trajectories（過濾後的軌跡）上進行訓練，使其學會在 compact visual histories（緊湊的視覺歷史）上進行 language-based reasoning（基於語言的推理）。關鍵在於，此過程保留了 spatial structure（空間結構）——即影像區塊的相對位置關係——這對於執行 clicks, typing, and navigation（點擊、輸入與導航）等 grounded actions（具體化動作）至關重要。由於無需 architecture changes（架構變更），ReVision 可與現有 Multimodal large language models（多模態大型語言模型, MLLMs）相容，僅透過調整輸入的 visual tokens（視覺標記）分佈即可提升效率。

#### 實驗數據解讀

本研究在 OSWorld、WebTailBench 與 AgentNetBench 三項基準測試上進行評估。首先，Table 1 的統計顯示，在八個 computer-use 環境中，平均每張截圖有 45.4% 的 redundant visual patches（冗餘視覺區塊），最高達 56.2%（OSWorld），最低亦有 36.4%（GUIAct）。這相當於每步平均浪費超過 1,000 個重複區塊，直接證明了 token reduction（標記縮減）的巨大潛力。

在使用 Qwen2.5-VL-7B 並納入 5 張 history screenshots（歷史截圖）的設定下，ReVision 平均減少 46% 的 token usage（標記使用量），同時在 success rate（成功率）上較 no drop baseline（無刪減基線）提升 3%。更具意義的是歷史長度的擴展行為：當僅使用 3 張歷史影像時，ReVision 已能接近部分最佳基線的表現，但僅消耗約一半的 visual tokens（視覺標記）；當歷史長度增加至 5 張或更多時，ReVision 平均穩定領先多數基線至少 2%。這項結果確立了明確的 efficiency gain（效率增益）：透過 Temporal Visual Redundancy Reduction（時序視覺冗餘縮減），agents 能夠在相同計算資源下處理更長的 interaction trajectories（互動軌跡），且效能隨歷史長度持續提升，打破了傳統方法中歷史納入的邊際效益遞減甚至飽和的現象。

#### 與現有研究的比較

在 visual token pruning（視覺標記修剪）領域，現有方法大致可分為單一影像內的空間修剪與軌跡層級的步驟刪減。ShowUI 與 FocusUI 等研究針對單一截圖內的空間冗餘進行區塊刪除；Focus-Scan-Refine 與 adaptive compression 則依據顯著性（saliency）或重要性壓縮標記。在軌跡層級，FocusAgent 選擇性減少納入上下文的過去步驟數量。然而，這些方法要麼僅在空間維度操作，要麼在時間維度上以整張影像為單位進行刪減，未能顯式建模 consecutive screenshots（連續截圖）之間的區塊級時序冗餘。

相較之下，ReVision 的獨特性在於：
1. **區塊級時序過濾**：直接在 MLLMs（多模態大型語言模型）的 token space 中，比較跨步驟的 patch representations（區塊表示法），而非僅在視覺編碼器的特徵空間或整體影像層級操作。
2. **空間結構保留**：不同於某些壓縮方法可能破壞二維佈局，ReVision 維持了 spatial structure（空間結構），確保模型仍能準確定位 GUIs（圖形使用者介面）元素。
3. **訓練階段整合**：多數現有方法僅在推論時刪減標記，而 ReVision 透過在 filtered trajectories（過濾後的軌跡）上訓練，使模型內建對 sparse visual histories（視覺歷史）的推理能力。

然而，ReVision 亦存在侷限。其冗餘偵測主要聚焦於相鄰兩步的 consecutive screenshots，對於長距離、非連續的視覺變化關聯性並未顯式建模；此外，其效能天花板仍受限於基礎模型 Qwen2.5-VL-7B 的 visual understanding（視覺理解）與推理能力。若能結合單一影像內的 pixels（像素）級或區塊級空間修剪，理論上可進一步推進 efficiency frontier（效率前沿）。

#### 可重現性評估

從提供的文本脈絡檢視，ReVision 採用的三項基準測試——OSWorld、WebTailBench 與 AgentNetBench——均為已公開的評測環境，且基礎模型 Qwen2.5-VL-7B 亦已開源，這為再現研究提供了基本條件。然而，關鍵的 learned patch selector（學習式區塊選擇器）之訓練程式碼、模型權重，以及經篩選的 filtered trajectories（過濾後的軌跡）資料集，在摘要與正文片段中並未明確提及是否公開釋出。

此外，雖然論文概念性地描述了區塊選擇器透過比較跨時間的 patch-level representations（區塊級表示法）來運作，但具體的損失函數設計、訓練超參數、以及如何在不進行 architecture changes（架構變更）的前提下將篩選後的標記序列餵入 Qwen2.5-VL-7B 的技術細節（例如：遮罩策略、位置編碼調整等），在現有片段中著墨有限。這意味著其他研究者若要完全重現此成果，仍需依賴尚未公開的實作細節或補充材料。整體而言，本研究在方法論層面具備可重現的潛力，但實際的開源透明度仍有待確認。

#### 未來研究方向

ReVision 確立了 Temporal Visual Redundancy Reduction（時序視覺冗餘縮減）在擴展 Computer-use agents（電腦使用智慧體, CUAs）上的價值，未來研究可從以下方向延伸：

第一，**長距離時序關聯**：當前方法僅比較 consecutive screenshots（連續截圖），未來可探索跨越多步的冗餘偵測機制，例如當介面在數步後回復先前狀態時，如何辨識並引用歷史 visual observations（視覺觀察）而非重複編碼。

第二，**混合式修剪策略**：將 ReVision 的跨步驟區塊過濾與 ShowUI、FocusUI 等單一影像內的空間修剪結合，同時消除空間與時間維度的冗餘，進一步降低 token cost（標記成本）。

第三，**動態歷史調適**：依據任務複雜度與當前 context budget（上下文預算）動態調整 history screenshots（歷史截圖）數量，而非固定使用 3 或 5 張影像，使 agents 在簡單任務中極致壓縮，在複雜任務中保留更多脈絡。

第四，**跨模態冗餘壓縮**：除了 visual tokens（視覺標記），interaction trajectories（互動軌跡）中的文字歷史（如過往動作與觀察描述）亦存在重複，未來可設計聯合壓縮視覺與語言脈絡的機制。

第五，**模型泛化與 scaling（擴展）**：驗證 ReVision 的 learned patch selector 是否可遷移至其他 multimodal language models（多模態語言模型），如 CogAgent、UI-TARS 或更大規模的 MLLMs（多模態大型語言模型），並探討在更高解析度或更長軌跡下的穩健性。

第六，**效率增益的再投資**：將節省下來的 compute budget（計算預算）用於執行更深入的 language-based reasoning（基於語言的推理）、嘗試多條行動路徑，或整合外部工具，從而將 token efficiency（標記效率）轉化為實質的 success rate（成功率）突破，而非僅止於降低成本。

## 論文問答

**Q1：ReVision 旨在解決電腦使用智慧體中的什麼核心問題？**
A：ReVision 主要解決當電腦使用智慧體處理長篇互動軌跡時，視覺標記成本隨著歷史截圖數量增加而快速膨脹的核心問題。由於每一張螢幕截圖都會被編碼為大量視覺標記，在固定上下文預算與計算預算下，代理能納入的歷史觀察極為有限。這導致與其他領域不同，單純增加歷史截圖數量幾乎無法帶來效能提升，嚴重限制了長期決策的品質。

**Q2：現有方法為何無法有效解決視覺歷史在電腦使用智慧體中的低效問題？**
A：現有方法大多僅在單一影像內進行空間層面的標記縮減，或是在軌跡層面直接減少納入的過去步驟數量，卻未明確建模連續截圖之間的時序視覺冗餘。這使得跨步驟重複出現的視覺區域被一再編碼與處理，造成大量計算資源的浪費。由於這些方法無法在保留關鍵時序證據的同時精細地過濾冗餘區塊，因此難以在擴展歷史長度的同時維持標記效率。

**Q3：為何解決時序視覺冗餘對於推進電腦使用智慧體的發展至關重要？**
A：根據論文分析，在多個基準測試中，平均有 45.4% 的視覺區塊在連續截圖間保持不變，最高甚至超過 56%，這代表將近一半的視覺標記消耗於重複內容。若能有效移除這些冗餘視覺區塊，代理便能在相同計算預算下納入更長的視覺歷史，從而突破效率前沿。這不僅能顯著降低推論成本，更能讓代理在納入更多過去觀察時持續提升成功率，徹底改變歷史資訊在電腦使用智慧體中的價值。

**Q4：ReVision 減少冗餘視覺標記的核心機制是什麼？**
A：ReVision 的核心機制在於使用一個學習式區塊選擇器，比較連續截圖之間的區塊級表示法，以辨識並過濾視覺冗餘區域。不同於僅在推論階段進行標記縮減，該方法直接在過濾後的軌跡上訓練多模態語言模型，使其學會在緊湊的視覺歷史上進行推理。此設計在移除冗餘視覺區塊的同時，完整保留了模型所需的空間結構，且無需進行任何架構變更即可與現有多模態大型語言模型相容。

**Q5：相較於先前的標記縮減方法，ReVision 的關鍵創新為何？**
A：ReVision 的關鍵創新在於它並非僅在單張影像內進行空間剪枝，也非直接丟棄整個歷史步驟，而是針對連續截圖執行細粒度的區塊級時序過濾。更重要的是，它透過在這些經時序過濾的軌跡上進行聯合訓練，讓代理學會如何在部分視覺資訊被移除的情況下，仍能有效利用保留的空間結構進行具體化動作預測。這種專為電腦使用智慧體設計的時序視覺冗餘縮減範式，精準對應了螢幕截圖在代理操作下逐步演變的特性。

**Q6：ReVision 為何選擇在過濾後的軌跡上訓練模型，而非僅在推論時應用區塊選擇？**
A：若僅在推論時移除冗餘區塊，模型在訓練階段從未見過這種帶有「空洞」的緊湊視覺歷史，可能無法正確解讀剩餘區塊的語境與空間關係。透過直接在過濾後的軌跡上進行訓練，ReVision 確保了訓練與推論的分布一致，使模型能穩健地推理被保留的時序證據。這種設計選擇讓模型將標記縮減視為內建能力，而非後天強加的外掛操作，從而顯著提升長期決策的準確性與穩定性。

**Q7：ReVision 在哪些基準測試上進行評估，這些測試衡量什麼能力？**
A：ReVision 在 OSWorld、WebTailBench 與 AgentNetBench 三個長期任務基準測試上進行評估。這些測試主要衡量代理在圖形使用者介面中執行多步驟任務的能力，例如網頁導航、桌面操作與一般電腦使用，代理必須根據視覺觀察生成點擊、輸入與導航等具體化動作。它們特別強調在長期互動軌跡中，代理能否有效利用視覺歷史來完成複雜的實際目標。

**Q8：ReVision 的主要量化結果如何證明其有效性？**
A：在使用 Qwen2.5-VL-7B 處理包含五張歷史截圖的軌跡時，ReVision 平均減少了約 46% 的標記使用量，同時成功率相較於無刪減基線提升了 3%。僅使用三張歷史影像時，它就能以約一半的視覺標記達到接近最佳基線的表現；而當歷史長度增加到五張以上時，其成功率平均領先多數基線至少 2%。這些結果明確顯示，ReVision 不僅大幅提升了標記效率，更透過更有效的歷史利用機制增強了任務成功率。

**Q9：在納入更多歷史截圖時，有無 ReVision 的電腦使用智慧體表現有何差異？**
A：在沒有冗餘移除機制的情況下，增加歷史截圖數量往往導致邊際效益遞減，因為上下文預算被大量重複的視覺標記佔據，使模型快速達到飽和。相對地，採用 ReVision 後，隨著納入更多過去觀察，成功率持續提升，顯示移除冗餘能有效延後視覺歷史的飽和點。這項發現重新確立了歷史資訊在電腦使用智慧體中的價值：問題不在於歷史本身無用，而在於過去未能有效處理時序視覺冗餘。

**Q10：ReVision 在哪些實際應用場景中最能發揮價值？**
A：ReVision 最能發揮價值的場景包括需要長期執行的圖形使用者介面自動化任務，例如自動化軟體測試、複雜網頁工作流程以及桌面環境中的多步驟操作。在這些情境中，代理必須在數十個步驟內持續追蹤介面狀態變化，並在發生錯誤時回溯歷史觀察進行修正，但傳統方法面臨極高的標記成本障礙。透過壓縮視覺歷史同時保留空間結構，ReVision 讓電腦使用智慧體能在計算資源受限的生產環境中實際部署並處理更長的任務軌跡。

**Q11：從產品整合的角度來看，ReVision 具備哪些吸引力？**
A：ReVision 的一大優勢在於它無需對現有多模態大型語言模型進行任何架構變更，即可實現顯著的標記縮減，這對已採用如 Qwen2.5-VL-7B 等模型的產品團隊極具吸引力。由於其學習式區塊選擇器僅過濾冗餘區塊並保留必要的空間結構，開發者可以將其視為即插即用的效率增強層，無需從頭設計代理管線。這種高度相容性大幅降低了導入門檻，使產品在規模化擴展時能立即享有成本降低與效能提升的雙重效益。

**Q12：ReVision 可能對多模態代理研究的廣泛領域產生什麼影響？**
A：ReVision 挑戰了「視覺歷史對電腦使用智慧體 inherently 低效」的既有假設，證明問題根源在於對未改變視覺內容的重複編碼，而非歷史資訊本身。透過確立時序區塊級過濾作為有效典範，它為視覺語言模型在序列決策任務中的高效上下文擴展開闢了新的研究方向。這種思維可望啟發機器人操作、影片理解等其他涉及連續視覺觀察的領域，進而推動長期多模態代理整體效率前沿的進步。

**Q13：ReVision 依賴連續截圖間的區塊級冗餘，這存在哪些固有侷限？**
A：ReVision 的區塊選擇器主要針對相鄰截圖進行比較，當介面發生全域性或劇烈變化時，例如整頁重新載入或應用程式切換，連續影像間的可重複區塊可能極少，此時壓縮效益會大幅下降。此外，該方法假設保留空間結構即足以支撐推理，但在某些情況下，關鍵線索可能以極細微且非局部的方式分布，區塊級比較可能難以精準保留這些語意細節。再者，目前成果主要基於 Qwen2.5-VL-7B 展示，其在採用不同視覺編碼策略的其他多模態大型語言模型上的泛化性仍有待進一步驗證。

**Q14：在什麼樣的條件下，ReVision 可能無法改善甚至損害代理的表現？**
A：當任務涉及快速全畫面轉換，例如影片播放、投影片切換或大型彈出視窗覆蓋時，連續截圖間的視覺重疊極低，區塊選擇器幾乎無法移除冗餘，導致 ReVision 的優勢無法發揮。若關鍵任務資訊恰好出現在與先前冗餘區塊空間對齊的微小區域，且訓練資料未充分涵蓋此類邊界案例，選擇器可能誤判並過濾掉這些必要線索。一旦模型遺失了這些時序證據，就可能對介面狀態產生錯誤理解，進而在長期推理中做出錯誤的具體化動作。

**Q15：基於 ReVision，有哪些值得探索的未來研究方向？**
A：未來研究可將時序過濾的範圍從僅限相鄰截圖擴展至更長期的依賴關係，以捕捉跨越多個步驟的狀態變化與冗餘模式。另一個方向是將 ReVision 的時序區塊級縮減與單張影像內的空間剪枝技術結合，達成更深度的視覺上下文壓縮。此外，將此學習式冗餘移除原則推廣至其他具有連續視覺觀察的領域，例如具身智慧或醫療影像序列分析，也有潛力進一步驗證訓練模型使用時序過濾視覺序列的通用價值。

## 實務應用指南

### 適用場景

1. **企業級流程自動化（RPA）**：財務對帳、ERP 系統間資料遷移等長時任務，代理需在多個視窗間切換數十至上百步，歷史截圖累積迅速。ReVision 可在不超出上下文預算的前提下，讓模型回溯更早的操作狀態，降低因遺失前期畫面而導致的流程中斷。
2. **客服與技術支援代理**：代理需引導使用者或自行後台排查，連續瀏覽知識庫、CRM 與設定頁面。這些頁面往往僅有局部內容變動（如選單展開、表單驗證提示），ReVision 能有效過濾導航列與頁首等固定區域，保留關鍵對話與錯誤訊息。
3. **遠端桌面與雲端作業代理**：在 VNC、RDP 或無頭瀏覽器環境中執行軟體部署、資料清理等長軌跡任務時，畫面變化頻率低但步數極長。透過時序視覺冗餘縮減，可顯著降低雲端 GPU 推論成本，並在相同計算預算下延長單次連線的可處理步數上限。
4. **網頁表單自動化與資料擷取**：跨頁面爬蟲或自動填表過程中，頁面骨架高度重複，僅有表格內容或分頁索引變動。ReVision 的區塊選擇器可學習保留動態內容區域，避免重複編碼相同的頁首與廣告版位，提升長序列網頁導航的穩定性。
5. **無障礙輔助操作與 UI 導航**：協助視障使用者操作桌面或行動裝置 GUI 時，代理需持續監控介面狀態。冗餘縮減能降低端到端延遲，使語音回饋更即時，同時在裝置端資源受限情境下延長可處理的歷史長度。

### 實作前置條件

- **資料**：需具備目標環境的互動軌跡資料，包含連續螢幕截圖與對應的具體化動作標註；若缺乏區塊級冗餘標籤，可先以現有軌跡搭配 GPT-4o 或 SSIM/餘弦相似度產生偽標籤，作為學習式區塊選擇器的冷啟動訓練資料。
- **運算資源**：微調階段建議至少配置 1 至 2 台 A100/H100（80GB）等級 GPU，以支援 Qwen2.5-VL-7B 或同等規模多模態大型語言模型的全參數或 LoRA 微調；推論端需能部署視覺編碼器與輕量區塊選擇器，並支援動態 patch masking。
- **技術能力**：團隊需熟悉多模態模型訓練流程（如 DeepSpeed、FSDP、LoRA）、視覺特徵比對與相似度計算、GUI 自動化工具鏈（Selenium、Playwright、pyautogui），以及具備處理 2D 位置編碼與注意力遮罩相容性的經驗。

### 實作步驟建議

1. **軌跡錄製與冗餘量化**：在目標應用程式中錄製操作軌跡，將連續截圖切分為固定大小的視覺區塊，計算跨幀的區塊表示法相似度，建立內部冗餘基線（參考表 1 方法），識別高冗餘區域（如靜態背景、固定導航列）。
2. **訓練時序區塊選擇器**：以輕量 MLP 或小型 CNN 在凍結的視覺編碼器特徵上訓練 patch scorer，輸入為相鄰兩幀對應位置的區塊級表示法，輸出為保留機率；損失函數需同時優化冗餘過濾率與空間結構保留，避免破壞模型所需的 2D 位置資訊。
3. **產生緊湊視覺歷史並微調模型**：使用訓練完成的選擇器過濾歷史軌跡，產生 filtered trajectories；以此資料微調 Qwen2.5-VL-7B（建議先以 LoRA 驗證可行性），使模型學會在缺漏部分視覺區塊的情況下進行推理與動作預測。
4. **部署推論管線**：在生產環境中，於視覺編碼器後嵌入區塊選擇器，動態比較當前幀與前一幀，僅將非冗餘的視覺標記送入多模態語言模型；確保剩餘 patch 的空間結構與位置編碼正確對應，無需進行架構變更。
5. **漸進式評估與規模化**：先以 3 張歷史截圖驗證 token 縮減率與成功率，確認接近論文所述的約 50% 標記縮減後，再逐步擴展至 5 張或更多歷史截圖，觀察效能飽和點是否延後，並監控端到端延遲與成本。

### 潛在風險與注意事項

- **關鍵微幅變化遺失**：過度過濾可能移除載入動畫、顏色狀態變化或微小提示訊息。建議對文字區域與互動元件設定較高保留權重，或採用動態閾值機制，確保任務相關線索不被捨棄。
- **空間結構與位置編碼錯位**：直接刪除 patch 若未妥善維護相對位置，會導致模型誤判點擊座標。實作時必須保留剩餘區塊的 2D 位置編碼對應關係，或使用佔位標記維持網格結構。
- **跨解析度與主題的分佈偏移**：訓練資料若僅涵蓋特定解析度或深淺色主題，推論時遇到新介面可能失效。應於多種解析度、縮放比例與色彩主題下進行資料增強，提升選擇器泛化能力。
- **計算開銷轉移而非減少**：patch 比對與選擇器推論會增加前端視覺編碼器的負擔。需進行端到端基準測試，確認整體延遲確實下降，避免瓶頸僅從語言模型轉移至視覺前處理層。
- **長期歷史的資訊斷裂**：當歷史長度極長時，過早截圖與當前畫面可能已無明顯對應關係，不適用簡單的相鄰冗餘比對。建議搭配分層記憶體機制，定期插入關鍵幀全保留，或將遠期歷史轉為文字摘要。

### 與其他技術的整合建議

- **嵌入現有 CUA 框架**：ReVision 可視為獨立的視覺前處理模組，無縫整合至 Open-CUA、UI-TARS、AGUVIS 等視覺優先範式架構，無需修改底層多模態大型語言模型架構，僅需在視覺編碼器輸出後加入區塊選擇邏輯。
- **融合結構化表示法**：與 DOM、輔助功能樹或 Set-of-Marks (SoM) 結合，利用結構化訊息輔助判斷哪些區塊包含可互動元素，使區塊選擇器在過濾背景時更精準，同時保留按鈕、輸入框等任務關鍵區域。
- **搭配 RAG 與長期記憶**：將過濾後的緊湊視覺歷史存入向量資料庫，近期軌跡以 ReVision 壓縮後的視覺標記處理，遠期歷史則透過檢索取得關鍵幀或文字摘要，實現雙層記憶架構。
- **推論引擎優化**：搭配 vLLM、TensorRT-LLM 等服務框架時，利用縮短的視覺標記序列提升 batch size 與吞吐量；輕量選擇器可部署於邊緣端或作為前置代理，降低中心雲端的計算預算壓力。
- **可觀測性與除錯**：整合 Langfuse、LangSmith 或自研監控面板，視覺化標記被過濾的區域（如以熱力圖標示），協助工程師理解模型「看到了什麼」，加速除錯與建立業務信任。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從「連續截圖為何浪費標記」這個直覺問題出發，先理解圖 1 與表 1 的冗餘數據；把 ReVision 想像成「只保留畫面有變化的區塊，其餘用透明膠帶貼起來」，不必急著理解區塊選擇器的數學細節，重點放在它如何讓電腦使用智慧體在相同成本下記得更多歷史、完成更長任務。
- **AI 工程師**：請聚焦論文第 4 節的實作細節，特別注意 selector 是在「區塊級表示法」層級運作，而非直接比對像素；評估移植到您現有 MLLM（如 InternVL、LLaVA）的可行性時，務必檢視位置編碼與 attention mask 的相容性，並優先以 LoRA 驗證微調策略。
- **研究人員**：本文的核心貢獻在於證明「去除時序視覺冗餘不僅節省計算，還能提升成功率（+3%）」，這與壓縮必然損失資訊的直覺相反；建議深入探討冗餘移除是否減輕了注意力分散（attention distraction），並思考如何將此概念擴展至影片理解、機器人操作等其他具時序冗餘的領域。
- **產品經理**：請將本文視為「在固定成本下延長代理記憶長度」的解決方案；關鍵數字是 46% 的標記縮減與 3% 的成功率提升，這代表您無需升級硬體或換用更大模型，即可讓代理處理更複雜的多步驟任務。評估導入時，請優先盤點現有流程中歷史截圖佔用的標記成本與任務失敗率，以估算投資報酬率。
