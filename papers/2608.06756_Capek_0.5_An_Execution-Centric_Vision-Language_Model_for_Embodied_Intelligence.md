# Capek 0.5：以執行為中心的具身智能視覺語言模型

## ⚡ TL;DR

現有具身視覺語言模型多按任務孤立訓練，難以支援反覆執行與可驗證推理。
Capek 0.5 以執行為中心將能力分為四類，先訓練專家再合併權重並蒸餾為單一模型。
2B 與 35B-A3B 模型在多數基準上提升，保留四項能力並成功轉移至閉環具身任務。

## 摘要翻譯

視覺語言模型（Vision-Language Model, VLM）日益成為具身智能體（Embodied Agent）的推理核心。機器人的執行過程本質上是迭代的：每個動作都會重塑場景與物理狀態，持續更新所需感知、推理與驗證的內容。要滿足這些需求，需要多種互補能力（Complementary Ability），而這些能力在監督訊號（Supervision Signal）、預測格式（Prediction Format）與驗證標準（Verification Criterion）上各有不同。現有方法通常針對彼此孤立、任務特定目標（Task-Specific Objective）來發展這些能力，至於它們應如何圍繞整體執行進行組織與整合，仍待釐清。我們提出 Capek 0.5，一個以執行為中心（Execution-Centric）的能力分類法（Capability Taxonomy）為核心所建構的具身視覺語言模型。此分類法並非依資料集或任務來組織訓練，而是根據各項具身能力在整個執行過程中所扮演的功能角色（Functional Role）進行分群，包含四大能力家族：空間推理（Spatial Reasoning）、時間理解（Temporal Understanding）、動作引導（Action Guidance）與狀態驗證（State Verification）。每項能力首先由一個專用專家模型（Dedicated Specialist）從共享骨幹網路（Shared Backbone）出發，透過具可驗證獎勵（Verifiable Reward）的強化學習（Reinforcement Learning）習得；接著，這些專家模型先經權重空間合併（Weight-Space Merging），再透過路由策略空間蒸餾（Routed Policy-Space Distillation），整合為單一推論時模型（Inference-Time Model）。我們在 2B 規模（2B Scale）與 35B-A3B 規模（35B-A3B Scale）上實例化 Capek 0.5，並從三個互補視角進行評估：全面的基準測試套件，包含新提出的狀態驗證基準 Capek-StateBench；從專家模型到統一模型的能力保留對照研究；以及在模擬具身環境（Simulated Embodied Environment）中的閉環評估（Closed-Loop Evaluation）。Capek 0.5 在絕大多數匹配的基準項目（Matched Benchmark Row）上，相較於初始化（Initialization）起點均有提升，在單一檢查點（Single Checkpoint）中保留全部四項專業化能力並量化各項能力的損失，且能遷移至閉環具身任務執行。

### 核心貢獻（3～5點）
- 提出以執行為中心的能力分類法，將具身能力依其在執行過程中的功能角色分為空間推理、時間理解、動作引導與狀態驗證四大家族。
- 設計從專家模型到統一模型的後訓練流程：各能力先由專用專家模型透過可驗證獎勵的強化學習習得，再經權重空間合併與路由策略空間蒸餾整合為單一檢查點。
- 在 2B 與 35B-A3B 兩種規模上實現 Capek 0.5，並透過整合分析量化單一模型對四項專業能力的保留程度。
- 提出新的狀態驗證基準 Capek-StateBench，並從綜合基準、能力保留研究與模擬環境閉環評估三個互補視角驗證模型效能。
- 證明統一後的 Capek 0.5 能在絕大多數匹配基準項目上超越初始化起點，並成功遷移至閉環具身任務執行。

### 適合對象
本論文適合對具身智能（Embodied Intelligence）、視覺語言模型（VLM）與機器人執行感興趣的研究人員與工程師，特別是關注如何將多種互補能力整合為單一可部署模型、以及希望透過強化學習與模型合併技術提升具身智能體執行效能的讀者。從事機器人導航、操作任務規劃、視覺推理基準設計或模型能力蒸餾相關研究的學者亦可從中獲得方法論與實驗設計上的參考。

## 深度分析

#### 方法論解析

##### 以執行為中心的能力分類法（Execution-Centric Capability Taxonomy）

Capek 0.5 的核心設計並非沿用傳統「按資料集（dataset）或任務（task）組織訓練」的思維，而是提出一套圍繞機器人執行迴圈（execution loop）的能力分類法（capability taxonomy）。該分類法將具身智能體（embodied agent）在反覆「觀察—推理—動作—驗證」過程中所需的能力，依功能角色（functional role）歸納為四大能力家族（capability family）：

1. **Spatial Reasoning（空間推理）**：處理場景幾何（scene geometry）、物體間關係（inter-entity relation）與空間上下文。
2. **Temporal Understanding（時間理解）**：建模事件順序（event order）、時間定位（temporal localization）與隨時間的變化。
3. **Action Guidance（動作引導）**：將任務相關實體（task-relevant entity）、可供性（affordance）對應到影像空間的點（point）、區域（region）與有序軌跡（ordered trajectory）。
4. **State Verification（狀態驗證）**：判斷物理謂詞（physical predicate）是否成立，以及任務目標（task goal）是否達成。

這種分類的關鍵在於強調四種能力並非互斥的階段，而是在單一執行軌跡（trajectory）中反覆出現、彼此重疊。例如在家庭操作任務中，智能體可能在同一時間需要更新空間上下文、定位事件、選擇動作目標，並驗證「火堆已點燃」這類狀態謂詞。

##### 面向能力的資料建構（Capability-Oriented Data Construction）

為配合上述分類法，Capek 0.5 採用 Capability-Oriented Data Construction（面向能力的資料建構），將訓練資料按四大能力家族重新組織，而非按原始資料集劃分。每個能力家族都有對應的資料來源與標註格式：

- **Spatial Reasoning（空間推理）**：可能包含相對位置、遮擋關係、支撐關係、3D 邊界框（3D bounding box）等結構化關係。
- **Temporal Understanding（時間理解）**：包含事件時間戳、動作順序、狀態轉換（state transition）等時間標註。
- **Action Guidance（動作引導）**：包含點選（pointing）、區域標註（region annotation）、軌跡（trajectory）等影像空間輸出。
- **State Verification（狀態驗證）**：包含二元或多元的物理狀態謂詞、任務完成證據等。

為了讓異質輸出能夠在單一模型中處理，作者進一步提出 **Unified Output Interface（統一輸出介面）** 與 **Data Standardization（資料標準化）**，將不同來源的標註轉換為一致的 token 序列格式。這是後續能夠使用單一語言模型（language model）進行多樣化預測的基礎，也讓不同能力的監督訊號（supervision signal）可以在相同解碼框架下被表達。

##### 專家到統一的後訓練（Specialist-to-Unified Post-Training）

Capek 0.5 的方法論可視為「先分後合」：先讓各能力在獨立專家模型（dedicated specialist）中充分學習，再將其整合為單一推論時模型（inference-time model）。

**第一階段：Capability Specialist Training（能力專家訓練）**

四個專家模型皆從同一個 Shared Backbone（共享骨幹網路）初始化，並分別針對對應能力家族的資料進行強化學習（Reinforcement Learning, RL）。具體演算法採用 **Token-Level GRPO Optimization（詞元級 GRPO 優化）**，即 Group Relative Policy Optimization（群組相對策略優化）在 token 層級的應用。相較於傳統的 PPO，GRPO 不需要額外的價值網路（value network），而是透過同一提示（prompt）下產生的多個回應（group of responses）之間的相對獎勵來估計優勢函數（advantage），這對於需要產生結構化輸出的視覺語言模型（Vision-Language Model, VLM）特別有利。

獎勵設計採用 **Verifiable Reward（可驗證獎勵）**，也就是獎勵函數可以自動檢驗預測結果的正確性，無需人工偏好標註。針對不同能力家族，獎勵設計（Capability-Specific Reward Design）會有所不同：

- 空間推理可能使用幾何距離或關係正確率。
- 時間理解可能使用事件順序正確性與時間定位誤差。
- 動作引導可能使用點選或軌跡與 ground truth 的距離。
- 狀態驗證則使用謂詞判斷正確率。

透過可驗證獎勵，專家模型可以在各自目標上進行穩定的策略優化。

**第二階段：Capability Consolidation（能力整合）**

將四個專家模型直接合併的挑戰在於參數間的優化干擾（optimization interference）。Capek 0.5 採用兩步驟整合策略：

1. **Weight-Space Merging（權重空間合併）**：使用 TIES [28] 方法對四個專家檢查點（checkpoint）進行合併，作為統一學生模型（unified student）的初始化。TIES 透過修剪（trimming）與選舉（electing）機制減少參數更新方向之間的衝突，從而保留各專家的重要更新。
2. **Routed MOPD（路由式 MOPD）**：在 TIES 初始化後，進一步執行 routed multi-teacher on-policy distillation（路由多教師同策略蒸餾）。此處的「路由（routed）」指的是根據輸入樣本所屬的能力家族，將學生模型產生的 prefix（前綴軌跡）導向對應的教師專家模型，進行策略空間蒸餾（Policy-Space Distillation）。由於蒸餾是在學生自己生成的 prefix 上進行，因此屬於 on-policy distillation，能夠緩解合併後模型在分佈外（out-of-distribution）行為上的退化。

最終產出的是單一檢查點（single checkpoint），在推論時無需根據能力切換模型，即可同時具備四種能力。

#### 實驗數據解讀

##### 三種互補的評估視角

Capek 0.5 的實驗設計從三個層次驗證模型：

1. **綜合基準測試（comprehensive benchmark suites）**：涵蓋一般視覺語言理解與具身推理能力，並包含作者新提出的 Capek-StateBench。
2. **受控的能力保留研究（controlled consolidation study）**：比較骨幹網路（backbone）、四個獨立專家、TIES 合併、MOPD-only、TIES+MOPD 等變體，量化整合過程中的能力損失（quantified loss）。
3. **閉環具身評估（closed-loop embodied evaluation）**：在模擬具身環境（simulated embodied environment）EmbodiedBench [23] 與 VIGIL [31] 中測試模型在動態執行過程中的能力組合。

##### 整體基準結果

作者實例化了兩個規模的模型：Capek 0.5-35B-A3B（基於 Qwen3.6-35B-A3B [29]）與 Capek 0.5-2B（基於 Qwen3.5-2B [30]），並與相同規模的基線模型進行比較。根據摘要與引言所述，Capek 0.5 在絕大多數可匹配的基準項目（matched benchmark row）上相較於初始化（initialization）有所提升。這表示：

- 後訓練（post-training）確實為基礎 VLM 注入了具身推理能力。
- 無論是在 2B 規模（2B scale）還是 35B-A3B 規模（35B-A3B scale），以執行為中心的能力分類法都能帶來一致的改進。
- 模型在一般視覺語言理解上並未因專注於具身能力而嚴重退化，顯示整合策略有效。

##### Capek-StateBench：狀態驗證的新基準

State Verification（狀態驗證）過去較少被獨立評估，Capek-StateBench 填補了這一缺口。該基準要求模型根據視覺證據判斷物理謂詞是否成立，例如「門是否打開」、「物體是否被握住」、「任務是否完成」等。由於狀態驗證直接關係到執行迴圈中的終止條件與錯誤偵測，將其獨立評估對於具身智能體至關重要。

##### 整合分析（Consolidation Analysis）

這部分是 Capek 0.5 方法論驗證的核心。實驗比較了以下變體：

- **Pretrained Backbone（預訓練骨幹網路）**：未經任何後訓練的 Qwen 模型。
- **Standalone Specialists（獨立專家模型）**：四個分別針對單一能力訓練的模型，代表各能力的上限。
- **TIES**：僅進行權重空間合併（Weight-Space Merging）的統一模型。
- **MOPD-only**：僅進行路由式 MOPD 蒸餾的統一模型。
- **TIES + MOPD**：Capek 0.5 的完整整合流程。

從摘要可知，最終的統一模型保留了全部四種專業能力，並且各能力的損失可以被量化。這意味著：

- TIES 提供了良好的初始化，但可能仍有能力間的干擾。
- MOPD 進一步修復了合併後的行為偏差，特別是在學生自己生成的軌跡分佈上。
- 完整流程（TIES + MOPD）在保留專家能力與維持單一模型便利性之間取得了最佳平衡。

##### 閉環具身智能體評估（Embodied Agent Evaluation）

在模擬環境中的評估使用了 EmbodiedBench [23] 與 VIGIL [31]。這類評估不同於靜態問答（Static QA），因為模型必須在動態環境中反覆做出決策，每個動作（action）都會改變場景與物理狀態（physical state），進而影響後續觀察與推理。

評估指標包括：

- **Trajectory Reward（軌跡獎勵）**：衡量整條執行軌跡完成任務的程度。
- **VABench-Trace Score（VABench-Trace 分數）**：用於評估軌跡品質的特定指標。

Capek 0.5 在這些閉環評估中展現出將空間推理（Spatial Reasoning）、時間理解（Temporal Understanding）、動作引導（Action Guidance）與狀態驗證（State Verification）組合運用的能力。這驗證了「以執行為中心」的設計不僅在孤立基準上有效，也能在動態任務執行中發揮作用。

#### 與現有研究的比較

##### 從任務導向到能力導向

現有許多具身視覺語言模型（embodied VLM）的後訓練流程是圍繞個別資料集或任務特定目標（task-specific objective）設計的，例如專門訓練導航、抓取或問答。Capek 0.5 的貢獻在於將訓練組織單位從「任務」轉移到「能力」，並明確指出這些能力在執行迴圈中的功能角色。這使得模型的能力獲取與評估更具系統性，也更容易診斷模型在實際執行中的弱點。

##### 分離能力獲取與能力整合

過去有些研究嘗試直接將多種具身任務混合進行多工學習（multi-task learning），但由於監督訊號（supervision signal）、預測格式（prediction format）與驗證標準（verification criterion）的異質性，容易產生優化干擾。Capek 0.5 透過「先訓練專家、再合併蒸餾」的兩階段方法，明確分離了能力獲取與能力整合。這與模型融合（model merging）與知識蒸餾（knowledge distillation）領域的最新進展相呼應，但將其應用於具身智能的異質能力整合上。

##### 與 TIES 及 MOPD 的關係

TIES [28] 原本是用於合併多個微調模型的方法，Capek 0.5 將其作為統一學生模型的權重空間初始化（Weight-Space Initialization）。MOPD [26] 則提供了多教師策略蒸餾的框架，Capek 0.5 進一步提出 routed MOPD，根據能力家族進行路由，使蒸餾過程更具針對性。這種「合佷初始化 + 路由蒸餾」的組合，相較於單純的模型平均或單一教師蒸餾，更能保留專家模型的專業行為。

##### 狀態驗證的獨立重視

State Verification（狀態驗證）在許多機器人系統中常被隱含在任務成功判斷中，較少作為獨立能力被訓練與評估。Capek 0.5 將其提升為四大能力家族之一，並推出 Capek-StateBench，這對於發展能夠自我監控執行進度與偵測失敗的具身智能體具有重要意義。

##### 限制與不足

儘管 Capek 0.5 在方法論上具有創新性，仍存在一些限制：

1. **僅在模擬環境中驗證**：目前閉環評估僅限於模擬具身環境（simulated embodied environment），尚未展示真實機器人（real robot）上的部署結果。
2. **能力分類法的覆蓋範圍**：四大能力家族雖然涵蓋了常見的視覺推理需求，但對於力觸覺推理（force/tactile reasoning）、社交互動、長期規劃（long-horizon planning）或錯誤恢復（error recovery）等能力的涵蓋有限。
3. **獎勵設計的工程成本**：雖然使用可驗證獎勵（verifiable reward）減少了人工標註需求，但每個能力家族仍需設計專屬的獎勵函數，這在擴展到新能力時仍需大量工程。
4. **模型規模**：目前僅驗證了 2B 與 35B-A3B 兩個規模，對於更大規模模型的行為與擴展性（scalability）仍需進一步研究。

#### 可重現性評估

從提供的上下文來看，論文並未明確說明是否公開原始碼（source code）、訓練資料集（training dataset）或模型權重（model weights）。雖然附錄中提供了 Evaluation Prompts（評估提示詞）、Capek-StateBench Protocol（Capek-StateBench 協議）、Trajectory Reward 與 VABench-Trace Score 的詳細定義，以及 Qualitative Rollouts（定性執行軌跡）等補充材料，但這些主要屬於實驗細節與案例展示，並不等同於完整的開源釋出。

若要達成高可重現性（reproducibility），以下資訊至關重要：

- **訓練資料**：四大能力家族各自的資料來源、篩選標準、標準化格式與資料量。
- **獎勵函數實作**：每個 Capability-Specific Reward Design 的具體程式碼與超參數。
- **GRPO 訓練設定**：群組大小（group size）、學習率（learning rate）、KL 懲罰係數、訓練步數等。
- **TIES 與 MOPD 實作**：合併比例、路由規則、蒸餾溫度與損失函數。
- **模型權重**：至少釋出最終的統一模型檢查點（single checkpoint），以便社群進行驗證與比較。

在缺乏上述開源資訊的情況下，其他研究者雖可根據論文描述復現方法概念，但難以完全重現報告中的數值結果。建議作者未來提供完整的開源套件，包括程式碼、資料處理流程與預訓練權重，以提升研究的可重現性與影響力。

#### 未來研究方向

##### 擴展能力分類法

目前的四大能力家族主要聚焦於視覺與語言推理。未來可進一步納入：

- **力觸覺推理（force/tactile reasoning）**：處理接觸力、摩擦力、物體材質等物理資訊。
- **社交與意圖推理（social/intent reasoning）**：在人機協作或人類環境中理解他人意圖。
- **錯誤恢復與異常檢測（error recovery & anomaly detection）**：在執行失敗時能夠診斷原因並重新規劃。

##### 真實世界部署與模擬到真實遷移

Capek 0.5 目前僅在模擬環境中進行閉環評估。未來研究可探索：

- **Sim-to-Real Transfer（模擬到真實遷移）**：將 Capek 0.5 部署到真實機器人平台，並研究領域差距（domain gap）對各能力的影響。
- **線上適應（online adaptation）**：在真實執行過程中根據回饋持續更新模型行為，而非僅使用離線後訓練。

##### 自動化獎勵與資料生成

雖然可驗證獎勵減少了人工標註，但設計過程仍具挑戰。未來可研究：

- **自動化獎勵塑造（automated reward shaping）**：利用大型模型或環境模擬器自動生成獎勵函數。
- **合成資料生成（synthetic data generation）**：透過模擬器大規模生成涵蓋四種能力的訓練資料，降低對真實標註的依賴。

##### 更大規模與多模態動作輸出

目前 Capek 0.5 輸出影像空間的點、區域與軌跡，但未直接輸出低階控制指令（low-level control command）。未來可探索：

- **端到端動作生成（end-to-end action generation）**：將 VLM 與動作策略模型（action policy model）更緊密結合，直接輸出關節角度或夾爪指令。
- **更大規模模型的擴展性研究**：驗證在 70B 或更大規模下，能力保留與整合是否仍然有效。

##### 理論理解能力整合

TIES 與 MOPD 在實證上有效，但對於為何特定合併與蒸餾策略能夠保留異質能力的理論理解仍有限。未來可從以下方向深入研究：

- **參數空間中能力表示的幾何結構**：分析不同能力在權重空間中的正交性或可線性組合性。
- **蒸餾過程中的知識流動**：量化各專家知識在 MOPD 過程中如何轉移到統一模型，以及哪些能力最容易在整合中流失。

這些方向不僅能強化 Capek 0.5 的實用性，也能為具身視覺語言模型（embodied VLM）的設計提供更堅實的理論基礎。

## 論文問答

**Q1：Capek 0.5 主要想解決什麼問題？**

A：Capek 0.5 旨在解決具身智能體在真實執行過程中，視覺語言模型（VLM）必須持續處理動態變化的場景與物理狀態的挑戰。傳統的 VLM 雖然具備強大的感知與語言先驗，但機器人執行本質上是反覆迭代的：每個動作都會改變環境，並不斷產生新的觀察證據供後續決策使用。因此，模型需要同時具備空間推理、時間理解、動作引導與狀態驗證等互補能力，而這些能力在監督訊號、輸出格式與驗證標準上差異極大，現有方法難以有效整合。

**Q2：現有方法為何難以滿足機器人執行的需求？**

A：現有方法通常以個別任務、資料集或基準為目標進行後訓練，導致不同能力被孤立地開發與優化。即使將多種監督訊號混合到單一模型中，由於輸出結構與評分規則高度異質，模型容易出現優化干擾，難以判斷哪些執行能力真正被學到、整合後是否仍然保留。此外，機器人執行需要可解釋且可驗證的中間預測，但任務特定目標往往無法提供這種以執行為中心的系統性組織。

**Q3：為什麼「以執行為中心的能力分類法」很重要？**

A：這個分類法將具身能力按照其在機器人執行過程中的功能角色進行組織，而非僅依資料集或任務劃分，從而提供一個統一的訓練與評估框架。它明確區分出空間推理、時間理解、動作引導與狀態驗證四大能力家族，幫助研究者理解這些能力如何在感知—推理—動作循環中反覆出現與協作。透過這種結構化視角，Capek 0.5 能夠針對每種能力設計專屬的監督訊號與驗證機制，並最終將它們整合到單一推論模型中。

**Q4：Capek 0.5 的核心方法是什麼？**

A：Capek 0.5 採用「專家到統一的後訓練」流程，將能力獲取與能力整合分開處理。首先，從共享骨幹網路出發，針對四大能力家族分別訓練專用專家模型，每個專家透過強化學習與可驗證獎勵進行詞元級 GRPO 優化。接著，利用 TIES 權重空間合併將各專家整合為單一初始模型，再透過路由式多策略蒸餾（Routed MOPD）進一步鞏固，最終得到一個能同時具備四種能力的統一檢查點。

**Q5：Capek 0.5 的關鍵創新在哪裡？**

A：其關鍵創新在於提出以執行為中心的能力分類法，並據此設計出可擴展的專家整合架構。不同於傳統以任務或資料集為導向的訓練，Capek 0.5 讓每種能力都有明確的功能定位、專屬獎勵設計與標準化輸出介面，從根本上解決異質目標之間的優化衝突。此外，透過權重空間合併結合路由策略空間蒸餾，模型在保留各專家能力的同時，仍能作為單一模型進行推論，實現能力保留與部署簡化的平衡。

**Q6：方法設計上有哪些重要選擇？**

A：首先，作者選擇將能力獲取與整合分離，避免直接在單一模型上進行多目標聯合優化所導致的干擾。其次，採用詞元級 GRPO 與針對能力的獎勵設計，讓每個專家能根據可驗證的回饋進行細粒度學習。最後，在整合階段先以 TIES 合併權重作為初始化，再輔以 Routed MOPD 在學生模型生成的字首上進行知識蒸餾，這種兩階段設計有助於量化並降低能力整合過程中的性能損失。

**Q7：實驗使用了哪些評估方式與基準？**

A：論文從三個互補視角進行評估：首先是全面的基準測試套件，涵蓋一般視覺語言理解、空間推理、時間理解、動作引導與狀態推理，並包含新提出的 Capek-StateBench 用於狀態驗證。其次是受控的整合分析，比較預訓練骨幹、四個獨立專家，以及 TIES、MOPD-only 與 TIES+MOPD 等變體，以量化能力保留程度。最後是閉環具身智能體評估，在 EmbodiedBench 與 VIGIL 等模擬具身環境中測試模型在動態任務執行中的能力組合表現。

**Q8：Capek 0.5 取得了哪些關鍵實驗結果？**

A：在大多數可匹配的基準項目上，Capek 0.5 相較於其初始化模型都有明顯提升，顯示後訓練流程能有效增強具身推理能力。整合分析顯示，統一模型能夠在單一檢查點中保留全部四種專家能力，並且可以量化每種能力在整合過程中的損失。此外，在模擬具身環境中的閉環評估也證明，這些多樣化的推理能力能夠在實際任務執行過程中有效組合與遷移。

**Q9：消融實驗揭示了什麼？**

A：消融實驗比較了僅使用 TIES 合併、僅使用 MOPD 蒸餾，以及兩者結合的完整流程，結果顯示 TIES+MOPD 在能力保留上表現最佳。這說明單純的權重空間合併雖然能快速獲得綜合能力，但不足以完全消除專家之間的衝突與遺忘；而加入路由策略空間蒸餾後，模型能在學生生成的資料上進一步對齊各能力的策略分佈。這樣的兩階段整合機制為未來設計多能力統一模型提供了可量化的設計依據。

**Q10：Capek 0.5 可應用於哪些實際場景？**

A：Capek 0.5 可應用於家庭服務機器人、倉儲物流自動化、輔助醫療照護與工業組裝等需要持續感知與決策的場景。例如，在家庭環境中，機器人需要判斷物品位置、理解事件順序、規劃抓取軌跡，並驗證任務是否完成，這些正好對應四大能力家族。由於模型能將多種能力整合於單一檢查點，部署時無需切換多個專家模型，有助於降低系統複雜度與推論延遲。

**Q11：在產品化與部署上需要考慮什麼？**

A：產品化時需考慮模型規模與推論成本的權衡，論文提供了 2B 與 35B-A3B 兩種規模，後者雖然能力更強但啟動參數與運算需求更高。此外，統一輸出介面的標準化有助於與下游機器人控制模組對接，但仍需針對真實硬體的感測器延遲、動作執行誤差與安全機制進行額外設計。最後，由於狀態驗證與動作引導直接影響物理安全，產品部署時應加入人機協作與異常處理機制，避免模型在開放環境中做出高風險決策。

**Q12：Capek 0.5 對具身智能領域可能帶來什麼影響？**

A：Capek 0.5 提出了一種以執行為中心的能力組織與整合典範，可能促使未來研究從「任務導向」轉向「能力導向」的模型開發。透過明確定義與量化四種核心能力，研究者可以更有系統地診斷模型在機器人執行中的弱點，並針對性地設計資料與訓練流程。此外，其專家到統一的後訓練方法也為如何在不犧牲能力保留的前提下實現單一模型部署，提供了可複製的技術路徑。

**Q13：論文承認了哪些限制？**

A：雖然 Capek 0.5 在模擬環境中展現了良好的閉環執行能力，但論文主要聚焦於模擬具身環境，尚未在真實機器人平台上進行大規模驗證。此外，能力分類法雖然涵蓋了執行過程中的核心需求，但可能尚未窮盡所有具身能力，例如多模態觸覺感知、社交互動與長期記憶管理等。最後，整合過程中仍存在可量化的能力損失，如何進一步降低這些損失並維持模型規模效率，仍是未解決的問題。

**Q14：模型在哪些情況下可能失敗？**

A：根據附錄中的靜態問答失敗案例，模型可能在視覺線索模糊、物理狀態變化細微或語言指令具有歧義時出錯。例如，當多個相似物件同時出現，或狀態變化僅涉及小部分像素時，狀態驗證能力可能無法正確判斷物理謂詞是否成立。此外，在長時間執行軌跡中，若早期預測出現偏差，錯誤可能隨著時間累積，導致後續動作引導與驗證連鎖失敗。

**Q15：未來可以朝哪些方向發展？**

A：未來可以將 Capek 0.5 的能力分類法擴展到更多感知模態，例如觸覺、聽覺與本體感覺，以支援更豐富的物理互動。另一個方向是將模型從模擬環境遷移到真實機器人平台，並結合線上適應與人類回饋機制，持續提升在開放世界中的穩健性。此外，進一步研究如何減少能力整合過程中的量化損失、發展更細緻的路由策略蒸餾方法，以及將長期記憶與規劃能力納入執行-centric 框架，都是值得探索的後續課題。

## 適用場景

1. **家用服務機器人的長期任務執行**  
   例如讓機器人完成「把報紙和木柴放進壁爐、點火、關閉打火機」這類多步驟家務。Capek 0.5 的四大能力家族可在每次動作後重新評估空間關係、事件順序、可操作目標與完成狀態，適合需要反覆觀察—推理—行動的動態環境。

2. **倉儲與物流機器人的揀放與巡檢**  
   在貨架間移動時，機器人需要持續判斷物品是否已被移動、箱子是否已開啟、托盤是否已對齊。狀態驗證與空間推理能力可用來確認每個揀放任務的中間狀態，降低錯誤堆疊。

3. **輔助機器人的視覺引導與安全確認**  
   例如協助行動不便者拿取水杯後，判斷「水是否已倒入杯中」「杯蓋是否蓋緊」「使用者是否已握住杯子」。動作引導提供圖像空間中的操作點與軌跡，狀態驗證則確認物理謂詞是否成立。

4. **工業裝配線的步驟追蹤與品質檢查**  
   在組裝過程中，模型可依序驗證零件是否已對齊、螺絲是否已鎖緊、蓋子是否已關閉。時間理解能力可定位關鍵事件發生時刻，並與標準作業程序比對。

5. **視覺語言導航與場景問答系統**  
   適用於室內機器人導航或 AR 眼鏡，使用者可用自然語言詢問「我剛才經過的紅色門還開著嗎？」模型結合時間理解與狀態驗證，回答跨時間的視覺問題。

## 實作前置條件

### 資料
- **多模態訓練資料**：需要涵蓋空間推理、時間理解、動作引導、狀態驗證四類的圖像—文字配對資料，並統一為 Capek 0.5 的統一輸出介面格式。
- **可驗證標註**：每個樣本需有能自動檢查正確性的標準答案，例如邊界框座標、軌跡點、事件時間戳、物理狀態標籤，以便設計可驗證獎勵。
- **領域資料（可選）**：若部署於特定場景，建議補充該場景的影片或圖像序列，例如家庭影片、倉儲監控片段、工業裝配流程。

### 運算
- **基礎推論**：2B 規模模型可在單張消費級 GPU 上運行；35B-A3B 規模模型需要多卡或高階 GPU 叢集。
- **專家模型訓練**：每個專家模型需使用強化學習進行後訓練，建議準備數張 A100/H100 等級 GPU，並支援詞元級 GRPO 優化。
- **整合階段**：權重空間合併與路由式 MOPD 蒸餾需要額外運算資源，但通常低於從頭訓練四個專家模型的總和。

### 技能
- **熟悉視覺語言模型與強化學習**：需理解 GRPO、獎勵設計、知識蒸餾與模型合併。
- **機器人系統整合能力**：需能將模型輸出轉換為機器人控制訊號，例如將圖像空間點或軌跡對應到末端執行器座標。
- **資料工程與評估能力**：需能建構或改寫基準資料，並設計對應的驗證標準與軌跡獎勵。

## 實作步驟建議

1. **定義執行場景與能力需求**  
   先釐清目標任務中哪些步驟需要空間推理、時間理解、動作引導或狀態驗證。以任務拆解為基礎，決定需要強化的能力家族。

2. **選擇骨幹網路規模**  
   依據延遲與精度需求選擇 2B 或 35B-A3B 規模。若為邊緣裝置或即時反應，優先考慮 2B；若任務複雜且可接受較高延遲，則選 35B-A3B。

3. **建構面向能力的資料集**  
   按照四大能力家族分別收集與標註資料，並進行資料標準化，使所有樣本共享相同的輸入輸出格式。可參考 Capek-StateBench 設計狀態驗證題目。

4. **訓練四個專家模型**  
   從同一個共享骨幹網路出發，針對每個能力家族使用詞元級 GRPO 優化與針對能力的獎勵設計，訓練出專用專家模型。

5. **合併與整合為單一檢查點**  
   先以權重空間合併產生統一學生模型的初始權重，再透過路由式 MOPD 在學生模型自身生成的軌跡上進行策略空間蒸餾，得到最終的單一檢查點。

6. **進行整合分析與能力保留評估**  
   比較骨幹網路、四個專家模型、TIES 初始化、MOPD-only 與 TIES+MOPD 的表現，量化每個能力在統一模型中的保留程度與量化損失。

7. **部署到模擬環境進行閉環評估**  
   在 EmbodiedBench、VIGIL 或自建的模擬具身環境中執行完整任務，觀察模型在動態執行過程中的能力組合表現，並以軌跡獎勵或 VABench-Trace 分數評估。

8. **轉移到真實機器人平台**  
   將模型輸出的圖像空間點、區域或軌跡對應到機器人控制介面，並設置狀態驗證模組作為每步動作後的檢查點，形成觀察—推理—行動—驗證的閉環。

## 潛在風險與注意事項

| 風險 | 說明 | 建議對策 |
|---|---|---|
| **能力干擾** | 四種能力監督訊號與預測格式差異大，直接混合訓練可能導致優化衝突。 | 採用專家到統一的後訓練流程：先獨立訓練專家模型，再透過權重空間合併與路由式 MOPD 整合。 |
| **狀態驗證誤判** | 物理謂詞的視覺判斷容易受光照、遮擋或視角影響。 | 結合多視角觀察與時序資訊，並在關鍵狀態設計保守的確認機制。 |
| **獎勵設計偏差** | 可驗證獎勵若過於簡化，可能鼓勵模型學到捷徑行為。 | 獎勵函數應同時涵蓋格式正確性、語義正確性與任務層級目標，並在模擬環境中驗證。 |
| **從模擬到真實的落差** | 模擬環境中的軌跡獎勵可能無法完全反映真實物理與感知雜訊。 | 部署前進行領域適應，收集真實場景資料微調，並保留人類介入或安全停機機制。 |
| **單一檢查點的維護成本** | 統一模型更新時，可能影響多項能力。 | 建立分能力回歸測試，每次更新後在 Capek-StateBench 等基準上驗證四項能力的保留程度。 |

## 與其他技術的整合建議

- **與機器人作業系統整合**：可將 Capek 0.5 作為感知推理節點，透過 ROS2 接收相機影像與語言指令，輸出圖像空間目標點或區域給運動規劃模組。
- **與低階控制器搭配**：動作引導輸出的是高階視覺提示，需進一步結合軌跡規劃器、逆運動學與抓取規劃器，才能轉換為關節指令。
- **與記憶與規劃模組整合**：將狀態驗證結果寫入符號化或向量化的世界記憶，供任務規劃器判斷下一步該執行哪個子目標。
- **與多模態感測器融合**：除了 RGB 影像，可引入深度相機、觸覺感測器或本體感覺資訊，彌補純視覺在狀態驗證上的不足。
- **與大型語言模型協作**：Capek 0.5 負責視覺 grounded 的推理與驗證，LLM 則負責高層次語義規劃與自然語言介面，兩者透過結構化 API 溝通。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從「執行-centric 能力分類法」與圖 2 的觀察—推理—行動循環開始，理解為什麼機器人需要同時具備空間、時間、動作與狀態四種能力。技術細節如 GRPO 與 MOPD 可先略讀，重點放在每個能力家族對應的實際例子上。

**AI 工程師**：請聚焦第 3、4 章的資料建構與後訓練流程，特別是專家模型訓練、權重空間合併與路由式 MOPD 的實作細節。建議對照附錄中的訓練與評估細節，思考如何將相同流程遷移到自身場景的資料格式與獎勵設計。

**研究人員**：論文核心貢獻在於將執行視角的能力分類法與專家到統一的訓練架構結合。建議深入分析整合分析章節，探討能力保留、優化干擾與模型合併之間的關係，並可延伸研究如何將更多能力家族納入同一框架。

**產品經理**：請將重點放在適用場景、整體基準結果與閉環評估。理解 Capek 0.5 能解決哪些真實任務、需要什麼資料與運算成本、以及從模擬到真實部署的風險，有助於評估產品化時程與資源配置。
