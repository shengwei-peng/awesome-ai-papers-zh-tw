# 自我評估遞迴代理（Self-Evaluating Recursive Agents）

## ⚡ TL;DR

遞迴語言模型代理難以訓練，因子任務缺乏標準答案，外部驗證器訊號粗粒度且昂貴。
本文提出SERA，讓策略在委派前生成加權評分量表，並以排序目標與葉節點覆蓋訊號聯合訓練。
TextCraft與TextWorld基準上分別領先5.38與13.14分，樹搜尋再添2.43分。

## 摘要翻譯

遞迴語言模型代理（recursive language-model agents）會分解任務，並將子任務（subtasks）委派給同一策略（same policy）的子實例（child instances），從而形成一棵工作樹（tree of work）。然而，訓練它們並不容易：最終結果雖可驗證，但自我發明的中間子任務（self-invented intermediate subtasks）為數眾多且沒有標準答案（ground truth）。現有方法使用驗證器（verifier）或 LLM 評判器（LLM judge）對每個節點評分，這在大規模下成本高昂，且無法察覺分解品質（decomposition quality）。我們主張遞迴代理必須在單一組權重（single set of weights）內學會三種耦合能力（coupled capabilities）：將問題分解為子任務、求解子任務，以及評估結果，每種能力都需要各自的訓練訊號（training signal）。SERA（自我評估遞迴代理，Self-Evaluating Recursive Agents）將評估轉化為策略（policy）本身的一項可學習能力。在委派之前，父代理（parent agent）會為每個子任務撰寫一份包含加權成功標準（weighted success criteria）的評分量表（rubric）；接著，透過對照已驗證結果的排序目標函數（ranking objective）來訓練評分量表生成（rubric generation），使這些標準能夠反映真實的子任務成功與否。此外，一個互補的葉節點覆蓋訊號（leaf-coverage signal）為任務分解（decomposition）提供直接的局部化信譽分配（localised credit assignment）。我們的核心發現是：驅動效能提升的關鍵，在於訓練策略生成對齊的評分量表；由於同一組權重（shared weights）同時負責評估與執行，學會評判子任務能夠強化代理求解子任務的能力。值得注意的是，外部監督（external supervision）也因此減少：評判器僅在訓練評分量表生成器（rubric generator）時被使用，而求解則是針對代理自身的評分量表分數進行訓練，後者的表現優於直接使用評判器。除了訓練之外，學到的評分量表還可兼作推理時的樹搜尋（tree search）選擇器（inference-time selector）。在 TextCraft-Synth 與 TextWorld-Sync 上，SERA 平均分別比強遞迴代理基準方法（strong recursive-agent baselines）高出 5.38 與 13.14 分，而推理時的評分量表引導樹搜尋（rubric-guided tree search）在 TextWorld-Sync 上再額外提升 2.43 分。

### 核心貢獻（3～5點）
- **統一三種耦合能力的學習框架**：主張遞迴代理必須在單一組共享權重內同時學會任務分解、子任務求解與結果評估三種能力，並為各能力設計對應的訓練訊號。
- **將評估內化為可學習能力**：提出 SERA 方法，讓父代理在委派前為每個子任務撰寫加權成功標準的評分量表，並以排序目標函數對照已驗證結果進行訓練，使評分量表生成成為策略本身的一部分。
- **引入葉節點覆蓋訊號**：為任務分解提供直接的局部化信譽分配，補充評分量表訓練訊號，解決自我發明子任務缺乏標準答案的難題。
- **減少外部監督依賴**：評判器僅用於訓練評分量表生成器，子任務求解則改以代理自身的評分量表分數作為訓練訊號，且後者表現優於直接使用評判器。
- **評分量表兼作推理時選擇器**：學到的評分量表在推理階段可引導樹搜尋挑選最佳子樹，在 TextWorld-Sync 上額外帶來 2.43 分的提升。

### 適合對象
從事大型語言模型代理（LLM agents）、強化學習中信譽分配（credit assignment）、測試階段擴展（test-time scaling）以及自動化任務分解研究的學者與工程師；特別是正在建構遞迴式或階層式代理系統、關注如何以單一策略同時處理分解、求解與自我評估的研究團隊。此外，對前沿程式設計代理（frontier coding agents）與研究代理（research agents）設計有興趣的業界實務者也將從中獲益。

## 深度分析

#### 方法論解析

SERA（Self-Evaluating Recursive Agents，自我評估遞迴代理）的核心洞見在於：遞迴代理（recursive agents）並非執行單一任務，而是在**單一組共享權重（shared weights）**中同時承擔三種耦合能力（coupled capabilities）——**任務分解（decomposition）**、**子任務求解（solving）**、以及**子任務評估（evaluation）**。三者必須各自擁有獨立的訓練訊號（training signal），否則會在共享參數上互相干擾。

**1. 評分量表（Rubric）作為自我評估機制**

傳統方法仰賴驗證器（verifier）或 LLM 評判器（LLM judge）對每個節點打分，但這種**逐節點訊號（per-node signal）**存在三項缺陷：粗粒度（僅二元成功／失敗）、成本高昂（每個節點皆需呼叫外部模型）、且對分解品質（decomposition quality）保持沉默。SERA 的解法是讓父代理（parent agent）在**委派子任務之前**先撰寫一份**加權成功標準（weighted success criteria）**——即一份以自然語言（natural-language criteria）描述的評分量表，內含多項條件與對應權重。關鍵設計在於「先寫、後跑」：評分量表必須在子代理執行前完成，因此無法事後擬合（fit）子代理的軌跡，從而避免評估者偏誤（evaluator bias）。

**2. 排序目標函數（Ranking Objective）訓練評分量表生成**

若直接以任務獎勵訓練評分量表生成（rubric generation），會引發**共同適應（co-adaptation）**問題——因為評分量表生成與子任務求解共用同一組權重，獎勵評分量表等於獎勵「容易被打高分的子任務」，導致評分量表分數虛胖但實際能力未提升。SERA 的解法是引入**排序目標函數**：對同一子任務採樣多個 rollout（rollout 1 成功、rollout 2 失敗），訓練評分量表生成器（rubric generator）使成功軌跡的評分量表分數高於失敗軌跡。外部評判器僅在此階段用於提供 verified outcome，從未直接作為節點獎勵——這大幅降低了**外部監督（external supervision）**的依賴。

**3. 葉節點覆蓋訊號（Leaf-Coverage Signal）獎勵分解品質**

對於分解能力，SERA 設計了**葉節點覆蓋訊號**：在已成功解決的樹中，父代理的委派動作依其子樹所涵蓋的葉節點工作比例獲得獎勵（reward = 任務成功 × 葉節點覆蓋率）。一個承擔大量、結構清晰工作的委派獲得高分；瑣碎的轉手獲得近零分；失敗樹中的委派獲得零分。此訊號獎勵代理「用委派來承擔結構性負擔」，這是任何執行訊號都無法捕捉的。該訊號在淺層、近獨立子任務上增益有限，但在子任務相互依賴（dependency chains、共享狀態、需協調）的場景中效果顯著。

**4. 三階段交替訓練（Alternating Training Stages）**

如 Figure 1 所示，SERA 採用三階段交替優化：
- **Stage 1（執行）**：以根節點任務成功（0/1）與非根節點的評分量表分數（連續值 [0,1]）作為獎勵，訓練求解能力。
- **Stage 2（委派）**：以任務成功 × 葉節點覆蓋率作為獎勵，專門訓練分解動作。
- **Stage 3（評分量表生成）**：以排序目標函數訓練評分量表生成，外部評判器僅在此階段介入。

此設計使三種能力在共享權重中各得其所，避免互相干擾。

**5. 推理時的評分量表引導樹搜尋（Rubric-Guided Tree Search）**

由於評分量表已學會對齊真實子任務品質，它在推理階段可作為**推理時選擇器（inference-time selector）**重複使用：採深度優先搜尋（depth-first search）展開樹，於每個分支依評分量表分數選擇最佳候選解，並將最佳結果向上傳播。這構成遞迴代理在測試階段擴展（test-time scaling）上的新軸度，與思維鏈（chains of thought）長度增加和更寬的取樣（wider sampling）並列。

#### 實驗數據解讀

**主要效能提升**

- 在 **TextCraft-Synth** 上，SERA 平均超越強遞迴代理基準（strong recursive-agent baselines）**5.38 點**。
- 在 **TextWorld-Sync** 上，平均提升達 **13.14 點**——後者增幅顯著更大，暗示 SERA 在子任務高度相互依賴、需要協調的環境中受益更明顯。
- 評分量表引導樹搜尋在 TextWorld-Sync 上額外帶來 **2.43 點**提升，證明學到的評估能力可作為推理時資產重複利用。

**關鍵消融與對比發現**

- **「訓練評分量表生成才是效能提升的關鍵」**：論文的中心發現是，學習評分量表生成（而非僅使用評分量表）才是驅動執行能力提升的主因。這印證了「**因為同一組權重既評估又執行，學習評判子任務會反過來銳化代理求解它們的能力**」的核心論點。
- **評分量表分數優於直接使用評判器**：以代理自身的評分量表分數作為訓練訊號，效果優於直接以 LLM judge 的評分作為獎勵。這是一個反直覺但重要的結果——外部評判器雖然更「客觀」，但作為訓練訊號時反而不如學到的內部評估有用，可能因為評分量表分數與策略的探索分布更對齊。
- **葉節點覆蓋訊號的邊際效應**：在淺層、近獨立子任務上增益有限，但在子任務相互依賴的任務中提供實質增益。這與設計直覺一致——當子任務可獨立解決時，分解策略的影響較小；當子任務需協調時，好的分解成為瓶頸。

**指標解讀的注意事項**

- 兩個基準（TextCraft-Synth、TextWorld-Sync）皆為文字遊戲類環境，屬於合成任務（synthetic tasks）。雖然能嚴格控制子任務依賴結構，但與真實世界的多跳研究（multi-hop research）或程式碼任務在開放性、長視野（long-horizon）特性上仍有差距。
- 報告的「平均分數」未明確說明是跨任務平均還是跨模型規模平均，需查閱附錄確認統計顯著性與變異數。

#### 與現有研究的比較

**定位**

SERA 屬於「**訓練遞迴代理本身**」這一新興研究方向，與「**將遞迴視為凍結模型的外殼**」的傳統做法形成對比。論文的相關工作分為三類：

1. **固定外殼方法**（Prasad et al., 2024; Schroeder et al., 2025）：將遞迴視為圍繞凍結模型的固定支架（scaffold），不訓練代理本身的委派行為。
2. **淺層委派訓練**（Team et al., 2026b; Sun et al., 2025; Chi et al., 2025）：以強化學習訓練平行委派，或聯合訓練 organizer–worker 系統，但通常限制在深度 1，且 worker 為固定或受限。
3. **RAO（Recursive Agent Optimization, Gandhi et al., 2026）**：最接近的競爭者，同樣訓練遞迴代理，但使用**二元逐節點訊號**作為獎勵。

**SERA 的相對優勢**

- **相對於 RAO**：RAO 的二元訊號無法區分「乾淨解」與「勉強合格解」，也無法標記成功樹中的弱節點；SERA 的連續評分量表分數（continuous score）解決了這個粗粒度問題。
- **相對於平行委派 RL**：SERA 支援任意深度的遞迴，且證明在淺層遞迴訓練可在推理時泛化到更深樹（composes across depth），這是平行委派方法未觸及的維度。
- **相對於 organizer–worker 系統**：SERA 的所有節點共用同一策略（same policy），無需訓練兩個獨立模型，參數效率更高，且統一了分解、求解、評估三種能力。

**限制與未涵蓋面向**

- **仍需外部監督**：雖然比直接以 judge 獎勵節點更輕，但評分量表生成階段仍需 verified outcome。在完全無外部監督的環境中（如開放式寫作），該方法需配合其他機制。
- **評估環境的範圍**：實驗集中於文字遊戲類基準，未在程式碼、研究代理等前沿應用（frontier coding and research agents）上驗證。雖然論文聲稱其設計動機來自這些應用，但實際驗證仍待補充。
- **評分量表的語言依賴**：評分量表以自然語言撰寫，其品質受基礎模型的語言能力限制。對於極複雜或極專業的子任務，評分量表可能過於粗糙。
- **三階段交替訓練的複雜度**：相較於端到端強化學習，三階段設計增加了工程複雜度與超參數敏感度。

#### 未來研究方向

**1. 理論層面：為何「學習評判」能「銳化求解」？**

論文以實驗觀察支持「共享權重下學習評估會反過來改善執行」，但缺乏理論解釋。未來可從以下角度切入：
- **表徵學習視角**：評分量表生成迫使策略在內部形成對「子任務成功」的隱式表徵，這種表徵可能與求解所需的表徵共享，從而產生正向遷移。
- **資訊理論視角**：可分析評分量表生成引入的互資訊（mutual information）下界，量化其對策略熵的影響。
- **損失景觀分析**：比較「有評分量表訓練」與「無評分量表訓練」下求解損失的曲率與最小值。

**2. 應用擴展：從文字遊戲到真實世界任務**

- **程式碼任務**：在 repository-scale code changes 中驗證 SERA，其中子任務依賴性極強（imports、types、tests）。
- **多跳研究問題**：在需要跨多文檔檢索與綜合的研究任務中測試，評估量表是否能捕捉「證據完整性」與「推理連貫性」。
- **長視野決策**：在需跨數百步操作的環境中驗證遞迴深度的泛化能力。

**3. 評分量表結構的演進**

- **階層式評分量表**：當前評分量表為扁平列表，可擴展為樹狀結構以對應遞迴樹本身。
- **多模態評分量表**：在視覺或多模態任務中，評分量表需涵蓋非語言維度（如空間正確性）。
- **動態評分量表**：允許評分量表在子代理執行過程中根據中間狀態調整，而非僅在執行前固定。

**4. 降低外部監督的極限**

- **自監督評分量表訓練**：探索是否可從任務本身的結構（如子任務間的因果依賴）推導出 verified outcome，進一步減少對外部 judge 的依賴。
- **跨任務遷移**：在一個任務上訓練的評分量表生成器能否遷移到新任務，作為零樣本評估器。

**5. 與其他測試階段擴展軸的組合**

- **評分量表 + 思維鏈**：評分量表不僅評估最終輸出，也可評估中間推理步驟，引導更長的思維鏈。
- **評分量表 + 更寬取樣**：在每個節點採樣多個候選解，以評分量表選擇最佳，與 self-consistency 等方法結合。
- **元學習評分量表**：學習「如何為新任務快速生成有效評分量表」，使 SERA 能適應任務分布的變化。

**6. 安全與可解釋性**

- 評分量表本身是人類可讀的自然語言標準，這為遞迴代理的決策提供了**可解釋性窗口**。未來可探索如何利用評分量表進行失敗分析、除錯與對齊審計——這對前沿代理（frontier agents）的部署安全至關重要。

## 論文問答

**Q1：為什麼訓練遞迴代理（recursive agents）本質上比訓練單次通過的代理更困難？**
A：單次通過的代理只需在單一決策點上產生輸出，而遞迴代理會將任務展開成一棵工作樹，每個節點都是同一策略的新實體例（fresh instance），因此訓練訊號必須沿著樹結構傳遞。更關鍵的困難在於：最終結果通常可驗證，但代理自行發明的子任務（self-invented subtasks）幾乎沒有標準答案（ground truth），使得傳統的監督式學習無法直接套用。這導致了嚴重的信譽分配（credit assignment）問題——根節點的獎勵（root reward）難以歸因到具體哪個子任務或哪段推理出了問題。

**Q2：現有方法在每個節點使用驗證器（verifier）或 LLM 評判器（LLM judge）時，存在哪些根本性的限制？**
A：第一個限制是訊號過於粗糙（coarse），二元式的逐節點訊號（binary per-node signal）無法區分一個乾淨的解答與勉強及格的解答，也無法標記出在最終成功的樹中品質較弱的節點。第二個限制是成本昂貴，要在樹中每個節點都呼叫可靠的驗證器或評判器，會隨樹的規模迅速膨脹，難以擴展。第三個限制是對分解品質（decomposition quality）保持沉默——評判器只告訴我們子任務是否被解決，卻無法告訴我們這些子任務是否本來就該這樣切分，而這個選擇往往決定了整棵樹能否成功。

**Q3：論文為何主張遞迴代理必須在單一策略中學習三種耦合能力（coupled capabilities）？**
A：因為遞迴代理的每個子代理都是父代理的新實例，所有節點共用同一組權重（shared weights），所以分解、求解、評估三種功能必須同時存在於同一個策略中。這三種能力彼此耦合卻又需要不同的訓練訊號：分解需要關注結構性負載、求解需要關注任務完成度、評估需要對齊真實的成功標準。若只用單一獎勵訊號同時訓練三者，會在共享參數上產生干擾，導致三種能力互相牽制而無法各自達到最佳表現。

**Q4：SERA 的評分量表（rubric）機制其核心創新為何？**
A：SERA 要求父代理在委派子任務之前，先撰寫一份包含加權成功標準（weighted success criteria）的自然語言評分量表，這份評分量表會在子代理執行之前就固定下來，因此無法事後根據軌跡進行擬合（fitted to the trajectory）。將評分量表套用於子代理的輸出後，可以得到一個連續的、子任務專屬的分數（continuous, subtask-specific score），取代傳統粗糙的二元訊號。更重要的是，這份評分量表本身是透過排序目標函數（ranking objective）對齊已驗證的結果來訓練的，使其能真正反映子任務的成功與否。

**Q5：為什麼評分量表的訓練訊號來自已驗證的結果，而非直接來自任務獎勵？**
A：因為評分量表生成與求解共用同一組權重，若以任務獎勵同時訓練兩者，兩者會產生共同適應（co-adapt）的現象——策略可以學會讓評分量表打出高分，卻未必真正提升求解品質，造成評分量表分數膨脹但實際表現不變。為了打破這種耦合，論文引入外部驗證結果作為訓練訊號：對子任務的多次 rollout 進行驗證，並訓練評分量表生成器將成功案例排在失敗案例之上。這樣一來，外部評判器僅用於訓練評分量表生成器，從不直接用於獎勵節點，大幅降低了對外部監督的依賴。

**Q6：葉節點覆蓋訊號（leaf-coverage signal）是什麼？為何需要它？**
A：葉節點覆蓋訊號是一種專門獎勵任務分解品質的訓練訊號，它根據某個委派節點的子樹所覆蓋的葉節點工作佔整體任務葉節點工作的比例來給分。在一棵成功解決的樹中，一個委派若承擔了範圍明確且份量充足的工作就會得到高分；瑣碎的委派則接近零分；在失敗的樹中所有委派都得零分。這項設計填補了執行訊號無法捕捉的結構性缺口——它獎勵代理「真正用委派來承載結構性負載」，對於子任務之間具有依賴鏈、共享狀態或需要協調的任務特別有幫助。

**Q7：SERA 在哪些基準上進行了實驗，主要結果為何？**
A：論文在 TextCraft-Synth 與 TextWorld-Sync 兩個基準上評估 SERA，前者屬於合成環境，後者屬於文字遊戲環境。相較於強遞迴代理基準（strong recursive-agent baselines），SERA 在 TextCraft-Synth 上平均提升 5.38 分，在 TextWorld-Sync 上平均提升 13.14 分，顯示其在不同類型的遞迴任務上都有顯著改善。此外，在推理階段使用評分量表引導的樹搜尋（rubric-guided tree search）後，TextWorld-Sync 上又額外增加了 2.43 分，證明學習到的評分量表不僅在訓練時有用，在推理時同樣能作為有效的選擇器。

**Q8：消融研究（ablation）顯示評分量表訓練為何如此關鍵？**
A：論文的中心發現是：驅動整體效能提升的關鍵在於訓練策略生成對齊的評分量表，而非單純加入評分量表機制。由於同一組權重同時負責評估與執行，學習評判子任務會反過來重塑策略的求解方式——也就是說，「學會判斷」會「磨利求解能力」。這個現象讓共享權重從潛在的缺陷轉變為資產，因為評估與求解之間的正向耦合使得訓練評估能力能直接帶動求解能力的提升，這是傳統將評估外包給獨立評判器的方法所無法獲得的。

**Q9：SERA 如何在降低外部監督的同時仍超越直接使用評判器的方法？**
A：在傳統方法中，評判器會在樹的每個節點直接提供獎勵訊號，因此需要大量且持續的外部監督；SERA 則將評判器的角色縮減為僅用於訓練評分量表生成器，之後的求解訓練完全依賴代理自己生成的評分量表分數。令人驚訝的是，這些由代理自己產生的評分量表分數在作為訓練訊號時，反而比直接使用外部評判器更有效，因為評分量表是子任務專屬且連續的，能提供比二元評判更細緻的梯度。這代表 SERA 不僅減少了對外部監督的需求，還提升了訓練訊號的品質。

**Q10：哪些實際應用場景最能受益於遞迴代理與 SERA 的設計？**
A：需要跨多步驟協調證據的多跳研究問題（multi-hop research questions）是典型場景，因為這類任務需要將檢索步驟拆解並依序執行；另一個重要場景是倉儲規模的程式碼變更（repository-scale code changes），其中各個編輯之間存在相依性，必須以結構化的方式分工。此外，當任務本身具有依賴鏈、共享狀態或需要協調時，葉節點覆蓋訊號能發揮最大效益，這也意味著 SERA 特別適合那些無法被簡單平行化的複雜任務。

**Q11：推理階段的評分量表引導樹搜尋（rubric-guided tree search）是如何運作的？**
A：在推理時，SERA 採用深度優先搜尋（DFS）走訪整棵工作樹，並在每個分支點根據評分量表分數對候選解答進行排序，選出最優的子樹結果向上傳遞。由於評分量表已經過訓練並對齊了真實的子任務成功標準，它能作為可靠的推理時選擇器（inference-time selector），在多個候選 rollout 中挑出最有可能成功的路徑。這種設計讓評估能力在訓練之外也持續貢獻價值，提供了遞迴代理在測試階段擴展（test-time scaling）上的另一個獨立軸度。

**Q12：SERA 對代理式 AI（agentic AI）領域的更廣泛影響為何？**
A：SERA 將自我評估（self-evaluation）從一個附屬功能提升為遞迴代理的核心能力之一，展示了同一組權重可以同時勝任分解、求解與評估三種角色，這對未來設計更通用的代理架構具有示範意義。它也為測試階段擴展提供了一條新軸度——除了更長的思維鏈（chains of thought）與更寬的取樣（wider sampling）之外，學習到的評分量表可以作為推理時的選擇器，進一步提升表現。更重要的是，SERA 證明了減少外部監督不必然犧牲效能，這對降低部署成本與提升自主性都有實質意義。

**Q13：論文承認 SERA 存在哪些限制？**
A：論文坦承未經訓練的策略會產生未對齊的評分量表（misaligned criteria），此時使用其分數作為獎勵效果有限且在不同任務上表現不一致，這凸顯了評分量表訓練的必要性。此外，雖然 SERA 大幅降低了對外部評判器的依賴，但訓練評分量表生成器本身仍需要已驗證的結果作為訊號來源，因此並非完全免監督。葉節點覆蓋訊號在淺層、近乎獨立的子任務上增益有限，主要在子任務具有相依性的場景中才能發揮作用。

**Q14：SERA 在哪些情境下可能會遭遇失敗或表現不佳？**
A：當子任務之間近乎獨立、可以平行處理時，葉節點覆蓋訊號幾乎無法提供額外價值，因為此時分解的結構性負載本來就低。當子任務的成功標準難以用自然語言清楚描述時（例如涉及高度主觀或開放性的判斷），父代理撰寫的評分量表可能本身就無法精準對齊真實目標。此外，若外部驗證本身不可靠（例如驗證器本身有雜訊或偏誤），那麼用來訓練評分量表生成器的排序目標也會受到影響，進而影響整體訓練品質。

**Q15：這項工作為未來研究開啟了哪些可能的方向？**
A：一個明顯的方向是探索更深的遞迴深度（deeper recursion），因為論文已顯示在淺層遞迴下訓練的策略可以泛化到推理時的更深樹，這意味著未來可以研究如何讓評分量表機制在更深、更複雜的樹結構中保持穩定。另一個方向是設計更豐富的評分量表結構，例如多層次、跨節點共享或動態調整權重的評分量表，以處理更複雜的任務結構。此外，將 SERA 的自我評估思想與其他測試階段擴展方法（如更長的思維鏈或更寬的取樣）相結合，也是值得探索的整合方向。

## 實務應用指南

### 適用場景

1. **多步驟程式碼重構與跨檔案除錯**：當工程任務需要同時修改多個相互依賴的模組（例如重構一個分散式系統中的認證與授權流程），SERA 可將任務拆解為「介面定義」、「資料庫遷移」、「前端整合」等子任務，並透過評分量表即時評估每個子代理的輸出，避免單一粗粒度的「程式可執行」訊號掩蓋部分失敗。

2. **深度研究報告撰寫**：在需要彙整多份財報、法律判決書或學術文獻的研究場景中，父代理可為每個子任務（例如「擷取 2023 年 Q3 營收數字」、「比對兩家公司供應鏈揭露」）預先撰寫加權評分量表，子代理完成後由評分量表評分，搜尋階段再以評分量表分數挑選最佳子樹。

3. **企業內部 SOP 自動化**：在需要遵循多步驟內部流程（如客戶盡職調查 KYC、保險理賠審核）的場景中，SERA 可將流程拆解為「文件驗證」、「風險評分」、「例外升級」等子任務，並用評分量表確保每個步驟符合公司規範，而非僅以最終通過與否作為回饋。

4. **多代理協作的資料管線建構**：在 ETL 或資料清洗流程中，父代理可將「欄位對應」、「異常值處理」、「輸出驗證」委派給子代理，葉節點覆蓋訊號會獎勵那些承擔實質工作量的委派決策，避免代理把所有事情都自己做完而失去遞迴的價值。

5. **互動式文字遊戲與長序列決策**：TextCraft-Synth 與 TextWorld-Sync 是論文的實驗場景，但相同機制可應用於任何需要長序列規劃的環境，例如模擬城市經營、回合制策略遊戲 AI，其中子任務間存在依賴鏈與共享狀態。

### 實作前置條件

**資料需求**
- 一組可驗證最終結果的任務集（每個任務需有可程式化檢查的成功條件，例如單元測試、答案比對、狀態檢查）。
- 每個任務至少需要能產生數條不同的成功與失敗 rollout，用於訓練評分量表的排序目標。
- 若任務無法自動驗證，需準備可靠的 LLM 評判器（judge）作為外部監督來源，但僅用於訓練階段。

**運算資源**
- 基礎模型需具備足夠的指令遵循與長上下文能力（建議 7B 以上參數量，或透過 API 呼叫 GPT-4 等級模型）。
- 訓練階段需要平行產生多棵遞迴樹的 rollout，建議配備多 GPU 環境或大量 API 額度。
- 推理階段的樹搜尋會增加 token 消耗，預估為單次推理的 3–10 倍，需準備對應的預算。

**技能前提**
- 熟悉強化學習中的策略梯度與排序損失（pairwise ranking loss）實作。
- 具備設計 prompt 結構以引導模型產出結構化評分量表的能力。
- 理解遞迴呼叫的上下文管理與 token 預算控制。
- 對任務分解的領域知識有基本掌握，以便設計葉節點覆蓋的標註規則。

### 實作步驟建議

1. **建立任務環境與驗證器**：先選定一個具備可驗證結果的領域（例如程式碼任務的測試套件、研究任務的答案比對），實作一個能回傳二元成功訊號的驗證器。這是整個系統的基石，因為評分量表的訓練訊號來自於此。

2. **設計遞迴代理的動作空間**：定義三種特殊 token 或動作標記：`solve`（執行子任務）、`delegate`（委派子任務並附帶評分量表）、`rubric`（撰寫評分量表）。每個父代理在呼叫子代理前必須先輸出評分量表，且評分量表在子代理執行前就固定，避免事後擬合。

3. **實作三階段交替訓練**：
   - **階段一（執行）**：凍結評分量表相關參數，僅用根節點任務成功訊號與非根節點的評分量表分數更新求解能力。
   - **階段二（委派）**：凍結求解與評分量表參數，根據 `task_success × leaf_coverage` 給予委派決策獎勵，鼓勵有意義的分解。
   - **階段三（評分量表生成）**：複製一份策略狀態，產生多條 rollout，由驗證器標記成功與失敗，訓練評分量表將成功排在失敗之上（pairwise ranking）。

4. **設計評分量表的格式**：建議採用「條目 + 權重」的結構化格式，例如 `{"criteria": [{"text": "程式通過所有測試", "weight": 0.6}, ...]}`，權重和為 1，方便計算連續分數。

5. **加入評分量表引導的樹搜尋**：推理時採用深度優先搜尋，每個節點產生多個候選解，以評分量表分數作為選擇器向上傳遞最佳結果。這是論文中額外帶來 2.43 點提升的部分，實作成本低但效益明顯。

6. **監控三種訊號的平衡**：訓練過程中需追蹤三個獎勵的相對量級，避免某一訊號過強導致其他能力退化（例如過度優化分解而犧牲求解品質）。

7. **迭代評估與消融實驗**：在驗證集上分別關閉評分量表訓練、葉節點覆蓋訊號、樹搜尋，確認每個元件的邊際貢獻，這也是論文強調的核心方法論。

### 潛在風險與注意事項

**評分量表與求解的共同適應風險**
- 評分量表生成與求解共用同一組權重，若直接用任務獎勵訓練評分量表，兩者會共適應導致評分量表分數虛高但實際表現未提升。緩解方式：嚴格使用外部驗證器的排序訊號訓練評分量表，而非任務獎勵。

**評分量表品質不穩定**
- 未經充分訓練的策略會產出與子任務成功無關的評分量表，此時用其分數作為獎勵會帶來雜訊甚至負面影響。緩解方式：在訓練初期可先用驗證器直接評分，僅在評分量表對齊後切換為自評分獎勵。

**葉節點覆蓋訊號的誤用**
- 在子任務近乎獨立時，葉節點覆蓋訊號幾乎無貢獻；在子任務高度耦合時則非常有效。緩解方式：根據任務特性調整該訊號的權重，或設計更精細的耦合度偵測機制。

**樹搜尋的計算成本**
- 深度優先搜尋搭配多候選解會顯著增加推理成本，在即時性要求高的場景需設定深度與分支數上限。緩解方式：對淺層節點使用貪婪解，對深層關鍵決策點才啟動搜尋。

**遞迴深度失控**
- 若無深度限制，代理可能無限委派造成 token 爆炸。緩解方式：設定最大遞迴深度（例如 4–6 層），並在評分量表中加入「是否過度委派」的懲罰條目。

**驗證器本身的偏誤**
- 若驗證器對某些失敗模式不敏感（例如只檢查最終答案而忽略中間推理瑕疵），訓練出的評分量表也會繼承這個盲點。緩解方式：定期以人工抽查驗證器的判斷，並補強多樣化的失敗案例。

### 與其他技術的整合建議

**與 ReAct / Function Calling 框架整合**
- SERA 的 `solve` 動作可包裝為標準的 function call，`delegate` 則對應遞迴呼叫同一個 agent endpoint。評分量表可作為 metadata 附加在呼叫結果上，方便與現有的 agent orchestration 框架（如 LangGraph、AutoGen）對接。

**與 Process Reward Model (PRM) 整合**
- 傳統 PRM 為每個推理步驟打分，SERA 的評分量表可被視為「任務層級的 PRM」。兩者可互補：PRM 評估單步推理品質，評分量表評估子任務整體成果。實作上可將評分量表分數作為 PRM 的聚合訊號。

**與 RAG 系統整合**
- 在檢索增強生成場景中，可將「證據擷取」、「答案合成」、「引用檢查」設為子任務，評分量表評估每個子任務的品質。葉節點覆蓋訊號則鼓勵代理在多跳檢索中合理分配委派，而非全部由單一代理完成。

**與程式碼代理整合**
- 與 SWE-bench 類型的程式碼任務結合時，驗證器即為測試套件，評分量表可包含「通過的測試比例」、「程式碼風格符合度」、「相依性正確性」等條目。樹搜尋則可在多個候選修補方案中挑選最佳。

**與人類回饋強化學習 (RLHF) 整合**
- 評分量表的權重可由人類標註者微調，使評分標準更貼近領域專家的判斷。這比直接標註每個子任務輸出更具擴展性。

**與測試階段擴展 (Test-Time Scaling) 整合**
- SERA 本身就是測試階段擴展的一個新軸度（遞迴深度），可與思維鏈長度、取樣寬度等其他軸度組合使用。論文中遞迴策略從淺層訓練泛化到深層推理的特性，正是這種組合的基礎。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解「代理」、「子任務」、「評分量表」三個概念即可，不必深究訓練細節。重點掌握 SERA 的核心洞見：同一個模型不只要會做，還要會拆解與評估自己做的事。可以從論文的圖 1 開始閱讀，它視覺化了整個遞迴樹與三階段訓練的流程，比文字描述更直觀。

**給 AI 工程師**：重點關注 §3 的方法細節，特別是評分量表的排序損失設計與三階段交替訓練的實作細節。建議親手實作一個最小可運行版本：在小型程式碼任務上，用 GPT-4 作為基礎模型，手寫評分量表 prompt，觀察評分量表分數與實際成功率的相關性。論文的消融實驗（§4）告訴我們哪些元件是必要的，這對實作取捨很有幫助。

**給研究者**：論文的理論貢獻在於將遞迴代理訓練重新框定為「分解、求解、評估」三種耦合能力的聯合學習，這個框架可推廣到其他多代理或層級式強化學習設定。建議追蹤論文中關於「共同適應」與「評分量表對齊」的討論，這是該領域尚未被充分探討的問題。RAO（Recursive Agent Optimization）作為前置工作也值得仔細研讀。

**給產品經理**：SERA 的商業價值在於「用更少的外部監督換取更好的代理表現」。論文的關鍵數字是 TextWorld-Sync 上 13.14 點的提升，以及推理時樹搜尋額外帶來的 2.43 點。在評估導入時，應關注三個指標：任務完成率、單次任務的 API 成本（因為樹搜尋會增加 token 消耗）、以及對失敗案例的可解釋性（評分量表本身就是失敗分析的好工具）。建議先在一個高價值但低風險的場景（例如內部研究助理）試點，再逐步擴展到客戶面向的應用。
