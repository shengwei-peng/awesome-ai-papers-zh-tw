## ⚡ TL;DR

解決臨床代理AI中雲端LLM洩漏病患隱私與本地LLM幻覺錯誤在管線中傳播的問題。
提出系統1代理，以確定性編譯器將工具結構與請求轉為選擇題，由單次決策模型作答。
在1952個請求中工具選擇正確率達97.0%，且無任何虛構內容，優於所有本地LLM代理。

代理型人工智慧（Agentic artificial intelligence）可自動化分析敏感性臨床資料（clinical data），但現有代理仰賴大型語言模型（large language models, LLMs）。雲端大型語言模型（Cloud LLMs）會洩露病患資料（patient data）；本地大型語言模型（Local LLMs）則會產生幻覺（hallucination），且工具呼叫（tool call）中出現的虛構值（invented value）會在後續每個步驟中傳遞。本文提出一種建構系統1代理（System 1 agents）的方法：無需生成文字即可呼叫工具的本地代理（local agent）。確定性編譯器（deterministic compiler）將每個工具的結構描述（tool schema）與請求（request）轉換為選擇題（multiple-choice questions），其選項（options）來自請求與工具結構描述，接著由單次決策模型（one-pass decision model）作答。在針對157個生物醫學工具（biomedical tools）的1,952筆請求中，表現最佳的系統1代理在97.0%的請求中正確選擇工具或正確拒絕（correctly declined），顯著優於全部18種本地LLM代理設定（最佳為95.2%）。系統1代理填入了6,056個指定引數值（argument values）中的97.0%。系統1代理的呼叫中未包含任何虛構內容（invented content），而大型語言模型呼叫中則有5.5%至19.7%。系統1代理框架（framework）以開源軟體（open-source software）形式免費提供，網址為 https://github.com/eltzanis/SystemOneAgents。

## 深度分析

#### 方法論解析

本論文提出「系統1代理」(System 1 agents) 的建構方法，核心設計哲學為「模型判斷、程式碼按字面執行」(the model judges, and code executes verbatim what is requested)。此方法借鑑認知科學中的雙重處理理論 (dual-process theory)，將代理決策類比為人類的「系統1」快速判斷，而非「系統2」式的慢速推理。

**三元件架構設計**

系統1代理由三個職責分離的元件組成：

1. **代理 (Agent)**：負責工作流程控制。首先對工具目錄中所有工具加上「none of these」選項進行一次整體詢問。當兩個最高機率工具的機率差距在 0.3 以內時，會進一步查詢哪個工具的參數能容納請求中的數值。接著詢問所選工具是否能完成請求，若機率低於 0.5 則正確拒絕 (correctly declined)。當必要引數值缺失時，代理不會自行填入，而是顯示固定提示模板等待使用者輸入——此處完全沒有隨機生成。

2. **編譯器 (Compiler)**：確定性程式碼，將所選工具的 JSON 結構描述 (JSON schema) 與請求轉換為有限選項的選擇題。對於枚舉值進行列舉詢問；對於布林值詢問「on/off/not mentioned」；對於路徑、數字、名稱等自由值，候選項從請求、結構描述中萃取，並加上「not specified」。候選項還包括由固定規則衍生的數值（如單位轉換、文字書寫的數字、由書寫片段組成的路徑）。清單項目逐一選擇，使候選項彼此競爭。可選引數僅在請求值的機率達到 0.7 時才設定；等於文件預設值的引數不傳遞；請求未給出的必要引數則永遠不填入，而是回報為缺失。

3. **決策模型 (Decision model)**：在單次前向傳遞 (one-pass) 中為每個選項輸出機率。問題介面包含四部分：狀態、題目文字、選項清單、類型（選擇題或是非題）。任何符合此介面的決策模型皆可直接替換使用。

**編譯器開發方法論**

編譯器的開發採用一個能區分模型失敗與編譯器失敗的迭代迴圈。透過「編譯器預言者」(compiler oracle)——以一個知道正確標籤的元件取代決策模型——來檢驗編譯器是否能表達每個標註的呼叫。預言者無法完成的請求揭示了「沒有任何題目提供該數值」的情境，這些問題透過通用規則（而非特定工具規則）來修正，例如請求如何書寫數值的方式。修改只有在以下條件同時成立時才被接受：提升開發請求上跨模型的正確呼叫總數、未使任何先前參考請求的損失超出固定容差、且通過留一法 (leave-one-out) 驗證。

**設計上的根本保證**

此架構從設計上杜絕了虛構內容 (invented content) 的可能性：決策模型僅能從所展示的選項中選擇；每次呼叫的工具必然來自目錄；每個引數名稱必然來自結構描述；每個數值必然來自請求、結構描述或代理政策。每個決策都附帶機率，閾值將其轉化為拒絕或缺失值提示。在相同硬體與軟體下，相同輸入必然產生相同輸出，且執行過程可從儲存的答案逐題稽核重現。

#### 實驗數據解讀

**評估規模與範圍**

研究團隊將此方法應用於 18 個模型上下文協議 (MCP) 伺服器中的 157 個生物醫學工具，涵蓋影像分類、影像分割、放射體學 (radiomics)、自動化機器學習 (AutoML)、電腦斷層基礎模型、蛋白質體學、代謝體學、基因體學、單細胞與空間轉錄體學、臨床試驗及化學等領域。評估集包含 1,952 個請求與 6,056 個陳述引數值。

**核心效能指標**

| 指標 | 最佳系統1代理 | 最佳本地LLM代理 |
|------|---------------|-----------------|
| 正確選擇工具或正確拒絕 | **97.0%** | 95.2% |
| 陳述引數值填入正確率 | **97.0%** | — |
| 虛構內容比例 | **0%** | 5.5–19.7% |

**結果意涵分析**

1. **工具選擇準確度的顯著提升**：97.0% vs 95.2% 的差距看似不大，但在 1,952 個請求的規模下，這代表系統1代理比最佳LLM代理設定多正確處理約 35 個請求。統計顯著性檢定支持此差異並非隨機波動。

2. **零虛構內容的工程意義**：在臨床分析管線 (analysis pipeline) 中，一個被引入的虛構數值不會明顯失敗，而是污染該步驟的結果，後續每一步都建立在此錯誤之上。LLM代理 5.5–19.7% 的虛構率意味著在多步驟分析中，錯誤累積的風險極高。系統1代理的 0% 虛構率從根本上消除了此類錯誤傳播路徑。

3. **引數填入的細節處理**：97.0% 的引數值填入率顯示，雖然系統1代理無法處理所有邊角情境，但對於請求中明確陳述的數值，其萃取與對應能力極為可靠。剩餘 3% 可能對應於請求中未明確給出但需要推論的情境。

4. **機率閾值的設計權衡**：0.3 的工具消歧閾值、0.5 的拒絕閾值、0.7 的可選引數閾值構成三層防線。這些閾值在保守性（避免錯誤呼叫）與可用性（避免過度拒絕）之間取得平衡。

#### 與現有研究的比較

**相較於雲端LLM代理的定位**

雲端LLM代理（如基於GPT-4、Claude的大型代理系統）雖能力強大，但每次請求與相關資料皆須離開機構邊界，與資料保護法規 (data protection) 及機構政策 (institutional policy) 衝突。系統1代理完全在本地運行，徹底解決隱私 (privacy) 障礙。

**相較於本地LLM代理的優勢**

本地LLM代理雖解決隱私問題，但因模型規模較小，幻覺 (hallucination) 率較高。LLM代理以逐詞元生成 (token-by-token generation) 方式寫出每個工具呼叫，可能呼叫不存在的工具、使用工具沒有的引數、或填入使用者從未給出的數值。推理模式 (reasoning modes) 雖能減少部分錯誤，但會倍增每次呼叫產生的文字量，連帶增加時間與能耗。系統1代理透過結構化約束從根本上消除此類錯誤。

**相較於傳統規則式系統的差異**

傳統專家系統或規則引擎需要為每個工具手工編寫規則，可擴展性差。系統1代理的編譯器是通用的——同一編譯器可處理 157 個不同領域的工具，只需替換 JSON 結構描述即可。這代表方法具有跨領域遷移性。

**方法論限制**

1. **表達能力上限**：編譯器只能表達可化約為選擇題的決策。對於需要開放式推理、創意生成或複雜多步驟規劃的任務，系統1代理並不適用。

2. **預言者依賴**：編譯器開發仰賴「編譯器預言者」來識別表達缺口，這需要標註資料。對於缺乏標註的新領域，冷啟動成本較高。

3. **機率校準需求**：決策模型的機率輸出必須經過良好校準，否則 0.3、0.5、0.7 等閾值將失去意義。論文中使用的六個決策模型（4 到 3 億參數）的校準特性需進一步檢驗。

4. **與系統2的互補空間**：論文的定位是針對臨床隱私敏感場景，但對於非敏感、可承擔錯誤風險的探索性任務，LLM代理仍具優勢。未來混合架構（系統1處理結構化決策、系統2處理開放式推理）可能是更全面的解決方案。

1. **決策模型的選擇**：論文中使用六個已發表的決策模型，若未明確指定模型版本、檢查點與量化設定，不同實驗者的結果可能產生偏差。

2. **機率閾值的敏感性**：0.3、0.5、0.7 三個閾值的選擇對最終效能有直接影響。論文中是否提供閾值選擇的消融實驗 (ablation study) 將影響結果的可驗證性。

3. **編譯器規則的完整性**：編譯器包含單位轉換、文字數字解析、路徑組合等通用規則，這些規則的具體實作若未完全公開，將限制方法的獨立驗證。

#### 未來研究方向

**1. 混合架構探索**

系統1代理擅長結構化決策，系統2代理（基於LLM）擅長開放式推理。未來可研究兩者的協作模式：LLM負責理解模糊請求、拆解複雜任務、處理例外情境；系統1代理負責執行結構化的工具呼叫與引數填入。此混合架構可能在保留隱私優勢的同時，擴展可處理的任務範圍。

**2. 編譯器自動化**

當前編譯器的開發仰賴人工迭代與預言者輔助。未來方向包括：
- 利用大型模型自動產生編譯器規則，再以小型決策模型執行
- 從工具呼叫日誌中自動學習常見的數值書寫模式
- 將編譯器本身形式化為可驗證的程式合成 (program synthesis) 問題

**3. 跨領域遷移性驗證**

論文展示 157 個生物醫學工具的應用，但未驗證方法在其他領域（如金融、法律、工程）的遷移表現。系統性研究編譯器規則在不同領域的通用性與領域特異性，將有助於釐清方法的適用邊界。

**4. 決策模型的專用化**

當前使用六個通用決策模型，未來可研究：
- 針對工具呼叫任務專門預訓練的小型模型
- 結合工具結構描述的編碼器增強
- 量化 (quantization) 與蒸餾 (distillation) 對機率校準的影響

**5. 形式化驗證與安全性保證**

系統1代理的確定性特性使其適合形式化驗證。未來可：
- 為編譯器產生正確性證明 (correctness proof)
- 為機率閾值選擇提供最壞情況效能下界
- 將系統整合進醫療器材軟體的監管框架 (如 FDA 的 SaMD 規範)

**6. 使用者互動模式最佳化**

當必要引數缺失時，系統1代理顯示固定提示等待使用者輸入。未來可研究：
- 主動詢問的最小化策略（減少使用者負擔）
- 互動歷史的學習機制（記住使用者偏好）
- 不確定性的溝通方式（如何向使用者解釋機率含義）

**7. 錯誤恢復與除錯工具**

雖然系統1代理不會產生虛構內容，但仍可能選擇錯誤工具或填入錯誤引數值。未來可發展：
- 視覺化的決策路徑追蹤工具
- 自動化的錯誤案例分析
- 與版本控制系統整合的呼叫歷史管理

**8. 基準測試與社群標準**

建立標準化的工具呼叫評估基準 (benchmark)，包含：
- 多樣化的工具類型與領域
- 明確的隱私與可靠性指標
- 公開的標註資料與評估協議

此舉將促進領域內方法的公平比較與持續進步。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於臨床與生物醫學研究中部署代理型人工智慧（Agentic AI）的兩大障礙：病患資料的隱私風險，以及本地大型語言模型在工具呼叫時產生幻覺的可靠性問題。作者指出，雖然代理型 AI 理論上能自動化處理敏感臨床資料的分析流程，但現有方法要嘛依賴雲端 LLM（造成資料外洩），要嘛使用本地 LLM（容易產生幻覺值並在管線中傳播錯誤）。因此，論文的目標是設計一種能在本地運行、且不會產生虛構內容的代理架構。

**Q2：為何現有的基於 LLM 的代理在臨床場景中會失敗？**
A：現有 LLM 代理以逐詞元（token-by-token）方式生成工具呼叫，這種開放式生成使得模型可能呼叫不存在的工具、使用工具未定義的引數，或填入使用者從未提供的值。在分析管線中，這類幻覺值不會立即引發可見錯誤，而是悄悄改變該步驟的結果，並讓後續所有步驟建立在錯誤之上。雖然推理模式（reasoning modes）能減少部分錯誤，但會大幅增加生成文字量、時間與能耗，更不利於臨床即時應用。

**Q3：為何這個問題對臨床與生物醫學研究特別重要？**
A：臨床資料受到嚴格的資料保護法規與機構政策約束，將病患資料傳送至雲端 LLM 服務往往違反相關規範，使最具能力的模型無法直接用於臨床。同時，生物醫學分析（如影像分割、放射組學、蛋白質體學等）通常以多步驟管線形式執行，每一步的錯誤都會污染下游結果，因此對工具呼叫的可靠性要求極高。一個兼顧隱私與可靠性的本地代理方法，對於讓 AI 真正進入臨床實務具有關鍵意義。

**Q4：System 1 代理的核心方法是什麼？**
A：System 1 代理的核心方法由三個元件組成：代理（agent）、確定性編譯器（deterministic compiler）與單次決策模型（one-pass decision model）。代理負責控制工作流程，編譯器將工具的 JSON 結構描述與使用者請求轉換為選項有限的選擇題，而決策模型則以單次前向傳遞為每個選項輸出機率分數。整個過程中沒有任何文字生成，所有決策都來自預先定義的選項，從而使幻覺在架構層面變得不可能。

**Q5：相較於既有方法，最關鍵的創新點為何？**
A：最關鍵的創新在於將「判斷」與「執行」分離：模型只負責在有限選項中做選擇，而所有具體的引數值、工具名稱與結構都來自請求本身、工具結構描述或代理政策。這種設計讓任何工具呼叫的內容都「可追溯」——每個值都能被回放並逐題稽核。此外，作者採用「編譯器神諭（compiler oracle）」的開發迴圈，將模型錯誤與編譯器錯誤明確區分，使系統能以通用規則而非工具專屬規則來改進，這是過去 LLM 代理研究較少觸及的方法論突破。

**Q6：編譯器與決策模型有哪些重要的設計選擇？**
A：編譯器在設計上採用列舉方式處理值、布林方式處理「on/off/未提及」狀態，並對路徑、數字、名稱等自由值從請求與結構描述中萃取候選項加上「未指定」選項。列表項目逐一選擇以使候選項彼此競爭；選填值僅在請求值的機率達 0.7 時才設定，且等於文件預設值的引數不會被傳遞；必填但請求未提供的值則一律不填，由代理向使用者提示。決策模型方面，任何能回答「狀態—題目—選項—類型」介面的模型皆可直接替換，使架構具備高度模型無關性。

**Q7：實驗使用了哪些基準與資料集？**
A：作者將方法應用於 18 個 MCP 伺服器、共 157 個生物醫學工具，涵蓋影像分類、分割、放射組學、AutoML、CT 基礎模型、蛋白質體學、代謝體學、基因體學、單細胞與空間轉錄體學、臨床試驗與化學等領域。評測涵蓋 1,952 筆工具請求與 6,056 個陳述的引數值，並比較了 6 個 System 1 代理與 9 種本地 LLM 代理設定（共 18 種 LLM 設定），在準確度、可靠性與效率三個面向進行系統性對比。

**Q8：最重要的實驗結果為何？**
A：最佳 System 1 代理在 97.0% 的請求中正確選擇工具或正確拒絕，顯著優於所有 18 種本地 LLM 代理設定（最佳 95.2%）；同時填入了 97.0% 的陳述引數值。更關鍵的是，System 1 代理的所有呼叫中沒有任何虛構內容，而 LLM 代理的呼叫中虛構內容比例介於 5.5% 至 19.7% 之間。這代表 System 1 代理不僅在準確度上勝出，更在「無幻覺」這個對臨床至關重要的指標上達到零失誤。

**Q9：論文中進行了哪些消融或分析研究？**
A：作者透過「編譯器神諭」實驗來分離模型錯誤與編譯器錯誤：當神諭（知道正確標籤）仍無法完成某些請求時，代表編譯器未提供對應選項，這類問題以通用規則而非工具專屬規則來修正。此外，每項改動必須同時滿足三項條件：在開發請求上提升正確呼叫總數、不超出容忍地失去任何先前的參考請求、以及通過留一法（leave-one-out）執行。這種嚴格的開發流程本身就是一種系統性的消融驗證，確保改進具有泛化性而非過擬合。

**Q10：這項技術能支援哪些實際應用場景？**
A：這項技術可直接支援醫院內部的影像檢查準備、模型訓練與推論、以及生物醫學資料庫查詢等場景，所有資料皆不離開機構。由於無幻覺特性，它特別適合用於多步驟分析管線，例如放射組學特徵萃取後串接 AutoML、蛋白質體學分析後接續統計檢定、或臨床試驗資料的多重查詢等需要嚴格資料正確性的工作流程。

**Q11：從產品與工程角度，這個框架有哪些值得考量的特性？**
A：從工程角度，System 1 Agents 框架以開源形式釋出，並採用「介面導向」的決策模型設計，使任何符合「狀態—題目—選項—類型」介面的模型皆可無縫替換，便於機構依需求選用合適的本地模型。此外，由於所有決策都附帶機率並可被閾值轉為拒絕或提示，框架天然支援可稽核性與可重播性——同一硬體與軟體下相同輸入必產生相同輸出，這對臨床環境的合規審查極為重要。

**Q12：這項研究對代理型 AI 領域的整體影響為何？**
A：這項研究挑戰了「代理必須基於 LLM」的隱含假設，提出了一條以決策模型與確定性編譯器為基礎的替代路徑，為高風險領域的代理部署提供了新範式。它也示範了一種嚴謹的開發方法論——透過神諭分離錯誤來源、以通用規則修正——這對未來構建可靠、可解釋的代理系統具有方法論上的示範意義，可能促使更多領域（如金融、法律、國防）借鏡這種「無生成、可稽核」的設計哲學。

**Q13：論文中承認的限制有哪些？**
A：論文中可推論的限制包括：System 1 代理仰賴工具目錄與結構描述的完整性，若工具本身設計不完善或結構描述不完整，代理表現會受影響。此外，雖然在 157 個生物醫學工具上表現優異，但對於需要開放式生成（例如自由文字摘要、創意內容生成）的任務並不適用，因為其設計本質上排除了開放式輸出。對於請求中未提供且無法從結構描述推導的值，代理會主動提示使用者而非自行猜測，這在某些自動化場景下可能需要額外的人機互動成本。

**Q14：哪些情況下 System 1 代理可能會失敗？**
A：當請求中包含編譯器未涵蓋的表達方式（例如非常規的數字寫法、罕見的單位、或非標準的路徑組合）時，代理可能無法從請求中萃取候選值，導致必填值被視為缺失而觸發使用者提示。此外，若兩個最可能工具的機率差距小於 0.3，代理會進入第二輪詢問，這在邊界案例上可能增加延遲。對於需要跨工具組合推理或動態規劃的複雜任務，僅靠單次選擇題的架構可能不足以表達完整意圖。

**Q15：未來可能的研究方向為何？**
A：未來方向可能包括：將此方法擴展至更多領域的工具集（如金融、法律、科研），並探索更強的決策模型以提升在邊界案例上的判斷力。此外，編譯器的通用規則仍可進一步豐富，以涵蓋更廣泛的請求表達方式；同時，如何將 System 1 與 System 2 代理結合（例如在需要開放式推理的步驟引入 LLM，但在工具呼叫層維持確定性）也是值得探索的混合架構方向。長期而言，這種「可稽核、可重播」的代理設計哲學有望成為高風險領域 AI 部署的事實標準。

### 實作步驟建議

**步驟 1：盤點工具並建立 MCP 伺服器**
盤點現有分析工具（影像、基因體、化學等），為每個工具撰寫 JSON Schema，明確定義引數名稱、型別、預設值與描述。將工具包裝為 MCP 伺服器，確保代理可透過統一介面呼叫。

**步驟 2：建立標註請求集**
收集 1,000 至 2,000 筆真實使用者的自然語言請求，由領域專家標註正確的工具選擇與引數值。建議涵蓋常見請求、邊界案例與應拒絕的請求（無對應工具）。

**步驟 3：實作確定性編譯器**
依照論文描述的架構，實作將「工具 Schema + 請求」轉換為選擇題的編譯器。重點處理：
- 列舉型引數的選項抽取
- 布林值的「開/關/未提及」三分類
- 數值與路徑的固定規則轉換（如單位轉換、數字文字解析）
- 必要引數缺失時的提示機制

**步驟 4：建立編譯器開發迴圈**
使用「編譯器神諭（compiler oracle）」區分模型錯誤與編譯器錯誤。神諭知道正確標籤，若神諭仍無法完成請求，表示編譯器未提供對應選項，需修正通用規則而非為特定工具寫特例。每次修改須提升開發集正確率、不破壞留一法表現。

**步驟 5：選擇與部署決策模型**
從六種已發表的決策模型中選擇，考量準確率、延遲與硬體限制。模型只需支援「狀態 + 問題文字 + 選項列表 + 種類」的介面，無需額外微調。

**步驟 6：設定閾值與政策**
根據論文建議設定：
- 工具選擇信心閾值（0.3 用於消歧、0.5 用於拒絕）
- 選用值機率閾值（0.7）
- 預設值處理政策（不傳遞等於預設的值）

**步驟 7：建立審核與回放機制**
儲存每次呼叫的問題、選項與機率分布，支援完整回放與逐步審核。這是符合臨床與研究合規要求的關鍵設計。

**步驟 8：部署與監控**
在本地環境部署代理，監控拒絕率、缺失引數提示頻率與使用者回饋，持續改進編譯器規則。

### 潛在風險與注意事項

**風險 1：編譯器規則覆蓋不足**
若自然語言請求的表達方式超出編譯器抽取規則，必要引數會被標記為缺失，使用者體驗受影響。
**緩解**：建立常見失敗模式清單，優先補強高頻缺失規則；提供清晰的缺失引數提示讓使用者手動補齊。

**風險 2：工具目錄擴充成本**
每新增工具都需設計 Schema 並驗證編譯器能否正確處理其引數。
**緩解**：建立 Schema 範本與自動驗證腳本；對新工具執行小規模標註測試。

**風險 3：決策模型的領域偏誤**
小型決策模型在特定領域（如罕見影像類型、特殊化學命名）可能判斷力不足。
**緩解**：保留信心閾值機制，低信心時主動拒絕而非猜測；考慮領域微調或使用更大模型。

**風險 4：複雜多步驟管線的錯誤傳播**
雖然單步呼叫無幻覺，但多步驟管線中前一步的選擇仍會影響後續。
**緩解**：每步皆記錄機率與拒絕原因；對關鍵步驟要求人類確認。

**風險 5：使用者對「AI 拒絕」的接受度**
當代理正確拒絕時，使用者可能誤以為系統故障。
**緩解**：設計清楚的拒絕訊息，說明原因並建議替代工具或請求方式。

**風險 6：與現有 LLM 工作流的相容性**
若組織已投資 LLM 代理基礎設施，轉換至 System 1 代理需重新設計部分流程。
**緩解**：採混合架構，System 1 代理處理結構化工具呼叫，LLM 僅用於開放式對話或摘要。

### 與其他技術的整合建議

**與 LLM 代理的混合架構**
System 1 代理擅長結構化工具呼叫，LLM 擅長開放式對話與摘要。建議架構：LLM 作為前端對話介面，理解使用者意圖後將結構化子任務轉交 System 1 代理執行；System 1 代理的結果再由 LLM 整理為自然語言回應。

**與電子病歷系統（EMR）整合**
透過 FHIR 或 DICOM 介面，將 EMR 中的結構化欄位（病人 ID、檢查日期、影像類型）直接傳遞給 System 1 代理，避免自然語言解析的誤差。代理的呼叫記錄可寫入 EMR 的稽核日誌。

**與 Jupyter 與研究筆記本整合**
將 System 1 代理封裝為 Jupyter magic command 或 Python API，研究人員可在筆記本中以自然語言請求工具呼叫，同時保留程式碼的可重現性。代理的問題-選項-機率記錄可匯出為研究附錄。

**與 CI/CD 與批次排程整合**
對於例行性分析管線，System 1 代理的確定性輸出特別適合 CI/CD 環境。每次提交的請求可產生相同的工具呼叫序列，便於測試與回歸驗證。

**與模型監控平台整合**
將代理的機率分布、拒絕率、缺失引數率等指標匯入現有 MLOps 監控平台，設定異常告警（如某工具的拒絕率突然上升可能表示 Schema 變更或請求模式改變）。

**與開源 LLM 框架整合**
System 1 Agents 框架可與 LangChain、LlamaIndex 等框架共存，作為其中的「工具呼叫執行器」元件，取代其內建的 LLM 工具呼叫邏輯。

### 給不同背景讀者的閱讀建議

**給初學者**：本文介紹的 System 1 代理概念直觀——與其讓 AI「自由發揮」產生幻覺，不如把每個決策變成選擇題，由專門的判斷模型從有限選項中挑選。建議先理解「幻覺為何危險」與「為什麼選擇題比開放式問答更可靠」這兩個核心動機，再閱讀方法章節。實作上可先從小型工具目錄（如 5-10 個工具）開始，體驗編譯器如何將請求轉為選擇題。

**給 AI 工程師**：重點關注編譯器的設計與開發迴圈。論文的「編譯器神諭」方法是值得借鏡的工程實踐——它強制區分模型能力極限與系統設計缺陷，避免在錯誤的方向上迭代。決策模型的介面設計（狀態、問題、選項、種類）簡潔且可擴展，可直接套用至其他領域的結構化決策問題。效能數據（97.0% 工具選擇準確率、零幻覺）是相較 LLM 代理的關鍵優勢。

**給研究者**：本文對臨床 AI 部署的「最後一哩路」問題提出了務實解法。幻覺在開放式生成中或許可接受，但在分析管線中卻會靜默傳播並污染結論。System 1 代理的確定性與可審計性為臨床研究的可重現性提供了新標準。建議深入閱讀編譯器開發迴圈的細節，理解如何在不過度擬合特定工具的前提下提升泛化能力。

**給產品經理**：System 1 代理解決了企業 AI 部署的兩個最大障礙——隱私與可靠性。對於處理敏感資料（醫療、金融、法律）的產品，這是合規友善的架構選擇。產品設計上需注意：代理會「正確地拒絕」不適合的請求，這對使用者體驗是新的設計模式，需教育使用者理解「拒絕」是品質而非缺陷。開源框架降低了採用門檻，適合快速原型驗證。
