## ⚡ TL;DR

多模態網頁代理常以更高推論成本換取效能，累積經驗反而更昂貴，且存在重複動作與低快取利用率等結構低效。
提出PANDO，以單次推展線上技能蒸餾建立技能庫，透過進度反思、分層路由與快取感知提示降低推論成本。
於VWA910項任務中，PANDO成功率58.3%領先SGV與WALT，Token用量減半以上。

## 摘要翻譯

近期多模態網頁代理（multimodal web agents）的進展往往仰賴更多的推論時計算（inference-time computation），包括推展搜尋（rollout search）、驗證器遍歷（verifier passes）、離線技能發現（offline skill discovery）與專家模型堆疊（specialist model stacks）。這引發了一個核心問題：網頁代理（web agent）能否在累積經驗的同時變得更有效率，而非更加昂貴？我們首先分析來自 VisualWebArena 的軌跡（trajectories），並找出三個反覆出現的效率低落來源：重複動作迴圈（repeat-action loops）、隱藏發現成本（hidden discovery costs），以及低提示快取重複使用率（low prompt-cache reuse）。接著我們提出 PANDO，一個單次推展（single-rollout）線上技能蒸餾（online skill distillation）框架，維護一個結構化的技能庫（Skill Library），並結合進度反思（progress reflection）、基於置信度的技能降級（confidence-based skill demotion）、分層路由（hierarchical routing）、視覺壓縮（visual compression）與快取感知提示（cache-aware prompting）。在全部 910 項 VisualWebArena 任務上，PANDO 達到 58.3% 的成功率（success rate），超越 SGV（54.0%）與我們復現的 WALT（45.2%），同時比 SGV 少用 58% 的 Token，比 WALT 少用 61% 的 Token，且無須任何評估前發現預算（pre-evaluation discovery budget）。一項涵蓋 300 項任務的消融實驗（ablation）進一步顯示，規則與例行程序（rules and routines）貢獻了大部分的成功率提升，而分層路由（hierarchical routing）、視覺壓縮（visual compression）與快取感知提示（cache-aware prompting）則將更大的技能庫（skill library）轉化為更低的邊際 Token 成本（marginal token cost）。最後，我們提出三項軌跡層級效率指標（trajectory-level efficiency metrics）——動作重複率（Action Repetition Rate）、步驟開銷比率（Step Overhead Ratio）與提示快取利用率（Prompt Cache Utilization）——使效率在終端成功（terminal success）之外亦能被具體衡量。

### 核心貢獻（3～5點）
- 分析 VisualWebArena 軌跡，識別多模態網頁代理的三項結構性效率低落來源：重複動作迴圈（repeat-action loops）、隱藏發現成本（hidden discovery costs）與低提示快取重複使用率（low prompt-cache reuse）。
- 提出單次推展（single-rollout）線上技能蒸餾（online skill distillation）框架 PANDO，透過結構化技能庫（Skill Library）與五大機制（進度反思、基於置信度的技能降級、分層路由、視覺壓縮、快取感知提示），在無須評估前發現預算（pre-evaluation discovery budget）下同步提升效能與效率。
- 於 910 項 VisualWebArena 任務達成 58.3% 成功率（success rate），超越 SGV（54.0%）與 WALT（45.2%），且分別減少 58% 與 61% 的 Token 消耗。
- 300 項任務消融實驗（ablation）顯示，規則與例行程序（rules and routines）是成功率提升的主因，而分層路由、視覺壓縮與快取感知提示則有效降低邊際 Token 成本（marginal token cost）。
- 提出三項軌跡層級效率指標（trajectory-level efficiency metrics）——動作重複率（Action Repetition Rate）、步驟開銷比率（Step Overhead Ratio）、提示快取利用率（Prompt Cache Utilization）——將效率評估從終端成功（terminal success）拓展至軌跡層級。

### 適合對象
從事多模態網頁代理、大型語言模型推論效率最佳化與網頁自動化研究的學者與工程師；特別適合關注如何在降低推論時計算（inference-time computation）與 Token 消耗的前提下，仍維持高任務成功率的讀者。

## 深度分析

#### 方法論解析

PANDO（PANDO）的核心假設是：多模態網頁代理（multimodal web agents）的效率低落並非單純源於模型能力不足，而是源於可識別的機械性浪費。作者首先對 VisualWebArena（VWA）（多模態網頁代理基準測試集）進行軌跡稽核，發現三大重複出現的低效來源：重複動作迴圈（repeat-action loops）（佔圖像標註失敗的 34–42%）、隱藏發現成本（hidden discovery costs）（如 WALT 在評估前進行離線工具探索），以及低提示快取重複使用率（low prompt-cache reuse）（傳統文字／字幕方法的 Prompt Cache Utilization（提示快取利用率）低於 11%）。這些發現構成 PANDO 的設計動機。

PANDO 是一個單次推展（single-rollout）的線上技能蒸餾（online skill distillation）框架，其關鍵在於維護一個持續增長的結構化 Skill Library（技能庫）。與離線技能發現（offline skill discovery）不同，PANDO 在測試查詢串流（test-query stream）中進行技能歸納，因此完全不需要評估前發現預算（pre-evaluation discovery budget）。

Skill Library（技能庫）包含兩類核心元素：
1. **Rules（規則）**：以模式索引（pattern-indexed）的方式儲存，用於攔截並阻止已知的重複失敗模式，直接對應重複動作迴圈（repeat-action loops）問題。
2. **Parameterized Routines（參數化例行程序）**：將多步驟的瀏覽子目標封裝為可重複呼叫的例行程序，取代冗長的 chain of thought（思維鏈）或逐步規劃。

在學習機制方面，Learning Module（學習模組）負責技能的准入、合併與降級。其中包含：
- **Polarity-pair merging（極性對合併）**：推測用於合併語意相近但表徵相反的技能實例，以維持技能庫的緊湊性。
- **Confidence-based skill demotion（基於置信度的技能降級）**：當技能在後續任務中的表現未達預期時，降低其優先級或將其淘汰，避免累積過時或錯誤的經驗。

在推論時（inference-time computation），PANDO 透過以下機制確保增長的 Skill Library（技能庫）不會成為負擔：
- **Progress reflection（進度反思）**：由 Reflector（反思器）驗證當前步驟是否確實推進任務，避免無效探索。
- **Hierarchical routing（分層路由）**：根據任務特徵與技能後設資料，快速導向最相關的規則或例行程序，而非將整個技能庫塞入提示（prompt）。
- **Visual compression（視覺壓縮）**：減少 screenshot processing（截圖處理）的 Token 負擔。
- **Cache-aware prompting（快取感知提示）**：主動重排提示結構以最大化可快取性（cacheability），直接回應低提示快取重複使用率（low prompt-cache reuse）的問題。

整體而言，PANDO 將「經驗累積」從一種記憶負擔轉化為結構化資產：隨著任務串流推進，Skill Library（技能庫）變大，但透過 routing、compression 與 cache-aware 設計，邊際 Token 成本（marginal token cost）反而下降。

#### 實驗數據解讀

作者在完整的 910 筆 VisualWebArena（VWA）任務上進行評估。PANDO 達到 58.3% 的 success rate（成功率），相較於 SGV（SGV）的 54.0% 提升 4.3 個百分點，相較於作者自行復現的 WALT（WALT）的 45.2% 更提升 13.1 個百分點。這顯示線上技能蒸餾（online skill distillation）不僅能提升終端成功（terminal success），其增益幅度還超過部分依賴推論時計算（inference-time computation）的基線。

更關鍵的是 Token 經濟（Token 經濟）的翻轉：PANDO 相較 SGV 減少 58% 的 Token 消耗，相較 WALT 減少 61%，且完全沒有預先投入的評估前發現預算（pre-evaluation discovery budget）。這打破了「更高成功率必須購買更多推論時計算」的慣例。

在 VWA-300 的消融實驗（ablation）中，作者進一步拆解各元件的貢獻：
- **Rules and routines（規則與例行程序）**：提供大部分的 success rate（成功率）增益。這驗證了將重複失敗與多步子目標結構化為技能的策略，確實能提升決策品質。
- **Hierarchical routing（分層路由）、visual compression（視覺壓縮）、cache-aware prompting（快取感知提示）**：則負責將較大的 Skill Library（技能庫）轉化為更低的邊際 Token 成本（marginal token cost）。換句話說，這三項機制解決了「技能庫變大後推論變慢」的規模化瓶頸。

此外，本文提出三項軌跡層級效率（trajectory-level efficiency）指標，彌補終端成功（terminal success）無法反映資源浪費的缺陷：
1. **Action Repetition Rate (ARR)（動作重複率）**：量化重複動作迴圈（repeat-action loops）的嚴重程度。
2. **Step Overhead Ratio (SOR)（步驟開銷比率）**：衡量相對於人類最小步數的膨脹程度。
3. **Prompt Cache Utilization（提示快取利用率）**：追蹤提示內容被重複利用的比例。

這些指標的引入具有方法論意義：它們使研究者能夠診斷「為何一個任務最終成功卻仍浪費大量 Token」，從而將代理評估從二元結果導向轉為軌跡層級的精細會計。

#### 與現有研究的比較

PANDO 在現有多模態網頁代理（multimodal web agents）光譜中，明確定位為「單次推展（single-rollout）效率派」的極致延伸。當前主流的高效能路徑往往遵循 Token 經濟（Token 經濟）邏輯：透過 behavior best-of-N（行為最佳 N 次取樣）、rollout search（推展搜尋）、verifier passes（驗證器遍歷）或 specialist model stacks（專家模型堆疊）來購買準確度。例如 Agent S 系列從 Agent S 的 20.6% OSWorld 成功率，到 Agent S3 透過 10-rollout 的 behavior best-of-N 達到 72.6%，其本質是將單次推展計算乘以十倍。相較之下，PANDO 反問：能否不增加推論時計算（inference-time computation），而是讓代理隨經驗累積變得更便宜？

與同為單次推展的 SGV（SGV）相比，PANDO 在 success rate（成功率）上領先 4.3 個百分點，同時 Token 消耗僅為其 42%。這顯示結構化的 Skill Library（技能庫）與線上技能蒸餾（online skill distillation）比 SGV 的隱式策略更具資料效率。與 WALT（WALT）相比，PANDO 不僅成功率大幅提升，更消除了 WALT 隱含的隱藏發現成本（hidden discovery costs）——WALT 在評估前需進行離線工具探索，而 PANDO 的線上歸納機制使這類預算歸零。

然而，PANDO 的評估情境仍存在邊界：
- **動作落地（grounding）難度**：VWA 採用 click[id] 風格的 DOM 選擇，屬於相對結構化的 grounding（動作落地）。在像素級 grounding（如 OSWorld 或 WindowsAgentArena）的環境中，screenshot processing（截圖處理）與視覺壓縮（visual compression）的挑戰會更嚴峻，PANDO 的視覺機制是否仍能維持同等壓縮率尚待驗證。
- **任務分布假設**：作者明確指出，實驗採用固定的 VWA-910 任務排序，且不假設任務分布的非穩定性（non-stationarity）。這意味著 PANDO 目前的「終身學習」仍是在固定分布內的序列歸納，尚未面對真實世界中任務分布漂移的挑戰。
- **骨幹模型（backbone）透明度**：文中未明確揭露 PANDO 使用的視覺語言模型（VLM）骨幹，這使得部分增益難以完全歸因於框架設計本身，而非基礎模型能力的差異。

從提供的文本來看，PANDO 的可重現性（reproducibility）呈現「基準公開、方法結構清晰、但實作細節與釋出狀態未明」的狀態。

**不利因素與缺口：**

綜合而言，PANDO 在方法論層面具備可重現的藍圖，但在工程實作層面仍需等待作者釋出程式碼與完整超參數，方能進行嚴格的第三方驗證。

#### 未來研究方向

PANDO 的設計為多模態網頁代理（multimodal web agents）的效率研究開啟了數條可延伸的路徑：

1. **跨基準技能遷移與共享**：目前 Skill Library（技能庫）在單一基準內累積。未來可探索跨 VisualWebArena（VWA）、WebArena、Mind2Web 甚至 OSWorld 的技能遷移，實現「許多可見樹幹、一個共享根系」的願景。更進一步，多代理系統可共享同一套 Skill Library（技能庫），形成真正的集體學習網路。

2. **像素級動作落地（pixel-level grounding）的適配**：當代理從 DOM-based 的 click[id] 轉向自由形式 pyautogui 或行動裝置手勢時，visual compression（視覺壓縮）與 grounding（動作落地）模組必須處理更高解析度、更複雜的視覺輸入。結合 UGround、Aguvis 或 UI-TARS 等專門的 GUI grounding VLM，可能是維持 PANDO 效率優勢的關鍵。

3. **非穩態與持續學習**：本文假設任務分布固定。未來研究應將 PANDO 置於非穩態（non-stationary）或對抗式任務串流中，檢驗 confidence-based skill demotion（基於置信度的技能降級）能否有效對抗災難性遺忘（catastrophic forgetting），並維持 Skill Library（技能庫）的時效性。

4. **技能庫的規模化法則（scaling laws）**：隨著技能數量增長，hierarchical routing（分層路由）的檢索成本與錯誤路由率可能上升。需要系統性研究 Skill Library（技能庫）大小與邊際 Token 成本（marginal token cost）之間的定量關係，以決定何時該合併、刪除或分片技能庫。

5. **從 Token 效率到能源與延遲效率**：本文聚焦於 Token 消耗，但引言中已援引資料中心能源需求作為動機。未來可將 PANDO 與 vLLM、PromptCache 等服務層優化疊加，直接測量 wall-clock latency（延遲）與每任務焦耳數（Joules per task），建立更完整的電腦使用代理（computer-use agents）碳會計框架。

6. **與推理增強骨幹的協同**：當前大型語言模型趨向更長的 reasoning traces（推理軌跡）。未來可研究 PANDO 的 Skill Library（技能庫）能否作為「外部記憶」，縮短甚至取代部分 chain of thought（思維鏈），在保持模型能力的前提下抑制輸出 Token 膨脹。

## 論文問答

**Q1：PANDO 旨在解決多模態網頁代理領域中的什麼核心問題？**
A：PANDO 旨在解決當前多模態網頁代理普遍依賴「Token 經濟」來換取效能提升的困境，也就是透過推論時計算（如推展搜尋、驗證器遍歷、離線技能發現或專家模型堆疊）來提高成功率，卻導致每次推論都更加昂貴。這種模式不僅造成邊際 Token 成本持續上升，也帶來延遲、能源消耗與隱藏發現成本等隱性負債。PANDO 的核心提問是：代理能否在累積經驗的過程中變得更便宜、更高效，而非每次執行都付出固定的推理稅？

**Q2：為何現有方法（如 SGV 與 WALT）難以同時達成高成功率與高效率？**
A：現有方法大多延續以更多計算換取準確度的路徑，例如 WALT 存在顯著的隱藏發現成本，而 SGV 雖然表現較佳，卻仍消耗大量 Token 且缺乏線上技能重用的機制。從軌跡層級的分析來看，這些基線系統普遍存在重複動作迴圈（佔失敗案例的 34–42%）、離線工具探索的隱藏成本，以及極低的提示快取重複使用率（低於 11%）。這些並非單純的模型能力不足，而是結構性的機械低效，因為代理缺乏持續累積並重用經驗的持久化結構。

**Q3：為何解決 Token 經濟與軌跡層級效率的問題，對電腦使用代理特別迫切？**
A：電腦使用代理天生就是 Token 密集型的系統，它們每步都需進行截圖處理、維護冗長的互動歷史、呼叫規劃器與反思器，並在動作落地失敗時重試，研究顯示其步數可達人類的 1.4–2.7 倍，且 75–94% 的延遲來自規劃與反思。與此同時，推論已主導機器學習的運算生命週期，資料中心的能源需求更成為首要的資源與環境限制，使得「花更多 Token 變更好」不再是可忽略的帳務細節。因此，將研究重心轉向「能否在不持續增加支出的前提下讓代理變得更好」，對於實際部署與永續營運至關重要。

**Q4：PANDO 的核心方法為何？它與離線技能發現或多推展方法有何根本差異？**
A：PANDO 是一個單次推展的線上技能蒸餾框架，它在評估過程中維護一個持續成長的結構化技能庫，且完全不需要評估前發現預算。不同於將探索與部署分離的離線技能發現，或將單次推展計算乘以十倍的最佳 N 次推展策略，PANDO 直接在測試查詢串流中進行終身學習式的技能歸納。這使得代理隨著任務串流的進行而變得更便宜，而非為每個新任務支付固定的推理稅。

**Q5：PANDO 技能庫的關鍵創新與維護機制為何？**
A：PANDO 的技能庫仿照「Pando 白楊樹群」的隱喻，作為共享根系支撐多個可見的任務執行，其內容包含以模式索引的規則（用於阻止重複失敗）與參數化的例行程序（用於取代多步驟的瀏覽子目標）。維護上，學習模組負責技能的准入、合併與基於置信度的技能降級，而進度反思機制則驗證執行進度，確保只有有用的模式被保留下來。這種結構化的持久記憶將原始軌跡經驗轉化為緊湊且可重複使用的知識，直接針對重複動作迴圈、隱藏發現成本與低提示快取重複使用率這三大低效來源。

**Q6：作者為何選擇將分層路由、視覺壓縮與快取感知提示整合於單一框架中？**
A：這三項設計各自扮演不同但互補的角色，共同將不斷擴大的技能庫轉化為更低的邊際 Token 成本，而非更高的推論負擔。分層路由確保僅呼叫與當前子目標最相關的技能，避免上下文膨脹；視覺壓縮降低每步截圖處理的 Token 負載；快取感知提示則最大化跨回合的提示前綴重用率。300 任務的消融實驗明確顯示，雖然規則與例行程序貢獻了大部分的成功率提升，但正是這三項機制防止了技能庫增長所帶來的線性成本上升。

**Q7：PANDO 在哪些基準測試上進行評估？評估範圍為何？**
A：PANDO 在完整的 VisualWebArena（VWA）基準上進行評估，涵蓋全部 910 項任務，並採用固定的任務排序，且不對任務分佈的非平穩性做任何假設。作者另外在一個 300 任務的子集上進行消融研究，以歸因各個元件的貢獻。選擇 VWA 是因為它代表了極具挑戰性的多模態網頁代理環境，而過往系統往往只能透過大量推論時計算才能在此取得高表現。

**Q8：PANDO 的主要量化結果為何？與基線相比有何優勢？**
A：在全部 910 項 VWA 任務中，PANDO 達到 58.3% 的成功率，分別超越 SGV（54.0%）4.3 個百分點，以及作者復現的 WALT（45.2%）13.1 個百分點。關鍵在於，PANDO 在提升準確度的同時，比 SGV 減少了 58% 的 Token 使用量，比 WALT 減少了 61%，且完全不需要評估前發現預算。這些結果證明 PANDO 同時推進了單次推展代理的準確率前緣與效率前緣。

**Q9：300 任務的消融實驗對 PANDO 各元件的貢獻提供了哪些洞見？**
A：消融實驗揭示了各元件之間明確的分工：規則與例行程序提供了大部分的成功率提升，因為它們直接編碼了可重複使用的動作模式，能阻止重複失敗並簡化子目標的完成流程。相對地，分層路由、視覺壓縮與快取感知提示則主要負責降低 Token 消耗，確保技能庫的增長不會線性地推升推論成本。這種職責分離驗證了作者的設計直覺：技能內容驅動準確度，而技能基礎設施驅動效率。

**Q10：在哪些實際部署場景中，PANDO 的線上技能蒸餾特別具有優勢？**
A：PANDO 特別適合需要處理長時間、連續且多樣化網頁自動化任務的生產環境，尤其是那些無法負擔大規模離線探索階段或昂貴 GPU 叢集進行推展搜尋的應用。由於其隨時間推移而變得更便宜的特性，它非常適合成本敏感的場景，例如客戶服務自動化、資料輸入與重複性的行政工作流程，這些場景中相同的底層模式會在不同工作階段反覆出現。此外，因為它不需要評估前發現預算，所以能立即部署在新的任務分佈上，並在遭遇真實使用者請求時自主改善。

**Q11：與依賴專家模型堆疊或最佳 N 次推展的系統相比，PANDO 在產品層面提供哪些優勢？**
A：從產品角度來看，PANDO 提供了可預測且遞減的邊際任務成本，而專家模型堆疊會增加系統複雜度與維護開銷，最佳 N 次推展則會將延遲與能源消耗放大一個數量級。單次推展的設計簡化了服務基礎設施、降低了 wall-clock 延遲，並避免了評估前發現預算所帶來的隱性負債，使總擁有成本更易於估算。此外，高提示快取利用率與視覺壓縮能直接轉化為更低的服務開支與更快的互動回應，對於互動式瀏覽器自動化產品尤為重要。

**Q12：PANDO 可能如何影響多模態代理設計與評估的未來研究方向？**
A：PANDO 將研究焦點從僅以終端成功率作為唯一優化目標，轉向雙目標典範，要求同時報告軌跡層級效率指標，例如動作重複率、步驟開銷比率與提示快取利用率。透過證明線上技能歸納能夠勝過依賴大量計算的基線，它鼓勵學界投資於持久的代理端記憶與結構化技能重用，而非無止境地擴大推論時規模。這可能催生一條將效率視為首要目標的終身學習代理研究路線，從而降低部署系統的環境與經濟足跡。

**Q13：作者承認 PANDO 目前的設計存在哪些限制？**
A：作者指出，PANDO 目前的評估是在 VisualWebArena 的固定任務排序下進行，且未對任務分佈的非平穩性做出假設，因此其在快速變化或對抗性排序下的表現仍是未解問題。雖然技能庫在線上持續成長，但當技能數量擴展到數千個高度異質的模式時，分層路由是否仍能維持效能而不退化，目前實驗尚未完全驗證。此外，單次推展的設計雖然提升了效率，但其成功率天花板可能天生低於能負擔大量推展搜尋或驗證器集合的方法。

**Q14：儘管具備技能庫，PANDO 仍可能面臨哪些類型的失敗案例或低效情況？**
A：儘管 PANDO 能緩解重複動作迴圈，但當遇到與技能庫中任何現有規則或例行程序都不匹配的全新任務結構時，仍可能在首次遭遇時產生探索性的低效。基於置信度的技能降級機制雖然能防止無效技能長期留存，但若早期的成功訊號帶有雜訊，也可能過於激進地降級那些僅有邊際用處的技能。此外，視覺壓縮與快取感知提示雖然降低了 Token 負載，但在極複雜的多頁面互動中，理論上可能遺漏細微的視覺線索或影響提示的連貫性，儘管本文未明確量化這些特定失敗模式。

**Q15：作者暗示或建議了哪些未來研究方向，以擴展 PANDO 的框架？**
A：作者暗示將 PANDO 擴展至非平穩任務分佈與跨網站的技能遷移，是極具潛力的下一步，這將使共享根系能夠在多樣化的網頁生態中通用。未來研究也可探索與先進的 GUI 動作落地視覺語言模型或強化學習骨幹網路進行更深度的整合，以在維持效率的前提下進一步提升單次推展的準確率上限。最後，軌跡層級效率指標的提出，暗示了一個朝向標準化效率基準測試的研究議程：未來的代理不僅應依據完成任務的能力被評估，也應依據整個互動軌跡中所產生的可見與隱藏成本來衡量。

## 實務應用指南

### 適用場景

**1. 跨系統企業流程自動化**
適用於需要在多個網頁應用程式間執行重複性、多步驟操作的場景，例如人力資源系統的新人到職設定、財務系統的請款單據核銷，或供應鏈管理平台的庫存調撥。PANDO 的結構化技能庫能將這些跨頁面操作流程沉澱為可重用的規則與例行程序，避免代理在每次執行時重新探索頁面邏輯，顯著降低邊際 Token 成本。

**2. 電商營運與競品監控**
適用於電商賣家或品牌營運團隊，需要定期登入後台更新商品資訊、調整價格、下載報表，或巡覽競品賣場進行價格與庫存監控。透過線上技能蒸餾，代理能在持續執行中學習各平台的頁面結構變化，並以視覺壓縮與快取感知提示減少截圖處理與互動歷史所帶來的推理負擔。

**3. 金融服務與合規申報**
適用於銀行、保險或證券業務中，需要操作網頁版核心系統或監管申報平台的場景，例如信貸資料查核、KYC 表單填寫或定期法規申報。此類環境通常不允許評估前發現預算（pre-evaluation discovery budget）或多次推展搜尋（rollout search），PANDO 的單次推展設計與進度反思機制，能在無預先離線探索的前提下，確保高風險操作的正確性與軌跡層級效率。

**4. 客戶服務後台輔助**
適用於客服人員使用的 SaaS 工具鏈（如 CRM、工單系統、知識庫），代理可協助自動查詢客戶歷程、更新工單狀態或跨系統同步備註。分層路由能依據任務類型快速匹配已學會的技能，減少規劃器與反思器反覆呼叫造成的延遲，適合對回應時間敏感的生產環境。

**5. 學術與公開資料彙整**
適用於研究助理或資料團隊需要從多個學術資料庫、政府公開平台或專業期刊網站檢索並下載資料的場景。代理在處理大量結構相似的查詢任務時，技能庫會持續累積檢索策略與表單填寫模式，透過提示快取利用率（Prompt Cache Utilization）的提升，讓後續同類任務的推理軌跡更短、費用更低。

### 實作前置條件

**資料準備**
- 種子軌跡資料：至少 50–100 條涵蓋目標網域的截圖—動作配對（screenshot-action pairs），用於初始化技能庫的冷啟動。
- 任務定義檔：包含目標描述、成功條件與動作空間（如 DOM-based 點擊或座標式操作）的結構化規格。
- 頁面結構中繼資料：目標網站的常見互動元素類型、導航邏輯與錯誤狀態截圖，以輔助動作落地（grounding）。

**運算資源**
- 視覺語言模型（VLM）推理端點：建議配置支援多模態輸入的模型服務（如 Qwen2.5-VL、UI-TARS 等級），並搭配 vLLM 或 PromptCache 等服務層級加速工具。
- 技能庫儲存：需具備向量資料庫或結構化快取（如 Redis、PostgreSQL + pgvector），用於儲存與檢索規則、例行程序及其置信度分數。
- 運算節點：單次推展雖無需 best-of-N 的多軌跡平行運算，但進度反思與線上技能蒸餾會增加每步驟的推論時計算，建議預留 20–30% 的 GPU 記憶體緩衝。

**技術能力**
- 具備網頁自動化框架（Playwright、Selenium 或 Browser Use）的部署與除錯經驗。
- 熟悉提示工程與多模態模型呼叫鏈設計，能理解快取感知提示的區塊切分原則。
- 基礎的強化學習或蒸餾概念，以便調整基於置信度的技能降級與極性對合併（polarity-pair merging）閾值。

### 實作步驟建議

**步驟一：建構基礎單次推展代理**
先以現成的 VLM 骨幹與網頁自動化工具建立最小可行代理，確保其具備「觀察截圖 → 產生動作 → 執行」的單步迴圈。此階段不引入技能庫，重點在確認動作落地穩定度與終端成功率（success rate）基線。

**步驟二：設計結構化技能庫 Schema**
定義技能庫的三層結構：規則（Rules，用於攔截已知錯誤）、參數化例行程序（Routines，多步驟子目標序列）與元資料（置信度、適用網域、視覺特徵）。建議採用 JSON Schema 或圖資料庫，以便後續進行階層式路由。

**步驟三：部署線上蒸餾與進度反思模組**
在代理執行任務流時，嵌入 Reflector 模組於關鍵檢查點（如頁面跳轉後、表單提交前）。當軌跡成功時，Learning Module 將其蒸餾為技能；當偵測到重複動作迴圈或停滯時，觸發規則學習。此階段需設定技能准入閾值，避免過度擬合單一噪聲軌跡。

**步驟四：實作分層路由與快取感知提示**
依據任務類型與當前頁面狀態，建立「網域 → 任務 → 技能」的三層路由索引。提示模板應區分靜態上下文（可快取的技能描述、互動歷史摘要）與動態上下文（當前截圖、即時變數），以最大化提示快取利用率。

**步驟五：引入視覺壓縮與置信度降級機制**
對截圖進行關鍵區域裁切或解析度調降，僅保留與技能相關的互動元素；同時建立置信度衰減函數，當某技能連續未被命中或觸發失敗時，自動執行基於置信度的技能降級，防止技能庫膨脹。

**步驟六：建立效率監控儀表板**
除了追蹤終端成功與 Token 總量，必須並列監控動作重複率（Action Repetition Rate）、步驟開銷比率（Step Overhead Ratio）與提示快取利用率。這三項軌跡層級效率指標能提前暴露機械性低效，而非僅在任務失敗後才發現問題。

**步驟七：漸進式上線與持續迭代**
先以 100–300 條任務進行內部燒機，觀察技能庫成長曲線與邊際 Token 成本是否如預期下降。確認極性對合併能有效整合相似技能後，再擴展至完整任務流。生產環境中應保留人工審核閘道，用於高風險技能的核准與合規檢查。

### 潛在風險與注意事項

**技能庫膨脹與維護債務**
隨著任務流持續輸入，技能庫可能累積大量重複或過時的規則，導致檢索延遲上升。建議嚴格執行置信度降級與週期性合併，並設定技能數量上限或 LRU（Least Recently Used）汰換策略，避免查詢成本侵蝕 Token 節省效益。

**視覺壓縮過度導致動作落地失敗**
過度裁切截圖或降低解析度可能使模型遺失關鍵視覺線索（如按鈕狀態變化、錯誤提示字樣），反而增加重試次數。應建立壓縮強度與接地成功率之間的 A/B 測試機制，並保留原始解析度作為降級後備方案。

**單次推展無法回復關鍵錯誤**
不同於 best-of-N 或驗證器遍歷（verifier passes）可透過多軌跡投票糾錯，PANDO 的單次推展架構一旦在關鍵步驟做出錯誤決策，缺乏平行備援軌跡。必須確保進度反思模組的覆蓋率足夠高，並在涉及交易、刪除或法規提交的操作前設置強制確認檢查點。

**非固定任務分布下的快取失效**
若實際任務分布與訓練時的固定排序差異過大（例如突然湧入大量未見過的網域），提示快取利用率可能急劇下降。建議在快取索引中加入網域指紋，並監控快取命中率的滑動平均值，作為擴充技能庫或觸發重新預熱的訊號。

**資料隱私與截圖合規**
截圖處理流程可能捕捉敏感個資或企業內部介面。所有視覺輸入應在傳輸至模型前進行本地端遮罩或去識別化，技能庫中也不得儲存含有機密資訊的原始截圖，僅保留結構化特徵與動作模式。

### 與其他技術的整合建議

**與現有 RPA 或瀏覽器自動化框架整合**
PANDO 可視為認知層的「大腦」，而實際的網頁操作仍建議交由成熟的低階框架（如 Playwright、Selenium 或企業級 RPA）執行。透過將 PANDO 產生的高階動作計畫（如「執行例行程序 #47：發票填寫」）轉譯為這些框架的 API 呼叫，可兼顧智慧決策與穩定的動作落地。

**與 LLM 服務加速層整合**
將 vLLM、PromptCache 或 RouteLLM 等推論加速工具部署於 VLM 服務層，可進一步放大 PANDO 的快取感知提示所帶來的效益。特別是 PromptCache 與 PANDO 的靜態技能描述區塊高度契合，能將重複出現的互動歷史與規則上下文轉化為實際的吞吐量提升。

**與向量檢索與 RAG 系統整合**
技能庫的檢索本質上是一種專業領域的 RAG（Retrieval-Augmented Generation）。可將技能庫接入現有的企業向量資料庫（如 Pinecone、Weaviate 或 Milvus），並利用現有的重排序（reranking）與嵌入模型管線來強化分層路由的召回品質，無需從頭建構檢索基礎設施。

**與可觀測性平台整合**
將動作重複率、步驟開銷比率與提示快取利用率等指標匯入既有的可觀測性工具（如 Langfuse、LangSmith 或 Prometheus/Grafana），建立代理專屬的 SLO（Service Level Objective）儀表板。當軌跡層級效率指標異常時，可自動觸發告警並將相關截圖與技能庫狀態快照送至人工審核佇列。

**與模型級聯或專家模型堆疊整合**
雖然 PANDO 旨在減少對專家模型堆疊（specialist model stacks）的依賴，但在面對極端複雜或高風險任務時，仍可將 PANDO 作為第一級路由（first-stage router）。當分層路由的置信度低於閾值時，再將任務降級或上送至專門的驗證器或更大的推理模型，形成 FrugalGPT 式的級聯架構，而非全有或全無的替換。

### 給不同背景讀者的閱讀建議

**給初學者**
本文的核心概念可以類比為「讓 AI 代理像資深員工一樣寫 SOP」：一開始代理需要逐步摸索網頁操作，但隨著經驗累積，它會把常見錯誤整理成規則、把重複流程整理成例行程序，以後執行就越來越快、越來越省。建議先從「適用場景」與「實作步驟建議」讀起，理解 PANDO 如何透過記憶與反思讓代理越用越便宜，再回頭對照論文中的 Token 經濟與效率指標，建立成本意識。

**給 AI 工程師**
重點關注結構化技能庫的 Schema 設計、分層路由的實作細節，以及快取感知提示的區塊切分策略。論文中的 300 任務消融實驗特別值得細讀：規則與例行程序貢獻了大部分的成功率提升，而路由、視覺壓縮與快取感知提示則負責將增大的技能庫轉化為更低的邊際 Token 負載。建議在實作時優先驗證技能庫的檢索延遲與快取命中率，這兩項是生產環境能否實現 58% Token 降幅的關鍵。

**給研究人員**
本文的貢獻不僅在於 VisualWebArena 上的成功率提升，更在於提出了「軌跡層級效率」的評估維度與 Token 經濟學框架。建議深入分析單次推展線上技能蒸餾與離線技能發現、推展搜尋之間的理論權衡，特別是 PANDO 如何在無評估前發現預算的前提下，達到比 SGV 與 WALT 更高的成功率。此外，三項軌跡層級效率指標（動作重複率、步驟開銷比率、提示快取利用率）可作為未來電腦使用代理研究的標準化評估工具。

**給產品經理**
請將閱讀重心放在「成本結構的翻轉」：傳統多模態網頁代理的邏輯是「花更多 Token 買更高成功率」，而 PANDO 證明了「累積經驗可以同時提升成功率並降低單次成本」。論文中的 58.3% 成功率與 58% Token 減少量是與業務方溝通時的關鍵數據，而無評估前發現預算的特性意味著導入時無需預先投入大規模離線探索成本。建議將「邊際 Token 成本隨任務量遞減」作為核心商業價值主張，並以軌跡層級效率指標作為與工程團隊協定的產品健康度儀表板。
