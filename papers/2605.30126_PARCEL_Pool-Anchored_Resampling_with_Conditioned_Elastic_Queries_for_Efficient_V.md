## 摘要翻譯

大型視覺語言模型（Large Vision-Language Models, LVLMs）將視覺輸入映射為密集的視覺令牌（visual tokens）序列，為推論帶來二次計算瓶頸（quadratic computational bottleneck）。彈性視覺令牌壓縮（Elastic visual-token compression）透過訓練單一模型，使其能在多種視覺令牌預算（visual-token budgets）下運作，以解決此問題。然而，現有方法在高度壓縮下仍顯乏力。純空間壓縮（Spatial-only compression），如巢狀池化（nested pooling），形同不完美的低通濾波器（low-pass filter），引發頻譜混疊（spectral aliasing），導致細粒度細節（fine-grained detail）模糊。純查詢壓縮（Query-only compression），如巢狀查詢重採樣（nested query resampling），以非局部摘要（non-local summaries）取代明確的網格對齊令牌，大幅損害空間定位能力（spatial grounding）。為了解決此表徵衝突，我們提出 PARCEL（Pool-Anchored Resampling with Conditioned Elastic Queries for Efficient Vision-Language Understanding），一種能動態劃分特徵提取任務的視覺令牌化架構（visual tokenization architecture）。PARCEL 建立空間池化令牌（spatial pool tokens）作為低頻佈局錨點（low-frequency layout anchors），並透過池化條件化查詢重採樣（Pool-Conditioned Query Resampling），使彈性查詢令牌（elastic query tokens）以這些錨點為條件。這促使查詢令牌專注於互補視覺特徵（complementary visual features），而非冗餘空間對應（redundant spatial mapping）。橫跨 27 項基準測試的廣泛評估顯示，PARCEL 推進了效能與效率的帕累托前沿（performance-efficiency Pareto frontier），在各種視覺令牌預算下始終優於現有的 Matryoshka 基線（Matryoshka baselines），同時維持「訓練一次，隨處部署（train once, deploy anywhere）」的範式。

### 核心貢獻（3～5點）
- 診斷現有彈性視覺令牌壓縮方法的表徵衝突：純空間壓縮（如巢狀池化）形同不完美低通濾波器，引發頻譜混疊並遮蔽細粒度細節；純查詢壓縮（如巢狀查詢重採樣）以非局部摘要取代網格對齊令牌，嚴重損害空間定位能力。
- 提出 PARCEL 視覺令牌化架構，透過「池化條件化查詢重採樣」動態劃分特徵提取任務：以空間池化令牌作為低頻佈局錨點，並使彈性查詢令牌以這些錨點為條件，從而專注於互補視覺特徵而非冗餘空間對應。
- 在橫跨 27 項基準測試的廣泛評估中，推進了效能與效率的帕累托前沿，於各種視覺令牌預算下均優於 Matryoshka 基線。
- 在實現高效彈性推論的同時，完整保留「訓練一次，隨處部署」之部署範式。

### 適合對象
從事多模態學習、大型視覺語言模型系統最佳化，以及專注於視覺令牌壓縮、彈性推論與計算效率之研究者與工程師。特別適合需要在延遲敏感場景中部署 LVLMs，並希望以單一模型彈性適應不同視覺令牌預算與運作點之開發者。

## 深度分析

#### 方法論解析

大型視覺語言模型（Large Vision-Language Models, LVLMs）在處理影像或影片時，通常將視覺輸入映射為密集的視覺令牌（visual tokens）序列，導致 Transformer 的自注意力（self-attention）機制產生嚴重的二次計算瓶頸（quadratic computational bottleneck）。為緩解此問題，靜態視覺令牌壓縮（static visual token compression）技術——如令牌丟棄（dropping）、合併（merging）與投影（projection）——雖能降低推論成本（inference costs），卻只能產生固定長度視覺表示（fixed-length visual representations），迫使實務者在部署前選定單一運作點（operating point），無法兼顧細粒度視覺細節（fine-grained visual detail）與延遲敏感（latency-sensitive）場景。彈性推論（elastic inference）或「訓練一次，隨處部署」（train once, deploy anywhere）因此成為關鍵目標。

現有的 Matryoshka 風格表示學習（Matryoshka-style representation learning）基線主要分為兩類，卻各自存在表示瓶頸：
1. **純空間壓縮（spatial-only compression）**：以 M3（Matryoshka Multimodal Models）為代表，透過巢狀池化（nested pooling）進行連續多尺度空間平均池化。本文作者指出，這種剛性空間下採樣本質上等同於不完美的低通濾波器（low-pass filter），會引入頻譜混疊（spectral aliasing），模糊高頻語義細節，對圖表推理與文字導向的視覺問答（visual question answering）等解析度敏感任務傷害極大。
2. **純查詢壓縮（query-only compression）**：以 MQT（Matryoshka Query Transformer）為代表，利用查詢 Transformer（query transformer）搭配巢狀查詢重採樣（nested query resampling）與巢狀丟棄（nested dropout）產生非局部摘要（non-local summaries）。然而，這種方法以隱式的學習摘要取代顯式的網格對齊令牌，大幅削弱了模型的空間定位能力（spatial grounding）與密集定位表現。

為解決上述表示衝突，PARCEL（Pool-Anchored Resampling with Conditioned Elastic Queries）提出一種混合式視覺令牌化架構（visual tokenization architecture），核心概念是**動態分工（dynamic division of labor）**：讓不同類型的令牌分別負責互補視覺特徵（complementary visual features）的不同頻段，避免冗餘空間對應（redundant spatial mapping）。

具體而言，PARCEL 架構包含三大機制：

**（一）空間池化令牌（spatial pool tokens）作為低頻佈局錨點（low-frequency layout anchors）**
PARCEL 從 SigLIP 視覺編碼器（SigLIP Visual Encoder）提取特徵後，透過預算感知平均池化（budget-aware average pooling，如 2×2、4×4）產生空間錨點。這些池化令牌（pool tokens）以顯式的二維幾何結構保留場景的低頻佈局資訊，提供穩定的幾何框架。

**（二）池化條件化查詢重採樣（Pool-Conditioned Query Resampling, PCQR）**
PARCEL 引入一組可學習的彈性查詢令牌（elastic query tokens），作為「語義探索者」（semantic explorers）。這些查詢令牌並非獨立運作，而是透過 PCQR 區塊顯式地條件化於空間錨點之上。根據圖示，PCQR 包含池化自注意力（Pool Self-Attention）機制，使查詢令牌先與錨點池化令牌交互，再透過交叉注意力（Cross-Attention）從 ViT 特徵中探索互補的高頻視覺訊號。這種條件化設計確保查詢令牌專注於恢復被池化丟棄的細節，而非重複學習空間佈局。

**（三）預算感知分段路由（Budget-Aware Piecewise Routing）**
PARCEL 在訓練時採用 Matryoshka 式的多預算學習，透過分段路由策略同時優化不同視覺令牌預算（visual-token budgets）——如低（Low）、中（Medium）、高（High）——的輸出。這使得單一模型在推論階段可依據可用運算資源與延遲目標，動態選擇池化與查詢令牌的組合比例，實現真正的彈性視覺令牌壓縮（elastic visual-token compression）。

整體而言，PARCEL 的創新在於將「剛性幾何錨定」與「彈性語義探索」解耦：池化令牌負責低頻、大範圍的空間結構；查詢令牌則在錨點引導下專責高頻、區域性的語義細節。這種分工顯著緩解了 M3 的頻譜混疊與 MQT 的空間迷失問題。

#### 實驗數據解讀

本文在 27 個基準測試（benchmarks）上進行廣泛評估，並使用 3 個不同隨機種子（seeds）以確保統計穩健性。實驗設計圍繞兩大核心指標：**下游任務效能保留率（retention）**與**推論效率（efficiency）**。

**效能保留率（Retention）分析**
圖 1 左側顯示相對於無壓縮基線 Vanilla PG2 的平均保留率（mean retention）。結果顯示，PARCEL 在所有視覺令牌預算（visual-token budgets）下均穩定優於 M3 與 MQT 兩大 Matryoshka 基線（Matryoshka baselines）：
- 在極低預算（如 16 個視覺令牌）下，PARCEL 的保留率顯著高於 MQT 與 M3，顯示其在激進壓縮（aggressive compression）下仍能維持較完整的語義與空間資訊。
- 隨著預算增加至 64 與 256 個令牌，PARCEL 持續保持領先，證明其分工架構在不同壓縮率下皆具備優越的效能-效率權衡（performance-efficiency trade-off）。

**效率與成本分析**
圖 1 右側量化理論預填充浮點運算（prefill FLOPs）與語言模型 KV 快取（KV-cache）成本：
- **影像輸入**：16 令牌僅需 1.0T FLOPs 與 15MB KV 快取；256 令牌則為 2.0T FLOPs 與 39MB。相較未壓縮的 Vanilla PG2，低預算可大幅削減運算與記憶體開銷。
- **影片輸入（16 幀）**：16 令牌需 4.9T FLOPs 與 33MB KV 快取；256 令牌則達 24.3T FLOPs 與 423MB。這顯示 PARCEL 的彈性壓縮對於高維度輸入（如影片理解，video understanding）尤具價值，因為序列長度（sequence length）的二次增長在此更為致命。

值得注意的是，作者指出在相同預算下，各方法的 KV 快取成本相同，且 FLOPs 差異主要來自連接器開銷（connector overhead），佔整體比例極小，因為共享的 ViT 與 LLM 項主導了總運算量。這意味著 PARCEL 的效能提升並非來自於「取巧地減少連接器計算」，而是來自於更優質的視覺表示（visual representations）。

**帕累托前沿（Pareto Frontier）意義**
綜合來看，PARCEL 推進了效能-效率帕累托前沿（performance-efficiency Pareto frontier）。這表示在給定運算預算下，PARCEL 達到了現有方法無法企及的下游任務效能（downstream performance）；反之，在達到相同效能目標時，PARCEL 所需的視覺令牌預算更低。這對於需要在邊緣裝置上執行多模態任務（multimodal tasks）的實務應用至關重要。

#### 與現有研究的比較

PARCEL 在彈性視覺令牌壓縮（elastic visual-token compression）的技術光譜上，佔據了一個獨特的混合式（hybrid）位置，明確針對現有兩大典範的結構性缺陷進行補強。

**相較於 M3（巢狀池化典範）**
M3 透過連續多尺度空間平均池化建立巢狀令牌結構，優勢在於保留了顯式的網格對齊關係，具備良好的幾何穩定性。然而，正如本文的光譜分析（spectral analysis）所示，純空間下採樣本質上是一種低通濾波，在高壓縮率下會產生頻譜混疊（spectral aliasing），導致細粒度細節（fine-grained detail）——特別是文字、圖表與小物體——嚴重失真。PARCEL 並未捨棄池化，而是將其「降級」為專職的低頻佈局錨點（low-frequency layout anchors），並透過 PCQR 引入額外的語義探索者查詢來恢復被池化過濾掉的高頻互補訊號。這使得 PARCEL 在繼承 M3 幾何穩定性的同時，規避了其頻譜瓶頸。

**相較於 MQT（巢狀查詢典範）**
MQT 利用查詢 Transformer 與巢狀丟棄（nested dropout）實現彈性，其查詢機制具備強大的高頻表達潛力。但問題在於，這些查詢令牌形成的是非局部摘要（non-local summaries），缺乏顯式的空間歸屬感，導致模型在需要密集空間理解（dense spatial understanding）與空間定位能力（spatial grounding）的任務上大幅退化。PARCEL 的關鍵改良在於「條件化」：查詢令牌並非自由探索，而是被顯式的空間錨點所錨定（anchor）與引導。這種池化感知（pool-aware）的設計強制查詢令牌維持與幾何結構的對應關係，從而顯著緩解 MQT 的空間迷失問題。

**整體定位與貢獻**
PARCEL 可被視為一種**表示分工（division of labor）**架構：剛性空間結構負責「在哪裡」（where），彈性語義查詢負責「是什麼」（what）。這種解耦策略比單純的純空間或純查詢方法更具表達效率，因為它避免了兩種機制學習冗餘空間對應（redundant spatial mapping）。

**潛在限制**
儘管實驗結果強勁，本文仍存在若干可進一步探討的限制：
1. **連接器開銷（connector overhead）**：雖然作者指出 PCQR 的額外 FLOPs 佔比極小，但在極低功耗或極高吞吐量場景下，交叉注意力（cross-attention）與額外的自注意力層仍可能構成延遲瓶頸。
2. **視覺編碼器依賴**：PARCEL 目前建構於 SigLIP 視覺編碼器之上，其空間錨點的品質高度依賴編碼器本身的特徵解析度。若套用至解析度較低或預訓練目標不同的編碼器（如早期 CLIP 變體），低頻錨點的品質可能下降，進而影響查詢條件化的效果。
3. **語言解碼器單一性**：實驗僅基於 Gemma2 語言解碼器（Gemma2 Language Decoder）進行驗證。雖然結果令人鼓舞，但 PARCEL 的通用性仍需在更多元的大型語言模型（LLM）骨幹——如 Llama、Qwen 或 Mistral——上進行交叉驗證，以確認其視覺連接器設計與不同 LLM 的相容性。
4. **離散預算層級**：目前的預算感知路由似乎仍基於離散的預算層級（如 16、64、256）。雖然這已優於固定長度表示，但距離真正連續的「任意預算」彈性仍有距離。

#### 未來研究方向

PARCEL 所確立的「錨點-探索者」分工範式，為彈性視覺語言理解開啟了多條值得深入的研究路徑：

**1. 連續彈性與輸入自適應預算分配**
目前的 PARCEL 似乎仍針對離散的視覺令牌預算（visual-token budgets）進行優化。未來可探索**連續彈性（continuous elasticity）**，讓模型根據輸入內容的複雜度動態決定池化與查詢令牌的比例。例如，對於簡單的自然影像可分配較多池化錨點與較少查詢；對於密集的圖表或文件影像則自動增加語義探索者查詢的數量，實現輸入自適應（input-adaptive）的資源分配。

**2. 長影片與時間一致性擴展**
PARCEL 的空間錨點機制非常適合擴展至影片理解（video understanding）領域。未來研究可引入**時間池化錨點（temporal pool anchors）**，在時間維度上建立低頻動作佈局，並讓查詢令牌探索跨幀的細微時空變化。這將有助於在極長影片（長上下文）場景下，維持 KV 快取（KV-cache）的可管理性，同時保留關鍵事件的精確時間定位能力。

**3. 與靜態壓縮技術的聯合最佳化**
PARCEL 本質上是一種動態、可學習的連接器設計。未來可將其與靜態視覺令牌壓縮（static visual token compression）技術——如基於相似度的令牌合併（token merging）或輕量化投影（projection）——進行級聯。例如，先以靜態方法壓縮 ViT 輸出，再輸入至 PARCEL 的 PCQR 區塊，進一步挑戰個位數視覺令牌（<10 tokens）的極限壓縮率。

**4. 跨視覺編碼器與跨語言模型的通用性驗證**
目前 PARCEL 與 SigLIP 及 Gemma2 緊密整合。未來應系統性地驗證其在其他視覺骨幹（如 DINOv2、SAM、CLIP）與其他語言解碼器（如 Llama-3、Qwen2-VL、Mistral）上的遷移能力。特別是探討不同預訓練目標（對比式 vs. 重建式）產生的視覺特徵，對於低頻佈局錨點（low-frequency layout anchors）品質的影響。

**5. 頻域顯式分解與可解釋性**
PARCEL 目前在空間域隱式地實現高低頻分工。未來可引入顯式的頻域處理，例如可學習的小波轉換（learnable wavelet transform）或傅立葉特徵分解，讓錨點與查詢分別在頻域中承擔更明確的角色。此外，透過視覺化「語義探索者」查詢令牌的注意力圖（attention maps），可進一步驗證其是否確實專注於高頻細節（如文字筆畫、小物體邊界），從提升模型可解釋性（interpretability）並指導架構改良。

**6. 多模態對齊與指令微調的聯合設計**
PARCEL 的彈性推論（elastic inference）特性為指令微調（instruction tuning）帶來新課題：如何在多預算（multi-budget）設定下進行對齊（alignment），使語言解碼器在不同令牌預算下都能穩定理解視覺指令？設計預算感知（budget-aware）的指令微調策略，將是實現真正「隨處部署」的關鍵下一步。

## 論文問答

**Q1：PARCEL 旨在解決大型視覺語言模型中的哪個核心計算挑戰？**
A：大型視覺語言模型在處理影像或影片時，通常會將視覺輸入編碼為數百甚至數千個視覺令牌，導致 Transformer 自注意力機制的序列長度急遽增加，形成二次計算瓶頸。這種輸入端的計算負擔不僅大幅提高推論成本與記憶體消耗，也使得模型難以部署在資源受限或延遲敏感的裝置上。PARCEL 正是為了解決此問題，透過彈性視覺令牌壓縮，在維持下游任務效能的同時，顯著降低推論過程中的計算與 KV 快取開銷。

**Q2：為何現有的 M3 與 MQT 等方法在激進的視覺令牌壓縮下會失效？**
A：現有的 Matryoshka 基線方法在高度壓縮的視覺令牌預算下會產生對立的表徵瓶頸：M3 採用純空間壓縮，其巢狀池化行為如同不完美的低通濾波器，會引發頻譜混疊，進而模糊圖表推理與文字導向視覺問答所需的高頻語義細節。相對地，MQT 採用純查詢壓縮，以非局部摘要取代明確的網格對齊令牌，雖然保留了語義資訊，卻大幅損害了密集空間定位能力。這兩種極端分別在空間結構與細粒度語義上出現缺陷，使得現有方法在激進壓縮下難以兼顧兩者。

**Q3：彈性視覺令牌壓縮對於實務部署為何如此重要？**
A：彈性視覺令牌壓縮之所以對實務部署至關重要，是因為傳統靜態壓縮技術只能產生固定長度的視覺表示，迫使開發者在部署前選擇單一運作點，導致效率與效能之間出現嚴格的權衡。在實際應用中，不同裝置的可用資源與延遲目標差異極大，從行動裝置到雲端伺服器，其能負擔的視覺令牌預算各不相同。彈性推論的「訓練一次，隨處部署」範式讓單一模型能依據當下環境動態調整預算，避免永久犧牲細粒度視覺細節或承擔過高的計算成本。

**Q4：PARCEL 的核心方法是什麼，它如何動態分工特徵提取的勞動？**
A：PARCEL 的核心機制是池化條件化查詢重採樣（PCQR），它透過動態分工的方式重新設計視覺令牌化架構。具體而言，PARCEL 首先利用預算感知的平均池化建立空間池化令牌，作為低頻佈局錨點以穩定捕捉整體幾何結構；接著，它引入一組巢狀丟棄的彈性查詢令牌，並將這些查詢顯式地條件化於空間錨點之上。這種設計讓查詢令牌專注於探索與池化互補的高頻視覺特徵，而非重複學習冗餘的空間對應關係。

**Q5：Pool-Conditioned Query Resampling（PCQR）如何解決空間壓縮與查詢壓縮之間的表徵衝突？**
A：PCQR 解決空間壓縮與查詢壓縮之間衝突的關鍵，在於它並非讓單一機制獨自承擔所有頻率的資訊，而是透過條件化連結將兩者的優勢結合。空間池化令牌提供了明確且穩定的二維幾何錨點，確保模型不會失去低頻的佈局資訊；而池化感知的語義探索查詢則在這些錨點的引導下，專門恢復標準池化所丟棄的互補視覺訊號。如此一來，PARCEL 同時具備了 M3 的幾何穩定性與 MQT 的高頻表達力，從而在激進壓縮下仍能保持均衡的表徵品質。

**Q6：PARCEL 為何選擇以平均池化建立空間錨點，並以跨注意力機制實現查詢令牌？**
A：PARCEL 選擇平均池化作為空間錨點，是因為這種操作能自然地充當低通濾波器，穩定地提取低頻的整體佈局與幾何結構，而不會引入額外的學習參數。相對地，查詢令牌採用跨注意力機制與視覺編碼器互動，使模型能夠根據池化錨點的條件，動態地從全域特徵圖中抽取非局部的高頻語義資訊。這種架構上的明確分工確保了每個元件都專精於其最擅長的頻段處理，避免了單一機制試圖同時涵蓋所有頻率而導致的表徵崩潰。

**Q7：PARCEL 在哪些基準測試上進行評估，涵蓋了哪些任務類型？**
A：PARCEL 在涵蓋影像與影片的 27 項基準測試上進行了廣泛評估，並使用 3 個不同隨機種子以確保結果的穩健性。這些測試橫跨了視覺問答、圖表推理、文字導向視覺問答、密集識別以及影片理解等多模態任務，能夠全面檢視模型在不同視覺令牌預算下的保留能力。實驗主要與現有的 Matryoshka 基線方法 M3 與 MQT 進行對比，以驗證 PARCEL 在效能與效率權衡上的優越性。

**Q8：PARCEL 在效能與效率權衡上的主要量化發現為何？**
A：實驗結果顯示，PARCEL 顯著推進了效能與效率的帕累托前沿，在 16、64、256 等匹配的視覺令牌預算下，其平均保留率均一致優於 M3 與 MQT。相較於未壓縮的 Vanilla PG2，PARCEL 在較低預算下能有效降低預填充浮點運算量與 LLM KV 快取成本，例如 16 個視覺令牌時 KV 快取僅需 15MB，遠低於完整模型的開銷。這證明 PARCEL 不僅在極端壓縮下保留了更多細粒度細節，也在計算資源與記憶體佔用之間取得了更佳的整體平衡。

**Q9：論文中對頻譜瓶頸的分析揭示了哪些關於 M3 與 MQT 的關鍵現象？**
A：論文中對頻譜瓶頸的分析以實證方式揭示了 M3 與 MQT 的結構性缺陷：M3 的剛性空間平均池化呈現出類似頻譜混疊的訊號特徵，導致高頻語義細節被抹除；而 MQT 的非局部查詢重採樣雖然保留了較多語義，卻在壓縮下大幅削弱了密集空間理解能力。透過對比實驗，PARCEL 的混合設計成功迴避了這兩種極端，證明動態分工能同時維持低頻佈局錨點的穩定性與高頻查詢的探索能力。

**Q10：PARCEL 的彈性推論在哪些實際部署場景中最具優勢？**
A：PARCEL 的彈性推論特性特別適合部署於計算資源高度異質的環境，例如行動裝置、邊緣運算節點以及需要即時回應的互動式應用。當輸入領域從靜態影像擴展到多幀影片時，視覺令牌數量與 KV 快取需求會急遽上升，PARCEL 能依據當下裝置的記憶體與延遲限制動態調整預算。這種隨處部署的彈性讓產品開發者無需為不同硬體規格維護多個模型版本，大幅簡化了多平台部署流程。

**Q11：對於產品團隊而言，PARCEL 如何實踐「訓練一次，隨處部署」的範式？**
A：對於產品團隊而言，PARCEL 的「訓練一次，隨處部署」範式意味著只需訓練單一檢查點，即可透過預算感知分段路由策略支援多種視覺令牌預算。這消除了傳統上必須針對低功耗裝置與高階伺服器分別訓練與微調不同模型的營運負擔。此外，由於 PARCEL 在連接器層的額外開銷很小，產品在切換預算時幾乎不會影響整體推論延遲，使得使用者體驗能夠根據網路或硬體狀態無縫調整。

**Q12：PARCEL 可能對未來高效多模態架構的研究產生什麼影響？**
A：PARCEL 為高效多模態架構的研究開闢了新的方向，證明透過動態分工結合互補機制，可以在不重新訓練模型的情況下實現細粒度的效能與效率權衡。這種混合式視覺連接器設計可能啟發後續研究將類似的條件化重採樣策略應用於其他模態，例如音訊或三維點雲資料。長遠來看，PARCEL 確立了彈性表示學習在大型視覺語言模型中的實用價值，推動學術界與產業界更積極地探索非單一化、可適應的模型架構。

**Q13：PARCEL 的混合設計存在哪些已知的根本限制？**
A：儘管 PARCEL 改善了連接器層的壓縮效率，它仍繼承了 Transformer 骨幹網路的基本限制：視覺編碼器與語言解碼器本身的自注意力成本仍隨序列長度呈二次增長，因此整體瓶頸僅被緩解而非根除。此外，池化與查詢之間的固定分工假設，在面對極度異質且同時包含全域結構與像素級細節的複雜場景時，可能無法達到最理想的頻率分配。最後，預算感知路由雖然開銷不大，但仍需在部署階段額外管理不同預算路徑的切換邏輯。

**Q14：在什麼條件下，PARCEL 相較於未壓縮基線仍可能出現效能掙扎或失敗？**
A：在極端壓縮條件下，例如視覺令牌預算低於 16 個令牌時，PARCEL 的錨點與查詢分工可能過於粗糙，導致無法保留足夠的細節來執行需要精細解析度的任務。相較於未壓縮的 Vanilla PG2，涉及像素級精確空間定位或微小文字辨識的下游任務，仍可能因為高頻資訊的損失而出現效能下降。此外，當影像同時包含複雜文字佈局與密集物件時，低頻佈局錨點的假設可能受到挑戰，使得查詢難以有效恢復所有互補特徵。

**Q15：基於 PARCEL，有哪些值得探索的未來研究方向？**
A：未來研究可從多個方向延伸 PARCEL 的框架，例如將池化條件化查詢重採樣機制擴展至音訊、三維點雲或其他新興模態，以建立統一的多模態彈性壓縮架構。另一個有潛力的方向是設計逐輸入自適應的路由策略，讓模型能根據單張影像或影片的內容複雜度動態選擇最佳視覺令牌預算，而非僅依裝置條件固定分配。此外，將 PARCEL 與語言解碼器端的動態推論技術（如早期退出或令牌合併）結合，有望實現從視覺編碼到語言生成端到端的全面效率最佳化。

## 實務應用指南

### 適用場景

1. **邊緣裝置多模態助理**  
   智慧型手機、AR 眼鏡或 IoT 相機需在電量與網路頻寬受限下執行視覺問答（Visual Question Answering）。PARCEL 的彈性視覺令牌預算（如 16 tokens）可於低功耗模式運作，並在裝置插電或連接 Wi-Fi 時無縫升級至 256 tokens 以獲取細粒度視覺細節，實現「同一模型、分級服務」。

2. **即時影片監控與事件偵測**  
   16 幀影片輸入在未壓縮下會產生龐大的 KV 快取（423 MB）與預填充浮點運算（24.3T FLOPs）。PARCEL 可在保全人員需要快速掃描時以 64 tokens 低延遲推論，僅於偵測到異常事件時切換至高預算模式進行密集識別，顯著降低雲端推論成本。

3. **文件理解與圖表推理（Document Intelligence）**  
   發票、財報與學術圖表等任務對高頻資訊極度敏感。傳統巢狀池化（M3）的頻譜混疊會模糊小字與線條，而 PARCEL 的池化條件化查詢重採樣（PCQR）透過語義探索查詢令牌（Semantic Explorer Query Tokens）補捉被平均池化丟失的互補視覺特徵，特別適合文字密集的視覺語言理解。

4. **雲端多租戶推論服務（SaaS/API）**  
   面向開發者的多模態 API 需同時服務延遲敏感的聊天機器人與重視準確度的企業分析流程。PARCEL 的「訓練一次，隨處部署」特性允許營運團隊以單一模型權重支撐多種運作點，依客戶訂閱等級動態調整視覺令牌預算，簡化模型倉庫管理。

5. **自動駕駛與機器人視覺感知**  
   自駕系統需同時維持空間定位能力（如車道線、行人邊界框）與語義理解（如交通號誌狀態）。純查詢壓縮（MQT）會降解空間定位，而 PARCEL 的空間池化令牌（Spatial Pool Tokens）作為低頻佈局錨點，能保留幾何穩定性，適合需要精確空間對應的機器人導航場景。

### 實作前置條件

**資料需求**  
需準備大規模圖像–文本配對資料與指令調優（Instruction Tuning）資料集，涵蓋視覺問答、圖表推理、密集定位與一般常識問答。視覺編碼器建議採用 SigLIP 或相容之 Vision Transformer，語言解碼器建議採用 Gemma2 或類似架構，以確保與 PCQR Block 的維度對齊。

**運算需求**  
彈性視覺令牌壓縮需在單一訓練階段同時優化多個預算目標，建議具備 4–8 張 NVIDIA A100/H100（80 GB）進行分散式訓練。由於需維持多組 KV 快取配置與巢狀丟棄（Nested Dropout）的動態路由，記憶體頻寬與 GPU 顯存為主要瓶頸，需搭配梯度檢查點與 ZeRO 優化。

**技能需求**  
團隊需熟悉 PyTorch/JAX、Vision Transformer 的特徵圖操作、Cross-Attention 機制與 Matryoshka 表示學習。此外，需具備閱讀頻譜分析與低通濾波器相關論述的能力，以調校池化核大小與查詢令牌數量的比例；部署端則需熟悉推論框架（如 vLLM、TensorRT-LLM）的動態序列長度處理。

---

### 實作步驟建議

**步驟一：基礎模型選型與環境建置**  
選定 LVLM 骨幹（如 PaliGemma2），確認視覺編碼器輸出的空間解析度與連接器（Connector）投影維度。建立支援動態序列長度的訓練框架，並預留三種標準視覺令牌預算：16（低）、64（中）、256（高）。

**步驟二：連接器置換為 PARCEL 架構**  
將原有視覺連接器替換為 Pool-Conditioned Query Resampling（PCQR）Block。初始化兩組令牌：(1) 透過 2×2 / 4×4 預算感知平均池化產生的空間錨點池化令牌（Anchor Pool Tokens），負責低頻佈局；(2) 可學習的池化感知查詢令牌（Pool-Aware Query Tokens），負責探索互補高頻特徵。

**步驟三：彈性預訓練與預算感知路由**  
在單一訓練階段中，採用 Budget-Aware Piecewise Routing 隨機抽樣不同視覺令牌預算。對每個訓練樣本，依據抽樣預算決定池化層級與查詢令牌數量，使模型同時學習多尺度表示，避免傳統固定長度視覺表示的單一運作點限制。

**步驟四：多工指令微調**  
使用涵蓋 27 項基準的混合資料進行指令微調，特別加強圖表推理、文字導向視覺問答與空間定位任務。此階段應監控不同預算下的保留率（Retention），確保低預算模型不會在解析度敏感任務上出現嚴重頻譜混疊。

**步驟五：部署優化與動態切換**  
針對目標裝置建立預算查找表，將 16/64/256 tokens 對應至各自的 TFLOPs 與 KV 快取記憶體佔用。於推論伺服器實作動態路由閘道器，依據當前裝置剩餘記憶體、電量或使用者設定的延遲目標，自動選擇運作點。

**步驟六：帕累托前沿驗證與迭代**  
在保留率、TFLOPs、KV 快取成本三維指標上繪製帕累托前沿（Pareto Frontier）。若發現某預算區間效能低於 MQT 或 M3 基線，則調整池化令牌與查詢令牌的比例，或引入額外的連接器開銷剪枝。

### 潛在風險與注意事項

1. **頻譜混疊導致細節遺失**  
   若池化核設計過於激進（如單層 8×8 平均池化），即使搭配查詢令牌仍可能無法完全恢復被低通濾波器抹除的高頻資訊。建議保留多尺度巢狀池化結構，並在 OCR、數學圖表等任務上設置高頻細節的離線監控閘道。

2. **空間定位能力退化**  
   查詢令牌若未充分條件化於池化錨點，容易淪為非局部摘要（Non-local Summaries），重蹈 MQT 覆轍而降解空間定位能力。實作時應確保 Pool Self-Attention 與 ViT Cross-Attention 的梯度流暢通，避免查詢令牌忽略空間幾何線索。

3. **Matryoshka 訓練收斂不一致**  
   巢狀丟棄可能導致 16 tokens 與 256 tokens 兩種極端預算的收斂速度不同。建議採用預算感知學習率調整，或於訓練前期先以完整預算（256 tokens）暖機，再漸進引入低預算樣本。

4. **推論框架的動態序列支援限制**  
   現有推論引擎（如 vLLM、TensorRT-LLM）多針對固定視覺序列長度優化，PARCEL 的動態視覺令牌預算可能導致記憶體碎片化。需客製化前處理管線，或預先編譯數種固定形狀的子圖並於執行期切換。

5. **連接器開銷在極低預算下相對顯著**  
   當視覺令牌預算壓至 16 tokens 時，PCQR Block 的額外參數與計算在總成本中佔比會上升。可透過線性投影層的權重共享或對 PCQR 進行模型蒸餾來緩解。

### 與其他技術的整合建議

1. **推論引擎外掛化**  
   將 PARCEL 的動態路由邏輯封裝為 vLLM 或 Text Generation Inference（TGI）的自定義前處理外掛。於 API Gateway 層解析請求優先級，動態注入對應數量的視覺令牌，並利用連續批處理（Continuous Batching）將相同預算的請求分群以提升 GPU 利用率。

2. **與靜態壓縮技術疊加**  
   PARCEL 作為彈性骨幹，可於其上層進一步疊加令牌丟棄（Token Dropping）或令牌合併（Token Merging），處理極端低預算或突發流量場景。例如：先以 PARCEL 產生 64 tokens，再於語言解碼器前執行語義冗餘合併降至 32 tokens。

3. **多模態檢索增強生成（RAG）**  
   在文件智慧管線中，離線索引階段使用高視覺令牌預算（256 tokens）建立高密度向量資料庫以保留圖表細節；使用者查詢階段則依其裝置等級降級至 64 或 16 tokens，僅於檢索到高相關性文件時觸發高預算重排（Re-ranking）。

4. **硬體感知編譯與邊緣部署**  
   針對 Apple Neural Engine 或 Qualcomm NPU 等偏好靜態形狀的加速器，可預先編譯 16/64/256 三種預算子圖。執行期透過條件分支選擇對應子圖，避免動態形狀帶來的重新編譯延遲。

5. **叢集自動擴展與成本監控**  
   於 Kubernetes 叢集中整合 GPU KV 快取使用率與 P99 延遲監控，當叢集負載升高時自動將部分實例的視覺令牌預算從 256 降級至 64，以維持服務等級協議（SLA），實現成本與效能的即時帕累托權衡。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先將「視覺令牌」理解為圖片被切成的許多小方塊，PARCEL 的核心創新在於同時保留地圖式的網格摘要（空間池化錨點）與偵探式的細節探查（條件化查詢），讓 AI 看圖時既能掌握整體佈局又不漏掉小字或圖表細節。閱讀時可跳過頻譜分析的數學推導，專注於圖 2 的架構圖與圖 1 的效能–效率曲線，建立直觀認識。

**AI 工程師**  
請重點關注 Pool-Conditioned Query Resampling（PCQR）的實作細節，包括 Pool Self-Attention 與 Cross-Attention 的串接順序、巢狀丟棊（Nested Dropout）的訓練程式碼實作，以及如何在現有 LVLM 程式碼庫中替換連接器。建議直接參考論文的預算分段路由策略與 KV 快取計算公式，以評估導入後的記憶體與延遲收益。

**研究人員**  
請深入閱讀第三節的頻譜瓶頸分析，理解 M3 的低通濾波特性和 MQT 的非局部摘要如何導致互補的表示缺陷。PARCEL 的動態分工框架——以剛性空間錨點穩定幾何結構、以彈性查詢補捉互補語義——可延伸至其他模態（如音訊頻譜、3D 點雲）的彈性令牌化，值得作為未來混合架構的理論基礎。

**產品經理**  
請把握「訓練一次，隨處部署」的商業價值：無需為手機版、網頁版、企業 API 版維護多個模型，顯著降低模型倉庫與版本管理成本。評估時請對照圖 1 的 TFLOPs 與 KV 快取數據，將 16/64/256 三種預算對應到不同使用者分群（如付費高階用戶、免費輕量用戶、邊緣 IoT 裝置）的服務等級協議，設計分級定價策略。
