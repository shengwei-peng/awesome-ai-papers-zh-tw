## 摘要翻譯

稀疏檢索（Sparse retrieval）是現代搜尋系統的基礎，涵蓋網頁搜尋到檢索增強生成（Retrieval-augmented generation, RAG）等應用。現有研究提出學習式稀疏檢索（Learned Sparse Retrieval, LSR），以突破精確詞彙匹配（Exact lexical matching）的限制，朝向更豐富的語義。然而，LSR 迄今仍侷限於編碼器式雙向架構（Encoder-style bidirectional architectures），且其擴展至多模態場景仍高度依賴輔助的跨模態模組（Cross-modal modules）。為解決這些限制，我們提出 UEmbed（Unified Embedding，統一嵌入模型），這是一個僅解碼器（Decoder-only）的多模態嵌入（Multimodal embeddings）模型，能夠在一次因果前向傳播（Causal forward pass）中同時產生稀疏詞彙表示（sparse lexical representations）與密集表示（dense representations）。UEmbed 在輸入後附加 N 個可學習的特殊詞元（Special tokens），並將詞彙表（Vocabulary）劃分為 N 個互斥子集（Disjoint subsets）。每個詞元在因果遮罩下的隱藏狀態（Hidden state）會預測其對應子集上的稀疏權重（Sparse weights），而 N 個子集則被串接（Concatenated）成完整的稀疏向量（Sparse vector）。UEmbed 在公開可用資料（Publicly available data）上完成訓練，我們釋出 2B、4B 與 9B 三種參數規模的模型。UEmbed-9B 在 MMEB-v2 上分別達到 71.8（密集）與 71.0（稀疏），優於其他在公開可用資料上訓練的多模態嵌入模型（例如 RzenEmbed）。在 BEIR 上，UEmbed 亦仍具競爭力，與強大的密集與稀疏基線模型（Baselines）相當。此外，我們從有效性、效率與智能體應用三個面向，展示 UEmbed 的實用價值。總體而言，UEmbed 提供了一種新典範：它不僅在單一模型中統一了密集與稀疏嵌入，更進一步將稀疏檢索擴展至統一文字與多模態輸入。

### 核心貢獻（3～5點）
- 提出 UEmbed，首個僅解碼器架構的多模態嵌入模型，能於單次因果前向傳播中同時產生稀疏與密集表示。
- 設計分區投影機制：透過 N 個可學習特殊詞元與詞彙表互斥子集，將因果遮罩下的隱藏狀態轉換為高維稀疏向量。
- 在公開可用資料上訓練並釋出 2B、4B、9B 三種規模，UEmbed-9B 於 MMEB-v2 的密集與稀疏任務均優於其他公開資料訓練的多模態嵌入模型。
- 於 BEIR 上與強大的密集與稀疏基線保持競爭力，驗證方法在純文字檢索的穩健性。
- 從有效性、效率與智能體應用三個面向展示 UEmbed 的實用價值，拓展稀疏檢索至統一文字與多模態輸入的新典範。

### 適合對象
本論文適合從事資訊檢索、多模態學習、檢索增強生成與嵌入模型研究的學者與工程師，特別是關注如何以單一模型統一稀疏與密集檢索、以及如何將大型語言模型的僅解碼器架構擴展至多模態嵌入場景的讀者。

## 深度分析

#### 方法論解析

UEmbed（統一嵌入模型）的核心目標，是在單一 decoder-only（僅解碼器）的多模態骨幹上，同時產生 dense retrieval（密集檢索）與 sparse retrieval（稀疏檢索）兩種表示。傳統的 learned sparse retrieval（學習式稀疏檢索，LSR）——例如 SPLADE（SPLADE）——通常建立在 encoder-style bidirectional architectures（編碼器式雙向架構）如 BERT（BERT）之上，透過對每個輸入詞元的 hidden state（隱藏狀態）做 token-level transformations（詞元級轉換），再以 max pooling（最大池化）聚合出整個序列的 sparse vector（稀疏向量）。然而，decoder-only 模型受限於 causal masking（因果遮罩）與 unidirectional attention（單向注意力），無法直接對所有輸入位置進行全局 max pooling，因此傳統 LSR 的聚合策略無法直接套用。

更進一步，若僅依靠單一 EOS token（結束詞元）或 CLS token（分類詞元）的 hidden state 投影到整個 vocabulary（詞彙表）空間，會形成嚴重的 information bottleneck（資訊瓶頸）：單一向量要同時決定數萬個詞項的 sparse weights（稀疏權重），表示能力明顯不足。UEmbed 的解決方案是「分區投影（partitioned projection）」：在輸入序列後方附加 N 個可學習的 special tokens（特殊詞元），並利用 k-means clustering（k-means 分群）將 vocabulary 劃分為 N 個 disjoint subsets（互斥子集）。每個 special token 在因果注意力下總結輸入語境，並只負責預測其所對應子集的 sparse weights；最後將 N 個子集串接（concatenated）成完整的 sparse vector。這樣一來，每個 special token 的輸出維度從 |V| 降為 |V|/N，既緩解了資訊瓶頸，也讓不同 special token 能夠朝不同的 spatial direction（空間方向）專化。

Dense embedding（密集嵌入）則取自緊接在 special tokens 之前的 EOS token hidden state，因此模型在一次 causal forward pass（因果前向傳播）中就能同時產出 dense 與 sparse 兩種表示。訓練上，UEmbed 延續對比式學習框架，採用 InfoNCE loss（InfoNCE 損失）分別或聯合優化 dense 與 sparse 兩個分支；sparse 分支的相似度函數通常使用內積，以便與 inverted-index search（倒排索引搜尋）相容。由於整個流程都維持 causal attention（因果注意力），UEmbed 能夠直接部署在針對 causal model 最佳化的 serving frameworks（服務框架）如 vLLM（vLLM）上，無需將 backbone 改為 bidirectional（雙向）或引入額外的 training curricula（訓練課程）。

在多模態處理方面，UEmbed 以單一 MLLM（多模態大型語言模型）為骨幹，直接處理文字與影像輸入，避免了過去多模態稀疏檢索常見的 auxiliary cross-modal modules（輔助跨模態模組）。這不僅簡化了模型結構，也讓擴展到新的模態組合（例如圖文交錯、視覺文件）更為直接。

#### 實驗數據解讀

論文在 MMEB-v2（MMEB-v2）與 BEIR（BEIR）兩大基準上進行評估。首先在 MMEB-v2 上，UEmbed-9B 的 dense retrieval（密集檢索）達到 71.8，sparse retrieval（稀疏檢索）達到 71.0，兩者差距在所有測試規模下都壓在 1 分以內。這個結果具有兩層意義：第一，它是首次有 sparse model 在 MMEB-v2 上進行系統性評估，並在僅使用 publicly available data（公開可用資料）的設定下，超越了如 RzenEmbed 等現有多模態嵌入模型；第二，dense 與 sparse 的分數如此接近，顯示 UEmbed 成功打破了「稀疏表示必然弱於密集表示」的刻板印象，證明兩種表示可以在同一模型內同時達到頂尖水準。

在 BEIR 的 9 個資料集上，UEmbed 與 SPLADE-v3 等強大 sparse baselines（基線模型）以及 dense baselines 相比仍具競爭力。BEIR 強調 out-of-domain（領域外）泛化，因此這項結果說明 UEmbed 學到的 lexical representation（詞彙表示）不僅能捕捉語義擴展，也保留了對罕見或專業詞彙的魯棒性，這對實際搜尋系統至關重要。

除了準確率，論文還提出三個實用維度的分析。第一，hybrid scoring（混合評分）結合 dense 與 sparse 模式後，無論是文字檢索或 visual-document retrieval（視覺文件檢索）都有穩定提升，顯示兩種表示在語義相似性（semantic similarity）與精確詞彙匹配（exact lexical matching）上具有互補性。第二，UEmbed 的設計保留了與 vLLM 與 inverted-index search 的相容性，意味著它能在高吞吐量服務堆疊中運作，而不需要為 sparse retrieval（稀疏檢索）額外打造專屬推論路徑。第三，在 BrowseComp-Plus 這類 agentic search（代理式搜尋）任務中，sparse 模式能夠降低 tool-call 成本，同時維持相近的 recall（召回率），凸顯其在互動式、多步驟檢索場景中的成本效益。

#### 與現有研究的比較

相較於傳統 LSR，UEmbed 最大的差異在於它完全在 decoder-only（僅解碼器）架構上實現 sparse retrieval（稀疏檢索）。過去的方法如 SPLADE 依賴 BERT 等 encoder-style bidirectional architectures（編碼器式雙向架構），因為它們需要對整個序列進行雙向編碼後再做 max pooling。近期嘗試將 LLM（大型語言模型）用於稀疏檢索的工作，往往要將 causal backbone 改為 bidirectional，或設計專門的 training curricula（訓練課程），這會破壞與 vLLM 等針對 causal model 最佳化之 serving frameworks（服務框架）的相容性。UEmbed 透過 appended special tokens 與 partitioned projection，在不改變 attention 機制的前提下完成稀疏表示，因此能直接沿用現有的 causal model 推論基礎設施。

在多模態稀疏檢索領域，現有方法大多引入 auxiliary cross-modal modules（輔助跨模態模組）或額外模型來處理非文字模態，這類設計通常只適用於特定模態對（例如圖文），難以擴展到新的模態。UEmbed 則以單一 MLLM（多模態大型語言模型）同時產出 dense 與 sparse 表示，不僅統一了模態處理，也讓模型更容易擴展到音訊、影片或其他新興模態。此外，與純 dense multimodal embeddings（多模態嵌入）相比，UEmbed 額外提供的 sparse vector 帶來更好的可解釋性，也支援傳統 inverted-index search 與 hybrid scoring。

然而，UEmbed 仍存在若干限制。首先，vocabulary 的劃分是透過 static k-means clustering（靜態 k-means 分群）在訓練前完成，這些 disjoint subsets（互斥子集）在訓練過程中並不會隨資料動態調整，可能限制某些語義群的優化空間。其次，N 個 special tokens 會增加序列長度與記憶體消耗，雖然每個 token 的輸出維度降低，但整體計算量仍需權衡。再者，sparse vector 的維度仍等於 vocabulary size，儲存與索引成本雖可透過稀疏性緩解，但對超大規模部署仍是挑戰。最後，論文目前僅使用公開資料訓練，與使用專有巨量資料訓練的頂尖模型相比，可能還有規模上的差距。

#### 可重現性評估

從可重現性角度來看，UEmbed 具備幾項有利條件。論文明確表示模型在 publicly available data（公開可用資料）上訓練，並釋出 2B、4B 與 9B 三種規模的模型權重。公開資料與多規模釋出對於學術界複製結果、進行消融實驗與 scaling analysis（規模分析）非常有幫助。若模型權重與推論程式碼確實公開，則在 MMEB-v2 與 BEIR 上的推理結果應具備高度可重現性。

不過，目前提供的摘要與方法片段中，仍缺少許多影響訓練重現的關鍵細節，例如 special tokens 的數量 N、k-means clustering 的具體實作與距離函數、dense 與 sparse 兩個分支的 loss weighting（損失加權）、temperature τ 的設定、訓練資料混合比例、學習率排程，以及多模態輸入的前處理流程。若論文未完整釋出訓練程式碼與資料處理腳本，則從頭復現 UEmbed 的訓練過程會有相當難度。因此，現階段可重現性可評估為「推論與下游評估較易重現，但完整訓練重現仍取決於後續是否公開更多實作細節」。

#### 未來研究方向

UEmbed 開啟了數個值得後續探索的研究方向：

1. **動態詞彙分群**：目前使用 static k-means clustering（靜態 k-means 分群）劃分 vocabulary，未來可研究讓 special tokens 與詞彙子集在訓練過程中共同學習，或根據語料統計動態調整 partition，以提升表示彈性。

2. **擴展至更多模態**：UEmbed 的單一 MLLM（多模態大型語言模型）設計使其有潛力納入 audio（音訊）、video（影片）、3D 場景或 structured data（結構化資料），進一步挑戰「通用多模態稀疏檢索」的極限。

3. **端到端混合檢索學習**：目前 hybrid scoring（混合評分）似乎是在推理階段結合 dense 與 sparse，未來可探索在訓練階段就學習兩者的最佳融合權重，甚至引入可學習的 gating mechanism（門控機制）。

4. **N 與模型規模的縮放律**：研究 special tokens 數量 N、vocabulary size（詞彙表大小）與模型參數量之間的縮放關係，有助於在表示能力、計算成本與索引效率之間取得最佳平衡。

5. **稀疏向量壓縮與硬體感知服務**：針對 UEmbed 產出的 sparse vector 進行 quantization（量化）、pruning（剪枝）或學習式壓縮，並設計專屬的 inverted-index search 與 GPU kernel，可進一步提升大規模部署效率。

6. **跨語言與多語言稀疏檢索**：探討 UEmbed 在多語言語料上的 sparse lexical 行為，以及不同語言是否會在 special tokens 中形成可解釋的語義群聚。

7. **結合 late interaction（晚期互動）**：將 UEmbed 的 sparse 輸出與 ColBERT 等 late interaction 技術結合，可能在保留稀疏檢索效率的同時，進一步提升細粒度比對能力。

8. **Agentic RAG 與工具檢索**：在 retrieval-augmented generation（檢索增強生成，RAG）與 agentic search（代理式搜尋）中，利用 UEmbed 的 sparse 模式進行工具選擇、記憶檢索與初步篩選，降低昂貴的 dense 比對或 LLM 呼叫次數。

9. **可解釋性分析**：深入分析每個 special token 所對應的 vocabulary cluster（詞彙群聚）與語義方向，有助於理解 decoder-only 模型如何透過因果注意力建構 sparse lexical representation。

10. **知識蒸餾到輕量模型**：將 UEmbed-9B 的 dense 與 sparse 知識蒸餾到更小模型，讓行動裝置或邊緣設備也能執行高品質的多模態混合檢索。

## 論文問答

**Q1：UEmbed 主要想解決稀疏檢索領域中的什麼問題？**

A：UEmbed 旨在解決學習式稀疏檢索（LSR）長期受限於編碼器式雙向架構、難以原生擴展到多模態情境的問題。傳統稀疏方法如 BM25 依賴精確詞彙匹配，雖然 SPLADE 等 LSR 方法透過詞元級轉換與最大池化提升了語義能力，但大多仍建構在 BERT 等文字專用編碼器上。UEmbed 提出了一個僅解碼器的多模態統一模型，能夠在單次因果前向傳播中同時產生稀疏詞彙表示與密集語義嵌入，從而突破現有架構與模態的限制。

**Q2：為什麼現有的 LSR 方法難以直接應用於僅解碼器模型與多模態輸入？**

A：現有 LSR 方法通常依賴雙向注意力來取得全局上下文，並透過最大池化聚合序列中每個詞元的詞彙投影，但僅解碼器模型使用因果遮罩，無法直接複製這種雙向池化策略。若要用大型語言模型進行稀疏檢索，過去必須將因果骨幹轉換為雙向架構或設計特殊訓練課程，這會增加訓練成本並破壞與 vLLM 等因果模型服務框架的相容性。在多模態方面，現有方法往往額外引入輔助跨模態模組來處理非文字模態，而非從單一多模態骨幹直接產生稀疏表示，因此難以擴展到新的模態組合。

**Q3：統一稀疏與密集多模態嵌入為什麼具有重要價值？**

A：統一兩種表示能讓單一模型同時具備精確詞彙對齊能力與豐富語義相似度建模能力，並可透過混合評分互補強化檢索效果。這種設計減少了部署時維護多個獨立模型的複雜度與成本，也讓稀疏檢索從傳統文字基準走向真實世界的多模態應用。此外，它為檢索增強生成與代理式搜尋等場景提供了更靈活、更高效的嵌入基礎設施。

**Q4：UEmbed 如何在單次因果前向傳播中同時產生稀疏與密集表示？**

A：UEmbed 在輸入序列後方追加 N 個可學習的特殊詞元，並將整個詞彙表透過 k-means 分群劃分為 N 個互斥子集。在因果注意力機制下，每個特殊詞元會根據其位置總結輸入資訊，並對應預測其所負責子集的稀疏權重，最後將這 N 個子集串接成完整稀疏向量。密集嵌入則取自緊接在特殊詞元之前的 EOS 詞元之隱藏狀態，因此兩種表示可於同一個因果前向傳播中一併產出。

**Q5：分區投影機制如何解決單一詞元投影所造成的資訊瓶頸？**

A：傳統上若僅靠單一詞元投影到龐大的 |V| 維詞彙空間，其表示能力會嚴重受限，形成資訊瓶頸。UEmbed 透過將詞彙表劃分為 N 個互斥子集，讓每個特殊詞元只需負責預測較小維度的權重分布，從而分散並擴展整體表示容量。這種分區投影策略有效繞過了單一詞元難以承載完整稀疏語義的問題，並能產出具語義意義的跨模態詞彙激活。

**Q6：為什麼選擇用 k-means 分群來劃分詞彙表，並追加可學習的特殊詞元？**

A：k-means 分群能讓每個詞彙子集對應到不同的空間方向，使各特殊詞元的職責更加結構化與可解釋。追加 N 個可學習特殊詞元則讓模型能為稀疏預測分配專屬容量，同時不干擾原本用於密集檢索的 EOS 詞元隱藏狀態。這樣的設計既保留了密集嵌入的純粹性，也讓稀疏權重預測在因果架構下得以有效進行。

**Q7：論文在哪些基準上評估 UEmbed，這些基準分別衡量什麼能力？**

A：論文主要在 MMEB-v2 與 BEIR 兩大基準上進行評估。MMEB-v2 是多用於衡量多模態嵌入模型在各種任務上表現的綜合基準；BEIR 則涵蓋九個資料集，以 nDCG@10 評估模型在零樣本文字資訊檢索上的能力。透過這兩組基準，作者同時檢驗了 UEmbed 的多模態泛化性與一般文字檢索強度。

**Q8：UEmbed 在 MMEB-v2 與 BEIR 上的關鍵實驗結果為何？**

A：在 MMEB-v2 上，UEmbed-9B 的密集模式達到 71.8，稀疏模式達到 71.0，兩者差距在所有測試規模下都控制在一分以內，並超越使用公開資料訓練的其他多模態嵌入模型如 RzenEmbed。在 BEIR 上，UEmbed 與 SPLADE-v3 等強大稀疏與密集基線相比仍具競爭力。這些結果顯示 UEmbed 在統一兩種表示模式的同時，並未犧牲任一模式的檢索品質。

**Q9：論文的分析進一步揭示了 UEmbed 在哪些實用面向的優勢？**

A：分析顯示，結合密集與稀疏模式的混合評分能持續提升文字與視覺文件檢索的效果。UEmbed 的設計保留了與 vLLM 等高吞吐量服務框架以及倒排索引搜尋的相容性，確保推論與檢索效率。在 BrowseComp-Plus 上，稀疏模式能在維持相近召回率的同時降低工具呼叫成本，展現其在代理式應用中的實用價值。

**Q10：UEmbed 可應用於哪些真實世界場景？**

A：UEmbed 可部署於網頁搜尋、多模態問答、檢索增強生成以及代理式瀏覽等系統。由於它能同時處理文字與視覺輸入，因此特別適合視覺文件檢索與跨模態搜尋任務。此外，其統一的稀疏與密集輸出也支援混合排序流程，在語義相關性與詞彙精確度之間取得平衡。

**Q11：從產品部署角度來看，UEmbed 具備哪些優勢？**

A：UEmbed 採用僅解碼器架構，能直接相容於 vLLM 等針對因果模型最佳化的推論服務框架，無需額外轉換為雙向架構。其稀疏表示可透過標準倒排索引進行服務，有利於大規模高效檢索。同時，單一模型即可產出兩種嵌入，能顯著降低記憶體佔用與維運成本，簡化實際產品中的模型管理。

**Q12：UEmbed 對多模態檢索領域可能帶來什麼樣的典範轉移？**

A：UEmbed 證明了稀疏檢索可以原生地從因果解碼器模型中推導出來，而不必依賴雙向編碼器。它也展示了稀疏與密集表示可以在單一多模態骨幹中統一，無需額外輔助跨模態模組。這不僅拓展了稀疏檢索的適用模態範圍，也讓稀疏檢索能更深入地整合進現代大型語言模型服務基礎設施之中。

**Q13：論文暗示或可能承認哪些限制？**

A：UEmbed 需要預先決定特殊詞元數量 N 與詞彙分區方式，這在不同詞彙表規模或領域上可能缺乏彈性。詞彙子集透過 k-means 分群產生，未必能最佳捕捉所有語言或模態的語義關係。此外，最大的 9B 模型雖然效果最佳，但其訓練與推論仍需要相當可觀的運算資源。

**Q14：在哪些情況下 UEmbed 的稀疏或密集模式可能表現不佳？**

A：當查詢或文件中的關鍵詞彙較為罕見，或語義關係無法被聚類後的詞彙子集有效捕捉時，稀疏模式可能表現較弱。密集模式則可能在需要精確詞彙匹配的任務上遇到困難，例如實體名稱或程式碼片段的精確檢索。對於訓練資料中覆蓋不足的低資源語言或專業領域，兩種模式的效果都可能下降。

**Q15：這項工作開啟了哪些未來研究方向？**

A：未來可將 UEmbed 擴展到音訊、影片等更多模態，並探索自適應或學習式的詞彙分區策略，以取代固定的 k-means 分群。另一個方向是根據輸入複雜度動態調整特殊詞元數量，或將 UEmbed 更緊密地整合進長上下文檢索與代理式系統中。最後，開發更小、更快的模型變體以適用於邊緣裝置部署，也將有助於提升其實務採用率。

## 實務應用指南

### 適用場景

1. **多模態企業知識庫檢索**  
   同時處理技術文件、簡報截圖、產品圖片與表格，使用單一模型產出 dense 與 sparse 兩種表示。sparse 向量可對應到具體詞彙，方便稽核與解釋檢索結果。

2. **視覺文件搜尋引擎**  
   針對發票、合約、產品目錄、醫學影像報告等視覺文件，利用 UEmbed 的多模態能力進行「以圖搜圖」或「以文字搜圖」，並透過 hybrid scoring 提升召回率。

3. **RAG（檢索增強生成）系統的檢索層**  
   在需要高召回與低延遲的生成式問答系統中，dense 負責語義匹配、sparse 負責關鍵字與專有名詞匹配，兩者互補可減少生成模型接收到無關內容的機率。

4. **Agentic 瀏覽與工具呼叫**  
   類似 BrowseComp-Plus 的場景，agent 需要在大量網頁或 API 結果中快速篩選。sparse 模式可先做低成本粗排，減少後續昂貴的大型語言模型工具呼叫次數。

5. **電商與內容推薦的語義匹配**  
   以商品圖文、影片封面、使用者查詢進行統一嵌入，支援「相似商品推薦」與「關鍵字檢索」兩種互動方式，並可透過 inverted index 加速線上服務。

---

### 實作前置條件

**資料**
- 成對的查詢–文件資料（query、positive document、in-batch negatives）。
- 多模態任務需準備圖文對（image–text pairs）或視覺文件資料。
- 領域微調時，建議準備領域內的 hard negatives 以提升區分度。
- 評估資料可參考 MMEB-v2、BEIR 或自建領域測試集。

**運算資源**
- **推論**：2B 模型可在單張消費級 GPU 執行；4B 與 9B 建議使用 A100 / H100 等級 GPU，並搭配 vLLM 等服務框架。
- **訓練 / 微調**：需要多張 GPU 與較大記憶體，9B 規模建議使用多節點訓練。
- **索引建置**：dense 向量需向量資料庫；sparse 向量需倒排索引或支援 sparse vector 的搜尋引擎。

**技術能力**
- 熟悉對比學習（InfoNCE）與多模態大型語言模型（MLLM）微調。
- 理解 SPLADE / 學習式稀疏檢索（LSR）與倒排索引運作原理。
- 具備模型服務化經驗（vLLM、TGI 等）與多模態資料前處理能力。

---

### 實作步驟建議

1. **選擇模型規模與取得檢查點**  
   依延遲與準確度需求選擇 UEmbed-2B、4B 或 9B。公開資料訓練的檢查點可直接用於微調或評估。

2. **資料整理與前處理**  
   將查詢與文件（含圖片）轉換為模型輸入格式，確保視覺編碼器與 tokenizer 一致。對比學習樣本需包含正樣本與困難負樣本。

3. **決定特殊詞元數量 N 與詞彙分群策略**  
   使用 k-means 將詞彙表劃分為 N 個互斥子集。N 越大表示每個特殊詞元負擔的詞彙越少、表示能力越強，但會增加計算量與記憶體佔用。

4. **插入可學習特殊詞元並設計輸出頭**  
   在輸入序列末尾附加 N 個可學習特殊詞元。每個特殊詞元的隱藏狀態（hidden state）負責預測對應詞彙子集的 sparse weights；dense embedding 則取自位於特殊詞元之前的 EOS token 隱藏狀態。

5. **聯合訓練 dense 與 sparse 表示**  
   同時優化 dense（cosine similarity）與 sparse（inner product）兩種相似度下的 InfoNCE loss。可針對不同任務調整 temperature 與 loss weighting。

6. **建置索引與線上服務**  
   - dense 向量匯入向量資料庫（如 Milvus、Pinecone、Weaviate）。
   - sparse 向量匯入倒排索引（如 Elasticsearch、Lucene）或專用 sparse vector DB。
   - 使用 vLLM 等因果模型服務框架部署 UEmbed，並在後處理階段分離 dense 與 sparse 輸出。

7. **評估、監控與迭代**  
   在 MMEB-v2、BEIR 或領域測試集上評估 nDCG@10、Recall@K；監控 sparse 向量的非零比例、檢索延遲與索引大小，持續調整 N 與 hybrid scoring 權重。

---

### 潛在風險與注意事項

- **資訊瓶頸與 N 的權衡**  
  N 過小會限制 sparse 表示能力；N 過大則增加序列長度與記憶體消耗。建議從中等數量開始實驗，並觀察各子集的權重分佈。

- **詞彙分群不平衡**  
  k-means 可能將過多高頻詞集中於某些子集，導致對應特殊詞元負擔過重。可考慮對詞嵌入做正規化，或在分群後檢查每個子集的詞頻分佈。

- **稀疏向量實際密度偏高**  
  雖然稱為 sparse，但學習式方法可能比 BM25 產生更多非零項，影響倒排索引效率。建議設定權重閾值進行截斷，並監控索引大小。

- **多模態對齊不穩定**  
  視覺輸入對應到詞彙子集的語義可能較為間接，需確保訓練資料涵蓋足夠的圖文對，必要時對視覺分支進行額外微調。

- **因果遮罩的限制**  
  特殊詞元只能看到其之前的內容，無法進行雙向交互。務必將特殊詞元置於輸入序列最尾端，並確認 EOS token 位於特殊詞元之前以抽取 dense 向量。

- **服務框架客製化需求**  
  vLLM 雖然相容因果模型，但分區投影與特殊詞元後處理需要額外實作。部署前應確認 serving stack 支援自訂輸出頭與多模態輸入。

---

### 與其他技術的整合建議

- **向量資料庫與倒排索引並用**  
  dense 部分使用 Milvus、Pinecone、Weaviate 等向量資料庫；sparse 部分使用 Elasticsearch、Lucene 或專門支援 sparse vector 的引擎，兩者結果再進行 hybrid fusion。

- **RAG Pipeline**  
  將 UEmbed 作為第一階段 retriever，後接 cross-encoder reranker 與生成模型。sparse 可強化專有名詞與罕見詞的召回，dense 可補足語義與多模態相似度。

- **Hybrid Scoring**  
  對 dense 與 sparse 分數進行線性組合，或訓練一個小型融合模型學習最佳權重。實驗顯示此策略對文字與視覺文件檢索都有穩定提升。

- **Agentic 框架**  
  在需要頻繁呼叫外部工具或瀏覽網頁的 agent 中，先用 UEmbed sparse 模式快速過濾候選結果，再將精簡後的結果送入大型語言模型進行深度推理，以降低延遲與成本。

- **實驗追蹤與監控**  
  使用 MLflow、Weights & Biases 或類似工具追蹤 nDCG@10、MMEB-v2 分數、推論延遲、sparse 向量密度與工具呼叫次數，確保模型在效果與效率間取得平衡。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先掌握「稀疏檢索 vs. 密集檢索」的基本概念，以及 BM25、SPLADE、對比學習（InfoNCE）的運作方式。把 UEmbed 理解成「一個模型同時產出兩種向量」即可快速入門，重點閱讀論文中的圖 1 與實驗結果表格。

**AI 工程師**  
請聚焦於第 3.2 節的方法細節：N 個可學習特殊詞元如何插入、k-means 詞彙分群的實作、因果前向傳播下的輸出頭設計，以及 dense 向量取自 EOS token 的機制。同時評估與 vLLM、倒排索引整合所需的客製化工作量。

**研究人員**  
值得深入分析 decoder-only 架構下 sparse retrieval 的資訊瓶頸問題，以及分區投影（partitioned projection）如何繞過單一詞元表示能力受限的理論動機。可進一步與 SPLADE、SPLADE-v3、RzenEmbed 等方法比較貢獻與限制。

**產品經理**  
重點關注適用場景、效果–效率權衡、模型規模選擇（2B / 4B / 9B）以及 hybrid scoring 對使用者體驗的影響。論文中 BrowseComp-Plus 的 agentic 應用與工具呼叫成本降低，是評估商業價值時的關鍵數據。
