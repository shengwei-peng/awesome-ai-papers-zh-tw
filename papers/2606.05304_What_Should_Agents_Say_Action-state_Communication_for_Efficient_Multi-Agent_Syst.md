## ⚡ TL;DR

現有多智能體系統的自由格式通訊導致Token成本高昂且效能下降。

實驗顯示PACT顯著降低Token用量並維持甚至提升任務表現。

## 摘要翻譯

以大型語言模型（Large Language Models, LLMs）為基礎的多智能體系統（Multi-Agent Systems, MAS）通常依角色（Roles）、管線（Pipelines）與輪次排程（Turn Schedules）加以組織，但智能體（Agents）之間傳遞的內容往往仍為無約束自然語言（Unconstrained Natural Language）。然而，這種自由格式通訊（Free-form Communication）會使 Token（詞元）使用量急遽增加、消耗共享的上下文視窗（Context Window），最終影響系統性能與推論成本（Inference Cost）。我們分析兩種 MAS 拓撲結構（MAS Topologies）中五種常見的智能體間通訊（Inter-agent Communication）策略，發現並無任何固定策略能普遍最優。相反地，有效的智能體間訊息始終保留下游智能體（Downstream Agents）所需的以動作為中心的資訊（Action-centered Information）。基於此，我們提出 PACT（Protocolized Action-state Communication and Transmission），將智能體間通訊視為公共狀態更新問題（Public State-update Problem），並在原始智能體輸出（Raw Agent Output）進入共享歷史紀錄（Shared History）之前，將其投影為精簡的動作-狀態記錄（Action-state Record）。在不同的 MAS 拓撲結構中，PACT 持續改善性能-成本權衡（Performance-cost Trade-off），以顯著較少的 Token 達到相當或更強的任務性能。這些增益也延伸至生產級程式碼框架（Production Coding Harnesses）：PACT 在提升 OpenHands 解決率（Resolve Rate）的同時，使每解決問題所需 Token 數（Tokens-per-resolved）降低 10%；在 SWE-agent 上則解決率維持持平（Resolve-neutral），同時將輸入 Token 減半。我們的程式碼已公開於 https://github.com/iNLP-Lab/PACT。

### 核心貢獻（3～5點）
- 分析五種常見智能體間通訊（Inter-agent Communication）策略，發現並無任何固定策略能普遍最優，但有效訊息需保留下游智能體（Downstream Agents）所需的以動作為中心的資訊（Action-centered Information）。
- 提出 PACT（Protocolized Action-state Communication and Transmission），將智能體間通訊形式化為公共狀態更新問題（Public State-update Problem），並將原始智能體輸出（Raw Agent Output）投影為精簡的動作-狀態記錄（Action-state Record）。
- 在不同 MAS 拓撲結構（MAS Topologies）中驗證 PACT 能持續改善性能-成本權衡（Performance-cost Trade-off），以顯著較少的 Token 達成相當或更佳的任務性能。
- 在生產級程式碼框架（Production Coding Harnesses）OpenHands 與 SWE-agent 上驗證實際效益：提升解決率（Resolve Rate）並降低每解決問題所需 Token 數（Tokens-per-resolved），或維持解決率持平（Resolve-neutral）同時減半輸入 Token。

### 適合對象
研究多智能體系統（MAS）與大型語言模型（LLM）應用之研究者與工程師，特別是關注智能體間通訊效率、推論成本（Inference Cost）優化，以及生產級程式碼框架（Production Coding Harnesses）實作的進階讀者。

## 深度分析

#### 方法論解析

本研究的核心命題在於重新審視 multi-agent systems (多智能體系統, MAS) 中的 inter-agent communication (智能體間通訊) 內容設計。作者指出，現有 MAS 大多聚焦於 roles (角色) 分配、turn schedules (輪次排程) 與 pipelines (管線) 編排，卻將 agent (智能體) 之間傳遞的內容視為 unconstrained natural language (無約束自然語言) 或 free-form natural language (自由格式自然語言)，導致 free-form communication (自由格式通訊) 迅速膨脹 token (詞元) 用量，並擠壓 context window (上下文視窗)。

為了診斷此問題，作者進行 diagnostic analysis (診斷分析)，比較五種常見的 communication strategies (通訊策略)：(1) 轉發 agent 的 full free-form output (完整自由格式輸出)；(2) 依賴模型內建能力的 native concise generation (原生簡潔生成)；(3) 僅保留最終結論的 conclusion-only messages (僅結論訊息)；(4) 產生短摘要；(5) 僅傳遞 role artifact (角色產出物) 的 artifact-only messages (僅產出物訊息)。實驗發現，沒有任何單一策略能在不同 MAS topologies (MAS 拓撲結構) 下普遍最優：完整輸出過於冗餘，簡潔生成可能遺漏 task-relevant information (任務相關資訊)，僅結論訊息對下游過度損失，而僅產出物訊息雖保留任務內容，卻仍使 downstream agents (下游智能體) 必須推論發送者的意圖與 grounding evidence。

基於上述觀察，作者提出將 inter-agent communication 重新概念化為 public state-update problem (公共狀態更新問題)。其核心洞見是：有效的訊息應該保留 action-centered information (以動作為中心的資訊)，而非轉發 sender 的 private computation (私有計算) 或 internal reasoning trace (內部推理軌跡)。據此，本論文提出 PACT (Protocolized Action-state Communication and Transmission) (協定化動作-狀態通訊與傳輸)，一種 training-free (無需訓練) 且 harness-agnostic (與框架無關) 的通訊協定。

PACT 的運作機制是在 raw agent output (原始智能體輸出) 進入 shared history (共享歷史紀錄) 或 shared dialogue history (共享對話歷史) 之前，先將其投影為一個結構化的 action-state record (動作-狀態記錄)。此記錄嚴格限定為三項 receiver-facing 的資訊：(i) 已執行或接下來需要的 action；(ii) 任務相關的 state；(iii) 可供下游重複使用的 result artifact。這種設計明確劃分了 private computation 與 public communication (公共通訊) 的邊界：agent 的內部推演過程不進入公共頻道，僅有更新共享狀態所需的最小行動資訊被保留。透過這種 public state-update (公共狀態更新) 的視角，PACT 將原本無限制的對話歷史轉化為緊湊、可複用且語義明確的狀態流。

#### 實驗數據解讀

作者選用兩種代表性的 MAS topologies 進行系統性評估。第一種為 split-evidence interaction (分割證據互動)，使用 HotpotQA 與 2WikiMultiHopQA 作為 benchmark，模擬兩個 agent 各自持有部分證據、必須透過溝通才能回答問題的情境。第二種為 sequential pipeline (順序管線)，採用四個固定順序的 agent（Planner、Critic、Refiner、Solver），並在數學推理（AIME 2024/2025）、科學推理（GPQA-Diamond）與常識問答（OpenBookQA）上進行測試。所有實驗均覆蓋 Qwen3-8B、Qwen3-14B 與 Qwen3-32B 三種模型規模，以確保結論的跨尺度穩健性。

實驗結果首先驗證了「無固定策略普遍最優」的假說：在不同 topology 與任務類型下，五種 baseline communication strategies 的表現與成本曲線各異。然而，無論在哪種設定中，成功傳遞 action-centered information 的訊息皆能更穩定地維持任務表現。PACT 在此基礎上，將 token usage (Token 使用量) 平均降低 38.7%，同時保留甚至提升任務正確率，顯著推進了 performance-cost trade-off (性能-成本權衡) 與 performance–cost frontier (性能-成本前沿)。

更具說服力的是 production coding harnesses (生產級程式碼框架) 上的驗證。在 OpenHands 中，PACT 不僅提升 resolve rate (解決率)，更將 tokens-per-resolved (每解決問題所需 Token 數) 降低 10%；在 SWE-agent 中，PACT 達成 resolve-neutral (解決率持平)，卻將 input tokens 減半。這些結果在實務上極具意義：程式碼任務往往涉及長期的 tool-augmented trajectories，shared history 極易累積冗長紀錄。PACT 透過抑制 verbose or noisy messages (冗長或雜訊過多的訊息) 進入 shared dialogue history，避免 downstream agents 反覆重新處理無關的 deliberative content，從而阻斷 token 成本在跨輪次間的複利效應，並減緩 context window 耗盡的風險。

#### 與現有研究的比較

在 MAS 領域，既有研究大多集中於「誰與誰對話」以及「何時對話」，例如 roles (角色) 的專業化、peer debate、turn-taking 機制與 parallel aggregation 等。這些工作雖然優化了系統的組織架構與 orchestration，卻普遍將 inter-agent message 的內容留給 free-form natural language，鮮少探討「應該傳遞什麼」。相較之下，本論文將通訊內容視為一個獨立且核心的設計槓桿，並透過 systematic diagnostic analysis 證明其對 inference cost (推論成本) 與任務表現的雙重影響。

在 token 效率方面，近期部分研究（如 Zou et al., Chen et al., Yu et al.）已開始關注 disciplined communication 對準確率與成本的影響，但多聚焦於訊息長度或形狀的約束。PACT 的獨特貢獻在於提出一個清晰的 communication invariant：只有 action、grounded state 與 reusable result 被納入 public communication，而 private deliberation 被排除於 shared history 之外。這不僅是一種壓縮策略，更是一種針對 MAS 語境設計的狀態更新語義框架。

然而，本研究亦存在可進一步拓展之處。首先，diagnostic analysis 已指出 no fixed strategy is universally optimal，而 PACT 採用相對固定的 action-state schema，雖然在實驗拓撲中表現穩健，但面對高度動態、非結構化或創意生成導向的任務時，「action」與「state」的定義可能變得模糊，固定模板的適用性將受挑戰。其次，PACT 的 projection 步驟依賴 LLM 自身的 in-context instruction following 能力，若模型無法精確從 raw agent output 中萃取關鍵資訊，則可能誤刪 grounding evidence，導致 downstream agent 缺乏足夠脈絡。此外，實驗主要集中於問答、數學推理與程式碼修復等具有明確目標的任務，對於開放式對話或創意協作等難以明確界定「state」的場景，PACT 的效益仍有待驗證。

#### 可重現性評估

本論文的重現性條件相當優越。首先，作者已將原始碼公開釋出於 https://github.com/iNLP-Lab/PACT，包含協定實作與實驗腳本。其次，PACT 為 training-free (無需訓練) 方法，不依賴任何微調後的專有模型權重，僅需具備基礎 LLM 的推理端點即可部署。實驗所使用的 Qwen3 系列模型亦為公開可取得之權重。在資料層面，HotpotQA、2WikiMultiHopQA、AIME、GPQA-Diamond、OpenBookQA 與 SWE-bench（透過 OpenHands 與 SWE-agent）均為公開 benchmark，無資料取得門檻。

再者，PACT 的 harness-agnostic (與框架無關) 特性意味著其並非綁定於特定 MAS 框架的客製化外掛，而是一種可插入現有 agent loop 的通用通訊層。作者已在兩個截然不同的 production coding harnesses 上完成移植，證明其整合複雜度低。實驗細節雖部分置於附錄，但核心演算法與 projection prompt 的設計邏輯已在正文中充分闡述，使其他研究者能夠快速複製並應用於自身的 MAS 架構中。

#### 未來研究方向

1. **動態模式適應（Dynamic Schema Adaptation）**：當前 PACT 採用相對固定的 action-state record (動作-狀態記錄) 結構。未來可探索依據任務階段、topology 變化或 agent 角色動態調整欄位定義，使通訊格式更具彈性，以應對複雜的長期互動。

2. **拓撲與內容的聯合優化（Joint Optimization）**：既有文獻已開始探討 agent 之間的通話拓撲（who talks to whom）。將 PACT 的通訊內容壓縮機制與動態拓撲選擇結合，可望在更廣泛的 configuration space 中找到全局最優的 performance-cost trade-off。

3. **輕量化學習型投影（Learned Projection）**：雖然 training-free 是 PACT 的優勢，但針對特定領域訓練輕量的 LoRA adapter 或專用 compressor，以取代 prompt-based projection，可能進一步提升 action-state extraction 的準確率與穩定性，特別是在超長 trajectories 中。

4. **資訊理論邊界分析**：從理論層面量化「在不損失 task-relevant information 的前提下，inter-agent message 可被壓縮至何種程度」，將有助於建立 MAS 通訊的資訊下限與 performance–cost frontier 的理論模型。

5. **多模態與工具導向延伸**：當前實驗以文字為主。未來可將 action-state communication 擴展至多模態 MAS，其中 role artifact 可能包含圖像、程式碼、資料庫查詢結果或工具輸出，探討跨模態的緊湊狀態表示法。

6. **超長軌跡與人機協作**：在數百輪以上的長期 agentic workflows 或 human-in-the-loop 場景中，驗證 PACT 的累積效益是否呈現超線性成長，並研究如何將 public/private 邊界應用於人機溝通以降低人類認知負荷。

## 論文問答

**Q1：這篇論文試圖解決多智能體系統中的什麼核心問題？**
A：這篇論文指出，現有的大型語言模型多智能體系統（MAS）雖然在角色分配、管線設計與輪次排程上已有大量研究，但智能體間的訊息內容往往被留為無約束自然語言，導致通訊內容過度冗長。這種自由格式通訊會迅速膨脹 Token 使用量，並消耗寶貴的共享上下文視窗，最終同時影響系統性能與推論成本。因此，作者將焦點放在一個被忽視的核心設計槓桿：智能體之間究竟應該傳遞什麼內容。

**Q2：現有方法在智能體間通訊上為何不足？**
A：現有研究大多著重於「誰在何時發言」以及工具配置，卻將智能體間訊息視為自由格式自然語言，缺乏對內容的系統性約束。當上游智能體轉發完整的內部推理軌跡時，下游智能體必須在每一輪重複處理這些冗長或雜訊過多的訊息，使得 Token 成本在多次輪替中複合增長。這種設計不僅浪費計算資源，還可能在任務完成前就耗盡上下文視窗，進而降低整體任務表現。

**Q3：為何智能體間的訊息內容設計如此重要？**
A：在多智能體協作中，每一輪的輸出都會成為共享對話歷史的一部分，後續智能體必須在有限的上下文視窗內重新處理這些資訊。如果訊息包含大量與任務無關的私有推理，Token 使用量與推論成本將隨著輪次急劇上升，直接影響生產環境的可行性。更重要的是，過度擁擠的共享歷史會干擾下游智能體對關鍵資訊的提取，最終拖累整個系統的決策品質與任務成功率。

**Q4：PACT 的核心方法是什麼？**
A：PACT（協定化動作-狀態通訊與傳輸）將智能體間通訊重新定義為公共狀態更新問題，而非單純的訊息轉發。在每一次非終端智能體完成生成後，PACT 會將其原始智能體輸出投影為一份精簡的動作-狀態記錄，僅保留下游智能體繼續執行所需的關鍵資訊。這份記錄在進入共享歷史之前，會明確區隔私有計算與公共通訊的邊界，避免內部推理軌跡污染共享上下文。

**Q5：相較於現有通訊策略，PACT 的關鍵創新為何？**
A：PACT 的關鍵創新在於提出「以動作為中心的資訊」是有效智能體間通訊的不變量，並據此設計出一套無需訓練且與框架無關的通訊協定。不同於過去固定使用完整輸出、僅結論訊息或僅產出物訊息等策略，PACT 系統性地證明只有保留「已採取或下一步所需的動作」、「任務相關狀態」以及「可重複使用的結果」才能兼顧性能與成本。這種設計將通訊內容從自由格式自然語言提升為結構化的公共狀態更新，為 MAS 開闢了新的設計維度。

**Q6：PACT 在設計上做了哪些具體選擇？**
A：PACT 明確排除了智能體的完整自由格式輸出與內部推理軌跡，避免下游智能體重複處理無關的私有計算內容。它選擇保留三項核心元素：智能體已執行或要求執行的動作、與任務直接相關的狀態資訊，以及可供下游使用的角色產出物。這種設計使得訊息既不像僅結論訊息那樣過度遺失上下文，也不像完整轉發那樣充斥冗餘資訊，從而在不同 MAS 拓撲結構中達成穩健的性能-成本權衡。

**Q7：實驗涵蓋了哪些基準測試與設定？**
A：實驗在兩種 MAS 拓撲結構上進行診斷分析，包括需要證據交換的分割證據互動設定（HotpotQA 與 2WikiMultiHopQA），以及依序處理的順序管線設定（AIME 2024/2025、GPQA-Diamond 與 OpenBookQA）。模型規模橫跨 Qwen3-8B、Qwen3-14B 與 Qwen3-32B，以驗證方法在不同參數量下的穩定性。此外，研究團隊也將 PACT 移植到兩個生產級程式碼框架——OpenHands 與 SWE-agent——進行真實世界軟體工程任務的驗證。

**Q8：PACT 取得了哪些關鍵實驗結果？**
A：在學術基準測試中，PACT 平均減少 38.7% 的 Token 使用量，同時維持甚至提升任務表現，顯著改善了性能-成本前沿。在 OpenHands 框架上，PACT 不僅提升了解決率，還降低了每解決問題所需 Token 數達 10%。而在 SWE-agent 上，PACT 在保持解決率持平的前提下，將輸入 Token 減半，證明其在高複雜度、長軌跡的生產環境中同樣具備實用價值。

**Q9：對五種常見通訊策略的診斷分析揭示了什麼？**
A：系統性比較顯示，沒有任何一種固定通訊策略能在不同拓撲結構中普遍最優：完整自由格式輸出過於昂貴且冗餘，原生簡潔生成可能遺失任務相關資訊，僅結論訊息在接收者缺乏周圍狀態時過度失真，而僅產出物訊息雖然保留了有用內容卻仍迫使接收者推斷發送者的意圖。相對地，所有有效的智能體間訊息都具備一個共同特徵：它們保留了下游智能體所需的以動作為中心的資訊。這項發現直接促成了 PACT 的設計，即將通訊視為公共狀態更新而非自由對話。

**Q10：PACT 在實務場景中可以如何應用？**
A：由於 PACT 是無需訓練且與框架無關的通訊協定，它可以作為推論時的通訊協議直接整合到現有的多智能體系統中，無需對底層大型語言模型進行微調。無論是採用順序管線的問答系統，還是需要分割證據互動的協作推理平台，都能透過在智能體輸出進入共享歷史前加入投影層來實施 PACT。這對於上下文視窗有限且需要長軌跡互動的場景——如自動化程式碼修復或長篇文件分析——尤其具有吸引力。

**Q11：從產品與工程角度，採用 PACT 有哪些考量與優勢？**
A：PACT 的導入成本極低，因為它不需要重新訓練模型或改變智能體的核心角色邏輯，僅需在訊息傳遞路徑上增加一個結構化投影步驟。透過大幅削減每輪的 Token 使用量，它能直接降低 API 呼叫的推論成本與延遲，對於需要頻繁智能體協作的商業化產品而言，這代表顯著的營運支出節省。此外，壓縮共享對話歷史有助於延緩上下文視窗耗盡，使系統能夠處理更複雜、更長週期的任務而不中斷。

**Q12：這項研究對多智能體系統領域的廣泛影響是什麼？**
A：這項研究將 MAS 的設計焦點從傳統的「誰在何時與誰交談」轉移到「應該傳遞什麼內容」，填補了智能體間通訊內容這一長期被忽視的設計維度。它確立了動作-狀態通訊作為共享歷史的核心不變量，為未來的 MAS 架構提供了一個可遵循的通訊原則。透過證明紀律化的訊息設計能同時提升性能並降低成本，這項工作為建構可擴展且經濟高效的生產級多智能體應用奠定了重要基礎。

**Q13：作者承認了哪些限制？**
A：本研究的診斷分析主要聚焦於分割證據互動與順序管線這兩種拓撲結構，對於更動態的辯論、平行輸出聚合或隨圖變化的通訊拓撲，其適用性仍需進一步驗證。雖然 PACT 的動作-狀態投影規則在多個領域表現穩健，但在極度特殊的任務領域中，這套固定規則可能需要額外的領域知識來調整。此外，研究假設智能體能夠從原始輸出中自動生成有意義的動作-狀態記錄，而未探討當智能體本身生成品質不佳時的容錯機制。

**Q14：在哪些情況下 PACT 可能失效或表現不佳？**
A：若任務本質上需要豐富的審議性上下文——例如深度哲學辯論或需要細緻推理鏈說服的創意協作——則強制剝離內部推理軌跡可能導致資訊過度壓縮而損害性能。在高度對抗性的多智能體環境中，如果下游智能體必須理解上游對手的完整思維過程才能進行有效反駁，僅傳遞動作-狀態記錄可能過於簡略。同樣地，若某個領域缺乏清晰的動作與狀態邊界，導致動作-狀態記錄難以精確定義，PACT 的投影步驟可能會遺失關鍵細節。

**Q15：未來有哪些值得探索的研究方向？**
A：未來研究可以將 PACT 擴展到動態拓撲結構，讓智能體在執行過程中依據任務需求自適應地調整通訊圖，而非僅限於固定順序。另一個方向是從固定規則走向學習式投影，透過輕量級訓練或提示工程讓智能體自動學習最適合當前任務的動作-狀態表示。此外，探索混合策略也具有潛力，例如根據上下文視窗壓力或任務複雜度，在完整通訊與動作-狀態更新之間動態切換，以進一步提升系統的適應性與效率。

## 實務應用指南

### 適用場景

1. **生產級軟體工程智能體**：在 OpenHands、SWE-agent 等框架中，多智能體長期協作處理 GitHub issue 時，利用 PACT 抑制工具呼叫與環境回饋累積造成的上下文視窗膨脹，顯著降低每解決問題所需 Token 數。
2. **企業內部順序管線**：如數據分析、文件審查或客服意圖解析等線性流程，將前階段智能體的完整推理軌跡替換為動作-狀態記錄，避免下游智能體重複處理無關雜訊。
3. **分割證據互動系統**：法律檢索、醫療診斷或文獻綜合場景中，多個智能體各自持有部分證據，透過結構化公共狀態更新交換關鍵發現，而非傳遞冗長的自由格式自然語言。
4. **邊緣或高頻推論環境**：在 Token 預算或上下文長度嚴格受限的邊緣部署中，以精簡的動作-狀態通訊維持多智能體協作，確保推論成本不隨輪次指數增長。
5. **複雜決策管線**：供應鏈規劃、財務風險評估等需要「規劃→批評→修正→執行」多角色輪替的系統，透過協定化通訊保留角色產出物與必要狀態，移除私有計算產生的冗餘內容。

### 實作前置條件

- **資料準備**：已明確定義各智能體的角色職責與預期產出物（如 Planner 輸出計畫、Critic 輸出批評、Solver 輸出最終答案）；現有對話歷史或推理軌跡供診斷分析，以識別目前通訊策略中的冗餘比例。
- **運算資源**：具備支援多輪對話與 function calling 的 LLM API 存取權限（如 GPT-4、Qwen3 系列）；足夠的 prompt caching 或快取機制以進一步放大成本節省效益；無需額外訓練算力。
- **技能需求**：熟悉結構化輸出（JSON schema、 constrained decoding）與 prompt engineering；理解 MAS 拓撲結構（順序管線、分割證據互動或同儕辯論）；具備在現有框架中插入中介層（middleware）的工程能力。

### 實作步驟建議

1. **現況診斷與基準建立**：記錄當前智能體間傳遞的完整自由格式輸出，量化平均訊息長度、重複內容比例，以及下游智能體實際引用上游資訊的頻率，建立性能-成本權衡基線。
2. **設計動作-狀態模式**：針對每個非終端智能體定義三欄位結構——**已執行動作（Action）**、**任務相關狀態（State）**、**下游可用產出物（Artifact）**。確保 State 包含下游接續所需的 grounding evidence，而非僅結論。
3. **建置投影層（Projection Layer）**：在智能體產出原始輸出後、寫入共享對話歷史前，插入一層解析器。該層負責將自由格式文字或內部推理軌跡轉譯為精簡的動作-狀態記錄，並確保私有計算不進入公共通訊頻道。
4. **漸進式驗證**：先從單一智能體（如 Critic 或 Refiner）試行 PACT，比較任務表現與 Token 使用量；確認無顯著性能衰退後，擴展至全管線。注意不同拓撲結構可能需要微調欄位細節。
5. **框架整合與部署**：將 PACT 封裝為與框架無關的通訊中介層，對接現有系統（如覆寫 AutoGen、LangChain 或 OpenHands 的訊息傳遞介面）。由於無需訓練，可直接作為推論時通訊協定上線。
6. **持續監控與調校**：追蹤解決率、Token 使用量與上下文視窗佔用率，針對「資訊過度壓縮」導致的錯誤進行根因分析，動態調整 State 欄位的保留粒度。

### 潛在風險與注意事項

- **資訊過度壓縮**：動作-狀態記錄若過度精簡，下游智能體可能遺失關鍵脈絡。建議在 State 欄位保留核心證據索引或摘要，而非僅保留最終結論。
- **一體適用的迷思**：論文已證實無單一通訊策略 universally optimal。分割證據互動與順序管線對資訊密度需求不同，需依場景調整投影規則，避免直接照搬固定模板。
- **可解釋性下降**：移除內部推理軌跡後，除錯難度上升。建議維護獨立的私有日誌（private trace log）供開發者查閱，與進入共享歷史的公共通訊嚴格分離。
- **格式解析失敗**：若智能體未遵循預期結構，投影層可能產生錯誤。建議搭配強制 JSON schema、outlines 或 guidance 等結構化生成工具，並加入後處理驗證與降級機制（fallback to raw output）。
- **角色產出物遺漏**：僅傳遞角色產出物（artifact-only）可能使接收方難以推斷發送方的意圖動作，需確保 Action 欄位明確記錄「下一步需要什麼」或「剛才完成了什麼」。

### 與其他技術的整合建議

- **現有 MAS 框架**：將 PACT 實作為訊息中介層，攔截並改寫智能體間的原始輸出後再寫入共享歷史。對上層框架而言，這是無侵入性的通訊協定升級。
- **RAG 與向量資料庫**：動作-狀態記錄中的 State 欄位可嵌入向量資料庫，供下游智能體進行語義檢索。當狀態過長時，不必全量寫入上下文，改以檢索增強方式按需調用。
- **結構化生成（Structured Generation）**：結合 JSON mode、outlines 或 guidance 函式庫，讓智能體直接產出符合 PACT 格式的記錄，降低自由格式文字解析的不確定性與額外成本。
- **Prompt Caching / KV-Cache 重用**：PACT 減少共享歷史中的冗餘內容，可進一步搭配 API 層級的 prompt caching 機制，讓重複出現的系統提示與精簡後的歷史紀錄獲得更大快取命中效益。
- **觀測與監控平台**：整合 LangSmith、Langfuse 或自研監控系統，分別追蹤公共通訊頻道（PACT 記錄）與私有計算頻道（原始推理軌跡），以視覺化方式呈現 Token 節省量與性能變化。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先聚焦論文的圖一與第三章診斷分析，建立「為何自由格式通訊會讓 Token 成本隨輪次複利增長」的直覺理解；不必急著深入程式碼框架，重點掌握「動作-狀態記錄」三要素（Action、State、Artifact）如何取代冗長對話即可。
- **AI 工程師**：請深入研讀 PACT 的投影層設計邏輯與第 4–5 章實驗設定，特別關注如何在不微調模型權重的情況下，僅透過通訊協定層優化性能-成本前沿；強烈建議直接參考作者公開的 GitHub 程式碼，在現有管線中復現並驗證 Token 降幅。
- **研究人員**：請著重分析第三章「無單一策略 universally optimal」的核心發現，以及公共狀態更新問題的形式化定義；可延伸探討動態通訊策略（依據下游智能體需求或任務難度自適應調整壓縮率），或將 PACT 原理擴展至更複雜的 MAS 拓撲結構與異質智能體協作場景。
- **產品經理**：請重點閱讀摘要與生產級程式碼框架實驗（OpenHands、SWE-agent），聚焦「減少 10% Token 同時提升解決率」與「Token 減半且解決率持平」的商業價值；將 PACT 視為降低 LLM 服務邊際成本、延長上下文視窗可用壽命的工程槓桿，優先評估導入高頻、長輪次產品管線的 ROI。
