## ⚡ TL;DR

## 摘要翻譯

GUI 智慧代理（GUI agents）有潛力成為在現有數位裝置（digital devices）上運作的通用執行器（general-purpose executor）。為了推動其真實世界應用（real-world use），我們設想的智慧代理能夠在真實裝置（real devices）上可靠運作、跨平台（cross-platform）執行工作流程（workflows）、結合 GUI 互動（GUI interaction）與 CLI 執行（CLI execution）、完成長期任務（long-horizon tasks）、主動啟動有用服務（proactively initiate useful services），並以最少人工投入（minimal human effort）自主提升其能力。在此願景的指引下，我們提出 Qwen-UI-Agent（通義千問 UI 智慧代理），一個以真實世界為中心（real-world centric）的基礎 GUI 智慧代理（foundation GUI agent），涵蓋行動裝置（mobile）、電腦使用（computer-use）、網頁（web）與 DeepSearch（深度搜尋）環境。Qwen-UI-Agent 結合多樣化的沙箱環境（sandbox environments）與大規模真實行動裝置執行環境（real-device mobile runtime）。其統一的動作空間（unified action space）將 GUI 操作與 CLI 執行交錯結合，並在單一模型回合（single model turn）中生成批次動作（batched actions）。一個 AutoResearch 風格的資料飛輪（data flywheel）利用智慧代理來建構任務與環境、診斷失敗，並規劃後續迭代。線上強化學習（online RL）支援超過 100 個回合的軌跡（trajectories）訓練，並透過超過 10,000 個並行環境（concurrent environments）加速 rollout（軌跡展開）。輕量化的 harness 層（harness layer）支援跨行動裝置與電腦的主動服務啟動（proactive service initiation）與具狀態工作流程（stateful workflows）。

在一系列廣泛的評估中，Qwen-UI-Agent 在行動裝置使用基準上創下最先進表現（state-of-the-art performance），並在電腦與瀏覽器使用（browser use）任務中與包括 Opus 4.8、Gemini 3.1 Pro 與 GPT-5.6 Sol 在內的前沿模型（frontier models）相比展現具競爭力的表現（competitive performance）。在行動裝置使用方面，它在 MobileWorld 上達到 82.1%、MobileWorld-Real 上達到 92.2%，以及 AndroidDaily 上達到 97.5%。在電腦使用方面，它在 OSWorld-Verified 上達到 79.5%，並在 OSWorld-v2 上取得 40.0% 的部分進展分數（partial-progress score）。在瀏覽器使用與 GUI 定位（GUI grounding）方面，它分別在 WebArena 上達到 73.6%、ScreenSpot-Pro 上達到 81.5%。

### 核心貢獻（3～5點）
- 提出以真實世界為中心的基礎 GUI 智慧代理 Qwen-UI-Agent，涵蓋行動裝置、電腦使用、網頁與 DeepSearch 環境，並結合多樣化沙箱與大規模真實行動裝置執行環境。
- 設計統一動作空間，將 GUI 操作與 CLI 執行交錯結合，並在單一模型回合中生成批次動作，以支援長期任務與跨平台工作流程。
- 建立 AutoResearch 風格的資料飛輪與線上強化學習機制，可自動建構任務與環境、診斷失敗、規劃迭代，並在超過 10,000 個並行環境中加速長軌跡 rollout。
- 透過輕量化 harness 層實現主動服務啟動與具狀態工作流程，強化真實裝置上的應用能力。
- 在 MobileWorld、MobileWorld-Real、AndroidDaily、OSWorld、WebArena 與 ScreenSpot-Pro 等多項基準上達到最先進或具競爭力的表現。

### 適合對象
適合對 GUI 智慧代理、多模態大型語言模型、行動／電腦／網頁自動化、強化學習與真實世界部署感興趣的研究人員與工程師，特別是關注長期任務、跨平台執行、真實裝置運作與自主能力提升的讀者。

## 深度分析

#### 方法論解析

Qwen-UI-Agent（通義千問 UI 智慧代理）被定位為一套以真實世界為中心（real-world centric）的基礎 GUI 智慧代理（foundation GUI agent），其核心設計目標是讓單一代理能夠同時操作行動裝置（mobile）、電腦使用（computer-use）、網頁（web）以及 DeepSearch（深度搜尋）四種異質環境（heterogeneous environments）。整體方法論可從系統設計、環境基礎設施、資料飛輪、訓練流程與控制層五個層面拆解。

**1. 任務形式化與統一動作空間（Unified Action Space）**

本研究將 GUI 智慧代理的任務視為一個部分可觀察的序列決策問題：代理根據螢幕截圖、文字提示與歷史軌跡，產生可改變環境狀態的動作。為了打破傳統 GUI 智慧代理僅能執行點擊、滑動等純 GUI 操作的限制，Qwen-UI-Agent 設計了混合式 GUI+CLI 動作空間（hybrid GUI+CLI action space），將圖形使用者介面（Graphical User Interface, GUI）操作與命令列介面（Command Line Interface, CLI）執行整合在同一個動作序列中。更具特色的是，該動作空間支援批次化動作（batched actions），即模型可以在單一推理回合（single model turn）內輸出多個連續動作，例如先開啟終端機、再執行一段腳本、最後回到 GUI 點擊確認。這種設計讓代理能夠依任務本質選擇最適執行方式：GUI 操作適合視覺導航與不確定性高的介面，CLI 執行則適合結構化資料處理、批次檔案操作或需要精確參數的任務。

**2. 環境基礎設施：從沙盒到真實裝置**

Qwen-UI-Agent 的環境層同時包含大規模沙盒環境（sandbox environments）與真實裝置（real devices）兩種運行時。沙盒環境用於快速擴充訓練資料與平行評估；而行動裝置部分則建置了超過 100 台實體裝置、支援超過 150 個應用程式的真實裝置行動環境（real-device mobile environment）。這是為了彌補模擬環境與真實世界之間的顯著落差：真實手機存在多樣化的 UI 排版、權限對話框、系統通知、網路延遲與應用程式版本差異，這些因素在模擬器中往往被過度簡化。透過在真實裝置上進行任務設計、軌跡收集、線上強化學習（online RL）與評估，模型得以學習更貼近實際使用者情境的行為。此外，系統還提供使用者接管（user takeover）機制，讓高風險操作可由人類介入，兼顧安全性與可用性。

**3. Agent-Driven 資料飛輪（Data Flywheel）**

為了降低對人工建置資料與手動除錯的依賴，Qwen-UI-Agent 採用類似 AutoResearch 風格的資料飛輪（data flywheel）。具體而言，代理本身被用來自動建構任務與環境、診斷失敗軌跡、規劃下一輪迭代所需的資料與訓練重點。這種自我增強迴圈讓開發流程從「人工設計任務 → 收集資料 → 訓練 → 評估 → 分析錯誤」轉變為由代理驅動的持續最佳化流程，從而減少最少人工投入（minimal human effort）並加速能力自主提升（autonomously improve capabilities）。

**4. 三階段訓練：SFT、ActionRL 與 OnlineRL**

訓練流程分為三個階段：

- **監督式微調（Supervised Fine-Tuning, SFT）**：利用收集到的軌跡資料進行初步行為克隆，讓模型學會基本的 GUI 與 CLI 操作模式。
- **ActionRL：Correcting Recurring Action Errors**：針對重複出現的動作層級錯誤進行強化學習（Reinforcement Learning, RL）微調，例如錯誤的點擊座標、重複嘗試無效操作、忽略系統提示等。此階段著重於步驟層級（step-level）的行為修正。
- **OnlineRL：Learning Long-Horizon Decision Making**：在真實或高保真環境中進行線上強化學習，支援超過 100 步的長期任務（long-horizon tasks）軌跡，並透過超過 10,000 個並行環境（concurrent environments）加速 rollout。此階段著重於軌跡層級（trajectory-level）的決策最佳化，包括長程規劃、狀態追蹤、中間驗證與錯誤恢復。

**5. Harness Layer：主動服務與跨平台工作流程**

最上層的 Harness Layer（控制層）負責將多領域能力整合為統一的工作流程（workflows）。它有兩大功能：

- **基於行動裝置通知的主動服務（proactive service based on mobile notifications）**：代理不再只是被動等待指令，而是監聽裝置上的數位訊號（如通知、行事曆提醒），在適當時機主動啟動有用服務（proactively initiate useful services）並建議下一步操作。
- **跨平台任務執行（cross-platform task execution）**：代理可在行動裝置與電腦之間無縫切換，並保留任務狀態與上下文。例如，當 GUI 工作流程需要外部資訊時，可呼叫 DeepSearch 進行檢索與驗證，再返回 GUI 繼續操作，避免耗時的網頁導航。

#### 實驗數據解讀

本技術報告在 MobileWorld、MobileWorld-Real、AndroidDaily、OSWorld-Verified、OSWorld-v2、WebArena、ScreenSpot-Pro 等多個基準測試（benchmarks）上進行評估，並與 Opus 4.8、Gemini 3.1 Pro、GPT-5.6 Sol 等前沿模型比較。

**1. 行動裝置使用評估（Mobile-Use Evaluation）**

- **MobileWorld**：82.1%
- **MobileWorld-Real**：92.2%
- **AndroidDaily**：97.5%

這三項結果顯示 Qwen-UI-Agent 在真實手機操作上的優勢特別明顯。MobileWorld-Real 作為真實世界行動裝置評估基準（real-world mobile use evaluation benchmark），其 92.2% 的成績遠高於一般僅在模擬環境中訓練的模型，印證了真實裝置訓練與評估對縮小模擬到真實落差（simulation-to-real gap）的關鍵作用。AndroidDaily 的 97.5% 則代表模型已能穩定完成高頻率日常流程，例如設定鬧鐘、傳送訊息、查詢天氣等。

**2. 電腦使用評估（Computer-Use Evaluation）**

- **OSWorld-Verified**：79.5%
- **OSWorld-v2 partial-progress score**：40.0%

OSWorld-Verified 的 79.5% 顯示 Qwen-UI-Agent 在桌面作業系統任務上具有與頂尖模型競爭的能力。然而 OSWorld-v2 的 partial-progress score 僅 40.0%，反映出長期任務（long-horizon tasks）與複雜多步驟桌面操作仍是顯著挑戰。partial-progress score 較低可能源於任務涉及更多中間狀態驗證、應用程式間切換與錯誤恢復，這些正是未來需要強化的方向。

**3. 瀏覽器使用與 DeepSearch 評估（Browser-Use and DeepSearch Evaluation）**

- **WebArena**：73.6%

WebArena 的 73.6% 顯示代理在網頁導航、表單填寫與資訊檢索方面表現良好，但相較於專門的瀏覽器代理仍有進步空間。DeepSearch 的整合讓代理能夠透過檢索與驗證外部資訊來補足 GUI 操作的不足，這對於需要事實查核的跨平台工作流程尤為重要。

**4. GUI 定位能力（GUI Grounding）**

- **ScreenSpot-Pro**：81.5%

ScreenSpot-Pro 測試模型在專業應用程式介面中定位可互動元素的能力。81.5% 的成績顯示 Qwen-UI-Agent 具備穩健的視覺 grounding 能力，能夠在複雜 UI 中準確識別按鈕、輸入框與選單項目，這是執行精確 GUI 操作的基礎。

**5. 綜合解讀**

整體而言，Qwen-UI-Agent 的強項在於真實行動裝置操作與跨平台整合，而在極長期桌面任務上仍有明顯瓶頸。結果也顯示混合式 GUI+CLI 動作空間與批次化動作確實提升了執行效率與任務覆蓋率，但長程決策的可靠性仍是下一代 GUI 智慧代理需要突破的核心問題。

#### 與現有研究的比較

Qwen-UI-Agent 與現有 GUI 智慧代理的主要差異可歸納為以下六個「轉變」：

**1. 從模擬環境到真實裝置執行**

多數現有行動裝置代理仍針對模擬基準（如 AndroidEnv、AITW）進行最佳化，而 Qwen-UI-Agent 直接以超過 100 台實體裝置作為訓練與評估環境。這讓它在真實世界應用（real-world use）中具備更高的泛化能力與魯棒性，特別是在處理權限對話框、通知干擾與應用程式版本差異時。

**2. 從孤立領域到跨平台工作流程**

傳統研究通常將行動裝置、桌面與網頁代理視為獨立模組。Qwen-UI-Agent 透過 Harness Layer 將這些能力整合為統一工作流程，使任務狀態能夠在不同裝置與環境間無縫傳遞。這對於現實中「在手機上收到通知 → 在電腦上處理檔案 → 在網頁上查證資訊」的場景尤為重要。

**3. 從純 GUI 操作到混合 GUI+CLI 與批次化動作**

現有 GUI 智慧代理大多只支援點擊、輸入、滑動等視覺動作。Qwen-UI-Agent 引入 CLI 執行與批次化動作，讓代理能夠在單一推理回合內完成更複雜的結構化操作，顯著提升執行效率並擴大任務覆蓋範圍。

**4. 從短期任務到可靠的長期任務完成**

透過 OnlineRL 支援超過 100 步的軌跡訓練，Qwen-UI-Agent 針對長期任務（long-horizon tasks）進行最佳化。相較於僅依賴 SFT 的模型，它在多步驟規劃、狀態追蹤與錯誤恢復方面更具優勢，但 OSWorld-v2 的 partial-progress score 也顯示這仍是未解決的難題。

**5. 從人工密集型流程到 AutoResearch 風格資料飛輪**

不同於需要大量人工標註與除錯的傳統流程，Qwen-UI-Agent 採用由代理驅動的資料飛輪，自動建構任務、診斷失敗並規劃迭代。這種設計更符合自主提升能力（autonomously improve capabilities）與最少人工投入（minimal human effort）的願景。

**6. 從被動執行到主動服務啟動**

大多數 GUI 智慧代理等待明確指令，而 Qwen-UI-Agent 透過監聽行動裝置通知等數位訊號，能夠主動啟動有用服務（proactively initiate useful services），提供更具前瞻性的使用者體驗。

**限制**

儘管有上述優勢，本研究仍存在若干限制。首先，真實裝置基礎設施成本高昂，限制了其他研究團隊的重現能力。其次，長期桌面任務的表現仍不理想，顯示錯誤恢復與中間驗證機制需要進一步強化。此外，主動服務功能涉及隱私與安全風險，如何在便利性与使用者控制之間取得平衡仍需更多研究。最後，AutoJudge 等自動評估工具在真實裝置上的可靠性雖有驗證，但對於開放式任務的判斷仍可能存在偏差。

#### 可重現性評估

從可重現性（reproducibility）角度來看，Qwen-UI-Agent 面臨較大挑戰：

**1. 開放資源狀況**

根據目前提供的技術報告內容，並未明確說明是否公開模型權重（model weights）、原始碼（source code）、訓練資料集（datasets）或環境配置。若這些資源未釋出，其他研究者將難以完全重現其結果。

**2. 硬體與基礎設施需求**

真實裝置行動環境需要超過 100 台實體裝置與相應的遠端控制、錄影與重設基礎設施，這對大多數學術實驗室而言是不可忽視的門檻。即使沙盒環境可以部分模擬，真實裝置上的訓練與評估仍難以複製。

**3. 評估工具與基準**

MobileWorld-Real 與 AutoJudge 等工具的公開程度將直接影響可重現性。若評估基準與自動判斷工具未開源，則難以驗證 92.2% 等數據在不同設定下的穩定性。

**4. 訓練規模**

OnlineRL 需要超過 10,000 個並行環境進行 rollout，這種規模的運算資源遠超一般研究單位能負擔的範圍。因此，即使方法論詳細，完整重現仍需要大量工程與計算資源。

總體而言，Qwen-UI-Agent 在方法論層面具備高度可理解性，但在實作與資源層面的可重現性較低，未來若能釋出部分模型、資料或輕量級沙盒版本，將有助於學術界進一步驗證與延伸其研究成果。

#### 未來研究方向

基於 Qwen-UI-Agent 的設計與實驗結果，以下幾個方向值得後續深入研究：

**1. 強化長期任務的錯誤恢復與中間驗證**

針對 OSWorld-v2 等長期任務表現不佳的問題，未來可發展更強大的自我驗證（self-verification）機制、檢查點（checkpoint）策略與回溯恢復（rollback recovery）能力，讓代理在執行多步驟任務時能夠及時發現並修正錯誤。

**2. 擴展真實裝置覆蓋範圍**

目前環境涵蓋超過 150 個應用程式，但真實世界中的應用程式數量與版本遠多於此。未來可進一步擴充裝置型號、作業系統版本、語言地區設定與無障礙服務（accessibility services）支援，以提升跨裝置泛化能力。

**3. 提升主動服務的安全性與隱私保護**

主動服務（proactive service）雖然能提升使用者體驗，但也帶來未經授權操作與隱私外洩的風險。未來研究可聚焦於使用者意圖推斷、風險分級、明確授權機制與可解釋的建議說明。

**4. 發展更輕量且可重現的訓練流程**

為了降低研究門檻，未來可探索模型蒸餾（distillation）、合成資料生成與少量真實裝置資料的混合訓練策略，讓更多研究單位能夠參與真實世界 GUI 智慧代理的開發。

**5. 深化 GUI 與 CLI 的協同策略**

雖然混合式 GUI+CLI 動作空間已展現潛力，但如何讓模型自動判斷何時該使用 GUI、何時該使用 CLI、如何將兩者最佳組合，仍需要更細緻的決策模型與更多實證研究。

**6. 跨平台狀態同步與多裝置協作**

未來可進一步研究如何在多個裝置間同步任務狀態、剪貼簿內容與應用程式上下文，並支援多人協作場景，讓 GUI 智慧代理真正成為跨裝置的通用執行器（general-purpose executor）。

**7. 建立更完整的真實世界評估基準**

目前真實裝置評估仍依賴部分自動化判斷工具。未來可發展更細緻、涵蓋更多日常與專業場景的真實世界基準，並結合人類評估與自動評估，以更準確地衡量代理的實用價值。

## 論文問答

**Q1：這篇技術報告主要想解決什麼問題？為什麼現有的 GUI 智慧代理還不夠實用？**  
A：本文聚焦於縮小 GUI 智慧代理在模擬基準測試與真實世界應用之間的顯著落差。雖然現有的多模態基礎模型在受控環境中表現亮眼，但它們大多針對模擬環境最佳化，難以應對真實裝置上多變的應用程式、權限對話框、即時中斷與跨平台工作流程。因此，作者提出以真實世界為中心的基礎 GUI 智慧代理，希望讓代理能真正成為現有數位裝置與服務的通用執行器。

**Q2：現有方法在真實裝置上失敗的主要原因是什麼？模擬到真實的落差表現在哪些方面？**  
A：現有方法常在模擬沙盒中訓練與評估，導致它們對真實裝置的複雜 UI 佈局、應用程式功能差異、系統權限與即時通知缺乏足夠適應力。真實手機環境還會出現廣告、彈窗、網路延遲與裝置特定互動邏輯，這些在模擬器中難以完整重現。此外，多數代理只專注單一領域，無法處理橫跨手機、電腦與網頁的連續工作流程，進一步限制了實用性。

**Q3：為什麼發展以真實世界為中心的 GUI 智慧代理很重要？它可能帶來什麼影響？**  
A：GUI 是大多數數位服務的主要入口，一個可靠的 GUI 智慧代理能讓使用者透過自然語言完成複雜任務，而無需每項服務都提供專屬 API。這不僅能降低自動化門檻，也能讓行動裝置、桌面與網頁服務無縫協作，提升個人與企業的生產力。更重要的是，若代理能主動感知數位訊號並提出下一步行動，將從被動工具轉變為主動協助使用者的智慧夥伴。

**Q4：Qwen-UI-Agent 的核心設計方法為何？它如何整合多種能力？**  
A：Qwen-UI-Agent 被設計為一個跨行動裝置、電腦使用、網頁與 DeepSearch 的基礎 GUI 智慧代理，透過統一的動作空間與 Harness 層將不同環境串接成單一工作流程。它採用 AutoResearch 風格的代理驅動資料飛輪，自動建構任務與環境、診斷失敗並規劃下一輪迭代，從而減少人工介入。再結合監督式微調、ActionRL 與 OnlineRL 三階段訓練，模型能同時修正單步錯誤並學習長期決策，支撐它在多個真實世界環境中的穩定表現。

**Q5：真實裝置行動環境在 Qwen-UI-Agent 中扮演什麼角色？它有哪些具體設計？**  
A：為了彌補模擬到真實的落差，作者建置了包含超過 100 台實體裝置與 150 個以上應用程式的真實裝置行動環境，用於任務設計、軌跡收集、線上強化學習與真實裝置評估。該環境支援高頻工作流程與較少使用的應用功能，並允許使用者在高風險操作時接管控制，兼顧安全性與覆蓋率。透過在真實裝置上直接訓練與驗證，模型能學到模擬器無法呈現的細微互動與錯誤復原策略。

**Q6：混合 GUI+CLI 與批次動作空間的設計動機與優勢是什麼？**  
A：GUI 操作雖然通用，但對於資料處理、檔案操作或批次任務而言效率較低；而隨著基礎模型程式能力的提升，CLI 成為結構化任務的自然互補。Qwen-UI-Agent 的統一動作空間讓模型能在單一回合內交錯執行 GUI 點擊、鍵盤輸入與 CLI 指令，甚至產生批次動作以減少往返次數。這種設計不僅提升執行效率，也擴大了可完成任務的範圍，使代理更接近人類靈活切換操作模式的能力。

A：它可以協助使用者完成橫跨手機、電腦與網頁的複合任務，例如根據行事曆通知主動規劃行程、在電腦上整理文件後到手機上傳送訊息，或透過 DeepSearch 查證資訊後再返回 GUI 繼續操作。由於 Harness 層會保留跨裝置的任務狀態，使用者不必反覆重述上下文。這類能力特別適合個人助理、企業流程自動化與研究資料蒐集等場景。

## 實務應用指南

### 適用場景

1. **企業端對端自動化流程**：例如業務人員需要從手機 App 收集客戶資料、傳輸到電腦進行 Excel 整理、再透過網頁後台建檔。Qwen-UI-Agent 可跨行動裝置、電腦與網頁執行，並在單一工作流程中保留上下文與任務狀態。

2. **智慧手機主動服務助理**：當手機收到航班延誤、會議提醒或物流通知時，代理可主動解析通知內容，自動開啟相關 App 查詢替代航班、傳送訊息或重新安排行事曆，無需使用者逐一下達指令。

3. **長期研究與資料彙整任務**：結合 DeepSearch 與 GUI 操作，適合需要反覆檢索外部資訊、驗證來源、下載檔案並整理成報告的任務，例如市場競品分析、學術文獻回顧或法規追蹤。

4. **跨平台軟體測試與品質驗證**：利用真實裝置環境與混合 GUI+CLI 動作空間，可在真實手機與電腦上執行長回合的回歸測試，涵蓋權限對話框、通知中斷、不同 UI 佈局等模擬環境難以覆蓋的情境。

5. **個人生產力自動化**：例如自動整理相簿、批次處理檔案重新命名、設定系統偏好、管理電子郵件與行事曆，並透過命令列執行結構化資料處理，再輔以 GUI 操作處理無法用指令完成的介面互動。

### 實作前置條件

- **資料準備**：需具備涵蓋行動裝置、電腦、網頁與 DeepSearch 的多領域任務軌跡資料；若目標為真實裝置部署，建議至少累積目標應用程式的高頻與冷門功能操作範例，並建立自動化評判機制（如 AutoJudge）以減少人工標註成本。

- **運算資源**：論文提及可支援超過一萬個並行環境進行 rollout，實務上初期至少需要可擴展的沙箱環境叢集（容器化桌面與模擬器）以及少量真實裝置叢集；線上強化學習階段需具備長軌跡（超過 100 回合）訓練能力，建議配置多 GPU 叢集與低延遲環境控制介面。

- **技術能力**：團隊需熟悉多模態大型語言模型微調、強化學習流程（SFT、ActionRL、Online RL）、Android 與桌面自動化框架（如 ADB、無障礙服務、VNC）、以及 CLI 工具鏈整合；產品化時還需具備資安、隱私與高風險操作接管機制的設計經驗。

### 實作步驟建議

1. **定義任務範圍與動作空間**：先鎖定 1–2 個高價值場景，決定需要 GUI 操作、CLI 執行或兩者混合的任務類型，並設計批次動作規範以提升單回合執行效率。

2. **建構分層環境基礎設施**：優先部署可擴展的沙箱環境進行快速迭代，再逐步接入真實裝置叢集；統一異質環境介面，使同一代理能無縫切換於行動裝置、電腦與網頁之間。

3. **啟動資料飛輪**：利用代理自動產生任務、建構環境、診斷失敗並規劃下一輪迭代，降低人工建構資料的比例；同時建立 AutoJudge 評估管線，確保軌跡品質與回饋訊號穩定。

4. **分階段訓練模型**：先以 SFT 建立基礎能力，再透過 ActionRL 修正重複出現的動作錯誤，最後以 Online RL 學習長期決策與錯誤恢復；訓練時應納入真實裝置軌跡以縮小模擬到真實的差距。

5. **開發 Harness 層與主動服務**：實作跨平台狀態保存與任務接續機制，並整合通知監聽模組，使代理能主動辨識可採取行動的時機並提出建議。

6. **產品化與持續迭代**：上線後保留使用者接管高風險操作的通道，收集真實失敗案例回流至資料飛輪，並定期以 Online RL 更新模型以適應應用程式更新與新介面佈局。

### 潛在風險與注意事項

- **模擬與真實效能落差**：在沙箱表現良好的模型不一定能在真實裝置上穩定執行，因真實環境存在權限對話框、廣告彈窗、網路延遲與 UI 版本差異。建議將真實裝置資料納入訓練與評估，並設計動態恢復機制。

- **長期任務的錯誤累積**：超過數十回合的任務容易因單一步驟錯誤而偏離目標。應在中間步驟加入驗證點與自我檢查能力，並讓模型學習如何偵測與回復錯誤狀態。

- **高風險操作的安全性**：涉及付款、刪除資料、傳送訊息或修改系統設定等操作時，必須設計明確的使用者確認或接管機制，避免代理在未經授權下執行不可逆動作。

- **隱私與合規**：真實裝置操作可能接觸個人照片、通訊紀錄與帳號資訊，需落實資料去識別化、本地執行選項與清晰的資料使用政策。

- **應用程式版本與介面漂移**：行動與網頁 App 經常更新，可能導致過往學到的 UI 定位策略失效。建議結合視覺 grounding 與語義理解，並透過持續的線上學習與資料飛輪保持模型新鮮度。

### 與其他技術的整合建議

- **RAG 與知識庫**：將 DeepSearch 與企業內部知識庫或文件檢索系統結合，使代理在執行 GUI 任務前能先查詢標準作業程序（SOP）或產品規格，減少探索成本。

- **低程式碼自動化平台**：可將 Qwen-UI-Agent 作為低程式碼平台背後的執行引擎，負責處理無法用固定 API 完成的視覺化操作，而平台則負責流程編排、審計紀錄與人機協作介面。

- **企業身分與存取管理（IAM）**：整合 SSO、角色權限與操作日誌系統，確保代理在不同裝置與服務間的執行行為可被追蹤、授權與事後稽核。

- **監控與可觀測性工具**：將代理的每回合觀察、動作與推理鏈接入現有 APM 或 SIEM 系統，便於即時偵測異常行為、分析失敗根因並支援合規報告。

- **邊緣與裝置端推論**：對於高度敏感的個人助理場景，可考慮將輕量版模型部署至邊緣裝置或手機端，僅在需要深度搜尋或複雜規劃時呼叫雲端模型。

### 給不同背景讀者的閱讀建議

**初學者**：建議先從「適用場景」與「潛在風險與注意事項」兩節讀起，理解 GUI 智慧代理能解決什麼問題、與傳統自動化有何不同，再回頭參考「實作步驟建議」建立整體流程概念，無需一開始深入強化學習或環境基礎設施細節。

**AI 工程師**：可聚焦於「實作前置條件」與「實作步驟建議」，特別留意混合 GUI+CLI 動作空間、批次動作設計、ActionRL 與 Online RL 的訓練順序，以及真實裝置環境與沙箱環境的資料配比；同時評估自身基礎設施是否支援長軌跡 rollout 與大規模並行環境。

**研究人員**：建議深入探討資料飛輪、AutoJudge 評估機制、模擬到真實的遷移問題，以及長期決策中的錯誤恢復與主動服務啟動等研究方向；這些都是目前 GUI 智慧代理從學術基準走向真實應用的核心挑戰。
