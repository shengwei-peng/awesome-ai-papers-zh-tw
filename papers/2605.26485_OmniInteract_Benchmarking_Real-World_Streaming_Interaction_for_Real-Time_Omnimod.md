## 摘要翻譯

本文提出 OmniInteract，一個針對即時全模態大型語言模型（Real-Time Omnimodal Large Language Models）的串流基準測試（Streaming Benchmark），透過對音訊視訊串流（Audio-Visual Streams）進行原生線上推論（Native Online Inference）來評估模型。不同於離線影片理解（Offline Video Understanding）或文字提示串流問答（Text-Prompted Streaming QA），OmniInteract 保留原始音訊視訊串流，並要求模型在無法取得未來內容（Future Content）的情況下，以線上方式處理該串流。使用者查詢（User Queries）與環境聲音（Ambient Sounds）均嵌入於音軌（Audio Track）中，模型必須偵測多模態觸發條件（Multimodal Triggers）、決定何時回應，並在串流進行中回答。OmniInteract 包含 250 部影片，共 1,430 個具時間定位的回應槽位（Temporally Grounded Response Slots）：其中 1,062 個涵蓋即時、主動式與巢狀情境（Real-Time, Proactive, and Nested Scenarios）的 1Q1A 槽位（1Q1A Slots），另有 368 個用於連續任務監控（Continuous Task Monitoring）與步驟引導（Step Guidance）的 1QnA 槽位（1QnA Slots）。每個槽位包含一個觸發條件（Trigger）、回應視窗（Response Window）與目標答案（Target Answer）。我們使用互動感知品質即時性 F1（Interaction-Aware Quality-Timeliness F1, IA-QTF1）、中斷診斷套件（Interruption Diagnostic Suite）與巢狀鏈結完成度分數（Nested Chain Completion Score），評估回應正確性（Response Correctness）、時機掌握（Timing）、無效輸出（Invalid Outputs）、中斷處理（Interruption Handling）與上下文連續性（Context Continuity）。實驗顯示，現有模型在串流互動方面表現仍顯薄弱，最佳整體 IA-QTF1 僅達 0.368，而最佳 1QnA IA-QTF1 僅為 0.052。針對全雙工設定（Full-Duplex Settings）中數學推理（Mathematical Reasoning）的進一步研究顯示，離線能力（Offline Capability）不一定能轉移至線上互動（Online Interaction）。程式碼與資料集將於 https://github.com/Lucky-Lance/OmniInteract 公開釋出。

### 核心貢獻（3～5點）
- 提出 OmniInteract 串流基準測試，透過對音訊視訊串流進行原生線上推論，在無法取得未來內容的條件下評估即時全模態大型語言模型的真實世界互動能力。
- 建構包含 250 部影片與 1,430 個具時間定位回應槽位的資料集，涵蓋即時、主動式與巢狀情境的 1Q1A 槽位，以及用於連續任務監控與步驟引導的 1QnA 槽位，並將使用者查詢與環境聲音均嵌入音軌以形成多模態觸發條件。
- 設計互動感知品質即時性 F1（IA-QTF1）、中斷診斷套件與巢狀鏈結完成度分數等多維評估指標，從回應正確性、時機掌握、無效輸出、中斷處理與上下文連續性全面衡量模型表現。
- 實驗證明現有模型在串流互動上仍嚴重不足，且離線能力無法直接轉移至線上互動，為全雙工導向的人機互動研究提供關鍵洞見與公開資源。

### 適合對象
從事多模態學習、即時人機互動、串流影片理解、全雙工對話系統與即時全模態大型語言模型研究的學者與工程師。

## 深度分析

#### 方法論解析

OmniInteract 的核心方法論在於建立一套能夠透過 Native Online Inference（原生線上推論）直接評估 Real-Time Omnimodal Large Language Models（即時全模態大型語言模型）的 Streaming Benchmark（串流基準測試）。與傳統將互動轉換為離線影片問答（Offline Video QA）或文字提示串流問答（Text-Prompted Streaming QA）的做法不同，OmniInteract 保留了原始的 Audio-Visual Streams（音訊視訊串流），將 Spoken Queries（口語查詢）與 Ambient Sounds（環境聲音）完整嵌入 Audio Track（音軌）之中，並要求模型在無法存取 Future Content（未來內容）的條件下進行即時處理。

為了將連續的串流互動轉化為可量化的評估單位，作者提出 Interaction Slot Formulation（互動槽位形式化）。每個 Temporally Grounded Response Slot（具時間定位的回應槽位）由三個要素構成：Trigger（觸發條件）、Response Window（回應視窗）與 Target Answer（目標答案）。這三者分別對應即時互動中的三項關鍵決策——是否存在回應機會、應於何時回應、以及回應內容為何。此形式化設計使得連續串流中的互動迴路（Interaction Loop）得以被精確測量，同時保留了互動的時間性與多模態本質。

在資料結構上，OmniInteract 包含兩個互補的互動結構。1Q1A Slots（1Q1A 槽位）共 1,062 個，涵蓋 Real-Time Scenarios（即時情境）、Proactive Scenarios（主動式情境）與 Nested Scenarios（巢狀情境），聚焦於局部化的單一回應機會；1QnA Slots（1QnA 槽位）共 368 個，則用於 Continuous Task Monitoring（連續任務監控）與 Step Guidance（步驟引導），單一指令可能隨任務推進產生多個具時間定位的回應需求。此外，資料集特別設計了 192 個中斷回應槽位（含 147 個 1Q1A 與 45 個 1QnA）以及 240 個巢狀槽位（形成 120 對），強制模型處理 Nested Interruption（巢狀中斷）與上下文恢復。

評估指標方面，OmniInteract 提出 Interaction-Aware Quality-Timeliness F1（IA-QTF1，互動感知品質即時性 F1），同時考量 Response Correctness（回應正確性）、Timing（時機掌握）與 Invalid Outputs（無效輸出）。輔以 Interruption Diagnostic Suite（IDS，中斷診斷套件）分析 Interruption Handling（中斷處理）能力，以及 Nested Chain Completion Score（NCCS，巢狀鏈結完成度分數）衡量 Context Continuity（上下文連續性）。這套指標體系突破了傳統僅評估答案語義正確性的局限，將「回應時機」與「互動控制」納入核心評量維度。

#### 實驗數據解讀

實驗結果揭示了當前全模態模型在 Streaming Interaction（串流互動）領域的嚴峻挑戰。整體而言，最佳模型的 IA-QTF1 僅達 0.368，而在 1QnA 任務上更僅有 0.052。這組數據傳達了幾項關鍵訊息：首先，即便離線多模態理解（Offline Multimodal Understanding）能力已相當成熟，一旦進入必須同步處理輸入與輸出的 Online Interaction（線上互動）場景，模型表現便急遽下滑。其次，Continuous Task Monitoring（連續任務監控）是所有情境中最具挑戰性的設定，這是因為模型必須在長時間串流中維持注意力，並產生多個精確對應時間點的回應，遠比單一即時問答困難。

作者進一步針對 Full-Duplex Settings（全雙工設定）下的 Mathematical Reasoning（數學推理）進行對照實驗，結果顯示離線推理能力並無法直接遷移至線上互動情境。當模型必須同時聆聽、思考與生成回應時，推理品質顯著劣化。這項發現凸顯了「理解能力」與「互動能力」之間存在明顯落差：強大的離線能力（Offline Capability）並不保證能轉化為穩健的即時互動表現。此外，實驗也觀察到各情境間存在顯著變異，暗示當前模型在 Trigger Detection（觸發偵測）、時機決策與中斷恢復等互動控制層面仍處於起步階段。

#### 與現有研究的比較

相較於 Existing Benchmarks（現有基準測試），OmniInteract 在多個維度上實現了關鍵性差異。根據文中 Table 1 的比較，StreamingBench、OVO-Bench、OmniMMI 與 ProactiveVideoQA 等基準雖然涵蓋影片與音訊模態，但其 Query Modality（查詢模態）均為文字（Text），且未採用模型原生的線上推論流程。PhoStream 雖支援線上評估，但使用的是自定義串流評估協定（custom streaming evaluation protocol），而非模型本身的 Native Online Inference（原生線上推論）。相對地，OmniInteract 是首個以 Audio（音訊）作為查詢模態、並透過原生線上推論進行評估的基準測試，完整覆蓋了 Real-Time（即時）、Proactive（主動式）、Nested（巢狀）、1QnA 與 Interruption（中斷）等互動類型。

在方法論層次，過往研究多將 Human–AI Interaction（人機互動）轉化為靜態的影片—文字問答對，而 OmniInteract 則保留了 Spoken Queries（口語查詢）與 Multimodal Events（多模態事件）在原始串流中的原生樣貌，使評估更貼近真實世界串流互動（Real-World Streaming Interaction）的複雜性。然而，此基準亦存在若干局限：資料集規模為 250 部影片與 1,430 個回應槽位，相較於大規模離離線資料集仍屬精緻型（ boutique-scale）設計；且 Self-Recorded Videos（自錄影片）與 Manual Annotations（人工標註）為主的建構方式，可能限制其場景多樣性與跨領域泛化性的評估廣度。此外，全雙工導向情境（Full-Duplex-Oriented Scenarios）對模型 API 的串流支援度要求極高，部分模型可能因技術架構限制而難以直接參與公平比較。

#### 可重現性評估

作為一項基準測試（Benchmarking）研究，OmniInteract 的可重現性主要建立在資料與評估程式的公開釋出。作者明確承諾 Code and datasets（程式碼與資料集）將於 GitHub 倉庫公開，這為後續研究提供了標準化的評估基礎。由於 OmniInteract 並非提出新模型架構，而是設計評估框架，因此不涉及模型權重（model weights）的釋出問題，這在某種程度上降低了重現門檻。

然而，此基準的可重現性仍面臨實務挑戰。首先，Native Online Inference（原生線上推論）要求受測模型必須具備即時串流推理的 API 或開源推論框架支援，並非所有現有的 Omnimodal（全模態）模型都公開提供此類介面。其次，IA-QTF1、IDS 與 NCCS 等指標的計算涉及時間對齊與互動邏輯判斷，若公開的評估程式未完整包含時間戳解析與音訊軌道處理細節，不同實驗室可能產生實作差異。最後，1QnA 任務中的長時程監控與 Full-Duplex Settings（全雙工設定）對運算環境的延遲與記憶體管理有嚴格要求，這些硬體與系統層面的變因也可能影響跨研究的重現一致性。

#### 未來研究方向

基於 OmniInteract 所揭示的效能缺口，未來研究可沿以下方向展開。第一，縮小 Offline Capability（離線能力）與 Online Interaction（線上互動）之間的落差是當務之急，特別需要發展能夠在 Full-Duplex Settings（全雙工設定）下同步進行感知、推理與生成的架構，例如強化記憶體機制（memory mechanisms）與非同步感知—決策—反應管線（asynchronous perception-decision-reaction pipelines）。第二，1QnA 情境的 IA-QTF1 僅 0.052，顯示 Continuous Task Monitoring（連續任務監控）與長時程 Step Guidance（步驟引導）是極待突破的瓶頸，未來可探索針對長時串流的強化學習（multi-turn reinforcement learning）或動態壓縮（dynamic compression）技術，以提升模型在長時間互動中的時間定位精準度。

第三，Interruption Handling（中斷處理）與 Nested Scenarios（巢狀情境）要求模型具備細緻的上下文管理與社交禮貌（conversational etiquette）判斷，這需要更精細的對話狀態追蹤與意圖切換模型。第四，數學推理在全雙工環境中的顯著退化，暗示需要專門針對串流情境設計的認知卸載（cognitive offloading）或思考鏈（Chain-of-Thought）調適機制，使模型能在即時壓力下維持邏輯嚴謹性。最後，在資料層面，擴充 OmniInteract 的規模至多樣化領域（如醫療照護、工業維修、教育輔導），並引入多語言口語查詢，將有助於評估真實世界全模態助理（Real-Time Omnimodal Assistants）的泛化能力與實用價值。

## 論文問答

**Q1：OmniInteract 旨在解決人機互動領域中的什麼核心問題？**

A：人機互動正從離線多模態理解轉向連續即時通訊，但現有基準測試大多僅評估離線理解或文字提示的串流問答，無法反映真實互動的動態本質。OmniInteract 旨在填補這個缺口，透過原生線上推論對連續音訊視訊串流進行評估，要求模型在無法預取未來內容的情況下即時處理串流資訊。這種設計更貼近真實世界中使用者以口語查詢、環境聲音與視覺事件交織而成的自然互動情境。

**Q2：為何現有的串流影片基準測試無法充分評估即時全模態助理？**

A：現有串流影片基準測試通常將互動轉換為影片與文字的問答對，而非保留音軌中的口語查詢與串流中的視覺事件，導致模型無需在原生多模態環境中偵測觸發條件。如表 1 所示，先前工作大多缺乏原生音訊查詢、一問多答、中斷處理與巢狀互動的評估覆蓋，無法測試模型在真實對話迴路中的表現。此外，這些方法往往允許模型使用未來內容或依賴文字提示，使其無法準確衡量即時全模態助理在連續串流中的反應與決策能力。

**Q3：相較於離線或文字提示的設定，透過原生線上串流推論進行評估為何更為重要？**

A：透過原生線上串流推論進行評估，能夠更真實地反映使用者在現實場景中以自然語言與系統互動的情況，因為口語查詢與環境聲音都保留在原始音軌中。離線評估讓模型得以存取未來內容，這與即時助理必須在當下做出反應的實際需求不符。文字提示串流問答則移除了多模態觸發偵測的挑戰，無法測試模型在原始音訊視訊串流中自主判斷回應時機與內容的關鍵能力。

**Q4：什麼是「互動槽位」（interaction slot）形式化方法，它如何使連續串流變得可評估？**

A：互動槽位是 OmniInteract 的核心評估單元，每個槽位由觸發條件、回應視窗與目標答案三個要素構成，分別對應即時互動中的三大關鍵決策。這種形式化方法讓原本連續且無邊界的全模態互動變得可測量，同時保留了其時間性與多模態本質。透過將串流拆解為具時間定位的回應機會，研究者得以精確檢驗模型是否能在正確時機產出恰當內容，而不僅僅是評估語義正確性。

**Q5：與先前基準測試相比，OmniInteract 的關鍵創新為何？**

A：OmniInteract 的關鍵創新在於保留原始音訊視訊串流的完整性，將使用者的口語查詢與環境聲音直接嵌入音軌，而非抽離為文字提示。其設計涵蓋 1Q1A 與 1QnA 兩種互動結構，並納入即時、主動式、巢狀中斷與連續任務監控等多樣情境，遠超既有基準測試的覆蓋範圍。此外，研究團隊提出互動感知品質即時性 F1（IA-QTF1）、中斷診斷套件（IDS）與巢狀鏈結完成度分數（NCCS），能同時衡量回應品質、時機掌握、無效輸出、中斷處理與上下文連續性。

**Q6：作者為何選擇將使用者查詢與環境聲音直接保留在音軌中，而非以獨立文字提示提供？**

A：作者選擇將使用者查詢與環境聲音直接保留在音軌中，是為了維持真實世界互動的原生多模態形式，避免人為簡化互動過程。這種設計強制模型必須在線上處理串流時自主執行多模態觸發偵測，且無法預先讀取未來內容，從而模擬真實助理的即時感知挑戰。如此一來，模型必須像真人助理一樣，從連續的音訊與視覺訊號中辨識何時該回應、該回應什麼，而非僅對預先給定的文字問題做出反應。

**Q7：OmniInteract 基準測試包含哪些特定情境與互動結構？**

A：OmniInteract 包含 250 部影片與 1,430 個具時間定位的回應槽位，分為 1Q1A 與 1QnA 兩大結構。1Q1A 部分涵蓋 638 個即時、184 個主動式與 240 個巢狀槽位，1QnA 部分則包含 368 個用於連續任務監控的槽位，適合評估長時間的步驟引導與錯誤提醒。此外，資料集中設有 192 個中斷回應槽位與 120 對巢狀鏈結，專門測試模型在被打斷後能否正確處理插入查詢並恢復外部上下文。

**Q8：實驗中對當前全模態模型進行評估，最重大的發現是什麼？**

A：實驗結果顯示，現有模型在串流互動方面仍然相當薄弱，最佳整體 IA-QTF1 僅達 0.368，而 1QnA 的最佳分數更是只有 0.052，顯示連續任務監控是最具挑戰性的情境。在全雙工數學推理的進一步研究中，研究團隊發現當模型必須同時聆聽與生成回應時，其推理品質會顯著下降。這些結果共同指出，目前離線多模態理解或推理的強大能力，並無法直接轉化為穩健的即時互動表現。

**Q9：針對數學推理的離線與線上比較研究，揭示了模型能力的什麼問題？**

A：針對 MiniCPM-o 在全雙工導向情境下的數學推理比較顯示，當模型必須在持續接收音訊輸入的同時進行推理並產出回應，其推理品質會大幅衰退。這項發現表明，離線環境中展現出的優異多模態理解或數學推理能力，並不會自動轉移到需要即時反應的線上互動場景。此結果凸顯了靜態評估與動態串流需求之間的關鍵落差，也說明未來模型架構必須特別針對全雙工條件進行最佳化。

**Q10：OmniInteract 所測試的能力在哪些真實世界應用中最為關鍵？**

A：OmniInteract 測試的能力對於烹飪指導、工業製程監控、醫療照護輔助與教育家教等場景至關重要，因為這些應用需要助理在使用者執行任務的同時提供即時回饋。在這些動態環境中，助理必須從連續音訊視訊串流中偵測口語指令與環境聲音，並在正確時機給予提醒或修正。此外，處理使用者臨時插話、中斷後恢復先前上下文的能力，更是自然流暢的人機協作不可或缺的要素。

**Q11：產品團隊在部署 OmniInteract 所評估的模型時，必須面對哪些工程挑戰？**

A：產品團隊在部署此類模型時，必須解決低延遲線上推論管線的工程挑戰，確保系統能同步處理串流音訊與視訊，且不能預取未來幀。他們需要建立穩健的觸發偵測機制，以區分使用者查詢、環境雜音與系統自身回應，同時避免產生無效輸出。此外，要妥善處理巢狀中斷並在長時間串流中維持上下文連續性，必須具備複雜的記憶體與狀態管理架構，這對即時全模態助理的商業化部署是一大考驗。

**Q12：OmniInteract 可能如何影響多模態 AI 與即時助理領域的未來研究與發展？**

A：OmniInteract 為原生線上串流評估建立了標準化基準，促使研究領域超越傳統的離線影片理解指標，重新定義全模態助理的評估範式。透過揭露離線能力與線上表現之間的巨大落差，它鼓勵研究者開發專為即時互動迴路最佳化的架構，而非僅將離線模型直接套用於串流場景。其對中斷、巢狀與主動式情境的全面覆蓋，也為未來的即時全模態助理設定了更高的能力門檻與研究方向。

**Q13：OmniInteract 基準測試目前有哪些已知的限制？**

A：OmniInteract 目前僅包含 250 部影片，雖涵蓋多種互動類型，但在真實世界領域的多樣性、聲學環境與文化語境方面仍有擴展空間。資料集的規模與語言種類有限，尚未涵蓋更多專業領域或多人協作場景。此外，評估機制依賴預先定義的槽位與目標答案，可能在開放式互動中無法完整涵蓋所有語意正確但表述不同的可接受答案，這是未來版本可以改進之處。

**Q14：根據實驗結果，當前模型在哪些特定情況下失敗最為嚴重？**

A：根據實驗結果，當前模型在連續任務監控（1QnA）情境下表現最差，因為它們必須在長時間串流中追蹤多個步驟並於特定時機產出多次回應，IA-QTF1 僅有 0.052。在全雙工數學推理中，同步聆聽與思考的需求也導致輸出品質顯著下滑。此外，處理巢狀中斷——即回答插入的內部查詢後能否正確恢復外部查詢的上下文——對現有系統而言仍是重大難題，顯示模型在互動控制與記憶管理方面亟待加強。

**Q15：這項工作為改善即時全模態助理指出了哪些未來研究方向？**

A：這項工作建議未來研究應發展能同時最佳化回應品質、時機掌握與中斷感知能力的端到端訓練目標，而非將這些能力分開處理。研究者需要設計在全雙工條件下——即輸入與輸出在時間上重疊時——仍能保持穩健推理的模型架構。此外，將基準測試擴展至更多元語言、更長時間的互動以及多人協作情境，對於推動即時全模態助理在真實世界中的部署與應用將至關重要。

## 實務應用指南

### 適用場景

1. **智慧居家即時助理**：透過原生音訊視訊串流監控家中環境，當使用者口語詢問「現在烤箱顯示幾度？」或環境出現異常聲響（如破碎聲）時，助理需在回應視窗內即時回應，並處理使用者的巢狀中斷提問。
2. **工業現場作業引導**：在裝配或維修流程中，以 1QnA 模式進行連續任務監控與步驟引導，例如指導技術人員組裝設備，並在偵測到錯誤操作（多模態觸發條件）時立即介入修正。
3. **遠距教育與實作輔導**：學生進行科學實驗或烹飪時，系統透過全雙工設定持續觀察串流畫面與口語對話，提供即時回饋，並允許學生中途打斷提問，再返回原有教學脈絡。
4. **無障礙輔助與生活協助**：視障或行動不便者透過穿戴式裝置串流第一視角畫面與環境聲音，助理需偵測口語查詢與環境聲音事件（如門鈴、車聲），在正確時機給予語音提示。
5. **即時客服與技術支援**：使用者透過手機鏡頭展示產品問題，客服助理在線上互動中同時理解視覺畫面與口語描述，處理使用者的中斷與追問，無需等待影片上傳完成。

### 實作前置條件

- **資料**：需蒐集具時間定位的回應槽位資料，包含觸發條件、回應視窗、目標答案；涵蓋即時、主動式、巢狀情境與連續任務監控的 1Q1A 與 1QnA 音訊視訊串流。建議至少具備數百段自錄影片與人工標註，並涵蓋環境聲音與口語查詢。
- **運算**：需支援原生線上推論的低延遲 GPU 或邊緣運算設備，具備全雙工音訊串流處理能力；推論延遲需控制在數百毫秒內，以確保互動感知品質即時性。
- **技術能力**：團隊需熟悉多模態大型語言模型的串流微調、即時系統工程（如 WebRTC、串流協定）、音訊前處理（ASR、聲音事件偵測），以及具備設計互動迴路與對話狀態管理的能力。

### 實作步驟建議

1. **定義互動槽位規格**：依據應用場景設計觸發條件（口語、視覺、聲音事件）、回應視窗（開始與結束時間）與目標答案，建立 1Q1A 與 1QnA 的標註規範。
2. **建置原生串流推論管線**：避免離線批次處理，搭建端到端音訊視訊串流輸入架構，確保模型無法存取未來內容，並支援即時解碼與生成。
3. **開發多模態觸發偵測**：整合 ASR 與聲音事件偵測（處理環境聲音中的使用者查詢）及視覺事件偵測，作為啟動回應的訊號源。
4. **實作回應時機決策機制**：設計決策模組判斷是否回應、何時回應，避免過早打斷或過晚回應，並導入 IA-QTF1 作為開發階段的驗證指標。
5. **建置中斷與巢狀互動處理**：針對全雙工導向情境，實作打斷偵測、上下文暫存與恢復機制，確保模型能完成巢狀鏈結後回到外部查詢。
6. **迭代評估與最佳化**：使用 Interruption Diagnostic Suite 與 Nested Chain Completion Score 進行系統性診斷，並針對數學推理等需要深度思考的任務，額外設計慢思考與快反應的平衡策略。

### 潛在風險與注意事項

- **離線能力無法直接遷移**：論文顯示離線多模態理解或數學推理能力未必能轉化為線上互動表現。切勿假設離線評測高分即代表串流互動表現優異，必須在真實串流環境中重新驗證。
- **全雙工下的上下文遺失與幻覺**：模型在同步聆聽與生成時，推理品質可能顯著下降。需特別注意無效輸出與上下文連續性，建議定期以人工檢視巢狀與中斷案例。
- **環境噪音與誤觸發**：環境聲音中的使用者查詢可能被掩蓋，或非查詢聲音被誤判為觸發條件。需強化音訊前處理與觸發條件的閾值調校。
- **隱私與資料蒐集倫理**：自錄影片與人工標註涉及個人隱私與肖像權，需建立去識別化流程與明確的資料使用同意機制，特別是在居家與無障礙場景中。

### 與其他技術的整合建議

- **與現有語音技術堆疊整合**：可將 OmniInteract 的評估框架與現有 ASR、TTS、語音活動偵測（VAD）模組串接，但需注意保持原生音訊互動，避免將口語查詢過早轉為文字後失去時間與語調資訊。
- **與邊緣運算及 IoT 感測器協作**：在智慧居家與工業場景中，可結合感測器資料（如溫度、動作偵測）作為輔助觸發條件，但核心互動仍應回歸音訊視訊串流的原生線上推論。
- **與 RAG 及知識庫結合**：對於需要專業知識的連續任務監控，可將即時串流理解與檢索增強生成（RAG）連動，但需確保檢索延遲不會壓縮回應視窗，導致互動感知品質即時性下降。
- **與對話管理系統（DMS）整合**：將 1QnA 的長期任務狀態交由外部 DMS 維護，讓全模態模型專注於即時感知與回應生成，透過 API 交換槽位狀態與任務進度。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先理解「離線影片理解」與「真實世界串流互動」的根本差異，重點閱讀圖一與圖二的對照，掌握 1Q1A 與 1QnA 的基本互動結構，無需深入指標公式，先建立「為何時間點與回應時機同樣重要」的直覺。
- **AI 工程師**：請聚焦於互動槽位（Slot）的設計邏輯、原生線上推論管線的建置細節，以及 IA-QTF1、IDS、NCCS 三大評估指標的程式實作方式。特別留意論文中關於全雙工設定與中斷處理的實驗設定，這些是將論文轉化為產品最關鍵的技術缺口。
- **研究人員**：建議深入分析論文提出的評估框架與現有基準測試的差異（表一），思考互動迴路的設計如何彌補當前串流影片問答的不足。可進一步探討離線能力無法遷移至線上互動的根本原因，並以此發展新的訓練目標或模型架構。
- **產品經理**：請將閱讀重心放在適用場景與實驗結果的「能力邊界」上。論文顯示目前最佳模型的 IA-QTF1 僅達 0.368，1QnA 更低至 0.052，代表即時全模態助理在連續任務監控與中斷處理上仍處於早期階段。規劃產品路線圖時，應優先選擇容錯率較高的單一回應情境，並預留充足的技術迭代空間。
