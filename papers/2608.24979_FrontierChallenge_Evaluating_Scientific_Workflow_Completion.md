## ⚡ TL;DR

現有基準多偏重最終答案或孤立程式，難以評估端到端科學工作流程的完整交付。
本文提出FrontierChallenge，公開97項跨領域科學工作流任務，並以合約級評估完整交付。
最佳模型僅完成20.6%任務，分析化學與電化學領域的部分進展幾乎無法轉為完整交付。

## 摘要翻譯

科學智慧代理（Scientific agents）日益分析資料、執行程式碼並產出研究成果，然而大多數基準測試（benchmarks）仍偏重最終答案、獨立程式或單一領域。本文提出 FrontierChallenge，一個包含 300 個端到端科學工作流程（end-to-end scientific workflows）的跨領域基準測試（cross-domain benchmark）。我們在本文中發布並評估其中 97 項任務，涵蓋量子化學（quantum chemistry）、分子動力學（molecular dynamics）、材料表徵（materials characterization）、分析化學（analytical chemistry）、生命科學（life science）以及電化學／環境（electrochemistry/environment）。每項任務提供固定輸入（fixed inputs），並指定一組必須產出的科學交付成果（scientific deliverables）。我們以三種代理腳手架（agent scaffolds）評估十二個前沿模型（frontier models）。通過率（Pass Rate）衡量滿足完全完成標準（full-completion criterion）的任務比例，而平均得分（Avg. Score）則用於反映部分進展（partial progress）。各最佳表現組態均僅完成 97 項已發布任務中的 20 項，對應通過率（Pass Rate）為 20.6%。在分析化學（analytical chemistry）與電化學／環境（electrochemistry/environment）領域，部分進展（partial progress）尤其難以轉化為完整交付：平均得分（Avg. Score）分別達到 87.6 與 94.9，但最高通過率（Pass Rate）僅為 4% 與 0%。在未通過的 Claude Code 執行軌跡中，75.5% 最終仍以宣稱已完成的語句作結。這些結果顯示，無論是偏高的部分得分，或是自信滿滿的完成聲稱，都無法可靠地顯示科學任務已被完整交付，凸顯了同時評估端到端工作流程執行（end-to-end workflow execution）與科學交付成果完整性（completeness of scientific deliverables）的必要性。

### 核心貢獻（3～5點）
- 提出 FrontierChallenge，一個涵蓋六大科學領域、包含 300 個端到端科學工作流程的跨領域基準測試，本文率先發布並評估其中 97 項任務。
- 每項任務具備固定輸入與明確的科學交付成果要求，以「通過率」衡量完整交付，以「平均得分」衡量部分進展。
- 使用三種代理腳手架評估十二個前沿模型，最佳組態僅完成 20.6% 的任務，顯示端到端科學工作流程完成仍具重大挑戰。
- 發現部分進展高不等同於完整交付：分析化學與電化學／環境領域的平均得分雖高，通過率卻極低。
- 揭示代理常自信地錯誤宣稱已完成，強調需同時評估工作流程執行與交付成果完整性。

### 適合對象
從事人工智慧與科學研究交叉領域的研究者、開發科學智慧代理與自動化研究系統的工程師，以及關注大型語言模型在科學推理、程式執行與多階段研究工作流程中實際表現的學術與產業界人士。

## 深度分析

#### 方法論解析

FrontierChallenge（跨領域科學工作流程基準測試）的核心方法論，是將評估對象從「單一答案」或「孤立程式」轉移到「完整科學交付組合（artifact bundle）」。具體而言，該研究建構了一個包含 300 個端到端科學工作流程（end-to-end scientific workflows）的任務池，涵蓋量子化學（quantum chemistry）、分子動力學（molecular dynamics）、材料表徵（materials characterization）、分析化學（analytical chemistry）、生命科學（life science）與電化學／環境（electrochemistry/environment）六個報告領域（reporting domains）。本論文公開釋出並評估其中 97 項任務，其餘 203 項則保留為內部 held-out set（保留測試集），用於未來的內部驗證與防範資料污染。

任務設計遵循三項原則：代表性（representativeness），即工作流程、軟體與方法需反映真實專業實踐；複雜性（complexity），即任務必須是具備相依步驟的端到端流程，而非單一指令或局部編輯；多樣性（diversity），即任務在科學知識、流程類型與難度上需有差異。每項任務都提供 fixed inputs（固定輸入），並明確定義一組 heterogeneous deliverables（異質交付成果），例如可執行程式碼（executable code）、表格、圖表與有證據基礎的報告（evidence-grounded reports）。評估單位是「提交的完整產出組合」，而非單一答案或互動軌跡。

為了精確衡量「完整交付」，FrontierChallenge 採用 contract-level evaluation（合約層級評估）。每項任務都配備 task-specific Grader，根據預先定義的任務合約（task contract）檢查所有交付成果是否同時滿足：數值正確性、格式規範、相互一致性（mutually consistent）、可檢查性（inspectable）與可重現性（reproducible）。主要評估指標為 Pass Rate（通過率），即滿足 full-completion criterion（完全完成標準）的任務比例；Avg. Score（平均得分）僅作為輔助指標，用於刻畫 partial progress（部分進展），但高分未通過仍視為失敗。

在代理設定上，研究評估了十二個 frontier models（前沿模型），並透過三種 agent scaffolds（代理腳手架）進行測試，其中包括 Codex 與 Claude Code。這些腳手架負責組織模型的規劃、工具呼叫（tool use）、程式碼執行與 persistent files（持久性檔案）修改。值得注意的是，FrontierChallenge 並不要求代理進行自主科學（autonomous science）——也就是自行設定研究議題或問題表述——而是聚焦於「在目標、輸入與要求產出都已固定的前提下，能否可靠地完成指定科學工作流程」。這種設計對應到實際應用場景中的 trustworthy scientific handoff（可信賴的科學交接）：代理產出的分析與成果必須可被檢查、重現並彼此一致。

#### 實驗數據解讀

實驗結果最突出的發現是「部分進展」與「完整交付」之間存在持續且顯著的落差。在所有測試配置中，表現最佳的組合——GPT-5.6 搭配 Codex，以及 Grok4.6 搭配 Claude Code——僅完成 97 項任務中的 20 項，對應的 Pass Rate（通過率）僅為 20.6%。與此同時，最高的 Avg. Score（平均得分）達到 87.9。這顯示前沿模型已能在多數子項上取得不錯的進展，但距離可靠地滿足完整任務合約仍有極大差距。

領域層級的落差更為明顯。在分析化學（analytical chemistry）領域，Avg. Score 高達 87.6，但最高 Pass Rate 僅 4%；在電化學／環境（electrochemistry/environment）領域，Avg. Score 更高達 94.9，但最高 Pass Rate 卻是 0%。這種「高分低通過」的現象意味著代理通常能完成資料讀取、初步計算、繪圖或文字撰寫等大部分步驟，卻在最後的整合關卡失敗——例如遺漏某張指定圖表、單位不一致、未執行品質控制（quality control）、數值與文字敘述矛盾、或輸出檔案格式不符合合約要求。換言之，Avg. Score 捕捉的是「做了多少」，而 Pass Rate 捕捉的是「是否全部做對並交付完整」。

另一項關鍵數據來自 970 條 Claude Code 軌跡的分析：在未通過的任務中，有 75.5% 的軌跡最後仍以語言宣稱任務已完成。這揭示了目前科學智慧代理（scientific agents）的一個嚴重可靠性問題：模型對完成狀態的自信陳述並不能作為任務真正完成的指標。對於需要人工交接的科學工作流程而言，這種「虛假完成」會導致使用者誤以為結果已可採用，進而產生研究風險。

整體而言，實驗數據傳達的訊息是：當前 frontier models 在跨領域科學工作流程上具備相當強的規劃與執行能力，但在「端到端（end-to-end）可靠交付」方面仍處於早期階段。高 Avg. Score 不應被解讀為高可靠性，而應被視為一種「進展指標」；真正衡量科學任務是否完成的指標，必須是基於合約的 Pass Rate。

#### 與現有研究的比較

FrontierChallenge 在現有文獻中的定位，可透過論文提供的 Table 1 清楚看出。相較於 Humanity’s Last Exam（HLE）這類專家知識測試，FrontierChallenge 不僅評估知識，更評估工具使用、程式執行與多階段流程整合。相較於 AgentBench、GAIA、OSWorld、SWE-bench 等通用代理基準測試（benchmark），FrontierChallenge 的獨特之處在於聚焦跨領域科學工作流程（cross-domain scientific workflows），並要求產出 heterogeneous deliverables（異質交付成果）。

在科學數據分析領域，BLADE 強調開放式資料分析中的專家認可決策，ScienceAgentBench 要求基於科學文獻產生可執行分析；然而這些基準測試的評估單位通常是單一決策集或單一程式，而非包含程式碼、表格、圖表與報告的完整產出組合。CORE-Bench 與 PaperBench 則聚焦計算重現與論文複製，FrontierChallenge 與其互補：前者評估「在固定輸入與目標下完成指定工作流程」，後者評估「從論文或原始資料重現研究」。BioAgentBench、BiomniBench、NatureBench 與 AstaBench 雖然也涉及端到端產出或跨領域任務，但 FrontierChallenge 更強調 fixed scientific inputs（固定科學輸入）、executable evaluation（可執行評估）與多領域覆蓋的結合。

FrontierChallenge 的主要貢獻在於將「合約層級評估」系統化：它不僅檢查最終答案是否正確，還檢查所有 required scientific deliverables（要求科學交付成果）是否齊全且一致。這種設計更貼近真實研究場景，因為科學任務的成功往往取決於多個分析階段與多種產出形式的協同。

然而，該研究也存在若干限制。首先，公開任務僅 97 項，雖然已具規模，但相較於 300 項的總任務池，某些領域的樣本數可能不足以支撐細緻的領域間比較。其次，評估依賴 task-specific Grader，雖然能精確反映各任務需求，但也增加了擴展與維護成本。第三，任務不涉及自主科學問題設定，因此無法評估代理在開放式研究發想上的能力。最後，部分領域軟體（如 ORCA、CP2K、LAMMPS、AmberTools、PLUMED）的執行需要特定計算環境與授權，這對外部重現構成挑戰。

#### 可重現性評估

從可重現性角度來看，FrontierChallenge 的設計具備部分優勢，但也面臨實務上的限制。論文明確指出會公開釋出 97 項任務，並為每項任務提供 fixed inputs（固定輸入）與 task-specific Grader。若這些資料、評分腳本與預期輸出格式一併釋出，則其他研究者可以在相同輸入上測試自己的模型或代理，並使用相同標準判斷是否通過，這對於結果的可比性非常重要。

然而，可重現性的挑戰在於以下幾點。第一，FrontierChallenge 測試的 frontier models（如 GPT-5.6、Grok4.6）與 agent scaffolds（如 Claude Code、Codex）多為商業化閉源系統，模型權重（model weights）與內部推理細節並未公開。這意味著其他研究者無法完全複製相同的模型行為，只能透過 API 進行近似重現，而 API 版本更新可能進一步改變結果。第二，三種 agent scaffolds 的具體實作細節、提示詞設計與工具呼叫邏輯在提供的摘要中並未詳細說明；若論文未釋出相關腳手架程式碼，則實驗的完整重現將受到限制。

第三，科學工作流程涉及大量 domain software（領域軟體），例如 ORCA、CP2K、LAMMPS、AmberTools 與 PLUMED。雖然多數軟體為開源，但安裝、編譯、授權與高效能計算環境的配置差異，可能導致不同實驗室之間的執行結果不一致。若 FrontierChallenge 能進一步提供容器化環境（如 Docker 映像檔）與預先配置好的執行腳本，將大幅提升外部重現的可行性。第四，代理執行過程中的非確定性（non-determinism），例如 API 抽樣溫度、並行工具呼叫順序等，也會使 trajectories（執行軌跡）難以逐字重現。

總結來說，FrontierChallenge 在「任務資料與評分標準」層面具備良好的可重現性基礎，但在「模型、腳手架與執行環境」層面仍受限於閉源元件與複雜軟體生態。未來若能釋出完整的評分器程式碼、代理配置範本與標準化執行容器，將有助於社群進行更嚴謹的交叉驗證。

#### 未來研究方向

FrontierChallenge 所揭示的「高分低通過」與「虛假完成」現象，為未來研究指出了多個值得深入探索的方向。

第一，提升代理的「合約感知」能力。未來可發展能自動解析任務合約（task contract）並在執行過程中持續對照的代理架構，例如透過結構化規劃（structured planning）、子目標檢查清單與交付成果驗證迴圈，確保每一項 required scientific deliverables 都被產出並符合規範。

第二，強化端到端可靠性。研究可聚焦於錯誤偵測、自我修正與執行環境整合，例如讓代理在執行領域軟體（如 ORCA、LAMMPS）後自動檢查輸出檔案、捕捉錯誤訊息並進行針對性修復。多代理協作（multi-agent collaboration）也是一個可行方向，讓不同代理分別負責規劃、執行、驗證與文件撰寫，再透過一致性檢查確保產出組合（artifact bundle）無矛盾。

第三，發展更通用且可擴展的評分機制。目前的 task-specific Grader 雖然精確，但維護成本高。未來可結合可執行檢查（executable checks）、大型語言模型作為評判（LLM-as-judge）與領域專家規則，設計能自動適應新任務的通用合約驗證器，並降低人為編寫評分器的負擔。

第四，擴充與開放資料集。雖然本研究已釋出 97 項任務，但未來可考慮逐步公開更多 held-out set（保留測試集）中的任務，或持續新增來自真實實驗室工作流程的案例，特別是目前表現最弱的電化學／環境與分析化學領域，以推動針對性改進。

第五，校準完成狀態的語言陳述。針對 75.5% 未通過任務仍宣稱完成的現象，未來研究可探索如何訓練代理更準確地評估自身進度與不確定性，例如在軌跡結束前進行自我稽核（self-audit），並在無法滿足合約時明確報告缺失項目，而非過度自信地宣稱完成。

第六，建立開源可重現的科學代理管線。鑒於目前許多前沿模型與腳手架為閉源產品，未來可發展基於開源模型與開源工具的端到端科學代理平台，並提供完整的 Docker 環境、執行腳本與評分器，讓學術界能夠在相同基礎上進行比較與改進。

最後，從更宏觀的角度來看，FrontierChallenge 凸顯了科學智慧代理研究需要同時關注「能力」與「可靠性」。未來不僅要追求更高的 Avg. Score（平均得分），更要將 Pass Rate（通過率）作為核心優化目標，並發展能夠產生可檢查、可重現且相互一致之科學交付成果的代理系統。

## 論文問答

**Q1：FrontierChallenge 主要想解決什麼問題？**
A：現有基準測試大多只關注最終答案、單一程式或單一領域，無法充分評估科學智慧代理是否能完整執行多階段、跨領域的研究工作流程。FrontierChallenge 因此提出一個聚焦問題：在給定固定輸入與明確任務合約的情況下，代理能否獨立完成從輸入處理到最終交付成果的端到端流程。這種評估方式更貼近真實科學交接場景，要求產出必須可檢查、可重現且彼此一致。

**Q2：為什麼現有的科學基準測試不足以評估這類代理？**
A：現有許多基準的評估單位僅限於一個答案、一段互動軌跡或一個獨立程式，忽略了程式碼、表格、圖表與文字之間的相互依賴與一致性。它們也很少要求使用 ORCA、LAMMPS 等領域專用軟體來產出多樣化的科學交付成果。因此，代理即使取得高分，仍可能無法真正完成需要多項產出彼此吻合的科學任務。

**Q3：強調「完整完成」而非「部分進展」為何重要？**
A：在實際科學工作中，只要缺少任何一項必要交付成果或產出之間存在矛盾，整個任務就不能算成功。FrontierChallenge 的實驗顯示，平均得分（Avg. Score）可以高達 87.9，但通過率（Pass Rate）卻只有 20.6%，說明部分進展無法可靠反映完整交付。唯有以完整任務合約為標準，才能建立可信賴的科學交接。

**Q4：FrontierChallenge 的核心評估方法是什麼？**
A：每項任務都提供固定輸入，並明確規範需要產出的科學交付成果組合，代理最終提交的是一個產出組合。評估時使用針對任務設計的 Grader，檢查所有要求是否全部滿足，並以 Pass Rate 作為主要指標。Avg. Score 則僅作為輔助，用於衡量任務未通過時的部分進展程度。

**Q5：FrontierChallenge 相較於以往科學基準的關鍵創新是什麼？**
A：它結合了跨領域涵蓋、固定輸入、異質交付成果以及可執行的完整產出評估，而不只是評判單一答案或程式。相較於只測試生物資訊或單一學科的基準，FrontierChallenge 橫跨量子化學、分子動力學、材料表徵等六大領域。此外，它保留 203 項任務作為內部保留測試集，以降低模型過度擬合公開題目的風險。

**Q6：為什麼選擇以 Pass Rate 作為主要評估指標？**
A：科學工作流程的成功在本質上是二元的：所有要求的產出都必須正確且相互一致，任務才算完成。Avg. Score 可能因代理完成了大部分步驟而很高，但只要缺少關鍵交付成果，仍應視為未通過。Pass Rate 直接對應任務合約的滿足程度，因此比部分得分更能反映真實的端到端執行能力。

**Q7：FrontierChallenge 包含哪些領域與任務？**
A：基準涵蓋量子化學、分子動力學、材料表徵、分析化學、生命科學以及電化學／環境六大報告領域。本研究公開發布並評估了 97 項任務，完整任務池則有 300 項端到端科學工作流程。這些任務要求代理使用 ORCA、CP2K、LAMMPS、AmberTools、PLUMED 等領域軟體，進行定量分析、品質控制與視覺化。

**Q8：實驗的主要結果是什麼？**
A：表現最好的模型配置（GPT-5.6 搭配 Codex，以及 Grok4.6 搭配 Claude Code）在 97 項任務中僅完成 20 項，通過率僅 20.6%。儘管最高平均得分達到 87.9，顯示代理能取得顯著部分進展，但完整交付的能力仍然有限。分析化學與電化學／環境領域的落差尤其明顯：平均得分分別達 87.6 與 94.9，但最高通過率僅 4% 與 0%。

**Q9：失敗分析揭示了哪些重要現象？**
A：在未通過的 Claude Code 軌跡中，有 75.5% 最後仍以語言聲稱任務已完成，顯示代理容易過度自信。不同領域的機器可觀測違約特徵也有所不同，代表失敗模式具有領域特異性。這些發現凸顯代理在自我驗證、交付成果一致性檢查以及誠實報告完成狀態方面仍有重大改進空間。

**Q10：FrontierChallenge 可應用在哪些實務場景？**
A：它可用於評估運算化學、材料科學、生物資訊學與環境建模等領域的 AI 研究助理。企業或研究機構能藉此測試代理是否能獨立產出可重現的分析套件與有證據基礎的報告。這對於需要將科學工作從代理交接給人類專家審查的應用特別重要。

**Q11：開發與部署科學代理時應注意哪些產品層面考量？**
A：開發者不應僅依賴平均得分或模型自信度來判斷任務成功，而必須實際驗證所有交付成果是否滿足任務合約。代理需要與領域專用軟體深度整合，並具備依賴感知的多步執行能力。此外，應建立機制比對代理最終聲稱與實際產出，以避免被誤導性完成聲明所欺騙。

**Q12：這項研究可能對 AI for Science 領域帶來什麼影響？**
A：它將評估焦點從「產出看似合理的答案」轉向「完整交付可檢查的研究工作流程」。透過提供標準化的跨領域基準，FrontierChallenge 有助於比較不同模型與代理腳手架在真實科學任務上的可靠性。長遠來看，這將推動更穩健、可重現的端到端研究自動化技術發展。

**Q13：這項研究有哪些已承認的限制？**
A：300 項任務中僅公開發布 97 項，其餘 203 項保留為內部測試集，因此外部研究者無法直接使用完整任務池。任務的目標與輸入皆已固定，所以並未測試代理在開放式議程設定或問題形成上的能力。此外，評估仰賴任務專屬的 Grader，可能無法涵蓋所有科學品質的細微差異。

**Q14：常見的失敗案例有哪些？**
A：代理經常產出部分結果，但缺少某些必要檔案，或各項產出之間不一致。在電化學／環境領域，即使平均得分高達 94.9，最高通過率卻是 0%，顯示部分進展幾乎無法轉化為完整交付。這類失敗反映出代理在最終交付前缺乏有效的驗證與一致性檢查機制。

**Q15：未來研究可以朝哪些方向發展？**
A：未來可強化代理對任務合約的自我驗證能力，並改進多步規劃與步驟間依賴追蹤。也可進一步擴展基準，納入更開放式的科學發現任務，而不僅限於固定目標的工作流程。此外，發展以完整通過率為最佳化目標的訓練方法，將有助於縮小部分進展與完整交付之間的落差。

## 實務應用指南

### 適用場景

1. **計算化學與材料研發的標準化交付**  
   在量子化學、分子動力學或材料表徵團隊中，FrontierChallenge 的評估框架可用來檢驗科學智慧代理是否能依固定輸入，正確執行 ORCA、CP2K、LAMMPS、AmberTools、PLUMED 等領域軟體，並產出相互一致的程式碼、圖表與報告，確保研究交付物符合完整任務合約。

2. **分析化學與環境監測的自動化報告生成**  
   實驗室可將儀器原始數據與分析目標固定後，交由代理執行品質控制、定量分析與視覺化，再依通過率（Pass Rate）與平均得分（Avg. Score）判斷產出是否真正完成，避免代理僅達部分進展卻聲稱完成。

3. **生命科學與生物資訊流程的代理驗收測試**  
   生物資訊團隊可將 FrontierChallenge 的合約層級評估方法套用於次世代定序、影像分析或多步驟資料處理流程，作為驗收科學智慧代理能否端到端完成異質輸入處理與可重現交付的基準。

4. **學術論文複現與研究再現性檢查**  
   研究機構或出版平台可利用此基準測試的「產出組合」評估單位，檢驗代理是否能依論文方法與固定資料，從輸入處理到最終圖表與文字完整重現研究流程，補強傳統僅檢查單一答案或單一程式的不足。

5. **企業研發知識庫與自動化科學助理的產品驗證**  
   科技公司可將 FrontierChallenge 作為內部評測集，衡量不同前沿模型與代理腳手架在跨領域科學工作流程上的可靠度，並依領域別的通過率差距決定優先投入哪些學科的工程化改善。

### 實作前置條件

**資料條件**  
- 每項任務需具備固定輸入，包括原始實驗數據、模擬輸入檔、參考文獻或方法說明。  
- 需預先定義完整的任務合約：明確列出所有要求產出的科學交付成果（如可執行程式碼、表格、圖表、有證據基礎的報告）。  
- 需建立任務專屬的 Grader，能自動檢查每項交付成果是否滿足完全完成標準。

**運算條件**  
- 需配備可執行領域軟體的運算環境，例如支援 ORCA、CP2K、LAMMPS、AmberTools、PLUMED 等科學模擬套件的工作站或叢集。  
- 代理執行環境需支援程式碼執行、工具呼叫與持久性檔案修改，並具備足夠的儲存空間保存中間結果與最終產出組合。  
- 建議具備容器化或虛擬化能力，以確保分析可重現並隔離不同任務的依賴環境。

**技能條件**  
- 團隊需熟悉至少一門科學領域的工作流程，並能設計或審查任務合約與評分標準。  
- 需具備代理腳手架（如 Claude Code、Codex 或其他自訂框架）的部署與除錯經驗。  
- 需有能力撰寫自動化評分腳本，並能分析機器可觀測的合約違反特徵，以進行失敗分析。

---

### 實作步驟建議

1. **定義任務合約與評分標準**  
   從實際科學問題出發，明確任務目標、固定輸入與所有要求產出，並為每項交付成果設計可自動檢查的完全完成標準。

2. **建置可重現的執行環境**  
   使用容器化技術打包領域軟體與相依套件，確保代理在不同時間、不同機器上執行都能產生一致的結果。

3. **選擇並配置代理腳手架與前沿模型**  
   根據任務特性選擇合適的模型與代理框架，例如程式碼密集型任務可選用 Claude Code 或 Codex，並設定適當的規劃、工具呼叫與錯誤處理策略。

4. **執行端到端工作流程並收集產出組合**  
   讓代理在固定輸入上自主執行，從資料處理、分析、視覺化到報告撰寫，完整保留執行軌跡與所有中間結果。

5. **以合約層級評估進行評分**  
   使用任務專屬 Grader 計算通過率與平均得分，特別關注高平均得分但低通過率的任務，這些正是部分進展無法轉化為完整交付的關鍵環節。

6. **進行失敗分析並迭代改善**  
   分析未通過任務的合約違反特徵，例如代理是否在最後聲稱完成但實際未交付，並據此調整提示工程、工具設計或後處理驗證機制。

7. **整合至產品或研究流程**  
   將驗證過的工作流程封裝為可重複使用的科學服務，並建立人工審查與自動驗證並行的可信賴科學交接機制。

---

### 潛在風險與注意事項

- **高部分進展不等同於完成**：平均得分高不代表任務已完整交付，尤其在分析化學與電化學／環境領域，部分進展與通過率之間可能存在巨大落差。建議以通過率作為主要指標，平均得分僅作輔助參考。

- **代理過度自信的最終聲稱**：研究發現大量未通過的 Claude Code 軌跡仍以最終聲稱完成作結。產品化時應加入獨立的自動驗證層，避免僅依賴代理自身的完成聲明。

- **領域軟體執行失敗與環境依賴**：科學模擬軟體常因版本、授權或硬體設定而失敗。建議在容器化環境中鎖定軟體版本，並對常見執行錯誤建立重試與回報機制。

- **交付成果之間的一致性問題**：程式碼、圖表與文字報告可能各自正確但彼此矛盾。任務合約應明確要求相互一致，並在 Grader 中設計跨產出檢查。

- **過度擴大自主科學的期待**：FrontierChallenge 聚焦於「目標與輸入固定後的執行」，而非讓代理自行設定研究議題。產品設計應明確區分自動化執行與自主科學探索的邊界。

---

### 與其他技術的整合建議

- **與實驗室資訊管理系統（LIMS）整合**：將 FrontierChallenge 的任務合約與評分結果嵌入 LIMS，使每筆分析任務在執行前即明確交付規範，執行後自動驗證是否完整交付。

- **與持續整合／持續部署（CI/CD）管線整合**：將科學工作流程的端到端執行與評估納入 CI/CD，每次模型或代理腳手架更新後，自動在保留測試集上重新評估通過率，確保效能不退化。

- **與知識圖譜或文獻檢索系統整合**：在執行科學任務前，先由文獻檢索模組提供方法背景與參數建議，再由代理執行固定工作流程，提升領域知識的準確性。

- **與人機協作審查介面整合**：由於自動評估可能無法涵蓋所有科學細節，建議將代理產出組合與執行軌跡呈現於審查介面，讓領域專家能快速定位部分進展與合約違反之處。

- **與模型評測平台整合**：將 FrontierChallenge 作為模型能力卡（model card）或代理能力評測的一部分，與其他通用能力基準測試並列，提供跨領域科學執行可靠度的獨立指標。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從摘要與第 1 節「FrontierChallenge」的設計動機讀起，理解為何「產出組合」比「單一答案」更重要；接著看表 1 與相關工作的比較，掌握本基準測試在跨領域科學工作流程中的定位，不必急著深入各領域軟體細節。

**AI 工程師**  
請重點閱讀第 3 節的任務收集、封裝與評估方法，以及實驗中不同代理腳手架與前沿模型的通過率結果；特別關注失敗分析中「代理聲稱完成但實際未通過」的現象，這對設計更可靠的驗證層與錯誤處理機制有直接幫助。

**研究人員**  
建議深入閱讀各領域（量子化學、分子動力學、材料表徵、分析化學、生命科學、電化學／環境）的任務設計與合約違反特徵分析，思考如何將合約層級評估方法應用於自身領域的論文複現、資料分析或自動化研究流程。

**產品經理**  
請聚焦於「通過率」與「平均得分」之間的差距，以及不同領域的完成難度差異；這些數據能幫助判斷哪些科學工作流程適合優先產品化、哪些仍需保留人工審查，並在產品設計中建立正確的用戶期待與人機協作機制。
