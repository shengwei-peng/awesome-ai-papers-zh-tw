# 一次前向傳遞勝過兩次：InnerZoom 實現準確且高效的 GUI 定位

**原文標題：** One Forward Beats Two: InnerZoom for Accurate and Efficient GUI Grounding

## ⚡ TL;DR

現有GUI定位需兩次前向傳遞，且中間層的目標區域證據常在座標解碼時流失，導致近失點擊與高延遲。
提出InnerZoom單次前向跨層證據橋接法，提取中間層目標線索注入後續解碼層，精準預測點擊座標。
在六項基準達最先進效能，較ZoomIn平均快28%延遲並減少29%運算量，同時提升準確率。

## 摘要翻譯

基於多模態大型語言模型（Multimodal Large Language Model, MLLM）的 GUI 定位（GUI Grounding）方法通常將目標定位（Target Localization）形式化為自迴歸座標生成（Autoregressive Coordinate Generation），使模型能夠利用 MLLM 強大的指令遵循（Instruction-following）與語意理解（Semantic Understanding）能力。然而，這種形式化要求模型在保留區域級目標證據的同時，以 GUI 點擊所要求的空間精確度（Spatial Precision）來解碼座標權杖（Coordinate Tokens）。我們的診斷分析顯示，目標區域感知（Target-region Awareness）會在中間解碼器層（Intermediate Decoder Layers）浮現，但既未被保留，也未轉化為最終座標預測。現有的 ZoomIn 式方法（ZoomIn-style Methods）透過外部裁切（External Crop）並重新執行（Crop-and-Rerun）來解決此問題，雖能提升定位準確度，卻增加了端到端延遲（End-to-end Latency）與計算成本（Computational Cost）。為了在不增加額外成本的前提下保留兩階段縮放的準確度優勢，我們提出 InnerZoom，一個用於跨層證據橋接（Cross-layer Evidence Bridging）的單次前向傳遞框架。InnerZoom 將原始前向傳遞（Forward Pass）中的目標相關線索轉化為緊湊的跨層證據狀態（Evidence State），然後在後續的解碼器層（Decoder Layers）中保留、精煉並重新注入此狀態，以引導座標預測。廣泛的實驗結果顯示，InnerZoom-4B 在全部六項 GUI 定位基準測試上均達成最先進的效能（State-of-the-Art Performance），於 OSWorld-G 獲得 64.7，於 UI-Vision 獲得 40.2，於 OSWorld-GR 獲得 73.1，以及於 MMBench-GUI 獲得 87.6，分別超越先前最佳結果 4.1、3.2、2.9 與 2.3 分。在受控的 4B 設定下，InnerZoom 平均提升相同的監督式微調（Supervised Fine-Tuning, SFT）與強化學習（Reinforcement Learning, RL）基線 5.3 分，並平均勝過兩階段 ZoomIn 1.3 分，同時最高降低端到端延遲（End-to-end Latency）31.8%，並將兆浮點運算次數（TFLOPs）減少約 29%。程式碼與模型將公開釋出。

### 核心貢獻（3～5點）
- 揭示 MLLM 在 GUI 定位中的關鍵瓶頸：目標區域感知（Target-region Awareness）雖在中間解碼器層浮現，卻無法保留並轉化為具空間精確度的點級座標預測，形成區域到點落差（Region-to-Point Gap）。
- 提出 InnerZoom 單次前向傳遞框架，以跨層證據橋接（Cross-layer Evidence Bridging）機制取代傳統兩階段 ZoomIn 式方法，無需外部裁切與重新執行（Crop-and-Rerun）即可在模型內部保留並精煉目標證據。
- 在六項 GUI 定位基準測試達成最先進效能（State-of-the-Art Performance），於 OSWorld-G、UI-Vision、OSWorld-GR、MMBench-GUI 等基準顯著超越先前最佳表現。
- 在維持甚至提升準確度的同時，最高降低端到端延遲 31.8% 與計算成本（約 29% TFLOPs），實現準確度與效率的雙贏。

### 適合對象
從事多模態大型語言模型（MLLM）、互動式 GUI 代理程式（Interactive GUI Agents）與視覺定位研究的學者與工程師，特別是關注模型推論效率、空間精確度（Spatial Precision）與端到端延遲最佳化的讀者。

## 深度分析

#### 方法論解析

本文的核心貢獻在於識別並解決 GUI 定位（GUI Grounding）中的**區域到點落差（Region-to-Point Gap）**。現有多模態大型語言模型（MLLM）通常將目標定位（Target Localization）任務表述為**自迴歸座標生成（Autoregressive Coordinate Generation）**，利用 MLLM 的指令遵循（Instruction-following）與語意理解（Semantic Understanding）能力來生成離散座標權杖（Discrete Coordinate Tokens）。然而，這種表述存在結構性矛盾：模型必須在解碼器層（Decoder Layers）中同時維持**區域級視覺證據（Region-level Visual Evidence）**與**點級座標預測（Point-level Coordinate Prediction）**所需的空間精確度（Spatial Precision）。作者的診斷分析顯示，**目標區域感知（Target-region Awareness）**確實會在**中間解碼器層（Intermediate Decoder Layers）**浮現——透過**文字條件化視覺回應圖（Text-conditioned Visual Response Maps）**可觀察到**真實目標（Ground-truth Target）**周圍出現高度激活區域——但這些局部空間證據（Local Spatial Evidence）在後續解碼過程中逐漸衰減，未能有效轉譯為最終的點擊座標（Click Coordinate），導致模型雖能辨識正確區域，卻產生**近失點擊（Near-miss Click）**。

為了在不引入額外前向傳遞（Forward Pass）的前提下橋接此落差，作者提出 **InnerZoom**，一個單次前向傳遞的**跨層證據橋接（Cross-layer Evidence Bridging）**框架。其方法論可拆解為三個階段：

1. **證據提取（Evidence Extraction）**：在原始前向傳遞的早期至中期解碼器層，模型從自身的文字-圖像回應中識別與目標相關的**細粒度線索（Fine-grained Cues）**。這並非依賴外部視覺編碼器，而是利用解碼器內部已經激活的區域資訊。
2. **狀態壓縮（State Compression）**：將這些分散於多層的視覺特徵轉換為一個緊湊的**證據狀態（Evidence State）**。此狀態作為跨層資訊的「摘要」，避免了直接傳遞高維特徵所帶來的計算與記憶體負擔。
3. **保留、精煉與再注入（Preserve, Refine, and Reinject）**：在後續的座標解碼層中，InnerZoom 持續保留並逐步精煉此**證據狀態**，並將其重新注入解碼流程，以引導**座標權杖（Coordinate Tokens）**的生成。這使得座標生成轉變為一個**保留證據的解碼（Evidence-preserving Decoding）**過程。

與現有 **ZoomIn 式方法（ZoomIn-style Methods）**所採用的**外部裁切（External Crop）**與**裁切並重新執行（Crop-and-Rerun）**兩階段流程相比，InnerZoom 實現的是**內部縮放（Internal Zoom）**：它在單一**前向傳遞**內部完成對目標區域證據的放大與利用，無需第二次**前向傳遞**、無需額外的測試時輸入（Test-time Inputs），也無需對 GUI 螢幕截圖（GUI Screenshot）進行物理裁切與放大。這種設計從根本上消除了兩階段方法在互動式 GUI 代理程式（Interactive GUI Agents）中的延遲瓶頸。

#### 實驗數據解讀

實驗結果顯示，**InnerZoom-4B** 在六項 GUI 定位基準測試（Benchmarks）上均達到**最先進的效能（State-of-the-Art Performance）**。具體而言，其在 OSWorld-G 達到 64.7 分（超越先前最佳結果 4.1 分）、UI-Vision 達到 40.2 分（+3.2 分）、OSWorld-GR 達到 73.1 分（+2.9 分）、MMBench-GUI 達到 87.6 分（+2.3 分）。這些絕對分數的提升在已相當競爭的基準上具有顯著意義，特別是 OSWorld-G 這類需要高難度互動推理的任務，顯示 InnerZoom 不僅改善局部定位，也保留了 MLLM 的語意推理能力。

更具說服力的是控制變因比較：在相同的 4B 骨幹網路與 **SFT+RL**（**監督式微調（SFT）** + **強化學習（RL）**）訓練配置下，InnerZoom 相較於未採用跨層橋接的基線模型平均提升 5.3 分。這證明了效能增益主要來自架構創新，而非資料規模或訓練策略的差異。

與兩階段 **ZoomIn 式方法**的比較則揭示了 InnerZoom 的雙重優勢：準確度平均高出 1.3 分，同時**端到端延遲（End-to-end Latency）**降低 25.5% 至 31.8%（四項基準平均降低 28.3%），**計算成本**以 **TFLOPs**（**兆浮點運算次數**）衡量則減少約 29%。這項結果打破了「提升定位精度必須犧牲速度」的傳統權衡，證明**區域級視覺證據**的流失才是瓶頸，而非視覺編碼器本身缺乏資訊。單次**前向傳遞**透過有效的跨層資訊橋接，不僅能彌補證據衰減，更能超越需要兩次**前向傳遞**的外部放大策略。

#### 與現有研究的比較

在現有文獻中，MLLM-based GUI 定位方法大致可分為兩類：一類是直接採用**自迴歸座標生成**，將座標視為普通語言權杖進行生成；另一類則是 **ZoomIn 式方法**，透過**外部裁切**放大預測區域後重新執行推理。前者受限於**區域到點落差**，容易產生**近失點擊**；後者雖然透過**裁切並重新執行**強化了目標區域的**視覺證據**，卻以倍增的**端到端延遲**與**計算成本**為代價，對於需要即時反應的**互動式 GUI 代理程式**而言並不理想。

InnerZoom 的學術定位在於它同時解決了這兩個流派的缺陷。它保留了 MLLM 統一生成架構的簡潔性，無需修改輸入管線或引入外部視覺處理模組；同時，它又達到了甚至超越了兩階段方法的**空間精確度**。從機制上來看，這是一種「解碼器內部的注意力重分配」策略，透過**跨層證據橋接**將中間層的區域感知顯式地傳遞至輸出層。

然而，從現有文本也可推論若干潛在限制。首先，InnerZoom 假設**中間解碼器層**已經具備正確的**目標區域感知**；若模型在語意層面即誤解指令，則提取出的證據狀態可能強化錯誤區域，此時缺乏外部裁切所帶來的「二次確認」機制。其次，論文未詳細說明**證據狀態**的維度、提取層數的選擇策略，以及再注入機制對解碼器原始注意力分布的干擾程度，這些都是架構設計中的關鍵細節。此外，目前所有控制實驗均基於 4B 參數規模，InnerZoom 在更大規模 MLLM（如 7B 或 13B 以上）上的擴展性與效益遞減點尚未被驗證。

#### 可重現性評估

就可重現性（Reproducibility）而言，作者明確聲明程式碼與模型權重將公開釋出（Code and models will be publicly available），這為後續研究與應用奠定了良好基礎。實驗所採用的基準測試——包括 OSWorld-G、UI-Vision、OSWorld-GR 與 MMBench-GUI——均為公開資料集，降低了資料取得的門檻。

儘管如此，在原始碼實際釋出前，仍有若干實作細節需要社群進一步驗證。例如，**文字條件化視覺回應圖**的具體計算方式（是否基於梯度或注意力權重）、**證據狀態**的壓縮與精煉模組架構、以及跨層再注入時的特徵對齊（Feature Alignment）機制，這些都是影響重現精確度的關鍵。此外，論文提及訓練採用 **SFT+RL**，但現有片段未詳述 **RL** 階段的獎勵函數設計、探索策略與資料規模，這些訓練細節對於達到報告中的絕對分數同樣重要。整體而言，InnerZoom 具備高可重現性潛力，但其核心創新——**跨層證據橋接**——的具體工程實現仍需等待儲存庫公開後才能完整評估。

#### 未來研究方向

基於 InnerZoom 的框架，未來研究可沿以下方向深化與擴展：

1. **多目標與序列證據橋接**：當前方法聚焦於單一**點擊座標**的**目標區域感知**。未來可將**證據狀態**擴展為多區域或時序性表示，以支援多目標定位、拖曳操作或需要多步驟座標預測的複雜 GUI 任務。

2. **與強化學習的深層耦合**：現有訓練僅將 InnerZoom 視為架構插件配合標準 **SFT+RL**。未來可將**證據狀態**的不確定性或置信度直接納入 **RL** 的獎勵設計，使模型在**保留證據的解碼**過程中學會主動修正定位誤差，而非僅依賴靜態橋接。

3. **動態層級選擇與自適應精煉**：目前證據提取與再注入的層級似乎是固定的。未來可探索基於輸入複雜度或**解碼不確定性**的動態層級選擇機制，讓模型自行決定在哪些**中間解碼器層**提取**細粒度線索**，以及在後續哪些層進行再注入，以提升計算效率。

4. **跨領域泛化驗證**：除了桌面級 GUI 定位，可將 InnerZoom 應用於行動裝置介面、網頁定位（Web Grounding）或擴增實境（AR）場景中的 3D 空間點選，檢驗**跨層證據橋接**在不同解析度與互動密度下的穩健性。

5. **模型規模擴展與效率分析**：驗證 InnerZoom 在 7B、13B 乃至更大 MLLM 上的效益。隨著模型加深，**區域到點落差**的表現形式可能改變，證據狀態的設計可能需要相應調整。同時，可進一步量化證據橋接模組在超大模型中的相對開銷。

6. **可解釋性與視覺化研究**：深入分析**文字條件化視覺回應圖**在不同解碼器層的演化軌跡，理解哪些語意線索（Semantic Cues）對於觸發正確的**目標區域感知**最為關鍵，從而為 MLLM 的視覺-語言對齊研究提供新的分析視角。

## 論文問答

**Q1：什麼是 MLLM 型 GUI 定位中的「區域到點落差」（Region-to-Point Gap），它為何會導致近失點擊？**

A：區域到點落差是指在自迴歸座標生成過程中，模型雖然能於中間解碼器層辨識出正確的目標區域，卻無法將這些區域級視覺證據有效保留並轉換為精確的點級座標預測。在解碼過程中，局部空間線索會隨著離散座標權杖的生成而逐漸消退，導致模型知道目標在哪個區域，但最終輸出的點擊座標卻出現偏差。這種現象正是近失點擊的主要成因：模型找對了區域，卻因證據在層間傳遞時衰減而未能給出可執行的精確座標。

**Q2：現有的 ZoomIn 式方法如何試圖解決這個問題，又存在哪些根本性的缺點？**

A：現有的 ZoomIn 式方法透過外部裁切並重新執行（crop-and-rerun）的兩階段流程來解決此問題，即先預測粗略目標區域、裁切放大後再進行第二次前向傳遞以生成最終座標。這種方式確實能透過增強目標區域的視覺證據來提升定位準確度，但它需要額外的一次完整推論，顯著增加了端到端延遲與計算成本。對於需要即時回應的互動式 GUI 代理程式而言，這種外部縮放所帶來的延遲與 TFLOPs 負擔是不可忽視的效能瓶頸。

**Q3：為何精確且低延遲的 GUI 定位對互動式代理程式至關重要？**

A：GUI 定位是 GUI 代理程式執行使用者指令的基礎能力，任何座標偏差都可能導致點擊錯誤按鈕或遺漏關鍵輸入欄位，進而造成整個任務失敗。在互動式應用場景中，使用者期望代理程式能即時回應，過高的推論延遲會嚴重損害使用者體驗與系統的實用性。因此，同時兼顧高空間精確度與低運算延遲，是將多模態大型語言模型部署於實際 GUI 自動化環境時必須克服的核心挑戰。

**Q4：InnerZoom 的核心概念是什麼，它與 ZoomIn 式方法在本質上有何不同？**

A：InnerZoom 是一個單次前向傳遞的跨層證據橋接框架，它將傳統的外部裁切放大改為在模型內部進行「內部縮放」。具體而言，它從中間解碼器層提取目標區域證據，將其轉換為緊湊的跨層證據狀態，並在後續解碼層中持續精煉與重新注入此狀態以引導座標預測。這種設計本質上是以內部證據保留機制取代了外部裁切與第二階段前向傳遞，從而無需額外的測試時輸入或第二次推論即可達成精確定位。

**Q5：InnerZoom 具體如何實現跨層證據橋接？**

A：InnerZoom 首先利用模型自身的文字條件化視覺回應圖，在中間層辨識出與目標相關的細粒度視覺特徵，並將這些特徵壓縮為一個緊湊的證據狀態。此證據狀態會在後續的解碼層中被保留並逐步精煉，充當區域級感知與點級預測之間的持續橋樑。最後，精煉後的證據會被重新注入解碼流程，直接引導離散座標權杖的生成，確保局部空間線索能夠維持到最終輸出。

**Q6：哪些關鍵設計選擇使 InnerZoom 能同時提升準確性與效率？**

A：關鍵設計在於將豐富的視覺特徵轉換為緊湊的跨層證據狀態，從而避免引入過度的運算開銷，同時將證據精煉流程無縫整合進現有的解碼管線中。由於 InnerZoom 直接重複利用模型自身的中間層激活值，無需像 ZoomIn 式方法那樣重新處理裁切後的影像，因此消除了第二階段的冗餘計算。這種緊密整合的設計使框架能夠在減少約 29% TFLOPs 的同時，相較於兩階段 ZoomIn 進一步提升定位準確度。

**Q7：InnerZoom 在哪些基準測試上進行了評估，其關鍵量化結果為何？**

A：InnerZoom-4B 在六個 GUI 定位基準測試上進行了評估，包括 OSWorld-G、UI-Vision、OSWorld-GR 與 MMBench-GUI 等。該模型在這些測試上分別獲得 64.7、40.2、73.1 與 87.6 的分數，超越先前最佳結果達 4.1、3.2、2.9 與 2.3 個百分點。在控制變因的 4B 設定下，相較於相同的 SFT+RL 基線，InnerZoom 平均提升 5.3 分，並較兩階段 ZoomIn 平均高出 1.3 分。

**Q8：在延遲與計算成本等效率指標上，InnerZoom 相較於 ZoomIn 式方法表現如何？**

A：與兩階段 ZoomIn 方法相比，InnerZoom 最高可減少 31.8% 的端到端延遲，並降低約 29% 的 TFLOPs。這些效率增益完全來自於移除了第二次前向傳遞與外部裁切放大流程。橫跨四個基準測試的平均延遲降幅達到 28.3%，顯示 InnerZoom 無需犧牲即時性即可達成更優異的準確度。

**Q9：作者進行了哪些診斷分析來驗證區域到點落差的存在以及證據橋接的有效性？**

A：作者分析了中間解碼器層的文字條件化視覺回應圖，發現在最終座標預測之前，真實目標周圍經常會出現局部化的高啟動區域。他們進一步進行控制性調變實驗，結果顯示放大這些特定區域能顯著改善定位準確性，而同等強度的隨機權杖介入則幾乎無益甚至降低表現。這些結果確認了瓶頸並非缺乏視覺證據，而是中間層的目標區域證據未能被保留並轉化為精確的最終座標。

**Q10：InnerZoom 的單次前向設計在哪些實際應用場景中最為有利？**

A：InnerZoom 的單次前向設計對於需要即時互動的 GUI 代理程式特別有利，例如自動化軟體測試、智慧客戶服務機器人以及個人數位助理。在這些場景中，低端到端延遲至關重要，因為使用者期望代理程式能對指令做出立即回應。透過消除額外的推論階段，InnerZoom 能夠在維持高精確度的同時，實現更流暢、更高效的人機互動體驗。

**Q11：開發者在將 InnerZoom 整合進 GUI 代理系統時，應考量哪些產品層面的因素？**

A：開發者應注意到 InnerZoom 在顯著降低運算負擔的同時仍保持高準確性，這使其非常適合部署於資源受限的環境或邊緣裝置上。由於該框架僅需單次前向傳遞，系統架構得以簡化，無需額外設計外部裁切模組與第二階段排程邏輯。此外，其緊湊的證據狀態設計有助於控制解碼過程中的記憶體使用，對於擴展至複雜的多步驟 GUI 自動化工作流程具有明顯優勢。

**Q12：InnerZoom 可能如何影響多模態 GUI 代理領域的未來研究與發展？**

A：InnerZoom 提出了內部證據橋接的新典範，挑戰了精確視覺定位必須依賴外部縮放或多階段架構的既有假設。這可能啟發研究者探索 MLLM 內部跨層資訊保留的其他形式，以應對點擊以外的精細空間任務。此外，InnerZoom 證明了準確性與效率可以同時提升，這為下一代必須即時運作且高可靠性的 GUI 代理程式樹立了新的效能標準。

**Q13：InnerZoom 目前設計中存在哪些已知的或隱含的限制？**

A：雖然論文未明確詳列所有限制，但當前設計隱含地依賴中間層能夠偵測到足夠的目標區域證據，這在面對極小或被嚴重遮擋的 GUI 元素時可能不成立。此外，為了效率而設計的緊湊證據狀態，可能在壓縮過程中遺失複雜高解析度介面中的細微視覺細節。該框架目前專為座標生成任務設計，其對於邊界框迴歸等其他定位格式的直接適用性仍有待進一步驗證。

**Q14：在哪些失效情況下，InnerZoom 仍可能產生不準確的定位結果？**

A：當中間解碼器層完全無法產生有意義的目標區域啟動時，例如面對嚴重視覺混亂、語意模糊的指令或訓練期間未見過的新穎 GUI 模式，InnerZoom 仍可能失效。若初始的證據提取步驟因語意混淆而捕捉到錯誤區域，後續的精煉與重新注入過程將會傳播並放大此錯誤。此外，需要多物件推理或在動態變化介面上進行精確座標預測的任務，可能也會超出當前單次前向證據橋接機制的處理能力。

**Q15：延伸 InnerZoom 的跨層證據橋接方法，有哪些具發展潛力的未來方向？**

A：未來研究可將此跨層證據橋接機制擴展至其他精細多模態任務，例如具備空間推理的視覺問答或機器人操作定位。研究者亦可探索調適性的證據狀態壓縮技術，以在處理超高解析度螢幕時更好地保留細節，同時不增加運算負擔。另一個有前途的方向是將強化學習訊號直接整合進證據精煉過程，以進一步最佳化定位精確度與解碼效率之間的權衡。

## 實務應用指南

### 適用場景

1. **企業流程自動化（RPA）與自動化 UI 測試**：在 ERP、CRM 或內部系統中，由 AI 代理程式根據自然語言指令精準點擊特定按鈕、輸入框或選單，取代傳統基於 XPath 或 OCR 的脆弱腳本。
2. **作業系統級智慧代理程式**：部署於桌面或手機環境，讓多模態大型語言模型（MLLM）直接解析 GUI 螢幕截圖並輸出點擊座標，自動執行跨應用程式任務（如整理檔案、發送郵件）。
3. **無障礙輔助技術**：協助視障或行動不便使用者操作 GUI，透過語音指令驅動模型定位螢幕上的目標元件，並交由輔助引擎執行實際點擊。
4. **遠端桌面與雲端服務自動化**：在無法直接存取底層 DOM 或作業系統 API 的情境下（如遠端連線、遊戲畫面、舊版系統），僅憑 GUI 螢幕截圖完成精確的視覺定位與操作。
5. **即時互動式 GUI Agent**：需要低端到端延遲的場景，例如即時客服輔助、線上教學導覽，利用單次前向傳遞降低回應時間，提升使用者體驗。

### 實作前置條件

- **資料**：需準備高品質的 GUI 定位資料集，包含 GUI 螢幕截圖、自然語言指令與正規化後的點擊座標（建議採用離散座標權杖格式）。若應用於特定領域（如醫療系統、工業控制介面），需額外收集並標註 5,000 至 20,000 筆領域專屬樣本。
- **運算資源**：微調階段建議至少配置單張 NVIDIA A100 80GB 或 H100，以載入 4B 等級 MLLM 並進行監督式微調（SFT）與強化學習（RL）；推論階段可於單張 RTX 4090、A10G 或雲端 T4 執行個體運行，但需確認記憶體足以容納單次前向傳遞中的跨層證據狀態。
- **技術能力**：團隊需熟悉 PyTorch、Hugging Face Transformers 與解碼器層架構；具備多模態模型微調經驗，能理解文字條件化視覺回應圖的提取與注入邏輯；具備量化與推論加速（如 vLLM、TensorRT-LLM）經驗者更佳。

### 實作步驟建議

1. **基線模型選型與環境建置**：選定 4B 等級的 MLLM 骨幹（如 Qwen2-VL、InternVL2 或論文採用之架構），將 InnerZoom 的跨層證據橋接模組整合至解碼器層間，確保可在中間解碼器層提取區域級視覺證據。
2. **資料前處理與格式標準化**：統一 GUI 螢幕截圖輸入解析度，將點擊座標轉換為模型支援的離散座標權杖，並建立訓練/驗證集的分層抽樣，避免特定作業系統或螢幕比例過度集中。
3. **監督式微調（SFT）**：先凍結視覺編碼器，微調投影層與語言模型骨幹，使模型習得基本的指令遵循與目標定位能力。此階段可暫時關閉 InnerZoom 的證據注入，僅訓練基礎座標生成。
4. **InnerZoom 模組啟用與聯合訓練**：在 SFT 後期或第二階段，啟用證據提取器與精煉機制。於中間解碼器層（例如第 8–16 層）提取目標區域感知，壓縮為緊湊的證據狀態，並在後續解碼層逐步注入，引導點級座標預測。
5. **強化學習（RL）微調**：設計獎勵函數同時考量區域正確性與座標歐氏距離誤差，對近失點擊給予部分獎勵或懲罰，進一步縮小區域到點落差。
6. **延遲與計算成本驗證**：在開發環境模擬真實點擊流程，比較 InnerZoom（單次前向傳遞）與 ZoomIn 式方法（兩次前向傳遞）的端到端延遲與兆浮點運算次數（TFLOPs），確認延遲降低達 25% 以上且準確度提升。
7. **部署與系統整合**：將模型匯出為 ONNX 或 TensorRT 格式，整合至自動化框架（如 Selenium、Appium、PyAutoGUI 或自研 Agent），並建立座標輸出後的點擊確認與異常回退機制。

### 潛在風險與注意事項

- **解析度與 DPI 變異**：不同裝置的螢幕縮放比例與解析度會導致座標偏移，必須在資料層與推論層建立統一的正規化流程（例如將座標統一對應至 1000×1000 的虛擬畫布），並在部署時依據實際螢幕尺寸反轉換。
- **動態介面與遮擋**：網頁或 App 的動態載入、彈出視窗、廣告遮擋可能使中間解碼器層提取的視覺證據過時，建議搭配輔助的 DOM 樹或 Accessibility Tree 進行交叉驗證，避免對已消失或位移的元件執行點擊。
- **跨層證據干擾**：過度強化證據狀態的注入權重可能影響模型的其他生成能力（例如產生說明文字或下一步推理），需透過消融實驗仔細調整注入層數與閘控權重，維持統一生成能力。
- **安全與誤操作風險**：自動化點擊涉及敏感操作（如刪除檔案、確認交易），務必設計人類在環（Human-in-the-loop）確認機制，特別是在首次執行新任務或點擊高風險區域時。
- **訓練資料偏差**：若資料集中特定作業系統（如 Windows）或特定應用類型佔比過高，模型可能在 macOS 或行動裝置上產生偏差，建議訓練資料涵蓋多種平台、語言與螢幕長寬比。

### 與其他技術的整合建議

- **與 RPA 工具鏈整合**：將 InnerZoom 作為視覺定位引擎嵌入現有 RPA 平台（如 UiPath、Automation Anywhere），取代傳統基於模板比對或 OCR 的元素定位，提升對動態 UI 的適應力，同時利用單次前向傳遞降低整體流程延遲。
- **結合作業系統 Accessibility API**：在支援的平台上（Windows UI Automation、macOS Accessibility、Android AccessibilityService），將 InnerZoom 的視覺預測結果與 API 回傳的邊界框進行機率融合，當視覺證據與結構化資訊衝突時啟動備援邏輯。
- **與 LLM Agent 架構整合**：作為 ReAct / CoT 流程中的「視覺動作模組」，將 InnerZoom 輸出的點擊座標直接轉譯為 PyAutoGUI、ADB 或 AppleScript 指令，並在動作執行前加入「視覺確認」步驟，檢查目標區域是否與預期一致。
- **多模態 RAG 增強**：針對企業內部特殊介面，建立 UI 元件截圖的向量資料庫，在 InnerZoom 推論前檢索相似截圖作為 in-context example，強化模型對罕見介面元素的語意理解與空間精確度。
- **邊緣部署與模型壓縮**：搭配 INT4/INT8 量化與剪枝技術，在維持單次前向傳遞優勢的同時，進一步降低邊緣裝置的記憶體佔用；可考慮將證據狀態的維度壓縮，以適配手機或嵌入式裝置的記憶體限制。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先理解 GUI 定位的基本任務——也就是「看著 GUI 螢幕截圖，根據指令指出要點哪裡」。本論文的核心價值在於「不用看兩次，看一次就能精準點擊」。閱讀時可聚焦在圖 1 與圖 2 的概念示意，暫時跳過跨層證據橋接的數學細節，重點掌握 InnerZoom 與 ZoomIn 式方法的差異在於「內部縮放」取代了「外部裁切」。
- **AI 工程師**：請深入閱讀動機分析與方法論章節，特別關注「區域到點落差」的診斷方式與證據狀態的實作細節。實作時需留意論文中提到的控制性調變實驗，這將幫助你驗證在中間解碼器層提取的文字條件化視覺回應圖是否確實對應到真實目標，並據此調整注入層位與狀態維度。
- **研究人員**：本文的貢獻在於重新思考「座標生成是否需要額外的視覺重新觀察」。建議仔細檢視跨層證據橋接的設計空間，例如證據狀態的壓縮率、注入位置（early vs. late decoding layers）對區域感知與點級精度的權衡影響。此外，論文中使用的強化學習訓練策略與獎勵設計也值得延伸至其他精細定位任務。
- **產品經理**：請將本文視為「在準確度與延遲之間取得最佳平衡」的技術方案。重點關注實驗結果中的端到端延遲降低 25–31% 與 TFLOPs 降低約 29%，這代表互動式 GUI 代理程式的使用者體驗可顯著提升。評估導入時，請優先盤點現有自動化流程中「兩階段裁切並重新執行」所產生的時間成本，並計算改為單次前向傳遞後的 ROI。
