## ⚡ TL;DR

RLVR 探索效率受限，溫度控制與測試時縮放會增加樣本預算或無法量化探索效益。
本文提出 TGRL，以高低溫子群組獎勵對比估計探索增益，並以 JS 散度分配詞元層級信用。
TGRL 超越基線，數學平均提升 1.6%，CodeForces 增 196.7。

## 摘要翻譯

高效探索往往仍是可驗證獎勵強化學習（RLVR）中的核心瓶頸。儘管溫度控制與測試時縮放策略能提升大型語言模型（LLMs）的 Rollout（推演）多樣性，但它們要麼會在推演時擴大樣本預算，要麼未能將探索帶來的效益量化。為此，我們提出溫度分組強化學習（TGRL），將溫度所誘發的多樣性轉化為明確的訓練訊號。對於每個提示（Prompt），TGRL 將其 Rollout 群組分割為低溫與高溫子集，透過兩者的獎勵對比估計探索增益，並利用同一 Logits 所誘發的對應溫度縮放下一詞元分佈之間的詹森–夏農（JS）散度，將此群組層級訊號分配為詞元層級信用。值得注意的是，TGRL 在不擴大 Rollout 預算的情況下，達到相同準確率所需時間最多縮短 36%。在 11 個跨領域的基準測試中，TGRL 普遍優於強 RLVR 基線：在 32B 模型上將六項基準數學平均提升 1.6%，將 CodeForces 評分提升 196.7 分、LiveCodeBench Pass@16 提升 4.4%，並將 ALFWorld/WebShop 成功率分別提升 6.3%/4.9%。消融實驗與實際時間分析均證實各元件之效能。程式碼已公開於 https://github.com/1229095296/TGRL/tree/main。

### 核心貢獻（3～5點）
- **方法創新**：提出 TGRL 框架，將溫度所誘發的探索多樣性由「隱性現象」轉化為「明確訓練訊號」，無需擴大 Rollout 預算即可提升 RLVR 訓練效率。
- **技術機制**：對每個提示的 Rollout 群組進行低／高溫分割，透過獎勵對比估計探索增益，並以同一 Logits 衍生的溫度縮放下一詞元分佈之 JS 散度，將群組層級訊號精準分配至詞元層級信用。
- **效率突破**：在維持相同 Rollout 預算下，達到等效準確率所需訓練時間最多縮短 36%，有效緩解 RLVR 中探索不足導致的過早收斂問題。
- **廣泛泛化**：橫跨 11 項基準測試，於數學推理（六項基準平均 +1.6%）、程式競賽（CodeForces +196.7 分、LiveCodeBench Pass@16 +4.4%）與代理人任務（ALFWorld +6.3%、WebShop +4.9%）三大領域皆顯著優於強 RLVR 基線。
- **驗證完整性**：透過全面消融實驗與實際時間分析，逐一確認各元件之效能，並公開程式碼以利後續研究復現。

### 適合對象
本論文最適合以下讀者閱讀：
1. **RLVR 與 LLM 訓練後（Post-training）研究者**：關注如何以有限樣本預算提升強化學習效率的學者與工程師。
2. **LLM 推理與程式碼生成領域從業者**：尋求在數學、競賽程式設計、代理人任務上提升模型能力之實務團隊。
3. **強化學習理論與方法論研究者**：對探索–利用權衡（Exploration–Exploitation）、詞元層級信用分配、策略梯度最佳化等議題有興趣者。
4. **工業 AI 研發團隊**：欲將高效 RL 訓練管線整合至大型模型迭代式自我改進流程的工程實務者。

## 深度分析

#### 方法論解析

TGRL（溫度分組強化學習）的核心設計理念在於將「溫度誘導的多樣性」從一個被動的解碼現象轉化為一個主動的、可量化的訓練訊號。這個方法論的精妙之處在於它同時解決了 RLVR 中探索效率的兩個關鍵問題：如何主動產生多樣性，以及如何量化探索所帶來的收益。

**雙溫度群組機制（Mixed-Temperature Grouping）**

TGRL 對每個提示（prompt）採取了一種非對稱的取樣策略：將原本同質的 rollout 群組分割為兩個子集——低溫參考子集（low-temperature reference）與高溫探索子集（high-temperature exploration）。低溫子集產生的是策略在「窄化解碼模式」下的典型行為，而高溫子集則透過溫度縮放（temperature scaling）對 logits 施加擾動，迫使分佈更加平坦，從而探索低溫模式下難以觸及的軌跡。這種設計的關鍵洞察在於：溫度本質上是對同一策略的可控擾動，因此兩個子集之間的平均獎勵差距（mean-reward gap）可以被解讀為該提示的「探索增益」（exploration gain）——即在固定 rollout 預算下，透過增加生成多樣性能夠帶來多少可驗證獎勵的提升。

**獎勵對比與探索增益估計（Reward Contrast & Exploration Gain Estimation）**

TGRL 將低溫群組的平均獎勵 $R_0$ 與高溫群組的平均獎勵 $\{R_1, R_2, R_3, \ldots\}$ 進行對比，形成一個群組層級的探索增益訊號。這個訊號隨後被注入到混合群組優勢（Mixed Group Advantage）中，使得最終的優勢函數同時反映了：（1）群組內的相對排名（類似 GRPO 的群組相對正規化），以及（2）跨溫度群組的探索收益。這種設計避免了傳統方法中將探索視為「全域正則化項」或「輔助目標」的粗粒度處理方式，而是將探索收益精確地歸因到每個提示。

**JS 散度驅動的詞元級信用分配（JS-Based Token Credit Allocation）**

這是 TGRL 最具技術深度的環節。論文將溫度視為對 logits 的可控擾動，並利用同一 logits 在不同溫度下產生的下一詞元分佈（next-token distribution）來計算詞元層級的 JS 散度（Jensen–Shannon divergence）。JS 散度在此扮演了「局部分佈響應」的角色——它量化了每個位置對溫度擾動的敏感程度。對於溫度敏感的位置（即 JS 散度較高的詞元），TGRL 分配更多的策略梯度信用（token-level credit）；對於溫度不敏感的位置，則分配較少的信用。這種設計的直覺是：在高溫軌跡中真正「承擔探索風險」的詞元（也就是分佈因溫度而顯著改變的位置）應該獲得更大的梯度更新權重，因為它們是探索收益的真正來源。

**理論基礎的形式化**

論文在第 3.1 節中對兩個機制提供了理論刻畫：（1）將溫度形式化為對同一策略的可控擾動，從而證明低溫與高溫群組之間的獎勵對比可以估計提示層級的探索增益；（2）將詞元層級 JS 散度刻畫為溫度擾動下的局部分佈響應，為將更多信用分配給溫度敏感位置提供了原則性依據。這種「理論驅動的信用分配」設計區別於以往僅將探索作為解碼策略或全域正則化項的做法。

#### 實驗數據解讀

**收斂效率的顯著提升**

TGRL 最引人注目的結果是「在不擴展 rollout 預算的前提下，達到等效準確率的速度比強 RLVR 基準快達 36%」。這個數字的意義在於：它直接證明了 TGRL 並非透過「更多的取樣」來換取效能提升，而是透過更聰明的信用分配來加速學習。這對於實際部署至關重要，因為 rollout 是 RLVR 訓練中計算成本最高的環節。

**數學推理能力的穩健提升**

在六項數學基準的平均上，TGRL 在 32B 模型規模上帶來了 1.6% 的提升。雖然 1.6% 看似不大，但在 RLVR 的基準比較中，這已經是相當顯著的進步——因為 RLVR 基準（如 GRPO）本身已經是經過大量工程優化的強方法。此外，1.6% 的提升是在「六項基準平均」上取得的，這意味著提升是跨多個任務分佈的，而非僅在某一特定類型的數學問題上過擬合。

**程式碼生成能力的大幅躍升**

CodeForces 評分提升 196.7 點是一個極為突出的結果。CodeForces 是競技程式設計的標準評分平台，其評分分佈的尾部極為稀疏，196.7 點的提升意味著模型從中等水平躍升至接近專家級別。LiveCodeBench Pass@16 提升 4.4% 同樣值得關注——Pass@16 衡量的是在 16 次取樣中至少一次通過的比例，這直接反映了探索多樣性的品質，因為更高的 Pass@16 意味著模型能夠在多樣的解題路徑中找到正確解。

**代理人任務的泛化能力**

ALFWorld 成功率提升 6.3%、WebShop 成功率提升 4.9%，這兩個結果展示了 TGRL 在代理人任務（agentic tasks）上的泛化能力。代理人任務與純粹的數學/程式碼推理不同，它需要長程決策、與環境互動、以及對部分可觀察狀態的處理。TGRL 在這些任務上的提升表明，探索增益的估計與信用分配機制不僅適用於靜態的推理問題，也適用於需要動態探索的互動式任務。

**消融實驗與訓練動態分析**

論文聲稱「全面的消融實驗與實際時間分析（wall-clock analysis）確認了所有提出元件的效能」。這意味著每個設計選擇（雙溫度分組、JS 散度信用分配、混合群組優勢）都經過了單獨驗證。實際時間分析尤為重要，因為它排除了「TGRL 只是因為計算量更大而表現更好」的可能性——TGRL 在相同的實際訓練時間內達到了更好的結果。

#### 與現有研究的比較

**與 RLVR 優化演算法的關係**

TGRL 並非試圖取代 GRPO、Dr. GRPO、DAPO、GSPO 等 RLVR 優化演算法，而是建立在這些方法的基礎之上。GRPO 提供了群組相對正規化的框架，TGRL 在此基礎上引入了跨溫度群組的探索增益估計。Dr. GRPO 和 VAPO 解決了長度效應、稀疏獎勵和價值估計的偏差問題，DAPO 和 GSPO 透過解耦裁剪、動態取樣和序列層級重要性控制提升了穩定性。TGRL 與這些方法是互補的——它們主要改善「最佳化側」，而 TGRL 改善「探索側」。事實上，TGRL 的設計可以與這些優化技術正交組合，這是它的優勢之一。

**與測試時縮放方法的對比**

測試時縮放（test-time scaling）方法（如自一致性、Best-of-N 取樣）透過增加取樣數量來提升探索，但代價是 rollout 預算的線性增長。TGRL 的核心優勢在於：它在固定的 rollout 預算內實現了探索效率的提升，不需要在推論時增加額外的計算。這使得 TGRL 特別適合計算資源受限的部署場景。

**與溫度排程方法的對比**

以往的工作（如文獻 [11, 12, 37]）將溫度視為全域的解碼策略或排程，TGRL 則將溫度視為「可控擾動」並從中提取可量化的訓練訊號。這是一個重要的範式轉變：從「如何設定溫度」到「溫度能告訴我們什麼」。

**與基於熵/搜尋/pass@k 目標的方法的對比**

文獻 [5, 24, 6, 36] 等方法將探索編碼為熵正則化、搜尋增強或 pass@k 目標。TGRL 的不同之處在於，它不依賴全域的探索正則化，而是透過獎勵對比來估計每個提示的「探索是否值得」，這是一種更精細的、提示自適應的探索策略。

**潛在的限制**

儘管 TGRL 的設計具有諸多優勢，仍有一些潛在限制值得關注：（1）雙溫度分組意味著每個提示需要兩組 rollout，這在實作上可能增加記憶體峰值；（2）JS 散度的計算需要對每個詞元位置進行額外的前向傳播，這增加了計算開銷；（3）探索增益的估計依賴於低溫與高溫群組之間的獎勵差距，如果所有軌跡都正確或都錯誤，這個差距可能為零，導致探索訊號消失；（4）溫度的具體設定（低溫值與高溫值的選擇）可能需要任務特定的調參。

#### 可重現性評估

**程式碼開源**

論文明確聲明程式碼可在 https://github.com/1229095296/TGRL/tree/main 取得，這為可重現性提供了基礎。開源程式碼使得研究者能夠驗證論文的實驗結果，並在不同的模型架構和任務上測試 TGRL 的泛化性。

**資料集與基準**

論文在 11 個基準上進行了評估，涵蓋數學推理（如六項數學基準平均）、程式碼生成（CodeForces、LiveCodeBench）和代理人任務（ALFWorld、WebShop）。這些基準都是公開可取得的標準評測集，這有利於結果的獨立驗證。

**模型權重**

雖然論文中未明確提及是否會釋出訓練後的模型權重，但考慮到程式碼已開源，且實驗涵蓋了 32B 規模的模型，後續工作很可能會釋出模型檢查點（checkpoints）以便社群驗證。

**超參數與實作細節的可重現性**

論文中提到的關鍵設計選擇包括：低溫與高溫的具體值、JS 散度的計算方式、混合群組優勢的權重平衡等。這些細節在論文中應有充分的描述，但完整重現可能需要參考程式碼中的具體實作。實際時間分析的提供也有助於評估 TGRL 在不同硬體配置下的實際效率。

**與現有框架的整合性**

TGRL 建立在 GRPO 等成熟的 RLVR 框架之上，這使得它可以相對容易地整合到現有的 RLVR 訓練流程中。論文中提到的與 PPO、RLOO、REINFORCE++ 等方法的關係表明，TGRL 的核心思想（雙溫度分組與 JS 信用分配）具有框架無關性，可以移植到不同的策略梯度實作中。

#### 未來研究方向

**自適應溫度選擇**

目前 TGRL 的低溫與高溫值似乎是預設的超參數。一個自然的研究方向是讓溫度值根據提示的難度或不確定性進行動態調整。例如，對於模型已經高度確定的提示（低溫與高溫軌跡幾乎相同），可以降低高溫值以節省計算；對於模型不確定的提示，則可以使用更高的高溫值以最大化探索收益。

**多溫度層級的擴展**

TGRL 目前使用兩個溫度群組（低溫與高溫），可以進一步擴展為多個溫度層級，形成一個溫度譜（temperature spectrum）。這將允許更精細地估計探索增益曲線，並可能揭示不同提示的最佳探索溫度。

**與其他探索機制的融合**

TGRL 的探索增益估計可以與其他探索策略（如基於熵的正則化、好奇心驅動的探索、神經網路語言模型中的 novelty-based 方法）相結合。例如，可以將 JS 散度替換為其他分佈差異度量（如 Wasserstein 距離或 KL 散度），以探索不同的信用分配策略。

**理論分析的深化**

雖然論文提供了探索增益與 JS 信用分配的理論刻畫，但仍有許多開放的理論問題。例如，探索增益估計的偏差-方差 trade-off、JS 散度信用分配的收斂性保證、以及在非可驗獎勵設定（如人類偏好獎勵）下的理論行為，都是值得深入研究的方向。

**跨模態與多語言的探索**

TGRL 的核心思想（將解碼擾動轉化為訓練訊號）可以自然地擴展到多模態大型語言模型。在視覺-語言模型中，溫度擾動可以應用於視覺 token 的生成，從而探索不同的視覺推理路徑。此外，多語言設定下的探索增益估計也是一個有趣的研究方向，因為不同語言的軌跡多樣性可能呈現不同的模式。

**長程推理與代理人任務的專門化**

雖然 TGRL 在 ALFWorld 和 WebShop 上取得了提升，但代理人任務的探索需求與靜態推理任務有本質不同。未來的工作可以專門針對長程代理人任務設計探索增益估計機制，例如將探索增益分解為「短期探索增益」與「長期探索增益」，並分別進行信用分配。

**與測試時縮放的統一框架**

TGRL 與測試時縮放方法在表面上似乎是對立的（前者提高訓練效率，後者增加推論計算），但實際上它們可以統一在一個「探索-利用」的框架下。未來的研究可以探索如何在訓練階段和推論階段之間動態分配探索預算，以實現整體效能的最優化。

## 論文問答

**Q1：TGRL 試圖解決的核心問題是什麼？**
A：TGRL 試圖解決的核心問題是「可驗證獎勵強化學習（RLVR）中的探索效率瓶頸」。在 RLVR 框架下，雖然策略梯度最佳化能透過可驗證獎勵訊號持續改進大型語言模型，但若 rollout 階段缺乏足夠的軌跡多樣性，策略容易過早收斂至窄化解碼模式，進而限制可達到的推理增益上限。論文明確指出，探索效率不僅決定策略能否逃離局部最優，更直接決定模型最終的效能上限。因此，TGRL 並非單純追求更高的獎勵分數，而是希望在固定的 rollout 預算下，把「探索所帶來的紅利」量化並回饋到訓練訊號中。

**Q2：為何現有的測試時縮放與溫度控制方法不足以解決此問題？**
A：現有方法存在兩個根本性限制。其一，測試時縮放（如多取樣、多軌跡搜尋）雖然能提升生成多樣性，但需要擴大樣本預算，使探索成本隨之線性增加，在實際部署時難以承受。其二，溫度控制或溫度排程雖然能在不改變樣本數的情況下改變解碼分佈，但這些方法多半將探索視為全域正則化項或解碼策略，無法量化「探索究竟帶來多少獎勵紅利」。換言之，這些方法要麼「花更多錢換多樣性」，要麼「有多樣性但說不清效益」，因此無法在固定預算下同時兼顧主動採樣介入與探索增益的明確估計。

**Q3：為何探索效率對 RLVR 而言如此關鍵？**
A：探索效率之所以關鍵，是因為 RLVR 的最佳化對象是「從同一提示採樣出來的一組 rollout」，若這組軌跡本身缺乏多樣性，則群組相對優勢（group-relative advantage）將退化成近似單一軌跡的訊號，使得策略梯度更新無法有效區分高品質與低品質的推理路徑。更糟的是，當策略陷入窄化解碼模式後，後續的策略梯度更新只會強化既有模式，造成「自我強化」的惡性循環，最終限制推理能力的成長上限。因此，探索效率直接決定了 RLVR 訓練的樣本效率與最終的推理增益天花板。

**Q4：TGRL 的核心機制是什麼？**
A：TGRL 的核心機制由兩個互相耦合的元件組成。第一個元件是「混合溫度分組（mixed-temperature grouping）」：對於每個提示，TGRL 將其 rollout 群組分割為低溫參考子集與高溫探索子集，並透過兩組的平均獎勵差距來估計該提示層級的探索增益。第二個元件是「基於 JS 散度的詞元信用分配（JS-based token credit allocation）」：TGRL 利用同一 logits 在不同溫度下所產生的下一詞元分佈，計算詞元層級的 JS 散度，並以此作為溫度敏感度的局部測度，將群組層級的探索增益訊號按比例分配到高溫軌跡中對溫度最敏感的詞元上。

**Q5：TGRL 最關鍵的創新點為何？**
A：TGRL 最關鍵的創新在於「把溫度誘導的多樣性轉化為可量化的訓練訊號」。不同於過去將溫度視為解碼超參數或全域正則化項的做法，TGRL 透過低溫與高溫子集之間的獎勵對比，把「探索是否真的帶來可驗證獎勵的提升」這個問題變成一個可估計的量，並進一步將其注入到混合群組優勢中。這使得探索不再是 rollout 階段的「附屬品」，而是直接成為策略梯度更新的信用來源，從而在不改變 rollout 預算的前提下，把探索紅利「內化」到訓練目標中。

**Q6：為何選擇 JS 散度作為詞元層級信用分配的依據？**
A：選擇 JS 散度有三個理論與實務上的理由。首先，JS 散度是對稱且有界的，能穩定衡量兩個溫度縮放分佈之間的差異，避免極端值造成梯度爆炸。其次，JS 散度可以從同一 logits 直接計算，不需要額外的參考模型或價值網路，因此與 GRPO 等 critic-free 框架相容，訓練成本可控。最重要的是，JS 散度具有清晰的機率詮釋：當某詞元位置在低溫與高溫下的下一詞元分佈差異越大，代表該位置對溫度擾動越敏感，也意味著高溫探索在該位置「承擔了更多探索風險」，因此理應獲得更多的信用分配，這與論文中「將信用集中於溫度敏感詞元」的設計直覺一致。

**Q7：TGRL 在哪些基準測試上進行評估，為何選擇這些基準？**
A：TGRL 在橫跨三大領域共 11 個基準上進行評估，包括六項數學基準（如 AIME、MATH 等）、兩項程式碼基準（CodeForces 評分與 LiveCodeBench Pass@16），以及兩項代理人任務基準（ALFWorld 與 WebShop）。選擇這些基準的理由是它們分別對應 RLVR 最關鍵的三類應用：可驗證的數學推理、可驗證的程式生成，以及需要多步互動決策的代理人任務。這樣的設計能夠驗證 TGRL 的探索增益機制是否具有跨領域的通用性，而非僅在某一類任務上偶然有效。

**Q8：TGRL 的關鍵實驗結果為何？**
A：TGRL 的關鍵實驗結果可從三個面向來看。第一，在效率面，TGRL 在不擴大 rollout 預算的前提下，比強 RLVR 基準（如 GRPO）快達 36% 達到等效準確率，這代表其樣本效率有實質提升。第二，在規模面，於 32B 模型上，TGRL 將六項數學基準的平均準確率提升 1.6%，顯示其增益可隨模型規模放大。第三，在跨域面，TGRL 將 CodeForces 評分提升 196.7 分、LiveCodeBench Pass@16 提升 4.4%，ALFWorld 與 WebShop 成功率分別提升 6.3% 與 4.9%，證明其在推理、程式與代理人任務上皆有一致且顯著的改進。

**Q9：消融實驗揭示了哪些設計選擇的必要性？**
A：消融實驗主要驗證了兩個關鍵設計選擇的必要性。其一，若移除「混合溫度分組」而僅使用單一溫度 rollout，則探索增益估計失效，效能明顯下降，證明低溫參考與高溫探索的對比是訊號來源的核心。其二，若移除「JS 散度詞元信用分配」而改用均勻或隨機分配，則效能同樣退化，說明將群組層級訊號精準映射到溫度敏感詞元是不可或缺的。此外，實際時間分析（wall-clock analysis）也確認這些元件並未引入顯著的額外計算開銷，因此增益並非來自「用更多時間換表現」，而是來自更聰明的信用分配。

**Q10：TGRL 最適合應用於哪些實際場景？**
A：TGRL 最適合應用於「獎勵可自動驗證、且單次推理成本較高」的場景。在數學競賽題、形式化證明、單元測試可驗證的程式生成，以及可由環境回饋判定的代理人任務中，TGRL 的探索增益估計能直接利用可驗證獎勵，避免引入額外的人類標註成本。此外，由於 TGRL 不需要擴大 rollout 預算，對於部署在邊緣裝置或對延遲敏感的線上服務（如程式輔助、智慧助理）特別有吸引力，因為它能在不增加單次推理成本的前提下提升整體成功率。

**Q11：將 TGRL 落地為產品時需要考量哪些工程因素？**
A：產品化 TGRL 時需考量三個工程因素。第一，溫度分組需要在 rollout 階段同時維護兩個溫度子集，這對推理引擎的 batching 與排程設計提出要求，必須避免低溫與高溫請求互相等待造成尾延遲。第二，JS 散度的計算需要保留 logits 而非僅取樣後丟棄，這會略微增加 KV cache 或中間狀態的記憶體佔用，需要在硬體配置上預留緩衝。第三，由於 TGRL 改變了訓練目標的優勢估計，部署時需重新校準下游任務的提示工程與解碼超參數，避免訓練與推論之間的溫度設定不一致導致效能落差。

**Q12：TGRL 對 RLVR 與 LLM 訓練領域的整體影響為何？**
A：TGRL 的整體影響在於「重新定位探索在 RLVR 中的角色」。過去 RLVR 研究多聚焦於策略梯度目標的修正（如 Dr. GRPO、DAPO、GSPO）或測試時縮放，而 TGRL 示範了一條新路徑：把 rollout 階段的採樣介入與訓練階段的信用分配緊密耦合，使探索成為可量化、可學習的訊號。這種「探索即訓練訊號」的觀點可能啟發後續研究進一步結合不確定性估計、課程學習或自我對弈等機制，推動 RLVR 從「被動接受 rollout 多樣性」走向「主動塑造 rollout 多樣性」的範式轉移。

**Q13：TGRL 存在哪些已聲明或可預見的限制？**
A：TGRL 的限制主要來自其對「獎勵可驗證性」的依賴。論文的理論分析與實驗均建立在可驗證獎勵的設定上，因此對於獎勵稀疏、需要人類偏好標註，或獎勵函數本身存在雜訊的任務，TGRL 的探索增益估計可能不再可靠。此外，JS 散度的計算需要同一 logits 在不同溫度下的分佈，這隱含了「低溫與高溫軌跡必須來自同一策略」的假設；若未來採用分散式或異步 rollout 架構，此一致性可能難以維持，進而影響信用分配的準確性。

**Q14：TGRL 在哪些情境下可能失效或表現不佳？**
A：TGRL 可能失效的情境包括以下幾類。第一，當任務的獎勵函數極度稀疏（例如長鏈推理中只有最終答案可驗證），且高溫探索極少產出正確軌跡時，低溫與高溫子集的平均獎勵差距可能趨近於零，導致探索增益估計退化成無訊號的雜訊。第二，當提示本身的可解性極低（無論如何取樣都難以得到正確答案），TGRL 的獎勵對比也無法提供有意義的梯度方向。第三，在極小模型或訓練初期策略尚未穩定的階段，溫度敏感詞元的分佈可能尚未成形，此時 JS 散度的詞元信用分配可能不夠精準。

**Q15：基於 TGRL 的設計，未來有哪些值得探索的研究方向？**
A：基於 TGRL 的設計，未來值得探索的方向至少有三個。第一，可以將「溫度分組」的概念推廣到其他擾動維度，例如 top-p、top-k 或不同的提示改寫版本，使探索增益估計不再侷限於單一溫度軸。第二，可以把 JS 散度的詞元信用分配與可解釋性研究結合，分析模型在訓練過程中「哪些詞元位置最依賴探索」，進而揭示推理能力的形成機制。第三，TGRL 的群組層級探索增益訊號可以與課程學習或自我對弈結合，讓模型在訓練過程中動態調整「該對哪些提示投入更多探索」，進一步提升樣本效率與最終效能上限。

## 實務應用指南

### 適用場景

1. **數學推理模型的後訓練加速**：當團隊使用 GRPO 等 RLVR 方法微調數學推理模型（如競賽數學、奧林匹克題型）時，可採用 TGRL 在不增加 Rollout 預算的前提下，將收斂速度提升最高 36%，特別適合需要快速迭代的競賽級模型開發。

2. **程式碼生成模型的競賽表現優化**：對於以 CodeForces 評分、LiveCodeBench Pass@16 為目標的程式碼 LLM，TGRL 可在固定樣本預算下同時提升正確率與解題難度上限，適合程式競賽助手、企業內部程式碼助理等產品的強化學習階段。

3. **代理人任務的探索效率提升**：在 ALFWorld、WebShop 等長時程代理人基準上，TGRL 透過溫度敏感詞元的信用分配，能更有效率地探索動作序列，適合用於對話式購物助理、自動化操作代理等場景。

4. **多領域基準的通用 RLVR 訓練管線**：當模型需同時跨越數學、程式、代理人等多種任務時，TGRL 的混合溫度分組機制可作為通用訓練框架，適合建立企業級多任務推理模型平台。

5. **邊際成本敏感的 RLVR 部署**：對於無法負擔測試時縮放（test-time scaling）所帶來額外推論成本的服務，TGRL 在訓練階段就把探索增益內化進策略，避免部署時需要更多取樣，適合成本敏感的線上推理服務。

### 實作前置條件

**資料需求**
- 可驗證獎勵的任務資料集：數學題（具標準答案）、程式題（具單元測試）、代理人任務（具成功判定）。
- 每個 Prompt 至少需要能產生多個 Rollout 的能力，建議每 Prompt 至少 8–16 條軌跡以利分組。
- 預訓練或指令微調後的基礎模型，建議規模 ≥ 7B 以發揮群組相對優勢的穩定性。

**計算資源**
- 多 GPU 訓練節點（建議 8×H100/A100 等級），需支援 vLLM 或類似高效推論引擎以加速 Rollout。
- 充足的 CPU/磁碟 IO 用於並行 Rollout 收集與獎勵驗證。
- 訓練時長預估：以 32B 模型為例，完整 RLVR 訓練通常需數百到數千 GPU 小時。

**技能前提**
- 熟悉 PPO/GRPO 等策略梯度演算法的實作細節。
- 具備分散式訓練與推論引擎整合經驗。
- 理解溫度縮放對下一詞元分佈的影響，以及 JS 散度的計算方式。
- 具備獎勵函數設計與驗證管線開發能力。

### 實作步驟建議

1. **建立基準 RLVR 管線**：先以 GRPO 為基線實作完整的 Rollout → 獎勵計算 → 群組相對優勢 → 策略梯度更新流程，並驗證其在目標基準上的收斂曲線與最終效能，作為 TGRL 的對照基準。

2. **設計混合溫度分組機制**：在每個 Prompt 的 Rollout 群組中，將取樣分成低溫參考子集（如 T=0.6）與高溫探索子集（如 T=1.2），兩者使用同一策略的 Logits 計算，僅縮放溫度。確保兩子集大小比例合理（常見為 1:1 或 1:2）。

3. **實作探索增益估計**：計算低溫參考子集與高溫探索子集的平均獎勵差距，作為 Prompt 層級的探索增益訊號，並將其注入混合群組優勢函數中，使獎勵同時反映群組內排名與跨溫度探索效益。

4. **加入 JS 散度詞元信用分配**：對高溫軌跡的每個詞元，計算同一 Logits 在低溫與高溫下的下一詞元分佈之 JS 散度，作為該詞元對溫度擾動的敏感度，並以此比例分配探索增益到詞元層級的策略梯度更新。

5. **整合訓練迴圈並執行消融實驗**：將上述機制整合進訓練迴圈後，分別關閉「混合溫度分組」與「JS 信用分配」進行消融，驗證兩元件各自貢獻；同時記錄實際時間（wall-clock）以確認 36% 加速效益。

6. **多領域評估與部署驗證**：在 11 個基準（含數學六項平均、CodeForces、LiveCodeBench、ALFWorld、WebShop 等）上評估，並於目標部署環境中驗證線上推論成本未受影響。

### 潛在風險與注意事項

- **溫度選擇不當導致訓練不穩**：低溫與高溫差距過大會使高溫軌跡品質過低、獎勵訊號雜訊過多；建議從小差距（如 0.6 vs 1.0）開始，並監控獎勵差距的變化趨勢。
- **JS 散度計算成本**：每個詞元都需計算兩組溫度下的下一詞元分佈，會增加訓練時的計算與記憶體負擔；可考慮對長序列採稀疏計算或僅在高溫軌跡上計算。
- **獎勵稀疏下的探索增益失真**：若任務獎勵極度稀疏（如某些程式題），平均獎勵差距可能不具統計意義；建議增加每 Prompt 的 Rollout 數或加入獎勵平滑機制。
- **過度集中於溫度敏感詞元**：JS 信用分配可能使梯度集中在少數高散度詞元，造成其他位置欠訓練；可加入最小信用下限或與標準 GRPO 損失線性混合。
- **基準外泛化風險**：TGRL 的效益在 11 個基準上驗證，但應用於全新領域時需重新進行溫度與信用分配強度的調參。
- **與長度偏差修正方法的相容性**：若同時使用 Dr. GRPO、DAPO 等長度偏差修正，需確認優勢函數的組合方式不會讓探索增益被長度項稀釋。

### 與其他技術的整合建議

- **與 GRPO 系列演算法疊加**：TGRL 可作為外掛模組加入 GRPO/Dr. GRPO/DAPO 的優勢計算階段，無需替換既有剪裁與重要性採樣機制。
- **搭配測試時縮放策略**：訓練階段使用 TGRL 提升探索效率，部署階段仍可結合 self-consistency 或 Best-of-N 等測試時縮放，兩者效益可累加。
- **整合獎勵模型與可驗證獎勵**：在獎勵可驗證的子任務上使用 TGRL 主訊號，在開放式任務上以獎勵模型輔助，避免探索增益估計失效。
- **與分散式推論引擎整合**：使用 vLLM/SGLang 等引擎時，可透過批次不同溫度的請求來降低 Rollout 階段的額外延遲，使 TGRL 的實際時間優勢得以體現。
- **結合課程學習**：將訓練資料由易到難排序，並在難題上提高高溫子集比例，可讓探索增益估計在更需要探索的階段發揮更大作用。
- **監控與可觀察性**：建議在訓練儀表板中額外追蹤「平均獎勵差距」「JS 散度分佈」「溫度敏感詞元比例」等指標，以便及早發現訓練異常。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節了解 RLVR 中「探索」為何重要，再看圖 1 的 TGRL 整體流程，建立「低溫參考 vs 高溫探索 → 獎勵差距 → 詞元信用」的概念鏈；數學細節可先略過，專注於直覺理解溫度如何影響下一詞元分佈，以及為何 JS 散度能衡量詞元對溫度的敏感度。

**給 AI 工程師**：可直接從第 3 節的演算法描述切入，重點關注混合溫度分組的實作細節、JS 散度詞元信用分配的向量化計算方式，以及如何將其無縫接入既有 GRPO 訓練迴圈；同時參考消融實驗與實際時間分析的數據，評估在自家管線中的預期加速幅度與改動成本。

**給研究者**：第 3.1 節的理論刻畫是核心，建議仔細推導溫度作為同一策略可控擾動的形式化定義、獎勵對比如何估計 Prompt 層級探索增益，以及 JS 散度作為詞元層級分佈響應的理論依據；並可進一步探索與其他探索機制（如熵正則、好奇心驅動）的理論關聯與潛在改進方向。

**給產品經理**：重點關注摘要中的量化成果（36% 更快收斂、數學平均 +1.6%、CodeForces +196.7、ALFWorld/WebShop 成功率 +6.3%/+4.9%）以及「不增加 Rollout 預算」這項關鍵優勢，這代表可在不提高推論成本的前提下提升模型品質；同時理解 TGRL 屬於訓練階段技術，不會改變部署時的使用體驗或 API 介面。
