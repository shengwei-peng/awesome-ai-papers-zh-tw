## ⚡ TL;DR

現有智能體技能多為手工或一次性生成，缺乏穩定可靠的優化機制。
SkillOpt將技能文件視為外部狀態，以優化器產生有界編輯並透過驗證閘門與學習率預算穩定訓練。

## 摘要翻譯

現今的智能體技能（Agent Skills）多為手工設計的（Hand-Crafted）、一次性生成的（One-Shot），或是透過鬆散控制的自我修訂（Self-Revision）來演化，這些方法皆不具備深度學習優化器（Deep-Learning Optimizer）般的優化行為，也無法在回饋下可靠地超越其初始表現。我們主張應將技能訓練為凍結智能體（Frozen Agent）的外部狀態（External State），並以同樣使權重空間優化（Weight-Space Optimization）得以複現的嚴謹規範來執行。據我們所知，SkillOpt 是首個針對智能體技能（Agent Skills）的系統性且可控的文本空間優化器（Text-Space Optimizer）：一個獨立的優化器模型（Optimizer Model）將評分執行軌跡（Scored Rollouts）轉換為對單一技能文件（Skill Document）的有界增刪替換編輯（Bounded Add/Delete/Replace Edits），且僅接受能確實提升保留驗證分數（Held-Out Validation Score）的編輯。文本學習率預算（Textual Learning-Rate Budget）、拒絕編輯緩衝區（Rejected-Edit Buffer），以及逐輪慢速/元更新（Epoch-Wise Slow/Meta Update）等機制，使技能訓練趨於穩定，同時在部署階段不增加任何推論時模型呼叫（Inference-Time Model Calls）。橫跨六項基準測試、七個目標模型與三種執行框架（Execution Harnesses）（直接對話（Direct Chat）、Codex、Claude Code），SkillOpt 在全部 52 個受評估的（模型、基準

## 深度分析

#### 方法論解析

SkillOpt 的核心論點是將 Agent Skills (智能體技能) 視為 Frozen Agent (凍結智能體) 的 External State (外部狀態)，並以 Deep-Learning Optimizer (深度學習優化器) 的紀律來執行 Text-Space Optimizer (文本空間優化)。不同於 Hand-Crafted (手工設計的) 或 One-Shot (一次性生成的) 技能，SkillOpt 建立了一個系統性的優化迴圈，其運作邏輯與權重空間的梯度下降高度類比，但操作對象是單一 Skill Document (技能文件) 中的自然語言內容。

優化流程由以下元件構成：

1. **軌跡採樣與證據累積**：針對目標領域，SkillOpt 反覆抽樣 Trajectory Batches (軌跡批次)，記錄 Scored Rollouts (評分執行軌跡) 中的成功與失敗案例。此處的 rollout 與 reflection batch sizes 對應深度學習中的 batch size，用於控制編輯證據的雜訊程度。

2. **結構化編輯提案**：由額外的 Frontier Language Models (前沿語言模型) 擔任 Optimizer Model (優化器模型)，將軌跡分析轉譯為 Bounded Add/Delete/Replace Edits (有界增刪替換編輯)。這些 Candidate Edits (候選編輯) 並非自由改寫，而是受限於 Textual Learning-Rate Budget (文本學習率預算) 的結構化操作，確保每次更新幅度可控，避免大型語義跳躍。

3. **保留驗證閘門（Held-Out Gate）**：每個候選技能必須通過 Held-Out Validation Score (保留驗證分數) 的嚴格篩選，僅當驗證表現「嚴格提升」時才接受編輯。這相當於深度學習中基於驗證集的 early stopping 與 model selection，防止有害提案在技能文件中累積。

4. **負回饋與長期穩定**：被拒絕的編輯存入 Rejected-Edit Buffer (拒絕編輯緩衝區)，作為後續更新的 negative feedback (負回饋)；Epoch-Wise Slow/Meta Update (逐輪慢速/元更新) 則扮演類似 momentum (動量) 的角色，將跨回合的穩定編輯方向保留下來。這兩項機制共同解決了 Self-Revision (自我修訂) 中常見的 unstable updates (不穩定更新) 問題。

5. **部署零負擔**：最終輸出為 `best_skill.md`，僅 300–2,000 tokens，部署時不增加任何 Inference-Time Model Calls (推論時模型呼叫)，Target Model (目標模型) 與 Execution Harnesses (執行框架) 保持固定。

方法論的關鍵創新在於將 Domain Adaptation (領域適應) 從 Weight Adaptation (權重適應) 或 Prompts (提示) 微調，轉化為對 Portable Natural-Language Artifact (可移植的自然語言產物) 的穩定優化。透過 Step Size (步長)、Update Direction (更新方向)、Selection Gate (選擇閘門) 等 Training-Style Controls (訓練風格控制機制)，SkillOpt 使技能文件具備可重現、可驗證、可迭代的訓練軌跡。

#### 實驗數據解讀

本研究進行了目前最廣泛的 Skill Optimization (技能優化) 評估，涵蓋六個 benchmarks（SearchQA、SpreadsheetBench、OfficeQA、DocVQA、LiveMathematicianBench、ALFWorld）、七個 Target Models（從 GPT-5.5 到小型 Qwen）以及三種 Execution Harnesses（Direct Chat (直接對話)、Codex、Claude Code）。在 52 個 (model, benchmark, harness) 評估單元中，SkillOpt 全部取得最佳或平手，呈現壓倒性的優勢。

**增益幅度分析**：
以 GPT-5.5 為例，No-Skill Accuracy (無技能準確率) 的平均提升在 Direct Chat 達 +23.5 點，Codex Agentic Loop (智能體迴圈) 達 +24.8 點，Claude Code 達 +19.1 點。其中 SpreadsheetBench 從 41.8 躍升至 80.7（+38.9 點），顯示對於需要複雜 Tool Policies (工具策略) 與 Output Constraints (輸出約束) 的領域，SkillOpt 能夠補足 Frozen Agent 的程序性知識缺口。

**基線比較**：
相較於 Human、One-Shot LLM、Trace2Skill、TextGrad、GEPA 與 EvoSkill 等基線，SkillOpt 在最強對手上平均再贏 +5.4 點。這說明單純的 Trajectory Lessons (軌跡經驗) 蒸餾（Trace2Skill）或 Prompt Optimization (提示優化)（TextGrad、GEPA）缺乏系統性的 Validation Gate 與 Edit Budget (編輯預算) 控制，難以穩定超越起點。

**遷移與泛化**：
Transfer Experiments (遷移實驗) 顯示 Skill Artifacts (技能產物) 具有實用價值：
- **Cross-Model Generalization (跨模型泛化)**：在 GPT-5.4 上訓練的 SpreadsheetBench 技能，能提升所有更小 GPT 變體的表現。
- **Cross-Harness**：Codex 訓練的試算表技能轉移至 Claude Code 仍帶來 +59.7 點增益，證明技能內容捕捉了領域本質而非框架特定雜訊。
- **Cross-Benchmark**：OlympiadBench 技能在 Omni-MATH 上產生正向增益，顯示程序性 Failure Modes (失效模式) 與領域 heuristics (啟發式) 可跨相近任務遷移。

**消融實驗**：
- Uncontrolled Rewriting 相較於 bounded textual learning 表現較差，證明 Textual Learning Rate 的必要性。
- Held-Out Gating 有效防止有害編輯累積。
- Rejected-Edit Buffer 將失敗嘗試轉為可利用的負回饋。
- Epoch-Wise Slow/Meta Update 改善長期優化軌跡，避免技能文件膨脹。

**效率特徵**：
優化後的技能僅需 1–4 次 accepted edits 即達收斂，最終文件維持 300–2,000 tokens 的緊湊性，且內容保持 procedural (程序性) 而非 instance-specific (實例特定)，兼顧可解釋性與泛化性。

#### 與現有研究的比較

現有技能適應方法大致可分為三類，SkillOpt 在每一類均提出結構性改進：

**1. 手工與一次性生成技能**
Hand-Crafted Skills 依賴專家勞力且對不同 Execution Harnesses 敏感；One-Shot LLM 生成雖然低成本，但在面對新領域或複雜 Multi-Step Execution Harnesses (多步驟執行框架) 時過於脆弱。SkillOpt 透過反覆的 rollout-validation 迴圈，確保技能「可靠地優於起點」。

**2. 鬆散控制的自我演化**
Trace2Skill 與 EvoSkill 等 Skill-Evolution (技能演化) 方法雖能從軌跡中提煉經驗，但缺乏類似深度學習的訓練紀律。相較之下，SkillOpt 明確引入：
- 類似 batch/minibatch 的證據聚合機制；
- 對應 learning rate 的 Edit Budget；
- 對應 validation set 的 Held-Out Gate；
- 對應 momentum 的 Slow/Meta Update。
這使 SkillOpt 的更新軌跡具備可預測性，避免因連續大幅跳躍導致優化歷史失效。

**3. 提示與系統配置自動調優**
TextGrad、GEPA、ABSTRAL 與 EvoTest 等屬於 Prompt Autotuning (提示自動調優) 或 Agent-Configuration Search (智能體配置搜尋)。這些方法主要針對單一 Prompts、system designs 或 full configurations，而非可重複使用的 Skill Document。SkillOpt 的差異在於將優化目標鎖定為「可移植的程序性產物」，其輸出是獨立的 `best_skill.md`，可在不同模型與框架間遷移，且不增加推論開銷。

**定位總結**：
SkillOpt 是第一個系統性的 Controllable Text-Space Optimizer (可控文本空間優化器)，它將技能學習從「經驗整理」提升為「外部狀態優化」。然而，其限制在於：
- 依賴額外的 Frontier Optimizer Model，優化階段成本較高；
- 需要足夠的 Trajectory Batches 與 Held-Out Validation Set 才能穩定運作，對低資源領域可能構成門檻；
- 目前僅針對單一 Skill Document，尚未探討多技能協作或技能庫層級的優化。

#### 可重現性評估

就本文提供的內容而言，可重現性呈現「部分開放、部分受限」的狀態。

**有利因素**：
- 使用的 benchmarks（SearchQA、SpreadsheetBench、OfficeQA、DocVQA、LiveMathematicianBench、ALFWorld、OlympiadBench、Omni-MATH）均為公開資料集，具備明確的評估指標。
- Target Models 與 Optimizer Model 均為商用 API（GPT 系列、Qwen、Claude），理論上可透過 API 復現。
- 方法論層面的演算法描述（Add/Delete/Replace Edits、Textual Learning-Rate Budget、Held-Out Gate）已足夠詳細，具備工程實作的可行性。

**不利因素**：
- 本文摘錄未提及原始碼、提示模板（prompt templates）、或超參數（如 batch size、learning rate budget 的具體數值、epoch 數量）是否公開。
- Optimizer Model 的具體版本（例如「GPT-5.5」或「GPT-5.4」在論文撰寫時的對應商業型號）與 API 參數（temperature、top-p 等）未於摘錄中揭露。
- Rejected-Edit Buffer 的儲存格式、Slow/Meta Update 的聚合邏輯、以及 edit ranking 的具體演算法細節，仍需更多附錄資訊才能精確復現。
- 部分基線（如 EvoSkill、Trace2Skill）若無開源實作，比較基準難以完全對齊。

**綜合評斷**：
本研究屬於方法論導向的開創性工作，其核心概念（將技能視為外部狀態並以深度學習紀律優化）具有高度可轉移性。然而，要達到論文宣稱的 52/52 全勝結果，仍需依賴尚未公開的實作細節與超參數調校。建議作者釋出原始碼框架與最佳化後的 Skill Artifacts，以強化社群驗證與 Cross-Model Transfer 的可比較性。

#### 未來研究方向

基於 SkillOpt 的框架，以下幾個方向值得深入探索：

**1. 多技能組合與階層式技能庫**
目前 SkillOpt 僅優化單一 Skill Document。未來可擴展至 Domain-Specific Skill Libraries (領域特定技能庫)，探討多個技能文件之間的組合、呼叫與衝突消解，甚至建立階層式的 meta-skill (元技能) 架構。

**2. 降低對前沿優化器模型的依賴**
當前系統依賴額外的 Frontier Language Models 作為 Optimizer Model。後續研究可嘗試將優化能力蒸餾至較小模型，或發展專門的 skill-editor model，以降低優化階段的成本與延遲。

**3. 理論分析文本空間優化動態**
Weight-Space Optimization 有豐富的收斂理論，但 Text-Space Optimizer 的動態仍屬黑箱。未來可針對 Bounded Edits、Validation Gate 與 Rejected-Edit Buffer 建立理論框架，分析其收斂條件與泛化邊界。

**4. 混合適應：權重與文本的聯合優化**
SkillOpt 專注於 External Text 適應。未來可探索與 Weight Adaptation 的混合模式，例如在開源模型上同時微調 Low-Rank Adapters (低秩適配器) 並優化 Skill Document，實現參數空間與文本空間的互補。

**5. 持續學習與線上技能演化**
目前的優化流程似為離線批次訓練。擴展至 online learning 情境，使 Agent Skills 能在持續互動中動態更新，同時避免 Catastrophic Forgetting (災難性遺忘)，是邁向真正 Self-Evolving Agent Skills 的關鍵。

**6. 安全性與對齊審計**
當技能可自動演化時，其內容可能產生意外的 Tool Policies 或輸出偏差。未來需建立自動化審計機制，確保優化後的 Skill Artifacts 符合安全規範，並能解釋其程序性決策。

**7. 跨模態技能優化**
當前技能聚焦自然語言程序。隨著多模態 Agent 興起，可將 SkillOpt 擴展至視覺-語言技能文件，優化圖像理解、工具使用與跨模態推理的程序性知識。

## 論文問答

**Q1：SkillOpt 旨在解決智能體技能優化領域中的什麼核心問題？**
A：當前的智能體技能主要依賴手工設計、一次性生成或鬆散控制的自我修訂，這些方法缺乏類似深度學習優化器的系統性訓練機制，無法在回饋下穩定地超越初始表現。SkillOpt 針對的核心問題在於：如果技能是智能體適應特定領域的主要介面，那麼技能文件本身就應該像模型權重一樣可被訓練與優化。然而，現有方法未能將技能編輯視為一個可控的領域適應過程，導致優化過程不可重現且容易發散，無法可靠地提升凍結智能體的任務表現。

**Q2：為何手工設計、一次性生成或現有的自我修訂方法無法可靠地提升智能體技能？**
A：手工設計的技能不僅耗費大量人力，且在面對不同的目標領域或執行框架時往往顯得脆弱；一次性生成的技能同樣缺乏迭代改進的能力，難以應對複雜的任務變化與邊界案例。至於現有的自我修訂或軌跡蒸餾方法，雖然能將執行經驗轉化為文字產物，但它們缺乏類似深度學習中的步長控制、保留驗證閘門與更新方向管理，容易產生不穩定的大幅語義跳躍。這種無控制的修訂使得技能無法保證在回饋下持續進步，甚至可能累積有害的修改，導致性能不升反降。

**Q3：將技能優化視為可控的訓練過程為何重要？**
A：隨著前沿語言模型越來越多地被部署為具備工具與驗證器的多步驟執行框架，領域適應不再僅是調整模型權重或提示詞，而是需要改進智能體收集證據、呼叫工具與遵循領域慣例的程序。技能作為可移植的自然語言產物，正是承載這些程序性知識、工具策略與輸出約束的理想介面；若缺乏系統性的優化紀律，技能將無法穩定地從執行回饋中學習。透過將技能文件視為凍結智能體的外部狀態並施以訓練風格的控制機制，我們可以在不觸及模型權重的情況下，實現可重現、可驗證且穩定的領域適應，這對閉源前沿模型尤其關鍵。

**Q4：SkillOpt 的核心方法論是什麼？**
A：SkillOpt 將技能文件視為凍結智能體的外部狀態，並引入一個獨立的前沿優化器模型，該模型負責將帶有評分的執行軌跡轉化為結構化的有界增刪替換編輯。在每次迭代中，系統會採樣軌跡批次、分析成功與失敗案例，並在文本學習率預算的約束下聚合與排序候選編輯，最後僅當候選技能在保留驗證分數上嚴格提升時，才透過選擇閘門接受該編輯。此外，被拒絕的編輯會被存入拒絕編輯緩衝區以提供負回饋，而逐輪慢速與元更新則像動量項一樣穩定長期的優化方向，確保技能訓練不會發散。

**Q5：相較於先前的技能演化方法，SkillOpt 的關鍵創新是什麼？**
A：SkillOpt 是首個系統性的可控文本空間優化器，它將深度學習優化的核心概念——如批次大小、學習率、驗證閘門與動量——操作性地類比並落實到自然語言技能的編輯過程中。不同於鬆散控制的自我修訂，SkillOpt 透過有界編輯與保留驗證確保每次更新都是穩定且可逆的，並利用被拒絕編輯的負回饋避免重複犯錯。更重要的是，優化後的產物是一個僅約三百到兩千個詞元的緊湊技能文件，部署時無需增加任何推論時模型呼叫，實現了訓練時複雜優化與部署時零成本使用的分離。

**Q6：為何 SkillOpt 選擇採用有界增刪替換編輯、保留驗證閘門與拒絕編輯緩衝區這些設計？**
A：有界編輯能防止技能文件在單次更新中出現過大的語義跳躍，確保相鄰版本之間的距離夠近，使後續的優化器呼叫仍能從過去的成功與失敗中學習有意義的優化歷史。保留驗證閘門則扮演類似機器學習中驗證集的角色，僅接受能提升獨立驗證分數的編輯，從而有效防止有害提案的累積與技能性能的退化。拒絕編輯緩衝區的設計則將失敗的編輯轉化為負回饋，讓優化器模型在後續迭代中了解哪些方向應避免，進而提升長期優化的穩定性與效率。

**Q7：SkillOpt 在哪些基準測試、目標模型與執行框架上進行了評估？**
A：本研究進行了涵蓋問答、試算表、文件、數學與具身決策等六項基準測試的系統性評估，具體包括 SearchQA、SpreadsheetBench、OfficeQA、DocVQA、LiveMathematicianBench 與 ALFWorld。目標模型橫跨七個不同規模的模型，從前沿規模的 GPT 系列到小規模的 Qwen，其中特別以 GPT-5.5 進行了詳細分析。執行框架方面則涵蓋直接對話、Codex 智能體迴圈與 Claude Code 智能體迴圈三種模式，以驗證方法在不同執行環境下的泛化能力。

**Q8：SkillOpt 取得了哪些關鍵量化成果？**
A：在五十二個評估的（模型、基準、框架）組合中，SkillOpt 全部取得最佳或並列最佳的表現，並在每一個組合中都擊敗了人類撰寫、一次性生成、Trace2Skill、TextGrad、GEPA 與 EvoSkill 等對照基線。以 GPT-5.5 為例，在直接對話模式下平均提升無技能準確率 23.5 個百分點，在 Codex 框架下提升 24.8 點，在 Claude Code 框架下提升 19.1 點；其中 SpreadsheetBench 更從 41.8 大幅躍升至 80.7。相較於各組合中最強的單一基線，SkillOpt 平均再高出 5.4 個百分點，顯示其優化後的技能產物具有顯著且穩定的優勢。

**Q9：消融實驗揭示了 SkillOpt 各組件的什麼作用？**
A：消融結果顯示，有界的文本學習率預算顯著優於無控制的全面重寫，證明限制編輯幅度是維持優化穩定性的關鍵；保留驗證閘門能有效阻擋有害編輯進入技能文件，避免性能隨迭代退化。拒絕編輯緩衝區將失敗經驗轉化為負回饋，顯著提升了後續編輯提案的品質；而逐輪慢速與元更新則能在不膨脹部署技能長度的前提下，改善長期視野的精煉效果。最終產出的技能文件僅需一到四次被接受的編輯即可收斂至三百到兩千詞元，且內容保持可檢查與程序性，而非針對特定實例的記憶。

**Q10：SkillOpt 在哪些實務場景中最具應用價值？**
A：SkillOpt 特別適用於需要為閉源前沿模型進行領域適應，但無法取得或修改模型權重的商業場景，例如企業內部專用的問答系統、試算表處理智能體或具身決策代理。由於優化後的產物是單一、可審計的文字檔案，它非常適合需要人工審查與合規檢查的生產環境，避免了黑箱權重調整帶來的風險與不可解釋性。此外，當同一技能需要在不同模型規模或不同執行框架之間遷移時，SkillOpt 產出的可移植技能產物能大幅降低重複優化的成本與維護負擔。

**Q11：從產品部署的角度來看，SkillOpt 具備哪些優勢？**
A：SkillOpt 在部署階段僅需載入一個輕量的技能文件，完全不需要增加額外的推論時模型呼叫，這對於延遲敏感與成本控制的產品至關重要。優化後的技能保持緊湊與程序性，開發者與領域專家可以直接閱讀、審核甚至手動微調技能內容，而不必理解複雜的模型內部結構。這種「優化一次、多處部署」的特性，使得團隊可以針對特定任務訓練技能，再無縫套用於 Codex、Claude Code 或直接對話等不同執行框架，無需修改底層智能體程式碼或執行環境。

**Q12：SkillOpt 可能對智能體設計與領域適應領域帶來什麼影響？**
A：SkillOpt 將領域適應的典範從傳統的權重調整或提示詞工程，擴展到對程序性知識的系統性文本空間優化，確立了技能文件作為可訓練外部狀態的地位。這種方法為智能體技能的發展引入了類似深度學習的紀律——包括可重現的批次採樣、步長控制與驗證機制——使得技能演化從臨時的藝術轉變為可控的科學。長遠來看，這有助於催生可跨模型與框架重用的標準化技能庫，甚至形成技能產物的市場生態，讓領域專家能專注於撰寫與交易高品質的程序性知識，而非重複為每個模型手工調適。

**Q13：這篇論文承認或暗示了哪些限制？**
A：SkillOpt 在訓練階段需要額外呼叫一個前沿優化器模型來產生編輯，這在計算資源與 API 成本上比單次生成方法更高，儘管這些成本不會發生在部署階段。由於優化發生在文本空間而非權重空間，對於某些極度依賴微觀語義調整或隱性知識的任務，其表達能力可能仍不及直接的模型微調。此外，整個流程高度依賴帶有評分的執行軌跡與保留驗證集的品質，若這些資料存在偏差、雜訊或覆蓋不足，優化方向可能會受到誤導而收斂至次優解。

**Q14：在哪些情況下 SkillOpt 可能會失敗或表現不佳？**
A：如果保留驗證集的規模過小或與真實目標分佈不一致，驗證閘門可能會錯誤地接受降低泛化性能的編輯，或拒絕真正有益的更新，導致優化過早停滯。當優化器模型提出的編輯在語法上合理但與現有技能結構存在隱性語義衝突時，有界編輯的局部調整可能難以修復深層的邏輯矛盾，使得技能文件陷入不一致的狀態。對於需要極長程序描述或涉及多技能協同的複雜領域，固定的編輯預算與單一文件格式可能會限制其表達能力，導致優化無法捕捉完整的領域慣例。

**Q15：這項工作暗示了哪些未來研究方向？**
A：未來可以將 SkillOpt 擴展至多技能同時優化或自動化技能庫的組織與檢索，以處理更複雜的多步驟智能體工作流程與技能間的依賴關係。另一個方向是探索文本空間技能優化與權重空間適應的混合範式，讓技能文件與模型內部參數進行協同訓練，進一步釋放適應潛力。此外，發展跨領域的元學習機制以暖啟動技能優化，以及設計能自動發現最佳技能架構（例如多文件、階層式結構或動態工具策略）的方法，都是值得深入探索的課題。

## 實務應用指南

### 適用場景

1. **企業級文件與試算表自動化**：針對財務、法務或營運部門重複性高的複雜試算表處理（如 SpreadsheetBench 類任務），將人類專家的操作程序封裝為可訓練的智能體技能，並依實際執行反饋逐步收斂至穩定程序。
2. **程式碼智能體工具鏈調校**：在 Codex 或 Claude Code 等執行框架中，優化智能體呼叫工具、讀取檔案與除錯的標準作業流程。例如針對內部程式碼庫的特定規範，訓練出專屬的程式碼審查與重構技能文件。
3. **客戶服務與領域問答增強**：針對需要多步驟證據搜集的專業客服（如醫療、保險、B2B 技術支援），將領域啟發式與工具策略外掛為技能文件，透過保留驗證分數篩選出真正提升解決率的程序更新。
4. **科學與數學推理程序優化**：針對數學或科學推理解題智能體，將「如何驗證中間步驟」「何時使用符號計算工具」等後設策略寫入技能文件，並以執行軌跡批次進行文本空間優化，避免一次性生成導致的邏輯漏洞。
5. **具身智能與流程自動化（RPA）**：在 ALFWorld 類的決策環境或企業 RPA 流程中，優化智能體探索環境、處理異常狀態與輸出約束的行為準則，並確保技能產物可跨模型規模遷移。

### 實作前置條件

- **資料準備**：需要具備明確輸入輸出的任務資料集、可自動評分的執行軌跡（scored rollouts），以及獨立的保留驗證集（held-out validation split）。驗證集必須與訓練軌跡分布一致，且評分函數需能穩定反映任務成敗。
- **運算資源**：需能呼叫至少兩個模型——目標模型（frozen agent，即被適應的智能體）與前沿優化器模型（optimizer model）。後者負責產生結構化增刪替換編輯，建議使用具備長上下文與遵循指令能力的前沿語言模型。
- **技能與環境基礎**：需準備一份初始技能文件（seed skill），即使只是簡短的人類撰寫程序或一次性 LLM 生成草稿；同時需完整設定執行框架（execution harness），包括工具接口、檔案系統權限與錯誤處理機制。

### 實作步驟建議

1. **定義領域與初始化技能**：撰寫首版技能文件 `skill_v0.md`，涵蓋基本程序、工具策略與輸出約束。設定評分指標與保留驗證閘門（selection gate）的通過門檻。
2. **建立批次執行管線**：讓目標模型在當前技能下執行軌跡批次（trajectory batches），記錄每筆軌跡的分數與中間狀態。建議每輪至少收集數十到數百條軌跡以降低雜訊。
3. **生成候選編輯**：將評分後的軌跡與當前技能文件餵給優化器模型，要求其產生有界增刪替換編輯（bounded add/delete/replace edits），並附上編輯理由。
4. **套用文本學習率預算**：根據設定的編輯預算（edit budget）過濾或截斷候選編輯，確保單輪更新幅度有限，避免技能文件出現大型語義跳躍。
5. **保留驗證閘門檢查**：將編輯後的候選技能在保留驗證集上執行，僅當保留驗證分數嚴格提升時才接受該編輯，否則拒絕。
6. **更新拒絕編輯緩衝區**：將被拒絕的編輯存入緩衝區，作為後續輪次給優化器模型的負回饋，避免重複提出無效修改。
7. **執行逐輪慢速／元更新**：每完成一個 epoch，讓優化器模型綜合多輪接受與拒絕的歷史，進行 epoch-wise slow/meta update，提煉跨輪次的穩定編輯方向。
8. **收斂與匯出**：當連續多輪無法通過驗證閘門，或達到預設輪數上限時，匯出最佳技能文件 `best_skill.md`（通常僅 300–2,000 tokens）。部署時直接掛載該文件，無需額外推論時模型呼叫。

### 潛在風險與注意事項

- **語意漂移與不穩定更新**：若未嚴格執行文本學習率預算，優化器可能一次性大幅改寫技能文件，導致先前有效的程序被覆蓋。建議每輪僅允許 1–4 個結構化編輯，並強制執行保留驗證。
- **過度擬合特定執行框架**：技能可能在 Codex 環境優化後，於 Claude Code 或 direct chat 中失效。建議在優化過程中定期進行跨框架驗證，或將技能內容保持為「程序性」而非「框架特定指令」。
- **有害編輯累積**：若缺少驗證閘門，錯誤的啟發式會被寫入技能並持續放大。務必以 held-out validation score 作為唯一接受標準，而非僅看訓練軌跡的平均分。
- **優化器模型成本爆炸**：頻繁呼叫大型優化器模型可能產生高額 API 費用。可透過增大軌跡批次規模、減少無意義的候選編輯數量，以及利用逐輪慢速更新降低呼叫頻率來控制成本。
- **技能膨脹（Skill Bloat）**：若未控制，技能文件可能累積過多實例特定細節。應監控 token 數量，確保最終產物維持在 2,000 tokens 以內，並在元更新階段刪除冗餘規則。

### 與其他技術的整合建議

- **與 RAG 系統整合**：將優化後的技能文件視為可檢索的外部知識庫一環。當智能體面對特定領域任務時，先檢索對應的 `best_skill.md` 並置入上下文，無需更動模型權重即可達成領域適應。
- **與提示管理（Prompt Management）平台整合**：將技能文件納入版本控制（如 Git-based prompt registry），利用 SkillOpt 的結構化編輯產生清晰的 diff，方便工程師審計每一輪接受的修改。
- **與傳統微調（Fine-Tuning）分工**：SkillOpt 負責「程序與策略」層面的外部優化，微調則負責「知識與風格」層面的權重適應。兩者可並行——先以 SkillOpt 收斂技能，再針對高頻任務進行輕量微調。
- **與 CI/CD 及可觀測性平台整合**：在智能體系統的持續整合流程中，將保留驗證閘門設為自動化回歸測試的一環；同時將執行軌跡批次自動匯入觀測平台，作為下一輪 SkillOpt 優化的資料來源。
- **與多智能體協作框架整合**：將不同智能體的角色描述與協作規則視為獨立技能文件，分別以 SkillOpt 優化，再透過 epoch-wise meta update 統整跨智能體的交互協議。

### 給不同背景讀者的閱讀建議

- **初學者**：請將本文想像成「訓練一份說明書」而非訓練模型。你不需要理解反向傳播或權重更新，只需掌握「智能體技能是一份可編輯的文字文件，而 SkillOpt 就像一位嚴格的編輯，只保留能通過考試的修改」這一核心概念，並從「適用場景」與「實作步驟建議」兩節開始閱讀。
- **AI 工程師**：請重點關注文本學習率預算、保留驗證閘門與拒絕編輯緩衝區的實作細節。這些機制是穩定性的關鍵，建議對照你現有的 Agent 基礎設施，評估如何將軌跡批次執行與結構化編輯管線嵌入現有的 LangChain / LlamaIndex 或自研框架中。
- **研究人員**：請深入閱讀方法論中的深度學習類比、各項消融實驗與遷移實驗。特別注意「為何文本空間優化需要類似權重空間優化的紀律」，以及技能產物在跨模型、跨框架、跨基準測試上的泛化現象，這對外部記憶與模型權重解耦的研究具有啟發性。
- **產品經理**：請聚焦於技能產物的商業價值：它是一份可審計、可重複使用且零推論時開銷的文字資產。跨模型遷移能力意味著企業可降低對單一模型供應商的依賴，而「優化一次、多處部署」的特性則能顯著縮短新領域上線的時程。建議將 SkillOpt 視為領域適應的標準化流程，而非一次性專案。
