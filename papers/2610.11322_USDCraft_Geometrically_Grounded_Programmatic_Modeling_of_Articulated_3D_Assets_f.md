## ⚡ TL;DR

解決真實到模擬中鉸接式資產重建的難題，特別是網格不完整或分布外物件的情況。
提出USDCraft框架，讓預訓練大型語言模型透過來源幾何分析與迭代再核對撰寫可執行程式。
在基準測試中取得領先的鉸接關節復原成果，並驗證真實到模擬再到真實機器人操作的有效性。

## 摘要翻譯

幾何保真且具功能性之鉸接式 3D 資產對於真實到模擬機器人操作至關重要，其中在模擬中訓練之策略必須遷移至物理物件。近期基於網格之方法學習從已標註的 3D 資產推斷鉸接關節，但當真實世界物件落在訓練分布之外，或其網格不完整或損壞時，部署仍極具挑戰性。為解決這些限制，我們將鉸接式資產重建表述為基於部分幾何證據之程式化建模，並引入 USDCraft——一個無需任務特定訓練的框架，由預訓練大型語言模型（LLM）撰寫並修訂可執行程式，以產生可用於模擬的鉸接式資產。我們提出來源幾何分析，將來源網格轉換為區分已觀察表面與未知空間之度量化的文字描述；以及迭代式幾何再核對，以同樣的表示重新編碼每個候選，使差異能作為程式編輯之依據，同時未觀察區域保持可補全。視覺回饋與物理編寫指引完成建模流程，產生具明確物理屬性之鉸接式 USD（通用場景描述）資產，無需手動調整即可載入 Isaac Sim。實驗在兩個基準測試上展現達到領先水準的鉸接關節復原能力，並驗證 USDCraft 對真實到模擬再到真實機器人操作之有效性。

### 核心貢獻（3～5點）
- **問題重新表述**：將鉸接式資產重建重新定義為基於部分幾何證據之程式化建模，擺脫對完整網格或任務特定訓練資料的依賴。
- **USDCraft 框架**：提出由預訓練大型語言模型（LLM）撰寫並修訂可執行程式之框架，無需任務特定訓練即可產出可用於模擬的鉸接式 USD 資產。
- **來源幾何分析**：將來源網格轉換為區分已觀察表面與未知空間之度量化的文字描述，使模型能基於不完整幾何證據進行推理。
- **迭代式幾何再核對**：以同樣的表示重新編碼每個候選，使差異能作為程式編輯之依據，同時允許未觀察區域進行合理化補全。
- **端到端模擬部署**：結合視覺回饋與物理編寫指引，產出之資產具明確物理屬性，無需手動調整即可直接載入 Isaac Sim，並在真實到模擬再到真實機器人操作中驗證有效性。

### 適合對象
從事機器人學習、3D 資產重建、電腦圖學與模擬到真實遷移（Sim-to-Real Transfer）研究之學者與工程師；特別關注鉸接式物件建模、分布外泛化、LLM 驅動之程式化生成，以及真實到模擬（Real-to-Sim）管線建構之研究者與實務工作者。

## 深度分析

#### 方法論解析

USDCraft 的核心方法論在於將「鉸接式 3D 資產重建」重新定義為一個「以部分幾何證據為錨定（grounded）的程式化建模問題」。此一框架跳脫了傳統 mesh-based 方法直接從靜態網格推斷部件分割與關節參數的思路，改採「代理式（agentic）程式生成」與「測量驅動回饋」雙軌並行的策略。

**整體架構與代理迴圈**

USDCraft 的核心是一個由預訓練大型語言模型（pretrained LLM）驅動的建模代理（modeling agent），搭配一個「建模工具環境（modeling harness）」。代理接收三項輸入：來源網格（source mesh）、參考影像（reference image），以及可選的文字請求。其運作流程為：(1) LLM 撰寫可執行的資產程式（executable asset program）；(2) 程式被編譯為 USD（Universal Scene Description）資產；(3) 編譯結果透過幾何與視覺回饋進行核對；(4) LLM 自主決定下一步應蒐集的證據與應參採的回饋類型；(5) 迭代修訂直至收斂。值得注意的是，整個流程無需任何任務特定微調（task-specific fine-tuning），完全仰賴 LLM 內建的世界知識與工具互動能力。

**來源幾何分析（Source Geometry Analysis）**

由於 LLM 無法直接讀取網格資料，USDCraft 設計了一個關鍵的中介步驟：將來源網格轉換為「度量化文字描述（metric textual description）」。此描述的獨特之處在於它明確區分了「已觀察表面（observed surface）」與「未知空間（unknown space）」，並涵蓋外部與內部表面。這種雙重區分至關重要，因為真實掃描往往伴隨不完整表面（incomplete surfaces）與融合部件（fused components），傳統分割方法在此情境下容易失敗。此外，代理可對此描述進行「隨選查詢（on-demand querying）」，即根據需要索取特定測量值，避免一次性灌入過多資訊造成 LLM 注意力分散。

**迭代式幾何再核對（Iterative Geometric Rechecking）**

此機制是 USDCraft 區別於其他代理式方法（如 Articraft、Procedura）的核心創新。每當 LLM 產生一個候選程式並編譯後，系統會將該候選資產以「與來源相同的度量化文字表示」重新編碼（re-encode）。如此一來，差異（discrepancy）的比對發生在「同一表示空間」中，使 LLM 能精準定位哪些程式編輯（program edits）能縮小差距。更重要的是，對於「未觀察區域（unobserved regions）」，系統允許「合理化補全（justified completion）」——即代理可根據常識與參考影像推斷缺失幾何，而不會被強迫匹配不存在的測量資料。這種「部分錨定 + 開放補全」的設計巧妙平衡了幾何保真度（geometric faithfulness）與功能性重建的需求。

**視覺回饋與物理編寫指引**

除了文字化的幾何比對，USDCraft 還引入視覺回饋（visual feedback）：將候選資產在不同鉸接組態下渲染，藉此揭露缺失部件、不合理組裝，以及運動干涉（clearance）問題。物理編寫指引（physical authoring guidance）則確保最終資產具備完整的物理屬性——碰撞幾何（collision geometry）、質量（masses）、接觸參數（contact parameters）、以及關節限制（joint limits）——使產出可直接載入 Isaac Sim 而無需手動調整（manual adjustment）。

**統一表示的副產品**

值得強調的是，USDCraft 的程式表示不僅支援從網格重建，也支援從文字或影像生成資產。這意味著同一框架同時涵蓋了「重建（reconstruction）」與「生成（generation）」兩條互補的工作流程，這在文獻中是較為罕見的統一設計。

#### 實驗數據解讀

**評測基準與資料集**

USDCraft 在兩個基準上進行評估：(1) 自建的 USDCraft-bench，涵蓋多樣化生成物件與真實掃描；(2) 公開的 Lightwheel 資料集，用於與已發表結果進行公平比較。此外，作者團隊發布了 USDCraft-10k——一個由 USDCraft 生成的鉸接式資產庫，可作為後續研究的資源。

**量化結果的意涵**

根據摘要所述，USDCraft 在 USDCraft-bench 上「領先所有評測基準（leading the evaluated baselines）」，這顯示其在自建基準的全面性評估中具有優勢。在 Lightwheel 上，USDCraft 達到「具競爭力的幾何重建（competitive geometry）」以及「強健的部件復原與關節估計（strong part recovery and joint estimation）」。「具競爭力」一詞暗示在幾何指標上可能未全面超越所有先前方法，但「強健」一詞則表明在部件與關節層面具備明顯優勢。這種 trade-off 反映了 USDCraft 的設計哲學：犧牲部分表面級擬合度，換取結構級的正確性。

**下游驗證：真實到模擬再到真實（Real-to-Sim-to-Real）**

最關鍵的驗證在於下游的機器人操作（robot manipulation）測試。USDCraft 不僅在重建指標上表現優異，更通過了「真實到模擬再到真實」閉環測試——即在模擬中訓練的操作策略（manipulation policies）能成功遷移至真實物件。這是衡量「可用於模擬（simulation-ready）」資產的黃金標準，因為僅有視覺擬合良好的資產並不足以支撐策略遷移；物理一致性與功能正確性才是關鍵。

**指標缺失的侷限**

然而，從所提供的文本中，我們無法得知具體的數值結果（例如各基準上的精確度、IoU、關節角度誤差等）。這使得對「領先幅度」的判斷只能停留在定性層面。此外，USDCraft-bench 作為自建基準，其難度與多樣性是否足以代表真實部署場景，仍有待社群檢驗。

#### 與現有研究的比較

**與基於網格的方法比較**

USDCraft 明確針對兩類現有方法的不足進行改進：

1. **部件分割與鉸接推斷方法**（如 Particulate、Instruct-Particulate、SIMART、ArtLLM）：這些方法仰賴任務特定訓練（task-specific training），在分布外（out-of-distribution, OOD）物件上泛化能力（generalization）受限；且當網格不完整或部件融合時，純分割方法無法恢復缺失幾何或功能性開口（functional openings）。USDCraft 透過 LLM 的常識知識與程式化重建繞過了這些瓶頸。

2. **視覺語言模型驅動方法**（如 Articulate AnyMesh）：雖然無需鉸接特定訓練，但其依賴視覺提示（visual prompting），對於幾何精度的控制不如 USDCraft 的度量化文字比對來得直接。

**與代理式方法比較**

在代理式方法陣營中，USDCraft 與 Articraft 和 Procedura 最為相關：

- **Articraft** 透過專用 SDK 與受限編寫環境實現可擴展的程式化資產生成，但缺乏對「目標實例幾何」的測量錨定，因此生成結果可能與真實物件存在幾何差異（geometric differences），進而限制策略遷移。
- **Procedura** 採用更具結構化的組裝流程（類型化配對約束 typed mates）與獨立視覺評論器，但其驗證僅針對「生成組裝的合理性」，而非「與目標物件測量幾何的一致性」。

USDCraft 的差異化在於：它將「來源幾何分析」與「迭代式幾何再核對」結合，使驗證發生在「與來源同一表示空間」中，從而真正實現了「實例級重建」而非僅僅是「類別級生成」。

**與影像生成方法的定位差異**

PhysX-Anything 與 URDF-Anything+ 從單張影像生成幾何、鉸接與物理屬性；URDFormer 與 Articulate-Anything 則從影像預測運動結構並從既有資產庫組裝。這些方法處理的設定與 USDCraft 不同——前者是「從影像生成」，後者是「從網格重建」。因此作者明確表示不將它們列為基準，這個定位是合理的。

**USDCraft 的侷限**

儘管優勢明顯，USDCraft 仍存在幾項潛在限制：(1) 高度依賴 LLM 的程式撰寫與推理能力，對極度複雜的多自由度鉸接（如多軸聯動機構）可能力有未逮；(2) 對於「未知空間」的合理化補全仰賴 LLM 常識，若目標物件屬於高度專業化或非標準設計，補全品質可能下降；(3) 迭代修訂的收斂性與計算成本未在文本中明確說明。

#### 可重現性評估

**程式碼與資產的釋出狀況**

從所提供的文本中，我們可確認以下資源的釋出：

1. **USDCraft-bench**：作為評測基準公開釋出，使後續研究得以進行公平比較。
2. **USDCraft-10k**：一個包含一萬個鉸接式資產的生成庫，可作為訓練資料或下游應用資源。

然而，**核心框架的程式碼是否開源**在所提供的文本中並未明確提及。作為一個強調「無需任務特定訓練」並以 LLM 為核心的方法，其可重現性主要取決於：(1) 建模工具環境（modeling harness）的實作細節；(2) 來源幾何分析與迭代式幾何再核對的具體演算法；(3) 與 Isaac Sim 的整合介面。

**模型權重與依賴**

USDCraft 使用的是「現成（off-the-shelf）」的預訓練 LLM，未進行微調。這降低了對專有權重的依賴，但同時也意味著結果對所選 LLM 版本敏感。文本中未指明具體使用的 LLM（例如 GPT-4、Claude、或開源替代方案），這對完全重現至關重要。

**模擬器依賴**

最終資產需載入 Isaac Sim 才能發揮效用，這對僅擁有非 NVIDIA 模擬環境（如 MuJoCo、PyBullet）的研究者構成一定門檻。雖然 USD 格式具備一定互通性，但物理屬性的精確遷移仍需驗證。

**整體可重現性評估**

在缺乏明確的程式碼釋出聲明、具體 LLM 規格、以及完整評測數值的情況下，USDCraft 的可重現性目前處於「部分可重現」狀態。USDCraft-bench 與 USDCraft-10k 的釋出是正面訊號，但核心方法的實作細節仍需透過後續論文、附錄或官方程式碼倉庫來補足。

#### 未來研究方向

**1. 鉸接複雜度的擴展**

當前評測主要涵蓋日常物件（如抽屜、門、鉸鏈等）。未來可探索：(a) 多自由度聯動機構（如剪刀、折疊椅、變形機器人）；(b) 連續形變（deformable）與剛體鉸接的混合建模；(c) 軟體機器人（soft robotics）資產的程式化表示。

**2. 多模態輸入融合**

USDCraft 已整合網格與影像，未來可進一步納入：(a) 影片序列以觀察實際運動軌跡；(b) 觸覺回饋以推斷鉸接限制；(c) 文字描述以處理語意模糊的部件名稱。這將使框架能處理更豐富的輸入場景。

**3. 物理屬性的自動化估計**

雖然 USDCraft 已輸出質量與接觸參數，但這些數值目前可能仍仰賴 LLM 的常識估計。整合材料識別、重量量測資料、或從互動影片中學習物理參數，將是提升真實到模擬遷移可靠性的關鍵方向。

**4. 跨模擬器互通**

目前聚焦於 Isaac Sim，未來可探索與其他模擬平台（如 MuJoCo、PyBullet、Gazebo）的互通。這需要對 USD 資產進行標準化的物理屬性映射，或發展模擬器無關的中介表示。

**5. 閉環式真實到模擬工作流程**

將 USDCraft 整合進完整的「掃描 → 重建 → 模擬訓練 → 真實部署」閉環，並研究當重建誤差存在時，策略如何透過域隨機化（domain randomization）或域適應（domain adaptation）保持魯棒性，是推向實際應用的必經之路。

**6. LLM 能力的進一步釋放**

隨著推理能力更強的 LLM 出現，USDCraft 可探索：(a) 自主設計新型鉸接機構（而非僅復原既有設計）；(b) 從極度稀疏的測量資料（如單張影像 + 文字描述）進行高品質重建；(c) 結合符號推理與神經渲染的混合方法。

**7. 評測基準的深化**

USDCraft-bench 的發布為社群提供了起點，但未來基準應涵蓋：(a) 更細粒度的物理正確性指標（如摩擦、阻尼、慣量張量）；(b) 跨類別的泛化壓力測試；(c) 對抗性損壞（如嚴重遮擋、噪訊）的魯棒性評估。

**8. 與基礎模型的結合**

將 USDCraft 與三維基礎模型（如 PartField、視覺語言三維模型）結合，可能進一步提升部件分割與鉸接推斷的準確性，特別是在 OOD 場景下。這代表了一條「程式化重建 + 神經表示」的混合路徑。

## 論文問答

**Q1：USDCraft 試圖解決的核心問題是什麼？為何這個問題在機器人學習領域特別重要？**

A：USDCraft 試圖解決的核心問題是「真實到模擬」（real-to-sim）流程中，如何從一個可能不完整或受損的來源網格（source mesh）重建出幾何保真且功能完整的鉸接式 3D 資產（articulated 3D asset）。這個問題之所以重要，是因為機器人操作策略（manipulation policies）需要在模擬環境中進行大量的示範收集（demonstration collection）與策略訓練（policy training），而模擬資產若無法真實反映目標實例（target instance）的幾何與鉸接關節，則訓練出來的策略將難以遷移到真實物件上。換言之，模擬到真實遷移（simulation-to-real transfer）的成敗直接取決於重建資產的幾何保真度（geometric faithfulness）與功能性鉸接（functional articulation）品質。

**Q2：現有的網格式方法在真實部署時面臨哪些挑戰？USDCraft 如何回應這些挑戰？**

A：現有的網格式方法（如 Particulate、Instruct-Particulate 等）仰賴任務特定訓練（task-specific training）來從靜態網格（static mesh）推斷部件分割（part segmentation）與關節軸（joint axes），但在真實部署時面臨兩大挑戰：第一，不完整表面（incomplete surfaces）與融合部件（fused components）會嚴重損害分割品質，且單純的部件分割無法復原缺失幾何（missing geometry）或功能性開口（functional openings）；第二，這些方法對分布外物件（out-of-distribution objects）的泛化能力有限，當目標物件的類別或機構機制在訓練分布（training distribution）中代表性不足時表現會明顯下降。USDCraft 的回應策略是將重建重新表述為「以部分幾何證據為錨定的程式化建模」，由預訓練的大型語言模型（pretrained LLM）撰寫並修訂可執行的資產程式（executable asset program），既不依賴任務特定訓練，也能透過來源幾何分析（source geometry analysis）與迭代式幾何再核對（iterative geometric rechecking）持續校正程式。

**Q3：為何「程式化建模」相較於「從零生成」或「純網格推斷」更適合真實到模擬的重建任務？**

A：純粹從零生成的代理式方法（agentic methods）雖然能利用 LLM 對日常物件（everyday objects）的豐富知識來涵蓋多樣類別，但缺乏對目標實例幾何的測量錨定，導致生成的尺寸與部件配置（part placement）可能與真實物件存在顯著差異，進而限制了操作策略的遷移效果。純網格推斷方法雖然能直接從測量資料出發，卻難以處理不完整或受損的網格，也無法重建缺失的幾何。程式化建模（programmatic modeling）則兼具兩者優勢：可執行程式（executable program）能靈活重建缺失幾何並分離融合部件，同時透過來源幾何分析將測量證據注入程式建構（programmatic construction）與修訂（program revision）過程，使最終資產在幾何上忠於來源、在功能上完整可用。

**Q4：USDCraft 的核心方法論是什麼？它如何將重建任務形式化？**

A：USDCraft 將鉸接式資產重建形式化為「以部分幾何證據為錨定的程式化建模」，其核心方法論由一個預訓練的大型語言模型（off-the-shelf LLM）作為建模代理（modeling agent），在一個包含工具、指引與回饋的建模環境（modeling harness）中反覆地撰寫、編譯並修訂可執行的資產程式（executable asset program）。由於 LLM 無法直接讀取網格，USDCraft 引入來源幾何分析將來源網格轉換為度量化文字描述（metric textual description），明確區分已觀察表面（observed surface）與未知空間（unknown space），並允許代理隨選查詢（on-demand querying）額外的測量資訊。接著，迭代式幾何再核對將每個候選資產以同一表示重新編碼（candidate encoding），使差異（discrepancy）能直接指向具體的程式編輯（program edits），而未觀察區域（unobserved regions）則保留合理化補全（justified completion）的彈性。

**Q5：來源幾何分析與迭代式幾何再核對這兩個關鍵創新各自扮演什麼角色？兩者如何協作？**

A：來源幾何分析（source geometry analysis）的角色是「讓 LLM 讀懂幾何」：它將來源網格轉換為同時描述外部表面（exterior surfaces）與內部表面（interior surfaces）的度量化文字描述，並清楚標示哪些區域是已觀察、哪些屬於未知空間，使 LLM 能在缺乏原生 3D 感知能力的情況下進行有意義的幾何推理。迭代式幾何再核對（iterative geometric rechecking）的角色則是「讓差異可被定位與修正」：它將每個程式編譯出的候選資產以同一文字表示重新編碼，與來源進行比對，使差異能直接對應到程式中的特定編輯點，而未觀察區域則保持開放以利合理化補全。兩者的協作形成一個閉迴路：來源幾何分析提供初始證據，迭代式幾何再核對持續回報候選與來源的差距，視覺回饋（visual feedback）則補充渲染後的外觀與跨組態的功能性檢查，三者共同驅動程式的迭代精煉。

**Q6：為何 USDCraft 選擇使用「無任務特定訓練」的預訓練 LLM？這個設計選擇帶來哪些權衡？**

A：USDCraft 選擇無任務特定微調（fine-tuning）的預訓練 LLM，是為了換取跨類別的泛化能力（generalization）與部署彈性：預訓練 LLM 已內含對日常物件結構與機構的豐富世界知識，使其能處理分布外（out-of-distribution）的物件類別與機制，而無需為每個新類別收集標註資料或重新訓練。這個設計選擇的權衡在於，LLM 無法直接處理 3D 網格、且可能產生與測量幾何不一致的臆測，因此 USDCraft 必須透過來源幾何分析、迭代式幾何再核對與視覺回饋等機制，將 LLM 的生成能力「錨定」在真實測量資料上。換言之，USDCraft 並非單純依賴 LLM 的先驗，而是建立一套讓測量證據持續引導並修正 LLM 輸出的工作流程。

**Q7：USDCraft 在哪些基準測試上進行評估？這些基準各自測試了什麼能力？**

A：USDCraft 在兩個基準上進行評估：自建的 USDCraft-bench 涵蓋多樣的生成物件與真實掃描，公開的 Lightwheel 資料集則用於與已發表結果進行比較。USDCraft-bench 主要測試 USDCraft 在多樣日常物件類別上的鉸接關節復原（articulation recovery）品質，並同時涵蓋生成與重建兩種工作流程；Lightwheel 資料集則提供了與其他網格式方法直接比較的基準，重點評估幾何重建、部件復原與關節估計的準確度。兩者結合使評估能同時反映 USDCraft 在「跨類別泛化」與「與專用方法的可比性」兩個面向的表現。

**Q8：USDCraft 的主要實驗結果為何？它在哪些指標上領先或具有競爭力？**

A：在 USDCraft-bench 上，USDCraft 在評估的所有基準方法中取得領先的鉸接關節復原（articulation recovery）表現；在 Lightwheel 資料集上，USDCraft 達到具競爭力的幾何重建品質，並在部件復原與關節估計上相對已發表結果展現強勁表現。除了重建準確度之外，USDCraft 也透過下游的真實到模擬再到真實（real-to-sim-to-real）機器人操作測試驗證其資產在策略遷移上的實用性，證明所產生的資產不僅在指標上表現良好，也確實能支撐實際的機器人操作任務。

**Q9：USDCraft 進行了哪些消融實驗或元件驗證？各元件的相對貢獻為何？**

A：USDCraft 的關鍵元件包括來源幾何分析、迭代式幾何再核對、視覺回饋與物理編寫指引（physical authoring guidance），每一項都對最終品質有特定貢獻。來源幾何分析提供了 LLM 可讀的測量錨定，移除後將使 LLM 失去可靠的幾何參考而難以貼近目標實例；迭代式幾何再核對提供了差異化的回饋訊號，移除後將使修訂過程失去精確的定位依據。視覺回饋則負責捕捉渲染後外觀與跨組態的功能性問題（如缺失部件、不合理組裝、間隙問題），對外觀與鉸接功能的正確性至關重要；物理編寫指引則確保最終資產具備碰撞幾何、質量、接觸參數與關節限制等明確的物理屬性（physical properties），使其能直接載入 Isaac Sim 而無需手動調整（manual adjustment）。

**Q10：USDCraft 在哪些實際場景中能發揮價值？請舉例說明。**

A：USDCraft 的典型應用場景之一是「真實到模擬再到真實」（real-to-sim-to-real）的機器人操作部署：當工廠或家庭中出現一個新的鉸接式物件（例如特殊設計的櫥櫃門、抽屜或工具）時，傳統流程需要手動測量並在模擬器中建模，耗時且易錯；USDCraft 可從該物件的網格掃描與參考影像（reference image）出發，自動重建出可在 Isaac Sim 中直接使用的 USD 資產，並用於策略訓練，最終將策略部署回真實機器人。另一個場景是大規模訓練資料生成：USDCraft-10k 函式庫展示了其可程式化地產出大量多樣化的鉸接式資產，為機器人學習（robot learning）提供豐富的模擬互動（simulated interaction）訓練素材。

**Q11：USDCraft 在產品化與工程整合上有哪些考量？為何選擇 USD 與 Isaac Sim？**

A：在產品化與工程整合上，USDCraft 選擇 USD（通用場景描述，Universal Scene Description）作為資產格式，並以 NVIDIA Isaac Sim 作為目標模擬器，這個選擇帶來幾項關鍵優勢：USD 是 NVIDIA 生態系中 3D 場景的標準表示，能完整承載幾何、鉸接、物理屬性與場景層級資訊；Isaac Sim 則是 NVIDIA 針對機器人模擬所優化的平台，與 PhysX 物理引擎深度整合。USDCraft 編譯出的資產自帶碰撞幾何、質量、接觸參數與關節限制等明確的物理屬性（physical properties），因此能「零手動調整」地直接載入 Isaac Sim，這對需要快速迭代的機器人開發流程而言大幅降低了整合摩擦。

**Q12：USDCraft 對機器人學習與模擬領域的整體影響為何？**

A：USDCraft 的整體影響在於降低了「真實到模擬」流程的技術門檻與人力成本：過去重建一個功能完整的鉸接式資產需要熟練的 3D 建模師與領域專家共同參與，而 USDCraft 透過預訓練 LLM 加上幾何錨定（geometric grounding）的程式化建模，使這個流程能在最少人工介入下完成。這使得研究團隊能將更多精力放在策略設計與任務定義上，而非資產建模；同時，USDCraft-10k 等大規模資產庫的釋出也將豐富機器人學習社群可用的訓練資料來源，推動模擬到真實遷移（simulation-to-real transfer）研究的進展。

**Q13：USDCraft 存在哪些已知的限制？**

A：根據方法描述可推論，USDCraft 的限制主要來自三方面：第一，由於依賴預訓練 LLM 的世界知識，對於極為罕見或訓練語料中幾乎未涵蓋的機構機制，LLM 可能產生不正確的先驗假設，需要更多輪次的迭代修正才能收斂；第二，來源幾何分析的品質取決於輸入網格的解析度與完整性，若來源網格缺失過多關鍵區域（例如關節內部結構），合理化補全（justified completion）的結果可能與真實機構存在差距。第三，整個流程涉及多次程式編譯、渲染與測量查詢，計算成本與時間成本較單次前向推論的網格式方法更高，對即時性要求嚴格的應用可能不夠友善。

**Q14：USDCraft 在哪些情況下可能會失敗？**

A：USDCraft 可能在以下情況下表現不佳：當來源網格（source mesh）極度不完整或嚴重受損時，例如缺少關鍵的鉸接區域或功能性開口（functional openings），即使有合理化補全機制，LLM 也難以僅憑文字描述與參考影像（reference image）正確推斷內部機構；當目標物件屬於訓練語料中極少出現的長尾類別（例如高度專業化的工業機具或非標準機構設計）時，LLM 的先驗可能誤導程式建構；當視覺回饋（visual feedback）所依賴的渲染品質不足以揭示細微的幾何差異時（例如薄壁結構或微小間隙），迭代式幾何再核對可能無法定位所有差異，導致最終資產在視覺上通過但物理模擬中表現異常。

**Q15：USDCraft 未來可能的研究方向為何？**

A：USDCraft 未來可能的研究方向包括：第一，擴大合理化補全（justified completion）的能力，例如引入更強的 3D 先驗或多模態模型來處理極端不完整的來源網格；第二，將流程延伸至更複雜的多鉸接鏈、軟體機構或可形變物件，突破目前以剛體鉸接為主的設定；第三，與機器人操作策略學習更緊密地結合，例如在建構階段就考慮下游任務的可操作性與接觸豐富度，主動優化資產的物理屬性以提升策略遷移成功率；第四，提升效率，包括減少迭代輪數、加速程式編譯與渲染，或探索將部分流程離線化以支援更大規模的資產生成；第五，將 USDCraft 的程式化建模範式推廣到其他需要幾何錨定（geometric grounding）的代理式 3D 生成任務，例如場景佈局或工具製造。

## 實務應用指南

### 適用場景

1. **家庭服務機器人的真實到模擬遷移（Real-to-Sim-to-Real）**
   場景描述：服務機器人公司需要將實體掃描的冰箱、洗衣機、抽屜櫃等家具重建為可互動的模擬資產，用於在 Isaac Sim 中訓練開門、抽屜等操作策略，再將策略遷移回實體機器人。USDCraft 能處理網格不完整或部件融合的問題，輸出帶有明確物理參數的 USD 資產。

2. **工業自動化中的異型夾治具快速建模**
   場景描述：工廠導入新型鉸接治具（如夾爪、翻蓋機構）時，可透過掃描網格與參考影像，由 USDCraft 自動生成可在模擬器中測試運動範圍與碰撞的 USD 資產，加速離線編程與可行性驗證。

3. **AR/VR 內容生成管線中的互動物件資產庫**
   場景描述：遊戲或 XR 工作室需要大量可開啟的日常物件（行李箱、工具箱、樂器盒）。USDCraft-10k 資產庫可直接作為素材來源，並可針對特定風格化物件以單張影像 + 文字請求生成新資產。

4. **機器人操作研究的基準測試資料擴充**
   場景描述：學術團隊需要擴增 PartNet、Lightwheel 等基準之外的物件類別以測試泛化能力。USDCraft 無需任務特定訓練即可重建分布外（OOD）物件，適合用於跨類別泛化實驗。

5. **數位孿生（Digital Twin）中的家具與設備建模**
   場景描述：建築資訊模型（BIM）或智慧建築平台需要將實體家具、門窗重建為可模擬開關的數位孿生資產。USDCraft 產出的 USD 資產可直接載入 Omniverse 生態，支援後續的能耗模擬、人流模擬。

### 實作前置條件

**資料前置條件**
- **來源網格**：需要待重建物件的 3D 掃描網格（建議來自 RGB-D 掃描器如 RealSense、photogrammetry 如 COLMAP 輸出，或 CAD 匯出）。網格需經過基本清理（去除孤立面片、修復法向）。
- **參考影像**：單張 RGB 影像，用於輔助 LLM 理解物件外觀與功能（建議解析度 ≥ 512×512，視角與網格一致最佳）。
- **可選文字請求**：用於指定類別、材質或特殊功能（例如「左開門、附三層抽屜」）。
- **基準資料**：若要評估重建品質，需準備 USDCraft-bench 或 Lightwheel 資料集作為 ground truth。

**運算前置條件**
- **LLM API 存取**：需具備 GPT-4 級別或以上的預訓練 LLM API 存取權（OpenAI、Anthropic 或自架開源模型如 Llama 3.1 70B+）。
- **NVIDIA Isaac Sim**：需安裝 Isaac Sim 2023.1+ 與 Omniverse USD Composer，用於載入與驗證產出資產。
- **GPU 工作站**：建議 NVIDIA RTX 4080 以上等級，用於 Isaac Sim 中的物理模擬與視覺回饋渲染。
- **Python 環境**：Python 3.10+、USD Python bindings（`usd-core`）、trimesh、Open3D 等網格處理套件。

**技能前置條件**
- **3D 與 USD 基礎**：熟悉 USD stage composition、prim 層級結構、xform 與物理 schema（collision、rigid body、joint）。
- **機器人模擬經驗**：理解 Isaac Sim 中的 articulation、joint drive、contact API。
- **LLM 提示工程（Prompt Engineering）**：能設計工具呼叫（tool-use）流程與結構化輸出解析。
- **網格處理**：能撰寫網格量測腳本（包圍盒、表面積、孔洞偵測）。

### 實作步驟建議

**階段一：環境建置與小規模驗證（1–2 週）**
1. 安裝 Isaac Sim 與 Omniverse，依官方教學載入一個範例鉸接資產（如簡單鉸鏈門）確認 USD 物理屬性正常運作。
2. 準備 5–10 個測試物件的網格與影像，先以人工方式撰寫 USD Python 程式產生對應資產，建立 ground truth 基準。
3. 實作「來源幾何分析（Source Geometry Analysis）」原型：將網格轉為度量化文字描述（包圍盒尺寸、主要表面積、孔洞位置、觀察/未知區域標記），可參考論文中 Figure 2 的流程。

**階段二：LLM 代理迴圈搭建（2–3 週）**
4. 設計 LLM 的工具集（tool set）：包含「查詢網格量測」、「編譯資產程式」、「執行幾何再核對」、「擷取渲染視圖」、「查詢物理參數建議」等函式。
5. 撰寫系統提示詞（system prompt），明定資產程式的 API 介面、USD 編譯流程、迭代修訂規則。
6. 實作「迭代式幾何再核對（Iterative Geometric Rechecking）」：將候選資產重新編碼為同一文字表示，與來源比對並回傳差異清單。
7. 整合「視覺回饋」：將候選資產在 Isaac Sim 中渲染多個關節配置，截圖回傳給 LLM。

**階段三：基準評估與迭代（2–4 週）**
8. 在 USDCraft-bench 與 Lightwheel 上評估鉸接復原準確率（part segmentation、joint axis estimation、joint type classification）。
9. 分析失敗案例，區分是 LLM 推理錯誤、量測誤差、還是程式 API 設計不足，針對性優化。
10. 調整迭代次數上限、溫度、上下文長度等超參數，平衡品質與成本。

**階段四：產品化與管線整合（4–8 週）**
11. 將流程包裝為 CLI 或 Web 服務，輸入網格 + 影像，輸出 USD 檔案 + 物理屬性 JSON。
12. 建立資產審核介面，讓人類專家可快速檢視 LLM 產出並標註錯誤，用於後續 fine-tuning 或錯誤分析。
13. 串接下游機器人訓練流程（如 Isaac Lab、Robomimic），驗證策略遷移效果。
14. 建立 USDCraft-10k 風格的內部資產庫，累積可重用資產。

**階段五：部署與監控**
15. 設定 API rate limit 與成本監控（LLM 呼叫是主要成本來源）。
16. 建立品質監控儀表板：成功率、平均迭代次數、最常見失敗模式。
17. 撰寫內部文件與 SOP，規範來源網格品質要求與提示詞模板。

### 潛在風險與注意事項

**風險一：LLM 幻覺導致物理參數錯誤**
- **現象**：LLM 可能編造不合理的質量、摩擦係數或關節限制，導致模擬行為偏離實體。
- **緩解**：建立物理參數白名單（基於材質與尺寸的查表），強制 LLM 從白名單選取而非自由生成；對關鍵參數（質量、阻尼）設定合理範圍檢查。

**風險二：迭代次數過多導致成本失控**
- **現象**：單一資產可能需要 20–50 次 LLM 呼叫才能收斂，雲端 API 成本快速累積。
- **緩解**：設定迭代上限（建議 10–15 次）；對簡單物件（單一鉸鏈）使用較小模型；快取常見部件的程式片段；採用開源模型自架以降低單位成本。

**風險三：來源網格品質差異大**
- **現象**：實務中網格常有破洞、噪訊、自遮擋，導致幾何分析輸出誤導 LLM。
- **緩解**：在管線前端加入網格品質檢查（孔洞率、噪訊程度、部件融合偵測）；對低品質網格提示 LLM 加大「合理化補全（justified completion）」的權重。

**風險四：USD 與 Isaac Sim 版本相容性**
- **現象**：USD schema 在不同 Isaac Sim 版本間有變更，產出資產可能無法載入。
- **緩解**：鎖定 Isaac Sim 版本並固定 USD Python bindings 版本；在 CI 中加入「載入測試」，確保每個產出資產可成功 instantiate。

**風險五：評估指標與下游任務脫鉤**
- **現象**：在基準上領先的鉸接復原未必能帶來更好的策略遷移效果。
- **緩解**：建立端到端的 sim-to-real 評估（成功率、任務完成時間），而非僅依賴幾何指標；定期以真實機器人任務驗證資產品質。

**風險六：智慧財產與資料合規**
- **現象**：將掃描網格與影像送至外部 LLM API 可能涉及隱私或 IP 風險。
- **緩解**：對敏感資料使用本地部署的開源 LLM；對送出的資料進行去識別化；建立資料處理合規審查流程。

### 與其他技術的整合建議

**與 PartNet / Lightwheel 等基準資料整合**
- 將 USDCraft 重建結果與 PartNet 的層級部件標註對齊，用於自動擴增訓練資料；對 Lightwheel 評估結果建立回歸測試，確保新版本不退步。

**與 Isaac Lab / Isaac Gym 整合**
- USDCraft 產出的 USD 資產可直接作為 Isaac Lab 中的 articulation asset，用於大規模平行模擬訓練；建議在訓練前以 Isaac Lab 的 `ArticulationView` 驗證 joint drive 與 contact 設定正確。

**與 3D 掃描管線整合**
- 串接 photogrammetry 工具（如 RealityCapture、Meshroom）或 RGB-D 重建（如 FoundationPose、Nerfstudio），形成「掃描 → 清理 → USDCraft 重建 → 模擬」完整管線；建議在掃描階段就規範輸出格式（單位、座標系、網格密度）。

**與機器人操作框架整合**
- 與 Robomimic、Diffusion Policy 等模仿學習框架整合時，將 USDCraft 產出的 USD 作為環境資產；可在 demonstration collection 階段就使用同一資產，確保訓練與部署一致。

**與 LLM 代理框架整合**
- USDCraft 的工具呼叫流程可整合進 LangChain、AutoGen 等代理框架，作為更大型機器人規劃系統的子模組；例如高層 LLM 規劃任務序列，低層 USDCraft 負責按需重建場景中的未知物件。

**與 CAD / PLM 系統整合**
- 對工業應用，可將 USDCraft 重建結果與 Onshape、SolidWorks 等 CAD 系統比對，識別設計偏差；USD 資產可透過 USD-STEP 轉換回 CAD 格式供工程師審閱。

**與 Omniverse 生態整合**
- 產出的 USD 資產可直接進入 Omniverse 協作平台，供多位設計師審閱、修改；可結合 Omniverse Replicator 進行合成資料生成，擴增機器人訓練資料。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先閱讀第 1 節（Introduction）了解 USDCraft 要解決的問題——為什麼機器人模擬需要「真實到模擬」的鉸接資產重建，以及現有方法的局限。接著跳到第 3.1 節（Problem setup）理解輸入輸出定義。技術細節可先略過，重點掌握「LLM 寫程式 → 編譯成 USD → 與來源比對 → 修訂」的迭代循環概念。建議搭配 Isaac Sim 官方教學動手做一個簡單鉸鏈門，建立直觀理解。

**給 AI 工程師**
重點閱讀第 3 節（Method）中的「來源幾何分析」與「迭代式幾何再核對」兩個核心機制，理解如何將非結構化的網格轉為 LLM 可讀的度量化文字表示。建議關注工具呼叫（tool-use）的設計模式、提示詞結構、以及迭代收斂條件。實作時可從複現小型基準開始，重點驗證 LLM 代理迴圈的穩定性與成本控制。對 LLM 微調有興趣者，可研究如何用失敗案例 fine-tune 開源模型以降低成本。

**給研究者**
第 2 節（Related Work）提供了完整的領域地圖，建議仔細對比 USDCraft 與 Particulate、Instruct-Particulate、SIMART、Articulate AnyMesh 等方法的差異，理解「程式化重建 vs. 隱式學習」的權衡。第 3 節的幾何再核對機制是論文的核心貢獻，值得深入分析其理論基礎（為何文字表示比直接網格比對更適合 LLM）。可考慮的延伸方向：多模態 LLM 直接處理網格的可能性、結合物理模擬器作為 differentiable feedback、以及在分布外物件上的失敗模式分析。

**給產品經理**
重點理解 USDCraft 的價值定位：它解決的是「實體物件 → 可互動模擬資產」的轉換瓶頸，這是機器人從實驗室走向真實應用的關鍵環節。商業價值在於：縮短機器人部署時間（無需為每個新物件手動建模）、降低模擬訓練成本（資產可重用）、支援長尾場景（OOD 物件）。需關注的成本項主要是 LLM API 呼叫與 Isaac Sim 授權；需評估的風險包括重建品質的穩定性與下游策略遷移的有效性。建議先以一個具體業務場景（如倉儲機器人處理抽屜櫃）做 POC，驗證端到端效果後再評估規模化。
