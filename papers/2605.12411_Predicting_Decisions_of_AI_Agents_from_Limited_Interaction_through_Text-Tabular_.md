# 透過文本-表格建模從有限互動中預測 AI 代理的決策

**原文標題：** Predicting Decisions of AI Agents from Limited Interaction through Text-Tabular Modeling  
**作者：** Eilam Shapira、Moshe Tennenholtz、Roi Reichart  
**發布日期：** 2026-05-12  
**HF 連結：** [https://huggingface.co/papers/2605.12411](https://huggingface.co/papers/2605.12411)

## ⚡ TL;DR

研究如何從少量互動中預測陌生AI對手方在議價談判中的下一步決策。
提出目標自適應文本-表格預測框架，以凍結LLM作觀察者編碼器擷取隱藏表示。
在91個留出代理上測試，觀察者特徵使AUC提升約4點，報價誤差降低14%。

## 摘要翻譯

AI 代理（AI Agent）與陌生的對手方（unfamiliar counterpart）以自然語言（natural language）進行談判與交易：例如面對未知賣方的買方機器人（buyer bot），或與供應商（supplier）談判的採購助理（procurement assistant）。在此類互動中，對手方的 LLM、提示（prompt）、控制邏輯（control logic）和基於規則的回退（rule-based fallbacks）都是隱藏的，而每個決策都可能帶來金錢後果（monetary consequences）。我們探討代理是否能從少數幾次互動中預測陌生對手方的下一個決策。為避免真實世界的日誌混淆（logging confounds），我們在受控的議價博弈（bargaining game）和談判博弈（negotiation game）中研究此問題，並將其形式化為目標自適應文本-表格預測（target-adaptive text-tabular prediction）：每個決策點（decision point）是一個表格行（table row），結合結構化博弈狀態（structured game state）、報價歷史（offer history）和對話（dialogue），而同一目標代理（target agent，即被建模的對手方）的 K 個先前博弈（K previous games）則以標記的適應範例（labeled adaptation examples）形式提供於提示中。我們的模型建立在表格基礎模型（tabular foundation model）之上，該模型使用博弈狀態特徵（game-state features）和基於 LLM 的文本表示（text representations）來表示行，並加入 LLM 作為觀察者（LLM-as-Observer）的額外表示：一個小型凍結的 LLM（frozen LLM）讀取決策時的公開狀態與對話；其輸出答案予以捨棄，而其隱藏狀態（hidden state）成為決策導向特徵（decision-oriented feature），使 LLM 成為編碼器（encoder）而非直接的少樣本預測器（few-shot predictor）。在 13 個前沿 LLM 代理（frontier-LLM agents）上訓練，並在 91 個留出的支架式代理（held-out scaffolded agents）上測試，完整模型超越了直接使用 LLM 作為預測器（LLM-as-Predictor）的提示方法以及博弈+文本特徵基線（baseline）。在此表格模型中，觀察者特徵在其他特徵方案（feature scheme）之外另有貢獻：在 K=16 時，它們在兩個任務中將回應預測（response prediction）的曲線下面積（AUC）提升約 4 點，並將議價報價預測誤差（bargaining offer-prediction error）降低 14%。這些結果顯示，將對手方預測（counterpart prediction）形式化為目標自適應文本-表格任務能實現有效的適應（adaptation），且隱藏的 LLM 表示（hidden LLM representations）揭示了直接提示（direct prompting）無法顯露的決策相關信號（decision-relevant signals）。

### 核心貢獻（3～5點）
- **問題形式化**：將對手方預測定義為目標自適應文本-表格預測任務，每個決策點為表格行，結合結構化博弈狀態、報價歷史與對話，並以 K 個先前的博弈作為標記的適應範例。
- **方法創新**：提出 LLM 作為觀察者（LLM-as-Observer），將凍結的 LLM 從預測器角色轉變為編碼器角色，從其隱藏狀態中提取決策導向特徵。
- **大規模實驗驗證**：在 13 個前沿 LLM 代理上訓練，並於 91 個留出的支架式代理上測試，證明方法對未見過的代理類型具有良好泛化能力。
- **量化性能提升**：在 K=16 的設定下，觀察者特徵將回應預測的 AUC 提升約 4 點，並將議價報價預測誤差降低 14%，超越直接提示與博弈+文本特徵基線。
- **核心洞見**：隱藏的 LLM 表示能揭示直接提示無法顯露的決策相關信號，為利用 LLM 內部表徵進行結構化預測提供了實證支持。

### 適合對象
本研究適合從事多代理系統（multi-agent systems）、自動化談判（automated negotiation）、大型語言模型應用（LLM applications）與博弈論機器學習（game-theoretic machine learning）研究的學者與工程師閱讀；亦適合對 AI 代理決策預測、表格基礎模型（tabular foundation models）以及少樣本適應（few-shot adaptation）等議題感興趣的產學研人士參考。

## 深度分析

#### 方法論解析

本論文提出一個針對「陌生 AI 代理預測」問題的創新框架，將其形式化為**目標自適應文本-表格預測**（Target-Adaptive Text-Tabular Prediction）。此方法論的核心在於將博弈論場景中的決策預測問題，巧妙地映射到表格學習（Tabular Learning）的典範中，使模型能同時利用結構化特徵與非結構化文本資訊。

**問題形式化的關鍵設計**

論文將每個決策點（Decision Point）表示為一個表格行（Table Row），該行整合三類異質資訊：(1) 結構化博弈狀態（Structured Game State），包含回合數、當前報價、歷史報價等公開配置變數；(2) 對話內容（Dialogue），即代理之間以自然語言進行的多輪交流；(3) 來自目標代理（Target Agent）的 K 個先前博弈（K Previous Games），作為標記的適應範例（Labeled Adaptation Examples）。此設計的精妙之處在於：它將「少樣本適應」（Few-Shot Adaptation）問題轉化為表格模型中的條件預測問題，使模型能在來源族群（Source Population）的整體規律與目標代理的特定證據之間取得平衡。

**三層特徵區塊的互補設計**

模型架構採用三個互補的特徵區塊（Feature Scheme）：

第一層為**博弈狀態特徵**（Game-State Features），提供結構化的數值資訊，例如當前報價金額、回合編號、買賣雙方的私有估值差異等。這些特徵捕捉博弈論層面的策略性資訊。

第二層為**文本表示**（Text Representations），使用基於 LLM 的編碼器將對話內容轉換為稠密向量，捕捉語義層面的細微訊號，例如語氣、論證策略、讓步模式等。

第三層也是本論文最具創新性的設計——**LLM 作為觀察者**（LLM-as-Observer）。此機制使用一個小型凍結的 LLM（Frozen LLM）讀取公開的決策時狀態（Public Decision-Time State）與對話內容，但其直接答案被刻意丟棄（Discarded），僅取其隱藏狀態（Hidden State）作為**決策導向特徵**（Decision-Oriented Feature）。此設計將 LLM 從「直接預測器」轉變為「編碼器」（Encoder），使其貢獻一個可重用的表示，而非最終的少樣本預測（Few-Shot Prediction）。

**為何選擇凍結 LLM 作為編碼器而非預測器**

論文明確指出此設計與自然替代方案 **LLM 作為預測器**（LLM-as-Predictor）的對比：直接提示（Direct Prompting）一個大型前沿 LLM，將當前博弈與目標代理的 K 個先前博弈放入上下文，要求其直接預測下一個決策。雖然直接提示能閱讀對話並在上下文中進行推理，但它必須承諾一個答案，且難以將目標代理的少量博弈與大型標記來源族群結合。相比之下，本論文的設計使 LLM 貢獻可重用的表示，而適應（Adaptation）則由表格學習器在來源與目標行上執行。

**兩個互補的預測任務**

論文研究兩個任務：(1) **回應預測**（Response Prediction），二元分類任務，預測目標代理是否接受當前報價；(2) **提案預測**（Proposal Prediction），迴歸任務，預測目標代理若拒絕將提出什麼報價。這兩個任務共同涵蓋了議價與談判博弈中的核心決策點。

#### 實驗數據解讀

**資料集設計的策略性**

論文的實驗設計展現了嚴謹的科學方法論。訓練集使用 GLEE 釋出的 13 個前沿 LLM 代理（Frontier-LLM Agents）循環賽，這些代理來自六個不同供應商，在相同提示下運作，僅底層 LLM 不同。此設計控制了提示變異，純化了「底層模型差異」這一維度。

測試集則引入一個 91 個代理的大學黑客松資料集（Scaffolded Agents），這些學生建構的代理共享一個底層 LLM，但在提示、控制邏輯（Control Logic）與基於規則的回退（Rule-Based Fallbacks）上有所不同。此分割測試了從一個代理變異軸（底層 LLM）學到的預測器是否能轉移到新遇到的工程化代理，其中異質性來自支架（Scaffolding）層面。整個資料集包含 4,921 場議價與談判博弈。

**關鍵量化結果**

在 K=16 的設定下（即每個目標代理提供 16 個先前博弈作為適應範例），完整的目標自適應文本-表格模型相較於直接 LLM 作為預測器提示與博弈+文本特徵基線（Game+Text Features Baselines）均表現更佳。具體而言：

- **回應預測 AUC**（Response Prediction AUC）：在兩個任務中，觀察者特徵（Observer Features）帶來約 4 個百分點的提升。
- **議價報價預測誤差**（Bargaining Offer-Prediction Error）：降低 14%。

**結果的深層意涵**

這些數字背後的關鍵發現是：增益並非主要來自觀察者的承諾答案，而是來自其隱藏狀態。這意味著凍結的 LLM 表示（Hidden LLM Representations）暴露了直接提示無法可靠揭示的決策相關信號（Decision-Relevant Signals）。換言之，LLM 的內部表示比其外顯輸出包含更豐富的策略性資訊。

此結果挑戰了「更大、更強的 LLM 直接提示必然更優」的直覺，揭示了將 LLM 視為特徵提取器而非最終預測器的價值。表格基礎模型（Tabular Foundation Model）作為整合層，能有效融合異質特徵並進行目標自適應，這是純粹的上下文學習（In-Context Learning）難以達成的。

**跨軸泛化的證據**

從 13 個前沿 LLM 代理訓練、在 91 個支架式代理上測試的成功，證明了模型學到的不僅是特定 LLM 的行為模式，而是更通用的「代理決策結構」。此泛化能力對於實際應用至關重要，因為現實中遇到的代理類型多樣，無法事先窮舉。

#### 與現有研究的比較

**相較於博弈論與機制設計文獻**

傳統博弈論模型假設代理遵循特定行為模式（如理性、特定的學習規則），並基於此推導均衡行為。本論文的方法不假設任何特定的行為模型，而是從資料中學習，這使其能捕捉 LLM 代理的「非標準」行為模式。然而，這也意味著模型在面對訓練分布外的代理時可能失效，這是資料驅動方法的固有權衡。

**相較於 LLM 代理模擬與評估研究**

GLEE 等基準測試專注於評估 LLM 代理的能力，而非預測其行為。本論文將此類資料集用於訓練預測器，開創了「代理行為預測」的新方向。與此相關的近期工作（如 AgentSims、SocialBench）多專注於模擬社會互動，而非預測特定代理的決策。

**相較於表格基礎模型研究**

近期表格基礎模型（如 TabPFN、TabPFNv2）的進展為本論文提供了基礎設施。然而，這些模型主要處理純數值表格資料，而本論文擴展至文本-表格混合設定，並加入了 LLM 觀察者特徵，這是對表格基礎模型範式的有意義擴展。

**相較於少樣本學習與元學習文獻**

本論文的目標自適應設定與元學習（Meta-Learning）有相似之處：從多個任務學習如何快速適應新任務。然而，傳統元學習方法（如 MAML、Prototypical Networks）通常假設任務間共享參數空間，而本論文的「任務」是不同代理的行為模式，其行為差異可能來自提示、控制邏輯等多個層面，這使得傳統元學習方法難以直接應用。

**論文的局限性**

儘管結果令人印象深刻，仍存在若干局限性：

1. **受控環境的代價**：使用受控博弈遊戲避免了真實世界日誌混淆（Logging Confounds），但也限制了結論對真實市場的適用性。真實採購談判涉及更多變數（法律條款、物流、信任建立等）。

2. **單一底層 LLM 的測試集**：91 個支架式代理共享一個底層 LLM，這限制了對「跨 LLM 泛化」的測試。理想情況下，測試集應包含多個底層 LLM 的支架式代理。

3. **K 值的限制**：實驗似乎集中在 K=16，未充分探索極少樣本（K=1, 2, 4）情境下的表現，而這對實際應用更為關鍵。

4. **觀察者 LLM 的選擇**：論文中「小型凍結 LLM」的具體選擇及其對結果的敏感性未充分討論。不同規模、不同預訓練資料的 LLM 作為觀察者可能產生不同品質的隱藏狀態。

5. **缺乏理論分析**：為何隱藏狀態比直接答案更有資訊量？缺乏形式化的理論解釋。

#### 可重現性評估

**資料與程式碼的可得性**

論文明確聲明：「程式碼與 91 個代理的 4,921 場議價與談判博弈資料集將在接受後釋出。」（Code and the 91-agent dataset of 4,921 bargaining and negotiation games will be released upon acceptance.）此承諾若兌現，將大幅提升可重現性。

**可重現性的優勢層面**

1. **GLEE 資料集已公開**：訓練所用的 13 個前沿 LLM 代理循環賽資料來自 GLEE 專案，這是已釋出的基準測試。

2. **任務形式化清晰**：兩個任務（回應預測、提案預測）的輸入輸出定義明確，便於獨立實作。

3. **基線明確**：LLM 作為預測器與博弈+文本特徵基線均有清楚定義。

**可重現性的挑戰**

1. **前沿 LLM 的 API 變動**：訓練涉及 13 個前沿 LLM，這些模型的 API、版本可能在論文發表後變動，影響重現。

2. **觀察者 LLM 的具體規格未明**：論文中「小型凍結 LLM」的具體型號、大小、預訓練資料未在現有內容中詳述，這對重現至關重要。

3. **表格基礎模型的選擇**：使用的具體表格基礎模型架構及其超參數需要明確記錄。

4. **提示工程細節**：LLM 作為預測器基線的具體提示模板需要完整公開。

5. **評估協議**：91 個代理的具體劃分、隨機種子、評估指標的計算細節均需記錄。

**建議的改進**

為提升可重現性，論文應補充：(1) 觀察者 LLM 的完整規格；(2) 所有提示模板；(3) 表格模型的超參數配置；(4) 隨機種子與資料劃分檔案；(5) 訓練與評估的計算資源需求。

#### 未來研究方向

**1. 真實世界場景的遷移**

最直接的延伸是將此框架應用於真實的市場日誌（Marketplace Logs），例如 B2B 採購談判、線上拍賣、客戶服務對話等。這需要解決：(a) 隱私與資料取得問題；(b) 從受控博弈到開放式對話的轉換；(c) 處理多模態資訊（圖表、附件、合約條款）。

**2. 主動學習與策略性探索**

當前的設定是被動地接收 K 個先前博弈。未來可探索主動學習（Active Learning）策略：預測器應主動選擇與哪些代理互動、提出何種報價，以最大化資訊獲取並降低預測不確定性。這與博弈論中的「資訊設計」（Information Design）密切相關。

**3. 對抗性對手方與穩健性**

現實中的對手方可能有策略性地誤導預測器的動機（例如假裝接受以誘使對方讓步）。未來工作應研究：(a) 對抗性操縱下的預測穩健性；(b) 檢測對手方是否在「博弈預測器」；(c) 設計對抗操縱具有韌性的預測模型。

**4. 觀察者機制的理論理解**

為何隱藏狀態比直接答案更有資訊量？此問題值得深入研究。可能的方向包括：(a) 資訊理論分析，量化隱藏狀態與直接答案之間的互資訊（Mutual Information）差異；(b) 探測研究（Probing Studies），識別隱藏狀態中編碼的特定決策相關維度；(c) 對比不同規模、不同預訓練資料的 LLM 作為觀察者的效果。

**5. 多代理與社會層面的考量**

當代理不僅與單一對手方互動，而是在多代理環境中運作時，預測問題變得更複雜。未來可探索：(a) 社會網路結構對預測的影響；(b) 代理聲譽與信任機制的建模；(c) 集體行為湧現（Emergent Collective Behavior）的預測。

**6. 跨語言與跨文化遷移**

議價與談判行為具有強烈的文化特異性。將此框架擴展至跨語言、跨文化場景，測試：(a) 觀察者 LLM 的語言依賴性；(b) 文化特異性談判策略的可學習性；(c) 跨文化代理預測的可行性。

**7. 與強化學習的整合**

將預測器作為強化學習代理的「世界模型」（World Model）組件，使代理能在模擬的對手方行為下進行策略規劃。這結合了預測與決策，可能產生更強的談判代理。

**8. 倫理與治理考量**

隨著 AI 代理在商業談判中的部署增加，預測對手方行為的能力引發倫理問題：(a) 操縱風險——預測能力是否會被用於剝削對手方？(b) 透明度——代理是否應披露其預測能力？(c) 公平性——預測能力的不對稱分布是否會加劇市場不平等？這些問題需要跨學科研究，包括 AI 倫理、法律與經濟學。

**9. 表格基礎模型的進一步發展**

本論文擴展了表格基礎模型以處理文本-表格混合資料。未來可進一步：(a) 設計原生支援多模態的表格基礎模型；(b) 研究觀察者特徵的理論最優整合方式；(c) 探索更大規模的預訓練是否能帶來更好的目標自適應能力。

**10. 應用於人類行為預測**

雖然本論文聚焦於 AI 代理，但其方法論可能適用於預測人類對手方在有限互動下的行為，例如：(a) 線上拍賣中的競標者行為預測；(b) 客戶談判風格的建模；(c) 對手方在重複博弈中的策略學習。當然，這需要仔細考慮人類行為的複雜性與倫理邊界。

總結而言，本論文在「陌生 AI 代理預測」這一重要問題上提出了創新且實證有效的解決方案，其將 LLM 作為編碼器而非預測器的設計理念，以及跨軸泛化的實證結果，為未來研究開啟了多個富有前景的方向。隨著 AI 代理在經濟活動中的角色日益重要，此類預測技術的發展與其倫理治理將成為關鍵的研究議題。

## 論文問答

**Q1：這篇論文主要解決什麼問題？**
A：這篇論文探討的是一個在 AI 代理經濟中日益重要的問題：當一個 AI 代理（例如買方機器人或採購助理）面對一個陌生的對手方時，該如何僅憑少數幾次先前的互動來預測對手方的下一個決策。對手方的底層大型語言模型、提示、控制邏輯以及基於規則的回退機制都是隱藏的，但每一個決策都可能帶來金錢後果。作者將此問題形式化為目標自適應文本-表格預測任務，每個決策點被表示為一個表格行，結合結構化博弈狀態、報價歷史與對話內容，而 K 個先前博弈則作為標記的適應範例提供給模型。

**Q2：為什麼現有的直接提示方法在這個問題上表現不佳？**
A：直接提示方法（即 LLM 作為預測器）雖然能讀取對話並在上下文中進行推理，但必須直接給出一個最終答案，無法靈活地將目標代理的少數博弈與大量標記的來源族群資料結合起來。這種方法受限於上下文窗口的容量，且難以系統性地從跨代理的規律中學習。相比之下，本文提出的方法將大型語言模型的角色重新定位為編碼器，由表格學習器負責在來源與目標資料列上進行適應，從而能更有效地結合族群層級的規律與目標特定的證據。

**Q3：為什麼這個研究問題在實務上很重要？**
A：在真實的商業場景中，AI 代理越來越常需要與陌生的對手方進行自然語言協商與交易，每一個錯誤的預測都可能造成實質的金錢損失。然而，現實世界的市場日誌通常不公開，且難以支援跨多個代理在相同策略條件下的系統性比較。因此，作者選擇在受控的議價博弈與談判博弈中研究此問題，這些博弈保留了語言媒介商業的核心要素：多輪報價、接受/拒絕決策、私人估值、金錢收益以及自由文本對話，同時允許研究者系統性地操控地平線、估值與資訊結構。

**Q4：這篇論文提出的核心方法是什麼？**
A：核心方法是目標自適應文本-表格預測框架，將每個決策點表示為一個表格行，結合三類互補的特徵區塊：博弈狀態特徵（如公開配置變數、回合數、當前報價與先前報價）、對話的通用文本表示，以及新提出的決策導向表示 LLM 作為觀察者。一個表格基礎模型以來源族群中先前觀察到的代理的標記資料列為條件，同時結合當前目標代理的 K 個標記博弈，使預測器能夠結合族群層級的規律與目標特定的證據，從而在不觀察對手方提示、程式碼或控制邏輯的情況下適應新的對手方。

**Q5：這篇論文最重要的創新是什麼？**
A：最重要的創新在於 LLM 作為觀察者的設計：一個小型凍結的大型語言模型讀取公開的決策時狀態與對話，其直接答案被丟棄，但其隱藏狀態被用作表格預測器的額外決策導向特徵。這種設計將大型語言模型從直接的少樣本預測器轉變為編碼器，使其隱藏的 LLM 表示能夠暴露出直接提示無法可靠揭示的決策相關信號。實驗顯示，在 K=16 時，這些觀察者特徵將回應預測的曲線下面積在兩個任務上各提升約 4 個百分點，並將議價報價預測誤差降低 14%。

**Q6：為什麼選擇將大型語言模型作為凍結的編碼器，而非可訓練的預測器？**
A：將大型語言模型保持凍結並僅提取其隱藏狀態，是一個關鍵的設計選擇，原因有三點：第一，凍結的模型保留了其在預訓練階段學到的豐富語言理解能力，避免了在少量目標資料上過擬合的風險；第二，隱藏狀態提供了比直接輸出更細粒度的決策相關信號，因為模型的中間表示往往編碼了比最終答案更豐富的語義資訊；第三，這種設計使表格學習器能夠靈活地結合觀察者特徵與其他結構化特徵，並在跨代理的來源資料上進行系統性的學習，這是直接提示方法難以實現的。

**Q7：這篇論文使用了哪些基準測試與資料集？**
A：作者使用了兩類博弈作為測試平台：議價博弈與談判博弈。在來源族群方面，他們採用了 GLEE 釋出的 13 個代理循環錦標賽，其中包含來自六個供應商的前沿大型語言模型代理，這些代理在相同提示下進行博弈，僅底層模型不同。在留出測試方面，作者引入了一個來自大學黑客松的 91 個代理資料集，這些代理共享同一個底層大型語言模型，但在提示、控制邏輯與基於規則的回退機制上有所不同，總計包含 4,921 場議價與談判博弈。這種分割設計檢驗了從一個代理變異軸（底層模型）學到的預測器是否能轉移到新遇到的、變異來自支架設計的工程化代理。

**Q8：這篇論文的關鍵實驗結果是什麼？**
A：完整的目標自適應文本-表格模型在 13 個前沿大型語言模型代理上訓練，並在 91 個留出的支架式代理上測試，其表現超越了直接 LLM 作為預測器提示與博弈加文本特徵的基線方法。在 K=16 的設定下，觀察者特徵將回應預測的曲線下面積在兩個任務上各提升約 4 個百分點，並將議價報價預測誤差降低 14%。更重要的是，這些增益主要並非來自觀察者的承諾答案，而是來自其隱藏狀態，這表明凍結的大型語言模型表示能夠暴露出直接提示無法可靠揭示的決策相關信號。

**Q9：這篇論文進行了哪些消融研究？**
A：雖然論文中沒有明確標示為「消融研究」的章節，但作者透過系統性的特徵方案比較展示了各組件的貢獻：博弈狀態特徵提供了結構化的博弈資訊；通用文本表示捕捉了對話的語義內容；而 LLM 作為觀察者的隱藏狀態則貢獻了超越前兩者的決策導向信號。實驗特別比較了觀察者的隱藏狀態與其直接輸出，結果顯示隱藏狀態提供的價值遠大於直接輸出，這是一個關鍵的消融發現，證明了將大型語言模型作為編碼器而非預測器的設計選擇是合理的。

**Q10：這篇論文的研究成果可以應用於哪些實際場景？**
A：這項研究的核心應用場景是 AI 代理之間的自動化商業協商，例如買方機器人面對未知的賣方、採購助理與供應商進行談判，或是任何需要與陌生對手方進行自然語言交易的情境。在這些場景中，預測對手方的下一步行動可以幫助代理制定更優的策略，例如決定何時接受對方的報價、何時提出反報價，或是在多輪博弈中預測對方的底線。此外，該方法也適用於任何需要從有限互動中建模隱藏代理行為的場景，例如人機協作中的使用者建模或自適應介面設計。

**Q11：在實際部署這套系統時，需要考慮哪些產品化因素？**
A：在實際部署時，需要考慮以下幾個關鍵因素：第一，計算成本，因為每個決策點都需要運行凍結的大型語言模型作為觀察者，這會增加延遲與運算開支；第二，K 值的選擇，較大的 K 值能提供更多目標特定的證據，但也意味著需要等待更多次的互動才能開始有效預測；第三，模型的更新與維護，當來源族群的代理組成發生變化時，表格基礎模型需要重新訓練；第四，解釋性問題，雖然隱藏狀態提供了豐富的決策相關信號，但其內部運作對使用者而言是不透明的，這在金融等高風險領域可能成為採用的障礙。

**Q12：這項研究對 AI 代理研究領域有什麼更廣泛的影響？**
A：這項研究對 AI 代理研究領域的影響主要體現在三個層面：在方法論上，它展示了將大型語言模型作為凍結編碼器與表格學習器結合的範式，這種思路可以推廣到其他需要從有限互動中建模隱藏代理的任務；在理論上，它揭示了大型語言模型的隱藏表示比其直接輸出包含更豐富的決策相關信號，這對理解大型語言模型的內部運作具有啟示意義；在實踐上，它為構建能夠與陌生對手方有效協商的 AI 代理提供了一條可行的技術路徑，這對於實現真正自主的 AI 經濟體具有重要意義。

**Q13：這篇論文承認了哪些局限性？**
A：這篇論文存在幾個明顯的局限性：第一，實驗是在受控的議價與談判博弈中進行的，雖然保留了語言媒介商業的核心要素，但與真實市場的複雜度仍有差距，真實的市場日誌通常包含更多噪音與策略條件的變異；第二，91 個留出代理來自大學黑客松，其多樣性可能無法完全代表真實世界中工程化代理的設計空間；第三，該方法依賴於能夠觀察到 K 個完整的先前博弈，在某些應用場景中可能難以滿足；第四，凍結的大型語言模型作為觀察者會帶來額外的計算開支，這在即時決策場景中可能成為瓶頸。

**Q14：在什麼情況下，這套方法可能會失敗？**
A：這套方法可能在以下幾種情況下表現不佳：第一，當目標代理的行為模式在 K 個先前博弈中未能充分展現時，例如代理採用高度情境依賴的策略或具有很強的隨機性；第二，當目標代理的底層大型語言模型與訓練時使用的前沿大型語言模型代理差異過大時，觀察者的隱藏狀態可能無法捕捉到相關的決策信號；第三，在高度對抗性的場景中，目標代理可能會刻意改變其行為模式以逃避預測，此時基於歷史博弈的適應範例將失去參考價值；第四，當博弈的狀態空間或對話結構與訓練時的議價和談判博弈顯著不同時，模型的泛化能力可能受到限制。

**Q15：這篇論文提出了哪些值得探索的未來方向？**
A：這篇論文開啟了多個值得探索的未來方向：第一，將框架擴展到更複雜的博弈類型與真實世界的市場日誌，檢驗其在受控環境之外的泛化能力；第二，探索更高效的觀察者設計，例如使用更小的模型或蒸餾技術來降低計算成本；第三，研究如何處理目標代理行為隨時間漂移的情境，這在長期部署中是一個實際挑戰；第四，將目標自適應文本-表格預測的範式推廣到其他需要從有限互動中建模隱藏代理的任務，例如多代理強化學習中的對手建模或人機協作中的使用者建模；第五，深入研究凍結大型語言模型隱藏狀態中編碼的決策相關信號的本質，這可能有助於理解大型語言模型的內部運作機制。

## 實務應用指南

### 適用場景

**1. 自動化採購談判助理**
企業的採購助理代理（procurement assistant）需要在不了解供應商內部 LLM、提示詞或控制邏輯的情況下，預測供應商代理對報價的反應。透過本方法，採購系統可在僅有 16 次歷史互動下，預測對手是否接受當前報價或將提出何種還價，適用於 B2B 採購、原料採購、長期合約議價等場景。

**2. 電商平台上的買賣方機器人對接**
在大型電商平台中，賣方機器人（seller bot）面對陌生買方機器人時，可利用本框架預測買方對折扣、運費或退貨政策的反應。特別適合高單價商品（如二手車、奢侈品、工業設備）的自動化議價模組，能在不暴露自家商業邏輯的前提下，預測對手的接受/拒絕決策。

**3. 多代理交易市場中的策略預判**
在多代理強化學習或自動化交易市場中，代理需要預測其他未知代理的出價行為。本方法可應用於廣告競價（real-time bidding）、能源市場結算、頻譜拍賣等場景，幫助代理在僅觀察到對手少量歷史出價的情況下，預測其下一步出價區間。

**4. 客戶服務與糾紛調解 AI**
當企業部署的客服 AI 與外部供應商的自動化糾紛處理系統互動時，可使用本框架預測對手在退款、補償或責任歸屬議題上的決策傾向，協助企業在 SLA 爭議中提前準備談判策略。

**5. 聯邦式多代理協作中的對手建模**
在多個組織各自部署專屬 LLM 代理、但需協作的場景（如跨機構物流調度、跨銀行清算），本方法可作為「黑盒對手建模」層，在不共享模型權重的前提下，僅透過對話歷史預測對手行為。

### 實作前置條件

**資料需求**
- **目標代理的歷史互動資料**：每個目標代理至少需要 K 筆（建議 K=16）完整的博弈記錄，每筆記錄需包含結構化狀態（輪數、當前報價、歷史報價序列）與對話文本。
- **來源族群（source population）訓練資料**：需有來自多個不同代理的標記決策資料。論文中使用 13 個前沿 LLM 代理的循環對抗賽資料；實務上可蒐集自家系統中不同版本、不同提示詞的代理歷史日誌。
- **標籤定義**：需明確「接受/拒絕」二元標籤（回應預測）以及「下一報價數值」標籤（提案預測），並建立統一的狀態-動作對齊格式。

**運算資源**
- **凍結 LLM（Observer）**：建議使用 7B–13B 參數量的開源模型（如 Llama-3.1-8B、Qwen2.5-7B），以單張 A100/H100 等級 GPU 即可承擔推論。
- **表格基礎模型**：可採用 TabPFN、TabICL 等現代表格基礎模型，或自建基於 Transformer 的表格模型；訓練階段在 CPU/GPU 上皆可完成，視資料規模而定。
- **儲存**：每筆決策點需儲存結構化特徵、文本嵌入與 LLM 隱藏狀態，預估每筆 1–10 KB；4,921 筆博弈（論文規模）約需數 GB。

**技能前提**
- 具備 NLP 與表格機器學習基礎（熟悉 embedding、tabular model 概念）。
- 熟悉 LLM 推論流程（vLLM、Hugging Face Transformers、hidden state 萃取）。
- 具備博弈/賽局理論基本素養（理解 payoffs、strategic conditions）。
- 具備 MLOps 能力（資料管線、模型版本管理、A/B 評估）。

### 實作步驟建議

**步驟一：定義任務與資料管線**
將業務場景對應到論文的兩個任務：
- **回應預測（response prediction）**：對手是否接受當前提案 → 二元分類。
- **提案預測（proposal prediction）**：對手下一步將提出什麼 → 數值回歸。
建立資料收集模組，記錄每個決策點的「公開狀態 + 報價歷史 + 對話文本 + 實際決策」。

**步驟二：建構三層特徵區塊**
1. **博弈狀態特徵**：回合數、當前報價、前 N 輪報價序列、剩餘時間/步數上限、雙方角色（買/賣）、公開估值區間等結構化欄位。
2. **文本表示**：使用通用 sentence embedding 模型（如 BGE、E5）將對話編碼為向量。
3. **LLM-as-Observer 特徵**：將「公開狀態 + 對話」組成 prompt，送入凍結的小型 LLM，丟棄其文字輸出，僅萃取最後一層（或倒數第二層）的 hidden state 作為特徵向量。

**步驟三：訓練表格基礎模型**
將三層特徵串接為表格行，目標變數為實際決策。使用來源族群資料訓練 tabular foundation model（如 TabPFN v2 或微調的 Transformer 表格模型）。訓練時採用交叉驗證，並監控 AUC（分類）與 MAE/RMSE（回歸）。

**步驟四：目標自適應推論**
對新遇到的目標代理：
1. 蒐集其 K 筆歷史博弈（K=16 為論文甜蜜點）。
2. 將這 K 筆作為「標記的適應範例」與來源族群資料共同輸入表格模型。
3. 對新決策點萃取三層特徵，呼叫表格模型取得預測。

**步驟五：與 LLM-as-Predictor 基線比較**
在部署前，務必以「直接提示大型 LLM + K 筆範例」作為基線比較。若表格模型未顯著超越基線，需檢查 Observer 隱藏狀態是否正確萃取、特徵是否對齊。

**步驟六：部署與監控**
- 將 Observer LLM 與表格模型封裝為低延遲推論服務（建議 P95 < 200ms）。
- 建立漂移監控：當目標代理行為分布改變時（例如供應商更新其 LLM），觸發重新適應流程。
- 設置人工覆核機制，特別在高金額決策點。

### 潛在風險與注意事項

**風險一：分布漂移（distribution shift）**
目標代理可能在部署期間更新其底層 LLM、提示詞或規則式回退邏輯，導致歷史 K 筆博弈失效。
**緩解**：建立行為漂移偵測器（例如監控預測信心分布），當漂移超過閾值時自動請求更多歷史資料或重新訓練。

**風險二：對抗性操縱**
若對手知道你在預測其行為，可能刻意製造誤導性歷史博弈（poisoning attack）。
**緩解**：對歷史博弈進行異常值檢測；對極高金額決策保留人工介入；採用 ensemble 多模型投票。

**風險三：Observer LLM 的偏見與幻覺**
凍結 LLM 的隱藏狀態雖不直接輸出，但其內部偏見仍會影響特徵品質。
**緩解**：定期以新版本開源 LLM 重新萃取特徵；在來源族群中納入多樣化代理以稀釋單一 LLM 偏見。

**風險四：冷啟動問題**
新代理完全沒有歷史時（K=0），模型僅能依賴來源族群，表現可能接近隨機。
**緩解**：設計保守的「不預測」策略；對低信心預測不採取行動；設計探索性互動以快速蒐集 K 筆資料。

**風險五：隱私與合規**
歷史博弈可能包含敏感商業資訊（價格、客戶資料）。
**緩解**：在萃取 Observer 特徵前對對話進行去識別化；採用本地部署的開源 LLM 避免資料外送；遵循 GDPR/個資法規範。

**風險六：可解釋性不足**
表格模型對業務方的「為何預測對手會接受」難以給出自然語言解釋。
**緩解**：搭配 SHAP/LIME 分析關鍵特徵；對高風險決策點同時輸出 LLM-as-Predictor 的文字推理作為輔助說明。

### 與其他技術的整合建議

**與 LLM 編排框架整合**
可將本方法嵌入 LangGraph、AutoGen、CrewAI 等多代理框架，作為「對手預測節點」。在每輪對話後呼叫 Observer LLM 萃取特徵，再由表格模型輸出預測，指導主代理的下一動作。

**與 CRM/ERP 系統整合**
將預測結果寫回 CRM（如 Salesforce、HubSpot），為業務人員提供「對手接受機率」與「建議還價區間」儀表板。採購場景可串接 SAP Ariba、Coupa 等採購系統，實現半自動議價。

**與即時競價/交易平台整合**
在 RTB、能源交易等低延遲場景，將 Observer 特徵預先計算並快取，僅在推論階段呼叫輕量表格模型，達成毫秒級回應。

**與強化學習代理整合**
將本框架作為 RL 代理的「對手模型」模組，協助代理在 self-play 之外進行穩健的策略學習，避免過擬合到特定對手。

**與監控與可觀測性平台整合**
透過 Prometheus/Grafana 監控預測延遲、信心分布、漂移指標；將預測日誌接入 ELK/Loki 供事後分析。

**與 A/B 測試平台整合**
部署時以 A/B 測試比較「有預測輔助」與「無預測輔助」的代理表現，以金額收益或成交率作為主要指標。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）與圖 1，理解「為何需要預測陌生 AI 代理」這個問題的動機。接著跳到結論段，記住三個關鍵詞：「目標自適應」、「文本-表格」、「LLM 作為編碼器」。具體的數學細節與模型架構可先略過，重點是掌握「用凍結 LLM 的隱藏狀態當作特徵，比直接讓 LLM 回答更有效」這個反直覺的發現。

**給 AI 工程師**：重點閱讀第 2、3 節的方法描述，特別是三層特徵區塊的設計與表格基礎模型的選擇。實作時建議先復現論文中的 LLM-as-Observer 模組（凍結 LLM + hidden state 萃取），再評估自家資料上表格模型（TabPFN 或自建）的表現。注意論文中 K=16 是甜蜜點，部署時應以此為基準設計資料收集策略，並務必與 LLM-as-Predictor 基線做對比實驗。

**給研究者**：本論文在「黑盒代理建模」與「表格基礎模型應用」兩個方向都有開創性。建議深入閱讀實驗章節，特別是 91 個留出代理的泛化分析、ablation study 中 Observer 特徵的貢獻度，以及來源族群（13 個前沿 LLM）與目標族群（91 個支架式代理）之間的轉移學習分析。可延伸的研究方向包括：將 Observer 換成更大或更新的 LLM、引入時序建模、結合因果推論分析對手策略意圖。

**給產品經理**：本方法的核心商業價值是「在不需取得對手內部資訊的情況下，僅靠少量歷史互動就能預測對手下一步」。在採購、議價、競價等場景中，這直接轉化為更高的成交率、更低的讓步成本、更穩定的供應鏈關係。建議優先評估自家業務中「多輪議價 + 對手為外部 AI 代理」的場景，從中選擇一個高金額、低頻次、可容忍離線訓練的場景作為試點。K=16 的資料需求在實務上通常 1–2 週即可蒐集完成，是相當務實的落地門檻。
