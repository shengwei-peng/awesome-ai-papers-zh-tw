## ⚡ TL;DR

GRPO強化學習在Lean定理證明中面臨獎勵稀疏、探索不足與模式崩潰等問題。
本文提出反饋蒸餾方法，讓模型透過詞元層級監督學習匹配自身在LLM反饋下的分布。
實驗顯示反饋蒸餾維持更高策略熵，與GRPO結合後LeanWorkbook的pass@1從59%提升至75%。

## 摘要翻譯

推理模型的訓練後微調（Post-training）通常結合監督式微調（Supervised Fine-Tuning, SFT）與可驗證獎勵強化學習（Reinforcement Learning from Verifiable Rewards, RLVR），其中最常見的是 GRPO（Group Relative Policy Optimization）。然而，此演算法存在稀疏獎勵（Sparse Rewards）、探索能力有限以及模式崩潰（Mode Collapse）等問題。基於近期自蒸餾（Self-Distillation）相關研究，我們提出**反饋蒸餾（Feedback Distillation）**，這是一種訓練模型在詞元層級（Token-Level）上匹配其自身在語言模型所產生特殊權限反饋（Privileged Feedback）條件下分布的訓練方法。反饋蒸餾提供詞元層級監督（Token-Level Supervision），並能注入外部知識。在 Lean4 定理證明任務上評估我們的方法後，我們發現反饋蒸餾相較於 GRPO 能在生成的軌跡中維持更高的多樣性（Diversity），產生更高的策略熵（Policy Entropy）與更佳的 Pass@k 擴展性。兩種方法互補：從反饋蒸餾的檢查點（Checkpoint）初始化 GRPO，其表現優於單獨使用任一方法。總結而言，我們的結果顯示了一條改善複雜推理任務訓練後微調的具前景研究方向。

### 核心貢獻（3～5點）
- 提出**反饋蒸餾（Feedback Distillation）**訓練方法，透過詞元層級監督使模型匹配其在特殊權限反饋條件下的自身分布，藉此注入外部知識並緩解 GRPO 的稀疏獎勵與模式崩潰問題。
- 實證反饋蒸餾在 Lean4 定理證明任務上相較 GRPO 能維持更高的軌跡多樣性與策略熵，並展現更佳的 Pass@k 擴展性。
- 證明反饋蒸餾與 GRPO 具有互補性：從反饋蒸餾檢查點初始化 GRPO，其表現優於單獨使用任一方法。
- 為複雜推理任務的訓練後微調流程（Post-Training Pipeline）開闢一條結合自蒸餾與強化學習的新研究方向。

### 適合對象
從事大型語言模型（LLM）後訓練（Post-training）、強化學習（RL）、形式化定理證明（Formal Theorem Proving）以及數學推理（Mathematical Reasoning）相關研究的研究者與工程師；特別關注蒸餾技術（Distillation）、獎勵設計與探索–利用權衡（Exploration–Exploitation Trade-off）的研究人員；以及對 Lean4 / Mathlib 生態系與 AI 輔助形式化證明感興趣的學術界與產業界從業者。

## 深度分析

#### 方法論解析

本文提出的核心方法——**反饋蒸餾 (Feedback Distillation)**——是建立在近期自蒸餾 (Self-Distillation) 研究脈絡之上的一種變體，其關鍵創新在於將「特殊權限反饋 (Privileged Feedback)」的來源從環境信號或標準解答 (Ground-Truth Solutions) 轉變為由凍結的語言模型 (Frozen LLM，如 Claude) 所生成的回饋意見。

**方法架構的核心要素：**

1. **學生-教師同構設定 (Student-Teacher Isomorphic Setup)**：與傳統知識蒸餾不同，反饋蒸餾採用同構的學生與教師模型（即兩者架構相同），唯一的差異在於教師模型在生成時可獲得「特殊權限資訊」。此設計避免了異構蒸餾中常見的能力差距問題。

2. **特殊權限反饋的建構流程**：
   - 學生模型首先針對 Lean4 陳述式 (Statement) 生成證明嘗試
   - 將學生嘗試與 Lean 證明檢查器 (Lean Proof Checker) 的輸出（錯誤訊息、型別錯誤等）一併封裝為提示 (Prompt)
   - 將此提示送入凍結的第三方 LLM（如 Claude），由其生成自然語言形式的反饋
   - 該反饋作為特殊權限資訊附加給教師模型，使其在「看見反饋」的條件下重新生成證明

3. **詞元層級 KL 散度損失 (Token-Level KL Divergence Loss)**：訓練目標是最小化學生模型分布 $p_{\text{student}}$ 與條件化於反饋的教師分布 $p_{\text{teacher}}(\cdot \mid \text{feedback})$ 之間的 KL 散度：
$$\mathcal{L} = \mathbb{E}_{x \sim p_{\text{student}}} \left[ D_{\text{KL}}\left( p_{\text{teacher}}(\cdot \mid x, \text{feedback}) \,\|\, p_{\text{student}}(\cdot \mid x) \right) \right]$$
此損失在詞元層級 (Token-Level) 提供細粒度的監督信號，與 GRPO 僅在軌跡層級 (Trajectory-Level) 提供稀疏獎勵形成鮮明對比。

4. **圖 1 的具體示例解析**：對於 MiniF2F 資料集中的 `mathd_algebra_480` 陳述式，學生模型傾向於使用 Unicode 符號 `π`（賦予 56.1% 機率），而教師模型在 Claude 反饋（「Lean 的 Mathlib 引理如 `Real.pi_nonneg` 引用 `Real.pi`，直接使用 `π` 可能導致統一失敗 (Unification Failures)」）的指引下，強烈偏好 `Real`（98.1% 機率）。透過 KL 損失，學生被訓練在該位置提升 `Real` 的機率，從而學會撰寫符合 Lean 規範的程式碼。

**方法的理論意涵：**

- **在策略性 (On-Policy) 知識轉移**：由於學生分布即為採樣分布，避免了 SFT 中離策略示範 (Off-Policy Demonstrations) 帶來的分布偏移問題，緩解了災難性遺忘 (Catastrophic Forgetting) 風險。
- **超越可驗證獎勵設定**：雖然本文聚焦於 Lean 環境，但反饋蒸餾不直接依賴驗證器信號，因此可推廣至缺乏確定性驗證器 (Deterministic Verifier) 的領域。
- **外部知識注入機制**：透過 LLM 反饋，可將形式化數學專家的隱性知識（如 Lean 慣例、Mathlib 命名空間結構）注入學生模型。

#### 實驗數據解讀

**核心實驗結果：**

| 訓練方法 | LeanWorkbook 測試集 Pass@1 準確率 |
|---------|-------------------------------|
| GRPO 單獨訓練 | 59% |
| 反饋蒸餾 + GRPO | 75% |

此 16 個百分點的絕對提升在形式化定理證明領域屬於顯著進步，特別考慮到 LeanWorkbook 屬於中等難度基準測試。

**關鍵評估指標分析：**

1. **策略熵 (Policy Entropy) 維持**：反饋蒸餾在訓練過程中維持較高的策略熵，這意味著模型未陷入模式崩潰 (Mode Collapse)。相較之下，GRPO 雖然能提升獎勵，但會使分布收斂至訓練前已存在的高獎勵模式（呼應 Yue et al., 2025 的觀察）。

2. **Pass@k 縮放特性 (Scaling Properties)**：反饋蒸餾訓練的模型在更大的 $k$ 值下表現更佳，顯示其生成的軌跡具有更高的多樣性 (Diversity)。這對形式化數學尤其重要，因為證明搜尋空間 (Search Spaces) 龐大，需要探索多樣化的引理組合策略 (Tactics)。

3. **方法互補性 (Complementarity)**：將反饋蒸餾檢查點 (Checkpoint) 作為 GRPO 的初始化點，產生了疊加效應。這暗示兩種方法捕獲了不同類型的學習信號——反饋蒸餾提供詞元層級的細粒度指導，而 GRPO 提供軌跡層級的獎勵優化。

**實驗設計的細節考量：**

- **基礎模型**：採用 Qwen3.5-9B 作為學生模型，此規模在形式化證明任務中屬於中等大小，平衡了計算成本與能力。
- **反饋提供者**：使用 Claude 作為凍結的第三方 LLM 提供反饋，這引入了對外部模型的依賴，但也帶來了高品質、多樣化的指導信號。
- **評估基準**：MiniF2F 與 LeanWorkbook 是形式化數學的標準基準，但兩者難度與覆蓋範圍不同，跨基準的泛化能力仍需進一步驗證。

**結果的侷限性解讀：**

- 75% 的 Pass@1 雖然優於 GRPO 的 59%，但仍未達到該領域的 SOTA 水準（部分基於測試時縮放 (Test-Time Scaling) 的系統已達更高水準）。
- 實驗未充分說明在更困難基準（如 PutnamBench）上的表現。
- 反饋蒸餾的訓練成本（包括 Claude API 呼叫費用）未被量化比較。

#### 與現有研究的比較

**相較於 GRPO 的優勢：**

| 比較維度 | GRPO | 反饋蒸餾 |
|---------|------|---------|
| 監督粒度 | 軌跡層級 | 詞元層級 |
| 獎勵稀疏性 | 嚴重（所有樣本失敗時無信號） | 透過反饋緩解 |
| 探索能力 | 易模式崩潰 | 維持高熵 |
| 外部知識注入 | 困難 | 透過 LLM 反饋自然實現 |
| 計算成本 | 較低 | 較高（需 LLM 推理） |

**相較於其他自蒸餾方法的定位：**

- **Hübotter et al. (2026)**：使用環境輸出作為特殊權限信號；本文擴展至 LLM 反饋，提供了更豐富的語義指導。
- **Shenfeld et al. (2026) 與 Zhao et al. (2026)**：使用標準解答作為特殊權限資訊；本文避免了對昂貴人工或合成標準解答的依賴，改用更易獲取的 LLM 反饋。
- **本文獨特貢獻**：首次系統性地分析自蒸餾在形式化數學中的特性，特別是策略熵維持與 Pass@k 縮放優勢。

**相較於 SFT+RLVR 範式：**

傳統的 SFT+RLVR 流程面臨三大挑戰：(1) SFT 階段受限於專家解答 (Expert Solutions) 的成本與難度；(2) 離策略示範導致災難性遺忘；(3) GRPO 的軌跡層級獎勵稀疏。反饋蒸餾透過在策略學習與詞元層級監督，同時緩解了這些問題。

**相對於測試時縮放 (Test-Time Scaling) 的互補性：**

近期形式化數學的進步（如 Varambally et al., 2026）主要來自測試時縮放——將訓練好的證明器與推理模型結合，透過迭代互動探索。反饋蒸餾改善的是基礎證明器的訓練，與這些「腳手架 (Scaffolding)」策略正交，可疊加使用。

**方法侷限性：**

1. **對外部 LLM 的依賴**：需要 Claude 等強大模型的 API 存取，引入成本與可重現性問題。
2. **反饋品質的不確定性**：LLM 反饋可能包含錯誤或不相關的建議，需透過驗證器過濾。
3. **訓練不穩定性**：作者在 Section 5 承認存在訓練不穩定問題，需謹慎調整超參數。
4. **領域特定性**：雖然方法論可推廣，但本文僅在 Lean4 上驗證，其他形式化系統（如 Coq、Isabelle）的適用性未知。

#### 可重現性評估

**有利於可重現性的因素：**

1. **基準測試公開**：MiniF2F (Zheng et al., 2022) 與 LeanWorkbook 均為公開可用的形式化數學基準。
2. **基礎模型開源**：Qwen3.5-9B 為開源模型，可從 Hugging Face 等平台獲取。
3. **Lean4 環境開源**：Lean4 證明器及其 Mathlib 函式庫完全開源。
4. **方法論透明度**：論文中提供了損失函數、訓練流程與評估協定的詳細描述。

**可重現性的潛在障礙：**

1. **Claude API 依賴**：反饋生成依賴於 Anthropic 的 Claude 模型，其 API 存取成本、版本更新與回應隨機性均會影響實驗重現。建議作者開源具體的反饋資料集或提供本地部署的替代方案。
2. **訓練超參數細節**：論文中未完整披露學習率、批次大小、KL 係數等關鍵超參數，這些對訓練穩定性至關重要。
3. **計算資源需求**：自蒸餾訓練需要同時運行學生模型與教師模型（加上 Claude API 呼叫），總計算成本較高，可能限制中小型實驗室的復現能力。
4. **評估細節**：Pass@k 的採樣策略、溫度參數、最大生成長度等評估設定需明確說明。

**建議的改進措施：**

- 開源完整的訓練程式碼與配置文件
- 釋出預訓練的反饋蒸餾檢查點
- 提供反饋資料集或本地反饋生成器的替代實作
- 詳細記錄所有超參數與訓練曲線

#### 未來研究方向

**1. 反饋機制的改進：**

- **多模型反饋融合**：整合多個 LLM 的反饋，透過投票或加權機制提升反饋品質與穩健性。
- **反饋品質驗證**：研究如何自動評估 LLM 反饋的正確性，並過濾低品質反饋以避免錯誤傳播。
- **反饋的課程學習 (Curriculum Learning)**：根據學生模型的當前能力，動態調整反饋的難度與抽象層級。

**2. 理論分析深化：**

- **收斂性分析**：在形式化設定下證明反饋蒸餾的收斂性質，特別是策略熵維持的理論依據。
- **與 GRPO 的等價性研究**：探討在何種條件下，詞元層級 KL 蒸餾與軌跡層級 RL 優化會收斂至相同的最優策略。
- **樣本複雜度界 (Sample Complexity Bounds)**：分析達到特定證明能力所需的反饋樣本數量。

**3. 跨領域推廣：**

- **其他形式化系統**：將方法推廣至 Coq、Isabelle、Agda 等其他互動式定理證明 (Interactive Theorem Proving) 系統。
- **非形式化數學**：在缺乏確定性驗證器的數學競賽問題上，探討反饋蒸餾是否仍優於純 RL 方法。
- **程式合成 (Program Synthesis)**：將 LLM 反饋蒸餾應用於一般程式碼生成任務，特別是需要滿足複雜規範的場景。

**4. 與其他技術的結合：**

- **測試時縮放整合**：將反饋蒸餾訓練的模型與 agentic 流程（如 Best-of-N 採樣、迭代修正）結合，實現訓練與推理的雙重優化。
- **過程獎勞模型 (Process Reward Models, PRM)**：探索反饋蒸餾與 PRM 的互補關係，前者提供詞元層級指導，後者提供步驟級評分。
- **多模態反饋**：整合程式碼執行結果、型別資訊、自然語言解釋等多模態反饋源。

**5. 效率與可擴展性：**

- **反饋蒸餾的蒸餾**：訓練小型本地模型模擬 Claude 的反饋行為，降低對外部 API 的依賴。
- **批次反饋生成**：透過提示工程或微調，使單次 LLM 呼叫能為多個學生嘗試生成反饋，提升訓練效率。
- **分散式訓練架構**：設計支援大規模分散式訓練的系統，使反饋蒸餾可應用於更大規模的基礎模型。

**6. 安全與對齊考量：**

- **反饋中的偏見傳遞**：研究 LLM 反饋可能引入的偏見（如特定證明風格的偏好），及其對學生模型行為的長期影響。
- **可解釋性分析**：透過分析學生模型在反饋蒸餾後的內部表示變化，理解知識轉移的機制。

這些研究方向不僅能深化對反饋蒸餾機制的理解，也將推動整個形式化推理與 LLM 訓練後微調 (Post-Training) 領域的發展。

## 論文問答

**Q1：這篇論文主要解決什麼核心問題？**
A：這篇論文主要解決大型語言模型在形式化定理證明（特別是 Lean4 環境）中進行訓練後微調（post-training）時所面臨的關鍵瓶頸。傳統的 SFT+GRPO 流程雖然是當前主流，但受限於稀疏獎勵、探索能力不足以及模式崩潰等問題，難以在 Lean 這類需要從龐大 Mathlib 引理庫中搜尋解題路徑的任務中發揮效果。作者因此提出了一種新的訓練範式，試圖在保持強化學習優勢的同時，提供更細粒度的學習信號，從而突破現有方法的性能天花板。

**Q2：為什麼現有的 SFT+GRPO 範式會失敗？**
A：現有範式的失敗可歸因於多個層面的限制。首先，SFT 階段仰賴昂貴且難以生成的專家解答資料，且因屬於離策略（off-policy）訓練，容易引發災難性遺忘，使模型在窄分布之外的表現退化。其次，GRPO 雖然被廣泛使用，但近期研究顯示它並未真正擴展模型的推理多樣性，反而傾向收斂到訓練前已存在的高獎勵模式，這對需要探索大量引理的 Lean 證明任務尤其致命。最後，GRPO 僅提供軌跡層級的獎勵，當所有採樣皆失敗時便完全沒有學習信號，造成訓練效率低落。

**Q3：為什麼形式化定理證明特別具有挑戰性？**
A：形式化定理證明的挑戰性來自於其獨特的任務特性：搜尋空間極為龐大、需要從如 Mathlib 般的大型引理庫中精準選用合適的引理，且正確性標準由確定性的 Lean 證明檢查器嚴格判定。這意味著任何語法或統一（unification）上的細微錯誤（例如使用 π 而非 Real.pi）都會導致證明失敗。此外，相較於非形式化的數學解題，形式化證明要求模型同時掌握數學直覺與 Lean 戰術（tactic）的細節，這使得純粹的強化學習探索變得格外困難。

**Q4：什麼是「反饋蒸餾」（Feedback Distillation），其運作機制為何？**
A：反饋蒸餾是一種基於自蒸餾（self-distillation）框架的訓練方法，其核心思想是讓學生模型在詞元層級（token-level）上模仿自己「在獲得特殊權限反饋（privileged feedback）後」的條件分布。具體而言，學生模型先產生一次證明嘗試，接著由凍結的教師模型（可以是自身的副本或第三方 LLM 如 Claude）根據嘗試結果與驗證器輸出產生自然語言反饋；學生模型再以該反饋為條件重新生成，並透過 KL 散度損失學習貼近此條件分布。這種設計提供了比 GRPO 更細粒度的監督信號，因為每個詞元都能獲得對應的學習訊號，而非僅有整體軌跡的成功或失敗。

**Q5：相較於既有的自蒸餾方法，本文的關鍵創新為何？**
A：本文的關鍵創新在於將「特殊權限資訊」的來源從環境輸出或標準解答，擴展為由語言模型生成的結構化自然語言反饋。這使得訓練不再受限於可驗證的環境信號，而是能注入更豐富的外部知識與修正建議，例如指出 Lean 程式碼中應使用 Real.pi 而非 unicode 符號 π 的統一失敗問題。此外，作者強調反饋蒸餾與 GRPO 是互補的：先用反饋蒸餾初始化模型，再接續 GRPO 訓練，可同時享有詞元級監督帶來的多樣性與強化學習的獎勵優化能力，這是過往自蒸餾工作較少深入探討的組合策略。

**Q6：在設計反饋蒸餾時有哪些重要的設計選擇？**
A：作者在設計上做了幾項關鍵取捨。首先，教師模型可以是學生模型的凍結副本，也可以是第三方 LLM（如 Claude），前者成本較低但反饋品質受限，後者則能提供更精準的修正建議。其次，反饋的觸發是基於學生嘗試與驗證器輸出，這意味著即使嘗試失敗，模型仍能從錯誤中學習，而非像 GRPO 在全軍覆沒時完全失去學習信號。最後，損失函數採用 KL 散度而非硬性模仿，使學生能在保留自身風格的同時吸收教師的修正偏好，這種「柔性」監督有助於維持策略熵與輸出多樣性。

**Q7：實驗使用了哪些基準測試與資料集？**
A：實驗主要在 Lean4 形式化數學環境中進行，使用 LeanWorkbook 作為訓練資料，並在 LeanWorkbook 的測試分割上評估 pass@1 準確率。此外，作者也參考了 MiniF2F（Zheng et al., 2022）與 PutnamBench（Tsoukalas et al., 2024）等形式化數學基準，這些都是當前衡量 LLM 定理證明能力的標準測試集。學生模型採用 Qwen3-8B 與 Qwen3.5-9B 等開源模型，這樣的選擇使結果具有可重現性並便於與既有研究比較。

**Q8：本研究最重要的實驗結果為何？**
A：最重要的結果是反饋蒸餾與 GRPO 的互補效應：在 LeanWorkbook 上，僅使用 GRPO 訓練的 Qwen3.5-9B 達到 59% 的 pass@1 測試準確率，而以反饋蒸餾檢查點初始化後再進行 GRPO 訓練，則可達到 75%，提升幅度相當顯著。此外，反饋蒸餾訓練後的模型展現出更高的策略熵（policy entropy）與更佳的 pass@k 擴展性，這意味著它保留了更多元的解題路徑，而非像 GRPO 般收斂到少數高獎勵模式。這些結果共同支持了作者的核心論點：詞元級監督有助於維持探索能力。

**Q9：作者進行了哪些消融研究（Ablation Studies）？**
A：作者進行了多項細部分析，包括比較不同反饋來源（凍結的學生副本 vs. 第三方 LLM Claude）的效果差異，以及探討反饋蒸餾與其他自蒸餾變體（如以標準解答作為特殊權限資訊）的相對表現。此外，他們也分析了訓練穩定性問題，並討論了反饋蒸餾作為一種「在策略知識轉移」（on-policy knowledge transfer）形式所帶來的質性影響，例如模型學會在 Lean 程式碼中使用規範的命名（如 Real.pi）而非 unicode 符號，這些細節對形式化證明的成功至關重要。

**Q10：反饋蒸餾有哪些實際應用場景？**
A：反饋蒸餾的應用場景不限於 Lean 定理證明，凡是涉及「模型嘗試後可獲得結構化反饋」的任務皆可適用，例如程式碼生成（編譯器錯誤訊息作為反饋）、數學解題（解題步驟的正確性檢查）、甚至機器人策略學習（環境回饋）。在形式化數學領域，這項技術可加速 Lean、Coq、Isabelle 等系統的自動化證明助手開發，使 AI 能協助數學家形式化新定理。此外，由於反饋可來自第三方 LLM，這也為「以強模型指導弱模型」的知識傳遞開啟了新途徑。

**Q11：在實際產品化時需要考量哪些因素？**
A：產品化時需考量幾項關鍵因素。首先是成本：若使用第三方 LLM（如 Claude）作為反饋來源，每次訓練迭代都會產生額外的 API 呼叫費用，這在規模化時可能成為瓶頸；相對地，使用凍結的學生副本雖成本較低，但反饋品質可能不如強模型。其次是延遲：反饋蒸餾需要兩輪生成（先嘗試再依反饋重生成），這比標準 SFT 多一倍推理時間。最後是品質控制：反饋本身可能包含錯誤或偏見，需要設計機制來過濾低品質反饋，避免學生學到錯誤的修正模式。

**Q12：這項研究對形式化數學與 LLM 訓練領域有何影響？**
A：對形式化數學領域而言，這項研究提供了一條不依賴昂貴專家解答、卻能持續提升自動化證明器性能的途徑，這對於加速數學形式化（如 Liquid Tensor Experiment 等大型專案）具有實質價值。對 LLM 訓練領域而言，反饋蒸餾示範了一種結合「強化學習的獎勵驅動」與「蒸餾的細粒度監督」的混合範式，挑戰了「RL 必然帶來新推理能力」的流行假設，並凸顯了維持策略多樣性的重要性。這也呼應了近期對 GRPO 模式崩潰問題的批評，為後續研究開啟了新的方向。

**Q13：作者明確承認了哪些研究限制？**
A：作者坦承訓練過程中存在不穩定性，這是反饋蒸餾的一項已知限制。此外，反饋品質高度依賴教師模型的能力——若使用凍結的學生副本，反饋可能不夠精準；若使用第三方 LLM，則受限於該模型的領域知識與 API 可用性。論文中也暗示，雖然反饋蒸餾在 LeanWorkbook 上表現優異，但其在更困難的基準（如 PutnamBench）上的泛化能力仍待驗證。最後，作者並未深入探討反饋蒸餾對模型其他能力（如同時進行非形式化數學解題）可能造成的副作用。

**Q14：在哪些情況下反饋蒸餾可能會失敗？**
A：反饋蒸餾可能在幾種情境下失效。第一，當反饋本身有誤時（例如教師模型給出錯誤的修正建議），學生會學到錯誤的模式，這在缺乏外部驗證的領域尤其危險。第二，對於極困難的問題，若學生初次嘗試與正確解答差距過大，反饋可能難以提供有意義的修正方向。第三，當任務的搜尋空間極度寬廣（如開放式數學研究問題）時，反饋蒸餾的細粒度監督優勢可能被稀釋，因為單一反饋難以涵蓋所有可能的解題路徑。最後，若學生模型容量過小，可能無法有效吸收教師反饋中的複雜修正建議。

**Q15：未來有哪些值得探索的研究方向？**
A：未來研究方向可從幾個層面展開。首先，可將反饋蒸餾擴展到其他形式化系統（如 Coq、Isabelle）以及其他需要結構化反饋的領域（如程式碼合成、化學推理）。其次，可探索更智慧的反饋機制，例如讓反饋本身也是可學習的，而非僅來自凍結模型。第三，可深入研究反饋蒸餾與其他 RL 演算法（如 PPO、DPO）的結合方式，以及如何設計更好的獎勵塑形（reward shaping）來進一步提升樣本效率。最後，作者也暗示可將此方法應用於測試時擴展（test-time scaling），結合代理式流程（agentic pipelines）以建構更強大的形式化證明系統。

## 實務應用指南

### 適用場景

1. **形式化數學研究助手**：在 Lean4 / Mathlib 環境中輔助數學家將非形式化證明轉換為可機器驗證的形式化證明，特別適用於需要處理大量引理搜尋與策略組合的場景。

2. **教育領域的互動式定理證明教學**：建置 Lean 證明教學平台時，可利用反饋蒸餾訓練的模型為學生提供逐步、引理級別的提示，而非僅給出完整解答或二元對錯回饋。

3. **自動形式化（Autoformalization）系統**：將自然語言數學文本（如教科書、競賽題解）自動轉為 Lean 程式碼的流程中，作為「證明骨架生成器」使用，搭配驗證器形成閉環。

4. **競賽數學 AI 助理**：針對 MiniF2F、PutnamBench 等基準的解題系統建構，特別是當需要兼顧 pass@1（單次答對率）與 pass@k（多次取樣答對率）時。

5. **企業內部形式化驗證工具**：在半導體驗證、密碼學協定證明、程式碼正確性證明等場景中，作為 Lean 證明生成的核心引擎，特別適合需要高覆蓋率探索的應用。

### 實作前置條件

**資料需求**
- 形式化定理語料庫：LeanWorkbook、MiniF2F、PutnamBench 等公開資料集，或自有的 Lean 專案
- 第三方反饋資料：使用 Claude、GPT-4 等強 LLM 對學生嘗試產生自然語言反饋（建議每題 1–3 條反饋）
- 驗證器輸出：每個學生生成必須經 Lean 證明檢查器執行，記錄錯誤訊息與戰術狀態

**運算資源**
- 訓練硬體：至少 4×A100/H100（80GB）以上，建議 8× 節點用於 8B–14B 規模模型
- 推理資源：教師模型（frozen copy 或第三方 API）需具備長上下文支援（≥8K tokens）
- 訓練時間：以 Qwen3.5-9B 為例，單次完整反饋蒸餾訓練預估需 200–500 GPU-hours

**技能門檻**
- 熟悉 Lean4 工具鏈（lake build、mathlib 依賴管理）
- 具備分散式訓練經驗（FSDP / DeepSpeed）
- 理解 KL 散度、token-level 監督、策略熵等概念
- 具備 prompt engineering 能力以產生高品質反饋

### 實作步驟建議

**步驟一：建立基礎管線**
- 部署 Lean4 環境並整合 Lean 證明檢查器作為確定性驗證器
- 準備 SFT 階段的專家解答資料（可從 LeanWorkbook 或自有人工標註取得）
- 完成基礎模型的監督式微調，取得初始 checkpoint

**步驟二：設計反饋生成機制**
- 選擇反饋來源：凍結的同架構模型副本（成本低）或第三方 LLM（品質高）
- 設計反饋 prompt 模板：包含學生嘗試、Lean 錯誤訊息、戰術狀態
- 範例 prompt 元素：「指出 Lean 命名慣例錯誤」、「建議使用 Real.pi 而非 π 符號」、「指出引理統一失敗原因」

**步驟三：實作反饋蒸餾損失**
- 計算學生在無反饋條件下的 token log-probability
- 計算教師在「學生嘗試 + 反饋」條件下的 token log-probability
- 最小化 KL 散度（log p_teacher − log p_student）於每個 token 位置
- 採用 on-policy 採樣：學生自己產生嘗試，而非使用預先生成的資料

**步驟四：訓練與監控**
- 監控指標：策略熵（應高於 GRPO）、pass@k 曲線、KL 散度值
- 設定早停條件：當策略熵急劇下降或 KL 散度爆炸時停止
- 定期評估 LeanWorkbook 測試集 pass@1 與 pass@64

**步驟五：與 GRPO 串接**
- 以反饋蒸餾 checkpoint 作為 GRPO 初始化
- 執行 GRPO 訓練，預期 pass@1 從 59% 提升至 75%（Qwen3.5-9B 規模）
- 比較單獨 GRPO 與「反饋蒸餾 + GRPO」的最終表現

**步驟六：部署與持續改進**
- 將訓練後模型整合到 Lean IDE 插件或 Web 介面
- 建立反饋資料回流機制：收集真實使用者的錯誤案例，產生新反饋資料
- 定期重新訓練以吸收新資料

### 潛在風險與注意事項

**風險一：訓練不穩定性**
- 現象：KL 散度在訓練後期可能劇烈波動，導致策略崩潰
- 緩解：採用梯度裁剪、學習率 warmup、KL 散度上限約束；參考論文中提到的「training instability」章節

**風險二：反饋品質不一致**
- 現象：第三方 LLM 產生的反饋可能包含錯誤建議或過時的 Lean 慣例
- 緩解：建立反饋品質過濾器（用 Lean 驗證器二次檢查反饋建議）；對反饋來源進行版本控管

**風險三：災難性遺忘**
- 現象：模型在專注於 Lean 證明後，可能喪失一般推理能力
- 緩解：混入通用語料進行聯合訓練；定期評估通用基準（MATH、GSM8K）

**風險四：模式崩潰（即使反饋蒸餾也無法完全避免）**
- 現象：長期訓練後策略熵仍可能下降，多樣性降低
- 緩解：定期重設部分訓練資料；使用 entropy bonus 項；監控 pass@k 退化

**風險五：驗證器依賴**
- 現象：Lean 證明檢查器執行耗時（單題可達數十秒），成為訓練瓶頸
- 緩解：並行化驗證、預過濾明顯錯誤的嘗試、快取常見引理查詢結果

**風險六：第三方 API 成本與延遲**
- 現象：使用 Claude 等 API 產生反饋成本高且有 rate limit
- 緩解：使用凍結的同架構模型作為主要反饋來源，僅在關鍵案例使用第三方 LLM

### 與其他技術的整合建議

**與 SFT 整合**
- 反饋蒸餾不應取代 SFT，而是接續在 SFT 之後
- SFT 提供基礎語法與戰術熟悉度，反饋蒸餾提供細粒度修正能力

**與 GRPO 整合（論文核心發現）**
- 最佳實踐：反饋蒸餾 → GRPO 的兩階段訓練
- 反饋蒸餾提供高熵、多樣性的起點，GRPO 在此基礎上進行獎勵最大化
- 避免單獨使用 GRPO：容易陷入模式崩潰，喪失探索能力

**與測試時計算擴展（Test-Time Scaling）整合**
- 反饋蒸餾訓練的模型在 pass@k 上表現優異，特別適合搭配 Best-of-N 取樣
- 可與 agentic pipeline（如 LeanAgent）結合：模型負責生成證明骨架，agent 負責迭代修正

**與其他形式化系統整合**
- 概念可遷移至 Coq、Isabelle、Rocq 等其他互動式定理證明器
- 需替換驗證器與反饋 prompt 模板，但核心訓練機制不變

**與知識圖譜整合**
- 將 Mathlib 引理依賴關係編碼為結構化先驗
- 在反饋中提示「相關引理位於 Mathlib.Algebra.X」，提升反饋品質

**與人類專家整合**
- 在高風險場景中保留人類專家審核環節
- 將模型反饋作為「初稿」，專家進行最終確認

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節了解「為什麼需要反饋蒸餾」，重點理解 GRPO 的三個限制（稀疏獎勵、有限探索、模式崩潰）。圖 1 是最佳起點，它直觀展示了「學生寫 π、教師寫 Real」這個具體範例如何體現 token-level 監督的價值。跳過數學推導，專注於「這個方法解決了什麼問題」。

**給 AI 工程師**：重點閱讀第 3 節的損失函數設計與第 4 節的實驗設定。特別注意 on-policy 採樣的實作細節、KL 散度的計算方式、以及如何整合 Lean 驗證器到訓練迴圈中。第 5 節的訓練不穩定性分析對實作至關重要，建議直接參考其緩解策略。

**給研究者**：第 4 節的策略熵與 pass@k 擴展分析是核心貢獻，建議仔細閱讀實驗設計與消融研究。與 Hübotter et al. (2026)、Shenfeld et al. (2026)、Zhao et al. (2026) 的自蒸餾工作進行比較閱讀，理解「反饋作為特殊權限資訊」相較於「環境輸出」或「真實解答」的理論意涵。第 5 節的定性分析提供了豐富的後續研究方向。

**給產品經理**：聚焦於第 1 節的動機陳述與第 4 節的最終結果（59% → 75% pass@1）。理解這個方法的核心商業價值在於：相較於單純的 RL，它能維持模型多樣性，這意味著更好的測試時擴展能力與更低的「重複犯錯」成本。建議評估自家產品中是否存在「二元獎勵導致探索不足」的類似問題，並思考反饋蒸餾的概念是否可遷移至非形式化領域（如程式碼生成、規劃任務）。
