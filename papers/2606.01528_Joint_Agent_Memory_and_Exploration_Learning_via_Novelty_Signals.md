## ⚡ TL;DR

現有語言模型智能體在開放式環境中缺乏有效探索能力，且潛在記憶缺乏可靠監督訊號。
本文提出JAMEL框架，以新穎性訊號聯合訓練智能體記憶與探索策略，形成互依迴路。
實驗顯示該方法能泛化至未見環境，探索深度媲美閉源模型並顯著降低Token消耗。

## 摘要翻譯

在開放式環境（open-ended environments）中，探索（exploration）對自主智能體（autonomous agents）而言至關重要，然而現有的語言模型智能體（language model agents）在此方面仍面臨挑戰。有效的探索需要記憶（memory），但在長期軌跡中保留原始互動歷史（raw interaction histories）的計算成本高昂。雖然潛在記憶（latent memory）為壓縮互動歷史提供了一種解決方案，但其訓練缺乏可靠的監督訊號（supervisory signals）。我們提出聯合智能體記憶與探索學習（Joint Agent Memory and Exploration Learning, JAMEL），一個透過新穎性驅動互動（novelty-driven interaction）共同訓練智能體記憶（agentic memory）與探索策略（exploration policy）的框架。我們觀察到記憶與探索形成了一個互依迴路（mutually dependent loop）：持續的探索需要記憶來區分已探索殆盡的行為與未見過的行為，而追求新穎性的互動則提供了使記憶對未來探索具備效用的監督。藉由利用確定性且持續的新穎性訊號（novelty signals）（例如 GUI 領域（GUI domain）中的程式碼覆蓋率（code coverage）），我們為記憶模組提供了自然且無註釋的監督（annotation-free supervision）。實證評估顯示，JAMEL 成功泛化至未見環境（unseen environments）。其探索能力優於開源權重基線模型（open-weight baselines），且探索深度（exploration depth）媲美閉源模型（closed-source model），同時降低 Token 消耗量（token consumption）。我們的程式碼與模型已於 https://github.com/MobileLLM/JAMEL 開源。

### 核心貢獻（3～5點）
- 提出聯合智能體記憶與探索學習（JAMEL）框架，透過新穎性驅動互動（novelty-driven interaction）聯合訓練智能體記憶（agentic memory）與探索策略（exploration policy），以解決開放式環境（open-ended environments）中語言模型智能體（language model agents）的探索難題。
- 揭示記憶（memory）與探索（exploration）之間的互依迴路（mutually dependent loop）：持續探索需依賴記憶區分已耗盡與未見行為，而新穎性追求則自然產生記憶學習所需的監督訊號（supervisory signals）。
- 利用確定性且持續的新穎性訊號（novelty signals）——如 GUI 領域（GUI domain）的程式碼覆蓋率（code coverage）——為潛在記憶（latent memory）提供無註釋監督（annotation-free supervision），無需人工標註即可有效訓練記憶模組。
- 透過實證驗證 JAMEL 可泛化至未見環境（unseen environments），其探索能力優於開源權重基線模型（open-weight baselines），探索深度（exploration depth）媲美閉源模型（closed-source model），並顯著降低 Token 消耗量（token consumption）。

### 適合對象
本論文適合研究語言模型智能體（language model agents / LLM-based agents）與自主智能體（autonomous agents）之學者與工程師，特別是關注開放式

## 深度分析

#### 方法論解析

JAMEL 將開放式環境（open-ended environments）中的探索任務形式化為有限時域的部分可觀測馬可夫決策過程（Partially Observable Markov Decision Process, POMDP），其目標並非抵達特定任務狀態，而是最大化累積的新穎性訊號（novelty signals）：\(J(\pi) = \mathbb{E}_{\tau \sim (\pi, P)} \sum_{t=1}^H r_t\)，其中 \(r_t = \text{Novelty}(s_t, H_{<t})\)。在部分可觀測環境（partially observable environment）中，智能體無法直接觀察完整狀態，必須依賴互動歷史（interaction history）\(H_{<t}\) 來推斷哪些行為已被窮盡，哪些介面區域（interface regions）或行為後果（behavioral consequences）仍屬未見。

本文的核心洞見在於記憶（memory）與探索（exploration）構成互依迴路（mutually dependent loop）：持續的探索需要記憶來區分已耗盡的行為與未見行為，而新穎性驅動互動（novelty-driven interaction）則反過來提供監督訊號（supervisory signals），使潛在記憶（latent memory）能夠學習哪些歷史資訊對未來決策有用。為了實現這一迴路，JAMEL 採用凍結的視覺語言模型（Vision-Language Model, VLM）\(F_\phi\) 作為歷史壓縮器（history compressor）。對於每一個觀測-動作對（observation-action pair）\((o_i, a_i)\)，先將其序列化為 \(x_i = \text{Format}(o_i, a_i)\)，再輸入 \(F_\phi\) 並擷取序列結尾標記（EOS token）最終層的隱藏狀態 \(h_i \in \mathbb{R}^{d_c}\)，作為該步驟的緊湊表徵。這些壓縮向量（compressed vectors）即構成記憶的向量前綴（vector prefix），以記憶 Token（memory tokens）的形式注入策略模型，從而大幅減少處理長軌跡時的原始互動歷史（raw interaction histories）所帶來的計算開銷。

在監督機制上，JAMEL 的關鍵創新是利用確定性且持續的新穎性代理指標來提供無註釋監督（annotation-free supervision）。在 GUI 領域（GUI domain）中，程式碼覆蓋率（code coverage）被用作行為新穎性（behavioral novelty）的自然代理：任何軟體應用程式均可被插樁（instrumented）以回報已執行的程式碼路徑，從而產生無需人工標註的步驟層級監督（step-level supervision）。當智能體觸及未被其歷史涵蓋的行為時，新穎性獎勵才會被觸發；最大化此獎勵會強迫以記憶為條件的策略（memory-conditioned policy）去編碼並利用「已嘗試過什麼」的資訊。這也創造了自然課程（natural curriculum）：隨著熟悉的互動被窮盡，只有更深層的多步驟序列（multi-step sequences）能持續產生新穎性獎勵，驅動策略與記憶在無需顯式課程設計的情況下共同進化。

在資料收集層面，作者透過拒絕微調（rejection fine-tuning）建立資料管線，於 86 個網頁應用程式中收集 24,000 筆訓練樣本，專門用於訓練 JAMEL 的探索能力。這種針對探索行為本身進行大規模採樣與篩選的方式，確保了記憶模組與探索策略（exploration policy）能夠在真實的互動分佈下聯合學習，而非僅依賴靜態的任務示範（task demonstrations）。

#### 實驗數據解讀

儘管提供的全文片段未包含完整的實驗表格，但從摘要與方法論的描述中，仍可對實驗設計與結果意涵進行深度解讀。首先，訓練資料涵蓋 86 個網頁應用程式、共 24,000 樣本，而測試則在 10 個保留（held-out）應用程式上進行，這表示評估重點並非單純的訓練集擬合，而是對未見環境（unseen environments）的泛化能力（generalization）。在開放式環境中，泛化是遠比平均回報更嚴苛的指標，因為它要求智能體將探索策略遷移到全新的狀態空間與互動拓撲中。

在效能宣稱上，JAMEL 的探索深度（exploration depth）不僅優於開源權重基線模型（open-weight baselines），更可與閉源模型（closed-source model）媲美。這一結果具有雙重意義：其一，它證明潛在記憶（latent memory）在充分監督下，能夠達到與大規模閉源系統相當的行為覆蓋率；其二，JAMEL 同時降低了 Token 消耗量（token consumption），這直接驗證了將長篇互動歷史壓縮為緊湊記憶 Token 的架構優勢。對於需要長期互動的自主智能體（autonomous agents）而言，Token 效率不僅是成本問題，更是決定能否在有限上下文窗口內維持有效推論時間配置（inference-time configuration）的關鍵。

值得進一步分析的是，程式碼覆蓋率（code coverage）作為新穎性訊號，其確定性（deterministic）與持續性（persistent）特質使得實驗結果具有較低的變異數，這讓作者能夠更清晰地隔離「記憶壓縮品質」對探索效能的因果影響，而非被雜訊較大的預測誤差訊號（如 ICM）所混淆。然而，也正因為該指標高度依賴可插樁的軟體環境，實驗結果的外部效度（external validity）主要受限於 GUI 領域；在無法取得底層程式碼覆蓋率的環境中，JAMEL 的絕對數值表現可能需要額外的訊號工程才能複現。

#### 與現有研究的比較

在智能體記憶（agentic memory）的研究光譜中，現有方法大致可分為三類：固定上下文窗口（fixed context windows）、外部檢索（如 RAG），以及潛在記憶（latent memory）。前兩者隨互動長度增加而面臨可擴展性瓶頸；後者如 MemoryLLM、M+、TokMem 與 Token Memory 雖然透過層級記憶池或程序性記憶 Token 提升了效率，但這些機制通常將記憶管理與智能體的學習目標解耦，依賴靜態緩衝區或啟發式檢索規則。JAMEL 的差異化在於將記憶壓縮直接嵌入探索迴路（exploration loop），使記憶的寫入與讀取目標與策略的學習目標完全一致，從而避免了「記憶編碼了無用資訊」或「策略不會使用記憶」的錯配問題。

在探索策略（exploration policy）方面，經典的內在動機方法如 ICM 與 RND 透過世界模型預測誤差或隨機網路誤差來鼓勵新穎性；Go-Explore 及其變體則維護邊境狀態檔案以進行針對性探索。JAMEL 並未發明新的探索啟發式演算法，而是解決了一個更根本的問題：如何讓新穎性訊號成為潛在記憶的可靠監督。相較於 GUI-Xplore 透過探索影片與層級下游任務來提升泛化，或 LLM-Explorer 利用緊湊知識降低逐步動作生成的成本，JAMEL 聚焦於「記憶編碼」本身——它讓探索過程中獲得的知識被壓縮進記憶 Token，並被未來的探索步驟重複使用。

然而，JAMEL 也存在可預見的侷限。首先，其無註釋監督（annotation-free supervision）在 GUI 領域依賴程式碼覆蓋率，這雖然免除了人工標註，但仍需環境層面的插樁工程，並非所有領域都能輕易取得等價的確定性訊號。其次，潛在記憶的壓縮向量缺乏人類可讀語義（human-readable semantics），這使得故障排查與記憶除錯遠比文字記憶（textual memories）困難；當智能體在保留應用程式上表現不佳時，研究者難以直接檢查記憶內容來診斷是壓縮失真還是策略誤用。最後，目前的框架主要針對純探索（pure exploration）設計，尚未顯式整合外在獎勵（extrinsic rewards），這意味著在需要平衡探索與任務完成的場景中，可能需要額外的目標函數設計。

#### 可重現性評估

從可重現性（reproducibility）的角度來看，JAMEL 具備良好的開放科學基礎：作者已將程式碼與模型權重釋出於 GitHub（https://github.com/MobileLLM/JAMEL），這大幅降低了其他研究者復現核心架構的門檻。資料集方面，24,000 筆訓練樣本橫跨 86 個網頁應用程式，且資料收集管線採用拒絕微調（rejection fine-tuning），這些資訊為第三方重建相似規模的資料集提供了具體的參考框架。

儘管如此，由於提供的全文片段在模型架構細節處截斷，若干關鍵的再現要素仍有賴原始儲存庫補充：例如，作為歷史壓縮器的凍結 VLM 具體採用何種模型（如 CLIP、LLaVA 或其他）、記憶 Token 的維度 \(d_c\)、策略模型的規模、訓練時的超參數（學習率、批次大小、記憶更新頻率），以及程式碼覆蓋率插樁的具體實作方式。此外，雖然 10 個保留應用程式的泛化實驗設計嚴謹，但這些應用程式的類型分佈、複雜度與互動深度若未詳細披露，將難以判斷「探索深度」指標的絕對意義。整體而言，JAMEL 的可重現性處於「中高」等級：核心概念與程式碼已公開，但完整的環境設定與硬體需求仍需參照原始論文的補充材料與儲存庫文件。

#### 未來研究方向

基於 JAMEL 的框架設計與現有侷限，以下幾個方向值得後續研究深入探索：

第一，**跨領域新穎性訊號的泛化**。程式碼覆蓋率雖是 GUI 領域的絕佳代理指標，但在具身環境（embodied environments）或其他無法插樁的數位環境中，需要發展自動化的類比訊號（如導航中發現新物體、操作中新狀態的觸發）。未來工作可結合自監督學習或對比學習，讓智能體自行學習領域適應的新穎性估計器，降低對確定性規則訊號的依賴。

第二，**混合記憶架構（hybrid memory）**。潛在記憶的壓縮效率與文字記憶的可解釋性並非互斥。後續研究可探索將 JAMEL 的壓縮向量與稀疏的文字記憶（textual memories）結合，例如讓潛在記憶負責快速檢索與模式完成，而文字記憶負責高階目標與異常處理，並透過新穎性訊號同時監督兩者。

第三，**長期記憶的鞏固與遺忘機制**。當前的潛在記憶似乎將所有歷史步驟的 EOS 表徵納入，但在數百步以上的超長軌跡中，記憶容量必然面臨瓶頸。引入受控遺忘（controlled forgetting）、記憶摘要（memory summarization）或分層時間尺度（hierarchical temporal scales），將有助於維持長期探索的穩定性。

第四，**從純探索到任務導向探索**。JAMEL 目前以最大化行為新穎性為單一目標。未來可研究如何將外在獎勵（extrinsic rewards）與新穎性訊號進行多目標平衡，使智能體在探索未知行為的同時，能夠朝向任務相關資訊（task-relevant information）收斂，避免無意義的介面漫遊。

第五，**多智能體共享記憶池**。若多個自主智能體（autonomous agents）在同一開放式環境中探索，它們的互動歷史可透過共享的潛在記憶池進行彙整。這將使新穎性訊號具備社會維度：智能體不僅要避免重複自己的歷史，還要避免重複其他智能體已覆蓋的行為，從而實現協作式探索。

第六，**記憶的因果解耦與歸因**。針對潛在記憶缺乏人類可讀語義的問題，未來可引入因果推論或機械可解釋性（mechanistic interpretability）工具，分析特定記憶維度對應於哪些行為單元或介面區域，從而建立壓縮向量與高階語義之間的對應關係。

## 論文問答

**Q1：JAMEL 旨在解決開放式環境中自主智能體的什麼核心問題？**
A：JAMEL 旨在解決當前基於 LLM 的智能體在開放式環境中缺乏有效探索能力的根本挑戰，這類環境通常極度稀疏或完全缺乏外在獎勵。研究指出，即使智能體在互動過程中遇到意外但與任務相關的資訊，它們在多數情況下仍無法據此行動，而這項缺陷根源於訓練方式而非推論時間配置。此外，雖然有效探索需要記憶來避免重複行為，但保留原始互動歷史的計算成本會隨軌跡長度急遽增加，而潛在記憶雖能壓縮歷史，卻又缺乏可靠的步驟層級監督訊號來指導其訓練。

**Q2：現有的智能體記憶機制為何無法充分支援探索任務？**
A：現有的記憶方法，例如固定上下文視窗或外部檢索增強生成（RAG），在互動長度增加時擴展性極差，而進階的潛在記憶方法如 MemoryLLM 或 TokMem 通常將記憶管理與智能體的學習目標解耦。這些機制往往依賴靜態緩衝區、啟發式檢索規則或標準任務示範，無法提供明確的步驟層級目標來告訴記憶應該編碼什麼，或策略應該如何使用記憶以避免重複。因此，在沒有與探索行為對齊的明確監督下，記憶模組無法有效區分已耗盡的行為與潛在的新穎行為，導致智能體在長軌跡中不斷重訪舊狀態並做出糟糕決策。

**Q3：記憶與探索之間的互依關係為何對自主智能體至關重要？**
A：本文觀察到記憶與探索形成了一個互依迴路：持續的探索需要記憶來區分已耗盡的行為與未見過的行為，而探索過程則會揭示哪些歷史資訊對未來決策有用。在部分可觀測環境中，若沒有有效的記憶，智能體無法判斷某個動作是否值得嘗試，最終只能盲目重複或隨機行動。這種相互依賴意味著單獨改進其中一個元件是不夠的，必須將兩者聯合優化，使記憶能夠編碼已嘗試的行為，同時讓策略利用這些知識去發現新狀態，從而實現真正有系統的探索。

**Q4：JAMEL 如何聯合訓練智能體記憶與探索策略？**
A：JAMEL 透過新穎性驅動互動來同時訓練智能體記憶與探索策略，將新穎性分數作為兩個元件共同的監督訊號。具體而言，該框架最大化只有在智能體達到其自身歷史未涵蓋的行為時才會授予的新穎性獎勵，這迫使以記憶為條件的策略必須編碼並利用已經嘗試過的內容。透過共享這項訊號，記憶模組學習將歷史互動壓縮為有用的潛在記憶標記，而策略則學習根據這些標記來尋找新穎狀態，形成一個統一的學習迴路。

**Q5：使用新穎性訊號作為潛在記憶監督的核心創新是什麼？**
A：核心創新在於認識到探索過程本身可以提供自然且無需註釋的監督，從而消除了對明確人類標註步驟目標的需求。在 GUI 等領域，可以透過對軟體應用程式進行插樁自動取得程式碼覆蓋率這類確定性且持續的新穎性訊號，無需額外標註即可提供可靠的行為新穎性代理指標。這種方法創造了自然課程：隨著熟悉的互動被耗盡，只有更深層的多步驟序列能持續產生新穎性獎勵，自動驅動記憶與策略協同進步。

**Q6：JAMEL 在潛在記憶模組的設計上做出了哪些具體架構選擇？**
A：JAMEL 設計了一種將歷史觀察與動作資訊壓縮為記憶標記的潛在記憶架構，大幅降低了處理長互動歷史的計算開銷。對於每個歷史步驟，系統先將觀察與動作序列化為輸入序列，再送入凍結的視覺語言模型，並取序列結尾標記在最終層的隱藏狀態作為該步驟的緊湊表示。這些壓縮後的表示被整合為記憶標記來條件化策略，使智能體無需保留完整的原始互動歷史，就能有效傳播歷史資訊並支援長期決策。

**Q7：評估 JAMEL 探索能力的實驗設置為何？**
A：實證評估在 GUI 領域進行，研究團隊建立了一個資料收集流程，透過拒絕微調的方式在 86 個網頁應用程式上收集了 24,000 筆訓練樣本。該框架以程式碼覆蓋率作為確定性的新穎性訊號，為軟體互動期間的行為新穎性提供了清晰且持續的衡量標準。為了測試泛化能力，模型在 10 個訓練時未見過的保留應用程式上進行評估，以檢驗其學到的探索與記憶能力是否能轉移到完全未見的環境。

**Q8：JAMEL 與基線模型相比的關鍵實證結果為何？**
A：結果顯示 JAMEL 能夠成功將探索能力泛化到未見過的應用程式，在探索效能上優於現有的開源權重智能體記憶基線模型。值得注意的是，其探索深度足以媲美閉源模型，同時還能減少 Token 消耗量，展現出卓越的運算效率。這些發現驗證了在新穎性訊號監督下聯合訓練記憶與探索策略，能夠在探索表現與計算成本之間取得比解耦方法更優的平衡。

**Q9：新穎性驅動的課程如何貢獻於 JAMEL 的學習動態？**
A：新穎性驅動互動創造了自然課程：智能體最初會因簡單的未探索行為獲得獎勵，但隨著這些行為被耗盡，它必須執行更深層的多步驟序列才能持續獲得新穎性獎勵。這個自動形成的課程迫使記憶模組逐步編碼更複雜且長程的歷史依賴關係，同時策略也必須學習越來越複雜的發現新狀態策略。這種湧現式的課程設計無需人工明確設計課程，並確保記憶壓縮與探索策略在訓練過程中協調地共同提升。

**Q10：JAMEL 的方法在哪些實際場景中最能有效應用？**
A：JAMEL 的方法特別適用於能夠輕易提取確定性新穎性訊號的領域，例如基於 GUI 的軟體探索，其中程式碼覆蓋率提供了自然且無需註釋的行為新穎性衡量方式。該方法也可擴展到具身環境，例如在導航與操作任務中發現新狀態或新物體時產生類似訊號的場景。任何需要自主智能體在缺乏密集外在獎勵的情況下持續探索並從長互動歷史中學習的開放式環境，都能受益於這種聯合記憶與探索的框架。

**Q11：JAMEL 在計算效率與部署方面具有哪些實務優勢？**
A：與處理完整互動歷史的基線方法相比，JAMEL 顯著減少了 Token 消耗量，使其更適合部署在資源受限或對成本敏感的應用中。透過將長軌跡壓縮為潛在記憶標記，該框架降低了 Transformer 架構智能體處理冗長互動序列時的計算開銷。此外，依賴程式碼覆蓋率等自動生成的新穎性訊號，消除了對昂貴人工標註的需求，進一步降低了訓練與部署自主探索智能體的成本與工作量。

**Q12：JAMEL 可能如何影響未來基於 LLM 的自主智能體研究？**
A：JAMEL 確立了一種訓練智能體記憶的新典範，證明探索過程本身就能產生學習緊湊且有用記憶表示所需的監督。這將研究重心從依賴外部標註或啟發式記憶規則，轉向自我監督、環境驅動的學習迴路，使記憶與策略能夠共同演化。未來在開放式智能體學習的研究中，可能會越來越多地採用新穎性驅動目標與潛在記憶架構，特別是在傳統獎勵訊號稀疏且長期記憶對有效行為至關重要的領域。

**Q13：JAMEL 框架的主要限制或約束為何？**
A：JAMEL 的一項主要限制是它依賴確定性且持續的新穎性訊號（如程式碼覆蓋率）的可取得性，而在軟體與某些具身環境之外的應用領域，這類訊號可能不易獲得或難以明確定義。在無法自動化衡量行為新穎性的任務中，框架將需要替代性的代理訊號，這可能重新引入人工設計或標註的需求。此外，雖然潛在記憶提升了效率，但其壓縮向量缺乏人類可讀語義，相較於顯式文字記憶，在解釋、除錯與手動修正記憶內容方面更具挑戰性。

**Q14：在什麼條件下，JAMEL 可能無法有效探索或學習到有用的記憶？**
A：如果環境中的新穎性訊號充滿雜訊、過於稀疏，或錯誤地獎勵表面行為而無法導向有意義的狀態覆蓋，JAMEL 可能會陷入困境，導致記憶編碼了無關的模式。當新穎性函數無法區分真正新穎且與任務相關的狀態與瑣碎的環境變化時，策略可能會利用訊號漏洞，而無法發展出連貫的探索策略。此外，在記憶容量不足以捕捉歷史完整複雜度的極長軌跡中，智能體仍可能遭受災難性遺忘或重複行為的問題，即便已採用潛在壓縮機制。

**Q15：這項工作為改進智能體記憶與探索指出了哪些未來研究方向？**
A：未來研究可以探討如何在更廣泛的領域中建立可靠的替代性新穎性訊號，例如開放式對話或創意任務，這些領域難以進行自動化插樁，可能需要透過學習型好奇心模型或世界模型預測誤差來解決。另一個有前景的方向是開發混合記憶架構，結合潛在標記的效率與顯式文字記憶的可解釋性，同時實現自動化學習與人類監督。最後，將此聯合學習框架擴展到多智能體環境或終身學習場景，使智能體必須在無限長的時間跨度中持續調適其記憶與探索策略，將是邁向真正自主智慧的重要下一步。

## 實務應用指南

### 適用場景

1. **跨應用程式自動化測試與品質保證**  
   在 SaaS 或企業內部軟體迭代過程中，JAMEL 可作為自主測試智能體，利用程式碼覆蓋率作為新穎性訊號，主動探索未觸及的程式路徑與介面狀態，自動生成高覆蓋率的測試軌跡，減少人工撰寫測試案例的成本。

2. **遺留系統（Legacy System）的流程探勘與數位化**  
   針對缺乏文件的老舊內部系統或 ERP，JAMEL 能透過潛在記憶壓縮長期互動歷史，避免重複點擊已探勘的功能模組，持續挖掘隱藏的業務流程與資料欄位，協助企業完成流程自動化（RPA）前的系統盤點。

3. **開放世界遊戲與模擬環境的內容發現**  
   在開放式遊戲或元宇宙模擬器中，以狀態發現或物件遭遇作為新穎性訊號，JAMEL 可驅動 NPC 或測試機器人深入探索地圖邊界與特殊事件觸發條件，突破腳本化行為的限制。

4. **智慧型網頁資料探勘與動態介面爬蟲**  
   面對現代 Web 應用的大量動態載入與條件渲染，傳統爬蟲難以觸及深層內容。JAMEL 的記憶機制能追蹤已執行的互動組合，策略性地嘗試新的表單輸入或按鈕序列，適用於價格監控、公開資料彙整等場景。

5. **具身智能機器人在未知空間的導航與操作**  
   雖然論文以 GUI 領域為主，但其框架可遷移至具身環境。透過「新發現的物體類別」或「未造訪的區域」作為新穎性訊號，機器人可利用潛在記憶避免重複巡視相同空間，提升長期自主任務的執行效率。

### 實作前置條件

**資料條件**  
目標環境必須能提供**確定性且持續的新穎性訊號**。在 GUI 領域，這意味著應用程式需可被注入覆蓋率探針（如 JavaScript 的 Istanbul、Java 的 JaCoCo）；若無法取得程式碼覆蓋率，則需自行設計狀態雜湊（state hash）或畫面語意差異函數來代理 `Novelty(s, H)`。此外，需準備數十個以上的目標應用程式作為訓練環境，以複現論文中 86 個 Web 應用的規模。

**運算資源**  
需具備微調大型視覺語言模型（VLM）的 GPU 叢集。雖然論文使用凍結的 VLM 作為歷史壓縮器，但記憶編碼器與探索策略的聯合訓練仍需顯存支援長序列與潛在記憶 Token 的梯度回傳。資料收集階段的拒絕微調（Rejection Fine-Tuning）亦需大量推論算力進行軌跡篩選。

**技術能力**  
團隊需熟悉 LLM/VLM 的參數高效微調（如 LoRA）、強化學習或獎勵篩選式訓練，並能理解部分可觀測馬可夫決策過程（POMDP）與記憶網路設計。同時需具備目標環境的程式化控制能力（如透過瀏覽器自動化框架操作 GUI）。

### 實作步驟建議

**步驟一：環境 Instrumentation 與新穎性訊號定義**  
為目標應用程式植入覆蓋率收集工具，定義步驟層級的新穎性獎勵函數。若使用程式碼覆蓋率，需確保其顆粒度（函數級或分支級）能反映語意上的行為差異，而非僅是無意義的程式路徑抖動。

**步驟二：設計潛在記憶架構**  
建構記憶壓縮模組。參考論文做法，可選用現成開源 VLM（如 Qwen-VL、LLaVA）作為凍結的歷史壓縮器，抽取每個互動步驟的 EOS Hidden State，再透過可訓練的記憶投影層將其轉化為 Memory Tokens。決定記憶更新機制（如每步覆寫或累加殘差）。

**步驟三：建立拒絕微調資料管線**  
讓初始策略與環境互動收集軌跡，根據累積新穎性獎勵篩選出高品質片段。論文收集 24k 訓練樣本橫跨 86 個應用程式，實務上建議先以 10–20 個應用程式進行概念驗證（PoC），確認訊號品質後再擴大規模。

**步驟四：聯合訓練記憶與策略**  
同時優化記憶編碼器與探索策略，目標為最大化累積新穎性獎勵。訓練過程中監控記憶是否出現崩潰（collapse）——即無論歷史為何，記憶向量都趨於相似。可透過輔助對比損失或週期性凍結策略來穩定訓練。

**步驟五：未見環境泛化驗證與部署**  
保留 10–20% 的應用程式作為 Held-out 測試集，評估探索深度與 Token 消耗量。部署時，將 JAMEL 封裝為探索服務，接收環境觀測後回傳動作，並定期將壓縮記憶寫入外部快取以支援超長軌跡。

### 潛在風險與注意事項

**新穎性訊號與語意目標脫鉤**  
程式碼覆蓋率並非總是對應使用者關心的語意新穎性。例如，觸發錯誤處理路徑可能提升覆蓋率，但畫面僅顯示空白錯誤頁。建議採用**混合訊號**（如 coverage + DOM 結構變化率 + 畫面雜湊），並在訓練前進行訊號相關性分析。

**潛在記憶的不可解釋性**  
與文字記憶不同，潛在記憶的壓縮向量缺乏人類可讀語義，除錯困難。實務上應建立**記憶探針（probing）機制**：定期檢查記憶向量是否能透過簡單分類器區分「已探索」與「未探索」狀態，確保其編碼了有效資訊。

**長軌跡的記憶漂移**  
隨著互動歷史增長，潛在記憶可能累積雜訊或遺忘早期關鍵決策點。若應用場景涉及數百步以上的軌跡，建議引入**分層記憶**（hierarchical memory）：近期歷史使用精細潛在記憶，遠期歷史則額外保存稀疏的文字摘要。

**領域遷移的訊號重新設計**  
從 GUI 遷移至具身環境或其他領域時，不可直接套用程式碼覆蓋率。需重新設計確定性新穎性指標（如 3D 場景中物體座標的離散化格子佔據率），否則互依迴路將因監督訊號失效而崩解。

### 與其他技術的整合建議

**與 RAG 及外部向量資料庫的互補**  
JAMEL 的潛在記憶適合編碼**短期互動上下文**，而長期知識（如使用者手冊、API 文件）仍可由傳統 RAG 透過向量資料庫（如 Milvus、Pinecone）檢索提供。兩者結合可兼顧探索效率與知識準確性。

**嵌入現有自動化測試框架**  
可將 JAMEL 作為探索引擎整合進 Playwright、Selenium 或 Appium 的測試管線中。JAMEL 負責產生高覆蓋率的互動序列，再由傳統斷言（assertion）檢查功能正確性，形成「探索 → 驗證」的閉環。

**在 LLM Agent 編排框架中擔任「探索專家」**  
於 LangChain、AutoGen 或 CrewAI 等多智能體架構中，JAMEL 可作為專責探索的節點（node）。當任務導向的 LLM 遇到未知錯誤或介面狀態時，呼叫 JAMEL 進行限時探索，收集環境資訊後再交還給主策略進行決策。

**結合內在動機方法強化訊號**  
可將 ICM（Intrinsic Curiosity Module）或 RND（Random Network Distillation）的預測誤差作為輔助新穎性訊號，與 JAMEL 的規則型訊號（如 coverage）進行加權融合，提升在 stochastic 環境中的探索穩健性。

---

### 給不同背景讀者的閱讀建議

**給初學者**  
先建立核心直覺：「為什麼智能體需要記憶才能有效探索？」把 JAMEL 想像成一位會主動記錄自己逛過哪些網頁功能的助理，並且因為找到新功能而獲得獎勵。不必急著理解 POMDP 數學，重點閱讀論文的架構圖（Figure 1）與 GUI 實驗結果，理解潛在記憶如何幫助減少 Token 消耗。

**給 AI 工程師**  
請聚焦於第 3.2 節的模型架構與資料收集管線。特別注意凍結 VLM 作為歷史壓縮器的實作細節、Memory Token 與策略網路的聯合訓練方式，以及拒絕微調（Rejection Fine-Tuning）的篩選閾值設定。這些是決定能否在實務場景複現探索能力的關鍵工程環節。

**給研究人員**  
建議深入分析記憶與探索的**互依迴路**（mutually dependent loop）以及**自然課程**（natural curriculum）的形成動力學。思考新穎性訊號的設計空間：除了程式碼覆蓋率，科學實驗設計、藥物分子合成或連續控制領域中，是否也存在確定性且無需人工標註的代理指標？這是將 JAMEL 框架泛化至高維度連續空間的重要研究方向。

**給產品經理**  
請優先關注兩個商業價值指標：**降低 Token 消耗量**（直接影響營運成本）與**泛化至未見應用**（決定產品能否規模化）。在評估導入時，需盤點目標系統是否能自動化產生類似 code coverage 的回饋訊號，並確認工程團隊具備微調開源模型的能力，以權衡自建 JAMEL 與直接呼叫閉源 API 的總體擁有成本（TCO）。
