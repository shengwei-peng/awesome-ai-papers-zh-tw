## 摘要翻譯

形態學轉換（morphological transforms）是形狀與遮罩處理領域長期以來的工具，但 Python 生態系中事實標準（de-facto standard）的參考實作 scipy.ndimage 僅為 CPU、單陣列（CPU-only, single-array）實作，因此若未經昂貴的裝置到主機往返（device-to-host round trip），便無法在 GPU 訓練迴圈（GPU training loop）中使用。基於 PyTorch 建構的 GPU 視覺函式庫（GPU vision libraries）僅涵蓋這些運算子的一小部分，通常僅限於兩個空間維度（spatial dimensions）與扁平結構元素（flat structuring elements）。本文提出 TorchMorph，一個輕量級的 PyTorch 擴充套件（PyTorch extension），以填補此缺口。TorchMorph 公開 22 個運算子（public operators），涵蓋二值形態學（binary morphology）、灰階形態學（greyscale morphology）、精確距離轉換（exact distance transforms）與近似距離轉換（approximate distance transforms），以及熵正規化最佳傳輸（entropy-regularised optimal transport）；所有運算子皆以融合 CUDA 核心（fused CUDA kernels）實作，可直接作用於 (B, C, Spatial...) CUDA 張量（CUDA tensors），並支援多達八個空間維度（spatial dimensions）。其 API 刻意逐引數對應（argument-for-argument）地鏡像 scipy.ndimage，包含邊界模式（border modes）、結構元素原點（structuring-element origins）與預先配置的輸出（pre-allocated outputs），因此既有流程只需修改 import 陳述式即可移植。本文闡述分層架構（layered architecture），以及各運算子家族（operator family）背後的核心設計（kernel designs）。相較於單執行緒 CPU 參考實作（single-threaded CPU references），批次執行（batched execution）在灰階形態學上的吞吐量（throughput）最高可達 scipy.ndimage 的 1.1×10³ 倍，在精確歐氏距離轉換（exact Euclidean distance transforms）上則高達 350 倍，而 Sinkhorn 求解器（Sinkhorn solver）比 POT 快達 42 倍。二值運算子（binary operators）與倒角運算子（chamfer operators）可精確重現其 SciPy 對應實作，而所有浮點數運算子與 CPU 參考實作的絕對誤差（absolute error）均小於 1.8×10⁻⁶。TorchMorph 以 MIT 授權（MIT licence）釋出，網址為 https://intcomp.github.io/tm。

### 核心貢獻（3～5點）
- 提出 TorchMorph：一個輕量級 PyTorch 擴充套件，提供 22 個公開運算子，涵蓋二值/灰階形態學、精確/近似距離轉換與熵正規化最佳傳輸，並支援多達八個空間維度。
- 所有運算子皆以融合 CUDA 核心實作，可直接作用於批次 CUDA 張量，無需裝置到主機往返即可嵌入 GPU 訓練迴圈。
- API 刻意與 scipy.ndimage 逐引數對應，降低既有 CPU 管線移植至 GPU 的門檻。
- 在灰階形態學與精確歐氏距離轉換等任務上，相較單執行緒 CPU 參考實作達到數百倍吞吐量提升；Sinkhorn 求解器較 POT 快達 42 倍。
- 二值與倒角運算子可精確重現 SciPy 結果，所有浮點運算子的絕對誤差均小於 1.8×10⁻⁶。

### 適合對象
適合需要在大規模影像或體積資料上進行可微分、GPU 加速形態學運算的深度學習研究者與工程師，特別是正在使用 scipy.ndimage 並希望無縫移植至 PyTorch GPU 訓練迴圈的電腦視覺、醫學影像與科學計算從業人員，以及開發相關下游函式庫的維護者。

## 深度分析

#### 方法論解析

TorchMorph 的方法論核心，是將傳統上由 **scipy.ndimage（SciPy 的 N 維影像處理參考實作）** 壟斷的**形態學轉換（morphological transforms）**，重新實作為可直接作用於 **PyTorch tensors（PyTorch 張量）** 的 **批次並行 CUDA 核心（batch-parallel CUDA kernels）**。現代深度學習管線中的影像資料通常以 `(B, C, Spatial...)` 的 **CUDA tensors（CUDA 張量）** 形式存在，而 **scipy.ndimage** 是**僅 CPU（CPU-only）**、**單陣列（single-array）** 的實作，每次呼叫都會觸發昂貴的 **device-to-host round trip（裝置到主機往返）**，並且在 CPU 上以單執行緒執行，這使得它無法直接嵌入 **GPU training loop（GPU 訓練迴圈）**。

為了解決這個問題，TorchMorph 採用了「語義優先、效能其次」的設計哲學：它並非重新發明一套新的 API，而是**逐參數鏡像 scipy.ndimage 的介面**，包括 `size`、`footprint`、`structure`、`mode`、`cval`、`origin`、`iterations`、`mask`、`border_value`、`return_distances`/`return_indices` 等關鍵字，甚至支援 **pre-allocated outputs（預先配置的輸出緩衝區）**。這種設計讓現有管線的移植成本幾乎只是「換一個 import」，同時也確保了**邊界模式（border modes）**、**結構元素原點（structuring-element origins）**與迭代語義的一致性。

在運算子覆蓋面上，TorchMorph 提供 22 個公開運算子，分屬四大家族與一個**結構元素（structuring elements）**工具群：

1. **二值形態學（binary morphology）**：`binary_erosion`、`binary_dilation` 及其組合（開運算、閉運算等）。
2. **灰階形態學（greyscale morphology）**：`grey_erosion`、`grey_dilation` 以及由此衍生的 opening、closing、gradient、Laplacian、top-hat 等。
3. **距離轉換（distance transforms）**：**精確歐氏距離轉換（exact Euclidean distance transforms, EDT）**（透過可分離的 lower-envelope 演算法）、chessboard/taxicab **倒角運算子（chamfer operators）**，以及一個暴力精確 oracle。
4. **熵正規化最佳傳輸（entropy-regularised optimal transport）**：以 **Sinkhorn solver（Sinkhorn 求解器）** 在 scaling 與 log domain 求解，並對兩個邊際分布皆可微。

值得注意的是，圖 1 中只有粗體項目擁有專屬的 CUDA kernel，其餘運算子是在 Python/host 端透過組合這些核心來實現。這是一個關鍵的架構決策：它最小化了 device 程式碼的數量，同時最大化 API 覆蓋率，因此新增一個 top-hat 變體不需要撰寫任何 CUDA 程式碼。

架構上分為三層：

- **Python 層**：負責引數正規化與驗證。它會依照 `structure > footprint > size` 的優先順序解析**結構元素（structuring element）**、將 `origin` 展開為每軸 tuple、對邊界模式字串進行編碼映射，並在 host 端組合衍生運算子。
- **C++/CUDA 層**：實作**融合 CUDA 核心（fused CUDA kernels）**。每個運算子一次 kernel launch，結構元素幾何在 host 端解析完成，並透過「內部快速路徑（interior fast path）」移除每軸的邊界條件判斷，以減少分支與記憶體存取。
- **Host 端組合層**：將開運算、閉運算、形態學梯度等運算子表示為侵蝕/膨脹的組合。

在**熵最佳傳輸（entropic optimal transport）**方面，TorchMorph 的 Sinkhorn 實作支援 **CUDA-graph replay（CUDA 圖形重播）**，這對於需要反覆執行固定計算圖的訓練損失來說，能進一步降低 kernel launch 開銷。相較於 **POT（Python Optimal Transport 函式庫）**，TorchMorph 的優勢在於原生支援 batch 維度與 GPU 張量。

不過，方法論上有一個明確的權衡：TorchMorph 強調與 scipy.ndimage 的數值一致性與語義一致性，而非可微性。相較於 **Kornia** 提供可微分的二維形態學，TorchMorph 的侵蝕/膨脹本質上是 `min`/`max` 運算，並不保證處處可微。因此它更適合作為後處理或標籤準備工具，而非直接嵌入需要平滑梯度的網路層。

#### 實驗數據解讀

論文摘要中給出的效能數字相當顯著：相較於單執行緒 CPU 參考實作，TorchMorph 在灰階形態學上可達到高達 **1.1×10³ 倍吞吐量（throughput）**，在**精確歐氏距離轉換（exact Euclidean distance transforms）**上高達 **350 倍**，而 Sinkhorn 求解器相較於 POT 可達 **42 倍**加速。這些數字需要從幾個角度理解：

首先，這些是**吞吐量**而非延遲的比較。TorchMorph 的設計目標是處理 `(B, C, Spatial...)` 的批次張量，因此加速來自三個方面：(1) 將原本需要 Python loop 逐樣本呼叫 scipy.ndimage 的過程，轉換為單一 CUDA kernel launch；(2) 避免 device-to-host 的資料搬移；(3) 利用 GPU 的記憶體頻寬與大量執行緒平行處理空間維度。對於 3-D 或 4-D 的體積時間序列（volumetric time series）這類「易並行工作負載（embarrassingly parallel workload）」，加速效果會特別明顯。

其次，數值正確性的驗證結果同樣重要：**二值運算子（binary operators）**與**倒角運算子（chamfer operators）**能與 SciPy 對應實作**完全重現（exact reproduction）**；所有浮點運算子的**絕對誤差（absolute error）**不超過 **1.8×10⁻⁶**。這個誤差水準處於單精度浮點數（float32）的合理範圍內，主要來自 CUDA 平行化後的 reduction 順序與浮點結合律差異，而非演算法層面的分歧。這驗證了 TorchMorph 不僅在 API 上與 scipy.ndimage 相容，在數值結果上也具有參考等價性。

然而，這些實驗數據也有一些解讀上的限制：

- 比較基準是**單執行緒 CPU references（單執行緒 CPU 參考實作）**。雖然 scipy.ndimage 在論文脈絡中被描述為單執行緒，但若啟用多執行緒或改用其他最佳化 CPU 實作，加速倍數會下降。不過，即使 CPU 端再快，device-to-host 往返與 Python loop 的開銷在訓練迴圈中仍是無法迴避的瓶頸。
- 論文未說明實驗使用的資料集或張量尺寸。從上下文推測，這些數字很可能來自合成張量（synthetic tensors）的標準化測試，而非真實醫學影像或下游任務。因此，實際應用中的加速倍數會因資料大小、記憶體佔用與 batch size 而有所不同。
- 評估指標主要集中在吞吐量與元素級誤差，缺少對記憶體使用量、編譯時間、不同 CUDA 架構的擴展性，以及下游任務（如分割後處理或邊界感知損失）的影響評估。

#### 與現有研究的比較

TorchMorph 在現有生態系中的定位，可以透過論文表 1 的六個維度來理解：**Torch（原生 torch.Tensor）**、**Batch（單一呼叫處理批次）**、**N-D（超過三個空間維度）**、**Sem.（與 scipy.ndimage 語義一致）**、**EDT（精確歐氏距離轉換）**、**OT（最佳傳輸）**。

- **scipy.ndimage**：作為事實標準（de-facto standard），在語義與邊界行為上是黃金參考，但完全不支援 GPU、批次與 N-D 張量。TorchMorph 的設計目標就是保留其語義，同時補上這些缺失。
- **scikit-image / OpenCV**：兩者都是**主機端（host-side）**函式庫，且快速路徑（fast paths）多限於二維影像，無法原生處理批次或高維張量。
- **Kornia**：提供原生 **torch.Tensor** 運算子、GPU 支援與批次處理，並且具備**可微分二維形態學（differentiable 2-D morphology）**的優勢。然而它缺乏 N 維運算子、完整的 scipy 邊界模式矩陣、精確 EDT 與 OT。TorchMorph 則在維度擴展性與運算子覆蓋面上勝出，但犧牲了形態學運算子的可微性。
- **cuCIM**：透過 **CuPy** 提供 GPU 形態學，但本質上是一個**互操作性層（interoperability layer）**，而非原生 torch.Tensor 運算子，也不支援批次維度與 N-D 語義。
- **MONAI**：作為醫學影像 AI 框架，它將部分形態學後處理步驟委託給 SciPy 或 CuPy，因此在批次、N-D、EDT 與 OT 上僅有部份或間接支援。
- **POT**：專注於最佳傳輸，支援 GPU 與批次，但不提供形態學或距離轉換，也不遵循 scipy.ndimage 的語義慣例。

總結來說，TorchMorph 是目前唯一同時滿足「原生 PyTorch 張量、GPU 加速、批次維度、N-D 空間、scipy 語義、精確 EDT、熵正規化 OT」這六項條件的函式庫。它的主要貢獻不是提出新的演算法，而是將這些經典演算法統一到現代深度學習的張量慣例中，並以融合 CUDA 核心的方式實現。

不過，TorchMorph 也有其侷限性：

- **CUDA-only**：目前僅支援 NVIDIA GPU，沒有 CPU fallback 或 ROCm 後端，這限制了它在邊緣裝置或非 CUDA 環境中的可用性。
- **形態學不可微**：對於需要將侵蝕/膨脹作為可微網路層的應用，Kornia 仍是更合適的選擇。
- **結構元素幾何在 host 端解析**：雖然這減少了 device 端分支，但也意味著每個 kernel call 通常對整個 batch 使用相同的結構元素，對於需要每樣本動態結構元素的應用可能不夠靈活。
- **效能比較基準**：與單執行緒 CPU 的比較雖然合理，但可能誇大了相對於多執行緒或最佳化 CPU 實作的優勢。

#### 可重現性評估

TorchMorph 在可重現性方面具備良好基礎。原始碼以 **MIT licence（MIT 授權）**釋出，並可於以下兩處取得：

- 文件與發布頁面：https://intcomp.github.io/tm
- 原始碼倉庫：https://github.com/intcomp/torchmorph

這是一個**輕量級 PyTorch 擴充套件（lightweight PyTorch extension）**，僅依賴 PyTorch 與 CUDA toolchain，沒有複雜的外部依賴。論文也明確說明所有運算子都經過元素級驗證：二值與倒角運算子與 SciPy 完全吻合，浮點運算子與 CPU 參考的絕對誤差在 1.8×10⁻⁶ 以內，Sinkhorn 則與 POT 比較。這種對參考實作的嚴格對齊，大幅提升了結果的可信度與可重現性。

然而，仍有幾點需要注意：

- **資料集與模型權重**：這是一個演算法函式庫，不涉及訓練模型或資料集，因此沒有模型權重（model weights）的問題。但論文未詳細說明效能測試的腳本、隨機種子或張量尺寸，若 benchmark 程式碼未一併釋出，則第三方難以完全重現 1100×、350×、42× 這些數字。
- **編譯環境**：作為 CUDA 擴充套件，使用者需要正確的 CUDA driver、toolkit 與 PyTorch 版本才能編譯與執行。雖然 MIT 授權降低了法律門檻，但環境設定仍是可重現性的潛在障礙。若能提供預編譯的 pip/conda wheel 與持續整合（CI）測試矩陣，將進一步提升可重現性。
- **測試覆蓋率**：論文未明確說明單元測試的範圍。考慮到它支援高達八個空間維度與多種邊界模式，完整的測試需要覆蓋各種維度組合、邊界條件與結構元素原點，這對長期維護至關重要。

#### 未來研究方向

基於 TorchMorph 的設計與現有侷限，未來研究可以朝以下幾個方向延伸：

1. **可微分形態學的整合**：在保留 scipy 語義的基礎上，提供可選的平滑近似（例如以 soft-min/soft-max 或學習型結構元素取代硬 min/max），讓侵蝕、膨脹與形態學梯度能直接嵌入需要反向傳播的網路層，彌補與 Kornia 之間的差異。

2. **跨硬體後端支援**：除了 CUDA，可考慮加入 CPU fallback、ROCm 支援，或透過 PyTorch 的 `torch.compile` / Inductor 產生後端無關的程式碼，以擴大適用場景。

3. **運算子擴展**：加入更多經典形態學與幾何演算法，例如 hit-or-miss 轉換、**骨架化（skeletonisation）**、**分水嶺種子點（watershed seeding）**、測地重建（geodesic reconstruction）、連通元件標記（connected-component labeling）、非平面結構元素（non-flat structuring elements），以及各向異性體素（anisotropic voxels）支援。

4. **記憶體與擴展性最佳化**：對於大型 3-D / 4-D 體積資料，可引入 tile-based 計算、in-place 運算、混合精度（mixed precision），以及更細緻的 shared memory 使用策略，以降低 GPU 記憶體佔用。

5. **下游任務驗證**：在真實應用（如醫學影像分割後處理、邊界感知損失、Hausdorff 距離代理）中評估 TorchMorph 的端到端加速效果與數值穩定性，並與多執行緒 CPU 實作進行更公平的比較。

6. **與生態系更深度的整合**：提供 MONAI、Kornia 或 torchvision 的 adapter/plugin，支援 **CUDA graphs（CUDA 圖形）**以外的最佳化（如 kernel fusion、persistent kernels），並探索 ONNX 匯出可能性。

7. **最佳傳輸的進階功能**：擴展 Sinkhorn 實作以支援自適應正規化參數 epsilon、Wasserstein barycenters、更穩定的 log-domain 預設行為，以及批次內逐樣本的收斂判斷。

8. **距離轉換的梯度傳播**：研究如何讓精確歐氏距離轉換與倒角轉換在自動微分框架中提供有用的次梯度或平滑近似，使其能作為可訓練損失函數的核心組件。

## 論文問答

**Q1：TorchMorph 主要是為了解決什麼問題？**
A：TorchMorph 針對的是現代 AI 影像管線中，形態學運算仍然被困在 CPU 上的問題。傳統的 `scipy.ndimage` 是僅 CPU、單陣列的參考實作，每次呼叫都必須把張量從 GPU 複製到主機、計算完再複製回去，這在訓練迴圈中非常昂貴。此外，現有 GPU 視覺函式庫大多只支援二維、扁平結構元素或部分運算子，無法滿足三維、四維甚至更高維度資料的批次處理需求，TorchMorph 正是為了填補這個涵蓋範圍缺口而設計。

**Q2：為什麼現有的 GPU 視覺函式庫無法滿足需求？**
A：現有函式庫各自有明顯的侷限：Kornia 雖然提供可微分的二維形態學，但缺乏 N 維運算子、完整的 `scipy.ndimage` 邊界模式以及精確歐氏距離轉換；cuCIM 透過 CuPy 提供 GPU 形態學，卻是互操作性層而非原生 `torch.Tensor` 運算子；MONAI 常把形態學後處理委託給 SciPy 或 CuPy；OpenCV 與 scikit-image 的快速路徑則停留在主機端且多為二維。至於熵正規化最佳傳輸又屬於另一套獨立堆疊，因此實務上必須拼湊多個函式庫，造成張量慣例與效能上的不一致。

**Q3：在 GPU 訓練迴圈中直接執行形態學運算為何重要？**
A：形態學掃描的計算成本會隨所有空間維度大小的乘積增長，對於體積時間序列或多通道斷層掃描這類三維、四維資料，CPU 很快就會成為瓶頸。若使用 `scipy.ndimage`，每次迭代都要進行裝置到主機的往返複製，並且以 Python 迴圈逐張處理批次資料，這會把原本極易並行化的工作負載強制序列化。TorchMorph 讓這些運算直接在 CUDA 張量上以批次並行方式執行，消除了昂貴的資料搬移，使形態學後處理、標籤準備與損失計算都能嵌入訓練迴圈。

**Q4：TorchMorph 的核心方法是什麼？**
A：TorchMorph 將 22 個公開運算子實作為融合 CUDA 核心，能直接對形狀為 `(B, C, Spatial...)` 的 CUDA 張量進行運算，並支援最多八個空間維度。它的 API 刻意逐參數對齊 `scipy.ndimage`，包括 `size`、`footprint`、`structure`、`mode`、`cval`、`origin` 等關鍵字，以及預先配置的輸出緩衝區，因此現有程式碼通常只需改變匯入即可移植。核心設計上，結構元素幾何在主機端解析，核心內部有去除每軸邊界測試的內部快速路徑，而 Sinkhorn 迭代則可利用 CUDA 圖形重播來降低發射開銷。

**Q5：TorchMorph 的關鍵創新有哪些？**
A：關鍵創新在於它是首個將二值形態學、灰階形態學、精確與近似距離轉換，以及熵正規化最佳傳輸統一在原生 PyTorch 張量世界中的輕量擴充套件。它支援高達八維空間秩的批次資料，並且與 `scipy.ndimage` 的語義保持一致，讓三維、四維資料成為一等公民而非特例。此外，透過融合核心與一次發射的設計，它避免了把運算拆成多個通用張量原語所帶來的額外記憶體與同步成本。

**Q6：TorchMorph 的分層架構與設計選擇為何？**
A：函式庫分為三層：Python 層負責正規化與驗證引數，例如按照 `structure > footprint > size` 的優先順序解析結構元素、把 `origin` 擴展為每軸元組、將邊界模式字串對應為整數編碼，並由主機端組合衍生運算子；C++/CUDA 層則執行真正的融合核心。這種設計的好處是，像開運算、閉運算、形態學梯度、拉普拉斯與禮帽變換等運算子，只要以侵蝕與膨脹為基礎在主機端組合即可，新增變體不需要撰寫任何裝置端程式碼。同時，所有運算子都支援預先配置的輸出緩衝區，並盡可能複製 `scipy.ndimage` 的迭代語義，例如 `iterations < 1` 表示迭代到結果不再變化。

**Q7：論文進行了哪些實驗與基準測試？**
A：論文將 TorchMorph 與單執行緒 CPU 參考實作進行比較，涵蓋灰階形態學與精確歐氏距離轉換，同時也與 POT 比較熵正規化最佳傳輸的 Sinkhorn 求解器。測試重點在於批次執行的吞吐量，以及數值上是否與 CPU 參考實作一致。此外，二值與倒角運算子會與 SciPy 進行逐元素精確比對，而所有浮點運算子則會檢查與 CPU 參考之間的絕對誤差。

**Q8：TorchMorph 的主要效能與正確性結果是什麼？**
A：在吞吐量方面，灰階形態學批次執行最高可達 `scipy.ndimage` 的 1.1×10³ 倍，精確歐氏距離轉換最高可達 350 倍，而 Sinkhorn 求解器相較於 POT 最高可快 42 倍。在正確性方面，二值運算子與倒角運算子能完全重現 SciPy 的對應結果，而每個浮點運算子與 CPU 參考的絕對誤差都在 1.8×10⁻⁶ 以內。這些結果顯示 TorchMorph 同時達到了高效能與高數值一致性。

**Q9：論文如何驗證運算子的正確性？**
A：驗證方式包括將二值與倒角運算子的輸出與 SciPy 進行逐元素比對，確保完全相等；對於浮點運算子，則測量與 CPU 參考實作之間的最大絕對誤差，並確認不超過 1.8×10⁻⁶。距離轉換家族中，除了以可分離下包絡演算法實作的精確歐氏距離轉換外，還使用暴力法轉換作為精確性神諭來交叉驗證。Sinkhorn 求解器也會與 POT 進行元素層級的數值比對，以確保微分與收斂行為一致。

**Q10：TorchMorph 適合哪些實際應用場景？**
A：它特別適合需要大量三維或四維資料處理的領域，例如醫學影像中的體積時間序列分割、多通道斷層掃描，以及標籤準備與連通元件後處理。在深度學習管線中，它可用於邊界感知損失與豪斯多夫距離代理，因為這些損失每一步訓練都需要重新計算距離場。此外，熵正規化最佳傳輸可作為直方圖比較損失，應用於點雲、注意力匹配與形狀比較等幾何感知任務。

**Q11：從產品與工程角度，TorchMorph 有哪些優勢？**
A：它是一個輕量級 PyTorch 擴充套件，僅依賴 PyTorch 與 CUDA 工具鏈，並以 MIT 授權釋出，便於整合到現有專案。由於 API 刻意鏡像 `scipy.ndimage`，開發者移植程式碼時通常只需改變 `import`，大幅降低採用門檻。它還支援預先配置輸出與 CUDA 圖形重播，能減少記憶體配置與核心發射開銷，並避免實務上拼湊多個函式庫所帶來的維護負擔。

**Q12：TorchMorph 對相關領域可能帶來什麼影響？**
A：它把數學形態學這些歷史悠久且廣泛使用的影像分析基元，正式帶入 GPU 原生的深度學習堆疊中，讓三維、四維資料的線上形態學增強、後處理與損失計算變得可行。透過與 `scipy.ndimage` 語義對齊，它有潛力成為 PyTorch 生態系中 N 維形態學運算的事實標準。長遠來看，這將加速醫學影像、科學計算與高維電腦視覺應用的研究與部署。

**Q13：TorchMorph 有哪些已知的限制？**
A：首先，並非所有 22 個公開運算子都有專屬 CUDA 核心，部分衍生運算子是在主機端以核心組合方式實作，雖然這簡化了擴充，但可能帶來額外的發射與同步成本。其次，TorchMorph 專注於 CUDA 與 PyTorch 生態系，目前沒有提供 CPU 後備實作或其他加速器支援。最後，雖然它涵蓋了形態學與最佳傳輸的主要家族，但並未宣稱涵蓋 `scipy.ndimage` 中的所有濾波器與運算子。

**Q14：在哪些情況下 TorchMorph 可能表現不如預期或出現誤差？**
A：當空間維度極大或批次尺寸過高時，GPU 記憶體可能成為瓶頸，因為所有運算都在裝置端張量上進行。精確歐氏距離轉換雖然使用可分離下包絡演算法達到精確，但倒角轉換作為近似方法，在對角線方向上仍可能與真實歐氏距離有偏差。此外，浮點運算子雖然與 CPU 參考的絕對誤差極小，但在需要位元級一致性的場景中，仍可能因單精度浮點捨入而產生最多 1.8×10⁻⁶ 的差異。

**Q15：未來可以朝哪些方向擴展 TorchMorph？**
A：未來可以加入更多距離度量與結構函數的支援，例如非歐式或各向異性結構元素，並針對超大體積資料實作分塊或稀疏運算以緩解記憶體壓力。也可以考慮加入 CPU 後備實作、混合精度核心，以及對其他加速器後端的支援，進一步提升可攜性與效能。在最佳傳輸方面，則可擴展到更多變體，例如非平衡最佳傳輸或動態正則化參數調整，並與 MONAI 等醫學影像框架進行更深度的整合。

## 實務應用指南

### 適用場景

1. **3D/4D 醫學影像分割後處理**  
   在 CT、MRI 或 fMRI 時間序列中，模型輸出的 (B, C, D, H, W) 或 (B, C, T, D, H, W) 機率圖需要轉為乾淨 mask。可用 `binary_opening`、`binary_fill_holes` 去除雜訊與填洞，再用 `euclidean` 距離轉換生成骨架或分水嶺種子點，全部留在 GPU 上，避免每張 volume 往返 CPU。

2. **多批次工業瑕疵檢測**  
   產線相機連續拍攝的瑕疵 mask 通常以批次形式進入 GPU。利用 `grey_opening`、`grey_closing` 或形態學梯度進行形狀清理與邊緣強化，可將原本以 Python loop 呼叫 `scipy.ndimage` 的瓶頸改為單一 CUDA launch。

3. **遙測與多通道斷層影像分析**  
   衛星影像或多通道 tomography 資料具有高空間維度與多通道特性。TorchMorph 支援最多 8 個空間維度與 (B, C, Spatial...) 張量，可直接對多光譜或高維科學資料進行侵蝕、膨脹與精確歐氏距離轉換。

4. **以熵正規化最佳傳輸作為訓練損失**  
   在需要比較直方圖、點雲或注意力匹配分佈的任務中，使用 `SinkhornSolver` 作為可微分幾何損失。由於支援批次與 log-domain 穩定計算，可直接嵌入生成模型、領域適應或神經渲染的訓練迴圈。

5. **影片與體積時間序列的形狀前處理**  
   對於動態 3D 掃描或影片資料，可在 GPU 上以批次方式執行形態學濾波與倒角距離轉換（chessboard/taxicab），作為後續追蹤、配準或時序模型輸入的預處理管線。

### 實作前置條件

- **硬體**：NVIDIA GPU，具備 CUDA 運算能力；記憶體需容納批次化的 (B, C, Spatial...) 張量，3D/4D 資料尤其需要注意 VRAM。
- **軟體環境**：已安裝 PyTorch 與 CUDA toolchain；可透過 `pip` 或原始碼編譯安裝 TorchMorph。
- **資料格式**：輸入必須是 `torch.Tensor` 且位於 CUDA 裝置上，形狀為 `(B, C, Spatial...)`，空間維度數量介於 1 到 8。
- **知識背景**：熟悉 `scipy.ndimage` 的參數語義（`size`、`footprint`、`structure`、`mode`、`origin`、`cval` 等）；若使用 Sinkhorn，需理解熵正規化最佳傳輸與收斂條件。
- **驗證基線**：準備好現有的 CPU 參考結果，以便比對二值/倒角運算子的逐元素一致性，以及浮點運算子的絕對誤差上限（≤ 1.8e-6）。

---

### 實作步驟建議

1. **盤點現有管線中的 `scipy.ndimage` 呼叫**  
   列出所有使用到的運算子與對應參數，確認 TorchMorph 的 API 是否支援（22 個公開運算子涵蓋多數常見需求）。

2. **將 import 改為 `torchmorph` 並調整張量裝置**  
   如論文範例所示，把 `ndi.grey_opening(v, size=3)` 改為 `tm.grey_opening(vols_cuda, size=3)`，其餘參數通常可維持不變。

3. **加入批次與通道維度**  
   確保輸入為 `(B, C, Spatial...)`。若資料為單張單通道 3D volume，需先 `unsqueeze` 兩次以補上 B 與 C。

4. **驗證數值一致性**  
   對二值與倒角運算子進行逐元素比對；對灰階與距離轉換運算子檢查絕對誤差是否低於 1.8e-6。特別注意 `origin`、`mode` 與結構元素語義是否與 SciPy 一致。

5. **針對 Sinkhorn 啟用 CUDA Graph 與 log-domain 穩定版本**  
   若運輸迭代次數固定，可使用 CUDA-graph replay 減少 launch overhead；對於小數值或長距離分佈，優先使用 log-domain Sinkhorn 以避免數值下溢。

6. **監控記憶體與吞吐量**  
   使用 `torch.cuda.memory_stats` 觀察 3D/4D 批次是否造成 OOM；必要時降低批次大小或啟用梯度檢查點。對比 SciPy 單執行緒參考，確認是否達到預期加速（灰階形態學最高約 1.1e3x，精確 EDT 最高約 350x，Sinkhorn 最高約 42x）。

7. **部署到訓練或推論迴圈**  
   將運算子直接嵌入 `nn.Module`、資料前處理或損失函式中，避免在 GPU 訓練迴圈內進行 device-to-host 往返。

---

### 潛在風險與注意事項

- **數值差異**：浮點運算子與 CPU 參考可能出現最高 1.8e-6 的絕對誤差，對於需要逐位元一致的下游任務（例如醫療法規驗證），需額外評估可接受範圍。
- **形態學運算子的可微分性**：TorchMorph 的侵蝕、膨脹等 min/max 型運算子本質上不可微分。若需要可微分的 2-D 形態學，應搭配 Kornia 或自行設計直通估計器（straight-through estimator）。
- **記憶體爆炸**：高維張量與大結構元素會快速消耗 VRAM；建議先以較小空間尺寸與結構元素測試，再逐步放大。
- **動態形狀限制**：CUDA Graph 對動態張量形狀支援有限，若每個 batch 的空間尺寸不同，需為每種形狀建立獨立 graph 或改回 eager launch。
- **邊界模式與原點語義**：雖然 API 鏡像 SciPy，但高維結構元素的 `origin` 與 `mode` 組合仍需逐案例驗證，特別是負原點或非對稱結構元素。
- **授權與維護**：TorchMorph 採 MIT 授權，可商業使用，但仍需追蹤版本更新與 CUDA/PyTorch 相容性。

### 與其他技術的整合建議

- **與 MONAI / nnU-Net 搭配**：在醫學影像框架中，將 TorchMorph 作為 GPU 上的形態學後處理層，取代原先回退到 SciPy 或 CuPy 的步驟。
- **與 Kornia 互補**：2-D 可微分形態學與資料增強交給 Kornia；N-D 批次形態學、精確 EDT 與 Sinkhorn 交給 TorchMorph。
- **與 POT 搭配**：若需要 CPU 端或特殊變體的最佳傳輸，可保留 POT 作為離線參考；線上訓練損失則使用 TorchMorph 的批次 Sinkhorn。
- **與資料載入管線整合**：由於運算子直接吃 `torch.Tensor`，可在 `DataLoader` 的 collate 後或 GPU 上的預處理函式中呼叫，無需轉成 NumPy。
- **與 ONNX / TensorRT 部署**：若需靜態圖部署，注意 TorchMorph 為 PyTorch C++/CUDA 擴充，需確認目標推理引擎是否支援該自訂運算子，或將其保留在 PyTorch runtime 中。

### 給不同背景讀者的閱讀建議

- **初學者**：先從論文的 Listing 1 與 Table 1 開始，理解「把 `scipy.ndimage` 的 import 換成 `torchmorph`」這個核心賣點；接著挑一個你熟悉的 2-D 或 3-D 形態學範例，在 GPU 上跑一遍並與 SciPy 結果比對，建立對 API 與數值誤差的直覺。

- **AI 工程師**：重點閱讀第 2.2 節的架構與核心設計，關注「批次並行 CUDA 核心」、「融合 kernel」、「CUDA Graph replay」與記憶體配置策略；實作時優先驗證你的訓練迴圈是否仍維持可微分（尤其 Sinkhorn），以及形態學運算子是否需要額外梯度處理。

- **研究人員**：深入第 2.1 節的演算法選擇，包括可分離 lower-envelope 精確歐氏距離轉換、倒角度量與 Sinkhorn 的 scaling / log-domain 版本；注意論文對數值一致性的嚴謹驗證，這對你設計需要可重現性的科學計算或醫學影像方法很重要。

- **產品經理**：把 Table 1 當成競品對照表，理解 TorchMorph 填補的是「GPU + 批次 + N-D + SciPy 語義 + 精確 EDT + OT」這個組合缺口；評估時重點放在吞吐量提升數字、授權彈性（MIT），以及它能減少多少從 GPU 搬回 CPU 的基礎設施複雜度。
