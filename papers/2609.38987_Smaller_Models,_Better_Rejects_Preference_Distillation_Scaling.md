# 較小的模型，更好的拒絕樣本：偏好蒸餾規模化（Preference Distillation Scaling）

**原文標題：** Smaller Models, Better Rejects: Preference Distillation Scaling  
**作者：** Rui Cai、Wenhui Zhu、Xiwen Chen 等 18 位作者  
**發布日期：** 2026-09-30

## ⚡ TL;DR

偏好蒸餾慣用學生自身錯誤作拒絕樣本，且需同等或更大模型生成，成本高昂。
本文提出以較小凍結模型生成拒絕樣本，並透過有限視界效用界設計混合、重指派與低似然選擇等介入。
在 7B 至 72B 學生上，較小凍結模型生成的拒絕樣本運算少效能強，低似然選擇與提高小模型比例可提升表現。

## 摘要翻譯

偏好蒸餾（preference distillation）通常將教師回應（teacher response）視為偏好回應（preferred response），並將學生自己的回應（student response）視為拒絕樣本（rejected response / reject）。這假設了自我生成拒絕樣本（self-generated rejects）是最具資訊性的負樣本，且拒絕樣本必須來自至少與學生模型（student model）同等規模的模型，使得大規模生成成本高昂。我們發現這兩項假設皆不成立：橫跨 7B 至 72B 的學生模型，較小的凍結模型（smaller frozen models）以較少的推理運算量（inference compute）生成拒絕樣本，卻能比自我生成拒絕樣本訓練出更強的學生模型，無論是在序列層級知識蒸餾（Sequence-level Knowledge Distillation, SeqKD）之前或之後，在程式碼生成（code generation）與數學推理（mathematical reasoning）任務上皆然。為了解釋此結果，我們在線性化特徵模型（linearized feature model）中，為直接偏好最佳化（Direct Preference Optimization, DPO）推導出一個有限視界效用界（finite-horizon utility bound）。此效用界刻畫了有利的拒絕樣本分佈（favorable reject distributions），並啟發三項介入（interventions）。首先，混合來自較小模型與學生規模模型的拒絕樣本，隨著較小模型所佔比例（share）提高，效能也隨之提升。其次，將拒絕樣本重新指派至其他提示（prompts），並打亂其中的程式碼權杖（code tokens），表現仍優於長度匹配的亂碼（length-matched gibberish），顯示任務結構（task structure）對拒絕樣本的效用（utility）具有貢獻。第三，當較高似然候選樣本（higher-likelihood candidates）所提供的對比（contrast）較無助益時，選擇參考策略（reference policy）下似然較低的候選樣本（lower-likelihood candidates）可提升淨遷移（net transfer）。對於每個來源，較低似然的選擇皆優於較高似然的選擇。這些結果顯示，有效的拒絕樣本在保留任務結構的同時，限制其與參考策略的耦合（coupling to the reference policy）；而較小的凍結模型能夠以低成本提供此類樣本。

### 核心貢獻（3～5點）
- 挑戰偏好蒸餾的兩項預設：自我生成拒絕樣本並非最具資訊性的負樣本，且拒絕樣本無需來自不小於學生規模的模型。
- 發現較小的凍結模型能以更低推理運算量生成更高品質的拒絕樣本，並在 SeqKD 前後、7B 至 72B 的學生模型上，於程式碼生成與數學推理任務中持續優於自我生成拒絕樣本。
- 在線性化特徵模型中為 DPO 推導有限視界效用界，以形式化方式刻畫有利的拒絕樣本分佈。
- 提出並驗證三項介入：混合不同來源拒絕樣本、破壞任務結構的對照實驗，以及依參考策略似然選擇候選樣本，證明有效拒絕樣本需保留任務結構並限制與參考策略的耦合。

### 適合對象
適合從事大型語言模型知識蒸餾、偏好學習與模型壓縮的研究者與工程師，特別是關注如何以低成本生成高品質負向監督訊號、提升 DPO 訓練效率，以及希望理解拒絕樣本設計理論基礎的讀者。

## 深度分析

#### 方法論解析

本研究重新檢視了偏好蒸餾（Preference Distillation）中「拒絕樣本（rejected response / reject）」的來源設計。傳統做法通常將教師回應（teacher response）視為偏好樣本（preferred response），將學生模型自己產生的回應視為拒絕樣本（self-generated rejects / self rejects），並預設學生自己的失敗樣本最具資訊量，且拒絕樣本的生成模型至少要與學生模型同等規模。本文挑戰這兩個預設，提出以**較小凍結模型（smaller frozen models）**作為 Base source 來生成拒絕樣本，並透過理論與實驗說明其優勢。

##### 1. 問題設定：偏好蒸餾與兩階段靜態流程

研究採用與 SODA 類似的兩階段靜態流程（static pipeline with two stages）：

1. **序列層級知識蒸餾（Sequence-level Knowledge Distillation, SeqKD）**：學生模型先模仿教師模型的輸出分佈。
2. **直接偏好最佳化（Direct Preference Optimization, DPO）**：在固定的偏好／拒絕樣本對上進行偏好學習。

在 DPO 階段，參考策略（reference policy）即為 SeqKD 後的學生模型。傳統 self rejects 的問題在於：經過 SeqKD 後，學生自己產生的錯誤回應往往是**近似正確樣本（near misses）**，在參考策略下的似然（likelihood under the reference policy）已經很高，導致 DPO 能學到的對比（contrast）有限。

##### 2. 核心方法：以較小凍結模型作為 Base source

本文將拒絕樣本的生成來源從學生模型本身，替換為參數量嚴格較小的凍結基礎模型（strictly smaller Base generator / vanilla model）。這些 Base model 不經過 SeqKD 或 DPO，直接對每個提示（prompt）採樣錯誤回應作為 rejects。由於模型較小，推理運算量（inference compute）顯著降低，但實驗顯示其訓練效果優於 self rejects。

##### 3. 理論分析：線性化特徵模型與有限視界效用界

為了解釋「較小模型反而產生較好 rejects」的現象，作者建立了一個**線性化特徵模型（linearized feature model）**，並推導出 DPO 在有限訓練步數下的**有限視界效用界（finite-horizon utility bound）**。

該效用界將拒絕樣本的價值拆解為兩個面向：

- **正向推動量**：拒絕樣本能將學生模型的更新方向推向正確任務表現的程度。
- **錯誤方向比例**：更新方向中指向錯誤方向的分量。

當正向推動量大、錯誤方向比例小時，該拒絕樣本來源就具有較高的淨遷移（net transfer）。這個框架把「拒絕樣本設計」視為一個**逆向資料設計（inverse data design）**問題：不是給定資料後看模型怎麼學，而是反過來選擇能讓模型學得最好的資料分佈。

##### 4. 三項建構介入（construction interventions）

理論分析進一步導出三項可驗證的介入：

1. **混合拒絕樣本（mixing rejects）**：將較小 Base model 與學生同規模模型的 rejects 按比例混合，預期效用會隨著較小模型比例（share）增加而提升。
2. **重新指派與打亂程式碼權杖（reassigning rejects to other prompts & shuffling code tokens）**：將 rejects 重新對應到其他提示，並打亂程式碼權杖（code tokens）順序，以檢驗「任務結構（task structure）」本身是否足以提供效用。
3. **參考策略似然選擇（likelihood-based selection）**：從固定候選池（candidate pool）中，根據其在參考策略下的似然高低進行選擇，驗證較低似然候選樣本（lower-likelihood candidates）是否帶來更好的對比。

這三項介入共同指向一個設計原則：**有效的拒絕樣本應保留任務結構（preserve task structure），同時限制與參考策略的耦合（limit coupling to the reference policy）**。較小凍結模型恰好同時滿足這兩個條件。

#### 實驗數據解讀

本文的實證部分涵蓋程式碼生成（code generation）與數學推理（mathematical reasoning）兩大任務，學生模型採用 Qwen2.5 系列，規模從 7B、14B、32B 到 72B。評估指標以 KoDCode 的 avg@4 為主，並輔以 Pass@k 等常見程式碼生成指標。

##### 1. 較小 Base model 全面勝過 Self rejects

圖 1a 顯示，對於 7B 到 72B 的每一位學生模型，所有「嚴格較小的基礎模型生成器（strictly smaller Base generator）」配置都超過兩種 self rejects：

- **vanilla Self**：未經 SeqKD 的原始學生模型所產生的 rejects。
- **post-SeqKD Self**：SeqKD 後的學生模型（即 DPO 的 reference policy）所產生的 rejects。

這是一個強健的規模化現象（scaling phenomenon）：無論學生模型多大，較小凍結模型生成的 rejects 都能帶來更高的 KoDCode avg@4，而且推理運算量更低。

##### 2. 混合比例實驗：效用隨較小模型比例單調上升

圖 1b 針對 Qwen2.5-14B 學生模型，將 Llama-3.2-1B-Instruct 產生的 rejects 與 Qwen2.5-14B-Instruct 的 vanilla Self rejects 進行隨機混合。結果顯示：

- 當 Llama-1B rejects 的比例從 0% 提升到 100%，avg@4 從 59.73% 上升至 63.28%。
- 提升幅度達 +3.55 個百分點，且呈現系統性的單調關係。

這與理論預測一致：混合來源的淨遷移（net transfer）對混合權重呈線性，因此增加較小 Base model 的 share 能穩定提升效用。

##### 3. 重新指派與打亂權杖：任務結構本身具有價值

作者進一步將較小 Base model 的 rejects：

- 重新指派至其他提示（reassigning rejects to other prompts）；
- 再打亂程式碼權杖（shuffling code tokens），破壞語法、順序與提示對應關係。

結果顯示，即使經過這些破壞，這些 rejects 仍然在每個學生規模上勝過「長度匹配的亂碼（length-matched gibberish）」。這說明：

- 部分效用來自於**任務特有的程式碼結構（task-characteristic code structure）**，而非僅來自於每個提示專屬的錯誤模式。
- 相對地，gibberish 幾乎沒有帶來超越「繼續在偏好樣本上訓練」的增益。

這項發現挑戰了傳統直覺：reject 不一定要是「針對該提示的具體錯誤答案」，只要保留任務領域的結構特徵，就能提供有效的負向監督訊號（negative supervision）。

##### 4. 參考策略似然選擇：低似然候選樣本更優

作者從每個來源固定採樣一組候選樣本（candidate pool），並根據其在 SeqKD 參考策略下的似然，分別挑選較高似然與較低似然的 rejects。結果發現：

- 對於**每一個來源**，較低似然候選樣本（lower-likelihood candidates）都勝過較高似然候選樣本（higher-likelihood candidates）。
- 例如對於 1.5B 來源，低似然選擇的 avg@4 達到 63.14%，而高似然選擇僅為 61.88%。

這驗證了理論預測：當高似然 rejects 提供的對比不足時，選擇在參考策略下機率較低的 rejects 能改善淨遷移。較小 Base model 的 rejects 之所以有效，部分原因正是它們在學生參考策略下的似然較低。

##### 5. 綜合意涵

實驗結果支持一個簡潔的設計原則：

> **有效 rejects = 保留任務結構（preserve task structure） + 限制與參考策略的耦合（limit coupling to the reference policy）。**

較小凍結模型生成的 rejects 恰好同時具備這兩項性質：它們仍屬於程式碼／數學領域的有效文本（保留任務結構），但因模型能力較弱，其輸出在學生參考策略下機率較低（限制耦合），從而為 DPO 提供強而有力的對比。

#### 與現有研究的比較

##### 1. 與 SODA 等偏好蒸餾方法的關係

SODA 是與本文設定最接近的工作，它同樣採用 SeqKD 後接 DPO 的兩階段靜態流程，並將教師回應作為偏好樣本、學生回應作為拒絕樣本。本文與 SODA 的關鍵差異在於：

- **SODA 將回應來源與訓練流程綁定**：teacher = preferred、student = rejected 是固定的。
- **本文將 reject-generating distribution 視為獨立設計變數**：透過理論與實驗證明，學生自己產生的 rejects 並非最佳選擇，較小凍結模型可以做得更好、更便宜。

這相當於把「資料工程」的視角引入偏好蒸餾：不只是設計損失函數，還要設計負樣本的分佈。

##### 2. 與偏好學習中 pair selection 研究的關係

近期許多研究聚焦於「如何選擇或加權觀察到的偏好對」，例如線上採樣（online sampling）、動態配對選擇、資料加權等。這些方法通常假設偏好對已經存在，問題在於如何從中挑選。本文則進一步向上游延伸：

- **不是選現成的 rejects，而是設計 rejects 的生成來源。**
- 透過較小凍結模型主動建構更便宜的負樣本分佈。

這與線上 DPO、迭代式偏好學習形成互補：未來可以結合「較小模型生成 rejects」與「線上策略更新」，進一步降低成本並提升樣本效率。

##### 3. 與黑箱知識蒸餾的關係

黑箱知識蒸餾（black-box knowledge distillation）通常只能使用教師模型的輸出，目標是讓學生模仿教師。本文的方法同樣適用於教師為專有模型（proprietary model）的情境，但強調：

- 除了模仿教師的偏好樣本外，還需要高品質的拒絕樣本。
- 這些拒絕樣本不一定需要從學生自己生成，而可以用更小的開源模型產生。

這對實務部署特別重要：當教師模型昂貴或無法大規模採樣時，可以用小模型低成本地生成大量有效 rejects。

##### 4. 本文的貢獻與限制

**主要貢獻：**

1. 建立了一個強健的規模化現象：7B–72B 學生模型上，較小凍結 Base model 的 rejects 全面勝過 self rejects。
2. 提出線性化特徵模型與有限視界效用界，將 reject source selection 形式化為逆向資料設計問題。
3. 透過三項介入實驗，識別出有效 rejects 的兩大可觀測性質：任務結構與低參考策略耦合。

**潛在限制：**

- 實驗主要集中在**可驗證任務**（程式碼生成與數學推理），對於開放式生成、創意寫作、對話安全等難以自動驗證的領域，較小 Base model rejects 是否同樣有效仍需驗證。
- 理論模型採用線性化假設，雖然能解釋現象並導出實驗假設，但與真實深度網路的非線性動態仍有差距。
- 研究未深入探討「多小才算夠小」的極限：當 Base model 小到一定程度（例如 100M 以下），任務結構可能崩解，效用是否仍成立尚不清楚。

#### 可重現性評估

根據目前提供的全文脈絡，本文為 arXiv 預印本形式，尚未見到明確的開源程式碼、資料集或模型權重連結。以下從幾個面向評估可重現性：

##### 1. 模型與資料

- **學生模型**：使用公開的 Qwen2.5 系列（7B、14B、32B、72B），這些權重可透過 Hugging Face 取得，降低了重現門檻。
- **Base source 模型**：包含 Llama-3.2-1B-Instruct 等較小開源模型，同樣公開可得。
- **評估基準**：KoDCode 用於程式碼生成，數學推理任務應為常見基準（如 GSM8K、MATH 等，但文中未明確列出）。若作者未公開處理後的資料與提示，重現者需自行建構。

##### 2. 訓練流程

- SeqKD + DPO 的兩階段流程在概念上標準，但實作細節（學習率、批次大小、DPO 的 β 參數、採樣溫度、拒絕樣本篩選條件等）對結果影響重大。
- 若作者未釋出訓練腳本與超參數，其他研究者難以完全復現數值。

##### 3. 實驗設計

- 三項介入實驗（混合比例、重新指派／打亂權杖、似然選擇）設計清楚，理論動機明確，具有可重複性。
- 但「重新指派至其他提示」與「打亂程式碼權杖」的具體實作方式（例如重新指派的配對規則、打亂的粒度）需要更詳細說明。

##### 4. 整體評估

目前可重現性處於**中等偏上**水準：核心模型與基準公開，實驗設計透明，但若無官方程式碼與資料，重現者仍需投入大量工程細節調校。建議作者未來釋出：

- 訓練與評估程式碼；
- 生成的偏好／拒絕樣本對；
- 完整的超參數設定與隨機種子；
- 各項介入實驗的詳細實作腳本。

#### 未來研究方向

本文開啟了多條值得後續探索的研究路徑：

##### 1. 跨任務與跨領域驗證

目前結果集中在程式碼生成與數學推理這類可驗證任務。未來可檢驗較小凍結模型 rejects 在以下領域的效果：

- 開放式問答與創意生成；
- 對話安全與價值對齊；
- 多模態任務（如影像描述、視覺問答）；
- 低資源語言與專業領域。

##### 2. 動態與線上拒絕樣本設計

本文採用靜態的兩階段流程。未來可結合線上 DPO 或迭代式偏好學習：

- 在訓練過程中動態選擇或生成 rejects；
- 根據學生模型當前的參考策略，自適應地挑選低似然但保留任務結構的 rejects；
- 設計「reject generator」作為可學習的模組，與學生模型共同演化。

##### 3. 理論模型的非線性延伸

本文的線性化特徵模型提供了可操作的直覺，但真實 LLM 的訓練動態高度非線性。未來可朝以下方向深化：

- 在更一般的損失景觀（loss landscape）下分析 reject 分佈的影響；
- 探討 reject 樣本與偏好樣本之間的幾何關係；
- 發展基於資訊理論或統計學習理論的樣本複雜度界。

##### 4. 自動化拒絕樣本來源搜尋

既然 reject source 是設計變數，未來可建立自動化搜尋框架：

- 給定學生模型與任務，自動選擇最適合的 Base model 規模與家族；
- 結合多個 Base model，學習最佳的來源組成（source composition）；
- 發展「reject scaling law」，預測不同規模 Base model 的效用與成本權衡。

##### 5. 與其他偏好學習目標的整合

本文使用 DPO，但相同概念可延伸至：

- IPO（Identity Preference Optimization）、KTO、SimPO 等變體；
- 列表式偏好目標（listwise preference objectives）；
- 強化學習人類回饋（RLHF）中的獎勵模型訓練。

探討不同目標函數下，較小凍結模型 rejects 的效用是否一致，將有助於建立更普遍的設計原則。

##### 6. 成本效益與環境影響

較小凍結模型 rejects 的核心優勢之一是降低推理運算量。未來可進行更系統的成本分析：

- 比較不同規模 Base model 的總訓練成本（生成 + 訓練）；
- 評估在固定預算下，應如何分配資源於偏好樣本生成、拒絕樣本生成與模型訓練；
- 將此方法應用於邊緣裝置或低資源環境中的模型微調。

總結來說，本文不僅提出了一個實用的低成本偏好蒸餾策略，更重要的是將「拒絕樣本分佈」提升為與損失函數、模型架構同等重要的設計維度，為未來的資料中心式偏好學習研究奠定了基礎。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**

A：這篇論文挑戰了偏好蒸餾中一個看似直覺的假設：把學生模型自己產生的錯誤回應當作拒絕樣本，並且認為拒絕樣本必須來自與學生同等或更大規模的模型。作者指出，這種做法不僅讓大規模生成負樣本的推理運算量變得昂貴，也可能因為學生自己的錯誤已經很接近正確答案，而無法提供足夠的對比訊號。因此，本文探討是否存在更便宜、更有效的拒絕樣本來源，以改善偏好蒸餾的規模化與成本問題。

**Q2：為什麼學生自己生成的拒絕樣本在 SeqKD 之後可能不是最好的負向監督？**

A：在經過序列層級知識蒸餾（SeqKD）之後，學生模型已經被初始化為會產生與教師回應相似的輸出，因此它自己生成的錯誤回應往往是「險些正確」的近似正確樣本。這些拒絕樣本在 DPO 的參考策略下已經具有較高的似然，導致偏好樣本與拒絕樣本之間的對比度不足，模型能從中學到的修正訊號有限。相較之下，來自較小凍結模型的拒絕樣本通常與參考策略耦合較低，因此能提供更有用的負向監督。

**Q3：這個問題的規模化與成本考量為什麼重要？**

A：隨著學生模型規模從 7B 成長到 72B，若每次都要從學生模型本身採樣拒絕樣本，推理運算量會隨模型大小線性甚至超線性增加，使得大規模偏好蒸餾變得非常昂貴。如果必須使用與學生同等或更大規模的模型來生成負樣本，那麼訓練成本將成為實際部署的重大瓶頸。因此，證明較小凍結模型能以更低成本提供甚至更強的拒絕樣本，對於降低大型語言模型偏好蒸餾的總體開銷具有重要意義。

**Q4：本文提出的核心方法是什麼？**

A：本文提出使用參數嚴格小於學生模型的凍結基礎模型（Base model）來生成拒絕樣本，取代傳統由學生自己生成自我拒絕樣本的做法。在實驗中，作者讓 Qwen2.5 系列學生模型（7B 到 72B）接受來自 Llama-3.2-1B-Instruct 等較小凍結模型的拒絕樣本，並進行 DPO 訓練。為了理解這個現象，作者還建立了一個線性化特徵模型，並推導出有限視界效用界來刻畫什麼樣的拒絕樣本分佈對訓練最有利。

**Q5：相較於既有偏好蒸餾方法，本文的主要創新在哪裡？**

A：既有方法通常把拒絕樣本的來源與訓練流程綁定在一起，例如固定使用學生回應作為拒絕樣本，而本文首次把「拒絕樣本來源」視為一個可以獨立設計的變數。作者透過大規模實驗發現，較小凍結模型生成的拒絕樣本不僅推理成本更低，還能訓練出更強的學生模型，這顛覆了「拒絕樣本必須來自較大模型」的直覺。此外，本文從逆資料設計的角度提出理論分析，並歸納出有效拒絕樣本的兩大特性：保留任務結構，以及限制與參考策略的耦合。

**Q6：理論分析如何引導出三項具體的拒絕樣本建構介入？**

A：線性化特徵模型下的有限視界效用界顯示，拒絕樣本的淨遷移效益與來源組成大致呈線性關係，因此作者設計了混合不同來源拒絕樣本的實驗。理論也指出，拒絕樣本的效用部分來自內容本身而非僅來自與提示的對應，所以作者測試把拒絕樣本重新指派到其他提示，甚至打亂程式碼權杖。最後，理論預測在參考策略下似然較低的候選樣本能提供更有用的對比，因此作者進行了依參考策略似然挑選拒絕樣本的消融實驗。

**Q7：實驗使用了哪些任務、模型與評估指標？**

A：實驗主要在可驗證的程式碼生成與數學推理任務上進行，其中程式碼生成的結果以 KoDCode 基準上的 avg@4 作為主要指標。學生模型採用 Qwen2.5 系列，規模涵蓋 7B、14B、32B 與 72B；較小凍結基礎模型則包括 Llama-3.2-1B-Instruct 等嚴格小於學生的模型。透過這樣的設定，作者能夠系統性地比較不同學生規模下，自我拒絕樣本與較小基礎模型拒絕樣本的效用差異。

**Q8：本文最重要的實驗發現是什麼？**

A：在所有測試的 18 種較小基礎模型配置中，來自較小凍結模型的拒絕樣本都擊敗了學生自己生成的拒絕樣本，無論是原始基線自我拒絕樣本還是 SeqKD 後的自我拒絕樣本。在 14B 學生模型的混合介入實驗中，當 Llama-1B 拒絕樣本的比例從 0% 提升到 100%，KoDCode avg@4 從 59.73% 上升到 63.28%。此外，對每一個拒絕樣本來源而言，選擇參考策略下似然較低的候選樣本，表現都優於似然較高的候選樣本。

**Q9：消融實驗進一步揭示了哪些關於拒絕樣本效用的機制？**

A：混合實驗顯示，隨著較小基礎模型拒絕樣本佔比增加，學生表現單調提升，說明來源組成可以系統性地調控訓練效用。重新指派拒絕樣本到其他提示並打亂程式碼權杖後，這些樣本仍然優於長度匹配的亂碼，顯示部分效用來自程式碼的任務結構，而非僅是針對特定提示的錯誤。相較之下，純亂碼幾乎無法帶來超越持續訓練偏好樣本的增益，證明有效拒絕樣本必須保留一定程度的任務相關結構。

**Q10：在實務應用中，這項研究最適合哪些場景？**

A：這項研究特別適合需要大規模進行偏好蒸餾、但希望降低推理運算成本的場景，例如企業內部訓練大型程式碼生成或數學推理模型。與其讓龐大的學生模型反覆採樣自我拒絕樣本，不如部署一個小型的專用凍結模型來批次生成高品質拒絕樣本。這樣不僅能減少 GPU 使用與延遲，還可能因為拒絕樣本品質更好而提升最終學生模型的表現。

**Q11：若要在產品中落地，有哪些設計與營運上的考量？**

A：產品團隊需要決定基礎模型的大小、拒絕樣本來源的混合比例，以及是否根據參考策略似然進行篩選，以在成本與效能之間取得平衡。由於較小凍結模型可以獨立於學生模型運作，因此可以將拒絕樣本生成視為可快取、可預先計算的資料管線步驟，進一步降低線上訓練負擔。此外，必須持續監控拒絕樣本是否仍保留任務結構，避免過度偏離目標領域而淪為無效負樣本。

**Q12：這項研究對偏好學習與知識蒸餾領域可能帶來什麼影響？**

A：這項研究挑戰了「拒絕樣本必須來自較大或同等模型」的隱含假設，並把焦點從「如何優化給定資料」轉向「如何設計更好的資料來源」。這種逆資料設計的觀點可能影響未來 DPO、RLHF 與其他偏好學習方法的資料策劃流程。更廣泛地說，它也提示研究者：負向監督訊號的品質並不單純由模型規模決定，而是由樣本與參考策略的關係以及任務結構共同決定。

**Q13：本文有哪些已承認或潛在的限制？**

A：本文的實驗主要集中在可驗證的程式碼生成與數學推理任務上，因此結論是否能直接推廣到開放式生成或多輪對話等領域，仍需要更多研究驗證。理論分析基於 DPO 的線性化特徵模型，這是一種近似，可能無法完整捕捉非線性深度網路在實際訓練中的所有動態。此外，研究採用的是靜態兩階段流程，對於線上採樣或迭代式偏好學習方法的適用性尚未充分探討。

**Q14：在什麼情況下，較小基礎模型生成的拒絕樣本可能效果不佳？**

A：如果較小基礎模型過度簡化或完全破壞了任務結構，例如生成與程式語法無關的純亂碼，那麼它提供的負向監督將難以幫助學生學到有意義的對比。同樣地，若拒絕樣本與目標任務領域嚴重脫節，即使它與參考策略的耦合很低，也可能無法引導學生朝向正確答案改進。因此，選擇基礎模型時必須確保它仍具備產生任務相關結構的能力，而非單純追求最小參數量。

**Q15：未來可以朝哪些方向延伸這項研究？**

A：未來可以將這個框架擴展到線上偏好學習，讓拒絕樣本來源在訓練過程中動態調整，而非僅使用靜態資料集。也可以探索其他領域，例如開放式問答、創意寫作或多模態任務，檢驗「較小模型產生較好拒絕樣本」的現象是否仍然成立。此外，結合主動學習或貝葉斯最佳實驗設計，自動選擇最具資訊量的拒絕樣本，將是進一步降低資料與運算成本的重要方向。

## 實務應用指南

### 適用場景

1. **企業程式碼輔助模型的低成本偏好對齊**  
   在內部程式碼生成場景中，若已有強大的閉源教師模型（專有模型）輸出作為偏好回應，可利用 1B–3B 等較小凍結模型產生拒絕樣本，取代讓 14B–72B 學生模型自我採樣負樣本，顯著降低推理運算量與大規模生成成本。

2. **數學推理或科學解題模型的蒸餾**  
   對於需要逐步驗證正確性的數學推理任務，使用較小基礎模型來源產生錯誤但保留任務結構的拒絕樣本，可提升 DPO 階段的對比學習效果，特別適合答案可自動檢驗（如 SymPy、單元測試）的場景。

3. **邊緣裝置或端側模型的能力向上壓縮**  
   當目標學生模型需要部署在手機、車機等資源受限環境時，可在資料中心用大型教師模型做 SeqKD，再用極小的凍結模型（例如 Llama-3.2-1B-Instruct）產生拒絕樣本進行偏好蒸餾，減少端側或雲端採樣負樣本的開銷。

4. **領域專屬模型（Domain-specific LLM）的偏好蒸餾**  
   在法律、醫療、金融等領域，若已微調出一個較小的領域基礎模型，可將其凍結後作為 Base source，針對領域提示產生結構正確但內容錯誤的拒絕樣本，強化學生模型對領域規範的區辨能力。

5. **API 型黑箱知識蒸餾的負樣本生成管線**  
   當教師模型僅能透過 API 呼叫取得輸出時，可將預算集中於取得高品質教師回應，而拒絕樣本改由本地部署的小模型批次產生，降低整體資料採購與推理成本。

### 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **資料** | 一組帶有正確性標籤或可驗證答案的提示（prompts）；每題需有教師模型產生的偏好回應，以及來自較小凍結模型或學生自身的多個拒絕樣本候選。 |
| **模型** | 一個學生模型（7B–72B 等級）、一個或多個嚴格較小的凍結 Base 模型（如 1B–3B）、以及作為 DPO 參考策略的 SeqKD 後學生模型。 |
| **運算** | 足夠進行序列層級知識蒸餾（SeqKD）與直接偏好最佳化（DPO）的 GPU/TPU 資源；小模型僅需推理，不需要反向傳播。 |
| **技能** | 熟悉 PyTorch/Transformers、DPO 訓練流程、能計算樣本在參考策略下的似然（log-probability），並具備自動化驗證程式碼（unit tests）或數學答案比對的能力。 |
| **工具** | 採樣管線（vLLM、TGI 或自製）、DPO 訓練框架（TRL、LLaMA-Factory 等）、評估基準（KoDCode、GSM8K、MATH 等）與實驗追蹤工具（Weights & Biases、MLflow）。 |

### 實作步驟建議

1. **建立偏好回應與參考策略**  
   使用教師模型對訓練提示生成偏好回應，並以 SeqKD 在學生模型上進行監督式微調，得到 DPO 所需的參考策略（reference policy）。

2. **選擇並凍結 Base 拒絕樣本來源**  
   挑選參數嚴格小於學生模型的凍結模型（例如 Llama-3.2-1B-Instruct 對應 Qwen2.5-14B-Instruct）。對每個提示採樣多個候選回應，並透過單元測試或答案比對確認其為錯誤樣本。

3. **計算參考策略似然並篩選低似然候選**  
   對每個拒絕樣本候選計算其在 SeqKD 後參考策略下的對數似然。優先選擇較低似然候選樣本作為 DPO 的拒絕樣本；若資源允許，可同時保留高似然組別進行對照實驗。

4. **設計來源混合比例（Mixture Intervention）**  
   從 100% 自我生成拒絕樣本開始，逐步提高較小 Base 模型的份額（如 25%、50%、75%、100%）。論文顯示隨著較小 Base 份額增加，avg@4 等指標通常單調上升。

5. **執行 DPO 訓練**  
   將教師回應作為偏好回應、篩選後的 Base 拒絕樣本作為拒絕樣本，執行固定資料集的 DPO。保持參考策略為 SeqKD 後的學生模型，並監控訓練過擬合與 KL 散度。

6. **驗證任務結構貢獻**  
   可選：將 Base 拒絕樣本重新指派至其他提示，或打亂程式碼權杖順序，與長度匹配的亂碼（gibberish）比較。若打亂後仍優於亂碼，表示任務結構確實帶來效用。

7. **評估與迭代**  
   在可驗證任務上使用 Pass@k、avg@k 或領域指標評估。比較不同來源組成、不同似然閾值的淨遷移效果，並鎖定最佳配置後部署。

### 潛在風險與注意事項

| 風險 | 說明與緩解方式 |
|---|---|
| **Base 模型與學生模型語言或領域不匹配** | 若較小凍結模型的輸出分佈與學生差異過大，可能產生離群拒絕樣本。建議優先選用與學生同系列或同領域微調過的小模型，並監控參考策略似然分佈。 |
| **過度依賴低品質負樣本** | 並非所有小模型輸出都有效。必須透過自動驗證確保其為「錯誤但結構合理」的樣本，避免將正確答案誤標為拒絕樣本。 |
| **參考策略似然閾值過於激進** | 過度篩選極低似然樣本可能導致訓練不穩定。建議從論文觀察到的趨勢出發，針對每個來源獨立尋找最佳閾值，而非使用單一全局值。 |
| **任務可驗證性限制** | 本文結論主要來自程式碼生成與數學推理等可驗證任務。開放式生成（創意寫作、開放問答）的拒絕樣本效用可能不同，需額外設計評估機制。 |
| **DPO 過擬合特定拒絕樣本** | 固定資料集 DPO 可能讓模型記住負樣本而非學到通用偏好。可搭配 early stopping、保留驗證集，或定期以線上採樣更新拒絕樣本池。 |

### 與其他技術的整合建議

- **與現有 SFT / SeqKD 管線銜接**  
  直接將偏好蒸餾作為 SeqKD 之後的第二階段（類似 SODA 的兩階段靜態流程），無需改動現有教師資料收集流程，只需新增小模型採樣節點。

- **與 RLHF / Online DPO 整合**  
  可將較小凍結模型作為「低成本負樣本生成器」嵌入線上訓練迴圈：每次迭代用學生模型與小模型同時採樣，快速擴充偏好對，再交由獎勵模型或驗證器篩選。

- **與模型壓縮與推理優化堆疊搭配**  
  在量化、剪枝、投機解碼等壓縮流程後，使用小模型產生拒絕樣本可進一步降低蒸餾階段的總擁有成本，特別適合邊緣部署場景。

- **與 MLOps 資料管理整合**  
  在資料平台中記錄每筆偏好對的來源組成（source composition）、參考策略似然與驗證結果，便於後續追蹤哪個 Base 來源對哪類提示最有效，並支援 A/B 測試。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先理解「偏好回應 vs. 拒絕樣本」的基本概念，再聚焦圖 1 與三項實驗介入：較小模型產生的負樣本反而更好、混合比例越高越好、低參考策略似然的樣本更有效。不必一開始就深入線性化特徵模型的推導，把重點放在「用小模型做負樣本可以省成本又提升效果」這個直覺上即可。

**AI 工程師**  
請仔細閱讀實作步驟與風險章節，特別是參考策略似然篩選、來源混合比例與自動驗證機制的設計。建議直接以 Qwen2.5 或 Llama 系列複現 14B 學生配 1B–3B Base 的配置，並將 DPO 訓練整合進現有的 TRL 或 LLaMA-Factory 管線。

**研究人員**  
本文的核心貢獻在於將拒絕樣本來源視為逆向資料設計問題，並以有限視界效用界刻畫有利的拒絕樣本分佈。建議深入分析理論模型如何連結「任務結構」與「參考策略耦合」這兩個觀測性質，並思考如何將結論推廣到不可驗證任務或線上偏好學習框架。

**產品經理**  
重點關注成本與效益權衡：使用較小凍結模型產生拒絕樣本能顯著降低大規模生成成本，同時在程式碼與數學場景提升學生模型表現。評估時請確認產品場景具備可驗證答案（如程式碼可執行、數學可檢查），並將「小模型負樣本生成器」視為降低 API 與推理預算的槓桿點。
