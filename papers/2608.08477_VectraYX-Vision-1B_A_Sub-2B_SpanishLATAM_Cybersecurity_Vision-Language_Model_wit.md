## ⚡ TL;DR

針對西班牙/拉丁美洲資安場景缺乏可離線部署的小型視覺語言模型，且現有模型無法理解資安工具截圖。
提出VectraYX-Vision-1B，以SigLIP與1B資安解碼器支援結構化推理與工具呼叫。
初步視覺定位表現不佳，B6接近零，但已釋出模型、語料庫與NoPE消融設計以確立優先主張。

## 摘要翻譯

我們提出 VectraYX-Vision-1B，一個針對西班牙文/拉丁美洲（Spanish/LATAM）網路安全（cybersecurity）影像、低於 20 億參數（sub-2B）的視覺語言模型（vision-language model, VLM），透過多層感知機投影器（MLP projector）將凍結的 SigLIP-so400m 編碼器（encoder）與 10.4 億參數（1.04B parameters）的西班牙文/拉丁美洲（Spanish/LATAM）資安解碼器（decoder）相連。據我們所知，這是首個專為網路安全使用者介面（cyber UI，如 IDA、Ghidra、Wireshark、Nmap、Metasploit、Volatility）設計、能以西班牙文回答、透過原生 <|think|> 詞元（tokens）輸出結構化推理（structured reasoning）、透過模型上下文協定（Model Context Protocol, MCP，<|tool_call|>）呼叫工具（tool invocation），並可匯出為 llama.cpp 的 LLaVA mmproj 格式以支援氣隙部署（air-gapped deployment）的低於 20 億參數（sub-2B）視覺語言模型（VLM）。我們報告一項視覺定位（visual grounding）的初步負面結果（negative preliminary result）：儘管所有管線（pipelines）均正常運作，當前的視覺監督式微調（visual supervised fine-tuning, SFT，400 至 1900 步，約 1600 萬詞元）仍產生趨近於零的 B6 分數（工具識別（tool-identification）僅 0.08），顯示模型忽略了圖像內容。我們提出補救措施（remediation，延長 SFT、重播比例（replay ratio）不低於 60%、降低學習率（learning rate, LR）），並揭露一個偽裝成訓練崩潰（training collapse）的檢查點載入器錯誤（checkpoint-loader bug，未移除的 llm. 前綴（unstripped llm. prefix））。至關重要的是，我們提出一個三變體消融矩陣（3-variant ablation matrix，V0：每四層一層無位置編碼（NoPE），V1：全部使用旋轉位置編碼（Rotary Position Embedding, RoPE），V2：無位置編碼（NoPE）搭配可學習二維位置嵌入（learned 2D positional embedding）），以研究週期性無位置編碼（NoPE）層對 729 個詞元（tokens）視覺區塊（visual block）的注意力運算（attention）是否有助抑或有害。我們釋出程式碼、設定檔與權重（weights），以在此架構問題上確立優先權（priority）。我們提供文字骨幹模型（text backbone）的 B1-B5 評估結果、文字對照組、初步 B6/B7 分數、實際執行時間（wall times）、CPU 上的 GGUF 效率，以及涵蓋 10 個領域、共 14,596 組問答對（QA pairs）的語料庫（corpus）。我們將所有模型與訓練軌跡（trajectories）開源：jsantillana/vectrayx-1b、jsantillana/vectrayx-vision-1b 與 jsantillana/vectrayx-vision-1b-checks。

### 核心貢獻（3～5點）
- 提出首個專為西班牙文/拉丁美洲（Spanish/LATAM）網路安全（cybersecurity）使用者介面（cyber UI）設計的低於 20 億參數（sub-2B）視覺語言模型（VLM），結合凍結編碼器（frozen encoder）、多層感知機投影器（MLP projector）與 10.4 億參數解碼器（decoder），並支援氣隙部署（air-gapped deployment）。
- 實現結構化視覺推理（structured visual reasoning）與原生工具使用（native tool use）：模型可透過原生 <|think|> 詞元（tokens）輸出結構化推理，並透過模型上下文協定（MCP，<|tool_call|>）呼叫外部工具。
- 公開報告視覺定位（visual grounding）的初步負面結果（negative preliminary result），指出當前視覺監督式微調（SFT）導致模型忽略圖像內容，並提出具體補救措施（remediation）。
- 揭露一個被誤判為訓練崩潰（training collapse）的檢查點載入器錯誤（checkpoint-loader bug，未移除的 llm. 前綴），提供診斷（diagnostic）與修正方向。
- 設計三變體消融矩陣（V0/V1/V2）以研究無位置編碼（NoPE）層對 729 個詞元視覺區塊（visual block）注意力運算（attention）的影響，並釋出權重（weights）以確立優先權（priority）。

### 適合對象
本論文最適合從事網路安全（cybersecurity）人工智慧應用、多模態（multimodal）視覺語言模型（VLM）小型化、西班牙文/拉丁美洲（Spanish/LATAM）語言模型，以及需要氣隙部署（air-gapped deployment）或資料主權環境（data-sovereign environments）地端使用（on-premise use）的研究人員與工程師。此外，對結構化推理（structured reasoning）、原生工具使用（native tool use）、模型量化（quantization）與 llama.cpp 部署，以及負面結果（negative results）與消融實驗（ablations）方法論感興趣的讀者亦將有所收穫。

## 深度分析

#### 方法論解析

VectraYX-Vision-1B 採用經典的 LLaVA（Large Language and Vision Assistant）風格投影器配方（projector recipe），但將其套用到一個極度狹窄的領域：西班牙文／拉丁美洲（Spanish/LATAM）網路安全（cybersecurity）影像。整體架構為：凍結的 SigLIP-so400m（凍結視覺編碼器）→ 多層感知機投影器（MLP projector）→ 1.04B 參數的 VectraYX-1B 西班牙文／拉丁美洲資安解碼器（decoder）。視覺編碼器保持凍結，可保留預訓練的視覺表徵並降低 GPU 記憶體需求；MLP projector 則負責將 729 個視覺圖塊詞元（patch tokens）映射到語言模型的嵌入空間。

此模型的核心科學問題在於「無位置編碼（NoPE, no-positional-encoding）層」與「視覺區塊（visual block）」的交互作用。VectraYX-1B 的骨幹每四層為一組：三層使用旋轉位置編碼（RoPE, Rotary Position Embedding），第四層不使用任何位置編碼（NoPE）。當 SigLIP-so400m 輸出的二維圖塊網格（patch grid）被攤平為 729 個一維詞元後，RoPE 層會賦予它虛假的單維順序（spurious 1D order），而 NoPE 層則讓視覺區塊對排列變換保持排列等變（permutation-equivariant）。論文提出三個變體構成消融矩陣（ablation matrix）：V0 為每四層 NoPE（NoPE-every-4）、V1 為全 RoPE（all-RoPE）、V2 為 NoPE 加上可學習二維位置嵌入（learned 2D positional embedding）。透過比較 B6(V0)−B6(V1) 的符號，可區分假設 H1（NoPE 有益）與 H2（NoPE 有害、學習二維位置編碼有幫助）。

除了視覺輸入，VectraYX-Vision-1B 還內建兩種原生（native）特殊詞元：`<|think|>` 用於結構化推理（structured reasoning），`<|tool_call|>` 用於模型上下文協定（MCP, Model Context Protocol）的工具呼叫（tool invocation）。這些不是提示工程（prompt engineering）的產物，而是直接加入詞彙表並在第四階段（phase 4c）透過監督式微調（SFT, Supervised Fine-Tuning）訓練出來的能力。模型會先針對資安物件（位址、操作碼、封包欄位、IOC 等）進行視覺推理（visual reasoning），再產生答案或觸發工具。

訓練採用四階段課程（four-phase curriculum）：4a 視覺對齊（vision alignment）、4b 視覺指令微調（vision instruct）、4c 推理與工具 SFT。設計時明確給出詞元預算（token budget）、重播比例（replay ratio）以及凍結／解凍排程（freeze/unfreeze schedule），目標硬體為 2×A100-40GB。論文還報告一項事後消融實驗（post-hoc ablation）：發現凍結詞元嵌入（tok_emb, token embedding）是導致 v3B 工具使用性能下降（tool-use degradation）的原因。

部署方面，模型被匯出為 llama.cpp 可讀取的 LLaVA mmproj 格式（LLaVA mmproj format），包含 model.gguf 與 mmproj.gguf，並以 GGUF 格式量化，可在氣隙部署（air-gapped deployment）與資料主權環境（data-sovereign environments）中以中央處理器（CPU）進行本地離線推論（local offline inference）。

在威脅模型（threat model）上，作者假設防禦型或授權攻擊型分析師（defensive or authorized-offensive analyst）在組織安全邊界（security perimeter）內作業，經常使用與外網隔離的主機。輸入影像可能由攻擊者控制，因此視覺提示注入（visual prompt injection）被納入安全討論；而工具呼叫能力具有雙重用途（dual-use），需要第一線的防護機制而非事後補強。

#### 實驗數據解讀

論文對文字骨幹提供 B1–B5 基準測試，用以確認 VectraYX-1B 在西班牙文／拉丁美洲資安語料上的基本能力。對於視覺能力，則提出兩個新基準：B6_vision 評估工具識別（tool-identification）與答案正確性，B7_think 評估思考鏈（thinking-chain）的存在與品質。

目前最重要的實驗發現是一個負面結果（negative result）：在視覺 SFT 僅進行 400–1900 步、約 1600 萬詞元（~16M tokens）後，B6_vision 的工具識別分數幾乎為零，最佳僅 0.08。這表示模型基本上忽略影像內容，視覺定位（visual grounding）嚴重不足。為了排除基準測試本身過於簡單的可能性，作者設置了純文字骨幹對照組（text-only backbone control），證明 B6 無法僅靠文字回答，因此問題確實出在視覺理解而非題目設計。

B7_think 的初步結果同樣被報告為初步負面結果（negative preliminary result），顯示目前的訓練量尚不足以讓模型穩定地產出高品質、與影像內容相關的結構化推理。

儘管視覺品質未達標，論文仍測量了實際執行時間（wall times）與 GGUF 在 CPU 上的效率（CPU efficiency），證明 sub-2B 模型確實能在通用硬體（commodity hardware）上運行，這對地端使用（on-premise use）與資源不足的安全團隊（under-resourced security teams）具有實務價值。

作者將此結果明確定位為負面結果，並提出補救措施（remediation）：需要更長的視覺 SFT、重播比例（replay ratio）至少 60%，以及更低的語言模型學習率（learning rate, LR）。這不是暫時佔位，而是具體可執行的後續實驗計畫。

另一項重要發現是檢查點載入器錯誤（checkpoint-loader bug）：由於未移除的 llm. 前綴（unstripped llm. prefix），模型權重在 LLaVA 風格匯出流程（LLaVA-style export pipeline）中被錯誤載入，外觀上酷似訓練崩潰（training collapse）。這個診斷方法（diagnostic）對任何使用類似匯出管線的研究者都有參考價值。

至於 NoPE 的消融矩陣（ablation matrix），目前僅釋出 V0 檢查點（checkpoint），V1 與 V2 的結果仍待完成；未來 B6(V0)−B6(V1) 的符號將成為判斷 H1／H2 的關鍵證據。

#### 與現有研究的比較

與通用視覺語言模型（general vision-language models）如 LLaVA、BLIP-2、InternVL、Qwen-VL、IDEFICS 相比，VectraYX-Vision-1B 的最大差異在於它並非使用現成的 7B–70B 通用大型語言模型（LLM），而是從頭訓練一個 1.04B 的領域專用解碼器。這帶來兩個優勢：一是對西班牙文技術內容與資安術語的掌握更精準，二是模型體積小到可在本地離線推論。代價則是通用知識與視覺定位能力可能較弱，這也反映在目前的負面結果上。

在視覺推理方面，Visual CoT 等研究透過提示策略（prompting strategy）激發中間推理；VectraYX-Vision-1B 則將 `<|think|>` 詞元內建為原生能力，並專注於資安物件而非自然場景。在工具使用方面，過往模型多依賴提示格式慣例，而 VectraYX-Vision-1B 直接輸出 `<|tool_call|>` 詞元來驅動 MCP 伺服器，屬於原生工具使用（native tool use）。

在領域專用視覺語言模型中，最接近的類比是醫學影像領域的 MedVersa 等模型。VectraYX-Vision-1B 則是首個針對網路安全使用者介面（cyber UI）——如 IDA、Ghidra、Wireshark、Nmap、Metasploit、Volatility——進行最佳化的 sub-2B 模型，並且支援西班牙文回答。

部署模式上，現有主流 VLM 多為雲端 API，無法滿足氣隙部署與資料主權環境的需求；VectraYX-Vision-1B 透過 llama.cpp 與 GGUF 格式實現完全本地執行，這是其獨特價值主張。

然而其限制也十分明顯：視覺定位尚未建立、參數規模可能限制複雜推理、僅聚焦西班牙文／拉丁美洲、訓練影像多為合成渲染（synthetic rendering）、NoPE 效應仍屬開放問題，且工具呼叫的實際安全性尚未經端對端驗證。

#### 可重現性評估

本研究在可重現性（reproducibility）方面表現相當透明。作者已於 Hugging Face 釋出程式碼、設定檔、模型權重與訓練軌跡（trajectories），儲存庫（repository）包括 jsantillana/vectrayx-1b、jsantillana/vectrayx-vision-1b 與 jsantillana/vectrayx-vision-1b-checks。其中 checkpoints 與 runner 也一併公開，讓其他研究者能直接執行推論與進一步實驗。

B6_vision 與 B7_think 兩個基準測試同樣釋出，並可透過合成影像渲染器（synthetic image renderer）端對端重現。論文詳細列出 B1–B5 文字基準、純文字對照組、初步 B6／B7 分數、實際執行時間、GGUF CPU 效率、語料庫規模（14,596 組問答對，QA pairs，涵蓋 10 個領域）以及 2×A100-40GB 的訓練配置。

更值得肯定的是，作者並未隱藏負面結果，反而明確報告視覺 SFT 不足導致的近零 B6 分數，並詳細說明檢查點載入器錯誤的診斷過程與補救措施。這種「釋出設計與方法以確立優先權（establish priority），而非等待完美結果」的做法，符合預印本（preprint）的開放科學精神。

不過目前仍有部分結果 pending：V1（all-RoPE）與 V2（NoPE+learned 2D）的消融實驗結果、以及採用更長 SFT 與更高重播比例的補救實驗都尚未完成。此外，作者註明其為 Globant 的 DevOps 工程師，所屬機構（institutional affiliation）核准仍在進行中，這在學術審查時可能需要補充。

#### 未來研究方向

1. **執行補救式視覺 SFT**：按照作者建議，進行更長的視覺監督式微調，重播比例（replay ratio）至少 60%，並降低語言模型學習率（LR），以檢視視覺定位（visual grounding）是否會隨訓練量顯著浮現。

2. **完成 NoPE 消融矩陣**：儘速完成 V1（all-RoPE）與 V2（NoPE+learned 2D positional embedding）的訓練與 B6 評估，透過 B6(V0)−B6(V1) 的符號判斷 NoPE 對 729 詞元視覺區塊的影響，並驗證 H1／H2。

3. **視覺編碼器與投影器的進一步調整**：可嘗試部分解凍 SigLIP-so400m 或 MLP projector，或引入更強的視覺－語言對齊機制，以改善對資安 UI 元素的定位。

4. **加入區域層級監督**：在語料庫中增加邊界框（bounding boxes）、OCR 覆蓋層或元件級標註，幫助模型學習將文字與介面區域對應到影像位置。

5. **對抗式安全與工具防護**：針對視覺提示注入（visual prompt injection）設計防禦機制，並為 `<|tool_call|>` 建立嚴格的輸入驗證與沙箱，避免雙重用途能力被濫用。

6. **擴充與多語言語料庫**：目前 14,596 組 QA pairs 以合成影像為主，未來可納入更多真實工具截圖、拉丁美洲西班牙文變體，甚至擴展至葡萄牙文等其他語言。

7. **與真實 MCP 伺服器的端對端評估**：將模型整合到實際的 Model Context Protocol（MCP）伺服器，測試其在真實資安工作流程中的工具呼叫準確率與安全性。

8. **標準化檢查點載入流程**：修正並記錄未移除 llm. 前綴的問題，將診斷方法回饋給 LLaVA 風格匯出管線社群，減少未來研究者誤判訓練崩潰。

9. **sub-2B 領域 VLM 的擴展法則研究**：探討在狹窄領域中，資料量、模型大小、重播比例與視覺定位性能之間的關係，為資源受限團隊提供實證指引。

10. **量化感知訓練**：針對 GGUF 量化過程中 `<|think|>` 與 `<|tool_call|>` 等特殊詞元的保留問題，研究量化感知訓練（quantization-aware training）以維持 CPU 推論時的推理與工具能力。

## 論文問答

**Q1：VectraYX-Vision-1B 主要想解決什麼問題？**

A：這篇論文指出，資安分析師在日常工作中經常需要直接判讀畫面，例如逆向工程師檢視 IDA 或 Ghidra 的反組譯窗格、SOC 分析師查看 Splunk 或 Wireshark 的輸出、鑑識人員掃描 Volatility 處理程序列表，以及滲透測試人員解讀 Nmap 與 Metasploit 的結果。然而，現行主流的純文字大型語言模型無法「看見」這些畫面，而通用視覺語言模型（如 LLaVA、InternVL、Qwen-VL）既不專精於資安影像，也難以用西班牙文精確回答技術內容，更因 7B–70B 的龐大規模而無法在氣隙或資料主權環境中本地離線執行。VectraYX-Vision-1B 正是為了填補這個缺口，打造一個低於 20 億參數、專門針對西班牙文／拉丁美洲資安影像的視覺語言模型，讓資源不足的安全團隊也能在本地端分析敏感截圖。

**Q2：為什麼現有的通用視覺語言模型無法滿足這個利基需求？**

A：通用視覺語言模型雖然能處理自然影像與一般問答，但它們並未針對 IDA、Ghidra、Wireshark 等網路安全使用者介面進行專門訓練，因此對於資安領域的專業術語、工具版面與攻擊指標缺乏細緻理解。此外，這些模型在西班牙文技術內容上的表現通常不佳，無法順暢回應拉丁美洲分析師的需求；更重要的是，它們的參數量動輒數十億，需要高階 GPU 或雲端 API 才能運行，這與許多資安場景要求的氣隙部署、資料不離境原則相互衝突。因此，現有模型在語言、領域專精度與部署彈性三個層面都無法直接適用於拉丁美洲的在地資安工作流程。

**Q3：開發一個低於 20 億參數的西班牙文資安視覺語言模型為何重要？**

A：在惡意軟體分析沙箱、機密鑑識工作站或事件應變戰情室等場景中，將可能包含敏感客戶資料、惡意程式字串或內部網路拓樸的截圖上傳到第三方雲端模型，往往違反組織政策或當地法規，因此模型必須能夠完全在地端運行。VectraYX-Vision-1B 透過 sub-2B 的輕量設計與 llama.cpp 的 GGUF 匯出格式，讓通用硬體甚至 CPU 都能執行本地離線推論，大幅降低部署門檻。同時，它針對西班牙文與拉丁美洲資安語境進行訓練，有助於縮小語言與地區的數位落差，使資源有限的團隊也能獲得專屬的 AI 輔助分析能力。

**Q4：VectraYX-Vision-1B 的核心架構是什麼？**

A：該模型採用類似 LLaVA 的投影器架構，將凍結的 SigLIP-so400m 視覺編碼器透過一個多層感知機投影器，連接到一個 10.4 億參數的西班牙文／拉丁美洲資安解碼器 VectraYX-1B。SigLIP-so400m 以 patch14/384 的設定運作，輸出 729 個詞元的視覺區塊，且沒有 CLS 詞元，這些視覺特徵會直接注入解碼器序列中。整體設計著重輕量化與可離線部署，最終可匯出為 llama.cpp 相容的 LLaVA mmproj 格式，讓模型與多模態投影權重能在氣隙環境中一起運行。

**Q5：這項研究有哪些關鍵創新？**

A：首先，VectraYX-Vision-1B 是首個專門針對網路安全使用者介面、且規模低於 20 億參數的視覺語言模型，並原生支援西班牙文回答。其次，它引入原生 <|think|> 詞元來產生結構化視覺推理，並透過原生 <|tool_call|> 詞元驅動模型上下文協定（MCP）進行工具呼叫，而非僅依賴提示格式慣例。最關鍵的學術貢獻在於提出並釋出一個三變體消融矩陣（V0：每四層無位置編碼、V1：全部旋轉位置編碼、V2：無位置編碼加可學習二維位置嵌入），用於研究骨幹網路中週期性無位置編碼層對 729 詞元視覺區塊注意力的影響，這是過去已釋出視覺語言模型中未曾出現的組合。

**Q6：作者為何選擇 SigLIP、凍結編碼器與週期性 NoPE 等設計？**

A：選用 SigLIP-so400m 是因為其 sigmoid 對比目標在相同運算量下優於 CLIP，且已成為近期強視覺語言模型的預設編碼器；凍結編碼器則是為了保留已學得的視覺表徵，避免在小型資安語料上過度擬合或破壞視覺特徵。至於週期性無位置編碼層的設計，則源於 VectraYX-1B 骨幹本身交替使用旋轉位置編碼（每四層中的三層）與無位置編碼（每第四層），在旋轉位置編碼層上，展平的圖塊網格會被賦予虛假的單維順序，而在無位置編碼層上視覺區塊則具有排列等變性；作者希望透過 V0/V1/V2 的消融實驗，判斷這種設計對視覺定位究竟是有益還是有害。

**Q7：論文引入了哪些評估基準與資料集？**

A：論文延續 VectraYX 系列對文字骨幹的 B1–B5 評估，並新增兩個多模態資安基準：B6_vision 用於評估工具識別與在保留截圖上的答案正確性，B7_think 則評估思考鏈的存在與品質。訓練與評估資料包含一個橫跨 10 個領域、共 14,596 組問答對的多模態資安語料庫，涵蓋逆向工程、組合語言、架構、除錯、鑑識、SOC、攻擊、密碼學、競技程式設計與拉丁美洲特定內容。這些問答對來自真實原始素材，並透過合成 IDA/Ghidra/終端機影像與真實工具截圖的雙語（英文／西班牙文）管線產生。

**Q8：論文報告了哪些關鍵實驗結果？**

A：最重要的結果是一個初步負面結果：儘管所有訓練管線都能正常運作，目前視覺監督式微調（約 1600 萬詞元、400 至 1900 步）並未產生有效的視覺定位，B6 工具識別分數接近零（最佳僅 0.08），顯示模型幾乎忽略圖像內容。為了確認這不是因為題目本身可從文字推得，作者也執行了純文字骨幹對照實驗，證明該基準無法單靠文字回答。此外，研究過程中還發現一個檢查點載入器錯誤：未移除的 llm. 前綴曾偽裝成訓練崩潰，這個診斷經驗對任何 LLaVA 風格匯出管線都有參考價值。

**Q9：消融實驗的設計與發現是什麼？**

A：核心消融是一個三變體矩陣：V0 為原始釋出的每四層無位置編碼版本，V1 為全部使用旋轉位置編碼的版本，V2 則是無位置編碼加上可學習二維位置嵌入的版本。作者以 B6(V0) 減去 B6(V1) 的符號來區分兩個競爭假設：H1 認為無位置編碼有益，H2 則認為無位置編碼有害、而學習二維位置嵌入能有所幫助。除了這個主消融之外，作者還報告一個事後消融，發現 v3B 模型工具使用性能退化的原因是詞元嵌入層被凍結，這說明在視覺監督式微調階段，凍結／解凍排程的設計對保留工具呼叫能力至關重要。

**Q10：這個模型適合哪些實際應用場景？**

A：VectraYX-Vision-1B 主要面向需要在氣隙或嚴格資料主權環境中運作的資安分析師，例如惡意軟體分析沙箱、機密鑑識工作站、事件應變戰情室，以及無法連接外部雲端的本地設備。具體任務包括協助逆向工程師理解 IDA/Ghidra 的反組譯畫面、幫助 SOC 分析師判讀 Wireshark 封包擷取或 Splunk 搜尋結果、輔助鑑識人員分析 Volatility 處理程序列表，以及支援滲透測試人員解讀 Nmap 掃描與 Metasploit 會話。由於模型可匯出為 GGUF 格式並在 CPU 上運行，特別適合預算有限、只能使用通用硬體的拉丁美洲安全團隊。

**Q11：在實際產品化與部署時需要考慮哪些安全與工程議題？**

A：首先，輸入截圖屬於攻擊者可控制的對象，惡意軟體樣本在反組譯器中的呈現方式或精心製作的截圖都可能構成視覺提示注入攻擊，因此必須將其納入威脅模型。其次，模型具備原生工具呼叫能力，可透過 MCP 伺服器執行真實動作，這是一個雙用途表面，必須建立穩固的工具定位與防護機制，而非僅作為後續補強。工程上則需確保 llama.cpp 的 mmproj 匯出正確無誤、檢查點載入器已處理 llm. 前綴問題，並驗證 CPU 量化後的推論效率與延遲，以符合地端離線部署的實際需求。

**Q12：這項研究可能對資安領域帶來什麼影響？**

A：如果後續補救訓練成功，VectraYX-Vision-1B 將讓資源不足的安全團隊首次能在本地、離線、低資源的條件下，使用專屬的西班牙文視覺語言模型輔助分析敏感資安影像，減少將截圖上傳雲端所帶來的合規與洩密風險。此外，透過開源模型權重、設定檔、訓練軌跡與執行程式，作者不僅釋出可驗證的系統，也確立了在「無位置編碼 × 視覺詞元注入」這個架構問題上的優先主張，鼓勵社群進一步複現與改進。長遠來看，這類專門化、輕量化的多模態資安模型有助於降低 AI 輔助分析的門檻，並促進拉丁美洲與其他非英語地區的資安能力普及。

**Q13：作者承認了哪些主要限制？**

A：作者非常明確地將目前視覺定位結果定位為初步負面結果，而非一個已完成的有效視覺模型；在現有視覺監督式微調步數下，B6 分數接近零，顯示模型尚未學會利用圖像內容來回答問題。論文也坦承，雖然所有訓練階段都已跑完、系統與語料庫均已釋出，但補救後的長時間監督式微調與完整消融結果仍待完成。這種保守的表述方式強調了研究的誠實性：它釋出的是一個可檢驗的架構假設與方法，而不是宣稱已經擁有運作良好的視覺模型。

**Q14：研究中發現了哪些失敗案例或技術陷阱？**

A：最顯著的失敗案例是視覺監督式微調後的模型幾乎無法進行工具識別，B6 最佳分數僅 0.08，顯示模型傾向忽略圖像、僅依賴文字先驗作答。另一個重要陷阱是檢查點載入器錯誤：由於權重名稱中未移除的 llm. 前綴，導致匯出管線出現異常，最初被誤判為訓練崩潰，這提醒研究者在診斷多模態模型時需仔細檢查權重名稱對應。此外，v3B 模型出現工具使用性能退化，後續事後消融發現原因是詞元嵌入層被凍結，這說明即使訓練管線看似正常，凍結／解凍排程的細微差異也可能嚴重影響特定能力。

**Q15：未來研究方向與補救計畫是什麼？**

A：作者提出的主要補救措施是執行更長的視覺監督式微調，並將重播比例提高到至少 60%，同時降低語言模型的學習率，以在增強視覺定位能力的同時保留西班牙文與工具使用能力。未來還需要完成 V0/V1/V2 三個變體的完整 NoPE × 視覺消融實驗，透過 B6 與 B7 的差異來判斷無位置編碼層對視覺注意力的真實影響。除此之外，後續工作也應強化工具定位與防護機制、擴充更多真實資安截圖資料，並進一步優化 llama.cpp 上的 CPU 量化效率，使這個輕量西班牙文資安視覺語言模型真正達到可實戰部署的水準。

## 實務應用指南

### 適用場景

1. **氣隙環境中的資安截圖初判**  
   在無法外連雲端 VLM 的惡意軟體分析沙箱、機密鑑識工作站或事件應變戰情室，可於本地 CPU 執行 VectraYX-Vision-1B，對 IDA、Ghidra、Wireshark、Nmap、Metasploit、Volatility 等工具的畫面進行西班牙文初步問答，例如「這個封包欄位代表什麼？」或「這段組合語言呼叫了哪個 API？」。

2. **拉丁美洲安全團隊的西班牙文輔助分析**  
   針對技術文件、終端機輸出或 SOC 儀表板截圖，模型可用西班牙文生成結構化推理（`<|think|>`）與工具呼叫（`<|tool_call|>`），協助資源不足的團隊以母語理解威脅指標（IOC）、記憶體傾印或掃描結果。

3. **離線工具協調與 MCP 自動化**  
   透過原生 `<|tool_call|>` 與 Model Context Protocol（MCP）伺服器整合，可在地端觸發查詢、掃描或日誌擷取動作，例如讓模型看到 Splunk 儀表板截圖後，自動產生對應的 SPL 查詢工具呼叫。

4. **NoPE × 視覺注意力機制的研究驗證**  
   由於作者已釋出 V0（NoPE-every-4）、V1（全 RoPE）、V2（NoPE+可學習 2D 位置嵌入）三種變體，研究團隊可直接在自有資安影像語料上重跑 B6/B7 基準，驗證週期性無位置編碼層對 729 詞元視覺區塊的影響。

5. **低資源邊緣裝置的資安問答原型**  
   模型以 GGUF 格式匯出後可在 llama.cpp 上執行，適合用於筆電、小型伺服器或 NUC 等通用硬體，作為無網路環境下的文字優先資安助手；視覺功能目前僅建議作為實驗性質使用。

### 實作前置條件

**資料條件**
- 若僅使用已釋出模型：無需額外訓練資料。
- 若要重現或補強視覺定位：需準備自有資安截圖與問答對，建議涵蓋逆向工程、組合語言、架構、除錯、鑑識、SOC、攻擊、加密等 10 個領域，並維持至少 60% 重播比例（replay ratio）以保留西班牙文與工具使用能力。
- 圖像建議使用 384×384 解析度，與 SigLIP-so400m / patch14 / 384 配置對齊。

**運算條件**
- **推論**：llama.cpp 可在 CPU 執行；若使用 GPU 加速，建議至少 8 GB VRAM。
- **訓練/微調**：作者使用 2×A100-40GB；若要執行補救式視覺 SFT，建議具備同等級 GPU 與約 1600 萬詞元以上的視覺詞元預算。

**技能條件**
- 熟悉 Python、PyTorch 與 Hugging Face Transformers。
- 了解 LLaVA 風格多模態架構（視覺編碼器 + MLP 投影器 + 解碼器）。
- 具備 llama.cpp 與 GGUF 轉換經驗，能處理權重名稱前綴（如 `llm.`）問題。
- 資安領域知識：能判讀 IDA、Ghidra、Wireshark、Nmap、Metasploit、Volatility 等工具輸出。

### 實作步驟建議

1. **環境建置與權重下載**
   - 從 Hugging Face 取得 `jsantillana/vectrayx-1b`、`jsantillana/vectrayx-vision-1b` 與 `jsantillana/vectrayx-vision-1b-checks`。
   - 安裝 llama.cpp、相關轉換腳本與 MCP 伺服器相依套件。

2. **檢查權重前綴與格式轉換**
   - 載入檢查點時，確認是否殘留未移除的 `llm.` 前綴；必要時重新對應權重名稱，避免誤判為訓練崩潰。
   - 將模型匯出為 LLaVA mmproj 格式，產生 `model.gguf` 與 `mmproj.gguf`，以便在 llama.cpp 離線執行。

3. **文字能力驗證（B1–B5）**
   - 先在不輸入圖像的情況下測試西班牙文資安問答、工具呼叫與 `<|think|>` 結構化推理，確認文字骨幹與工具使用能力正常。
   - 若發現工具使用退化，可參考論文事後消融實驗，檢查是否凍結了 `tok_emb`（詞元嵌入）。

4. **視覺能力評估（B6/B7）**
   - 使用論文釋出的合成影像渲染器產生 50 張以上持有測試截圖。
   - 執行 B6_vision（工具識別與答案正確性）與 B7_think（思考鏈存在與品質）基準。
   - 預期目前視覺 SFT 步數（400–1900 步）可能得到接近零的 B6 分數，這是已知的初步負面結果。

5. **補救式視覺 SFT**
   - 延長視覺 SFT 至更長步數，採用較低學習率。
   - 維持 ≥60% 重播比例，避免文字與工具能力災難性遺忘。
   - 依照凍結/解凍排程逐步開放視覺投影器與部分解碼器層。

6. **部署與監控**
   - 在氣隙主機上以 llama.cpp 執行 GGUF 模型。
   - 對 `<|tool_call|>` 輸出加入允許清單與人工確認閘道，避免未經授權執行動作。
   - 持續記錄 wall times、CPU 效率與 B6/B7 分數，作為迭代依據。

### 潛在風險與注意事項

- **視覺定位尚未可靠**：目前視覺 SFT 產生的模型可能忽略圖像內容，B6 工具識別分數接近 0.08。不應直接將視覺輸出用於高風險判斷，建議僅作輔助並搭配人工確認。
- **檢查點載入器錯誤**：未移除的 `llm.` 前綴可能偽裝成訓練崩潰。轉換前務必檢查權重名稱對應表，避免誤判模型品質。
- **工具呼叫的雙重用途風險**：原生 `<|tool_call|>` 可驅動 MCP 伺服器執行真實動作。輸入圖像可能包含對抗式視覺提示注入（adversarial visual prompt injection），必須在工具執行前加入授權、沙箱與稽核機制。
- **災難性遺忘**：視覺微調可能削弱西班牙文能力與工具使用能力。務必使用高重播比例與凍結/解凍排程，並在 B1–B5 上持續監控。
- **量化與硬體限制**：雖然 GGUF 可在 CPU 執行，但過度量化可能影響已經有限的視覺定位能力，建議先以 Q4_K_M 或更高精度測試。

---

### 與其他技術的整合建議

- **MCP 伺服器**：將 `<|tool_call|>` 輸出對接至本地 MCP 實作，讓模型可呼叫 Nmap、Volatility、Wireshark tshark、Splunk REST API 或自訂鑑識腳本；所有呼叫應經過允許清單過濾。
- **SIEM / SOAR 平台**：把模型部署為 SOAR  playbook 的一個「視覺解讀」節點，接收告警截圖並輸出結構化推理與建議動作，但保留人工審批閘道。
- **惡意軟體分析沙箱**：在 Cuckoo、CAPE 或自訂沙箱中嵌入 llama.cpp 推論服務，自動對 Ghidra/IDA 截圖產生西班牙文摘要，減少分析師重複勞動。
- **向量資料庫與 RAG**：將模型輸出的 `<|think|>` 鏈與工具結果寫入向量庫，搭配檢索增強生成（RAG）建立可追蹤的資安知識庫。
- **現有 LLaVA / Qwen-VL 管線**：若視覺任務需要更高準確度，可將 VectraYX-Vision-1B 作為離線、西班牙文專用的輔助模型，與較大通用 VLM 形成階層式判讀流程。

### 給不同背景讀者的閱讀建議

**初學者**：這份預印本適合先從「動機」與「適用場景」入手，理解為什麼需要離線、西班牙文的資安視覺模型；技術細節如 NoPE、RoPE、MCP 與 GGUF 可先略讀，重點放在論文坦承的「負面結果」——它清楚告訴你目前視覺功能還不能直接用於生產環境。

**AI 工程師**：請聚焦第 3、4、7 節的訓練流程、凍結/解凍排程、檢查點載入器錯誤，以及 B6/B7 基準的實作細節。特別注意 `llm.` 前綴問題與 `tok_emb` 凍結對工具使用的影響，這些都是實際部署時會踩到的坑；若你要重現，建議先跑文字控制組再進入視覺階段。

**研究人員**：核心貢獻在於 NoPE × 視覺區塊的消融矩陣（V0/V1/V2）。建議仔細閱讀實驗設計與假設 H1/H2，並利用作者釋出的檢查點與執行程式重跑 B6，驗證週期性無位置編碼層對 729 詞元視覺區塊的注意力影響；這是論文明確標示為「可發表問題」的主軸。

**產品經理**：請把這篇論文視為一份誠實的技術路標，而非已成熟的產品。現階段可評估將文字骨幹與工具呼叫能力整合進地端資安輔助工具，但視覺問答功能應列為實驗項目；決策重點在於氣隙部署、資料主權、MCP 工具授權，以及後續補救式 SFT 所需的 GPU 與資料預算。
