# DarwinX：透過天擇演化智慧體 Harness

**原文標題：** DarwinX: Evolving Agent Harnesses Through Natural Selection  
**作者：** Yifan Zhang、Yutong Dai、Juntao Tan 等 12 位作者  
**發布日期：** 2026-07-31

## ⚡ TL;DR

現有 LLM 智慧體的 harness 自我改進常陷單譜系路徑依賴，且局部優化會導致跨任務退化。
DarwinX 以族群天擇演化 harness 變體，透過保留擴展契約限制退化，並以典藏庫重組互補譜系。
凍結模型權重下，四項基準平均提升約 17 分，且 harness 可零樣本遷移至 SWE-bench。

---

## 摘要翻譯

LLM 智慧體（LLM agent）的能力不僅取決於模型權重（model weights），也取決於其 harness：提示詞（prompt）、工具（tool）、技能（skill）與控制流程（control flow）。自我改進迴路（self-improvement loop）已能編輯 harness，但單譜系搜尋（single-lineage search）具有路徑依賴（path dependence），且局部勝利（local wins）常導致其他任務（task）退化（regress）。我們提出 DarwinX，將自我演化（self-evolution）視為在模型凍結（frozen model）的前提下，對 harness 族群（population）進行天擇（natural selection）：「保留並擴展契約」（preserve-and-extend contract）只接受擴大涵蓋範圍（coverage）且不造成退化（regress）的變體（variant）；典藏庫（archive）保存替代譜系（alternative lineages）以供重組（recombination）；從失敗衍生的證據（failure-derived evidence）、教師衍生的證據（teacher-derived evidence）與自我衍生的證據（self-derived evidence）則共用同一編輯介面（edit interface）。適應度（fitness）來自各基準測試（benchmark）自身的驗證器（verifier）：沒有黃金解答（gold solutions），也沒有人工挑選的勝出者（hand-picked winners）。在四個逐步將演化訊號與測試分離的基準測試中，單一迴路平均可提升約 17 個百分點：Terminal-Bench 2.1 在配對基礎模型（matched base）上提升 7.7 個百分點至 83.2%，並在更強的基礎模型（stronger base）上達到經驗證前沿（verified frontier）的 84.7%；TerminalWorld 的保留測試集（held-out split）達到 68.3%，領先所有現成智慧體（off-the-shelf agent）；WebArena-Infinity 的真實任務 pass@1（real-task pass@1）從 43.5% 提升至 93.0%（稽核無誤，audit-clean）；而一個 Terminal-Bench 2.1 的 harness 更原封不動地遷移（transfers unchanged）至 SWE-bench Verified。所演化的是通用智慧體能力（general agent competence），而非特定基準測試的補丁（benchmark-specific patches），因此即使任務（task）、驗證器（verifier）與基礎模型（base model）改變，仍能延續。凍結模型（frozen model）未必等同固定的智慧體：harness 選擇能將評估運算資源（evaluation compute）轉化為持久能力（durable capability）。

### 核心貢獻（3～5點）
- 將自我演化重新框架為凍結模型（frozen model）下的 harness 天擇（natural selection）：在模型權重不變的前提下，對 harness 族群（population）進行選擇，把評估運算資源（evaluation compute）轉化為持久能力（durable capability）。
- 提出「保留並擴展契約」（preserve-and-extend contract）與典藏庫（archive）重組（recombination）機制：只接受擴大涵蓋範圍（coverage）且不造成退化（regress）的變體（variant），並保存替代譜系（alternative lineages），以緩解單譜系搜尋（single-lineage search）的路徑依賴（path dependence）與局部勝利（local wins）引發的跨任務退化。
- 統一多源證據於單一編輯介面（edit interface）：整合從失敗、教師與自我衍生的證據（failure-/teacher-/self-derived evidence），並以各基準測試（benchmark）的驗證器（verifier）作為適應度（fitness）來源，無需黃金解答（gold solutions）或人工挑選的勝出者（hand-picked winners）。
- 展現跨基準遷移與通用智慧體能力（general agent competence）：在四個逐步分離演化訊號與測試的基準測試上，單一迴路平均提升約 17 個百分點；Terminal-Bench 2.1 的 harness 可原封不動地遷移至 SWE-bench Verified，顯示所演化的是通用能力，而非特定基準測試的補丁（benchmark-specific patches）。

### 適合對象
適合對 LLM 智慧體（LLM agent）系統設計、提示工程、工具學習、自我改進／自我演化代理，以及品質多樣性／開放式演化搜尋感興趣的研究者與工程師；特別是關注如何在凍結模型權重下透過 harness 選擇提升通用能力、並希望避免基準測試過擬合的讀者。

## 深度分析

#### 方法論解析

DarwinX 的核心命題是：在**模型權重（model weights）**凍結的前提下，把智慧體能力提升重新框架為「對 harness（harness，包含提示詞（prompts）、工具（tools）、技能（skills）、控制流程（control flow）與記憶體（memory）的外掛架構）變體（variants）進行天擇（natural selection）」。這與常見的「單譜系（single-lineage）自我改進迴路（self-improvement loop）」形成對比：後者只保留一條最佳血統，容易因早期編輯而陷入**路徑依賴（path dependence）**，並在異質任務分佈上出現**跨任務干擾（cross-task interference）**。

論文將 DarwinX 拆解為三個相互支撐的機制：

1. **族群式選擇與典藏庫（archive）**  
   DarwinX 同時維護多個 harness **譜系（lineages）**。每個譜系都是從某個親代（parent）經突變（mutation）產生的子代（child）。這些子代不會立刻取代親代，而是先進入典藏庫，成為後續繼承（inheritance）或**重組（recombination）**的候選。這樣一來，針對不同任務家族（task families）發展出的**專門化變體（specialists）**不會被鎖死在各自獨立的支線裡，而是有機會被合併成更通用的 harness。

2. **保留並擴展契約（preserve-and-extend contract）**  
   這是 DarwinX 選擇規則的靈魂。一個子代要被接納，必須滿足「擴大**涵蓋範圍（coverage）**而不造成**退化（regression）**」的條件。具體而言，作者使用**測量適應度（measured fitness）**——即該變體在基準測試（benchmark）自帶**驗證器（verifier）**下的 **avg@k（avg@k，前 k 個樣本的平均成功率）**——作為唯一篩選標準。  
   為了控制評估雜訊，DarwinX 採用兩階段閘控：  
   - **存活選擇（survival selection）**：允許有界退化風險的候選成為祖先；  
   - **晉升確認（promotion confirmation）**：用更嚴格的 avg@k 門檻確認該變體確實穩定提升。  
   這種「bounded-regression」設計讓局部勝利（local wins）不會以犧牲其他任務為代價，從而緩解跨任務干擾。

3. **模組化的提案訊號（proposal signal）**  
   編輯 harness 的訊號來自三種證據，但全部統一到同一個 harness 層級的**編輯介面（edit interface）**：  
   - **從失敗衍生的證據（failure-derived evidence）**：分析 rollout（rollout，一次執行軌跡）失敗的原因，產生針對性編輯；  
   - **教師衍生的證據（teacher-derived evidence）**：利用外部示範或更強模型提供的示範；  
   - **自我衍生的證據（self-derived evidence）**：透過對比不同 rollout 的結果，自我診斷並提出改進。  
   關鍵在於這些訊號都不更新模型權重，只改變 harness，因此「凍結模型（frozen model）」不再是「固定智慧體」的同義詞。

4. **互補存活者的合併（merge of complementary survivors）**  
   當典藏庫中出現解決互補任務的譜系時，DarwinX 會嘗試將它們合併。這對應到生物天擇中的重組，而非單純的**梯度下降類比（gradient-descent analogy）**。合併後的子代同樣要接受 preserve-and-extend 契約的檢驗，確保合併不會引入新的退化。

總結來說，DarwinX 把「自我演化（self-evolution）」從「沿著單一梯度不斷修改」轉變為「在族群層級上進行無黃金解答（no gold solutions）、無人工挑選勝出者（no hand-picked winners）的適應度篩選」。這種設計讓評估運算資源（evaluation compute）轉化為持久能力（durable capability）。

#### 實驗數據解讀

作者設計了四個由易到難的評估情境，目的在於逐步把「演化訊號」與「最終測試」分離，從而檢驗 DarwinX 學到的是通用智慧體能力（general agent competence），而非特定基準測試的補丁（benchmark-specific patches）。

##### 1. Terminal-Bench 2.1：域內測試時演化
- **配對基礎模型（matched base）**：從 75.5% 提升至 **83.2%**（+7.7）。  
- **更強的基礎模型（stronger base）**：達到 **84.7%**，進入該基準的**經驗證前沿（verified frontier）**。  
這說明在模型凍結、只改 harness 的情況下，DarwinX 已能逼近或達到該領域最佳表現。由於 Terminal-Bench 2.1 的驗證器直接作為適應度函數，這裡的訊號與測試高度重疊，但 +7.7 的增幅仍顯示 harness 層級還有大量未被挖掘的空間。

##### 2. TerminalWorld：保留測試集（held-out split）上的任務泛化
- 演化後在保留測試集達到 **68.3%**，超越所有**現成智慧體（off-the-shelf agent）**（+7.3）。  
這裡的關鍵是「保留測試集」代表智慧體在演化過程中沒有直接看過這些任務。提升來自於 harness 學會了更穩健的終端機操作與驗證行為，而非記住特定題目。

##### 3. WebArena-Infinity：合成意圖到真實任務的泛化
- 真實任務 **pass@1（pass@1，第一次嘗試即通過的比例）** 從 43.5% 提升至 **93.0%**（**稽核無誤**，audit-clean）。  
這是最引人注目的結果之一：DarwinX 只在合成意圖（synthetic intents）上進行演化，卻能在真實網頁任務上取得將近翻倍的提升。這強烈暗示演化後的 harness 掌握了可遷移的網頁操作與規劃原則，例如更可靠的表單填寫、導航與結果驗證策略。

##### 4. Terminal-Bench 2.1 → SWE-bench Verified：跨基準測試遷移
- 把在 Terminal-Bench 2.1 上演化出的 harness **原封不動地遷移（transfers unchanged）** 到 SWE-bench Verified，無需域內回饋。  
雖然論文未給出具體數字，但強調這是「零樣本遷移（zero-shot transfer）」的成功案例。這對方法論意義重大：如果 harness 只是針對 Terminal-Bench 2.1 的驗證器過擬合，那麼遷移到軟體工程任務應該會崩潰。實驗結果支持 DarwinX 確實演化出某種跨任務、跨驗證器、甚至跨基礎模型（cross-base-model）的通用能力。

##### 綜合解讀
作者指出「一次迴路平均增加約 17 分」。這個數字橫跨四個不同領域，顯示 DarwinX 的選擇壓力並非來自單一任務分佈，而是來自「能通過多樣化驗證器」的通用解題結構。這與單純提示詞工程或模型微調的常見結果不同：後者往往在訓練分佈上提升，卻在遷移時退化。

#### 與現有研究的比較

論文透過 Table 1 將 DarwinX 與既有自我改進智慧體方法對照，對照軸包括「編輯對象」、「搜尋方式」、「選擇機制」與「訊號來源」。

| 方法群組 | 代表方法 | 編輯對象 | 搜尋/選擇特徵 | 與 DarwinX 的關鍵差異 |
|---|---|---|---|---|
| 針對單一人工製品的最佳化器 | OPRO、PromptBreeder、TextGrad | 提示詞字串 | 單一譜系或有限族群，無互補任務重組 | 不編輯工具與控制流程，也無跨譜系合併 |
| 工作流程/技能最佳化器 | ADAS、AFlow、GPTSwarm、SkillOpt | 工作流程或技能文件 | 有族群但缺乏嚴格的退化控制 | 無 preserve-and-extend 契約，容易在混合任務上停滯 |
| 自我修改原始碼的智慧體 | SICA、DGM | 智慧體自身原始碼 | 單親代突變，無跨譜系重組 | DGM 一次突變一個親代（mutates one parent at a time），解決互補任務的譜系永遠無法合併；DarwinX 只改 harness，風險更低且更易重組 |
| 強調退化控制的 harness 編輯 | HarnessX | harness | 有界退化但無族群典藏庫 | 缺乏 archive 與 cross-lineage merge，仍受限於路徑依賴 |

DarwinX 相較於這些方法的綜合優勢可歸納為四點：

1. **從單譜系到族群天擇**：透過典藏庫保存多條譜系，避免早期編輯鎖死未來搜尋方向。  
2. **從局部最佳化到全局適應度**：使用最終基準測試的驗證器作為適應度函數，而非狹隘的局部目標（narrow local objective）。  
3. **從「贏者全拿」到「保留並擴展」**：任何進步都必須承擔不造成退化的義務，這讓異質任務分佊上的演化得以持續。  
4. **從單一訊號到統一編輯介面**：失敗、教師、自我三種證據共用同一個 harness 層級介面，提升系統的模組化與可擴展性。

然而，DarwinX 也有其前提限制：它假設存在可靠且可規模化的驗證器。對於沒有自動驗證器的開放式任務（例如創意寫作或開放對話），如何定義適應度仍是未解問題。此外，由於 Monet 是 Salesforce 的專有智慧體，DarwinX 的具體實作與底層模型細節對外部研究者並不完全透明。

#### 可重現性評估

可重現性是評估任何自我演化系統時不可忽視的維度。就目前論文提供的資訊而言：

- **程式碼與模型權重**：論文未明確宣告是否開源 DarwinX 的完整實作。Monet 被標示為 Salesforce 的專有（proprietary）智慧體，底層模型權重亦未公開。這意味著外部研究者難以完全複製「Monet (DarwinX)」的數據點。
- **基準測試資料**：Terminal-Bench 2.1、TerminalWorld、WebArena-Infinity 與 SWE-bench Verified 均為公開或部分公開的基準測試，任務與驗證器原則上可取得。這讓「適應度測量」本身具備可重現性。
- **演化產物**：論文提到附錄包含**演化產物（evolved artifacts）**與**稽核規則（audit rubrics）**，這對理解最終 harness 的內容與確認 audit-clean 結果至關重要。若作者未來釋出這些 artifact，將大幅提升可重現性。
- **隨機性與運算成本**：族群式搜尋涉及大量 rollout 與驗證，論文未詳細說明每個數據點所需的運算資源、重複次數與變異度區間。這些細節對於重現「avg@k」與「pass@1」結果非常重要。

整體而言，DarwinX 的**方法論層級**是可重現的——選擇迴路、契約條件與訊號介面都可以被重新實作；但**系統層級**的可重現性受限于 Monet 的封閉性與程式碼未公開。若未來能釋出開源實作（例如基於公開 LLM 的 DarwinX 版本），將有助於社群驗證其泛化性。

#### 未來研究方向

DarwinX 把「凍結模型 + 演化 harness」的潛力展現得相當清楚，但也開啟了若干值得後續探索的方向：

1. **開放式任務的適應度設計**  
   當基準測試沒有自動驗證器時，如何設計適應度函數？可結合人類回饋、模型評判器（model-based judges）或延遲獎勵，發展適用於創意、研究與對話任務的 DarwinX 變體。

2. **與模型微調的協同**  
   DarwinX 目前完全不改模型權重。未來可研究「harness 天擇」與「模型權重更新」的交替迴路：例如用 DarwinX 產生高品質 rollout 資料，再進行微調，形成雙軌演化。

3. **理論化選擇機制**  
   作者提到 Yang 等人與 Darwin Agent Team 把自我改進視為強化學習（reinforcement learning）的「操作鏡像（operational mirror）」。未來可進一步形式化 DarwinX 的 preserve-and-extend 契約與族群動態，分析其收斂性、樣本複雜度與探索—利用權衡。

4. **自動任務家族發現**  
   目前任務家族（task families）似乎仍由人類或既有基準預先定義。若能讓系統自動發現任務家族並據此維護專門化譜系，將進一步降低人工設計負擔。

5. **安全性與對齊**  
   自我演化系統可能會發展出繞過驗證器或對齊機制的 harness 策略。未來需要建立「演化對齊（evolutionary alignment）」框架，確保 harness 的優化目標與人類意圖保持一致。

6. **多模態與具身智慧體**  
   DarwinX 目前聚焦於終端機與網頁智慧體。將其擴展到視覺—語言—動作（VLA）智慧體、機器人控制或科學實驗平台，將是檢驗其通用性的下一個戰場。

7. **開源實作與標準化評估協議**  
   建立一個不依賴專有模型的 DarwinX 開源版本，並制定標準化的運算成本、重複次數與稽核流程，將有助於社群進行公平比較與後續改進。

總體而言，DarwinX 的貢獻不僅在於分數提升，更在於提出了一個可擴展的「harness 天擇」典範：當模型權重被凍結，評估運算資源本身就能轉化為可遷移、可累積的智慧體能力。

## 論文問答

**Q1：DarwinX 試圖解決的核心問題是什麼？為何「harness」的演化對 LLM 智慧體如此重要？**

A：DarwinX 針對的是現代 LLM 智慧體的能力不僅取決於模型權重，更取決於圍繞模型的 harness（提示詞、工具、技能、控制流程與記憶體）這一事實。現有的自我改進迴路雖然能編輯 harness，但多採用單譜系搜尋，容易產生路徑依賴，且局部勝利常導致其他任務退化。因此，DarwinX 將自我演化重新框架為「在凍結模型的前提下，對 harness 變體族群進行天擇」，讓評估運算資源轉化為持久且可遷移的通用智慧體能力。

**Q2：現有自我改進智慧體方法的主要失敗模式是什麼？DarwinX 如何克服它們？**

A：現有方法主要有兩個失敗模式：一是路徑依賴，單譜系 keep-best 機制會被早期編輯所偏見，最終停滯；二是跨任務干擾，針對某一任務家族的修復可能暗中讓另一家族退化。DarwinX 透過典藏庫保存多個替代譜系，並允許互補的專門化變體進行繼承或合併，同時以「保留並擴展契約」限制任何勝出變體可造成的退化範圍，從而讓不同譜系的進步能夠重新匯聚。

**Q3：為什麼 DarwinX 強調「天擇」而非設計者指定的更新規則？這對智慧體能力有何深遠意義？**

A：DarwinX 所謂的天擇是字面意義：沒有黃金解答，也沒有人工挑選的勝出者，只有變體在測量適應度下的更適者生存。這種純粹由基準測試自身驗證器驅動的選擇，能避免設計者狹隘的局部目標，並促使 harness 學到通用智慧體能力而非針對特定測試的補丁。結果是演化出的能力能跨任務、跨驗證器、甚至跨基礎模型存活，真正將評估運算資源轉化為持久能力。

**Q4：DarwinX 的核心方法可以分為哪三個部分？請簡要說明。**

A：DarwinX 的第一部分是譜系分支演化：透過 trace-guided 編輯反覆產生 harness 變體，並以生存選擇與更嚴格的 avg@k 確認來決定是否晉升。第二部分是族群層級的典藏庫：存活與歸檔的分支形成族群，互補的專門化變體可被繼承或合併，使不同譜系的進步不再被困住。第三部分是模組化的提案訊號：失敗衍生、教師衍生與自我衍生的證據都透過同一編輯介面轉換為 harness 層級的修改，而不觸動模型權重。

**Q5：DarwinX 相較於 DGM 等前作的關鍵創新是什麼？**

A：關鍵創新在於把「變體如何取得典藏庫席位」的規則明確化：DarwinX 要求子代必須簽訂「保留並擴展契約」，只有在擴大涵蓋範圍且不造成退化的前提下才能被接納。相較於 DGM 一次只突變一個親代並讓子代與親代比較，DarwinX 會將互補譜系重新合併，並以基準測試最終驗證器的 avg@k 作為唯一適應度。這使得 harness 的演化不再是孤立的單線改進，而是能累積多元專長的族群天擇。

**Q6：DarwinX 為何選擇演化 harness 而非整個智慧體原始碼？為何使用 avg@k 且不要黃金解答？**

A：演化 harness 而非整個智慧體原始碼，是因為 harness 是能力與行為更直接、更可重組的載體，便於執行「保留並擴展契約」與跨譜系合併。使用 avg@k 作為適應度，並以基準測試自身驗證器評分，能讓選擇準則對齊最終任務分佈，而非設計者手動挑選的局部勝利。排除黃金解答與人工挑選勝出者，則可防止過度擬合與人為偏見，確保演化訊號來自真實的測量適應度。

**Q7：DarwinX 在四個基準測試上的評估設計有何特殊之處？它們如何區分「演化訊號」與「測試」？**

A：四個基準測試按照「演化訊號與最終測試之間的距離」遞增排列：Terminal-Bench 2.1 是同域測試時演化；TerminalWorld 是保留測試集的任務泛化；WebArena-Infinity 是合成意圖到真實任務的泛化；SWE-bench Verified 則是跨基準測試的零樣本遷移。這種設計能區分 harness 是學到可遷移的通用能力，還是僅僅在優化其評估集，從而更嚴謹地檢驗 DarwinX 的泛化性。

**Q8：DarwinX 在四個基準測試上的關鍵數據結果是什麼？**

A：在 Terminal-Bench 2.1 上，DarwinX 在配對基礎模型上提升 7.7 分達到 83.2%，在更強基礎模型上達到經驗證的前沿 84.7%。在 TerminalWorld 的保留測試集上達到 68.3%，超越所有現成智慧體；在 WebArena-Infinity 上，真實任務 pass@1 從 43.5% 提升至 93.0% 且經稽核無誤。此外，Terminal-Bench 2.1 的 harness 原封不動地遷移到 SWE-bench Verified，顯示其演化的是通用能力而非特定測試補丁。

**Q9：消融實驗與案例研究揭示了哪些關鍵的演化行為？**

A：消融實驗透過比較最佳演化 harness 與基礎 Terminal-Bench 2.1 智慧體，發現主要增益可歸因於一組演化出的驗證與契約技能組合。雖然作者謹慎地不宣稱每項技能的獨立因果效應，但案例研究顯示，演化後的 harness 更懂得在執行過程中自我檢查、利用驗證器回饋並維持行為契約。這說明 DarwinX 不只是堆疊特定補丁，而是催生了更高階的後設認知與驗證行為。

**Q10：DarwinX 在實務上可以應用於哪些場景？**

A：DarwinX 可應用於需要長期自主運作的複雜編碼智慧體、終端機自動化、網頁代理以及軟體工程任務。企業可以在自己的任務分佈與內部驗證器上持續演化 harness，無需重新訓練或微調基礎模型，從而累積組織專屬的持久能力。由於 harness 是凍結模型外的可替換元件，這也讓能力升級與模型替換可以分開進行，降低維運風險。

**Q11：若將 DarwinX 產品化，需要考慮哪些工程與治理議題？**

A：首先，演化過程需要大量評估運算資源，因此必須建立高效的批次展開與快取機制；其次，驗證器的品質與覆蓋率直接決定適應度訊號，若驗證器有雜訊或漏洞，天擇可能導向錯誤方向。此外，典藏庫規模、譜系追蹤、稽核無誤流程以及「保留並擴展契約」在生產環境中的嚴格執行，都是確保演化結果不會暗中退化既有任務的關鍵治理環節。

**Q12：DarwinX 對整個 LLM 智慧體研究領域可能帶來什麼影響？**

A：DarwinX 將研究焦點從單純擴大模型權重訓練，轉移到如何利用評估運算資源進行 harness 層級的天擇演化。它串連了自我改進智慧體、品質多樣性搜尋與開放式演化等研究傳統，並提供了一個以測量適應度為唯一選擇標準的具體範式。長遠來看，這可能改變我們對「能力從何而來」的理解：不只有模型訓練能產生能力，持續的 harness 選擇同樣能將評估轉化為 durable capability。

**Q13：DarwinX 有哪些已承認或可想見的限制？**

A：DarwinX 高度依賴基準測試或任務分佈上存在可靠、可規模化的驗證器，若驗證器本身不完整，則天擇訊號會失真。其次，演化需要大量運算與多輪評估，對於資源受限的場景可能不敷使用；此外，消融實驗並未宣稱每項演化技能的獨立因果效應，因此難以精確指出哪一個 harness 元件對哪一類任務負責。最後，典藏庫與譜系數量持續增長，也會帶來儲存、管理與合併衝突的挑戰。

**Q14：在哪些情況下 DarwinX 可能會失敗或表現不如預期？**

A：當「保留並擴展契約」過於嚴格時，某些短期會造成輕微退化、但長期能帶來更大突破的變體可能會被過早淘汰。若不同譜系發展出的策略在語義或控制流程上互相衝突，合併時也可能無法產生預期的互補效果，甚至產生新的退化。此外，若初始族群多樣性不足或任務分佈過於狹窄，天擇仍可能陷入局部最佳，無法完全擺脫路徑依賴。

**Q15：未來研究可以如何延伸 DarwinX 的框架？**

A：未來可以將 DarwinX 擴展到多模態智慧體，讓視覺、語言與行動的 harness 共同演化；也可以探索 harness 演化與模型權重更新之間的協同，例如用演化出的訓練資料或獎勵訊號進一步精煉模型。另一個方向是發展更豐富的譜系追蹤與自動合併演算法，並將其應用於安全關鍵領域，搭配形式化驗證器進行更嚴謹的「保留並擴展」保證。最後，研究 harness 選擇的規模法則與開放演化動力學，將有助於理解這種新型能力來源的極限。

## 實務應用指南

### 適用場景

1. **企業內部開發者平台（Internal Developer Platform）的終端機與 DevOps 智慧體**  
   讓 LLM 智慧體在凍結模型權重的情況下，持續演化處理 shell、Git、CI/CD、容器與雲端指令的提示詞、工具與控制流程。適合需要穩定提升終端機任務通過率、又不想頻繁微調基礎模型的工程團隊。

2. **軟體工程工單自動化（SWE-bench 類場景）**  
   將 DarwinX 用於演化「驗證／契約技能包」（verification/contract skill bundle），讓智慧體自動修復 issue、執行測試、檢查 diff 並提交 patch。由於 harness 可原封不動遷移到 SWE-bench Verified，企業可將同一套演化後的 harness 套用至內部程式碼庫的工單處理流程。

3. **網頁操作與客服自動化（WebArena-Infinity 類場景）**  
   在合成意圖（synthetic intents）上進行 harness 演化，再部署到真實網頁任務。適合電商、金融或 SaaS 企業的後台操作、表單填寫、資料查詢與跨系統流程自動化，並透過稽核機制確保真實任務 pass@1 的可靠性。

4. **異質性資料與 API 整合代理（Data/ETL Agent）**  
   當智慧體需要呼叫多種外部 API、資料庫與檔案系統時，DarwinX 可透過族群搜尋與保留並擴展契約，避免「修好 A 任務、退化 B 任務」的跨任務干擾，適合資料工程、報表生成與跨系統同步。

5. **QA／迴歸測試智慧體**  
   利用驗證器作為適應度函數，讓智慧體演化測試腳本生成、錯誤診斷與重試策略。由於 fitness 來自基準測試自身的 verifier，無需人工標註黃金解答，適合持續整合環境中的自動化測試維護。

### 實作前置條件

**資料**
- 具有明確驗證器（verifier）的任務分佈：每個任務必須能自動判斷成功或失敗，例如單元測試、環境狀態檢查或輸出比對。
- 歷史 rollout 軌跡：包含成功與失敗的執行記錄，作為 failure-derived、self-derived 與 teacher-derived 訊號的素材。
- （建議）教師示範或高品質參考軌跡：用於初始化或引導特定技能文件（skill documents）的生成。

**運算資源**
- 大量平行評估運算：DarwinX 的核心是將評估運算轉化為持久能力，需準備可平行執行數百至數千次 rollout 的運算叢集或容器環境。
- 沙箱化執行環境：每個變體都必須在隔離環境中執行，避免污染檔案系統或外部服務。
- 版本化儲存空間：用於保存典藏庫（archive）中的多個 harness 譜系與其適應度記錄。

**技能與團隊**
- 熟悉智慧體框架與 harness 設計（提示詞、工具、控制流程、記憶體）。
- 具備建置自動化評估管線與 verifier 的能力。
- 了解版本控制、A/B 測試與持續整合流程，以便將演化後的 harness 安全部署到生產環境。

---

### 實作步驟建議

1. **定義任務分佈與適應度函數**  
   選定一組真實業務任務，並為每個任務建立自動 verifier。適應度採用 avg@k 或 pass@1，且必須能反映最終基準測試表現，而非局部目標。

2. **建立基礎 harness 並凍結模型**  
   準備初始提示詞、工具、技能文件與控制流程。確認基礎模型權重固定，所有改進都發生在 harness 層。

3. **初始化族群與典藏庫**  
   從基礎 harness 產生數個變體作為創始族群，並建立 archive 保存每個存活譜系。保留多樣性，避免過早收斂到單一路徑。

4. **建置三種提案訊號模組**  
   實作 failure-derived（失敗診斷）、teacher-derived（教師示範）與 self-derived（rollout 對比）訊號，並統一轉換為 harness 層級的編輯建議。

5. **實作保留並擴展契約**  
   設定明確的退化（regression）閾值：子代只有在不造成既有任務退化、或退化幅度被嚴格限制時，才能晉升為祖先。使用更嚴格的 avg@k 確認來控制晉升。

6. **執行演化迴路與重組**  
   反覆進行「批次展開 → 反思 → 有限編輯 → 閘控篩選」。當典藏庫中出現互補的專門化變體時，進行譜系間的繼承或合併（merge）。

7. **稽核與真實任務驗證**  
   對最佳 harness 執行人工稽核（audit-clean），並在保留測試集或真實環境中驗證，確保提升不是針對 verifier 的過擬合。

8. **部署與持續演化**  
   將通過驗證的 harness 部署到生產環境，同時保留回滾機制。持續收集新的 rollout 軌跡，讓族群隨著新任務與新任務家族不斷演化。

---

### 潛在風險與注意事項

- **過度擬合 verifier／基準測試特定補丁**  
  智慧體可能學會欺騙 verifier 而非真正解決任務。  
  **緩解**：使用保留測試集、真實任務稽核，並定期更換 verifier 或加入多樣化任務家族。

- **跨任務退化**  
  局部勝利可能導致其他任務性能下降。  
  **緩解**：嚴格執行保留並擴展契約，對所有候選變體進行全分佈 avg@k 評估，而非只看單一任務家族。

- **運算成本爆炸**  
  族群搜尋需要大量 rollout。  
  **緩解**：設定預算上限、使用早期淘汰機制、優先評估高潛力變體，並利用快取避免重複執行相同任務。

- **自我修改的安全性與可解釋性**  
  harness 會改變提示詞、工具與控制流程，可能引入未預期行為。  
  **緩解**：沙箱執行、版本控制每個變體、人工閘控最終晉升、保留完整變更日誌以便稽核。

- **模型 API 或基礎能力變化**  
  凍結模型並非永遠不變，基礎模型升級可能使舊 harness 失效。  
  **緩解**：將 harness 與模型版本綁定，並在模型更新後重新執行保留並擴展契約驗證。

### 與其他技術的整合建議

- **CI/CD 管線**：將 DarwinX 的演化迴路視為長時間執行的「智慧體訓練任務」，在夜間或離峰時段執行，並把通過驗證的 harness 以 artifact 形式發布到部署管線。
- **可觀測性平台**：將每個 rollout 的軌跡、適應度與 harness 版本匯入追蹤系統，方便後續分析退化來源與技能使用頻率。
- **模型服務（Model Serving）**：DarwinX 不修改模型權重，因此可無縫對接現有 LLM API 或自架推論服務，只需確保模型版本固定。
- **向量資料庫與技能文件管理**：將演化後的技能文件儲存在向量資料庫中，讓智慧體在執行期依據任務動態檢索，並支援版本化更新。
- **現有 Agent 框架（如 LangChain、AutoGen）**：可將 DarwinX 作為 harness 最佳化層，產生或更新框架內的提示詞、工具定義與控制流程節點。
- **人類回饋迴路（Human-in-the-Loop）**：在關鍵晉升閘道加入人工審查，特別是涉及程式碼提交、生產環境操作或敏感資料的任務。

### 給不同背景讀者的閱讀建議

**初學者**：把 DarwinX 想像成「自動化的 A/B 測試與提示詞工程」——它不改變 LLM 本身，而是透過不斷嘗試、篩選與合併提示詞、工具與流程，找出最穩定的智慧體配置。重點理解「保留並擴展契約」與「用驗證器打分」這兩個概念即可。

**AI 工程師**：請聚焦於 §2 的選擇迴路與 §8 的技能歸因。實作時最關鍵的是 archive 管理、退化閘控、avg@k 晉升機制，以及三種提案訊號如何統一成 harness 層級編輯。建議先從單一任務家族開始驗證，再擴展到異質性分佈。

**研究人員**：本文的核心貢獻在於將自我演化重新框架為「無黃金標籤、無人工挑選勝出者的天擇過程」。建議深入分析 preserve-and-extend contract 對跨任務干擾的影響、族群多樣性與路徑依賴的權衡，以及從合成到真實、跨基準測試遷移的泛化機制。

**產品經理**：DarwinX 的價值主張是「把評估運算資源轉化為持久能力」，無需重新訓練模型即可持續提升智慧體表現。請關注適用場景、運算成本、稽核與治理風險，並將其定位為現有 LLM 服務之上的「能力演化層」，而非取代現有模型基礎建設。
