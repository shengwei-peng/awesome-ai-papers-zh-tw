## 摘要翻譯

現今的自迴歸（AR）影片擴散模型在短視界影片生成上表現優異，然而長影片生成仍具挑戰性，原因在於漂移（drifting）：顏色與紋理發生變化，且運動動態（motion dynamics）逐漸衰退。現有方法主要依賴 KV 條件化（KV conditioning），透過選取或修改快取的鍵值（KV）項目（KV entries）來緩解漂移。然而，我們觀察到僅靠 KV 條件化並不足夠，因為它假設快取的 KV 項目仍維持在分佈內（in-distribution）。此一假設在超出訓練視界（training horizon）時失效：在推出（rollout）過程中沒有任何機制限制 KV 項目的建構，因而產生 KV 來源問題（KV-provenance problem），使得快取的 KV 項目本身成為分佈外（OOD）。為解決此問題，我們提出 In-Distribution Forcing（ID-Forcing），這是一個測試階段框架（test-time framework），可將 KV 快取（KV caching）與 KV 條件化兩者皆與訓練配置對齊（align with training configurations）。其核心機制「自我快取」（self-caching）能從源頭防止分佈外 KV 項目。每個片段（chunk）在進行 KV 快取時皆不關注（attend to）先前的 KV 項目（prior KV entry），使滾動視窗（rolling window）精確地維持在分佈內。因此，ID-Forcing 能無縫擴展（seamlessly extend）短視界模型至分鐘級影片生成（minute-scale video generation）。廣泛的評估（evaluations）顯示，我們的方法在標準影片生成基準（video generation benchmark）上仍具有競爭力（competitive），同時在緩解漂移方面大幅優於（substantially outperform）先前工作（prior work），此結果亦經由我們的漂移指標（drift metric）與使用者研究（user study）共同驗證。

### 核心貢獻（3～5點）
- 指出現有 KV 條件化方法的關鍵限制：其隱含假設快取的 KV 項目始終維持在分佈內，但此假設在超出訓練視界時並不成立。
- 提出 KV 來源問題：在自迴歸推出過程中，KV 項目的建構缺乏約束，導致快取項目本身逐漸成為分佈外（OOD），成為長影片漂移的根本來源。
- 提出 ID-Forcing 測試階段框架，透過自我快取機制從源頭防止分佈外 KV 項目，使滾動視窗精確對齊訓練分佈。
- 將短視界模型無縫擴展至分鐘級長影片生成，並在標準基準上維持競爭力，同時在緩解漂移方面大幅優於先前方法。
- 透過客製化漂移指標與使用者研究，驗證方法在視覺品質與動態連貫性上的顯著改善。

### 適合對象
本論文適合從事長影片生成、自迴歸（AR）影片擴散模型、世界模型（world model）以及串流長影片微調（streaming long-video tuning）相關研究的研究人員與工程師。特別是關注如何緩解長視界生成（long-horizon generation）中漂移、誤差累積與訓練–推論差距（training-inference gap）問題，以及對 KV 快取與 KV 條件化設計感興趣的讀者。此外，對於希望將短視界模型擴展至分鐘級影片生成、應用於長篇敘事（long-form storytelling）或互動式應用（interactive application）的實務開發者亦具參考價值。

## 深度分析

#### 方法論解析

本文提出的核心方法為 **In-Distribution Forcing（ID-Forcing，分佈內強制）**，其目標並非重新設計擴散模型本身，而是在**測試階段（test time）**透過控制兩項關鍵的 **KV 操作（KV operations）**——**KV 快取（KV caching）**與 **KV 條件化（KV conditioning）**——來讓長影片生成過程始終停留在訓練時見過的條件配置中，從而抑制 **drifting（漂移）**。

##### 1. 問題根源：KV 來源問題（KV-provenance problem）

在標準的 **自迴歸（AR）影片擴散模型（autoregressive video diffusion model）** 中，影片被切成一連串 **chunk（片段）** \(x_j\)，並依據式 (1) 的分解逐段生成：

\[
p(x_{0:M}) = \prod_{j=0}^{M} p(x_j \mid x_{<j}).
\]

實作上，過去的片段不會直接作為原始 latent 傳入，而是先被編碼成單一 **KV 項目（KV entry）** \(\kappa_i\)，後續片段再透過注意力機制關注這些項目。訓練時，模型進行長度為 \(N\) 的 **自我推出（self-rollout）**，對於第 \(i\) 個片段：

- **KV 條件化**：生成 \(x_i\) 時，去噪器 \(G_\theta\) 關注所有先前的 KV 項目 \(\kappa_{<i}\)（式 2）。
- **KV 快取**：生成乾淨片段 \(x_i^0\) 後，同樣的去噪器在 \(t=0\) 時再次前向傳播，將對應的 KV 狀態抽出並儲存為 \(\kappa_i\)（式 3）。

關鍵在於：式 (2) 與式 (3) 使用的上下文視窗完全相同，都是 \(\kappa_{<i}\)。因此，在 **訓練視界（training horizon）** 內，每一個 KV 項目都是在「看過 \(0\) 到 \(i-1\) 個先前項目」的條件下建構的，這些 **來源（provenance）** 都屬於 **分佈內（in-distribution）**。

然而，當生成超過訓練視界（\(i \ge N\)）時，標準的 **滾動視窗（rolling window）** 方法會固定視窗大小為 \(L < N\)，只保留最近的 \(L\) 個 KV 項目。此時雖然 **KV 條件化** 與 **KV 快取** 的數學形式不變，但它們所關注的窗口內容卻是訓練時從未出現過的組合：一個片段被快取時，它所關注的上下文是在「已經被其他 OOD 上下文建構出來的 KV 項目」之上。這就是作者所稱的 **KV 來源問題（KV-provenance problem）**：**快取的 KV 項目（cached KV entries）** 本身已經變成 **分佈外（out-of-distribution, OOD）**，後續無論如何選擇或修改要讀取的項目，都無法挽回這個源頭錯誤。

##### 2. 核心機制：Self-Caching（自我快取）

ID-Forcing 的解法是 **self-caching（自我快取）**。其直覺非常簡潔：要讓所有 KV 項目的來源都屬於訓練分佈，就必須在 **KV 快取** 的當下，讓每個項目被建構時所關注的上下文，與訓練時某個片段曾經見過的上下文完全一致。

具體來說，當滾動視窗已滿（長度為 \(L\)）並繼續外推時：

- **視窗中最舊的片段**在進行 KV 快取時，只讓它關注自己（即使用空的快取視窗）。這相當於訓練時第 \(0\) 個 chunk 的情況。
- **視窗中後續的片段**則在這個新建立的自我快取項目之上，依序進行 **自迴歸（autoregressive）** 快取。這相當於訓練時第 \(1, 2, \dots, L-1\) 個 chunk 的情況。

如此一來，滾動視窗中的每一個 KV 項目，其 **來源（provenance）** 都是長度不超過 \(L\) 的前綴，而這些前綴組合在訓練時（因為 \(L < N\)）已經全部出現過。換句話說，**每個 KV 操作都是訓練時執行過的操作**。

圖 2 與圖 3 清楚說明了這一點：在 **Self-Forcing** 或 **Sink Caching** 中，即使 **KV 條件化** 使用相同的視窗，由於最舊片段的快取方式不同，導致下一個片段 \(x_7\) 出現漂移；而 **self-caching** 因為從源頭保證了分佈內，後續生成不再漂移。

##### 3. KV 條件化的對齊

作者進一步指出，僅有正確的 KV 快取還不夠，**KV 條件化** 也必須與訓練配置對齊。特別是，滾動視窗中的**第一個片段必須保留在條件視窗中**，否則後續片段在生成時所見的上下文仍然會偏離訓練分佈。**Self-caching** 的設計恰好讓整個滾動視窗維持在分佈內，因此可以搭配最簡單的純滾動視窗策略，無需額外的 **注意力匯點（attention sink）** 或 **時間位置嵌入（temporal positional embedding）** 修改。

總結來說，ID-Forcing 的演算法極為簡潔：對於每一個新的片段，執行兩條規則：

1. **KV 快取**：若該片段將成為滾動視窗中最舊的項目，則在快取時不關注任何先前的 KV 項目；否則依序關注視窗內已有的項目。
2. **KV 條件化**：生成時使用與訓練時相同的滾動視窗，確保第一個項目保留在視窗內。

這使得一個原本只能生成約五秒影片的 **短視界模型（short-horizon model）**，可以在不重新訓練的情況下，直接擴展到 **分鐘級影片生成（minute-scale video generation）**。

#### 實驗數據解讀

由於提供的上下文未包含具體的數值表格，以下根據摘要與方法論進行推論性解讀，並指出應關注的實驗設計細節。

##### 1. 評估面向

作者強調 ID-Forcing 在兩個層面上進行評估：

- **標準影片生成基準（video generation benchmark）**：用於確認方法在常規短視界生成上沒有退化，維持與原模型相當的 **視覺品質（visual quality）** 與 **運動動態（motion dynamics）**。
- **漂移指標（drift metrics）與使用者研究（user study）**：用於量化長時間生成中 **顏色與紋理（color and texture）** 的穩定性以及動態是否衰減。

##### 2. 漂移指標的意義

漂移的本質是時間上的漸進式退化，因此單一幀的品質指標（如 FID、FVD）可能無法充分捕捉。合理的 **drift metric** 設計應包括：

- **外觀一致性**：測量相鄰 chunk 重疊區域的顏色、紋理變化，例如 LPIPS、PSNR、SSIM 的時間曲線。
- **動態持續性**：測量光流（optical flow）大小或動作幅度是否隨時間遞減。
- **長期 FVD**：將整段長影片與真實影片分布比較，觀察 FVD 是否隨長度線性增長。

若 ID-Forcing 能有效抑制漂移，我們預期看到：

- 外觀一致性指標在長時間內保持平穩，不會出現明顯的顏色偏移或紋理模糊。
- 動態指標不會隨時間衰減到接近靜止畫面。
- 與基線相比，漂移曲線的斜率顯著降低。

##### 3. 使用者研究的意義

由於許多漂移現象（如細微的色調偏移、動作不自然）對自動指標不敏感，**使用者研究（user study）** 提供了重要的互補證據。若結果顯示受試者明顯偏好 ID-Forcing，則代表該方法在感知層面上確實減少了長影片中的不連貫與退化。

##### 4. 需要注意的實驗細節

在閱讀完整論文時，應特別檢視：

- **訓練視界 \(N\)** 與 **滾動視窗大小 \(L\)** 的設定。ID-Forcing 的有效性依賴於 \(L < N\)，若 \(L\) 過大或訓練時未涵蓋足夠長度的前綴，則理論保證會失效。
- 是否與 **Self-Forcing**、**LongLive**、**attention sink**、**temporal positional embedding 修改** 等方法進行公平比較，包括相同的基礎模型與相同的生成分辨率。
- 是否報告了生成時間與記憶體開銷。**Self-caching** 可能需要額外的前向傳播來在空上下文下重新計算 KV，這會影響實用性。

#### 與現有研究的比較

##### 1. 相對於 KV 條件化方法

現有工作大多聚焦於 **KV 條件化（KV conditioning）**，例如：

- **Attention sink（注意力匯點）**：在滾動視窗中保留最舊的幾個 KV 項目，希望維持長期一致性。
- **Temporal positional embedding 修改**：調整 KV 項目的位置嵌入，讓模型對滾動視窗中的時間位置更魯棒。

這些方法都隱含一個假設：**快取的 KV 項目（cached KV entries）** 本身是分佈內的。作者明確指出這個假設在超出訓練視界後不成立，因為這些項目的 **來源（provenance）** 已經 OOD。因此，無論選擇哪些項目或如何調整位置，都無法從根本上消除漂移。ID-Forcing 的貢獻在於將問題從「讀什麼」推進到「這些項目是怎麼被建構出來的」。

##### 2. 相對於 Self-Forcing

**Self-Forcing** 透過在訓練時進行 **自我推出（self-rollout）**，讓模型習慣自己生成的上下文，從而縮小 **訓練–推論差距（training-inference gap）**。然而，訓練時的推出長度仍然是有限的。一旦測試時需要生成比訓練視界更長的影片，仍然會遇到外推問題。ID-Forcing 可以視為 Self-Forcing 的互補：Self-Forcing 解決了訓練範圍內的分布對齊，ID-Forcing 則解決了超出訓練視界後的測試階段對齊。

##### 3. 相對於 LongLive

**LongLive** 透過 **串流長影片微調（streaming long-video tuning）** 來擴展生成長度，這需要額外的訓練資料與計算資源。相較之下，ID-Forcing 是一個純粹的 **測試階段框架（test-time framework）**，不需要重新訓練或微調模型，這在部署彈性與計算成本上具有明顯優勢。

##### 4. 優勢與限制

**優勢：**

- **簡潔性**：不需要修改模型架構、損失函數或訓練流程，僅調整 KV 操作。
- **通用性**：可應用於任何基於 **KV cache（鍵值快取）** 的 **自迴歸（AR）影片擴散模型**。
- **有效性**：從源頭防止 OOD KV 項目，理論上比僅調整 KV 條件化更根本。

**限制：**

- 依賴於訓練時涵蓋足夠長度的前綴。若滾動視窗大小 \(L\) 超過訓練視界 \(N\)，則無法保證分佈內。
- 只處理了 KV 操作層面的漂移，對於其他來源的誤差累積（例如去噪步數不足、採樣器選擇、量化誤差）並無直接作用。
- **Self-caching** 可能需要額外的計算：為了在空上下文下建立 KV 項目，可能需要對同一片段進行額外的前向傳播，這會增加生成延遲與記憶體頻寬需求。
- 對於需要長期敘事連貫性的應用（如 **long-form storytelling**），僅保證區域性視窗分佈內可能仍不足夠，因為滾動視窗會遺忘更早的內容。

#### 可重現性評估

根據目前提供的上下文，論文並未明確提及是否公開 **原始碼（code）**、**資料集（datasets）**、**模型權重（model weights）** 或推論腳本。因此，從可重現性的角度，現階段只能做出以下評估：

##### 1. 方法本身的可重現性

ID-Forcing 的演算法描述相當清晰，核心僅涉及兩項 KV 操作的調整。對於已經熟悉 **自迴歸（AR）影片擴散** 與 **KV cache** 實作的研究者來說，理論上可以在現有模型基礎上復現。所需的修改包括：

- 在 KV 快取階段，根據片段是否為滾動視窗中最舊項目，決定是否使用空上下文。
- 在 KV 條件化階段，確保滾動視窗的組成與訓練時一致。

##### 2. 需要公開的資源

若要達到高可重現性，作者應提供：

- 完整的推論程式碼，包含 **self-caching** 的實作細節。
- 基礎模型的權重與訓練配置，特別是 **訓練視界（training horizon）** \(N\)、**滾動視窗大小（rolling window size）** \(L\)、去噪步數 \(T\)。
- **漂移指標（drift metrics）** 的實作與評估腳本。
- 使用者研究的協議與原始數據。
- 用於評估的提示詞（prompts）與生成樣本。

##### 3. 當前評估

在缺乏上述資源的情況下，本論文的可重現性屬於**中等**。方法概念簡潔，降低了復現門檻；但具體的 KV 快取實作（例如 stop-gradient 的處理、空上下文的定義、與現有框架如 Diffusers 的整合）仍可能存在細節差異，影響結果的一致性。

#### 未來研究方向

ID-Forcing 為長影片生成中的漂移問題提供了一個新的視角，未來可以從以下方向延伸：

##### 1. 與訓練方法結合

將 ID-Forcing 與 **Self-Forcing** 或 **LongLive** 結合，形成「訓練時擴展視界 + 測試時強制分佈內」的雙重保障。例如，在訓練時使用較長的自我推出，並在測試時使用 **self-caching** 進一步外推。

##### 2. 自適應滾動視窗

目前的 ID-Forcing 使用固定大小的 **滾動視窗（rolling window）**。未來可研究根據內容動態調整視窗大小：在動作劇烈或場景轉換時保留更多上下文，在靜態場景中縮小視窗以節省記憶體。

##### 3. 層級式 KV 快取

對於分鐘級甚至小時級影片，單一層級的 KV 項目可能不足以捕捉長期結構。可探索多層級摘要機制，例如將數個片段壓縮為一個高階 KV 項目，同時保留 **self-caching** 的分佈內保證。

##### 4. 理論刻畫漂移

目前對漂移的理解主要來自經驗觀察。未來可建立更嚴格的數學模型，分析 **KV 來源（provenance）**、誤差累積與生成分佈偏移之間的定量關係，並據此設計最優的快取策略。

##### 5. 擴展到其他模態與任務

ID-Forcing 的核心思想——控制條件化與快取的來源以維持分佈內——可應用於其他需要長期一致性的生成任務，例如長音訊生成、3D 場景生成、互動式 **世界模型（world model）** 以及多模態串流內容生成。

##### 6. 記憶體與效率最佳化

**Self-caching** 可能帶來額外計算開銷。未來可研究如何將其與 KV 快取壓縮、量化、稀疏注意力等技術結合，在保持分佈內的同時降低記憶體與延遲。

##### 7. 使用者可控的漂移權衡

在某些創意應用中，輕微的風格漂移可能是可接受甚至是有意的。未來可探索讓使用者控制「漂移預算」，在一致性与多樣性之間進行權衡。

## 論文問答

**Q1：什麼是長影片生成中的「漂移」（drifting），它為什麼會發生？**

A：漂移是指在長影片生成過程中，隨著時間推進，畫面的顏色與紋理逐漸偏移、運動動態逐漸衰減的漸進式退化現象。這主要是因為測試階段的自迴歸推出（rollout）與訓練時所見的推出分佈不同：模型在訓練時只接觸到有限的訓練視界，超出該視界後，條件配置就進入分佈外（OOD）區域。隨著生成片段不斷累積，這些微小誤差會逐步放大，最終導致視覺品質明顯下降。

**Q2：現有的 KV 條件化（KV conditioning）方法為什麼不足以解決漂移？**

A：現有 KV 條件化方法通常只決定生成時要關注哪些快取的 KV 項目，或如何調整它們的時間位置嵌入，但它們預設了所有被快取的 KV 項目都是分佈內（in-distribution）的。然而，在超出訓練視界後，這些 KV 項目本身可能已經是在分佈外上下文中建構出來的，單純改變讀取方式無法修復其內在偏差。換句話說，KV 條件化只處理「讀什麼」，卻忽略了「這些項目是怎麼被寫入快取」的根本問題。

**Q3：什麼是 KV 來源問題（KV-provenance problem），為什麼它對長影片生成至關重要？**

A：KV 來源問題指的是：一個 KV 項目不僅取決於它對應的影片片段，也取決於它在 KV 快取時所關注的其他 KV 項目，也就是它的「來源」或「溯源」。當生成超出訓練視界時，片段會在一個訓練從未見過的來源上下文中被快取，導致該 KV 項目成為分佈外項目。由於來源在 KV 快取完成的當下就被固定下來，後續任何 KV 條件化策略都無法挽回，因此必須同時控制 KV 快取與 KV 條件化才能從源頭抑制漂移。

**Q4：In-Distribution Forcing（ID-Forcing）的核心方法是什麼？它如何運作？**

A：ID-Forcing 是一個測試階段框架，目標是將 KV 快取與 KV 條件化兩種操作都對齊到訓練時所見的 KV 上下文配置。其核心機制是「自我快取」（self-caching）：在超出訓練視界後，較早的 KV 項目只關注自身進行快取，後續項目則在這些穩定的項目上自迴歸地堆疊。如此一來，每一個 KV 項目的來源都不會超出訓練分佈，從而避免產生分佈外 KV 項目。

**Q5：自我快取（self-caching）如何確保滾動視窗（rolling window）維持在分佈內？**

A：自我快取讓每個片段在快取時不關注先前的 KV 項目，或只關注已經被確認為分佈內的項目，因此滾動視窗中的內容與訓練時所見的上下文完全一致。由於 KV 快取與 KV 條件化都對應到訓練時執行過的操作，整個推出過程相當於在測試階段重現訓練配置。這使得模型能夠把原本只適用於數秒影片的短視界模型，無縫擴展到分鐘級的長影片生成。

**Q6：為什麼不直接延長訓練視界，或使用注意力匯點（attention sinks）等方法？**

A：單純延長訓練視界無法根本解決問題，因為在任意長的影片生成中，總會有需要外推到訓練視界之外的時刻。注意力匯點等 KV 條件化方法雖然保留第一個片段，但若 KV 快取時的上下文仍是訓練未見過的，整個視窗依舊處於分佈外。ID-Forcing 的關鍵在於從源頭控制 KV 項目的建構過程，並同時對齊條件化與快取兩個環節，因此能真正抑制漂移。

**Q7：本研究在哪些基準與設定下進行評估？**

A：論文在標準影片生成基準上驗證了方法的一般效能，同時針對長影片生成設計了專門的漂移指標與使用者研究。評估涵蓋了分鐘級影片生成任務，並與先前的 KV 條件化方法進行比較。透過這些多元的評估方式，作者能夠同時檢視視覺品質、時間一致性與運動動態的保持程度。

**Q8：ID-Forcing 的主要實驗結果是什麼？**

A：實驗顯示，ID-Forcing 在標準影片生成基準上仍具有競爭力，沒有因為強調長影片穩定性而犧牲短片段品質。在緩解漂移方面，它大幅優於先前工作，無論是透過客觀的漂移指標還是主觀的使用者研究都獲得驗證。最重要的是，該方法能將一個原本只訓練於約五秒影片的模型，成功擴展到分鐘級的連貫生成。

**Q9：論文進行了哪些消融實驗來驗證設計選擇？**

A：消融實驗比較了自我快取、Self-Forcing 快取與 Sink 快取等不同快取策略，結果顯示只有自我快取能避免 KV 項目進入分佈外來源。此外，作者也驗證了第一個片段必須保留在條件視窗中，才能維持分佈內條件化。這些實驗共同說明：單靠 KV 條件化無法解決漂移，必須同時控制 KV 快取的來源。

**Q10：ID-Forcing 可應用於哪些實際場景？**

A：此方法特別適合需要長時間連貫生成的互動式應用，例如世界模型、串流內容生成與長篇敘事影片製作。這些應用不僅要求高保真視覺品質，也需要動作與場景在數十秒甚至數分鐘內保持一致。ID-Forcing 讓現有的短視界模型能夠直接支援這類長視界需求，降低開發長影片生成系統的門檻。

**Q11：從產品部署的角度來看，ID-Forcing 有哪些優勢？**

A：ID-Forcing 是一個測試階段框架，不需要重新訓練或微調模型，能直接應用於已訓練好的自迴歸影片擴散模型。它的實作相當簡潔，基本上是一個帶有明確規則的滾動視窗，對每個 KV 操作給出一條對齊訓練配置的原則。這意味著產品團隊可以在不增加大量運算或模型複雜度的前提下，顯著提升長影片生成的視覺穩定性與動態連貫性。

**Q12：這項研究對長影片生成領域可能帶來什麼影響？**

A：這項研究將研究焦點從單純的 KV 條件化，轉移到 KV 項目的來源與建構過程，提供了理解漂移成因的新視角。它強調訓練與推論配置對齊的重要性，為未來的長視界生成方法奠定了理論基礎。此框架也可能啟發其他自迴歸生成任務，例如長音訊或長文本生成，重新思考快取與條件化的設計。

**Q13：ID-Forcing 有哪些可能的限制？**

A：此方法主要針對自迴歸影片擴散模型中的低階視覺漂移，對於高階語義一致性或長期劇情連貫性的保證仍有限。它假設模型已經在固定訓練視界內進行過自我推出訓練，若訓練過程本身不具代表性，效果可能打折。此外，雖然能達到分鐘級生成，但在極長或極複雜的影片中，仍可能出現緩慢的品質衰減。

**Q14：在哪些情況下 ID-Forcing 可能會失效？**

A：當影片內容包含劇烈的場景轉換、罕見的物體動作，或訓練資料中幾乎未出現的視覺概念時，模型仍可能產生不一致的結果。若滾動視窗大小選擇不當，也可能讓條件化視窗偏離訓練時的配置。此外，第一個片段的品質至關重要，因為後續所有自我快取都建立在其上，初始錯誤會被持續傳遞。

**Q15：未來可以朝哪些方向延伸這項工作？**

A：未來可以結合語義記憶或高階規劃機制，進一步提升長期劇情與場景一致性。也可以探索階層式或自適應的 KV 快取策略，讓模型在更長的影片中動態調整視窗大小與關注範圍。此外，將 ID-Forcing 的核心思想推廣到其他模態，如長音訊、長文本或多模態生成，也是值得研究的方向。

### 實作前置條件

**資料前提**
- 已有一個自迴歸（AR）影片擴散模型，且已知其**訓練視界**（training horizon，即訓練時最多自我推出的片段數）。
- 可取得模型的文字編碼器、VAE/影像編解碼器與擴散 Transformer（DiT）權重。
- 具備與目標應用相符的影片—文字對或條件描述，用於上線前驗證漂移指標。

**運算前提**
- 至少一張高記憶體 GPU（如 24 GB 以上 VRAM）用於推理；分鐘級生成建議多 GPU 或高效 KV 快取管理。
- 若需批次評估或使用者研究，需額外儲存與計算資源。

**技術前提**
- 熟悉 PyTorch/Transformer 推理流程，尤其是注意力機制與 KV 快取實作。
- 理解擴散模型去噪步驟、時間位置嵌入與片段化（chunking）策略。
- 具備修改模型前向傳播（forward pass）與快取邏輯的能力，因為需要區分「KV 快取」與「KV 條件化」兩個階段。

### 實作步驟建議

1. **確認訓練配置與模型限制**  
   從模型訓練紀錄或論文中取得訓練視界 \(N\)、每個片段的幀數 \(f\)、去噪步驟數 \(T\)，以及原本使用的滾動視窗大小 \(L\)。這是決定 ID-Forcing 參數的基礎。

2. **在推理框架中區分 KV 快取與 KV 條件化**  
   將生成流程拆成兩個獨立操作：
   - **KV 條件化**：生成片段 \(x_i\) 時，去噪器關注滾動視窗 \(\kappa_{i-L:i}\)。
   - **KV 快取**：生成乾淨片段 \(x_i\) 後，計算並儲存其 KV 項目 \(\kappa_i\)。

3. **實作自我快取（Self-Caching）**  
   對於超出訓練視界的片段，讓其在 KV 快取階段**只關注自己**（或維持在訓練時見過的視窗配置），而非關注所有先前的 KV 項目。這能從源頭防止分佈外 KV 項目的產生。

4. **設定滾動視窗與第一片段保留規則**  
   - 滾動視窗大小 \(L\) 應與訓練時的上下文配置一致。
   - 確保第一個片段始終保留在條件化視窗中，因為它是後續所有片段的「錨點」。
   - 後續片段在 KV 條件化時可正常關注滾動視窗，但這些視窗必須是由自我快取產生的分佈內項目。

5. **加入漂移監控與品質評估**  
   部署論文提出的漂移指標，例如顏色/紋理一致性與動態衰減指標，並輔以使用者研究。建議在正式上線前，針對目標長度（如 1、2、5 分鐘）進行 A/B 測試。

6. **最佳化記憶體與延遲**  
   自我快取會改變注意力模式，需重新評估記憶體佔用。可考慮：
   - 使用序列並行或分頁注意力（paged attention）管理長 KV 快取。
   - 對非關鍵片段降低去噪步驟數或解析度，以提升吞吐量。
   - 實作串流輸出，讓使用者能邊看邊生成。

7. **產品化封裝**  
   將 ID-Forcing 包裝成可重複使用的推理服務，提供 API 參數如 `max_duration`、`window_size`、`keep_first_chunk`，並整合條件輸入（文字、圖片、動作）與後製流程。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **自我快取實作錯誤導致 OOD KV 項目** | 若在快取階段仍讓片段關注到訓練未見過的視窗，漂移問題會重新出現。 | 嚴格區分「快取時的關注範圍」與「生成時的關注範圍」，並用單元測試驗證。 |
| **滾動視窗大小與訓練配置不一致** | \(L\) 過大或過小都會使條件化配置偏離訓練分佈。 | 優先使用訓練時的視窗大小，若需調整則重新評估漂移指標。 |
| **第一片段被移出條件化視窗** | 一旦第一個片段被驅逐，後續片段的條件化來源就會變成分佈外。 | 在滾動視窗中永久保留第一個 KV 項目，或將其設為注意力匯點（attention sink）的替代方案。 |
| **時間位置嵌入未對齊** | 若模型使用絕對或相對時間位置嵌入，長外推可能導致位置編碼超出訓練範圍。 | 檢查位置嵌入處理方式，必要時採用迴旋/插值或與 ID-Forcing 相容的位置編碼策略。 |
| **記憶體與運算成本上升** | 分鐘級生成需要快取大量 KV 項目，自我快取也可能改變記憶體存取模式。 | 使用 KV 壓縮、分頁快取、量化或分層卸載（offloading）技術。 |
| **與現有 KV 條件化技術衝突** | 若模型已整合 attention sinks 或修改時間位置嵌入的方法，可能與自我快取假設衝突。 | 將 ID-Forcing 視為底層框架，先確保 KV 來源正確，再決定是否保留其他條件化技巧。 |
| **評估指標無法捕捉主觀漂移** | 自動指標可能無法反映人眼對色調或動態變化的敏感度。 | 結合使用者研究與領域專家評分，特別針對顏色、紋理與動態一致性。 |

### 與其他技術的整合建議

- **與 Self-Forcing / LongLive 整合**  
  ID-Forcing 是測試階段方法，可直接疊加在已經過 Self-Forcing 或 LongLive 訓練的模型上。重點是將訓練階段的自我推出邏輯，轉換為推理階段的自我快取規則。

- **與 VAE 與文字編碼器管線整合**  
  確保影片潛空間編解碼器與文字條件編碼器能處理長序列。若 VAE 對長影片有記憶體限制，可採用片段級編解碼並在潛空間進行 ID-Forcing。

- **與串流推理引擎整合**  
  將 ID-Forcing 封裝成串流服務，讓每個片段生成後立即輸出，同時在背景更新 KV 快取。可搭配 vLLM、TensorRT-LLM 或自訂的 diffusion serving 框架。

- **與微調/LoRA 整合**  
  若目標領域與基礎模型分佈差異大，可先以 LoRA 進行領域適應，再套用 ID-Forcing 延長生成長度。注意微調時的訓練視界會影響 ID-Forcing 的參數設定。

- **與後製與品質控制管線整合**  
  將漂移指標與使用者回饋接入 MLOps 管線，持續監控長影片生成品質，並在漂移超標時觸發重新生成或人工審核。

建議先理解「自迴歸生成」與「KV 快取」的基本概念，再聚焦論文的圖 2 與圖 3：它們清楚說明為何「同樣的條件視窗、不同的快取方式」會導致漂移。不必一開始就深入數學推導，重點掌握「KV 項目是怎麼被建構的」這一核心洞察。

**AI 工程師**  
請直接閱讀第 3 節的方法細節，並對照你目前使用的推理框架檢查兩件事：一是 KV 快取階段的 attention mask 是否正確；二是滾動視窗與第一片段保留邏輯是否與訓練配置一致。實作時建議先以短序列（如 2–3 倍訓練視界）驗證漂移指標，再擴展到分鐘級。

**研究人員**  
論文的核心貢獻在於指出「KV 來源問題（KV-provenance problem）」是長影片漂移的根本來源，而非僅是 KV 條件化策略不足。建議深入分析第 3.1 與 3.2 節的證明與機制設計，並思考是否能將 self-caching 推廣到其他序列生成任務（如長音訊、3D 場景序列）或與其他長上下文技術結合。

**產品經理**  
這是一個**無需重新訓練模型**即可延長生成長度的測試階段技術，適合快速驗證長影片應用。請關注「適用場景」與「潛在風險」兩節，評估你的使用情境是否對色調一致性與動態持續性高度敏感；同時預留工程資源處理記憶體優化與使用者研究，因為分鐘級生成的品質最終仍需人眼驗證。
