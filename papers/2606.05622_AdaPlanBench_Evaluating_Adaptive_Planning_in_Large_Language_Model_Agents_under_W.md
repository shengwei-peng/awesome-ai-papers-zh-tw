## 摘要翻譯

語言模型針對真實世界問題進行規劃（Planning）時，往往涉及世界約束（World Constraint）與使用者約束（User Constraint），這些約束（Constraint）可能無法事先完整指定，而是於互動過程中漸進式揭露（Progressive Disclosure）。然而，現有基準測試（Benchmark）對於在這類漸進式揭露的雙重約束（Dual Constraint）下進行適應性規劃（Adaptive Planning）仍缺乏充分探索。為填補此缺口，我們提出 AdaPlanBench，一個動態互動式基準測試（Dynamic Interactive Benchmark），用於評估大型語言模型（Large Language Model, LLM）智慧體（Agent）是否能在漸進式揭露的世界與使用者約束下，適應性地規劃與重新規劃（Re-planning）。AdaPlanBench 建構於 307 項家務任務（Household Task）之上，並具備可擴充性（Scalable）的約束建構流程（Constraint Construction Pipeline），為每項任務擴增雙重約束。在執行階段，智慧體透過多輪協定（Multi-turn Protocol）與環境互動，隱藏約束（Hidden Constraint）僅在智慧體提出違反這些約束的計畫時才會被揭露，智慧體因此必須在累積回饋（Accumulating Feedback）下進行迭代式計畫修正（Iterative Plan Revision）。這使得規劃更具挑戰性，因為智慧體必須從回饋（Feedback）中推論與追蹤約束（Infer and Track Constraints），同時有效地重新規劃。針對十個領先的大型語言模型進行的實驗顯示，在雙重約束下進行適應性規劃仍具挑戰性，最佳模型僅達到 67.75% 的準確率（Accuracy）。我們進一步觀察到，隨著更多約束累積，效能會下降，其中使用者約束構成特別大的挑戰，而失敗往往源自於較弱的物理基礎（Physical Grounding）與降低的有效性（Effectiveness）。這些結果確立了 AdaPlanBench 作為雙重約束互動式規劃（Interactive Planning）的測試平台，並凸顯 LLM 智慧體（LLM Agent）在對動態揭露約束（Dynamically Revealed Constraint）進行可靠適應（Reliable Adaptation）時所面臨的挑戰。

### 核心貢獻（3～5點）
- 揭示現有基準測試（Benchmark）在「漸進式揭露雙重約束（Progressively Revealed Dual Constraint）」情境下的評估缺口，明確指出適應性規劃（Adaptive Planning）與重新規劃（Re-planning）的研究需求。
- 提出 AdaPlanBench，一個動態互動式基準測試（Dynamic Interactive Benchmark），以 307 項家務任務（Household Task）為基礎，並設計可擴充性（Scalable）的約束建構流程（Constraint Construction Pipeline），系統性地為任務擴增世界與使用者雙重約束（Dual Constraint）。
- 設計多輪協定（Multi-turn Protocol）與隱藏約束（Hidden Constraint）觸發機制：約束僅在智慧體（Agent）提出違反約束之計畫時才揭露，要求智慧體在累積回饋（Accumulating Feedback）下進行迭代式計畫修正（Iterative Plan Revision）。
- 透過十個領先大型語言模型（LLM）的實驗，證明雙重約束下的適應性規劃仍具高度挑戰性（最佳準確率（Accuracy）僅 67.75%），並發現使用者約束（User Constraint）、物理基礎（Physical Grounding）與有效性（Effectiveness）為主要瓶頸。

### 適合對象
本論文特別適合從事大型語言模型智慧體（LLM Agent）、自動規劃（Planning）、互動式人工智慧與人機協作研究的學者與工程師；對於設計動態互動式基準測試（Dynamic Interactive Benchmark）、評估智慧體在世界約束（World Constraint）與使用者偏好下之可靠適應（Reliable Adaptation）能力，以及探索多輪協定（Multi-turn Protocol）與迭代式重新規劃（Iterative Re-planning）機制的研究者，尤具參考價值。

## 深度分析

#### 方法論解析

AdaPlanBench 的方法論核心由兩個緊密耦合的元件構成：自動化的 Constraint Construction Pipeline（約束建構流程）與運行期的 Multi-turn Protocol（多輪協定）。

在資料建構階段，研究者以 MacGyver dataset 為基礎，經過篩選與重寫保留 307 條 Household Task（家務任務）查詢。針對每條查詢，系統透過一個 Multi-agent Framework（多智慧體框架）產生 Dual-constraint Profile（雙重約束設定檔）E = (B_w, B_u)。該框架包含六個角色專屬模型（role-specific models）：query rewriter（查詢重寫器, M_rw）、binary filter（二元過濾器, M_flt）、planner（規劃器, M_plan）、extractor（抽取器, M_ext）、merge（合併器, M_merge）與 check（驗證器, M_chk）。其中，World Constraints（世界約束, B_w）捕捉環境限制，例如 Tool Availability（工具可用性）與 Resource Limitation（資源限制）；User Constraints（使用者約束, B_u）則編碼具體的個人 Preference（偏好）與 Priority（優先順序）。此設計保留了 Open-Ended Evaluation（開放式評估）特性——任何滿足約束的解皆被接受——同時維持實質上無界的 Action Space（動作空間）與 Solution Space（解空間）。

在 Runtime Protocol（運行期協定）中，Hidden Constraints（隱藏約束）於初始階段完全保留，不直接揭露給 Agent（智慧體）。在每一回合 t，Agent 根據目前所知提出計畫 P_t，由 Judge LLM 檢查是否觸發 Constraint Violation（約束違反）。若計畫違反特定約束，系統僅回傳該違反項目的部分回饋，而非完整約束集合。Agent 必須根據 Accumulating Feedback（累積回饋）進行 Iterative Re-planning（迭代式重新規劃），持續從片段回饋中推論並追蹤尚未揭露的 Implicit Constraints（隱式約束），並在下一回合 t+1 提出修正後的計畫。此機制強制要求 Agent 具備從部分回饋中 Infer and Track Constraints（推論與追蹤約束）的能力，並在動態變化的約束集合下執行 Reliable Adaptation（可靠適應），形成對持續互動（Sustained Interaction）中雙重結構的嚴格檢驗。

#### 實驗數據解讀

本研究評估了十個頂尖的 open-source 與 proprietary LLMs（大型語言模型）。整體結果顯示，即便是最強大的模型，其 Accuracy（準確率）也僅達 67.75%，而 open-weight 模型通常落在 30% 或更低。這項數據凸顯了 Dual Constraints（雙重約束）下的 Interactive Planning（互動式規劃）對現有 LLM Agents（大型語言模型智慧體）而言仍是重大挑戰。

進一步的趨勢分析揭示，隨著 Progressive Constraint Disclosure（漸進式約束揭露）的進行，約束在軌跡上不斷累積，Planning（規劃）品質隨之下降。特別值得注意的是，User Constraints（使用者約束）相較於 World Constraints（世界約束）對模型造成更大的困難。即使引入 explicit constraint tracking 或 rubric-based feedback，也無法顯著緩解效能衰退，暗示當前的困難並非單純源自記憶或提示設計的不足，而是更深層的推理架構問題。

在失敗模式分析上，研究發現當 Dual Constraints（雙重約束）累積時，錯誤計畫往往伴隨兩大特徵：一是 Effectiveness（有效性）降低，即計畫無法有效達成原始目標；二是 Physical Grounding（物理基礎）薄弱，表示模型對物理世界的因果與工具運作理解不足。這兩項發現為後續改善 LLM Agents 的務實推理能力提供了明確的診斷方向。

#### 與現有研究的比較

透過 Table 1 的七維度比較可以清楚看出，AdaPlanBench 是首個同時滿足 Iterative Re-planning（迭代式重新規劃）、User Interaction（使用者互動）、World Interaction（世界互動）、Dual Constraint（雙重約束）、Progressive Disclosure（漸進式揭露）、Open-Ended Evaluation（開放式評估）與 Scalable（可擴充性）七項特性的基準測試。

相較之下，CostBench 支援 World Interaction 與 Scalable Constraints，但缺乏 Progressive Disclosure 與 User Interaction；FlowBench 具備 Dual Constraint 與 Progressive Disclosure，卻不支援 Open-Ended Evaluation 與 Scalable Constraints；NaturalPlan、PrefEval、RealPref、UserBench、PersonaMem-v2、τ-Bench、τ²-Bench 與 TravelPlanner 等基準測試則各自在不同維度上有所欠缺，且絕大多數僅聚焦於 User Constraints 或 World Constraints 的單一面向。AdaPlanBench 填補了「聯合處理雙重約束」這一研究空白。

從方法論設計觀察，潛在侷限包括：首先，任務領域目前侷限於 Household Task（家務任務），雖然這類任務天然蘊含 World 與 User Constraints，但其物理規則與偏好型態是否能直接遷移至其他領域（如 Scientific Discovery（科學發現）或軟體工程）仍需驗證。其次，Constraint Construction Pipeline（約束建構流程）與 Judge LLM 均高度依賴自動化的語言模型，可能引入系統性偏差或標註不一致性。最後，雖然 Action Space 開放，但底層資料來自 MacGyver dataset，其解題型態可能無法涵蓋所有真實世界 Task Execution（任務執行）情境的複雜度。

#### 可重現性評估

就現有文本而言，本研究標註為 Preprint（預印本）且 Under Review（審查中），尚未提供明確的開源程式碼、資料集釋出連結或模型權重下載資訊。儘管作者詳細描述了 Multi-agent Framework 的六個角色分工、Runtime Protocol（運行期協定）的狀態轉換邏輯，以及基於 MacGyver dataset 的資料篩選標準，這些細節在方法論層面有助於復現，但實際的提示詞（prompts）、約束設定檔與 Judge LLM 的評分 rubric 並未在提供的片段中完整揭露。

從正面角度看，Constraint Construction Pipeline 被強調為 Scalable（可擴充性）且自動化，理論上只要取得原始 MacGyver 資料並依循所述流程，即可重新生成 Dual Constraints（雙重約束）。然而，完整的可重現性仍取決於作者後續是否公開實作細節與互動式評估環境。在缺乏這些資源的情況下，其他研究者僅能依據論文描述進行近似復現，難以確保結果的完全一致。

#### 未來研究方向

基於 AdaPlanBench 所揭示的挑戰，未來研究可朝以下方向推進：

第一，發展更強大的記憶與推理架構，以處理 Accumulating Feedback（累積回饋）與長期約束追蹤。當前模型在約束累積後效能顯著衰退，顯示現有的 context window 利用方式與工作記憶機制不足以應對動態揭露的隱式約束。

第二，強化 Physical Grounding（物理基礎）與 Effectiveness（有效性）。由於失敗常根源於對物理世界因果關係的誤解，未來可探索結合外部物理模擬器、知識圖譜或符號規劃器（symbolic planner）的混合式架構，以彌補純粹 LLM 推理在物理常識上的不足。

第三，針對 User Constraints（使用者約束）的專門建模。實驗顯示使用者偏好與優先順序對模型難度最高，未來可發展專門的偏好推論模組，或利用反事實推理（counterfactual reasoning）來提升對主觀約束的適應能力。

第四，將評估框架擴展至 Household Task 以外的領域，例如 Computer Operation（電腦操作）或 Complex Code Generation（複雜程式碼生成），以驗證方法論在跨領域 External World（外部世界）互動中的泛化性。

第五，縮小 open-weight 與 proprietary 模型之間的效能差距。開源模型僅達 30% 準確率，顯示在資源受限情境下部署具備 Adaptive Planning（適應性規劃）能力的 LLM Agents 仍有極大進步空間，可能需要透過專門的後訓練（post-training）或合成資料微調來提升。

第六，改進 Progressive Disclosure（漸進式揭露）的回饋機制。研究發現即使用明確的 rubric-based feedback 也難以緩解效能下降，暗示需要更細緻的回饋設計，例如分層式揭露（hierarchical disclosure）或主動式探詢（Proactive Exploration（主動探索）），讓 Agent 能更高效地探索隱藏約束空間。

## 論文問答

**Q1：AdaPlanBench 旨在解決什麼核心問題？**
A：AdaPlanBench 旨在解決大型語言模型智慧體在真實世界規劃中，同時面對世界約束與使用者約束的核心挑戰。這些約束往往並非預先完整給定，而是在互動過程中漸進式揭露，導致智慧體必須持續適應與重新規劃。然而，現有的基準測試通常只探討單一類型的約束，缺乏對雙重約束下適應性規劃的嚴謹評估，因此本研究透過建立動態互動式基準測試來填補此缺口。

**Q2：為何現有的基準測試無法充分評估適應性規劃能力？**
A：現有的基準測試大多僅聚焦於使用者約束或世界約束的其中一方，未能同時涵蓋這兩種緊密交織的互動維度。此外，這些測試通常缺乏漸進式約束揭露與迭代式重新規劃的機制，無法模擬真實情境中約束隨互動逐步浮現的過程。因此，它們無法有效衡量智慧體在累積回饋下推論、追蹤並修正計畫的動態適應能力。

**Q3：為何評估雙重約束下的適應性規劃對 LLM 智慧體至關重要？**
A：真實世界的任務執行本質上具有雙重結構，智慧體必須同時與外部世界互動以獲取資訊與執行動作，並與使用者互動以推斷目標與偏好。這意味著智慧體在規劃時必須同時考量工具可用性與資源限制等世界約束，以及個人偏好與優先順序等使用者約束。若無法可靠地適應這兩類動態揭露的約束，LLM 智慧體將難以在複雜的開放式環境中完成需要持續互動的多步驟任務。

**Q4：AdaPlanBench 的核心方法架構為何？**
A：AdaPlanBench 以 MacGyver 資料集中篩選出的 307 項家務任務為基礎，透過可擴充的自動化多智慧體框架為每項任務建構世界約束與使用者約束的雙重約束設定檔。在評估階段，系統採用多輪協定，初始時隱藏所有約束，僅在智慧體提出的計畫違反某項約束時才予以揭露。這種設計迫使智慧體在累積回饋中進行迭代式計畫修正，從而測試其推論隱藏約束與持續重新規劃的能力。

**Q5：AdaPlanBench 在運行時協定上的關鍵創新是什麼？**
A：其關鍵創新在於「違反才揭露」的漸進式約束揭露機制，系統會主動隱藏約束，直到智慧體的計畫觸犯規則時才提供部分回饋。這要求智慧體必須從有限的負面回饋中推論潛在的隱式約束，並持續追蹤已揭露的違規事項以調整後續決策。相較於傳統預先給定所有條件的靜態評估，此協定更貼近真實世界中約束隨互動逐步浮現的動態特性。

**Q6：作者為何選擇以 MacGyver 資料集的家務任務作為基礎？**
A：家務任務領域天然地同時蘊含世界約束與使用者約束，例如環境中的工具限制與個人的物品偏好，非常符合雙重約束的研究設定。這些任務保留了廣大且實質上無邊界的動作空間，允許任何滿足約束條件的解決方案，從而支援開放式評估。此外，家務情境貼近日常生活，易於理解且具備良好的可擴充性，適合作為建構動態互動式基準測試的根基。

**Q7：實驗中評估了哪些模型，整體表現如何？**
A：研究團隊評估了十個頂尖的開源與專有大型語言模型，涵蓋不同架構與規模的模型。實驗結果顯示，即使是最強大的模型，其準確率也僅達到 67.75%，顯示雙重約束下的適應性規劃仍是極具挑戰性的任務。至於開源權重模型，其表現通常僅在 30% 或更低，反映出目前多數 LLM 智慧體在動態約束環境中的規劃能力仍有顯著不足。

**Q8：關於約束累積對效能的影響，實驗有哪些關鍵發現？**
A：實驗發現，隨著漸進式揭露的約束在互動軌跡中不斷累積，智慧體的規劃品質越來越難以維持，整體表現隨約束負擔增加而明顯下降。特別值得注意的是，使用者約束相較於世界約束帶來了更大的挑戰，對模型效能的負面影響更為顯著。這項結果凸顯了智慧體在面對多重要求與個人偏好時，難以持續進行有效推論與計畫調整的困境。

**Q9：失敗分析進一步揭示了智慧體在哪些面向存在弱點？**
A：進一步分析顯示，在雙重約束累積的情況下，規劃失敗往往伴隨著目標有效性降低與物理基礎變弱的現象，例如提出不符合物理現實或無法達成目標的步驟。研究也發現，單純引入顯式約束追蹤或基於評分標準的回饋機制，並無法輕易緩解這些挑戰。這暗示當前 LLM 智慧體不僅難以維持對物理世界的穩固理解，也在高負載的約束條件下逐漸喪失計畫的有效性。

**Q10：AdaPlanBench 測試的能力在哪些實際應用場景中至關重要？**
A：此基準測試評估的能力對於家庭服務機器人尤其關鍵，這類智慧體必須在使用者偏好與家中實際環境限制下完成打掃、烹飪等家務。同樣地，在客戶服務或行程規劃領域，智慧體也必須同時遵守企業政策或法規等世界約束，以及滿足客戶的個人偏好等使用者約束。任何需要在物理環境中與人持續互動、並根據動態回饋調整行動的 AI 系統，都必須具備此處測試的適應性規劃能力。

**Q11：AdaPlanBench 對開發互動式 LLM 智慧體的產品設計有何啟示？**
A：開發者應設計能夠跨多輪對話持續追蹤推論約束的系統架構，而非僅依賴單輪規劃後直接執行。產品設計必須同時處理隱式的使用者偏好與物理世界的限制，並建立有效的機制讓智慧體從負面回饋中學習與調整。此外，鑑於目前頂尖模型的準確率仍有限，在部署於高風險或約束繁複的真實環境前，仍需顯著的技術突破與安全機制設計。

**Q12：AdaPlanBench 可能對 LLM 智慧體研究領域帶來什麼影響？**
A：AdaPlanBench 為雙重約束下的互動式規劃建立了嚴謹的測試平台，使研究者能夠系統性地衡量與比較不同模型的動態適應能力。它明確揭示了當前 LLM 智慧體在面對漸進式揭露約束時的能力缺口，從而激勵社群發展能夠動態規劃、適應與修正的下一代模型。長遠而言，此基準測試有助於推動更可靠、更具物理基礎且更貼近真實世界需求的智慧體研究。

**Q13：AdaPlanBench 的研究範疇與設計存在哪些局限？**
A：目前 AdaPlanBench 的任務主要集中於家務領域，雖然約束建構流程具備可擴充性，但其他領域的通用性仍需進一步驗證。自動化產生的雙重約束雖能規模化，卻可能難以完整捕捉真實世界中所有語境依賴且高度細緻的隱式約束。此外，評估機制高度依賴大型語言模型擔任裁判與互動環境，這可能引入模型內生的偏誤與評估上的不確定性。

**Q14：LLM 智慧體在 AdaPlanBench 上最常見的失敗模式為何？**
A：最常見的失敗模式包括智慧體無法從累積回饋中正確推論與追蹤隱藏約束，導致反覆提出違反相同規則的計畫。其次，許多失敗案例顯示智慧體的物理基礎薄弱，提出的解決方案在現實中不可行或缺乏物理可信度。此外，隨著約束數量增加，智慧體往往難以維持原始目標的有效性，產生偏離使用者需求或無法完成任務的次優計畫。

**Q15：AdaPlanBench 指出了哪些未來研究方向？**
A：未來研究可著重於增強智慧體的物理基礎理解能力，使其在面對世界約束時能提出更具物理可信度的計畫。同時，需要開發更強大的約束推論與長期追蹤機制，以改善智慧體在使用者約束累積時的適應表現。此外，將此動態互動框架擴展至家務以外的領域，並結合主動探索策略以更有效率地揭露隱藏約束，亦是極具潛力的研究方向。

## 實務應用指南

### 適用場景

**1. 智慧家庭與服務機器人**
當家用機器人執行家務任務時，必須同時面對世界約束（如工具損壞、清潔劑存量不足）與使用者約束（如偏好無噪音時段、禁用特定化學品）。透過漸進式揭露約束的互動設計，機器人可在提出初步計畫後，根據環境與使用者的回饋迭代式重新規劃，而非一次性要求使用者完整列出所有限制。

**2. 企業數位助理與流程自動化**
企業內部的 LLM 智慧體在協助員工完成跨系統任務（如申請差旅、採購流程）時，需適應動態的 IT 環境限制（系統維護中、權限不足）與主管或員工的個人偏好（優先順序、預算上限）。採用 AdaPlanBench 的多輪協定，可讓智慧體在提案後逐步發現隱藏約束，並動態調整執行路徑。

**3. 醫療與長期照護排程系統**
照護規劃涉及嚴格的世界約束（藥物交互作用、醫療設備可預約時段）與高度個人化的使用者約束（病患飲食偏好、家屬探視時間限制）。由於這些約束往往無法在對話初期完整收集，適應性規劃系統必須能在互動中推論與追蹤約束，並持續修正照護計畫。

**4. 個人化旅遊與生活規劃助理**
旅遊規劃助理需處理動態的外部世界條件（航班取消、景點臨時休館）與旅客的隱式偏好（避免紅眼班機、偏好步行距離內的景點）。透過雙重約束的漸進式揭露，助理可在每次推薦後根據使用者的否定回饋（「這間飯店太貴」「我不想搭地鐵」）累積回饋並重新規劃。

**5. 客戶支援與爭議處理智慧體**
在客戶服務場景中，智慧體必須遵守公司政策（世界約束：退換貨期限、補償上限）與客戶的個人訴求（使用者約束：堅持全額退款、要求特定補償方式）。這些約束通常在多輪對話中才會浮現，需要智慧體具備從拒絕與反饋中推論隱藏約束的能力。

### 實作前置條件

**資料層面**
- **領域任務語料**：需蒐集開放式、多步驟的任務描述（如論文採用的 MacGyver 家務任務），作為規劃基礎。
- **雙重約束資料集**：需具備世界約束（環境限制、工具可用性）與使用者約束（偏好、優先順序）的結構化資料，或能透過多智慧體框架自動生成。
- **環境模擬器或工具 API**：用於驗證計畫的物理基礎與有效性，確保規劃不只是文字生成，而是可執行的動作序列。

**運算層面**
- **多輪互動推理預算**：由於採用漸進式揭露，單一任務可能涉及 3–10 輪以上的 LLM 呼叫，需預留充足的推理 token 配額與低延遲推理叢集。
- **Judge LLM 評估資源**：需要獨立的評估用 LLM（或規則引擎）作為約束裁判（Constraint Judge），用於檢查計畫是否違反隱藏約束並產生回饋。

**技術與人力層面**
- **提示工程與智慧體框架設計**：熟悉 ReAct、Reflexion 等互動式規劃框架，能設計具備工作記憶（Working Memory）的智慧體架構。
- **約束推論與追蹤機制**：需具備將自然語言回饋轉換為結構化約束表示的能力，並在後續輪次中避免重複違反。
- **開放式評估設計能力**：由於解空間極大，需設計基於評分標準（Rubric）的自動化評估流程，而非僅依賴單一正確答案。

### 實作步驟建議

**步驟一：領域任務篩選與改寫**
從目標領域蒐集開放式任務查詢（Query），並進行改寫與過濾，確保任務具備明確目標但允許多種達成路徑。任務應保留大且實質上無界的動作空間，避免淪為單一正確答案的封閉式問題。

**步驟二：自動化雙重約束建構**
參考論文的多智慧體框架，建立專屬模型角色：
- **規劃器（Planner）**：生成候選解決方案，作為約束誘導的基礎。
- **約束萃取器（Extractor）**：從候選方案中歸納可能的世界約束（如資源限制、物理規則）與使用者約束（如偏好、優先順序）。
- **合併與驗證器（Merge & Check）**：確保約束彼此不矛盾，且與原始任務語境一致。

**步驟三：設計漸進式揭露互動協定**
建立運行期多輪協定：
1. 智慧體根據目前所知提出計畫 \(P_t\)。
2. **約束裁判（Constraint Judge）** 檢查 \(P_t\) 是否違反任何尚未揭露的隱藏約束。
3. 若存在違反，僅揭露被違反的約束（而非全部），並要求智慧體重新規劃。
4. 重複直到計畫通過所有約束或達到最大輪次上限。
此設計強迫智慧體從部分回饋中推論，而非一次性獲得完整資訊。

**步驟四：建構具記憶與重新規劃能力的智慧體**
智慧體核心需包含：
- **約束記憶模組**：明確記錄已揭露的世界約束與使用者約束，避免遺忘。
- **推論模組**：從裁判回饋中推論潛在的隱含約束（例如連續兩次因「噪音」被拒，應推論使用者偏好安靜方案）。
- **重新規劃引擎**：在每次收到新回饋後，基於累積約束集合生成新計畫，而非僅做局部修補。

**步驟五：建立評估與持續迭代機制**
上線前應以類似 AdaPlanBench 的指標進行壓力測試：
- **準確率（Accuracy）**：最終計畫是否滿足所有約束。
- **物理基礎（Physical Grounding）**：計畫中的動作是否在現實中可行。
- **有效性（Effectiveness）**：計畫是否確實達成原始目標。
針對約束累積導致的效能衰退進行分析，並透過增加範例或微調改善使用者約束的處理能力。

### 潛在風險與注意事項

**約束累積導致的效能衰退**
論文顯示，隨著漸進式揭露的約束不斷累積，所有模型的準確率皆顯著下滑。**緩解措施**：引入顯式約束追蹤（Explicit Constraint Tracking），將已揭露約束結構化為檢查清單（Checklist），在每次重新規劃前強制驗證；或採用分段驗證策略，先確認子目標可行性再擴展至完整計畫。

**使用者約束的隱含性與主觀性**
使用者約束（如偏好、情緒、優先順序）比世界約束更難推論，且容易因文化或語境而異。**緩解措施**：設計主動澄清機制（Active Clarification），當智慧體對某條回饋信心不足時，應以選擇題或確認句向使用者求證，而非盲目猜測。

**物理基礎不足導致的無效計畫**
模型常產生看似合理但實際不可行的計畫（如使用已損壞的工具）。**緩解措施**：將智慧體與外部模擬器、知識圖譜或工具 API 綁定，在規劃階段即驗證動作的可執行性；或引入「世界模型」模組進行預演。

**幻覺與虛構約束**
智慧體可能在重新規劃時過度解讀回饋，甚至發明不存在的約束，導致解空間被過度限縮。**緩解措施**：建立約束來源追溯機制，區分「已確認約束」與「推論約束」，並對後者設定較低的決策權重。

**多輪互動的成本與延遲**
每增加一輪重新規劃，即增加一次 LLM 呼叫與裁判驗證成本。**緩解措施**：設定早期終止條件（Early Stop），當連續多輪無顯著進展時改由人工接管；或採用較小的模型處理初步規劃，僅在最終驗證階段呼叫最強大的模型。

### 與其他技術的整合建議

**向量資料庫與 RAG 用於約束記憶**
在多輪互動中，已揭露的約束數量可能龐大。建議將每條約束向量化後存入向量資料庫，並在重新規劃前透過 RAG（Retrieval-Augmented Generation）召回相關約束，避免上下文長度不足導致的遺忘。對於高度結構化的世界約束，可輔以圖資料庫（Graph DB）管理因果關係。

**符號規劃器處理世界約束**
對於明確的物理限制與資源限制（世界約束），可將其轉譯為 PDDL 或其他符號規劃語言，由傳統 AI 規劃器處理；LLM 則專注於理解使用者約束與生成高層次策略。此混合架構可顯著提升物理基礎，並減少純神經規劃的幻覺風險。

**RLHF 與線上學習適應使用者偏好**
論文指出使用者約束是主要瓶頸。建議在系統上線後收集互動軌跡，透過 RLHF（Reinforcement Learning from Human Feedback）或 DPO（Direct Preference Optimization）微調模型，使其更擅長從少數回饋中推論個人偏好，降低對多輪試錯的依賴。

**工具使用框架增強物理基礎**
整合 LangChain、MCP（Model Context Protocol）或類似工具框架，讓智慧體在規劃過程中能查詢外部狀態（如庫存系統、日曆 API、感測器數據）。這將部分世界約束從「隱藏」轉為「可查詢」，降低推論難度。

**可觀測性平台追蹤互動軌跡**
部署 LangSmith、Langfuse 或自研觀測平台，記錄每一輪的計畫 \(P_t\)、裁判回饋與約束揭露事件。這對於上線後診斷「為何智慧體在特定約束組合下持續失敗」至關重要，也能作為後續建構自動化約束建構流程的訓練資料。

### 給不同背景讀者的閱讀建議

**初學者**
建議從論文的圖一與表一開始，先理解「雙重約束」與「漸進式揭露」的核心概念：真實世界的任務通常同時存在環境限制與人的偏好，而且這些限制不會一次說清楚。接著閱讀摘要與第 1 節的動機，無需深入技術細節，重點掌握「為何現有的單一約束基準測試無法評估真實互動場景」即可。

**AI 工程師**
請聚焦第 2 節的資料建構流程與運行期協定。重點理解多智慧體框架中各角色（Rewriter、Filter、Planner、Extractor、Merge、Check）如何協作生成約束，以及 Constraint Judge 的設計邏輯。實作時請特別參考論文關於「顯式約束追蹤」與「回饋累積」的發現，這直接影響智慧體的記憶體設計與重新規劃策略。

**研究人員**
建議深入分析實驗結果中「約束累積導致效能衰退」與「使用者約束特別困難」的現象。論文指出失敗常伴隨物理基礎薄弱與有效性下降，這暗示未來研究可朝向混合神經-符號規劃、更強大的世界模型、或針對隱式偏好推論的專門架構發展。AdaPlanBench 的開放式評估設計也提供了擴展至其他領域（如軟體工程、科學實驗）的基礎。

**產品經理**
請將閱讀重點放在適用場景與準確率數據：即使是最強大的模型，在雙重約束下的準確率也僅約 68%，開源模型更低於 30%。這代表在產品設計上，「完全自動化的適應性規劃」目前仍不可行，必須保留人工介入點（Human-in-the-Loop）、設定明確的重新規劃輪次上限，並優先將此技術應用於錯誤成本較低、可回滾的場景（如旅遊規劃、家務建議），而非高風險的醫療或財務決策。
