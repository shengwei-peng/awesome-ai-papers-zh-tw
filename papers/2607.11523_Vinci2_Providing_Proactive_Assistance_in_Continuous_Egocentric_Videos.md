## 摘要翻譯

智慧助理（Intelligent Assistant）應該在何時主動開口？連續性第一人稱視角影片（Continuous Egocentric Video）提供了豐富且不斷變化的情境，促成了一種新型態的協助：主動式協助（Proactive Assistance）而非僅止於反應式（Reactive）。然而，現有方法要不是被動等待使用者查詢（User Query），就是將每個偵測到的事件（Detected Event）都視為需要回應，而未考量使用者歷史（User History）、當前活動（Current Activity），或協助是否真正受歡迎。我們將主動式協助重新框架為依情境決策問題（Context-Dependent Decision Problem）：智慧代理不僅必須感知（Perception）正在發生的事，還須根據累積時間情境（Accumulated Temporal Context）進行推理（Reasoning），以決定何時以及是否介入（Intervention）。為此，我們提出 Vinci2，一個主動式第一人稱視角協助系統，使裝置端助理（On-Device Assistant）Vinci 從反應式回應邁向主動式協助。在評估方面，我們提出 EgoServe，首個針對連續性第一人稱視角影片中主動式協助的大規模基準（Large-Scale Benchmark）。EgoServe 包含超過 3,000 個服務實例（Service Instances），依 4 種時間記憶範圍（Temporal Memory Horizons）組織，橫跨 10 個服務類別（Service Categories），範圍從即時的安全警示（Safety Alerts）到長期的習慣輔導（Habit Coaching）。在建模方面，我們提出 EgoMemo，一個免訓練（Training-Free）的記憶增強型智慧代理（Memory-Augmented Agent），維護三種互補的記憶表徵：多尺度時間摘要（Multi-Scale Temporal Summaries）、語義知識圖譜（Semantic Knowledge Graph），以及視覺嵌入檔案庫（Visual Embedding Archives）。在每個時間步驟（Timestep），EgoMemo 執行檢索增強推理（Retrieval-Augmented Reasoning），以判斷是否應提供協助；若是，則產生具情境根據的回應（Contextually Grounded Responses）。實驗顯示，EgoMemo 在 EgoServe 上建立了強大的基線（Baselines），同時在現有的第一人稱視角基準（Egocentric Benchmarks）上仍具競爭力。我們的基準與程式碼已公開於 https://sitonggong.github.io/EgoServe-page/{Vinci2}。

### 核心貢獻（3～5點）
- 提出主動式第一人稱視角協助系統 Vinci2，將前代裝置端助理 Vinci 從反應式回應擴展至主動式協助典範。
- 建立首個針對連續性第一人稱視角影片主動式協助的大規模基準 EgoServe，涵蓋 3,000 個以上服務實例、4 種時間記憶範圍與 10 種服務類別。
- 提出免訓練的記憶增強型智慧代理 EgoMemo，透過多尺度時間摘要、語義知識圖譜與視覺嵌入檔案庫進行檢索增強推理。
- 在 EgoServe 與現有第一人稱視角基準上驗證，建立強大基線並展現競爭力。

### 適合對象
適合對串流視覺感知、主動式協助／對話、第一人稱視角基礎模型、記憶增強型代理，以及穿戴式智慧助理（如智慧眼鏡）與長期行為輔導應用有興趣的研究者與工程師。

## 深度分析

#### 方法論解析

Vinci2 將主動式協助（proactive assistance）重新定義為一個「連續影片串流上的聯合決策與生成（joint decision-and-generation）」問題。給定第一人稱視角影片（egocentric video）串流 \(V=\{v_1,v_2,\dots\}\)，智慧代理（agent）在每個時間步 \(t\) 觀察到當前片段 \(v_t\) 後，必須同時做出兩件事：（1）判斷此刻是否值得介入（intervention）或應保持沉默（remain silent）；（2）若決定介入，則生成與當前及歷史情境緊密相連的回應。這與傳統反應式典範（reactive paradigm）僅回應使用者查詢（user query），以及半主動式典範（semi-proactive paradigm）依預先給定的明確指令（explicit instruction）觸發回應有本質區別。

為了支撐這個決策過程，作者提出 EgoMemo，一個免訓練（training-free）的記憶增強型智慧代理（memory-augmented agent）。其核心設計是維護三種互補的記憶表徵：

1. 多尺度時間摘要（multi-scale temporal summaries）：從最細粒度的片段層級描述，到中層的活動摘要，再到最粗粒度的整段會話摘要，形成層次化結構。這讓代理能依問題需求選擇適當的時間粒度進行檢索。
2. 語義知識圖譜（semantic knowledge graph）：編碼實體關係與活動模式，例如「使用者經常在煮飯前先洗手」或「某個工具通常放在某處」，支援關係型與常識型推理。
3. 視覺嵌入檔案庫（visual embedding archives）：儲存歷史畫面的視覺嵌入向量（visual embeddings），用於相似度檢索，找回與當前畫面視覺上相似的過去時刻。

在每個時間步，EgoMemo 並非直接對完整影片進行推理，而是先評估當前觀察是否可能觸發協助；若需要更深層的情境，則從上述三種記憶庫中檢索相關資訊，再透過檢索增強推理（retrieval-augmented reasoning）產生決策與回應。值得注意的是，EgoMemo 的記憶建構與檢索都是完全串流（streaming）進行的，這對連續性第一人稱視角影片（continuous egocentric video）的即時應用至關重要。此外，系統還包含一個以視覺語言模型（Vision-Language Model, VLM）為基礎的標題重建（caption reconstruction）步驟，用於彌補結構化檢索結果與自然語言推理所需的情境描述之間的資訊落差。

整體而言，Vinci2 可視為前代裝置端助理（on-device assistant）Vinci 的延伸：從單純的反應式回應進化到真正的主動式典範（proactive paradigm）。系統由兩大互補元件組成：評估用的 EgoServe 基準測試（benchmark）與建模用的 EgoMemo 代理。

#### 實驗數據解讀

EgoServe 是第一個針對連續第一人稱視角影片中主動式協助所設計的大規模基準測試（large-scale benchmark）。它建立在 EgoLife、HoloAssist 與 CaptainCook4D 三個現有資料集之上，涵蓋多種日常活動（daily activities）、多位使用者，以及從數分鐘到數小時的延伸時間情境（extended temporal contexts）。該基準包含超過 3,000 個服務實例（service instances），並依據所需的時間記憶範圍（temporal memory horizons）劃分為四個層級：從即時的安全警示（safety alerts），到短期提醒、中期活動輔助，再到長期的習慣輔導（habit coaching）。同時，這些實例又歸類為 10 個服務類別（service categories），以評估代理在不同協助情境下的泛化能力。

由於提供的全文片段未包含實驗表格與完整指標定義，以下指標為根據任務形式與相關文獻的合理推論。評估主動式協助時，至少應包含兩個層面：

- 決策層面：代理是否正確判斷該介入或保持沉默。常用指標可能包括介入的精確率（precision）、召回率（recall）、F1 分數，以及誤報率（false alarm rate）與沉默準確率。
- 生成層面：介入時產生的回應是否與情境一致、具備情境根據（contextually grounded），並避免幻覺（hallucination）。可能採用 BLEU、ROUGE、CIDEr，或針對 groundedness 與 helpfulness 的人工評分。

作者指出，EgoMemo 在 EgoServe 上建立了強大的基線（baselines），並在現有的第一人稱視角基準測試上保持競爭力。這一結果的意義在於：EgoMemo 是免訓練的，僅透過記憶機制（memory mechanisms）與檢索增強推理即可達到可觀表現，顯示主動式協助在無需大規模微調的情況下已具可行性。然而，缺乏詳細數據使我們無法判斷其在四個時間記憶範圍上的相對強弱，也無法得知不同服務類別間的表現差異。

#### 與現有研究的比較

Vinci2 與 EgoMemo 的定位可從三個研究軸線來理解：

1. 相對於影片大型語言模型（Video-LLMs）與串流理解基準（streaming comprehension benchmarks）：現有 Video-LLMs 多屬反應式典範，僅在使用者提問後回應；串流理解基準（如 OVO-Bench）雖評估連續串流上的時間理解，但並未評估「是否該主動介入」的決策。EgoServe 與 EgoMemo 填補了這一缺口。

2. 相對於事件觸發式系統（event-triggered systems）與半主動式方法：StreamBridge、EWO、ProAssist 以及前代 Vinci 等系統雖具備某種程度的主動性，但它們通常需要使用者預先提供明確指令（explicit instruction），並將「事件偵測（event detection）」直接等同於「介入決策」。這忽略了兩個關鍵問題：當前情境是否真的需要打斷使用者，以及系統是否具備長期歷史觀察（long-horizon historical observations）來做出判斷。EgoMemo 則將介入視為一個顯式的推理結果，並以累積時間情境（accumulated temporal context）為條件。

3. 相對於記憶導向的影片代理（memory-based video agents）：MovieChat、MA-LMM、VideoAgent、VideoRAG、Vgent、WorldMM 等方法雖引入多類型記憶與圖結構索引，但多假設可離線存取完整影片，且未處理主動介入決策。EgoMemo 的差異在於記憶建構與檢索皆為串流，並結合主動決策與 VLM 標題重建。

4. 相對於語言導向的主動代理：ProAgent、ContextAgent、SensibleAgent、ProAgentBench 等研究聚焦於語言或多代理合作，或僅使用短時間範圍的可穿戴感測器訊號。Vinci2 則專注於連續第一人稱視角影片，強調長期記憶與跨時間範圍的時間推理（temporal reasoning）。

儘管如此，本研究仍存在若干限制。首先，免訓練（training-free）設計雖降低部署門檻，但也可能限制代理對使用者個人習慣與偏好的適應能力。其次，決策是否介入可能高度依賴啟發式閾值或提示設計，對不同使用者或文化情境的泛化性有待驗證。第三，EgoServe 的服務實例來自已公開資料集的註釋，雖具規模，但是否能真實反映使用者在實際穿戴裝置上對「被打斷」的容忍度，仍需進一步的使用者研究確認。最後，視覺嵌入與知識圖譜的建構品質會直接影響檢索增強推理的效果，若底層 VLM 產生錯誤描述，錯誤可能沿著記憶鏈傳播。

#### 可重現性評估

根據摘要，本研究的程式碼與 EgoServe 基準測試已公開於 https://sitonggong.github.io/EgoServe-page/{Vinci2}。由於 EgoMemo 是免訓練的記憶增強型智慧代理，理論上無需釋出額外的模型權重，只需提供記憶建構、檢索與決策流程的程式碼、提示詞（prompts）與超參數，即可在具備適當 VLM/LLM 的環境中重現。EgoServe 的底層資料來自 EgoLife、HoloAssist 與 CaptainCook4D，這些資料集若已公開，則有助於其他研究者複製訓練與測試流程。

然而，可重現性也取決於幾項未在片段中詳細說明的因素：實際使用的 VLM/LLM 版本與大小、API 或本地推理設定、記憶更新頻率、檢索時的 top-k 與相似度閾值、以及決策提示詞的完整內容。此外，論文宣稱 Vinci2 是裝置端助理（on-device assistant），但裝置規格、延遲測量方式與能耗數據若未充分揭露，將影響其他研究者在不同硬體上重現「on-device」宣稱的難度。最後，公開連結中的 `{Vinci2}` 看起來像是佔位符，實際可用網址需以論文正式發表版本為準。

#### 未來研究方向

Vinci2 與 EgoServe 為主動式第一人稱視角助理開闢了多條後續研究路徑：

1. 學習式介入決策：目前 EgoMemo 採用免訓練的檢索增強推理，未來可引入強化學習（reinforcement learning）或從人類回饋中學習（RLHF），根據使用者的明確或隱式回饋（如忽略、採納、打斷頻率）來優化介入時機與方式。

2. 個人化長期記憶：將使用者歷史（user history）、目標（user goals）與習慣更細緻地編碼進語義知識圖譜，並支援持續學習與遺忘機制，使助理能隨時間適應個別使用者。

3. 多模態情境融合：除了視覺串流，未來可整合音訊、慣性測量單元（IMU）、生理訊號、行事曆與位置資訊，以提升對當前活動（current activity）與使用者可用注意力狀態的判斷。

4. 真實世界部署與使用者研究：在實際穿戴式裝置或 AR 眼鏡上進行長期使用者研究，評估主觀指標如有用性（helpfulness）、侵擾性（intrusiveness）與信任度，並建立以使用者為中心的介入準則。

5. 記憶效率與裝置端最佳化：研究如何在有限記憶體與運算資源下，進行長期記憶壓縮、摘要更新與快速檢索，以真正實現低延遲的裝置端助理。

6. 因果與反事實推理：特別是針對安全警示類服務，未來可探索因果推理（causal reasoning）與反事實分析，判斷「若不及時提醒，是否會發生危險」，從而降低不必要的打斷。

7. 開放領域主動協助：EgoServe 目前涵蓋 10 個服務類別，未來可擴展至更開放、未預先定義的協助情境，並評估代理在無類別標籤下的自主發現能力。

8. 隱私與可解釋性：由於主動助理持續觀察使用者生活，如何確保資料隱私、提供可解釋的介入理由，並讓使用者能控制助理的積極程度，將是實際落地不可或缺的議題。

## 論文問答

**Q1：什麼是連續性第一人稱視角影片中的主動式協助？為何這個問題值得被重新定義為依情境決策問題？**

A：主動式協助指的是智慧助理無需使用者明確提問，就能根據持續觀察到的第一人稱視角影片內容，主動判斷是否、何時以及如何提供幫助。這與傳統反應式典範僅在使用者查詢後才回應截然不同，也超越了半主動式典範中僅依預先指令監控特定事件的限制。由於使用者的歷史行為、當前活動與長期目標都會影響介入是否恰當，因此這不僅是感知問題，更是需要累積時間情境進行推理的決策問題。

**Q2：現有的反應式與半主動式方法存在哪些根本限制，使它們難以實現真正的主動協助？**

A：反應式影片大型語言模型只能被動等待使用者查詢，無法在使用者未開口時提供及時協助；半主動式的事件觸發式系統雖能監控預定義事件，但通常受限於初始明確指令的範圍，且僅依賴即時視覺情境。這些方法缺乏對長期歷史觀察的推理能力，也沒有機制評估當前情境是否真的值得打斷使用者。因此，它們容易產生過度干預或錯失關鍵協助時機的問題。

**Q3：為什麼連續性第一人稱視角影片特別適合發展主動式智慧助理？**

A：第一人稱視角影片能夠持續捕捉使用者所見的豐富動態情境，從數分鐘到數小時的活動脈絡都蘊含其中，這為理解使用者意圖與習慣提供了獨特資料來源。相較於離線預先分段的影片，連續串流讓助理有機會觀察事件如何隨時間演變，並在關鍵時刻主動介入。這種累積時間情境使助理能夠從單純回答問題，進階到預測需求、提醒安全、輔導習慣等更貼近真實生活的服務。

**Q4：EgoMemo 的核心運作機制是什麼？它如何在每個時間步決定是否介入？**

A：EgoMemo 是一個免訓練的記憶增強型智慧代理，它在每個時間步觀察新的影片片段後，會先判斷當前情境是否需要主動協助。若需要更深入的情境，它會從三種互補的記憶儲存中檢索相關資訊，並透過檢索增強推理產生具情境根據的回應。這種設計讓代理能夠同時處理即時感知與長期記憶，並在應該保持沉默時選擇不介入。

**Q5：EgoMemo 維護的三種記憶表徵各自扮演什麼角色？為何它們被設計為互補？**

A：第一種是多尺度時間摘要，從片段級描述到活動與會話層級摘要，提供不同時間粒度的情境；第二種是語義知識圖譜，編碼實體關係與活動模式，協助理解事物之間的結構化關聯；第三種是視覺嵌入檔案庫，支援基於相似度的檢索，補捉難以用文字描述的視覺細節。這三者互補，因為單一表徵無法同時涵蓋時間層次、語義結構與原始視覺特徵，而結合後能更全面地支援主動決策。

**Q6：作者為何選擇免訓練且完全串流化的記憶建構方式？這帶來哪些實務優勢？**

A：免訓練的設計避免了針對主動協助任務進行大規模微調所需的資料與運算成本，使方法更容易部署於裝置端助理。完全串流化的記憶建構與檢索意味著系統無需等待完整影片，就能持續更新記憶並即時做出決策，這對連續性第一人稱視角影片應用至關重要。此外，這種設計也提升了可擴展性與實用性，讓 EgoMemo 能夠在資源受限的穿戴式裝置上運作。

**Q7：EgoServe 作為首個主動協助基準測試，其規模與結構有何特色？**

A：EgoServe 包含超過 3,000 個服務實例，涵蓋 10 種服務類別，並依據 4 種時間記憶範圍進行組織，從即時安全警示到長期習慣輔導皆有涵蓋。該基準建構於 EgoLife、HoloAssist 與 CaptainCook4D 等資料集之上，橫越多位使用者與多樣日常活動，時間脈絡從數分鐘延伸至數小時。這樣的設計能夠系統性地評估代理在不同時間尺度與協助類型上的主動決策能力。

**Q8：論文報告的主要實驗結果為何？EgoMemo 在現有基準上的表現如何？**

A：實驗顯示 EgoMemo 在 EgoServe 上建立了強大的基線表現，證明免訓練的記憶增強方法已能有效處理主動協助任務。同時，它在現有的第一人稱視角基準測試上仍具競爭力，顯示該架構不僅適用於新提出的主動式設定，也能兼顧傳統的影片理解任務。這些結果支持了檢索增強推理與多記憶表徵在連續串流情境中的可行性。

**Q9：從 EgoMemo 的架構設計可以推論出哪些關於記憶模組貢獻的實驗啟示？**

A：雖然摘要中未詳列各項消融實驗數據，但三種記憶表徵的設計本身就暗示了不同模組對應不同挑戰：多尺度時間摘要對長期活動推理至關重要，語義知識圖譜有助於結構化關係推論，視覺嵌入檔案庫則能補強相似性檢索與細節辨識。未來的消融研究可以驗證移除任一記憶儲存後，代理在特定時間記憶範圍或服務類別上的表現是否顯著下降。這樣的分析將進一步確認每種記憶表徵在實現主動協助時的獨特價值。

**Q10：EgoServe 中的服務類別可對應到哪些真實世界應用場景？**

A：即時安全警示可應用於廚房烹飪時提醒火源未關或刀具使用風險，避免意外發生；中期活動輔助可協助使用者完成組裝家具、遵循食譜步驟或確認是否遺漏流程；長期習慣輔導則能追蹤使用者的日常行為模式，例如提醒保持良好姿勢、規律飲水或減少浪費。這些場景都體現了主動式協助從緊急介入到生活優化的廣泛潛力。

**Q11：將 Vinci2 這類主動式助理產品化時，需要考慮哪些實務挑戰？**

A：首先必須確保使用者隱私，因為持續錄影與記憶儲存涉及高度敏感的個人視覺資料；其次，裝置端運算需兼顧延遲、耗電與儲存空間，才能提供流暢的使用體驗。此外，系統必須精準拿捏介入時機，過度打斷會造成使用者困擾，而漏判關鍵事件則可能帶來安全風險，因此誤報與漏報的平衡是產品設計的核心難題。

**Q12：這項研究可能對第一人稱視角人工智慧與穿戴式裝置領域帶來什麼影響？**

A：Vinci2 將研究焦點從「如何回答問題」轉向「何時主動提供幫助」，推動第一人稱視角助理從反應式走向真正的主動式典範。這對智慧眼鏡、擴增實境裝置與其他穿戴式裝置的發展具有重要意義，因為它們正需要能夠理解長期情境並適時介入的助理。長遠來看，這類技術有望讓穿戴裝置成為更自然、更貼近使用者需求的日常夥伴。

**Q13：從目前的方法描述中，可以推論出哪些潛在限制？**

A：EgoMemo 採用免訓練設計，雖然具備部署彈性，但可能無法針對主動協助任務進行深度最佳化，從而限制其在複雜情境下的上限。此外，系統依賴視覺語言模型進行字幕重建與推理，若基礎模型產生錯誤描述，後續記憶與決策都可能被誤導。記憶儲存的規模與更新機制也可能在長時間運作下面臨累積雜訊與儲存成本的挑戰。

**Q14：主動式協助系統可能出現哪些典型的失敗案例？**

A：常見的失敗包括在不適當的時機介入，例如使用者專注於重要對話時發出瑣碎提醒，造成干擾；另一種是錯誤評估情境嚴重性，導致真正的安全事件被忽略或無關事件被過度放大。此外，系統也可能因記憶檢索不準確而產生與當前情境脫節的建議，甚至出現幻覺式回應，這些都會損害使用者信任。

**Q15：這項工作為未來研究指出了哪些方向？**

A：未來可以探索端到端訓練的主動協助模型，以進一步提升決策與生成的協調性；也可以加入更細緻的使用者偏好學習機制，讓助理能夠根據個人習慣調整介入風格與時機。此外，整合多模態感知、因果推理與使用者回饋迴路，並擴充更大規模與更多元文化背景的基準測試，都是推動主動式第一人稱視角助理走向實用的重要方向。

## 實務應用指南

### 適用場景

1. **智慧眼鏡烹飪助理**  
   使用者在廚房備料與烹調時，Vinci2 可透過連續性第一人稱視角影片追蹤步驟進度，主動提醒「你忘了加鹽」或「這個步驟已經重複第三次，建議縮短拌炒時間」，並根據過往烹飪習慣給出個人化建議。

2. **工業組裝與安全警示**  
   在工廠或維修現場，作業人員配戴穿戴式攝影機，系統可即時偵測危險動作（如未戴護具、操作順序錯誤），並在必要時主動發出安全警示；同時累積長期操作紀錄，協助管理人員進行習慣輔導與再訓練。

3. **高齡者日常生活協助**  
   針對獨居長者，系統可監測日常活動模式，例如是否按時服藥、是否重複進行某項無意義行為，並在異常時主動提醒家屬或發出溫和提示，達到長期健康習慣輔導的目的。

4. **健身與運動姿勢回饋**  
   在健身房或復健場域，Vinci2 可根據連續動作影片即時指出姿勢錯誤，並結合過往訓練紀錄調整建議強度，避免運動傷害並提升訓練效果。

5. **旅遊與導覽主動提示**  
   當使用者在陌生城市行走時，系統可根據視覺情境與過往偏好（例如常造訪的景點類型），主動推薦附近景點、提醒回程時間或指出潛在迷路風險。

### 實作前置條件

- **資料**：需要大量連續性第一人稱視角影片，並依照 EgoServe 的架構標註服務實例，包括是否需要介入、介入時機、回應內容與對應的時間記憶範圍。若無現成資料集，需自行收集並建立標註流程。
- **運算資源**：影片大型語言模型、視覺嵌入模型與語義知識圖譜的建置需要 GPU 伺服器或邊緣運算裝置；若要走裝置端助理路線，需評估模型量化與推理延遲。
- **技術能力**：團隊需具備影片理解、檢索增強生成、提示工程、圖資料庫與串流系統開發經驗；同時需要熟悉隱私保護與人機互動設計。
- **領域知識**：針對特定應用場景（如醫療、工業安全），需要領域專家協助定義介入準則與風險等級。

### 實作步驟建議

1. **定義服務範疇與介入策略**  
   先與領域專家與潛在使用者討論，列出需要主動式協助的服務類別，並為每個類別設定明確的介入條件與「保持沉默」的準則。

2. **建立或擴充資料集**  
   以 EgoServe 為基準，收集對應場景的影片並標註服務實例。若資料不足，可考慮從 EgoLife、HoloAssist、CaptainCook4D 等公開資料集擷取片段，再進行領域適配標註。

3. **建置多層記憶系統**  
   實作 EgoMemo 的三種互補記憶：多尺度時間摘要、語義知識圖譜與視覺嵌入檔案庫。確保記憶更新是串流進行，而非離線批次處理。

4. **開發檢索增強推理模組**  
   設計決策流程：在每個時間步先判斷是否需要介入，若需要再從三種記憶中檢索相關資訊，並產生具情境根據的回應。此處需反覆調整提示與檢索閾值。

5. **評估與迭代**  
   使用 EgoServe 的 4 個時間記憶範圍與 10 個服務類別進行評估，同時關注介入準確率、使用者滿意度與打斷頻率。根據結果調整決策保守度與回應風格。

6. **部署與持續學習**  
   將系統部署至目標裝置或雲端，建立使用者回饋機制，讓系統能根據實際互動紀錄逐步改善介入時機與內容。

### 潛在風險與注意事項

- **隱私外洩風險**：第一人稱視角影片會記錄大量敏感環境與人物資訊。建議採用裝置端處理、去識別化、差分隱私或聯邦學習，並讓使用者清楚掌握資料用途。
- **過度打斷與打擾疲勞**：若系統過於積極介入，容易讓使用者感到煩躁。應設定保守的介入閾值，並提供使用者自訂打斷頻率與主題黑白名單。
- **安全關鍵錯誤**：在工業或醫療場景中，錯誤的安全警示可能導致嚴重後果。關鍵決策應保留人工確認機制，並對高風險情境提高證據門檻。
- **偏見與不公平**：訓練資料若集中在特定族群或場景，可能導致對少數群體的判斷失準。需定期審查資料分布與模型表現。
- **記憶規模與延遲**：長時間累積的記憶會增加檢索成本。需設計記憶壓縮、分層索引與定期清理機制，以維持即時反應。

### 與其他技術的整合建議

- **AR 眼鏡與穿戴式攝影機**：Vinci2 最自然的載體是智慧眼鏡，可將視覺輸入、語音輸出與微投影提示結合，實現無手操作的主動式協助。
- **現有語音助理**：可將 EgoMemo 作為感知與決策後端，對接 Siri、Google Assistant 或企業自研助理，負責判斷何時該說話、該說什麼。
- **行事曆與健康資料庫**：將外部語境（如行程、睡眠、用藥紀錄）納入語義知識圖譜，可提升長期習慣輔導與個人化建議的品質。
- **事件觸發式系統**：可保留現有事件偵測模組作為初步篩選，再由 EgoMemo 進行第二階段的情境判斷，避免將所有偵測到的事件都視為需要介入。
- **企業知識管理系統**：在工業或醫療場景，可將標準作業流程、設備手冊與安全規範匯入檢索增強生成流程，讓回應更具專業依據。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先從摘要與第一章開始，理解「反應式典範」、「半主動式典範」與「主動式典範」的差異，並把 Vinci2 想像成「會看影片、會記得你過去做什麼、再決定要不要開口」的智慧助理，不必急著深入模型細節。

- **AI 工程師**：請重點閱讀 EgoMemo 的記憶架構與檢索增強推理流程，特別是多尺度時間摘要、語義知識圖譜與視覺嵌入檔案庫如何協同運作，並思考如何將其改寫為符合自身產品延遲與隱私需求的串流管線。

- **研究人員**：建議聚焦於 EgoServe 的任務定義、4 個時間記憶範圍與 10 個服務類別的設計邏輯，以及論文如何將主動式協助形式化為「決策驅動的推理任務」，這裡有許多可延伸的研究方向，例如介入時機學習、使用者偏好建模與長期記憶壓縮。

- **產品經理**：請把重心放在適用場景、使用者體驗與潛在風險。主動式協助的核心不是技術多強，而是「在對的時機說對的話」，因此介入頻率、回應語氣、隱私控制與使用者回饋機制，往往比模型準確率更能決定產品成敗。

| Explicit instruction | 明確指令 | 使用者預先提供的任務指令 |
| User query | 使用者查詢 | 使用者主動提出的問題 |
| Remain silent | 保持沉默 | 系統判斷無需介入而不回應 |
| Task-completion setting | 任務完成設定 | 以完成使用者指定任務為目標的設定 |
| Offline video QA benchmarks | 離線影片問答基準 | 針對預先分段影片的問答評測 |
| Streaming comprehension benchmarks | 串流理解基準 | 評估連續串流理解的基準測試 |
| Proactive dialogue benchmarks | 主動對話基準 | 評估主動對話行為的基準測試 |
| Daily activities | 日常活動 | 日常生活中的各種行為 |
| Extended temporal contexts | 延伸時間情境 | 跨越數分鐘至數小時的時間脈絡 |
| Memory mechanisms | 記憶機制 | 用於儲存與檢索資訊的機制 |
| Baselines | 基線 | 用於比較的基準方法 |
| Egocentric assistant | 第一人稱視角助理 | 以第一人稱影片為輸入的助理 |
| First-person video | 第一人稱影片 | 與 egocentric video 同義 |
| Visual context | 視覺情境 | 當前畫面所提供的脈絡資訊 |
| Perception | 感知 | 對視覺輸入的理解與辨識 |
| Reasoning | 推理 | 根據資訊進行判斷與決策 |
| Comprehension | 理解 | 對影片內容的整體掌握 |
| Evaluation | 評估 | 對方法或系統表現的衡量 |
| Modeling | 建模 | 設計與實作模型的過程 |
| Large-scale benchmark | 大規模基準 | 包含大量樣本的評測標準 |
