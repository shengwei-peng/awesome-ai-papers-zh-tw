## ⚡ TL;DR

既有 CAD 生成無法迭代驗證，難以產出符合結構需求的組裝工件。

## 摘要翻譯

電腦輔助設計（Computer-aided Design, CAD）是現代工業設計的基石，然而學習式 CAD 生成器仍不及真實工程流程：它們既不會像工程師般迭代，也無法評估工程真正所需的項目。過往研究將 CAD 生成視為兩個互不相關的步驟——零件合成與組裝（assembly）——前者根據與黃金參考的接近程度評分，後者即便有所處理，也被簡化為獨立的約束求解（constraint solving）步驟。在本研究中，我們提出一個更貼近產業實務的任務定義，要求模型根據自由形式的工程需求簡述產出完全組裝好的多零件 STEP 檔案，並透過有限元素分析（Finite Element Analysis, FEA）進行驗證。有限元素分析驗證顯示，Codex（GPT-5.5）與 Claude Code（Opus-4.7）智慧體在主要首輪全面測試中未能產出任何嚴格通過的成品，最佳配置平均僅滿足約 20% 的輸入文字需求。此外，我們引入兩項額外的監督訊號：一種新穎的純文字藍圖（blueprint）綱要，以及協助智慧體進行視覺檢查的 21 視角影像渲染器（21-view image renderer），使生成循環更貼合工程師實務上的迭代方式。在 S2O 與 Fusion360 上，相同的回饋工具提升了幾何重建表現，GPT-5.5/xhigh 在 S2O 的 Box-IoU 從 0.444 提升至 0.592，在 Fusion360 則從 0.397 提升至 0.505。綜合而言，這些訊號促使 CAD 程式朝向產出不僅在視覺上合理、且能通過物理與結構需求檢驗的成品。

### 核心貢獻（3～5點）
- 提出貼近產業實務的端到端 CAD 生成任務定義：從自由形式工程簡述直接產出可進行有限元素分析驗證的完整多零件組裝 STEP 檔。
- 揭示現有大語言模型智慧體（Codex／GPT-5.5、Claude Code／Opus-4.7）在首輪生成中的顯著缺口：未能產出任何嚴格通過有限元素分析的成品，最佳配置僅滿足約 20% 的輸入文字需求。
- 引入兩項額外監督訊號——純文字藍圖綱要與 21 視角影像渲染器——使生成循環更貼合工程師實務上的迭代與視覺檢查方式。
- 驗證回饋工具在 S2O 與 Fusion360 上顯著提升幾何重建表現（Box-IoU），推動 CAD 程式產出兼具視覺合理性與物理／結構可驗證性的成品。

### 適合對象
從事電腦輔助設計、生成式 AI 與工程設計自動化研究的學者與工程師；特別是關注如何將物理驗證（如有限元素分析）整合至生成式智慧體回饋迴路，以及希望提升多零件組裝與結構可行性之 CAD 生成系統的研發人員。

## 深度分析

#### 方法論解析

本研究將電腦輔助設計（CAD）生成重新定義為一個迭代式工具使用流程（iterative tool-using process），而非傳統的單次序列到幾何（sequence-to-geometry）映射。核心架構由一個大型語言模型（LLM）agent 與一個確定性控制器（deterministic controller）協同組成：agent 負責設計決策與 CAD 程式碼修復（CAD-code repair），控制器則掌管執行、量測、組裝（assembly）與驗證。在此框架下，agent 根據自由形式工程簡報（free-form engineering brief）輸出 CadQuery 程式，經執行後匯出 STEP 檔案，再透過結構化回饋進行最多 10 次的修訂迭代。

方法論的關鍵創新在於引入三個互補的監督訊號，共同彌合「視覺上合理」與「工程上可驗證」之間的鴻溝：

1. **結構化藍圖（blueprint）**：在生成 CAD 程式碼之前，agent 先產生一份 schema-v4 藍圖，記錄設計承諾（design commitments）。這份藍圖將幾何約束在可審計的參數化基本圖元（auditable parametric primitives）上，預先固定外殼（envelopes）與介面（interfaces），並將尺寸與功能宣稱暴露給後續的驗證器與重試回饋。這類比於工程師在實際建模前的設計規劃階段，使後續的程式碼生成不再是開放式的幾何合成，而是受約束的參數實現。

2. **21 視角影像渲染器（21-view image renderer）**：不同於過去視覺 CAD 程式碼評估常用的 4–6 張渲染圖，本研究提供 21 個校準視角（calibrated views），涵蓋外觀視角、特寫（close-ups）與內部 X 光剖面（internal x-ray cuts）。這讓 agent 能進行類似工程師繞行組裝、放大檢視介面、截取剖面的靜態等效視覺檢查，從而偵測組裝錯誤（assembly errors）、介面錯置或選擇器（selector）失效等僅憑外觀渲染難以發現的問題。

3. **有限元素分析（Finite Element Analysis, FEA）回饋**：透過開源求解器 CalculiX，系統對候選設計（candidate design）進行自動網格劃分（meshing）與物理分析，回傳類型化失效（typed failures），涵蓋應力（stress）、位移（displacement）、模態（modal）、挫曲（buckling）、接觸（contact）與間隙需求（clearance requirements）。這是將 CAD 生成從「形狀近似」推向「物理合規」的關鍵步驟，使 agent 能針對負載路徑（load path）與結構完整性進行語義層級的修復。

這三個訊號構成一個由抽象到具體、由幾何到物理的漸進式驗證鏈：藍圖確保設計意圖的結構化與可審計性；21 視角渲染提供中間層級的幾何與組裝檢查；FEA 則作為最終的物理仲裁者。迭代迴圈將 test-time compute 組織為結構化的工程回饋，而非單純擴大單次推理預算。

#### 實驗數據解讀

本研究引入 Hephaestus-CCX（H-CCX）基準測試，包含 50 個來自專利、供應商規格書、工程標準與競賽的工程簡報，每個案例配對可執行的類型化需求檢查器（typed requirement checkers）。評估標準並非與單一參考網格的距離，而是生成的組裝 STEP 檔案是否滿足陳述的物理與幾何合約。

**首次嘗試的嚴峻現實** 是最值得關注的發現：在 400 次首次嘗試（first-attempt sweep）中，Codex (GPT-5.5) 與 Claude Code (Opus-4.7) 未產生任何嚴格通過（strict-passing）的工件，最佳配置平均僅滿足約 20% 的類型化需求（typed requirements）。這項結果揭示了當前 frontier models 在直接將自由形式工程簡報轉譯為可通過工程驗證之多零件組裝體方面的能力幾近於零，也凸顯了 H-CCX 相較於傳統基準的難度躍升。

**回饋訊號的量化效益** 則呈現在部分信用指標（partial-credit metrics）上：
- 21 視角回饋（21-view feedback）將 GPT-5.5 在 H-CCX 上的平均需求通過率（mean requirement pass）從 19.4% 提升至 29.3%，並在 Fusion360 資料集上將 Box-IoU 從 0.397 提升至 0.505。
- 藍圖（blueprinting）在 S2O 資料集上將 Box-IoU 從 0.444 顯著提升至 0.592。
- 然而，單輪 FEA 回饋僅在額外 400 次修訂提交中增加 1 個嚴格通過，顯示單次物理回饋仍不足以讓模型跨越工程合規門檻。

**Test-time compute 的穩定擴展** 是另一項核心發現。在最長的 GPT-5.5/high 運行中，模型平均每項花費 68 分鐘（相較於 10 分鐘的兩次嘗試基線，增加近 7 倍），平均需求通過率從 38.8% 提升至 60.5%，並在 50 個案例中達成 9 個嚴格通過。這證明當推論時計算量（test-time compute）被組織為結構化工程回饋時，能穩定地轉化為更好的 CAD 工件，而非僅靠擴大單次推理預算。

**質性案例分析** 顯示了三種典型的修復模式：發射器（launcher）移除脆弱且過度細節的幾何，將負載重新導向更簡單的剛體；柱（column）增加支撐（bracing）與截面剛度以恢復軸向承載力（axial capacity）；太空船面板（spacecraft panel）則在維持相似外觀形狀的同時，修正隱藏的密度與質量屬性錯誤。這些案例證明 agent 不僅能修正表面幾何，還能進行涉及負載路徑與材料分佈的深層工程權衡。

#### 與現有研究的比較

本研究對現有 CAD 生成文獻提出了三個層面的結構性批判與改進：

**評估典範的轉移**：既有研究長期將 CAD 生成視為黃金參考匹配（gold reference matching）問題，使用 Chamfer Distance（CD）、F-score、Intersection over Union（IoU）與 Invalidity Ratio（IR）等指標衡量與參考形狀的接近程度。另有研究加入視覺合理性（visual plausibility）或流形性（manifoldness）等檢查。本文指出，這些訊號無法捕捉使設計報廢的關鍵失效模式，例如介面錯置（misplaced interface）、間隙不足（insufficient clearance）、無效負載路徑（invalid load path）或無法支援下游分析的選擇器錯誤。相較之下，H-CCX 以類型化需求檢查器與 FEA 作為評估仲裁，直接對齊工業界的工程審計（engineering audit）標準。

**零件合成與組裝的整合**：過去文獻結構性地將零件合成（part synthesis）與組裝（assembly）視為不相交問題。第一類研究生成孤立零件，完全忽略組裝；第二類研究雖處理組裝，但從現有工作組裝（如 Fusion360 Gallery）中提取已可接合的零件，僅預測接合軸（joint axes）或接合姿態（mate poses）。這迴避了工程設計中最困難的核心——接合本身（the joint itself）——包括公差累積（tolerance buildup）、螺栓圖案對齊與纜線間隙等。本文要求模型從工程簡報直接生成完整組裝的多零件 STEP 檔案，將可接合的零件（jointable part）視為必須被主動達成的輸出，而非免費的副產品。

**視覺與物理驗證的深化**：既有視覺評估通常僅使用 4–6 張渲染圖，由視覺語言模型（VLM）進行判斷，這無法解析內部接合（internal mating）或隱藏結構缺陷。本文的 21 視角影像渲染器（含 X 光剖面）大幅擴展了視覺檢查的覆蓋率。同時，流形性（manifoldness）或許足以通過 3D 列印檢查，但無法通過結構工程審計；FEA 回饋則將驗證標準提升至物理與結構需求層級。

#### 可重現性評估

在可重現性方面，本研究採取了部分開放策略：

**已釋出資源**：作者承諾釋出 Hephaestus-CCX 基準測試，包含 50 個單零件與多零件工程簡報、CalculiX 評估套件（evaluation kits）以及類型化通過/失敗需求檢查器（typed pass/fail requirement checkers）。這為後續研究提供了標準化的評估基礎與明確的任務定義，是推動社群進入工程導向 CAD 生成的關鍵貢獻。

**未明確釋出之項目**：儘管論文詳細描述了 agent 架構，但並未明確說明是否釋出完整的生產級編碼 agent 框架（production coding-agent harnesses）、確定性控制器（deterministic controller）的 CadQuery 執行與組裝程式碼、藍圖 schema 的完整規格、選擇器後設資料（selector metadata）的格式，或是驅動 frontier models 的完整提示詞（prompts）。這些元件對於嚴格重現迭代迴圈至關重要。

**計算與成本障礙**：實驗使用 Codex (GPT-5.5) 與 Claude Code (Opus-4.7) 等商業 frontier models，且最長設定需 68 分鐘/項的 test-time compute。這代表重現完整實驗將涉及高額的 API 成本與長時間的推論延遲，對學術界的廣泛重現構成實際門檻。

**建議**：為提升可重現性，作者應考慮釋出藍圖 schema-v4 的正式規格文件、控制器原始碼、以及用於解析 FEA 報告並生成修復建議的提示詞模板，使社群能在不依賴特定內部基礎設施的情況下複製核心方法。

#### 未來研究方向

基於本文的發現與限制，以下幾個方向值得後續研究深入探索：

**提升首次嘗試成功率**：當前 frontier models 的首次嘗試嚴格通過率為零，顯示模型缺乏足夠的工程物理先驗知識。未來可探索針對 CAD 領域的持續預訓練（continual pre-training）或指令微調（instruction fine-tuning），將工程標準、材料力學與製造知識注入模型參數中，降低對多輪迭代回饋的絕對依賴。

**回饋機制的效率與精確性**：單輪 FEA 回饋的邊際效益極低（400 次中僅增 1 次嚴格通過），顯示現有 agent 難以將類型化失效（typed failures）有效映射到 CadQuery 程式碼的具體修復。未來需要更智慧的錯誤定位（fault localization）與修復規劃（repair planning）演算法，例如將應力熱點或位移過量區域直接關聯到藍圖中的特定參數或幾何特徵。

**多物理場與多尺度整合**：當前僅使用 CalculiX 進行結構有限元素分析（FEA）。未來可整合計算流體動力學（CFD）、熱傳導分析、多體動力學（multibody dynamics）以及電磁模擬，使 CAD agent 能處理更廣泛的工程領域。同時，從巨觀結構行為到微觀材料晶格（lattice）設計的多尺度生成也是重要延伸。

**公差與製造約束的顯式建模**：本文雖強調接合（joint）的重要性，但未明確處理幾何尺寸與公差（GD&T）、公差累積（tolerance buildup）與製造可行性（manufacturability）。將製造回饋（如 CNC 加工性、3D 列印支撐結構需求）納入迭代迴圈，是縮短「生成—驗證—生產」鏈隙距的關鍵。

**專用模型架構的開發**：目前完全依賴通用 coding agent（如 GPT-5.5、Opus-4.7）。未來可設計專門針對 CAD 與 FEA 的多模態模型，能夠原生處理 21 視角影像、網格（mesh）資料與場量（field quantities，如應力場、位移場）的聯合推理，而非僅透過文字回饋間接理解物理結果。

**基準測試的擴充與多樣化**：H-CCX 僅含 50 個案例，雖具代表性但規模有限。未來需擴展至數百乃至數千案例，涵蓋航太、生醫、土木與電子封裝等多元領域，並納入動態負載、疲勞分析與最佳化目標（如輕量化）等更複雜的設計任務。

## 論文問答

**Q1：現有的學習式 CAD 生成系統在工業應用中存在哪些根本性的不足？**
A：現有的學習式 CAD 生成系統雖然在文字轉零件生成、CAD 程式碼合成與視覺合理性方面有所進展，但它們與真實工程流程的耦合仍然非常薄弱。這些系統通常僅以與參考形狀的距離、渲染圖的視覺可信度或拓撲有效性作為評估標準，忽略了工程設計中至關重要的結構與物理需求。因此，它們無法檢測出諸如介面錯位、間隙不足、無效負載路徑或無法支撐後續分析等致命錯誤，導致產出的設計在實務上往往無法使用。

**Q2：為什麼傳統將零件合成與組裝視為兩個獨立步驟的做法，無法符合真實工業設計的需求？**
A：在真實的工業工程中，設計心力有很大一部分投注於接合部位本身，必須確保零件能與鄰件在公差範圍內接合、符合螺栓孔位、避開線纜並傳遞負載。然而，過往研究要麼只生成孤立零件而完全忽略組裝，要麼從現有組裝體中提取已可接合的零件來預測接合軸或姿態，迴避了接合設計的核心難題。這種將零件生成與組裝分離的作法，使得模型無法學習如何從零開始設計出可實際裝配且具功能性的多零件組件。

**Q3：本文為何強調引入有限元素分析（FEA）作為回饋訊號，而非僅依賴傳統的幾何相似度指標？**
A：傳統指標如 Chamfer Distance、F-score 或 IoU 只能衡量生成幾何與參考形狀的接近程度，卻無法驗證設計是否滿足應力、位移、挫曲或接觸等物理需求。有限元素分析能夠揭示傳統視覺或幾何檢查無法發現的內部結構缺陷，例如隱藏的密度錯誤或無效的負載傳遞路徑。透過將 FEA 納入迭代迴圈，生成代理程式得以像真正的工程師一樣，根據結構與物理約束逐步修正設計，而非僅僅複製外觀。

**Q4：本文提出的 CAD 生成代理程式採用了什麼樣的迭代流程來模擬真實工程師的工作方式？**
A：本文將 CAD 生成重新框架為一個反覆使用工具的過程，其中大型語言模型代理程式撰寫 CadQuery 程式並輸出 STEP 檔案，隨後透過渲染、驗證與模擬工具獲得結構化回饋。代理程式會根據這些回饋修訂 CAD 程式與選擇器元資料，並在最多十次嘗試中重新提交設計。這種迴圈讓模型能夠在幾何、視覺與物理層面持續修正錯誤，而非僅進行一次性的一次性推論與生成。

**Q5：什麼是「藍圖（blueprint）」階段，它在整個生成流程中扮演什麼關鍵角色？**
A：藍圖階段是在實際撰寫 CAD 程式之前的預設計階段，它以一種結構化的文字綱要記錄代理程式必須滿足的設計承諾。此階段將幾何約束在可審計的參數化基本圖元上，預先固定外殼與介面，並揭露尺寸與功能主張以供後續驗證器與重試回饋使用。透過在編碼前確立這些不可動搖的設計承諾，藍圖有效防止代理程式在後續迭代中偏離核心工程需求，並提供可稽核的設計依據。

**Q6：本文提出的 21 視角影像渲染器與傳統視覺評估方法相比，有何獨特之處與優勢？**
A：傳統的視覺評估通常僅使用 4 到 6 張渲染圖，難以完整捕捉組裝體的內部結構與介面細節。本文的 21 視角影像渲染器則提供外觀視圖、特寫以及內部 X 光剖面等多樣化角度，相當於讓代理程式能夠繞行組裝體、放大檢視接合處並進行剖面檢查。這種豐富的靜態視覺回饋使代理程式能在最終提交前，先行發現並修正可見的幾何錯誤、組裝失誤與選擇器問題，大幅提升後續物理驗證的成功率。

**Q7：Hephaestus-CCX（H-CCX）基準測試與現有 CAD 生成評測集相比，有何根本性的不同？**
A：Hephaestus-CCX 包含 50 個從專利、供應商規格書、工程標準與競賽中收集而來的工程需求簡述，每個案例都要求產出一個完整組裝的多零件 STEP 檔案。與傳統評測僅比對參考網格不同，H-CCX 透過可執行的需求檢查器與 CalculiX 有限元素分析，根據設計是否滿足既定的物理與幾何契約來評分。這種評估方式從「像不像參考設計」轉向「能不能通過工程驗證」，更貼近真實工業設計的驗收標準。

**Q8：在首次嘗試（first-attempt）的實驗中，前沿語言模型在 Hephaestus-CCX 上的表現揭示了什麼樣的挑戰？**
A：實驗結果顯示，即使是 Codex（GPT-5.5）與 Claude Code（Opus-4.7）這類前沿模型，在 400 次首次嘗試中也未能產出任何一個嚴格通過（strict-passing）的工件，最佳配置平均僅能滿足約 20% 的類型化需求。這項結果凸顯了當前大型語言模型在理解自由形式工程簡述、並將其轉化為符合物理與組裝約束之可執行 CAD 程式方面，仍存在巨大鴻溝。同時，這也證明了傳統僅以參考匹配或視覺合理性為目標的評估方式，嚴重低估了真實工程生成任務的難度。

**Q9：結構化藍圖、21 視角視覺回饋與 FEA 重試回饋各自對模型表現帶來了哪些量化的改善？**
A：21 視角視覺回饋將 GPT-5.5 在 Hephaestus-CCX 上的平均需求通過率從 19.4% 提升至 29.3%，並將 Fusion360 上的 Box-IoU 從 0.397 提升至 0.505。結構化藍圖則使 GPT-5.5/xhigh 在 S2O 資料集上的 Box-IoU 從 0.444 顯著提升至 0.592，顯示預先規劃對幾何重建的關鍵助益。當這些回饋訊號在長時間迴圈中複合使用時，最長的 GPT-5.5/high 運行將平均需求通過率從 38.8% 推升至 60.5%，並在 50 個案例中產出 9 個嚴格通過的工件，證明結構化工程回饋能有效將測試時間運算轉化為實質的設計品質提升。

**Q10：這套具備 FEA 回饋的自我改進代理程式在實務上最適合應用於哪些工程設計場景？**
A：這套系統特別適用於需要同時滿足幾何、組裝與結構物理需求的機械設計場景，例如航太零件、承重結構柱、發射器本體等需要經過嚴謹應力與挫曲分析的產品。由於代理程式能夠根據工程簡述自動迭代並通過有限元素驗證，它有潛力成為概念設計階段的輔助工具，加速工程師從需求到可驗證數位原型的過程。此外，對於需要頻繁修改設計參數以符合不同負載條件的客製化零件開發，此系統也能透過自動化回饋迴圈顯著縮短設計驗證週期。

**Q11：從產品開發的角度來看，引入藍圖階段與多視角視覺檢查對設計流程的品質保證有何意義？**
A：藍圖階段相當於在正式建模前建立一份可審計的設計契約，確保外殼、介面與關鍵參數在編碼前即被凍結，從源頭減少後續因需求漂移造成的重工。21 視角視覺檢查則提供了類似工程師實體巡檢的數位等價物，能在進入耗時的有限元素分析前，先過濾掉明顯的幾何與組裝錯誤。這兩項機制共同將傳統依賴人工經驗的品質把關轉化為結構化、可自動執行的前驗與中驗步驟，有助於提升設計流程的可追溯性與可靠性。

**Q12：本文釋出的 Hephaestus-CCX 基準測試對未來 CAD 生成與工程 AI 研究領域可能產生什麼影響？**
A：Hephaestus-CCX 的釋出為學界提供了一個以工程有效性為核心、而非僅以幾何相似度為導向的標準化評測平台，有望引導後續研究更關注物理可製造性與結構完整性。透過將評估標準從「匹配參考網格」轉向「滿足類型化工程需求」，該基準能夠促進更具實務價值的模型開發，縮短學術成果與工業應用之間的落差。長遠來看，這將激發更多結合多物理場模擬、迭代式代理程式與製造約束的跨領域研究，推動電腦輔助設計從形狀生成邁向真正的工程智能。

**Q13：儘管引入了多重回饋機制，本文坦承目前系統仍存在哪些主要的限制？**
A：即使在最長的回饋迴路中，GPT-5.5/high 也僅能在 50 個案例中達成 9 個嚴格通過，顯示當前前沿模型距離完全自主解決工程設計問題仍有相當距離。此外，每次迭代仍需耗費大量測試時間運算，最長運行平均需 68 分鐘處理單一項目，對於需要快速週期的設計流程而言成本仍然過高。這些限制表明，單純增加回饋次數與運算資源並無法線性解決所有工程複雜度，模型在理解深層物理因果與長程設計依賴方面仍需根本性的能力突破。

**Q14：實驗中觀察到的失敗案例主要呈現哪些模式，這些模式對未來改進有何啟示？**
A：實驗中的失敗模式包括：過度細緻的脆弱幾何導致負載路徑無效、柱體缺乏支撐與截面剛度而喪失軸向承載力，以及太空船面板雖外觀相似但隱藏密度與質量屬性錯誤。這些案例顯示模型經常能複製外觀形狀，卻難以正確配置內部結構與材料屬性以滿足物理需求。未來的改進方向應著重於強化代理程式對負載路徑、材料分佈與隱藏特徵的因果推理能力，並在藍圖階段納入更明確的結構設計規則與材料模型。

**Q15：針對目前 CAD 生成代理程式的表現，作者認為未來研究應朝哪些方向發展以進一步縮短與工業級應用的差距？**
A：作者認為未來研究應持續探索如何將測試時間運算穩定地轉化為工程品質提升，而非僅僅擴大一次性推論的規模，這需要更精細的結構化回饋表示與長程規劃機制。此外，整合更廣泛的製造約束——如公差分析、熱傳導或疲勞壽命——將使代理程式能處理更完整的產品生命週期需求。最後，發展專門針對工程領域的基礎模型或檢索增強生成架構，以提升對專利、標準與供應商規格書中隱含設計知識的理解，將是實現真正工業級自主設計的關鍵下一步。

## 實務應用指南

### 適用場景

1. **快速概念設計驗證**：機械設計團隊在投產前，由 AI 根據自然語言需求規格書生成可組裝的 STEP 檔，並自動執行 FEA 驗證結構強度與間隙，縮短設計-分析迴圈。
2. **專利與標準件自動建模**：將專利文件或供應商規格書轉換為參數化 CAD 程式碼，透過藍圖約束確保幾何承諾可審計，適合法務與採購單位建立可驗證的 3D 零件庫。
3. **教育與工程競賽輔助**：在工程教育或學生競賽中，作為「虛擬助教」協助學生將文字題目轉為可分析的實體模型，並透過 21 視角渲染與 FEA 回饋指出設計缺陷。
4. **跨領域系統整合原型**：航太或汽車產業中，由系統工程師撰寫高階需求，AI 生成多零件裝配體並驗證負載路徑、接觸與挫曲行為，作為詳細設計前的架構雛形。
5. **既有產品設計迭代優化**：針對已上市產品，輸入修改需求（如減重、增加軸向承載力），AI 在保留外部包絡與介面的前提下，自動加入支撐或調整截面，並以 FEA 確認修改後仍滿足物理合約。

### 實作前置條件

- **資料層面**：需準備自由格式工程需求書（brief）、對應的參數化藍圖模板（schema-v4）、以及可執行的需求檢查器（typed requirement checkers）。若評估幾何重建，需備有 S2O 或 Fusion360 等參考資料集。
- **運算層面**：需能執行 LLM agent（如 GPT-5.5/xhigh 或 Claude Code Opus-4.7）的 API 配額；本地或雲端需部署 CadQuery 執行環境、STEP 匯出工具、21 視角影像渲染器，以及 CalculiX 有限元素求解器。單一案例完整回饋迴圈平均耗時可達 60–70 分鐘，需預留充足 test-time compute。
- **技能層面**：團隊需具備 Python/CadQuery 參數化建模能力、FEA 網格劃分與邊界條件設定知識，以及能將工程規範轉譯為可自動化檢查項目的領域專家。

### 實作步驟建議

1. **需求結構化與藍圖生成**：將自由格式工程需求書轉換為 schema-v4 藍圖，明確定義包絡尺寸、介面位置、可審計的參數化基本圖元與功能宣稱，作為後續 CAD 程式碼生成的不可變約束。
2. **初始 CAD 程式碼生成**：由 LLM agent 根據藍圖撰寫 CadQuery 程式，透過確定性控制器執行、測量、組合與驗證，輸出第一版多零件 STEP 裝配檔。
3. **視覺檢查與幾何修復**：啟動 21 視角影像渲染器（外觀、特寫、內部 X 光剖面），讓 agent 進行靜態視覺巡檢，修正可見的幾何錯誤、組裝錯誤與選擇器錯誤。
4. **FEA 回饋與物理驗證**：將候選設計匯入 CalculiX 進行網格劃分與分析，回傳結構化失敗報告（應力、位移、模態、挫曲、接觸、間隙），由 agent 據此修復負載路徑或調整截面。
5. **迭代收斂與提交**：重複步驟 2–4 最多 10 次，直至滿足 typed requirements 或達到時間/成本上限。最終產出需通過嚴格通過（strict-pass）檢查的 STEP 檔與對應的 FEA 報告。
6. **產品化封裝**：將成功通過的藍圖模板、提示詞（prompt）、選擇器後設資料（selector metadata）與修復軌跡封裝為可重複使用的設計劇本（playbook），整合至 PLM 或版本控制系統。

### 潛在風險與注意事項

- **首次嘗試極低通過率**：即使是前沿模型，首次生成 strict-pass 率可能為零，平均僅滿足約 20% 需求。建議將預期設定為「多輪迭代」而非「一鍵生成」，並建立明確的 partial-credit 里程碑。
- **幻覺與不可製造特徵**：LLM 可能產生過度精細或脆弱的幾何（如論文中的 launcher 案例），導致應力集中。需在藍圖階段限制可審計圖元，並於 FEA 階段設定製造約束檢查。
- **計算成本膨脹**：完整 10 輪回饋平均耗時近 70 分鐘/件，API 與雲端運算成本高昂。建議設定早期停機條件（early stopping），例如連續三輪無顯著 partial-credit 提升即終止。
- **模擬邊界條件誤設**：CalculiX 的結果高度依賴網格品質與邊界條件。若自動化流程設定錯誤，agent 會基於錯誤回饋進行無效修復。需由領域專家預先審查 FEA 模板。
- **多零件介面公差累積**：論文指出組裝不僅是姿態預測，更涉及公差與配合。自動化流程需額外整合公差分析工具，否則可能產生看似正確但實際無法裝配的介面。

### 與其他技術的整合建議

- **PLM / PDM 系統**：將藍圖 schema 與 STEP 產出直接寫入產品生命週期管理系統，利用現有版控與變更管理流程追蹤 AI 生成的設計迭代軌跡。
- **MBD（Model-Based Definition）**：將藍圖中的尺寸與功能宣稱轉為 PMI（Product and Manufacturing Information），銜接下游 CNC 加工或 3D 列印的語義化製造指令。
- **拓撲最佳化工具**：在 FEA 回饋指出應力或重量問題時，先由拓撲最佳化引擎（如 nTopology 或 ANSYS Discovery）產生概念性材料分佈，再由 LLM 轉譯為 CadQuery 參數化特徵，避免 agent 盲目試誤。
- **VLM 與數位孿生**：將 21 視角渲染器擴充為即時數位孿生檢視，讓工程師在 VR/AR 環境中與 AI agent 協作標註問題，而非僅依賴靜態影像回饋。
- **CI/CD for Hardware**：將 FEA 檢查器與需求驗證腳本封裝為自動化閘道，整合至硬體持續整合管線，確保每次 AI 修改都通過回歸測試。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先聚焦於論文的圖 1 與圖 2，理解「藍圖 → CAD 生成 → 視覺檢查 → FEA 回饋 → 修復」這個大迴圈。不必深究 CalculiX 的求解器設定，但需認識到「看起來像」和「工程上可用」是兩回事。
- **AI 工程師**：重點閱讀實驗設定與 feedback source 的消融比較，特別是 21 視角影像渲染器與藍圖 schema 如何分別貢獻幾何與結構指標。注意 agent harness 中「確定性控制器」與「LLM 設計決策」的職責分離，這是將 test-time compute 轉化為可靠增益的關鍵架構。
- **研究人員**：深入探討問題重新定義的貢獻——為何 gold-reference matching 與 visual plausibility 不足以評估 CAD 生成，以及 Hephaestus-CCX 的 typed requirement checkers 如何改變評估典範。可延伸思考如何將公差分析、熱傳導或計算流體力學納入回饋迴圈。
- **產品經理**：關注「首次嘗試零通過、十輪後 18% strict-pass」這個殘酷現實，據此規劃產品路線圖。短期可將此技術定位為「輔助概念發想與需求澄清工具」，而非「全自動設計師」。同時評估 70 分鐘/件的運算成本是否在目標客群的單件設計預算內。
