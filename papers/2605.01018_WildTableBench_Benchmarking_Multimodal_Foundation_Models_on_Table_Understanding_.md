提出WildTableBench，收錄402張真實表格影像與928道驗證問題，涵蓋五大類十七子類型。

## 摘要翻譯

利用多模態基礎模型（Multimodal Foundation Models）分析表格圖像是消費者與企業場景中一項高價值但具挑戰性的應用。儘管此應用十分重要，現有的評估主要依賴結構化文字表格或乾淨的渲染圖像（Rendered Images），導致真實世界（In the Wild）表格圖像的視覺複雜度仍缺乏深入探討。這類圖像具有多樣的版面配置（Layouts）與領域（Domains），需要精密的結構感知與數值推理（Numerical Reasoning）。為了彌補此差距，我們提出 WildTableBench，為首個針對真實世界場景（Real-World Settings）中自然存在（Naturally Occurring）之表格圖像所建構的問答基準測試（Question-Answering Benchmark）。WildTableBench 包含 402 張高資訊密度（High-Information-Density）表格圖像，收集自橫跨多樣領域（Domains）的線上論壇與網站；另含 928 道經手動標註與驗證（Manually Annotated and Verified）的問題，涵蓋五個類別（Categories）下之 17 種問題子類型（Question Subtypes）。我們在此基準測試（Benchmark）上評估 21 個前沿專有與開源多模態基礎模型（Frontier Proprietary and Open-Source Multimodal Foundation Models）。僅有一個模型的

## 深度分析

#### 方法論解析

WildTableBench 的核心方法論旨在縮小現有 Evaluation Settings (評估設定) 與 Practical Table Understanding (實際表格理解) 之間的落差，其建構流程可分為資料收集與問題設計兩大軸線。

在資料收集端，研究團隊直接從線上論壇與公開網站擷取 Naturally Occurring (自然存在) 的表格圖像，涵蓋 Screenshots (螢幕截圖)、Scans (掃描檔) 與 Photographs (照片)，共計 402 張 High-Information-Density (高資訊密度) 的影像。這些影像橫跨工作表、交通、運動、教育、金融、科學、工程與醫療等多個 Domains (領域)，具備 Layouts (版面配置) 多樣性、Irregular Cell Spans (不規則儲存格跨距)、Dense Content (密集內容)、Decorative Formatting (裝飾性格式) 與傾斜方向等 Real-World Settings (真實世界場景) 常見的視覺與結構複雜度。

在問題設計端，研究者先歸納公開論壇中的實際使用情境，建立涵蓋五個 Categories (類別) 與 17 種 Question Subtypes (問題子類型) 的分類架構。五大 Categories (類別) 包含 Cell-Level Understanding (儲存格層級理解)、Numerical Reasoning (數值推理)、Fact Verification (事實驗證)、Hypothetical Reasoning (假設推理) 與 Color-Based Reasoning (基於顏色的推理)。問題生成採用人機協作流程：首先利用 LLMs (Large Language Models) (大型語言模型) 產生 Seed Questions (種子問題)，再由 Professional Annotators (專業標註人員) 進行精修與擴充，確保每道問題清晰、無歧義且僅憑影像即可驗證。最終的 928 道 Manually Annotated (手動標註) 且 Manually Verified (手動驗證) 的問題皆強調 Non-Trivial (非瑣碎) 的 Visual Grounding (視覺接地) 與 Reasoning over Table Structure and Values (對表格結構與數值進行推理)，並搭配 Cross-Checked (交叉驗證) 的 Reference Answer (參考答案)。

#### 實驗數據解讀

本研究系統性評估了 21 個 Frontier Proprietary Models (前沿專有模型) 與 Open-Source Models (開源模型)，包含其 Instruction-Tuned (指令微調) 與 Reasoning Variants (推理變體)。實驗結果顯示，僅有 Gemini-3-Pro 的 Accuracy (準確率) 超過 50%，達到 67.9%；其餘所有模型均低於 50.0%，分佈範圍從 4.1% 至 49.9%，顯示真實世界表格圖像對現行 Multimodal Foundation Models (多模態基礎模型) 構成極大挑戰。

Diagnostic Analyses (診斷分析) 進一步刻畫 Model Failures (模型失效) 的系統性模式。首先，模型對於位於較深層行列的儲存格呈現一致的效能衰退，顯示 Visual Grounding (視覺接地) 與長程結構感知能力存在持續性弱點。其次，研究量化 Reasoning Difficulty (推理難度) 與 Reasoning Budget (推理預算) 對效能的影響，發現即使增加推理資源，模型在複雜 Layouts (版面配置) 與 High-Information-Density (高資訊密度) 情境下的增益仍然有限。此外，不同 Model Families (模型家族) 與 Parameter Sizes (參數規模) 之間存在顯著差異，但即便最大規模的模型也無法穩定 Parse (解析) Irregular Cell Spans (不規則儲存格跨距) 與 Decorative Formatting (裝飾性格式)，顯示穩健的表格圖像理解仍遠未解決。

#### 與現有研究的比較

現有 Benchmark (基準測試) 大致可分為兩大類，而 WildTableBench 明確填補了兩者共同的評估盲區。

第一類為 Text-based Table Benchmarks (文字型表格基準測試)，例如 TabFact、TableBench、NeedleInATable 與 TableEval。這類工作將表格轉換為 CSV、HTML 或 Markdown 等結構化文字格式，雖能評估 Numerical Reasoning (數值推理) 與 Fact Verification (事實驗證)，但完全繞過 Visual Perception (視覺感知)，使模型無需真正 Parse (解析) Layouts (版面配置) 即可利用資料層級相關性作答。

第二類為 Rendered Images (渲染圖像) 基準測試，例如 TableVQA-Bench、M2-TabFact 與 RealHiTBench。這類工作透過受控渲染或轉換管線將結構化資料轉為影像，產生的輸入在字體、顏色、間距與格式上相對乾淨且同質，屬於 Clean Digital Tables (乾淨的數位表格) 範疇。然而，它們缺乏 Real-World Settings (真實世界場景) 中常見的壓縮失真、模糊、透視變形、遮擋、背景雜訊與來源特定樣式變異。

相較之下，WildTableBench 直接從真實視覺來源收集影像，完整涵蓋 Domains (領域) 多樣性、Layouts (版面配置) 不規則性、視覺雜訊與結構複雜度。其問答設計亦強調 Non-Trivial (非瑣碎) 的 Reasoning over Table Structure and Values (對表格結構與數值進行推理)，而非僅做表層檢索。儘管如此，本研究在規模上仍屬精緻化的小型 Benchmark (基準測試)（402 張圖像、928 道問題），且從提供的脈絡觀察，尚未明確探討資料污染或訓練集重疊問題，這是後續可強化的面向。

#### 可重現性評估

就提供的全文脈絡而言，WildTableBench 作為一個 Question-Answering Benchmark (問答基準測試)，其可重現性取決於資料集與評估管線的公開程度。然而，目前文本並未明確提及原始碼、資料集下載連結或授權條款的釋出細節，這是 Benchmark (基準測試) 論文常見但此處尚未確認的環節。

在模型端，研究評估的對象包含可透過 API 存取的 Frontier Proprietary Models (前沿專有模型)（如 Gemini、GPT、Claude、Seed-series）以及已釋出權重的 Open-Source Models (開源模型)（如 Kimi、GLM、Qwen-series），這部分具備高度可重現性。但若 Benchmark (基準測試) 資料本身未公開，後續研究者將難以進行公平比較或擴充研究。建議作者群遵循 Benchmark (基準測試) 社群慣例，於公開平台釋出圖像、問題、Reference Answer (參考答案) 與評分腳本，以確保 Diagnostic Analyses (診斷分析) 與 Model Failures (模型失效) 的發現能被獨立驗證。

#### 未來研究方向

基於 WildTableBench 所揭示的 Model Failures (模型失效) 與效能缺口，未來研究可朝以下方向推進：

第一，強化結構感知能力。針對 Irregular Cell Spans (不規則儲存格跨距)、傾斜方向與多層表頭等 Layouts (版面配置) 挑戰，可發展專門的表格編碼器或結構感知的預訓練目標，以改善 Visual Grounding (視覺接地)。

第二，提升深層行列推理。Diagnostic Analyses (診斷分析) 顯示模型對深層行列的效能衰退，未來可結合 OCR (Optical Character Recognition) (光學字元辨識) 與版面分析的混合架構，或設計針對長表格的注意力機制，以維持對 High-Information-Density (高資訊密度) 影像的穩定 Parse (解析) 能力。

第三，擴展 In the Wild (真實世界) 的視覺穩健性。需強化對壓縮失真、模糊、透視變形、部分遮擋與背景雜訊的處理，可透過資料增強或領域適應技術，提升模型在 Screenshots (螢幕截圖)、Scans (掃描檔) 與 Photographs (照片) 上的泛化表現。

第四，推理機制優化。研究可進一步探索 Reasoning Budget (推理預算) 與 Reasoning Difficulty (推理難度) 的最佳平衡，發展針對 Numerical Reasoning (數值推理)、Hypothetical Reasoning (假設推理) 與 Color-Based Reasoning (基於顏色的推理) 的專用鏈式思考變體。

第五，規模化與多語言擴充。當前資料集規模為 402 張圖像與 928 道問題，未來可擴大樣本數並納入非英文 Domains (領域)，建立更具代表性的多語言 Practical Table Understanding (實際表格理解) 評估體系。

## 論文問答

**Q1：WildTableBench 旨在解決多模態基礎模型在表格理解領域的哪個核心問題？**
A：WildTableBench 旨在解決現有評估設定與真實世界應用之間存在的顯著落差。當前的基準測試大多依賴結構化文字表格或經過程式渲染的乾淨圖像，無法反映真實場景中表格圖像的視覺複雜度與結構不規則性。這導致模型在實際面對螢幕截圖、掃描檔或照片等自然存在的表格時，其理解能力被嚴重高估。

**Q2：為何現有的表格理解基準測試無法充分評估模型的真實能力？**
A：現有基準測試主要分為兩類，但皆存在根本缺陷：一類直接以結構化文字（如 CSV、HTML 或 Markdown）呈現表格，使模型無需進行視覺感知即可利用結構化資訊；另一類雖將表格轉為圖像，卻是透過受控的渲染管線產生，導致視覺呈現過於乾淨且同質化。這些方法忽略了真實世界表格中常見的壓縮失真、模糊、透視變形、部分遮蔽與裝飾性格式等挑戰，因此無法檢驗模型是否真正具備解析表格版面配置的能力。

**Q3：為何「真實世界」中的表格理解具有特別重要的價值？**
A：在消費者與企業應用場景中，表格往往以螢幕截圖、掃描檔或照片的形式出現，而非乾淨的數位格式。這些自然存在的表格圖像通常具有高資訊密度、不規則的儲存格跨距、密集內容以及傾斜方向等特徵，對結構感知與數值推理構成嚴峻挑戰。若缺乏針對此類真實場景的評估基準，將難以推動多模態基礎模型在實務應用中的可靠性與可用性。

**Q4：WildTableBench 的核心建構方法為何？**
A：WildTableBench 的建構分為圖像收集與問題設計兩大階段。研究團隊從公開的網路論壇與網站中，蒐集了 402 張涵蓋工作表、交通、運動、教育、金融、科學、工程與醫療等多元領域的真實表格圖像，包含螢幕截圖、掃描檔與照片。接著，研究人員先從實際使用案例中歸納出五大類別共 17 種問題子類型的分類學，再利用大型語言模型生成種子問題，並由專業標註人員進行精修、擴展與交叉驗證，最終產出 928 道高品質問答題組。

**Q5：相較於先前的基準測試，WildTableBench 的關鍵創新為何？**
A：WildTableBench 是首個專為「自然存在」的真實世界表格圖像所設計的問答基準測試，其圖像並非來自程式渲染，而是直接擷取自真實的網路環境。此基準首次系統性地將不規則儲存格跨距、密集內容、裝飾性格式、傾斜方向與背景雜訊等真實視覺特徵納入評估範疇。此外，其問題設計強調非瑣碎的視覺定位與對表格結構及數值的推理，而非僅止於表層的資料查詢。

**Q6：在問題標註過程中，研究團隊做了哪些重要的設計選擇？**
A：研究團隊刻意優先設計需要非瑣碎視覺定位與結構推理的問題，避免僅要求模型進行簡單的表層查詢。他們先檢視公開論壇與網站中的實際使用案例，以此為基礎建立涵蓋儲存格層級理解、數值推理、事實驗證、假設推理與基於顏色的推理等五大類別的分類學。每道問題都經過專業標註人員精修與擴展，確保其語意清晰、無歧義且僅憑圖像即可驗證，並透過交叉驗證確保參考答案的正確性。

**Q7：哪些模型在 WildTableBench 上接受了評估？**
A：研究團隊系統性地評估了 21 個前沿的多模態基礎模型，涵蓋專有閉源模型與開源模型兩大陣營。專有模型包括 Gemini、GPT、Claude 與 Seed 系列，而開源模型則包含 Kimi、GLM 與 Qwen 系列等，同時也納入了這些模型的指令微調版本與強化推理變體。這樣的廣泛評估陣容能夠全面呈現當前模型家族在不同參數規模與訓練策略下，面對真實世界表格圖像時的能力樣貌。

**Q8：實驗結果呈現了哪些關鍵發現？**
A：實驗結果顯示，當前多模態基礎模型在真實世界表格理解上仍面臨巨大挑戰，僅有 Gemini-3-Pro 的準確率超過五成，達到 67.9%，而其餘所有模型的表現皆低於 50.0%，甚至部分模型僅有 4.1% 至 49.9% 的準確率。不同模型家族與參數規模之間存在顯著的性能差異，顯示現有模型普遍難以準確感知複雜的表格結構並進行穩健的數值推理。這些結果明確指出，真實世界表格圖像的多樣性與問題集的廣度對現行模型構成了嚴峻考驗。

**Q9：研究團隊進行了哪些診斷分析以理解模型的失效模式？**
A：研究團隊設計了診斷實驗，量化推理難度與推理預算對模型表現的影響，以深入探究模型失敗的根本原因。分析結果揭示了一個持續存在的弱點：模型對於位於較深層行或列的儲存格，其表現會出現一致的衰退，顯示視覺定位與長距離結構推理能力明顯不足。這些診斷性發現不僅具體刻畫了模型在結構感知與推理上的失效模式，也為未來改善視覺定位機制與結構化解析能力提供了明確的研究方向。

**Q10：真實世界表格理解有哪些實際的應用場景？**
A：真實世界表格理解在消費者與企業情境中均具備極高的應用價值，例如處理網路論壇分享的財務報表截圖、教育領域的作業照片、醫療紀錄掃描檔，或是交通運輸時刻表的螢幕截圖。這些場景中的表格往往以非結構化的圖像形式流通，使用者需要模型能夠自動解析其內容並回答複雜的語意問題。WildTableBench 所涵蓋的多元領域與視覺型態，正是為了模擬這些實務上高頻率出現卻難以處理的真實案例。

**Q11：這項研究對部署表格理解模型提出了哪些產品層面的考量？**
A：這項研究凸顯了在實際產品中部署表格理解模型時，絕不能僅以乾淨的渲染圖像或結構化文字作為性能評估的標準，而必須納入真實環境中的視覺雜訊與版面不規則性。產品開發者應正視模型在處理密集內容、傾斜圖像或裝飾性格式時的脆弱性，並針對結構感知與數值推理進行強化。此外，由於目前僅有極少數模型能達到勉強及格的表現，產品在落地前需設置更嚴謹的人機協作驗證機制，以避免錯誤解析導致的決策風險。

**Q12：WildTableBench 對多模態人工智慧研究領域帶來了什麼樣的影響？**
A：WildTableBench 填補了現有評估體系在真實世界視覺複雜度上的重大空白，為學界與業界提供了一個具診斷價值的標準化評估工具。它不僅系統性地揭示了當前前沿模型在表格結構感知與推理上的具體弱點，也透過細緻的分類學與診斷分析，為後續研究指明了改進視覺定位與結構化理解技術的方向。作為首個專注於自然存在表格圖像的基準測試，它將推動多模態基礎模型從理想化的實驗環境邁向更貼近實務應用的穩健發展。

**Q13：這項研究在範疇與規模上存在哪些可預見的限制？**
A：WildTableBench 目前收錄了 402 張圖像與 928 道問題，雖然具備高品質的人工標註與驗證，但相較於動輒數萬筆資料的純文字基準，其規模仍屬精緻型而非海量型，可能無法窮盡所有真實世界的視覺變異。此外，該基準專注於問答任務，強調語意理解與推理，對於表格結構的逐格精確還原或跨頁表格追蹤等任務的覆蓋較為有限。這些範疇上的邊界意味著未來仍需擴充資料量與任務類型，才能更完整地評估模型的通用表格理解能力。

**Q14：研究發現了哪些一致的模型失效模式？**
A：診斷分析一致顯示，模型在定位與推理位於較深層行或列的儲存格時，表現會顯著下降，顯示其視覺定位與長距離結構關聯能力存在系統性缺陷。此外，無論是專有或開源模型，普遍在準確感知不規則儲存格跨距、解析裝飾性格式以及處理高資訊密度的視覺配置時遭遇困難。這些失效模式表明，當前模型尚未建立對表格空間結構的穩健內部表徵，往往難以將視覺資訊正確對應到邏輯化的結構與數值關係上。

**Q15：這項工作指出了哪些未來的研究方向？**
A：未來研究應優先針對視覺定位與結構感知能力進行強化，特別是改善模型對深層行列與不規則版面配置的解析穩健性。研究者需要開發能夠有效處理真實世界雜訊（如壓縮失真、模糊與傾斜）的新型架構或預訓練策略，以縮小實驗室環境與實務應用之間的落差。此外，擴展基準測試的規模與任務多樣性，並結合更細緻的診斷工具來追蹤模型在結構化推理過程中的中間表徵，將是推動表格圖像理解邁向成熟的重要途徑。

## 實務應用指南

### 適用場景

1. **金融業財報與發票自動化審核**：處理客戶上傳的截圖、掃描檔或手機拍攝的 Excel 表格，進行跨欄位數值比對、異常檢測與事實驗證，解決傳統 OCR 無法理解不規則版面與裝飾性格式的痛點。
2. **醫療檢驗報告單數位化**：將醫院或健檢中心開立的檢驗單照片轉為結構化資料，自動提取關鍵數值並與歷史資料進行趨勢比對，需應對密集內容與傾斜拍攝造成的視覺複雜度。
3. **物流與交通時刻表解析**：理解來自不同官網或論壇截圖的時刻表、運價表，處理不規則合併儲存格與顏色標記，支援自然語言查詢（如「週五最晚一班車的抵達時間」）。
4. **教育領域試卷與成績單分析**：處理學生或教師拍攝的成績單、課表或實驗數據表，進行假設性推理（如「若某科提高五分，平均會變多少」），考驗模型對深層行列的數值推理能力。
5. **企業內部知識庫報表問答**：針對員工上傳的各類業務報表截圖，建立視覺問答系統，無需人工整理成 CSV 即可直接查詢，縮短決策鏈路。

### 實作前置條件

- **資料**：蒐集數百張目標場景的真實表格圖像（螢幕截圖、掃描檔、照片），確保涵蓋版面不規則、密集內容、裝飾性格式與傾斜等視覺變異。需準備對應的高品質問答對與參考答案，並經人工驗證與交叉驗證。
- **運算**：具備前沿多模態基礎模型（如 Gemini、GPT-4V、Claude、Qwen-VL 等）的 API 存取權；若採用開源大型模型本地部署，建議配置 A100 等級 GPU。另需圖像儲存、標註管理與實驗追蹤的基礎設施。
- **技能**：團隊需具備電腦視覺基礎、提示工程（Prompt Engineering）能力、資料標註流程設計經驗，以及熟悉 OCR、表格結構辨識（Table Structure Recognition）與基礎數值運算驗證工具鏈。

### 實作步驟建議

1. **領域盤點與資料蒐集**：界定目標場景（如財務、醫療、物流），從內部系統或公開網路論壇蒐集真實表格圖像，確保樣本包含視覺雜訊與版面不規則案例，避免僅使用乾淨渲染圖或結構化文字。
2. **建立驗證基準（Benchmarking）**：參考 WildTableBench 的五類十七子類型設計問答對，涵蓋儲存格層級理解、數值推理、事實驗證、假設推理與顏色推理。以專業標註人員進行人工標註與交叉驗證，確保答案可單從圖像推導。
3. **模型選型與基線評估**：選定 2–3 個前沿模型（建議至少一個專有模型與一個開源模型）進行零樣本（Zero-shot）評估，記錄準確率與各類型錯誤分布，識別結構感知與數值推理的弱點。
4. **提示工程與推理預算調校**：設計結構化提示，要求模型先描述表格結構再回答問題；調整推理預算（Reasoning Budget）與 Chain-of-Thought 策略，觀察其對深層行列定位與多步驟計算的影響。
5. **錯誤診斷與人機協作迴路**：針對模型在深層行列或密集內容的失效模式，引入視覺前端處理（如透視校正、對比增強）或後處理驗證（如程式化計算檢查），並建立人工複審機制處理低信心度預測。
6. **部署與持續監控**：將模型整合至產品流程，持續收集使用者上傳的真實圖像與錯誤案例，定期擴充驗證集並重新評估，避免模型因視覺風格漂移而退化。

### 潛在風險與注意事項

- **結構感知錯誤**：目前即使最佳模型（Gemini-3-Pro）準確率亦僅 67.9%，多數模型在 50% 以下，部分甚至低於 5%。直接上線可能導致嚴重數值誤判，建議在關鍵業務場景強制加入人工確認或程式化驗證層。
- **視覺雜訊與版面多樣性**：真實世界圖像常含壓縮失真、模糊、傾斜與背景雜訊，實驗室環境的渲染圖表現無法外推。部署前必須以目標場景的實際圖像進行壓力測試。
- **數值幻覺（Numerical Hallucination）**：模型在跨儲存格計算時容易產生幻覺，特別是涉及多步驟推理或假設性情境。應將提取與計算解耦：先以模型擷取結構化數值，再以程式執行運算。
- **顏色與格式過度解讀**：裝飾性格式與顏色標記可能被模型誤判為語意訊號。需明確定義顏色編碼規則，或在提示中要求模型區分「裝飾」與「語意」。
- **資料隱私與授權**：真實表格常含個資或商業機密，蒐集與標註時須符合 GDPR、個資法等規範，並建立去識別化流程。

### 與其他技術的整合建議

- **與 OCR 及表格結構辨識（TSR）串接**：不要完全依賴端到端多模態模型。可先以專用 OCR（如 PaddleOCR、Tesseract）或 TSR 模型提取儲存格座標與文字，再將結構化結果連同原始圖像餵入多模態模型進行問答，降低結構感知負擔。
- **與 RAG 架構結合**：將解析後的表格結構化資料存入向量資料庫或圖資料庫。對於高頻查詢的固定報表，可預先建立結構化索引，僅對新穎或複雜圖像啟用多模態模型即時推理。
- **與程式執行環境（Code Interpreter）整合**：針對數值推理與假設推理類問題，讓多模態模型生成 Python 或 SQL 程式碼，由解釋器執行計算，而非直接輸出答案，可顯著降低計算錯誤率。
- **與文件理解（Document Understanding）系統搭配**：在處理 PDF 或掃描文件時，先以版面分析模型（如 LayoutLM、YOLOv8）偵測表格區域，裁切後再送入專用表格理解管線，避免全頁雜訊干擾。

### 給不同背景讀者的閱讀建議

- **初學者**：這篇論文揭示了「看起來簡單的表格圖片，對 AI 來說其實非常困難」。建議從「適用場景」與「潛在風險」兩節入手，理解真實世界表格與乾淨 Excel 的差異，並認識到目前多模態模型在結構感知上的極限，避免對現成 API 抱持過度樂觀的期待。
- **AI 工程師**：重點關注「實作步驟建議」與「與其他技術的整合建議」。論文中的診斷分析指出深層行列定位與數值推理是主要瓶頸，實作時應優先導入結構化提取與程式化驗證的混合架構，而非追求單一模型的端到端解決方案。
- **研究人員**：論文的貢獻在於填補了真實世界表格圖像評估的空白。建議深入分析 17 種問題子類型的設計邏輯與各模型家族的失效模式，特別是推理難度與推理預算對效能的量化關係，這可作為設計新架構（如專用表格編碼器或視覺定位增強機制）的重要依據。
- **產品經理**：請聚焦「適用場景」與「潛在風險」。目前所有主流模型在真實表格上的準確率均未達生產環境可單獨上線的水準，建議將此技術定位為「輔助提取與草稿生成」而非「全自動無人化處理」，並在產品路線圖中預留人機協作與錯誤回報機制的開發資源。
