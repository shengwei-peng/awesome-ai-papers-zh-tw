# SpatialOPSD：從經驗證的編碼代理軌跡自蒸餾空間智能

**原文標題：** SpatialOPSD: Self-Distilling Spatial Intelligence from Verified Coding Agent Traces

## ⚡ TL;DR

空間編碼代理雖能提升多模態模型的空間推理能力，但推理時需仰賴外部工具，造成高延遲與基礎設施負擔。
本文提出 SpatialOPSD 框架，以代理軌跡為特權進行在線自蒸餾，並以感知重複機制避免洩漏。
實驗顯示此方法在空間與分布外基準上平均超越 SFT 與 GRPO，且無需工具即可逼近代理效能。

## 摘要翻譯

空間編碼代理（Spatial Coding Agent）透過使用外部工具產生經驗證的執行軌跡，顯著提升了多模態大型語言模型（Multimodal Large Language Models, MLLMs）中的空間推理（Spatial Reasoning）能力。然而，此範式本質上存在著令人卻步的推理時間開銷（Inference-Time Overhead）與外部依賴問題。在本文中，我們探討一個多模態大型語言模型是否能夠內化（Internalize）此代理式（Agentic）能力，以完全無需工具（Tool-free）的方式運作。我們首先從一個簡單的觀察談起：將空間編碼代理的摘要執行軌跡作為提示，能自然地開啟模型的內部空間思維鏈（Internal Spatial CoT）。受此啟發，我們提出 SpatialOPSD——一個在線策略自蒸餾（On-Policy Self-Distillation, OPSD）框架，透過將經驗證的代理軌跡視為特權資訊（Privileged Information），將空間推理內化至獨立的多模態大型語言模型（Standalone MLLM）中。為緩解蒸餾過程中的特權資訊洩漏（Privileged-Information Leakage）問題，我們提出感知重複的蒸餾（Repetition-Aware Distillation）方法，結合重複遮罩（Repetition Masking）與非似然正則化（Unlikelihood Regularization）技術。跨多個基準的實驗表明，自蒸餾的 SpatialOPSD 在空間任務與分布外（Out-of-Distribution, OOD）資料集上，平均準確率皆高於監督式微調（Supervised Fine-Tuning, SFT）與群組相對策略優化（Group Relative Policy Optimization, GRPO），展現出優異的效能與泛化能力（Generalization）。

### 核心貢獻（3～5點）
- 提出 SpatialOPSD 框架：將空間編碼代理的經驗證軌跡視為特權資訊，透過在線策略自蒸餾將空間推理能力內化至獨立的多模態大型語言模型中，使其無需依賴外部工具即可執行空間推理。
- 提出感知重複的蒸餾方法：結合重複遮罩與非似然正則化技術，有效緩解自蒸餾過程中的特權資訊洩漏問題，避免模型產生逐字複製（Verbatim Copying）與自我重複（Self-Repetition）等不良行為。
- 實證優於主流訓練範式：在多個空間推理基準上，SpatialOPSD 的平均準確率均超越監督式微調（SFT）與群組相對策略優化（GRPO），展現更佳的效能與泛化能力。
- 揭示關鍵觀察：以空間編碼代理的摘要執行軌跡提示多模態大型語言模型，能自然開啟其內部空間思維鏈，為代理式能力內化提供了簡單而有效的途徑。

### 適合對象
從事多模態大型語言模型、空間推理、知識蒸餾及強化學習研究的學者與工程師；尤其適合關注如何將代理式工具使用能力內化為模型原生能力、探討自蒸餾與強化學習訓練策略的研究人員。

## 深度分析

#### 方法論解析

SpatialOPSD 的方法論建立在兩個關鍵觀察之上：其一，空間編碼代理（Spatial Coding Agent）透過迭代執行程式碼產生的軌跡（traces）能有效引發多模態大型語言模型（MLLMs）的內部空間思維鏈（Internal Spatial CoT）；其二，這種推理時的增益可以透過在線策略自蒸餾（On-Policy Self-Distillation, OPSD）轉化為訓練監督信號，從而讓模型在無需工具（tool-free）的情況下內化空間推理能力。

**空間編碼代理的形式化定義。** 論文將空間編碼代理定義為一個在持久 Python 核心（persistent Python kernel）上運行的系統，該核心配備感知模組（perception modules）與科學計算函式庫（如幾何工具）。對於輸入 $x$，代理產生 $T$ 步軌跡 $\tau = (r_0, a_0, o_0, \ldots, r_t, a_t, o_t, \ldots, y_A)$，其中 $r_t$ 為自然語言推理步驟、$a_t$ 為可執行程式碼片段、$o_t$ 為執行輸出、$y_A$ 為最終答案。策略 $\pi_\theta$ 在每步條件化於歷史上下文生成 $(r_t, a_t)$，核心執行後保留狀態變數供後續步驟使用。這種設計巧妙地將空間推理的「可驗證性瓶頸」（verifiability bottleneck）轉化為可程式化驗證的問題。

**在線策略自蒸餾的數學框架。** OPSD 的核心思想是使用學生模型的初始副本作為凍結教師（frozen teacher），並讓教師條件化於特權資訊（privileged information）$I$。具體而言，對於學生生成的軌跡 $y$，迭代級訓練目標為：

$$\ell_{\text{OPSD}}(y) \triangleq \frac{1}{|y|} \sum_{t=1}^{|y|} D_{\text{KL}}\left(p_\theta(\cdot|x, y_{<t}) \;\|\; p_\phi(\cdot|x, I, y_{<t})\right)$$

其中 $p_\theta$ 為可訓練學生、$p_\phi$ 為凍結教師，兩者從同一檢查點初始化。訓練損失為在線策略學生 rollout 上的期望：

$$L_{\text{OPSD}} = \mathbb{E}_{y \sim p_{\bar{\theta}}(\cdot|x)}[\ell_{\text{OPSD}}(y)], \quad \bar{\theta} = \text{sg}(\theta)$$

此處 $\text{sg}$ 表示停止梯度（stop-gradient），梯度僅流經學生分支。這種設計提供了對學生自身軌跡的密集監督，但同時引入了兩個風險：自我強化重複（self-reinforcing repetition）以及特權資訊洩漏（privileged-information leakage）。

**特權資訊的建構。** SpatialOPSD 將經驗證的代理軌跡摘要為特權資訊 $I$，使學生在訓練時能「窺見」代理的執行過程，但推理時必須獨立完成。這種「軌跡特權設定」（trace-privileged setup）將推理時的計算增益轉化為訓練時的監督信號。

**感知重複的蒸餾（Repetition-Aware Distillation）。** 為緩解上述兩個風險，論文提出結合重複遮罩（repetition masking）與非似然正則化（unlikelihood regularization）的機制。重複遮罩旨在隔離空間推理與執行軌跡中固有的工具特定產物（tool-specific artifacts），避免學生學到工具呼叫模式而非真正的幾何推論；非似然正則化則懲罰逐字複製（verbatim copying）特權內容與自我重複（self-repetition）的行為，迫使模型學習任務相關的推理而非簡單的上下文複製。

**思維鏈的形式化。** 論文將思維鏈（Chain-of-Thought, CoT）形式化為 $p(y, z|x) = p(y|x, z) \cdot p(z|x)$，其中 $z$ 為中間推理依據。值得注意的是，論文指出純文字 CoT 在空間推理中表現不一致——對某些模型與任務有提升，對其他則有損害，這凸顯了單獨生成中間推理並不足以確保有效的空間推理，必須結合執行驗證的軌跡。

#### 實驗數據解讀

**提示策略對比實驗（Figure 2a）。** 論文在 MindCube-Tiny 與 SPAR-Bench-Tiny 兩個基準上，使用 Qwen3.5-9B 比較四種推理設定：

| 設定 | MindCube-Tiny | SPAR-Bench-Tiny |
|------|---------------|-----------------|
| 直接問答（Direct QA） | 40.2% | 48.0% |
| 提示式 CoT（Prompted CoT） | 47.4% | 49.4% |
| 空間編碼代理（Spatial Coding Agent） | 62.9% | 56.6% |
| 代理軌跡條件化 CoT（Agent-Trace-Conditioned CoT） | 63.0% | 57.0% |

此結果揭示一個關鍵現象：僅僅將 CoT 條件化於觀察到的代理軌跡（不再呼叫工具）即可匹配完整代理的性能。這證明了代理軌跡中蘊含的空間推理知識可被模型吸收，無需實際執行工具。

**空間概念頻率分析（Figure 2b）。** 代理軌跡條件化 CoT 顯著提升了生成推理中空間概念的相對頻率：3D/度量概念提升 1.83 倍、反事實運動（counterfactual motion）提升 1.60 倍、視角（perspective）提升 1.30 倍、空間關係（spatial relations）提升 1.09 倍、逐步推理（step-by-step）提升 1.06 倍。這表明代理軌跡有效地將模型的推理「接地」（ground）於具體的空間分析，而非抽象的語言推理。

**主要性能結果。** 根據 Figure 1 與正文描述，SpatialOPSD 在 MindCube 與 ViewSpatial 基準上大幅超越標準 SFT 與 GRPO 基準線，同時在無需工具的情況下接近工具使用空間代理的性能。更重要的是，該方法在分布外（OOD）基準上大幅保留了性能，顯示出優異的泛化能力，且在不同模型規模上均有效。

**消融與泛化意涵。** 論文的實驗設計隱含了幾個重要訊息：(1) 自蒸餾循環（self-distillation loop）的建立——由於依賴自生成軌跡，該範式為幾何推理建立了可持續的改進機制；(2) 規模無關性——在不同模型大小上均觀察到增益，顯示方法的廣泛適用性；(3) OOD 泛化——在空間任務上學到的能力可遷移至其他視覺語言任務，證明學到的是真正的空間理解而非過擬合特定基準。

#### 與現有研究的比較

**與基於工具的空間代理方法的比較。** 現有方法（如 Luo et al., 2026; Cho et al., 2026）將空間推理視為代理式任務（agentic task），透過配備程式碼執行介面與外部幾何工具解決可驗證性瓶頸。SpatialOPSD 的核心優勢在於將這種工具增強推理「內化」到獨立 MLLM 中，消除推理時間的高延遲（high latency）與基礎設施開銷（infrastructure overhead），同時保留大部分性能增益。

**與標準訓練範式的比較。** 與監督式微調（SFT）相比，SpatialOPSD 透過 OPSD 提供了更密集的監督，避免了答案級 SFT 將空間理解保持為隱式且脆弱（brittle）的問題。與 GRPO 等強化學習方法相比，SpatialOPSD 不依賴冷啟動資料（cold-start data）與稀疏結果獎勵（sparse outcome rewards），訓練效率更高。論文明確指出「Lacking verifiable intermediate steps, current RL pipelines are forced to rely on costly cold-start data and sparse outcome rewards」，這是 RL 在空間推理上面臨的核心困境。

**與現有自蒸餾方法的關係。** SpatialOPSD 基於 Zhao et al. (2026a) 提出的 OPSD 框架，但針對空間推理的特殊性進行了關鍵改進：(1) 將代理軌跡作為特權資訊的來源，而非人工設計的提示；(2) 引入感知重複的蒸餾機制，專門處理執行軌跡中固有的工具特定產物與重複模式問題。

**局限性分析。** 儘管成果顯著，該方法仍存在若干限制：(1) 依賴上游空間編碼代理的質量——若代理本身存在系統性錯誤，蒸餾將放大這些錯誤；(2) 特權資訊的摘要策略可能遺失細粒度的幾何資訊；(3) 對於極其複雜的多步空間推理，內化後的模型可能仍無法完全匹配代理的迭代探索能力；(4) 感知重複的蒸餾機制的理論保證尚不明確，其有效性主要來自經驗觀察。

#### 可重現性評估

**程式碼與模型權重。** 根據論文提供的資訊（arXiv:2610.11366v1），目前為預印本（Preprint）狀態，尚未明確聲明程式碼開源。論文中提及的實驗基於 Qwen3.5-9B（Qwen Team, 2026a），這是一個可公開取得的模型。空間編碼代理所依賴的感知模組與科學函式庫（Lin et al., 2025; Carion et al., 2026）以及 MindCube（Yin et al., 2025）和 ViewSpatial（Li et al., 2026a）基準均為公開資源。

**可重現性的關鍵要素。** 從方法論角度，SpatialOPSD 的可重現性取決於：(1) 空間編碼代理的完整實作細節，包括 Python 核心的狀態管理與工具介面；(2) 代理軌跡的摘要策略——論文中未詳細說明如何將 $T$ 步軌跡轉化為特權資訊 $I$；(3) 感知重複蒸餾中超參數的設定，包括重複遮罩的閾值與非似然正則化的權重；(4) OPSD 訓練中的 rollout 策略與 KL 散度的計算細節。

**資料集可及性。** MindCube 與 ViewSpatial 作為公開基準應可取得，但訓練所需的「經驗證代理軌跡」需要自行運行空間編碼代理生成，這對重現構成一定門檻。論文中提及「relying on self-generated traces, this paradigm establishes a self-distillation loop」，暗示在理想情況下可使用學生自身生成的軌跡進行迭代改進，但首次訓練仍需依賴外部代理。

**整體評估。** 在缺乏明確開源承諾的情況下，SpatialOPSD 的可重現性處於中等水平。核心方法論（OPSD + 特權資訊 + 感知重複蒸餾）描述清晰，但實作細節（特別是軌跡摘要與正則化權重）需要從附錄或補充材料中獲取。建議作者在正式發表時提供完整的程式碼與預訓練權重，以促進社區驗證與後續研究。

#### 未來研究方向

**自蒸餾循環的理論分析。** SpatialOPSD 建立了「代理軌跡生成 → 蒸餾 → 學生生成軌跡 → 再蒸餾」的自蒸餾循環。未來研究可探索：(1) 此循環的收斂性理論——在何種條件下迭代蒸餾能持續改進而非陷入局部最優；(2) 循環中錯誤累積的機制與緩解策略；(3) 循環終止的自動化準則。

**特權資訊設計的系統化。** 論文中將代理軌跡摘要為特權資訊，但摘要策略的選擇對最終性能有重大影響。未來方向包括：(1) 學習式摘要——訓練一個神經摘要器自動提取軌跡中的關鍵空間資訊；(2) 多層次特權資訊——區分低層幾何操作與高層推理策略，提供結構化監督；(3) 動態特權資訊——根據學生當前能力調整特權資訊的詳細程度，實現課程式學習。

**感知重複蒸餾的理論深化。** 目前重複遮罩與非似然正則化的組合主要基於經驗。未來可：(1) 從資訊理論角度形式化特權資訊洩漏的度量；(2) 探索更優的正則化形式，如對比學習或資訊瓶頸（information bottleneck）；(3) 分析重複模式與空間推理失敗案例的關聯，建立診斷工具。

**跨模態與跨領域擴展。** SpatialOPSD 的核心思想——將代理的執行軌跡作為特權資訊進行自蒸餾——可推廣至其他需要工具增強推理的領域：(1) 數學推理（符號計算代理軌跡）；(2) 科學推理（模擬實驗代理軌跡）；(3) 程式設計（除錯代理軌跡）。這將建立一個統一的「代理軌跡蒸餾」範式。

**與人類認知對齊。** 空間推理是人類認知的核心組成部分。SpatialOPSD 透過內化代理軌跡獲得的空間智能是否與人類的空間認知機制相似？未來可結合認知科學實驗，分析模型內化後的推理模式與人類空間推理（如心理旋轉、視角轉換）的對應關係，這既可驗證方法的有效性，也可為 AGI 的空間智能研究提供新視角。

**效率與可擴展性優化。** 儘管 SpatialOPSD 消除了推理時的工具依賴，訓練階段仍需運行空間編碼代理生成軌跡，成本不菲。未來方向包括：(1) 軌跡快取與重用機制；(2) 蒸餾過程中的課程學習——從簡單空間任務逐步過渡到複雜任務；(3) 與模型壓縮技術結合，在保持空間推理能力的同時降低模型規模。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？為什麼空間推理對多模態大型語言模型（MLLM）來說特別困難？**
A：這篇論文要解決的核心問題是如何讓多模態大型語言模型具備強健的空間推理能力，同時避免依賴外部工具所帶來的推理時間開銷。空間推理之所以特別困難，是因為它要求模型從二維觀察中推斷出潛在的三維屬性，例如物體的幾何關係、視角變化與反事實運動等。雖然最終答案通常可以被驗證，但中間的幾何推論步驟卻難以自動標註或驗證，這形成了所謂的「可驗證性瓶頸」，使得標準的監督式微調與強化學習方法都難以有效運作。

**Q2：為什麼現有的訓練方法（如 SFT、CoT 監督、GRPO）在空間推理任務上表現不佳？**
A：標準的監督式微調（SFT）僅在答案層級提供監督，迫使空間理解以隱式且脆弱的方式存在於模型中，缺乏明確的推理過程。顯式的思維鏈（CoT）監督雖然能提供中間推理步驟，但標註成本極高且難以規模化。GRPO 等強化學習方法雖然能透過探索繞過標註瓶頸，但由於缺乏可驗證的中間步驟，目前的強化學習流程被迫依賴昂貴的冷啟動資料與稀疏的結果獎勵，導致訓練效率低落。

**Q3：為什麼「空間編碼代理」雖然有效，卻不是理想的最終解決方案？**
A：空間編碼代理透過配備程式碼執行介面與外部幾何工具，讓模型能以迭代方式撰寫並執行程式碼來解決空間問題，這種代理式範式優雅地解決了可驗證性瓶頸。然而，這種方案僅僅將負擔轉移到了推理階段，因為反覆的解碼與工具執行循環會引入高延遲與基礎設施開銷。因此，研究的動機在於探問：是否能讓 MLLM 從這些經驗證的代理軌跡中內化空間推理能力，從而在推理時完全無需工具？

**Q4：SpatialOPSD 的核心方法是什麼？它如何將代理能力內化到模型中？**
A：SpatialOPSD 的核心方法是「在線策略自蒸餾」（On-Policy Self-Distillation, OPSD），它將經驗證的空間編碼代理軌跡轉化為特權資訊，用於蒸餾一個獨立的 MLLM。具體而言，學生模型與凍結的教師模型都從同一個檢查點初始化，教師模型在生成軌跡時會被給予特權資訊（即代理的執行軌跡摘要），而學生模型則基於自身的在線策略 rollout 進行訓練。透過 KL 散度對齊學生與教師的輸出分布，模型得以將工具輔助的空間推理能力內化為自身的隱性能力。

**Q5：什麼是「重複感知蒸餾」（Repetition-Aware Distillation）？為什麼需要它？**
A：重複感知蒸餾是 SpatialOPSD 的一項關鍵創新，結合了「重複遮罩」與「非似然正則化」兩種技術，用以緩解在線策略自蒸餾中的特權資訊洩漏問題。在蒸餾過程中，教師模型可能會鼓勵學生逐字複製特權資訊中的內容，或產生自我重複的延續，這兩種行為都不利於學習任務相關的推理。重複遮罩會遮蔽掉重複的片段，而非似然正則化則會對這些被遮罩的 token 施加懲罰，從而促使學生學會真正的空間推理，而非單純地記憶或複製代理軌跡。

**Q6：為什麼選擇將代理軌跡視為「特權資訊」而非直接用於監督式微調？這樣的設計選擇帶來什麼好處？**
A：將代理軌跡視為特權資訊而非直接的監督標籤，是因為代理軌跡中混雜著工具特定的產物（例如程式碼片段、執行輸出），這些內容在推理時並不可用。透過在線策略自蒸餾的框架，模型被鼓勵在自身的 rollout 上學習，而非被動地模仿代理軌跡。這種設計使得訓練過程能夠隔離空間推理與工具特定產物，讓學生模型學會的是「為什麼這樣推理」，而非「如何複製這些軌跡」，從而實現真正的能力內化。

**Q7：SpatialOPSD 在哪些基準測試上進行了評估？為什麼選擇這些基準？**
A：SpatialOPSD 主要在 MindCube（含 MindCube-Tiny 子集）與 ViewSpatial 兩個空間推理基準上進行評估。MindCube 與 ViewSpatial 都是專門設計來測試多模態模型在三維空間理解、視角轉換、反事實運動等方面能力的基準，能夠全面衡量模型的空間推理水平。此外，論文還在分布外（OOD）基準上進行了泛化測試，以驗證 SpatialOPSD 是否會犧牲模型在其他任務上的表現。

**Q8：SpatialOPSD 的關鍵實驗結果是什麼？它相較於基準方法有何優勢？**
A：實驗結果顯示，SpatialOPSD 在多個基準上的平均準確率均優於 SFT 與 GRPO 等基準訓練方法，展現出更佳的性能與泛化能力。值得注意的是，雖然 SpatialOPSD 在推理時完全無需使用工具，但其表現已接近使用工具的空間編碼代理。此外，SpatialOPSD 在分布外基準上仍能維持大部分性能，並在不同的模型規模上皆觀察到一致的提升，證明了該方法的廣泛適用性。

**Q9：論文中進行了哪些消融實驗來驗證各個設計選擇的必要性？**
A：論文中透過比較四種推理設定（直接問答、提示式 CoT、空間編碼代理、代理軌跡條件式 CoT）來驗證代理軌跡作為特權資訊的有效性，結果顯示僅僅以代理軌跡作為條件就能匹配完整代理的性能。此外，論文中也展示了代理軌跡條件式 CoT 顯著提升了生成推理中對三維感知（1.8 倍）與反事實運動（1.6 倍）等空間概念的引用頻率，這證明了軌跡確實能引導模型產生更具空間性的推理。重複感知蒸餾的引入則是為了對抗特權資訊洩漏，雖然具體的消融數據未在摘錄中詳列，但該設計被明確指出是為了隔離空間推理與工具特定產物。

**Q10：SpatialOPSD 在實際應用場景中有哪些潛在價值？**
A：SpatialOPSD 在實際應用中具有廣泛的價值，特別是在需要即時空間推理但無法依賴外部工具的場景。例如，在機器人導航、擴增實境、自動駕駛等邊緣部署環境中，模型需要在低延遲、無網路連線的條件下進行空間推論。透過將代理能力內化，SpatialOPSD 使得模型能夠在沒有程式碼執行環境或幾何工具的情況下，依然保持高品質的空間推理能力，大幅降低了部署成本與基礎設施需求。

**Q11：從產品化的角度來看，SpatialOPSD 帶來了哪些具體的優勢？**
A：從產品化角度來看，SpatialOPSD 的最大優勢在於「無需工具」的推理模式，這意味著產品可以省去維護程式碼執行沙箱、幾何工具庫等基礎設施的成本。同時，由於不需要迭代式的解碼與工具呼叫循環，推理延遲大幅降低，使用者體驗更為流暢。此外，該方法依賴於自身生成的軌跡形成自蒸餾迴路，這意味著隨著使用規模擴大，模型可以不斷自我改進，而無需持續收集昂貴的人工標註資料。

**Q12：SpatialOPSD 對空間智慧研究領域有什麼更廣泛的影響？**
A：SpatialOPSD 對空間智慧研究領域的影響在於它建立了一個「自蒸餾迴路」的範式，用於幾何推理。這個範式不僅解決了當前空間推理的可驗證性瓶頸，還為其他需要中間推理步驟但難以標註的領域（如科學推理、數學證明）提供了借鏡。更重要的是，這種從「工具輔助」到「能力內化」的轉變路徑，可能成為未來構建更強大、更自主的多模態智慧系統的關鍵策略之一。

**Q13：SpatialOPSD 存在哪些已承認的限制？**
A：儘管 SpatialOPSD 展現了優異的性能，但從論文中仍可推斷出一些限制。首先，該方法依賴於空間編碼代理能夠產生高品質的執行軌跡，這意味著代理本身的性能上限會影響蒸餾的效果。其次，雖然重複感知蒸餾能緩解特權資訊洩漏，但無法完全消除這一風險，學生模型仍可能學到一些與工具相關的偽相關。此外，論文中也提到文本式 CoT 在空間推理上的效果因模型與任務而異，這暗示了 SpatialOPSD 的效果可能也會受到基礎模型特性的影響。

**Q14：在什麼樣的情況下，SpatialOPSD 可能會失敗或表現不佳？**
A：SpatialOPSD 可能會在以下情況下表現不佳：當空間任務的複雜度超出代理軌跡所能涵蓋的範圍時，學生模型可能無法從中學到足夠的推理策略；當測試時的輸入分布與訓練時顯著不同（例如極端的視角變化或未曾見過的空間配置）時，模型的泛化能力可能受到挑戰。此外，如果基礎模型本身在空間概念的理解上存在根本性的缺陷，那麼僅靠蒸餾可能無法完全彌補這些不足，因為自蒸餾的本質是「從自身出發」的學習。

**Q15：基於 SpatialOPSD 的成果，未來有哪些值得探索的研究方向？**
A：基於 SpatialOPSD 的成果，未來有幾個值得探索的方向。首先，可以將這種「工具輔助到能力內化」的範式擴展到其他需要中間推理的領域，例如程式碼生成、數學證明或科學假說檢驗。其次，可以進一步研究如何讓自蒸餾迴路更加穩健，例如透過更先進的正則化技術或更豐富的特權資訊形式。此外，探索如何將多個不同代理的軌跡融合起來進行蒸餾，以獲得更全面的空間智能，也是值得嘗試的方向。最後，將這種方法應用於更大規模的模型或更多模態的輸入（如點雲、深度圖），可能會帶來更強大的空間推理系統。

## 實務應用指南

### 適用場景

**1. 機器人與自主導航系統**
在服務型機器人、無人機、倉儲自動化等場景中，代理需即時理解三維空間關係（障礙物距離、可行路徑、相對方位）。SpatialOPSD 訓練後的模型可在無外部幾何工具（如點雲處理庫、SLAM 模組）的情況下完成空間推論，適合部署於運算資源受限的邊緣裝置，降低延遲並減少對雲端工具鏈的依賴。

**2. 擴增實境（AR）與虛擬實境（VR）內容生成**
AR/VR 應用常需根據單張或少量 2D 影像推斷場景三維結構，以正確放置虛擬物件或規劃使用者移動軌跡。SpatialOPSD 內化的空間思維鏈可協助模型判斷「若相機移動，物體將如何相對位移」（反事實運動），這正是 Figure 2b 中提及的關鍵能力提升項。

**3. 電腦輔助設計（CAD）與建築視覺化**
室內設計、裝潢配置、建築預覽等應用中，使用者常以 2D 平面圖或照片詢問空間配置問題。SpatialOPSD 可讓模型直接回答「沙發能否通過此走廊？」、「此房間能否容納 L 型沙發？」等問題，無需即時呼叫幾何運算工具。

**4. 醫療影像三維重建輔助診斷**
在 CT、MRI 等 2D 切片的空間關係推斷任務中，模型需理解器官在三維空間中的相對位置。SpatialOPSD 訓練後的模型可作為輔助診斷工具的推理引擎，在不依賴外部三維視覺化工具的情況下提供初步空間分析。

**5. 智慧家庭與物聯網情境感知**
智慧音箱、居家機器人需理解「杯子在桌子左邊」、「窗戶在沙發對面」等空間描述以執行指令。SpatialOPSD 內化的空間推理能力可強化此類裝置的指令理解正確率，且無需在裝置端維護 Python 執行環境。

### 實作步驟建議

**步驟一：建置空間編碼代理**
部署具備 Python 執行介面的 MLLM 代理，整合感知模組（如深度估計、物件偵測）與幾何運算函式庫。代理需能迭代產生推理步驟 `r_t`、可執行程式碼 `a_t`，並接收執行輸出 `o_t`，最終輸出答案 `y_A`。建議先在 MindCube-Tiny 子集驗證代理的正確率，確認其空間推理能力優於直接問答與一般 CoT 提示。

**步驟二：採集並驗證代理軌跡**
在目標訓練資料集上運行代理，收集完整的 T 步軌跡 `τ = (r_0, a_0, o_0, ..., r_T, a_T, o_T, y_A)`。僅保留最終答案正確的軌跡作為「已驗證軌跡」。建議過濾掉執行逾時、語法錯誤或答案不一致的樣本，以確保訓練信號品質。

**步驟三：將軌跡摘要為特權資訊**
將已驗證軌跡摘要為結構化的特權資訊 `I`，供教師模型使用。摘要應保留關鍵的空間推理內容（3D 度量、反事實運動、視角變換），但需隔離工具特定產物（如具體的 API 呼叫、變數名稱、堆疊追蹤）。可使用較強的 LLM（如 GPT-4、Qwen3.5-Max）作為摘要器，並以人工抽樣檢核摘要品質。

**步驟四：實作 OPSD 訓練框架**
複製基礎模型（Qwen3.5-9B）兩份，分別作為學生 `p_θ`（可訓練）與教師 `p_ϕ`（凍結）。學生先以自身參數 `θ̄ = sg(θ)` 採樣軌跡 `y`，再以 KL 散度對齊教師在特權資訊 `I` 條件下的輸出分布。實作時需注意：學生採樣階段的參數需停止梯度（stop-gradient），僅學生分支的 KL 計算保留梯度。

**步驟五：加入感知重複的蒸餾機制**
實作 Repetition-Aware Distillation，包含兩個組件：
- **重複遮罩（Repetition Masking）**：在計算 KL 散度時，遮罩掉學生與教師輸出中重複的 n-gram，避免鼓勵逐字複製特權內容。
- **非似然正則化（Unlikelihood Regularization）**：對學生產生重複片段的機率施加懲罰項，降低自我重複傾向。
兩者結合可緩解特權資訊洩漏與自我強化重複兩大風險。

**步驟六：訓練、評估與迭代**
在 MindCube 與 ViewSpatial 上進行訓練，並於訓練週期中定期評估空間任務與 OOD 任務的準確率。建議監控以下指標：(1) 空間任務平均準確率；(2) OOD 任務的準確率下降幅度（應控制在 5% 以內）；(3) 學生輸出中對特權內容的逐字複製比例（應隨訓練下降）。若 OOD 退化過大，可考慮加入一般指令遵循資料進行混合訓練。

**步驟七：部署為無需工具的服務**
訓練完成後，僅部署學生模型，無需保留 Python 執行環境或幾何工具鏈。模型可直接整合至邊緣裝置、行動應用或低延遲服務，推理成本接近標準 MLLM 的單次前向傳遞。

### 潛在風險與注意事項

**風險一：特權資訊洩漏（Privileged-Information Leakage）**
- **現象**：學生模型學會在輸出中重現特權資訊中的具體細節（如特定座標值、API 呼叫結果），而非學習背後的推理邏輯。部署後遇到類似問題時，模型會「卡住」等待不存在的工具輸出。
- **緩解**：嚴格執行 Repetition-Aware Distillation；在評估集中加入「無特權資訊可參考」的測試案例，觀察模型是否仍能正確推理；定期以人工檢核學生輸出的推理鏈是否具備邏輯連貫性。

**風險二：自我強化重複（Self-Reinforcing Repetition）**
- **現象**：OPSD 的教師由學生初始化，可能在訓練初期就認可學生的重複模式，導致模型陷入「重複 → 被認可 → 更加重複」的循環。
- **緩解**：非似然正則化項應在訓練初期即啟用，並隨訓練進度調整懲罰強度；監控輸出序列的 distinct-n 指標，若連續多個檢查點下降則需介入。

**風險三：工具特定產物污染**
- **現象**：代理軌跡中摻雜工具呼叫的副作用（如錯誤訊息、除錯輸出、特定函式庫的怪異行為），學生可能誤將其視為推理內容。
- **緩解**：在步驟三的摘要階段嚴格過濾；建立「乾淨軌跡」與「原始軌跡」對照實驗，量化工具產物對最終準確率的影響。

**風險四：泛化能力下降**
- **現象**：在空間任務上表現優異，但在 OOD 任務（如一般 VQA、OCR）上顯著退化。
- **緩解**：採用混合訓練策略，將空間資料與一般指令資料按比例（如 7:3）混合；定期評估 OOD 基準，設定早停條件。

**風險五：軌跡品質不穩定**
- **現象**：代理在不同問題類型上的成功率差異大，部分類別的軌跡可能系統性錯誤。
- **緩解**：按問題類型分層採樣軌跡，確保各類別的驗證通過率達標；對低通過率類別進行錯誤分析，必要時人工修正或排除。

**風險六：運算成本超支**
- **現象**：軌跡採集階段需大量代理呼叫，OPSD 訓練需同時載入學生與教師模型，整體成本可能遠高於標準 SFT。
- **緩解**：優先在小規模資料集驗證可行性；採用軌跡快取與重用機制；考慮使用較小的學生模型（如 4B）進行初步實驗。

### 與其他技術的整合建議

**與現有 MLLM 微調流程整合**
SpatialOPSD 可作為既有 SFT 流程的「進階階段」：先以標準 SFT 建立基礎指令遵循能力，再以 OPSD 進行空間推理專項強化。建議保留 SFT 階段的資料混合比例，避免 OPSD 階段過度專注空間任務而犧牲通用性。

**與強化學習方法互補**
SpatialOPSD 與 GRPO 並非互斥。可考慮兩階段訓練：先以 SpatialOPSD 內化代理的推理模式，再以 GRPO 進行結果導向的強化學習。此時 SpatialOPSD 提供的密集監督可大幅降低 GRPO 對冷啟動資料的需求，提升樣本效率。

**與代理框架共存**
在資源充足的場景中，可保留空間編碼代理作為「專家系統」，SpatialOPSD 訓練後的模型作為「輕量級替代」。根據問題難度動態路由：簡單問題由獨立模型處理，複雜問題升級至代理，形成分層服務架構。

**與邊緣部署技術整合**
訓練後的學生模型可與量化（INT4/INT8）、剪枝、知識蒸餾等邊端優化技術結合，進一步降低部署成本。SpatialOPSD 內化的推理模式對量化較為友善，因為其輸出分布相對集中於空間推理相關詞彙。

**與視覺編碼器升級路徑整合**
當視覺編碼器（如 ViT、SigLIP）升級時，SpatialOPSD 的訓練流程可平行擴展：保留語言端的 OPSD 機制，僅替換視覺編碼器並重新對齊。建議建立模組化的訓練 pipeline 以支援此類迭代。

**與評估與監控系統整合**
將空間推理準確率、OOD 退化率、輸出重複率等指標整合至 MLOps 監控平台，設定自動化警報。當指標偏離預期時，自動觸發再訓練或人工審查流程。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先閱讀第 1 節（Introduction）以理解「為何空間推理對 MLLM 是難題」以及「為何需要內化代理能力」，再閱讀第 3.1 節（Motivation）中的 Figure 2，直觀感受不同提示策略的效果差異。技術細節可先跳過，重點掌握「用已驗證的代理軌跡作為訓練信號」這個核心概念。閱讀時可搭配查閱思維鏈（CoT）與知識蒸餾的基礎教材，建立先備知識。

**給 AI 工程師**
重點閱讀第 2 節（Preliminary）中的 OPSD 數學定義（公式 2、3）與第 3 節的完整方法描述，特別是 Repetition-Aware Distillation 的實作細節。建議直接從論文的開源程式碼（若釋出）著手，先重現小規模實驗（如在 MindCube-Tiny 上以較小模型驗證），再逐步擴展至完整設定。實作時需特別注意學生採樣階段的 stop-gradient 處理，以及 KL 散度的計算粒度（token-level vs. sequence-level）。

**給研究者**
重點關注三個面向：(1) 特權資訊洩漏的理論分析——為何 OPSD 在空間任務上特別容易出現此問題；(2) Repetition-Aware Distillation 的消融實驗設計——重複遮罩與非似然正則化的相對貢獻；(3) 與 GRPO 等強化學習方法的理論比較——密集監督 vs. 稀疏獎勵的樣本效率邊界。建議延伸思考：此框架是否可應用於其他具備「可驗證代理軌跡」但缺乏中間標註的領域（如數學證明、化學反應設計）。

**給產品經理**
聚焦於「商業價值」與「部署可行性」兩個維度。SpatialOPSD 的核心價值在於：將原本需仰賴外部工具鏈的高延遲空間推理，轉化為單次模型推論的低延遲服務，這對延遲敏感的應用（如機器人控制、AR 互動）至關重要。部署成本方面，無需維護 Python 執行環境與幾何函式庫，可顯著降低基礎設施開銷。建議評估時優先考慮「空間推理為核心功能且對延遲敏感」的產品場景，並預留 A/B 測試資源以驗證 OOD 泛化表現。
