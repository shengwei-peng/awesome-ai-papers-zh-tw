# CausalCine：多鏡頭影片敘事之即時自迴歸生成

## ⚡ TL;DR

解決現有自迴歸影片模型在多鏡頭長片生成中動作停滯與語意漂移的問題。
提出 CausalCine 框架，結合多鏡頭因果基底模型與內容感知記憶路由，並蒸餾為即時生成器。
14B 模型在 8 張 H200 GPU 上達 16 FPS 串流，超越自迴歸基準並逼近雙向模型。

## 摘要翻譯

自迴歸影片生成（Autoregressive Generation）旨在達成即時、開放式的合成（Open-Ended Synthesis）。然而，電影級敘事（Cinematic Storytelling）並非僅是單一場景的無限延伸；它需要隨著事件演進、視角轉換（Viewpoint Shift）以及離散的鏡頭邊界（Shot Boundary）而推進。現有的自迴歸模型在此設定下往往表現不佳。這些模型主要為短時域延續（Short-Horizon Continuation）所訓練，將長序列視為延伸的單一鏡頭，因此在長序列推展（Long Rollout）期間不可避免地遭受動作停滯（Motion Stagnation）與語意漂移（Semantic Drift）的問題。為彌合此落差，我們提出 CausalCine，一個將多鏡頭影片生成（Multi-Shot Video Generation）轉化為線上導演流程（Online Directing Process）的互動式自迴歸框架（Interactive Autoregressive Framework）。CausalCine 能夠在鏡頭轉換（Shot Transition）間進行因果生成（Causal Generation），即時接受動態提示詞（Dynamic Prompt），並在無需重新生成先前鏡頭的情況下重用上下文（Context Reuse）。為實現此目標，我們首先在原生多鏡頭序列（Native Multi-Shot Sequence）上訓練一個因果基底模型（Causal Base Model），以便在後續蒸餾加速之前，先學會複雜的鏡頭轉換。接著，我們提出內容感知記憶路由（Content-Aware Memory Routing, CAMR），該方法根據基於注意力的相關性分數（Attention-Based Relevance Score）而非時間鄰近性（Temporal Proximity）來動態擷取歷史 KV 條目（KV Entry），在有界活躍記憶體（Bounded Active Memory）的限制下維持跨鏡頭一致性（Cross-Shot Coherence）。最後，我們將因果基底模型蒸餾（Distillation）為一個少步驟生成器（Few-Step Generator），以實現即時互動生成（Real-Time Interactive Generation）。大量實驗證明，CausalCine 顯著優於自迴歸基準模型（Baseline），並在解鎖因果生成之串流互動性（Streaming Interactivity）的同時，逼近雙向模型（Bidirectional Model）的能力。展示頁面（Demo）請見 https://yihao-meng.github.io/CausalCine/

### 核心貢獻（3～5點）
- **提出 CausalCine 框架**：將多鏡頭影片生成重新定位為線上導演流程，使自迴歸模型能夠在鏡頭轉換間進行因果生成、即時接受動態提示詞，並支援上下文重用而無需重新生成先前鏡頭。
- **訓練原生多鏡頭因果基底模型**：直接在原生多鏡頭序列上訓練因果基底模型，使其在蒸餾加速之前即學會複雜的鏡頭轉換先驗，從根本上緩解動作停滯與語意漂移問題。
- **設計內容感知記憶路由（CAMR）**：以基於注意力的相關性分數取代傳統的時間鄰近性作為 KV 條目的擷取依據，在有界活躍記憶體下有效維持跨鏡頭一致性。
- **蒸餾為少步驟生成器**：將因果基底模型蒸餾為少步驟生成器，兼顧視覺品質與即時互動生成效率。
- **實驗驗證**：在多鏡頭影片敘事任務上，CausalCine 顯著優於自迴歸基準模型，並逼近雙向模型的生成能力，同時保有因果生成特有的串流互動性。

### 適合對象
本論文最適合以下讀者閱讀：
- 從事**影片生成、擴散模型（Diffusion Video Model）與自迴歸生成**研究的學者與工程師，特別關注長序列、多鏡頭敘事生成者；
- 對**即時互動式生成、串流影片合成（Streaming Video Synthesis）**及其在創意內容產業應用感興趣的研究人員；

## 深度分析

#### 方法論解析

CausalCine 的方法論核心在於將「多鏡頭影片生成」重新定位為一個「線上導演流程」(online directing process)，而非傳統的單一場景延伸。其技術架構由三大支柱構成，每一項都針對現有自迴歸影片模型在長序列推展 (long rollout) 中的具體缺陷進行設計。

**第一支柱：原生多鏡頭因果基底模型 (Causal Base Model)**

作者提出一個關鍵觀察：「長序列因果行為應在加速之前學習」。這與現有方法（如 CausVid [55]、Self Forcing [17]）的策略形成對比——後者通常先將雙向擴散模型 (bidirectional diffusion model) 直接蒸餾為快速自迴歸生成器 (fast autoregressive generator)。CausalCine 反其道而行，先在原生多鏡頭序列 (native multi-shot sequence) 上以教師強制 (teacher forcing) 訓練一個全步因果多鏡頭基底模型 (full-step causal multi-shot base model)。

具體而言，模型採用 **2N 區段教師強制佈局 (2N-segment teacher-forcing layout)**（圖 2a），將多個鏡頭的因果依賴結構在單一平行前向傳遞中學習。這種設計使模型在訓練階段就能觀察到鏡頭邊界 (shot boundary)、提示詞變更、長距離實體再現 (long-range entity reappearance) 等現象，從而大幅縮減教師強制推展落差 (teacher-forcing rollout gap)。換言之，模型在訓練時所見的因果依賴結構與推論時使用 KV 快取 (KV cache) 的結構一致，這是穩定長序列推展的基礎。

**第二支柱：內容感知記憶路由 (Content-Aware Memory Routing, CAMR)**

這是本文最具創新性的技術貢獻。傳統自迴歸影片模型在處理長序列時，依賴滑動窗口 (sliding window) 或固定錨點 (fixed anchor) 來保留局部外觀 (local appearance) 與動作連續性 (motion continuity)。然而，在多鏡頭情境下，有用的上下文不再由時間鄰近性 (temporal proximity) 決定——模型可能需要從遙遠的過去召回某個角色、忽略緊鄰的前一個場景，或結合多個早期鏡頭的語意線索。

CAMR 的設計如圖 2c 所示，包含以下步驟：
1. **每幀內容描述子 (per-frame content descriptor)**：對歷史 KV 條目 (KV entry) 進行 K-projection 平均池化，得到 $d_i \in \mathbb{R}^{L \times D}$ 的描述子。
2. **每區塊查詢描述子 (per-chunk query descriptor)**：對當前區塊的查詢進行 Q-projection 平均池化，得到 $q_i \in \mathbb{R}^{L \times D}$。
3. **基於注意力的相關性分數 (attention-based relevance score)**：計算 $s_{i,j} = q_i \cdot d_j$，並選取 top-k 最相關的歷史幀。
4. **區塊相對 RoPE 重錨定 (Block-Relative RoPE re-anchoring)**：將選取幀的位置編碼重新映射到訓練範圍內，避免長序列推展時的位置相位漂移。

此機制的關鍵洞見在於：跨鏡頭一致性 (cross-shot coherence) 應由「語意相關性」而非「時間距離」驅動。這使得模型能在有界活躍記憶體 (bounded active memory) 約束下，動態保留真正有用的長距離上下文。

**第三支柱：少步驟蒸餾 (Few-Step Distillation)**

在因果基底模型已學會多鏡頭結構之後，作者採用分佈匹配蒸餾 (Distribution Matching Distillation, DMD) [54, 53] 將其壓縮為少步驟生成器 (few-step generator)。由於因果性與多鏡頭結構已在前一階段習得，DMD 此時可專注於軌跡壓縮 (trajectory compression)，同時保留視覺品質與跨鏡頭一致性。

**輔助機制：每鏡頭交叉注意力 (Per-Shot Cross-Attention)**

如圖 2b 所示，模型為每個鏡頭維護獨立的文字 KV 條目 (per-shot text key-value)，並透過交叉注意力將當前區塊路由至其對應的活躍鏡頭提示詞。這使得使用者能在生成過程中動態更新提示詞 (dynamic prompt)，而無需重新生成先前鏡頭。

整體而言，CausalCine 的方法論展現出一種「先學正確因果行為，再壓縮效率」的訓練哲學，與「先追求效率，再修補長序列缺陷」的傳統路線形成鮮明對比。

#### 實驗數據解讀

根據論文摘要與引言所述，CausalCine 在多個維度上顯著超越自迴歸基準模型 (autoregressive baseline)，並逼近雙向模型 (bidirectional model) 的能力。具體實驗結果可從以下幾個層面解讀：

**1. 鏡頭級品質 (Shot-Level Quality)**

CausalCine 在單一鏡頭內的視覺品質上接近雙向擴散模型，這驗證了「先訓練因果基底模型再蒸餾」策略的有效性。傳統直接蒸餾方法（如 CausVid）在短時域延續 (short-horizon continuation) 上表現尚可，但在長序列推展時容易出現動作停滯 (motion stagnation) 與語意漂移 (semantic drift)。CausalCine 透過原生多鏡頭訓練，從根本上緩解了這些問題。

**2. 提示詞對齊 (Prompt Alignment)**

由於採用每鏡頭交叉注意力機制，模型能精確遵循各鏡頭的獨立提示詞。這對於多鏡頭敘事至關重要——例如圖 1 所示，使用者可依序指定「高角度全景鏡頭 (high-angle wide shot)」、「中景鏡頭 (medium shot)」、「特寫鏡頭 (close-up)」等不同視角與構圖指令。

**3. 身份保留 (Identity Preservation)**

跨鏡頭的身份一致性是多鏡頭生成的經典難題。CausalCine 透過 CAMR 機制，能在後續鏡頭中召回早期鏡頭的角色外觀資訊，即使該角色在時間軸上已遠離當前生成位置。這驗證了「內容相關性優於時間鄰近性」的核心假設。

**4. 轉換結構 (Transition Structure)**

模型能生成自然的鏡頭轉換 (shot transition)，而非將多鏡頭影片視為單一場景的延伸。這是 CausalCine 與現有自迴歸模型最關鍵的區別——後者往往將長序列視為擴展的單一鏡頭，導致轉換生硬或缺乏敘事節奏。

**5. 系統效能**

CausalCine 建構於 14B 參數的影片生成器上，於 8 張 NVIDIA H200 GPU 上以 16 FPS 串流輸出。這代表即時互動生成 (real-time interactive generation) 已達到實用規模——使用者可在生成過程中隨時插入新提示詞，模型會即時調整後續鏡頭內容，同時保留先前鏡頭的 KV 快取，無需重新計算。

**實驗結果的深層意涵**

值得注意的是，論文強調 CausalCine「逼近雙向模型能力」的同時「保留了因果生成的串流互動性 (streaming interactivity)」。這意味著在品質-效率權衡曲線上，CausalCine 找到了一個新的最優邊界：過去使用者必須在「高品質但無法互動」（雙向模型）與「可互動但品質受限」（自迴歸模型）之間二擇一，現在則可同時獲得兩者優勢。

#### 與現有研究的比較

**與自迴歸影片模型的比較**

CausalCine 與 CausVid [55]、Self Forcing [17]、Causal Forcing [62] 等近期自迴歸影片模型的差異在於「訓練目標的設定」。這些方法主要設計用於單一場景延續，將長影片生成視為局部動作模式 (local motion pattern) 的擴展。當推展超出單一局部模式時，它們容易停滯、循環或語意漂移。CausalCine 則明確將多鏡頭結構納入訓練目標，使模型天生具備處理鏡頭邊界、視角轉換 (viewpoint shift) 與持續故事脈絡 (persistent story context) 的能力。

**與多鏡頭影片生成方法的比較**

現有多鏡頭方法（如基於腳本、鏡頭或關鍵幀分解的方法 [1, 16, 28, 44, 50, 58, 48, 60, 61]）通常將任務分解為離散的子任務，並以短影片模型逐一生成各片段。這種「離線規劃」策略雖然能產生結構化的多鏡頭影片，但缺乏即時互動性——使用者無法在生成過程中動態調整敘事方向。CausalCine 的線上導演流程則保留了自迴歸生成的串流特性，同時支援多鏡頭結構。

**與長上下文自迴歸系統的比較**

部分長上下文自迴歸系統採用滾動快取、局部窗口、固定錨點或執行階段提示詞更新 [51, 26, 52, 8] 來擴展生成長度。然而，這些機制仍以時間鄰近性為記憶選擇依據，在多鏡頭情境下會遺失重要的長距離語意關聯。CausalCine 的 CAMR 機制則以內容相關性取代時間鄰近性，這是記憶管理範式的根本轉變。

**CausalCine 的局限性**

儘管 CausalCine 在多個維度上表現優異，仍存在以下潛在限制：
1. **訓練資料需求**：原生多鏡頭序列資料的規模與品質直接影響模型表現，此類資料的蒐集與標註成本可能較高。
2. **硬體門檻**：14B 參數模型搭配 8 張 H200 GPU 的配置，對一般研究機構而言仍屬高門檻部署。
3. **鏡頭邊界的隱式學習**：模型雖能處理鏡頭轉換，但轉換的時機與風格仍由訓練資料決定，使用者對轉換節奏的細粒度控制能力可能有限。
4. **CAMR 的計算開銷**：每個區塊生成時需計算所有歷史 KV 條目的相關性分數，雖然 top-k 選擇降低了實際讀取的條目數，但分數計算本身仍隨序列長度線性增長。

#### 可重現性評估

**程式碼與模型權重**

根據論文提供的資訊，目前僅有展示頁面 (demo) 公開（https://yihao-meng.github.io/CausalCine/），論文中並未明確聲明是否將釋出訓練程式碼、推論程式碼或預訓練模型權重。對於一個涉及 14B 參數模型、8 張 H200 GPU 訓練配置的研究而言，完全重現的門檻極高。

**資料可及性**

論文提及使用「原生多鏡頭序列」進行訓練，但未在提供的文本片段中具體說明資料來源、規模或標註流程。這對重現性構成挑戰——若使用私有資料集，外部研究者將難以複製實驗結果。

**實驗細節**

論文中描述了 CAMR 的數學形式（如 $s_{i,j} = q_i \cdot d_j$ 的相關性計算）與架構細節（2N 區段教師強制佈局、每鏡頭交叉注意力、區塊相對 RoPE 重錨定），這些技術細節的清晰度有利於概念重現。然而，完整的超參數配置、訓練曲線、消融實驗數據等在當前文本片段中未完整呈現。

**重現性建議**

若 CausalCine 欲提升其學術影響力與實務採用率，建議：
1. 釋出推論程式碼與預訓練權重（即使僅釋出蒸餾後的少步驟版本）。
2. 公開訓練資料的蒐集流程或提供資料來源的詳細說明。
3. 在論文中補充完整的消融實驗，量化 CAMR、教師強制佈局、每鏡頭交叉注意力等各元件的獨立貢獻。
4. 提供在較小規模模型（如 1B-3B 參數）上的重現方案，降低硬體門檻。

#### 未來研究方向

**1. 細粒度導演控制 (Fine-Grained Directorial Control)**

當前的 CausalCine 允許使用者在鏡頭層級更新提示詞，但對鏡頭轉換的時機、風格（如淡入淡出、跳切、匹配剪輯）與節奏的控制仍屬隱式學習。未來可探索讓使用者明確指定轉換類型與時間點的機制，例如引入轉換標記符號或獨立的轉換控制模組。

**2. CAMR 的理論分析與擴展**

CAMR 的核心假設是「內容相關性優於時間鄰近性」，但此假設在不同影片類型（如動作片、對話場景、風景紀錄）下的適用程度可能不同。未來可進行更細緻的消融研究，分析 CAMR 在不同語意密度、不同鏡頭切換頻率下的表現。此外，可探索將 CAMR 與稀疏注意力 (sparse attention) 或線性注意力 (linear attention) 結合，進一步降低計算開銷。

**3. 多模態導演介面 (Multimodal Directorial Interface)**

目前的提示詞更新以文字為主，未來可擴展為多模態介面——例如允許使用者上傳參考圖片、語音指令、甚至即時繪製的草圖作為新鏡頭的起點。這將使 CausalCine 更貼近真實導演的工作流程。

**4. 與世界模型 (World Model) 的整合**

CausalCine 目前主要關注視覺生成，未來可探索將其與物理世界模型結合，使生成的多鏡頭影片不僅在視覺上一致，也在物理規律上合理。例如，角色動作應符合重力與慣性，場景光影應隨時間合理變化。

**5. 互動式敘事生成 (Interactive Narrative Generation)**

CausalCine 的即時互動特性為互動式敘事提供了技術基礎。未來可探索將其整合至遊戲引擎或虛擬實境環境，使玩家或使用者的選擇能即時影響影片敘事走向。這需要進一步研究長程因果一致性、角色行為合理性與敘事張力維持等問題。

**6. 效率優化與邊緣部署**

目前的 14B 參數配置與 8 張 H200 GPU 需求限制了 CausalCine 的部署場景。未來可探索模型量化 (quantization)、知識蒸餾 (knowledge distillation) 至更小規模、或是專用硬體加速方案，使互動式多鏡頭生成能在消費級設備上運行。

**7. 評測基準與指標**

目前多鏡頭影片生成的評測缺乏統一標準，未來可建立專門針對多鏡頭敘事的評測基準，涵蓋鏡頭轉換自然度、跨鏡頭身份一致性、敘事連貫性、提示詞遵循度等維度。這將有助於推動整個領域的標準化發展。

**8. 倫理與偏誤考量**

隨著即時互動影片生成技術的成熟，深度偽造 (deepfake)、虛假資訊傳播、版權歸屬等倫理議題將日益凸顯。未來研究應同步探討內容溯源機制、使用者身份驗證、生成內容標識等配套技術，以確保技術發展符合社會責任。

## 論文問答

**Q1：CausalCine 試圖解決的核心問題是什麼？**
A：CausalCine 聚焦於「互動式自迴歸多鏡頭影片生成」這個新任務，要求模型能夠以因果方式跨越鏡頭邊界生成影片、在生成過程中即時接受新的提示詞，並且在不必重新生成先前鏡頭的前提下重用相關的長距離脈絡。傳統的擴散影片模型雖然視覺保真度高，但因採用雙向注意力，難以支援長序列且低延遲的互動生成；而現有的自迴歸影片模型又多半以短時域延續為訓練目標，無法處理鏡頭切換、視角轉換與持續故事脈絡等電影級敘事需求。CausalCine 將多鏡頭影片生成重新詮釋為一個線上導演流程，試圖同時兼顧即時互動性與長程語意一致性。

**Q2：為什麼現有的自迴歸影片模型在多鏡頭場景中會失敗？**
A：現有自迴歸影片模型主要在短片段延續的設定下訓練與評估，將長序列視為單一鏡頭的延伸，因此在長序列推展時容易出現動作停滯、循環重播或語意漂移等問題。當生成任務需要跨越鏡頭邊界、引入新內容、轉換視角或回應新提示詞時，這些模型缺乏處理「離散鏡頭切換」的能力，也無法判斷哪些早期資訊應該被保留。此外，傳統的 KV 快取管理策略（如滑動窗口或固定錨點）依賴時間鄰近性來選擇歷史 KV 條目，在多鏡頭場景中往往會選到不相關的內容，進一步損害跨鏡頭一致性。

**Q3：為什麼多鏡頭影片生成對電影級敘事如此重要？**
A：電影級敘事並非單一鏡頭的無限延伸，而是由多個演進事件、視角轉換與離散鏡頭邊界所組成，必須在長時間尺度上維持持續故事脈絡與角色身分。真正的長片影片需要支援鏡頭切換、新事件引入以及跨鏡頭的實體再現，這些都是單鏡頭延續模型難以勝任的。多鏡頭生成能力讓模型能夠模擬導演的決策過程，根據敘事需要在不同視角與場景間切換，同時保持視覺與語意上的連貫性，這對於實現真正可互動、可控制的影片創作至關重要。

**Q4：CausalCine 的核心方法架構為何？**
A：CausalCine 的核心方法包含三個關鍵階段：首先在原生多鏡頭序列上以教師強制訓練一個全步因果多鏡頭基底模型，使其在與推論相同的因果依賴結構下學習鏡頭轉換、提示詞變化與長距離實體再現；接著引入內容感知記憶路由（CAMR），根據基於注意力的相關性分數動態選擇歷史 KV 條目，而非依賴時間鄰近性；最後透過分配匹配蒸餾（DMD）將因果基底模型壓縮為少步驟生成器，實現即時互動生成。這三個階段環環相扣，先學會長程因果行為再進行加速，使最終模型能在 16 FPS 下串流輸出並支援動態提示詞更新。

**Q5：內容感知記憶路由（CAMR）的創新之處在哪裡？**
A：CAMR 的核心創新在於打破了傳統 KV 快取管理對時間鄰近性的依賴，改為根據內容相關性動態檢索歷史 KV 條目。它透過對每幀計算內容描述子、對每個區塊計算查詢描述子，再利用兩者之間的相似度分數選出 top-k 最相關的歷史幀，從而能在有界活躍記憶體預算下保留跨鏡頭一致性。這種設計特別適合多鏡頭場景：模型可能需要從遙遠的過去召回某個角色、忽略緊鄰的前一個場景，或結合多個早期鏡頭的語意線索。CAMR 還結合了區塊相對 RoPE 重新錨定位置，確保在長序列推展時位置編碼仍維持在訓練範圍內。

**Q6：為什麼論文中選擇先訓練因果基底模型再進行蒸餾，而非直接從雙向模型蒸餾？**
A：論文的關鍵觀察是「長程因果行為應該在加速之前就學會」，這是因為直接從雙向擴散模型蒸餾成快速自�歸生成器時，模型從未在因果依賴結構下見過鏡頭邊界、提示詞變化與長距離實體再現等現象。透過先在原生多鏡頭序列上以教師強制訓練全步因果基底模型，模型能夠在與推論相同的因果依賴結構下學習這些複雜模式，大幅縮減教師強制推展落差。後續的 DMD 蒸餾便能專注於軌跡壓縮，而不必同時學習因果性與多鏡頭結構，從而保留視覺品質與跨鏡頭一致性。

**Q7：實驗中使用了哪些基準模型與評估指標？**
A：論文中將 CausalCine 與多個自迴歸基準模型進行比較，並與雙向模型在視覺品質上進行對標。評估面向涵蓋鏡頭級品質、提示詞對齊、身分保留以及轉換結構等多個維度，目的是全面衡量模型在多鏡頭設定下的綜合表現。實驗還展示了 CausalCine 在 14B 參數規模下，於 8 張 NVIDIA H200 GPU 上以 16 FPS 串流運行的實務可行性，證明其不僅在品質上接近雙向模型，更保留了因果生成獨有的效率與互動性優勢。

**Q8：CausalCine 的關鍵實驗結果為何？**
A：實驗結果顯示 CausalCine 在鏡頭級品質、提示詞對齊、身分保留與轉換結構等指標上，大幅超越現有的自迴歸基準模型。更值得注意的是，CausalCine 在視覺品質上已接近雙向模型的水準，同時保留了因果生成獨有的串流互動性與效率。這代表 CausalCine 首次在「品質」與「互動性」之間取得了實務可用的平衡，證明了因果自�歸架構在多鏡頭長片影片生成上的可行性。

**Q9：有哪些消融實驗支持了各項設計選擇？**
A：論文中透過消融實驗驗證了多鏡頭訓練資料、CAMR 機制以及蒸餾流程各自的必要性。具體而言，移除原生多鏡頭序列訓練會導致教師強制推展落差擴大、長序列推展不穩定；改用固定錨點或滑動窗口等傳統 KV 管理策略則會損害跨鏡頭一致性，因為這些方法無法根據內容相關性選擇歷史脈絡。此外，先訓練因果基底模型再進行 DMD 蒸餾的兩階段策略，也被證明比直接從雙向模型蒸餾更能保留視覺品質與多鏡頭結構。

**Q10：CausalCine 開啟了哪些實際應用情境？**
A：CausalCine 將影片生成從「離線批次渲染」轉變為「即時線上導演」，使用者可以從初始鏡頭開始，在生成過程中隨時輸入新的提示詞來引入新事件、轉換視角或切換場景，而模型會即時回應並繼續生成。在創意產業中，這項技術可用於互動式故事敘事、遊戲過場動畫、廣告分鏡預覽以及個人化的影片創作工具；對於教育訓練、模擬演示等需要根據使用者輸入動態調整內容的場景，CausalCine 也能提供高度靈活的影片生成能力。

**Q11：CausalCine 在產品化考量上有哪些重要展示？**

### 實作前置條件

**資料前置條件**
- **原生多鏡頭影片資料集**：需蒐集具備明確鏡頭邊界（cut、fade、wipe 等轉場標記）的長片影片，每段影片應包含多個鏡頭、視角變化與實體再現。建議從電影、影集、紀錄片等具有專業分鏡的素材中萃取，並以鏡頭偵測演算法（如 TransNetV2、AutoShot）預先標註。
- **鏡頭級提示詞標註**：每個鏡頭需有對應的自然語言描述，可透過影片字幕、腳本或 VLM（如 GPT-4V、Gemini）自動產生，再由人工校對。
- **實體身份資料**：若需跨鏡頭維持角色一致性，需建立角色參考庫（reference bank），包含外貌、服裝、配件等視覺特徵。

**算力前置條件**
- **訓練階段**：完整因果基底模型訓練建議使用 8 張以上 NVIDIA H200 / A100 80GB 等級 GPU，總 VRAM 至少 640GB；蒸餾階段可略低，但仍需多機多卡配置。
- **推論階段**：14B 參數模型搭配串流 KV 快取，需 8 張 H200 GPU 才能達到 16 FPS 即時生成；較小規模（如蒸餾後的 1.3B–4B 版本）可在單機 4 卡 A100 上運行，但需相應降低解析度或幀率。
- **儲存**：長序列 KV 快取會佔用大量顯存，建議配備高速 NVMe SSD 作為快取溢出（offload）備援。

**技能前置條件**
- 熟悉擴散模型與自迴歸影片生成的理論基礎（DDPM、Flow Matching、DMD 蒸餾）。
- 具備 Transformer 訓練經驗，理解因果注意力、KV 快取、RoPE 位置編碼等機制。
- 熟悉分散式訓練框架（DeepSpeed、FSDP、Megatron）與串流推論最佳化（vLLM、SGLang、TorchServe）。
- 具備影片前處理與鏡頭分割的工程能力。

### 實作步驟建議

**步驟 1：資料準備與鏡頭分割**
- 蒐集長片影片原始檔，使用鏡頭偵測工具切分鏡頭並標註邊界類型。
- 為每個鏡頭產生文字描述，必要時以 VLM 補強細節。
- 建立訓練用的多鏡頭序列樣本，每個樣本包含 N 個鏡頭、對應提示詞與時間戳。

**步驟 2：因果基底模型預訓練**
- 採用 2N 段教師強制（teacher forcing）佈局（如論文圖 2a），讓模型在單次前向傳遞中學習跨鏡頭因果依賴。
- 實作「鏡頭級交叉注意力」（per-shot cross-attention），使每個影片區塊只關注其所屬鏡頭的提示詞。
- 訓練目標為標準擴散損失（flow matching 或 DDPM），重點關注長序列的教師強制落差（teacher-forcing rollout gap）。

**步驟 3：導入 Content-Aware Memory Routing（CAMR）**
- 為每幀計算內容描述子（per-frame content descriptor），透過 Q-projection 與 K-projection 的均值池化取得。
- 為每個區塊計算查詢描述子（per-chunk query descriptor）。
- 以注意力相關性分數動態選取 top-k 歷史 KV 條目，而非依時間鄰近性。
- 結合區塊相對 RoPE（Block-Relative RoPE）重置位置相位，避免長序列推展時位置編碼超出訓練範圍。

**步驟 4：蒸餾為少步驟生成器**
- 使用 Distribution Matching Distillation（DMD）將全步因果基底模型蒸餾為少步驟（4–8 步）生成器。
- 因因果性與多鏡頭結構已由基底模型學會，蒸餾階段可專注於軌跡壓縮，視覺品質與跨鏡頭一致性較易保留。
- 蒸餾時同樣以多鏡頭序列作為監督訊號，避免蒸餾後模型退化为單鏡頭延續模式。

**步驟 5：串流推論與互動介面整合**
- 部署串流推論服務，支援 KV 快取重用：使用者追加新提示詞時，僅重新計算新鏡頭的 KV，舊鏡頭直接從快取讀取。
- 設計 WebSocket 或 gRPC 介面，支援中途更新提示詞、調整生成速度、暫停與續生。
- 前端以 16 FPS 串流播放新生成的影片區塊，提供「即時導演」互動體驗。

**步驟 6：評估與迭代**
- 評估指標應涵蓋：鏡頭級畫質（FID、FVD）、提示詞對齊度、跨鏡頭實體一致性（identity preservation）、鏡頭轉換結構合理性（transition structure）。
- 與自迴歸基準（如 CausVid、Self Forcing）以及雙向擴散模型（如 Wan、HunyuanVideo）進行對照實驗。
- 收集真人導演或編劇的使用回饋，迭代記憶路由策略與提示詞理解能力。

### 潛在風險與注意事項

**1. 教師強制落差未完全消除**
即使使用原生多鏡頭資料訓練，長序列推展時仍可能出現動作停滯或語意漂移。**緩解方式**：在訓練中加入雜訊注入（noisy queries / noisy key-values，如論文圖 2a 所示），讓模型適應推論時的誤差累積；並設置最大推展長度上限，超過後強制重置或切換鏡頭。

**2. CAMR 的 top-k 選擇可能遺漏關鍵上下文**
若 top-k 設得過小，模型可能遺忘早期鏡頭中的關鍵實體；若過大，則活躍記憶體膨脹、推論速度下降。**緩解方式**：依影片長度動態調整 k 值，並設計「強制保留」機制（例如每個實體至少保留 1–2 個參考幀）。

**3. 蒸餾後的多鏡頭能力退化**
DMD 蒸餾可能使模型傾向生成「安全的單鏡頭延續」，而非主動引入新鏡頭內容。**緩解方式**：在蒸餾損失中加入鏡頭邊界偵測的輔助任務，或在監督訊號中強化跨鏡頭切換的範例。

**4. 位置編碼在超長序列下失效**
標準 RoPE 在超出訓練長度後，相位會失真，導致長尾鏡頭品質下降。**緩解方式**：採用論文提出的區塊相對 RoPE 重置策略，或使用支援外插的位置編碼（如 YaRN、LongRoPE）。

**5. 提示詞中途更新的語意衝突**
使用者在生成過程中追加的提示詞可能與既有故事脈絡矛盾（例如突然要求場景從白天切到黑夜卻無過渡）。**緩解方式**：在介面層提供「鏡頭轉場類型」選項（cut、dissolve、fade），並讓模型學習對應的轉場模式；或在後處理階段加入一致性檢查。

**6. 算力成本與商業化門檻**
14B 模型 + 8 張 H200 的配置對中小型團隊門檻偏高。**緩解方式**：考慮採用較小的蒸餾版本（如 1.3B–4B），犧牲部分長距離一致性以換取部署可行性；或採用雲端 GPU 租賃與按使用量計費的 API 模式。

**7. 內容安全與偏見**
長序列生成可能放大訓練資料中的偏見，或產生不當內容。**緩解方式**：在提示詞輸入端與影片輸出端皆加入內容審查過濾器；建立鏡頭級的敏感詞與場景黑名單。

### 與其他技術的整合建議

**1. 與腳本生成 LLM 整合**
將 CausalCine 與 GPT-4、Claude 等大型語言模型串接：LLM 負責將使用者的高階敘事意圖拆解為鏡頭級提示詞序列，再交由 CausalCine 生成影片。可形成「LLM 編劇 + CausalCine 攝影」的自動化工作流。

**2. 與影片理解模型整合**
搭配 Video-LLaMA、InternVideo 等影片理解模型，實現「生成—理解—修正」閉環：理解模型檢視已生成的鏡頭，自動偵測敘事漏洞或一致性問題，並回頭調整後續鏡頭的提示詞。

**3. 與傳統剪輯軟體整合**
透過 OFX 或 OpenTimelineIO 介面，將 CausalCine 的輸出導入 DaVinci Resolve、Premiere Pro 等剪輯軟體，讓專業剪輯師在 AI 生成的基礎上進行精修、調色與混音。

**4. 與遊戲引擎整合**
透過 Unreal Engine 的 Movie Render Queue 或 Unity 的 Timeline，將 CausalCine 作為過場動畫的即時生成後端，根據玩家行為動態觸發鏡頭切換。

**5. 與數位人（Digital Human）技術整合**
若敘事涉及特定角色，可將 CausalCine 與 Live2D、VRM、NeRF 數位人技術結合，讓 CAMR 不僅維持 2D 外觀一致性，還能維持 3D 角色幾何的一致性。

**6. 與即時通訊與協作平台整合**
將 CausalCine 部署於 Slack、Teams、Discord 等協作平台，讓團隊成員在聊天過程中共同「導演」一支影片，每個人可隨時追加鏡頭提示詞，系統即時串流更新。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先理解「自迴歸生成」與「擴散模型」的基本概念，再閱讀本論文的摘要與圖 1，掌握 CausalCine 想解決的問題——現有 AI 影片生成無法像電影一樣處理多鏡頭敘事。接著閱讀第 1 節的「我們的第一個觀察」段落，了解為何要先訓練因果基底模型再加速。技術細節可暫時跳過，重點放在「即時導演」這個使用情境的想像。

**給 AI 工程師**
重點閱讀第 1 節後半段、圖 2 的三個子圖，以及方法論章節。特別關注：(1) 2N 段教師強制佈局如何讓模型在單次前向傳遞中學習跨鏡頭依賴；(2) CAMR 的內容描述子如何透過 Q/K projection 的均值池化取得，以及 top-k 選取如何避免時間鄰近性的偏誤；(3) 區塊相對 RoPE 如何解決長序列位置編碼失效問題。實作上可從較小規模（如 1.3B）開始重現蒸餾階段，再逐步擴展到完整 14B 配置。

**給研究者**
本論文的核心貢獻在於「將多鏡頭敘事視為線上導演流程」的問題定式，以及「先學因果再加速」的訓練哲學。建議從這個視角出發，思考以下開放問題：(1) CAMR 的 top-k 選取是否可由學習式稀疏注意力取代？(2) 蒸餾階段是否可結合強化學習，以使用者互動回饋進一步最佳化？(3) 多鏡頭結構是否能與世界模型（world model）結合，讓模型理解物理因果而不僅是視覺一致性？相關工作中 Self Forcing 與 Causal Forcing 的 train-test mismatch 處理方式值得深入比較。

**給產品經理**
CausalCine 的商業價值在於「即時互動」與「長距離一致性」的結合，這是現有影片生成工具（不論是 Runway、Pika 還是 Sora）都尚未妥善解決的痛點。建議從「互動式分鏡預覽」與「自動化多機位導播」兩個場景切入，評估目標客戶的付費意願與工作流整合難度。技術上需特別關注三個指標：單次生成的算力成本（決定單價）、KV 快取可重用的最大長度（決定單支影片的商業價值）、以及提示詞中途更新的延遲（決定互動體驗）。建議先以 API 形式提供給 B2B 客戶（如影視前期公司、廣告代理商），驗證需求後再考慮 C 端產品化。
