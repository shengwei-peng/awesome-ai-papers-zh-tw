## ⚡ TL;DR

長程代理的決策相關資訊會隨軌跡增長而衰減，導致重複錯誤或遺漏需求。
提出主動式記憶代理，並行維護結構化記憶庫，選擇性地向行動代理注入提醒。
在兩大基準上提升 pass@1，選擇性介入優於被動檢索，並可部分遷移至開源模型。

## 摘要翻譯

在長程任務（long-horizon tasks）中，決策相關狀態（decision-relevant state）往往分散於不斷擴展的軌跡（expanding trajectory）之中，而行動代理（action agent）必須將其提取並據以行動。隨著軌跡增長，任務需求（task requirements）、環境事實（environment facts）、先前嘗試（prior attempts）、失敗診斷（diagnoses）與開放子目標（open subgoals）可能會被淹沒在上下文視窗（context window）中，甚至被擠出視窗之外，導致在需要時無法影響決策。我們將這種失效模式（failure mode）稱為「行為狀態衰減」（behavioral state decay）。我們將記憶視為主動介入機制（active intervention mechanism），而非被動檢索（passive retrieval）來研究。一個獨立的記憶代理（memory agent）與未經修改的行動代理並行運作，根據近期軌跡更新結構化記憶庫（structured memory bank），並決定要注入基於記憶的提醒（memory-grounded reminder），抑或保持靜默（silent）。此模組可與前沿行動代理（frontier action agents）及現有代理框架／代理測試架構（agent harnesses）隨插即用（plug-and-play）。在 Terminal-Bench 2.0 與 τ²-Bench 上，無論行動代理能力較弱或較強（weaker and stronger action agents），其 pass@1 均獲得提升，於 Terminal-Bench 提升 8.3 百分點（pp），於 τ²-Bench 提升 6.8 百分點。消融實驗（ablations）顯示，選擇性介入（selective intervention）優於被動式記憶庫暴露（passive bank exposure）、常時注入（always-on injection）、僅顧問式引導（advisor-only guidance）與通用檢索（general retrieval）。作為邁向開源權重記憶策略（open-weight memory policies）的早期嘗試，我們使用監督式微調（SFT）與群組相對策略最佳化（GRPO）在 SETA 上訓練 Qwen3.5-27B，提升了驗證獎勵（validation reward），並在 Terminal-Bench 上達成部分遷移（transfer）。

### 核心貢獻（3～5點）
- 提出「行為狀態衰減」（behavioral state decay）問題，指出長程任務中決策相關資訊會隨軌跡增長而逐漸失去對行為的影響力。
- 設計主動式記憶代理（proactive memory agent），以選擇性介入（selective intervention）機制動態決定何時注入記憶提醒，而非持續暴露記憶庫。
- 模組可隨插即用（plug-and-play）整合至現有前沿行動代理與代理測試架構，無需修改行動代理本身。
- 在 Terminal-Bench 2.0 與 τ²-Bench 上顯著提升 pass@1，並透過消融實驗驗證選擇性介入優於多種基線方法。
- 開源權重記憶策略的初步嘗試：以 SFT 與 GRPO 訓練 Qwen3.5-27B，在驗證獎勵上獲得改善並達成部分跨基準遷移。

### 適合對象
適合對長程代理（long-horizon agents）、LLM 記憶機制、主動式記憶系統與強化學習感興趣的研究者與工程師，特別是關注如何提升多步驟任務中決策穩定性、以及如何設計輕量可插拔記憶模組的讀者。

## 深度分析

#### 方法論解析

本研究將「記憶」重新定位為一種**主動介入機制（active intervention mechanism）**，而非單純的儲存與檢索工具。其核心論點是：在**長程任務（long-horizon tasks）**中，真正造成失敗的原因往往不是資訊遺失於**上下文視窗（context window）**之外，而是決策相關資訊雖仍存在於**軌跡紀錄（transcript）**中，卻無法可靠地影響下一步行動。作者將此現象命名為**行為狀態衰減（behavioral state decay）**，並據此提出一個與**行動代理（action agent）**並行運作的**記憶代理（memory agent）**。

##### 1. 雙階段記憶介入架構

整體架構可拆解為兩個階段：**記憶維護（memory maintenance）**與**選擇性介入（selective intervention）**。

- **記憶維護階段**：記憶代理定期讀取近期**軌跡（trajectory）**，從中萃取並更新一個**結構化記憶庫（structured memory bank）**。記憶內容涵蓋多種執行狀態，包括**任務需求（task requirements）**、**環境事實（environment facts）**、**先前嘗試（previous attempts）**、**失敗診斷（failure diagnoses）**、**過程中發現（intermediate discoveries）**以及**開放子目標（open subgoals）**等。
- **介入決策階段**：記憶代理在每次行動代理即將做決策前，判斷是否應將某條記憶轉換為簡潔的**基於記憶的提醒（memory-grounded reminder）**注入其**上下文視窗（context window）**，或選擇**靜默（silent）**不介入。

這種設計的關鍵在於「何時介入」與「介入什麼」被解耦：記憶庫負責組織資訊，而介入策略則負責決定資訊是否應在當前決策點成為主動控制訊號。這比傳統摘要（summarization）更強，因為摘要只回答「保留什麼」，而記憶代理進一步回答「保留的內容是否應打斷下一個行動」。

##### 2. 與行動代理的關係：隨插即用

該模組標榜為**隨插即用（plug-and-play）**：行動代理無需修改，記憶代理僅透過在適當時機注入提醒來影響行為。這意味著它可以疊加於現有**前沿行動代理（frontier action agents）**與**代理框架（agent harnesses）**之上，無需重新訓練或改動行動代理的推理流程。這種低侵入性對於實務部署相當重要，因為它允許團隊在不更動核心決策系統的前提下，提升長程任務的穩定性。

##### 3. 提醒內容的約束

作者刻意將記憶代理的輸出限制為**基於記憶的提醒（memory-grounded reminder）**，而非廣泛的策略建議。這是為了與**顧問式引導（advisor-only guidance）**區隔：顧問可能提供「你應該先規劃」這類高層建議，而記憶代理只能說「請記得 X 需求尚未滿足」或「Y 指令之前已失敗」。這種約束降低了記憶代理干擾行動代理局部推理的風險，同時確保介入內容具有明確的狀態依據。

##### 4. 開源權重記憶策略的初步訓練

為了探索記憶策略是否可被學習，作者以 **Qwen3.5-27B** 為基礎，在自行建構的 **SETA** 資料集上進行**監督式微調（SFT, Supervised Fine-Tuning）**與**群組相對策略最佳化（GRPO, Group Relative Policy Optimization）**。訓練目標是讓開源模型學會根據軌跡更新記憶庫並決定是否介入。實驗顯示，該模型在驗證獎勵（validation reward）上有所提升，並能部分遷移至 **Terminal-Bench 2.0**。雖然效能尚未追上以 **Claude Opus 4.6** 作為記憶代理的表現，但這證明了記憶介入策略具備可學習性，為未來**開源權重記憶策略（open-weight memory policies）**奠定了基礎。

#### 實驗數據解讀

本研究在兩個長程基準上進行評估：**Terminal-Bench 2.0**（自主命令列執行）與 **τ²-Bench（tau-squared Bench）**（互動式工具使用與領域規則）。主要評估指標為 **pass@1**，即單次執行成功率。

##### 1. 主要結果：記憶介入帶來穩定提升

以 **Claude Opus 4.6** 作為記憶代理時，實驗結果如下：

| 行動代理（action agent） | 基準 | 基線 pass@1 | 加入記憶代理後 pass@1 | 提升 |
|---|---|---|---|---|
| Claude Sonnet 4.5 | Terminal-Bench 2.0 | 37.6% | 45.9% | +8.3 pp |
| Claude Sonnet 4.5 | τ²-Bench | 55.0% | 61.8% | +6.8 pp |
| Claude Opus 4.6 | Terminal-Bench 2.0 | — | — | +2.4 pp |
| Claude Opus 4.6 | τ²-Bench | — | — | +2.5 pp |

這裡的 **pp（percentage points）** 是絕對百分點差異。對於較弱的 **Sonnet 4.5**，記憶介入帶來了顯著增益；而對於已經較強的 **Opus 4.6**，增益雖然縮小，但仍為正向。這點十分重要：它顯示行為狀態衰減並非僅發生在弱模型上，即使是強大的行動代理，也會因長程軌跡中的資訊被埋沒而做出次佳決策。

##### 2. 消融實驗：選擇性介入勝過其他變體

作者進行了一系列消融實驗，驗證各設計選擇的貢獻：

- **被動式記憶庫暴露（passive bank exposure）**：持續將整個記憶庫內容附加在行動代理的上下文中。結果顯示，單純暴露記憶庫不如選擇性介入，可能因為過多資訊造成干擾（distract）並增加 **token** 消耗。
- **常時注入（always-on injection）**：每一步都強制注入提醒。這會增加延遲（latency）與成本，且可能打斷行動代理的局部進展。
- **僅顧問式引導（advisor-only guidance）**：提供一般性策略建議而非基於記憶的提醒。這種方式缺乏具體狀態錨定，效果較差。
- **通用檢索（general retrieval）**：根據語意相似度檢索記憶，而非由記憶代理主動判斷介入時機。其表現也不及選擇性介入。

消融結果支持了核心假設：**記憶的價值不僅在於「能否被檢索」，更在於「是否在被需要的時機主動介入」**。

##### 3. 開源模型訓練結果

在 **SETA** 上訓練的 **Qwen3.5-27B** 記憶代理，驗證獎勵（validation reward）有所提升，並在 **Terminal-Bench 2.0** 上觀察到部分遷移（partial transfer）。這表示記憶介入策略並非只能由最大型的閉源模型執行，較小的開源模型也能學到一定程度。然而，「部分遷移」也暗示目前訓練規模或資料多樣性仍不足，距離完全替代大型閉源記憶代理尚有距離。

##### 4. 數據意涵

整體而言，實驗數據強化了以下幾點結論：

1. **行為狀態衰減（behavioral state decay）**是真實且可量測的失效模式，會在兩種不同類型的長程任務中造成顯著效能損失。
2. 選擇性記憶介入是一種有效的矯正機制，且對強弱行動代理皆有益處。
3. 記憶代理的設計必須同時考慮「寫入/更新」與「介入時機」，單純改善其中一項不足以達到最佳效果。
4. 開源權重記憶策略雖然可行，但仍需更多資料與訓練才能達到實用門檻。

#### 與現有研究的比較

##### 1. 相對於傳統記憶系統

現有許多代理記憶系統（如 Mem0、Voyager、Generative Agents 等）強調**持久化使用者狀態（persistent user state）**、**跨會話召回（cross-session recall）**、**個人化（personalization）**以及可重複使用技能的儲存。這些系統主要解決的是「寫入與檢索問題（write and retrieval problem）」：如何有效儲存過去互動，並在需要時取出。

本研究則將焦點轉向「**介入問題（intervention problem）**」：即使記憶可以被檢索，也必須決定它是否應在當前決策點主動影響行為。這是對記憶角色的一次重要擴展——從「資訊倉儲」變成「控制迴路中的主動參與者」。

##### 2. 相對於長上下文與摘要方法

近年大型語言模型的**上下文視窗（context window）**不斷擴大，但研究已顯示，資訊在上下文中的位置會影響其被利用的程度（即所謂的「lost in the middle」現象）。單純將更長的歷史塞進模型，並不能保證決策相關狀態會被適當使用。

摘要（summarization）方法則試圖壓縮歷史，但摘要策略通常是靜態的：它決定「保留什麼」，卻不決定「何時讓保留的內容發揮作用」。本研究的記憶代理進一步做出「是否介入」的判斷，因此比摘要更貼近主動控制。

##### 3. 相對於 Memory-as-Action 與 Context-Folding

與 **Memory-as-Action（Zhang et al., 2025）** 相比，該方法將工作記憶管理視為可由行動代理自身執行的編輯動作，並與任務表現聯合最佳化。本研究則採用**雙代理架構**，將記憶維護與介入決策從行動代理中分離，這降低了行動代理的認知負擔，也讓記憶模組更容易**隨插即用（plug-and-play）**。

**Context-Folding（Sun et al., 2025）** 透過分支與折疊子軌跡來管理上下文，並以強化學習獎勵分解與上下文管理。本研究則不修改軌跡結構，而是透過外部記憶代理持續監控並選擇性提醒，兩者可視為互補：一個側重於結構化上下文，另一個側重於狀態驅動的提醒。

##### 4. 相對於顧問模型

近期也有研究提出讓顧問模型（advisor models）在旁觀察並提供高層策略建議。本研究刻意將記憶代理限制為**基於記憶的提醒（memory-grounded reminder）**，避免給予過於廣泛的建議。這種約束使介入內容更具可解釋性，也減少對行動代理局部推理的干擾。

##### 5. 限制

儘管本研究提出了有力的架構，仍有幾項限制值得注意：

- **記憶代理本身也是語言模型**：它同樣受限於上下文長度與推理能力，當軌跡極長時，記憶代理本身也可能發生狀態衰減。
- **提醒內容的品質高度依賴記憶代理能力**：若記憶代理錯誤判斷介入時機或產生不準確提醒，反而可能誤導行動代理。
- **結構化記憶庫的設計細節未完全揭露**：雖然論文提及記憶庫包含多種狀態類型，但具體的資料結構、更新規則與衝突處理機制仍有待更多細節。
- **訓練資料 SETA 的規模與公開性不明**：這影響了開源權重記憶策略的可重現性與泛化能力。

#### 可重現性評估

根據目前提供的論文內容，**未明確提及原始碼、資料集或模型權重是否公開釋出**。以下從幾個層面評估可重現性：

##### 1. 程式碼與實作細節

論文描述了高層架構（記憶代理定期讀取軌跡、更新記憶庫、決定是否注入提醒），但缺乏關鍵實作細節，例如：

- 記憶代理的呼叫頻率（「固定間隔」具體是每幾步？）
- **結構化記憶庫（structured memory bank）**的實際資料結構（是鍵值對、圖、還是自然語言條目？）
- 提醒的格式與長度限制
- 記憶庫更新時如何處理衝突或過時資訊
- 行動代理與記憶代理之間的介面定義

若作者未釋出程式碼，其他研究者需要根據描述自行實作，這會引入相當大的重現變異。

##### 2. 資料集

本研究提出了一個訓練資料集 **SETA**，用於訓練 **Qwen3.5-27B** 的記憶策略。然而，目前內容未說明：

- SETA 的規模、任務分佈與建構方式
- 是否涵蓋 **Terminal-Bench 2.0** 與 **τ²-Bench** 的任務類型
- 是否會公開釋出

若 SETA 不公開，則開源權重記憶策略的訓練與比較將難以重現。

##### 3. 模型權重

論文提到以 **Qwen3.5-27B** 為基礎進行 SFT 與 GRPO，但並未說明微調後的權重是否會釋出。若權重不公開，則其他研究者無法直接驗證其遷移效果。

##### 4. 基準測試

所幸 **Terminal-Bench 2.0** 與 **τ²-Bench** 是已發表的公開基準，這部分相對容易重現。只要取得這些基準並使用相同的行動代理（如 Claude Sonnet 4.5 / Opus 4.6），原則上可以重複主要實驗。然而，由於記憶代理的實作細節與提示設計未公開，重現的門檻仍然較高。

##### 5. 綜合評估

整體而言，本研究在**問題定義與架構設計**上相當清晰，但在**實作細節與資源公開**方面仍有不足。若要達到高可重現性，建議作者至少釋出：

- 記憶代理的提示模板（prompt templates）
- 結構化記憶庫的規格與更新邏輯
- SETA 資料集的建構說明或部分樣本
- 微調後 **Qwen3.5-27B** 的權重或訓練腳本

#### 未來研究方向

本研究為長程代理的記憶設計開啟了多條值得深入探索的路徑：

##### 1. 更強大的開源權重記憶策略

目前 **Qwen3.5-27B** 僅達到部分遷移。未來可嘗試：

- 擴大 **SETA** 資料集規模與多樣性
- 採用更先進的強化學習演算法（如 PPO、DPO 或其變體）
- 使用更大參數量的開源模型作為記憶代理
- 設計專門的記憶介入獎勵函數，以更好捕捉「適時提醒」的價值

##### 2. 記憶代理的層級化設計

當軌跡極長時，單一記憶代理可能自身也面臨上下文限制。未來可研究**多層級記憶架構**，例如：

- 短期工作記憶（處理最近幾步）
- 中期情節記憶（追蹤子目標與嘗試）
- 長期語意記憶（儲存可跨任務重用的環境事實與技能）

##### 3. 與檢索增強生成（RAG）的整合

本研究的記憶庫可視為一種任務特定的動態知識庫。未來可探索如何將其與外部**檢索增強生成（Retrieval-Augmented Generation, RAG）**系統結合，使代理同時具備即時狀態記憶與靜態領域知識。

##### 4. 介入時機的理論建模

目前介入決策主要依賴語言模型的判斷。未來可發展更形式化的框架，例如：

- 將記憶介入建模為部分可觀察馬可夫決策過程（POMDP）中的資訊價值計算
- 設計可解釋的介入規則，例如「當行動代理即將執行與過去失敗指令相似的動作時觸發提醒」

##### 5. 跨任務與跨領域遷移

本研究主要驗證了記憶代理在命令列與互動式工具使用任務上的效果。未來可測試其在其他長程領域的泛化能力，例如：

- 多步驟機器學習工程（multi-step machine-learning engineering）
- 科學實驗規劃
- 軟體開發與除錯
- 個人化助理的跨會話任務追蹤

##### 6. 成本、延遲與效能的權衡

記憶代理的每次呼叫都會增加 **token** 消耗與**延遲（latency）**。未來可研究：

- 如何壓縮記憶表示以降低推理成本
- 自適應呼叫頻率（在關鍵決策點才啟動記憶代理）
- 記憶代理與行動代理的聯合最佳化，以在效能與開銷之間取得平衡

##### 7. 安全性與對齊

主動介入機制也帶來新的安全議題：

- 若記憶代理被誤導，可能持續注入錯誤提醒，導致行動代理偏離目標
- 需要設計記憶驗證機制，確保提醒內容與實際軌跡一致
- 可研究如何讓行動代理對記憶提醒保持適度批判性，而非盲目遵從

##### 8. 與長上下文模型的協同

隨著語言模型上下文視窗持續擴大，未來可探討：

- 在極長上下文模型中，外部記憶代理是否仍然必要？
- 外部記憶是否可以作為長上下文模型的「注意力引導」機制，彌補其對遠端資訊利用不足的問題？

總結來說，本研究不僅提出了一個具體有效的架構，更重要的是將「記憶應該何時介入」這一控制問題推到研究前沿。後續工作若能在此基礎上強化開源性、理論基礎與跨領域泛化能力，將有望顯著提升長程代理在真實世界任務中的可靠性。

## 論文問答

**Q1：什麼是「行為狀態衰減」（behavioral state decay），為什麼長程代理會出現這個問題？**
A：行為狀態衰減指的是在長程執行過程中，原本應該影響未來行動的決策相關資訊——例如任務需求、環境事實、先前嘗試、失敗診斷、過程中發現與開放子目標——逐漸失去對代理下一個決策的約束力。這些資訊可能仍然存在於對話紀錄中，甚至仍在上下文視窗內，但隨著軌跡不斷擴展，它們被新觀察與行動淹沒，導致代理在關鍵時刻無法回憶或遵從。結果就是代理會重複犯錯、忽略硬性需求，或把已經診斷過的錯誤當成新問題處理。

**Q2：現有的記憶系統（強調儲存與檢索）為何不足以解決長程任務執行中的問題？**
A：傳統記憶系統主要聚焦於如何儲存、更新與檢索相關紀錄，這對個人化、跨會話召回與持久化使用者狀態非常重要，但並未處理「何時該讓記憶影響行動」的介入問題。在長程任務中，單純把資訊放進記憶庫或讓行動代理被動地看到記憶，並不能保證代理會在正確的決策點使用它。如果記憶浮現太少，代理會重蹈覆轍；如果浮現太多，則會增加延遲、消耗 token，並可能干擾當前局部進度。

**Q3：為何「決定何時介入」比「摘要或保留資訊」更關鍵？**
A：摘要只回答「應該保留什麼」，但長程任務的挑戰在於判斷「已保留的執行狀態是否應在下一個決策中變成活躍」。不同任務的失效模式各異，有時關鍵是初始指令的硬性需求，有時是環境事實、失敗指令、錯誤診斷或未完成的子目標，固定摘要策略無法預知哪一條記憶應該打斷下一步行動。因此，記憶不僅是寫入與檢索問題，更是一個控制問題：必須選擇性地在關鍵時刻重新啟動記憶，才能可靠地約束未來行為。

**Q4：主動式記憶代理的核心架構是什麼？它如何與行動代理互動？**
A：作者提出一個與行動代理並行運作的獨立記憶代理，行動代理本身不需要修改。記憶代理會以固定間隔檢視近期軌跡，更新一個結構化記憶庫，然後決定是否要將一則基於記憶的簡潔提醒注入下一次行動代理呼叫，或選擇靜默不介入。這種兩階段架構把記憶維護與行動選擇解耦，讓記憶代理專注於「何時該讓記憶進入控制迴路」，而行動代理則專注於執行決策。

**Q5：主動式記憶介入與被動式記憶暴露、常時注入及僅顧問式引導有何不同？**
A：被動式記憶暴露持續把整個記憶庫內容呈現給行動代理，但無法保證代理在關鍵時刻注意到正確資訊；常時注入則每一步都塞入提醒，容易造成干擾與成本浪費；僅顧問式引導提供廣泛策略建議，卻不一定根植於實際執行歷程。相較之下，主動式記憶代理只注入與當前決策點高度相關、且來自結構化記憶庫的具體提醒，並可選擇靜默，從而在介入與不干擾之間取得平衡。

**Q6：記憶代理可以注入哪些類型的提醒？它何時選擇保持靜默？**
A：記憶代理注入的提醒包括被遺忘的任務需求、穩定的環境事實、先前失敗的嘗試以及對錯誤模式的診斷等決策相關執行狀態。當它判斷目前沒有任何記憶條目需要重新進入行動代理的下一個決策時，就會選擇靜默，避免無謂的干擾。這種選擇性介入讓提醒只在「重要時刻」出現，而不是每一步都強迫行動代理處理額外資訊。

**Q7：實驗使用了哪些基準？它們分別評估什麼能力？**
A：實驗在 Terminal-Bench 2.0 與 τ²-Bench 兩個基準上進行。Terminal-Bench 2.0 評估自主命令列執行這類長程任務，代理需要在終端機環境中完成多步驟操作；τ²-Bench 則評估在領域特定規則下的互動式工具使用，強調代理與工具、環境及可能的使用者之間的多輪互動。兩者都涵蓋需要長期狀態維護的複雜場景，適合用來檢驗記憶介入是否能減少行為狀態衰減。

**Q8：主要量化結果是什麼？對較弱與較強的行動代理各有何影響？**
A：以 Claude Opus 4.6 作為記憶代理時，Claude Sonnet 4.5 在 Terminal-Bench 2.0 的 pass@1 從 37.6% 提升至 45.9%，在 τ²-Bench 則從 55.0% 提升至 61.8%。即使改用較強的 Opus 4.6 作為行動代理，記憶介入仍然帶來顯著增益，分別提升 2.4 與 2.5 個百分點。整體而言，記憶代理在兩個基準上分別帶來 +8.3 與 +6.8 個百分點的進步，且增益不會因行動代理變強而消失。

**Q9：消融實驗揭示了什麼？選擇性介入相較於其他變體表現如何？**
A：消融實驗顯示，選擇性介入優於被動式記憶庫暴露、常時注入、僅顧問式引導以及通用檢索等替代方案。這表示單純讓行動代理看到記憶庫、或每一步都提醒、或提供一般性建議，都不如由記憶代理主動判斷何時注入記憶提示來得有效。結果支持了論文的核心主張：長程代理的記憶不僅要能儲存與檢索，更要能精準地決定何時介入控制迴路。

**Q10：在哪些真實場景中，主動式記憶代理最具價值？**
A：主動式記憶代理特別適合需要長時間、多步驟互動的場景，例如自動化軟體開發與除錯、資料分析管線建置、複雜的終端機維運任務，以及需要遵守領域規則的客戶服務或預訂工具使用。在這些情境中，初始需求、環境限制、先前失敗與未完成的子目標會隨著對話不斷累積，若沒有選擇性地提醒，代理很容易偏離目標。透過在關鍵時刻喚醒決策相關狀態，主動式記憶代理能顯著降低重複錯誤與違反需求的情況。

**Q11：部署這個模組時需要考量哪些實務因素，例如延遲、token 成本與干擾？**
A：每次記憶代理更新記憶庫並決定是否注入提醒，都會帶來額外的推理延遲與 token 消耗，因此必須權衡提醒頻率與系統成本。如果記憶代理過度積極，每一步都注入提醒，不僅浪費資源，還可能讓行動代理分心，無法專注於當前局部子問題；如果過於保守，則會錯失防止錯誤的時機。選擇性介入的設計正是為了在這兩者之間取得平衡，讓記憶只在真正重要時才浮現。

**Q12：這項研究可能如何影響未來代理框架或記憶層的設計？**
A：這項研究指出，未來的代理框架不應只把記憶視為被動的儲存與檢索層，而應將其視為能主動決策何時介入控制迴路的獨立元件。由於記憶代理是隨插即用的模組，可與現有前沿行動代理和代理測試架構整合，因此能降低採用門檻，並促進記憶策略的標準化。長遠來看，這可能催生專門的開源權重記憶策略模型，讓長程代理在執行過程中更穩定地維持決策相關狀態。

**Q13：目前提出的記憶代理架構有哪些限制？**
A：論文目前主要使用 Claude Opus 4.6 等專有模型作為記憶代理，雖然也嘗試用 Qwen3.5-27B 進行開源權重訓練，但僅達到部分遷移，顯示開源記憶策略仍有進步空間。此外，記憶代理以固定間隔運作，可能無法完美對齊所有任務中真正關鍵的決策時刻。整體而言，這是一個早期步驟，記憶庫的結構、提醒格式與介入時機的學習都還需要更多研究。

**Q14：在哪些情況下，記憶代理仍可能遺漏重要介入？**
A：如果記憶代理對近期軌跡的更新不夠及時，或者對某條資訊在下一個決策中的重要性判斷錯誤，就可能選擇靜默而錯失提醒時機。當任務需求非常隱晦、環境事實快速變化，或錯誤診斷本身不完整時，記憶代理也可能無法產生有效的記憶提示。此外，若行動代理即使收到提醒仍無法正確理解或執行，記憶介入的效果也會受限。

**Q15：作者建議哪些未來方向，特別是關於開源權重記憶策略？**
A：作者建議持續發展開源權重的記憶策略，讓記憶代理不再依賴專有模型，並能更廣泛地部署於不同代理框架中。他們以 Qwen3.5-27B 為例，透過 SFT 與 GRPO 在 SETA 資料集上訓練，已看到驗證獎勵提升並部分遷移到 Terminal-Bench，但未來需要更大規模的訓練資料與更強的強化學習訊號來改善泛化。另一個方向是讓記憶代理學習更動態的介入時機，而不只是固定間隔更新，以進一步貼近任務中真正關鍵的決策點。

## 實務應用指南

### 適用場景

1. **長時間終端機除錯與基礎設施部署**  
   在 DevOps / SRE 場景中，代理需要執行數十到數百條命令來排查問題、修改設定、驗證服務狀態。初始的硬性需求（例如「不能重啟生產資料庫」）、環境事實（某台機器無法連線）或先前失敗的診斷，很容易在長軌跡中被淹沒。主動式記憶代理可在關鍵步驟前提醒行動代理，避免重複錯誤或違反約束。

2. **多輪客戶服務或銷售助理**  
   當對話跨越多輪，使用者曾提到的需求、未完成的子目標、領域特定規則（例如退換貨期限）會散落在對話紀錄中。記憶代理可選擇性地在適當時機注入提醒，讓行動代理不會在後續回覆中忽略已承諾的事項或已確認的條件。

3. **長文件法律 / 合規審查**  
   代理需要逐段分析合約、法規或審計文件，並在多輪推理中維持對關鍵條款、中間發現與開放子目標的追蹤。記憶代理能將「這份文件必須符合 GDPR 第 17 條」這類硬性需求轉化為適時提醒，降低行為狀態衰減造成的遺漏。

4. **軟體開發中的長期 Issue 修復**  
   從閱讀 issue、定位 bug、嘗試修補到執行測試，代理會產生大量軌跡。先前嘗試過但失敗的命令、錯誤診斷、環境事實（例如某個相依版本過舊）都應影響後續決策。主動式記憶代理可協助維持這些決策相關狀態，減少繞路與重複勞動。

---

### 實作前置條件

- **資料準備**
  - 現有行動代理的真實或模擬長軌跡，涵蓋成功與失敗案例。
  - 標註出決策相關狀態：硬性需求、環境事實、先前嘗試、失敗診斷、過程中發現、開放子目標。
  - 若要走開源權重路線，需要類似 SETA 的訓練資料，包含「是否該在這一步注入提醒」的決策標籤與對應獎勵。

- **運算資源**
  - 記憶代理的推理成本：可選用前沿閉源模型（如 Claude Opus 4.6）做原型，或部署 Qwen3.5-27B 等開源模型。
  - 若進行微調，需要 SFT 與 GRPO 的訓練基礎設施，以及足夠的 GPU 資源與驗證環境。
  - 評估需要可重現的代理測試架構（agent harnesses），例如 Terminal-Bench 2.0 或 τ²-Bench 等長程基準。

- **技能與團隊**
  - 熟悉提示工程與結構化輸出設計。
  - 具備強化學習或策略最佳化經驗（若要走 GRPO）。
  - 了解目標領域的失敗模式，能設計合理的記憶庫 schema 與介入條件。
  - 具備可觀測性與日誌追蹤能力，以便分析記憶代理為何選擇靜默或注入。

---

### 實作步驟建議

1. **診斷行為狀態衰減**  
   先從現有行動代理的失敗軌跡中，找出「早期已知、後期被忽略」的決策相關狀態，確認問題確實來自狀態影響力下降，而非單純能力不足。

2. **設計結構化記憶庫 schema**  
   將記憶條目分類為硬性需求、環境事實、先前嘗試、失敗診斷、過程中發現、開放子目標等欄位，並決定每筆記憶的更新、合併與失效規則。

3. **建置記憶代理 sidecar**  
   讓記憶代理以獨立程序與行動代理並行運作，定期讀取近期軌跡，更新記憶庫，再決定「注入提醒」或「保持靜默」。此階段不修改行動代理本身，保持隨插即用。

4. **設計提醒格式與介入策略**  
   提醒必須簡潔、基於記憶、與下一步決策直接相關。避免把整份記憶庫貼進上下文；應透過選擇性介入，只注入當前最可能影響行為的項目。

5. **整合現有代理框架**  
   將記憶代理掛接到現有 harness 中，在每次行動代理呼叫前插入記憶代理的判斷邏輯，並記錄注入內容與時機。

6. **評估與消融實驗**  
   以 pass@1 為主要指標，比較基線、被動式記憶庫暴露、常時注入、僅顧問式引導與通用檢索等變體，驗證選擇性介入的優勢。

7. **（選用）訓練開源記憶策略**  
   收集領域內的決策資料，先以 SFT 學習基本策略，再以 GRPO 最佳化驗證獎勵，最後測試對 Terminal-Bench 等基準的遷移能力。

8. **上線監控與迭代**  
   追蹤提醒頻率、token 開銷、延遲、行動代理對提醒的遵從率，以及是否出現過度干擾或遺漏關鍵狀態，持續調整介入閾值與記憶更新規則。

---

### 潛在風險與注意事項

- **過度介入導致干擾**  
  提醒太頻繁或內容不相關，會增加 token 消耗、延長回應時間，並讓行動代理偏離當前局部進度。應設定信心閾值，並優先注入與下一步高度相關的記憶。

- **介入不足遺漏關鍵狀態**  
  若記憶代理過於保守，會回到原本的行為狀態衰減問題。可透過領域規則標記「不可遺漏」的硬性需求，作為保底機制。

- **記憶過時或衝突**  
  環境事實可能隨執行改變，開放子目標可能已完成。記憶庫必須支援更新、刪除與時效標記，避免注入已失效的資訊。

- **行動代理過度依賴提醒**  
  長期下來，行動代理可能變得被動，只等提醒才做決策。可保留部分無提醒的訓練或評估樣本，維持行動代理本身的推理能力。

- **幻覺與錯誤記憶**  
  記憶代理可能產生不存在的失敗診斷或環境事實。建議對關鍵記憶條目進行環境驗證或人機協同確認，並在生產環境保留審計日誌。

- **評估偏差**  
  訓練資料若與測試基準重疊，可能高估遷移效果。應使用獨立驗證集，並在真實任務上進行 A/B 測試。

---

### 與其他技術的整合建議

- **與 RAG / 持久化記憶層搭配**  
  將跨會話的使用者狀態、領域知識交給 RAG 或 Mem0 等持久化記憶層；主動式記憶代理則專注於「當前軌跡中哪些執行狀態應立即影響下一步行動」。

- **與上下文管理技術搭配**  
  可結合 Context-Folding 或 Memory-as-Action 等機制處理子任務分支，再由記憶代理決定何時將折疊後的摘要重新激活為提醒。

- **與顧問模型區分職責**  
  顧問模型適合提供高層策略建議；記憶代理則應受限於基於記憶的提醒，不主動生成未經軌跡支撐的廣泛建議，避免兩者混淆。

- **與現有代理框架整合**  
  無論使用 LangChain、AutoGen 或自研 harness，都可將記憶代理設計為 sidecar，透過標準介面在每次行動代理呼叫前注入提醒，降低對現有程式碼的侵入性。

- **與可觀測性工具整合**  
  將記憶庫狀態、注入決策與提醒內容寫入追蹤系統，方便後續除錯、審計與策略迭代。

### 給不同背景讀者的閱讀建議

- **初學者**  
  先聚焦「行為狀態衰減」這個直覺概念：代理在長任務中會忘記早期重要的資訊。接著理解主動式記憶代理的核心做法——不是把所有歷史都塞進上下文，而是像一位適時提醒的助手，只在關鍵時刻提示行動代理。可先跳過訓練細節，重點看適用場景與風險。

- **AI 工程師**  
  建議深入閱讀記憶代理的兩階段架構：結構化記憶庫維護與選擇性介入決策。注意提醒格式、介入時機與靜默策略的設計，並參考消融實驗比較被動式記憶庫暴露、常時注入與通用檢索的差異。若資源允許，可嘗試以 SFT + GRPO 複現開源權重記憶策略。

- **研究人員**  
  本文將記憶視為控制問題而非單純的儲存或檢索問題，這是主要的理論貢獻。可進一步探討介入決策的最佳化目標、記憶條目的形式化表示、以及在不同任務分佈上的泛化與遷移。開源權重記憶策略的訓練與評估也是值得延伸的方向。

- **產品經理**  
  關注主動式記憶代理能帶來的業務價值：降低長任務失敗率、減少重複勞動、提升單次執行成功率。同時要評估額外的推理成本與延遲，並規劃人機協同的風險控管機制。建議從失敗代價高、軌跡長的場景優先導入，並以 A/B 測試驗證 ROI。
