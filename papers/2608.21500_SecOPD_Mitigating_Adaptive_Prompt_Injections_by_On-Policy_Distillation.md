## ⚡ TL;DR

現有防禦對自適應提示注入的攻擊成功率仍近百分之百。
本文提出 SecOPD，以乾淨輸入的初始化模型對輸出詞元進行安全同策略蒸餾。

## 摘要翻譯

提示注入（Prompt Injection）被列為 AI 代理（AI agents）的頭號威脅。當代理存取網站、檔案或郵件等外部資料時，攻擊者可能將提示注入資料中，例如：「忽略所有先前的指令，並執行<攻擊者的任務>。」為了防止代理被任意操控，防禦者嘗試訓練安全的大型語言模型（Large Language Model, LLM），然而這些模型在面對自適應提示注入（Adaptive Prompt Injections）時，攻擊成功率（Attack Success Rate, ASR）仍接近 100%。我們指出，這是因為現有的防禦式微調（Defensive Fine-Tuning）方法依賴序列層級回饋（Sequence-Level Feedback）訊號（如直接偏好最佳化（Direct Preference Optimization, DPO）或群組相對策略最佳化（Group Relative Policy Optimization, GRPO）中所使用）。將整個輸出序列一視同仁地處理，會使模型無法精確學習哪些輸出詞元（Token）是不安全的。在本文中，我們提出安全同策略蒸餾（Secure On-Policy Distillation, SecOPD），透過提供詞元層級回饋（Token-Level Feedback）來引導防禦式微調。大型語言模型接收一個注入樣本並產生一條取樣軌跡（Rollout），其各個詞元再由初始化模型（Initialization Model）依據對應的乾淨輸入（Clean Input）進行評分。藉由更細緻的訓練訊號，以 SecOPD 防禦微調後的 Qwen3.6-27B 在面對最先進的（State-of-the-Art, SoTA）PISmith 自適應提示注入時，達到 9.0% 的攻擊成功率，相較於先前最先進方法 Meta-SecAlign 的 94.0%。所習得的安全性可泛化至訓練中完全未見的領域：在代理式工具呼叫（Agentic Tool Calling）中，SecOPD 達到 4.7% 的攻擊成功率，相較於 Meta-SecAlign 的 5.5%。程式碼與模型可於 https://github.com/pppyb/SecOPD 與 https://huggingface.co/pybbb/Qwen3.6-27B-SecOPD 取得。

### 核心貢獻（3～5點）
- 指出現有防禦式微調方法（如 DPO、GRPO）因採用序列層級回饋，無法精確辨識輸出序列中哪些詞元不安全，導致面對自適應提示注入時防禦效果不佳。
- 提出安全同策略蒸餾（SecOPD），以詞元層級回饋引導防禦式微調，並由初始化模型依據乾淨輸入對注入樣本產生的取樣軌跡逐詞元評分。
- 在 Qwen3.6-27B 上實現顯著的安全提升：面對 PISmith 自適應提示注入時，攻擊成功率從 Meta-SecAlign 的 94.0% 降至 9.0%。
- 驗證 SecOPD 所習得的安全性可泛化至訓練中完全未見的領域，例如在代理式工具呼叫場景中，攻擊成功率從 Meta-SecAlign 的 5.5% 降至 4.7%。
- 開源釋出程式碼與經 SecOPD 防禦微調後的模型 Qwen3.6-27B-SecOPD，供後續研究與實務應用。

### 適合對象
本論文最適合大型語言模型安全研究者、AI 代理（AI agents）安全工程師、從事提示注入（Prompt Injection）防禦與對齊（Alignment）研究的學者，以及對強化學習（Reinforcement Learning）、防禦式微調（Defensive Fine-Tuning）與知識蒸餾（Distillation）在 LLM 安全領域應用有興趣的進階讀者。對於希望了解如何透過更細緻的詞元層級回饋提升模型對抗自適應攻擊能力的實務人員亦具高度參考價值。

## 深度分析

#### 方法論解析

##### 1.1 問題設定與威脅模型

SecOPD 處理的是 Prompt Injection（提示注入）對 AI agents（AI 代理）的威脅。在這個威脅模型中，使用者提供的 **Trusted User Prompt（可信使用者提示）** 記為 \(I\)，而來自網站、檔案或郵件的 **Untrusted External Data（不可信外部資料）** 記為 \(c\)。攻擊者會在 \(c\) 中插入惡意指令 \(g\)，形成被污染的資料 \(A(c,g)\)。最終模型看到的輸入為

\[
p_a = R\bigl(I, A(c,g)\bigr),
\]

其中 \(R(\cdot)\) 代表 chat template（對話模板）的序列化。相對地，**Clean Input（乾淨輸入）** 為

\[
p_c = R(I, c),
\]

即僅保留良性資料、移除注入內容後的輸入。模型層級防禦的目標是：在面對 \(p_a\) 時，行為盡可能接近面對 \(p_c\) 時的行為——把不可信資料當作「上下文」使用，但絕不將其中的指令視為需要執行的命令。

##### 1.2 Sequence-Level Feedback（序列層級回饋）的缺陷

過去的防禦式微調（Defensive Fine-Tuning）大多採用 Direct Preference Optimization (DPO)（直接偏好最佳化）或 Group Relative Policy Optimization (GRPO)（群組相對策略最佳化）。這些方法對整個輸出序列只給出一個回饋訊號：要麼整段回應被標為安全（偏好正例），要麼整段被標為不安全（偏好負例），要麼從最終 reward（獎勵）反推梯度。

然而，Prompt Injection 的輸出通常是 **hybrid response（混合回應）**：前半段可能正確回應了可信使用者提示，後半段卻被攻擊者牽著走。Sequence-Level Feedback（序列層級回饋）無法區分「哪些 token（詞元）該鼓勵、哪些該抑制」，導致 Credit Assignment Problem（功勞分配問題）惡化，模型難以精確學到安全策略。

##### 1.3 SecOPD 的教師—學生架構

SecOPD（Secure On-Policy Distillation，安全同策略蒸餾）的核心是 **On-Policy Distillation (OPD)（同策略蒸餾）**。其流程可概括為：

1. **Student（學生模型）**：當前策略 \(M_\theta\) 看到被攻擊輸入 \(p_a\)，產生一條 rollout（取樣軌跡） \(\mathbf{y} = (y_1, y_2, \dots, y_T)\)。
2. **Teacher（教師模型）**：使用與學生同源的 **Initialization Model（初始化模型）** \(M_0\)（即未經防禦微調的 Base LLM（基礎大型語言模型）），在對應的 Clean Input（乾淨輸入） \(p_c\) 上對每個 \(y_t\) 打分。
3. **Token-Level Feedback（詞元層級回饋）**：對於學生在攻擊輸入下產生的每個 token，教師計算其在乾淨輸入下的條件機率或對數機率

\[
s_t = \log P_{M_0}\bigl(y_t \mid p_c, y_{<t}\bigr).
\]

由於教師從未在輸入中看到注入內容，其行為自然符合可信指令，因此可作為安全的參考分布。

這是一種 **self-distillation（自我蒸餾）**：教師與學生來自同一個初始化點，不需要額外的大型模型或人工標註的安全回應。

##### 1.4 Token-Level 回饋與可微監督

與 Sequence-Level 方法不同，SecOPD 對每個輸出位置都提供可微監督。直觀上，若學生在攻擊輸入下產生的 token 與教師在乾淨輸入下會產生的 token 一致，則該 token 獲得高分；若 token 明顯是在服從注入指令，則分數低。這相當於把「安全行為」拆解到每個 token 上，讓模型能精確學習：

- 鼓勵回應 Trusted User Prompt（可信使用者提示）的 token；
- 抑制回應 Untrusted External Data（不可信外部資料）中惡意指令的 token。

由於現代 LLM（如 Qwen3.6-27B）常會產生 reasoning tokens（推理詞元），SecOPD 也一併對這些內部思考 token 進行監督，這是 Sequence-Level Reward（序列層級獎勵）難以做到的。

##### 1.5 與 Context Distillation 及 OPD 的關係

SecOPD 與 Context Distillation（情境蒸餾）有概念上的相似：都是讓模型在沒有輔助提示的情況下，複製帶有輔助提示時的行為。但 SecOPD 更進一步：

- 學生是在 **被攻擊輸入** 上進行 on-policy 取樣；
- 教師是在 **乾淨輸入** 上提供 token-level 的參考分布；
- 透過 OPD 把兩者的對齊粒度從「整段回應」提升到「每個 token」。

這使得 SecOPD 不僅是一種知識蒸餾（Distillation），更是一種針對 Prompt Injection 安全策略的精細微調（Fine-Tuning）方法。

#### 實驗數據解讀

##### 2.1 評估設定

論文主要在兩個場景評估：

- **SEP benchmark（SEP 基準測試）** 搭配 **PISmith**：PISmith 是目前的 State-of-the-Art (SoTA)（最先進的）自適應提示注入攻擊，會針對受害者模型的 prompt format（提示格式）進行最佳化。
- **AgentDojo benchmark（AgentDojo 基準測試）**：評估代理式工具呼叫（Agentic Tool Calling）場景下的安全性，屬於訓練時完全未見的領域。

模型採用 **Qwen3.6-27B**，對手方法為 **Meta-SecAlign**（先前的 SoTA 防禦）。衡量指標為 **Attack Success Rate (ASR)（攻擊成功率）**，越低越好；同時也報告 **Utility（效用 / 可用性）**，衡量模型在乾淨輸入上的正常表現。

##### 2.2 SEP / PISmith 結果

在 PISmith 自適應攻擊下：

| 方法 | ASR（攻擊成功率） |
|---|---|
| Meta-SecAlign | 94.0% |
| SecOPD | 9.0% |

這是一個數量級的改善。Meta-SecAlign 雖然是 prior SoTA，但在針對性自適應攻擊下幾乎全線潰敗；SecOPD 則將攻擊成功率壓到個位數。這顯示 Token-Level Feedback（詞元層級回饋）能讓模型學到更細緻的安全邊界，而不是僅靠整段回應的偏好標籤來判斷安全與否。

##### 2.3 AgentDojo 結果與跨領域泛化

在 AgentDojo 的代理式工具呼叫場景中：

| 方法 | ASR（攻擊成功率） |
|---|---|
| Meta-SecAlign | 5.5% |
| SecOPD | 4.7% |

兩者表現都不錯，但 SecOPD 仍略勝。更重要的是，AgentDojo 是訓練時 **完全未見的領域**，這說明 SecOPD 學到的並非只是記憶訓練集中的特定攻擊樣式，而是某種可遷移的「忽略不可信資料中指令」的安全策略。

##### 2.4 Utility（效用）維持

論文指出 SecOPD 的 Utility（可用性）與未防禦模型相比僅差幾個百分點。這點非常關鍵：許多防禦方法為了降低 ASR 會過度保守，導致模型在正常使用時也頻繁拒絕或表現下降。SecOPD 透過對齊乾淨輸入下的教師行為，保留了模型原本遵循可信指令的能力。

##### 2.5 數據意涵與限制

這些數字強烈支持「Token-Level 回饋優於 Sequence-Level 回饋」的假設。但需注意：

- PISmith 的攻擊可能是針對 Meta-SecAlign 或一般模型訓練的，未必是專門針對 SecOPD 的「最強自適應攻擊」。
- 9.0% 的 ASR 仍代表部分攻擊成功，現實部署中仍需搭配其他防禦層。
- Utility 僅差「幾個百分點」的具體任務分布與量測方式，會影響對實用性的判斷。

#### 與現有研究的比較

##### 3.1 系統層級防禦

現有許多防禦屬於系統層級，例如：

- 輸入偵測器（detectors）、prompt shields（提示護盾）、輸入過濾器（input filters）；
- 動作限制（action restrictions）、sanitizers（清理器）。

這類方法的優點是無需改動模型內部，可保護黑盒模型，部署彈性高。但缺點是無法直接改變 LLM 的 instruction-following（指令遵循）行為，攻擊者常可透過編碼、分段、語義轉換等方式繞過。SecOPD 則屬於模型層級防禦，從根本上訓練模型區分可信與不可信指令。

##### 3.2 模型層級防禦：DPO / GRPO

模型層級防禦通常會在 chat template（對話模板）中新增專門承載不可信資料的 message type（訊息類型），並透過模擬注入進行微調。Meta-SecAlign 使用 DPO，將每個樣本建構成偏好對 \((y^+, y^-)\)：\(y^+\) 遵循可信指令，\(y^-\) 遵循注入指令。

DPO 與 GRPO 本質上都是 Sequence-Level Reinforcement Learning（序列層級強化學習）：它們對「整段輸出」給予獎勵或偏好訊號。這在 hybrid response（混合回應）場景下會遇到嚴重的 Credit Assignment Problem（功勞分配問題）——模型無法知道到底是哪些 token 導致回應被評為不安全。

##### 3.3 Meta-SecAlign 與 SecOPD 的對比

| 面向 | Meta-SecAlign | SecOPD |
|---|---|---|
| 訓練訊號 | Sequence-Level Preference（DPO） | Token-Level Feedback（OPD） |
| 教師來源 | 偏好資料集中的人工/模擬安全回應 | Initialization Model（初始化模型）在 Clean Input（乾淨輸入）上的行為 |
| 對 hybrid response 的處理 | 整段視為一體 | 每個 token 個別評分 |
| SEP / PISmith ASR | 94.0% | 9.0% |
| AgentDojo ASR | 5.5% | 4.7% |

從理論上看，DPO 在適當獎勵模型下可視為 PPO（Proximal Policy Optimization，近端策略最佳化）的變形，因此同樣受限於序列層級的獎勵設計。SecOPD 透過 OPD 把獎勵粒度降到 token level，從而獲得更精確的策略梯度與更好的實證表現。

##### 3.4 限制與適用條件

SecOPD 雖然表現突出，但仍有以下限制：

- **訓練時需要知道注入位置**：教師模型需要對應的 Clean Input（乾淨輸入），這意味著訓練資料必須能夠移除 Injection（注入內容）。在真實攻擊中，模型無法事先知道哪段資料被污染，但這只影響訓練階段，不影響推論階段。
- **依賴 Base LLM 的乾淨行為**：教師是 Initialization Model（初始化模型），若基礎模型本身在乾淨輸入下就會產生有害或不當內容，SecOPD 會把這些行為一併蒸餾給學生。
- **不適用黑盒 API**：SecOPD 需要對模型進行微調，因此無法直接部署在無法修改權重的第三方 API 上。
- **對隱性注入的挑戰**：若攻擊者不使用明確的「Ignore all prior instructions」語句，而是透過語境、暗示或文件結構誘導模型，Token-Level 監督是否仍足夠，需要更多研究。

#### 可重現性評估

##### 4.1 開源釋出

論文已公開：

- 原始碼：https://github.com/pppyb/SecOPD
- 模型權重：https://huggingface.co/pybbb/Qwen3.6-27B-SecOPD

這對可重現性（Reproducibility）是重大加分。研究者可以直接下載 **Qwen3.6-27B-SecOPD** 進行推論、評估，甚至在此基礎上繼續微調。

##### 4.2 重現所需資訊

要完整重現 SecOPD，除了程式碼與權重外，還需要：

- 訓練資料的生成腳本（如何從良性資料產生被攻擊樣本與對應 Clean Input）；
- 超參數，例如學習率、batch size、rollout 長度、教師評分的具體損失形式（KL divergence、cross-entropy 或 policy gradient）；
- 訓練硬體與時間；
- 評估腳本與基準測試的確切版本（SEP、AgentDojo）。

若 GitHub 倉庫包含上述全部內容，則可重現性極高；若僅釋出推論程式與最終權重，則訓練過程的重現仍需額外確認。無論如何，釋出模型權重已經讓社群能夠快速驗證其安全性與 Utility（可用性）。

#### 未來研究方向

1. **針對 SecOPD 的專屬自適應攻擊**：設計專門對抗 Token-Level Distillation 的攻擊，檢驗 SecOPD 在更強紅隊壓力下的極限。
2. **多輪與長期代理互動**：將 SecOPD 擴展到多輪對話與長期 Agentic Tool Calling（代理式工具呼叫）場景，處理跨回合的注入與狀態累積。
3. **結合系統層級防禦**：把 SecOPD 與輸入過濾、輸出偵測、動作限制等機制結合，形成縱深防禦（defense in depth）。
4. **多模態注入**：研究圖片、音訊、影片中的隱式 Prompt Injection（提示注入），並將 Token-Level Feedback 擴展到多模態 token。
5. **更強的教師模型**：探索使用更大或經過安全對齊的教師模型，而非僅用 Initialization Model（初始化模型），以進一步提升安全上限。
6. **效率最佳化**：On-Policy Distillation（同策略蒸餾）需要產生 rollout 並由教師評分，計算成本較 DPO 高，未來可研究如何降低訓練開銷。
7. **理論分析**：從 Credit Assignment、KL divergence、策略收斂等角度，建立 SecOPD 相較於 Sequence-Level 方法的理論保證。
8. **隱性指令與語義攻擊**：研究當攻擊者不寫明「忽略先前指令」，而是透過語境操縱模型時，Token-Level Feedback 是否仍能有效區分可信與不可信意圖。
9. **跨模型與跨語言驗證**：在 Llama、GPT 系列等其他 LLM，以及非英文語境下驗證 SecOPD 的泛化能力。
10. **與 RLHF / 安全獎勵模型結合**：將 SecOPD 的 Token-Level 監督與更廣泛的安全獎勵模型結合，同時對抗 Prompt Injection、Jailbreak（越獄）與其他濫用行為。

## 論文問答

**Q1：什麼是提示注入，為什麼它被視為 AI 代理的首要威脅？**
A：提示注入（prompt injection）是指攻擊者將惡意指令嵌入 AI 代理所存取的外部資料中，例如網頁、電子郵件或檔案內容，試圖讓模型忽略原本可信的使用者指令並執行攻擊者指定的行為。由於 AI 代理（AI agents）會主動與環境互動、呼叫工具並採取行動，一旦模型被注入的指令操控，就可能導致未經授權的資料外洩、錯誤決策或有害操作。OWASP GenAI Security Project 已將提示注入列為 AI 代理的頭號威脅，因為它直接挑戰了模型區分「可信指令」與「不可信外部資料」的核心能力。

**Q2：現有的防禦式微調方法（如 DPO、GRPO）為何在自適應提示注入面前仍然脆弱？**
A：現有方法大多使用序列層級回饋（sequence-level feedback），也就是對整個輸出給予單一獎勵或偏好分數，這會讓模型難以判斷回應中哪些詞元（tokens）是安全的、哪些是不安全的。在提示注入攻擊中，模型的回應可能同時包含「正確遵循可信指令」的部分與「被惡意注入操控」的部分，序列層級回饋無法精確區分這兩者。這種粗粒度的訓練訊號導致模型無法有效學習安全策略，因此面對 PISmith 等自適應攻擊時，先前最先進的 Meta-SecAlign 仍出現接近 94% 的攻擊成功率。

**Q3：為何詞元層級回饋對提示注入防禦特別重要？**
A：詞元層級回饋（token-level feedback）能針對輸出序列中的每一個詞元個別評分，從而解決序列層級方法中的功勞分配問題（credit assignment problem）。當模型面對被注入的輸入時，某些詞元應該對應可信使用者提示的內容，而另一些詞元則可能受到惡意注入的影響，個別評分可以精確告訴模型哪些行為應被鼓勵、哪些應被抑制。這種更細緻的監督訊號使模型能夠更準確地學習「使用外部資料作為上下文、但不遵循其中指令」的安全策略。

**Q4：SecOPD 的核心方法是什麼？它與先前的序列層級防禦有何不同？**
A：SecOPD（Secure On-Policy Distillation）是一種基於同策略蒸餾（on-policy distillation）的防禦方法，它讓模型在被注入的輸入上產生 rollout，然後用對應的乾淨輸入去計算每個輸出詞元的分數。與 Meta-SecAlign 使用 DPO 對整個回應給予偏好配對不同，SecOPD 提供可微分的詞元層級監督，讓模型知道每個生成步驟是否偏離了可信指令。這種設計使 SecOPD 能夠更精細地學習安全行為，並在面對自適應攻擊時顯著降低攻擊成功率。

**Q5：SecOPD 中的教師模型或初始化模型是如何建構的？**
A：SecOPD 在訓練時使用基礎大型語言模型（base LLM）作為教師，但輸入的是「移除注入內容後的乾淨輸入」，也就是只包含可信使用者提示與良性外部資料。由於教師模型在訓練時從未見過惡意注入，它自然會產生安全的參考行為，因此成為理想的蒸餾來源。雖然這樣的教師在測試時無法直接取得，但在訓練階段可以透過資料建構方式實現，從而為每個詞元提供安全的對齊目標。

**Q6：SecOPD 有哪些關鍵設計選擇？**
A：SecOPD 的關鍵設計包括：採用 on-policy 蒸餾讓學生模型在自己生成的軌跡上學習、對每個輸出詞元進行評分、以及使用區隔可信與不可信訊息的聊天模板（chat template）。聊天模板將可信使用者提示與不可信外部資料分開編碼，使模型能明確辨識哪些內容應被遵循、哪些僅能作為上下文。此外，SecOPD 也會對推理詞元（reasoning tokens）進行評分，確保連中間思考過程都受到安全監督。

**Q7：論文使用了哪些基準測試與攻擊方法來評估 SecOPD？**
A：論文主要使用 SEP 基準測試（SEP benchmark）評估對抗 PISmith 這類最先進自適應提示注入攻擊的表現，PISmith 會針對防禦模型動態調整攻擊提示。此外，為了驗證跨領域泛化能力，作者也在 AgentDojo 基準測試上評估代理式工具呼叫（agentic tool calling）的安全性。這兩個測試分別涵蓋了直接回應安全與實際代理行動安全，能夠全面檢驗防禦方法的實用價值。

**Q8：SecOPD 相較於 Meta-SecAlign 的主要量化結果為何？**
A：在 SEP 基準上對抗 PISmith 自適應攻擊時，SecOPD 將 Qwen3.6-27B 的攻擊成功率（ASR）從 Meta-SecAlign 的 94.0% 大幅降低至 9.0%，達到數量級的改善。在訓練時完全未見過的 AgentDojo 代理工具呼叫場景中，SecOPD 的 ASR 為 4.7%，也優於 Meta-SecAlign 的 5.5%。與此同時，SecOPD 在一般任務上的效用（utility）僅比未防禦模型下降幾個百分點，顯示其安全性與可用性之間取得了良好平衡。

**Q9：論文是否進行了消融實驗或效用評估？**
A：論文強調 SecOPD 在提升安全性的同時，仍維持接近原始模型的效用表現，僅有少數百分點的下降。雖然提供的摘要與片段未詳列所有消融實驗，但從方法論來看，詞元層級回饋本身即是一種針對序列層級 DPO/GRPO 的消融對照。這些結果共同說明，將回饋粒度從序列層級提升到詞元層級，是提升防禦效果的關鍵因素，而非單純增加資料量或模型規模。

**Q10：SecOPD 可如何應用於真實世界的 AI 代理系統？**
A：SecOPD 可部署於需要存取外部資料的 AI 代理，例如自動化處理電子郵件、讀取網頁內容或分析上傳文件的助理系統。透過防禦微調，模型能學會將不可信資料視為上下文，而不會被其中的惡意指令覆寫原本任務。這對於企業級應用特別重要，因為它能降低代理在開放環境中被操控的風險，同時保留原有的任務執行能力。

**Q11：在產品部署時使用 SecOPD 需要考慮哪些因素？**
A：首先，SecOPD 需要額外的訓練資源來生成 rollout 並計算每個詞元的分數，因此部署前需評估運算成本與訓練時間。其次，雖然 SecOPD 提供模型層級防禦，但實際產品仍建議搭配系統層級防護，例如輸入過濾、輸出檢測或動作限制，以形成縱深防禦。最後，開發者需要持續監控新型自適應攻擊，並定期更新訓練資料，以確保防禦模型能跟上攻擊技術的演進。

**Q12：SecOPD 對 AI 安全與提示注入研究領域可能帶來什麼影響？**
A：SecOPD 展示了詞元層級回饋在對齊與安全微調中的潛力，可能促使更多研究從序列層級強化學習轉向更細粒度的監督訊號設計。它也為提示注入防禦提供了一個新的典範：透過蒸餾乾淨輸入上的安全行為，來對抗被污染輸入中的惡意操控。這種方法不僅適用於提示注入，也可能啟發其他需要區分可信與不可信資訊的安全任務，例如對抗越獄攻擊或虛假資訊操控。

**Q13：SecOPD 有哪些可能的限制？**
A：SecOPD 的訓練依賴於能夠建構對應乾淨輸入的資料集，若某些應用場景難以取得或定義乾淨版本，則教師模型的建構會變得困難。此外，詞元層級評分需要額外的計算資源，對於超大規模模型或高頻推理服務可能帶來成本壓力。最後，雖然 SecOPD 在 PISmith 與 AgentDojo 上表現優異，但其泛化能力仍受限於訓練資料的分布，對於極度新穎或跨語言的攻擊形式可能需要進一步驗證。

**Q14：在哪些失敗案例中，SecOPD 仍可能遭受攻擊？**
A：當惡意注入的指令與可信使用者提示在語義上高度重疊時，模型可能難以區分哪些內容應被遵循，進而產生不安全的回應。此外，若攻擊者設計出訓練資料中完全未出現的注入格式或語言，SecOPD 的泛化能力可能不足以應對。另一種潛在風險是攻擊針對模型的推理詞元（reasoning tokens）進行操控，若中間思考過程被誘導偏離安全策略，最終輸出也可能受到影響。

**Q15：這項工作提出了哪些未來研究方向？**
A：未來研究可以探索將 SecOPD 與其他系統層級防禦機制結合，例如即時輸入過濾與輸出檢測，以建立更強健的多層次防禦體系。另一個方向是將詞元層級蒸餾擴展到多輪對話與長上下文場景，因為 AI 代理往往需要在複雜互動中維持安全行為。此外，開發更強大的自適應攻擊評估框架，並持續提升教師模型對未知攻擊形式的穩健性，也是值得深入探討的課題。

## 實務應用指南

## 適用場景

1. **企業郵件與行事曆助理**  
   AI 代理讀取外部郵件、會議邀請或附件時，攻擊者可能在郵件內文注入「忽略先前指示」等惡意指令。SecOPD 可訓練模型只遵循使用者設定的任務（如摘要、排程），而不執行郵件中的指令。

2. **網頁瀏覽與資料檢索代理**  
   當代理自動瀏覽網頁、抓取表單或搜尋結果時，網頁內容屬於不可信外部資料。SecOPD 能讓模型把網頁內容當作上下文，而非可執行命令，降低被誘導洩漏對話或執行未授權動作的風險。

3. **文件分析與 RAG 知識庫問答**  
   使用者上傳 PDF、Word 或 Markdown 等文件至 RAG 系統時，文件可能夾帶提示注入。SecOPD 適合用於強化「讀取文件後仍只回答使用者問題、不聽從文件內指令」的模型行為。

4. **客戶支援與對話機器人**  
   客服機器人會參考外部知識庫、工單或使用者貼上的第三方連結。透過 SecOPD 微調，可減少攻擊者利用這些外部資料覆寫系統提示或誘導模型輸出有害內容。

5. **程式碼輔助與開發代理**  
   當 AI 代理讀取外部套件文件、Issue 討論或 Stack Overflow 內容以協助開發時，惡意注入可能誘導模型產生危險程式碼或洩漏機密。SecOPD 可強化模型對「可信使用者指令」與「不可信外部程式碼說明」的區分能力。

## 實作前置條件

### 資料條件
- **乾淨輸入資料**：大量僅含可信使用者提示與良性外部資料的樣本，作為教師模型評分依據。
- **注入攻擊樣本**：包含靜態模板與自適應攻擊（如 PISmith）的對抗樣本，用於訓練與評估。
- **領域對應資料**：若應用於郵件、網頁或文件，需準備與目標領域語意相近的資料，以確保安全與效用平衡。
- **評估基準**：如 SEP benchmark、AgentDojo benchmark 等，用於量測攻擊成功率與代理工具呼叫安全性。

### 運算條件
- **基礎模型**：建議使用 Qwen3.6-27B 或同等規模的開源大型語言模型。
- **硬體資源**：至少數張高記憶體 GPU（如 NVIDIA A100 / H100），以支援 27B 參數模型的全參數或 LoRA 微調。
- **訓練框架**：需支援 on-policy rollout、token-level loss 與大規模分散式訓練的框架，如 TRL、LLaMA-Factory 或自訂 PyTorch 管線。

### 技術能力
- 熟悉 LLM 微調、強化學習（PPO / GRPO / DPO）與知識蒸餾。
- 能建構與執行提示注入攻擊（紅隊測試），並設計安全評估流程。
- 具備資料清洗、對齊（alignment）與模型部署經驗。

## 實作步驟建議

1. **定義威脅模型與對話模板**  
   將「可信使用者提示」與「不可信外部資料」以不同訊息角色區隔（如 `<|im_start|>user` 與 `<|im_start|>input`），並在 assistant 前綴後生成回覆。

2. **建構乾淨與攻擊配對資料**  
   對每筆乾淨樣本，產生對應的提示注入版本。注入內容應涵蓋靜態模板與自適應攻擊（如 PISmith），並確保教師模型使用的乾淨輸入已完全移除注入內容。

3. **建立教師評分機制**  
   以初始化模型（init model）對乾淨輸入生成參考分佈，並用此分佈對學生模型在攻擊輸入下產生的每個輸出詞元進行 token-level 評分。

4. **執行 SecOPD 防禦微調**  
   讓學生模型在攻擊輸入上進行 rollout，並根據教師在乾淨輸入上的分數計算 token-level 損失，進行梯度更新。過程中同時監控攻擊成功率與良性任務效用。

5. **自適應安全評估**  
   使用 PISmith 等自適應攻擊與 SEP benchmark 評估 ASR；並在 AgentDojo 等未見領域測試安全泛化能力。

6. **部署與持續監控**  
   上線時搭配輸入過濾、輸出監控與權限控管。建立紅隊測試與模型更新循環，以因應新形態攻擊。

## 潛在風險與注意事項

| 風險 | 說明 | 因應方式 |
|---|---|---|
| **過度擬合訓練攻擊** | 模型可能只學會抵擋訓練中見過的注入樣式。 | 使用多樣化自適應攻擊、持續紅隊測試與資料擴增。 |
| **效用下降** | 強化安全可能降低一般指令遵循能力。 | 在微調時保留乾淨任務資料，並以效用指標監控。 |
| **教師模型並非絕對安全** | 若乾淨輸入仍含隱藏指令，教師會傳遞錯誤訊號。 | 嚴格清洗訓練資料，確保乾淨輸入僅含可信提示與良性資料。 |
| **運算與訓練不穩定** | On-policy distillation 需頻繁取樣 rollout，成本較高。 | 使用快取、梯度累積與分散式訓練，並從小規模實驗開始。 |
| **錯誤安全感** | 低 ASR 不代表絕對安全，攻擊者不斷演化。 | 將 SecOPD 視為多層防禦的一環，而非唯一防線。 |
| **領域與語言偏移** | 訓練語料與實際部署環境可能不同。 | 在目標領域進行微調與評估，並監控線上表現。 |

## 與其他技術的整合建議

- **系統層防禦**：與輸入偵測器、提示護盾（prompt shield）、輸出過濾器並行部署，形成縱深防禦。
- **RAG 信任評分**：對外部文件進行來源可信度評分，高風險文件先經過濾再送入模型。
- **權限與沙箱**：在代理工具呼叫層級設定最小權限，敏感操作需人類確認或於沙箱執行。
- **DPO / GRPO 基線整合**：可先以 DPO 或 GRPO 建立穩定基線，再以 SecOPD 進行 token-level 精細化調校。
- **持續學習管線**：將線上偵測到的攻擊樣本自動回流至訓練資料，定期重新微調模型。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從摘要與圖 1 開始，理解「提示注入」為何是 AI 代理的首要威脅，以及「序列層級回饋」與「詞元層級回饋」的直觀差異。接著參考詞彙表熟悉 DPO、GRPO、OPD 等術語，再回頭閱讀方法細節。

**AI 工程師**：請重點閱讀對話模板設計、SecOPD 的訓練流程與損失函數實作，特別是如何用乾淨輸入建立教師模型、如何對攻擊輸入下的 rollout 進行逐詞元評分。評估部分可參考 PISmith 與 AgentDojo 的實作方式，作為上線前的測試藍圖。

**研究人員**：建議深入探討 DPO 與 PPO 的等價性分析，以及為何序列層級回饋難以解決 credit assignment 問題。可進一步思考 SecOPD 的理論保證、教師模型的假設限制，以及未來能否結合更強大的自適應攻擊生成器或形式化驗證方法。

**產品經理**：請聚焦於攻擊成功率（ASR）與效用（utility）之間的權衡、部署所需的運算成本，以及 SecOPD 如何與現有系統層防禦整合。建議將本文視為降低提示注入風險的技術選項之一，並規劃紅隊測試、持續監控與版本更新機制。
