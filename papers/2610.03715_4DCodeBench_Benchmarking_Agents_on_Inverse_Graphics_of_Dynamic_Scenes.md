## ⚡ TL;DR

現有代理難以透過 4D 逆向圖形學，從影片重建具物理交互的動態場景。
提出 4DCodeBench，含兩百個動態場景，要求代理生成可執行圖形程式重建幾何與動態。
評測十八個前沿模型並對齊人類偏好後發現，動態重建仍是各模型的共同弱點。

## 摘要翻譯

我們提出 4DCodeBench，一個透過程式碼生成（code generation）進行 4D 逆向圖形學（4D inverse graphics）的基準測試（benchmark），其中代理（agents）從影片（video）中將動態場景（dynamic scenes）重建（reconstruct）為可執行圖形程式（executable graphics programs）。為達成此目標，代理必須將視覺觀測（visual observations）轉譯為場景結構（scene structure）與動態（dynamics）的緊湊表示（compact representations），並藉由實作如物理模擬（physical simulations）等抽象（abstractions）來重現複雜行為。為評估此能力，我們彙整一組真實世界影片（real-world videos），並建構涵蓋多樣物理現象（physical phenomena）的合成場景（synthetic scenes），包括形變（deformation）、流體流動（fluid flow）與斷裂（fracture）。我們對前沿模型（frontier models）進行廣泛的基準測試（benchmarking），發現強大的靜態重建（static reconstruction）能力尚未轉化為對複雜動態（complex dynamics）的可靠重建（reconstruction）。4DCodeBench 提供一個測試平台（testbed），用於追蹤代理在透過程式碼詮釋世界動態方面的進展。我們的基準測試可於 https://github.com/4DCodeBench/4DCodeBench 取得。

### 核心貢獻（3～5點）
- 提出 4DCodeBench，首個針對 4D 逆向圖形學的程式碼生成基準測試，要求代理從影片重建動態場景為可執行圖形程式。
- 建立涵蓋形變、流體流動、斷裂等多元物理現象的評估資料集，包含真實世界影片與合成場景。
- 透過廣泛評測前沿模型，揭示強大的靜態重建能力並不足以保證複雜動態的可靠重建。
- 提供追蹤多模態程式設計代理在視覺推理與物理模擬抽象能力進展的測試平台。

### 適合對象
電腦視覺、電腦圖形學、機器人學與人工智慧領域的研究者，特別是關注動態場景理解、逆向圖形學、程式碼生成代理、物理模擬與世界模型（world models）的學者與工程師。

## 深度分析

#### 方法論解析

本研究將 4D inverse graphics（4D 逆向圖形學）重新定義為一個 code generation（程式碼生成）任務：給定一段 reference video（參考影片）\(x_{\text{ref}}=(x_0,\dots,x_{T-1})\)，多模態程式設計代理（multimodal coding agent）必須輸出一組可執行圖形程式（executable graphics program）\(\Gamma=(\gamma_1,\dots,\gamma_m)\)，這些程式在執行時能夠於每個時間步重建場景的 3D geometry（3D 幾何）並透過 Blender 進行 render（渲染）。與傳統 inverse graphics（逆向圖形學）常見的「將觀測擬合到預設模型」不同，此處的 model specification（模型規格）被納入 inference problem（推論問題）本身：代理不僅要估計參數，還必須自行決定要用什麼 abstraction（抽象）來表達 scene structure（場景結構）與 dynamics（動態）。

任務設計有幾個核心特徵。首先，representation-agnostic（表示法不可知）：代理可以使用 keyframe（關鍵影格）、analytic motion（解析運動）、physical simulation（物理模擬）或任何工具（如 Taichi、Warp）來實現動態。其次，執行階段禁止存取 reference video（參考影片），因此程式必須內化所觀察到的物理規則，而非在執行時查表。第三，輸出必須暴露明確的幾何狀態 \(s_\Gamma(t)\)，並以指定的相機、燈光與材質渲染，確保輸出與參考影片在解析度、影格數與幀率上對齊。

資料集由 100 段 real-world video（真實世界影片）與 100 個 synthetic scene（合成場景）組成，涵蓋剛體與關節體、可變形固體、低維結構（布、繩）以及流動材質（顆粒、流體）等四大類。真實影片強調外觀真實性與複雜動態，但缺乏 4D ground truth（4D 真實標註）；合成場景則提供每幀的幾何與運動真值，便於在 3D/4D 空間直接評估。場景進一步區分被動動態與外部驅動動態（如機器人操作），並涵蓋 collisions（碰撞）、deformation（形變）、fluid flow（流體流動）與 fracture（斷裂）等現象。

評估框架分為三個層次：appearance（外觀）透過渲染影像與參考影片比較；geometry（幾何）在 synthetic scene（合成場景）上與 ground truth（真實標註）比對 2.5D 與 3D 資訊；dynamics（動態）則評估時間演化的正確性。為了對齊人類判斷，作者進行大規模 human preference study（人類偏好研究），並以 VLM（視覺語言模型）建立自動化評分機制。

#### 實驗數據解讀

研究評估了 18 個 frontier model（前沿模型），包含 proprietary model（專有模型）與 open-weight model（開放權重模型）。圖 2 左側呈現 cost–quality trade-off（成本–品質權衡）：橫軸為 VLM Elo（VLM Elo 評分），縱軸為 average tokens per task（每項任務平均 token 數）並採用 log scale（對數尺度）。靠近 Pareto frontier（帕雷托前緣）的模型代表以較低 token 消耗取得較高視覺品質；圖中可見 olE、MLV 等模型位於較佳位置，而部分開放權重模型雖然成本較低，但品質明顯落後。

圖 2 右側顯示 VLM Elo 與 human Elo（人類 Elo 評分）之間的高度一致性：Spearman \(\rho=0.980\)、Pearson \(r=0.993\)、coefficient of determination \(R^2=0.985\)、slope（斜率）約為 \(1.22\)。這表示 VLM-based 自動評分能夠可靠地追蹤人類偏好，為大規模、可重複的 benchmark（基準測試）評估奠定基礎。值得注意的是 slope 略大於 1，暗示 VLM 對於高分模型的區辨度可能稍高於人類，或人類對部分失敗案例較為寬容。

整體結果指出，現有模型在 appearance（外觀）與 static geometry（靜態幾何）上已有不錯表現，但 dynamic reconstruction（動態重建）明顯落後。這說明單靠強大的靜態重建能力並不足以掌握複雜動態。進一步觀察發現，雖然 analytic motion（解析運動）是最常見策略，但頂尖模型在實作方式上差異顯著，有的偏好參數化軌跡，有的則嘗試引入 physical simulation（物理模擬）。這也呼應了本 benchmark（基準測試）的核心動機：讓模型自行選擇與實現適當的 abstraction（抽象），而非強制統一表示法。

#### 與現有研究的比較

相較於傳統 inverse graphics（逆向圖形學）通常要求觀測擬合到預先給定的表示法（例如固定拓樸的網格或特定神經場），4DCodeBench 將 model specification（模型規格）變成推論輸出的一部分。這與近年 video-to-4D、NeRF、4D Gaussian Splatting 等方法形成對比：後者雖能產生連續視覺結果，但通常隱含固定表示法，且難以顯式區分 geometry（幾何）、material（材質）與 dynamics（動態）。本研究則要求代理輸出 executable graphics program（可執行圖形程式），使場景結構與物理規則變得可檢查、可編輯、可重複執行。

另一方面，當前熱門的 video generation（影片生成）模型能產生逼真影像，卻不一定具備真正的 3D 幾何或物理理解。4DCodeBench 透過要求輸出顯式幾何與動態程式，迫使模型進行「世界動力學」層次的推理，這對機器人 sim-to-real transfer（模擬到真實遷移）、數位孿生（digital twin）與可解釋 AI 都有重要意義。

然而，本研究也存在若干限制。資料集雖涵蓋多種物理現象，但刻意排除人類與動物，並偏好 stationary camera（固定相機）與有限遮擋，這降低了部分現實挑戰。合成場景依賴特定 physical simulation（物理模擬）的假設，可能無法完全捕捉真實世界的材質與接觸行為。此外，評估雖與人類高度相關，但仍以視覺相似性為主，對於物理正確性（如能量守恆、碰撞反應）的測量仍有限。

#### 可重現性評估

作者已將 benchmark（基準測試）與資料集釋出於 GitHub，並使用 Blender 作為統一渲染與執行環境，這有助於確保不同模型之間的 fair comparison（公平比較）。由於程式碼實作 simulator-agnostic（模擬器不可知），研究者可以重現評估流程，並在相同 common execution environment（共同執行環境）下測試新模型。

不過，可重現性仍受幾項因素影響。首先，100 段 real-world video（真實世界影片）來自多個現有資料集與網路來源，其授權與可再散布性可能限制部分使用情境。其次，部分 frontier model（前沿模型）為 proprietary model（專有模型），其權重與 API 行為可能隨時間改變，導致歷史分數難以完全復現。第三，合成場景使用多個物理模擬器與公開網格（如 Stanford bunny、armadillo），只要作者提供完整的場景描述、材質參數與模擬腳本，原則上可重現；但若缺少這些細節，則難以精確復原 ground truth（真實標註）。

#### 未來研究方向

1. **擴充資料規模與難度**：將場景數量從 200 擴展到數千，並納入人類與動物、移動相機（moving camera）、嚴重遮擋與非剛性交互，以更接近真實世界挑戰。
2. **發展物理正確性指標**：除了視覺相似性，可引入能量守恆、動量交換、拓樸變化一致性等物理指標，補強現有 appearance（外觀）導向的評估。
3. **結合神經表示與程式合成**：未來可探索 differentiable physics（可微分物理）與 neural scene representation（神經場景表示）的混合方法，讓代理在保持可執行程式優勢的同時，也能處理高解析度外觀細節。
4. **建立標準化物理領域特定語言（DSL）**：雖然表示法自由具彈性，但發展一套共享的 physics DSL 可提升可解釋性、可比較性，並促進社群累積可重複使用的模組。
5. **強化代理的規劃與迭代能力**：目前的評估多為單次生成，未來可引入多輪工具使用、執行錯誤回饋與自我修正機制，讓 agent（代理）能夠像軟體工程師般逐步除錯與優化 4D code（4D 程式碼）。
6. **跨模態與互動式評估**：讓代理不只看影片，還能接收文字描述、多視角影像或互動指令，進一步檢驗其對動態場景的因果與物理推理能力。

## 論文問答

**Q1：什麼是 4D 逆向圖形學，為什麼 4DCodeBench 選擇用「程式碼生成」來解決這個問題？**
A：傳統的逆向圖形學通常是將預設好的模型擬合到視覺觀測上，而 4DCodeBench 則要求代理程式根據參考影片寫出可執行圖形程式，把模型規格本身也變成推論問題的一部分。這種做法讓代理程式能夠自行決定要用什麼抽象來表達場景結構與動態，例如選擇關鍵影格或物理模擬。由於程式碼可以被執行並在 Blender 中渲染，評估者能直接檢視重建出來的 3D 幾何隨時間變化的結果，而不只是比對像素。

**Q2：現有的強大靜態重建方法為何在動態場景上仍然不足？**
A：靜態重建擅長恢復外觀與物體放置，但動態場景涉及形變、流體流動、斷裂以及材質交互作用，這些現象常伴隨形狀甚至拓樸的改變。僅靠靜態幾何與相機運動無法捕捉物體之間如何相互影響運動。4DCodeBench 的實驗也發現，即使模型在外觀與靜態幾何上表現良好，動態重建仍然是持續的弱項。

**Q3：為什麼需要一個專門針對動態場景逆向圖形學的基準測試？**
A：這個基準測試能檢驗多模態程式設計代理是否真正理解影片中的物理世界動態，而不只是複製視覺紋理。對機器人操作、虛擬製作與可模擬內容生成等應用而言，能從影片推論出可執行的動態表示非常重要。4DCodeBench 提供了一個標準化的測試平台，讓研究者能追蹤代理在解釋世界動態方面的進展。

**Q4：4DCodeBench 的核心任務定義是什麼？**
A：給定一段參考影片，代理程式必須產生一組稱為 4D 程式碼的可執行圖形程式，這些程式要建構場景的 3D 幾何並描述其隨時間的演化。執行後，程式必須在每個評估時間步暴露幾何狀態，並透過指定的相機、燈光與材質在 Blender 中渲染出影片。評估時代理無法再存取參考影片，因此程式必須內含完整的場景結構與動態資訊。

**Q5：4DCodeBench 相較於其他逆向圖形學或影片重建基準，關鍵創新在哪裡？**
A：它的關鍵創新在於把 4D 逆向圖形學視為開放式的程式碼生成問題，不強制使用特定模擬器或表示法。資料集同時包含 100 段真實世界影片與 100 個具備 4D 真實標註的合成場景，並分別評估外觀、幾何與動態三個層面。此外，研究團隊還開發了與人類判斷高度對齊的自動化視覺語言模型指標，使大規模評估更可行。

**Q6：為什麼要同時使用真實世界影片與合成場景？**
A：真實世界影片能呈現真實的外觀與複雜動態，且不受特定物理模擬器假設的限制，但缺乏 4D 真實標註。合成場景雖然依賴模擬器的物理假設，卻能提供每一幀的精確幾何與運動，讓評估可以直接在 3D 與 4D 空間進行。兩者互補，使基準既能貼近真實應用，又能進行嚴格的量化分析。

**Q7：實驗中評估了哪些模型與場景類型？**
A：研究團隊在共同執行環境下評估了 18 個前沿模型，包括專有模型與開放權重模型。場景涵蓋剛體與關節物體、可形變固體、布料與繩索等共維結構，以及顆粒與流體等流動材質。這些場景展現了碰撞、形變、流動與斷裂等多樣物理現象，能系統性地測試不同難度的動態重建能力。

**Q8：4DCodeBench 的主要實驗結果是什麼？**
A：結果顯示，無論是哪個模型，動態重建的表現都明顯落後於外觀與靜態幾何重建。雖然解析運動是最常見的策略，但頂尖模型在方法選擇上仍有顯著差異。圖 2 也顯示模型之間存在明顯的成本–品質權衡，而視覺語言模型的 Elo 評分與人類 Elo 評分高度相關，代表自動指標能有效反映人類偏好。

**Q9：研究如何診斷不同模型的重建失敗？**
A：透過大規模人類偏好研究與自動化指標，團隊分析了哪些場景屬性與物理機制最容易暴露模型的弱點。他們發現動態重建是幾乎所有模型一致的瓶頸，但不同模型在不同物理機制下的失敗模式並不相同。這種診斷式分析讓研究者能清楚看到目前多模態程式設計代理在物理推理上的具體缺口。

**Q10：4DCodeBench 的技術在哪些實際場景中有應用價值？**
A：這項技術可應用於機器人操作，讓機器人從示範影片中學習可模擬的物體動態模型。在虛擬製作與遊戲開發中，它能將真實影片轉換為可編輯、可重複渲染的 3D 動態資產。此外，科學視覺化與教育領域也能受益於自動從觀測影片生成可執行物理模擬的能力。

**Q11：如果要將這類代理產品化，需要考慮哪些工程與設計問題？**
A：首先需要安全的程式碼執行沙盒，因為代理會產生並執行圖形與模擬程式碼。其次要控制每項任務的 token 消耗與運算成本，圖 2 顯示不同模型在成本–品質權衡上差異很大。此外，還需處理真實世界中的遮擋、移動相機與非剛性物體，並確保自動評估指標與人類偏好持續對齊。

**Q12：4DCodeBench 對人工智慧與電腦圖形學領域可能帶來什麼影響？**
A：它搭起了影片理解與可程式化場景表示之間的橋樑，推動多模態模型從被動描述影像走向主動推理物理因果。透過提供標準化的資料集與評估協定，研究社群能更一致地比較不同方法在動態重建上的進展。長遠來看，這有助於發展出能夠透過程式碼解釋並重現世界動態的通用代理。

**Q13：4DCodeBench 有哪些已知的限制？**
A：資料集排除了人類、動物與大部分可見的手部，因為這些對象的詳細幾何與動作超出目前對材質動態的聚焦。真實世界影片優先選擇固定相機、少遮擋且無剪接的片段，因此尚未涵蓋更複雜的拍攝條件。合成場景則受限於所使用模擬器的物理假設，可能無法完全代表真實世界的所有材質行為。

**Q14：模型在哪些類型的場景或物理現象上最容易失敗？**
A：模型在涉及拓樸變化的現象上特別吃力，例如流體流動、斷裂與布料複雜摺疊。許多模型傾向使用簡化的解析運動來近似動態，而非真正實作物理模擬，導致長期穩定性與交互作用不真實。常見的失敗是外觀看起來合理，但物體運動、碰撞反應或材質特性與參考影片明顯不符。

**Q15：未來研究可以朝哪些方向改進？**
A：未來可以強化代理的物理推理能力，讓它們更懂得選擇並正確使用模擬器，甚至結合學習式物理模型。也可以擴展到更困難的真實條件，例如移動相機、嚴重遮擋與包含人類或動物的場景。此外，開發更精細的自動評估指標、支援互動式修正，以及將世界模型與程式碼生成結合，都是值得探索的方向。

## 實務應用指南

### 適用場景

1. **機器人學習與模擬資料生成**  
   將真實操作影片轉換為可執行的 3D 物理程式，讓機器人在模擬環境中重現抓取、推動、形變等動態，用於生成低成本、可擴充的訓練資料。

2. **影視與遊戲資產自動化**  
   把實拍或合成影片逆向重建為 Blender 可執行的動態場景程式，加速流體、布料、破碎等特效資產的製作與迭代。

3. **數位孿生與製程監控**  
   針對產線或實驗室的動態過程（如材料形變、顆粒流動），建立可解釋的 4D 幾何與物理表示，用於異常檢測、流程回放與虛擬除錯。

4. **擴增實境（AR）內容製作**  
   從單一參考影片產出帶有時間軸的 3D 幾何程式，讓虛擬物體在真實環境中以正確物理行為互動。

5. **科學與工程現象建模**  
   對實驗影片（如斷裂、液滴撞擊、軟體形變）進行逆向圖形學重建，協助研究人員驗證材料參數與物理假設。

---

### 實作前置條件

**資料**
- 高品質參考影片：靜止或已知相機運動、低遮蔽、連續無剪接，解析度與幀率一致。
- 若需 3D/4D 真實標註，建議搭配合成場景，使用物理模擬器產生逐幾何何與運動真值。
- 場景分類清單：剛體／關節、可變形固體、布料／繩索、顆粒／流體等。

**運算資源**
- GPU 伺服器：用於 Blender 渲染、物理模擬（Taichi／Warp）以及多模態模型 inference。
- 足夠的儲存空間：每個場景需保存參考影片、生成程式、渲染結果、中間幾何狀態與評估指標。
- Token 預算：前沿模型每項任務可能消耗數百萬 token，需評估成本–品質權衡。

**技術能力**
- 熟悉 Python、Blender API、物理模擬器（如 Taichi、Warp、PyBullet）。
- 具備電腦視覺與 3D 圖形學基礎，能判斷幾何、外觀與動態重建品質。
- 熟悉多模態程式設計代理的提示工程與程式碼執行環境隔離。
- 具備評估指標設計能力，包含 VLM-based 自動評分與人類偏好對齊。

---

### 實作步驟建議

1. **定義任務範圍與成功指標**  
   決定要重建的物理類別（剛體、形變、流體、斷裂），並設定外觀、幾何、動態三方面的評估權重。

2. **準備參考影片與執行環境**  
   收集或合成影片，建立統一格式（解析度、幀率、長度）。部署 Blender 與選定的物理模擬器，並確保代理無法在執行時存取參考影片。

3. **選擇與設定多模態程式設計代理**  
   依據成本–品質權衡挑選模型。設計 prompt，要求代理輸出可執行的 4D code，並明確規定格式的輸出（幾何狀態、相機、燈光、材質）。

4. **生成與執行 4D code**  
   讓代理根據參考影片撰寫程式，執行後產生逐幀幾何狀態與渲染結果。記錄執行時間、token 用量與是否成功執行。

5. **多維度評估重建結果**  
   - **外觀**：比較渲染影像與參考影片的視覺相似度。  
   - **幾何**：在合成場景上比對 3D 幾何真值。  
   - **動態**：分析隨時間變化的運動與物理行為是否正確。  
   同時使用 VLM Elo 與人類偏好研究校正自動指標。

6. **診斷失敗模式並迭代**  
   針對動態重建較弱的案例，分析是物理抽象選擇錯誤、材質參數不準、拓樸變化處理失敗，還是相機運動估計有誤，再調整 prompt 或引入專家規則。

7. **產品化與持續監控**  
   將通過評估的程式納入資產管線，建立版本控制與回歸測試，並持續用新場景更新基準測試。

---

### 潛在風險與注意事項

- **動態重建明顯落後於外觀與靜態幾何**  
  即使外觀看起來合理，運動與物理行為可能錯誤。建議將動態指標設為通過門檻，而非僅看視覺相似度。

- **物理模擬器與真實現象不匹配**  
  合成場景依賴模擬器假設，真實世界影片則無真值。應混合真實與合成資料進行驗證，並對模擬器參數做敏感性分析。

- **拓樸變化與材質交互困難**  
  斷裂、流體、顆粒等涉及形狀與拓樸改變，代理常選擇解析運動或簡化模型。可預先提供場景分類提示，或限制使用特定模擬器。

- **遮蔽、移動相機與人體干擾**  
  論文已排除人類與動物，並偏好靜止相機。產品應先進行相機標定與前景分割，降低干擾。

- **高運算與成本風險**  
  前沿模型 token 消耗大，渲染與模擬也耗 GPU。建議先用小規模子集做帕雷托前緣分析，再決定部署模型。

- **安全與授權**  
  真實世界影片需注意版權與隱私；自動生成的程式碼應在沙箱中執行，避免惡意操作或資源耗盡。

---

### 與其他技術的整合建議

- **與 MLOps／評估管線整合**  
  將 4DCodeBench 的評估指標（VLM Elo、幾何誤差、動態誤差）接入 CI/CD，對每次模型更新進行回歸測試。

- **與遊戲引擎（Unity／Unreal）連接**  
  透過 Blender 匯出 FBX／USD，將重建的動態場景轉為遊戲引擎資產，或用於即時渲染與互動應用。

- **與數位孿生平台整合**  
  將重建出的可執行物理程式嵌入數位孿生，用於模擬「假設情境」與預測設備或材料行為。

- **與人機協作審查系統整合**  
  利用 VLM-based 自動評分做初篩，再由領域專家進行人類偏好判斷，形成高效率的品質確認迴圈。

- **與模擬器生態系結合**  
  支援 Taichi、Warp 等模擬器，並可根據場景類型自動選擇最適合的後端，提升重建的物理正確性。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從摘要與第 1 節開始，理解「把影片變成可執行圖形程式」的核心概念，再瀏覽第 2 節的任務定義與資料集分類。技術細節如評估指標與模擬器實作可先略讀，重點放在為什麼動態重建比靜態重建更困難。

**AI 工程師**  
請聚焦第 2.1 節的任務形式化、第 2.4 節的評估指標，以及實驗中的成本–品質權衡圖。這些內容直接影響你如何設計 prompt、執行環境、錯誤處理與自動評分管線。建議同時參考附錄中的模擬器與資料來源。

**研究人員**  
建議深入閱讀基準建構方法、人類對齊的 VLM 評估設計，以及不同模型在各类物理現象上的失敗分析。論文提出的「讓代理自行選擇物理抽象」是關鍵研究問題，可延伸探討結構化先驗、世界模型與程式合成之間的結合。

**產品經理**  
重點閱讀適用場景、資料集統計與成本–品質權衡。理解目前前沿模型在動態重建上的限制，有助於設定合理的產品範圍、評估投入產出比，並規劇與設計師、工程師、領域專家協作的人機審查流程。
