## ⚡ TL;DR

本文探討多智能體LLM工作流程在端到端強化學習訓練下，何時能提升效能及其不穩定成因。
研究橫跨三種工作流程、數學與程式碼任務及三種模型規模，比較共享與獨立策略訓練。
結果顯示多智能體RL通常優於基礎模型，但策略共享與否會因工作流程與任務產生不同權衡與失效模式。

## 深度分析

#### 方法論解析

本研究的核心方法論並非提出新的訓練演算法，而是建立一個控制變因的實驗網格（controlled experimental grid），以系統性地檢驗多智能體強化學習（Multi-Agent Reinforcement Learning, MARL）在大型語言模型（Large Language Model, LLM）工作流程（workflow）中的表現條件。實驗設計橫跨四個維度：任務（task，數學推理與程式碼生成）、模型規模（model scale，Qwen3 的 0.6B、1.7B 與 4B）、策略路由策略（policy-routing strategy，共享策略訓練（Shared-Policy training）相對於獨立策略訓練（Isolated-Policy training）），以及工作流程拓撲（workflow topology）。

在三種工作流程拓撲中，Eval-Opt 採用生成器（Generator）產生草稿（Draft），再由評估器（Evaluator）進行評估並驅動修訂（Revision），形成序列式的生成-評估-改進迴路；Voting 則部署多個投票者（Voter）對問題進行獨立判斷，最終由聚合器（Aggregator）彙整出最終答案；Orch-Workers 則由編排器（Orchestrator）將子任務委派給多個工作者（Worker），最後由合成器（Synthesizer）產出最終輸出。後兩者因包含平行同角色智能體（parallel same-role agents），其互動模式與 Eval-Opt 的序列式角色有本質差異。

訓練採用端到端強化學習訓練（end-to-end RL training），以結果獎勵（outcome reward）作為唯一的回饋訊號，透過群組相對策略最佳化（Group Relative Policy Optimization, GRPO）進行最佳化。具體而言，每個問題進行 n=8 次展開（rollout），在該群組內計算相對優勢函數（advantage），且刻意不對參考策略（reference policy）施加明確的 KL 懲罰（KL penalty）。這種設計凸顯了工作流程拓撲與策略路由本身對訓練穩定性的純粹影響，排除了額外正則化項的干擾。

尤為關鍵的是對照組（control）的設置：除了未經訓練的基礎模型（base model）外，研究還針對每個模型規模與任務設置了單智能體強化學習（single-agent RL）對照。這使得研究者能夠將「多智能體互動所帶來的增益」與「單純由強化學習引起的性能提升」分離，從而精確定位多智能體訓練的邊際效益與特有風險。資料集採用 DAPO-Math-17K（數學任務, Math task）與 DeepCoder（程式碼任務, Code task），模型則統一使用 Qwen3 系列，確保架構固定下僅有規模變異。

#### 實驗數據解讀

實驗結果首先確立了一個基線事實：多智能體強化學習訓練（multi-agent RL training）在多數設定下確實優於未經訓練的基礎模型。然而，增益並非均勻分布，而是取決於工作流程（workflow）、任務（task）與模型規模（model scale）的聯合效應，而非單純由策略共享策略（policy-sharing strategy）所決定。

在策略共享的權衡（policy-sharing tradeoff）上，獨立策略訓練（Isolated-Policy training）通常能達到更高的峰值準確率（peak accuracy），但更容易在訓練後期遭遇終端準確率斷崖（terminal accuracy cliff）——即性能在達到高點後急劇崩落。相對地，共享策略訓練（Shared-Policy training）雖然在天花板表現上較為保守，卻並未如直覺預期般消除失效，而是將訓練壓力（training pressure）重新分配到不同通道，產生質性迥異的失效特徵（failure signature）。值得注意的是，部分共享策略下的失效模式在詞元層級（token-level）的訓練指標中並不可見，僅在回合正確性層級（episode-correctness layer）才浮現，這意味著傳統的損失監控可能無法及時捕捉多智能體訓練的隱性劣化。

為解釋這些現象，作者提出兩個由工作流程拓撲與策略路由誘導的角色層級梯度動態（role-level gradient dynamics）機制：

第一，梯度放大（gradient amplification）發生於獨立策略訓練下的 Voting 與 Orch-Workers 工作流程。由於這些拓撲包含平行同角色智能體（parallel same-role agents）處理共享提示（shared prompts），多個智能體從相似輸入中計算出的每角色梯度（per-role gradient）會產生建設性干涉，放大該角色參數的更新幅度。這種放大效應在訓練初期可能加速收斂，但在後期卻導致過度優化與終端劣化。

第二，共享策略角色捕獲（sp_role_capture）則是共享策略訓練下的核心病理。由於所有角色共用同一組參數（parameters），不同角色在每個時間步貢獻的梯度量並不對稱。當某一角色（例如編排器或生成器）在軌跡（trajectory）中佔據主導地位時，其非對稱每步梯度量（asymmetric per-step gradient mass）會將共享策略拉向該主導角色（dominant role）的行為模式，造成其他角色的功能被壓抑。此效應的具體失效特徵會隨任務與工作流程而變：在需要高度角色分化的程式碼任務中，這可能表現為工作者退化為被動執行單元；在數學推理中，則可能表現為評估器或投票者的判斷標準被生成器的分佈所覆蓋。

#### 與現有研究的比較

現有多智能體強化學習研究大致可分為兩條脈絡：一是針對特定工作流程設計演算法變體，如 AT-GRPO、MAGRPO、M-GRPO 與 MHGPO，分別處理樹狀採樣、分散式部分可觀察馬可夫決策過程（Dec-POMDP）、階層式可變長度子智能體呼叫，以及異質群組優勢等問題；二是聚焦系統層級的策略適應，如 MPDF 與 MARFT，探討基於排序的元策略或 LoRA 適配器的微調框架。近期 Dr.MAS 則進一步指出全局優勢正規化（global advantage normalization）所導致的梯度範數不平衡（gradient-norm imbalance），並提出智能體層級正規化（agent-wise normalization）作為對策。

相較於上述研究多從演算法層面提出針對性修補，本研究的定位是結構性與經驗性的。它不追求設計新的訓練目標函數，而是透過控制變因的跨工作流程、跨規模、跨任務實證比較，搭配基礎模型與單智能體強化學習對照，建立多智能體訓練失效的經驗地圖（empirical map）。在解釋層面，本文將觀察到的最強模式歸因於工作流程拓撲與策略路由所誘導的梯度動態，而非單純的優化雜訊。這與 Long et al. 從散度選擇（divergence-choice）角度處理多樣性崩潰（diversity collapse）、Wang et al. 透過輕量級協議監控修復角色漂移（role drift）、或 Zhang et al. 關注智能體貢獻不足（agent under-contribution）等後驗修復導向的研究形成互補——本文旨在說明哪些結構條件會在訓練初期即誘發這些病理。

然而，本研究也存在可延伸的空間。首先，每個實驗配置僅以固定隨機種子（fixed seed）訓練一次，缺乏跨種子的統計顯著性評估；其次，刻意省略 KL 懲罰雖有助於凸顯拓撲效應，卻也意味著研究結論可能無法直接推廣至採用強正則化的標準強化學習流程；最後，模型規模上限為 4B，對於更大規模模型（如 70B 等級）中角色專精化（role specialization）與策略漂移的互動關係，仍屬開放問題。

#### 可重現性評估

在資料與模型層面，本研究採用的 Qwen3 系列模型權重已公開釋出，涵蓋 0.6B、1.7B 與 4B 三種規模，這為外部復現提供了堅實基礎。資料集方面，DAPO-Math-17K 與 DeepCoder 在文獻中亦有公開紀錄，理論上可降低資料準備的門檻。訓練演算法 GRPO 及其結果獎勵迴路（outcome-reward loop）在社群中已有相對成熟的實作參考。

儘管如此，根據提供的文本內容，作者並未明確宣告訓練程式碼、超參數（hyperparameters）配置檔、或訓練後策略權重（policy checkpoints）的開源釋出。由於多智能體工作流程的實作涉及複雜的角色排程、提示路由（prompt routing）與梯度聚合邏輯，缺乏官方釋出的程式碼將顯著增加獨立復現的難度。此外，工作流程拓撲中平行同角色智能體的展開（rollout）同步機制、以及獨立策略與共享策略在反向傳播時的具體參數隔離或共享實作細節，若無參考實作，外部研究者難以確保其復現結果與原文嚴格對應。因此，本研究在方法論透明度上具備概念層級的可重現性，但在工程實作層級的完全可重現性仍有賴作者後續釋出原始碼。

#### 未來研究方向

基於本文所揭示的經驗地圖與梯度動態機制，未來研究可沿以下數個方向展開：

第一，演算法層級的病理抑制。針對獨立策略訓練中的梯度放大（gradient amplification），可設計基於角色層級的梯度裁剪（per-role gradient clipping）或自適應學習率調度；針對共享策略訓練中的 sp_role_capture，則可探索對稱化梯度質量（symmetric gradient mass）的正則項，或動態遮罩（dynamic masking）以保護弱勢角色的梯度貢獻。

第二，混合策略路由（hybrid policy routing）。未來可設計條件式或動態的策略共享機制，例如在訓練初期採用共享策略以穩定探索，待角色分化明確後逐步分離為獨立策略；或依據每步梯度對稱性自動切換路由模式，以期兼取兩者之長。

第三，規模與拓撲的擴展驗證。當模型規模擴展至 14B、72B 甚至更大時，角色專精化（role specialization）的能力可能顯著提升，從而改變梯度動態的相對強度。此外，將分析框架延伸至辯論（debate）、搜尋（search）、階層式工具使用（hierarchical tool use）等更複雜的互動模式，可檢驗本文機制的泛化性。

第四，正則化效應的系統性研究。本文刻意排除 KL 懲罰以隔離變因，但未來應量化 KL 懲罰、熵獎勵（entropy bonus）或參考模型錨定（reference model anchoring）對終端準確率斷崖與角色捕獲現象的緩解或轉移效果。

第五，早期失效偵測系統。由於部分失效僅在回合正確性層級顯現，開發基於軌跡（trajectory）結構或角色間互動資訊流的即時監控器，可在訓練過早階段預警策略劣化，避免資源浪費。

第六，跨任務角色遷移。探討在多智能體強化學習中習得的角色策略（role-specific policy）是否能遷移至新任務，以及策略共享或獨立的選擇如何影響遷移效率，將有助於建構更通用的多智能體 LLM 系統。

## 論文問答

**Q1：多智能體 LLM 工作流程在引入強化學習進行端到端訓練時，面臨什麼樣的核心問題？**
A：多智能體 LLM 工作流程雖然能透過專門化角色在推論時期提升最終任務準確率，但當使用強化學習對這些角色進行聯合訓練時，訓練過程往往呈現不穩定的現象。這種不穩定性具體表現為訓練後期可能出現終端準確率斷崖，或是某些角色逐漸退化，而現有研究對於這些現象背後的機制仍缺乏系統性的理解。因此，研究者難以預判在何種工作流程、任務與模型規模下，端到端強化學習訓練真正能帶來穩定的提升，而非反而損害基礎模型的表現。

**Q2：現有的多智能體強化學習方法（如 AT-GRPO、MAGRPO 等）為何不足以回答「何時以及為何訓練會成功或失敗」這個問題？**
A：現有方法大多針對特定的工作流程拓撲（如辯論、搜尋或階層式工具使用）設計專門的演算法元件，例如引入特殊的優勢函數計算方式或軌跡對齊機制。雖然這些工作在各自設定的場景中展現了可行性，但它們並未提供一個跨工作流程、跨任務且包含適當對照組的系統性比較框架。換句話說，缺乏同時控制基礎模型與單智能體強化學習對照組的嚴謹實驗設計，使得我們無法區分「多智能體互動帶來的增益」與「單純強化學習本身就能產生的增益」，也無法歸因失敗是源於多智能體互動還是單一策略的漂移。

**Q3：為什麼理解策略共享（Shared-Policy 與 Isolated-Policy）的權衡對多智能體 LLM 工作流程的設計至關重要？**
A：策略共享策略決定了訓練壓力如何透過策略路由在不同角色之間傳遞與分配，這直接影響了每角色梯度的形成與更新方向。選擇獨立策略訓練雖然能讓各角色擁有獨立參數以追求更高的峰值準確率，但容易因平行同角色智能體的梯度放大效應而墜入終端準確率斷崖；相對地，共享策略訓練雖然較為保守，卻可能導致共享策略被主導角色捕獲，產生截然不同的失效特徵。因此，策略共享並非單純的「穩定性開關」，而是一個會與工作流程拓撲和任務類型產生複雜交互作用的設計選擇，必須根據具體應用條件來權衡。

**Q4：本研究採用的核心實驗架構是什麼？它如何確保研究結果的嚴謹性與可比性？**
A：本研究建立了一個橫跨四個維度的控制網格：任務（數學任務與程式碼任務）、模型規模（0.6B、1.7B、4B 的 Qwen3 系列）、策略路由策略（共享策略與獨立策略），以及工作流程拓撲（Eval-Opt、Voting、Orch-Workers）。為了確保嚴謹性，每一個實驗細胞都同時與未經訓練的基礎模型對照組，以及在同樣任務與規模下訓練的單智能體強化學習對照組進行比較，從而將「多智能體訓練特有的增益或漂移」從「強化學習的一般效應」中分離出來。這種系統性的實驗設計讓研究者能夠獨立評估工作流程、任務、模型規模與策略共享策略對最終任務準確率的聯合影響，而非僅觀察單一因素的效應。

**Q5：相較於既有文獻，本研究在解釋訓練動態方面的關鍵創新是什麼？**
A：本研究的關鍵創新在於從「工作流程拓撲與策略路由所誘導的角色層級梯度動態」來解釋觀察到的失效模式，而非僅停留在現象描述。具體而言，研究提出了兩個核心機制：一是在獨立策略訓練下的「梯度放大」（gradient amplification），即平行同角色智能體在共享提示上運作時會放大每角色梯度，導致 Voting 與 Orch-Workers 工作流程的終端退化；二是在共享策略訓練下的「共享策略被主導角色捕獲」（sp_role_capture），即非對稱每步梯度量使得共享策略逐漸被某一主導角色掌控，並依任務與工作流程產生不同的失效特徵。這種結構性的解釋將多智能體強化學習的穩定性問題從演算法層次下沉到角色互動與梯度流動的層次，提供了更具一般性的理論視角。

**Q6：為什麼研究選擇 GRPO 作為訓練演算法，並且不使用明確的 KL 懲罰項？**
A：研究選擇群組相對策略最佳化（GRPO）是因為它已成為可驗證獎勵強化學習（RLVR）中訓練大型語言模型的標準方法，特別適合以結果獎勵作為訊號的場景。不使用明確的 KL 懲罰項是為了直接觀察在多智能體設定中，純粹的結果獎勵 GRPO 迴路會產生什麼樣的訓練動態與漂移現象，避免正則化項掩蓋由工作流程拓撲與策略路由所引發的本質不穩定性。這樣的設計選擇雖然可能讓訓練更為激進，但卻能更真實地反映多智能體互動下梯度動態的原始行為，有助於識別那些隱藏在 token 層級訓練指標之下、僅在回合正確性層面才浮現的失效模式。

**Q7：實驗涵蓋了哪些基準測試與模型規模？這樣的選擇有何考量？**
A：實驗涵蓋了數學推理任務（使用 DAPO-Math-17K 資料集）與程式碼生成任務（使用 DeepCoder 資料集），並在 Qwen3 模型家族的三個規模（0.6B、1.7B、4B）上進行驗證。選擇數學與程式碼任務是因為這兩個領域具備可驗證結果，能夠提供明確的結果訊號與結果獎勵，非常適合評估強化學習帶來的實質改進。採用同一模型家族的不同規模則是為了在固定架構的前提下，系統性地檢驗模型容量如何影響角色專門化、策略漂移與工作流程層級的行為變化，從而揭示規模與多智能體訓練穩定性之間的關聯。

**Q8：實驗結果顯示，多智能體強化學習相較於基礎模型與單智能體強化學習的整體表現趨勢為何？**
A：整體而言，多智能體強化學習訓練在大多數設定下確實能夠提升基礎模型的表現，顯示透過工作流程分解與角色專門化進行端到端訓練具有實質潛力。然而，這些增益並非均勻分布，而是共同取決於工作流程拓撲、任務類型與模型規模，單純改變策略共享策略並無法保證穩定改善。值得注意的是，獨立策略訓練往往能達到更高的峰值準確率，但同時也更頻繁地遭遇終端準確率斷崖；共享策略訓練則未能消除失敗，而是將失敗重新分配到性質不同的模式中，甚至有些共享策略的失效特徵在 token 層級的訓練指標中無法被察覺，必須透過回合正確性才能發現。

**Q9：獨立策略訓練與共享策略訓練在失效模式上有何具體差異？有無任何隱藏的失效特徵？**
A：獨立策略訓練的主要失效模式是「終端準確率斷崖」，即在訓練後期準確率突然急劇下滑，這在 Voting 與 Orch-Workers 工作流程中尤為明顯，其根源在於平行同角色智能體對每角色梯度的放大效應。共享策略訓練則不會出現相同的斷崖，而是表現為共享策略被某一主導角色捕獲，導致其他角色實質上失去專門化功能，並依據不同任務與工作流程呈現出多樣的失效特徵。最隱蔽的是，某些共享策略訓練的失敗並不會反映在傳統的 token 層級訓練指標（如損失或 KL 散度）上，而是只有在檢視整個回合的最終答案正確性時才會暴露出來，這使得僅監控訓練損失可能無法及時偵測到訓練漂移。

**Q10：這些研究發現對於實際部署多智能體 LLM 系統（如數學解題或程式碼生成工具）有何具體的設計啟示？**
A：對於實際產品開發者而言，這項研究提醒在設計多智能體 LLM 工作流程時，不能預設共享策略就一定比獨立策略更穩定，而必須根據具體的工作流程拓撲來選擇策略路由方式。例如，在包含大量平行同角色智能體的 Voting 或 Orch-Workers 架構中，採用獨立策略可能帶來更高的準確率天花板，但必須搭配嚴格的終端訓練監控以防範準確率斷崖；反之，共享策略雖然較為保守，但需要警覺主導角色捕獲所造成的隱性角色退化。此外，由於失效特徵可能在 token 層級指標中隱藏，產品團隊應建立以回合正確性為核心的評估管線，而非僅依賴訓練損失來判斷模型品質。

**Q11：在選擇多智能體工作流程的拓撲結構時，產品團隊應該如何權衡 Eval-Opt、Voting 與 Orch-Workers 的適用場景？**
A：Eval-Opt 流程透過生成器與評估器的迭代修訂來提升輸出品質，適合需要精細打磨單一輸出的場景，例如數學證明或文件生成；Voting 流程則透過多個投票者與聚合器來匯集共識，適合答案空間明確且可從多元視角受益的判斷型任務。Orch-Workers 流程由編排器動態委派給多個工作者，再經合成器整合，適合需要將複雜問題分解為異質子任務的程式碼生成或專案規劃場景。產品團隊應根據任務是否可驗證、是否需要平行探索、以及角色之間的依賴關係來選擇拓撲，並同時考量該拓撲與策略共享策略交互作用後對訓練穩定性的影響。

**Q12：本研究對多智能體強化學習這個研究領域可能帶來什麼樣的長遠影響？**
A：本研究將多智能體強化學習的討論從「設計新演算法」拓展到「理解結構與動態」，強調工作流程拓撲與策略路由是決定訓練成敗的關鍵結構性因素，而非僅是演算法細節的優化問題。這種觀點可能引導未來研究更重視「拓撲感知」的訓練方法，例如在設計目標函數時主動考量角色之間的梯度流動與非對稱貢獻，而非僅套用單一的全局最佳化框架。此外，研究揭示的隱性失效特徵也凸顯了發展輕量級協議層級監控器與角色層級診斷工具的必要性，這將有助於建立更可靠、可解釋的多智能體 LLM 系統。

**Q13：作者承認本研究存在哪些主要限制？**
A：本研究的主要定位是提供一個系統性的經驗地圖與機制解釋，而非提出一個全新的訓練演算法來解決觀察到的不穩定性問題。實驗雖然橫跨多個維度，但僅使用了 Qwen3 模型家族與 GRPO 訓練框架，尚未驗證這些發現是否能直接推廣到其他模型架構（如 Dense-MoE 混合架構）或不同的強化學習演算法（如 PPO 或 DPO 的多智能體變體）。此外，研究中的每個實驗細胞僅使用固定種子訓練一次，雖然能夠揭示明確的趨勢與模式，但在統計顯著性與變異數估計上仍有擴充空間。

**Q14：根據本文分析，哪些情況最可能導致多智能體強化學習訓練出現嚴重的失效？**
A：最嚴重的失效情況之一是獨立策略訓練下，平行同角色智能體在共享提示上運作時引發的梯度放大效應，這會在 Voting 與 Orch-Workers 工作流程中驅動終端準確率斷崖，使得訓練後期的表現甚至遠低於基礎模型。另一個高風險情境是共享策略訓練中，由於非對稱每步梯度量的累積，導致共享策略被單一主導角色捕獲，使得其他角色喪失專門化能力，產生難以從 token 層級指標察覺的隱性退化。這些失效並非隨機發生，而是由工作流程拓撲與策略路由的結構性交互作用所決定，因此在設計複雜多智能體系統時，若忽略角色層級的梯度動態，就極易觸發這類不可逆的訓練崩潰。

**Q15：基於本文的發現，未來研究可以朝哪些方向進一步探索？**
A：未來研究可以朝開發「拓撲感知」的多智能體強化學習演算法邁進，例如在 GRPO 的群組相對優勢計算中引入角色層級的正規化或梯度裁剪機制，以主動緩解梯度放大與角色捕獲問題。另一個重要方向是建立即時的角色層級監控與診斷系統，能夠在訓練過程中偵測非對稱每步梯度量或角色貢獻失衡，並在終端準確率斷崖發生前觸發早期預警或自動介入。此外，將這套分析框架擴展到更長的回合軌跡、動態工作流程（如智能體可自主決定呼叫哪些角色的開放式系統），以及更多元的任務領域（如科學推理或多模態協作），將有助於驗證這些梯度動態機制的普遍性，並推動更穩健的多智能體 LLM 工作流程設計。

## 實務應用指南

### 適用場景

1. **程式碼自動審查與修復管線**：採用 Eval-Opt 工作流程，讓 Generator 產生修補草稿，Evaluator 執行單元測試並回傳錯誤訊息，再透過多輪修訂提升程式碼通過率。適用於需要高正確性的軟體工程團隊。
2. **多專家醫療或金融決策系統**：採用 Voting 工作流程，讓多個專科角色（如腫瘤科、放射科）或風險模型分別對個案投票，再由 Aggregator 整合共識。適用於可驗證診斷結果或歷史績效的場景。
3. **階層式客戶服務與工具調度**：採用 Orch-Workers 工作流程，由 Orchestrator 解析使用者意圖並分派給查詢知識庫、操作後台或生成回覆的 Worker，最後由 Synthesizer 統一輸出。適用於需要多工具協作的企業內部助理。
4. **科學計算與數學證明輔助**：利用多智能體分工驗證推論步驟，透過結果獎勵（如符號驗證器確認證明正確性）進行端到端 RL 訓練，提升大型數學模型的步驟正確率。
5. **高品質內容多輪校對**：類似 Eval-Opt 的變形，由寫手角色生成初稿，事實查核角色標註錯誤，修訂角色根據查核結果改寫，適用於需要嚴謹事實性的出版或法律文件生成。

### 實作前置條件

- **資料**：任務必須具備可驗證的結果訊號（如單元測試通過與否、數學答案正確與否、符號驗證結果）。每個角色需有對應的提示模板與少樣本軌跡，用於冷啟動基礎工作流程。
- **運算**：至少需支援 4B 參數模型高效微調（如 LoRA 或 QLoRA）的 GPU 叢集。多智能體 GRPO 每題需展開 n=8 條軌跡，VRAM 與節點間通訊頻寬會隨角色數量線性增長；獨立策略訓練的記憶體佔用為共享策略的數倍。
- **技術**：團隊需熟悉 GRPO 或策略梯度方法、能設計工作流程拓撲（DAG 或迴圈）、並具備建構結果獎勵函數（outcome verifier）的能力。建議先有單智能體 RLVR 的調校經驗，再進入多智能體聯合訓練。

### 實作步驟建議

1. **選擇工作流程拓撲**：依任務特性選型。需要迭代精進選 Eval-Opt；需要降低單點偏差選 Voting；需要異質分工選 Orch-Workers。
2. **建立基礎與單智能體對照組**：在投入多智能體訓練前，先評估基礎模型與單智能體 RL 基線，確認多智能體帶來的是「系統級增量」而非單一角色能力提升即可解決。
3. **決定策略路由策略**：若追求最高峰值準確率且能承擔監控成本，選擇 Isolated-Policy（每角色獨立參數）；若希望降低記憶體佔用並分散訓練風險，選擇 Shared-Policy（全角色共用一組參數）。
4. **實作結果獎勵 GRPO 迴路**：採用無明確 KL 懲罰的 GRPO，每題採樣 8 條工作流程軌跡，以群組相對優勢更新策略。確保獎勵僅來自最終可驗證結果（如測試通過），而非中間過程的啟發式分數。
5. **分階段擴展與監控**：先以 0.6B 規模驗證梯度動態與角色漂移，確認無終端準確率斷崖後，再擴展至 1.7B 與 4B。訓練過程中同時監控 token-level loss 與 episode-level 正確率，因共享策略的某些失效模式僅在後者浮現。
6. **部署與持續對齊**：上線後保留基礎模型作為參考，定期以新收集的可驗證結果進行微調，並設計早停機制與角色重新初始化策略，防止後期退化。

### 潛在風險與注意事項

1. **終端準確率斷崖（Isolated-Policy）**：獨立策略在後期常因平行同角色智能體的梯度放大（gradient amplification）而突然崩潰。建議實作角色級梯度裁剪、動態學習率，並在驗證集準確率連續下降三個檢查點時強制早停。
2. **主導角色捕獲（Shared-Policy）**：共享策略下，非對稱每步梯度量會使策略被 Workflow 中的主導角色（如 Orchestrator 或 Generator）綁架，導致其他角色退化。建議引入角色遮罩或梯度平衡機制，確保更新時各角色有相近的梯度貢獻。
3. **隱藏於 Token 層級的失效**：共享策略的失效特徵可能不顯現在 perplexity 或 policy loss，僅在端到端回合正確率下降。切勿僅以語言模型損失作為訓練收斂指標。
4. **規模與任務的非單調性**：多智能體 RL 的增益並非隨模型規模單調遞增，且數學與程式碼任務的最適 Workflow 與策略共享組合不同。避免盲目放大模型，應針對目標任務進行四維（Workflow × Scale × Task × Policy-sharing）消融實驗。
5. **記憶體與通訊瓶頸**：獨立策略的參數量隨角色數倍增，在 Voting 或 Orch-Workers 等多角色 Workflow 中尤其明顯。若資源有限，可對獨立策略使用 LoRA 適配器，或改用共享策略搭配角色提示區隔。

### 與其他技術的整合建議

1. **與 LLM 編排框架整合**：將 Eval-Opt、Voting、Orch-Workers 實作為 LangChain、LlamaIndex 或自研 DAG 中的可重用節點，利用框架的狀態管理追蹤多輪軌跡與中間產物。
2. **銜接單智能體 RLVR 管線**：先以單智能體 RLVR（如 DeepSeek-R1 或 DeepCoder 風格）提升基礎模型的單步推理能力，再接入多智能體 Workflow 進行系統級優化，避免基礎能力瓶頸被誤判為 Workflow 設計問題。
3. **結合檢索增強生成（RAG）與工具使用**：在 Orch-Workers 中，讓 Worker 角色具備呼叫外部 API、查詢向量資料庫或執行程式碼直譯器的能力，並以結果獎勵訓練 Orchestrator 學習何時觸發檢索。
4. **部署輕量級協議監控器**：參考角色漂移修復研究，在推論與訓練時部署規則型或小型分類器監控器，偵測主導角色、退化角色或重複輸出，並觸發重新初始化或人工介入。
5. **嵌入 MLOps 與 A/B 測試平台**：將多智能體展開、結果驗證、GRPO 更新封裝為標準化訓練任務，支援模型版本控制、漸進式上線（canary deployment）與線上 A/B 測試，以實際業務指標驗證 Multi-Agent RL 的增量價值。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從「為何要將單一任務拆成多個角色」這個直觀問題出發，先理解 Eval-Opt 的「生成→評估→修訂」迴路，暫時略過 GRPO 的數學推導，重點掌握本文核心結論：獨立策略天花板較高但後期容易崩潰，共享策略較為穩定卻可能發生角色失衡。
- **AI 工程師**：請聚焦第 3、5 節的實驗設定與梯度機制。特別注意 Isolated-Policy 的 gradient amplification 與 Shared-Policy 的 sp_role_capture，這兩個現象直接影響生產環境的訓練排程、監控指標與早停條件設計。建議將「每角色梯度量」與「回合正確率」同時納入訓練儀表板。
- **研究人員**：本文的核心貢獻在於以控制實驗拆解 Workflow、Scale、Task、Policy-Sharing 的四維交互效應。建議深入分析第 3–4 節的 empirical map，並將第 5 節的梯度動態解釋作為未來設計新多智能體 RL 演算法（如角色感知優勢分解或代理級正規化）的理論起點。
- **產品經理**：請優先閱讀「適用場景」與「潛在風險」。重點理解多智能體 RL 並非萬靈丹：它僅適合已有明確可驗證結果（如程式碼通過測試、數學答案正確）的任務，且需承擔訓練不穩定與後期退化的成本。在規劃產品路線時，應預留建立對照組、設計早停機制與監控儀表板的開發資源。
