## 摘要翻譯

近期將大型語言模型（Large Language Models, LLMs）與因果發現（Causal Discovery）結合的嘗試，要求模型推論配對方向（Pairwise Directions）、提出圖結構（Graph Structures），或將語言模型的輸出注入作為先驗（Priors）與約束（Constraints）。這些方法宣稱能帶來更快的分析，但它們也模糊了因果證據（Causal Evidence）究竟是由資料與假設所支持，還是由文本關聯（Textual Associations）、提示詞偽跡（Prompt Artifacts）與幻覺機制（Hallucinated Mechanisms）所支持。我們主張代理（Agents）在因果發現中應扮演不同的角色：代理應檢視資料、擷取上下文、解釋方法假設並釐清圖輸出，但不應提供邊（Edges）、方向（Orientations）、先驗、約束或因果結論（Causal Conclusions）。我們提出一項原則：代理協助工作流程（Workflow），而因果主張（Causal Claims）仍須植基於資料、明確的假設、形式化演算法、診斷（Diagnostics）以及使用者或領域專家（Domain Expert）的決策。我們在 causal-learn+ 中實例化此原則——這是一個線上平台，以 causal-learn 的演算法生態系統（Algorithmic Ecosystem）為核心，協調資料分析、預處理（Preprocessing）、方法推薦（Method Recommendation）、專家知識整合（Expert-knowledge Incorporation）、形式化發現與詮釋。針對大五人格資料（Big Five Personality Data）的案例研究（Case Study）展示了代理輔助的因果發現流程，且未將語言模型不可靠性（Language-model Unreliability）轉化為因果證據。該平台可於 causallearn.com 取得。

### 核心貢獻（3～5點）
- **釐清 LLM 介入因果發現的風險**：指出將語言模型輸出作為先驗、約束或直接生成邊/方向的做法，會模糊因果證據的真正來源，使文本關聯與幻覺機制可能被誤認為資料支持。
- **提出代理角色定位原則**：主張代理應專注於輔助工作流程（檢視資料、擷取上下文、解釋假設、釐清輸出），而非取代形式化演算法提供因果結論。
- **強調因果主張的可驗證基礎**：明確因果結論須植基於資料、明確假設、形式化演算法、診斷與領域專家決策，確保因果發現的嚴謹性與可重現性。
- **實例化 causal-learn+ 線上平台**：以 causal-learn 演算法生態系統為核心，整合資料分析、預處理、方法推薦、專家知識整合與詮釋等流程，提供完整的代理輔助因果發現環境。
- **以大五人格資料案例驗證可行性**：透過實際案例展示如何在不將語言模型不可靠性轉化為因果證據的前提下，有效運用代理輔助因果發現流程。

### 適合對象
- **因果發現與因果推論領域的研究者**：關注如何將 AI 技術整合至因果分析方法論的學者。
- **大型語言模型與 AI 應用開發者**：正在探索 LLM 在科學研究輔助中角色的工程師與研究者。
- **心理學、社會科學、生物醫學等領域的實務應用者**：需要從觀測資料中發掘因果結構、但同時重視方法嚴謹性的領域專家。
- **資料科學家與方法論顧問**：負責為研究團隊選擇與評估因果分析流程的專業人士。
- **AI 可靠性與可解釋性研究者**：關注語言模型不可靠性對科學結論影響的研究者。

## 深度分析

#### 方法論解析

本文的核心方法論並非提出新的因果發現演算法，而是建立一套**原則性框架（principled framework）**與配套的線上平台 **causal-learn+**，重新界定代理（agents）在因果發現流程中的角色定位。

**核心原則：「代理輔助，而非取代」**

作者提出一個關鍵區分原則：因果發現的證據來源必須可追溯至資料、明確假設、形式化演算法、診斷程序與使用者決策；而代理（基於大型語言模型）的功能僅限於工作流程的協調與輔助。具體而言，代理被嚴格禁止執行以下操作：
- 提供邊（edges）或方向（orientations）
- 注入先驗（priors）或約束（constraints）
- 直接產生因果結論

代理被允許執行的操作則包括：
- 檢視資料（data inspection）
- 擷取方法論與領域背景知識（retrieval of methodological and domain context）
- 解釋演算法假設（explaining method assumptions）
- 釐清圖輸出（clarifying graph outputs）
- 協調模組化工具（coordinating modular skills）

**causal-learn+ 平台架構**

平台圍繞開源函式庫 **causal-learn** 的演算法生態系統建構，將因果分析流程拆解為六個可追溯步驟：

1. **資料檢視（data inspection）**：代理協助理解資料特性，例如缺失值、分佈、變數類型。
2. **假設釐清（assumption elicitation）**：代理引導使用者明確陳述因果假設（如忠實性、因果充分性、線性等），而非由代理自行假設。
3. **方法推薦（method recommendation）**：根據資料特性與假設，從約束型方法（如 PC、FCI）、評分型方法（如 GES）、因果函數模型（如 LiNGAM）、潛在變數方法中推薦合適演算法。
4. **專家知識整合（expert-knowledge incorporation）**：由領域專家或使用者提供知識，代理僅作為介面，而非知識來源。
5. **形式化發現（formal discovery）**：執行選定演算法，產生因果圖（causal graph）。
6. **結果詮釋（interpretation）**：代理協助解讀圖結構，但不對因果關係下結論。

此架構的關鍵設計在於**證據鏈的可追溯性（traceability）**：每一條邊、每一個方向都能回溯到具體的演算法、假設與統計檢定，而非語言模型的文字模式匹配。

**方法論的理論基礎**

本文的方法論立場建立在因果發現領域的既有認識論基礎上：因果發現的結論強度取決於其假設強度。約束型方法（如 PC 演算法）僅依賴條件獨立（conditional independences）檢定，產生部分可識別的馬可夫等價類（Markov equivalence class）；評分型方法（如 GES 演算法）透過統計準則（statistical criterion）搜尋；因果函數模型則利用雜訊分佈（noise distributions）或函數形式（functional form）的不對稱性來定向邊。每一類方法都有其假設與適用範圍，沒有方法是無假設的（assumption-free）。代理若直接介入圖建構，將模糊這些假設的邊界，使結論的證據地位變得模糊。

#### 實驗數據解讀

本文以**大五人格資料（Big Five personality data）**作為案例研究，展示代理輔助管線的運作。雖然完整實驗細節需參考全文，但從摘要與方法論描述可推導以下解讀重點：

**案例設計意圖**

大五人格模型包含開放性、盡責性、外向性、宜人性、神經質五個維度，是心理學中廣泛研究的構念（construct）。選擇此資料集作為案例具有以下策略性意義：
- **領域知識豐富**：大五人格之間的相關性與潛在因果結構在心理學文獻中有大量討論，可作為基準對照。
- **變數數量適中**：五個變數適合展示因果發現流程的完整步驟，不會因維度過高而模糊重點。
- **適合展示代理邊界**：心理學領域充斥著基於語言的理論與通俗信念（如「外向性導致更高的幸福感」），正是展示「語言模型不可靠性不應轉化為因果證據」的理想場域。

**預期展示的流程要素**

案例研究預期展示以下代理輔助管線的關鍵環節：
1. 代理如何引導使用者理解資料特性（如變數的分佈、相關性結構）。
2. 代理如何協助使用者釐清假設（例如：是否假設因果充分性？是否允許潛在混淆？）。
3. 代理如何根據假設推薦方法（例如：在無潛在變數假設下推薦 PC 演算法；若允許潛在變數則推薦 FCI 演算法）。
4. 演算法執行後，代理如何協助詮釋輸出圖，但不對邊的存在或方向下因果結論。
5. 最終的因果主張由使用者在明確假設下基於演算法輸出做出。

**量化指標的侷限性**

值得注意的是，本文作為方法論立場論文，其「實驗」並非以傳統量化指標（如 F1 分數、邊預測準確率）評估，而是以**流程的完整性與證據鏈的可追溯性**作為評估標準。這是一種質性評估（qualitative evaluation），強調的是方法論紀律而非預測效能。

#### 與現有研究的比較

**現有 LLM 結合因果發現的方法分類**

本文明確區分了現有將大型語言模型引入因果發現的三類做法，並指出其共同缺陷：

| 做法類型 | 代表方法 | 問題 |
|---------|---------|------|
| 配對方向查詢 | 查詢 LLM 判斷變數間的因果方向 | 將文字模式匹配誤認為因果證據 |
| 完整圖結構生成 | 由 LLM 直接提出因果圖 | 圖結構可能反映預訓練語料中的常識而非資料證據 |
| 先驗/約束注入 | 將 LLM 輸出作為統計發現程序的先驗或約束 | 一旦注入，無法區分邊緣來自資料還是文字 |

**本文的定位差異**

與上述做法相比，本文採取**保守立場（conservative position）**，主張代理應輔助而非取代因果發現。這一立場的關鍵差異在於：

1. **證據來源的可分離性**：現有方法將 LLM 輸出與統計證據混合後，無法分離；本文透過角色劃分，確保因果證據僅來自資料與演算法。
2. **假設的明確性**：現有方法中，LLM 的「隱含假設」（如預訓練語料中的科學共識）難以被審查；本文要求所有假設由使用者明確陳述。
3. **幻覺機制（hallucinated mechanisms）的隔離**：LLM 可能產生看似合理但虛構的因果機制，本文透過禁止代理提供邊、方向或結論來隔離此風險。

**改進與侷限**

**改進之處**：
- 保留了因果發現的認識論紀律（epistemic discipline）。
- 提升了可用性（usability），讓非專業使用者也能完成因果分析流程。
- 透過 causal-learn+ 平台實現了流程的標準化與可追溯性。

**侷限之處**：
- 代理的輔助角色可能限制了自動化程度，對於希望快速獲得因果假設的使用者而言效率較低。
- 案例研究僅展示大五人格資料，未在多個領域、多種資料類型上進行系統性驗證。
- 平台依賴 causal-learn 的演算法生態，繼承了其所有假設限制。
- 對於「代理輔助」與「代理介入」之間的邊界，僅給出了原則性描述，缺乏形式化定義，在實務中可能出現灰色地帶（例如：代理推薦某方法是否構成「注入先驗」？）。

#### 可重現性評估

**程式碼與平台可用性**

本文的可重現性支援較為完善：
- **causal-learn+ 平台**：已上線，可透過 causallearn.com 存取。
- **底層函式庫 causal-learn**：為開源專案，演算法實作可審查與修改。
- **案例研究**：大五人格資料為公開資料集，可重現分析流程。

**可重現性的優勢**

- 平台採用模組化設計，每一步驟（資料檢視、假設釐清、方法推薦、演算法執行、結果詮釋）均可獨立檢視與重現。
- 因果發現演算法本身（如 PC、FCI、GES）已有成熟的開源實作，參數設定與輸出均可重現。
- 案例研究的資料與流程描述若完整公開，第三方可驗證代理輔助管線的每一步。

**可重現性的不足**

- 代理（LLM）的行為具有非確定性（non-determinism），即使在相同提示詞下，不同執行可能產生不同輸出，這對「可重現性」構成根本挑戰。
- 平台是否開源、代理的具體實作細節、提示詞模板（prompt templates）是否公開，從摘要與可見內容中無法確認。
- 案例研究的完整實驗設定（具體使用的演算法、參數、假設陳述）在提供的文本中未詳述，需查閱全文。
- 缺乏標準化的評估指標來衡量「代理輔助管線」的品質，例如：使用者決策品質、假設釐清的完整性、結果詮釋的準確性等。

**與領域標準的對比**

相較於許多僅提供程式碼片段或 API 呼叫範例的論文，本文提供了完整的線上平台，這在因果發現工具的可及性（accessibility）方面是顯著進步。然而，平台的長期維護、版本控制、與 causal-learn 函式庫的同步更新等工程問題，仍需持續關注。

#### 未來研究方向

**1. 代理邊界的形式化定義**

本文目前僅以原則性語言描述代理的輔助角色，未來可發展形式化框架，明確定義「輔助」與「介入」的邊界。例如：可定義代理輸出的「證據貢獻度」（evidential contribution），若代理輸出對最終因果結論的證據貢獻超過某閾值，則視為介入並需明確標記。

**2. 多領域系統性驗證**

目前案例研究僅限於大五人格資料，未來應在以下領域進行系統性驗證：
- **基因組學（genomics）**：高維度、潛在變數豐富的典型場域。
- **流行病學（epidemiology）**：觀測資料為主、介入實驗受限的場域。
- **神經科學（neuroscience）**：時間序列資料與潛在混淆並存的場域。
- **生態學（ecology）**：空間與時間依賴結構複雜的場域。

**3. 代理輔助品質的量化評估**

發展專門的評估指標，衡量代理在以下面向的表現：
- 假設釐清的完整性（是否引導使用者考慮所有關鍵假設）。
- 方法推薦的適切性（推薦方法是否與資料特性、假設匹配）。
- 結果詮釋的忠實性（是否避免過度詮釋或引入幻覺機制）。
- 使用者決策品質的提升程度（與無代理輔助的基線比較）。

**4. 與形式化驗證的整合**

將因果發現的證據鏈與形式化驗證工具（如定理證明器）整合，自動檢查每一步驟是否符合因果發現的認識論規範。例如：自動驗證「邊的方向是否僅由演算法在明確假設下產生」。

**5. 互動式假設敏感性分析**

擴展平台功能，使代理能引導使用者進行假設敏感性分析：若改變某項假設（如從「無潛在變數」改為「允許潛在變數」），因果圖如何變化？這將幫助使用者理解其結論對假設的依賴程度。

**6. 跨語言與跨文化適應**

當前平台主要服務英語使用者，未來應探索代理在多語言環境下的表現，特別是當領域知識以非英語形式存在時，如何避免語言偏誤（linguistic bias）影響假設釐清與方法推薦。

**7. 與介入實驗設計的整合**

因果發現的最終目的之一是指導介入實驗設計（interventional experiment design）。未來可探索代理如何協助將因果發現結果轉化為具體的實驗建議，同時保持「建議」與「因果結論」的明確區分。

**8. 開源生態與社群治理**

causal-learn+ 的長期發展需要社群參與。未來應建立透明的治理機制，包括：演算法新增的審查流程、代理行為準則、使用者回饋機制等，確保平台發展不會偏離「證據紀律」的核心原則。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於一個關鍵問題：當大型語言模型（LLMs）被引入因果發現流程時，如何避免將語言模型的輸出誤認為因果證據。傳統的因果發現旨在從觀測資料中學習因果關係，其結論的可信度仰賴於明確的假設、形式化演算法與統計診斷。然而，近期許多研究嘗試讓 LLM 直接推論配對方向、提出圖結構，或將語言模型的輸出作為先驗與約束注入搜尋程序，這使得最終的因果圖可能混雜了資料證據、預訓練語料中的常識、提示詞偽跡，甚至是幻覺機制。論文的立場是：代理（agents）應輔助因果發現的工作流程，而非取代它，因為因果主張必須紮根於資料、明確假設與形式化程序，而非語言模型的文本關聯。

**Q2：為什麼現有將 LLM 結合因果發現的方法會失敗？**
A：現有方法失敗的根本原因在於混淆了「語言模式預測」與「因果證據」的本質差異。LLM 是基於文本模式訓練的，當其輸出被直接注入圖建構程序時，所得到的邊或方向可能反映的是預訓練語料中的常見科學信念、提示詞措辭，或甚至是幻覺機制，而非資料中的統計證據。一旦這些來源在最終的因果圖中混合，圖的證據地位就變得模糊不清，使用者也難以分辨哪些結論是由資料與假設支撐、哪些僅是語言模型的推測。這在因果發現中尤其嚴重，因為因果結論的價值取決於我們能否清楚說明支撐它的假設、資料與演算法。

**Q3：為什麼這個問題在當前的研究與實務中特別重要？**
A：這個問題的重要性來自於因果發現在多個科學領域的關鍵地位：在基因組學、生態學、神經科學、流行病學等領域中，大規模觀測資料往往比介入實驗更容易取得，而因果發現能將資料轉化為可檢驗的因果假設。然而，因果發現高度依賴假設的選擇與詮釋，這對缺乏專業訓練的實務工作者而言是巨大的瓶頸。雖然現有軟體函式庫已讓許多演算法變得可及，但「可及性」並不等於「正確使用」，真正的瓶頸在於領域專業知識、資料分析與因果方法論之間的鴻溝。若 LLM 的不可靠性被誤導為因果證據，將嚴重損害因果分析的可靠性，因此建立一個能保留證據紀律的代理輔助框架至關重要。

**Q4：本文提出的核心方法論原則是什麼？**
A：本文提出的核心原則是「代理輔助工作流程，而因果主張仍須紮根於資料、明確假設、形式化演算法、診斷與使用者或領域專家的決策」。具體而言，代理的角色被嚴格限定在檢視資料、擷取脈絡、解釋方法假設、釐清圖輸出等輔助性任務上；它們不應提供邊、方向、先驗、約束或因果結論。這項原則的關鍵洞見在於：因果發現的價值在於其結論能被追溯到具體的證據來源，而 LLM 的輸出無法滿足這種可追溯性要求。透過這種職責劃分，系統既能利用 LLM 的語言理解與知識擷取能力來提升可用性，又能確保因果結論的證據純度。

**Q5：causal-learn+ 這個平台的關鍵創新是什麼？**
A：causal-learn+ 的關鍵創新在於它將代理定位為因果發現的「助手」而非「替代者」，並圍繞開源的 causal-learn 演算法生態系統建構出一個可追溯的線上代理系統。這個平台將分析流程組織為多個可追蹤的步驟，包括資料檢視、假設釐清、方法推薦、工具協調、演算法執行、圖檢視與結果詮釋，每一步驟都明確區分代理輔助與形式化因果推論的責任歸屬。這種設計的創新之處在於：它既利用了 LLM 在語言理解、方法論知識擷取、領域脈絡提供與模組化技能調度上的優勢，又透過嚴格的職責邊界防止語言模型不可靠性污染因果證據，從而在擴大因果發現可及性的同時保留了可靠分析所需的證據紀律。

**Q6：causal-learn+ 在系統設計上有哪些關鍵選擇？**
A：causal-learn+ 的設計選擇體現了「證據純度優先」的工程哲學。首先，平台採用模組化架構，將資料分析、預處理、方法推薦、專家知識整合、形式化發現與詮釋等環節解耦，使每個步驟的證據來源都清晰可辨。其次，代理被設計為「協調者」而非「決策者」——它們可以調用工具、擷取方法論文件、提供領域知識，但所有涉及邊、方向、先驗或約束的決定都必須由形式化演算法或使用者核准後執行。此外，平台強調診斷（diagnostics）的角色，確保演算法輸出能經過統計檢驗與假設驗證，而非直接接受 LLM 的敘事性解釋作為因果結論。

**Q10：causal-learn+ 在哪些實際場景中能發揮最大價值？**
A：causal-learn+ 在那些「擁有豐富觀測資料但缺乏因果方法論專業訓練」的場景中價值最大，例如基因組學中的基因調控網路推論、生態學中的物種交互作用分析、神經科學中的腦區連結研究，以及流行病學中的風險因子識別。在這些領域中，研究者往往具備深厚的領域知識與資料，但對於如何選擇約束型方法（如 PC、FCI）、評分型方法（如 GES）、因果函數模型或潛在變數因果發現方法感到困難。causal-learn+ 的代理可以幫助他們理解各方法的假設、診斷輸出，並在保留證據紀律的前提下引導他們完成分析，這對於加速科學發現同時維持可靠性具有重要意義。

**Q11：在產品化與部署上，causal-learn+ 有哪些重要的考量？**
A：在產品化層面，causal-learn+ 的設計考量首先體現在「使用者控制權」的保留：所有關鍵決策——包括變數選擇、假設設定、方法選擇、結果核准——都必須由使用者或領域專家確認，代理僅提供建議與解釋。其次，平台強調可追溯性，每一個因果結論都能被追溯到具體的演算法、假設與資料子集，這對於科學研究中的可重現性要求至關重要。此外，平台採用開源的 causal-learn 演算法生態系統作為後盾，這不僅降低了維護成本，也讓使用者能信任底層演算法的成熟度。從部署角度來看，causal-learn+ 作為線上平台（causallearn.com）的形式降低了使用門檻，使跨機構、跨領域的合作研究更容易進行。

**Q12：這項工作對因果發現與可靠 AI 領域的影響是什麼？**
A：這項工作對領域的影響是雙重的：在方法論層面，它為「LLM 與因果發現的結合」提供了一條不同於「直接讓 LLM 推論因果」的務實路線，強調證據紀律與職責劃分；在實務層面，它示範了如何讓因果發現從「專家專屬」走向「更廣泛可及」，同時不犧牲科學嚴謹性。更深遠地，這項工作呼應了「可靠 AI」（Reliable AI）的核心精神：AI 系統的價值不僅在於其能力，更在於其結論能否被信任、追溯與驗證。透過將代理定位為助手而非決策者，causal-learn+ 為未來 AI 輔助科學發現的設計提供了一個可參考的範式，特別是在那些結論必須經得起科學社群檢驗的領域。

**Q13：本文所承認的限制是什麼？**
A：本文坦承的一項核心限制是：因果發現本身並非「無假設」的，任何方法都依賴於特定的假設——無論是條件獨立性、函數形式、雜訊分佈，還是潛在變數的處理方式。causal-learn+ 雖然透過代理提升了可用性，但它無法消除這些底層假設的要求，使用者仍需具備足夠的領域知識來判斷哪些假設合理。此外，代理的輔助品質受限於其擷取的方法論知識與領域知識的完整性，若訓練資料或擷取來源存在偏差，代理的建議也可能繼承這些偏差。最後，平台雖然強調可追溯性，但因果結論的最終詮釋仍高度依賴使用者的判斷，這意味著「錯誤使用」的風險無法被系統完全消除。

**Q14：在哪些情況下，這個方法可能會失敗？**
A：這個方法可能在幾種情況下面臨挑戰。第一，當領域知識極度缺乏或高度爭議時，代理在「假設釐清」與「方法推薦」環節的建議可能不夠準確，因為擷取的知識庫本身就不完整或有偏誤。第二，當資料存在嚴重的隱藏變數或混淆因素時，即使形式化演算法（如 FCI 或潛在變數因果發現方法）能給出輸出，代理對結果的詮釋仍可能誤導使用者，特別是當代理傾向於提供「過於流暢」的敘事性解釋時。第三，若使用者過度信任代理的建議而跳過自己的判斷——例如未仔細審視假設是否合理——則即使系統設計嚴謹，最終結論仍可能出錯。這些失敗案例提醒我們：causal-learn+ 是工具而非保證，正確使用仍需要使用者的批判性思考。

**Q15：本文指出了哪些未來研究方向？**
A：本文開啟了幾個值得探索的未來方向。首先，如何進一步豐富代理在「假設釐清」與「診斷解釋」上的能力，使它能更精準地引導使用者識別資料中的潛在問題——例如缺失值機制、選擇偏差、測量誤差——是一個重要方向。其次，將因果發現與介入實驗設計更緊密結合，讓代理不僅能支援觀測資料分析，還能建議後續的驗證性實驗，這將大幅提升因果假設的可檢驗性。第三，擴展到更複雜的設定，如時間序列因果發現、跨資料集的因果遷移學習，以及結合因果發現與因果效應估計的整合流程。此外，如何在多代理協作環境中維持證據紀律——例如讓多個代理分別負責資料檢視、方法推薦、結果詮釋——也是一個值得探索的系統設計問題。這些方向共同指向一個願景：讓因果發現既可及又可靠，成為科學發現的標準工具。

## 實務應用指南

### 適用場景

以下列舉五個適合採用「代理輔助式因果發現」（agent-assisted causal discovery）架構的真實應用場景，每個場景都符合本文核心原則——由代理協調流程、由資料與演算法產出因果主張。

**1. 基因組學中的基因調控網路探索**
研究團隊擁有大量基因表現觀測資料，但無法對人類進行大規模基因介入實驗。可使用 causal-learn+ 載入表現量資料，由代理引導研究者說明哪些變數屬於已知調控路徑、哪些可能為隱藏變數，再由 PC、FCI 或 GES 等演算法輸出因果圖，代理僅負責解釋每條邊的可信度與假設限制，避免將語言模型對文獻的記憶誤認為因果證據。

**2. 流行病學中的風險因子分析**
公共衛生團隊需要從觀測性健康資料中區分哪些是風險因子、哪些只是相關變項。代理可協助處理缺失值、建議合適的條件獨立檢定、提醒研究者注意未測量混淆變數（如社經地位），但最終的因果方向必須由 FCI 等處理潛在混淆的演算法決定，而非由代理直接給出。

**3. 行為科學中的大五人格研究**
本文案例研究使用的場景。研究者收集人格量表資料，代理可協助說明各分量表的測量意涵、推薦適合處理連續變數的方法（如基於廣義獨立雜訊的函數因果模型）、引導研究者標記合理的時序假設，但人格特質間的因果方向仍須由資料與演算法決定。

**4. 商業決策中的行銷因果分析**
行銷團隊希望從 A/B 測試與觀測資料中判斷哪些活動真正帶來轉換。代理可協助整合多源資料、推薦適合處理選擇偏誤的方法、視覺化因果圖；但代理不應直接告訴團隊「社群媒體廣告導致購買」，這類結論必須來自於明確的假設與可重現的演算法輸出。

**5. 神經科學中的腦區互動分析**
神經科學家常面臨無法進行介入實驗的限制，且許多認知變數為潛在變數。代理可協助研究者理解 FCI 與基於秩約束的潛在變數方法的差異、提醒假設違反的後果，並在結果解釋階段幫忙對照文獻，但腦區間的因果連結仍須由資料驅動的演算法建立。

### 實作前置條件

**資料面**
- 觀測資料集：需有足夠樣本數（一般建議至少數百筆，視變數數量而定）以支持條件獨立檢定的統計檢力。
- 變數定義文件：包含變數名稱、測量方式、單位、預期的時序關係，這些是代理引導假設澄清時的必要輸入。
- 領域知識來源：可選的文獻庫或專家註記，用於代理檢索背景知識，但僅作為「假設候選」而非「因果證據」。
- 缺失值與異常值報告：代理在預處理階段需要這些資訊來推薦合適的處理策略。

**運算面**
- Python 環境（建議 3.9 以上），因為 causal-learn 函式庫以 Python 為主。
- causal-learn 套件安裝（`pip install causal-learn`），作為底層演算法生態系。
- causal-learn+ 線上平台帳號（causallearn.com），用於代理協調與流程追蹤。
- 若使用本地部署，需具備 LLM API 存取權（如 OpenAI、Anthropic 或開源模型）以及檢索增強生成（RAG）所需的向量資料庫。
- 基本的 Jupyter Notebook 或網頁介面操作能力。

**技能面**
- 因果推斷基礎：理解因果圖、d-分離、干預與反事實的區別。
- 統計檢定知識：熟悉條件獨立檢定（如 Fisher's z 檢定）及其假設。
- 演算法素養：了解 PC、FCI、GES 等方法的核心假設與適用情境。
- 領域專業知識：能判斷代理提出的假設候選是否合理。
- 提示工程基礎：能設計讓代理聚焦於「流程輔助」而非「因果推論」的系統提示。

### 實作步驟建議

以下步驟將本文的原則轉化為可執行的產品化流程，每一步都明確區分「代理職責」與「演算法/使用者職責」。

**步驟一：界定代理的角色邊界**
在系統提示中明確禁止代理直接輸出邊、方向、先驗或約束。代理的角色僅限於：解釋方法假設、檢索領域知識、協調工具呼叫、視覺化結果、提醒假設違反。建議建立「代理輸出審查清單」，任何包含「X 導致 Y」「X 是 Y 的原因」等措詞的代理輸出都應被攔截並改寫為假設候選。

**步驟二：建立可追溯的工作流程**
參考 causal-learn+ 的設計，將流程拆分為：資料檢查 → 預處理 → 假設釐清 → 方法推薦 → 演算法執行 → 圖形檢查 → 結果解釋。每個步驟都記錄：使用了哪些工具、引用了哪些文獻、由誰（代理或使用者）做出最終決定。這份日誌是因果主張可審查性的基礎。

**步驟三：設計代理的「假設釐清」對話**
代理應主動詢問使用者：變數間是否有已知的時序關係？是否有理由懷疑存在未測量混淆？資料生成過程是否符合某些可識別性假設（如函數因果模型中的非高斯性）？這些問題的答案會決定後續演算法的選擇，但代理不應自行假設。

**步驟四：整合 causal-learn 演算法生態系**
將 PC、FCI、GES、基於廣義獨立雜訊的方法、基於秩約束的潛在變數方法等包裝為可由代理呼叫的工具。代理根據使用者的假設回答推薦方法，但實際執行仍由演算法完成，且演算法的隨機性、參數設定都需記錄。

**步驟五：建立診斷與穩健性檢查**
演算法執行後，代理應引導使用者進行：殘差分析、假設違反測試（如非高斯性檢定）、子樣本穩健性檢查。若診斷失敗，代理應建議更換方法或放棄因果結論，而非強行解釋。

**步驟六：分離「解釋」與「證據」**
代理可以解釋圖中每條邊的統計強度、對應的條件獨立關係、違反了哪些假設時該邊會失效。但代理不應說「這條邊代表因果關係」，而應說「在假設 X、Y、Z 成立且資料支持條件獨立關係 P 的情況下，此邊被演算法保留」。

**步驟七：領域專家覆核機制**
在最終報告生成前，強制要求領域專家對代理整理的假設清單與演算法輸出進行覆核。專家的決定（如「加入這條邊作為背景知識約束」）需明確記錄，且與演算法自動發現的邊在視覺化中區分。

### 潛在風險與注意事項

**風險一：代理輸出被誤用為因果證據**
即使系統設計嚴謹，使用者仍可能將代理的「合理猜測」誤認為因果結論。緩解方式：在 UI 上明確標示代理輸出與演算法輸出的視覺區別（如不同顏色、不同圖示），並在匯出報告時自動加入免責聲明。

**風險二：提示詞偽跡污染假設釐清**
代理在詢問假設時，可能受提示詞措辭影響而傾向特定答案。緩解方式：對同一問題設計多個措辭版本，檢查代理的回應是否一致；對關鍵假設問題，採用結構化表單而非自由對話。

**風險三：幻覺機制被當作先驗注入**
若代理根據文獻「總結」出某條邊，使用者可能將其作為先驗加入演算法，導致文獻偏誤混入因果結論。緩解方式：禁止代理輸出直接作為先驗；任何來自文獻的「知識」必須經過使用者明確確認，且在圖中標示為「使用者加入的約束」而非「演算法發現」。

**風險四：演算法假設被過度簡化**
代理在向非專業使用者解釋時，可能為求易懂而省略關鍵假設。緩解方式：建立「假設完整性檢查清單」，代理每次解釋方法時必須涵蓋所有核心假設；提供「進階模式」讓使用者查看完整假設列表。

**風險五：因果結論的可重現性問題**
LLM 的非確定性可能導致同一資料、同一演算法產生不同的「解釋」文字，但因果圖本身應保持穩定。緩解方式：將因果圖的 JSON 表示作為唯一真相來源，代理的解釋文字僅作為輔助；對代理解釋設定溫度參數為 0 以提高穩定性。

**風險六：領域專家覆核的形式化**
若覆核僅停留在「看過」而非「明確同意」，則無法追溯責任。緩解方式：要求專家對每個關鍵決策點進行結構化簽核（如勾選「我確認假設 X 成立」），並記錄時間戳。

### 與其他技術的整合建議

**與 AutoML 平台的整合**
因果發現可作為 AutoML 流程的「解釋層」，在模型訓練完成後，由代理引導使用者對特徵間的因果關係進行探索。建議將 causal-learn+ 作為獨立的解釋模組，而非嵌入 AutoML 主流程，以維持因果結論的獨立性。

**與知識圖譜的整合**
領域知識圖譜可作為代理檢索的來源，但必須明確區分「知識圖譜中的關聯」與「因果發現的結論」。建議設計雙圖視覺化：左側為知識圖譜（可能包含未經驗證的關聯），右側為因果發現結果（附假設與證據強度）。

**與實驗管理平台的整合**
因果發現的假設常需要後續實驗驗證。建議將 causal-learn+ 與實驗管理系統（如 MLflow、Weights & Biases）對接，將每個因果假設記錄為可追蹤的實驗項目，並在後續實驗完成後回填驗證結果。

**與版本控制系統的整合**
因果圖、假設清單、演算法參數都應納入 Git 版本控制。建議將每次分析視為一個 commit，包含資料快照、程式碼、代理對話日誌、演算法輸出 JSON，這樣可完整重現任何一次因果分析。

**與 LLM 代理框架的整合**
若使用 LangChain、AutoGen 等代理框架，需特別注意：因果發現的核心演算法不應被包裝為代理可自由組合的「工具」，而應作為受控的標準流程。代理僅在「協調」與「解釋」層級運作，避免代理自行組合演算法而破壞可識別性假設。

**與統計軟體的整合**
對於習慣使用 R 或 Stata 的研究者，可透過 reticulate 或 API 將 causal-learn 的演算法包裝為熟悉的介面，但代理層仍建議統一在 Python 環境中，以維持對話狀態的一致性。

### 給不同背景讀者的閱讀建議

**給初學者**
若您剛接觸因果推斷，建議先閱讀本文的摘要與第 1 節，理解「代理不應直接給出因果結論」這個核心立場。接著閱讀第 2 節，了解為什麼語言模型的輸出不能等同於因果證據。實作上，可先到 causallearn.com 註冊帳號，嘗試本文的大五人格案例，親身體驗「代理引導流程、演算法產出結論」的分工模式，再回頭閱讀方法論細節。

**給 AI 工程師**
重點關注本文的系統設計原則：如何將 LLM 代理與形式化演算法解耦、如何設計可追溯的工作流程、如何防止代理輸出污染因果結論。建議將第 2 節的「代理不能提供因果證據」清單轉化為程式碼層級的約束（如輸出過濾器、角色權限控制），並參考 causal-learn+ 的模組化設計，將資料檢查、假設釐清、方法推薦、演算法執行、結果解釋拆分為獨立的微服務。

**給研究者**
本文對因果發現方法論的貢獻在於明確劃定了 LLM 在因果推論中的合理邊界。建議仔細閱讀第 1 節對 PC、FCI、GES、函數因果模型、潛在變數方法的回顧，並思考：您目前的研究中，哪些環節可能被 LLM 誤導？哪些環節可以安全地由 LLM 加速？案例研究部分提供了將抽象原則落實到具體資料的範例，值得仔細對照。

**給產品經理**
本文的核心訊息是：因果發現產品的價值不在於「讓 AI 直接告訴使用者答案」，而在於「讓 AI 幫助使用者走過複雜的因果推論流程」。產品設計上，應將代理定位為「流程導遊」而非「答案提供者」，並在 UI 上明確區分「AI 建議」與「資料支持的結論」。商業模式上，可考慮將因果發現的「可審查性」與「可重現性」作為差異化賣點，因為這正是本文強調的、傳統 LLM 直接給答案的方式所缺乏的。
