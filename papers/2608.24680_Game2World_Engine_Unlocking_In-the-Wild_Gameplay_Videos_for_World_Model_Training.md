## 摘要翻譯

電子遊戲為影片世界模型（Video World Models）提供了可擴展的訓練資料來源，具備多樣化的環境、複雜的互動，以及豐富的野外遊戲實況影片（In-the-Wild Gameplay Videos）。然而，原始遊戲實況影片將遊戲世界與螢幕空間介面（Screen-space Interfaces）交織在一起，引入了阻礙世界模型訓練（World Model Training）的遊戲特定偏差（Game-specific Biases）與無關動態（Irrelevant Dynamics）。為解決此問題，我們提出 GameUI 分類法（GameUI-Taxonomy）與 G2WEngine——一個將遊戲 UI 定位（Gameplay UI Grounding）與 UI 移除（UI Removal）形式化的全端框架。G2WEngine 能自動從真實野外遊戲實況影片（In-the-Wild Gameplay Videos）中擷取可重複使用的 UI 素材（UI Assets），並在乾淨的遊戲實況影片上合成時間一致的 UI 疊加層（UI Overlays）。利用此引擎，我們建構了 Game2World，包含 96K 組具備精確重建目標（Reconstruction Targets）的合成配對影片（Synthetic Paired Videos），以及來自 303 款遊戲的 1,079 段野外片段，以進行真實評估。其素材庫（Asset Library）包含 5,132 個經驗證的 UI 元素（UI Elements），涵蓋 21 個分類類別（Taxonomy Categories），並從 1,010 個具代表性的遊戲實況幀中收集而來。基於 Game2World，我們提出 GameCleaner，一個無遮罩（Mask-free）的遊戲 UI 移除模型，結合多模態語義理解（Multimodal Semantic Understanding）與影片編輯（Video Editing）能力。不同於基於遮罩的方法，GameCleaner 能直接識別並移除多樣的 HUD 元素（HUD Elements），同時保留底層的場景內容（Scene Content）與時間動態（Temporal Dynamics）。在一項受控的先導研究中，以無 UI 的遊戲實況資料訓練的世界模型（World Models），其整體 VideoReward 相較於以疊加 UI 資料訓練的模型提升了 6.83%。在 UI 移除（UI Removal）評估中，GameCleaner 於合成影片上達到平均 AAR 95.36，優於最強的時間遮罩基線（Temporal Mask Baseline）57.3%，並在野外資料中取得最佳的 AAR 80.05，同時達到 99.8% 的背景保留（Background Preservation）率。這些結果展現了將網路遊戲實況影片轉換為高品質世界模型訓練資料的可擴展潛力。程式碼、資料集與模型將於 https://github.com/Dongping-Chen/Game2World 公開。

### 核心貢獻（3～5點）
- 提出 GameUI 分類法（GameUI-Taxonomy）與全端框架 G2WEngine，將遊戲 UI 定位（Gameplay UI Grounding）與 UI 移除（UI Removal）形式化，並自動從真實野外遊戲實況影片中擷取可重複使用的 UI 素材（UI Assets）。
- 建構 Game2World 資料集，包含 96K 組具精確重建目標（Reconstruction Targets）的合成配對影片（Synthetic Paired Videos），以及來自 303 款遊戲的 1,079 段野外遊戲實況影片（In-the-Wild Gameplay Videos）；其素材庫（Asset Library）收錄 5,132 個經驗證的 UI 元素（UI Elements），涵蓋 21 個分類類別（Taxonomy Categories）。
- 提出無遮罩（Mask-free）遊戲 UI 移除模型 GameCleaner，結合多模態語義理解（Multimodal Semantic Understanding）與影片編輯（Video Editing），在合成與野外資料上均達到領先的 AAR 與背景保留（Background Preservation）表現。
- 驗證以無 UI 遊戲實況資料訓練的世界模型（World Models）可顯著提升 VideoReward（6.83%），展現將網路遊戲實況影片轉化為高品質世界模型訓練資料（World Model Training Data）的潛力。

### 適合對象
適合對影片世界模型（Video World Models）、遊戲內容理解、多模態語義理解（Multimodal Semantic Understanding）、影片編輯（Video Editing）及大規模資料集建構感興趣的研究者與工程師，特別是關注如何從野外遊戲實況影片（In-the-Wild Gameplay Videos）中提煉乾淨、可用於互動式模擬（Interactive Simulation）與可控影片生成（Controllable Video Generation）之訓練資料的讀者。

## 深度分析

#### 方法論解析

本研究將「野外遊戲實況影片（in-the-wild gameplay videos）」視為訓練影片世界模型（video world models）的潛在規模化資料來源，並提出一套從「介面與世界解耦（interface-world disentanglement）」出發的全端框架。整體方法可拆解為四個層次：問題形式化、分類法與資料引擎、資料集建構，以及移除模型。

**1. 問題形式化：介面與世界解耦**

作者指出，原始遊戲實況影片並非對遊戲世界的直接觀測，而是將底層場景與螢幕空間介面（screen-space interfaces）——如抬頭顯示器（HUD, Heads-Up Display）、選單（menus）、通知（notifications）、浮水印（watermarks）與串流疊加層（streaming overlays）——複合渲染後的結果。這些元素會引入遊戲特定偏差（game-specific biases）與無關動態（irrelevant dynamics），使世界模型學到與物理環境演化無關的捷徑。因此，本研究將 HUD 移除重新定義為「介面與世界解耦」：在時間軸上穩定地識別結構化疊加層、移除它們，並重建被遮擋的遊戲內容（occluded game content），同時保留無關的場景細節（scene details）與時間動態（temporal dynamics）。

**2. GameUI-Taxonomy 與 G2WEngine**

為了讓 UI 移除從單純的視覺修補提升為「具備遊戲語意理解的結構化任務」，作者提出 GameUI-Taxonomy，涵蓋 21 個 UI 分類類別（taxonomy categories）。該分類法不僅提供元素層級的語意標籤，也同時支撐 UI 定位（gameplay UI grounding）與 UI 移除（UI removal）兩項子任務。

在此基礎上，G2WEngine（Game2World Engine）作為全端處理框架，負責兩項核心功能：

- **真實 UI 素材萃取（UI assets extraction）**：從代表性遊戲畫面中自動擷取可重複使用的 UI 素材（UI assets），並經過驗證，最終形成包含 5,132 個已驗證 UI 元素（UI elements）的素材庫（asset library）。這些素材來自 1,010 張代表性遊戲幀，橫跨 21 個分類。
- **時間一致性的合成疊加（temporally coherent UI overlay synthesis）**：將萃取出的 UI 素材以符合各類別時空行為的方式，疊加在乾淨遊戲畫面上，產生成對的合成影片。這樣的「合成配對影片（synthetic paired videos）」提供了精確的重建目標（reconstruction targets），讓模型能夠在監督訊號下學習移除與重建。

相較於直接使用網路影片進行無監督學習，G2WEngine 透過「真實素材 + 可控合成」的設計，在資料規模與標註精度之間取得平衡。

**3. Game2World 資料集**

基於 G2WEngine，作者建構 Game2World 資料集，包含兩個互補子集：

| 子集 | 規模 | 用途 |
|---|---|---|
| Synthetic paired videos（合成配對影片） | 96K 對 | 提供精確乾淨參考，評估重建忠實度 |
| In-the-wild clips（野外實況片段） | 1,079 段，來自 303 款遊戲 | 評估對真實、未見遊戲與 UI 佈局的泛化能力 |

這種「控制組 + 真實組」的設計，使研究者能分離「重建品質」與「泛化能力」兩個維度。

**4. GameCleaner：無遮罩遊戲 UI 移除模型**

GameCleaner 是本研究提出的無遮罩（mask-free）遊戲 UI 移除模型。不同於傳統影片修補（video inpainting）方法需要輸入遮罩，GameCleaner 結合多模態語義理解（multimodal semantic understanding）與影片編輯（video editing）能力，直接識別多樣化的 HUD 元素（HUD elements），在移除它們的同時重建被遮擋區域，並維持背景保留（background preservation）與時間一致性（temporal coherence）。

從方法論角度來看，GameCleaner 的設計體現了三個關鍵選擇：

- **語意驅動而非純像素驅動**：利用 GameUI-Taxonomy 提供的類別語意，模型能區分「應移除的 UI 疊加層（UI overlays）」與「應保留的場景內容（scene content）」。
- **無遮罩輸入**：降低實際應用門檻，因為對每段野外影片手動產生時間遮罩（temporal mask）成本極高。
- **影片級編輯而非單幀修補**：強調時間動態（temporal dynamics）的保留，避免逐幀處理造成的閃爍或不連續。

#### 實驗數據解讀

本研究的實驗可分為兩大主軸：一是「UI 移除對世界模型訓練的影響」之先導研究，二是「GameCleaner 的 UI 移除效能」評估。

**1. 先導研究：乾淨遊戲影片作為世界模型訓練資料**

作者使用 5,442 段遊戲片段，分別製作乾淨版與 UI 疊加版，並在 Wan-2.1-T2V-1.3B 模型上進行微調，以 VideoReward 作為主要評估指標。結果顯示：

| 比較項目 | 乾淨資料 | UI 疊加資料 | 差異 |
|---|---|---|---|
| VideoReward Overall | 0.068 | -0.009 | **+6.83%** |
| Video Quality（影片品質, VQ） | -0.643 | -0.661 | +2.7% |
| Motion Quality（動作品質, MQ） | -0.298 | -0.367 | **+18.8%** |
| Text Alignment（TA） | 1.008 | 1.018 | -1.0% |

此外，在視覺品質與動作統計上，乾淨影片在美學品質（aesthetic quality, LAION）提升 8.59%，動作一致性（motion consistency, RAFT）提升 4.36%，但 MUSIQ 清晰度（clarity）反而下降 1.43%。

這組數據的解讀相當重要：UI 疊加層通常包含高對比文字、圖示與邊框，會讓清晰度指標（MUSIQ）產生虛高，但這些高頻細節對世界模型學習「環境動態」並無幫助，甚至造成干擾。真正衡量世界模型品質的動作品質（MQ）與整體 VideoReward 在乾淨資料上顯著提升，其中 MQ 提升 18.8% 尤其說明 UI 移除能讓模型學到更流暢、更符合物理的時間動態。

**2. GameCleaner 的 UI 移除效能**

在合成資料集上，GameCleaner 的平均 AAR（Average Asset Removal，平均資產移除分數）達到 95.36，相較最強的時間遮罩基線（temporal mask baseline）提升 57.3%，背景保留率達 99.8。這顯示模型在可控環境下幾乎能完整移除 UI，同時不傷害背景。

在更具挑戰性的野外資料集上，GameCleaner 的表現同樣突出：

| 評估場景 | GameCleaner | 主要對照方法 | 相對優勢 |
|---|---|---|---|
| Synthetic overall score | 0.5697 | LoomVideo（最強無遮罩基線） | +40.3% |
| Synthetic overall score | 0.5697 | EffectErase（遮罩輔助基線） | 僅低 0.0233 |
| In-the-wild overall score | 0.4886 | EffectErase | +23.7% |
| In-the-wild AAR w. ref | 80.05 | — | 最佳 |
| In-the-wild AAR w.o. ref | 51.60 | — | 最佳 |

這裡有幾個值得注意的現象：

- **遮罩輔助方法在合成資料上仍具優勢，但在野外資料上被反超**：EffectErase 在合成集上略勝 GameCleaner，但在野外集上落後 23.7%。這說明當測試分佈偏離訓練分佈、且無法取得精確遮罩時，GameCleaner 的無遮罩語意理解能力展現出更強的泛化性。
- **有無參考（w. ref / w.o. ref）的 AAR 差距大**：野外 AAR 從 80.05（有參考）降至 51.60（無參考），顯示在缺乏乾淨參考時，評估 UI 移除的難度顯著增加，也反映真實場景中「何謂正確背景」本身具有歧義性。

**3. 自動評估指標的可信度**

作者還訓練了一個 MLLM（Multimodal Large Language Model，多模態大型語言模型）評估器，在 removed F1 上達到 87.78%，與人工標註的 Cohen's κ 為 0.820。這表示自動化指標與人類判斷具有高度一致性，讓大規模野外評估成為可能。

#### 與現有研究的比較

**1. 與遊戲世界模型研究的區隔**

過去從遊戲實況學習世界模型的研究，如 DIAMOND、Genie，以及近期的動作條件生成模型（action-conditioned generative models），大多直接將渲染後的畫面視為世界觀測，未區分遊戲內容與 UI 疊加層。本研究首次系統性地將「介面與世界解耦」納入資料準備流程，並透過先導研究證明：即使使用相同的模型架構，僅移除 UI 就能顯著提升 VideoReward 與動作品質。

**2. 與影片修補（Video Inpainting）研究的區隔**

傳統影片修補方法（如 STTN、E2FGVI、ProPainter）與近期擴散模型（diffusion models）主要針對自然影片中的物理物件移除，通常需要遮罩輸入，且處理的是具有連續紋理、陰影與反射的物體。遊戲 UI 則具有以下特殊性：

- **螢幕空間固定性**：UI 元素以螢幕座標渲染，與場景透視無關；
- **類別特定行為**：不同 HUD 元素有固定或動態的時空模式（如血條、小地圖、對話框）；
- **半透明與高對比文字**：容易與背景混淆，也會干擾紋理重建。

GameCleaner 透過 GameUI-Taxonomy 引入語意層級的理解，彌補了傳統修補方法在「結構化螢幕疊加層」上的不足。

**3. 與基線方法的比較**

- **LoomVideo（最強無遮罩基線）**：在合成集上被 GameCleaner 大幅超越（+40.3%），顯示通用影片編輯模型缺乏針對遊戲 UI 的語意先驗。
- **EffectErase（遮罩輔助基線）**：雖在合成集上略勝，但在野外集上落後，說明遮罩品質在真實場景中難以保證，也凸顯無遮罩方法的實用價值。
- **時間遮罩基線（temporal mask baseline）**：在 AAR 上落後 57.3%，顯示單純依靠時間遮罩無法處理 UI 元素的類別多樣性與動態行為。

**4. 限制與待釐清之處**

儘管成果顯著，本研究仍存在若干限制：

- **遊戲覆蓋範圍**：1,079 段野外片段來自 303 款遊戲，雖具多樣性，但相輔於全球數萬款遊戲，仍可能遺漏特定類型 UI（如 VR/AR 介面、觸控介面）。
- **合成與真實的差距**：G2WEngine 合成的 UI 疊加層雖基於真實素材，但未必能完全重現串流疊加層、動態廣告、浮水印壓縮失真等真實雜訊。
- **評估指標的侷限**：AAR 與背景保留率雖經 MLLM 與人工標註驗證，但對於「語意正確的重建」仍可能與人類感知存在落差，特別是在被 UI 長期遮擋的區域。
- **未納入動作條件**：先導研究使用 text-to-video（T2V）模型作為代理，尚未驗證在動作條件世界模型（action-conditioned world models）上的效益。
- **版權與倫理議題**：移除浮水印與串流疊加層可能涉及內容來源標示與版權問題，論文未深入討論。

#### 可重現性評估

本研究在可重現性方面採取相對開放的策略：作者於摘要與內文多次提到程式碼（code）、資料集（dataset）與模型權重（model weights）將釋出於 `https://github.com/Dongping-Chen/Game2World`。若該承諾完整兌現，將包含以下關鍵資源：

- Game2World 資料集：96K 合成配對影片、1,079 段野外實況片段、5,132 個已驗證 UI 素材；
- GameUI-Taxonomy：21 個類別的定義與標註；
- G2WEngine：UI 素材萃取與合成疊加的處理流程；
- GameCleaner 模型與推論程式；
- 評估指標與 MLLM 評估器實作。

這些資源若能完整釋出，將大幅提升後續研究的可重現性，並讓社群能直接驗證先導研究中的 VideoReward 提升、進行跨模型比較，以及擴充分類法。

然而，可重現性也面臨幾項實務挑戰：

- **運算資源需求**：G2WEngine 的素材萃取、合成影片生成，以及 GameCleaner 的訓練與推論，可能都需要大量 GPU 運算與儲存空間，論文未詳細說明硬體配置與訓練成本。
- **資料授權問題**：遊戲畫面、UI 素材與實況影片涉及遊戲發行商與實況主的版權。即使研究用途可主張合理使用，大規模公開釋出仍可能需要去識別化或僅釋出特徵/標註。
- **再現細節**：目前提供的上下文未包含完整的超參數、訓練步數、擴散模型架構細節等，未來需參照正式釋出的技術文件與程式碼進行確認。

#### 未來研究方向

基於本研究的成果與限制，以下幾個方向值得後續探索：

**1. 動作條件世界模型的端到端驗證**

本研究的先導研究使用 text-to-video 模型作為代理。未來應直接將 UI 移除整合進 action-conditioned world models（如基於 Wan、DIAMOND 或 Genie 的互動式模擬器），驗證 UI-free 資料對長期互動資料（long-horizon interaction data）與策略學習的影響。

**2. 擴充分類法至多樣化介面**

GameUI-Taxonomy 目前涵蓋 21 類常見 HUD 元素。未來可擴展至 VR/AR 抬頭顯示器、觸控 UI、動態廣告疊加層、實況互動元件（如聊天室、斗內通知），以及跨語言、跨文化風格的介面。

**3. 更強的時間一致性與長影片處理**

現有方法主要處理短片段。未來可發展針對長影片的記憶機制或分層時間建模，以處理持續存在的小地圖、任務追蹤列等長期 UI 元素，並減少長序列中的累積誤差。

**4. 從 UI 移除到 UI 語意的再利用**

UI 元素本身蘊含豐富的遊戲狀態與玩家行為資訊（如血量、彈藥、任務目標）。未來可研究「移除 UI 以訓練世界模型」與「解析 UI 以學習獎勵函數或動作空間」的聯合框架，讓介面資訊成為輔助訊號而非單純雜訊。

**5. 即時與串流應用**

將 GameCleaner 最佳化為即時處理管線，可應用於實況串流（streaming）的 UI 去背、遊戲內容重製、可及性輔助，以及版權敏感內容的過濾。這需要兼顧推論速度與品質。

**6. 結合物件移除與效果修復**

遊戲畫面中除了 UI，還可能存在玩家名稱標籤、陰影、反射等與場景互動的元素。未來可將 gameplay UI removal 與通用 video inpainting、陰影移除、反射補全等技術結合，形成更完整的「畫面淨化」框架。

**7. 倫理與法律框架**

隨著 UI 移除技術成熟，如何處理浮水印、實況主個人識別疊加層，以及避免被用於規避版權標示，將成為重要的研究與政策議題。未來可建立標準化的資料使用協議與倫理評估流程。

## 論文問答

**Q1：Game2World Engine 想要解決什麼核心問題？為什麼不能直接拿原始遊戲實況影片來訓練世界模型？**

A：原始遊戲實況影片並非單純的遊戲世界觀測，而是將底層場景與抬頭顯示器（HUD）、選單、通知、浮水印、串流疊加層等螢幕空間介面混合在一起的合成畫面。這些介面元素會引入與物理環境演化無關的遊戲特定偏差與無關動態，使世界模型學到錯誤的視覺捷徑與多餘監督訊號。Game2World Engine 的核心目標即是把「介面」與「世界」解耦，將野外遊戲影片轉換成適合世界模型訓練的乾淨資料。

**Q2：現有的影片修補或物件移除方法為什麼不適合直接拿來移除遊戲 UI？**

A：傳統影片修補主要針對自然影片中的實體物件，例如行人或車輛，這些物件通常遵循物理運動與場景幾何；然而遊戲 UI 是結構化的螢幕空間疊加層，具有類別特定的空間佈局與時間行為，例如固定角落的血條、彈出的通知或持續存在的迷你地圖。這些特性使得通用物件移除模型難以準確定位 UI、理解其語義，並在移除後保持被遮擋場景的時間一致性。因此需要結合遊戲語義理解與專門的時間連貫重建機制，而非單純的像素填補。

**Q3：移除 UI 對世界模型訓練為何重要？論文提供了什麼實證？**

A：UI 疊加層會提供與遊戲世界動態無關的視覺線索，使模型傾向學習介面外觀而非場景演化，進而降低生成品質與動作一致性。論文的控制實驗顯示，在相同的 5,442 段遊戲影片上，使用無 UI 版本訓練的模型整體 VideoReward 提升了 6.83%，其中動作品質提升 18.8%、影片品質提升 2.7%，美學品質提升 8.59%、動作一致性提升 4.36%。這些結果清楚說明，移除 UI 不僅是視覺編輯操作，更能顯著提升遊戲影片作為世界模型訓練資料的價值。

**Q4：G2WEngine 的核心流程包含哪些步驟？它如何產生可重複使用的訓練資料？**

A：G2WEngine 首先透過 GameUI-Taxonomy 對遊戲介面元素進行語義分類與定位，然後從真實遊戲影片中自動提取可重複使用的 UI 素材，建立經過驗證的素材庫。接著引擎將這些 UI 素材以時間連貫的方式疊加到乾淨的遊戲畫面上，合成帶有精確重建目標的成對影片。透過這種「先提取、再合成」的全端流程，研究團隊能大規模產生具有乾淨參考的合成資料，同時保留真實 UI 的視覺與時間特性。

**Q5：GameCleaner 與傳統需要遮罩的移除方法相比，主要創新在哪裡？**

A：GameCleaner 是一個無遮罩的遊戲 UI 移除模型，它結合多模態語義理解與影片編輯能力，能直接辨識並移除多樣化的 HUD 元素，而無需使用者提供明確的遮罩輸入。相較於遮罩式方法，它更適合處理野外遊戲影片中大量、類別各異且佈局陌生的介面元素。此外，GameCleaner 在移除 UI 的同時會重建被遮擋的遊戲內容，並保留無關的場景細節與時間動態，使其能泛化到未見過的遊戲與 UI 佈局。

**Q6：GameUI-Taxonomy 在整個框架中扮演什麼角色？為什麼需要建立統一分類法？**

A：GameUI-Taxonomy 將遊戲介面元素系統化地劃分為 21 個類別，涵蓋 HUD、選單、通知、浮水印、串流疊加層等常見介面類型，為 UI 定位與移除任務提供統一的語義基礎。這個分類法不僅幫助 G2WEngine 有條理地提取與組織 5,132 個經驗證的 UI 素材，也讓 GameCleaner 能根據類別特性進行更精準的語義理解與移除決策。同時，它還支撐了元素級的移除、偽影與背景保留評估指標，使整個研究具備可重複且細緻的評量標準。

**Q7：Game2World 資料集由哪些部分組成？各自用來評估什麼能力？**

A：Game2World 包含 96,000 組合成配對影片，每組都有帶 UI 疊加的輸入與乾淨的參考畫面，用於評估模型在受控條件下的精確重建能力。此外，資料集還包含來自 303 款遊戲的 1,079 段野外真實遊戲影片，用於測試模型在真實、未經控制的 UI 分佈上的泛化表現。其素材庫則從 1,010 張代表性遊戲畫面中收集並驗證了 5,132 個 UI 元素，橫跨 21 個分類類別，為後續研究提供可擴展的資產基礎。

**Q8：GameCleaner 在實驗中取得了哪些關鍵量化結果？**

A：在合成資料集上，GameCleaner 的平均 AAR 達到 95.36，比最強的時間遮罩基線高出 57.3%；其整體評分為 0.5697，比最強的無遮罩基線 LoomVideo 提升 40.3%，且僅比需要遮罩輔助的 EffectErase 低 0.0233。在更具挑戰性的野外資料集上，GameCleaner 取得最佳整體評分 0.4886，超越 EffectErase 23.7%，並達到 80.05 的 AAR（有參考）與 51.60 的 AAR（無參考），背景保留率高達 99.8。這些結果顯示它在 UI 移除與場景保留之間取得了優異平衡。

**Q9：論文如何評估 UI 移除的品質？自動評估與人工評估的一致性如何？**

A：研究團隊設計了元素級的移除率、偽影程度與背景保留度等指標，並從多個維度衡量模型是否完整移除 UI、是否破壞原始場景、以及輸出是否時間連貫。他們還訓練了一個多模態大型語言模型（MLLM）評估器，該評估器在「是否移除」任務上達到 87.78% 的 F1 分數，與人工標註的 Cohen’s κ 為 0.820。這表示自動評估具有很高的人類一致性，能可靠地支援大規模資料集與模型的評比。

**Q10：Game2World Engine 可應用在哪些實際場景？**

A：最直接的應用是將網路上大量的野外遊戲實況影片轉換為乾淨、長期互動資料，用於訓練互動式模擬、可控影片生成與具身智能體的世界模型。它也能協助遊戲內容創作者自動移除 HUD 與串流疊加層，產生更適合剪輯、宣傳或二次創作的乾淨畫面。此外，該引擎可支援資料集策展、遊戲 AI 研究、以及為實況主提供即時或後製的 UI 清理工具。

**Q11：若要將此技術產品化，需要考慮哪些實務議題？**

A：首先必須確保模型能穩定處理未見過的遊戲、解析度、畫面比例與各種串流疊加層，避免在真實部署中出現閃爍或殘影等時間不一致問題。其次，移除 UI 後的場景重建必須保留遊戲原本的藝術風格與細節，否則會降低後續應用的視覺品質。此外，從網路影片提取 UI 素材與移除串流疊加層時，也必須注意版權、隱私與平台條款等法律與倫理問題，並考量大規模影片處理的運算成本。

**Q12：這項研究對世界模型與遊戲 AI 領域可能帶來什麼影響？**

A：它證明了野外遊戲影片經過適當的 UI 清理後，可以成為高品質且可擴展的世界模型訓練資料，減少對昂貴封閉式模擬器或儀器化環境的依賴。透過釋放網路上數量龐大、風格與任務多樣的遊戲影片，研究人員能訓練出更具泛化能力、動作品質更高的生成式世界模型。長遠來看，這有助於加速通用互動模擬、開放世界遊戲 AI 與具身智能體的發展，讓模型從真實人類遊玩行為中學習複雜環境動態。

**Q13：論文有哪些已經承認或可以推論出的限制？**

A：目前的先導研究使用文字轉影片模型作為代理任務，而非直接訓練動作條件化的世界模型，因此未來仍需驗證在互動式模擬上的最終效益。合成 UI 疊加層雖然提供了精確的重建目標，但可能無法完全複製真實影片中 UI 動畫、透明度、動態通知等複雜行為。此外，野外評估雖涵蓋 303 款遊戲，但相較於整個網路遊戲生態仍屬有限，某些罕見或風格極端的介面類別可能仍是挑戰。

**Q14：GameCleaner 可能會在哪些情況下失敗？**

A：當 UI 與遊戲場景視覺上高度融合時，例如世界內的「遊戲內介面」（diegetic UI），模型可能無法正確區分介面與場景，導致漏移除或過度移除。對於尺寸極小、出現時間短暫或快速移動的通知與彈窗，模型可能留下殘影或偽影。若 HUD 背後的場景紋理複雜且被長時間遮擋，重建結果也可能出現模糊或不合理的內容；極端寬高比、重度串流疊加層或低解析度影片也會對泛化能力構成考驗。

**Q15：基於這項工作，未來可以朝哪些方向延伸？**

A：未來可以將清理後的遊戲影片直接用於訓練動作條件化的世界模型，並結合音訊、玩家輸入與遊戲狀態資訊，建立更完整的互動模擬環境。另一個方向是擴充資料集規模，納入更多遊戲類型、語言與文化風格的 UI，並提升對動態、半透明與遊戲內介面的處理能力。此外，也可發展即時 UI 移除系統以支援直播後製，或引入人機協作的迭代編輯介面，讓創作者能微調移除結果並確保版權合規的素材再利用。

## 實務應用指南

### 適用場景

1. **遊戲世界模型訓練資料清洗**  
   將 YouTube、Twitch 或內部錄製的野外遊戲實況影片，自動去除 HUD、選單、通知、浮水印與串流疊加層，轉換為乾淨的 world-model training data，提升 VideoReward 與動作品質。

   為 DIAMOND、Genie、Wan-2.1-T2V 等影片世界模型或互動式模擬器提供 UI-free 觀測，降低遊戲特定偏差，讓模型學到更真實的環境動態。

3. **遊戲內容自動剪輯與重製**  
   去除 HUD 後進行遊戲預告片剪輯、AI 生成 cinematics、風格轉換或解析度提升，避免介面元素干擾視覺敘事。

4. **遊戲 UI 分析與可及性研究**  
   利用 GameUI-Taxonomy 自動定位與分類介面元素，支援 UI 設計評估、視障輔助介面開發，以及遊戲可用性研究。

5. **具身智能體與機器人模擬資料產生**  
   從第三人稱或第一人稱遊戲影片中學習物理與互動動態，移除螢幕空間介面後作為具身智能體的訓練資料來源。

### 實作前置條件

- **資料**
  - 原始野外遊戲實況影片（建議涵蓋多種遊戲類型、視角與解析度）。
  - 乾淨參考畫面或可自行合成的乾淨遊戲畫面。
  - Game2World 資料集（96K 合成配對影片、1,079 野外片段、5,132 驗證 UI 素材）或自建同等規模資料。
  - 依 GameUI-Taxonomy 21 個分類類別標註的 UI 元素。

- **運算資源**
  - 訓練/微調：建議使用 A100 / H100 等級 GPU，影片擴散模型與多幀推論需要大量 VRAM。
  - 推論：中高階 GPU 可執行 GameCleaner，但高解析度長影片仍需批次處理與記憶體管理。
  - 儲存：合成配對影片與素材庫會快速膨脹，需準備數 TB 級儲存空間。

- **技術能力**
  - Python、PyTorch 與影片處理工具（OpenCV、ffmpeg）。
  - 熟悉 diffusion-based video inpainting / editing。
  - 多模態大語言模型（MLLM）評估與資料標註經驗。
  - 資料管線工程能力（ETL、版本控制、品質監控）。

### 實作步驟建議

1. **定義 UI 範疇與分類**  
   採用 GameUI-Taxonomy，針對目標遊戲列出常見 HUD 元素（血條、小地圖、彈藥、對話框、浮水印、串流聊天室等）。

2. **收集與預處理影片**  
   統一解析度、幀率與片段長度，切分為固定長度 clip，並記錄來源與授權資訊。

3. **UI 定位與素材擷取**  
   使用 G2WEngine 從真實影片中自動提取可重複使用的 UI assets，建立素材庫，並進行人工驗證與分類。

4. **合成配對訓練資料**  
   將驗證過的 UI assets 以時間一致的方式疊加在乾淨畫面上，產生 synthetic paired videos 與精確的 reconstruction targets。

5. **訓練或微調 GameCleaner**  
   在 Game2World 上訓練無遮罩 UI 移除模型，或載入預訓練權重後針對特定遊戲類型進行領域適應。

6. **推論與品質驗證**  
   對野外影片執行 GameCleaner，使用 AAR、背景保留率、VideoReward、MLLM evaluator 與人類評估進行多維度驗證。

7. **下游世界模型訓練**  
   將 UI-free 影片餵入影片生成模型或世界模型，監控 motion quality、video quality 與 temporal consistency。

8. **持續迭代**  
   根據錯誤案例擴充 GameUI-Taxonomy 與素材庫，重新生成合成資料並更新模型。

### 潛在風險與注意事項

- **過度移除（Over-removal）**  
  當 UI 與場景紋理或顏色相近時，模型可能誤判並移除遊戲世界內容。建議結合多模態語義理解與時間一致性約束，並用背景保留指標監控。

- **重建幻覺（Hallucination）**  
  被 UI 遮擋的區域可能生成不存在的場景細節。需搭配乾淨參考畫面或人類評估，特別是在 in-the-wild 無參考情境下。

- **時間閃爍與不一致**  
  逐幀獨立處理容易產生閃爍。GameCleaner 需考慮多幀資訊，推論後也應進行時間一致性後處理。

- **未見遊戲泛化不足**  
  新遊戲的視覺風格或 UI 佈局可能與訓練分佈不同。建議持續擴充素材庫，並對新遊戲進行少量領域適應。

- **版權與隱私**  
  野外影片與串流疊加層可能包含創作者資訊、商標或個人資料。使用前需確認授權，並進行去識別化處理。

- **指標陷阱**  
  AAR 高並不一定代表視覺品質好。建議同時採用 VideoReward、MLLM evaluator 與人類評估，避免單一指標誤導。

### 與其他技術的整合建議

- **影片生成模型**  
  將 GameCleaner 作為 Wan-2.1-T2V、CogVideo 或其他 T2V 模型訓練前的資料前處理管線，提升生成影片的動作一致性與美學品質。

- **世界模型與神經遊戲引擎**  
  與 DIAMOND、Genie、OS-Genesis 等系統串接，提供 clean observation，減少 HUD 引入的無關動態。

- **多模態大語言模型（MLLM）**  
  利用 MLLM 進行自動 UI 分類、移除品質評估與錯誤案例分析，降低人工標註成本。

- **遮罩式基線方法**  
  對於困難案例，可將 SAM、EffectErase 等遮罩基線與 GameCleaner 結合，產生輔助遮罩或作為 fallback 方案。

- **資料管理平台**  
  使用 DVC、LakeFS 或自研資料平台管理素材庫、合成資料版本與模型檢查點，確保實驗可重現。

- **強化學習與具身智能體框架**  
  將 UI-free 遊戲影片轉換為 action-conditioned trajectories，餵入 RL 或具身智能體訓練流程。

### 給不同背景讀者的閱讀建議

- **初學者**  
  先理解「為什麼 HUD 會干擾世界模型學習」這個核心問題，再跟著 G2WEngine 的開源程式碼與 Game2World 資料集執行推論範例，逐步熟悉影片修補、UI 定位與 AAR / VideoReward 等評估指標。

- **AI 工程師**  
  重點閱讀 GameCleaner 的無遮罩訓練流程、G2WEngine 的合成資料產生管線，以及模型推論的記憶體與延遲考量。評估如何將預訓練模型整合到現有的 T2V 或世界模型資料前處理鏈中。

- **研究人員**  
  關注 GameUI-Taxonomy 的設計原則、interface-world disentanglement 的問題形式化、AAR / 背景保留 / MLLM evaluator 的指標設計，以及 pilot study 中「移除 UI 提升世界模型訓練效果」的因果證據。

- **產品經理**  
  聚焦適用場景與商業價值：降低世界模型訓練資料成本、提升生成影片品質、開拓遊戲內容自動化與可及性功能。同時需特別注意資料授權、版權與隱私風險。
