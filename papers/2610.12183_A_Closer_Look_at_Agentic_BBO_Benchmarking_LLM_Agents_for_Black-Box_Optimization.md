## 摘要翻譯

黑盒優化（Black-box optimization, BBO）出現於許多科學與工程問題中，其中目標評估（objective evaluations）成本高昂且次數有限。近期的大型語言模型（large language model, LLM）代理透過結合任務語義（task semantics）、計算、優化工具（optimization tools）以及反饋驅動（feedback-driven）的決策制定，為黑盒優化提供了一種新途徑，並因整合數學嚴謹的工具而展現極大潛力。然而，現有的代理式黑盒優化（agentic BBO）研究採用了不同的任務領域與系統配置，導致其結果難以比較，且個別設計選擇的效應難以隔離。因此，我們提出了 AgenticBBO-Bench，一個跨領域的代理式黑盒優化基準，涵蓋合成函數（synthetic functions）、超參數優化（hyperparameter optimization）、資料庫調校（database tuning）、晶片設計（chip design）與分子設計（molecular design），並採用統一的有限預算評估協定（finite-budget evaluation protocol）。在我們的實驗中，代理式黑盒優化在所有五個領域中均達到比直接基於 LLM 的方法更高的家族平均分數（family-averaged scores），並在其中四個領域中優於最佳的數值優化器（numerical optimizers）。我們進一步研究了影響代理性能的三個因素：優化工具、任務資訊與先驗知識（prior knowledge），以及 LLM 在搜尋過程中的角色。我們的結果顯示，額外的數值工具並未持續提升性能，任務語義普遍有用，但更具體的先驗知識則較不可靠，而數值優化器能有效從代理所建立的搜尋軌跡（search trajectories）中吸收增益。最後，我們在 AgenticBBO-Bench 中引入了一個五任務的前沿挑戰（frontier challenge），並在 Codex 代理框架（Codex agent harness）下評估了七個 LLM，其中 GPT-6 Astra 與 DeepSeek-V4.1-Flash 在所評估模型中落在性能與成本的帕累托前緣（Pareto frontier）上。我們的程式碼可於 https://github.com/lamda-bbo/agentic-bbo 取得。

### 核心貢獻（4點）
- **提出跨領域基準 AgenticBBO-Bench**：涵蓋合成函數、超參數優化、資料庫調校、晶片設計與分子設計五大領域，並採用統一的有限預算評估協定，使不同代理式黑盒優化方法得以公平比較。
- **驗證代理式黑盒優化的有效性**：實驗結果顯示，代理式黑盒優化在所有五個領域中均優於直接基於 LLM 的方法，並在其中四個領域中勝過最佳數值優化器。
- **剖析影響代理性能的三大因素**：系統性地分析優化工具、任務資訊與先驗知識、以及 LLM 在搜尋中的角色，揭示額外數值工具未必持續提升性能、任務語義普遍有用但具體先驗較不可靠、且數值優化器能有效吸收代理所建立的搜尋軌跡增益。
- **建立前沿挑戰與模型評估**：在 AgenticBBO-Bench 中引入五任務前沿挑戰，並於 Codex 代理框架下評估七個 LLM，發現 GPT-6 Astra 與 DeepSeek-V4.1-Flash 位於性能與成本的帕累托前緣，為成本性能權衡提供實證參考。

### 適合對象
從事黑盒優化、大型語言模型代理、自動化機器學習（AutoML）、貝氏優化與演化演算法研究，以及在超參數優化、資料庫調校、晶片設計與分子設計等科學與工程領域中應用計算優化方法的學者、研究人員與工程師。此外，對 LLM 代理的評估方法論、基準設計與成本效益分析感興趣的讀者亦將從中獲益。

## 深度分析

#### 方法論解析

本論文提出了一個系統性的基準測試框架 AgenticBBO-Bench，用於評估大型語言模型（Large Language Model, LLM）代理在黑盒優化（Black-Box Optimization, BBO）任務中的表現。其方法論的核心在於將「代理式黑盒優化」（Agentic BBO）從過往零散的研究中抽離出來，建立可比較、可重現的統一評估環境。

**1. 代理式黑盒優化（Agentic BBO）的形式化定義**

傳統的黑盒優化問題定義為尋找 $x^\star \in \arg\max_{x \in \mathcal{X}} f(x)$，其中 $f(x)$ 的解析形式與梯度皆不可取得。有限預算的序列式優化（finite-budget sequential optimization）則遵循以下迴圈：

$$H_{t-1} \rightarrow x_t \rightarrow y_t = f(x_t) \rightarrow H_t$$

其中 $H_{t-1} = \{(x_i, y_i)\}_{i=1}^{t-1}$ 為歷史觀察值。本論文的核心創新在於將 LLM 從「固定運算子」（fixed operator）提升為「代理」（agent）：在每一輪中，LLM 不僅生成候選解，還能檢查搜尋狀態（search state）、執行程式碼、調用領域特定工具（domain-specific tools），並根據觀察結果線上決定（online determination）下一步動作。這種「代理式表述」（agentic formulation）使得 LLM 的中間動作序列（intermediate actions）由模型動態決定，而非由外圍演算法（surrounding algorithm）預先指定。

**2. 跨領域基準設計**

AgenticBBO-Bench 涵蓋五個代表性領域，橫跨連續、混合與結構化搜尋空間：

- **合成函數（Synthetic functions）**：採用 BBOB 基準（Hansen et al., 2021），用於純數值連續優化
- **超參數優化（Hyperparameter optimization）**：採用 Bayesmark（Turner et al., 2021），涉及混合變數類型
- **資料庫調校（Database tuning）**：基於 Zhang et al. (2022) 的工作
- **晶片設計（Chip design）**：採用 BBOPlace-Bench（Xue et al., 2026）的巨集佈局（macroplacement）任務
- **分子設計（Molecular design）**：採用 GuacaMol（Brown et al., 2019）基準

此設計的關鍵在於「統一有限預算評估協定」（unified finite-budget evaluation protocol），使得通用代理與領域特定優化器（包括 TuRBO、TPE、Graph-GA 等）能在一致的評估規則下進行比較。

**3. 三項關鍵影響因子的控制實驗**

論文設計了控制變量實驗來隔離三個設計選擇的影響：

- **優化工具（Optimization tools）**：測試額外數值工具是否能穩定提升性能
- **任務資訊與先驗知識（Task information and prior knowledge）**：區分任務語義（task semantics）與更具體的先驗知識
- **LLM 在優化迴圈中的參與程度**：觀察 LLM 與數值優化器的協作模式

**4. 前沿挑戰（Frontier Challenge）**

論文最後定義了一個精簡的五任務前沿挑戰，從每個領域選取一個代表性任務，作為通用優化代理的標準化排行榜（leaderboard）。此設計採用 Codex 代理框架（Codex agent harness）評估七個前沿 LLM，並以帕累托前緣（Pareto frontier）分析性能與成本的權衡。

---

#### 實驗數據解讀

**1. 整體性能表現**

根據摘要所述，代理式黑盒優化在所有五個領域中均取得比直接基於 LLM 的方法（direct LLM-based methods）更高的家族平均分數（family-averaged scores），並在其中四個領域超越最佳數值優化器（numerical optimizers）。這項結果具有重要意義：它證實了 LLM 代理不僅能作為輔助工具，還能在多數情況下獨立勝過經過數十年發展的專用優化演算法。

**2. 前沿模型的帕累托分析**

圖 1 揭示了七個前沿 LLM 在 AgenticBBO-Bench 上的性能與成本權衡：

- **GPT-6 Astra** 與 **DeepSeek-V4.1-Flash** 位於帕累托前緣（Pareto frontier），代表性能與成本的最佳平衡
- **GPT-5.6 Sol** 與 **Gemini 3.1 Pro** 性能相近但成本差異顯著
- **GLM-5.3** 與 **Kimi-K3** 處於中間位置
- **DeepSeek V4 Pro** 雖然性能尚可，但成本最高

從圖中數據可見，GPT-6 Astra 達到約 59.1 分，DeepSeek-V4.1-Flash 達到約 58.4 分，而 GPT-5.6 Sol 為 51.2 分，Gemini 3.1 Pro 為 50.7 分。值得注意的是，性能相近的模型（如 GPT-5.6 Sol 與 Gemini 3.1 Pro）在每任務令牌成本（token cost per task）上可能存在數倍差距，這凸顯了成本性能權衡（cost-performance trade-off）在實際部署中的重要性。

**3. 三項關鍵因子的實驗發現**

- **優化工具的影響**：額外的數值工具並不能穩定提升代理性能。這項發現挑戰了「工具越多越好」的直覺，暗示工具整合需要精細設計，否則可能反而干擾 LLM 的決策過程。

- **任務語義 vs. 先驗知識**：任務語義（task semantics）普遍有益，但更具體的先驗知識（prior knowledge）可靠性較低。這表明 LLM 能有效利用一般性的任務描述，但對於高度特定的領域知識，其應用可能產生噪聲或錯誤。

- **LLM 與數值優化器的協作**：數值優化器有時能有效吸收（absorb）代理引導搜尋所建立的搜尋軌跡（search trajectories）。這意味著 LLM 代理的價值不僅在於其自身的搜尋能力，還在於其能為後續數值方法提供良好的起點。

**4. 跨領域性能差異的意涵**

五個領域涵蓋了不同的搜尋空間特性：連續變數（BBOB）、混合變數（Bayesmark）、結構化約束（資料庫調校、晶片設計、分子設計）。代理式方法在多數領域的優勢表明，LLM 的語言理解與推理能力能夠泛化到多樣化的優化問題，而非僅限於特定類型。

#### 與現有研究的比較

**1. 與經典黑盒優化方法的比較**

傳統方法如貝氏優化（Bayesian optimization）依賴替代模型（surrogate models）與獲取函數（acquisition functions），演化演算法（evolutionary algorithms）則依賴預定義的搜尋運算子（search operators）。這些方法僅利用數值觀察（numerical observations），無法直接利用任務描述、變數語義（variable semantics）與領域知識（domain knowledge）。AgenticBBO-Bench 透過統一協定，使這些方法能與 LLM 代理進行公平比較，結果顯示代理式方法在四個領域中勝出，證明了整合語言理解與數學嚴謹性（mathematical rigor）的價值。

**2. 與既有 LLM 黑盒優化研究的比較**

既有研究（如 Yang et al., 2024; Liu et al., 2024; Ran et al., 2025; Tan et al., 2025）通常將 LLM 作為優化程序的固定元件（fixed component），在每一輪由外圍演算法調用 LLM 執行預定義操作（predefined operation），如生成下一個候選解。相比之下，本論文研究的「代理式表述」允許 LLM 動態決定中間動作序列，這更接近真實的代理行為。然而，現有研究使用不同的任務領域與系統配置，使得結果難以直接比較。本論文正是為填補此缺口而設計。

**3. 與近期代理式黑盒優化研究的比較**

近期工作（Maus et al., 2026; Brunzema et al., 2026; Suwandi, 2026）開始採用更代理化的設定，但這些研究通常在單一領域內評估，且對代理框架（agent harness）的設計選擇各異。本論文的貢獻在於提供跨領域基準，使不同研究的結果能夠對齊。

**4. 與特定領域基準的比較**

- **BBOB**：作為連續優化的經典基準，被本論文作為合成函數領域的基礎
- **Bayesmark**：專注於超參數優化，本論文將其納入跨領域評估
- **BBOPlace-Bench**：晶片設計領域的基準
- **GuacaMol**：分子設計領域的基準

本論文的創新在於將這些異質基準統一在單一評估協定下，這在現有文獻中尚屬首次。

**5. 局限性**

- 雖然涵蓋五個領域，但每個領域僅選取有限任務，可能無法完全代表該領域的複雜度
- Codex 代理框架的選擇可能影響結果的普適性，其他框架下的表現可能有所不同
- 評估的七個 LLM 樣本有限，未涵蓋所有前沿模型
- 成本分析基於官方定價（official list price），實際部署成本可能因批量折扣、速率限制等因素而異

#### 可重現性評估

**1. 程式碼開源**

論文明確聲明程式碼已開源，存放於 https://github.com/lamda-bbo/agentic-bbo。此舉大幅提升了研究的可重現性，使其他研究者能夠：

- 重現基準測試結果
- 在統一協定下評估新的 LLM 代理
- 測試不同的代理框架設計
- 擴展基準至新的領域或任務

**2. 基準的標準化**

AgenticBBO-Bench 的統一有限預算評估協定（unified finite-budget evaluation protocol）為未來研究提供了標準化的評估基礎。這種標準化使得不同研究團隊的結果能夠直接比較，避免了「各自為政」的評估方式所帶來的混淆。

**3. 評估框架的透明度**

論文詳細描述了：
- 五個領域的任務選擇與配置
- 數值優化器（TuRBO、TPE、Graph-GA）的整合方式
- Codex 代理框架的設定
- 性能指標的計算方法

**4. 模型權重與 API 訪問**

雖然程式碼已開源，但論文中評估的七個前沿 LLM（GPT-6 Astra、DeepSeek-V4.1-Flash、GPT-5.6 Sol、Gemini 3.1 Pro、GLM-5.3、Kimi-K3、DeepSeek V4 Pro）均為商業模型，其權重不公開。研究重現需要透過各模型的 API 進行，這可能受到：
- API 定價變動的影響
- 模型版本更新的影響
- 訪問限制的影響

**5. 數據集可用性**

基準中的五個領域均基於既有公開基準（BBOB、Bayesmark、BBOPlace-Bench、GuacaMol、Zhang et al. 的資料庫調校工作），這些數據集本身是可獲取的。

**6. 可重現性的潛在挑戰**

- LLM 的隨機性可能導致結果的變異，需要多次運行取平均
- 代理框架的具體實現細節可能影響結果
- 硬體環境（如程式碼執行沙箱）可能影響某些領域的結果

#### 未來研究方向

**1. 基準的擴展**

- **更多領域**：可考慮納入材料優化（materials optimization）、神經架構搜尋（Neural Architecture Search, NAS）、強化學習超參數調校等領域
- **更多任務**：在現有領域內增加任務數量，以提高基準的統計可靠性
- **動態環境**：研究非靜態目標函數（隨時間變化的黑盒優化問題）

**2. 代理框架設計的深入研究**

論文發現額外的數值工具並不能穩定提升性能，這開啟了多個研究方向：
- 如何設計工具整合機制，使 LLM 能有效選擇與使用工具
- 工具調用時機與頻率對性能的影響
- 不同類型工具（數值優化器、領域模擬器、分析工具）的最佳組合

**3. 先驗知識的可靠性研究**

論文發現更具體的先驗知識可靠性較低，未來可探討：
- 如何評估先驗知識的品質與適用性
- LLM 何時應信任、何時應質疑先驗知識
- 自動驗證或調整先驗知識的機制

**4. 人機協作優化**

- 將人類專家知識整合到代理式優化流程中
- 設計互動式介面，使人類能指導 LLM 代理的搜尋方向
- 研究人類反饋如何影響代理的決策

**5. 多代理協作**

- 多個 LLM 代理並行搜尋並共享資訊
- 專門化代理（如專注於探索的代理與專注於利用的代理）的協作
- 代理間的知識蒸餾與遷移

**6. 理論分析**

- 代理式黑盒優化的收斂性分析
- LLM 決策的理論保證
- 與傳統優化理論的橋接（如 regret bounds）

**7. 效率與成本的優化**

- 降低 LLM 調用次數的策略
- 緩存與重用 LLM 推理結果
- 邊緣部署的小型化代理

**8. 安全性與魯棒性**

- 對抗性輸入對代理決策的影響
- 代理行為的可解釋性
- 失敗模式分析與恢復策略

**9. 跨領域遷移學習**

- 研究代理在一個領域學到的優化策略能否遷移到其他領域
- 設計通用的優化「元技能」
- 建立領域間的知識共享機制

**10. 實際應用的落地**

- 將代理式黑盒優化應用於真實科學問題（如藥物發現、材料設計）
- 與實驗室自動化系統整合
- 處理高風險領域的可靠性要求

這些研究方向不僅能深化對代理式黑盒優化的理解，還能推動 LLM 代理在科學研究與工程實務中的實際應用，最終實現更高效、更智慧的自動化優化流程。

## 論文問答

**Q1：什麼是黑盒優化（BBO），為什麼它在科學與工程領域中如此重要？**
A：黑盒優化處理的是那些目標函數可以評估但其解析形式與梯度無法取得的情境，這類問題廣泛存在於化學設計、材料優化與複雜系統配置等領域。由於每次目標函數評估往往涉及昂貴的物理實驗或運算程序，如何在有限的評估預算內有效率地搜尋最優解成為核心挑戰。論文中將其形式化為有限預算序列優化問題，每一輪根據歷史觀察選出新候選解並接收評估值，這種設定貼近真實應用中「昂貴且有限」的評估特性。

**Q2：現有的基於 LLM 的黑盒優化方法存在哪些不足？**
A：現有方法通常將 LLM 視為優化程序中的固定元件，僅在每一輪被外圍演算法呼叫以執行預定義的操作，例如生成下一個候選解或建模目標函數，而其餘的優化迴圈則事先指定。這種「LLM 作為單一固定運算子」的角色限制了 LLM 對搜尋狀態的動態觀察與決策能力，也使得不同研究之間的結果難以直接比較。此外，各研究在任務領域、系統配置與評估協定上的差異，使得個別設計選擇對性能的影響難以隔離分析。

**Q3：為什麼代理式黑盒優化（Agentic BBO）需要一個跨領域的基準？**
A：代理式 BBO 將 LLM 置於更自主的角色，使其能與優化環境互動、檢查搜尋狀態、執行程式碼、調用領域特定工具並線上決定下一步動作，這種靈活性也使得方法間的比較變得更為複雜。不同代理在觀察資訊、可存取工具與代理框架管理方式上的差異，都會顯著影響搜尋行為與最終結果。因此，建立一個跨領域、統一評估協定的基準對於釐清哪些發現反映 Agentic BBO 的一般性質、哪些僅依賴特定任務或系統設計至關重要。

**Q4：AgenticBBO-Bench 的核心方法論是什麼？**
A：AgenticBBO-Bench 是一個跨領域基準，涵蓋五個具代表性的優化領域：來自 BBOB 的合成數值優化、來自 Bayesmark 的超參數優化、資料庫調校、來自 BBOPlace-Bench 的晶片設計（巨集佈局），以及來自 GuacaMol 的分子設計。這些領域橫跨連續、混合與結構化搜尋空間，並具有不同的任務語義與可行性約束。透過將它們置於共同的有限預算評估協定下，使通用代理與領域特定優化器（如連續 BBO 的 TuRBO、超參數優化的 TPE、分子設計的 Graph-GA）能在一致的評估規則下進行比較。

**Q5：統一評估協定有哪些關鍵創新？**
A：統一評估協定的核心創新在於將異質的 BBO 問題標準化為相同的有限預算序列優化流程，使不同領域的結果具備可比性。具體而言，該協定規範了每一輪根據歷史觀察選取候選解、提交黑盒評估、接收觀察值並更新歷史的標準化迴圈。此外，該協定允許通用代理與領域特定優化器在同一框架下進行公平比較，這對於區分「代理帶來的增益」與「特定優化器本身的優勢」非常關鍵。

**Q6：代理框架（agent harness）的設計選擇如何影響實驗？**
A：代理框架的設計選擇包括代理可觀察的資訊、可存取的工具集合，以及框架如何管理代理與環境的互動，這些都會直接影響搜尋行為與最終優化性能。論文中採用 Codex 代理框架作為標準化平台，並透過控制實驗研究三個關鍵因素：優化工具、任務資訊與先驗知識，以及 LLM 在優化迴圈中的參與程度。這種設計使得研究者能夠系統性地隔離各設計選擇的影響，而非僅觀察整體性能差異。

**Q7：基準涵蓋哪些具體的領域與任務？**
A：基準涵蓋五個領域：合成函數優化（BBOB）、超參數優化（Bayesmark）、資料庫調校、晶片設計中的巨集佈局（BBOPlace-Bench）以及分子設計（GuacaMol）。這些任務涵蓋連續變數（如 BBOB）、混合變數（如超參數優化中的類別與連續變數混合）以及結構化物件（如分子與晶片佈局）。每個領域都帶有不同的任務語義與可行性約束，這種多樣性使得基準能夠全面評估代理在不同搜尋空間下的泛化能力。

**Q8：實驗中代理式 BBO 相較於基準方法的主要結果為何？**
A：在所有五個領域中，代理式 BBO 達到了比直接基於 LLM 的方法更高的家族平均分數，並在其中四個領域中優於最佳的數值優化器。這顯示出代理式方法整合任務語義、計算能力、優化工具與反饋驅動決策的綜合優勢。然而，論文中也指出額外的數值工具並不會一致地提升性能，這意味著工具整合的效益並非理所當然。

**Q9：消融研究揭示了哪些關於三個關鍵因素的發現？**
A：研究發現三個重要結論：第一，提供額外的數值工具並不會一致地改善性能，這挑戰了「工具越多越好」的直覺；第二，存取任務語義通常是有益的，但更具體的先驗知識則較不可靠，其價值高度依賴於問題特性；第三，LLM 在優化過程中可以扮演不同角色，而數值優化器有時能有效地從代理引導的搜尋軌跡中繼續改進，這顯示出代理與傳統優化器的互補性。

**Q10：哪些實際情境最能從這項研究中受益？**
A：任何涉及昂貴目標評估的科學與工程問題都能從中受益，包括藥物探索中的分子設計、晶片設計中的巨集佈局、機器學習模型的超參數優化，以及資料庫系統的效能調校。這些場景的共同特徵是每次評估成本高、預算有限，且往往伴隨豐富的領域知識與任務語義。代理式 BBO 透過整合這些非數值資訊與嚴謹的數學工具，為這類問題提供了新的解決途徑。

**Q11：從成本與性能的權衡來看，部署代理式 BBO 時應考慮哪些產品/工程因素？**
A：圖 1 顯示前沿模型在優化性能與推論成本之間存在顯著差異——性能相近的模型在每任務令牌成本上可能差距懸殊，這對於實際部署至關重要。GPT-6 Astra 與 DeepSeek-V4.1-Flash 位於性能與成本的帕累托前緣，意味著它們在當前評估中提供了最佳的成本性能權衡。實際部署時應根據任務的評估成本、相關性能需求與預算限制，選擇位於帕累托前緣的合適模型，而非單純追求最高性能。

**Q12：這項研究對 LLM 代理領域的更廣泛影響是什麼？**
A：這項研究將 LLM 代理的評估從特定領域擴展到跨領域、統一協定的基準設定，為未來通用優化代理的開發提供了標準化的排行榜與比較基礎。它揭示了代理設計中工具整合、任務語義利用與 LLM 參與程度的細微影響，這些發現對其他領域的代理設計（如程式碼生成、科學研究自動化）也具有參考價值。此外，該研究強調了評估代理時必須考慮系統配置與代理框架的敏感性，這對整個 LLM 代理評估方法論具有啟發意義。

**Q13：論文承認了哪些限制？**
A：論文承認其基準雖然涵蓋五個領域，但每個領域僅選取代表性任務，可能無法完全代表該領域內所有問題的特性。此外，代理框架的選擇（Codex）與工具集合的設計本身也是一種設計選擇，不同的框架可能導致不同的結論。論文中也指出，先驗知識的價值高度依賴於問題，這意味著對於特定問題，使用者仍需謹慎評估哪些先驗資訊真正有益。

**Q14：論文中揭示了哪些失敗案例或限制情境？**
A：論文中揭示的限制情境包括：額外的數值工具並非總是有效，這意味著在某些任務中，工具整合可能無法帶來預期增益；更具體的先驗知識可能不可靠，這在某些領域中可能導致代理被誤導而非受益。此外，雖然代理式 BBO 在多數領域表現優異，但並非在所有五個領域都優於最佳數值優化器，這顯示出代理式方法並非萬能，仍有其適用範圍。

**Q15：這項工作提出了哪些未來研究方向？**
A：未來研究方向包括：進一步探索代理框架設計對性能的影響，以建立更系統化的代理設計原則；研究如何更可靠地整合先驗知識，使其在不同問題上都能穩定帶來增益；以及擴展基準至更多領域與任務，建立更全面的通用優化代理評估體系。此外，五任務前沿挑戰作為標準化排行榜，將持續追蹤未來前沿模型的發展，為研究者提供清晰的進步基準。

## 實務應用指南

### 適用場景

1. **機器學習模型超參數調校**：在 AutoML 流程中，針對 XGBoost、LightGBM、神經網路架構等模型，利用 LLM 代理整合任務語義（如「這是影像分類任務，資料量小」）與數值搜尋歷史，比單純使用 TPE 或貝氏優化更能利用領域知識。

2. **資料庫系統調校**：PostgreSQL、ClickHouse 等資料庫的 knob configuration（如 `shared_buffers`、`work_mem`），可讓 LLM 代理根據工作負載描述（OLTP vs. OLAP）與過去評估結果，自主決定要查詢哪些系統狀態、執行哪些測試查詢。

3. **晶片實體設計中的巨集佈局（macro placement）**：在 BBOPlace-Bench 設定中，代理可觀察線長、擁擠度等指標，呼叫佈局工具並迭代修正候選解，適合用於 EDA 流程中的早期探索階段。

4. **藥物與材料設計的分子最佳化**：在 GuacaMol 基準下，代理可結合化學先驗（如官能基相容性、合成可行性）與分子性質預測值，引導結構搜尋，比純遺傳演算法更能貼近藥化學家的思考模式。

5. **工業製程與排程參數搜尋**：在半導體製程、機器人運動規劃、推薦系統 A/B 測試等場景中，當評估昂貴且變數含混合型別（連續、類別、結構化）時，代理式 BBO 可作為通用探索層。

### 實作前置條件

**資料與環境**
- 一個可執行的黑盒評估函數 `f(x)`，能回傳數值分數或經正規化的 reward；單次評估成本需可量化（時間、金錢或 API 額度）。
- 明確的搜尋空間定義：連續區間、類別集合、結構化物件（SMILES、placement 矩陣等），以及可行性約束。
- 評估預算 `B`（例如 200–500 次評估），需事先固定以便跨方法比較。

**運算資源**
- LLM API 存取權限（OpenAI、DeepSeek、Gemini 等），並準備對應的官方定價資訊以估算每任務成本。
- 代理執行環境（建議使用 Codex agent harness 或等效的程式碼執行沙箱），需具備工具呼叫、狀態持久化與日誌記錄能力。
- 若涉及領域工具（如晶片佈局器、分子模擬器），需預先容器化並提供 CLI/REST 介面。

**技能門檻**
- 熟悉 Python、LLM API 串接、function calling / tool use 協定。
- 具備基本的最佳化素養（理解貝氏優化、演化策略、surrogate model 的概念），以便診斷代理行為。
- 領域知識：依應用場景需具備相應專業（資料庫 DBA、EDA 工程師、藥化學家等），用於設計 prompt 中的任務語義與先驗。

---

### 實作步驟建議

1. **定義任務契約**：依 AgenticBBO-Bench 的精神，明確規範「代理可觀察什麼」（搜尋歷史、任務描述、變數語義）、「可呼叫哪些工具」（評估器、領域工具、數值優化器）以及「每回合動作預算」。這份契約是後續所有比較的基準。

2. **建立有限預算評估協定**：固定總評估次數 `B`、隨機種子數（建議 ≥ 5）、正規化方式（將原始分數映射到 [0,1]）。所有候選方法（代理、純 LLM、TPE、TuRBO 等）必須在同一協定下評估，才能得出可比較的 family-averaged score。

3. **設計代理 prompt 與工具介面**：將任務描述、變數語義、搜尋歷史摘要、可用工具清單組裝成 system prompt；工具以 JSON schema 形式註冊。建議先以「僅任務語義」為基線，再逐步加入數值工具與先驗知識，以利後續消融實驗。

4. **執行基準實驗並記錄軌跡**：對每個任務跑完整預算，記錄每回合的動作、工具輸出、token 用量與成本。論文顯示「搜尋軌跡可被數值優化器吸收」，因此完整軌跡日誌是後續分析的關鍵資產。

5. **進行消融分析**：依循論文的三因子框架，分別測試（a）有／無數值工具、（b）有／無任務語義、（c）LLM 介入程度（純代理 vs. 代理引導 + 數值優化器接手）。這能幫助你判斷哪些設計選擇對你的場景真正有效。

6. **建立五任務前沿挑戰子集**：從你的應用中挑選五個代表性任務組成 leaderboard，定期評估新模型。論文示範了 GPT-6 Astra 與 DeepSeek-V4.1-Flash 在性能—成本帕累托前緣上的優勢，可作為選型參考。

7. **部署與監控**：將代理封裝為服務，設置單任務成本上限、單回合動作上限與超時保護；建立回歸測試，確保 prompt 或工具變更不會導致性能顯著下降。

### 潛在風險與注意事項

- **「加更多工具不一定更好」**：論文明確指出額外的數值工具未必能提升表現，反而可能讓代理陷入無效的工具呼叫迴圈，浪費 token 與時間。**緩解**：從最小工具集開始，僅在消融實驗證明有效時才加入。

- **過度依賴先驗知識的幻覺**：LLM 可能自信地給出錯誤的領域建議（例如錯誤的化學子結構偏好）。**緩解**：將先驗視為「提示」而非「指令」，並設置安全邊界（如可行性過濾器、人工審核節點）。

- **成本失控**：前沿模型單次任務成本可相差一個數量級以上（論文圖 1 顯示從 $0.5 到 $50+）。**緩解**：在協定中加入單任務 token 預算上限，並在 Pareto 前緣上做選型，而非只看性能。

- **評估不具可比性**：不同任務域、不同預算、不同 prompt 格式會讓結果無法橫向比較。**緩解**：嚴格遵守統一協定，公開所有超參數與隨機種子，必要時引用 AgenticBBO-Bench 作為對照。

- **代理行為難以重現**：LLM 溫度、版本更新、API 變動都會導致結果漂移。**緩解**：固定模型版本與溫度（建議 0 或極低），記錄完整 prompt 與工具呼叫日誌。

- **搜尋軌跡交接失敗**：雖然論文顯示數值優化器可從代理軌跡接手，但若代理產出的歷史品質太差（如大量重複或無資訊樣本），接手效果會打折。**緩解**：在交接前對歷史做去重與篩選。

### 與其他技術的整合建議

- **與 AutoML 框架整合**：可將代理式 BBO 作為 Optuna、Ray Tune 的「自訂 sampler」，由代理決定每回合要嘗試的超參數組合，框架負責並行化與持久化。

- **與 MLOps / Experiment Tracking 整合**：把每次代理動作、工具輸出、評估結果寫入 MLflow 或 Weights & Biases，便於跨實驗比較與審計。

- **與領域模擬器整合**：晶片設計可串接 OpenROAD、分子設計可串接 RDKit + docking 工具；建議以薄包裝層（thin wrapper）暴露 CLI，讓代理透過 function calling 呼叫。

- **與傳統優化器組成混合管線**：依論文發現，可採「代理引導前期 + 數值優化器收尾」的模式，例如前 30% 預算交給代理探索語義空間，後 70% 交給 TuRBO 或 TPE 做精細化。

- **與成本監控系統整合**：串接 FinOps 工具追蹤每任務的 token 成本，設定告警閾值；可參考論文的「官方定價 × 每任務 token 用量」估算方式。

- **與安全與合規層整合**：在金融、醫療等受監管場景，需在代理外層加入動作白名單、輸出審查與人工覆核機制，避免代理呼叫未授權工具或產生不可解釋的決策。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先讀摘要與第 1 節的「Agentic BBO」定義，理解它與傳統貝氏優化的差異在於「LLM 自主決定動作序列」。接著看第 2 節的有限預算迴圈公式，這是理解所有後續實驗的基礎。實作上可從 Bayesmark 的超參數調校任務開始，用現成的 Codex harness 跑一次 baseline，感受代理的行為模式。

**給 AI 工程師**：重點放在第 1 節後半的「三因子分析」與論文的消融實驗設計。論文揭示了幾個反直覺的工程結論（工具不是越多越好、先驗不是越具體越好），這些對設計 production 代理非常有價值。建議在自己的場域複製這些消融實驗，建立內部的設計選擇決策樹。

**給研究者**：本論文的核心貢獻是「統一評估協定」與「跨域基準」，這對 BBO 社群是方法論上的推進。建議仔細閱讀實驗章節中關於 family-averaged score 的計算方式、隨機化設計，以及「代理軌跡被數值優化器吸收」這個現象的理論意涵——它暗示 LLM 與傳統優化器之間存在某種可分解的分工結構，值得進一步形式化。

**給產品經理**：關鍵訊息是「性能與成本可以差很多」。圖 1 的帕累托前緣圖是選型決策的絕佳參考：GPT-6 Astra 與 DeepSeek-V4.1-Flash 在性能—成本權衡上表現最佳。在規劃產品時，應將「每任務成本上限」列為一等需求，並要求團隊提供 AgenticBBO-Bench 五任務子集的標準化報告，而非單一任務的展示結果。同時，理解代理式 BBO 並非萬靈丹——它適合「評估昂貴、變數語義豐富、有領域知識可利用」的場景，對純連續低維問題可能不如 TuRBO。
