# DeepSearch-World：可驗證環境中深度搜尋代理的自我蒸餾

**原文標題：** DeepSearch-World: Self-Distillation for Deep Search Agents in a Verifiable Environment

**發布日期：** 2026-07-08

## ⚡ TL;DR

現有長程工具代理受限於靜態模仿與稀疏獎勵，缺乏可驗證的過程監督。
提出DeepSearch-World與DeepSearch-Evolve，以鷹架監督實現自我蒸餾。
DeepSearch-World-9B達31.2%、61.5%、93.4%，無需強教師且能自我演化。

## 摘要翻譯

訓練工具使用代理（tool-use agents）從自身經驗中改進仍具挑戰性，因為監督式微調（supervised fine-tuning, SFT）依賴固定的教師蒸餾軌跡（teacher-distilled trajectories），而稀疏獎勵強化學習（sparse-reward reinforcement learning）僅能為長程互動（long-horizon interactions）提供微弱的監督訊號。我們提出 DeepSearch-Evolve，一個建構於 DeepSearch-World 之上的網頁代理（web agents）自我蒸餾框架（self-distillation framework）；DeepSearch-World 是一個具備可重現搜尋（reproducible search）與頁面閱讀工具（page-reading tools）的確定性且可驗證的環境（deterministic and verifiable environment）。DeepSearch-World 包含 42 萬筆對齊的多跳問答任務（aligned multi-hop QA tasks），透過實體層級隨機遊走（entity-level random walks）建構而成，並支援對自我演化（self-evolution）至關重要的代理認知行為（agentic cognitive behaviors），包括進度驗證（progress verification）、基於事實的反思（grounded reflection）與失敗恢復（failure recovery）。DeepSearch-Evolve 透過迭代地執行軌跡生成（trajectory generation）、軌跡過濾（trajectory filtering）、資料混合（data mixing）與微調（fine-tuning），以訓練出更強的代理。無需仰賴更強模型的蒸餾，DeepSearch-World-9B 相較於開源代理（open-source agents）取得具競爭力的表現，在 BrowseComp 達到 31.2%、在 GAIA 達到 61.5%、在 HotpotQA 達到 93.4%，顯示可驗證環境使長程網頁代理（long-horizon web agents）的可擴展自我演化（scalable self-evolution）成為可能。我們將釋出環境、42 萬筆任務的訓練池（training pool）、驗證集（validation set）、模型與程式碼，以促進未來自我改進的深度搜尋代理（self-improving deep search agents）相關研究。

### 核心貢獻（3～5點）
- 提出 DeepSearch-Evolve 自我蒸餾框架，使代理無需更強教師模型即可從自身經驗中持續改進。
- 建構 DeepSearch-World：一個確定性且可驗證的環境，具備可重現搜尋與頁面閱讀工具，並包含 42 萬筆對齊的多跳問答任務。
- 支援進度驗證、基於事實的反思、失敗恢復等關鍵代理認知行為，為自我演化提供結構化基礎。
- 透過迭代軌跡生成、軌跡過濾、資料混合與微調，實現可擴展的自我演化蒸餾。
- DeepSearch-World-9B 在 BrowseComp、GAIA、HotpotQA 等基準上達到具競爭力的表現，並將釋出環境、資料、模型與程式碼。

### 適合對象
適合對工具使用代理、自我改進機制、長程網頁代理與可驗證訓練環境感興趣的研究人員與工程師，特別是關注如何在不依賴更強教師模型的前提下，透過自我蒸餾與可驗證環境實現代理自我演化的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心問題設定：為何需要可驗證的離線環境？

現有工具使用代理（tool-use agents）的自我改進（self-improving）主要面臨三種監督訊號的困境：

- **基於模仿的監督式微調（Imitation-based SFT）**：依賴固定教師軌跡（teacher-distilled trajectories），軌跡多樣性受限，且學生能力上限受教師與骨幹模型能力束縛。
- **基於獎勵的強化學習（Reward-based RL）**：僅靠稀疏最終獎勵（sparse final reward）進行長程互動學習，訊號微弱、優化不穩定，且難以驗證中間步驟。
- **即時網頁環境（live web environments）**：雖然真實，但觀察不可重現、服務成本高，且難以提供可靠的過程層級監督（process-level supervision）。

本論文因此提出 **DeepSearch-World**，一個建立在 Wikipedia 上的**確定性且可驗證的環境（deterministic and verifiable environment）**，並在此基礎上發展出 **DeepSearch-Evolve** 自我蒸餾框架（self-distillation framework），讓代理能從自身經驗中穩定演化。

##### 2. DeepSearch-World 的建構

DeepSearch-World 包含三大支柱：

**（1）以實體層級隨機遊走（entity-level random walks）產生多跳問答（multi-hop QA）任務**

論文從 Wikipedia 知識圖譜中進行隨機遊走（random walks），產生目標實體集合 \(T_i = \{e_{i,1}, \dots, e_{i,H}\}\)，再據此生成需要跨文件推理的問題。這種方式能系統性地控制問題難度與所需跳數，並確保每個問題都有明確、可檢索的證據鏈。

**（2）對齊的離線語料庫（aligned offline corpus）**

針對 420K 筆任務，論文爬取對應 Wikipedia 頁面，建立約 1,000 萬筆條目的本地語料庫 \(C_i\)，每筆包含標題、摘要與全文。這種**對齊任務（aligned tasks）**設計確保問題所需的證據可在離線環境中被搜尋與驗證，而不會因真實網頁變動而失效。

**（3）確定性工具（deterministic tools）**

環境提供兩類核心工具：

- **Web Search**：以 BM25 實作的離線搜尋，具有確定性檢索函式（deterministic retrieval function）。
- **Wiki Visit**：模擬瀏覽器造訪，透過 SQLite 索引將 URL 對應到完整文章，提供確定性閱讀函式（deterministic reading function）。

由於工具呼叫結果可重現，研究者可以對代理的每一個中間工具使用決策（intermediate tool-use decisions）進行驗證，這是過程層級監督的基礎。

##### 3. DeepSearch-Evolve：自我蒸餾迴圈

DeepSearch-Evolve 由四個階段組成迭代迴圈：

**（1）教師軌跡生成（Teacher Generation）**

教師代理（teacher agent）在 DeepSearch-World 中執行任務，並使用**鷹架式過程監督（scaffold process supervision）**。不同於傳統只輸出最終答案的軌跡，教師會顯式追蹤：

- 規劃（planning）
- 證據與記憶（memory）
- 失敗嘗試（failed attempts）
- 錯誤修正與回滾（error correction & rollback）
- 查詢重寫（query rewriting）

這些結構化的鷹架軌跡（scaffold trajectories）記錄了代理的認知過程，而不只是行動序列。

**（2）已驗證軌跡過濾（Verified Trajectory Filtering）**

由於環境可驗證，系統可以檢查每條軌跡是否正確到達目標答案，並只保留成功的軌跡。這相當於一種拒絕取樣（rejection sampling），但不同於 RL 的稀疏獎勵，此處的驗證訊號是確定且可解釋的。

**（3）鷹架轉 ReAct 轉換（Scaffold-to-ReAct Conversion）**

為了讓學生模型（student model）能學習，論文將鷹架軌跡轉換為標準的 **ReAct** 格式。轉換過程中會將規劃、記憶追蹤、基於事實的反思（grounded reflection）與失敗恢復（failure recovery）等認知行為注入學生，使其不僅模仿行動，更學習如何思考與修正。

**（4）重要性取樣資料混合與 SFT 訓練（Importance-Sampling-based Data Mixing & SFT）**

為避免迭代過程中資料分布崩潰，論文採用重要性取樣（importance sampling）進行新舊資料混合（data mixing），確保訓練池涵蓋多樣的推理路徑、失敗模式與恢復模式。隨後以監督式微調（SFT）更新學生模型，形成「生成 → 驗證 → 蒸餾 → 訓練」的閉環。

整體而言，DeepSearch-Evolve 的關鍵創新在於將**自我演化（self-evolution）**從「模仿固定教師」或「獎勵驅動探索（reward-driven exploration）」轉變為「已驗證的自我演化蒸餾（verified self-evolving distillation）」，在確定性環境中提供可控的認知行為監督。

#### 實驗數據解讀

論文在摘要中報告了 **DeepSearch-World-9B**（90 億參數的學生代理模型）在三個基準測試上的表現：

| 基準測試 | 分數 | 意義 |
|---|---|---|
| **BrowseComp** | 31.2% | 衡量深度網頁瀏覽與多步資訊整合能力的基準 |
| **GAIA** | 61.5% | 通用 AI 助理（General AI Assistant）綜合能力評估 |
| **HotpotQA** | 93.4% | 多跳推理問答（multi-hop QA）資料集 |

##### 1. 整體表現的意涵

最值得注意的並非單一分數，而是這些結果是在**未從更強大的專有模型進行知識蒸餾**的情況下達成。這表示 DeepSearch-Evolve 能讓開源模型（open-source agents）透過自我蒸餾（self-distillation）持續提升，而不必依賴 GPT-4 等封閉教師模型產生合成軌跡。

- **HotpotQA 93.4%**：已接近該資料集的天花板，顯示代理在結構化多跳問答上具備極強的檢索與推理能力。
- **GAIA 61.5%**：在需要綜合規劃、工具使用與常識推理的通用助理任務上表現突出。
- **BrowseComp 31.2%**：雖然絕對值不高，但 BrowseComp 專門測試極深層的網頁瀏覽能力，此分數在開源代理中已具競爭力。

##### 2. 行為層面的觀察

論文進一步指出，DeepSearch-World-9B 能夠：

- 維持更長的工具使用互動（sustains longer tool-use interactions）
- 更有效地使用工具（uses tools more effectively）

這呼應了方法論設計的目標：透過鷹架式過程監督，代理學會的不只是「找到答案」，而是如何進行長程規劃、記憶管理、反思與恢復。這些行為在稀疏獎勵強化學習（sparse-reward RL）中通常難以穩定湧現。

##### 3. 數據解讀的限制

由於目前僅能看到摘要與部分方法論，缺乏詳細的消融實驗（ablation studies），例如：

- 鷹架式過程監督相較於純 ReAct 軌跡的具體增益
- 迭代輪數與效能提升的關係
- 重要性取樣資料混合（importance-sampling-based data mixing）對分布穩定性的影響
- 在 BrowseComp 各難度子集上的細部分析

這些細節對於理解方法各組件的貢獻至關重要，期待完整論文與補充材料釋出後能進一步驗證。

#### 與現有研究的比較

##### 1. 相較於傳統 SFT：從靜態模仿到動態自我演化

傳統監督式微調（SFT）依賴教師蒸餾軌跡（teacher-distilled trajectories），存在兩大問題：

- **靜態模仿訊號（static imitation signals）**：訓練資料固定，無法隨學生能力提升而調整。
- **軌跡多樣性有限（limited trajectory diversity）**：學生只能看到教師的單一路徑，難以學習錯誤恢復與替代策略。

DeepSearch-Evolve 透過迭代生成與驗證，讓學生代理自己產生並篩選軌跡，逐步擴大有效行為空間，突破了傳統 SFT 的靜態限制。

##### 2. 相較於 RL：從稀疏結果獎勵到密集過程監督

GRPO 等群體強化學習（group RL）雖然已成為工具使用代理的主流後訓練範式，但其依賴：

- **稀疏最終獎勵（sparse final reward）**：長程任務中訊號微弱。
- **弱可驗證性（weak verifiability）**：難以判斷中間步驟是否正確。
- **行為隨機湧現（behaviors emerge randomly）**：規劃、反思等認知行為不一定穩定出現。

DeepSearch-Evolve 則利用可驗證環境提供確定的過程訊號，使規劃（planning）、記憶（memory）、錯誤修正（error correction）、回滾（rollback）與查詢重寫（query rewriting）成為可控制、可學習的行為。

##### 3. 相較於 OPSD / 在線策略蒸餾：從非平穩教師到穩定自我蒸餾

近期 OPSD（On-Policy Self-Distillation）等方法嘗試透過在線策略生成（on-policy generation）緩解 RL 的不穩定性，但其教師策略（teacher policy）本身並非總是可靠或平穩（not always reliable or stationary）。DeepSearch-Evolve 的解決方式是建立一個**確定性且可驗證的環境（deterministic and verifiable environment）**，讓成功軌跡可以被客觀驗證，從而提供穩定的蒸餾目標。

##### 4. 相較於其他虛擬工具環境

過去研究透過 API 快取、程式化模擬器或 LLM 建模環境來提升可重現性，但常面臨：

- 真實性有限（limited realism）
- 幻覺觀察（hallucinated observations）
- 高服務成本（high serving cost）

DeepSearch-World 以真實 Wikipedia 為基礎建立離線語料庫，兼顧真實性、可重現性與低成本，是介於「真實網頁」與「純合成環境」之間的重要折衷。

##### 5. 限制與潛在弱點

儘管方法論設計精巧，仍有以下限制：

- **環境封閉性**：DeepSearch-World 是離線 Wikipedia 環境，雖然可驗證，但與動態真實網頁仍有差距，可能影響到 BrowseComp 等真實網頁基準的泛化能力。
- **任務分布**：以實體隨機遊走產生的多跳問答（multi-hop QA）雖然結構清晰，但與真實使用者查詢的分布可能不同。
- **工具確定性假設**：真實搜尋引擎具有排序波動與個人化，未來若要遷移到即時網頁，需處理隨機性與部分可觀察性。
- **規模上限**：目前展示的是 9B 學生模型，雖然已具競爭力，但與更大規模模型相比仍有提升空間。

#### 可重現性評估

##### 1. 開源承諾

論文明確表示將釋出：

- DeepSearch-World 環境
- 420K 訓練池（training pool）
- 驗證集（validation set）
- DeepSearch-World-9B 模型權重
- 原始碼（code）

這對於長程網頁代理（long-horizon web agents）研究是極大利多，因為目前該領域缺乏標準化、可重現的訓練與評估平台。

##### 2. 環境設計利於重現

DeepSearch-World 的設計本身就有助於可重現性：

- **確定性工具呼叫（deterministic tool call）**：相同查詢與動作總是得到相同結果，便於除錯與比較不同模型。
- **離線語料庫**：以 SQLite 索引儲存 Wikipedia 文章，無需即時呼叫外部 API，降低實驗成本與不穩定性。
- **可驗證中間步驟**：每個工具呼叫的結果都可以與 ground-truth 實體集合比對，提供客觀的過程監督訊號。

##### 3. 可重現性的潛在挑戰

儘管設計良好，仍需注意：

- **大規模語料庫的下載與儲存**：約 1,000 萬筆 Wikipedia 條目與 420K 任務需要相當的儲存空間與頻寬。
- **教師代理的實作細節**：鷹架式過程監督（scaffold process supervision）的提示工程（prompt engineering）與結構化輸出格式若未完整釋出，可能難以完全復現。
- **訓練運算資源**：迭代自我蒸餾需要大量生成與微調運算，對於資源有限的研究者仍是門檻。
- **釋出時程與授權**：論文僅表示「將釋出」，實際開源時程、授權條款與維護程度將影響長期可重現性。

整體而言，若論文確實完整釋出環境、資料、模型與程式碼，DeepSearch-World 有望成為工具使用代理（tool-use agents）領域的重要開放基礎設施。

#### 未來研究方向

##### 1. 擴展到動態真實網頁環境

DeepSearch-World 目前以離線 Wikipedia 為基礎。未來可研究如何將自我蒸餾框架遷移到即時網頁環境（live web environments），例如透過：

- 網頁快取與版本控制
- 對抗排序波動的穩健檢索策略
- 結合真實瀏覽器模擬器（如 WebArena、Mind2Web）

##### 2. 與強化學習的結合

雖然本論文強調 SFT 自我蒸餾的穩定性，但未來可探索將 DeepSearch-Evolve 與 RL 結合：

- 以已驗證軌跡作為 RL 的初始示範資料
- 設計過程獎勵模型（process reward models, PRM）
- 在驗證環境中進行安全的獎勵驅動探索（reward-driven exploration）

##### 3. 自動化課程與難度調適

目前 420K 任務來自隨機遊走，未來可發展：

- 基於學生失敗模式的自動課程學習（automatic curriculum learning）
- 動態調整問題難度與所需跳數
- 針對性生成對抗式範例以強化弱項

##### 4. 多代理與協作式自我演化

單一代理的自我演化可擴展為多代理系統：

- 規劃代理、檢索代理、驗證代理分工協作
- 代理間互相批評與修正
- 建立分布式的自我蒸餾機制

##### 5. 認知行為的細粒度分析

未來可更深入分析代理學到的認知行為：

- 規劃（planning）的層次結構
- 記憶（memory）的組織與檢索策略
- 基於事實的反思（grounded reflection）如何觸發
- 回滾（rollback）與查詢重寫（query rewriting）的最佳時機

##### 6. 模型規模與效率

- 將方法應用於更大模型（如 30B、70B）以探索能力上限
- 研究如何將蒸餾後的能力壓縮到更小模型，適用於邊緣裝置
- 開發更高效的非同步生成與訓練管線

##### 7. 安全性與對齊

自我演化代理（self-evolving agents）長期來看涉及安全議題：

- 如何防止代理在自我蒸餾過程中學到錯誤或有害行為
- 設計人類回饋機制（human-in-the-loop verification）
- 確保驗證訊號本身不會被操縱或產生偏差

##### 8. 跨領域工具遷移

除了網頁搜尋與瀏覽，未來可將 DeepSearch-Evolve 的框架應用到：

- 程式碼生成與執行工具
- API 呼叫與資料庫查詢
- 科學實驗設計與模擬環境
- 多模態工具（如圖片搜尋、地圖導航）

總結來說，DeepSearch-World 與 DeepSearch-Evolve 為長程工具使用代理提供了一個可驗證、可擴展的自我演化範式。未來研究可在環境真實性、演算法多樣性、模型規模與安全對齊等方向持續推進。

## 論文問答

**Q1：訓練能夠自我改進的工具使用代理時，核心挑戰是什麼？**
A：核心挑戰在於如何讓代理從自身長程互動經驗中穩定地學習並持續進步，而非僅依賴固定不變的教師示範。傳統監督式微調（SFT）仰賴教師蒸餾軌跡，這些軌跡不僅受限於教師模型的能力上限，也缺乏足夠的多樣性來涵蓋各種失敗與恢復情境。另一方面，稀疏獎勵強化學習（RL）只能在任務結束時提供微弱的結果訊號，難以對中間每一步的工具使用決策給予有效監督，導致長程任務的優化過程不穩定。

**Q2：為什麼基於模仿的 SFT 與基於獎勵的 RL 對於深度搜尋代理而言仍顯不足？**
A：基於模仿的 SFT 本質上受限於骨幹模型能力，且軌跡多樣性有限，學生只能複製教師的行為而難以超越教師。基於獎勵的 RL 雖然能透過獎勵驅動探索，但稀疏最終獎勵無法清楚告知代理哪一個中間步驟正確、哪一個錯誤，使得行為可能隨機浮現且難以解釋。兩者都缺乏可靠的過程層級監督，無法針對規劃、記憶、反思與回滾等認知行為進行細緻訓練。

**Q3：可驗證環境對於可擴展的自我演化為何至關重要？**
A：長程網頁代理需要在每個中間步驟獲得明確回饋，才能學會何時該搜尋、何時該瀏覽、何時該反思或重寫查詢。可驗證環境能夠暴露中間工具使用決策的正確性，例如確認某次搜尋是否找到所需證據、某次頁面瀏覽是否取得關鍵資訊。這種過程層級監督讓規劃、基於事實的反思、錯誤修正與失敗恢復等可控制的認知行為得以被系統化地培養，而不只是依賴最終結果的獎懲。

**Q4：DeepSearch-Evolve 的核心方法包含哪三大組成部分？**
A：DeepSearch-Evolve 首先建立在 DeepSearch-World 之上，這是一個以 Wikipedia 為基礎的確定性且可驗證的離線環境，內含 42 萬筆對齊的多跳問答任務。其次，它採用鷹架式教師代理（scaffold teacher agent），在軌跡生成過程中明確追蹤進度、證據、失敗嘗試與恢復路徑。最後，它透過迭代式的自我演化訓練迴圈，結合非同步軌跡生成、已驗證軌跡過濾、重要性取樣資料混合與監督式微調，持續提升學生代理的能力。

**Q5：什麼是鷹架式過程監督（scaffold process supervision），它如何幫助學生學習？**
A：鷹架式過程監督是指教師代理在 rollout 過程中主動記錄並結構化地呈現任務進度、已收集證據、錯誤嘗試以及修復策略。這些鷹架軌跡隨後會被轉換為標準的 ReAct 格式，讓學生模型能夠在熟悉的推理行動框架下學習。透過這種鷹架轉 ReAct 轉換，學生不僅學會產生正確答案，更能內化規劃、記憶追蹤、基於事實的反思與失敗恢復等深度搜尋所需的認知行為。

**Q6：作者為何選擇確定性離線的 Wikipedia 環境，而非即時網頁環境？**
A：即時網頁環境雖然真實，但具有動態性、高服務成本、難以重現以及觀察結果不可靠等問題，這些都不利於大規模軌跡生成與嚴格驗證。相對地，以 Wikipedia 為基礎的離線環境能提供可重現觀察與可重現搜尋，並確保每個問題所需的證據都能在本機語料庫中被檢索與驗證。這種設計讓研究者能夠在穩定、可控的條件下進行自我蒸餾，並針對中間步驟進行實體層級的驗證。

**Q7：DeepSearch-World-9B 在哪些基準測試上進行評估？**
A：該模型主要在 BrowseComp、GAIA 與 HotpotQA 三個基準上進行評估。BrowseComp 測試代理在複雜網頁瀏覽任務中的長程搜尋與資訊整合能力；GAIA 評估通用 AI 助理在真實世界多步驟問題上的表現；HotpotQA 則是經典的多跳推理問答資料集，要求代理跨越多份文件進行推理。這三個基準分別從網頁瀏覽、通用助理能力與多文件問答等角度，全面檢視深度搜尋代理的實力。

**Q8：DeepSearch-World-9B 取得了哪些關鍵實驗結果？**
A：DeepSearch-World-9B 在 BrowseComp 上達到 31.2%，在 GAIA 上達到 61.5%，在 HotpotQA 上更高達 93.4%，整體表現與開源代理相比具有競爭力。特別值得注意的是，這些成績是在沒有從更強大的專有模型進行知識蒸餾的情況下達成的，顯示出自我蒸餾的潛力。這項結果證明了確定性且可驗證的環境能夠支撐長程網頁代理的可擴展自我演化，而不必依賴外部超級教師。

**Q9：作者提供了哪些額外的分析來支持方法的有效性？**
A：額外分析顯示 DeepSearch-World-9B 能夠維持更長的工具使用互動，並且更有效地運用搜尋與瀏覽工具。作者也指出，整體效能同時受益於已驗證軌跡過濾與鷹架轉 ReAct 轉換這兩項設計，前者確保只有正確軌跡進入訓練，後者則將結構化過程監督轉化為學生可學習的格式。這些分析說明了自我蒸餾的穩定性並非來自單一技巧，而是來自環境可驗證性、軌跡篩選與監督格式轉換的協同作用。

**Q10：DeepSearch-Evolve 在實務上可以應用於哪些場景？**
A：DeepSearch-Evolve 可應用於需要多步驟文獻檢索的研究助理、在企業知識庫中導航的客戶支援代理，以及需要驗證中間證據的專業問答系統。由於環境具有確定性與可驗證性，它特別適合對正確性與可解釋性要求較高的領域，例如法律、醫療或金融資訊查詢。只要目標領域擁有結構化且可離線建置的語料庫，就有可能複製這套自我演化流程來訓練專屬的深度搜尋代理。

**Q11：產品團隊在部署此類代理時應考量哪些因素？**
A：產品團隊首先必須權衡環境真實性與可重現性之間的取捨，因為 DeepSearch-World 雖然穩定可控，但無法完全模擬即時網頁的動態內容與雜訊。其次，部署時需要設計持續的自我演化迴圈，並監控代理在轉移到真實工具或更新語料庫時是否出現分布偏移。最後，由於代理會進行長程規劃與查詢重寫，團隊也應建立適當的過程審計機制，以便追蹤與解釋每一次工具呼叫的決策依據。

**Q12：這項研究可能對自我改進代理領域帶來什麼影響？**
A：這項研究將研究焦點從模仿專有教師模型或依賴稀疏 RL 獎勵，轉移到在可驗證環境中進行自我演化蒸餾。作者承諾開放環境、42 萬筆訓練池、驗證集、模型與程式碼，這將大幅降低長程代理自我改進研究的進入門檻。未來研究可以在此基礎上探索更複雜的工具生態、更強大的驗證機制，以及與其他學習範式的結合，進一步推動可擴展且可信賴的代理自我演化。

**Q13：這篇論文暗示或承認了哪些限制？**
A：由於環境建構在 Wikipedia 之上，其知識範圍與領域特性可能無法直接泛化到所有真實網頁或需要即時資訊的應用情境。確定性設定雖然帶來可驗證性，但也簡化了即時網頁代理必須面對的動態內容、廣告干擾與雜訊搜尋結果等挑戰。此外，9B 參數規模雖然在開源模型中表現出色，但在處理極度複雜的多跳推理時，其推理深度可能仍不及更大規模的專有模型。

**Q14：DeepSearch-World 中的代理仍可能出現哪些失敗案例？**
A：當問題所需的證據未被包含在離線語料庫中，或無法透過 BM25 離線搜尋有效檢索時，代理即使具備良好策略也難以成功回答。即使經過鷹架式訓練，代理在面對連鎖性錯誤時仍可能無法有效恢復，特別是當早期查詢方向嚴重偏離目標實體時。這些失敗案例凸顯了語料庫覆蓋率、檢索函式設計以及查詢重寫能力對於整體系統表現的關鍵影響。

**Q15：有哪些值得期待的未來研究方向？**
A：未來研究可以將 DeepSearch-World 擴展到動態或多模態網頁環境，並整合更強大的自動驗證機制來處理非結構化觀察。另一個方向是結合自我蒸餾與強化學習，利用已驗證的過程訊號作為密集獎勵，形成混合式監督架構。此外，將此方法擴展到更大規模的模型、更多樣化的工具套件，以及更廣泛的領域知識庫，也有助於進一步驗證可驗證自我演化在通用代理訓練中的可擴展性。

### 適用場景

1. **企業內部知識問答與決策輔助**  
   將公司內部文件（技術文件、產品規格、會議紀錄）建構成離線知識庫，讓深度搜尋代理執行多跳問答，協助員工追蹤專案進度、比對合約條款或查找跨部門資訊。

2. **金融與法律盡職調查**  
   在確定性且可驗證的環境中，讓代理依序檢索公司關係圖、財報、訴訟記錄與監管文件，並透過過程層級監督確認每一步證據是否正確，降低遺漏關鍵資訊的風險。

3. **學術研究助理**  
   針對特定領域文獻建立離線語料庫，代理可自動進行主題擴展、引用追蹤與實驗比較，並在發現檢索結果不匹配時執行查詢重寫與失敗恢復。

4. **客戶支援自動化**  
   把常見問題、產品手冊與歷史工單轉為可搜尋的離線環境，讓工具使用代理在多輪對話中查證事實、比對錯誤碼，並給出可追蹤來源的答案。

5. **內部 IT 與維運排查**  
   將系統日誌、Runbook、架構圖與事件記錄對齊為結構化語料，代理可依症狀逐步檢索可能原因、驗證中間假設，並在錯誤時回滾重新推理。

- 可平行進行軌跡生成與訓練的非同步運算資源，因為自我蒸餾需要反覆產生、過濾、混合資料。

- 熟悉 LLM 微調、ReAct 格式與工具呼叫設計。

- 能設計過程層級驗證邏輯與評估指標，並監控長程互動中的錯誤傳播。

### 實作步驟建議

1. **建構可驗證的離線環境**  
   將領域語料轉為確定性搜尋與頁面閱讀工具，確保相同查詢與動作總是回傳相同結果，並為每個中間步驟設計可驗證訊號。

2. **產生對齊的多跳問答任務池**  
   參考實體層級隨機遊走方法，從知識圖譜中產生需要跨文件推理的任務，並確認所需證據都能在離線語料中檢索到。

3. **設計鷹架式教師代理**  
   讓教師模型在 rollout 時顯式追蹤進度、證據、失敗嘗試與恢復過程，產生包含規劃、記憶、基於事實的反思與回滾行為的鷹架軌跡。

4. **鷹架轉 ReAct 轉換**  
   將結構化鷹架軌跡轉為標準 ReAct 格式，使學生模型能學習到可執行的思考—行動序列，同時保留過程監督資訊。

5. **執行迭代自我蒸餾迴圈**  
   反覆進行：(a) 使用目前模型生成軌跡；(b) 以驗證訊號過濾成功軌跡；(c) 透過重要性取樣進行資料混合；(d) 對學生模型執行 SFT。

6. **驗證與行為分析**  
   在保留的驗證集上評估最終答案正確率、工具使用效率、平均互動長度與失敗恢復率，必要時調整驗證訊號與資料混合比例。

7. **產品化部署與監控**  
   將訓練好的模型包裝為 API，加入查詢限制、來源引用與人機協作介面，並持續收集真實互動資料以進行下一輪自我演化。

### 潛在風險與注意事項

| 風險 | 說明 | 因應方式 |
|---|---|---|
| **離線到真實網頁的分布偏移** | 確定性環境與即時網頁環境的檢索結果不同，模型上線後可能表現下滑。 | 上線前在真實網頁基準（如 BrowseComp、GAIA）測試，並保留查詢重寫與容錯機制。 |
| **驗證訊號被鑽漏洞** | 代理可能學會滿足驗證條件但答案不正確的捷徑。 | 設計多維度驗證（答案正確性、證據覆蓋率、工具使用合理性），並定期人工抽檢。 |
| **災難性遺忘** | 反覆自我蒸餾可能讓模型遺忘通用能力或早期學到的成功模式。 | 使用重要性取樣的資料混合，保留歷史高品質軌跡與通用語料。 |
| **運算成本膨脹** | 長程軌跡生成與反覆 SFT 需要大量 GPU 與儲存資源。 | 先以小規模任務池驗證流程，再逐步擴展；使用非同步生成與低精度訓練加速。 |
| **語料版權與隱私** | 內部或第三方語料可能涉及敏感資訊或授權限制。 | 在離線環境中做好去識別化與存取控管，並確認語料使用符合法規。 |

### 與其他技術的整合建議

- **與 RAG 系統整合**：將 DeepSearch-World 的離線搜尋工具視為可驗證的檢索層，與現有向量資料庫或關鍵字索引互補，提升多跳推理時的召回與可解釋性。
- **與強化學習或 RLHF 整合**：在自我蒸餾產生高品質軌跡後，可進一步使用稀疏結果獎勵或人類偏好進行微調，彌補 SFT 在探索新策略上的不足。
- **與企業知識庫 / CRM 整合**：透過標準化工具介面（如 REST API、MCP）讓代理查詢內部系統，並將答案與來源連結回傳給前端應用。
- **與即時網頁 API 整合**：在離線環境訓練完成後，可將模型遷移到受控沙箱或即時搜尋 API，並以離線驗證邏輯作為安全檢查層。
- **與可觀測性平台整合**：記錄每個工具呼叫、反思步驟與回滾事件，方便除錯、審計與後續迭代。

**研究人員**：建議深入分析確定性且可驗證環境的設計原理、實體層級隨機遊走如何產生可擴展的多跳問答任務，以及自我蒸餾與現有 GRPO 式強化學習在收斂性與穩定性上的差異。

**產品經理**：優先關注適用場景、BrowseComp / GAIA / HotpotQA 等評估結果所代表的產品能力邊界，以及運算成本、資料準備與上線風險，再評估是否值得投入建構自有離線環境或等待開源釋出的模型與程式碼。
