CARTBench 的方法論設計圍繞兩個核心障礙展開：**資料稀缺 (Data Scarcity)** 與**標準化評分規準的困難 (Difficulty Standardizing Criteria)**。整體方法論可拆解為四個相互耦合的環節：資料策展、原則蒸餾、評分規準實例化、以及原則引導式提示。

**資料策展層面**，作者並未採用合成資料或爬蟲公開頁面，而是直接從**商業購物需求 (Commercial Shopping Needs)** 中策展 CART 案例。這種做法確保了**需求有效性 (Need Validity)** 與**意圖準確度 (Intent Accuracy)** 的真實性——案例中的需求確實來自真實消費者，而非研究者臆測。透過**分層抽樣 (Stratified Sampling)** 涵蓋 17 個常見**零售領域 (Retail Domains)**，並將**時間戳對話 (Timestamped Dialogue)** 與 1,603 筆**產品紀錄 (Product Records)** 配對。時間戳的保留至關重要：它使評測能區分「歷史需求是否仍適用」與「未確認的偏好是否被合理保留」，這是過往基準如 WebShop、EComAgentBench 等所缺乏的維度。

**原則蒸餾層面**，作者提出**理想回應原則 (Ideal Response Principles)**，這是方法論中最具巧思的設計。原則的來源是「從**成功完成的訂單 (Successfully Completed Orders)** 中人工挑選的優秀回覆」，由專家進行歸納蒸餾。這種「由實證回溯到原則」的路徑，與傳統「由理論推導到 checklist」的做法相反，其優勢在於原則能反映真實商業場景中被消費者接受的回應模式，而非研究者主觀設定的理想化標準。原則同時承擔兩個功能：(1) 維持跨案例評分規準的一致性；(2) 透過**原則引導式 CART 提示 (Principle-Guided CART Prompting)** 引導受測模型產生符合原則的回覆。

**評分規準實例化層面**，每個案例配備**案例專屬評分規準 (Case-Specific Rubrics)**，分為三層：**核心 (Core)** 檢核必要行為、**卓越 (Excellence)** 獎勵超越必要行為的高品質建議、**安全 (Safety)** 檢核案例特有的推薦風險。這種三層結構呼應了論文中 Figure 1 的待產包案例：核心檢核「保留衣物、延後大量採購」等必要行為；卓越檢核「標記套組內容物衝突」等進階建議；安全檢核「不推斷健康狀態、不開立處方」等風險防範。值得注意的是，評分規準對受測模型隱藏 (frozen rubrics)，僅提供原則，這避免了資料洩漏並模擬真實部署情境。

**診斷方法論層面**，作者並未止步於整體分數，而是對失敗案例進行**共享失敗模式 (Shared Failure Modes)** 的歸因分析，識別出兩大主要失效路徑：**產品證據 (Product Evidence)** 的缺失與**未解決的需求 (Unresolved Needs)**，並將其連結到**變動中的需求 (Changing Requirements)** 與**決定性未知項 (Decisive Unknowns)**。這種由分數到根因的分析鏈條，使基準不僅是排名工具，更是診斷工具。

方法論的潛在限制在於：原則蒸餾仰賴「成功訂單中的優秀回覆」，這隱含選擇偏差——成功訂單的回覆未必是最佳回覆，可能僅是「夠好」的回覆。此外，案例專屬評分規準的撰寫成本高昂，1,328 條規準的專家標註工作量限制了基準的可擴展性。

#### 實驗數據解讀

**全套評估 (Full-Suite Evaluation)** 的核心數據揭示了一個戲劇性的不對稱：在**凍結評分規準 (Frozen Rubrics)** 協議下，10 個受測模型中有 3 個在**核心 (Core)** 維度超過 90%，但**沒有任何模型**在**卓越 (Excellence)** 維度超過 45%。這個 90% vs. 45% 的落差是論文最關鍵的經驗發現，也是「**理解到執行的落差 (Understanding-to-execution gap)**」一詞的數據基礎。

**核心維度的高分表現**說明：當代旗艦模型（包含 GPT-6.1-Sol、Claude-Opus-5 等**旗艦商業 API 模型 (Flagship Commercial API Models)**，以及 35B+ 參數的**開放權重模型 (Open-Weight Models)**）已能可靠地執行 CART 場景中的必要行為——例如保留未確認條件、標記衝突資訊、不跨越安全邊界。這反映出現有 LLM 在「遵循明確指令」上的成熟度。

**卓越維度的低分天花板**則暴露了更深層的問題：模型能「做對必要的事」，卻難以「提供超越必要的高品質購物決策建議」。卓越維度要求的並非額外的指令遵循，而是需要模型主動進行**證據檢核 (Evidence Check)**、**適配依據 (Fit Basis)** 的推理、以及對**未解決的需求 (Unresolved Needs)** 的細緻處理。這類任務需要模型在「不確定性下做出有依據的條件式判斷」，而非簡單的指令匹配。

**診斷層面的數據**進一步指出，共享失敗集中在兩個維度：(1) **產品證據 (Product Evidence)**——模型傾向於給出概括性推薦，卻未引用具體產品屬性或描述中的證據來支撐判斷；(2) **未解決的需求 (Unresolved Needs)**——模型傾向於「填補空白」，對**決定性未知項 (Decisive Unknowns)** 做出未經驗證的假設，而非保留為開放狀態。這兩類失敗與**變動中的需求 (Changing Requirements)** 相互強化：當需求隨時間變化時，模型既無法及時更新其證據基礎，也無法正確處理隨之產生的新未知項。

從 Figure 1 的待產包案例可看出這種失敗模式的具體形態：模型可能正確建議「保留衣物、延後採購」（核心通過），卻未能進一步指出套組內容物存在衝突需實際驗證（卓越失敗），或未明確標示「不進行健康評估」的邊界（安全風險）。這說明模型在「必要行為」與「高品質建議」之間存在系統性的能力斷層。

實驗設計的一個值得注意的細節是：模型僅獲得原則，不獲得評分規準。這模擬了真實部署中模型無法窺見評審標準的情境，使評測結果更貼近實際應用表現。然而，這也意味著模型表現可能受提示工程影響——若不同模型對原則的解讀能力不同，分數差異可能部分反映提示遵循能力而非購物建議品質。

#### 與現有研究的比較

CARTBench 在購物基準生態系中的定位可從 Table 1 的比較表清楚看出。相較於七個現有基準（WebShop、EComAgentBench、ShoppingComp、Shopping Reasoning Bench、MMShopBench、PACEShop、RealWorldShop），CARTBench 是唯一在所有九個維度都達到完整覆蓋 (✓) 的基準。

**相對優勢**體現在三個先前基準普遍缺失的維度：

第一，**時限 (Timeline)** 維度。過往基準均未明確將時間戳或經過時間納入評測，這使得基準無法判斷「建議是否回應了已過期的需求」。Figure 1 的案例清楚展示：13 Jan 的禮物需求在 15 Jan 已過期，模型若未察覺時限變化，可能繼續推薦禮物而非轉向待產包準備。CARTBench 透過保留時間戳對話，使這類時序推理成為可評測的能力。

第二，**保留未知項 (Unknowns Preserved)** 維度。ShoppingComp 雖檢核適配性，但僅針對已陳述需求；對於**未確認的偏好 (Unconfirmed Preferences)** 與**開放的未知項 (Open Unknowns)**，過往基準無法區分「幸運猜測 (Lucky Guess)」與「有依據的條件式回答 (Justified Conditional Answer)」。CARTBench 透過卓越維度明確獎勵「保留未知項」的行為，這是評測理念上的重要進展。

第三，**逐案評分規準 (Per-Case Rubrics)** 維度。過往基準多採用共享 checklist，但論文的 Figure 1 案例清楚說明：即使是同一零售領域（如嬰兒用品），不同案例的檢核重點也截然不同——待產包案例需檢核「套組內容物衝突」，而其他嬰兒用品案例可能需檢核「年齡分級標示」。共享 checklist 無法捕捉這種案例間的差異，案例專屬評分規準則能精確對應每個場景的獨特需求。

**相對限制**同樣值得審視：

第一，**規模限制**。1,328 條專家標註規準雖然品質高，但規模遠小於 WebShop 等基於爬蟲的大規模基準。這限制了統計檢定的 power，也使基準難以支援細粒度的子群體分析（如按零售領域、按時限長度分組的表現差異）。

第二，**評分規準的撰寫成本**。每個案例需專家撰寫案例專屬評分規準，這種「重質不重量」的策略雖然提升了評測效度，卻也使基準難以快速擴展或適應新興零售場景。

第三，**原則的普適性**。**理想回應原則 (Ideal Response Principles)** 蒸餾自成功訂單，可能內嵌了特定商業模式或文化脈絡的偏見。例如，「保留未知項」在某些文化中可能被視為不夠果斷的建議風格。基準的跨文化適用性有待驗證。

第四，**模型覆蓋的時效性**。論文中提及 GPT-6.1-Sol 與 Claude-Opus-5 等模型，這些是 2026 年的旗艦模型。基準的結論是否能在下一代模型中維持，仍是開放問題——若新模型在卓越維度突破 45% 天花板，將直接挑戰「理解到執行的落差」的持久性論述。

**資料層面**，1,603 筆產品紀錄、17 個零售領域的案例、以及 1,328 條**專家標註評分規準 (Expert-Annotated Criteria)** 的釋出，使其他研究者能完整重現評測環境。**時間戳對話 (Timestamped Dialogue)** 的保留尤其重要，因為時序資訊是 CART 評測的核心維度，缺少時間戳將使基準退化为普通購物基準。

**程式碼層面**，評測流程的開源使其他研究者能：(1) 在新模型上重現論文的分數報告；(2) 修改提示模板以測試**原則引導式 CART 提示 (Principle-Guided CART Prompting)** 的敏感性；(3) 對評分規準進行版本管理與迭代。然而，論文中提及的 GPT-6.1-Sol 與 Claude-Opus-5 等商業 API 模型屬於付費服務，其輸出可能隨版本更新而變化，這對長期可重現性構成挑戰——論文中使用「frozen rubrics」但未明確說明是否使用「frozen model versions」。

**評分規準層面**，案例專屬評分規準的釋出使評測過程透明化，但同時也帶來「訓練-測試洩漏」的潛在風險：若未來模型在訓練過程中接觸到這些評分規準，將嚴重污染評測效度。論文中「評分規準對受測模型隱藏」的設計緩解了這一風險，但無法防止基準資料被納入未來模型的預訓練資料。

**限制層面**，以下要素的可重現性仍不明確：(1) 蒸餾**理想回應原則 (Ideal Response Principles)** 的具體流程——論文中描述了原則的來源（成功訂單中的優秀回覆），但未詳細說明蒸餾的具體程序（如專家人數、迭代輪數、衝突解決機制）；(2) 專家標註的品質控制流程——1,328 條規準的標註者間一致性 (inter-annotator agreement) 未在論文中報告；(3) 商業 API 模型的完整提示模板與超參數設定。這些「程序性細節」的缺失，使基準的「完全可重現」與「原則可重現」之間存在差距。

#### 未來研究方向

CARTBench 開啟的研究議題可從四個方向延伸。

**第一，能力斷層的神經機制研究**。「**理解到執行的落差 (Understanding-to-execution gap)**」的發現引出一個根本問題：為何模型能正確識別「應保留未知項」（核心），卻無法主動產生「標記套組內容物衝突」（卓越）？這是否反映 Transformer 架構在「被動遵循指令」與「主動證據推理」之間的能力分化？未來研究可透過注意力視覺化、探針任務 (probing tasks) 等方法，定位卓越維度失敗的內部表徵層次。

**第二，時序推理的形式化**。CARTBench 將**時限 (Timeline)** 引入購物評測，但時序推理的形式化仍處於早期階段。未來工作可探索：(1) 將時序邏輯 (temporal logic) 引入評分規準，使「需求過期」的判斷可形式化驗證；(2) 構建時序敏感的合成基準，以系統性測試模型在不同時限長度、不同需求變化頻率下的表現；(3) 將時序維度擴展至其他領域（如醫療建議、法律諮詢），檢驗「理解到執行的落差」是否為跨領域的普遍現象。

**第三，**保留未知項 (Unknowns Preserved)** 的對齊研究**。現有 LLM 對齊方法（如 RLHF）傾向獎勵「自信且完整」的回答，這與「保留未知項」的原則存在張力。未來研究可探索：(1) 設計專門獎勵「適度保留」的獎勵函數；(2) 構建「未知項識別」的中間訓練任務，使模型在最終回答前先進行未知項盤點；(3) 探討「保留未知項」與「使用者滿意度」之間的實證關係——消費者是否真的偏好「保留未知項」的回覆，還是偏好「果斷推薦」？

**第四，**產品證據 (Product Evidence)** 的檢核機制**。論文的診斷指出，模型傾向於給出概括性推薦卻未引用具體證據。未來工作可從三個路徑推進：(1) 構建「證據鏈結 (evidence linking)」的中間任務，要求模型在生成推薦時必須引用產品描述中的具體片段；(2) 探索檢索增強生成 (RAG) 與購物建議的深度整合，使模型能動態查詢產品資料庫；(3) 設計「證據完整性」的自動評測指標，減少對人工評分規準的依賴。

**第五，跨文化與跨領域泛化**。CARTBench 的案例來自特定商業脈絡，其**理想回應原則 (Ideal Response Principles)** 可能內嵌文化偏見。未來研究可：(1) 在不同文化市場（如歐美、東亞、中東）重複實驗，檢驗原則的普適性；(2) 將 CART 框架擴展至非購物領域（如旅遊規劃、醫療諮詢），檢驗「複雜且模糊的時限請求」是否為跨領域的通用挑戰；(3) 構建多語言版本的 CARTBench，測試模型在跨語言購物建議中的表現差異。

**第六，基準的動態演化機制**。隨著模型能力提升，現有評分規準可能會「過時」——曾經是卓越維度的要求，可能在下一代模型中成為核心維度的基本能力。未來工作可探索「動態評分規準」機制：根據模型表現自動調整卓越維度的難度，使基準始終保持鑑別力。這類似於教育測驗中的「難度校準」概念，但應用於 LLM 評測。

A：CARTBench 的更廣泛影響在於它推動了「對話式推薦評測」從「功能正確性」邁向「決策可靠性」的典範轉移。傳統基準多關注模型能否推薦「對」的產品，但 CARTBench 強調推薦的時效性、條件性與安全性，這更貼近真實商業決策的本質。此外，「原則共通、規準個案化」的雙層評測設計為其他領域（如醫療、法律諮詢）的對話評測提供了可遷移的方法論框架。從產業角度，CARTBench 的結果提醒從業者：即使是旗艦模型，在高品質購物建議上仍有顯著改進空間，這為專注於對話品質與決策支援的差異化產品創造了市場機會。

**Q13：CARTBench 自身存在哪些已承認的限制？**

**Q15：基於 CARTBench 的發現，未來有哪些值得探索的研究方向？**

A：基於 CARTBench 的發現，未來研究可朝幾個方向探索。第一，針對「理解到執行的落差」，可研究如何讓模型在理解 Core 要求後，更有效地將其轉化為 Excellence 級別的建議，例如透過推理增強、反思機制或多步驟規劃。第二，針對「產品證據」失敗，可探索更結構化的產品資訊引用方法，例如強制模型引用產品描述的具體欄位，或結合檢索增強生成（RAG）來強化證據基礎。第三，針對「未解決需求」失敗，可研究如何讓模型更精準地識別「決定性未知項」並以條件式語言回應，而非給出過度確定的建議。第四，「原則引導式提示」的成功顯示原則工程（principle engineering）作為新興研究方向值得系統化探索。最後，將 CARTBench 的「原則共通、規準個案化」設計遷移至醫療、法律、教育等其他高風險對話領域，將是極具價值的研究路線。
