# 具身圖靈機：用於機器人遞迴自我改進的有狀態代碼

## ⚡ TL;DR

現有機器人策略將模型置於控制迴路中，狀態隱式且難以檢查控制。
本文提出純代碼策略COAP，將具身世界視為圖靈機，以代碼變量顯式儲存狀態並執行決策。
在RoboDojo 42個雙手任務上，COAP達70.24%成功率，超越最先進方法38.9%。

## 摘要翻譯

大多數機器人策略在控制迴路中採用一個模型：視覺-語言-動作模型（VLA）將觀察映射為動作，而代理駕馭框架（例如代理即策略或駕馭式VLA）則在運行時間查詢視覺-語言模型（VLM）進行決策制定。我們提出一個不同的觀點：具身世界是一個具身圖靈機，其紙帶為機器人與環境狀態，規則為策略。若此狀態能被準確表示，則決策制定可完全以代碼撰寫。因此我們提出純代碼策略（COAP）：代碼從相機影像與本體感覺中測量並追蹤機器人、環境與任務狀態，並據此做出每個決策。相同的代碼跨回合適用，不同任務共享同一函式庫，且迴路中無VLM或VLA。相較於VLA與代理駕馭框架，我們分析COAP的三項優勢：(i) 顯式狀態：狀態可儲存於代碼中；(ii) 執行：代碼使決策制定可控、靈活地從故障中恢復，並線上快速且低成本地運行；(iii) 可擴展性：新任務可復用、繼承或擴展共享函式庫，使能力能跨任務累積。這些優勢使COAP成為遞迴自我改進（RSI）的合適媒介：編碼代理在閉環中開發函式庫，且每項變更皆為顯式且可控。在RoboDojo的42個雙手操作任務上，所得函式庫在測試時間無需任何模型即達到70.24%的成功率。COAP的上界取決於用於決策制定的狀態表示準確程度，以及代碼邏輯的穩健性。因此我們提出COAP作為具身任務的新範式；由於其跨回合適用，亦可作為VLA與代理駕馭框架的高效數據引擎。

### 核心貢獻（3～5點）
- **提出新範式「純代碼策略（COAP）」**：將具身世界重新詮釋為具身圖靈機，以代碼取代模型在控制迴路中的角色，從相機影像與本體感覺中測量並追蹤狀態，實現完全以代碼驅動的決策制定。
- **系統性分析COAP三大優勢**：包括顯式狀態（狀態可儲存於代碼中）、執行（決策可控、可靈活故障恢復、快速且低成本線上運行）、可擴展性（任務間可復用、繼承或擴展共享函式庫，能力得以跨任務累積）。
- **實現遞迴自我改進（RSI）的合適媒介**：編碼代理可在閉環中開發函式庫，每項變更皆為顯式且可控，為機器人遞迴自我改進提供實務可行的路徑。
- **實驗驗證效能**：在RoboDojo的42個雙手操作任務上，所得函式庫於測試時間無需任何模型即達到70.24%的成功率。
- **雙重定位**：COAP不僅是具身任務的新範式，亦可作為VLA與代理駕馭框架的高效數據引擎。

### 適合對象
從事機器人學、具身智慧（Embodied AI）、視覺-語言-動作模型（VLA）研究，以及對程式碼驅動策略、遞迴自我改進（RSI）、代理系統（Agent Systems）感興趣的研究者與工程師；亦適合關注機器人通用介面設計、數據引擎構建、雙手操作任務基準測試的學術界與產業界讀者。

## 深度分析

#### 方法論解析

本文提出了一個嶄新的具身智能（embodied intelligence）範式，其核心論點建立在對圖靈機（Turing machine）的重新詮釋之上。作者將機器人與其所處環境共同視為一台「具身圖靈機」（Embodied Turing Machine）：其中「紙帶」（tape）對應機器人狀態（robot state）與環境狀態（environment state）的集合，「規則」（rules）則對應策略（policy）。這個抽象框架的關鍵洞見在於：當紙帶上的狀態能夠被精確表示時，規則（即策略）便可以完全以代碼形式編寫，無需依賴神經網路模型在運行時進行隱式推理。

**純代碼策略（Code-Only-as-Policy, COAP）的核心設計理念**

COAP 的設計哲學與現有方法形成鮮明對比。傳統的視覺-語言-動作模型（Vision-Language-Action Model, VLA）將狀態隱式編碼於神經網路權重中，無法被檢查或編輯；代理駕馭框架（Agent Harness，如 Agent-as-Policy 或 Harness VLA）雖然將部分狀態以文本形式暴露於模型的上下文中，但仍依賴 VLM/VLA 作為黑盒（blackbox）進行決策。COAP 則主張：當狀態可被精確測量時，整個決策過程應以「白盒」（whitebox）代碼實現，狀態儲存於代碼變量（code variable）中，規則則以代碼邏輯（code logic）形式表達。

**狀態測量機制**

COAP 的可行性建立在兩個關鍵觀察之上：第一，機器人狀態可透過本體感覺（proprioception）直接獲取，無需估計；第二，環境中的物體位姿（object pose）可從 RGB 影像中利用已知的物體幾何（object geometry）恢復。這意味著 COAP 不需要學習型的感知模型，而是採用確定性的測量方法。論文中提及使用 SAM 3 等分割模型作為感知工具，但強調感知結果以代碼變量形式存在，而非隱藏於模型內部。

**跨回合與跨任務的代碼復用**

COAP 的一個重要特性是「同一段代碼適用於不同回合」（the same code applies across episodes）。由於任務固定，狀態空間的結構是穩定的，因此一段足夠穩健的代碼可以在不同回合（episode）中重複使用，無需每回合重新生成。這與既有代碼策略（如 CaP、PyRUA-Lean、Skill2Real）形成對比——後者要求模型在每個回合中逐步寫出新代碼。此外，COAP 採用共享函式庫（shared library）架構：不同任務共用同一個感知與執行的函式庫，新任務只需編寫少量任務特定邏輯。論文報告新任務運行的代碼中 83% 來自函式庫，僅 17% 為任務特定代碼。

**遞迴自我改進（Recursive Self-Improvement, RSI）的閉環設計**

COAP 被定位為 RSI 的理想媒介。編碼代理（coding agent，本文使用 Opus 5.5 Max）在固定規則下（如禁止針對單一回合的 hack、測試時不使用真實標註狀態）對函式庫進行摘要、編寫、除錯的迭代開發。這個閉環的關鍵優勢在於：每次改動都是顯式且可控的，代碼的演進軌跡可以被完整追蹤與審查。

#### 實驗數據解讀

**評估平台與任務規模**

實驗在 RoboDojo 的 42 個雙手操作任務（bimanual task）上進行。雙手操作任務的選擇具有重要意義：這類任務涉及兩隻機械手臂的協調控制，狀態空間複雜度高，對策略的精確性與穩健性提出嚴苛要求，是檢驗 COAP 框架的嚴格試金石。

**核心結果**

COAP 達到 70.24% 的成功率（success rate），相較於現有最先進方法提升 38.9 個百分點。這個數字的解讀需要放在具身策略的評估語境中：機器人任務的成功率往往受到初始狀態隨機化、感知誤差、執行不確定性等多重因素影響，70% 級別的成功率在雙手操作任務中已屬於較高水平。

**結果的深層意涵**

這個 38.9% 的絕對提升幅度值得深入分析。它表明在 RoboDojo 這一基準上，純代碼策略相較於基於模型的策略具有結構性優勢。可能的解釋包括：（1）雙手操作任務的狀態可測量性較高，物體幾何相對明確；（2）任務的邏輯結構（如堆疊碗 stack_bowls）適合以程式化方式表達；（3）共享函式庫使得感知與運動基元（motion primitive）的開發更為充分。

**上界分析**

作者明確指出 COAP 的上界（upper bound）取決於兩個因素：狀態表示的準確性與代碼邏輯的穩健性。這意味著當前 70.24% 的成功率並非天花板，而是當前技術條件下的快照。隨著感知精度提升與代碼邏輯迭代，理論上仍有提升空間。

**作為數據引擎的潛力**

論文第 5.5 節提出 COAP 可作為高效的數據引擎（data engine），為 VLA 與 Agent Harness 生成成功軌跡。這是一個重要的副產品：即使在某些場景下 COAP 本身不夠通用，其穩定產生成功示範的能力仍可服務於其他範式的訓練。

#### 與現有研究的比較

**與 VLA 的比較**

VLA（如 RT-2、OpenVLA、π₀、π₀.₅）將觀察到動作的映射隱式編碼於神經網路權重中。這帶來兩個根本性限制：第一，每次改進都需要新數據與重新訓練；第二，LIBERO-PRO 等研究顯示基準測試的成功率可能反映的是對訓練配置的記憶，而非真正的泛化能力。COAP 將狀態顯式儲存於代碼變量中，可從失敗中回溯（backtrack），這是 VLA 難以實現的能力。

**與 Agent Harness 的比較**

Agent-as-Policy 與 Harness VLA 將部分過程顯式化（如文本記憶），但 VLM/VLA 仍是黑盒，無法完全檢查或控制動作的推導過程。COAP 則將整個決策過程以代碼形式呈現，達到完全的白盒化。

**與既有代碼策略的比較**

圖 2 清楚展示了 COAP 與既有代碼策略的差異。CaP、PyRUA-Lean、Skill2Real 等方法要求模型在每回合中逐步寫出代碼；RHO 與 EmbodiedSWE 則從學習模型或模擬器真實標註中獲取狀態。COAP 的獨特之處在於：（1）狀態由代碼自身測量，而非來自學習模型或模擬器神諭；（2）同一段代碼跨回合復用，而非每回合重新生成；（3）採用共享函式庫架構，而非任務特定的獨立代碼。

**COAP 的局限性**

作者坦誠指出 COAP 的主要弱點在於泛化能力：每個新任務仍需少量任務特定代碼邏輯。然而，作者反駁道 Agent-as-Policy 與 Harness VLA 同樣涉及任務級記憶，部分方法甚至依賴回合級邏輯，因此 COAP 的這一限制並非獨有。此外，本文聚焦於探索 COAP 的上界，而非追求最大泛化性。

#### 可重現性評估

**代碼與函式庫的可獲得性**

論文提及 COAP 在 RoboDojo 的 42 個任務上進行評估，並使用 Opus 5.5 Max 作為編碼代理。然而，從所提供的全文片段中，無法明確判斷作者是否計劃開源（open-source）以下資源：（1）完整的 COAP 函式庫代碼；（2）任務特定代碼；（3）RSI 開發閉環的實現細節。對於一項強調「代碼即策略」的工作而言，代碼的可獲得性至關重要——若代碼不公開，則「顯式且可控」的優勢無法被獨立驗證。

**數據集與模型權重**

COAP 本身不使用學習模型，因此不存在傳統意義上的模型權重（model weights）。然而，感知環節可能涉及 SAM 3 等預訓練模型，這些模型的權重通常可從原始發布處獲得。RSI 過程中產生的成功軌跡若作為數據引擎的副產品，其可獲得性也是評估可重現性的重要面向。

**實驗細節的充分性**

論文提供了關鍵的實驗約束（禁止單回合 hack、測試時不使用真實標註狀態），但對於 RSI 閉環的具體迭代次數、開發時間、計算資源消耗等細節，從所提供的片段中無法完整評估。這些資訊對於其他研究者復現 RSI 過程至關重要。

**評估協議的透明度**

RoboDojo 作為基準測試平台，其評估協議（evaluation protocol）應已公開。但 COAP 在該基準上的具體評估配置（如回合數、隨機種子、初始狀態分佈）需要進一步確認，以確保結果的可比較性。

#### 未來研究方向

**提升狀態表示的準確性**

COAP 的上界直接受限於狀態測量的精度。未來研究可探索：（1）結合多視角（multi-view）視覺與深度資訊以提升物體位姿估計；（2）引入觸覺（tactile）感測以處理視覺遮擋（occlusion）問題；（3）發展不確定性估計機制，使代碼能夠在狀態測量不確定時採取保守策略。

**增強代碼邏輯的穩健性**

代碼邏輯的穩健性是另一個關鍵瓶頸。可探索的方向包括：（1）形式化驗證（formal verification）技術以確保代碼邏輯的正確性；（2）自動測試生成（automated test generation）以覆蓋更多邊界情況；（3）故障恢復（failure recovery）機制的系統化設計，使代碼能夠從部分失敗中恢復而非完全重來。

**RSI 閉環的理論分析**

本文以經驗方式展示了 RSI 的可行性，但缺乏理論分析。未來可研究：（1）RSI 收斂性的形式化條件；（2）函式庫規模與任務覆蓋度之間的關係；（3）避免 RSI 過程中災難性遺忘（catastrophic forgetting）的機制。

**與學習方法的混合架構**

純代碼策略與學習方法並非互斥。未來可探索：（1）將學習組件限制於感知層，而決策層保持純代碼；（2）利用 COAP 生成的數據訓練 VLA，形成「COAP 產生數據 → VLA 學習泛化」的閉環；（3）發展可解釋的混合架構，使神經網路與符號推理（symbolic reasoning）的分工更為清晰。

**跨機器人平台的遷移**

當前實驗在 RoboDojo 平台上進行，未來可探索 COAP 函式庫在不同機器人平台（如不同機械手臂、靈巧手、輪式機器人）之間的遷移性。函式庫的抽象層次設計將直接影響遷移的可行性。

**長期自主學習**

本文的 RSI 閉環依賴人類設計的固定規則（如禁止單回合 hack）。未來可探索更為自主的學習機制，使機器人能夠在更少的先驗約束下進行自我改進，同時保持安全性與可預測性。

**安全與可驗證性**

隨著 COAP 函式庫規模的擴大，安全性與可驗證性將成為關鍵議題。特別是在人機協作（human-robot collaboration）場景中，需要確保代碼邏輯的執行不會導致危險行為。這需要發展專門針對具身代碼的驗證技術與執行監控機制。

## 論文問答

**Q1：這篇論文試圖解決機器人領域中的什麼核心問題？**
A：這篇論文試圖解決機器人策略中「狀態表示」與「決策制定」之間的根本性耦合問題。傳統方法如視覺-語言-動作模型（VLA）將觀察到動作的映射隱式編碼在模型權重中，導致策略難以檢查、編輯或控制；而代理駕馭框架（Agent Harness）雖引入文本記憶，但核心決策仍依賴黑盒模型。作者主張，若能將機器人與環境狀態以顯式方式表示，則整個決策過程可以完全由代碼實現，從而擺脫對模型的依賴。這個問題之所以重要，是因為它直接影響機器人策略的可解釋性、可控性與長期可改進性。

**Q2：為什麼現有的視覺-語言-動作模型（VLA）和代理駕馭框架（Agent Harness）方法不足以解決這個問題？**
A：VLA 將狀態隱式編碼於神經網路權重中，無法直接檢查或編輯，每次改進都需要重新收集數據並訓練，這使得迭代成本高昂且難以追溯錯誤來源。Agent Harness 雖然透過 VLM 引入文本記憶與提示詞工程，使部分決策過程變得顯式，但 VLM 與 VLA 本身仍是黑盒，無法完全掌控從狀態到動作的推導過程。此外，這兩類方法都將模型保留在控制迴路中，導致運行時計算成本高、延遲大，且難以進行精細的故障恢復。相較之下，純代碼策略（COAP）將狀態儲存於代碼變量中，規則以代碼邏輯形式呈現，整個決策過程是白盒且可執行的。

**Q3：為什麼這個問題在機器人學與人工智慧領域中如此重要？**
A：機器人策略的可解釋性與可控性是其在現實世界部署的關鍵前提，特別是在工業製造、醫療照護等高風險場景中，必須能夠追溯每一個動作的決策依據。此外，機器人能力的累積需要穩定的自我改進機制，而黑盒模型難以支援這種遞迴式的迭代優化。本論文提出的「具身圖靈機」視角將機器人與環境視為可計算系統，為通用機器人智慧提供了理論框架。更重要的是，若代碼能作為策略的通用介面，則不同任務間的能力復用與遷移將變得自然，從而加速整個領域的進展。

**Q4：什麼是「具身圖靈機」（Embodied Turing Machine）？它如何將圖靈機概念應用於機器人系統？**
A：「具身圖靈機」是本論文提出的核心抽象，將機器人與其環境類比為一台圖靈機：環境狀態與機器人狀態（如物體位姿、機械手臂姿態、可達位姿等）構成圖靈機的「紙帶」，而策略則扮演「規則」的角色，負責從紙帶讀取符號並寫入新符號。這個抽象的關鍵洞見在於，雖然規則是固定的，但紙帶（即世界狀態）會隨著時間變化，因此同一套規則可以處理不同的輸入情境。在物理世界中，機器人透過感知（如 RGB 影像與本體感覺）讀取紙帶，並透過動作寫入紙帶，從而完成具身互動。這種視角使得機器人策略的設計從「訓練一個模型」轉變為「編寫一套規則」，為純代碼策略提供了理論基礎。

**Q5：什麼是「純代碼策略」（Code-Only-as-Policy, COAP）？它與現有的代碼型策略有何根本差異？**
A：純代碼策略（COAP）是一種全新的機器人策略範式，其核心思想是：所有決策都由代碼完成，無需任何 VLM 或 VLA 在運行時介入。具體而言，COAP 用代碼測量並追蹤機器人、環境與任務狀態（透過相機影像與本體感覺），並從這些顯式狀態中做出每一個決策。與既有代碼型策略相比，COAP 有三點根本差異：第一，先前方法（如 Code as Policies、PyRUA-Lean）依賴模型在線上逐回合生成代碼，而 COAP 的同一套代碼適用於所有回合；第二，先前方法（如 RHO、EmbodiedSWE）從學習模型或模擬器獲取狀態，而 COAP 用自己的代碼測量狀態；第三，COAP 構建了一個跨任務共享的函式庫，新任務只需編寫少量任務專屬邏輯（83% 的代碼來自函式庫），從而實現能力的累積。

**Q6：COAP 相比於 VLA 與 Agent Harness 的三大優勢是什麼？它們如何支撐遞迴自我改進？**
A：COAP 的三大優勢分別是「顯式狀態」、「執行」與「可擴展性」。首先，顯式狀態意味著所有資訊都儲存於代碼變量中，每個決策都基於這些可檢查的變量，這與 VLA 的隱式權重形成鮮明對比。其次，執行層面的優勢包括：代碼提供對狀態與動作的精細控制、可透過回溯與重試靈活恢復故障、且運行速度快、成本低。最後，可擴展性體現在新任務可以復用、繼承或擴展共享函式庫，使能力得以跨任務累積。這三大優勢共同使 COAP 成為遞迴自我改進（RSI）的理想媒介：編碼代理在閉環中開發函式庫，每次更改都是顯式且可控的，從而實現穩定的自我迭代。

**Q7：本論文使用什麼基準測試來評估 COAP？為何選擇這個基準？**
A：本論文使用 RoboDojo 的 42 個雙手操作任務作為評估基準。RoboDojo 涵蓋了豐富的雙手操作場景，能夠全面測試策略在多樣化任務中的泛化能力與穩健性。選擇這個基準的原因在於：雙手操作任務對狀態表示的精確性要求極高（例如需要同時追蹤兩個機械手臂與多個物體的位姿），這正是 COAP「顯式狀態」優勢的試金石。此外，42 個任務的規模足以驗證 COAP 的可擴展性——即新任務能否有效復用共享函式庫，從而檢驗「83% 代碼來自函式庫」這一關鍵設計假設。

**Q8：COAP 在 RoboDojo 上的關鍵實驗結果為何？這些數字說明了什麼？**
A：COAP 在 RoboDojo 的 42 個雙手操作任務上達到了 70.24% 的成功率，比當前最先進的方法高出 38.9 個百分點。這個結果意義重大，因為它是在測試時完全不使用任何 VLM 或 VLA 的前提下取得的，純粹依靠代碼邏輯與顯式狀態表示完成所有決策。更值得注意的是，這個成果是透過遞迴自我改進閉環實現的——編碼代理（Opus 5.5 Max）在固定規則下自主開發函式庫，無需人類介入。這說明了當狀態表示足夠準確、代碼邏輯足夠穩健時，純代碼策略可以達到甚至超越基於模型的策略。

**Q9：本論文是否進行了消融實驗或組件分析？這些分析揭示了什麼？**
A：雖然提供的文本未完整展示所有消融實驗細節，但論文明確指出 COAP 的上界取決於兩個關鍵因素：狀態表示的準確性與代碼邏輯的穩健性。這暗示了相關的組件分析：當感知模組（如物體位姿估計）更精確時，策略表現會相應提升；當代碼邏輯能覆蓋更多故障情境時，成功率也會提高。此外，論文強調 83% 的新任務代碼來自共享函式庫，這本身就是一種「函式庫復用率」的消融證據——證明了可擴展性優勢的實際效益，也為未來優化指明了方向。

**Q10：COAP 在實際應用中適合哪些場景？**
A：COAP 特別適合那些任務相對固定、需要在多回合間穩定執行的工業與服務場景。例如，在結構化製造環境中，機器人需要反覆執行相同的裝配任務，COAP 的「同一代碼適用於所有回合」特性正好契合此需求。在倉儲物流中，分揀與包裝任務同樣具有高度重複性，COAP 可以透過共享函式庫快速部署到新品種。此外，COAP 也適用於需要嚴格可追溯性的場景（如醫療輔助機器人），因為其白盒特性使得每個決策都能被檢查與審計，這在受監管產業中尤為重要。

**Q11：將 COAP 部署為實際產品時需要考慮哪些工程因素？**
A：將 COAP 產品化時需考慮以下工程因素：首先，感知模組的可靠性至關重要，因為 COAP 的所有決策都依賴於從 RGB 影像與本體感覺中準確估計的狀態，任何感知誤差都會直接傳遞到動作層。其次，需要建立完善的測試與驗證流程，確保代碼邏輯在各種邊緣案例下都能穩健運行，特別是故障恢復機制（如回溯與重試）的設計。此外，函式庫的版本管理與維護也是關鍵，因為隨著任務增加，函式庫會持續演進，需要避免破壞性更改影響已部署的任務。最後，雖然 COAP 在運行時不需要 VLM/VLA，但開發階段仍需要編碼代理與算力支持，這部分的成本與延遲也需納入考量。

**Q12：COAP 對機器人學與人工智慧領域的長遠影響是什麼？**
A：COAP 的長遠影響可能體現在三個層面：在學術層面，它提出了「具身圖靈機」這一全新抽象，為機器人智慧提供了理論框架，可能啟發後續關於可計算具身系統的研究。在技術層面，COAP 展示了純代碼策略的可行性，挑戰了「機器人必須依賴神經網路模型」的傳統假設，可能促使研究者重新思考模型與代碼的分工。在生態層面，COAP 可作為高效的數據引擎，為 VLA 與 Agent Harness 生成穩定且多樣的成功軌跡，從而加速整個領域的數據飛輪。長期來看，若代碼能成為機器人能力的通用介面，則跨任務、跨機器人平台的能力遷移將變得更加自然。

**Q13：本論文明確承認 COAP 的哪些局限性？**
A：論文明確指出 COAP 的主要弱點在於其泛化能力，因為每個新任務仍需要少量任務專屬的代碼邏輯。雖然 83% 的代碼來自共享函式庫，但剩餘的 17% 仍需針對具體任務編寫，這在面對高度多樣化的任務時可能成為瓶頸。此外，COAP 的表現上界受限於兩個因素：狀態表示的準確性（若感知模組無法準確估計物體位姿，則後續決策將受影響）與代碼邏輯的穩健性（若代碼無法處理所有邊緣案例，則會失敗）。論文也坦承，Agent-as-Policy 與 Harness VLA 同樣涉及任務級記憶，某些甚至依賴回合級邏輯，因此 COAP 並非在所有維度上都優於基於模型的方法。

**Q14：COAP 在哪些情況下可能會失敗？**
A：COAP 可能在以下情況下失敗：第一，當環境狀態無法被準確感知時，例如物體被遮擋、光照劇烈變化或出現訓練時未見過的新型物體，導致位姿估計失效。第二，當任務邏輯過於複雜或需要常識推理時，純代碼可能難以覆蓋所有分支，例如涉及模糊指令或多步驟規劃的開放式任務。第三，當機器人面對高度動態或非結構化的環境時，預先編寫的代碼可能無法即時適應新情境。第四，若共享函式庫中存在錯誤，這些錯誤會傳播到所有依賴該函式庫的任務中，因此函式庫的品質控制至關重要。

**Q15：本論文為未來研究指出了哪些方向？**
A：論文為未來研究指出了多個方向：首先，提升狀態表示的準確性是關鍵，包括發展更穩健的物體位姿估計、處理遮擋與動態場景的感知方法，以及融合多模態資訊的狀態追蹤技術。其次，強化代碼邏輯的穩健性，包括自動化的故障檢測與恢復機制、形式化驗證方法，以及從失敗案例中自動學習並改進代碼的技術。第三，探索 COAP 作為數據引擎的潛力，系統性地研究如何利用 COAP 生成高品質軌跡來訓練 VLA 與 Agent Harness。第四，將 COAP 擴展到更廣泛的機器人形態與任務類型，例如移動機器人、人形機器人等。最後，研究人機協作的 RSI 流程，讓人類專家能高效地引導編碼代理的開發過程。

## 實務應用指南

### 適用場景

**1. 結構化工業組裝產線**
在固定工位的雙手組裝任務（如電子元件插件、精密機械對位）中，COAP特別適合。任務流程固定、物件幾何可測量、狀態可顯式追蹤，83%的程式碼可從共享函式庫復用，僅需少量任務特定邏輯即可部署。

**2. 倉儲分揀與堆疊作業**
類似 RoboDojo 中的堆疊碗（stack bowls）任務，物流倉儲中的箱體堆疊、分類揀貨等場景，物件位姿可從 RGB 影像與本體感覺推估，狀態變化規律，COAP 可在無 VLM/VLA 的情況下穩定執行。

**3. 實驗室自動化操作**
生物實驗、化學合成中的移液、樣品製備等任務，環境結構化、動作可分解、容錯需求高（需回溯重試），COAP 的顯式狀態與可控執行特性非常契合。

**4. 餐飲自動化（結構化廚房）**
固定食譜的備料、擺盤、烹飪輔助任務，物件（食材、餐具）幾何已知，狀態追蹤明確，COAP 可作為骨幹策略，並透過 RSI 持續累積新食譜的處理能力。

**5. VLA / Agent Harness 的訓練數據引擎**
當 COAP 在某任務上穩定執行後，其產生的成功軌跡可作為高品質訓練數據，反哺視覺-語言-動作模型與代理駕馭框架的迭代，形成「COAP 生成 → VLA 學習」的閉環。

### 實作前置條件

**資料需求**
- **RGB 影像串流**：至少一張以上多視角相機，用於物體位姿估測
- **本體感覺資料**：機械手臂關節角度、末端位姿、夾爪狀態
- **物件幾何模型**：CAD 檔案或量測得到的尺寸、形狀、質量分布
- **任務規格文件**：任務步驟、初始狀態、終止條件、成功準則

**運算資源**
- **開發階段**：需具備執行前沿編碼代理（如 Claude Opus 級別模型）的 API 存取權，用於 RSI 閉環開發
- **訓練階段**：若需訓練視覺感知模型（如物件偵測、分割），建議配備 ≥ 1 張 A100/H100 等級 GPU
- **部署階段**：邊緣裝置需支援 Python 執行環境（如 NVIDIA Jetson Orin、Intel NUC 等），無需 GPU 即可運行 COAP 策略

**技能門檻**
- **機器人學基礎**：正向運動學、座標轉換、路徑規劃
- **電腦視覺**：6D 位姿估測、物件分割、點雲處理
- **軟體工程**：Python 程式設計、模組化設計、單元測試
- **領域知識**：目標應用場景的工藝流程與容錯規範

### 實作步驟建議

**步驟一：任務分析與狀態定義**
盤點目標任務的所有可能狀態（環境狀態 + 機器人狀態），明確定義每個狀態變量如何從感知資料推估。建議先從單一任務的小規模試點開始，驗證狀態可測量性。

**步驟二：建立共享感知函式庫**
開發可復用的感知模組，例如 `perception.look(snap)` 介面，從 RGB 影像回傳物件位姿清單。論文指出 83% 的程式碼來自函式庫，因此函式庫的設計品質直接決定擴展性。

**步驟三：實作任務特定邏輯**
針對單一任務撰寫決策邏輯，例如 `tasks/stack_bowls.py`，呼叫共享函式庫的感知與動作原語。程式碼須遵守「無單一回合 hack」與「測試時無真實標註狀態」的紀律。

**步驟四：建立 RSI 開發閉環**
設定編碼代理在固定規則下自主迭代：摘要現有程式碼、撰寫新邏輯、除錯、驗證跨回合穩定性。每一次變更都應是顯式且可審查的。

**步驟五：跨任務擴展與能力累積**
新任務應優先復用既有函式庫，僅在必要時繼承或擴展。隨著任務數增加，函式庫會自然累積通用能力（如抓取、放置、對位）。

**步驟六：部署與監控**
將凍結的 COAP 策略部署至目標機器人，監控成功率、執行時間、故障模式。COAP 的優勢在於故障可追溯至具體程式碼行，便於線上修補。

**步驟七（可選）：作為數據引擎**
若需訓練 VLA 或 Agent Harness，可讓 COAP 在不同回合中執行並記錄成功軌跡，作為高品質示範數據。

### 潛在風險與注意事項

**風險一：狀態估測誤差累積**
若感知模組的位姿估測存在系統偏差，後續決策將建立在錯誤狀態上，導致連鎖失敗。
**緩解**：在函式庫中加入狀態合理性檢查（例如「物件是否在可達工作空間內」），並設計回溯機制。

**風險二：程式碼脆弱性**
COAP 假設「若仍需要 VLM/VLA，代表程式碼尚不夠穩健」。對於高度變化或未預期的場景，硬編碼邏輯可能失效。
**緩解**：保留 VLM/VLA 作為 fallback，僅在 COAP 連續失敗時啟動；同時持續擴展函式庫覆蓋的場景。

**風險三：泛化能力受限**
論文明確指出 COAP 的弱點在於泛化，每個新任務仍需少量任務特定邏輯。
**緩解**：透過 RSI 閉環讓函式庫持續演化，並以任務分群策略減少重複開發。

**風險四：開發紀律鬆弛**
工程師可能為單一回合加入 hack（例如硬編碼某次失敗的物件位置），破壞跨回合穩定性。
**緩解**：建立 code review 機制，明文禁止 episode-specific hack，並以自動化測試驗證跨回合一致性。

**風險五：安全與可預測性**
雖然 COAP 是白盒、可控的，但若邏輯錯誤未被察覺，可能導致機器人執行危險動作。
**緩解**：在部署前進行大量模擬測試，並設置硬體層級的安全護欄（力限制、速度限制、緊急停止）。

### 與其他技術的整合建議

**與 VLA 整合**
COAP 可作為 VLA 的「教師」：在結構化任務中產生大量成功軌跡，用於 VLA 的模仿學習或微調。當 VLA 在分布外場景失效時，可回退至 COAP 處理已知場景。

**與 Agent Harness 整合**
Agent-as-Policy 或 Harness VLA 可將 COAP 函式庫作為可呼叫的工具（tool），由 VLM 進行高層任務分解，COAP 處理低層執行。這種分工兼顧了 VLM 的泛化能力與 COAP 的執行穩定性。

**與 ROS / 機器人中介軟體整合**
將 COAP 封裝為 ROS 節點，動作原語對應到 ROS topic/service，便於與現有的導航、感知、規劃模組共存。狀態變量可透過 ROS parameter 或 topic 對外暴露，方便除錯與監控。

**與模擬器整合**
在開發階段使用模擬器（如 Isaac Sim、MuJoCo）進行 RSI 閉環迭代，可大幅降低實機測試成本。COAP 的程式碼可在模擬與實機間無縫遷移，只需替換感知介面的實作。

**與版本控制與 CI/CD 整合**
COAP 的程式碼變更應納入 Git 版本控制，每次 RSI 迭代對應一個 commit。CI/CD 流程可自動執行跨回合測試，確保新版本不退步。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解圖靈機的基本概念（紙帶 + 規則），再閱讀第 1 節的 Embodied Turing Machine 比喻。核心訊息是：當機器人與環境的狀態可以被「讀」出來時，決策不一定需要神經網路，可以直接寫成程式碼。COAP 的三大優勢（顯式狀態、可控執行、可擴展）會自然引導你思考「哪些任務其實不需要 AI 模型」。

**給 AI 工程師**：重點關注 §4.3 的三大優勢分析與 §4.4 的 RSI 設計。COAP 並非要取代 VLA，而是提供一個互補範式：在結構化任務中用程式碼取代模型，在非結構化任務中仍由 VLM/VLA 主導。建議評估你目前的機器人專案中，哪些任務的狀態可顯式測量，適合採用 COAP；哪些仍需 VLM 的泛化能力。同時，COAP 作為數據引擎的潛力（§5.5）值得深入探索。

**給研究者**：論文的理論框架（Embodied Turing Machine）與實證結果（70.24% 成功率，超越 SOTA 38.9%）都值得仔細推敲。開放問題包括：狀態表示的理論上界、程式碼複雜度與任務泛化能力的權衡、RSI 閉環的收斂性保證。建議從「程式碼作為策略媒介」的角度出發，與神經符號（neuro-symbolic）方法、程式合成（program synthesis）文獻對話。

**給產品經理**：COAP 的商業價值在於「可控、可審查、可累積」。相較於 VLA 的黑盒特性，COAP 讓每一次決策都可追溯至具體程式碼行，這對醫療、工業等高合規場景極具吸引力。同時，COAP 的執行成本低（無需 GPU 推理）、回應速度快、故障可恢復，這些特性直接影響產品的 SLA 設計。建議將 COAP 定位為「結構化任務的骨幹策略 + 非結構化任務的數據引擎」，作為產品技術路線的雙軌策略之一。
