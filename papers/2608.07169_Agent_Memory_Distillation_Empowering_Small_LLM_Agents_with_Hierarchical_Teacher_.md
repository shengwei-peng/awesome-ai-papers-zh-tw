# 智慧體記憶蒸餾（AMD）：以階層式教師記憶強化小型大型語言模型智慧體

**原文標題：** Agent Memory Distillation: Empowering Small LLM Agents with Hierarchical Teacher Memory  
**作者：** Taeil Kim、Kangsan Kim、Sung Ju Hwang  
**發布日期：** 2026-08-07  
**HF 連結：** [https://huggingface.co/papers/2608.07169](https://huggingface.co/papers/2608.07169)  
**arXiv：** [https://arxiv.org/abs/2608.07169](https://arxiv.org/abs/2608.07169)  

---

## ⚡ TL;DR

小型LLM智慧體難以自行產生足夠成功軌跡，導致記憶庫充斥失敗經驗，限制記憶效用。
提出免訓練的AMD框架，將教師成功經驗依工作流程、子任務與函式三層記憶轉移給小型智慧體。
於AppWorld等三項基準，4B–8B學生模型準確率提升最高達27.2個百分點，縮短互動輪數。

---

## 摘要翻譯

記憶系統雖已展現提升智慧體效能的潛力，但對於難以自行產生足夠成功軌跡（successful trajectories）的小型語言模型而言，其潛力仍多半未被充分探索。本文提出智慧體記憶蒸餾（Agent Memory Distillation, AMD），一個免訓練框架（training-free framework），透過階層式記憶（hierarchical memory）將結構化知識從大型教師智慧體（teacher agent）轉移至小型學生智慧體（student agent）。AMD 從教師的成功軌跡中建構三種互補的記憶類型：工作流程記憶（Workflow memory）編碼任務層級策略（task-level strategies），子任務記憶（Subtask memory）以中等粒度（intermediate granularity）提供具體行為範例，而函式記憶（Function memory）則捕捉個別函式呼叫慣例（per-function calling conventions）與常見陷阱（common pitfalls）。工作流程記憶與子任務記憶會在每項任務開始時主動注入（proactive injection），函式記憶則在發生工具呼叫錯誤（tool-calling errors）時反應式檢索（reactive retrieval）。我們在三項工具使用基準測試（tool-use benchmarks）上評估 AMD，以 GPT-5-mini 作為教師，使用四個學生模型（40 億至 80 億參數，4B–8B parameters），結果在 AppWorld、BFCL V3 與 ToolSandbox 上分別取得相較基線平均 27.2、11.2 與 3.4 百分點（percentage points, pp）的準確率提升（accuracy gains），並一致優於現有的基於記憶的基線方法（memory-based baselines）。進一步分析顯示，子任務記憶帶來最大的提升，教師效能取決於教師能力（teacher capability）與學生適配性（student compatibility），而 40 億參數規模的學生從 AMD 中獲益最多。

### 核心貢獻（3～5點）
- 提出 AMD 免訓練框架，透過階層式教師記憶將結構化知識轉移至小型學生智慧體，無需更新模型參數。
- 設計三種互補記憶類型：工作流程記憶（Workflow memory）、子任務記憶（Subtask memory）與函式記憶（Function memory），分別對應任務層級策略、中等粒度行為範例與個別函式呼叫慣例。
- 結合主動注入（proactive injection）與反應式檢索（reactive retrieval）機制，依據不同記憶特性在適當時機提供資訊。
- 在三項工具使用基準測試（AppWorld、BFCL V3、ToolSandbox）上驗證，對 4B–8B 參數的學生模型帶來顯著且一致的準確率提升。
- 深入分析教師效能的關鍵因素，發現子任務記憶貢獻最大，且 4B 規模的學生從 AMD 中獲益最多。

### 適合對象
適合對大型語言模型智慧體、記憶系統、知識蒸餾與工具使用基準測試有興趣的研究者與工程師，特別是關注如何在資源受限的小型模型上提升智慧體表現、或希望以無需微調的方式增強工具呼叫能力的讀者。

## 深度分析

#### 方法論解析

本研究提出 **Agent Memory Distillation（AMD，智慧體記憶蒸餾）**，核心目標是讓 **small LLM agents（小型大型語言模型智慧體）** 在不更新 **model parameters（模型參數）** 的前提下，吸收強大 **teacher agent（教師智慧體）** 累積的結構化經驗。整體設計可拆解為三個層次：問題設定、教師記憶生成，以及學生記憶檢索與使用。

##### 1. 問題設定與動機
小型智慧體由於能力有限，自行探索時產生的 **successful trajectories（成功軌跡）** 稀少，導致 **memory repositories（記憶庫）** 充斥 **failed trajectories（失敗軌跡）**。雖然可以從失敗中 **reflection（反思）**，但缺乏成功範例會从根本上限制 **memory utilization（記憶利用）** 的效果。因此，作者轉向讓效能更強的教師智慧體產生大量成功經驗，再將這些經驗蒸餾給學生。然而，直接轉移教師記憶（naive memory transfer）效果有限，原因在於教師與學生之間存在 **capability gap（能力落差）**：教師能輕易執行的高階策略，學生可能連其中單一步驟都無法完成。這個現象與傳統 **knowledge distillation（知識蒸餾）** 中觀察到的問題一致。

##### 2. 階層式教師記憶（Hierarchical Teacher Memory）
為了彌合能力落差，AMD 將教師經驗組織成三種互補的記憶類型，對應不同 **task granularity（任務粒度）**：

- **Workflow memory（工作流程記憶）**：記錄整體 **task-level strategies（任務層級策略）**，協助學生進行 **task decomposition（任務分解）** 並建立 **high-level plan（高階計畫）**。這層記憶對應「要做什麼」與「先做什麼」。
- **Subtask memory（子任務記憶）**：提供中等粒度（**intermediate granularity**）的具體 **action examples（動作範例）**。它介於抽象策略與底層工具呼叫之間，讓學生能參考教師在特定子任務上的成功行為。
- **Function memory（函式記憶）**：記錄個別函式的 **tool schemas（工具綱要）**、**argument schemas（引數綱要）**、**return structures（回傳結構）** 與 **common pitfalls（常見陷阱）**，屬於最細粒度的操作知識。

這種階層式結構的設計理念在於：小型智慧體的 **in-context learning（情境學習）** 與指令遵循能力較弱，單一粗粒度記憶難以落地，單一細粒度範例又難以掌握全局。三層記憶同時提供鳥瞰圖、中層範例與底層手冊，降低理解與應用教師知識的門檻。

##### 3. 主動注入與反應式檢索
AMD 在推論階段採用兩種記憶使用策略：

- **Proactive injection（主動注入）**：**Workflow memory** 與 **Subtask memory** 在任務開始時即加入學生的 **prompt（提示）**。這讓學生在一開始就具備正確的規劃方向與可參考的子任務範例。
- **Reactive retrieval（反應式檢索）**：**Function memory** 只有在學生發生 **tool-calling errors（工具呼叫錯誤）** 時才會被檢索。這種按需檢索的方式避免一次塞入過多細節造成干擾，同時在錯誤發生時提供及時的修正指引。

整體而言，AMD 是一個 **training-free framework（免訓練框架）**：不修改學生模型權重，而是透過精心設計的記憶內容與檢索機制，在推論時提升學生智慧體的表現。

#### 實驗數據解讀

論文在三個 **tool-use benchmarks（工具使用基準測試）** 上進行評估：**AppWorld**、**BFCL V3（Berkeley Function-Calling Leaderboard 第三版）** 與 **ToolSandbox**，並使用四個 4B–8B 參數的學生模型，教師模型為 **GPT-5-mini**。主要結果顯示，AMD 相對於 **zero-shot baseline（零樣本基線）** 的平均準確率提升分別為：

- AppWorld：**+27.2 percentage points（pp，百分點）**
- BFCL V3：**+11.2 pp**
- ToolSandbox：**+3.4 pp**

##### 1. 不同基準的增益差異
AppWorld 的增益最為顯著，這與其任務特性密切相關。AppWorld 涉及多步驟手機應用程式操作，需要長程規劃與跨應用協調，因此 **Workflow memory** 與 **Subtask memory** 能發揮最大價值。BFCL V3 專注於函式呼叫正確性，雖然步驟較短，但 **Function memory** 與 **Subtask memory** 仍能顯著減少引數錯誤與格式問題。ToolSandbox 的增益相對較小，可能因為該基準的任務較為獨立、學生基線已經不低，或教師經驗與學生能力之間的轉換空間較有限。

##### 2. 記憶類型的貢獻
進一步分析指出，**Subtask memory 貢獻最大**。這說明對於小型智慧體而言，最關鍵的並不是宏觀策略，也不是最細部的工具文件，而是「在這個子任務上，教師具體做了什麼」的中層範例。Subtask memory 同時具備可執行性與泛化性，能直接指導學生的下一步動作，也能在不同任務間重複使用。

**Workflow memory** 雖然貢獻較小，但對於降低互動回合數、讓學生軌跡更接近教師軌跡具有結構性作用。**Function memory** 則主要在錯誤發生後發揮救援功能，對於提升最終成功率屬於「保險型」貢獻。

##### 3. 學生模型規模的影響
實驗發現 **4B-scale students（40 億參數級學生模型）** 受益最大。這符合直覺：能力越弱的模型，自行產生成功經驗的機會越低，因此對外部教師記憶的依賴越高。相對地，8B 模型可能已具備部分規劃與工具使用能力，記憶蒸餾的邊際效益遞減。這也暗示 AMD 特別適合作為「拉抬底部模型表現」的技術。

##### 4. 教師效能的雙重條件
研究強調教師效能不只取決於 **teacher capability（教師能力）**，也取決於 **student compatibility（學生適配性）**。一個極強的教師若其策略嚴重超出學生可執行範圍，反而無法有效轉移。這呼應了方法論中階層式設計的必要性：透過 Subtask 與 Function 記憶填補 Workflow 策略與學生執行能力之間的鴻溝。

#### 與現有研究的比較

##### 1. 相對於現有記憶方法的定位
現有記憶相關研究如 **Reflexion**、**ExpeL**、**AWM**、**ReasoningBank**、**MemP**、**ReflecTool** 與 **SASM** 等，大多在大型專有模型（如 GPT-4 或 Gemini 2.5）上驗證，並未針對 **small agents（小型智慧體）** 的記憶稀缺問題進行設計。這些方法通常假設智慧體本身已能產生足夠多的成功軌跡，因此可以直接從自身經驗中萃取記憶。AMD 則明確指出小型智慧體無法滿足這個前提，並引入教師經驗作為外部知識來源。

##### 2. 相對於其他蒸餾與轉移方法
- **AgentDistill** 採取 **training-free** 方式直接重複使用教師產生的 MCPs，但並未讓學生直接利用教師記憶。
- **MemoryTransferLearning** 探討模型間知識轉移，但並非針對教師–學生蒸餾情境設計。
- 傳統知識蒸餾通常透過微調或強化學習更新學生參數，而 AMD 選擇在推論階段轉移結構化經驗，避免了訓練成本。

AMD 的主要創新在於：它是首個系統性研究 **teacher-to-student memory distillation（教師對學生記憶蒸餾）** 的框架，並透過 **hierarchical structure（階層式結構）** 與 **proactive/reactive retrieval（主動／反應式檢索）** 機制，具體處理能力落差問題。

##### 3. 限制與待釐清之處
- **成功軌跡偏誤**：AMD 目前主要從 **successful trajectories** 建立記憶，未能充分利用 **unsuccessful trajectories** 中的負向知識。
- **教師依賴性**：若教師在某類任務上表現不佳，或教師使用的工具／API 與學生可呼叫的不一致，記憶品質會直接下降。
- **無參數更新的天花板**：雖然免訓練降低了部署門檻，但學生模型本身的推理能力未變，長期來看可能會遇到吸收上限。
- **記憶規模與檢索成本**：階層式記憶雖然提升效果，但也增加了 **context length（上下文長度）** 與檢索複雜度，論文對這部分的開銷分析較少。

#### 可重現性評估

從提供的內容來看，論文並未明確說明是否公開原始碼、記憶生成腳本或教師軌跡資料。以下從幾個面向評估可重現性：

- **公開基準測試**：AppWorld、BFCL V3 與 ToolSandbox 均為公開資料集，實驗設定本身具備重複執行的基礎。
- **教師模型**：GPT-5-mini 為專有模型（proprietary model），若未來無法穩定取得相同版本，則教師軌跡難以完全複製。
- **學生模型**：4B–8B 的學生模型通常來自開源系列（如 Qwen、Llama 等），模型權重可取得，但論文未指明確切版本與量化設定。
- **記憶生成與檢索細節**：階層式記憶的萃取需要詳細的 **prompt（提示）** 設計、相似度檢索邏輯、錯誤觸發條件等，這些都是重現的關鍵。若作者未釋出相關程式碼，其他研究者只能根據描述進行近似實作。

整體而言，本研究的方法概念清晰，但完整重現需要作者進一步釋出 **code（程式碼）**、**memory generation prompts（記憶生成提示）**、**retrieval implementation（檢索實作）** 以及部分 **teacher trajectories（教師軌跡）**。建議後續版本補充這些資訊，以提升社群的可重現性與可比較性。

#### 未來研究方向

1. **結合參數高效微調（PEFT）**：將 AMD 的記憶內容進一步蒸餾為模型參數更新（如 LoRA），在保留免訓練優勢的同時突破推論階段的能力天花板。
2. **負向記憶蒸餾**：除了成功軌跡，也從教師或學生的失敗經驗中提取「不該做什麼」的記憶，強化錯誤預防能力。
3. **自適應記憶檢索**：引入學習式或基於不確定性的檢索機制，動態決定在不同階段該注入哪些記憶，而非固定使用 Workflow + Subtask 的主動注入。
4. **多教師記憶融合**：當單一教師與學生適配性不足時，可結合多位教師的記憶，並透過相容性評分選擇最適合學生的範例。
5. **動態記憶更新與自我演化**：讓學生隨著自身能力提升，逐步從依賴教師記憶轉向使用自身產生的成功經驗，形成 **self-evolving agents（自我演化智慧體）**。
6. **跨領域泛化研究**：探討在某一領域（如 AppWorld）學到的階層式記憶，能否遷移到其他工具使用情境。
7. **理論分析能力落差**：建立更嚴謹的框架來量化 **teacher capability**、**student compatibility** 與蒸餾成效之間的關係。
8. **記憶壓縮與長上下文管理**：針對階層式記憶可能帶來的上下文負擔，研究如何在不損失資訊的前提下進行記憶摘要與壓縮。
9. **人類參與的記憶策展（Human-in-the-loop curation）**：讓領域專家審核或補充教師記憶，提升關鍵任務上的可靠性與安全性。
10. **與主流智慧體框架整合**：將 AMD 模組化為 LangChain、AutoGen 等框架的記憶外掛，降低實務部署門檻。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**

A：本文指出，雖然記憶系統能顯著提升大型語言模型智慧體的表現，但小型 LLM 智慧體由於任務成功率較低，自己累積的記憶庫往往充斥著失敗軌跡，成功經驗非常稀少，導致記憶難以發揮作用。這種「成功軌跡不足」的問題限制了小型智慧體透過過往經驗自我演化的能力。為此，作者提出讓小型學生智慧體直接利用強大教師智慧體所產生的高品質成功經驗，以彌補其自身探索能力的不足。

**Q2：為什麼現有的記憶方法對小型智慧體效果不佳？**

A：現有記憶方法多半是在 GPT-4 或 Gemini 等大型專有模型上驗證，這些模型具備強大的上下文學習與指令遵循能力，能夠有效理解與應用記憶內容。然而，小型模型在這些能力上較弱，即使直接提供教師記憶，也常因能力差距過大而無法正確執行，例如教師建議「先登入再播放清單」，學生卻連登入步驟都無法完成。因此，單純的記憶轉移對小型智慧體幫助有限，需要更細緻的知識轉移策略。

**Q3：教師記憶蒸餾對小型智慧體的發展為何重要？**

A：教師記憶蒸餾讓小型智慧體無需昂貴的微調或強化學習，就能吸收強大教師累積的成功行為模式與工具使用經驗。這不僅能降低部署成本，也讓邊緣裝置或資源受限場景有機會運行更強大的智慧體。長遠來看，這種機制為小型 LLM 智慧體的自我演化與能力擴展奠定了重要基礎。

**Q4：Agent Memory Distillation（AMD）的核心方法是什麼？**

A：AMD 是一個免訓練框架，它先讓強大的教師智慧體在任務中產生成功軌跡，再從這些軌跡中萃取出三種互補的階層式記憶：工作流程記憶、子任務記憶與函式記憶。在推論階段，工作流程記憶與子任務記憶會在任務開始時主動注入學生智慧體，協助其制定高階計畫與參考具體行為範例；函式記憶則在發生工具呼叫錯誤時被反應式檢索，用來修正工具使用方式。

**Q5：AMD 相較於單純記憶轉移的關鍵創新是什麼？**

A：AMD 的關鍵創新在於採用「階層式教師記憶」來橋接教師與學生之間的能力差距，而非一次性提供原始軌跡或單一抽象層級的記憶。透過將知識區分為任務層級、子任務層級與函式層級，學生能依照自身能力逐步理解與應用教師經驗。此外，主動注入與反應式檢索的結合，讓記憶既不會在規劃階段造成過載，也能在出錯時提供精準指引。

**Q6：為什麼要設計三種記憶類型，並分別採用主動注入與反應式檢索？**

A：工作流程記憶負責編碼整體任務完成策略，適合在任務一開始就提供，幫助學生進行任務分解與建立高階計畫；子任務記憶提供中等粒度的具體行動範例，能讓學生在執行過程中參考教師的成功行為；函式記憶則記錄個別工具的引數綱要、回傳結構與常見陷阱，只有在遇到工具呼叫錯誤時才檢索，可避免無謂的資訊干擾。這種分層與分時機的設計，能讓小型模型更有效吸收與應用教師知識。

**Q7：實驗使用了哪些基準測試與模型？**

A：作者在 AppWorld、BFCL V3 與 ToolSandbox 三個工具使用基準測試上評估 AMD，涵蓋手機應用程式操作、函式呼叫能力與工具沙盒場景。學生模型選用四個參數規模介於 40 億至 80 億之間的小型語言模型，教師則使用 GPT-5-mini。這樣的設計能檢驗 AMD 在不同難度與不同學生能力條件下的泛化性。

**Q8：AMD 帶來了哪些主要實驗結果？**

A：相較於零樣本基線，AMD 在三個基準測試上分別帶來平均 27.2、11.2 與 3.4 個百分點的準確率提升，並且在所有記憶型基線方法中表現最佳。此外，AMD 還能減少學生智慧體與環境互動的回合數，使其產生的軌跡更接近教師的執行模式。值得注意的是，40 億參數規模的學生模型從教師記憶蒸餾中獲益最大，顯示該方法對較弱小型模型特別有幫助。

**Q9：消融實驗與進一步分析揭示了什麼？**

A：分析顯示，子任務記憶對整體效能提升的貢獻最大，因為它提供了學生最容易直接模仿的具體行為範例。教師記憶的轉移品質同時取決於教師能力與教師—學生適配性，也就是說，教師本身要夠強，且其知識表達方式要適合學生理解。此外，實驗也發現 4B 規模的學生受益最明顯，這與其原本成功經驗稀少、可塑性較高的特性一致。

**Q10：AMD 在實務上可以應用在哪些場景？**

A：AMD 特別適合部署在運算資源有限的邊緣裝置上，例如手機端的個人助理、智慧客服機器人或自動化操作手機應用程式的代理。在這些場景中，使用小型模型能降低延遲與成本，而透過教師記憶蒸餾則可彌補模型本身能力較弱的問題。此外，任何需要反覆呼叫外部 API 或工具的工作流程，例如行程規劃、資料查詢與自動化測試，都可能從 AMD 受益。

**Q11：若將 AMD 產品化，需要考慮哪些實際因素？**

A：首先必須建立高效的記憶儲存與檢索系統，確保主動注入與反應式檢索不會顯著增加推論延遲。其次，教師模型的選擇與教師—學生適配性評估至關重要，因為不適配的教師記憶可能無法被學生有效利用。此外，還需考量隱私與安全性，例如教師軌跡是否包含敏感資料，以及記憶內容是否需要定期更新以保持時效性。

**Q12：這項研究對智慧體領域可能產生什麼影響？**

A：AMD 為小型 LLM 智慧體的能力提升提供了一條免訓練且可擴展的路徑，有助於降低對大型專有模型的依賴，使更多應用能在本地或低成本環境中運行。它也開啟了「跨模型記憶轉移」這一新研究方向，讓不同能力與規模的智慧體能共享經驗。長期而言，這可能促進更開放、更具可解釋性且能持續自我演化的智慧體生態系統。

**Q13：作者承認 AMD 有哪些限制？**

A：AMD 的成效高度依賴教師智慧體能否產生足夠多且正確的成功軌跡，若教師本身在特定任務上表現不佳，則蒸餾效果會受限。此外，不同基準測試的增益幅度差異明顯，例如 ToolSandbox 的提升僅 3.4 個百分點，顯示方法在某些環境下的效益較有限。最後，目前框架主要針對已有成功範例的任務，對於完全未見過或需要高度創造性推理的任務，其幫助可能較小。

**Q14：在哪些情況下 AMD 可能會失敗或表現不佳？**

A：當教師與學生之間的能力差距過大時，即使提供階層式記憶，學生仍可能無法理解或執行教師的策略。若任務需要動態適應環境變化，而教師記憶中的範例無法涵蓋新的錯誤情境，函式記憶的反應式檢索也可能失效。此外，若學生過度依賴教師記憶而缺乏自主探索，可能在面對與教師經驗不同的新任務時出現泛化困難。

**Q15：未來可以朝哪些方向延伸這項研究？**

A：未來可以探索動態記憶權重機制，讓系統根據任務難度與學生能力自動調整三種記憶的貢獻比例。另一個方向是結合學生自身的後續成功經驗，持續更新與擴充記憶庫，實現真正的線上自我演化。此外，也可將 AMD 與輕量微調或強化學習結合，並進一步研究教師—學生適配性的量化指標，以設計更精準的記憶選擇與轉移策略。

## 實務應用指南

## 適用場景

1. **企業內部流程自動化助理**  
   例如報帳申請、請假審批、會議室預約等需要依序操作多個內部系統的任務。教師智慧體（如 GPT-5-mini）先產出成功軌跡，AMD 將其蒸餾為工作流程記憶與子任務記憶，讓 4B–8B 的小型模型也能正確完成多步驟操作。

2. **客戶服務與售後支援智慧體**  
   處理退換貨、訂單查詢、故障排除等流程。透過教師記憶，學生智慧體可在一開始就掌握整體處理策略（Workflow memory），並在遇到工具呼叫錯誤時檢索函式記憶（Function memory）修正引數或呼叫順序。

3. **開發者工具與 API 呼叫助手**  
   協助開發者呼叫複雜 API、生成程式碼或執行測試。Function memory 可儲存個別函式的引數綱要、回傳結構與常見陷阱，學生模型在出錯時即時檢索，降低反覆試錯的互動回合數。

4. **醫療或法律表單填寫助理**  
   在高度規範的領域中，教師智慧體的成功經驗可轉化為任務層級策略與中等粒度的行為範例，協助小型模型遵循正確流程填寫表單，減少因不熟悉工具慣例造成的錯誤。

5. **教育輔導智慧體**  
   引導學生完成多步驀作業或實驗流程。Workflow memory 幫助學生智慧體建立高階計畫，Subtask memory 提供每個階段的具體動作範例，讓小型模型給出結構化且一致的引導。

## 實作前置條件

- **資料準備**
  - 目標領域的工具綱要、API 文件與引數結構。
  - 由強大教師智慧體產生的成功軌跡，數量需足以覆蓋主要任務類型。
  - 歷史失敗軌跡與常見錯誤日誌，用於強化 Function memory 中的常見陷阱。

- **運算資源**
  - 學生模型建議使用 4B–8B 參數等級的小型大型語言模型。
  - 免訓練框架，因此不需要微調所需的 GPU 叢集，但需足夠的推論資源運行教師與學生模型。
  - 向量資料庫或記憶庫，用於儲存與檢索階層式教師記憶。

- **技術與技能**
  - 熟悉提示工程與智慧體框架（如 LangChain、AutoGen 等）。
  - 具備工具使用基準測試的設計與評估能力。
  - 了解檢索增強生成（RAG）與記憶管理機制。

## 實作步驟建議

1. **定義任務領域與工具範圍**  
   明確智慧體需完成的任務類型、可呼叫的外部工具，以及成功與失敗的判斷標準。

2. **收集教師成功軌跡**  
   使用 GPT-5-mini 或其他強大教師智慧體在目標任務上執行，產出高品質的成功軌跡，並確保涵蓋多樣化的任務情境。

3. **建構階層式教師記憶**
   - **Workflow memory**：從成功軌跡中萃取任務層級策略，形成整體任務完成流程。
   - **Subtask memory**：擷取中等粒度的行為範例，記錄每個子任務的具體執行方式。
   - **Function memory**：整理個別函式呼叫慣例、引數綱要、回傳結構與常見陷阱。

4. **設計記憶注入與檢索機制**
   - 在任務開始時，主動注入 Workflow memory 與 Subtask memory。
   - 在學生智慧體遭遇工具呼叫錯誤時，反應式檢索 Function memory 並提供修正建議。

5. **整合至學生智慧體提示**  
   將階層式記憶以結構化方式嵌入學生模型的系統提示或對話上下文，避免資訊過載並確保記憶與當前任務相關。

6. **評估與迭代**
   - 在工具使用基準測試（如 AppWorld、BFCL V3、ToolSandbox）或自訂測試集上評估準確率與互動回合數。
   - 分析各記憶類型的貢獻，並針對教師能力與學生適配性進行調整。

7. **部署持續更新管線**  
   建立監控機制，定期以新的教師成功軌跡更新記憶庫，並淘汰過時或不再適用的記憶。

## 潛在風險與注意事項

- **教師與學生能力差距過大**  
  若教師策略過於複雜，小型學生模型可能無法理解或執行。建議選擇與學生能力相匹配的教師軌跡，或將 Workflow memory 拆解為更細的子任務。

- **記憶檢索不準確**  
  反應式檢索可能取回不相關的 Function memory，導致錯誤修正方向偏離。可透過語意相似度過濾、元資料標註與人工審核提升檢索品質。

- **提示長度與成本膨脹**  
  注入過多記憶會增加推論成本並稀釋學生模型的注意力。應對記憶進行壓縮、摘要，並限制每次注入的記憶數量。

- **過度依賴教師記憶**  
  學生可能只在熟悉情境表現良好，遇到新任務時泛化能力下降。建議保留零樣本基線能力，並設計探索與反思機制作為後備。

- **隱私與安全風險**  
  教師軌跡可能包含敏感資料。記憶庫應進行去識別化處理，並對 Function memory 中的工具呼叫範例進行權限控管。

- **錯誤串聯效應**  
  若 Workflow memory 中的高階計畫有誤，後續子任務與函式呼叫可能一錯再錯。應建立人機協作驗證機制，特別在高風險場景中。

## 與其他技術的整合建議

- **檢索增強生成（RAG）**  
  可將階層式教師記憶視為結構化 RAG 資料來源，Workflow 與 Subtask memory 作為高層語境，Function memory 作為細節知識庫。

- **現有智慧體框架**  
  AMD 可嵌入 LangChain、AutoGen、Semantic Kernel 等框架，作為記憶管理層，與現有的工具呼叫、規劃與反思模組協同運作。

- **可觀測性工具**  
  搭配 LangSmith、Weights & Biases 或自訂追蹤系統，監控記憶注入、檢索與工具呼叫錯誤，協助診斷知識轉移瓶頸。

- **持續整合／持續部署（CI/CD）**  
  將記憶庫更新納入 CI/CD 流程，當教師模型產出新成功軌跡或工具 API 變更時，自動重建並驗證階層式記憶。

- **人機協作（Human-in-the-Loop）**  
  在關鍵決策點引入人工審核，特別是 Workflow memory 所建議的高階計畫，確保教師知識符合業務規範與安全要求。

## 給不同背景讀者的閱讀建議

- **初學者**  
  建議先從「智慧體記憶蒸餾」的核心概念入手，把教師智慧體想像成經驗豐富的前輩，學生智慧體則是剛入門的新人。重點理解 Workflow、Subtask、Function 三層記憶的分工，以及為什麼小型模型需要階層式知識才能學會複雜任務。

- **AI 工程師**  
  請聚焦於第 3 節的方法實作細節，包括如何從教師軌跡萃取三層記憶、主動注入與反應式檢索的提示設計，以及如何在 4B–8B 模型上平衡提示長度與效能。實驗部分可參考 AppWorld、BFCL V3 與 ToolSandbox 的評估方式。

- **研究人員**  
  本文的貢獻在於首次系統性地探討教師到學生的記憶蒸餾問題，並提出階層式結構來緩解教師與學生之間的能力差距。建議關注記憶類型的個別貢獻分析、教師準確率與學生適配性的交互作用，以及未來可延伸的記憶更新、跨領域遷移與理論蒸餾邊界等研究方向。

- **產品經理**  
  本方法適合希望以較小模型成本達成接近大模型表現的產品場景。評估時應同時關注準確率提升與互動回合數下降所帶來的用戶體驗與成本效益，並優先選擇流程明確、成功軌跡易取得的任務作為首批落地應用。
