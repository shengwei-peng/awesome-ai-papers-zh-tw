## ⚡ TL;DR

執行時防護只能暫時修正動作，導致策略與防護機制持續錯配而阻礙任務進行。
FailBank 以純觀察 CBF 教師收集反事實修正，經篩選與受保護 LoRA 更新實現自我演化。

## 摘要翻譯

視覺-語言-動作（Vision-Language-Action, VLA）模型雖可泛化至眾多機器人操作任務（manipulation tasks），但在複雜環境中，必須在任務成功率（task success rate）與非預期接觸（unintended contact）之間取得平衡。執行時防護機制（runtime shields）可修正個別動作，但無法改變底層策略，因此反覆出現的分歧可能導致持續的策略-防護不匹配（policy-shield mismatch），進而阻礙任務進展。為解決此挑戰，我們提出 FailBank，一個四階段自我演化（self-evolution）框架，可將執行時回饋（runtime feedback）轉化為持續的策略改進。在收集階段，固定的基於控制障礙函數（Control Barrier Function, CBF）的安全模組作為純觀察教師（observe-only teacher），在策略仍實際掌控執行的同時產生反事實修正（counterfactual corrections）。接著，結果感知篩選（outcome-aware admission）將有用的反事實提案（counterfactual proposals）轉換為修正目標，並將成功且未經修正的動作保留為靜態錨點（quiet anchors），以進行受保護的低秩適配（Low-Rank Adaptation, LoRA）更新。我們在 VLA-Arena 基準測試（benchmark）上評估 FailBank，涵蓋兩種難度等級與兩種 VLA 骨幹模型（backbones）。與基礎策略（base policies）相比，FailBank 改善了聯合成功-成本運作點（joint success-cost operating point）。在兩種骨幹模型上，FailBank 分別將任務成功率提升 8.5 與 6.9 個百分點（percentage points），同時將策略引發的累積成本（policy-induced cumulative cost）分別降低 35.6% 與 23.8%。與執行時防護機制相比，FailBank 分別將任務成功率提升 25.4 與 9.5 個百分點，同時維持相近的策略引發的累積成本。這些結果顯示，執行時回饋可作為持續的策略監督，而不僅僅是暫時的動作約束（action constraint）。

### 核心貢獻（3～5點）
- 提出 FailBank 四階段自我演化（self-evolution）框架，將執行時回饋（runtime feedback）轉化為持續的策略改進，而非僅作為暫時的動作約束。
- 設計純觀察教師（observe-only teacher）機制，以基於控制障礙函數（CBF）的安全模組在不干預執行的前提下產生反事實修正（counterfactual corrections）。
- 提出結果感知篩選（outcome-aware admission）與靜態錨點（quiet anchors），用於產生修正目標並穩定受保護的 LoRA 更新。
- 在 VLA-Arena 基準測試上跨兩種難度與兩種 VLA 骨幹模型驗證，顯著改善聯合成功-成本運作點（joint success-cost operating point）。

### 適合對象
適合對機器人學習、視覺-語言-動作（VLA）模型、安全強化學習，以及執行時防護機制（runtime shields）感興趣的研究人員與工程師，特別是關注如何將執行時安全回饋轉化為策略持續改進的讀者。

## 深度分析

#### 方法論解析

本文提出的 **FailBank（失敗庫自我演化框架）** 是一個四階段迴圈，目標是將 **runtime feedback（執行時回饋）** 轉化為對 **Vision-Language-Action（VLA, 視覺-語言-動作）模型** 的持續策略改進，而非僅在動作執行當下進行暫時修正。其核心動機在於：現有的 **runtime shields（執行時防護機制）**（例如以 **Control Barrier Function（CBF, 控制障礙函數）** 為基礎的 AEGIS）雖能修正單一步驟的不安全動作，但 **nominal policy（原始策略）** 本身未被更新，導致 **policy-shield mismatch（策略-防護不匹配）** 反覆出現，最終在困難場景中造成所謂的 shield collapse（防護崩潰）。

FailBank 的四個階段可對應到圖中的 **Observe & Label（觀察與標記）**、**Admit & Weight（採納與加權）**、**Accumulate（累積）** 與 **Update（更新）**：

1. **Observe & Label**：在收集階段，原始策略根據 RGB 影像、本體感受（proprioception）與語言指令輸出動作。此時一個固定的 **CBF-based safety module（基於 CBF 的安全模組）** 作為 **observe-only teacher（純觀察教師）**，只計算並記錄 **counterfactual proposals（反事實提案）**，也就是「如果由防護機構決定，機器人應該採取的安全動作」，但並不實際執行這些修正。這個設計至關重要：它讓系統在策略自身的 rollout 分布上觀察 **failure distribution（失敗分布）**，同時避免因教師動作介入而改變狀態分布，從而取得真實的 **action disagreement（動作分歧）** 樣本。

2. **Admit & Weight**：並非所有教師提案都值得學習。**Outcome-aware admission（結果感知篩選）** 會根據實際執行結果，判斷哪些 **pre-contact corrections（接觸前修正）** 真正有助於同時提升安全與任務成功率，並將其轉為 corrective targets（修正目標）。與此同時，成功且未經防護修正的動作會被保留為 **quiet anchors（靜態錨點）**，用來穩定後續更新、避免策略遺忘原本已經會做的行為。每筆紀錄還會賦予 score weight ηᵢ，以反映其可信度或重要性。

3. **Accumulate**：被採納的紀錄會加入一個持續累積的 **training bank（訓練庫）**。這個 **failure bank（失敗庫）** 不僅儲存當次迭代的失敗經驗，也保留歷史資料，使稀有但關鍵的失敗模式能夠被重複學習，而不是在每次重新訓練後被洗掉。

4. **Update**：在更新階段，系統會在訓練庫上重新擬合一個 **fresh LoRA adapter（全新 LoRA 適配器）**。為了避免 **guarded LoRA updates（受保護的 LoRA 更新）** 破壞原始動作分布，作者設計了雙重驗收條件：**held-out flow loss（驗證流程損失）** 必須維持在一定範圍內，確保適配器對保留資料仍有良好泛化；**first-action drift（首步動作偏移）** 也必須受控，避免更新後策略在第一步就大幅偏離原始分布。只有同時通過這兩項檢查，新的 LoRA 才會被接受，並成為下一輪 rollouts 的 nominal policy。

部署時，接受後的策略僅需要 RGB 觀測與本體感受即可運作，無需持續呼叫教師模組。整體而言，FailBank 的設計同時處理了「教師可能出錯」、「策略可能遺忘」與「更新可能漂移」三個學習式安全系統的常見風險。

#### 實驗數據解讀

論文在 **VLA-Arena benchmark（VLA-Arena 基準測試）** 的 static-obstacle suite 上進行評估，涵蓋兩個難度等級（Level 1 與 Level 2）以及兩個 VLA backbones（π₀ 與 π₀.₅）。評估指標採用 **task success rate（任務成功率，SR）** 與 **policy-induced cumulative cost（策略引發的累積成本，CC_policy）**，並以 **joint success-cost operating point（聯合成功-成本運作點）** 作為綜合判斷依據。

從摘要的整體數據來看，FailBank 相對於 base policy 在兩個 backbone 上分別提升 SR 8.5 與 6.9 個百分點，同時降低 CC_policy 35.6% 與 23.8%。這表示 FailBank 不僅讓機器人更常完成任務，也減少了由策略本身造成的 **unintended contact（非預期接觸）**。相較於 **AEGIS（一種執行時防護方法）**，FailBank 在兩個 backbone 上進一步提升 SR 25.4 與 9.5 個百分點，而 CC_policy 則維持在相近水準。這說明單純的 runtime shielding 雖能降低局部成本，卻可能因反覆修正而犧牲任務完成率；FailBank 則把同樣的回饋轉為持久監督，從而同時改善成功與成本。

圖 1 以 Level-2 的三個代表性任務（Mango、Apple、Tomato）展示三種運作 regime：
- **Shield effective（防護有效）**：在 Mango 上，AEGIS 能在保持高成功率的同時降低成本。
- **Policy bottleneck（策略瓶頸）**：在 Apple 上，AEGIS 未能提升成功率。
- **Shield collapse（防護崩潰）**：在 Tomato 上，AEGIS 大幅降低成功率。

FailBank 在三種情況下都達到最高的 SR，並且相對於 Base 降低 CC_policy。圖 2 的 Level-2 onion 任務更具體地說明：AEGIS 為了避開附近的 hazard bottles（危險瓶罐），反覆將夾爪從目標洋蔥旁拉開，最終導致超時；FailBank 則透過學習這些 runtime corrections，成功將洋蔥放入碗中。

值得注意的是，兩個 backbone 的改善幅度不同，暗示 FailBank 的增益會受到基礎模型容量與原始 **failure distribution（失敗分布）** 的影響。此外，CC_policy 特別強調「策略引發」的成本，意味著它衡量的是原始策略動作所造成的接觸，而非防護機構介入後的結果；FailBank 能降低此指標，正說明策略本身已學會更安全的行為，而不只是依賴外部修正。

#### 與現有研究的比較

在相關研究中，generalist VLA policies（例如 π₀ 與 π₀.₅）透過 **flow matching（流程匹配）** 等技術實現連續動作生成與廣泛泛化，但本身並未內建安全機制。**Runtime safety mechanisms（執行時安全機制）** 方面，CBF（Ames et al., 2017）提供數學上的安全約束；AEGIS 結合 **visual grounding（視覺定位）** 與 CBF projection，成為可插拔的 VLA 安全層；另有 constrained flow matching 在生成階段就引入安全引導。這些方法都屬於動作時間的約束，並未改變底層策略。

FailBank 的差異在於：它把 runtime shield 的輸出視為監督訊號，透過 **observe-only teacher（純觀察教師）** 與 **failure bank（失敗庫）** 進行策略層級的自我演化。這帶來幾項優勢：
- 解決 **policy-shield mismatch（策略-防護不匹配）**，減少反覆介入與 shield collapse。
- 部署時僅需 RGB 與本體感受，無需持續執行昂貴的 CBF 投影。
- 透過 **quiet anchors（靜態錨點）** 與 acceptance guards，降低災難性遺忘與動作漂移的風險。

然而，FailBank 也存在明顯限制：
- 教師模組固定，若 CBF 的局部幾何模型在語義上誤判（例如把必經路徑視為障礙），則產生的 **counterfactual corrections（反事實修正）** 可能誤導策略。
- **Outcome-aware admission（結果感知篩選）** 需要知道執行結果，這在真實機器人上可能成本較高，且目前實驗僅限於 static-obstacle 的模擬環境。
- 接受新 LoRA 的固定門檻可能難以跨任務泛化。
- 雖然降低了 policy-induced cost，但論文未提供形式化的安全保證，無法像傳統 CBF 那樣給出嚴格的不變集證明。

#### 可重現性評估

論文指出原始碼已公開於 `Mingyuee88/FailBank`，並使用 VLA-Arena 官方定義的任務與指標，這對可重現性是正面因素。兩個 VLA backbones（π₀ 與 π₀.₅）在文獻中已有公開說明，但實際模型權重與訓練細節仍需視原始釋出情況而定。由於本文為 arXiv preprint，讀者可透過公開程式碼與基準測試重現主要實驗。

不過，可重現性仍有幾項潛在缺口：
- 論文未在提供的片段中詳細說明 LoRA rank、acceptance thresholds、訓練庫大小、學習率、迭代次數等關鍵超參數，這些細節需從原始碼或完整附錄中取得。
- 隨機種子、計算資源、每個數據點的試驗次數等資訊未於片段中呈現。
- 目前僅在模擬環境驗證，尚未提供真實機器人實驗，因此實體部署時的延遲、感測器雜訊與教師計算成本等問題仍有待確認。

#### 未來研究方向

基於 FailBank 的框架，未來研究可朝以下方向延伸：

1. **真實世界部署與線上學習**：將 failure bank 擴展為 streaming（串流）形式，讓機器人在真實環境中持續收集並更新紀錄，同時設計更強的遺忘抑制機制。

2. **自適應採納與驗收門檻**：目前的 outcome-aware admission 與 LoRA acceptance 使用固定門檻，未來可根據任務難度、教師不確定性或策略當前表現動態調整。

3. **與生成式安全機制結合**：將 FailBank 的學習紀錄整合進 constrained flow matching 或 diffusion policy，使安全資訊在動作生成階段就發揮作用，而不僅是事後修正。

4. **形式化安全保證**：研究如何在 LoRA 更新過程中保留或學習 CBF 相容性，使更新後的策略具備某種程度的不變集或 Lyapunov 式安全證明。

5. **動態障礙與長期任務**：目前實驗集中在 static obstacles，未來可擴展至移動障礙、多步驟 long-horizon manipulation tasks，以及更複雜的語義場景（例如 **lookalike objects（外觀相似物件）** 與 **protected items（受保護物品）** 的細緻區分）。

6. **多模態與人機協作回饋**：除了 CBF 的幾何修正，可納入力覺、觸覺或人類示範與糾正，豐富 failure bank 的監督訊號。

7. **跨機構遷移與樣本效率**：研究 failure bank 中的紀錄是否能在不同機器人型態或不同 VLA backbone 之間遷移，並開發主動採樣策略以減少所需 rollout 數量。

8. **教師與策略共同演化**：目前教師固定，未來可考慮讓 CBF 教師也根據策略的學習進度進行調整，形成教師-策略共同演化的良性迴圈。

## 論文問答

**Q1：在複雜環境中部署視覺-語言-動作（VLA）模型時，核心挑戰是什麼？**
A：VLA 模型雖然能泛化到多種機器人操作任務，但在複雜場景中必須同時兼顧任務完成與避免非預期接觸。真實環境常存在外觀相似物件與附近受保護物品，策略必須精確辨識目標、執行動作序列，又不能干擾無關物體。因此任務成功率與策略引發的累積成本必須聯合評估，單純提升成功率可能增加碰撞，而過度保守則會犧牲任務完成。

**Q2：現有的執行時防護機制（runtime shields）為何無法從根本解決安全問題？**
A：執行時防護機制只能在動作執行前修正單一步驟，卻不會更新原始策略，因此同樣的動作分歧會在後續時間步反覆出現。反覆介入會使機器人進入不熟悉狀態，甚至形成持續的「策略—防護不匹配」（policy–shield mismatch）。在狹窄抓取場景中，防護雖能降低當下成本，卻可能因持續把夾爪推離危險區域而連帶推離目標，最終導致任務逾時失敗。

**Q3：為什麼把執行時回饋轉換為持續性策略監督很重要？**
A：如果僅把執行時回饋當成暫時約束，同類錯誤會不斷重複，系統無法隨經驗成長。執行時回饋蘊含豐富的反事實資訊，能告訴我們「在相同狀態下，更安全的動作應該長什麼樣子」。將這些證據轉為學習紀錄，才能讓策略自我演化，逐步減少未來對外部防護的依賴，同時維持或提升任務成功率。

**Q4：FailBank 的核心方法包含哪四個階段？**
A：第一階段是「觀察與標記」：固定策略執行動作，基於 CBF 的安全模組作為純觀察教師，只記錄反事實提案而不干預執行。第二階段是「結果感知篩選」：根據執行結果挑選有用的接觸前修正，並保留成功且未經修正的動作作為靜態錨點。第三階段把採納的紀錄累積到訓練庫，第四階段則重新訓練 LoRA 適配器，並只有在驗證流程損失與首步動作偏移都符合門檻時才接受更新。

**Q5：FailBank 相較於傳統執行時防護的主要創新是什麼？**
A：關鍵創新在於提出「純觀察教師」介面，讓 CBF 教師在策略自己的 rollout 分布上收集反事實修正，卻不改變實際執行軌跡。其次，FailBank 透過失敗庫（Failure-Bank）與結果感知篩選，把一次性介入轉為可累積的學習紀錄。最後，受保護的 LoRA 更新機制確保策略在吸收新經驗的同時，不會偏離原本成功的行為分布。

**Q6：為何要設計「結果感知篩選」與「靜態錨點」？**
A：並非所有教師提案都合理，固定 CBF 教師可能給出無效或過度保守的修正，因此需要根據執行結果區分真正有用的接觸前修正。靜態錨點則是成功且未經修正的動作，能防止適配器更新時遺忘原本表現良好的行為。兩者結合可讓策略在學習安全修正的同時，避免過度擬合失敗案例或破壞原始動作分布。

**Q7：實驗在哪些基準與模型上進行？**
A：實驗使用 VLA-Arena 的 static-obstacle 套件，涵蓋兩個難度等級，等級越高代表任務越困難。研究在兩種 VLA 骨幹模型上評估，包括 π₀ 與 π₀.₅。該基準提供受控的安全、干擾與外插場景，能同時測量任務成功率與策略引發的累積成本。

**Q8：FailBank 相較於基線策略與 AEGIS 取得了哪些關鍵結果？**
A：與原始策略相比，FailBank 在兩個骨幹上分別提升任務成功率 8.5 與 6.9 個百分點，並降低策略引發的累積成本 35.6% 與 23.8%。與執行時防護方法 AEGIS 相比，FailBank 分別提升成功率 25.4 與 9.5 個百分點，同時維持相近的累積成本。整體而言，FailBank 持續改善聯合成功—成本運作點，即使在 AEGIS 成功率大幅下降的困難任務上亦然。

**Q9：論文如何分析不同任務難度下的防護行為？**
A：作者提出三種診斷情境：有效防護、策略瓶頸與防護崩潰（shield collapse）。圖一顯示在 Level-2 的 Mango、Apple、Tomato 任務中，AEGIS 在 Mango 上有效降低成本的同時保持成功率，但在 Tomato 上卻因反覆修正而大幅降低成功率；FailBank 在三項任務中都達到最高成功率並降低成本。圖二進一步以 Level-2 洋蔥任務為例，展示 AEGIS 反覆把夾爪推離危險瓶罐而遠離目標，最終逾時，而 FailBank 能成功完成任務。

**Q10：FailBank 在哪些實際應用場景最具潛力？**
A：FailBank 特別適合家庭服務、醫療照護與倉儲物流等 cluttered 環境，這些場景中常有外觀相似物件與不可碰撞的受保護物品。例如在廚房整理時，機器人必須抓取目標蔬果，同時避免打翻鄰近玻璃瓶。透過持續從執行時回饋學習，系統能逐漸適應特定環境佈局，減少人為重新標註資料的需求。

**Q11：若將 FailBank 產品化，需要考慮哪些部署與維護因素？**
A：部署時 FailBank 只需 RGB 觀測與本體感覺資訊，硬體需求相對單純。由於 CBF 教師在收集階段僅觀察不干預，可降低策略在學習過程中執行危險動作的風險。然而產品化仍需維護固定的安全教師模型、計算反事實提案的運算成本，以及設計合理的驗收門檻來避免不穩定的策略更新。

**Q12：FailBank 對機器人學習與安全領域可能帶來什麼影響？**
A：FailBank 將執行時安全從「暫時性動作約束」轉變為「持續性策略監督」，改變了人們對防護機制的使用方式。這有助於減少反覆手動調整防護參數的工程負擔，並提升通用 VLA 策略在開放世界接觸敏感任務中的可靠性。長遠來看，這種自我演化範式可讓機器人在真實部署中隨時間變得更安全、更有效率。

**Q13：論文承認 FailBank 有哪些限制？**
A：CBF 教師是固定的，可能產生無效或過度保守的反事實修正，結果感知篩選雖能過濾但無法保證完全正確。此外，實驗主要在模擬環境中進行，並依賴 CBF 觸發機制來產生標籤，這在真實世界可能面臨感知與動力學誤差。不同骨幹與任務間的改善幅度也有差異，顯示方法對任務難度與模型特性仍有一定依賴。

**Q14：FailBank 可能在哪些情況下表現不佳或失敗？**
A：當目標位於危險物品環繞的狹窄區域時，教師可能持續提出與任務方向衝突的修正，導致學習信號混亂。如果結果感知篩選錯誤採納了無效修正，或拒絕了真正有用的修正，後續 LoRA 更新便無法改善策略。此外，若首步動作偏移或驗證損失門檻設得太嚴格，可能會阻擋有益的更新，使系統停滯在原始策略表現。

**Q15：未來可以朝哪些方向延伸 FailBank？**
A：未來可將框架擴展到動態障礙物與多步推理任務，並探索以學習式安全評估器取代固定 CBF 教師。也可結合持續學習技術，避免失敗庫累積過程中的災難性遺忘，並引入人類教師或偏好回饋來豐富學習紀錄。另外，將 FailBank 與約束式 flow matching 等生成階段安全機制結合，或許能同時提升動作品質與長期安全性。

## 實務應用指南

### 適用場景

1. **倉儲揀選與保護物共存環境**  
   在自動化倉儲中，機器人需從外觀相似物件（lookalike objects）中抓取目標 SKU，同時避免碰倒鄰近的易碎品或高價值貨物。FailBank 可利用執行時防護機制（runtime shield）的反事實修正（counterfactual corrections）作為持續監督，讓視覺-語言-動作模型（VLA model）逐漸學會在靠近受保護物品（protected items）時採取更安全的軌跡，而非僅依賴每次的即時投影。

2. **居家輔助機器人**  
   家用場景充斥狹窄桌面、玻璃器皿與兒童玩具等障礙。原始策略（nominal policy）可能反覆與安全層產生動作分歧（action disagreement），導致任務逾時。FailBank 透過純觀察教師（observe-only teacher）記錄這些分歧，並以結果感知篩選（outcome-aware admission）保留有效修正，使機器人在不犧牲任務成功率的前提下降低非預期接觸（unintended contact）。

3. **醫療與實驗室物流**  
   在醫院或實驗室中，機械臂需運送試劑、藥品或精密儀器，周圍常有不可碰撞的設備。FailBank 的失敗庫（failure bank）能累積特定場景的失敗分布（failure distribution），並透過受保護的 LoRA 更新（guarded LoRA updates）讓策略學會避開重複發生的高風險區域，同時維持原始成功行為。

4. **零售補貨與貨架整理**  
   機器人需在擁擠貨架間補貨或調整商品位置。執行時防護機制可即時阻止碰撞，但長期下來可能形成策略-防護不匹配（policy-shield mismatch）。FailBank 將這些執行時回饋（runtime feedback）轉為持久策略改進，減少對防護層的依賴，提升作業流暢度。

5. **製造業精密組裝**  
   在組裝線上，機器人必須將零件放入狹窄治具，且不能干擾周圍的感測器或半成品。FailBank 的接觸前修正（pre-contact corrections）與靜態錨點（quiet anchors）機制，可幫助策略在複雜幾何約束下穩定學習，並透過首步動作偏移（first-action drift）檢查避免更新後行為劇烈變化。

### 實作前置條件

**資料準備**
- 可取得 RGB 影像、本體感覺（proprioception）與自然語言指令的成對資料。
- 具備場景中受保護物品與危險區域的幾何或語義標註，以便建立基於 CBF 的安全模組（CBF-based safety module）。
- 建議先在模擬環境（如 VLA-Arena）中累積足夠的執行軌跡，再考慮真實機器人部署。

**運算資源**
- 可執行 VLA 模型推理的 GPU，並支援 LoRA 適配器（LoRA adapter）的微調。
- 能即時求解控制障礙函數（CBF）二次規劃問題的運算單元，確保純觀察教師可在策略控制期間同步產生反事實提案（counterfactual proposals）。

**技術與團隊能力**
- 熟悉 VLA 模型架構、低秩適配（LoRA）與流程匹配（flow matching）訓練。
- 具備 CBF 或約束學習（constrained learning）基礎，能設計與調整安全模組。
- 具備機器人系統整合、模擬到真實（sim2real）驗證與安全測試經驗。

### 實作步驟建議

1. **部署原始策略與純觀察教師**  
   將既有 VLA 模型作為原始策略（nominal policy）上線，並並行掛載基於 CBF 的安全模組作為 observe-only teacher。此階段教師只記錄反事實修正，不實際干預機器人執行，以確保收集到的資料反映策略自身的失敗分布。

2. **收集執行時回饋**  
   在模擬或受控真實環境中執行大量回合，讓教師記錄每個時間步的候選安全動作、是否觸發修正、以及最終任務結果。同時記錄未經修正但成功的動作，作為後續的靜態錨點。

3. **結果感知篩選與加權**  
   依據回合成敗與成本，對教師提案進行 outcome-aware admission：採納能導向成功且降低成本的修正，剔除無效或過度保守的提案。對成功未修正動作給予適當權重，避免策略更新時遺忘原始能力。

4. **建立並維護訓練庫**  
   將採納的紀錄累積至訓練庫（training bank）。定期清理過時或重複樣本，並依任務難度與場景分層，確保失敗庫（failure bank）能涵蓋多樣的失敗模式。

5. **執行受保護的 LoRA 更新**  
   每次迭代重新訓練一個全新的 LoRA 適配器（fresh LoRA adapter）。在保留資料上計算驗證流程損失（held-out flow loss），並監測首步動作偏移（first-action drift）。只有兩者皆在固定門檻內才接受該適配器。

6. **分階段驗證與部署**  
   先在模擬環境中比較新任務成功率（task success rate）與策略引發的累積成本（policy-induced cumulative cost），確認聯合成功-成本運作點（joint success-cost operating point）確實改善。再於真實機器人上進行小規模、有人監控的 A/B 測試。

7. **持續監控與再訓練**  
   部署後持續記錄新的執行時回饋，定期將新紀錄併入訓練庫並重新執行 FailBank 四階段流程。同時保留可隨時回滾至上一版適配器的機制。

### 潛在風險與注意事項

| 風險 | 說明 | 因應措施 |
|---|---|---|
| **過度擬合教師行為** | 策略可能只學會模仿 CBF 教師的局部幾何修正，而非真正理解任務語義。 | 保留大量成功未修正動作作為靜態錨點，並以 held-out flow loss 檢查泛化能力。 |
| **教師誤判** | CBF 層可能對外觀相似物件或遮擋場景產生錯誤的安全約束，導致無效反事實提案被採納。 | 實施 outcome-aware admission，僅採納最終導向成功的修正；必要時加入人工審查。 |
| **災難性遺忘** | LoRA 更新可能削弱原始策略在簡單場景的表現。 | 使用 quiet anchors 與 first-action drift 檢查，限制更新幅度。 |
| **模擬到真實落差** | 在模擬器中學到的避障行為可能無法直接遷移到真實感測器與動力學。 | 採用領域隨機化、漸進式真實部署，並保留執行時防護機制作為最後防線。 |
| **安全驗證不足** | 若適配器在未充分驗證的情況下被接受，可能產生新的危險行為。 | 設定嚴格的接受門檻，並在獨立測試集上評估成功率與成本；部署時仍須有實體安全籠或緊急停止機制。 |
| **資料偏斜** | 若訓練庫過度集中於少數失敗類型，更新後策略可能對其他場景變脆弱。 | 定期分析失敗分布，主動採樣少數類別與新任務變體。 |

### 與其他技術的整合建議

- **與現有執行時防護機制並存**：FailBank 並非要取代 AEGIS 等 runtime shields，而是將其轉為 observe-only teacher。建議在生產環境中仍保留一層獨立的安全監控或緊急停止機制，直到新適配器通過充分驗證。
- **與艦隊資料紀錄系統整合**：將多機器人的執行軌跡統一匯入訓練庫，可加速失敗庫累積並提升策略泛化性。
- **與數位孿生（digital twin）結合**：在模擬環境中預先驗證 LoRA 更新，並利用孿生環境產生更多邊角案例，豐富 failure bank。
- **與 MLOps 管線整合**：將四階段流程自動化，包含資料收集、適配器訓練、驗證閘道與漸進式部署，確保每次更新都可追蹤與回滾。
- **與人機協作介面結合**：對於高風險或模稜兩可的修正提案，可引入人工審核節點，進一步提升 outcome-aware admission 的可靠性。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦於論文的動機與圖示：理解「執行時防護只能暫時修正動作，無法解決策略-防護不匹配」這個核心問題，再順著四階段流程圖了解 FailBank 如何將失敗經驗轉為學習資料。遇到 CBF 或 LoRA 等技術名詞時，可先將其視為「安全教師」與「輕量微調模組」，不必急於深入數學細節。

**AI 工程師**  
請重點閱讀方法章節與實作細節，特別是 outcome-aware admission 的篩選邏輯、quiet anchors 的權重設計，以及 guarded LoRA updates 的接受條件（held-out flow loss 與 first-action drift）。這些設計直接影響系統在真實部署時的穩定性與可維護性，建議同時參考原始碼與 VLA-Arena 的評估腳本。

**研究人員**  
本論文的核心貢獻在於提出「將 runtime feedback 轉為持久策略監督」的學習框架，並透過 observe-only teacher 避免執行時干預對資料分布造成的影響。建議深入探討其與 constrained learning、offline RL 及 imitation learning 的理論關聯，並思考如何將 failure bank 的累積機制擴展至更長期記憶、多任務遷移或更複雜的獎勵塑形設定。

**產品經理**  
本技術適合需要「在複雜場景中同時提升成功率並降低碰撞成本」的機器人產品。評估時請關注論文中的聯合成功-成本運作點，而非單純追求成功率；同時留意實作前置條件與風險，例如需要具備 CBF 安全模組與持續資料管線。建議將 FailBank 規劃為長期迭代能力，而非一次性功能，並預留模擬驗證與漸進式真實部署的時程。
