# WHALE：聯合 Harness（控制框架）與權重優化的簡易方法

## ⚡ TL;DR

現有智慧體僅單獨優化模型權重或提示，忽略了可執行 harness 程式碼這個共同瓶頸。
WHALE 輪流更新模型權重與搜尋 harness，並以自適應耐心規則決定切換時機。
在三領域中，WHALE 比單一基線提升 4.15–24.38 百分點，交替更新也優於分階段優化。

## 摘要翻譯

智慧體效能（agent performance）同時取決於模型參數，以及管理上下文（context）與控制流程（control flow）的可執行 harness（executable harness code）程式碼。單獨優化任一組件都會讓系統受困於仍被凍結的對應組件：權重更新可能改變哪個 harness 有效，而 harness 更新則可能改變哪些模型能力得以發揮。現有的聯合適應方法僅優化權重與文字提示，但讓更廣泛的 harness（broader harness）保持固定。我們提出 Weight-Harness Alternating LEarning（WHALE），這是一個簡易方法，它交替兩個階段：在當前 harness 下更新模型，然後在更新後的模型下搜尋更好的 harness。我們分別以線上拒絕採樣微調（online rejection-sampling fine-tuning）與 Meta-Harness 來具體實現這兩個階段。何時切換是一個關鍵的設計選擇：為了從雜訊中區分出真正的改進，同時避免針對不斷變化的對應組件進行過度優化，WHALE 採用固定階段長度或基於訓練訊號的自適應耐心規則（adaptive patience rule）。我們在搜尋式問答（search question answering）、數學推理與西洋棋謎題（chess puzzles）三個領域使用 Qwen3.5-2B/4B 智慧體（agent）進行實驗，WHALE 在最佳 mean@8 準確率（best mean@8 accuracy）上，分別比僅權重（weight-only）、僅 harness（harness-only）以及 Fast-Slow Training 高出 4.15 至 24.38 個百分點。任一組件都可能成為瓶頸：在 SearchQA 中，harness 搜尋僅需遠少於僅權重方法的 rollouts 次數即可達到相同的峰值準確率，但數學準確率只有在權重更新後才會提升。小規模的交錯更新在準確率與 rollout 成本上，也優於階段式的先權重後 harness 優化。程式碼可於 https://github.com/krafton-ai/WHALE 取得。

### 核心貢獻（3～5點）
- 提出 WHALE 框架，透過權重與 harness 交替優化，解決單獨更新任一組件時受困於另一凍結組件的瓶頸問題。
- 結合線上拒絕採樣微調與 Meta-Harness，分別實現權重更新與 harness 搜尋兩個階段。
- 設計固定階段長度與自適應耐心規則兩種切換策略，以在雜訊中辨識真正改進並避免過度優化。
- 在搜尋式問答、數學推理與西洋棋謎題三個領域驗證，WHALE 顯著優於僅權重、僅 harness 與 Fast-Slow Training 基線。
- 發現任一組件都可能成為瓶頸，且小規模交錯更新在準確率與 rollout 成本上均優於階段式先權重後 harness 的優化方式。

### 適合對象
適合對智慧體語言模型系統、模型微調、控制框架搜尋，以及聯合優化權重與執行流程感興趣的研究者與工程師。特別是關注如何透過交替更新模型參數與可執行 harness 程式碼來提升智慧體效能，並希望了解切換策略設計與多領域實證結果的讀者。

## 深度分析

#### 方法論解析

WHALE（Weight-Harness Alternating LEarning，權重-控制框架交替學習）把智慧體（agent）的整體效能視為由兩個互相耦合的變數共同決定：模型權重（weights）θ 與可執行的控制框架（harness）h。harness（控制框架）在此不僅是系統提示詞（system prompt），更包含工具綱要（tool schema）、上下文（context）管理、解析與執行邏輯、錯誤處理以及終止策略（termination policy）。論文將目標形式化為最大化聯合期望獎勵：

\[
J(\theta,h) \triangleq \mathbb{E}_{x\sim P}\mathbb{E}_{\tau\sim \pi_{\theta,h}(\cdot|x)}[R(x,\tau)]
\]

其中 πθ,h 是模型與 harness 共同誘導的軌跡（trajectory）分佈，R 為驗證器（verifier）給出的獎勵。由於 θ 與 h 透過 πθ,h 緊密耦合，同時更新兩者會造成信用分配（credit assignment）困難，因此 WHALE 採用交替優化（alternating optimization）策略：一次只更新一個組件，另一個組件保持固定。

**權重更新階段（Weight-update phase）**  
論文使用線上拒絕採樣微調（online rejection-sampling fine-tuning，online RSFT）來更新 θ。具體而言，在固定的 harness h 下，使用一個凍結的舊權重副本 θ_old 對每個提示（prompt）抽樣 G 條軌跡，只保留被 verifier 接受的 (x, τ) 對，再以監督式微調（supervised fine-tuning，SFT）更新 θ。這種做法屬於獎勵篩選的自我訓練（reward-filtered self-training）家族，相較於策略梯度（policy gradient）方法更為穩定且實作簡單。

**控制框架搜尋階段（Harness-search phase）**  
論文以 Meta-Harness 作為 harness 搜尋的實例。Meta-Harness 是一種基於大型語言模型（LLM）的程式碼搜尋器，會在固定 θ 的前提下，對可執行的 harness 程式碼提出修改提案，並透過多次 rollout（軌跡展開）評估其效能，從而選出更好的 harness。

**切換排程（Switching schedule）**  
WHALE 的核心設計問題在於「何時切換階段」。論文提出兩種策略：

1. **固定階段長度（fixed phase durations）**：在所有循環（cycles）中使用預先調好的超參數決定每階段持續多久。
2. **自適應 WHALE（adaptive WHALE）**：每個階段至少執行一個最小長度，之後監控當前階段的訓練訊號（training signal），當訊號不再改善時即切換。這種自適應耐心規則（adaptive patience rule）能在「收集足夠證據以區分真實進步與雜訊」和「避免對固定對應組件過度優化」之間取得平衡。

整體而言，WHALE 是一個模組化框架：權重更新與 harness 搜尋的具體演算法可以更換，重點在於透過交替（alternation）來解耦兩個不同時間尺度的優化過程。

#### 實驗數據解讀

論文使用 Qwen3.5-2B/4B 模型，在三個領域進行評估：搜尋問答（SearchQA）、具備程式碼執行（code execution）的數學推理（Math），以及西洋棋謎題（chess puzzles）。評估指標為最佳 mean@8 準確率（best mean@8 accuracy），即對每個問題抽樣 8 條軌跡後取平均，再計算最佳準確率。

**主要結果**  
WHALE 相較於僅更新權重（weight-only）、僅搜尋 harness（harness-only）以及 Fast-Slow Training（FST，快-慢訓練）等基線，在 best mean@8 accuracy 上分別提升 7.67–24.38 與 4.15–13.00 個百分點。這顯示：

- 單獨優化任一組件都會受另一個凍結組件的限制；
- 把 harness 搜尋空間從文字提示擴展到可執行程式碼，能帶來顯著增益；
- 交替式聯合優化優於僅聯合調整提示詞與權重的方法。

**瓶頸機制的對比**  
實驗觀察到不同領域存在不同的瓶頸：

- **SearchQA：harness 受限（harness-limited）**  
  單純的 harness 搜尋就能以遠少於 weight-only 的 rollout 次數達到 weight-only 的峰值準確率。這說明在搜尋問答中，檢索與證據整合的 harness 設計是主要瓶頸；一旦 harness 能正確取得證據，模型權重本身已足夠完成綜合。

- **Math：權重受限（weight-limited）**  
  在數學推理領域，harness 搜尋在權重更新前幾乎沒有幫助；直到經過一次小型權重更新後，同樣的 harness 搜尋才變得有效。這表示模型必須先具備一定的程式碼執行與推理能力，才能利用更好的 harness。

這兩種對比鮮明的機制說明了聯合優化的必要性：瓶領會隨領域與訓練階段而轉移，更新一個組件可以「解鎖」另一個組件的潛能。

**交替更新 vs. 階段式優化（stagewise optimization）**  
論文將 WHALE 與「先用完整預算更新權重，再一次性用完整預算搜尋 harness」的階段式優化比較。結果顯示，WHALE 的小規模交替更新在 SearchQA 與 Math 上分別提升 5.32 與 9.16 個百分點，並且僅需 29% 與 49% 的 rollout 數量即可超越階段式結果。這證明頻繁交替能更快適應瓶頸轉移，避免在已經不是瓶頸的組件上浪費預算。

**自適應策略的效果**  
在兩個評估領域中，自適應 WHALE（adaptive WHALE）的表現都優於經過調參的固定排程。這意味著自適應耐心規則不僅減少超參數調校負擔，也能根據每個循環的實際訓練動態做出更好的切換決策。

#### 與現有研究的比較

**相對於僅調整提示詞的聯合方法**  
過去同時調整模型權重與上下文的聯合適應方法（如 Soylu et al.、Zhang et al.、Tiwari et al.）大多把「上下文」限制在文字提示（textual prompts）。WHALE 則把搜尋空間擴展到完整的可執行 harness 程式碼，包括工具介面、編排邏輯、錯誤處理與終止條件。論文特別設計了 FST 控制組：使用與 WHALE 相同的更新方法與排程，但只允許修改系統與使用者提示詞。結果 WHALE 顯著優於該控制組，證明「harness 表達能力」本身才是效能差異的來源。

**相對於固定 harness 的模型訓練**  
多回合推理與工具使用（multi-turn reasoning and tool use）領域已有許多基於 SFT 或強化學習的訓練方法（如 ReAct、WebGPT、CodeAct 等），但它們通常假設 harness 固定不變。WHALE 的貢獻在於研究當 harness 也會共同演化時，如何穩定地訓練模型權重。

**相對於固定模型下的系統優化**  
另一條研究軸線是在固定模型權重下優化提示程式、代理架構或工作流程（如 DSPy、AutoGPT、Meta-Harness 等）。WHALE 把這條線與模型訓練線連接起來，透過交替執行獎勵篩選訓練與可執行 harness 搜尋，形成一個端到端的聯合優化流程。

**相對於其他聯合/交替優化方法**  
交替優化（alternating optimization）在數學上已有長期研究（Wright, 2015）。WHALE 把這個框架具體應用到權重-harness 耦合問題。與同時並行（concurrently）更新兩者相比，交替更新避免了「對應組件不斷漂移」所造成的混淆信用分配（confounding credit assignment），也迴避了兩個階段更新節奏不同所需的同步障礙（synchronization barriers）。

**限制**  
儘管 WHALE 展現了顯著進步，仍有以下限制：

- 實驗規模：僅使用 Qwen3.5-2B/4B，尚未驗證於更大模型（如 70B 等級）；
- 領域範圍：僅三個領域，且都具備明確 verifier，對開放式生成任務的適用性未知；
- 演算法選擇：權重更新固定使用 online RSFT，harness 搜尋固定使用 Meta-Harness，與其他訓練或搜尋演算法的組合效果未充分探討；
- 理論保證：目前缺乏收斂性證明或最優切換時間的理論分析；
- 評估指標：best mean@8 accuracy 對高變異方法較為寬鬆，可能無法完全反映最差-case 穩定性；
- 計算成本：harness 搜尋需要大量 rollout，對於需要呼叫外部 API 的 LLM 優化器而言成本不低。

#### 可重現性評估

論文作者已將程式碼公開於 GitHub（https://github.com/krafton-ai/WHALE），這是提升可重現性的重要基礎。若倉庫中包含完整的訓練配置、harness 模板、Meta-Harness 的提示詞與評估腳本，則其他研究者原則上能夠復現主要實驗。

**有利因素**

- 使用開放權重模型 Qwen3.5-2B/4B，取得門檻低；
- 採用明確的 verifier 與 best mean@8 accuracy 指標，評估流程相對客觀；
- online RSFT 與 Meta-Harness 都是模組化設計，便於替換與除錯。

**潛在障礙**

- Meta-Harness 作為 LLM-based optimizer，可能依賴特定的大型語言模型 API（如 GPT-4 等），不同 API 版本或取樣溫度會影響 harness 提案品質，造成難以完全復現；
- 自適應耐心規則（adaptive patience rule）的具體閾值、最小階段長度、訓練訊號定義等細節若未在論文或程式碼中完整揭露，會影響復現；
- harness 搜尋涉及大量 rollout，需要可觀的計算資源與時間；
- 資料集與驗證器的預處理流程（如 SearchQA 的檢索後處理、Math 的程式執行環境、chess puzzles 的棋局表示）若未詳細說明，也可能成為復現落差來源。

整體而言，程式碼公開大幅提升了可重現性，但要達到論文所報告的精確數字，仍需仔細對齊 API 版本、隨機種子（random seed）與計算預算。

#### 未來研究方向

**1. 理論基礎與最優切換策略**  
目前 WHALE 的切換排程仍屬啟發式。未來可針對交替權重-harness 優化建立收斂理論，分析在何種條件下交替更新能單調提升 J(θ,h)，並推導最優切換時間或動態預算分配公式。

**2. 瓶頸偵測與自適應資源分配**  
可設計專門的瓶頸偵測模組，根據 rollout 分佈、梯度大小或 harness 修改接受率，自動判斷當前是權重受限還是 harness 受限，並動態調整兩階段的計算預算。

**3. 跨規模與跨領域驗證**  
將 WHALE 應用於更大參數量的模型（如 14B、70B 甚至更大），以及更廣泛的任務（多模態工具使用、長期規劃、網頁導航、機器人控制等），以驗證其泛化能力。

**4. 與其他訓練/搜尋演算法的組合**  
除了 online RSFT，可嘗試結合強化學習（如 PPO、DPO、GRPO）或線上偏好學習作為權重更新；harness 搜尋也可嘗試程式合成（program synthesis）、演化演算法（evolutionary algorithms）或貝葉斯最佳化（Bayesian optimization）。

**5. 部分並行與多保真度評估**  
完全交替雖然簡潔，但可能犧牲效率。未來可研究在保持信用分配清晰的前提下，讓兩階段部分並行（partial concurrency），或使用低成本的代理模型（surrogate model）與多保真度評估（multi-fidelity evaluation）來降低 harness 搜尋的 rollout 成本。

**6. Harness 的安全性、可解釋性與版本控制**  
當 harness 被自動修改時，可能引入未預期的行為或獎勵駭取（reward hacking）。未來研究可加入形式化約束、人類回饋迴路（human-in-the-loop）以及 harness 版本控制機制，確保自動搜尋的 harness 穩定且可解釋。

**7. 知識蒸餾與單一模型化**  
最終目標可能是把搜尋到的 harness 能力蒸餾（distillation）回模型權重中，或訓練一個能夠根據任務動態調整自身控制流程的單一模型，從而減少對外部 harness 程式的依賴。

## 論文問答

**Q1：為什麼單獨優化模型權重或 harness 會讓智慧體系統遇到瓶頸？**  
A：因為智慧體效能同時取決於模型權重與可執行的 harness 程式碼，兩者會互相牽制。舉例來說，即使模型權重變強，若 harness 從未檢索到相關證據，模型也無法利用這些證據；反之，再好的檢索機制也無法彌補模型無法綜合證據的缺陷。因此只更新其中一個組件，系統遲早會被另一個凍結的組件限制住，形成所謂的「轉移瓶頸」。

**Q2：現有的聯合適應方法存在什麼主要限制？**  
A：現有方法大多只聯合調整模型權重與文字提示（prompt），卻把更廣泛的 harness 固定下來。然而，可執行的工具使用智慧體還涉及工具 schema、上下文管理、錯誤處理與終止策略等程式碼層面的設計，這些都會顯著影響效能。只優化文字提示會錯過對整體控制框架的調整，因此無法充分釋放模型與工具協作的潛力。

**Q3：為什麼協調權重訓練與 harness 搜尋特別困難？**  
A：兩個階段的時間尺度不同：harness 搜尋需要經歷漫長的提案與接受循環，並依賴大量 rollout 來評估；而線上微調則是在收集 rollout 與梯度更新之間快速交替。若同時並行執行，會因為對應組件不斷變動而混淆信用分配，或者因為更新節奏不一致而需要頻繁同步。WHALE 透過交替更新來迴避這個兩難，讓每個階段在固定對應組件的條件下進行最佳化。

**Q4：WHALE 的核心方法論是什麼？**  
A：WHALE 全名是 Weight-Harness Alternating LEarning，其基本做法是把聯合最佳化拆成兩個條件式更新階段：先在當前 harness 下更新模型權重，再在更新後的模型下搜尋更好的 harness。論文具體使用線上拒絕採樣微調（online RSFT）作為權重更新階段，並以 Meta-Harness 作為 harness 搜尋階段。兩個階段輪流進行，形成一個可循環的交替學習流程。

**Q5：WHALE 如何決定何時從權重更新切換到 harness 搜尋？**  
A：切換時機是 WHALE 的關鍵設計選擇，預設使用跨循環共用的固定階段長度。此外，論文提出自適應 WHALE，它在每個階段達到最小持續時間後，監控當前階段的訓練訊號，一旦訊號不再改善就切換。這種自適應耐心規則能夠在區分真實進步與雜訊的同時，避免對正在變動的對應組件過度擬合。

**Q6：WHALE 與 Fast-Slow Training（FST）的主要差異在哪裡？**  
A：FST 是論文用來隔離 harness 搜尋空間影響的控制變因，它使用與 WHALE 相同的更新方法與排程，但只允許調整系統提示與使用者提示。相較之下，WHALE 會對完整的可執行 harness 程式碼進行搜尋，包括工具介面、上下文管理與控制流程。實驗顯示，WHALE 在最佳 mean@8 準確率上比 FST 高出 4.15–13.00 個百分點，證明擴大搜尋空間的價值。

**Q7：實驗使用了哪些模型與評估領域？**  
A：實驗採用 Qwen3.5-2B 與 Qwen3.5-4B 作為基礎模型，並在三個領域進行評估：搜尋問答（SearchQA）、具備程式碼執行的數學推理（Math），以及西洋棋謎題（Chess puzzles）。這些領域分別涉及檢索工具、程式碼執行工具與策略規劃，能夠檢驗 harness 與權重在不同情境下的互動。比較對象包括僅更新權重、僅更新 harness，以及 Fast-Slow Training 等基線。

**Q8：WHALE 相較於各基線的效能提升為何？**  
A：在最佳 mean@8 準確率上，WHALE 比單一組件基線高出 7.67–24.38 個百分點，比 FST 高出 4.15–13.00 個百分點。此外，與階段式優化相比，WHALE 的小步交替更新在 SearchQA 與 Math 上分別提升 5.32 與 9.16 個百分點，並且只用了 29% 與 49% 的 rollout 數量就超越階段式結果。這顯示交替更新不僅更準確，也更節省評估成本。

**Q9：實驗觀察到哪些關於瓶頸轉移的現象？**  
A：研究發現不同領域的瓶領位置並不相同，說明聯合最佳化的必要性。在 SearchQA 中，系統偏向 harness 受限：單獨搜尋 harness 就能以遠少於權重-only 的 rollout 達到相近的峰值準確率。在 Math 中則偏向權重受限：同樣的 harness 搜尋在權重更新前幾乎沒有進步，直到一次小型權重更新後才顯著提升，顯示更新一個組件能夠解鎖另一個組件的潛能。

**Q10：WHALE 可應用於哪些實際產品場景？**  
A：任何需要模型與外部工具協作的智慧體系統都可能受益，例如企業搜尋問答、具備程式碼執行的數學家教、遊戲或西洋棋謎題求解器，以及自動化資料分析流程。透過同時調整模型行為與控制框架，產品可以在不更換基礎模型的情況下顯著提升任務完成率。此外，交替更新有助於在固定總預算內更快找到高品質的權重-harness 組合。

**Q11：在將 WHALE 產品化時需要考慮哪些成本與部署因素？**  
A：首先，harness 搜尋會產生並評估可執行程式碼，因此需要安全的沙箱環境與可靠的驗證器（verifier）來避免危險操作。其次，線上 RSFT 需要持續收集通過驗證的 rollout 並進行梯度更新，對運算與儲存資源有一定需求。最後，自適應 WHALE 雖然能減少不必要的 rollout，但仍需仔細設定最小階段長度與耐心閾值，以平衡探索效率與訓練穩定性。

**Q12：WHALE 對智慧體研究領域可能帶來什麼長期影響？**  
A：WHALE 把聯合最佳化的範圍從文字提示擴展到完整的可執行 harness，為未來的權重-harness 共同設計提供了模組化框架。它證明交替更新是一種可行且高效的協調策略，並揭示了瓶頸會隨領域與訓練階段轉移的現象。這將激勵更多研究探討切換準則、收斂理論，以及更廣泛的智慧體系統設計空間。

**Q13：論文承認 WHALE 有哪些限制？**  
A：研究只在三個領域與兩種模型規模上進行驗證，因此結果是否能推廣到更大模型或更複雜任務仍需更多實證。權重更新與 harness 搜尋分別固定使用 online RSFT 與 Meta-Harness，其他演算法組合的表現尚未全面探討。此外，自適應 WHALE 只在兩個領域中評估，其切換規則在更廣泛情境下的穩健性仍有待確認。

**Q14：WHALE 在哪些情況下可能失敗或表現不佳？**  
A：當 harness 搜尋空間過大或驗證訊號雜訊過高時，搜尋階段可能難以找到穩定改善的提案，導致資源浪費。若權重與 harness 之間存在強耦合，必須同時改變才能產生效果，則單純交替更新可能收斂緩慢或陷入局部最佳。此外，若階段長度設定不當，可能會在對應組件尚未穩定前就過度擬合，或錯過真正的進步訊號。

**Q15：未來有哪些值得探索的研究方向？**  
A：未來可以發展更精細的切換準則，例如基於統計檢定或模型不確定性的動態排程，並建立交替權重-harness 最佳化的理論收斂保證。另一個方向是設計能夠安全並行更新兩個組件的方法，以解決信用分配與同步問題。此外，也可將 WHALE 擴展到更複雜的 harness 設計，例如長期記憶、多智慧體協作、自動安全約束，以及與強化學習方法的結合。

## 實務應用指南

### 適用場景

1. **企業內部知識問答智慧體**  
   當檢索工具、提示詞與模型權重都需要隨資料與使用方式演進時，WHALE 可交替優化「如何檢索」的 harness 與「如何綜合證據」的模型權重，避免單獨調 prompt 或單獨 fine-tune 時被另一個組件卡住。

2. **數學／科學推理輔助系統**  
   需要程式碼執行、符號運算或多步驟驗證的場景。此類任務常出現「harness 先準備好工具，但模型還不會用」或「模型變強後需要新的觀察格式」的權重受限與 harness 受限交替現象，WHALE 的小步交替更新能逐步解鎖雙方能力。

3. **遊戲或棋類 AI 教練**  
   例如西洋棋謎題求解，harness 決定合法走法檢查、搜尋深度與終止條件，模型決定局面評估。WHALE 可同時調整走法介面與模型判斷，提升在固定運算預算下的最佳 mean@8 準確率。

4. **客服或流程自動化 agent**  
   當工具呼叫、錯誤處理與對話流程會影響最終任務完成率時，WHALE 能將「對話控制流程程式碼」納入聯合優化，而不只調整系統提示詞。

5. **需要持續學習的邊緣或垂直領域 agent**  
   例如醫療、法律或製造場景，任務分佈與工具介面會隨時間改變。WHALE 的模組化交替框架便於週期性地重新訓練權重並搜尋更適合當前模型的 harness。

---

### 實作前置條件

**資料條件**
- 具備可驗證答案的任務分佈：每個問題需有 ground-truth 或自動 verifier，因為 RSFT 與 harness 搜尋都依賴 accepted rollouts 的獎勵訊號。
- 足夠的 prompt 覆蓋度：建議每個階段至少有數百到數千筆不同難度的樣本，才能區分真實進步與抽樣雜訊。
- 軌跡可記錄：需要能完整記錄模型訊息、工具呼叫、執行結果與環境轉移的 trajectory。

**運算條件**
- 模型訓練資源：需支援小規模語言模型（如 Qwen3.5-2B/4B 等級）的 online fine-tune，至少一張高記憶體 GPU。
- 大量 rollout 預算：harness 搜尋與 RSFT 都需要多次抽樣與 verifier 評分，建議預留比單純 SFT 多 5–10 倍的推理運算。
- 可並行執行環境：工具呼叫、程式碼執行或環境模擬需要能批次執行，否則 rollout 成本會成為瓶頸。

**技能條件**
- 熟悉 rejection-sampling fine-tuning（RSFT）或類似的 reward-filtered SFT 流程。
- 能夠定義與修改 executable harness：包括系統指令、工具 schema、context 管理、錯誤處理與終止條件。
- 具備自動化 verifier 與實驗追蹤能力，因為 WHALE 需要監控每個階段的訓練訊號來決定是否切換。

---

### 實作步驟建議

1. **建立可量測的基線**  
   先固定一個合理的初始 harness 與初始模型，計算 mean@8 準確率與所需 rollout 數，作為後續比較基準。

2. **設計 harness 搜尋空間**  
   明確列出可變動的 harness 組件：系統提示、工具 schema、觀察注入方式、錯誤處理邏輯、終止條件等。建議從小範圍開始，避免搜尋空間過大導致訊號被雜訊淹沒。

3. **實作 online RSFT 權重更新階段**  
   使用 frozen copy 產生 rollouts，只保留 verifier 接受的軌跡進行 supervised fine-tuning。設定每個階段的最小與最大更新步數。

4. **實作 harness 搜尋階段（如 Meta-Harness）**  
   在當前權重固定下，對 harness 進行提案—評估—接受的循環。使用與 RSFT 相同的 verifier 與評估指標，確保兩個階段的訊號一致。

5. **選擇切換策略**  
   - **固定週期版**：預先調好每個階段的步數或 rollout 數，簡單但需網格搜尋。  
   - **自適應 WHALE**：在最小階段長度後，監控當前階段的訓練訊號（如 accepted ratio 或驗證準確率），當訊號不再提升時切換。實務上自適應版通常表現更好。

6. **小步交替，而非一次性 stagewise**  
   不要先把全部預算花在權重更新再跑一次 harness 搜尋。論文顯示小步交替能用更少 rollout 達到更高準確率，建議每個循環只做「夠區分訊號」的少量更新。

7. **持續監控瓶頸轉移**  
   記錄每個階段結束後的準確率與 rollout 成本。若 harness 搜尋幾乎無進展，可能處於權重受限，應先更新模型；若權重更新停滯，可能處於 harness 受限，應切換搜尋 harness。

8. **部署前凍結與回歸測試**  
   選出最佳 model–harness pair 後，在保留測試集與真實使用者分佈上驗證，並確認 harness 程式碼在生產環境可安全執行。

---

### 潛在風險與注意事項

- **訓練訊號雜訊過大**  
  若每個階段太短，會把抽樣雜訊誤認為進步；若太長，則會過度擬合當前固定的對應組件。建議設定最小階段長度，並使用自適應耐心規則來決定切換時機。

- **Verifier 偏誤**  
  Verifier 若過於寬鬆，RSFT 會收斂到「騙過 verifier」的軌跡；若過嚴，則 accepted rollouts 太少導致訓練資料不足。需定期檢查 accepted rollouts 的品質。

- **Harness 搜尋產生不穩定程式碼**  
  自動生成的 harness 程式碼可能引入無限迴圈、錯誤處理漏洞或不安全的工具呼叫。建議在沙箱中執行，並對 harness 變更做語法與行為約束。

- **權重與 harness 版本錯配**  
  生產環境若只更新模型卻沿用舊 harness，可能出現效能倒退。需將 model checkpoint 與 harness 程式碼視為一併版本化的 artifact。

- **運算成本膨脹**  
  交替過程中會重複產生大量 rollouts。建議先在小模型與子集資料上驗證切換策略，再放大到完整預算。

- **過度擬合特定 harness**  
  模型可能在某一 harness 下表現極佳，但換到下一個 harness 後失效。保留跨 harness 的驗證集可偵測此問題。

---

### 與其他技術的整合建議

- **與現有 MLOps 管線整合**  
  將 WHALE 的兩個階段視為獨立的訓練與搜尋工作：RSFT 可接入現有的 SFT / LoRA 訓練管線；Meta-Harness 可包裝成獨立的實驗任務，透過實驗追蹤工具記錄每次 harness 提案與分數。

- **與 prompt 優化工具搭配**  
  若現有系統已有 prompt 優化流程，可先將其視為 harness 搜尋空間的一部分，再逐步擴展到工具 schema、錯誤處理與控制流程。

- **與強化學習（RL）或 DPO 整合**  
  RSFT 只是權重更新的一種實例。若任務需要更細緻的偏好學習，可將 WHALE 的權重階段替換為 DPO、PPO 或 REINFORCE 變體，只要保持「固定 harness 下更新權重」的交替結構即可。

- **與檢索系統或工具庫整合**  
  Harness 搜尋可針對現有工具介面進行調整，例如改變檢索結果注入格式、重試次數或錯誤回傳訊息，無需從頭重建工具後端。

- **與評估平台整合**  
  將 verifier、mean@8 準確率與 rollout 成本自動回報到評估儀表板，便於觀察每個循環是否進入權重受限或 harness 受限階段。

### 給不同背景讀者的閱讀建議

**初學者**  
這篇論文的核心概念是：一個 agent 的表現不只取決於模型本身，也取決於控制流程與工具使用的「harness」程式碼。WHALE 的做法是輪流改進模型權重與 harness，而不是一次只調一邊。建議先理解「為什麼兩個組件會互相卡住」，再從實驗結果看不同任務（搜尋問答、數學、西洋棋）分別由哪一邊成為瓶頸，技術細節可暫時略過。

**AI 工程師**  
重點關注實作層面的交替節奏：online RSFT 如何產生 accepted rollouts、Meta-Harness 如何提案與評估 harness，以及固定週期與自適應耐心規則的切換邏輯。建議直接參考論文附錄與開源程式碼，並思考如何將現有 SFT 管線與 harness 搜尋任務拆成可獨立執行、可版本控制的模組。

**研究人員**  
本研究提供了一個「權重–harness」聯合優化的控制實驗框架，值得關注的是它如何將過去僅限於 prompt 與權重的聯合適應，擴展到可執行的 harness 程式碼。可進一步探討的問題包括：交替優化的收斂條件、不同權重更新方法（如 RL、DPO）與 harness 搜尋方法的組合、以及更廣泛的 harness 搜尋空間與理論保證。

**產品經理**  
這篇論文說明了一個產品洞察：單純提升模型或單純改流程都可能遇到天花板，而兩者小步交替優化能用較少成本突破瓶頸。評估時請注意 rollout 與訓練預算會顯著高於單一優化，且需要可驗證的任務與自動化評分機制。適合應用在已有明確成功指標、且工具流程複雜的 agent 產品。
