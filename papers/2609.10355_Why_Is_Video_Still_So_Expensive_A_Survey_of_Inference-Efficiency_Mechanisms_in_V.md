## ⚡ TL;DR

影片大型語言模型推論成本隨幀數與上下文激增，難以部署於即時與資源受限環境。
本文依管線階段統整幀取樣、視聽編碼、連接器 token 縮減與 LLM 推論之效率機制。
彙整文獻之準確度與成本比較，揭示視聽效率與標準化評估缺口，並維護資源儲存庫。

## 摘要翻譯

影片理解（video understanding）領域已迅速發展至影片大型語言模型（VideoLLMs）：這類系統將影片表徵與預訓練大型語言模型（pretrained large language models）結合，並以文字提示（textual prompt）為條件來生成。它們在影像敘述（captioning）、問答（question answering, QA）、檢索（retrieval）與時間定位（temporal grounding）等任務上表現優異，但伴隨著隨幀數（frame count）與上下文長度（context length）而增加的計算與記憶體成本（computation and memory cost），限制了其在即時（real-time）、行動裝置（mobile）與資源受限環境（resource-constrained settings）中的部署。本綜述涵蓋針對視覺與視聽影片大型語言模型（visual and audiovisual VideoLLMs）的推論效率機制（inference-efficiency mechanisms），這些機制在參數量（parameter count）、每輸入浮點運算次數（FLOPs per input）、延遲（latency）、記憶體（memory），或視覺 token 數量（visual token count）與音訊 token 數量（audio token count）方面報告了具體的降低。我們分析幀取樣（frame sampling）、模態編碼（modality encoding）、連接器層級 token 縮減（connector-level token reduction），以及 LLM 預填充（LLM prefilling）與 LLM 解碼（LLM decoding）等環節的瓶頸。我們依方法所作用的管線階段（pipeline stage）加以組織，涵蓋自 2022 年底以來發展出的 VideoLLM，以及至今仍為現有管線組成元件的早期幀取樣與視覺編碼器（vision encoder）機制。我們盡可能彙整文獻中在相同宿主模型（host model）與輸入協定（input protocol）下報告的準確度–成本比較（accuracy–cost comparison），並將其與異質的跨論文證據（heterogeneous cross-paper evidence）區分開來，同時指出視聽效率與標準化評估（standardized evaluation）方面的研究缺口。相關資源儲存庫（repository）維護於 https://github.com/momentslab/awesome-efficient-videollm。

### 核心貢獻（3～5點）
- 系統性回顧視覺與視聽 VideoLLM 的推論效率機制，依其所作用的管線階段組織，涵蓋幀取樣、模態編碼、連接器層級 token 縮減，以及 LLM 預填充與解碼等關鍵環節。
- 彙整文獻中在相同宿主模型與輸入協定下報告的準確度–成本比較，並將其與異質的跨論文證據區分開來，提升比較的可信度。
- 識別視聽效率與標準化評估方面的研究缺口，為後續研究指出具體方向。
- 維護一個相關資源儲存庫，供研究者追蹤此快速發展領域的方法與進展。

### 適合對象
從事多模態大型語言模型、影片理解、模型效率最佳化相關研究的研究人員與工程師，特別是關注即時、行動裝置與資源受限環境部署，以及希望系統性了解 VideoLLM 推論效率機制與瓶頸的讀者。

## 深度分析

#### 方法論解析

本調查論文（survey）並非提出單一模型，而是建立一套針對影片大型語言模型（VideoLLM）推論效率機制的系統性回顧框架。其核心方法論可從以下幾個層面拆解：

1. **四階段管線（pipeline stage）分類法**  
   作者將 VideoLLM 的推論流程劃分為四個主要階段，並額外標示「跨階段（joint stages）」方法：
   - **輸入建構（input construction）**：決定幀數（frame count）、區塊（patch）與解析度（resolution），例如自適應幀取樣（adaptive frame sampling）與關鍵幀選擇。
   - **編碼器運算（encoder computation）**：視覺骨幹網路（vision backbone）與音訊編碼器（audio encoder）的計算，例如輕量化視覺 Transformer、MobileCLIP、VideoMamba 等。
   - **表徵／連接器（representation/connector）**：將視覺／音訊特徵映射到大型語言模型（LLM）輸入空間，並進行 token 縮減，例如 Perceiver Resampler、Q-Former、LLaVA-PruMerge、SparseVLM 等。
   - **LLM 執行與狀態（LLM execution/state）**：涵蓋預填充（prefilling）、解碼（decoding）、鍵值快取（KV cache）管理與視覺 token 剪枝（visual token pruning）。
   - **跨階段方法**：同時在多個階段降低成本的設計，例如動態解析度與幀數聯合調整。

2. **納入標準：必須報告具體的成本降低指標**  
   作者明確限定只收錄在以下至少一項指標上提出具體改善的工作：參數量（parameter count）、每輸入浮點運算次數（FLOPs per input）、延遲（latency）、記憶體（memory）、視覺 token 數量（visual token count）或音訊 token 數量（audio token count）。這項篩選標準使本調查與一般性架構回顧區隔，聚焦於「可量化的推論效率」。

3. **時間軸與方法清單（Figure 1）**  
   論文以時間軸方式呈現 2014 年至 2026 年的相關方法，並以顏色標示其所作用的管線階段。值得注意的是，作者刻意納入 2022 年底 VideoLLM 興起之前的幀取樣（frame sampling）與視覺編碼器（vision encoder）研究，因為這些機制至今仍構成現代 VideoLLM 管線的元件。這種「縱向整合」有助於理解當前效率技術的歷史脈絡。

4. **準確度–成本比較（accuracy–cost comparison）的彙整策略**  
   作者嘗試在「共享宿主模型（shared host model）」與「相同輸入協定（input protocol）」下，彙整文獻中報告的準確度與成本數據；無法滿足此條件者則標示為異質跨論文證據（heterogeneous cross-paper evidence）。這種區分對於避免不正確的跨方法排名至關重要，因為不同論文常使用不同的 LLM 骨幹、解析度、幀數與評估基準。

5. **視聽（audiovisual）系統的擴展**  
   除了純視覺 VideoLLM，作者特別納入視聽模型，討論音訊 token 壓縮（audio token compression）與聲音引導視覺選擇（sound-guided visual selection）等機制，並指出此領域的效率研究仍相對不足。

#### 實驗數據解讀

作為調查論文，本研究的「實驗」並非執行新的訓練或推論，而是對現有文獻中的效率–準確度數據進行後設分析（meta-analysis）。以下為數據解讀的關鍵觀察：

1. **評估指標的異質性（heterogeneity）**  
   - **準確度指標**：涵蓋影像敘述（captioning）的 CIDEr／SPICE、問答（QA）的 top-1 accuracy、檢索（retrieval）的 R@K、時間定位（temporal grounding）的 mIoU 與 R@1 等。不同任務對幀數與 token 密度的敏感度不同，例如時間定位通常需要較密集的時間取樣，而高階語義摘要可能只需少數關鍵幀。
   - **成本指標**：包括參數量（parameter count）、浮點運算（FLOPs）、延遲（latency）、記憶體（memory）與 token 數量。這些指標彼此並非完全線性相關；例如減少視覺 token 數量可顯著降低 KV cache 記憶體，但對編碼器 FLOPs 的影響可能有限。

2. **各階段效率機制的取捨（trade-off）**  
   - **幀取樣（frame sampling）**：減少輸入幀數可線性降低編碼器與連接器成本，但過度稀疏化容易遺失短暫事件或快速動作，對精細時間定位任務傷害較大。
   - **連接器層級 token 縮減（connector-level token reduction）**：透過 Perceiver、query-based transformer 或剪枝策略壓縮視覺 token，可顯著降低 LLM 預填充（prefilling）階段的計算與記憶體開銷；然而過度壓縮可能損害需要細粒度空間推理的任務。
   - **LLM 內部剪枝與 KV cache 管理**：在解碼（decoding）階段減少視覺 KV cache 可緩解長影片的記憶體瓶頸，但需注意自迴歸生成過程中資訊遺失的累積效應。
   - **視聽壓縮**：音訊 token 壓縮與聲音引導選擇能減少多模態輸入長度，但目前文獻數量較少，且多數方法僅在特定語音或聲音事件任務上驗證。

3. **共享宿主模型比較的價值與限制**  
   作者強調只有在相同宿主模型（host model）與輸入協定（input protocol）下，才能進行公平的準確度–成本比較。然而現有文獻中，許多方法僅在自有的模型組合上報告結果，導致跨論文比較往往只能提供質性趨勢，而非嚴格的帕累托（Pareto）排序。本調查透過標示「同質」與「異質」證據，幫助讀者辨識哪些結論具有較高的可信度。

4. **明顯的研究缺口**  
   數據彙整顯示，視聽（audiovisual）效率、長時間上下文（long temporal context）的標準化評估、以及動態預算分配（dynamic budget allocation）仍是未充分探索的領域。多數現有方法仍針對單一階段進行優化，缺乏跨階段聯合設計的系統性比較。

#### 與現有研究的比較

本調查在現有文獻中的定位可從以下幾個面向理解：

1. **與能力導向回顧的區隔**  
   Madan et al.、Nguyen et al.、Tang et al. 等人主要回顧影片基礎模型（video foundation model）、影片–語言學習與 VideoLLM 架構，重點放在能力、任務與基準測試（benchmark）。相較之下，本調查專注於「推論效率機制」，並以成本指標作為納入門檻。

2. **與效率導向回顧的差異**  
   - Jin et al. 涵蓋高效能多模態大型語言模型（MLLM），但影片僅作為應用場景之一，未深入探討影片特有的時間取樣與長上下文問題。
   - Shao et al. 從機制中心視角整理影像、影片與音訊的 token 壓縮方法，並在特定宿主模型與 token 預算下進行比較。本調查在此基礎上進一步納入幀取樣（frame sampling）與輕量化視覺編碼器（efficient vision encoder），並將討論擴展至 LLM 預填充與解碼階段。
   - Zhang et al. 採用管線視角分析大型視覺語言模型（LVLM）推論，但主要聚焦編碼、預填充與解碼。本調查則將影片特有的輸入建構與編碼器設計納入同一框架，並特別處理視聽（audiovisual）情境。

3. **本調查的貢獻與優勢**  
   - **縱向涵蓋範圍廣**：納入 VideoLLM 出現之前的幀取樣與視覺骨幹研究，有助於理解現有元件的歷史演進。
   - **明確的成本指標門檻**：避免將僅具概念性貢獻的方法與真正降低推論成本的方法混為一談。
   - **區分同質與異質證據**：提升跨方法比較的嚴謹性。
   - **突顯視聽效率缺口**：將音訊 token 壓縮與聲音引導選擇納入討論，填補既有回顧的空白。

4. **限制與挑戰**  
   - 作為調查，其結論受制於原始文獻的報告品質與可取得性；若原始論文未公開程式碼或模型權重（model weights），則難以獨立驗證。
   - 影片領域的評估協定（evaluation protocol）高度異質，即使作者嘗試彙整共享宿主模型的比較，仍有大量方法無法直接對齊。
   - 調查為靜態快照，而 VideoLLM 領域發展迅速，部分最新方法可能未被完整涵蓋。
   - 對於「為何影片推論仍昂貴」這一核心問題，雖然論文從管線各階段分析瓶頸，但尚未提供統一的量化分解（例如各階段在總延遲中的精確佔比），這部分仍有賴未來的標準化剖析工具。

#### 可重現性評估

1. **儲存庫（repository）與資源開放性**  
   作者維護了一個 GitHub 儲存庫：`awesome-efficient-videollm`，用於整理所回顧的方法清單與相關資源。對於調查論文而言，這是提升可重現性（reproducibility）與可追蹤性的重要基礎，讀者可以透過該儲存庫快速定位原始論文、官方程式碼與模型檢查點（checkpoint）。

2. **調查本身的可重現性**  
   - 本論文未提出新模型，因此不涉及訓練程式碼或模型權重的釋出。
   - 其可重現性主要體現在文獻篩選過程、分類架構與比較表格的透明度。若作者能在儲存庫中提供篩選準則、納入／排除清單，以及用於生成圖表的原始數據（例如 CSV 表格與繪圖腳本），將進一步提升後續研究者驗證與擴充的可能性。

3. **底層方法的可重現性落差**  
   - 幀取樣（frame sampling）與輕量化視覺編碼器（efficient vision encoder）等較早期方法，通常有較完整的開源實作與預訓練權重。
   - 近期的連接器（connector）壓縮、LLM 內部 token 剪枝與 KV cache 管理方法，部分僅釋出推論程式碼或示範腳本，完整訓練程式碼與模型權重未必公開。
   - 視聽（audiovisual）方法由於涉及多模態資料前處理與對齊，重現門檻通常更高。

4. **對可重現性的建議**  
   - 將比較表格以結構化格式（如 CSV 或 JSON）釋出，並標註每筆數據的來源論文、宿主模型、輸入協定與評估基準。
   - 在儲存庫中建立「標準化評估套件」的雛形，例如固定使用 LLaVA-1.5、Qwen2-VL 或 InternVL2.5 作為宿主模型，並提供統一的幀取樣、解析度與 token 預算設定。
   - 鼓勵未來研究在發表時同時釋出推論延遲（latency）、記憶體（memory）與 FLOPs 的測量腳本，以便納入後續調查。

#### 未來研究方向

基於本調查所揭示的瓶頸與缺口，以下為具潛力的後續研究方向：

1. **視聽（audiovisual）聯合效率優化**  
   現有視聽 VideoLLM 多數直接將音訊編碼器輸出拼接至 LLM，缺乏針對音訊 token 的專門壓縮機制。未來可探索：
   - 音訊事件驅動的視覺幀選擇（sound-guided temporal sampling）。
   - 跨模態冗餘消除，例如當音訊已提供足夠語義時，降低對應時段視覺 token 的密度。
   - 音訊專用的 KV cache 壓縮與解碼加速策略。

2. **動態與自適應推論預算分配**  
   目前多數方法採用固定幀數或固定 token 預算。未來可發展：
   - 依據影片內容複雜度、任務需求與硬體限制，動態調整幀取樣率與 token 壓縮率。
   - 強化學習（reinforcement learning）或神經架構搜尋（NAS）輔助的端到端預算策略。
   - 線上／串流影片（streaming video）場景中的自適應快取與早期退出（early-exit）機制。

3. **長時間上下文（long temporal context）的 LLM 優化**  
   隨著影片長度增加，LLM 的 KV cache 與注意力計算（attention compute）成為主要瓶頸。未來方向包括：
   - 針對視覺 token 設計的長上下文注意力近似（long-context attention approximation）。
   - 狀態空間模型（state-space model, SSM）或線性注意力（linear attention）在 VideoLLM 中的應用。
   - 分層式記憶體管理，例如將遠距離視覺資訊壓縮為語義摘要 token。

4. **跨管線階段的聯合最佳化**  
   現有研究多針對單一階段（如僅優化幀取樣或僅優化連接器）。未來應發展：
   - 同時考慮輸入建構、編碼器、連接器與 LLM 執行的聯合目標函數。
   - 可微分的 token 預算分配，使幀選擇與 token 壓縮能夠端到端學習。
   - 針對特定下游任務（如時間定位 vs. 摘要）設計階段間協同機制。

5. **標準化評估與基準測試**  
   為了讓不同效率機制能夠公平比較，未來需要：
   - 建立固定宿主模型（host model）與輸入協定（input protocol）的評估平台。
   - 統一報告 FLOPs、延遲（latency）、記憶體（memory）、視覺 token 數量與準確度。
   - 納入行動裝置（mobile）與邊緣裝置上的真實推論延遲與能耗（energy consumption）指標。

6. **硬體感知（hardware-aware）的效率技術**  
   除了演算法層面的 token 與幀數縮減，未來可結合：
   - 針對 VideoLLM 連接器與多模態 LLM 的量化（quantization）、剪枝（pruning）與知識蒸餾（knowledge distillation）。
   - 編譯器與核心（kernel）層級優化，以充分發揮稀疏化或動態計算的硬體潛力。

7. **效率機制的可解釋性（interpretability）**  
   理解哪些視覺 token 或幀可以被安全移除，對於設計更穩健的壓縮策略至關重要。未來可發展：
   - 視覺 token 重要性估計與任務相關性分析。
   - 針對不同任務（問答、時間定位、檢索）的剪枝敏感度研究。
   - 可解釋的動態取樣決策視覺化工具。

## 論文問答

**Q1：這篇調查論文主要想解決什麼問題？**
A：這篇調查聚焦於影片大型語言模型（VideoLLM）在推論階段的高昂成本，特別是隨著幀數、解析度與上下文長度增加，計算量、記憶體需求與延遲都會快速上升。這樣的成本讓即時應用、行動裝置部署以及資源受限環境中的影片理解變得困難。因此，作者系統性地檢視各種能夠降低參數量、每輸入浮點運算次數（FLOPs）、延遲、記憶體以及視覺或音訊 token 數量的推論效率機制。

**Q2：為什麼現有的效率提升方法仍無法完全解決影片推論昂貴的問題？**
A：許多效率機制是針對特定任務或特定宿主模型單獨提出的，彼此之間難以直接比較。此外，不同研究使用的評估指標、輸入協定與測試條件差異很大，導致難以判斷成本究竟集中在哪個管線階段，也難以確認哪種策略在給定預算下最有效。再加上早期幀取樣與視覺編碼器方法常被直接嵌入現代 VideoLLM 管線，卻缺乏與連接器層級和 LLM 端優化的統一分析。

**Q3：研究 VideoLLM 推論效率的重要性為何？**
A：影片理解正朝向開放式、長上下文與多模態推理發展，這需要超越資料中心的可擴展部署能力。降低參數量、FLOPs、延遲與記憶體不僅能讓行動裝置、第一人稱視角助理與串流平台即時運行，也能擴大應用場景到邊緣運算。系統性的調查能幫助研究者與工程師辨識真正的瓶頸，並針對不同管線階段選擇最合適的效率機制。

**Q4：這篇調查的核心方法論架構是什麼？**
A：作者將推論效率機制按照標準 VideoLLM 管線劃分為四個階段：輸入建構、視覺骨幹網路編碼、連接器層級的表徵縮減，以及 LLM 的預填充與解碼。除了單階段方法外，調查也涵蓋同時作用於多個階段的聯合機制。這種以管線階段為中心的分类法能夠把上游的幀取樣、解析度選擇與下游的 token 預算和記憶體成本連結起來，例如 Figure 1 中的 Frame-Voyager、VisionZip、LongVU 與 StreamKV 等方法即分屬不同階段。

**Q5：這篇調查相較於以往文獻的主要創新貢獻是什麼？**
A：不同於過去聚焦於通用多模態大型語言模型或單純 token 壓縮的綜述，本文明確涵蓋幀取樣、輕量化視覺編碼器、連接器壓縮以及 LLM 端優化，並同時納入視覺與視聽 VideoLLM。作者盡可能在共享宿主模型與輸入協定的條件下彙整文獻中的準確度–成本比較，並將其與異質的跨論文證據區分開來。這樣的綜合分析揭示了視聽效率與標準化評估方面的研究缺口，是過去相關綜述較少觸及的。

**Q6：作者在比較不同方法時強調哪些設計選擇？**
A：調查強調每個方法作用的管線階段、所降低的成本指標，以及其評估時使用的宿主模型與輸入協定。作者區分了減少視覺 token 數量、音訊 token 數量、FLOPs、延遲或記憶體的不同機制，並注意增益是否在同一骨幹網路上報告。這種階段化且指標導向的組織方式讓能力與效率之間的權衡變得更加透明。

**Q7：這篇調查涵蓋了哪些基準測試與任務？**
A：調查文獻橫跨影像敘述、問答、檢索、時間定位與密集摘要等影片–文字任務。資料來源包括短社群影片、教學影片、電影以及長時間第一人稱視角錄影，反映了多樣的空間、時間與多模態需求。作者指出，這些任務的評估協定與指標仍然相當異質，使得直接比較不同方法的效果變得困難。

**Q8：關於準確度與成本權衡，調查有哪些關鍵發現？**
A：調查發現效率增益高度依賴管線階段與宿主模型，沒有任何單一方法在所有設定下都佔優勢。在共享宿主模型與輸入協定的條件下，部分連接器層級 token 縮減與幀取樣策略能在大幅降低 FLOPs 或記憶體的同時維持準確度，但過度壓縮通常會損害時間推理能力。跨論文證據則必須謹慎解讀，因為不同研究使用的幀數、解析度與評估指標往往不一致。

**Q9：這篇調查對消融研究與控制比較有什麼看法？**
A：作者強調，只有部分文獻在相同 VideoLLM 骨幹與輸入協定下進行控制消融，而這對於孤立出單一效率機制的真實影響至關重要。許多研究同時改動多個管線階段，或與不匹配的基線比較，導致難以將增益歸因於特定設計選擇。因此，調查將內部控制比較與異質跨論文證據分開處理，以避免得出誤導性結論。

**Q10：哪些實際應用場景最能受惠於這些效率機制？**
A：即時影片字幕生成、行動裝置上的第一人稱視角助理、直播內容審核以及資源受限的邊緣裝置都是主要受惠者。這些應用需要在處理長影片或高解析度輸入的同時保持低延遲與小記憶體佔用。減少視覺 token 數量、壓縮音訊 token 或縮小鍵值（KV）快取等機制，對於裝置端與串流部署特別重要。

**Q11：在產品化過程中，選擇效率機制時需要考慮哪些因素？**
A：產品團隊必須在準確度、延遲、記憶體與功耗之間取得平衡，並根據目標裝置與使用情境做出取捨。例如，幀取樣策略對短影片可能足夠，但對精細時間定位任務可能遺漏關鍵畫面；而過度激進的 token 剪枝雖能加速預填充，卻可能犧牲推理品質。這篇調查以管線階段為基礎的分類法，能幫助團隊判斷是編碼、連接器映射還是 LLM 解碼才是自家產品真正的瓶頸。

**Q12：這篇調查可能對高效率影片理解領域產生什麼影響？**
A：透過將原本碎片化的研究統整為以管線階段為導向的框架，這篇調查能引導未來研究關注視聽效率與標準化基準等較少探索的領域。它鼓勵研究者在共享宿主模型與輸入協定下報告準確度–成本比較，從而促成更公平的評估。長遠來看，這有助於加速開發可部署於真實資源受限環境的 VideoLLM。

**Q13：這篇調查承認了哪些限制？**
A：調查受限於文獻中可取得指標的完整性與一致性，許多研究並未使用相同宿主模型或輸入協定。因此，部分比較仍屬質性分析，或必須依賴異質的跨論文證據，而非嚴格控制實驗。此外，由於該領域演變迅速，新的方法與基準可能會使調查收錄的內容快速過時。

**Q14：這些效率機制可能出現哪些失效案例或風險？**
A：過度激進的幀取樣可能遺漏快速或細微事件，而過度剪枝視覺 token 則可能移除時間定位或多模態推理所需的關鍵細節。聲音引導視覺選擇在聲音線索模糊或缺失時可能失效，輕量化視覺編碼器也可能在高解析度或長上下文影片中降低表徵品質。這些權衡意味著效率提升往往伴隨著對困難輸入魯棒性的下降。

**Q15：這篇調查提出了哪些未來研究方向？**
A：未來應發展能同時衡量準確度、延遲、記憶體與 FLOPs 的標準化評估協定，並在共享 VideoLLM 骨幹下進行測試。視聽效率仍有許多研究空間，包括聲音引導取樣與音訊 token 壓縮，以及能夠聯合優化四個管線階段的機制。最後，長上下文與串流影片場景仍屬未充分探索的領域，需要能根據內容與硬體限制動態調整的效率方法。

## 實務應用指南

### 適用場景

**即時影片內容審核與安全監控**
適用於社群平台、直播串流或公共安全監控系統，需要在邊緣裝置或低延遲雲端環境中持續分析影片內容。透過幀取樣、視覺 token 剪枝與輕量化視覺骨幹網路，可在不處理每一幀的前提下，偵測暴力、不當內容或異常事件，並將延遲控制在可接受範圍內。

**行動裝置上的影片問答與輔助說明**
適用於視障輔助、教育學習或現場維修指引等應用，使用者透過手機拍攝影片並以文字提問。由於行動裝置的計算與記憶體資源受限，必須採用連接器層級 token 縮減、KV 快取壓縮與小型化 VideoLLM，才能在裝置端或近端伺服器完成推論。

**長影片檢索與時間定位**
適用於新聞資料庫、會議記錄、運動賽事分析或影視後製，需要從數小時影片中找出特定事件發生的時間點。透過幀選擇策略與長時間上下文處理機制，可減少 LLM 預填充階段的計算量，同時保留關鍵時間資訊。

**視聽多模態內容理解**
適用於影音平台自動生成字幕、Podcast 內容摘要、電影場景分析或客服錄音錄影檢閱。結合音訊 token 壓縮與聲音引導視覺選擇，可降低多模態輸入帶來的 token 數量與記憶體開銷。

**自動駕駛與機器人視覺感知**
適用於需要連續處理高解析度幀與長時間上下文的嵌入式系統。透過輕量化編碼器、動態 token 縮減與串流式記憶體管理，可在車載電腦或機器人控制器上執行場景理解與決策輔助。

### 實作前置條件

**資料準備**
需要具備與目標應用領域相符的影片資料，並清楚定義輸入協定，包括解析度、幀率、片段長度與音訊取樣格式。若應用涉及問答或時間定位，需準備對應的標註資料或評估基準，例如 MSRVTT、ActivityNet-QA 或 Ego4D。對於資源受限環境，建議先建立小型驗證集，用於比較不同效率機制在準確度與成本上的權衡。

**計算資源**
開發階段建議至少配備一張具備充足 VRAM 的 GPU，用於載入預訓練大型語言模型與視覺編碼器。部署階段則需根據目標延遲與吞吐量，選擇雲端 GPU、邊緣裝置或行動晶片。若採用 KV 快取壓縮或連接器層級 token 縮減，需額外評估推論時記憶體開銷與快取管理策略。

**技術能力**
團隊需熟悉深度學習框架、多模態模型架構與推論最佳化技術，包括模型量化、剪枝、注意力機制與快取管理。同時需要具備影片處理與音訊前處理經驗，並能閱讀與重現 VideoLLM 相關論文的實驗設定，以便在共享宿主模型與輸入協定下進行公平比較。

### 實作步驟建議

**步驟一：定義成本瓶頸與效能目標**
先分析應用場景中計算成本的主要來源，是來自視覺編碼器處理高解析度幀、連接器產生過多視覺 token，還是 LLM 預填充與解碼階段的注意力計算。同時設定明確的延遲、記憶體上限與準確度門檻，作為後續選擇效率機制的依據。

**步驟二：選擇基礎 VideoLLM 與輸入協定**
選定一個與任務匹配的宿主模型，例如基於 LLaVA、Qwen2-VL 或 InternVL 的影片理解模型。固定輸入協定，包括幀數、解析度與音訊編碼方式，確保後續比較不同方法時具有一致性。

**步驟三：從輸入建構階段開始最佳化**
優先評估幀取樣與畫面選擇策略，例如均勻取樣、基於重要性的動態選擇或場景變化偵測。此階段的改動通常影響最大且風險較低，因為不會改變模型架構。

**步驟四：最佳化編碼器與連接器**
若輸入階段仍無法滿足成本限制，可考慮更換輕量化視覺骨幹網路，或採用 token 壓縮、池化與剪枝技術來減少連接器輸出的視覺 token 數量。對於視聽系統，同步評估音訊 token 壓縮與聲音引導視覺選擇。

**步驟五：最佳化 LLM 執行與記憶體管理**
在 LLM 預填充與解碼階段，導入 KV 快取壓縮、視覺 token 剪枝或串流式記憶體機制，以降低長影片帶來的上下文長度壓力。若需處理極長影片，可採用分層或滑動視窗策略。

**步驟六：建立標準化評估流程**
在相同宿主模型與輸入協定下，記錄參數量、每輸入 FLOPs、延遲、記憶體使用量與視覺 token 數量，並與準確度指標一同呈現。區分同論文內比較與跨論文異質證據，避免過度推論。

**步驟七：部署與持續監控**
將最佳化後的模型部署至目標環境，並持續監控實際延遲、錯誤率與使用者回饋。根據線上表現調整幀取樣密度、token 預算與快取策略。

### 潛在風險與注意事項

**過度壓縫導致語義遺失**
過度減少幀數或視覺 token 數量，可能遺失快速發生的關鍵事件或細微動作。建議在應用相關的長尾場景上進行驗證，並保留動態調整 token 預算的機制。

**跨論文比較失真**
不同研究使用不同的宿主模型、輸入協定與評估基準，直接比較數字可能產生誤導。應優先參考在共享模型與設定下的實驗結果，並將跨論文證據視為方向性參考。

**音視訊不同步或模態失衡**
在視聽系統中，過度壓縮音訊 token 或僅依賴聲音引導視覺選擇，可能導致語音與畫面不同步，或忽略靜音但視覺重要的片段。需設計模態權重調整與對齊檢查機制。

**長影片的上下文遺忘**
即使採用 KV 快取壓縮，極長影片仍可能出現早期內容遺忘。建議評估模型在長時間上下文上的時間定位能力，必要時採用分段摘要或記憶體增強機制。

**部署環境與開發環境差異**
開發階段使用高階 GPU 測得的延遲與記憶體數據，可能無法直接反映邊緣裝置或行動裝置上的表現。應盡早在目標硬體上進行原型驗證。

### 與其他技術的整合建議

**與向量資料庫與檢索系統整合**
對於長影片檢索應用，可先將影片分段並提取緊湊的視覺特徵，存入向量資料庫。查詢時僅召回相關片段送入 VideoLLM，結合連接器層級 token 縮減，可大幅降低 LLM 預填充成本。

**與傳統電腦視覺管線整合**
在進入 VideoLLM 前，可先使用輕量物件偵測、場景切換偵測或動作辨識模型進行預篩選，將候選幀或片段餵入語言模型。這種混合式架構能減少無意義幀的編碼成本。

**與邊緣運算與模型服務框架整合**
部署時可結合 TensorRT、ONNX Runtime、vLLM 或專為多模態設計的推論框架，進一步降低延遲與記憶體開銷。KV 快取管理與連續批次處理是提升吞吐量的關鍵。

**與音訊處理技術整合**
對於視聽應用，可先使用語音辨識或音效分類模型提取結構化資訊，再與壓縮後的音訊 token 一起輸入模型。這樣既能保留語義，也能減少原始音訊特徵的計算量。

**與資料標註與回饋迴路整合**
建立線上錯誤回饋機制，將模型在困難樣本上的表現回傳至訓練或提示工程流程，持續改善幀選擇策略與 token 壓縮閾值。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先從本調查的圖一與管線四階段架構入手，理解影片大型語言模型從幀取樣、視覺編碼、連接器映射到 LLM 執行的完整流程。不必急著深入每個技術細節，重點是認識「為什麼影片推論昂貴」以及「降低成本有哪些大方向」。遇到專有名詞時，可對照文末詞彙表，建立對 FLOPs、KV 快取、視覺 token 等核心概念的直覺。

**給 AI 工程師**
建議聚焦於各管線階段的具體方法與實作權衡，特別是幀選擇、連接器 token 縮減與 KV 快取壓縮這三個對延遲與記憶體影響最大的環節。閱讀時可同步對照論文提供的儲存庫連結，尋找可重現的程式碼與預訓練模型。實作時務必在相同宿主模型與輸入協定下進行基準測試，避免被跨論文的異質數據誤導。

**給研究人員**
本調查整理了自 2022 年底以來的 VideoLLM 效率機制，並納入早期仍被現有管線採用的幀取樣與視覺編碼器方法。建議從文獻中的準確度–成本比較表格出發，辨識目前評估標準化的缺口，特別是視聽效率與長影片一致性評估方面的不足。可進一步探索如何設計統一的評估協定，或提出能同時作用於多個管線階段的聯合最佳化方法。

**給產品經理**
建議將本調查視為技術選型的參考地圖，重點關注適用場景、成本指標與部署限制之間的對應關係。不必深入每個演算法細節，但需理解不同效率機制對使用者體驗的影響，例如幀取樣過低可能遺失關鍵事件、KV 快取壓縮可能影響長影片問答品質。與工程團隊討論時，可要求對方以固定輸入協定呈現延遲、記憶體與準確度的權衡數據，作為產品決策依據。
