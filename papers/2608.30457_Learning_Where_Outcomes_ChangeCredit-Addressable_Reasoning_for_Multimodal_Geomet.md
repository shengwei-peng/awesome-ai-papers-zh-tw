## 摘要翻譯

多模態幾何推理（Multimodal Geometry Reasoning）要求視覺語言模型（Vision-Language Models, VLMs）擷取精確的視覺關係（visual relations），並在多步驟演繹（multi-step deduction）中維持這些關係。現有的自由形式推理軌跡（free-form reasoning traces）掩蓋了決定答案的關鍵決策，而軌跡層級強化學習（trajectory-level reinforcement learning）則將單一終端訊號分散至整個回應。我們提出信用可定址推理（Credit-Addressable Reasoning），其中推論期間呈現的語義單元（semantic units）也定義了學習應在何處比較替代方案並分配信用（credit）。我們以程式化思維鏈（Code-CoT, Code Chain-of-Thought）具現化此一原則：它保留圖表（diagram）、將視覺關係表示為行可定址可執行程式碼（line-addressable executable code），並將推理組織為類型化事件（typed events）；並透過信用事件 GRPO（CE-GRPO, Credit-Event Group Relative Policy Optimization），利用結構先驗（structural priors）與類型正規化熵（type-normalized entropy）選擇事件邊界（event boundaries）、從共享前綴（shared prefixes）取樣完整接續（continuations），並將結果差異（outcome differences）轉換為局部優勢（localized advantages）。橫跨九個幾何基準測試（geometry benchmarks），CE-GRPO 的平均準確率（average accuracy）達 76.04，分別比 Qwen3-VL-8B 與軌跡層級 GRPO（trajectory-level GRPO）高出 8.09 與 3.43 個百分點。其相對優勢隨中間事件（intermediate events）數量增加而提升，顯示出表示法與最佳化共同設計（representation–optimization co-design）對於長程、高度依賴的多模態推理（long, dependency-heavy multimodal reasoning）之價值。

### 核心貢獻（3～5點）
- 提出「信用可定址推理」（Credit-Addressable Reasoning）框架，讓推論時暴露的語義單元同時成為學習比較替代方案與分配信用的位置。
- 設計 Code-CoT（程式化思維鏈）表示法：保留圖表、將視覺關係編碼為行可定址可執行程式碼，並將推理組織為類型化事件。
- 提出 CE-GRPO（信用事件 GRPO）：利用結構先驗與類型正規化熵選擇事件邊界，從共享前綴取樣完整接續，並將結果差異轉換為局部優勢。
- 在九個幾何基準測試上驗證，CE-GRPO 平均準確率達 76.04，顯著優於 Qwen3-VL-8B 與軌跡層級 GRPO，且優勢隨中間事件數量增加而放大。

### 適合對象
適合對多模態推理、視覺語言模型、數學推理與強化學習感興趣的研究者與工程師，特別是關注長程推理、信用分配問題，以及幾何問題求解中視覺與符號表示整合的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心問題意識：表示缺口（Representation Gap）與信用缺口（Credit Gap）

本論文指出多模態幾何推理（Multimodal Geometry Reasoning）存在兩個互相糾纏的缺口：

- **表示缺口（Representation Gap）**：決定答案的關鍵視覺決策——例如**物件綁定（Object Binding）**、**角度詮釋（Angle Interpretation）**、**輔助構造（Auxiliary Construction）**——在**自由形式推理軌跡（Free-form Reasoning Trace）**中隱而不顯。
- **信用缺口（Credit Gap）**：傳統**軌跡層級（Trajectory-level）**強化學習只給整段回應一個終端獎勵，無法區分「哪一個中間決策」導致答案對錯。

作者提出的解方是**信用可定址推理（Credit-Addressable Reasoning）**：推論時暴露的語義單元（Semantic Units），同時也是學習時比較替代方案與分配**信用（Credit）**的位置。

##### 2. Code-CoT：把視覺關係變成「行可定址」的事件

**Code-CoT（程式化思維鏈）**的設計動機來自 Table 1 的觀察：**圖表加外部程式碼（I+C）**幾乎總是優於僅圖表（I）或僅程式碼（C）。這帶出三個設計原則：

1. **程式碼不取代圖表**：保留原始圖像，讓模型持續使用視覺資訊。
2. **程式碼由模型自己產生**：不是外部工具給定，而是內生推理空間。
3. **程式碼必須被明確學習**：不能只是提示工程（Prompting）的產物。

具體來說，Code-CoT 把推理組織成數種**具型別的事件（Typed Events）**：

- **perception**：從圖表中擷取視覺關係。
- **reference**：標註或引用幾何物件。
- **auxiliary**：進行**輔助構造（Auxiliary Construction）**。
- **coordinate**：建立座標系或數值計算。
- **think**：一般性演繹步驟。

每個事件都是可檢查的幾何操作，同時也是**可定址（Addressable）**的信用單元。這讓「哪一行 code、哪一個事件改變結果」變得明確。

##### 3. CE-GRPO：在關鍵事件邊界比較完整未來

標準 **GRPO（群組相對策略最佳化）** 從原始問題開始取樣一整群完整回應，並把同一個**群組相對優勢（Group-Relative Advantage）**攤到整段軌跡上。這對扁平文字軌跡還行，但對事件結構化的 Code-CoT 來說，會把「無關的前綴」也一起更新。

**CE-GRPO（信用事件 GRPO）** 的關鍵操作是：

1. **選擇候選事件邊界（Candidate Event Boundaries）**：利用**結構先驗（Structural Prior）**與**型別正規化熵（Type-Normalized Entropy）**挑出可能改變結果的邊界。
2. **固定共享前綴（Shared Prefix）**：把圖像、題目與事件邊界之前的完整前綴固定住。
3. **從該邊界取樣多條接續（Continuations）**：每條接續都走到最終答案。
4. **把結果差異轉為局部優勢（Localized Advantage）**：同一群接續拿到相同終端獎勵，但共享前綴不計入策略損失，因此梯度只更新「該事件之後」的決策。

這裡的「關鍵事件（Critical Event）」是操作型定義：一個事件邊界若在不同**接續（Continuation）**下產生不同終端結果，它就是值得學習的信用位置。結構提供語義分支點，熵決定分支預算（Branching Budget），獎勵變異決定是否產生有用的**信用訊號（Credit Signal）**。

##### 4. 方法論的協同設計

Code-CoT 與 CE-GRPO 並非獨立模組，而是**表示法—最佳化協同設計（Representation–Optimization Co-design）**：

- 沒有 Code-CoT 的事件結構，CE-GRPO 就沒有可定址的單元。
- 沒有 CE-GRPO，Code-CoT 只是另一種可執行表示，無法把終端獎勵局部化到關鍵決策。

這種「語義單元同時服務推論與學習」的觀念，是本文相較於單純程式輔助方法或細粒度 RL 方法的最大區別。

#### 實驗數據解讀

##### 1. 主要結果：九個幾何基準測試的平均準確率

CE-GRPO 在九個**幾何基準測試（Geometry Benchmarks）**上達到 **76.04% 平均準確率（Average Accuracy）**，相較於：

- **原生骨幹模型（Native Backbone）** **Qwen3-VL-8B**：+8.09 分
- **Code-CoT SFT**：+6.49 分
- **軌跡層級 GRPO（Trajectory-level GRPO）**：+3.43 分

值得注意的是，CE-GRPO 在**所有九個基準測試**都優於原生骨幹模型，顯示方法具有跨資料集的穩定性，而非只在特定任務上取巧。

##### 2. 終止品質 vs. 協議遵循

作者進一步區分「有效終止回應（Validly Terminated Responses）」：在這些回應中，CE-GRPO 相對於軌跡層級 GRPO 仍有 **3.91 分的平均增益**。這說明改進來自**解答品質（Solution Quality）**，而不只是讓模型學會輸出格式或停止符號。

##### 3. MathVerse 的啟發性分析（Table 1）

Table 1 比較六個模型在 **MathVerse** 上「僅圖表（I）」、「僅程式碼（C）」、「圖表加外部程式碼（I+C）」的表現：

- 對所有開源與專有模型，I+C 都優於單一模態。
- 開源模型在「僅自我生成程式碼（C_self）」設定下，落後外部程式碼 11.7–16.6 分。

這驗證了兩件事：

1. 程式碼與圖表是互補的，程式碼能把隱含關係顯式化。
2. **可靠地自我生成程式碼**是主要瓶頸，因此不能只是把 code 當外部工具，必須讓模型在訓練中學會產生正確 code。

##### 4. 事件數量與 CE-GRPO 優勢的相關性

離線分析顯示：

- **結構選擇（Structural Selection）** 找出「會改變結果的事件」的頻率，比隨機選擇高约 30%。
- CE-GRPO 的相對優勢隨**中間事件（Intermediate Events）**數量增加而提升：每多一個中間事件，邊際增益約 **3.77 分**（r = 0.866，精確 p = 0.0016）。

這是方法機制最直接的證據：當推理鏈越長、**高度依賴的推理（Dependency-heavy Reasoning）**越多，局部信用分配就越重要。軌跡層級方法在長鏈中會把單一終端獎勵稀釋到整段序列，而 CE-GRPO 能把信用聚焦在真正分叉的決策點。

#### 與現有研究的比較

##### 1. 相較於程式輔助方法（PAL、ToRA）

**PAL（Program-Aided Learning）** 與 **ToRA** 等方法把計算組織成程式或工具呼叫，但它們主要把程式當作「外部計算器」或「中間表示」。Code-CoT 的差異在於：

- 保留原始圖像，程式碼是內生推理空間。
- 每個程式步驟都是**最佳化單元（Optimization Unit）**，而不只是驗證或計算單元。

##### 2. 相較於形式化幾何系統（AlphaGeometry、GeoTikzBridge）

**AlphaGeometry** 與 **GeoTikzBridge** 把幾何關係翻譯成形式化語言（Formal Language）或可執行表示（Executable Representation）。這些系統通常依賴大量符號規則或人類設計的推論引擎。Code-CoT 則使用通用 **Matplotlib** 程式碼作為**行可定址可執行程式碼（Line-Addressable Executable Code）**，門檻較低，且直接與神經策略最佳化結合。

##### 3. 相較於細粒度強化學習方法（VinePPO、Segment Policy Optimization、GPO、GRPO-MA）

這類方法在中間狀態（Intermediate State）、段落、關鍵步驟或分支思考（Branched Thought）上估計局部優勢。但它們的切分依賴：

- 學習到的價值模型（Learned Value Model）
- 固定邊界（Fixed Boundaries）
- Token 層級統計

CE-GRPO 不需要額外價值模型，也不需要人工標註流程。它利用 Code-CoT 的事件結構作為自然邊界，並以「結果是否改變」作為選擇標準，讓**信用分配（Credit Assignment）**與**語義單元（Semantic Units）**對齊。

##### 4. 相對優勢與限制

**優勢：**

- 無需過程標註（Process Annotations）或輔助價值模型。
- 在長推理鏈上優勢明顯，且與事件數量高度相關。
- 可執行事件提供可檢查、可驗證的中間步驟。

**限制：**

- 目前僅驗證於幾何領域，事件型別與結構先驗需要領域知識設計。
- 依賴模型能產生可執行且語法正確的程式碼；若程式碼生成錯誤，後續事件會連鎖失效。
- 型別正規化熵與結構先驗的參數（例如分支預算）可能需要針對不同資料集調校。
- 對於無法輕易寫成程式的事件（例如開放式視覺問答），Code-CoT 的適用性尚未驗證。

#### 可重現性評估

##### 1. 公開資源現況

根據目前提供的上下文，論文並未明確說明是否釋出：

- 原始碼
- 訓練腳本
- 模型權重
- 事件切分與前處理流程

因此，**可重現性（Reproducibility）**目前評為「中等偏低」：方法論描述完整，但實作細節（如事件型別標註、熵正規化方式、GRPO 超參數、過濾無效終止的準則）仍需更多資訊才能完整復現。

##### 2. 有利於重現的要素

- **骨幹模型（Backbone）** 使用公開的 **Qwen3-VL-8B**，社群可取得。
- **Matplotlib** 是通用繪圖庫，不需要特殊幾何引擎。
- 九個**幾何基準測試（Geometry Benchmarks）**多為公開資料集（如 MathVerse），評估指標為標準**準確率（Accuracy）**。
- 方法基於標準 **GRPO（群組相對策略最佳化）**，演算法框架已廣為人知。

##### 3. 不利於重現的要素

- Code-CoT 的事件結構需要把自然語言推理對應到特定程式碼型別，這段對齊過程若未公開，難以複製。
- CE-GRPO 的「結構先驗」具體規則（如何挑選候選事件邊界）在摘要中僅提及概念，未給偽碼。
- 訓練時的取樣策略、獎勵塑形（Reward Shaping）、無效回應處理等細節會顯著影響結果。

##### 4. 建議

為提升可重現性，作者可釋出：

- 完整訓練與推論程式碼（含事件解析器）。
- 模型檢查點（Checkpoints）。
- 超參數設定與資料處理流程。
- 錯誤分析範例，說明哪些事件邊界最常被選為關鍵事件。

#### 未來研究方向

##### 1. 跨領域擴展

Code-CoT 的事件化設計可推廣到其他需要視覺—符號混合推理的領域，例如：

- 物理圖表（力學、電路圖）
- 化學分子結構與反應路徑
- 工程製圖與 CAD 推理

關鍵挑戰在於定義各領域的**事件型別（Event Types）**與可執行表示。

##### 2. 與形式化證明器結合

目前 Code-CoT 使用 Matplotlib 進行幾何操作，但未與嚴格的形式化幾何系統（如 **AlphaGeometry** 或 **GeoTikzBridge**）對接。未來可探索：

- 用神經模型產生候輔助構造，再用形式化引擎驗證。
- 把形式化證明中的「推論步驟」也視為事件，讓 CE-GRPO 學習選擇有效的定理應用順序。

##### 3. 自適應事件邊界

目前的結構先驗與熵選擇仍屬啟發式。未來可發展：

- 學習型事件選擇器（Learned Event Selector），直接預測哪些邊界最可能改變結果。
- 動態**分支預算（Branching Budget）**分配，依據問題難度與當前不確定性決定要取樣多少接續。

##### 4. 混合價值模型

CE-GRPO 強調不需要輔助價值模型，但在極長推理鏈中，終端獎勵可能過於稀疏。可研究：

- 輕量級過程獎勵模型（Process Reward Model）與 CE-GRPO 的結合。
- 利用可執行事件的中間檢查點，設計基於語法/語義正確性的密集獎勵。

##### 5. 開源與社群驗證

釋出完整實作與模型權重，將有助於：

- 驗證方法在不同骨幹模型（如 InternVL、LLaVA）上的泛化性。
- 發展更標準化的多模態推理事件格式。
- 建立「可定址推理」的公開評估協定，讓後續研究能比較不同信用分配策略。

##### 6. 人機協作與可解釋性

由於 Code-CoT 把每個決策顯式化，未來可發展：

- 互動式幾何解題介面，讓使用者點擊事件查看其下游後果（Downstream Consequence）。
- 錯誤定位工具，自動標示「哪個關鍵事件」導致答案錯誤，輔助教育應用。

總結來說，本文透過**信用可定址推理（Credit-Addressable Reasoning）**、**Code-CoT** 與 **CE-GRPO** 的協同設計，為長程、高度依賴的多模態推理提供了一個可擴展的學習框架。未來若能解決跨領域泛化、開源釋出與稀疏獎勵問題，將有潛力成為視覺數學推理的標準範式之一。

## 論文問答

**Q1：當前多模態幾何推理存在哪兩個相互關聯的缺口？**

A：當前方法主要面臨表示缺口與信用缺口的雙重挑戰。表示缺口指的是決定答案的關鍵視覺決策——例如物件綁定、角度詮釋或輔助構造——在自由形式推理軌跡中缺乏明確的語義單元，導致模型難以檢查與修正。信用缺口則源於軌跡層級強化學習僅提供單一終端獎勵，無法區分個別決策對最終結果的影響，使得錯誤難以被精確定位與更新。

**Q2：為何幾何推理對視覺語言模型而言特別困難？**

A：幾何推理要求模型同時準確解讀圖表關係並在多步驟演繹中保持一致性，任何物件綁定、角度詮釋或輔助構造的單一錯誤都可能使後續推論全部失效。與純文字數學問題不同，幾何題目的視覺資訊與符號推論緊密交織，模型必須將圖像中的空間關係轉換為可操作的結構化表示。這種高度依賴的推理特性使得錯誤會沿著推理鏈向下傳播，因此需要能夠精確定位並修正中間決策的學習機制。

**Q3：表1的實驗結果如何支持將程式碼作為共享推理空間的設計？**

A：表1顯示無論是開源或專有模型，在「圖表加外部程式碼」設定下的平均準確率都顯著高於僅使用圖表或僅使用程式碼的設定，例如 InternVL3.5-8B 從 45.5 提升至 63.9，提升達 18.4 個百分點。這項結果說明程式碼能夠補充而非取代圖像資訊，兩者結合可產生協同效應。同時，開源模型在僅程式碼設定下與外部程式碼差距達 11.7 至 16.6 個百分點，凸顯由推理模型自身生成並明確學習程式碼的重要性，而非僅依賴外部或提示產生的程式碼。

**Q4：什麼是信用可定址推理？它如何同時彌合表示缺口與信用缺口？**

A：信用可定址推理是指推論過程中暴露的語義單元，同時也定義了最佳化比較替代方案與分配信用的位置。透過將視覺決策轉化為明確、可檢查的事件單元，模型不再隱藏於自由形式文字中，從而解決了表示缺口。由於這些事件單元可以直接作為強化學習的更新錨點，終端結果的差異能夠被轉換為局部優勢，進而彌合信用缺口，讓學習知道哪個決策導致了結果改變。

**Q5：Code-CoT 與先前的程式輔助方法（如 PAL 或 ToRA）有何不同？**

A：Code-CoT 保留了原始圖像，並將圖表感知與幾何操作表示為行可定址的可執行程式碼，進而組織成參考、輔助、座標與思考等類型化事件。相較於 PAL 或 ToRA 主要將程式碼作為計算工具或外部表示，Code-CoT 將每個事件同時視為可驗證的幾何操作與可定址的信用單元。這種設計使程式碼不僅是執行媒介，更成為與學習共享的持久推理空間，讓視覺關係能夠被明確追蹤與更新。

**Q6：CE-GRPO 如何操作化定義「關鍵事件」，並將終端信用局部化？**

A：CE-GRPO 將關鍵事件定義為：在相同前綴下，不同接續會產生不同終端結果的事件邊界。它利用結構先驗與類型正規化熵來選擇候選事件邊界，然後固定圖像、問題與完整前綴，從該前綴採樣多條通往最終答案的接續路徑。由於共享前綴被排除在策略損失之外，群組相對優勢只會更新該事件之後的接續部分，從而將終端獎勵的差異轉換為局部化的信用訊號。

**Q7：在九個幾何基準測試上，CE-GRPO 取得了哪些主要量化結果？**

A：CE-GRPO 在九個幾何基準測試上達到 76.04 的平均準確率，較原生 Qwen3-VL-8B 骨幹模型提升 8.09 個百分點，較軌跡層級 GRPO 提升 3.43 個百分點，較 Code-CoT 監督式微調提升 6.49 個百分點。更重要的是，它在所有九個基準測試上都優於原生骨幹模型，顯示方法具有廣泛的泛化能力。即使在僅考慮有效終止回應的情況下，CE-GRPO 仍較軌跡層級 GRPO 保持 3.91 個百分點的平均優勢，證明提升來自解題品質而非僅是格式遵循。

**Q8：事件數量分析揭示了 CE-GRPO 有效性的什麼特性？**

A：離線分析顯示，CE-GRPO 的相對優勢隨著中間事件數量增加而擴大，每增加一個中間事件，平均邊際提升約 3.77 個百分點，且與事件數量的相關係數高達 0.866。這表示當推理鏈越長、決策之間的依賴關係越複雜時，局部化信用分配的價值越明顯。相較之下，軌跡層級方法在長鏈推理中難以區分個別決策的貢獻，因此 CE-GRPO 在高度依賴的長程推理場景中具有結構性優勢。

**Q9：有哪些消融或驗證證據支持結構化選擇能找出改變結果的事件？**

A：論文進行了結構選擇器的驗證，發現基於結構先驗與類型正規化熵的選擇機制，比隨機選擇更能找出改變結果的事件，頻率高出約 30%。此外，當所有接續獲得相同獎勵時，該群組不會貢獻更新，這項設計確保了無資訊量的選擇不會造成有害更新，只會浪費計算資源。這些證據共同說明 CE-GRPO 的事件選擇並非隨機，而是能夠有效識別那些真正會導致結果分歧的決策點。

**Q10：在哪些實際教育場景中，Code-CoT 與 CE-GRPO 可能最具價值？**

A：這套方法特別適合需要逐步解釋幾何證明過程的智慧家教系統，因為它能將每個視覺決策與幾何操作轉化為可檢查的事件。當學生在輔助構造或角度詮釋上犯錯時，系統可以精確定位錯誤發生的事件位置，並提供針對性的回饋，而非僅告知最終答案錯誤。此外，由於程式碼是可執行的，教師與學生都能驗證每個中間步驟的正確性，這對於培養幾何直覺與邏輯推理能力具有重要價值。

**Q11：這項方法可能如何影響未來多模態推理產品的設計？**

A：這項研究提示未來產品應將「可解釋的語義單元」內建於模型架構與訓練流程中，而非僅在輸出層進行後處理。產品設計者可以採用類似 Code-CoT 的結構化事件介面，讓使用者能夠檢視、編輯甚至回溯每個推理決策，從而提升透明度與可信度。同時，CE-GRPO 的局部信用分配機制也為需要長鏈推理的應用——如工程圖面分析、科學圖表理解或醫學影像診斷——提供了可擴展的訓練範式。

**Q12：信用可定址推理對幾何以外的領域可能產生什麼更廣泛影響？**

A：信用可定址推理的核心原則——讓推論時的語義單元同時成為學習時的信用錨點——可以推廣到任何需要多步驟決策且錯誤會傳播的領域。例如在法律文件分析、財務報表推理或科學實驗設計中，關鍵假設或中間推論都可以被視為事件，並透過比較接續結果來分配信用。這種表示與最佳化的共同設計思維，可能成為提升長程多模態推理可靠性的重要方向。

**Q13：這項方法目前有哪些主要限制或約束？**

A：目前方法主要針對幾何領域設計，事件類型與結構先驗需要根據不同領域重新定義，因此跨領域遷移仍需額外研究。此外，CE-GRPO 需要從每個候選事件採樣多條完整接續，這會增加訓練時的計算成本，對於計算資源有限的應用場景可能構成挑戰。最後，雖然程式碼提供了可執行性，但程式碼生成錯誤本身仍可能成為瓶頸，模型需要具備足夠的程式合成能力才能穩定產生正確的幾何操作。

**Q14：在哪些失敗案例中，CE-GRPO 仍可能表現不佳？**

A：當關鍵錯誤發生在結構選擇器未能識別的事件位置時，CE-GRPO 將無法對該決策分配正確的信用，導致錯誤持續存在。如果所有採樣接續都獲得相同獎勵，該事件不會產生有用的信用訊號，模型也無法從中學習。此外，當視覺感知本身出現錯誤——例如圖表中的物件綁定從一開始就錯誤——後續的局部信用分配可能只是在錯誤基礎上進行微調，難以從根本上修正問題。

**Q15：這項工作為未來多模態推理研究指出了哪些方向？**

A：未來研究可以探索如何自動學習或適應不同領域的事件類型與結構先驗，減少對人工設計的依賴。另一個方向是結合過程獎勵模型或形式化驗證器，在 CE-GRPO 的局部更新之外提供更細緻的中間回饋。此外，如何降低採樣多條完整接續的計算成本、將信用可定址推理擴展到更長的推理鏈，以及應用於動態或互動式多模態環境，都是值得深入探索的課題。

## 實務應用指南

### 適用場景

1. **K-12 與高等教育數位幾何輔導系統**  
   學生上傳幾何題目圖片後，系統以 Code-CoT 產生可執行的視覺感知與推論事件，並在答錯時定位是哪一個「物件綁定」「角度詮釋」或「輔助構造」事件出錯，提供針對性回饋。

2. **工程圖面與 CAD 設計審查**  
   針對機械、土木或建築圖面，模型可將圖表關係轉為行可定址可執行程式碼（例如 Matplotlib 幾何運算），自動驗證尺寸、角度、平行或相切條件，並標註可能導致下游後果的關鍵事件。

3. **機器人視覺導航與空間推理**  
   機器人透過相機取得環境影像後，利用 Code-CoT 將視覺特徵轉換為座標事件與幾何約束，再進行多步驟演繹，判斷可行路徑或物體相對位置。

4. **科學文獻圖表自動驗證**  
   對於論文中的幾何示意圖或數據圖，系統可抽取圖表關係並以可執行表示法重現，檢查圖示與文字敘述是否一致，輔助審稿與可重現性評估。

5. **建築與室內設計法規合規檢查**  
   將設計圖輸入模型，透過事件化推理檢查法規要求的幾何條件（如逃生通道寬度、無障礙迴轉半徑），並在結果改變的關鍵事件處產生可解釋的審查報告。

### 實作前置條件

**資料準備**
- 高品質幾何圖表與對應題目文本。
- 參考解答或外部生成程式碼，用於監督式微調（SFT）的初始對齊。
- 建議準備事件層級的對照資料（雖非必要，但可加速結構先驗與事件邊界設計）。

**運算資源**
- 多模態骨幹模型（如 Qwen3-VL-8B 等級）的推論與微調環境。
- 支援 GRPO 的 GPU 叢集，用於 CE-GRPO 的接續採樣與群組相對優勢計算。
- 安全的程式碼執行沙箱（Sandbox），用於執行 Matplotlib 等幾何運算程式碼。

**技術能力**
- 熟悉多模態大型語言模型微調與強化學習（特別是 GRPO）。
- 具備 Python／Matplotlib 幾何繪圖與程式執行環境建置經驗。
- 了解幾何形式化與基準測試（如 MathVerse）的評估方式。

---

### 實作步驟建議

1. **定義事件類型與程式碼語法**  
   根據領域需求設計 Code-CoT 的事件類型（如 reference、auxiliary、coordinate、think），並規範每種事件對應的可執行程式碼結構，使其同時是語義單元與最佳化單元。

2. **建構 Code-CoT 訓練資料**  
   將每道題目的圖表與問題轉換為「圖表 + 行可定址可執行程式碼 + 事件序列」的格式。可先用外部生成程式碼或專家標註建立冷啟動資料，再逐步過渡到模型自生成。

3. **監督式微調（SFT）**  
   以 Code-CoT 資料對骨幹模型進行 SFT，使其學會在保留原始圖像的同時，輸出結構化、可執行的事件序列。

4. **設計關鍵事件選擇器**  
   實作結構先驗與類型正規化熵（type-normalized entropy），從完整軌跡中挑選可能改變結果的事件邊界，作為 CE-GRPO 的分支點。

5. **執行 CE-GRPO 訓練**  
   在選定的事件邊界處固定共享前綴（shared prefix），採樣多條完整接續（continuation），根據終端結果差異計算局部優勢（localized advantage），並僅更新接續部分的政策。

6. **驗證、部署與持續迭代**  
   透過程式執行驗證每個事件輸出，結合正確答案計算獎勵；同時監控有效終止率、事件數與準確率的關係，並將錯誤事件回饋至資料管線進行再訓練。

### 潛在風險與注意事項

| 風險 | 說明 | 因應措施 |
|---|---|---|
| **程式碼執行安全** | 模型產生的程式碼可能包含惡意或無限迴圈指令。 | 使用隔離沙箱、限制執行時間與資源，並禁止網路存取。 |
| **幻覺程式碼** | 模型可能生成語法正確但幾何意義錯誤的程式碼。 | 加入幾何斷言與單元測試，對每個事件進行可執行驗證。 |
| **事件邊界選擇不當** | 選到無法改變結果的事件會浪費運算，選錯位置則信用分配失真。 | 結合結構先驗與熵正規化，並以離線分析監控結果改變事件的命中率。 |
| **獎勵駭取（Reward Hacking）** | 模型可能學會產生形式上終止正確但推理空洞的軌跡。 | 採用過程獎勵與程式執行結果雙重檢查，避免僅依賴最終答案。 |
| **長程依賴錯誤放大** | 高度依賴的推理鏈中，早期小錯會導致下游連鎖錯誤。 | 增加中間事件驗證與局部優勢訊號，讓模型在錯誤發生處即時修正。 |
| **運算成本** | 每個關鍵事件都需採樣多條接續，訓練與推論成本較高。 | 動態調整分支預算，優先對高熵事件進行採樣，並使用快取共享前綴。 |

### 與其他技術的整合建議

- **與學習管理系統（LMS）整合**：將 Code-CoT 的事件序列直接渲染為逐步解題動畫，並在學生卡關時高亮顯示關鍵事件，提升可解釋性。
- **與 CAD／BIM 工具整合**：透過 API 將模型輸出的 coordinate 事件轉換為 AutoCAD、Rhino 或 Revit 可讀取的幾何物件，實現圖面自動檢查。
- **與形式化證明輔助工具整合**：將 Code-CoT 作為 AlphaGeometry、GeoTikzBridge 或 Lean 的前處理器，把視覺圖表轉為形式化語言後再進行嚴謹證明。
- **與檢索增強生成（RAG）整合**：在 think 事件前檢索幾何定理與輔助構造範例，降低模型對長尾知識的記憶負擔。
- **與其他強化學習方法整合**：可將 CE-GRPO 與 VinePPO、Segment Policy Optimization 或 MCTS 結合，利用不同層級的信用訊號互補。

### 給不同背景讀者的閱讀建議

**初學者**：請先聚焦「把視覺決策變明確，再學習結果在哪裡改變」這個核心概念。你可以把 Code-CoT 想像成「讓模型一邊看圖、一邊寫可執行筆記」，而 CE-GRPO 則是「針對筆記中可能影響答案的關鍵步驟做強化學習」，不必一開始就深入數學細節。

**AI 工程師**：建議從 Code-CoT 的資料格式與事件類型設計開始，接著實作事件選擇器（結構先驗 + 類型正規化熵），最後理解 CE-GRPO 如何在共享前綴下採樣接續並計算局部優勢。特別注意程式碼沙箱與獎勵設計，這是落地時最容易出問題的環節。

**研究人員**：本文的貢獻在於提出「信用可定址推理」這個表示法與最佳化共同設計的框架。建議關注事件邊界的操作型定義、結果改變事件的驗證分析，以及事件數量與準確率增益的相關性，並思考如何將此框架推廣到數學證明、機器人規劃等其他長程推理任務。

**產品經理**：請把重點放在適用場景與商業價值上。本技術特別適合需要「可解釋、可驗證、可定位錯誤」的幾何推理產品，例如智慧家教、工程審查或機器人視覺系統。評估時請同時考量資料準備成本、GPU 訓練預算，以及使用者對逐步透明推理的體驗需求。
