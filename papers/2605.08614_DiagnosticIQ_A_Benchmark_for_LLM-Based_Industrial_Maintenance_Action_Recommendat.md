## 摘要翻譯

監控複雜工業資產須仰賴工程師撰寫之符號規則（symbolic rules）；該規則依感測器條件觸發，並指示技術人員執行矯正行動。瓶頸不在於偵測，而在於回應：將規則轉換為維護步驟，需要多年實務累積之設備專屬知識。我們探討大型語言模型（LLM）是否能為此規則至行動之轉換步驟提供決策支援，並提出 DiagnosticIQ，一個包含 6,690 道經專家驗證之選擇題（multiple-choice questions）基準測試（benchmark），題目取自 118 組規則–行動配對，橫跨 16 種設備類型（asset types）。我們的貢獻包含：(i) 一個符號–選擇題問答（MCQA）轉換管線，將規則正規化為析取範式（Disjunctive Normal Form），並採用基於嵌入（embedding）之干擾項（distractor）取樣；(ii) 五種變體（variants），用於探究不同失效模式（failure modes）（Pro、Pert、Verbose、Aug、Rationale）；以及 (iii) 針對 29 個 LLM 與 4 個嵌入基線（embedding baselines）之基準測試。一項人工評估（9 位實務人員，平均 45.0%）證實 DiagnosticIQ 需要超越操作經驗之專業知識。三項發現尤為顯著。頂尖模型間的差距已趨於收斂：前三名 LLM 相差不到一個 Macro 分（Macro point），且 Bradley-Terry Elo 評分（Bradley-Terry Elo）結果顯示 claude-opus-4-6 領先次一名模型 30 分。然而，Pro 變體暴露了脆弱性（brittleness），所有模型在干擾項擴增下之相對準確率（accuracy）均下降 13–60%。Aug 變體則暴露了模式比對（pattern-matching）現象：在條件反轉下，頂尖模型仍有 49–63% 的比例選擇原始答案。部署瓶頸不在於能力，而在於校準（calibration）：頂尖模型能處理模板式故障偵測，但在結構性擾動（structural perturbation）下則失效。

### 核心貢獻（3～5點）
- 提出 DiagnosticIQ 基準測試：收錄 6,690 道經專家驗證之選擇題，涵蓋 16 種設備類型與 118 組規則–行動配對，驗證 LLM 於工業維護決策支援之性能。
- 建立符號–選擇題問答（MCQA）自動轉換管線：將工程師撰寫之符號規則正規化為析取範式（Disjunctive Normal Form），並採用基於嵌入之干擾項取樣技術生成高品質試題。
- 設計五種探測變體（Pro、Pert、Verbose、Aug、Rationale）：系統性評估 LLM 在干擾項擴增、條件反轉、冗餘敘述等不同失效模式下的表現。
- 完成 29 個 LLM 與 4 個嵌入基線之大規模評測，以 Bradley-Terry Elo 評分進行模型排序。
- 揭示頂尖模型之脆弱性與模式比對問題，指出實際部署瓶頸在於校準（calibration）而非基本能力。

### 適合對象
適合對工業維護決策支援、大型語言模型基準測試設計、符號規則推論，以及關鍵任務領域 AI 部署與校準議題有興趣之研究者與實務工程師。特別推薦給欲評估 LLM 於結構性擾動下性能表現，或尋求將專家知識轉化為可驗證測試框架之智慧維護系統開發者。

## 深度分析

#### 方法論解析

本研究的核心貢獻在於提出一套確定性（deterministic）的 symbolic-to-MCQA（符號規則轉多選問答）管線，將領域專家撰寫的符號規則（symbolic rules）——包含時間謂詞（temporal predicates）與感測器條件——系統性地轉換為專家驗證（expert-validated）的多選題。管線首先將規則正規化為 Disjunctive Normal Form（DNF，析取範式），藉此展開邏輯條件的所有可能組合，擴大 rule-action pairs（規則-動作對）的覆蓋率。隨後，透過 embedding-based（基於嵌入）的取樣機制，從同一設備家族（asset family）中運作相近的維護動作裡抽取 plausible distractors（合理干擾項），確保錯誤選項具備操作上的可信度，而非隨機雜訊。

在此基礎上，作者建構了 DiagnosticIQ（診斷智商基準測試），涵蓋 16 種異質設備類型（asset types）、118 組 rule-action pairs，並衍生出 6,690 道專家驗證題目。為了系統性探測大型語言模型（Large Language Models, LLMs）的失效模式（failure modes），研究設計五種變體（variants）：
- **DiagnosticIQ Pro（專業困難變體）**：透過 distractor expansion（干擾項擴增）提升選項混淆度；
- **DiagnosticIQ Pert（擾動變體）**：對規則進行結構性擾動；
- **DiagnosticIQ Verbose（冗述變體）**：將符號規則改寫為自然語言敘述，測試 symbolic-to-linguistic gap（符號到語言的落差）；
- **DiagnosticIQ Aug（擴增變體）**：執行 condition inversion（條件反轉）等邏輯擴增，檢驗模型是否真正評估條件；
- **DiagnosticIQ Rationale（理由變體）**：要求模型生成並驗證推理理由（rationale）。

此外，研究納入人類基準評估：9 位從業人員平均準確率（Accuracy）僅 45.0%，證明此任務所需的 asset-specific knowledge（設備專屬知識）已超越一般操作經驗，確保 benchmark（基準測試）具備足夠的領域門檻。

#### 實驗數據解讀

研究評估了 29 個 LLMs（橫跨 9 個模型家族）與 4 個 embedding baselines（嵌入基線模型）。整體而言，DiagnosticIQ 對當前前沿模型（frontier models）仍屬未飽和（unsaturated）任務：領先模型達到 73.6% Macro（宏觀平均），但與人類專家的 45.0% 相比，雖顯著領先，卻也顯示仍有近三成空間待填補。

**前沿模型收斂（Frontier Convergence）**：前三名閉源模型——claude-opus-4-6、gpt-5.4、gemini-3.1——在 Macro 上差距不到 1 個百分點，顯示頂層能力已趨於收斂。Bradley-Terry Elo（Bradley-Terry Elo 評分）則將 claude-opus-4-6 排在次高模型之上 30 分，呈現細微但穩定的排序差異。

**脆弱性（Brittleness）探針**：DiagnosticIQ Pro 的實驗結果極具警示性——所有模型在 distractor expansion 下相對準確率（relative accuracy）下降 13% 至 60%。這表明即便總體表現亮眼，模型對於選項空間的細微擴張極度敏感，存在嚴重的 brittleness（脆弱性）。

**模式匹配（Pattern-Matching）而非邏輯推理**：DiagnosticIQ Aug 透過 condition inversion 揭露，前沿模型在條件被反轉後，仍有 49% 至 63% 的機率選擇「原始正確答案」（此時已變為錯誤）。這強烈暗示當前 LLMs 將結構化規則視為 templates（模板）進行表面識別，而非對邏輯條件進行語意評估。

**符號-語言落差**：DiagnosticIQ Verbose 顯示，將規則改寫為自然語言平均造成 4.3 Macro points 的損失，小型模型甚至高達 −9.6。這凸顯 symbolic rules（符號規則）與自然語言敘述之間存在顯著轉換鴻溝。

**微調（Fine-Tuning）的架構分岔**：實驗發現 Supervised Fine-Tuning（SFT，監督式微調）對 reasoning-tuned models（推理強化模型）較有利，而 GRPO（Group Relative Policy Optimization，群體相對策略優化）則對 non-reasoning models（非推理模型）效果更佳。這種依 base architecture（基礎架構）而異的 bifurcation（分岔現象）為後續部署時的訓練策略選擇提供了重要依據。

**營運影響（Operational Impact）量化**：頂尖模型的正確推薦預估可帶來 313 萬至 482 萬美元的營運效益，將學術 benchmark 與工業維護的經濟價值直接掛鉤。

#### 與現有研究的比較

研究透過四個維度定位 DiagnosticIQ（見 Table 1）：Industrial-asset Specificity（IS，工業資產特異性）、Option Distractors（OD，選項干擾項品質）、Condition Understanding（CU，條件理解）、Action Recommendation（AR，動作推薦）。既有基準測試如 GPQA、TruthfulQA、MMLU、MMLU-Pro 均不具備工業場景特異性；ComplexBench 雖評估組合式指令遵循，但缺乏感測器謂詞（sensor predicates）、設備專業術語與維護規則常見的時間持續限制（temporal duration constraints）。在工業維護領域，CAMB、Wind Turbine（風力發電機）基準、PHM-Bench 與 FailureSensorIQ 等主要聚焦於 fault recognition（故障識別）、log classification（日誌分類）或 sensor-failure association（感測器-故障關聯），皆屬於上游的 detection（檢測）階段。DiagnosticIQ 則首次針對下游的 rule-to-action step（規則到動作步驟）——即「警報發生後技師該做什麼」——建立標準化評估，並同時滿足 IS、OD、CU、AR 四項標準。

本研究也明確劃清範圍：不探討 LLMs 作為 time-series reasoners（時間序列推理器）的角色，而是假設 symbolic rule（符號規則）與 triggering condition（觸發條件）已給定，專注於決策支援（decision support）。這與 rule discovery（規則發現）、predictive maintenance（預測性維護）及 signal monitoring（訊號監測）等上游文獻形成互補，填補了工業維護管線中「檢測後決策」的評估空白。

然而，其限制在於目前僅涵蓋 16 種 asset types（設備類型），且規則來源仰賴專家手動編寫與驗證，規模擴充性受限於領域專家的可及性。

#### 可重現性評估

從方法論描述來看，symbolic-to-MCQA 管線被設計為 deterministic（確定性）流程，理論上只要取得相同的原始規則與專家動作庫，即可復現題目生成過程。研究亦詳細說明了 DNF（析取範式）轉換邏輯與 embedding-based distractor sampling（基於嵌入的干擾項取樣）機制，為復現提供充分演算法細節。

但從開放科學角度，本文目前標註為 preprint（預印本），提供的上下文未明確提及原始碼、資料集或模型權重是否公開釋出。此外，實驗涉及 29 個 LLMs，其選擇受每月 5,000 美元運算預算限制，這意味著部分前沿模型的評估結果可能因商業 API 版本迭代而難以完全復現。若未來作者能釋出專家驗證的 rule-action pairs 與生成腳本，將大幅提升本 benchmark 的可重現性與社群採用度。

#### 未來研究方向

1. **結構化推理強化**：當前 frontier models（前沿模型）在 condition inversion（條件反轉）與 distractor expansion（干擾項擴增）下表現崩解，顯示未來研究需發展能真正執行邏輯評估的架構，而非依賴 template matching（模板匹配）。結合符號推理引擎（symbolic reasoners）與 LLMs 的 neuro-symbolic（神經符號）方法可能是關鍵路徑。

2. **縮減符號-語言鴻溝**：DiagnosticIQ Verbose 暴露的 symbolic-to-linguistic gap 提示，需要更好的自然語言介面或中間表徵（intermediate representations），使技師能以口語化方式查詢，而模型仍能準確對應到底層邏輯條件。

3. **時間序列與決策整合**：本研究刻意排除 time-series reasoning（時間序列推理），但未來可將上游感測器異常檢測與下游動作推薦整合為端到端（end-to-end）評估，測試 LLMs 在完整維護管線中的實用性。

4. **微調策略深化**：SFT 與 GRPO 的架構依賴性分岔現象值得更深入的理論分析，特別是針對 reasoning-tuned（推理調校）與 non-reasoning（非推理）基礎模型的差異，以建立通用的工業領域適應（domain adaptation）框架。

5. **校準與信任機制**：研究指出 deployment bottleneck（部署瓶頸）不在能力而在 calibration（校準）。未來應發展針對工業維護的置信度校準（confidence calibration）與不確定性量化（uncertainty quantification）方法，確保模型在實際部署時能可靠地標示高風險決策。

6. **擴充設備與跨領域泛化**：將 16 種 asset types（設備類型）擴展至更廣泛的工業場景（如半導體製程、鐵路系統），並測試 compositional generalization（組合式泛化）能力，將是驗證 benchmark 外部效度的重要方向。

## 論文問答

**Q1：DiagnosticIQ 旨在解決工業維護中的什麼核心問題？**
A：DiagnosticIQ 鎖定的核心瓶頸是「規則到行動」的轉譯落差：當物聯網感測器觸發符號規則警示後，現場技術人員往往缺乏明確指引來決定應採取何種具體糾正措施。雖然現有的自動化系統擅長異常偵測，但將觸發條件轉化為適當維護步驟，需要通常只有多年實務經驗才能累積的設備專屬知識。本研究因此探討大型語言模型能否作為決策支援工具，協助技術人員跨越這個關鍵的下游瓶頸。

**Q2：為何現有的自動化監控系統與既有基準測試無法充分解決這個問題？**
A：現有的物聯網監控系統大多僅限於偵測異常，在問題發生後提供給技術人員的糾正措施指引非常有限，無法有效支援後續的應對決策。此外，工業領域中既有的基準測試多半評估故障識別、感測器異常關聯或日誌分類，而非在規則觸發後推薦具體的維護行動。DiagnosticIQ 則是首個同時涵蓋工業設備特異性、合理干擾選項、組合式條件理解與行動推薦四個面向的基準測試，填補了這項缺口。

**Q3：為什麼規則到行動的轉譯特別具有挑戰性，且對大型語言模型進行此任務的基準測試為何重要？**
A：判斷正確的檢修或維修步驟往往超出設施管理員的專業範圍，尤其是在擁有來自不同製造商、數百個感測器的異質設備環境中，所需知識高度專業且設備專屬。人類實務專家在評估中平均僅達 45.0% 的準確率，顯示這項任務所需的能力已超越一般操作經驗，必須具備深厚的專家級知識。對大型語言模型進行此基準測試至關重要，因為這能檢驗它們是否能在資料中心、醫療設施等高風險且營運關鍵的環境中，扮演可靠的決策支援角色。

**Q4：建構 DiagnosticIQ 基準測試的核心方法論是什麼？**
A：作者開發了一套確定性的符號規則到多選題（symbolic-to-MCQA）管線，將專家撰寫的符號規則轉換為多選題。規則會被正規化為析取範式（Disjunctive Normal Form, DNF），以擴展規則與行動配對的覆蓋範圍，並透過基於嵌入向量的抽樣機制，從同一設備家族中操作相鄰的行動裡建構出多樣且合理的干擾選項。這樣的設計確保了基準測試能夠檢驗模型對組合式邏輯條件的真正理解，而非僅僅仰賴簡單的模式比對。

**Q5：五種變體（Pro、Pert、Verbose、Aug、Rationale）分別用於探測什麼能力，其創新之處為何？**
A：每種變體針對不同的失敗模式或能力進行測試：Pro 透過擴增干擾選項來檢驗模型在更困難區分情境下的穩健性；Pert 施加結構擾動；Verbose 測試模型對於自然語言改寫規則的表現；Aug 透過條件反轉評估邏輯敏感度；Rationale 則檢視推理品質。這些變體的創新之處在於，它們超越了單純的整體準確率評估，能夠系統性地揭露大型語言模型究竟是在進行模板式識別，還是確實執行了真正的邏輯評估，從而暴露其脆弱性與模式比對傾向。

**Q6：作者為何選擇將規則正規化為析取範式（DNF）以及採用基於嵌入向量的干擾選項抽樣，作為關鍵的設計選擇？**
A：將規則正規化為 DNF 能讓管線系統性地拆解複雜的邏輯條件，轉化為標準化的析取子句，從而確保規則到行動配對的覆蓋範圍更加全面。基於嵌入向量的干擾選項抽樣則確保錯誤選項在語義上具有合理性且操作上彼此鄰近，例如同一設備類型的其他維護行動，而非隨機產生的無意義選項。這項設計顯著提高了基準測試的難度，迫使模型必須解析組合式的感測器謂詞與時間限制，而不能僅靠表面的刪去法來作答。

**Q7：在 29 個大型語言模型的基準測試中，有哪些關鍵的量化結果？**
A：領先模型在 DiagnosticIQ 上達到 73.6% 的 Macro 準確率，然而前沿模型的表現已趨於收斂，前三名的最新一代閉源模型彼此差距僅在一個 Macro 點以內。在難度更高的 DiagnosticIQ Pro 變體上，所有模型的表現都出現顯著下滑，因干擾選項擴增而導致相對準確率損失 13% 至 60%。這些結果顯示，雖然現有大型語言模型展現了一定潛力，但尚未有任何模型完全攻克此基準，且所有模型在面對更具挑戰性或受擾動的題目時都呈現出明顯的脆弱性。

**Q8：Aug 變體與邏輯反轉探針揭示了前沿大型語言模型處理符號規則的什麼特性？**
A：Aug 變體暴露了強烈的模式比對傾向：在條件被邏輯反轉後，前沿模型仍有 49% 到 63% 的機率選擇原本正確但現在已錯誤的答案。這顯示這些模型經常將結構化規則視為需要識別的模板，而非需要評估真值的邏輯條件。這種行為揭示了一個關鍵的校準缺口，即模型在標準模板式的故障偵測中看似有能力，但當規則的結構邏輯受到擾動時便會失效。

**Q9：微調與架構選擇如何影響模型表現，而正確推薦所帶來的營運影響又估計為何？**
A：微調結果因基礎架構而呈現兩極化：監督式微調（SFT）對經過推理調校的模型較為有利，而 GRPO 則對非推理型模型較有幫助，這顯示盲目採用單一微調策略未必能普遍提升維護行動推薦的表現。此外，領先模型所做出的正確推薦，估計可帶來 313 萬至 482 萬美元的營運影響。這凸顯了在真實工業環境中部署這類系統所涉及的高經濟風險與潛在報酬。

**Q10：DiagnosticIQ 類型的決策支援在哪些實際工業場景中最具價值？**
A：這類決策支援在醫療設施、風力發電場與大型資料中心等營運關鍵環境中最具價值，因為這些場所的空氣處理機組、冷卻器與風力渦輪機都需要快速且準確的維護回應。當警示觸發時，例如溫度超過閾值或焓值低於限制，技術人員必須立即判斷該檢查閥門、皮帶還是對齊狀況，而這些決策目前往往仰賴稀少且資深的專家經驗。若能透過大型語言模型從符號規則中可靠地推薦正確行動，將可顯著減少停機時間並防止連鎖故障。

**Q11：在部署大型語言模型進行維護行動推薦時，應考量哪些產品設計因素？**
A：部署時必須特別注意校準問題，因為前沿模型雖擅長處理模板式的故障偵測，但在結構擾動（如邏輯反轉或自然語言改寫）下容易失效。產品團隊因此應設置防護機制，不應將大型語言模型的輸出視為絕對權威，尤其是在規則被重新表述或反轉時，並且若採用監督式微調應優先考慮推理調校過的架構。此外，系統應定位為決策支援工具而非完全自動化，確保人類技術人員在涉及高風險維護行動時仍保有最終決定權。

**Q12：廣泛採用基於大型語言模型的維護推薦系統，可能對工業人力與營運經濟產生什麼影響？**
A：廣泛採用這類系統可望使專業的設備專屬知識普及化，縮短資淺技術人員的學習曲線，並減少對少數高度資深工程師的依賴。從經濟角度來看，正確推薦所帶來的數百萬美元營運影響估計，意味著透過減少誤診、縮短維修時間與提升設備可靠性，可創造可觀的成本節省。然而，這些效益完全取決於能否克服當前模型的脆弱性與校準缺口，確保模型不會在規則的細微變化下自信地給出錯誤推薦。

**Q13：DiagnosticIQ 基準測試與評估有哪些已承認的限制？**
A：該基準測試假設符號規則及其觸發條件已作為輸入提供，刻意排除了上游的時間序列推理與異常偵測範圍。此外，人類評估的專家小組規模相對較小（僅 9 位從業人員），且每月 5,000 美元的運算預算也限制了可評估的模型廣度。這些限制意味著此基準尚未涵蓋完整的端到端維護管線，也未完全反映全球工業專業知識的全部多樣性。

**Q14：當前前沿模型中最關鍵的失敗案例是什麼？**
A：最關鍵的失敗案例涉及結構擾動：當規則被邏輯反轉或改寫為冗長的自然語言時，前沿模型經常退回模式比對的答案，而非重新評估邏輯真值。例如，在 Pro 變體中，所有模型都因干擾選項擴增而顯著損失準確率，而領先模型在條件反轉後仍有 63% 的機率選擇原本的正確答案。這些失敗顯示當前大型語言模型缺乏穩健的符號推理能力，且當干擾選項在語義上高度接近時，容易產生操作相關的幻覺。

**Q15：作者建議哪些未來方向以改進基於大型語言模型的工業維護決策支援？**
A：未來研究應著重於增強對符號規則的真正邏輯推理能力，而非僅僅改善模板識別，可能的途徑包括開發明確針對組合式條件評估與時間謂詞理解進行訓練的架構。將基準測試擴展至涵蓋上游時間序列推理與端到端的規則發現，將能建立更全面的評估框架。此外，發展更佳的校準技術與不確定性量化方法，可協助模型在偵測到規則遭受結構擾動時，選擇棄權而非自信地給出錯誤推薦。

## 實務應用指南

### 適用場景

1. **多廠牌異質設備的統一維修決策支援**  
   當廠區同時運作風力發電機、空氣處理機組、冰水主機等 16 類以上設備，且各設備製造商的維修手冊規格不一時，可利用本方法將工程師撰寫的符號規則（如 Temperature>80°F）自動對應到正確的檢修建議，縮短第一線技師查閱文件的時間。

2. **資深工程師經驗的知識固化與傳承**  
   論文顯示人類從業者平均準確率僅 45.0%，代表「規則觸發後該做什麼」屬於需要多年實務累積的資產專屬知識。透過 DiagnosticIQ 的 MCQA 管線，可將退休專家腦中的規則—動作對應關係結構化為 118 組標準題組，供新進人員學習與系統推理使用。

3. **IoT 警示後的自動化工單建議**  
   在既有 IoT 或 SCADA 系統已部署規則引擎的情境下，當感測器條件滿足、警示發出後，LLM 可作為下游「回應層」，直接推薦具體維修動作（如檢查皮帶、校正閥門），並寫入 CMMS 工單的「建議處置」欄位。

4. **夜班與初階技師的即時輔助問答**  
   將規則轉為選擇題介面，技師在手持裝置上收到警示後，可看到由 embedding-based distractor sampling 產生的高混淆度選項，透過人機協作方式確認最終維修步驟，降低人為疏失。

5. **維修策略的結構化壓力測試**  
   維運團隊可利用 DiagnosticIQ Pro（干擾項擴充）、Aug（條件反轉）等變體，定期檢驗現行 LLM 是否仍將規則視為「模板比對」而非「邏輯條件評估」，作為模型上線前的校準關卡。

### 實作前置條件

**資料需求**
- **專家驗證的符號規則庫**：需具備工程師撰寫的觸發條件，並能正規化為析取範式（DNF），每個子句對應單一維護動作。
- **設備語意對照表**：16 類設備類型的感測器標籤、故障模式詞彙與維修動作詞庫，用於確保選項與規則的資產專一性。
- **操作鄰近動作庫**：作為 embedding-based distractor sampling 的負樣本來源，需涵蓋同設備家族內容易混淆的維修步驟。
- **人類專家覆核標註**：至少需領域專家對 118 組規則—動作對進行正確性驗證，並建立基準人類表現（論文為 9 位從業者）。

**運算需求**
- **推理預算**：論文以每月約 5,000 美元運算預算評估 29 個 LLM，實務上需依據廠區規模預留 frontier 模型的 API 呼叫或私有部署算力。
- **Embedding 運算**：需執行 distractor sampling 與規則語意向量化的環境（如 GPU 或高效能 CPU 叢集）。
- **微調資源**：若計畫進行監督式微調（SFT）或 GRPO，需額外準備支援相應基座模型的 GPU 叢集。

**技能需求**
- **工業領域工程師**：能撰寫、理解並驗證符號規則與感測器條件，具備資產專屬的故障模式知識。
- **AI/資料工程師**：熟悉 DNF 正規化、embedding 語意檢索、LLM prompt engineering，以及 MCQA 資料建構流程。
- **維運產品經理**：理解「偵測」與「回應」的管線分界，能設計人機協作介面與回饋機制。

### 實作步驟建議

**步驟一：規則盤點與 DNF 正規化**  
收集現行規則引擎中的觸發條件，將複合邏輯（含時序謂詞）轉換為析取範式（DNF）。此舉可擴大規則對動作的覆蓋率，並確保每個最小子句都能獨立對應到具體維修建議。

**步驟二：Embedding-based 干擾項建構**  
針對每個正確維修動作，利用設備類型內的操作鄰近動作庫，透過語意向量相似度採樣高混淆度選項。論文證明 distractor 品質直接影響評估嚴謹度，應避免使用隨機負樣本。

**步驟三：基線模型評估**  
選定 3–5 個 frontier LLM（涵蓋不同家族），以 zero-shot 方式在自建 MCQA 上測試 Macro 準確率，並以 Bradley-Terry Elo 評分建立模型排序基線。

**步驟四：脆弱性探測與校準**  
執行五種變體測試：Pro（擴充干擾項數量）、Aug（條件反轉）、Verbose（自然語言改寫規則）、Pert（擾動）、Rationale（推理鏈驗證）。特別注意 Aug 變體：若模型在邏輯反轉後仍高比例選擇原始答案，代表其僅進行模板比對，需加入邏輯驗證層。

**步驟五：針對性微調**  
依據基座模型特性選擇微調策略：若基礎模型已具備推理鏈能力（reasoning-tuned），優先採用 SFT；若為非推理型基座，則可嘗試 GRPO。論文顯示兩種方法對不同架構存在顯著分歧。

**步驟六：人機協作部署與回饋閉環**  
將 LLM 輸出定位為「決策支援」而非「自動派工」。技師確認後，將現場執行結果回流至規則庫，持續優化 distractor 分布與動作對應關係。

### 潛在風險與注意事項

- **結構擾動脆弱性**：論文顯示 frontier 模型在條件反轉（Aug）時，仍有 49–63% 機率選擇原始答案。這表示模型傾向將規則視為模板而非邏輯條件。實務部署必須增設符號邏輯驗證層，不可直接採信 LLM 的選項輸出。
- **干擾項膨脹效應**：DiagnosticIQ Pro 變體使所有模型相對準確率下降 13–60%。當實際應用選項超過 4–5 個時，需額外監控模型信心度校準，避免過度自信導致錯誤派工。
- **符號—語言落差**：將規則改寫為自然語言（Verbose）平均損失 4.3 Macro 點，部分小型模型甚至下降 9.6 點。建議輸入端保留原始符號條件與感測器語法，減少 paraphrasing 造成的資訊扭曲。
- **領域知識缺口**：人類專家平均僅 45.0%，顯示此任務超越一般操作經驗。模型建議必須由具備資產專屬知識的資深工程師覆核，特別是在涉及安全關鍵設備時。
- **成本與延遲權衡**：前三強模型（claude-opus-4-6、gpt-5.4、gemini-3.1）Macro 準確率差距在 1 點內，但推理成本與延遲可能差異極大。需依據每月運算預算與工單即時性要求選擇模型，而非一味追求排行榜首位。

### 與其他技術的整合建議

- **CMMS / EAM 系統**：將 LLM 產生的維修建議透過 API 寫入 Oracle Maintenance Cloud 或企業資產管理系統的工單「建議動作」欄位，銜接既有維修流程。
- **IoT / SCADA 規則引擎**：維持現有規則引擎負責異常偵測（detection），LLM 負責下游動作推薦（response）。規則觸發後，將 DNF 條件與設備 ID 傳遞給 LLM 管線，保持管線職責清晰。
- **預測性維護（PHM）上游管線**：與規則探勘（rule discovery）、感測器時序分析等模組互補。上游負責「何時報警」，DiagnosticIQ 管線負責「報警後做什麼」，形成端到端維護決策鏈。
- **RAG 與知識圖譜**：整合設備手冊、FMEA 故障模式庫作為檢索上下文，彌補 LLM 對特定廠牌資產的知識缺口；並以知識圖譜強化設備類型與感測器語意的結構化理解。
- **數位孿生（Digital Twin）**：將 LLM 推薦的維修動作先於數位孿生環境模擬驗證，確認對設備狀態的預期影響後，再產生實體工單，降低誤操作風險。

### 給不同背景讀者的閱讀建議

**給初學者**  
請先掌握「偵測不等於回應」這個核心命題。本文並非教 LLM 解讀感測器時序圖，而是探討「當警示已經響起，技師該做什麼」。建議從圖 1 的維護管線與 Bob（設施經理）/ Alice（操作員）的故事開始，理解規則觸發到維修動作之間的知識落差，再逐步進入 MCQA 的建構邏輯。

**給 AI 工程師**  
請重點關注符號規則到 MCQA 的管線實作細節，特別是 DNF 正規化與 embedding-based distractor sampling 的程式實現。評估階段務必執行 Aug（條件反轉）與 Pro（干擾項擴充）變體，它們是檢驗模型究竟具備邏輯評估能力、抑或僅進行模板比對的關鍵探針。若計畫微調，請注意 SFT 與 GRPO 對不同基座模型（reasoning-tuned vs. non-reasoning）的效果分歧。

**給研究人員**  
本文的核心貢獻在於填補「規則到動作」這一下游任務的基準測試空白，並提出工業資產專一性（IS）、干擾項品質（OD）、條件理解（CU）與動作推薦（AR）四個評估維度。建議深入比較 Table 1 與其他 MCQA 基準測試的差異化定位，未來可延伸的研究方向包括時序謂詞的組合式推理、跨設備類型的知識遷移，以及針對結構擾動的對抗式訓練方法。

**給產品經理**  
本研究揭示「能力已達標，但校準不足」的部署瓶頸：前段模型雖可達 73.6% Macro 準確率，但在結構擾動下會顯著劣化。規劃產品時應將 LLM 定位為「決策支援」而非「自動派工」，並預留資深技師覆核機制。另請留意論文估計的正確建議所帶來的營運影響（約 313–482 萬美元），此數據可作為投資報酬率與採購預算的論證依據。
