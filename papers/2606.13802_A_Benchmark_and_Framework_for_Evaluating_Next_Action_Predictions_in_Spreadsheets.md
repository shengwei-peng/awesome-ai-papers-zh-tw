## ⚡ TL;DR

試算表缺乏自動補全，因公開語料庫無編輯歷史且動作空間複雜。

## 摘要翻譯

預測式程式碼補全（Predictive code completion）能大幅提升開發者的工作效率。然而在試算表（Spreadsheet）中，儘管使用更為普及，這類自動補全（Auto-completion）功能卻幾乎不存在。為彌補此缺口，我們針對能觀察試算表中使用者動作（Action）序列（Sequence）並預測未來動作（Future action）的系統，提出一項基準測試（Benchmark）與評估框架（Framework）。兩大挑戰在於：（1）公開試算表語料庫（Spreadsheet corpus）中缺乏編輯歷史（Edit history）；以及（2）試算表動作空間甚為複雜（涵蓋空間（Spatial）、時間（Temporal）與複合（Composite）特性）。為解決（1），我們人工編製了 52 個序列、共 12K 個動作，以重現公開語料庫（Corpora）中的試算表；這些序列先以參數化啟發式方法（Parametrized heuristic）產生雛形，再經大型語言模型（Large Language Model, LLM）精煉（LLM refinement）。為解決（2），我們提出一種線上評估（Online evaluation）機制，於每個使用者動作後要求產生一項預測，並接受（Accept）或拒絕（Reject）該預測；一旦接受，便更新未來動作，重複此流程直到取得目標試算表。我們採用多個基線預測器（Baseline predictor）（包括零樣本（Zero-shot）大型語言模型、微調（Fine-tuned）小型語言模型（Small Language Model, SLM）與傳統模型（Classical model）），並分析基準測試所揭示的各項屬性（Property），包括但不限於：節省動作（Saved action）與偽陽性（False positive）之屬性、效率（Efficiency）、使用者設定檔（User profile）的影響、觸發條件（Trigger）的影響，以及上下文（Context）的影響。

### 核心貢獻（3～5點）
- 提出試算表下一步動作預測的基準測試與評估框架，解決公開語料庫缺乏編輯歷史及動作空間複雜之雙重挑戰。
- 人工編製 52 個序列、共 12K 個動作之高品質重建資料，結合參數化啟發式方法與大型語言模型精煉，填補公開試算表語料庫的歷史紀錄缺口。
- 設計線上評估機制，透過逐步預測、接受／拒絕回饋與未來動作更新，模擬真實互動式試算表製作流程。
- 系統性評比多種基線預測器，涵蓋零樣本大型語言模型、微調小型語言模型與傳統模型，並深入剖析節省動作、偽陽性、效率、使用者設定檔、觸發條件與上下文等關鍵屬性。

### 適合對象
從事試算表智慧輔助、人機互動、程式碼補全與辦公軟體自動化研究的學者與工程師；亦適合需建構互動式預測系統評估機制之機器學習與自然語言處理研究者。

## 深度分析

#### 方法論解析

本文的方法論核心在於解決試算表（spreadsheet）領域中下一步動作預測（next action prediction）的兩項根本挑戰：公開試算表語料庫（spreadsheet corpora）缺乏編輯歷史（edit history），以及試算表動作空間（action space）同時具備空間（spatial）、時間（temporal）與複合（composite）特性。針對第一項挑戰，作者採用手動策展（manually curate）策略，以公開語料庫中的靜態工作表為目標狀態（target state），透過參數化啟發式方法（parametrized heuristic）生成初始種子序列，再經大型語言模型精煉（LLM refinement）產出 52 條高品質的試算表製作（spreadsheet authoring）軌跡，共計 11,907 個使用者介面動作（UI action），平均每條 229 步（範圍介於 35 至 821 步）。這些序列並非真實使用者日誌，而是經人工驗證的重建軌跡，雖犧牲部分生態真實性（ecological validity），卻首次提供了動作層級的 ground truth，使監督式學習與系統性評測成為可能。

針對第二項挑戰，作者提出線上評估（online evaluation）框架，徹底摒棄傳統 teacher-forced 的離線靜態評測。該框架的運作邏輯為：在每一個時間步（timestep），系統觀察歷史紀錄（history）與目前狀態（current state），輸出預測動作（predicted action）。評估器將預測與未來動作（future action）進行比對，計算精確率（precision）等指標。若使用者接受（accept）預測，則從未來序列中移除已被滿足的操作，並針對錯誤預測（如圖 1 中錯誤的 fill（填滿））前置補償動作以回復狀態，形成新的未來（new future）；若拒絕（reject），則未來序列維持不變，繼續下一個使用者步驟。此設計使得預測錯誤會實際改變後續狀態，強制模型在必須處理錯誤累積（error compounding）與狀態修復的真實情境下進行預測。

評估指標採用多層級設計：per-simulation、per-prediction 與 per-action。其中節省動作（saved action）是衡量使用者因正確預測而減少總操作數的核心效用指標；偽陽性（false positive）與精確率（precision）則反映預測品質。基線預測器（baseline predictor）涵蓋零樣本大型語言模型（zero-shot LLM）、微調小型語言模型（fine-tuned SLM）以及傳統模型（classical model），確保比較基準的全面性。

#### 實驗數據解讀

實驗數據揭示了模型能力、接受策略與觸發條件（trigger）之間的微妙權衡。在節省動作（saved action）指標上，GPT-5 with reasoning 可達 33% 的節省率，而 GPT-5 mini 僅有 18%，顯示模型規模與推理能力對捕捉試算表（spreadsheet）中的重複模式具有顯著影響。然而，最具啟發性的發現是：參數量僅 360M 的微調小型語言模型（fine-tuned SLM）可達到與 GPT-5 相當的 27% 節省率。這強烈暗示下一步動作預測（next action prediction）並非必須依賴超大規模模型，而是可透過針對性微調（fine-tuning）在輕量模型上有效習得，這對實際部署的運算效率（efficiency）與回應延遲至關重要。

但數據同時警示「並非所有預測都值得被接受」。實驗指出，低精確率（low precision）的接受啟發式策略會導致負節省（-19%），即使用者反而需要額外操作來修正錯誤預測。這凸顯了基於淨使用者效益（net user benefit）的節制機制（abstention）之必要性——系統必須具備「拒絕輸出」的能力，而非僅追求預測覆蓋率。此外，觸發條件（trigger）頻率的實驗表明，在每一個動作（per-action）後即進行預測可節省 27% 動作，相較於每四個動作預測一次的 17% 有顯著提升。這暗示更頻繁的預測時機雖增加推論次數，卻能捕捉更多局部重複模式；未來若搭配更便宜的模型，此策略將更具實用價值。

從圖 1 的範例可進一步理解評估邏輯：預測包含兩個正確的 border（框線）與一個部分正確的 fill（填滿），在儲存格-屬性（cell-property）層級達到 7/8 的精確率（precision）。接受後，兩個正確 border 從未來移除，錯誤 fill 透過新增 fill(C4, empty) 回復，最終淨節省一個動作。這說明框架不僅計算表面正確率，更納入狀態修復成本，貼近真實使用者體驗。

#### 與現有研究的比較

與現有研究相比，本文填補了試算表自動補全（auto-completion）與程式碼補全（code completion）之間的關鍵鴻溝。在程式碼領域，預測式程式碼補全（predictive code completion）已從早期符號式系統（如 Blue-Pencil）演進至基於 Transformer 的整行建議，再到現代編碼助理的多函式生成。然而在試算表領域，既有研究多聚焦於特定情境：FlashFill 推導欄位公式、明確意圖觸發的公式建議，或近期基於自然語言意圖的代理（agent）。這些工具缺乏對一般化、低階 UI 動作（如選取範圍（range）、設定字體、添加框線（border））的預測能力，且呼叫代理的認知與等待成本往往高於手動編輯，導致使用者回歸直接操作（direct manipulation）。

本文提出的線上評估（online evaluation）框架相較於傳統離線評估有三項優勢：第一，預測會改變目前狀態（current state），後續預測必須在已變動的狀態上進行，真實反映錯誤累積；第二，系統無法透過重複建議簡單動作來刷分，因為已執行的操作會從未來移除；第三，框架強制要求模型具備自我修正與修復（revise/repair）能力，因為錯誤預測需要額外補償動作來回復目標狀態（target state）。

儘管如此，本研究仍存在局限。資料集規模僅 52 條序列，雖經人工驗證，但相較於程式碼領域動輒數百萬筆的編輯歷史（edit history），樣本量仍屬小規模。此外，軌跡是透過重建靜態語料庫產生，可能無法完全捕捉真實使用者在探索式編輯中的回溯、試錯與非線性行為。動作空間雖涵蓋空間（spatial）與時間（temporal）維度，但對於高度複合（composite）操作（如同時調整多個屬性（property）的巨集式動作）的分解與預測，仍有待更深入探討。

#### 可重現性評估

就可重現性（reproducibility）而言，本文提供的上下文未明確提及原始碼、資料集或模型權重的公開釋出資訊。一個完善的基準測試（benchmark）若要推動領域發展，需至少包含：(1) 52 條動作序列的結構化釋出，含目標試算表與中間狀態（state）；(2) 線上評估框架的參考實作，特別是動態更新未來動作（future action）與計算節省動作（saved action）的邏輯；(3) 基線預測器（baseline predictor）的推論腳本，尤其是微調 SLM（small language model）的訓練配置與資料切分方式。目前從文本推斷，資料策展過程涉及大量人工驗證與 LLM（large language model）精煉，這些中間產物若未釋出，將增加第三方復現門檻。建議作者群後續發布評估框架的開源套件，並提供資料集的下載與授權條款，以利社群進行公平的跨模型比較。

#### 未來研究方向

未來研究方向可從五個維度展開。首先是觸發條件（trigger）的最佳化：實驗顯示 per-action 預測效益最高，但頻繁呼叫模型成本高昂，因此可研究基於不確定性（uncertainty）或狀態變化幅度的適應性觸發機制，以平衡效率（efficiency）與節省率。其次是使用者設定檔（user profile）的個人化：不同使用者的格式偏好、命名慣例與操作順序差異甚大，引入使用者層級的微調或記憶機制可望提升預測精確率（precision）。

第三，擴展資料集規模與多樣性：從 52 條軌跡擴展至數千條，並納入真實編輯歷史（edit history）——例如透過企業內部試算表語料庫或模擬使用者研究（user study）取得——將使基準測試更具代表性。第四，複合動作（composite action）的分解與層級預測：當使用者意圖涉及跨範圍（range）、跨屬性（property）的批次操作時，模型需學會輸出高階意圖（如「將標題列加粗並加上下框線」）再拆解為低階 UI 動作，這與程式碼補全（code completion）中的多語句預測類似。

最後，與生產環境整合的實務研究不可或缺，包含延遲感知（latency-aware）的模型選擇、使用者介面（UI）呈現方式對接受率（acceptance rate）的影響，以及長期使用者適應（user adaptation）的回饋迴路。這些方向將使下一步動作預測（next action prediction）從基準測試（benchmark）走向實際產品，真正提升試算表製作（spreadsheet authoring）的生產力。

## 論文問答

**Q1：本文旨在解決什麼核心問題？為何試算表領域需要專屬的下一步動作預測基準測試？**
A：本文針對試算表環境中缺乏預測式自動補全功能的問題，提出首個專門評估「下一步動作預測」系統的基準測試與框架。雖然預測式程式碼補全已顯著提升開發者的生產力，但在更為普及的試算表應用中，類似的自動輔助功能卻幾乎不存在。為了填補這個缺口，作者建立了一個能夠觀察使用者操作歷史並預測未來動作的標準化評估機制，以推動試算表智慧輔助技術的發展。

**Q2：相較於程式碼的自動補全，為何現有方法難以直接套用於試算表的下一步動作預測？**
A：試算表的預測輔助面臨兩大獨特挑戰：第一，公開語料庫中缺乏像程式碼版本控制那樣詳細的編輯歷史，僅有靜態的最終檔案；第二，試算表的動作空間極為複雜，兼具空間性（影響不同儲存格範圍）、時間性（執行順序影響結果）與複合性（多種屬性交織）。這些特性使得傳統針對線性程式碼設計的離線評估或序列預測模型無法直接遷移，必須設計專屬的資料建構方法與線上互動評估機制。

**Q3：為什麼提升試算表製作效率對使用者與產業而言具有重要價值？**
A：製作視覺上專業且結構完整的試算表通常需要數百個低階使用者介面操作，例如選取範圍、輸入資料與設定格式，過程極為繁瑣且重複性高。現有的試算表助理多聚焦於公式推薦或自然語言指令代理，對於這些日常的重複性手動編輯卻缺乏輔助，導致使用者寧願手動操作也不願呼叫複雜工具。因此，精準的下一步動作預測能夠直接減少重複勞動，顯著提升試算表編寫的生產力，並降低非專業使用者的操作門檻。

**Q4：本文提出的核心方法包含哪些主要元件，如何協同運作以評估預測系統？**
A：核心方法由兩大支柱組成：一是經人工精心整理、包含52條軌跡共11,907個操作步驟的基準資料集；二是模擬真實使用者互動的線上評估框架。在評估過程中，系統根據歷史操作與目前狀態預測未來動作，接著模擬使用者接受或拒絕預測，並在接受時動態更新後續的目標動作序列，直到完成試算表。這種設計讓評估不僅檢驗單步預測的準確度，更能衡量預測對整體編輯流程的實際效益。

**Q5：相較於傳統的離線「教師強制」評估，本文的線上評估框架有何關鍵創新？**
A：傳統離線評估通常讓模型在固定時間點針對靜態目標進行預測，無法反映真實互動中錯誤會累積、狀態會改變的特性。本文提出的線上評估要求模型在每次使用者動作後即時預測，並且一旦預測被接受，後續的未來動作必須相應調整，例如移除已完成的操作或加入復原步驟來修正錯誤預測。這種動態回饋機制更貼近真實使用場景，能夠評估模型在狀態持續演變下的穩健性與對使用者實際節省步驟的貢獻。

**Q6：在資料集建構與評估設計上，作者做了哪些關鍵的設計選擇以確保品質與實用性？**
A：為了解決公開語料缺乏編輯歷史的問題，作者採用參數化啟發式方法生成初始操作序列，再經由大型語言模型精煉與人工驗證，確保52條重建軌跡的高品質與多樣性。在評估設計上，作者選擇以「每個動作後即時預測」為預設模式，並設計多層級指標（模擬層級、預測層級、動作層級）來捕捉不同面向的系統表現。此外，框架特別納入接受／拒絕機制與動態未來更新，以模擬真實使用者只採納有利建議的行為模式。

**Q7：本文建構的基準資料集具有哪些統計特性與內容特徵？**
A：該資料集包含52條從無到有重建公開試算表的完整軌跡，總計11,907個經人工驗證的操作步驟。每條軌跡的長度介於35至821個步驟之間，平均約為229步，涵蓋了格式設定、框線、填滿色彩等多種低階使用者介面操作。這些軌跡透過參數化啟發式規則與大型語言模型精煉產生，確保了動作序列在空間、時間與複合屬性上的豐富度，足以代表真實世界中複雜的試算表製作流程。

**Q8：實驗中的基線預測器呈現了哪些關鍵的比較結果？**
A：實驗顯示，更強大的模型能為使用者節省更多動作，例如具備推理能力的GPT-5可節省33%的步驟，而GPT-5 mini僅能節省18%。令人意外的是，經微調的3.6億參數小型語言模型（SLM）表現可與標準GPT-5持平，兩者皆達到27%的動作節省率，顯示此任務具有可學習性且不一定需要超大模型。相對地，若採用低精確率的接受啟發式策略，反而會導致負效益（-19%的節省率），凸顯預測品質與接受門檻的重要性。

**Q9：針對觸發條件、上下文與使用者特徵的分析揭示了哪些重要發現？**
A：研究發現，在「每個動作後都進行預測」的設定下，系統可節省27%的步驟，優於「每四個動作後才預測」的17%，這表明預測頻率與觸發時機對整體效益有顯著影響，也暗示開發更精準的觸發條件或更輕量的模型值得深入研究。此外，框架也分析了不同使用者設定檔、上下文範圍對預測表現的影響，以及偽陽性預測與實際節省動作之間的關係。這些多維度分析證明，單純追求預測精確率並不足夠，必須同時考量預測時機與使用者行為模式才能最大化實用價值。

**Q10：這項研究在哪些實際應用場景中能夠發揮最大價值？**
A：此技術最直接的應用是整合至 Excel 或 Google Sheets 等主流試算表軟體中，作為即時的智慧格式與編輯輔助工具。當使用者進行重複性的排版工作，例如為多個區塊設定相同框線、填滿色彩或調整字體時，系統可主動建議後續一系列操作，大幅減少機械式點擊。對於需要快速製作專業報表、財務模型或數據看板的商業使用者而言，這種預測式自動補全能顯著縮短製作時間並降低人為疏失。

**Q11：從產品設計角度來看，部署此類預測系統時需要考量哪些關鍵因素？**
A：產品化時必須謹慎設計預測的觸發條件與接受策略，因為研究顯示錯誤的接受門檻會導致負面效益，反而增加使用者負擔。系統需要在「頻繁預測以最大化節省機會」與「避免過度打擾使用者」之間取得平衡，因此良好的觸發機制與基於淨效益的節制策略至關重要。此外，由於預測被接受後會改變試算表狀態，產品必須確保建議的視覺呈現清晰，並提供便捷的復原途徑，以維持使用者對系統的信任感。

**Q12：這項研究對試算表編寫領域與更廣泛的智慧代理研究將帶來什麼影響？**
A：本研究架起了「程式碼自動補全」與「試算表智慧代理」兩大新興領域之間的橋樑，為試算表環境中的低階操作預測建立了標準化的研究基礎。它不僅填補了通用動作建議的空白，也提供了一個可擴展的評估框架，讓後續研究能夠公平比較不同模型的實用效益而非僅看靜態準確率。對於智慧代理研究而言，這強調了在複合式、二維空間介面中進行序列預測與人機互動評估的獨特挑戰，有助於推動更貼近真實使用者工作流的代理系統發展。

**Q13：本文作者承認了哪些資料集與評估框架上的限制？**
A：儘管資料集經過人工驗證，但52條軌跡相對於真實世界中數以億計的試算表而言規模仍然有限，可能無法涵蓋所有領域或極端複雜的編輯模式。此外，目前的軌跡是從公開語料庫的靜態檔案重建而來，而非來自真實使用者的原始操作日誌，因此可能遺漏了真實編輯過程中的試錯、回退與非線性跳躍行為。線上評估雖然模擬了接受與拒絕行為，但模擬的使用者模型畢竟無法完全重現真實人類在認知負荷、偏好與錯誤容忍度上的細微差異。

**Q14：實驗中觀察到哪些失敗案例或負面結果，這些現象帶來什麼啟示？**
A：實驗明確顯示，若系統缺乏節制機制而採用低精確率的接受啟發式，整體效益會呈現負值（-19%），意味著錯誤的預測不僅無法省時，反而迫使使用者花費額外步驟復原。此外，部分預測雖然在儲存格層級具有不錯的精確率（如7/8），但單一錯誤的填色動作就可能需要額外的復原操作，進而抵銷正確預測所帶來的效益。這些案例強調，評估預測系統時不能只看表面精確率，而必須以「淨節省動作數」作為最終的實用性指標，並建立有效的棄權或延遲預測機制。

**Q15：基於本文的成果與發現，未來研究可以朝哪些方向深入發展？**
A：未來研究可探索更精細的觸發條件，例如僅在偵測到重複模式或使用者停頓時才啟動預測，以兼顧效益與干擾度。另一個方向是擴大資料集規模並引入真實使用者的原始操作日誌，捕捉更自然的試錯行為與個人化編輯風格，從而提升模型的泛化能力。此外，結合視覺感知的多模態模型或強化學習來優化長期互動策略，以及針對不同使用者設定檔進行個人化微調，都是值得進一步探索、能夠讓預測系統更貼近實際部署的途徑。

## 實務應用指南

### 適用場景

1. **企業內部試算表自動化平台**：加速財務、營運人員製作月報、預算表等重複性格式化工作，透過下一步動作預測自動補全框線、色彩與資料填滿。
2. **線上協作試算表工具的智慧型外掛**：在 Excel Online 或 Google Sheets 等環境中，於使用者每次操作後即時預測後續動作，減少重複點選與格式設定時間。
3. **試算表製作教學與輔助系統**：利用預測模型觀察學習者的歷史紀錄，即時提示下一步操作或自動完成部分動作，降低試算表製作的學習曲線。
4. **低程式碼資料視覺化前處理**：協助使用者在整理資料時，自動補全欄位屬性、儲存格範圍格式與樣式，銜接後續圖表生成。
5. **試算表稽核與合規檢查工具**：比對實際編輯歷史與預期範本的偏差，偵測異常操作序列，確保關鍵報表的產出流程符合標準。

### 實作前置條件

- **資料**：需具備目標試算表的目標狀態（target state），若缺乏編輯歷史（edit history），必須參考本文方法，以參數化啟發式方法（parametrized heuristics）產生初始動作序列，再透過大型語言模型精煉（LLM refinement）與人工驗證，建立至少數十組高品質軌跡作為基準測試（benchmark）。
- **運算**：微調小型語言模型（SLM）需至少單張中高階 GPU（如 A100 等級）；若採用零樣本（zero-shot）大型語言模型（LLM）API 推論，則需評估 API 延遲與成本。此外，需建構可模擬試算表狀態轉換的執行環境以支援線上評估（online evaluation）。
- **技能**：團隊需熟悉試算表資料模型（儲存格、範圍、屬性）、具備序列建模與微調經驗，並能開發互動式評估框架以處理接受（accept）／拒絕（reject）邏輯與動態狀態更新。

### 實作步驟建議

1. **資料建構與清理**：從公開試算表語料庫（spreadsheet corpus）選取目標檔案，利用啟發式方法產生初始動作序列，再以 LLM 精煉並經人工驗證，建立含 52 組軌跡、共約 12,000 步操作的基準資料集。
2. **動作空間正規化**：定義低階使用者介面動作（UI action）的結構化表示，涵蓋空間（spatial，如儲存格範圍）、時間（temporal，如操作順序）與複合（composite，如合併多項屬性變更）維度。
3. **基線模型開發**：依序實作傳統模型（classical model）、零樣本 LLM 與微調 SLM。建議先以強大模型（如 GPT-5 with reasoning）探索表現上限，再以 360M 參數等級的 SLM 驗證邊緣部署可行性。
4. **線上評估框架實作**：建構 `predict(history, state)` 介面，使系統在每次使用者動作後輸出預測動作（predicted action）。實作接受／拒絕邏輯，並在接受後動態更新未來動作（future action）與目前狀態（current state）。
5. **觸發條件與使用者設定檔實驗**：測試不同觸發條件（trigger，如每個動作後預測 vs. 每四個動作後預測）與使用者設定檔（user profile）對節省動作（saved action）與偽陽性（false positive）的影響，找出最佳互動節奏。
6. **部署與迭代**：將模型封裝為試算表工具的外掛或內建服務，整合即時預測與使用者回饋迴路，持續以精確率（precision）與淨使用者效益作為迭代指標。

### 潛在風險與注意事項

- **複合錯誤累積**：線上評估中，錯誤預測一旦被接受，將改變未來狀態，導致後續預測基於錯誤上下文（context）而偏離。建議設定嚴格接受門檻，或採用預測後驗證機制，確保預測動作不會破壞目標狀態的可達性。
- **偽陽性與負面效益**：低精確率的接受啟發式會導致負節省動作（negative saved actions），反而增加使用者負擔。實務上應以淨效益為導向，寧可保守拒絕也不濫發建議。
- **動作空間爆炸**：試算表動作涉及大量儲存格範圍與屬性組合，輸出空間遠大於傳統程式碼補全（code completion）。需設計分層解碼策略或限制預測範圍，避免模型迷失在過大的動作空間中。
- **資料隱私**：企業內部試算表常含敏感資料，重建編輯歷史時需確保去識別化，或在本地端完成模型微調與推論。

### 與其他技術的整合建議

- **與現有試算表軟體整合**：可透過 Office.js 或 Google Apps Script 開發外掛，將預測系統作為自動補全（auto-completion）層疊加於現有 UI，無需更動底層試算表引擎。
- **與試算表代理程式整合**：本文聚焦低階動作預測，可與基於自然語言指令的高階試算表製作（spreadsheet authoring）代理結合：代理負責理解「製作季度報表」意圖，本系統負責加速執行過程中的重複性格式設定。
- **與程式碼補全工具整合**：對於使用 Excel LAMBDA 或 Python in Excel 的進階使用者，可將試算表動作預測與程式碼補全管線串接，統一預測「下一個操作」，無論其為 UI 動作或程式碼輸入。
- **與版本控制系統整合**：將編輯歷史自動匯出為結構化序列，不僅能持續擴充訓練語料庫，也能支援試算表層級的 diff 與稽核功能。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從圖 1 的線上評估流程與摘要中的「節省動作」概念開始理解。重點放在「為何試算表需要自動補全」以及「接受與拒絕預測如何影響使用者體驗」，無需深入模型細節，先建立對試算表動作空間複雜度的直覺。
- **AI 工程師**：請聚焦於資料建構方法與線上評估框架實作細節。特別注意動作序列的結構化表示、動態更新未來動作的狀態管理，以及不同觸發條件對延遲與精確率的權衡。本文的基線實作（零樣本 LLM、微調 SLM、傳統模型）可直接作為你內部驗證的起點。
- **研究人員**：請深入分析本文提出的評估指標體系，特別是線上評估相較於傳統離線 teacher-forced 評估的優勢。關注錯誤累積、使用者設定檔效應、以及偽陽性對淨效益的影響，這些都是後續研究可擴展的理論方向。
- **產品經理**：請將閱讀重心放在適用場景與實驗結論：GPT-5 with reasoning 可節省 33% 動作、微調 SLM 可達相近效果、以及觸發頻率對使用者效益的影響。這些數據能幫助你評估智慧型試算表輔助功能的投資報酬率、技術選型（雲端 LLM vs. 端側 SLM）與使用者互動設計（何時跳出建議最不干擾）。
