## ⚡ TL;DR

現有文字技能僅為被動建議，無法在智慧體迴圈中明確介入何時與如何修正行為。
本文提出HASP框架，將技能轉為可執行程式函數，能於易失效狀態主動介入並修正動作。
在網頁搜尋、數學推理與程式編寫任務上，HASP顯著提升效能，最高較基線改善逾三成。

## 摘要翻譯

為 LLM 智慧體（LLM agents）配備源自過去經驗的可複用技能（reusable skills），已成為處理複雜且長程任務（long-horizon tasks）的熱門且成功方法。然而，這些經驗通常被編碼為文字指引（textual guidance），仍多屬諮詢式（advisory），缺乏針對何時以及如何介入智慧體迴圈（agent loop）的明確機制。為彌合此落差，我們提出 HASP（Harnessing LLM Agents with Skill Programs），一個將技能升級為可執行程式函數（Program Functions, PFs）的新框架。PFs 並非僅提供被動建議（passive advice），而是作為可執行護欄（executable guardrails），於易失效狀態（failure-prone states）下啟動，並修改下一步動作（next action）或注入修正性上下文（corrective context）。HASP 具高度模組化特性：可於推論階段（inference time）直接介入智慧體迴圈（agent loop）、於後訓練（post-training）階段提供結構化監督（structured supervision），或透過演化經驗證且經教師審查的 PFs（teacher-reviewed PFs）以實現自我改進（self-improvement）。實證上，HASP 在網頁搜尋（web-search）、數學推理（math reasoning）與程式編寫（coding）任務上，相較於免訓練（training-free）與基於訓練（training-based）的方法均帶來顯著提升。例如，在網頁搜尋推理方面，僅於推論階段（inference time）使用 PFs 便相較於（多迴圈）ReAct Agent 平均效能提升 25%；而後訓練（post-training）與受控演化（controlled evolution）則相較於 Search-R1 達到 30.

## 深度分析

#### 方法論解析

HASP（Harnessing LLM Agents with Skill Programs）的核心方法論在於將傳統以自然語言編碼的「可複用技能（reusable skills）」升級為可執行的狀態–動作介入函數，即程式函數（Program Functions, PFs）。不同於僅提供「被動建議（passive advice）」的文字指引（textual guidance），PF 是一個具備明確介面的計算實體：給定智慧體（agent）的當前狀態與候選下一步動作（candidate next action），PF 透過 `should_activate()` 判斷是否於該決策點介入，再經由 `intervention()` 直接修改下一步動作、或透過上下文注入（context injection）增強策略的輸入脈絡，最後以 `emit_signals()` 輸出結構化介入訊號（structured intervention signals）供下游學習使用。這種設計使技能從「模型可能採納的參考建議」轉變為「可隨需觸發、直接作用於動作空間（action space）的可執行護欄（executable guardrails）」。

在系統架構上，HASP 扮演外部智慧體束套（external agent harness），亦即環繞基底策略（base policy）的控制層（control layer）。於每個策略迴圈（policy loop）步驟中，基底策略先生成動作，HASP 隨即檢索相關 PFs、評估其啟動謂詞（activation predicates）、執行通過驗證的介入，再將修訂後的動作或注入的修正上下文反饋至迴路。此架構確保 PF 的執行不依賴基底模型的配合意願，從而彌合了「語言描述的經驗」與「可靠控制行為」之間的落差。

HASP 的模組化（modular）特性體現在三種互補的應用範式：

1. **推論階段（inference time）介入**：無需更新模型權重，直接將 PF 嵌入現有智慧體迴圈（agent loop）。當智慧體進入易失效狀態（failure-prone states）時，PF 自動觸發並修正行為。此模式特別適合快速部署與冷啟動場景。
2. **後訓練（post-training）與策略內化（policy internalization）**：每次 PF 執行均產生結構化記錄，包含原始動作、PF 修復內容、啟動的技能識別符與觀察效應。HASP 以 PF 衍生的結構化監督（structured supervision）為這些事件評分，並利用經 PF 修正後的軌跡（PF-corrected traces），透過監督式微調（SFT）、拒絕採樣（Rejection Sampling, RS）或 on-policy Distillation 訓練學生策略，使外部技能知識逐步內化為基底策略的固有能力。
3. **自我改進（self-improvement）與技能庫演化（skill library evolution）**：在閉迴路設定中，HASP 針對當前檢查點下的失敗案例進行回溯，歸納反覆出現的失效模式（recurring failure patterns）與修復模式，將其摘要為候選 PFs。這些候選函數必須通過語法、介面與模擬執行（mock-execution）三重驗證，並經教師審查（teacher-reviewed PFs）後，方可納入外部技能庫（skill library）。此機制將執行、學習與技能庫擴張緊密銜接，形成持續演化的行為知識（behavioral knowledge）累積迴路。

值得強調的是，PF 的准入門檻設計對系統穩定性至關重要。論文明確指出，僅有通過執行期驗證的 PFs 才能進入活躍技能庫，這避免了低品質或語法錯誤的程式函數在推論時引發連鎖失效，也為後續穩定的技能庫演化（skill library evolution）奠定基礎。

#### 實驗數據解讀

論文於網頁搜尋推理（web-search reasoning）、數學推理（math reasoning）與程式編寫（coding）三大領域進行評估，數據呈現清晰的效能階梯與方法論驗證邏輯。

在**網頁搜尋推理**任務中，基準線（multi-loop ReAct Agent）之上，僅憑推論階段（inference time）的 PF 自動觸發與介入，平均準確率即達 51.0%，相較基準提升達 25%。這項結果具有重要方法論意涵：即便不進行任何模型權重更新，將技能從「文字提示」轉化為「可執行護欄」本身就能產生巨大增益，證明了明確的狀態–動作介入機制遠優於諮詢式（advisory）指引。進一步引入輔助教師（auxiliary teacher）進行 PF 選擇後，推論效能提升至 56.2%，顯示 PF 的「檢索與觸發時機」仍是效能瓶頸，也暗示在複雜狀態空間中，純粹基於規則的 `should_activate()` 可能面臨語意歧義。

進入後訓練階段，在固定技能庫（fixed skill library）設定下，拒絕採樣（RS）達到 59.3%，而 on-policy Distillation 更達 62.5%。這說明經 PF 結構化監督修正後的高品質軌跡，能有效驅動策略內化（policy internalization），使基底模型習得原本需要外部介入才能產生的正確行為模式。值得注意的是，受控演化（controlled evolution）搭配閉迴路拒絕採樣（closed-loop RS）達到 60.3%，雖略低於固定庫下的 Distillation，但論文同時指出此演化機制相較 Search-R1 達到 30.4% 的增益。這暗示演化後的動態技能庫可能在穩健性或跨分佈泛化上具備優勢，而非僅追求單一檢查點的最高分。

在**數學推理**方面，受控演化將效能推升至 45.4%，顯示 PF 機制不僅適用於工具呼叫頻繁的網頁搜尋，也能捕捉數學推論中反覆出現的邏輯謬誤與驗證缺失。至於**程式編寫**任務，教師輔助的 PF 介入達到 68.7% 的平均 pass@1，而 PF 導向的訓練（PF-based training）進一步提升至 69.9%。此處訓練後的微幅領先（約 1.2%）表明，對於需要嚴格語法與執行正確性的 coding 任務，將外部修復經驗蒸餾進基底策略，其邊際效益相對推論介入更為穩定。

綜合而論，實驗數據揭示了三條主軸：（一）可執行介入本身即具備強大價值；（二）策略內化能進一步突破推論階段的天花板；（三）教師監督與穩定演化是確保技能庫品質的關鍵閘門。

#### 與現有研究的比較

透過論文表一的五維度定性比較，可清晰定位 HASP 於現有文獻中的獨特性。既有方法大致可分為兩類：技能導向（skill-based/self-improving）與強化學習導向（general RL-based）。

在技能導向陣營中，ExpeL、MemSkill、SKILL0、SkillRL 與 SAGE 均嘗試將過去經驗抽象為可複用知識。然而，這些系統大多將技能維持在文字形式（textual form），其執行期控制（runtime control）至多為部分支援（partial）：技能通常以提示（prompt）注入或間接塑造獎勵，缺乏如 PFs 般精確的狀態觸發與動作修改能力。例如 SKILL0 雖支援策略訓練與學習訊號，卻無執行期控制；MemSkill 支援技能庫演化（skill evolution），但無政策訓練（policy training）。相較之下，HASP 同時具備明確的技能形式（可執行程式函數）、完整的執行期控制、結構化學習訊號、政策訓練能力與技能庫演化機制，五項能力全數支援。

在強化學習導向陣營中，Search-R1、ReSearch、P-GRPO 等方法聚焦於透過獎勵驅動或任務層級目標優化策略。這類方法通常不具備顯式的技能形式（skill form），也缺乏執行期透過可複用護欄進行控制的機制。AgentFlow 雖有部分技能與演化支援，但其執行期控制與技能形式仍屬間接。HASP 的優勢在於不排斥 RL 訓練，而是以模組化方式兼容 SFT、RS 與 Distillation，同時保留人類可讀、可驗證、可演化的技能庫作為中介層。

儘管 HASP 在功能覆蓋上最為完整，論文脈絡亦暗示若干相對限制。首先，自我改進迴路中的教師審查（teacher review）步驟可能成為規模化瓶頸，若缺乏自動化教師，技能庫的擴張速度將受限。其次，PF 的初始設計仍需從訓練池的失敗案例中萃取，並手動或半自動地具現化為 `should_activate()` 與 `intervention()` 介面，這對新領域的冷啟動仍要求一定工程投入。此外，當多個 PFs 同時滿足啟動條件時，論文未詳細闡述衝突消解（conflict resolution）機制，這在技能庫規模擴大後將成為實務挑戰。

#### 可重現性評估

根據目前提供的論文脈絡，作者尚未明確釋出開源程式碼、資料集或模型權重。本文標註為 Preprint（arXiv:2502.11743），處於學術發表的早期階段，因此完整可重現性（reproducibility）仍有待觀察。

從系統複雜度評估，HASP 的復現門檻相當高。其 pipeline 橫跨三個階段：推論階段需建置外部智慧體束套（external agent harness）與 PF 執行環境；後訓練階段需蒐集 PF-corrected traces 並實作結構化評分準則；自我改進階段則需額外的教師模型（teacher model）進行審查、以及語法與模擬執行驗證基礎建設。特別是網頁搜尋任務，需穩定的搜尋引擎 API 與瀏覽器環境；程式編寫任務則需安全的程式執行沙盒以驗證 pass@1。這些外部依賴若未標準化，不同實驗室復現時易產生環境漂移（environment drift）。

此外，PF 的具體實作細節——例如 `should_activate()` 的特徵提取邏輯、`intervention()` 的動作修改語法、以及 `emit_signals()` 的結構化格式——對結果影響重大，但論文受限於篇幅僅提供概念層描述。若無補充材料（appendix）或開源實作，其他研究者難以精確重建 PF 的介面規格與技能庫初始化流程。整體而言，在原始碼與環境設定公開前，HASP 的可重現性評估為「中等偏低」，建議作者未來釋出 harness 框架、基準技能庫模板與環境包裝器（environment wrappers），以降低社群復現門檻。

#### 未來研究方向

基於 HASP 的架構設計與實驗發現，以下幾個方向值得後續深入研究：

1. **自動化教師審查與 PF 合成**：目前自我改進迴路依賴教師審查（teacher review）作為品質閘門。未來可探索以更強大的教師模型（或形式化驗證工具）取代人工或昂貴的人類專家審查，甚至讓智慧體透過「自我批判（self-critique）」生成候選 PFs，從而實現全自動化的技能庫演化（skill library evolution）。

2. **多 PF 衝突消解與組合最佳化**：當技能庫擴張時，多個程式函數（PFs）可能同時於同一狀態觸發。未來需發展組合語意（composition semantics）或優先級學習機制，避免介入行動互相矛盾，並使 PFs 能協同作用而非僅獨立執行。

3. **介入穩定性的理論分析**：外部控制層直接修改動作空間（action space）可能改變基底策略的動態特性。未來研究可從理論上分析可執行護欄（executable guardrails）於何種條件下能確保收斂，或探討過度介入導致策略退化（policy degradation）的臨界條件。

4. **跨領域技能庫遷移**：當前實驗中各領域技能庫似乎獨立演化。未來可研究網頁搜尋、數學推理與程式編寫之間的行為知識（behavioral knowledge）遷移性，例如「驗證優於提交」這類後設認知技能（meta-cognitive skills）是否能以通用 PF 形式跨任務複用。

5. **與可驗證獎勵強化學習（RLVR）的深度融合**：近期 RLVR（Reinforcement Learning with Verifiable Rewards）在推理與程式任務上表現突出。將 HASP 的結構化介入訊號與最終結果獎勵結合，可能產生更為樣本高效的訓練方法，使 PF 同時扮演「過程獎勵模型（process reward model）」與「可執行修正器」的雙重角色。

6. **動態技能庫壓縮與線上適應**：隨著技能庫成長，檢索與啟動開銷將增加。未來可研究如何在維持效能的前提下，對技能庫進行即時剪枝（pruning）或知識蒸餾壓縮，甚至支援部署階段的線上 PF 適應（online adaptation），使智慧體能於推論階段即時學習新失效模式並生成對應護欄。

## 論文問答

**Q1：HASP 旨在解決 LLM 智慧體系統中的什麼核心問題？**
A：HASP 旨在彌合「以自然語言表達的可複用經驗」與「能夠可靠且明確控制智慧體行為的可執行機制」之間的鴻溝。現有的智慧體系統雖然會將過去經驗編碼為文字指引，但這類指引僅屬於被動建議，缺乏在策略迴圈中明確決定何時介入、如何介入的機制。這導致智慧體在面對長程任務時，無法有效根據反覆出現的失效模式調整行為，進而重複犯下相似的錯誤。

**Q2：為何現有的文字技能方法無法可靠地提升智慧體表現？**
A：現有方法通常將技能以提示注入或檢索建議的形式提供，使其本質上仍屬於諮詢式的被動建議。文字技能雖然能在原則上表達智慧體應該做什麼，卻無法精確指定在策略迴圈中的啟動時機，也無法直接修改候選下一步動作。因此，模型在實務中經常忽略這些指引，導致智慧體持續做出輕率的中間結論或重複無效的行動。

**Q3：將文字技能轉化為可執行介入為何具有重要性？**
A：隨著任務分佈的變化與跨回合回饋的累積，智慧體必然會遭遇反覆出現的失效模式，需要系統性的修正機制。若僅依賴被動建議而缺乏明確的動作空間介入能力，智慧體便難以將過去經驗轉化為未來行為的可靠依據。透過建立可執行護欄，智慧體才能在易失效狀態下自動觸發修正，這對於完成需要多步規劃的長程任務至關重要。

**Q4：HASP 的核心機制是什麼？它如何改造傳統的技能表示法？**
A：HASP 的核心機制是將技能重新定義為可執行的程式函數（PFs），這是一種可重用的狀態–動作介入函數。每個 PF 會根據當前智慧體狀態與候選下一步動作，判斷是否需要介入，並透過修改動作或注入上下文來明確增強策略。這種設計將傳統僅供參考的文字技能，轉變為能夠在智慧體迴圈中隨需啟動並直接介入的可執行物件。

**Q5：相較於先前的技能表示法，程式函數（PFs）的關鍵創新為何？**
A：PFs 的關鍵創新在於其具備明確的啟動條件（should_activate）與介入介面（intervention），而非僅是被動的文字內容。它們能夠在偵測到易失效狀態時自動啟動，直接修改下一步動作或注入修正性上下文，從而在動作空間中發揮可執行護欄的作用。這使得技能不再是模型可選擇性遵循的建議，而是能夠可靠且明確控制智慧體行為的主動機制。

**Q6：HASP 為何採用模組化設計，同時支援推論階段、後訓練與自我改進？**
A：HASP 採用模組化設計的原因在於 PFs 統一的狀態–動作介入介面，使其能夠在不改變底層架構的前提下，靈活應用於多種部署範式。在推論階段，PFs 可作為外部控制層直接介入智慧體迴圈；在後訓練階段，每次 PF 執行都會產生結構化介入訊號，可用於監督式微調或拒絕採樣。這種設計讓框架能夠根據實際可用的運算資源與資料，逐步從外部介入過渡到策略內化與技能庫演化。

**Q7：HASP 在哪些基準測試與任務上進行了評估？**
A：HASP 在網頁搜尋推理、數學推理與程式編寫這三個具有代表性的領域進行了全面評估。這些任務涵蓋了需要規劃、工具使用與多步驟推理的長程挑戰，能夠充分檢驗框架的泛化能力。實驗設計同時包含免訓練的推論介入與基於訓練的策略內化，以驗證 HASP 在不同應用情境下的有效性。

**Q8：哪些關鍵實證結果證明了 HASP 的有效性？**
A：在網頁搜尋推理任務上，僅靠推論階段的 PFs 介入，平均效能便比多迴圈的 ReAct Agent 提升了 25%，而結合後訓練與控制演化的方法則相較 Search-R1 獲得 30.4% 的增益。在程式編寫領域，經教師增強的 PF 介入達到 68.7% 的平均 pass@1，而基於 PF 的訓練更進一步將其提升至 69.9%。這些結果顯示，無論是在推論階段直接介入，或是將結構化監督內化至策略中，可執行技能都能帶來顯著且穩定的效能提升。

**Q9：機制分析提供了哪些關於 PF 觸發與技能內化的深入見解？**
A：機制分析揭示了 PFs 如何在特定的易失效狀態下觸發，以及其介入如何透過動作修改或上下文注入來改變智慧體的決策路徑。分析也探討了在後訓練過程中，結構化介入訊號如何被基礎策略吸收，逐步實現策略內化。此外，研究指出穩定的技能庫演化必須依賴可執行驗證與教師審查，以避免在自我改進過程中引入不穩定或衝突的程式函數。

**Q10：在哪些實務場景中，HASP 的推論階段介入最能發揮效益？**
A：推論階段介入對於無法頻繁重新訓練模型的生產環境特別有價值，例如即時客服智慧體或線上搜尋助手。透過將 PFs 作為外部控制層直接嵌入現有智慧體迴圈，產品團隊無需更新模型權重，即可快速部署針對新發現失效模式的行為修正。這種方式能夠在維持系統穩定運作的同時，即時提供可執行護欄以確保輸出品質。

**Q11：產品團隊在將 HASP 整合至現有智慧體系統時，應考量哪些因素？**
A：產品團隊應善用 HASP 的模組化特性，先從推論階段的 PF 介入開始驗證效益，再逐步導入後訓練與自我改進流程。必須建立嚴謹的驗證管線，對候選 PF 進行語法、介面與模擬執行驗證，確保只有可靠的程式函數能進入活躍技能庫。此外，在面向使用者的應用中，納入教師審查機制對於維持介入邏輯的正確性與防止錯誤修正擴散至關重要。

**Q12：HASP 可能如何影響 LLM 智慧體領域的未來研究與發展？**
A：HASP 確立了將智慧體技能視為可執行程式而非靜態文字的新典範，可能促使研究社群重新思考記憶體與學習架構的設計方向。由於實證顯示明確的狀態–動作介入優於被動提示，未來可能會出現更多針對策略迴圈控制機制與混合神經符號系統的研究。其模組化框架同時串連了推論階段的工程實務與訓練階段的策略最佳化，為智慧體的迭代改進提供了一個統一且可擴展的平台。

**Q13：論文對於 HASP 現行設計的哪些限制有所著墨？**
A：論文指出穩定的技能庫演化需要謹慎的可執行驗證與教師審查，暗示完全自主、無監督的 PF 演化可能導致系統不穩定。此外，PFs 的有效性取決於初始訓練池中失效案例的涵蓋範圍與摘要品質，若原始資料存在偏差，生成的介入邏輯也可能帶有偏誤。雖然模組化設計帶來高度彈性，但隨著技能庫規模擴大，如何高效檢索並解決多個候選 PF 之間的潛在衝突，仍是需要持續優化的挑戰。

**Q14：在哪些情況下，PFs 可能無法改善甚至損害智慧體的表現？**
A：若 PF 的啟動條件定義不精確，可能導致在關鍵狀態下遺漏介入，或在正確的推理鏈上進行不必要的干擾。當技能庫中存在相互衝突的程式函數，或驗證機制不足時，智慧體可能因為矛盾的修正而出現行為震盪或效能退化。此外，在與訓練分佈差異極大的離群情境中，PFs 可能無法適當泛化，反而提供不相關甚至有害的介入。

**Q15：HASP 為可執行技能框架指出了哪些未來研究方向？**
A：未來研究可朝向從大規模互動日誌中自動合成 PFs，以降低對人工教師審查的依賴並提升擴展性。將形式化驗證方法整合至 PF 的啟動與介入邏輯中，有助於在安全性關鍵的應用場景中提供更强的可靠性保證。此外，將 HASP 擴展至多智慧體協作環境，使 PFs 能夠協調分散式智慧體之間的介入行為，也是一個極具潛力且值得探索的發展方向。

## 實務應用指南

### 適用場景

1. **企業級複雜查詢與多輪客服**：在需要多步驟推理的長程任務中，智慧體常因過早終止、未驗證證據或重複無效動作而失敗。HASP 可針對「未核實即給出最終答案」等反覆出現的失效模式部署可執行護欄，於易失效狀態自動介入或注入修正上下文，顯著提升對話完成率。

2. **金融與醫療領域的長文件分析與報告生成**：這類場景對正確性要求極高，傳統文字指引難以強制執行。透過程式函數（PFs）將領域規則（如「引用數據前必須交叉比對至少兩個來源」）轉為可執行技能，能在策略迴圈中直接攔截錯誤決策，避免生成不可挽回的結論。

3. **軟體開發輔助與程式碼審查**：針對 coding 任務中常見的邊界條件遺漏、未處理異常等錯誤，PFs 可在智慧體即將輸出高風險程式碼時觸發，修改候選下一步動作或補充提示，使 pass@1 穩定提升，並作為結構化監督來源用於後續模型微調。

4. **自動化研究助理與深度網路搜尋**：在 web-search 場景中，智慧體容易過早採信單一來源或陷入重複搜尋。HASP 的推論階段介入能於 runtime 偵測這類行為，透過動作修改引導智慧體擴大檢索範圍，平均準確率可較純 ReAct Agent 提升約 25%。

5. **教育領域的數學解題輔導**：數學推理需要嚴謹的中間步驟驗證。將常見的邏輯跳躍或計算失誤封裝為 PFs，可在學生（或智慧體）即將犯下特定錯誤時即時注入提醒，並透過後訓練將這些技能內化至基礎策略中。

### 實作前置條件

**資料需求**：
- 歷史失敗軌跡與對應的成功修復記錄，用於初始化第一版技能庫。
- 領域驗證資料集，供 mock-execution 與語法驗證使用。
- 若進行後訓練，需準備 PF 修正後的結構化介入訊號與軌跡對（原始動作、PF 修復、觀察效果）。

**運算資源**：
- 基礎 LLM 智慧體的推論端點（支援多輪互動）。
- PF 執行環境：輕量級的規則引擎或程式執行沙盒，用於 should_activate 判斷與 intervention 邏輯。
- 後訓練階段需額外 GPU 資源，以執行 SFT、拒絕採樣（RS）或知識蒸餾。

**能力與人力前提**：
- 熟悉現有 Agent 架構（如 ReAct）與策略迴圈運作方式。
- 具備程式設計能力，能將領域經驗轉譯為具備明確介面（should_activate、intervention、emit_signals）的 PFs。
- 領域專家或教師角色，負責審查候選 PFs 的正確性，並把關技能庫演化的品質。

### 實作步驟建議

**步驟一：萃取失效模式，建立初始技能庫**
從現有 LLM 智慧體的日誌中，彙整反覆出現的失效模式（如過早終止、證據未驗證、重複動作）。將這些模式從被動的文字指引轉譯為具體的「狀態–動作」規則，作為第一批候選程式函數（PFs）。

**步驟二：設計與實作 PF 介面**
為每個 PF 定義三個核心介面：`should_activate()`（判斷當前狀態是否滿足觸發條件）、`intervention()`（修改候選下一步動作或執行上下文注入）、`emit_signals()`（輸出結構化介入訊號供下游使用）。確保介入邏輯直接作用於動作空間，而非僅提供建議。

**步驟三：驗證與模擬執行**
在正式上線前，對每個 PF 進行語法檢查、介面一致性驗證與 mock-execution。確認 PF 在 agent loop 中不會引發副作用或無限迴圈後，才允許納入活躍技能庫。

**步驟四：推論階段部署（Inference-time Harness）**
將 HASP 作為外部 harness 層包覆現有基礎智慧體。在每個決策步驟，由 harness 檢索相關 PFs、評估激活條件、執行有效介入，再將修訂後的動作或注入的上下文餵回策略迴圈。此階段無需重新訓練模型即可獲得顯著增益。

**步驟五：結構化監督與後訓練**
收集推論階段產生的 PF 修正軌跡，利用結構化 PF 衍生準則進行評分。將高品質的 PF-corrected traces 用於監督式微調（SFT）、拒絕採樣（RS）或 on-policy distillation，使基礎策略逐步吸收可複用技能，降低對外部 harness 的依賴。

**步驟六：教師審查與技能庫演化**
定期讓系統在當前檢查點下重新檢視失敗案例，自動摘要新的「失敗–修復」模式並生成候選 PFs。經過可執行驗證與教師審查後，穩定地更新外部技能庫，形成「執行→學習→庫成長」的閉環自我改進。

### 潛在風險與注意事項

- **過度介入導致策略僵化**：若 PFs 觸發過於頻繁，可能抑制基礎模型的泛化與探索能力。應持續監控 PF 觸發率與修復成功率，並將 should_activate 條件設計得足夠精準，僅針對高置信度的易失效狀態介入。

- **技能庫膨脹與維護成本**：未經篩選的 PF 累積會增加檢索延遲與執行開銷。必須建立穩定的淘汰機制，對長期未被觸發或修復效果不佳的 PFs 進行降級或移除，維持技能庫演化的穩定性。

- **驗證不足的生產風險**：跳過 mock-execution 驗證直接上線的 PF，可能在真實 agent loop 中產生錯誤介入，引發連鎖失效。務必將驗證閘道設為技能庫更新的強制流程。

- **領域遷移與任務分佈偏移**：在特定領域有效的 PFs，面對新任務分佈時可能失效或誤觸發。建議為每個 PF 記錄適用場景標籤，並在部署新領域前進行小規模對照實驗。

- **教師審查瓶頸**：自我改進迴路依賴教師審查來確保品質。若組織缺乏足夠的領域專家，候選 PFs 的篩選可能成為瓶頸。可輔以自動化測試與多 PF 投票機制來分擔人力負擔。

### 與其他技術的整合建議

- **與 RAG / 向量資料庫整合**：將 PF 的 `should_activate` 條件與向量檢索結合，讓語義相似度輔助判斷當前狀態是否匹配已知失效模式，提升觸發精準度與檢索效率。

- **與現有 Agent 框架（LangChain、AutoGen 等）整合**：HASP 可作為外部控制層，透過包裝器（wrapper）介入原生智慧體迴圈，無需重構現有流程即可疊加可執行護欄能力。

- **與強化學習框架（GRPO、PPO 等）整合**：PFs 產生的結構化介入訊號可作為細緻的獎勵塑形依據，或直接用於拒絕採樣的篩選標準，彌補傳統稀疏任務獎勵的不足。

- **與可觀測性平台整合**：將 PF 觸發事件、介入內容與觀察效果匯入監控系統（如 LangSmith、Weights & Biases），建立可視化的回饋迴路，協助工程師與教師快速定位問題。

- **與低程式碼自動化工具整合**：將 PFs 的 `intervention()` 輸出對接至現有業務流程引擎或 API 閘道，使智慧體的修正動作能直接驅動下游企業系統（如工單建立、資料庫回滾）。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先聚焦「被動文字技能」與「可執行程式函數」的核心差異，把 HASP 理解為智慧體的「自動修正外掛」。閱讀時可優先看論文的圖一與推論階段應用段落，掌握 PFs 如何在關鍵時刻攔截錯誤、修改動作，無需深入後訓練數學細節即可建立直覺。

**給 AI 工程師**：請深入研讀 PF 的介面設計（`should_activate`、`intervention`、`emit_signals`）與 harness 的實作細節。重點評估如何在不修改基礎模型權重的情況下，透過外部控制層包裝現有 agent loop，並規劃從推論介入到結構化監督的漸進式部署路徑。

**給研究人員**：建議深入探討策略內化（policy internalization）的機制，以及技能庫演化（skill library evolution）所需的穩定性條件。可將 HASP 與 SkillRL、SAGE、ExpeL 等方法進行對照，分析其在學習訊號粒度、執行時控制強度與自我改進閉環設計上的差異與優勢。

**給產品經理**：請關注 HASP 三種部署模式（推論階段介入、後訓練、自我改進）的商業價值與成本權衡。論文中 25% 至 30% 的性能提升在實際業務中如何轉化為用戶留存、錯誤率下降或人工複審成本節省，是評估導入優先級與 ROI 的關鍵；同時需預留教師審查與技能庫維運的長期人力預算。
