## ⚡ TL;DR

現有基準難以評估行動代理的真實執行與規劃能力。
本文提出 MobilePA-Bench，以互動式有狀態沙盒評估四大核心能力。

## 摘要翻譯

隨著裝置端大型語言模型代理（on-device LLM agents）逐漸演進為個人副駕駛（personal copilots），行動作業系統（mobile operating system）已成為此典範的關鍵試驗場，使得嚴謹的能力評估（capability evaluation）至關重要。然而，現有基準測試分為兩大陣營，各自存在關鍵盲點：以圖形使用者介面為中心的基準測試（GUI-centric benchmarks）僅測試表層螢幕操作（surface-level screen manipulation），卻忽略了背景工具使用（background tool use）與長程規劃（long-horizon planning）；而靜態函式呼叫基準測試（static function-calling benchmarks）則仰賴離線 API 匹配（offline API matching），與真實的執行階段限制（runtime constraints）脫節。為彌補此缺口，我們提出 MobilePA-Bench，一個互動式（interactive）、具狀態（stateful）且以工具為中心的基準測試（tool-centric benchmark），用於評估行動規劃代理（mobile planner agents）的工具呼叫（tool-calling）與規劃能力（planning abilities）。MobilePA-Bench 運行於可執行沙盒（executable sandbox）之上，該沙盒維護即時應用程式資料庫（live application databases）並回傳結構化回饋（structured feedback），涵蓋 13 個功能領域（functional domains）與 212 個貼近真實情境的行動工具（mobile tools）。除了基本工具使用（Basic Tool Use）之外，它還從三個進階維度評估中央規劃代理（planning agent）：（1）子代理協作（Sub-agent Collaboration）——分解複雜任務（decomposing a complex task）並將專門工作（specialized work）委派（delegating）給能幹的子代理（capable sub-agents）；（2）記憶使用（Memory Usage）——召回儲存的記憶（stored memories）、使用者設定檔（user profiles）與過往偏好（past preferences），以處理隱含請求（implicit requests）；以及（3）技能使用（Skill Usage）——呼叫預先封裝的複合技能（pre-packaged composite skills），而非從頭規劃每一步（planning every step from scratch）。大量實驗顯示，當前的前沿大型語言模型（frontier LLMs）在行動環境中仍然不可靠：在嚴格的工具順序（strict tool ordering）、權限限制（permission limits）與未預期的執行階段錯誤（unexpected runtime errors）下，效能會急遽下降。透過結合互動式函式呼叫沙盒（interactive function-calling sandbox）與基於證據的驗證（evidence-based verification），MobilePA-Bench 既可作為實用的診斷基準測試，也可作為代理式強化學習（agentic reinforcement learning）的互動式基礎——加速可靠行動代理（dependable mobile agents）的發展。

### 核心貢獻（3～5點）
- 提出 MobilePA-Bench，一個互動式、具狀態且以工具為中心的基準測試，彌補現有 GUI-centric 與靜態函式呼叫基準測試在背景工具使用、長程規劃與執行階段限制上的盲點。
- 建構可執行沙盒環境，整合即時應用程式資料庫與結構化回饋，涵蓋 13 個功能領域與 212 個貼近真實情境的行動工具。
- 設計三大進階評估維度——子代理協作、記憶使用與技能使用——使評估超越基本工具使用，聚焦中央規劃代理的高階規劃能力。
- 透過大量實驗揭示前沿大型語言模型在行動環境中的脆弱性，特別是在嚴格工具順序、權限限制與未預期執行階段錯誤下效能急遽下降。
- 結合互動式函式呼叫沙盒與基於證據的驗證，使 MobilePA-Bench 同時具備實用診斷基準與代理式強化學習互動式基礎的雙重價值。

### 適合對象
本論文適合對行動裝置端 AI 代理、工具呼叫與規劃能力評估有興趣的研究人員與工程師；特別適合從事大型語言模型代理、行動作業系統智慧助理、代理式強化學習、人機互動以及行動生態系統相關領域的學者與產品開發者閱讀。

## 深度分析

#### 方法論解析

MobilePA-Bench（行動規劃代理基準測試）的核心方法論，在於把「行動規劃代理（mobile planner agents）」從傳統的 GUI-centric（以圖形使用者介面為中心）或 static function-calling（靜態函式呼叫）評估框架中抽離出來，建立一個 interactive（互動式）、stateful（具狀態）、tool-centric（以工具為中心）的評估沙盒。其設計可從以下四個層面拆解：

1. **Executable Sandbox（可執行沙盒）**  
   不同於靜態字串匹配（static string matching）的離線形式（offline formulation），MobilePA-Bench 運行在一個可執行的沙盒環境中，內含 live application databases（即時應用程式資料庫）。代理發出的 tool calls（工具呼叫）會真實改變資料庫狀態，並收到 structured feedback（結構化回饋）。這讓 runtime constraints（執行階段限制）——例如嚴格的工具順序（strict tool ordering）、權限限制（permission limits）、未預期的執行階段錯誤（unexpected runtime errors）——成為評估的一部分，而非被忽略。

2. **四維能力框架**  
   作者將複雜真實世界任務（complex real-world tasks）拆解為四個互補的規劃能力（planner capabilities）：
   - **Basic Tool Use（基本工具使用）**：處理多模態輸入（如多模態 QR 碼，multimodal QR codes）、遵守執行順序與權限邊界，並根據動態 OS-level exceptions（作業系統層級例外）進行錯誤恢復。
   - **Sub-agent Collaboration（子代理協作）**：將複雜任務分解（decomposing a complex task）後，把專門工作（specialized work）委派（delegating）給能幹的子代理（capable sub-agents），例如當 structured APIs unavailable（結構化 API 不可用）時，交由 visual GUI agent（視覺圖形使用者介面代理）完成表單填寫。
   - **Memory Usage（記憶使用）**：透過 Memory Retrieval（記憶檢索）查詢使用者設定檔（user profiles）、過往偏好（past preferences）與儲存的記憶（stored memories），以解決隱含請求（implicit requests）。
   - **Skill Usage（技能使用）**：調用預先封裝的複合技能（pre-packaged composite skills），例如同步航班與住宿的 Skills Execution（技能執行），避免在長程規劃（long-hoizon planning）中從頭規劃每一步（planning every step from scratch）。

3. **Central Planner（中央規劃代理）與下游執行解耦**  
   方法論上，MobilePA-Bench 把「高階決策」與「低階視覺解析」分離：中央規劃代理負責決定何時呼叫 API、何時使用 skill、何時把任務交給 GUI 子代理；而重複的 pixel-level perception（像素級感知）與 raw GUI manipulation（原始圖形使用者介面操作）則由專屬子代理處理。這種設計符合快速且節能（fast, energy-efficient）的系統層級執行（system-level execution）目標。

4. **Evidence-based Verification（基於證據的驗證）**  
   由於沙盒會回傳真實執行後的結構化狀態變化，評估不僅檢查 API 名稱是否匹配，而是檢視端對端任務（end-to-end task）完成後的證據——例如資料庫是否確實產生訂單、記憶是否被正確引用、子代理交接是否帶有有效上下文（valid contextual handoffs）。

#### 實驗數據解讀

從摘要與引言可歸納出以下實驗發現：

1. **整體表現仍有顯著缺口**  
   即使是最先進的前沿大型語言模型（frontier LLMs），在 MobilePA-Bench 上的整體表現也僅達 **75.52%**。這表示在 1,705 個真實任務中，仍有約四分之一的端對端任務失敗，顯示現有模型距離可靠的行動代理（dependable mobile agents）尚有一段距離。

2. **嚴格執行條件下的性能崩落**  
   實驗指出，當面臨 strict tool ordering、permission limits 與 unexpected runtime errors 時，模型表現會急劇下降。這呼應了方法論的核心論點：靜態函式呼叫基準測試（static function-calling benchmarks）無法捕捉真實行動作業系統（mobile operating system）中的動態摩擦；而僅有離線 API 匹配能力的模型，在具狀態環境中容易因為一步錯誤而導致後續連鎖失敗。

3. **四維能力的難度分佈**  
   雖然完整數據表未在提供的節錄中出現，但從敘述可推論：
   - **Basic Tool Use** 是基礎門檻，卻因權限與順序限制而經常出錯。
   - **Sub-agent Collaboration** 要求模型具備任務分解與上下文交接能力，是較高階的挑戰。
   - **Memory Usage** 涉及隱含請求與個人化推理，模型必須先檢索再規劃，否則會產生不符合使用者偏好的計畫。
   - **Skill Usage** 則考驗模型是否能識別並調用預先封裝的複合技能，而非自行展開長步驟流程；錯誤的技能選擇會導致 error accumulation（錯誤累積）。

4. **失敗模式的診斷價值**  
   MobilePA-Bench 不只是一個排名工具，更是一個 diagnostic suite（診斷套件）。透過區分「規劃錯誤」、「工具順序錯誤」、「記憶檢索失敗」與「子代理交接失敗」，研究者可以定位模型在 mobile planning 上的具體弱點。

#### 與現有研究的比較

MobilePA-Bench 在定位上明確區隔於兩類既有研究：

1. **相對於 GUI-centric mobile benchmarks（以視覺為中心的行動基準測試）**  
   AndroidWorld、OSWorld、MobiBench、MobiFlow 等框架著重於 raw GUI manipulation 與 pixel-level perception。這些研究雖能測試低階感知與版面接地（layout grounding），但忽略了 background tool use 與 long-horizon planning。MobilePA-Bench 的改進在於：將視覺操作降級為「必要時才使用的子代理能力」，讓中央規劃代理專注於系統層級執行與結構化 API 的協調。

2. **相對於 static function-calling benchmarks（靜態函式呼叫基準測試）**  
   傳統文字型函式呼叫基準僅以 static string matching 評估規劃能力，缺乏 real-time environmental feedback。MobilePA-Bench 透過 executable sandbox 與 live application databases，把 runtime constraints 納入評估，彌補了離線形式與真實執行之間的落差。

3. **相對於單一能力基準**  
   過去許多基準只測試單一維度，例如記憶檢索、工具使用或多代理協作。MobilePA-Bench 的貢獻在於提供一個 unified evaluation framework（統一評估框架），同時涵蓋 Basic Tool Use、Sub-agent Collaboration、Memory Usage 與 Skill Usage，並以真實的端對端任務串連這四個維度。

4. **限制與潛在批評**  
   - **沙盒與真實裝置的落差**：雖然 sandbox 模擬了 live databases，但仍可能無法完全複製真實行動裝置上的網路延遲、電池限制、背景程序競爭等現象。
   - **子代理能力的理想化**：實驗中假設 GUI sub-agent 具備足夠能力完成被委派的任務；在現實中，子代理本身也可能失敗，進而影響整體評估。
   - **任務覆蓋範圍**：13 個功能領域與 212 個工具雖已相當廣泛，但行動生態系統（mobile ecosystem）持續擴張，新興應用與權限模型可能未被涵蓋。

#### 可重現性評估

根據摘要與引言的宣示，MobilePA-Bench 在可重現性（reproducibility）方面採取開放策略：

1. **完整開源基礎設施**  
   作者承諾 open-source 完整的基礎設施，包括全部 1,705 個基準任務、評估資料集，以及 high-throughput sandbox environment（高吞吐量沙盒環境）。這對於後續的 agent training（代理訓練）與代理式強化學習（agentic reinforcement learning）至關重要。

2. **可執行環境降低重現門檻**  
   相較於僅提供靜態資料集的基準，MobilePA-Bench 提供 executable sandbox，讓其他研究者可以在相同環境下執行代理、觀察 structured feedback，並比較不同模型的行為軌跡。

3. **尚待確認的項目**  
   由於提供的節錄未包含實驗細節與附錄，以下項目仍需查閱完整論文與程式庫確認：
   - 是否提供 model weights（模型權重）或僅提供 baseline 的 prompt 與設定。
   - sandbox 的相依性與執行平台（例如是否基於 Android emulator、Docker 或自訂模擬器）。
   - 評分器的具體實作細節，特別是 evidence-based verification 的判斷邏輯。

#### 未來研究方向

基於 MobilePA-Bench 所揭示的缺口與其開放的基礎設施，可延伸出以下研究方向：

1. **具錯誤恢復能力的規劃模型**  
   由於現有 frontier LLMs 在 strict tool ordering 與 unexpected runtime errors 下表現不佳，未來可研究如何在規劃階段內建 retry mechanism（重試機制）、fallback policy（後備策略）與 exception-aware planning（例外感知規劃）。

2. **記憶與個人化推理的深化**  
   Memory Usage 要求代理不僅檢索事實，還要將 user profiles 與 past preferences 整合進規劃。未來可探索長期記憶架構、偏好衝突解決，以及隱含請求（implicit requests）的推論強化。

3. **動態技能發現與學習**  
   Skill Usage 目前聚焦於調用預先封裝的複合技能。下一步可研究如何讓代理在執行過程中自動發現、組合甚至學習新的 composite skills，以適應未見過的功能領域。

4. **多代理協作機制的最佳化**  
   Sub-agent Collaboration 涉及任務分解與上下文交接。未來可發展更細緻的 handoff protocol（交接協定）、子代理能力建模，以及中央規劃代理與 GUI sub-agent 之間的通訊效率最佳化。

5. **代理式強化學習的訓練平台**  
   MobilePA-Bench 的 interactive function-calling sandbox 可作為 agentic reinforcement learning 的訓練環境。研究者可以在此設計 reward shaping（獎勵塑造）、trajectory-level optimization（軌跡層級最佳化），以及從人類回饋中學習（learning from human feedback）的機制。

6. **真實裝置部署與邊緣運算**  
   最終，mobile planner agents 需要運行於 on-device LLM agents 上。未來研究可關注模型壓縮、推論效率、隱私保護的記憶管理，以及如何在資源受限的裝置端維持高階規劃能力。

## 論文問答

**Q1：MobilePA-Bench 旨在解決現有行動代理評測中的什麼核心問題？**
A：現有基準測試主要分為以圖形使用者介面為中心與靜態函式呼叫兩大陣營，前者只測試表層螢幕操作，後者僅做離線 API 字串匹配，兩者都無法捕捉真實裝置端智慧所需的系統層級協調與長程規劃。MobilePA-Bench 因此提出一個互動式、具狀態、以工具為中心的評測框架，專門檢驗行動規劃代理在複雜真實世界任務中的工具呼叫與規劃能力。這個基準測試強調即時環境回饋、執行階段限制與多維度能力，彌補了既有方法在背景工具使用與動態執行方面的盲點。

**Q2：為什麼單純的 GUI 操作或靜態函式呼叫不足以評估真正的行動代理？**
A：以視覺為中心的基準測試聚焦像素級感知與原始 GUI 操作，雖能檢驗低階介面互動，卻忽略了背景工具使用、結構化 API 與長程規劃等系統層級執行能力。另一方面，文字型函式呼叫基準採用靜態字串匹配，無法反映執行階段的權限限制、嚴格工具順序與未預期的作業系統層級例外。真實的行動代理必須在動態、有狀態的環境中同時處理多模態輸入、記憶檢索與子代理協作，因此需要更貼近實際執行條件的評測方式。

**Q3：為什麼嚴謹評估行動規劃代理對個人副駕駛的發展至關重要？**
A：隨著裝置端大型語言模型代理逐漸演變為個人副駕駛，行動作業系統已成為驗證此典範的關鍵試驗場，代理必須主動理解自然語言意圖並協調複雜系統工具。真實任務如規劃三天上海行程，涉及記憶檢索、航班與飯店預訂技能、QR 碼掃描，以及無結構化 API 時交由視覺 GUI 代理處理，這些都無法用單一模式完成。若缺乏嚴謹評估，將難以發現模型在權限、順序與錯誤恢復上的脆弱性，進而阻礙可靠行動代理的落地。

**Q4：MobilePA-Bench 的核心架構與運作方式是什麼？**
A：MobilePA-Bench 建構在一個可執行沙盒之上，沙盒維護即時應用程式資料庫並在每次工具呼叫後回傳結構化回饋，讓中央規劃代理能觀察狀態變化與執行結果。該基準涵蓋 1,705 個真實世界使用者任務、橫跨 13 個功能領域與 212 個寫實行動工具，並從四個維度評估代理：基本工具使用、子代理協作、記憶使用與技能使用。透過將中央規劃與低階視覺解析解耦，平台能專注診斷高階決策、技能選擇與執行階段錯誤恢復能力。

**Q5：MobilePA-Bench 相較於既有基準的關鍵創新是什麼？**
A：其關鍵創新在於把「中央規劃」與「視覺佈局解析」分離，讓 GUI 操作交由專門的下游視覺 GUI 代理處理，中央代理則專注於任務分解、工具選擇與子代理協作。同時，它引入具狀態的互動式函式呼叫沙盒，能模擬真實的執行階段摩擦，例如呼叫相依性、權限阻擋與動態狀態突變。這種設計結合基於證據的驗證，使評測不再只是離線 API 匹配，而能反映端對端任務的真實執行保真度。

**Q6：為何 MobilePA-Bench 選擇以工具為中心，而非純視覺導向的設計？**
A：作者認為原始 GUI 操作只是行動生態系統的一小部分，稱職的行動代理應優先採用結構化 API 進行快速且節能的系統層級執行，而非浪費運算資源在重複的視覺解析上。以工具為中心的設計能直接檢驗代理如何選擇正確 API、遵守嚴格工具順序、處理權限限制與未預期執行階段錯誤。當結構化 API 不可用時，再透過子代理協作將視覺表單填寫等任務委派給 GUI 代理，兼顧效率與彈性。

**Q7：MobilePA-Bench 的任務規模與覆蓋範圍為何？**
A：該基準共收錄 1,705 個真實世界使用者任務，涵蓋 13 個功能領域，並提供 212 個寫實行動工具供代理呼叫。這些任務設計為端對端執行，要求代理同時運用記憶檢索、複合技能、基本工具與子代理協作才能完成。如此規模與多樣性使 MobilePA-Bench 能系統性地診斷代理在不同領域與能力維度上的強弱項。

**Q8：實驗中前沿大型語言模型的整體表現如何？**
A：實驗顯示，即使是最先進的前沿大型語言模型，在行動設定中仍然不夠可靠，最佳模型整體準確率僅達 75.52%。當面臨嚴格工具順序、權限限制與未預期執行階段錯誤時，模型表現會急劇下降。這些結果凸顯出當前模型在動態、有狀態環境中進行長程規劃與錯誤恢復的關鍵缺陷。

**Q9：哪些能力維度或情境最讓現有模型受挫？**
A：模型在子代理協作、模糊記憶檢索與執行階段例外處理上特別脆弱，因為這些情境需要正確的任務分解、有效的上下文交接與穩健的錯誤恢復。嚴格的工具呼叫順序與權限邊界也會造成明顯的效能下滑，顯示代理難以在受限環境中維持正確執行軌跡。此外，當結構化 API 不可用而必須 fallback 到視覺 GUI 代理時，上下文傳遞不完整常導致任務失敗。

**Q10：MobilePA-Bench 如何對應到真實產品中的使用情境？**
A：圖一中的三天上海行程即為典型範例：代理需檢索使用者偏好與個人詳細資料、執行航班與飯店預訂的複合技能、掃描多模態 QR 碼，並在博物館預訂無 API 時交由 GUI 代理完成表單填寫。這類端對端任務正是個人副駕駛日常需要處理的複雜工作流程。MobilePA-Bench 提供可重現的診斷場景，幫助產品團隊識別代理在記憶、技能、工具與協作上的具體瓶頸。

**Q11：將 MobilePA-Bench 的評測結果轉化為實際產品時，應考量哪些設計議題？**
A：產品化時必須妥善處理權限管理、隱私保護與本地記憶的安全存取，因為代理會頻繁查詢使用者設定檔與過往偏好。此外，需要設計有效的錯誤恢復機制與子代理間的上下文交接協議，以避免在 API 失敗或 GUI 步驟中斷時任務崩潰。最後，為了符合行動裝置的能耗與延遲限制，應優先使用結構化 API，並只在必要時才啟動視覺 GUI 代理。

**Q12：MobilePA-Bench 對行動代理研究領域可能帶來什麼影響？**
A：它為行動規劃代理提供了一個統一且開源的診斷基準，將研究焦點從單純的像素點擊轉向系統層級規劃與多代理協調。完整開源的 1,705 項任務、評測資料集與高吞吐量沙盒環境，可作為代理式強化學習與未來代理訓練的互動式基礎。長遠來看，這有助於加速開發更可靠、更能適應真實行動作業系統限制的個人副駕駛。

**Q13：MobilePA-Bench 目前有哪些可能的限制？**
A：儘管沙盒能模擬即時應用程式資料庫與執行階段摩擦，它仍屬於模擬環境，可能無法完全複製真實裝置上的硬體差異、網路延遲與各種廠商定製介面。此外，目前的 13 個功能領域與 212 個工具雖已相當廣泛，但仍難以涵蓋所有真實世界應用程式與邊緣案例。未來需要持續擴充領域、引入真實裝置部署，並加強對安全與隱私風險的評估。

**Q14：根據實驗觀察，模型常見的失敗案例有哪些？**
A：常見失敗包括未依正確順序呼叫工具而觸發相依性錯誤、在權限被拒時無法調整策略，以及遇到未預期執行階段錯誤後無法有效恢復。在記憶使用方面，模型常難以從模糊請求中推斷出應檢索的使用者偏好或個人詳細資料。在子代理協作中，上下文交接不完整會導致 GUI 代理無法正確填寫表單或確認預訂，最終使端對端任務失敗。

**Q15：未來研究可朝哪些方向延伸 MobilePA-Bench？**
A：未來可擴展更多功能領域與行動工具，並將沙盒部署到真實裝置上，以捕捉更豐富的硬體與網路變異。同時可發展更強大的子代理協作協議與多模態感知能力，讓中央規劃代理與 GUI 代理之間的上下文傳遞更順暢。此外，結合代理式強化學習，讓模型從互動式沙盒的結構化回饋中持續學習，並納入個人化、安全與隱私保護機制，將是提升可靠行動代理的重要方向。

## 實務應用指南

## 適用場景

1. **個人行程與差旅助理**  
   使用者以自然語言要求「下週三去上海三天，包含往返機票、飯店與景點」，行動規劃代理需檢索使用者偏好（居住城市、艙等、飯店星等）、呼叫航班／飯店預訂技能，並在僅有 QR 碼或視覺表單時交由 GUI 子代理完成預約。

2. **跨 App 自動化工作流程**  
   例如「幫我把相簿裡上週的發票截圖整理成報帳清單，並上傳到雲端硬碟」。代理必須協調相簿、OCR、檔案管理、雲端儲存等多個行動工具，處理權限與工具呼叫順序。

3. **裝置端智慧家居／IoT 控制中心**  
   使用者說「我回家後開啟冷氣、播放輕音樂、把燈光調到閱讀模式」。代理需根據使用者過往偏好與目前裝置狀態，規劃並執行一連串需要嚴格順序的技能呼叫。

4. **企業行動化業務流程（mBPM）**  
   例如業務人員在外勤時說「幫我查詢客戶 A 的合約、產生拜訪紀錄草稿並寄送給主管」。代理需整合 CRM、郵件、行事曆與文件工具，並在結構化 API 不可用時切換至 GUI 子代理操作第三方 App。

5. **長期個人化推薦與提醒**  
   例如「週末幫我安排一場符合我飲食偏好的聚餐，並提前訂位」。代理需回憶儲存的記憶與過往偏好，將隱含請求轉為明確計畫，再委派給餐廳搜尋與訂位技能。

## 實作前置條件

### 資料準備
- **工具與 API 規格**：整理目標領域的結構化 API 描述（名稱、參數、回傳格式、必填欄位、權限需求），建議參考 MobilePA-Bench 的 212 個行動工具格式。
- **使用者記憶與偏好資料庫**：建立可持久化的使用者設定檔、過往偏好與歷史互動紀錄，供記憶檢索模組查詢。
- **任務語料與評測集**：收集真實世界多步驟任務描述，並標註正確的工具呼叫序列、預期狀態變化與驗證條件。

### 運算資源
- **沙盒執行環境**：需可執行的模擬或真實行動作業系統沙盒，能維護即時應用程式資料庫並回傳結構化回饋。
- **模型推理資源**：中央規劃代理建議使用具備函式呼叫能力的前沿大型語言模型；GUI 子代理則需要視覺語言模型（VLM）與截圖解析能力。
- **評測與日誌基礎設施**：支援高吞吐量執行、狀態追蹤、錯誤重現與基於證據的驗證（evidence-based verification）。

### 技能與團隊準備
- **多代理協作設計能力**：能設計中央規劃代理與 GUI 子代理之間的上下文交接協定。
- **行動系統與權限知識**：熟悉 Android／iOS 權限模型、背景工具執行、App 間通訊與常見執行階段例外。
- **強化學習或偏好調優經驗**：若希望將沙盒用於代理式強化學習，需具備軌跡收集、獎勵設計與模型微調能力。

## 實作步驟建議

1. **定義能力維度與任務範圍**  
   依產品需求選擇四大能力維度：基本工具使用、子代理協作、記憶使用、技能使用，並列出優先支援的功能領域（如旅遊、行事曆、通訊、裝置控制）。

2. **建立互動式函式呼叫沙盒**  
   建置可執行的有狀態沙盒，內含即時應用程式資料庫，能模擬真實執行階段限制（權限封鎖、工具相依性、未預期錯誤），並回傳結構化回饋。

3. **設計工具與技能註冊表**  
   將所有行動工具與預先封裝的複合技能標準化為結構化描述，明確定義輸入、輸出、副作用、呼叫順序與權限需求。

4. **開發中央規劃代理**  
   讓 LLM 根據使用者自然語言意圖進行高階決策：判斷是否需要記憶檢索、是否呼叫複合技能、是否將視覺操作委派給 GUI 子代理。

5. **實作子代理協作協定**  
   定義中央規劃代理與 GUI 子代理之間的上下文交接格式，確保任務分解、狀態傳遞與結果回報一致。

6. **建立記憶檢索與偏好解析模組**  
   在使用者請求模糊時，先查詢使用者設定檔與過往偏好，將隱含請求轉為明確參數後再進行規劃。

7. **執行端對端評測與診斷**  
   使用 MobilePA-Bench 類型的任務集，評估代理在嚴格工具順序、權限限制與執行階段錯誤下的表現，並針對失敗模式迭代。

8. **部署與持續學習**  
   將沙盒作為互動式基礎設施，收集真實軌跡並用於代理式強化學習或偏好微調，逐步提升可靠性。

## 潛在風險與注意事項

| 風險 | 說明 | 因應措施 |
|---|---|---|
| **工具呼叫順序錯誤** | 真實行動任務常有嚴格相依性，順序錯誤會導致狀態不一致或交易失敗。 | 在沙盒中明確建模前置條件，並於規劃階段強制檢查呼叫順序。 |
| **權限與隱私外洩** | 代理可能過度索取敏感權限（聯絡人、位置、相機），或在不當情境使用個人資料。 | 採用最小權限原則，對記憶檢索與個人資料使用進行稽核與使用者確認。 |
| **執行階段例外處理不足** | 網路中斷、App 未回應、API 變更等未預期錯誤會讓代理陷入迴圈或產生錯誤動作。 | 設計標準化錯誤回饋與重試機制，並在沙盒中大量注入例外情境進行壓力測試。 |
| **過度依賴 GUI 子代理** | 凡事都交給視覺代理會浪費運算、降低速度，且容易受畫面變動影響。 | 優先使用結構化 API 與複合技能，僅在結構化 API 不可用時才 fallback 至 GUI 子代理。 |
| **長程任務錯誤累積** | 多步驟工作流程中，前期小錯會被後續步驟放大。 | 引入中間狀態驗證與檢查點，並使用預先封裝的複合技能減少細粒度規劃錯誤。 |
| **評測與真實環境落差** | 沙盒無法完全模擬所有真實裝置行為，可能產生過度樂觀的評測結果。 | 定期將通過沙盒的代理部署至真實裝置進行小規模測試，並持續更新沙盒資料庫。 |

## 與其他技術的整合建議

- **與現有 GUI 自動化框架整合**  
  可將 AndroidWorld、OSWorld 等 GUI 中心基準測試作為下游 GUI 子代理的訓練與評測環境，而中央規劃代理專注於高階決策與工具編排。

- **與企業 API 閘道整合**  
  將行動工具註冊到企業現有的 API 管理或微服務網格，讓代理能安全地呼叫後端服務，同時統一進行身份驗證、速率限制與日誌記錄。

- **與向量資料庫／RAG 整合**  
  使用者記憶與偏好可儲存於向量資料庫，結合檢索增強生成（RAG）技術，讓代理在規劃前快速回憶相關上下文。

- **與強化學習管線整合**  
  將 MobilePA-Bench 風格的互動式沙盒作為環境，收集成功與失敗軌跡，用於 PPO、DPO 等代理式強化學習，持續優化規劃策略。

- **與監控與可解釋性工具整合**  
  搭配追蹤工具鏈（如 LangSmith、Langfuse）記錄每次工具呼叫、子代理交接與狀態變化，便於事後診斷與合規稽核。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從圖 1 的端對端任務範例入手，理解「記憶檢索、技能執行、基本工具使用、子代理協作」四個核心能力的分工，再回頭閱讀 MobilePA-Bench 的設計動機，無需一開始深入模型細節或沙盒實作。

**AI 工程師**：請重點關注互動式函式呼叫沙盒的設計、工具註冊表格式、中央規劃代理與 GUI 子代理的上下文交接協定，以及論文揭示的失敗模式（嚴格工具順序、權限限制、執行階段錯誤），這些是將論文轉為產品時最直接的工程參考。

**研究人員**：建議深入分析四大能力維度的評測方法論、1,705 個任務與 212 個工具的覆蓋設計，以及基於證據的驗證機制；可進一步將開源基礎設施作為代理式強化學習或多代理協作研究的實驗平台。

**產品經理**：請聚焦於「為何現有 GUI 中心與靜態函式呼叫基準測試無法滿足真實需求」的論證，以及 MobilePA-Bench 如何幫助團隊診斷產品在複雜真實世界任務中的可靠性缺口，並據此規劃功能優先順序與風險控管策略。
