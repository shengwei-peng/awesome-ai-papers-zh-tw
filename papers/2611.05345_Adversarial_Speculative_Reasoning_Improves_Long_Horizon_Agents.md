本文提出「對抗推測推理」（Adversarial Speculative Reasoning, ASR），其核心洞見在於重新詮釋推測解碼（speculative decoding）機制中草稿模型（draft model）的角色。傳統觀點將草稿模型視為純粹的加速器（pure accelerator），其唯一目標是最大化接受率（acceptance rate）以提升解碼速度（decoding speed）。然而，本文論證在長程代理（long-horizon agent）場景下，草稿模型應被重新定位為「上下文精度的主動分配器」（active allocator for context precision）。

**核心問題的識別**

論文首先揭示一個被忽略的現象：推測驗證（speculative verification）在分佈層面是無損的（lossless in distribution），但在數值精度（numerical precision）層面並非均勻（not neutral in precision）。具體而言，透過對相同前綴（prefix）重複執行前向傳遞（forward pass）並比較 top-k 對數概率（log-probabilities），作者發現：

2. 在最後一槽，對數概率偏移（log-probability shifts）超過 2 個自然對數單位（nats）的情況幾乎是首槽的兩倍。

此現象的根源在於前沿模型（frontier models）並非以理想化方式託管：低精度權重（low-precision weights）、KV 快取量化（KV cache quantization）、稀疏注意力（sparse attention）等部署技術使得目標模型（target model）的邏輯值（logits）成為一個依賴計算佈局（computation layout）的噪聲量。

**方法設計**

ASR 的關鍵設計在於利用拒絕採樣規則（rejection-sampling rule）所賦予的自由度。當草稿詞元（draft token）被接受時，該詞元以驗證槽位（verification slot）所對應的精度被提交至 KV 快取；當草稿詞元被拒絕時，目標模型透過殘差分佈重採樣（residual distribution resampling）生成新詞元，並被寫入新驗證區塊的首槽——即噪聲最低的位置。

因此，方法的核心策略為：

1. **識別關鍵推理點（critical reasoning points）**：在代理軌跡（agent traces）中定位那些承載關鍵決策框架（decision framing）的思考詞元（thinking tokens），例如以原則與證據（principle and evidence）為框架的推理、以測試驅動（test-driven）的決策等。論文審計顯示，這類框架的正確率約為以可能性或風險為框架的推理的兩倍。

2. **建構偏好對（preference pairs）**：在替代性決策框架之間建立對比資料。

3. **反向直接偏好優化（reverse DPO）**：以反向方向訓練草稿模型，使其傾向於選擇目標模型應避免的框架。直觀而言，草稿模型被訓練為「在關鍵決策點被拒絕」（trained to be rejected）。

4. **推理時機制**：在推論階段，草稿與目標恰好在這些決策點分歧，目標模型自身的選擇透過殘差採樣被提交，並以最低噪聲條件編碼至 KV 快取。

此方法的一大優勢在於：目標模型完全不變，驗證規則及其精確性保證（exactness guarantee）也保持完整。僅改變草稿模型，從而重新分配上下文精度（context precision）。訓練參數量僅佔託管參數（hosted parameters）的 0.06% 至 0.28%。

### 潛在風險與注意事項

**風險一：過度拒絕導致加速效果損失**
若草稿模型在太多位置被訓練為「應該被拒絕」，會導致整體接受率下降，推論速度變慢。**緩解措施**：僅在經驗證確實是關鍵決策點的位置進行反向 DPO 訓練，並監控平均接受長度，確保加速比沒有顯著下降。

**風險二：決策點識別錯誤**
若將非關鍵位置誤判為關鍵決策點，會浪費訓練訊號；若漏掉真正的關鍵點，則無法發揮效果。**緩解措施**：使用多種識別方法（規則、分類器、LLLM-as-a-judge）進行交叉驗證，並進行消融實驗確認識別品質。

**風險三：泛化能力不足**
訓練資料可能無法覆蓋所有任務類型，導致在新任務上效果不佳。**緩解措施**：使用多樣化的任務進行訓練，並在多個基準上進行評估；考慮加入任務類型標籤，進行條件化訓練。

**風險四：與目標模型版本的耦合**
若目標模型更新（例如從 GLM-5.3 升級到 GLM-5.4），草稿模型可能需要重新訓練。**緩解措施**：建立自動化的草稿模型重訓練流程，並在新版本發布時進行快速適配。

**風險五：KV 快取噪聲的測量誤差**
論文中的噪聲測量是透過重跑相同前向傳遞進行的，這在某些推論引擎上可能無法精確重現。**緩解措施**：在實際部署環境中進行噪聲測量，而非依賴論文的測量結果；根據實際測量調整訓練策略。

**風險六：決策框架的時效性**
論文指出「正確決策不一定在整個任務生命週期中都保持正確」，有些錯誤決策可透過環境回饋修正。**緩解措施**：不要過度訓練草稿模型在所有決策點都被拒絕，保留一定的彈性讓代理能夠自我修正。

**風險七：評估基準的侷限性**
論文主要在 DeepSWE 上評估，其他類型的長程任務（如研究、寫作）效果可能不同。**緩解措施**：在實際應用場景中進行小規模 A/B 測試，而非僅依賴基準測試結果。

**與代理框架整合**
可與 SWE-agent、OpenHands、AutoGen 等代理框架整合。整合點在於：
- 在代理框架中標註關鍵決策點的類型
- 將標註資訊傳遞給推論引擎，用於選擇性地啟用反向 DPO 行為
- 在代理軌跡中記錄決策點的拒絕/接受狀態，用於後續分析

**與 RLHF / DPO 流程整合**
本方法的反向 DPO 訓練可與目標模型的 RLHF 流程並行進行，但需要注意：
- 草稿模型的訓練資料應來自目標模型的軌跡，而非草稿模型自身的軌跡
- 草稿模型的訓練目標與目標模型的訓練目標相反，這需要在訓練流程中明確區分

**與推論加速技術整合**
可與投機性執行（Speculative Execution）、連續批次處理（Continuous Batching）、分頁注意力（Paged Attention）等技術疊加使用。本方法不改變推論引擎的整體架構，因此與這些技術完全相容。

**與監控與可觀測性整合**

- 每個驗證區塊的噪聲水平
- 關鍵決策點的拒絕率
- 草稿接受長度的分佈
- 端到端任務成功率
