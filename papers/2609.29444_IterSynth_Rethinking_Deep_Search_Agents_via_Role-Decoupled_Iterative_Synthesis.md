## ⚡ TL;DR

現有 ReAct 深度搜尋智慧體存在能力耦合與上下文累積問題，導致長程搜尋效能下降。
本文提出 IterSynth，以規劃器與合成器角色解耦迭代，並透過 RDPO 訓練角色專屬策略。
IterSynth-8B 在五項基準平均達 50.7%，領先同規模模型 4.2%，並提升前沿模型零樣本表現。

## 摘要翻譯

深度搜尋（deep search）要求大型語言模型智慧體（LLM agents）分解複雜查詢（complex query）、搜尋證據，並合成基於證據的答案；然而現有的 ReAct 風格智慧體（ReAct-style agents）面臨兩項限制：角色耦合（role coupling），即單一策略必須同時處理規劃（planning）、證據運用與合成；以及上下文累積（context accumulation），即不斷增長的搜尋歷史（search histories）會引入雜訊並遮蔽有用資訊。為了解決這些問題，我們提出 IterSynth，一種角色解耦（role-decoupled）且基於摘要（summary-based）的典範，讓規劃器（Planner）負責識別資訊需求、合成器（Synthesizer）負責將證據整合到持續演進的摘要狀態（summary state），兩者交替運作。此設計將規劃與合成分離，同時以摘要作為搜尋的持久狀態，從而降低能力耦合（capability coupling）與上下文雜訊。為了有效訓練 IterSynth，我們進一步提出用於強化學習（reinforcement learning）的角色解耦策略最佳化（Role-Decoupled Policy Optimization, RDPO），結合終端結果獎勵（terminal outcome rewards）與回合級評分標準評估（turn-level rubric evaluations），並計算角色特定優勢（role-specific advantages）以實現更精確的信用分配（credit assignment）。在五個長程深度搜尋基準（long-horizon deep-search benchmarks，如 BrowseComp 與 Xbench-DS）上的實驗顯示，IterSynth-8B 的平均分數達到 50.7，超越先前最強的 ≤8B 智慧體達 +4.2%。此外，IterSynth 亦可作為模型無關提示典範（model-agnostic prompting paradigm），在前沿專有模型（frontier proprietary models）上相較於 ReAct 及類似提示典範，帶來顯著的零樣本增益（zero-shot gains）。

### 核心貢獻（3～5點）
- 提出 IterSynth，一種角色解耦且基於摘要的深度搜尋智慧體典範，將規劃（Planner）與合成（Synthesizer）分離，並以摘要狀態作為持久狀態，降低能力耦合與上下文雜訊。
- 提出角色解耦策略最佳化（RDPO），結合終端結果獎勵、回合級評分標準評估與角色特定優勢，實現更精確的信用分配。
- 在 BrowseComp、Xbench-DS 等五個長程深度搜尋基準上驗證，IterSynth-8B 平均分數達 50.7，超越先前最強 ≤8B 智慧體達 4.2 個百分點。
- IterSynth 亦可作為模型無關提示典範，在前沿專有模型上相較於 ReAct 帶來顯著零樣本增益。

### 適合對象
本論文適合對大型語言模型智慧體、深度搜尋、強化學習與多智慧體系統有興趣的研究人員與工程師，特別是關注如何透過角色解耦與摘要機制提升長程搜尋效能、以及如何設計更有效之信用分配機制的讀者。

## 深度分析

#### 方法論解析

IterSynth（角色解耦迭代合成框架）的核心設計是將傳統由單一策略（single policy）承擔的「規劃（planning）—檢索—證據使用—合成（synthesis）」流程，拆分成兩個在**同一個大型語言模型（Large Language Model, LLM）**內交替執行的角色：**規劃器（Planner）**與**合成器（Synthesizer）**。這兩個角色共享同一組參數，但在每一回合（turn）中負責截然不同的認知工作，從而同時達到多智慧體系統（multi-agent systems）的專業化優勢，以及基於摘要的系統（summary-based systems）的上下文控制優勢，卻不需要額外模型或參數。

**1. 規劃器（Planner）與合成器（Synthesizer）的角色分工**

- **規劃器（Planner）**：面對的是經過壓縮後的「摘要狀態（summary state）」，其任務是進行高階資訊需求分析、缺口識別（gap identification）、查詢制定（query formulation），並決定下一步要發出的搜尋查詢。由於它不接觸原始檢索段落（retrieved passages），因此能專注於「還需要什麼證據」，避免被大量細節淹沒。
- **合成器（Synthesizer）**：讀取規劃器產生的查詢所帶回的證據，負責將有用發現整合進持續演化的摘要狀態（summary state）中，同時進行證據過濾（evidence filtering）、衝突解決（conflict resolution）與雜訊抑制。換言之，合成器不決定「下一步搜尋什麼」，而是決定「這些證據如何改變我們目前已知的答案」。

這種角色解耦（role decoupling）的關鍵在於：**摘要（summary）不是被動的緊湊記憶（compact memory）或外部輔助模組（external auxiliary module），而是搜尋過程的持久狀態（persistent state）**。每次合成器更新摘要後，下一回合的規劃器便在這個更新後的摘要上運作。如此一來，上下文累積（context accumulation）所帶來的雜訊被有效抑制，因為原始搜尋歷史（search histories）不會無限制地傳遞，只有經過合成器篩選與整合後的資訊才會進入後續決策。

**2. 從監督式微調（SFT）到角色解耦策略最佳化（RDPO）的訓練管線**

作者提出一條「冷啟動 SFT → 強化學習（reinforcement learning, RL）」的兩階段訓練配方：

- **冷啟動 SFT 階段**：透過模仿學習讓模型學會 Planner–Synthesizer 的互動格式，產生有效的迭代搜尋軌跡（search-and-reasoning trajectories）。然而，單純的 SFT 只能學會「如何互動」，並未明確最佳化「何時該搜尋」「該保留哪些證據」以及「兩個角色該如何協調」。
- **RDPO（Role-Decoupled Policy Optimization，角色解耦策略最佳化）**：為了解決上述問題，RDPO 結合了兩種獎勵訊號：
  1. **終端結果獎勵（terminal outcome rewards）**：根據最終答案是否正確給予獎勵。
  2. **回合級評分標準評估（turn-level rubric evaluations）**：在搜尋過程的每一回合，根據預設評分標準給予中間獎勵，例如查詢是否切題、摘要是否準確整合證據、是否出現冗餘搜尋（redundant searches）或過早終止（premature termination）等。

更重要的是，RDPO 針對**每個角色分別計算群組相對優勢（group-relative advantages）**，也就是為規劃器（Planner）與合成器（Synthesizer）各自估計角色特定優勢（role-specific advantages）。這種設計大幅改善了長程軌跡中的信用分配（credit assignment）問題：當最終答案正確或錯誤時，模型能更精確地判斷是「規劃器選錯了查詢方向」還是「合成器誤解了證據」，從而讓兩個角色的策略各自朝正確方向更新。

相較於傳統的結果驅動強化學習（outcome-driven RL）——例如僅使用最終獎勵的 GRPO——RDPO 透過回合級評分標準與角色分離的優勢估計，讓模型在探索密集（exploration-intensive）的基準上獲得更穩定的提升。

#### 實驗數據解讀

論文在五個長程深度搜尋基準（long-horizon deep-search benchmarks）上進行評估，包括 GAIA-text-only、xBench-2505、xBench-2510、BrowseComp 與 BrowseComp-ZH。這些基準涵蓋了英文與中文的複雜查詢（complex query），需要智慧體進行多輪檢索、推理與答案合成。

**1. 整體表現**

IterSynth-8B 在這五個基準上的平均得分達到 **50.7%**，超越了先前最強的 ≤8B 開源智慧體達 **+4.2%**，並且能與多個 30B 規模的智慧體競爭，參數量卻不到它們的三分之一。這顯示角色解耦與摘要狀態的設計在小型模型上具有顯著的參數效率優勢。

**2. 消融實驗：RDPO 的貢獻**

作者進行了關鍵的消融比較：

- SFT 基線：44.1%
- 僅使用終端結果獎勵的 GRPO：48.9%
- 完整 RDPO：50.7%

這組數據說明了幾個重點：

- **RL 優於純 SFT**：即使只使用終端結果獎勵，GRPO 仍能將表現從 44.1% 提升到 48.9%，顯示強化學習對於長程搜尋策略的優化是必要的。
- **RDPO 進一步帶來結構性提升**：RDPO 額外帶來約 1.8% 的絕對提升，且在探索密集型基準上效果更明顯。這證明回合級評分標準評估（turn-level rubric evaluations）與角色特定優勢（role-specific advantages）能讓模型學到更細緻的搜尋行為，而不只是學會「最後答案要對」。
- **角色解耦訓練是關鍵**：如果將 Planner 與 Synthesizer 視為同一個角色並使用單一優勢估計，則難以區分規劃錯誤與合成錯誤，導致信用分配（credit assignment）模糊。

**3. 作為模型無關提示典範（model-agnostic prompting paradigm）的泛化能力**

IterSynth 不僅是一個需要訓練的架構，也可以直接作為提示策略（prompting paradigm）應用於前沿專有模型（frontier proprietary models）。實驗顯示，在 Claude-4.5-Opus 與 DeepSeek-V3.1 等模型上，IterSynth 的提示方式能穩定超越 ReAct（Reasoning + Acting）與 IterResearch 等現有提示典範，在 BrowseComp-ZH 上相較於 ReAct 最高可達 **+10.0%** 的零樣本增益（zero-shot gains）。

這項結果特別重要，因為它顯示 IterSynth 的價值不僅來自於訓練後的 8B 模型，更來自於其**工作流程（workflow）本身的設計優勢**：將規劃與合成解耦、以摘要作為狀態，這種結構性安排對於大型專有模型同樣有效。

**4. 上下文效率的隱含證據**

雖然論文未在提供的片段中給出詳細的上下文長度實驗，但引言中提到一個值得注意的觀察：在 BrowseComp 上，即使擁有 64K 上下文，ReAct 風格智慧體（ReAct-style agents）仍有超過 59% 的軌跡在上下文耗盡（context exhaustion）前無法終止。這間接凸顯了 IterSynth 以摘要狀態（summary state）取代完整搜尋歷史（search histories）的重要性——它不僅減少雜訊，也讓長程搜尋在實務上可行。

#### 與現有研究的比較

**1. 相較於 ReAct 風格智慧體（ReAct-style agents）**

現有大多數開源深度搜尋智慧體（deep-search agents）採用 ReAct 風格的工作流程：單一策略（single policy）在單一不斷膨脹的上下文中交錯進行推理、搜尋與合成。這導致兩個核心問題：

- **能力耦合（capability coupling）**：規劃、查詢制定、證據過濾、衝突解決與最終合成（final synthesis）等異質能力（heterogeneous abilities）被迫由同一個策略承擔，容易出現過早終止、冗餘搜尋或淺層證據使用（shallow evidence use）。
- **上下文累積（context accumulation）**：隨著搜尋範圍（search horizon）增長，檢索段落、中間思維（intermediate thoughts）與部分結論（partial conclusions）不斷堆積，使得有用證據難以定位，早期錯誤也更容易傳播到後續決策。

IterSynth 透過角色解耦（role decoupling）與摘要狀態（summary state）同時解決這兩個問題，並且不需要增加參數量。

**2. 相較於多智慧體系統（multi-agent systems）**

多智慧體方法（如 Researcher、Refiner、Synthesizer 各自使用不同模型）確實能達到能力解耦，但它們通常需要多組參數（multi-parameter sets），帶來更高的推論成本、部署複雜度與協調開銷。IterSynth 的創新之處在於：**在單一參數集合（single parameter set）內實現能力解耦（capability decoupled）**，因此兼具多智慧體系統的專業化優勢與單一模型的部署簡潔性。

**3. 相較於基於摘要的系統（summary-based systems）**

現有的摘要型智慧體會定期將搜尋歷史壓縮成緊湊記憶（compact memory），以緩解上下文累積。然而，這些系統通常將摘要視為外部輔助模組（external auxiliary module），而非搜尋策略（search policy）的可學習部分（learned part）。因此，它們雖然能控制上下文長度，但規劃與合成仍然耦合，且外部摘要可能丟棄有用資訊或保留誤導性雜訊。

IterSynth 的差異在於讓**合成器（Synthesizer）主動更新摘要**，使摘要成為搜尋的持久狀態（persistent state），並透過 RDPO 讓這個更新過程成為可最佳化的行為。這不僅是「壓縮上下文」，而是「讓摘要本身成為推理與決策的狀態」。

**4. 相較於其他強化學習訓練方法**

許多現有開源智慧體使用結果驅動強化學習（outcome-driven RL）或偏好目標（preference objectives）來最佳化工具使用與答案準確率。IterSynth 的 RDPO 進一步引入：

- 回合級評分標準評估（turn-level rubric evaluations），提供比單純終端結果獎勵（terminal outcome rewards）更密集的訓練訊號。
- 角色特定優勢（role-specific advantages），解決多角色軌跡中的信用分配（credit assignment）問題。

這讓 RDPO 在探索密集型任務上比標準 GRPO 表現更穩定。

**5. 潛在限制**

儘管 IterSynth 的設計具有吸引力，仍有幾點需要注意：

- **評分標準設計的依賴性**：RDPO 需要預先定義的回合級評分標準（turn-level rubric）。如果評分標準設計不當，可能會引入偏差或獎勵駭取（reward hacking）。
- **角色切換的開銷**：雖然共享參數，但 Planner 與 Synthesizer 的交替執行可能增加推理時的結構化開銷，尤其是在需要極高頻率搜尋的場景。
- **摘要可能遺失細節**：即使摘要更新是可學習的，長程搜尋中仍可能出現關鍵細節被壓縮掉的風險，特別是在需要精確引用原始來源的情境。
- **基準覆蓋範圍**：目前實驗主要集中在文字檢索任務，對於需要多模態、網頁導航或動態工具使用的場景，IterSynth 的通用性仍需更多驗證。

#### 可重現性評估

根據目前提供的論文片段，**IterSynth 的可重現性仍處於不確定狀態**。以下是具體評估：

**1. 程式碼與模型權重**

提供的摘要與引言中並未明確提及是否開源程式碼、訓練資料集或 IterSynth-8B 的模型權重。對於一個涉及複雜訓練管線（SFT + RDPO）與多個基準評估的研究，若缺少官方實作，其他研究者將難以完全重現其結果。

**2. 資料與環境依賴**

深度搜尋智慧體（deep-search agents）的可重現性高度依賴於：

- 搜尋工具或檢索引擎的 API（例如是否使用真實網頁搜尋、模擬環境或靜態語料）。
- 回合級評分標準（turn-level rubric）的具體定義與實作細節。
- 各基準（如 BrowseComp、xBench-DS）的資料切分與評分腳本。

若論文未提供這些元件，重現將面臨顯著障礙。

**3. 訓練細節**

RDPO 涉及群組相對優勢（group-relative advantages）的角色分離計算，其實作細節（例如如何分群、優勢正規化方式、獎勵加權係數）對最終表現可能非常敏感。缺少這些細節會降低可重現性。

**4. 建議**

為了提升可重現性，作者應考慮釋出：

- 訓練與推論程式碼。
- IterSynth-8B 模型權重。
- SFT 與 RL 所使用的資料或資料生成腳本。
- 各基準的評估設定與搜尋工具配置。
- 回合級評分標準（turn-level rubric）的完整定義。

在這些資源釋出之前，IterSynth 的結果雖然令人印象深刻，但其他研究者只能將其視為一個強有力的概念驗證，而非可立即複製的開源基線。

#### 未來研究方向

IterSynth 的角色解耦與摘要狀態設計為深度搜尋（deep search）開啟了多個值得探索的方向：

**1. 多模態與動態工具擴展**

目前的 IterSynth 主要聚焦於文字檢索。未來可將 Planner–Synthesizer 架構擴展到多模態場景，例如讓 Planner 決定是否需要搜尋圖片、表格或程式碼執行結果，而 Synthesizer 負責整合跨模態證據。

**2. 層級化記憶與摘要機制**

雖然 IterSynth 使用單一摘要狀態（summary state），但未來可探索更豐富的記憶結構，例如短期工作記憶、長期事實庫與來源追溯索引，讓合成器在更新摘要時能保留更細緻的引用資訊。

**3. 自適應角色粒度**

目前的角色只有 Planner 與 Synthesizer 兩個。未來可研究是否需要更多細粒度角色（例如專門的查詢重寫器、衝突仲裁器或來源可信度評估器），或讓模型動態決定角色數量與切換時機。

**4. 更精細的信用分配機制**

RDPO 已經在角色層級進行信用分配（credit assignment），但未來可進一步細分到「查詢層級」或「證據片段層級」，讓模型知道哪一次搜尋、哪一段檢索段落（retrieved passage）對最終答案最有貢獻。

**5. 線上探索與世界模型學習**

目前的訓練可能仍依賴靜態或半靜態的搜尋環境。未來可結合線上探索（online exploration）與世界模型（world model），讓 Planner 能預測不同查詢可能帶回的資訊價值，從而減少冗餘搜尋（redundant searches）。

**6. 開源生態與標準化評估**

為了推動領域發展，建立開源的 IterSynth 實作、標準化的長程搜尋評估框架，以及公開的回合級評分標準（turn-level rubric）資料集，將有助於後續研究進行公平比較與迭代改進。

**7. 提示典範的進一步優化**

IterSynth 作為模型無關提示典範（model-agnostic prompting paradigm）已展現潛力。未來可研究如何將其與其他提示技術（如 chain-of-verification、self-consistency）結合，並探索在不同規模與架構的模型上的最佳提示形式。

**8. 可解釋性與人機協作**

由於 Planner 與 Synthesizer 的分工明確，IterSynth 天然適合發展可解釋的搜尋流程。未來可讓人類使用者在任何回合介入、修改摘要狀態或糾正規劃方向，從而提升人機協作（human-agent collaboration）的效率與信任度。

## 論文問答

### 【Background & Motivation】

**Q1：深度搜尋要解決什麼問題？為什麼它比傳統檢索更困難？**  
A：深度搜尋要求大型語言模型智慧體從被動檢索轉向主動知識建構，必須先分解複雜查詢、主動搜尋證據，再合成出有根據的答案。這比單純檢索困難許多，因為它同時涉及規劃、查詢制定、證據過濾、缺口識別、衝突解決與最終合成等異質能力。隨著搜尋範圍拉長，檢索段落、中間思維與部分結論不斷累積，使得錯誤容易傳播，有用的資訊也愈來愈難定位。

**Q2：現有的 ReAct 風格智慧體存在哪兩大核心限制？**  
A：第一個限制是角色耦合，也就是單一策略必須同時負責規劃、證據使用與最終合成，容易導致過早終止、冗餘搜尋或淺層證據使用。第二個限制是上下文累積，隨著搜尋歷史增長，雜訊不斷引入，重要資訊反而被淹沒；論文觀察到即使在 64K 上下文下，ReAct 在 BrowseComp 上仍有超過 59% 的軌跡會在上下文耗盡前無法結束。這兩個問題讓長程深度搜尋變得脆弱且低效。

**Q3：為什麼多智慧體系統與基於摘要的方法仍不足夠？**  
A：多智慧體系統雖然把不同子任務交給不同模型，降低了單一模型的認知負擔，但卻增加了推論成本、部署複雜度與協調開銷。基於摘要的方法則把搜尋歷史壓縮成緊湊記憶，雖能緩解上下文累積，但通常把摘要視為外部輔助模組，而非搜尋策略的可學習部分。因此，這些方法仍讓規劃與證據使用耦合在一起，且外部摘要可能丟棄有用資訊或保留誤導性雜訊。

---

### 【Method & Innovation】

**Q4：IterSynth 的核心設計是什麼？它與先前工作有何不同？**  
A：IterSynth 是一種角色解耦且基於摘要的深度搜尋典範，在同一個共享的大型語言模型策略內交替執行規劃器與合成器兩個角色。規劃器負責在緊湊的摘要狀態上推理，找出尚未解決的資訊需求並產生下個查詢；合成器則閱讀檢索到的證據，把有用發現整合進持續演化的摘要狀態，並解決不一致與過濾雜訊。不同於多智慧體系統，它不需要額外模型；也不同於外部摘要模組，摘要更新成為智慧體行為中可明確最佳化的一環。

**Q5：規劃器與合成器各自扮演什麼角色？為何要分離？**  
A：規劃器專注於高階規劃：檢視當前摘要狀態、判斷還缺哪些資訊，並決定下一步要搜尋什麼。合成器則專注於證據整合：閱讀檢索段落、抽取相關事實、解決衝突、移除雜訊，並寫出更新後的摘要。把這兩種異質能力分開，可以避免單一策略被迫同時進行搜尋規劃與證據合成，從而減少能力耦合所帶來的過早終止、重複搜尋與淺層證據使用。

**Q6：什麼是角色解耦策略最佳化（RDPO）？它如何提升訓練效果？**  
A：RDPO 是專為 IterSynth 設計的強化學習演算法，結合終端結果獎勵與回合級評分標準評估，並為兩個角色分別計算群組相對優勢。這種設計能提供更精確的角色特定信用分配，讓規劃器與合成器各自根據自身貢獻獲得適合的梯度，而非只依賴稀疏的最終獎勵。實驗顯示，相較於僅使用結果獎勵的 GRPO，RDPO 把平均分數從 48.9% 進一步提升到 50.7%，證明角色解耦訓練對長程搜尋至關重要。

### 【Experiments & Results】

**Q7：實驗使用了哪些基準？IterSynth-8B 的主要成績為何？**  
A：實驗涵蓋五個長程深度搜尋基準，包括 GAIA-text-only、xBench-2505、xBench-2510、BrowseComp 與 BrowseComp-ZH。IterSynth-8B 在這五個基準上的平均分數達到 50.7%，超過先前最強的 ≤8B 智慧體 4.2 個百分點，並能以不到三分之一的參數量與多個 30B 級模型競爭。這顯示 IterSynth 在參數效率與任務廣度上都表現出色。

**Q8：消融實驗揭示了 RDPO 的什麼價值？**  
A：從監督式微調基線的 44.1% 開始，僅使用結果獎勵的 GRPO 可將成績提升至 48.9%，而加入 RDPO 後進一步達到 50.7%。RDPO 帶來的額外增益在探索密集型基準上尤其明顯，顯示回合級評分標準獎勵與角色特定優勢能幫助智慧體學會何時搜尋、保留哪些證據。這證實了角色解耦訓練不僅僅是標準結果驅動強化學習的簡單延伸。

**Q9：IterSynth 作為提示典範在前沿專有模型上的表現如何？**  
A：IterSynth 也能作為模型無關提示典範，直接應用於 Claude-4.5-Opus、DeepSeek-V3.1 等前沿專有模型，並持續優於 ReAct 與 IterResearch。在 BrowseComp-ZH 上，它相較 ReAct 最高可帶來 +10.0% 的零樣本增益。這說明規劃器—合成器分解與摘要狀態設計具有結構性優勢，即使不額外訓練也能提升大型模型的深度搜尋能力。

### 【Applications & Impact】

**Q10：IterSynth 最適合應用在哪些實務場景？**  
A：IterSynth 特別適合需要多輪證據蒐集與合成的複雜知識工作，例如學術研究、競爭情報分析、法律盡職調查與醫學文獻回顧。由於它以緊湊的摘要狀態作為持續狀態，能夠在長程任務中延緩上下文耗盡的問題。又因為只使用單一共享策略，它比多智慧體系統更容易部署，同時仍能享有角色專業化帶來的好處。

**Q11：在產品化部署 IterSynth 時需要考慮哪些因素？**  
A：產品團隊需要仔細設計 RDPO 使用的評分標準，因為回合級獎勵會直接影響規劃器與合成器學到的行為偏好。同時必須監控摘要品質，因為持續存在的摘要狀態是整個搜尋過程的核心，任何偏差或雜訊都會跨回合傳播。此外，雖然 IterSynth 省去了多模型的成本，但仍需調校角色交替頻率與搜尋終止條件，以在搜尋完整性與回應延遲之間取得平衡。

**Q12：IterSynth 可能對深度搜尋智慧體領域帶來什麼影響？**  
A：IterSynth 顯示工作流程設計——特別是角色解耦與摘要狀態管理——對長程智慧體的重要性可能不亞於訓練演算法的改進。它證明單一共享策略就能模擬多智慧體系統的專業化優勢，可能促使更多研究轉向設計緊湊且結構化的智慧體狀態，而非單純擴展上下文長度。它同時作為訓練模型與提示典範都取得成功，也暗示了可跨模型規模與部署情境遷移的統一設計原則。

### 【Limitations & Future】

**Q13：論文已承認或暗示了哪些限制？**  
A：論文目前聚焦於規劃器與合成器的雙角色分解，尚未探討更豐富的角色層級或超越固定交替模式的自適應角色切換。它也依賴評分標準進行回合級獎勵，而這些評分標準需要人工或模型生成，可能無法完整涵蓋良好搜尋行為的所有面向。此外，儘管摘要狀態緊湊，若合成器未能辨識某些證據的長期重要性，仍可能遺失細緻資訊。

**Q14：IterSynth 可能出現哪些失敗案例？**  
A：如果初始摘要對問題的刻畫有誤，後續規劃器的查詢都會建立在錯誤狀態上，導致搜尋方向偏離。合成器也可能過濾掉看似矛盾但實則正確的證據，或反過來保留誤導性雜訊，使摘要品質下降。規劃器也可能反覆發出相似查詢而未能開拓新資訊來源；雖然 RDPO 在探索密集型基準上部分緩解了這些問題，但並未完全消除。

**Q15：有哪些值得期待的未來研究方向？**  
A：未來可擴展 IterSynth 引入更多角色，例如專門的批判器或驗證器，並允許根據任務需求自適應調度角色，而非嚴格交替。另一方向是讓摘要更新函數更具表達力，例如讓模型自行決定何時擴展、重構或重置摘要狀態。最後，將 IterSynth 與更強大的檢索工具、網頁導航能力及多模態證據結合，可進一步拓展其在文字以外的深度搜尋應用。

## 實務應用指南

### 適用場景

1. **企業級研究報告生成**  
   當分析師需要針對產業趨勢、競爭對手動態或法規變化撰寫長篇報告時，IterSynth 可將「規劃查詢」與「證據合成」分離，讓 Planner 持續發掘資訊缺口，Synthesizer 則把多輪檢索結果整理成可追蹤的摘要狀態，避免傳統 ReAct 在長軌跡中遺失關鍵證據。

2. **法律與醫療文獻調查**  
   律師或研究人員面對需交叉比對多份判例、論文或臨床試驗的複雜查詢時，IterSynth 的摘要狀態能保留已確認的事實、待驗證的假設與衝突證據，並由 Planner 決定下一輪檢索方向，適合高風險、需可解釋性的深度搜尋任務。

3. **客戶支援與技術問題排查**  
   在處理需要多步驟診斷的技術工單時，Planner 可依據目前摘要判斷還需查詢哪些日誌、文件或知識庫條目，Synthesizer 則把新證據併入執行摘要，最終產生結構化答案，減少單一策略在長對話中重複提問或過早收斂的問題。

4. **金融盡職調查與投資研究**  
   針對需要整合財報、新聞、監管公告與市場數據的投資主題，IterSynth 能在每輪搜尋後更新摘要狀態，標記已回答與未回答的資訊需求，協助研究員在數十輪檢索後仍能掌握全局，避免上下文累積導致的雜訊干擾。

5. **開放式學術研究輔助**  
   研究者可把 IterSynth 當作模型無關提示典範，直接在前沿專有模型上執行零樣本深度搜尋，用於文獻回顧、假設發掘或實驗設計，無需從頭訓練專屬模型即可獲得比 ReAct 更穩定的長程搜尋表現。

### 實作前置條件

**資料準備**
- 高品質的搜尋與推理軌跡資料，用於冷啟動監督式微調（SFT）。若無現成軌跡，需準備包含「查詢 → 檢索結果 → 摘要更新 → 最終答案」結構的合成資料。
- 評分標準（rubric）範本，用於 RDPO 的回合級獎勵設計，例如：查詢是否切中資訊缺口、摘要是否正確整合證據、是否解決衝突、最終答案是否 grounded。
- 搜尋工具或 API（如網頁搜尋、內部知識庫、向量資料庫），並確保回傳結果包含足夠上下文供 Synthesizer 判讀。

**運算資源**
- **訓練路徑**：至少 1–8 張高階 GPU（如 A100/H100），視模型規模而定；IterSynth-8B 等級建議具備 32GB 以上 VRAM 的單節點或多節點環境。
- **推論路徑**：若僅採用提示典範，則只需能呼叫 frontier 模型（Claude-4.5-Opus、DeepSeek-V3.1 等）的 API 配額，以及可執行多輪搜尋的後端服務。
- 儲存空間需容納長程軌跡、中間摘要與檢索快取，建議搭配日誌與版本控制系統。

**技能需求**
- 熟悉強化學習基礎（policy gradient、advantage estimation）與 LLM 微調流程（SFT、GRPO/PPO）。
- 具備設計多角色提示（multi-role prompting）與評分標準的能力。
- 能建構搜尋工具鏈與狀態管理機制，確保 Planner 與 Synthesizer 之間的摘要狀態正確傳遞。
- 產品化時需具備評估與監控經驗，能追蹤長程任務成功率、檢索輪數與答案 groundedness。

### 實作步驟建議

1. **定義角色與狀態格式**  
   先將搜尋流程固定為 Planner → Search → Synthesizer 的循環。明確定義摘要狀態的欄位，例如：已確認事實、待驗證問題、衝突與備註、下一輪資訊需求。這份格式會成為兩個角色之間的持久狀態。

2. **建立搜尋工具與環境**  
   串接搜尋 API 或內部檢索系統，並設計回傳格式（標題、摘要、來源、原文片段）。確保 Planner 只看摘要狀態與使用者查詢，Synthesizer 則接收檢索結果並更新摘要狀態。

3. **冷啟動 SFT**  
   收集或合成符合上述格式的多輪軌跡，對基礎模型進行監督式微調。目標不是學到最佳策略，而是讓模型學會 Planner 與 Synthesizer 的互動格式、摘要更新語法與終止條件。

4. **設計 RDPO 獎勵函數**  
   結合終端結果獎勵（答案正確性）與回合級評分標準獎勵（查詣品質、摘要正確性、衝突解決、冗餘搜尋懲罰）。為 Planner 與 Synthesizer 分別計算群組相對優勢（group-relative advantages），讓信用分配更精準。

5. **執行角色解耦強化學習**  
   使用 RDPO 對 SFT 後的模型進行訓練。每一條軌跡需標記每個回合的角色，並根據該角色的回合級 rubric 分數與最終結果計算優勢。持續監控每個角色的 loss 與獎勵曲線，避免單一角色的梯度主導更新。

6. **評估與迭代**  
   在長程深度搜尋基準或自建的領域測試集上評估。重點觀察：平均檢索輪數、上下文耗盡比例、過早終止率、最終答案正確率。針對高失敗案例調整 rubric 權重或摘要格式。

7. **產品化部署**  
   將訓練好的模型或提示範本封裝成服務，加入逾時控制、最大輪數限制、來源引用與人機協作審核機制。若資源有限，可直接把 IterSynth 提示典範應用於 frontier 專有模型，快速驗證產品價值。

### 潛在風險與注意事項

- **摘要遺失關鍵資訊**  
  Synthesizer 為了控制上下文長度，可能過度壓縮而丟棄後續 Planner 需要的線索。  
  *緩解*：在摘要格式中保留「待驗證問題」與「高優先級證據片段」，並在 rubric 中給予資訊保留度明確獎勵。

- **Planner 過早終止或冗餘搜尋**  
  角色解耦後，Planner 可能誤判資訊缺口已填滿，或反覆查詢相似內容。  
  *緩解*：在回合級獎勵中加入「新資訊增益」與「終止正確性」指標，並使用 RDPO 讓 Planner 獨立承擔對應信用。

- **兩角色能力不平衡**  
  訓練過程中可能出現某一角色 loss 過大或過小，導致其中一角色的行為退化。  
  *緩解*：分開監控 Planner 與 Synthesizer 的梯度規模與優勢分佈，必要時調整角色特定的學習率或獎勵權重。

- **評分標準設計偏差**  
  Rubric 若過度強調表面格式，模型可能學會「寫出漂亮摘要」卻忽略答案正確性。  
  *緩解*：終端結果獎勵應佔足夠權重，並定期以人工抽樣檢查 rubric 分數與人類判斷的一致性。

- **長軌跡導致上下文耗盡**  
  即使採用摘要狀態，極端複雜查詢仍可能超出模型上下文上限。  
  *緩解*：設定硬性的最大輪數與摘要長度上限，並在接近上限時觸發強制終止與最終合成。

---

### 與其他技術的整合建議

- **與檢索增強生成（RAG）系統整合**  
  將 IterSynth 視為 RAG 之上的「主動規劃層」。底層保留向量資料庫與重排序模型，上層以 Planner 決定何時檢索、檢索什麼，Synthesizer 負責把檢索結果寫入摘要狀態，彌補傳統 RAG 一次性檢索的不足。

- **與多智慧體（Multi-Agent）框架整合**  
  若組織已採用多智慧體架構，可保留現有的 Researcher / Refiner 分工，但把 IterSynth 的單一參數集角色解耦設計作為輕量化替代，降低模型協調開銷與部署成本。

- **與現有 ReAct 服務整合**  
  可將 IterSynth 提示典範作為 ReAct 的升級版本：在不更換模型的情況下，把原本交錯的推理、搜尋、合成動作重構為 Planner 查詢與 Synthesizer 更新摘要的循環，快速取得零樣本增益。

- **與評估與監控平台整合**  
  將每輪的摘要狀態、角色動作與 rubric 分數寫入可觀測性系統，支援事後稽核、錯誤案例回放與持續學習資料收集。

- **與人機協作（Human-in-the-loop）流程整合**  
  在關鍵決策點（例如 Planner 提出高風險查詢、Synthesizer 遇到衝突證據）開放人工介入，讓摘要狀態成為人與模型協作的共同介面。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從「IterSynth 作為提示典範」開始理解：把一次長篇搜尋拆成「規劃器決定下一步查什麼」與「合成器把結果整理成摘要」兩個角色，重點在於讓模型用摘要狀態代替不斷增長的完整對話紀錄。不必急著理解 RDPO 的數學細節，先掌握「角色解耦」與「摘要狀態」這兩個核心概念即可。

**AI 工程師**  
請聚焦第 3–4 節的訓練流程與 RDPO 實作細節：如何設計 SFT 資料格式、如何為 Planner 與 Synthesizer 分別計算 group-relative advantages、回合級 rubric 與終端結果獎勵的權重調校。建議直接參考論文附錄中的軌跡範例，並在自有資料上重現 SFT → RDPO 的完整 pipeline。

**研究人員**  
值得深入分析的是 IterSynth 對「能力耦合」與「上下文累積」這兩個長程搜尋瓶頸的拆解方式，以及 RDPO 在信用分配上的設計動機。可進一步探訋：角色解耦是否適用於其他長程決策任務？摘要狀態的最適資訊理論表徵為何？回合級 rubric 與終端獎勵之間的權衡關係也值得延伸研究。

**產品經理**  
請把重點放在適用場景與商業權衡：IterSynth 能在不增加模型參數的前提下，讓小模型逼近更大模型的長程搜尋表現，也能作為提示典範快速提升現有 frontier 模型的搜尋品質。評估時應同時看準確率、平均檢索輪數、延遲與可解釋性，並優先選擇「答案需要來源追溯」與「查詢需多輪分解」的場景進行試點。
