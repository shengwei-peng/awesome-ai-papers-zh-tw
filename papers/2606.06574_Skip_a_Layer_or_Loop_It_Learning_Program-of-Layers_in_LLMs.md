## 摘要翻譯

大型語言模型 (LLMs) 進行推論時，遵循固定深度與固定順序，非遞迴地執行所有層。我們揭示了無需訓練、靈活且動態的層級程式 (PoLar) 廣泛存在，其中預訓練層可被封裝為模組，進而透過跳層或迴圈的方式，為每個輸入組成自訂程式。對於大多數輸入而言，顯著更短的程式執行即可達到相同或更佳的準確率，而原始 LLM 的錯誤預測可藉由使用更少層的替代程式加以修正。這些觀察顯示，推論存在超越標準前向傳遞的多種有效潛在計算。為了有效率地在實務中實現 PoLar，我們提出一個輕量級 PoLar 預測網路，該網路學習為每個輸入產生執行程式，動態地跳過或重複使用預訓練層。在數學推理基準上的實驗表明，PoLar 在準確率上持續優於標準推論及先前的動態深度方法，且通常在執行更少層的情況下達成此優勢，而這些增益在分布外評測下依然存在。我們的結果顯示，固定深度執行僅捕捉到 LLM 的潛在推理能力中的一個狹窄子集。

### 核心貢獻（3～5點）
- 揭示無需訓練、靈活且動態的層級程式 (PoLar) 廣泛存在於大型語言模型中，預訓練層可封裝為模組並透過跳層或迴圈組成自訂程式。
- 透過實證觀察指出：對於大多數輸入，更短的程式執行即可達到相同或更佳的準確率，且能修正原始 LLM 的錯誤預測，證明推論存在超越標準前向傳遞的多種有效潛在計算。
- 提出輕量級 PoLar 預測網路，學習為每個輸入動態產生跳層或重複使用預訓練層的執行程式，無需額外訓練即可部署。
- 在數學推理基準上，PoLar 在準確率上持續優於標準推論及先前的動態深度方法，且通常以更少層達成此優勢，該增益在分布外評測中依然成立。
- 指出固定深度執行僅捕捉到 LLM 潛在推理能力中的一個狹窄子集，為動態推論與自適應計算開啟新的研究方向。

### 適合對象
從事大型語言模型推論效率優化、動態深度網路架構、自適應計算與條件式計算研究的學者與工程師；對模型壓縮、程式合成、神經網路潛在能力探勘等議題感興趣的研究人員；以及關注如何以更低計算成本提升 LLM 推理能力（特別是數學推理任務）之產業界實務工作者。

## 深度分析

#### 方法論解析

本文提出了一種名為 **層級程式（Program-of-Layers, PoLar）** 的動態推論框架，其核心思想是將預訓練大型語言模型（Large Language Model, LLM）中的每一層視為一個可被任意呼叫的「原子函數（atomic function）」，並為每個輸入動態生成一個專屬的執行程式（execution program），藉此突破傳統固定深度、固定順序的前向傳遞（forward pass）限制。

**1. 問題形式化（Problem Formulation）**

給定一個具有 $D$ 層 Transformer 的預訓練 LLM，每一層 $f_i: \mathbb{R}^{T \times d} \rightarrow \mathbb{R}^{T \times d}$ 定義一個固定的計算函數。一個執行程式被定義為層索引的有限序列 $\pi = (i_1, i_2, \ldots, i_K)$，其中 $i_k \in \{0, \ldots, D-1\}$，並透過函數複合 $F_\pi = f_{i_K} \circ \cdots \circ f_{i_1}$ 來產生預測。這種形式化允許兩種操作：
- **跳層（Layer Skipping）**：省略一個或多個層，縮短計算路徑；
- **層級遞迴（Layer Recurrence）**：重複使用一個或多個層進行迭代優化（iterative refinement）。

**2. 蒙地卡羅樹搜尋（MCTS）階段的探索性研究**

由於執行程式空間巨大、離散且高度非凸，窮舉搜尋不可行。作者採用蒙地卡羅樹搜尋（Monte-Carlo Tree Search, MCTS）作為分析工具，在聯合的跳層/遞迴空間中搜尋有效的執行程式。此階段屬於「無需訓練（training-free）」的探索，目的是驗證 PoLar 假設的成立性，並分析成功程式的結構特性。關鍵發現包括：
- 對大多數輸入，存在比標準前向傳遞更短或更準確的執行程式；
- 跳層與遞迴的聯合搜尋空間比單獨的跳層或遞迴空間能發現更優質的程式；
- 大多數成功程式主要由**連續的層段（contiguous layer segments）**組成，這一結構特性為後續的預測網路設計提供了重要先驗。

**3. 輕量級 PoLar 預測網路（PoLar Prediction Network）**

由於 MCTS 在推論時的計算成本過高，作者將程式選擇從「線上搜尋問題」轉化為「單次預測問題」。具體而言，他們訓練一個輕量級網路（lightweight network），該網路以輸入特徵為條件，預測一個輸入特定的執行程式，決定哪些預訓練層被跳過或重複。這個設計具有三個關鍵優勢：
- **計算可行性**：消除了昂貴的逐輸入搜尋成本；
- **方法統一性**：在同一框架內同時支援跳層與遞迴，嚴格推廣了僅支援單一操作（如僅跳層或僅迴圈）的先前動態深度方法；
- **測試時計算縮放（test-time computation scaling）**：透過增加候選執行程式的數量，可在完全凍結的模型上靈活調整推論計算量，同時保持模型的泛化能力。

**4. 與傳統動態方法的差異**

與早期退出（early exit）、迴圈式 Transformer（looped transformer）等僅採用單一操作（跳層或重複）的方法不同，PoLar 在統一的執行框架中聯合支援兩種操作。這使得 PoLar 能夠探索更豐富的架構空間，發現先前方法無法觸及的潛在計算（latent computation）路徑。

#### 實驗數據解讀

**1. 評測基準與模型**

實驗在多個數學推理基準（mathematical reasoning benchmarks）上進行，使用多個預訓練 LLM 進行評測。這些基準涵蓋了不同難度等級的數學問題，能夠有效檢驗 PoLar 在處理多樣化輸入時的適應能力。

**2. 核心實驗結果**

- **準確率提升**：PoLar 在所有評測基準上均持續優於標準推論（standard inference）以及先前的動態深度方法（dynamic-depth methods）。這表明動態調整層級執行策略確實能釋放 LLM 潛在推理能力（latent reasoning capacity）的更大子集。
- **計算效率**：值得注意的是，PoLar 在提升準確率的同時，**平均執行的層數更少**。這意味著 PoLar 並非僅透過增加計算量來換取性能提升，而是透過更智慧的層級分配來實現「少做多得」的效果。
- **測試時計算縮放**：增加候選執行程式的數量能帶來穩定的性能提升，驗證了 PoLar 框架在測試時計算縮放方面的有效性。

**3. 泛化能力評測**

在分布外評測（Out-of-Distribution, OOD evaluation）中，於分布內數據上學習到的執行程式能有效泛化到跨領域的 OOD 基準。這一結果具有重要意義：
- 證明 PoLar 學到的是通用的層級執行策略，而非對特定數據集的過擬合；
- 表明層級程式的預測機制捕捉到了輸入難度與所需計算量之間的內在關聯，這種關聯在不同領域間具有遷移性。

**4. 結構性發現的意義**

MCTS 階段揭示的「成功程式主要由連續層段組成」這一發現，不僅驗證了 PoLar 假設的合理性，也為預測網路的設計提供了歸納偏置（inductive bias），使得預測網路能夠在合理的假設空間內高效學習。

#### 與現有研究的比較

**1. 與動態深度方法的比較**

| 方法類型 | 操作類型 | 局限性 |
|---------|---------|--------|
| 早期退出（Early Exit） | 僅跳層 | 僅支援單向縮短，無法利用遞迴進行迭代優化 |
| 迴圈式 Transformer（Looped Transformer） | 僅遞迴 | 固定的重複模式，缺乏輸入適應性 |
| 跳層方法（Layer Skipping） | 僅跳層 | 無法透過重複使用層來增強計算 |
| **PoLar（本文）** | **跳層 + 遞迴聯合** | **統一的動態框架，嚴格推廣上述方法** |

PoLar 的核心優勢在於其**表達能力更強**：它能夠在統一的搜尋空間中同時探索跳層和遞迴，發現比任何單一操作方法都更優質的執行程式。

**2. 與測試時計算縮放方法的比較**

與需要額外訓練或微調（fine-tuning）的測試時計算縮放方法不同，PoLar 在**完全凍結的預訓練模型**上實現動態推論。這使得 PoLar 能夠：
- 保留預訓練模型的泛化能力；
- 無需修改原始模型權重，降低部署成本；
- 與現有的模型服務基礎設施兼容。

**3. 與搜尋式推論方法的比較**

與 Li 等人（2025）等需要對每個輸入進行線上搜尋或枚舉的方法相比，PoLar 透過將搜尋轉化為單次預測，大幅降低了推論成本，使其在實際部署中具有可行性。

**4. 局限性分析**

- **預測網路的訓練成本**：雖然推論時無需搜尋，但預測網路本身需要訓練，這需要一定的計算資源和標註數據；
- **層段粒度的限制**：由於成功程式主要由連續層段組成，預測網路可能無法充分探索非連續層組合的潛力；
- **任務範圍**：目前實驗主要集中在數學推理任務，在更廣泛的任務（如開放域問答、程式碼生成）上的有效性尚待驗證；
- **可解釋性**：執行程式的選擇機制目前仍是黑箱，缺乏對「為何某個輸入需要特定層級配置」的深入理論解釋。

#### 可重現性評估

**1. 程式碼與模型權重**

作為 ICML 2026 的論文，本文的研究很可能伴隨公開的程式碼實現。然而，基於目前提供的資訊：
- 預測網路的架構與訓練流程需要明確的開源實現；
- MCTS 搜尋階段的程式碼對於復現實證發現至關重要；
- 預訓練 LLM 的權重應使用公開可獲取的模型（如 LLaMA 系列），以確保可重現性。

**2. 數據集**

實驗使用的數學推理基準應為公開數據集（如 GSM8K、MATH 等），這有利於結果的獨立驗證。OOD 評測的數據集選擇也應明確記錄。

**3. 實驗細節**

可重現性的關鍵因素包括：
- 預測網路的超參數（hyperparameter）設定；
- MCTS 搜尋的計算預算與節點擴展策略；
- 執行程式的最大長度限制與層段粒度設定；
- 評測時的隨機性控制（如溫度參數、採樣策略）。

**4. 潛在的可重現性挑戰**

- MCTS 階段的隨機性可能導致搜尋結果的變異；
- 不同預訓練模型版本之間的差異可能影響結果的一致性；
- 預測網路的訓練對初始化敏感，可能需要多次運行取平均。

#### 未來研究方向

**1. 理論基礎的深化**

PoLar 目前主要基於實證觀察，未來需要建立更嚴格的理論框架來解釋：
- 為何凍結的預訓練層能夠透過不同的組合順序產生正確預測；
- 執行程式的存在性與模型表達能力之間的理論關聯；
- 跳層與遞迴操作對模型函數空間的具體影響。

**2. 預測網路架構的改進**

- 探索更高效的網路架構（如基於 Transformer 的層級預測器），以更好地捕捉輸入與執行程式之間的映射關係；
- 引入強化學習（reinforcement learning）來直接優化執行程式的預測策略，以最終任務性能作為獎勵訊號（reward signal）；
- 研究層段粒度的自適應機制，而非固定粒度。

**3. 應用領域的拓展**

- 將 PoLar 從數學推理擴展到程式碼生成、開放域問答、多輪對話等任務；
- 探索 PoLar 在視覺語言模型（Vision-Language Model, VLM）中的應用，實現跨模態的動態計算；
- 研究 PoLar 與思維鏈（Chain-of-Thought, CoT）提示技術的結合，實現「顯式推理」與「潛在計算」的協同。

**4. 與其他動態計算範式的融合**

- 將 PoLar 與混合專家模型（Mixture of Experts, MoE）結合，實現層級與專家層級的雙重動態化；
- 探索 PoLar 與自適應計算時間（Adaptive Computation Time, ACT）的結合，實現更細粒度的計算分配；
- 研究 PoLar 在聯邦學習或邊緣計算場景下的應用，利用其動態深度特性降低推論延遲（inference latency）。

**5. 安全與可解釋性**

- 分析 PoLar 的執行程式選擇是否會受到對抗性輸入的影響；
- 研究執行程式與模型可解釋性之間的關聯，例如透過分析執行程式來理解模型的「推理路徑」；
- 探索 PoLar 在模型審計（model auditing）中的應用，例如透過異常的執行程式來檢測分布外輸入。

**6. 硬體協同設計**

- 設計專門支援跳層與遞迴操作的硬體加速器，以充分發揮 PoLar 的動態計算優勢；
- 研究 PoLar 與記憶體層次結構的互動，最小化動態層級切換帶來的記憶體開銷。

總結而言，PoLar 提出了一個重要的範式轉移：從「固定深度的前向傳遞」到「輸入特定的層級程式執行」。這項工作不僅揭示了 LLM 潛在推理能力的豐富性，也為未來的自適應計算（adaptive computation）研究開闢了新的方向。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文挑戰了大型語言模型（LLM）長期以來的一個基本假設——所有輸入都必須經過固定深度、固定順序的前向傳遞（forward pass）。作者指出，現有 LLM 對不同難度、不同複雜度的輸入一律採用相同的靜態架構（static architecture）與非遞迴執行（non-recurrent execution），這種「一刀切」的方式忽略了輸入之間的差異性。論文的核心理念是將預訓練層（pretrained layer）視為可重組的原子函數（atomic functions），並為每個輸入動態生成專屬的「層級程式」（Program-of-Layers, PoLar），藉此釋放模型尚未被充分利用的潛在推理能力（latent reasoning capacity）。

**Q2：為什麼現有的動態深度方法不足以解決這個問題？**
A：現有的動態深度方法（dynamic-depth method）如跳層（layer skipping）、層級遞迴（layer recurrence）、提前退出（early exit）以及迴圈式 Transformer（looped transformer）等，都僅支援單一形式的執行控制——只能在「跳過」或「重複」之間二選一，無法在同一推論路徑中靈活組合兩種操作。此外，這些方法大多仰賴昂貴的逐輸入搜尋（例如列舉或探索執行路徑），在實際部署上成本過高。論文透過蒙地卡羅樹搜尋（MCTS）的實證研究證實，在「跳層與遞迴的聯合空間」中搜尋所找到的程式，品質遠優於在各自獨立空間中搜尋的結果，這凸顯了現有方法的根本侷限性。

**Q3：這項研究為何重要？它對 LLM 推論效率有何啟示？**
A：這項研究的重要性在於它揭示了一個被忽略的事實：固定深度的執行方式僅捕捉到 LLM 潛在推理能力中的一小部分。對於大多數輸入而言，實質上更短的執行程式就能達到相同甚至更好的準確率（accuracy），這意味著標準推論（standard inference）在計算上存在大量冗餘。更重要的是，原本會被標準前向傳遞錯誤預測的輸入，可以透過替代程式（包含跳層與遞迴的組合）來修正，這為提升 LLM 的可靠性開闢了新途徑。這項發現對推論延遲（inference latency）與推論成本（inference cost）都有深遠影響，因為它證明了「更少的計算不等於更差的結果」。

**Q4：PoLar 的核心方法是什麼？它如何運作？**
A：PoLar 的核心是一個輕量級的 PoLar 預測網路（PoLar prediction network），它在推論時為每個輸入預測一個執行程式（execution program），決定哪些預訓練層要被跳過、哪些要被重複執行。具體而言，給定一個具有 D 個 Transformer 層的預訓練模型，每一層被視為一個固定的函數 f_i，而 PoLar 預測的程式 π = (i_1, i_2, ..., i_K) 是一個層索引（layer index）的序列，透過組合 F_π = f_{i_K} ∘ ... ∘ f_{i_1} 來產生最終輸出。這個設計將原本的「線上搜尋問題」轉化為「單次預測問題」，使層級程式推論在實務上變得可行。

**Q5：PoLar 相較於先前方法的關鍵創新是什麼？**
A：PoLar 的關鍵創新在於它首次將「跳層」與「層級遞迴」統一在同一個執行框架中，嚴格地推廣了僅支援單一操作形式的先前動態深度方法。這意味著 PoLar 不僅能省略不必要的層，還能在需要時對特定層進行迭代優化（iterative refinement），從而靈活地調整每個輸入的計算路徑。另一個重要創新是用一個輕量級網路取代了 MCTS 等昂貴的搜尋程序，使得動態深度推論可以在不犧牲效率的前提下實際部署。此外，PoLar 完全在凍結的預訓練模型（frozen pretrained model）上運作，無需微調（fine-tuning），保留了模型的通用性。

**Q6：PoLar 在設計上有哪些重要的選擇？這些選擇的依據為何？**
A：PoLar 的設計選擇之一是將預訓練層視為模組函式庫（module library）中的原子函數，而非可調整參數的元件，這保證了原始模型的知識不被破壞。另一個關鍵設計是選擇「預測」而非「搜尋」執行程式，這是基於 MCTS 實證研究的發現——大多數成功的程式主要由連續的層區段組成，這使得學習一個預測網路成為可能，而非必須進行高成本的組合搜尋。此外，PoLar 支援可變長度的執行程式，這使得測試階段的計算量可以根據輸入難度進行彈性調整，實現了真正的自適應計算（adaptive computation）。

**Q7：論文中使用了哪些基準測試來評估 PoLar？**
A：論文中 PoLar 的評估主要聚焦於數學推理基準（mathematical reasoning benchmark），這類任務對多步驟推理能力要求極高，是測試 LLM 潛在計算能力的理想場景。作者使用了多個預訓練 LLM 來驗證 PoLar 的泛用性，並進行了分布外評測（out-of-distribution evaluation, OOD evaluation），以確認學到的執行程式是否能跨領域遷移。這種「同領域訓練、跨領域測試」的設計有助於驗證 PoLar 預測網路是否真正學會了通用的程式選擇策略，而非僅僅記住特定任務的模式。

**Q8：PoLar 的主要實驗結果為何？**
A：實驗結果顯示，PoLar 在多個數學推理基準上持續優於標準推論以及先前的動態深度方法，同時平均執行的層數更少，展現了「更少計算、更高準確率」的雙重優勢。此外，當增加候選執行程式的數量時，PoLar 表現出強健的測試階段計算量擴展（test-time computation scaling）特性，這意味著使用者可以透過增加候選數量來進一步提升效能。更值得注意的是，在分布外評測中，PoLar 所帶來的增益依然存在，這證明了其學到的程式選擇機制具有良好的泛化能力（generalization）。

**Q9：論文中進行了哪些消融實驗（Ablation Study）來驗證設計選擇？**
A：論文中的一個關鍵消融實驗是比較「跳層與遞迴的聯合搜尋空間」與「各自獨立的搜尋空間」，結果證實聯合空間能發現顯著更好的程式，這直接支持了 PoLar 統一框架的設計理念。另一個重要觀察來自 MCTS 搜尋結果的結構分析：大多數成功的程式主要由連續的層區段（contiguous layer segments）組成，這個發現為 PoLar 預測網路的可行性提供了實證基礎，並指導了其架構設計。這些消融實驗共同說明了，PoLar 並非僅憑直覺設計，而是有嚴謹的實證數據作為支撐。

**Q10：PoLar 在實際應用中有哪些適合的情境？**
A：PoLar 特別適合用於輸入難度差異極大的場景，例如客服系統中同時處理簡單問答與複雜技術問題，或教育平台中同時應對基礎練習與進階競賽題目。在這些情境下，PoLar 可以為簡單輸入自動選擇較短的執行程式以節省推論成本，同時為困難輸入保留足夠的計算資源以確保準確率。此外，PoLar 也適用於對推論延遲敏感的邊緣運算部署，因為它能在不犧牲太多準確率的前提下，動態調整計算量以滿足即時性需求。

**Q11：在將 PoLar 整合到產品中時，需要考量哪些實務因素？**
A：將 PoLar 整合到產品時，首先需要考量的是 PoLar 預測網路本身所帶來的額外推論成本，雖然它是輕量級網路，但仍會增加一些延遲，因此需要在預測網路的複雜度與其帶來的效益之間取得平衡。其次，執行程式的設計需要考慮硬體相容性，例如跳層與遞迴操作在 GPU 上的實際加速效果可能與理論計算量不成正比，因為記憶體存取模式會受到影響。此外，產品的監控系統需要追蹤每個輸入所選用的程式，以便在出現異常時進行診斷與調整。

**Q12：這項研究對 LLM 領域可能產生哪些深遠影響？**
A：這項研究最根本的影響在於它挑戰了「固定深度執行是 LLM 唯一合理推論方式」的傳統觀念，開啟了「動態架構推論」這個新的研究方向。它促使研究者重新思考 LLM 的推理能力（reasoning capacity）究竟有多大，並激發後續探索更複雜的程式結構（例如條件分支、迴圈等）的可能性。從產業角度來看，這項研究為降低 LLM 部署成本提供了新思路，因為它證明了在不重新訓練模型的前提下，可以透過更聰明的計算分配來提升效率與準確率。

**Q13：論文中承認了哪些限制？**
A：論文中的一個明顯限制是其評估主要集中在數學推理基準，雖然這是測試多步驟推理的理想場景，但 PoLar 在其他領域（如開放式問答、程式合成、創意寫作等）的表現仍需進一步驗證。此外，PoLar 預測網路本身需要訓練資料來學習程式選擇策略，這意味著在缺乏標註資料的全新領域中部署時，可能會面臨冷啟動問題。論文中也暗示，執行程式的搜尋空間雖然比完整架構搜尋小得多，但對於極大規模的 LLM 而言，如何有效擴展 PoLar 仍是一個開放問題。

**Q14：PoLar 可能會在哪些情況下失效？**
A：PoLar 可能會在以下情況下失效：當輸入的難度分布與訓練資料差異極大時，預測網路可能無法準確判斷該跳過哪些層或重複哪些層，導致選擇了次佳的執行程式。此外，對於需要跨層資訊整合的複雜推理任務，過度跳層可能會切斷必要的資訊流，而過度遞迴則可能導致過擬合（overfitting）於中間表示，反而損害最終預測。另一個潛在的失敗情境是當預訓練模型本身的某些層對特定任務至關重要時，PoLar 的跳層機制可能會無意中省略這些關鍵層。

**Q15：這項研究未來可以朝哪些方向發展？**
A：未來研究可以朝幾個方向延伸：首先，將 PoLar 從數學推理擴展到更廣泛的自然語言處理任務，驗證其在不同領域的通用性；其次，探索更豐富的程式結構，例如引入條件分支（根據中間結果決定後續層的選擇）或更靈活的迴圈控制，使程式能模擬更複雜的演算法結構（algorithmic structure）。另一個有前景的方向是將 PoLar 與其他測試階段技術結合，例如與思維鏈（Chain-of-Thought, CoT）提示或自一致性（self-consistency）方法結合，實現「token 空間」與「隱藏狀態空間」的雙重動態推理。此外，研究如何將 PoLar 應用於視覺語言模型（VLM）或多模態模型，也是值得探索的方向。

## 實務應用指南

### 適用場景

PoLar 的核心價值在於「凍結預訓練權重、以動態層級程式取代固定前向傳遞」，因此特別適合以下場景：

1. **數學與符號推理服務**：例如教育科技平台、競賽題解系統、數理家教 Chatbot。論文在 GSM8K、MATH 等基準上證明 PoLar 能以更少層數達到更高準確率，這對延遲敏感的即時解題服務特別有吸引力。

2. **企業內部 RAG 問答系統**：當問句難度差異極大（從簡單事實查詢到多步驟推理）時，PoLar 可根據輸入難度自動選擇「跳層」或「迴圈」策略，在簡單問題上節省推論成本、在困難問題上透過層級遞迴提升品質。

3. **邊緣裝置或成本受限的 LLM 部署**：在行動裝置、嵌入式 AI、CPU-only 推論環境中，減少平均執行層數直接轉化為延遲降低與能耗節省。PoLar 預測網路本身是輕量級的，可在不重新訓練主模型的前提下達成自適應深度。

4. **多任務通用助手（Generalist Agent）**：當同一個 LLM 需同時處理程式碼生成、規劃、寫作等異質任務時，可為不同任務類型學習不同的層級程式分布，實現「一個模型、多種推論路徑」。

5. **測試階段計算量擴展（Test-Time Compute Scaling）**：當使用者願意為更困難的問題付出更多推論時間時，PoLar 可透過增加候選執行程式數量來擴展計算，並在 OOD 資料上仍維持泛化能力，適合需要彈性定價的 AI 服務。

### 實作前置條件

**資料需求**
- 一組預訓練 LLM 的權重（論文以數學推理模型為主，但概念可遷移），需具備可存取每一層中間隱藏狀態的能力。
- 用於訓練 PoLar 預測網路的「輸入—最佳執行程式」配對資料。可透過 MCTS 在小型校準集上搜尋產生標籤，或以人工標註的難度分級作為代理訊號。
- 評測資料需涵蓋目標任務的分布內（ID）與分布外（OOD）子集，以驗證泛化性。

**計算資源**
- MCTS 標籤生成階段：單張高階 GPU（如 A100/H100）即可，但搜尋空間龐大，建議準備數十至數百 GPU 小時。
- 預測網路訓練：輕量級 MLP 或小型 Transformer，單卡即可完成，訓練時間通常遠小於主 LLM。
- 推論階段：需支援動態控制流程的執行環境（如自定義 CUDA kernel、PyTorch JIT、或 ONNX Runtime 的動態圖支援）。

**技能門檻**
- 熟悉 Transformer 內部結構（注意力、前饋網路、殘差連接），能從主流開源框架（HuggingFace、vLLM、TGI）取得層級 hook。
- 具備 MCTS 實作經驗，或能整合現有樹搜尋函式庫。
- 了解強化學習或監督式學習中的序列預測（policy network）訓練流程。
- 具備推論優化經驗者更佳：能處理 KV-cache 在跳層/迴圈時的正確性。

---

### 實作步驟建議

**步驟一：建立層級函式庫介面**
將預訓練 LLM 的每一層封裝為可獨立呼叫的函式 `f_i`，並設計統一的輸入/輸出介面（隱藏狀態張量）。確認殘差連接與層正規化在跳層時仍維持語意一致性。

**步驟二：以 MCTS 探索有效執行程式**
在小型校準集（數百至數千樣本）上執行 MCTS，搜尋空間定義為「層索引序列，允許跳過與重複」。獎勵函數可結合「預測正確性」與「程式長度（負權重）」，以鼓勵短而正確的程式。記錄每筆輸入對應的最佳程式作為監督訊號。

**步驟三：設計並訓練 PoLar 預測網路**
預測網路輸入為問題嵌入（可取自主 LLM 的某一中間層或獨立編碼器），輸出為執行程式的機率分布或直接回歸層索引序列。以步驟二的標籤進行監督式訓練；亦可採模仿學習（behavior cloning）搭配強化學習微調。

**步驟四：建構動態推論執行器**
實作一個執行器，能根據預測網路輸出的程式序列動態決定每一層是否執行、執行幾次。關鍵工程細節包括：KV-cache 的正確管理、跳層時的隱藏狀態傳遞、以及迴圈時的迭代停止條件。

**步驟五：評估與迭代**
在 ID 與 OOD 基準上比較 PoLar 與標準推論、僅跳層、僅迴圈等基線。分析平均執行層數、準確率、延遲分布，並針對失敗案例進行錯誤分析，必要時回到步驟二擴大搜尋或調整獎勵函數。

**步驟六：部署與監控**
將執行器整合至推論服務（可與 vLLM、TGI 等框架共存），加入日誌記錄每筆輸入的執行程式長度與分布，作為後續模型維護與成本分析的依據。

### 潛在風險與注意事項

1. **KV-cache 與注意力狀態的一致性**：跳層或迴圈時，若未正確重置或延續注意力鍵值，可能導致隱藏狀態污染。緩解方式：在每次跳層時重新計算對應位置的 KV-cache，或在迴圈起點明確標記狀態邊界。

2. **預測網路的錯誤傳播**：若預測網路輸出無效程式（例如指向不存在的層或產生無限迴圈），需設計安全機制——例如最大層數上限、預設退回標準前向傳遞、或在執行器層加入合法性檢查。

3. **MCTS 標籤的偏差**：MCTS 搜尋受獎勵函數設計影響，可能偏好「短但偶然正確」的程式，忽略泛化性。建議在標籤生成階段加入多樣性約束，或以集成多條候選程式作為標籤。

4. **OOD 泛化不保證**：雖然論文聲稱 OOD 表現良好，但若部署領域與訓練校準集差異過大（如從數學轉到醫療問答），預測網路可能系統性誤判難度。緩解方式：定期以新領域樣本重新校準預測網路。

5. **推論框架相容性**：多數高效推論引擎（vLLM、TGI）假設固定層數順序執行，動態跳層/迴圈需自定義 kernel 或在 Python 層攔截，可能犧牲部分吞吐量。建議先以離線批次場景驗證，再考慮線上低延遲部署。

6. **可解釋性與除錯困難**：執行程式因輸入而異，傳統的「同一模型、同一行為」假設不再成立。需建立完善的視覺化工具，記錄每筆輸入的程式軌跡，以便問題排查。

### 與其他技術的整合建議

- **與思維鏈（Chain-of-Thought, CoT）整合**：CoT 在 token 空間展開推理，PoLar 在隱藏狀態空間調整計算。兩者可正交結合——以 CoT 提示引導模型，再以 PoLar 動態決定層數，形成「顯式推理 + 隱式計算」的雙重自適應。

- **與 Speculative Decoding 整合**：PoLar 決定「執行哪些層」，Speculative Decoding 決定「如何加速 token 生成」。兩者可共用小型草稿模型，但 PoLar 的預測網路本身已具備輕量特性，可作為草稿模型的候選。

- **與 LoRA / Adapter 微調整合**：若需在特定領域微調主 LLM，可凍結主模型權重，僅訓練 LoRA 並搭配 PoLar 預測網路。這種組合在保留通用性的同時兼顧領域適應，且 PoLar 的動態深度可補償 LoRA 的容量限制。

- **與 Early Exit 機制整合**：Early Exit 在中間層插入分類頭並提前終止；PoLar 的跳層操作可涵蓋此場景，但更靈活（允許非線性跳過）。建議以 PoLar 為主、Early Exit 為輔，作為預測網路失效時的備援策略。

- **與模型路由（Model Routing）整合**：在多模型服務架構中，可將 PoLar 預測網路擴展為「模型 + 程式」聯合路由器，根據輸入難度同時決定使用哪個模型與其內部的執行程式。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解 Transformer 的基本結構（層、注意力、前饋網路）與「前向傳遞」的意義，再閱讀摘要與圖 1，掌握「層可以當作函式被任意呼叫」這個核心比喻。實作面可先從小規模實驗開始，例如在小型模型上手動嘗試跳過最後幾層觀察輸出變化，再進階到自動化程式搜尋。

**給 AI 工程師**：重點關注第 2 節的程式形式化定義、MCTS 搜尋空間設計、以及預測網路的訓練目標。工程上最關鍵的問題是「如何在不重寫推論引擎的前提下支援動態層級執行」，建議先在 HuggingFace Transformers 上以 hook 機制驗證概念，再評估移植到 vLLM 或自定義 kernel 的可行性。

**給研究者**：論文的實證發現（短程式常足夠、跳層與迴圈需聯合搜尋、連續層段為主）值得深入探討其背後的理論意涵——為何凍結模型已隱含如此豐富的計算結構？可考慮從資訊瓶頸、函式逼近、或神經 ODE 的角度切入，並探索 PoLar 與測試階段計算量擴展（test-time scaling）的理論連結。

**給產品經理**：PoLar 提供了一個獨特的價值主張——「不重新訓練模型，就能讓同一個 LLM 對簡單問題更快、對困難問題更準」。在與客戶溝通時，可強調「成本下降 + 品質提升」的雙重效益；但也須誠實說明工程整合成本與 OOD 風險，避免過度承諾。建議先以內部工具或非關鍵場景試點，累積資料後再推向客戶-facing 服務。
