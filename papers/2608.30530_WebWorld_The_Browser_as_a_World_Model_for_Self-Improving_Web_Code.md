## 摘要翻譯

由視覺語言模型（Vision-Language Model, VLM）驅動的網頁程式碼自我改進（Self-Improving Web Code）存在一個結構性缺陷：提出修補的模型同時也是評判該修補的模型，而在這樣的評判機制下，視覺合理性（Visual Plausibility）只是頁面是否真正運作的不良代理指標。這個迴圈缺少的是一個 VLM 無法欺騙的制衡方（Counterparty），而瀏覽器正是這個制衡方：它是一個確定性可執行模擬器（Deterministic Executable Simulator），能模擬 HTML 成品（HTML Artifact）在使用者操作（User Actions）下的行為，實質上已經是網頁程式碼的世界模型（World Model）。我們提出 WebWorld，一個讓 VLM 先驗（VLM Prior）能夠自主地與此瀏覽器即世界模型（Browser as a World Model）互動，並決定哪些互動成為監督訊號（Supervision）的介面。每一輪中，VLM 產生批判（Critique），規劃器（Planner）再將其編譯為型別化互動契約（Typed Interaction Contract）；瀏覽器重新執行（Browser Re-execution）候選修補（Candidate Patch），只有在目標進展（Target Progress）達成且所有先前已驗證能力（Previously Verified Capability）均獲保留（Preservation）時，才會發出驗收憑證（Acceptance Certificate）；這些已認證轉移（Certified Transitions）會累積成為品質棘輪（Quality Ratchet），也是監督式微調（Supervised Fine-Tuning, SFT）匯出唯一會看到的內容。在相同訓練設定下，WebWorld-27B 在 HTMLBench-400 上相較 Raw-27B 提升 5.3 分，在 MiniAppBench-Val 上提升 14.9 分，並在互動式 HTML 生成方面達到 Kimi-K2.6 與 GPT-5.4 等強大前沿系統的水準。相同規模的消融實驗顯示，瀏覽器背書准入（Browser-Backed Admission）是這些增益的來源：若無憑證（Certificate），同設定下 9B 模型的提升幾乎消失。

### 核心貢獻（3～5點）
- 指出 VLM 驅動的自我改進存在「提案者—評判者落差」（Proposer-Judge Gap）：同一模型既提案又評判，導致視覺合理性無法真實反映網頁運作正確性。
- 提出將瀏覽器視為網頁程式碼的現成世界模型（Ready-Made World Model）與不可欺騙的制衡方，以確定性可執行模擬取代單純的視覺判斷。
- 設計 WebWorld 框架，使 VLM 能自主與瀏覽器互動，並透過型別化互動契約（Typed Interaction Contract）將 VLM 批判轉為可由瀏覽器檢驗的具約束力主張（Binding Claim）。
- 引入驗收憑證（Acceptance Certificate）與品質棘輪（Quality Ratchet）機制，確保僅有同時達成目標進展並保留既有能力的已認證轉移，才能進入監督式微調（SFT）訓練資料。
- 在 HTMLBench-400 與 MiniAppBench-Val 上驗證，瀏覽器背書准入（Browser-Backed Admission）是效能提升的關鍵，且 WebWorld-27B 可達到前沿商用系統水準。

### 適合對象
本論文適合對大型視覺語言模型自我改進、自動化網頁與前端程式碼生成、具世界模型（World Model）的代理決策系統，以及可驗證強化學習（Verified RL）感興趣的研究人員與工程師。特別適合關注如何以確定性模擬器或瀏覽器作為不可欺騙之回饋來源，以提升生成式模型在互動式 GUI 任務上可靠性的讀者。

## 深度分析

#### 方法論解析

WebWorld 的核心論點是：由視覺語言模型（Vision-Language Model, VLM）驅動的網頁程式碼（Web Code）自我改進（Self-Improvement）迴圈存在結構性缺陷——**提案者—評判者落差（Proposer-Judge Gap）**。當 VLM 同時負責提出修補（Candidate Patch）又負責判斷修補好壞時，畫面看起來正確的**視覺合理性（Visual Plausibility）**並不能保證頁面在互動後真的可運作。為此，作者把**瀏覽器（Browser）**重新定位為**現成的世界模型（Ready-Made World Model）**：它是一個**確定性可執行模擬器（Deterministic Executable Simulator）**，能夠在給定使用者操作（User Actions）下模擬 HTML 成品（HTML Artifact）的實際行為。WebWorld 則是讓 VLM 先驗（VLM Prior）與這個瀏覽器世界模型自主互動，並決定哪些互動可以成為**監督訊號（Supervision）**的介面。

整個流程可拆解為三個互相耦合的機制：

1. **型別化互動契約（Typed Interaction Contract）**  
   每一輪，VLM 先讀取瀏覽器執行後產生的觀察（Observation），包括截圖、DOM、主控台狀態、探針結果與執行動作軌跡（Action Trace），然後產生**批判（Critique）**。批判必須指出問題類型、支援證據、受影響區域、修復後應滿足的成功條件、必須保留的行為，以及建議的修補技能。接著，**契約規劃器（Contract Planner）**把這段自由形式的批判編譯成一份具約束力的主張（Binding Claim），也就是互動契約。契約包含三個承諾：修復後必須達成的**目標謂語（Target Predicate）**、瀏覽器將如何檢驗它的**重播動作（Replay Action）**，以及必須維持不變的**保留集合（Preserve Set）**。

2. **驗收憑證（Acceptance Certificate）**  
   候選修補（Candidate Patch）產生後，瀏覽器會依據契約重新執行（Browser Re-execution）該候選程式碼。只有在同時滿足「目標進展（Target Progress）成立」與「所有**先前已驗證的能力（Previously Verified Capability）**都被保留」兩個條件時，**憑證閘門（Certificate Gate）**才會發出接受憑證。若任一條件失敗，系統會產生具型別的拒絕（Typed Rejection），這份拒絕會留在路由串流中供後續改進參考，但**絕不會進入監督式微調（Supervised Fine-Tuning, SFT）**的訓練資料。

3. **品質棘輪（Quality Ratchet）**  
   只有獲得憑證的**已認證轉移（Certified Transitions）**才會被累積到軌跡記憶（Trajectory Memory）與 **SFT 匯出（SFT Export）**中。這形成了一個單向的品質棘輪：已驗證的能力集合只會擴大，任何在後續輪次破壞既有能力的修補都會被拒絕。因此，**失敗不會污染監督訊號（Failure Cannot Contaminate Supervision）**，而**監督單位（Unit of Supervision）**不再是靜態的最終截圖或純量偏好，而是經過瀏覽器證明的狀態轉移。

從設計上，WebWorld 確保四個性質：

- **依設計分離假設與證明（Hypothesis and Proof Split by Construction）**：VLM 提出假設，瀏覽器負責驗證。  
- **具型別主張（Typed Claims）**：所有批判都化約為對瀏覽器可觀察狀態的謂語，排除純視覺判斷。  
- **單調能力記憶（Monotone Capability Memory）**：已驗證集合只增不減。  
- **確定性准入（Deterministic Admission）**：契約准入與憑證閘門都是對**具型別輸入（Typed Inputs）**的**確定性策略（Deterministic Policies）**，每個接受或拒絕都可以離線重現。

數學上，第 t 輪的驗證可寫成：給定請求 r_t、契約、候選成品 x_t 與已驗證謂語集合 P_t，候選 x_{t+1} 被接受若且唯若：

- TARGET(r_t, x_t) = 0（目前狀態尚未達成目標）
- TARGET(r_t, x_{t+1}) = 1（修補後達成目標）
- 對所有 p ∈ P_t，p(x_{t+1}) = 1（保留所有先前已驗證能力）

訓練時使用的樣本因此是 (x_t, c_t, r_t, x_{t+1}, e_t)，其中 e_t 是記錄准許證據的憑證，而非單純的最終 HTML 檔案。

#### 實驗數據解讀

作者在兩個互動式 HTML 生成基準上進行評估：**HTMLBench-400** 與 **MiniAppBench-Val**。結果顯示，在相同規模訓練條件下：

- **WebWorld-27B** 在 HTMLBench-400 上達到 **52.7**，相較於未經自我改進的 **Raw-27B** 提升 **5.3 分**。  
- 在 MiniAppBench-Val 上達到 **85.5**，相較於 Raw-27B 提升 **14.9 分**。  
- WebWorld-27B 在互動式 HTML 生成任務上達到與 **Kimi-K2.6**、**GPT-5.4** 等強大前沿系統（Frontier Systems）相當的水準。

更重要的是消融實驗（Ablations）：在相同規模的 **9B** 模型上，若移除憑證機制（即沒有瀏覽器背書准入，Browser-Backed Admission），相對於 Raw-9B 的提升幾乎消失，僅剩 **0.4 分**。這強烈支持論文的核心假設：**瀏覽器重新執行與憑證發放才是效能提升的來源**，而非 VLM 單純透過視覺批判產生更好的外觀。

這些數字有幾層意義：

1. **世界模型確實在做事**：不是 VLM 自己說自己變好，而是瀏覽器作為無法被欺騙的對手方（Counterparty），把真正可運作的轉移篩選出來。  
2. **監督訊號的品質比數量重要**：雖然憑證機制會拒絕大量候選，但留下來的樣本具有行為正確性保證，因此對 SFT 更有效。  
3. **互動正確性對 MiniApp 場景更關鍵**：MiniAppBench-Val 的提升（14.9 分）遠大於 HTMLBench-400（5.3 分），暗示當任務涉及更多按鈕、鍵盤輸入、狀態變化等互動時，單靠視覺判斷的缺陷更嚴重，瀏覽器驗證的價值也更高。

不過，論文未詳細說明這些分數的具體計算方式（例如是否包含功能正確性、視覺相似度、人類評分等），也沒有提供標準差或多次實驗的穩定性分析，這在解讀時需要留意。

#### 與現有研究的比較

WebWorld 與過往 VLM 驅動的程式碼自我改進研究有幾個關鍵差異：

**相較於純 VLM 批判—改寫迴圈（VLM-Only Critique-and-Rewrite Loop）**  
過去常見的做法是：顯示截圖給 VLM，要求它提出改進，再直接對輸出進行 SFT。這種方法的失敗模式有兩種：第一，修復後的截圖可能看起來更好，但頁面在互動下其實已經損壞；第二，單一區域的改進可能悄悄移除前幾輪才建立好的控制項或行為。WebWorld 透過瀏覽器重新執行與保留集合，把這兩種迴歸（Regression）都擋下來。

**相較於以人類回饋或偏好模型為監督的改進方法**  
傳統強化學習自人類回饋（RLHF）或視覺偏好模型通常以純量分數或成對比較作為監督，這些訊號無法保證功能性正確。WebWorld 的監督單位是經過瀏覽器證明的狀態轉移，本質上是一種**結構化、可執行的證明**，而非主觀偏好。

**相較於自行訓練世界模型（Learned World Model）的方法**  
在機器人、遊戲或決策領域，世界模型通常需要額外訓練。WebWorld 的創新在於指出瀏覽器本身就是**瀏覽器即世界模型（Browser as a World Model）**，無需額外訓練即可使用。這大幅降低了部署成本，也保證了確定性。

**相較於前端測試或程式碼驗證工具**  
現有的單元測試、E2E 測試或靜態分析也能驗證程式碼，但它們通常需要人類撰寫測試案例。WebWorld 的契約是由 VLM 批判自動編譯而來，並由瀏覽器執行，形成一個**自主（Autonomous）**的改進迴圈。

**限制與潛在弱點**

- **探針與技能清單的覆蓋率**：系統依賴固定的探針目錄（Probe Catalogue）與修補技能庫（Skill Inventory）。若某種互動類型或錯誤模式不在清單中，瀏覽器就無法驗證，VLM 也無法提出對應批判。  
- **瀏覽器可觀察性不等於語意正確性**：瀏覽器能確認「點擊按鈕後出現某個元素」，但未必能判斷該元素是否為使用者真正想要的內容。目標謂語仍由 VLM 定義，若 VLM 對任務理解錯誤，契約本身就會錯。  
- **僅使用 SFT，未結合強化學習**：目前認證轉移只用於監督式微調。雖然這保證了訓練資料的純淨，但也限制了模型從拒絕樣本中學習的能力。  
- **計算成本**：每一輪都需要在真實瀏覽器中重新執行候選程式碼、執行探針、比較狀態，對於大規模自我改進來說，計算與記憶體開銷可能相當可觀。  
- **泛化到真實網頁與後端**：目前評估集中在合成任務（Synthetic Task）與小型互動應用。對於需要後端 API、跨頁面導航、第三方服務或複雜狀態管理的真實網頁，瀏覽器世界模型是否足夠，仍需驗證。

#### 可重現性評估

從提供的論文內容來看，作者並未明確提及是否公開原始碼、資料集或模型權重。文中提到「探針目錄與技能庫列於附錄 G（Appendix G）」，這表示方法細節有文件記錄，但並不保證可執行實作已釋出。

可重現性的幾個關鍵面向：

- **方法描述**：WebWorld 的架構、契約格式、憑證條件與品質棘輪在論文中有清楚定義，理論上可依描述重新實作。  
- **瀏覽器環境**：使用真實瀏覽器（如 Chromium）作為世界模型，這部分可透過 Playwright、Selenium 或 Puppeteer 等現有工具重建。  
- **資料集**：HTMLBench-400 與 MiniAppBench-Val 若為公開基準，則結果可比較；但若為作者自建或尚未釋出，則外部驗證會受限。  
- **模型與訓練細節**：論文提到 27B 與 9B 模型，但未說明基礎模型來源、訓練步數、學習率、批次大小等超參數，這會影響重現。  
- **確定性**：由於契約與憑證都是確定性策略，只要固定瀏覽器版本、種子與輸入，原則上可離線重現接受／拒絕決策，這是優勢。

整體而言，這篇論文在方法層面足夠透明，但若要完全重現端到端結果，仍需要作者釋出程式碼、預訓練模型權重與完整訓練腳本。目前根據現有資訊，可重現性評估為「方法可重建，但完整實驗重現需等待開源釋出」。

#### 未來研究方向

WebWorld 把瀏覽器定位為世界模型的思路，可以延伸到多個後續研究方向：

1. **結合強化學習（Reinforcement Learning, RL）**  
   目前僅將認證轉移用於 SFT。未來可設計以憑證為獎勵訊號的 RL 演算法，讓模型學習從被拒絕的候選中改進探索策略，進一步提升發現有效修補的能力。

2. **動態擴充探針與技能庫**  
   讓 VLM 或另一個學習模組在執行過程中自動發現新的互動模式與錯誤類型，並動態加入探針目錄與修補技能庫，降低對人工設計清單的依賴。

3. **跨頁面與後端互動的驗證**  
   將瀏覽器世界模型擴展到多頁面導航、API 呼叫、資料庫狀態與使用者會話（Session）管理，讓方法適用於更真實的網頁應用開發場景。

4. **與人類回饋或單元測試整合**  
   瀏覽器驗證可與現有測試框架（如 Jest、Cypress）或人類提供的規格結合，形成多層次的監督體系：瀏覽器負責行為正確性，人類或測試負責高階語意。

5. **應用到其他具有可執行模擬器的程式碼領域**  
   同樣的「模型提出假設、模擬器負責證明」框架可應用於遊戲腳本、行動應用（Mobile App）、資料流程管道（Data Pipeline）或硬體模擬等領域，只要該領域存在確定性可執行模擬器。

6. **開源完整實作與標準化評估**  
   釋出 WebWorld 的程式碼、模型權重與評估工具，並建立標準化的互動式 HTML 生成評估協議，將有助於社群驗證與進一步發展。

7. **提升 VLM 批判的品質與可解釋性**  
   研究如何讓 VLM 產生更精確、更少幻覺（Hallucination）的批判，並讓批判與瀏覽器觀察之間的對應關係更可解釋，將進一步強化整個迴圈的可靠性。

## 論文問答

**Q1：WebWorld 主要想解決 VLM 驅動網頁程式碼自我改進中的什麼根本問題？**

A：WebWorld 針對的核心問題是「提案者—評判者落差」，也就是同一個視覺語言模型（VLM）既負責產生修補，又負責用截圖判斷修補好壞，導致視覺合理性無法真實反映頁面是否可運作。這種結構性缺陷會讓頁面看起來改進了，但按鈕可能沒反應、遊戲可能忽略鍵盤輸入，甚至悄悄移除之前已能運作的控制項。WebWorld 透過引入瀏覽器作為無法被 VLM 欺騙的對手方，把「看起來對」轉換成「執行後真的對」。

**Q2：為什麼單純的「批判—重寫」迴圈無法做好互動式 HTML 生成？**

A：在單純的批判—重寫迴圈中，VLM 只看到截圖就提出修改，監督訊號來自修改後的畫面，這會把「視覺上變好」與「功能上正確」混為一談。這種做法可能讓某個區域變得更精緻，卻在同時破壞了使用者互動行為，也可能讓某次孤立的改進默默回歸掉前幾輪才建立好的能力。由於 VLM 同時扮演提案者與評判者，這些失敗模式會污染訓練訊號，並在反覆迭代中不斷累積。

**Q3：為什麼瀏覽器適合作為網頁程式碼的世界模型？**

A：瀏覽器本身就是一個確定性、可執行的模擬器，能夠模擬 HTML 成品在點擊、鍵盤輸入等使用者操作下的行為，因此它提供了無需額外訓練的現成世界模型。它可以在大規模環境中重複執行，也能離線重現結果，並且檢查的是功能保留而非僅僅視覺相似度。這讓瀏覽器成為 VLM 無法用「看起來合理」的輸出欺騙的自然制衡方。

**Q4：WebWorld 的核心方法架構是什麼？**

A：WebWorld 讓 VLM 先驗能夠自主地與「瀏覽器即世界模型」互動，並只把經過認證的狀態轉移納入監督資料。每一輪中，VLM 會產生結構化批判，規劃器再將其編譯成型別化互動契約，包含目標謂語、重播動作、保留集合與證據路徑；接著瀏覽器重新執行候選程式碼，只有在達成目標進展且保留所有先前已驗證能力時，才會發出驗收憑證。這些已認證轉移會累積成品質棘輪，並成為監督式微調匯出的唯一來源。

**Q5：WebWorld 的三個關鍵元件如何對應單純迴圈的失敗模式？**

A：互動契約把 VLM 自由形式的批判轉換成瀏覽器可以檢驗的具約束力主張，避免只用「讓它更精緻」這類模糊判斷。驗收憑證則要求瀏覽器重新執行後證明目標達成且既有功能保留，才能讓候選成為下一個基線，防止破損的修改混入訓練。品質棘輪只允許已認證轉移進入軌跡記憶與 SFT 匯出，從而把執行時的探索與訓練監督分離開來。

**Q6：哪些設計選擇確保了「假設與證明分離」以及確定性准入？**

A：VLM 負責提出假設，也就是透過批判與契約描述應該如何修補；但只有瀏覽器能透過重新執行發出證明，也就是驗收憑證，因此沒有任何主張能在未經實證檢驗前進入訓練資料池。每一條批判都會被歸約為對瀏覽器可觀察狀態的型別化謂語，杜絕僅憑視覺感受的判斷。憑證閘門與准入策略都是對型別化輸入的確定性函數，使得每一次接受或拒絕都可以離線重現與稽核。

**Q7：論文使用了哪些基準測試，主要結果為何？**

A：作者在 HTMLBench-400 與 MiniAppBench-Val 上評估互動式 HTML 生成能力。在相同訓練設定下，WebWorld-27B 在 HTMLBench-400 上比 Raw-27B 提升 5.3 分，在 MiniAppBench-Val 上提升 14.9 分，並達到與 Kimi-K2.6、GPT-5.4 等強大前沿系統相當的水準。這些結果顯示，經過瀏覽器驗證的自我改進能夠在功能性網頁程式碼生成上媲美甚至超越規模更大或專有的模型。

**Q8：消融實驗揭示了瀏覽器背書准入的什麼重要性？**

A：等規模消融實驗顯示，憑證機制幾乎承載了所有增益：若移除驗收憑證，9B 模型相對於 Raw 的提升幾乎消失，僅剩約 0.4 分。這說明單靠 VLM 先驗無法可靠區分好的修補與壞的修補，瀏覽器發出的接受憑證才是高品質監督的關鍵來源。真正推動改進迴圈的是世界模型，而不是視覺批判模型。

**Q9：WebWorld 與前沿系統相比處於什麼位置？**

A：WebWorld-27B 在互動式 HTML 生成上達到與 Kimi-K2.6、GPT-5.4 等強大前沿系統相當的水準，而它只使用 27B 模型與瀏覽器驗證，並不依賴專有級規模或人工回饋。這暗示一個設計良好的世界模型介面，可以透過提供高品質的自我生成監督來彌補模型規模的差距。論文在相同訓練條件下進行比較，以隔離 WebWorld 流程本身的貢獻。

**Q10：哪些實務場景可能受惠於 WebWorld？**

A：WebWorld 可用於自主前端原型設計工具，讓模型根據提示反覆精修 HTML、CSS 與 JavaScript，並保證按鈕、表單與遊戲確實對使用者輸入有反應。它也適合修復老舊網頁、生成迷你應用程式，以及製作必須在新增功能同時保留既有行為的互動式教學頁面。任何一個畫面不僅要「看起來正確」、還要「互動時正確」的場景，都可以藉由瀏覽器即世界模型來認證品質。

**Q11：部署 WebWorld 時需要考慮哪些產品層面問題？**

A：產品團隊必須維護真實瀏覽器執行環境、互動探針目錄以及修補技能庫，這些基礎設施比單純截圖加重寫的迴圈更複雜。確定性准入閘門雖然會增加每輪延遲與運算成本，但同時也讓失敗案例可被稽核與重現，有助於除錯與安全。要實際產品化，必須在探索預算、契約覆蓋率與使用者端延遲之間取得平衡。

**Q12：WebWorld 可能對程式碼自我改進領域帶來什麼更廣泛影響？**

A：WebWorld 把自我改進重新框架為世界模型代理問題，並證明對於網頁程式碼而言，現成的模擬器可以取代額外訓練世界模型的需求。這種方法可能啟發其他可執行成品的類似介面，例如行動應用程式、遊戲或資料管線，只要存在確定性執行環境就能擔任無法被操弄的評判者。它也凸顯了將假設生成與驗證分離的重要性，以避免模型污染自己的監督訊號。

**Q13：WebWorld 有哪些已承認的限制？**

A：此方法仰賴瀏覽器能夠模擬使用者操作並觀察狀態，因此僅適用於可表達為型別化謂語與重播動作的互動行為，細微的視覺回歸或跨瀏覽器差異可能無法完全捕捉。互動契約與修補技能的品質也會限制系統覆蓋範圍，若 VLM 批判不佳，可能提出被瀏覽器正確拒絕、卻無法帶來進展的契約。此外，探針與技能目錄具有任務專一性，必須隨目標領域演進而持續維護。

**Q14：即使有了憑證閘門，仍可能出現哪些失敗案例？**

A：候選程式碼可能通過所有已檢查謂語，卻在契約或探針目錄未涵蓋的互動上出錯，導致已驗證能力集合之外的潛在錯誤。保留集合只保護先前已驗證的能力，因此若某輪同時引入新目標與新的回歸，且後者未被明確測試，就可能被忽略。此外，若 VLM 批判誤判根本原因，契約可能鎖定錯誤行為，憑證也只會驗證一個無關的修補。

**Q15：未來有哪些有潛力的研究方向？**

A：未來研究可以把瀏覽器即世界模型擴展到更豐富的互動模態，例如多點觸控、無障礙樹與網路相依行為，以擴大可驗證能力的範圍。另一個方向是讓契約規劃器與修補技能從已認證軌跡中學習，減少對人工設計探針與技能的依賴。最後，將 WebWorld 與強化學習或測試時間搜尋結合，可以在准許單一轉移前探索大量候選，進一步放大品質棘輪的效果。

## 實務應用指南

### 適用場景

1. **互動式前端元件自動修復**  
   企業內部的 Dashboard、表單、電商結帳頁等，常發生「畫面正常但按鈕沒反應」的問題。WebWorld 可讓 VLM 根據截圖與 DOM 提出修補，再由瀏覽器驗證點擊、鍵盤輸入、表單提交後的行為，並確保既有互動能力不被破壞。

2. **低程式碼／無程式碼平台生成可運作頁面**  
   使用者用自然語言描述需求後，系統產生 HTML/CSS/JS。透過瀏覽器即世界模型（Browser-as-World-Model）的驗證，可避免生成「看起來對但無法互動」的頁面，特別適合 MiniApp、Landing Page、互動小遊戲等場景。

3. **廣告與行銷落地頁快速迭代**  
   行銷團隊需要大量 A/B 版本的 landing page。WebWorld 能在每個版本產出後，自動執行使用者轉換流程（如點擊 CTA、填寫表單、跳轉感謝頁），只保留通過驗證的變體進入訓練資料或上線流程。

4. **網頁程式設計教育與自動批改**  
   學生繳交網頁作業後，系統可自動產生批判、修補並驗證功能，累積帶有 acceptance certificate 的改進軌跡，作為教材或評分依據，減少助教人工檢查互動細節的負擔。

5. **多裝置／多語言適配管線**  
   產生響應式頁面後，可透過型別化互動契約（Typed Interaction Contract）驗證不同 viewport、輸入法、輔助技術下的目標進展與保留行為，確保適配過程不會悄悄破壞核心功能。

### 實作前置條件

**資料**
- 初始 HTML 種子資料集：內部 UI 元件、MiniApp 風格任務或公開網頁生成基準。
- 互動探針目錄：點擊、鍵盤輸入、表單填寫、捲動、遊戲控制等可重播動作。
- VLM 批判範例與對應契約樣板：用於引導模型產出可被瀏覽器檢驗的結構化批判。

**運算**
- 可並行的無頭瀏覽器叢集（如 Playwright、Puppeteer）：用於重新執行候選程式碼與發放憑證。
- VLM 推論資源：論文使用 27B 級模型，實務上可視規模選用 API 或本地多 GPU。
- 軌跡與 SFT 資料儲存空間：每輪都需保存觀測、契約、憑證與拒絕記錄。

**技能**
- 前端工程：熟悉 HTML/CSS/JS、DOM、事件機制與常見互動模式。
- 瀏覽器自動化測試：能建置穩定、可重現的無頭瀏覽器環境。
- VLM Prompt Engineering / SFT：能設計批判格式、規劃器轉譯邏輯與微調資料管線。
- 型別化契約設計：能將自由格式批判轉為 target predicate、replay action、preserve set、evidence path。

### 實作步驟建議

1. **建立確定性瀏覽器執行環境**  
   將無頭瀏覽器容器化，固定瀏覽器版本、viewport、字型、時區與網路條件，避免非同步載入或外部資源造成 flaky verification。

2. **標準化觀測格式**  
   定義每輪必須記錄的證據：截圖、DOM 狀態、console 輸出、probe outcomes、執行的 action trace。這些是 VLM 批判與憑證閘門的共同語言。

3. **開發契約規劃器（Contract Planner）**  
   將 VLM 的自由格式批判轉譯為具約束力的 interaction contract：目標謂語（target predicate）、重播動作（replay action）、保留集合（preserve set）、證據路徑（evidence path）。無法對應到觀測證據的批判應被拒絕。

4. **實作憑證閘門（Certificate Gate）**  
   對每個 candidate patch 重新執行契約：確認 target progress 成立，且所有 previously verified capability 都被保留。只有兩者同時通過，才發出 acceptance certificate 並晉升為下一輪基線。

5. **建構品質棘輪（Quality Ratchet）與 SFT 匯出**  
   只將 certified transitions 寫入 trajectory memory 與 SFT export。未通過驗證的 reject 可保留作為審計紀錄，但絕不進入訓練資料，確保 failure cannot contaminate supervision。

6. **持續監控與迭代**  
   定期分析 reject 原因、VLM-only false positive、以及探針覆蓋缺口，擴充技能庫與 preserve set，並以累積的 certified transitions 重新微調 VLM。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **瀏覽器執行不穩定** | 非同步載入、外部資源、字型差異可能導致同一候選程式碼時而通過、時而失敗。 | 固定資源與版本、mock 外部 API、設定明確等待條件、必要時多次執行取穩定結果。 |
| **契約覆蓋不足** | 未納入 preserve set 的能力可能在後續輪次被默默移除。 | 從初始基準與每輪成功執行自動抽取能力，強制列入保留集合。 |
| **VLM 批判幻覺** | 模型可能提出無法對應觀測證據的修補建議。 | 要求批判必須引用 evidence path，規劃器過濾無效或過於模糊的契約。 |
| **計算成本爆炸** | 每輪都重新執行多個契約與互動探針，成本可能快速上升。 | 優先執行與本次修改相關的契約、快取未變區域的驗證結果、並行化執行。 |
| **過度擬合驗證器** | 模型可能學會通過特定探針，但真實使用者體驗仍然不佳。 | 定期擴充探針目錄、引入真實使用者互動資料、人工抽樣審查通過案例。 |

---

### 與其他技術的整合建議

- **CI/CD 管線**：將 WebWorld 憑證閘門作為前端 PR 的合併前檢查，只有 certified transitions 才能進入主分支，讓 browser-backed admission 成為程式碼品質閘門。
- **傳統單元測試與 E2E 測試**：把現有測試案例轉為 preserve set 與 target predicate，而非完全取代傳統測試。瀏覽器世界模型負責動態生成、傳統測試難以窮舉的互動驗證。
- **RLHF / DPO**：certified transitions 可作為高品質偏好資料，但只採用通過瀏覽器驗證的軌跡，避免視覺偏好誤導模型。
- **設計／原型工具**：從 Figma、Sketch 或設計規範自動生成初始 HTML 種子，再進入 WebWorld 迴圈修復互動細節與行為一致性。
- **可觀測性平台**：把生產環境的真實錯誤軌跡（RUM）轉為新的互動契約，持續擴充驗證集，讓系統隨真實使用者行為演進。

### 給不同背景讀者的閱讀建議

**初學者**  
先掌握核心直覺：VLM 擅長「看起來對」的修補，但不一定「跑得動」；瀏覽器才是真正的對手方與裁判。建議把論文圖 1、圖 2 看懂，理解「VLM 提案、瀏覽器驗證、憑證把關」的分工即可，數學式可暫時略過。

**AI 工程師**  
重點閱讀 §2.3–2.5，深入理解 interaction contract、acceptance certificate、quality ratchet 的實作細節，以及 §3 的消融實驗為何「沒有憑證時 9B 提升幾乎消失」。實作時優先思考如何將你手邊的 VLM 與 Playwright/Puppeteer 管線對接，並確保瀏覽器執行環境的確定性。

**研究人員**  
關注「proposer-judge gap」與「browser-as-world-model」的問題框架轉換。可延伸探討契約語言的完備性、憑證閘門的理論保證、以及如何將此框架推廣到其他可執行產物，例如行動 App、嵌入式 UI 或資料管線腳本。

**產品經理**  
聚焦適用場景與 ROI：哪些前端任務因「視覺對但互動錯」而浪費最多 QA 與工程人力？評估導入後能否縮短迭代週期、減少回歸錯誤，同時留意運算成本、法規與安全風險（例如自動執行未經審查的網頁程式碼）。
