## ⚡ TL;DR

機器人任務僅以一句話描述，缺乏抓取、接觸順序等細節，代理需試誤探索。
ENCORE將示範轉為多視角關鍵幀等證據包，由程式碼代理讀取並迭代精煉策略程式。
在LIBERO-PRO達96.3%勝過先前代理系統89.3%，並成功部署於真實雙臂機器人。

## 摘要翻譯

程式碼代理如今僅需極少人類協助即可撰寫、執行與除錯程式。然而，機器人任務通常僅以一句話描述，省略了如何抓取、以何順序接觸，以及最終結果應呈現何種樣貌；而僅以該句話為輸入的代理必須透過試誤法自行找出這些細節。我們提出 ENCORE，將少量示範作為供代理閱讀的證據，而非訓練資料。確定性建構器將每個示範蒸餾為一個包含多視角關鍵幀、夾爪事件、幀條與完整軌跡的示範包。程式碼代理研究該示範包，針對固定的感知與動作 API 撰寫策略程式，經數次開發回合迭代精煉，並在密封評測前將其凍結，該評測永不揭露成功訊號。在 LIBERO-PRO 上，代理的首個程式在有示範的情況下已能於半數擾動任務中成功，在無示範的情況下則僅於一項任務中成功；且凍結程式在使用相同語言模型時，表現優於最強的先前代理式系統（96.3% 對比 89.3%）。在指令未明確說明目標的 RoboDojo 任務上，無示範時沒有任何程式能成功。ENCORE 亦能於真實雙臂機器人上運行，分別從五個示範中學習方塊交接與杯子翻轉。

### 核心貢獻（3～5點）
- 提出 ENCORE 框架，將少量示範定位為供代理閱讀的「證據」而非訓練資料，使代理能從示範中歸納操作細節，而非僅依賴任務語句進行試誤探索。
- 設計確定性建構器，將每個示範蒸餾為結構化的示範包（多視角關鍵幀、夾爪事件、幀條、完整軌跡），為程式碼代理提供可程式化讀取的視覺與動作資訊。
- 建立「開發回合迭代精煉 → 凍結程式 → 密封評測」之流程，避免評測期間洩露成功訊號，確保評測結果公正可信。
- 在 LIBERO-PRO 基準上，凍結程式以相同語言模型擊敗最強先前代理式系統（96.3% vs 89.3%），並在 RoboDojo 未明示目標的任務中證明示範之必要性。
- 將方法延伸至真實雙臂機器人，僅以五個示範即成功學習方塊交接與杯子翻轉，驗證其在真實環境中的可遷移性。

### 適合對象
從事機器人學習、模仿學習（imitation learning）與具身智慧（embodied AI）研究之學者與工程師；對程式碼代理（coding agent）與大型語言模型驅動之機器人策略生成感興趣之人工智慧研究者；以及尋求以最少示範資料快速部署機器人操作技能之產業界實務人士。

## 深度分析

#### 方法論解析

ENCORE 的核心設計理念在於重新定位示範資料（demonstrations）的角色——將其從傳統的「訓練資料」轉變為「可供查詢的證據」（evidence）。這個轉變貫穿了整個系統架構，並體現在三個關鍵模組的設計中。

**確定性建構器（Deterministic Builder）與示範包（Demonstration Pack）**

建構器的職責是將遙操作示範轉化為結構化的多模態記錄。具體而言，每個示範被蒸餾為四類元素：(1) 多視角關鍵幀（multi-view keyframes），即在夾爪動作發生時刻從各個相機視角擷取的影像；(2) 夾爪事件（gripper events），記錄開合、接觸、釋放的時間序列；(3) 幀條（frame strips），圍繞每個接觸事件前後的連續影像序列；(4) 完整軌跡（full trajectory），保留底層的狀態資訊。這種設計的關鍵洞見在於：決定任務成敗的關鍵時刻僅佔整個回合（episode）的極小比例，而將整個回合直接餵入上下文會讓代理（agent）淹沒於無關細節中。透過預先識別夾爪動作作為關鍵事件，建構器將「哪些細節重要」這個判斷從代理身上移走，但同時保留了代理可能需要的意外線索，例如抓取方向的變化或重新抓取（regrasp）前的晃動。

**感知與動作 API（Perception and Action API）**

ENCORE 採用了一套精簡但表達力強的 API 介面，分為三個層次：
- **感知擷取（Sense capture）**：`capture()` 提供 RGB-D 影像、`deproject()` 進行反投影、`eef()` 回傳末端執行器（end-effector）狀態、`gripper()` 回報夾爪寬度。
- **感知處理（Perceive）**：`sam3()` 呼叫 SAM3 進行開放詞彙（open-vocabulary）分割、`ground()` 進行定位、`vqa()` 進行視覺問答（Visual Question Answering）。
- **動作執行（Act）**：`move()` 進行笛卡兒運動（Cartesian motion）、`move_path()` 沿路徑移動、`grip()` 控制夾爪開閉。

這個 API 設計刻意保持狹窄，目的是讓代理能夠在固定的介面上撰寫策略程式（policy program），同時避免介面過於複雜而導致代理無法有效探索。

**代理式開發循環（Agentic Development Loop）**

編碼代理（coding agent）的工作流程分為三個階段：
1. **觀察（Observe）**：代理透過自己撰寫的分析程式碼來查詢示範包，從中推斷任務意圖與操作策略。
2. **撰寫（Write）**：代理根據觀察結果，針對固定 API 撰寫策略程式。
3. **精煉（Refine）**：代理在少量開發回合（development rollouts）上執行程式，根據執行結果進行迭代修正。

最關鍵的設計決策是**開發時間與評測時間的分離**：代理在開發階段可以存取回饋（feedback），但一旦程式被凍結（frozen），進入密封評測（sealed evaluation）後，代理完全不在迴圈中，策略程式也不再進行任何模型呼叫。這使得策略可以在數千個密封回合上進行評測，且每次執行的成本與延遲與傳統的程式化策略相同。

**示範作為搜尋先驗（Search Prior）**

論文的核心論點是：示範資料的作用是為代理式策略建構提供搜尋先驗。具體而言，示範暴露了操作策略中的關鍵細節——例如抓取位置、方向、路徑——這些細節在任務語句中往往未被提及，但在新佈局（new layout）下卻是成敗的決定因素。代理透過觀察示範來學習這些策略，然後將其轉化為可在不同環境中執行的程式碼。

#### 實驗數據解讀

**LIBERO-PRO 基準測試結果**

在 LIBERO-PRO 上，ENCORE 達到了 96.3% 的密封回合成功率，相較於先前最強的代理式系統 ASPIRE（使用相同語言模型）的 89.3%，提升了 7 個百分點。這個差距在機器人學習領域是相當顯著的，因為 LIBERO-PRO 是一個經過擾動（perturbed）的基準測試，環境配置與訓練時所見不同。

更具啟發性的數據是**首次程式的成功率**：在有示範（K=3）的情況下，代理撰寫的第一個程式就能在約一半的擾動任務中成功；而在沒有示範（K=0）的情況下，首次程式幾乎從未成功。這表明示範的價值在於大幅縮短代理的搜尋過程，讓代理從一開始就朝著正確的方向探索。

值得注意的是，**沒有示範的代理在給予足夠嘗試次數後，最終能達到類似的成功率**。這暗示了示範並非提供了代理無法自行發現的資訊，而是加速了發現過程。然而，在某些特定任務中，示範所提供的抓取策略決定了每一個回合的成敗（論文第 4.3 節），這表明在某些情況下，示範提供了不可或缺的策略資訊。

**RoboDojo 任務結果**

RoboDojo 的任務語句刻意省略了目標或接觸策略的描述。在這些任務上，沒有任何程式能在沒有示範的情況下成功。這凸顯了示範在「目標不明確」任務中的不可替代作用：當語言本身無法提供足夠資訊時，視覺示範成為了理解任務的唯一線索。

**真實機器人實驗**

ENCORE 在真實的雙臂機器人（bimanual robot）上進行了驗證，從五個示範中學習了方塊交接（cube handover）和杯子翻轉（cup inversion）兩個任務。方塊交接任務特別具有挑戰性，因為它涉及雙臂之間的協調：給予手臂（giving arm）從側面呈現方塊，接收夾爪（receiving gripper）需要旋轉四分之一轉使指尖平面（finger planes）交叉，並在給予夾爪打開之前閉合。這些細節在任務語句中完全沒有提及，但對於成功至關重要。

**每回合預算（Per-Episode Budgets）**

實驗設計中明確控制了每回合的預算，這對於公平比較不同方法至關重要。代理在開發階段有固定的嘗試次數，而評測階段則在密封條件下進行，不洩露成功訊號（success signal）。

#### 與現有研究的比較

**與 Code-as-Policies 的關係**

ENCORE 延續了將機器人策略表達為程式碼的傳統（Code-as-Policies [5, 6]），但做了兩個關鍵的擴展：(1) 策略程式不僅是靜態生成的，而是透過代理的迭代精煉產生；(2) 策略的生成過程利用了示範資料作為證據，而非僅依賴語言指令。

**與 ASPIRE 的比較**

ASPIRE [8] 是先前最強的代理式機器人系統，也是 ENCORE 的主要比較對象。兩者的關鍵差異在於：
- ASPIRE 僅從語言指令開始迭代，不使用示範資料。
- ASPIRE 的執行軌跡註解了人類撰寫的診斷規則，例如「夾爪寬度多少算抓取成功」。
- ENCORE 則透過示範包讓代理自行發現這些規則，無需人工編碼。

在 LIBERO-PRO 上，ENCORE 以 96.3% 對 89.3% 超越了 ASPIRE。更重要的是，當論文嘗試將原始軌跡檔案作為示範提供給 ASPIRE 時，並未帶來可測量的增益。這表明問題不在於「是否有示範」，而在於「示範以何種形式提供給代理」。

**與模仿學習（Imitation Learning）的對比**

傳統的模仿學習方法 [1, 2] 從示範中學習策略，但面臨兩個根本挑戰：(1) 示範僅覆蓋狀態空間的極小部分；(2) 沒有合成資料增強（synthetic augmentation [3, 4]）的情況下，訓練出來的策略在偏離示範路徑時就會失敗。ENCORE 透過將示範轉化為「證據」而非「訓練資料」，繞過了這些限制：代理不是從示範中學習一個泛化策略，而是從示範中提取策略，然後將其編碼為可在新環境中執行的程式。

**與 GenRL、Hi Robot 等的定位**

近期的一些工作（如 GenRL、Hi Robot [9, 16]）也探索了讓代理累積可重用技能的方案。ENCORE 的獨特之處在於其對示範角色的重新定義：示範不是用於訓練神經網路策略，也不是用於建立技能庫，而是用於指導代理的程式碼生成過程。

**限制與不足**

ENCORE 的限制主要體現在以下幾個方面：
1. **依賴強大的語言模型**：代理需要能夠撰寫、執行、除錯程式碼的前沿語言模型，這對模型能力提出了較高要求。
2. **API 的表達力上限**：策略的能力受限於固定 API 的表達力。某些操作可能無法用現有 API 表達。
3. **開發時間成本**：雖然凍結後的執行成本低，但開發階段需要多次回合執行，總成本可能較高。
4. **示範品質的敏感性**：系統效能可能對示範品質敏感，低品質的示範可能誤導代理。

#### 可重現性評估

ENCORE 在可重現性方面表現良好，主要體現在以下幾個方面：

**開源程式碼**

論文提供了 GitHub 連結（github.com/YIFANK/encore），程式碼已開源。這使得其他研究者可以重現實驗結果，並在 ENCORE 的基礎上進行進一步的研究。

**專案頁面**

論文提供了專案頁面（yifank.github.io/encore），其中可能包含影片、補充材料等，有助於理解系統的實際運作情況。

**基準測試的標準化**

實驗使用了兩個公開的基準測試（LIBERO-PRO 和 RoboDojo），這使得結果可以與其他方法進行直接比較。

**真實機器人實驗的限制**

真實機器人實驗的可重現性較低，因為不同實驗室的機器人硬體、夾爪規格、相機配置可能不同。論文中描述的方塊交接和杯子翻轉任務需要特定的硬體設置才能重現。

**模型權重與 API 依賴**

ENCORE 依賴於 SAM3 等視覺基礎模型，這些模型本身可能有版本更新或 API 變化。此外，編碼代理的能力取決於所使用的語言模型，論文中並未明確說明使用的是哪個具體模型，這可能影響可重現性。

**評測協議的透明度**

論文詳細描述了密封評測協議，包括不洩露成功訊號的設計，這有助於其他研究者理解並重現評測過程。

#### 未來研究方向

**1. 示範數量與品質的系統性研究**

ENCORE 目前使用 K=3 或 K=5 個示範。未來可以系統性地研究示範數量、品質、多樣性對最終策略效能的影響。例如，最少需要多少示範才能達到特定的成功率？示範的哪些屬性（例如視角多樣性、策略變化）最為關鍵？

**2. 跨任務的技能累積**

目前的 ENCORE 為每個任務獨立開發策略程式。未來可以探索如何讓代理在多個任務間累積可重用的程式碼模組或策略片段，從而加速新任務的學習。這與 GenRL、Hi Robot 等工作中的技能累積思路相呼應，但 ENCORE 的程式化策略可能更易於組合與重用。

**3. 示範來源的擴展**

目前的示範來自人類遙操作。未來可以探索其他示範來源，例如：
- 其他代理產生的示範
- 從影片中提取的示範（例如 YouTube 影片）
- 從語言描述合成的示範

這將大幅降低示範資料的獲取成本。

**4. 不確定性下的策略生成**

目前的策略是確定性的程式碼。未來可以探索如何讓代理生成帶有機率性的策略，或在執行過程中根據不確定性進行動態調整。這對於處理環境變化或感測器雜訊特別重要。

**5. 多模態示範的整合**

目前的示範包主要包含視覺和運動資訊。未來可以整合更多模態，例如觸覺回饋、力感測器資料、語音指令等，這可能讓代理能夠學習更豐富的操作策略。

**6. 安全性與形式化驗證**

由於策略是程式碼，未來可以探索對生成的策略進行形式化驗證（formal verification），確保其在所有預期情況下的安全性。這對於在真實世界中部署機器人策略至關重要。

**7. 與基礎模型的更深度整合**

隨著視覺-語言-動作（Vision-Language-Action, VLA）基礎模型的發展，未來可以探索如何將 ENCORE 的程式化策略與這些基礎模型結合。例如，基礎模型提供低階的運動生成，而 ENCORE 提供高階的策略規劃。

**8. 長期任務與組合泛化**

目前的任務相對短暫。未來可以探索 ENCORE 在長期任務（涉及數十個步驟）以及需要組合泛化（將已學策略組合成新策略）的場景中的表現。

**9. 人機協作策略**

ENCORE 的程式化策略天然易於人類理解和修改。未來可以探索如何讓人類與代理協作開發策略，例如人類提供高階指導，代理負責實作細節。

**10. 理論分析**

目前對 ENCORE 的理解主要是經驗性的。未來可以進行更深入的理論分析，例如：示範資訊的容量如何影響策略的可學習性？代理的搜尋過程如何收斂？這些分析將有助於指導未來的系統設計。

## 論文問答

**Q1：ENCORE 這篇論文主要想解決什麼問題？**
A：ENCORE 旨在解決機器人操作任務中「任務描述過於簡略」所帶來的挑戰。一般機器人任務僅以一句話描述目標，但實際操作所需的細節——例如如何抓取、接觸順序、預期結果——皆未明說，使得僅憑語言指令的代理必須透過大量試誤法來摸索策略。論文中以雙臂方塊交接為例，任務句子完全未提及給予手臂從側面遞出、接收夾爪需旋轉四分之一轉使指尖平面交叉等關鍵細節。ENCORE 的核心主張是：示範應作為「證據」供代理閱讀，而非當作訓練資料，從而將人類隱性知識注入代理式策略建構過程。

**Q2：為什麼現有的代理式機器人方法在面對示範時效果不佳？**
A：現有方法在處理示範資料時面臨兩難：若將整段遠端操作回合（包含數百個時間步、多個相機視角與關節狀態通道）直接放入上下文，會讓代理淹沒於無關細節中；若將回合壓縮為文字摘要或緊湊的 token 序列，則需預先決定哪些細節重要，可能遺漏如抓取方向改變或重新抓取前的晃動等關鍵線索。論文實驗顯示，即使將相同示範以原始軌跡檔形式交給最強的先前代理管線（如 ASPIRE），也未帶來可測量的效益。這正是 ENCORE 設計「示範包」結構化記錄的動機。

**Q3：為什麼這項研究對機器人領域很重要？**
A：這項研究的重要性在於它重新定位了示範在機器人學習中的角色——從訓練資料轉變為代理可查詢的證據，從而結合了編碼代理的強大推理能力與人類示範的隱性策略知識。傳統從少量軌跡學習策略的方法，由於示範僅覆蓋狀態空間的極小部分，在偏離示範路徑時容易失敗；而 ENCORE 讓代理能將示範中觀察到的策略轉移至新佈局、組合出新指令並轉化為可執行程式。這種「示範作為搜尋先驗」的觀點，為少樣本機器人操作開闢了一條新路徑。

**Q4：ENCORE 的核心方法是什麼？**
A：ENCORE 的核心方法分為兩個階段：首先，一個確定性建構器將每個示範蒸餾為一個「示範包」，內含多視角關鍵幀、夾爪事件、幀條與完整軌跡；接著，一個全新的編碼代理研究這些證據，自行撰寫分析程式碼進行探索，推斷任務內容，並針對固定的感知與動作 API 實作策略程式。代理在少量開發回合中反覆精煉該程式，並在密封評測前將其凍結——此時部署的策略不再進行任何模型呼叫，因此可在無代理在場的情況下評估數千個密封回合。

**Q5：ENCORE 最關鍵的創新是什麼？**
A：ENCORE 最關鍵的創新在於將示範重新定義為「證據」而非「訓練資料」，並設計了一個能讓編碼代理有效查詢的結構化示範包。這個示範包同時陳述了預期結果與達成該結果的策略：示範者在何處抓取、以何方位、沿何路徑移動。這種設計讓代理能像工程師閱讀文件一樣，從少數示範中提取出可轉移的操作策略。此外，代理在開發階段而非執行階段使用語言模型的設計，使凍結後的程式可在無模型呼叫的情況下高效部署。

**Q6：ENCORE 在設計上有哪些重要選擇？**
A：ENCORE 的一個關鍵設計選擇是將代理與策略的界線劃在「開發時間」：語言模型負責撰寫、測試與修復程式，而部署的策略則完全不進行模型呼叫，這使得密封評測可在無代理介入的情況下進行。另一個重要選擇是「密封評測」機制——代理在開發過程中從未獲得成功訊號，因此其泛化能力是真實的而非過度擬合於獎勵函數。此外，ENCORE 採用固定的感知與動作 API（如 sam3()、ground()、vqa()、move()、grip() 等），既限制了策略空間使其可控，又保留了足夠的表達能力來處理複雜操作。

**Q7：ENCORE 在哪些基準上進行了評估？**
A：ENCORE 在三個場景中進行了評估：LIBERO-PRO 基準（包含擾動任務）、RoboDojo 基準（涵蓋 22 個目標或接觸策略未被明說的任務），以及真實的雙臂機器人（學習方塊交接與杯子翻轉兩個任務，各使用五個示範）。LIBERO-PRO 用於衡量在受控擾動下的策略轉移能力；RoboDojo 則測試在指令不明確時示範的必要性；真實機器人實驗則驗證了從模擬到現實的可行性。這種多層次的評估設計使結論更具說服力。

**Q8：ENCORE 的主要實驗結果為何？**
A：在 LIBERO-PRO 上，ENCORE 凍結的程式在密封擾動回合中達到 96.3% 的成功率，超越了使用相同語言模型的先前最強代理式系統（ASPIRE）的 89.3%。更具啟發性的是，代理所寫的第一個程式在有示範的情況下已能在約一半的擾動任務中成功，而沒有示範時幾乎從未成功——這直接證明了示範作為搜尋先驗的價值。在 RoboDojo 上，對於指令未明說目標的任務，沒有示範就沒有任何程式能成功，進一步凸顯示範在策略發現中的不可替代性。

**Q9：ENCORE 進行了哪些消融實驗？**
A：ENCORE 進行了受控的消融比較：在相同模型、相同 API、相同開發預算與相同評測協定下，比較使用三個示範（K=3）與不使用示範（K=0）的表現。實驗顯示，有示範時代理的第一個程式在開發階段就能在約一半的擾動單元中成功；無示範時則幾乎從未成功，但若給予足夠嘗試次數，最終仍可達到相近的成功率。此外，論文中還分析了在哪些情況下示範的抓取方式決定了每個回合的成敗，展示了示範對策略發現的具體貢獻。

**Q10：ENCORE 適用於哪些實際場景？**
A：ENCORE 特別適用於那些「任務描述無法完整表達操作策略」的複雜操作場景，例如雙臂協調任務（方塊交接需要雙臂時序配合）、精密操作（杯子翻轉需要特定抓取方位與翻轉路徑），以及任何需要隱性策略知識的工業或服務機器人應用。在論文的真實機器人實驗中，ENCORE 僅用五個示範就學會了方塊交接與杯子翻轉，展示了其在實際部署中的可行性。這種少樣本學習能力對於機器人在新環境中快速適應特別有價值。

**Q11：將 ENCORE 應用於實際產品時需要考慮哪些因素？**
A：將 ENCORE 應用於實際產品時，需考慮以下因素：首先，部署的策略程式不進行模型呼叫，因此可在無網路連線的情況下即時執行，適合邊緣部署；其次，密封評測機制確保了策略的泛化能力，但開發階段需要語言模型與執行環境的支援，因此開發成本較高。此外，示範包的建構需要確定性處理流程，這對示範品質與一致性提出了要求；最後，固定的感知與動作 API 雖簡化了策略空間，但也限制了可表達的操作範圍，需根據具體應用進行擴充。

**Q12：ENCORE 對機器人與代理式 AI 領域的影響是什麼？**
A：ENCORE 對機器人領域的影響在於它示範了如何將編碼代理的強大推理能力與人類示範的隱性知識結合，為少樣本機器人操作提供了一條新路徑。對代理式 AI 領域而言，ENCORE 展示了「證據」與「訓練資料」的區分如何影響代理的學習效率——結構化的證據比原始資料或預先摘要更能幫助代理發現策略。這種「示範作為搜尋先驗」的觀點可能啟發後續研究探索其他形式的證據（如失敗案例、修正軌跡）如何進一步提升代理式策略建構的效果。

**Q13：ENCORE 論文承認了哪些限制？**
A：ENCORE 論文承認的限制包括：在 RoboDojo 某些指令未明說目標的任務中，沒有示範就沒有任何程式能成功，這意味著 ENCORE 並非在所有情況下都能從零開始發現策略。此外，ENCORE 的效能受限於固定的感知與動作 API 的表達能力，雖然這簡化了策略空間，但也可能限制其處理更複雜操作的能力。論文中也提到，示範包的設計需要決定哪些細節值得保留，這本身是一個取捨——過濾過多可能遺漏關鍵線索，保留過多則可能淹沒代理。

**Q14：ENCORE 在哪些情況下會失敗？**
A：ENCORE 在以下情況下可能失敗：當任務指令完全未說明目標且沒有示範時（如 RoboDojo 的某些任務），代理無法僅憑語言推斷出正確的操作策略。此外，當示範本身品質不佳或示範間存在矛盾時，代理可能難以從中提取一致的策略。論文也指出，即使有示範，若任務的新佈局與示範差異過大（例如物體位置、尺寸大幅改變），代理可能無法將示範中的策略有效轉移。密封評測機制雖然防止了過擬合，但也意味著代理無法在評測中根據失敗進行調整。

**Q15：ENCORE 未來可能的研究方向有哪些？**
A：ENCORE 未來可能的研究方向包括：擴展感知與動作 API 以處理更複雜的操作任務（如柔性物體操作、多步驟組裝）；探索更多類型的「證據」（如失敗案例、修正軌跡、人類回饋）如何進一步提升代理的策略發現能力；將 ENCORE 應用於更多真實機器人場景，驗證其在工業自動化、服務機器人等領域的實用性。此外，研究如何讓代理在開發階段更高效地利用預算（例如透過更好的程式碼重用、技能累積）也是一個重要方向；最後，將 ENCORE 與其他機器人學習範式（如模仿學習、強化學習）結合，可能產生互補效益。

## 實務應用指南

### 適用場景

ENCORE 適合以下幾類需要「從少量示範中快速產出可部署機器人策略」的實務情境：

1. **家庭與服務機器人的新任務上線**：例如讓雙臂機器人學會「把杯子翻過來瀝乾」、「把玩具從 A 盒移到 B 盒」等任務。操作員只需用控制器示範 3–5 次，無需撰寫程式碼或收集上千筆資料，ENCORE 即可產出可在新擺放位置直接執行的策略程式。

2. **工廠異質工件組裝**：當產線換料、夾具或工件幾何變動時，傳統視覺伺服或寫死的腳本失效。技術員示範幾次新工件的操作流程，ENCORE 即可生成對應的抓取與放置策略，縮短換線時間。

3. **研究實驗室中的策略原型驗證**：機器人學習研究者想快速驗證「某個新任務能否用程式碼策略解決」，但不想花時間標註資料或訓練神經網路。ENCORE 提供一個低門檻的開發循環：示範 → 程式生成 → 模擬測試 → 凍結部署。

4. **危險或精密操作的可審核部署**：例如醫療輔助、實驗室自動化等場景，部署的策略必須是「可讀、可審查、可追溯」的程式碼，而非黑盒神經網路。ENCORE 產出的凍結程式正好滿足此需求。

5. **教學與示範用途**：在機器人課程中，學生可以觀察 ENCORE 如何從示範中提煉策略，理解「示範作為證據」與「示範作為訓練資料」的差異。

### 實作前置條件

**資料面**
- 每個任務需準備 **3–5 筆遙操作示範**（論文使用 K=3 為主要設定），涵蓋 RGB-D 多視角影像、末端執行器姿態、夾爪開合狀態與完整關節軌跡。
- 示範需涵蓋任務的關鍵接觸事件（抓取、放置、交接、翻面等），否則建構器無法萃取出有意義的關鍵幀。
- 建議具備任務的語言指令（sentence-level），即使指令未描述細節也可，但需有基本意圖說明。

**運算面**
- 一台具備多視角 RGB-D 串流的機器人（模擬或實體皆可，論文使用 LIBERO-PRO、RoboDojo 模擬環境與真實雙臂機器人）。
- 開發階段需呼叫前沿語言模型（論文未指定模型，但需具備「寫程式、執行、除錯」能力的代理式 LLM，例如 GPT-4 級別或更強）。
- 模擬環境需支援快速 rollout（每個開發回合數秒至數十秒級），以便在預算內完成迭代。
- 部署階段無需 GPU 推論——凍結程式只呼叫固定的感知與動作 API，不含模型呼叫。

**技能面**
- 熟悉 Python 程式設計與基本的機器人 API（笛卡兒運動、夾爪控制、視覺感知）。
- 了解如何設計「感知與動作 API」的介面（capture、sam3、ground、vqa、move、grip 等）。
- 具備提示工程（prompt engineering）經驗，能引導代理正確讀取示範包並產出可執行程式。
- 對機器人操作任務的物理直覺（抓取點選擇、接觸順序、容錯策略）有基本理解。

### 實作步驟建議

**步驟 1：建立示範收集管線**
- 設置多視角 RGB-D 相機（建議至少 2–3 個視角，包含自上而下與手腕視角）。
- 記錄遙操作過程中的末端執行器姿態、夾爪寬度、關節角度與時間戳。
- 儲存為標準格式（如 HDF5 或 ROS bag），確保每個時間步的感測資料對齊。

**步驟 2：實作確定性建構器（Deterministic Builder）**
- 從原始軌跡中偵測夾爪事件（開/合/接觸），萃取出關鍵幀。
- 為每個關鍵事件生成多視角影像、幀條（事件前後數幀的影像序列）與對應的軌跡片段。
- 將這些元素打包成「示範包」（Demonstration Pack），附上結構化中繼資料（事件類型、時間戳、涉及的物件）。
- 建構器必須是確定性的——相同的示範必須產生相同的示範包，確保可重現性。

**步驟 3：設計固定的感知與動作 API**
- 定義 `capture()`：回傳 RGB-D、末端執行器姿態、夾爪狀態。
- 定義 `sam3()`、`ground()`、`vqa()`：開放詞彙的視覺感知與物件定位。
- 定義 `move()`、`move_path()`、`grip()`：笛卡兒空間的移動與夾爪控制。
- API 應保持窄而穩定，避免代理在開發過程中因 API 變動而產生不一致的程式。

**步驟 4：配置編碼代理（Coding Agent）**
- 給予代理：任務指令、示範包、API 文件、開發環境（模擬器或真實機器人介面）。
- 設定每回合預算（per-episode budget），限制單次 rollout 的時間與步數。
- 設定總開發回合數上限（例如 5–10 次），避免無限迭代。
- 代理的工作流程：讀取示範包 → 撰寫策略程式 → 執行 → 觀察結果 → 修正。

**步驟 5：執行開發循環並凍結程式**
- 讓代理在開發環境中迭代，直到程式在開發回合中穩定成功，或預算耗盡。
- 凍結最終程式，移除所有模型呼叫——部署的策略僅依賴固定 API。
- 在「密封評測」中驗證：評測環境不透露成功訊號，僅回傳二元結果。

**步驟 6：部署與監控**
- 將凍結程式部署到目標機器人（模擬或實體）。
- 監控執行過程中的感測異常（例如物件未偵測到、夾爪卡住），設計 fallback 行為。

### 潛在風險與注意事項

**風險 1：示範品質不佳導致策略偏差**
- *現象*：示範中包含不必要的動作或錯誤的抓取點，代理會忠實地將其寫入程式。
- *緩解*：示範前先由人類審核，確保每個示範都成功且動作乾淨；必要時過濾掉異常示範。

**風險 2：代理在開發回合中過擬合**
- *現象*：代理反覆調整程式直到在特定開發場景中成功，但泛化到新擺放位置時失敗。
- *緩解*：在開發循環中加入擾動（perturbed layouts），模擬 LIBERO-PRO 的做法；不要讓代理只看到單一固定場景。

**風險 3：API 設計不當限制策略表達力**
- *現象*：API 太細粒度導致代理寫出冗長程式；太粗粒度導致代理無法表達精細操作。
- *緩解*：參考論文的 API 設計（capture、sam3、move、grip 等），從中等粒度開始，根據任務需求擴充。

**風險 4：開發預算耗盡但程式未收斂**
- *現象*：代理陷入反覆修改但無法穩定成功的循環。
- *緩解*：設定明確的停止條件（例如連續 N 次成功即凍結）；提供人類介入的「重置」機制，重新引導代理。

**風險 5：真實機器人與模擬之間的差距（Sim-to-Real Gap）**
- *現象*：在模擬中成功的程式，在真實機器人上因感測雜訊、執行誤差而失敗。
- *緩解*：在真實機器人上進行少量微調；或直接在真實機器人上執行開發循環（論文已展示此可行性）。

**風險 6：安全與可預測性**
- *現象*：代理生成的程式可能包含未預期的動作（例如快速撞擊、夾爪過度施力）。
- *緩解*：在 API 層加入安全限制（速度上限、力上限、碰撞偵測）；凍結程式前進行安全審查。

### 與其他技術的整合建議

**與模仿學習（Imitation Learning）整合**
- ENCORE 不取代模仿學習，而是互補。對於需要高度泛化、處理高維感測輸入的任務，神經網路策略仍更適合；ENCORE 適合需要可審查、快速原型、少量示範的場景。
- 可將 ENCORE 產出的凍結程式作為「專家示範」，用於訓練更泛化的神經網路策略。

**與任務與運動規劃（TAMP）整合**
- ENCORE 的策略程式可作為 TAMP 系統中的「技能原語」（skill primitives）。高層規劃器選擇技能，ENCORE 程式負責執行。
- 將 ENCORE 的 API 擴充為可被 TAMP 系統呼叫的模組化介面。

**與視覺語言模型（VLM）整合**
- 論文中已使用 SAM3 與 VQA 作為感知模組。可進一步整合更強的 VLM（例如 GPT-4V、Gemini）來處理開放詞彙的物件識別與場景理解。
- 注意：部署階段的凍結程式不應依賴 VLM 呼叫，否則會失去「無模型推論」的優勢。

**與機器人作業系統（ROS）整合**
- 將 ENCORE 的感知與動作 API 包裝為 ROS 節點或服務，使其能與現有的 ROS 生態系無縫銜接。
- 示範包可儲存為 ROS bag，便於重播與分析。

**與持續學習整合**
- 當任務失敗時，收集新的示範並重新執行 ENCORE 流程，產出更新版本的策略程式。
- 建立版本控制機制，追蹤每個任務的策略演進歷史。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先讀摘要與第 1 節的引言，理解「為什麼機器人任務很難用語言完整描述」以及「示範作為證據 vs. 訓練資料」的差異。圖 1 是最好的視覺化入口，展示 ENCORE 的整體流程。接著跳到第 4 節的實驗結果，感受「有示範 vs. 沒示範」的效能落差。不需要深入程式碼細節，重點是建立直覺：示範能幫助代理更快找到正確的策略。

**給 AI 工程師**：重點關注第 3 節的系統設計，特別是「確定性建構器」的輸出格式、「感知與動作 API」的設計原則，以及「開發循環 vs. 密封評測」的邊界劃分。思考如何將這個框架整合到現有的機器人平台——你需要設計哪些 API、如何收集示範、如何設定開發預算。程式碼已在 GitHub 開源，建議實際跑一遍 LIBERO-PRO 的範例，理解代理如何讀取示範包並產出程式。

**給研究者**：這篇論文的核心貢獻在於「將示範重新定位為搜尋先驗（search prior）」，而非訓練資料。建議深入閱讀第 4 節的消融實驗，特別是 K=0 vs. K=3 的比較，以及「第一個程式就成功」的分析。這開啟了一個有趣的研究方向：如何設計更好的示範包表示、如何結合符號推理與神經感知、如何量化「示範資訊量」。相關工作（ASPIRE、Code-as-Policies）值得對比閱讀，理解 ENCORE 在代理式機器人領域的定位。

**給產品經理**：ENCORE 的商業價值在於「縮短機器人新任務的部署時間」——從傳統的數週（資料收集、標註、訓練、除錯）縮短到數小時（示範、生成、凍結）。關鍵限制是：每個任務仍需 3–5 次人工示範，且代理需要前沿語言模型支援。適合的應用場景是「任務多變、每個任務量不大、但需要快速上線」的環境，例如服務機器人、實驗室自動化、小批量製造。不適合大規模量產的單一任務（傳統自動化更經濟）。建議先在一個具體任務上做概念驗證，評估示範收集成本與策略穩定性。
