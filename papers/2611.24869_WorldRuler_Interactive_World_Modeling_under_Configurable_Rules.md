WorldRuler 的方法論設計圍繞著解決兩個核心挑戰：規則-狀態持久性（Rule-State Persistence）與規則到視覺實現（Rule-to-Visual Realization）。整體架構採用「可執行 3D 規則圖」（executable 3D rule graph）作為骨幹，將規則定義、依賴關係、物件身分與屬性狀態整合於同一結構中，並透過動態物件綁定（dynamic object binding）與感知回饋（perceptual feedback）形成閉迴路系統。

**3D 規則圖的設計理念**：相較於傳統的純符號化規則引擎或僅作為條件輸入的圖結構，WorldRuler 的 3D 規則圖具備三項關鍵特性。第一，它將規則定義（rule definitions）、規則依賴（rule dependencies）、物件身分（object identities）與屬性狀態（attribute states）統一編碼，使規則執行能直接存取空間資訊。第二，圖結構支援聯合存檔與讀檔——當玩家存檔時，規則圖的完整狀態被序列化；讀檔時，規則圖與世界狀態同步還原，確保後續動作評估基於正確的前提條件。第三，圖結構提供結構化的條件介面，使影片生成模型能從中讀取物件關係與互動約束。

**動態物件綁定機制**：此機制解決了「規則指定的實體如何對應到視覺實例」的問題。當規則圖中某個邏輯物件（例如「monster_01」）需要在影片中呈現時，動態綁定會將其連結到對應的視覺實例。更關鍵的是，對於「受影響物件在當前視野中不可見」（unseen objects）的情況，系統使用儲存的狀態來約束該物件「首次出現」（first appearance）時的生成結果。例如，若玩家觸發開關使遠處的門打開，則當門首次進入視野時，生成過程已被預先約束為「開啟」狀態，而非從「關閉」狀態開始變化。

**物件屬性狀態替換（Object Attribute State Replacement）**：此機制在去噪（denoising）過程中運作。系統讀取當前生成中的物件屬性狀態，並將其替換為規則指定的目標狀態，從而修正受控屬性的偏差。這是一種「硬約束」式的介入，確保規則指定的屬性變化能精確反映在視覺輸出中。

**反事實重建訓練（Counterfactual Reconstruction Training）**：單純的屬性替換可能導致視覺不協調（例如將門從關閉替換為開啟，但周圍光影與運動未對應改變）。為此，作者引入反事實重建訓練，讓模型學習每個狀態的視覺實現方式。配對監督（paired supervision）鼓勵相容的變化（例如門開啟時光線變化、人物姿態調整），同時抑制對無關內容的干擾。這種訓練策略使模型能在保持規則一致性的同時，產生視覺上連貫的結果。

**感知回饋迴路**：生成的影片經過感知模組驗證，更新物件對應關係與局部幾何資訊，供後續綁定與生成使用。值得注意的是，規則指定的狀態與視覺證據是分離管理的——視覺觀察僅用於更新物件對應與幾何，不會覆寫規則強制設定的狀態，避免「視覺幻覺」污染規則邏輯。

**RuleVerse 資料集建構**：作者使用 GTA-V 與 Habitat 兩個環境建立自動化資料收集與標註流程。GTA-V 提供豐富的城市與室內場景，Habitat 提供室內環境的精確模擬。標註涵蓋物件狀態、觸發條件、規則後果與事件時序，特別包含「規則在受影響物件可見之前生效」的情境，這對訓練模型處理 unseen objects 的首次出現約束至關重要。

### 實作步驟建議

**步驟一：建立最小可行的規則圖骨架**
從單一規則鏈開始（例如「開關 → 門開啟」），實作 3D 規則圖的節點（規則定義、物件狀態、空間資訊）與邊（依賴關係）。建議先用程式碼生成小型合成資料驗證圖的序列化與反序列化正確性，再進入影片生成階段。

**步驟二：實作動態物件綁定層**
設計視覺實例（visual instance）與規則節點的對應機制。關鍵是處理「物件尚未出現於畫面」的情境——需在規則圖中保留物件的空間先驗（spatial prior），待首次渲染時再綁定。可參考本文提及的「stored states constrain generation from first appearance」設計。

**步驟三：整合影片擴散模型**
挑選一個開源影片擴散模型作為基座（例如基於 Stable Video Diffusion 或 Wan 系列的架構），將規則圖的條件注入注意力機制。建議先凍結基座權重，僅訓練條件注入模組與物件屬性狀態替換機制，以降低運算成本。

**步驟四：實作物件屬性狀態替換**
在去噪過程（denoising）中讀取受控物件的屬性潛在特徵，並依規則指定的目標狀態進行替換。注意：替換僅作用於受控屬性，避免破壞其他視覺內容；可透過遮罩（mask）機制限制替換範圍。

**步驟五：加入反事實重建訓練**
蒐集「同一場景、不同規則結果」的配對影片，訓練模型在維持非受控內容一致的前提下改變受控屬性。建議從單一屬性變化開始（例如僅改變門的開闔狀態），再逐步擴展到多屬性與多步驟規則鏈。

**步驟六：建立閉迴路感知回饋**
在生成結果後，透過物件偵測與分割模型驗證視覺輸出是否符合規則預期；若不符，自動更新物件綁定與局部幾何資訊並重新生成。此步驟是實現「Rule-State Persistence」跨存檔讀檔的關鍵。

**步驟七：產品化與效能優化**
將規則圖序列化為可儲存的格式（JSON、Protocol Buffers），整合存檔讀檔流程；對影片生成做蒸餾或量化以提升互動即時性；最後建立規則編輯介面（圖形化或自然語言輸入）。

### 潛在風險與注意事項

**風險一：規則組合爆炸（Rule Combinatorial Explosion）**
當規則數量增加，規則圖的節點與邊會快速膨脹，導致序列化檔案過大、推理延遲上升。
**緩解**：採用規則分層（rule hierarchy）與延遲求值（lazy evaluation），僅在玩家接近相關區域時載入對應子圖；對規則鏈做剪枝與快取。

**風險二：屬性替換造成視覺不連貫**
強制替換屬性潛在特徵可能導致邊界瑕疵、光影不一致或運動軌跡斷裂。
**緩解**：在替換後加入輕量後處理（inpainting、temporal smoothing）；訓練時加入邊界一致性損失（boundary consistency loss）。

**風險三：物件綁定漂移（Binding Drift）**
在長時序互動中，視覺實例可能因遮擋、光線變化或視角切換而失去與規則節點的對應，導致規則作用於錯誤物件。
**緩解**：結合多模態感知回饋（深度估計、語意分割）定期重新綁定；設計綁定信心分數（binding confidence），低於閾值時觸發人工或自動校正。

**風險四：反事實資料不足**
反事實重建需要大量「同一場景、不同規則結果」的配對資料，蒐集成本高。
**緩解**：利用遊戲引擎的確定性（determinism）特性，在 GTA-V 或 Habitat 中以相同隨機種子產生配對樣本；或採用合成資料增強（data augmentation）策略。

**風險五：存檔讀檔的狀態不一致**
若規則圖與世界狀態的序列化格式版本不同，可能導致舊存檔無法在新版本正確還原。
**緩解**：建立嚴格的版本管理與向下相容機制；對關鍵狀態做校驗碼（checksum）驗證。

**風險六：運算成本過高難以產品化**
影片生成與閉迴路回饋的總成本可能超出消費級硬體承受範圍。
**緩解**：採用模型蒸餾、量化、投影片快取（latent cache）；對非關鍵場景降級為靜態圖片或低幀率影片。

### 與其他技術的整合建議

**與大型語言模型（LLM）整合**
LLM 可作為規則的自然語言入口：玩家輸入「踩到紅色地板會傳送到起點」，LLM 解析後輸出結構化規則定義並寫入 3D 規則圖。建議使用具備結構化輸出（structured output）能力的模型（如 function calling），並加入規則合法性檢查以避免產生自相矛盾的規則。

**與遊戲引擎整合**
Unity 與 Unreal Engine 均可作為規則執行環境。建議將 WorldRuler 的規則圖作為引擎的行為樹（behavior tree）或狀態機（state machine）的補充層，影片生成結果作為視覺預覽或實際渲染輸出。對於即時互動需求，可將影片生成結果降階為關鍵幀（keyframes）並由引擎內插。

**與現有影片生成模型整合**
WorldRuler 的設計是模組化的，可與 Stable Video Diffusion、Wan、AnimateDiff 等開源模型結合。建議優先選擇支援條件注入（controlnet-style）的架構，以降低改動成本。

**與知識圖譜整合**
對於複雜敘事或領域規則（例如法律、化學反應），可將外部知識圖譜作為規則來源的補充。WorldRuler 的規則圖可設計為與 RDF 或 OWL 格式相容的子集。

**與數位孿生（Digital Twin）整合**
在工業或智慧城市應用中，WorldRuler 可作為數位孿生的「情境模擬器」：定義「若某感測器失效則系統降級」的規則，生成對應的視覺化情境供操作員演練。
