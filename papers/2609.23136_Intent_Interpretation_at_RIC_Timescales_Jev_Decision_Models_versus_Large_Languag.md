# RIC 時間尺度下的意圖解譯：6G 開放式 RAN 中的 Jev 決策模型與大型語言模型

**原文標題：** Intent Interpretation at RIC Timescales: Jev Decision Models versus Large Language Models in 6G Open RAN

## ⚡ TL;DR

探討6GOpenRAN中，LLM意圖解譯延遲能否趕上近即時RIC控制時限。
提出RANIntentv1基準，於ns-3閉迴路與真實A1/E2路徑比較Jev決策模型與託管LLM。
Jev-1.13.0達99.8%近即時預算，LLM多數超時；基準點未見LLM無線成效顯著優於Jev。

## 摘要翻譯

基於意圖的開放式 RAN（Intent-based Open RAN）需要一個解譯器（Interpreter），能夠在 RAN 智慧控制器（RIC）的迴路內將意圖（Intent）轉為 A1 策略（A1 Policy）。Jev-1.13.0 等決策模型（Decision Model）會回傳型別化策略欄位（Typed Policy Fields），而生成式大型語言模型（Generative Large Language Model, LLM）則逐詞元（Token）生成策略。我們探討 LLM 的額外延遲（Extra Delay）是否會導致錯過控制截止時間（Control Deadline）、消耗 RIC 容量（RIC Capacity）或損及無線電效能（Radio Performance）。我們在 RANIntent v1 基準測試（RANIntent v1 Benchmark）上，將 Jev-1.13.0 與另外兩個決策模型和 LLM 進行比較，並於閉迴路 ns-3 模擬（Closed-loop ns-3 Simulation）以及真實 A1 與 E2 路徑（Real A1 and E2 Path）中進行評估。中位數解譯延遲（Median Interpretation Latency）為 0.286 至 2.35 秒，而 A1 傳輸（A1 Transfer）與 E2 傳輸／控制（E2 Transfer / Control）則低於 25 毫秒。Jev-1.13.0 在 99.8% 的呼叫中滿足 1 秒近即時預算（Near-real-time Budget），而兩個託管式大型語言模型（Hosted LLM）分別僅有 17.9% 與 0%。在無線網路中，相較於基準點（Base Point）的未更新（No Update）情境，理想執行（Ideal Enforcement）使受影響類別（Affected Class）的服務等級協定（Service-level Agreement, SLA）違規（SLA Violation）率依各意圖所要求的方向移動 3.96 個百分點。在該點上，沒有任何託管式 LLM 相較於 Jev-1.13.0 呈現可解析的增加（Resolved Increase）。在同樣的點上，每秒直接控制（Per-second Direct Control）相較於數值型 xApp（Numerical xApp）也未帶來可解析的 SLA 降低。慢速解譯器（Slow Interpreter）無法滿足 1 秒預算，且有兩個解譯器在每秒 2 個意圖的速率下發生佇列飽和（Queue Saturation）；然而，在基準點上並未解析出慢速解譯器所造成的無線電效能損失（Radio Penalty）。

### 核心貢獻（3～5點）
- 提出並驗證 RIC 時間尺度下意圖解譯的延遲問題，比較 Jev 決策模型與生成式 LLM 在 RANIntent v1 基準測試上的表現。
- 透過閉迴路 ns-3 模擬與真實 A1/E2 路徑實驗，量化中位數解譯延遲、A1/E2 傳輸延遲，以及各模型滿足近即時預算的比例。
- 證明 Jev-1.13.0 能在 99.8% 的呼叫中滿足 1 秒近即時預算，而託管式 LLM 僅達 17.9% 與 0%。
- 分析無線網路成效：理想執行可改善受影響類別 SLA 違規率 3.96 個百分點，但 LLM 與每秒直接控制相較於傳統數值方法並無顯著優勢。
- 指出慢速解譯器會錯過控制預算並導致佇列飽和，但在基準點上尚未觀察到可解析的無線電效能損失。

### 適合對象
行動通訊與開放無線接取網路（Open RAN）研究者、近即時 RIC 與 xApp 開發者，以及對意圖驅動網路管理（Intent-based Networking）與大型語言模型在 6G 控制面應用有興趣的學術與產業界人士。

## 深度分析

#### 方法論解析

本研究圍繞「意圖解譯（Intent Interpretation）」在 O-RAN 控制迴路中的可放置性與影響，提出一套從資料集、模擬驗證到真實協定路徑量測的完整方法論。核心設計可拆解為四個層次：

1. **RANIntent v1 基準測試（RANIntent v1 Benchmark）**  
   作者建立了一個針對 A1 策略（A1 Policy）結構化的意圖資料集。每筆意圖都會對應到一組型別化策略欄位（Typed Policy Fields），包括類別（Class）、範圍（Scope）與優先權（Priority）。為了模擬真實 RAN 環境，每筆意圖附帶一張 KPM（關鍵效能量測，Key Performance Measurement）遙測表格，表格大小從 3 到 57 個基地台（cell）不等，並且以新鮮（fresh）、陳舊（stale）、雜訊（noisy）或矛盾（contradictory）四種形式呈現。標籤（label tuples）在意圖文字撰寫前即固定，並由一位獨立的盲審驗證者（blind verifier）檢查每段意圖文字是否與其 21-cell 新鮮遙測一致。這種設計確保了語義與策略欄位之間的對應關係可被客觀驗證，避免生成式模型以語言流暢度掩蓋結構錯誤。

2. **O-RAN 對齊的閉迴路評估（O-RAN-aligned Closed-loop Evaluation）**  
   研究使用 ns-3 搭配 5G-LENA 模擬一個 21-cell 的 New Radio（NR）網路，使用者設備（UE）會移動並在不同基地台間進行交遞（Handover）。控制路徑模擬 O-RAN 的 A1 與 E2 介面語義，並將每個解譯器的實際延遲與策略注入模擬中。為了分離「延遲」與「正確性」對無線電效能的影響，作者設計了三條實驗臂（arms）：
   - **L 臂（Latency-only arm）**：只考慮解譯延遲，策略視為正確，觀察延遲對無線電結果（Radio Outcome）的影響。
   - **A 臂（Accuracy-only arm）**：忽略延遲，只觀察策略錯誤的影響。
   - **N 臂（Net arm）**：同時納入真實延遲與真實策略錯誤，反映完整閉迴路表現。
   評估指標涵蓋受影響類別（Affected Class）與全網的 SLA 違規（SLA Violation）、基地台邊緣吞吐量（cell-edge throughput）、交遞表現，以及陳舊策略暴露（stale-policy exposure）。

3. **真實協定堆疊的控制路徑量測（Real-stack Control-path Measurement）**  
   除了模擬，作者還在真實軟體無線電堆疊上進行量測，包含 srsRAN、Open5GS 與 O-RAN Software Community 的近即時 RIC（Near-RT RIC）。他們將意圖解譯結果透過真實 A1 與 E2 路徑傳送至軟體 gNB（Next-generation NodeB），並將從意圖發出到 gNB 控制確認（control acknowledgement）的端到端延遲拆解為解譯、A1 傳輸（A1 Transfer）、E2 控制（E2 Control）等階段。這讓研究能區分「解譯器本身的延遲」與「O-RAN 控制介面的固有延遲」。

4. **決策模型與託管式 LLM 的對照比較**  
   研究比較了三個決策模型（Decision Model）與三個託管式大型語言模型（Hosted LLM）：
   - 決策模型：Jev-1.13.0、SemIf-Qwen3.5-4B、AnyJev（來自 Nokia Applied Research）。
   - 託管 LLM：DeepSeek-V4.1-Flash、GLM-5.3-Flash、Qwen3.8-Flash。
   此外還使用 Qwen3.5-4B-JSON 作為生成式參考（generative reference），其與 SemIf-Qwen3.5-4B 共享權重。決策模型直接輸出離散的策略欄位與機率，而生成式 LLM 則逐詞元（Token）產生策略文字，因此兩者在延遲特性與輸出結構上有本質差異。

整體而言，這套方法論的強項在於把「自然語言意圖 → 結構化 A1 策略 → 無線電層級效能」串成可量測的因果鏈，並透過 L/A/N 三臂設計將延遲與準確度這兩個常被混為一談的因素分離。

#### 實驗數據解讀

實驗結果可從「控制時限」、「RIC 容量」、「無線電成效」與「成本」四個維度解讀：

1. **解譯延遲決定控制迴路歸屬**  
   中位數解譯延遲（Median Interpretation Latency）落在 0.286 到 2.35 秒之間，而 A1 傳輸僅 15.5–19.1 毫秒，E2 控制僅 2.4–3.1 毫秒。換言之，A1/E2 傳輸延遲相對於解譯延遲幾乎可忽略，**意圖解譯器（Interpreter）的延遲才是決定該元件能否置於近即時 RIC（Near-RT RIC）的關鍵**。Jev-1.13.0 在 99.8% 的呼叫中滿足 1 秒近即時預算（Near-real-time Budget），p99 延遲僅 0.472 秒；相較之下，GLM-5.3-Flash 僅 17.9% 的呼叫達標，Qwen3.8-Flash 則為 0%。這顯示目前主流的託管式 LLM 在本實驗設定下應歸類於非即時迴路（Non-RT Loop），而非近即時 RIC。

2. **RIC 容量與佇列飽和（Queue Saturation）**  
   在意圖到達率為 2 intents/s 時，Jev-1.13.0 最多只占用 14.9% 的解譯槽位，而 AnyJev-L0 與 Qwen3.8-Flash 則超過滿載，其 p95 佇列等待時間分別達到 34.5 秒與 20.3 秒。這說明慢速解譯器（Slow Interpreter）不僅單次呼叫超時，還會因佇列累積而產生級聯延遲，進一步侵蝕控制截止時間（Control Deadline）。對於需要頻繁調整策略的場景（例如行動邊緣運算，Mobile Edge Computing 中的動態負載平衡），LLM 的吞吐量會成為 RIC 容量（RIC Capacity）的瓶頸。

3. **無線電條件的主導性大於解譯器選擇**  
   在 21-cell 閉迴路中，UE 速度與意圖到達率可使受影響類別的 SLA 違規變化高達 17 個百分點（pp），而「理想執行（Ideal Enforcement）」相對於未更新（No Update）的基準點（Base Point）僅能改善 3.96 pp。更重要的是，**沒有任何託管 LLM 在基準點上顯示出相對於 Jev-1.13.0 的可解析提升（Resolved Increase）**，且解譯器選擇所造成的無線電效能損失（Radio Penalty）在統計上無法被解析。這意味著：在當前實驗條件下，LLM 可能帶來的準確度優勢並未轉化為可測量的無線電增益，而其高延遲卻確實造成控制時限風險。

4. **每秒直接控制並未帶來額外 SLA 增益**  
   研究還測試讓解譯器每秒直接輸出每基地台控制（Per-cell Control），結果顯示相較於「策略解譯 + 數值型 xApp（Numerical xApp）」的分工模式，並沒有可解析的 SLA 降低；28 組對比中甚至有 5 組出現可解析的惡化。這支持了研究的核心主張：在意圖變化相對緩慢、無線電狀態快速變化的場景中，應由決策模型負責一次性意圖解譯，再由數值型控制器追蹤無線電狀態（Radio State），而非讓 LLM 頻繁介入即時控制。

5. **準確度必須在時限內評估**  
   在 57-cell 表格上，GLM-5.3-Flash 與 DeepSeek-V4.1-Flash 的準確度分別達到 0.967 與 0.960，高於 Jev-1.13.0 的 0.907，但兩者與 Jev 的成對差異都未被解析。更關鍵的是，GLM-5.3-Flash 僅有 17.9% 的呼叫能在 1 秒內完成，因此其高準確度在大多數近即時控制機會中無法被利用。從成本角度看，在該表格大小下，Jev-1.13.0 是每 1,000 筆正確策略最便宜的託管解譯器，約 0.207 USD。這凸顯了「截止時間內的正確率」才是實際部署應優化的指標，而非單純的離線準確度。

總結來說，數據描繪出一個清晰的權衡：決策模型（特別是 Jev-1.13.0）在延遲、容量與成本上佔優，而託管 LLM 雖在大型表格上展現較高離線準確度，但其延遲與佇列行為使其難以勝任近即時 RIC 中的意圖解譯角色。

#### 與現有研究的比較

本研究在 Intent-based Open RAN 的文獻中填補了幾個重要缺口，與現有研究的差異可從以下面向說明：

1. **從「功能展示」到「控制迴路可放置性」**  
   過去研究如 A1gent、CAIF、ORION 等主要展示 LLM 代理（LLM Agent）能將營運商目標（Operator Goal）轉譯為 A1 策略或切片 API 呼叫，並在模擬中驗證吞吐量與交遞時間。然而，這些研究多半將解譯器置於非即時 rApp，鮮少嚴格量測其是否滿足近即時 RIC 的 1 秒預算。本研究則明確比較了解譯器置於 rApp（模式 P-T 與 E）與置於 near-RT RIC（模式 X）的差異，並以實際延遲分佈（Latency Distribution）論證多數託管 LLM 應留在非即時迴路。

2. **延遲與準確度的分離量測**  
   現有 LLM 代理研究常將端到端延遲歸因於 LLM 呼叫（如 CAIF 單次意圖需 11.8 秒、ORION 將大部分延遲歸因於 LLM），但較少進一步區分「解譯延遲」、「A1 傳輸」與「E2 控制」。本研究透過真實 srsRAN/Open5GS/O-RAN SC 堆疊，將路徑延遲拆解，並以 L/A/N 三臂設計分離延遲與錯誤的影響，這在現有文獻中較為少見。

3. **決策模型作為 LLM 的結構化替代方案**  
   相較於純生成式 LLM，Jev-1.13.0 與 AnyJev 這類決策模型直接輸出型別化策略欄位，天然具備結構正確性與低延遲。SemIf-Qwen3.5-4B 則介於兩者之間，將開放 LLM 轉換為決策模型。這與 Li et al. 在邊緣服務准許（service admission）中使用決策模型的方向一致，但本研究將其擴展到完整的 O-RAN 控制迴路，並與多個託管 LLM 進行系統性比較。

4. **對「LLM 萬能論」的實證修正**  
   部分近期研究讓 LLM 代理透過 NETCONF 調整發射功率、部署 xApp 管線，或協調多代理系統，隱含假設 LLM 可直接參與即時控制。本研究則以數據指出：在基準點上，LLM 相對於決策模型並未帶來可解析的無線電增益，且每秒直接控制也無法超越「策略 + 數值型 xApp」的分工。這提醒後續研究不能僅以離線準確度或功能正確性評估 LLM，而必須將控制截止時間納入設計。

5. **局限與適用範圍**  
   本研究主要聚焦於「調整服務類別優先權」這類結構相對簡單的 A1 策略，對於需要複雜推理、多步規劃或多代理協調的意圖（例如跨切片資源協商、故障根因分析），LLM 的優勢可能更難被決策模型取代。此外，實驗中的 LLM 均為託管式 API，未包含在地端最佳化後的輕量模型，這可能低估 LLM 在延遲上的潛力。

#### 可重現性評估

可重現性是本研究能否被社群採納的關鍵。根據提供的上下文，可從以下面向評估：

1. **模擬與軟體堆疊的開放性**  
   研究使用 ns-3 與 5G-LENA 進行閉迴路模擬，這兩者皆為開源工具；真實協定路徑量測則使用 srsRAN、Open5GS 與 O-RAN Software Community 的近即時 RIC，這些也都是公開可取得的開源專案。因此，模擬環境與控制協定堆疊原則上可被其他研究者重建。

2. **RANIntent v1 資料集與模型權重**  
   RANIntent v1 benchmark 是本研究的核心貢獻之一，但根據目前提供的資訊，無法確認該資料集、標籤生成流程與盲審驗證腳本是否已公開釋出。Jev-1.13.0 與 AnyJev 來自 Nokia Applied Research，SemIf-Qwen3.5-4B 與 Qwen3.5-4B-JSON 的權重可能受限於模型授權或商業協議；託管 LLM（DeepSeek、GLM、Qwen）雖可透過 API 呼叫，但不同時間點的模型版本與延遲可能變動，這會影響實驗的可重複性。

3. **延遲量測的再現性**  
   真實 A1/E2 路徑的延遲會受到網路拓撲、容器資源配置、RIC 實作版本與 gNB 軟體版本的影響。作者雖然提供了中位數與百分位數，但若未公開完整的部署拓撲與資源配置，其他團隊難以完全複製相同的絕對數值。不過，相對趨勢（Jev 遠快於託管 LLM）具有較高的可轉移性。

4. **建議的再現條件**  
   為提升可重現性，建議作者釋出：
   - RANIntent v1 的意圖文字、KPM 表格與標準答案；
   - 用於產生意圖與驗證標籤的腳本；
   - ns-3 模擬場景的設定檔與事件追蹤；
   - 真實堆疊的部署版本與資源配置（例如 CPU、記憶體、容器映像檔版本）；
   - 各解譯器的 API 呼叫參數（溫度、最大詞元數、提示模板等）。

整體而言，本研究在方法論與工具鏈上具備良好的開放基礎，但資料集與部分模型權重的公開程度，將是決定其能否被大規模複現的關鍵。

#### 未來研究方向

基於本研究的發現，以下幾個方向值得後續深入探索：

1. **截止時間感知（Deadline-aware）的 LLM 解譯器**  
   未來可研究如何在 LLM 推論過程中引入早期停止（early stopping）、自適應解碼長度或分層推理機制，使模型在 1 秒預算內優先輸出高信心度的策略欄位，並在時間允許時才進行精細推理。這類「 anytime inference 」機制可能讓 LLM 同時兼顧準確度與時限。

2. **決策模型與 LLM 的混合架構**  
   可設計一種分層解譯器：由輕量決策模型（如 Jev）負責常見、低延遲的近即時決策，僅在語義模糊、需要複雜推理或出現未見過的意圖模式時，才將請求轉交給 LLM。這種「快速路徑 + 慢速後備」的設計可能同時提升 RIC 容量與處理彈性。

3. **在地端輕量 LLM 與推論加速**  
   本研究的 LLM 均為遠端託管 API，未來可在近即時 RIC 內部署量化（quantized）或蒸餾（distilled）後的輕量模型，並結合推測解碼（speculative decoding）、KV-cache 快取與批次處理（batching）等技術，評估其是否能將 p99 延遲壓低至 1 秒以內。

4. **佇列管理與准入控制（Admission Control）**  
   當意圖到達率超過解譯器處理能力時，RIC 需要智慧化的佇列排程與丟棄策略。未來可研究如何根據意圖緊急程度、預估解譯時間與無線電狀態，動態決定哪些意圖應被優先處理或延後至非即時迴路。

5. **更廣泛的 A1 策略空間與多意圖衝突**  
   本研究聚焦於單一類別優先權調整。未來可將 RANIntent 擴展到切片配置、節能、負載平衡、移動性管理等更複雜的策略欄位，並研究多個同時到達意圖之間的衝突偵測與協調機制。

6. **真實 gNB 與現場網路驗證**  
   雖然本研究已在軟體 gNB 上量測真實 A1/E2 路徑，但未來可在商業化 gNB 或戶外測試場中驗證，特別是在高速移動、密集交遞與高負載情境下，解譯延遲對 SLA 違規的實際影響。

7. **6G AI-native 控制架構的標準化意涵**  
   隨著 IMT-2030 將 AI 與通訊列為使用情境（Usage Scenario），本研究的結論可為 6G 標準化提供參考：例如定義近即時 RIC 中解譯器的最大延遲要求、A1 策略結構的複雜度上限，以及非即時 rApp 與近即時 xApp 之間的功能切分原則。

總結而言，本研究為 Intent-based Open RAN 的解譯器選型提供了嚴謹的實證基礎，未來工作可在保持低延遲優勢的同時，逐步釋放 LLM 在複雜語義理解上的潛力，並推動相關標準與開源工具的成熟。

## 論文問答

**【背景與動機】**

**Q1：這篇論文主要想解決什麼問題？**
A：這篇論文聚焦於基於意圖的開放式 RAN（Intent-based Open RAN）中，如何將自然語言意圖即時轉換為 A1 策略並納入 RAN 智慧控制器（RIC）的控制迴路。由於無線電排程會在意圖解譯期間持續運作，解譯器產生的任何延遲都會壓縮到實際可用於改善服務等級協定（SLA）的時間預算。研究核心在於評估生成式大型語言模型（LLM）相較於 Jev 這類決策模型，是否會因為額外的逐詞元生成延遲而錯過控制截止時間、耗盡 RIC 容量，或最終損害無線電效能。

**Q2：為什麼現有的 LLM 意圖解譯方法難以滿足近即時 RIC 的需求？**
A：現有 LLM 代理通常採用生成式模型，必須逐詞元（token by token）產出策略文字，導致單次意圖解譯的延遲達到數秒等級，例如 CAIF 報告單次意圖需 11.8 秒，ORION 的端到端延遲也主要來自 LLM。這樣的秒級延遲本質上屬於非即時（non-RT）迴路，無法符合近即時 RIC 通常要求的 1 秒預算。相較之下，Jev 等決策模型直接輸出型別化策略欄位，能將中位數延遲壓在數百毫秒內，因此更適合部署在近即時迴路。

**Q3：為什麼把解譯器放在正確的 RIC 迴路中如此重要？**
A：因為基地台排程器（gNB scheduler）在意圖到達前仍會持續使用舊的類別權重服務受影響類別的流量，解譯等待時間與無線電傳遞時間共享同一個 SLA 延遲預算。如果解譯器太慢，新策略抵達排程器時，受影響的使用者設備（UE）可能已經錯過了改善服務品質的關鍵時機。因此，解譯器必須在時限內完成解譯並透過 A1/E2 路徑下發，否則即使策略正確也無法轉化為可解析的無線電成效提升。

**【方法與創新】**

**Q4：本研究的核心方法與評估框架是什麼？**
A：作者建構了 RANIntent v1 基準測試，將營運商與租戶意圖對應到 A1 策略的各個型別化欄位，並搭配 3 到 57 個基地台的 KPM 遙測表格。接著在 ns-3 與 5G-LENA 中建立 21 細胞閉迴路模擬，同時也在真實的 A1 與 E2 路徑上進行軟體基地台測試。實驗比較了三種決策模型（Jev-1.13.0、SemIf-Qwen3.5-4B、AnyJev）與三種託管式 LLM（DeepSeek-V4.1-Flash、GLM-5.3-Flash、Qwen3.8-Flash），並透過延遲-only（L）、準確率-only（A）與網路綜合（N）三種實驗臂來分離延遲與策略錯誤的影響。

**Q5：本研究有哪些關鍵創新貢獻？**
A：第一，RANIntent v1 提供了帶有標籤、並在 fresh、stale、noisy、contradictory 四種遙測狀態下評測的意圖解譯基準。第二，研究設計了與 O-RAN 對齊的閉迴路評估，能同時觀察解譯延遲與策略準確度對 SLA、細胞邊緣吞吐量與交遞的影響。第三，作者在真實 A1/E2 軟體堆疊上分解了從意圖發出到基地台控制確認的完整路徑延遲，並首次系統性地比較了決策模型與託管 LLM 在 RIC 迴路中的可部署性。

**Q6：研究中做了哪些重要設計選擇，理由是什麼？**
A：作者選擇讓決策模型直接輸出型別化策略欄位，而讓生成式 LLM 逐詞元產出策略，以凸顯兩者在延遲與輸出結構上的根本差異。在部署位置上，研究比較了在 rApp 中解譯後經 A1 下發（P-T 與 E 模式）與在近即時 RIC 中直接解譯（X 模式）的差異，強調解譯器位置決定了它適合哪個控制迴路。此外，研究將「一次性意圖解譯」與「每秒追蹤無線電狀態的數值型 xApp」分開，避免把無線電狀態追蹤的責任錯誤地交給解譯器。

**【實驗與結果】**

**Q7：實驗使用了哪些基準測試與評估指標？**
A：主要基準是 RANIntent v1，評測指標包括解譯延遲分佈（中位數、p99）、1 秒近即時預算達成率、A1 與 E2 傳輸延遲、策略準確率，以及閉迴路無線電指標。無線電指標涵蓋受影響類別與全網 SLA 違規比例、細胞邊緣吞吐量、交遞表現，以及舊策略暴露時間（stale-policy exposure）。此外，研究也計算了每 1,000 筆正確策略的託管成本，以協助營運商評估經濟可行性。

**Q8：實驗有哪些關鍵發現？**
A：Jev-1.13.0 的中位數解譯延遲僅約 0.286 秒，p99 為 0.472 秒，能在 99.8% 的呼叫中滿足 1 秒近即時預算；相對地，託管 LLM 的中位數延遲介於 0.286 到 2.35 秒之間，GLM-5.3-Flash 只有 17.9% 的呼叫達標，Qwen3.8-Flash 則完全無法達標。在無線電網路中，理想執行（ideal enforcement）能將受影響類別的 SLA 違規相較於未更新基準點改善 3.96 個百分點，但在該基準點上沒有任何託管 LLM 展現出相對於 Jev-1.13.0 可解析的成效提升。

**Q9：研究進行了哪些消融或額外分析？**
A：研究透過 L、A、N 三種實驗臂分離「純延遲效應」與「純策略錯誤效應」，發現無線電條件（UE 速度與意圖速率）對受影響類別 SLA 違規的影響可高達 17 個百分點，遠大於解譯器選擇的影響。在 RIC 容量分析中，Jev-1.13.0 在意圖速率為 2 intents/s 時最多只占用 14.9% 的解譯槽位，而 AnyJev-L0 與 Qwen3.8-Flash 則會超過滿載，p95 佇列等待時間分別達到 34.5 秒與 20.3 秒。此外，每秒直接由解譯器發出控制指令並未相較於「策略＋xApp」拆分帶來可解析的 SLA 降低，甚至在 28 組對比中有五組出現可解析的惡化。

**【應用與影響】**

**Q10：在實務部署中，Jev 與 LLM 分別適合哪些場景？**
A：Jev-1.13.0 適合部署在近即時 RIC 內部，處理需要在一秒內完成意圖解譯並下發的動態無線電控制場景，例如即時調整某類服務的優先權或回復預設策略。託管 LLM 由於延遲較高，較適合放在非即時 rApp 中執行較慢速的策略規劃、營運商意圖的初步轉譯，或需要人類在迴路中確認的任務。若未來 LLM 延遲能顯著降低，則可進一步評估其是否適合進入近即時迴路。

**Q11：營運商在選擇與部署意圖解譯器時應考慮哪些產品層面因素？**
A：首先必須確認解譯器的延遲分佈是否能滿足目標控制迴路的截止時間，因為即使離線準確率很高，無法在時限內產出策略就等於無效。其次要評估 RIC 容量與佇列行為，避免在高意圖到達率下發生佇列飽和，導致控制指令積壓。最後也應考量成本，例如在本研究的 57 細胞表格上，Jev-1.13.0 是每 1,000 筆正確策略最便宜的託管解譯器，約 0.207 美元，這對大規模部署的總擁有成本影響顯著。

**Q12：這項研究對 6G Open RAN 的實際影響是什麼？**
A：研究明確指出解譯器的延遲與部署位置會決定它屬於近即時還是非即時迴路，為 6G Open RAN 的意圖驅動控制提供了具體的設計準則。它也提醒產業界，無線電條件往往比解譯器選擇更能決定最終 SLA 表現，因此不應單純以離線準確率選型。整體而言，這項工作有助於營運商在導入 AI 解譯器時，兼顧控制時限、RIC 容量與無線電成效，避免將不適合的模型錯置到關鍵控制路徑。

**【限制與未來方向】**

**Q13：本研究有哪些已承認的限制？**
A：研究目前只針對一種 A1 策略綱要進行評估，尚未涵蓋更複雜或多樣的意圖類型與策略欄位。真實堆疊測試使用的是軟體基地台，雖然能精確分解 A1/E2 路徑延遲，但與商用硬體基地台的絕對數值可能仍有差異。此外，託管 LLM 的延遲與成本會隨供應商、區域與模型版本變動，實驗結果反映的是特定時間點的服務表現。

**Q14：研究中觀察到哪些失敗或不利案例？**
A：最明顯的失敗案例是慢速解譯器無法在 1 秒內完成解譯，導致大量呼叫錯過近即時預算；在 2 intents/s 的負載下，AnyJev-L0 與 Qwen3.8-Flash 的解譯佇列甚至會飽和。另一個不利發現是每秒直接由解譯器進行每細胞控制，並未帶來可解析的 SLA 改善，反而在部分對比中出現可解析的惡化，顯示將無線電狀態追蹤交給數值型 xApp 更為穩健。此外，當 KPM 遙測處於 stale、noisy 或 contradictory 狀態時，解譯準確率也可能下降，進一步影響控制成效。

**Q15：未來可以朝哪些方向延伸這項研究？**
A：未來可探索模型量化、推論快取、推測解碼（speculative decoding）或更小的本地部署 LLM，以縮短生成式模型的延遲並評估其是否可進入近即時迴路。另一個方向是結合 LLM 的語意彈性與決策模型的低延遲，例如讓 LLM 負責離線意圖理解與策略模板生成，再由決策模型在即時路徑中快速選擇欄位數值。此外，也可擴展到更多 A1 策略綱要、真實商用基地台，以及加入線上適應、安全夾制（safety clamps）與多意圖協調機制，使意圖驅動的 Open RAN 控制更加可靠。

## 實務應用指南

### 適用場景

1. **企業專網與 VIP 用戶的動態 QoS 調整**  
   當園區或體育場等場域出現臨時性高優先級業務（例如 AR/VR 導覽、直播回傳）時，營運商可透過自然語言意圖（如「提升金牌企業用戶的優先權」）觸發 Jev 決策模型，在近即時 RIC（near-RT RIC）內於 1 秒預算內產生 A1 策略，再由 xApp 經 E2 介面調整 gNB 排程權重。

2. **緊急服務與公共安全優先化**  
   救災或大型活動期間，指揮中心需要快速將特定服務類別（affected class）提升優先順序。由於控制截止時間（control deadline）嚴格，應採用 Jev-1.13.0 這類低延遲解譯器，避免託管式 LLM 的秒級延遲導致 SLA 違規。

3. **網路切片的租户自助式策略下達**  
   垂直行業租户透過 BSS/OSS 入口輸入意圖（例如「在尖峰時段保障切片 A 的吞吐量」）。對於需要近即時反應的切片，建議將解譯器放在 near-RT RIC；若為日常組態變更，可將 LLM 放在非即時迴路（non-RT loop）的 rApp，經 A1 下發策略。

4. **節能與負載平衡策略自動化**  
   當網路負載下降時，營運商可下達「降低某類背景流量的優先權並恢復預設策略」等意圖。透過 policy-and-xApp 的分工，由解譯器輸出類別策略（class policy），再由數值型 xApp 持續追蹤無線電狀態（radio state），避免每秒呼叫解譯器造成佇列飽和。

5. **SLA 違規後的自動復原**  
   當 KPM 報告顯示某類別 SLA 違規上升時，閉迴路系統可自動發出意圖。由於論文發現無線電條件（UE 速度、意圖速率）對 SLA 的影響遠大於解譯器選擇，實作時應優先確保策略能及時送達排程器，而非過度追求解譯器的複雜度。

### 實作前置條件

- **資料準備**  
  - 需要結構化的意圖語料與對應的 A1 策略欄位標籤，可參考 RANIntent v1 基準測試的設計：每個意圖搭配 3–57 個基地台的 KPM 表格，並涵蓋新鮮（fresh）、過時（stale）、雜訊（noisy）與矛盾（contradictory）等情境。  
  - 必須有真實或模擬的無線電遙測資料，包括每細胞負載（cell load）、吞吐量、交遞（handover）紀錄與 SLA 狀態。

- **運算與基礎設施**  
  - 可部署 near-RT RIC 的環境（如 O-RAN Software Community RIC），並具備 A1 Mediator 與 E2 介面連線能力。  
  - 若採用 Jev-1.13.0 或 AnyJev，需要可託管的推論節點；若採用託管式 LLM，則需評估網路往返延遲與 API 成本。  
  - 建議具備 ns-3 / 5G-LENA 閉迴路模擬環境，以及 srsRAN + Open5GS 的真實協定堆疊測試床。

- **技能需求**  
  - O-RAN 架構與 A1/E2 介面知識。  
  - 自然語言處理與決策模型部署經驗（特別是型別化策略欄位輸出與 JSON schema 驗證）。  
  - RAN 工程背景，能理解排程器權重、KPM 報告與 SLA 指標之間的關聯。  
  - MLOps/DevOps 能力，用於監控延遲分佈、佇列長度與模型版本管理。

### 實作步驟建議

1. **定義策略綱要與意圖分類**  
   先確定 A1 policy schema 的欄位（class、scope、priority 等），並將營運商常見意圖對應到這些型別化策略欄位。此步驟決定了解譯器輸出的結構，也影響後續驗證方式。

2. **建立標註資料集與基準測試**  
   參考 RANIntent v1 的做法：先固定標籤組合，再撰寫自然語言意圖文字，並由獨立驗證者檢查文字與 21 細胞新鮮遙測的一致性。建議同時建立延遲基準（latency-only arm L）、準確度基準（accuracy-only arm A）與網路成效基準（net arm N）。

3. **選擇解譯器與部署位置**  
   - 若目標是近即時控制（<1 s），優先評估 Jev-1.13.0 或 AnyJev，並部署於 near-RT RIC（mode X）。  
   - 若意圖變更頻率低且可容忍數秒延遲，可將 LLM 放在 rApp（mode E），經 A1 下發策略。  
   - 避免在 near-RT 迴路中直接使用高延遲的託管式 LLM。

4. **整合 A1/E2 控制路徑**  
   將解譯器輸出接至 A1 Mediator，再由 xApp 透過 E2 介面控制 gNB 排程器。論文顯示 A1 傳輸約 15.5–19.1 ms、E2 控制約 2.4–3.1 ms，因此控制路徑本身不是瓶頸，解譯延遲才是。

5. **實作逾時、降級與夾制機制**  
   設定 1 秒逾時；若解譯器未在時限內回傳，則沿用上一筆有效策略或回復預設策略。同時對 A1 策略欄位進行 schema 驗證與數值夾制（clamp），避免錯誤輸出直接影響無線電排程。

6. **閉迴路模擬驗證**  
   在 ns-3 / 5G-LENA 中模擬 21 細胞、移動 UE 與交遞情境，比較「理想執行（ideal enforcement）」「未更新（no update）」與各解譯器的實際延遲/錯誤組合，觀察受影響類別的 SLA 違規變化。

7. **真實堆疊試點與上線監控**  
   在 srsRAN + Open5GS + near-RT RIC 的真實路徑上測量從意圖發出到 gNB 控制確認的端到端延遲。上線後持續監控：中位數與 p99 解譯延遲、佇列等待時間、佇列飽和率、每秒意圖處理量，以及 SLA 違規趨勢。

### 潛在風險與注意事項

- **延遲超過控制截止時間**  
  託管式 LLM 的中位數解譯延遲可達 0.286–2.35 s，部分模型甚至 0% 滿足 1 秒預算。若將其置於 near-RT RIC，會導致策略過時（stale-policy exposure），在 UE 交遞或負載快速變化時錯失控制時機。  
  **因應**：近即時場景使用 Jev 決策模型；LLM 僅用於非即時規劃或輔助生成意圖草稿。

- **高意圖速率下的佇列飽和**  
  論文指出在 2 intents/s 時，部分慢速解譯器會達到滿載利用，p95 佇列等待時間可達 20–34 秒。  
  **因應**：對意圖發送速率進行限流與合併；評估解譯器在預期負載下的佇列行為，而非僅看單次延遲。

- **準確度與延遲的權衡**  
  在 57 細胞表格上，部分 LLM 的準確率可達 0.960–0.967，高於 Jev-1.13.0 的 0.907，但這些差異在統計上未被解析（not resolved），且 LLM 僅 17.9% 滿足近即時預算。  
  **因應**：以「在截止時間內的正確策略數量」作為主要指標，而非單純比較離線準確率。

- **直接控制的誤用**  
  每秒由解譯器直接發出每細胞控制指令，並未帶來相對於「策略 + 數值型 xApp」的解析化 SLA 改善，反而增加解譯負載。  
  **因應**：讓解譯器輸出高階類別策略，由 xApp 負責追蹤無線電狀態與細胞層級調整。

- **成本與供應商鎖定**  
  託管式 LLM 的單次呼叫成本與延遲會隨表格大小與輸出長度增加。  
  **因應**：在設計階段估算每 1,000 筆正確策略的成本，並保留可切換至本地決策模型的退路。

- **安全性與輸出驗證**  
  LLM 可能產生不符合 schema 或超出安全範圍的數值。  
  **因應**：所有輸出必須經過 schema 驗證、數值夾制與營運規則檢查，才能送往 A1/E2。

### 與其他技術的整合建議

- **O-RAN SMO / rApp**  
  將 LLM 或非頻繁的意圖解譯放在非即時迴路的 rApp，負責長期策略規劃與意圖草稿生成，再經 A1 介面下發至 near-RT RIC。

- **A1 Mediator 與 E2 xApp**  
  解譯器輸出應以標準 A1 policy 格式傳遞，由 A1 Mediator 路由至對應 xApp；xApp 再透過 E2 介面將類別權重寫入 gNB 排程器。此分工可讓解譯器專注於意圖到策略的映射，xApp 專注於無線電狀態追蹤。

- **KPM 收集與數位孿生**  
  將真實網路的 KPM 報告餵入解譯器作為上下文，並在數位孿生環境中重放不同延遲與錯誤組合，預測對 SLA 的影響。

- **BSS/OSS 與意圖入口**  
  在前端入口提供自然語言輸入，但背後將常見意圖範本化，減少解譯器負擔並提升輸出穩定性。

- **MLOps 監控平台**  
  整合模型延遲、佇列長度、schema 驗證失敗率、SLA 違規與成本等指標，建立自動告警與模型切換機制。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先掌握本文附錄的詞彙對照表，理解「意圖」「A1 策略」「near-RT RIC」「xApp」等核心概念，再閱讀「適用場景」與「潛在風險」兩節，建立「為什麼解譯延遲會影響無線網路」的直覺，最後再回頭看論文中的延遲數據。

- **AI 工程師**  
  請重點關注解譯器的延遲分佈、Jev 決策模型與 LLM 的輸出方式差異，以及「在截止時間內的正確策略數量」這項綜合指標。實作時請特別注意 schema 驗證、佇列飽和與逾時降級機制，並將 LLM 視為非即時元件而非 near-RT 控制核心。

- **研究人員**  
  建議深入分析 RANIntent v1 的基準設計、L/A/N 三種評估臂（arm）的分離邏輯，以及「resolved increase」這類統計判斷標準。可進一步探討在更大規模網路、更高意圖速率或更複雜策略綱要下，決策模型與生成式 LLM 的延遲—準確度權衡曲線。

- **產品經理**  
  請聚焦於 SLA 違規、成本與部署模式的商業意涵：Jev-1.13.0 能以低成本滿足近即時預算，適合需要快速反應的場景；LLM 雖然準確率數字較高，但延遲與佇列飽和問題使其更適合 rApp 層級的規劃工具。決策時應以「端到端 SLA 改善」與「每千筆正確策略成本」作為主要評估維度。
