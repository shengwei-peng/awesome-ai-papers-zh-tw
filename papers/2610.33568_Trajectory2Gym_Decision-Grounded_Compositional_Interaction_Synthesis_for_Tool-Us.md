Trajectory2Gym 的核心論點在於重新定義「軌跡監督」的意義：成功的軌跡（successful trajectories）並不等於有用的監督（useful supervision）。論文提出兩個耦合的需求——**組合覆蓋率**（compositional coverage）與**決策可依據性**（decision grounding），並以此為基礎設計三階段框架。

**第一階段：組合式互動合成（Compositional Interaction Synthesis）**

此階段針對「組合覆蓋率」挑戰。論文中指出，在 34,772 個已認證候選項（certified candidates）中，40.9% 僅包含至多兩個監督決策，僅 10.0% 包含真實錯誤（authentic error）之後的認證決策。這意味著既有資料池嚴重缺乏跨步驟相依性（cross-step dependencies）的展示。合成階段並非隨機生成任務，而是圍繞「支援不足的組合結構」（under-supported compositional structures）建構並執行任務，使資訊獲取（information acquisition）與錯誤恢復（recovery）能被示範。具體而言，系統在原生環境（native environments）中建構可執行的互動（executable interactions），確保觀察、使用者更新、狀態變更等元素能決定後續決策。

**第二階段：可依據的監督（Grounded Supervision）**

此階段針對「決策可依據性」挑戰。論文以圖一的 Tau2 Retail 案例說明：API 執行成功並不能保證動作的正確性——一個使用過時識別碼的兩品項交換（stale two-item exchange）與最終使用者請求的僅檯燈交換（lamp-only exchange）同樣會被原生工具回放接受。監督遮罩（supervision mask）僅保留由可見證據、執行結果與工作流程順序所認證的決策，並將真實錯誤保留為恢復情境（recovery context）。此機制將「每個動作是否可從學習者可見的互動歷史（learner-visible interaction history）佐證」作為監督取捨的標準。

**第三階段：結構性支援學習（Structural-Support Learning）**

此階段包含兩個耦合機制：**結構性支援選擇**（structural-support selection）以每個規模的支援深度（per-scale support depth）分配軌跡，確保能力路徑（capability paths）被覆蓋；**父項歸一化監督式微調**（parent-normalized supervised fine-tuning）則將語意互動（semantic interaction）作為訓練權重單位（unit of training weight），避免子動作被獨立加權而破壞組合語意。

三階段的耦合關係是論文的關鍵設計：合成而無可依據性會教導收集器的捷徑；可依據性而無合成則認證一個恢復與探索稀少的資料池；選擇而無前兩者僅是重新加權既有資料池。這種耦合設計使得整體框架並非單純的資料增強或篩選，而是一種「刻意建構可學習的互動經驗（deliberate construction of learnable interaction experience）」。

### 實作步驟建議

**第一步：盤點現有軌跡池的組合覆蓋率**
統計目前資料池中每段軌跡的「已認證決策數」分佈，識別支援不足的結構（例如：少於 3 個監督決策的軌跡佔比、認證錯誤後的恢復動作佔比）。這對應論文的 Challenge 1。

**第二步：建立可執行的原生環境**
確保每個工具呼叫都能在受控環境中重現並回傳真實結果。沒有可重現的執行環境，就無法進行「決策可依據性」的認證。

**第三步：合成組合互動**
針對支援不足的結構，主動建構任務並在原生環境中執行。例如：刻意製造「查詢失敗 → 取得替代資訊 → 重試」的路徑，或「使用者中途變更請求 → 代理人調整後續動作」的情境。這對應論文的 Stage 1。

**第四步：建立決策可依據性認證機制**
對每個候選動作，檢查其引數與目標是否可由「截至該步驟為止、代理人可見的歷史」佐證。通過認證的動作進入訓練集，未通過的捨棄（但保留其作為「恢復上下文」）。這對應論文的 Stage 2。

**第五步：結構性支援選擇**
依模型規模設定支援深度閾值，優先選用能覆蓋更多能力路徑的軌跡。避免小規模模型被過深的組合軌跡淹沒，也避免大規模模型只學到淺層互動。

**第六步：父項歸一化監督式微調**
以「語意互動作為訓練權重單位」進行 SFT，而非以個別動作為單位。這能避免「一段長軌跡中只有少數動作錯誤，卻被當作完整正樣本」的問題。

**第七步：分尺度評估**
在 Tau1、Tau2、BFCL（或自有的領域基準）上評估每個規模的表現，特別關注「有狀態」與「多輪」場景的提升幅度。

### 潛在風險與注意事項

**風險一：原生環境重現成本高**
若工具涉及外部副作用（真實下單、實際扣款），無法在訓練環境中重現，決策可依據性認證就無從執行。
**緩解**：建立沙盒化的環境鏡像，或使用 mock 服務搭配狀態追蹤。

**風險二：認證機制過於嚴格導致資料量萎縮**
若可依據性標準過嚴，可能篩掉大量可用軌跡，使訓練資料不足以支撐目標規模。
**緩解**：分階段放寬標準，先以「寬鬆可依據性」訓練，再用「嚴格可依據性」做第二輪微調；或參考論文的「保留真實錯誤作為恢復上下文」做法。

**風險三：結構性支援選擇引入選擇偏差**
若能力路徑定義本身偏頗（例如過度強調「查詢失敗恢復」而忽略「並行請求處理」），選擇機制會放大這個偏差。
**緩解**：以領域專家審核能力路徑清單，並定期以基準表現回頭檢驗選擇分佈。

**風險四：父項歸一化可能稀釋強監督訊號**
若一段互動中只有少數關鍵動作是正確的，整段被當作一個訓練樣本時，正確動作的權重會被稀釋。
**緩解**：論文的做法是「保留語意互動作為權重單位」，但內部仍對每個動作套用決策可依據性遮罩；實作時需確認遮罩與權重的對應關係正確。

**風險五：基準表現提升不等於真實部署表現**
Tau1、Tau2、BFCL 都是有狀態、多輪的合成基準，與真實業務流程仍有落差。
**緩解**：在自有領域的「影子模式」（shadow mode）中以人類專家標註做額外評估。

### 與其他技術的整合建議

**與既有 agent framework 整合**
Trajectory2Gym 的三個階段可作為「資料準備層」插入 LangChain、AutoGen、Claude Agent SDK 等框架的下游。具體做法：在框架產生候選軌跡後，接上「組合互動合成器」與「決策可依據性認證器」，再進入 SFT 流程。

**與 MCP（Model Context Protocol）生態系整合**
論文中提到 MCP 生態系是相關工作之一。Trajectory2Gym 的原生環境執行假設與 MCP 的工具抽象層相容，可將 MCP 工具定義直接作為「可重現環境」的基礎，省去自建沙盒的成本。

**與強化學習（RL）整合**
Trajectory2Gym 產出的「已認證軌跡」可作為 RL 的初始策略（behavior policy）或獎勵塑形（reward shaping）的參考。特別是「保留真實錯誤作為恢復上下文」的做法，可直接轉化為 RL 中的「負向樣本 + 恢復示範」配對。

**與失敗診斷方法整合**
論文中提到的 DARC（Wang et al., 2026a）使用失敗診斷選擇恢復介入。Trajectory2Gym 的決策可依據性認證可作為 DARC 的前置篩選：先過濾掉「無法被可見歷史佐證」的動作，再對剩下的失敗進行診斷。

**與 SEAL 整合**
SEAL（Hu et al., 2026）結合診斷導向的訓練介面適應與策略更新。Trajectory2Gym 的結構性支援選擇可作為 SEAL 策略更新階段的資料來源，兩者形成「介面適應 → 軌跡篩選 → 策略更新」的串接。

**與 FACA 整合**
FACA（Zhao et al., 2026）使用下一輪使用者反應做局部信用歸屬。Trajectory2Gym 的父項歸一化 SFT 可作為 FACA 的監督基底，再以 FACA 的局部信用訊號做第二階段微調。
