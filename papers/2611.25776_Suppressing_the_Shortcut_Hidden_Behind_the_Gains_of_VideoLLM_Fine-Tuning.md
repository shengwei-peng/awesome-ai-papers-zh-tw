本文提出的核心方法 VETO（Video-Evidence Training via Orthogonal projection，透過正交投影進行的影片證據訓練）從一個根本性的觀察出發：在監督式微調（Supervised Fine-Tuning, SFT）過程中，影片大型語言模型（Video Large Language Models, VideoLLMs）會學習一條「捷徑」（shortcut），即繞過影片內容、改由文字規律性（textual regularities）來推導答案。這條捷徑在訓練分布（training distribution）內表現為準確率（accuracy）上升，但在分布偏移（distribution shift）下卻成為模型泛化（generalization）的絆腳石。

**問題定位的精妙之處**

作者並非直接攻擊資料或損失函數（loss function），而是追問「捷徑究竟在哪裡形成」。透過實驗追蹤，作者發現：
1. 無論訓練輪次（training epoch）、資料規模（data size）或骨幹網路（backbone）為何，捷徑都會形成；
2. 訓練分布內的準確率上升掩蓋了捷徑的存在；
3. 過濾（filtering）資料並無法預防捷徑的產生。

這個觀察將問題從「資料層面」轉移到「更新層面」，是方法論上的關鍵轉向。

**VETO 的技術核心**

VETO 的設計包含兩個階段：

第一階段為**子空間校準（subspace calibration）**：對每個骨幹網路（backbone）僅執行一次，從基礎模型（base model）在僅文字輸入（text-only input）下產生的激活值（activations）中，萃取出承載捷徑資訊的子空間（subspace）。這個子空間代表模型「僅憑文字就能讀取答案」的方向。

第二階段為**正交投影（orthogonal projection）**：在微調過程中，將 LoRA（Low-Rank Adaptation，低秩適應）的更新量（update）投影到該子空間的正交補空間（orthogonal complement）上。這意味著微調更新無法進入捷徑所在的特徵方向，迫使模型必須從完整輸入（full input，即影片加文字）中學習。

**方法論的優勢**

VETO 的設計具有幾個重要特性：
- **無需定義捷徑**：相較於資料過濾需要預先指定哪些規律性算作捷徑，VETO 不需要任何先驗定義；
- **不修改資料或損失**：純粹在參數更新層面介入；
- **保留基礎模型先驗**：僅約束更新方向，不影響模型原有的知識；
- **計算成本低**：每步只需一次投影運算，校準僅需執行一次。

這種「在更新層面而非資料或輸出層面介入」的思路，呼應了機器學習中對「學習動態」（learning dynamics）理解的深化，也與近期對表徵學習中虛假相關性（spurious correlation）的研究方向一致。

**現有方法的分類與局限**

作者將對抗捷徑的現有方法分為三類，並指出各自的局限：

1. **資料過濾（Data Filtering）**（Chen et al., 2020; Shvetsova et al., 2025）：需要預先定義哪些規律性算作捷徑，但微調過程中會學習到的規律性往往難以事先預知。本文實驗證明，即使過濾了「文字可解」的樣本，捷徑仍會在訓練中重新形成。

2. **損失懲罰（Loss Penalization）**（Cadene et al., 2019; Clark et al., 2019; Niu et al., 2021; Chen & Li, 2026）：透過在損失函數中加入懲罰項來抑制特定行為。但這種方法約束的是模型輸出，而非參數更新本身，因此無法從根本上阻止捷徑被「寫入」參數。

3. **後處理調整（Post-hoc Adjustment）**（Wang et al., 2024; Yang et al., 2025）：在訓練完成後調整模型或解碼（decoding）過程。這類方法屬於「症狀治療」，無法改變模型已經學到的捷徑。

**VETO 的定位突破**

VETO 的核心突破在於**介入點的選擇**：它不處理資料、不修改損失、不調整輸出，而是在參數更新形成的瞬間進行約束。這種「治本」而非「治標」的思路，與近期對學習動態、優化過程中表徵幾何的研究趨勢一致。

從理論角度，VETO 與以下研究方向有共通之處：
- **表徵工程（Representation Engineering）**：透過操控模型中間層的激活值來引導模型行為；
- **子空間干預（Subspace Intervention）**：在特定特徵方向上進行投影以控制模型屬性；
- **LoRA 變體**：如 LoRA+、DoRA 等對 LoRA 更新結構的改進。

**相較於這些方法，VETO 的獨特之處在於**：
- 目標明確：抑制捷徑而非引導特定行為；
- 介入精準：僅約束更新方向，不影響模型其他能力；
- 通用性強：適用於多種骨幹網路，無需針對特定任務調整。

**現有論文的局限性**

儘管 VETO 展現了顯著效果，仍存在以下局限：
1. **依賴僅文字輸入的校準**：需要能夠產生僅文字輸入的場景，對某些多模態任務可能不適用；
2. **LoRA 特定的設計**：目前僅在 LoRA 微調下驗證，全參數微調下的效果尚待探索；
3. **單次校準的假設**：假設捷徑子空間在微調過程中保持穩定，但這個假設在極端分布偏移下可能被打破；
4. **捷徑定義的模糊性**：雖然不需要預先定義捷徑，但校準階段仍隱含了「捷徑存在於僅文字激活值中」的假設。

A：從工程角度，VETO 的部署成本相當低：它只需要在微調前對基礎模型做一次僅文字輸入的前向傳播以校準子空間，並在每一步微調中對 LoRA 更新量做一次正交投影，額外計算量極小。然而，產品團隊仍需考量：校準子空間所用的「僅文字輸入」應如何選取（需能代表部署場景中模型可能遇到的文字模式），以及 LoRA 秩（rank）的選擇是否會影響正交投影的效果。此外，由於 VETO 改變了更新方向，學習率與訓練排程可能需要重新調整，這在實際部署中是必須驗證的環節。

**Q12：VETO 對 VideoLLM 領域的更廣泛影響是什麼？**

A：VETO 對領域的更廣泛影響在於它挑戰了一個被普遍接受的假設——「微調必然會帶來影片理解的提升」。它揭示了 SFT 的準確率上升可能隱藏著對影片的依賴下降，並提供了一個可在不改變資料、損失或排程的前提下壓制捷徑的工具。這種「介入於更新量」的思路也可能啟發其他模態（如音訊、3D、觸覺）的大型多模態模型微調研究，讓研究者重新思考「什麼是真正的跨模態學習」。長遠來看，VETO 推動了領域從「追求訓練分布準確率」轉向「追求分布偏移下的影片依據性」。

**Q13：VETO 存在哪些已聲明或可預見的限制？**

A：VETO 的限制之一在於它依賴於「文字子空間可被清晰校準」的假設——若基礎模型在僅文字輸入下的激活值無法形成一個穩定且有意義的子空間（例如文字與影片資訊在某些層已深度耦合），投影的效果可能打折。此外，VETO 目前僅在 LoRA 微調下驗證，對全參數微調（full fine-tuning）的適用性與效果尚待探索。另一個潛在限制是：VETO 假設捷徑完全位於文字子空間內，但若捷徑涉及跨模態的統計規律（例如影片幀率與問題類型的相關性），則單純的正交投影可能不足以完全壓制。

**Q14：VETO 在哪些情境下可能會失效或表現不如預期？**

A：VETO 可能失效的情境包括：當訓練資料中的文字規律與影片內容高度相關時（例如問題總是針對影片中明顯可見的物體），投影到正交補空間可能反而阻礙了模型學習有效的跨模態對應。此外，若下游任務的答案確實可以從文字中可靠推得（例如「影片中是否有人說話？」這類問題），VETO 強迫模型依賴影片可能導致不必要的效能損失。在極小資料規模或極短微調步數下，校準出的子空間可能不夠穩定，導致投影方向有偏差，這也是需要注意的失敗情境。

**Q15：這篇論文為未來研究開啟了哪些方向？**

A：這篇論文開啟了多個值得探索的方向：第一，將「正交投影壓制捷徑」的思路推廣到全參數微調或其他模態（如音訊、3D 點雲）的多模態模型；第二，研究如何在不依賴 LoRA 的情況下，以更低成本實現類似的更新約束；第三，探索「文字子空間」的動態特性——是否需要在微調過程中定期重新校準；第四，將 VETO 與強化學習（RL）階段結合，探討在 RL 階段是否也會形成類似的捷徑；最後，更根本的問題是：能否設計出一種從根本上鼓勵跨模態對應（而非單模態規律）的微調目標函數，這將是該領域的長期追求。

## 實務應用指南

### 適用場景

1. **短影片平台的內容審核與分類**：TikTok、YouTube Shorts 等平台需要對海量影片進行違規內容、類別標籤的自動判讀。VETO 可避免模型僅依賴影片標題、描述等文字欄位做判斷，迫使模型真正讀取影片畫面，降低誤判率並提升對新型違規內容的偵測能力。

2. **醫療手術影片的術後記錄與問答**：醫療團隊常需從手術錄影中擷取關鍵步驟、器械使用順序等資訊。VETO 能防止模型從病歷文字、術式名稱等捷徑猜測答案，確保回答確實來自影片內容，對臨床決策支援至關重要。

3. **工業產線的瑕疵檢測與異常事件分析**：智慧工廠中 VideoLLM 用於分析產線監控影片、判斷異常事件類型。VETO 抑制模型從工單編號、機台名稱等文字欄位猜測結果的傾向，使模型必須觀察實際影像，提升在新品項、新機台上的泛化表現。

4. **教育影片的互動式學習助理**：線上學習平台希望學生提問時，模型能根據影片內容回答，而非從課程大綱、章節標題推測。VETO 確保模型在學生跳著看、跨章節提問時仍能依據影片證據作答。

5. **自駕車與機器人影片的事件回溯分析**：自駕系統需從行車記錄器影片回答「前幾秒發生了什麼」、「為何急煞」等問題。VETO 防止模型從 GPS 標籤、感測器日誌等文字元資料猜測，強制以視覺證據為依據，提升事故分析的可靠性。

### 實作前置條件

**資料需求**
- 目標影片問答資料集（訓練與評估用），需含影片檔與對應的問題、選項、答案。
- 純文字輸入的校準資料：可從訓練資料衍生，僅取問題與選項組成 text-only 輸入，無需額外標註。
- 分布偏移評測集：建議準備至少 3–6 個與訓練資料場景、問題形式、答案格式不同的基準（如 Perception Test、NextQA、ActivityNet-QA 等）。

**運算資源**
- 至少一張具備 40GB 以上 VRAM 的 GPU（如 A100、H100），用於 7B 級 VideoLLM 的 LoRA 微調與推論。
- 若使用 13B 以上模型，建議多卡並行（2–4 張 A100/H100）。
- 校準階段只需前向傳遞，記憶體需求低於完整微調；正式微調階段需考量梯度與優化器狀態的額外開銷。

**技術技能**
- 熟悉 PyTorch、Hugging Face Transformers 與 PEFT（LoRA）套件。
- 具備線性代數基礎：理解子空間、正交投影、SVD 分解等概念。
- 了解 VideoLLM 的架構（視覺編碼器 + 投影層 + LLM），能定位「文字-only 激活值」應在何層擷取。
- 具備評估影片問答模型的經驗，包含 text-only 與 full-input 兩種輸入設定的對照實驗設計。

### 實作步驟建議

1. **建立 text-only 校準集**：從訓練資料中取 N 筆（建議 500–2000 筆）樣本，僅保留問題與選項文字，移除影片。確保這些樣本在基礎模型上的 text-only 準確率低於隨機猜測，以保證校準出的子空間代表「文字捷徑」而非真實推理。

2. **校準文字子空間**：將校準集輸入基礎模型（凍結權重），於每一層 Transformer 擷取隱藏狀態。對每層的激活值矩陣執行 SVD，保留前 k 個奇異向量（k 為超參數，建議從 8–32 開始調整），構成該層的「文字子空間」 $V_{\text{text}}$。此步驟每個骨幹模型只需執行一次，結果可重複使用。

3. **包裝 LoRA 模組並掛載正交投影**：在標準 LoRA 微調流程中，於每個 LoRA 層的更新量 $\Delta W$ 應用於權重之前，先計算 $\Delta W \cdot V_{\text{text}} V_{\text{text}}^\top$，將其從更新中扣除（即投影至正交補空間）。實作上可寫為自訂的 `torch.autograd.Function`，確保梯度正確回傳。

4. **執行微調**：使用標準 SFT 流程（學習率、batch size、epoch 數）進行微調，唯一差異是每步更新都經過正交投影。建議先以小規模資料驗證流程正確性，再擴展至完整資料集。

5. **建立雙軌評估機制**：每個 checkpoint 需同時評估 (a) full-input 準確率與 (b) text-only 準確率。捷徑形成的訊號是 text-only 準確率上升；VETO 成功的訊號是 full-input 維持或上升、text-only 維持在低檔。

6. **在分布偏移基準上驗證**：於 3–6 個未見過的基準上重複步驟 5 的評估，確認 VETO 相較純 SFT 在偏移場景有實質增益。

7. **部署與監控**：將訓練好的 LoRA 權重合併回基礎模型，部署至推論服務。建議在線上持續監控 text-only 與 full-input 準確率差距，作為捷徑回歸的早期警示指標。

### 潛在風險與注意事項

- **子空間校準品質不穩**：若校準集太小或與目標任務差異過大，校準出的子空間可能無法準確代表「文字捷徑」。**緩解方式**：使用較大且多元的校準集，並以消融實驗驗證不同 k 值的效果。

- **過度抑制導致欠擬合**：若正交投影過於激進，可能連帶壓抑模型從文字學習合理推理的能力，使 full-input 準確率下降。**緩解方式**：監控訓練分布的 full-input 準確率，確保不低於純 SFT 的 95%；必要時調降 k 值或僅在部分層套用投影。

- **骨幹模型變更需重新校準**：VETO 的子空間是針對特定骨幹校準的，更換基礎模型後必須重新執行校準流程。**緩解方式**：將校準流程模組化並納入 MLOps 流水線，確保模型版本與子空間檔案綁定。

- **正交投影的額外運算成本**：每步更新都需進行矩陣乘法，會增加訓練時間（估計 5–15%）。**緩解方式**：將投影矩陣預先快取於 GPU，並考慮僅在 LLM 主幹套用、不投影視覺編碼器與投影層。

- **評估指標的單一性風險**：僅以準確率評估可能忽略細粒度的推理品質。**緩解方式**：輔以人工抽樣檢視模型回答，特別關注「答對但理由錯誤」的情況。

- **與其他去偏方法疊加的相容性**：若同時使用資料過濾、損失懲罰等方法，可能產生過度校正。**緩解方式**：先單獨驗證 VETO 效果，再逐步加入其他方法並觀察交互影響。

### 與其他技術的整合建議

- **與 LoRA / QLoRA 整合**：VETO 設計上即與 LoRA 相容，可直接嵌入現有 PEFT 流程。對 QLoRA（4-bit 量化）同樣適用，只需在量化權重上套用相同的投影邏輯。

- **與 RLHF / DPO 銜接**：VETO 作用於 SFT 階段，可作為 RLHF 的前置步驟。先用 VETO 抑制捷徑，再進行偏好對齊，可避免獎勵模型也被捷徑污染。

- **與資料過濾管線互補**：論文中已指出資料過濾無法根除捷徑，但可作為前置處理降低明顯的偏捷徑樣本，再交由 VETO 在更新層面處理剩餘的隱性捷徑。

- **與多模態檢索增強（RAG）整合**：在推論階段可結合影片片段檢索，將模型回答錨定至具體時間區間，與 VETO 的「依據影片證據」精神一致。

- **與模型監控與可觀測性工具整合**：將 text-only 與 full-input 準確率差距納入模型監控儀表板（如 Weights & Biases、MLflow），作為持續追蹤捷徑回歸的指標。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與圖 1，直觀理解「模型從文字猜答案」是什麼意思，再回頭看第 1 節的問題陳述。技術細節可先跳過，重點掌握「VETO 在不改資料、不改損失的前提下，於模型更新層面抑制捷徑」這個核心觀念。

**給 AI 工程師**：重點閱讀第 2 節的校準流程與第 3 節的投影實作細節，並直接參考官方程式碼（GitHub 連結）以了解 LoRA 層的掛載方式與正交投影的 autograd 實作。建議在自己的影片問答資料上先重現論文的雙軌評估實驗，再評估導入 VETO 的成本效益。

**給研究者**：第 2 節的捷徑形成分析（跨 epoch、資料規模、骨幹的實驗）值得深入探討，可思考 VETO 概念是否能延伸至音訊、觸覺等其他模態，或應用於純文字 LLM 的偏捷徑抑制。正交投影與其他去偏方法（如因果介入、資訊瓶頸）的理論連結也是值得探索的方向。

**給產品經理**：重點理解 VETO 解決的商業問題——模型在訓練資料上看似表現良好，部署後卻在真實場景失靈。建議將「text-only 與 full-input 準確率差距」列為模型驗收的標準指標之一，並評估在自家影片問答產品上導入 VETO 的 ROI，特別關注分布偏移場景下的使用者體驗改善。
