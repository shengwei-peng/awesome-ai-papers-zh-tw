# 稀疏性應由輸出來「ALLOT」（分配）：影片擴散Transformer中塊稀疏注意力的無需訓練分配

**原文標題：** Sparsity Should Be ALLOTted by Output: Training-Free Allocation of Block-Sparse Attention for Video Diffusion Transformers  
**作者：** Tianze Xia、Xiaoling Zhou、Ruya Lan 等 6 位作者  
**發布日期：** 2026-10-21

## ⚡ TL;DR

影片擴散Transformer的塊稀疏注意力分配仰賴啟發式規則或局部指標，無法可靠反映最終影片誤差。
本文提出無需訓練的ALLOT，透過單元探測與軌跡校準估計敏感度，在延遲預算下聯合優化密度分配。
ALLOT在Wan與HunyuanVideo上皆優於或持平所有比較策略，PSNR提升11.8 dB。

## 摘要翻譯

在影片擴散Transformer（Diffusion Transformers）中，全三維注意力（3D Attention）成本高昂。塊稀疏注意力（Block-Sparse Attention）透過僅計算選定的注意力塊來降低此成本。然而，現有方法要麼忽略了優化稀疏性（Sparsity）分配的潛力，要麼依賴啟發式規則（Heuristic rules）或局部指標（Local metrics）來引導分配。在本研究中，我們觀察到，在不同層（Layer）和不同去噪步驟（Denoising Steps）中對注意力進行稀疏化，會對最終影片保真度（Final-video fidelity）產生程度各異的影響。然而，最敏感的層-步驟對（Layer-step pairs）的具體身份在不同輸入間幾乎保持不變。基於這些發現，我們提出了透過輸出測試分配層-步驟延遲（Allocating Layer-step Latency by Output Tests, ALLOT），這是一種無需訓練（Training-free）的稀疏性分配方法。ALLOT將每個層-步驟對視為一個單元（Cell），透過（i）單元探測（Cell probing）和（ii）軌跡校準（Trajectory calibration）來估計每個單元對最終影片誤差（Final-video error）的貢獻，然後在已測量的延遲預算（Latency budget）下聯合優化單元密度（Cell densities）。它保留了現有的選擇策略（Selection strategies）和核心（Kernels），僅替換分配元件（Allocation component）。在相同或更短的實際執行時間（Wall-clock time）下，ALLOT在使用XAttention時優於所有比較的分配策略，並在HunyuanVideo上實現了11.8 dB的峰值信噪比（PSNR）提升。在Wan2.1、Wan2.2和HunyuanVideo上額外四個已發表流程（Pipeline）中進行的廣泛實驗亦表明，ALLOT在所有九種設定中均優於或與預設方法持平。

### 核心貢獻（3～5點）
- **關鍵觀察**：揭示不同層-步驟對的稀疏化敏感度（Sensitivity）差異顯著，但最敏感的層-步驟對身份在不同輸入間高度穩定，為跨輸入的稀疏性分配（Sparsity allocation）提供了理論基礎。
- **方法創新**：提出無需訓練的ALLOT方法，透過單元探測與軌跡校準兩階段機制，精準估計每個層-步驟單元對最終影片誤差的貢獻。
- **實用設計**：在測量延遲預算下聯合優化單元密度，僅替換分配元件，完整保留現有的選擇策略與計算核心，易於與現有稀疏注意力方案整合。
- **實驗成效**：在HunyuanVideo上以XAttention為基礎實現11.8 dB PSNR的大幅提升，並於Wan2.1、Wan2.2、HunyuanVideo共九種設定中全面勝出或持平預設方法。

### 適合對象
從事影片生成（Video generation）、擴散模型（Diffusion）加速推論、稀疏注意力（Sparse attention）機制設計的研究人員與工程師；以及對無需訓練（Training-free）模型優化、層-步驟延遲（Layer-step Latency）分配策略感興趣的學術界與產業界讀者。

## 深度分析

#### 方法論解析

ALLOT（Allocating Layer-step Latency by Output Tests，透過輸出測試分配層-步驟延遲）的核心思想是將稀疏性分配（sparsity allocation）從啟發式規則或局部代理指標（local proxies）轉變為基於最終影片敏感度（sensitivity）的全局優化問題。其方法論可從以下幾個層次解析：

**1. 問題形式化（Problem Formulation）**

作者將每一個（層 ℓ, 去噪步驟 s）對定義為一個「單元」（cell），並引入敏感度函數 S(ℓ, s; b)，量化將該單元稀疏化至密度 b 時，最終影片相對於密集輸出（dense output）的退化程度。直接測量所有單元的 S 需要數千次完整生成，計算上不可行，因此 ALLOT 將其分解為兩個更便宜的訊號。

**2. 單元探測（Cell Probing）**

單元探測測量的是「單步輸出誤差」（one-step output error）：當某一層在某一去噪步驟被稀疏化時，模型輸出與密集輸出之間的差異。這是一個局部測量，但比注意力圖指標（attention mass、Hellinger distance）更接近最終影片的誤差。實驗數據顯示，Wan2.1-1.3B 的第 0 層單步誤差是中位層的 53 倍，Wan2.1-14B 的第 0 層達到 154 倍，HunyuanVideo 的第 1 層為 35 倍——這證明了層間敏感度差異極為懸殊。

**3. 軌跡校準（Trajectory Calibration）**

軌跡校準測量的是「跨步驟誤差放大效應」：當一個步驟窗口被稀疏化時，最終影片誤差相對於單步誤差的放大倍數。圖 3(b) 顯示 Wan2.1-1.3B 的第一個窗口的最終影片誤差是單步誤差的 463 倍，而最後一個窗口僅為 6.4 倍——這意味著早期步驟的微小誤差會被後續去噪過程顯著放大，而後期步驟的誤差則較容易被「吸收」。這個觀察直接挑戰了現有方法將所有步驟平等對待的假設。

**4. 聯合密度優化（Joint Density Optimization）**

在獲得每個單元的敏感度估計後，ALLOT 在測量得到的延遲預算（latency budget）下聯合求解所有單元的密度配置。這是一個受約束的優化問題，目標是最小化加權敏感度總和，約束為總延遲不超過預算。重要的是，「暖啟長度」（warm-up length）和「密集層」（dense layers）不再是手工設定的規則，而是從優化解中自然浮現——這是 ALLOT 與現有啟發式方法的根本區別。

**5. 離線預計算與推論查表**

由於敏感度排名在固定模型與選擇策略下跨輸入保持穩定（這是論文的核心觀察之一），單元探測與軌跡校準只需離線執行一次，結果以表格形式儲存。推論時，ALLOT 僅查詢預計算的密度表，改變現有塊稀疏注意力流程中的分配元件（allocation component），而保留選擇策略（selection strategies）與計算核心（kernels）不變。這種「即插即用」的設計哲學使 ALLOT 能與 XAttention、SVOO、SVG2、SpargeAttn、Radial 等六種選擇策略無縫結合。

**6. 與現有方法的本質差異**

現有方法的分配維度包括：每層 [3]、每（層, 頭）[1, 14, 35]、每步驟 [9, 33]、每（層, 步驟）[28]、每（步驟, 層, 頭）[27, 36]。ALLOT 同樣在（層, 步驟）粒度上分配，但關鍵差異在於：(i) 它直接校準最終影片誤差而非局部代理指標；(ii) 它捕捉跨步驟誤差放大；(iii) 它在測量延遲預算下聯合求解所有單元，而非逐層或逐步獨立設定。

#### 實驗數據解讀

**1. 核心結果：HunyuanVideo 上的 11.8 dB PSNR 增益**

在 HunyuanVideo 上搭配 XAttention（HEART 的設定），ALLOT 在相同 1.21× 加速倍率下達到 23.2 dB PSNR，而 HEART（EBC）僅為 16.0 dB——這是 11.8 dB 的巨大差距。這個數字值得深入解讀：PSNR 每提升 1 dB 代表約 26% 的均方誤差（MSE）下降，11.8 dB 的差距意味著 MSE 下降超過兩個數量級。這表明在 HunyuanVideo 上，預設的分配策略嚴重低估了某些層-步驟對的敏感度，而 ALLOT 的全局優化能精確識別並保護這些關鍵單元。

**2. Wan2.1-14B 720p 上的 SVOO 流程**

在 Wan2.1-14B、720p×81、SVOO 流程下，密集推理為 1.00× 基準，SVOO 為 1.31× 加速（21.2 dB），SVOO + ALLOT 為 1.32× 加速（24.8 dB）。ALLOT 在幾乎相同的加速倍率下帶來 3.6 dB 的 PSNR 提升，且加速倍率甚至略高於基線——這證明了 ALLOT 不僅改善品質，還能更高效地利用延遲預算。

**3. 跨模型與跨解析度的穩健性**

實驗涵蓋 Wan2.1-14B 720p、Wan2.2-A14B 720p、Wan2.1-1.3B 720p、HunyuanVideo、Wan2.1-1.3B 480p 等五種設定，以及 XAttention、SVOO、SVG2、SpargeAttn、Radial 等五種選擇策略，共九個設定。ALLOT 在所有九個設定中「勝出或持平」（outperforms or ties），且 95% 信賴區間（CI）顯示增益在統計上顯著。這種跨模型、跨解析度、跨選擇策略的一致性，是 ALLOT 最具說服力的實驗證據。

**4. 視覺品質驗證**

圖 1 左側的視覺比較顯示，密集輸出與基線（HEART EBC）在藍框區域有明顯的偽影或細節丟失，而 ALLOT 的輸出更接近密集結果。這驗證了 PSNR 數字背後的視覺意義——敏感度優化不僅提升像素級準確度，也改善了感知品質。

**5. 局部指標的失敗案例**

圖 2(a) 揭示了一個關鍵發現：Wan2.1-1.3B 的第 0 層在 SVOO 排名中僅為第 3（30 層中），在 Hellinger 距離排名中為第 1，但其單步誤差是中位層的 53 倍。Wan2.1-14B 的第 0 層更為極端：SVOO 排名 22，Hellinger 排名 13，但單步誤差為中位層的 154 倍。這意味著基於注意力圖指標的分配方法會嚴重誤判關鍵層，導致品質大幅下降。附錄 B 進一步證實，基於這些局部指標的分配甚至可能劣於均勻基線（uniform baseline）。

**6. 軌跡放大的量化**

圖 3(b) 顯示 Wan2.1-1.3B 上，第一個窗口的最終影片誤差是單步誤差的 463 倍，而最後一個窗口僅為 6.4 倍——放大倍數差異達 72 倍。這直接說明了為什麼「所有步驟平等」的分配策略是次優的：早期步驟的微小誤差會被後續去噪過程指數級放大，因此需要分配更多計算資源。

#### 與現有研究的比較

**1. 定位：分配層的通用框架**

ALLOT 的獨特定位在於：它不與現有選擇策略（XAttention、SVOO 等）競爭，而是作為一個「分配層」（allocation layer）增強它們。這種設計哲學類似於編譯器中的優化遍（optimization pass）——不改變演算法本身，只改變資源配置。這使得 ALLOT 能與六種不同的選擇策略無縫結合，展現出極強的通用性。

**2. 對啟發式規則的改進**

現有方法常用「第一層密集」或「前 10–30% 步驟密集」等固定規則 [12, 14, 25]。ALLOT 的實驗證明這些規則不可靠：最敏感的層因模型而異（Wan2.1-1.3B 為第 0 層，HunyuanVideo 為第 1 層），且「第一層密集」規則在 Wan2.1-14B 上會錯過第 0 層（其 SVOO 排名僅為 22）。ALLOT 透過數據驅動的敏感度估計取代了這些脆弱的先驗。

**3. 對局部指標方法的改進**

HEART（EBC + TMR）[14]、CalibAttn [3]、DiTFastAttn [35] 等方法使用累積注意力質量、Hellinger 距離、單步輸出誤差等局部代理指標。ALLOT 的關鍵貢獻是證明這些指標與最終影片敏感度的排名不一致——圖 2(a) 顯示 Wan2.1-1.3B 第 0 層在 SVOO 排名為第 3，但在最終影片誤差中是最敏感的層。這意味著基於局部指標的分配可能將計算資源錯誤地分配給不重要的單元，而忽略真正關鍵的單元。

**4. 對基於訓練方法的優勢**

VSA [30]、VMoBA [21]、NABLA [15] 等方法需要訓練或微調模型，計算成本高昂且難以泛化到新模型。ALLOT 作為無需訓練（training-free）的方法，只需離線預計算一次敏感度表，即可應用於任意提示詞，且不修改模型權重。這對於閉源模型（如部分商業影片生成 API）尤為重要。

**5. 局限性**

儘管 ALLOT 表現優異，仍存在以下局限：

- **離線預計算成本**：雖然只需執行一次，但單元探測與軌跡校準仍需要數百次部分生成，對於快速迭代的模型開發流程可能成為瓶頸。
- **模型與策略耦合**：敏感度表是針對特定模型與選擇策略預計算的，更換模型或策略需要重新計算。論文中未明確給出重新計算的成本。
- **頭維度未考慮**：現有方法如 [27, 36] 在（步驟, 層, 頭）粒度上分配，ALLOT 僅在（層, 步驟）粒度，可能錯過頭級別的優化機會。
- **動態輸入的適應性**：雖然敏感度排名跨輸入穩定，但對於極端異常的提示詞（如高度非典型的場景），穩定性假設可能不成立。

#### 可重現性評估

**1. 程式碼可用性**

論文標題暗示「ALLOT」是一個可獨立實作的方法，但提供的全文中未明確提及開源程式碼倉庫連結。考慮到論文作者包括 KlingAI 的實習生與通訊作者，且方法論描述詳盡（包括單元探測、軌跡校準、聯合優化的具體公式），可重現性在技術上是可行的。然而，缺乏官方實作會增加第三方重現的難度，特別是軌跡校準中「測量延遲預算」的具體測量方法可能存在實作細節差異。

**2. 模型權重**

實驗使用的 Wan2.1、Wan2.2、HunyuanVideo 均為公開模型，權重可從官方倉庫下載。XAttention、SVOO、SVG2、SpargeAttn、Radial 等選擇策略的程式碼也應為開源（這些是近期發表的方法）。因此，硬體與軟體依賴均可滿足。

**3. 資料集與評測協議**

論文未明確說明使用的評測提示詞集。從圖 1 的描述（「prompts are near the median gain」）推測，作者可能使用了多個提示詞並報告中位數附近的結果。PSNR 的計算需要密集輸出作為參考，這要求對每個提示詞執行一次完整推理——對於 720p×81 的影片，這在單 GPU 上需要約一小時，因此大規模評測的計算成本不容忽視。

**4. 評測指標**

PSNR 是主要的量化指標，但缺乏 LPIPS、FVD、人類偏好評分等感知指標的補充。雖然 PSNR 提升 11.8 dB 極為顯著，但感知品質與像素級準確度並不完全相關。未來工作可考慮加入更多感知指標。

**5. 統計顯著性**

作者報告了 95% 信賴區間（CI），這是良好的統計實踐。但未明確說明每個設定的提示詞數量與抽樣方法。對於「勝出或持平」的結論，需要足夠大的樣本量才能支撐。

#### 未來研究方向

**1. 頭維度與時間維度的聯合優化**

ALLOT 目前僅在（層, 步驟）粒度分配密度，未考慮頭（head）維度。不同注意力頭可能對稀疏化有截然不同的敏感度——例如，某些頭專注於局部紋理，某些頭負責全局結構。將 ALLOT 擴展至（層, 步驟, 頭）三維粒度，可能進一步提升效率與品質的權衡。此外，影片的時間維度（幀間注意力 vs. 幀內注意力）也可作為分配維度。

**2. 動態敏感度估計**

雖然敏感度排名跨輸入穩定，但對於極端異常的提示詞（如高度抽象的概念藝術或非標準構圖），穩定性假設可能不成立。未來可探索輕量級的線上敏感度估計方法，例如在推理的前幾步進行少量探測，動態調整密度表。這需要在「額外探測成本」與「適應性增益」之間取得平衡。

**3. 與其他稀疏化技術的結合**

ALLOT 專注於注意力層的稀疏化，但影片 DiT 的計算瓶頸還包括其他組件（如 MLP 層、位置編碼）。未來可探索將 ALLOT 的分配思想擴展至整個模型的計算圖，實現端到端的資源優化。此外，與 token 合併（token merging）、token 剪枝（token pruning）等技術的結合也值得探索。

**4. 理論分析：為何敏感度排名穩定？**

論文觀察到敏感度排名跨輸入穩定，但未深入解釋其理論根源。一個可能的方向是：不同層-步驟對的功能角色（如早期去噪的整體結構生成 vs. 後期去噪的細節精煉）是由模型架構與訓練目標決定的，因此對輸入變化的魯棒性較高。深入理解這一現象可能啟發更原則化的分配方法。

**5. 應用於其他模態與任務**

ALLOT 的核心思想——「直接測量最終輸出敏感度而非依賴局部代理指標」——可應用於任何涉及稀疏計算的生成任務，包括音訊擴散模型、3D 點雲生成、多模態生成等。此外，在語言模型的長上下文推理中，類似的分配問題也存在，ALLOT 的方法論可能具有跨領域的適用性。

**6. 自動化預計算流程**

目前的離線預計算需要人工設定探測協議與優化參數。未來可開發自動化工具，根據模型架構自動生成敏感度表，進一步降低使用門檻。這對於快速發展的影片生成領域尤為重要——新模型層出不窮，手動預計算難以跟上節奏。

**7. 與蒸餾或量化技術的協同**

稀疏化、蒸餾、量化是模型壓縮的三大支柱。ALLOT 目前僅關注稀疏化，未來可探索其與蒸餾（如一致性模型）或量化（如 INT8 注意力）的協同效應。例如，在稀疏化的同時對不敏感的層-步驟對進行更低精度量化，可能進一步提升效率。

**8. 公平性與偏見考量**

影片生成模型可能存在社會偏見，稀疏化可能放大或抑制某些偏見——例如，某些層可能負責生成特定性別或種族的特徵，稀疏化這些層可能改變輸出的多樣性。未來工作應評估 ALLOT 對生成多樣性與公平性的影響，確保效率提升不以犧牲代表性為代價。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於影片擴散Transformer（Video Diffusion Transformers）中全三維注意力（full 3D attention）運算成本過高的問題。由於注意力計算量隨token數量呈二次方增長，在單一GPU上，Wan2.1-14B生成一段720p、81幀的影片需要約一小時，其中注意力運算就佔據超過一半的端到端時間。雖然塊稀疏注意力（block-sparse attention）能透過只計算選定的注意力塊來降低成本，但現有方法在「每個層、每個去噪步驟應保留多少稀疏密度」的分配（sparsity allocation）上仍有明顯不足，因此論文試圖系統性地解決這個分配問題。

**Q2：為什麼現有的稀疏性分配方法會失敗？**
A：現有方法主要存在兩個根本性的限制。第一，啟發式規則（heuristic rules）無法可靠地跨設定轉移，例如「保留第一層密集」或「前10–30%去噪步驟保持密集」這類固定規則，在不同模型與選擇策略下效果差異極大，因為最敏感的層在不同模型中並不一致。第二，局部指標（local metrics）無法反映最終影片的真實誤差，常用的累積注意力質量、Hellinger距離、單步輸出誤差等代理指標所誘導的敏感度排序，與最終影片誤差的排序並不一致，甚至依此分配會比均勻基線（uniform baseline）產生更差的最終影片保真度。

**Q3：為什麼這個問題對影片生成特別重要？**
A：影片生成相比影像生成需要處理的token數量遠為龐大，因為它同時包含空間與時間維度，這使得三維注意力的二次方成本成為實際部署的主要瓶頸。此外，影片生成對時空一致性（spatio-temporally consistent）的要求極高，任何在中間步驟累積的誤差都可能因為後續去噪步驟的放大效應而嚴重損害最終品質。因此，如何在嚴格的延遲預算（latency budget）下，智慧地將計算資源分配到真正重要的層-步驟對上，就成為兼顧效率與品質的關鍵課題。

**Q4：ALLOT的核心方法是什麼？**
A：ALLOT（Allocating Layer-step Latency by Output Tests）的核心想法是將每一個「層-步驟對」視為一個「單元」（cell），並直接評估每個單元對最終影片誤差的敏感度（sensitivity）。具體而言，ALLOT透過兩個互補的訊號來估計每個單元的誤差貢獻：單元探測（cell probing）測量在該步驟將一層稀疏化所產生的單步輸出誤差，而軌跡校準（trajectory calibration）則測量後續去噪步驟對該誤差的放大或衰減程度。接著，ALLOT在測量得到的延遲預算下聯合求解所有單元的密度分配，使暖機長度與密集層等設定自然從最佳化解中浮現，而非仰賴人工設定的規則。

**Q5：單元探測與軌跡校準這兩個關鍵創新點解決了什麼問題？**
A：單元探測解決了「如何可靠地識別敏感層」的問題，因為它直接測量稀疏化對模型輸出的影響，而非依賴注意力圖的代理指標；實驗顯示前1–2層的單步誤差可達中位數層的53倍甚至154倍，而這些層也恰好是影響最終影片品質最關鍵的層。軌跡校準則解決了「跨步驟誤差傳播」的問題，因為去噪過程中早期注入的誤差會被後續步驟顯著放大（例如首個視窗的最終影片誤差可達最後一個視窗的463倍）。兩者結合後，ALLOT能同時捕捉「哪裡注入誤差」與「誤差如何傳播」，比僅看單步誤差的局部方法更貼近最終影片的真實敏感度。

**Q6：ALLOT在設計上做了哪些務實的選擇以利於實際部署？**
A：ALLOT在設計上採取了多項務實的選擇以最大化實用性。首先，由於敏感度排序在固定模型與選擇策略下對不同輸入保持高度穩定，ALLOT將單元探測與軌跡校準的測量一次性離線完成，之後跨提示詞（prompts）重複使用，因此推論時只需查表而不需重新計算。其次，ALLOT保留了現有選擇策略與計算核心（kernels），僅替換分配元件（allocation component），這意味著它可以無縫整合到XAttention、SVOO、SVG2、SpargeAttn、Radial等多種既有流程中。最後，ALLOT在測量實際延遲（而非理論FLOPs）的預算下進行聯合最佳化，因此分配結果直接對應到真實的wall-clock時間。

**Q7：實驗使用了哪些基準測試與模型？**
A：實驗涵蓋了四個公開的影片生成流程與三個模型家族，包括Wan2.1-1.3B、Wan2.1-14B、Wan2.2-A14B以及HunyuanVideo，解析度涵蓋480p與720p，影片長度為81幀。在選擇策略方面，ALLOT與六種已發表的稀疏注意力方法整合進行評估，包含XAttention、SVOO、SVG2、SpargeAttn、Radial等。對比的分配策略則包括HEART（EBC與EBC+TMR兩個變體）、Efficient-vDiT、DiTFastAttn-style、FAST、PASA、DFSAttn-style與CalibAtt-style等共九種設定，構成相當全面的基準比較。

**Q8：ALLOT最重要的量化結果為何？**
A：最突出的結果是ALLOT在HunyuanVideo搭配XAttention時，於相同或更短的wall-clock時間下，比所有比較的分配策略高出11.8 dB PSNR，顯示其在困難設定下的巨大優勢。在Wan2.1-1.3B 480p×81搭配XAttention（HEART的設定）下，HEART（EBC）僅達16.0 dB PSNR，而ALLOT在相同1.21×加速比下達到23.2 dB PSNR；在Wan2.1-14B 720p×81的SVOO流程中，SVOO達21.2 dB PSNR，SVOO+ALLOT則達24.8 dB PSNR。整體而言，在九種設定中ALLOT全部勝出或至少打平所有對比方法，證明了其跨模型與跨流程的穩健性。

**Q9：論文中進行了哪些消融研究（Ablation Studies）？**
A：雖然完整消融研究在論文中以附錄形式呈現，但從正文與圖表可看出幾項關鍵消融：首先是不同局部指標（注意力質量、Hellinger距離、單步輸出誤差）vs.最終影片誤差的排序比較，結果顯示這些代理指標的排名與真實敏感度排名並不一致，驗證了ALLOT直接以最終影片為標的的必要性。其次是單元探測與軌跡校準兩個元件的個別貢獻分析，兩者缺一都會顯著降低效能。此外，圖2(b)展示了首尾視窗的最終影片誤差與單步誤差的對比，凸顯軌跡校準捕捉誤差放大效應的重要性，這些消融共同支撐了ALLOT設計的合理性。

**Q10：ALLOT適合哪些實際應用場景？**
A：ALLOT特別適合需要高效能影片生成的場景，例如短影片內容創作平台、廣告素材自動生成、遊戲與電影預覽（previz）以及社群媒體影片工具。在這些場景中，使用者通常需要在數秒到數分鐘內得到高品質結果，而ALLOT能在維持甚至提升品質的同時縮短生成時間。此外，對於雲端推論服務而言，ALLOT透過提升每張GPU的吞吐量，可直接降低單位影片的推論成本，使服務更具經濟效益。對於邊緣裝置或消費級硬體的部署，ALLOT的延遲最佳化特性也使其成為在有限算力下提供可接受品質的關鍵技術。

**Q11：從產品角度，ALLOT帶來哪些具體優勢？**
A：從產品角度，ALLOT帶來三項具體優勢。第一是「即插即用」的整合性，由於它只替換分配元件而不改變選擇策略或核心，產品團隊可在不重寫現有推論流程的情況下直接受益於其加速效果。第二是「品質保證」的可預測性，因為ALLOT在九種設定中全部勝出或打平，產品上線後不會遇到某些模型或流程下效能意外崩盤的風險。第三是「跨模型可移植性」，同一套ALLOT框架可應用於Wan與HunyuanVideo等不同模型家族，這對於支援多模型的產品平台特別有價值，能減少為每個模型單獨調校的維運負擔。

**Q12：ALLOT對整個領域有什麼更廣泛的影響？**
A：ALLOT對領域的更廣泛影響在於它重新定義了稀疏性分配的評估標準——從依賴局部代理指標轉向直接以最終輸出品質為標的，這個思路可推廣到其他生成模型與稀疏化技術，例如影像擴散Transformer、音訊擴散模型甚至大型語言模型的長上下文注意力。此外，ALLOT揭示的「敏感度跨輸入穩定性」現象，為未來設計更通用的稀疏化預測器提供了實證基礎。它也促使學界與業界重新審視那些僅以單步誤差或注意力圖統計量作為最佳化目標的方法，因為這些方法可能在最終任務指標上表現不佳。

**Q13：ALLOT有哪些已承認的限制？**
A：ALLOT的限制主要來自其依賴離線測量的特性。雖然敏感度排序在固定模型與選擇策略下對不同輸入保持穩定，但若使用者更換模型、選擇策略或甚至微調模型權重，則需要重新進行單元探測與軌跡校準，這會帶來一次性的計算成本。此外，ALLOT目前假設延遲預算固定，未動態適應不同硬體或不同並行設定下的最佳分配。最後，雖然ALLOT在六種選擇策略與三個模型家族上驗證有效，但對於極度稀疏（例如密度低於10%）或極長影片（例如數百幀以上）的設定，其表現仍待進一步驗證。

**Q14：ALLOT在哪些情況下可能會失敗？**
A：ALLOT可能在以下情況下表現不如預期：第一，當輸入分布與離線測量時使用的提示詞差異極大時（例如極長的敘事性影片或高度風格化的內容），雖然排序穩定性是經驗性觀察，但極端分布偏移仍可能導致敏感度排序改變。第二，當去噪排程（sampling schedule）改變時，軌跡校準的誤差放大效應可能與原測量假設不符，因此ALLOT的預計算密度表需要重新生成。第三，若使用者同時改變多個元件（例如同時更換選擇策略與模型），ALLOT的單元敏感度可能不再適用，需要重新校準。最後，在極低延遲預算下，所有單元都被迫高度稀疏，此時分配的最佳化空間有限，ALLOT相對於均勻分配的優勢也會縮小。

**Q15：基於ALLOT，未來有哪些值得探索的研究方向？**
A：基於ALLOT的發現，未來有幾個值得探索的方向。首先，可將「以最終輸出為標的」的分配思路推廣到訓練階段，發展聯合訓練稀疏模式與模型權重的方法，使模型本身就適應特定的稀疏分配。其次，可探索動態分配機制，根據當前輸入的內容特性（例如運動幅度或場景複雜度）即時調整密度表，進一步提升對分布偏移的韌性。第三，可將ALLOT的框架應用於其他昂貴的計算模組，例如影片VAE的時序解碼或長上下文語言模型中的注意力，以驗證其通用性。最後，研究如何將單元探測與軌跡校準的計算成本本身進一步降低（例如透過更少的採樣或代理模型），將使ALLOT更容易應用於快速迭代的模型開發流程中。

5. **長影片或多鏡頭一致性生成**：對於需要生成 81 幀以上長影片或多鏡頭切換的場景，ALLOT 透過軌跡校準（trajectory calibration）捕捉跨步驟誤差放大效應，能在長序列去噪過程中維持時空一致性，特別適合敘事性影片或電影預覽生成。

### 實作前置條件

**資料需求**：
- 一組用於離線校準的代表性提示詞（prompt set），建議至少 50–100 條涵蓋不同場景（人物、風景、動作、文字等），用於建立穩定的敏感度排名。
- 每個目標模型（如 Wan2.1-14B、Wan2.2-A14B、HunyuanVideo）對應的密集參考輸出，用於計算 PSNR 與最終影片誤差。
- 對應的影片 VAE 編解碼流程，以便在像素空間評估最終保真度。

**計算資源需求**：
- 至少一張具備 ≥ 48GB VRAM 的 GPU（如 A6000、A100 80GB、H100）以運行 14B 級別模型的密集推論作為參考。
- 額外 GPU 時間用於離線探測：每個 (層, 步驟) 單元需執行一次單步探測與一次軌跡校準，總計約數百至數千次部分推論（遠少於完整生成所有單元）。
- 儲存空間：預計算的密度查表通常為 MB 級別，但中間探測結果可能需要數十 GB。

**技能需求**：
- 熟悉 PyTorch 與 Transformer 架構，能修改 DiT 的注意力前向傳播邏輯。
- 理解區塊稀疏注意力的選擇策略（如 XAttention 的閾值機制）與底層 kernel（如 FlashAttention 的稀疏變體）。
- 具備基本的最佳化建模能力，能將密度分配問題形式化為線性規劃或凸優化問題。
- 熟悉影片品質評估指標（PSNR、LPIPS、VBench 等）以驗證部署效果。

### 實作步驟建議

**步驟 1：建立密集參考基準**
選定目標模型與解析度（如 Wan2.1-14B 720p × 81 幀），在固定隨機種子下對校準提示詞集執行完整密集推論，儲存每個去噪步驟的中間潛在表示與最終影片輸出，作為敏感度評估的 ground truth。

**步驟 2：整合區塊稀疏注意力選擇策略**
選擇一個現有的選擇策略（如 XAttention）並將其整合至模型的注意力層。確認 kernel 支援可變密度（即每層、每步驟可指定不同的保留區塊比例），這是 ALLOT 替換分配元件的前提。

**步驟 3：實作單元探測（Cell Probing）**
對每個 (層 ℓ, 步驟 s) 單元，在該步驟將第 ℓ 層的注意力替換為稀疏版本（密度可調），測量其單步輸出誤差相對於密集參考的偏差。記錄誤差比值以建立層級敏感度排名。

**步驟 4：實作軌跡校準（Trajectory Calibration）**
對每個步驟窗口（建議 5–10 步為一組），將整個窗口內所有層稀疏化並繼續執行後續去噪，測量最終影片 MSE 的放大倍數。此步驟捕捉跨步驟誤差傳播效應。

**步驟 5：求解聯合密度分配**
將每個單元的敏感度（單元探測誤差 × 軌跡增益）作為權重，在測量得到的延遲預算下求解：
$$\min \sum_{\ell,s} S(\ell,s) \cdot (1 - b_{\ell,s}) \quad \text{s.t.} \quad \sum_{\ell,s} L(b_{\ell,s}) \leq B$$
其中 $b_{\ell,s}$ 為密度、$L(\cdot)$ 為測量延遲函數、$B$ 為預算。可使用線性規劃或網格搜尋。

**步驟 6：建立密度查表並部署**
將求解得到的密度陣列序列化為 JSON 或 Pickle 檔案，在推論時由 ALLOT 模組查詢並注入至注意力層。確認熱身長度（warm-up steps）與密集層從解中自然浮現，而非手動設定。

**步驟 7：驗證與監控**
在保留的測試提示詞集上比較 ALLOT 與原始分配的 PSNR、LPIPS、VBench 分數，並監控實際 wall-clock time 是否符合預算。建議設定自動回退機制：若敏感度排名在新提示詞分佈下顯著偏移，則觸發重新校準。

### 潛在風險與注意事項

**風險 1：敏感度排名跨輸入的穩定性假設**
論文聲稱排名在固定模型與選擇策略下「近乎不變」，但若部署場景的提示詞分佈與校準集差異極大（如從風景轉為文字密集場景），排名可能漂移。**緩解**：定期以小批次新提示詞重新驗證排名；若漂移超過閾值則觸發增量校準。

**風險 2：離線校準成本被低估**
雖然單步探測比完整生成便宜，但對於 14B 模型 × 60 層 × 50 步的網格，總探測次數仍可達數千次。**緩解**：採用分層抽樣（先粗粒度掃描再細粒度優化），並利用軌跡校準的窗口結構減少重複計算。

**風險 3：延遲測量與實際部署環境不一致**
實驗室的單 GPU 延遲測量可能與生產環境的多 GPU 分散式部署差異甚大。**緩解**：在目標部署硬體上重新測量延遲函數 $L(\cdot)$，並考慮通訊開銷；若使用 tensor parallelism，需評估稀疏注意力對通訊模式的影響。

**風險 4：與動態選擇策略的相容性**
部分選擇策略（如基於即時注意力的 SpargeAttn）會根據輸入動態改變區塊數，ALLOT 的固定密度查表可能與之衝突。**緩解**：將 ALLOT 的密度視為「上限」或「目標比例」，允許選擇策略在該範圍內動態調整。

**風險 5：品質指標的單一性**
論文主要使用 PSNR，但 PSNR 對人類感知不敏感，可能掩蓋細節退化。**緩解**：在最終驗證階段加入 LPIPS、VBench、人類評估等多維度指標，避免僅依賴 PSNR 做部署決策。

**風險 6：模型版本更新導致重新校準**
當模型權重更新（如 Wan2.1 → Wan2.2）或微調後，敏感度排名會改變。**緩解**：將校準流程版本化並與模型版本綁定，建立自動化的重新校準 CI/CD 流程。

### 與其他技術的整合建議

**與模型蒸餾或量化整合**：ALLOT 處理的是注意力稀疏性，與 INT8/FP8 量化、權重蒸餾正交。可先量化再套用 ALLOT，或反之；兩者結合時需注意 kernel 是否同時支援稀疏與量化（部分稀疏注意力 kernel 僅支援 FP16）。

**與快取機制整合**：許多影片 DiT 部署會快取去噪步驟間的 KV cache。ALLOT 的密度變化會影響 KV cache 的記憶體佔用，建議在分配求解時將 KV cache 成本納入延遲函數 $L(\cdot)$，或採用動態 KV cache 配置。

**與分散式推論框架整合**：在 vLLM、SGLang、TensorRT-LLM 等框架中部署時，需將 ALLOT 的密度查表封裝為 scheduler hint，使框架能預先分配注意力 kernel 的工作負載。對於序列並行（sequence parallelism），需評估稀疏注意力對跨 GPU 通訊量的影響。

**與影片 VAE 解碼整合**：稀疏注意力僅影響 DiT 部分，VAE 解碼成本不變。若目標是端到端加速，需將 VAE 解碼納入整體延遲預算考量，或採用 tile-based VAE 解碼以進一步降低瓶頸。

**與 A/B 測試平台整合**：將 ALLOT 與原始分配作為實驗組與對照組，透過 A/B 測試平台收集使用者偏好訊號（thumbs up/down、再生產率），以業務指標驗證 PSNR 提升是否轉化為使用者體驗改善。

**與監控與可觀測性整合**：在生產環境中暴露每個 (層, 步驟) 單元的實際密度、單步誤差、軌跡增益等指標至 Prometheus/Grafana，便於日後診斷品質退化或延遲異常。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）了解影片 DiT 的注意力成本問題，再看第 3 節（Motivation）的 Figure 2，直觀感受不同層與步驟的敏感度差異。技術細節可先跳過，重點理解「不是所有注意力都同等重要」這個核心洞察，以及 ALLOT 如何用「單元」的概念重新組織稀疏分配問題。

**給 AI 工程師**：重點閱讀第 4 節（Method）的單元探測與軌跡校準實作細節，以及第 4.5 節關於如何「僅替換分配元件」的整合說明。直接參考論文的開源程式碼（若有）將 ALLOT 模組插入現有的 XAttention 或 SVOO 流程，並以單 GPU 環境先復現 Figure 1 的 PSNR 增益結果，再評估生產部署的可行性。

**給研究人員**：第 3 節的兩個觀察（層敏感度差異極大、局部指標誤判最終誤差）是本論文最具啟發性的貢獻。建議深入分析為何 Hellinger 距離、累積注意力質量等局部代理指標會誤導分配，並探索是否可將「輸出測試」框架推廣至其他稀疏化場景（如專家混合 MoE 的路由分配、token pruning 的層級分配等）。第 5 節的消融實驗也值得仔細研讀。

**給產品經理**：核心訊息是「不改模型、不改選擇策略，僅改分配方式即可在相同速度下大幅提升品質」。這意味著現有影片生成產品的加速優化存在「低垂果實」——無需訓練新模型或採購更多 GPU，即可透過軟體層最佳化提升使用者體驗。建議評估將 ALLOT 整合至現有推論流程的 ROI，特別關注 PSNR 11.8 dB 提升對應的業務指標（如使用者留存、付費轉換）改善幅度。
