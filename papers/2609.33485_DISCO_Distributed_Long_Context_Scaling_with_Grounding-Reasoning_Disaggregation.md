# DISCO：以扎根與推理解耦實現分散式長上下文擴展

## ⚡ TL;DR

單體式 LLM 在長上下文推理時，因扎根與推理結構糾纏而出現上下文衰減。
以 WorkerLLM 平行扎根、GRPO 訓練的 DriverLLM 規劃綜合，DISCO 解耦扎根與推理。
RULER-QA 百萬詞元達 78.4%，LongBench v2 領先基線 9.8 分，成本降逾八成。

## 摘要翻譯

儘管大型語言模型（LLMs）標榜百萬 token 上下文視窗（context window），但隨著輸入增長，推理品質（reasoning quality）經常崩潰——這種現象被稱為上下文衰減（context rot）。這種失效源自單體式架構（monolithic architecture）中的結構糾纏（structural entanglement）：在這種架構中，上下文扎根（contextual grounding）所需的大量搜尋負擔（search burden），耗盡了複雜推理（complex reasoning）所需的表徵容量（representational capacity）。為了解決這個問題，我們提出透過 DISCO（DIStributed long COntext scaling，分散式長上下文擴展）實現扎根與推理解耦（Grounding-Reasoning Disaggregation）。受 Apache Spark 等分散式計算框架（distributed computing framework）啟發，DISCO 將長上下文（long context）分片（shard）後，交由一個專責平行且局部化扎根的 Worker LLM（工作者模型）集群（fleet）處理。中央的 Driver LLM（驅動模型）透過強化學習（GRPO）訓練以最佳化規劃（planning），並協調執行：先將查詢（query）動態映射（map）為原子提取任務（atomic extraction task），再對收集到的證據（evidence）進行歸約（reduce），進而綜合（synthesize）出最終答案（final answer）。透過將推理（reasoning）與原始上下文雜訊（raw context noise）隔離，DISCO 有效消除了上下文衰減（context rot）。在 RULER-QA（100 萬個 token）上，DISCO 維持 78.4% 的準確率（accuracy），而標準基線（standard baseline）則崩潰殆盡。此外，它在 LongBench v2 上比全上下文模型（full-context model）高出最多 9.8 分，並且能與 Gemini-3-Pro-Preview 等前沿模型（frontier model）匹敵，同時將推理成本（inference cost）降低超過 80%，為穩健的長上下文推理（robust long-context inference）樹立了一個高效率的典範。

### 核心貢獻（3～5點）
- 提出扎根與推理解耦（Grounding-Reasoning Disaggregation）架構，將上下文扎根與綜合推理分離，解決單體式模型中因結構糾纏導致的上下文衰減問題。
- 設計 DISCO 分散式長上下文擴展框架，借鏡 Apache Spark 的 Map-Reduce 運算思想，以 Worker LLM 集群進行平行且局部化的上下文扎根，並由 Driver LLM 負責規劃與證據歸約。
- 透過 GRPO 強化學習訓練 Driver LLM，使其能動態將查詢拆解為原子提取任務，並協調多個 Worker 執行高效能的分散式長上下文推理。
- 在 RULER-QA（1M token）與 LongBench v2 上達到顯著效能提升，同時降低超過 80% 的推理成本，展現高效且穩健的長上下文推理能力。

### 適合對象
從事長上下文推理、大型語言模型系統架構、分散式推論與資訊檢索相關研究的學者與工程師；特別適合關注如何擴展 LLM 有效上下文視窗、降低推理成本，以及探索以解耦架構提升模型推理品質的讀者。

## 深度分析

#### 方法論解析

##### 1. 問題形式化：扎根（Grounding）與推理（Reasoning）的結構性糾纏
論文將長上下文任務定義為：給定長度為 L 的上下文序列 x = (x₁, ..., x_L)、查詢（query）q 與目標回應 y，單體式架構（monolithic architecture）以單一參數 θ 同時建模 Pθ(y | x, q)。作者引入潛在變數 z 表示隱藏在 x 中的離散證據（evidence）集合，並將聯合機率分解為：

Pθ(y | x, q) = Σ_z Pθ(y | z, q) · Pθ(z | x, q)

其中 Pθ(z | x, q) 對應上下文扎根（contextual grounding），Pθ(y | z, q) 對應推理（reasoning）。在單體式典範（monolithic paradigm）下，同一組參數與單一注意力視窗（context window）必須同時逼近這兩項。隨著 L 增加，相關資訊稀疏分布，注意力機制（attention mechanism）難以區分訊號與雜訊，導致上下文衰減（context rot）與 lost-in-the-middle 現象。此時模型並非缺乏推理能力，而是因為證據扎根崩潰，使後續推理無法建立在可靠事實上。

##### 2. DISCO 的分散式架構
DISCO（DIStributed long COntext scaling）借鏡 Apache Spark 等分散式計算框架（distributed computing framework），將長上下文視為持久化分散式資料（persistent distributed data），並採用 Driver-Worker 架構：

- **Worker LLM（Worker LLM，工作者模型）**：負責局部高保真上下文扎根（local high-fidelity grounding）。原始上下文被切分為 K 個資料分片（data shard）{x⁽ᵏ⁾}，每個 Worker 僅處理自己的分片，提取局部證據：
  z⁽ᵏ⁾ ~ Pθ_W(· | x⁽ᵏ⁾, q)

- **Driver LLM（Driver LLM，驅動模型）**：作為中央規劃與綜合單元，不直接接觸原始上下文 x，而是基於聚合後的證據進行全局綜合（global synthesis）與最終推理：
  z ~ Pθ_D(· | ⊕_{k=1}^K z⁽ᵏ⁾, q)
  y ~ Pθ_D(· | z, q)

透過將雜訊密集的原始上下文替換為高密度證據 z，Driver 恢復了注意力機制的保真度，使複雜推理（complex reasoning）不再被大規模輸入干擾。

##### 3. 查詢分解與動態 DAG
為了彌補輕量 Worker 在多跳（multiple hops）查詢上的推理深度不足，DISCO 將查詢分解為動態有向無環圖（Directed Acyclic Graph, DAG）。Driver 作為高階規劃器（planner），將使用者查詢映射為可平行化的原子提取任務（atomic extraction task），即 Map（映射）運算；隨後將各 Worker 回傳的證據進行 Reduce（歸約）運算，進行全局推理並產生最終答案（final answer）。

此設計帶來兩項關鍵的純推理時間擴展（inference-time scaling）特性：
- 上下文增長時，增加 Map 動作與 Worker 數量即可平行擴展；
- 推理複雜度增加時，增加 Wide-dependency 動作與迭代規劃深度即可應對。

系統會動態重新規劃 DAG，直到收集到足夠證據為止，這使 DISCO 能處理開放式、多階段的長上下文問答。

##### 4. Driver 的強化學習調校
DISCO 提供原生環境以進行強化學習（Reinforcement Learning, RL）。論文採用 GRPO（Group Relative Policy Optimization，群組相對策略最佳化）訓練 Driver，目標是學習最佳執行計畫（planning），包括：
- 如何將查詢切分為適當的原子提取任務；
- 如何決定 Worker 調度順序與迭代次數；
- 如何從雜訊或冗餘證據中篩選並綜合出有效資訊。

透過 RL tuning，Driver 能逐步學會產生精確推理路徑（precise reasoning path），進一步放大 DISCO 在推理密集型基準測試（reasoning-intensive benchmark）上的優勢。

#### 實驗數據解讀

##### 1. RULER-QA（1M token）上的穩健性
論文在 RULER-QA（百萬 token 問答基準測試）上進行評估，結果顯示：
- DISCO（以 Qwen3-8B 為基礎）在 1M token 長度下維持 **78.4% 準確率（accuracy）**；
- 標準檢索基線模型（retrieval baseline）則崩潰至 **10.9%**。

這項結果直接驗證了「上下文衰減（context rot）可被結構性解耦消除」的核心假說。傳統檢索方法雖然能降低輸入長度，但在極長序列中難以定位真正相關的稀疏證據；DISCO 透過平行化、局部高保真扎根，再交由 Driver 綜合，顯著提升了極長上下文下的證據召回與推理穩定性。

##### 2. LongBench v2 上的推理品質
在 LongBench v2（長上下文綜合基準測試）上：
- DISCO 相較於全上下文基線（full-context baseline）最高提升 **9.8 分**（以 Qwen3-14B 為基礎，Long subset）；
- RL tuning 進一步放大增益。

這說明單純將全部上下文塞入模型（full-context model）並非最佳策略：即使模型宣稱支援百萬 token 上下文視窗（million-token context window），其有效上下文視窗（effective context window）與表徵容量（representational capacity）仍會被原始上下文雜訊（raw context noise）稀釋。DISCO 透過先提煉事實子集（subset of facts），再讓 Driver 進行綜合（synthesis），反而能釋放出更強的複雜推理能力。

##### 3. 與前沿模型的成本效益比較
論文指出 DISCO 能夠：
- 達到與 Gemini-3-Pro-Preview 等前沿模型（frontier model）相當的效能；
- 同時將推理成本（inference cost）降低 **超過 80%**。

這凸顯了 DISCO 在經濟規模化（economic scaling）上的潛力：透過將大量上下文扎根工作卸載至多個輕量 Worker，並以單一 Driver 執行高階推理，整體運算量遠低於讓大型單體模型處理全部 token。對於實際部署而言，這意味著企業與研究機構可能以較小模型組合達到頂尖長上下文推理表現。

##### 4. 數據解讀的注意事項
儘管數據亮眼，仍需留意：
- 論文未詳細說明 RULER-QA 與 LongBench v2 的完整實驗設定，例如 Worker 數量、分片大小、DAG 迭代次數等；
- 成本比較可能基於特定硬體配置與模型定價，實際節省比例會隨部署環境而異；
- 與 Gemini-3-Pro-Preview 的比較可能僅限於特定子任務，未必涵蓋所有長上下文能力維度。

#### 與現有研究的比較

##### 1. 相較於單體式長上下文模型
近期 LLM 不斷擴展上下文視窗（OpenAI, 2023; Huang and Yang, 2025; Guo et al., 2025），但這些單體式架構（monolithic architecture）仍面臨結構性糾纏（structural entanglement）：上下文扎根與推理共享同一表徵容量。DISCO 的解耦設計從根本上分離這兩個階段，使模型不再因搜尋負擔（search burden）而犧牲推理品質（reasoning quality）。

##### 2. 相較於檢索增強生成（RAG）與序列式分塊方法
現有許多長上下文方法將上下文切分為區塊（chunk），並以序列方式處理（serially）。這類方法雖然能應用完整 LLM 級理解（full LLM-grade understanding）於每個區塊，但會產生：
- **線性延遲（linear latency）**：區塊數量增加時，處理時間線性增長；
- **脆弱的跨步驟狀態管理（cross-step state management）**：多跳推理時，前後步驟狀態容易退化。

DISCO 透過資料平行計算（data-parallel computing）與動態 DAG，實現深度且可平行化的扎根（deep, parallelizable grounding），並將跨區塊綜合交由單一 Driver 統一處理，避免了序列狀態衰減。

##### 3. 相較於記憶增強架構
記憶增強架構（memory-augmented architecture）試圖內化長程保留能力，但論文指出這類方法通常需要從頭預訓練（pre-training from scratch），成本高昂且泛化性（generalization）尚未充分探索。DISCO 的優勢在於：
- 無需重新預訓練基礎模型；
- 可透過強化學習調校 Driver 快速適應新任務；
- 具備更好的可解釋性，因為證據提取與綜合過程明確分離。

##### 4. 相較於 Map-Reduce 與 Agentic 系統
DISCO 與 Map-Reduce 風格的多智能體系統有概念相似之處，但差異在於：
- 它明確以「扎根與推理解耦（Grounding-Reasoning Disaggregation）」為設計原則，而非僅是流程工程；
- Worker 被嚴格限制為局部上下文扎根，不進行全局推理，從而降低認知負荷（cognitive load）；
- Driver 透過 GRPO 學習規劃，而非依賴固定提示模板（prompt template）。

##### 5. 限制與潛在弱點
- **Driver 規劃錯誤會被放大**：若 Driver 將查詢分解為不適當的原子提取任務，Worker 即使扎根正確也無法取得所需證據。
- **分片邊界問題**：若關鍵事實橫跨多個資料分片（data shard），單一 Worker 可能無法完整提取，需要額外的重疊分片或跨分片機制。
- **延遲與成本的權衡**：雖然總推理成本降低，但多 Worker 平行調度可能引入通訊與同步開銷，對低延遲應用仍是挑戰。
- **RL 訓練資料需求**：GRPO 訓練 Driver 需要高品質的長上下文規劃軌跡，這類資料可能難以取得。

## 論文問答

**Q1：什麼是「上下文衰減」（context rot），為什麼它會在單體式大型語言模型中發生？**

A：上下文衰減是指當輸入長度增加時，大型語言模型的推理品質顯著下降的現象。它源自單體式架構中的結構糾纏：同一組參數與暫態注意力機制必須同時負責上下文扎根與複雜推理，導致搜尋負擔耗盡表徵容量。隨著上下文變長，注意力機制難以區分訊號與雜訊，甚至出現「lost-in-the-middle」問題，最終使模型不是因缺乏推理能力而失敗，而是因證據扎根崩潰而失敗。

**Q2：現有的長上下文方法為什麼無法根本解決這個問題？**

A：現有方法大致可分為檢索基線與分塊序列處理，但兩者都無法同時達成深度且可平行化的扎根，並將其與推理結構性隔離。檢索基線在 RULER-QA 等百萬 token 任務上會崩潰；分塊方法雖對每個區塊套用完整 LLM 級理解，卻只能序列處理，帶來線性延遲與脆弱的跨步驟狀態管理，在多跳推理中逐漸劣化。記憶體增強架構雖是替代方向，但目前需要從頭預訓練，成本過高且泛化性尚未充分探索。

**Q3：為什麼將上下文扎根與推理解耦對長上下文推理如此重要？**

A：將上下文扎根與推理解耦，可以讓複雜推理只在高度精煉的事實子集上進行，避免原始上下文雜訊干擾推理過程。透過獨立且平行化的扎根階段，模型能將資訊檢索的重擔交給專責的工作者模型，從而保護驅動模型的推理能力不被規模壓垮。這種結構性分離不僅提升準確率，也為高效且高保真的長上下文推理奠定基礎。

**Q4：DISCO 的核心架構是什麼，它如何類比 Apache Spark 的設計？**

A：DISCO 把長上下文視為持久化分散式資料，類比 Apache Spark 的運算節點與運算記憶體限制。它將上下文切分為資料分片，由一群 Worker LLM 各自在局部高保真視窗內執行扎根；中央 Driver LLM 則像 Spark 的驅動程式，負責規劃、把查詢映射為原子提取任務，再將各 Worker 回傳的證據歸約成最終答案。當上下文增長時增加映射運算，當推理複雜度提高時增加寬依賴動作，實現純推理時間的擴展。

**Q5：DISCO 如何用機率形式化扎根與推理解耦？**

A：DISCO 引入潛在變數 z 表示隱藏在長文本中的離散證據片段，將生成機率分解為 P(y|x,q) = P(y|z,q) · P(z|x,q)。單體式架構用單一參數同時逼近扎根與推理兩項，導致注意力機制在長序列中難以定位訊號；DISCO 則把上下文分片，令每個 Worker 獨立估計局部扎根 P(z(k)|x(k),q)，再由 Driver 進行全局綜合。如此一來，Driver 的條件輸入從雜訊重的原始上下文 x 替換為高密度的證據 z，恢復了注意力機制的保真度。

**Q6：Driver LLM 在 DISCO 中扮演什麼角色，又是如何被訓練的？**

A：Driver LLM 是 DISCO 的中央規劃與綜合單元，它把使用者查詢分解為動態有向無環圖中的原子提取任務，並在證據不足時反覆重新規劃。它不直接讀取原始上下文，而是根據各 Worker 回傳的局部證據進行全局綜合，再生成最終答案。為了學習最佳執行計畫，作者使用 GRPO（群組相對策略最佳化）對 Driver 進行強化學習調校，使其在推理階段產生更精確的推理路徑。

**Q7：論文使用了哪些基準測試，主要實驗結果為何？**

A：論文在 RULER-QA 的百萬 token 問答任務上測試，DISCO 搭配 Qwen3-8B 維持 78.4% 準確率，而標準檢索基線則崩潰至 10.9%。在 LongBench v2 的長子集上，DISCO 以 Qwen3-14B 為基礎，比全上下文基線高出最多 9.8 分，且強化學習調校進一步放大增益。此外，DISCO 在達到與 Gemini-3-Pro-Preview 等前沿模型相當表現的同時，將推理成本降低超過 80%。

**Q8：與全上下文模型和前沿模型相比，DISCO 在準確率與成本上各有什麼優勢？**

A：與全上下文模型相比，DISCO 在推理密集型基準測試上顯著提升準確率，因為它把推理與原始上下文雜訊隔離。與 Gemini-3-Pro-Preview 等前沿模型相比，DISCO 能達到相近效能，卻不需要一次性處理全部百萬 token。這種分散式架構透過平行化局部扎根與精簡的中央綜合，把推理成本壓低八成以上，展現出經濟擴展的優勢。

**Q9：實驗中有哪些消融或調校洞見值得注意？**

A：實驗顯示，強化學習調校對 Driver 的規劃品質有顯著助益，能進一步放大 DISCO 在 LongBench v2 等任務上的增益。將強大且推理密集的 Driver 與輕量高效的 Worker 組成階層式架構，是兼顧成本與效能的關鍵設計。若缺少扎根與推理解耦，單一模型同時處理全部上下文會因上下文衰減而迅速失效，這凸顯了結構性分離的重要性。

**Q10：哪些實際應用場景最能受惠於 DISCO？**

A：DISCO 特別適合需要同時閱讀百萬級 token 並進行多跳推理的場景，例如法律文件審查、醫學文獻綜述、企業知識庫問答與大型程式碼庫分析。在這些應用中，相關事實稀疏分散於長文本各處，傳統單體式模型容易遺漏或混淆。DISCO 透過平行化局部扎根與中央綜合，不僅提升準確率，也降低延遲與推理成本，使長上下文應用更具商業可行性。

**Q11：在產品化部署 DISCO 時，需要考慮哪些工程議題？**

A：部署 DISCO 需要建構分片管理、Worker 集群排程與動態有向無環圖執行引擎，並確保 Worker 輸出能可靠地傳遞給 Driver。工程團隊必須在 Worker 模型大小與局部扎根保真度之間取捨，同時設計容錯與重新規劃機制以處理提取失敗。此外，Driver 的 GRPO 訓練管線、狀態持久化與 API 協調都會增加系統複雜度，需要額外的基礎設施投資。

**Q12：DISCO 可能對長上下文建模領域帶來什麼影響？**

A：DISCO 代表長上下文建模從「建造更大上下文視窗」轉向「以資料平行計算方式分散處理」的典範轉移。它證明透過扎根與推理解耦，中小型模型組成的系統也能匹敵甚至超越單一大型前沿模型。這可能激發更多階層式、專業化模型協作的架構研究，並降低對昂貴單體式百萬 token 模型的依賴。

**Q13：論文承認或暗示了哪些限制？**

A：論文指出記憶體增強架構雖是另一條路，但目前需要從頭預訓練且泛化性未明，因此 DISCO 選擇在推理階段進行結構解耦。DISCO 也假設每個資料分片都能納入 Worker 的高保真視窗，若分片過大或語意邊界不佳，局部扎根品質會下降。此外，整體效能高度依賴 Driver 的查詢分解能力與 Worker 的局部理解能力，任何一環出錯都可能影響最終答案。

**Q14：在哪些失敗案例中，DISCO 仍可能表現不佳？**

A：當查詢需要全局性語境理解，而無法拆成獨立的原子提取任務時，DISCO 可能難以正確綜合。若關鍵證據稀疏且跨越多個資料分片，並存在細微的跨分片依賴，輕量 Worker 可能因缺乏全局視野而遺漏或誤解。Driver 若對模糊查詢產生錯誤的 DAG 規劃，也會導致後續歸約與推理偏離正確答案；過多的迭代則可能抵銷平行化帶來的延遲優勢。

**Q15：DISCO 暗示了哪些未來研究方向？**

A：未來可進一步結合強化學習讓 Driver 自適應地調整規劃策略，並探索多層級 Worker 以處理更複雜的語意層次。共同訓練 Driver 與 Worker、引入記憶體增強機制作為輔助，以及將架構擴展至多模態長上下文與串流場景，都是值得研究的方向。此外，優化分片排程、快取與通訊開銷，將有助於 DISCO 在更長、更動態的輸入上維持高效且穩健的推理。

## 實務應用指南

### 適用場景

1. **大規模法律與金融文件盡職調查**  
   面對數百頁合約、年報、交易紀錄與法規條文，傳統單體式 LLM 容易因上下文雜訊而遺漏關鍵條款。DISCO 可將文件分片後由 Worker LLM 平行扎根，再由 Driver LLM 綜合多份證據，進行跨文件的多跳推理，例如「比較三家子公司在 2023 年的違約條款差異」。

2. **企業內部知識庫問答與決策輔助**  
   當知識來源涵蓋 Wiki、會議紀錄、郵件、技術文件與工單系統時，DISCO 能把原始上下文視為持久化分散式資料，先以 Worker 在各資料分片中提取相關事實，再由 Driver 規劃查詢路徑並給出最終答案，適合處理「這個專案過去六個月有哪些風險被討論過？」這類需要廣泛扎根的問題。

3. **大型程式碼庫理解與跨檔案除錯**  
   在百萬行等級的程式碼庫中，錯誤往往橫越多個模組與提交紀錄。DISCO 可將程式碼與 Git 歷史分片，讓 Worker 在各自區塊中定位相關函式、呼叫鏈與註解，Driver 則負責還原跨檔案的推理路徑，回答「為什麼這個 API 在 v2.3 後行為改變？」

4. **學術文獻與專利綜合研究**  
   研究人員需要從數十篇甚至上百篇論文中比較方法、數據與結論。DISCO 的 Map-Reduce 架構適合將每篇文獻視為一個資料分片，由 Worker 提取方法、實驗結果與限制，再由 Driver 進行系統性文獻回顧與趨勢綜合。

5. **長篇客服對話與醫療病歷摘要**  
   當輸入是數週甚至數月的對話紀錄或病歷時，DISCO 可分段提取關鍵事件、用藥紀錄與客訴重點，再由 Driver 生成時間軸式摘要與後續建議，避免單體式模型在長序列中遺失早期資訊。

### 實作前置條件

**資料條件**
- 原始長上下文資料需可切分為語意相對完整的資料分片（例如章節、檔案、對話回合），每個分片長度應落在 Worker LLM 的有效上下文視窗內。
- 需要準備查詢與對應證據的標註資料，用於評估 Worker 的扎根品質，以及作為 Driver 強化學習調校的獎勵信號來源。
- 若涉及多跳推理，資料中應包含跨分片的關聯事實，以便驗證 Driver 的規劃與綜合能力。

**運算條件**
- **Driver LLM**：建議使用推理能力較強的模型（如 Qwen3-14B 或更大規模模型），負責查詢分解、DAG 規劃與最終綜合。
- **Worker LLM 集群**：可使用輕量高效模型（如 Qwen3-8B），數量隨上下文長度與查詢複雜度彈性擴展。
- **排程與通訊基礎設施**：需要能平行呼叫多個 Worker、收集輸出、管理狀態的系統，可借鏡 Apache Spark 的資料平行計算概念，或使用現有的分散式推理框架。
- **強化學習訓練資源**：若採用 GRPO 訓練 Driver，需要足夠的 GPU 記憶體與採樣預算，以產生多組執行計畫並計算相對獎勵。

**技能條件**
- 熟悉 LLM 推理與提示工程，能設計扎根導向的 Worker 提示與綜合導向的 Driver 提示。
- 具備分散式系統基礎，能處理平行呼叫、錯誤重試、結果彙整與快取。
- 了解強化學習流程，特別是策略梯度方法與 GRPO 的獎勵設計。
- 具備領域知識，能判斷資料分片策略與評估最終答案品質。

### 實作步驟建議

1. **問題定義與分片策略設計**  
   先釐清查詢類型（單一事實查詢、多跳推理、摘要、比較），並決定分片單位。分片應盡量保留語意邊界，例如以文件、章節或函式為單位，而非任意 token 切分。

2. **建立 Worker 扎根管線**  
   為每個 Worker LLM 設計提示，要求其在指定資料分片中提取與查詢相關的事實、片段或邏輯謂詞，並輸出結構化證據（例如 JSON 格式，包含來源位置、置信度與摘要）。

3. **實作 Driver 的規劃與綜合模組**  
   讓 Driver 先將使用者查詢分解為原子提取任務，動態建立 DAG。每個 Map 節點對應一個 Worker 任務，Reduce 節點則將收集到的證據歸約為全局觀點，最終生成最終答案。

4. **引入迭代式重新規劃**  
   當 Driver 發現證據不足或存在衝突時，應能動態新增 Map 任務，要求 Worker 針對特定分片進行更深入扎根，直到滿足停止條件（如證據覆蓋率或置信度門檻）。

5. **以 GRPO 調校 Driver**  
   在標註資料上，讓 Driver 對同一查詢產生多組執行計畫，根據最終答案準確率、證據覆蓋率與推理路徑精確度計算相對獎勵，透過群組相對策略最佳化提升規劃品質。

6. **建構評估與監控機制**  
   在 RULER-QA、LongBench v2 等長上下文基準測試上驗證，同時建立內部評估集，追蹤上下文衰減、多跳推理成功率與推理成本。

7. **部署與成本最佳化**  
   實作 Worker 輸出快取、重複查詢的 DAG 重用、以及依查詢複雜度動態調整 Worker 數量的機制，確保在維持高準確率的同時降低推理成本。

### 潛在風險與注意事項

| 風險 | 說明 | 因應措施 |
|---|---|---|
| **分片邊界切斷關鍵證據** | 若相關事實橫跨兩個分片，單一 Worker 可能無法完整提取。 | 採用重疊分片或鄰近分片聯合扎根策略，並讓 Driver 能偵測缺口後重新指派任務。 |
| **Driver 過度依賴不完整證據** | Worker 遺漏或誤判可能導致 Driver 在錯誤基礎上推理。 | 要求 Worker 輸出置信度與反證，Driver 在綜合前進行衝突檢測與多源交叉驗證。 |
| **延遲與成本反轉** | 當 Worker 數量過多或 DAG 過深時，平行化的優勢可能被協調開銷抵銷。 | 設定 Worker 數量上限與總 token 預算，對簡單查詢直接走捷徑或回退到較短上下文模型。 |
| **強化學習訓練不穩定** | GRPO 獎勵設計不當可能讓 Driver 學會生成冗長但無用的計畫。 | 獎勵函數應同時考量準確率、成本與計畫簡潔度，並使用多組獨立採樣降低方差。 |
| **隱私與資料治理** | 將敏感文件分發給多個 Worker 可能增加暴露風險。 | 實作分片級存取控制、去識別化前處理，並在私有環境中部署 Worker 集群。 |
| **幻覺與來源不可追溯** | Driver 綜合時可能生成未出現在證據中的內容。 | 強制最終答案必須引用 Worker 提供的來源分片，並提供可驗證的證據鏈。 |

### 與其他技術的整合建議

- **與 RAG 管線結合**：可將向量資料庫作為第一階段篩選器，先召回最相關的資料分片，再交由 DISCO 的 Worker 進行深度扎根，兼顧效率與高保真推理。
- **接入 Agent 框架**：透過 LangChain、LlamaIndex 或自研 Agent 框架，將 DISCO 封裝為一個可重複使用的長上下文工具，讓其他 Agent 呼叫其 Map-Reduce 能力。
- **使用分散式運算框架排程**：雖然 DISCO 是邏輯架構，但其靈感來自 Apache Spark，實際部署時可借鏡 Spark/Dask 的任務排程、容錯與資料局部性概念來管理 Worker 任務。
- **整合 API 閘道與觀測系統**：在生產環境中，透過 API 閘道統一管理查詢入口，並將每個 DAG 節點的輸入輸出、延遲與成本記錄到可觀測平台，便於後續除錯與 RL 資料回收。
- **與評估平台連動**：將 DISCO 的執行結果自動匯入評估系統，持續比較全上下文基線、檢索基線與 DISCO 的表現，作為模型迭代與成本優化的依據。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從「上下文衰減」與「單體式架構」的直覺理解開始，把 DISCO 想像成「一位主管（Driver）帶領多位助理（Workers）分頭查資料，最後再開會綜合結論」。重點掌握 Map 與 Reduce 的分工、為什麼分開扎根與推理能提升準確率，以及長上下文任務在實務上的挑戰，數學公式與 GRPO 細節可先略過。

**AI 工程師**  
請聚焦於第 2 節的架構設計與實作細節，特別是資料分片策略、Worker 提示設計、Driver 的 DAG 規劃與迭代重新規劃機制。建議同時評估自己手邊的推理基礎設施是否能支撐平行 Worker 呼叫，並思考如何將 GRPO 訓練整合到現有的模型微調流程中。

**研究人員**  
建議深入閱讀 Grounding-Reasoning Disaggregation 的理論動機（§2.1）與機率分解，評估其與現有記憶增強架構、RAG、Chain-of-Thought 等方法的關係。可進一步探討的問題包括：最優分片大小的理論保證、GRPO 獎勵函數對多跳推理的影響，以及在不同領域資料上的泛化性。

**產品經理**  
請將重點放在實驗結果與成本效益：DISCO 在 RULER-QA 與 LongBench v2 上的準確率提升、與 Gemini-3-Pro-Preview 相當但推理成本降低超過 80% 的商業意義。同時評估自家產品中哪些長上下文場景最適合導入，並規劃與現有 RAG 或知識庫產品的整合路徑與上線風險。
