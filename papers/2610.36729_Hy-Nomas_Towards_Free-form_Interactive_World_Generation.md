Hy-Nomas 的方法論核心在於解決互動式世界生成（Interactive World Generation）中的兩個根本性挑戰：**時間因果性（Temporal Causality）**與**多模態指令協調（Multimodal Instruction Coordination）**。整體架構以 HunyuanVideo 1.5（8B 參數擴散 Transformer，DiT）為基礎骨幹（Backbone），透過四個相互耦合的設計模組實現功能。

**1. 結構化影片字幕（Structured Video Captioning）與資料管線**

資料層面採用四階段管線：預處理（Preprocessing）、資料分佈（Data Distribution）、影片標記（Video Tagging）與訓練階段（Training Stages）。預處理階段透過解析度、長寬比、時長等影片屬性過濾與階層式聚類（Hierarchical Clustering）進行視覺品質篩選與去重。影片字幕生成採用結構化標註，記錄**持久主體身分（Persistent Subject Identities）**、**場景變化（Scene Changes）**與**時間戳動作（Timestamped Actions）**，並搭配估計的攝影機軌跡（Camera Trajectories）。這種結構化設計使後續的注意力遮罩（Attention Mask）能精確區分描述性內容與動作指令。

**2. 動作感知因果注意力（Action-aware Causal Attention）**

這是 Hy-Nomas 最具創新性的架構設計。傳統的因果注意力（Causal Attention）僅保證時間序列上的單向資訊流，但無法處理「描述性上下文應跨片段持續可用，而動作指令僅在其指定時間窗口內生效」的需求。Hy-Nomas 的解決方案是將字幕拆分為兩類：

- **描述性上下文（Descriptive Context）**：包含場景、主體身分、整體氛圍等資訊，透過全注意力（Full Attention）使其在後續所有片段中持續可訪問。
- **動作指令（Action Instructions）**：僅在原始片段及其標註的時間窗口（Temporal Window）內生效，透過限制性遮罩（Restrictive Mask）防止動作指令洩漏到不相關的時間段。

這種分離設計避免了「重複發送動作指令導致動作重複執行」的問題，同時保留了動作的視覺後果（Visual Consequences）。

**3. 攝影機軌跡條件化（Camera-Trajectory Conditioning）**

攝影機控制採用軌跡條件化機制，使模型能接收連續的攝影機運動指令。混合文字與攝影機條件化訓練支援兩種互動模式的無縫切換。具體實作細節在第 3.2 節描述，應涉及將攝影機參數（如位置、旋轉、視角）編碼後注入擴散模型的條件機制中。

**4. 提示增強器（Prompt Enhancer, PE）**

PE 是一個視覺語言模型（VLM），負責將使用者的自由形式請求（Free-form Requests）與多模態互動歷史（Multimodal Interaction Histories）轉換為下一片段的結構化條件，包含適當的時長估計。這解決了使用者輸入的模糊性與模型所需精確結構化條件之間的鴻溝。

**5. 多階段訓練課程（Multi-stage Curriculum）**

訓練策略採用漸進式課程學習（Curriculum Learning）：

| 階段 | 內容 |
|------|------|
| 持續預訓練（Continual Pre-Training） | 從 HunyuanVideo 1.5 開始適應 |
| 因果生成（Causal Generation） | 引入片段因果性 |
| 文字互動（Text Interaction） | 加入動作感知因果注意力 |
| 攝影機控制（Camera Control） | 整合軌跡條件化 |
| 高品質退火（High-Quality Annealing） | 提升生成品質 |
| 片段強制（Segment Forcing） | 在模型自身生成的歷史上訓練 |
| 擴散蒸餾（Diffusion Distillation） | 加速推論 |

**片段強制（Segment Forcing）**尤為關鍵：因為每個生成的片段會成為下一片段的歷史，小錯誤會累積導致外觀漂移（Appearance Drift）、不合理的運動與場景崩潰，因此模型必須在自身不完美的預測上訓練。

**6. 訓練基礎設施（Training Infrastructure）**

為支援可變長度影片的訓練，採用：

**2. 架構層面的改進**

- **評估範圍**：人類評估的規模與多樣性未在可見內容中詳細說明。
- **泛化性**：在訓練分佈外的場景與動作類型表現未明確驗證。

**5. 與遊戲 AI、機器人世界模型的關係**

Hy-Nomas 與遊戲 AI（如 GameNGen）、機器人世界模型（如 DreamerV3）共享世界模型概念，但聚焦於**視覺生成品質**而非策略學習，這是應用導向的差異。

作者已指出當前模型的關鍵局限：時間因果性不等於物理因果性。未來方向包括：
- 整合物理模擬引擎（如基於 NeRF 或 3D Gaussian Splatting 的物理模型）
- 引入物理一致性損失函數（Physics Consistency Loss）
- 結合動作預測與視覺預測的聯合訓練

**2. 更高階的因果注意力機制**

當前的動作感知因果注意力是二元分離（描述性 vs. 動作性），未來可探索：
- **多層次時間注意力**：支援不同時間尺度的因果關係
- **物件級因果追蹤**：追蹤特定物件的因果鏈
- **反事實推理（Counterfactual Reasoning）**：回答「若不執行該動作會如何」

**3. 擴展互動模態**

目前支援文字與攝影機控制，未來可整合：
- **音訊生成**：同步環境音與動作音效
- **觸覺/力回饋**：對機器人應用至關重要
- **多代理人互動**：支援多使用者或多 NPC 互動

**4. 效率提升與即時互動**

- **更激進的擴散蒸餾**：從當前蒸餾進一步減少取樣步數
- **快取壓縮技術**：減少長時互動中的 KV 快取記憶體
- **流式生成（Streaming Generation）**：支援真正的即時互動而非批次生成

**5. 評估方法的標準化**

Hy-Nomas-Bench 是重要一步，但未來需要：
- **更大規模的人類評估協議**
- **自動化因果一致性指標**
- **跨系統的公平比較框架**

**6. 安全與倫理考量（Safety and Ethics）**

互動式世界模型的潛在濫用風險（如深偽內容生成、操縱性內容）需要：
- **內容審查機制**
- **浮水印與溯源技術**
- **使用政策與紅隊測試（Red Teaming）**

**7. 與遊戲引擎、神經渲染的融合**

未來可能出現**混合架構**：
- 神經渲染處理視覺品質
- 傳統遊戲引擎處理邏輯與物理
- LLM 處理敘事與 NPC 行為

**8. 領域特定適應**

透過 LoRA 工作流程，可探索：
- 醫療模擬訓練
- 自動駕駛場景生成
- 工業機器人訓練環境

這些方向將使 Hy-Nomas 從通用世界模型演變為特定領域的實用工具，推動互動式世界生成從研究走向實際應用。

## 論文問答

**Q1：什麼是「互動式影片世界模型」，它與傳統影片生成任務的根本差異為何？**
A：互動式影片世界模型是一種在使用者輸入指令時即時渲染未來視覺觀察的虛擬環境，其核心特徵在於「封閉式互動迴路」——使用者觀察當前世界、做出行動決策，模型再根據指令與先前的互動歷史生成新的視覺觀察。相較之下，傳統影片生成通常以一個固定的提示詞預先指定一段短影片，屬於「一次性」生成。這種差異意味著互動式世界模型必須容納在生成過程中到來的輸入指令、建模動作相關的動態，並保留先前動作的後果，因此對時序因果性、歷史一致性和指令遵循能力都提出了遠高於傳統影片生成的要求。

**Q2：為何現有的影片生成模型無法直接應用於互動式世界生成？**
A：現有的影片生成模型多採用預訓練的雙向擴散 Transformer（DiT），其注意力機制本質上是雙向而非因果的，因此無法直接用於需要嚴格時序因果性的互動式場景。僅僅將完整注意力替換為因果遮罩並不足以解決問題，因為模型還需要適應從可用歷史生成連續片段、遵循當前使用者指令、避免破壞因果性的資訊洩漏，並支援快取上下文的高效重用。更棘手的是，每個生成的片段都會成為下一片段的證據，小錯誤會累積成外觀漂移、不合理的運動甚至場景崩潰，因此訓練必須讓模型為其自身不完美的預測做好準備，這是傳統影片生成模型未曾面對的挑戰。

**Q3：為什麼「物理因果性」比「時序因果性」更難以實現？**
A：僅僅實現時序因果性的資訊流並不足以建立真正的物理因果性，因為物理因果性要求模型學習合理的「動作到狀態」的轉換關係，而不僅僅是「下一步該發生什麼」。這需要訓練資料能夠將動作與其可觀察的後果連結起來，並透過評估來測試這些行為在連續互動中的表現。換言之，模型必須理解「為什麼這個動作會導致這個結果」，這對資料標註的細粒度、模型架構的歸納偏置以及訓練策略的設計都提出了更深層的要求，是當前世界模型研究的核心難題之一。

**Q4：Hy-Nomas 的核心方法架構是什麼？**
A：Hy-Nomas 的核心方法架構圍繞著「結構化影片字幕」與「動作感知因果注意力」的協同設計展開。模型透過結構化影片字幕記錄持久的主體身分、場景變化與時間戳記的動作，並結合估計的攝影機軌跡進行條件化。在注意力機制上，描述性文字在後續片段中保持可用，而動作特定文字則被限制在其原始片段與註明的時間窗口內，這種分離設計既能保留描述性上下文與動作的視覺後果，又避免重複發出相同動作指令，從根本上解決了「動作何時生效」與「場景如何延續」之間的張力。

**Q5：Prompt Enhancer（PE）在系統中扮演什麼關鍵角色？**
A：Prompt Enhancer（PE）是一個視覺語言模型（VLM），負責將使用者的請求與當前觀察轉換為下一片段的結構化提示，並決定適當的持續時間。PE 的關鍵作用在於橋接自由形式的使用者輸入與模型所需的結構化條件，使模型能夠同時處理文字指令與多模態互動歷史。透過 PE 的轉譯，使用者可以交錯輸入自由形式文字提示與攝影機控制指令，而歷史的視覺與語意上下文則透過自迴歸的 KV 快取向前傳遞，這使得「使用者說什麼」與「模型如何理解」之間的轉譯鴻溝得以有效填補。

**Q6：Hy-Nomas 的多階段訓練課程是如何設計的？**
A：Hy-Nomas 的訓練課程從 HunyuanVideo 1.5 開始，逐步引入片段因果性、局部化動作條件化與攝影機控制，接著進行高品質退火與片段強制訓練，最終透過擴散蒸餾提升效率。這種漸進式設計讓模型先掌握基本的因果生成能力，再學習處理文字互動，最後整合攝影機控制與模型自身生成歷史的訓練，使模型能力穩步建構而非一次性承受過多任務。為了使這種訓練切實可行，系統結合了高壓縮率的影片自動編碼器、可變長度影片的 FLOPs 平衡打包、執行異質遮罩的注意力核心、分散式序列與模型狀態分片，以及階段相依的記憶體管理，支援長達 360K token 的打包序列。

### 適用場景

**1. 遊戲開發與關卡原型設計**
Hy-Nomas 可作為遊戲工作室的快速原型工具，設計師輸入文字指令（如「玩家進入森林營地，營火被點燃」）並搭配攝影機軌跡，即可在數分鐘內產出可探索的場景預覽影片，用於評估關卡氛圍、敘事節奏與玩家視角，無需等待美術團隊建模貼圖。對於獨立遊戲或前期概念驗證特別有價值。

**2. 電影與廣告的 Pre-vis（預視覺化）**
導演與攝影指導可在拍攝前以文字描述場景動作（如「主角推開門走入雨中，鏡頭從背後跟拍」）並指定攝影機運動，產出近似成片品質的動態分鏡。這對於高成本動作場面、複雜特效或需要向投資方提案的場景尤其實用，可大幅降低溝通成本。

**3. 機器人與自駕車的合成資料生成**
將機器人手臂動作指令、無人機飛行路徑或自駕車駕駛行為作為「動作指令」輸入，搭配真實或模擬的環境文字描述，可生成大量帶有動作—後果對應關係的訓練影片，用於補強真實資料中難以覆蓋的邊角情境（corner cases）。

**4. 建築與室內設計的沉浸式導覽**
建築師輸入設計說明（如「客戶走進客廳，落地窗外是海景，鏡頭向右旋轉 90 度」），即可生成具備真實光影與材質感的導覽影片，用於業主提案或行銷素材。相較於傳統 3D 渲染，文字驅動的方式更貼近非技術背景客戶的溝通習慣。

**5. 教育訓練與緊急應變模擬**
在醫療、消防、工業操作等領域，可建構「虛擬實習」環境：學員以文字下達處置指令（如「給予腎上腺素 0.3mg」），模型生成對應的視覺後果與場景演變，提供可重複、低風險且可記錄的訓練體驗。

### 實作前置條件

**資料需求**
- **影片來源**：需蒐集具備物理互動、人類與物體運動、攝影機運動的影片資料集，原始素材規模建議在數十萬至數百萬片段級別。
- **影片字幕（Captions）**：需具備結構化字幕能力，能標註主體身分持續性、場景變化與時間戳動作；可借助 GPT-4V、Gemini 等視覺語言模型進行批次標註，但需人工抽樣校驗。
- **攝影機軌跡**：需使用 COLMAP、VGGT 或 DROID-SLAM 等工具從影片估計攝影機姿態，並過濾估計失敗的片段。
- **資料過濾管線**：解析度、長寬比、時長、視覺品質的分層過濾與去重機制（論文中採用階層式聚類）。

**算力需求**
- **訓練**：8B 參數擴散模型的完整訓練需大量 GPU（如 H100/H200 叢集），單機多卡難以勝任；論文中採用模型與資料並行、序列分片、注意力異質遮罩等技術，支援長達 360K token 的打包序列。
- **推論**：單次生成一個片段需多張高階 GPU；擴散蒸餾後可降低即時性需求，但仍建議至少 1–2 張高階 GPU。
- **儲存**：高壓縮影片自編碼器（如 HunyuanVideo 1.5 使用的 Causal 3D VAE）可顯著降低儲存成本，但原始影片與中間特徵仍需數 TB 至 PB 級儲存空間。

**技能門檻**
- 熟悉擴散模型（DiT）架構、影片擴散模型訓練流程。
- 具備分散式訓練經驗（FSDP、ZeRO、序列並行）。
- 對視覺語言模型（VLM）有基本理解，以便整合 Prompt Enhancer。
- 具備影片處理、攝影機姿態估計的工程能力。
- 若進行 LoRA 微調，則需熟悉 PEFT 工具鏈。

1. 蒐集符合領域需求的影片素材，建立原始資料池。
2. 建立資料過濾管線：解析度、長寬比、時長、視覺品質分層過濾 → 階層式聚類去重 → 分類標註。
3. 估計攝影機軌跡並過濾失敗樣本。
4. 使用視覺語言模型產生結構化字幕，標註主體身分、場景變化、時間戳動作。
5. 將資料切分為訓練集、驗證集與 Hy-Nomas-Bench 風格的評測集。

**階段二：基礎模型建構（預估 8–12 週）**
1. 採用 HunyuanVideo 1.5 或同類影片擴散模型作為起點。
2. 替換注意力機制為「片段式因果注意力（Segment-wise Causal Attention）」：描述性文本跨片段可見，動作指令僅在其時間窗口內可見。
3. 加入攝影機軌跡條件化模組，支援文字與攝影機雙模式切換。
4. 整合高壓縮影片自編碼器，降低 token 數量。

**階段三：課程式訓練（預估 12–16 週）**
1. **持續預訓練**：在大型影片資料上進行通用影片生成預訓練。
2. **因果生成階段**：引入片段式因果注意力，學習自迴式片段生成。
3. **文字互動階段**：加入動作感知條件化，學習遵循文字指令。
4. **攝影機控制階段**：混合文字與攝影機條件訓練。
5. **高品質退火**：使用精選高品質資料微調，提升視覺品質。
6. **片段強制（Segment Forcing）**：在模型自身生成的歷史條件下訓練，緩解誤差累積。
7. **擴散蒸餾**：將多步去噪蒸餾為少步，提升推論效率。

**階段四：推論系統建構（預估 4–6 週）**
1. 部署 Prompt Enhancer（基於 VLM），將使用者請求與多模態互動歷史轉換為結構化條件。
2. 實作 KV 快取機制，跨片段重用歷史上下文。
3. 整合擴散蒸餾後的少步採樣器。
4. 建立使用者介面（CLI、Web UI 或 API），支援文字與攝影機指令的交錯輸入。

**階段五：領域適配與產品化（預估 4–8 週）**
1. 使用 LoRA 對特定領域（如特定遊戲風格、建築類型）進行輕量微調。
2. 建立評測流程：使用 Hy-Nomas-Bench 風格的人類評估協議。
3. 整合至下游系統（遊戲引擎、3D 工具鏈、機器人模擬平台）。
4. 建立監控與回饋機制，收集使用者互動資料以持續改進。

### 潛在風險與注意事項

**風險一：誤差累積導致場景崩壞**
- **現象**：自迴式生成中，每個片段的微小偏差會在後續片段放大，造成主體外觀漂移、運動不自然甚至場景崩潰。
- **緩解**：採用「片段強制」訓練策略，讓模型在自身生成的歷史條件下學習；建立自動偵測機制，當漂移超過閾值時觸發場景重置或使用者介入。

**風險二：時間因果 ≠ 物理因果**
- **現象**：模型可能學會「時間上正確」的序列，但缺乏真實的物理因果推理（如物體應因動作而移動，而非僅在時間上對齊）。
- **緩解**：在資料階段優先選擇具備明確物理互動的影片；在評測階段設計專門測試動作—後果對應的基準（論文中 Hy-Nomas-Bench 即為此設計）。

**風險三：動作指令洩漏至非目標片段**
- **現象**：若注意力遮罩設計不當，動作指令可能影響前後片段，破壞「動作僅在其時間窗口生效」的設計目標。
- **緩解**：嚴格審查片段式因果注意力的遮罩實作；建立單元測試驗證特定動作指令僅影響對應時間區段。

**風險四：算力與成本過高**
- **現象**：8B 模型 + 長序列訓練對算力需求極高，可能超出中小團隊預算。
- **緩解**：採用擴散蒸餾降低推論成本；使用 LoRA 進行領域適配而非全參數微調；考慮使用雲端隨選 GPU 資源。

**風險五：主體身分與場景一致性難以維持**
- **現象**：當先前觀察過的內容重新進入畫面時，主體身分、場景佈局可能發生變化。
- **緩解**：在資料階段強化主體身分的字幕標註；在評測階段設計「返回視角」測試案例。

**風險六：攝影機與文字指令的協調衝突**
- **現象**：當攝影機指令與文字指令同時存在時，可能產生不一致的視覺結果。
- **緩解**：在 Prompt Enhancer 中明確區分兩類指令的優先級；在訓練階段使用混合模式資料，讓模型學會處理衝突情境。

### 與其他技術的整合建議

**與遊戲引擎整合（Unity / Unreal Engine）**
- 將 Hy-Nomas 作為「敘事預覽層」：遊戲邏輯觸發文字指令與攝影機軌跡，Hy-Nomas 產出對應的過場動畫或環境預覽。
- 透過 Unreal 的 Movie Render Queue 或 Unity 的 Recorder 將生成影片整合至既有管線。
- 注意：Hy-Nomas 目前為離線生成，無法即時回應玩家輸入；建議用於過場動畫、預覽或非互動式敘事段落。

**與機器人模擬平台整合（Isaac Sim / MuJoCo / CARLA）**
- 將機器人動作指令轉換為 Hy-Nomas 的文字動作描述，搭配模擬環境的攝影機軌跡，生成視覺訓練資料。
- 可作為「資料增強器」：在模擬器中產生動作軌跡，透過 Hy-Nomas 渲染為逼真影片，用於訓練視覺感知模型。
- 注意：需驗證生成影片的物理合理性，避免引入錯誤的視覺模式。

**與視覺語言模型（VLM）整合**
- Hy-Nomas 內建的 Prompt Enhancer 已採用 VLM 架構；可進一步整合更強大的 VLM（如 GPT-4V、Gemini）作為「高階規劃器」，將複雜任務分解為多回合指令序列。
- 整合時需注意 VLM 的延遲成本，建議將高階規劃與低階生成解耦。

**與既有影片生成管線整合**
- 可將 Hy-Nomas 的片段式因果注意力設計移植至其他影片擴散模型（如 Wan、MovieGen），作為互動式生成的基礎模組。
- 論文中使用的 HunyuanVideo 1.5 自編碼器與注意力核函式可作為起點，但需根據目標模型調整。

**與 3D 重建技術整合**
- 將 Hy-Nomas 生成的影片作為 3D 重建（如 NeRF、3DGS）的輸入，用於從文字描述快速建立可探索的 3D 場景。
- 此組合可彌補 Hy-Nomas 目前無法提供「自由視角探索」的限制。

**與 LoRA 生態整合**
- 論文中已展示 LoRA 適配流程；可建立 LoRA 市場，讓使用者下載特定風格（如「吉卜力風格」、「賽博龐克風格」）的 LoRA 權重，無需重新訓練基礎模型。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）建立對「互動式世界模型」的概念理解，再跳讀第 3.1 節（Segment-wise Causal Attention）了解核心創意。數學細節可暫時略過，重點掌握「為什麼需要因果注意力」與「動作指令為何要限制時間窗口」這兩個設計動機。影片與圖表（Figure 1）是理解系統全貌的最佳起點。

**給 AI 工程師**：重點閱讀第 3 章（Model Architecture）與第 4 章（Training Infrastructure），特別是片段式因果注意力的實作細節、攝影機軌跡條件化方式，以及分散式訓練中的記憶體優化策略。第 5 章的訓練課程設計提供了從預訓練到蒸餾的完整路徑圖，第 6 章的推論優化則是部署階段的實務參考。建議直接閱讀官方程式碼以驗證細節。

**給研究者**：重點關注第 3.1 節的「動作感知因果注意力」設計、第 5.4 節的「片段強制」訓練策略，以及第 7 章的評測協議設計。這三處是論文最具方法論貢獻的部分。建議與 Genie 3、LingBot-World v2 等近期工作進行對比閱讀，理解不同世界模型在「因果性」、「物理合理性」與「長時序一致性」上的取捨。第 9 章的未來方向也值得深入思考。

**給產品經理**：建議先閱讀摘要與第 1 節，理解 Hy-Nomas 能解決什麼問題、無法解決什麼問題。第 7.3 節的比較結果提供了相對定位的參考。實務上應關注：單次生成的算力成本、單段影片時長上限、多回合互動的延遲表現，以及 LoRA 適配所需的資料量與時間。這些指標決定了產品化的可行邊界。建議與工程團隊共同評估「擴散蒸餾後的推論成本」是否落在可接受範圍內。
