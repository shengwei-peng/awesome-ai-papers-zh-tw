## 摘要翻譯

多教師同策略蒸餾（Multi-teacher On-policy Distillation, M-OPD）已成為一個頗具前景的典範，可透過密集、token 層級的獎勵監督（dense, token-level reward supervision），將領域專精的強化學習（Reinforcement Learning, RL）專家整合為單一通才學生（generalist student）。儘管在實務上已取得成效，多教師能力整合（capability integration）背後的最佳化動態（optimization dynamics）仍了解有限，且開放且嚴謹可複現的配方（reproducible recipe）仍明顯匱乏。在本研究中，我們在 SmolLM3-3B-Base 上建立一個受控 M-OPD 基準（controlled benchmark），並藉由神諭路由（oracle routing）隔離能力整合與路由歧義（routing ambiguity）。我們的研究揭示了一個顯著的能力整合落差（capability integration gap）：標準 M-OPD 相對於領域路由神諭集成模型（domain-routed oracle ensemble）僅回收 35.6% 的可用提升空間（available headroom），且簡潔任務（concise tasks，如指令遵循（instruction following, IF））出現嚴重退化與過早停滯。關鍵在於，我們證明此失敗並非源自梯度衝突（gradient conflict），而是源自 token 層級最佳化預算（token-level optimization budget）的嚴重錯置（misallocation）。此病態現象由三個正交因素（orthogonal factors）驅動：跨領域的結構性序列長度差異（sequence-length disparities）、非均勻學習率（non-uniform learning rates）導致的動態收斂漂移（convergence drift），以及非同步策略更新（asynchronous policy updates）造成的多步獎勵陳舊（multi-step reward staleness）。為了解決這些失衡，我們提出 Open-MOPD，一個原則性框架（principled framework），結合 token 佔比平衡（token-share balancing）、落差感知動態預算分配（gap-aware dynamic budget allocation）與學生獎勵刷新（student reward refresh）。這些機制共同系統性地恢復跨領域平衡（cross-domain balance），使單一可部署學生（deployable student）的可用提升空間回收率從 35.6% 提升至 83.4%。我們完整開源端到端後訓練配方（end-to-end post-training recipe）、訓練軌跡（training trajectories）與評估套件（evaluation suites），且全部可在學術級硬體預算（academic hardware budget）內完成。

### 核心貢獻（3～5點）
- 在 SmolLM3-3B-Base 上建立受控 M-OPD 基準，並藉由神諭路由排除路由歧義，首次量化揭示「能力整合落差」：標準 M-OPD 僅回收 35.6% 的可用提升空間。
- 診斷出能力失衡的根本原因並非梯度衝突，而是 token 層級最佳化預算的嚴重錯置，並歸納出三個正交成因：序列長度差異、動態收斂漂移與多步獎勵陳舊。
- 提出 Open-MOPD 框架，透過 token 佔比平衡、落差感知動態預算分配與學生獎勵刷新三項機制，將可用提升空間回收率從 35.6% 提升至 83.4%。
- 完整開源端到端後訓練配方、訓練軌跡與評估套件，且全部可在學術級硬體預算內復現。

### 適合對象
本論文適合從事大型語言模型後訓練（post-training）、強化學習微調（RL fine-tuning）、模型蒸餾、多任務／多領域能力整合，以及開源可復現訓練配方的研究人員與工程師閱讀。對於希望以單一統一模型取代多個領域專家，並在有限硬體預算下實現高效能力整合的實務者尤其具有參考價值。

## 深度分析

#### 方法論解析

本文提出的 **Open-MOPD** 是一套針對 **多教師同策略蒸餾（Multi-teacher on-policy distillation, M-OPD）** 中 **能力失衡（capability imbalance）** 問題的診斷與修復框架。其核心目標是將數個 **領域專精強化學習專家（domain-specialized RL experts）** 的能力整合進單一 **通才學生（generalist student）**，並在可部署的模型中回收絕大多數理論 **提升空間（headroom）**。以下從基礎目標函式、診斷出的三項失真機制，以及對應的三項矯正機制進行剖析。

##### 1. 基礎 M-OPD 目標函式

在 Open-MOPD 的設定中，領域集合為 \( \mathcal{D}=\{\text{math},\text{code},\text{instruction\_following (IF)}\} \)。對每個提示 \( x \)，依據真實 **領域標籤（domain label）** \( d(x) \) 將其 **路由（route）** 至對應的 **領域專家 RL 教師（domain-expert RL teacher）** \( \pi_{\phi_{d(x)}} \)。學生策略 \( \pi_\theta \) 對該提示產生回應 \( y \sim \pi_\theta(\cdot \mid x) \) 後，教師僅需一次 **預填（prefill）** 前向傳播即可取得教師分佈。

對於位置 \( t \)，先取學生分佈的 **Top-K** 集合：
\[
S_t = \text{TopK}_k\big(\pi_\theta(\cdot \mid x, y_{<t})\big),
\]
預設 \( k=16 \)。對每個 \( v \in S_t \)，計算 **教師–學生對數機率差（teacher–student log-probability difference）**：
\[
\delta_t(v)=\text{sg}\Big[\log\pi_{\phi_{d(x)}}(v \mid x, y_{<t}) - \log\pi_\theta(v \mid x, y_{<t})\Big],
\]
其中 \( \text{sg}[\cdot] \) 表示停止梯度（stop-gradient），確保教師分佈不參與學生梯度更新。接著將 \( \delta_t(v) \) 以學生分佈在 \( S_t \) 上的 softmax 權重加權，得到 **密集獎勵（dense reward）**：
\[
r_t(v)=\delta_t(v)\cdot \tilde{\pi}_\theta(v \mid x, y_{<t}),\quad
\tilde{\pi}_\theta(v \mid x, y_{<t})=\text{softmax}_{u\in S_t}\big(\log\pi_\theta(u \mid x, y_{<t})\big)(v).
\]
位置層級獎勵為：
\[
r_t=\sum_{v\in S_t} r_t(v).
\]
此 \( r_t \) 直接作為優勢（advantage）放入策略梯度目標中進行更新。由於沒有額外的 **評論家（critic）**，整體方法屬於 **無評論家同策略蒸餾（critic-free on-policy distillation）**。

##### 2. 三項 token 層級最佳化預算失真機制

本文透過受控實驗指出，**能力整合落差（capability integration gap）** 並非源於傳統假設的 **梯度衝突（gradient conflict）**，而是來自 **token 層級最佳化預算（token-level optimization budget）** 的錯置。具體可分解為三個彼此 **正交（orthogonal）** 的因素：

- **結構性序列長度差異（structural sequence-length disparities）**：不同領域的回應長度分佈差異極大。以 **指令遵循（instruction following, IF）** 為例，其回應通常簡短；儘管輸入提示佔了 20.3%，卻只貢獻 0.99% 的梯度 token。因此，即便提示層級採用均勻取樣，實際獲得的梯度更新份額仍嚴重不足。

- **動態收斂漂移（dynamic convergence drift）**：各領域教師與學生之間的 **落差（gap）** 縮減速度不同，導致獎勵訊號的強度隨訓練步數非均勻衰減。若僅做靜態的 token 比例控制，數十步後預算會再次偏向已快速收斂的領域，造成其他領域過早停滯。

- **多步獎勵陳舊（multi-step reward staleness）**：標準的 **多步 rollout 重用（multi-step rollout reuse）** 會讓同一批軌跡（trajectory）被重複用於多次梯度更新。由於獎勵中的學生對數機率項與當前策略相關，當學生策略已更新後，舊 rollout 計算出的獎勵便成為 **陳舊（stale）** 訊號，進一步扭曲各領域的有效學習率。

##### 3. Open-MOPD 的三項矯正機制

針對上述三項失真，Open-MOPD 分別引入對應機制：

- **Token 佔比平衡（token-share balancing）**：不再以每個 batch 的固定提示數或固定 token 數作為預算單位，而是建立 **加權 token 佔比目標（weighted token-share target）**，使各領域在梯度更新中實際貢獻的 token 比例符合預設目標，從而將 **最佳化預算（optimization budget）** 的分配與序列長度解耦。

- **落差感知動態預算分配（gap-aware dynamic budget allocation）**：持續監控各領域剩餘的 **學生–教師落差（student–teacher gap）**，並將額外預算導向落差最大的領域。這避免了單純 **獎勵正規化（reward normalization）** 在訓練第 74 步出現的崩潰現象——即預算被浪費地注入已收斂領域，而尚未收斂的領域卻被忽視。

- **學生獎勵刷新（student reward refresh）**：在每次梯度步之前，使用當前學生策略重新計算學生對數機率，同時快取教師狀態，以消除 **樣本陳舊（sample staleness）**。此機制僅帶來可忽略的額外計算開銷，卻能顯著降低 **非同步策略更新（asynchronous policy updates）** 造成的獎勵失真。

這三項機制可獨立運作、亦可疊加，形成一套系統化的 **跨領域平衡（cross-domain balance）** 方案，最終將 **理論提升空間回收率（recovered theoretical headroom）** 從 **樸素 M-OPD（Naive M-OPD）** 的 35.6% 提升至 83.4%。

#### 實驗數據解讀

本文在 **SmolLM3-3B-Base** 上建立受控基準，採用 **混合 SFT 初始化（mixed-SFT initialization）** 與三個 **領域專家 RL 教師（domain-expert RL teachers）**（數學、程式設計、指令遵循），並以 **神諭路由（oracle routing）** 排除路由錯誤的干擾，專注檢驗 **能力整合（capability integration）** 本身。

##### 1. 主要評估指標與基線

- **RouteRL**：各領域單獨進行 RL 訓練後，依真實領域標籤路由的上限基線。
- **RouteOPD**：以神諭路由進行多教師蒸餾的上限方法，用於衡量部署時的 **整合落差（integration gap）**。
- **Naive M-OPD**：未加入任何平衡機制的基線方法。
- **理論提升空間回收率**：定義為 \( (\text{current}-\pi_{\text{mixsft}})/(\text{RouteRL}-\pi_{\text{mixsft}}) \)，衡量相對於混合 SFT 初始化後還可回收多少 RouteRL 帶來的進步空間。

##### 2. 核心數據解讀

在標準化的 **六項基準評估協定（six-benchmark evaluation protocol）** 下：

- **樸素 M-OPD** 的平均分數為 28.05，而各領域單獨蒸餾可達 31.55，顯示單純多教師蒸餾存在顯著 **能力整合落差**。
- 與 **RouteOPD** 相比，**指令遵循（IF）** 領域的絕對落差高達 6.16 分，是數學領域落差（約 1.89 分）的 3.3 倍；程式設計領域的落差約為 2.45 分。
- 從 **理論提升空間回收率** 來看，樸素 M-OPD 僅回收 35.6%，而 Open-MOPD 將其提升至 83.4%，幾乎回收了絕大部分可獲得的性能空間。
- 訓練曲線顯示，IF 是最早出現 **過早停滯（premature stagnation）** 的領域，與其序列簡短、梯度 token 佔比極低的觀察一致。

##### 3. 消融實驗的意涵

透過逐步加入三項機制的 **消融階梯（ablation ladder）**，可以觀察到：

- 僅加入 **token 佔比平衡** 即可緩解 IF 的嚴重退化，因為它直接補償了簡短回應在梯度中的弱勢。
- 加入 **落差感知動態預算分配** 後，可避免預算被已收斂領域佔據，使訓練過程更穩定，防止在第 74 步出現的獎勵正規化崩潰。
- **學生獎勵刷新** 則進一步消除多步 rollout 重用帶來的陳舊訊號，對長程推理與多步更新的領域（如程式設計與數學）尤為重要。

整體而言，實驗數據強烈支持本文的核心論點：M-OPD 的瓶頸不在於 **梯度衝突**，而在於 **token 層級最佳化預算** 的錯置；只要針對性地矯正這三項失真，就能在單一可部署學生中實現接近上限的跨領域能力整合。

#### 與現有研究的比較

##### 1. 相對於傳統多教師蒸餾的改進

過往多教師蒸餾研究常將整合失敗歸因於 **梯度衝突** 或 **教師間不一致（teacher disagreement）**，並透過梯度投影、衝突緩解或教師權重調整來處理。本文則提出不同觀點：在受控的 **神諭路由（oracle routing）** 設定下，**token 層級教師不一致** 並非主要瓶頸；真正的問題是 **最佳化預算錯置**。這一診斷將研究焦點從「教師之間的衝突」轉向「學生與各教師之間的學習動態不均」。

##### 2. 相對於單一教師同策略蒸餾的擴展

單一教師的 **同策略蒸餾（on-policy distillation）** 已顯示密集 token 獎勵能有效遷移專家能力，但當擴展至多領域時，序列長度差異與收斂速度差異會被放大。Open-MOPD 首次系統性地將這些問題形式化，並提出可落地的解決方案，特別是 **token 佔比平衡** 與 **落差感知動態預算分配**，填補了多教師設定下的方法論空白。

##### 3. 相對於獎勵正規化與課程學習的差異

單純的 **獎勵正規化（reward normalization）** 在本文實驗中於第 74 步出現崩潰，顯示其無法處理動態收斂漂移。Open-MOPD 的 **落差感知動態預算分配** 可視為一種自適應課程（adaptive curriculum），但其分配依據是實證測量的剩餘落差，而非預設難度或固定排程，因此對非均勻收斂更具魯棒性。

##### 4. 限制與待釐清之處

儘管 Open-MOPD 成效顯著，仍存在若干限制：

- **神諭路由的現實性**：實驗採用真實領域標籤進行路由，實際部署時仍需搭配領域分類器或路由模型，路由誤差可能重新引入整合挑戰。
- **領域數量與規模**：目前僅驗證三個領域，且基底模型為 3B 規模；在更多領域或更大模型上的泛化性仍需驗證。
- **評估基準的覆蓋度**：雖採用六項基準，但仍可能無法涵蓋所有真實世界能力維度，例如多輪對話、工具使用或長文件生成。
- **理論保證不足**：本文以實證診斷為主，尚未提供收斂性或最優預算分配的嚴格理論分析。
- **計算與記憶體開銷**：學生獎勵刷新雖開銷可忽略，但整體訓練仍需 8×A100-80GB 的學術級硬體預算，對資源有限環境仍具門檻。

#### 可重現性評估

本文在可重現性方面採取了相當完整的開放措施，符合其標榜的 **Open-MOPD** 名稱：

- **端到端後訓練配方（end-to-end post-training recipe）**：完整開源從混合 SFT 初始化、教師訓練、學生蒸餾到評估的流程。
- **模型檢查點（model checkpoints）**：釋出訓練過程中的模型權重，便於驗證各階段性能。
- **訓練軌跡（training trajectories）**：提供策略生成的序列與對應獎勵記錄，使其他研究者能追蹤訓練動態。
- **評估套件（evaluation suites）**：包含六項基準的評估協定與腳本，降低比較門檻。
- **學術級硬體預算（academic hardware budget）**：整個流程可在 8×A100-80GB 上複現，對學術實驗室相對可及。

這些釋出內容大幅提升了研究的透明度，使社群能夠直接驗證 35.6% → 83.4% 的 **理論提升空間回收率** 提升，並在此基礎上進行後續改進。不過，可重現性仍部分依賴於資料集授權、教師模型取得方式，以及硬體環境的一致性；建議作者進一步提供詳細的環境版本、隨機種子與執行時間，以強化嚴格可複現性。

#### 未來研究方向

基於本文的診斷與方法，以下幾個方向值得進一步探索：

1. **與真實路由模型的聯合訓練**：將 Open-MOPD 與可學習的領域路由模型共同訓練，研究 **路由歧義（routing ambiguity）** 與 **能力整合落差** 的交互影響，並發展聯合最佳化策略。

2. **擴展至更多領域與更大規模模型**：驗證 token 佔比平衡與落差感知分配在 7B、13B 乃至更大 **大型語言模型（LLM）**、以及超過十個領域時的穩定性與可擴展性。

3. **理論分析與最適預算分配**：建立 M-OPD 收斂性的理論框架，推導在給定訓練步數下各領域的 **最佳化預算（optimization budget）** 最適比例，並設計無需神諭標籤的線上估計方法。

4. **離線與異策略多教師蒸餾**：將診斷延伸至 **異策略（off-policy）** 或 **離線（offline）** 多教師蒸餾，探討陳舊獎勵與分佈偏移（distribution shift）在這些設定中的相對影響。

5. **稀疏獎勵與混合監督訊號**：研究當部分領域僅有稀疏獎勵（例如最終答案正確性）而非密集 token 獎勵時，如何調整預算分配與獎勵刷新機制。

6. **長程推理與多輪互動**：將方法應用於需要 **長程推理（long-horizon reasoning）**、多輪對話或工具使用的場景，檢驗序列長度差異更極端時的穩健性。

7. **硬體效率與記憶體最佳化**：進一步降低學生獎勵刷新與多教師前向傳播的記憶體與計算成本，使 Open-MOPD 能在更小的學術級硬體預算上運行。

8. **多模態領域整合**：將 M-OPD 框架擴展至視覺–語言、語音–文字等多模態任務，探討不同模態序列長度與收斂速度差異帶來的新挑戰。

總結而言，Open-MOPD 不僅提供了一套有效的多教師能力整合配方，更重要的是將社群對 M-OPD 失敗模式的理解從「梯度衝突」轉向「token 層級最佳化預算錯置」，為後續研究開闢了明確的問題意識與方法論基礎。

## 論文問答

**Q1：Open-MOPD 主要想解決什麼問題？為什麼多教師同策略蒸餾（M-OPD）值得被深入研究？**

A：Open-MOPD 針對的是多教師同策略蒸餾在整合多領域專家能力時出現的「能力整合落差」。雖然 M-OPD 在工業界已被廣泛採用，但社群對於多領域能力整合的最佳化動態理解仍然有限，也缺乏可嚴謹複現的開放配方。透過建立受控基準並排除路由歧義，作者希望釐清學生模型真正無法吸收各教師專長的原因，最終讓單一通才模型能夠取代多個昂貴的領域專家。

**Q2：樸素 M-OPD 為什麼無法成功整合各領域能力？所謂的整合落差具體表現在哪裡？**

A：樸素 M-OPD 的失敗並非來自災難性的梯度衝突，而是源於 token 層級最佳化預算的嚴重錯置。以指令遵循（IF）為例，它雖佔輸入提示的 20.3%，卻只貢獻 0.99% 的梯度 token，導致簡潔任務獲得的更新資源遠低於數學或程式設計等長序列領域。這種失衡使得指令遵循出現嚴重退化並過早停滯，整體僅回收 35.6% 的可用提升空間，顯示能力整合落差真實存在且高度不對稱。

**Q3：為什麼說「完美路由」仍然不足以保證 M-OPD 成功？神諭路由在實驗設計中扮演什麼角色？**

A：作者使用神諭路由（oracle routing），根據真實領域標籤將提示分派給對應教師，從而把「路由歧義」與「能力整合」兩個問題分離開來。實驗顯示，即使在完美路由下，樸素 M-OPD 仍與 RouteOPD 上限存在顯著差距，證明單靠正確路由無法保證成功整合。這項發現凸顯了最佳化過程本身——而非路由決策——才是多教師蒸餾的核心瓶頸。

**Q4：Open-MOPD 的核心方法包含哪三個機制？它們分別對應哪些失衡因素？**

A：Open-MOPD 包含 token 佔比平衡、落差感知動態預算分配，以及學生獎勵刷新三個機制。token 佔比平衡處理不同領域序列長度結構性差異所造成的梯度預算偏斜；落差感知動態預算分配針對非均勻學習率導致的收斂漂移；學生獎勵刷新則消除多步 rollout 重複使用所帶來的獎勵陳舊性。這三個因素彼此正交，分別對應序列長度差異、動態收斂漂移與非同步策略更新。

**Q5：token 佔比平衡與傳統的每批次配額平衡有何不同？為什麼需要這樣的設計？**

A：傳統方法常以每個 batch 的固定提示數量或原始 token 數量來分配領域，但這會讓長回應領域在梯度更新中佔據過大比例。token 佔比平衡改為設定加權的 token 佔比目標，使每個領域在實際最佳化預算中獲得預先規劃的份額，而不受該領域樣本長短影響。如此一來，簡潔的指令遵循任務才能獲得與數學、程式設計相當的更新機會，避免在訓練初期就被長序列領域淹沒。

**Q6：落差感知動態預算分配如何防止訓練崩潰？學生獎勵刷新又扮演什麼角色？**

A：落差感知動態預算分配會持續監控各領域的學生—教師差距，並將更多最佳化資源導向仍有最大進步空間的領域。這能防止樸素獎勵正規化在步驟 74 左右出現的訓練崩潰，即預算被錯誤地注入已經收斂的領域。學生獎勵刷新則在快取教師狀態的同時，於每次梯度更新前重新估計學生策略的 log-probability，從而以極小額外開銷消除多步 rollout 重複使用造成的獎勵陳舊性，確保優勢信號反映當前策略。

**Q7：本研究的實驗設置為何？使用了哪些模型、領域、硬體與評估協定？**

A：研究在 SmolLM3-3B-Base 上建立受控 M-OPD 基準，先經過三領域混合 SFT 初始化，再使用數學、程式設計與指令遵循三個領域專家 RL 教師進行蒸餾。提示透過真實領域標籤進行神諭路由，並在 8×A100-80GB 的學術級硬體上完成訓練與消融。評估採用標準化的六項基準協定，以領域宏觀平均與相對於 RouteRL 的理論提升空間回收率作為主要指標。

**Q8：Open-MOPD 取得了哪些關鍵量化結果？各領域的表現如何改善？**

A：樸素 M-OPD 在標準化六項基準上平均僅達 28.05 分，而各領域單獨蒸餾可達 31.55 分，顯示存在明顯整合落差。引入 Open-MOPD 後，理論提升空間回收率從 35.6% 大幅提升至 83.4%，且單一可部署學生即可接近領域路由神諭集成模型的表現。特別是指令遵循領域的絕對差距從原先最嚴重的 6.16 分獲得顯著改善，顯示跨領域平衡已被有效修復。

**Q9：消融實驗揭示了什麼？三個機制是否缺一不可？**

A：消融實驗以累積方式驗證三個機制的貢獻：僅加入 token 佔比平衡即可緩解序列長度差異造成的預算偏斜；再加入落差感知動態預算分配後，可進一步抑制非均勻收斂導致的預算漂移；最後加入學生獎勵刷新，消除多步獎勵陳舊性，使整體回收率達到 83.4%。這三個因素彼此正交，單獨處理任一項都無法完全彌補整合落差，必須同時介入才能釋放 M-OPD 的完整潛力。

**Q10：在實際應用中，Open-MOPD 如何取代多個專家模型？適合哪些場景？**

A：Open-MOPD 讓單一學生模型能同時具備數學推理、程式設計與指令遵循等多項專長，從而取代需要分開部署與維護的多個領域專家模型。這不僅降低服務多個專家所需的推理成本與系統複雜度，也簡化了模型版本管理與更新流程。對於需要在對話、程式輔助與數學解題之間無縫切換的應用場景，Open-MOPD 提供了一個統一且高效的解決方案。

**Q11：將 Open-MOPD 落地到產品時，需要考慮哪些工程與部署問題？**

A：在產品落地時，雖然本研究使用神諭路由來隔離問題，但實際系統仍需搭配可靠的路由器或意圖分類器來決定提示所屬領域。此外，學生獎勵刷新與動態預算分配會帶來額外的計算與記憶體開銷，雖然論文稱其額外開銷極小，仍需在延遲敏感的服務中進行權衡。硬體方面，完整配方可在 8×A100-80GB 上複現，對學術與中小型團隊相對友善，但大規模部署時仍需評估吞吐量與成本。

**Q12：這項研究對整個領域可能帶來什麼影響？開源貢獻為何重要？**

A：Open-MOPD 不僅提出了一套有原則的 M-OPD 最佳化框架，更重要的是開源了端到端後訓練配方、模型檢查點、訓練軌跡與評估套件。這填補了過去工業界方法缺乏可複現配方的空白，使學術界能夠在統一且受控的環境下研究多教師能力整合。透過將診斷、方法與工具全部公開，本研究有望加速後訓練蒸餾、模型合併與通才模型訓練等相關領域的進展。

**Q13：作者承認了哪些研究限制？這些限制會如何影響結論的推廣？**

A：本研究目前僅在三個領域與單一基底模型 SmolLM3-3B-Base 上進行驗證，結果是否能推廣到更多領域或更大參數規模仍需進一步研究。此外，實驗採用神諭路由，實際部署中路由錯誤可能與最佳化失衡交互作用，產生額外的挑戰。最後，本框架主要針對 token 層級最佳化預算錯置進行診斷，對於教師品質不一致或獎勵設計缺陷等問題並未深入探討。

**Q14：在哪些情況下，Open-MOPD 仍可能表現不佳或失效？**

A：當領域間的序列長度差異極端懸殊，或教師之間的獎勵尺度與分佈高度不一致時，Open-MOPD 的動態預算分配可能仍難以完全平衡。若某些領域的教師本身尚未收斂或持續變化，學生獎勵刷新也無法彌補非穩定監督信號帶來的干擾。此外，在沒有可靠領域標籤或路由器表現不佳的真實場景中，路由錯誤可能放大整合落差，使單一通才模型難以達到預期上限。

**Q15：未來可以朝哪些方向延伸這項工作？**

A：未來研究可將 Open-MOPD 與可學習路由器結合，在不再依賴神諭標籤的情況下同時最佳化路由與能力整合。另一方向是擴展到更多領域與更大規模模型，並探討與批判模型（critic）或離線蒸餾技術的結合是否能進一步提升回收率。此外，將 token 層級最佳化預算分析應用於多模態模型或其他序列決策任務，也有助於驗證這套診斷框架的普適性。

## 實務應用指南

### 適用場景

1. **多領域客服助理整合**  
   企業常擁有分別處理訂單查詢、技術支援、退換貨政策的專精模型。Open-MOPD 可將這些領域專家 RL 教師整合為單一通才學生，減少線上模型數量與推理成本，同時維持各領域回應品質。

2. **程式碼與數學推理的統一教育輔助工具**  
   教育平台需要同時支援數學解題、程式設計與一般指令遵循。透過神諭路由隔離各領域能力，Open-MOPD 能緩解簡潔任務（如指令遵循）在傳統 M-OPD 中過早停滯的問題，讓單一模型穩定涵蓋長程推理與簡短問答。

3. **企業內部多工 LLM 後訓練**  
   當組織已針對法務、財報、行銷等場景訓練出領域專家，卻希望部署一個可動態承接各類任務的統一模型時，Open-MOPD 提供可複現的端到端後訓練配方，並在學術級硬體預算（8×A100-80GB）內完成。

4. **邊緣裝置上的精簡多工模型**  
   在資源受限環境中，無法同時載入多個大型專家。Open-MOPD 可將數個領域專精強化學習專家蒸餾到單一可部署學生，降低記憶體與推論延遲，適合地端知識庫問答或智慧製造現場助手。

5. **開源社群的通用後訓練基準**  
   研究團隊可利用 Open-MOPD 的受控基準與開源訓練軌跡，快速驗證新的多教師蒸餾演算法，並與 RouteOPD、RouteRL 等上限基線進行公平比較。

### 實作前置條件

**資料準備**
- 每個目標領域需具備高品質提示（prompt）與真實領域標籤，以便執行神諭路由並隔離能力整合動態。
- 需先完成混合 SFT 初始化，讓學生具備各領域基本語言與格式能力。
- 每個領域需有已訓練完成的領域專家 RL 教師，能對學生 rollout 輸出逐 token 獎勵監督。

**運算資源**
- 建議至少 8×A100-80GB 的學術級硬體配置，以支撐 SmolLM3-3B-Base 規模的長程推理與多步 rollout 重用。
- 需具備足夠儲存空間保存教師狀態快取、訓練軌跡與多個模型檢查點。

**技術能力**
- 熟悉強化學習（RL）與語言模型後訓練流程，特別是同策略蒸餾與 PPO/GRPO 風格的優勢估計。
- 能進行 token 層級梯度預算分析，並依序列長度差異與收斂漂移調整訓練配置。
- 具備分散式訓練與評估套件建置經驗，能重現六項基準評估協定。

### 實作步驟建議

1. **建立受控基線**  
   從 SmolLM3-3B-Base 出發，先執行混合 SFT 初始化，再分別訓練數學、程式設計、指令遵循三個領域的 RL 教師。以 RouteRL 與 RouteOPD 作為上限基線，量化可用品提升空間。

2. **實作神諭路由的 M-OPD 管線**  
   使用真實領域標籤將每筆提示路由至對應教師，學生對每個提示進行同策略 rollout，教師以單次 prefill 產生教師分佈，計算 token 層級獎勵監督。

3. **診斷 token 層級最佳化預算錯置**  
   記錄各領域輸入提示佔比與梯度 token 佔比。若發現簡潔任務（如指令遵循）提示佔 20% 但梯度 token 佔不到 1%，即確認存在能力整合落差。

4. **導入 Open-MOPD 三大機制**
   - **Token 佔比平衡**：依加權 token-share target 重新取樣或加權，而非固定每批次配額，使各領域實際獲得的梯度更新量符合預期。
   - **落差感知動態預算分配**：持續監控學生—教師 gap，將額外預算導向剩餘落差最大的領域，避免已收斂領域浪費訓練資源。
   - **學生獎勵刷新**：在每次梯度步驟前以學生當前策略重新計算 log-probability，同時快取教師狀態，消除多步 rollout 重用造成的獎勵陳舊。

5. **累積消融與穩定性驗證**  
   依消融階梯逐步加入三項機制，觀察理論提升空間回收率是否從約 35.6% 提升至 80% 以上。同時監控驗證軌跡，確認沒有領域過早停滯。

6. **產品化部署**  
   將訓練完成的單一可部署學生匯出為標準格式，接上既有推理服務。保留領域標籤用於離線評估與持續監控，但線上推論時不再需要教師模型。

### 潛在風險與注意事項

- **簡潔任務被長序列領域淹沒**  
  數學與程式設計通常產生較長回應，會在梯度中佔據絕大部分 token。若未做 token 佔比平衡，指令遵循能力會嚴重退化。建議在每次更新前檢查各領域實際梯度 token 佔比，而非僅看提示數量。

- **獎勵歸一化導致預算錯置**  
  單純對各領域獎勵做歸一�化可能在第 74 步左右引發訓練崩潰，將預算導向已收斂領域。應改用落差感知動態預算分配，依剩餘學生—教師 gap 調整權重。

- **多步 rollout 重用造成獎勵陳舊**  
  標準多步 rollout 重用在連續小批次中會使學生相關獎勵分量過時。導入學生獎勵刷新可顯著降低此問題，且額外開銷極小。

- **過度擬合教師而非學習通泛能力**  
  若學生過度貼近特定教師的分佈，可能喪失跨領域泛化性。建議保留獨立驗證集與六項基準評估協定，並與 RouteOPD 持續比對。

- **硬體與儲存瓶頸**  
  快取教師狀態與保存訓練軌跡會增加儲存需求。建議在實驗初期先以較小規模驗證配置，確認 I/O 與記憶體無虞後再進行完整訓練。

### 與其他技術的整合建議

- **與現有路由系統整合**  
  Open-MOPD 在訓練階段使用神諭路由以隔離能力整合問題，但產品部署時可與輕量領域分類器或意圖識別模型搭配，用於離線評估與錯誤分析，而非線上強制路由。

- **與模型合併（Model Merging）技術互補**  
  若組織已使用模型合併快速產生通才模型，可將 Open-MOPD 作為後續精煉步驟，進一步縮小與領域路由神諭集成模型之間的能力整合落差。

- **與持續學習（Continual Learning）流程結合**  
  當新領域專家加入時，可將其視為新的教師，沿用 token 佔比平衡與落差感知分配機制，避免新舊領域間的災難性遺忘。

- **與 RLHF / DPO 管線銜接**  
  Open-MOPD 可承接混合 SFT 初始化後的模型，再銜接偏好學習階段。建議將 Open-MOPD 視為能力整合的蒸餾階段，後續再以人類回饋進行對齊與風格調整。

- **與模型壓縮與量化工具整合**  
  訓練完成的可部署學生可進一步透過量化、剪枝或推論加速框架部署到邊緣裝置，發揮單一模型取代多專家的成本優勢。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦於圖 1 與摘要，理解「為什麼把多個專家合併成一個模型很困難」，以及「簡短任務會因為 token 太少而被忽略」這兩個直覺。接著閱讀第 2 節的問題設定，暫時跳過公式細節，把 Open-MOPD 想像成「依各領域還差多少來動態分配練習時間」的學習方法即可。

**AI 工程師**  
請優先研讀第 3 節的診斷實驗與第 4 節的三大機制，特別注意 token 佔比平衡、落差感知動態預算分配與學生獎勵刷新的實作細節。建議直接參考開源配方重現消融階梯，並將你手邊的訓練管線與論文中的梯度 token 佔比監控方式進行對照。

**研究人員**  
本論文的核心貢獻在於指出能力整合落差並非來自梯度衝突，而是 token 層級最佳化預算錯置。建議深入分析第 3 節的實證診斷與第 4 節的機制分解，思考這三項正交因素在其他多任務學習或蒸餾設定中的適用性，並利用開源受控基準驗證你的假設。

**產品經理**  
請把重點放在「一個可部署學生取代多個專家」的商業價值與風險權衡。理解簡潔任務過早停滯意味著使用者常見的簡短問答可能品質下降，而 Open-MOPD 透過動態預算分配將回收率從 35.6% 提升到 83.4%。評估時請同時關注領域宏觀平均與各領域單獨表現，避免被整體平均分數掩蓋特定場景退化。
