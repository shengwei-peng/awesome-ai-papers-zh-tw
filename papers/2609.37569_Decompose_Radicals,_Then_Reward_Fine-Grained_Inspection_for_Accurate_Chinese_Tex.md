## 摘要翻譯

文字生成圖像（Text-to-Image）模型在渲染精準中文文字方面仍面臨重大挑戰。現有的基於光學字元辨識（Optical Character Recognition, OCR）之強化學習（Reinforcement Learning, RL）獎勵，會將解碼所得的轉錄文字與目標字串進行比對。此類獎勵忽略了中文書寫的組合性：漢字（Ideograph）由透過明確空間關係（Spatial Relation）排列的可重用部件（Reusable Components）組成，但光學字元辨識卻將其視為單一字元進行評估。因此，視覺上不同的部首級錯誤可能會獲得同樣粗糙的回饋，鼓勵產生僅僅相似於目標的字形（Glyph），而非忠實重現其內部結構。

我們採用漢字結構描述序列（Ideographic Description Sequences, IDS），其由空間運算子（Spatial Operator）與字元部件（Component）組成，並訓練一個專家 IDS 辨識器（Expert IDS Recognizer），將渲染出的中文文字轉錄為此表示形式。在此辨識器基礎上，我們提出 IDSpect，該方法將目標文字以確定性方式分解（Deterministic Decomposition）為 IDS 標記，並將裁切級視覺 IDS 預測（Crop-Level Visual IDS Prediction）與目標序列（Target Sequence）對齊。全域唯一字符信用（Globally Unique Token Credit）使此比對不受偵測文字區域（Detected Text Regions）順序的影響。結合整字語意獎勵（Whole-Character Semantic Reward），IDSpect 提供部件與空間關係層級的細粒度信用分配（Fine-Grained Credit），且無需更改圖像生成器（Image Generator），亦不會增加推論時間成本（Inference-Time Cost）。透過 Qwen-Image 的群組相對策略最佳化（Group Relative Policy Optimization, GRPO）後訓練（Post-training）實驗證實，IDSpect 在 LongText 與 GenTextEval 上達到領先的結構品質（Structural Quality）與語意對齊（Semantic Alignment）。

### 核心貢獻（3～5點）
- 提出基於漢字結構描述序列（IDS）的 IDSpect 方法，透過確定性分解提供部件與空間關係層級的細粒度信用分配
- 訓練專家 IDS 辨識器，將渲染文字轉錄為 IDS 表示，實現裁切級視覺 IDS 預測與目標序列的精準對齊
- 設計全域唯一字符信用機制，使獎勵比對不受偵測文字區域順序影響，提升對文字版面變化的魯棒性
- 結合整字語意獎勵，無需更改圖像生成器架構且不增加推論時間成本，即可同時提升結構品質與語意對齊
- 在 Qwen-Image 上以群組相對策略最佳化（GRPO）進行後訓練，於 LongText 與 GenTextEval 基準上達到領先性能

### 適合對象
從事文字生成圖像（Text-to-Image）、中文文字渲染、多模態生成模型後訓練與強化學習獎勵設計的研究人員與工程師；以及對漢字結構分析、IDS 表示學習、計算語言學與文件分析領域感興趣的研究者。

## 深度分析

#### 方法論解析

本論文提出 IDSpect，核心思想在於將漢字的內部結構納入強化學習獎勵函數，以解決現有 OCR-based 獎勵在中文文字渲染任務中的「粗粒度信用分配」(coarse credit assignment) 問題。

**問題形式化 (Problem Formulation)**

給定圖像描述 $p$ 與目標文字 $y = (c_1, \ldots, c_M)$，生成器 $G_\theta$ 採樣圖像 $I \sim G_\theta(p, y)$。在 GRPO (Group Relative Policy Optimization，群組相對策略最佳化) 後訓練階段，多張圖像在同一條件下被採樣並由獎勵 $R(I, y)$ 評分。語意忠實度 (semantic fidelity) 透過標準化字元編輯相似度衡量：

$$r_{\text{sem}}(I, y) = \begin{cases} 1, & \bar{y} \text{ occurs in } \hat{\bar{y}} \\ 1 - \frac{\min\{\text{Lev}(\hat{\bar{y}}, \bar{y}), |\bar{y}|\}}{|\bar{y}|}, & \text{otherwise} \end{cases}$$

此設計在目標文字被正確辨識時給予滿分，即使 OCR 輸出包含額外字元。然而此語意獎勵將每個漢字視為原子符號 (atomic symbol)，無法反映部分正確的內部結構。

**IDS 結構分解 (IDS Structural Decomposition)**

漢字結構描述序列 (Ideographic Description Sequences, IDS) 是 Unicode 標準中用於描述漢字組合結構的表示法，由空間運算子 (spatial operators) 與部件 (components) 組成。例如「⿺⿱亠乂⿸丆⿰丨丶」即描述一個漢字由哪些部件透過左右、上下、包圍等空間關係組合而成。IDSpect 利用此特性，將目標文字確定性分解 (deterministic decomposition) 為 IDS token 序列，並訓練一個專家 IDS 辨識器 (expert IDS recognizer) 將生成圖像中的裁切區域 (crops) 轉錄為對應的 IDS 表示。

**雙分支獎勵架構 (Dual-Branch Reward Architecture)**

IDSpect 採用兩個互補的獎勵分支：

1. **語意分支 (Semantic Branch)**：比較 OCR 轉錄結果與目標文字，提供整字層級的語意忠實度。
2. **結構分支 (Structural Branch)**：將視覺 IDS 預測與目標 IDS 序列對齊，提供部件級與空間關係級的細粒度回饋。

兩個分支的加權和構成最終獎勵，同時兼顧轉錄層級的保真度與字內結構信用 (intra-character structural credit)。

**全域唯一字符信用 (Globally Unique Token Credit)**

IDSpect 的關鍵設計是將 IDS token 視為全域唯一 (globally unique)，使比對結果對偵測文字區域 (detected text regions) 的順序具有穩健性 (robust)。這避免了因文字偵測順序變動而導致的獎勵波動，有利於 GRPO 訓練的穩定性。

**與現有方法的差異化**

相較於 TextPecker 將所有錯誤字形統一標記為「#」(異常標記，anomaly marker)，IDSpect 保留了正確與錯誤部件的區分能力。圖 1 清楚展示：對於同一個結構錯誤的漢字，Expert OCR 給予 0.00、MLLM OCR 因語言先驗給予偽陽性 1.00、TextPecker 同樣給予 0.00，而 IDSpect 給予 0.22，保留了部分結構進步的信用。

**獎勵函數的細粒度特性**

圖 1 的案例分析極具說服力：對於目標漢字「尬」，IDSpect 給予 0.22 的 IDS 獎勵，而非 0 或 1。這意味著：
- 正確的部件（如「尢」、「口」）獲得了部分信用
- 錯誤的部件或空間關係受到了相應懲罰
- 訓練訊號能夠引導模型逐步修正結構錯誤，而非僅在「完全正確」或「完全錯誤」之間跳躍

**與基準方法的比較**

從圖 1 可推斷：
- **Expert OCR**：視覺正確但語意錯誤時，給予 0.00（無法區分「部分正確」與「完全錯誤」）
- **MLLM OCR**：語言先驗可能導致偽陽性，給予 1.00（視覺證據不足卻獲得滿分）
- **TextPecker**：正確識別異常但給予 0.00（無法量化「錯誤程度」）
- **IDSpect**：給予 0.22（精確量化部分結構進步）

#### 與現有研究的比較

**定位 (Positioning)**

IDSpect 定位於視覺文字渲染 (visual text rendering) 的後訓練階段，與以下研究脈絡相關：

1. **視覺文字生成 (Visual Text Generation)**：如 GlyphControl、TextDiffuser 等透過專用編碼器與字形條件化 (glyph conditioning) 改善渲染品質。IDSpect 不改變生成器架構，僅優化獎勵函數。

2. **OCR-based 獎勵**：如 PP-OCRv5 等專家 OCR 模型直接優化轉錄準確率，但受限於辨識器的原子標籤空間 (atomic label space)。

3. **結構感知評估器**：如 TextPecker 引入結構異常量化，但將所有錯誤字形統一標記為「#」，過於粗略。

**改進 (Improvements)**

相較於 TextPecker，IDSpect 的主要改進在於：
- **保留結構資訊**：不將錯誤字形塌縮為異常標記，而是分解為 IDS token 進行比對
- **量化部分進步**：能區分「修復一個部件」與「修復兩個部件」的差異
- **空間關係感知**：透過 IDS 空間運算子，監督部件間的排列關係

相較於一般 OCR 獎勵：
- **避免語言先驗干擾**：不依賴語言模型恢復目標字，而是基於視覺證據評分
- **細粒度信用分配**：為部分正確的結構提供漸進式獎勵

**限制 (Limitations)**

1. **IDS 覆蓋範圍**：IDS 主要描述漢字的組合結構，對於極少數無法用 IDS 描述的字符可能失效
2. **辨識器誤差傳播**：專家 IDS 辨識器的錯誤會直接影響獎勵品質
3. **計算成本**：訓練專家 IDS 辨識器需要額外的標註資料與計算資源
4. **泛化性**：論文僅在 Qwen-Image 上驗證，對其他生成器架構的適用性有待確認

## 論文問答

**Q1：為什麼在文字生成圖像（T2I）模型中，渲染中文文字比渲染拉丁字母文字更具挑戰性？**
A：拉丁字母屬於一維線性序列，每個字元由少量筆畫組成，視覺變化空間相對有限；而中文漢字是二維組合結構，由可重複使用的部件（如部首）透過左右、上下、包圍等明確的空間關係組合而成。這種組合性使得漢字的輸出空間極為龐大且呈長尾分佈，許多罕見字甚至未在訓練資料中充分出現。對生成模型而言，即使一個漢字保留了若干正確部件，只要其中一個部件或空間配置出錯，整個字就會被視為錯誤；對評估模型而言，要在這個龐大且稀疏的空間中精確判斷「哪裡錯、錯多少」也極為困難，這正是中文文字渲染長期被視為 T2I 模型的頑固失效模式的原因。

**Q2：現有 OCR 式獎勵在中文渲染任務中存在什麼「粗粒度信用（coarse-credit）」的根本限制？**
A：傳統 OCR 獎勵先把影像壓縮成字元轉錄結果，再以編輯距離等方式與目標字串比對，因此每個漢字被當作不可分割的原子符號評分。這種做法會產生兩種典型問題：第一，部分結構進度無法反映——若一個原本辨識錯誤的字被修復了其中一個部件，但整字仍無法被辨識為目標字元，獎勵值可能完全不變；第二，語言先驗可能造成偽陽性——多模態大型語言模型（MLLM）會利用上下文語意「猜回」目標字，即使字形本身已經嚴重變形，仍可能得到滿分。換言之，視覺上截然不同的部件級錯誤可能獲得完全相同的反饋，使得強化學習訊號無法有效引導模型學習「先修對一半、再修對另一半」的漸進式進步。

**Q3：為什麼漢字的「組合性」對獎勵設計如此關鍵？**
A：漢字的組合性意味著「正確性」並非二元（對／錯），而是一個連續的光譜——一個字可能保留了正確的左半部、錯放了右半部，或正確的包圍框內填入了錯誤的內部部件。若獎勵函數只看整字是否命中，就無法區分「錯 10%」與「錯 90%」的差異，模型也就缺乏朝著正確方向微調的細粒度梯度。IDSpect 的核心洞見正是：把評估單位從「整字」下沉到「部件＋空間關係」，讓獎勵能反映「內部結構已對了多少」，這對長尾、罕見、結構複雜的漢字尤其重要，因為這些字往往正是模型最容易崩壞、卻也最需要細緻監督的對象。

**Q4：什麼是漢字結構描述序列（IDS），IDSpect 如何運用它來設計獎勵？**
A：IDS 是一種形式化表示法，使用空間運算子（如 ⿰ 左右、⿱ 上下、⿸ 包圍）搭配部件符號來描述一個漢字的內部結構，例如「還」可分解為 ⿺⿱亠乂⿸丆⿰丨丶。IDSpect 訓練一個專家 IDS 辨識器，把生成影像中偵測到的文字裁切區域轉錄成 IDS token 序列；同時對目標文字做確定性分解得到目標 IDS。結構分支獎勵便是在視覺預測 IDS 與目標 IDS 之間做比對，並透過「全域唯一字符信用」機制，使比對結果不受偵測區域順序影響。這樣一來，即使模型生成的部件順序與目標不同，只要集合一致就能得到合理分數，從而提供部件級與空間關係級的細粒度回饋。

**Q5：IDSpect 的雙分支獎勵（語意分支＋結構分支）是如何分工與融合的？**
A：語意分支沿用 OCR 轉錄與目標字串的編輯相似度，負責衡量「整段文字是否被正確讀出來」，確保最終可讀性；結構分支則比對視覺 IDS 預測與目標 IDS，負責衡量「每個漢字內部結構對了多少」。兩者以加權和融合，形成一個同時反映轉錄層級忠實度與字符內部結構進度的獎勵訊號。這種分工的精妙之處在於：語意分支防止模型只顧部件正確卻拼出錯字（例如部件全對但空間關係全錯），結構分支則防止模型只顧整字命中卻放任內部崩壞。實驗顯示，這種互補設計在 LongText 與 GenTextEval 上同時提升了結構品質與語意對齊。

**Q6：「全域唯一字符信用（globally unique token credit）」這個設計選擇解決了什麼問題？**
A：在實際生成影像中，OCR 偵測器可能以任意順序回傳文字區域（例如先回「尬」再回「還」），若直接做序列比對，順序不一致會被誤判為大量錯誤。IDSpect 的解法是：對目標 IDS 做確定性分解後，把每個 token 視為全域唯一的標籤，比對時只看「這個 token 有沒有在預測集合中出現」，而不強制要求順序。這使得獎勵對偵測順序具有不變性，也對部分偵測遺漏具有穩健性——少偵測到一個區域只會線性降低分數，不會因為錯位而雪崩式扣分。這是相較於傳統序列比對（如 BLEU 或編輯距離）在處理多區域文字時的關鍵優勢。

**Q7：實驗為何選擇 LongText 與 GenTextEval 這兩個基準？**
A：LongText 著重於長篇、多區域中文文字的渲染，模擬真實場景中招牌、海報、字幕等多段文字並存的情境，能有效檢驗模型在多區域偵測、跨區域結構一致性上的表現；GenTextEval 則是較新的視覺文字生成評測基準，涵蓋中英文與多語言，提供結構品質與語意對齊兩類指標。兩者互補：LongText 強調「量與區域數」的壓力測試，GenTextEval 提供標準化、可重現的量化比較。選擇這兩個基準能同時回答「在極端長文本下是否仍穩健」與「在標準化評測中是否具競爭力」兩個問題，對中文渲染任務而言是相當完整的實驗設計。

**Q8：IDSpect 在結構品質與語意對齊上的關鍵實驗結果為何？**
A：根據摘要與正文描述，IDSpect 在以 Qwen-Image 為基礎模型、GRPO 為後訓練演算法的設定下，於 LongText 與 GenTextEval 上同時達到領先的結構品質與語意對齊分數。具體而言，相較於以 PP-OCRv5 等專家 OCR 為獎勵的基準，IDSpect 在結構指標上明顯勝出，因為它能區分「整字錯」與「部件錯」；相較於 TextPecker 這類異常感知獎勵，IDSpect 在語意對齊上更佳，因為它不會把所有異常字一律打成「#」而失去部分正確的結構信用。圖 1 的定性範例也顯示，對同一個結構錯誤的漢字，傳統 OCR 給 0.00 或偽陽性 1.00，而 IDSpect 給出 0.22 的中間分數，反映出更細緻的進度訊號。

**Q9：有哪些消融實驗或對比支持 IDSpect 的設計選擇？**
A：雖然正文未完整列出所有消融表格，但從方法描述可推論幾項關鍵對比：（1）僅用語意分支 vs. 雙分支融合，驗證結構分支的附加價值；（2）結構分支中，序列比對 vs. 全域唯一字符信用比對，驗證順序不變性的重要性；（3）以 PP-OCRv5、MLLM OCR、TextPecker 等不同獎勵源做對比，驗證 IDS 分解相較於原子字元標籤或異常標記的優勢。圖 1 的視覺化案例本身就是一個微型消融：在同一張影像、同一個錯誤漢字上，三種獎勵給出截然不同的分數（0.00、1.00、0.22），直觀展示了 IDSpect 的細粒度特性。

**Q10：IDSpect 最直接的實際應用場景有哪些？**
A：凡是需要在生成影像中嵌入精確中文文字的場景都將受益，包括電商商品圖（標語、促銷文字）、社群媒體行銷素材（標題、hashtag）、電影與遊戲海報（片名、標語）、教育教材插圖（詩詞、課文）、廣告招牌模擬（店名、地址）等。特別是涉及罕見字、古漢字、書法風格或長篇文字組合的場景，傳統模型最容易出錯，而 IDSpect 的部件級監督能顯著降低「看起來像但其實錯字」的發生率。對中文內容創作者與設計師而言，這代表可以用 T2I 模型快速產出可直接使用的素材，減少人工校對與重繪成本。

**Q11：將 IDSpect 部署到實際產品時需要考量哪些工程因素？**
A：首先，IDSpect 需要一個額外的 IDS 辨識器與 OCR 偵測器在訓練迴圈中運作，會增加訓練時的計算與記憶體成本，但因為不改變圖像生成器本體、也不增加推論時間，所以部署成本可控。其次，IDS 辨識器的訓練資料涵蓋面會直接影響獎勵品質——若遇到極罕見的異體字或古文字，IDS 分解可能不準，需考慮資料擴充或 fallback 機制。再者，OCR 偵測器本身的遺漏與誤偵測會傳遞到獎勵品質，因此選用穩健的偵測器（如 PP-OCRv5）並對裁切品質做前處理是必要的。最後，雙分支加權係數屬於超參數，產品化時需針對目標場景（短文案 vs. 長文本）做調整。

**Q12：IDSpect 對視覺文字生成領域的更廣泛影響是什麼？**
A：IDSpect 提出了一個範式轉移：從「字元是否被辨識出來」轉向「字元的內部結構是否正確組合」，這對所有具有組合性結構的文字系統都有啟發意義，例如韓文（諺文＋漢字）、日文（假名＋漢字）、藏文、阿拉伯文連寫字等。更廣義地，它示範了如何把語言學的結構化表示（IDS、CMU 韻律、語法樹等）注入強化學習獎勵，使獎勵函數從「黑箱相似度」走向「可解釋的結構對齊」。這對學術界而言是一個可複製的研究模板，對工業界則提示了「領域知識＋RL」在生成式 AI 中的巨大潛力。

**Q13：IDSpect 存在哪些已認知的方法限制？**
A：第一，IDS 本身是針對現代漢字設計的，對於書法變體、異體字、簡繁轉換中的非標準寫法，IDS 分解可能不完整或不存在，導致結構分支失效。第二，IDS 辨識器本身的錯誤會直接污染獎勵訊號——若辨識器把正確的字誤判為錯誤的 IDS，模型會被引導往錯的方向學習。第三，雙分支獎勵的加權係數目前依賴經驗設定，缺乏自適應機制。最後，IDSpect 假設目標文字可被確定性分解為 IDS，但對於極少數無法用標準 IDS 表示的字（如某些符號字、合字），需要額外處理。

**Q14：在哪些失敗案例中 IDSpect 仍可能表現不佳？**
A：當生成影像中的文字嚴重扭曲、遮擋或與背景融合時，OCR 偵測器可能根本找不到文字區域，此時結構分支完全失效，獎勵退化成純語意分支，細粒度優勢消失。當多個漢字視覺上極為相似（例如「己」「已」「巳」）時，即使部件正確，空間關係的微小差異也可能導致 IDS 比對給出過低分數。此外，對於創意性文字排版（如垂直書寫、環形排列、文字作為圖案），IDSpect 假設的水平 IDS 分解可能無法正確對應。最後，當目標文字包含大量罕見字或專業術語時，IDS 辨識器的訓練資料不足可能成為瓶頸。

**Q15：基於 IDSpect 的未來研究方向有哪些？**
A：值得探索的方向包括：（1）把 IDS 分解擴展到其他組合性文字系統（韓文、日文、藏文），驗證「結構化獎勵」範式的通用性；（2）引入階層式或注意力式的 IDS 比對機制，讓空間關係錯誤獲得比部件錯誤更重的懲罰；（3）結合擴散模型的逐步去噪過程，在不同時間步施加不同粒度的獎勵，實現更精細的課程式學習；（4）把 IDS 與擴散模型的內部表徵對齊，使獎勵不只在輸出空間生效，也影響中間語意表徵；（5）發展自適應的雙分支加權機制，根據樣本難度動態調整語意與結構獎勵的比例；（6）探索 IDSpect 與人類回饋強化學習（RLHF）的結合，讓細粒度結構評估與整體美學判斷互補。

## 實務應用指南

### 適用場景

1. **中文海報與廣告素材自動生成**：電商平台、行銷團隊常需快速產出含正確中文標語（如「限時特價」「新品上市」）的宣傳圖。IDSpect 可在 GRPO 後訓練階段提供部件級回饋，協助模型正確渲染含複雜部件的字（如「贏」「鑽」「鬱」），避免出現「形似但部件錯置」的偽陽性字形。

2. **社群媒體梗圖與短影音封面**：內容創作者大量使用 T2I 模型生成含中文標題的封面圖。IDSpect 的細粒度獎勵能區分「整字錯誤」與「部分部件正確」，使模型在反覆生成中逐步修正結構錯誤，提升標題可讀性與品牌一致性。

3. **教育與語言學習教材**：兒童讀物、漢字教學卡片常需呈現筆畫清晰、部件正確的示範字。IDSpect 的 IDS 分解獎勵與教學語言學的部件分析框架一致，可作為「視覺化部件教學」的後訓練信號。

4. **遊戲本地化與 UI 文字渲染**：遊戲內道具名稱、技能說明、對話字幕常含罕用字或異體字。IDSpect 的專家 IDS 辨識器能處理長尾字元，減少翻譯後字形崩壞的問題。

5. **包裝設計與菜單生成**：餐飲、零售業常需將中文品名、成分標示嵌入產品圖。IDSpect 的裁切級比對機制對多區域文字（如主標題＋副標題＋小字註記）特別有利，能避免 OCR 獎勵因區域順序錯亂而誤判。

### 實作前置條件

**資料需求**
- 大量含中文文字的圖文對資料（用於基礎 T2I 預訓練或微調）。
- 帶 IDS 標註的中文字元資料集（用於訓練專家 IDS 辨識器）；可從 Unihan、IDS-UCS-Babel 等開源來源取得 IDS 序列。
- 文字偵測與裁切資料集（如 ICDAR、ReCTS），用於訓練 OCR 偵測器以產生 crop。
- 評測基準：LongText、GenTextEval，或自建含目標中文文字的 prompt 集。

**運算資源**
- 多張高階 GPU（如 NVIDIA A100/H100），用於 GRPO 群組採樣與策略更新；Qwen-Image 規模的模型通常需要 8 卡以上節點。
- 訓練專家 IDS 辨識器可使用單卡或雙卡，端看模型大小。
- 推論階段不增加額外成本（IDSpect 僅在訓練時運作）。

**技能門檻**
- 熟悉強化學習（特別是 GRPO/PPO 演算法）與 reward shaping。
- 具備 OCR pipeline（偵測 + 辨識）的實作經驗。
- 對漢字結構（部首、部件、空間關係）有基本理解；無需語言學博士程度，但需能讀懂 IDS 表示法（如 ⿰、⿱、⿸ 等運算子）。
- 熟悉 PyTorch、Diffusion 模型訓練流程。

### 實作步驟建議

1. **準備 IDS 標註資料**：從 Unihan 資料庫下載 UIDS 欄位，建立「字元 → IDS 序列」的對映表。對罕用字進行人工核對，確保 IDS 標註品質。

2. **訓練專家 IDS 辨識器**
   - 以現成 OCR 偵測器（如 PP-OCRv5 的偵測模組）切出文字 crop。
   - 設計辨識模型：可採用 CRNN、Transformer 或輕量 ViT，輸出為 IDS token 序列（空間運算子 + 部件）。
   - 訓練目標為序列交叉熵，並加入 CTC 或 attention 解碼以處理可變長度。
   - 在驗證集上評估「部件正確率」與「整字正確率」，確認辨識器對結構錯誤敏感。

3. **建立 IDSpect 獎勵函式**
   - 語意分支：使用 OCR 模型取得轉錄文字，計算編輯距離相似度（含子字串完全匹配加成）。
   - 結構分支：將目標文字確定性分解為 IDS token 序列，與辨識器預測的 IDS 序列做對齊；採用「全域唯一 token 信用」機制，使比對結果不受偵測區域順序影響。
   - 加權融合：例如 `R = α · r_sem + (1 − α) · r_struct`，α 可依任務調整（純結構任務可降低 α）。

4. **整合至 GRPO 後訓練流程**
   - 以 Qwen-Image（或同類 T2I 模型）作為策略模型。
   - 對每個 prompt 採樣 N 張圖（如 N=8），計算 IDSpect 獎勵。
   - 計算群組相對優勢，執行策略更新。
   - 監控 KL 散度避免獎勵 hack。

5. **評估與迭代**
   - 在 LongText、GenTextEval 上比較結構品質（部件正確率、空間關係正確率）與語意對齊（OCR 相似度）。
   - 對失敗案例進行錯誤分析：若 IDS 辨識器本身出錯，會誤導獎勵，需優先改善辨識器。
   - 逐步擴充訓練 prompt 集的多樣性（不同字數、不同字體場景）。

6. **部署上線**
   - 由於 IDSpect 僅在訓練階段使用，部署時只需載入後訓練好的模型權重，無需改動推論 pipeline。
   - 建立回饋機制：收集生成失敗案例，特別是含複雜部件的字，用於持續微調。

### 潛在風險與注意事項

- **IDS 辨識器錯誤傳播**：若辨識器對某個部件的辨識率偏低，會系統性地低估該部件的獎勵，造成模型傾向避開該部件。**緩解**：定期以人工核對的測試集監控辨識器品質；對低信心部件給予較低權重。

- **獎勵 hack（Reward Hacking）**：模型可能學會生成「部件正確但整字語意不通」的偽造字形以獲取結構獎勵。**緩解**：保留語意分支作為下限約束；對結構獎勵設定上限（如不超過語意獎勵的某個倍數）。

- **空間關係標註不一致**：IDS 的空間運算子（⿰⿱⿸ 等）在不同來源可能有歧義。**緩解**：統一採用單一標註規範（如 IDS-UCS-Babel），並在訓練前清洗資料。

- **長尾字元覆蓋不足**：罕用字可能 IDS 標註稀少，導致訓練資料不平衡。**緩解**：對低頻字進行資料增強（合成字體圖）；或採用 few-shot 策略。

- **GRPO 訓練不穩定**：群組相對估計在高方差獎勵下可能震盪。**緩解**：使用較大的群組大小、KL 約束、學習率 warmup。

- **多語言泛化**：本方法針對漢字設計，無法直接應用於拉丁字母或阿拉伯文。**緩解**：若需多語言，需為每種文字系統設計對應的結構化表示（如拉丁字母的字母＋變音符號分解）。

- **版權與內容審查**：訓練資料中的中文文字可能涉及敏感內容。**緩解**：建立文字內容過濾清單，避免生成含特定詞彙的圖像。

### 與其他技術的整合建議

- **與 TextPecker 互補**：TextPecker 擅長偵測異常字形（標記為 #），IDSpect 提供部件級細粒度評分。可將 TextPecker 作為「異常偵測前篩」，IDSpect 作為「結構評分後段」，形成兩階段獎勵。

- **與 GlyphControl、TextDiffuser 等字形條件化方法整合**：這些方法在生成階段提供字形先驗，IDSpect 在後訓練階段提供獎勵信號，兩者互補——前者改善「能不能寫對」，後者改善「寫對的程度」。

- **與 MLLM 評測器結合**：可使用 GPT-4V、Qwen-VL 等多模態模型做最終語意檢查，但應避免直接作為獎勵（因其語言先驗過強，易產生偽陽性，如論文 Fig. 1 所示）。

- **與偏好學習（DPO）整合**：可將 IDSpect 分數轉為偏好對，進行 DPO 訓練，適用於無法使用 GRPO 的場景。

- **與 LoRA / 輕量微調結合**：若無資源做全模型 GRPO，可凍結主模型，僅訓練 LoRA 適配器，IDSpect 仍可作為獎勵信號。

- **與內容審核 pipeline 整合**：在生成後以 OCR + IDS 辨識器自動檢查文字正確性，作為品質保證閘道。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解「為什麼中文文字渲染比英文難」——因為漢字是二維組合結構，而非一維字母序列。閱讀時可先看 Fig. 1 的視覺化範例，直觀感受「整字錯誤」與「部件錯誤」的差異，再回頭讀 Introduction 會更容易掌握動機。IDS 表示法（⿰⿱ 等運算子）可查 Unihan 資料庫的範例，無需深入語言學。

**給 AI 工程師**：重點關注 Method 章節的獎勵函式設計（特別是「全域唯一 token 信用」如何處理偵測區域順序問題）以及 GRPO 整合細節。實作時可先以小型 T2I 模型（如 Stable Diffusion 1.5 + 中文 LoRA）做概念驗證，再遷移到 Qwen-Image。建議先重現 OCR-only baseline，再逐步加入結構分支，觀察獎勵曲線變化。

**給研究者**：本論文的核心貢獻在於「將語言學結構表示（IDS）引入 RL 獎勵設計」，這是一個可推廣的範式——任何具有結構化分解的視覺任務（如數學公式、化學結構式、音樂符號）都可借鏡此思路。建議關注 Related Work 中關於 radicals、strokes、IDS 的傳統 OCR 研究，這些是本方法的理論根基。實驗部分可進一步探討：IDS 粒度（部件 vs. 筆畫）的影響、不同空間運算子的獎勵權重設計、跨字體泛化能力等。

**給產品經理**：IDSpect 的商業價值在於「降低中文 T2I 的品質不確定性」——傳統 OCR 獎勵容易讓模型停在「看起來像但其實錯」的字形，IDSpect 提供更精細的學習信號，使產品迭代更穩定。部署成本低（無推論開銷）是關鍵優勢。建議在導入時先定義明確的「文字正確性 KPI」（如部件正確率 ≥ 95%），並建立 A/B 測試框架比較 OCR-only 與 IDSpect 後訓練的效果。需注意 IDS 辨識器本身的維護成本，特別是對新字、網路流行語的覆蓋。
