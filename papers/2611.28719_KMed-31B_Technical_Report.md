KMed-31B 的核心方法論建立在「任務異質性導致訓練干擾」這一個關鍵觀察之上。作者將醫療任務依據兩個維度進行分類：**預期輸出形式**（expected output）與**可用回饋類型**（available feedback），並據此設計對應的訓練策略。

**任務分類與專家模型設計**

論文將醫療任務劃分為四大類別：
1. **開放式問答**（open-ended question answering）——具有參考答案
2. **選擇題問答**（multiple-choice question answering）——具有參考答案
3. **診斷預測**（diagnosis prediction）——具有參考答案
4. **臨床問診**（clinical inquiry）——無單一正確答案，需以評分量表（rubric）評分

前三類任務因具備參考答案，採用**答案匹配獎勵**（answer-matching rewards）的強化學習（RL）進行訓練；第四類臨床問診則因輸出開放且需多面向評估，採用專屬的訓練流程：**監督式微調（SFT）→ 固定評分量表的強化學習 → 改良版基於評分量表的在線策略蒸餾（D-ROPD）**。D-ROPD 是對 ROPD 的改進，在最終階段會根據多個模型共同產生的固定參考回應以及專家模型當前的 rollouts 重新生成每個查詢的評分量表，這種「評分量表再生」機制有助於提升回饋訊號的多樣性與穩定性。

**多教師在線策略差值蒸餾（MOPD²）的整合機制**

MOPD² 是本文最具方法論創新性的部分。它結合了兩個既有技術：
- **多教師在線策略蒸餾（MOPD）**：將多個領域專家模型整合為單一學生模型
- **在線策略差值蒸餾（OPD²）**：使用差值訊號而非絕對 log-probability

具體而言，在學生模型自身的 rollouts 上，每個任務類別對應的專家模型提供基於其 log-probability 差值的 token-level 訊號，差值的基準是固定的參考模型（即預訓練的 Gemma-4-31B 檢查點）。這種設計使訊號反映的是「專家相對於基礎模型學到了什麼」，而非專家的絕對機率分佈，從而避免了不同專家之間的絕對分數不可比問題，也保留了每個專家的領域優勢。

**合成健康對話（SHD）的資料建構**

SHD 是針對臨床問診任務設計的合成語料庫，其特點包括：
- 模擬基層醫療（primary care）中常見的臨床表現
- 涵蓋非專業使用者（lay users）與臨床醫師（clinicians）兩種對話角色
- 模擬器分離使用者可見資訊與助手可觀察資訊，創造「相關上下文可能初始缺失」的對話情境
- 示範資料鼓勵模型主動追問缺失上下文並檢驗請求前提

這種設計直接回應了臨床問診的核心挑戰：資訊不完整下的推理與互動。

- 公開醫療問答與臨床案例資料集（如 MedQA、PubMedQA 等）作為有參考答案任務的訓練來源。
- 臨床問診任務需要建構或取得帶有評分量表（rubric）的對話資料；本文提出的 Synthetic Health Dialogue (SHD) 採用韓國醫師執照考試臨床技能目標作為病患案例基礎，可作為仿效範本。
- 需準備多個教師模型（包含基礎模型本身）以產生示範回應與評分量表。

**運算資源**
- 訓練 31B 規模的專家模型與學生模型，建議配備 8 張以上 80GB 等級 GPU（如 H100/A100）並支援 bf16/fp16 混合精度。
- 強化學習階段（特別是 D-ROPD）需要大量 on-policy rollout，估計單次完整訓練需數週 GPU 時間。
- 部署階段單張 48GB GPU（如 A6000、L40）即可推論 31B 模型（4-bit 量化），符合「有限硬體」目標。

**技術能力**
- 熟悉分散式訓練框架（DeepSpeed、FSDP 或 Megatron-LM）。
- 具備強化學習實作經驗，特別是 GRPO、DPO 或 ROPD 系列演算法。
- 具備資料工程能力，能建構模擬病患對話產生器與評分量表自動生成流程。
- 醫學領域專家協助審核合成資料品質與評分量表合理性。

### 實作步驟建議

1. **任務分類與專家定義**：依「預期輸出」與「可取得回饋」兩軸，將目標醫療任務分為四類：(a) 開放式問答、(b) 選擇題問答、(c) 診斷預測、(d) 臨床問診。前三者具參考答案，採答案比對獎勵；第四類無單一正解，採評分量表回饋。

2. **基礎模型選擇**：選用合規、可商用的開放權重模型作為起點。本文以 Gemma-4-31B-IT 為主，並驗證 Qwen3.8-27B 同樣適用，顯示配方具備可移植性。

3. **專家模型訓練**：
   - 對前三類任務，以 RL + 答案比對獎勵訓練專家。
   - 對臨床問診任務，依序進行 SFT → 固定評分量表的 RL → D-ROPD（Diversified ROPD），最後階段以多模型共同產生的參考回應重新生成評分量表。

4. **建構 SHD 對話資料**：設計病患模擬器與臨床醫師模擬器，明確區分使用者可見資訊與助理可觀察資訊，刻意製造「關鍵上下文初始缺失」的情境，並產生鼓勵追問與檢驗前提的示範回應。

5. **多專家整合（MOPD^2）**：以基礎模型（未經後訓練的 Gemma-4-31B）作為固定參考模型，在學生模型的 on-policy rollout 上，由各任務對應的專家提供 log-probability 差值訊號，使學生學到「相對基礎模型的增量知識」而非專家本身的全部行為。

6. **評估與迭代**：以 HealthBench Hard、HealthBench Professional、MedXpertQA Text、JAMA Clinical Challenge、NEJM AI QA、MedQA-USMLE 六項基準監測效能，特別注意「選擇題分數 vs. 開放式對話分數」的消長，必要時調整專家訓練強度或資料混合比例。

7. **部署與監控**：以 4-bit 量化版本部署於本地伺服器，建立領域外問題過濾機制與回應品質抽樣審核流程，特別關注涉及診斷與用藥建議的回應。

### 潛在風險與注意事項

**幻覺與安全性風險**
- 醫療模型產生錯誤診斷或用藥建議可能造成實質傷害。緩解方式：限制模型對高風險問題的自主回答，要求其轉介專業醫療人員；建立紅隊測試集定期壓測。
- 評分量表可能無法涵蓋所有臨床情境，導致 RL 訊號失真。緩解方式：邀請臨床醫師定期審視評分量表，並保留人類監督迴路。

**資料偏誤風險**
- SHD 以韓國醫師執照考試臨床技能目標為基礎，可能無法代表其他族群或醫療體系。緩解方式：依目標使用族群在地化案例集，並評估跨族群表現差異。
- 合成對話可能過於「乾淨」，缺乏真實臨床溝通中的模糊、矛盾與情緒因素。緩解方式：混入真實去識別化對話（需取得 IRB 核准）。

**訓練不穩定風險**
- 多專家整合時，不同專家訊號強度差異可能導致學生偏向某一類任務。緩解方式：監測各任務驗證集分數，必要時調整專家訊號權重或採用課程式訓練。
- D-ROPD 階段若評分量表品質不穩定，可能造成訓練震盪。緩解方式：保留早期 checkpoint，設定保守的學習率與 KL 約束。

**法規與合規風險**
- 醫療 AI 在多數國家受醫療器材法規規範。緩解方式：確認目標市場的監管路徑（如 FDA SaMD、EU MDR、台灣 TFDA），必要時以「臨床決策輔助」而非「自主診斷」定位上市。
- 病患資料用於訓練需符合 HIPAA、GDPR 或在地個資法。緩解方式：採用合成資料優先策略，建立資料治理與稽核機制。

**成本與時程風險**
- 完整重現本文結果需投入大量 GPU 時數與人力。緩解方式：先以小規模實驗驗證配方可行性，再逐步擴大；考慮與具備醫療 AI 經驗的雲端服務商合作。

### 與其他技術的整合建議

**與電子病歷系統（EMR/EHR）整合**
- 透過 FHIR API 將模型接入醫院 HIS 系統，使其能讀取結構化病歷資料回答臨床問題。建議採用檢索增強生成（RAG）架構，讓模型先檢索相關病歷段落再生成回應，減少幻覺。
- 整合時應建立權限控管層，確保模型僅能存取當次診療所需的病患資料。

**與醫療影像 AI 整合**
- 將 KMed-31B 作為多模態系統的文字推理層，搭配專門的影像模型（如放射學 CT/MRI 模型、病理切片模型）形成「視覺編碼器 + 醫療 LLM」架構。
- 影像模型輸出結構化發現，由 KMed-31B 整合病歷文字與影像發現產生綜合判讀報告。

**與臨床指引知識庫整合**
- 串接 UpToDate、DynaMed 等臨床指引資料庫，採用 RAG 確保回應引用最新指引版本。
- 建立引用追溯機制，使每個臨床建議都能回溯至具體指引條文，便於醫師查證。

**與既有醫療 LLM 整合**
- 在多模型情境下，可將 KMed-31B 作為「臨床問診專家」，與擅長選擇題的模型（如 Med-PaLM 系列）組成模型路由系統，依任務類型分派。
- 透過 API 閘道統一介面，前端應用無需感知後端模型切換。

**與品質監控平台整合**
- 串接 LangSmith、Langfuse 或自建監控系統，追蹤每次推論的輸入、輸出、評分量表分數與使用者回饋。
- 建立自動化異常偵測規則，例如當模型對同一症狀給出矛盾建議時觸發人工審核。
