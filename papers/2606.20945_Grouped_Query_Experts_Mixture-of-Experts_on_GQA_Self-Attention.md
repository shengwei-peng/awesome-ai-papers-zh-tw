# 分組查詢專家：基於 GQA 自注意力的混合專家模型

## ⚡ TL;DR

標準注意力對所有詞元均勻啟動，造成長序列計算浪費。
本文提出分組查詢專家，在GQA群組內以路由器為每個詞元選擇少量查詢頭專家，保持KV快取稠密。
在固定訓練預算下，GQE啟動半數查詢頭即達成全啟動GQA的下游準確率，長序列預填充加速約1.7倍。

## 摘要翻譯

自注意力（Self-attention）是 Transformer 效能的核心，且在長上下文（long context）情境下通常是 Transformer 中成本最高的部分，因為其成對詞元交互作用（pairwise token interactions）會隨序列長度（sequence length）呈二次方擴展（quadratic scaling）。標準稠密注意力（standard dense attention）也會對每個詞元（token）套用同一組注意力頭（attention heads），無論詞元難度或資訊含量為何。這種均勻啟動（uniform activation）會浪費計算量，在序列變長、注意力成本快速增加時尤其如此。我們提出分組查詢專家（Grouped Query Experts, GQE），一個建構於分組查詢注意力（Grouped-Query Attention, GQA）之上的混合專家模型（Mixture-of-Experts, MoE）層。在每個 GQA 分組內，路由器（router）會為每個詞元選取 k 個查詢頭專家（query-head experts），而所有鍵值頭（key-value / KV heads）則保持稠密（dense）且不做更動。因此，GQE 保留了 GQA 的 KV 快取（KV cache）優勢，且僅縮減實際啟動的查詢頭（query heads）的計算量。在 250M 參數規模（parameter scale）與固定的 30B 詞元預算（token budget）下，GQE 在下游準確率（downstream accuracy）上與全啟動 GQA 基線（all-active GQA baseline）持平，同時每個詞元僅啟動一半的查詢頭。

### 核心貢獻（3～5點）
- 揭示標準稠密注意力（standard dense attention）在長上下文（long context）時的兩大瓶頸：成對詞元交互作用（pairwise token interactions）隨序列長度（sequence length）呈二次方擴展（quadratic scaling），以及均勻啟動（uniform activation）所有注意力頭（attention heads）所造成的計算浪費。
- 提出分組查詢專家（Grouped Query Experts, GQE），作為建構於分組查詢注意力（Grouped-Query Attention, GQA）之上的混合專家模型（Mixture-of-Experts, MoE）層；透過路由器（router）為每個詞元（token）動態選取 k 個查詢頭專家（query-head experts），同時保持所有鍵值頭（key-value / KV heads）稠密（dense）不變。
- 在完整保留 GQA 的 KV 快取（KV cache）優勢與記憶體效率的前提下，僅針對實際啟動的查詢頭（query heads）縮減計算量，實現查詢端的條件式稀疏化。
- 在 250M 參數規模（parameter scale）與固定 30B 詞元預算（token budget）下，證明 GQE 可達到與全啟動 GQA 基線（all-active GQA baseline）對等的下游準確率（downstream accuracy），但每詞元僅需啟動一半查詢頭。

### 適合對象
從事大型語言模型架構設計與效率最佳化的研究者與工程師，特別是關注注意力機制稀疏化、混合專家模型（MoE）應用，以及長上下文（long context）推論加速與 KV 快取（KV cache）記憶體最佳化的進階讀者。

## 深度分析

#### 方法論解析

本研究的核心命題在於：標準稠密注意力（standard dense attention）對所有詞元（token）均啟動（uniform activation）相同的注意力頭（attention heads）集合，導致計算資源在異質詞元上下文（heterogeneous token contexts）中分配不當。具內容詞彙（content-bearing words）或長程依賴（long-range dependencies）可能需要專門化注意力頭（specialized heads），而標點、停用詞（stop words）與低資訊量詞元（low-information tokens）則未必需要。為此，作者提出 Grouped Query Experts（GQE，分組查詢專家），將混合專家模型（Mixture-of-Experts, MoE）的條件計算（conditional computation）從傳統的 MLP 區塊（MLP blocks）遷移至分組查詢注意力（Grouped-Query Attention, GQA）架構之上。

在 GQA 中，查詢頭（query heads）被劃分為若干群組（groups），每個群組共享單一組鍵值頭（key-value heads, KV heads），從而降低 KV 快取（KV cache）的記憶體頻寬（memory bandwidth）壓力。然而，GQA 仍對每個詞元計算所有查詢頭，僅節省記憶體而未減少查詢端運算量。GQE 的設計保留 GQA 的稠密 KV 快取（dense KV cache）與鍵值投影完全不變，僅在「群組內」引入路由器（router）：對於每個詞元，路由器在每一個 GQA 群組中選擇 top-k 個查詢頭專家（query-head experts）進行運算，其餘查詢頭專家則不參與當前詞元的自注意力（self-attention）計算。

具體而言，設總共有 N 個查詢頭專家，分為 G 個群組，則每群組含 M = N/G 個專家 {E_{g,1}, ..., E_{g,M}}。每個專家擁有獨立的查詢投影（query projection），但共享所屬群組 g 的同一組 KV 投影與 KV 快取。輸出時，僅有被選中的 k 個專家之輸出會被組合，再經輸出投影 W_O 彙整。這種設計確保了序列長度（sequence length）增加時，雖然成對詞元交互作用（pairwise token interactions）仍隨二次方擴展（quadratic scaling），但查詢端運算已被稀疏化，從而實現計算量縮減（compute reduction）。

值得特別注意的是，作者引入了一個常開共享頭（always-on shared head）作為穩定機制。該頭不經路由、永遠啟動，為路由器（router）提供穩定的學習訊號（learning signal），避免稀疏查詢頭路由（sparse query-head routing）在訓練初期因梯度不穩定而崩潰。這是方法論上的關鍵細節：若無此共享頭，GQE 很難在從頭聯合訓練（jointly trained from the start）的設定下收斂至與全啟動 GQA 基線（all-active GQA baseline）對等（parity）的品質。

#### 實驗數據解讀

作者在固定 30B 詞元預算（token budget）與 250M 參數規模（parameter scale）下進行訓練與評估。此設定屬於中小型模型範疇，但足以驗證核心假設：GQE 能否在無品質損失（quality loss）的前提下啟動更少的查詢頭。實驗結果顯示，GQE 在下游準確率（downstream accuracy）上與全啟動 GQA 基線持平，但每個詞元僅啟動一半的查詢頭專家；若計入常開共享頭，實際運算量約為 9/16 的查詢注意力頭（query-attention heads）。

從圖 1 的預填充時間（prefill time）加速比（speedup）來看，GQE 在長上下文（long context）情境下可達約 1.7–1.8× 的加速。這符合理論預期：當序列長度（sequence length）增長，自注意力的計算瓶頸（compute bottleneck）主導整體延遲，此時省略的查詢端注意力計算（avoided query-side attention computation）所帶來的效益被放大。相對地，在短序列時加速比趨近於 1×，因為固定開銷與其他層的計算佔比較高。

然而，實驗範圍存在明顯限制。首先，250M 參數規模對於現代大型語言模型而言仍屬小規模，MoE 類方法通常在更大規模（如 7B 以上）才能充分展現其條件計算的優勢。其次，30B 詞元預算雖足以訓練小型模型，但是否能支撐更複雜的路由策略與專家分化仍有疑問。此外，論文提供的實驗脈絡主要聚焦預填充階段（prefill phase），對於自迴歸解碼（autoregressive decoding）階段中 KV 快取讀取與稀疏查詢頭之間的互動效應著墨較少。

#### 與現有研究的比較

相較於傳統將 MoE 應用於 MLP 區塊的作法，GQE 首次系統性地將稀疏專家路由機制嵌入 GQA 注意力區塊（attention block），且嚴格限制「僅稀疏化查詢頭、不動 KV 路徑」。這與過往的條件注意力研究形成鮮明對比：

1. **Head pruning（注意力頭剪枝）**：屬於訓練後的靜態剪枝，永久移除不重要的頭。GQE 則是動態條件計算，每個詞元可依其需求選擇不同子集，保留模型容量（model capacity）的完整性。
2. **MoA（Mixture of Attention）**：從全部注意力頭中選擇 top-k，可能破壞 GQA 的群組結構，且未針對 KV 快取共享進行優化。GQE 則在固定 GQA 群組內路由，確保每個群組仍貢獻專家，並維持記憶體使用配置（memory profile）與 GQA 一致。
3. **SwitchHead / MoH（Mixture of Heads）**：雖引入閘控機制，但保留完整的每頭 KV 快取，未享有 GQA 的記憶體頻寬優勢。GQE 直接繼承 GQA 的 KV 共享設計，記憶體成本更低。
4. **MoMHA / LLaMA-MoE v2**：前者將專家設計為共享 KV 的頭群組；後者則是將已訓練好的稠密模型轉換為 MoE。GQE 的設計更為簡約：不重新分群、不轉換現有模型，而是從頭聯合訓練路由器與專家，並與 GQA 的現有實作完全對齊。

GQE 的主要優勢在於工程簡潔性與記憶體相容性。由於 KV 快取維持稠密，現有的推理優化（如 KV cache paging、flash attention 變體）幾乎無需修改即可適用。然而，其限制也同樣源於此設計：KV 端的計算與記憶體成本並未減少，僅縮減查詢投影與查詢-鍵交互的運算。對於極長上下文，若 KV cache 本身已成瓶頸，GQE 的助益將被限制。

#### 可重現性評估

就本研究提供的全文脈絡而言，作者並未提及任何開源程式碼（open-source code）、訓練資料集（training datasets）或釋出的模型權重（model weights）。文中未引用 GitHub 倉庫（repository）或資料卡（data card），亦未詳細交代硬體配置、路由器優化器設定、負載平衡損失（load-balancing loss）有無採用、以及 top-k 選擇的具體 k 值在不同群組間是否動態調整等關鍵實作細節。

在 250M 參數規模與 30B 詞元預算下，理論上復現門檻不高，但缺乏上述資訊將顯著增加復現難度。例如，常開共享頭的初始化方式、路由器輸入的隱藏狀態選取（是使用前置層輸出還是獨立投影）、以及專家輸出如何加權（是否使用 router probability 進行加權求和或純粹 top-k 平均）等，均直接影響訓練動態與最終下游準確率。此外，圖 1 的預填充時間測量未說明硬體規格與批次大小（batch size），使得 1.7–1.8× 加速比的外部驗證變得困難。

#### 未來研究方向

1. **大規模參數驗證**：將 GQE 擴展至 7B、70B 甚至更大參數規模，觀察其在大型模型上的計算量縮減與品質保留是否依然成立。MoE 方法通常在大模型上才能充分發揮條件計算的容量優勢。
2. **解碼階段深度優化**：當前成果偏重預填充（prefill），未來應針對自迴歸解碼（autoregressive decoding）階段評估 GQE 的延遲與吞吐量。特別是在每步僅生成一個詞元的場景下，稀疏查詢頭是否能有效降低記憶體頻寬壓力，值得進一步探討。
3. **路由器機制精進**：本文採用相對簡單的 top-k 路由，未來可引入輔助負載平衡損失、專家選擇的多樣性正則化，或探索任務特定路由（task-specific routing）以提升專家分化程度。
4. **與 MLP MoE 的複合設計**：同時在注意力區塊與 MLP 區塊引入稀疏專家，形成「雙稀疏」架構。需探討兩者的路由訊號是否會互相干擾，或能否透過聯合設計達到更顯著的整體加速。
5. **硬體協同設計**：現有深度學習框架對於稀疏查詢頭的啟動支援有限，未來可開發專用 CUDA kernel，針對「群組內部分專家啟動」的記憶體存取模式進行優化，以實現圖 1 以外更穩定的端到端加速。
6. **長上下文基準測試**：在針草堆尋針（needle-in-a-haystack）、長文件問答等長上下文（long context）基準上，驗證稀疏查詢頭是否會遺失關鍵的長程依賴資訊，並分析不同專家對不同距離依賴的專精程度。

## 論文問答

**Q1：標準自注意力機制在處理長序列時，主要面臨什麼樣的計算效率問題？**
A：標準自注意力的成對詞元交互作用會隨序列長度呈二次方擴展，使其成為長上下文 Transformer 中最主要的計算瓶頸。此外，標準稠密注意力會對每個詞元均勻啟動所有注意力頭，無論該詞元是承載內容的詞彙還是標點符號等低資訊量詞元，這種均勻分配造成了大量不必要的計算浪費。隨著序列增長，這種無差別的計算支出會迅速放大，導致推理成本急劇上升。

**Q2：現有方法如 GQA 或應用於 MLP 區塊的 MoE，為何仍無法充分解決注意力查詢端的計算浪費？**
A：分組查詢注意力（GQA）雖然透過在查詢群組內共享鍵值頭來降低 KV 快取的記憶體與頻寬負擔，但它仍然對每個詞元計算所有查詢頭，查詢端的計算量依舊是稠密的。傳統混合專家模型（MoE）則主要應用於 Transformer 的 MLP 區塊，並未觸及注意力區塊內部的均勻啟動問題。至於現有的條件或稀疏注意力方法，有些會更動 KV 快取結構、永久剪枝注意力頭，或是在不適當的粒度上進行路由，因而難以同時保留 GQA 的記憶體優勢並實現查詢端的條件計算。

**Q3：為何將條件計算引入注意力區塊對現代大型語言模型如此重要？**
A：隨著模型需要處理的上下文長度不斷增加，注意力成本在整體計算中的佔比持續攀升，提升注意力效率已成為模型可擴展性的關鍵。自然語言中的詞元本質上具有異質性：罕見詞項與具內容詞彙可能需要專門化的注意力模式，而停用詞或常見詞則未必需要同等資源，因此均勻計算本質上是次優的。讓查詢頭的啟動變成條件式，能讓模型依據詞元需求動態分配計算，從而在維持品質的同時顯著降低推理開銷。

**Q4：分組查詢專家（GQE）的核心運作機制是什麼？**
A：GQE 將每個 GQA 群組內的查詢頭視為一組專家，並透過路由器為每個詞元在群組內選擇前 k 個查詢頭專家進行計算。所有的鍵值頭（KV heads）則保持稠密且不變，完整保留原始 GQA 的記憶體使用配置與 KV 快取結構。這種設計僅讓查詢端的計算變成條件式，而每個詞元仍然對相同的群組 KV 頭進行注意力運算。

**Q5：相較於 MoA、SwitchHead 或 MoMHA 等先前的混合注意力方法，GQE 的關鍵區別與創新何在？**
A：GQE 僅在固定的 GQA 群組內部進行路由，而非從全局所有頭中挑選，這確保了每個群組都能持續貢獻資訊，同時簡化了路由決策的複雜度。最關鍵的是，GQE 完全不更動或稀疏化 KV 快取，避免了因 KV 頭變動而帶來的記憶體與頻寬難題。此外，GQE 從頭開始聯合訓練路由器與專家，而非對已訓練好的稠密模型進行剪枝或轉換，這使其訓練過程更為一致且穩定。

**Q6：為什麼 GQE 的設計包含一個「常開共享頭」，並且堅持保持 KV 頭稠密？**
A：常開共享頭的存在是為了提供路由器穩定的學習訊號，這對於稀疏查詢頭路由能否達到與稠密基線相當的品質至關重要，缺乏此穩定機制可能導致路由策略崩潰。保持 KV 頭稠密則是為了完整保留 GQA 降低 KV 快取記憶體與頻寬消耗的核心優勢，確保自迴歸解碼階段的效率不會受損。這些設計選擇反映了在最小化模型穩定性風險與最大化查詢端實際計算節省之間的刻意權衡。

**Q7：論文中用於評估 GQE 的實驗設定為何？**
A：實驗在 250M 參數規模下進行，並採用固定的 30B 詞元預算，將 GQE 與全啟動的 GQA 基線進行比較。這種控制變因的設定能夠隔離條件式查詢計算所帶來的影響，因為模型大小與資料曝光量都維持一致。評估重點放在下游準確率上，以驗證計算量縮減並未犧牲模型品質。

**Q8：實驗的主要結果在準確率與計算量方面呈現了什麼發現？**
A：GQE 在下游準確率上成功達到了與全啟動 GQA 基線相當的水準，儘管每個詞元僅啟動了一半的路由查詢頭專家。在主要設定中，包含常開共享頭在內，總共只計算了 16 個查詢注意力頭中的 9 個。此外，在長上下文情境下，實際測得的預填充時間加速比約達到 1.7 至 1.8 倍，顯示出顯著的實際牆鐘時間效率提升。

**Q9：稀疏查詢頭路由要有效運作，必須滿足什麼關鍵條件？**
A：根據論文所述，稀疏查詢頭路由只有在路由器獲得適當學習訊號，並且由常開共享頭加以穩定的情況下，才能匹配稠密 GQA 基線的表現。若缺少這種穩定機制，路由器可能無法學習到有效的專家選擇策略，進而導致品質下降。這說明常開共享頭不僅是架構上的細節，更是訓練穩定性與最終性能對等的關鍵元件。

**Q10：在哪些實際部署場景中，GQE 能夠提供最大的價值？**
A：GQE 在預填充階段注意力佔據主要延遲的長上下文應用中特別有價值，例如文件理解、程式碼生成或多輪對話代理。由於它保留了稠密 KV 快取，因此也非常適合自迴歸解碼場景，這類場景通常受記憶體頻寬與快取大小限制。任何大規模部署 GQA 基礎模型的生產系統，都可以採用 GQE 來降低查詢端計算，而無需重寫 KV 儲存的服務基礎設施。

**Q11：從系統與模型服務的角度來看，GQE 有哪些吸引人的特性？**
A：GQE 維持與標準 GQA 完全相同的 KV 快取結構，這意味著現有的推論引擎、記憶體佈局與分頁機制幾乎不需要修改即可支援。計算節省集中在查詢端，能直接轉化為更快的預填充時間與前向傳播時更低的啟動記憶體需求。由於此方法並非永久剪枝注意力頭，當模型需要時仍能動用完整容量，為生產環境提供了一條安全的部署路徑。

**Q12：GQE 可能對未來高效 Transformer 架構的研究產生什麼樣的影響？**
A：GQE 證明了 MoE 原則可以有效地從 MLP 區塊遷移至注意力區塊，同時不犧牲 KV 快取的效率，這開啟了條件計算在 Transformer 中的全新設計空間。它挑戰了「所有注意力頭必須對所有詞元保持啟動」的預設假設，可能激發更細粒度的路由機制與異質注意力模式。未來的架構或許會更傾向將注意力視為一種可動態分配的資源，而非固定不變的均勻成本。

**Q13：從文中描述的實驗範圍來看，GQE 目前存在哪些明顯的限制？**
A：目前的結果僅限於 250M 參數規模與固定的 30B 詞元訓練預算，對於擴展到數十億甚至兆級參數模型的可擴展性仍屬未知。論文也未報告針對不同 k 值、不同群組數量，或超越摘要準確率指標的多樣下游任務的廣泛消融實驗。此外，評估重點放在預填充加速比上，對於極長上下文下的端到端自迴歸生成延遲影響，仍有待更充分的測量。

**Q14：在什麼樣的條件下，GQE 可能無法達到基線水準的效能？**
A：若路由器未獲得充分穩定——例如移除常開共享頭——稀疏路由可能無法獲得適當的梯度訊號，導致專家選擇策略崩潰至次優狀態。某些需要每個查詢頭同時捕捉細粒度全局模式的任務，可能會挑戰「詞元僅需部分專家子集即可勝任」的核心假設。此外，在極小規模或訓練資料不足的情況下，額外的路由器參數可能無法學習到有意義的條件模式，導致品質低於稠密基線。

**Q15：GQE 為未來研究指出了哪些可能的方向？**
A：未來研究可將 GQE 擴展至更大模型規模與更長的訓練週期，以驗證在高容量制度下準確率與計算的權衡是否依然有利。學界也可探索自適應路由策略，例如依據詞元或層級動態調整 k 值，而非對所有序列使用固定的 top-k。另一個有前景的方向是將 GQE 與線性注意力或狀態空間模型等其他高效注意力變體結合，以在查詢端與 KV 端同時複合節省計算成本。

## 實務應用指南

### 適用場景

1. **長文件分析與法律／醫療問答**：處理數萬詞元以上的合約、病歷或研究文獻時，自注意力的二次方擴展會使預填充時間成為瓶頸。GQE 在長上下文區間可達 1.7–1.8× 加速比，且保持稠密 KV 快取，特別適合需頻繁載入長篇參考資料的檢索增強生成（RAG）系統。
2. **多輪對話與即時串流摘要**：客服代理或會議摘要工具需在多輪歷史中快速定位關鍵資訊。GQE 讓具內容詞彙啟動專門化注意力頭，低資訊量詞元則減少查詢頭計算，降低每次預填充的延遲。
3. **邊緣裝置長上下文推論**：手機或車載晶片記憶體頻寬有限，GQA 已能壓縮 KV 快取，GQE 進一步縮減查詢端活躍計算量，在固定記憶體配置下支援更長序列。
4. **大規模程式碼理解與生成**：程式碼庫常含長程依賴與重複結構，GQE 的條件計算可針對語法關鍵詞元啟動對應查詢頭專家，減少在標點與常見模板上的無謂計算。
5. **多模態長序列建模**：影片或長時音訊的詞元序列極長，GQE 可在不更動共享鍵值路徑的前提下，於每個分組查詢注意力群組內稀疏啟動查詢頭，降低跨模態注意力區塊的成本。

### 實作前置條件

- **資料**：需準備符合目標領域的長上下文語料。若從頭訓練，建議至少具備 30B 詞元等級的預訓練預算；若基於現有 GQA 模型持續預訓練，則需額外準備長序列樣本以讓路由器學習異質詞元上下文的分派模式。
- **算力**：訓練階段需支援大規模並行的 GPU 叢集（如 NVIDIA A100/H100）。推論階段則需評估目標硬體是否受惠於查詢端計算縮減——特別是預填充階段為瓶頸的場景。
- **技術能力**：團隊需熟悉 Transformer 底層實作、GQA 機制、MoE 路由損失設計，並能修改注意力核心（如客製化 CUDA kernel 或 Triton）以支援每個詞元僅計算 top-k 查詢頭。
- **模型基底**：必須以 GQA 架構為起點（如 LLaMA 2/3、Mistral 系列），因 GQE 的路由粒度建立在固定分組查詢群組之上。

### 實作步驟建議

1. **確認 GQA 基底與群組配置**：先確保模型已採用分組查詢注意力，並固定 KV 群組數量（如 8 個群組）。每個群組內規劃 M 個查詢頭專家，總數 N = G × M。
2. **設計群組內路由器與常開共享頭**：在每個 GQA 群組內建置路由器，輸出該詞元對 M 個查詢頭專家的分數；同時保留一個 always-on shared head（常開共享頭），作為穩定訓練信號與品質保底。
3. **聯合訓練與負載平衡**：從頭聯合訓練路由器與專家，而非事後剪枝或轉換稠密模型。加入輔助負載平衡損失，避免所有詞元都湧向少數查詢頭專家。
4. **固定詞元預算對齊驗證**：在固定訓練詞元預算（如 30B）下，與全啟動 GQA 基線比較下游準確率。論文顯示啟動一半查詢頭（含共享頭為 9/16）即可達到對等品質。
5. **長上下文推論優化**：針對目標序列長度（512–1024 以上）測量預填充時間。由於 KV 快取維持稠密，可沿用現有分頁注意力機制，但需在查詢投影與注意力核心層實作稀疏啟動邏輯。
6. **部署與漸進上線**：先於離線批次任務（如文件摘要）驗證端到端延遲與準確率，再導入即時服務；監控路由器分派分佈，確保罕見詞項仍被正確路由至專門化注意力頭。

### 潛在風險與注意事項

- **路由不穩定與訓練崩潰**：若缺少常開共享頭，路由器可能在訓練初期因梯度稀疏而震盪。務必保留 always-on shared head，並在熱啟動階段給予較高學習率穩定信號。
- **短序列效益不明顯**：GQE 的加速比隨序列長度增加而提升。若應用以短提示為主（<256 詞元），稀疏查詢頭的額外路由開銷可能抵銷收益，建議先以長上下文任務為目標。
- **硬體與框架支援缺口**：標準 FlashAttention 或 cuDNN 並未原生支援「每詞元不同查詢頭」的稀疏模式，需自行撰寫 Triton/CUDA 核心或等待框架更新，否則實測加速可能低於理論值。
- **專家崩潰（Expert Collapse）**：即使保留稠密 KV 快取，群組內查詢頭仍可能出現負載失衡。建議監控每個專家的啟動頻率，並調整輔助損失權重。
- **領域遷移時的品質風險**：若將預訓練好的 GQE 模型微調至全新領域，原本學習的異質詞元分派模式可能失效。建議在領域適應時一併微調路由器層。

### 與其他技術的整合建議

- **推論引擎（vLLM、TensorRT-LLM）**：由於 GQE 不更動 KV 快取結構，可無縫整合現有分頁 KV 快取與連續批處理。只需在注意力前向傳播層注入群組內 top-k 選擇邏輯。
- **量化與壓縮（AWQ、GPTQ、KV cache quantization）**：查詢投影矩陣可獨立量化；KV 路徑維持稠密，因此標準 KV 快取量化（如 INT8）可直接套用，雙重節省記憶體頻寬。
- **投機解碼（Speculative Decoding）**：GQE 主要降低預填充延遲，投機解碼則加速解碼階段，兩者可互補。建議在長上下文服務中同時導入，分別優化 prefill 與 decode。
- **上下文稀疏化（H2O、SnapKV）**：這類方法壓縮 KV 快取長度，而 GQE 壓縮查詢端計算。技術正交，可疊加使用，但需注意疊加後的注意力模式是否過度稀疏導致長程依賴遺失。
- **分散式 MoE 訓練框架（DeepSpeed-MoE、FSDP）**：雖 GQE 的專家位於注意力區塊而非 MLP，仍可借鏡 MoE 的專家並行策略，將不同查詢頭專家分置不同 GPU，但由於每個詞元僅啟動 k 個專家，通訊量相對可控。

### 給不同背景讀者的閱讀建議

- **初學者**：請先理解「為何每個詞元都需要啟動所有注意力頭」這個核心問題，並對照圖 2 與圖 3 的架構示意，建立「群組內路由」與「保留稠密 KV 快取」的直覺。數學式可略過，重點放在均勻啟動造成的計算浪費與條件計算帶來的效益。
- **AI 工程師**：請仔細研讀第 3 節的架構細節，特別是 always-on shared head 的實作方式與路由器輔助損失設計。評估現有程式碼庫是否能在 GQA 基礎上新增每群組 top-k 選擇，並規劃客製化核心以實現論文圖 1 的 1.7–1.8× 加速比。
- **研究人員**：關注本文與 MoA、SwitchHead、MoH 等注意力路由方法的差異（見第 2.3 節）。GQE 的設計選擇——在固定 GQA 群組內路由、不改 KV 快取、從頭聯合訓練——提供了「約束即簡化」的研究視角，適合探討條件計算在注意力區塊的理論極限。
- **產品經理**：掌握圖 1 的長上下文加速比與「固定 30B 詞元預算下準確率對等」這兩個關鍵數據。請注意這是訓練階段的架構變更，無法直接套用在已訓練好的稠密模型上；規劃產品路線圖時，需預留從頭訓練或持續預訓練的時程與算力資源。
