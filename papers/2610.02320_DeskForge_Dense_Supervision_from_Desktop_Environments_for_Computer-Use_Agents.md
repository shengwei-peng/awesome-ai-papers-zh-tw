# DeskForge：來自桌面環境（desktop environment）、用於電腦使用代理（computer-use agents）的密集監督訊號（dense supervision）

**原文標題：** DeskForge: Dense Supervision from Desktop Environments for Computer-Use Agents  
**作者：** A. Said Gurbuz、Ahmed Nassar、Sunghwan Hong 等 5 位作者  
**發布日期：** 2026-10-01  
**HF 連結：** [https://huggingface.co/papers/2610.02320](https://huggingface.co/papers/2610.02320)  
**arXiv：** [https://arxiv.org/abs/2610.02320](https://arxiv.org/abs/2610.02320)  

---

## ⚡ TL;DR

現有桌面操作代理缺乏具密集標註且可控變化的訓練資料。
提出 DeskForge，可控組合真實應用程式於桌面場景，融合截圖、輔助樹與視窗幾何生成密集標註。
微調四款視覺語言模型後，在保留與外部 GUI 定位基準及長程任務完成率上均顯著提升。

---

## 摘要翻譯

電腦使用代理（computer-use agents）必須在複雜桌面環境（desktop environment）中可靠地定位動作目標；然而多個應用程式、重疊視窗（overlapping windows）與視覺相似的控制項（visually similar controls）常相互干擾。現有訓練資料鮮少同時為這類場景提供密集元素標註（dense element annotations），亦鮮少以可控方式系統化地變化這些場景。我們提出 DeskForge，一個可控的 Linux 桌面環境（Linux desktop environment）框架，能夠組合並探索真實應用程式（real applications），為電腦使用代理產生大規模監督訊號。其可變化應用程式狀態（application state）、內容、視窗佈局（window layout）、外觀與解析度（resolution），並將截圖、輔助功能樹（accessibility tree）與視窗幾何資訊（window geometry）融合為密集元素標註，同時記錄每個執行動作的動作結果（action outcome）。利用此環境，我們建構了 DeskForge-1M，一個包含 120 萬張已標註桌面觀察影像與 1.597 億個元素實例（element instances）的資料集。我們從 DeskForge-1M 中抽取 20 萬筆定位範例，對四個視覺語言模型（vision-language models, VLMs）進行微調（fine-tuning）。四個模型在未見過的桌面條件（held-out desktop conditions）以及全部五個外部 GUI 定位基準測試（external GUI grounding benchmarks）上皆有所提升；其中 Qwen3.5-4B 在 ScreenSpot-Pro 上的準確率提升 11.51 個百分點，在 OSWorld-G 上提升 10.11 個百分點。這些提升也延伸至長程任務完成（long-horizon task completion）：在使用固定規劃器（planner）時，經微調的動作模型（action model）能完成更多 WebArena-Infinity 與 OpenApps 任務，其中 Qwen3.5-4B 分別從 119 個任務中的 31 個提升至 50 個，以及從 100 個任務中的 3 個提升至 15 個。這些結果顯示，真實桌面環境的可控組合能提供可擴展的監督訊號來源，同時改善 GUI 定位（GUI grounding）與長程電腦使用。框架程式碼、資料集與微調後的模型均可於專案頁面取得：https://saidgurbuz.github.io/deskforge/

### 核心貢獻（3～5點）
- 提出 DeskForge：一個可控的真實 Linux 桌面環境框架，能系統化地組合並變化應用程式狀態、內容、視窗佈局、外觀與解析度，以產生大規模密集監督訊號。
- 建構 DeskForge-1M 資料集：包含 120 萬張已標註桌面截圖與 1.597 億個元素實例，透過融合截圖、輔助功能樹與視窗幾何資訊，產生高品質的密集元素標註與動作結果記錄。
- 驗證密集監督訊號對 GUI 定位的效益：在四個視覺語言模型上進行微調後，於未見過的桌面條件與五個外部 GUI 定位基準測試上均顯著提升，Qwen3.5-4B 在 ScreenSpot-Pro 與 OSWorld-G 上分別提升 11.51 與 10.11 個百分點。
- 展示長程任務完成的遷移效果：在固定規劃器下，經微調的動作模型於 WebArena-Infinity 與 OpenApps 上完成更多任務，證明 GUI 定位能力的提升可轉化為實際電腦操作表現。
- 開源釋出框架程式碼、資料集與微調模型，促進後續電腦使用代理研究。

### 適合對象
從事電腦使用代理、GUI 定位、視覺語言模型與人機互動研究的學者與工程師；特別適合需要大規模真實桌面監督訊號以訓練或評估代理模型，或關注長程桌面任務完成與跨應用程式泛化能力的研究團隊。

## 深度分析

#### 方法論解析

DeskForge 的核心方法論並非單純「錄製」桌面畫面，而是「生成」桌面場景：透過可控制的場景規格（scene specification）在真實 Linux 桌面環境中組合多個真實應用程式（real applications），並在執行互動的同時收集密集的結構化觀察與動作轉移（transitions）。

**1. 可控桌面環境的組成**

DeskForge 的運作流程可拆解為四個階段（見圖 1）：

- **Configure（場景配置）**：使用種子（seed）驅動的場景規格，控制應用程式選擇與初始狀態（application state）、內容設定檔（content profile）、視窗佈局（window layout）與視窗堆疊（window stack）、視覺預設（visual preset）以及解析度（resolution）。這些變因可以系統性地改變，讓模型接觸到多樣化的桌面條件。
- **Environment（環境執行）**：真實應用程式在隔離會話（isolated sessions）中執行，避免互相干擾。環境支援 `reset(seed)` 與 `step(click)` 兩種基本操作，分別用於根據種子重置場景與執行點擊動作。
- **Structured Screen State（結構化螢幕狀態）**：系統同時截取螢幕截圖（screenshot）、擷取 AT-SPI 樹（AT-SPI tree）以及視窗幾何資訊（window geometry），並將三者融合為密集的 ScreenTag 標註。
- **DeskForge-1M 資料集**：最終產出 120 萬張帶有密集元素標註（dense element annotations）的桌面觀察，包含 1.597 億個元素實例（element instances）與 91.7 萬筆點擊轉移（click transitions）。

**2. 密集標註流程（annotation pipeline）**

取得密集監督訊號（dense supervision）的關鍵在於融合三種互補但各自不完整的資訊來源：

- **AT-SPI 樹**：提供元素的類型與階層（types + hierarchy）、互動屬性（interaction properties）以及所有權（ownership）。但此結構常因應用程式而異（application-dependent）且不完整（incomplete interface structure）。
- **視窗幾何資訊**：提供視窗位置、大小與視窗堆疊順序，用於判斷元素間的遮擋關係。
- **螢幕截圖**：提供實際渲染外觀（rendered appearance），用於像素驗證文字（pixel-verified text）與幾何資訊精煉（geometry refinement）。

標註流程會進行遮擋解析（occlusion resolution），判斷元素是否被其他視窗遮蓋；同時保留介面階層、應用程式與視窗所有權、堆疊關係，將個別元素置於整個組合桌面的結構中。每一個執行的點擊都會連結到後續觀察，記錄動作結果（action outcome），形成 `(S_t, a_t, S_{t+1})` 的狀態轉移（transition）。

**3. 從密集標註到定位訓練樣本**

DeskForge-1M 不僅是靜態的截圖語料庫，還可從記錄的互動中衍生自然語言指令，將「前一刻截圖 + 指令」配對到單一目標元素，構成 GUI 定位（GUI grounding）的訓練範例。研究團隊從中抽取 20 萬筆定位範例，對四個視覺語言模型（vision-language models, VLMs）進行微調（fine-tuning）。

**4. 全螢幕元素偵測器**

除了 VLM 微調，DeskForge-1M 的密集元素標註也被用來訓練一個全螢幕元素偵測器：以 RT-DETRv4-L 為基礎，在 DeskForge-1M 上微調後，在 GroundCUA 的三種定位指標上優於 OmniParser v2 與 ScreenParse YOLO11-L。

---

#### 實驗數據解讀

**1. GUI 定位表現**

研究團隊在四個 VLMs 上進行微調，並在保留的桌面條件（held-out desktop conditions）與五個外部 GUI 定位基準（external GUI grounding benchmarks）上測試。主要發現包括：

- **所有模型在保留條件與外部基準上均有提升**，平均準確率提升 1.5 至 24.9 個百分點。
- **Qwen3.5-4B** 在 DeskForge-1M 的保留測試上，平均準確率從 76.26% 提升至 87.54%。
- 提升幅度隨著畫面中應用程式數量增加、目標被部分遮擋（occluded）而變大，這正是桌面定位最困難的條件，顯示 DeskForge-1M 成功補強了模型在複雜桌面場景中的泛化能力。

在外部基準上，Qwen3.5-4B 的具體進步包括：

- **ScreenSpot-Pro**：提升 11.51 個百分點。
- **OSWorld-G**：提升 10.11 個百分點。

這些數字顯示，DeskForge-1M 的訓練訊號不僅對「同分布」的桌面條件有效，也能遷移到其他資料集與應用程式場景。

**2. 長程任務完成表現**

為了驗證單步定位能力提升是否能轉化為多步任務表現，研究團隊固定規劃器（planner）為 Qwen3.6-27B，只更換動作模型（action model）的權重。結果顯示：

- 在 **WebArena-Infinity** 的 119 個任務中，Qwen3.5-4B 解決的任務數從 31 個提升至 50 個。
- 在 **OpenApps** 的 100 個任務中，解決的任務數從 3 個提升至 15 個。

這兩個基準分別代表網頁與桌面應用的長程任務完成（long-horizon task completion）。雖然絕對數字仍有進步空間，但相對提升幅度顯著（WebArena-Infinity 提升約 61%，OpenApps 提升 5 倍），說明密集的定位監督訊號確實能改善下游代理程式的動作執行可靠性。

**3. 元素偵測器表現**

RT-DETRv4-L 在 DeskForge-1M 上微調後，於 GroundCUA 的三種定位指標上超越 OmniParser v2 與 ScreenParse YOLO11-L。這顯示 DeskForge-1M 的密集邊界框與元素標註也能獨立支援傳統電腦視覺模型，而不僅限於 VLM 微調。

**4. 資料集規模與多樣性**

DeskForge-1M 包含：

- 120 萬張帶標註桌面觀察
- 1.597 億個元素實例
- 91.7 萬筆點擊轉移
- 橫跨 19 個應用程式
- 7 種視覺預設
- 7 種解析度

場景層級的資料切分（scene-level splits）確保相關截圖不會同時出現在訓練與測試集，並測試模型對新場景、保留應用程式、保留視覺預設與保留解析度的泛化能力。

#### 與現有研究的比較

**1. 相較於靜態截圖語料庫**

Rico 與 WebUI 等早期工作提供行動與網頁介面的截圖與結構資訊，但屬於靜態語料庫（static corpora），無法系統性地改變場景。DeskForge 的關鍵差異在於「可控生成」：透過種子化場景配置，可以反覆產生不同應用程式狀態、內容、佈局與外觀的桌面畫面。

**2. 相較於合成介面與自動化收集**

Jedi、MolmoPoint-GUISyn、UGround 等工作透過介面分解、合成或網頁結構生成訓練資料。這些方法雖然規模大，但常使用合成或簡化介面，與真實桌面有差距。DeskForge 直接使用真實應用程式（real applications），並在真實 Linux 桌面環境中執行，因此更接近實際代理程式需要面對的視覺與互動複雜度。

**3. 相較於單一應用程式探索**

GUIrilla 透過原生輔助功能 API（accessibility APIs）探索執行中的應用程式並建立狀態—動作圖，但一次只處理單一應用程式。DeskForge 則在同個桌面場景中組合多個應用程式，並處理視窗重疊（overlapping windows）、跨應用程式干擾項（cross-application distractors）與多視窗佈局（multi-window layout）等真實挑戰。

**4. 相較於可執行環境**

WebArena、OSWorld、OpenApps、CUA-Gym、WebArena-Infinity 等可執行環境（executable environments）主要設計用於任務評估，而非產生密集的螢幕標註。DeskForge 則將環境控制與密集標註結合，讓每一個執行的動作都伴隨完整的 before/after 觀察與元素級標註。

**5. 相較於 WinDeskGround**

WinDeskGround 透過組合已擷取的視窗影像來變化佈局、遮擋與干擾，用於定位評估。但其組合是靜態的，無法執行進一步動作。DeskForge 在執行中的桌面內進行組合與互動，因此能同時收集動作結果與連續轉移。

**6. 相較於 GroundCUA**

GroundCUA 提供密集且經人工驗證的專家桌面工作流程標註，品質高但規模與多樣性受限。DeskForge-1M 則透過自動化、可控的環境產生大規模資料，並在 GroundCUA 相關評估中展現競爭力。

**7. 限制**

儘管 DeskForge 有顯著貢獻，仍有幾項限制：

- **動作類型單一**：目前主要記錄點擊轉移（click transitions），尚未涵蓋鍵盤輸入、拖曳、滾動等更豐富的互動形式。
- **作業系統侷限**：目前僅支援 Linux 桌面環境，對 Windows 或 macOS 的跨平台泛化仍需驗證。
- **應用程式覆蓋**：雖然包含 19 個應用程式，但相較於真實世界數以萬計的桌面與網頁應用程式，覆蓋範圍仍有限。
- **任務層級監督較弱**：DeskForge-1M 主要提供元素級與動作級監督，長程任務目標與高層規劃的訓練訊號仍需仰賴外部規劃器與任務基準。
- **外觀與解析度**：雖然有 7 種視覺預設與 7 種解析度，但真實使用者可能使用更多樣化的主題、字型縮放與高 DPI 設定。

#### 可重現性評估

根據論文所述，DeskForge 的框架程式碼、資料集與微調後模型權重均將透過專案頁面釋出：

> https://saidgurbuz.github.io/deskforge/

這對可重現性（reproducibility）是正面訊號：

- **開源框架**：DeskForge 環境的程式碼公開後，其他研究者可以重現場景生成、應用程式組合與標註流程。
- **公開資料集**：DeskForge-1M 的 120 萬張截圖與 1.597 億個元素標註若完整釋出，將成為 GUI 定位與電腦使用代理（computer-use agents）研究的重要公共資源。
- **模型權重**：微調後的 Qwen3.5-4B 等模型權重公開，有助於直接比較後續研究，並作為下游任務的基礎動作模型（action model）。

然而，可重現性也取決於以下因素：

- **執行環境相依性**：真實應用程式的版本、Linux 發行版、桌面環境與 AT-SPI 實作都可能影響結果重現。
- **硬體與授權**：大規模截圖與應用程式執行需要可觀的運算資源，部分商業應用程式可能涉及授權問題。
- **資料釋出細節**：是否釋出原始截圖、AT-SPI 樹、視窗幾何資訊、ScreenTag 標註與點擊轉移的完整格式，將影響資料集可用性。

整體而言，DeskForge 在開放性上優於許多僅釋出模型權重或僅描述方法的工作，但實際可重現程度仍需等待程式碼與資料正式上線後評估。

#### 未來研究方向

**1. 擴展動作空間**

目前 DeskForge 主要記錄點擊（click）轉移。未來可加入鍵盤輸入、文字輸入、拖曳（drag）、滾動（scroll）、右鍵選單、快捷鍵與組合鍵等動作，讓資料集更貼近真實電腦使用代理所需的多樣化動作空間。

**2. 跨作業系統與跨平台**

將 DeskForge 從 Linux 桌面環境擴展到 Windows 與 macOS，或開發跨平台的輔助功能 API 橋接層，可提升模型在不同作業系統上的泛化能力，並擴大應用程式覆蓋範圍。

**3. 結合網頁與桌面應用程式

現代電腦使用代理常需在瀏覽器、桌面應用程式與系統控制之間切換。未來可將網頁應用程式（如透過瀏覽器執行的 WebArena 任務）與桌面應用程式整合到同一場景中，產生跨網頁—桌面的密集標註。

**4. 長程任務與規劃監督**

DeskForge-1M 目前提供豐富的單步定位與動作轉移監督，但缺乏明確的任務目標與多步規劃標註。未來可結合任務規格與驗證器（verifiers），自動產生帶有目標描述、子目標分解與成功條件的長程軌跡，以同時訓練規劃器（planner）與動作模型（action model）。

**5. 主動式與適應性資料收集**

目前的場景變化主要依賴種子化配置。未來可引入主動學習（active learning）或好奇心驅動探索（curiosity-driven exploration），讓環境自動發現模型容易失敗的條件（如高度遮擋、視覺相似控制項、罕見解析度），並針對這些困難案例生成更多訓練資料。

**6. 時間與動態推理

桌面介面常隨時間變化（如載入動畫、通知彈出、背景程式更新）。未來可加入影片序列或連續幀監督，訓練模型理解動態變化、等待時機與處理非同步事件。

**7. 更強大的元素偵測與解析

雖然 RT-DETRv4-L 已展現潛力，但未來可探索以 VLM 為基礎的開放詞彙（open-vocabulary）元素偵測、遮擋復原（occlusion recovery）與語意分組，進一步提升在極端重疊視窗與視覺相似控制項（visually similar controls）上的定位能力。

**8. 人機協作與真實使用者軌跡

將 DeskForge 與真實使用者示範結合，可產生更貼近實際工作流程的監督訊號。例如，透過錄製專家操作並在 DeskForge 中重播與重新標註，可同時獲得自然語言意圖、動作序列與密集元素標註。

**9. 隱私、安全與效率

大規模桌面資料收集涉及潛在隱私風險（如截圖中可能包含敏感資訊）。未來研究可發展自動隱私遮蔽、合成內容注入與差分隱私技術。同時，提升環境並行度與降低單一場景生成成本，將有助於擴大資料集規模。

**10. 與大型多模態模型結合

隨著 Qwen、GPT-4V、Gemini 等視覺語言模型持續演進，DeskForge 可作為高品質的微調與評估平台，協助研究哪些架構、預訓練目標與推理策略最能受益於密集桌面監督訊號。

## 論文問答

【Background & Motivation】

**Q1：電腦使用代理在桌面環境中面臨的核心挑戰是什麼？**
A：桌面介面本質上是組合式的，同一畫面上可能同時存在多個應用程式視窗、對話框與系統控制項，代理必須在這種密集視覺脈絡中準確定位動作目標。此外，相同應用程式可能呈現不同內容、位於不同視窗佈局，甚至與視覺相似的控制項或跨應用程式干擾項並存，使得目標辨識變得困難。這些因素要求訓練資料必須能夠捕捉完整桌面場景、保留詳細結構資訊，並支援系統化的桌面配置變化。

**Q2：現有的訓練資源為何難以滿足桌面代理的需求？**
A：現有資源大多屬於靜態語料庫，無法主動改變或控制場景內容；許多資料集只標註單一應用程式或單一目標，缺乏多視窗同時出現的複雜情境；而可執行環境通常設計來評估任務完成度，而非提供密集的畫面標註。換句話說，這些資源各自具備部分優點，但沒有一個同時結合「可控場景組合」、「密集每畫面標註」與「動作結果記錄」三項特性。因此，代理在面對遮擋、跨應用干擾與多視窗佈局等困難條件時，往往缺乏足夠的監督訊號來學習穩健定位。

**Q3：密集監督訊號對提升 GUI 定位能力為何重要？**
A：密集監督不僅標註目標位置，還保留元素的類型、階層、所屬視窗、可見性與互動屬性，讓模型能夠理解整個介面結構。當目標被部分遮擋或與其他視覺相似元素並存時，這些結構化資訊有助於模型區分相關控制項與干擾項。此外，將執行動作與後續狀態變化連結起來，可形成狀態轉移監督，進一步協助代理學習動作在真實桌面上的實際成效。

【Method & Innovation】

**Q4：DeskForge 的核心方法與主要設計理念是什麼？**
A：DeskForge 的關鍵理念是「生成桌面場景，而非僅僅錄製桌面」：它透過場景規格與種子化配置，在真實 Linux 桌面環境中啟動並組合多個真實應用程式。系統會控制應用程式選擇與初始狀態、內容、視窗佈局與堆疊順序、外觀主題以及螢幕解析度，並在執行過程中同時擷取截圖、輔助功能樹與視窗幾何資訊。每一個執行的點擊動作都會連結到後續觀察，記錄狀態轉移，從而產生可重現且結構化的密集觀測資料。

**Q5：DeskForge 的標註管線有哪些關鍵創新？**
A：標註管線整合了原本不完整且隨應用程式而異的輔助功能 API、實際渲染截圖以及視窗幾何資訊，以產生密集元素標註。它會進行幾何資訊精煉、遮擋解析、像素驗證文字，並保留介面階層、應用程式與視窗所有權、堆疊關係等結構資訊。最終將所有資訊融合為 ScreenTag 表示法，使每個元素都能被放置在整個組合式桌面的結構脈絡中，而不只是孤立的位置框。

**Q6：為什麼 DeskForge 選擇使用真實應用程式，而非合成介面？**
A：真實應用程式能提供真實的渲染外觀、複雜的控制項互動、跨應用程式干擾以及可信的動作結果，這些都是合成介面難以完全模擬的。透過在隔離工作階段中執行真實應用程式，DeskForge 既能保持場景的真實性，又能透過種子化配置系統化地變化內容與佈局。這種設計讓產生的監督訊號同時具備真實世界複雜度與實驗可控性，對訓練穩健的電腦使用代理至關重要。

【Experiments & Results】

**Q7：DeskForge-1M 資料集的規模與組成為何？**
A：DeskForge-1M 包含 120 萬張經過密集標註的桌面觀測截圖、1.597 億個元素實例，以及 91.7 萬筆記錄的點擊轉移。資料涵蓋 19 個應用程式、7 種視覺預設主題與 7 種解析度，並採用場景層級切分，以確保相關擷取畫面保留在同一分割中。此外，研究者從記錄的互動中衍生自然語言指令，形成「截圖—指令—單一目標」的 grounding 訓練樣本，便於訓練視覺語言模型。

**Q8：在 GUI 定位實驗中，微調後的模型取得了哪些關鍵成果？**
A：研究團隊從 DeskForge-1M 中抽取 20 萬筆 grounding 範例，微調了四個視覺語言模型，結果所有模型在保留的桌面條件與五個外部 GUI 定位基準上都有提升。以 Qwen3.5-4B 為例，其在 ScreenSpot-Pro 上提升 11.51 個百分點，在 OSWorld-G 上提升 10.11 個百分點，保留條件下的平均準確率也從 76.26% 提升至 87.54%。值得注意的是，畫面中同時出現的應用程式越多、目標越容易被遮擋時，增益越明顯，顯示密集監督有效解決了桌面定位的困難情境。

**Q9：DeskForge 的監督訊號對長程任務完成有何下游效益？**
A：在固定使用 Qwen3.6-27B 規劃器的前提下，僅更換動作模型權重，四個微調後的模型在 WebArena-Infinity 與 OpenApps 長程任務基準上都解決了更多任務。以 Qwen 為例，在 119 個 WebArena-Infinity 任務中，完成數從 31 個提升至 50 個；在 100 個 OpenApps 任務中，完成數則從 3 個大幅提升至 15 個。這些結果顯示，單一目標的 grounding 監督能夠轉化為多步驟任務完成能力的改善，串連了低階定位與高階電腦操作。

【Applications & Impact】

**Q10：DeskForge 可應用於哪些實務場景？**
A：DeskForge 可用於訓練桌面自動化代理、機器人流程自動化系統、無障礙輔助助理，以及需要跨應用程式執行工作流程的智慧體。由於它能產生帶有密集標註的真實桌面截圖，開發者可以針對特定應用程式、解析度或外觀主題生成客製化訓練資料。這對於需要在雜亂畫面中可靠定位控制項的產品來說，能顯著降低資料蒐集與標註成本。

**Q11：將 DeskForge 落地為產品或平台時，需要考慮哪些因素？**
A：首先必須確保應用程式在隔離工作階段中執行，以兼顧安全性、可重現性與避免互相干擾；其次，種子化配置讓回歸測試與資料擴增變得可行，但標註管線必須能處理各種應用程式差異極大的輔助功能 API 與渲染行為。此外，擴展到更多作業系統、應用程式授權與內容隱私問題，以及維持大規模資料產生的運算成本，都是在產品化過程中需要審慎評估的面向。

**Q12：DeskForge 對電腦使用代理領域可能帶來什麼影響？**
A：DeskForge 證明了透過可控方式組合真實桌面環境，可以成為大規模且可擴展的監督訊號來源，並同時改善 GUI 定位與長程任務完成。這項工作架起了低階視覺定位與高階規劃執行之間的橋樑，可能催生新的基準測試與訓練典範。由於框架程式碼、資料集與微調模型皆已公開，後續研究可以在此基礎上進行復現、擴展與比較，加速整個領域的發展。

【Limitations & Future】

**Q13：DeskForge 目前有哪些已知的限制？**
A：目前的環境主要建構在 Linux 桌面之上，且僅涵蓋 19 個應用程式，作業系統與應用範圍仍有限。標註品質高度依賴輔助功能 API，而這些 API 在不同應用程式中可能不完整或不一致，導致部分元素資訊遺漏。此外，目前的動作空間以點擊為主，尚未涵蓋鍵盤輸入、拖曳、滾動等更豐富的互動形式，這限制了可學習任務的廣度。

**Q14：在哪些情況下，基於 DeskForge 訓練的模型仍可能失敗？**
A：當目標被嚴重遮擋、出現訓練時未見過的全新應用程式、解析度極低，或畫面中存在多個外觀極為相似的控制項時，模型仍可能定位錯誤。若輔助功能樹本身提供錯誤資訊，或幾何資訊精煉與遮擋解析發生失誤，這些錯誤也會傳遞給下游模型。在長程任務中，即使動作模型的 grounding 能力提升，規劃器若產生錯誤的高階步驟，整體任務仍可能失敗。

**Q15：未來可以朝哪些方向擴展 DeskForge？**
A：未來可將環境擴展到 Windows 與 macOS 等其他作業系統，並納入更豐富的動作空間，例如鍵盤輸入、拖曳、滾動與快捷鍵。也可以加入動態網頁內容、更複雜的多模態指令，以及結合線上探索與強化學習來自動發現困難場景。另一方面，提升標註管線對各種應用程式的魯棒性，並將規劃器與動作模型進行端到端聯合訓練，也是值得深入探索的方向。

## 實務應用指南

### 適用場景

1. **企業級桌面流程自動化（RPA 2.0）**  
   適合需要跨應用程式執行重複性任務的場景，例如從電子郵件讀取訂單、開啟試算表核對庫存、再回網頁系統下單。DeskForge 的密集標註能訓練動作模型在重疊視窗與視覺相似控制項中準確定位，減少傳統 RPA 對絕對座標的依賴。

2. **軟體自動化測試與回歸驗證**  
   可用於產生大量帶有元素標註的桌面截圖，自動驗證 UI 在不同解析度、佈局、外觀主題下的可見性與可互動性，並記錄點擊前後的狀態轉移，協助定位功能回歸。

3. **無障礙輔助與智慧介面導航**  
   將 DeskForge 訓練出的定位模型結合輔助功能樹，可為視障使用者提供更穩定的「語音操作桌面」能力，即使應用程式的無障礙 API 資訊不完整，也能透過視覺語言模型補足目標位置。

4. **長程電腦使用智慧體的動作模型微調**  
   適合已經有規劃器（planner）但需要更強動作執行層的系統，例如客服代理、程式碼編輯助手或資料分析助手，透過 DeskForge-1M 提升在多視窗桌面中的單步定位準確率。

5. **GUI 定位專用訓練資料合成**  
   當外部基準測試（如 ScreenSpot-Pro、OSWorld-G）資料不足或與目標應用領域有落差時，可用 DeskForge 可控地產生符合目標分佈的桌面場景與密集標註，作為資料擴增來源。

### 實作前置條件

**資料**
- 可直接使用 **DeskForge-1M**（120 萬張截圖、1.597 億個元素實例、91.7 萬筆點擊轉移）進行微調。
- 若目標應用不在 19 個預設應用程式內，需準備自有應用程式的場景規格（scene specification）與互動腳本，並重新執行標註流程。

**運算資源**
- **資料產生端**：Linux 桌面虛擬機或容器（建議 KVM/QEMU 或 Docker + VNC），每個隔離會話（isolated session）需 2–4 vCPU、4–8 GB RAM，視同時執行的應用程式數量而定。
- **模型訓練端**：微調視覺語言模型（如 Qwen3.5-4B）建議至少 1 張 24 GB VRAM 的 GPU；更大模型（如 Qwen3.6-27B 規劃器）需多卡或高記憶體設定。RT-DETRv4-L 等全畫面元素偵測器則需額外 GPU 訓練資源。
- **儲存**：DeskForge-1M 原始截圖與密集標註預估需數百 GB 至數 TB 空間，建議使用物件儲存或高速 SSD。

**技能與工具**
- 熟悉 Python、PyTorch / Transformers、Linux 桌面環境與 AT-SPI / 輔助功能 API。
- 具備 Docker/KVM 虛擬化經驗，能夠設定隔離會話與自動化互動。
- 了解視覺語言模型微調流程（LoRA / 全參數微調）、資料格式轉換與評估指標。
- 若要做長程任務驗證，需能整合現有規劃器與環境（WebArena-Infinity、OpenApps 或自訂任務）。

### 實作步驟建議

1. **部署 DeskForge 環境**  
   在 Linux 主機上建立隔離桌面會話，安裝目標應用程式，設定場景規格（應用選擇、內容設定檔、視窗佈局、視覺預設、解析度）。透過 `reset(seed)` 確保場景可重現。

2. **產生並擷取結構化畫面狀態**  
   執行自動化探索腳本，對每個場景進行截圖，同時收集 AT-SPI 樹、視窗幾何資訊與視窗堆疊。這些是後續密集標註的基礎。

3. **執行標註流程**  
   融合截圖、輔助功能樹與視窗幾何資訊，進行幾何資訊精煉、遮擋解析、可見性判斷、像素驗證文字與互動屬性標註，輸出 ScreenTag 或自訂格式的密集元素標註。

4. **記錄動作轉移**  
   透過 `step(click)` 在畫面上執行可互動元素的點擊，記錄 `(S_t, a_t, S_{t+1})` 轉移。這些轉移可用於訓練動作結果預測模型，也可衍生自然語言指令作為定位訓練樣本。

5. **建構定位訓練集**  
   從 DeskForge-1M 或自產資料中抽取 grounding 樣本：每張截圖搭配一條自然語言指令與單一目標元素。建議依場景切分（scene-level splits），避免資料洩漏。

6. **微調視覺語言模型與元素偵測器**  
   使用 grounding 樣本微調 Qwen3.5-4B 等 VLM，並以全畫面元素標註微調 RT-DETRv4-L 等偵測器。論文使用約 20 萬筆 grounding 範例即可觀察到顯著提升。

7. **評估泛化能力**  
   在保留的桌面條件（新場景、未見應用、保留外觀預設、保留解析度）與外部基準（ScreenSpot-Pro、OSWorld-G、GroundCUA 等）上測試定位準確率。

8. **整合規劃器進行長程任務驗證**  
   固定一個強規劃器（如 Qwen3.6-27B），僅替換動作模型權重，在 WebArena-Infinity、OpenApps 或自訂任務上測量任務完成率，確認單步定位進步能轉化為長程表現。

9. **部署與持續迭代**  
   將微調後的動作模型包裝成 API，與企業現有系統對接。持續收集線上失敗案例，回灌至 DeskForge 產生新的訓練場景，形成資料閉環。

### 潛在風險與注意事項

- **輔助功能 API 資訊不完整**：AT-SPI 樹可能遺漏元素或幾何資訊不準。建議以截圖像素驗證文字與邊界框，並在標註流程中進行幾何資訊精煉與遮擋解析，不能完全依賴單一資訊來源。
- **遮擋與可見性判斷錯誤**：多視窗重疊時，模型可能誤判被遮擋元素為可點擊。標註時應明確標記 `occluded` 與可見性，訓練時可加入負樣本避免誤點。
- **跨平台分佈偏移**：DeskForge 目前基於 Linux 桌面，若目標環境為 Windows 或 macOS，截圖風格、視窗裝飾與控制項外觀會有差異。建議將 DeskForge 視為預訓練或資料擴增來源，並在目標作業系統上進行少量領域適應。
- **應用程式授權與法律風險**：自動化操作真實應用程式時，需確認軟體授權條款允許此類使用，並避免對第三方服務進行未授權自動化。
- **動作安全性**：在生產環境執行點擊、輸入等動作前，應先於沙箱中驗證，並設立人機協同機制（human-in-the-loop）或動作白名單，防止誤刪檔案或誤下單。
- **運算與儲存成本**：大規模產生 120 萬張截圖與密集標註需要大量運算與儲存。建議先以小型場景驗證效果，再逐步擴充。

### 與其他技術的整合建議

- **與現有 RPA 平台整合**：將 DeskForge 微調後的 VLM 作為「視覺定位模組」，取代傳統 RPA 的絕對座標或 XPath 選擇器；RPA 引擎負責流程編排，VLM 負責在動態桌面中找出正確控制項。
- **與大型語言模型規劃器整合**：固定 LLM planner（如 Qwen3.6-27B、GPT-4V），讓 planner 輸出高層步驟與自然語言指令，再由 DeskForge 訓練的動作模型將指令轉換為具體點擊或輸入座標。
- **與 OCR 與圖示偵測器整合**：DeskForge 的全畫面元素偵測器（RT-DETRv4-L）可與 OCR、icon detection 模組串接，先產生候選元素，再由 VLM 根據指令選擇最適目標，降低單一模型的錯誤率。
- **與 CI/CD 整合**：將 DeskForge 環境納入自動化測試管線，每次軟體更新後自動產生新場景、執行回歸測試，並比對元素可見性與互動屬性變化。
- **與可觀測性工具整合**：記錄每次動作的截圖、輔助功能樹、預測座標與執行結果，建立追蹤資料庫，方便後續錯誤分析與模型再訓練。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從「GUI 定位」與「電腦使用代理」的基本概念開始，理解為何重疊視窗與視覺相似控制項會讓代理難以定位。接著把 DeskForge 想像成一座「可控制的虛擬桌面工廠」：它能自動產生大量帶有詳細標註的截圖，幫助模型學會看螢幕、找按鈕。實作時可先使用作者釋出的 DeskForge-1M 資料集與微調模型，不必急著自己架設環境。

**AI 工程師**  
重點關注標註流程如何融合 AT-SPI 樹、截圖與視窗幾何資訊，以及場景層級切分（scene-level splits）如何避免資料洩漏。實作時建議先以 20 萬筆 grounding 樣本微調 Qwen3.5-4B，觀察在 ScreenSpot-Pro 與 OSWorld-G 上的提升；若資源允許，再嘗試全畫面元素偵測器與長程任務驗證。注意微調時的負樣本設計與遮擋元素處理，這是桌面 grounding 的關鍵難點。

**研究人員**  
本論文的核心貢獻在於提出「可控桌面組合」作為大規模密集監督的來源。建議深入分析 DeskForge 的變因設計（應用狀態、內容、視窗佈局、外觀、解析度）與資料分佈，思考如何擴展到 Windows/macOS、多模態動作（鍵盤、拖曳、滾動）以及更複雜的跨應用長程任務。此外，動作結果轉移 `(S_t, a_t, S_{t+1})` 可作為世界模型（world model）或強化學習研究的寶貴資源。

**產品經理**  
請把 DeskForge 視為一個「降低電腦使用代理落地門檻」的資料與訓練基礎設施。它能幫助團隊在受控環境中快速累積失敗案例、驗證模型在特定桌面條件下的表現，並縮短從原型到企業部署的距離。評估時應同時關注單步定位準確率與長程任務完成率，並預留預算給虛擬桌面運算、儲存與合規審查。
