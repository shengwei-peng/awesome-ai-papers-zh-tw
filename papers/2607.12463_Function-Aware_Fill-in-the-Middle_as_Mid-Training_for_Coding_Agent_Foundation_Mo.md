# 以函式感知的中間填補作為程式設計代理基礎模型的中階訓練

**原文標題：** Function-Aware Fill-in-the-Middle as Mid-Training for Coding Agent Foundation Models  
**作者：** Yubo Wang、Jiarong Liang、Yuxuan Zhang 等 8 位作者  
**發布日期：** 2026-07-14  
**HF 連結：** [https://huggingface.co/papers/2607.12463](https://huggingface.co/papers/2607.12463)

## ⚡ TL;DR

現有程式碼模型僅由左至右預訓練，難以銜接代理互動中動作與外部觀察的雙向條件結構。
提出函式感知的中間填補中階訓練，以程式相依圖與複雜度—可推論性準則選取遮蔽函式，並嵌入思維鏈推理。
中階訓練使SWE-Bench提升2.8–5.4分，並減緩後訓練對非代理程式與工具使用能力的侵蝕。

## 摘要翻譯

程式設計代理（coding agents）必須將外部工具回傳結果（external tool returns）整合到持續進行的推理（reasoning）中——這種能力在標準的由左至右預訓練（left-to-right pretraining）中，僅會以前向方式呈現。我們觀察到，程式設計代理的動作—觀察—延續迴圈（action-observation-continuation loop）在結構上與函式呼叫點（function call site）同構：呼叫者（caller）綁定引數（arguments），被呼叫者（callee）回傳在其他地方計算的值，而下游程式碼（downstream code）則使用該值。這種條件化結構（conditioning structure）在一般程式碼中以網際網路規模廣泛存在。我們透過函式感知的中間填補（Function-Aware Fill-in-the-Middle, FIM）中階訓練（mid-training）來利用此結構：此自監督目標函數（self-supervised objective）會遮蔽透過程式相依圖（program dependency graph）分析與複雜度—可推論性雙重準則（complexity-inferability double criterion）所選出的函式。

我們在取自 968 個 GitHub 儲存庫（GitHub repositories）、共 26 億詞元的去污染語料庫（decontaminated corpus）上，對 Qwen2.5-Coder-Instruct（7B/14B）與 Qwen3-8B 進行中階訓練，再套用現有的代理式後訓練流程（agentic post-training pipelines）。中階訓練使 SWE-Bench-Verified 在 7B/14B 上提升 +2.8/+3.0，在 Qwen3-8B 上提升 +3.2；在相同模型上，SWE-Bench-Lite 的增益分別為 +3.7/+4.0/+5.4。此提升在兩種後訓練流程（R2E-Gym、SWE-Smith）以及非 Qwen2.5 基礎模型（non-Qwen2.5 base，搭配 SWE-Lego 的 Qwen3-8B）上均成立。

除了領域內的增益外，中階訓練也緩解了代理式後訓練原本會對非代理程式設計（non-agent coding，例如 LiveCodeBench）與非程式設計工具使用基準測試（non-coding tool-use benchmarks，如 tau-bench、BFCL）造成的能力退化（capability erosion）：儘管中階訓練語料庫僅包含 Python 程式碼，函式呼叫歸納偏置（function-call inductive bias）仍能在後訓練後保留下來，並帶來穩定的增益。

### 核心貢獻（3～5點）
- 提出程式設計代理的動作—觀察—延續迴圈與函式呼叫點之間的結構同構關係，將代理整合外部工具回傳結果的能力對應到程式碼中既有的條件化結構。
- 設計函式感知的中間填補（FIM）中階訓練目標，透過程式相依圖分析與複雜度—可推論性雙重準則選取遮蔽函式，以自監督方式學習函式層級的條件化結構。
- 在 26 億詞元的去污染 Python 語料庫上對多個基礎模型進行中階訓練，顯著提升 SWE-Bench-Verified 與 SWE-Bench-Lite 的表現，且效果跨後訓練流程與基礎模型均穩健。
- 發現中階訓練能緩解代理式後訓練對非代理程式設計與非程式設計工具使用基準的能力退化，顯示函式呼叫歸納偏置可在後訓練後保留並遷移。

### 適合對象
適合對大型語言模型訓練、程式碼生成、軟體工程代理，以及自監督學習方法有興趣的研究者與工程師。特別是關注如何透過中階訓練銜接預訓練與代理式後訓練、並減緩能力退化的讀者。

## 深度分析

#### 方法論解析

本研究的核心論點是：程式設計代理（coding agents）在每一步所經歷的「動作—觀察—延續迴圈」（action-observation-continuation loop），與一般程式碼中的「函式呼叫點」（function call site）在條件化結構（conditioning structure）上具有結構同構性。具體而言，代理的歷史（history）對應呼叫前程式碼（pre-call code）所建立的意圖（intent）與引數（arguments）；代理的動作（action）對應函式呼叫本身；外部工具回傳結果（external tool returns）對應被呼叫函式（callee）的回傳值（return value）；而代理在觀察後的接續生成（continuation）則對應下游程式碼（downstream code）對回傳值的消費。基於此對應關係，作者提出以「函式感知的中間填補」（Function-Aware Fill-in-the-Middle, FIM）作為中階訓練（mid-training）目標，使基礎模型（base model）在進入代理式後訓練（agentic post-training）之前，先建立對函式層級相依關係（function-level dependencies）的雙向推理能力。

相較於現有程式碼大型語言模型（code LLM）常採用的「隨機跨度中間填補」（random-span FIM），本研究指出三項結構性缺陷：其一，隨機跨度的邊界（span boundaries）往往是語法上任意的（syntactically arbitrary），經常切斷運算式（expressions）或不完整陳述句（partial statements），難以傳遞函式層級的語義；其二，隨機跨度 FIM 缺乏推理監督（reasoning supervision），模型直接填補中間片段，而沒有產生類似代理「先思考再行動」的中間推理依據（intermediate rationale）；其三，該目標函數（objective）被稀釋在龐大的由左至右預訓練（left-to-right pretraining）過程中，等到後訓練開始時，其結構先驗已經被攤提在大量無關詞元（token）上。為此，作者設計了三項對應改進。

第一，遮蔽目標的選取以函式為單位，並透過「程式相依圖」（program dependency graph）分析進行篩選。具體流程是：先從抽象語法樹（Abstract Syntax Tree, AST）解析出呼叫邊（call edges）與同類別方法間的兄弟邊（sibling edges），將函式視為圖中的節點；接著應用一個「複雜度—可推論性雙重準則」（complexity-inferability double criterion）來挑選最適合作為 FIM 中間跨度（FIM middle spans）的目標。複雜度（complexity）由程式碼行數（LoC）、圈複雜度（Cyclomatic Complexity, CC）與呼叫深度（depth）等指標組成；可推論性（inferability）則由五種上下文訊號（caller、callee、signature、docstring、class context 等）衡量。兩者透過調和平均形成 FIM 分數，僅當分數超過門檻 τ 時才會被選為遮蔽目標。這個準則的一個重要特性是「基礎模型無關」（base-model-agnostic）：它不依賴特定模型的困惑度（perplexity）或生成能力，而是純粹從程式結構與靜態分析出發，因此對不同模型族（如 Qwen2.5-Coder 與 Qwen3）都具有可遷移性。

第二，作者將「思維鏈推理依據」（chain-of-thought rationales）嵌入 FIM 中間跨度內部。這意味著模型在填補被遮蔽函式時，不僅要還原程式碼本身，還要產生與最終程式碼一致的推理過程。這種設計直接對應代理行為中「先推理再行動」的範式：模型學會在給定前後文（context）與後綴（suffix）的條件下，推論被遮蔽函式的行為，而不是單純記憶程式碼片段。這也強化了「函式呼叫歸納偏置」（function-call inductive bias）在表徵（representations）層次的扎根。

第三，整個目標函數被放在一個「專屬中階訓練階段」（dedicated mid-training stage）執行，而非混入預訓練（pretraining）。這個階段緊接在基礎模型完成大規模預訓練之後、代理式後訓練之前，使訊號在時間上集中於最需要該結構先驗的階段。資料來源為 968 個經過「去污染」（decontaminated）處理的 GitHub 儲存庫（GitHub repositories），總計約 2.6B 詞元，產出約 400K 個 FIM 樣本，其中包含單一函式、函式對與函式三元組等多種遮蔽粒度。去污染措施包含兩層：一是以儲存庫名稱與已知分支比對，移除與 SWE-Bench 來源重疊的專案；二是將每個儲存庫限制在 SWE-Bench-Verified 與 SWE-Bench-Lite 最早基準提交時間之前的提交，以避免測試時資料洩漏（test-time leakage）。

綜合來看，本研究的方法論並非單純提出一個新的自監督目標函數（self-supervised objective），而是重新定位了預訓練、中階訓練與後訓練之間的分工：預訓練負責廣泛的語言與程式知識；中階訓練負責將「函式呼叫」這種網際網路規模程式碼（internet-scale code）中普遍存在的結構，轉化為代理相關歸納偏置（agent-relevant inductive biases）；後訓練則在具體的代理軌跡資料上進行行為對齊。這種分層設計避免了後訓練必須同時學習「結構先驗」與「任務策略」的雙重負擔。

#### 實驗數據解讀

本研究的實驗設計圍繞三個「穩健性軸線」（robustness axes）展開：模型規模、後訓練管線（post-training pipelines）與基礎模型族。首先在 Qwen2.5-Coder-Instruct 系列上，7B 與 14B 模型經過中階訓練後，於 SWE-Bench-Verified 分別提升 +2.8 與 +3.0 分。這個結果有兩層意義：一是函式感知 FIM 所注入的結構先驗並未被更大的預訓練模型「吸收」而失效，顯示在實際部署規模（7B–14B）內仍有明確增益；二是增益在不同規模上相當一致，暗示該先驗具有某種規模可擴展性（scalability）的特質，而非僅對小模型有效。

其次，作者在同一 7B 基礎模型上比較了兩條不同的代理式後訓練流程：R2E-Gym 與 SWE-Smith。兩者結合中階訓練後均有提升，其中 SWE-Smith 配對在 SWE-Bench-Verified 上達到 +5.3 分的增幅。這說明中階訓練所建立的先驗能夠與不同風格的合成代理軌跡資料（synthetic agent-trajectory data）相容，並且對較強的後訓練管線能產生更大的邊際效益。換句話說，中階訓練並非只對某一特定資料分布過擬合（overfit），而是提供了一個可被多種後訓練策略利用的共享表徵基礎。

第三，作者將方法遷移到非 Qwen2.5 基礎模型——Qwen3-8B，並搭配 SWE-Lego 後訓練管線，於 SWE-Bench-Verified 獲得 +3.2 分提升。由於這個比較同時改變了基礎模型與後訓練管線，因此不宜被解讀為跨模型族的絕對保證，但它確實提供了重要證據：函式呼叫歸納偏置並非 Qwen2.5-Coder 與 R2E-Gym/SWE-Smith 組合的專屬產物，而是可以轉移到不同模型架構與訓練流程。

在跨領域（cross-domain）影響方面，實驗結果呈現出一個值得深入討論的現象：單獨進行代理式後訓練會對非目標能力造成顯著退化（capability erosion）。以 14B 模型為例，代理式後訓練單獨進行時，LiveCodeBench、BFCL（Berkeley Function-Calling Leaderboard）與 tau-bench 等基準測試出現雙位數的下降。這反映了後訓練資料過度聚焦於「問題解決任務」（issue-resolution tasks）時，模型會遺忘或壓抑其他程式設計與工具使用能力。然而，當在中階訓練之後再進行同樣的後訓練，這些非代理能力得到顯著恢復：LiveCodeBench +11.1、BFCL +2.4、tau-bench +3.9。

這個「恢復」現象是本研究最具理論意義的發現之一。由於中階訓練語料僅包含 Python 程式碼（Python code），且完全沒有工具使用資料（tool-use data），它在 tau-bench 與 BFCL 等非程式設計工具使用基準測試（non-coding tool-use benchmarks）上的增益，無法用資料重疊或任務相似性解釋。作者將此解讀為「函式呼叫／工具呼叫同構性」（function-call/tool-call isomorphism）的直接證據：模型在程式碼中學到的「給定上下文與下游使用，推論外部計算回傳值（externally-computed return）」的能力，被遷移到「給定歷史與任務目標，推論工具回傳結果」的場景。換言之，中階訓練所強化的並非特定領域知識，而是一種更抽象的「條件化於外部回傳的延續生成」能力。

不過，也需要謹慎解讀這些數字。首先，所有評估都是在「完整流程」後進行（僅後訓練，或中階訓練加後訓練），因為單獨的 FIM 檢查點會損害指令遵循（instruction-following）能力，無法與指令調校基線（instruction-tuned baselines）直接比較。這意味著我們無法從實驗中分離出「中階訓練本身」與「中階訓練和後訓練的交互作用」各自的貢獻。其次，跨領域恢復的絕對數值雖然顯著，但並未完全抵消後訓練造成的全部退化，顯示中階訓練是「緩解」而非「根除」能力侵蝕。最後，所有實驗均以 Qwen 系列為主，雖然包含 Qwen3-8B，但仍屬於同一生態系，對於 Llama、DeepSeek-Coder 等其他模型族的泛化性仍需更多驗證。

#### 與現有研究的比較

本研究在幾個層面上與現有文獻形成對話。首先是與「隨機跨度中間填補」（random-span FIM）的比較。隨機跨度 FIM 已被證明能提升程式碼模型的雙向理解能力，並被融入多個主流 code LLM 的預訓練中。然而，本研究指出其邊界選擇與代理任務的條件化結構並不對齊：隨機遮蔽經常切斷語法單位，無法穩定地捕捉「呼叫者—被呼叫者—下游使用」的完整語義單元。相較之下，函式感知 FIM 以程式相依圖為基礎，將遮蔽目標鎖定在函式層級，並透過複雜度—可推論性雙重準則確保每個樣本都具備足夠的學習價值。這可以視為對 FIM 目標函數的一種「語義化」與「任務對齊化」改造。

其次是與代理資料合成管線（如 SWE-Gym、R2E-Gym、SWE-Smith）的關係。這些管線的核心貢獻在於大規模合成代理軌跡資料，並透過強化學習或監督式微調讓模型學會問題解決策略。本研究並未試圖取代這些後訓練管線，而是指出它們所依賴的基礎模型在進入後訓練前，往往缺少一個關鍵的結構先驗。這相當於在「資料工程」導向的代理訓練之外，補上了一個「表徵工程」導向的中階訓練階段。從這個角度看，本研究與現有後訓練管線是互補關係：後訓練提供任務特定的行為示範，中階訓練則提供可遷移的雙向推理偏置。

第三是與「能力退化」（capability erosion）相關研究的關聯。近年來，越來越多研究發現針對特定任務進行後訓練會導致模型在通用程式設計或推理基準上退步。本研究的獨特之處在於，它提出了一個「預防性」而非「治療性」的解決方案：透過在中階訓練階段強化與代理任務同構但更廣泛的程式結構能力，使模型在後續專精化過程中保留更多通用能力。這與常見的「在後訓練中加入多樣化資料以維持通用能力」策略不同，後者通常是在後訓練階段透過資料混合（data mixing）來抑制遺忘，而本研究則是在更早階段改變模型的表徵幾何。

本研究的主要限制在於其方法論的適用範圍。首先，資料語料僅限於 Python，雖然作者證明了其結構先驗可遷移到非 Python 的工具使用任務，但對於其他程式語言（如 JavaScript、C++、Rust）的函式呼叫結構是否同樣有效，仍需驗證。其次，遮蔽目標的選擇依賴靜態程式分析，對於高度動態的程式碼（如大量使用反射、動態匯入、裝飾器或元程式設計的程式庫）可能無法準確建立程式相依圖，從而降低樣本品質。第三，複雜度—可推論性分數雖然基礎模型無關，但其超參數（如門檻 τ、各項指標權重）仍需要針對不同語料規模進行調校，缺乏一個完全自動化的最佳化流程。最後，本研究主要聚焦於「函式」層級的遮蔽，對於更細粒度（如類別、模組、API 邊界）或更粗粒度（如跨檔案、跨儲存庫的相依關係）的結構單元尚未探討。

#### 可重現性評估

可重現性（reproducibility）是本研究的一大亮點。作者明確承諾開放釋出以下資源：968 個經去污染處理的儲存庫所構成的語料庫（約 400K FIM 樣本、2.6B 詞元）、函式感知 FIM 目標選取流程（selection pipeline），以及中階訓練檢查點（mid-training checkpoints）。這些資源的釋出對於後續研究具有重要價值，因為它們允許其他研究者直接複製中階訓練階段，並將其與不同的後訓練管線或基礎模型結合，進行更廣泛的消融實驗（ablation studies）。

從方法描述來看，選取流程依賴於靜態程式分析工具（從 AST 建立程式相依圖）與可解釋的評分函數，這些步驟原則上可以在不依賴特定硬體或商業 API 的情況下重現。去污染策略也相對透明：透過儲存庫名稱比對與提交時間截斷來避免與 SWE-Bench 重疊。然而，有幾個細節可能影響重現的精確度：首先是「手動品質過濾」（manual quality filtering）的具體標準在正文中僅簡要提及，若未公開詳細準則，其他研究者可能難以完全複製相同的儲存庫集合；其次是複雜度—可推論性分數中的權重與門檻 τ 雖然在附錄中列出，但這些超參數對最終樣本分布的影響需要進一步敏感度分析；最後，中階訓練的訓練超參數（學習率、訓練步數、批次大小、FIM 格式比例等）在提供的片段中未完整揭露，需依賴論文附錄或釋出程式碼才能完整重現。

另一個可重現性考量是計算成本。中階訓練在 2.6B 詞元上進行，對於 7B–14B 模型而言，雖然遠小於預訓練，但仍需要相當規模的 GPU 資源。作者釋出檢查點的舉措降低了重現門檻，因為研究者可以直接從中階訓練後的模型開始進行自己的後訓練實驗，而無需從頭執行整個中階訓練。這對於資源較少的學術團隊尤其重要。

在評估可重現性時，也應注意 SWE-Bench 本身的高變異性。該基準測試的結果容易受到執行環境、依賴版本、測試框架與評分腳本的影響。作者若能在釋出程式碼時一併提供完整的評估環境設定（如 Docker 映像檔、相依套件清單），將進一步提升結果的可比較性。此外，由於本研究涉及多個後訓練管線（R2E-Gym、SWE-Smith、SWE-Lego），這些管線本身的資料與程式碼是否完全公開，也會影響整體流程的可重現性。

#### 未來研究方向

基於本研究的發現，可以從五個方向延伸未來研究。

第一，擴展至多語言與跨語言設定。本研究的中階訓練語料僅包含 Python 程式碼，未來可以檢驗函式感知 FIM 在 JavaScript、TypeScript、Java、C++、Rust 等語言上的效果，並探討跨語言遷移的可能性。特別是，不同語言的函式呼叫語義（如回呼函式、非同步 Promise、泛型、trait 等）可能對應不同型態的代理互動，值得設計更細緻的遮蔽策略。

第二，動態與互動式遮蔽目標選取。目前的選取流程是靜態的，基於整個檔案的程式相依圖。未來可以引入模型自身的困惑度或資訊增益作為輔助訊號，動態調整遮蔽目標，使中階訓練樣本更貼近模型當前的學習狀態。這也與「課程學習」（curriculum learning）的想法相呼應：從簡單的單一函式遮蔽逐步過渡到複雜的跨檔案相依遮蔽。

第三，與推理模型（reasoning models）的整合。本研究已將思維鏈推理依據嵌入 FIM 中間跨度，但未深入探討不同推理格式（如 OpenAI 的 reasoning tokens、DeepSeek-R1 的長思維鏈）對最終效果的影響。未來可以研究中階訓練如何與「測試時擴展」（test-time scaling）或「強化學習驅動的推理」相結合，進一步提升代理在複雜軟體工程問題上的表現。

第四，更廣泛的代理結構同構性。函式呼叫只是眾多程式結構中的一種。未來可以探索其他結構單元是否也能對應到代理行為：例如，類別（class）與模組（module）邊界可能對應多代理系統中的角色分工；異常處理（exception handling）可能對應代理的錯誤恢復機制；型別註解（type annotations）與合約（contracts）可能對應代理的規劃與驗證步驟。將這些結構納入中階訓練目標，可能進一步豐富代理的歸納偏置。

第五，理論理解與表徵分析。本研究提供了強有力的實證證據，顯示函式感知 FIM 能夠轉移到代理任務，但其背後的表徵機制仍不清楚。未來可以透過探針（probing）、因果中介分析（causal mediation analysis）或表徵相似性分析（representation similarity analysis）來檢驗：中階訓練是否確實在模型內部建立了「函式呼叫 ≡ 工具呼叫」的共享表徵？這些表徵分佈在哪些層級與注意力頭（attention heads）中？理解這些問題將有助於設計更精準、更高效的結構先驗注入方法。

最後，從實務應用角度，未來可以探索如何將函式感知 FIM 中階訓練整合到現有的程式碼模型訓練流程中，作為一個標準化的「預後訓練」（pre-post-training）步驟。若能證明其在多種基礎模型與後訓練管線上都能穩定提升，並且計算成本可控，則有望成為建構程式設計代理基礎模型（coding agent foundation models）的標準配方之一。

## 論文問答

**Q1：這篇論文指出目前訓練程式設計代理的什麼關鍵缺口？**

A：現有的程式設計代理通常直接從大規模的由左至右預訓練基礎模型，進入以合成代理軌跡資料為主的代理式後訓練流程，中間缺乏針對代理互動結構的銜接階段。這個訓練階段缺口意味著基礎模型在面對「歷史—動作—外部觀察—延續」的條件化結構時，並未獲得充分的歸納偏置。論文因此提出一個專屬的中階訓練階段，在引入代理專屬資料之前，先讓模型學習與代理行為相關的結構化先驗。

**Q2：為什麼傳統的隨機跨度中間填補無法有效支援代理式條件化？**

A：隨機跨度中間填補有三個主要缺陷：首先，遮蔽邊界通常是語法上任意的，經常切斷運算式或不完整陳述句，難以傳達函式層級相依關係；其次，它缺乏推理監督，模型直接填補片段，無需產生類似代理「先思考再行動」的中間推理依據；最後，這項目標在數兆詞元的預訓練中被稀釋，等到後訓練開始時，其結構先驗已經被大量無關語料攤提。相較之下，函式感知的中間填補以完整函式為遮蔽單位、嵌入思維鏈推理依據，並在中階訓練階段集中訊號。

**Q3：為什麼函式呼叫點可被視為代理動作—觀察—延續迴圈的網際網路規模類比？**

A：函式呼叫點可以分解為呼叫前程式碼、函式呼叫、外部計算回傳值，以及使用回傳值的下游程式碼，這與代理的歷史、動作、觀察、延續四個部分在結構上同構。由於網際網路規模程式碼中存在數量龐大的函式呼叫，這種結構提供了免費且可擴展的自監督訓練訊號。當模型學會從呼叫者上下文與下游使用方式雙向推論被呼叫者的行為時，它同時也獲得了在給定工具回傳結果後繼續生成代理軌跡所需的核心能力。

**Q4：函式感知的中間填補中階訓練的核心方法是什麼？**

A：該方法在預訓練與代理式後訓練之間插入一個自監督階段，透過程式相依圖分析與複雜度—可推論性雙重準則選擇要遮蔽的函式，並要求模型根據前後文填補中間片段。這些中間片段不僅包含被遮蔽函式的程式碼，還嵌入了思維鏈推理依據，使模型在還原程式碼的同時學習結構化推理。訓練語料來自 968 個經過去污染處理的 GitHub 儲存庫，共約 2.6B 詞元，涵蓋單一函式、函式對與函式三元組等多種遮蔽目標。

**Q5：遮蔽目標是如何被挑選出來的？**

A：論文首先將原始碼解析成抽象語法樹，再建構程式相依圖，其中包含函式間的呼叫邊以及同類別方法間的兄弟邊。接著對每個候選函式計算兩個分數：複雜度分數考量行數、循環複雜度與巢狀深度，可推論性分數則綜合呼叫者、被呼叫者、兄弟函式、函式簽名與文件字串等上下文訊號。只有當綜合分數超過門檻時，該函式或相連的 2–3 個函式群組才會被選為中間填補目標，以確保目標既不過於簡單，也不至於無法從上下文推論。

**Q6：思維鏈推理依據在這個方法中扮演什麼角色？**

A：思維鏈推理依據被嵌入到 FIM 中間跨度內部，因此模型在填補時必須先生成與最終程式碼一致的逐步推理過程，再輸出實際程式碼。這種設計模擬了代理「先思考再行動」的行為模式，提供了隨機跨度中間填補所缺乏的推理監督。透過這種方式，模型學到的表徵更容易從程式碼重建任務遷移到代理軌跡延續任務。

**Q7：論文使用了哪些模型、後訓練流程與評測基準？**

A：實驗主要基於 Qwen2.5-Coder-Instruct 的 7B 與 14B 版本，並在 Qwen3-8B 上進行跨系列驗證；後訓練流程則涵蓋 R2E-Gym、SWE-Smith 與 SWE-Lego。評測基準分為三大類：代理任務使用 SWE-Bench-Verified 與 SWE-Bench-Lite，非代理程式設計使用 LiveCodeBench，非程式設計工具使用則使用 BFCL 與 tau-bench。這樣的組合能同時檢驗中階訓練在目標代理能力與跨領域泛化上的效果。

**Q8：論文的主要量化結果是什麼？**

A：在 SWE-Bench-Verified 上，中階訓練讓 Qwen2.5-Coder-Instruct 7B 與 14B 分別提升 2.8 與 3.0 分，Qwen3-8B 提升 3.2 分；在 SWE-Bench-Lite 上則分別提升 3.7、4.0 與 5.4 分。當 7B 模型搭配 SWE-Smith 後訓練時，SWE-Bench-Verified 的增益更高達 5.3 分。更令人意外的是，中階訓練還能緩解代理式後訓練造成的能力退化，例如在 14B 模型上讓 LiveCodeBench 回升 11.1 分、BFCL 回升 2.4 分、tau-bench 回升 3.9 分。

**Q9：哪些實驗設計支持了方法的穩健性與泛化性？**

A：論文從三個軸心驗證穩健性：模型規模涵蓋 7B 與 14B，顯示增益不會被更大的預訓練模型吸收；後訓練流程同時測試 R2E-Gym 與 SWE-Smith，證明中階訓練能與不同管線相容；基礎模型則額外使用 Qwen3-8B 搭配 SWE-Lego，顯示函式呼叫歸納偏置不限於單一模型家族。此外，由於中階訓練語料僅含 Python 程式碼，卻能改善非程式設計工具使用基準，這成為函式呼叫與工具呼叫結構同構的直接證據。

**Q10：這項研究在哪些實際應用場景中最有價值？**

A：對於需要整合測試執行器、程式碼搜尋、語言伺服器或版本控制等外部工具的程式設計代理，中階訓練能強化模型根據工具回傳結果進行下一步規劃的能力。在整合開發環境中，這也有助於提升函式層級的自動完成與程式碼重構品質。更廣泛地說，任何以程式碼大型語言模型為基礎、再透過代理式後訓練強化的產品，都可以將此階段視為標準化的銜接訓練。

**Q11：在產品化與部署時需要考慮哪些因素？**

A：首先必須建立高品質且去污染的程式碼語料庫，並維護抽象語法樹解析與程式相依圖建構的基礎設施，這會增加資料管線的複雜度。其次，中階訓練雖然額外消耗運算資源，但它能減少後訓練對非目標能力的侵蝕，並提升最終代理效能，因此長期來看具有成本效益。最後，由於複雜度—可推論性準則是基礎模型無關的，產品團隊在更換基礎模型時仍需重新驗證門檻與目標選擇策略。

**Q12：這項工作對整個研究領域可能帶來什麼影響？**

A：它重新框架了程式設計代理能力的來源：代理所需的結構化先驗不必完全仰賴昂貴的合成代理軌跡資料，而可以從網際網路規模的普通程式碼中自監督學習。這也為程式碼基礎模型建立了一個明確的中階訓練範式，填補了預訓練與後訓練之間的理論與實務空白。此外，論文開放釋出去污染語料庫、選擇流程與中階訓練檢查點，將有助於後續研究在此基礎上進行復現與擴展。

**Q13：論文承認了哪些限制？**

A：中階訓練語料僅包含 Python 程式碼，因此無法直接證明在多語言程式碼上的效果；多函式遮蔽目標也只佔整體樣本的一小部分，其影響仍有待更細緻分析。Qwen3-8B 的實驗同時更換了基礎模型與後訓練流程，因此雖能證明偏置不限於單一組合，卻無法精確分離兩者的貢獻。此外，單獨的中間填補檢查點會損害指令遵循能力，所以所有評比都必須在完整管線後進行，這也限制了對中階訓練本身直接效應的觀察。

**Q14：在什麼情況下這個方法可能效果有限或失效？**

A：如果代理任務的核心挑戰超出函式呼叫結構，例如需要長期規劃、自然語言協商或多輪策略推理，那麼單靠函式呼叫歸納偏置可能不足以帶來顯著增益。對於規模過小、語法不規則或相依關係極度稀疏的程式碼庫，程式相依圖分析可能選出低品質的遮蔽目標，進而削弱訓練訊號。此外，如果後訓練資料與中階訓練所學的結構嚴重錯位，那麼中階訓練帶來的先驗也可能在後訓練過程中被覆蓋。

**Q15：未來可以朝哪些方向延伸這項研究？**

A：未來可以將函式感知的中間填補擴展到 Python 以外的多種程式語言，並探索如何納入多模態工具回傳結果，例如終端機輸出、圖像或結構化資料。另一個方向是將工具呼叫語法更明確地嵌入中間填補目標，使模型在自監督階段就直接學習工具呼叫格式。也可以研究中階訓練與後訓練的聯合最佳化，或根據不同基礎模型的特性動態調整複雜度—可推論性門檻。最後，這種「動作—觀察—延續」的結構同構思路或許也能應用於網頁代理、機器人或其他互動式代理領域。

## 實務應用指南

### 適用場景

1. **企業內部程式設計代理（Coding Agent）**  
   用於在私有程式碼庫中修復議題、新增功能或重構，代理需要反覆呼叫測試框架、Linter、Git、檢索工具等，並根據外部工具回傳結果繼續推理。函式感知的中間填補能讓模型在後訓練前就先熟悉「動作—觀察—延續」的條件化結構。

2. **工具使用型對話助手（Tool-Use Assistant）**  
   客服、業務或資料分析代理在呼叫 API、資料庫或搜尋引擎後，必須根據回傳值決定下一步動作或回覆。雖然論文語料僅含 Python 程式碼，但學到的函式呼叫歸納偏置可遷移到非程式碼工具使用情境。

3. **開源專案維護機器人**  
   自動處理 GitHub Issues、產生修補程式或審查 PR 的機器人，可透過中階訓練強化函式層級相依推理，並減少代理式後訓練對通用程式能力的侵蝕。

4. **程式輔助與教育平台**  
   在學生或開發者寫到一半時，根據前後文與函式呼叫結構補全程式碼，同時提供思維鏈（Chain-of-Thought）解釋，幫助理解「為何這樣呼叫、回傳值如何被下游使用」。

5. **多步資料分析代理**  
   代理呼叫 pandas、SQL、計算工具或視覺化函式後，依據回傳結果繼續生成後續分析程式碼，適用於財務、生醫、營運等需要反覆工具互動的場景。

### 實作步驟建議

1. **定義目標任務與評估基準**  
   先選定要解決的代理任務（如 issue 修復、API 工具使用），並建立 before/after 評估組合：SWE-Bench-Verified／Lite 測代理能力，LiveCodeBench、BFCL、tau-bench 監控非代理能力退化。

2. **收集與去污染語料**  
   從 GitHub 挑選高品質儲存庫，依星數、主題與人工品質篩選；移除與 SWE-Bench 等評測來源重疊的儲存庫，並將所有程式碼限制在評測最早 base-commit 時間點之前的 commit，避免測試時資料洩漏。

3. **建構程式相依圖與函式選擇管線**  
   使用 AST 解析呼叫邊（call edges）與同類別方法間的兄弟邊（sibling edges），對每個函式計算：
   - **複雜度分數 Ĥ**：程式行數、循環複雜度、巢狀深度等；
   - **可推論性分數 Î**：呼叫者上下文、被呼叫者簽章、文件字串、類別與頂層資訊等；
   - 綜合分數 FIM = Ĥ·Î／(Ĥ + Î)，選取超過門檻 τ 的單一函式或 2–3 個相連函式群組作為遮蔽目標。

4. **產生 FIM 樣本並嵌入思維鏈**  
   對選定目標建立 prefix／middle／suffix 結構；在 middle span 中嵌入 Chain-of-Thought 推理依據，讓模型先說明「根據呼叫者意圖與下游使用，我應該如何實作」，再產出實際程式碼。

5. **執行函式感知中階訓練**  
   以 Qwen2.5-Coder-Instruct、Qwen3 等基礎模型為起點，使用自監督 FIM 目標訓練約 2.6B 詞元。注意控制學習率與訓練長度，避免過度遺忘指令遵循能力。

6. **接上代理式後訓練**  
   中階訓練後的模型作為更強起點，接續使用 R2E-Gym、SWE-Smith、SWE-Lego 等合成代理軌跡資料進行 SFT 或 RL，使其學會在真實環境中採取動作。

7. **全面評估與迭代**  
   比較「僅後訓練」與「中階訓練＋後訓練」的結果。若發現非代理能力仍退化，可調整中階語料比例、CoT 長度或後訓練資料混合策略。

8. **部署與持續監控**  
   將模型整合至 IDE 外掛、Issue Bot 或內部開發平台，持續收集真實軌跡，定期更新去污染語料並重新執行中階訓練，形成資料閉環。

### 潛在風險與注意事項

- **資料污染風險**  
  若訓練語料包含評測題目或測試程式，會嚴重膨脹分數。必須以儲存庫名稱、fork 關係與 commit 時間進行嚴格去污染。

- **語言限制**  
  論文語料僅為 Python。若要支援 Java、TypeScript、Go 等語言，需重新建立 AST／PDG 解析器與對應語料，不可直接套用現有管線。

- **遮蔽目標選擇不當**  
  若複雜度—可推論性門檻過鬆，會選到過簡單或無法從上下文推論的函式，降低訊號品質；過嚴則樣本數不足。建議從論文提供的 τ 與特徵權重出發，再依內部評估微調。

- **指令遵循能力退化**  
  單純 FIM 中階訓練可能損害模型的指令遵循與對話能力，因此**必須**接上後訓練才能部署，不能直接將 FIM checkpoint 上線。

- **運算與時間成本**  
  中階訓練是額外完整階段，對資源有限團隊負擔較大。可先以 7B 模型與 10–20% 語料進行概念驗證，確認增益後再擴大規模。

- **評估成本與偏差**  
  SWE-Bench 執行昂貴且耗時，建議建立輕量內部評估作為快速迭代依據；同時注意不同後訓練管線的增益可能差異甚大。

- **授權合規**  
  使用公開儲存庫時需確認授權條款，特別是若計畫公開釋出語料或模型權重，應避免使用 GPL 等強 copyleft 授權的程式碼。

### 與其他技術的整合建議

- **與 RLHF／DPO 後訓練銜接**  
  中階訓練提供結構化先驗後，可再接偏好學習進一步對齊代理行為，例如讓模型學會在「過早呼叫工具」與「充分推理後再動作」之間做出更符合人類偏好的選擇。

- **結合檢索增強生成（RAG）**  
  代理在採取動作前可檢索相關程式碼片段或文件；函式感知 FIM 培養的雙向推理能力，有助於模型理解檢索結果與下游程式碼如何銜接。

- **與 IDE／LSP 整合**  
  利用語言伺服器協定（LSP）取得真實函式簽章、呼叫圖與型別資訊，可提升 target selection 的準確度，並在部署時提供更可靠的程式碼補全。

- **搭配合成軌跡資料管線**  
  中階訓練負責「結構先驗」，SWE-Gym、R2E-Gym、SWE-Smith 負責「任務軌跡」，兩者互補。可在合成軌跡中刻意設計包含函式呼叫與工具回傳的轉折點，強化遷移效果。

- **擴展至非程式碼工具使用**  
  將函式呼叫的歸納偏置視為一般「動作—觀察—延續」結構，補充 API 描述、資料庫綱要或工具文件作為上下文，可嘗試遷移到 tau-bench、BFCL 等非程式碼工具使用情境。

- **與 MLOps／實驗追蹤整合**  
  記錄每筆 FIM 樣本的 Ĥ、Î、來源儲存庫、commit hash 與授權資訊，便於審計、再現與後續去污染更新。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先掌握核心類比：「函式呼叫」就是程式碼世界裡的「代理動作—觀察—延續」。把本文理解為「在正式教代理做事之前，先讓模型大量練習根據前後文猜出函式內容」的方法即可；程式相依圖、複雜度—可推論性分數等技術細節可先略讀，待熟悉基礎後再回頭深究。

- **AI 工程師**  
  請重點關注資料管線（去污染、PDG 分析、CoT 嵌入）與訓練編排（中階訓練的學習率、詞元預算、與後訓練的銜接）。論文中 LiveCodeBench、BFCL、tau-bench 的能力恢復現象是評估重點，應在內部複現並納入上線標準。

- **研究人員**  
  核心貢獻在於將函式呼叫點結構與代理條件化結構建立同構關係，並以自監督 FIM 作為結構先驗。可延伸探討跨語言遷移、跨工具遷移，以及複雜度—可推論性雙重準則的理論基礎與更廣泛的任務適用性。

- **產品經理**  
  本技術可提升程式設計代理在真實議題解決的通過率，同時減少後訓練對通用程式能力的侵蝕。評估時應同時看 SWE-Bench 提升與 LiveCodeBench／BFCL 是否穩定，並為中階訓練預留額外的資料清洗、運算與授權審查成本。
