## ⚡ TL;DR

現有受限解碼過早限制推理，自然生成又缺乏結構，兩者難以兼顧。
本研究提出混合解碼框架，讓模型於單次呼叫中先自由推理，再以觸發詞元啟動結構化生成。
實驗顯示，該方法在分類與推理任務上較最先進技術最高提升27%準確率，且幾乎消除過早觸發問題。

## 摘要翻譯

自然生成（Natural generation）使大型語言模型（Large Language Models, LLMs）能夠產生富含推理內容的自由形式回應（free-form responses），然而缺乏結構使得輸出難以驗證。相對地，受限解碼（constrained decoding）確保了標準化格式，但可能因在生成過程中過早施加約束而無意間限制推理能力。我們提出了一種混合方法（hybrid approach），即 In-Writing，在單次呼叫（single call）中結合自由形式推理（free-form reasoning）與結構化生成（structured generation）。模型首先進行無約束推理（unconstrained reasoning），並且僅在產生觸發詞元（trigger token）後才套用結構化解碼（structured decoding），明確地將推理與格式化解耦（decoupling reasoning from formatting）。我們證明，所提出的觸發詞元策略幾乎可根除過早觸發（premature triggering），即受限解碼會中斷進行中的推理之失效模式（failure mode）。於多個涵蓋分類（classification）與推理任務（reasoning tasks）的資料集上所進行的評估顯示，我們的方法在準確率（accuracy）上相較於自然生成取得高達 27% 的提升，並優於最先進技術（state-of-the-art）。我們的程式碼可於以下網址取得：https://github.com/Nokia-Bell-Labs/InWriting。

### 核心貢獻（3～5點）
- 提出 In-Writing 混合方法，於單次呼叫中結合自由形式推理與結構化生成，兼顧推理豐富度與輸出結構化。
- 透過觸發詞元機制，明確地將推理與格式化解耦，使模型得以先進行無約束推理，再進入結構化輸出階段。
- 證實所提出的觸發詞元策略幾乎可根除過早觸發之失效模式，解決受限解碼中斷進行中推理的問題。
- 在涵蓋分類與推理任務的多樣資料集上驗證，相較自然生成最高可達 27% 的準確率提升，並優於最先進技術。

### 適合對象
研究大型語言模型解碼策略、結構化生成與受限解碼之研究人員與演算法工程師；需於問答、資料擷取、分類等下游任務中同時確保輸出格式正確性與推理品質之應用開發者；以及對提升推論階段效率與模型準確率有興趣之學術與產業界讀者。

## 深度分析

#### 方法論解析

本研究的核心命題在於平衡**自由形式推理（free-form reasoning）**與**結構化生成（structured generation）**之間的張力。**自然生成（natural generation）**雖能讓**大型語言模型（Large Language Models, LLMs）**產出流暢且具豐富推論過程的**自由形式回應（free-form responses）**，但缺乏**預先定義的輸出結構（predefined output structures）**，導致下游難以自動驗證；反之，傳統**硬受限解碼（hard constrained decoding）**透過**有限自動機（Finite Automata）**或正規表示式（regex）在每一步進行 logit masking，雖能保證**標準化格式（standardized formats）**，卻因過早將整個生成過程限制在**語法空間（grammar space）**內，而壓縮了模型的推理能力。

**In-Writing** 框架提出**先思考後約束（Thinking Before Constraining）**的範式，核心為**推理與格式化解耦（decoupling reasoning from formatting）**。其方法論可拆解為以下機制：

1. **單次呼叫（single call）內的兩階段生成**：模型首先進入**無約束推理（unconstrained reasoning）**階段，以標準自迴歸方式生成完整的思維鏈（Chain-of-Thought, CoT）。此階段不施加任何結構限制，確保推理路徑的自然分布不受**受限解碼（constrained decoding）**干預。
2. **觸發詞元（trigger token）啟動結構化階段**：當模型生成特定觸發詞元（例如 `<eos>`、`{` 或其他預設符號）後，解碼器才切換至**結構化解碼（structured decoding）**模式，後續詞元必須符合目標 regex 或文法規則，並由**有限自動機（Finite Automata）**引導狀態轉移。
3. **過早觸發（premature triggering）的緩解策略**：論文針對觸發詞元可能在推理完成前意外出現的**失效模式（failure mode）**，設計對應策略以「幾乎根除」（virtually eradicate）此問題，確保結構限制不會中斷進行中的推理鏈。

形式化而言，傳統方法將答案 A 在問題 q 與格式 F 下的條件機率聯合建模為：
$$P(A \mid q, F) = \sum_R P(A \mid R, q, F)P(R \mid q, F)$$
其中推理路徑 R 被強制約束於 F 之內，導致無效推理路徑被剔除。In-Writing 透過觸發機制，實質上讓 $P(R \mid q)$ 回歸無約束分布，僅在觸發後對答案段落施加 $F$ 的限制。這使得模型能在完整的語意空間中進行推理，再將最終結果「寫入」結構化模板。

#### 實驗數據解讀

實驗涵蓋多樣化的**下游任務（downstream tasks）**，包含**分類（classification）**與**推理任務（reasoning tasks）**，評估對象橫跨 Qwen、Llama、Gemma、DeepSeek 與 SmolLM 等**模型家族（model families）**（參數量 1.5B 至 14B）。評估指標包含**準確率（accuracy）**、可解析性（parsability）與**詞元效率（token efficiency）**。

關鍵數據與現象解讀如下：

- **準確率（Accuracy）顯著提升**：In-Writing 相較於純**自然生成（natural generation）**最高可達 27% 的準確率增益。這顯示單純依賴模型自發產生結構化輸出並不可靠，而顯式分離推理與格式化能顯著提升最終答案的正確性。此結果也暗示，強迫模型在**語法空間（grammar space）**內進行推理會損害其解題能力。
- **可解析性與校正效應**：如圖 1 的夥伴交換推理題所示，**自然生成（natural generation）**與 In-Writing 的前段推理過程完全一致，但 In-Writing 在觸發後能將自然語言結論「Helga」自動映射至選項 A，並輸出標準 JSON（`{"final_answer":"A"}`）。這顯示**受限解碼（constrained decoding）**在此框架中不僅是格式強制工具，更扮演了**解析器（parser）**與**校正器（corrector）**的角色，能修正語法並標準化答案。
- **詞元開銷（Token overhead）極小化**：框架強調以最小額外成本達成目標。相較於兩階段**管線（pipeline）**（如 NL-to-Format）需進行兩次生成與上下文傳遞，In-Writing 在**單次呼叫（single call）**內完成，顯著降低**詞元開銷（token overhead）**與延遲。
- **跨模型穩健性**：實驗涵蓋 1.5B 至 14B 參數量的多個**模型家族（model families）**，顯示此**統一解碼框架（Unified Decoding Framework）**具備良好的泛用性，並非僅對特定模型有效。

#### 與現有研究的比較

In-Writing 在相關研究中佔據獨特定位，可從三個維度與既有方法區隔：

1. **相較於自然生成（Natural Generation）**：純自然輸出雖具彈性，但缺乏**標準化格式（standardized formats）**保證，下游難以自動驗證。In-Writing 在不犧牲推理豐富度的前提下，補足了結構保證與可解析性。
2. **相較於硬受限解碼（Hard Constrained Decoding）**：傳統方法在每一解碼步驟均透過**有限自動機（Finite Automata）**進行遮罩，強制整個生成過程符合 regex。Tam et al. 與 Banerjee et al. 等研究已指出此舉會降低模型表現。In-Writing 以實證說明，「強迫模型完全在受限語法空間內推理」遠不如「先自由推理、後限制格式」有效。
3. **相較於混合基線方法**：
   - **NL-to-Format**：採用剛性兩階段**管線（pipeline）**，先產生自然語言再轉換格式，計算與**詞元開銷（token overhead）**較高，且錯誤會在階段間傳遞。
   - **CRANE**：將推理與受限區域緊密耦合（tightly couple），限制了自由形式推理的空間。In-Writing 則透過**觸發詞元（trigger token）**實現顯式分離，保留更大的推理靈活性。

**限制與邊界**：In-Writing 的有效性高度依賴**觸發詞元（trigger token）**策略的設計。若觸發詞元選擇不當，或任務特性導致模型在推理中途即生成該詞元，仍可能出現**過早觸發（premature triggering）**。此外，目前框架主要針對正規表示式層級的約束，對於更複雜的上下文無關文法（CFG）或巢狀結構，**有限自動機（Finite Automata）**的表達能力有其理論上限。

#### 可重現性評估

本研究在可重現性方面具備多項正面條件：

- **開源釋出**：原始碼已公開於 https://github.com/Nokia-Bell-Labs/InWriting，提供框架實作、推論腳本與觸發策略的具體細節。
- **模型可取得性**：實驗採用的 Qwen、Llama、Gemma、DeepSeek、SmolLM 均為公開權重之**模型家族（model families）**，研究者可復現 1.5B–14B 參數量範圍內的實驗。
- **基準測試（Benchmarks）**：雖摘要未詳列所有資料集名稱，但明確指出涵蓋**分類（classification）**與**推理任務（reasoning tasks）**等標準**下游任務（downstream tasks）**，屬常見評估範疇。
- **技術基礎成熟**：**受限解碼（constrained decoding）**所需的**有限自動機（Finite Automata）**與 regex-guided decoding 已有成熟開源實作（如 Willard and Louf, 2023; Koo et al., 2024），降低基礎建構門檻。

潛在挑戰包括：**觸發詞元（trigger token）**策略的動態偵測邏輯與超參數（如溫度、top-p）的交互作用，需依賴原始碼的完整文件才能完全復現；此外，不同**模型家族（model families）**對特定觸發符號（如 `{` 或 `<eos>`）的先驗機率分布差異，可能影響跨模型復現時的穩定性。

#### 未來研究方向

基於**先思考後約束（Thinking Before Constraining）**的範式，未來研究可朝以下方向延伸：

1. **動態與語境感知觸發機制**：當前**觸發詞元（trigger token）**多為靜態符號。未來可探索由模型自身判斷推理完成時機的動態觸發，或引入輕量分類器偵測推理終點，進一步降低**過早觸發（premature triggering）**風險。
2. **複雜文法擴展**：將目前的 regex / **有限自動機（Finite Automata）**層級約束，擴展至上下文無關文法（CFG）或樹狀結構約束，以支援更複雜的**基於綱要的資訊擷取（schema-based information extraction）**、巢狀 JSON 或領域特定語言（DSL）輸出。
3. **多輪**工具使用（Tool Use）**與 API 整合**：在需要頻繁呼叫外部工具或 API 的場景中，可將 In-Writing 應用於「推理 → 工具呼叫 → 結構化結果」的循環，使**工具使用（tool use）**過程兼具推理深度與格式嚴謹性。
4. **理論分析**：深入探討為何**語法空間（grammar space）**限制會損害推理能力，以及**推理與格式化解耦（decoupling reasoning from formatting）**在資訊理論或認知模擬層面的意義，為混合解碼策略提供理論保證。
5. **詞元效率（Token Efficiency）**與推論加速**：研究如何壓縮觸發詞元與結構化尾段的**詞元開銷（token overhead）**，或開發與 In-Writing 相容的推論加速技術（如投機解碼、草稿模型），以提升**推論時間（inference time）**效率。
6. **跨模態應用**：將此**統一解碼框架（Unified Decoding Framework）**延伸至多模態大型模型，在視覺推理、**網頁導航（web navigation）**或**程式碼生成（code generation）**等任務中，平衡自由形式分析與結構化輸出（如特定標記語言或程式語法）。

## 論文問答

**Q1：這篇論文旨在解決大型語言模型在解碼過程中的核心問題是什麼？**
A：這篇論文主要解決自然生成與結構化生成之間的根本張力。自然生成雖然能讓模型進行豐富的自由形式推理，但缺乏預先定義的輸出結構保證，使得輸出結果難以驗證與解析。相對地，受限解碼雖能確保標準化格式，卻可能在生成過程中過早施加約束，反而限制了模型的推理能力。

**Q2：現有方法（如硬受限解碼與 NL-to-Format）為何無法充分解決上述問題？**
A：硬受限解碼透過有限自動機在每一步都強制模型處於語法空間內，這會剔除許多語法上不符合但推理上有效的路徑，進而損害任務表現。NL-to-Format 採用僵化的兩階段管線，不僅缺乏嚴格的即時結構強制，還增加了系統複雜度與延遲。至於 CRANE，則將推理與受限區域緊密耦合，仍舊無法讓模型在格式化之前進行完全無約束的思考。

**Q3：為何將推理與格式化進行解耦對大型語言模型如此重要？**
A：解耦能讓模型充分運用其預訓練所得的自然語言推理能力，而不會在思考初期就被語法規則 prematurely 限制。這確保了推理過程可以自由展開，同時最終輸出仍能嚴格符合下游應用所需的結構規範。對於基於綱要的資訊擷取、工具呼叫或任何需要同時保證正確性與可解析性的場景而言，這種分離至關重要。

**Q4：In-Writing 框架的核心機制是什麼？**
A：In-Writing 是一個統一的解碼框架，允許模型在生成的第一階段進行完全無約束的自由形式推理。只有在生成特定觸發詞元（例如 `<eos>` 或 `{`）之後，系統才會啟動結構化解碼機制。這種設計在單次自迴歸呼叫中，明確地將推理階段與格式化階段分離開來。

**Q5：相較於先前的混合式方法，In-Writing 的關鍵創新為何？**
A：與 NL-to-Format 的剛性管線或 CRANE 的緊密耦合不同，In-Writing 透過觸發詞元策略實現推理與格式化的真正解耦。它僅在推理完成後才施加受限解碼，從而幾乎根除了過早觸發這一失效模式。此設計在保留模型自然推理表達能力的同時，以極低的詞元開銷達成了嚴格的格式遵循。

**Q6：論文如何從形式化角度區分硬受限解碼與 In-Writing？**
A：論文將思維鏈推理建模為潛在變數程序，其中答案取決於推理軌跡。硬受限解碼將格式條件 F 同時施加於推理與答案，即 P(R|q,F) 會將所有不符合語法 F 的推理路徑機率歸零並重新正規化。相對地，In-Writing 讓推理從無約束分布 P(R|q) 中抽取，僅在觸發詞元後對最終答案段施加 F，從而完整保留了原始的推理空間。

**Q7：In-Writing 在哪些模型與任務上進行了評估？**
A：該框架在橫跨多個模型家族的設定下進行測試，包括 Qwen、Llama、Gemma、DeepSeek 與 SmolLM，參數規模從 1.5B 到 14B 不等。實驗涵蓋了多樣化的下游任務，同時包含分類與推理基準測試。評估指標採用準確率、可解析性與詞元效率，以全面驗證方法的有效性。

**Q8：論文報告的最關鍵量化結果為何？**
A：In-Writing 在評估資料集上相較於自然生成基線取得了最高達 27% 的準確率提升。該方法也透過成功消除過早觸發的失效模式，表現優於現有的最先進受限解碼方法。此外，實驗結果顯示在此框架下，受限解碼本身能作為比獨立模型更有效的解析器與校正器。

**Q9：關於過早觸發問題，論文提供了哪些證據，In-Writing 又是如何緩解的？**
A：論文將過早觸發界定為結構化解碼在推理尚未完成時就意外啟動，導致思考過程中斷或劣化的關鍵失效模式。透過對觸發詞元策略的深入研究，作者證明其方法能夠幾乎徹底根除此問題。這確保了從自由形式推理到結構化輸出的轉換，只會在模型真正完成推理鏈之後才發生。

**Q10：In-Writing 在哪些實際應用場景中最具效益？**
A：In-Writing 特別適合需要複雜多步驟推理且同時要求輸出嚴格可解析的場景，例如基於綱要的資訊擷取、JSON 格式的工具呼叫，以及結構化問答系統。它使模型能夠產生人類可讀的推理軌跡，同時保證最終答案符合預先定義的正規表示式或 JSON 綱要。這種雙重能力減少了生產系統中對事後解析或獨立格式化管線的需求。

**Q11：在產品層面，In-Writing 相較於兩階段 NL-to-Format 管線有何優勢？**
A：In-Writing 在單次生成呼叫內完成推理與格式化，消除了管理獨立階段所帶來的延遲與架構複雜度。透過將受限解碼整合為內建的解析器與校正器，它降低了對額外輔助模型來提取或驗證最終答案的需求。此外，其極低的詞元開銷使其在資源受限的部署環境中仍具備高度的計算效率。

**Q12：In-Writing 可能如何影響受限解碼領域的未來研究與發展？**
A：該研究證明強迫模型在整個生成過程中都處於受限語法空間內是次優的，從而挑戰了結構必須從第一個詞元就開始強制的既有假設。它確立了「先思考後約束」的新典範，可能啟發各種生成任務中的混合解碼策略。此框架的統一方法也有望促進更靈活的有限自動機實作，使其能在自迴歸生成過程中支援動態啟動。

**Q13：論文對 In-Writing 框架承認了哪些限制？**
A：雖然實證結果強勁，但論文主要聚焦於可由有限自動機表達的正規表示式與文法約束，這可能無法涵蓋所有複雜的輸出結構。觸發詞元策略的有效性也可能因模型家族穩定產生指定觸發詞元的能力而有所差異。此外，目前的評估雖然多樣，但或許仍未能窮盡所有推理與格式化交互方式不同的領域。

**Q14：論文討論了哪些失效模式或邊緣案例，又是如何處理的？**
A：核心討論的失效模式是過早觸發，即模型在推理完成前意外生成觸發詞元，導致約束過早啟動。論文透過專門設計的觸發詞元策略來處理此問題，使這類意外啟動在統計上幾乎可以忽略。然而，若模型的自然推理過程中本身就包含類似觸發詞元的模式，理論上仍存在非預期約束啟動的殘留風險。

**Q15：論文提出了哪些未來研究方向？**
A：作者建議將框架擴展至有限自動機之外更具表達力的約束形式，例如具備動態作用範圍的上下文無關文法。另一個方向是研究自適應觸發機制，使其能從資料中學習最佳切換點，而非依賴預先定義的詞元。最後，將此解耦原則應用於多輪對話與具備代理能力的工作流程，以確保更長互動跨度下的結構化推理，也是極具前景的研究途徑。

## 實務應用指南

### 適用場景

1. **金融合規報告生成**：分析師需要模型先進行自由形式的市場推理與風險評估，最終卻必須輸出符合監管要求的嚴格 JSON 或 XML 格式。In-Writing 可確保複雜推理不被結構化語法過早打斷，同時保證輸出具備 100% 可解析性。

2. **醫療診斷輔助系統**：模型需先針對病歷進行多步驟自由形式推理（如鑑別診斷），最終輸出標準化結構，例如 ICD-10 編碼或特定綱要的醫療決策物件。此場景下，過早觸發可能導致診斷邏輯被截斷，造成臨床風險。

3. **企業級工具呼叫（Tool Use）與 API 編排**：在智慧助理或 Agent 系統中，模型需先推理使用者意圖與多步驟執行策略，再於觸發詞元後輸出嚴格結構化的 API 請求參數。In-Writing 以單次呼叫（Single Call）完成「思考」與「格式化」，避免傳統 NL-to-Format 管線的延遲與錯誤傳播。

4. **法律文件審查與條款萃取**：針對冗長合約進行多輪邏輯比對與推理後，輸出符合預先定義輸出結構（Predefined Output Structures）的萃取結果。受限解碼（Constrained Decoding）在此充當解析器（Parser）與校正器（Corrector），自動修正模型在結尾處的格式偏差。

5. **科學實驗數據分析**：研究人員要求模型執行數學或邏輯推理後，將最終結果填入標準化實驗記錄格式。相較於強迫模型在整個語法空間（Grammar Space）中推理，In-Writing 可顯著提升準確率（Accuracy）並降低詞元開銷（Token Overhead）。

### 實作前置條件

- **資料準備**：需蒐集涵蓋目標領域的問答對，每筆資料應包含完整的自由形式推理過程（Free-form Reasoning）與對應的結構化正確答案，用於設計觸發詞元（Trigger Token）與驗證正規表達式（Regex）或 EBNF 語法。
- **運算資源**：需具備支援 FSM-based 受限解碼的推論環境，例如 vLLM、Outlines 或 lm-format-enforcer。建議配置至少 16GB VRAM 的 GPU 以順暢執行 7B–8B 參數（Parameters）級別的大型語言模型（LLMs）。
- **技術能力**：團隊需熟悉 Python、正規表達式或上下文無關語法定義、有限自動機（Finite Automata）基本概念，並理解目標模型家族（Model Families）如 Llama、Qwen、DeepSeek 的 Tokenizer 行為，以避免觸發詞元被意外切分。

### 實作步驟建議

1. **定義結構化語法**：根據下游任務（Downstream Tasks）需求，將目標輸出格式轉譯為 Regex 或 JSON Schema，並建立對應的有限自動機狀態轉移表。
2. **設計觸發詞元策略**：選擇不易在自然推理文本中出現的觸發詞元（例如特定控制符或結構化起始符 `{`），並透過預備資料集驗證過早觸發（Premature Triggering）機率。論文建議可採用複合觸發條件以虛根除過早觸發失效模式。
3. **整合解碼引擎**：在現有推論框架（如 vLLM）中注入 FSM 遮罩邏輯，確保在觸發詞元生成前，解碼過程完全無約束（Unconstrained Reasoning）；觸發後立即啟動結構化解碼（Structured Decoding）。
4. **設計提示詞模板**：於提示中明確區隔「推理階段」與「格式化階段」，指導模型先進行 Chain-of-Thought 推理，待生成觸發詞元後再輸出標準化格式（Standardized Formats）。
5. **建立評估管線**：除了準確率外，必須同時測量可解析率（Parsability）與詞元效率（Token Efficiency），並與自然生成（Natural Generation）及 CRANE 等基準方法進行對照。
6. **生產環境部署**：啟用即時監控，追蹤觸發詞元位置分佈與結構化輸出合規率，並保留降級機制（如偵測到異常時退回純自然生成搭配後處理解析器）。

### 潛在風險與注意事項

- **過早觸發風險**：若觸發詞元選擇不當（如常見標點或英文單字），可能在推理中途被誤判，導致結構化解碼中斷正在進行的推理。建議採用論文提出的觸發詞元策略，並預留詞元逃逸（Token Escaping）機制作為備案。
- **詞元效率與延遲權衡**：雖然 In-Writing 宣稱具備最小詞元開銷，但 FSM 狀態轉移計算仍會增加每步解碼延遲。在極高吞吐量場景中，需評估批次推論（Batch Inference）下的遮罩計算成本。
- **Tokenizer 相容性**：不同模型家族對相同字元串的詞元切分方式各異，某個模型中為單一詞元的觸發符號，在另一模型中可能被拆為子詞元（Subword），導致觸發機制失效。務必在目標模型上驗證詞元 ID 對應關係。
- **語法複雜度上限**：過於複雜的語法空間會使 FSM 狀態數爆炸，增加記憶體佔用與推論延遲。建議將複雜格式拆解為多個簡單 Regex 階段，或限制結構化輸出的巢狀深度。
- **錯誤傳播與內容正確性**：受限解碼僅能保證「格式正確」，無法修正推理階段的邏輯錯誤。若應用於高風險領域（如醫療或金融），仍需額外建構語意驗證層或人機協作審查機制。

### 與其他技術的整合建議

- **與推論引擎整合**：可直接將 In-Writing 的 FSM 遮罩邏輯嵌入 vLLM、TensorRT-LLM 或 TGI（Text Generation Inference），利用其現有的 Logits Processor 介面，在觸發前後動態切換遮罩狀態，實現單次呼叫（Single Call）端到端生成。
- **與 RAG / Agent 框架整合**：在 LangChain 或 LlamaIndex 中，可將 In-Writing 作為底層輸出解析器，取代傳統後處理正規表達式或獨立校正模型。這能顯著降低管線（Pipeline）延遲，並提升工具呼叫（Tool Use）時的參數填入正確率。
- **與觀測與評估平台整合**：透過追蹤觸發詞元在生成序列中的位置，可視化「推理長度」與「格式化長度」的分佈，協助產品團隊優化提示詞設計與語法複雜度。
- **與模型微調流程整合**：在持續預訓練或指令微調階段，可於訓練資料中明確標註觸發詞元位置，使模型更穩定地學習「先推理後格式」的行為模式，進一步降低推論時的過早觸發機率。

### 給不同背景讀者的閱讀建議

- **初學者**：請直接參考圖 1 的對照範例，建立「先自由思考、後強制格式」的直覺理解即可。無需深究第 2 節有限自動機的數學定義，重點放在理解為何過早約束會傷害模型推理能力。
- **AI 工程師**：建議精讀第 4 節的方法論與演算法 1，掌握觸發詞元策略的實作細節與 FSM 遮罩的整合方式。特別關注論文如何將推理與格式化解耦（Decoupling Reasoning from Formatting），並評估現有開源函式庫（如 Outlines）的移植成本。
- **研究人員**：請深入第 2 節預備知識與第 3 節相關工作，比較 In-Writing 與 CRANE、NL-to-Format 在機率分解（Equation 1–3）上的根本差異。論文對過早觸發失效模式的分析，可作為後續混合解碼研究的理論基礎。
- **產品經理**：請聚焦第 5–6 節的實驗結果與準確率提升數據（最高達 27%）。評估導入此框架時，應權衡推論延遲、維護成本與現有後處理管線的替代效益，特別適合推動「高準確率＋嚴格格式」的企業級應用落地。
