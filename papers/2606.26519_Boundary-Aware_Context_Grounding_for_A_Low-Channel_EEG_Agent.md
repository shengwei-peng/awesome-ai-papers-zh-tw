## ⚡ TL;DR

低通道腦電圖結合語言模型時，易產生缺乏硬體與科學邊界支援的推論，且原始數據外洩風險高。
提出新架構將本地確定性腦電圖引擎與語言層分離，僅以允許清單摘要和版本化情境賦基驅動語言模型。
經重複性、故障隔離與288組邊界感知測試，證實該架構能有效校準代理程式的接受、限定與拒絕行為。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）可使科學軟體更易於使用。然而，通用模型並不會自動知道特定感測器支援哪些測量、目前軟體實作了哪些演算法，或哪些結論可由計算結果所支持。這些區別對於低通道腦電圖（low-channel Electroencephalography, EEG）尤其重要，因為稀疏的空間覆蓋範圍與不穩定的訊號品質，容易產生看似合理但缺乏根據的詮釋。我們提出 NeuraDock Agent，一種開源架構，將確定性本地腦電圖引擎（Deterministic Local EEG Engine）與硬體感知語言層（Hardware-Aware Language Layer）分離。數值引擎解析記錄、進行品質控制、執行經審查的頻譜工作流程（Spectral Workflows），並寫入機器可讀的產出物（Machine-Readable Artifacts）。大型語言模型（LLM）僅接收一份精簡的允許清單摘要（Allowlisted Summary）與一份版本化的情境套件（Versioned Context Pack）。該情境描述了七通道硬體、經審查的工作流程、結果欄位、實作邊界（Implementation Boundaries）、科學限制與參考案例。原始腦電圖（Raw EEG）與高密度逐樣本陣列（Dense Per-Sample Arrays）保留在本地。

我們在三個層級上評估此系統。首先，12 筆記錄在重複十次數值運算中產生相同的結構化結果，且一次完整的 Rest/Task 執行在三次重複中產生相同的結果、報告與圖表雜湊值。其次，請求擷取（Request-Capture）與故障注入（Failure-Injection）實驗確認了受測的資料邊界（Data Boundary），以及在 HTTP 錯誤、格式錯誤輸出（Malformed-Output）與連線故障（Connection Failures）下本地產出物的保存。第三，一項邊界感知基準測試（Boundary-Awareness Benchmark）在四種情境消融（Context Ablations）與兩個大型語言模型（LLMs）下，測試了 36 個一般與對抗性問題（Adversarial Questions），共產生 288 筆輸出。這些結果支持硬體與實作感知的情境賦基（Hardware- and Implementation-Aware Context Grounding），作為校準腦電圖代理接受、有條件地接受或拒絕內容的實用機制；但其並未確立臨床有效性（Clinical Validity），亦未確立經驗證的

## 深度分析

#### 方法論解析

NeuraDock Agent 的核心設計在於嚴格區分數值真實性（numerical truth）與語言行為（language behavior）。系統採用雙層架構：底層為確定性本地腦電圖引擎（deterministic local EEG engine），上層為硬體感知語言層（hardware-aware language layer）。本地引擎以經審查的 Python 工作流程（reviewed Python workflows）為唯一數值來源，負責解析記錄（parse recordings）、執行品質控制（quality control）、運算頻譜特徵（spectral features），並輸出機器可讀產物（machine-readable artifacts）。此設計確保濾波器參數、閾值、統計檢定等關鍵分析要素不會被大型語言模型（Large Language Models, LLMs）隨機更動，從而消除隨機程式碼生成（stochastic code generation）進入數值路徑所帶來的分析變異與責任風險。

上層 LLM 並不接收原始腦電圖（raw EEG）或高密度逐樣本陣列（dense per-sample arrays），而是僅取得緊湊的允許清單摘要（compact allowlisted summary）與版本化情境包（versioned context pack）。此情境賦基（context grounding）機制圍繞四重邊界感知（boundary awareness）展開：
1. **物理邊界（Physical boundary）**：明定七通道乾電極研究平台（通道順序 channel order 為 CP5、CP6、PO3、PO4、O1、Oz、O2，取樣率 250 Hz）的觀測極限，防止模型建議前端導程（frontal montage）才能支援的分析；
2. **實作邊界（Implementation boundary）**：記錄當前軟體版本已實現且經審查的工作流程（reviewed workflows），避免模型宣稱存在未實裝的穩態視覺誘發電位（SSVEP）分類器；
3. **結果邊界（Result boundary）**：界定確定性輸出欄位（deterministic output fields）的實際語義，例如區分「技術上乾淨的記錄」與「受試者專注」；
4. **科學邊界（Scientific boundary）**：規範由觀測到推論的合理範圍，防止將工程品質標誌（quality flag）誤譯為神經學或臨床結論。

以視覺認知負荷工作流程（Visual Cognitive Load workflow）為例，系統將後方 alpha 活動（posterior alpha activity）視為記錄內（within-recording）的相對啟發式（relative heuristic），而非普世或診斷性指標。這種設計對低通道腦電圖（low-channel EEG）尤為關鍵，因為稀疏空間取樣（sparse spatial sampling）極易導致解剖學上看似合理、但物理上缺乏支援的錯誤標記——例如將後方節律（posterior rhythm）誤判為額葉、顳葉或局部皮質效應。透過將原始訊號與高密度陣列保留於本地，系統同時滿足隱私保護與資料邊界（data boundary）的雙重要求。

#### 實驗數據解讀

論文採用三層級驗證策略，從數值確定性、系統韌性到語言層邊界行為進行全面評估，各層級的實驗設計與意涵如下。

**第一層：數值可重複性（numerical repeatability）**  
12 筆記錄在 10 次重複執行下產生完全相同的結構化結果；完整的 Rest/Task 流程在 3 次重複中，其結果、報告與圖表雜湊值（hashes）完全一致。這證明本地引擎具備嚴格的確定性（determinism），任何濾波、閾值或特徵提取的變動都必須透過版本控制的工作流程更新，而非由 LLM 在對話中隱式竄改。對於科學計算而言，雜湊層級的一致性遠比「數值近似相等」更為嚴格，它確保了從訊號處理到視覺化輸出的全路徑可復現。

**第二層：請求攔截（request-capture）與故障注入（failure-injection）**  
研究者在 HTTP 異常、格式錯誤輸出（malformed-output）與連線故障（connection failures）等極端情境下測試系統行為。結果顯示本地產物（local artifacts）得以保存，資料邊界（data boundary）未被穿透。這驗證了架構在面對網路層與模型層失效時的隔離能力：即使語言層完全離線或回傳垃圾訊息，已完成的數值分析與其中間檔案仍維持完整，不會發生「模型幻覺導致本地數值被覆寫」的災難性場景。

**第三層：邊界感知基準測試（boundary-awareness benchmark）**  
研究團隊以 36 個普通與對抗性問題（ordinary and adversarial questions），搭配四種情境消融（context ablations）與兩種 LLM，共產生 288 筆輸出。此基準測試要求模型做出精確的四向決策（four-way decisions），並輔以二元可行／不可行（feasible/infeasible）區分，同時測量不安全接受（unsafe acceptance）與過度保守拒絕（over-conservative rejection）。四種消融條件應對應於逐步剝奪情境包中的硬體、實作、結果與科學脈絡，以量化各類情境賦基（context grounding）對邊界維持的邊際貢獻。值得注意的是，該基準不僅懲罰「幻覺式」的越界宣稱，也懲罰「過度拒絕」——即模型為了安全而將合理請求判定為不可行，這在科學代理（scientific agent）場景中同樣會損害可用性。

#### 與現有研究的比較

**與通用腦電圖軟體的關係**  
相較於 MNE-Python 與 EEGLAB 等成熟腦電圖分析環境，NeuraDock Agent 並非追求廣度，而是建構一個明確受限的窄化工作流程層（narrower workflow layer）。其硬體假設、輸入輸出與科學宣稱均經過嚴格限縮，降低使用者在方法論上的決策負擔，但也意味著它無法直接取代支援多種導程數與研究設計的通用生態系。這種取捨反映了「邊界明確」與「功能泛用」之間的設計權衡。

**與 LLM 情境賦基及工具使用的差異**  
在大型語言模型的應用領域，檢索增強生成（Retrieval-Augmented Generation, RAG）與工具使用（tool-use）系統分別透過外部文件與函式呼叫擴展模型能力。NeuraDock 的差異化在於強調能力邊界識別（capability boundary recognition）：模型不僅要「知道什麼」，更要「知道自己不知道什麼」。此外，多數幻覺（hallucination）研究聚焦於不實內容的生成，而本文特別關注過度拒絕（over-refusal）這一反直覺的失效模式，並將其納入基準測試，這在科學軟體的互動設計中尤為重要——使用者需要精確的「可行／不可行」判斷，而非一概的規避性回覆。

**與臨床決策支援及醫療 AI 的對照**  
與 Med-PaLM 等臨床決策支援系統相比，NeuraDock 將「非自主原則」（non-autonomous role）應用於神經科技堆疊（neurotechnology stack）的更底層。語言層僅能解釋經審查的結果，無權重新定義分析方法，更不能將工程輸出轉譯為臨床決策。這呼應了醫療 AI 研究中「廣泛知識正確性並不足夠」的發現，但在認知神經科技的應用情境中提前設下防火牆，避免未經驗證的認知負荷指數（cognitive-load index）被誤用為診斷依據。

**與 TinyML 及邊緣 AI 的落差**  
在硬體協同設計（hardware-software co-design）方面，系統雖採用 ADS1299 前端與 nRF52840 微控制器實現可攜式串流，但評估的數值工作流程目前仍於工作站執行，尚未達到 TinyML 意義上的端側推論（on-device inference）。這是當前架構與完整邊緣 AI 願景之間的主要差距，也意味著「本地」在資料層面是成立的，但在運算層面尚未完全去中心化。

#### 可重現性評估

NeuraDock Agent 採用開源架構（open-source architecture），並明確標示版本範圍（Version Scope）：實驗數據來自 2026 年 6 月 12 日的軟體快照（software snapshot），公開釋出版本 2026.6.24（原始碼提交 hash：61aada4）保留了相同的核心邊界機制。這種版本化敘述有助於未來研究者精確復現論文宣稱的數值與行為，符合科學計算中「可復現性始於環境凍結」的基本原則。

然而，可重現性仍存在若干限制。首先，288 筆邊界基準測試並未涵蓋公開釋出後新增的 AlphaDynamics 工作流程、線上視覺負荷 API、瀏覽器儀表板與確定性合成回放（deterministic synthetic replay）等功能，因此欲復現完整實驗必須回退至特定快照，而非直接使用最新公開版。其次，原始腦電圖資料與逐樣本陣列因隱私考量保留於本地，論文未明確說明是否提供公開驗證資料集或合成資料，這對第三方重複執行三層級驗證——特別是 12 筆記錄的雜湊一致性測試——構成挑戰。若未來能釋出經去識別化的標準測試資料或確定性合成回放腳本，將顯著提升外部驗證的可行性。

#### 未來研究方向

**動態情境檢索與邊界更新**  
情境包（context pack）目前採靜態組裝，未來可發展為選擇性檢索（selective retrieval）機制，依據使用者查詢動態載入相關邊界資訊，在維持硬體感知精度的同時降低上下文長度。此外，隨著軟體版本迭代，實作邊界（implementation boundary）與結果欄位（result fields）勢必演變，需要自動化邊界迴歸測試，確保新版本不會意外放寬或錯置科學限制。

**端側數值引擎的實現**  
數值引擎目前運行於工作站，未來應探索將經審查的頻譜工作流程部署至 ADS1299-nRF52840 端或相近邊緣硬體，實現真正的端側確定性分析（edge deterministic analysis）。這將進一步壓縮資料外洩風險，並使「本地優先」（local-first）從資料儲存層延伸至運算層，對於可攜式低通道腦電圖裝置的現場應用（field deployment）具有重大價值。

**跨硬體與多工作流程擴展**  
當前系統鎖定於七通道後方導程（posterior montage），未來需開發可適應不同通道數量與空間配置（如額葉或全腦覆蓋）的模組化邊界框架，並建立對應的通道順序（channel order）驗證機制。同時，除了視覺認知負荷與 AlphaDynamics，可發展更多經審查的工作流程（reviewed workflows），例如事件相關電位（ERP）或睡眠分期，但每項新增流程都必須伴隨完整的四重邊界定義與基準測試。

**臨床有效性與標準化指標**  
作者明確指出本研究不宣稱臨床有效性（clinical validity）或經驗證的認知負荷指數（validated cognitive-load index）。後續研究可朝建立標準化實驗範式、跨設備驗證與常模參照（norm-referenced）分析邁進，將目前的相對啟發式（relative heuristic）轉化為具有臨床解釋力的絕對指標。此步驟需要與神經生理學家及臨床醫師合作，並在嚴格的倫理審查下收集驗證資料。

**強化對抗性穩健性**  
邊界感知基準測試可擴展為持續整合（Continuous Integration, CI）中的自動化測試套件，納入更多對抗性攻擊變體（adversarial variants），例如誘導模型進行跨通道錯誤歸因、混淆品質標誌與臨床診斷、或利用語義模糊性繞過實作邊界。透過對抗壓力測試（adversarial stress testing）不斷強化語言層的穩健性，是確保此類科學代理長期安全部署的關鍵。

## 論文問答

**Q1：為什麼將大型語言模型直接用於低通道腦電圖分析會產生根本性的安全與正確性問題？**
A：通用大型語言模型雖具備廣泛的腦電圖知識，但這並不代表它了解特定感測器的物理限制、當前軟體實作的演算法範圍，或是計算結果所能支持的科學推論邊界。在低通道腦電圖情境中，稀疏的空間取樣與訊號品質的變異性，使得模型極易產生「解剖學上看似合理、但物理上缺乏支援」的錯誤詮釋，例如將後腦節律誤標為前額或局部皮質效應。此外，若允許語言模型在數值分析路徑中生成隨機程式碼，可能會在未被察覺的情況下修改濾波器閾值或統計檢定，進而引入責任歸屬與使用者安全的嚴重風險。

**Q2：本文所提出的「邊界感知」包含哪四個核心層面，它們之間為何不可互換？**
A：邊界感知涵蓋物理邊界、實作邊界、結果邊界與科學邊界四個層面。物理邊界關注感測器陣列實際能觀測到什麼，例如後腦電極可以記錄視覺誘發反應，但這並不保證實作邊界中存在經過審查的穩態視覺誘發電位分類器。同樣地，結果邊界說明確定性輸出欄位實際報告了什麼工程數值，而科學邊界則進一步判斷這些觀察是否足以支持特定的神經科學或臨床推論，因此四者雖然相關，卻各自對應不同的能力限制與詮釋權限。

**Q3：低通道腦電圖的技術特性為何特別凸顯邊界感知的重要性？**
A：低通道系統僅具備稀疏的空間覆蓋，例如本文評估的七通道乾電極平台僅在特定後腦與頂葉位置取樣，這使得任何跨腦區的推論都缺乏足夠的感測器證據。由於通道數量有限，訊號品質也更容易出現波動，導致模型可能基於片段或雜訊資料產生看似合理但實際上毫無根據的解讀。因此，若缺乏明確的邊界感知機制，代理程式極易將單一位置的感測器層級測量過度推廣為全腦或臨床層級的結論，造成誤導性風險。

**Q4：NeuraDock Agent 的核心架構如何確保數值運算與語言詮釋層之間的分離？**
A：該系統採用雙層架構，由確定性的本地腦電圖數值引擎負責解析記錄、執行品質控制、運行經過審查的頻譜工作流程，並產生機器可讀的結構化產物。大型語言模型僅作為受約束的詮釋與規劃層，接收的是經過允許清單篩選的緊湊摘要以及版本化的情境套件，而非原始腦電圖訊號或高密度逐樣本陣列。這種設計確保了數值真相的單一來源始終是本地經過審查的 Python 程式碼，從根本上防止語言模型在分析路徑中暗中修改濾波器、閾值或特徵提取方法。

**Q5：版本化情境套件在系統中扮演什麼角色，其內容涵蓋哪些關鍵資訊？**
A：版本化情境套件是綁定語言層與硬體現實的核心機制，它明確描述了七通道硬體的通道順序與取樣率、當前已審查的工作流程登錄檔、結果欄位的語義定義、實作模組的邊界、科學限制以及參考案例。透過將這些資訊以結構化形式提供給語言模型，系統能夠在提示工程層面建立硬體感知與實作感知的賦基基礎。這使得代理程式在回應使用者查詢時，能夠根據當前軟體快照的具體能力範圍進行校準，而非依賴訓練資料中籠統的腦電圖常識。

**Q6：相較於傳統的檢索增強生成或工具使用框架，NeuraDock Agent 的邊界感知設計有何獨特之處？**
A：傳統檢索增強生成側重於將模型輸出與外部文件連結，而工具使用系統則讓模型選擇外部函數或應用程式介面，但兩者較少針對「模型是否正確辨識當前能力邊界」進行系統性評估。NeuraDock Agent 的情境層雖與這些想法相容，但更強調以版本化硬體情境明確框定語言模型的詮釋權限，並將原始數據完全保留在本地。此外，該架構特別關注「過度拒絕」這一失敗模式，即通用模型為了避免幻覺而將可行請求誤判為不支援，因此設計上必須同時衡量不安全接受與過度保守拒絕。

**Q10：NeuraDock Agent 在實際應用中如何平衡科學軟體的易用性與神經科技產品的安全責任？**
A：該系統透過自然語言介面降低科學軟體的操作門檻，讓使用者能夠以對話方式理解術語、規劃處理步驟或摘要數值結果，但嚴格禁止語言層重新定義分析方法或將工程輸出轉化為臨床決策。這種設計在神經科技堆疊的早期階段就引入了明確的能力邊界與監督式非自主角色，避免使用者因模型的流暢表述而誤解品質控制標誌的神經學意義。對於低通道腦電圖這類空間取樣稀疏的硬體而言，這種權限分離特別關鍵，因為它能防止看似合理的錯誤推論直接影響使用者對認知狀態的判斷。

## 實務應用指南

### 適用場景

1. **穿戴式視覺認知負荷監測原型**：適用於倉儲揀貨、遠端無人機操控或視覺檢測作業，以七通道乾電極設備（CP5、CP6、PO3、PO4、O1、Oz、O2，250 Hz）記錄後腦 alpha 活動，透過本地確定性引擎計算相對抑制比例，再由 LLM 層產出結構化品質報告，供現場研究人員參考（非診斷用途）。
2. **教育科技專注度回饋實驗**：在程式設計或視覺學習任務中，作為研究工具記錄受試者的「當前區段 vs 基線」後腦 alpha 變化，並透過對話式介面讓教學者查詢已審查的頻譜結果，降低解讀門檻。
3. **硬體受限的野外腦電圖研究**：戶外運動、移動情境或資源有限的現場研究，利用低通道數設備與本地數值引擎，在不上傳原始訊號與高密度逐樣本陣列的前提下，於邊緣工作站完成品質控管與頻譜分析。
4. **神經科技軟體的對話式操作層**：為既有七通道 EEG 數據庫提供自然語言查詢介面，讓非程式背景的研究助理透過對話檢索已審查的 Visual Cognitive Load 結果，同時防止模型建議未實作的分析（例如 frontal alpha asymmetry 或 SSVEP 分類器）。
5. **合成數據驗證與教學演示**：使用確定性合成回放（synthetic replay）功能，在課堂或產品展示中重現相同的數值結果、報告與圖表雜湊值，驗證系統可重複性與邊界行為。

### 實作前置條件

- **資料**：原始 EEG 必須符合論文定義的通道順序（CP5, CP6, PO3, PO4, O1, Oz, O2）且取樣率為 250 Hz；若使用官方硬體，需具備 ADS1299 前端與 nRF52840 微控制器的擷取模組。
- **運算**：一台可執行本地 Python 工作流程的工作站（確定性本地腦電圖引擎），以及可選的 LLM API 端點；原始 EEG 與高密度逐樣本陣列必須保留於本地，不得外傳。
- **技能**：需具備 Python 與基礎訊號處理能力（能理解品質控管閘門與頻譜工作流程）；需具備 API 整合與提示工程能力（能組裝 versioned context pack 與 allowlisted summary）；最重要的是理解論文所述的四種邊界——物理邊界、實作邊界、結果邊界與科學邊界——以正確執行情境賦基。

### 實作步驟建議

1. **硬體與通道對齊**：確認設備通道順序與論文定義的七通道後腦配置一致，建立通道對應表並鎖定取樣率為 250 Hz。
2. **本地引擎部署**：部署 NeuraDock Agent 的本地數值引擎，設定原始資料儲存路徑，確保原始 EEG 與高密度逐樣本陣列不離開本地環境。
3. **工作流程審查與鎖定**：啟用 Visual Cognitive Load（或後續版本的 Alpha Dynamics）工作流程，審查頻譜閾值、濾波器與品質旗標，將其設為數值真相的單一來源，禁止 LLM 層修改任何參數。
4. **情境賦基封裝**：組裝 versioned context pack，納入硬體規格（七通道乾電極）、已審查工作流程清單、結果欄位定義、實作邊界與科學限制（例如「僅為錄音內相對特徵，非通用或診斷指標」）。
5. **摘要允許清單設計**：定義 allowlisted summary 的欄位與格式（如品質通過/未通過、相對 alpha 抑制比例、雜訊旗標），確保 LLM 僅接收此緊湊摘要，而非原始數據或逐樣本陣列。
6. **邊界感知基準測試**：在正式上線前，執行類似論文的 36-case boundary-awareness benchmark，涵蓋普通與對抗性問題，並測試四種情境消融條件，確認模型能正確接受、限定或拒絕請求。
7. **失效隔離與路由測試**：注入 HTTP 錯誤、連線故障與畸形輸出，驗證本地工件的保存與資料邊界的完整性，確保異常時原始分析結果仍留存在地端。
8. **產品介面整合**：將引擎輸出（結果、報告、圖表雜湊）與 LLM 解釋層綁定至前端儀表板或瀏覽器介面，提供結構化輸出與自然語言說明。

### 潛在風險與注意事項

- **臨床誤用風險**：系統輸出為工程品質旗標與相對頻譜特徵，不具臨床有效性，也未建立經驗證的絕對認知負荷指數。必須在介面與文件中明確標示「非醫療診斷」，防止使用者將 alpha 抑制指標誤解為疾病或認知能力判斷。
- **邊界混淆風險**：LLM 可能將「技術上乾淨的訊號」詮釋為「受試者專注」，或建議未實作的分析（如 SSVEP 分類器）。必須透過 context pack 明確劃分四條邊界，並定期審查提示詞，避免實作邊界與科學邊界混為一談。
- **資料外洩風險**：雖然原始 EEG 留在本地，但 allowlisted summary 與 metadata 仍可能包含敏感資訊。應最小化傳輸欄位，並對 LLM API 呼叫啟用傳輸加密與存取紀錄。
- **過度拒絕或過度接受**：模型可能過度保守而拒絕可行請求，或在對抗性問題下不當接受。應持續監控四向決策（接受/限定/拒絕/轉介）的分佈，並依據邊界感知基準測試結果調整 context。
- **數值再現性陷阱**：雖然論文驗證十次數值重複與雜湊一致，但若本地環境的 Python 套件版本、隨機種子或浮點運算環境變動，可能破壞確定性。應鎖定容器化環境與版本。

### 與其他技術的整合建議

- **與 MNE-Python / EEGLAB 整合**：NeuraDock Agent 並非取代這些成熟生態系，而是作為其上層的窄化工作流程層。可將本地引擎輸出的結構化結果匯出為 MNE 可讀格式（如 FIFF），供後續高密度研究或專家人工檢視。
- **與既有儀表板 / BI 工具整合**：將 allowlisted summary 與結果雜湊導入 Grafana 或自研儀表板，顯示品質閘門狀態與相對認知負荷趨勢；LLM 層則負責產生文字摘要與異常解釋。
- **與邊緣推論框架整合**：雖然目前數值工作流程運行於工作站，但未來可參考 TinyML 共設計思路，將部分品質控管閘門下放至 nRF52840 或更強大的邊緣處理器，進一步減少原始訊號傳輸。
- **與 RAG / 工具使用系統整合**：versioned context pack 可與檢索增強生成結合，將審查過的論文、硬體規格書與科學限制文件作為靜態或動態檢索庫，強化邊界感知而非僅依賴靜態提示。
