## 摘要翻譯

視覺生成正從透過單次呼叫使用的生成模型（Generative Models），演變為能夠規劃（Planning）、選擇工具（Tool Use）、檢視中間合成輸出（Intermediate Synthesized Output）、修正失敗（Failure），並重複使用先前經驗（Prior Experience）的智能體控制（Agentic Control）流程。在大多數現有系統中，控制器（Controller）是大型語言模型（Large Language Model, LLM）或視覺語言模型（Vision-Language Model, VLM），而視覺生成模型（Visual Generation Model）則作為工具（Tool）或執行器（Executor）。然而，現有研究缺乏一致的準則來判斷生成系統何時具備智能體特性（Agenticity）。規劃深度（Planning Depth）、工具使用（Tool Use）、多角色協作（Multi-Role Collaboration）與強化學習（Reinforcement Learning）常被視為智能體特性（Agenticity）的證據，儘管它們之中沒有任何一項必然決定控制器（Controller）能夠做出哪些生成層級決策（Generation-Level Decision）。我們根據控制器（Controller）在生成流程（Generation Process）中能夠直接控制的範圍來組織該領域。在 L1 條件控制（L1 Conditioning Control）中，控制器（Controller）為預定生成器（Predetermined Generator）準備輸入，但不控制執行哪一項視覺操作。在 L2 執行控制（L2 Execution Control）中，它選擇並調用實際的生成、編輯（Editing）、渲染（Rendering）或其他內容修改操作（Content-Modifying Operations）。在 L3 結果適應控制（L3 Outcome-Adaptive Control）中，它觀察中間結果（Intermediate Outcome），並根據此觀察改變當前任務（Current Task）內的後續操作（Subsequent Operation）。在 L4 經驗適應控制（L4 Experience-Adaptive Control）中，它保留來自已完成任務（Completed Task）的經驗，並利用該經驗來改變未來任務（Future Task）的決策。L0 固定支援（L0 Fixed Support）另外指稱生成器（Generator）、編輯器（Editor）、評估器（Evaluator）、獎勵模型（Reward Model）、基準測試（Benchmark），以及未部署任何會做出生成層級決策（Generation-Level Decision）之控制器（Controller）的固定流程（Fixed Pipeline）。這些層級描述的是逐漸擴大的決策範圍（Decision-Making Scope），而非模型規模（Model Size）、系統複雜度（System Complexity）、輸出品質（Output Quality）、工具或角色數量，或訓練方法（Training Method）。將此框架應用於圖像生成（Image Generation）、影片生成（Video Generation）、編輯（Editing）、3D 生成（3D Generation）、世界生成（World Generation）、簡報生成（Slide Generation）與使用者介面生成（User-Interface Generation），可揭示控制器（Controller）能力如何演變，以及其機制如何分布於各層級。

### 核心貢獻（3～5點）
- 提出以「控制器在生成流程中的決策範圍」作為判斷視覺生成系統是否具備智能體特性（Agenticity）的統一準則。
- 建立 L0 至 L4 的五級分類框架，釐清從固定支援、條件控制、執行控制、結果適應控制到經驗適應控制的連續光譜。
- 明確區分真正決定智能體特性的因素（決策範圍）與常被誤認為證據的表面特徵（規劃深度、工具使用、多角色協作、強化學習、模型規模等）。
- 將框架應用於圖像、影片、編輯、3D、世界、簡報與使用者介面生成等多個領域，展示控制器能力的演變與機制分布。

### 適合對象
適合對生成式 AI、視覺生成、智能體系統有興趣的研究者與工程師，特別是關注如何評估與設計具備自主決策能力之視覺生成系統的讀者。

## 深度分析

#### 方法論解析

本文的核心方法論並非提出新的生成模型，而是建立一套以 **Controller（控制器）** 的 **Decision-Making Scope（決策範圍）** 為軸心的分級框架，將 **Agentic Visual Generation（智能體視覺生成）** 從「模型能力」與「系統複雜度」中抽離出來，重新定義何謂具備 **Agenticity（智能體特性）**。作者指出，過去文獻常把 **Planning Depth（規劃深度）**、**Tool Use（工具使用）**、**Multi-Role Collaboration（多角色協作）** 或 **Reinforcement Learning（強化學習）** 當成智能體的證據，但這些特徵本身並不能回答「控制器能夠在生成流程的哪個環節改變決策」這個根本問題。

在此框架下，視覺生成系統被劃分為五個層級：

- **L0 Fixed Support（L0 固定支援）**：包含 **Generator（生成器）**、**Editor（編輯器）**、**Evaluator（評估器）**、**Reward Model（獎勵模型）**、**Benchmark（基準測試）** 與 **Fixed Pipeline（固定流程）** 等預定元件。這些元件提供生成與評估能力，但沒有部署會做 **Generation-Level Decision（生成層級決策）** 的控制器。
- **L1 Conditioning Control（L1 條件控制）**：控制器不決定執行哪一個視覺操作，只負責為 **Predetermined Executor（預定執行器）** 建構 **Input Conditioning（輸入條件化）** 或 **Specification（規格）**。例如將複雜文字需求轉成物件描述、邊界框或版面配置。
- **L2 Execution Control（L2 執行控制）**：控制器能夠選擇並調用實際的 **Content-Modifying Operations（內容修改操作）**，例如生成、編輯、渲染等，這是從「準備輸入」到「決定行動」的關鍵躍遷。
- **L3 Outcome-Adaptive Control（L3 結果適應控制）**：控制器觀察 **Intermediate Synthesized Output（中間合成輸出）** 或 **Intermediate Outcome（中間結果）**，並在 **Current Task（當前任務）** 內改變 **Subsequent Operation（後續操作）**，形成閉環修正。
- **L4 Experience-Adaptive Control（L4 經驗適應控制）**：控制器保留 **Completed Task（已完成任務）** 的經驗，並用來改變後續獨立 **Future Task（未來任務）** 的決策，跨越 **Episode（回合）** 邊界。

這五個層級的因果意義在於：每往上一級，能夠影響未來生成決策的「最晚證據點」就往後延伸——從 L1 的執行前條件建構、L2 的執行中操作選擇、L3 的執行後結果修正，到 L4 的跨任務經驗累積。作者進一步提出 **Level-Conditioned Evaluation Framework（層級條件化評估框架）**，透過在不同層級間匹配 **Generator（生成器）**、**Tool（工具）**、預算與 **Evaluator（評估器）**，來隔離「擴大控制器決策範圍」本身所帶來的價值，而非混淆於模型規模、系統複雜度或訓練方法。

#### 實驗數據解讀

由於提供的上下文僅包含摘要與引言，尚未出現具體的數值表格，因此以下從摘要與引言所提及的線索進行解讀。文中引用了多個視覺生成評估基準：**T2I-CompBench** 與 **GenEval** 用於診斷圖像的組合性與物件綁定錯誤；**VBench** 與 **EvalCrafter** 則用於揭露影片的時間一致性與感知缺陷。這些 **Evaluator（評估器）** 在 L0 層級提供診斷證據，但本身不會自動修正生成結果；到了 L3，這些評估訊號才被控制器用來驅動後續操作。

在 **Level-Conditioned Evaluation Framework（層級條件化評估框架）** 下，合理的實驗設計會固定生成模型、工具集與運算預算，僅改變控制器的決策範圍，從而觀察下列指標的變化：

- **文字—視覺對齊度（text-visual alignment）**：L1 透過更好的 **Specification（規格）** 應可提升。
- **組合正確性與物件綁定（compositional correctness / object binding）**：L2 透過操作選擇與分解，應比單次生成更能處理複合概念。
- **時間一致性與感知品質（temporal consistency / perceptual quality）**：L3 透過中間結果回饋修正，應能減少錯誤累積。
- **任務成功率與人類偏好（task success rate / human preference）**：隨層級提升，**Autonomy（自主性）** 提高，**Human Supervision（人類監督）** 減少。
- **效率指標（inference cost, number of tool calls, latency）**：L3/L4 雖可能增加單次成本，但 L4 可透過經驗重用降低長期平均成本。

若實驗結果顯示，在相同預算與底層模型下，L3 相較於 L2 能顯著降低組合錯誤，或 L4 相較於 L3 在相似任務上減少重複試錯次數，則可證明「擴大決策範圍」本身具有獨立價值。反之，若高層級僅因使用更強大的生成器或更多工具而獲勝，則無法歸因於 **Agentic Control（智能體控制）**。讀者在檢視完整論文時，應特別注意作者是否對這些混淆因子做了嚴格控制。

#### 與現有研究的比較

本文與現有研究的根本差異在於「以控制器決策範圍取代現象特徵」作為分類標準。過去許多系統將 **Large Language Model（LLM，大型語言模型）** 或 **Vision-Language Model（VLM，視覺語言模型）** 當作規劃者，把 **Visual Generation Model（視覺生成模型）** 當作 **Tool（工具）** 或 **Executor（執行器）**，並宣稱具備智能體特性。然而，若該控制器僅是把使用者需求轉譯成提示詞再送給單一擴散模型，則依本文標準仍屬 L1，而非 L2。

文中舉例說明了各層級的代表性工作：

- **L1**：LLM-grounded Diffusion（LMD）、LayoutGPT 等，透過 LLM 產生版面或物件描述來條件化預定生成器。
- **L3**：SLD 將診斷出的不匹配轉換為新的取樣決策；GenPilot 利用視覺回饋選擇後續精煉操作。
- **L4**：OctoT2I 更新持久化的能力檔案以影響未來路由；GenEvolve 蒸餾成功與失敗的生成軌跡；COMFYCLAW 將驗證過的工作流程提升為可重用的技能庫。

本文的優點在於提供了一致的判準，能夠澄清許多系統的實際層級。例如，一個具備多個 **Tool（工具）** 與多個 **Role（角色）** 的系統，若控制器無法在生成過程中根據中間結果改變操作，則仍不具備 L3 的 **Outcome-Adaptive Control（結果適應控制）**。同樣地，使用 **Reinforcement Learning（強化學習）** 訓練並不保證達到 L4，除非經驗確實被保留並用於改變未來獨立任務的決策。

然而，此框架也有其限制：

1. **層級之間的連續性**：實際系統常同時具備多層特徵，例如一個 L3 系統也可能內建 L4 的輕量記憶，單一標籤可能過度簡化。
2. **適應品質的量化**：框架說明「能否」根據結果或經驗改變決策，但對於「改變得好不好」仍依賴外部 **Evaluator（評估器）** 的品質。
3. **人機協作邊界**：當人類在迴路中提供回饋時，難以區分哪些決策來自控制器、哪些來自人類。
4. **信用分配問題**：在 L4 中，如何將跨 **Episode（回合）** 的成功或失敗歸因於特定決策，仍是一個開放挑戰。

#### 可重現性評估

摘要最後提到「Project resources are available at the project repository」，顯示作者有意釋出相關資源，這對可重現性是正面訊號。然而，僅憑摘要與引言無法判斷釋出的完整程度。若要達到高度可重現，建議的釋出內容應包括：

- 各層級（L0–L4）的基線實作與控制器提示詞（prompts）。
- **Level-Conditioned Evaluation Framework（層級條件化評估框架）** 的評估腳本，包含如何匹配生成器、工具、預算與評估器。
- 所使用的 **Benchmark（基準測試）** 清單與前處理流程。
- 若涉及 L4，則需釋出能力檔案、技能庫或經驗蒸餾後的模型權重。
- 推論與訓練的完整配置（hyperparameters、API 呼叫紀錄）。

若僅釋出靜態網頁或展示影片，則可重現性會大打折扣。此外，由於許多 L2/L3 系統依賴商業 API（如 GPT-4V、DALL-E）或特定版本的開源模型，未來研究者在復現時需特別注意 API 版本漂移與模型權重可用性的問題。

#### 未來研究方向

基於本文提出的 L0–L4 框架與所強調的關鍵轉換，未來研究可朝以下方向發展：

1. **Generator-as-Controller（生成器即控制器）**：目前控制器多為外部 LLM/VLM，未來可讓 **Visual Generation Model（視覺生成模型）** 本身內建規劃、評估與修正的內部迴路，並以相同決策範圍測試其層級。
2. **跨層級聯合訓練**：設計能同時學習 L2 操作選擇、L3 結果適應與 L4 經驗累積的端到端目標，例如結合強化學習與記憶機制的統一訓練框架。
3. **自我評估與診斷能力**：發展更強大的內建 **Evaluator（評估器）**，使 L3 系統能在沒有外部基準的情況下自我檢測並修正 **Failure（失敗）**。
4. **可解釋的經驗重用**：研究 L4 中能力檔案、技能庫與失敗案例的組織方式，並讓其決策過程對人類可解釋。
5. **多控制器協作**：在 **Multi-Role Collaboration（多角色協作）** 架構下，依據 L0–L4 框架明確劃分各控制器的決策範圍與責任邊界。
6. **新興應用領域的標準化**：將此框架擴展至 **World Generation（世界生成）**、**Slide Generation（簡報生成）**、**User-Interface Generation（使用者介面生成）** 與 **3D Generation（3D 生成）**，建立對應的層級標註資料集與評估基準。
7. **安全性與倫理控制**：利用 L3/L4 的適應迴路，在生成過程中即時抑制偏見、版權風險或不當內容。
8. **人類監督遞減策略**：研究如何在提升 **Autonomy（自主性）** 的同時，設計可信的人機協作與接管機制。
9. **層級條件化基準的社群化**：推動社群採用 L0–L4 作為報告與比較的標準，使不同論文能在相同決策範圍下公平比較。

## 論文問答

**Q1：智能體視覺生成（Agentic Visual Generation）要解決的核心問題是什麼？**
A：傳統視覺生成多仰賴使用者對固定生成模型進行單次呼叫，但真實創作需求往往涉及規劃、工具選擇、中間結果檢查、失敗修正與經驗重用等連續決策。現有系統雖然常以大型語言模型或視覺語言模型作為控制器，卻缺乏一致標準來判斷「何時算得上具備智能體特性」。本文因此提出以控制器在生成流程中的決策範圍為依據的分級框架，讓研究者能清楚區分生成器能力與控制自主性的進展。

**Q2：為什麼規劃深度、工具使用、多角色協作或強化學習不能單獨作為智能體特性的判準？**
A：這些特徵常被誤認為智能體性的充分證據，但它們並未說明控制器能直接決定哪些生成層級的決策。舉例來說，一個系統即使擁有許多工具或複雜規劃，若只是用來為預定執行器建構輸入條件，仍屬於 L1 條件控制。本文強調應以控制器對生成流程的因果影響範圍來判定智能體性，而非表面上的系統複雜度或訓練方法。

**Q3：建立統一的智能體性判準對整個領域為何重要？**
A：目前相關文獻橫跨圖像、影片、3D、世界、簡報與使用者介面生成等任務，卻使用不一致的標準來描述系統，導致難以比較真正的自主程度。統一判準能讓研究者把焦點從模型規模、輸出品質或工具數量，轉移到控制器能直接控制的決策範圍。這也有助於產品開發者根據應用需求，選擇適當的控制層級與人機協作方式。

**Q4：本文提出的核心方法是什麼？**
A：本文將視覺生成系統依控制器的決策範圍劃分為 L0 固定支援、L1 條件控制、L2 執行控制、L3 結果適應控制與 L4 經驗適應控制五個層級。每一層級描述的是證據能夠改變未來生成決策的最晚時點，從前置條件建構、操作中工具選擇、任務內修正，到跨任務經驗重用。這個框架適用於圖像、影片、編輯、3D、世界、簡報與使用者介面生成等多種視覺任務。

**Q5：相較於既有研究，本文最主要的創新之處在哪裡？**
A：本文最大的創新在於將「智能體性」重新定義為控制器的決策範圍，而非規劃深度、角色數量、工具數量或是否使用強化學習。這種以因果影響範圍為核心的觀點，能夠區分執行器本身的進步與控制器自主性的提升。此外，作者進一步提出層級條件化評估框架，以隔離擴大決策範圍所帶來的價值。

**Q6：為什麼要將 L0 獨立出來，而未來的「生成器即控制器」也不被視為額外層級？**
A：L0 固定支援標示了納入框架的邊界，代表生成器、編輯器、評估器、獎勵模型與固定流程等沒有部署控制器介入的預定元件。把 L0 獨立出來可避免將執行器能力提升誤認為控制自主性提升。至於未來生成器本身兼任控制器的情況，作者認為仍可用相同的最大因果影響範圍測試來歸類，因此不需要新增層級，保持框架的一致性。

**Q7：本文討論了哪些基準測試與評估器，它們分別對應哪些層級？**
A：文中提到 T2I-CompBench 與 GenEval 用於診斷組合性與物件綁定錯誤，VBench 與 EvalCrafter 則用於發現影片的時間一致性與感知缺陷，這些都屬於 L0 固定支援中的評估器。SLD 與 GenPilot 則將診斷結果回饋給控制器以改變後續生成決策，展現 L3 結果適應控制。OctoT2I、GenEvolve 與 COMFYCLAW 進一步把成功或失敗的軌跡轉化為可重複使用的能力設定或技能庫，對應 L4 經驗適應控制。

**Q8：將此框架應用到各類視覺生成任務後，主要揭示了什麼結果或趨勢？**
A：應用結果顯示，控制器的能力是沿著生成流程逐步擴展的，從塑造輸入條件、選擇操作、根據中間結果修正，到利用先前經驗調整未來任務，人類監督隨之遞減。框架也揭示許多看似複雜的系統，其控制器的實際決策範圍可能僅止於 L1 或 L2。透過層級條件化評估，研究者能更公平地比較不同層級的貢獻，而不會把執行器或資源優勢誤歸於控制機制。

**Q9：層級條件化評估框架如何進行「消融」或對照，以驗證控制範圍的價值？**
A：該評估框架透過在不同層級之間匹配生成器、工具、預算與評估器，來隔離「擴大控制器決策範圍」本身所帶來的效益。若未進行這種匹配，實驗結果可能混淆了更強大的執行器、更多工具或更高運算資源所帶來的進步。這種設計相當於對控制層級進行系統性消融，讓研究者能判斷 L3 或 L4 控制是否真正改善了生成結果。

**Q10：這個框架在實務上可以應用於哪些場景？**
A：此框架可應用於自動化平面設計、影片剪輯、3D 資產生成、使用者介面原型設計、虛擬世界模擬以及簡報製作等需要多步驟視覺創作的場景。在這些應用中，控制器能將模糊的使用者需求轉為具體規格，選擇合適的生成或編輯工具，並在過程中檢查中間合成輸出。隨著層級提升，系統能減少反覆人工介入，逐步實現更高自主性的內容生產。

**Q11：從產品設計角度，採用不同控制層級時需要考慮哪些因素？**
A：產品設計者必須在自主性與可靠性之間取得平衡，因為 L3 與 L4 雖然能減少人工迭代，卻高度依賴評估器的正確診斷與經驗儲存的安全性。此外，不同應用對失敗的容忍度不同，例如廣告素材生成與醫療影像合成所需的人類監督程度便大相逕庭。本文的層級分類有助於團隊根據目標任務選擇最適架構，並明確定義人機協作的控制點。

**Q12：這項研究對整個視覺生成領域可能帶來什麼影響？**
A：本文提供了一套共同的詞彙與一致判準，能夠減少文獻中對「智能體性」的混亂描述，並將研究焦點從表面複雜度轉向控制器的決策範圍。它有助於建立更貼近真實自主程度的評估協議，並指導未來生成器即控制器的系統設計。長遠來看，這個框架能促進跨任務比較，加速從單次生成模型到真正智能體控制流程的轉變。

**Q13：作者承認或隱含了哪些框架限制？**
A：由於框架以控制器的決策範圍為核心，它刻意抽象了許多實作細節，因此可能無法完整捕捉多智能體協商或特定人機互動模式的細微差異。將一個系統歸類到單一層級也可能過於簡化，因為實際系統可能同時具備多個層級的能力。此外，此框架主要關注控制範圍，對輸出美學、倫理安全與社會影響等議題並未直接納入分級依據。

**Q14：在不同控制層級中，可能出現哪些典型的失敗案例？**
A：在 L3 結果適應控制中，若評估器錯誤診斷中間結果，控制器可能做出不當的後續修正，反而讓輸出變得更差。在 L4 經驗適應控制中，若保留的經驗帶有偏見或已經過時，系統可能在未來任務中重複錯誤決策。在 L2 執行控制中，若工具描述不準確或工具集合不完整，控制器可能選擇不適合的視覺操作，導致生成流程偏離使用者意圖。

**Q15：未來研究可以朝哪些方向發展？**
A：作者指出未來的關鍵轉變包括從生成模型邁向可執行控制、建立可靠的結果驅動修正機制、發展可跨任務重用的經驗，以及探索生成器本身作為控制器的 regime。後續研究可聚焦於統一控制器的訓練目標、開發更精準的視覺評估器，以及設計能持續學習的終身經驗累積機制。同時，也需要更多與 L0–L4 層級對齊的基準測試，才能有效衡量這些進展。

## 實務應用指南

### 適用場景

1. **大量行銷素材自動化產製**  
   電商或品牌每週需要數百張符合季節、文案與版位規格的圖像。透過 L1 條件控制將商品資訊轉為結構化 prompt 與佈局，再由 L2 執行控制依據版位（banner、社群貼文、EDM）選擇不同生成器或編輯工具，最後以 L3 結果適應控制自動檢查文字可讀性與品牌色，迭代修正。

2. **互動式使用者介面（UI）原型生成**  
   產品團隊輸入需求描述後，系統自動輸出 Figma/Sketch 可編輯的 UI 稿。L2 控制器可選擇「產生畫面 → 產生元件 → 排版檢查」等操作；L3 根據預覽截圖偵測對齊或對比度問題並重新渲染；L4 則累積設計系統（Design System）經驗，讓後續專案更快符合品牌規範。

3. **遊戲與虛擬世界內容管線**  
   開放世界遊戲需要持續產生 3D 場景、NPC 外觀與動畫。L0 固定支援提供基礎生成器與物理模擬器；L2 控制器依任務選擇地形、建築、角色或天氣工具；L3 在模擬後檢視場景一致性（例如碰撞、光照）並重跑特定步驟；L4 將成功關卡設計沉澱為可重複使用的世界生成流程。

4. **短影片廣告與社群內容製作**  
   從腳本到 5–15 秒影片，系統依腳本分鏡選擇圖像生成、影片生成、配音與字幕工具（L2），並在每一鏡頭生成後檢查主體一致性、口型同步與節奏（L3），最終把通過審核的風格參數與剪輯節奏存入風格庫（L4）。

5. **建築與室內設計視覺化**  
   設計師輸入平面圖與風格偏好，系統自動產生 3D 渲染與 VR 漫遊。L1 將草圖轉為結構化條件（房間功能、材質、光照）；L2 選擇 3D 重建、材質生成或渲染器；L3 根據中間渲染圖偵測比例錯誤或材質衝突並重算；L4 累積客戶偏好與常見修改模式，縮短未來提案週期。

### 實作前置條件

- **資料準備**
  - 高品質的任務範例庫（輸入描述、中間產物、最終輸出、成功/失敗標籤）。
  - 領域專用評估標準，例如品牌色卡、設計系統規範、物理一致性規則或使用者滿意度指標。
  - 若要做到 L4，需有跨任務的歷史紀錄與可檢索的經驗庫（成功軌跡、常見失敗模式、修正動作）。

- **運算資源**
  - L0/L1：至少可部署一個視覺生成模型（如 Stable Diffusion、FLUX、視訊擴散模型）的 GPU 或 API 配額。
  - L2/L3：需要額外的控制器推理成本（LLM/VLM 呼叫）以及反覆生成帶來的運算倍增，建議預留 3–5 倍原始生成的預算。
  - L4：需要長期儲存與檢索系統（向量資料庫、經驗索引）以及週期性再訓練或檢索增強的微調資源。

- **技術與團隊能力**
  - 熟悉提示工程、視覺生成模型（擴散模型、自回歸模型）與多模態模型（VLM）的運作。
  - 具備將控制器與工具串接的能力（API 包裝、狀態機、錯誤處理）。
  - 具備評估與資料工程能力，能建立自動化評估器與回饋迴路。
  - 產品與設計團隊需共同定義「何謂成功」，避免僅由工程端單方面決定。

### 實作步驟建議

1. **從 L0 固定支援開始盤點**  
   列出已擁有的生成器、編輯器、評估器與固定流程，確認它們的輸入輸出格式、成本與失敗模式。不要一開始就追求最高層級。

2. **定義任務與決策邊界**  
   釐清「控制器需要決定什麼」：是只要準備 prompt（L1）、選擇工具（L2）、根據中間結果修正（L3），還是跨任務學習（L4）。選擇能解決問題的最低層級，降低複雜度。

3. **建立條件化與規格轉換層（L1）**  
   將使用者自然語言或結構化需求轉為執行器可理解的規格：prompt、佈局、風格參數、遮罩、3D 條件等。此層是後續所有控制的基礎。

4. **設計工具選擇與執行控制（L2）**  
   讓控制器能根據任務選擇並呼叫適當工具。建議先用規則或少量範例啟動，再逐步引入模型化決策。記錄每次選擇的工具、參數與結果，為 L3/L4 累積資料。

5. **加入中間結果檢視與修正迴路（L3）**  
   針對最容易出錯的步驟部署評估器（VLM 判斷、規則檢查、使用者回饋）。當評估未通過時，控制器應能重新選擇後續操作，而非僅重跑同一模型。

6. **建構可重複使用的經驗庫（L4）**  
   將完成任務的成功軌跡、失敗原因與修正動作結構化儲存。未來新任務先檢索相似案例，再決定初始條件、工具選擇或修正策略。

7. **建立層級對齊的評估機制**  
   使用論文提出的 level-conditioned evaluation：在相同生成器、工具、預算與評估器下，比較不同層級帶來的實質增益，避免把「系統變複雜」誤認為「變得更智能體化」。

---

### 潛在風險與注意事項

- **過度工程化**  
  並非所有應用都需要 L3 或 L4。若任務單純且失敗成本低，L1 或 L2 可能已足夠。過早引入多輪修正與記憶會大幅增加延遲與成本。

- **錯誤傳播與迴路失控**  
  L3 的修正迴路若評估器本身不準，可能導致「愈修愈錯」。建議設定最大迭代次數、人工介入閥值，並保留每個中間結果供追溯。

- **延遲與成本飆升**  
  每增加一層控制，通常意味更多模型呼叫與生成次數。需在產品設計階段就納入成本模型，並提供「快速模式」與「高品質模式」。

- **智慧財產權與內容安全**  
  視覺生成模型可能複製訓練資料風格或產生不當內容。控制器層級愈高，責任邊界愈模糊。建議在 L2 工具選擇與 L3 評估中嵌入版權檢查、安全過濾與人工審核閘門。

- **評估指標與業務目標脫鉤**  
  自動化指標（如 FID、CLIP Score）未必反映使用者滿意度。應將人類回饋或業務指標（點擊率、轉換率、審核通過率）納入 L3/L4 的學習訊號。

### 與其他技術的整合建議

- **數位資產管理（DAM）與設計系統**  
  將 L0 生成器與 L4 經驗庫對接企業 DAM，讓生成的素材、風格參數與成功範本能被設計師搜尋、審核與複用。

- **MLOps / LLMOps 管線**  
  把控制器決策、工具呼叫、中間結果與評估分數記錄到實驗追蹤平台（如 Weights & Biases、MLflow），支援 A/B 測試、迴歸測試與版本控制。

- **CI/CD 與品質閘門**  
  在部署前將 L3 評估器納入自動化測試，確保新版生成器或控制器不會降低輸出品質。可設定「若連續 N 次修正失敗則阻擋發布」。

- **現有設計與生產工具**  
  透過外掛或 API 將智能體視覺生成整合到 Figma、Adobe Creative Suite、Blender、Unity 或遊戲引擎中，讓控制器輸出的中間產物可直接進入人工編輯流程。

- **檢索增強生成（RAG）與知識庫**  
  L4 的經驗庫可視為一種多模態 RAG。將成功軌跡、設計規範與使用者回饋向量化，讓控制器在面對新任務時先檢索再決策。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先聚焦在圖 1 的 L0 到 L4 分級與第一節的動機，理解「智能體特性」取決於控制器能決定什麼，而非模型有多大或用了多少工具。接著從 L1 的實際案例（如 LayoutGPT、LMD）入手，體會「把使用者需求轉成生成器可執行的規格」這個最基礎也最重要的步驟。

- **AI 工程師**  
  請重點閱讀分級框架的定義與各層級的過渡條件，並對照你目前的系統判斷它實際落在哪一層。特別注意 L2 與 L3 的差異：並非只要有工具選擇或迴圈就是 L3，關鍵在於控制器是否根據「中間合成輸出」改變後續操作。實作時優先建立可觀測的狀態機與評估器，再逐步往上堆疊。

- **研究人員**  
  本文的核心貢獻在於提出以「決策範圍」而非「訓練方法或系統複雜度」來定義智能體視覺生成。建議深入檢視作者如何將現有文獻重新歸類，並思考 level-conditioned evaluation 的設計如何影響未來基準測試。可進一步探討「生成器即控制器」這一未來方向對模型架構與訓練目標的啟示。

- **產品經理**  
  把這篇論文當作產品分級的參考架構：L1 對應「自動化 prompt 與規格生成」、L2 對應「多工具工作流」、L3 對應「自動品檢與修正」、L4 對應「越用越聰明的經驗累積」。在規劃產品路線圖時，可依業務價值與失敗成本決定要先做到哪一層，並用文中框架與工程團隊對齊語言，避免把「有規劃」或「有工具」誤認為已達成智能體化。
