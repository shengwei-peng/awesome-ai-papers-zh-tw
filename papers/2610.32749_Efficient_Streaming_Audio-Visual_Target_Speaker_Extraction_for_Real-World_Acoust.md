Falcon 的整體方法論圍繞「單次前向傳播（single-pass）」與「編碼器空間對比學習」兩大核心設計理念展開，試圖在因果性（causal）約束下同時兼顧提取品質與邊緣部署效率。

**分離器（Separator）的多尺度時頻分離架構**

Falcon 的分離器採用編碼器-解碼器（encoder-decoder）主幹結構，與傳統時頻分離器的關鍵差異在於「單遍解碼器遍歷（single decoder traversal）」設計。具體而言，分離器在一次解碼器前向傳播中，將不同尺度的時頻建模任務分配到不同的解碼器層級：

- **中尺度層級**：負責時間軸（time-axis）建模，捕捉時序動態

這種「由粗到細」的層級式分工，使模型能在單次前向傳播中完成多尺度分離，避免了 SwiftNet 等輕量化方法需要反覆呼叫小型分離器（repeatedly invoking a small separator）所帶來的計算成本累積問題。這是 Falcon 能將計算量降低 20.2 倍的架構基礎。

**編碼器空間說話人對比損失（Encoder-space Speaker Contrastive Loss）**

Falcon 在訓練階段引入了一個關鍵的輔助損失函數——編碼器空間說話人對比損失。該損失在分離器的 STFT 編碼器空間中計算，目標是：

- 將目標說話人（target speaker）的編碼特徵拉近乾淨參考
- 將每個近場干擾說話人（near-field interfering speaker）的編碼特徵推離乾淨參考

此設計的精妙之處在於「零推理成本（zero inference cost）」特性：對比損失僅在訓練時作用於編碼器空間，推理階段無需額外計算，卻能有效抑制近場洩漏（near-field leakage）。此外，論文聲稱此損失具有「跨骨幹網路（backbones）可遷移性」，意味著它可作為通用訓練策略應用於其他 AVTSE 骨幹。

**音視覺融合（Audio-Visual Fusion）策略**

Falcon 透過目標說話人的視覺串流（visual stream），即唇部動作（lip movements），作為註冊線索（enrollment cues）來引導音訊分離。這與現有 AVTSE 方法的融合策略一致，但 Falcon 的單遍設計使融合後的特徵能直接在多尺度解碼器中處理，避免了反覆融合的計算開銷。

**因果性保證**

Falcon 嚴格遵循 SwiftNet 提出的因果化協議，將所有時間操作限制在過去與當前幀內，確保流式（streaming）推理的可行性，這對視訊會議、助聽裝置等延遲敏感應用至關重要。

A：現有基準（如 LRS2-2Mix、LRS3-2Mix、VoxCeleb2-2Mix）將混合音中的說話人數固定為兩人，且不涵蓋近場／遠場空間幾何、可控混響與突發噪音等真實聲學條件，導致模型在受控環境下的表現無法預測其在真實裝置上的行為。在模型層面，AV-TFGridNet、AV-Mossformer2 等高效因果架構雖然保留了分離品質，但其參數量與每幀 FLOPs 過高，使推理延遲超出邊緣硬體的即時預算；而 SwiftNet 等輕量化替代方案則透過反覆呼叫小型分離器來換取容量，反而抵銷了縮小模型帶來的延遲優勢。

**Q3：為什麼這個問題在學術與產業上都很重要？**
A：在產業面，視訊會議、助聽裝置、AR/VR 頭戴裝置等應用對延遲極為敏感，使用者期望系統能即時處理音訊並精準聚焦於目標說話人，若模型過於龐大或延遲過高，將直接影響使用者體驗與產品的可行性。在學術面，目前缺乏能同時反映說話人數變化、空間幾何、混響與突發噪音的 AVTSE 基準，使得學界難以系統性地評估因果模型在真實場景中的泛化能力，也阻礙了真正可部署之 AVTSE 技術的進展。

**Q4：Falcon 的核心方法架構是什麼？**
A：Falcon 是一種單遍（single-pass）因果式 AVTSE 方法，其核心是 Separator 元件，採用編碼器—解碼器骨幹對音視覺融合特徵進行處理。在單次解碼器遍歷中，Falcon 將頻率軸、時間軸與聯合時頻建模分配到不同層級的解碼區塊，由粗到細地執行多尺度時頻分離，這與 SwiftNet 反覆呼叫同一小型分離器的策略形成對比。透過這種層級分工設計，Falcon 能在單次前向傳遞中同時捕捉跨頻率、跨時間與時頻耦合的干擾結構。

**Q5：Falcon 最關鍵的創新點——編碼器空間說話人對比損失——是如何運作的？**
A：這個損失函式是在分離器的 STFT 編碼器空間中計算的，將編碼後的特徵同時與乾淨目標語音以及每個近場干擾說話人進行對比學習，使目標說話人的編碼特徵在嵌入空間中與干擾者拉開距離。由於這個對比約束作用於編碼器的中間表示而非最終輸出波形，它能在不增加任何推理成本的情況下抑制近場洩漏。更重要的是，作者指出此損失具備跨骨幹網路的可遷移性，可直接套用於其他 AVTSE 架構以提升其抗干擾能力。

**Q6：Falcon 在設計上做了哪些關鍵取捨？**
A：第一個關鍵取捨是放棄了「反覆呼叫小型分離器」的迭代式設計，改採單遍編碼器—解碼器架構搭配層級分工的多尺度分離區塊，以換取更穩定的每幀計算量與更低的推理延遲。第二個取捨是將對比損失放在編碼器空間而非輸出波形層級，這雖然需要仔細設計正負樣本的對應關係，但換來了「零推理成本」的洩漏抑制效果。第三個取捨是將頻率軸、時間軸與聯合時頻建模分別指派給不同解碼層級，使模型能以由粗到細的方式逐步精煉分離結果，而非一次性處理所有時頻結構。

**Q7：論文中使用了哪些基準資料集來評估 Falcon？**

**Q8：Falcon 的關鍵實驗結果為何？**
A：在 RealSSA-Sim、LRS2-2Mix、LRS3-2Mix 與 VoxCeleb2-2Mix 上，Falcon 達到了與最強因果基線（AV-TFGridNet、AV-Mossformer2、SwiftNet、RTFSNet 等）相當或更佳的分離品質。在效率方面，相較於因果式 AV-TFGridNet 基線，Falcon 將參數量削減了 91.9%、計算量降低了 20.2 倍、GPU 推理延遲縮短了 11.1 倍，展現了極高的效率優勢。在 RealSSA-Real 上，Falcon 也取得了具競爭力的感知品質、詞錯誤率（WER）與目標說話人相似度，證實其在真實錄音上仍具實用性。

- **Sim-to-Real 落差**：即便有 RealSSA-Real，模擬資料仍無法涵蓋所有真實麥克風特性。緩解：在自有裝置上做小規模 domain adaptation，並監控 WER 退化幅度。
- **多目標快速切換**：當兩位候選人輪流發言時，因果模型可能延遲切換。緩解：設計視覺切換緩衝（hysteresis）與最小切換間隔。
- **邊緣裝置熱節流**：長時間推論可能觸發降頻，造成延遲抖動。緩解：動態幀率調整或排程到冷卻週期。
- **隱私與合規**：持續擷取臉部影像可能違反 GDPR / 個資法。緩解：裝置端即時丟棄原始影像、僅傳遞唇部 embedding；提供實體鏡頭蓋與指示燈。
- **對比損失的負樣本選擇**：若近場干擾者數量變動劇烈，需動態調整負樣本採樣策略，避免訓練不穩定。
- **單通道假設**：Falcon 預設單麥克風輸入，若產品有多麥克風陣列，需評估是否先以波束成形預處理，否則可能浪費空間資訊。

---

### 與其他技術的整合建議

- **與 ASR 串接**：Falcon 輸出可直接送入 Whisper、Conformer 等串流 ASR；建議在 Falcon 與 ASR 之間插入 VAD 模組，避免 ASR 在靜音段產生幻覺。
- **與多麥克風陣列整合**：若硬體支援，建議先以 MVDR / 線性波束成形做空間濾波，再交給 Falcon 做目標鎖定；Falcon 仍可從中受益於殘餘干擾壓制。
- **與聲紋註冊系統整合**：在多人會議中，可讓使用者預先註冊聲紋 embedding，與視覺線索做 late fusion，提升切換準確率。
- **與會議系統整合**：在 Zoom / Teams / Webex SDK 中以音訊處理外挂形式插入；需注意取樣率（16 kHz 為 Falcon 預設）與 frame size 相容性。
- **與邊緣 AI 框架整合**：可透過 ONNX Runtime、TensorRT、Core ML 等將模型落地；視覺前端建議與音訊前端解耦部署，避免相互阻塞。
- **與說話人日誌（speaker diarization）整合**：Falcon 適合做「給定目標」分離，若需自動決定目標，可先以 diarization 切段，再以 Falcon 逐段提取。
