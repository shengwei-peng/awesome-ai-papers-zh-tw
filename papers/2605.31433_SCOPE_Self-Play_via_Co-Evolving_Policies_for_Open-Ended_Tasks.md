# SCOPE：透過共同演化策略進行開放式任務的自我對弈

## ⚡ TL;DR

現有自我對弈受限於可規則驗證答案，開放式任務仍依賴外部監督。
SCOPE共同演化挑戰者與解題者，以凍結的自我評判生成評分標準並打分。
於八項基準提升達10.4分，超越採用九千筆提示的GRPO_data，並泛化至短問答。

## 摘要翻譯

自我對弈（Self-play）無需外部監督（external supervision）即可訓練語言模型（language models）。然而，現有方法需要可規則驗證的答案（rule-checkable answers），使得開放式任務（open-ended tasks）必須依賴人工策劃提示（curated prompts）或前沿模型評判器（frontier-model judges）。我們提出 SCOPE，一個針對開放式任務的無需資料的自我對弈（data-free self-play）框架，透過共同演化策略（co-evolving policies）同時訓練兩個策略：挑戰者（Challenger）負責生成基於文件的任務（document-grounded tasks），解題者（Solver）則透過多輪檢索（multi-turn retrieval）回答這些任務。初始模型的凍結副本（frozen copy）擔任自我評判（self-judge），根據來源文件（source document）生成任務特定評分標準（task-specific rubrics），並據此對解題者的回應進行評分。在三個 7–8B 指令微調模型（instruction-tuned models）（Qwen2.5、Qwen3、OLMo-3）上，SCOPE 在八項基準測試（benchmarks）中將開放式任務表現提升高達 +10.4 分，並達到或超越以約 9K 人工策劃提示訓練的 GRPO_data。雖然僅以開放式任務進行訓練，SCOPE 仍在七項保留基準測試（held-out benchmarks）中將短形式問答（short-form QA）表現提升高達 +13.8 分，且在三個模型上皆超越 GRPO_data。消融實驗（Ablations）顯示，共同演化挑戰者對於使任務維持在解題者的能力邊界（capability frontier）附近是必要的；增益來自檢索（retrieval）與綜合（synthesis）兩方面的改進，且其相對貢獻隨任務而異；此外，評分標準生成（rubric generation）品質是自我評判的瓶頸（bottleneck）。

### 核心貢獻（3～5點）
- 提出無需外部資料與規則驗證的開放式任務自我對弈框架 SCOPE，透過共同演化策略同時訓練挑戰者與解題者，擺脫對人工策劃提示或前沿模型評判器的依賴。
- 以初始模型的凍結副本擔任自我評判，自動依據來源文件生成任務特定評分標準，為開放式回應提供可解釋的獎勵訊號。
- 在八項基準測試上顯著提升開放式任務表現（最高達 +10.4 分），並達到或超越以約 9K 人工策劃提示訓練的 GRPO_data。
- 僅以開放式任務訓練即可泛化至保留的短形式問答基準測試（最高提升 +13.8 分），展現強大的跨任務遷移能力。
- 消融實驗證實共同演化挑戰者對維持任務難度於解題者能力邊界至關重要，且評分標準生成品質為自我評判的關鍵瓶頸。

### 適合對象
從事大型語言模型後訓練、強化學習與自然語言處理的研究者與工程師，特別是關注自我對弈、開放式生成任務獎勵設計，以及希望降低對人工策劃資料或更強外部評判器依賴的讀者。

## 深度分析

#### 方法論解析

SCOPE（Self-play via Co-Evolving Policies for Open-Ended tasks）的核心貢獻在於將 data-free self-play（無需資料的自我對弈）從僅適用於可規則驗證答案的封閉領域，擴展至 open-ended tasks（開放式任務）。其方法論圍繞三個從同一個 base model（基礎模型）M₀ 初始化的角色展開：Challenger（挑戰者）、Solver（解題者）與 Judge（自我評判）。

**角色分工與資訊不對稱設計**
Challenger policy（挑戰者策略）π_C 與 Solver policy（解題者策略）π_S 在訓練過程中持續更新，而 Judge 則維持為 frozen copy（凍結副本）的 M₀。Challenger 針對來自未標註語料 D 的 source document（來源文件）d，透過 multi-turn retrieval（多輪檢索）生成 document-grounded tasks（基於文件的任務）；Solver 同樣以 multi-turn retrieval-augmented generation（多輪檢索增強生成）回答這些任務，但關鍵在於 Solver 在推理時無法直接取得 d 的完整內容，必須自行檢索證據。Judge 則根據 d 撰寫 task-specific rubrics（任務特定評分標準）G = {(c_k, w_k)}，並對 Solver 的回應進行二元評分，最終彙整為 rubric reward（評分標準獎勵）。這種資訊不對稱（information asymmetry）強迫 Solver 發展有效的 retrieval（檢索）能力，而非僅依賴參數記憶。

**共同演化訓練迴圈**
每一 iteration（迭代）包含兩個階段：
1. **Challenger Training**：Challenger 針對當前 Solver 的能力生成 moderately challenging（適度挑戰性）的任務。其 reward signal（獎勵訊號）來自任務是否落在 Solver 的 capability frontier（能力邊界）上——太簡單或太困難都無法提供有效訓練訊號。
2. **Solver Training**：Solver 在經過 quality gates（品質閘門）篩選的 Challenger-generated tasks 上進行訓練，目標是最大化 Judge 給予的 rubric score 以及 search effectiveness。

兩個策略均採用 GRPO（Group Relative Policy Optimization，群體相對策略最佳化）進行最佳化。GRPO 透過 within-group reward statistics（群體內獎勵統計量）估計 advantage（優勢值），無需額外的 value function（價值函數），這對於開放式任務中稀疏且主觀的獎勵分佈尤為適合。整體 reward（獎勵）為多項加權組合，包含 format reward、difficulty reward、rubric reward 與 search reward 等。

**獎勵駭取防護機制**
作者特別設計了兩項機制防止 reward hacking（獎勵駭取）：quality gates 用於過濾低品質或格式錯誤的 Challenger 輸出；cosine length penalty（餘弦長度懲罰）則抑制 Solver 透過冗長生成操縱評分的行為。Ablation（消融實驗）顯示，這兩項機制各自阻擋了不同型態的 failure mode（失效模式）。

#### 實驗數據解讀

實驗選用三個 7–8B 規模的 instruction-tuned models（指令微調模型）：Qwen2.5-7B、Qwen3-8B 與 OLMo-3-7B，涵蓋八項 open-ended benchmarks（開放式基準測試）與七項 held-out short-form QA benchmarks（保留短形式問答基準測試）。

**開放式任務上的主效能**
在開放式任務中，SCOPE 相較於 base model（基礎模型）帶來顯著提升，其中 Qwen2.5-7B 的進步幅度高達 +10.4 分（24.4 → 34.8）。更具指標意義的是，SCOPE 在完全不使用 curated prompts（人工策劃提示）的情況下，能夠 match or exceed（達到或超越）以約 9K 筆人工策劃提示訓練的 GRPO_data。即使在最強的 Qwen3-8B 上（headroom 最小），SCOPE（43.1）仍優於 GRPO_data（41.5），顯示 self-play（自我對弈）的訓練動態對於已具備強大基礎能力的模型依然有效。

**跨任務型態的遷移與泛化**
最令人驚訝的發現是 SCOPE 的 generalization（泛化）能力：儘管訓練僅針對 open-ended tasks，它在 held-out benchmarks（保留基準測試）的 short-form QA（短形式問答）上最高提升達 +13.8 分，且在三個模型家族上均超越 GRPO_data。這暗示透過 rubric-based self-play（基於評分標準的自我對弈）所習得的能力（如精準檢索與資訊綜合）具有高度可遷移性，而非單純過擬合於特定任務格式。

在 creative writing（創意寫作）——一項完全缺乏 factual grounding（事實基礎）的任務——SCOPE 同樣領先 GRPO_data 最高達 +7.4 分。值得注意的是，GRPO_data 在其中兩個 backbone（骨幹模型）上的表現甚至低於未經訓練的 base model，反映出人工策劃資料可能引入分佈偏移或過度擬合，而 SCOPE 的 data-free（無需資料）機制反而維持了穩健性。

**消融實驗的深層意涵**
Ablation studies（消融研究）揭示了幾項關鍵洞見：
- **Co-evolution（共同演化）的必要性**：若將 Challenger 固定為 frozen Challenger，Solver 的進步在第一個 iteration（迭代）後即停滯。這證實了任務難度必須動態追蹤 Solver 的 capability frontier，否則訓練訊號迅速飽和。
- **雙軌能力增益**：效能提升同時來自 retrieval（檢索）與 synthesis（綜合）的進步，且兩者的 relative contribution（相對貢獻度）隨任務而異。這意味著 SCOPE 並非僅教會模型「找更多資料」，而是同步優化了「如何運用資料生成答案」。
- **自我評判的瓶頸**：實驗指出 rubric generation（評分標準生成）的品質是 self-judging（自我評判）的 bottleneck（瓶頸），而非 grading capacity（評分能力）。換言之，Judge 能正確依據給定的 rubric 打分，但它撰寫的 rubric 本身可能不夠完整或精確，限制了 Solver 的上限。

#### 與現有研究的比較

**定位：填補開放式與無外部監督之間的鴻溝**
如 Table 1 所示，現有研究呈現明顯的兩極分化。一方面，SPICE、Dr.Zero、R-Zero、Abs.Zero 與 OpenSIR 等 self-play（自我對弈）方法實現了 data-free（無需資料）訓練，但其 reward signal（獎勵訊號）依賴 rule-checkable answers（可規則驗證的答案）——包括 string match（字串匹配）、numerical equality（數值相等）或 code execution（程式碼執行）。這將它們限制在具有唯一正確解的封閉領域，無法處理 valid responses（有效回應）多樣的 open-ended tasks（開放式任務）。

另一方面，RaR、DRTulu 等 rubric-based RL（基於評分標準的強化學習）方法雖能處理開放式任務，卻依賴 frontier-model judges（前沿模型評判器）或大量 human-curated prompts（人工策劃提示），本質上仍受外部監督瓶頸所束縛。RPG 雖採用 self-judge（自我評判），但根據作者論述，其仍牽涉 curated prompts 的使用，未能完全解除對外部資料的依賴。

SCOPE 首次同時滿足「open-ended（開放式）」與「data-free（無需資料）」兩項條件，透過 co-evolving policies（共同演化策略）與 frozen Judge 的 rubric generation（評分標準生成），建立了一個無需人類或更強模型介入的封閉訓練迴路。

**相對優勢**
相較於 GRPO_data，SCOPE 不僅省卻了 ~9K 筆 curated prompts 的蒐集與維護成本，更在 short-form QA 與 creative writing 上展現更強的泛化與穩定性。這說明由模型自身產生的訓練訊號，在適當的資訊不對稱設計下，可以超越人工精心設計的靜態資料集。

**侷限性**
儘管 SCOPE 突破了既有框架，仍存在若干限制：
1. **Judge 的能力上限**：Judge 為 frozen copy（凍結副本）的初始模型，其 rubric generation quality（評分標準生成品質）直接決定了 reward signal 的理論上限。若 base model（基礎模型）本身對某類任務的理解有偏誤，此偏誤將在 self-play 迴路中被放大或固化。
2. **文件依賴**：目前的 Challenger 與 Judge 皆需 conditioning on source document（來源文件），對於無法明確指定文件的全開放式創作（如純粹的哲學思辨），其適用性需進一步驗證。
3. **規模驗證**：實驗僅涵蓋 7–8B 模型，尚未驗證於更大規模（如 70B+）或更長訓練週期下的 scaling behavior（規模化行為）。

#### 可重現性評估

根據本文提供的節錄內容，作者並未明確提及是否釋出原始碼（source code）、訓練資料集（datasets）或微調後的模型權重（model weights）。然而，研究採用的基礎模型均為公開可取得之開放權重模型：Qwen2.5-7B、Qwen3-8B 與 OLMo-3-7B，這降低了部分重現門檻。

**有利於重現的要素**
- 方法論層面，SCOPE 僅需一個 unlabelled document corpus（未標註文件語料）D 與初始模型 M₀，無需依賴專有或難以取得的 curated prompts（人工策劃提示）與 frontier-model judges（前沿模型評判器）。
- 演算法核心採用標準 GRPO（Group Relative Policy Optimization，群體相對策略最佳化），其公式與超參數（clip range ϵ、KL regularisation coefficient β 等）在 Background 章節有明確定義。

**潛在的重現障礙**
- 節錄文本在 Stage 1: Train Challenger 處中斷，具體的 quality gates（品質閘門）實作細節、cosine length penalty（餘弦長度懲罰）的計算方式、以及各項 reward components（獎勵元件）的權重 λ_j 並未完整揭露。
- multi-turn retrieval（多輪檢索）的具體工具（是否使用向量資料庫、搜尋 API 或原生生成式檢索）與 prompt template（提示模板）設計亦未詳述。
- 因此，雖然概念上可重現，實務上仍需依賴作者後續釋出實作細節或原始碼，才能確保不同團隊能復現相同的 +10.4 分等量化結果。

#### 未來研究方向

**1. 解決 Rubric Generation 的瓶頸**
既然實驗已確認 rubric generation quality（評分標準生成品質）是 self-judging（自我評判）的主要 bottleneck（瓶頸），未來可探索讓 Judge 進行 lightweight co-evolution（輕量共同演化）——例如以較慢的更新頻率或受限的 KL divergence（KL 散度）範圍微調 Judge，使其 rubric 能隨 Solver 能力成長而精緻化，同時避免與 Solver 共謀產生 reward hacking（獎勵駭取）。

**2. 擴展至非文件導向的開放式任務**
當前 SCOPE 的 Challenger 與 Judge 皆 conditioning on source document（來源文件）。未來可研究如何將框架擴展至無明確文件基礎的任務，例如抽象數學證明、純創意發想或價值觀辯論，可能需要讓 Challenger 在 latent space（潛空間）或知識圖譜上進行「概念檢索」而非文件檢索。

**3. 規模化與收斂性理論分析**
本文僅驗證於 7–8B 模型。未來需在 30B、70B 乃至更大模型上驗證 SCOPE 的 scaling law（規模法則），並探討 open-ended self-play（開放式自我對弈）的收斂條件。理論上，當 Solver 與 Challenger 的能力差距過大或過小時，訓練動態可能崩潰，需要更嚴謹的 difficulty calibration（難度校準）機制。

**4. 整合 Process Reward 與長程規劃**
SCOPE 的 Solver 目前以 multi-turn retrieval（多輪檢索）作為主要行動空間。引入 process reward model（過程獎勵模型）或 Monte Carlo Tree Search（蒙地卡羅樹狀搜尋）來規劃檢索路徑，可能進一步提升 deep research（深度研究）等需要長程資訊整合任務的表現。

**5. 多模態與跨語言延伸**
SCOPE 的原則並不限於文字。將 Challenger-Solver-Judge 架構延伸至視覺-語言任務（如根據圖片生成開放式問題並進行多輪視覺檢索），或是跨語言設定（讓 Challenger 生成低資源語言的任務以提升 Solver 的多語言能力），皆是極具潛力的應用場景。

## 論文問答

**Q1：SCOPE 旨在解決訓練語言模型處理開放式任務時的什麼根本問題？**

A：SCOPE 旨在解決現有自我對弈方法無法應用於開放式任務的核心困境，因為這類任務如深度研究與寫作並不存在唯一正確答案，無法透過基於規則的驗證來產生獎勵訊號。傳統上，這迫使研究者必須依賴人工策劃提示、參考答案或更強大的前沿模型評判器來提供外部監督，進而形成了效能天花板與資源瓶頸。因此，SCOPE 的目標是建立一個無需任何外部資料或更強模型介入的自我對弈框架，使語言模型能夠自主地在開放式領域中持續進步。

**Q2：為何現有的自我對弈方法無法直接應用於開放式任務，而基於評分標準的替代方案又有何限制？**

A：現有的自我對弈方法之所以失效，是因為它們根本性地依賴可規則驗證的答案，例如字串匹配、數值相等或程式碼執行來自動判定正確性並計算獎勵。然而，開放式任務允許多種有效回應，根本不具備可供規則檢驗的唯一解答，因此這類方法在概念上即不適用。雖然 RaR、DRTulu 等基於評分標準的強化學習方法能處理開放式任務，但它們仍須仰賴人工策劃提示或前沿模型評判器，未能擺脫對外部監督的依賴，也就無法突破人類水準或更強模型的限制。

**Q3：為何消除外部監督對於推動語言模型能力超越人類表現至關重要？**

A：消除外部監督至關重要，因為人工策劃的資料本質上會將模型學習上限釘在人類表現水準，使模型難以發現超越人類的超人策略。同時，依賴前沿模型評判器會讓系統陷入對更強大商業模型的持續依賴，不僅成本高昂，也會受制於該模型的能力邊界與存取權限。無需資料的自我對弈讓模型能從自我生成的經驗中學習，這在圍棋與賽局 AI 中已證明能達到超人表現，SCOPE 則將此範式首次擴展到開放式語言任務。

**Q4：SCOPE 包含哪三個核心角色，它們在訓練過程中如何互動？**

A：SCOPE 從同一個基礎模型初始化三個角色：負責生成基於文件任務的挑戰者（Challenger）、透過多輪檢索回答任務的解題者（Solver），以及一個固定不動的評判者（Judge）。挑戰者會針對解題者當前的能力邊界生成適度挑戰性的任務，而評判者則依據解題者看不見的來源文件撰寫任務特定評分標準，並對解題者的回應進行評分。這種資訊不對稱迫使解題者必須透過多輪檢索主動取得資訊，而挑戰者與解題者則透過群體相對策略最佳化（GRPO）根據各自的獎勵訊號持續共同演化。

**Q5：SCOPE 能首次將無需資料的自我對弈擴展到開放式任務的關鍵創新是什麼？**

A：關鍵創新在於使用基礎模型的凍結副本作為自我評判器，使其能夠直接從來源文件動態生成任務特定評分標準，而非仰賴預先撰寫的人工準則或更強的外部模型。這種基於評分標準的自我評判機制為缺乏唯一正確答案的開放式回應提供了可計算的獎勵訊號，從而繞過了對規則驗證的需求。結合挑戰者與解題者的共同演化策略，SCOPE 建立了一個完全自主的訓練迴圈，無需任何人工策劃資料或前沿模型 API 即可運作。

**Q6：為何 SCOPE 選擇共同演化挑戰者策略，而非將其凍結？此外，哪些設計選擇能防止獎勵駭入？**

A：消融實驗顯示，若將挑戰者凍結，其生成的任務難度無法隨著解題者進步而調整，導致訓練在第一次迭代後即停滯不前，因此共同演化是維持任務於解題者能力邊界的必要條件。為了防止獎勵駭入，SCOPE 設置了品質門檻（quality gates）來過濾挑戰者產生的劣質或退化任務，並引入餘弦長度懲罰（cosine length penalty）以避免解題者透過冗長但空洞的回應來操弄評分標準。這兩項機制各自阻擋了不同的失效模式，確保自我對弈迴圈的完整性與學習訊號的真實性。

**Q7：SCOPE 在哪些模型與基準測試上進行評估，涵蓋了哪些類型的任務？**

A：SCOPE 在三個 7–8B 參數的指令微調模型上進行評估，包括 Qwen2.5-7B、Qwen3-8B 與 OLMo-3-7B。評估涵蓋八個開放式基準測試，涉及深度研究、複雜問答與創意寫作等需要檢索與綜合能力的長篇生成任務。此外，研究團隊也在七個保留的短形式問答基準測試上檢驗模型的泛化能力，以確認僅在開放式任務上訓練是否也能提升簡短問答表現。

**Q8：相較於監督式基線，SCOPE 最顯著的量化結果為何？**

A：在八個開放式基準測試上，SCOPE 於 Qwen2.5-7B 取得了高達 +10.4 分的進步，並且在未使用任何人工策劃提示的情況下，整體表現持平或超越了以約 9,000 筆人工策劃提示訓練的 GRPO_data。更令人驚訝的是，儘管 SCOPE 僅在開放式任務上訓練，它在七個保留短形式問答基準測試上仍帶來最高達 +13.8 分的提升，並在三個模型家族上全數勝過 GRPO_data。在創意寫作這項完全無事實依據的任務中，SCOPE 領先 GRPO_data 最高達 +7.4 分，而 GRPO_data 在其中兩個骨幹模型上的表現甚至低於基礎模型。

**Q9：消融實驗揭示了哪些關於效能提升來源與自我評判瓶頸的洞見？**

A：消融實驗證實共同演化挑戰者是絕對必要的，因為一旦將其凍結，訓練成效在首次迭代後便無法持續，這凸顯了動態調整任務難度對於持續自我改進的重要性。實驗也發現效能增益同時來自檢索能力與綜合能力的提升，但兩者的相對貢獻會依任務類型而有所不同。最關鍵的發現是，自我評判的瓶頸不在於評分能力本身，而在於評分標準生成的品質，這意味評判器從來源文件產出準確且完整評分細則的能力，直接決定了整個系統的學習上限。

**Q10：在哪些實際應用場景中，SCOPE 對部署語言模型特別具有價值？**

A：SCOPE 特別適合應用於需要持續精進、且人工訓練資料稀少或昂貴的專業領域，例如企業內部知識庫、法律研究、醫學文獻綜述與學術深度研究工具。這些場景通常擁有大量未標註文件，卻難以負擔大規模人工策劃提示或前沿模型 API 的成本與隱私風險。由於 SCOPE 僅需文件語料庫即可自我訓練，它對於具有嚴格資料隱私要求或處於冷門領域、無法取得強大外部評判器的組織而言，具有極高的實務價值。

**Q11：產品團隊在將 SCOPE 整合進模型訓練流程時，應考量哪些產品層面的因素？**

A：團隊首先必須確保擁有足夠規模且高品質的未標註文件語料庫，作為挑戰者生成任務與評判器撰寫評分標準的基礎。其次，需要建置穩定的多輪檢索增強生成基礎設施，並預留充足的運算資源以支撐挑戰者與解題者之間的反覆共同演化。此外，由於評分標準生成品質是整體瓶頸，產品層面應建立監控機制來偵測自我生成準則是否出現模糊或自相矛盾，並視需求定期以人工偏好校準凍結評判器的輸出一致性。

**Q12：SCOPE 可能如何改變強化學習與自我改進語言模型的研究格局？**

A：SCOPE 將自我對弈的適用範圍從封閉的可規則驗證領域，擴展到佔據絕大多數真實應用的開放式任務，有望降低先進模型後訓練的進入門檻。它證明了無需資料的自我對弈不僅可行，還能勝過數千筆人工策劃提示的訓練效果，這挑戰了「高品質人類監督或前沿模型蒸餾是強化學習必要條件」的既有假設。此成果可能激發新一輪自主自我改進迴圈的研究熱潮，減少對商業 API 的依賴，並使規模較小的研究團隊也能開發出能力持續精進的開放模型。

**Q13：論文坦承 SCOPE 框架存在哪些限制？**

A：論文明確指出評分標準生成的品質是當前框架的根本瓶頸，這意味凍結評判器產出準則的能力直接限制了整體系統的效能天花板。此外，SCOPE 的有效性仰賴於相關文件語料庫的可用性，且其共同演化過程需要仔細調校多項獎勵元件，以避免不同形式的獎勵駭入與訓練不穩定。框架同時也繼承了語言模型強化學習的一般性挑戰，例如在反覆自我對弈迴圈中維持訓練穩定性與避免策略崩潰。

**Q14：SCOPE 防範了哪些失效模式，而當這些防護機制被移除時會發生什麼情況？**

A：SCOPE 透過兩項機制防範獎勵駭入：品質門檻可過濾挑戰者產生的退化或無意義任務，而餘弦長度懲罰則阻止解題者利用冗長回應來操弄基於評分標準的計分。若移除這些防護，挑戰者可能會崩潰為生成過於簡單或格式破碎的任務，導致解題者無法學習；解題者則可能學會產生格式正確但實質空洞的長篇內容，以取巧方式提高評分而非真正提升檢索與推理能力。消融實驗證實這兩項機制各自阻擋了不同的失效模式，缺少任一都會損害自我對弈迴圈的完整性。

**Q15：SCOPE 為開放式任務的無需資料自我對弈指出了哪些未來研究方向？**

A：未來研究可優先聚焦於突破自我評判器的評分標準生成瓶頸，例如透過針對性微調或設計更結構化的準則生成協定，以提升凍結模型產出評分細則的品質與穩定性。另一個重要方向是探索如何降低挑戰者與解題者共同演化的運算成本，使這種無需資料的自我對弈框架能夠應用於更大規模的模型與更長的訓練週期。此外，研究者亦可進一步檢驗在維持評估一致性的前提下，以特定頻率迭代更新評判器權重是否能打破現有天花板，同時避免引入循環偏差或獎勵駭入的風險。

## 實務應用指南

### 適用場景

1. **企業內部知識庫開放式問答**：適合需要從大量內部文件（如法務合約、技術文件、研究報告）中進行深度綜合的場景。SCOPE 無需人工撰寫參考答案或策劃提示，可直接利用未標註的文件庫訓練解題者（Solver）進行多輪檢索與開放式回答。
2. **自動化深度研究助理**：針對需要跨文件比對、彙整多方觀點並生成分析報告的任務。挑戰者（Challenger）可持續生成接近模型能力邊界的文件導向任務，推動模型自主提升檢索與綜合能力。
3. **教育領域的開放式輔導系統**：適用於無標準答案的申論題、案例分析或寫作指導。透過自我評判（Self-judge）動態生成任務特定評分標準（Task-specific rubrics），系統可在無人工逐題批改的情況下持續自我改進。
4. **專業領域文件分析（法律、醫療、金融）**：在涉及複雜推理、需援引多份來源文件且答案非唯一正確的場景中，SCOPE 能透過共同演化策略維持任務難度於解題者的能力前緣，避免訓練數據快速飽和。
5. **內容生成與報告撰寫**：適合需事實根據的長篇內容生成，如市場分析報告或政策評估。模型透過多輪檢索（Multi-turn retrieval）確保生成內容有文件依據，並以評分標準約束回應品質。

### 實作前置條件

**資料需求**：
- 一份未標註的領域文件語料庫（Unlabelled document corpus），作為挑戰者生成任務與解題者檢索的來源。
- 無需人工策劃提示（Curated prompts）、參考答案（Reference answers）或外部評判資料。

**運算資源**：
- 至少一個 7B–8B 指令微調模型（Instruction-tuned model）作為基礎模型（Base model），如 Qwen2.5、Qwen3 或 OLMo-3 等級。
- 支援 GRPO（Group Relative Policy Optimization）訓練的 GPU 叢集。每次迭代需採樣多個 Rollout（論文中為多輪檢索軌跡），記憶體與運算需求顯著高於單純 SFT。
- 向量資料庫與檢索基礎建設，支援解題者的多輪檢索互動。

**技術能力**：
- 熟悉強化學習（Reinforcement learning）與 GRPO 演算法實作。
- 具備檢索增強生成（RAG）管線建置經驗，能整合搜尋工具與語言模型。
- 能設計品質閘門（Quality gates）與獎勵函數（含長度懲罰與格式檢查），以防止獎勵訊號（Reward signal）被破解。

### 實作步驟建議

**步驟一：準備基礎模型與語料**
選定一個 7B 以上的指令微調模型作為初始模型 \(M_0\)，並建置領域文件語料庫 \(D\)。確保文件品質足夠，因為挑戰者與評判者（Judge）都會以這些文件為條件生成任務與評分標準。

**步驟二：初始化三個角色**
從同一個基礎模型 \(M_0\) 出發，初始化挑戰者 \(C\)、解題者 \(S\) 與評判者 \(J\)。其中評判者必須維持為凍結副本（Frozen copy），在整個訓練過程中不更新權重。

**步驟三：建置多輪檢索環境**
為解題者與挑戰者配置多輪檢索（Multi-turn retrieval）能力，通常需整合向量搜尋與重排（Reranking）工具。解題者必須在生成最終答案前，能主動發出多次檢索查詢。

**步驟四：實作挑戰者訓練迴圈**
挑戰者針對抽樣文件生成開放式、基於文件的任務。引入品質閘門過濾低品質任務，並以「任務對當前解題者是否具適度挑戰性（Moderately challenging）」作為獎勵訊號，驅動挑戰者將任務難度維持在解題者的能力邊界（Capability frontier）。

**步驟五：實作解題者訓練迴圈**
解題者針對挑戰者生成的任務進行多輪檢索並產出回應。凍結的評判者依據來源文件撰寫任務特定評分標準（Rubric generation），並對解題者回應進行二元準則評分。解題者的獎勵為加權平均的評分標準分數（Rubric reward），並輔以格式獎勵與餘弦長度懲罰（Cosine length penalty）。

**步驟六：交替共同演化**
嚴格交替執行「訓練挑戰者」與「訓練解題者」。切勿在過程中凍結挑戰者，因為消融實驗（Ablations）顯示凍結挑戰者將導致任務難度無法跟上解題者進步，自我對弈（Self-play）在首次迭代後即停滯。

**步驟七：部署獎勵駭客防禦機制**
監控解題者是否利用格式漏洞或過度冗長獲取高分。確保餘弦長度懲罰與格式獎勵正常運作，這兩者分別防範了不同的獎勵駭客（Reward-hacking）失敗模式。

**步驟八：保留基準測試與迭代驗證**
在獨立的保留基準測試（Held-out benchmarks）上評估開放式任務與短形式問答（Short-form QA）的遷移效果。若評判者生成的評分標準品質不佳，應優先改善提示設計或評判者的初始能力，因為評分標準生成品質是自我評判的瓶頸（Bottleneck）。

### 潛在風險與注意事項

- **獎勵駭客與回應品質劣化**：解題者可能學會操弄評分標準的字面條件，例如產生過長但空洞的回應，或僅滿足格式要求而忽略內容正確性。必須同時啟用品質閘門與餘弦長度懲罰，兩者分別阻擋不同類型的投機行為。
- **評分標準生成為效能天花板**：評判者的評分標準生成（Rubric generation）品質是整體系統的瓶頸，而非評分（Grading）能力。若基礎模型在初始階段撰寫的評分標準過於籠統或偏頗，共同演化將被錯誤訊號牽引。建議在冷啟動階段先驗證凍結評判者產出的評分標準合理性。
- **任務難度漂移與共同演化失效**：若挑戰者未持續更新，生成的任務將迅速落後於解題者的成長曲線，導致訓練訊號消失。實務上必須確保挑戰者與解題者同步更新，維持資訊不對稱：挑戰者與評判者掌握來源文件，而解題者只能透過檢索間接取得。
- **運算成本高昂**：相較於單輪生成，多輪檢索的自我對弈需為每個提示採樣多條 Rollout，並執行多次模型前向傳播與檢索呼叫。在產品化前需評估推論與訓練的總體運算預算。
- **領域覆蓋度不足**：若文件語料庫在特定子領域過於稀疏，挑戰者生成的任務可能重複或偏離目標分佈，進而限制解題者的泛化能力。

### 與其他技術的整合建議

- **向量資料庫與檢索管線**：將 Milvus、Pinecone 或 Weaviate 等向量資料庫整合為解題者的檢索後端，並支援多輪查詢改寫（Query rewriting）。檢索品質直接影響 SCOPE 的最終效能，因為論文顯示增益同時來自檢索（Retrieval）與綜合（Synthesis）的進步。
- **RL 訓練框架**：使用 TRL（Transformer Reinforcement Learning）或 verl 等框架實作 GRPO，利用其內建的群體相對優勢估計與 KL 正則化機制，降低自研訓練迴圈的複雜度。
- **模型服務化（vLLM / TGI）**：在自我對弈的採樣階段，透過 vLLM 或 Text Generation Inference 加速 Rollout 生成，尤其對於需要高吞吐多輪檢索的場景至關重要。
- **外部評判器冷啟動（選用）**：若基礎模型過小導致凍結評判者的評分標準品質不佳，可考慮在最初一至兩個迭代使用更強的前沿模型評判器（Frontier-model judge）產生高品質評分標準，作為教師模型蒸餾至凍結評判者，但後續應回歸完全無外部監督的自我對弈架構以符合資料自由（Data-free）優勢。
- **評估與監控儀表板**：整合 LangSmith、Weights & Biases 或自研儀表板，追蹤每個迭代中挑戰者生成任務的難度分佈、評判者評分標準的詞彙多樣性，以及解題者檢索輪數的變化，以便及早發現訓練失衡。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先聚焦「自我對弈」與「共同演化」的核心概念，理解為何開放式任務（Open-ended tasks）難以用傳統規則驗證（Rule-based verification）解決。可將 SCOPE 想像成一個自己出考題、自己找資料作答、再自己訂評分標準的學習系統，重點在於兩個角色互相追趕，避免題目太簡單或太難。

**給 AI 工程師**：請深入研讀第 3 節的訓練迴圈與圖 1 的架構，特別注意 GRPO 的群體相對優勢計算、多輪檢索的動作空間設計，以及品質閘門與餘弦長度懲罰的實作細節。實作時優先確保挑戰者與解題者的提示模板（Prompt template）能正確區分角色，並驗證凍結評判者在您的領域文件上產出的評分標準是否穩定。

**給研究人員**：本文的消融實驗與瓶頸分析是關鍵貢獻。請仔細檢視「凍結挑戰者」與「共同演化」的比較、檢索與綜合的相對貢獻度，以及評分標準生成品質如何限制自我評判上限。這些結果對於設計下一代無需資料的自我改進演算法具有直接的理論與實務啟發。

**給產品經理**：SCOPE 的核心商業價值在於擺脫對人工策劃提示與前沿模型評判器的依賴，顯著降低開放式任務的資料標註成本。請關注第 4 節的實驗結果：SCOPE 不僅在八項開放式基準測試上擊敗使用約 9K 人工資料的 GRPO_data，還能遷移至未訓練的短形式問答與創意寫作任務。這代表一次訓練投資可同時提升多項產品功能的表現。
