# X-Tree（可複用經驗樹）：將可複用經驗詞元化以實現高效的智能體泛化

**原文標題：** X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization  
**作者：** Sitao Cheng、Xunjian Yin、Zhiyuan Sun 等 7 位作者  
**發布日期：** 2026-09-26  
**HF 連結：** [https://huggingface.co/papers/2609.32993](https://huggingface.co/papers/2609.32993)  
**arXiv：** [https://arxiv.org/abs/2609.32993](https://arxiv.org/abs/2609.32993)  

---

## ⚡ TL;DR

現有智能體訓練將軌跡視為扁平動作流，忽略可複用的子程序階層，導致資料利用不足且泛化受限。
本文提出 X-Tree，以 X-Score 從軌跡中挖掘可複用經驗並層層合併為技能樹，無需 LLM 呼叫。
在三個互動環境與三種模型規模下，X-Tree 於相同資料與預算下提升成功率達 4.5% 以上。

## 摘要翻譯

多步驟智能體（Multi-step Agents）目前以扁平動作流（Flat Action Streams）進行訓練：監督式微調（SFT）與驗證器獎勵強化學習（RLVR）對每個詞元（token）均等加權，忽略了跨任務重複出現的子程序（Sub-procedures），也忽略了讓人類得以從可複用例行程式（Reusable Routines）自上而下（Top-down）規劃的階層結構（Hierarchy）。此結構未被利用，扁平訓練也未能充分運用每條稀缺軌跡（Scarce Trajectory）所蘊含的內容。近期智能體雖也會利用此結構，但僅將其作為由大型語言模型撰寫的技能（LLM-written Skills）、置於上下文中的技能，從未納入模型權重（Weights），因此其效益僅止於檢索（Retrieval），無法真正泛化（Generalization）。我們則直接從資料本身復原此階層結構並加以訓練，過程中無需呼叫大型語言模型（LLM）。借鏡文字詞元化器（Text Tokenizers）僅靠計數建立詞彙表的做法，我們依據可複用性（Reusability）為動作片段（Action Spans）評分，並將正規化動作（Canonicalized Actions）合併為可複用的經驗樹（Experience Tree），即 X-Tree。每個 X-Tree 節點（Node）捕捉一個頻繁出現且帶有成功訊號的技能（Success-bearing Skill）如何由子技能（Sub-skills）組成，從而引導高效的泛化。我們將 X-Tree 整合至三種訓練設定：離線強化學習（Offline RL），以每個節點作為一筆訓練樣本（Training Instance）；線上 RLVR（Online RLVR），搭配適應性技能獎勵（Adaptive Skill Bonus）；以及同策略自我蒸餾（On-policy Self-distillation, OPSD），以 X-Tree 作為自我教師（Self-teacher）的特權上下文（Privileged Context）。在 WebArena、ScienceWorld 與 WebShop 三個環境、三種模型規模（Model Scale）下，X-Tree 在資料與預算對等（Matched Data and Budget）的條件下相較於標準做法，於 WebArena 最多提升 4.5% 成功率（Success Rate, SR）、於 ScienceWorld 最多提升 5.8% SR，並於 WebShop 最多提升 4.1% 的成功率。對照分析（Matched Analyses）顯示，這些增益可歸因於 X-Tree 結構本身以及上述三種整合方式。

### 核心貢獻（3～5點）
- 提出 X-Tree（可複用經驗樹）：一種僅從資料中自動復原動作階層結構的方法，無需 LLM 參與，即可將可複用經驗（Reusable Experience）編碼為樹狀結構。
- 借鏡文字詞元化器的合併機制，依據可複用性（Reusability）將正規化動作（Canonicalized Actions）合併為帶有成功訊號的技能（Success-bearing Skills），並以子技能（Sub-skills）組成更高層技能。
- 將 X-Tree 整合至三種訓練典範：離線強化學習（Offline RL，每個節點為一筆訓練樣本）、線上 RLVR（Online RLVR，搭配適應性技能獎勵）以及同策略自我蒸餾（OPSD，以 X-Tree 作為自我教師的特權上下文）。
- 在 WebArena、ScienceWorld 與 WebShop 三個互動環境、三種模型規模下，於資料與預算對等的條件下顯著提升成功率，並透過對照分析驗證增益來自 X-Tree 結構與三種整合方式。

### 適合對象
本論文適合對大型語言模型智能體（LLM Agents）、強化學習（Reinforcement Learning）、離線強化學習、自我蒸餾與可複用技能學習有興趣的研究者與工程師；特別是關注如何從有限軌跡資料中自動發現結構化知識、提升多步驟決策模型泛化能力，以及希望將結構化經驗真正學入模型權重而非僅作為提示詞的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心動機：從扁平動作流（flat action streams）中挖掘可複用經驗（reusable experience）

本文指出，現有多步驟智能體（multi-step agents）的訓練通常將軌跡（trajectory）視為扁平動作流（flat action streams），無論是監督式微調（SFT）還是驗證器獎勵強化學習（RLVR），都對每個 token 均等加權（equal weighting）。這種做法忽略了跨任務反覆出現的子程序（sub-procedures）或例行程式（reusable routines），例如「瀏覽並選擇」（browse-and-select）或「撿起並移動」（pick-up-and-move）。這些子程序本質上構成了一種階層結構（hierarchy），能讓智能體像人類一樣自上而下（top-down）地從目標（goal）分解到子目標（sub-goals）再到原始動作（primitives）。然而，現有方法並未將這種結構納入模型權重（weights），導致每條稀缺軌跡（scarce trajectory）的資訊利用不足。

為了解決這個問題，作者提出將「經驗」視為一種需要被 token 化（tokenizing）的語言：就像文字 tokenizer 透過統計共現性將字元合併成詞彙單元，X-Tree 透過統計動作序列中的重複模式，將可複用經驗（reusable experience）組合成一個確定性、可審計的階層樹狀結構。

##### 2. X-Tree 的建構流程

X-Tree 的建構包含三個主要步驟：

**（1）動作正規化（canonicalized actions）**

每個動作步驟被轉換為一個類型化 token，形式為 `verb<role>`。這種正規化動作（canonicalized actions）能將語義等價但表面形式不同的動作統一表示，例如不同日期輸入框的填寫動作都可以被歸類為同一種「填入」類型。這是後續統計重複性的基礎。

**（2）X-Score：可複用性評分（reusability scoring）**

作者提出 X-Score，用於衡量一個動作片段（action spans）的可複用性（reusability）。該分數綜合考慮三個因素：

- **Recurrence（重複出現頻率）**：該動作片段在資料集中出現的次數；
- **Length（長度）**：片段越長，代表其捕捉到的行為結構越豐富；
- **Success weights（成功權重）**：片段出現在成功軌跡中的比例。

透過這三個維度，X-Score 能夠篩選出既頻繁出現、又能導致任務成功的技能（success-bearing skill）。

**（3）階層式合併（hierarchical merging）**

受到 Byte-Pair-Encoding（BPE）等文字 token 化方法的啟發，X-Tree 從最底層的原始動作（primitives）開始，根據 X-Score 反覆合併相鄰的動作對，形成更高層次的節點（node）。每個節點代表一個可複用的技能（skill），並由多個子技能（sub-skills）組成。這個過程完全基於資料統計，**不需要任何大型語言模型（LLM）呼叫**，因此具有確定性與可重現性。

最終產生的 X-Tree（可複用經驗樹）是一個有向樹狀結構，每個節點都捕捉了一個頻繁且成功導向的行為單元，以及它如何由更細粒度的子單元組合而成。

##### 3. X-Tree 的三種訓練整合方式

作者將 X-Tree 整合到三種不同的訓練設定中：

**（1）作為資料：離線強化學習（Offline RL）**

當只有靜態軌跡資料、沒有互動環境時，每個 X-Tree 節點（node）被視為一個訓練樣本（training instance）。具體而言，策略模型會從該節點之前的黃金前綴（gold prefix）開始部分展開（partial rollout），並使用 GRPO 進行最佳化，獎勵函數包含動作匹配獎勵（step-matching reward）以及依節點深度縮放的完成獎勵（depth-scaled completion bonus）。這種方式讓模型學習「在什麼情境下應該執行哪個可複用技能」。

**（2）作為獎勵：線上 RLVR（Online RLVR）**

當環境與驗證器（verifier）可用時，X-Tree 提供適應性技能獎勵（adaptive skill bonus）。每當智能體在 rollout 中執行到某個 X-Tree 技能時，就會獲得額外獎勵。該獎勵的權重會動態調整：在訓練早期，驗證器訊號（verifier signal）稀疏時，技能獎勵提供較強的引導；隨著訓練進行、驗證器訊號變得更可靠時，技能獎勵的權重會自動降低。這種設計避免了過早依賴稀疏的最終結果獎勵。

**（3）作為上下文：同策略自我蒸餾（OPSD）**

在同策略自我蒸餾（on-policy self-distillation, OPSD）中，X-Tree 取代了原本由 LLM 撰寫的技能庫，成為自我教師（self-teacher）的特權上下文（privileged context）。自我教師可以讀取 X-Tree 中的階層結構，並據此重新加權學習者模型自身的 token。這種整合的關鍵優勢在於：它不再需要昂貴且不穩定的 LLM 抽象步驟，同時將可複用結構真正帶入訓練過程。

#### 實驗數據解讀

##### 1. 實驗設定概覽

論文在三個互動環境與三個模型規模（model scale）上進行評估：

- **WebArena**：網頁互動基準測試環境，評估真實網站操作能力；
- **ScienceWorld**：科學推理互動環境基準，評估長程規劃與實驗操作；
- **WebShop**：線上購物互動環境基準，評估多輪對話與商品搜尋能力。

模型方面使用了 Qwen2.5-7B 等至少三個不同規模的模型。所有比較都在「相同資料量與相同運算預算」（matched data and budget）下進行，這使得實驗結果具有較高的公平性與說服力。

##### 2. 主要結果

**離線強化學習（Offline RL）**

在 WebArena 上，使用 X-Tree 的離線 RL 相較於完整資料的 SFT，成功率（Success Rate, SR）提升了 **4.5%**。這顯示即使在沒有環境互動的情況下，僅透過將 X-Tree 節點作為訓練樣本，就能比傳統的扁平監督式微調更有效地利用軌跡資料。

**線上 RLVR（Online RLVR）**

在 ScienceWorld 上，X-Tree 輔助的線上 RLVR 在所有模型規模上都優於僅使用結果導向獎勵的 RL，最高提升達 **4.9% SR**，並且在保留任務（held-out tasks）上表現最佳。這說明適應性技能獎勵（adaptive skill bonus）能夠在長程、稀疏獎勵的環境中提供穩定的中間訊號。

在 WebShop 上，X-Tree 線上 RLVR 相較於標準配方（standard recipe）最高提升 **3.6% 成功率** 與 **4.6% 分級分數（graded score）**。這表示 X-Tree 不僅能提高任務完成率，也能改善完成品質。

**同策略自我蒸餾（OPSD）**

在 ScienceWorld 與 WebShop 上，X-Tree 作為自我教師（self-teacher）的特權上下文（privileged context），其表現與使用 LLM 撰寫技能庫的 OPSD 相當，但**完全不需要 LLM 呼叫**。這在運算成本與可重現性方面具有顯著優勢。

##### 3. 消融實驗與歸因分析

論文進行了對照分析（matched analyses），包括隨機樹（random tree）等消融實驗。結果顯示，效能提升主要來自於：

1. **X-Tree 的結構本身**：隨機樹無法達到相同效果，證明並非任何階層結構都有效，而是必須基於可複用性（reusability）與成功訊號（success-bearing）來建構；
2. **三種整合方式各自的貢獻**：無論是作為資料、獎勵或上下文，X-Tree 都能在不同訓練設定中帶來穩定增益。

這些消融結果強化了論文的核心主張：將可複用經驗（reusable experience）的階層結構學進模型權重（weights），是提升樣本效率與泛化能力（generalization）的關鍵。

#### 與現有研究的比較

##### 1. 相較於扁平訓練（Flat Training）

傳統的 SFT 與 RLVR 將軌跡（trajectory）視為扁平動作流（flat action streams），對每個 token 均等加權（equal weighting）。這種方法雖然簡單直接，但無法區分「關鍵子程序」與「一次性動作」，導致樣本效率低下。X-Tree 透過識別並強化可複用技能（reusable skills），讓模型從有限資料中學到更具泛化性的結構。

##### 2. 相較於 LLM 撰寫技能（LLM-written Skills）

近期研究如 OpenClaw 等系統使用 LLM 將過去經驗總結為自然語言工作流程（natural-language workflows），並在推論時將其放入提示詞（prompt）中。然而，這類方法有幾個缺點：

- **無法泛化至檢索之外（no generalization beyond retrieval）**：技能僅存在於上下文，未被壓縮進模型權重；
- **成本高昂**：每次都需要呼叫強大的 LLM 進行抽象；
- **不可控且不可重現**：LLM 產生的技能庫難以複製，且品質不穩定。

X-Tree 完全取代 LLM 抽象步驟，以確定性統計方法從資料中挖掘階層結構，並將其真正用於訓練。

##### 3. 相較於同策略自我蒸餾（OPSD）中的 LLM 技能庫

OPSD 本身已經將技能帶入訓練過程，透過自我教師（self-teacher）讀取技能並重新加權學習者 token。但現有 OPSD 依賴 LLM 撰寫技能庫。X-Tree 的貢獻在於提供了一個無需 LLM 呼叫、可從資料單獨重建的替代技能庫，並在實驗中達到與 LLM 技能庫相當的表現。

##### 4. 相較於階層式強化學習（Hierarchical RL / Options）

認知科學與強化學習領域長期研究從示範中分割軌跡為選項（options）或子策略（sub-policies）。X-Tree 與這些工作的差異在於：

- 它不學習額外的子策略網路，而是將階層結構作為訓練訊號（資料、獎勵、上下文）注入現有訓練流程；
- 它強調「可複用性」與「成功導向」的雙重篩選，而非僅僅基於狀態轉移或時間邊界進行分割；
- 它專注於離散、符號化的動作空間（如網頁操作），並透過正規化動作（canonicalized actions）處理語義等價性。

##### 5. 相較於壓縮與程式庫學習（Compression & Library Learning）

文法推導（grammar induction）、字典壓縮（dictionary compression）與程式庫學習（library learning）都試圖從序列中找出可複用結構。機器人領域也有將連續動作 token 化（tokenizing）的做法。最接近的是 PRISE 與 Subwords-as-Skills，它們將 BPE 應用於量化後的連續控制動作。

X-Tree 的區別在於：

- 它處理的是具有語義結構的離散動作（如 `click<Apply>`、`fill<date_from>`），而非純數值動作；
- 它明確引入成功訊號（success weights）作為合併準則，使樹中的每個節點都帶有任務導向的語義；
- 它將樹結構應用於三種不同的訓練範式，而不僅是動作表示學習。

##### 6. 限制與待釐清之處

儘管 X-Tree 在多個基準上表現優異，仍有幾點需要注意：

- **正規化品質依賴領域知識**：`verb<role>` 的正規化方式需要針對不同環境設計，對於動作空間複雜或觀察為原始像素/多模態的環境，正規化可能較困難；
- **樹的深度與粒度需要調校**：過深的樹可能導致過度特化，過淺則無法捕捉有意義的子程序；
- **目前主要針對成功軌跡**：雖然 X-Score 考慮成功權重，但對於失敗軌跡中潛在的有用片段（例如「幾乎成功」的路徑）利用較少；
- **缺乏與 LLM 抽象結合的探討**：雖然論文強調無需 LLM，但在某些複雜語義抽象場景，純統計方法可能不如 LLM 靈活。

#### 可重現性評估

##### 1. 方法論層面的可重現性優勢

X-Tree 的一個重要優勢是其建構過程完全基於資料統計，**零 LLM 呼叫（zero LLM calls）**。這意味著：

- 給定相同的軌跡資料集與正規化規則，任何研究者都能重建出相同的 X-Tree；
- 不依賴專有 API 或特定 LLM 的行為，降低了再現門檻；
- 樹結構本身可作為審計對象，研究者可以檢視每個節點（node）代表的子技能（sub-skills）及其組成。

##### 2. 目前資訊的不足

然而，根據目前提供的論文內容，**尚未看到明確的開源程式碼、資料集或模型權重連結**。論文處於 preprint 階段，實驗細節如：

- X-Score 的確切數學公式與超參數；
- 正規化動作（canonicalized actions）的完整規則；
- GRPO 的群組大小、學習率、獎勵縮放係數；
- X-Tree 合併的停止條件與深度限制；

這些細節對於完全重現結果至關重要，但在摘要與引言中尚未完整揭露。

##### 3. 對重現的建議

若作者未來釋出原始碼，建議至少包含：

- X-Tree 建構管線的完整實作；
- 三個環境（WebArena、ScienceWorld、WebShop）的資料前處理腳本；
- 三種訓練整合（offline RL、online RLVR、OPSD）的訓練配置；
- 預訓練或微調後的檢查點（checkpoints），以便進行直接比較。

在這些資源釋出前，X-Tree 的可重現性仍屬於「概念上高度可重現，但實務上需要更多細節」的階段。

#### 未來研究方向

##### 1. 擴展至連續與多模態動作空間

目前 X-Tree 主要針對離散、符號化動作（如網頁操作指令）。未來可探索將其擴展至連續控制（continuous control）或多模態觀察（multimodal observations），例如結合向量量化（vector quantization）技術，將連續動作離散化後再進行 X-Tree 建構。

##### 2. 動態更新與終身學習（Lifelong Learning）

現有 X-Tree 似乎是從靜態軌跡資料集中一次性建構。未來可研究如何在線上互動過程中動態更新 X-Tree，隨著智能體探索新環境而不斷擴充可複用技能庫，實現終身學習。

##### 3. 與 LLM 抽象能力的混合架構

雖然 X-Tree 強調無需 LLM，但未來可探討「統計挖掘 + LLM 精煉」的混合模式：先由 X-Tree 找出高頻成功模式，再由小型 LLM 為這些模式生成可解釋的自然語言描述，兼顧效率與語義豐富性。

##### 4. 理論分析：為何階層結構能提升泛化？

目前論文主要透過實驗驗證 X-Tree 的有效性。未來可從理論角度分析：在什麼條件下，基於可複用性的階層訓練能夠降低樣本複雜度？它與程式歸納（program induction）、貝葉斯非參數方法（Bayesian non-parametrics）之間有何聯繫？

##### 5. 跨領域遷移與組合泛化

X-Tree 中的每個節點代表一個可複用技能，這使其天然適合跨任務遷移。未來可研究如何將在一個環境（如 WebShop）中學到的 X-Tree 節點遷移到另一個環境（如 WebArena），或如何透過組合現有子技能（sub-skills）來解決全新任務。

##### 6. 結合樹狀推理（Tree-of-Thought / Hierarchical Planning）

X-Tree 提供了行為的階層結構，但未來可進一步讓模型在推論時主動「規劃」要使用哪些節點，例如結合樹狀推理（tree-of-thought）或階層式規劃（hierarchical planning），讓智能體不僅學到技能，還能靈活組合技能以應對複雜目標。

##### 7. 改進 X-Score 以納入更多訊號

目前的 X-Score 主要考慮頻率、長度與成功率。未來可納入更多訊號，例如：

- 動作片段的語義一致性；
- 與環境狀態轉移的因果關係；
- 人類標註或偏好（human preference）；
- 失敗軌跡中的「接近成功」訊號。

這將使 X-Tree 更能捕捉細緻且穩健的可複用行為模式。

## 論文問答

**Q1：X-Tree 主要想解決什麼問題？**
A：現有的多步驟智能體（multi-step agents）通常把整段軌跡（trajectory）當成扁平的動作流（flat action stream）來訓練，無論是 SFT 還是 RLVR，都對每個 token 一視同仁地加權。這種均等加權忽略了跨任務反覆出現的子程序（sub-procedures）與階層結構（hierarchy），例如「瀏覽並選擇」或「拿起並移動」等可複用例行程式。由於經驗資料取得成本高且稀缺，未能充分利用這些結構會讓訓練效率低落，也需要更多資料才能學會泛化。

**Q2：為什麼現有利用 LLM 撰寫技能的方法無法真正泛化？**
A：近期方法如 OpenClaw 等會請大型語言模型把過去經驗總結成自然語言工作流程，並在推論時把它們放進提示詞（prompt）中當作技能使用。然而這些技能從未被壓縮進模型權重（weights），因此它們的效益僅限於檢索（retrieval）到的情境，無法在權重中形成可泛化的行為。此外，這種做法依賴昂貴、不可控且無法單從資料重現的 LLM 抽象步驟，難以大規模應用。

**Q3：為什麼利用可複用經驗的階層結構對智能體學習很重要？**
A：認知科學早已指出，人類會自發把行為重編碼成可複用的階層結構，並從目標透過子目標（sub-goals）再落實到原始動作（primitives）。這種階層結構其實已經潛藏在收集到的軌跡資料中，只是傳統訓練目標沒有使用它。若能從資料中恢復並訓練這些結構，就能從有限的軌跡中榨取更多訊號，減少資料需求並提升對新任務的泛化能力。

**Q4：X-Tree 的核心方法是什麼？**
A：X-Tree 把「經驗 token 化」：首先把每個動作步驟正規化（canonicalize）成帶類型的 token（例如 verb<role>），接著提出 X-Score 來衡量動作片段（action spans）的可複用性。根據出現頻率、長度與成功訊號，反覆把相鄰的高分片段合併成節點（node），最終形成一棵可複用經驗樹（X-Tree）。整個過程完全由資料統計驅動，不需要任何 LLM 呼叫，且具有確定性與可稽核性。

**Q5：X-Score 如何引導 X-Tree 的建構？**
A：X-Score 同時考量三個因素：某段動作序列在不同任務中重複出現的頻率、序列的長度，以及它出現在成功軌跡中的比例。分數高的片段會被優先合併成節點，並再與其他節點繼續組合成更高層的技能。這樣每個 X-Tree 節點都代表一個既頻繁出現又帶有成功訊號的技能（success-bearing skill），並且清楚記錄它由哪些子技能（sub-skills）組成。

**Q6：X-Tree 與三種訓練設定是如何整合的？**
A：第一，在離線強化學習（offline RL）中，每個 X-Tree 節點都是一筆訓練樣本，策略會從節點前的黃金前綴部分展開，並以步驟匹配獎勵與深度縮放的完成獎勵進行 GRPO 訓練。第二，在線上 RLVR（online RLVR）中，X-Tree 會對執行到的技能給予適應性獎勵（adaptive skill bonus），在驗證器訊號稀少時提供額外梯度，訊號充足時則自動降低權重。第三，在同策略自我蒸餾（OPSD）中，X-Tree 取代 LLM 撰寫的技能庫，成為自我教師（self-teacher）的特權上下文（privileged context）。

**Q7：實驗在哪些環境與模型規模上進行？**
A：實驗橫跨 WebArena、ScienceWorld 與 WebShop 三個互動式基準測試環境，並在三種模型規模下進行。所有比較都在相同的資料量與運算預算（matched data and budget）下進行，以確保結果公平。例如文中特別提到在 WebArena 上使用 Qwen2.5-7B 進行離線 RL 實驗，並與完整資料的 SFT 進行比較。

**Q8：X-Tree 帶來了哪些關鍵量化結果？**
A：在離線 RL 設定下，X-Tree 在 WebArena 上比完整資料 SFT 提升了最多 4.5% 的成功率（SR）。在線上 RLVR 設定下，於 ScienceWorld 上最多提升 5.8% SR（部分比較中相對 outcome-based RL 提升達 4.9% SR），並在 WebShop 上穩定超越標準配方最多 3.6% 成功率與 4.6% 分級分數。在 OPSD 設定中，X-Tree 作為自我教師的特權上下文，表現與 LLM 撰寫的技能相當，但完全不需要 LLM 呼叫。

**Q9：消融實驗與對照分析說明了什麼？**
A：作者進行了隨機樹（random tree）等消融實驗，結果顯示性能提升確實來自 X-Tree 的結構本身，而非單純的額外訓練訊號或離線 RL 方法。匹配資料與預算的對照分析進一步把增益歸因於 X-Tree 的階層結構以及三種不同的整合方式。這些分析確認了無論是作為資料、獎勵或上下文，X-Tree 都能穩定且有意義地改善訓練效果。

**Q10：X-Tree 在哪些實際場景特別有用？**
A：X-Tree 特別適合軌跡資料昂貴或稀缺的場景，例如網頁自動化（WebArena）、科學推理互動（ScienceWorld）以及線上購物任務（WebShop）。當只有靜態軌跡而沒有互動環境時，離線 RL 整合能直接利用 X-Tree 節點進行訓練。當環境與驗證器存在但早期訊號稀疏時，線上 RLVR 的適應性技能獎勵能提供穩定學習訊號。

**Q11：若要把 X-Tree 落地到產品中，需要考慮哪些因素？**
A：首先，X-Tree 的建構完全不需要 LLM 呼叫，這大幅降低了部署成本並提升了可重現性，適合需要稽核的企業流程。其次，動作的正規化（canonicalization）與 X-Score 的閾值需要隨領域調整，以確保合併出的節點確實對應有意義的技能。最後，當新資料持續進來時，需要設計更新機制來維護或重新生成 X-Tree，讓技能庫隨經驗演進。

**Q12：X-Tree 對整個智能體研究領域可能帶來什麼影響？**
A：X-Tree 把「技能抽象」從過去依賴 LLM 撰寫提示詞的做法，轉向從資料中自動挖掘並學進模型權重。這銜接了階層式行為學習（hierarchy learning）與現代語言模型智能體訓練，並展示了類文字 token 化（tokenization）概念對動作經驗的適用性。未來可能啟發更多將資料驅動壓縮、可複用結構與強化學習結合的研究方向。

**Q13：X-Tree 有哪些已知的限制？**
A：X-Tree 的品質高度依賴正規化規則能否正確捕捉語義等價的動作，若規則設計不當，可能把本質相同的行為拆成不同 token。此外，它需要足夠的資料頻率與成功標籤才能形成有意義的節點，對於罕見或長尾任務可能覆蓋不足。最後，節點深度、合併次數與各整合方式的超參數仍需針對不同環境進行調校。

**Q14：X-Tree 可能在什麼情況下表現不佳或失敗？**
A：如果資料中成功軌跡的分布有偏，X-Score 可能會把某些常見但非最優的動作序列誤認為高價值技能。過度合併也可能產生過於籠統或語義不連貫的節點，導致策略學到錯誤的抽象。另外，當環境動作空間高度連續或觀測包含大量多模態訊號時，單純的離散動作正規化可能無法充分表達行為結構。

**Q15：未來可以朝哪些方向延伸 X-Tree？**
A：未來可以將 X-Tree 擴展到連續動作空間或多模態觀測，例如結合向量量化（vector quantization）來處理機器人或視覺導航任務。也可以探索讓 X-Tree 在部署過程中線上更新，隨著智能體與環境互動不斷精煉技能階層。此外，結合 LLM 進行語義驗證或命名，同時保留資料驅動的核心建構流程，也是一個值得研究的混合方向。

## 實務應用指南

### 適用場景

1. **企業流程自動化（RPA / 網頁代理）**  
   在 ERP、CRM、HR 或財務系統間執行重複性任務時，X-Tree 可從現有操作軌跡中挖掘「登入 → 搜尋 → 篩選日期 → 下載報表」等可複用子程序，並將其學進模型權重，減少對大量人工標註軌跡的依賴。

2. **客戶服務與 IT 維運代理**  
   面對需要多步驟排查的工單（例如重設密碼、診斷網路問題、開立雲端資源），X-Tree 能把常見的成功診斷流程建成階層，並在線上 RLVR 中透過適應性技能獎勵加速學習，讓代理更快收斂到可解決問題的策略。

3. **科學實驗與數據分析助理**  
   在需要重複執行實驗協定的環境（如試管操作、資料清理、特徵工程）中，X-Tree 可捕捉「取樣 → 過濾 → 執行測試 → 記錄結果」等帶有成功訊號的技能，協助模型在新任務中自上而下組合既有子技能。

4. **電商與旅遊預訂助理**  
   類似 WebShop 的場景中，代理需要反覆執行「搜尋商品 → 比較規格 → 加入購物車 → 套用優惠碼 → 結帳」等例行程式。X-Tree 能把這些成功路徑 token 化為可複用經驗，提升對新商品類別或新網站的泛化能力。

5. **軟體開發代理（Issue 解決 / DevOps）**  
   從現有 issue 修復軌跡中挖掘「重現問題 → 定位檔案 → 修改程式碼 → 執行測試 → 提交 PR」等結構，離線 RL 可直接以 X-Tree 節點為訓練樣本，讓小型模型在有限資料下學會可遷移的開發例程。

### 實作前置條件

**資料**
- 高品質的軌跡語料：包含動作序列、任務指令、觀測（可選）以及成功／失敗標籤。
- 正規化動作格式：建議統一為 `verb<role>` 或類似的 typed token，讓語義等價的動作能被合併。
- 足夠的樣本量：需能支撐可複用性的統計顯著性，通常數百到數千條成功軌跡起步，視環境複雜度而定。
- 驗證器（Verifier）：線上 RLVR 需要可信賴的任務完成判斷；離線 RL 則至少需要軌跡結局標籤。

**運算**
- 模型訓練：至少一張高階 GPU（如 A100 / H100），依模型規模（7B–14B）調整。
- X-Tree 挖掘：主要為 CPU 密集的字串／計數操作，需要足夠記憶體存放共現表與階層樹。
- 環境互動（線上設定）：需要可批次執行、可重現的模擬環境或沙箱。

**技能**
- 熟悉 SFT、RL（GRPO / PPO）與 RLVR 訓練流程。
- 能為目標環境設計動作空間與正規化規則。
- 具備評估基礎建設：成功率（SR）、graded score、held-out task 切分。
- 有能力審查與維護挖掘出的技能樹，避免錯誤合併。

### 實作步驟建議

1. **收集並正規化軌跡**  
   在現有系統或模擬環境中記錄代理動作，將語義等價的步驟統一為 typed token（例如 `click<Apply>`、`fill<date_from>`）。同時記錄每條軌跡是否成功，作為 X-Score 的成功訊號。

2. **挖掘 X-Tree**  
   計算每個動作片段的 X-Score（綜合出現頻率、長度與成功率），依分數反覆合併相鄰片段，建立由原始動作到複合技能的階層樹。過程中設定最小支持度與最低成功率門檻，剔除雜訊節點。

3. **選擇整合模式**  
   - 只有靜態資料 → **離線強化學習**：每個 X-Tree 節點作為一筆訓練樣本，搭配黃金前綴與深度縮放的完成獎勵。  
   - 有環境與驗證器 → **線上 RLVR**：在原本 outcome reward 外，加入 X-Tree 適應性技能獎勵。  
   - 已有 OPSD 流程 → **同策略自我蒸餾**：以 X-Tree 取代 LLM 撰寫的技能庫，作為自我教師的特權上下文。

4. **調整訓練目標與資料載入**  
   根據所選模式修改 loss / reward function：離線 RL 需設計 step-matching reward 與 completion bonus；線上 RLVR 需實作 adaptive skill bonus 的衰減機制；OPSD 需將 X-Tree 節點序列注入自我教師的上下文。

5. **對照實驗與消融**  
   在相同資料量與運算預算下，與標準 SFT / RLVR / OPSD 比較。建議加入隨機樹（random tree）或扁平動作流基線，確認增益來自 X-Tree 結構本身，而非額外資料或參數。

6. **部署與持續更新**  
   上線後記錄代理實際執行的技能路徑，定期將新軌跡回饋至 X-Tree 挖掘流程，重新生成樹並微調模型，以應對環境變化與新任務型態。

### 潛在風險與注意事項

- **正規化錯誤導致偽技能**  
  若動作語義未被正確統一，X-Tree 可能合併出無意義的「技能」。建議對高頻節點進行人工抽樣審查，並保留可解釋的動作 schema。

- **資料稀缺造成過擬合**  
  軌跡不足時，挖掘出的節點可能只反映少數任務。可透過提高最小支持度、交叉驗證節點泛化性，或結合資料增強來緩解。

- **線上 RLVR 的獎勵作弊（Reward Hacking）**  
  適應性技能獎勵雖會隨驗證器訊號增強而降低權重，但仍建議設定獎勵上限，並監控「執行技能」與「任務成功」的相關性，避免代理只為湊技能而偏離目標。

- **技能樹過時**  
  網頁介面、API 或任務定義會變動，X-Tree 需定期重新挖掘。建議建立自動化排程，並在環境重大改版後強制重建。

- **語義等價但語法不同的動作無法合併**  
  X-Tree 是基於正規化動作的統計方法，對於需要深層語義理解才能對齊的步驟可能不足。可選擇性引入輕量語義聚類，或保留 LLM 作為輔助審查工具，但核心挖掘仍保持零 LLM 呼叫。

---

### 與其他技術的整合建議

- **與 RAG 結合**  
  將 X-Tree 學進權重負責「可複用例行程式」的泛化，同時保留檢索系統提供少樣本示例或最新文件，形成「權重 + 上下文」的雙軌能力。

- **與 LLM 規劃器結合**  
  由大型語言模型產生高階任務計畫，X-Tree 提供經過資料驗證、可執行的低階子技能，降低對昂貴 LLM 呼叫的依賴並提升執行穩定性。

- **接入現有 RL 框架**  
  X-Tree 可透過自訂 reward function 與 data collator 整合至 TRL、verl 等框架；離線 RL 的節點樣本可視為特殊化的 trajectory chunk。

- **作為課程學習（Curriculum Learning）來源**  
  先以淺層、高頻的 X-Tree 節點訓練，再逐步引入深層複合技能，幫助模型穩定學習長程規劃。

- **與觀測 grounded 技術搭配**  
  結合網頁 DOM、無障礙樹（accessibility tree）或截圖特徵，讓正規化動作更貼近真實介面元素，進一步提升 X-Tree 的實用性。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先聚焦圖 1 的直覺：X-Tree 就像文字處理中的 BPE tokenizer，只不過它把「動作序列」切分成可重複使用的技能區塊。重點理解「扁平動作流」與「階層結構」的差別，以及為什麼把可複用經驗學進模型權重能幫助代理面對新任務，暫時不需要深入數學細節。

- **AI 工程師**  
  請優先閱讀第 3 節的三種整合方式：離線強化學習的節點取樣與 GRPO 目標、線上 RLVR 的適應性技能獎勵實作、以及 OPSD 中如何把 X-Tree 當作自我教師的特權上下文。實作時請特別注意正規化動作、X-Score 計算與獎勵權重衰減機制，並嘗試在 WebShop 或 WebArena 等公開環境復現。

- **研究人員**  
  可從本文與階層式強化學習（options / sub-policies）以及 LLM 撰寫技能文獻的對比切入，關注「零 LLM 呼叫」與「從資料本身恢復結構」這兩項核心貢獻。消融實驗與跨模型規模的結果值得細讀，未來可延伸至連續動作、部分可觀測環境，或動態更新 X-Tree 的線上挖掘演算法。

- **產品經理**  
  本文的商業價值在於：用有限軌跡資料就能提升代理泛化能力，且無需持續呼叫昂貴的大型語言模型來產生技能摘要，整個技能樹可從資料中審計與重現。適合應用於自動化流程、客戶支援、電商導購等場景，但需確保組織已有足夠品質的軌跡資料與可信的任務驗證器。
