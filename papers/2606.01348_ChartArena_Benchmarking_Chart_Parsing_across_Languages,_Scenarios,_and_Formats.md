## 摘要翻譯

圖表（charts）是傳達量化與關聯性資訊的主要媒介，然而系統性評估圖表解析（chart parsing）模型仍然困難。現有的基準測試（benchmarks）多聚焦於狹隘的圖表類別，且在很大程度上未涵蓋流程圖（flowcharts）、心智圖（mind maps）等圖解結構（diagrammatic structures）；同時，模型輸出格式互不相容（incompatible formats），而資料集也很少包含實務中會遇到的印刷照片（printed photos）或手繪照片（hand-drawn photos）。為了解決這些問題，我們提出 ChartArena，一個全面的雙語基準測試（bilingual benchmark），涵蓋八個圖表類別，橫跨數值圖表（numeric charts）與圖解結構（diagrammatic structures），每個類別都在三種視覺情境下進行評估：數位渲染圖（digital renderings）、印刷照片（printed photos）與手繪照片（hand-drawn photos）。此資料集透過人機協作標註流程（human-agent collaborative annotation pipeline）建立，並經多階段人工驗證（multi-stage human verification）以確保標註可靠性（annotation reliability）。為實現公平的跨模型比較（cross-model comparison），我們進一步設計格式無關評估協定（format-agnostic evaluation protocol），將異質輸出（heterogeneous outputs）映射至兩個標準語義空間（canonical semantic spaces）——標準化三元組視圖（normalized triple view）與

## 深度分析

#### 方法論解析

本研究的核心貢獻在於提出 ChartArena，一個涵蓋八種圖表家族（chart families）、三種視覺情境（visual scenarios）與雙語（bilingual）設定的綜合性圖表解析（chart parsing）基準測試（benchmarking）資料集，並搭配一套格式無關評估協定（format-agnostic evaluation protocol）。以下從資料建構與評估方法兩個層面進行剖析。

**人機協作標註流程（Human-agent Collaborative Annotation Pipeline）**
為確保標註可靠性（annotation reliability），ChartArena 採用人機協作標註流程（human-agent collaborative annotation pipeline）。具體而言，研究團隊先利用模型自動生成初步標註草稿（model-assisted drafts），再透過多階段人工驗證（multi-stage human verification）進行迭代式修正。這種設計有效結合了自動化產出的效率與人類對於結構一致性（structural consistency）的判斷力，特別是在處理圖解結構（diagrammatic structures）如流程圖（flowcharts）與心智圖（mind maps）時，單純仰賴自動化標註容易遺漏節點間的語義關聯，而人工介入能顯著降低這類錯誤。相較於傳統僅由人工標註或完全自動生成的資料集，此流程在規模化與品質之間取得了平衡。

**跨情境與雙語資料設計**
ChartArena 的資料建構策略明確針對真實世界視覺擾動（real-world visual perturbations）進行設計。資料集橫跨三種視覺情境：原始數位渲染圖（pristine digital renderings）、印刷照片（printed photos）與手繪照片（hand-drawn photos）。後兩者引入了模糊（blur）、透視變形（perspective distortion）與墨水不一致性（ink inconsistencies）等實際雜訊，迫使模型必須具備超越乾淨數位環境的強健性。此外，所有圖表影像均同時包含中文與英文版本，使其成為首個具備此規模與多樣性的雙語基準測試（bilingual benchmark）。這種設計直接挑戰了現有模型在多語言與低影像品質情境下的泛化能力。

**格式無關評估協定（Format-agnostic Evaluation Protocol）**
現有圖表解析模型常輸出孤立的輸出格式（siloed output formats），例如 Markdown 表格（Markdown tables）、JSON 結構（JSON structures）、CSV、Python 程式碼（Python code）、SVG 程式碼（SVG code）或 Mermaid、Graphviz、PlantUML 等圖形語言，這些互不相容的語法形式（mutually incompatible syntactic forms）使得直接跨模型比較（direct cross-model comparison）幾乎不可能。為解決此碎片化（fragmentation）問題，作者提出將異質輸出（heterogeneous outputs）投影至兩個標準語義空間（canonical semantic spaces）：

1. **標準化三元組視圖（Normalized Triple View）**：針對數值圖表（numeric charts），如長條圖（bar charts）、折線圖（line charts）、圓餅圖（pie charts）、雷達圖（radar charts）、箱型圖（boxplot）與組合圖（combination chart），將各種格式統一轉換為結構化的三元組表示。此表示法能捕捉圖表中的實體、屬性與數值關係，類似於機器可執行表示（machine-executable representations）中的關聯資料形式。
2. **有向圖視圖（Directed Graph View）**：針對圖解結構（diagrammatic structures），如流程圖與心智圖，將輸出正規化為有向圖，以節點與邊的形式表達圖層級結構理解（graph-level structural understanding）所需的連通性與方向性資訊。

在統一語義空間後，評分採用結構感知指標（structure-aware metrics），報告 Exact Match 與 mean Average Precision（mAP）於多重容許誤差（multiple tolerances）下的表現。此設計的關鍵優勢在於，分數差異真正反映語義內容（semantic content）的理解落差，而非表面的語法格式選擇。

#### 實驗數據解讀

本研究評估了 26 個領先模型，涵蓋通用多模態大型語言模型（general-purpose Multimodal Large Language Models, MLLMs）、文件解析模型（document parsing models）與專家圖表解析器（expert chart parsers）。實驗結果呈現出三個一致且深具啟發性的發現。

**前沿專有模型與開源系統的能力消長**
實驗顯示，前沿專有模型（frontier proprietary models）如 Gemini 3.1 Pro 在整體表現上仍居領先地位，然而最強大的開源系統（open-source systems）正迅速縮小差距。這項趨勢顯示圖表解析領域的技術民主化正在加速：專有模型憑藉其龐大的訓練資源與模型規模維持優勢，但開源社群透過針對性微調與架構創新，已在特定圖表類型上達到可比的語義理解水準。對研究者而言，這意味著建構通用圖表解析器（general chart parser）的門檻正在降低，但要在所有圖表家族與視覺情境上全面超越專有模型，仍需結構性的方法論突破。

**數值圖表與圖解結構的結構性落差**
文件解析模型在數值圖表上表現尚可，但在圖解結構上卻大幅落後。這項結果凸顯了當前端對端生成方法（end-to-end generation approaches）的一項根本缺陷：這類模型通常針對文件中的表格與常見圖表進行最佳化，其內部表徵偏向於擷取文字與座標對應關係，而非推論節點間的抽象連結。相對地，流程圖與心智圖要求模型進行圖層級結構理解，包括辨識方向性、層級關係與語義角色，這超出了傳統文件解析的範疇。另一方面，專家圖表解析器雖在特定類型上可能有較高精度，卻受限於狹窄的圖表家族（narrow chart families），無法處理跨類型的異質輸入。這揭示了目前領域中「專精」與「通用」之間的權衡困境。

**雷達圖與手繪情境：尚未解決的硬骨頭**
跨所有模型類別，雷達圖（radar charts）與手繪照片（hand-drawn photos）始終是最具挑戰性的情境。雷達圖的困難源自其極座標系統與多軸數值比較的複雜性，模型必須同時解析角度、半徑與多維度資料點的相對關係，這對基於直角座標系訓練的視覺編碼器構成挑戰。手繪情境則因真實世界視覺擾動而惡化：線條粗細不一、文字潦草、非標準符號與背景雜訊共同導致特徵擷取失敗。值得注意的是，即使是頂尖的專有模型在此類情境下也出現顯著效能衰減，暗示目前的視覺編碼器與預訓練策略對於低品質、高變異輸入的魯棒性（robustness）仍顯不足。

#### 與現有研究的比較

ChartArena 的推出，直接回應了圖表理解（chart understanding）領域長期以來缺乏統一評估標準（unified evaluation standards）的問題。透過與現有基準測試的系統性對照，可清楚定位其貢獻與侷限。

**覆蓋率的全面性突破**
從 Table 1 的比較可見，現有基準測試如 PlotQA-SE、ChartQA-SE、MMC-Bench、ChartX-SE、ChartY、VG-DCU、ChartP-Bench、ParseBench 與 ExChart-Bench，大多僅涵蓋少數數值圖表（通常為長條圖、折線圖與圓餅圖），且幾乎全部僅使用原始數位渲染圖，並以英文為主。ChartArena 是首個同時納入數值圖表與圖解結構（流程圖、心智圖）、涵蓋數位渲染圖、印刷照片與手繪照片三種視覺情境，並提供中英雙語版本的基準測試。這種廣度使其能夠評估過往受控基準測試（controlled benchmarks）無法觸及的能力差距（capability gaps），特別是模型在面對非標準化、結構複雜且視覺品質低落的輸入時的表現。

**從格式碎片化到公平跨模型比較**
過去研究受限於孤立的輸出格式，不同模型分別輸出 Markdown、JSON、CSV 或程式碼，導致無法進行公平的跨模型比較。ChartArena 的格式無關評估協定透過標準語義空間的設計，首次實現了跨典範（cross-paradigm）的公平比較，無論模型採用模組化流程（modular pipelines）或端對端生成方法，其輸出均可被決定性地映射至同一組語義表示進行評分。這項方法論創新不僅適用於當前主流格式，更具備擴充性（extensible），可容納未來可能出現的新穎輸出形式。

**本研究的侷限性**
儘管 ChartArena 在覆蓋率上達到新高度，其資料集規模為 2,400 張影像，相較於 PlotQA-SE 的 33,657 筆或 ChartY 的 6,048 筆仍屬中等。多樣性與規模之間的權衡意味著每個圖表家族與情境組合的樣本數相對有限，可能影響對稀有錯誤模式的統計顯著性。此外，目前的評估聚焦於圖表解析的結構正確性，尚未深入探討下游分析（downstream analysis）、問答（question answering）或自動化推理（automated reasoning）等應用層面的效用。最後，雖然資料集為雙語設計，但僅涵蓋中文與英文，對於其他語系的使用者而言，其跨語言泛化性的驗證仍不完整。

#### 可重現性評估

作為一個基準測試研究，可重現性（reproducibility）取決於資料集、評估協定與實驗設定的透明程度。

**資料集與工具公開性**
根據論文所述，ChartArena 已於 GitHub 公開釋出（https://github.com/pspdada/ChartArena），這包含圖表影像、真實標註三元組（ground truth triplets）與真實標註圖（ground truth graph）。資料集的公開是確保後續研究能夠驗證與延伸本研究發現的基石。然而，論文未明確說明是否同步釋出格式無關評估協定的官方實作程式碼（如將 Markdown、Mermaid、Python 程式碼等轉換至標準語義空間的解析器與評分腳本）。若僅釋出資料而無標準化工具，不同研究團隊在重現評估流程時可能因實作細節差異而產生分數漂移，這是後續需要補強之處。

**標註流程的可複製性**
人機協作標註流程涉及多階段人工驗證，雖然論文描述了整體框架，但具體的品質控管準則、驗證者間一致性（inter-annotator agreement）數據與模型輔助草稿的生成參數並未詳盡揭露。這使得其他研究者難以完全複製相同的標註流程來擴充資料集。理想情況下，作者應提供詳細的標註指南（annotation guidelines）與輔助模型檢查點（checkpoint），以降低未來擴展工作的門檻。

**模型權重與實驗設定的透明度**
本研究評估的 26 個模型均為現有公開或專有模型，並未訓練新模型，因此不涉及新模型權重（model weights）的釋出問題。然而，對於專有模型（如 Gemini 3.1 Pro）的 API 版本、溫度參數（temperature）、提示詞設計（prompting strategy）與解碼設定，論文應提供更完整的附錄資訊，以確保實驗結果可被獨立驗證。開源系統的評估則相對透明，只要指定模型版本與推論框架即可重現。

#### 未來研究方向

ChartArena 所揭示的能力差距與方法論框架，為後續研究開闢了多條具體且高價值的路徑。

**擴充圖表類型與語言覆蓋率**
當前 ChartArena 涵蓋八種圖表家族，但未包含散佈圖（scatter plots）、熱力圖（heatmaps）、甘特圖（Gantt charts）或桑基圖（Sankey diagrams）等常見於商業與科學領域的類型。未來研究可將標準語義空間擴展至這些類型，例如為網絡圖設計更複雜的超圖（hypergraph）視圖。在語言方面，從目前的雙語基準測試擴展至多語系（如日文、阿拉伯文、德文），將能更嚴格地測試多模態大型語言模型的跨語言遷移能力，特別是對於手寫體與非拉丁字母的處理。

**強化圖層級結構理解能力**
實驗結果顯示，圖解結構是當前所有模型的共同弱點。未來可探索融合圖神經網路（Graph Neural Networks, GNNs）與多模態大型語言模型的混合架構，在視覺編碼器提取特徵後，透過顯式的圖推理模組重建節點與邊的關係。另一方向是設計針對有向圖視圖（directed graph view）的預訓練任務，例如圖結構去噪或邊預測，以增強模型對流程圖與心智圖的結構感知能力。

**真實世界視覺擾動的領域適應**
手繪照片與印刷照片帶來的挑戰，凸顯了領域適應（domain adaptation）與強健性訓練的重要性。後續研究可發展針對模糊、透視變形與墨水不一致性的資料增強策略，或利用合成至真實（synthetic-to-real）的遷移學習來彌補乾淨數位渲染圖與真實世界影像之間的領域差距。此外，設計能夠主動偵測並校正視覺雜訊的前處理模組，可能有助於提升現成模型在惡劣視覺條件下的表現。

**邁向通用圖表解析器與下游整合**
目前專家圖表解析器與通用模型各有所長，但未來的聖杯是建構真正的通用圖表解析器，能夠在單一框架內無縫處理數值圖表與圖解結構。這可能需要新的統一表徵學習架構，或基於 ChartArena 標準語義空間進行多工學習（multi-task learning）。更進一步，圖表解析不應僅止於結構提取，而需與下游分析、問答與自動化推理緊密整合。開發能夠直接在標準化三元組與有向圖視圖上執行符號推理（symbolic reasoning）的系統，將是釋放圖表資料價值的關鍵下一步。

**動態與互動式圖表理解**
最後，靜態圖表僅是起點。未來基準測試可朝向動態圖表（如隨時間變化的動畫圖表）與互動式圖表（如可縮放、可篩選的儀表板）發展，要求模型理解時序變化與使用者操作語義。這將把圖表解析從單一影像理解任務，推向更貼近真實數據分析工作流的複雜多模態推理挑戰。

## 論文問答

**Q1：ChartArena 旨在解決圖表解析領域中的什麼核心問題？**
A：ChartArena 旨在解決圖表解析領域中評估標準嚴重碎片化的核心問題。現有的基準測試往往過於狹隘，無法系統性地衡量模型在多元圖表類型、語言及真實視覺條件下的能力。這種碎片化的現象使得研究者難以準確識別當前模型的失敗之處，也阻礙了真正通用圖表解析器的發展。

**Q2：為何現有的基準測試與評估方法無法充分評估圖表解析能力？**
A：現有的基準測試與評估方法主要因為三個相互疊加的差距而無法充分評估圖表解析能力。首先，不同模型的輸出格式彼此孤立且互不相容，例如 Markdown、JSON、CSV 或 Python 程式碼，導致無法進行直接的跨模型比較。其次，現有資料集大多僅涵蓋少數數值圖表類型，忽略了流程圖與心智圖等需要圖層級結構理解的圖解結構。第三，目前的資料集多由原始數位渲染圖組成，鮮少包含印刷文件或手繪草圖等帶有真實世界視覺擾動的影像。

**Q3：建立像 ChartArena 這樣的統一基準測試，對於通用圖表解析器的發展為何重要？**

4. **跨語言市場情報彙整**：跨國企業需同時處理中文與英文的產業圖表。ChartArena 作為首個雙語圖表解析基準，可用於驗證模型在兩種語言下的結構一致性，確保從全球各來源擷取的數值與關係資訊能被統一語義空間比較與彙整。

### 實作步驟建議

1. **需求盤點與圖表分類**：先界定產品需支援的圖表家族（數值型 vs. 圖解型）與視覺情境（數位、印刷、手繪）。若涉及流程圖或心智圖，應優先選擇在 ChartArena 上對圖解結構表現較佳的通用 MLLM，而非僅針對文件設計的解析模型。
2. **模型選型與基線建立**：參考論文中 26 個模型的評測結果設定基線。專有模型（如 Gemini 3.1 Pro）整體領先，但頂尖開源系統差距已快速縮小；若成本敏感，可優先評測開源方案。同時注意文件解析模型在數值圖表與圖解結構上的效能落差。
3. **建立格式無關後處理管線**：設計正規化層，將所有模型輸出（無論是 Markdown 表格、JSON、CSV、Python 程式碼或 Mermaid 語法）映射到標準化三元組視圖（數值圖表）或有向圖視圖（圖解結構）。此為實現跨模型比較與下游系統對接的關鍵。
4. **人機協作標註與驗證**：若需自建領域資料，採用論文提出的人機協作標註流程——先以模型生成草稿，再透過多階段人工驗證修正結構錯誤，確保標註可靠性與結構一致性。
5. **情境擴充與提示工程**：針對印刷照片與手繪照片的真實世界視覺擾動，於提示中納入 few-shot 範例或加入影像前處理（去模糊、透視校正），以提升在困難情境下的解析準確率。
6. **結構感知評估與迭代**：以 ChartArena 的結構感知指標（Exact Match、mAP 多容差）持續監控模型表現，特別關注雷達圖與手繪情境等普遍弱項，並將失敗案例回流至標註流程，形成迭代優化閉環。

### 潛在風險與注意事項

1. **格式孤島與比較失準**：不同模型輸出互不相容（如 Markdown 對比 Python 程式碼），若未建立正規化層，跨模型比較將流於表面語法比對，而非語義理解差異。**因應措施**：嚴格導入格式無關評估協定，統一映射至標準語義空間後再計分。
2. **圖解結構的效能斷崖**：文件解析模型雖在數值圖表表現合理，但在流程圖、心智圖等需圖層級結構理解的任務上表現急遽下滑。**因應措施**：產品若涉及圖解結構，應選用通用 MLLM 或針對圖結構特化微調的模型，而非傳統文件解析方案。
3. **真實視覺擾動的魯棒性不足**：手繪草稿的墨水不一致性與印刷照片的模糊、透視變形，對所有模型皆為顯著挑戰。**因應措施**：在訓練與測試集中強制納入此類樣本，並於推論前加入影像前處理管線（如自動透視校正、對比度增強）。
4. **專家解析器的維護成本**：專家圖表解析器僅適用狹窄圖表家族，長期維護成本高且難以擴充。**因應措施**：朝向通用解析器架構發展，或設計動態路由機制，依圖表類型自動分派對應子模型。
5. **雙語語境下的格式與語義差異**：中文與英文在數值格式（千分位、日期）、標籤語義與版面習慣上存在差異，可能導致後處理錯誤。**因應措施**：在標準化三元組生成階段加入在地化解析規則，並以 ChartArena 的雙語標註作為驗證依據。

### 與其他技術的整合建議

1. **RAG 與知識庫系統**：將圖表解析後的標準化三元組與有向圖存入圖資料庫（如 Neo4j）或向量資料庫，結合檢索增強生成（RAG）架構，讓 LLM 能基於結構化圖表資訊進行問答、趨勢分析與自動化推理。
2. **OCR 與版面分析（Layout Analysis）前置管線**：在 MLLM 前串接文件級 OCR 與版面偵測模組，先精準定位圖表區域並濾除周邊文字雜訊，再送入 ChartArena 評測過的解析模型，可顯著降低誤判率。
3. **BI 與流程設計工具**：數值圖表的標準化三元組可直接對接 Power BI、Tableau 或自研報表引擎；圖解結構的有向圖則可轉為 BPMN、Graphviz 或 Cytoscape 格式，匯入流程設計與視覺化工具。
4. **規則引擎與資料驗證**：在格式無關評估層之上疊加業務規則引擎（例如驗證圓餅圖各分項總和是否為 100%、流程圖是否有唯一起點），作為語義正確性的第二道防線，彌補純模型解析的不確定性。
5. **MLOps 監控與資料飛輪**：在生產環境持續收集解析失敗案例（特別是雷達圖與手繪情境），自動回流至人機協作標註管線進行標註與驗證，定期重新評估模型於 ChartArena 上的結構感知指標，形成持續優化的資料飛輪。

### 給不同背景讀者的閱讀建議

**初學者**：建議從摘要與第一章的「問題碎片化」論述開始，理解為何圖表解析領域需要統一的雙語基準；接著對照表一（基準比較表）與圖一（異質輸出格式），建立對領域挑戰的直觀認識，再視需求深入格式無關評估協定的細節。

**AI 工程師**：應重點研讀格式無關評估協定的實作細節，掌握如何將 Markdown、JSON、Mermaid 等異質輸出正規化為三元組與有向圖；同時參考 26 個模型的評測結果進行選型，特別留意文件解析模型與通用 MLLM 在圖解結構上的效能落差，據此設計後處理與容錯機制。

**研究者**：建議聚焦於 ChartArena 的資料建構方法論——人機協作標註流程與多階段人工驗證——以及結構感知指標的設計邏輯；可進一步探討雷達圖與手繪情境為何對現有模型仍具挑戰性，並將此基準作為未來通用圖表解析器研究的統一試金石。

**產品經理**：應關注論文中的「能力差距」發現：專有模型領先但開源迅速追趕、數值圖表與圖解結構的難度差異、以及真實世界視覺擾動對準確率的影響。這些結論可直接用於評估技術成熟度、規劃產品路線圖，並為用戶設定合理的功能期望與上線優先順序。
