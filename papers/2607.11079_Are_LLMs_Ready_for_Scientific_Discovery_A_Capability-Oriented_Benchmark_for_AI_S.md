## 摘要翻譯

現有的科學數據分析（Scientific Data Analysis）基準測試主要評估大型語言模型（Large Language Models, LLMs）在程式碼執行（Code Execution）或工作流程完成（Workflow Completion）上的表現，卻忽略了科學分析旨在支持不同類型的科學主張（Scientific Claims）：假設探索（Hypothesis Exploration）、統計推論（Statistical Inference）、機制性解釋（Mechanistic Explanation），而每一種主張各有其不同的假設（Assumptions）與有效性標準（Validity Criteria）。我們提出 SDABench（科學數據分析基準測試，SDABench），一個圍繞六項能力（Capabilities）——描述性分析（Descriptive Analysis）、探索性分析（Exploratory Analysis）、推論性分析（Inferential Analysis）、預測性分析（Predictive Analysis）、因果性分析（Causal Analysis）與機制性分析（Mechanistic Analysis）——涵蓋五個領域（Domains）：生物學（Biology）、化學（Chemistry）、環境科學（Environment）、地理學（Geography）、物理學（Physics），重新組織評估的基準測試。SDABench 包含 527 個真實數據實例（Real-Data Instances，SDA-Real）與 6000 個合成數據實例（Synthetic Instances，SDA-Synth），每個實例均提供選擇題形式（Multiple-Choice Format）與開放式形式（Open-Ended Format）兩種形式，並透過自動化流程（Automated Pipeline）建構而成。在評估 15 個代表性大型語言模型（Representative LLMs）後，我們發現模型在描述性分析上表現良好，但在需要假設選擇（Assumption Selection）、潛在過程建模（Latent-Process Modeling）或機制性推理（Mechanistic Reasoning）的任務上則急遽衰退。SDABench 更進一步提供一個五階段錯誤分析框架（Five-Stage Error Analysis Framework），以定位大型語言模型失敗所在：較先進的模型能更可靠地辨識相關範圍（Relevant Scope）與變數（Variables），但仍難以選擇適當的分析方法（Analytical Procedures）、進行變數關係建模（Model Variable Relationships），並得出有效結論（Draw Valid Conclusions）。

### 核心貢獻（3～5點）
- 提出 SDABench，一個以六項科學數據分析能力為核心、涵蓋五大領域的基準測試，強調科學分析應服務於不同類型的科學主張。
- 建構包含 527 個真實數據實例（SDA-Real）與 6000 個合成數據實例（SDA-Synth）的雙題型資料集（選擇題與開放式），並透過自動化流程生成。
- 系統性評估 15 個代表性 LLMs，揭示模型在描述性分析表現良好，但在假設選擇、潛在過程建模與機制性推理等高階能力上明顯不足。
- 提出五階段錯誤分析框架，細緻定位 LLM 在科學數據分析流程中的失敗環節。

### 適合對象
對於大型語言模型在科學研究應用、科學數據分析方法論、AI for Science 基準測試設計，以及自動化科學發現感興趣的研究者與實務工作者。

## 深度分析

#### 方法論解析

本研究的核心貢獻在於將科學數據分析（Scientific Data Analysis）的評估從傳統的「程式碼執行（Code Execution）」或「工作流程完成（Workflow Completion）」導向，轉向「以能力為導向的基準測試（Capability-Oriented Benchmark）」。作者採用 Leek and Peng（2015）的六類問題框架，將其重新詮釋為六種科學發現能力（Scientific Discovery Capabilities）：

1. **Descriptive Analysis（描述性分析）**：總結與表徵資料中的基本特徵。  
2. **Exploratory Analysis（探索性分析）**：發現模式、異常或潛在關聯。  
3. **Inferential Analysis（推論性分析）**：進行統計推論（Statistical Inference）並估計不確定性。  
4. **Predictive Analysis（預測性分析）**：建立預測模型並評估其泛化能力。  
5. **Causal Analysis（因果性分析）**：判斷變數（Variables）間的因果關係，需處理混淆因子與干預。  
6. **Mechanistic Analysis（機制性分析）**：理解資料背後的潛在過程（Latent Process）與機制性解釋（Mechanistic Explanation）。

這六種能力對應不同的科學主張（Scientific Claims），各自具有不同的假設（Assumptions）與有效性標準（Validity Criteria），因此不能僅以單一執行成功率概括。

在資料建構上，SDABench 分為兩個互補子集：

- **SDA-Real**：527 個真實數據實例（Real-Data Instances），橫跨 Biology（生物學）、Chemistry（化學）、Environment（環境科學）、Geography（地理學）、Physics（物理學）五個領域（Domains）。這些實例來自真實世界的科學資料集，確保評估的生態效度（Ecological Validity）。
- **SDA-Synth**：6,000 個合成數據實例（Synthetic Instances），透過語義圖（Semantic Graphs）建構，並經由三階段自動化流程（Automated Pipeline）產生：
  1. **LLM-based Template Construction（基於 LLM 的模板建構）**：利用大型語言模型（Large Language Models, LLMs）生成問題模板與資料生成規則。
  2. **Programmatic Ground-Truth Derivation（程式化標準答案推導）**：以程式自動計算正確答案，確保可擴展性與客觀性。
  3. **Option Generation（選項生成）**：為選擇題形式（Multiple-Choice Question, MCQ）生成干擾選項。

每個實例同時提供 **MCQ（選擇題）** 與 **OEQ（Open-Ended Question，開放式問答）** 兩種格式，讓研究者能比較模型在封閉選項與自由作答情境下的表現差異。

此外，作者提出一個**五階段錯誤分析框架（Five-Stage Error Analysis Framework）**，用於定位 LLM 的失敗環節。根據文中描述，這五個階段大致對應：

1. 辨識任務的相關範圍（Relevant Scope）與目標。  
2. 識別相關變數（Variables）。  
3. 選擇適當的分析方法（Analytical Procedures）。  
4. 對變數關係進行建模（Model Variable Relationships）。  
5. 根據證據得出有效結論（Draw Valid Conclusions）。

這種診斷式評估能夠區分「模型是否會寫程式」與「模型是否能進行有效的科學推理」，從而避免 Aggregate Scores（聚合分數）掩蓋具體的推理失敗（Reasoning Failures）。

#### 實驗數據解讀

本研究評估了 15 個代表性 LLMs（Representative LLMs），涵蓋不同規模與架構。雖然文中未逐一列出模型名稱，但從實驗設計可推知包含主流專有模型（如 GPT 系列、Claude、Gemini）與開源模型（如 Llama、Qwen 等）。

主要實驗發現可歸納如下：

**1. 描述性分析表現最佳，高階推理能力顯著退化**  
模型在 Descriptive Analysis（描述性分析）上表現良好，顯示 LLM 已能勝任資料摘要、基本統計與趨勢描述。然而，一旦任務涉及 Assumption Selection（假設選擇）、Latent-Process Modeling（潛在過程建模）或 Mechanistic Reasoning（機制性推理），表現便急劇下降。這呼應了科學界長期以來的擔憂：LLM 擅長表面模式匹配，但對於需要深層因果與機制理解的任務仍力有未逮。

**2. MCQ 形式可能誘發膚淺的捷徑學習**  
研究發現，在某些任務類型中，提供明確選項反而會降低模型表現。這是因為 MCQ 可能誘導模型進行 Superficial Pattern Matching（膚淺的模式匹配），而非真正的科學推理。這對當前許多科學推理基準測試過度依賴選擇題形式提出了重要警示：高分不一定代表具備真正的分析能力。

**3. 先進模型在「問題理解」階段進步，但在「方法選擇」與「關係建模」階段仍薄弱**  
五階段錯誤分析顯示，較先進的模型更能可靠地辨識 Relevant Scope（相關範圍）與 Variables（變數），但在選擇適當的 Analytical Procedures（分析方法）、準確建模變數關係（Model Variable Relationships）以及 Draw Valid Conclusions（得出有效結論）方面仍有明顯困難。這意味著，即使模型「看懂」了問題，也未必能正確執行科學推論。

**4. Aggregate Workflow Scores 掩蓋了深層缺陷**  
傳統基於 Workflow Completion（工作流程完成）的分數會將資料清理、特徵工程、模型訓練與結果解釋混為一談，無法區分模型是在基礎資料處理失敗，還是在高階因果推論失敗。SDABench 的能力導向設計讓這些差異變得可見。

**5. SDA-Real 與 SDA-Synth 的互補價值**  
SDA-Real 提供真實性（Realism）與領域多樣性，適合評估模型在真實科學資料上的泛化能力；SDA-Synth 則透過可控的資料生成機制，允許大規模、系統性地測試特定能力（如因果性、機制性），並降低資料蒐集成本。兩者結合使基準測試同時具備外部效度與內部效度。

#### 與現有研究的比較

文中表 1 將 SDABench 與多個現有基準測試進行比較，包括 DataSciBench、KramaBench、ScienceAgentBench、QRData、LLM-SRBench、DSBench、DA-Code 與 BLADE。相較於這些工作，SDABench 的主要差異與優勢如下：

**1. 從「執行成功」轉向「科學主張有效性」**  
現有基準測試大多評估 Code Execution（程式碼執行）或 Workflow Completion（工作流程完成），例如模型是否能生成可執行的分析腳本、完成特徵選擇或建立預測模型。然而，Successful Execution（成功執行）並不等同於 Scientific Validity（科學有效性）——模型可能算出正確數值，卻無法支持預期的科學主張（Intended Scientific Claim）。SDABench 直接圍繞不同類型的科學主張設計題目，彌補了這一根本缺陷。

**2. 更完整的能力覆蓋**  
如表 1 所示，多數現有基準測試缺乏 Causal Reasoning（因果推理）與 Mechanistic Reasoning（機制性推理）的系統評估，而這兩者正是科學發現的核心。SDABench 是少數同時涵蓋描述性、探索性、推論性、預測性、因果性與機制性六種能力的基準測試。

**3. 結合真實與合成資料，並提供雙重題型**  
相較於僅使用真實資料（如 QRData）或僅使用合成資料（如部分程式化基準）的工作，SDABench 同時納入 SDA-Real 與 SDA-Synth，並提供 MCQ 與 OEQ 兩種格式，使評估更為全面。

**4. 結構化的錯誤分析框架**  
多數現有基準僅報告正確率或執行成功率，缺乏對失敗原因的細緻分類。SDABench 的五階段錯誤分析框架能夠診斷模型在科學推理鏈中的具體薄弱環節，這對於開發更可靠的 AI 科學家（AI Scientists）具有重要指導意義。

**限制與待改進之處：**

- **合成資料的現實性限制**：SDA-Synth 雖然規模大且可控，但語義圖生成機制可能無法完全捕捉真實科學資料的複雜雜訊與領域細節。
- **LLM-as-Judge 的潛在偏誤**：開放式問答（OEQ）的評估可能依賴 LLM 作為評判者，這可能引入模型自身的偏好與盲點。
- **MCQ 的設計挑戰**：儘管研究指出 MCQ 可能誘發捷徑學習，但如何設計真正具有鑑別力的選項仍是一大難題。
- **語言與文化侷限**：目前資料與評估主要基於英文科學文獻，對於其他語言或在地化科學情境的適用性有限。
- **缺乏互動式探索**：真實科學分析常是反覆試誤的過程，而 SDABench 目前主要評估單輪問答，尚未充分模擬互動式資料探索。

#### 可重現性評估

可重現性（Reproducibility）是科學基準測試能否被廣泛採用的關鍵。根據提供的全文脈絡，SDABench 的可重現性取決於以下幾個要素：

**1. 資料集與生成程式碼的公開程度**  
SDA-Real 的 527 個真實數據實例與 SDA-Synth 的 6,000 個合成數據實例若能完整公開，並附上詳細的資料來源、授權資訊與預處理腳本，將大幅提升可重現性。特別是 SDA-Synth 的三階段自動化流程（Automated Pipeline）——包括 LLM-based Template Construction、Programmatic Ground-Truth Derivation 與 Option Generation——必須開源，才能讓其他研究者重製或擴充資料。

**2. 評估程式碼與提示詞模板**  
本研究同時使用自動化評分（Auto）與 LLM 評分（LLM-as-Judge）兩種方式。為確保可重現性，作者應公開：
- MCQ 與 OEQ 的評分腳本；
- 用於 LLM-as-Judge 的提示詞模板（Prompt Templates）；
- 模型輸出的後處理與標準化流程；
- 各模型呼叫的 API 版本、溫度參數（Temperature）、取樣參數與上下文長度設定。

**3. 模型權重與 API 版本**  
由於評估涉及 15 個代表性 LLMs，其中部分為專有 API 模型（如 GPT-4、Claude、Gemini），其權重無法公開，但作者應明確記錄所使用的具體版本（例如 GPT-4-Turbo-2024-04-09）。對於開源模型，則應提供模型名稱、參數規模與推論設定，以便他人復現。

**4. 錯誤分析框架的操作化細節**  
五階段錯誤分析框架（Five-Stage Error Analysis Framework）需要清晰的判斷準則與標註範例，否則不同研究者可能對「模型是否正確識別 Variables」或「是否選擇適當 Analytical Procedures」產生分歧。建議作者公開錯誤分類的標註指南（Annotation Guidelines）與一致性檢驗結果。

**總結**：根據目前提供的資訊，文中並未明確提及原始碼、資料集或模型權重的公開連結。若作者能完整釋出上述資源，SDABench 將具備高度的可重現性；反之，則可能限制其他研究團隊的驗證與後續擴展。

#### 未來研究方向

SDABench 為評估 LLM 的科學發現能力奠定了重要基礎，但未來仍有許多值得延伸的方向：

**1. 擴展能力維度：從分析到實驗設計與理論建構**  
目前的六種能力主要聚焦於資料分析階段。未來可進一步納入：
- **Experimental Design（實驗設計）**：評估模型是否能設計有效實驗以檢驗假設；
- **Hypothesis Generation（假設生成）**：評估模型從文獻與資料中提出新穎假設的能力；
- **Uncertainty Quantification（不確定性量化）**：評估模型對估計誤差與置信區間的理解；
- **Model Criticism（模型批判）**：評估模型檢視自身假設與限制的能力。

**2. 多模態科學資料整合**  
真實科學發現常涉及圖像（如顯微影像、光譜圖）、時間序列（Time Series）、空間資料（Spatial Data）與結構資料（如分子結構、蛋白質結構）。未來可將 SDABench 擴展為多模態基準測試，評估模型整合文本、數值與非結構化資料的能力。

**3. 互動式與自主型 AI 科學家**  
目前的評估多為單輪問答。未來可設計互動式環境，讓模型能夠：
- 反覆查詢資料；
- 呼叫外部模擬器（Simulators）或實驗設備；
- 根據初步結果調整假設與分析方法。
這將更接近真實科學發現的迭代本質。

**4. 領域專屬基礎模型的微調與評估**  
未來可基於 SDABench 開發針對特定領域（如化學反應機制或生態系統動態）的科學基礎模型，並探討領域預訓練是否能顯著提升 Causal 與 Mechanistic Reasoning 能力。

**5. 神經符號（Neuro-Symbolic）方法的整合**  
純粹的 LLM 可能在數學推導與因果識別上存在限制。未來可結合：
- 因果推論引擎（Causal Inference Engines）；
- 微分方程求解器（Differential Equation Solvers）；
- 符號數學系統（Symbolic Mathematics Systems）；
以提升模型在 Mechanistic 與 Causal Analysis 上的可靠性。

**6. 動態與抗污染基準測試**  
隨著 LLM 訓練資料不斷擴大，基準測試資料可能洩漏至模型預訓練語料中。未來可發展動態生成機制，持續更新 SDA-Synth 的語義圖與題目，以降低資料污染（Data Contamination）風險。

**7. 跨語言與跨文化科學推理評估**  
目前 SDABench 主要基於英文科學資料。未來可將其翻譯或改編為中文、日文、法文等多語言版本，探討科學推理能力是否受語言與文化背景影響。

**8. 人機協作的有效性研究**  
最後，未來研究可探討科學家如何根據 SDABench 的錯誤分析結果與 AI 協作，例如讓人類專家專注於模型薄弱的 Mechanistic Reasoning 環節，而將 Descriptive 與 Exploratory Analysis 交由 AI 處理，從而提升整體科學發現效率。

## 論文問答

**Q1：現有的科學數據分析基準測試存在什麼根本問題，促使作者提出 SDABench？**  
A：現有基準大多聚焦於程式碼執行或工作流程完成，容易把「成功執行」誤認為「科學上有效」，卻忽略分析結果是否真正支持預期的科學主張。此外，它們常以單一聚合分數評量，無法區分模型是在基本描述出錯，還是在複雜因果或機制推理上失敗。因此，作者認為需要以能力為導向的評估框架，根據科學主張類型來檢驗大型語言模型。

**Q2：為什麼「工作流程完成」不足以衡量 AI 科學家的數據分析能力？**  
A：一個模型即使能產生並執行分析程式碼，也不代表它理解該分析所需的統計假設或證據界限。舉例來說，模型可能正確計算出相關係數，卻誤把相關解釋為因果，從而得出無效的科學結論。因此，僅看執行成功會掩蓋深層推理缺陷，無法確保模型具備真正的科學發現能力。

**Q3：以科學主張類型為核心進行評估，對 AI for Science 的發展有何重要性？**  
A：作者採用 Leek 與 Peng 提出的六種資料分析問題類型框架，並將其重新詮釋為六種科學發現能力。不同科學主張——如描述、探索、推論、預測、因果與機制解釋——對資料與方法的要求各不相同，必須符合相應的有效性標準。以能力為導向的評估能精確定位模型在哪些推理環節薄弱，避免把操作能力混同於科學判斷能力，對建構可信賴的 AI 科學家至關重要。

**Q4：SDABench 的核心架構與組成是什麼？**  
A：SDABench 改編自 Leek 與 Peng 的框架，圍繞描述性、探索性、推論性、預測性、因果性與機制性六種能力，橫跨生物、化學、環境、地理與物理五個領域進行設計。它包含 527 筆真實數據實例（SDA-Real）與 6,000 筆合成數據實例（SDA-Synth），每筆實例都提供選擇題與開放式問答兩種形式。整體透過自動化流程建構，結合大型語言模型生成模板、程式化推導標準答案，以及選項生成等步驟。

**Q5：相較於 DataSciBench、KramaBench 等既有基準，SDABench 的主要創新在哪裡？**  
A：SDABench 不再以「能否執行分析流程」為唯一標準，而是根據科學主張類型來組織評估，並首次系統性地納入因果性與機制性推理。它同時提供真實與合成數據、選擇題與開放題，並搭配五階段錯誤分析框架，能診斷模型在哪個推理階段出錯。這種設計讓評估結果更具解釋性，也更能反映模型在真實科學發現中的潛力與風險。

**Q6：SDABench 為何同時採用選擇題與開放題，並結合真實與合成數據？**  
A：選擇題便於自動化評分與大規模比較，但研究發現有時會誘發表層模式匹配，反而降低某些任務的表現；開放題則能測試模型自由推理與論證能力。真實數據確保問題具備真實性與領域相關性，合成數據則透過語意圖建構產生，能擴充規模、控制變異，並涵蓋現實中較難取得的實驗情境。兩者互補，使基準同時具備生態效度與可擴展性。

**Q7：實驗評估了哪些模型，測試範圍涵蓋哪些面向？**  
A：作者評估了 15 個具代表性的大型語言模型，涵蓋不同規模與架構。測試範圍包括 SDA-Real 與 SDA-Synth 兩大子集，橫跨五個科學領域與六種分析能力，並同時檢視選擇題與開放題表現。這樣的設計能從多個維度比較模型的科學推理強項與弱點。

**Q8：實驗的主要發現是什麼？哪些能力對模型來說最困難？**  
A：整體而言，模型在描述性分析上表現較好，但在需要選擇適當假設、潛在過程建模或機制性推理的任務上明顯退步。研究還發現，提供明確選項有時會損害表現，顯示僅依賴選擇題評分可能高估或誤導對模型能力的判斷。此外，即使較先進的模型能更可靠地辨識相關範圍與變數，仍常在選擇分析方法、建模變數關係與得出有效結論上出錯。

**Q9：五階段錯誤分析框架揭示了什麼樣的失敗模式？**  
A：該框架將錯誤定位於理解任務目標、辨識相關範圍與變數、選擇適當分析方法、建立變數間關係，以及推導有效結論等階段。結果顯示，較強大的模型在前端階段（如範圍與變數辨識）進步較明顯，但在中端與後端階段（如方法選擇與結論有效性）仍持續受挫。這說明單一總分無法呈現模型的真實瓶頸，必須細緻拆解才能找出改進方向。

**Q10：SDABench 在實務上可以如何應用？**  
A：SDABench 可作為開發科學 AI 助理的標準化測試平台，幫助研究團隊在部署前評估模型的分析可靠性。它也能用於診斷特定模型在哪些科學推理環節不足，從而指導微調資料設計或提示工程策略。對教育領域而言，這套基準還能協助設計培養數據素養與科學推理的課程與教材。

**Q11：對於建構 AI 科學工具的產品團隊，這篇研究帶來什麼啟示？**  
A：產品團隊不應只以執行成功率或選擇題分數作為能力指標，而需納入假設檢驗、證據界限與結論有效性等科學標準。介面設計應讓使用者能檢視模型在每個推理階段的判斷，例如為何選擇某種統計方法、變數關係如何建立。此外，針對因果與機制性任務，應加入額外驗證機制，避免模型輸出未經檢驗的科學主張。

**Q12：這項研究可能對 AI for Science 領域的評估方式產生什麼影響？**  
A：SDABench 推動評估典範從「執行導向」轉向「主張導向」，強調科學數據分析的最終目的是支持有效的科學主張。這將促使未來基準更重視因果與機制推理、假設意識與不確定性處理，而不只是程式碼正確性。長期來看，這有助於提升 AI 驅動科學發現的可解釋性、可重複性與可信度。

**Q13：SDABench 有哪些可能的限制？**  
A：合成數據雖然能擴充規模，但可能無法完全複製真實實驗中的雜訊、測量誤差與領域脈絡。選擇題形式雖然方便評分，卻可能誘發猜測或模式匹配，無法完整反映開放推理能力。此外，目前涵蓋的五個領域與六種能力仍只是科學研究的一部份，未來需要擴展到更多學科與更複雜的實驗設計情境。

**Q14：根據實驗結果，大型語言模型在哪些任務上最容易失敗？**  
A：模型最容易在需要選擇適當統計假設、進行潛在過程建模，以及提供機制性解釋的任務上失敗。例如，它們可能誤用線性模型處理非線性機制，或把觀察性資料中的相關性直接推論為因果關係。這些失敗顯示模型在整合領域知識、統計方法論與證據評估方面仍有明顯缺口。

**Q15：未來研究可以朝哪些方向改進或延伸？**  
A：未來可開發能顯式推理假設與證據界限的模型，並結合符號推理或統計工具以補強大型語言模型的弱項。評估方式也可朝向互動式或人機協作式發展，讓模型在真實科學家的回饋下修正分析。此外，將基準擴展到實驗設計、資料收集與跨領域知識整合，將更接近完整的 AI 科學家願景。

## 實務應用指南

### 適用場景

1. **AI 科學家助手的能力體檢**  
   研究機構或企業研發部門可利用 SDABench 的六種能力維度（描述性、探索性、推論性、預測性、因果性、機制性分析），定期評估內部使用的大型語言模型在科學數據分析上的真實水準，避免僅以「程式碼是否執行成功」或「工作流程是否完成」作為唯一指標。

2. **跨領域科學數據分析產品的選型與驗收**  
   在生物學、化學、環境科學、地理學、物理學等領域建置智慧分析平台時，可將 SDABench 的 SDA-Real 與 SDA-Synth 作為標準測試集，比較不同模型在選擇題（MCQ）與開放式題（OEQ）上的表現，並透過五階段錯誤分析框架定位模型弱點。

3. **科學教育與研究訓練的診斷工具**  
   大學或研究訓練課程可將 SDABench 的開放式實例轉化為教學案例，幫助學生理解不同科學主張（假設探索、統計推論、機制性解釋）所需的假設與有效性標準，並觀察模型在哪些推理階段出錯。

4. **自動化科學發現管線的風險稽核**  
   當組織部署 AI 驅動的假設生成、實驗設計或論文撰寫系統時，可利用 SDABench 檢驗模型是否會在「選擇適當分析方法」「變數關係建模」「得出有效結論」等關鍵階段產生錯誤，作為上線前的風險把關機制。

5. **合成數據生成與領域擴充的參考架構**  
   資料科學團隊可參考 SDABench 的自動化流程（語意圖建構、LLM 模板生成、程式化標準答案推導、選項生成），為自身領域設計專屬的合成數據實例，以低成本擴充評測或訓練資料。

### 實作前置條件

**資料條件**
- 至少能取得或建置與目標領域對應的科學數據集：真實數據（如 SDA-Real 的 527 筆實例）可用於反映實際場景，合成數據（如 SDA-Synth 的 6,000 筆實例）則用於大規模壓力測試。
- 每筆實例需具備明確的科學主張類型、對應的分析方法、假設與有效性標準，並準備好標準答案或任務特定成功標準。
- 若採用開放式題型，需預先設計可自動評分的規則或準備 LLM-as-a-Judge 的評分提示詞。

**運算條件**
- 可執行 Python 或 R 的運算環境，用於資料前處理、統計檢定、因果推論與機制模擬。
- 能呼叫受測大型語言模型的 API 或本地推論服務；若進行 15 個以上模型的系統性評測，建議具備批次呼叫與結果快取機制。
- 具備足夠的儲存空間保存原始數據、模型輸出、中繼推理過程與錯誤分類結果。

**技能條件**
- 至少一名熟悉統計學、因果推論與領域知識的科學家，負責審核定義科學主張與分析方法。
- 至少一名 AI 工程師，負責模型呼叫、自動化流程建置、評分腳本開發與錯誤分析框架落地。
- 建議具備提示工程（prompt engineering）與 LLM 輸出解析經驗，以便從模型回答中提取推理步驟並對應到五階段錯誤類別。

### 實作步驟建議

1. **定義評測目標與能力維度**  
   依據產品或研究需求，從 SDABench 的六種科學發現能力中選擇優先評測項目。例如，藥物研發團隊可能優先關注因果性分析與機制性解釋，而環境監測團隊則更重視描述性與預測性分析。

2. **準備資料與題型**  
   下載或參照 SDA-Real 與 SDA-Synth 的格式，將資料整理為「選擇題 + 開放式題」兩種形式。對於自有領域資料，可參考 SDABench 的三階段自動化流程：語意圖建構、LLM 模板生成、程式化標準答案推導，再產生干擾選項。

3. **建立評分與錯誤分析機制**  
   針對選擇題設計自動比對邏輯；針對開放式題，設計基於規則或 LLM-as-a-Judge 的評分器。同時導入五階段錯誤分析框架：辨識相關範圍與變數、選擇分析方法、建模變數關係、執行運算、得出有效結論。

4. **執行模型評測與結果收集**  
   批次呼叫目標大型語言模型，記錄每筆實例的原始輸出、推理過程（若模型支援 Chain-of-Thought）與最終答案。建議同時測試有無提供選項的設定，以觀察選擇題是否誘發表面模式匹配。

5. **進行能力導向的診斷報告**  
   不僅呈現總分，而是按能力維度、領域、題型與錯誤階段拆解分數。特別關注模型在「假設選擇」「潛在過程建模」「機制性推理」上的衰退情況，並標註高風險錯誤類型。

6. **回饋至產品設計與模型改進**  
   將診斷結果轉化為產品功能限制清單，例如禁止模型在未經人類確認下進行因果推論；或針對弱項設計專屬微調資料與檢索增強生成（RAG）流程，逐步提升特定科學推理能力。

### 潛在風險與注意事項

- **誤把執行成功當成科學有效**  
  模型可能成功產出程式碼與數值結果，但該結果並不支持預期的科學主張。建議在評分時同時檢驗「計算正確性」與「推論有效性」，並要求模型說明所依據的假設。

- **選擇題誘發表面模式匹配**  
  研究發現，提供明確選項在某些任務類型上反而降低表現。建議不要只依賴 MCQ 評估，應搭配開放式題以觀察模型是否真正理解分析方法。

- **領域知識與統計假設的錯配**  
  不同科學領域對變數關係、因果結構與機制解釋的要求不同。直接套用 SDABench 模板到全新領域時，需由領域專家重新審定假設與有效性標準。

- **開放式題評分的主觀性**  
  LLM-as-a-Judge 可能產生不一致的評分。建議建立多人標註的黃金標準集，定期校正評分器，並對邊界案例進行人工覆核。

- **過度依賴先進模型的「範圍辨識」能力**  
  雖然更強大的模型更能正確識別相關範圍與變數，但在選擇分析方法、建模變數關係與得出結論上仍可能出錯。產品設計應保留人機協作與專家審查環節。

### 與其他技術的整合建議

- **與 LLM Agent 框架整合**  
  可將 SDABench 的六種能力拆解為 Agent 的專門工具（如描述性統計工具、因果推論工具、微分方程模擬工具），並以錯誤分析框架作為反思（reflection）與驗證模組，提升科學發現管線的可靠性。

- **與檢索增強生成（RAG）結合**  
  針對模型在「假設選擇」與「分析方法選擇」上的弱點，可串接領域文獻、統計方法論資料庫與過往實驗紀錄，讓模型在推理時能參考經過驗證的方法與假設。

- **與可解釋性工具（XAI）搭配**  
  在因果性與機制性分析任務中，可結合 SHAP、因果圖（causal graph）或結構方程模型視覺化工具，讓模型輸出不只是結論，還能呈現變數關係與機制路徑，便於專家審查。

- **與 MLOps / 評測平台整合**  
  將 SDABench 的評測腳本與錯誤分類邏輯嵌入持續整合（CI）流程，對每次模型更新進行回歸測試，並在儀表板中呈現各能力維度的趨勢變化。

- **與科學知識圖譜（KG）串接**  
  利用知識圖譜補強模型對領域實體、因果關係與物理機制的理解，特別是在機制性解釋任務中，可將圖譜路徑作為推理依據，降低虛構機制的風險。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從摘要與「適用場景」開始，理解為什麼「程式碼跑得出來」不等於「科學分析正確」，再透過六種能力維度建立對科學數據分析任務的分類直覺；遇到技術細節時，可先略過自動化流程與錯誤分析框架的實作細節，專注於圖表與主要發現。

**給 AI 工程師**  
重點閱讀自動化流程、五階段錯誤分析框架與模型評測結果，思考如何將 SDABench 的資料格式、評分邏輯與錯誤分類機制移植到自家的 LLM 評測平台；特別留意選擇題與開放式題的表現差異，以及模型在假設選擇與機制推理上的失效模式。

**給研究人員**  
建議深入檢視能力導向的評測設計與 Leek & Peng 的六問題框架如何轉化為實際任務，並評估 SDABench 相較於 DataSciBench、KramaBench 等基準測試的互補性；可進一步探討如何將 SDA-Synth 的合成數據方法擴展到自身研究領域。

**給產品經理**  
聚焦於「適用場景」「潛在風險」與「整合建議」，將論文發現轉化為產品需求：例如哪些科學推理能力適合自動化、哪些必須保留人機協作、如何設計驗收測試與風險提示；同時關注 MCQ 與 OEQ 的評測差異，以決定產品中應採用的互動與驗證方式。
