## ⚡ TL;DR

現有PD分離式MoE推論的解碼路由器僅平衡負載，忽略專家局部性，導致同負載下延遲不一。
提出ELDR，從預填充專家激活建立簽章，以平衡K-means離線分群與局部性頻帶路由調度請求。
於vLLM實現並在40GPU部署評估，降低中位數TPOT達5.9%至13.9%且不影響輸出。

## 摘要翻譯

在預填充-解碼（Prefill-Decode, PD）分離式大型語言模型（Large Language Model, LLM）服務中，每個請求在預填充（Prefill）後被指派至一個解碼工作節點（Decode worker）。現有的解碼路由器（Decode router）僅平衡負載；對於混合專家模型（Mixture-of-Experts, MoE）而言，此做法仍顯不完備：負載相同的工作節點其延遲（Latency）可能有所差異，因為每個解碼（Decode）步驟都會載入其批次（Batch）所激活之每個相異專家（Distinct experts）的專家權重（Expert weights）。我們提出 ELDR（Expert-Locality-Aware Decode Routing），一個用於 PD 分離式 MoE 服務的專家局部性感知（Expert-locality-aware）解碼路由器。從請求在預填充階段的專家激活（Expert activation），ELDR 建立一個專家簽章（Expert signature），用以預測該請求在生成（Generation）期間將激活的專家。離線時，平衡式 K-means 分群（Balanced K-means）跨解碼工作節點劃分簽章空間（Signature space）；線上時，局部性頻帶路由（Locality-band routing）將每個請求傳送至與其簽章最匹配的工作節點之中，負載最低者。簽章快取與 KV 快取（KV cache）以 KV 區塊粒度（Block-granular）共同索引（Co-indexed），使簽章與前綴快取（Prefix caching）狀態保持精確一致。在 vLLM 中實作並於多達 40 張 GPU 的部署（Deployment）上評估，ELDR 相較於四個負載平衡（Load balancing）基線（Baseline）中最強者，於三個 MoE 模型與兩個工作負載（Workload）上可降低中位數每輸出 Token 延遲（Time-per-Output-Token, TPOT）達 5.9–13.9%，且模型輸出（Model output）維持不變。

### 核心貢獻（3～5點）
- 提出 ELDR，首個針對預填充-解碼（PD）分離式混合專家模型（MoE）服務的專家局部性感知解碼路由器，揭示單純負載平衡無法保證解碼延遲最優的問題。
- 基於預填充階段的專家激活建立專家簽章（Expert Signature），以預測生成階段的專家使用模式，並透過離線平衡式 K-means 分群與線上局部性頻帶路由，兼顧專家局部性與負載平衡。
- 設計與 KV 快取共同索引、以區塊粒度管理的簽章快取機制，確保簽章在前綴快取（Prefix Caching）情境下仍維持精確一致。
- 於 vLLM 實作並在 40 張 GPU 規模的部署中驗證，相較最強基線可降低中位數 TPOT 達 5.9–13.9%，且不影響模型輸出品質。

### 適合對象
從事大型語言模型（LLM）推論系統、分散式服務架構、混合專家模型（MoE）加速，以及關注預填充-解碼（PD）分離部署與負載平衡策略的研究人員與系統工程師。

## 深度分析

#### 方法論解析

ELDR 的核心問題意識在於：在預填充-解碼（PD）分離架構中，現有解碼路由器（decode router）僅以負載平衡（load balancing）為目標，但對於混合專家模型（MoE）而言，這是不完整的（incomplete）。其根本原因是 MoE 解碼（decode）的記憶體頻寬瓶頸並非來自批次（batch）大小本身，而是來自每個解碼步驟必須載入的「相異專家（distinct experts）聯集（union）」。即使兩個解碼工作節點（decode worker）的負載相等，若其共置（colocation）的請求（request）激活大量不重疊的專家權重（expert weights），延遲（latency）仍會有顯著差異。觀察數據顯示，同領域（same-domain）的解碼批次相較於混合批次（mixed batches），每步驟激活的相異專家數量可減少 17–21%，這構成了「專家局部性（expert locality）」作為路由軸心的物理基礎。

ELDR 的方法論可拆解為四個層次：

**1. 品質篩選專家簽章（Quality-Selected Expert Signature）**
論文發現，預填充（prefill）與解碼（decode）階段的逐專家激活（per-expert activation）具有高度相關性（0.70–0.92）。因此，ELDR 在預填充完成後、預填充-解碼交接（handoff）發生前，從請求的預填充專家激活推導出一個緊湊的專家簽章（expert signature）。此簽章的篩選準則極為關鍵：它不以人類可解釋性或聚類便利性為目標，而是以「簽章鄰近度對解碼階段專家重疊度的預測忠實度」為唯一優化目標。這種與下游分群及路由解耦的設計，確保了簽章空間（signature space）的幾何距離能直接對應到共置後的記憶體頻寬節省。

**2. 離線平衡式 K-means（Balanced K-means）分群**
簽章空間的結構是跨請求聚合才能觀察到的，屬於離線可學習的統計特性。ELDR 在離線階段以平衡式 K-means 將簽章空間劃分為與解碼工作節點數量相等的局部性區域（locality region）。「平衡式」的設計確保每個區域的請求數量均勻，避免純粹按專家相似性聚類導致熱門領域（如程式或數學）過度擁擠。此步驟捕捉了工作負載（workload）的結構，但不繼承其即時偏斜。

**3. 線上局部性頻帶路由（Locality-Band Routing）**
路由決策必須同時滿足兩個資訊邊界不同的目標：專家局部性是聚合屬性，僅能透過離線結構得知；而負載是瞬時屬性，僅在決策當下可觀測。ELDR 將決策沿此資訊邊界切分：線上階段，對於每個請求，先找出其簽章與各工作節點質心距離落在「局部性頻帶（locality band）」內的候選節點集合（即專家最匹配的節點），再從該集合中選擇負載最低者。頻帶強制執行專家局部性，頻帶內的負載選擇則吸收即時偏斜（live skew），單次決策同時服務雙重目標。

**4. 前綴快取一致性簽章（Prefix-Cache-Coherent Signature）**
前綴快取（prefix caching）會使請求跳過預填充階段，導致無法從頭計算專家簽章。ELDR 因此設計了與 KV 快取（KV cache）共同索引（co-indexed）的區塊粒度（block-granular）簽章快取：每個 KV 區塊攜帶其所屬 token 的專家足跡（expert footprint）。當發生快取命中（cache hit）時，無論是部分命中（partial hit）或完全命中（full hit），系統透過加總快取區塊與新計算區塊的簽章，即可恢復完整簽章，且無需重新計算，也不改變原有快取驅逐（cache eviction）邏輯。此設計使 ELDR 能與前綴快取機制無縫組合，簽章快取體積僅占 KV 快取 1% 以下。

值得注意的是，ELDR 僅改變請求被導向哪個解碼工作節點，完全不觸及模型參數、MoE 門控（gating）決策、核心運算或批次處理邏輯。因此模型輸出（model output）與標準 top-k 門控完全一致，屬於零影響（zero-impact）的透明加速。

#### 實驗數據解讀

論文於 vLLM 上實作 ELDR，部署規模達 40 張 GPU，並在三個開源 MoE 模型——Qwen3-30B-A3B、GPT-OSS-120B、Gemma-4-26B-A4B——與兩類工作負載（task 與 language，後者使用 WildChat）上進行評估。

**主要延遲改善**
相較於四種負載平衡基線（baselines，包含輪詢 round-robin、加入最短佇列 join-shortest-queue、二次選擇 power-of-two-choices 等）中最強者，ELDR 降低中位數 TPOT（median TPOT）達 5.9–13.9%。細部分解顯示，任務型工作負載（task workload）的改善幅度（7.0–13.9%）高於語言型工作負載（language workload，5.9–10.0%）。這與圖 1 的領域分離現象一致：任務領域（程式、數學、醫療、法律）的專家激活分佈更為離散，因此同領域共置的收益更大；而語言型流量（如多語言對話）雖亦有分離（不同語言激活不同專家子集），但領域邊界相對模糊。

**專家局部性的量化證據**
實驗數據提供了兩個關鍵的量化支撐：
1. **預測有效性**：三個模型上預填充與解碼的逐專家激活相關性（correlation）高達 0.70–0.92，證明預填充階段的專家簽章確實是解碼階段專家行為的強預測因子。
2. **批次組成影響**：同領域解碼批次相較混合批次，每步驟激活的相異專家數減少 17–21%。這直接轉化為更小的每步驟聯集（per-step union），從而減少記憶體頻寬壓力與 TPOT。

**前綴快取相容性與開銷**
簽章快取與 KV 快取共同索引的設計，使 ELDR 在啟用前綴快取時仍能保持簽章精確。實測顯示簽章快取僅占 KV 快取容量的 1% 以下，對系統記憶體佔用幾無影響，證明此機制的實用性。

**規模推廣性**
論文進一步驗證 ELDR 可推廣至 235B 參數規模的部署，並支援專家平行（expert parallelism）。這顯示專家局部性路由不僅適用於單一節點內的批次調度，也能與大規模模型平行策略共存。

#### 與現有研究的比較

**定位與差異**
現有 PD 分離架構的路由研究主要聚焦兩大系統層目標：一是快取親和性策略（cache-affinity policy），優先將請求路由至已具備可重用 KV 區塊的預填充工作節點（prefill worker）；二是負載平衡策略，透過輪詢、加入最短佇列或二次選擇等方法分散請求。這些方法決定的僅是「請求在哪裡執行」，對模型內部決定 MoE 解碼記憶體頻寬成本的專家激活完全無感知。

ELDR 首次指出，對於 MoE 模型，「同等負載不等於同等延遲」。由於解碼階段是延遲敏感（latency-sensitive）且記憶體頻寬受限的，每步驟載入的相異專家權重數量才是決定 TPOT 的關鍵變因。因此，ELDR 填補了「解碼端 MoE 感知路由」的研究空白。

與其他 MoE 優化研究（如改進門控演算法、專家選擇機制或批次內專家排程）不同，ELDR 的創新層次在於跨工作節點的請求路由（request routing），而非改變模型內部的專家選擇邏輯。這使其成為一種「透明」的系統層優化：模型輸出與標準 top-k 門控完全一致，無需重新訓練或微調模型。

**限制**
1. **預測穩健性**：ELDR 依賴預填充與解碼專家激活之間的穩定相關性。若請求在生成階段主題大幅漂移（例如從法律問題突然轉為數學推導），離線學習的簽章空間劃分可能失效。
2. **離線結構的動態適應**：平衡式 K-means 為離線訓練，若線上工作負載分佈發生長期漂移（如新增未見領域），局部性區域劃分可能過時，需定期重新訓練或線上更新機制。
3. **單點優化**：目前僅針對解碼路由器（decode router）進行優化，未與預填充端路由（prefill-side routing）或 KV 快取親和性進行聯合決策，存在全域次優的可能性。
4. **前綴快取極端情況**：當發生完全快取命中（full cache hit）且無任何新提示詞片段時，簽章完全來自快取歷史。若快取中的簽章來自與當前生成意圖不同的歷史請求，可能導致局部性誤判（雖論文透過區塊粒度設計緩解此問題，但理論上仍存在風險）。

#### 可重現性評估

**有利因素**
- **開源基礎設施**：ELDR 基於廣泛使用的開源推論引擎 vLLM 實作，對熟悉該架構的研究者而言，整合門檻相對較低。
- **公開模型與資料**：實驗使用的 Qwen3-30B-A3B、GPT-OSS-120B、Gemma-4-26B-A4B 均為公開可取得權重之模型；工作負載方面，任務型資料來自公開的程式、數學、醫療、法律資料集，語言型資料使用公開的 WildChat，資料可及性高。
- **評估指標明確**：採用標準的每輸出 Token 延遲（TPOT）、首 Token 延遲（TTFT）與中位數 TPOT，實驗設定與基線對照清晰。

**不利因素與缺口**
- **原始碼釋出狀態不明**：論文未明確聲明是否公開釋出 ELDR 的原始碼（source code）。雖然其邏輯描述詳盡，但「平衡式 K-means」的具體約束條件、「局部性頻帶」的寬度選擇演算法、以及簽章快取與 vLLM KV 快取區塊層級的共同索引實作細節，仍需原始碼方能完全重現。
- **大規模硬體門檻**：40 GPU 乃至 235B 模型的部署實驗，對學術界中小型實驗室而言硬體門檻極高。雖然核心機制理論上可在較小規模驗證，但論文未提供小規模復現指南。
- **超參數敏感度**：簽章維度、K-means 的 K 值、頻帶寬度等超參數對不同模型與工作負載的敏感度分析，在提供的摘要與節錄中著墨有限。

#### 未來研究方向

**1. 線上適應性分群**
將離線平衡式 K-means 擴展為線上或增量式（incremental）分群演算法，使簽章空間劃分能隨工作負載漂移（workload drift）動態調整。例如，可結合串流聚類或基於請求到達分佈的週期性微調，避免離線模型過時。

**2. 聯合多目標路由**
目前 ELDR 專注於專家局部性與負載平衡的二維權衡。未來可探索將 KV 快取親和性（cache affinity）、專家局部性（expert locality）與即時負載（live load）納入統一的三目標聯合優化框架，從預填充（prefill）到解碼（decode）的全鏈路進行全域路由決策。

**3. 自適應局部性頻帶**
設計動態調整局部性頻帶（locality band）寬度的機制。在系統高負載時縮小頻帶以強制專家局部性、降低記憶體頻寬壓力；在低負載時放寬頻帶，給予負載平衡更大的彈性，避免熱點節點形成。

**4. 逐層與深度感知簽章**
當前簽章似乎為全域聚合表示。未來可研究逐層（layer-wise）或深度感知（depth-aware）的專家簽章，捕捉請求在生成過程中不同解碼深度專家激活模式的演變，進一步提升預測精準度。

**5. 與專家平行（Expert Parallelism）的深度整合**
論文初步驗證了 235B 規模部署，但未詳述在專家平行策略下，跨節點的專家分片（expert sharding）如何與局部性頻帶交互作用。未來可研究當目標專家權重已分散在不同節點時，路由決策是否應同時考慮專家權重的網路傳輸成本與記憶體頻寬成本。

**6. 強化前綴快取極端情境**
針對完全快取命中（full cache hit）導致無預填充信號的極端情況，可探索結合請求元資料（如應用程式類別、使用者歷史標籤）或輕量級前綴編碼器，輔助推導專家簽章，降低對預填充激活的絕對依賴。

## 論文問答

**Q1：在預填充-解碼（PD）分離的混合專家模型（MoE）服務中，ELDR 旨在解決什麼核心問題？**
A：在現有的 PD 分離架構中，解碼路由器通常僅考量負載平衡，將請求均勻分配至各解碼工作節點，但對於 MoE 模型而言，這種做法並不足以優化延遲。這是因為每個解碼步驟都必須載入該批次所激活的所有相異專家權重，因此即使兩個工作節點的負載完全相同，若其批次激活的專家聯集大小不同，實際的每輸出 Token 延遲（TPOT）也會有顯著差異。ELDR 正是為了解決這個問題，提出以專家局部性作為路由依據，從而降低記憶體頻寬瓶頸並縮短解碼延遲。

**Q2：為何現有的負載平衡解碼路由器在 MoE 模型上表現不佳？**
A：現有的負載平衡策略（例如輪詢或最短佇列優先）將解碼工作節點視為同質資源，僅根據即時佇列長度或請求數量進行分派，完全忽略了 MoE 模型內部的專家激活結構。然而，相關請求具有強烈的專家局部性：來自相同領域的請求傾向激活重疊的專家子集，而混合批次則會激活多達 17–21% 的額外相異專家。現有路由器將性質相近的請求打散至不同節點，導致每個工作節點在每個解碼步驟都必須載入更大的專家聯集，直接推升了記憶體頻寬需求與 TPOT。

**Q3：專家局部性為何是影響 MoE 服務延遲的關鍵路由軸線？**
A：解碼階段屬於延遲敏感且記憶體頻寬受限的過程，而載入批次內所有相異專家的權重是構成每步驟延遲的主要來源之一，因此減少每步驟需載入的專家數量可直接加速生成。研究顯示，預填充與解碼階段的專家激活具有高度相關性（0.70 至 0.92），這表示請求的提示詞階段已能可靠預測其在生成階段將激活哪些專家。基於此特性，ELDR 能夠在路由時將具有重疊專家需求的請求共置於同一工作節點，從而縮小每步驟的專家聯集，在不改變模型輸出的前提下有效提升 TPOT。

**Q4：ELDR 的核心方法論包含哪些主要元件？**
A：ELDR 首先從每個請求的預填充專家激活狀態中，提取出一個緊湊的專家簽章，用以預測該請求在後續解碼階段將激活的專家集合。在離線階段，系統採用平衡式 K-means 分群演算法將簽章空間劃分為多個區域，並將每個區域對應至特定的解碼工作節點，以捕捉請求間的結構性局部性。在線上階段，局部性頻帶路由機制則會在與請求簽章最匹配的一群工作節點中，選擇當前負載最低者來處理該請求，同時兼顧專家局部性與即時負載平衡。

**Q5：相較於先前的方法，ELDR 的關鍵創新是什麼？**
A：ELDR 的關鍵創新在於將專家簽章的品質篩選標準與後續的分群和路由邏輯解耦，僅以「簽章距離能多大程度忠實預測解碼階段的專家重疊度」作為簽章選擇的唯一準則，確保表示法直接服務於最終目標。另一項創新是提出與 KV 快取共同索引的區塊粒度簽章快取，即使發生前綴快取命中而跳過預填充，也能透過累加已快取區塊的簽章來恢復完整資訊，無需重新計算。這使得 ELDR 能夠與現有的前綴快取機制無縫整合，在不改變模型輸出的情況下實現專家感知的路由。

**Q6：ELDR 為何選擇離線使用平衡式 K-means、線上使用局部性頻帶路由？**
A：這項設計決策源於兩種資訊的本質差異：專家局部性是跨大量請求才能顯現的聚合特性，適合透過離線的歷史資料學習穩定的空間結構，因此使用平衡式 K-means 進行分群；而負載則是隨時間波動的瞬時狀態，只能在決策當下觀測，因此交由線上機制處理。局部性頻帶路由先以頻帶限制候選節點必須與請求簽章足夠相似，確保專家局部性，再從中挑選負載最低者以吸收即時的負載傾斜。這種離線與線上的職責分離，有效避免了純局部性路由導致的熱門領域過載，以及純負載平衡造成的相似請求打散問題。

**Q7：論文採用了哪些實驗設定與基準測試來評估 ELDR？**
A：作者將 ELDR 實作為 vLLM 上的一層輕量級擴充，並在最多 40 張 GPU 的部署環境中進行評估，測試對象涵蓋三個 MoE 模型：Qwen3-30B-A3B、GPT-OSS-120B 與 Gemma-4-26B-A4B。工作負載方面，實驗同時包含任務型工作負載（涵蓋程式、數學、醫療與法律等領域）以及語言型工作負載（來自 WildChat 的多語言對話流量）。評估比較了四種負載平衡基線方法，以驗證 ELDR 在不同模型架構與流量模式下的有效性。

**Q8：ELDR 取得了哪些主要的效能提升成果？**
A：實驗結果顯示，相較於最強的負載平衡基線，ELDR 在任務型工作負載上可降低中位數 TPOT 達 7.0–13.9%，在語言型工作負載上則可降低 5.9–10.0%，且此成效橫跨全部三個受測模型。這些效能增益的記憶體代價極低，其專家簽章快取僅佔 KV 快取容量的 1% 以下。更重要的是，由於 ELDR 僅改變請求導向哪個解碼工作節點，並未更動 MoE 門控決策、核心運算或批次排程，因此模型輸出與標準 top-k 門控完全一致，確保了結果的正確性。

**Q9：ELDR 是否能推廣至更大規模或不同配置的部署環境？**
A：論文進一步展示 ELDR 可推廣至 235B 參數規模的部署，且能在專家平行（expert parallelism）設定下運作，顯示其具備擴展至更大模型與更複雜分散式架構的潛力。區塊粒度的簽章快取設計使其在面對部分命中、完全命中或快取驅逐等前綴快取情境時，仍能保持簽章的精確性與低開銷。綜合來看，ELDR 在三種截然不同的模型架構與兩種工作負載類型上均展現穩定的 TPOT 改善，顯示其對於不同的專家配置與流量模式具有良好的穩健性。

**Q10：在哪些實際生產場景中，ELDR 能發揮最大效益？**
A：ELDR 特別適合部署於處理多樣化、多租戶流量的雲端 LLM 服務平台，例如同時服務程式碼輔助、數學推理、法律文件分析與多語言對話等應用。在這些場景中，不同領域的請求自然會激活不同的專家區域，ELDR 能將具有相似專家足跡的請求共置於同一解碼節點，避免無關領域混合批次所造成的記憶體頻寬污染。任何已採用 PD 分離架構、使用 MoE 模型並具備前綴快取機制的推論服務，都能以極低的整合成本導入 ELDR 並獲得延遲改善。

**Q11：部署 ELDR 在實務上需要考慮哪些成本與整合需求？**
A：ELDR 僅作為現有 PD 分離堆疊（如 vLLM）上的一層輕量級路由邏輯，僅改變請求最終導向的解碼工作節點，而不觸及模型權重、MoE 門控決策、GPU 核心或批次排程，因此工程風險與整合成本相當低。其專家簽章快取僅增加不到 KV 快取 1% 的額外記憶體開銷，在生產環境中幾乎可忽略不計。此外，由於 ELDR 完全不影響模型輸出，營運團隊無需進行輸出品質回歸驗證，可直接在現有服務上無縫部署。

**Q12：ELDR 可能對未來 MoE 模型服務系統的設計產生什麼影響？**
A：ELDR 將專家局部性提升至與負載平衡、快取親和性同等重要的第一級路由目標，證明未來的推論路由器應具備模型結構感知能力，而非將運算節點視為黑箱。透過驗證預填充激活可高度預測解碼行為，此研究為 PD 分離架構中的跨階段協同優化開闢了新方向。長遠來看，這也可能激勵 MoE 訓練與服務的聯合設計，例如在訓練階段即考量專家專業化與部署時的可預測性，使模型天生具備更利於局部性感知的激活結構。

**Q13：ELDR 的設計存在哪些內在限制或隱含假設？**
A：ELDR 的路由成效高度依賴預填充與解碼階段專家激活之間的強相關性，雖然實驗中觀察到 0.70 至 0.92 的高相關性，但這仍非完美預測，表示解碼階段仍存在一定程度的不可預測變異。離線的平衡式 K-means 分群亦假設工作負載的領域分佈在時間維度上具有足夠的穩定性，若流量特性發生劇烈且持續的飄移，預先劃分的簽章區域可能逐漸失效。此外，ELDR 目前僅優化解碼工作節點的請求放置，並未進一步調整節點內部的批次排程策略或專家平行配置，仍有部分延遲優化空間未被觸及。

**Q14：在什麼情況下，ELDR 可能無法改善效能，甚至導致表現下降？**
A：若輸入請求在專家激活上呈現高度隨機或對抗式分佈，使得簽章空間中不存在明顯可聚集的結構，則局部性頻帶機制無法縮小每步驟的專家聯集，反而會因限制候選節點數量而損害負載平衡。同樣地，當某一特定領域的流量突然暴增時，該簽章區域對應的局部性頻帶可能將過多請求導向少數幾個工作節點，形成熱點，這是純負載平衡策略原本可以避免的。雖然 ELDR 透過在頻帶內選擇負載最低者來緩解此問題，但若頻帶內所有節點均處於高負載狀態，其 TPOT 仍可能暫時高於純負載平衡基線。

**Q15：ELDR 為未來研究指出了哪些可能的方向？**
A：未來研究可將專家局部性感知路由擴展至預填充階段，或進一步整合快取親和性、負載平衡與專家局部性為單一統一的路由最佳化框架。另一個方向是讓離線分群模型具備線上動態更新能力，使其能隨工作負載分佈漂移自動調整簽章區域劃分，減少對週期性離線重新訓練的依賴。此外，從模型訓練階段即聯合設計專家專業化與服務局部性——例如透過輔助目標鼓勵專家激活模式更具可預測性與可聚集性——將有機會從源頭放大 ELDR 這類路由器的效益。

## 實務應用指南

### 適用場景

1. **高併發 MoE 模型 API 服務**：企業級推理平台（如基於 Qwen3-30B-A3B、Gemma-4-26B-A4B 或 GPT-OSS-120B 的對外 API）需同時服務數百至數千條請求，且對每輸出 Token 延遲（TPOT）極度敏感。當純負載平衡已無法解決記憶體頻寬瓶頸時，ELDR 可透過專家局部性降低 5.9–13.9% 的中位數延遲。
2. **多領域混合工作負載的內部 LLM 閘道器**：同一路由器後方混合程式碼生成、數學推理、醫療問答與法律文件分析等任務。這些領域會激活截然不同的專家子集（如圖 1 所示），ELDR 能將同領域請求共置於相同解碼工作節點，減少每步驟需載入的相異專家權重聯集。
3. **多語言客服與內容生成**：服務中英日韓、俄語或法語等請求的場景。語言本身即構成強烈的專家激活分群，ELDR 的簽章空間分群可自然將不同語言導向最適合的解碼工作節點，降低跨語言混合批次帶來的權重載入開銷。
4. **具前綴快取優化的長上下文應用**：RAG 系統、程式碼補全或客服機器人等大量請求共享系統提示詞（system prompt）或文件前綴。ELDR 的區塊粒度簽章快取與前綴快取共同索引，能在快取命中時直接恢復完整專家簽章，無需重新執行預填充門控。
5. **大規模 PD 分離叢集**：xP yD 架構下超過 20–40 張 GPU 的部署。當解碼工作節點數量增加，單純負載平衡會將領域相關的請求打散至全叢集，導致每步驟激活的相異專家數量趨近理論上限；ELDR 的離線分群與線上局部性頻帶路由在此規模下效益最為顯著。

### 實作前置條件

- **模型限制**：必須為混合專家模型（Sparse MoE），且系統需能取得預填充階段的門控決策（gating decisions）或專家激活索引。Dense 模型無專家局部性可言，不適用。
- **系統架構**：已採用預填充-解碼（PD）分離架構（如 vLLM 的 disaggregated serving、Mooncake 或類似系統），具備獨立的預填充工作節點池與解碼工作節點池，並存在預填充至解碼的請求交接點。
- **數據需求**：需收集代表性工作負載的預填充專家簽章（expert signature）作為離線分群樣本。建議至少涵蓋數十萬至百萬級請求，以確保 balanced K-means 的 centroid 能反映真實分布。
- **運算資源**：簽章快取僅佔 KV 快取 1% 以下的額外記憶體；離線分群計算僅需一般 CPU 叢集。線上路由決策為輕量距離計算與負載查詢，無額外 GPU 開銷。
- **技能需求**：需熟悉 vLLM 原始碼（特別是 scheduler、block manager 與 router 模組）、分散式推理架構，以及具備修改 C++/Python 推論引擎與叢集排程層（Kubernetes/Slurm）的能力。

### 實作步驟建議

1. **專家簽章萃取與品質驗證**：在預填充工作節點中攔截每層 MoE 門控的 top-k 專家索引，將其編碼為緊湊簽章（如多層激活的布林向量或壓縮索引）。驗證預填充與解碼階段專家激活的相關性，論文顯示需達 0.70–0.92 方具預測價值。
2. **離線簽章空間分群**：執行平衡式 K-means（balanced K-means）將高維簽章空間劃分為與解碼工作節點數量相等的區域。此處「平衡」指每個分群的請求量相近，避免特定 worker 成為熱點。產出的 centroid 配置檔應版本化並部署至所有路由節點。
3. **線上局部性頻帶路由實作**：在解碼路由器實作兩階段決策：先計算請求簽章與各 worker centroid 的距離，選出最匹配的「局部性頻帶」（例如 top-2 或 top-3 最近 centroid），再從該頻帶內選取當前負載最低（如佇列最短或 GPU 利用率最低）的工作節點。
4. **前綴快取一致性整合**：將簽章快取與現有 KV 快取的區塊管理器（block manager）共同索引。每個 KV 區塊儲存對應 token 區間的局部專家簽章；發生前綴快取命中時，累加命中區塊的簽章與新鮮計算區塊的簽章，即可恢復完整簽章，無需重新執行門控。
5. **漸進式上線與 Shadow 驗證**：先於小規模叢集（如 4P4D）部署，與 Round-Robin、Least-Loaded 等基線進行 shadow 比較。確認 TPOT 改善幅度符合預期（5–14%），且模型輸出與基線完全一致（bit-exact，因 ELDR 不改變門控決策）後，再推廣至生產叢集。

### 潛在風險與注意事項

- **冷啟動與分布偏移**：若線上工作負載與離線訓練資料分布差異過大（例如突然湧入全新領域或未曾見過的語言），簽章分群可能失效。建議保留 fallback 機制：當請求簽章與所有 centroid 距離過遠時，直接退回純負載平衡路由。並建立定期（如每週）重新計算 centroid 的管線。
- **簽章快取記憶體競爭**：雖然簽章快取僅佔 KV 快取 1% 以下，但在極高併發且前綴命中頻繁的場景，區塊粒度的共同索引可能與 vLLM 的 block allocator 產生鎖競爭。建議將 signature cache 置於獨立的 pinned memory pool，或採用無鎖資料結構管理。
- **負載震盪與頻帶寬度調校**：局部性頻帶過窄會導致請求過度集中於特定 worker，反而造成記憶體頻寬瓶頸；過寬則失去專家局部性效益。頻帶大小應依叢集規模與工作負載動態調整，可透過線上控制迴路（如依據 worker 佇列長度回饋）自動縮放。
- **專家平行（Expert Parallelism, EP）的複雜度**：當模型採用 EP 時，單一解碼工作節點可能不具備全部專家權重，需透過 all-to-all 通訊取得遠端專家。論文顯示 ELDR 可擴展至 235B 部署，但實作中必須確認專家權重的節點放置策略，避免局部性最佳化與 EP 通訊模式產生衝突。

### 與其他技術的整合建議

- **與 Prefix Caching 原生整合**：ELDR 的簽章快取設計本質上就是與前綴快取共生。建議直接整合進 vLLM 的 Prefix Caching 模組（v0.5+ 的 block manager），讓 signature 隨 KV 區塊一起被雜湊、命中、驅逐與重用，無需額外快取管理邏輯。
- **與 Cache-Affinity Prefill Router 疊加**：現有 PD 分離系統常採用快取親和性預填充路由（將請求導向已具備可重用 KV 區塊的預填充節點以優化 TTFT）。ELDR 專注於解碼側路由以優化 TPOT，兩者正交：prefill 端降低首 Token 延遲，decode 端降低每輸出 Token 延遲，可同時啟用。
- **與 Continuous Batching 及 Speculative Decoding 共存**：ELDR 不改變模型輸出與批次調度邏輯，因此可與 continuous batching 無縫整合。若同時使用推測解碼（speculative decoding），建議僅以 target model 的預填充簽章作為路由依據，因 draft model 的專家激活模式可能與 target model 不同。
- **與 Kubernetes / 雲端自動擴縮整合**：在容器化環境中，可將 balanced K-means 的 centroid 配置儲存為 ConfigMap 或分散式鍵值儲存（如 etcd），解碼路由器以 sidecar 形式讀取，實現分群策略的熱更新，無需重建容器映像檔或重啟服務。

### 給不同背景讀者的閱讀建議

- **初學者**：這篇論文假設讀者已具備 MoE 架構與 PD 分離的基本知識。建議先建立直覺：「為何把同類請求送到同一台機器能加速？」關鍵在於減少每步驟載入的相異專家權重。接著聚焦圖 1 與局部性頻帶路由的概念——就像把同類書籍放在同一書架以減少走動時間。離線 K-means 與簽章表示的數學細節可暫時略過。
- **AI 工程師**：重點關注實作細節：簽章如何從預填充門控萃取、品質篩選的標準為何、signature cache 與 KV cache 的共同索引結構，以及與 vLLM 整合時的程式碼切入點。論文強調「不改變模型輸出」這一點對生產環境至關重要，代表導入風險極低，可直接評估上線。
- **研究人員**：核心貢獻在於將「專家局部性」形式化為可預測、可路由的訊號，並巧妙地分離離線結構（balanced K-means 捕捉長期分布）與線上動態（locality-band routing 吸收即時負載震盪）。可延伸思考：簽章表示是否可透過小型網路學習（learned signature）而非啟發式選取？動態分群（online clustering）能否更好適應分布偏移？與專家平行策略的聯合優化亦是值得探索的方向。
- **產品經理**：這是一項「零成本提升效能」的基礎設施技術——不改變模型行為、不影響輸出品質，僅透過更聰明的請求調度降低延遲。評估導入時，請確認你的服務是否採用 MoE 模型、是否已實施 PD 分離，以及工作負載是否具有明顯的領域或語言分群。TPOT 降低 5–13% 可直接換算為單位 GPU 吞吐量提升或雲端運算成本節省。
