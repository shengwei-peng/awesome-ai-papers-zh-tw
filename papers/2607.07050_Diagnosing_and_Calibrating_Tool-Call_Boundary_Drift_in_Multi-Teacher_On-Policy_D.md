## ⚡ TL;DR

多教師 on-policy 蒸餾會引發工具呼叫邊界偏移，使模型在不該呼叫時過度呼叫。
提出 Soft Clamp，以逐 token 散度校準動態壓縮極端 JSD 並保留梯度。
在 APIGen-MT 上將過度呼叫從 13.7% 降至 9.0%，並在 BFCL 減少工具呼叫迴圈。

## 摘要翻譯

具代理性質的語言模型（agentic language models）必須學習何時呼叫工具（call tools）、何時接收並利用工具回應，以及何時直接回答（answer directly）。這使得多教師 on-policy 蒸餾（multi-teacher on-policy distillation, MOPD）成為一種自然的訓練策略：一位教師可專精於工具呼叫（tool calls），另一位專精於直接回應（direct responses），而學生模型（student）可在自身生成的分布（distribution）上同時向兩者學習。我們顯示，此策略可能引發一種僅從聚合損失（aggregate losses）無法察覺的行為轉變。在雙教師工具使用設定中，基礎廣義知識蒸餾（vanilla generalized knowledge distillation, GKD）提升了工具呼叫召回率（tool-call recall），但同時也使模型趨向過度呼叫工具（over-calling），即在不該使用工具、應直接回答的範例上仍呼叫工具。僅憑聚合層級的解釋並不足夠：工具呼叫樣本並未獲得更多的 token 曝光量（token exposure），而工具呼叫教師的全序列逐 token 散度（full-sequence per-token divergence）也並未更大。我們轉而分析行為槓桿不平衡（behavior leverage imbalance）：在模式進入 token（mode-entry tokens）與結構位置（structural positions），例如 `<tool_call>` 與函式名稱（function names）上的局部逐 token 訊號，可能對整體生成模式（generation mode）產生不成比例的控制。我們提出 Soft Clamp（軟截斷），一種逐 token 散度校準（per-token divergence calibration）方法，可在保留非零梯度（nonzero gradients）的同時，動態壓縮極端的逐 token 詹森-香農散度（Jensen-Shannon divergence, JSD）。在 APIGen-MT 上，相較於基礎 GKD，Soft Clamp 將過度呼叫工具的比例從 13.7% 降至 9.0%，同時維持與其相當的決策準確率（decision accuracy）。在 BFCL 多輪診斷中，它也能減少 GKD 變體中的工具呼叫迴圈（tool-call loops）與重複呼叫（repeated calls）。這些結果顯示，多教師 OPD 應監控教師訊號作用的位置，而非僅關注其聚合層級的大小。

### 核心貢獻（3～5點）
- 揭示多教師 on-policy 蒸餾（MOPD）中的工具呼叫邊界偏移（Tool-Call Boundary Drift）現象：基礎 GKD 雖提升工具呼叫召回率，卻同時使模型趨向過度呼叫工具。
- 提出行為槓桿不平衡（Behavior Leverage Imbalance）分析視角：模式進入 token（如 `<tool_call>`）與結構位置（如函式名稱）的局部訊號，對整體生成模式具有不成比例的控制力。
- 設計 Soft Clamp（軟截斷）方法：一種逐 token 散度校準機制，能動態壓縮極端詹森-香農散度（JSD），同時保留非零梯度以持續學習。
- 在 APIGen-MT 與 BFCL 多輪基準上驗證：Soft Clamp 降低過度呼叫、工具呼叫迴圈與重複呼叫，且維持與基礎 GKD 相當的決策準確率。
- 指出多教師蒸餾的監控重點應從「聚合損失大小」轉向「教師訊號作用的結構位置」。

### 適合對象
本論文適合研究具代理性質語言模型（agentic language models）、工具使用（tool use / function calling）、知識蒸餾與多教師訓練的研究者與工程師，特別是關注蒸餾過程中行為對齊、過度呼叫、決策邊界，以及希望從 token 層級診斷與校準模型行為的讀者。

## 深度分析

#### 方法論解析

##### 1. 多教師 on-policy 蒸餾（Multi-Teacher On-Policy Distillation，MOPD）的設定
本文研究的訓練場景是：學生模型（student）在自身生成的軌跡（rollouts）上，同時接受兩位教師模型的監督。一位是工具呼叫教師（tool-call teacher），專精於結構化函式呼叫；另一位是回應教師（response teacher），專精於直接自然語言回答。訓練目標採用 Generalized Knowledge Distillation（廣義知識蒸餾，GKD）的逐 token 損失，即對學生與教師的下一個 token 分布計算 Jensen-Shannon divergence（詹森-香農散度，JSD）：

\[
d_i = \mathrm{JSD}\bigl(p_t(\cdot \mid x,y_{<i}) \,\|\, p_s(\cdot \mid x,y_{<i})\bigr)
\]

其中 \(p_t\) 與 \(p_s\) 分別為教師分布（teacher distributions）與學生分布。實作上，為了效率，兩者都在教師回傳的前 32 個 token 上重新正規化，因此所測量的 JSD 是一種 top-k 近似。序列損失則對所有受監督目標位置上的 \(d_i\) 取平均。此外，作者加入一個固定的 supervised format anchor（監督格式錨點），只在資料集來源的軌跡上作用，以確保工具呼叫的文本協議不會被破壞；這個錨點在所有 GKD 變體中保持一致，不屬於本文提出的損失修正。

##### 2. 行為槓桿不平衡（behavior leverage imbalance）的診斷視角
本文的核心論點不在於提出一個全新的蒸餾架構，而在於指出：聚合損失（aggregate losses）無法反映行為邊界的偏移。作者發現，在 APIGen-MT 的工具使用設定中，vanilla GKD 雖然提升了工具呼叫召回率（tool-call recall），卻也提高了過度呼叫工具（over-calling）的比例。為了解釋這個現象，他們提出「行為槓桿」的概念：某些 token 位置（如 `<tool_call>`、函式名稱（function names）、結構位置（structural positions））對整體生成模式（generation mode）具有不成比例的控制力。改變這些模式進入 token（mode-entry tokens）會重新導向未來軌跡（future trajectory）；而自然語言回應的訊號通常分散在許多內容 token 上，每個 token 的局部影響較小。因此，即使工具呼叫教師的總曝光量或總散度並未較大，其訊號若集中在高槓桿位置，就足以彎曲（bend）決策邊界。

這個診斷框架與傳統的「token 難度」觀念不同。一個內容 token 可能有很高的 JSD，但修正它只會改變局部用詞；一個結構 token 的 JSD 即使相近，卻可能改變整條軌跡的類型。作者也透過 targeted-clamp diagnostics（目標截斷診斷）進一步驗證：只截斷前幾個進入 token 並無法完全重現 Soft Clamp 的效果，說明高槓桿訊號也可能出現在後續結構位置或教師不偏好軌跡位置（teacher-dispreferred trajectory positions）。

##### 3. Soft Clamp（軟截斷）的設計
針對上述問題，作者提出 Soft Clamp，一種輕量的逐 token 散度校準（per-token divergence calibration）方法。對於每個 token 的散度 \(d_i\)，Soft Clamp 使用一個分離批次閾值（detached batch threshold）\(\tau\)：當 \(d_i \le \tau\) 時保持不變；當 \(d_i > \tau\) 時，以一個分離因子（detached factor）進行縮放。這樣的設計同時達到兩個目的：

- **限制前向貢獻（forward contribution）**：極端散度不會在損失中佔據過大權重，從而降低高槓桿位置對模型決策邊界的過度牽引。
- **保留非零梯度（gradient）**：與 hard clipping（硬截斷）直接將超過閾值的部分截平不同，Soft Clamp 仍對困難 token 提供學習訊號，避免因梯度消失而損害召回率。

具體而言，可將其視為一種「軟性壓縮」映射：極端值被壓低，但不被完全消除；閾值與縮放因子都從批次統計中分離（detached），因此不會反向傳播到這些超參數的估計上，只影響學生對個別 token 的學習強度。這種局部化（localized）處理與 Global Reweight（全局重加權）形成對比，後者對所有 token 一視同仁地調整權重，可能同時壓抑了本應保留的正常學習訊號。

##### 4. 與其他校準策略的比較
作者將 Soft Clamp 與四種替代方案進行概念性比較：

- **Hard Clip**：直接將超過閾值的散度截斷到閾值。簡單有效，但會完全丟失極端 token 的梯度，可能傷害工具呼叫召回率。
- **Global Reweight**：對所有 token 的散度進行全局加權。雖然能降低整體散度規模，但缺乏局部性，無法區分高槓桿結構位置與一般內容位置。
- **Inference-time entry bias（推論時進入偏置）**：在部署階段對模式進入 token 加入偏置，以抵消訓練產生的邊界偏移。這需要對每個 checkpoint 進行驗證調參（per-checkpoint validation tuning），部署成本較高。
- **Soft Clamp**：在訓練階段局部壓縮極端散度，無需推論時調參，兼具梯度保留與局部性。

這四種方法構成一個校準光譜：從完全截斷到全局調整，再到局部壓縮與推論時補償。Soft Clamp 的設計目標是在這個光譜中取得較佳平衡。

#### 實驗數據解讀

##### 1. APIGen-MT 上的決策與過度呼叫
在 APIGen-MT 工具使用評估資料集上，作者比較了 vanilla GKD 與 Soft Clamp 的表現。關鍵結果是：

- Vanilla GKD 在提升工具呼叫召回率的同時，過度呼叫工具（over-calling）比例達到 **13.7%**。
- Soft Clamp 將過度呼叫比例降至 **9.0%**，同時保持與 vanilla GKD 相當的決策準確率（decision accuracy）。

這個結果具有兩層意義。第一，它證實了「邊界偏移」確實存在：模型並非單純地「學得更好」，而是在應直接回答（direct answers）的樣本上也更傾向進入工具呼叫模式。第二，Soft Clamp 的校準並未以犧牲應呼叫樣本的表現為代價，說明極端散度的壓縮並未削弱模型在真正需要工具時的召回能力。這與 hard clipping 的擔憂形成對照——若截斷過度，可能同時壓抑工具呼叫教師在高槓桿位置的訊號，導致 under-calling（工具呼叫不足）。

##### 2. Token-level JSD 集中度
圖 1 顯示了不同方法下 token-level JSD 的集中度。Vanilla GKD 的極端散度集中在少數 supervised token 上，而 Soft Clamp 與 Global Reweight 都能降低這種集中度。值得注意的是，作者發現工具呼叫樣本並未在訓練中獲得更多的 token 曝光量（token exposure），全序列逐 token 散度（full-sequence per-token divergence）也並未在工具呼叫教師上更大。這排除了幾種常見的聚合解釋：

- 不是因為工具呼叫樣本數量較多。
- 不是因為工具呼叫 token 的總散度較大。
- 不是因為回應教師的訊號較弱。

因此，行為偏移必須從「訊號落在何處」來理解，而非僅從「訊號總量」來理解。這也說明為何單純監控 aggregate losses 會誤導：兩個訓練過程的總損失可能相近，但一個會過度呼叫工具，另一個不會。

##### 3. BFCL 多輪診斷
在 Berkeley Function Calling Leaderboard（BFCL）多輪診斷中，Soft Clamp 相較於其他 GKD 變體降低了工具呼叫迴圈（tool-call loops）與重複呼叫（repeated calls）的發生率。這是邊界偏移在實際應用中的典型症狀：當模型傾向於進入工具呼叫模式後，即使已獲得足夠觀察，仍可能持續呼叫工具，造成延遲與成本（latency and cost）上升。Soft Clamp 在這裡展現了其在多輪（multi-turn）互動中的穩定性優勢。

##### 4. 模型規模與種子穩定性
實驗涵蓋 9B 與 4B 兩種模型規模。Soft Clamp 在 9B 模型上展現出較強的校準效果，且在三個評估種子（seeds）上的標準差較低，顯示其訓練過程較為穩定。在 4B 模型上則仍具競爭力。這暗示 Soft Clamp 的效益可能隨模型容量提升而更為明顯，但即使在較小模型上也不會顯著劣於 baseline。

##### 5. 實驗設計的細節限制
需要留意的是，主實驗使用混合軌跡來源：80% 來自學生當前策略（\(\lambda=0.8\)），20% 來自資料集軌跡。這種 on-policy distillation（on-policy 蒸餾）設定使得學生會不斷在自己的分布上學習，邊界偏移可能因此放大。此外，工具呼叫目標必須先預先渲染（pre-render）為聊天模板的文本形式；若忽略此實作細節，模型可能學到無效 schema，即使決策指標看起來合理。這也提醒重現者：資料前處理與模板格式對結果有重大影響。

#### 與現有研究的比較

##### 1. 相對於傳統 GKD 的改進
Generalized Knowledge Distillation（廣義知識蒸餾，GKD）本身強調在學生自身 rollouts（軌跡採樣）上進行知識轉移，以解決教師分布與學生分布不一致的問題。本文並未否定 GKD，而是指出其在多教師（multi-teacher）情境下的隱藏風險：當不同教師監督異質行為（heterogeneous behaviors）時，局部 token 訊號可能彎曲全局決策邊界。Soft Clamp 可視為對 GKD 損失的一種輕量修正，而非替代方案。

##### 2. 相對於單一教師蒸餾的優勢與代價
多教師架構的優勢在於 specialization（專業化）：工具呼叫教師與回應教師可以各自專精，無需人工合併異質行為。然而，本文揭示的代價是：兩位教師的訊號在「槓桿位置」上分布不均，容易導致行為邊界偏移。這與過去許多多教師蒸餾研究主要關注「如何融合教師知識」不同，本文更關注「教師訊號在何處作用」。

##### 3. 相對於推論時校準的差異
Inference-time entry bias（推論時進入偏置）是一種常見的補償手段：若發現模型過度傾向工具呼叫，可在解碼時對直接回答的進入 token 給予額外分數。本文將其納入比較，並指出其缺點在於需要對每個 checkpoint 進行驗證調參，增加部署成本。Soft Clamp 則在訓練階段完成校準，推論時無需額外調整，這在需要頻繁更新模型或部署至多個場景時更具實用價值。

##### 4. 相對於其他損失裁剪方法的特色
Hard clipping 與 Global Reweight 都是常見的損失裁剪或重加權策略。Soft Clamp 的獨特之處在於：

- **局部性**：只作用於超過批次閾值的極端 token，不改變大多數正常 token 的學習動態。
- **梯度保留**：不像 hard clipping 完全截斷，Soft Clamp 仍保留非零梯度，對困難樣本持續學習。
- **自適應性**：閾值與縮放因子來自批次統計，無需手動設定固定超參數。

##### 5. 限制與未解決問題
本文的診斷框架明確定位為「診斷性詮釋（diagnostic interpretation）」，而非完整的因果分解（causal decomposition）。作者並未聲稱已完全證明行為槓桿不平衡是過度呼叫的唯一成因。此外，實驗僅聚焦於工具使用領域，Soft Clamp 在其他需要模式切換的任務（如程式碼生成、多輪規劃）是否同樣有效，仍需驗證。最後，top-k JSD 近似、固定的 \(\lambda=0.8\)、以及 \(\alpha=0.3\) 的格式錨點都是特定設計選擇，可能影響結論的泛化性。

#### 可重現性評估

##### 1. 資料集與評估基準
本文使用的兩個主要評估資源——APIGen-MT 與 BFCL——都屬於公開可取得的工具使用評估資料集。BFCL（Berkeley Function Calling Leaderboard）是廣為人知的多輪函式呼叫基準，資料與評分方式均已公開。APIGen-MT 則應為 APIGen 系列的多輪擴展，若作者使用公開版本，則資料可取得。然而，從提供的文本中無法確認 APIGen-MT 的確切版本與分割方式。

##### 2. 模型與權重
文中提到 9B 與 4B 兩種模型規模，但未明確說明基礎模型名稱（例如是否為某個公開的 9B 語言模型）。教師模型與學生模型都從同一 basemodel 出發，但 basemodel 的確切身分、是否公開釋出權重、以及訓練後的 checkpoint 是否釋出，在提供的文本中均未提及。

##### 3. 程式碼與實作細節
本文詳細描述了損失函式、混合軌跡來源、格式錨點、top-k 重新正規化等實作細節，這對重現非常有幫助。特別是作者強調工具呼叫目標必須 pre-render 為聊天模板的文本形式，這是一個關鍵重現細節。然而，目前文本並未提及是否會公開原始訓練程式碼、超參數設定檔、或訓練腳本。若無法取得作者實作，重現者需要自行根據描述重建 Soft Clamp 的閾值與縮放機制，這可能引入實作差異。

##### 4. Soft Clamp 的實作門檻
Soft Clamp 本身是一個輕量的損失修正，理論上可輕易整合到現有的 GKD 訓練框架中。其核心只需要：
- 計算每個 token 的 JSD；
- 從批次中計算 detached batch threshold；
- 對超過閾值的 token 套用 detached factor 縮放。

這些操作在主流深度學習框架中都不難實作。但「detached batch threshold」與「detached factor」的具體定義（例如閾值是取中位數、某個百分位數，還是均值加標準差；縮放因子是固定常數還是根據極端程度動態計算）在文本中未完全展開，這是重現時最需要釐清的部分。

##### 5. 整體可重現性評價
綜合而言，本文在方法描述與評估基準上具備一定的可重現性基礎，但由於未明確承諾開源程式碼、模型權重與完整超參數，可重現性屬於「中等」。重現者可以根據論文描述復現核心概念與大致趨勢，但要精確重現 13.7% → 9.0% 等數字，仍需更多實作細節與隨機種子資訊。

#### 未來研究方向

##### 1. 行為槓桿的量化與理論刻畫
本文提出「behavior leverage imbalance（行為槓桿不平衡）」作為診斷概念，但未給出嚴格的數學定義。未來研究可以嘗試將行為槓桿形式化，例如透過反事實干預（counterfactual intervention）或影響函數（influence functions）衡量個別 token 對最終決策的邊際影響，從而建立更完整的因果分解（causal decomposition）。

##### 2. 自適應與動態閾值
Soft Clamp 使用 detached batch threshold 與 detached factor，但未深入探討這些超參數的選擇策略。未來可以研究根據訓練階段、任務難度或模型規模動態調整閾值與縮放因子的方法，例如結合學習率調度或損失分布估計，進一步提升穩定性與效果。

##### 3. 多輪互動中的信用分配
BFCL 實驗顯示 Soft Clamp 能減少 tool-call loops（工具呼叫迴圈）與 repeated calls（重複呼叫），但多輪場景中的錯誤可能源於更早的決策。未來可以結合強化學習（reinforcement learning）或過程獎勵模型（process reward models），將多輪信用分配（credit assignment）與逐 token 散度校準結合，從根本上減少迴圈行為。

##### 4. 擴展至其他異質行為領域
本文聚焦於工具使用與直接回答的邊界，但類似的模式切換問題也存在於程式碼生成（程式碼區塊 vs. 自然語言解釋）、多模態生成（文字 vs. 圖像標記）、以及長篇規劃（規劃步驟 vs. 執行步驟）等領域。未來可以驗證 Soft Clamp 在這些領域的泛化性，並針對不同領域設計專屬的槓桿位置識別方法。

##### 5. 教師路由與訊號設計
多教師 OPD 的另一個研究面向是教師路由策略。本文採用簡單的標籤路由（teacher tag），未來可以研究如何根據學生當前狀態動態選擇教師，或設計能夠平衡高槓桿位置訊號的教師分布。例如，是否可以讓回應教師在模式進入 token 上提供更強的對比訊號，以抵消工具呼叫教師的槓桿效應。

##### 6. 與其他對齊方法的結合
Soft Clamp 是一種訓練時的損失校準，未來可以探索其與偏好優化（preference optimization，如 DPO、IPO）、近端策略優化（Proximal Policy Optimization，PPO）或最佳化推理解碼（best-of-n sampling）的結合。特別是，將 Soft Clamp 用於限制教師分布與學生分布之間的過度偏離，可能有助於穩定 RL 訓練並減少模式崩潰（mode collapse）。

##### 7. 自動化邊界審計工具
本文強調 multi-teacher OPD 應在 behavior boundaries（行為邊界）進行審計，而非僅看 aggregate losses。未來可以開發自動化診斷工具，自動識別高槓桿 token、監控過度呼叫趨勢、並在訓練過程中即時發出警報，從而降低多教師蒸餾的調試成本。

## 論文問答

**Q1：什麼是「工具呼叫邊界偏移」，為什麼它對具代理性質的語言模型特別危險？**

A：工具呼叫邊界偏移指的是模型在「應該直接回答」與「應該呼叫工具」之間的決策邊界發生偏移，導致過度呼叫工具或工具呼叫不足。過度呼叫會增加延遲與成本，並可能在多輪互動中陷入反覆的工具呼叫迴圈；工具呼叫不足則會讓模型錯過需要外部資訊或動作才能完成的任務。由於代理模型需要在對話與工具使用軌跡之間頻繁切換，這個邊界只要稍微彎曲，就會對使用者體驗與系統可靠性造成放大影響。

**Q2：為什麼多教師 on-policy 蒸餾看似適合工具使用學習，卻會出現邊界偏移？**

A：多教師 on-policy 蒸餾讓工具呼叫教師專精結構化函式呼叫，回應教師專精自然語言回答，理論上能同時學到兩種模式。然而實驗發現，廣義知識蒸餾雖然提升了工具呼叫召回率，卻也讓模型在應該直接回答的樣本上更傾向呼叫工具。這種行為彎曲無法從聚合損失看出，因為整體損失與決策準確率可能都表現良好，但決策邊界已經悄悄偏移。

**Q3：為什麼僅監控聚合損失無法診斷邊界偏移？**

A：研究發現工具呼叫樣本並未佔據更多 token 曝光量，全序列逐 token 詹森-香農散度也沒有在工具呼叫教師上特別大，有時甚至回應 token 的聚合散度更高。因此問題不在於哪個教師的整體訊號更強，而在於訊號落在哪些位置。真正關鍵的是行為槓桿不平衡：少數位於模式進入點或結構位置的高槓桿 token，能以很小的局部訊號改變整體生成模式。

**Q4：Soft Clamp 的核心機制是什麼？**

A：Soft Clamp 是一種逐 token 散度校準方法，針對每個 token 的詹森-香農散度進行動態壓縮。它使用分離批次閾值，對低於閾值的 token 保持不變，對超過閾值的極端散度則以分離因子縮放其前向貢獻與梯度。這樣既能抑制極端 token 訊號對行為邊界的不成比例影響，又保留非零梯度讓困難 token 持續學習。

**Q5：相較於硬截斷、全局重加權與推論時進入偏置，Soft Clamp 的關鍵優勢在哪裡？**

A：硬截斷會直接截掉超過閾值的散度，導致這些 token 的梯度消失，喪失學習訊號；全局重加權則對所有 token 一視同仁，無法精準處理局部高槓桿位置；推論時進入偏置需要在部署前對每個檢查點進行驗證調參。Soft Clamp 是訓練階段的局部化選項，只壓縮極端值、保留梯度，且不需要額外的推論時調校。

**Q6：Soft Clamp 在設計上為什麼選擇分離的批次閾值與分離因子？**

A：分離閾值與分離因子意味著它們不參與反向傳播，校準機制本身不會改變損失對模型參數的梯度結構，只是縮放極端 token 的學習強度。這確保了閾值是根據當前批次動態估計，而不是一個需要手動調整的超參數。同時，因為因子與閾值都不可梯度，模型不會透過校準模組產生意外的優化路徑。

**Q7：論文在哪些基準上驗證了方法？它們各自衡量什麼？**

A：主要實驗在 APIGen-MT 上進行，這是一個工具使用評估資料集，用來衡量決策準確率、工具呼叫召回率與過度呼叫比例。此外，作者也在 BFCL 的多輪診斷中檢視模型是否會產生工具呼叫迴圈與重複呼叫。APIGen-MT 偏重單輪決策邊界，BFCL 則能揭露多輪互動中邊界偏移引發的動態失敗。

**Q8：Soft Clamp 帶來了哪些關鍵量化結果？**

A：在 APIGen-MT 上，Soft Clamp 將過度呼叫比例從 vanilla GKD 的 13.7% 降至 9.0%，同時維持與 vanilla GKD 相當的決策準確率。在 9B 模型上，Soft Clamp 在三個種子間的標準差較低，顯示出更穩定的校準效果。即使在 4B 模型上，它也保持競爭力，顯示該方法在不同規模都有一定泛化能力。

**Q9：論文做了哪些診斷性實驗來支持「行為槓桿不平衡」的解釋？**

A：作者進行了目標截斷診斷，發現只截斷最前面幾個模式進入 token 並無法完全重現 Soft Clamp 的效益，說明高槓桿訊號也出現在後續結構位置或教師不偏好軌跡位置。圖 1 顯示 vanilla GKD 的逐 token 散度集中在少數 token 上，印證了極端局部訊號的存在。這些診斷支持「訊號位置比訊號總量更能影響行為邊界」的觀點，但作者也強調這是診斷性詮釋而非完整因果分解。

**Q10：在實際產品中，工具呼叫邊界偏移會出現在哪些場景？**

A：客服機器人可能在使用者詢問常見問題時過度查詢外部知識庫，導致回應變慢；程式輔助代理可能在不需要執行指令時頻繁呼叫解釋器，增加運算成本；檢索增強型問答系統也可能把本可內部回答的問題導向搜尋工具。這些場景都會因為過度呼叫而損害使用者體驗，並在多輪對話中演變成重複呼叫或工具呼叫迴圈。

**Q11：從產品部署角度看，選擇不同校準方法時應考量哪些權衡？**

A：Soft Clamp 的優勢在於訓練時完成校準，部署時不需要針對每個檢查點調整推論偏置，適合快速迭代與多環境部署。硬截斷實作簡單但可能犧牲困難 token 的學習訊號；全局重加權可能改變整體梯度分佈，導致召回率波動；推論時進入偏置雖然有效，但需要額外的驗證資源與超參數搜尋。產品團隊應根據延遲預算、穩定性需求與維護成本來選擇最適方案。

**Q12：這篇研究對多教師蒸餾領域可能帶來什麼影響？**

A：它提醒研究者與工程師，當不同教師監督不同生成模式時，不能只看聚合損失或整體準確率，而必須在行為邊界進行審計。論文提出的行為槓桿概念與校準比較框架，為未來設計更穩健的多教師蒸餾方法提供了診斷語言。這也暗示在程式生成、檢索決策、多模態動作選擇等其他模式切換任務中，類似的邊界偏移問題可能同樣存在。

**Q13：作者承認了哪些研究限制？**

A：作者明確指出「行為槓桿不平衡」是一種診斷性詮釋，而非完整的因果分解，無法將過度呼叫完全歸因於特定 token 或教師。實驗中使用的逐 token 詹森-香農散度是基於教師回傳的前 32 個 token 進行 top-k 近似，可能遺漏完整詞彙表的細節。此外，工具呼叫的序列化方式與聊天模板相關，屬於實作細節，不同框架可能需要調整。

**Q14：在哪些情況下，Soft Clamp 可能仍不足以解決邊界偏移？**

A：如果邊界偏移主要來自資料標註錯誤、教師模型本身品質不佳，或兩位教師的分布嚴重重疊，那麼單純壓縮極端散度可能只能緩解症狀而無法根治。當過度呼叫比例極高、模型規模過小導致決策不穩定，或任務需要精細的多輪規劃時，Soft Clamp 也可能需要與其他技術搭配使用。因此，它應被視為一種輕量級校準工具，而非萬用解方。

**Q15：未來研究可以朝哪些方向延伸？**

A：未來可以將行為槓桿分析推廣到其他模式切換任務，例如程式碼生成與自然語言解釋之間的切換、檢索與直接回答之間的切換。也可以發展自適應閾值機制，讓 Soft Clamp 根據不同任務或訓練階段動態調整壓縮強度。此外，結合更嚴謹的因果歸因方法，以及將多輪強化學習與多教師蒸餾結合，都是值得探索的方向。

## 實務應用指南

## 適用場景

**1. 企業級客服助理**
當客服機器人需要同時處理「直接回答常見問題」與「呼叫訂單查詢、退換貨、預約系統」兩類任務時，多教師 on-policy 蒸餾可讓不同教師分別專精於自然語言回應與結構化工具呼叫。Soft Clamp 適合用來抑制模型在簡單問答情境下過度呼叫後端 API，降低延遲與成本。

**2. 程式開發輔助代理**
程式碼助手經常要在「直接回答解釋」與「呼叫編譯器、測試框架、檢索工具」之間做決策。透過工具呼叫教師與回應教師的分工，可以提升應呼叫工具時的召回率；再以 Soft Clamp 校準極端逐 token 散度，可避免模型在不需要執行環境的問題上仍反覆呼叫工具。

**3. 醫療或法律諮詢助手**
這類助手對「是否呼叫外部知識庫、計算工具或專家系統」的決策邊界特別敏感。過度呼叫會增加回應時間與外部依賴，不足則可能遺漏必要資訊。本文的診斷框架可協助團隊監控模式進入 token（如 `<tool_call>`）與函式名稱等高槓桿位置，確保決策邊界穩定。

**4. 多輪對話的個人助理**
在需要連續多輪互動的場景（如日曆安排、行程規劃、智能家居控制），模型容易出現工具呼叫迴圈或重複呼叫。Soft Clamp 在 BFCL 多輪診斷中展現降低迴圈與重複呼叫的效果，適合部署於需要長期互動穩定性的產品。

**5. 異質資料來源的 RAG 系統**
當模型面對多種檢索來源（向量資料庫、網頁搜尋、內部文件）時，不同教師可分別專精於「直接摘要」與「呼叫檢索工具」。透過監控行為槓桿不平衡，可避免模型在已有足夠上下文時仍過度觸發檢索，減少無效查詢。

## 實作前置條件

**資料準備**
- 需具備明確標註「應直接回答」與「應呼叫工具」的對話資料集，每筆範例需有教師標籤（tool / response）。
- 工具呼叫範例必須使用模型聊天模板預先渲染為預期的文字格式，否則學生模型可能學到無效 schema。
- 建議準備多輪評估資料（如 BFCL）以診斷工具呼叫迴圈與重複呼叫行為。

**運算資源**
- 至少需能微調 4B 至 9B 規模的語言模型；論文主要結果在 9B 模型上效果最明顯。
- 需支援 on-policy rollout 的訓練框架，能從學生當前策略採樣軌跡並計算教師分布。
- 需有足夠資源進行多組種子實驗，以觀察校準方法在不同初始化下的穩定性。

**技術能力**
- 熟悉廣義知識蒸餾（GKD）與 on-policy distillation 的訓練流程。
- 能夠計算與分析逐 token 詹森-香農散度（JSD），並識別高槓桿的結構位置。
- 具備將工具呼叫序列渲染為模型聊天模板格式的工程經驗。
- 有能力設計決策準確率、工具呼叫召回率、過度呼叫率等多維度評估指標。

## 實作步驟建議

**步驟一：建立雙教師基線**
從同一基座模型出發，分別以工具呼叫資料微調「工具呼叫教師」，以直接回應資料微調「回應教師」。確保兩位教師在各自領域有穩定表現。

**步驟二：建構多教師 on-policy 蒸餾流程**
讓學生模型從自身 rollout 採樣延續序列，並根據每筆範例的教師標籤，將軌跡導向對應的教師分布。建議混合 80% 學生生成軌跡與 20% 資料集軌跡，並對資料集軌跡加入格式錨定損失（α = 0.3）。

**步驟三：監控聚合損失以外的指標**
不要僅看總損失。需追蹤：
- 各類 token 的曝光量比例
- 全序列逐 token JSD 分布
- 模式進入 token（如 `<tool_call>`、函式名稱）的散度集中度
- 應呼叫與應回答範例的決策準確率、召回率、過度呼叫率

**步驟四：診斷行為槓桿不平衡**
分析少量高散度 token 是否集中在高槓桿結構位置。可透過目標截斷診斷（如只截斷前幾個進入 token）來判斷高槓桿訊號是否也出現在後續結構位置或教師不偏好軌跡位置。

**步驟五：導入 Soft Clamp**
對每個 token 的 JSD 計算分離批次閾值。低於閾值的 token 保持不變；高於閾值的 token 以分離因子縮放其前向貢獻與梯度，保留學習訊號但壓縮極端影響。

**步驟六：與替代方案進行校準比較**
同時評估硬截斷、全局重加權、Soft Clamp 與推論時進入偏置。比較維度包括：過度呼叫率、決策準確率、工具呼叫召回率、種子間穩定性、部署複雜度。

**步驟七：多輪行為驗證**
在 BFCL 或類似多輪基準上驗證，確認校準後模型是否減少工具呼叫迴圈與重複呼叫，並維持任務完成率。

## 潛在風險與注意事項

**風險一：過度抑制工具呼叫**
Soft Clamp 雖能降低過度呼叫，但若閾值或縮放因子設定過於激進，可能連帶降低應呼叫工具時的召回率。建議透過多組種子實驗觀察標準差，並在驗證集上監控決策準確率與召回率的平衡。

**風險二：高槓桿位置判斷錯誤**
若僅截斷前幾個進入 token 而忽略後續結構位置，可能無法完全緩解邊界偏移。需進行目標截斷診斷，確認高槓桿訊號的實際分布，避免過度簡化問題。

**風險三：教師分布實作不一致**
工具呼叫目標必須正確渲染為模型聊天模板的文字格式。若將工具呼叫當成一般助理回應處理，學生模型可能學到語法正確但 schema 無效的輸出，導致評估指標看似合理卻無法實際執行。

**風險四：聚合指標誤導決策**
總損失、token 曝光量、全序列平均 JSD 都可能無法反映行為邊界偏移。產品團隊應建立專門的決策邊界儀表板，區分「應回答卻呼叫」與「應呼叫卻未呼叫」兩類錯誤。

**風險五：推論時進入偏置的部署成本**
雖然推論時偏置可能有效，但需要為每個檢查點進行驗證調整，增加部署與維運負擔。Soft Clamp 作為訓練時選項可減少這部分成本，但仍需在訓練階段仔細調參。

## 與其他技術的整合建議

**與 RLHF / DPO 整合**
Soft Clamp 可視為在蒸餾階段對逐 token 散度的正則化，後續仍可銜接基於人類回饋的強化學習或直接偏好最佳化。建議將「避免過度呼叫」與「避免不足呼叫」明確納入偏好模型或獎勵函數，以強化決策邊界。

**與推論時工具選擇機制整合**
即使導入 Soft Clamp，仍可在推論階段搭配工具可用性過濾、強制格式檢查與重複呼叫偵測。訓練時校準與推論時守衛機制並行，可進一步降低工具呼叫迴圈風險。

**與可觀測性平台整合**
將逐 token JSD、模式進入 token 機率、決策邊界指標輸出至可觀測性系統。當過度呼叫率上升時，可快速定位是高槓桿結構位置散度異常，還是整體分布偏移所致。

**與多教師擴充架構整合**
本文使用兩位教師，但框架可擴充至更多教師（如檢索教師、程式執行教師、摘要教師）。每新增一位教師，都應重新評估行為槓桿不平衡，並視需要調整 Soft Clamp 的閾值策略。

**與模型壓縮技術整合**
Soft Clamp 在 4B 與 9B 模型上均有競爭力，適合作為模型蒸餾與量化流程中的一環。可在蒸餾階段使用 Soft Clamp 穩定決策邊界，再進行量化或剪枝以部署至邊緣裝置。

## 給不同背景讀者的閱讀建議

**給初學者**
這篇論文討論的是「讓 AI 學會正確決定要不要使用工具」的訓練問題。如果你剛接觸這個領域，建議先理解什麼是工具呼叫、什麼是直接回答，以及為什麼模型會「該用工具時不用」或「不該用時一直用」。接著再回來看 Soft Clamp 這個方法，它就像一個「溫和的煞車」，讓模型不要因為少數幾個關鍵 token 的強烈訊號而過度偏向呼叫工具。

**給 AI 工程師**
對你來說，這篇論文最有價值的是實作細節與診斷方法：如何渲染工具呼叫格式、如何混合學生 rollout 與資料集軌跡、如何計算逐 token JSD、如何設計目標截斷診斷。建議直接跳到問題設定與校準比較章節，並將 Soft Clamp 實作為訓練流程中的可選正則化模組，同時建立決策邊界儀表板以監控過度呼叫與不足呼叫。

**給研究人員**
本文的核心貢獻在於提出「行為槓桿不平衡」這個診斷視角，挑戰了僅用聚合損失解釋模型行為的慣例。建議深入閱讀行為槓桿的定義、目標截斷診斷的設計，以及 Soft Clamp 與硬截斷、全局重加權、推論時偏置之間的理論與實證比較。未來可進一步探索因果分解、更多教師設定，以及其他生成模式邊界（如程式碼 vs. 自然語言）的適用性。

**給產品經理**
這篇論文提醒一個關鍵產品風險：模型整體表現變好，不代表決策行為沒有偏掉。如果你負責設計會使用工具的 AI 產品，請關注「過度呼叫」帶來的延遲、成本與使用者體驗問題，以及「不足呼叫」導致的任務失敗。建議將本文的評估指標（決策準確率、召回率、過度呼叫率、多輪迴圈次數）納入產品儀表板，並與工程團隊討論是否導入 Soft Clamp 作為訓練時的穩定機制。
