## ⚡ TL;DR

現有世界模型基準僅靠暴力計算單一分數，無法解釋物理、因果與狀態演變的判斷依據。
HarnessEval-W 以階層式智慧體分解評估問題，子智慧體運用診斷工具建構透明證據樹。
在十八個世界模型、三百三十個案例上，其判斷貼近人類偏好，並提供可驗證的細粒度診斷。

## 摘要翻譯

基準測試（benchmark）不應僅提供一個純量分數（scalar score）：評估（evaluation）結果是否可信（trustworthy），取決於支撐該分數的推理（reasoning）。這對世界模型（world model）而言尤其關鍵，因為判斷一條 rollout（生成軌跡）是否正確，需要理解其中的物理（physics）、因果性（causality）與世界狀態（world state）是否正確演變。人類能自然察覺這類違反現象，但現有的基準測試都未能將此能力自動化：指標（metric）往往以暴力法（brute-force）計算，無法留下可供檢視或驗證的推理鏈（reasoning chain）。

我們提出 HarnessEval-W，這是一個智慧體化評估流程（agentified evaluation pipeline），將大型語言模型生態系（LLM ecosystem）中的 harness 典範（harness paradigm）引入世界模型基準測試。不同於套用固定評分標準（rubric），HarnessEval-W 會解讀每個評估案例（evaluation case）的情境（context），將評估問題拆解為可衡量的子問題（subproblem），並生成（spawn）專門的子智慧體（sub-agent）；每個子智慧體都配備客製化的情境與診斷工具（diagnostic tools），以針對其所負責的子問題進行推理。父智慧體（parent agent）隨後驗證所收集的證據（evidence），並將其彙整為最終判決（verdict）。此階層式工作流程（hierarchical workflow）使每項評估形成一棵透明的證據樹（evidence tree），其完整的推理鏈足以支撐最終結果。

我們將 HarnessEval-W 應用於 18 個具代表性的世界模型，涵蓋 330 餘個評估案例。其判斷與人類偏好（human preference）高度一致，同時能對每個生成軌跡（generated rollout）提供可驗證的細粒度診斷（fine-grained diagnosis）。我們將完整流程開源（open-source）為一個動態基準（live benchmark），並邀請廣大社群共同貢獻，隨著世界模型的演進持續擴充新技能（skill）與評估案例。

### 核心貢獻（3～5點）
- 提出 HarnessEval-W，將大型語言模型生態系的 harness 典範引入世界模型基準測試，建立以智慧體為核心的自動化評估流程。
- 不依賴固定評分標準，而是依據每個評估案例的情境動態拆解問題，生成專門子智慧體進行細粒度推理與證據收集。
- 透過父智慧體驗證並彙整證據，形成透明的證據樹與完整推理鏈，使每次評估結果皆可檢視與驗證。
- 在 18 個代表性世界模型、330 餘個評估案例上驗證，判斷與人類偏好高度一致，並提供可驗證的細粒度診斷。
- 將完整流程開源為動態基準，邀請社群持續貢獻新技能與評估案例，以伴隨世界模型發展共同成長。

### 適合對象
從事世界模型、影片生成模型與互動式模擬環境的研究者與工程師；關注模型評估方法、可解釋性與 AI 安全的學者；以及希望建立或參與動態基準測試的開源社群成員。

## 深度分析

#### 方法論解析

HarnessEval-W 的核心貢獻在於將「evaluation harness（評估 harness）」的典範從 LLM（Large Language Model，大型語言模型）生態系遷移至 world model（世界模型）的評估場域，並將整個評估過程智慧體化（agentified）。傳統基準測試（benchmark）通常以固定指標（metric）對生成影片進行暴力法（brute-force）計分，結果僅是一個 scalar score（純量分數），缺乏可檢視的 reasoning chain（推理鏈）。相對地，HarnessEval-W 把每一次評估都視為一個需要主動推理、證據收集（evidence gathering）與工具使用（tool use）的動態工作流程。

其方法論可拆解為四個層次：

1. **情境詮釋（context interpretation）與 skill routing（技能路由）**  
   每個 evaluation case（評估案例）都對應一個獨特的 unique world（獨特世界），具有不同的 physical action（物理動作）、temporal structure（時間結構）與 observation state（觀察狀態）。因此，HarnessEval-W 首先由一個 parent agent（父智慧體）解析案例情境，判斷應啟動哪些 skill（技能）。例如，若案例涉及「夾爪提起方塊」，系統會將其路由至 Intentional Change（意圖性變化）與 Physical Plausibility（物理合理性）等相關 skill，而不會啟用不相關的 Offscreen Evolution（螢幕外演化）或 Drift Degradation（漂移退化）等技能。這種 case-specific（案例專屬）的路由機制避免了 fixed rubric（固定評分標準）在不同物理情境下的僵化問題。

2. **問題分解與 sub-agent（子智慧體）委派**  
   當 skill 被選定後，評估問題會進一步被拆解為可測量的 subquestion（子問題），每個 subquestion 再交由具備專屬 context 與 diagnostic tool（診斷工具）的 sub-agent 處理。以 collision（碰撞）評估為例，系統會分別追蹤 bounding box（邊界框）、驗證 temporal intersection（時間交集）、估計 velocity（速度）等，並由不同子智慧體各自產出證據。這種分解方式讓評估從「整體印象分」轉變為「多維度可驗證的診斷」。

3. **證據驗證與 verdict（最終判決）合成**  
   所有 sub-agent 回傳 evidence（證據）後，parent agent 會進行一致性檢查與權重整合，最終產出 fine-grained diagnosis（細粒度診斷）與 scalar score。關鍵在於，這個過程會被記錄為一棵 evidence tree（證據樹），明確記載「測試了什麼」、「哪個工具提供了 visual grounding（視覺定位）」以及「邏輯鏈如何推導出最終分數」。這使得評估結果具備可解釋性與可審計性。

4. **遞迴式階層工作流程（hierarchical workflow）**  
   該流程可遞迴執行：sub-agent 在必要時可再生成下層 sub-agent 進行更細緻的調查。這種設計讓 HarnessEval-W 能處理複雜的因果推理，例如驗證「物體被遮擋後是否仍保持 object permanence（物體恆存性）」或「長時間 rollout 後 world state（世界狀態）是否保持一致」。

在評估架構上，HarnessEval-W 圍繞世界模型的三大核心功能組織 330 個 evaluation case：

- **Observation Quality（觀察品質）**：評估模型從當前狀態渲染觀察結果的能力，包括 render quality（渲染品質）、motion consistency（動作一致性）等。
- **Transition Correctness（轉移正確性）**：評估模型在 intervention（干預）下更新世界狀態的能力，例如 Intentional Change、Physical Plausibility。
- **World Persistence（世界持續性）**：評估模型在長時間 rollout 中維持狀態一致性的能力，例如 Offscreen Evolution、Drift Degradation。

此外，案例本身也是透過一個 agentic construction pipeline（智慧體化建構流程）產生：從結構化場景分類法中採樣多樣 initial world（初始世界），將具體動作 grounded（扎根）於生成場景中，並在接受每個 candidate case（候選案例）前進行驗證。這確保了測試案例的多樣性與可評估性。

#### 實驗數據解讀

論文對 18 個 representative world models（代表性世界模型）進行評估，涵蓋 general-purpose video generators（通用影片生成模型）與 interactive world simulators（互動式世界模擬器）。雖然完整數值表格未在提供的上下文中列出，但從摘要與引言可歸納出以下實驗發現：

1. **與 human preference（人類偏好）高度一致**  
   HarnessEval-W 的排序與人類偏好對齊良好，這顯示其 agentic judging 不僅能捕捉低階視覺品質，也能反映人類對物理因果性（physical causality）、幾何一致性（geometric consistency）與觀察真實性（observation realism）的綜合判斷。相較於傳統 metric，這是一項重要進展，因為現有指標往往與人類判斷存在顯著落差。

2. **細粒度診斷揭示模型失敗模式**  
   透過 evidence tree，HarnessEval-W 能指出模型在哪一個子問題上失敗。例如，某模型可能在 target specificity（目標明確性）獲得 1.00，表示它能正確鎖定操作對象；但在 final state（最終狀態）僅得 0.25，顯示動作雖然發生，卻未達成預期結果；同時 no extra event（無額外事件）為 0.00，表示 rollout 中出現了不相關的偽影（artifact）。這種拆解遠比單一平均分數更能指導模型改進。

3. **影片生成器轉型為世界模型並非均勻提升**  
   研究發現，將 video generator（影片生成器）改裝為 world model 並不會在所有面向上一致進步，而是會重新分配能力分布。某些模型在 Observation Quality 上表現優異，但在 Transition Correctness 或 World Persistence 上明顯不足；反之，專為互動設計的模型可能在物理轉移上更穩定，但視覺保真度較低。這凸顯了同時評估三大軸向的必要性。

4. **不同 skill 的鑑別力差異**  
   從示意圖可觀察到，HarnessEval-W 對每個案例動態選擇 skill。這意味著某些 skill（如 Intentional Change）對於區分「互動式世界模型」與「開環影片生成器」特別敏感；而 World Persistence 相關 skill 則對長 horizon rollout 的模型更具鑑別力。未來若公布各 skill 的模型分數分布，將能進一步量化哪些物理推理能力仍是社群瓶頸。

5. **證據樹作為可驗證的評估紀錄**  
   實驗結果不只是分數，而是每個 rollout 都附帶完整的 reasoning chain。這讓研究者可以回溯：當兩個模型總分接近時，它們的失敗模式是否相同？某個模型是否透過「作弊」式的外觀一致性掩蓋了狀態不一致？這種透明度是傳統 benchmark 難以提供的。

#### 與現有研究的比較

HarnessEval-W 與現有 video generation benchmark（影片生成基準測試）及互動世界評估方法相比，具有明確的定位差異與優勢：

**相較於 VBench、EvalCrafter、FETV、Video-Bench / VBench++**

- **從靜態指標到動態推理**：VBench 等基準雖然將 video quality 分解為 imaging、temporal stability、subject consistency 等維度，但本質上仍依賴預先定義的 metric 進行計算。HarnessEval-W 則根據每個案例的情境動態選擇評估策略，並產出可檢視的 reasoning。
- **從開環影片到互動式世界**：VBench++ 等雖引入 MLLM（Multimodal Large Language Model，多模態大型語言模型）作為 judge，但多數仍聚焦於 text-to-video 或 image-to-video 的開環生成。HarnessEval-W 專注於 action-conditioned（動作條件化）的 closed-loop（閉環）互動，評估 Transition Correctness 與 World Persistence，這是傳統影片基準較少觸及的面向。
- **從分數到證據樹**：現有基準提供 scalar score 或維度分數，但缺乏「為何得到此分數」的細節。HarnessEval-W 的 evidence tree 讓評估結果可被檢驗、反駁與改進。

**相較於互動式世界模型（Genie、GameNGen、DIAMOND、MineWorld、YUME 1.5、HY-World 1.5 等）**

- 這些模型本身提供了 action-conditioned generation 的能力，但過去多依賴遊戲內建分數或人類主觀評分。HarnessEval-W 提供了一個統一的、可擴充的評估框架，能跨不同控制介面（keyboard、mouse、language、camera）進行比較。
- 透過 skill routing 與 sub-agent，HarnessEval-W 能評估模型是否真正「理解」動作意圖（intent of action），而非僅產生視覺上合理的影片。

**主要限制**

- **計算成本與延遲**：agentic pipeline 涉及多次 LLM / VLM（Vision-Language Model，視覺語言模型）呼叫與視覺工具執行，評估成本遠高於傳統 metric。這可能限制大規模自動化評估的頻率。
- **對底層模型能力的依賴**：parent agent 與 sub-agent 的推理品質取決於所使用 LLM / VLM 與 diagnostic tool 的準確性。若底層視覺工具在 bounding box 追蹤或 velocity 估計上出錯，evidence tree 可能產生誤導。
- **案例覆蓋的有限性**：雖然 330 個案例已具代表性，但真實世界的物理法則與互動組合幾近無限。目前案例可能仍偏向特定視覺風格與簡化物理情境。
- **人類對齊的潛在偏誤**：與 human preference 對齊並不等同於客觀正確性。若人類標註者對物理合理性的直覺存在系統性偏誤，agent 也可能學到這些偏誤。

#### 可重現性評估

可重現性（reproducibility）是 HarnessEval-W 設計中的重要訴求。論文明確表示將完整 pipeline 以 live benchmark（動態基準）形式開源（open-source），並邀請社群貢獻新的 skill 與 evaluation case。這對研究社群具有以下意義：

- **程式碼與流程開源**：完整的 agentic evaluation pipeline、skill routing 邏輯、sub-agent 設計與 evidence tree 生成機制預計公開，使其他研究者能重現對 18 個模型的評估結果，並在此基礎上擴充。
- **案例資料集開放**：330 個 evaluation case 的結構化描述、初始世界設定、動作序列與預期行為應一併釋出，確保不同模型在相同輸入下被測試。
- **第三方模型權重**：論文評估的 18 個 world models 多為已發表或開源模型（如 CogVideoX、HunyuanVideo、Wan、Genie、DIAMOND 等），但部分模型權重可能需遵循各自授權。HarnessEval-W 本身提供評估框架，而非重新訓練模型，因此模型權重取得不影響基準的可重現性，但研究者仍需自行準備被測模型。
- **動態更新機制**：作為 live benchmark，HarnessEval-W 允許社群提交新的 skill 與案例，這雖然增強了長期適用性，但也帶來版本控制與結果可比性的挑戰。建議未來建立明確的版本標記與凍結機制，以確保歷史結果的可比較性。
- **透明證據樹**：每個評估結果都附帶 reasoning chain，這本身就是可重現性的強化——其他研究者可以檢查特定分數的推導過程，並在發現錯誤時進行修正或重新評估。

整體而言，HarnessEval-W 在可重現性方面優於許多僅釋出分數表格的傳統 benchmark，但仍需關注底層 LLM / VLM 版本更新、工具鏈變動對結果穩定性的影響。

#### 未來研究方向

HarnessEval-W 的 agentic evaluation 框架為 world model 評估開啟了多條值得探索的研究路徑：

1. **擴充物理推理 skill 的深度與廣度**  
   目前 skill 已涵蓋碰撞、意圖性變化、螢幕外演化等，但未來可加入更複雜的物理法則，如流體動力學、剛體堆疊穩定性、摩擦力與彈性碰撞、光學一致性等。這需要開發更精準的 diagnostic tool 與對應的 sub-agent。

2. **結合因果干預（causal intervention）的評估**  
   世界模型的核心在於「反事實推理」能力。未來可設計透過干預特定變因（例如改變重力方向、移除支撐物）來評估模型是否具備真正的因果理解，而非僅依賴統計相關性生成合理畫面。

3. **從合成場景到真實世界影片**  
   目前案例多基於結構化場景分類法生成。未來可將 HarnessEval-W 擴展至真實世界影片與機器人互動資料，評估世界模型在複雜、未受控環境中的表現。

4. **發展標準化的 harness API 與社群貢獻機制**  
   為了讓 live benchmark 持續健康發展，需要建立清晰的 skill 註冊介面、案例提交規範、審查流程與版本控制機制。這將使 HarnessEval-W 成為世界模型領域類似於 LMSYS Chatbot Arena 的公共評估基礎設施。

5. **提升評估效率與可擴展性**  
   研究如何透過模型蒸餾、快取機制或專用小型 VLM 來降低 agentic evaluation 的成本與延遲，使其能夠整合進日常模型開發流程，作為持續整合（CI）的一部分。

6. **人機協作的評估校正**  
   雖然 HarnessEval-W 已與人類偏好對齊，但對於邊界案例或新興物理現象，仍需要人類專家介入。未來可設計主動學習（active learning）機制，讓 agent 在信心不足時自動請求人類標註，並持續改進自身的 reasoning 能力。

7. **安全性與對齊評估**  
   世界模型未來可能用於機器人控制、自動駕駛等安全關鍵場景。HarnessEval-W 的框架可擴展至評估危險動作預測、物理安全邊界、以及模型是否會生成違反物理常識而導致危險決策的 rollout。

8. **跨模態控制介面的統一評估**  
   隨著 world model 支援 language、camera、keyboard-and-mouse 等多元控制方式，未來需要設計能夠比較不同控制模態下模型一致性的 skill，探討模型對同一意圖在不同輸入形式下的表現是否穩定。

總結來說，HarnessEval-W 不僅提出了一個新的 benchmark，更提出了一種「評估即智慧體流程」的典範。它將評估從黑箱分數轉化為可檢視、可驗證、可協作的證據推理過程，為未來 world model 的發展提供了更可靠的 North Star（指引目標）。

## 論文問答

**【背景與動機】**

**Q1：HarnessEval-W 主要想解決世界模型評估中的什麼核心問題？**
A：現有的世界模型基準測試大多只能給出一個無法解釋的純量分數，無法說明模型在物理因果性、幾何一致性或觀察真實性上為何通過或失敗。人類在評估生成軌跡時，會自然地定位物體、追蹤物體恆存性並驗證因果關係，但這種推理能力過去從未被自動化。HarnessEval-W 正是要彌補這個缺口，將評估過程智慧體化，使每個分數背後都附帶可檢視、可驗證的推理鏈與細粒度證據。

**Q2：為什麼傳統指標難以提供可信的世界模型評估？**
A：傳統指標通常直接對生成影片進行暴力計算，沒有把評估問題拆解成可解釋的子問題，因此缺乏可供檢查的推理鏈。它們往往使用固定評分標準，忽略了每個測試案例獨特的物理動作、時間結構與觀察狀態。結果是，這些指標無法指出模型究竟在哪裡、為什麼違反物理規律或世界狀態一致性，導致其說服力與診斷價值都很有限。

**Q3：對世界模型而言，基於推理的評估為何特別重要？**
A：世界模型必須在長時間軸上維持一致的狀態，並對外部干預做出正確反應，因此評估不能只看視覺品質，還要驗證物體恆存性、物理法則與因果關係是否成立。單一純量分數無法區分失敗是來自渲染、狀態轉移還是長期記憶。HarnessEval-W 透過揭露每個裁決背後的完整邏輯鏈，讓研究者能夠診斷失敗模式並決定後續改進方向。

**【方法與創新】**

**Q4：HarnessEval-W 的核心方法是什麼？**
A：HarnessEval-W 將評估視為一個階層式智慧體流程：頂層的父智慧體先解讀每個案例的情境，再將其路由到合適的評估技能。接著，評估問題被進一步分解成可測量的子問題，並委派給具備專屬情境與診斷工具的子智慧體，例如追蹤邊界框、檢查時間交集或估計速度。最後，父智慧體驗證各子智慧體回傳的證據，再整合成最終裁決，並產生一棵透明的證據樹。

**Q5：與現有基準相比，HarnessEval-W 的關鍵創新在哪裡？**
A：關鍵創新在於從靜態、固定評分標準轉向動態、情境感知的智慧體化 harness 典範。它不再對每個 rollout 套用同一套指標，而是根據當前世界、動作與問題，動態調整推理方式、工具與子智慧體。這種設計產出的證據樹會詳細記錄測試了什麼、哪個工具提供了視覺基礎，以及證據如何支持最終分數。

**Q6：哪些重要設計選擇讓 HarnessEval-W 能處理多樣化的評估案例？**
A：系統採用技能路由，根據案例特性將其導向相關的評估面向；同時透過遞迴分解，把複雜判斷拆成可測量的子問題。每個子智慧體都獲得量身打造的上下文與專屬診斷工具，因此同一個框架可以評估碰撞、物體恆存性或渲染品質等不同面向。父智慧體的證據驗證步驟則確保只有具備充分依據的子結論才會進入最終裁決。

**【實驗與結果】**

**Q7：作者建構了什麼樣的基準資料集，又是如何組織的？**
A：作者建構了包含 330 個評估案例的基準，圍繞世界模型的三大核心功能組織：觀察品質、轉移正確性與世界恆存性。這些案例由一個智慧體化建構流程產生，該流程從結構化場景分類學中採樣多樣的初始世界，並在其中落地具體動作，最後驗證每個候選案例後才予以接受。這樣的設計確保了基準能廣泛涵蓋世界模型必須處理的物理、因果與幾何情境。

**Q8：作者評估了哪些模型，關鍵發現為何？**
A：作者評估了 18 個具代表性的世界模型，涵蓋通用影片生成模型與互動式世界模擬器。HarnessEval-W 產生的模型排序與人類偏好高度一致，顯示這個智慧體化評估器能夠捕捉有意義的品質差異。進一步分析還發現，把影片生成模型改造成互動式世界模型並不會均勻提升所有能力，而是會在不同設定間重新分配能力表現。

**Q9：論文是否進行了消融或診斷分析，結果顯示什麼？**
A：雖然論文未以傳統意義進行大量消融實驗，但證據樹本身就是一種細粒度診斷分析：它能指出是哪個子智慧體或工具發現了失敗，例如碰撞中缺少邊界框交集，或離屏狀態出現不一致。這種顆粒度讓研究者能夠判斷錯誤源於渲染、轉移邏輯還是長期恆存記憶。這種透明診斷是暴力純量指標無法提供的，也是本研究在實驗上的核心貢獻之一。

**【應用與影響】**

**Q10：HarnessEval-W 可以應用在哪些實務場景？**
A：HarnessEval-W 可協助研究人員在開發過程中比較新一代影片生成器與互動式模擬器，也可供工程師除錯特定失敗模式，例如錯誤碰撞或物體消失。由於其證據樹具有可稽核性，它也適合用於安全關鍵或產品層級的評估。此外，作為開源且動態成長的基準，社群能持續貢獻特定領域的評估情境。

**Q11：在產品化部署 HarnessEval-W 時，需要考慮哪些因素？**
A：由於整個流程是智慧體化且需要呼叫多種診斷工具，部署時必須考量運算成本、工具可靠性，以及遞迴子智慧體呼叫的一致性。產品團隊需要將證據樹以可解讀的方式呈現，讓非技術利害關係人也能理解裁決依據。同時，技能與工具的版本控制也很重要，才能確保基準更新後的結果仍具可比較性與可重現性。

**Q12：HarnessEval-W 可能對世界模型基準領域帶來什麼影響？**
A：HarnessEval-W 證明了評估本身也可以是一個具備推理能力的智慧流程，促使社群從黑箱指標走向透明、可稽核的評估器。其 harness 典範可能成為具身智慧、機器人學與互動式模擬等領域未來基準的標準腳手架。開源且動態成長的設計也能促進協作，使評估方法能跟上生成式世界模型的快速演進。

**【限制與未來】**

**Q13：論文承認或暗示了 HarnessEval-W 的哪些限制？**
A：論文並未宣稱涵蓋所有可能的物理法則或真實世界情境，330 個案例仍來自一個結構化但有限的場景分類學。智慧體化流程的可靠性取決於子智慧體與診斷工具的品質，而這些組件本身也可能出錯或帶有偏見。此外，相較於簡單純量指標，遞迴且工具增強的推理計算成本更高，可能限制大規模部署。

**Q14：哪些失敗案例或邊界情況可能對 HarnessEval-W 構成挑戰？**
A：涉及細微物理交互的案例，例如軟體形變或流體動力學，可能超出目前邊界框與速度工具的能力範圍。動作意圖模糊或提示描述不充分的案例，可能導致父智慧體產生不同解讀，進而使裁決不一致。長時間軌跡中若存在大量離屏狀態變化，也可能加重證據收集負擔，並在推理鏈中累積錯誤。

**Q15：作者對智慧體化評估的未來方向有何展望？**
A：作者希望 HarnessEval-W 成為一個動態基準，隨著世界模型演進持續新增技能、診斷工具與評估案例，並由社群共同貢獻擴展。未來可整合更強大的物理模擬器作為工具、提升技能路由的穩健性，並自動發現容易誘發失敗的評估情境。最終目標是讓每個基準分數都伴隨一條可驗證、與人類偏好對齊的推理鏈。

## 適用場景

1. **互動式世界模型的上市前驗證**  
   遊戲、機器人模擬器或自動駕駛場景生成器在釋出前，可用 HarnessEval-W 自動檢查 rollout 是否符合物理因果性、幾何一致性與物體恆存性，避免僅憑純量分數就判定模型可用。

2. **生成式影片模型的能力診斷與迭代優化**  
   影片生成團隊可將 HarnessEval-W 整合進 CI/CD，針對 Observation Quality、Transition Correctness、World Persistence 三個軸向取得細粒度診斷，定位模型在碰撞、遮擋、狀態漂移等面向的具體失敗點。

3. **具身智慧（Embodied AI）與機器人模擬的動作驗證**  
   機器人學習中的模擬環境可透過 HarnessEval-W 評估「動作意圖」是否正確轉換為視覺與物理狀態變化，例如夾爪是否確實抓起方塊、物體是否在視野外仍保持存在。

4. **多模態基準測試平台的建置**  
   學術或產業研究單位可將 HarnessEval-W 作為動態基準，持續新增技能與評估案例，追蹤不同世界模型隨時間的進步，並讓社群貢獻新的診斷工具與測試情境。

5. **人機協作內容審查的輔助系統**  
   對於需要人工複審的生成內容平台，HarnessEval-W 可先產出可檢視的證據樹與推理鏈，協助審查者快速理解模型輸出何處違反物理或因果關係，降低人工檢視成本。

## 實作前置條件

### 資料
- **評估案例庫**：需準備包含初始世界狀態、動作序列、預期轉折與觀察狀態的結構化案例；若無現成資料，可參考論文的 agentic construction pipeline，從結構化場景分類學中採樣並自動驗證候選案例。
- **模型輸出（rollout）**：待測世界模型在相同輸入條件下產生的連續影片或狀態序列，建議包含時間戳與可視化幀。
- **輔助標註與工具輸出**：例如邊界框追蹤、光流、深度圖、物體分割遮罩等，供子智慧體進行視覺定位與時空證據收集。

### 運算
- **GPU 資源**：執行視覺診斷工具（如 MLLM、影片理解模型、物件偵測與追蹤模型）需要中等到高階 GPU；若僅使用輕量規則式工具，CPU 叢集亦可應付。
- **LLM API 或本地模型**：父智慧體與子智慧體需要具備強大指令遵循與推理能力的大型語言模型，建議準備 GPT-4o、Claude 3 或同等開源模型（如 Qwen2-VL、LLaVA-OneVision）的存取權限。
- **儲存與日誌系統**：每個案例會產生證據樹、推理鏈與多媒體證據，需有足夠儲存空間與結構化日誌系統。

### 技能
- **多模態模型調用經驗**：熟悉如何透過 API 或本地部署呼叫視覺語言模型，並設計結構化輸出。
- **影片/電腦視覺基礎**：理解物件追蹤、邊界框、光流、深度估計等工具，以便擴充或維護診斷工具。
- **智慧體流程設計**：具備將複雜評估問題分解為子問題、設計父智慧體與子智慧體協作流程的經驗。
- **基準測試與評量方法論**：了解如何與人類偏好對齊、設計可重現的評估協定，並避免資料污染。

## 實作步驟建議

1. **定義評估目標與三軸向覆蓋**  
   先決定要評測 Observation Quality、Transition Correctness、World Persistence 中的哪些面向，並列出對應的失敗模式（如偽影、錯誤碰撞、狀態漂移、物體恆存違反）。

2. **建立或擴充技能庫（Skill Library）**  
   依據目標設計專門技能，例如 Render Quality、Intentional Change、Offscreen Evolution、Physical Plausibility、Drift Degradation 等。每個技能應明確定義適用情境與不適用情境。

3. **設計案例專屬路由與分解邏輯**  
   讓父智慧體先解讀每個評估案例的情境，選擇合適技能，再將評估問題拆成可測量子問題，並指派對應子智慧體或診斷工具。

4. **實作子智慧體與診斷工具**  
   為每個子問題開發專用工具：例如追蹤邊界框以驗證時間交集、估計速度以判斷碰撞合理性、使用 MLLM 檢查視覺一致性。工具輸出應包含可視化證據與數值結果。

5. **建立證據驗證與整合機制**  
   父智慧體彙整所有子智慧體回傳的證據，檢查邏輯一致性，再產出最終裁決與證據樹。此處應保留完整推理鏈，方便後續人工審查。

6. **對齊人類偏好並校正評分**  
   在內部資料集上進行人類標註，比對 HarnessEval-W 的判決與人類偏好，調整提示詞、工具權重與評分標準，直到兩者高度一致。

7. **部署為可執行的動態基準**  
   將整個流程封裝為可重複執行的 harness，整合進模型開發流程或發布為開源動態基準，持續接受社群貢獻新技能與評估案例。

## 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **智慧體幻覺導致誤判** | LLM 可能在缺乏足夠視覺證據時虛構推理鏈或錯誤解讀 rollout。 | 要求每個判斷必須引用具體工具輸出與幀編號；引入人類在環（human-in-the-loop）抽樣驗證。 |
| **工具失準造成系統性偏差** | 物件追蹤或深度估計工具本身有誤差，可能讓子智慧體產出錯誤證據。 | 對工具進行基準校正，並在證據樹中標註工具可信度；多工具交叉驗證同一子問題。 |
| **固定技能無法涵蓋新情境** | 世界模型快速演進，既有技能可能無法評估新出現的物理現象或互動模式。 | 將 HarnessEval-W 設計為動態基準，定期新增技能與評估案例，並由社群審查。 |
| **計算成本高昂** | 每個案例都需多次呼叫 LLM 與視覺模型，規模化後成本可觀。 | 對簡單案例使用輕量規則式工具，僅在複雜情境啟動完整智慧體流程；建立快取機制。 |
| **評估標準的主觀性** | 某些面向（如觀察真實性）難以完全客觀量化，可能與人類偏好產生落差。 | 持續收集人類偏好資料，將其納入評分標準校正，並清楚揭露每項評估的判斷依據。 |
| **資料污染與過擬合** | 若待測模型在訓練時已見過評估案例，分數將失去鑑別力。 | 定期更新案例庫，採用結構化場景分類學產生新案例，並對敏感資料進行隔離。 |

## 與其他技術的整合建議

- **與 VBench / VBench++ 等傳統影片基準並行使用**  
  HarnessEval-W 補強傳統基準在「可解釋推理」與「物理因果判斷」上的不足；建議先用 VBench 取得整體品質分數，再用 HarnessEval-W 進行細粒度診斷與失敗定位。

- **整合 MLLM-as-a-Judge 流程**  
  可將 HarnessEval-W 的父智慧體與子智慧體視為多層次的 MLLM 評審，並與現有的 LLM 評估 harness（如 lm-evaluation-harness）對接，統一管理提示詞、模型呼叫與結果記錄。

- **銜接資料生成與模型訓練管線**  
  將 HarnessEval-W 的失敗案例自動回饋給世界模型的訓練或微調流程，形成「評估 → 診斷 → 資料增強 → 再訓練」的閉環。

- **與模擬器（MuJoCo、Isaac Gym、ThreeDWorld）結合**  
  在具備真實物理引擎的模擬器中產生 ground-truth 軌跡，作為 HarnessEval-W 的參考狀態，提升 Transition Correctness 與 World Persistence 評估的客觀性。

- **嵌入 CI/CD 與模型釋出閘道**  
  將 HarnessEval-W 設為模型釋出前的自動化閘道，當關鍵技能分數低於門檻或出現高風險失敗模式時自動阻擋釋出，並產出證據報告供工程師審查。
