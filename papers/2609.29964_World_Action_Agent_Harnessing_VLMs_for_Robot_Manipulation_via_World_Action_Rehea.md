## ⚡ TL;DR

現有系統僅讓 VLM 間接規劃或觀看場景，未提供可操作的視覺世界。
提出 WAA，透過接觸視圖、動作排練與視野內修正，讓 VLM 在視覺工作空間中駕馭機器人。
LIBERO-Pro 達 75.6%，9B VLM 領域外自 1.7% 升至 43.3%。

## 摘要翻譯

通用視覺語言模型（Vision-Language Models, VLMs）為機器人操作帶來廣泛知識與空間推理能力，然而現有系統或者間接使用它們——例如預測關係約束或撰寫程式——或者僅提供場景視角，而非一個可供其操作的世界。我們提出世界動作智能體（World Action Agent, WAA），一個多智能體駕馭框架（multi-agent harness），讓 VLM 透過基本工具駕馭機器人，並在視覺動作工作空間（visual action workspace）中做出每個決策。該工作空間具備三項特性。接觸視圖（contact views）依場景幾何（scene geometry）自動選取，呈現當前互動（current interaction）周圍的場景。動作排練（action rehearsal）將每個動作轉換為可編輯提案（editable proposal），智能體可自行或透過想像智能體（Imagination Agent），對照規劃回饋（planning feedback）在執行前預覽並修訂。視野內修正（in-view correction）構成觀測、排練與低階執行（low-level execution）之間的閉迴路（closed loop），讓智能體能在觀察到殘差偏移（residual offsets）的視野中直接消除該偏移。透過同一個工作空間，WAA 以兩種方式獲取具身程序性知識（embodied procedural knowledge）：它在基於證據的審查（evidence-based review）下，從專家影片（expert videos）與人類教導（human teaching）中演化出多模態技能（multimodal skills），並透過技能智能體（Skill Agent）檢索並運用這些技能；同時，其互動軌跡（interaction traces）可訓練較小的 VLM 來駕馭同一個框架。在 LIBERO-Pro 上，僅由 LIBERO-90 演化技能的 WAA 達到最先進水準（state-of-the-art）的 75.6% 平均成功率，優於端到端視覺語言動作模型（end-to-end VLAs）、程式即策略智能體（code-as-policy agents），以及採用相同骨幹網路（backbone）的視覺駕馭框架基線（visual-harness baseline）；這些技能在 robosuite 上無需進一步學習仍保持有效。在駕馭框架的互動軌跡上微調 Qwen3.5-9B，使其領域外成功率（out-of-domain success）從 1.7% 提升至 43.3%。

### 核心貢獻（3～5點）
- 提出 WAA 多智能體駕馭框架，讓 VLM 在視覺動作工作空間中直接駕馭機器人，而非僅作為約束預測器或程式生成器。
- 設計三大核心機制：依場景幾何自動選取的接觸視圖、可預覽與修訂的動作排練，以及能直接消除殘差偏移的視野內修正閉迴路。
- 建立雙途徑具身知識獲取方式：透過專家影片與人類教導在基於證據的審查下演化多模態技能，並以互動軌跡微調較小 VLM 來駕馭同一框架。
- 在 LIBERO-Pro 達到 75.6% 的最先進水準平均成功率，且技能可跨模擬器泛化至 robosuite，無需額外學習。

### 適合對象
本論文最適合機器人操作、具身智能（embodied AI）與視覺語言模型應用領域的研究者與工程師，特別是關注如何將大型 VLM/VLA 落地於實際機器人控制、多智能體協作框架、技能學習與泛化，以及希望透過人類教導與專家示範來演化可複用操作技能的讀者。對於想理解閉迴路視覺動作介面設計與開源 VLM 微調策略的學生與從業人員亦具高度參考價值。

## 深度分析

#### 方法論解析

##### 1.1 從「看場景」到「在世界中行動」的設計轉向

世界動作智能體（World Action Agent, WAA）的核心設計哲學，是讓通用視覺語言模型（Vision-Language Models, VLMs）不再只是間接提供關係約束（Relational Constraints）、中間路徑（Intermediate Paths）或程式碼，而是直接作為機器人操作的「駕駛員」，在單一視覺動作工作空間（Visual Action Workspace）內完成觀測、規劃、排練與修正。這個駕馭框架（Harness）透過基本原語（Basic Primitives）——例如 `pick()`、`place()`、`stack()`——讓 VLM 能夠反覆與視覺世界互動，而不是一次性輸出動作後就結束決策。

##### 1.2 視覺動作工作空間的三項性質

WAA 的工作空間具備三項關鍵性質，這三點也正是它與既有視覺機器人介面（Visual Robot Interface）的根本差異：

1. **接觸視圖（Contact Views）**：系統自動依據場景幾何（Scene Geometry）選取圍繞當前互動（Current Interaction）的局部視角，例如正面接觸視圖（Contact Front）與側面接觸視圖（Contact Side）。這讓 VLM 能專注於夾爪（Gripper）、物體（Object）與目標（Target）之間的局部關係（Local Relations），而非僅從全域視圖（Global View）推測空間細節。
2. **動作排練（Action Rehearsal）**：每個動作都被視為可編輯提案（Editable Proposal）。在真正執行前，VLM 可以預覽（Preview）動作效果，並根據規劃回饋（Planning Feedback）修訂（Revise）候選動作（Candidate Actions）。這個過程可由主智能體獨立完成，也可透過想像智能體（Imagination Agent）進行想像、模擬與評估，最後才確認並執行（Commit & Act）。
3. **視野內修正（In-view Correction）**：觀測（Observation）、排練與低階執行（Low-level Execution）形成閉迴路（Closed Loop）。當執行後仍存在殘差偏移（Residual Offsets）時，智能體可以在它實際觀察到的視野中直接修正，而不需要把影像誤差重新轉換為座標（Coordinates）再下指令。這大幅降低了感知空間與動作空間之間的轉換負擔。

##### 1.3 多智能體協作：想像智能體與技能智能體

WAA 是一個多智能體（Multi-agent）架構，除了主 VLM 之外，至少包含兩個關鍵角色：

- **想像智能體（Imagination Agent）**：負責在視覺世界中對候選動作進行心智模擬，評估不同提案的可行性與預期結果，並將評估結果作為規劃回饋提供給主智能體。這相當於讓 VLM 具備「先想後做」的能力。
- **技能智能體（Skill Agent）**：負責檢索與組合可複用技能（Reusable Skills）。這些技能是從專家影片（Expert Videos）與人類教導（Human Teaching）中演化而來的多模態技能（Multimodal Skills），結合了視覺觀測與語言描述，能夠跨任務共用。

##### 1.4 具身程序性知識的獲取與蒸餾

WAA 透過同一個工作空間獲取具身程序性知識（Embodied Procedural Knowledge），主要有兩條路徑：

1. **非參數化技能演化**：從專家影片與人類教導中學習技能，並透過基於證據的審查（Evidence-based Review）進行篩選與改進。人類教導可透過引導介面（Guidance Interface）進行，學習到的技能能支援零樣本適應（Zero-shot Adaptation）或單樣本適應（One-shot Adaptation）。
2. **互動軌跡蒸餾**：將 WAA 與環境互動產生的互動軌跡（Interaction Traces）用來微調（Fine-tuning）較小的開源視覺語言模型（Open-source VLMs），例如 Qwen3.5-9B，使其也能駕馭同一個 harness。這讓大型前沿 VLM 的決策能力有機會被壓縮到可在邊緣部署的模型上。

#### 實驗數據解讀

##### 2.1 LIBERO-Pro 上的最先進表現

在 LIBERO-Pro 基準測試（Benchmark）上，WAA 僅使用從 LIBERO-90 演化而來的技能，就達到 **75.6% 的平均成功率（Average Success）**，超越 ASPIRE 的 72.0%，也優於端到端視覺語言動作模型（End-to-end VLAs）、程式即策略智能體（Code-as-policy Agents），以及使用相同骨幹網路（Backbone）的視覺駕馭框架基線（Visual-harness Baseline）。

這個結果的意義在於：LIBERO-Pro 與 LIBERO-90 並非同一任務集合，WAA 展現了從相關但不同的任務分佈中遷移技能的能力。相較於需要大量機器人動作資料微調的 VLA，WAA 保留了 VLM 的通用理解與推理（General Understanding and Reasoning），同時透過視覺動作排練與接觸視圖彌補了空間精度的不足。

##### 2.2 跨環境遷移：robosuite

更值得注意的一點是，同一組技能在 robosuite 上仍然有效，且無需進一步學習。這顯示 WAA 所學到的技能並非過度擬合（Overfit）於 LIBERO 的特定模擬環境或物體外觀，而是捕捉了某種層次的任務結構與空間目標（Spatial Goals）。這對於未來跨模擬器、甚至跨真實機器人平台的遷移具有正面暗示。

##### 2.3 小型 VLM 的軌跡微調

作者將互動軌跡用於微調 Qwen3.5-9B，使其 out-of-domain success（領域外成功率）從原本的 **1.7% 提升至 43.3%**。這個對比非常強烈：

- **1.7%** 說明未經訓練的小型 VLM 幾乎無法直接駕馭 WAA 這類 harness，凸顯了視覺動作排練與多智能體協作對模型推理能力的高要求。
- **43.3%** 則證明互動軌跡中確實包含了可被學習的結構化決策模式，讓較小模型也能在一定程度上複製大型前沿 VLM 的操作行為。

不過，43.3% 與 WAA 使用大型 VLM 時的 75.6% 仍有顯著差距，這暗示小型模型在複雜規劃、錯誤診斷與多步排練方面仍有瓶頸。

##### 2.4 數據背後的意涵與限制

雖然 75.6% 是 state-of-the-art（最先進水準），但摘要與引言中並未提供標準差、任務層級分解或失敗案例分析。平均成功率（Average Success）可能掩蓋某些任務類別（例如涉及關節式機構 Articulated Mechanisms 的開抽屜任務）表現較差的情況。此外，實驗似乎仍侷限於模擬環境，尚未見真實機器人驗證。

#### 與現有研究的比較

##### 3.1 相對於端到端 VLA 與 WAM

視覺語言動作模型（Vision-Language-Action, VLA）如 RT-2、OpenVLA、π₀ 等，直接從視覺觀測（Visual Observations）與語言指令（Language Instructions）預測機器人動作（Robot Actions）。然而，為動作預測微調 VLM 可能削弱其一般理解與推理能力，且需要大量機器人資料。世界動作模型（World Action Models, WAMs）雖結合環境動力學（Environment Dynamics）與動作學習（Action Learning），但將學到的視覺動態落地（Grounding）到可執行控制（Executable Control）仍需要機器人資料與動作對齊（Action Alignment）。

WAA 採取互補途徑（Complementary Route）：不微調 VLM 的動作輸出，而是讓 VLM 在 harness 中透過基本原語進行決策，從而保留其廣泛知識（Broad Knowledge）與空間推理（Spatial Reasoning）。

##### 3.2 相對於 VLM 作為約束／程式產生器

HAMSTER、ReKep、OmniManip、FSD 等方法讓 VLM 產生關係約束、關鍵點、可 affordance 區域或視覺軌跡，再由下游策略（Downstream Policy）或最佳化器（Optimizer）轉換為動作。程式即策略（Code as Policies, CaP）與 CaP-X、ASPIRE、RATs、GaP 等則讓語言模型編寫感知與控制 API（Perception and Control APIs）程式，並透過執行回饋（Execution Feedback）修訂。

這些方法的有效性高度依賴手設抽象層的品質，CaP-X 甚至報告移除手設抽象後性能下降。WAA 的差異在於：VLM 不是產生約束或程式，而是直接在視覺動作工作空間內選擇、排練與修正動作，從而減少對符號化 API 的依賴。

##### 3.3 相對於視覺機器人介面

Show-Harness 與 VIA 已經讓 VLM 透過視覺介面直接選擇與修訂動作，將操作轉化為互動式視覺推理（Interactive Visual Reasoning）問題。但作者指出這類介面只「顯示場景」而非「提供可操作的世界」，缺少三項要素：

1. 觀測未以當前互動為中心；
2. 動作無法在執行前試探；
3. 感知與動作處於不同空間。

WAA 透過接觸視圖、動作排練與視野內修正，分別對應解決了這三個缺失。

##### 3.4 限制與未解決的挑戰

儘管 WAA 在概念與數據上都很有說服力，但仍有一些潛在限制：

- **接觸視圖的生成依賴場景幾何**：在真實環境中，如何從單眼或稀疏相機系統穩定估計場景幾何並選取適當視角，仍是開放問題。
- **基本原語的表達力有限**：`pick()`、`place()` 等原語適合拾取與放置（Pick & Place）、碗置於盤上（Bowl on Plate）、開抽屜（Open Drawer）等任務，但對於需要連續力控制或複雜軌跡的操作可能不足。
- **計算成本**：多智能體排練、想像模擬與反覆修訂可能帶來顯著的推理延遲。
- **缺乏真實機器人驗證**：目前結果集中在 LIBERO-Pro 與 robosuite 模擬環境，sim-to-real 的挑戰尚未被檢驗。

---

#### 可重現性評估

從提供的摘要與引言來看，作者並未明確說明是否釋出原始碼、模型權重或互動軌跡資料集。若要達成高可重現性，至少需要以下項目公開：

- WAA harness 的完整實作，包括接觸視圖選取、動作排練迴路與視野內修正機制；
- 想像智能體（Imagination Agent）與技能智能體（Skill Agent）的提示設計與決策流程；
- 從 LIBERO-90 演化技能的完整流程，以及所產生的可複用技能庫；
- 用於人類教導的引導介面（Guidance Interface）規格；
- 微調 Qwen3.5-9B 所使用的互動軌跡（Interaction Traces）與訓練設定；
- 在 LIBERO-Pro 與 robosuite 上的評估腳本與隨機種子設定。

目前 LIBERO、robosuite 與 Qwen3.5-9B 均為公開資源，但 WAA 本身的實作細節若未釋出，其他研究者只能進行概念層級的復現，難以精確重現 75.6% 與 43.3% 等數據。

#### 未來研究方向

1. **真實機器人部署與 sim-to-real 遷移**：將 WAA 從模擬環境轉移到真實機器人，研究接觸視圖在真實相機下的選取策略，以及視野內修正對校準誤差的容忍度。
2. **與世界動作模型（WAMs）的深度融合**：目前 WAA 的排練可能依賴簡單幾何或 VLM 內部想像；若結合學習過的環境動力學，可進行更真實的動作預演。
3. **線上技能演化與終身學習**：讓 WAA 在執行過程中持續收集證據、更新技能庫，並自動發現新的可複用技能，而非僅從靜態專家影片學習。
4. **擴展感知模態**：除了視覺，可引入觸覺、力覺、聽覺等多模態資訊，讓接觸視圖與動作排練能處理更細緻的物理互動。
5. **主動感知（Active Perception）**：將接觸視圖的選取從基於幾何啟發式規則，提升為可由 VLM 或專用策略學習的主動觀測決策。
6. **更小模型的進一步蒸餾與邊緣部署**：探索如何將 WAA 的決策模式蒸餾到更小甚至專用的視覺語言模型，以降低延遲與成本。
7. **安全與可解釋性**：由於 VLM 直接控制機器人，需要建立可解釋的排練過程與安全守衛機制，讓人類能理解並在必要時介入修正。
8. **複雜連續動作與工具使用**：擴展基本原語，使其能表達更複雜的連續軌跡、力控制與多步工具操作任務。

## 論文問答

**Q1：WAA 試圖解決機器人操作領域中的什麼核心問題？**

A：WAA 針對的核心問題是：如何讓具備廣泛知識與空間推理能力的通用視覺語言模型（VLM），能夠直接駕馭機器人執行操作任務，而不是僅作為間接的約束產生器或程式撰寫者。現有方法往往把 VLM 當成高階規劃工具，再由下游策略或最佳化器轉換成動作，導致 VLM 的空間理解無法直接落實到控制。WAA 透過建立一個視覺動作工作空間，讓 VLM 在單一介面中觀察、排練並修正每個基本動作，從而扮演真正的機器人駕駛員。

**Q2：為什麼現有的端到端 VLA 與世界動作模型（WAM）無法充分解決這個問題？**

A：端到端 VLA 需要微調 VLM 來預測動作，這個過程可能削弱模型原本的一般理解與多模態推理能力，進而限制泛化表現。WAM 雖然結合環境動力學與動作學習，但要把學到的視覺動態對應到可執行控制，通常仍需要大量機器人資料與動作對齊，跨型態遷移也對機器人形態與動作空間差異很敏感。WAA 採取互補路徑：保留 VLM 的通用性，讓它透過基本原語在視覺世界中直接做決策，而非重新訓練整個動作模型。

**Q3：為什麼「給 VLM 一個世界而不只是畫面」對機器人操作如此重要？**

A：現有的視覺機器人介面只把場景顯示給 VLM，讓它選擇動作，但缺少以當前互動為中心的觀測，也無法在執行前試探動作後果，導致感知與動作空間脫節。WAA 提出的視覺動作工作空間則具備接觸視圖、動作排練與視野內修正三項特性，讓夾爪、物體與目標之間的局部關係成為決策核心。這種設計把操作轉化為互動式視覺推理問題，使 VLM 能夠在執行前就「看見」並修訂自己的行為。

**Q4：WAA 的視覺動作工作空間具備哪三項關鍵特性？**

A：第一項是接觸視圖，系統會依據場景幾何自動選取圍繞當前互動的局部視角，讓 VLM 專注於夾爪與物體之間的關鍵空間關係。第二項是動作排練，每個動作都先變成可編輯提案，由智能體單獨或透過想像智能體進行預覽，並根據規劃回饋修訂後才執行。第三項是視野內修正，觀測、排練與低階執行在同一組已校準的視圖中形成閉迴路，讓智能體能直接在觀察到的視野中消除殘差偏移。

**Q5：世界動作排練機制是如何運作的？**

A：在 WAA 中，每個待執行的動作都會先被轉換為可編輯提案，而不是立刻發送給機器人。智能體可以在視覺工作空間中預覽該提案的結果，並根據規劃回饋反覆修訂；想像智能體則負責想像、模擬與評估多個候選動作，協助挑選最合適方案。只有在排練通過後，系統才會執行「確認並執行」，把提案轉成實際的低階控制指令。

**Q6：WAA 的多智能體架構包含哪些角色，各自負責什麼？**

A：WAA 主要由三個智能體協同運作：主駕駛智能體負責在視覺動作工作空間中觀察場景並建構動作提案；想像智能體負責對候選動作進行想像、模擬與評估，提供排練回饋；技能智能體則負責從多模態技能庫中檢索並組合可複用技能。這些智能體共享同一個視覺工作空間，使高階語義推理、空間預覽與程序性知識能夠無縫銜接。這種分工讓通用 VLM 不必重新訓練，就能以基本工具完成多樣化的操作任務。

**Q7：WAA 在哪些基準測試與任務上進行評估？**

A：論文主要在 LIBERO-Pro 上評估 WAA 的平均成功率，並且僅使用 LIBERO-90 的資料來演化技能，以測試跨任務遷移能力。此外，同一組技能被直接應用到 robosuite 模擬平台，驗證其無需進一步學習即可轉移。測試任務涵蓋拾取與放置、碗置於盤上、開抽屜等涉及空間目標與關節式機構的多樣化操作。

**Q8：WAA 取得了哪些關鍵實驗結果？**

A：WAA 在 LIBERO-Pro 上達到 75.6% 的平均成功率，超過 ASPIRE 的 72.0%，也優於端到端 VLA、程式即策略智能體以及使用相同骨幹網路的視覺駕馭框架基線。更令人注意的是，這些技能僅從 LIBERO-90 演化而來，卻能直接在 robosuite 上保持有效，無需額外學習。另外，在 WAA 的互動軌跡上微調 Qwen3.5-9B 後，其領域外成功率從 1.7% 大幅提升到 43.3%，顯示小型開源 VLM 也能學會駕馭同一框架。

**Q9：哪些對照實驗或消融分析證明了 WAA 設計的價值？**

A：與使用相同骨幹網路的視覺駕馭框架基線相比，WAA 的接觸視圖、動作排練與視野內修正顯著提升了操作成功率，證明「給 VLM 一個可操作世界」比單純顯示場景更有效。與程式即策略智能體和端到端 VLA 的比較則顯示，直接讓 VLM 在視覺空間中選擇並修訂基本原語，優於間接產生約束或撰寫程式。技能演化實驗也顯示，基於專家影片與人類教導、並經過基於證據審查的多模態技能庫，是達成高泛化表現的關鍵。

**Q10：WAA 可能應用在哪些實際場景？**

A：WAA 可應用於家庭服務機器人，例如根據自然語言指令完成拾取放置、堆疊餐具或開關抽屜等日常操作。在工業場景中，它也能透過可複用技能庫快速適應不同的組裝或搬運流程，並透過人類教導的引導介面進行單樣本或零樣本適應。由於 WAA 主要依賴通用 VLM 與基本原語，而非大量任務專屬機器人資料，因此能降低新任務部署的資料收集成本。

**Q11：若要將 WAA 產品化，需要考慮哪些實務問題？**

A：首先必須確保接觸視圖能從場景幾何中穩定且即時地產生，因為視角品質會直接影響 VLM 的空間判斷。其次，動作排練與多智能體互動會增加推理延遲，需要設計高效的排程與快取機制，並在確認執行前加入安全檢查。最後，真實世界的感知雜訊、遮擋與機器人控制誤差都可能挑戰視野內修正的效果，因此需要與低階控制器緊密整合並進行實機驗證。

**Q12：WAA 對機器人學習領域可能帶來什麼影響？**

A：WAA 代表一種新的範式轉移：與其微調 VLM 成為動作預測器，或學習專用的世界動作模型，不如把前沿 VLM 當成能在視覺世界中推理與排練的駕駛員。它同時展示了兩種知識累積途徑——非參數化的技能演化與互動軌跡蒸餾到較小 VLM——為通用機器人系統的規模化提供可行路徑。這種方法有助於縮短高階語義理解與低階機器人控制之間的鴻溝，推動更具泛化性的具身智能體發展。

**Q13：WAA 目前有哪些已承認或隱含的限制？**

A：WAA 的表現高度依賴 VLM 本身的空間推理能力，以及場景幾何與接觸視圖的品質，若視角選取不當可能導致錯誤判斷。相較於端到端策略，多智能體排練與修訂迴路會增加推理時間，對需要毫秒級反應的任務可能構成挑戰。此外，目前提供的內容主要聚焦於模擬環境，真實世界中的感測器雜訊、物理不確定性與更複雜的操作原語仍需進一步驗證。

**Q14：WAA 可能在哪些情況下失敗？**

A：如果接觸視圖未能涵蓋關鍵的局部幾何資訊，例如物體背面或夾爪與目標的精確接觸點，VLM 可能做出錯誤的動作提案。想像智能體若對環境動力學模擬不準，排練結果也會誤導後續執行，導致碰撞或抓取失敗。此外，當初始誤差過大、視野嚴重遮擋，或任務涉及技能庫中未涵蓋的新型關節式機構時，視野內修正可能無法完全恢復正確操作。

**Q15：未來可以朝哪些方向延伸 WAA？**

A：未來可以將 WAA 部署到真實機器人與更多樣的機器人型態上，驗證其跨 embodiment 的適用性。同時，可結合更精確的世界模型來強化動作排練，使想像智能體能預測更複雜的物理交互與長期後果。另一個方向是擴大技能庫規模、累積更多互動軌跡，並結合自主探索與自我導向遊戲，讓 WAA 能持續演化具身程序性知識，進一步提升開源 VLM 的駕馭能力。

## 實務應用指南

### 適用場景

**智慧倉儲與物流揀選**  
WAA 的接觸視圖與視野內修正特別適合貨架揀選、料箱取放與混箱裝載。VLM 可根據局部視覺關係判斷夾爪與目標物的相對位置，並透過動作排練預覽抓取姿態，減少碰撞與掉落。當貨物品項或擺放方式改變時，可藉由專家影片或少量人類教導演化新技能，無需從頭收集大規模機器人軌跡。

**家庭服務機器人**  
在開放式家居環境中，WAA 可讓通用 VLM 透過基本原語（如 pick()、place()、stack()）執行收拾餐具、把碗置於盤上、開抽屜等任務。多模態技能庫能儲存常見家務程序，遇到新佈局時由 Skill Agent 檢索並組合可複用技能，並由 Imagination Agent 在視覺世界中排練候選動作，降低在真實環境試錯的成本。

**製造業組裝與品檢**  
針對小批量、多品項的產線任務，WAA 可將人類示範影片轉化為結構化技能，並在執行時透過閉迴路修正殘差偏移。例如插件、鎖螺絲、工件堆疊等操作，可利用接觸視圖聚焦夾爪與孔位或螺絲的局部關係，並在視覺動作工作空間中反覆排練與校正，提升組裝精度與換線彈性。

**醫療輔助與長照**  
在輔助餵藥、遞送物品或整理病床環境等任務中，WAA 的多智能體架構可將高風險動作先於視覺世界中排練，並由人類照護者透過引導介面審查與修訂。基於證據的技能審查機制有助於確保學習到的程序符合安全規範，減少因 VLM 推論錯誤導致的危險動作。

**零售與餐飲服務**  
從咖啡拉花前的器具擺放、餐點裝盤到貨架補貨，WAA 可將店員示範錄製為多模態技能，並在營業低峰時由機器人複製相同程序。當菜單或陳列規則更新時，只需提供新的專家影片或人類教導軌跡，即可透過同一個視覺動作工作空間演化技能，縮短導入週期。

### 實作前置條件

**資料準備**  
需要高品質的專家示範影片或人類教導軌跡，內容應包含視覺觀測、語言指令與對應的低階機器人動作。若採用 LIBERO-90 這類現有基準進行技能演化，則需確認場景幾何與任務標註格式與 WAA 相容。此外，建議預先建立任務語言模板與物體名稱對照表，以便 Skill Agent 檢索與組合可複用技能。

**運算資源**  
核心決策仰賴前沿視覺語言模型（如 GPT-4V、Gemini 或 Qwen 系列），可選擇 API 呼叫或本地部署。若要在互動軌跡上微調較小 VLM（如 Qwen3.5-9B），則需配備至少數張高階 GPU 的訓練叢集。模擬環境（如 robosuite 或 LIBERO）用於驗證排練迴路與技能演化，建議具備可渲染接觸視圖的相機配置與物理引擎。

**技能與團隊**  
實作團隊需熟悉機器人學（運動學、夾爪控制）、電腦視覺（相機標定、場景幾何）、提示工程與多智能體系統設計。若要走完整論文路線，還需具備微調開源 VLM 與評估領域外泛化的能力。產品化時則建議加入資安、功能安全與人機互動設計人員。

### 實作步驟建議

**步驟一：建構視覺動作工作空間**  
先決定機器人平台的相機配置與座標系統，確保能根據場景幾何自動選取接觸視圖（正面與側面）。接著建立全域視圖與局部接觸視圖的對應關係，並完成相機內外參標定，使影像中的像素偏移能直接對應到執行座標，為後續視野內修正奠定基礎。

**步驟二：定義基本原語與動作提案格式**  
將機器人能力封裝為一組基本原語，例如 pick()、place()、stack()、open() 等。每個原語需包含可編輯參數（目標物、目標位置、接近方向、夾爪開合度），並設計成 VLM 可直接產生與修訂的結構化格式。這些原語是動作排練與技能組合的最小單元。

**步驟三：實作世界動作排練閉迴路**  
讓 VLM 在每次執行前將動作轉為可編輯提案，並透過 Imagination Agent 在視覺世界中預覽與評估。規劃回饋應包含碰撞檢查、目標達成度與穩定性估計。若評估未通過，則回到 VLM 修訂參數，反覆排練直到確認並執行。執行後再將觀測結果與預期比對，進行視野內修正。

**步驟四：建立技能庫與 Skill Agent**  
收集專家影片與人類教導軌跡，透過基於證據的審查機制演化多模態技能。每個技能應記錄前置條件、執行步驟、預期結果與適用場景描述。Skill Agent 負責根據語言指令與當前觀測檢索相關技能，並將其組合為完整任務計畫。

**步驟五：模擬驗證與迭代**  
在 LIBERO-Pro、robosuite 或自訂模擬環境中進行大規模測試，評估平均成功率與領域外泛化能力。特別關注接觸視圖選取是否正確、動作排練是否減少失敗、視野內修正能否消除殘差偏移。根據錯誤案例補充示範資料或調整提示模板。

**步驟六：真實機器人部署與持續學習**  
將驗證後的系統部署到真實機器人，初期保留人類監督與引導介面，讓操作員能在動作排練階段介入修訂。收集真實互動軌跡，定期用於微調較小 VLM 或擴充技能庫，形成「執行—檢討—演化」的持續學習管線。

### 潛在風險與注意事項

**VLM 幻覺與空間誤差**  
通用 VLM 可能對細微深度或遮擋關係產生錯誤判斷。建議透過接觸視圖強化局部觀測，並以動作排練作為 sanity check；對於高風險動作，可強制要求 Imagination Agent 產生多組候選動作並比較評分，再交由人工或安全規則最終把關。

**延遲與即時性**  
反覆排練與多智能體協作會增加決策延遲，可能不適合需要毫秒級反應的任務。可將常見技能編譯為快取策略，或讓較小 VLM 在本地處理簡單子任務，僅將複雜場景提交給大型前沿 VLM 進行排練。

**技能庫膨脹與維護**  
隨著任務增加，可複用技能數量可能快速成長，導致檢索效率下降或版本混亂。應建立技能版本控制、相似度去重與定期審查機制，並為每個技能標註失效條件與適用機器人型號。

**安全與人機協作**  
即使動作經過排練，真實環境仍可能出現未建模的干擾。建議在硬體層設置緊急停止、力控保護與工作空間限制，並在軟體層將高衝擊動作標記為需人工確認。部署初期應採用協作模式，而非全自主運行。

**領域外泛化限制**  
論文顯示微調後的 Qwen3.5-9B 在領域外成功率仍有限。產品化時應明確界定任務範圍，並設計降級策略：當 Skill Agent 無法檢索到合適技能或 Imagination Agent 評估分數過低時，主動請求人類介入。

### 與其他技術的整合建議

**與端到端 VLA 模型搭配**  
可將 WAA 作為高階決策層，負責任務分解、技能選擇與動作排練；VLA 模型則作為低階控制器，負責將 WAA 產生的目標姿態轉為連續機器人動作。這樣既能保留 VLM 的泛化性與可解釋性，又能利用 VLA 的動作精細度。

**與世界動作模型（WAM）整合**  
WAM 可提供環境動力學預測，補強 Imagination Agent 的模擬能力。例如 WAM 預測物體被推動後的運動軌跡，WAA 則在此基礎上排練抓取或放置動作，並透過視野內修正對齊真實狀態。

**與數位孿生及模擬平台整合**  
將 WAA 的視覺動作工作空間對接到數位孿生環境，可在虛擬世界中大規模排練新技能，再將驗證過的技能部署到實體機器人。這也能支援遠端監控與人類操作員透過引導介面進行教導。

**與企業系統（MES/WMS）整合**  
在倉儲或製造場景中，WAA 可接收來自倉儲管理系統（WMS）或製造執行系統（MES）的語言指令與工單資訊，並將執行結果回傳。Skill Agent 可根據工單類型自動檢索對應技能，實現彈性生產與動態揀選。

**與持續學習管線整合**  
將互動軌跡自動匯入資料湖，定期觸發技能演化與 VLM 微調。可結合主動學習策略，優先挑選不確定性高或失敗案例進行人工標註，避免重複收集大量冗餘資料。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從圖 1 的整體架構與「視覺動作工作空間」三個特性（接觸視圖、動作排練、視野內修正）著手，理解 WAA 如何讓通用 VLM 像「機器人駕駛」一樣操作機器人。不必急著深入多智能體細節，重點掌握它與端到端 VLA、程式即策略（CaP）的差異：WAA 不直接預測動作，也不寫程式，而是在視覺世界中反覆排練與修正。

**給 AI 工程師**  
請聚焦於實作細節：接觸視圖如何根據場景幾何自動選取、動作提案的資料結構與 API 設計、Imagination Agent 與 Skill Agent 的提示模板與協作流程，以及如何利用互動軌跡微調 Qwen3.5-9B。建議搭配 LIBERO 或 robosuite 重現論文實驗，並嘗試將基本原語對接到自己熟悉的機器人平台。

**給研究人員**  
本文的核心貢獻在於提出「世界動作排練」作為連接 VLM 空間推理與機器人執行的中介機制。可進一步探討的問題包括：接觸視圖選取的理論保證、動作排練與模型預測控制（MPC）的關係、技能庫的組合泛化邊界，以及 WAA 與世界動作模型（WAM）的深度融合。論文中的 LIBERO-Pro 與 robosuite 轉移實驗也提供了良好的基準延伸方向。

**給產品經理**  
請將本文視為一個「降低機器人任務導入成本」的架構：它讓非專家能透過影片示範或人類教導生成可複用技能，並以視覺化方式審查機器人即將執行的動作。評估導入時，應優先考慮任務是否具備重複性、容錯性與可視覺化排練的特性，並規劃人機協作與安全把關機制。技術選型上需權衡 API 成本、延遲與資料隱私，決定採用雲端前沿 VLM 或本地微調模型。
