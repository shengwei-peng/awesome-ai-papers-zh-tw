## 摘要翻譯

使用終端機的智慧體（Terminal-Using Agents）已迅速成為語言模型（Language Models, LM）最熱門的下游應用（Downstream Application）。儘管它們如此普及，學術界對這些模型基於強化學習（Reinforcement Learning, RL）的訓練卻相對少有探討，推測原因在於困難的基準測試、資料不足，以及缺乏簡單的基線配方（Baseline Recipes）。我們提出 TMAX，這是迄今最強大的終端機智慧體（Terminal Agents）開放強化學習配方，使開放資料配方（Open Data Recipes）更接近前沿（Frontier）。我們的配方雖然簡單，但在 Terminal-Bench 2.0 上僅以 9B 參數（Parameters）便達到 27% 的表現，超越了先前研究中規模大得多的模型。具體而言，我們使用新穎的分類法（Taxonomy）來生成資料，結合難度控制（Difficulty Control）、角色設定（Personas）與驗證器多樣化（Verifier Diversification），使我們得以低成本地生成大量終端機環境（Terminal Environments），以供強化學習（RL）與監督式微調（Supervised Fine-Tuning, SFT）訓練之用。我們以開源（Open-Source）方式釋出終端機資料集（Terminal Dataset），其規模比先前釋出的終端機智慧體資料集大 2.5 倍以上。接著，我們運用上述資料，透過簡單的僅結果導向配方（Outcome-Only Recipe），以強化學習訓練開放權重模型（Open-Weight Models）。我們將資料、模型與程式碼釋出於 https://github.com/hamishivi/tmax，作為未來終端機智慧體開放學術研究的強大基

## 深度分析

#### 方法論解析

本研究提出 TMAX（Terminal MAX），一套針對終端機智慧體（terminal agents）的開放強化學習（Reinforcement Learning, RL）配方。其核心方法論可分為資料生成管線與 RL 訓練配方兩大支柱。

在資料生成端，作者設計了一套新穎的 taxonomy（分類法），透過 difficulty control（難度控制）、personas（角色設定）與 verifier diversification（驗證器多樣化）三項策略，利用 frontier（前沿）語言模型（Language Models, LMs）大規模合成終端機環境（terminal environments）。具體而言，difficulty control 能系統性地調控任務複雜度，避免資料過於簡單而無法提供有效學習訊號；personas 則透過多樣化的角色設定增加任務分布的廣度；verifier diversification 讓驗證機制不再侷限於二元正確性檢查，而是針對特定任務提供 continuous-valued rewards（連續數值獎勵）。最終產出的 TMAX-15K 資料集包含 14,600 個 RL 環境實例，規模超過先前最大公開終端機資料集（terminal dataset）的 2.5 倍，且在難度上顯著高於多數既有工作。

在訓練端，TMAX 採用 outcome-only recipe（僅結果導向配方），即僅依據任務最終結果給予獎勵，而非設計繁複的過程獎勵。作者基於 open-instruct 框架建構 fully asynchronous RL infrastructure（全非同步強化學習基礎設施）。針對長期任務（long-horizon tasks）中 naive GRPO（Group Relative Policy Optimization）訓練不穩定的問題，本研究選用 DPPO（Divergence Proximal Policy Optimization）作為最佳化器，並搭配 FP32 LM head 與 large group size（大群組大小）以穩定梯度更新。這套簡單卻有效的組合，使得開放權重模型（open-weight models）能在複雜的 agentic coding（智慧體程式設計）場景中完成穩定的 RL 訓練。

#### 實驗數據解讀

實驗結果顯示，TMAX-9B 在 Terminal-Bench 2.0 上達到 27% 的成績，在 32B 參數（parameters）以下的模型中主導了 Pareto curve（帕累托曲線）。從 Figure 1 可以觀察到，TMAX 系列不僅大幅超越先前採用開放資料配方（open data recipes）的模型（如 TerminalTraj、TermiGen、Endless Terminals 與 OpenThinker-Agent），甚至優於許多參數規模（model size）更大的開放權重模型，例如 Nemotron-32B 與 LiberCoder-235B-A22B。TMAX-27B 同樣位於帕累托前沿（Pareto frontier）上，顯示此配方具備良好的規模擴展性。

更值得關注的是泛化性實驗。作者發現，經過 TMAX 資料進行 RL 訓練後，模型在 SWE-Bench Verified（錯誤修復基準）上提升超過 5 分，在非代理評估如 AIME 上亦有進步。這項結果強烈表明，此訓練並非單純的 harness-fitting（評估框架過擬合），而是真正教會了模型可遷移的新能力與技能。此外，跨 harness（評估框架）實驗顯示，即使測試時採用與訓練期間不同的 prompts（提示）與 toolsets（工具集），模型表現依然提升，證明其具備穩健的泛化能力。

#### 與現有研究的比較

相較於既有研究，TMAX 的定位十分明確：填補終端機智慧體領域中 RL-based training（基於強化學習的訓練）的學術空白。過往工作多聚焦於 bug-fixing setups（錯誤修復設定）或相對簡單的終端機任務（如 NL2Bash），且大多僅將生成的資料用於監督式微調（Supervised Fine-Tuning, SFT），較少深入探討 RL 訓練端。TMAX-15K 在規模與難度上均超越這些前期資料集，並成功證明簡單的 outcome-only RL 即可顯著提升效能。

與閉源模型（closed models）相比，TMAX-9B 的表現已可媲美較小規模的 Claude-Haiku-4.5，但在絕對數值上仍落後於 Claude-Sonnet-4.6、GLM-5、Kimi-K2.5 與 GPT-5 系列等頂尖閉源或超大模型。這顯示開放配方雖已逼近前沿（frontier），仍有成長空間。此外，本研究的資料生成仍高度依賴單一強大的 frontier model，這可能引入生成資料的偏差或能力天花板，是方法論上的一項潛在限制。

#### 可重現性評估

TMAX 在可重現性（reproducibility）方面樹立了良好典範。作者公開釋出資料、模型權重與程式碼，並特別提供 RL 訓練過程中的 rollouts（展開軌跡）與 logprobs（對數機率）等訓練產物。這些 artifacts 對於後續研究者分析訓練動態、除錯與改進配方至關重要。訓練基礎設施基於 open-instruct，採用開放且可取得的技術堆疊，加上作者刻意強調的 simple baseline recipes（簡單基線配方），大幅降低了學術界進入此領域的門檻。釋出的模型涵蓋 TMAX-2B、4B、9B 與 27B，使研究者能針對不同運算資源進行 scaling analysis（規模分析）。

#### 未來研究方向

基於 TMAX 的貢獻與限制，未來研究可朝以下方向推進：

第一，訓練穩定性。儘管 DPPO 與 FP32 LM head 已改善 naive GRPO 的問題，長期任務（long-horizon tasks）中的 RL 訓練穩定性仍是核心挑戰，值得探索更先進的 policy optimization 演算法或 value function 輔助機制。

第二，複雜工具呼叫與協調。目前的 terminal environments 主要聚焦於單一終端機操作，未來可擴展至更複雜的 tool call setups（工具呼叫設定），例如多工具並行、跨環境狀態追蹤，以及與外部 API 的深度整合。

第三，評估框架改進。現有的 Terminal-Bench 2.0 雖已比早期基準複雜，但真實世界的軟體開發場景更為多變。未來需要 harness improvements（評估框架改進）來捕捉更細緻的代理能力，例如長期記憶、使用者意圖推論與多輪協作。

第四，資料品質與多樣性。降低對單一 frontier model 生成資料的依賴，引入更多元的 verifier diversification（驗證器多樣化）策略與 crowdsourced 驗證，將有助於突破合成資料的品質天花板。

第五，跨領域遷移與下游應用。TMAX 已初步展示 terminal RL 訓練對 SWE-Bench 與 AIME 的正面外溢效果，未來應系統性探討其對其他下游應用（downstream applications）的助益，並發展專門的理論框架來解釋此現象。

第六，規模擴展。探索超過 27B 參數的模型，或將此配方應用於更強大的基礎模型，觀察是否能持續推進帕累托前沿（Pareto frontier），與頂尖閉源模型縮小差距。

## 論文問答

**Q1：為什麼終端機智慧體的強化學習訓練在學術界相對缺乏研究？**

A：根據本文分析，終端機智慧體雖然已成為語言模型最熱門的下游應用之一，但學術界對於基於強化學習的訓練方法探討卻相對稀少。這主要是因為該領域面臨三大挑戰：基準測試難度過高、缺乏足夠的公開訓練資料，以及缺少簡單且可複現的基線配方。此外，現有研究大多聚焦於錯誤修復或相對簡單的終端任務，而非像 Terminal-Bench 所呈現的複雜長期任務，這使得研究者難以建立有效的強化學習訓練流程。

**Q2：現有的終端機智慧體資料集存在哪些主要缺陷？**

A：現有的終端機智慧體資料集普遍存在規模不足與難度偏低的問題。例如，過往的 NL2Bash 資料集僅包含簡短的自然語言指令與對應的 Bash 命令，無法提供複雜任務所需的強化學習訊號；而後續的開源資料集在環境數量與任務多樣性上也相當有限。更重要的是，多數資料集缺乏對任務難度的明確控制，也僅使用二元正確性檢查作為驗證機制，無法充分訓練模型處理需要連續評估的複雜終端環境。

**Q3：為什麼建立簡單且強大的終端機智慧體基線對學術界很重要？**

A：建立簡單且強大的基線能夠有效降低學術研究的進入門檻，讓更多研究者能在穩固的起點上進行後續創新。由於終端機智慧體的應用已迅速普及，但開放資料配方與技術前沿之間存在明顯差距，若沒有公開的資料、模型與訓練配方，學術界將難以複現或超越現有成果。本文強調，提供像 TMAX 這樣的開源基線不僅能推動技術進步，還能幫助社群探索訓練穩定性、複雜工具呼叫設定等獨特挑戰。

**Q4：TMAX 資料生成的核心方法是什麼？**

A：TMAX 採用一個強大但簡單的合成資料生成流程，透過前沿模型產生多樣化的終端機環境。其核心創新在於引入了一個新穎的分類法，結合難度控制、角色設定與驗證器多樣化三項策略，使得研究團隊能夠以較低成本大規模生成高品質的終端環境。這種方法不僅能產生超過 14,600 個強化學習環境實例，還能針對不同任務類型與難度等級進行精細調控，遠超過以往僅依賴二元正確性檢查的資料生成方式。

**Q5：TMAX 在強化學習訓練上有哪些關鍵的技術選擇？**

A：為了解決長期任務中訓練不穩定的問題，TMAX 沒有採用常見的 GRPO，而是選擇使用 Divergence Proximal Policy Optimization（DPPO）作為主要的強化學習演算法。研究團隊特別搭配了 FP32 的語言模型輸出層與較大的群組大小，以進一步提升訓練過程的數值穩定性。此外，TMAX 採用僅結果導向的簡單配方，不依賴複雜的過程獎勵或中間步驟監督，證明即使在長期且複雜的終端機場景中，單純的結果導向強化學習也能達到強大的效能。

**Q6：TMAX 的資料集 TMAX-15K 與先前資料集相比有何獨特之處？**

A：TMAX-15K 包含 14,600 個強化學習環境實例，規模超過先前公開終端機資料集的 2.5 倍以上，是目前最大的公開終端機智慧體資料集之一。與過往資料集不同的是，TMAX-15K 明確控制任務難度，並涵蓋多樣化的領域與所需技能，且針對特定任務採用連續數值獎勵而非僅有二元正確性判斷。根據 Gemini-3-Flash-Preview 的通過率評估，該資料集的整體難度顯著高於大多數既有工作，能為模型提供更具挑戰性的學習訊號。

**Q7：TMAX 在 Terminal-Bench 2.0 上的主要實驗結果為何？**

A：TMAX-9B 在 Terminal-Bench 2.0 上達到了 27% 的成績，這個表現不僅超越了許多參數量更大的既有開源模型，甚至在 320 億參數以下的模型中佔據了帕累托前沿的主導地位。相較於先前的開放強化學習配方如 Endless Terminals 和 OpenThinker-Agent，TMAX 展現了明顯的效能優勢。值得注意的是，這樣的成績僅透過一個簡單的僅結果導向強化學習配方與 90 億參數的模型就得以實現，顯示了資料品質與訓練策略的重要性。

**Q8：TMAX 的訓練成果在跨任務與跨框架泛化方面表現如何？**

A：實驗顯示 TMAX 的強化學習訓練不僅僅是「評估框架過擬合」，而是真正教會了模型新的能力。研究發現，經過強化學習訓練的模型在 SWE-Bench Verified 上提升了超過 5 個百分點，在非智慧體評估如 AIME 上也有進步。更重要的是，即使改用與訓練時不同的提示詞與工具集進行評估，模型表現依然提升，這提供了強而有力的證據，證明終端機環境中的強化學習訓練能夠非平凡地泛化到不同任務與評估框架。

**Q9：與閉源及大型開源模型相比，TMAX 的效能定位為何？**

A：雖然 TMAX-9B 的 27% 成績仍低於 Claude-Sonnet-4.6、GLM-5 等頂尖閉源或超大規模模型，但它在 320 億參數以下的開放權重模型中已達到最先進水準。圖一顯示 TMAX 系列模型明顯主導了小型模型的帕累托曲線，TMAX-27B 也位於效能前沿。這表示 TMAX 成功將開放資料配方大幅推向技術前沿，證明透過精心設計的資料生成與簡單的強化學習配方，中小型開源模型也能在複雜終端任務上與更大型的模型競爭。

**Q10：TMAX 的開源釋出對實務應用與學術研究有何具體價值？**

A：TMAX 團隊公開釋出了資料集、模型權重、訓練程式碼，甚至包含強化學習訓練過程中的 rollout 與 logprob 等訓練產物，這大幅降低了後續研究者重現與分析門檻。對於實務應用而言，這意味著開發者可以直接使用經過強化學習訓練的強大終端機智慧體，無需從頭建構昂貴的資料生成與訓練基礎設施。對學術界來說，這些資源提供了一個穩固的基線，使研究者能夠專注於探索訓練穩定性、複雜工具呼叫與更困難下游任務等開放問題。

**Q11：終端機智慧體在實際產品開發中面臨哪些獨特挑戰？**

A：終端機智慧體在實際產品中必須處理長時間執行且高度複雜的任務，這對訓練穩定性與工具呼叫的精確度提出了嚴苛要求。與一般的對話或程式碼生成不同，終端機環境中的錯誤可能會連鎖放大，導致長期任務中的微小失誤最終造成完全失敗，因此需要更強大的驗證與錯誤恢復機制。此外，產品化時還必須考量評估框架的設計、不同作業系統與工具鏈的相容性，以及如何確保模型在開放式終端環境中的安全性與可控性。

**Q12：TMAX 的研究對終端機智慧體領域的長遠影響可能是什麼？**

A：TMAX 證明了簡單的開源強化學習配方搭配高品質合成資料，就能讓中小型模型在複雜終端任務上達到接近前沿的表現，這可能會改變領域內對於「必須依賴超大模型或閉源 API」的既有認知。透過建立強大的公開基線，TMAX 有望加速學術界對長期智慧體任務、強化學習穩定性與跨領域泛化的研究進程。長遠來看，這項工作為終端機智慧體的民主化奠定了基礎，使更多研究機構與開發者能夠參與並推動這項技術的演進。

**Q13：TMAX 目前存在哪些已知的限制？**

A：儘管 TMAX 在開源模型中表現突出，但其最佳模型在 Terminal-Bench 2.0 上僅達到 27%，顯示在極度複雜的終端任務上仍有巨大的進步空間。此外，研究團隊坦承在訓練過程中，原始的 GRPO 演算法在長期智慧體場景中難以維持穩定，這暗示現有的強化學習方法在處理長期終端任務時仍存在根本性的挑戰。與頂尖閉源模型相比，TMAX 的絕對效能仍有差距，且目前釋出的模型規模最大為 270 億參數，尚未探索更大規模模型的潛力。

**Q14：TMAX 在哪些情況下可能會失敗或表現不佳？**

A：根據文中對訓練難度的描述，TMAX 可能在需要極長期規劃或多步驟複雜推理的終端任務中面臨挑戰，因為這類任務容易超出強化學習的穩定訓練範圍。對於訓練資料中未涵蓋的罕見領域或極高難度任務，模型可能因為缺乏足夠的學習訊號而表現不佳。此外，由於 TMAX 採用僅結果導向的強化學習配方，若任務的中間過程存在多個合理路徑但最終結果難以收斂，模型可能難以學習到有效的策略。

**Q15：TMAX 為未來研究指出了哪些方向？**

A：未來研究可以從多個方向延伸 TMAX 的成果，包括開發更穩定的長期強化學習演算法、設計更精細的過程獎勵機制，以及進一步擴充與多樣化終端機訓練資料。研究者也應該持續改進評估框架與工具呼叫機制，以因應更困難的下游任務與更複雜的真實世界場景。最後，探索更大參數規模的模型、結合多模態輸入，以及提升模型在跨作業系統與跨工具鏈上的泛化能力，都是 TMAX 基線之上值得深入的重要課題。

## 實務應用指南

### 適用場景

1. **自動化雲端維運與基礎設施管理**：讓終端機智慧體在隔離環境中執行伺服器設定、日誌分析、故障排除與資源調度等長期任務，減少維運人員重複性手動操作。
2. **軟體開發與錯誤修復輔助**：整合至開發者工具鏈，自動執行編譯、測試、版本控制與錯誤修復流程，特別適用於類似 SWE-Bench 的多步驟程式碼維護場景。
3. **資安稽核與合規檢查**：在沙箱中執行指令進行系統弱點掃描、設定檔稽核與滲透測試步驟，利用智慧體自動產生並執行複雜的終端機檢查腳本。
4. **資料工程與批次處理**：自動化 ETL 流程、資料庫遷移、大規模檔案轉換等需要多步驟終端機操作的工作，透過 RL 訓練讓智慧體學會處理非預期錯誤與中繼狀態。
5. **互動式技術教育與技術支援**：作為教學或客服工具，引導使用者在終端機中完成複雜的系統管理或程式設計任務，並依據使用者角色設定（personas）調整回應與操作難度。

### 實作前置條件

- **資料準備**：需取得或自行生成高品質的終端機環境資料集。若遵循 TMAX 配方，應建立包含難度控制、角色設定（personas）與驗證器多樣化（verifier diversification）的分類法（taxonomy），並產出至少數千組帶有連續值獎勵或二元正確性標籤的 RL 環境實例。
- **運算資源**：進行完整 RL 訓練需具備多張高記憶體 GPU（如 A100 或 H100）的單一或多節點叢集，以支援非同步 RL 基礎設施與較大的群組大小（group size）。若僅執行推論或監督式微調（SFT），則可使用較輕量的消費級 GPU 或雲端伺服器。
- **技術能力**：團隊需熟悉強化學習（RL）流程（特別是 DPPO 演算法）、具備 Docker 等容器化技術以建立終端機沙箱，並能操作 open-instruct 等開源訓練框架進行非同步分散式訓練與 FP32 LM head 設定。

### 實作步驟建議

1. **建置非同步訓練基礎設施**：部署基於 open-instruct 的非同步 RL 訓練環境，確保能同時處理大量終端機環境實例的 rollout 與梯度更新。
2. **生成或取得 TMAX-15K 規模資料集**：使用論文提出的分類法產生 14,000 組以上的 RL 環境，明確控制任務難度並涵蓋多樣領域；若資源有限，可直接使用論文釋出的開源終端機資料集。
3. **監督式微調（SFT）建立基礎能力**：以生成的資料對基礎語言模型（如 Qwen 系列）進行 SFT，使模型先具備基本的終端機指令理解與工具呼叫能力。
4. **執行僅結果導向的 RL 訓練**：採用 outcome-only 配方，使用 DPPO 演算法進行訓練。關鍵設定包括使用 FP32 精度的 LM head 與較大的 group size，以提升長期任務的訓練穩定性，避免 naive GRPO 造成的發散問題。
5. **跨評估框架與跨任務驗證**：在 Terminal-Bench 2.0 上評估模型表現後，進一步於 SWE-Bench Verified、AIME 等不同 harness 與工具集下測試，確認模型學到的是通用能力而非僅針對單一評估框架過度擬合。
6. **沙箱化部署與持續監控**：將訓練完成的開放權重模型（如 TMAX-9B）整合至產品環境，搭配嚴格的終端機沙箱與操作日誌記錄，並建立回滾機制以確保安全性。

### 潛在風險與注意事項

- **訓練不穩定與發散**：長期任務的 RL 訓練容易不穩定，切勿直接使用 naive GRPO。務必採用 DPPO，並將 LM head 維持在 FP32 精度，同時確保 group size 足夠大以穩定梯度估計。
- **終端機操作安全性**：終端機智慧體具備執行實際指令的能力，必須在完全隔離的沙箱（如 Docker 容器或虛擬機）中運行，防止資料誤刪、未授權存取或惡意指令注入。
- **評估框架過度擬合（Harness-fitting）**：模型可能僅記憶特定評估框架的提示模式而非真正學會解題。應透過更換提示詞、工具集與跨 harness 驗證來檢驗泛化能力。
- **資料品質與獎勵設計**：若自行生成資料，缺乏難度控制與驗證器多樣化會導致訓練訊號薄弱。建議遵循論文的分類法設計，並對適合的任務採用連續值獎勵而非僅有二元正確性。
- **運算成本門檻**：非同步 RL 基礎設施與大型群組訓練需要大量 GPU 記憶體與節點間通訊頻寬。資源有限的團隊應優先使用 TMAX 釋出的開源模型進行領域適應，而非從頭執行完整 RL 訓練。

### 與其他技術的整合建議

- **整合開發環境（IDE）**：將 TMAX 模型透過外掛或 API 形式嵌入 VS Code、Cursor 或 JetBrains 系列 IDE，作為終端機面板內的智慧助理，接收自然語言指令後自動執行對應操作並回傳結果。
- **結合容器化與編排平台**：利用 Docker 與 Kubernetes 建立可重現的終端機環境，讓智慧體在獨立 Pod 中執行任務；搭配 GitOps 流程管理環境設定，確保每次執行的一致性與可追溯性。
- **作為專用工具呼叫層**：在既有大型語言模型（LLM）管線中，將 TMAX 定位為專責終端機指令執行的工具呼叫層（tool-calling layer），由上游通用模型負責理解意圖，TMAX 負責精確的多步驟終端機操作。
- **融入可觀測性與日誌系統**：將終端機操作軌跡與輸出導入 Prometheus、Grafana 或 ELK Stack 等可觀測性平台，便於即時監控、事後除錯，並作為後續強化學習人類回饋（RLHF）或資料篩選的依據。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先理解終端機智慧體的基本運作原理，從論文釋出的開源模型、資料集與推理範例著手，嘗試在本機或雲端沙箱中執行，無需深入強化學習演算法細節即可體驗其應用潛力。
- **AI 工程師**：重點關注資料生成管線（分類法、角色設定、驗證器多樣化）與 DPPO 訓練設定的實作細節，特別是 FP32 LM head 與 group size 的調校；可直接參考 open-instruct 基礎設施進行復現與領域微調。
- **研究人員**：深入分析 TMAX-15K 的資料設計哲學與 outcome-only RL 在長期任務中的收斂特性，論文提供的 RL rollouts 與 logprobs 等訓練產物是研究訓練動態與泛化機制的寶貴資源。
- **產品經理**：聚焦於「僅 9B 參數即可達 27% Terminal-Bench 2.0 表現並超越更大模型」的性價比優勢與開源策略，評估將 TMAX 整合至現有開發者工具鏈的可行性，同時優先規劃終端機操作的安全合規與沙箱隔離需求。
