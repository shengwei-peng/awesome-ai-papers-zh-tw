## ⚡ TL;DR

終端獎勵無法定位長程搜尋中的中間錯誤，且靜態回饋難以跟上策略演化。
CAFE以共享模型交替訓練代理與評論家，透過CFE與RDPO共同演化回饋。
在七個搜尋基準上平均優於RL基線，並在六個領域外測試中維持增益且降低幻覺。

## 摘要翻譯

結果監督式搜尋代理（outcome-supervised search agents）學習何時以及如何檢索證據，但終端獎勵（terminal rewards）既無法定位中間錯誤，也無法在錯誤累積之前導正進行中的軌跡（trajectory）。將修正回饋（corrective feedback）視為可學習的軌跡內介入（learned in-trajectory intervention），會使這兩個角色相互耦合：代理（agent）必須決定何時請求回饋（feedback request）、以及如何使用回饋（feedback use）；而評論家（critic）則必須從結果混淆的推展（outcome-confounded rollouts）中推導出有用的修正，且這些推展的失敗模式（failure patterns）會隨著代理改進而轉移。我們提出 CAFE（Coupled Agent–Feedback Evolution，耦合代理–回饋共同演化）框架，其中共享參數模型（shared-parameter model）會交替扮演搜尋代理（search agent）與評論家兩種角色。CAFE 首先以基礎代理（base agent）自身的失敗為核心建構軌跡，並從中初始化回饋條件化恢復（feedback-conditioned recovery）；隨後結合線上與離線最佳化（online and offline optimization）。在線上強化學習（online RL）階段，比較式回饋估計（comparative feedback estimate）利用提示層級呼叫–跳過成功差距（prompt-level call–skip success gap）來塑造請求回報（request returns），而回饋感知優勢塑形（feedback-aware advantage shaping）則會在回饋前後重新加權各詞元優勢（token advantages）。離線時，推展導向偏好最佳化（rollout-derived preference optimization）從配對的成功與失敗軌跡（matched successful and unsuccessful trajectories）中學習回饋。在七個代理式搜尋基準（agentic search benchmarks）上，CAFE 平均而言優於所評估的強化學習搜尋代理，在所有六個領域外基準（out-of-domain benchmarks）上均維持其增益，並減少答案層級幻覺（answer-level hallucinations）。單向消融實驗（one-sided ablations）顯示，僅改進代理或僅改進評論家最終都會陷入停滯（plateau），而交替更新兩者則能持續提升表現。這些發現顯示，自我改進搜尋代理（self-improving search agent）需要與其所引導的策略（policy）共同演化的回饋。

### 核心貢獻（3～5點）
- 提出 CAFE 框架，以共享參數模型交替扮演搜尋代理與評論家，使回饋機制與代理策略能夠共同演化。
- 將修正回饋建模為可學習的軌跡內介入，讓代理能在錯誤累積前主動請求並使用回饋，從而改善長程搜尋過程。
- 結合線上強化學習與離線偏好最佳化：線上透過比較式回饋估計與回饋感知優勢塑形學習何時請求回饋；離線透過配對軌跡學習高品質修正回饋。
- 在七個代理式搜尋基準上平均優於現有強化學習搜尋代理，並在六個領域外基準維持性能增益，同時減少答案層級幻覺。
- 單向消融實驗證明僅更新代理或僅更新評論家最終會停滯，交替更新兩者才能持續進步，凸顯共同演化的必要性。

### 適合對象
適合研究檢索增強語言模型、代理式搜尋、強化學習與自我改進系統的研究者與工程師，特別是關注長程搜尋、回饋設計、線上／離線策略最佳化，以及希望了解如何讓回饋機制隨策略共同演化的讀者。

## 深度分析

#### 方法論解析

CAFE（Coupled Agent–Feedback Evolution）將自我改進搜尋代理（self-improving search agent）重新定義為一個**耦合最佳化（coupled optimization）**問題：同一個 shared-parameter model（共享參數模型）必須同時學會當搜尋代理（search agent）與當評論家（critic），而且兩種能力不能獨立訓練後再拼接，而必須隨著彼此產生的軌跡（trajectory）與失敗模式（failure pattern）共同演化。

##### 1. 問題設定：為何終端獎勵（terminal reward）不足

傳統 outcome-supervised search agent（結果監督式搜尋代理）只依靠 terminal task reward（終端任務獎勵）來學習「何時檢索、如何檢索」。這類方法在長程搜尋（long-horizon search）中會遇到兩個結構性問題：

- **錯誤會複合傳播**：一個早期的方向性錯誤（directional error）不會在當下收到修正訊號（corrective signal），其成本會沿著整條軌跡擴散。
- **失敗根源難以追溯**：terminal reward 只能說「最後答案錯了」，卻無法指出是在哪一步遺漏了 required subgoal（必要子目標）、在哪一步 silently drop 了條件，或陷入 query rephrasing（查詢改寫）的迴圈。

因此，CAFE 主張需要一種 **in-trajectory intervention（軌跡內介入）**：在進行中軌跡（active trajectory）裡即時診斷並導正搜尋方向，而不是等軌跡結束後再給予事後回饋（post hoc feedback）。

##### 2. 初始化：從基礎代理（base agent）的失敗中學習回饋條件化恢復

學習「請求回饋—產生回饋—使用回饋」的互動，若直接從稀疏的 terminal reward 開始，探索空間過大。因此 CAFE 採用 **feedback-conditioned recovery（回饋條件化恢復）** 做為冷啟動：

1. 先讓 base agent 在任務上推展（rollout），收集失敗軌跡。
2. 保留失敗軌跡的錯誤前綴（erroneous prefix）。
3. 在適當位置插入 `<request_feedback>` 這類特殊 token，並由模型產生診斷性回饋（例如指出 missing evidence、建議 next action）。
4. 後接一條成功的接續軌跡（successful continuation），構成完整的 recovery demonstration。

這種做法的關鍵在於**不會用一條從頭到尾完美的軌跡取代失敗軌跡**，而是讓模型在「自己實際會造訪的狀態」上學會如何被挽救。這比使用人工撰寫的理想軌跡更符合 online RL 後續會遇到的狀態分布。

##### 3. 線上強化學習：學會何時請求回饋與如何分配功勞

即使有了初始化，模型仍須回答兩個問題：**何時該請求回饋？** 以及 **回饋前後的 token 該如何分配 credit？** CAFE 提出兩個機制：

**Comparative Feedback Estimate（CFE，比較式回饋估計）**

CFE 在 prompt level 比較同一問題下「呼叫回饋」與「跳過回饋」的成功率差距，即 **prompt-level call–skip success gap（提示層級呼叫—跳過成功差距）**。這個差距被用來塑造 **request return（請求回報）**：如果某個狀態下請求回饋顯著提升成功機率，就強化在該狀態觸發 `<request_feedback>` 的傾向；反之則抑制不必要的呼叫。這讓 agent 學會選擇性介入，而不是每步都求助。

**Feedback-aware Advantage Shaping（回饋感知優勢塑形）**

當一條軌跡因回饋而從失敗被挽救為成功時，rescued trajectory（被挽救的軌跡）與 flawless trajectory（完美軌跡）會拿到相同的 terminal reward，但兩者的過程品質顯然不同。為了避免「因為最後成功就全盤肯定前期錯誤」，CAFE 對 token advantage（token 優勢）進行重新加權：

- 回饋請求之前的 token 通常應承擔較低的優勢（因為它們導致了需要介入）。
- 回饋之後的 token 若成功導向正確答案，則獲得較高的優勢。
- 回饋內容與觀察 token 通常被排除在政策梯度之外，避免模型為了優化回饋文字而扭曲搜尋目標。

這種 **advantage shaping（優勢塑形）** 讓 agent 不僅學會「使用回饋」，也學會「避免再次落入需要回饋的狀態」。

##### 4. 離線偏好最佳化：讓評論家與策略同步演化

Critic 的訓練不能依賴靜態的真實標註（ground truth），因為回饋的效用會被 preceding search（先前的搜尋）與 subsequent action（後續動作）所混淆，而且隨著 policy 更新，failure pattern（失敗模式）會轉移，導致 static critic（靜態評論家）逐漸 misaligned（不一致）。

CAFE 提出 **Rollout-Derived Preference Optimization（RDPO，推展導向偏好最佳化）**：

1. 從最新的 online rollouts 中挖掘 prefix-matched preference pairs（前綴配對的偏好對）。
2. 對於同一個錯誤前綴，比較「呼叫回饋後成功恢復」與「呼叫回饋後仍然失敗」的兩條軌跡。
3. 透過 gated high-value filtering 篩選出高資訊價值的 pair，避免低品質或隨機成功的樣本干擾。
4. 使用這些 outcome-labeled preference pairs 進行離線 DPO 更新，讓 critic 學會產生更有助於恢復的回饋。

由於這些 preference pairs 來自於當前 policy 產生的 rollout，critic 會隨著 agent 的演化而持續對齊。

##### 5. 交替共同演化迴圈

CAFE 的完整流程是一個迭代迴圈：

- **Online agent optimization（線上代理最佳化）**：使用 CFE 與 feedback-aware advantage shaping 更新 agent 的策略（policy）。
- 產生最新 rollouts 後，從中抽取 prefix-matched successful and unsuccessful trajectories（配對的成功與失敗軌跡）。
- **Offline feedback optimization（離線回饋最佳化）**：使用 RDPO 更新 critic。
- 下一輪再用更新後的模型同時擔任 agent 與 critic，繼續 online RL。

這種 **alternating update（交替更新）** 是 CAFE 的核心：agent 造訪的狀態分布改變後，critic 必須跟著改變；而 critic 變強後，又能引導 agent 探索更高品質的軌跡。

#### 實驗數據解讀

##### 1. 主結果：平均表現領先

在七個 agentic search benchmark（代理式搜尋基準）上，以 Qwen2.5-7B-Instruct 為骨幹的 CAFE 在平均表現（average performance）上優於所有被評比的 RL-based search agent，相較最強基線提升 **2.1 EM** 與 **1.3 F1**。這表示 CAFE 不只在單一資料集取勝，而是跨資料集都穩定改善。

這個提升的幅度雖然看起來是個位數，但在搜尋問答任務中，EM（Exact Match）與 F1 對最終答案正確性非常敏感，2.1 EM 的增益通常對應到相當比例的問題從「答案錯誤」變成「完全正確」。

##### 2. 領域外泛化：增益穩定保留

更值得注意的结果是：在全部六個 out-of-domain benchmark（領域外基準）上，CAFE 都能 **retain gains（維持增益）**。這說明：

- 學到的回饋機制不是對訓練資料 overfit 的檢索技巧。
- Feedback-conditioned recovery 與 RDPO 讓模型學到的是更通用的「錯誤診斷與修正」能力，而非特定領域的檢索模板。
- 在 3B 模型上也能觀察到類似趨勢，顯示方法具有 scale generalization 的潛力。

##### 3. 幻覺降低：軌跡品質確實改善

CAFE 將 answer-level hallucination（答案層級幻覺）從平均 **17.6% 降至 12.6%**。這是一個重要的質性證據：

- 終端獎勵有時會鼓勵模型「猜對答案」或「拼湊看起來合理的答案」。
- 引入 in-trajectory feedback 後，模型更傾向於在軌跡中主動檢查證據、發現 missing evidence，而不是在答案階段虛構內容。
- 幻覺下降也間接證明 critic 確實在引導 agent 進行更可靠的檢索，而不只是提升答案生成流暢度。

##### 4. 消融實驗：共同演化的必要性

One-sided ablation（單向消融實驗）顯示：

- 只更新 agent、固定 critic：性能最終會 plateau（停滯）。
- 只更新 critic、固定 agent：性能也會 plateau。
- 只有交替更新兩者時，性能持續提升。

這個結果強烈支持論文的核心假說：**self-improving search agent 需要 co-evolving feedback（共同演化的回饋）**。單靠更強的 agent 會因為 critic 無法診斷新出現的錯誤而飽和；單靠更強的 critic 則因為 agent 無法執行建議而無法轉化為終端性能。

##### 5. 訓練動態與交叉扮演的啟示

透過 agent–critic cross-play（交叉扮演）與訓練動態分析，作者進一步說明 co-evolution 不是單純的「兩個模組輪流變強」，而是兩個角色在共享參數中互相牽引。當 agent 學會更頻繁或更精準地請求回饋時，critic 收到的訓練分布也會改變；critic 變強後又會改變 agent 對「哪些狀態值得介入」的估計。這種動態平衡是 CAFE 能持續進步的關鍵。

#### 與現有研究的比較

##### 1. 相較於固定檢索策略

早期的 retrieval-augmented pipeline（檢索增強流程）使用 fixed strategy（固定策略）或 hand-crafted condition（人工設計條件）決定何時檢索，例如在 predetermined reasoning stage（預設推理階段）觸發檢索。這類方法缺乏適應性，無法根據當前軌跡狀態動態調整。CAFE 則讓 agent 自己學習何時請求回饋，並讓回饋內容本身也成為可學習的對象。

##### 2. 相較於 outcome-supervised RL search agents

近期的 outcome-supervised search agent（如以 terminal reward 訓練的 RL 搜尋代理）雖然學會了檢索時機，但仍缺乏 introspection（自我檢視）。它們能學習「尋找什麼外部知識」，卻無法在軌跡進行中診斷自己的錯誤。CAFE 把 feedback 內化為軌跡的一部分，使 agent 具備主動自我修正的能力。

##### 3. 相較於細粒度信用訊號

有些研究提出 information gain（資訊增益）、confidence change（信心變化）或 local state comparison（局部狀態比較）等 finer-grained credit（更細粒度的功勞分配）機制。這些訊號雖然比 terminal reward 更細緻，但本質上仍是 **evaluative signal（評價性訊號）**：它們告訴模型「這一步好不好」，卻不告訴模型「該怎麼修正」。CAFE 的回饋則是 **instructive signal（指導性訊號）**，會具體指出 missing evidence 與 next action。

##### 4. 相較於事後回饋方法

Reflexion（反思法）、Self-Refine（自我精煉法）、CRITIC（批判式回饋法）等方法雖然也使用 natural-language critique（自然語言評論），但它們通常是：

- **Post hoc feedback（事後回饋）**：軌跡結束後才進行反思，無法挽救當前軌跡。
- **Prompted model（提示驅動模型）**：依靠人工設計的提示產生回饋，而非從資料中學習。
- **靜態流程**：回饋機制不會隨著 agent 策略改變而調整。

CAFE 的 feedback 是 learned in-trajectory intervention（可學習的軌跡內介入），並透過 RDPO 持續適應 evolving policy（演化的策略）。

##### 5. 相較於靜態獎勵模型

傳統 RLHF 或 DPO 通常訓練一個 static reward model（靜態獎勵模型）或偏好模型來評判輸出。這些模型在 policy 更新後容易出現 reward hacking 或分布偏移問題。CAFE 的 critic 是從「當前 policy 產生的 rollout」中持續提煉 preference pairs，因此能緩解 state distribution shift（狀態分布偏移）造成的 misaligned critic 問題。

##### 6. 限制與待釐清之處

儘管 CAFE 有明顯貢獻，仍有幾點限制：

- **初始化依賴 base agent 的失敗**：如果 base agent 過弱，產生的 failure pattern 可能不足以覆蓋後續會遇到的困難狀態，recovery demonstration 的品質也會受限。
- **共享參數的容量競爭**：agent 與 critic 共用參數雖然促進 co-evolution，但也可能在更大模型或更複雜任務中出現 capacity conflict，導致兩個角色互相擠壓。
- **CFE 的估計雜訊**：prompt-level call–skip success gap 需要足夠的 rollout 樣本才能穩定估計，在樣本稀少或任務隨機性高的場景可能不穩定。
- **回饋內容的可解釋性**：雖然論文提到回饋會診斷軌跡、建議下一步，但對於回饋品質的自動評估與人類可讀性分析仍有擴充空間。

#### 可重現性評估

從提供的上下文來看，CAFE 的實驗設計具備一定的可重現性基礎，但也存在資訊揭露不足的風險。

##### 1. 公開可取得的資源

- **模型**：使用 Qwen2.5-7B-Instruct 與 Qwen2.5-3B-Instruct，這些模型權重已公開，社群可以取得。
- **基準**：七個 agentic search benchmark 與 BrowseComp-Plus 屬於公開或已發表的評測資料集，原則上可重複實驗。
- **方法描述**：論文對 CFE、advantage shaping、RDPO 與交替訓練流程有相當清楚的說明，核心概念可據此復現。

##### 2. 目前缺乏的資訊

- **原始碼與訓練腳本**：文中未提及是否釋出原始碼、超參數設定、訓練管線或資料處理腳本。若無這些細節， exact reproduction 會非常困難。
- **Recovery demonstration 的構建細節**：雖然概念上保留錯誤前綴並插入成功接續，但實際如何配對前綴、如何過濾低品質 recovery、成功接續從何而來，這些實作細節會顯著影響結果。
- **CFE 的實作與門檻**：call–skip gap 的估計方式、gated high-value filtering 的閾值、以及 rollout 數量等，都需要更多細節才能穩定復現。
- **模型權重**：論文未說明是否會釋出訓練後的 CAFE checkpoint。

##### 3. 綜合評估

若以「概念復現」為標準，CAFE 的可重現性屬於**中等偏高**：公開模型與基準降低了進入門檻，方法論也足夠詳細。但若以「數值完全重現」為標準，則目前資訊揭露程度屬於**中等偏低**，需要作者釋出程式碼、超參數與訓練後權重，才能讓後續研究有效比較與延伸。

---

#### 未來研究方向

CAFE 開啟了「agent 與 critic 共同演化」的研究路線，未來可以從以下幾個方向延伸：

##### 1. 擴展到更大規模與更多模態

目前實驗集中在 Qwen2.5-7B/3B-Instruct。未來可在更大參數模型（如 32B、70B）上驗證 shared-parameter co-evolution 是否仍然有效，或是否會出現容量競爭。此外，也可將框架擴展到多模態搜尋（圖片、表格、程式碼檢索）等更複雜的環境。

##### 2. 外部化或模組化的 Critic

CAFE 目前使用共享參數的 critic。未來可探索：

- 使用獨立的 external critic（外部評論家）模組，減少與 agent 的參數競爭。
- 設計多層次 critic，例如局部步驟級 critic 與全局軌跡級 critic 分工。
- 引入 process reward model（過程獎勵模型）作為輔助訊號，與 CAFE 的 feedback 機制互補。

##### 3. 自動化與可擴展的 Recovery Demonstration 構建

目前 recovery demonstration 依賴 base agent 的失敗軌跡與成功接續。未來可研究：

- 使用更強大的教師模型或搜尋演算法自動生成高品質 recovery。
- 開展 curriculum learning（課程學習），依照錯誤難度逐步增加 recovery 的複雜度。
- 結合合成資料生成，降低對真實 rollout 的依賴。

##### 4. 理論分析與收斂性研究

CAFE 的交替更新本質上是一個雙方互相影響的動態系統。未來可從理論上分析：

- 在什麼條件下 agent–critic co-evolution 會收斂？
- 如何避免雙方互相放大偏差（例如 agent 學會呼叫無意義回饋，critic 學會給出無效建議）？
- 建立類似 Nash equilibrium 或 stable fixed point 的分析框架。

##### 5. 回饋品質與可解釋性

目前對於 critic 產生的 natural-language critique 品質，主要依賴終端任務性能間接衡量。未來可發展：

- 自動化的 feedback quality metric（回饋品質指標）。
- 人類評估與案例研究，分析回饋是否真正指出失敗根源。
- 可視化工具，展示 agent 在何種狀態下傾向請求回饋，以及回饋如何改變後續軌跡。

##### 6. 應用到其他長程決策任務

CAFE 的核心思想——在軌跡內學習請求、生成與使用回饋——不只適用於搜尋問答。未來可應用於：

- 程式碼生成與除錯（long-horizon coding agents）。
- 網頁導航與多步工具使用（web navigation、tool-use agents）。
- 科學推理與實驗設計等需要反覆試誤的任務。

##### 7. 減少回饋相關的計算成本

交替 online RL 與 offline RDPO 會增加訓練開銷。未來可研究：

- 更輕量的 CFE 估計方法，例如使用 value function 近似而非大量 rollout。
- 選擇性執行 RDPO，只在 critic 與 agent 出現明顯 misalignment 時才觸發。
- 回饋壓縮（feedback compression）與階層式回饋，減少冗長自然語言回饋帶來的計算負擔。

總結來說，CAFE 不僅提出了一個具體的搜尋代理訓練框架，更重要的是確立了「回饋必須與策略共同演化」這一設計原則，為未來長程自主代理的設計提供了新的理論與實作方向。

## 論文問答

**Q1：結果監督式搜尋代理的根本問題是什麼？為什麼終端獎勵不足以支撐長程搜尋？**

A：結果監督式搜尋代理只在軌跡結束時獲得終端任務獎勵，因此無法指出中間哪一步出錯，也無法在錯誤還沒放大之前即時導正。在長程搜尋中，早期的方向性錯誤會沿著後續軌跡不斷傳播，導致最終失敗，但終端獎勵無法區分「從頭正確」與「先錯後救」的軌跡。這使得代理難以學會自我診斷與修正，也讓錯誤模式隨著策略演化而不斷累積。

**Q2：現有的上下文內回饋方法（如 Reflexion、Self-Refine、CRITIC）為何無法滿足 CAFE 想解決的需求？**

A：這些方法大多在軌跡結束後才提供自然語言評論，並且依賴提示驅動模型而非經過訓練的學習機制，因此無法在進行中軌跡內即時介入。它們也沒有教導代理「何時該請求回饋」，也無法處理被挽救軌跡與完美軌跡獲得相同獎勵所帶來的信用分配問題。此外，隨著策略改進，代理造訪的狀態與失敗模式會轉移，靜態評論家容易變得與當前策略不一致。

**Q3：為什麼代理與評論家必須「共同演化」，而不是各自獨立優化？**

A：線上策略更新會改變代理造訪的狀態分布與失敗模式，如果評論家維持不變，它對錯誤的診斷會逐漸偏離實際情況，成為不一致的評論家。單向消融實驗顯示，只更新代理或只更新評論家最終都會進入停滯期，無法持續進步。只有交替更新兩者，才能讓回饋機制與策略同步演化，維持長期的指導效果。

**Q4：CAFE 的核心架構與訓練流程是什麼？**

A：CAFE 使用單一共享參數模型，同時扮演搜尋代理與評論家兩種角色，並透過交替的線上與離線最佳化來共同訓練。初始化階段會以基礎代理自身的失敗軌跡為基礎，保留錯誤前綴、插入修正回饋，並接上成功後續，建立回饋條件化恢復的示範資料。線上強化學習負責訓練代理何時請求與如何使用回饋，離線則透過推展導向偏好最佳化（RDPO）精煉評論家的回饋生成能力。

**Q5：CAFE 如何讓代理學會「何時請求回饋」以及「如何分配回饋帶來的信用」？**

A：CAFE 提出比較式回饋估計（CFE），在提示層級比較「請求回饋」與「不請求回饋」的成功率差距，藉此塑造請求回報，讓代理知道何時介入最有價值。同時，回饋感知優勢塑形會針對回饋前後的 token 重新加權其優勢值，避免被挽救軌跡與完美軌跡獲得相同終端獎勵時造成信用混淆。這兩者結合，使代理能主動判斷介入時機，並正確歸因回饋帶來的貢獻。

**Q6：推展導向偏好最佳化（RDPO）的設計重點與價值是什麼？**

A：RDPO 從最新線上推展中挖掘「前綴相同、結果不同」的成功與失敗軌跡配對，將回饋生成視為偏好學習問題。由於這些配對軌跡共享相同前綴，能有效降低結果混淆，讓評論家學到在相似情境下什麼樣的回饋更可能導致成功。透過持續使用最新推展資料，RDPO 能讓評論家緊跟代理的演化步伐，避免靜態批評逐漸失效。

**Q7：CAFE 在哪些基準與模型上進行評估？**

A：實驗使用 Qwen2.5-7B-Instruct 與 Qwen2.5-3B-Instruct 兩種規模的模型，在七個代理式搜尋問答基準上進行測試。此外，研究還納入 BrowseComp-Plus 作為額外評估，並檢視模型在六個領域外基準上的泛化能力。這樣的設計能同時檢驗 CAFE 在同分布與跨領域情境下的穩健性。

**Q8：CAFE 的主要實驗結果為何？**

A：在 7B 規模上，CAFE 在所有評比的強化學習式搜尋方法中取得最強的平均表現，相較最強基線提升 2.1 EM 與 1.3 F1。更重要的是，這些增益在所有六個領域外基準上都得以維持，並能穩健地泛化到 3B 模型。此外，CAFE 將答案層級幻覺率從 17.6% 降至 12.6%，顯示其不僅提升正確率，也減少虛構答案。

**Q9：消融實驗揭示了哪些關鍵結論？**

A：單向消融實驗顯示，只更新代理或只更新評論家最終都會停滯，而交替更新兩者則能持續改善軌跡品質與搜尋表現。這直接證明了耦合最佳化與共同演化的必要性，而非單純強化代理的外部檢索能力。針對目標函數的消融也確認，回饋感知優勢塑形與 CFE 對於正確學習介入時機與信用分配不可或缺。

**Q10：CAFE 最適合應用在哪些實務場景？**

A：CAFE 特別適合需要多步檢索、且早期錯誤會不斷放大的知識密集型任務，例如法律或醫學文獻調查、多跳事實查核、複雜技術故障排除等。在這些場景中，代理若能在進行中軌跡內即時診斷方向偏離並取得修正回饋，就能避免無效查詢與證據累積錯誤。這種自我改進能力可顯著減少人工介入與重複檢索的成本。

**Q11：將 CAFE 部署到實際產品時需要考慮哪些因素？**

A：首先，線上推展與離線偏好配對的收集需要額外的運算與儲存開銷，因此必須設計高效的推展採樣與過濾機制。其次，共享參數模型雖然降低部署負擔，但代理與評論家交替更新可能帶來訓練不穩定，需要仔細安排更新頻率與學習率。最後，回饋的延遲與品質會直接影響使用者體驗，必須監控回饋本身是否產生幻覺或過度請求。

**Q12：CAFE 對自我改進代理領域可能帶來什麼影響？**

A：CAFE 將回饋從傳統的事後反思轉變為可學習的軌跡內介入，並證明回饋機制必須與策略共同演化才能持續有效。這為未來的自我改進代理提供了一個耦合代理—評論家訓練的範式，強調「指導性訊號」而非僅是「評價性訊號」的重要性。其框架也可能擴展到搜尋以外的長程決策任務，例如程式生成、規劃與對話系統。

**Q13：CAFE 有哪些已經存在或潛在的限制？**

A：CAFE 依賴終端結果標籤來建立成功與失敗軌跡的偏好配對，在極度稀疏或延遲獎勵的環境中可能學習緩慢。此外，CFE 透過比較有無回饋的成功率來估計回饋價值，這種估計在樣本有限時可能帶有雜訊。初始化階段也需要先收集基礎代理的失敗軌跡，對於某些高成本環境可能是一筆前置開銷。

**Q14：在哪些失敗案例中，CAFE 可能仍然表現不佳？**

A：當失敗根源來自於細微的推理謬誤，而非檢索到的證據不足時，評論家可能難以產生有效的修正回饋。如果代理過度依賴回饋機制，也可能出現頻繁請求回饋卻未真正改善決策的現象。另外，若外部搜尋環境發生劇烈變化，評論家可能需要較多迭代才能重新對齊新環境下的失敗模式。

**Q15：CAFE 指出了哪些未來研究方向？**

A：未來可以將 CAFE 的耦合共同演化框架應用到搜尋以外的長程代理任務，例如程式碼除錯或機器人規劃。也可以探索引入人類或外部驗證器的回饋，以補強自動學習的評論家。此外，共享參數與分離參數架構之間的權衡、共同演化的理論收斂保證，以及多代理情境下的回饋協調，都是值得深入研究的方向。

## 實務應用指南

### 適用場景

1. **企業內部知識問答與決策輔助**  
   在大型組織中，員工需要跨越多份文件、資料庫與歷史紀錄才能回答複雜問題。CAFE 可讓搜尋代理在長程檢索過程中主動發現「方向性錯誤」——例如查詢偏離核心主題、遺漏必要子目標——並透過軌跡內修正回饋即時導正，最終降低答案層級幻覺。

2. **法律與法規盡職調查**  
   律師或合規人員需在大量判例、法條與合約中追蹤特定條件。CAFE 的評論家角色可診斷代理是否遺漏關鍵證據、是否過度依賴單一來源，並在進行中軌跡建議下一步檢索方向，避免終端獎勵無法定位失敗根源的問題。

3. **醫學文獻與臨床證據綜合**  
   醫學搜尋常涉及多輪查詢與證據比對。CAFE 能學習何時請求回饋、如何根據回饋調整查詢策略，並透過 rollout-derived preference optimization 持續讓評論家與策略共同演化，適合處理失敗模式會隨策略進步而轉移的動態任務。

4. **複雜客戶支援與故障排除**  
   當代理需要依序查閱知識庫、日誌與歷史工單來診斷問題時，早期誤判會導致後續一連串無效查詢。CAFE 的回饋條件化恢復機制可從基礎代理的真實失敗軌跡中學習，在實際造訪的狀態中插入修正回饋，提升首次解決率。

5. **金融研究與投資盡職調查**  
   分析師需整合財報、新聞、產業報告與市場數據。CAFE 的比較式回饋估計（CFE）可量化「請求回饋」相對於「不請求回饋」的成功差距，幫助代理在資訊不足時主動求助，減少過度自信或查詢重述的無效迴圈。

### 實作前置條件

**資料條件**
- 一個可互動的**外部搜尋環境**（如企業搜尋引擎、向量資料庫、網頁檢索 API），能根據代理的查詢返回證據。
- 可計算的**終端任務獎勵**，例如答案的 Exact Match（EM）或 F1，用於判斷軌跡成功與否。
- 基礎代理的**失敗軌跡資料**：用於建構回饋條件化恢復的初始示範，保留錯誤前綴、插入修正回饋並接上成功後續軌跡。

**運算條件**
- 至少一張可微調 7B 等級模型的 GPU（論文使用 Qwen2.5-7/3B-Instruct），若進行完整線上強化學習與離線偏好最佳化，建議多卡環境。
- 足夠的 rollout 儲存與運算資源：每個迭代需收集大量軌跡推展，並從中挖掘 prefix-matched 的成功與失敗配對。

**技能條件**
- 熟悉大型語言模型微調、強化學習（PPO / GRPO 等）與偏好最佳化（DPO）。
- 具備建構 agentic search 系統的經驗，包括動作空間設計、搜尋環境介接與軌跡記錄。
- 能理解並實作優勢塑形、獎勵設計與分布偏移分析，以調適 CFE 與 RDPO。

---

### 實作步驟建議

1. **建立基礎搜尋代理**  
   先訓練或取得一個結果監督式搜尋代理，作為 CAFE 的**基礎代理**。此代理不需具備回饋能力，但需能產生可分析的長程軌跡。

2. **收集並標註失敗軌跡**  
   讓基礎代理在目標任務上推展，收集成功與失敗軌跡。針對失敗軌跡，人工或半自動地找出**失敗根源**（如遺漏子目標、過度查詢改寫、證據使用不當）。

3. **建構回饋條件化恢復示範**  
   對每個失敗軌跡，保留錯誤前綴，在中間插入 `<request_feedback>` 與自然語言修正回饋，再接上能導致成功的後續軌跡。這些示範教會共享模型在自身策略實際造訪的狀態中請求、生成並使用回饋。

4. **初始化共享參數模型**  
   使用上述示範對單一模型進行監督式微調，使模型同時具備代理與評論家的初始能力。此時模型已能產生軌跡內回饋，但尚未學會判斷何時該請求回饋。

5. **線上強化學習：CFE 與優勢塑形**  
   在線上 rollout 中引入 `<request_feedback>` 動作。利用**比較式回饋估計（CFE）**衡量「呼叫回饋」與「跳過回饋」在提示層級的成功率差距，藉此塑造**請求回報**。同時使用**回饋感知優勢塑形**，在回饋前後重新加權 token 優勢，確保被挽救軌跡與完美軌跡獲得適當的信用分配。

6. **離線偏好最佳化：RDPO**  
   從最新 rollout 中挖掘具有相同前綴的成功與失敗軌跡，組成 prefix-matched preference pairs。透過 **rollout-derived preference optimization（RDPO）** 更新評論家，降低結果混淆，並讓回饋生成能力隨策略演化。

7. **交替迭代代理與評論家**  
   每個迭代輪流執行：線上代理學習（更新策略）→ 離線評論家精煉（RDPO）。避免只更新單一方，因為論文發現單向消融會快速進入停滯，而交替更新才能持續提升。

8. **領域外評估與部署**  
   在領域外基準測試泛化能力，監控答案層級幻覺與回饋請求頻率。部署時可加入門控機制，限制每條軌跡的回饋次數，並保留人類覆核介面。

---

### 潛在風險與注意事項

- **回饋幻覺與錯誤診斷**  
  評論家可能生成看似合理但實際錯誤的修正回饋。建議透過 RDPO 持續用最新 rollout 的配對軌跡更新評論家，並在關鍵場景保留人類標註或事後驗證。

- **獎勵駭入與過度請求回饋**  
  代理可能學會濫用 `<request_feedback>` 來操縱獎勵。CFE 的 call–skip success gap 與門控設計可抑制此行為，但仍需監控每軌跡回饋次數與最終答案品質的關聯。

- **分布偏移與靜態評論家**  
  若評論家未隨策略更新，將成為不一致的評論家，導致回饋與當前代理狀態脫節。務必執行交替更新，並定期測量代理–評論家交叉表現。

- **運算與儲存成本**  
  線上 RL 需要大量 rollout 與前綴配對挖掘。建議先在小規模資料上驗證 CFE 與優勢塑形的超參數，再擴大到完整訓練。

- **隱私與資料安全**  
  企業場景中的失敗軌跡可能包含敏感查詢。建議對 rollout 資料進行去識別化，並限制 RDPO 訓練資料的存取權限。

---

### 與其他技術的整合建議

- **既有 RAG 管線**  
  CAFE 可視為 RAG 的「主動導航層」，負責決定何時檢索、何時請求回饋。可保留現有的檢索器與向量資料庫，僅將代理的規劃與反思模組替換為 CAFE 的共享模型。

- **現有搜尋引擎與 API**  
  將外部搜尋環境封裝為統一介面，使 CAFE 的查詢動作可無縫對接企業搜尋、網頁搜尋或專業資料庫 API。

- **評估與可觀測性平台**  
  整合軌跡記錄、回饋請求標記與終端獎勵追蹤，便於計算 CFE、監控失敗模式轉移，並自動產生 RDPO 所需的 preference pairs。

- **人機協作介面**  
  在高風險場景（如法律、醫療）中，可將 CAFE 請求回饋的時機設為觸發人類專家介入的訊號，形成「模型自評 + 人類覆核」的混合迴路。

- **其他 RL 與偏好學習框架**  
  CAFE 的 CFE 與 RDPO 可與 GRPO、Rejection Sampling Fine-Tuning 或 DPO 變體結合，但需注意共享參數模型在角色切換時的訓練穩定性。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦論文的圖 1 與第 1 節動機：理解「為什麼終端獎勵無法定位長程搜尋中的錯誤」，以及 CAFE 如何透過「代理請求回饋、評論家給予修正」這個迴路來解決問題。技術細節如 CFE 與 RDPO 可先略讀，重點掌握「共同演化」這個核心概念。

**AI 工程師**  
請深入第 2 節方法論與消融實驗，特別注意回饋感知優勢塑形如何重新分配 token 級信用、RDPO 如何從 rollout 中挖掘 prefix-matched preference pairs，以及交替更新排程的實作細節。這些是將論文轉為產品時最關鍵的工程決策。

**研究人員**  
建議關注論文對「結果混淆 rollout」、「失敗模式轉移」與「代理–評論家交叉表現」的分析。CAFE 把自我改進搜尋框架化為耦合的代理–回饋學習問題，這為後續研究提供了可擴展的理論與實證基礎，值得與 Reflexion、CRITIC 等事後回饋方法進行對照。

**產品經理**  
請把重點放在適用場景與風險權衡：CAFE 適合「長程、多輪、失敗代價高」的知識密集型任務，但需要額外的運算資源與失敗軌跡資料來初始化。評估時不應只看平均表現，也要關注領域外泛化、幻覺降低與回饋請求頻率，這些指標決定了產品是否能在真實環境中穩定運行。
