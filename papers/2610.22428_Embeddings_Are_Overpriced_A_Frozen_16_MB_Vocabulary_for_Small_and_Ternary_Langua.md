# 嵌入（向量）是否太昂貴了？一組 16 MB 的凍結詞彙表，用於小型與三元語言模型

**原文標題：** Embeddings Are Overpriced? A Frozen 16 MB Vocabulary for Small and Ternary Language Models  
**作者：** Sai Kiran Bathula  
**發布日期：** 2026-10-15  
**HF 連結：** [https://huggingface.co/papers/2610.22428](https://huggingface.co/papers/2610.22428)

## ⚡ TL;DR

小型語言模型的詞彙嵌入表佔參數過半，量化後仍以16位元儲存，部署成本過高。
以主成分投影與符號二值化將預訓練嵌入壓縮為凍結的512位元編碼表，僅訓練小型映射層。
凍結表模型在多項基準與浮點模型持平，罕見詞表現更佳，搭配三元主體僅46MB且推論速度提升五至六倍。

## 摘要翻譯

在小型語言模型（Small Language Model）中，詞彙表（Vocabulary）是佔比最大的單一元件。在 Gemma 3 270M 中，嵌入表（Embedding table）佔據了 268M 參數中的 168M，且由於量化（Quantisation）方法將嵌入保留為 16 位元（16-bit），當模型其餘部分被壓縮後，詞彙表也佔據了檔案的大部分。我們想問這張表究竟換來了什麼。我們將其替換為一張凍結的（Frozen）512 位元（512-bit）編碼（Codes）表，大小為 16 MB，沒有可訓練參數（Trainable parameters），僅需從預訓練嵌入（Pretrained embedding）透過主成分投影（Principal-component projection）與符號二值化（Sign binarisation）一次性衍生，並在相同的 2.05B 詞元（Token）上，從頭訓練（From scratch）相同的 Gemma 形狀模型主體（Body），分別加上與不加上這張表。學習式詞彙表（Learned table）以 2.6 倍的可訓練參數量換來 0.20 奈特（Nats）的驗證損失（Validation loss），但在 LAMBADA、HellaSwag 與 PIQA 上，凍結詞彙表模型表現更佳或平手（Tied）；僅有 ARC-Easy 偏好（Favours）學習式詞彙表。採用三元 BitNet b1.58 模型主體時，整個模型為 46 MB 的檔案，在 LAMBADA 與 PIQA 上仍與浮點模型（Float model）平手，且在筆電 CPU（Laptop CPU）上以 62 MB 記憶體、每秒產生 615 至 740 個詞元（Tokens per second）的速度運行，速度為浮點模型 8 位元（8-bit）GGUF（於 llama.cpp 中執行）的五至六倍，而記憶體僅為其七分之一。凍結詞彙表在罕見詞（Rare words）上以 1.7 至 2.3 奈特勝出（Wins by），並能在訓練後僅付出 3% 的成本接受 10,000 個新詞（New words），而學習式詞彙表則崩潰（Collapses）了 43%；上述所有內容（包括權重、訓練資料與每題評估結果）皆一併發布（Released）。

### 核心貢獻（3～5點）
- **揭示詞彙表成本問題**：系統性量化了嵌入表在小型語言模型中的參數與檔案佔比，指出在 Gemma 3 270M 中嵌入表佔總參數的 63%，且量化後仍佔檔案大部分，挑戰了「詞彙表值得學習」的預設假設。
- **提出凍結詞彙表方案**：設計了一套無可訓練參數、僅 16 MB 的凍結 512 位元編碼表，透過主成分投影與符號二值化從預訓練嵌入一次性衍生，可直接取代傳統嵌入表。
- **驗證效能與效率的雙重優勢**：在 LAMBADA、HellaSwag、PIQA 等基準測試上，凍結詞彙表模型表現優於或平於學習式詞彙表模型；結合三元 BitNet b1.58 模型主體後，整個模型僅 46 MB，在筆電 CPU 上以 62 MB 記憶體達到每秒 615–740 詞元的生成速度，為浮點模型 8 位元 GGUF 的五至六倍速、記憶體僅其七分之一。
- **展現優異的詞彙擴展性**：凍結詞彙表在罕見詞上勝出 1.7–2.3 奈特，且能在訓練後以僅 3% 的成本接受 10,000 個新詞，而學習式詞彙表則崩潰 43%，證明其在詞彙動態性需求下更具韌性。
- **全面開源釋出**：所有權重、訓練資料與每題評估結果皆一併發布，便於重現與後續研究。

### 適合對象
本論文特別適合從事邊緣裝置（Edge device）語言模型部署、模型壓縮與量化（Quantisation）、以及高效能自然語言處理研究的學者與工程師閱讀；同時，對於關注開源模型生態、詞彙表設計對模型效能影響，以及希望在筆電 CPU 等資源受限環境中運行語言模型的研究者與實務工作者，亦具有高度參考價值。

## 深度分析

#### 方法論解析

本論文的核心方法論挑戰了小型語言模型（Small Language Model）設計中的一個根深蒂固的假設：詞彙表（Vocabulary）必須是可學習的、密集的浮點嵌入表（Embedding table）。作者提出了一種稱為「凍結詞彙表」（Frozen table）的替代方案，並透過嚴格的控制實驗驗證其有效性。

**凍結詞彙表的構造方法**

凍結詞彙表的生成過程可分為三個步驟。首先，從一個預訓練嵌入（Pretrained embedding）矩陣 E 開始（本文使用 Gemma 3 270M 自身的嵌入矩陣，形狀為 262,144 × 640）。其次，對該矩陣進行中心化處理後，透過主成分投影（Principal-component projection）提取前 512 個主成分方向 W。最後，對每個詞元（Token）的投影結果進行符號二值化（Sign binarisation），得到一個 512 位元（512-bit）的二值編碼：

code(t) = sign(W^T (E_t - μ)) ∈ {-1, +1}^512

這個過程的關鍵特性在於：512 個主成分方向保留了原始嵌入矩陣 92.3% 的變異數（variance），且在 WordSim-353 詞彙相似度任務上，二值編碼與人類相似度評分的相關性達到 0.617，幾乎與原始浮點嵌入的 0.614 相當。在最近鄰檢索任務中，每個詞元 10 個最近的浮點鄰居中，有 67% 同樣出現在其 10 個最近的編碼鄰居中。這些統計數據表明，符號二值化過程保留了原始嵌入的絕大多數語義資訊。

**架構整合方式**

凍結詞彙表並非直接替換原嵌入層，而是透過兩個小型可訓練線性映射整合進模型主體（Body）。輸入端，詞元的 512 位元編碼透過一個 512 → 640 的線性映射進入模型主體；輸出端，模型主體的最終狀態透過 640 → 512 的映射後，與所有詞元的編碼進行點積（dot product）相似度計算，並除以 √512 作為溫度參數。這兩個映射僅佔 0.65M 參數，相較於原嵌入表的 167.8M 參數，縮減了約 258 倍。

**「封印」（Seal）機制**

作者引入了一個稱為「封印」（Seal）的固定詞元先驗（per-token prior），即每個詞元在訓練資料中的對數單詞頻率（log unigram frequency）。這個先驗以 1 MB 的儲存成本加入輸出分數中，且不包含可訓練參數。在實驗分支 C 中，該先驗可從初始值進一步訓練，這增加了 262,144 個可訓練參數。

**三個實驗分支的設計**

實驗採用三個分支（A、B、C）進行對比，所有分支使用相同的 Gemma 3 270M 架構（18 層、寬度 640、gated GELU FFN 維度 2,048、4 個查詢頭和 1 個 KV 頭、QK-norm、5 個局部層配 1 個全局層、RoPE 基礎 10k 局部和 1M 全局、RMSNorm、無偏置、無 dropout），從相同的隨機初始化開始訓練，使用相同的 2.05B 個 FineWeb-Edu 詞元、相同的批次順序、相同的隨機種子。

- **分支 A**：學習式詞彙表（Learned table），262,144 × 640 的可學習嵌入表，與輸出頭（Output head / lm_head）共享權重（Tied），主體使用 bfloat16 自動精度轉換，共 268.1M 可訓練參數。
- **分支 B**：凍結詞彙表加固定封印，主體同樣使用 bfloat16，共 101.0M 可訓練參數。
- **分支 C**：凍結詞彙表，主體中所有線性層替換為 BitNet b1.58 的 BitLinear（RMSNorm 輸入、int8 absmax 激活、absmean 三元權重（ternary weights）、直通估計器（straight-through estimator）），注意力運算和 KV 快取保持 16 位元，封印從單詞頻率起始進行訓練，共 101.2M 可訓練參數。

**訓練策略的差異化處理**

分支 A 和 B 使用 AdamW 優化器，峰值學習率 6e-4、betas 為 0.9 和 0.95、權重衰減 0.1、1% 預熱和餘弦衰減至峰值的 10%。分支 C 則遵循 BitNet 作者發布的最小模型配方：峰值 1.5e-3 線性衰減，中點降至 1e-3，前半段權重衰減 0.1、後半段為 0、375 步預熱。這種差異化處理反映了三元權重模型需要不同的優化動力學。

#### 實驗數據解讀

**參數效率的權衡**

從驗證損失（Validation loss）的角度，學習式詞彙表以 2.6 倍的可訓練參數量換取了 0.20 奈特（Nats）的損失降低。這個數字看似支持學習式詞彙表，但需要放在具體應用場景中解讀。0.20 奈特的損失差異在困惑度（perplexity）上對應約 1.22 倍的倍數（e^0.20 ≈ 1.22），這在語言模型的標準評估中屬於較小的差距。然而，學習式詞彙表需要 167.8M 額外參數，這對於小型模型而言是巨大的開銷。

**基準測試結果的細微差異**

在四個標準基準測試（Benchmark）上，結果呈現出有趣的分化模式：

- **LAMBADA、HellaSwag、PIQA**：凍結詞彙表模型表現更好或至少持平（Tied）。這三個基準測試分別評估長距離上下文理解、常識推理和物理推理，表明凍結詞彙表在多數實際推理任務上並未損失能力。
- **ARC-Easy**：唯一偏向學習式詞彙表的基準。ARC-Easy 涉及科學問題的多步推理，可能更依賴於詞彙表中精細的語義區分能力。

這種分化模式暗示：凍結詞彙表保留了大部分語義資訊，但在需要精細區分相近概念的任務上可能略有不足。

**部署效率的顯著提升**

分支 C（BitNet b1.58 主體 + 凍結詞彙表）的部署數據尤為亮眼。整個模型檔案僅 46 MB，在筆電 CPU（Laptop CPU）上生成速度達到 615-740 詞元/秒（tokens per second），記憶體佔用僅 62 MB。相比之下，浮點模型（Float model）的 8 位元 GGUF 在 llama.cpp 中的速度僅為其五到六分之一，記憶體佔用則為其七倍。這意味著在邊緣部署場景中，凍結詞彙表結合三元權重能帶來數量級的效率提升。

**罕見詞與新詞的處理能力**

這是論文最具說服力的實驗結果之一。在罕見詞（Rare words）上，凍結詞彙表勝出 1.7-2.3 奈特，這是一個相當大的差距。這反直覺的結果可能源於：學習式詞彙表中罕見詞的嵌入向量在訓練過程中更新不充分，而凍結詞彙表的編碼來自預訓練模型的成熟嵌入，反而保留了更好的語義資訊。

在新詞（New words）適應性上，差異更加懸殊。凍結詞彙表在接受 10,000 個新詞後，僅產生 3% 的性能損失；而學習式詞彙表則崩潰（Collapses）了 43%。這個結果的根源在於架構設計：凍結詞彙表是預訓練嵌入的函數，任何向量都可以透過 code(mean of its pieces' rows) 或任意選定的向量成為新詞；而學習式詞彙表的新行在訓練前是隨機的，需要大量訓練才能收斂。

**統計顯著性的考量**

需要注意的是，論文使用的是 2.05B 詞元的訓練規模，這對於現代語言模型而言屬於較小規模。2.05B 詞元可能不足以讓學習式詞彙表充分收斂，特別是對於 262,144 個詞元中許多罕見詞的嵌入向量。這可能在一定程度上放大了凍結詞彙表的優勢。在更大規模的訓練下，學習式詞彙表的 0.20 奈特優勢可能會擴大或縮小，這是一個值得進一步探討的問題。

#### 與現有研究的比較

**與作者自身先前工作的比較**

作者在論文中明確指出，本文是 SHADOW-250M 和 SHADOW-50M 的「控制實驗版本」。SHADOW-250M 是一個 250M 參數模型，訓練於 30B 詞元，詞彙表為 131,072 個詞元各攜帶固定的 512 位元編碼，注意力層和 FFN 主體權重低於 2 位元，整個模型 60 MB，在筆電 CPU 上生成約 400 詞元/秒，記憶體 80 MB，驗證困惑度 23.3，PIQA 60、HellaSwag 34、ARC-Easy 41。SHADOW-50M 是 44M 參數的三元模型，詞彙表 73,880 詞元，總計 19.8 MB，速度約 2,000 詞元/秒。

相較於這些先前工作，本文的關鍵進步在於：1) 採用了嚴格的控制變量設計，僅改變詞彙表而保持其他所有因素不變；2) 提供了與標準學習式詞彙表的直接對比；3) 系統性地評估了罕見詞和新詞場景。先前工作「同時改變了太多東西」，缺乏因果歸因的能力，而本文填補了這一方法論空白。

**與 BitNet b1.58 的比較**

BitNet b1.58 是本文分支 C 主體架構的來源。BitNet 證明了 Transformer 可以使用 {-1, 0, +1} 三元權重訓練並保持大部分品質。微軟的 BitNet b1.58 2B4T 模型報告其記憶體為「0.4 GB（非嵌入部分）」，刻意將詞彙表排除在頭條數字之外。本文的工作與 BitNet 形成互補：BitNet 解決了主體的量化問題，但留下了詞彙表這個「固定成本」；本文則挑戰了這個固定成本本身。

值得注意的是，BitNet 本身也保持嵌入和輸出頭在 16 位元，這與本文的觀察一致：詞彙表是壓縮的盲點。本文提出的凍結詞彙表可以與 BitNet 疊加使用，產生更極致的壓縮效果。

**與傳統量化方法的比較**

GPTQ、AWQ 等傳統量化方法同樣將 embed_tokens 和 lm_head 排除在量化之外。llama.cpp 將輸出頭存儲為 6-8 位元，但仍保留相當的精度。這些方法的共同假設是：詞彙表對模型品質至關重要，不能輕易壓縮。本文從實證角度挑戰了這一假設，證明在小型模型中，詞彙表可以用 512 位元的凍結編碼替代，且在多數任務上不損失品質。

**與其他詞彙表壓縮研究的關係**

詞彙表壓縮並非全新研究方向。傳統方法包括子詞合併、字元級或位元組級（byte-level）編碼、稀疏嵌入等。本文的方法獨特之處在於：1) 完全凍結，不引入可訓練參數；2) 來自預訓練模型的成熟嵌入，而非隨機初始化；3) 保留了語義資訊（92.3% 變異數、WordSim-353 相關性 0.617）。這使得凍結詞彙表在「零成本適配」方面具有獨特優勢。

**局限性分析**

本文的局限性主要體現在以下幾個方面：

1. **規模限制**：實驗僅在 270M 參數規模和 2.05B 詞元訓練量下進行。對於更大模型或更大訓練規模，學習式詞彙表的相對優勢可能會改變。
2. **語言限制**：實驗使用 Gemma 的英語分詞器，對於形態更豐富的語言（如芬蘭語、土耳其語）或表意文字系統（中文、日文），凍結詞彙表的有效性尚未驗證。
3. **任務範圍**：評估僅限於四個基準測試，對於程式碼生成、數學推理、多輪對話等任務的表現未知。
4. **依賴預訓練嵌入**：凍結詞彙表的構造需要一個預訓練嵌入，這在「從頭訓練」（From scratch）的場景下需要額外的預訓練步驟或外部資源。

**可重現性的潛在挑戰**

儘管資源發布完整，仍存在一些可重現性挑戰：

1. **計算資源需求**：訓練 270M 模型需要相當的 GPU 資源，雖然遠小於前沿模型，但仍非所有研究者都能輕易負擔。
2. **隨機性控制**：論文聲稱使用相同的隨機種子和批次順序，但分散式訓練中的隨機性可能難以完全控制。
3. **依賴項版本**：分詞器版本、深度學習框架版本等可能影響結果，需要在程式碼中明確固定。

總體而言，本論文在可重現性方面樹立了良好的榜樣，特別是「每題評估結果」的發布，這在語言模型研究中仍屬少見。

#### 未來研究方向

本論文開啟了多個值得深入探索的研究方向。

**規模擴展實驗**

最直接的後續研究是在更大模型和更大訓練規模下驗證凍結詞彙表的有效性。具體問題包括：1) 對於 1B、7B 甚至更大參數的模型，凍結詞彙表是否仍然有效？2) 在 100B+ 詞元的訓練規模下，學習式詞彙表能否縮小與凍結詞彙表的差距？3) 隨著模型規模增長，詞彙表佔比的下降是否會改變權衡？這些問題的答案將決定凍結詞彙表方法的適用邊界。

**編碼大小的優化**

本文使用 512 位元的固定編碼大小，但這是否是最佳選擇值得探討。可能的探索方向包括：1) 不同編碼大小（256、1024、2048 位元）對性能和儲存成本的影響；2) 詞元自適應的編碼大小，常見詞使用較短編碼、罕見詞使用較長編碼；3) 層次化編碼結構，類似於霍夫曼編碼的思想。

**多語言和跨語言場景**

本文僅在英語場景下驗證。對於多語言模型，凍結詞彙表的構造需要考慮：1) 不同語言的形態複雜度差異；2) 跨語言詞彙共享的編碼效率；3) 文字編碼（中文、日文、阿拉伯文等）對二值化編碼的影響。特別是對於低資源語言，凍結詞彙表可能提供顯著優勢，因為學習式詞彙表在低資源語言上的訓練往往不充分。

**動態詞彙表更新機制**

本文展示了凍結詞彙表在接受新詞時僅產生 3% 的性能損失，而學習式詞彙表崩潰 43%。這啟發了動態詞彙表的研究方向：1) 如何高效地為新詞生成編碼？2) 是否可以設計增量更新機制，在不完全重新訓練的情況下擴展詞彙表？3) 詞彙表剪枝（vocabulary pruning）與凍結詞彙表的結合，即從預訓練模型中提取最有效的詞元子集。

**與其他壓縮技術的結合**

凍結詞彙表可以與多種現有壓縮技術疊加：1) 與 BitNet b1.58 結合（本文已展示）；2) 與稀疏專家混合（Mixture of Experts）結合，詞彙表層可以設計為稀疏路由；3) 與知識蒸餾結合，使用大模型的嵌入來指導小模型的詞彙表設計；4) 與檢索增強生成（RAG）結合，凍結詞彙表可以作為檢索索引的基礎結構。

**理論分析**

本文主要從實證角度論證凍結詞彙表的有效性，缺乏理論解釋。未來研究可以探索：1) 為什麼 512 位元的二值編碼能保留 92.3% 的變異數？是否存在資訊理論的下界？2) 凍結詞彙表在何種條件下優於學習式詞彙表？是否與詞元頻率分佈的冪律特性有關？3) PCA + 符號二值化是否是最優的編碼方案？隨機投影（Random Projection）或其他降維方法是否同樣有效？

**應用場景探索**

凍結詞彙表的特性使其特別適合某些應用場景：1) 邊緣部署（Edge deployment），如手機、嵌入式系統；2) 隱私敏感場景，模型需要在本地運行；3) 實時應用，對延遲敏感；4) 物聯網設備，記憶體和計算資源極其有限。未來研究可以系統性地探索這些場景中的部署效果。

**詞彙表作為介面設計**

本文提出了一個有趣的觀點：詞彙表是模型的「介面」，而非其「智慧」的核心。這啟發了重新思考詞彙表的設計哲學：1) 詞彙表是否應該標準化，以便不同模型之間共享？2) 是否可以設計通用的詞彙表編碼方案，類似於 Unicode 的角色？3) 詞彙表是否可以作為獨立的「產品」進行開發和分發？

這些研究方向不僅能推動小型語言模型的發展，也可能對整個自然語言處理領域產生深遠影響，特別是在資源受限環境下的語言模型部署方面。

## 論文問答

**Q1：為什麼在小型語言模型中，詞彙嵌入表會成為最大的參數負擔？**
A：在小型語言模型中，詞彙嵌入表佔據了不成比例的參數比例。以 Gemma 3 270M 為例，其總參數為 268M，其中嵌入表（與輸出頭共享）就佔了 167.8M，比例高達 62.6%，而負責實際計算的前饋層僅佔 26.4%、注意力層佔 11.0%。這是因為詞彙表大小（262,144 個詞元）與模型維度（640）的乘積是一個固定成本，無論模型規模如何縮減，詞彙表大小都不會等比例縮小。對大型模型而言，詞彙表只是「捨入誤差」，但對小型模型而言，它幾乎就是模型本身。

**Q2：為何現有的量化方法無法有效解決嵌入表過大的問題？**
A：現有量化方法如 GPTQ、AWQ 以及 BitNet b1.58 都刻意保留嵌入層與輸出頭在 16 位元精度，因為這些層對量化極為敏感，壓縮會嚴重損害模型品質。這意味著當模型主體被壓縮到極低位元（如三元權重）後，詞彙表反而成為檔案大小的主要負擔——一個三元主體搭配 16 位元詞彙的 Gemma 3 270M 會變成約 20 MB 主體加上 335 MB 詞彙表。Microsoft 在 BitNet b1.58 2B4T 的報告中也以「0.4 GB（非嵌入）」來迴避這個問題，將詞彙表視為使用詞彙的固定成本。

**Q3：為什麼這個問題在當前特別值得重視？**
A：過去幾年三個趨勢同時發生：BitNet 證明三元權重 Transformer 仍能維持品質；十億參數以下的模型已實用化（如 Gemma 3 270M、SmolLM、Qwen 最小尺寸）；這些模型開始被部署到手機與筆電 CPU 上執行。在這種資源受限的環境中，每一個 MB 與每個詞元讀取的位元組都直接影響延遲與使用者體驗。詞彙表卻未獲得同等的研究關注，形成了一個明顯的效率瓶頸。

**Q4：這篇論文提出的核心方法——凍結詞彙表——具體是如何建構的？**
A：作者從一個預訓練的嵌入矩陣 E（Gemma 3 270M 的 262,144 × 640 矩陣）出發，先將其中心化，再取前 512 個主成分方向組成投影矩陣 W，然後對每個詞元的投影結果取符號，得到 code(t) = sign(W^T (E_t − μ))，每個詞元僅用 512 位元表示，整個詞彙表僅 16.8 MB。這個表在建構後即凍結，不再更新；詞元進入模型時透過一個小型的可訓練線性映射（512→640）轉換，輸出時則經由另一個映射（640→512）後與所有編碼做點積並除以 √512。

**Q5：相較於作者先前釋出的 SHADOW-250M 與 SHADOW-50M，本研究的關鍵創新為何？**
A：先前兩個模型雖然都採用了凍結詞彙表，但同時改變了太多變數（架構、訓練資料、訓練步數等），且從未與學習式詞彙表做對照實驗，因此無法確定詞彙表替換本身帶來多少影響。本研究採用嚴格的控制變數設計：相同模型主體、相同資料、相同訓練步數、相同隨機種子，唯一改變的只有詞彙表。這使得「凍結 vs 學習式詞彙表」的比較結論具有因果性，而非僅是觀察性。

**Q6：在設計凍結詞彙表時，為何選擇 512 位元、主成分投影與符號二值化這些設計？**
A：512 位元是經驗與理論的折衷：512 個主成分方向承載了原始嵌入矩陣 92.3% 的變異數，足以保留大部分語意資訊；同時 512 位元讓整個詞彙表僅 16 MB，比原本 167.8M 個 16 位元參數（335 MB）小了一個數量級。主成分投影確保編碼捕捉到最重要的變異方向，而符號二值化則將每個維度壓縮到 1 位元，並自然產生漢明距離可解釋的相似度——在 WordSim-353 上，編碼與人類相似度評分的相關性達 0.617，甚至略高於原始浮點嵌入的 0.614。

**Q7：本研究使用了哪些基準測試，關鍵結果為何？**
A：研究在 LAMBADA、HellaSwag、PIQA 與 ARC-Easy 四個標準基準上評估。結果顯示學習式詞彙表（Arm A）僅在驗證損失上以 0.20 奈特的優勢勝出，但代價是 2.6 倍的可訓練參數；在 LAMBADA、HellaSwag、PIQA 上凍結詞彙表（Arm B）與學習式詞彙表持平或更佳，僅 ARC-Easy 偏好學習式詞彙表。搭配三元主體的 Arm C 整個模型僅 46 MB，在 LAMBADA 與 PIQA 上仍與浮點模型持平，並在筆電 CPU 上以 62 MB 記憶體達到每秒 615–740 詞元的生成速度，是 llama.cpp 中 8 位元 GGUF 浮點模型的 5–6 倍，記憶體僅其七分之一。

**Q8：實驗中最令人意外或最重要的發現是什麼？**
A：最令人意外的發現是凍結詞彙表在罕見詞上反而勝出學習式詞彙表 1.7–2.3 奈特——這與直覺相反，因為學習式詞彙表理論上應該更適應訓練資料。原因是學習式詞彙表中罕見詞的嵌入僅被少數樣本更新，容易過擬合或欠擬合；而凍結詞彙表是從一個已訓練好的嵌入推導而來，其編碼反映了預訓練階段學到的全域語意結構，對低頻詞反而更穩健。另一個關鍵發現是詞彙擴充能力：凍結詞彙表能在訓練後以 3% 的成本接受 10,000 個新詞，而學習式詞彙表在加入新行後會崩潰 43%。

**Q9：本研究做了哪些消融實驗或對照比較？**
A：研究設計了三個實驗分支形成系統性對照：Arm A 為學習式共享詞彙表搭配 bfloat16 主體（基準線）；Arm B 為凍結詞彙表搭配相同浮點主體，驗證詞彙表替換本身的影響；Arm C 為凍結詞彙表搭配 BitNet b1.58 三元主體，驗證詞彙表與極低位元主體的相容性。三者使用完全相同的 2.05B FineWeb-Edu 詞元、相同的批次順序與隨機種子，僅改變詞彙表與主體精度，從而能隔離每個設計選擇的貢獻。

**Q10：這項技術適合哪些實際部署場景？**
A：最直接的應用是邊緣裝置與離線部署：在筆電 CPU 上以 62 MB 記憶體、每秒 600+ 詞元的速度運行，使得在無 GPU 的環境中也能使用語言模型。手機應用是另一個明顯場景——46 MB 的模型檔案可輕鬆隨應用程式發布，無需依賴雲端 API。此外，物聯網裝置、嵌入式系統、隱私敏感的本地推理（如醫療、法律文件處理）都能受益於這種小體積、低記憶體的部署模式。

**Q11：從產品角度，這項技術帶來哪些新的設計可能性？**
A：產品設計上，開發者現在可以將整個模型（包括詞彙表）打包進單一小型檔案，無需依賴外部詞彙檔或雲端服務，大幅簡化部署流程。詞彙擴充能力（凍結詞彙表能以低成本加入新詞）使得領域適應變得容易——例如為醫療、法律或特定方言添加專業詞彙，僅需 3% 的成本。此外，凍結詞彙表的確定性編碼使得模型行為更可預測、可審查，有助於符合監管要求與建立使用者信任。

**Q12：這項研究對小型語言模型領域的更廣泛影響是什麼？**
A：這項研究挑戰了「詞彙表是固定成本」的普遍假設，證明詞彙表可以被大幅壓縮而不損失品質，甚至在某些維度上表現更佳。它為極小型模型（數十 MB 等級）的實用化開啟了新路徑，使得「在裝置上運行完整語言模型」從理論走向可行。此外，凍結詞彙表的概念可能啟發後續研究：例如探索不同編碼方式（不僅限於符號二值化）、動態詞彙擴充機制、或將類似思想應用於其他大型靜態參數（如位置編碼）。

**Q13：本研究承認哪些限制？**
A：作者明確指出，本研究的資料規模僅 2.05B 詞元，遠小於現代大型模型的訓練量，因此結論是否能在更大規模下成立仍待驗證。此外，詞彙表是從 Gemma 3 270M 的特定嵌入推導而來，這意味著凍結詞彙表的品質上限受限於該預訓練嵌入——若原始嵌入本身有偏差或缺陷，凍結詞彙表也會繼承這些問題。實驗也僅在英文 FineWeb-Edu 上進行，多語言場景下的表現尚未評估。

**Q14：在哪些情況下學習式詞彙表仍可能優於凍結詞彙表？**
A：根據實驗結果，ARC-Easy 基準上學習式詞彙表表現較好，顯示在某些需要精確語意區分的推理任務上，可訓練的詞元表示仍有優勢。此外，當訓練資料與預訓練嵌入來源（Gemma 3 270M）的資料分佈差異極大時，學習式詞彙表可能因為能從頭適應新分佈而表現更佳。對於需要極高精度詞元區分（如程式碼生成、數學符號）的任務，學習式詞彙表的微調能力也可能更為重要。

**Q15：未來有哪些值得探索的研究方向？**
A：未來方向包括：探索更大規模訓練（數十 B 或數百 B 詞元）下凍結詞彙表是否仍維持優勢；研究不同的編碼方案（如多值量化、學習式哈希）能否進一步提升效率；將凍結詞彙表概念擴展到多語言與多模態場景；以及探討凍結詞彙表與其他極低位元技術（如 2 位元注意力、稀疏化）的組合。此外，詞彙擴充機制（如何以最低成本加入新詞）也是一個值得深入研究的實用問題。

## 實務應用指南

### 適用場景

1. **手機與筆電上的離線助手**：將 46 MB 的三元模型部署於 Android/iOS 應用或筆電，無需網路即可提供問答、摘要、改寫功能。論文中 615–740 tokens/sec 的筆電 CPU 速度已足夠支援即時對話，且記憶體僅 62 MB，可與其他 App 共存。

2. **隱私敏感的本地推論**：醫療筆記、法律草稿、個人日記等場景下，資料完全不離開裝置。凍結詞彙表無需重新訓練即可在裝置端完成推論，避免任何雲端 API 呼叫。

3. **嵌入式與 IoT 裝置的語音/文字介面**：智慧音箱、工業 HMI、車載系統等記憶體受限的場景。16 MB 的詞彙表加上 30 MB 的三元主體，可塞進 MCU 等級的硬體（搭配外掛 DRAM）。

4. **快速領域適配的詞彙擴充**：企業內部術語、新興品牌名、罕見人名等需要新增詞彙的場景。凍結表只需將新詞的子詞編碼取平均即可加入，訓練成本僅 3%；學習式詞彙表則會崩潰 43%。

5. **低延遲自動完成與拼字建議**：瀏覽器擴充、IDE 插件、輸入法等需要毫秒級回應的場景。CPU 推論速度比 llama.cpp 的 8-bit GGUF 快 5–6 倍，記憶體僅其七分之一。

### 實作前置條件

**資料**
- 預訓練嵌入來源：需有一個公開的嵌入表（論文使用 Gemma 3 270M 的 262,144 × 640 矩陣）。可從 Hugging Face `google/gemma-3-270m` 直接取得。
- 訓練語料：FineWeb-Edu sample-10BT 或等量級（≥2B tokens）的高品質網頁文字，並使用對應 tokenizer。
- 驗證集：10M tokens 的 held-out 文字，以及 LAMBADA、HellaSwag、PIQA、ARC-Easy 的標準評測集。

**算力**
- 訓練：單張消費級 GPU（如 RTX 4090 或 A100 40GB）即可重現論文的 2.05B tokens 訓練，預估數天。
- 推論：任何 x86/ARM CPU 即可，無需 GPU。論文的 615–740 tokens/sec 在一般筆電 CPU 上達成。

**技能**
- 必備：PyTorch、Transformer 訓練流程、tokenizer 使用、PCA 與線性代數基礎。
- 加分：BitNet b1.58 的 BitLinear 實作、llama.cpp 的 GGUF 格式、模型量化經驗。
- 工具：Hugging Face Transformers、bitsandbytes 或自訂 int8 absmax 量化器。

### 實作步驟建議

1. **取得預訓練嵌入並產生凍結表**
   - 下載 Gemma 3 270M 的 `embed_tokens.weight`（262,144 × 640）。
   - 對每列做中心化，計算前 512 個主成分方向矩陣 W。
   - 對每個 token 計算 `sign(W^T (E_t − μ))`，得到 512-bit 編碼。
   - 儲存為 16 MB 的二值檔案，這就是凍結詞彙表。

2. **建立模型主體**
   - 依照 Gemma 3 270M 的公開配置（18 層、寬度 640、gated GELU FFN 2048、4 query + 1 KV head、QK-norm、5 個滑窗層、RoPE）從頭初始化。
   - 替換嵌入層：將 `embed_tokens` 換成「凍結編碼 → 512→640 線性映射」的模組。
   - 替換輸出頭：將 `lm_head` 換成「640→512 線性映射 → 與所有編碼做點積」的模組，並加上 seal（log unigram 先驗）。

3. **選擇實驗分支並訓練**
   - 分支 A（基準）：學習式詞彙表 + bfloat16 主體，268M 可訓練參數，AdamW，peak LR 6e-4。
   - 分支 B（凍結表 + 浮點主體）：101M 可訓練參數，同樣 AdamW 設定。
   - 分支 C（三元主體）：將所有線性層換成 BitLinear（int8 absmax 激活、absmean 三元權重、STE），peak LR 1.5e-3 線性衰減，375 步 warm-up。
   - 三個分支使用相同 seed、相同 batch 順序、相同 7,820 步，確保公平比較。

4. **評估與驗證**
   - 計算驗證集 loss（nats）與四個基準測試的標準化準確率。
   - 特別檢查罕見詞與新詞的表現：凍結表在罕見詞上應勝出 1.7–2.3 nats。
   - 測試 CPU 推論速度與峰值記憶體，確認符合部署目標。

5. **匯出與部署**
   - 將凍結表（16 MB）、三元權重（≈30 MB）、兩個小線性映射（≈0.65M 參數）打包成單一檔案。
   - 若需 llama.cpp 相容性，將三元權重轉成 GGUF（注意：凍結表機制需要客製化 tokenizer 邏輯）。
   - 釋出時一併提供權重、中間檢查點、訓練日誌與每題評測結果，方便重現。

6. **詞彙擴充（選用）**
   - 新詞：取其子詞編碼的平均作為新編碼，僅 3% 成本。
   - 若需微調 seal，僅更新 262,144 個對數頻率參數，極輕量。

### 潛在風險與注意事項

1. **品質天花板受限於預訓練嵌入**：凍結表是 Gemma 3 270M 嵌入的 PCA + 符號投影，僅保留 92.3% 的變異數。若預訓練嵌入本身品質不佳，下游表現也會受限。**緩解**：選擇已知高品質的嵌入來源，或在多個嵌入上做集成。

2. **三元主體的訓練不穩定性**：BitNet b1.58 對學習率、warm-up、weight decay 排程極為敏感。論文使用 BitNet 官方最小模型的配方，但若改變資料或架構需重新調參。**緩解**：嚴格遵循已發布配方，並保留分支 B 作為穩定 fallback。

3. **與現有推論框架的相容性**：凍結表機制（編碼 → 小線性映射 → 主體）與標準 `embed_tokens` 介面不同，llama.cpp、vLLM 等框架需要客製化載入器。**緩解**：先以 PyTorch 原型驗證，再投資框架整合；或考慮將凍結表展開為 dense 嵌入（會犧牲檔案大小優勢）。

4. **新詞加入的語意合理性**：凍結表用「子詞編碼平均」處理新詞，對複合詞效果尚可，但對語意偏移大的詞（如品牌名諧音）可能失真。**緩解**：允許使用者手動指定新詞的編碼向量，或在 seal 層做調整。

5. **基準測試的侷限**：論文僅在四個基準（LAMBADA、HellaSwag、PIQA、ARC-Easy）上比較，未涵蓋程式碼、數學、多輪對話等場景。**緩解**：在目標領域自行評估，不要直接外推。

6. **授權與商用限制**：論文以「非商業研究」授權釋出。**緩解**：商用前需聯繫作者取得授權，或自行從頭重現（論文已釋出完整程式碼與資料）。

### 與其他技術的整合建議

1. **llama.cpp / GGUF**：可將三元主體轉成 GGUF，但凍結表需以自訂 tokenizer metadata 形式嵌入。建議 fork llama.cpp 並新增 `frozen_vocab` 載入路徑，或在 Python 端用 PyTorch 原型部署。

2. **Hugging Face Transformers**：將凍結表包裝成 `PreTrainedModel` 的子類別，覆寫 `embed_tokens` 與 `lm_head` 的 forward 方法，使其對外仍呈現標準介面，方便與 `pipeline()`、`generate()` 相容。

3. **裝置端框架**：ONNX Runtime、TensorFlow Lite、Core ML 都支援自訂運算子，可將「編碼查詢 + 點積」實作為單一 fused op，進一步提升推論速度。

4. **RAG 與工具呼叫**：46 MB 的三元模型可作為本地路由器，判斷是否需要呼叫雲端 LLM；或作為 RAG 的 reranker，在裝置端完成初步篩選。

5. **持續學習管線**：凍結表 + 可訓練 seal 的設計天然支援線上學習——只需更新 262,144 個對數頻率參數即可適應使用者詞彙分布，無需完整重訓。

6. **多語言擴展**：若有多語言預訓練嵌入，可分別產生多個凍結表並依語言切換，總成本仍遠低於單一大型學習式詞彙表。

### 給不同背景讀者的閱讀建議

**給初學者**：先讀摘要與第 1 節，理解「為什麼小模型的詞彙表是最大成本」這個直覺——想像一本字典佔了整本書的 63%，而你只需要其中 512 個是非題的答案。跳過數學細節，專注在「凍結表是什麼、它能跑多快、檔案多小」這三個結論。建議直接到 Hugging Face 試跑作者釋出的模型，感受 615 tokens/sec 的速度。

**給 AI 工程師**：重點讀第 2 節的凍結表構造（PCA + sign binarization）與第 3 節的三個分支設定。特別注意分支 C 的 BitLinear 細節（int8 absmax 激活、absmean 三元權重、STE）以及學習率排程——這些是重現的關鍵。實作時先復現分支 B（最簡單），再進階到分支 C。評估時務必加入罕見詞與新詞測試，這是凍結表真正的優勢所在。

**給研究者**：這篇論文的價值在於「控制變數的實驗設計」——相同主體、相同資料、相同步數、相同 seed，只改變詞彙表。這是過去 SHADOW 系列模型缺乏的嚴謹度。建議從三個方向延伸：(1) 將凍結表機制套用到更大模型，觀察規模效應；(2) 嘗試不同的編碼方式（k-means、隨機投影、學習式量化）取代 PCA + sign；(3) 理論分析為何 512-bit 編碼能保留 92.3% 變異數且在 WordSim-353 上與浮點嵌入幾乎一致。

**給產品經理**：核心訊息是「46 MB、62 MB 記憶體、每秒 600+ tokens 的筆電 CPU 推論」——這把語言模型從雲端 API 變成了可以像圖片一樣嵌入 App 的資產。優先評估的場景是隱私敏感（醫療、法律）、離線需求（野外、飛機上）、成本敏感（高頻呼叫但單次價值低）。注意「非商業研究」授權的限制，商用前需與作者接洽。建議先做一個 4 週的技術可行性 PoC，驗證目標使用者的品質感受是否可接受。
