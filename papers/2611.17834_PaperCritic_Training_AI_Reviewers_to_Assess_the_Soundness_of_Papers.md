## 深度分析

#### 方法論解析

本論文提出了一套完整的 AI 審稿人（AI reviewer）訓練框架，核心在於重新定義論文審稿的學習目標，並據此設計資料集建構與模型訓練流程。以下從問題形式化、資料集建構、模型訓練三個層面進行深度解析。

**問題形式化的重新設計**

傳統的 AI 審稿人訓練方法將任務形式化為「整體審稿與評分生成」（holistic review-and-score generation），目標是最小化生成審稿與人類參考審稿之間的相似度差距，或最大化整體評分的一致性。這種做法本質上是「人類審稿模仿」（human review imitation），存在兩個根本問題：第一，審稿本身具有多重目的——評估健全性（soundness）、趣味性（interestingness）與清晰度（clarity），其中後兩者具有高度主觀性，難以作為可靠的學習信號；第二，整體相似度提供的監督過於稀疏（sparse supervision），無法精細區分審稿中各要點的品質差異。

本論文將任務窄化為「論文健全性評估」（paper soundness assessment），僅聚焦於審稿三項核心目的中最重要且最具客觀性的健全性。透過對七位 AI 研究人員的人類研究（human study），作者歸納出兩個通用評估標準（universal evaluation criteria）：

- **健全性（Soundness）**：審稿要點（review point）是否依據論文內容或領域知識中的正確前提。
- **實質性（Substantiveness）**：審稿要點是否對論文的主要論點（main claim）或核心證據（central evidence）提出中等程度以上的疑慮（concern）。

在此基礎上，作者進一步引入第三個目標——**完整性（completeness）**，衡量生成內容對健全且實質的參考評估（reference assessment）的覆蓋率（coverage）。最終將學習目標形式化為聯合最大化精確率（precision，即健全性與實質性）與召回率（recall，即覆蓋率），這是一個類似資訊檢索中 Precision-Recall 框架的設計，使問題具備明確且可量化的目標函數（objective function）。

**PaperSound-23K 資料集的建構**

資料集包含 1K 篇 ICLR 投稿（submission）與 23K 個審稿要點（review point），其中兼顧人類撰寫（human-written）與 LLM 生成（LLM-generated）的來源。品質標註（quality labeling）的關鍵在於：使用具有強推理能力的 LLM 對每個審稿要點進行健全性與實質性的自動化評估，並透過人類研究驗證 LLM 評分者與人類評分者的一致性達到與人類之間一致性相當的水準（Table 1）。這項設計解決了傳統資料集中以作者回覆作為品質標籤所帶來的雜訊問題（Goldberg et al., 2025），也避免了人類標註的高昂成本。

**PaperCritic 的訓練流程**

訓練採用兩階段策略：

1. **監督式微調（Supervised Fine-Tuning, SFT）**：在健全且實質的參考要點上進行微調，使模型學習產生高品質審稿要點的基本模式。
2. **線上強化學習（Online Reinforcement Learning, RL）**：以精確率與召回率的 F1 分數（F1 score）作為獎勵（reward）。具體而言，使用兩個獎勵模型（reward models, RMs）分別評估健全性與實質性以估計精確率，並使用一個匹配器（matcher）測量參考覆蓋率以估計召回率。

此設計的精妙之處在於：相較於傳統方法僅以整體審稿相似度或評分相似度作為獎勵，本方法提供了**密集獎勵（dense reward）**——每個審稿要點都能獲得獨立的品質評估，從而實現更精細的學習信號。

#### 實驗數據解讀

**領域內（in-domain）效能**

在 PaperSound-23K 測試集上，PaperCritic-4B 優於其他使用傳統方法訓練的 4B 模型以及前沿模型（frontier models）。這項結果具有重要意義：4B 參數量的模型能夠超越規模遠大的前沿模型，顯示出問題形式化與訓練方法設計的關鍵作用，而非單純依賴模型規模。

**領域外（out-of-domain, OOD）遷移能力**

最令人矚目的是遷移（transfer）實驗結果。在 ICLR 投稿上學習審稿的能力，可遷移至四個截然不同的領域：

1. **Nature 系列論文（Nature-family papers）**：與 ICLR 投稿同屬學術論文，但風格、領域、長度差異顯著。
2. **程式碼審查（code review）**：從學術文本轉向程式碼文本。
3. **法律合約審查（legal contract review）**：高度專業化的法律文本。
4. **故事寫作回饋（story writing feedback）**：從技術性文本轉向創意寫作。

在所有四個基準測試中，RL 訓練階段均一致地提升了模型效能。這項結果暗示：學習「評估健全性」的能力可能是一種通用的批判性思維技能，可跨文本類型遷移。

**獎勵設計的穩健性**

作者進一步驗證了使用不同 LLM 評分者進行評估時，訓練方法仍然有效；同時在更大模型上訓練也保持效能提升。這兩項消融實驗增強了方法的可信度，顯示其不依賴特定的評分模型或模型規模。

**人類與模型一致性**

Table 1 顯示 LLM 評分者與人類的一致性達到人類之間一致性的可比水準，這是整個方法論的基石——若品質標註不可靠，則下游訓練與評估均失去意義。

#### 與現有研究的比較

**相較於現有 AI 審稿人訓練方法**

| 面向 | 傳統方法（Idahl & Ahmadi, 2025; Weng et al., 2025; Zhu et al., 2025; Zeng et al., 2025; Liu et al., 2026） | PaperCritic |
|------|------|------|
| 學習目標 | 整體審稿相似度 + 評分相似度 | 精確率（健全性+實質性）+ 召回率（覆蓋率） |
| 監督密度 | 稀疏（整體層級） | 密集（要點層級） |
| 評估對象 | 整體審稿品質 | 個別審稿要點品質 |
| 獎勵設計 | 相似度/偏好 | F1 分數 |
| 資料標註 | 人類撰寫審稿或作者回覆 | 健全性+實質性的品質標註 |

**相較於 Mun et al. (2026)**

Mun et al. 使用作者回覆作為品質標籤進行 SFT 與 DPO 訓練，但作者回覆提供的是雜訊標籤（Goldberg et al., 2025），且難以用於線上獎勵計算。PaperCritic 透過定義明確的健全性與實質性標準，並使用對應的獎勵模型實現線上學習，克服了這些限制。

**相較於現有論文審稿資料集**

早期資料集（Kang et al., 2018; Dycke et al., 2023）僅針對論文接受分類或評分預測等初步任務；近期資料集（Gao et al., 2024; Weng et al., 2025; Zhu et al., 2025）雖針對審稿生成，但未考慮審稿目的的多重性與個別要點的品質差異。PaperSound-23K 透過窄化任務範疇並標註個別要點品質，解決了這些問題。

**限制與不足**

1. **任務範疇的窄化**：僅評估健全性而忽略趣味性與清晰度，可能限制其在需要全面審稿的場景中的實用性。
2. **領域限制**：訓練資料來自 ICLR，雖然展現了遷移能力，但在某些高度專業化的領域（如臨床醫學論文）的表現仍待驗證。
3. **LLM 評分者的循環依賴**：使用 LLM 進行品質標籤與獎勵計算，雖然經過人類一致性驗證，但本質上仍存在循環依賴風險。
4. **缺乏對人類偏見的探討**：健全性評估雖然相對客觀，但仍可能受到評分者對特定方法論或研究方向的偏好影響。

1. **訓練細節未完全公開**：RL 階段的具體超參數、獎勵模型的架構與訓練過程、PPO/GRPO 等演算法選擇等細節需查閱附錄或程式碼。

#### 未來研究方向

**1. 擴展至其他審稿維度**

本論文僅聚焦於健全性，未來可將相同框架擴展至趣味性與清晰度的評估。然而，這需要解決兩者的主觀性問題——可能需要引入多評分者機制或個人化偏好建模。

**2. 互動式審稿代理人**

目前的 PaperCritic 僅產生靜態的審稿要點，未來可發展為互動式審稿代理人，能與作者進行多輪對話、追問細節、提供具體的改進建議。這需要結合對話管理與領域知識推理能力。

**3. 跨領域遷移的理論分析**

本論文觀察到從 ICLR 審稿到四個截然不同領域的遷移現象，但缺乏理論解釋。未來可從表徵學習、任務泛化理論等角度分析「健全性評估」作為通用技能的遷移機制。

**4. 與人類審稿人的協作模式**

未來可探索 PaperCritic 作為人類審稿助理的協作模式，例如：預審稿（pre-screening）以減輕人類負擔、生成審稿要點供人類編輯、或在意見分歧時提供第二參考。這需要研究人機協作中的信任校準與責任歸屬問題。

**5. 獎勵模型的改進**

目前的獎勵模型依賴 LLM 評分者，存在循環依賴與偏見風險。未來可探索：(a) 結合人類標註與 LLM 標註的混合獎勵機制；(b) 對抗式訓練以提升獎勵模型的穩健性；(c) 引入因果推理以更準確評估健全性。

**6. 應用於其他品質評估任務**

「健全性評估」的框架可推廣至其他需要批判性評估的領域，例如：新聞事實查核、政策文件評估、AI 系統輸出的品質審查等。這將使 PaperCritic 的方法論產生更廣泛的社會影響。

**7. 偏見與公平性研究**

需系統研究 PaperCritic 是否對特定研究方法、語言風格、機構背景存在偏見，以及如何緩解這些偏見。這對於 AI 審稿在學術生態中的公平應用至關重要。

**8. 大規模人類研究驗證**

雖然 LLM 評分者的一致性已達人類水準，但仍需更大規模的人類研究驗證 PaperCritic 在真實審稿場景中的效用，包括與人類審稿人的比較研究、對作者修改行為的影響分析等。

A：PaperSound-23K 資料集從 1K 篇 ICLR 投稿中收集了 23K 個審稿要點，這些要點混合了人類撰寫與 LLM 生成的內容，並使用具備強推理能力的 LLM 對每個要點進行品質標註（健全且實質 vs. 其他）。使用 LLM 進行標註的合理性來自於人類研究中觀察到的現象：LLM 標註與人類標註的一致性與人類標註者之間的一致性相當（Table 1），這意味著 LLM 標註可以作為可靠的品質代理指標。這種自動化標註方式大幅降低了建構大規模品質標註資料集的成本，使訓練資料規模得以擴展至 23K 個要點。

**Q6：為什麼選擇強化學習搭配 F1 分數作為獎勵，而非傳統的監督式微調或偏好學習？**

A：強化學習搭配 F1 分數作為獎勵的設計有兩個關鍵優勢：第一，F1 分數同時考量精確率與召回率，能鼓勵模型在「提出健全且實質的疑慮」與「全面覆蓋重要問題」之間取得平衡，避免單一指標極端化；第二，獎勵模型與匹配器提供的是密集回饋（dense rewards），相較於傳統偏好學習僅在整體審稿層級提供稀疏訊號，能對每個審稿要點的品質進行更細緻的指導。此外，論文中先進行監督式微調（SFT）再進行線上強化學習（RL）的兩階段訓練，能讓模型先學習基本的審稿模式，再透過獎勵訊號進一步優化。

**Q7：PaperCritic 在哪些基準測試上進行評估？為什麼選擇這些測試集？**

A：PaperCritic 在五個基準測試上進行評估：領域內的 PaperSound-23K 測試集，以及四個領域外基準——Nature 系列論文審稿、程式碼審查、法律合約審查與故事寫作回饋。選擇領域內測試集是為了驗證模型在訓練分布內的表現，而選擇四個差異極大的領域外任務則是為了測試模型的遷移能力，驗證「學習審稿 ICLR 投稿」這一訓練目標是否能泛化至本質上都是「評估文本論點健全性」的相關任務。這種設計呼應了論文中「健全性評估」作為通用審稿能力的核心主張。

**Q8：PaperCritic 的關鍵實驗結果為何？它如何超越前沿模型與其他訓練方法？**

A：實驗結果顯示，PaperCritic-4B 在領域內 PaperSound-23K 測試集上超越了其他 4B 模型（使用傳統訓練方法）以及前沿模型。更令人驚訝的是，僅在 ICLR 論文審稿資料上進行的強化學習訓練，能持續提升模型在所有四個領域外基準上的表現，顯示出強健的遷移能力。此外，作者還驗證了該訓練方法在使用不同 LLM 評分器時仍然有效，並且能擴展至更大的模型，這些結果共同支持了「以健全性為核心的訓練目標」相較於「整體審稿模仿」的優勢。

**Q9：強化學習訓練對於領域外遷移能力的影響為何？有哪些消融實驗支持此結論？**

A：強化學習訓練對領域外遷移能力有顯著的正面影響——即使訓練資料僅來自 ICLR 論文審稿，經過 RL 訓練後的模型在 Nature 論文審稿、程式碼審查、法律合約審查與故事寫作回饋等四個截然不同的任務上均獲得一致的效能提升。雖然論文中未明確列出獨立的消融實驗章節，但作者透過比較 SFT-only 與 SFT+RL 的模型表現，以及使用不同 LLM 評分器與不同模型規模的實驗，驗證了 RL 階段的必要性與方法的穩健性。這種跨領域的遷移現象暗示，「健全性評估」可能是一種通用的文本批判能力，可應用於任何需要評估論點是否被充分支持的場景。

**Q10：PaperCritic 在實際學術會議審稿流程中可能如何部署？**

A：在實際部署上，PaperCritic 最可能作為「輔助性審稿助理」而非完全取代人類審稿人，例如在會議審稿初期自動標記出潛在的健全性疑慮，幫助人類審稿人更快聚焦於關鍵問題。它也可以用於會議主席（AC）分配審稿時，根據健全性疑慮的嚴重程度建議審稿人數量，或在 rebuttal 階段提供作者回應的健全性評估。此外，PaperCritic 還能應用於期刊編輯初篩投稿，識別出論點明顯缺乏支持的稿件，從而減輕合格審稿人的工作量。

**Q11：將 PaperCritic 應用於程式碼審查、法律合約審查等領域外任務時，需要注意哪些產品設計考量？**

A：將 PaperCritic 應用於領域外任務時，產品設計上需注意幾個關鍵考量：首先，雖然模型展現了遷移能力，但實際部署時仍應進行領域特定的微調或提示工程，以確保審稿要點符合該領域的專業術語與慣例。其次，模型輸出的「健全且實質」標籤應作為輔助參考而非最終決策依據，特別是在法律合約審查這類高風險場景中，必須由人類專家進行最終確認。此外，使用者介面應清楚呈現每個審稿要點的健全性與實質性評分，讓使用者能理解模型的判斷依據，而非將其視為黑盒子。

**Q12：這項研究對學術出版與 AI 輔助審稿領域的長期影響為何？**

A：這項研究的長期影響在於重新定義了 AI 審稿人的訓練範式——從「模仿人類審稿」轉向「學習客觀的健全性評估標準」，這對於學術出版的品質控制具有深遠意義。隨著 AI 會議投稿量持續爆炸性成長，這種可量化、可驗證的 AI 審稿工具有助於緩解合格審稿人不足的問題，同時維持審稿的客觀性與嚴謹度。更重要的是，該研究展示了「健全性評估」作為通用文本批判能力的遷移潛力，為未來開發跨領域的 AI 評估助手（如政策文件審查、新聞事實查核等）開闢了新的研究方向。

**Q13：論文作者承認哪些方法論上的限制？**

A：雖然論文中未明確列出獨立的「限制」章節，但從方法論設計可以推論出幾項限制：第一，訓練資料僅來自 ICLR 投稿，可能無法完全代表所有學術領域的審稿標準，特別是 Nature 系列論文中常見的跨學科審稿場景。第二，使用 LLM 進行品質標註雖然與人類標註者一致性相當，但仍可能繼承 LLM 的系統性偏見，例如對特定論述風格的偏好。第三，健全性與實質性的二元標籤可能過於簡化，無法捕捉審稿要點品質的細微差異，例如「部分健全但提出邊際疑慮」這類中間狀態。

**Q14：在哪些情況下 PaperCritic 可能會產生誤判或失敗？**

A：PaperCritic 可能在以下情況下產生誤判：第一，當論文的論點依賴高度領域專門知識時，模型可能因缺乏該領域的深度理解而誤判前提的正確性，特別是在數學證明或複雜實驗設計的健全性評估上。第二，對於論點新穎但尚未被廣泛接受的研究，模型可能將其誤判為「不健全」，因為它依賴的證據尚未在領域內建立共識。第三，在跨學科論文中，模型可能難以判斷哪些證據標準適用於哪個子領域，導致健全性評估的不一致。

**Q15：未來的研究方向有哪些？特別是如何將此框架擴展到「趣味性」與「清晰度」等其他審稿面向？**

A：未來研究方向可分為幾個層次：在健全性評估方面，可探索更細緻的品質標註（如多級評分而非二元標籤），以及結合領域知識圖譜來提升對專門論點的判斷能力。在審稿面向的擴展上，最大的挑戰在於如何為「趣味性」與「清晰度」定義同樣客觀且可量化的標準——這可能需要借鑑推薦系統中的偏好學習，或結合讀者行為資料（如引用次數、閱讀完成率）作為間接訊號。此外，將 PaperCritic 與作者回應生成結合，形成「審稿—回應—再審稿」的完整對話系統，也是值得探索的方向。

### 實作前置條件

**資料需求**
- 至少 1,000 篇具備人類審稿意見的學術論文（建議來自 OpenReview 等開放平台，如 ICLR 2023–2025 投稿）
- 每篇論文需有 3–5 位審稿人的完整審稿意見，用於建立參考審稿要點

- 具備強化學習基礎（PPO/GRPO 演算法理解）
- 具備 prompt engineering 與 LLM-as-a-judge 設計經驗

### 實作步驟建議

**步驟一：資料準備與品質標註**
1. 從 OpenReview 收集 1K+ ICLR 投稿 PDF 與對應審稿意見
2. 將 PDF 轉為結構化文字（建議使用 Nougat、Marker 或 GPT-4o 視覺模型）
3. 將每篇審稿拆解為「審稿要點」（review point）— 每點為自足的評估單元
4. 使用強推理 LLM 對每個要點標註「健全性」與「實質性」標籤（參考 Definition 1）
5. 抽樣 100 筆由人類專家驗證，確認人機一致性達到人類間一致性水準（Kappa ≥ 0.7）

**步驟二：監督式微調（SFT）**
1. 篩選「健全且實質」的參考要點作為 SFT 訓練資料
2. 使用標準 instruction-tuning 格式：`<論文全文> → <健全且實質的審稿要點>`
3. 訓練 2–3 epochs，學習率 1e-5，採用 cosine schedule
4. 驗證 SFT 模型已學會產生結構化、要點式的審稿輸出

**步驟三：獎勵模型訓練**
1. **健全性獎勵模型**：以標註資料訓練二元分類器，判斷要點前提是否正確
2. **實質性獎勵模型**：訓練分類器判斷要點是否提出中等以上程度的疑慮
3. **覆蓋率匹配器**：訓練模型判斷生成要點是否對應到參考要點（可用 embedding 相似度 + 規則匹配混合方案）

**步驟四：強化學習（RL）**
1. 採用 GRPO 或 PPO 演算法
2. 獎勵函數 = F1(precision, recall)，其中 precision 由兩個獎勵模型估計，recall 由匹配器估計
3. 每個 prompt 採樣 4–8 個回應，計算群組相對優勢
4. 訓練 1–2 epochs，注意 KL 散度懲罰避免模型偏離 SFT 基礎

**步驟五：評估與部署**
1. 在 PaperSound-23K 測試集上評估 precision、recall、F1
2. 在四個 OOD 基準（Nature 論文、程式碼審查、法律合約、故事寫作）上驗證遷移能力
3. 使用 vLLM 部署推論服務，提供 REST API
4. 設計 UI：輸入論文 → 輸出結構化審稿要點清單（含健全性/實質性信心分數）

### 潛在風險與注意事項

**風險一：評估偏誤與獎勵 hacking**
- 兩個獎勵模型可能與人類判斷存在系統性偏差，模型可能學會「投機取巧」產生高分但無實質價值的要點
- **緩解**：定期以人類專家抽樣審查；採用 ensemble 多個獎勵模型；加入長度與多樣性懲罰項

**風險二：領域漂移導致品質下降**
- 在 ICLR 訓練的模型應用於高度專業領域（如臨床醫學論文）時，可能產生表面合理但實質錯誤的審稿
- **緩解**：在目標領域收集少量資料進行領域適配（LoRA 微調）；明確告知使用者「僅供參考」

**風險三：偏見放大**
- 訓練資料來自 ICLR，可能內含對特定方法論、寫作風格或研究社群的偏見
- **緩解**：審稿輸出應附帶信心分數與依據引用；保留人類審稿人最終決定權

**風險四：抄襲與隱私問題**
- 將未發表論文上傳至第三方 LLM API 可能違反會議雙盲政策或洩露研究
- **緩解**：採用本地部署；簽署資料處理協議；對作者身份資訊進行遮罩

**風險五：法律與學術倫理責任**
- 若 AI 審稿意見被用於拒稿決策，可能引發申訴或法律爭議
- **緩解**：AI 審稿僅作為「建議」而非「決定」；保留完整審稿紀錄供申訴查驗

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節了解「為何需要專門的健全性審稿模型」，跳過技術細節，重點理解「健全性 vs. 趣味性 vs. 清晰度」的三分法，以及 precision/recall 在審稿任務中的意義。可先嘗試使用作者釋出的模型（若開源）對自己寫過的報告做測試，直觀感受其能力與限制。

**給 AI 工程師**：重點閱讀第 3 節的問題形式化、第 4 節的獎勵模型設計，以及附錄中的訓練細節。特別注意 F1 獎勵的設計巧思——將 precision 拆解為健全性與實質性兩個獨立獎勵模型，是將抽象品質標準轉化為可學習訊號的典範。建議嘗試在自己的領域資料上重現此流程，並實驗不同的 RL 演算法（GRPO vs. PPO）。

**給研究者**：本論文的核心貢獻在於「重新定義問題」而非單純的模型創新——將審稿從「模仿人類」轉為「優化客觀指標」。建議深入分析 Definition 1 的理論基礎、獎勵模型的偏差來源、以及跨領域遷移的機制（為何 ICLR 訓練能遷移到故事寫作？）。可進一步探索：是否能將此框架應用於 peer review 以外的品質評估任務（如新聞事實查核、教材品質審查）？

**給產品經理**：本技術的商業價值在於「緩解專業審稿人力短缺」與「提升文件品質審查效率」。建議關注其遷移能力——單一模型可服務多個垂直市場（學術、程式碼、法律、創意寫作），具備平台化潛力。產品設計上應強調「AI 輔助而非取代人類」的定位，並設計透明的信心分數與依據可追溯機制，以建立使用者信任。需特別注意資料隱私、學術倫理與法律責任邊界。
