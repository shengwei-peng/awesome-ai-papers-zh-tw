## ⚡ TL;DR

反思式提示詞優化器從失敗軌跡學習，但雜訊訊號會導致錯誤歸因與有害更新。
本文提出 GEPA-Curator，透過任務策展過濾雜訊任務，並檢索先前成功軌跡作為反思器上下文。
在四項基準測試中，效能比 GEPA 提升最多 20.7%，比 ACE 提升最多 21.2%。

## 摘要翻譯

大型語言模型（LLMs）越來越多地用於多輪代理工作負載，這類任務需要與複雜環境進行持續互動。現有的反思式提示詞優化器（例如 GEPA）從失敗的執行軌跡中學習，但代理式失敗也可能源自提示詞弱點、執行框架限制、隨機執行或雜訊評審。我們主張此類失敗未必能提供有用的學習訊號，甚至可能有害；因此，必須策展哪些任務應提供給提示詞優化器，以獲得更好的效能。我們提出 GEPA-Curator，一個增強提示詞優化器的框架，以選擇哪些代理經驗應影響提示詞優化。具體而言，GEPA-Curator 包含兩個組件：任務策展，負責篩除可能產生雜訊或不可靠學習訊號的任務；以及先前成功檢索，選擇性地檢索該任務過去的成功軌跡，並將其作為額外上下文提供給提示詞優化器。我們在 GoBrowse、ALFWorld、AppWorld 與 τ-bench 上評估 GEPA-Curator，分別使用 Gemini 3.1 Pro 與 Claude Opus 5 作為優化器模型。GEPA-Curator 在平均效能上匹配或超越兩個基準，相較 GEPA 最高提升 20.7%，相較 ACE 最高提升 21.2%。

### 核心貢獻（3～5點）
- **問題識別：** 指出反思式提示詞優化器僅從失敗軌跡學習的局限性——代理式失敗可能源自提示詞弱點、執行框架限制、隨機執行或雜訊評審，未必提供可靠的學習訊號，甚至可能導致有害更新。
- **方法提出：** 設計 GEPA-Curator 框架，透過兩個互補組件——任務策展（過濾雜訊或不可靠任務）與先前成功檢索（選擇性擷取過去成功軌跡作為額外上下文）——系統性地策展送入提示詞優化器的代理經驗。
- **廣泛實驗評估：** 在 GoBrowse、ALFWorld、AppWorld 與 τ-bench 四個多輪代理基準測試上進行驗證，並分別採用 Gemini 3.1 Pro 與 Claude Opus 5 作為優化器模型，展現方法的跨模型與跨任務泛用性。
- **顯著效能提升：** GEPA-Curator 在平均效能上匹配或超越 GEPA 與 ACE 兩項基準方法，相較 GEPA 最高提升 20.7%，相較 ACE 最高提升 21.2%，證實策展式學習訊號對提示詞優化的關鍵價值。

### 適合對象
- 研究提示詞優化、反思式提示詞優化（Reflective Prompt Optimization）與代理系統的學術研究者
- 從事大型語言模型自我改進（Self-improvement）與遞迴自我改進（RSI）相關研究的工程師與科學家
- 關注多輪代理工作負載中 LLM-as-a-judge 雜訊問題與評估可靠性的 NLP/AI 從業者
- 對代理式設定（Agentic Settings）中提示詞缺陷診斷與執行框架限制感興趣的技術決策者

## 深度分析

#### 方法論解析

GEPA-Curator 的核心設計理念建立在對代理式學習 (agentic learning) 中「失敗訊號可靠性」的批判性反思之上。傳統的反思式提示詞優化器 (reflective prompt optimizers) 如 GEPA 假設失敗的執行軌跡 (failed rollouts) 必然反映提示詞的缺陷，但本文論證此假設在多輪代理工作負載 (multi-turn agentic workloads) 中往往不成立——失敗可能源自提示詞弱點 (prompt weaknesses)、執行框架限制 (harness limitations)、隨機執行 (stochastic execution)、雜訊評審 (noisy judges)，甚至是任務本身的模糊性 (ambiguous tasks) 或不可行性 (infeasible tasks)。當反思器 (Reflector) 將這些雜訊訊號 (noisy signals) 誤判為提示詞缺陷 (prompt deficiencies) 時，便會產生錯誤歸因 (misattribution)，進而導致有害更新 (harmful updates)。

**雙重策展機制 (Dual Curation Mechanism)**

GEPA-Curator 作為一個運行於現有提示詞優化器之上的代理式資料策展框架 (agentic data Curator)，包含兩個互補的核心元件：

1. **任務策展 (Task Curation)**：取代傳統隨機選取小批次 (minibatch) 的做法，主動篩選可能提供乾淨學習訊號 (clean learning signal) 的任務，剔除疑似雜訊或故障的任務。此機制從源頭提升反思品質，而非僅在變異後進行驗證。

2. **先前成功檢索 (Prior Success Retrieval)**：選擇性地檢索特定任務的歷史成功軌跡 (successful trajectories)，並將其作為額外上下文 (additional context) 提供給提示詞優化器。這使反思器能夠對比「過去為何成功」與「現在為何失敗」，從而更精準地診斷真正的提示詞問題。

**與驗證式閘控機制的本質差異**

現有方法如 GEPA 採用保留驗證集 (held-out validation set) 進行變異後的閘控決策，但本文指出此機制有兩大根本限制：(1) 聚合評分可能因隨機性而錯誤接受有害變異或拒絕有益變異；(2) 閘控僅在變異產生後才介入，無法根本改善反思與變異本身的品質。GEPA-Curator 透過在變異前提供策展後的任務與成功範例，從根本上提升反思器的推理基礎。

#### 實驗數據解讀

**評估基準與模型配置**

實驗在四個具有代表性的代理式基準上進行：GoBrowse（基於 WebArena 的四個網站）、ALFWorld（文字冒險環境）、AppWorld（應用程式互動環境）以及 τ-bench（多輪對話代理基準）。優化器模型採用 Gemini 3.1 Pro 與 Claude Opus 5 兩種前沿大型語言模型，以驗證方法的模型無關性 (model-agnostic)。

**關鍵效能結果**

GEPA-Curator 在所有基準上匹配或超越基準方法的平均效能 (mean performance)，具體增益為：
- 相較 GEPA 最高提升 20.7%
- 相較 ACE 最高提升 21.2%

此結果的意義在於：(1) 策展機制的效益具有跨基準的普適性，涵蓋網頁瀏覽、室內導航、應用操作與對話代理等異質任務；(2) 跨優化器模型的一致表現表明，策展機制並非依賴特定模型的特性，而是捕捉了代理式學習中的結構性問題。

**結果的深層意涵**

值得注意的是，雖然摘要未提供各基準的細粒度數據，但「匹配或超越」的措辭暗示在某些基準上 GEPA-Curator 僅與基準持平。這可能反映策展機制的效益與任務特性相關——在雜訊較高的環境（如網頁瀏覽中按鈕故障的情境）中，策展的價值更為顯著；而在較為穩定的環境中，傳統方法已能提供足夠訊號。

#### 與現有研究的比較

**方法論定位**

GEPA-Curator 與現有反思式優化器形成正交互補的關係。GEPA 採用進化搜尋結合反思進行系統層級軌跡診斷；ACE 透過結構化 playbook 組織累積策略；SkillOpt 將技能文件視為可訓練的外部狀態並進行有界編輯；Meta-Harness 則將優化對象擴展至執行框架程式碼本身。GEPA-Curator 並非取代這些方法，而是回答一個互補的問題：「哪些代理軌跡提供有效的反思訊號，以及應伴隨何種歷史證據？」

**相對優勢**

相較於僅依賴變異後驗證的方法，GEPA-Curator 的優勢在於：(1) 從源頭提升反思品質而非僅在末端過濾；(2) 透過成功範例提供正向對比，使反思器能區分真正的提示詞問題與環境雜訊；(3) 策展機制可與任何基線優化器組合，具有模組化優勢。

**現有限制**

然而，本文未深入探討的潛在限制包括：(1) 任務策展本身的判斷標準若依賴 LLM，可能引入新的雜訊來源；(2) 先前成功檢索的有效性取決於歷史軌跡的可用性與代表性，在冷啟動 (cold start) 場景下可能受限；(3) 策展機制增加了計算開銷，需評估其效益成本比；(4) 對於任務模糊性與不可行性的判斷缺乏明確的理論框架。

#### 可重現性評估

根據論文提供的資訊，GEPA-Curator 採用 Gemini 3.1 Pro 與 Claude Opus 5 作為優化器模型，並在 GoBrowse、ALFWorld、AppWorld 與 τ-bench 等公開基準上進行評估。然而，論文中未明確說明程式碼、資料集與模型權重的開源狀況。考量到：(1) 使用的基準均為公開基準，理論上支援重現；(2) 採用商業 API 模型（Gemini 與 Claude）而非開源權重，存在 API 變動與成本的風險；(3) 策展機制的具體實作細節（如策展標準的定義、成功軌跡的檢索演算法）需從論文中仔細提取。整體而言，重現性處於中等水平——基準與模型可獲取，但完整實作細節與程式碼的可用性尚待確認。

#### 未來研究方向

**理論層面**

未來研究可朝以下方向深化：(1) 形式化定義代理式任務中的「訊號雜訊比」，建立策展機制的理論基礎；(2) 探究任務模糊性與不可行性的自動識別方法，減少對人工標註的依賴；(3) 研究策展機制與驗證式閘控的理論最優組合策略。

**方法層面**

(1) 將策展機制擴展至多模態代理環境，處理視覺與文字混合的失敗歸因問題；(2) 探索基於強化學習的自適應策展策略，使策展標準隨優化過程動態調整；(3) 整合因果推斷方法，更精準地分離提示詞因素與環境因素的影響；(4) 研究跨任務的成功軌跡遷移機制，提升檢索效率與泛化能力。

**應用層面**

(1) 將 GEPA-Curator 應用於真實世界的企業代理場景，驗證其在生產環境中的實用性；(2) 探索策展機制在多代理協作 (multi-agent collaboration) 場景中的角色，其中失敗歸因更為複雜；(3) 結合人類反饋 (RLHF) 機制，使策展標準能融入人類價值觀與領域知識；(4) 研究策展機制在長視野任務 (long-horizon tasks) 中的可擴展性，特別是當歷史軌跡庫規模龐大時的檢索效率問題。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於代理式（agentic）大型語言模型在多輪互動工作負載中進行反思式提示詞優化時所面臨的「雜訊學習訊號」問題。具體而言，當代理在複雜環境中執行任務失敗時，失敗的原因未必來自提示詞本身的缺陷，而可能源自執行框架的限制、隨機執行、雜訊評審，甚至是任務本身的模糊或不可行。然而，現有的反思式提示詞優化器（如 GEPA）往往將所有失敗軌跡視為有效的學習訊號，要求反思器（Reflector）據此修改提示詞，這種做法可能導致錯誤歸因，產生不必要甚至有害的提示詞更新。因此，論文的核心理念是：必須對提供給提示詞優化器的任務經驗進行策展（curation），以提升自我改進的可靠性。

**Q2：為什麼現有的反思式提示詞優化方法（如 GEPA 和 ACE）會失敗？**
A：現有方法失敗的根本原因在於它們假設所有失敗軌跡都包含可泛化的學習訊號，但這個假設在代理式設定中往往不成立。論文中以購物網站任務為例說明：當代理因為網頁按鈕暫時故障而失敗時，反思器若將此視為提示詞缺陷的證據，便可能錯誤地建議代理尋找替代方式完成購買，從而引入有害的提示詞變異。此外，雖然 GEPA 等方法使用保留驗證集（held-out validation set）作為變異後的守門機制，但這種驗證式閘控僅在變異產生後才作用，無法從根本上改善反思或變異本身的品質；而且由於評估分數本身可能因執行或評審的隨機性而帶有雜訊，導致好的變異可能被拒絕、壞的變異反而被接受。

**Q3：為何在代理式 AI 系統中，策展學習訊號的問題特別重要？**
A：在代理式 AI 系統中，學習訊號的品質問題被多重因素放大，因此策展變得格外關鍵。首先，代理的執行涉及與外部環境的複雜互動，並透過執行框架（harness）與工具中介，這使得失敗的因果歸因變得困難；任務本身也常見模糊不清或不可行的情況，進一步增加雜訊。其次，代理任務通常以 LLM 作為評審（LLM-as-a-judge）來評估成敗，這種評審方式本身就可能引入不穩定性。最後，遞迴自我改進（RSI）的核心承諾是讓代理從自身經驗中持續學習，但若學習訊號品質不佳，這個反饋迴路不僅無法帶來改善，反而會累積錯誤的提示詞修改，最終損害系統效能。因此，策展是實現可靠自我改進的必要前提。

**Q4：GEPA-Curator 的核心方法是什麼？**
A：GEPA-Curator 是一個運行於現有提示詞優化器之上的代理式資料策展框架（agentic data Curator），其核心設計理念是「先策展、再優化」。具體而言，它在原本隨機選取任務組成小批次（minibatch）的流程中，插入一個策展層，負責挑選可能提供乾淨學習訊號的任務，並丟棄疑似雜訊或故障的任務。這個策展層同時也負責從過去的執行歷史中檢索與當前任務相關的成功軌跡，作為額外上下文提供給反思器，使其能對照過去成功與當前失敗的差異，產生更精準的提示詞變異。透過這種方式，GEPA-Curator 不取代 GEPA 等優化器，而是作為外掛式的執行框架，從「輸入端」增強其運作。

**Q5：GEPA-Curator 的兩個關鍵創新是什麼？**
A：第一個關鍵創新是「任務策展」（task curation），即不再隨機選取任務進入小批次，而是根據任務是否可能提供乾淨且可靠的學習訊號來進行篩選，這能避免反思器被雜訊或不可歸因的失敗所誤導。第二個關鍵創新是「先前成功檢索」（prior success retrieval），它會選擇性地從代理的過往經驗中擷取同一任務的成功軌跡，並將其作為額外上下文餵給提示詞優化器，使反思器能看見「過去為何成功、現在為何失敗」的對照，進而產生更聚焦、更準確的提示詞變異。這兩個機制共同作用，從「輸入端」改善了反思品質，補足了既有方法僅在「輸出端」進行驗證式閘控的不足。

**Q6：GEPA-Curator 在設計上做了哪些重要選擇？**
A：在設計選擇上，GEPA-Curator 採取了一個務實的「外掛式」架構決策——它不重新設計提示詞優化器本身，而是作為執行框架層（harness layer）運作於 GEPA 等既有優化器之上，這使得該方法能與不同的優化器模型（如 Gemini 3.1 Pro 與 Claude Opus 5）靈活組合。另一個重要選擇是將策展的責任交由代理本身承擔，而非使用預定義的啟發式規則，這讓策展邏輯能適應不同任務與環境的特性。此外，系統刻意保留了「保留驗證集」的閘控機制，而非完全取代它，顯示作者認為策展與驗證是互補而非互斥的防線，兩者結合能提供更穩健的保護。

**Q7：論文中使用了哪些基準測試來評估 GEPA-Curator？**
A：論文中使用了四個具有代表性的代理式基準測試來評估 GEPA-Curator 的效能，分別是 GoBrowse（涵蓋四個 WebArena 網站）、ALFWorld（模擬家庭環境中的文字遊戲任務）、AppWorld（測試代理在模擬應用程式生態中的操作能力），以及 τ-bench（專注於多輪對話與工具使用的基準）。這些基準涵蓋了網頁瀏覽、家庭任務、應用程式互動與對話式代理等不同場景，能夠全面檢驗 GEPA-Curator 在多樣化代理式設定下的泛化能力。此外，作者同時使用 Gemini 3.1 Pro 與 Claude Opus 5 作為優化器模型，以驗證策展效益是否跨模型一致，而非僅在特定模型上有效。

**Q8：GEPA-Curator 的關鍵實驗結果為何？**

### 潛在風險與注意事項

**風險一：策展過度保守，導致學習訊號不足**
- 若策展器過於嚴格，可能將過多任務標記為「雜訊」，使反思器缺乏足夠樣本
- **緩解**：設定策展閾值時保留一定比例的「邊界任務」，並監控反思器的輸出品質

**風險二：先前成功軌跡的偏誤**
- 過去成功的軌跡可能反映的是舊版提示詞的行為，不一定適用於當前提示詞
- **緩解**：在檢索時加入「軌跡時效性」權重，或僅檢索與當前失敗模式相關的成功片段

**風險三：評審雜訊被錯誤放大**
- 若 LLM-as-a-judge 本身不穩定，策展器可能將其誤判為「任務雜訊」
- **緩解**：對評審進行一致性檢查（如多次評分取眾數），並將評審穩定性納入策展依據

**風險四：計算成本顯著增加**
- 策展與檢索機制會增加每次迭代的開銷
- **緩解**：使用較小的模型執行策展，並對成功軌跡儲存庫建立快取

**風險五：提示詞變異的可解釋性下降**
- 當反思器同時接收策展後的任務與成功軌跡，其產生的變異可能更難追溯
- **緩解**：保留完整的變異日誌，並要求反思器在變異時附上理由
