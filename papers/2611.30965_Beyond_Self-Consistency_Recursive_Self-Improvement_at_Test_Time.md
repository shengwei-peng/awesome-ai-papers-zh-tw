本文提出 **測試時遞迴自我改進（Test-Time Recursive Self-Improvement, TT-RSI）** 框架，其核心設計理念在於突破現有測試時方法對自一致性（Self-Consistency, SC）的依賴。該框架由兩個相互強化的組件構成：上下文遞迴自我改進（In-Context RSI）與權重遞迴自我改進（In-Weight RSI），形成一個閉環的自我改進迴路。

**In-Context RSI（推論階段）**：此組件是一種無需訓練（training-free）的測試時擴展（test-time scaling）策略。其運作機制為：給定問題 $q$，模型 $\pi_\theta$ 首先生成初始解 $a_1$，接著反覆以最新解作為上下文重新解題，產生 $a_2, a_3, \ldots, a_\ell$ 的精煉（refinement）鏈。關鍵設計在於「中性呈現」前次完整解——保留中間推理步驟，讓模型自主決定是否重用（reuse）、重做（rework）或採用新方法（new approach）。此設計避免了簡單條件化可能造成的探索受限與重複問題，同時使額外的推論計算（inference compute）能夠建立在先前推理之上，而非產生更多獨立樣本（independent samples）。

**In-Weight RSI（訓練階段）**：此組件將 In-Context RSI 的精煉成果蒸餾（distill）至模型權重中。其採用**同策略自我蒸餾（On-Policy Self-Distillation, OPSD）** 機制，使用來自同一精煉鏈中相鄰的兩個解（$a_1$ 與 $a_2$）作為教師參考。具體包含兩種蒸餾方式：
- **遞迴蒸餾（Recursive Distillation）**：結合 $a_1$ 條件化引導（用於答題 $L_{ans}$）與 $a_2$ 條件化引導（用於精煉 $L_{ref}$），形成 $L_{Rec}$。
- **加速蒸餾（Accelerated Distillation）**：比較 $a_1$ 與 $a_2$ 條件化引導在 $y^0$ 上的差異，僅加權 $a_2$ 引導（$L_{Acc}$），其中較大的引導位移（per-token shift，以全變異距離 TV 衡量）獲得較大的權重。

**理論基礎**：作者證明了從兩個連續解進行蒸餾能強化精煉能力，並使首次嘗試朝向模型的無限步精煉極限（infinite-step refinement limit）移動。這一理論保證為框架的有效性提供了數學支撐。

A：現有自一致性方法存在兩個相互關聯的缺陷。首先，在推論階段，每次嘗試都從零開始，先前的推理過程完全被浪費掉，額外的計算資源只產生更多獨立樣本而非更好的推理，這使得推論效率低落。其次，在訓練階段，多數投票會獎勵模型最常產生的答案，當這個多數答案本身就是錯誤的時候，訓練反而會強化這個錯誤，形成惡性循環。這兩個缺陷使得測試時的改進停滯而無法累積，打斷了「更好答案訓練更好模型」的理想迴圈。

**Q3：為什麼遞迴自我改進對通用人工智慧（AGI）的研究很重要？**

A：遞迴自我改進被視為通往通用人工智慧的關鍵路徑之一，因為它代表著 AI 系統能夠自主提升自身能力，而不僅僅依賴人類設計者提供更多資料或更大模型。這種能力使得模型在部署後仍能持續進化，理論上可以突破人類設計時所設定的能力上限。論文中也引用了 Silver 與 Sutton 的觀點，強調「持續學習」與「遞迴自我改進」是 AGI 發展的核心議題，因此探索如何在測試時實現這種改進具有深遠的理論與實務意義。

**Q4：TT-RSI 的核心方法是什麼？**

A：TT-RSI（Test-Time Recursive Self-Improvement，測試時遞迴自我改進）的核心概念是引入一個「改進步驟」（improvement step），讓模型以先前的完整解答作為參考來重新解題，而非從頭開始。這個框架包含兩個互補的組件：在推論時使用 In-Context RSI 進行無需訓練的測試時擴展，在訓練時使用 In-Weight RSI 將精煉成果蒸餾到模型權重中。這種設計使得推論計算能建立在先前推理之上，而訓練則從模型自身的精煉中學習，而非依賴多數投票，從而實現真正的遞迴改進。

**Q5：In-Context RSI 與 In-Weight RSI 如何相互強化？**

A：In-Context RSI 透過讓模型以完整先前解答作為上下文反覆重新解題，產生一系列連續的精煉結果；這些精煉結果接著被 In-Weight RSI 用作訓練信號，透過自我蒸餾（on-policy self-distillation）將改進成果轉移到模型權重中。更新後的模型不僅能直接給出更好的答案，還能在下一輪 In-Context RSI 中產生更強的精煉結果，進而成為後續訓練的更佳參考。這種「推論產生訓練資料，訓練改善推論能力」的雙向迴圈，正是 TT-RSI 能夠累積改進而非停滯的關鍵機制。

**Q6：為什麼 In-Context RSI 要「中性呈現」完整解答而非僅給出最終答案？**

A：作者刻意選擇將完整解答（包括中間推理步驟）以中性方式呈現給模型，而非僅提供最終答案，這是因為這樣做能讓模型自主決定如何利用先前內容：可以保留已驗證的步驟、聚焦於有疑問的部分，或完全採用新方法。這種設計避免了兩種極端問題——若完全不提供先前推理，模型會重複犯同樣的錯誤；若過度限制探索，模型則可能陷入重複迴圈。實驗結果顯示，這種做法不僅提升了準確率，還將生成的 token 數量減少了相對 68.6%，證明了「建構於先前推理之上」比「從頭重新解題」更為高效。

**Q7：論文中使用了哪些基準測試來驗證 TT-RSI？**

A：作者選用了五個競賽級數學基準測試來評估 TT-RSI 的效能，這些基準涵蓋了不同難度與類型的數學推理問題，能夠全面檢驗模型的解題能力。在模型方面，實驗使用了 Qwen3 系列的 1.7B、4B 與 8B 三種規模，這樣的設計可以驗證方法在不同模型容量下的一致性。此外，論文還與五種無標籤基準方法進行比較，確保評估的公平性與全面性。

**Q8：TT-RSI 在準確率上的關鍵成果為何？**

A：實驗結果顯示，完整的 TT-RSI 框架相較於基礎模型平均提升了 +13.89% 的準確率，而僅使用 In-Weight RSI 也能帶來 +5.79% 的提升。在相同的測試時擴展預算下，TT-RSI 比最強的自一致性方法 TTPO + SC 還要高出 +4.79% 的平均準確率。這些數據證明了遞迴自我改進相較於傳統多數投票方法的實質優勢，也顯示出 In-Context RSI 與 In-Weight RSI 結合後的累積效應。

**Q9：除了準確率之外，TT-RSI 在效率與消融實驗方面還有哪些發現？**

A：在效率方面，In-Context RSI 透過重用先前推理而非從頭開始，將生成的 token 數量減少了相對 68.6%，這對於實際部署時的成本控制具有重要意義。在消融實驗方面，論文的理論分析證明了從兩個連續解答進行蒸餾能強化精煉能力，並將首次嘗試推向模型的無限步精煉極限。此外，論文中提到的「加速蒸餾」（Accelerated Distillation）機制透過比較 a1 與 a2 條件下的引導差異，對變化較大的 token 給予較高權重，進一步提升了訓練效率。

**Q10：TT-RSI 在實際部署中有哪些適合的應用場景？**

A：TT-RSI 特別適合需要高準確率且無法取得標籤資料的場景，例如教育科技中的自動解題系統、數學競賽輔助工具，以及企業內部的複雜推理任務。在這些場景中，使用者通常只提供問題而無標準答案，因此能利用的監督信號僅來自模型自身。此外，對於需要即時推理且計算資源有限的邊緣部署，TT-RSI 的 token 效率優勢（減少 68.6%）使其比傳統自一致性方法更具實用價值。

**Q11：在將 TT-RSI 整合到產品中時，需要考量哪些工程與設計因素？**

A：產品化 TT-RSI 時需要考量幾個關鍵因素：首先，由於 In-Weight RSI 涉及模型權重的更新，需要設計合適的更新頻率與版本管理機制，避免模型在多次更新後偏離原始能力。其次，In-Context RSI 的多輪精煉會增加延遲，需要在準確率提升與回應時間之間取得平衡，產品設計上可考慮提供「快速模式」與「精煉模式」兩種選項。此外，由於精煉過程中模型可能產生不一致的中間結果，需要設計良好的使用者介面來呈現推理過程，增強使用者對結果的信任。

A：TT-RSI 的提出挑戰了「測試時只能透過獨立採樣與多數投票來提升效能」的傳統觀念，為測試時改進開闢了新的研究方向。它強調了「建構於先前推理之上」的重要性，這種思路可能會啟發更多關於序列式推理、迭代式精煉的研究。此外，TT-RSI 展示了無標籤自我改進的可行性，這對於降低模型訓練對標註資料的依賴具有重要意義，可能會推動整個領域朝向更自主、更持續學習的 AI 系統發展。

## 實作步驟建議

**步驟一：建立基線評估管線**
先以基礎模型在目標領域上評估單次生成準確率與平均 token 消耗，作為後續比較的基準。同步實作多數投票（SC）基線，因為它是論文的對照組。

**步驟二：實作 In-Context RSI**
- 設計 prompt 模板：將前一次完整解題（含推理與最終答案）作為下一次生成的 context
- 關鍵設計：完整呈現前次解題而非僅呈現最終答案，並以中性語氣引入（避免暗示「這是錯誤的」或「這是正確的」），讓模型自主決定重用、重做或新解
- 設定鏈長 ℓ：論文中 ℓ 越大效果越好，但需平衡成本；建議從 ℓ=2 或 3 開始觀察邊際效益
- 監控 token 消耗：相較 SC 應有顯著下降（論文報告 68.6% 相對降幅）

**步驟三：實作 In-Weight RSI**
- 採用 on-policy self-distillation（OPSD）框架
- 訓練資料：來自步驟二的相鄰解對 (a₁, a₂)，其中 a₂ 為 a₁ 的精煉
- 損失函數設計：
  - `L_ans`：以 a₁ 為教師，引導模型在無參考時也能答對
  - `L_ref`：以 a₂ 為教師，引導模型在有 a₁ 為參考時能精煉
  - `L_rec`：兩者加權組合
  - `L_acc`（可選加速蒸餾）：僅在 a₁ 與 a₂ 條件下的引導差異處加權，差異越大權重越高
- 訓練多輪：每輪用最新模型重新生成精煉鏈，再做下一輪蒸餾

**步驟四：建立迴圈監控**
- 追蹤每輪後 (a) 單次生成準確率、(b) 精煉後準確率、(c) 與「無限步精煉極限」的差距
- 若準確率停滯或下降，停止迴圈並檢查是否陷入自我強化偏誤

**步驟五：部署與持續運作**
- 線上服務時同時使用 In-Context RSI（推論時精煉）與定期排程的 In-Weight RSI（背景微調）
- 保留人類回饋通道，以便在關鍵領域做最終把關

## 潛在風險與注意事項

**風險一：自我強化偏誤（Self-Reinforcing Bias）**
若模型在某類錯誤上高度自信，遞迴精煉可能反覆強化同一錯誤。緩解方式：
- 維持多樣性：在 In-Context RSI 中偶爾引入不同 temperature 或不同 prompt 變體
- 設定「重置」機制：當連續多輪無改善時，從頭重新生成
- 保留外部驗證：對可驗證答案的題目（數學、程式），用規則檢查取代人類判斷

**風險二：分布漂移與災難性遺忘**
反覆在自身輸出上蒸餾可能導致模型偏離原始能力。緩解方式：
- 混合原始預訓練資料的一小部分（例如 5–10%）做 replay
- 定期在保留的「金標」驗證集上評估，發現退化即停止
- 使用 LoRA 等參數高效方法，便於快速回滾

**風險三：成本失控**
雖然 In-Context RSI 降低 token 消耗，但鏈長 ℓ 增加會線性放大推論成本。緩解方式：
- 設定動態停止條件：精煉後答案與前次相同即提前結束
- 對簡單題目使用較短鏈，困難題目使用較長鏈（難度可由信心度估計）

**風險四：評估幻覺**
「最終答案正確」不等於「推理過程正確」。在教育或研究場景，需額外評估推理品質。緩解方式：
- 引入過程級獎勵模型或人類抽查
- 對數學題檢查中間步驟的一致性

**風險五：領域外推風險**
論文僅在競賽數學上驗證。應用至其他領域（醫療、法律、創意寫作）時，遞迴精煉的效益與風險模式可能不同。建議先做小規模 POC 再擴展。

## 與其他技術的整合建議

**與 RAG（檢索增強生成）整合**
In-Context RSI 的精煉鏈可與 RAG 結合：每次重解時不僅參考前次解題，也檢索新的外部證據。這對需要最新知識的領域（時事、技術文件）特別有價值。

**與 RLHF / DPO 整合**
In-Weight RSI 可作為 RLHF 的暖身步驟：先用無標籤遞迴精煉產生「自我獎勵」訊號，再以少量人類偏好資料做 DPO 對齊。這能降低對昂貴人類標註的依賴。

**與 Test-Time Compute Scaling 框架整合**
TT-RSI 與現有 test-time scaling 方法（如 best-of-n、tree search）並非互斥。可設計混合策略：先用 SC 產生多樣候選，再以 In-Context RSI 對 top-k 候選做精煉，最後用 In-Weight RSI 把整體改進蒸餾回模型。

**與 Agent 框架整合**
在多步代理任務中，可將 TT-RSI 視為「自我反思」機制：每個子任務完成後，代理以自身軌跡為參考重做，逐步修正規劃錯誤。

**與監控與可觀察性整合**
部署時應將精煉鏈全程記錄（包含被捨棄的中間步驟），供事後稽核與除錯。這也是相較於 SC 的額外優勢——SC 只保留最終答案，TT-RSI 保留了完整的推理演進。
