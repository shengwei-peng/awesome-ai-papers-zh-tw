## 摘要翻譯

思維鏈推理（Chain-of-Thought reasoning）透過使大型語言模型（LLMs）得以在回答前將問題拆解為中間步驟（intermediate steps），革新了自然語言處理。然而，將推理侷限於文字領域，對於需要直接操作視覺表徵（visual representations）的任務而言仍有其侷限。近期研究透過外部視覺專家工具（external visual expert tools），如深度估計（depth estimation）或物件偵測（object detection）模組，來增強多模態大型語言模型（MLLMs），但這類方法在本質上仍受限於狹隘且僵化操作（rigid operations），無法靈活生成或轉換視覺內容。我們提出 ReImaGin，其利用圖像生成模型（image generation models）作為多模態大型語言模型（MLLMs）的靈活視覺推理機制（flexible visual reasoning mechanism）：不同於固定功能工具（fixed-function tools），圖像生成模型接受自然語言指令（natural language commands），並可執行開放式視覺操作（open-ended visual operations），例如移除遮蔽（removing an occlusion），或從一個房間的多個互不相連視角生成平面圖（floorplan）。在包含多視角空間推理（multi-view spatial reasoning）與碰撞預測（collision prediction）在內的六項多樣化視覺推理任務中，ReImaGin 始終優於純文字推理（text-only reasoning）與專業視覺工具基線（specialist vision-tool baselines），提升幅度高達 25%（gains of up to 25%），展現了靈活且生成式視覺推理（flexible, generative visual reasoning）的優勢。

### 核心貢獻（3～5點）
- 指出純文字思維鏈推理在處理需直接操作視覺表徵的任務時存在侷限。
- 提出 ReImaGin，以圖像生成模型作為靈活視覺推理機制，能接受自然語言指令並執行開放式視覺操作。
- 在六項多樣化視覺推理任務上，相較於純文字推理與專業視覺工具基線，提升幅度高達 25%。
- 驗證生成式視覺推理相較於固定功能視覺專家工具，在空間理解與視覺內容轉換上的靈活性優勢。

### 適合對象
多模態人工智慧、視覺推理、大型語言模型與圖像生成領域的研究人員與工程師，特別是對思維鏈推理、多模態智慧體（multimodal agent）及生成式視覺推理感興趣者。

## 深度分析

#### 方法論解析

REIMAGINE（Reasoning with Image Generation）的核心主張是將「指令微調圖像生成模型（instruction-tuned image generation model）」視為一種通用視覺推理工具，而非僅把圖像生成當作最終輸出。具體而言，作者設計了一個多模態智慧體（multimodal agent），讓多模態大型語言模型（MLLMs）在進行文字思維鏈（Chain-of-Thought, CoT）推理的過程中，能夠隨時呼叫 `generate_image` 工具，把自然語言指令轉換成視覺中間結果（visual intermediate），再將該結果放回智慧體的上下文（context）中繼續推理。

與先前工具增強式 MLLM（如 Visual Sketchpad）依賴一組固定功能工具（fixed-function tools）——例如深度估計（depth estimation）、物件偵測（object detection）、分割（segmentation）或裁切（cropping）——不同，`generate_image` 是一個單一但開放式的生成介面。只要能用自然語言描述，它就能執行多樣的視覺操作（open-ended visual operations），例如移除遮蔽（removing an occlusion）、從多張不連續房間視角生成平面圖（floorplan）、畫出移動物體的軌跡線以預測碰撞等。這種設計讓同一個模型可以跨任務使用，無需針對每個任務重新訓練或新增專門模組。

在實作層面，REIMAGINE 讓智慧體在一個 Python 環境中運作，除了 `generate_image` 之外，也可使用傳統程式化圖像工具（如 crop、overlay、subtract、numpy 等）進行後處理。這意味著生成模型負責「靈活且開放式的視覺轉換」，而程式化工具則負責精確、可重複的幾何或像素層級操作，兩者互補。整個推理過程發生在可解釋的像素空間（interpretable pixel space），而非難以理解的潛在空間（latent space），這對除錯與驗證推理鏈非常有利。

另一個重要貢獻是「自動發現視覺推理策略」的機制。由於 `generate_image` 接受任意自然語言指令，關鍵問題變成：對於特定任務，什麼樣的視覺轉換才真正有幫助？傳統做法仰賴手工設計的情境內範例（hand-crafted in-context examples）來指定策略，但這需要大量人工且限制泛化（generalization）。REIMAGINE 提出一個迭代迴圈：由一個提案模型（proposal model）生成候選提示（prompts），在小型開發集（development set）上評估成效，再根據成功與失敗案例進行修正。這把「策略發現」問題轉化為「提示優化（prompt optimization）」問題，讓系統有機會自動找出類似人類設計的視覺化策略。

#### 實驗數據解讀

論文在六個差異甚大的視覺推理任務上進行評估，包括深度感知（depth perception）、視覺拼圖完成（visual puzzle completion）、部分遮蔽下的計數（counting under partial occlusion）、碰撞預測（collision prediction）、多視角空間推理（multi-view spatial reasoning），以及作者自行提出的路徑追蹤任務（path tracing）。值得注意的是，所有任務都使用同一個圖像生成模型作為工具，沒有進行任何任務特定專門化（task-specific specialization），這強調了 REIMAGINE 的通用性。

實驗結果顯示，REIMAGINE 在手動設計策略（handcrafted strategies）設定下，持續優於兩種基線：純文字推理（text-only reasoning）與使用固定視覺專家工具（specialist vision-tool baselines）的 Visual Sketchpad。具體來說，在路徑追蹤任務上提升高達 25%，在部分遮蔽計數任務上相對提升達 40%。這些數字說明，當任務需要空間或物理直覺（spatial or physical intuition）時，僅靠把視覺輸入（visual inputs）轉成文字描述再進行邏輯推理是不足的；而生成式視覺中間結果能夠直接補足這些直覺缺口。

自動發現策略（automatically discovered strategies）的實驗則呈現出更有趣的現象：自動優化出的提示往往與人類設計的策略相似，例如「從移動物體前端畫出箭頭來預測碰撞」。這暗示 MLLM 對於「什麼樣的視覺轉換有助於什麼任務」具備某種有用的先驗知識（useful priors）。然而，自動策略通常只能恢復手工策略的大部分成效，在需要更複雜視覺推理政策（elaborate visual reasoning policies）的任務上仍存在差距。這也指出提示優化雖然能減少人工，但尚未完全取代人類對任務結構的深入理解。

從方法論與實驗設計來看，作者並未過度宣稱生成模型能完美執行所有指令；相反地，他們強調的是「靈活性」與「可擴展性」——隨著視覺生成（visual generation）技術進步，REIMAGINE 能夠執行的推理操作範圍也會自然擴大。這是一個重要的定位：它不是一個針對特定任務調校的專家系統，而是一個隨基礎模型能力成長的通用框架。

#### 與現有研究的比較

REIMAGINE 與現有研究的區別可以從三個層面來理解：工具性質、訓練需求與推理空間。

第一，在工具性質上，先前工作如 Visual Sketchpad 與相關方法為 MLLM 配備固定視覺專家工具（visual expert tools），例如裁切、深度估計、物件偵測或分割。這些工具雖然可靠，但只能執行預定義操作，無法進行生成式或複雜轉換（例如想像場景的替代視角、合成平面圖）。REIMAGINE 以單一指令微調圖像生成模型取代這些狹隘模組，讓智慧體能夠透過自然語言指令執行開放式視覺操作。

第二，在訓練需求上，部分近期研究雖然也嘗試使用生成式或潛在視覺模型進行推理，但往往需要任務特定訓練（task-specific training）、聚焦單一狹隘領域，或在非解釋性的潛在空間中運作。REIMAGINE 強調其為無需訓練（training-free）且模組化（modular）的框架：它直接呼叫現成的圖像生成模型，在可解釋的像素空間中進行視覺推理，並在六個不同任務上驗證通用性。

第三，在策略指定方式上，傳統工具增強方法通常需要手工設計情境內範例來教導模型何時、如何使用工具，這不僅耗費人力，也限制對新任務的泛化。REIMAGINE 透過自動提示優化探索策略發現，雖然目前仍無法完全追上手工策略，但已展現出減少人工介入的潛力。

然而，REIMAGINE 也有其限制。首先，它的成效高度依賴底層圖像生成模型的能力與指令遵循準確度；若生成模型誤解自然語言指令或產生幻覺（hallucination），後續推理將建立在錯誤的視覺中間結果上。其次，生成式工具雖然靈活，但在需要精確幾何量測的任務上，可能不如專門的深度估計或物件偵測模組穩定。第三，自動策略發現目前仍依賴小型開發集與提示優化，對於需要多步驟、長程視覺推理的複雜任務，搜尋空間可能過大。最後，論文尚未詳細討論計算成本：反覆呼叫圖像生成模型進行推理，無論在時間還是資源上都遠比純文字推理昂貴。

此外，REIMAGINE 的成效與所使用的指令微調圖像生成模型密切相關。論文引用了 DeepMind（2025）、Black Forest Labs（2025）與 Wu et al.（2025）等近期生成模型，但並未清楚說明實際使用的是哪一個模型版本、其參數規模、取樣參數（如 inference steps、guidance scale）以及 API 或本地部署方式。這些細節對於重現實驗至關重要，因為生成模型的輸出品質對最終任務表現影響極大。

總體而言，REIMAGINE 作為一個概念新穎且實驗廣泛的框架，若能配合開源程式碼、資料集建構說明與模型配置細節，將大幅提升其對學術界的影響力與可驗證性。

#### 未來研究方向

REIMAGINE 開啟了「以圖像生成進行推理（reasoning with image generation）」這條研究路線，未來可以從以下幾個方向延伸：

1. **更強大且可控的生成模型整合**：隨著視覺生成技術進步，未來可探索更精確遵循空間關係與物理規則的生成模型，以減少幻覺並提升幾何一致性。同時，可結合區域控制、佈局條件或 3D 條件生成，讓 `generate_image` 在複雜場景中更具可靠性。

2. **自動策略發現的強化**：目前的提示優化迴圈可進一步結合強化學習（reinforcement learning）、蒙特卡洛樹搜尋（MCTS）或大型語言模型自我反思機制，讓智慧體能夠在更廣泛的視覺操作空間中發現多步驟推理策略，而不僅限於單一提示微調。

3. **生成式工具與符號式工具的混合架構**：未來可設計一個能夠動態選擇「生成式工具」與「傳統專家工具」的智慧體。對於需要精確量測的步驟使用深度估計或物件偵測，對於需要想像與合成的步驟則使用 `generate_image`，達到靈活性與準確性的平衡。

4. **多輪視覺推理與錯誤修正**：目前框架主要將生成圖像作為中間結果供模型檢視。未來可讓智慧體主動比較多個生成結果、偵測不一致性並進行修正，形成更穩健的多輪視覺推理迴圈。

5. **標準化視覺推理基準**：為了推動此領域發展，需要建立更全面的基準測試，涵蓋空間推理、物理模擬、因果推理與多視角合成等面向，並提供明確的評估指標與人類表現上限。

6. **效率與可擴展性**：反覆呼叫圖像生成模型成本高昂，未來可研究如何壓縮生成步驟、使用輕量級生成模型進行草稿式推理，或開發專門針對推理任務的視覺生成模型，以降低延遲與運算資源。

7. **理論理解與可解釋性**：深入分析為何某些視覺轉換能幫助特定任務、MLLM 的視覺先驗來自何處，以及生成中間結果如何改變模型的注意力與決策過程，將有助於設計更可靠的視覺推理系統。

## 論文問答

**Q1：現有多模態大型語言模型在視覺推理上存在什麼根本問題？**

A：現有大多數多模態框架將「推理」侷限在文字領域，僅把視覺輸入轉換成語言描述後再進行邏輯處理。這種以文字為中心的方法雖然對部分任務有效，但對需要空間或物理直覺的問題並不適用，例如想像移除遮蔽後的場景或合成新視角。因此，純文字推理難以直接操作視覺表徵，限制了模型處理複雜視覺任務的能力。

**Q2：為什麼傳統的外部視覺專家工具無法滿足開放式視覺推理需求？**

A：傳統方法常為多模態大型語言模型配備固定功能工具，例如裁切、深度估計、物件偵測或分割模組。這些工具只能執行預先定義好的狹隘操作，無法進行靈活、生成式或複雜的圖像轉換，例如想像場景的替代視角或根據多張照片合成平面圖。此外，這些工具通常需要人工設計情境內範例來教導模型使用，增加了手動成本並限制了對新任務的泛化能力。

**Q3：為何靈活的視覺推理機制對需要空間直覺的任務特別重要？**

A：許多視覺任務本質上需要對空間關係、物理動態或幾何結構進行直覺式操作，而非單靠語言描述就能解決。例如碰撞預測需要追蹤物體軌跡，多視角空間推理需要整合不同視角的資訊，而部分遮蔽下的計數則需要補全被擋住的物體。若模型能直接生成並檢視視覺中間結果，就能將這些空間與物理直覺外顯化，從而提升推理的正確性與可解釋性。

**Q4：ReImaGin 的核心方法與過去工具增強型多模態模型有何不同？**

A：ReImaGin 是一個多模態智慧體，它在文字思維鏈推理的過程中，交錯呼叫一個指令微調的圖像生成模型作為通用工具。不同於 Visual Sketchpad 等依賴多個固定專家模組的方法，ReImaGin 僅使用單一個 `generate_image` 工具，就能透過自然語言指令執行開放式視覺操作。這種設計讓同一個生成模型可以同時扮演分割、深度估計、視角合成等多種角色，並能完成過去專業工具無法達成的任意視覺轉換。

**Q5：`generate_image` 工具在推理循環中如何運作？**

A：智慧體在進行文字思維鏈推理時，可以在任何中間步驟以自然語言提示呼叫 `generate_image`，並將生成的視覺中間結果直接納入後續上下文。例如在碰撞預測任務中，模型可能要求生成一張畫出移動物體軌跡線的圖片，再檢視該線條最先與哪個物體相交。由於提示是自由形式的，同一個工具可以根據不同任務需求產生深度圖、移除遮蔽、合成平面圖或繪製輔助箭頭等多元視覺化結果。

**Q6：ReImaGin 如何自動發現有效的視覺推理策略？**

A：由於視覺轉換策略是透過提示傳達給智慧體，因此自動發現策略可轉化為提示最佳化問題。論文設計了一個迭代循環：提案模型先產生候選提示，再於小型開發集上評估其效果，最後根據成功與失敗案例進行修正。這種方法無需人工設計範例，且自動發現的策略常與人類設計的策略相似，例如從移動物體前端畫箭頭來預測碰撞，顯示多模態大型語言模型對何種視覺轉換有助於任務具備有用的先驗知識。

**Q7：論文在哪些視覺推理任務上評估 ReImaGin？**

A：論文選用了六個多樣化的視覺推理任務，包括深度感知、視覺拼圖補全、部分遮蔽下的計數、碰撞預測、多視角空間推理，以及作者自行提出的路徑追蹤任務。這些任務涵蓋了幾何理解、空間整合、動態預測與遮蔽推理等不同挑戰。值得注意的是，同一個圖像生成模型在所有任務中都被當作通用工具使用，沒有針對任何任務進行特定專門化。

**Q8：ReImaGin 相較於基線方法取得了哪些主要量化結果？**

A：ReImaGin 在六個任務中一致優於純文字推理以及使用固定視覺專家工具的 Visual Sketchpad 基線。具體而言，在路徑追蹤任務上提升高達 25%，在部分遮蔽計數任務上相對提升達 40%。這些結果顯示，以生成式模型作為靈活視覺推理機制，能顯著超越依賴僵化操作的傳統視覺工具。

**Q9：自動發現策略與人工設計策略的比較揭示了什麼？**

A：自動發現的策略通常能恢復大部分人工設計策略所帶來的效能增益，且經常與人類會設計的策略相似，例如畫出軌跡線或箭頭來輔助推理。這表示多模態大型語言模型本身具備關於哪些視覺轉換對特定任務有幫助的內在知識。然而，在需要更精緻視覺推理策略的任務上，自動發現策略與人工設計策略之間仍存在一定差距。

**Q10：ReImaGin 在哪些實際應用場景中最具潛力？**

A：ReImaGin 可應用於機器人導航中的空間規劃、自動駕駛中的碰撞預測、建築設計中的平面圖合成，以及醫學影像或工業檢測中的遮蔽補全與異常視覺化。由於它只需要自然語言指令就能執行多種視覺操作，開發者無需為每個新任務建置專屬的電腦視覺模組。這種通用性特別適合快速變動或需求多元的應用場景，能大幅降低系統整合與維護成本。

**Q11：在產品化或工程部署上，使用生成式圖像工具需要考慮哪些問題？**

A：首先，生成模型可能產生幻覺或不準確的視覺中間結果，導致後續推理出錯，因此需要設計驗證或回饋機制來確保品質。其次，生成圖像需要額外的計算資源與延遲，對於即時應用必須進行效率優化或快取策略。最後，提示的設計與最佳化會直接影響工具效果，產品團隊需要持續監控並迭代提示，以適應不同使用者情境與資料分佈。

**Q12：這項研究可能如何影響多模態推理領域的未來發展？**

A：ReImaGin 將視覺生成模型從「最終輸出工具」重新定位為「推理過程中的中間媒介」，開啟了以生成進行推理的新範式。這可能促使未來研究更關注如何讓模型在像素空間中進行可解釋的視覺思考，而非僅依賴語言描述。隨著圖像生成模型能力持續提升，這種靈活的視覺推理機制將能自動擴展到更多任務，進一步模糊感知、生成與推理之間的界線。

**Q13：論文承認自動策略發現存在哪些限制？**

A：雖然自動發現策略在多數任務上能逼近人工設計策略，但在需要更複雜或多步驟視覺推理政策的任務上，兩者之間仍有差距。這表示目前的提示最佳化方法尚無法完全捕捉精細的人類設計經驗。此外，自動探索需要額外的開發集與迭代計算成本，對於資料稀少或評估昂貴的任務可能較難直接套用。

**Q14：使用圖像生成作為推理工具有哪些潛在的失敗案例或風險？**

A：生成模型可能誤解自然語言指令，產生與預期不符的視覺中間結果，例如錯誤的軌跡方向或不符合幾何一致性的平面圖。由於智慧體會把這些生成結果當成事實繼續推理，錯誤的圖像可能會被放大並導致最終答案錯誤。此外，生成模型本身可能存在訓練資料偏誤，對少見場景或細微空間關係的表現不穩定，進而影響整體系統的可靠性。

**Q15：未來研究可以朝哪些方向延伸這項工作？**

A：未來可以探索更強大的提示最佳化演算法，以縮短自動發現策略與人工設計策略之間的差距，並減少所需的開發資料量。另一個方向是結合多個生成工具或引入回饋機制，讓智慧體能檢查並修正生成結果，形成更穩健的視覺推理循環。此外，將這種以生成進行推理的框架擴展到影片、三維場景或其他模態，也有望進一步提升模型在真實世界複雜任務上的推理能力。

## 實務應用指南

### 適用場景

1. **室內設計與房地產空間規劃**  
   使用者上傳多張不同角度的房間照片，系統透過 `generate_image` 生成平面圖、去除家具遮蔽或合成虛擬裝潢後的視角，協助客戶與設計師快速理解空間關係。

2. **自動駕駛與機器人碰撞預測**  
   在動態場景中，模型可生成物體軌跡線或移除遮蔽物以推論潛在碰撞點，輔助決策系統判斷煞車或迴避時機。

3. **工業檢測與維修輔助**  
   針對設備內部或管線影像，利用自然語言指令生成「移除外殼後的內部結構圖」或「標示異常區域的視覺化結果」，降低專業人員判讀負擔。

4. **教育與科學視覺化**  
   學生或教師輸入物理、幾何或生物問題，系統生成輔助圖像（如光路圖、立體展開圖、去除遮蔽的解剖圖），將抽象推理轉為可視覺化解釋。

5. **零售與電商商品展示**  
   根據多張商品局部照片生成去背、去遮蔽或 360 度合成視圖，提升消費者對產品外觀與尺寸的空間理解。

### 實作前置條件

**資料需求**
- 原始視覺輸入：高品質影像或連續影格，解析度需足以支撐下游任務細節判讀。
- 任務相關文字描述或問題：用於驅動 `generate_image` 的自然語言指令與最終回答。
- 小型開發集（development set）：若採用自動化策略發現，需要數十至數百筆帶標籤樣本以評估與篩選提示詞。

**運算需求**
- 可呼叫的指令微調圖像生成模型 API 或本地部署版本（如 FLUX、Imagen 等級模型）。
- 多模態大型語言模型（MLLM）推論環境，支援交錯文字與圖像上下文。
- 基礎 Python 執行環境，可執行裁切、疊加、數值運算等輔助工具。

**技能需求**
- 熟悉提示工程（prompt engineering）與 MLLM 工具呼叫設計。
- 具備基礎電腦視覺與圖像處理知識，能評估生成圖像品質。
- 若進行自動策略發現，需了解迭代式提示優化流程與評估指標設計。

### 實作步驟建議

1. **任務拆解與視覺化策略設計**  
   先分析問題是否需要空間或物理直覺，決定哪些中間步驟適合生成圖像（例如：去遮蔽、畫軌跡線、合成平面圖）。

2. **建構 `generate_image` 工具介面**  
   為 MLLM 提供可自由呼叫的圖像生成函式，讓模型在思維鏈推理過程中依需求產生視覺中間結果，並將結果回傳至上下文。

3. **撰寫手工設計的情境內範例（hand-crafted in-context examples）**  
   針對目標任務設計 1–3 組示範，展示何時呼叫 `generate_image`、提示詞如何撰寫，以及如何根據生成圖像繼續推理。

4. **建立評估基線**  
   同時測試純文字推理與固定功能工具（如深度估計、物件偵測）基線，量化視覺生成帶來的效益。

5. **（選用）自動化策略發現**  
   若任務規模大或人工設計困難，可建議提示詞提案模型，在開發集上迭代生成、評估、篩選提示詞，逐步逼近有效策略。

6. **產品化與錯誤處理**  
   加入生成圖像品質檢查、重試機制與人類回饋迴路，並將視覺中間結果以可解釋方式呈現給終端使用者。

### 潛在風險與注意事項

| 風險 | 說明 | 因應方式 |
|---|---|---|
| **生成圖像幻覺** | 圖像生成模型可能產生不符合真實場景的細節，導致錯誤推理。 | 結合原始影像進行交叉驗證，並對關鍵決策保留人類確認機制。 |
| **提示詞敏感度高** | 自然語言指令的細微差異可能大幅影響生成結果。 | 建立提示詞版本管理與 A/B 測試流程，必要時使用自動化策略發現。 |
| **運算成本與延遲** | 每次推理可能呼叫多次圖像生成，成本與回應時間較高。 | 設立快取機制，對常見視覺操作預先生成模板，並限制每題呼叫次數。 |
| **可解釋性不足** | 生成圖像作為中間結果，可能難以追溯錯誤來源。 | 記錄完整思維鏈與對應生成圖像，提供可視化稽核介面。 |
| **資料隱私與版權** | 上傳影像與生成結果可能涉及個人隱私或智慧財產權議題。 | 採用符合法規的資料處理流程，並在使用者協議中明確說明生成內容用途。 |

### 與其他技術的整合建議

- **與固定視覺專家工具互補**：對於需要精確數值的任務（如深度估計、物件偵測邊界框），可先使用傳統視覺模型取得結構化資訊，再由 `generate_image` 進行開放式視覺轉換與綜合推理。

- **與檢索增強生成（RAG）結合**：在設計、維修或教育場景中，將生成圖像與領域知識庫連結，讓模型根據檢索到的規範或範例生成更符合情境的視覺化結果。

- **與互動式前端整合**：將 `generate_image` 產生的視覺中間結果即時呈現給使用者，並允許使用者以自然語言修正指令，形成人機協作的視覺推理迴路。

- **與模擬器或數位孿生系統對接**：在自動駕駛或機器人應用中，可將生成結果輸入物理模擬器進行驗證，降低單純依賴生成模型進行決策的風險。
