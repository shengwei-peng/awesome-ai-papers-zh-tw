# SKT（Skill-Use Training）：透過經驗證的合成資料生成（Verified Synthetic Data Generation）實現大規模技能使用訓練

**原文標題：** SKT: Skill-Use Training at Scale via Verified Synthetic Data Generation

## ⚡ TL;DR

現有語言模型智慧體難以有效識別、應用與協調各項技能。
本文提出 SKT，透過規則與智慧體驗證及回饋修復，合成基於技能的可執行訓練軌跡。
以兩千項公開技能生成四千任務與兩萬七千多條驗證軌跡，監督式微調顯著提升跨基準與框架的技能使用表現。

---

## 摘要翻譯

智慧體技能（Agent Skill）已成為為語言模型智慧體（Language-Model Agent）配備可重複使用的程序性知識（Reusable Procedural Knowledge）的重要機制。然而，僅提供技能並無法保證當前模型能有效識別、應用與協調它們。為了提升技能使用能力，我們提出 SKT（Skill-Use Training），一個經驗證的合成資料生成（Verified Synthetic Data Generation）流程，能從大量智慧體技能中建立基於技能的任務（Skill-Grounded Task）與可執行軌跡（Executable Trajectory）。SKT 選取適當的單技能配置（Single-Skill Configuration）與多技能配置（Multi-Skill Configuration），透過基於規則的驗證（Rule-Based Verification）與基於智慧體的驗證（Agent-Based Verification），並輔以回饋引導修復（Feedback-Guided Repair）來合成任務，且僅保留成功且實質運用每項所需技能的軌跡。利用 2,000 項公開技能，SKT 產生了 4,000 個任務套件（Task Package）與 27,164 條經驗證的軌跡。基於相同的流程與一個互不相交的測試池，我們進一步建構了 SkillEval，一個用於評估技能使用的保留的可執行基準測試（Held-Out Executable Benchmark）。跨越多樣模型、基準測試與智慧體測試框架（Agent Harness）的實驗顯示，在 SKT 生成的軌跡上進行監督式微調（Supervised Fine-Tuning, SFT），能一致地提升技能使用表現。驗證消融實驗（Verification Ablation）、跨框架評估（Cross-Harness Evaluation）與擴展實驗（Scaling Experiment）進一步證明，這些成效仰賴高品質的監督訊號、不僅限於單一智慧體介面，並會隨著更廣泛的技能涵蓋範圍（Skill Coverage）而提升。綜合而言，這些結果確立了經驗證的合成資料生成作為技能使用訓練的一種有效且可擴展的方法。

### 核心貢獻（3～5點）
- 提出 SKT（Skill-Use Training），一個從大量公開智慧體技能自動合成基於技能的任務與可執行軌跡的經驗證資料生成流程。
- 設計結合基於規則與基於智慧體的驗證，以及回饋引導修復的機制，確保合成軌跡確實且成功地使用每項所需技能。
- 建構 SkillEval，一個與訓練資料互不相交的保留可執行基準測試，用於評估語言模型智慧體的技能使用能力。
- 透過跨模型、跨基準測試與跨智慧體測試框架的實驗，證明在 SKT 資料上進行監督式微調能一致提升技能使用表現，且成效隨技能涵蓋範圍擴大而提升。

### 適合對象
本論文適合對大型語言模型智慧體、技能學習與合成資料生成有興趣的研究人員與工程師，特別是關注如何透過可驗證程序提升智慧體工具使用、多技能協調能力，以及希望建構可擴展訓練資料的實務工作者。

## 深度分析

#### 方法論解析

##### 核心問題與整體框架

本文提出的 **SKT（Skill-Use Training，技能使用訓練）** 針對的是「公開技能（Agent Skill）數量爆炸，但語言模型智慧體（Language-Model Agent / LLM-based Agent）未必能有效識別、應用與協調技能」的現象。與過去研究多聚焦於「如何檢索、內化或創造技能」不同，SKT 將重點放在 **如何讓模型學會使用既有技能（skill-use capabilities）**。其核心做法是：從公開技能倉庫（Public Skill Repository）中篩選出高品質、具多樣性且可組合的技能，自動合成 **基於技能的任務（Skill-Grounded Task）**，並透過可執行驗證產生 **可執行軌跡（Executable Trajectory）**，最後以這些經驗證的軌跡進行 **監督式微調（Supervised Fine-Tuning, SFT）**。

整個流程可拆解為四個階段：

1. **技能策展與候選技能池（Candidate Skill Pool）建構**  
   從公開技能生態系統（Skill Ecosystem）中取得約 2,000 個公開技能，並依據品質、領域多樣性與 **可組合性（Composability）** 進行篩選。此處的「可組合性」是關鍵：SKT 不僅需要單一技能能獨立運作，還要能找出可協同解決複雜任務的 **互補技能（Complementary Skill）** 組合。

2. **任務合成：單技能與多技能配置（Single-Skill / Multi-Skill Configuration）**  
   根據選定的技能配置，SKT 自動生成對應的 **任務套件（Task Package）**。任務難度經過 **可控複雜度（Controlled Complexity）** 設計，從僅需單一技能（Single-Skill Configuration）的基礎情境，到需要多項技能協調（Multi-Skill Configuration）的複合情境。每個任務套件不僅包含結化任務描述，也包含參考解答與驗證機制，以確保任務可解（solvability）且可驗證（verifiability）。

3. **雙重驗證與回饋引導修復（Feedback-Guided Repair）**  
   任務與軌跡的正確性由兩類驗證機制把關：
   - **基於規則的驗證（Rule-Based Verification）**：利用預設規則檢查任務規格、輸入輸出格式、技能使用條件等是否符合 **操作限制（Operational Constraint）**。
   - **基於智慧體的驗證（Agent-Based Verification）**：讓智慧體在 **智慧體執行環境（Agent Harness）** 中實際執行任務，根據執行結果判斷軌跡是否成功。  
   當驗證失敗時，系統會將錯誤回饋用於 **回饋引導修復（Feedback-Guided Repair）**，反覆修正任務描述、技能組合或執行軌跡，直到產出可接受的訓練樣本。

4. **軌跡篩選與監督式微調**  
   SKT 透過強大的 LLM 在互動環境中收集執行軌跡，但只保留「成功執行」且「確實使用了每一項所需技能」的軌跡。這種篩選條件確保模型學到的不是捷徑解（shortcut solutions），而是 **忠實技能使用（faithful skill utilization）** 的示範。最終以這些軌跡對 Qwen3.5-9B 與 Gemma4E4B-IT 等模型進行 SFT。

##### SkillEval 的建構邏輯

除了訓練資料，作者還利用相同管線與 **不相交的保留技能池（held-out skill pool）** 建構了 **SkillEval**，這是一個 **保留的可執行基準測試（Held-Out Executable Benchmark）**。其重要性在於：測試技能與訓練資料完全無重疊，因此能更真實地評估模型是否學會了「使用新技能」的泛化能力，而非僅記住訓練中見過的特定技能內容。

#### 實驗數據解讀

##### 資料規模與模型設定

根據摘要與引言，SKT 從 2,000 個公開技能產出：

- **4,000 個任務套件（Task Package）**
- **27,164 條經驗證的可執行軌跡（Verified Trajectory）**

這個數量級顯示該方法具備一定規模化潛力：平均每個技能約對應 2 個任務套件、13–14 條軌跡。訓練對象選用 **Qwen3.5-9B** 與 **Gemma4E4B-IT**，兩者皆為近期較小參數量的開放權重模型，這樣的選擇有助於驗證「SKT 對中等規模模型也有效」，並降低實驗成本。

##### 評測基準與跨框架設計

實驗在四大基準上進行：

1. **SkillsBench**：衡量 curated skills 的邊際價值，透過有無技能配對執行來評估。
2. **MolBench-Bind**
3. **AgentSkillOS-bench**：聚焦於技能檢索（Skill Retrieval）與使用。
4. **SkillEval（本文提出）**：保留技能池上的可執行評測。

此外，作者進行了 **跨框架評估（Cross-Harness Evaluation）**，即在不同 **智慧體測試框架（Agent Harness）** 上測試同一模型。這點特別重要：許多現有研究只在單一執行環境中驗證，而 SKT 強調學到的技能使用能力能 **超越單一智慧體介面（agent interface）**，顯示模型學到的是較通用的程序性知識（Procedural Knowledge），而非特定環境的表層指令。

##### 結果意涵

雖然具體數值在提供的上下文中未完整呈現，但摘要明確指出：

- **SFT 後模型在技能使用表現上持續提升**：這說明經驗證的合成軌跡確實提供了有效的監督訊號。
- **驗證消融實驗（Verification Ablation）** 顯示成效依賴高品質監督：移除或簡化驗證機制會削弱最終表現，印證了「僅合成任務不夠，必須確保軌跡正確且忠實使用技能」的設計理念。
- **擴展實驗（Scaling Experiment）** 顯示隨著 **技能涵蓋範圍（Skill Coverage）** 擴大，模型表現持續提升。這暗示 SKT 具有正向規模效應：更多樣化的技能組合能帶來更強的泛化與組合能力。

整體而言，實驗設計從「資料品質」、「跨環境泛化」、「規模化趨勢」三個維度支撐了 SKT 的有效性。

#### 與現有研究的比較

##### 與「學習與演化外部技能」研究的區別

近期研究如 **SAGE（Wang et al., 2025）**、**SkillRL（Xia et al., 2026）**、**Skill1（Shi et al., 2026）** 與 **Skill-R1（Vishe et al., 2026）** 主要關注如何讓智慧體在互動過程中創造、編輯或累積技能。這類工作將技能視為可持續更新的外部記憶（external memory）。相較之下，**SKT 並不創造新技能，而是假設技能已存在，並專注於訓練模型正確使用它們**。兩者可視為互補：SKT 可讓模型更好地利用由 SAGE 或 SkillRL 產出的技能庫。

##### 與「技能內化（Skill Internalization）」研究的區別

**SKILL0（Lu et al., 2026）**、**SkillC（Lin et al., 2026）**、**SIRI（He et al., 2026）** 與 **Skill0.5（Zhu et al., 2026a）** 嘗試將外部技能轉化為模型內部能力，最終減少對外部技能文件的依賴。這類方法的核心是「暫時使用技能作為訓練鷹架」。SKT 則保留外部技能的存在，並強化模型在執行階段識別與協調技能的能力。換言之，SKILL0 系列問的是「如何讓模型不再需要技能文件」，SKT 問的是「如何讓模型在有技能文件時真正會用」。

##### 與「參數化技能表徵（Parameterized Skill Representations）」研究的區別

**Skill-to-LoRA（Zhang & Qi, 2026）**、**Latent Skill（Yu et al., 2026）** 與 **ParametricSkills（Zhao et al., 2026）** 將技能壓縮成 LoRA 權重或超網路（hypernetwork）輸出，屬於權重空間（weight-space）方法。SKT 則停留在資料空間（data-space）：透過合成高品質軌跡進行 SFT，不改變技能表徵形式，也不為每個技能訓練專屬參數。這使 SKT 更易與現有技能生態系統整合，因為它不需要重新設計技能的儲存或載入機制。

##### 與「Agent Skill 評測」研究的關係

**SkillsBench（Li et al., 2026b）** 提供了衡量技能邊際價值的框架，而 **AgentSkillOS-bench（Li et al., 2026a）** 聚焦於技能檢索。SKT 在這些基準上進行評測，並額外提出 **SkillEval**，補充了「保留技能池上的可執行評測」這一缺口。相較於靜態問答式評測，SkillEval 強調實際執行與驗證，更接近真實智慧體部署情境。

##### 主要貢獻與限制

**主要貢獻**：
- 明確區分「技能存在」與「技能使用」兩個問題，填補了現有文獻中對後者的關注不足。
- 提出可規模化的經驗證合成資料管線，並同時支援訓練與基準建構。
- 透過跨框架與擴展實驗，證明所學能力具有泛化性與規模效應。

**潛在限制**（根據現有上下文推論）：
- 軌跡由「強大的 LLM」產生，若該教師模型本身對某些技能理解有偏，錯誤可能透過驗證機制殘留並傳遞給學生模型。
- 驗證機制雖結合規則與智慧體執行，但對於需要主觀判斷或開放式輸出的任務，可能難以設計完善的驗證器。
- 實驗主要集中於 9B 等級模型，對於更大規模模型（如 70B+）或閉源模型的效益尚需更多驗證。
- 目前上下文未提供各基準的絕對分數與標準差，難以判斷提升幅度是否具統計顯著性。

#### 可重現性評估

##### 公開資源現況

根據提供的上下文，本文並未明確說明是否釋出：

- 原始程式碼（source code）
- 合成的 4,000 個任務套件與 27,164 條軌跡資料集
- 微調後的模型權重（fine-tuned model weights）
- SkillEval 基準的完整測試集與驗證器

因此，從可重現性角度來看，目前只能確認研究使用了 **2,000 個公開技能** 與多個公開基準（SkillsBench、MolBench-Bind、AgentSkillOS-bench）。若作者未進一步釋出 SKT 管線實作與合成資料，其他研究者將難以完全複製訓練過程與數據規模。

##### 重現難點

1. **智慧體執行環境（Agent Harness）的異質性**：不同框架的 API、工具呼叫格式與狀態管理差異大，跨框架重現需要大量工程工作。
2. **教師模型與驗證器設定**：軌跡品質高度依賴所使用的強大 LLM 與驗證規則，若未公開這些細節，重現結果可能出現顯著落差。
3. **技能版本與相依性**：公開技能倉庫持續更新，2,000 個技能的確切選取標準與版本會影響任務合成結果。
4. **運算成本**：從 2,000 個技能合成數萬條軌跡並進行反覆驗證與修復，需要可觀的 LLM API 呼叫或本地運算資源。

##### 可重現性建議

若作者希望提升影響力，建議至少釋出：
- SKT 管線的開源實作（含規則驗證器與回饋修復邏輯）。
- 用於訓練與 SkillEval 的任務套件與軌跡樣本（即使非全部，也應提供代表性子集）。
- 微調後模型的檢查點（checkpoint），以便直接比較。
- 詳細的超參數、教師模型版本與智慧體環境配置。

#### 未來研究方向

##### 1. 從監督式微調延伸至強化學習

SKT 目前以 SFT 為主，未來可結合 **強化學習（Reinforcement Learning, RL）** 或 **線上學習（Online Learning）**，讓模型在執行過程中根據驗證器的回饋持續優化技能選擇與使用策略。特別是引入類似 **Skill-R1（Vishe et al., 2026）** 的 verifier-scored generation 機制，可進一步提升模型在複雜多技能任務上的穩健性。

##### 2. 動態技能檢索與組合規劃

現有流程可能預先決定技能組合，未來可研究如何讓模型在執行時 **動態檢索（Dynamic Retrieval）** 並規劃技能組合。這涉及將 SKT 與技能檢索系統（如 AgentSkillOS-bench 所評測的機制）更緊密結合，使模型能面對開放式、大規模技能生態系統。

##### 3. 多智慧體協作中的技能使用

目前 SKT 聚焦於單一智慧體使用技能，未來可擴展至 **多智慧體協作（Multi-Agent Collaboration）** 情境，研究不同智慧體如何分工、共享與協調各自持有的技能，以解決更複雜的開放式任務。

##### 4. 人機協同驗證與主觀任務擴展

對於創意寫作、設計或需要主觀判斷的任務，純自動驗證可能不足。未來可引入 **人機協同驗證（Human-in-the-Loop Verification）**，或訓練學習型驗證器（learned verifier）來評估開放式輸出品質，從而擴大 SKT 的適用範圍。

##### 5. 技能使用能力的可解釋性與安全性

隨著模型被賦予更多可執行技能，理解其「為何選擇某技能」、「是否誤用高風險技能」變得重要。未來可發展 **可解釋性（Interpretability）** 工具與 **安全對齊（Safety Alignment）** 機制，確保模型不會因錯誤的技能組合而產生有害或不可逆的操作。

##### 6. 更大規模與跨語言技能生態系統

目前實驗以 2,000 個公開技能與 9B 模型為主，未來可探索：
- 將技能規模擴展至數萬甚至數十萬個，檢驗規模效應是否持續。
- 在中文、英文及其他語言的技能生態系統中驗證 SKT 的跨語言泛化能力。
- 與 **參數化技能表徵（Parameterized Skill Representations）** 方法結合，同時享有資料空間訓練與權重空間效率的優勢。

##### 7. 開放科學與社群驅動的基準

SkillEval 作為新基準具有潛力，但未來需要社群持續貢獻更多保留技能與任務，並建立標準化的提交與評測平台，才能成為衡量智慧體技能使用能力的長期參考標準。

## 論文問答

**Q1：SKT 主要想解決什麼問題？為什麼單純提供 Agent Skill 並不足夠？**

A：SKT 旨在解決大型語言模型智慧體（LLM-based Agent）雖然能夠取得大量 Agent Skill，卻無法有效「使用」這些技能的問題。根據論文，公開技能倉庫中的技能數量已超過六十萬個，但技能的可取得性並不保證模型能自動辨識何時該用、如何正確執行，以及如何與其他互補技能（complementary skill）協調。因此，SKT 提出一套經驗證的合成資料生成流程，讓模型透過高品質監督式微調（SFT）學習真正的技能使用能力，而不只是擁有技能文件。

**Q2：現有的相關方法為什麼無法充分解決技能使用問題？**

A：現有研究大多聚焦於技能檢索（skill retrieval）、技能內化（skill internalization）或讓技能與策略共同演化，這些方法雖然改善了技能如何被找到或壓縮進模型，但並未直接教會模型在多元任務中理解、協調與執行技能。換句話說，它們處理的是「技能在哪裡」與「如何表示技能」，而非「何時與如何使用技能」。SKT 則填補了這個缺口，專注於生成以技能為基礎的任務（skill-grounded task）與可執行軌跡（executable trajectory），讓模型學習完整的技能使用流程。

**Q3：為什麼提升技能使用能力對整個語言模型智慧體領域很重要？**

A：隨著公開技能生態系統（skill ecosystem）快速擴張，Agent Skill 已成為擴展大型語言模型能力的重要機制，能夠封裝領域知識、程序性知識（procedural knowledge）與輔助工具。如果模型無法有效使用這些可重複使用的程序性知識，那麼再豐富的技能庫也難以轉化為實際任務表現。SKT 透過規模化的經驗證合成資料生成，讓模型學會利用這些外部資源，對於建構能適應多領域、解決複雜任務的通用智慧體具有關鍵意義。

**Q4：SKT 的核心方法流程是什麼？請說明其主要步驟。**

A：SKT 的流程可分為四個主要階段：首先從公開技能倉庫中篩選出高品質、具多樣性且可組合的候選技能池（candidate skill pool）；接著根據單技能配置（single-skill configuration）與多技能配置（multi-skill configuration）合成具有可控複雜度（controlled complexity）的基於技能的任務；每個任務都包含結化規格、參考解答與驗證機制，以確保可解性與可驗證性；最後透過強大的語言模型在智慧體測試框架（agent harness）中執行，收集並過濾出成功且確實使用到每一項所需技能的可執行軌跡，作為後續監督式微調的訓練資料。

**Q5：相較於以往的資料合成方法，SKT 的關鍵創新是什麼？**

A：SKT 的關鍵創新在於結合了基於規則的驗證（rule-based verification）、基於智慧體的驗證（agent-based verification）以及回饋引導修復（feedback-guided repair），形成一個可擴展且高品質的驗證閉環。它不僅檢查任務本身是否合理，更保留「成功執行」且「確實使用每一項必要技能」的軌跡，避免模型學到空泛或錯誤的技能調用模式。此外，SKT 還能利用相同管線與不相交的保留技能池建構 SkillEval，展現其同時支援訓練資料生成與基準測試建構的雙重價值。

**Q6：SKT 在設計上為什麼要同時包含單技能與多技能任務，並採用兩種驗證方式？**

A：單技能任務讓模型學習如何辨識並正確執行單一技能，而多技能任務則訓練模型協調多項互補技能以解決複雜問題，兩者共同覆蓋了技能使用能力的不同層次。基於規則的驗證適合快速檢查任務結構、語法與參考解答的正確性，而基於智慧體的驗證則能透過實際執行確認軌跡是否成功並符合技能的運作約束（operational constraint）。兩者互補，加上回饋引導修復，能夠在規模化生成的同時維持資料品質。

**Q7：論文在哪些基準測試上進行評估？SkillEval 與其他基準有何不同？**

A：實驗評估涵蓋了 SkillsBench、MolBench-Bind、AgentSkillOS-bench 以及論文新提出的 SkillEval 四個基準。其中 SkillEval 是透過與 SKT 相同的資料合成管線，從與訓練語料完全不相交的保留技能池（held-out skill pool）所建構出的可執行基準測試（held-out executable benchmark）。這個設計讓 SkillEval 能夠更嚴謹地檢驗模型對於未見技能的泛化能力，而不只是記憶訓練中出現過的任務模式。

**Q8：SKT 的主要實驗結果是什麼？模型在微調後有哪些具體改善？**

A：研究團隊利用 SKT 從 2,000 個公開技能中產出 4,000 個任務套件（task package）與 27,164 條經驗證的可執行軌跡，並用這些資料對 Qwen3.5-9B 與 Gemma4E4B-IT 進行監督式微調。實驗結果顯示，經過 SKT 訓練的模型在四個基準與多個智慧體測試框架上，技能使用表現都有穩定提升。這些增益來自於高品質的軌跡監督、能夠跨不同智慧體執行環境泛化，並且隨著技能涵蓋範圍（skill coverage）擴大而持續成長。

**Q9：論文中的消融實驗與擴展實驗揭示了哪些重要結論？**

A：驗證消融實驗（verification ablation）顯示，若移除或簡化 SKT 中的驗證機制，模型性能會明顯下降，證明高品質監督是成效的關鍵來源。跨框架評估（cross-harness evaluation）則指出，SKT 的效益不局限於單一智慧體測試框架，而是能夠遷移到不同的智慧體介面。擴展實驗（scaling experiment）進一步發現，隨著納入的技能與任務數量增加，模型表現持續提升，顯示 SKT 具備良好的規模化潛力。

**Q10：SKT 在實際應用中適合哪些場景？能否舉例說明？**

A：SKT 特別適合需要協調多項工具與程序性知識的複雜工作流，例如財務發票詐欺檢測、醫療資料處理、軟體開發流程或科學實驗自動化。以論文中的發票詐欺檢測為例，智慧體需要依序使用 PDF 掃描、試算表載入、模糊比對、欄位驗證與報告生成等多項技能。透過 SKT 生成的多技能任務與軌跡，模型能學會在正確時機呼叫正確技能，並按照操作限制完成端到端任務。

**Q11：若要將 SKT 落地到產品或平台中，需要考慮哪些工程與設計議題？**

A：首先必須與現有的技能生態系統或公開技能倉庫整合，並持續維護候選技能池的品質與多樣性。其次，驗證流程會帶來額外計算成本，因此需要在資料品質、生成規模與驗證開銷之間取得平衡。此外，由於不同智慧體測試框架的 API 與執行環境各異，產品化時必須確保生成的軌跡在目標框架上可執行且安全，並隨著技能更新定期重新生成與過濾訓練資料。

**Q12：SKT 對語言模型智慧體領域可能帶來什麼樣的長遠影響？**

A：SKT 將研究焦點從「如何創造或檢索技能」轉向「如何讓模型真正會用技能」，為大規模技能生態系統的實際應用鋪路。它證明了經驗證的合成資料生成是一種有效且可規模化的技能使用訓練途徑，有助於縮短專家知識與模型執行能力之間的落差。長遠來看，這可能加速通用型智慧體的發展，使其能更靈活地組合外部技能來處理真實世界中不斷變化的任務。

**Q13：論文可能承認哪些限制或潛在風險？**

A：SKT 依賴強大的語言模型來生成與執行軌跡，因此可能繼承該模型的偏誤、幻覺或錯誤行為。此外，並非所有公開技能都具備可執行性或可驗證性，對於需要外部即時資訊或高度主觀判斷的技能，現有驗證機制可能難以完整涵蓋。合成任務的分布也可能與真實世界任務存在差距，需要進一步透過真實使用者回饋或人類評估來補強。

**Q14：在哪些情況下，SKT 生成的資料或訓練後的模型可能會失敗？**

A：當技能描述本身模糊不清、技能之間的操作限制互相衝突，或任務需要超出技能文件範圍的常識推理時，模型可能無法正確判斷該使用哪些技能。對於需要極長期規劃、多步驟協調且超出軌跡長度上限的複雜組合，SKT 也可能難以生成足夠完整的監督訊號。此外，若目標執行環境與生成時使用的智慧體測試框架差異過大，則訓練軌跡可能無法順利遷移，導致實際執行失敗。

**Q15：未來可以朝哪些方向延伸或改進 SKT？**

A：未來可以將 SKT 擴展到更多元化的技能生態系統，包括多模態技能或動態更新的技能庫，並引入人類參與的驗證迴路以提升資料品質。另一方面，可結合強化學習進一步優化技能選擇與組合策略，並針對未見過的技能組合進行更深入的泛化研究。最後，開發更強大、更通用的驗證器，以及研究如何自動適應不同智慧體執行環境的差異，將是提升 SKT 實用性與穩健性的重要方向。

## 實務應用指南

### 適用場景

1. **企業流程自動化（RPA 升級）**  
   組織內部累積大量標準作業程序（SOP）、腳本與工具說明文件時，可將其封裝為 Agent Skill，再透過 SKT 合成對應任務與可執行軌跡，訓練模型自動判斷「何時該用哪個技能」並正確執行，例如發票驗證、報表生成、資料核對等跨系統流程。

2. **客戶支援與服務智慧體**  
   客服場景常需協調多項互補技能，如查詢訂單、比對退換貨政策、寄送通知信、更新 CRM。SKT 可基於這些技能合成多技能配置任務，讓語言模型智慧體學會依使用者意圖選擇、組合並依序執行技能，減少人工轉接。

3. **軟體開發輔助工具**  
   將程式碼生成、單元測試、靜態檢查、文件撰寫、版本控制等技能封裝後，SKT 能產生從單一功能實作到端到端專案建置的任務套件，訓練開發智慧體在正確時機呼叫對應工具，並遵守操作限制。

4. **科學與數據分析管線**  
   在需要重複使用程序性知識的領域（如生物資訊流程、財務模型計算），SKT 可將公開技能倉庫中的分析腳本與模板轉為基於技能的任務，透過經驗證的合成資料生成，提升模型對專業工具鏈的掌握度。

5. **教育與模擬訓練環境**  
   針對特定學科或職訓課程，將解題步驟、實驗流程、評分規則封裝為技能，利用 SKT 產生難度可控的單技能與多技能題目，並透過可執行軌跡驗證學習成效，作為互動式教學或測評系統的後盾。

### 實作前置條件

- **資料準備**
  - 一定數量且品質穩定的 **Agent Skill**，每個技能應包含清晰指令、後設資料（用途、輸入輸出、操作限制）以及可執行資源（腳本、模板、API 規格）。
  - 建議先從 **公開技能倉庫** 或內部文件整理出 **候選技能池**，並依品質、多樣性與 **可組合性** 進行篩選。
  - 若需評估模型成效，應額外準備與訓練池不相交的保留技能集合，用於建構 **Held-Out Executable Benchmark**（如 SkillEval）。

- **運算資源**
  - 具備呼叫強大語言模型（作為合成與執行智慧體）的 API 配額或本地 GPU/TPU 叢集。
  - 可執行環境：用於執行技能腳本、執行軌跡並進行 **基於規則的驗證** 與 **基於智慧體的驗證** 的沙箱或容器化平台。
  - 微調所需運算：根據目標模型大小（如 9B、4B 參數級別）準備對應的 GPU 記憶體與訓練框架。

- **技能與系統前提**
  - 技能必須是「可執行」且結果可驗證，否則無法產生可靠的 **可執行軌跡**。
  - 需要定義 **智慧體測試框架（Agent Harness）**，讓模型能與技能互動、觀察執行結果並決定下一步。
  - 建議具備基礎的 MLOps 與資料管線能力，以便管理任務套件、軌跡資料與模型版本。

---

### 實作步驟建議

1. **技能盤點與候選池建構**  
   收集內部或公開技能，統一格式為 SKILL.md 或類似結構，並依據使用頻率、文件完整度、可執行性與領域覆蓋率篩選出 **候選技能池**。同步標註技能間的互補關係，作為後續 **多技能配置** 的基礎。

2. **設計智慧體執行環境（Harness）**  
   建立能載入技能、執行動作、回傳觀察結果的 **Agent Harness**。此環境需支援單步執行、完整軌跡記錄，並能與後續驗證器對接。

3. **合成基於技能的任務**  
   利用 SKT 的生成模組，依據單技能與多技能配置產生 **任務套件**。每個任務應包含結化規格、參考解答、預期輸出與驗證機制，並透過 **可控複雜度** 機制調整難度。

4. **多層次驗證與回饋引導修復**  
   對合成任務與軌跡進行 **基於規則的驗證**（檢查格式、輸出、約束）與 **基於智慧體的驗證**（實際執行並檢查結果）。驗證失敗時啟動 **回饋引導修復**，反覆修正任務描述、參考解答或執行路徑。

5. **收集並過濾可執行軌跡**  
   讓強大語言模型在 Harness 上執行任務，收集完整互動軌跡。只保留成功完成且確實使用每一項所需技能的 **可執行軌跡**，確保監督訊號品質。

6. **監督式微調（SFT）**  
   將過濾後的軌跡轉為訓練資料，對目標模型進行 **監督式微調**。可視任務規模調整學習率、批次大小與訓練輪數，避免過度擬合合成資料。

7. **建構保留評測基準並評估**  
   使用與訓練資料不相交的技能集合，透過相同 SKT 管線產生 **SkillEval** 或其他 **保留的可執行基準測試**。在 **跨框架評估** 中檢驗模型是否僅適應單一 Harness，還是具備通用技能使用能力。

8. **部署與持續迭代**  
   將微調後模型整合至產品 **智慧體執行環境**，並建立監控機制追蹤技能呼叫成功率、多技能協調失敗案例與使用者回饋，定期回流資料以擴充 **技能涵蓋範圍**。

### 潛在風險與注意事項

- **驗證成本高昂**  
  大規模合成與執行驗證會消耗大量 API 配額與運算資源。建議先以小規模 **候選技能池** 試跑，驗證 Harness 與驗證器穩定性後再擴大規模。

- **技能品質參差不齊**  
  文件不完整或語意模糊的技能會導致合成任務錯誤、軌跡不穩定。應在進入 SKT 前進行技能清理，並對高風險技能加入額外單元測試。

- **過度擬合特定 Harness**  
  模型可能學會迎合特定 **智慧體測試框架** 的輸出格式，而非真正理解技能。透過 **跨框架評估** 與保留技能基準測試可有效偵測此問題。

- **執行安全性風險**  
  技能常包含可執行腳本或 API 呼叫，需在隔離沙箱中執行，避免資料外洩、權限提升或惡意程式碼影響生產環境。

- **多技能協調失敗**  
  多技能配置任務容易出現順序錯誤、依賴遺漏或狀態污染。建議在任務規格中明確標示技能間的輸入輸出關係，並在驗證階段檢查每項技能是否被實質使用。

- **資料外洩與基準污染**  
  建構 **Held-Out Executable Benchmark** 時，務必確認測試技能與訓練技能完全不相交，並定期稽核任務套件是否意外洩漏訓練資訊。

---

### 與其他技術的整合建議

- **與 RAG / 技能檢索系統整合**  
  SKT 訓練的是「使用技能的能力」，但實際部署時仍需 **技能檢索** 機制從大型 **技能生態系統** 中找出相關技能。可將 SKT 微調後的模型作為 RAG 管線中的推理核心，結合向量檢索提升召回與應用準確率。

- **與現有 Agent 框架整合**  
  SKT 產生的任務套件與軌跡可轉換為 LangChain、AutoGen、Semantic Kernel 等框架可讀格式，讓企業在既有 **智慧體執行環境** 中快速導入，無需從頭打造 Harness。

- **與 CI/CD 及 MLOps 整合**  
  將 SKT 的資料合成、驗證、微調與 **SkillEval** 評估流程納入 CI/CD，讓每次技能更新或模型迭代都能自動產生新任務、重新驗證並回歸測試，確保技能品質與模型穩定性。

- **與可觀測性工具整合**  
  在生產環境記錄模型選擇技能、執行步驟與失敗案例，並與 SKT 的驗證資料比對，形成持續學習迴路，逐步擴充 **技能覆蓋率** 並修正常見錯誤模式。

- **與參數化技能表示法整合**  
  若未來採用 Skill-to-LoRA、Latent Skill 等參數化技能方案，SKT 產生的高品質軌跡可同時作為技能微調與模型內化（Skill Internalization）的訓練資料，兼顧靈活性與推論效率。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先聚焦「什麼是 Agent Skill」以及「為什麼有技能還不會用」這兩個核心問題，理解 SKT 如何透過「合成任務 → 驗證 → 收集成功軌跡 → 微調模型」四步驟，讓語言模型學會正確使用技能。可略過技術細節，重點看適用場景與潛在風險。

- **AI 工程師**  
  請重點研讀 SKT 的資料管線、驗證機制與 **回饋引導修復** 設計，並參考實作步驟建議將論文方法落地。特別注意 **Agent Harness** 的設計、軌跡過濾條件，以及如何避免模型過度擬合特定執行環境。

- **研究人員**  
  建議深入分析 **基於規則的驗證** 與 **基於智慧體的驗證** 的互補性、**多技能配置** 的協調難題，以及 **SkillEval** 作為保留可執行基準的建構方式。可進一步探索驗證機制消融、跨框架泛化與規模化實驗的設計空間。

- **產品經理**  
  請從適用場景與商業價值切入，理解 SKT 能將企業現有的 SOP、工具文件轉化為可訓練智慧體的資料資產。評估時需同時考量運算成本、驗證品質、部署安全與後續維運，並規劃與現有 RAG、Agent 框架及監控系統的整合路徑。
