# S³Gym：大型語言模型（LLMs）能否將自我測試（Self-Testing）與自我評判（Self-Judging）轉化為自我改進（Self-Improvement）？

## ⚡ TL;DR

既有基準多將大型語言模型視為固定策略，難以評估其能否從互動經驗中自我測試、評判並改進。
提出S³Gym基準，以寬鬆探索與保留評估，在七款文字遊戲中比較歷史情境學習、摘要記憶與參數訓練。
實驗顯示自我改進並非自動，效果取決於任務結構：摘要記憶利於規則壓縮，參數訓練則可能不穩定或負遷移。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）日益與外部環境互動，並累積大量行為經驗（behavioral experience），但現有的代理基準大多將模型視為固定策略（fixed policy）來評測。因此，目前仍不清楚代理（agent）是否能主動測試其行為、評判所產生的經驗，並利用該經驗改進未來決策。我們提出 S³Gym，這是一個互動式基準（interactive benchmark），透過三項相互耦合的能力來評估大型語言模型的自我改進：自我測試（Self-Testing）、自我評判（Self-Judging）與自我改進（Self-Improvement）。S³Gym 將寬鬆探索（permissive exploration）與嚴格的保留評估（held-out evaluation）分開，並在七款配備可執行環境驗證器（executable environment verifiers）的文字遊戲（text-based games）中實例化此協定。我們評估三種整合互動經驗的途徑：直接的歷史情境學習（History In-Context Learning, History ICL）、以分數為條件的摘要記憶（Summary Memory），以及參數訓練（Parameter Training）。

實驗結果顯示，自我改進既不會自動發生，也不具有一致性。情境層級經驗（context-level experience）能改善數個模型–遊戲組合的表現，但最有效的途徑高度取決於任務結構：當經驗可被壓縮為可重複使用策略規則（reusable strategic rules）時，摘要記憶有所助益；但當成功取決於精確且依狀態而定的資訊時，摘要記憶的表現往往不如原始歷史來得好。參數訓練在某些任務上帶來顯著提升，但在其他任務上改進幅度也不穩定，並出現嚴重的負遷移（negative transfer）。這些結果顯示，僅辨識成功行動並不足夠；代理還必須將回饋轉化為可執行且可遷移的策略。S³Gym 提供一個統一框架，不僅用於診斷此流程，更可辨識阻礙代理將互動經驗轉化為可靠自我改進的瓶頸。

### 核心貢獻（3～5點）
- 提出 S³Gym 互動式基準，將 LLM 自我改進拆解為自我測試、自我評判、自我改進三項耦合能力，並明確區分寬鬆探索與保留評估兩個階段。
- 在七款文字遊戲中實例化評測協定，搭配可執行環境驗證器，提供可診斷、可重複的互動經驗學習框架。
- 系統比較三種經驗整合途徑：歷史情境學習（History ICL）、摘要記憶（Summary Memory）與參數訓練（Parameter Training），發現其成效高度依賴任務結構。
- 揭示自我改進並非自動發生：參數訓練雖在部分任務帶來顯著增益，但也可能出現不穩定改進與嚴重負遷移。
- 強調代理必須將環境回饋轉化為可執行且可遷移的策略，而非僅止於辨識成功行動。

### 適合對象
適合對大型語言模型代理（LLM agents）、互動式評測基準、自我改進機制與經驗學習感興趣的研究者與工程師，特別是關注多輪決策（multi-turn decision-making）、環境探索（environment exploration）、記憶機制設計，以及希望診斷代理如何將互動軌跡（trajectories）轉化為可遷移策略的讀者。

## 深度分析

#### 方法論解析

S³Gym（Self-Testing、Self-Judging、Self-Improvement Gym）的核心貢獻在於把「經驗驅動的自我改進（experience-driven self-improvement）」從一個籠統概念轉化為可重複測試的協定。它並非單純評量模型當下的固定策略（fixed policy），而是設計了一個兩階段流程：**寬鬆探索階段（permissive exploration phase）** 與 **保留評估階段（held-out evaluation phase）**。在探索階段，代理（agent）與較寬鬆的環境配置互動，產生成功、失敗與部分成功的軌跡（trajectories）；在評估階段，則把經過自我評判（self-judging）後的經驗應用到更嚴格、未見過的環境配置，檢驗經驗是否真正具有可遷移性（transferability）。

此框架把學習拆解為三個互相依賴的能力：

1. **自我測試（Self-Testing）**：代理主動探索策略、蒐集診斷性證據（diagnostic evidence）。這不只是隨機嘗試，而是要在多輪決策（multi-turn decision-making）中產生能區分不同假設的互動軌跡。
2. **自我評判（Self-Judging）**：代理必須評斷哪些行動與結果是可重複使用的，哪些屬於失敗模式（failure patterns）。這裡的關鍵在於 S³Gym 明確區分「模型自己產生的評判」與「環境驗證器（executable environment verifiers）計算的真實結果」，讓研究者能診斷評判品質是否成為後續自我改進（self-improvement）的瓶頸。
3. **自我改進（Self-Improvement）**：把經過測試與評判的經驗轉化為未來決策的改變。

在經驗整合的機制上，論文比較了三條處於不同持久度層級的路徑：

- **歷史情境學習（History ICL / in-context learning）**：直接把過去的觀察、行動與分數放入提示（prompt）中。這屬於短期記憶，保留了精確的狀態相依資訊（state-contingent information），但受限於上下文長度。
- **摘要記憶（Summary Memory / external memory）**：把長軌跡壓縮成自然語言的可重複使用策略規則（reusable strategic rules）、失敗模式或可重複使用技能（reusable skills）。這類似 Reflexion 與 Voyager 的做法，屬於中期記憶，能在上下文有限的情況下提供緊湊抽象，但高度依賴自我評判的品質。
- **參數訓練（Parameter Training）**：透過參數更新把篩選或修正後的軌跡內化，屬於長期記憶。這對應 STaR、ReST、Re-ReST 等方向，能提供持久改變，但也可能放大錯誤評判所導致的偏差。

方法論上最值得注意的是「分離探索與評估」的設計。許多現有基準（benchmark）把模型當成固定策略，只回答「當下表現如何」；S³Gym 則進一步問「模型能否把自己的互動經驗轉化為可遷移的行為改進」。這種設計特別適合評估體驗式學習（experiential learning）與反思性探究（reflective inquiry）所強調的「經驗必須經過抽象與再應用才能成為知識」。

七款文字遊戲（text-based games）—— Chess、Minesweeper、Nullify、Tetris、Snake、PvZ、Trust Evolution——涵蓋了潛規則歸納、約束滿足、數值轉換、空間規劃、資源分配、生存與多代理策略等多元任務結構。每款遊戲都提供相關但不同的探索與評估配置，迫使代理從經驗中提取可遷移知識，而非僅記憶孤立動作或種子（seed）。

#### 實驗數據解讀

由於目前可取得的內容主要為摘要與部分引言，以下根據論文所描述的趨勢進行解讀，並指出若取得完整表格後應進一步檢視的面向。

論文指出，**自我改進並非自動發生，也非均勻分布**。這是一個關鍵結論：並非把所有互動歷史丟進模型就能帶來進步。具體來說：

- **情境層級經驗（context-level experience）**，即 History ICL，對若干模型—遊戲組合（model–game pairs）有正面幫助。這顯示在上下文允許的範圍內，直接提供原始軌跡能讓模型捕捉到精確的狀態相依資訊，對於需要「看到具體情況才決定下一步」的任務特別有效。
- **摘要記憶（Summary Memory）** 的效果呈現高度任務依賴性。當成功經驗可以被壓縮成可重複使用策略規則時，摘要能帶來穩定增益；然而，當任務成功取決於精確、狀態相依的細節時，摘要往往不如原始歷史（raw history）。這呼應了外部記憶（external memory）方法的經典權衡：抽象帶來緊湊性，卻可能遺失關鍵細節。
- **參數訓練（Parameter Training）** 在某些任務上帶來顯著進步，但也出現不穩定改進（unstable improvement）與嚴重負遷移（negative transfer）。這說明把經驗內化為參數更新雖然潛力最大，卻也最危險：一旦自我評判錯誤地把失敗軌跡標記為成功，或把僅適用於特定配置的經驗過度一般化，參數更新會系統性地放大錯誤。

從評估指標來看，S³Gym 同時使用兩類訊號：

1. **環境驗證器（executable environment verifiers）提供的客觀分數**：包括每步分數（step-level scores）或終局分數（terminal scores），用於衡量最終行為表現。
2. **模型自我評判（self-judgments）與驗證結果的一致性**：用於診斷代理是否能正確辨識有用與有害的經驗。

這種雙軌指標設計讓研究者可以區分兩種失敗來源：一種是「探索不足」導致沒有蒐集到好經驗；另一種是「評判錯誤」導致好經驗被錯誤標記或壞經驗被誤用。若未來能看到完整數據，應特別關注：

- 在哪些遊戲中，自我評判的準確率（例如成功軌跡被正確標記的比例、失敗原因歸因的正確率）與最終保留評估表現高度相關；
- 不同模型規模或架構在 Summary Memory 與 Training 路徑上的差距；
- 負遷移（negative transfer）是否集中在特定類型的遊戲（例如規則隱藏、獎勵稀疏或長期依賴較強的環境）。

#### 與現有研究的比較

S³Gym 與現有研究的關係可從三個層次理解：

**相對於傳統代理基準**：多數基準（如 ALFWorld、ScienceWorld、TextWorld 相關評測）把模型視為固定策略，重點在規劃、推理與工具使用能力。S³Gym 則把「經驗能否轉化為改進」設為核心研究問題，並透過分離探索與保留評估來強制檢驗遷移性。

**相對於現有的自我改進方法**：Reflexion、Voyager、STaR、ReST、Re-ReST 等方法分別對應 external memory 或 training 路徑，但它們通常在各自任務與設定下獨立評估，難以直接比較。S³Gym 的貢獻在於提供統一協定，把 History ICL、Summary Memory、Parameter Training 放在同一個互動與測試條件下比較，從而揭示哪種經驗整合機制在何種任務結構下最有效。

**相對於 KORGym**：KORGym 同樣使用文字遊戲評估大型語言模型推理，但聚焦於多樣遊戲中的推理能力。S³Gym 借用其遊戲化評估典範，但把焦點轉向「經驗驅動的自我改進」，並加入可執行環境驗證器以確保評估的客觀性。

**主要限制與待釐清處**：

- 目前公開內容未包含完整實驗表格，因此對於「哪些模型在哪些遊戲上進步最大」仍無法做定量比較。
- 論文提到參數訓練出現不穩定與負遷移，但未說明是否使用特定正則化、篩選門檻或課程策略來緩解；這是後續可深入之處。
- 七款遊戲雖涵蓋多種認知需求，但是否足以代表真實部署中「前線部署工程師（forward-deployed engineer, FDE）」所面對的開放式、回饋稀疏且目標模糊的任務，仍有討論空間。

#### 可重現性評估

可重現性（reproducibility）是互動式基準（interactive benchmark）的關鍵。根據目前資訊，S³Gym 具備以下有利條件：

- **可執行環境驗證器（executable environment verifiers）**：每款遊戲都有程式化、可重複執行的規則來計算分數，減少人為評判的主觀差異。
- **明確的兩階段協定**：探索配置與評估配置分離，若資料集與種子固定，則不同研究團隊可在相同條件下複製實驗。
- **七款文字遊戲（text-based games）**：文字介面通常比視覺模擬器更易於跨平台部署，降低了環境重現的門檻。

然而，目前摘要與引言並未明確說明以下項目的開放程度：

- 原始碼（source code）是否已公開於 GitHub 等平臺；
- 探索與評估的環境配置、種子（seeds）、提示模板（prompt templates）是否完整釋出；
- 模型權重（model weights）或微調後的檢查點（checkpoints）是否提供；
- 原始軌跡（raw trajectories）、摘要記憶（summary memory）內容與自我評判（self-judgments）是否可供下載，以便進行錯誤分析。

對於一個強調「診斷瓶頸」的基準而言，僅公布最終分數是不足的；理想上應釋出完整的互動日誌、評判結果與環境狀態轉換，才能讓其他研究者驗證「自我評判錯誤是否確實導致自我改進失敗」這類因果推論。若論文已提供相關資源，則可重現性評價將大幅提升；若尚未公開，則建議後續補充。

#### 未來研究方向

基於 S³Gym 所揭示的現象，未來研究可朝以下方向延伸：

1. **更精細的自我評判機制**：既然自我評判品質是瓶頸，未來可探索讓代理同時產生「成功/失敗標籤」與「因果解釋」的機制，並透過對照實驗驗證哪種解釋形式最能提升後續 Summary Memory 與 Parameter Training 的效果。

2. **混合式經驗整合（hybrid experience integration）**：論文顯示不同路徑各有優劣。未來可設計動態切換機制：在需要精確狀態資訊時使用 History ICL，在可抽象為規則時使用 Summary Memory，在累積足夠高品質軌跡後才觸發 Parameter Training，並以驗證器分數作為觸發條件。

3. **緩解負遷移（negative transfer）的訓練策略**：針對 Parameter Training 的不穩定性，可引入基於驗證器分數的篩選門檻、對比學習（contrastive learning）或課程式經驗回放（curriculum experience replay），以降低錯誤經驗被內化的風險。

4. **擴展到更開放、回饋稀疏的環境**：目前七款遊戲多具有明確分數與可驗證規則。未來可將 S³Gym 協定延伸至目標模糊、回饋延遲且需要與人類或其他代理協商的場景，例如軟體工程任務、科學實驗設計或多代理談判。

5. **模型生成評判與人類專家評判的對照研究**：透過比較模型自我評判與人類前線部署工程師（FDE）的判斷，可進一步定位「模型在哪些認知步驟上仍需要人類介入」，並為半自動化（human-in-the-loop）的自我改進系統提供設計依據。

6. **跨遊戲遷移與技能組合庫（skill library）**：未來可研究代理是否能從一款遊戲（例如 Minesweeper 的約束推理）提取抽象技能，並在另一款遊戲（例如 Chess 或 Nullify）中重組應用，從而測試更高層次的可遷移知識。

## 論文問答

**Q1：S³Gym 想要解決的核心問題是什麼？**
A：現有的大型語言模型代理評測大多把模型當成固定策略，只測量它在評測當下的靜態能力，卻無法回答代理是否能從自己累積的行為經驗中持續自我改進。S³Gym 針對的正是這個缺口：它把「經驗驅動的自我改進」視為一個需要獨立評估的能力，並透過互動式基準來檢驗代理能否主動測試、評判並利用經驗。這讓研究者能夠診斷代理在真實部署情境中，是否具備從互動中學習並轉化為更好決策的潛力。

**Q2：為什麼現有的代理基準無法充分捕捉自我改進能力？**
A：傳統基準通常在任務、獎勵與執行腳架都已預先設定好的情況下進行測試，模型只需在給定環境中表現即可，沒有機會先探索再接受保留評估。它們也鮮少區分代理自己產生的自我評判與環境驗證器給出的客觀結果，因此無法判斷經驗是否真的被正確理解與轉移。換句話說，這些基準測的是「當下會不會做」，而非「做過之後有沒有變得更會做」。

**Q3：為什麼從經驗中自我改進對 LLM 代理如此重要？**
A：在真實應用中，目標往往模糊、回饋訊號可能缺失或不可靠，系統必須像前線部署工程師一樣持續適應與修正。體驗式學習與反思性探究的理論也指出，單純收集軌跡並不保證學習，經驗必須經過檢驗、抽象化並重新應用才會成為知識。因此，讓代理具備自我測試、自我評判與自我改進的能力，是減少對人工介入依賴、邁向真正自主系統的關鍵。

**Q4：S³Gym 的核心評測協議是什麼？**
A：S³Gym 把每次評測分為寬鬆探索階段與嚴格的保留評估階段：在探索階段，代理可以在較寬容的環境設定中嘗試不同策略並產生成功或失敗的軌跡；在評估階段，則把更新後的代理放到更嚴格且保留的設定中，測試經驗是否能遷移。整個過程透過可執行環境驗證器來計算客觀分數，並明確區分代理的自我評判與環境驗證結果。這種設計能直接檢驗經驗是否被轉化為可執行且可轉移的策略。

**Q5：相較於 KORGym 等既有遊戲基準，S³Gym 的關鍵創新在哪裡？**
A：KORGym 主要利用多樣化的文字遊戲來評估 LLM 的推理能力，而 S³Gym 則把這些遊戲當作控制化的測試場，專門用來研究經驗驅動的自我改進。它的創新在於同時評量自我測試、自我評判與自我改進三個環節，並把探索與評估分離，讓研究者能診斷「學到的是通用策略還是只是記住特定種子」。此外，它還在統一協議下比較歷史情境學習、摘要記憶與參數訓練三種經驗整合路徑。

**Q6：作者為什麼選擇這三種經驗整合路徑？**
A：這三種路徑分別對應不同持久度與資訊保真度的權衡：歷史情境學習屬於短期經驗，能保留精確的狀態相依資訊，但會消耗大量上下文；摘要記憶屬於中期外部記憶，把長軌跡壓縮成可重複使用策略規則或失敗模式，但高度依賴自我評判的品質；參數訓練則是長期內化，能持久地改變模型行為，卻也可能放大錯誤評判的經驗。透過同時評估這三條路徑，S³Gym 能揭示哪種經驗轉化方式最適合特定任務結構。

**Q7：S³Gym 包含哪些遊戲，各自測試什麼能力？**
A：S³Gym 包含 Chess、Minesweeper、Nullify、Tetris、Snake、PvZ 與 Trust Evolution 七款文字遊戲，涵蓋潛規則歸納、約束滿足、數值轉換、空間規劃、資源分配、生存與多代理策略等面向。每款遊戲都提供相關但不同的探索與評估設定，迫使代理從經驗中提取可轉移的知識，而非僅僅記住孤立動作或特定種子。這些遊戲具備多輪互動、部分可觀察、延遲後果與長程決策等特性，能產生豐富的行為軌跡供分析。

**Q8：實驗的主要發現是什麼？**
A：研究發現自我改進既不是自動發生，也不會均勻出現在所有模型與遊戲組合上，而是強烈依賴任務結構與經驗整合方式。情境層級的歷史情境學習在若干模型—遊戲組合中帶來進步；摘要記憶在經驗能被壓縮成可重複使用策略規則時特別有效，但在需要精確狀態相依資訊的任務上常不如原始歷史。參數訓練雖然在某些任務上帶來顯著提升，卻也出現不穩定的改進與嚴重的負遷移。

**Q9：這些結果對「自我評判」能力有何啟示？**
A：實驗顯示，僅僅辨識出成功的動作並不足夠，代理還必須把回饋轉化為可執行且可轉移的策略，而這正是自我評判的瓶頸所在。當代理產生的自我評判與可執行環境驗證器的客觀結果不一致時，錯誤的經驗可能透過摘要記憶被固化，或在參數訓練中被放大，導致後續表現反而變差。因此，S³Gym 強調必須把模型生成的自我評判與環境驗證分開檢視，才能準確診斷自我改進失敗的原因。

**Q10：S³Gym 對真實世界代理部署有何啟發？**
A：S³Gym 提供了一個可重現的協議，讓開發者在正式部署前就能評估代理是否具備探索、評判與改進的完整循環，這與前線部署工程師在客戶環境中反覆試錯、修正的過程相呼應。企業可以依據任務特性選擇最適合的經驗整合路徑，例如狀態相依的任務優先使用歷史情境學習，而規則可壓縮的任務則適合摘要記憶。這有助於把評測焦點從單次基準分數轉向持續學習與適應的系統能力。

**Q11：這項研究對產品設計有哪些具體建議？**
A：產品設計不應假設單一記憶或訓練機制就能適用所有任務，而應根據任務結構選擇經驗整合方式。開發者需要特別監控自我評判的品質，因為錯誤的判斷會透過參數訓練或摘要記憶造成負遷移，反而讓系統表現退步。此外，產品應明確區分寬鬆探索與嚴格評估階段，並引入可執行環境驗證器來確認經驗是否真的轉化為更好的行為。

**Q12：S³Gym 可能對整個研究領域帶來什麼影響？**
A：S³Gym 把自我測試、自我評判與自我改進統整到同一個評測框架中，讓不同記憶與訓練方法能在相同的互動與測試條件下被系統性比較。它推動研究重心從靜態能力評估轉向經驗驅動的學習動態，並凸顯出自我評判與經驗轉化這兩個過去較少被獨立檢視的環節。長遠來看，這可能催生更強大的反思機制、更穩健的信用分配方法，以及更安全的自主自我訓練技術。

**Q13：這項研究有哪些應被承認的限制？**
A：S³Gym 目前以文字遊戲為主要環境，雖然能精細控制互動與驗證，但尚未涵蓋多模態或更複雜的真實世界部署情境。實驗雖評估了具代表性的大型語言模型，但並未涵蓋所有規模、架構或後訓練方法，因此結果的普遍性仍需進一步驗證。此外，研究採用的三種經驗整合路徑仍屬原型層級，尚未納入學習型世界模型、元學習或更進階的反思架構。

**Q14：研究中觀察到哪些具代表性的失敗模式？**
A：參數訓練在某些遊戲中出現嚴重的負遷移，顯示代理可能過度擬合探索階段的特定設定，或把錯誤評判的經驗內化到參數中。摘要記憶有時會產生過度抽象或不正確的可重複使用策略規則，導致在保留評估中做出錯誤推論。歷史情境學習雖然保留較多細節，但原始軌跡可能包含無關雜訊，並在上下文長度受限時無法完整載入，影響決策品質。

**Q15：S³Gym 指出了哪些未來研究方向？**
A：未來可以發展更可靠的自我評判機制，讓模型生成的判斷與可執行環境驗證器的客觀結果更一致，從而減少負遷移與錯誤固化。也可以探索混合式經驗整合，例如結合歷史情境學習的細節、摘要記憶的規則壓縮與參數訓練的持久內化，以發揮各路的優勢。此外，把 S³Gym 的協議擴展到多模態環境、真實世界回饋，以及研究自主自我訓練的安全性與穩定性，都是值得深入的方向。

## 實務應用指南

### 適用場景

1. **企業內部自動化流程代理**  
   讓 LLM 代理在沙箱環境中反覆嘗試操作企業系統（填表、呼叫 API、核對資料），透過自我測試累積成功與失敗軌跡，再由自我評判提煉出可重複使用的標準作業流程，最後部署到正式環境處理真實工單。

2. **軟體開發與測試助手**  
   程式碼生成代理可以在可執行的單元測試環境中自我測試不同實作，依據測試結果（通過/失敗/部分通過）進行自我評判，並將修正策略寫入摘要記憶，後續遇到類似需求時直接套用經驗規則。

3. **客戶服務與對話代理**  
   客服代理在多輪對話中探索不同回應策略，根據用戶滿意度或問題解決與否進行自我評判，把有效的應對方式與常見失敗模式整理成摘要記憶，持續改善未來對話品質。

4. **遊戲 AI 與模擬訓練**  
   在文字或模擬環境中訓練策略代理，例如棋類、資源管理或生存遊戲，透過寬鬆探索累積經驗，再以保留評估檢驗策略是否能遷移到新地圖、新對手或新規則。

5. **科學實驗與研究自動化**  
   讓代理在模擬實驗環境中提出假設、執行步驟、觀察結果，並依據可驗證的實驗結果進行自我評判，將有效實驗設計與失敗原因記錄下來，作為下一輪實驗的參考。

---

### 實作前置條件

- **資料準備**
  - 可執行的任務環境與客觀驗證器（verifier），能產生步驟級或最終分數。
  - 寬鬆探索配置與保留評估配置，兩者需有明確區隔但任務結構相關。
  - 歷史互動軌跡（觀察、推理、行動、回饋）的儲存與追蹤機制。

- **運算資源**
  - LLM 推論端點（API 或本地部署），用於產生行動、自我評判與摘要。
  - 若採用參數訓練，需要 GPU/TPU 叢集與微調框架（如 LoRA、DPO、PPO）。
  - 向量資料庫或記憶儲存空間，用於存放摘要記憶與歷史軌跡。

- **技能與團隊**
  - 熟悉提示工程與多輪代理架構設計。
  - 具備強化學習或監督式微調經驗（若要走參數訓練路徑）。
  - 能設計評估指標、對照實驗與診斷分析流程。
  - 領域專家協助定義成功標準與失敗模式。

---

### 實作步驟建議

1. **定義任務與可驗證回饋**  
   將業務問題轉換為代理可以互動的環境，並建立客觀的評分函式或驗證器，確保自我評判與環境驗證結果可以分開比對。

2. **建立雙階段評估協議**  
   設計「寬鬆探索階段」讓代理自由嘗試，再設計「保留評估階段」測試經驗是否能遷移到未見過的設定。

3. **實作自我測試迴圈**  
   讓代理在探索階段進行多輪觀察–推理–行動–回饋迴圈，收集成功、失敗與部分成功的完整軌跡。

4. **實作自我評判機制**  
   讓 LLM 對每段軌跡進行評判，指出哪些行動有效、哪些無效、原因為何，並將模型生成的評判與環境驗證器的客觀結果進行比對，量化評判可靠性。

5. **選擇經驗整合路徑**
   - **History ICL**：直接把篩選過的歷史軌跡放入提示，適合需要精確狀態相依資訊的任務。
   - **摘要記憶**：將長軌跡壓縮成自然語言策略規則、失敗模式或可重複使用技能，適合可抽象化的任務。
   - **參數訓練**：挑選高品質軌跡進行微調，適合需要長期記憶與大規模遷移的場景，但需特別監控負遷移。

6. **執行探索並更新代理**  
   在探索階段產生經驗，依據自我評判結果整理記憶或訓練資料，再將更新後的代理投入保留評估。

7. **診斷瓶頸並迭代**  
   比較不同路徑在保留評估上的表現，分析是自我測試不足、自我評判錯誤，還是經驗轉換成可執行策略時失敗，針對瓶頸調整環境、提示或訓練流程。

---

### 潛在風險與注意事項

- **自我評判幻覺**  
  模型可能錯誤歸因成功或失敗原因，導致摘要記憶或訓練資料包含錯誤規則。  
  **因應**：將模型評判與環境驗證器結果交叉比對，必要時引入人類審核或一致性檢查。

- **負遷移與不穩定訓練**  
  參數訓練在某些任務上可能讓表現變差，或對特定探索種子過度擬合。  
  **因應**：保留多組獨立評估配置，使用早停機制與對照實驗，避免只用探索階段分數判斷好壞。

- **情境長度限制**  
  History ICL 會快速耗盡上下文，導致遺漏關鍵狀態資訊。  
  **因應**：結合摘要記憶進行階層式檢索，只保留與當前狀態最相關的歷史片段。

- **獎勵駭取與捷徑行為**  
  代理可能找到利用驗證器漏洞的方式，而非真正學會解決問題。  
  **因應**：設計多維度評估指標，包含過程正確性與最終結果，並定期更新驗證器。

- **成本與延遲**  
  多輪探索、自我評判與微調會顯著增加運算開銷。  
  **因應**：先在小規模環境與少數任務上驗證概念，確認有效後再擴大規模。

### 與其他技術的整合建議

- **代理框架**  
  可與 LangChain、AutoGen、Semantic Kernel 等框架整合，將 S³Gym 的探索–評估協議封裝成可重複使用的代理訓練管線。

- **記憶與檢索系統**  
  將摘要記憶存入向量資料庫（如 Chroma、Pinecone、Weaviate），並依任務狀態進行語意檢索，彌補 History ICL 的上下文限制。

- **RLHF 與偏好學習管線**  
  參數訓練路徑可銜接現有的 RLHF、DPO 或 ReST 流程，把自我評判產生的偏好對直接用於模型更新。

- **可觀測性與 MLOps 工具**  
  整合追蹤工具（如 LangSmith、Weights & Biases、MLflow）記錄每條軌跡、評判分數與保留評估結果，便於後續診斷與審計。

- **CI/CD 與持續學習**  
  將保留評估設為部署閘道，只有在新經驗確實提升保留表現時才更新線上代理，避免負遷移影響正式服務。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先聚焦「適用場景」與「實作步驟建議」，理解 S³Gym 如何把「嘗試、評分、改進」這三個步驟變成可重複的系統流程；遇到專有名詞可對照詞彙表，不必一開始就深入參數訓練細節。

- **AI 工程師**  
  請重點閱讀「實作步驟建議」與「與其他技術的整合建議」，特別注意 History ICL、摘要記憶與參數訓練三種路徑的取捨，並在實作時把環境驗證器與模型自我評判分開設計，以便後續診斷。

- **研究人員**  
  建議從論文的方法論與實驗設計切入，關注 S³Gym 如何形式化自我測試、自我評判與自我改進的關係，以及不同經驗整合路徑在七款遊戲上的表現差異，從中尋找可延伸的研究問題。

- **產品經理**  
  請優先參考「適用場景」與「潛在風險與注意事項」，評估哪些業務流程適合引入自我改進代理，並把保留評估、人類審核與成本控管視為產品上線前的必要條件。
