# 強化學習中的評分準則到程式碼信用分配（Rubric-to-Code Credit Assignment, RCCA）

**原文標題：** Rubric-to-Code Credit Assignment for Reinforcement Learning  
**作者：** Rui Jin、Jikai Chen、Yihan Chen 等 8 位作者  
**發布日期：** 2026-08-28  
**HF 連結：** [https://huggingface.co/papers/2608.27906](https://huggingface.co/papers/2608.27906)  
**arXiv：** [https://arxiv.org/abs/2608.27906](https://arxiv.org/abs/2608.27906)  

---

## ⚡ TL;DR

傳統GRPO將互動網頁的多項功能回饋壓縮為單一獎勵，並均勻分配優勢給所有詞元，導致信用分配薄弱。
RCCA透過階層式獎勵與評估器文字歸因，將評分準則層級的功能回饋對齊到負責任的程式碼片段與詞元。
所訓練模型於兩項基準獲41.25與76.19分，超越Claude Opus 4.5和GPT-5。

## 摘要翻譯

互動式網頁應用生成（interactive web application generation）要求模型能夠根據自然語言請求（natural language requests）產出可用的 HTML、CSS 與 JavaScript 應用程式。與傳統的程式碼生成（code generation）不同，應用程式品質取決於多項面向使用者的功能性需求（functional requirements），而每一項需求通常都與事件處理器（event handlers）、狀態更新（state updates）、DOM 片段（DOM fragments）或 CSS 選擇器（CSS selectors）等局部化的程式碼區域相關。標準的群體相對策略最佳化（Group Relative Policy Optimization, GRPO）將這些結構化結果壓縮為單一的序列層級獎勵（sequence-level reward），並將所產生的群體相對優勢（group-relative advantage）均勻地套用至所有生成的詞元（generated tokens），從而削弱了信用分配（credit assignment）。我們提出評分準則到程式碼信用分配（Rubric-to-Code Credit Assignment, RCCA），這是一個強化學習（reinforcement learning）框架，可將評分準則層級功能性回饋（rubric-level functional feedback）轉換為生成程式碼（generated code）上的局部化最佳化訊號（localized optimization signals）。RCCA 圍繞明確功能性評分準則（explicit functional rubrics）建構訓練任務（training tasks），使用階層式獎勵（hierarchical reward）來區分格式失敗（format failures）、原始碼失敗（source-code failures）、執行時期失敗（runtime failures）與功能性失敗（functional failures），並將評估器生成的文字歸因（evaluator-generated textual attributions）與負責任的程式碼片段（responsible code spans）及生成的詞元對齊。由此產生的模型 Ling-RCCA-Flash 在 MiniAppBench 上獲得 41.25 分，較 Ling-3.0-Flash 提升 32.20 分，並小幅超越 Claude Opus 4.5。該模型在 ArtifactsBench 上亦達到 76.19 分，較監督式微調模型（Supervised Fine-Tuning model, SFT model）提升 4.48 分，且在官方 ArtifactsBench 排行榜設定下超越 GPT-5 的分數 3.64 分，創下新的最高分，顯示出可遷移的實作層級提升（implementation-level gains）。

### 核心貢獻（3～5點）
- 提出 RCCA 強化學習框架，將評分準則層級功能性回饋轉換為生成程式碼上的局部化最佳化訊號，改善傳統 GRPO 將序列層級獎勵均勻分配至所有詞元所造成的信用分配不足問題。
- 設計階層式獎勵機制，區分格式、原始碼、執行時期與功能性失敗，並將評估器生成的文字歸因對齊至負責任的程式碼片段與生成的詞元。
- 訓練出 Ling-RCCA-Flash 模型，在 MiniAppBench 與 ArtifactsBench 上取得領先成績，分別超越 Ling-3.0-Flash／Claude Opus 4.5 與 SFT 模型／GPT-5。
- 顯示出可遷移至不同基準的實作層級提升，為互動式網頁應用生成提供可擴展的訓練與評估方向。

### 適合對象
從事大型語言模型程式碼生成、強化學習後訓練、互動式網頁應用生成，以及自動化評測基準建構的研究人員與工程師；亦適合關注如何將結構化功能性回饋轉化為局部化訓練訊號，以提升模型實作品質的讀者。

## 深度分析

#### 方法論解析

##### 1. 問題設定：從「整體獎勵」到「評分準則層級回饋」
互動式網頁應用生成（interactive web application generation）的目標，是讓大型語言模型（Large Language Models, LLMs）根據自然語言請求（natural language requests）輸出可用的 HTML、CSS 與 JavaScript。與傳統程式碼生成（code generation）不同，這類任務的正確性並非單一單元測試所能概括，而是由多項使用者面向的功能性需求（functional requirements）共同決定，例如「點擊按鈕後開啟面板」、「輸入框內容更新後即時反映到畫面」等。這些需求通常只對應到程式碼中的局部區域，如事件處理器（event handlers）、狀態更新（state updates）、DOM 片段（DOM fragments）或 CSS 選擇器（CSS selectors）。

標準的群體相對策略最佳化（Group Relative Policy Optimization, GRPO）將所有功能性結果壓縮成單一序列層級獎勵（sequence-level reward），再把群體相對優勢（group-relative advantage）均勻分配到所有生成的詞元（generated tokens）。這造成嚴重的顆粒度不匹配：模型知道「這個應用程式好或不好」，卻不知道「哪些程式碼片段該為成功或失敗負責」。Rubric-to-Code Credit Assignment（RCCA）即針對此問題，將評分準則層級功能性回饋（rubric-level functional feedback）轉換為生成程式碼（generated code）上的局部化最佳化訊號（localized optimization signals）。

##### 2. RCCA 的三層架構
RCCA 可拆解為三個互相配合的層次：

**（1）訓練任務層：以明確功能性評分準則（explicit functional rubrics）為中心**
RCCA 透過評分準則驅動的合成管線（rubric-driven synthesis pipeline）建構 RL 訓練任務（training tasks）。每個訓練樣本都附帶一組可執行、可驗證的評分準則，這些準則同時扮演兩種角色：一是定義模型應該學會的行為目標；二是作為後續評估與歸因的基本單位。這種設計讓應用程式層級的品質可以被分解為需求層級結果（requirement-level outcomes），從而避免「整體分數（holistic score）」的模糊性。

**（2）樣本層：階層式獎勵（hierarchical reward）**
RCCA 設計了一個由淺入深的四階段階層式獎勵：
1. 輸出格式有效性（output-format validity）：檢查模型輸出是否為合法的可解析格式。
2. 原始碼有效性（source-code validity）：檢查 HTML/CSS/JS 是否語法正確。
3. 執行時期有效性（runtime validity）：檢查應用程式能否在瀏覽器或執行環境中正常載入與運行。
4. 評分準則層級功能正確性（rubric-level functional correctness）：透過實際互動軌跡（interaction traces）驗證每項功能性需求是否被滿足。

這種階層結構能區分無效產物（invalid artifacts）、損壞程式（broken programs）、執行時期失敗（runtime failures）與部分正確應用（partially correct applications），讓群體相對最佳化（group-relative optimization）獲得比單一獎勵更清晰的結構化訊號。

**（3）詞元層：從文字歸因到程式碼片段再到詞元權重**
這是 RCCA 的核心創新。評估器（evaluator）不僅判斷每條評分準則是否通過，還會產生文字歸因（evaluator-generated textual attributions），將功能性結果對應到具體的實作區域，例如「按鈕點擊無反應，問題出在 `onclick` 事件處理器」。RCCA 接著把這些負責任的程式碼片段（responsible code spans）對齊到模型生成的詞元，並利用這些對齊結果加權 GRPO 目標。結果是：與功能結果直接相關的詞元獲得更強的梯度訊號，無關區域則被降權，從而恢復需求層級回饋與詞元層級策略更新之間的連結。

##### 3. 與標準 GRPO 的對比
標準 GRPO 的目標可視為對整個序列施加統一的優勢權重；RCCA 則相當於在序列內部引入「結構化遮罩」或「重要性權重」。這種做法在概念上類似將「區域性獎勵」與「序列獎勵」結合，但關鍵差異在於 RCCA 的區域性訊號來自可執行的評分準則與自動化歸因，而非人工標註的片段標籤。這使得 RCCA 能夠在不需要大量人工標註的情況下，將環境中介訓練訊號（environment-mediated training signals）轉化為局部化最佳化訊號。

#### 實驗數據解讀

##### 1. 主要結果
論文報告了兩個核心基準測試的結果：

- **MiniAppBench**：Ling-RCCA-Flash 獲得 **41.25** 分，相較於基礎模型 Ling-3.0-Flash 提升 **32.20** 分，並且略微超越 Claude Opus 4.5。
- **ArtifactsBench**：Ling-RCCA-Flash 達到 **76.19** 分，相較於監督式微調模型（SFT model）提升 **4.48** 分，並在官方排行榜設定下超越 GPT-5 **3.64** 分，成為新的最佳成績。

##### 2. 結果意涵
首先，**MiniAppBench 上超過 30 分的躍升**顯示 RCCA 對於互動式網頁應用生成具有顯著的實作層級提升（implementation-level gains）。這不是單純的格式或語法改進，而是功能正確性的實質進步，因為 RCCA 的獎勵設計直接針對功能性需求進行最佳化。

其次，**ArtifactsBench 上超越 GPT-5** 的結果具有指標意義。ArtifactsBench 是較為成熟的官方排行榜基準，能夠在該設定下取得領先，代表 RCCA 的改進具備跨基準遷移能力（cross-benchmark transfer），而非僅過擬合（overfitting）到 MiniAppBench 的特定題型。

最後，**SFT 模型僅提升 4.48 分**而 RCCA 能進一步拉開差距，暗示單純的監督式微調（supervised fine-tuning）在捕捉複雜互動行為上存在瓶頸；強化學習（RL）階段透過環境回饋與精細信用分配，能夠有效補足這段差距。

##### 3. 需要注意的解讀限制
儘管數據亮眼，但從現有片段中無法得知以下細節：
- 是否進行了充分的消融實驗（ablation studies）以區分「階層式獎勵」與「詞元層級歸因」各自的貢獻？
- 評估器（evaluator）本身是否開源或經過人工校驗？其歸因準確率如何？
- 訓練資料規模、模型大小、訓練步數等超參數尚未揭露，因此難以判斷增益是否來自方法本身或規模效應。

#### 與現有研究的比較

##### 1. 相對於互動式網頁生成基準
過去研究如 WebDev Arena、ArtifactsBench、MiniAppBench、DashArena 等主要聚焦於如何評估互動式輸出，採用人工偏好、視覺品質、功能性需求或動態互動作為指標。這些工作強調「應用程式應被視為端到端的使用者面向產物」，但較少探討如何將這些評估轉化為訓練訊號。RCCA 的貢獻在於承接這一轉向，並進一步回答：如何將結構化、需求層級的評估結果轉換為有效的強化學習訓練訊號。

##### 2. 相對於標準 GRPO 與 RLHF
GRPO 透過群體相對基準（group-relative baseline）避免額外訓練價值模型（value model），在大型語言模型強化學習中廣泛應用。然而，在互動式網頁生成這類結構化輸出任務中，GRPO 的序列層級獎勵會喪失局部資訊。RCCA 保留了 GRPO 的群體相對優勢估計，但透過階層式獎勵與詞元層級歸因改善了其信用分配（credit assignment）能力。

##### 3. 相對於細粒度回饋研究
近期研究在推理與可驗證任務中探索了過程層級、片段層級與詞元層級回饋，例如利用步驟正確性、中間結果或自然語言批評來引導模型。RCCA 與這些工作的共同點在於都試圖縮小「評估訊號」與「策略更新」之間的顆粒度差距。不同之處在於，RCCA 專注於「程式碼區域」與「功能性需求」之間的對應，並且將自然語言歸因對齊到生成的詞元，這在互動式網頁應用生成領域較為少見。

##### 4. 侷限性
- **評估器品質依賴**：RCCA 的效果高度仰賴評估器能否準確判斷評分準則並產生正確的文字歸因。若評估器本身有偏誤，錯誤的歸因會將梯度導向錯誤的程式碼片段。
- **領域侷限**：目前方法針對互動式網頁應用設計，雖然概念可遷移，但將 RCCA 應用到其他程式語言或互動形式（如行動應用、桌面軟體）仍需重新設計評估器與歸因機制。
- **計算成本**：執行應用程式、收集互動軌跡、進行多階段評估與文字歸因，均會增加每次 RL 迭代的計算與延遲成本，可能限制大規模應用。
- **可解釋性與穩定性**：詞元層級權重雖然提升了信用分配，但也可能放大評估器雜訊，導致訓練不穩定，需要額外的正則化或歸因置信度機制。

#### 未來研究方向

##### 1. 擴展到其他互動式產物形式
RCCA 的核心思想——將需求層級回饋對齊到程式碼區域——可應用於行動應用、桌面 GUI、遊戲腳本、資料視覺化儀表板，甚至機器人控制程式。未來研究可探索如何為不同領域設計對應的評分準則與歸因機制。

##### 2. 自動化與學習式歸因
目前 RCCA 依賴評估器產生文字歸因。未來可發展「歸因模型」（attribution model），透過學習方式自動定位負責任的程式碼片段，減少對人工設計評估器的依賴，並提升歸因速度與規模。

##### 3. 多模態與視覺回饋的整合
互動式應用的正確性不僅體現在功能上，也體現在視覺佈局與使用者體驗。將截圖比對、視覺語言模型（vision-language models）的回饋納入 RCCA 的歸因與獎勵設計，是極具潛力的方向。

##### 4. 與代理基礎設施的深度融合
AWorld 等代理執行環境提供了真實世界互動能力。未來可將 RCCA 與這類環境更緊密整合，讓模型在更長的互動軌跡中學習，並處理多步驟、多頁面的複雜應用生成任務。

##### 5. 強化學習穩定性與歸因置信度
為了降低錯誤歸因帶來的負面影響，未來可引入歸因置信度（attribution confidence）或對抗性歸因驗證，並結合 KL 散度約束、獎勵塑形（reward shaping）等技術，提升訓練穩定性。

##### 6. 可解釋性與人機協作
RCCA 產生的文字歸因本身可作為人類開發者理解模型行為的介面。未來可研究如何將這些歸因轉化為可操作的除錯建議，或讓人類在迴路中（human-in-the-loop）修正歸因，進一步提升模型可靠性。

## 論文問答

**Q1：RCCA 想要解決的核心問題是什麼？**

A：RCCA 針對的是互動式網頁應用生成情境，在這種任務中，模型必須把自然語言請求轉換成可執行且使用者可操作的 HTML、CSS 與 JavaScript 程式碼。與傳統程式碼生成不同，應用程式的正確性取決於多項使用者面向的功能性需求，例如點擊按鈕後是否開啟面板、輸入欄位是否正確更新內容等。標準 GRPO 把這些結構化的功能結果壓縮成單一的序列層級獎勵，並將優勢平均分給所有詞元，導致信用分配變弱，無法讓模型知道哪些程式碼區域該為成功或失敗負責。

**Q2：為什麼標準 GRPO 在互動式網頁應用生成中會失效？**

A：標準 GRPO 雖然能透過群體相對基準判斷哪一個生成的應用程式整體表現較好，但它把多個功能性評分準則的結果合併成一個純量獎勵。接著它把這個群體相對優勢均勻地套用到整個序列的所有詞元上，使得與錯誤無關的程式碼片段也獲得相同的更新訊號。這種回饋粒度與策略最佳化粒度之間的不匹配，會削弱模型學習特定實作修正的能力，因為它無法區分事件處理器、狀態更新或 CSS 選擇器等局部程式碼的責任。

**Q3：局部化的信用分配為什麼對這類任務特別重要？**

A：在互動式網頁應用中，許多使用者可見行為都可以追溯到具體且局部的實作選擇，例如某個事件處理器、某段狀態更新、某個 DOM 片段或某條 CSS 選擇器。如果能將功能層級的回饋對應到這些負責任的程式碼片段，模型就能把學習重點放在真正需要修改的地方，而不是對整段程式碼一視同仁地調整。這不僅能提升學習效率，也能避免正確的程式碼區域被錯誤地懲罰，從而產生更穩定、可解釋的訓練訊號。

**Q4：RCCA 的核心方法包含哪些主要步驟？**

A：RCCA 首先以明確的功能性評分準則來建構訓練任務，讓每個任務都有可驗證的使用者面向行為目標。接著它設計了一個階層式獎勵，依序檢查輸出格式有效性、原始碼有效性、執行時期有效性以及評分準則層級的功能正確性。最後，RCCA 利用評估器產生的文字歸因，把每個功能性結果對應到負責任的程式碼片段與生成的詞元，並用這些對應關係來加權 GRPO 目標，使相關詞元獲得更強的優化訊號。

**Q5：RCCA 相較於標準 GRPO 的關鍵創新在哪裡？**

A：RCCA 的關鍵創新在於把評分準則層級的功能性回饋轉換成局部化的最佳化訊號，而不是只使用單一整體分數。它透過階層式獎勵把不同階段的失敗區分開來，讓群體相對最佳化有更清楚的獎勵結構。此外，它引入評估器生成的文字歸因，並將這些歸因對齊到生成的詞元，從而實現針對性加權，讓與功能結果相關的程式碼區域獲得更大的梯度更新。

**Q6：為什麼 RCCA 要採用階層式獎勵設計？**

A：階層式獎勵能夠區分格式失敗、原始碼失敗、執行時期失敗與功能性失敗這四種不同層次的問題，而不是把所有情況混為一談。這樣的設計讓無效產物、損壞程式、執行時錯誤與部分正確的應用程式各自得到不同的獎勵訊號，使群體相對最佳化能夠更精確地辨識樣本間的差異。相較於單一的整體分數，階層式獎勵提供了更清晰的學習結構，有助於模型逐步學會產出格式正確、可執行且功能完整的互動式應用。

**Q7：論文在哪些基準測試上評估 Ling-RCCA-Flash？**

A：論文主要在 MiniAppBench 與 ArtifactsBench 兩個基準上進行評估，這兩個基準都著重於互動式網頁應用的端對端功能正確性與使用者體驗。比較對象包括基礎模型 Ling-3.0-Flash、監督式微調模型、Claude Opus 4.5 以及 GPT-5。這些跨模型與跨基準的比較能夠檢驗 RCCA 是否能帶來可轉移的實作層級提升，而不只是單一測試的過擬合。

**Q8：Ling-RCCA-Flash 取得了哪些關鍵實驗結果？**

A：在 MiniAppBench 上，Ling-RCCA-Flash 獲得 41.25 分，比 Ling-3.0-Flash 進步了 32.20 分，並且小幅超越 Claude Opus 4.5。在 ArtifactsBench 上，它達到 76.19 分，比監督式微調模型提升了 4.48 分，並在官方排行榜設定下超越 GPT-5 達 3.64 分。這些結果顯示 RCCA 不僅能顯著提升目標基準表現，也能帶來跨基準的可轉移實作能力。

**Q9：從實驗設計來看，RCCA 的哪些組件可能對結果貢獻最大？**

A：雖然提供的上下文未詳細列出每一項消融實驗，但從方法設計可以推論，階層式獎勵與評估器文字歸因的對齊是兩個核心貢獻來源。階層式獎勵讓模型能夠區分不同階段的失敗，避免所有錯誤都被視為同等嚴重；而文字歸因對齊則把功能回饋局部化到具體詞元，強化了信用分配。兩者結合使 GRPO 能夠針對真正影響功能正確性的程式碼區域進行更新，從而帶來顯著的效能提升。

**Q10：RCCA 在實務上可以應用在哪些場景？**

A：RCCA 非常適合用於低程式碼或無程式碼平台，讓使用者透過自然語言描述就能生成可互動的儀表板、表單、資料視覺化介面或小型工具應用。它也能加速產品原型設計，讓設計師或產品經理快速把想法轉換成可點擊、可操作的網頁原型。此外，任何需要把結構化環境回饋轉換成模型訓練訊號的互動式生成任務，例如教育用的互動習題或內部管理後台，都可能受益於 RCCA 的局部化信用分配機制。

**Q11：若要把 RCCA 落地成產品，需要考慮哪些因素？**

A：首先需要一個穩定且安全的執行環境來執行與評估生成的 JavaScript 程式碼，避免惡意程式碼或無限迴圈影響系統。其次，評估器必須能夠產生高品質的文字歸因，並且準確地把功能性結果對應到正確的程式碼片段，否則局部化加權可能反而誤導模型。此外，評分準則的設計、執行時的延遲與成本、以及生成內容的安全性與可維護性，都是在產品化過程中必須仔細權衡的議題。

**Q12：RCCA 對整個研究領域可能帶來什麼影響？**

A：RCCA 體現了從代理基礎設施到模型訓練的典範轉移，強調執行環境不僅能用來評估，也能提供環境中介的訓練訊號。它展示了如何把結構化、需求層級的回饋轉換成有效的強化學習訊號，這對其他需要與環境互動的生成任務具有參考價值。透過在 MiniAppBench 與 ArtifactsBench 上的跨基準進步，RCCA 也證明了局部化信用分配能帶來可轉移的實作層級提升，可能推動更多針對互動式應用生成的訓練方法研究。

**Q13：RCCA 目前可能存在哪些限制？**

A：RCCA 需要預先定義的功能性評分準則以及能夠執行與評估應用程式的環境，這在資料準備與基礎建設上的成本較高。評估器產生的文字歸因品質會直接影響信用分配的準確性，如果歸因錯誤，模型可能學到錯誤的對應關係。此外，目前的設計主要針對可執行、可驗證的功能性需求，對於更主觀的使用者體驗、視覺美感或長期互動流暢度等面向，可能還需要額外的評估機制來補充。

**Q14：在哪些情況下 RCCA 可能會失敗或表現不佳？**

A：當應用程式出現複雜的多步驟互動錯誤，且多個程式碼區域彼此牽連時，評估器可能難以準確歸因責任，導致局部化加權效果下降。如果生成的程式碼在格式或原始碼層級就已經嚴重錯誤，階層式獎勵會給出較低的訊號，但模型仍需要額外學習才能修復根本的語法或結構問題。另外，當評分準則無法完整涵蓋使用者需求，或環境執行結果具有不確定性時，RCCA 的訓練訊號也可能變得不穩定。

**Q15：未來可以朝哪些方向延伸 RCCA？**

A：未來可以發展更強大的自動評分準則生成技術，減少人工設計準則的成本，並讓方法能擴展到更多領域。也可以改進評估器的歸因能力，例如結合執行時的互動軌跡與程式碼覆蓋率資訊，讓責任定位更精確。此外，將 RCCA 應用到其他可執行環境，例如行動應用、遊戲介面或機器人控制，並結合人類偏好回饋與多模態訊號，都是值得探索的後續方向。

## 實務應用指南

### 適用場景

1. **低程式碼／無程式碼平台的前端生成器**：企業內部工具或 SaaS 平台可將使用者的自然語言需求轉為可執行的 HTML/CSS/JavaScript 應用。RCCA 的評分準則層級回饋特別適合「按鈕點擊後開啟面板」「表單輸入後更新狀態」等互動細節的優化，避免生成外觀正確但功能缺失的半成品。

2. **設計稿到可互動原型的自動轉換**：產品設計團隊可將 Figma 或文字描述轉為可點擊原型，並以功能性需求（rubric）驗證每個互動路徑。RCCA 能將評估器發現的問題歸因到特定事件處理器或 DOM 片段，加速迭代。

3. **教育程式碼生成與自動批改**：程式教育平台可讓學生用自然語言描述作業需求，模型生成網頁應用後，系統依明確功能性評分準則批改。階層式獎勵能區分格式錯誤、語法錯誤、執行時期錯誤與功能未達成，給予學生更精準的回饋。

4. **客服與營運工具的動態表單生成**：金融、電商或醫療場景中，第一線人員常需要依當下需求快速產生帶有複雜互動的表單或儀表板。RCCA 可確保「選擇選項後顯示對應欄位」「提交前驗證必填項目」等區域性功能被正確實作。

5. **多輪對話式應用開發助手**：在對話過程中逐步收集需求並生成可執行程式碼的 AI 助手，可利用 RCCA 將每次執行後的環境中介訓練訊號轉為局部化更新，持續改善特定互動行為而非整體平均分數。

### 實作前置條件

**資料準備**
- 大量自然語言需求與對應的互動式網頁應用程式碼對（HTML/CSS/JS）。
- 每個訓練樣本需附帶明確功能性評分準則（rubric），描述可透過執行驗證的使用者行為。
- 評估器需能輸出文字歸因，指出每個 rubric 結果對應的負責任程式碼片段（如事件處理器、狀態更新、DOM 片段、CSS 選擇器）。
- 建議具備可執行環境（如瀏覽器或無頭執行環境）以產生互動軌跡與診斷證據。

**運算資源**
- 訓練大型語言模型所需的 GPU 叢集，足以執行 GRPO 群體採樣與策略更新。
- 評估階段需要可擴展的執行環境，因每個訓練樣本可能需多次執行與互動驗證。
- 儲存與處理互動軌跡、原始碼與歸因標註的後端基礎設施。

**技能需求**
- 熟悉強化學習與 GRPO 演算法。
- 具備前端開發與瀏覽器自動化測試經驗。
- 能設計與維護評估器（evaluator），包含階層式獎勵邏輯與文字歸因生成。
- 熟悉大型語言模型微調流程與分散式訓練框架。

### 實作步驟建議

1. **定義功能性評分準則（Rubric Design）**：將產品需求拆解為可執行、可驗證的單一功能項目。每個 rubric 應對應一個具體使用者行為，例如「點擊新增按鈕後，待辦事項列表新增一列」。

2. **建立可執行評估環境**：建置能執行生成程式碼、模擬使用者互動、並記錄互動軌跡的環境。此環境需能判斷輸出格式有效性、原始碼有效性、執行時期有效性與 rubric 層級功能正確性。

3. **開發階層式獎勵與歸因評估器**：實作四層級獎勵（格式、原始碼、執行時期、功能），並讓評估器在判斷每個 rubric 結果後，輸出對應負責任程式碼片段的文字歸因。

4. **建構對齊機制**：將評估器輸出的程式碼片段對齊到生成程式碼中的 token 位置，建立「rubric 結果 → 程式碼片段 → 生成詞元」的映射，作為 RCCA 權重依據。

5. **訓練 RCCA 策略**：以 GRPO 為基礎，將群體相對優勢依對齊結果加權分配到相關 token，使負責功能成敗的程式碼區域獲得更強的優化訊號。

6. **迭代驗證與部署**：在 MiniAppBench、ArtifactsBench 等基準測試驗證後，將模型整合至產品管線，並持續以真實使用者互動資料回補訓練集。

### 潛在風險與注意事項

- **評估器偏差**：若評估器對 rubric 的判斷或歸因不準，模型會學到錯誤的局部訊號。建議定期抽樣人工驗證評估器輸出，並建立歸因品質指標。
- **過度擬合訓練 rubric**：模型可能學會滿足訓練時的評分準則，但在未見過的需求上表現不佳。應保留多樣化測試集，並將 rubric 設計貼近真實使用者需求。
- **執行環境安全與成本**：自動執行生成程式碼有資安風險，需使用沙箱環境；同時大規模執行互動測試成本高昂，需評估運算預算。
- **獎勵駭入（Reward Hacking）**：模型可能找到滿足 rubric 但不符合使用者意圖的捷徑。可透過多維度評估與人類回饋機制降低風險。
- **對齊錯誤導致錯誤加權**：若程式碼片段與生成 token 的對齊不精確，無關區域可能獲得過高或過低權重。需審慎設計對齊演算法並監控權重分佈。

### 與其他技術的整合建議

- **與現有 LLM 微調管線整合**：RCCA 可疊加於現有的監督式微調（SFT）與 GRPO 流程之上，作為第二階段強化學習。先以 SFT 學會基本格式與語法，再以 RCCA 強化功能正確性。
- **與自動化測試框架整合**：將現有單元測試、端對端測試（如 Playwright、Selenium）包裝為 rubric，直接轉化為訓練訊號，降低評估器開發成本。
- **與代理執行環境（如 AWorld）整合**：利用現有代理環境執行應用、收集互動軌跡與診斷證據，再餵入 RCCA 進行訓練。
- **與人類回饋迴路整合**：將使用者回報的問題轉為新 rubric，持續擴充訓練資料，形成「部署 → 收集回饋 → 生成 rubric → 強化學習」的閉環。
- **與視覺語言模型整合**：在需求包含設計稿或截圖時，可先用視覺模型提取結構與風格資訊，再交由 RCCA 強化互動行為的正確性。

### 給不同背景讀者的閱讀建議

**初學者**：建議先理解「互動式網頁應用生成」與「強化學習」兩個基本概念，再聚焦於圖二所呈現的動機：標準 GRPO 把整個應用的成敗當成單一分數，而 RCCA 則像是一位能指出「哪行程式碼導致按鈕沒反應」的老師。不必急著理解所有數學細節，重點是掌握「評分準則 → 程式碼片段 → 詞元權重」這條核心思路。

**AI 工程師**：本論文提供了一個可直接參考的訓練框架。建議深入閱讀階層式獎勵設計與文字歸因對齊機制，並思考如何將現有評估器改寫為能輸出負責任程式碼片段的版本。實作時請特別注意評估器延遲、執行環境穩定性，以及 token 層級權重計算的效率。

**研究人員**：RCCA 的核心貢獻在於將環境中介的結構化回饋轉化為局部化策略更新，這為「可驗證獎勵強化學習」與「程式碼生成信用分配」提供了新的連結。建議關注其與 process reward、segment-level feedback、natural language critique 等研究的關係，並思考是否能將此方法擴展至後端程式、行動應用或其他可執行產物。

**產品經理**：這篇論文展示了一種讓 AI 生成「真正可用」的互動應用的方法，而非僅產出靜態程式碼。建議關注適用場景與實作前置條件，評估團隊是否具備定義 rubric、建立評估環境與持續收集互動資料的能力。關鍵決策在於：你的產品是否願意投資建立高品質的功能性評估器，因為這是 RCCA 能否發揮效果的瓶頸。
