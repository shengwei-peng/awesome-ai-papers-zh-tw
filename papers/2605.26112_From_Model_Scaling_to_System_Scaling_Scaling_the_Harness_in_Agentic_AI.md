## 摘要翻譯

本文將代理式 AI（agentic AI）的下一個主要瓶頸定位為系統擴展（system scaling），而非僅是模型擴展（model scaling）：圍繞基礎模型（foundation model）設計可稽核（auditable）、永續（persistent）、模組化（modular）且可驗證（verifiable）的架構。我們將此轉變稱為載具擴展（scaling the harness）：將圍繞基礎模型的結構化執行層（structured execution layer）視為設計、評估與最佳化的一等公民（first-class object）。儘管近期的大型語言模型（large language models）使代理人（agents）能夠使用工具（tool use）、檢索資訊（retrieval）、維持記憶（memory），並執行長程（long-horizon）工作流程（workflows），但評估在很大程度上仍以模型為中心（model-centric），經常將代理人簡化為最終任務成敗（final-task success），同時將記憶、檢索、工具使用、編排（orchestration）、驗證（verification）與治理（governance）視為次要的實作細節。這種框架日益不足，因為代理人的表現源於基礎模型、記憶底層（memory substrate）、上下文建構器（context constructor）、技能路由層（skill-routing layer）、編排迴路（orchestration loop）與驗證與治理層（verification-and-governance layer）之間的互動。這些組件共同構成代理人載具（agent harness），將模型能力轉化為長程代理人行為。我們透過三個核心瓶頸研究載具擴展：上下文治理（context governance）、可信記憶（trustworthy memory）與動態技能路由（dynamic skill routing），以及協調與約束它們的編排與治理機制。我們進一步概述載具層級基準測試（harness-level benchmarks）的研究議程，超越單次任務成功（one-shot task success），以衡量軌跡品質（trajectory quality）、記憶衛生（memory hygiene）、上下文效率（context efficiency）、通訊保真度（communication fidelity）、驗證成本（verification cost），以及隨時間推移的安全演化（safe evolution over time）。為使討論具體化，我們開發了 CheetahClaws（https://github.com/SafeRL-Lab/cheetahclaws），一個 Python 原生的參考載具（reference harness），並將其與 Claude Code 及 OpenClaw 進行比較。我們的主要主張是，代理式 AI 的未來進展對系統設計的依賴，並不亞於對更強大基礎模型的依賴。

### 核心貢獻（3～5點）
- 提出「載具擴展（Scaling the Harness）」概念，主張代理式 AI 的下一個重大瓶頸在於系統層級的架構設計，而非僅是基礎模型擴展。
- 界定構成代理人載具的六大核心組件：基礎模型、記憶底層、上下文建構器、技能路由層、編排迴路與驗證與治理層，並說明其如何將模型能力轉化為長程行為。
- 識別載具擴展的三大核心瓶頸：上下文治理、可信記憶與動態技能路由，以及協調與約束這些組件的編排與治理機制。
- 提出載具層級基準測試的研究議程，強調應超越單次任務成功，納入軌跡品質、記憶衛生、上下文效率、通訊保真度、驗證成本與安全演化等縱向評估指標。
- 開發 Python 原生參考載具 CheetahClaws，並與 Claude Code、OpenClaw 進行比較，以具體化載具設計與系統擴展的討論。

### 適合對象
從事代理式 AI 系統設計、大型語言模型應用架構、AI 基礎設施與評估方法論研究的學者與工程師；特別適合關注長程任務執行、記憶系統設計、工具編排與 AI 治理的進階研發人員與系統架構師。

## 深度分析

#### 方法論解析

本文的核心方法論並非提出單一演算法，而是建立一套 System Scaling（系統擴展）的系統級框架，將研究焦點從傳統的 Model Scaling（模型擴展）轉移至 Scaling the Harness（載具擴展）。作者主張，Agentic AI（代理式 AI）的下一個重大瓶頸不在於 Foundation Model（基礎模型）本身的參數量或後訓練強度，而在於圍繞模型之周邊架構的設計、評估與最佳化。此一架構被命名為 Agent Harness（代理人載具），其功能定位為 Structured Execution Layer（結構化執行層），負責將基礎模型的 Raw Reasoning Capability（原始推理能力）轉譯為可持續的 Long-horizon（長期）行為。

在框架設計上，作者將 Harness 視為 System Infrastructure（系統基礎設施），明確區分出六大互動組件：Foundation Model（基礎模型）、Memory Substrate（記憶底層）、Context Constructor（上下文建構器）、Skill-Routing Layer（技能路由層）、Orchestration Loop（編排迴路），以及 Verification-and-Governance Layer（驗證與治理層）。這些組件並非單純的實作細節，而是決定代理人最終行為的一級設計對象。進一步地，框架在時間維度上提出 Prompt、Skill 與 Memory 作為 Temporal Layers（時間層次），強調執行過程中的狀態演變與跨回合資訊流動。

針對系統擴展的三大瓶頸，作者分別提出分析維度：
1. **Context Governance（上下文治理）**：超越單純擴充上下文長度，轉而探討「應檢索什麼、如何壓縮、如何排序、何時刷新、何者可信、何者應保持活躍」等治理問題。
2. **Trustworthy Memory（可信記憶）**：記憶的困難不在於儲存容量，而在於 Memory Hygiene（記憶衛生），包含如何避免 Staleness、Drift、Contamination 與 Over-generalization，並確保在正確時間檢索到正確資訊。
3. **Dynamic Skill Routing（動態技能路由）與 Verification（驗證）**：涉及工具與 Subagent（子代理人）的即時分派、Action Verification（動作驗證）機制，以及執行過程中的約束與稽核。

在評估方法論上，作者提出從傳統的 Outcome Metrics（結果指標）轉向 Process Metrics（過程指標），並強調需建立 Longitudinal Evaluation（縱向評估）與 Safe Evolution（安全演化）的標準。為使討論具體化，作者開發了 CheetahClaws（CheetahClaws）作為 Python-native 的 Reference Harness，並與 Production Harness（生產級載具）如 Claude Code（Claude Code）與 OpenClaw（OpenClaw）進行設計層級的系統性比較。

#### 實驗數據解讀

由於本文本質上為架構與立場論文（position paper），並非以原創對照實驗為主，因此「實驗數據」需從其引用的實證發現與提出的評估議程兩個層面加以解讀。

在支持論點的實證線索方面，作者援引多項研究結果以證明 Harness 設計的獨立影響力。SWE-agent [40] 的結果顯示，在固定 Backbone Model（骨幹模型）的前提下，僅透過 Tool Schema Design（工具綱要設計）與 Agent–Computer Interface 的重新設計，即可顯著提升 SWE-bench 的準確率。這直接證成「許多所謂的模型分數，實際上是 Model-plus-Harness Score」的核心論斷。同樣地，上下文長度的相關研究 [11, 21] 指出，更大的 Context Window 並不保證有效的資訊存取：Attention 會在長輸入上產生稀釋效應，且模型對位於上下文中段（middle）的 Evidence 偏好較低。這些發現為 Context Governance（上下文治理）的重要性提供了經驗基礎，說明單純擴充上下文屬於 Model Scaling 思維，而如何治理上下文才是 System Scaling 的問題。

在可靠性缺口（reliability gap）方面，τ-bench [43] 的數據顯示，在 Single-shot Pass Rate 下表現強勁的代理人，在 Pass^k（k 次獨立 Rollouts 的成功率）指標下可能出現性能崩潰。這暴露 Endpoint Accuracy 所隱藏的系統脆弱性，也說明為何需要 Process Metrics（過程指標）與 Trajectory Quality（軌跡品質）評估。此外，GAIA [25]、Terminal-Bench [24] 等 Realistic Benchmarks 顯示，Frontier Models 在面對多步驟工具互動與環境互動時仍顯吃力；多代理人系統 [6, 8] 雖在 Breadth-first Tasks 上優於單一代理人，卻會引入協調失敗（coordination failures），而這類問題無法被傳統的 Single-agent Metrics 捕捉。

至於 CheetahClaws 與 Claude Code、OpenClaw 的比較，本文並未提供量化性能競賽表格，而是採取質性比較，將三者的 Harness-level Design Choices 視為 System-scaling Variables 的具體實例。這種比較方式的價值在於揭示生產級系統與研究用載具在模組化、可稽核性與上下文建構策略上的設計權衡，而非宣稱某一載具在特定 Benchmark（基準測試）上絕對勝出。

#### 與現有研究的比較

相較於現有文獻普遍將 Agentic AI 視為 Foundation Model（基礎模型）加上 Prompt（提示詞）與少數工具的組合，本文的根本差異在於將 Agent Harness（代理人載具）提升為第一級的研究與設計對象。傳統研究如 ReAct [44]、Self-taught Tool Invocation [31] 與 Verbal Self-correction Loops [32] 提供了代理人運作的基本原語（primitives），而 Claude Code [3, 5]、OpenClaw [34] 與 Codex-style Harness Engineering [30] 則將這些原語封裝為可程式化的 Production Harness（生產級載具）。然而，這些現有工作大多將結果報告為「特定模型變體」的成績，較少將 Harness 本身視為可控、可重現、可獨立研究的對象。本文正是填補這一空白，主張 Harness 的設計選擇應與模型選擇分離，成為獨立的優化變因。

在記憶與檢索領域，Retrieval-augmented Generation [19] 證明了外部 Non-parametric Memory 的價值；MemGPT [29] 提出 Hierarchical Memory Management，Voyager [35] 則建立 Growing Skill Library。本文將這些進展整合進統一的 Harness Framework，並進一步指出記憶系統的難點已從「如何儲存」轉向「如何維持記憶品質與可信度」。相較於 SWE-agent [40] 聚焦於軟體工程領域的 Agent–Computer Interface 設計，本文的框架更具一般性，涵蓋 Context Construction（上下文建構）、Orchestration（編排）、Verification（驗證）與 Governance（治理）等跨領域組件。

本文也明確指出目前研究的限制：儘管 Multi-agent Systems 被廣泛討論，可靠的協作仍需 Explicit Communication Protocols 與 Uncertainty Sharing [12]，而這在現有系統中尚未成熟。此外，Agent Evolution（代理人演化）的框架——包含 Skills 更新、Memory 精煉、跨角色溝通與持續稽核——仍處於萌芽階段。這些坦承的局限反而凸顯了本文作為研究議程設定者的價值。

#### 可重現性評估

本文在可重現性方面的最大貢獻是釋出了 CheetahClaws（https://github.com/SafeRL-Lab/cheetahclaws），作為 Python-native 的 Open-source Reference Harness。這項具體實作讓抽象的 System Scaling（系統擴展）框架得以被具體檢驗與重現，研究者可直接檢視其 Memory Substrate（記憶底層）、Context Constructor（上下文建構器）與 Skill-Routing Layer（技能路由層）的互動邏輯。

由於本文屬於系統架構與設計願景論文，其「可重現性」主要體現在架構設計的透明性與參考實作的可用性，而非傳統機器學習論文所強調的固定 Dataset 與 Model Weights。作者並未宣稱釋出新的訓練資料或基礎模型權重，而是建立在現有 Foundation Model（基礎模型）之上，透過模組化設計讓其他研究者能夠替換底層模型、重複實驗。

在與現有系統的比較上，Claude Code 作為商業化 Production Harness（生產級載具），其內部細節可能未完全公開，這使得外部研究者難以精確重現其 Harness-level Design；相較之下，OpenClaw [34] 與 CheetahClaws 皆具備開源屬性，更適合作為 Harness-level 研究的 Controlled Objects。作者強調 Harness 應具備 Auditable（可稽核的）、Modular（模組化的）、Verifiable（可驗證的）與 Persistent（永續的）屬性，這些設計原則本身即為可重現性的基石，因為它們要求系統行為可被記錄、追蹤與事後審查。

#### 未來研究方向

基於本文提出的框架與未竟之處，未來研究可沿以下方向深化：

1. **Harness-level Benchmarks（載具層級基準測試）**：建立超越 One-shot Task Success（單次任務成功）的標準化測試，系統性地納入 Trajectory Quality（軌跡品質）、Memory Hygiene（記憶衛生）、Context Efficiency（上下文效率）、Communication Fidelity（通訊保真度）、Verification Cost（驗證成本）與 Safe Evolution（安全演化）等指標。

2. **Longitudinal Evaluation（縱向評估）**：從 Single Episodes（單一回合）的評估模式，轉向長時間跨度的持續追蹤。未來研究需發展能夠評估代理人在重複使用、持續互動與環境演變下之穩定性與 Drift 的方法論。

3. **Context Governance（上下文治理）演算法**：針對 Attention Dilution 與 Evidence Placement Bias，開發動態的 Retrieval、Compression、Ordering、Refreshing 與 Trust Calibration 機制，使 Context Construction（上下文建構）從經驗性工藝轉為可最佳化的科學。

4. **Trustworthy Memory（可信記憶）**：研究如何量化並抑制記憶的 Staleness、Drift、Contamination 與 Over-generalization，並建立 Calibrated Uncertainty 機制，使代理人能夠自主決定「何時檢索、何時遺忘、何時更新」。

5. **Dynamic Skill Routing（動態技能路由）與多代理人編排**：設計更精細的 Subagent（子代理人）協調協定、Uncertainty Sharing 機制，以及兼顧效率與正確性的 Action Verification（動作驗證）策略，解決 Multi-agent Systems 中的 Coordination Failures。

6. **Safe Agent Evolution（安全代理人演化）**：建立代理人在更新 Skills、精煉 Memory、跨角色溝通時的 Governance 框架與稽核標準，確保系統在適應過程中維持 Auditable（可稽核的）與 Safe。

7. **成本意識評估（Cost-aware Evaluation）**：延續 [17] 的發現，發展能將 Capability 與 Costs、Prompting Strategy、Demonstrations 分離的分析方法，建立資源效率與非帕累托最適（non-Pareto-optimal）的評估典範，使 System Scaling 的進展能被更精確地衡量。

## 論文問答

**Q1：這篇論文指出的核心問題是什麼？為何傳統的模型擴展思維已不足以推動代理式 AI 的進步？**
A：本文指出，代理式 AI 的下一個主要瓶頸並非僅在於基礎模型本身的擴展，而是在於如何擴展圍繞基礎模型的結構化執行層，也就是「載具擴展」。傳統上，領域進展多以模型擴展為主軸，強調更大的模型規模、更多的訓練資料與更高的基準測試分數；然而當基礎模型被嵌入工具、終端機、瀏覽器與外部服務後，其行為已不再由模型單獨決定，而是由整個系統的互動所塑造。因此，僅將評估焦點放在模型層級，會忽略記憶底層、上下文建構器、技能路由層、編排迴路與驗證與治理層等關鍵組件對長期行為的影響，導致無法解決長程任務中的可靠性缺口。

**Q2：現有的模型中心化評估方法為何在代理式 AI 中失效？**
A：現有評估大多將代理人簡化為單次任務成功與否的最終結果，並將記憶、檢索、工具使用、編排與治理視為次要的實作細節。這種框架日益不足，因為代理人的實際表現是從基礎模型與周邊系統組件的互動中湧現出來，而非僅由模型的原始推理能力決定。例如，τ-bench 的研究顯示，在單次通過率下表現強勁的代理人，在多次獨立推演的 pass^k 評估中可能崩潰，這種可靠性缺口正是端點準確率所掩蓋的系統性問題。

**Q3：為何「載具擴展」在當前階段特別重要？**
A：作者主張，一旦基礎模型達到足夠的能力門檻，長期代理人效能的額外增益將越來越依賴周圍系統的設計品質。近期實證發現，例如 SWE-agent 的研究表明，僅重新設計代理人與電腦的介面（即載具層面），即使骨幹模型固定，也能顯著提升基準測試準確度。這顯示實用的代理人能力並非僅來自下一個詞元預測，而是來自基礎模型與載具的協同作用，因此將結構化執行層視為設計與分析的一等公民，是突破當前瓶頸的關鍵。

**Q4：本文提出的核心方法與框架是什麼？**
A：本文發展了一個以系統為中心的代理式 AI 框架，明確將「代理人載具」界定為圍繞基礎模型、使其轉化為長期行為的結構化系統基礎設施。此框架將骨幹模型的推理能力與系統因素分離，後者涵蓋記憶、上下文建構、動態技能路由、編排以及驗證與治理等層級。透過將載具視為可設計、可評估且可最佳化的一等對象，研究者得以系統性地分析各組件如何協同運作，而非僅關注單一模型的輸出品質。

**Q5：本文在載具設計上的關鍵創新與設計選擇為何？**

## 實務應用指南

### 適用場景

**1. 企業級長程工作流程自動化**
適用於動輒數十至數百步的跨系統業務流程，例如採購審批、供應鏈調度或保險理賠。這類場景需要代理人載具具備永續記憶、可稽核的編排迴路，以及動態技能路由，才能在數小時甚至數天的時間跨度中維持上下文治理與軌跡品質，而非僅依賴單次提示詞的單次任務成功。

**2. 軟體工程智慧輔助系統**
如 Claude Code 或 SWE-agent 所示，程式碼生成已從「補全函式」演變為長期專案維護。實作時需圍繞骨幹模型設計結構化執行層，包含專案記憶底層、工具綱要設計與失敗稽核機制，以確保代理人在修改多個檔案、呼叫測試與版本控制工具時，仍保持記憶衛生與動作可驗證性。

**3. 金融合規與稽核代理**
金融業對可稽核性與驗證成本極度敏感。代理人載具必須在檢索法規、比對交易與生成報告的過程中，提供完整的動作驗證鏈與記憶來源追溯，避免記憶汙染或過度概化導致合規缺口。此處的系統擴展重點在於驗證與治理層，而非單純提升基礎模型的推理能力。

**4. 醫療照護協調與追蹤**
跨科別、跨機構的病患照護涉及多代理人協作（如排程、用藥提醒、病歷彙整）。系統需支援縱向評估，追蹤數週至數月間的記憶一致性與通訊保真度，並建立安全演化標準，確保任何技能或記憶更新不會逆轉先前的醫療決策協議。

**5. 科研實驗室知識管理**
研究型組織需管理實驗記錄、文獻回顧與儀器操作手冊。透過載具擴展，可將基礎模型嵌入具備可信記憶的系統中，自動偵測文獻 staleness、整合新實驗數據，並透過上下文效率最佳化，避免研究人員被過期或冗餘資訊淹沒。

### 實作前置條件

**資料**
- 結構化與非結構化領域知識庫（如技術文件、法規、歷史工單）
- 工具綱要（Tool Schemas）與 API 規格，明確定義每項技能的輸入輸出與副作用
- 互動軌跡日誌，用於後續的過程指標分析與記憶衛生稽核
- 人類示範或回饋資料，用於校準動態技能路由與驗證閾值

**運算**
- 骨幹模型推理端點（可為私有部署或 API）
- 記憶底層儲存（向量資料庫、圖資料庫、物件儲存混合架構）
- 檢索與上下文建構服務（需支援即時壓縮、排序與刷新）
- 編排與驗證叢集（用於執行多步迴路、子代理人排程與動作驗證）

**技能**
- 系統架構設計：能將記憶、上下文、路由、驗證視為獨立模組
- 提示詞工程與工具設計：熟悉 ReAct、SWE-agent 等模式，並能設計領域專用綱要
- 可觀測性與 SRE：建立分散式追蹤、記憶漂移警報與失敗稽核管線
- 領域專家知識：確保驗證與治理層的規則符合業務與法規要求

### 實作步驟建議

**步驟一：固定骨幹模型基線**
選定一個能力足夠的基礎模型後即凍結版本，明確其原始推理能力邊界。後續所有性能提升應來自載具擴展，而非不斷更換模型，以確保實驗變因可控。

**步驟二：設計模組化載具架構**
依據論文框架，將系統劃分為記憶底層、上下文建構器、技能路由層、編排迴路與驗證與治理層。各層級需定義清晰介面，支援獨立迭代與替換，例如可將 CheetahClaws 的 Python 原生設計作為初始參考架構。

**步驟三：建立上下文治理機制**
實作「什麼該被檢索、壓縮、排序、刷新、信任與保持活躍」的規則。避免僅擴增上下文長度；應主動治理，例如針對「Lost in the Middle」現象設計證據重排策略，並監控上下文效率。

**步驟四：建構可信記憶層**
設計記憶儲存結構（短期工作記憶、長期情節記憶、程序技能記憶），並內建記憶衛生機制：過期偵測、來源追溯、防汙染過濾器與漂移校正。記憶不應只是儲存，而需具備品質控管。

**步驟五：實作動態技能路由**
定義技能註冊表與子代理人通訊協定，使系統能依任務情境即時分派工具或子代理人。搭配不確定性共享機制，讓路由決策能基於置信度進行，而非硬性規則。

**步驟六：嵌入驗證與治理迴路**
在關鍵動作後加入動作驗證節點，建立失敗稽核日誌。設計分層驗證策略以降低驗證成本：高風險操作（如交易、部署）需嚴格驗證，低風險操作可採抽樣或延遲驗證。

**步驟七：導入縱向評估與安全演化**
從單次任務成功的結果指標，轉向過程指標與縱向評估。持續監控軌跡品質、記憶衛生、通訊保真度與驗證成本。任何技能或記憶的更新皆需通過回歸測試與人類迴路核准，實現安全演化。

### 潛在風險與注意事項

**模型中心迷思**
最常見的陷阱是將所有任務失敗歸因於基礎模型能力不足，而忽視載具設計缺陷。實務上，重新設計工具綱要或上下文建構器往往比更換模型更能顯著提升長期表現。

**記憶汙染與漂移**
代理人可能將錯誤推論、過時資訊或隱私資料寫入長期記憶，導致持續性錯誤。應實施記憶版本控制、來源追溯與定期清理，並對寫入記憶的操作本身進行驗證。

**上下文稀釋與注意力偏誤**
即使基礎模型支援長上下文，資訊仍可能因注意力稀釋而遺失。避免盲目塞入全文；應採用主動檢索、摘要與重排策略，並監控模型對不同位置證據的利用率。

**多代理人協調失敗**
引入子代理人並不保證協作效益，反而可能因通訊失真或目標衝突而降低可靠性。必須建立顯式通訊協定、共享不確定性表示，並在編排迴路中設計衝突解決與回退機制。

**驗證成本爆炸**
隨著步驟增加，逐動作驗證可能消耗大量資源。需設計成本感知的驗證策略，例如關鍵路徑驗證、批次驗證或輕量級語義檢查，避免驗證本身成為系統瓶頸。

**安全演化缺口**
代理人若具備自我更新技能或記憶的能力，可能產生不可預期的行為漂移。任何演化機制都應具備沙箱測試、漸進式發布與緊急回滾能力，並維持全程可稽核。

### 與其他技術的整合建議

**RAG 與向量資料庫**
不要將 RAG 僅視為「片段檢索+填入提示詞」。應將其升級為治理導向的記憶底層，整合記憶衛生、過期偵測與來源追溯，並與上下文建構器協同設計，確保檢索結果經過壓縮與可信度評分後才進入模型視野。

**企業核心系統（ERP、CRM、CI/CD）**
透過標準化工具綱要銜接既有 API，避免為每個系統客製化提示詞。將企業系統視為技能註冊表中的外部工具，由技能路由層統一調度，並由驗證與治理層確保呼叫符合業務規則與資安政策。

**可觀測性堆疊（OpenTelemetry、Tracing）**
將載具層的每個決策點（上下文建構、記憶檢索、技能路由、動作驗證）輸出為結構化追蹤資料。這不僅有助於除錯，更是實現失敗稽核與軌跡品質量化的基礎設施。

**LLMOps 與 MLOps 平台**
將代理人載具視為需版本控制的軟體元件，而非一次性提示詞。利用 LLMOps 平台進行載具層的 A/B 測試、漸進式發布與效能迴歸測試，特別針對縱向評估指標建立長期監控儀表板。

**現有多代理人框架（如 LangGraph、AutoGen）**
這些框架提供了便捷的路由與圖結構，但往往缺乏嚴謹的驗證與治理層。整合時應補強記憶衛生、動作驗證與安全演化機制，避免將「能跑」的多代理人原型直接投入生產。

### 給不同背景讀者的閱讀建議

**初學者**
請將「載具擴展」理解為「好車不僅需要強勁引擎，還需要底盤、傳動與煞車系統」；本文的核心在於指出代理式 AI 的下一步瓶頸不在於基礎模型這顆引擎，而在於周圍的結構化執行層。建議從第三章的系統框架與 CheetahClaws 參考實作開始，先建立對記憶、上下文與技能路由的直觀認識，再回頭細讀模型擴展的相關文獻。

**AI 工程師**
本文是你從「提示詞調校」邁向「系統工程」的路線圖。請重點研讀第 4 章的三大瓶頸（上下文治理、可信記憶、動態技能路由）以及 CheetahClaws 的設計選擇，對照你目前使用的框架（如 Claude Code 或 OpenClaw）檢視其載具層的成熟度。實作時優先建立可觀測的編排迴路與記憶衛生管線，再逐步加入驗證與治理層。

**研究人員**
本文提出了一個將代理人載具視為頭等設計物件的框架，並主張從結果指標轉向過程指標與縱向評估。建議深入閱讀第 5 章的評估議程，特別是軌跡品質、記憶衛生、通訊保真度與安全演化的測量方法。若你正在設計基準測試，請思考如何讓評量能區分模型能力與載具設計的貢獻，避免兩者混為一談。

**產品經理**
這篇文章揭示了為何許多代理式 AI 的概念驗證（PoC）難以產品化：團隊往往過度投資於模型選型，卻低估了記憶一致性、稽核軌跡與長期可靠性的系統成本。請聚焦於「系統擴展」的商業意涵——它意味著產品護城河將來自載具層的模組化設計與安全演化能力，而非單純呼叫最新模型。在規劃路線圖時，建議將上下文治理與驗證成本納入總擁有成本（TCO）評估。
