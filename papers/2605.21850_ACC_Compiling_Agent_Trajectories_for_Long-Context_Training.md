## 摘要翻譯

近期智慧代理人（agents）的發展，再次凸顯了對大型語言模型（LLM）長上下文推理（long-context reasoning）能力的需求。然而，為了訓練 LLM 具備此能力，往往需要成本高昂的長文件整理（long-document curation）或啟發式上下文合成（heuristic context synthesis）。我們觀察到，智慧代理人（agents）在解決問題時會產生大量的代理人軌跡（agent trajectories），在諸多回合（turns）中進行工具呼叫（tool calls）、接收環境觀察（environment observations）；回答原始問題（original question）所需的證據（evidence）因此分散於這些回合之中，需要整合遠距上下文片段（distant context segments）。儘管如此，標準的智慧代理人監督式微調（SFT）會遮罩工具回應（tool responses），僅訓練回合級工具選擇（turn-level tool selection），因而形成監督盲點（supervision blind spot），使這些分散的訊號（signals）未能被利用。我們提出智慧代理人上下文編譯（Agent Context Compilation, ACC），將來自搜尋代理人（search agents）、軟體工程（SWE）代理人（software engineering agents）與 SQL 代理人（SQL agents）的軌跡轉換為長上下文問答對（long-context QA pairs），結合原始問題（original question）與跨多個回合（turns）所收集的工具回應（tool responses）和環境觀察（environment observations），訓練模型在不使用工具（tool use）的情況下直接回答。這使得問題與證據（evidence）之間的依賴關係（dependencies）變得明確，無需額外人工標註（human annotation），即可直接監督（direct supervision）針對遠距上下文片段（distant context segments）的長上下文推理（long-context reasoning）。ACC 是一種簡潔而有效的方法，可與任何現有的長上下文延伸（long-context extension）或訓練方法結合，提供可擴充的（scalable）監督式微調（SFT）資料。我們透過 MRCR 與 GraphWalks 在長程依賴建模（long-range dependency modeling）任務上驗證 ACC，這兩項具挑戰性的基準測試（benchmarks）需要跨回合共指消解（cross-turn coreference resolution），並在延伸上下文（extended context）上進行圖遍歷（graph traversal）。使用 ACC 訓練 Qwen3-30B-A3B，在 MRCR 上達到 68.3（+18.1），在 GraphWalks 上達到 77.5（+7.6），表現與 Qwen3-235B-A22B 相當，同時保留在 GPQA、MMLU-Pro、AIME 與 IFEval 上的通用能力（general capabilities）。進一步的機制分析（mechanism analysis）顯示，經 ACC 訓練的模型展現出任務自適應注意力重組（task-adaptive attention restructuring）與專家專門化（expert specialization）。

### 核心貢獻（3～5點）
- 提出智慧代理人上下文編譯（ACC），將搜尋、軟體工程與資料庫查詢代理人的多回合軌跡轉換為長上下文問答對，使原始問題與分散證據間的依賴關係顯式化，無需額外人工標註即可直接監督長上下文推理。
- 解決標準智慧代理人監督式微調（SFT）因遮罩工具回應而產生的監督盲點，有效利用跨回合分散的證據訊號進行訓練。
- 在 MRCR 與 GraphWalks 等需跨回合共指消解與圖遍歷的長程依賴建模任務上顯著提升模型表

## 深度分析

#### 方法論解析

本文的核心貢獻在於揭示並解決標準智慧代理人（agent）監督式微調（Supervised Fine-Tuning, SFT）中存在的**監督盲點（supervision blind spot）**。在傳統的多回合（multi-turn）代理人軌跡（agent trajectory）訓練中，模型僅被監督去學習「下一個動作」或「回合級工具選擇（turn-level tool selection）」，而工具回應（tool response）與環境觀察（environment observation）通常被遮罩（mask）處理。這導致一個關鍵問題：回答原始問題（original question）所需的證據（evidence）其實分散在跨越多個回合的遠距上下文片段（distant context segment）中，但模型從未接受過「整合（integration）這些分散的證據（scattered evidence）」的直接監督（direct supervision）。

智慧代理人上下文編譯（Agent Context Compilation, ACC）的方法論極具巧思：它將完整的代理人軌跡——包括搜尋代理人（search agent）的網頁結果、軟體工程（Software Engineering, SWE）代理人的原始碼與執行輸出、以及 SQL 代理人的資料庫查詢結果——編譯成單一的長上下文問答對（long-context QA pair）。具體而言，ACC 將原始問題與多回合收集到的所有工具回應及環境觀察拼接為「編譯後上下文（compiled context）」，並以代理人的最終答案作為標準答案，形成一個無需額外人工標註（human annotation）的長上下文訓練樣本。

這個做法的關鍵在於**強制模型進行無工具（tool-free）的直接推理**。不同於標準代理人微調中模型逐步呼叫工具，ACC 訓練要求模型在面對編譯後的長上下文時，直接從中抽取並整合資訊以產生答案。這使得問題與證據之間的依賴（dependency）關係被顯式地（explicitly）呈現，從而讓模型學習到真正的長上下文推理（long-context reasoning）能力，而非僅是學習工具使用的表面模式。此外，ACC 作為一種資料層面的轉換技術，具備高度的方法論相容性，可與任何現有的長上下文擴展（long-context extension）或訓練方法結合，提供可擴充的（scalable）監督式微調資料來源。

#### 實驗數據解讀

作者在長程依賴建模（long-range dependency modeling）的兩個高難度基準測試（benchmark）——MRCR（Multi-Round Coreference Resolution）與 GraphWalks——上驗證 ACC 的有效性。這兩項測試分別要求模型執行跨回合共指消解（cross-turn coreference resolution）與延伸上下文（extended context）中的圖遍歷（graph traversal），遠比傳統的單輪檢索或局部定位任務困難。

實驗結果顯示，經過 ACC 訓練的 Qwen3-30B-A3B 在 MRCR 上達到 68.3（提升 +18.1），在 GraphWalks 上達到 77.5（提升 +7.6）。這組數據極具意義：首先，30B 級別的模型透過 ACC 訓練，其長上下文能力已可與 235B 級別的 Qwen3-235B-A22B 相提並論，顯示 ACC 在模型效率（model efficiency）上的巨大增益。其次，這些提升並非以犧牲通用能力（general capability）為代價——模型在 GPQA、MMLU-Pro、AIME 與 IFEval 等涵蓋科學問答、數學推理與指令遵循的基準測試上均無顯著衰退，證明 ACC 所增強的長上下文推理能力與一般認知能力之間具有良好的正交性（orthogonality）。

更值得關注的是機制分析（mechanism analysis）的發現：ACC 訓練後的模型展現出任務自適應注意力重組（task-adaptive attention restructuring）與專家專門化（expert specialization）。這暗示模型並非透過死記硬背（rote memorization）來應對長上下文，而是發展出靈活的、依據任務需求調整的內部表徵模式。這種湧現（emergent）的結構性變化，為理解長上下文能力的神經機制提供了重要的實證線索。

#### 與現有研究的比較

現有長上下文研究大致可分為四大類別，ACC 與其相比具有明確的定位差異：

1. **架構層面修改**：如 MrRoPe、ROPE++、Native Sparse Attention 等方法透過修改位置編碼（position embedding）或注意力機制（attention mechanism）來擴展上下文視窗。ACC 不修改模型架構，而是從資料層面提供監督訊號，因此可與這些技術正交互補。

2. **長文件整理與預訓練資料建構**：Longwanjuan、LiteLong、Quest 等方法專注於在預訓練（pre-training）階段合成或篩選高品質長文件。相較之下，ACC 無需昂貴的長文件整理（long-document curation）或啟發式上下文合成（heuristic context synthesis），而是直接利用代理人軌跡這種「已內建複雜依賴結構」的現成資料，大幅降低資料準備成本。

3. **後訓練強化學習（RL）配方**：longRLVR、LongPO、LoongRL 等研究運用強化學習或偏好最佳化（preference optimization）來增強長上下文能力，通常需要精確的證據標註（evidence labeling）或複雜的獎勵設計（reward design）。ACC 則採用簡潔的 SFT 路徑，無需額外的人工標註或繁瑣的 RL 管線，卻能達到媲美甚至超越部分 RL 方法的成效。

4. **推理階段代理人框架**：QwenLong-L1.5、MemAgent 等研究在推理時（inference time）透過知識圖譜或記憶體管理來處理長上下文。ACC 的差異在於它強化的是基礎模型（base model）本身的長上下文理解能力，而非依賴外部記憶機制，這使得模型在無法使用複雜代理人框架的場景下依然表現穩健。

然而，ACC 也存在侷限：其效果高度依賴於現有代理人軌跡的品質與多樣性。若軌跡本身存在錯誤的推理鏈或工具回應品質低落，編譯後的訓練資料將繼承這些雜訊。此外，目前展示的應用範圍主要集中在搜尋、軟體工程與資料庫查詢三大領域，對於需要多模態感知或具身推理（embodied reasoning）的任務，其通用性仍有待驗證。

#### 可重現性評估

就現有預印本（preprint）揭露的資訊而言，作者尚未明確釋出開源程式碼、編譯後的資料集或模型權重（model weights）。這在可重現性（reproducibility）上構成一定程度的挑戰，特別是對於希望直接驗證 MRCR 與 GraphWalks 數據的後續研究者。

不過，ACC 的方法論本身具有極高的概念簡潔性與實作可行性。其核心僅涉及：（1）收集已驗證答案的代理人軌跡；（2）將多回合的工具回應與環境觀察按特定格式拼接至原始問題後；（3）以標準 SFT 進行訓練。這意味著具備現有代理人框架（如搜尋、SWE、SQL 代理人）與基礎模型存取權的研究團隊，理論上可在較短時間內復現（reproduce）此流程。若作者未來能釋出軌跡編譯的具體提示詞模板（prompt template）、資料過濾規則與訓練超參數（hyperparameters），將顯著提升社群的重現效率與方法論採用率。

#### 未來研究方向

ACC 的提出為長上下文訓練開闢了一條低成本、高擴充性的新路徑，未來研究可從以下數個方向深化：

1. **多模態與具身智慧代理人擴展**：當前 ACC 聚焦於文字與結構化資料。未來可將其擴展至多模態代理人軌跡，例如結合視覺觀察（visual observation）的機器人任務或圖表分析，編譯包含影像與文字的長上下文問答對，以訓練多模態大型語言模型（Multimodal LLM）的長程依賴建模能力。

2. **與強化學習的協同**：ACC 產生的高品質長上下文 QA 對，可作為強化學習（Reinforcement Learning, RL）或偏好學習（如 DPO、RLVR）的冷啟動（cold-start）資料。未來研究可探索「ACC + RL」的兩階段訓練：先以 ACC 建立基礎長上下文理解，再透過 RL 微調模型對複雜推理鏈的偏好。

3. **注意力機制的理論剖析**：本文觀察到任務自適應注意力重組與專家專門化現象，但其背後的數學機制仍不明朗。後續可透過因果中介分析（causal mediation analysis）或探針技術（probing）來量化不同注意力頭（attention head）與混合專家（Mixture-of-Experts, MoE）層在長上下文整合中的具體功能，進而設計更精確的長上下文歸納偏置（inductive bias）。

4. **規模化法則（Scaling Laws）與資料品質**：ACC 的效能增益是否隨編譯軌跡數量呈現可預測的規模化曲線？不同領域軌跡的混合比例如何影響跨領域泛化？建立 ACC 資料的規模化法則將有助於最佳化資料收集與訓練預算分配。

5. **自動化驗證與雜訊過濾**：由於 ACC 依賴代理人軌跡的正確性，發展自動化的軌跡驗證機制——例如利用輕量級驗證器（verifier）或一致性檢查（consistency check）來篩除錯誤軌跡——將是提升編譯資料品質的關鍵，也有助於將 ACC 應用於更開放、更難以驗證的領域。

6. **跨語言長上下文編譯**：當前實驗主要基於英文語境的代理人任務。將 ACC 應用於中文、日文等具有不同語法結構與指代系統的語言，並觀察跨語言遷移學習（cross-lingual transfer）的效果，將對非英語社群的長上下文模型發展具有重要價值。

## 論文問答

**Q1：為何現有方法在擴充 LLM 長上下文推理能力時面臨瓶頸？**
A：現有方法主要依賴昂貴的長文件整理或啟發式上下文合成，前者需要精確的證據標註與密集的品質過濾，後者則缺乏真實問題解決過程中複雜的依賴關係。這些限制使得可擴充的長跨度推理訓練資料難以取得，嚴重制約了模型處理延伸上下文的能力。此外，傳統的監督式微調在處理智慧代理人軌跡時，往往遮蔽工具回應，導致分散在多回合中的關鍵證據訊號無法被有效利用。

**Q2：標準智慧代理人 SFT 存在什麼樣的「監督盲點」？**
A：標準的智慧代理人監督式微調通常會遮蔽所有工具回應與環境觀察，僅針對每一回合的推理與工具選擇進行監督。這種做法使得模型無法學習如何整合散落在多個回合中的證據片段，因為這些遠距上下文片段之間的依賴關係從未被明確地納入訓練目標。結果，這些寶貴的分散訊號被浪費，形成了一個嚴重的監督盲點，阻礙了長上下文能力的發展。

**Q3：智慧代理人軌跡為何特別適合用來解決長上下文訓練的資料稀缺問題？**
A：智慧代理人在解決問題時會產生大量的多回合軌跡，這些軌跡包含多次工具呼叫與環境觀察，而回答原始問題所需的證據往往分散在這些不同的回合之中。這種自然產生的長程依賴結構，恰好提供了真實且複雜的長上下文推理範例，無需額外的人工標註即可取得。因此，利用這些軌跡作為訓練資料來源，不僅成本低廉且可擴充，還能直接對應到實際應用中所需的跨回合資訊整合能力。

**Q4：ACC 的核心運作機制是什麼？它如何將代理人軌跡轉換為訓練資料？**
A：智慧代理人上下文編譯（ACC）的核心機制是將多回合代理人軌跡中的工具回應與環境觀察，按照原始問題進行彙整與組裝，形成長上下文問答對。具體而言，它會把散落在不同回合的搜尋結果、程式碼執行輸出或資料庫查詢結果等，與原始問題拼接成單一的延伸上下文，並以代理人的最終答案作為標準答案。這樣一來，模型便能在不使用工具的情況下，直接在長上下文中進行推理並回答問題，從而獲得對遠距證據片段的明確監督。

**Q5：與現有的長上下文擴展或訓練方法相比，ACC 的關鍵創新之處在哪裡？**
A：ACC 的關鍵創新在於它直接利用現有的智慧代理人軌跡作為長上下文監督式微調的資料來源，無需修改模型架構、進行複雜的強化學習後訓練，或額外進行昂貴的人工標註。不同於啟發式合成長文件或從頭整理長文件，ACC 透過上下文編譯讓問題與分散證據之間的依賴關係變得明確，從而實現對長程推理的直接監督。此外，ACC 是一種簡單但有效的方法，能夠與任何現有的長上下文擴展或訓練方法結合，提供可擴充的監督式微調資料。

**Q6：為何 ACC 選擇讓模型「直接回答而不使用工具」，而不是繼續訓練工具使用？**
A：因為 ACC 的目標是強化模型的長上下文推理能力，而非強化其工具呼叫能力；透過將多回合的工具回應與環境觀察編譯成單一長上下文，模型被迫在沒有外部工具輔助的情況下，直接從延伸上下文中提取並整合遠距證據。這種設計使得問題與證據之間的依賴關係變得顯式且直接，讓監督訊號能夠精準地作用於長程資訊整合的過程。如果繼續訓練工具使用，模型仍可能停留在回合級的決策模式，無法有效學習如何在一次前向傳播中處理跨越多回合的複雜依賴。

**Q7：作者選擇哪些基準測試來驗證 ACC 的長程依賴建模能力？這些測試有何挑戰性？**
A：作者選擇了 MRCR（Multi-Round Coreference Resolution）和 GraphWalks 兩個基準測試來驗證 ACC 的長程依賴建模能力。MRCR 要求模型進行跨回合的共指消解，而 GraphWalks 則需要在延伸上下文中進行圖遍歷，兩者都比傳統的單回合檢索或局部資訊提取任務困難得多。這些測試特別強調模型必須整合散落在長距離上下文中的片段資訊，因此能有效衡量模型是否真正具備長跨度推理能力，而非僅僅是表面上的檢索技巧。

**Q8：ACC 在主要實驗中取得了哪些具體成果？與更大模型相比表現如何？**
A：在 Qwen3-30B-A3B 模型上使用 ACC 進行訓練後，模型在 MRCR 上獲得 68.3 分（提升 18.1 分），在 GraphWalks 上獲得 77.5 分（提升 7.6 分）。這樣的表現已經與規模大上許多的 Qwen3-235B-A22B 模型相當，顯示 ACC 能夠以較小的模型參數量達到頂尖的長上下文推理水準。與此同時，該模型在 GPQA、MMLU-Pro、AIME 和 IFEval 等通用能力基準上依然保持了原有表現，證明 ACC 並未犧牲模型的一般知識與指令遵循能力。

**Q9：除了整體性能提升外，機制分析揭示了 ACC 訓練後模型內部發生了什麼變化？**
A：機制分析顯示，經過 ACC 訓練的模型展現出任務自適應注意力重組與專家專門化的現象。這表示模型在面對不同類型的長程推理任務時，能夠彈性地調整其內部注意力模式，並讓特定的專家網路負責處理不同的長距離依賴結構。這些發現不僅解釋了性能提升的內在原因，也暗示 ACC 所培養的長上下文能力並非死記硬背，而是以靈活且任務導向的神經機制呈現。

**Q10：ACC 可以應用在哪些類型的智慧代理人上？實務上如何取得訓練資料？**
A：ACC 可應用於搜尋代理人、軟體工程（SWE）代理人以及 SQL 資料庫查詢代理人等多種類型，這些代理人在執行任務時都會產生包含多回合工具回應與環境觀察的軌跡。在實務上，開發者可以直接使用現有代理人系統在解題過程中自然產生的、且已經過答案驗證的軌跡，無需額外聘請標註人員進行長文件整理或證據標註。這使得 ACC 成為一種極具成本效益且可規模化的資料取得策略，特別適合已經部署了代理人框架的企業或研究團隊。

**Q11：對於已經具備長上下文擴展技術的模型，ACC 能帶來什麼額外價值？**
A：ACC 能與任何現有的長上下文擴展或訓練方法結合，為模型提供高品質的監督式微調資料，從而填補技術擴展後的訓練資料缺口。即使模型透過位置編碼插值或稀疏注意力機制擴大了上下文窗口，若缺乏針對長程依賴的精細監督，仍難以充分發揮硬體潛力；ACC 正好提供了這種直接且明確的長上下文監督訊號。因此，ACC 不僅能加速長上下文能力的收斂，還能確保擴展後的窗口被真正用於複雜的跨片段推理，而非僅僅是容納更長的輸入。

**Q12：ACC 對整個 LLM 領域可能帶來什麼樣的深遠影響？**
A：ACC 為長上下文訓練開闢了一條全新的資料來源路徑，將原本被忽視的智慧代理人軌跡轉化為寶貴的監督訊號，這可能改變未來長上下文模型開發的經濟學與方法論。它證明了無需昂貴的人工長文件標註或複雜的強化學習管線，也能有效培養模型的長程推理能力，從而降低技術門檻並促進更多研究與應用。長遠來看，隨著智慧代理人系統的普及，ACC 所代表的「軌跡即資料」典範有望成為持續擴充長上下文訓練語料的重要基礎設施。

**Q13：ACC 方法目前存在哪些潛在的限制或前提條件？**
A：ACC 的前提在於必須擁有已經過答案驗證的高品質代理人軌跡，如果原始軌跡本身包含錯誤的工具呼叫或錯誤的最終答案，編譯後的長上下文問答對也會繼承這些錯誤，導致監督訊號失真。此外，ACC 目前主要針對能夠明確彙整工具回應與環境觀察的任務類型進行驗證，對於需要複雜多模態互動或連續動態環境回饋的任務，其適用性仍需進一步探討。最後，由於 ACC 將多回合資訊壓縮為單一長上下文，可能會遺失部分回合間的時間順序或因果互動細節，這在某些精細推理場景中可能構成限制。

**Q14：在什麼樣的場景或任務中，ACC 可能會遭遇失敗或表現不佳？**
A：如果任務所需的證據不僅分散在多個回合中，還高度依賴回合間的動態互動順序或工具使用的副作用（例如程式碼執行後的狀態變更），那麼將這些軌跡扁平化為單一長上下文可能會破壞關鍵的因果鏈。此外，當原始問題需要模型主動探索並動態決定下一步工具呼叫時，ACC 所訓練的直接回答模式可能無法培養出這種互動式探索能力。對於那些工具回應極長且充斥大量雜訊的軌跡，若未經適當篩選與壓縮，編譯後的上下文可能會稀釋關鍵證據，反而增加模型的推理負擔。

**Q15：未來研究可以從哪些方向進一步擴展 ACC 的框架與應用？**
A：未來研究可以探索如何將 ACC 與強化學習或偏好最佳化方法結合，讓模型不僅學習長上下文整合，還能學習在長文本中進行批判性思考與自我驗證。另一個方向是發展更智慧的上下文編譯策略，例如根據資訊相關性進行選擇性彙整或層次式摘要，以處理更長、更複雜的代理人軌跡。此外，將 ACC 擴展到多模態代理人軌跡（如包含圖像、音訊或影片的環境觀察）以及跨代理人協作場景，將是進一步提升通用長上下文推理能力的重要前沿。

## 實務應用指南

### 適用場景

1. **企業內部知識問答系統**：將多步驟搜尋代理人軌跡編譯為長上下文問答對，訓練模型直接整合分散在不同文件、維基或資料庫中的證據，回答需要跨部門資訊彙整的複雜問題。
2. **軟體工程輔助工具**：利用 SWE 代理人在大型程式碼庫中跨檔案搜尋、除錯與執行測試的多回合軌跡，編譯成長上下文訓練資料，強化模型直接理解跨檔案長程依賴與錯誤根因的能力。
3. **金融與醫療結構化查詢**：將 SQL 代理人查詢多張關聯資料表、進行多輪聚合與篩選的軌跡轉換為長上下文問答對，使模型能直接基於複雜資料表關聯與歷史查詢結果進行推理。
4. **客戶服務對話根因分析**：把多輪客服機器人呼叫內部知識庫、票務系統與日誌工具的多回合軌跡編譯成單一長上下文範例，訓練模型從分散的對話片段與工具回應中直接識別核心問題與解決方案。
5. **法律與合規多文件比對**：將檢索代理人在多份法律條文、判例與合約間來回檢索的軌跡編譯為長上下文訓練資料，使模型能直接進行跨文件條文比對與多跳推理。

### 實作前置條件

- **資料**：已驗證答案的多回合代理人軌跡（包含原始問題、每回合工具回應、環境觀察與最終答案），建議至少數千至數萬條高品質軌跡。若無現成軌跡，需先建置搜尋、SWE 或 SQL 代理人並收集執行日誌。軌跡需經過答案正確性驗證與品質過濾。
- **運算**：至少具備 80GB 以上 VRAM 的 GPU（如 NVIDIA A100/H100）以進行 30B 級模型的長上下文監督式微調；若採用 LoRA/QLoRA 等參數高效技術，可降至 40GB 左右。訓練框架需支援 32K 以上序列長度與 Flash Attention 等記憶體最佳化。
- **技能**：熟悉 PyTorch/Transformers、監督式微調流程與長上下文訓練技術（如 RoPE 插值、YaRN）；具備智慧代理人系統建置經驗（工具定義、環境互動、軌跡記錄）；能執行資料清洗、長度分層與證據正確性抽樣驗證。

### 實作步驟建議

1. **軌跡收集與驗證**：部署搜尋、SWE 或 SQL 代理人，在真實或高保真模擬環境中執行任務，記錄完整多回合軌跡。過濾掉執行失敗、答案錯誤或過短（缺乏分散證據）的軌跡，確保最終答案可直接作為標準答案使用。
2. **上下文編譯（ACC）**：將每條軌跡中的原始問題與所有工具回應、環境觀察按時間順序拼接，形成「編譯後上下文」；保留原始問題與最終答案組成長上下文問答對。移除工具呼叫標記與回合界線，使模型學習直接回答而非進行回合級工具選擇。
3. **長度分層與品質過濾**：依編譯後上下文長度分層（如 8K、32K、64K、128K），確保各長度區間均有足夠樣本。檢查證據是否確實分散於多個遠距上下文片段，避免局部檢索即可回答的簡單樣本混入訓練集。
4. **訓練配置**：採用現有長上下文擴展方法（如 RoPE 插值、NTK-aware 縮放或 YaRN）將基礎模型擴展至目標長度。使用編譯後的長上下文問答對進行監督式微調，採用標準語言建模損失（**不遮罩工具回應**，讓模型學習整合分散證據）。
5. **能力驗證與迭代**：在 MRCR、GraphWalks 或自建的長程依賴基準上評估長上下文推理能力；同時在 GPQA、MMLU-Pro、AIME、IFEval 等通用能力測試上監控是否退化。若長上下文能力提升但通用能力下降，需調整 ACC 資料與通用 SFT 資料的比例。
6. **部署整合**：將訓練後的模型部署為直接推理服務，替代原本的多回合代理人迴路以減少延遲；或保留原有智慧代理人系統，僅在需要長程證據整合時切換至 ACC 訓練模型作為專門的上下文整合模組。

### 潛在風險與注意事項

- **監督盲點轉移風險**：若編譯時遺漏關鍵工具回應、順序錯亂或混入錯誤觀察，模型會學到錯誤的證據依賴關係。建議保留原始軌跡來源標記，編譯後進行抽樣人工驗證，確認問題與分散證據間的對應關係正確。
- **通用能力災難性遺忘**：過度聚焦長上下文問答可能削弱模型在短文本、工具使用或通用知識的表現。建議混合原有通用 SFT 資料與 ACC 資料（例如 1:1 或 2:1 比例），並持續監控 GPQA、MMLU-Pro、AIME 等指標。
- **上下文長度不均與訓練不穩定**：若多數樣本集中在單一長度，模型可能僅對該長度過擬合。建議採用長度分層取樣（length-based sampling）或序列打包（packing）策略，並確認位置編碼外推能力涵蓋目標長度。
- **幻覺與證據捏造**：當編譯上下文過長且證據稀疏時，模型可能產生看似合理但無軌跡支持的答案。可在編譯階段加入「證據鏈」標註，或在推論時要求模型先指出依據段落再生成答案。
- **工具依賴性降低的副作用**：ACC 訓練模型傾向直接回答，可能降低與外部工具協同的意願。若產品仍需即時工具呼叫（如即時搜尋、程式碼執行），建議僅將 ACC 應用於「長程整合」子任務，而非全面取代智慧代理人架構。

### 與其他技術的整合建議

- **與現有長上下文擴展技術整合**：ACC 可與 RoPE 插值、YaRN、NTK-aware 縮放或 Native Sparse Attention 等位置編碼／注意力機制改良並用。ACC 提供高品質長上下文訓練資料，這些技術提供架構與外推支援，兩者相輔相成。
- **與 RLHF/DPO/RL 整合**：將 ACC 編譯的長上下文問答對作為 SFT 冷啟動資料，後續接續 LongPO、longRLVR 等偏好學習方法，進一步強化模型在長文本中的事實正確性與推理穩定性。
- **與 RAG/Agent 框架整合**：ACC 訓練後的模型可作為 RAG 系統中的「重排與綜合層」（rerank-and-synthesize layer），直接處理由檢索模組提供的多份長文件；或作為智慧代理人系統中的「記憶整合模組」，負責將多回合環境觀察濃縮為決策依據。
- **與模型量化/推論加速整合**：由於 ACC 訓練後的模型需處理長序列，建議搭配 KV Cache 壓縮（如 H2O、SnapKV）、推論加速框架（vLLM、TensorRT-LLM）及 4-bit/8-bit 量化，以降低部署成本與延遲。
- **與資料合成管線整合**：若現有代理人軌跡不足，可先用 Quest、LiteLong 等長文件合成方法產生模擬問題，再驅動代理人執行並收集軌跡，形成「合成問題 → 代理人執行 → ACC 編譯」的自動化資料工廠。

### 給不同背景讀者的閱讀建議

- **初學者**：本文核心概念是「把智慧代理人多次使用工具的過程錄下來，把所有工具回應拼成一份長文件，再訓練模型直接讀懂這份長文件」。建議先理解圖一的流程，並對照日常生活中「先搜尋 A、再搜尋 B、最後綜合答案」的經驗，就能掌握 ACC 如何解決長上下文訓練資料不足的問題。
- **AI 工程師**：重點關注第三節的方法細節與實驗設定。你需要理解標準智慧代理人 SFT 為何會遮罩工具回應（造成監督盲點），以及 ACC 如何透過不遮罩、直接拼接的方式建立長程依賴監督。實作時請特別注意軌跡驗證、長度分層取樣，以及與 Flash Attention 等訓練框架的相容性。
- **研究人員**：本文的貢獻在於提出了一種可擴充的長上下文監督來源，並透過 MRCR 與 GraphWalks 驗證了長程依賴建模效果。建議深入閱讀機制分析部分（任務自適應注意力重組與專家專門化），思考 ACC 是否能在混合專家模型（MoE）中誘發更可解釋的長程路由模式，並探索 ACC 在其他智慧代理人領域（如多模態工具使用）的泛化性。
- **產品經理**：ACC 的價值在於用現有的智慧代理人執行日誌低成本地產生高價值訓練資料，無需額外人工標註長文件。評估導入時，請盤點團隊是否已累積足夠的「答案正確」的多回合軌跡資料；若已有搜尋型或程式碼型 Agent 產品，ACC 是提升長上下文能力的捷徑，但需留意通用能力監控與推論成本（長序列 = 高算力消耗）。
