## ⚡ TL;DR

現有視覺文件檢索的細粒度監督常因文字描述或區域標註而不完整或不準確。
ConceptFormer以查詢為條件學習自適應潛在概念，動態決定數量並橋接視覺證據與語義相關性。
多項基準上ConceptFormer平均NDCG@10超越視覺與OCR基線16.7%及22.1%。

## 摘要翻譯

視覺文件檢索（Visual Document Retrieval）是多模態檢索增強生成（Multimodal Retrieval-Augmented Generation, RAG）的關鍵組成部分，旨在從證據分散於文字、版面、圖表與視覺結構之中的文件集合，找出與查詢相關的頁面。近期針對細粒度監督（Fine-Grained Supervision）的研究主要依賴文字描述或局部化視覺區域（Localized Visual Regions）作為證據代理（Evidence Proxy）。然而，這類監督訊號可能忽略複雜的視覺結構，或對底層證據提供不完整且不準確的表徵。為了解決這些限制，我們提出 ConceptFormer，一個用於視覺文件檢索的潛在概念表徵學習框架（Latent Concept Representation Learning Framework）。ConceptFormer 將查詢相關證據建模為連續、以查詢為條件的潛在概念（Query-Conditioned Latent Concepts），明確地銜接局部化視覺證據（Localized Visual Evidence）與語義相關性（Semantic Relevance），無需文字中介表徵（Textual Intermediate Representations），也不直接依賴原始視覺標註（Raw Visual Annotations）。訓練過程中，ConceptFormer 利用強大的視覺-語言模型（Vision-Language Model, VLM）動態決定潛在概念標記（Latent Concept Tokens）的數量，並將這些概念作為中介表徵（Intermediate Representation），以彌合查詢與文件之間的語義差距（Semantic Gap），進而引導嵌入空間（Embedding Space）的學習。於多個視覺文件檢索基準測試的實驗顯示，ConceptFormer 在平均 NDCG@10（Average NDCG@10）上相較於最強的視覺檢索基線（Visual Retrieval Baseline）與最強的基於 OCR 的文字檢索基線（OCR-based Text Retrieval Baseline），分別達到 16.7% 與 22.1% 的相對提升。進一步分析顯示，潛在概念（Latent Concepts）能有效地連結局部化視覺證據與語義相關性，使檢索器得以同時捕捉細粒度的文字線索與複雜的文件層級視覺結構，並維持良好的檢索對齊（Retrieval Alignment）。程式碼與資料可於 https://github.com/Neuir/ConceptFormer 取得。

### 核心貢獻（3～5點）
- 提出 ConceptFormer，一個專為視覺文件檢索設計的潛在概念表徵學習框架，將查詢相關證據建模為連續、以查詢為條件的潛在概念。
- 透過潛在概念明確銜接局部化視覺證據與語義相關性，無需文字中介表徵，也不直接依賴原始視覺標註。
- 利用強大的視覺-語言模型（VLM）動態決定潛在概念標記的數量，並以這些概念作為中介表徵彌合查詢與文件之間的語義差距。
- 在多個視覺文件檢索基準測試上，相較於最強的視覺檢索基線與基於 OCR 的文字檢索基線，分別達到 16.7% 與 22.1% 的平均 NDCG@10 相對提升。
- 驗證潛在概念能同時捕捉細粒度文字線索與複雜文件層級視覺結構，並維持良好的檢索對齊。

### 適合對象
本論文適合從事多模態資訊檢索、視覺文件理解、檢索增強生成（RAG）系統、跨模態表徵學習，以及需要處理版面、圖表與視覺結構等複雜文件內容的研究人員與工程師閱讀。對於關注如何以無監督或弱監督方式學習細粒度視覺證據表徵，並提升文件檢索對齊品質的讀者尤其具有參考價值。

## 深度分析

#### 方法論解析

ConceptFormer 的核心貢獻在於將 visual document retrieval（視覺文件檢索）中的 query-document relevance（查詢-文件相關性）監督訊號，從傳統的 page-level supervision（頁面層級監督）提升到以 continuous latent concept（連續潛在概念）為媒介的 fine-grained supervision（細粒度監督）。具體而言，論文假設查詢相關的證據並非均勻分佈在整張文件影像（document image）上，而是集中在特定區域；同時，這些區域的語義又不能僅用裁剪後的 visual concept proxy（視覺概念代理）或 textual intermediate representation（文字中介表徵）完整表達。因此，ConceptFormer 提出以 query-conditioned latent concept（以查詢為條件的潛在概念）作為 intermediate representation（中介表徵），在 localized visual evidence（局部化視覺證據）與 semantic relevance（語義相關性）之間建立橋樑。

訓練流程可分為三個階段。第一階段是證據定位與容量估計：針對一個 query（查詢）與其 positive page（正樣本頁面），ConceptFormer 先利用一個具備強大 visual understanding capability（視覺理解能力）的 Vision-language model（視覺-語言模型，VLM）定位出查詢相關的頁面區域，再將這些區域對應到 retriever 自身的 visual token grid（視覺標記網格）上，藉此估計需要多少 latent concept token（潛在概念標記）才能充分表達該查詢的證據。這一步決定了 latent concept sequence（潛在概念序列）的長度，使概念容量能夠隨證據規模自適應調整，而非使用固定長度。

第二階段是概念生成：檢索器在給定查詢與相關文件的條件下，生成對應長度的 adaptive latent concept（自適應潛在概念）。這些概念是連續向量，不對應任何人類可讀的文字，也不直接等於原始視覺區域，而是學習到的 evidence representation（證據表徵）。由於它們同時以查詢與文件為條件，因此能夠編碼「這個查詢在這份文件的哪些視覺線索上應該被滿足」。

第三階段是排序分佈恢復：ConceptFormer 將生成的 latent concept 用於建立一個 ranking distribution（排序分佈），並要求該分佈能夠 recover 原本由查詢驅動的文件排序偏好（query-driven document ranking preference）。換句話說，標準的 contrastive objective（對比目標）僅要求正樣本在共享嵌入空間（shared embedding space）中比負樣本更接近查詢；而 ConceptFormer 進一步要求「透過潛在概念所誘導出的候選文件排序」與「原始查詢-文件相似度所決定的排序」一致。這相當於在 contrastive training（對比式訓練）之上加入一層以 latent concept 為媒介的知識蒸餾或輔助對齊目標，迫使 embedding space（嵌入空間）學到更細緻的 cross-modal alignment（跨模態對齊）。

推論階段則可維持一般 dual-encoder 檢索器的效率：latent concept 主要作為訓練時的 complementary relevance supervision（互補相關性監督），協助學出更 tailored visual document representation（量身打造的視覺文件表徵）；實際檢索時仍可使用學習到的 dense representation（稠密表徵）進行近似最近鄰搜尋，不必在線上重新生成概念。

#### 實驗數據解讀

論文在多個視覺文件檢索基準上進行評估，主要採用 NDCG@10（Normalized Discounted Cumulative Gain at 10）作為指標。摘要中報告的關鍵數字是：相較於最強的 visual retrieval baseline（視覺檢索基線），ConceptFormer 在 average NDCG@10（平均 NDCG@10）上取得 16.7% 的相對提升；相較於最強的 OCR-based text retrieval baseline（基於 OCR 的文字檢索基線），則取得 22.1% 的相對提升。

這兩個數字具有幾層意義。首先，22.1% 相對於 OCR 基線的增益顯示，當文件證據涉及版面配置、圖表、非文字元素時，直接處理 full-page screenshot（全頁截圖）並學習視覺語義，能顯著減少 OCR 錯誤與資訊損失（information loss）所帶來的瓶頸。其次，16.7% 相對於視覺檢索基線的增益則說明，單靠 global page context（全局頁面上下文）或全域比對仍不足以捕捉 fine-grained visual evidence（細粒度視覺證據），而 latent concept 所提供的細粒度監督能有效填補這段 semantic gap（語義差距）。

由於論文強調「diverse visual document retrieval benchmarks」，這些平均提升也暗示方法在不同文件類型（例如表單、圖表、簡報、資訊圖表）上具備一定泛化能力。進一步分析指出，學到的 latent concept 佔據 query 與 document 之間的 intermediate space（中介空間），比 textual concept proxy（文字概念代理）或 visual concept proxy（視覺概念代理）更適合進行跨模態對齊；同時 adaptive capacity analysis（自適應容量分析）顯示查詢相關證據的規模變化（scale variation）相當大，動態配置概念數量因此比固定大小（fixed-size）的表徵更能貼近實際需求。

#### 與現有研究的比較

ConceptFormer 的定位介於幾類現有方法之間，並試圖同時避免它們的缺點。

相較於傳統 OCR-based text retrieval baseline，ConceptFormer 直接以 document image 為輸入，保留了 layout-dependent structure（版面相關結構）、chart structures 與其他 non-textual elements，因此不會受到 OCR 識別錯誤與 cascading error（級聯錯誤）影響。

相較於 DSE、VisRAG、VDocRetriever 等視覺檢索方法，這些方法大多仍依賴 global matching（全域比對）與 page-level supervision，難以定位頁面內的關鍵區域。ConceptFormer 則透過 latent concept 提供細粒度的 query-document alignment 訊號，使模型能同時學到文件層級的視覺結構與查詢相關的局部線索。

相較於 ColPali 這類採用 multi-vector interaction（多向量互動）的方法，ColPali 強調在視覺標記層級進行 late interaction，能捕捉局部語義，但並未明確建立一個介於查詢與文件之間的 semantic bridge。ConceptFormer 的 latent concept 則扮演這個中介角色，將局部視覺證據壓縮成語義化的連續表徵。

相較於 ReAlign 等使用 region-level textual descriptions 的方法，ConceptFormer 不使用文字中介表徵，因此不會因為文字化過程而遺失複雜圖表或空間版面的資訊；同時它也不直接依賴 raw visual annotation（原始視覺標註）作為輸入，避免了區域裁剪可能缺乏 global page context 的問題。

然而，ConceptFormer 仍有其限制。首先，概念數量的估計與區域定位仰賴強大的 VLM，若該 VLM 對查詢相關區域的判斷有偏誤，訓練監督也會跟著偏差。其次，動態長度的 latent concept sequence 在實作上會增加批次處理與記憶體管理的複雜度。再者，latent concept 本身屬於連續隱性表徵，可解釋性較低，難以直接對應回人類可理解的文字或區域。最後，概念生成目前主要用於訓練階段，推論時並未使用，這雖然保留效率，但也意味著檢索品質完全取決於概念監督是否成功內化到 embedding space 中。

#### 可重現性評估

論文作者已將程式碼與資料公開於 GitHub（https://github.com/Neuir/ConceptFormer），這對可重現性（reproducibility）是正面訊號。開放原始碼與資料集能讓其他研究者驗證訓練流程、重跑實驗，並在此基礎上進行擴展。

不過，要達到完全可重現，仍取決於以下細節是否一併釋出：模型權重（model weights）、訓練日誌、完整超參數、隨機種子、硬體環境，以及用於區域定位與容量估計的 VLM 版本與提示詞（prompts）。特別是若論文使用封閉式 API（例如 GPT-4V 等商業 VLM）來產生偽標註，則會因 API 的非確定性、存取限制與成本而降低可重現性。此外，從 VLM 的 bounding box 對應到 retriever 的 visual token grid 的轉換規則，也需要清楚文件化，否則其他研究者難以複製相同的概念容量估計。

整體而言，ConceptFormer 在「開放程式碼與資料」這一項已達到不錯的透明度，但若缺少上述訓練細節與模型權重，重現其最佳效能仍會面臨挑戰。

#### 未來研究方向

ConceptFormer 為視覺文件檢索開啟了以 latent concept 作為中介表徵的研究方向，未來可從以下幾個面向延伸：

1. **推論階段使用 latent concept**：目前概念僅用於訓練監督，未來可探索在 inference 時也生成概念，並將其作為查詢擴展或 late interaction 的輸入，以進一步提升檢索準確率，同時研究如何控制額外計算成本。

2. **與 multi-vector retrieval 結合**：可將 ConceptFormer 的自適應概念與 ColPali 式的多向量互動整合，讓模型同時擁有語義化的概念壓縮能力與標記層級的細粒度比對能力。

3. **降低對強大 VLM 的依賴**：透過知識蒸餾或聯合訓練，將強 VLM 的定位與概念容量估計能力轉移到檢索器本身，減少對封閉式 API 的依賴，並提升方法的可擴展性與可重現性。

4. **多頁文件與文件層級檢索**：現有方法主要聚焦於單一頁面，未來可將 latent concept 擴展到多頁文件，學習跨頁的證據聚合與排序。

5. **跨語言與低資源文件類型**：驗證 ConceptFormer 在不同語言、不同版面風格或低資源文件類型上的泛化能力，並設計對應的資料增強與預訓練策略。

6. **可解釋性與人機互動**：開發將 latent concept 視覺化或對應回文件區域的方法，讓使用者能理解檢索器為何認為某頁面與查詢相關，進一步應用於多模態 RAG（multimodal retrieval-augmented generation）的下游任務。

7. **端對端 RAG 評估**：除了 retrieval 指標外，未來可評估 ConceptFormer 在實際 multimodal retrieval-augmented generation 系統中對最終生成品質的影響，確認檢索改善能確實轉化為下游應用效益。

## 論文問答

**Q1：視覺文件檢索在現代多模態檢索增強生成（RAG）中扮演什麼角色？為什麼它是一個值得深入研究的問題？**

A：視覺文件檢索旨在從大量視覺豐富的文件集合中，找出與使用者查詢相關的頁面，這些頁面的證據可能分散在文字、版面、圖表與視覺結構之中。在多模態 RAG 的應用場景中，檢索器必須先正確定位到包含答案的文件頁面，後續的生成模型才能基於這些頁面進行推理與回答，因此檢索品質直接影響下游任務的表現。然而，由於查詢與文件分屬不同模態，且文件中的證據往往具有細粒度與複雜的視覺結構，如何準確建模兩者之間的相關性，成為視覺文件檢索的核心挑戰。

**Q2：現有的細粒度監督方法主要有哪些？它們各自存在什麼根本性的缺陷？**

A：現有研究主要透過兩種證據代理來提供細粒度監督：一種是區域層級的文字描述，另一種是局部化的視覺區域。文字描述雖然能提供高層次的語義詮釋，但容易遺失複雜的視覺結構，例如圖表、空間版面與非文字元素，導致監督訊號不夠精確。相對地，局部化視覺區域雖然保留了細粒度的視覺 grounding，卻常常缺乏全局頁面上下文與文件層級語義，難以完整表達頁面與查詢之間的真實相關性。

**Q3：為什麼僅使用頁面層級的對比式監督不足以訓練出優秀的視覺文件檢索模型？**

A：頁面層級的對比目標只告訴模型「哪些頁面與查詢相關、哪些不相關」，但並未指出頁面內部真正支持答案的視覺證據位置。這種粗粒度的監督訊號使得模型難以學會辨識關鍵的細粒度線索，例如特定表格欄位、圖表趨勢或版面區塊。因此，模型可能在面對外觀相似但內容不同的頁面時產生混淆，無法穩健地將查詢語義對齊到正確的視覺證據上。

**Q4：ConceptFormer 的核心方法是什麼？它如何表達查詢相關的證據？**

A：ConceptFormer 提出了一種潛在概念表徵學習框架，將查詢相關證據建模為連續、以查詢為條件的潛在概念。這些潛在概念作為中介表徵，橋接了局部化視覺證據與語義相關性，既不需要依賴文字中介表徵，也不需要直接使用原始視覺標註。透過這種方式，ConceptFormer 能夠在共享嵌入空間中提供更細緻的查詢-文件對齊訊號，縮小文字查詢與視覺文件之間的語義差距。

**Q5：ConceptFormer 如何決定每個查詢需要多少個潛在概念標記？這個設計為什麼重要？**

A：ConceptFormer 在訓練時利用強大的視覺-語言模型，先在正樣本頁面上定位查詢相關區域，再將這些區域對應到檢索器視覺標記網格上，以估計證據表徵所需的潛在概念容量。根據估計結果，模型會動態分配對應長度的潛在概念序列，讓檢索器生成以查詢與文件為條件的潛在概念表徵。這個自適應設計非常重要，因為實驗分析顯示查詢相關證據的規模變化很大，固定數量的概念無法充分涵蓋不同查詢所需的證據範圍，動態分配才能提供量身打造的監督。

**Q6：與先前的文字描述或視覺區域代理方法相比，ConceptFormer 在設計上有哪些關鍵創新？**

A：ConceptFormer 的關鍵創新在於將證據表徵從離散的文字或區域形式，轉換為連續、可學習的潛在概念，使模型能夠同時捕捉細粒度文字線索與複雜文件層級視覺結構。此外，ConceptFormer 採用動態概念容量機制，根據每個查詢的證據覆蓋範圍調整概念數量，而非使用固定大小的代理。這些設計讓潛在概念能夠佔據查詢與視覺文件之間的中介空間，成為比文字概念代理或視覺概念代理更有效的跨模態對齊橋樑。

**Q7：ConceptFormer 在哪些基準測試上進行評估？主要的量化結果為何？**

A：論文在多樣化的視覺文件檢索基準上進行實驗，結果顯示 ConceptFormer 相較於最強的視覺檢索基線與最強的 OCR 文字檢索基線，在平均 NDCG@10 上分別取得了 16.7% 與 22.1% 的相對提升。這些結果顯示，無論是與直接處理文件影像的方法相比，還是與依賴 OCR 文字的傳統檢索方法相比，ConceptFormer 都能顯著改善檢索品質。這樣的進步主要歸功於學習到的潛在概念能夠提供比標準頁面層級匹配更有效、更細緻的相關性監督。

**Q8：論文進行了哪些分析或消融研究來驗證 ConceptFormer 的設計選擇？**

A：論文進一步分析了潛在概念在查詢與視覺文件之間的中介空間角色，證明它們比文字或視覺概念代理更能有效連接局部化視覺證據與語義相關性。此外，自適應容量分析顯示查詢相關證據的規模存在顯著變化，因此根據證據覆蓋範圍動態分配潛在概念容量，能夠提供更貼近實際需求的證據表徵。這些分析不僅驗證了動態與連續潛在概念的價值，也說明 ConceptFormer 能夠同時捕捉細粒度文字線索與複雜文件層級視覺結構。

**Q9：潛在概念如何同時連接「局部化視覺證據」與「語義相關性」？這對檢索對齊有什麼幫助？**

A：潛在概念透過以查詢與文件為條件生成連續表徵，將視覺區域中的具體證據轉換為語義層次上與查詢相關的概念單元。這種表徵方式讓檢索器能夠學習到「哪些視覺區域在語義上回應了查詢」，而不僅僅是「哪些頁面整體上與查詢相似」。因此，潛在概念幫助檢索器在嵌入空間中建立更精細的查詢-文件對齊，提升對複雜版面、圖表與分散證據的辨識能力。

**Q10：ConceptFormer 在實務上可以應用於哪些場景？**

A：ConceptFormer 可應用於企業知識管理、法律文件檢索、財務報表查詢、醫療病歷檢索，以及任何需要從視覺豐富文件中快速定位相關頁面的場景。例如，使用者可以針對「2023 年第三季營收成長趨勢」提問，系統能直接從掃描報告或簡報影像中找出包含對應圖表的頁面。由於 ConceptFormer 不依賴 OCR 文字，也能處理版面複雜、圖表密集或文字難以辨識的文件，擴展了傳統文件檢索系統的適用範圍。

**Q11：在實際產品部署 ConceptFormer 時，需要考慮哪些工程與效能議題？**

A：首先，ConceptFormer 在訓練階段需要呼叫強大的視覺-語言模型來生成潛在概念監督，這會帶來額外的運算成本與延遲，因此需要評估線上推理與離線訓練之間的權衡。其次，動態分配潛在概念序列長度雖然提升了表徵彈性，但也可能增加批次處理與記憶體管理的複雜度，需要針對不同硬體環境進行最佳化。最後，由於潛在概念是連續且不可解釋的表徵，產品團隊可能需要額外設計可解釋性機制，例如視覺化概念對應區域，以提升使用者信任與除錯效率。

**Q12：ConceptFormer 對視覺文件檢索與多模態 RAG 領域可能帶來什麼影響？**

A：ConceptFormer 展示了連續潛在概念作為細粒度監督訊號的潛力，可能促使更多研究從離散的文字描述或區域標註，轉向學習性的連續中介表徵。這種範式轉移有助於解決查詢與視覺文件之間長期存在的語義差距問題，並推動多模態 RAG 系統在檢索階段就能更準確地定位複雜證據。長遠來看，ConceptFormer 也為其他需要跨模態對齊的任務，例如視覺問答、資訊抽取與多模態推理，提供了可借鏡的表徵學習框架。

**Q13：ConceptFormer 目前可能存在哪些限制或弱點？**

A：ConceptFormer 在訓練時依賴強大的視覺-語言模型來生成潛在概念監督，這使得訓練成本相對較高，且監督品質會受到該模型能力的上限限制。此外，雖然潛在概念提供了細粒度對齊訊號，但它們本質上是連續且不可解釋的，難以直接驗證每個概念是否確實對應到正確的視覺證據。最後，動態概念容量雖然提升了彈性，但在極端長文件或證據高度分散的情況下，如何有效分配與聚合概念仍然是值得進一步研究的問題。

**Q14：在哪些情況下 ConceptFormer 可能會出現檢索失敗？**

A：當視覺-語言模型在定位查詢相關區域時出錯，後續生成的潛在概念監督就可能誤導檢索器，導致錯誤的對齊學習。此外，若查詢需要跨頁面推理或整合多個分散區域的資訊，單一頁面的潛在概念可能難以完整表達這種複雜相關性。還有，當文件中存在大量外觀相似但語義不同的區塊時，例如格式統一的表格或重複出現的圖表，ConceptFormer 也可能因為視覺線索過於接近而產生混淆。

**Q15：基於 ConceptFormer，未來有哪些值得探索的研究方向？**

A：未來研究可以探索如何讓潛在概念具備更好的可解釋性，例如透過對齊機制將每個概念對應回具體的視覺區域或文字片段，以提升模型的透明度與除錯能力。另一個方向是將 ConceptFormer 擴展到跨頁面或多文件檢索場景，讓潛在概念能夠建模更長程、更分散的證據結構。此外，也可以研究如何降低對強大視覺-語言模型的依賴，例如開發更輕量的概念生成器，或結合主動學習與人類回饋來提升監督訊號的品質與效率。

## 實務應用指南

### 適用場景

1. **企業內部知識庫與財報檢索**
   適用於需要從掃描版財報、法說會簡報、合約或技術手冊中，依據自然語言問題找出相關頁面的場景。ConceptFormer 能同時捕捉表格、圖表與版面結構，避免傳統 OCR 序列化造成的資訊損失，特別適合證據分散在多個視覺區域的文件。

2. **多模態檢索增強生成（RAG）系統**
   當生成模型需要引用文件影像中的視覺證據時，ConceptFormer 可作為前端檢索器，提供與查詢語義更對齊的頁面排序。其潛在概念能橋接局部視覺證據與語義相關性，讓後續生成模型獲得更精準的上下文。

3. **法律與醫療文件審查**
   在訴狀、病歷、保險單或醫學影像報告的檢索任務中，查詢常涉及專業術語與複雜版面。ConceptFormer 的細粒度監督可協助定位查詢相關區域，減少僅依賴頁面層級對比學習所遺漏的關鍵線索。

4. **電商與產品型錄搜尋**
   針對包含產品規格表、價格區塊與圖片的型錄 PDF 或網頁截圖，使用者能以自然語言查詢（如「支援 5G 且電池容量大於 4000mAh 的手機」）檢索相關頁面，無需預先抽取結構化欄位。

5. **學術文獻與專利圖表檢索**
   適合需要從論文或專利文件中找出包含特定圖表、公式或實驗結果頁面的情境。潛在概念可學習圖表結構與文字敘述之間的對應關係，提升對複雜視覺結構的檢索能力。

### 實作前置條件

**資料準備**
- 文件影像集合：全頁截圖或高解析度頁面影像，建議保留原始版面與視覺結構。
- 查詢-文件對應關係：至少具備頁面層級的正樣本標註（查詢與相關頁面配對）。
- 可選但建議：若有區域層級標註可輔助驗證，但 ConceptFormer 的設計目標即為減少對原始視覺標註的依賴。

**運算資源**
- 訓練階段需要支援大規模視覺-語言模型推理的 GPU（如 A100 或 H100），因需利用強大 VLM 動態生成潛在概念標記作為監督訊號。
- 推論階段可視部署規模選用較輕量模型或進行知識蒸餾，以降低延遲與成本。

**技術能力**
- 熟悉視覺-語言模型（VLM）與對比式學習。
- 具備文件影像預處理經驗，例如解析度調整、分頁與批次處理。
- 了解向量資料庫與近似最近鄰搜尋（ANN）的部署流程。

### 實作步驟建議

1. **建立文件影像索引**
   將原始文件轉換為全頁截圖，並依據下游任務決定是否保留放大裁切區域。避免過度壓縮導致圖表或細小文字失真。

2. **訓練 ConceptFormer 檢索器**
   以查詢-正樣本頁面配對為基礎，利用強大 VLM 在正樣本頁面上定位查詢相關區域，並映射至檢索器視覺標記網格以估計所需潛在概念數量。接著動態配置潛在概念序列，讓檢索器學習以查詢為條件的潛在概念表徵。

3. **對齊排序分佈**
   最佳化檢索器，使其基於潛在概念所誘導的排序分佈，能夠還原原始查詢驅動的文件排序偏好。此步驟是縮小查詢與文件間語義差距的關鍵。

4. **建置向量索引與線上服務**
   將訓練完成的檢索器用於離線抽取文件稠密表徵，並存入向量資料庫。線上接收查詢時，先編碼查詢再執行近似最近鄰搜尋，回傳 Top-K 相關頁面。

5. **持續評估與迭代**
   使用 NDCG@10 等指標監控檢索品質，並針對失敗案例分析潛在概念是否遺漏關鍵視覺結構或過度聚焦於非證據區域，據此調整概念容量與訓練資料。

### 潛在風險與注意事項

- **強大 VLM 的監督品質不穩定**
  若用於生成潛在概念的 VLM 對特定領域文件（如手寫病歷或低品質掃描件）理解不足，可能產生不準確的證據表徵。建議在領域資料上微調 VLM，或加入人工抽樣驗證。

- **動態概念容量的計算成本**
  動態決定潛在概念標記數量雖能提升表徵彈性，但會增加訓練與推論開銷。可透過快取常見查詢類型的概念長度分佈，或設定上限來平衡效率與效果。

- **過度擬合局部視覺證據**
  細粒度監督可能使模型過度關注局部區域而忽略文件層級語義。應保留頁面層級對比目標作為輔助，確保全局頁面上下文與局部證據並重。

- **解析度與視覺標記網格的對應誤差**
  高解析度文件縮放至模型輸入尺寸時，可能導致查詢相關區域映射到錯誤的視覺標記。建議在預處理階段統一長寬比與解析度，並驗證區域映射準確度。

- **與 OCR 系統的權衡**
  雖然 ConceptFormer 在視覺檢索上表現優於 OCR 基線，但對於以文字為主且版面單純的文件，OCR 方案可能仍具成本優勢。建議依文件類型混合部署。

### 與其他技術的整合建議

- **與 OCR 管線互補**
  對於已具備 OCR 基礎設施的系統，可將 ConceptFormer 作為視覺路徑的增強模組，與 OCR 文字檢索結果進行融合排序（如 RRF 或學習式重排），以兼顧文字精確性與視覺結構理解。

- **銜接大型語言模型（LLM）生成**
  在多模態 RAG 架構中，ConceptFormer 負責召回相關頁面後，可將頁面影像或經 OCR 擷取的文字區塊一併送入多模態 LLM 進行答案生成，形成「視覺檢索 → 視覺推理 → 生成」的完整流程。

- **結合重排模型（Reranker）**
  初步檢索後可接入更重的跨模態重排模型，對 ConceptFormer 回傳的 Top-K 頁面進行精細化排序，進一步提升最終召回品質。

- **整合向量資料庫與 ANN 索引**
  使用支援高維稠密向量的資料庫（如 Milvus、Pinecone 或 Weaviate）儲存文件表徵，並根據資料規模選擇 HNSW、IVF 等索引策略，以滿足低延遲檢索需求。

### 給不同背景讀者的閱讀建議

**給初學者**
這篇論文的核心想法是：與其讓檢索模型只看整頁文件與查詢是否相關，不如先讓一個強大的視覺-語言模型自動找出頁面中與查詢有關的區域，再把這些區域轉換成「潛在概念」來教檢索模型學習。你可以把它想像成請一位助教先看過文件，標出重點區域，再讓檢索模型根據這些重點學會更精準地找文件。閱讀時建議先理解「為什麼頁面層級監督不夠細緻」，再回來看潛在概念如何解決這個問題。

**給 AI 工程師**
本論文提供了一個可落地的訓練框架：利用強大 VLM 產生查詢條件化的潛在概念標記，作為檢索器的中間監督訊號，並透過排序分佈對齊來最佳化嵌入空間。實作時應特別關注動態概念容量的計算開銷、視覺標記網格與原始頁面區域的對應關係，以及推論階段的延遲問題。建議從方法章節的訓練目標與損失函式入手，再評估是否適合引入現有產品管線。

**給研究人員**
ConceptFormer 的貢獻在於提出以連續潛在概念作為查詢-文件對齊的中介表徵，跳脫了文字描述或局部視覺區域作為證據代理的傳統思路。值得進一步探討的方向包括：潛在概念的可解釋性、不同 VLM 監督品質對檢索效果的影響、動態概念長度的理論基礎，以及將此框架延伸至影片、網頁截圖等其他視覺豐富文件類型的可能性。

**給產品經理**
這項技術適合需要從視覺豐富文件（如 PDF、簡報、掃描件）中進行自然語言搜尋的產品，特別是證據涉及圖表、表格或版面的場景。導入前需評估文件影像品質、是否有足夠的查詢-頁面配對資料，以及是否能負擔 VLM 監督所需的運算成本。短期可從高價值場景（如法務審查或財報分析）試點，再逐步擴展至多模態 RAG 應用。
