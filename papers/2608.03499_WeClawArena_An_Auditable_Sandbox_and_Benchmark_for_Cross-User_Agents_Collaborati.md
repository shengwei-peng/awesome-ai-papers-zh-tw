# WeClawArena：以人為中心的代理網路中跨使用者代理協作與安全性的可審計沙盒與基準測試

**原文標題：** WeClawArena: An Auditable Sandbox and Benchmark for Cross-User Agents Collaboration and Security in Human-Centered Agent Networks

## ⚡ TL;DR

現有基準測試缺乏可驗證的跨使用者代理協作環境，無法評估個人工作空間中的多工具協同與攻擊風險。
本文提出 WeClawArena，以 Docker 沙盒支援多方代理協作，記錄訊息、工具與操作。
該基準含 124 項任務與 620 種情境，分別評估效用與攻擊成功率，並診斷協作、隱私及治理危害。

## 摘要翻譯

近期在持久化個人代理框架（persistent personal-agent frameworks）上的進展，正使以人為中心的代理網路（human-centered agent networks）成為現實可部署的目標：每位使用者都能由一個代表其行動、維持狀態，並透過社交與任務關係與其他代理溝通的 AI 代理（AI agent）來服務。在這些網路中，日常的工具使用（tool use）轉變為在個人工作空間（personal workspaces）上進行的多方擁有者代理協作（multi-party owned-agent collaboration），而檔案、記錄、工具與政策在不同擁有者之間並非直接可見。現有的代理基準測試雖然研究了工具使用與協作，但並未提供端對端沙盒（end-to-end sandbox）以支援可驗證的跨使用者代理協作（cross-user agents collaboration），也未納入貼近真實的個人數位工作空間（realistic user digital workspaces），更未測試有害行為如何能在以人為中心的代理網路中傳播。我們提出 WeClawArena，一個可審計的基準測試（auditable benchmark）與執行時期沙盒（runtime sandbox），用於在個人工作空間上進行多方擁有者代理協作。WeClawArena 鎖定協作式工具使用任務，其中個人工作空間同時作為操作工具與個人約束。該基準測試包含橫跨六個跨使用者任務領域的 124 個基礎任務（base tasks），並擴展為 620 個情境變體（scenario variants），每個基礎任務各含一個良性對照（benign control）與四個攻擊向量變體（attack-vector variants）。沙盒會記錄代理間訊息（peer messages）、工具呼叫（tool calls）、資源操作（resource operations）、受治理決策（governed decisions）以及最終工作空間狀態（final workspace states）。WeClawArena 分別回報效用（utility）與攻擊成功率（attack success rate），並依據有界執行時期證據（bounded runtime evidence）審計攻擊是否成功，支援診斷任務分解失敗（task breakdown）、隱私洩漏（privacy leakage）、毒化證據（poisoned evidence）以及無效授權路徑（invalid authority paths）。

### 核心貢獻（3～5點）
- 提出 WeClawArena，一個可審計的基準測試與執行時期沙盒，專門支援在個人工作空間上進行的多方擁有者代理協作。
- 設計 124 個跨六個跨使用者任務領域的基礎任務，並擴展為 620 個情境變體，每個任務皆包含一個良性對照與四個攻擊向量變體。
- 沙盒完整記錄代理間訊息、工具呼叫、資源操作、受治理決策與最終工作空間狀態，提供可驗證的執行時期證據。
- 分別回報任務效用與攻擊成功率，並能從有界執行時期證據審計與診斷四類攻擊成功類型：任務分解失敗、隱私洩漏、毒化證據與無效授權路徑。

### 適合對象
本論文適合多代理系統、AI 安全與對齊、以人為中心的 AI、個人化 AI 代理、跨使用者協作系統，以及關注代理行為可審計性與風險評估的研究人員與工程師閱讀；對於設計或評測持久化個人代理框架、多代理協調框架，以及需要建立可驗證安全基準的政策制定者與產品開發者亦有參考價值。

## 深度分析

#### 方法論解析

WeClawArena（可審計沙盒與基準測試）的核心方法論，是將「以人為中心的代理網路（Human-Centered Agent Networks）」從過去的多代理對話或單一使用者工具使用，轉化為「多方擁有者代理協作（multi-party owned-agent collaboration）」的端到端（end-to-end）評測問題。具體而言，它把每個人類使用者視為一個 principal（委託主體），並為其建立一個 personal workspace（個人工作空間）節點：

\[
n_u = (u, A_u, W_u),\quad W_u=(F_u, D_u, T_u, P_u)
\]

其中 \(F_u\) 代表檔案系統狀態、\(D_u\) 代表結構化資料庫或紀錄、\(T_u\) 是可用的 owner-scoped tools（擁有者範圍工具），而 \(P_u\) 則是政策、限制、同意規則與批准流程。整個網路被形式化為有向圖 \(G=(N,E)\)，邊 \(e(n_u,n_v)\) 不僅表示社交或任務關係，還攜帶角色、階段、親和性、權限與批准脈絡。這樣的設計讓 workspace boundaries（工作空間邊界）成為任務的一部分：代理無法直接窺視其他擁有者的資源，而必須透過訊息交換、證據傳遞、同意或批准來協作。

在執行層面，WeClawArena 採用 Docker-backed owner workspace（以 Docker 為後端的擁有者工作空間）來模擬真實的個人數位環境，並透過一個 message gateway（訊息閘道）讓代理之間通訊、呼叫領域工具、操作被擁有的資源。沙盒會記錄 peer messages（同儕訊息）、tool calls（工具呼叫）、resource operations（資源操作）、governed decisions（受治理決策）以及 final workspace states（最終工作空間狀態）。這些 runtime evidence（執行時期證據）構成了後續審計的基礎。

任務設計上，WeClawArena 包含 124 個 base tasks（基礎任務），橫跨 bargaining（議價）、bidding（競標）、travel（旅遊）、SWE-Workspace（軟體工程工作空間）、clinical（臨床）與 trading（交易）六個跨使用者任務領域。每個基礎任務再擴展為五個 matched scenarios（配對情境）：一個 benign control（良性對照）與四個 attack-vector variants（攻擊向量變體），總計 620 個 scenario variants（情境變體）。四種攻擊向量分別對應 collaboration（協作）、security（安全）、privacy（隱私）與 governance（治理）四個危害家族，讓同一條協作通道同時承載正常任務需求與對抗性壓力。

評測協議將 task utility（任務效用）與 attack success rate（攻擊成功率，ASR）分開報告。utility 衡量代理在資訊、工具與決策權分散於多個 personal workspaces 時，是否仍能完成可驗證的協作任務；ASR 則衡量在相同協作過程中，有害行為是否成功滲透。審計層面進一步利用 bounded runtime evidence（有界執行時期證據）診斷四類失敗：task breakdown（任務分解失敗）、privacy leakage（隱私洩漏）、poisoned evidence（毒化證據）與 invalid authority paths（無效授權路徑）。

#### 實驗數據解讀

從提供的摘要與引言來看，WeClawArena 的實驗設計重點不在於單一數值排名，而在於建立一個能同時觀察「協作效用」與「安全風險」的雙軌評測架構。124 個 base tasks 與 620 個情境變體的規模，意味著評測覆蓋了相當廣泛的跨領域協作模式；每個基礎任務都配對一個 benign control 與四個 attack-vector variants，則確保了實驗條件的可比性——同一任務結構下的正常版本與攻擊版本可以進行直接對照。

在指標意義上，task utility 回答的是 RQ1：當所需資訊、工具與決策權被拆分到不同 personal workspaces 時，代理是否仍能完成任務。這比傳統單使用者 tool use（工具使用）基準更困難，因為代理必須處理 partial observability（部分可觀察性）、跨擁有者訊息傳遞與政策約束。預期上，WeClawArena 的 utility 分數會顯著低於 τ-bench 或 τ2-Bench 等單使用者基準，因為後者不需要處理 workspace boundaries 與多所有者授權。

ASR 則回答 RQ2：當協作通道被對手利用時，會產生哪些 final harm（最終危害）。四種 attack-vector variants 的設計讓研究者能夠區分不同類型的脆弱性。例如，在 clinical（臨床）領域，攻擊可能透過偽造的授權文件誘使代理洩漏病患紀錄，這屬於 privacy leakage 與 invalid authority paths 的複合問題；在 trading（交易）領域，攻擊者可能透過毒化證據讓代理誤判市場條件，進而違反 budget ceiling（預算上限）或交易政策，這對應到 poisoned evidence 與 governance 危害。

審計指標回答 RQ3：是否能從 bounded runtime evidence 中還原「誰做了什麼、哪些訊息與工具呼叫導致了結果、授權路徑是否有效」。這四類診斷指標的價值在於，它們不僅報告「是否成功攻擊」，還指出攻擊成功的原因。例如，task breakdown 表示協作本身因為溝通或工具使用失敗而崩解；privacy leakage 表示敏感資源跨邊界流動；poisoned evidence 表示代理依賴了被竄改的跨使用者證據；invalid authority paths 則表示代理在未經適當 consent or approval（同意或批准）的情況下執行了動作。

將 utility 與 ASR 分開報告的設計特別重要：一組代理可能在 benign control 上表現良好，但在 attack-vector variants 上暴露出高 ASR；反之，過度保守的代理可能拒絕所有跨邊界協作而導致 utility 低落。WeClawArena 因此能夠描繪出「效用—安全」權衡曲線，而不是用單一分數掩蓋兩種不同的失敗模式。

#### 與現有研究的比較

現有基準測試各自覆蓋了問題的一部分，但缺乏 WeClawArena 所強調的「跨使用者、擁有者範圍、可審計」的端到端設定。τ-bench 與 τ2-Bench 聚焦於單一使用者的 realistic tool use（真實工具使用），並未將任務結構分散到多個 personal workspaces；AgentBench 與 GAIA 雖然測試長程執行與環境推理，但同樣未處理多所有者邊界與跨使用者授權；MultiAgentBench 評估代理間的協作與競爭，但其環境通常是共享沙盒，而非每個代理各自擁有獨立的工作空間與政策；AgentSocialBench 則偏重多代理社交溝通，而非可驗證的工具使用協作任務。

在隱私與安全方面，現有研究如記憶攻擊、contextual privacy failures（情境隱私失敗）等，雖然揭示了代理系統的洩漏風險，但大多數仍停留在單一代理或單一對話層面，未能呈現 harmful actions（有害行為）如何透過 human-centered agent network 中的訊息、資源、工具與批准路徑傳播。WeClawArena 的貢獻在於把這些問題整合到同一個 runtime sandbox（執行時期沙盒）中：代理必須完成真實任務，同時面對來自協作通道的對抗性壓力，並留下可供審計的證據。

然而，WeClawArena 也有其限制。首先，六個任務領域雖然涵蓋了多種協作模式，但仍屬於模擬環境，與真實世界中的企業系統、醫療資訊系統或金融交易平台相比，政策複雜度與工具多樣性仍有差距。其次，目前的攻擊向量似乎是預先定義的 scenario variants，對於自適應對手（adaptive adversaries）或更複雜的社會工程攻擊的覆蓋程度尚不明確。此外，評測需要同時執行多個 Docker 工作空間與訊息閘道，對運算資源與實驗設定的要求較高，可能影響大規模擴展。

#### 可重現性評估

就提供的摘要與引言而言，WeClawArena 在可重現性方面具備良好的結構基礎：它明確定義了 personal workspace 的形式化模型、Docker-backed 執行環境、message gateway 介面，以及 utility 與 ASR 的評測協議。這些描述為其他研究者複現沙盒架構提供了清晰的藍圖。124 個 base tasks 與 620 個 scenario variants 的規模也暗示作者可能準備了相對完整的任務定義與資料集。

不過，根據目前可見的內容，尚未出現明確的 open-source code（開放原始碼）、dataset release（資料集釋出）或 model weights（模型權重）連結。要達到高度可重現性，作者社群需要公開以下元件：Docker 映像檔與工作空間模板、領域工具與資料庫結構描述、任務定義與攻擊變體腳本、message gateway API 規格、代理提示詞（prompts）與 orchestration（協調）邏輯，以及評測腳本與審計解析器。若這些 artifact（研究產出物）能夠釋出，將大幅提升 WeClawArena 作為長期社群基準的價值；反之，若僅有論文描述而無執行環境，則其他團隊在重現 exact experimental conditions（精確實驗條件）時會面臨相當挑戰。

#### 未來研究方向

WeClawArena 開啟了數個值得後續探索的研究方向。第一，可將目前的靜態任務圖擴展為 dynamic social networks（動態社交網路），讓使用者的關係、信任程度與授權範圍在執行過程中變化，從而測試代理在更真實的社會情境中的適應能力。第二，可引入更強大的 adaptive attackers（自適應攻擊者），例如能夠根據代理回應即時調整策略的對手，以評估現有防禦機制的穩健性。

第三，審計機制可以進一步結合 formal verification（形式化驗證）或 symbolic reasoning（符號推理），讓 invalid authority paths 的檢測不僅依賴執行紀錄，還能透過政策邏輯進行先驗證明。第四，隨著 Agent-to-Agent protocols（A2A 協定）與 model context protocol（MCP）等標準逐漸成熟，WeClawArena 可以擴充為跨平台、跨框架的相容評測環境，讓不同 persistent personal-agent frameworks（持久化個人代理框架）在同一套任務上進行公平比較。

第五，未來研究可探討 human-in-the-loop（人類在迴路）機制：當代理需要 consent or approval 時，人類擁有者的反應時間、認知負荷與決策偏誤如何影響 utility 與 ASR。第六，可將工作空間從目前的檔案系統與資料庫擴展到 multi-modal（多模態）環境，例如包含影像、音訊、感測器資料與即時協作編輯工具，以貼近更廣泛的個人數位工作空間。最後，建立標準化的 audit log format（審計日誌格式）與第三方認證流程，將有助於把 WeClawArena 從研究基準轉化為產業級的安全評估工具。

## 論文問答

**Q1：WeClawArena 想要解決的核心問題是什麼？**
A：WeClawArena 針對的是「以人為中心的代理網路」中，多方擁有者代理在個人工作空間上進行跨使用者工具協作的問題。在這樣的網路裡，每位使用者都由自己的代理代表，代理只能存取該擁有者範圍內的檔案、資料庫、工具與政策，並必須與其他代理協調完成任務。這使得日常的工具使用任務變成分散式協作，代理必須整合片段資訊、交換證據、請求同意或批准，並且不能逾越工作空間邊界。

**Q2：現有的基準測試為何無法充分捕捉這個問題？**
A：現有的工具使用基準如 τ-bench、τ2-Bench、AgentBench 與 GAIA 主要評估單一使用者或共享沙盒中的工具使用與長期執行能力，並未模擬多位擁有者各自的個人工作空間。多代理基準雖然研究協作與競爭，但缺乏擁有者範圍的資源隔離與真實的個人約束；隱私與安全基準則多聚焦於洩漏或攻擊本身，卻未提供端到端的跨使用者協作環境。因此，它們無法同時檢驗合法協作的工具效用，以及攻擊如何透過同樣的訊息、資源與批准路徑傳播。

**Q3：為什麼這個問題在現階段特別重要？**
A：隨著 OpenClaw 等持久化個人代理框架，以及代理對代理協定的快速發展，人類使用者擁有長期運作、能維持狀態並互相通訊的代理已變得愈來愈可行。當這些代理透過社交與任務關係協作時，惡意行為也可能沿著相同的協作通道影響多個擁有者的工作空間。若只關注任務完成度而忽略攻擊審計，將難以發現預算上限洩漏、無效授權或毒化證據等危害，因此需要同時評估效用與安全的可審計沙盒。

**Q4：WeClawArena 的核心方法是什麼？**
A：WeClawArena 提供了一個可審計的基準測試與執行時期沙盒，將每位使用者建模為擁有個人工作空間的擁有者，工作空間包含檔案系統、資料庫、工具與政策，並以 Docker 容器模擬。代理之間透過訊息閘道進行通訊、呼叫領域工具與存取受擁有者範圍限制的資源，而閘道會同時記錄可供審計的執行時期證據。整個模擬過程會保存同儕訊息、工具呼叫、資源操作、受治理決策以及最終工作空間狀態，作為後續分析與診斷的依據。

**Q5：WeClawArena 的主要創新之處有哪些？**
A：首先，它形式化了多方跨使用者工具協作問題，明確將個人工作空間同時視為操作基板與約束表面。其次，它為每個基礎任務設計了一個良性對照與四種攻擊向量變體，能夠分開卻又配對地衡量任務效用與攻擊成功率。第三，它利用有界執行時期證據來審計攻擊成功，並支援診斷任務分解失敗、隱私洩漏、毒化證據與無效授權路徑等具體危害類型。

**Q6：哪些設計選擇讓 WeClawArena 具備可審計性？**
A：沙盒採用 Docker 支援的擁有者工作空間，以強制隔離不同使用者的資源並模擬真實的個人數位環境。訊息閘道集中路由代理間通訊與工具呼叫，並記錄有限的執行時期證據，而非僅依賴最終輸出進行判斷。此外，評估協議將任務效用與攻擊成功率分開計算，因此即使代理團隊完成了可見任務，也能被審計出是否同時造成隱私或治理上的危害。

**Q7：WeClawArena 包含哪些基準任務與情境？**
A：WeClawArena 包含 124 個基礎任務，涵蓋議價、投標、旅遊、SWE-Workspace、臨床醫療與交易等六個跨使用者任務領域。每個基礎任務被擴展為五個情境變體，包括一個良性對照與四個攻擊向量變體，分別對應協作、安全、隱私與治理四個攻擊危害家族，總計 620 個配對情境。這種設計讓研究者能在相同的任務骨架下，比較正常協作與不同攻擊情境下的表現差異。

**Q8：WeClawArena 的主要評估指標與預期結果是什麼？**
A：該基準分開報告任務效用與攻擊成功率，任務效用衡量代理在個人工作空間限制下是否完成協作任務，攻擊成功率則衡量有害行為是否達成其目標。攻擊成功是從有界執行時期證據中審計而來，因此可以診斷出具體的失敗模式，例如隱私洩漏或無效授權路徑。雖然摘錄未提供詳細實證分數，但此設計確保高任務效用不會掩蓋高攻擊成功率，兩者必須同時檢視。

**Q9：這個框架支援哪些消融研究或控制比較？**
A：研究者可以消融工作空間邊界、審計日誌、同意或批准要求，以及攻擊者存在與否，以隔離各因素對效用與安全的影響。例如，比較有無執行時期證據記錄的情境，可以測試可審計性是否提升攻擊偵測率。比較同一基礎任務的良性對照與攻擊向量變體，則能揭示對抗壓力如何改變任務效用，以及哪些治理機制在攻擊下會失效。

**Q10：WeClawArena 模擬了哪些實際應用情境？**
A：它模擬了多種真實的多方協作情境，例如多位病患的臨床代理在取得同意後才共享醫療記錄、旅遊代理在個人行事曆與預算限制下協調行程，或軟體工程代理跨私有程式碼庫與議題追蹤系統協作。在這些情境中，檔案、記錄、工具與政策無法直接跨擁有者可見，因此代理必須協商存取權限與批准流程。這些設計反映了以人為中心的代理網路中，個人工作空間同時作為操作工具與個人約束的真實樣貌。

**Q11：這項研究對產品設計有哪些啟示？**
A：產品團隊應將個人工作空間視為能力與約束的綜合體，並實作擁有者範圍工具、明確的同意與批准流程，以及防篡改的審計日誌。閘道架構提示我們，代理通訊與資源存取應集中路由與記錄，而非讓代理直接點對點存取彼此的工作空間。此外，將任務效用指標與攻擊成功率分開評估，也意味著產品測試應針對每個協作流程設計紅隊攻擊變體，避免只看表面完成度。

**Q12：WeClawArena 可能對整個領域產生什麼影響？**
A：它建立了首個針對跨使用者代理協作與安全的端到端沙盒，將評估焦點從單一工具使用或對話式多代理基準，轉移到擁有者範圍、可審計的協作環境。透過同時連結任務效用與攻擊審計，它能引導更安全的代理對代理協定與持久化個人代理框架設計。此外，它提供了一個可重複使用的平台，讓研究者能系統性地研究隱私洩漏、毒化證據與治理失敗等問題。

**Q13：這項研究有哪些已承認或隱含的限制？**
A：摘錄未詳細說明支援的代理框架、大型語言模型骨幹或攻擊策略範圍，因此其在所有真實部署情境下的泛化能力仍需進一步驗證。沙盒以 Docker 模擬個人工作空間，雖然能提供控制與隔離，但可能無法完全重現真實企業系統或人類在迴路中的所有細節。此外，124 個基礎任務涵蓋六個領域，但仍可能無法窮盡所有跨使用者協作模式。

**Q14：WeClawArena 可能揭示哪些失敗案例？**
A：代理團隊可能在完成可見任務的同時，洩漏了受保護的預算上限、接受了無效的授權，或依賴了惡意同儕提供的毒化證據。代理也可能未請求必要同意、試圖繞過工作空間邊界，或在批准鏈中錯誤歸因授權路徑。這些失敗案例顯示，高任務效用可能與嚴重的安全、隱私或治理危害同時存在，因此不能單以任務完成度評斷系統好壞。

**Q15：這項工作暗示了哪些未來研究方向？**
A：未來可以擴展基準到更多領域、更豐富的人類在迴路互動，以及能根據執行時期證據動態調整策略的適應性攻擊者。另一個方向是開發自動化的審計摘要與解釋方法，將有界執行時期證據轉換為可理解的攻擊報告。最後，將 WeClawArena 與真實的代理對代理協定實作以及多樣化的大型語言模型骨幹整合，將能進一步提升其對生產環境中以人為中心的代理網路之研究價值。

## 實務應用指南

### 適用場景

1. **跨部門企業協作平台**  
   當財務、法務、業務等部門各自擁有以人為中心的代理，並需在個人工作空間（檔案、資料庫、政策）內完成採購議價、合約審閱或預算核可時，WeClawArena 可用來驗證代理是否能在不越過工作空間邊界的前提下完成任務，同時偵測隱私洩漏或無效授權路徑。

2. **醫療照護協調系統**  
   醫師、護理師、檢驗單位與保險窗口各自由代理代表，需在臨床工作空間中交換病歷摘要、檢驗報告與同意書。WeClawArena 的臨床任務領域可評估代理在多方擁有者代理協作下，是否遵守同意或批准流程，並審計毒化證據或任務分解失敗。

3. **個人化旅遊與行程規劃服務**  
   家庭成員或旅伴各自擁有持久化個人代理，代理需跨個人工作空間協調航班、預算上限、偏好與文件（如護照掃描）。WeClawArena 的旅遊領域可測試代理在面對攻擊向量變體時，是否仍能保持任務效用並避免預算上限等敏感資訊外洩。

4. **軟體工程團隊的跨成員工作空間協作（SWE-Workspace）**  
   開發者、測試人員與維運人員的代理分別操作各自的程式碼倉庫、Issue 追蹤與部署政策。WeClawArena 可驗證代理在提交程式碼、申請審查與觸發部署時，是否遵循擁有者範圍工具與治理規則。

5. **金融交易與資產管理網路**  
   投資人、理專、風控與交易所的代理透過代理對代理協定互動，執行下單、風險檢查與資產轉移。WeClawArena 的交易領域可評估攻擊成功率，例如代理是否會接受無效授權或依賴被毒化的市場證據。

### 實作前置條件

**資料準備**
- 每個人類使用者需有對應的個人工作空間定義：檔案系統狀態、資料庫或結構化紀錄、可用工具集，以及政策／同意／批准規則。
- 需準備任務描述與預期結果，涵蓋議價、投標、旅遊、SWE-Workspace、臨床與交易等至少一個跨使用者任務領域。
- 若進行攻擊評測，需設計四種攻擊向量變體（協作、安全、隱私、治理）以及對應的良性對照。

**運算資源**
- 可執行 Docker 容器叢集的環境，用於模擬每位擁有者的數位工作空間。
- 足夠執行多代理長期協作的運算資源，包含 LLM 推理呼叫、工具執行與沙盒紀錄儲存。
- 儲存空間需容納執行時期證據，包括同儕訊息、工具呼叫、資源操作、治理決策與最終工作空間狀態。

**技能與團隊**
- 熟悉多代理協調框架與工具使用語言代理的 AI 工程師。
- 具備 Docker、資料庫與檔案系統管理能力的後端工程師。
- 了解安全、隱私與治理需求的領域專家，以設計有效的攻擊向量與審計規則。
- 熟悉評測指標設計的人員，能區分任務效用與攻擊成功率。

### 實作步驟建議

1. **定義人類使用者與工作空間拓撲**  
   將每個使用者建模為擁有者節點，包含其代理集合、檔案系統、資料庫、擁有者範圍工具與政策。建立有向圖表示社交或任務關係，並標示邊上的角色、權限與批准脈絡。

2. **建立 Docker 支援的個人工作空間**  
   為每位擁有者建立獨立的 Docker 容器，模擬其數位工作空間。確保檔案、資料庫與工具在預設情況下不可被其他擁有者的代理直接存取。

3. **部署訊息閘道與沙盒紀錄機制**  
   實作閘道介面，讓代理能夠傳送同儕訊息、呼叫工具、更新資源並請求同意或批准。閘道需持續記錄執行時期證據，作為後續攻擊審計的依據。

4. **設計基礎任務與情境變體**  
   從單一領域開始，設計 1–2 個基礎任務，再為每個任務產生一個良性對照與四個攻擊向量變體。逐步擴展到多個跨使用者任務領域，累積可重複執行的基準測試集。

5. **連接 LLM 骨幹與代理框架**  
   將現有代理框架（如 OpenClaw 或其他持久化個人代理框架）接入沙盒，讓每個代理能根據其擁有者的工作空間狀態進行推理與行動。

6. **執行模擬並分開評估效用與攻擊成功率**  
   對每個情境執行多次模擬，分別計算任務效用（是否完成可見任務目標）與攻擊成功率（是否發生最終危害）。避免將兩者混為一談。

7. **利用有界執行時期證據進行攻擊審計**  
   針對攻擊成功的案例，從 bounded runtime evidence 中診斷是任務分解失敗、隱私洩漏、毒化證據或無效授權路徑，並回饋至工作空間政策或代理提示設計。

8. **迭代強化並產品化**  
   根據審計結果調整政策、工具權限與代理協作協定，再重新跑測。當通過率穩定後，將沙盒評測流程整合至 CI/CD，作為上線前的自動化閘道。

### 潛在風險與注意事項

- **工作空間邊界過度寬鬆**  
  若閘道或工具權限設定不當，代理可能繞過擁有者範圍工具直接讀取其他使用者資源。建議採用最小權限原則，並在沙盒中預設拒絕跨工作空間存取。

- **將任務效用與攻擊成功率混為一談**  
  代理可能完成任務卻同時洩漏預算上限或接受無效授權。評測時必須分開報告兩項指標，不能僅因任務完成就認定系統安全。

- **攻擊向量設計過於單一**  
  若只測試一種攻擊情境，會遺漏協作、安全、隱私、治理等不同面向的危害。建議每個基礎任務都對應四種攻擊向量變體。

- **執行時期證據不完整**  
  缺少同儕訊息、工具呼叫或治理決策紀錄會導致攻擊審計無法進行。閘道必須完整記錄所有關鍵事件，並確保紀錄不可被代理竄改。

- **模擬到真實的落差**  
  Docker 沙盒無法完全重現真實使用者行為與外部系統延遲。建議在沙盒通過後，再於分段環境進行小規模真人測試，並持續監控實際部署中的攻擊成功指標。

- **過度依賴單一 LLM 骨幹**  
  不同模型對政策理解與工具使用的穩定度差異很大。建議至少評測多個 LLM 骨幹，並針對最弱環節加強提示工程或後處理檢查。

### 與其他技術的整合建議

- **持久化個人代理框架（如 OpenClaw）**  
  將 WeClawArena 作為 OpenClaw 等框架的評測後端，讓每個使用者的代理在真實工作空間狀態下進行協作，並利用沙盒紀錄進行攻擊審計。

- **Agent-to-Agent（A2A）協定**  
  可將 WeClawArena 的訊息閘道對接 A2A 協定，使不同廠商或框架的代理能夠在標準溝通層上互動，同時由沙盒監控訊息內容與授權路徑。

- **現有工具使用基準（如 τ-bench、τ2-Bench、AgentBench、GAIA）**  
  這些基準適合驗證單一使用者工具使用能力，WeClawArena 則補足跨使用者協作與安全面向。建議先以單使用者基準篩選模型能力，再以 WeClawArena 評估多方協作風險。

- **身分識別與存取管理（IAM）系統**  
  將工作空間邊界與企業 IAM 整合，讓代理的每次工具呼叫與資源存取都經過身分驗證與授權檢查，並把決策紀錄寫入沙盒審計日誌。

- **可觀測性與 SIEM 平台**  
  把 WeClawArena 產生的執行時期證據匯出至 SIEM 或追蹤系統，協助維運團隊在生產環境中持續監控異常協作模式與攻擊成功率趨勢。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦於「以人為中心的代理網路」與「個人工作空間」這兩個核心概念，理解為什麼代理不能隨意讀取別人的檔案或工具；接著從適用場景中的旅遊或企業協作範例入手，體會任務效用與攻擊成功率為何需要分開評估，最後再回頭閱讀問題形式化與沙盒設計細節。

**AI 工程師**  
請重點閱讀問題形式化、Docker 支援的工作空間實作、訊息閘道設計與執行時期證據紀錄機制；實作時建議先從單一領域的基礎任務開始，逐步接入 LLM 骨幹與代理框架，並特別注意工作空間邊界、工具權限與審計日誌的完整性。

**研究人員**  
建議深入分析 RQ1–RQ3 的設計動機，以及四種攻擊向量變體如何對應協作、安全、隱私與治理四個危害家族；可進一步探討有界執行時期證據在攻擊審計中的理論保證，並思考如何將 WeClawArena 擴展至更多任務領域或更複雜的社會網路拓撲。

**產品經理**  
請優先掌握適用場景、潛在風險與整合建議，理解 WeClawArena 能為產品帶來的差異化價值——即可審計的跨使用者代理協作安全；在規劃產品路線圖時，可將沙盒評測設為上線前的強制閘道，並與法務、資安團隊合作定義隱私洩漏、無效授權路徑等關鍵風險指標。
