# KeyRec：用於串流與長影片理解（Streaming and Long-Video Understanding）的有界視覺記憶體（Bounded Visual Memory）

**原文標題：** KeyRec: Bounded Visual Memory for Streaming and Long-Video Understanding

**發布日期：** 2026-09-26

## ⚡ TL;DR

長影片與串流中密集視覺標記隨時間累積，導致推論成本高昂且現有方法難以兼顧近期細節與長程事件證據。
KeyRec 以查詢無關寫入建立有界視覺記憶，含近期快取與事件庫，並以文字路由器動態分配讀取預算。
在四基準與三骨幹上，KeyRec 僅用 10% 視覺標記預算，於 13/15 設定取得最佳壓縮效能。

## 摘要翻譯

視覺語言模型（Vision-Language Models, VLMs）日益被用於理解長影片（Long Videos）與連續串流（Continuous Streams）。然而，密集視覺標記（Dense Visual Tokens）會隨影片長度累積，使長上下文推論（Long-Context Inference）成本高到難以負擔。現有的免訓練視覺標記選擇方法（Training-Free Visual-Token Selection Methods）透過保留資訊性標記（Informative Tokens）來降低此成本，但可能遺失連貫的事件證據（Coherent Event Evidence），並無法區分詳細的近期觀察（Detailed Recent Observations）與長程歷史（Long-Range History）。我們提出 KeyRec，一個用於建構有界視覺記憶體（Bounded Visual Memory）的免訓練框架（Training-Free Framework）。在查詢無關寫入（Query-Agnostic Writing）階段，KeyRec 將細粒度的近期觀察（Fine-Grained Recent Observations）保留於視覺快取（Visual Cache）中，並將歷史證據組織成結構化事件庫（Structured Event Bank）。候選事件（Candidate Events）依其相對於已儲存事件的新穎性（Novelty）提出，並透過線上新增–合併–驅逐更新（Online Add–Merge–Evict Update）機制維護。當問題到來時，純文字路由器（Text-Only Router）會在近期記憶體（Recent Memory）與事件記憶體（Event Memory）之間自適應地分配固定讀取預算（Fixed Readout Budget），且無需重新處理歷史影格（Reprocessing Historical Frames）。KeyRec 運作於面向模型的視覺嵌入（Model-Facing Visual Embeddings）上，並同時支援模組化編碼器–投影器視覺語言模型（Modular Encoder–Projector VLMs），以及無編碼器且無投影器的 NEO-ov 架構（Encoder- and Projector-Free NEO-ov Architecture）。在四個串流與長影片基準測試（Streaming and Long-Video Benchmarks）及三個視覺語言模型骨幹網路（VLM Backbones）上，KeyRec 僅使用 10% 的面向解碼器的密集視覺標記預算（Dense Decoder-Facing Visual-Token Budget），便在 15 個設定中的 13 個達到最佳壓縮後效能（Compressed Performance）。在即時問題（Real-Time Questions）上，它較最強壓縮基線（Compressed Baseline）高出 2.21–18.37 分（Points）；在六個長影片設定（Long-Video Settings）中的五個達到最佳壓縮結果（Compressed Result）；並在每個 NEO-ov 2B 設定中均表現最佳。

### 核心貢獻（3～5點）
- 提出 KeyRec，一個免訓練（training-free）的有界視覺記憶體框架，透過雙記憶設計（視覺快取＋結構化事件庫）同時保留近期細節與長程歷史證據。
- 採用查詢無關寫入（query-agnostic writing）與問題導向讀取，問題到來時無需重新處理歷史影格，提升推論效率。
- 設計依新穎性（novelty）進行的線上新增–合併–驅逐更新機制，動態維護結構化事件庫。
- 支援模組化編碼器–投影器 VLM 與無編碼器／投影器的 NEO-ov 架構，具廣泛模型適用性。
- 在四個串流與長影片基準及三個 VLM 骨幹上達到優異壓縮效能，僅使用 10% 視覺標記預算。

### 適合對象
從事多模態學習、長影片理解、串流影片分析與視覺語言模型效率化研究的學者與工程師；特別適合關注免訓練（training-free）方法、視覺標記壓縮、記憶體機制設計，以及欲將 VLM 部署於長影片或即時串流場景的讀者。

## 深度分析

#### 方法論解析

KeyRec 的核心貢獻在於把「壓縮視覺上下文」重新定義為「建立有界視覺記憶體（bounded visual memory）」。傳統 dense VLM（密集視覺語言模型）會把每一個影格（frame）透過視覺編碼器轉成數十到數百個 visual tokens（視覺標記），隨著影片長度 𝜏 線性增長；在 prefilling（預填充）階段，dense self-attention（密集自注意力）的計算量又隨序列長度二次成長，這對 streaming video（串流影片）與 long videos（長影片）都構成可擴展性瓶頸。KeyRec 把這個問題形式化為一個 query-agnostic writing（查詢無關寫入）與 query-adaptive reading（查詢自適應讀取）的分離架構：

- 寫入階段：\(M_t = \text{Update}_M(M_{t-1}, H_t)\)，且 \(|M_t| \le S\)。這裡 \(H_t=\Phi(x_t)\) 是模型原生視覺嵌入（model-facing visual embeddings，面向模型的視覺嵌入），\(S\) 是 persistent visual-token storage budget（持久視覺標記儲存預算）。
- 讀取階段：當問題 \(q\) 在時間 𝜏 到達時，\(Z_q = \text{Read}(M_\tau, q)\)，且 \(|Z_q| \le B\)。\(B\) 是 fixed readout budget（固定讀取預算），最終答案由 \(\hat y = \text{VLM}(Z_q, q)\) 產生，無需重新處理歷史影格。

在記憶體結構上，KeyRec 採用雙層設計：\(M_t=(C_t, E_t)\)。

第一層是 visual cache（視覺快取）\(C_t\)，專門保留 fine-grained recent observations（細粒度的近期觀察）。這個快取最多儲存 \(N_C\) 個 visual tokens，目的是回答「現在正在發生什麼」這類需要高細節的即時問題。由於近期影格通常包含最多與當前問題相關的動作、物體與場景細節，KeyRec 選擇以較高解析度保留它們，而不是與歷史事件共用同一套稀疏化策略。

第二層是 structured event bank（結構化事件庫）\(E_t=\{e_k\}_{k=1}^{K_t}\)，用來組織 long-range history（長程歷史）中的關鍵事件證據。每個事件 \(e_k\) 最多包含 \(m\) 個 tokens，整個事件庫最多 \(K\) 個事件，因此總儲存量滿足 \(|C|+\sum_{e_k\in E_t}|e_k|\le N_C+Km\le S\)。事件庫的寫入流程是 KeyRec 最具特色的部分：當新影格到達時，系統會根據其相對於已儲存事件的 novelty（新穎性）提出 candidate events（候選事件）；接著透過 online add–merge–evict update（線上新增–合併–驅逐更新）來維護事件庫。這個更新同時考慮 semantic similarity（語義相似度）與 temporal proximity（時間鄰近性）——語義相近且時間接近的觀察會被合併成同一事件，語義新穎的觀察會被新增，而重要性較低或過時的事件則被驅逐。這樣的設計避免了傳統方法把「連貫事件證據」切成零碎 token，也減少了把不同時間但視覺相似的場景誤判為同一事件的風險。

當問題到達時，KeyRec 使用一個 text-only router（純文字路由器）來決定如何分配 fixed readout budget（固定讀取預算）\(B\)。路由器只根據問題文字，自適應地決定要從 visual cache（近期記憶體）還是 event bank（事件記憶體）讀取多少 token，並可進一步依據 query relevance（查詢相關性）或 temporal coverage（時間覆蓋率）從事件庫中檢索事件。由於整個讀取過程只讀取已儲存的記憶體，無需重新編碼歷史影格，因此能顯著降低 inference（推論）延遲與記憶體佔用。

KeyRec 的另一個重要特性是它直接操作 model-facing visual embeddings（面向模型的視覺嵌入），而非在原始像素或中間特徵上進行壓縮。這讓它能同時支援兩種截然不同的 VLM（視覺語言模型）架構：傳統的 modular encoder–projector VLMs（模組化編碼器–投影器視覺語言模型），以及 encoder- and projector-free 的 NEO-ov architecture（無編碼器且無投影器的 NEO-ov 架構）。對於 NEO-ov 這類 native one-vision VLM，KeyRec 還會保留 token 的時空索引結構，確保壓縮後的視覺標記仍然能被模型正確解讀。整個框架是 training-free（免訓練）的，意味著不需要額外的訓練資料或微調，就能直接套用在已凍結的模型上。

#### 實驗數據解讀

論文在四個 streaming and long-video benchmarks（串流與長影片基準測試）與三個 VLM backbones（視覺語言模型骨幹網路）上進行評估，包括 Gemma 4 E2B/E4B 與 NEO-ov 2B。最引人注目的數據是：KeyRec 僅使用 10% 的 dense decoder-facing visual-token budget（面向解碼器的密集視覺標記預算），就在 13/15 個設定中取得最佳 compressed performance（壓縮後效能）。這相當於在視覺標記數量上達到約 10 倍的壓縮比，同時在多數情境下仍優於所有比較的 compressed baseline（壓縮基線）。

在即時問題（real-time questions）上，KeyRec 相較於最強的壓縮基線提升了 2.21–18.37 points（分）。這個範圍很大，顯示在某些串流任務中，傳統 token-selection（標記選擇）方法會嚴重遺失近期細節，而 KeyRec 透過獨立的 visual cache（視覺快取）與 query-adaptive router（查詢自適應路由器）有效彌補了這個缺口。長影片設定（long-video settings）方面，KeyRec 在六個設定中的五個取得最佳 compressed result（壓縮結果），說明事件庫的結構化組織對於需要回溯數分鐘甚至數十分鐘前事件的問題特別有幫助。至於 NEO-ov 2B，KeyRec 在所有設定都表現最佳，這強調了該方法對於新興 native one-vision 架構的相容性，也證明「保留 token 結構」對於這類模型至關重要。

從實驗設計的角度來看，論文採用的是「固定壓縮預算下的相對比較」：所有方法都只能在 10% 的原始視覺標記預算內運作，因此勝出代表在相同成本下保留了更多資訊。不過，由於提供的上下文未包含絕對數值（例如 dense baseline 的準確率、KeyRec 相對於 dense 的絕對下降幅度、各資料集的評估指標細節），我們無法判斷 10% 預算下的效能是否已接近未壓縮模型。若 dense baseline 的準確率遠高於所有壓縮方法，則 10% 預算仍可能伴隨顯著資訊損失；反之，若差距很小，則 KeyRec 幾乎達到「無損壓縮」的效果。此外，13/15 的勝率雖高，但仍有兩個設定未達最佳，這暗示某些影片類型或問題分佈可能對事件庫的設計較不敏感，或是 hyperparameter（超參數）設定在這些情境下並非最優。

#### 與現有研究的比較

現有的 training-free visual-token selection methods（免訓練視覺標記選擇方法）主要透過 spatial-temporal scoring（時空評分）、相鄰影格差異、historical anchors（歷史錨點）或 compact semantic representation（緊湊語義表示）來移除重複背景與低資訊內容。這些方法在降低視覺上下文長度上確實有效，但論文指出三個關鍵限制：

1. **缺乏事件層級組織**：novelty（新穎性）通常只與最近影格、粗糙錨點或全域語義比較，導致演變中的事件被切碎，而視覺相似但時間不同的發生則被混淆。KeyRec 透過 structured event bank（結構化事件庫）與 add–merge–evict update（新增–合併–驅逐更新）把歷史證據組織成 temporally localized events（時間局部化事件），改善了連貫性。
2. **遺失連貫的事件證據**：獨立選取 informative tokens（資訊性標記）可能丟棄連接動作者、動作、物體與場景的上下文。KeyRec 以事件為單位保留證據，並透過語義相似度與時間鄰近性來合併相關觀察。
3. **近期觀察與長程歷史互相競爭**：傳統方法對整段影片套用統一的 retention policy（保留策略），使得 detailed recent observations（詳細的近期觀察）與 long-range history（長程歷史）爭奪同一預算。KeyRec 明確分離 visual cache（近期記憶體）與 event bank（事件記憶體），並由 router（路由器）根據問題動態分配 readout budget（讀取預算）。

相較於這些方法，KeyRec 的優勢在於把壓縮問題提升到「記憶體管理」的層次：寫入時建立 bounded（有界）且 query-agnostic（查詢無關）的記憶體，讀取時再根據問題做固定預算下的自適應檢索。這也讓它能跨越多種 VLM 架構，包括無編碼器的 NEO-ov。

然而，KeyRec 仍存在一些限制。首先，text-only router（純文字路由器）完全依賴問題文字來分配預算，無法看到實際視覺內容；如果問題用詞模糊或同時涉及近期與歷史，路由器可能誤判。其次，事件的新穎性判斷、語義相似度門檻、合併與驅逐策略都依賴啟發式設計與超參數（如 \(N_C\)、\(K\)、\(m\)），在沒有訓練的情況下難以針對特定領域自動調整。第三，事件庫的容量固定，若影片內容極度豐富或事件密度高，\(m\) 個 token 可能不足以保留關鍵細節；而過度合併語義相近的事件，也可能讓時間上相近但因果不同的場景被混為一談。最後，雖然 KeyRec 支援 NEO-ov，但對於其他新興架構（例如完全無 token 的連續視覺表示）是否適用，仍需進一步驗證。

#### 可重現性評估

從提供的上下文來看，論文並未明確提及是否公開 source code（原始碼）、model weights（模型權重）或實驗腳本。作者來自 Google，使用的模型（Gemma 4 E2B/E4B、NEO-ov 2B）與資料集（Lin et al., 2026a; Niu et al., 2025; Fu et al., 2026; Wu et al., 2024）多為公開或即將公開的資源，這降低了部分重現門檻。由於 KeyRec 是 training-free（免訓練）框架，原則上不需要額外的訓練資料或 GPU 訓練，只要取得預訓練模型即可執行。

不過，重現的關鍵在於實作細節：candidate event（候選事件）的提取方式、novelty（新穎性）的數學定義、semantic similarity（語義相似度）的度量（例如 cosine similarity 或學習式距離）、temporal proximity（時間鄰近性）的門檻、add–merge–evict（新增–合併–驅逐）的優先順序，以及 text-only router（純文字路由器）的 prompt（提示詞）設計。這些細節若未在論文或補充材料中完整披露，不同實作者可能會得到差異頗大的結果。此外，由於涉及 streaming（串流）設定，latency（延遲）、throughput（吞吐量）與 memory footprint（記憶體佔用）也會受到程式實作品質與硬體環境影響。

整體而言，KeyRec 的可重現性處於「中等」水準：概念清楚、不依賴私有訓練資料，但若要完全復現論文宣稱的 13/15 最佳表現，仍需要作者釋出程式碼與完整超參數。建議未來版本附上 reproducibility checklist（可重現性檢查清單），包含環境設定、隨機種子、router prompt、事件相似度門檻，以及各資料集的預處理流程。

#### 未來研究方向

KeyRec 為串流與長影片理解開啟了幾個值得深入探索的方向：

1. **學習式路由器與記憶體策略**：目前的 text-only router（純文字路由器）與 add–merge–evict（新增–合併–驅逐）規則都是啟發式設計。未來可引入輕量級 adapter（轉接器）或強化學習，讓路由器根據問題類型與記憶體內容學習最佳預算分配，同時讓事件合併與驅逐策略從資料中自動學習。
2. **多層次事件記憶體**：目前事件庫以單一粒度儲存事件。可進一步建立 hierarchical event memory（階層式事件記憶體），例如「場景—事件—動作—關鍵影格」多層結構，讓讀取階段能根據問題抽象程度選擇不同粒度。
3. **動態記憶體預算**：目前 \(N_C\)、\(K\)、\(m\) 為固定值。未來可根據影片動態程度（例如動作速度、場景變化率）自動調整近期快取與事件庫大小，在靜態片段節省預算，在動態片段保留更多細節。
4. **跨模態記憶體寫入**：除了視覺嵌入，也可整合 audio（音訊）、ASR 字幕或使用者互動文字來輔助事件偵測與合併，特別適用於多模態串流場景。
5. **與長上下文技術結合**：KeyRec 壓縮視覺標記，但語言模型本身的 context length（上下文長度）與 KV cache（鍵值快取）仍是瓶頸。可研究如何將視覺記憶體與 KV cache compression（KV 快取壓縮）或 prompt caching（提示快取）技術結合。
6. **理論分析**：探討在固定儲存預算 \(S\) 與讀取預算 \(B\) 下，資訊損失的下界與事件庫設計的理論保證，有助於指導超參數選擇。
7. **更長與互動式串流**：目前的評估集中在四個基準測試。未來可在數小時甚至數天的 continuous streams（連續串流）上測試，並加入互動式問答（例如使用者可追問「剛才那輛車是什麼顏色？」）。
8. **多攝影機與第一人稱視角**：將 KeyRec 擴展到 multi-camera（多攝影機）或 egocentric（第一人稱）串流，需要處理視角切換與時間對齊問題。
9. **事件庫索引與快速檢索**：當事件庫規模變大時，可依據語義或時間建立索引，加速 query relevance（查詢相關性）檢索。
10. **與訓練式壓縮方法融合**：雖然 KeyRec 強調 training-free（免訓練），但可探索在凍結模型上加入少量可學習參數（例如視覺標記投影或事件嵌入），在保持低訓練成本的前提下進一步提升壓縮品質。

## 論文問答

**Q1：KeyRec 主要想解決什麼問題？**

A：KeyRec 旨在解決視覺語言模型在處理長影片與連續串流時，因密集視覺標記隨影格數線性累積而導致的長上下文推論成本過高問題。隨著影片長度增加，視覺序列會變得越來越長，使得預填充階段的密集自注意力計算量呈現二次成長。這種現象對於串流影片尤其嚴重，因為其長度未知且問題可能隨時到達，因此需要一種有界且可重複使用的視覺記憶體來降低推論負擔。

**Q2：現有的免訓練視覺標記選擇方法為何不足？**

A：現有方法雖然能透過保留資訊性標記來減少冗餘，但存在三個主要限制：它們常以近期影格或粗略錨點衡量新穎性，導致演變中的事件被碎片化，或將時間不同但視覺相似的事件混淆。此外，獨立選擇重要標記可能會丟棄連結行為者、動作、物體與場景的支援性上下文，使事件證據失去連貫性。最後，這些方法通常對整段影片採用統一的保留策略，迫使詳細的近期觀察與長程歷史證據相互競爭，無法同時兼顧兩者的需求。

**Q3：為何有界視覺記憶體對可擴展的影片理解至關重要？**

A：有界視覺記憶體能夠在儲存容量受限的前提下，持續保存串流或長影片中的關鍵資訊，避免因影片長度無限增長而耗盡記憶體或超出上下文預算。對於串流場景而言，問題可能隨時到達，因此必須在查詢到來前就以查詢無關的方式建立好記憶體。這種設計不僅能讓多個問題重複使用同一組視覺記憶，也無需為每個問題重新處理所有歷史影格，大幅提升推論效率。

**Q4：KeyRec 的核心方法架構是什麼？**

A：KeyRec 是一個免訓練框架，將查詢無關的記憶體寫入與查詢自適應的固定預算讀取解耦開來。在寫入階段，它同時維護一個保存細粒度近期觀察的視覺快取，以及一個以結構化方式組織歷史證據的事件庫；新事件會根據相對於已儲存事件的新穎性被提出，並透過線上新增–合併–驅逐機制進行維護。當問題到達時，純文字路由器會在固定讀取預算下，自適應地分配近期記憶體與事件記憶體的比例，且無需重新處理歷史影格。

**Q5：KeyRec 相較於先前方法的主要創新是什麼？**

A：KeyRec 將視覺壓縮從單純的標記選擇提升為有界視覺記憶體的組織問題，這是其最核心的創新。它明確區分細粒度的近期觀察與結構化的長程歷史事件，並利用語義相似性與時間鄰近性來維護事件庫，從而保留連貫的事件證據。此外，純文字路由器的引入讓系統能根據問題內容動態調配讀取預算，在不需要重新編碼歷史畫面的情況下實現靈活的記憶體讀取。

**Q6：KeyRec 為何能支援不同類型的視覺語言模型架構？**

A：KeyRec 運作於面向模型的視覺嵌入層，因此能直接適用於模組化編碼器–投影器視覺語言模型，也能支援無編碼器且無投影器的 NEO-ov 架構。對於 NEO-ov，它會保留所選標記的時間與空間索引，確保原生單一視覺模型能正確解讀壓縮後的視覺輸入。這種與模型內部表徵對齊的設計，使同一套記憶體機制能夠跨越多種骨幹網路進行部署。

**Q7：KeyRec 在哪些基準測試與模型骨幹上進行評估？**

A：KeyRec 在四個串流與長影片基準測試以及三個視覺語言模型骨幹上進行評估，其中包括 Gemma 4 E2B/E4B 與 NEO-ov 2B。這些基準涵蓋了即時問題的串流場景，以及需要理解長篇錄影的長影片問答任務。如此廣泛的評估設計能夠驗證 KeyRec 在不同資料特性與模型架構下的泛化能力。

**Q8：KeyRec 的關鍵實驗結果有哪些？**

A：KeyRec 在 15 個設定中有 13 個達到最佳壓縮後效能，且僅使用面向解碼器的密集視覺標記預算的 10%。在即時問題上，它相較於最強的壓縮基線提升了 2.21 至 18.37 分；在六個長影片設定中，有五個取得最佳壓縮結果。此外，在所有 NEO-ov 2B 的設定中，KeyRec 都表現最佳，顯示其對原生單一視覺模型特別有效。

**Q9：從 KeyRec 的設計可以推導出哪些消融研究的洞見？**

A：將視覺快取與事件庫分離的設計顯示，同時保留細粒度近期觀察與結構化歷史事件對於維持推理品質至關重要。線上新增–合併–驅逐機制則確保事件庫在容量有界的情況下，仍能持續保留時間局部化且語義連貫的證據。純文字路由器的自適應預算分配也說明，不同問題對近期與歷史資訊的需求並不相同，固定讀取預算下的動態調配能有效提升整體表現。

**Q10：哪些實際應用場景最能受惠於 KeyRec？**

A：KeyRec 特別適合需要即時分析連續串流的場景，例如監控系統、直播內容審核、自動駕駛或機器人視覺等，因為這些應用的影片長度無法預先確定，且問題可能隨時出現。它也適用於長影片理解任務，例如紀錄片、體育賽事或教育影片的問答系統。由於其記憶體有界，KeyRec 也更容易部署在記憶體與計算資源受限的邊緣裝置上。

**Q11：在產品化部署 KeyRec 時需要考慮哪些因素？**

A：產品團隊需要仔細權衡持久儲存預算與每次查詢讀取預算之間的取捨，因為這兩者直接決定了儲存成本與推論延遲。查詢無關的寫入階段讓同一部影片的記憶體能被多個問題重複使用，非常適合互動式問答產品。然而，純文字路由器的分配策略需要針對實際問題分布進行驗證，以確保在特定應用場景中不會過度偏重近期或歷史記憶體。

**Q12：KeyRec 可能對影片理解領域帶來什麼影響？**

A：KeyRec 推動了視覺壓縮研究從單純標記選擇走向結構化記憶體組織的新典範，可能啟發更多記憶體增強型多模態模型的發展。它在極低視覺標記預算下仍能保持強勁效能，降低了將視覺語言模型應用於長影片與串流任務的門檻。由於其免訓練特性，現有模型可以較容易地整合 KeyRec，加速相關技術的實際落地。

**Q13：KeyRec 可能存在哪些限制？**

A：KeyRec 依賴新穎性來提出候選事件，這可能導致某些視覺變化細微但語義重要的事件被忽略。純文字路由器僅根據問題文字分配記憶體預算，無法直接參考視覺內容，可能在某些需要精細視覺判斷的問題上分配不當。此外，固定的儲存預算對於場景極度複雜或變化極快的影片可能仍顯不足。

**Q14：KeyRec 在哪些失敗案例中可能表現不佳？**

A：當多個事件視覺相似但語義不同時，KeyRec 可能因新穎性不足而將它們合併或遺漏，導致歷史證據失真。若關鍵證據分散在很長的時間間隔中，而事件庫容量有限，則可能無法同時保留所有相關事件。此外，在快速切換場景的影片中，固定大小的視覺快取可能無法完整捕捉近期細節，進而影響「現在發生什麼事」這類問題的準確率。

**Q15：KeyRec 指出了哪些未來研究方向？**

A：未來可以探索結合文字與視覺特徵的學習型路由器，以更精準地預測近期與歷史記憶體的最佳分配比例。另一個方向是設計階層式事件結構，讓事件庫能表達更豐富的時間關係與因果推理。此外，將 KeyRec 擴展至多模態串流理解，例如同時整合音訊或感測器訊號，也有助於建構更完整的連續感知系統。

## 實務應用指南

### 適用場景

- **即時監控與異常告警**：適用於連續串流影片，查詢隨機到達且需快速回應的場景。KeyRec 的近期視覺快取（Visual Cache）可保留「現在發生什麼」的細節，事件庫（Event Bank）則保留異常或關鍵歷程。
- **長影片內容審查與合規**：針對長篇錄影需多次查詢、反覆審閱的情境，KeyRec 以查詢無關寫入（Query-Agnostic Writing）建立有界視覺記憶體（Bounded Visual Memory），避免每次問題都重新處理歷史影格。
- **智慧零售與顧客行為分析**：在攝影機串流中追蹤特定事件（如結帳、貨架互動、排隊），需要連貫的事件證據（Coherent Event Evidence），而非零散的視覺標記（Visual Tokens）。
- **遠距醫療與手術／復健影片回顧**：長影片理解需同時掌握細粒度的近期觀察（Fine-Grained Recent Observations）與長程歷史（Long-Range History），KeyRec 的雙記憶體設計可兼顧兩者。
- **自動駕駛與機器人視覺日誌**：在記憶體與計算受限的邊緣裝置上，KeyRec 能以僅 10% 的密集解碼器端視覺標記預算（Dense Decoder-Facing Visual-Token Budget）維持可擴展的影片理解（Scalable Video Understanding）。

### 實作前置條件

- **資料（Data）**：
  - 原始影片串流或長影片檔案。
  - 可取得模型原生、面向模型的視覺嵌入（Model-Facing Visual Embeddings）。
  - 若使用 NEO-ov 等無編碼器且無投影器架構，需能保留視覺標記的時空索引。
- **運算（Compute）**：
  - 支援的視覺語言模型骨幹（VLM Backbones），例如 Gemma 4 E2B/E4B 或 NEO-ov 2B。
  - 足夠的 GPU／TPU 資源進行預填充（Prefilling）與推理。
  - 明確的持久儲存預算 \(S\) 與每次查詢讀取預算 \(B\)，需根據延遲與顯存上限設定。
- **技能（Skills）**：
  - 熟悉 VLM 推理管線、視覺標記化（Visual Tokenization）與投影器行為。
  - 具備向量相似度計算、線上資料結構（如滑動視窗、優先佇列）設計能力。
  - 能進行延遲優化、記憶體預算調校與串流系統整合。

### 實作步驟建議

1. **選定骨幹並確認嵌入介面**  
   判斷目標系統屬於模組化編碼器–投影器 VLM（Modular Encoder–Projector VLMs）或 NEO-ov 架構，並確認每幀可取得視覺嵌入 \(H_t = \Phi(x_t)\)。

2. **設定記憶體預算**  
   定義近期快取大小 \(N_C\)、事件庫事件數上限 \(K\)、每事件標記數上限 \(m\)，使總儲存量 \(|C| + \sum |P_k| \leq S\)，同時設定每次查詢的固定讀取預算（Fixed Readout Budget）\(B\)。

3. **建立近期視覺快取（Visual Cache）**  
   每來一幀即將其視覺標記寫入快取；超過 \(N_C\) 時，依時間順序驅逐最舊幀或最舊標記，保留詳細的近期觀察。

4. **事件候選提出（Candidate Event Proposal）**  
   對新進幀計算相對於已儲存事件的新穎性（Novelty），結合語義相似度與時間鄰近性，決定是否形成新的候選事件。

5. **線上新增–合併–驅逐更新（Online Add–Merge–Evict Update）**  
   - **Add**：新穎性高時新增事件。  
   - **Merge**：與現有事件語義相近且時間接近時合併，避免連貫事件證據碎片化。  
   - **Evict**：事件庫超過 \(K\) 時，依重要性、時間遠近或覆蓋率驅逐。

6. **建構純文字路由器（Text-Only Router）**  
   根據問題文字特徵（例如「現在發生什麼？」vs.「稍早發生了什麼？」），動態分配讀取預算 \(B\) 給近期記憶體（Recent Memory）與事件記憶體（Event Memory）。

7. **查詢時讀取（Read）**  
   問題到達後，不重新處理歷史影格，直接從快取與事件庫選取相關視覺標記組成 \(Z_q\)，輸入 VLM 生成答案。

8. **評估與調校**  
   在串流與長影片基準測試（Streaming and Long-Video Benchmarks）上衡量壓縮後效能（Compressed Performance），調整 \(N_C\)、\(K\)、\(m\)、\(B\) 與新穎性閾值，達到目標延遲與準確率。

### 潛在風險與注意事項

- **事件碎片化或過度合併**：新穎性閾值過低會把不同時間點的相似事件混為一談；過高則使同一事件被切分成多段。建議以驗證集監控事件數量與品質。
- **近期與長程平衡失調**：純文字路由器若過度偏向近期快取，會遺漏長程歷史；過度偏向事件庫則可能失去回答「現在」問題所需的細節。可依問題類型做動態或學習式分配。
- **語義漂移（Semantic Drift）**：長時間串流中場景緩慢變化，歷史錨點（Historical Anchors）可能過時。可引入時間衰減或定期更新事件摘要。
- **計算瓶頸轉移**：雖然減少了解碼器端密集自注意力（Dense Self-Attention）的開銷，但線上 add–merge–evict 與相似度計算會帶來額外成本。必要時使用近似最近鄰（ANN）或量化加速。
- **模型相依性**：KeyRec 運作於 model-facing embeddings，不同骨幹的投影器輸出或 NEO-ov 原生標記結構不同，需針對特定 VLM 調整索引與維度處理。

### 與其他技術的整合建議

- **與現有 VLM 服務整合**：將 KeyRec 作為編碼器與解碼器之間的記憶體層，對下游維持相同 API，僅在內部替換視覺上下文（Visual Context）。
- **與向量資料庫整合**：事件庫可存放於向量資料庫，利用 ANN 搜尋加速事件合併與查詢相關性檢索。
- **與串流處理框架整合**：搭配 Kafka、Kinesis 或即時推理引擎，每個影格到達即觸發 Update，問題到達即觸發 Read。
- **與快取／分層儲存整合**：將近期快取視為 LRU 快取，事件庫視為長期分層儲存，支援多查詢共用同一視覺記憶體。
- **與檢索增強生成（RAG）或領域微調整合**：KeyRec 為免訓練（Training-Free）模組，可與領域微調模型或文字 RAG 並行；事件庫提供視覺證據，文字 RAG 提供外部知識。

### 給不同背景讀者的閱讀建議

- **初學者**：先理解「為何長影片會讓 VLM 推論變慢」以及「有界視覺記憶體」的核心概念，再對照論文圖表觀察近期快取與事件庫如何分工，不必一開始深入相似度計算與路由器的數學細節。
- **AI 工程師**：重點閱讀 Method 與實作細節，關注 model-facing embeddings、add–merge–evict 的線上複雜度、純文字路由器的預算分配策略，並參考論文附錄中的超參數與記憶體預算設定。
- **研究人員**：關注問題形式化、與其他免訓練視覺標記選擇方法（Training-Free Visual-Token Selection Methods）的比較、實驗設計與消融研究，思考如何將事件記憶體機制擴展至多模態長上下文或主動學習。
- **產品經理**：聚焦適用場景、效能數據（13/15 設定最佳、僅用 10% 標記預算）與部署成本，評估哪些產品線可透過 KeyRec 降低推理延遲與記憶體支出，並規劃與現有串流或長影片產品的整合路徑。
