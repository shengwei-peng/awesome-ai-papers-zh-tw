## 摘要翻譯

高品質的結構化有機反應（organic reaction）資料對於發展化學人工智慧（artificial intelligence for chemistry, AI4Chem）至關重要，然而這些知識大多仍分散於專利文本（patent text）、圖像與反應圖示（reaction schemes）之中。本研究提出 DianShi-RxnDB，這是一個大規模（large-scale）、細粒度（fine-grained）的有機反應資料平台（data platform），透過一套整合專利文本、圖像與反應圖示的全自動化抽取與正規化（extraction and normalization）管線建置而成。其語料庫涵蓋美國專利商標局（USPTO）與歐洲專利局（EPO）於 1976 至 2025 年間公開之有機合成（organic synthesis）專利，產出約 2,400 萬筆反應實例（reaction instances），其中約 1,480 萬筆（61.7%）通過自動化品質檢定（qualification checks）。每個實例代表一個特定的單步驟實驗（single-step experiment），記載反應參與物（participants）、角色（roles）、用量（quantities）、溫度（temperatures）、反應時間（reaction times）、產率（yields）、實驗程序（experimental procedures），以及來源專利（source patents）的出處連結（provenance links）。針對 1,300 筆抽樣合格實例進行人工評估後，微平均欄位級準確率（micro-averaged field-level accuracy）達 92.95%。與 Pistachio 的配對比較進一步顯示，本平台在去重複後的記錄數量（deduplicated record counts）、表徵細緻度（representation granularity）與欄位級精確一致率（field-level exact agreement）方面具有優勢。本平台提供網頁研究工作台（Web research workbench），支援記錄的搜尋、篩選、比較與來源驗證（source-verifying），另提供模型上下文協定（Model Context Protocol, MCP）服務，為 AI 代理（AI agents）提供可組合的結構化檢索工具（composable structured retrieval tools）。DianShi-RxnDB 可於以下網址取得：https://dianshi.opendatalab.org.cn/ 。

### 核心貢獻（3～5點）
- 建構大規模有機反應資料庫：涵蓋 USPTO 與 EPO 於 1976–2025 年間公開的有機合成專利，產出約 2,400 萬筆反應實例，其中約 1,480 萬筆通過自動化品質檢定。
- 提出全自動化抽取與正規化管線：整合專利文本、圖像與反應圖示，將反應參與物、角色、用量、溫度、反應時間、產率、實驗程序與來源專利出處連結結構化。
- 具備高資料品質與可比性：人工評估顯示微平均欄位級準確率達 92.95%，與 Pistachio 相比在去重複記錄數、表徵細緻度與欄位級精確一致率上具優勢。
- 同時服務研究者與 AI 代理：提供網頁研究工作台進行搜尋、篩選、比較與來源驗證，並透過 MCP 服務提供可組合的結構化檢索工具。

### 適合對象
本論文最適合從事化學資訊學、化學人工智慧（AI4Chem）、有機合成、藥物與材料研發的研究者，以及需要大規模、可溯源、機器可讀反應資料來訓練模型或建構檢索系統的 AI 開發者與資料工程師閱讀。

## 深度分析

#### 方法論解析

DianShi-RxnDB（點石反應資料庫）的核心方法論可視為一條「從非結構化專利文獻到結構化反應實例（reaction instances）」的全自動抽取與正規化（extraction and normalization）管線。其輸入資料涵蓋美國專利商標局（USPTO）與歐洲專利局（EPO）自 1976 年至 2025 年間的有機合成專利，並同時處理專利文本（patent text）、圖像（images）與反應式／反應圖示（reaction schemes）三種模態。整體流程可拆解為以下環節：

1. **多模態文件解析與化學實體辨識**  
   專利中的反應知識分散於主文、實施例、表格、圖說與支持資訊，因此管線必須整合文字理解、圖像理解與版面分析。對於文本，系統需執行化學實體（chemical entities）辨識、IUPAC 名稱或分子式解析；對於圖像與反應式，則需進行化學結構圖像辨識（image-to-structure）以產生機器可讀（machine-readable）的結構表示（如 SMILES／InChI）。此處的挑戰在於同一化合物可能以文字、結構圖、編號三者並存，必須透過上下文連結（contextual linking）與文件內交叉引用（in-document cross-references）進行對齊。

2. **反應關係與角色判定**  
   在取得化合物結構後，系統需判斷反應關係（reaction relationships），並將各參與物（participants）指派為反應物（reactants）、試劑（reagents）、催化劑、溶劑或產物（products）等角色（roles）。這一步不僅依賴反應式圖示中的箭頭方向，也必須參考文本中的動詞、操作描述與化學語境，才能正確區分「反應物」與「過量試劑」。

3. **實驗邊界判定與欄位抽取**  
   有別於僅記錄反應骨架的資料集，DianShi-RxnDB 以單步驟實驗（single-step experiment）為基本單位，因此必須進行實驗邊界判定（experimental-boundary determination）：從專利實施例中切分出每一次獨立反應，並抽取用量（quantities）、當量（equivalents）、溫度（temperatures）、反應時間（reaction times）、產率（yields）與實驗程序（experimental procedures）等欄位。程序欄位更進一步對應到預定義的操作與參數，形成結構化程序（structured procedures）。

4. **表示法正規化與來源定位**  
   為確保跨文件的一致性，管線執行表示法正規化（representational normalization），包括結構標準化、單位換算、溫度與時間區間統一等。同時，每一筆 reaction instance 都保留來源連結（provenance links），並定位至段落層級（paragraph-level provenance localization），使研究者能進行來源驗證（source-verifying）。

5. **資格檢查與反應群組聚合**  
   抽取完成後，系統執行自動化資格檢查（qualification checks），篩除欄位缺失、結構解析失敗或語義不一致的紀錄。通過檢查的 reaction instances 約占 61.7%。隨後，資料模型將相同反應物–產物組合的實例聚合為 Reaction Group（反應群組），但保留各實例的條件、產率、程序與來源，以支援比較與檢索。

6. **雙軌服務介面**  
   在資料層之上，平台提供網頁研究工作台（Web research workbench）供研究者搜尋、篩選、比較與驗證；另提供 Model Context Protocol（MCP，模型上下文協定）服務，將查詢能力封裝為可組合的結構化檢索工具（composable structured retrieval tools），供 AI agents（AI 代理）進行多步推理與資料調用。

#### 實驗數據解讀

論文報告的實驗結果主要圍繞三個數字：資料規模、欄位級準確率，以及與 Pistachio 的配對比較。

- **規模與資格通過率**  
  管線從 USPTO 與 EPO 專利中產出約 2,400 萬筆 reaction instances，其中約 1,480 萬筆（61.7%）通過自動化資格檢查（qualification checks）。這個比例具有雙重意義：一方面顯示全自動管線能從大量專利中回收可觀的結構化反應紀錄；另一方面也說明將近四成紀錄因欄位不完整、結構解析失敗或語義不一致而被過濾。這 38.3% 的損失可能包含部分「實際有效但表達複雜」的反應，例如依賴多段落交叉引用、使用罕見縮寫或圖像品質不佳的實施例。

- **微平均欄位級準確率（micro-averaged field-level accuracy）**  
  在 1,300 筆抽樣的合格 reaction instances 上，人工評估得到 92.95% 的微平均欄位級準確率。微平均意味著所有欄位預測被視為單一樣本集合進行計算，因此熱門欄位（如反應物結構）會主導分數。92.95% 顯示對於已通過資格檢查的資料，欄位內容大致可信；但需注意評估對象僅限「合格」樣本，未涵蓋被過濾掉的 38.3%，因此整體管線的實際端到端準確率可能低於此數字。此外，欄位級準確率對於「部分正確」較不敏感，例如溫度區間被錯誤截取為單一數值、產率單位誤判等，可能仍被計為錯誤。

- **與 Pistachio 的配對比較**  
  論文指出 DianShi-RxnDB 在去重複後的記錄數量（deduplicated record counts）、表示粒度（representation granularity）與欄位級精確一致率（field-level exact agreement）上優於 Pistachio。Pistachio 是商業資料庫，具段落層級來源定位與豐富欄位，但需付費。DianShi-RxnDB 的優勢在於免費非商業存取、更新至 2025 年、並透過 MCP 提供機器存取。然而，比較的具體配對方法（例如以何種結構鍵進行對齊、如何定義「exact agreement」）在提供的摘要與引言中未詳述，需進一步檢視完整論文以判斷其客觀性。

整體而言，數據呈現「高覆蓋、中等通過率、高欄位準確率」的組合，適合作為反應先例檢索（reaction-precedent retrieval）、反應條件預測（reaction-condition prediction）與資料驅動的逆合成規劃（data-driven retrosynthetic planning）的資料基礎，但使用時仍建議對關鍵欄位進行來源驗證。

#### 與現有研究的比較

從引言中的 Table 1 可看出，現有有機反應資源在規模、文獻覆蓋、實驗欄位、來源定位與存取模式上差異顯著。DianShi-RxnDB 的定位介於「開放下載但較粗糙」的資料集與「專業但付費」的商業資料庫之間。

| 面向 | 開放資料集（USPTO-Lowe、CJHIF、USPTO-LLM） | 商業資料庫（Pistachio、Reaxys、CAS Reactions） | DianShi-RxnDB |
|---|---|---|---|
| 規模 | 數十萬至數百萬 | 數千萬至數億 | 約 2,400 萬原始 / 1,480 萬合格 |
| 文獻覆蓋 | 多限於 USPTO 1976–2016 | 廣泛（專利與期刊） | USPTO + EPO，1976–2025 |
| 實驗欄位 | 通常缺少程序或多階段支援 | 豐富，但欄位定義不一 | R·Q·C·S·P·Y·O，含結構化程序 |
| 來源定位 | 多僅到文件層級 | 部分到段落層級 | 段落層級（paragraph） |
| 機器存取 | 下載檔案為主 | API／MCP 需授權 | 免費 Web + MCP（非商業） |
| 人工策展 | 無或有限 | 有專業策展 | 全自動，無人工策展 |

**主要改進**：

1. **規模與時效性**：相較於 USPTO-Lowe（約 375 萬）與 USPTO-LLM（約 24.7 萬），DianShi-RxnDB 的原始紀錄數量提升近一個數量級，且涵蓋至 2025 年。
2. **欄位豐富度**：相較於多數開放資料集僅記錄反應物、產物與產率，DianShi-RxnDB 額外記錄角色、當量、條件、結構化程序與其他結果（outcomes other than yield），並支援多階段反應（multistage support）。
3. **來源可驗證性**：段落層級的來源定位（provenance localization）讓使用者能回溯原始專利段落，這對於 AI4Chem（化學人工智慧）應用中的可解釋性與信任度至關重要。
4. **AI 代理介面**：透過 MCP 提供可組合的結構化檢索工具，是現有開放資料集與部分商業資料庫所缺乏的設計。

**限制與待釐清之處**：

1. **文獻來源單一**：目前僅涵蓋 USPTO 與 EPO 專利，未納入期刊文章、中國（CNIPA）、日本（JPO）或韓國（KIPO）專利，可能偏限於特定語言與地區的化學知識。
2. **全自動無策展**：雖然規模大，但缺乏專業化學家的人工驗證。資格檢查（qualification checks）雖可過濾明顯錯誤，卻無法保證化學語義完全正確，例如立體化學、互變異構物（tautomers）或罕見官能基的判讀錯誤。
3. **評估偏差**：人工評估僅針對已通過資格檢查的樣本，可能高估實際可用資料的準確率；且 1,300 筆樣本相對於 1,480 萬筆合格紀錄仍屬少量，需更多分層抽樣與錯誤分析。
4. **比較方法透明度**：與 Pistachio 的配對比較細節（如去重複策略、欄位對齊規則）未在提供的文本中充分說明，影響可比較性。
5. **存取限制**：雖標示為免費非商業存取，但商業用途、大量批次下載與系統整合可能受授權條款限制，與完全開放的資料集仍有區別。

#### 可重現性評估

可重現性（reproducibility）是評估任何大規模資料平台的重要維度。根據目前提供的資訊：

- **資料與平台可及性**：DianShi-RxnDB 已於 https://dianshi.opendatalab.org.cn/ 上線，提供 Web 研究工作台與 MCP 服務，研究者與 AI agents 可透過這些介面查詢資料。這確保了「使用層級」的可重現性——其他團隊可以驗證查詢結果、進行下游實驗。
  
- **管線與模型開放性**：摘要與引言並未明確說明是否釋出抽取管線的原始碼、訓練資料、模型權重或資格檢查的具體規則。若僅提供查詢介面而無底層程式碼，則獨立研究者難以從原始專利重新產出相同的 2,400 萬筆 reaction instances，也難以驗證去重複、正規化與資格檢查的邏輯。

- **評估資料與協定**：人工評估的 1,300 筆樣本與評分準則是否公開，將直接影響社群能否複製 92.95% 的欄位級準確率。建議釋出評估腳本、標註指引與抽樣分層資訊。

- **資料模式與 API 文件**：為支援 AI agents 與批次研究，完整的資料綱要（schema）、MCP 工具規格、速率限制與授權條款必須透明。目前僅知為「免費非商業 Web/MCP 存取」，具體條款尚待確認。

綜合而言，DianShi-RxnDB 在「服務可重現」上已具基礎，但在「方法可重現」與「資料可重現」上仍需釋出更多技術細節與開源資產，才能達到學術社群普遍期待的完全可重現標準。

#### 未來研究方向

基於 DianShi-RxnDB 的設計與現有侷限，以下幾個方向值得後續探索：

1. **擴充文獻來源與語言覆蓋**  
   將管線延伸至期刊文章（如 ACS、RSC、Wiley）、化學預印本，以及中、日、韓等非英語專利，並處理多語言化學命名與單位慣例，可顯著提升資料代表性。

2. **多模態基礎模型與人機協作策展**  
   結合大型多模態語言模型（multimodal LLMs）與化學結構基礎模型，提升圖像與反應式解析的準確率；同時引入主動學習（active learning）與化學家人機協作（human-in-the-loop curation），針對低置信度實例進行標註與校正。

3. **標準化評估基準**  
   建立涵蓋結構、角色、用量、條件、產率、程序與來源定位的公開評測任務與標註資料集，讓不同抽取系統能在相同標準下比較，並進行細粒度錯誤分析。

4. **多階段反應與後處理資訊**  
   目前雖標示支援多階段反應（multistage support），但專利中常見的「one-pot」多步反應、後處理（work-up）、純化與分析數據仍有待更細緻的建模，以支援完整合成路徑重建。

5. **與 AI4Chem 下游任務深度整合**  
   將 DianShi-RxnDB 與反應結果預測（reaction-outcome prediction）、反應條件推薦、逆合成規劃（retrosynthetic planning）及實驗室自動化系統串接，並透過 MCP 提供更多工具（如條件優化、安全／毒性查詢、文獻趨勢分析）。

6. **去重複與反應索引標準**  
   發展統一的反應指紋與去重複協定，處理溶劑、試劑、條件差異與結構標準化問題，並建立版本控制機制，以支援資料更新與歷史追溯。

7. **開放資料釋出與可重現性 artifact**  
   釋出抽取管線原始碼、模型權重、資格檢查規則、去重複邏輯與評估樣本，將大幅提升學術可重現性，並促進社群共同改進平台。

## 論文問答

**Q1：DianShi-RxnDB 主要想解決什麼問題？為什麼高品質的結構化有機反應資料對 AI4Chem 如此重要？**

A：DianShi-RxnDB 旨在解決有機反應知識分散於專利文本、圖像與反應式中，難以直接轉換為統一且機器可讀的結構化反應記錄的問題。對於化學人工智慧（AI4Chem）而言，僅知道反應物與產物的結構變化並不足夠，還需要參與物角色、用量、反應條件、產率與實驗程序等細節，才能訓練反應結果預測、反應條件預測與資料驅動的逆合成規劃模型。因此，建立大規模、細粒度且來源可驗證的反應資料平台，是推動智慧化學研究的關鍵基礎建設。

**Q2：現有的開放反應資料集與專業資料庫存在哪些主要不足，為什麼無法完全滿足需求？**

A：現有開放資料集在資料規模、專利文獻覆蓋範圍、實例級實驗資訊、來源定位與資料組織一致性方面仍有明顯限制，難以支撐細粒度的反應檢索與條件比較。相較之下，專業資料庫雖然提供較豐富的策展資訊與檢索服務，但通常需要付費訂閱或商業授權，機器存取、批次使用與系統整合也常受到相應限制。DianShi-RxnDB 因此試圖在開放可及性與專業級資料品質之間取得平衡，提供免費非商業使用的網頁與 MCP 存取，同時保留段落級來源定位。

**Q3：為什麼專利文獻特別難以抽取成結構化反應資料？**

A：專利文件中的單一實驗資訊往往分散於不同段落、反應步驟與實施例之間，且部分化合物與操作必須結合一般程序、上下文與文件內交叉引用才能正確理解。反應結構、條件、產率與程序可能同時出現在主文、反應圖示、表格、圖說或實驗章節中，需要同時解讀文本、表格與圖像。因此，從原始專利建立細粒度反應資料，不僅要辨識化學實體與反應關係，還必須進行實驗邊界判定、上下文連結、來源定位與表徵正規化，這正是 DianShi-RxnDB 自動化管線所面對的核心挑戰。

**Q4：DianShi-RxnDB 的核心資料模型是什麼？「反應實例」與「反應群組」各自扮演什麼角色？**

A：DianShi-RxnDB 將反應知識組織為「物質（Substance）」、「反應實例（Reaction Instance）」、「反應群組（Reaction Group）」與「文獻（Reference）」四種結構化物件。每個反應實例代表從專利中抽取出的單步驟實驗，記錄反應物與產物的結構表示、參與物角色、各物質用量與當量、溫度、時間、產率、實驗程序，並連結到來源專利與段落位置。反應群組則將具有相同反應物—產物組合的多個單步驟反應實例聚合在一起，同時保留每個實例的條件、產率、程序與來源資訊，方便研究者進行檢索、比較與來源驗證。

**Q5：DianShi-RxnDB 自動化管線的關鍵創新點是什麼？**

A：該平台的關鍵創新在於建立了一條完全自動化的資訊抽取與正規化管線，能夠同時整合專利文本、圖像與反應式三種異質資訊來源。相較於僅處理文本或結構的傳統方法，此管線可將分散在不同模態中的反應參與物、角色、用量、條件與程序統一為結構化記錄，並進行表示法正規化。此外，管線還包含自動化資格檢查與段落級來源定位，確保資料不僅規模大，也具備可追溯性與一定的品質保證。

**Q6：為什麼 DianShi-RxnDB 選擇以「單步驟反應實例」作為基本單位，並同時提供網頁研究工作台與 MCP 服務？**

A：選擇單步驟反應實例作為基本單位，是因為它能精確對應到專利中實際報導的實驗操作，便於比較不同文獻對同一反應轉換所報告的條件、產率與程序。透過反應群組聚合相同反應物—產物組合，平台既能保留實例級的細節，又能支援宏觀的反應先例檢索。同時提供網頁研究工作台與模型上下文協定（MCP）服務，則是為了兼顧人類研究者對視覺化搜尋、篩選與來源驗證的需求，以及 AI 代理對可組合結構化檢索工具的需求。

**Q7：DianShi-RxnDB 進行了哪些評估？主要結果為何？**

A：研究團隊對 1,300 個通過自動化資格檢查的抽樣反應實例進行人工評估，結果顯示微平均欄位級準確率（micro-averaged field-level accuracy）達到 92.95%。這表示在反應參與物、角色、用量、溫度、時間、產率與程序等關鍵欄位上，絕大多數自動抽取結果與人工判讀一致。此準確率為平台作為大規模反應資料基礎的可信度提供了實證支持。

**Q8：DianShi-RxnDB 與 Pistachio 資料集進行了怎樣的比較？結果說明了什麼？**

A：論文進行了一項配對比較（matched comparison），從去重複後的記錄數量、表示粒度以及欄位級精確一致率三個面向，將 DianShi-RxnDB 與 Pistachio Reaction Dataset 進行對照。結果顯示 DianShi-RxnDB 在這些指標上具有優勢，代表其不僅能產生更多不重複的反應記錄，也能在更細緻的欄位層級與來源文件保持一致。這項比較凸顯了自動化管線在資料規模與結構化細節上的競爭力。

**Q9：自動化資格檢查的結果如何？它對資料品質有何意義？**

A：該管線從 1976 年至 2025 年的美國專利商標局（USPTO）與歐洲專利局（EPO）有機合成專利中，產出約 2,400 萬個反應實例，其中約 1,480 萬個（61.7%）通過自動化資格檢查。資格檢查可過濾掉結構不完整、欄位缺失或明顯不一致的記錄，確保後續分析與應用所依賴的資料具備基本品質。雖然仍有近四成實例未通過檢查，但這也反映了專利文獻本身的複雜性與自動抽取的挑戰。

**Q10：研究者可以如何利用 DianShi-RxnDB 的網頁研究工作台？**

A：網頁研究工作台支援搜尋、篩選、實例比較、連結探索與來源驗證等功能，讓研究者能夠針對特定反應轉換快速找到多篇專利中的相關實驗記錄。使用者可以比較不同實例的反應條件、產率與程序，並透過段落級來源連結回到原始專利文件進行人工確認。這對於有機合成方法開發、反應條件優化以及文獻調查都具有實用價值。

**Q11：MCP 服務如何支援 AI 代理使用 DianShi-RxnDB？**

A：模型上下文協定（MCP）服務將 DianShi-RxnDB 的查詢能力封裝為可組合的結構化檢索工具，使 AI 代理能夠進行多步驟查詢並在每次呼叫中保留對底層記錄與來源文件的連結。這種設計讓 AI 代理不僅能取得反應資料，還能在推理過程中引用原始出處，提升結果的可解釋性與可驗證性。對於需要大量反應先例與實驗細節的化學人工智慧應用而言，這是一項重要的基礎設施。

**Q12：DianShi-RxnDB 對化學人工智慧領域可能帶來什麼影響？**

A：DianShi-RxnDB 提供了一個大規模、細粒度且來源可驗證的有機反應資料基礎，可直接支援反應先例檢索、反應結果預測、反應條件預測與資料驅動的逆合成規劃等 AI4Chem 核心任務。由於每筆記錄都連結到原始專利段落，研究者與模型開發者可以追溯資料來源，降低因資料錯誤導致的模型偏差風險。長遠來看，這類平台有助於縮小文獻知識與機器學習模型之間的落差，加速智慧化學研究的發展。

**Q13：DianShi-RxnDB 目前有哪些已知的限制？**

A：雖然人工評估的欄位級準確率達到 92.95%，但這仍表示約有 7% 的欄位可能存在錯誤，對於需要極高精度的應用仍需人工覆核。此外，目前資料主要來自 1976 年至 2025 年的 USPTO 與 EPO 有機合成專利，尚未涵蓋期刊文獻、其他語言專利或更廣泛的化學領域。自動化管線在處理極為複雜的多步驟反應、模糊交叉引用或低品質圖像時，也可能出現抽取失敗或誤判。

**Q14：在哪些情況下，DianShi-RxnDB 的資料可能特別不可靠？**

A：當專利中的反應資訊分散在多個段落且缺乏明確的實驗邊界標記時，管線可能錯誤合併或拆分反應步驟，導致反應實例不完整。若反應式圖像解析度不足、手寫標記或化學結構表示不標準，化學實體辨識與角色指派也容易出錯。此外，對於涉及多階段反應、催化劑當量未明確記載或產率以範圍表示的記錄，欄位級精確度可能會下降。

**Q15：DianShi-RxnDB 未來可以朝哪些方向發展？**

A：未來可將資料來源擴展到期刊文獻、亞洲專利資料庫以及多語言專利文件，進一步提升覆蓋範圍與多樣性。同時，可結合更強大的多模態語言模型與化學資訊學方法，提升複雜反應與低品質圖像的抽取準確率，並引入人機協作的回饋機制進行持續校正。在應用層面，也可擴充 MCP 工具組，使其能與合成規劃代理、實驗設計系統更緊密整合，成為 AI 驅動化學研究的完整資料中樞。

## 實務應用指南

### 適用場景

1. **化學合成路線設計與逆合成規劃**  
   利用 DianShi-RxnDB 中約 1,480 萬筆通過資格檢定的單步反應實例，訓練或評估逆合成與反應結果預測模型，也可直接檢索與目標轉換相似的反應先例。

2. **反應條件推薦與實驗最佳化**  
   針對特定反應物–產物組合，查詢溫度、反應時間、當量、溶劑、產率與實驗程序，快速彙整文獻條件分佈，輔助實驗室條件篩選。

3. **專利自由實施（FTO）與先前技術調查**  
   透過段落級來源定位（paragraph-level provenance），從反應記錄一鍵回到 USPTO/EPO 原始專利段落，驗證某化學轉換是否已公開。

4. **AI 代理自動化文獻綜述與來源引用**  
   透過 MCP 服務提供可組合的結構化檢索工具，讓 AI agent 執行多步查詢、比較多筆反應實例，並在回答中保留原始出處連結。

5. **化學資訊學資料基準與品質研究**  
   將 DianShi-RxnDB 作為大規模有標註反應資料集，用於模型訓練、與 Pistachio/Reaxys 的對照實驗，或研究自動化抽取的錯誤模式。

### 實作前置條件

**資料**
- 可透過 https://dianshi.opendatalab.org.cn/ 使用網頁工作台，或呼叫 MCP 服務取得結構化反應實例。
- 若需本地分析，須取得反應實例匯出檔（建議包含 participants、roles、quantities、conditions、yields、procedures、provenance）。
- 進行來源驗證時，需要能存取對應 USPTO/EPO 專利全文或影像。

**運算**
- 網頁查詢與小規模探索：一般筆電與穩定網路即可。
- 全庫統計、去重複、模型訓練：建議具備多核心 CPU／GPU 叢集與數百 GB 以上儲存空間，以處理 2,400 萬筆反應實例。

**技能**
- 化學資訊學基礎：能判讀 SMILES、反應角色（reactant/reagent/catalyst/solvent）、RInChI 與反應式圖示。
- Python 資料處理與 API 呼叫：熟悉 pandas、RDKit、REST/MCP 介面。
- 專利文件結構理解：能定位實施例、一般程序與反應式段落。
- AI 工程師若要用於 agent 或 RAG，需具備工具鏈整合與提示工程經驗。

### 實作步驟建議

1. **界定應用範圍**  
   明確目標是反應檢索、條件預測、逆合成訓練或專利調查；決定時間範圍、反應類型，以及是否只使用通過資格檢定的 1,480 萬筆實例。

2. **資料取得與探索**  
   使用網頁工作台或 MCP 工具進行結構化查詢，篩選所需欄位；先以小樣本熟悉資料模型：Substance → Reaction Instance → Reaction Group → Reference。

3. **資料品質確認與清洗**  
   檢查欄位完整性、SMILES 標準化、角色標註一致性，並進行反應去重複。對關鍵應用建議自行抽樣驗證，不要直接沿用論文的 92.95% field-level accuracy。

4. **來源驗證與上下文補強**  
   依 provenance 連結回到原始專利段落，交叉比對反應式圖像與實驗程序，確認結構、條件與產率無誤。

5. **模型或應用開發**  
   將資料餵入反應預測模型、RAG 檢索系統或 AI agent workflow。劃分訓練／驗證／測試時，應按 Reaction Group 或專利分層，避免資料洩漏。

6. **產品化與持續維運**  
   建立 MCP tool 呼叫規範、快取策略與資料版本控制；監控平台更新（1976–2025 後續新增專利），並定期重新評估資料品質。

### 潛在風險與注意事項

- **自動化抽取仍有誤差**：field-level accuracy 雖達 92.95%，但約 7% 欄位可能錯誤，關鍵決策前應人工驗證。
- **資格檢查並非萬無一失**：38.3% 實例未通過資格檢查，可能遺漏有價值資料或混入低品質記錄，需理解其檢定標準。
- **授權與使用限制**：平台目前為 free non-commercial Web/MCP access，商業用途須另行確認授權；USPTO/EPO 內容雖公開，衍生資料的使用條款仍需留意。
- **資料洩漏與重複**：同一 Reaction Group 內的多筆 Reaction Instance 可能高度相似，建構訓練集時須按群組分層。
- **結構與角色表示差異**：SMILES 標準化、鹽型、溶劑標註可能與內部慣例不同，需與內部化合物庫對齊。
- **來源定位粒度**：段落級定位不等同於實驗編號，驗證時應比對完整實施例與反應式圖像。

### 與其他技術的整合建議

- **RAG / 大型語言模型**：將 DianShi-RxnDB 作為結構化知識庫，透過 MCP tool 提供檢索結果給 LLM，減少幻覺並附帶來源引用。
- **化學資訊學工具鏈**：與 RDKit、Open Babel 整合進行 SMILES 標準化、分子指紋比對與反應模板抽取。
- **內部 ELN / LIMS**：將文獻條件與內部實驗記錄對照，建立「文獻條件 → 內部重現」的回饋迴路。
- **專利檢索系統**：結合 USPTO/EPO 全文 API 與 PDF 影像檢視器，實現從反應記錄一鍵跳轉原始專利段落。
- **機器學習平台**：與 PyTorch/TensorFlow、Hugging Face Datasets、Weights & Biases 整合，進行反應預測模型訓練與實驗追蹤。
- **知識圖譜**：將 Substance、Reaction Instance、Reaction Group、Reference 匯入 Neo4j 等圖資料庫，支援連結探索與路徑分析。

**產品經理**：請從使用場景、存取模式（免費非商業 Web/MCP）、授權限制與差異化定位切入，比較 Reaxys、CAS、Pistachio 等專業資料庫，規劃產品整合路徑與合規邊界。
