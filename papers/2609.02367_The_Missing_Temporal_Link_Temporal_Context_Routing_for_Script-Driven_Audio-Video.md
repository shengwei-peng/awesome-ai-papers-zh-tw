# 缺失的時間連結：腳本驅動的音訊影片生成之時間上下文路由（Temporal Context Routing, TCR）

**原文標題：** The Missing Temporal Link: Temporal Context Routing for Script-Driven Audio-Video Generation  
**作者：** Yichen Liu、Quanwei Zhang、Haozhe Wang 等 10 位作者  
**發布日期：** 2026-09-02  
**HF 連結：** [https://huggingface.co/papers/2609.02367](https://huggingface.co/papers/2609.02367)

## ⚡ TL;DR

現有聯合音影片生成雖能音畫同步，卻無法精準遵循腳本中的鏡頭與對白時間軸。
本文提出時間上下文路由，將腳本時序映射至共享時間軸，並把各提示導引至音影對應位置。
TCR使鏡頭邊界誤差從1.11秒降至0.042秒，對白準確率提升至84.1%，並維持音畫品質。

## 摘要翻譯

聯合音訊影片生成（Joint Audio-Video Generation）模型在視覺品質（Visual Quality）與音畫同步（Audio-Visual Synchronization）方面已取得顯著進展。然而，它們對於鏡頭轉場（Shot Transitions）與對白（Dialogue）發生時機的控制仍然有限。這項限制使其在腳本驅動的內容創作（Script-Driven Content Creation）上的應用受到侷限，因為時間誤差可能損害敘事連貫性（Narrative Coherence）與觀看體驗（Viewing Experience）。現有的聯合生成器雖會在共享時間軸（Shared Temporal Axis）上對齊影片（Video）與音訊（Audio）表徵，但結構化提示（Structured Prompt）中所指定的鏡頭（Shot）與對白精確時間，僅編碼於提示的文字表徵（Text Representation）中，且未與任一模態（Modality）的時間座標（Temporal Coordinates）對齊。因此，影片與音訊彼此間或許仍保持同步（Synchronization），但兩者皆未能遵循腳本時間軸。這種不匹配促使我們將時間對齊（Temporal Alignment）從影片與音訊擴展至包含結構化腳本（Structured Script）。因此，本研究提出時間上下文路由（Temporal Context Routing, TCR），將腳本時間映射至影片與音訊生成的共享時間軸，並把每個提示的引導訊號路由至兩種模態中的對應位置。在 200 份測試腳本上與基線（Baseline）相比，TCR 將鏡頭邊界平均絕對誤差（Shot Boundary MAE）降低了 96%，從 1.11 秒降至 0.042 秒，並將對白準確率@0.5秒（Dialogue Acc@0.5 s）從 28.3% 提升至 84.1%。TCR 在達成上述改進的同時，仍維持與各基線（Baselines）相當的視覺品質與音畫同步。使用者研究（User Study）進一步顯示，參與者在所有五個評估維度上皆偏好 TCR。

### 核心貢獻（3～5點）
- 指出現有聯合音訊影片生成模型雖能達成音畫同步，但結構化提示中的鏡頭與對白時間並未對齊影片與音訊的時間座標，導致生成結果偏離腳本時間軸。
- 提出時間上下文路由（TCR），將腳本時間映射到影片與音訊生成的共享時間軸，並把每個提示的引導訊號路由至兩種模態的對應位置，實現腳本層級的時間對齊。
- 在 200 份測試腳本上顯著降低鏡頭邊界平均絕對誤差達 96%，並將對白準確率@0.5秒大幅提升，同時維持與基線相當的視覺品質與音畫同步。
- 使用者研究顯示，參與者在所有五個評估維度上皆偏好 TCR，驗證其在觀看體驗與敘事連貫性上的優勢。

### 適合對象
適合從事多模態生成、電腦視覺、語音合成與內容創作的研究者與工程師，特別是關注腳本驅動生成（如短劇、廣告）、時間控制與音畫對齊問題的讀者；亦適合希望將大型語言模型與生成模型結合、以提升敘事時間一致性的開發者與創作者。

## 深度分析

#### 方法論解析

##### 問題形式化與核心洞察
本文針對的是 **script-driven audio-video generation（腳本驅動的音訊影片生成）**：輸入不再是單一 **text prompt（文字提示）**，而是由 **Large Language Model（LLM，大型語言模型）** 從 **screenplay（劇本）** 轉換而來的 **structured timed prompt（結構化時間提示）**，其中包含多個 **shot descriptions（鏡頭描述）**、**dialogue lines（對白台詞）** 以及它們各自的時間區間。現有的 **joint audio-video generation（聯合音訊影片生成）** 模型雖然能把 **video（影片）** 與 **audio（音訊）** 對齊到同一條 **shared temporal axis（共享時間軸）**，但並未把腳本中每個 prompt 的明確時間座標也對齊到這條軸上。結果是：影片與音訊彼此仍可能同步，卻共同偏離腳本時間軸，造成 **shot transitions（鏡頭轉場）** 與 **dialogue（對白）** 發生時間錯誤。本文的核心洞察即是將 **temporal alignment（時間對齊）** 從「影片—音訊」兩者之間，擴展到包含「結構化腳本」的三方對齊。

##### Temporal Context Routing（TCR，時間上下文路由）的運作機制
TCR 是一個可加在現有聯合生成器上的輕量機制。對於每個 prompt \(i\)，給定其在腳本中指定的時間區間 \([s_i, e_i]\)，TCR 會計算一個 **duration-normalized routing score（依持續時間正規化的路由分數）** \(r_i(t)\)，並將其作為 **bias（偏置）** 加在 **video-text cross-attention（影片—文字交叉注意力）** 與 **audio-text cross-attention（音訊—文字交叉注意力）** 的 **logits（對數機率）** 上：

\[
\text{logit}'_i(t)=\text{logit}_i(t)+r_i(t)
\]

隨後再進行 softmax。由於 \(r_i(t)\) 只在該 prompt 指定的時間區間內顯著為正，模型在對應時間點會更傾向關注該 prompt，從而實現「把每個 prompt 的引導路由到正確時間位置」的效果。因為分數經過持續時間正規化，較長的 prompt 不會因為時間跨度大而過度主導注意力。

##### 獨立控制與重疊提示
腳本中的一個關鍵特性是 **shot（鏡頭）** 與 **dialogue（對白）** 的時間區間可能部分重疊，例如一句對白可能跨過一個鏡頭轉場。TCR 採用 **per-prompt additive design（逐提示加法設計）**，每個 prompt 都有自己獨立的路由分數，因此不需要強迫所有 prompt 共享同一套時間分段。這讓 shot prompts 與 dialogue prompts 可以同時作用、各自在指定的 **time span（時間跨度）** 內發揮影響，解決了傳統方法難以處理重疊語義的問題。

##### 不修改表徵的設計選擇
TCR 只修改 cross-attention 的 logits，而不更動原始的 **text representation（文字表徵）**、query（查詢）或 key（鍵值）。這個設計有兩個好處：第一，它保留了底層聯合生成器已經學到的視覺品質與 **audio-visual synchronization（音畫同步）**；第二，它可以作為即插即用的模組，應用在不同的 **diffusion model（擴散模型）**、**diffusion transformer（擴散變壓器）** 或 **flow matching（流匹配）** 骨幹上，而不需要重新設計整個模型架構。

##### 由粗到細的資料建構管線
為了提供 TCR 所需的細粒度時間監督，作者提出一條 **coarse-to-fine data construction pipeline（由粗到細的資料建構管線）**：
1. 建立包含多個鏡頭且對白跨越轉場的影片片段。
2. 使用 **Gemini** 在預定義的腳本 schema 下提供語義標註與粗略時間。
3. 利用偵測到的視覺切點與字層級語音對齊（word-level speech alignment）進行時間精修。
4. 最終將 **shot boundaries（鏡頭邊界）** 與 **dialogue spans（對白區間）** 四捨五入到 0.1 秒的網格。

這條管線解決了「初始標註僅有粗略時間」的問題，使 TCR 能學到精確的時間控制。

---

#### 實驗數據解讀

##### 評估設定與指標
實驗在 200 個測試腳本上進行，分為兩種互補設定：
- **End-to-end comparison（端到端比較）**：與現有開源聯合生成器直接比較。
- **Controlled comparison（控制變因比較）**：在同一骨幹上只更換 **temporal operator（時間運算子）**，以隔離 TCR 本身的貢獻。

主要客觀指標為：
- **Shot Boundary MAE（鏡頭邊界平均絕對誤差）**：生成轉場時間與腳本要求時間的絕對誤差平均值，單位為秒，越低越好。
- **Dialogue Acc@0.5 s（對白準確率@0.5秒）**：對白時間誤差在 0.5 秒內的比例，越高越好。

##### 端到端比較
與最強開源 **baseline（基線）** 相比，TCR 將 Shot Boundary MAE 從 1.11 秒降至 0.042 秒，降幅達 96%；Dialogue Acc@0.5 s 則從 28.3% 提升至 84.1%。0.042 秒約等於 24 fps 下的一格畫面（約 0.0417 秒），代表 TCR 已達到接近影格等級的轉場精度。與此同時，TCR 在 **visual quality（視覺品質）** 與 **audio-visual synchronization（音畫同步）** 上仍與基線相當，顯示時間控制的提升並未犧牲生成品質。

##### 控制變因比較
當僅更換時間運算子而保持其他條件不變時，TCR 相對於兩個時間基線都將 Shot Boundary MAE 降低超過 60%，並再次取得最高的 Dialogue Acc@0.5 s。這說明 TCR 的優勢不僅來自於更強大的整體生成器，而是其路由機制本身在時間對齊上更有效。

##### 消融實驗
作者進行了使用粗略標註（coarse timing）而非精修標註（refined timing）的消融。結果顯示，無論是 shot 還是 dialogue 的時間準確度都明顯下降，證明了由粗到細資料管線對 TCR 訓練的重要性。這也暗示：單靠 TCR 的架構設計不足以彌補低品質時間監督的不足。

##### 使用者研究
在 **user study（使用者研究）** 中，參與者在五個維度上都更偏好 TCR：shot timing（鏡頭時間）、dialogue timing（對白時間）、**script fidelity（腳本忠實度）**、audio-visual synchronization（音畫同步）以及 overall quality（整體品質）。這與客觀指標一致，也說明時間準確度的提升確實轉化為更好的觀看體驗與敘事連貫性。

##### 綜合解讀
整體而言，實驗結果支持了本文的核心論點：單純讓影片與音訊互相同步並不足夠，必須把腳本時間也納入對齊。TCR 在幾乎不損失視覺與音畫品質的前提下，大幅改善了腳本驅動生成中最關鍵的時間控制問題。

#### 與現有研究的比較

##### 與傳統文字條件生成的區別
傳統 **text-conditioned generation（文字條件生成）** 通常只接受單一 text prompt，模型自行決定內容在時間軸上的展開方式。相對地，script-driven generation 要求模型嚴格遵循結構化提示中的時間安排。TCR 正是為了填補這個「結構化控制」缺口而設計。

##### 與影片時間控制方法的關係
過去已有一些影片生成方法探討「局部文字提示應在何時影響影片生成」（如 Yan et al., 2025；Wu et al., 2025b；Shu et al., 2026），但它們主要聚焦於 video modality（影片模態），並未處理如何讓結構化腳本同時控制影片與音訊。TCR 把時間路由同時應用到影片與音訊的 cross-attention，這是這些方法所未觸及的。

##### 與聯合音訊影片生成器的關係
現有 joint generators（如 MM-Diffusion、AV-DiT、JavisDiT、Harmony 等）已經能將 video 與 audio 對齊到 shared temporal axis，但它們把腳本時間僅編碼在 prompt 的 text representation 中，沒有顯式對齊到任一模態的 temporal coordinates。TCR 的貢獻在於把「腳本—影片—音訊」三者進行時間對齊，從而解決了「兩模態彼此同步卻同時偏離腳本」的 **temporal drift（時間漂移）** 問題。

##### 優勢與限制
**優勢：**
- 輕量且即插即用，不改變底層生成器的表徵空間。
- 支援重疊的 shot 與 dialogue 控制，靈活性高。
- 在客觀指標與主觀評價上都顯著優於基線。

**限制：**
- 需要預先由 LLM 將 screenplay 轉換為帶時間戳的 structured prompt，若 LLM 的時間標註有誤，會直接影響生成結果。
- 訓練需要精細的時間標註，資料建構管線依賴 Gemini 與視覺/語音偵測工具，成本與複雜度較高。
- 最終標註四捨五入到 0.1 秒網格，對於需要次於 100 毫秒精度的應用可能仍有限制。
- 目前主要針對 shot boundaries 與 dialogue spans，尚未涵蓋更細緻的動作節拍、音樂節拍或 **sound effects（音效）** 的時間控制。

#### 可重現性評估

##### 開源狀態
根據目前提供的論文內容，作者並未明確說明是否公開原始碼、模型權重或 200 個測試腳本。因此，從現有資訊判斷，本研究的 **可重現性（reproducibility）** 仍屬未知；若作者後續釋出相關資源，將大幅提升社群驗證與延伸應用的可能性。

##### 資料與訓練管線
即使沒有官方釋出，TCR 的實作概念相對明確：在現有聯合生成器的 video-text 與 audio-text cross-attention logits 上加入依時間區間計算的路由偏置。然而，要完整重現論文效果，仍需重建 coarse-to-fine 資料管線，包括：
- 使用 Gemini 進行語義標註與粗略時間標註；
- 偵測視覺切點以精修 shot boundaries；
- 進行 word-level speech alignment 以精修 dialogue spans；
- 將標註對齊到 0.1 秒網格。

這些步驟涉及外部 API 與多個偵測工具，且論文未詳細說明所有超參數（例如 routing score 的溫度係數、正規化方式、訓練時的損失權重等），因此獨立重現具有一定門檻。

##### 實作門檻
TCR 的優點是架構輕量，理論上可移植到任何使用 cross-attention 進行 text conditioning 的 diffusion/flow-based 聯合生成器。但實際上，要達到論文所報告的 0.042 秒 Shot Boundary MAE，必須同時具備高品質的基礎生成器、精細的訓練資料，以及對 routing 機制的仔細調校。對於沒有相應運算資源與資料處理流程的研究者而言，完整重現仍有挑戰。

---

#### 未來研究方向

1. **更細粒度的時間控制**：將 TCR 從 shot/dialogue 層級延伸至動作關鍵影格、語音音素（phoneme）層級或音樂節拍，實現更精確的 **lip sync（唇形同步）** 與節奏控制。

2. **端到端腳本時間學習**：目前腳本時間由 LLM 預先標註，未來可探索讓生成器與 LLM 聯合學習時間對齊，減少對外部時間標註的依賴。

3. **長篇與多場景內容生成**：將 TCR 擴展到包含多個 **scene（場景）** 的長篇敘事，處理場景之間的時間一致性、角色連貫性與劇情節奏。

4. **多語言與跨文化腳本**：驗證 TCR 在不同語言、語速與文化敘事結構下的泛化能力，並開發對應的資料建構管線。

5. **納入更多模態**：除了對白，也可將背景音樂、音效、環境音與字幕的時間控制納入 shared temporal axis，形成更完整的腳本驅動生成框架。

6. **互動式與即時編輯**：發展支援使用者即時調整腳本時間並重新生成的系統，應用於廣告、短劇與互動敘事製作。

7. **可解釋性與可控性分析**：深入研究 routing score 對生成結果的影響，發展可視化工具，讓創作者能直觀理解與調整每個 prompt 的時間影響範圍。

8. **降低資料依賴**：探索弱監督或自監督方法，減少對 Gemini 與人工精修標註的依賴，使 TCR 更容易應用於更大規模或更多領域的資料。

## 論文問答

**Q1：腳本驅動的音訊影片生成目前面臨的核心問題是什麼？**

A：目前聯合音訊影片生成模型雖然在視覺品質與音畫同步上已有顯著進展，但仍難以精確控制鏡頭轉場與對白發生的時間點。當腳本中明確指定了每個鏡頭與每句對白的時間區間時，生成結果卻常出現時間漂移，導致敘事連貫性受損。這個問題限制了模型在短劇、廣告等需要嚴格時間結構的內容創作場景中的實用性。

**Q2：為什麼現有的聯合生成器無法準確遵循腳本時間軸？**

A：現有方法通常將影片與音訊對齊到共享時間軸上，但腳本中鏡頭與對白的精確時間僅被編碼在文字表徵之中，並未與任一模態的時間座標建立明確對應。換句話說，模型知道「什麼」要發生，卻沒有收到「何時」發生的明確控制訊號。因此，影片與音訊彼此之間可能仍然同步，但兩者卻共同偏離了腳本所要求的時間線。

**Q3：精確的時間控制對腳本驅動內容創作為何特別重要？**

A：在腳本驅動的工作流程中，鏡頭轉場或對白提前或延後出現，都會打斷敘事節奏並降低觀看體驗。不同於單一文字提示的生成，結構化提示由多個鏡頭描述與對白台詞組成，每個提示都對應特定的時間跨度。唯有精準執行這些時間資訊，才能將劇本轉化為連貫且具敘事力的音訊影片內容。

**Q4：時間上下文路由（TCR）的核心運作機制是什麼？**

A：TCR 將每個提示所指定的時間映射到影片與音訊生成的共享時間軸上，並把該提示的引導訊號路由到兩個模態中對應的位置。具體而言，它為每個提示計算一個基於時間區間正規化的路由分數，並將此分數作為偏置加在影片—文字與音訊—文字的交叉注意力 logit 上。這種設計讓腳本時間成為明確的控制訊號，同時作用於影片與音訊兩種模態。

**Q5：TCR 如何實現鏡頭與對白提示的獨立控制，即使它們的時間區間重疊？**

A：TCR 採用逐提示相加的偏置設計，不改變原始文字、查詢或鍵值表徵，因此每個提示只在其指定的時間區間內發揮影響力。由於對白可能跨越鏡頭轉場持續發生，這種獨立路由機制避免了強迫兩類提示共享同一套時間分段。舉例來說，一句對白提示可以在多個鏡頭之間保持作用，而每個鏡頭提示則各自控制其對應的畫面區間。

**Q6：TCR 在提升時間準確度的同時，如何維持視覺品質與音畫同步？**

A：TCR 僅對現有的交叉注意力 logit 加入輕量的路由偏置，而不改動底層生成器的核心表徵與學習到的多模態先驗。這種最小化干預讓模型保留了原本在視覺品質與音畫同步上的表現能力。實驗結果也證實，TCR 在大幅提升時間對齊準確度的同時，視覺品質與音畫同步仍與基線相當。

**Q7：論文使用了哪些評估設定與指標來驗證 TCR？**

A：研究團隊在 200 份測試腳本上進行兩種互補的評估：一是與現有開源聯合生成器進行端到端比較，二是在相同骨幹模型上與其他時間操作模組進行控制變因比較。主要評估指標包括鏡頭邊界平均絕對誤差（Shot Boundary MAE）與對白準確率@0.5秒（Dialogue Acc@0.5 s），同時也評估視覺品質與音畫同步。此外，論文還進行了使用者研究，從五個維度收集參與者的主觀偏好。

**Q8：TCR 相較於基線方法取得了哪些關鍵量化結果？**

A：與最強的開源基線相比，TCR 將鏡頭邊界平均絕對誤差從 1.11 秒降低至 0.042 秒，降幅達 96%；對白準確率@0.5秒則從 28.3% 提升至 84.1%。在控制變因比較中，TCR 相較於兩個時間基線都將鏡頭邊界誤差降低超過 60%，並再次取得最高的對白時間準確率。這些進步是在維持與基線相當的視覺品質與音畫同步前提下達成的。

**Q9：消融實驗揭示了資料建構流程的什麼重要性？**

A：消融實驗顯示，若使用粗略時間標註而非精細標註，鏡頭與對白的時間準確度都會顯著下降，證明了由粗到細的資料建構流程至關重要。該流程首先建立包含跨鏡頭轉場對白的多鏡頭片段，再利用 Gemini 依預定義腳本格式產生語意標註與粗略時間，最後結合偵測到的視覺切點與字級語音對齊，將鏡頭與對白時間細化到 0.1 秒網格。精細的監督訊號因此是學習精確時間控制不可或缺的基礎。

**Q10：TCR 最適合應用在哪些實際內容創作場景？**

A：TCR 特別適合短劇、廣告以及其他需要依劇本精確安排鏡頭轉場與對白時間的敘事影片工作流程。透過忠實執行腳本時間軸，創作者可以直接從劇本產出音畫同步的影片內容，減少手動修正時間漂移的後製成本。這將有助於簡化從劇本到成片的製作管線，並提升生成式影片在專業創作中的可用性。

**Q11：在實際創作工具中部署 TCR 時，需要考慮哪些產品層面的問題？**

A：實際部署時需要整合能將原始劇本轉換為結構化時間提示的大型語言模型模組，以確保鏡頭與對白時間被正確解析。系統也必須能處理提示重疊、時間區間部分交錯，以及需要由粗到細資料流程進行時間精修的情況。此外，在提升時間準確度的同時維持視覺品質與音畫同步，是確保輸出符合專業內容標準的關鍵。

**Q12：TCR 可能對生成式影片與多模態人工智慧領域帶來什麼更廣泛的影響？**

A：TCR 將時間對齊的範疇從單純的影片—音訊同步，擴展到包含結構化腳本在內的三方對齊。這項轉變提示未來生成模型應將時間視為明確的控制訊號，而非僅隱含在文字資訊中。它也為更複雜的腳本驅動生成系統開闢了方向，例如處理多角色對話、複雜敘事結構與更細緻的編輯控制。

**Q13：儘管結果強勁，TCR 仍可能存在哪些限制？**

A：TCR 的效果部分依賴於劇本解析的準確度以及由粗到細標註流程的品質，若前端解析或時間精修出錯，後續生成也會受到影響。此外，對於極長或結構極為複雜的腳本，路由機制是否能穩定維持高精度仍有待更多驗證。TCR 主要聚焦於時間對齊，對於語意忠實度、風格一致性等其他面向則未必能完全解決。

**Q14：TCR 在哪些困難輸入或失敗案例上可能表現不佳？**

A：當結構化提示中的時間標註模糊、對白與鏡頭在語意上高度衝突且大量重疊，或場景包含快速來回切換的短鏡頭時，TCR 可能面臨挑戰。若底層聯合生成器對某些動作或語音風格缺乏足夠先驗，也可能導致殘留的時間錯位或音畫品質下降。這些情況需要更強大的基礎模型或更細緻的提示設計來輔助。

**Q15：基於 TCR，未來有哪些值得探索的研究方向？**

A：未來研究可將 TCR 擴展到更多敘事元素，例如攝影機運動、角色情緒與背景音樂的時間控制。另一個方向是發展端到端系統，讓劇本解析、時間路由與生成過程聯合最佳化，減少對獨立標註流程的依賴。此外，將 TCR 應用於長篇內容與互動式編輯工具，也有助於進一步普及腳本驅動的影片製作。

## 實務應用指南

### 適用場景

1. **短劇與廣告的腳本驅動生成**  
   製作短劇、品牌廣告或社群影片時，創作者可將帶時間戳的劇本直接轉為結構化提示，讓模型在指定時間點切換鏡頭並播放對白，減少後製剪輯與對軌成本。

2. **自動化預告片與精華片段製作**  
   編輯可將長篇影片腳本或摘要輸入系統，由 TCR 控制關鍵鏡頭轉場與旁白節奏，快速生成符合敘事時間軸的預告片或精華片段。

3. **互動式敘事與分支劇情內容**  
   在遊戲、互動影集或教育訓練影片中，不同劇情分支需要精確的對白與鏡頭時間控制。TCR 能讓每段對白與畫面在正確時間出現，維持敘事連貫性。

4. **多語言配音與在地化改編**  
   將原始對白時間軸對齊到不同語言的語音生成流程，TCR 可確保新語言的對白仍落在正確鏡頭區間，避免聲畫不同步或對白錯位。

5. **虛擬製片與前期視覺預覽（Pre-vis）**  
   導演與攝影指導可先用文字腳本生成帶精確鏡頭切換與對白時間的預覽影片，作為拍攝排程、運鏡設計與演員對戲的參考。

### 實作前置條件

**資料準備**
- 至少數百至數千組「結構化時間提示—影片—音訊」配對，用於訓練或微調。每筆資料需包含：
  - 鏡頭描述與對白台詞
  - 每個鏡頭與對白的起訖時間（建議精細到 0.1 秒）
  - 對應的影片與音訊內容
- 若無現成資料，需建立由 Gemini 等大型多模態模型進行語義標註與粗對齊，再經視覺切點偵測與字級語音對齊進行細修的資料管線。

**運算資源**
- 需要支援大規模擴散模型或 flow matching 模型訓練的 GPU 叢集（例如數十張高階 GPU），特別是當基礎模型為聯合音訊影片生成器時。
- 推論階段至少需一張高記憶體 GPU，用於生成數秒至數十秒的高解析度影片與同步音訊。

**技術能力**
- 熟悉擴散模型、DiT 或 flow matching 的訓練與推論流程。
- 具備多模態資料處理經驗，包括影片切點偵測、語音辨識與強制對齊（forced alignment）。
- 能夠設計結構化提示格式，並將原始劇本轉換為帶時間戳的結構化時間提示。

---

### 實作步驟建議

1. **劇本結構化與時間標註**  
   使用大型語言模型將原始劇本轉換為結構化時間提示，包含全域描述、參考資料、鏡頭描述、對白台詞及其對應時間區間。

2. **建立或擴充基礎聯合生成模型**  
   選擇一個現有的聯合音訊影片生成器（如 AV-DiT、JavisDiT 等）作為骨幹，確保其已具備音畫同步能力。

3. **整合 Temporal Context Routing（TCR）**  
   對每個鏡頭與對白提示，依其指定時間區間計算 duration-normalized routing score，並在影片—文字與音訊—文字的 cross-attention logits 上加入偏置項。此設計不需修改原始文字、查詢或鍵值表徵。

4. **建構由粗到細的訓練資料管線**  
   先以 Gemini 產生語義標註與粗略時間，再透過視覺切點偵測與字級語音對齊將鏡頭邊界與對白時間細修到 0.1 秒網格。

5. **訓練與驗證**  
   在帶精細時間標註的多鏡頭對白資料上訓練模型，並以 Shot Boundary MAE 與 Dialogue Acc@0.5 s 等指標監控時間準確度，同時保留視覺品質與音畫同步指標。

6. **推論與後製整合**  
   部署時接收結構化時間提示，生成影片與音訊後，可選擇輸出時間軸中繼資料供剪輯軟體進行微調或自動化組裝。

---

### 潛在風險與注意事項

| 風險 | 說明 | 因應方式 |
|---|---|---|
| **時間標註品質不足** | 若訓練資料的鏡頭切點或對白時間不精確，TCR 難以學會精準控制。 | 投資由粗到細的資料管線，使用視覺切點與字級語音對齊進行細修。 |
| **鏡頭與對白時間重疊導致衝突** | 對白可能跨越多個鏡頭，兩種提示類型不能共用單一時間分段。 | 採用 TCR 的 per-prompt additive 設計，讓每個提示獨立路由到對應時間區間。 |
| **過度強調時間控制而犧牲視覺品質** | 加入時間偏置可能干擾原本的文字條件生成。 | 僅在 attention logits 加入偏置，不改變文字、查詢或鍵值表徵，並持續監控視覺品質與音畫同步指標。 |
| **推論時腳本時間不合理** | 使用者可能給出過短或互相矛盾的時間區間。 | 在產品層加入腳本合法性檢查，例如最小鏡頭長度、對白不可超出影片長度等。 |
| **資料版權與倫理問題** | 訓練資料可能涉及影視內容、演員肖像或配音授權。 | 使用合法授權資料，並在生成內容中標示為 AI 生成。 |

---

### 與其他技術的整合建議

- **與 LLM 劇本解析工具整合**  
  將 TCR 前接一個專門的劇本解析模型，自動從傳統劇本格式（如 Fountain、Final Draft）抽取場景、鏡頭與對白，並產生帶時間戳的結構化時間提示。

- **與影片後製與剪輯軟體整合**  
  輸出包含鏡頭切點與對白時間軸的中繼資料（如 EDL、XML 或 JSON），讓 Premiere、DaVinci Resolve 等工具可直接載入並進行人工微調。

- **與語音合成（TTS）與語音克隆技術整合**  
  若對白需要特定角色聲音，可將 TCR 的對白時間區間作為 TTS 的時間約束，再與生成音訊混合，確保角色語音與嘴型一致。

- **與品質評估與回饋迴路整合**  
  建立自動化評估流程，持續測量 Shot Boundary MAE、Dialogue Acc@0.5 s、音畫同步與視覺品質，並將結果回饋到模型迭代與資料標註流程。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從圖 1 與摘要開始，理解「腳本驅動生成」與「時間漂移」的直覺概念：模型雖然能讓音訊與影片互相對齊，但兩者可能一起偏離劇本時間軸。接著閱讀「適用場景」與「實作步驟建議」，建立整體流程感，技術細節可暫時略過。

**AI 工程師**  
重點閱讀 TCR 的實作方式：如何計算 duration-normalized routing score、如何在 video-text 與 audio-text cross-attention logits 加入偏置，以及為何不修改原始表徵。同時仔細研究由粗到細的資料管線，因為資料品質是時間準確度的關鍵。

**研究人員**  
建議深入分析論文的核心洞察：將時間對齊從「音訊—影片」擴展到「音訊—影片—腳本」。可進一步探討 TCR 與其他時間條件機制（如 temporal attention mask、time embedding）的關係，並思考如何將此方法推廣到更多模態或更長的敘事結構。

**產品經理**  
聚焦於量化成果與使用者研究：Shot Boundary MAE 降低 96%、Dialogue Acc@0.5 s 從 28.3% 提升至 84.1%，以及五個維度皆獲得使用者偏好。評估時請同時考量資料標註成本、運算資源需求，以及與現有剪輯工作流程的整合難度。
