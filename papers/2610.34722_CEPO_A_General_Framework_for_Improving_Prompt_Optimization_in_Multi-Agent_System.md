CEPO（Coordinator-Executor Prompt Optimization，協調器-執行器提示優化）的核心設計動機源於一個關鍵觀察：現有的多代理系統（Multi-Agent Systems, MAS）提示優化方法將系統層級協調（system-level coordination）與代理層級執行（agent-level execution）這兩種本質上不同的功能耦合在同一個代理專屬提示（agent-specific prompt）之中。這種耦合導致一個結構性問題——當需要修訂共享的協調規則時，必須在多個具有不同執行職責的提示中進行一致性的修改，這不僅增加了優化搜尋空間的複雜度，也使得協調規則的更新難以在所有代理間保持一致性。

CEPO 透過兩個互補的核心元件來解決此問題：

**第一個元件：協調器-執行器提示分解（Coordinator-Executor Prompt Decomposition）。** 此元件將原本耦合的提示結構拆分為兩個獨立的優化參數集合：(1) 一個共享的協調器提示 $p_C$（coordinator prompt），由所有代理共用，定義系統層級的協調規則，例如代理間的溝通協議、資訊流轉順序、衝突解決機制等；(2) 多個代理專屬的執行器提示 $p_E$（executor prompts），每個代理擁有其獨立的執行器提示，定義該代理如何完成其被指派的具體任務。這種結構設計的關鍵優勢在於：當協調規則需要更新時，只需修改單一的 $p_C$，所有代理便能同步獲得更新後的協調指引；而各代理的執行指令則可獨立調整，不會相互干擾。

**第二個元件：角色對齊的優化指引（Role-Aligned Optimization Guidance）。** 此元件為協調器和執行器提供不同的元指令（meta-instructions），引導優化器分別朝向不同的目標進行搜尋。具體而言，協調器的優化指引朝向團隊層級的協作（team-level collaboration），例如改善代理間的資訊共享效率、決策共識機制等；執行器的優化指引則朝向各代理的任務執行（task execution），例如提升特定子任務的準確度、推理深度等。這種角色對齊的設計使得優化過程能夠針對不同功能進行差異化調整，避免了角色無關優化（role-agnostic optimization）可能帶來的功能混淆問題。

從框架設計的角度來看，CEPO 採用了一種「即插即用」（plug-and-play）的設計哲學。它本身不執行底層的提示搜尋演算法，而是指定提示的結構以及更新的引導方式，將實際的搜尋工作交由現有的提示優化器（prompt optimizer）來完成。這種設計使得 CEPO 能夠與多種現有優化器相容，包括通用型優化器（如 PE2、OPRO、ProTeGi）以及 MAS 專用優化器（如 MASPO），展現了高度的通用性。

從資訊流轉的角度來分析，在 CEPO 框架下，每個代理在執行任務時會同時接收共享的協調器提示 $p_C$ 和其專屬的執行器提示 $p_E$，兩者共同構成該代理的完整指令集。優化過程中，$p_C$ 的更新會影響所有代理的協作行為，而 $p_E$ 的更新僅影響對應代理的執行表現。這種分離使得優化器能夠以更細粒度的方式控制 MAS 的整體行為。

**領域四：影片理解（Video Understanding）。** 結合多模態證據處理、時間定位、假設驗證等任務，需要代理間進行複雜的資訊整合。

#### 與現有研究的比較

CEPO 在 MAS 提示優化領域中佔據了一個獨特且互補的位置。從技術演進的角度來看，提示優化經歷了從單代理設定（如 PE2、OPRO、ProTeGi）到複合系統（compound systems）的擴展，近年來進一步延伸至 MAS 場景。

**與 MASPO（Wang et al., 2026b）的比較：** MASPO 將下游互動（downstream interactions）與協調失敗（coordination failures）納入提示優化的考量，是 MAS 專用優化器的代表。然而，MASPO 仍然在代理專屬提示的層級進行優化，未明確分離協調與執行功能。CEPO 與 MASPO 的關係是互補的而非競爭的——CEPO 提供提示結構與優化指引的框架，MASPO 提供底層的搜尋演算法，兩者結合時 CEPO 能進一步提升 MASPO 的效能。

**與聯合優化提示與拓樸的方法（如 Zhou et al., 2026; Zhuge et al., 2024）的比較：** 這些方法同時優化代理的提示與系統的連接拓樸（topology），追求更全面的系統級優化。然而，它們同樣未在提示內部區分協調與執行功能。CEPO 的貢獻在於從提示結構的微觀層面切入，解決了這些方法未能觸及的耦合問題。

**與單代理提示優化器的比較：** PE2、OPRO、ProTeGi 等通用優化器在單代理場景中表現優異，但直接應用於 MAS 時面臨協調規則難以一致更新的挑戰。CEPO 透過引入共享協調器提示，使得這些通用優化器也能有效處理 MAS 場景，擴展了它們的適用範圍。

**CEPO 的局限性與待解決問題：** 首先，CEPO 假設 MAS 具有清晰的協調-執行分離結構，但某些 MAS 設計中代理角色可能高度重疊或動態變化，此時固定的協調器-執行器分解可能不夠靈活。其次，CEPO 的效能高度依賴於底層優化器的品質，若底層優化器本身存在偏差或搜尋效率低下，CEPO 的增益可能受限。第三，論文的實驗主要在特定類型的 MAS（如文件理解、數學推理等）上進行，對於更複雜或開放式的 MAS 場景的泛化能力尚需進一步驗證。第四，CEPO 引入的共享協調器提示增加了提示設計的複雜度，需要研究者具備對 MAS 協調機制的深入理解才能有效設定初始提示。

- 範例：`pC` 的指引可寫「優化此提示以提升代理間協作效率」；`pE_i` 可寫「優化此提示以提升此代理在 X 任務上的表現」。

**Step 4：選擇底層優化器並整合 CEPO**
- 從 PE2、OPRO、ProTeGi、MASPO 中選擇一個或多個作為底層搜尋機制。
- 將 `pC` 與 `pE_i` 註冊為該優化器的優化目標，並掛載對應的角色對齊指引。
- 若使用 MASPO，可進一步整合下游互動回饋。

**Step 5：執行優化並監控**
- 在驗證集上執行迭代優化。
- 監控 `pC` 與各 `pE_i` 的更新軌跡，確保協調規則的更新能一致地反映到所有代理。
- 記錄每回合的評估分數與 prompt 變化，便於後續分析。

**Step 6：消融驗證與部署**
- 比較「vanilla 優化器」「僅做 prompt 分解」「分解 + 角色對齊指引（完整 CEPO）」三組結果，確認 CEPO 各組件的貢獻。
- 通過驗證後部署至生產環境，並持續監控代理協作品質。

### 潛在風險與注意事項

**風險 1：協調器與執行器內容邊界模糊**
- 現象：某些指令同時涉及協作與執行（例如「將結果以 JSON 格式傳給下一個代理」），難以歸類。
- 緩解：採用「內容測試」——若該指令對所有代理都適用，歸入 `pC`；若僅對特定代理有意義，歸入 `pE_i`。對模糊案例，優先放入 `pC` 以維持一致性。

**風險 2：優化預算爆炸**
- 現象：CEPO 將單一 prompt 優化擴展為多 prompt 聯合優化，可能放大計算成本。
- 緩解：根據論文的「優化預算效率」發現，CEPO 在相同預算下通常達到更高分數，因此應以「達標所需回合數」而非「總回合數」衡量成本。建議先在小規模驗證集上做預實驗。

**風險 3：協調器過度擬合**
- 現象：`pC` 在訓練資料上學到過於特定的協作模式，泛化至新任務時失效。
- 緩解：保留多樣化的驗證集；定期在 out-of-distribution 樣本上測試；對 `pC` 的更新幅度設上限。

**風險 4：底層優化器不相容**
- 現象：部分優化器（如純粹的 gradient-based 方法）可能不適用於分離式 prompt 結構。
- 緩解：論文中驗證的四個優化器（PE2、OPRO、ProTeGi、MASPO）皆可運作；採用新優化器前先小規模測試其對多目標 prompt 的支援能力。

**風險 5：代理數量擴展時的維度膨脹**
- 現象：代理數增加時，`pE_i` 數量線性增長，優化空間擴大。
- 緩解：論文的「performance scaling with the number of agents」實驗顯示 CEPO 在代理數增加時仍有效率優勢，但仍建議設定合理的代理數上限（如 5–8 個），避免優化難度失控。

### 與其他技術的整合建議

**與現有多代理框架整合**
- **LangGraph / AutoGen / CrewAI**：這些框架已內建代理間通訊機制，可將 `pC` 注入框架的「system message」或「shared context」層，`pE_i` 則作為各代理的專屬 system prompt。
- **拓撲優化方法（如 GPTSwarm、MASPO 的拓撲變體）**：CEPO 專注於 prompt 結構，可與拓撲搜尋正交組合——CEPO 處理「每個節點的 prompt」，拓撲優化處理「節點間的連線結構」。

**與單代理提示優化器整合**
- 任何接受「多個 prompt 輸入 + 各自 meta-instruction」的優化器皆可作為 CEPO 的底層。整合時只需將 `pC` 與 `pE_i` 視為獨立的優化目標，並餵入對應的角色對齊指引。

**與評估管線整合**
- 建議將評估分為「協作品質指標」（如代理間交接成功率、整合答案一致性）與「執行品質指標」（如各代理的單任務表現），分別監控 `pC` 與 `pE_i` 的優化效果。

**與 LLM 部署基礎設施整合**
- 若使用 vLLM、TGI 等推論服務，可將 `pC` 快取為共享 prefix，降低重複 token 的計算成本——這是 CEPO 結構帶來的額外工程紅利。
