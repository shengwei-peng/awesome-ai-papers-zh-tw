## 摘要翻譯

我們提出 onPanda，一個用於高效標註大型語言模型（LLM）對齊資料與智能體（Agent）軌跡（Trajectory）的互動式工具。onPanda 以詞元級校正（Token-Level Correction）作為核心互動機制：標註者在閱讀模型回應（Model Response）時，定位至第一個不適當的詞元（token），並從模型的候選詞元（Candidate Token）中挑選替代，或透過自由格式編輯（Free-Form Editing）直接輸入正確文字。系統隨即截斷（Truncate）該位置之後的所有內容，並從校正後的前綴（Prefix）繼續生成，重複此定位-修正-繼續循環（Locate-Correct-Continue Loop），直到獲得令人滿意的回應為止。此機制使標註者得以低成本精確引導模型輸出：一項小型對照研究顯示，相較於人工後編輯（Manual Post-Editing），onPanda 可將中位數標註時間（Median Annotation Time）降低 52%。由於最終回應中絕大多數詞元由模型自身生成，所產生的資料在很大程度上保留了模型的取樣分佈（Sampling Distribution），非常適合建構在策略監督式微調（SFT）與偏好資料（Preference Data）。此外，標註過程中記錄的詞元級校正提供了具備精確位置的細粒度監督（Fine-Grained Supervision），並自然形成正負樣本對（Positive–Negative Pair）。onPanda 亦可連接外部工具（External Tool）與測試框架（Harness），從而得以在真實環境中進行互動式軌跡標註（Trajectory Annotation）。另外，我們釋出以 onPanda 標註的資料集 Panda-CVL，以及詞元級校正基準測試。

### 核心貢獻（3～5點）
- 提出互動式標註工具 onPanda，以詞元級校正（Token-Level Correction）為核心，透過定位-修正-繼續循環（Locate-Correct-Continue Loop）讓標註者以低成本精確引導模型輸出。
- 相較於人工後編輯（Manual Post-Editing），onPanda 可將中位數標註時間（Median Annotation Time）降低 52%，顯著提升對齊資料標註效率。
- 由於最終回應中絕大多數詞元由模型自身生成，所產資料能保留模型原始取樣分佈（Sampling Distribution），適合建構在策略監督式微調（SFT）與偏好資料（Preference Data）。
- 詞元級校正記錄提供具備精確位置的細粒度監督（Fine-Grained Supervision），並自然形成正負樣本對（Positive–Negative Pair）。
- onPanda 支援連接外部工具（External Tool）與測試框架（Harness），可在真實環境中進行互動式軌跡標註（Trajectory Annotation），並釋出 Panda-CVL 資料集與詞元級校正基準測試。

### 適合對象
適合從事大型語言模型（LLM）對齊、監督式微調（SFT）、偏好學習、獎勵模型（Reward Model）訓練、智能體（Agent）軌跡標註，以及對齊資料建構與品質控制的研究人員與工程師閱讀。

## 深度分析

#### 方法論解析

onPanda 的核心方法論是將「詞元級校正（token-level correction）」作為人機互動的基礎單元，並圍繞它建立一套「定位–修正–繼續（locate–correct–continue）」的循環標註流程。具體而言，當標註者閱讀模型回應（model response）時，只需找出第一個不適當的詞元（token），onPanda 會在該位置顯示模型預測的 top-k 候選詞元（candidate tokens）及其機率。標註者可以：

1. **點選候選詞元**：若模型已經能夠取樣到正確內容，則用一個點擊完成修正。
2. **自由格式編輯（free-form editing）**：若 top-k 候選集合都不合適，標註者可直接輸入正確文字。

完成修正後，系統會**截斷（truncate）**該位置之後的所有內容，並從更新後的**前綴（prefix）**繼續生成。這個過程反覆進行，直到回應達到預設的 SFT 品質門檻（SFT quality bar），即 `is_good=Y`。

這套流程帶來幾個關鍵的技術特性：

- **低認知負擔的線性工作流**：標註者採用「邊讀邊改」的策略，不需要反覆重讀整段回應，也不需從零撰寫完整答案。
- **高在策略（on-policy）保真度**：絕大多數最終回應中的詞元仍由模型本身生成，只有少數錯誤位置被人為介入。即使標註者選擇模型自己的高機率候選詞元，對取樣分佈（sampling distribution）的干擾也極小。
- **細粒度監督訊號**：每一次詞元級校正都會記錄錯誤位置、被拒絕的詞元、被選擇的替代詞元，以及前後對應的完整對話版本。這些資訊天然構成**正負樣本對（positive–negative pair）**，可轉換為：
  - 回應級偏好資料（response-level preference），用於獎勵模型（reward model）或 DPO（Direct Preference Optimization）訓練；
  - 過程獎勵資料（process reward data），用於 PRM（Process Reward Model）訓練。
- **完整表達能力**：自由格式編輯作為後備機制，讓標註者即使面對模型完全無法取樣到正確內容的情況，也能注入正確文字並引導後續生成。雖然這會稍微偏離模型分佈，但只發生在極少數超出模型能力的位置。

在系統實作上，onPanda 是一個元件化的前端函式庫，具備兩種使用模式：

- **輕量網頁應用**：可透過靜態託管部署，無需資料庫，使用者拖入本地標註檔案即可開始工作，瀏覽器直接呼叫 Chat Completions API。
- **嵌入現有資料平台**：其元件可整合到既有後端，由後端負責任務分派與資料收集。

onPanda 對推論 API 有兩項基本要求：支援從 assistant message 前綴繼續生成（例如 vLLM 的 `continue_final_message`），以及回傳每個詞元的 top-k 候選及其對數機率（logprobs）。所有標註產出——包括訊息、標註、操作日誌與機率快取——都會序列化為單一 `.panda.json` 檔案，便於分發、收集與解析。

標註過程還被組織成一棵**標註樹（annotation tree）**：每個節點是一個對話（dialog），包含完整的訊息、工具與標註副本。每次校正都會分叉出一個新節點，其父節點是校正前的對話。所有中間版本自動保存，無需標註者手動管理版本。每個節點都記錄操作類型、時間戳、校正內容、是否標記為在策略（on-policy），以及取樣設定的快照，確保每筆資料都具有完整的可追溯性（provenance）。

最後，onPanda 也支援**智能體（agent）軌跡標註（trajectory annotation）**。它可以透過 MCP 連接外部工具，並整合 Claude Code、Codex、OpenClaw 等測試框架（harness），讓標註者在真實環境中互動式地修正工具呼叫（tool calls）與推理步驟，並在執行修正後繼續生成後續軌跡。

#### 實驗數據解讀

論文中提到的實驗證據相對精簡，主要來自一項小型對照研究：

- **標註時間（annotation time）**：onPanda 相較於傳統的人工後編輯（manual post-editing），可將**中位數標註時間（median annotation time）降低 52%**。這是一個顯著的效率提升，顯示「詞元級校正」確實能減少標註者的認知與打字負擔。
- **在策略保真度（on-policy fidelity）**：雖然沒有提供具體的數值指標，但論文強調最終回應中絕大多數詞元仍由模型本身生成，因此產生的 SFT 資料（SFT data）與偏好資料（preference data）能夠高度保留原始 rollout 模型的取樣分佈。
- **Panda-CVL 資料集與基準**：作者釋出了 Panda-CVL（Chinese Vision–Language dataset for token-level correction），這是一個以 onPanda 標註的多模態資料集，並附帶一個針對詞元級校正的基準測試（benchmark），用於促進社群對此類資料的研究。

需要留意的是，論文並未詳細說明這項對照研究的樣本數、任務類型、標註者背景、統計顯著性檢定，或與其他互動式標註工具的定量比較。因此，52% 的時間縮減應被視為初步證據，而非經過大規模驗證的結論。此外，關於在策略保真度的論述主要來自方法設計上的直覺，尚缺乏例如分佈距離（如 KL divergence、perplexity 差異）或下游任務表現等量化驗證。

#### 與現有研究的比較

onPanda 的定位介於幾種現有典範之間，並試圖同時解決它們的缺點：

| 現有方法 | 主要缺點 | onPanda 的改進 |
|---|---|---|
| 從零人工撰寫回應（manual writing） | 成本高、偏離模型分佈、產生離策略資料（off-policy data） | 以模型生成為主，僅修正錯誤位置，降低標註負擔並提升在策略 fidelity |
| 人工後編輯（manual post-editing） | 需反覆閱讀整段回應、認知負擔高、仍會顯著改變分佈 | 線性「邊讀邊改」流程，中位數時間降低 52%，且只改動必要詞元 |
| 偏好標註（preference annotation） | 僅提供回應級（response-level）監督，無法指出錯誤位置；當模型無法取樣好答案時幫助有限 | 提供詞元級錯誤位置與正負樣本對，可轉換為 DPO、reward model、PRM 訓練資料 |
| 觀察與評分 live agent 的工具（如 Jurgens et al., 2026; Ou et al., 2025） | 可介入執行過程，但不一定支援即時文字與工具呼叫修正 | 支援在真實環境中即時修正工具呼叫與推理，並繼續生成後續軌跡 |
| RepTile（Dou et al., 2025） | 允許編輯模型輸出並由終端環境執行，但社群仍缺乏跨環境的通用互動工具 | 透過 MCP 與多種 harness 整合，提供跨環境的通用詞元級校正能力 |

儘管如此，onPanda 仍存在一些限制：

- **候選集合的侷限**：當正確內容不在模型的 top-k 候選集合中時，標註者必須切換到自由格式編輯，這會偏離模型分佈，且需要更多打字與認知成本。
- **對 API 能力的依賴**：需要推論 API 支援 `continue_final_message` 與 `logprobs`，並回傳 top-k 候選。並非所有模型服務都原生支援這些功能。
- **標註者能力要求**：標註者必須能夠快速判斷「第一個不適當的詞元」。對於需要深度領域知識或長程依賴的錯誤，這並不總是容易。
- **實驗規模有限**：目前僅報告小型對照研究的時間效益，缺乏大規模跨任務、跨語言、跨模型的系統性評估。
- **自由格式編輯的分佈代價**：雖然論文認為這只發生在少數位置，但在實際應用中，若模型能力明顯不足，人工注入的比例可能上升，進而影響在策略資料的純度。

#### 可重現性評估

從論文描述來看，onPanda 在可重現性（reproducibility）方面採取了相對開放的策略：

- **開源前端函式庫**：onPanda 被定位為一個元件化的前端函式庫，可靜態託管，也可嵌入現有平台。
- **標準化資料格式**：所有標註產出儲存為 `.panda.json`，包含完整對話、標註、操作日誌與機率快取，便於分享與解析。
- **Python 解析工具**：論文提到提供 `onpanda` Python 函式庫，可將 `.panda.json` 轉換為 SFT 樣本與偏好資料對。
- **釋出資料集與基準**：Panda-CVL 資料集與對應的詞元級校正基準測試已釋出，供社群研究使用。

然而，根據目前提供的上下文，仍有幾項可重現性資訊未明確說明：

- **原始碼倉庫位置**：論文未提供 GitHub 或其他程式碼託管連結，無法確認前端函式庫與 `onpanda` Python 套件是否已公開。
- **模型權重**：onPanda 本身是一個標註工具，並不訓練或釋出新的模型權重，因此不適用於模型權重可取得性的評估。
- **API 與環境依賴**：雖然工具設計上支援通用 Chat Completions API，但實際重現需要具備 `continue_final_message` 與 top-k `logprobs` 的推論後端，以及 MCP 與 harness 的整合細節。
- **Panda-CVL 的授權與規模**：論文未詳細說明資料集的授權條款、樣本數量、任務分佈與取得方式。

整體而言，onPanda 在方法與資料格式上具備良好的可重現潛力，但實際能否完全重現，仍取決於原始碼、文件與資料集是否完整公開。

#### 未來研究方向

onPanda 開啟了詞元級校正作為對齊資料生產典範的可能性，未來可沿以下方向延伸：

1. **自動化校正建議**：結合 critique model 或驗證器，在標註者定位錯誤前主動標示可疑詞元，甚至直接推薦最可能的修正，進一步降低標註成本。
2. **強化學習與詞元級回饋**：將記錄下來的詞元級正負樣本對用於訓練更細粒度的獎勵模型（reward model）或過程獎勵模型（PRM），並探索如何將其整合進 PPO、DPO 等強化學習流程。
3. **多模態與跨領域擴展**：Panda-CVL 已邁向視覺–語言（vision–language）領域，未來可擴展到更多模態（如音訊、程式碼、結構化資料）以及更多語言，特別是低資源語言。
4. **長程智能體軌跡標註**：目前的 agent 支援已展示與 harness 整合的能力，未來可針對更長程、多輪工具呼叫與環境回饋的任務，設計專門的標註介面與評估基準。
5. **主動式學習與資料選擇**：利用詞元級的不確定性或校正頻率，主動選擇最需要標註的樣本，提升資料生產的樣本效率。
6. **標註者一致性與品質控制**：建立詞元級校正的標註者間一致性（inter-annotator agreement）指標，並設計品質控制機制，以確保產生的 SFT 與偏好資料具有高度可靠性。
7. **分佈偏離的量化與控制**：發展指標來衡量自由格式編輯對在策略分佈的影響，並設計演算法在「正確性」與「分佈保真度」之間做最佳權衡。
8. **協作式標註平台**：將 onPanda 擴展為支援多名標註者協作、審查與討論的平台，並結合版本控制與衝突解決機制。
9. **詞元級校正基準的標準化**：除了 Panda-CVL，未來可建立涵蓋不同難度、錯誤類型與領域的標準化 benchmark，用於評估自動校正模型與標註輔助系統。
10. **與合成資料生成結合**：將 onPanda 的互動式標註與大規模合成資料生成流程結合，利用少量高品質人工校正引導更大規模的資料蒸餾。

## 論文問答

**Q1：onPanda 主要想解決 LLM 對齊與智能體資料建構中的什麼核心瓶頸？**

A：onPanda 針對的核心瓶頸是高品質對齊資料與智能體軌跡資料在規模化時，難以同時兼顧標註成本、在策略（on-policy）保真度與監督粒度這三項目標。傳統的人工從頭撰寫回應或人工後編輯雖然能產生符合品質門檻的資料，但成本高昂，且會讓最終資料偏離模型本身的取樣分佈，形成離策略（off-policy）資料。onPanda 透過詞元級校正機制，讓標註者只修改少數錯誤位置，其餘詞元仍由模型生成，從而在降低標註負擔的同時保留模型的原始分佈。

**Q2：為什麼人工撰寫回應或人工後編輯會產生離策略資料，這會帶來什麼問題？**

A：當標註者從頭寫出完整回應，或對模型輸出進行大段後編輯時，最終回應中的大量詞元並非來自模型在給定提示下的實際取樣分佈，而是來自人類的書寫習慣與風格。這使得資料成為離策略資料，與模型在推理時會看到的分佈不一致，可能降低監督式微調（SFT）與偏好學習的效果。相較之下，onPanda 只在模型出錯的少數位置介入，絕大多數詞元仍由模型自己生成或從模型候選中選取，因此更能保留在策略特性。

**Q3：偏好標註（preference annotation）在模型無法取樣出好答案時會有什麼不足？**

A：偏好標註通常要求標註者從模型已生成的兩個或多個回應中選出較好者，但如果模型本身的能力不足以產生任何正確或可用的回應，那麼所有候選都可能很差，偏好標註無法提供正確內容的監督訊號。這種情況下，單純比較「哪一個比較不差」無法告訴模型應該怎麼正確回答。onPanda 的自由格式編輯後備機制允許標註者直接注入正確文字，從而彌補偏好標註在模型能力不足時的缺陷。

**Q4：onPanda 的「定位—修正—繼續」詞元級校正循環具體如何運作？**

A：標註者閱讀模型回應時，一旦發現第一個不適當的詞元，就可以點擊該位置，系統會顯示模型在該位置的前 k 個候選詞元及其機率。標註者可以從候選中選取合適的替代詞元，或在候選都不理想時透過雙擊進行自由格式編輯，輸入任意正確文字。接著系統會截斷該位置之後的所有內容，並從更新後的前綴繼續生成，標註者重複這個循環直到回應符合品質門檻為止。

**Q5：onPanda 宣稱具有哪四項主要優勢，這些優勢分別來自哪些設計？**

A：第一項是高效標註，因為多數校正只需滑鼠點擊，且線性的「邊讀邊改」流程避免重複閱讀整段回應。第二項是高在策略保真度，因為人類只觸碰少數錯誤詞元，其餘詞元由模型生成，且從模型自身高機率候選中選取會進一步減少分佈擾動。第三項是細粒度監督，因為每次詞元級校正都會記錄錯誤位置、替代詞元與自然配對的正負樣本，可轉換為偏好資料或過程獎勵資料。第四項是完全表達能力，因為自由格式編輯讓標註者即使面對模型無法自行取樣的正確內容，也能注入正確文字並引導後續生成。

**Q6：onPanda 為什麼同時提供「候選詞元選取」與「自由格式編輯」兩種修正方式？**

A：候選詞元選取讓標註者利用模型已經能夠合理預測的高機率詞元進行快速修正，這種方式對取樣分佈的干擾最小，也最符合在策略精神。然而，當模型完全無法在某個位置取樣出正確內容時，候選集合可能全部錯誤或不適用，此時自由格式編輯就成為必要的後備機制。兩者結合既保證了常見錯誤的高效修正，又確保了極端或困難情況下標註者仍能注入正確資訊，維持資料的正確性與可用性。

**Q7：論文提供了哪些實證證據來支持 onPanda 的標註效率？**

A：論文報告了一項小型對照研究，結果顯示 onPanda 相較於傳統人工後編輯，能將中位數標註時間降低 52%。這項效率提升主要來自於標註者只需定位並修正第一個錯誤詞元，而不需要反覆閱讀與修改整段回應。雖然這只是初步實驗，但它顯示了詞元級校正互動在降低認知負荷與打字負擔方面的潛力。

**Q8：onPanda 如何保持在策略保真度，其資料協議又記錄了哪些資訊？**

A：onPanda 透過讓絕大多數詞元由模型自身生成，並只在必要位置進行最小化介入，來保持資料接近模型原始取樣分佈。每次標註過程會產生一個 `.panda.json` 檔案，裡面包含完整對話、詞元級註解、操作日誌、機率快取與取樣設定快照，確保每筆資料都有可追溯的來源。這些記錄不僅能匯出為 SFT 樣本，也能根據同一提示下的正負節點自動配對成偏好資料。

**Q9：什麼是標註樹（annotation tree），它如何轉換成 SFT 與偏好資料？**

A：標註樹是由一連串對話節點組成的結構，每個節點都是一次完整對話與工具狀態的快照，每次詞元級校正都會從父節點分叉出一個新節點。所有中間版本都會自動保存，因此標註者無需手動管理版本。最終被標記為 `is_good=Y` 的節點會匯出為 SFT 正樣本，而同一提示下、共享前綴但在校正點分叉的祖先節點則會與正樣本配對，形成自然的正負偏好樣本對。

**Q10：onPanda 如何支援真實環境中的智能體軌跡標註？**

A：onPanda 可以透過 MCP 連接外部工具，並與 Claude Code、Codex、OpenClaw 等測試框架對接，讓標註者能夠在真實環境中與智能體互動。當標註者修正涉及工具呼叫的詞元時，系統會執行修正後的呼叫並取得真實環境回饋，再讓模型繼續後續生成。這種能力彌補了現有工具只能觀察或評分智能體、卻難以即時修正並執行工具呼叫的不足。

**Q11：Panda-CVL 是什麼，論文為什麼要釋出這個資料集與基準？**

A：Panda-CVL 是一個以 onPanda 標註的中文視覺—語言資料集，專門用於詞元級校正研究。論文釋出該資料集與相應基準，是為了讓研究社群能夠取得公開的詞元級校正資料，進一步探索這種新型監督訊號的應用。這有助於推動在策略對齊資料、過程獎�模型與細粒度模型檢測等方向的後續研究。

**Q12：除了資料標註，onPanda 還能扮演什麼樣的研究或產品角色？**

A：由於 onPanda 會即時顯示每個詞元的取樣機率與前 k 候選詞元，它本身就可以作為模型檢測與錯誤分析工具。開發者可以透過它觀察模型在哪些位置機率分佈不確定、候選詞元品質如何，以及少量修正如何影響後續生成。這種可視化與互動能力對於診斷模型弱點、設計提示工程策略以及評估模型行為都非常有價值。

**Q13：自由格式編輯雖然強大，但會帶來什麼樣的分佈成本或限制？**

A：自由格式編輯允許標註者輸入模型原本無法取樣的文字，因此會讓該位置的資料偏離模型自身的取樣分佈。不過，由於這種介入只發生在少數模型能力不足的位置，整體回應中絕大多數詞元仍由模型生成，因此分佈成本被控制在最小範圍。這是一種在正確性與在策略保真度之間的權衡，適合用於確保 SFT 資料能滿足任務要求。

**Q14：在哪些情況下，詞元級校正仍可能無法產生令人滿意的回應？**

A：如果模型在提示理解、長程規劃或多步推理上存在系統性缺陷，那麼僅僅修正單一詞元可能無法引導後續生成走向正確方向，因為錯誤可能會在後續步驟中再次出現。此外，當標註者難以判斷第一個錯誤詞元的確切位置，或錯誤根源來自更早的推理步驟時，定位—修正—繼續的循環可能需要多次迭代。在這些情況下，標註成本會上升，且最終資料可能需要額外的人工審查。

**Q15：onPanda 開啟了哪些未來研究方向？**

A：onPanda 讓社群能夠系統性地收集詞元級校正資料，這可用於訓練更細粒度的過程獎勵模型（PRM）與直接偏好最佳化（DPO）模型。未來研究可以探索如何將這些資料與強化學習演算法結合，以進一步提升模型在推理與工具使用上的可靠性。此外，開發自動化的錯誤定位輔助、跨語言與跨模態的詞元級校正，以及將 onPanda 整合到更大規模的生產標註流程中，也都是值得深入的方向。

## 實務應用指南

### 適用場景

1. **企業內部專屬領域問答的 SFT 資料建置**  
   金融、醫療、法律等領域需要模型回答符合公司知識與合規要求，但人工從頭撰寫回應成本高。使用 onPanda，標註者只需在模型生成的回應中定位第一個錯誤詞元，點選候選詞元或輸入正確文字，即可快速產出大量保留模型原分佈的在策略 SFT 資料。

2. **多模態視覺—語言模型的錯誤修正資料**  
   針對圖片描述、圖表問答或文件理解等任務，模型常在細節詞元出錯（例如把「梯形」說成「平行四邊形」）。onPanda 的詞元級校正可精確標記錯誤位置，並透過 Panda-CVL 這類資料集與 benchmark 訓練模型學會「看圖說對細節」。

3. **Agent 工具呼叫軌跡的互動式標註**  
   當 Agent 在程式碼編輯、資料分析或網頁操作等多步環境中出錯時，標註者可在 onPanda 中即時修正工具呼叫參數或推理步驟，系統會執行修正後的呼叫並繼續生成後續軌跡，適合用於 Claude Code、Codex、OpenClaw 等 harness 的軌跡資料生產。

4. **偏好與過程獎勵模型訓練資料**  
   標註過程中自動記錄的詞元級修正可轉換為 DPO 偏好對，或依據錯誤步驟與前後文轉換為 PRM 的過程獎勵資料，特別適合需要細粒度監督訊號的強化學習對齊流程。

5. **模型檢測與可解釋性分析**  
   onPanda 視覺化每個詞元的 top-k 候選與機率，產品團隊可用它來檢視模型在哪些位置開始偏離預期，協助定位模型弱點、設計更好的提示詞或評估上線風險。

### 實作前置條件

- **資料準備**  
  需要一批待標註的 prompt 或任務輸入，並定義清楚的品質門檻（`is_good` 標準）與標註 schema（單選、多選、文字欄位等）。若為 Agent 任務，需準備對應的環境、工具描述與可執行的 harness。

- **推論後端**  
  需要能支援兩項功能的 API：  
  (1) 從 assistant message 前綴繼續生成（如 vLLM 的 `continue_final_message`）；  
  (2) 回傳每個詞元的 top-k 候選詞元與 logprobs。若使用商業 API，需確認是否開放 logprobs 與前綴續寫能力。

- **運算資源**  
  前端為靜態網頁，部署成本低；主要運算來自推論後端。建議準備足夠的 GPU 推理資源以支援串流生成與 logprobs 計算，並預留儲存空間保存 `.panda.json` 檔案與中間版本。

- **人員技能**  
  標註者需理解任務領域與品質標準，能判斷「第一個不適當詞元」；工程師需熟悉 LLM API、MCP 或 harness 整合，以及資料後處理（將 `.panda.json` 轉為 SFT / preference / PRM 訓練格式）。

---

### 實作步驟建議

1. **定義任務與品質標準**  
   明確寫下何種回應可標為 `is_good=Y`，包括格式、事實正確性、風格與安全規範，並設計標註 schema。

2. **部署 onPanda**  
   選擇輕量版靜態網頁快速試驗，或將元件嵌入既有資料平台。設定推論 API 端點，確認能取得 top-k 候選與 logprobs，並啟用 `continue_final_message` 類功能。

3. **產生初始模型回應**  
   使用目標 rollout 模型對 prompt 進行取樣，將生成結果匯入 onPanda。建議固定 sampling config（temperature、top-p 等）以利後續追蹤。

4. **進行詞元級標註**  
   標註者依序閱讀回應，定位第一個不適當詞元，優先點選模型 top-k 候選中的正確詞元；若候選皆不合適，則使用自由格式編輯輸入正確文字。重複「定位—修正—繼續」循環直到回應達標。

5. **匯出與轉換訓練資料**  
   使用 `onpanda` Python 函式庫解析 `.panda.json`：將 `is_good=Y` 的最終對話匯出為 SFT 樣本；將同一標註鏈上的正負節點配對為 preference 資料；依錯誤步驟產生 PRM 的過程獎勵資料。

6. **驗證資料品質與分佈**  
   比較標註後資料與原始 rollout 分佈的差異，統計人工注入詞元比例、候選詞元使用率與中位數標註時間，確保資料仍接近在策略分佈。

7. **迭代擴充與上線**  
   根據模型訓練結果回補困難案例，擴充到多語言、多模態或更多 Agent 環境，並將 onPanda 整合進持續資料生產管線。

### 潛在風險與注意事項

- **候選詞元限制導致偏差**  
  若標註者頻繁使用自由格式編輯，會在少數位置大幅偏離模型原分佈。建議監控人工注入詞元比例，並在訓練時對這些位置加權或標記，避免模型學到無法自行生成的內容。

- **標註者一致性難以維持**  
  「第一個不適當詞元」的判斷可能因人而異。需透過詳細指南、範例庫與定期校準會議來降低歧異，並利用 onPanda 自動保存的中間版本進行覆核。

- **Agent 環境執行風險**  
  修正工具呼叫後實際執行可能產生副作用（如刪除檔案、呼叫外部 API）。務必在沙箱或隔離環境中運行 harness，並對危險操作加上確認機制。

- **資料洩漏與隱私**  
  `.panda.json` 包含完整對話、機率快取與操作日誌，可能記錄敏感資訊。需建立去識別化流程、存取權限控管與安全的傳輸儲存機制。

- **過度擬合標註者偏好**  
  由於資料緊貼 rollout 模型分佈，若模型本身有系統性偏誤，標註者可能習慣只修小錯而忽略結構性問題。建議搭配獨立的人工審查與多樣化 prompt 來補強。

### 與其他技術的整合建議

- **與現有資料平台整合**  
  onPanda 的元件可嵌入內部標註平台，由後端負責任務分派、品質抽檢與 `.panda.json` 彙整，前端專注於互動標註與視覺化。

- **與 vLLM / TGI / 商業 API 整合**  
  確認推論後端支援 `continue_final_message` 與 logprobs；若使用不支援的 API，可考慮在本機部署 vLLM 作為標註專用推理層，再將訓練資料餵給主模型。

- **與 MCP 及 Agent harness 整合**  
  透過 MCP 協定連接外部工具，並對接 Claude Code、Codex、OpenClaw 等 harness，讓修正後的工具呼叫能即時執行並回傳真實環境反饋。

- **與 DPO / PPO / PRM 訓練管線整合**  
  將 onPanda 輸出的正負樣本對直接餵入 DPO 或獎勵模型訓練；將詞元級修正位置與步驟資訊轉為 PRM 的過程獎勵標籤，強化多步推理能力。

- **與版本控制與實驗追蹤整合**  
  把 `.panda.json` 與對應的 sampling config、模型版本一併納入 DVC 或 MLflow 管理，確保每筆訓練資料都可追溯來源與產生條件。

- **初學者**

- **AI 工程師**  
  重點閱讀「實作前置條件」與「與其他技術的整合建議」，確認你的推論 API 是否支援 `continue_final_message` 與 logprobs，並評估將 onPanda 嵌入現有資料平台或 Agent harness 的工法；同時留意「潛在風險」中關於分佈偏移與資料轉換的實務細節。

- **研究人員**  
  請聚焦論文的方法論貢獻與資料協定：詞元級校正如何產生自然配對的正負樣本、如何在保留 rollout 分佈的同時提供細粒度監督，以及 Panda-CVL benchmark 對 token-level correction 研究的意義；可進一步探索將這些資料用於 DPO、PRM 或 process reward 的理論保證。

- **產品經理**  
  建議優先瀏覽「適用場景」與「潛在風險與注意事項」，評估 onPanda 能否降低你所在領域的標註成本並提升資料品質；同時把「實作前置條件」當作資源與時程評估的檢查清單，並與工程團隊討論如何將標註流程整合進現有產品開發週期。
