## 摘要翻譯

本文提出 EvolvingWorld（演化世界），一個用於互動式文學世界（Interactive Literary World）中角色與世界共同演化（Character and World Co-Evolution）的框架與基準。現有系統往往將互動式文學模擬視為靜態人格模仿（Static Persona Imitation）或獨立場景生成（Isolated Scene Generation），無法捕捉角色與世界如何隨時間共同演化。為了解決此問題，EvolvingWorld 將文學模擬建模為一個長期過程（Long-Horizon Process），其中角色互動、場景推進（Scene Progression），並持續更新角色狀態（Character State）與世界狀態（World State）。不同於依賴固定綱要（Fixed Schemas）的先前系統，EvolvingWorld 採用開放綱要框架（Open-Schema Framework），以支援在多樣化的文學世界（Diverse Literary Worlds）中進行模擬。該框架由兩個相互耦合的模組組成：角色代理（Character Agent）負責多角色扮演（Multi-Character Role-Play）與持續性角色檔案演化（Persistent Profile Evolution）；基於大型語言模型的世界模型（LLM-based World Model）則負責全局狀態（Global State）與地點／實體層級狀態（Location/Entity-Level State）的狀態維護（State Maintenance）及場景推進（Scene Progression）。基於此架構，我們制定了 7 項可訓練任務（Trainable Tasks），用於場景初始化（Scene Initialization）、互動生成（Interaction Generation）與狀態更新（State Update）。我們從 57 本書建構了資料集，產生 138,596 個監督式訓練樣本（Supervised Training Samples）與 222 個用於測試的快照（Snapshots）。此外，我們提出一個軌跡層級（Trajectory-Level）的 LLM-as-Judge（大型語言模型評判）評估協定（Evaluation Protocol），涵蓋 10 個維度（Dimensions）與 20 項指標（Metrics）。實驗顯示，EvolvingWorld 能夠透過有效維持持續且連貫的發展（Persistent, Coherent Development），提升長期模擬表現。

### 核心貢獻（3～5點）
- 提出開放綱要框架（Open-Schema Framework），突破固定綱要限制，支援多樣化文學世界中的長期模擬。
- 設計雙耦合模組架構：角色代理（Character Agent）負責多角色扮演與持續性角色檔案演化；基於大型語言模型的世界模型（LLM-based World Model）負責全局與地點／實體層級狀態維護及場景推進。
- 將文學模擬形式化為 7 項可訓練任務（Trainable Tasks），涵蓋場景初始化、互動生成與狀態更新。
- 從 57 本書建構大規模資料集，包含 138,596 個監督式訓練樣本與 222 個測試快照。
- 提出軌跡層級（Trajectory-Level）的 LLM-as-Judge 評估協定，以 10 個維度與 20 項指標評量長期模擬的持續性與連貫性。

### 適合對象
本論文適合對互動式敘事、角色扮演代理（Role-Play Agents）、世界模型（World Model）、大型語言模型（LLMs）長期模擬、計算創意與文學計算有興趣的研究者與開發者，特別是關注角色與世界如何隨時間共同演化、以及如何建立可持續運作的互動式文學世界之讀者。

## 深度分析

#### 方法論解析

EvolvingWorld（演化世界）將互動式文學世界（Interactive Literary World）的模擬重新定義為一個長期過程（Long-Horizon Process），其核心目標不再只是產生下一句符合角色人格的對話，而是要在多個場景（Scene）推進的過程中，持續維護並演化角色狀態（Character State）與世界狀態（World State）。為此，論文提出了一個開放綱要框架（Open-Schema Framework）：系統不預先為所有書籍固定相同的欄位結構，而是根據每本書的內容自動推論應追蹤的角色維度（如核心人格、職業身份、社會地位、信念、動機、關係等）與世界維度（如社會秩序、地點狀態、重要實體等）。這種設計讓框架能夠跨越多樣化的文學世界（Diverse Literary Worlds），例如偵探小說、維多利亞時代孤兒故事或超自然體系，而不必強行將它們塞入同一套固定綱要（Fixed Schemas）。

在架構上，EvolvingWorld 由兩個緊密耦合的模組組成。第一個是 Character Agent（角色代理），負責多角色扮演（Multi-Character Role-Play）與持續性角色檔案演化（Persistent Profile Evolution）。它不僅生成對話（Speech），還可輸出內心獨白（Thought）、行動（Action）、環境訊息（Environmental Message）以及集體行動（Group Action），從而讓多個虛構角色在同一場景中同時互動。第二個是 LLM-based World Model（基於大型語言模型的世界模型），負責全局狀態（Global State）與地點／實體層級狀態（Location/Entity-Level State）的維護，並推動場景推進（Scene Progression）。兩個模組的關鍵在於「共同演化」：角色的行動可以改變地點或社會秩序，而世界的變化又會回過頭影響角色的動機與人格發展。

為了讓這個過程可學習且可評估，作者將整個流程拆解為 7 項可訓練任務（Trainable Tasks），涵蓋場景初始化（Scene Initialization）、互動生成（Interaction Generation）與狀態更新（State Update）三大階段。場景初始化根據當前世界與角色狀態決定新場景的參與者、地點與情境；互動生成則產出多角色的語言、行動與環境反饋；狀態更新則進一步細分為角色檔案更新、全局世界狀態更新以及地點／實體層級更新。這種監督式拆解的優點在於，每個子任務都可以獨立訓練與除錯，而不必將所有責任都壓在一個端到端模型上。

從方法論設計來看，最困難的環節在於「何時、以何種證據更新哪些維度」。EvolvingWorld 採用證據驅動的更新邏輯：當互動內容提供足夠線索時，才會修改角色人格或世界狀態，並記錄為 ∆World State（世界狀態變化）或 ∆Core Personality（核心人格變化）。以《玩偶之家》（A Doll’s House）為例，系統能夠追蹤「信箱從有信變為空」這類地點狀態變化，以及 Nora 從恐懼轉為冷靜決心的核心人格轉變。這顯示框架試圖將文學模擬從「靜態人格模仿」（Static Persona Imitation）提升為「持續且連貫的發展」（Persistent, Coherent Development）。

#### 實驗數據解讀

論文從 57 本書籍中構建了一個資料集，包含 138,596 個監督式訓練樣本（Supervised Training Samples）以及 222 個測試用快照（Snapshots）。這個規模對於文學世界模擬任務來說已屬可觀，但相對於整體文學作品總量仍屬小型，且書籍的版權與授權問題可能會限制資料的公開與擴充。測試快照是從書中截取的特定時刻狀態，用於評估模型在長期互動後能否維持與原著一致的發展軌跡。

在評估方面，作者提出了一個軌跡層級（Trajectory-Level）的 LLM-as-Judge（大型語言模型評判）評估協定（Evaluation Protocol），涵蓋 10 個維度（Dimensions）與 20 項指標（Metrics）。與傳統只評估單一回合對話流暢度的做法不同，這個協定評估的是整條互動軌跡，重點檢視長期模擬中的角色一致性、世界狀態連貫性、場景推進合理性以及事件因果關係等面向。這種設計更能反映文學模擬的真實挑戰：即使每一句對話都流暢，長期下來角色人格或世界狀態仍可能逐漸漂移。

實驗結果顯示，EvolvingWorld 能夠減少先前框架在長期模擬中常見的性能衰退（Long-Horizon Performance Degradation），有效維持持續且連貫的角色與世界發展。由於提供的片段未包含詳細數值表格，我們無法判斷各維度（Dimensions）的絕對分數與變異程度，但從方法論推論，這樣的改善主要來自兩點：一是將狀態維護與互動生成解耦為可訓練子任務，降低了錯誤累積；二是開放綱要讓模型能夠針對不同書籍追蹤最相關的狀態維度，而非被迫忽略關鍵資訊。

然而，LLM-as-Judge 本身也存在方法論風險。評判模型可能偏好語言流暢、辭藻華麗但偏離原著的輸出，也可能對某些文學風格或時代背景產生偏見。因此，未來若能補充人類評審對照、報告評判者間一致性（Inter-Annotator Agreement）以及各指標的權重設計，將能大幅提升評估結果的可信度。此外，222 個測試快照雖足以進行初步驗證，但要涵蓋不同文類、時代與文化背景，仍需要更大規模且更多元化的測試集。

#### 與現有研究的比較

從 Table 1 的比較可以清楚看出，EvolvingWorld 是目前唯一在角色、互動與世界三個層面都提供完整支援的框架。傳統的角色扮演系統如 ChatHaruhi、CharacterLLM、RoleLLM、CharacterGLM 等主要停留在靜態人格模仿（Static Persona Imitation）：它們擁有角色檔案（Profile）並能生成對話（Speech），但缺乏自動的角色檔案更新（Profile Update）、開放綱要（Open-Schema）以及世界狀態維護。這意味著這些系統適合短對話，但難以處理隨劇情演變的角色成長。

多智能體環境如 GenerativeAgents、LARP、CharacterBox 雖然支援行動、思想與多角色互動，但它們通常依賴手動設定的沙盒（Manual Sandboxes），難以擴展到多樣化的文學世界，且在開放綱要、全局狀態演化（Global State Evolution）與監督式訓練（Training）方面支援有限。BookWorld 是與 EvolvingWorld 最接近的前置研究，它會更新角色目標、狀態與全局事件，但缺少完整的角色檔案演化、地點／實體層級更新，以及可訓練子任務的監督訊號。相較之下，EvolvingWorld 透過將場景初始化、互動生成與狀態更新都轉化為可訓練任務，讓整個共同演化過程變得更加透明與可控。

儘管如此，EvolvingWorld 也存在一些限制。首先，開放綱要雖然提升了彈性，但其維度推論完全依賴大型語言模型（LLMs），可能產生幻覺維度（Hallucinated Dimensions）或遺漏關鍵維度，尤其是在結構複雜或象徵性強的文學作品中。其次，狀態更新需要精確的因果證據，但 LLM 在區分「相關事件」與「真正導致狀態改變的事件」時仍可能出錯。第三，LLM-as-Judge 的主觀性與模型偏好可能影響評估結果。第四，57 本書的資料集雖具代表性，但對於涵蓋全球多元文學仍顯不足，且書籍授權可能限制後續擴展。最後，整個框架需要多次呼叫 LLM 進行維度推論、互動生成與狀態更新，計算成本與延遲可能較高，限制了即時互動應用。

#### 可重現性評估

論文提供了 GitHub 連結（https://github.com/HKUST-KnowComp/EvolvingWorld），這是提升可重現性的重要第一步。然而，可重現性的高低取決於作者實際釋出了哪些內容。理想的開源釋出應包含：原始書籍資料的處理腳本、138,596 個監督式訓練樣本（Supervised Training Samples）、222 個測試快照（Snapshots）、七項可訓練任務（Trainable Tasks）的訓練程式碼與提示模板（Prompts）、模型權重（Model Weights）、推論流程，以及 LLM-as-Judge（大型語言模型評判）評估協定（Evaluation Protocol）中 10 個維度（Dimensions）與 20 項指標（Metrics）的詳細定義與評分提示。

如果倉庫僅提供部分示範程式或預處理工具，而缺少訓練資料與模型權重，那麼其他研究者將難以完全重現論文中的實驗結果，也難以在此基礎上進行公平比較。此外，由於資料來自 57 本書籍，版權與授權問題可能會限制完整資料集的公開，這是文學領域常見的可重現性障礙。建議作者至少釋出資料處理流程、去識別化或摘要後的樣本格式、訓練超參數、隨機種子（Random Seeds）以及依賴環境（Requirements），以便社群能夠在合法範圍內重建實驗。

#### 未來研究方向

EvolvingWorld 為互動式文學世界（Interactive Literary World）的長期模擬開闢了多條後續研究路徑。首先，可以將框架擴展至多模態（Multimodal）文學世界，結合視覺場景、聲音與音樂，讓模擬不僅限於文字。其次，可以引入即時人類使用者介入機制，讓使用者能夠在模擬過程中與角色互動，並觀察世界狀態（World State）隨之產生的連鎖反應。

第三，開放綱要（Open-Schema）的推論與精煉可以進一步自動化，例如讓系統在發現現有維度無法解釋新事件時，動態新增或合併維度。第四，狀態更新可以結合更強大的因果推理（Causal Reasoning）與事件邏輯，區分真正導致角色轉變的關鍵事件與背景雜訊。第五，長期記憶（Long-Term Memory）與檢索機制的設計將變得更加重要，尤其是在模擬長篇小說時，如何有效檢索過往事件以支持當前決策是一大挑戰。

第六，可以結合人類回饋強化學習（RLHF）或人類評審，讓模型學習更符合文學審美與敘事結構的生成策略。第七，跨書籍世界（Cross-Book Worlds）或原創世界生成也是值得探索的方向：讓系統不僅模擬現有書籍，還能創造全新的文學宇宙。第八，與遊戲引擎或互動敘事平台整合，可將文學模擬轉化為可玩的互動體驗。第九，社會模擬（Social Simulation）與群體動力學（Group Dynamics）的引入，可以讓多個角色之間的關係網路隨時間更真實地演化。最後，安全性、偏見、版權與隱私問題也需要持續關注，確保這類強大的文學模擬工具能夠被負責任地部署與使用。

## 論文問答

**Q1：EvolvingWorld 主要想解決什麼問題？**
A：EvolvingWorld 旨在將互動式文學世界模擬重新定義為一個長期過程，讓角色與世界狀態能夠隨著劇情持續共同演化。過往系統多半只把互動文學視為靜態人格模仿或獨立場景生成，無法捕捉角色信念、動機、關係以及地點、物件、社會背景隨時間產生的變化。因此，本文的核心目標是建立一個能同時維持角色狀態與世界狀態持續且連貫發展的框架。

**Q2：現有的角色扮演系統為何無法勝任長期文學模擬？**
A：現有系統主要在三個方面不足：第一，多數人格導向代理僅依賴靜態檔案或短對話上下文；第二，多代理環境常需人工指定沙盒，難以擴展到多樣化的文學世界；第三，既有書本導向系統多聚焦單一場景或部分長期更新，缺乏完整的角色檔案演化、地點／實體層級的世界更新，以及可訓練子任務的監督訊號。從表1可見，幾乎所有對照框架在開放綱要、世界狀態演化與持續性角色更新等項目都未完整支援。這些缺失使得長期模擬容易出現狀態漂移與劇情不一致。

**Q3：角色與世界共同演化為何對文學模擬至關重要？**
A：在真實文學敘事中，角色行動會改變地點、物件與社會秩序，而世界的變化也會回過頭來影響角色的動機與人格。如果只更新角色而忽略世界，或只生成場景而不維護狀態，模擬就會失去因果連貫性與敘事深度。共同演化因此是讓互動文學世界從「重現固定情節」邁向「動態且可信的長期發展」的關鍵。

**Q4：EvolvingWorld 的核心架構包含哪些模組？**
A：框架由兩個緊密耦合的模組組成：一是 Character Agent，負責多角色扮演與持續性角色檔案演化；二是基於大型語言模型的 World Model，負責維護全局狀態以及地點／實體層級狀態，並推動場景推進。兩個模組互相回饋，確保角色行為能反映世界變化，世界狀態也能因角色互動而更新。在此架構上，作者進一步將整個流程拆解為七項可訓練子任務，涵蓋場景初始化、互動生成與狀態更新。

**Q5：什麼是「開放綱要框架」，它為何是關鍵創新？**
A：開放綱要指的是系統不預先強制所有故事套用固定欄位，而是根據每本書的內容自動推論應追蹤的角色與世界維度。例如偵探故事可能需要追蹤「辦案習慣」，而維多利亞時代孤兒故事則需追蹤「社會地位」；世界維度也可能從學校規則轉變為政治秩序或超自然系統。這種彈性讓 EvolvingWorld 能支援多樣化的文學世界，並根據劇情證據決定何時更新哪些維度。

**Q6：EvolvingWorld 的七項可訓練任務大致涵蓋哪些面向？**
A：這七項任務圍繞場景初始化、互動生成與狀態更新三大階段，包括自動生成新場景、多角色之間的對話、內心想法、行動與環境訊息，以及集體行為等互動內容，還有角色檔案更新與世界全局／地點／實體狀態更新。透過監督式學習，這些子任務提供了明確的訓練訊號，使長期模擬不再只是端到端生成。這樣的拆解也提升了系統的可解釋性與可控性。

**Q7：實驗使用了什麼資料集與評估協定？**
A：研究團隊從 57 本書建構資料集，產出 138,596 個監督式訓練樣本與 222 個測試快照，用於訓練與驗證模型。評估方面則提出軌跡層級的 LLM-as-Judge 評估協定，涵蓋 10 個評估維度與 20 項指標。這套協定不只看單一回合的角色扮演品質，更著重整條互動軌跡中角色與世界狀態是否持續、連貫地發展。

**Q8：實驗的主要結果是什麼？**
A：實驗顯示 EvolvingWorld 能有效改善長期模擬表現，維持角色與世界狀態的持續且連貫發展。與先前框架相比，它減少了長期模擬中常見的效能衰退問題。這證明將角色代理與世界模型耦合、並採用開放綱要設計，對於長期文學世界模擬具有實質助益。

**Q9：從對照表與消融角度可看出哪些關鍵設計的貢獻？**
A：表1顯示 EvolvingWorld 是少數同時完整支援開放綱要角色檔案、多角色場景初始化、多種訊息類型、全局與地點／實體世界更新，以及可訓練子任務的框架；相較之下，BookWorld 僅提供部分支援。雖然提供的摘要未詳列每一項消融實驗，但從架構設計可推論，若移除世界模型或改回固定綱要，長期一致性與狀態維護能力將明顯下降。這凸顯了耦合式角色—世界共同演化與開放綱要的重要性。

**Q10：EvolvingWorld 可應用在哪些實際場景？**
A：這項技術可應用於互動式小說、AI 輔助敘事創作、教育角色扮演、開放世界遊戲以及虛擬社會模擬等領域。它能讓使用者與文學角色互動時，看到角色與世界隨著選擇持續演變，而非重複固定台詞。這為沉浸式敘事引擎與動態遊戲劇情提供了新的可能性。

**Q11：若要將此技術產品化，需要考慮哪些問題？**
A：首先必須處理版權書籍內容的使用授權，並建立內容安全過濾機制。其次，大型語言模型驅動的多角色代理與世界模型計算成本高昂，需要考慮延遲與擴展性。此外，開放綱要維度的自動推論需要校準，LLM-as-Judge 評估也必須處理評判偏差與成本問題。

**Q12：這項研究對相關領域可能帶來什麼影響？**
A：EvolvingWorld 將角色扮演研究從「靜態人格模仿」推向「長期共同演化」的新方向。它提供了可訓練任務與基準，讓後續研究能針對長期一致性進行系統性比較。同時，開放綱要的世界建模思路也可能影響互動敘事、遊戲 AI 與多代理系統的未來設計。

**Q13：這項研究有哪些可能的限制？**
A：資料集目前僅涵蓋 57 本書，文學類型與文化背景仍有限；LLM-as-Judge 評估雖然全面，但可能繼承語言模型的偏好與偏差。開放綱要維度的推論依賴大型語言模型，可能產生幻覺或不完整的維度設定。此外，長期模擬的計算開銷與狀態追蹤複雜度也會隨著互動長度增加而上升。

**Q14：在實際運作中可能出現哪些失敗案例？**
A：世界模型可能遺漏間接後果，導致某些地點或物件狀態更新不一致；角色檔案在長期互動中可能過度漂移，偏離原始設定。開放綱若有時會遺漏關鍵維度或引入無關維度，影響狀態追蹤品質。若使用者輸入與書本證據嚴重不符，系統也可能產生不合邏輯的演化結果。

**Q15：未來可以朝哪些方向延伸？**
A：未來可擴展到更長的互動軌跡與真正的使用者即時互動情境，並加強自動綱要推論與一致性檢查機制。結合外部記憶與檢索技術，有助於維持更龐大的世界狀態。此外，發展更可靠的人類評估、支援多模態世界狀態，以及將框架應用於遊戲與虛擬社會，都是值得探索的方向。

## 實務應用指南

### 適用場景

1. **動態敘事遊戲與互動影視**  
   將 EvolvingWorld 作為遊戲引擎的劇情核心，讓 NPC 不再是重複固定台詞的靜態角色，而是隨玩家選擇持續改變信念、動機與人際關係；同時地點與關鍵物件狀態也會同步更新，產生具有長期因果連貫性的分支劇情。

2. **文學教育與沉浸式閱讀輔助**  
   讓學生進入《玩偶之家》等經典作品，與書中角色對話並探索「如果 Nora 做出不同決定」的後續發展。世界模型會維護 19 世紀社會秩序、家庭空間與信件等實體狀態，幫助學習者理解角色與社會如何共同演化。

3. **長期陪伴型虛擬角色**  
   應用於社交或情感陪伴產品，角色檔案會隨著長期互動逐漸演化，地點與物品狀態也會記錄共同經歷，避免「每次對話都重新認識使用者」的斷裂感。

4. **小說與劇本共同創作工具**  
   作家可與 AI 共同發展長篇故事，系統自動維護世界觀一致性、角色成長弧線與場景推進，減少因長期寫作導致的人設崩壞或設定矛盾。

5. **企業情境模擬與培訓**  
   模擬組織變革、客戶關係或跨部門談判，參與者與多個虛擬角色互動，角色立場與辦公室、文件等世界狀態會隨決策演變，用於評估策略後果。

### 實作前置條件

**資料條件**
- 需要高品質文學文本或劇本，包含角色對話、場景描述、角色內心狀態與世界狀態變化。
- 若無現成標註，需自行抽取並標註「模擬前 snapshot → 互動軌跡 → 模擬後 snapshot / ∆ state」。
- 可參考論文從 57 本書建構 138,596 筆監督式訓練樣本與 222 個測試快照的做法。

**運算條件**
- 需可微調大型語言模型的 GPU 資源（如 A100 / H100），用於七項可訓練任務的監督式學習。
- 需要穩定的 LLM 推理環境，支援多輪長期軌跡生成。
- 評估階段建議準備 LLM-as-Judge 用的 API 或本地評判模型，以執行 10 維度 20 指標的軌跡層級評估。

**技能條件**
- 熟悉 LLM 微調、Prompt Engineering 與資料工程。
- 具備知識表示與開放綱要設計能力，能為不同文學世界推導適合的角色與世界維度。
- 具備評估設計與產品整合經驗，能將學術框架轉化為可上線的服務。

### 實作步驟建議

1. **定義應用領域與開放綱要**  
   先釐清目標文學世界的特性，從文本中推導角色維度（人格、信念、動機、關係）與世界維度（社會秩序、地點、實體），避免強制套用固定欄位。

2. **收集與建構資料**  
   從書籍、劇本或原創設定中抽取場景、對話與狀態變化，建立「模擬前 snapshot → 互動軌跡 → 狀態變化（∆）」的訓練樣本。

3. **設計雙模組架構**  
   實作 Character Agent（負責多角色扮演與持續性角色檔案演化）與 LLM-based World Model（負責全局、地點與實體層級的狀態維護與場景推進）。

4. **實作七項可訓練任務**  
   將場景初始化、互動生成（speech / thought / action / environmental / group message）與狀態更新拆解為可監督學習的子任務，分別訓練或聯合訓練。

5. **訓練、驗證與對齊**  
   使用自有資料或論文資料進行微調，並透過 snapshot 比對與規則檢查，確保角色與世界狀態在長期軌跡中保持一致。

6. **建立軌跡層級評估機制**  
   導入 LLM-as-Judge 評估協定，從 10 個維度、20 項指標持續監控長期模擬品質，並保留人類抽樣複審。

7. **產品化與迭代**  
   封裝為 API，串接前端互動介面、記憶儲存與內容安全過濾機制，並依使用者回饋持續更新資料與模型。

### 潛在風險與注意事項

- **開放綱要導致維度膨脹與不一致**  
  開放綱要雖能支援多樣文學世界，但若缺乏本體約束，容易出現維度過多或定義衝突。建議為每個世界建立最小核心維度集，並透過評估指標把關。

- **長期狀態飄移與幻覺**  
  隨著模擬回合增加，角色或世界狀態可能逐漸偏離原作或自身設定。可定期進行 snapshot 對齊、引入摘要機制，並結合人類回饋校正。

- **版權與內容安全**  
  使用受版權書籍作為訓練或測試資料時需確認授權；生成內容可能涉及暴力、歧視或不當價值觀，需設置過濾與審核機制。

- **高昂的推理與評估成本**  
  長期軌跡生成與 LLM-as-Judge 評估會消耗大量算力與 API 費用。可採用分層世界模型、快取常用狀態、或對評估指標進行抽樣執行。

- **角色同質化或偏離原作風格**  
  模型可能傾向生成通用對話，失去特定文學世界的語言風格。建議在訓練資料中強化原作語言特徵，並加入風格對齊指標。

- **評估主觀性與 LLM 評判偏差**  
  LLM-as-Judge 可能偏好流暢但不符合設定的輸出。建議結合規則檢查、原作對照與人類評分，形成多層次評估。

### 與其他技術的整合建議

- **遊戲引擎（Unity / Unreal）**  
  將 World Model 的狀態輸出透過 API 同步到遊戲場景，例如地點狀態改變時更新場景物件，角色狀態改變時影響 NPC 行為樹。

- **RAG 與向量資料庫**  
  使用向量資料庫儲存長期記憶、世界設定與歷史場景摘要，讓 Character Agent 與 World Model 能快速檢索相關上下文。

- **現有對話系統與客服平台**  
  將 EvolvingWorld 作為後端角色引擎，為客服、品牌大使或教育機器人提供具備長期關係演化的多角色互動能力。

- **創作工具外掛（Scrivener、Final Draft、Notion）**  
  開發外掛讓作家在寫作過程中呼叫 AI 生成下一場景、檢查設定一致性，或探索不同劇情分支。

- **多模態生成模型**  
  結合圖像、語音或音樂生成模型，將 World Model 中的地點與情境描述轉為場景畫面、角色語音或背景音樂。

- **RLHF / DPO 優化管線**  
  將 LLM-as-Judge 與人類回饋整合進強化學習或偏好優化流程，持續改善角色行為與世界狀態更新的品質。
