## 摘要翻譯

觸覺（touch）提供了感知內在材料屬性（intrinsic material properties）所需的物理基礎（physical grounding），例如摩擦力（friction）與柔順性（compliance），而這些屬性往往僅靠視覺（vision）難以判斷。然而，近期為多模態大型語言模型（multimodal large language model, MLLM）賦予此觸覺感知（tactile sense）的嘗試，揭示了一項零和權衡（zero-sum trade-off）：緊湊模型（compact models）有限的參數預算（parameter budget），迫使模型在獲取新感官模態（sensory modality）與保留既有視覺-語言推理（vision-language reasoning）能力之間做出抉擇。我們提出 Splash（Mask-isolated Tactile Alignment Learning），一個用於 MLLM 的遮罩隔離觸覺對齊學習框架。Splash 量化每個預訓練參數（pretrained parameter）的重要性，並將參數空間（parameter space）劃分為休眠子空間（dormant subspace）與關鍵子空間（critical subspace）。凍結的關鍵子空間（frozen critical subspace）作為穩定錨點（stable anchor），保護一般視覺知識（general visual knowledge）；與此同時，Splash 更新隔離的休眠子空間（isolated dormant subspace），以將觸覺對齊（tactile alignment）內化至 LLM 中。這種選擇性非破壞性擴展（selective, non-destructive expansion）能有效防止災難性遺忘（catastrophic forgetting），並確保非破壞性模態擴展（non-destructive modality expansion）。大量實驗顯示，Splash 能在 LLM 部分不增加額外推論開銷（inference overhead）的前提下，有效實現觸覺推理（tactile reasoning），並在 SSVTP、TVL 與 TacQuad 等視覺-觸覺基準（visuo-tactile benchmarks）上展現最先進表現（state-of-the-art），同時保留其原有的通用能力（general-purpose capabilities）。

### 核心貢獻（3～5點）
- 提出 Splash 框架：以遮罩隔離觸覺對齊學習（Mask-isolated Tactile Alignment Learning）為緊湊型 MLLM 引入觸覺感知，突破新增模態與保留既有能力之間的零和權衡。
- 選擇性參數更新機制：量化預訓練參數重要性，將參數空間劃分為凍結的關鍵子空間（穩定錨點）與隔離的休眠子空間，有效防止災難性遺忘。
- 無額外推論開銷：在 LLM 部分不增加額外推論開銷的前提下實現觸覺推理，並於 SSVTP、TVL、TacQuad 等視覺-觸覺基準達到最先進表現。
- 保留通用能力：在擴展觸覺模態的同時，維持模型原有的視覺-語言推理與通用能力，實現非破壞性模態擴展。

### 適合對象
從事多模態大型語言模型、具身智慧、機器人感知與觸覺感測研究的學者與工程師，特別是關注如何在資源受限的緊湊模型中進行非破壞性模態擴展、視覺-觸覺-語言推理，以及邊緣機器人部署的讀者。

## 深度分析

#### 方法論解析

Splash 的核心命題是：在緊湊型多模態大型語言模型（compact MLLM，例如 ≤3B 規模的 sMLLM）中，觸覺（touch）對齊與既有視覺-語言（vision-language, VL）能力之間存在零和權衡（zero-sum trade-off）。為了在新增觸覺模態的同時避免災難性遺忘（catastrophic forgetting），作者將 LLM 的參數空間（parameter space）劃分為「關鍵子空間（critical subspace）」與「休眠子空間（dormant subspace）」，並僅在後者上進行觸覺對齊學習。

具體來說，Splash 首先對每個預訓練參數（pretrained parameter）的重要性進行量化。此重要性並非單純依據權重絕對值，而是採用一種相對於 VL 任務的指標，結合權重與激活值統計（weight and activation statistics）來估計。這樣的設計假設是：對於原始視覺-語言推理越重要的參數，越不應該被觸覺訓練干擾；反之，對 VL 影響較小、處於「休眠」狀態的參數，則可以被重新喚醒以內化觸覺對齊（internalize tactile alignment）。

在劃分完成後，關鍵子空間會被凍結（frozen），作為穩定錨點（stable anchor）來保護一般視覺知識（general visual knowledge）；而休眠子空間則透過遮罩（mask）進行隔離，只允許梯度在這些參數上更新。這種遮罩隔離（mask-isolated）機制確保了觸覺訓練不會擴散到整個 LLM，從而實現非破壞性模態擴展（non-destructive modality expansion）。

值得注意的是，Splash 並未引入額外的外部模組（如 adapter 或 LoRA），唯一的額外結構是一個可忽略的前端觸覺編碼器（tactile front-end）。因此，在 LLM 部分不會產生額外的推論開銷（inference overhead）。此外，不同於過往需要多階段對齊與微調（multi-stage alignment and fine-tuning）的方法，Splash 採用單階段統一訓練（single-stage unified training），同步優化觸覺前端與 LLM 中的休眠子空間。

從學習理論的角度來看，Splash 可視為將「剪枝式多任務學習（pruning-based multi-task learning）」從任務層級（task-level）提升到模態層級（modality-level）的應用。它利用 LLM 內部參數的冗餘性，將不同模態的學習限制在不相交的參數子集上，從而降低跨模態干擾。這對於觸覺這種與視覺表徵差距極大的新感官模態（sensory modality）尤其重要，因為觸覺訊號通常包含摩擦力（friction）、柔順性（compliance）等難以從視覺直接推論的內在材料屬性（intrinsic material properties）。

#### 實驗數據解讀

根據論文所述，Splash 在三個視覺-觸覺基準（visuo-tactile benchmarks）上進行評估：SSVTP、TVL 與 TacQuad。這些基準分別涵蓋了不同的評估面向：SSVTP 側重於跨模態檢索與配對、TVL 強調視覺-觸覺-語言（VTL）推理與問答、TacQuad 則涉及跨感測器與細粒度觸覺理解。實驗結果顯示，Splash-3B 達到了最先進表現（state-of-the-art），甚至超越了先前的 7B 規模方法。

這個結果具有幾層意義。首先，它證明了參數隔離策略不僅能避免災難性遺忘，還能釋放出足夠的模型容量來學習高品質的觸覺表徵。相較於全參數微調（full finetuning）導致視覺特徵被扭曲（如圖 1 所示，加入觸覺分支後模型將罐頭上的光線誤判為橡膠工具），Splash 透過凍結關鍵參數維持了視覺-語言推理的穩定性。

其次，Splash 在 Qwen2.5-VL-3B 與 InternVL-1B 兩種不同架構的 sMLLM 上都有效，顯示其方法具有跨骨幹網路（backbone）的通用性。這對於邊緣機器人（edge robots）部署特別重要，因為這些平台通常無法負擔 LLaMA-7B 等運算密集的骨幹網路（computationally intensive backbones）。

第三，論文強調 Splash 保留了模型原有的通用能力（general-purpose capabilities）。作者在多個複雜的通用視覺-語言基準上進行了保留性分析，結果顯示觸覺對齊並未損害 MLLM 骨幹的廣泛智慧。這意味著 Splash 不僅是一個針對觸覺任務的特化方法，更是一種能夠維持模型整體表現的模態擴展方案。

不過，由於目前可取得的上下文未包含完整的數據表格，我們無法進一步分析各項指標的絕對數值、標準差或統計顯著性。若能取得詳細實驗數據，將有助於判斷 Splash 在不同任務類型（如檢索 retrieval、分類 classification、開放詞彙推理 open-vocabulary reasoning）上的相對強弱。

#### 與現有研究的比較

在 Splash 之前，視覺-觸覺-語言（VTL）對齊的研究主要分為兩大類。第一類是基於對比學習（contrastive learning）學習共享 VTL 表徵空間的方法，這類方法在檢索與分類等判別式任務（discriminative tasks）上表現良好，但缺乏高層次語義推理（higher-level semantic reasoning）與指令遵循（instruction following）能力，也難以泛化到視覺上模糊紋理（visually ambiguous textures）的新穎物體（novel objects）。第二類則是將觸覺整合進 MLLM 的方法，但這些方法多依賴大型骨幹（如 7B 規模），並未針對 sMLLM 的容量限制進行設計。

Splash 的貢獻在於填補了「緊湊型 MLLM 觸覺整合」這一研究空白。與過往方法相比，Splash 的主要改進包括：

1. **非破壞性模態擴展**：透過遮罩隔離休眠子空間，Splash 在新增觸覺能力的同時保護了預訓練的視覺-語言能力，解決了圖 1 所示的災難性遺忘問題。

2. **零額外推論開銷**：不同於 adapter 或專家混合（MoE）等需要額外計算的方法，Splash 在 LLM 部分不增加任何推論開銷，僅需一個極小的觸覺前端。

3. **單階段統一訓練**：過往方法常需要分階段進行對齊與微調，而 Splash 可同時訓練觸覺前端與 LLM 的休眠子空間，簡化了訓練流程。

4. **以小勝大**：Splash-3B 在 VTL 基準上超越了 7B 規模方法，顯示參數效率（parameter efficiency）與模態隔離策略的重要性。

然而，Splash 也存在一些潛在限制。首先，參數重要性估計依賴於權重與激活統計，這可能對不同資料分佈或觸覺感測器（tactile sensor）類型敏感。其次，雖然論文強調零額外推論開銷，但觸覺前端的設計細節（例如是否支援多種觸覺感測器、輸入解析度等）會影響實際部署彈性。最後，目前評估主要集中在基準測試上，尚未展示在真實機器人主動操作（active manipulation）任務中的端到端表現。

#### 可重現性評估

從目前提供的論文內容來看，作者尚未明確說明是否公開原始碼、資料集或模型權重。對於這類涉及新模態整合的研究，可重現性（reproducibility）取決於以下幾個關鍵因素：

1. **觸覺資料集與預處理流程**：SSVTP、TVL 與 TacQuad 雖為公開基準，但觸覺訊號的格式、感測器校正與前處理步驟對結果影響極大。若作者能提供完整的資料載入與前處理程式碼，將大幅提升可重現性。

2. **遮罩產生機制**：參數重要性估計與遮罩生成是 Splash 的核心。若未公開具體演算法與超參數（例如休眠子空間的比例、遮罩更新頻率、閾值設定），其他研究者難以復現相同的參數劃分結果。

3. **訓練程式碼與設定**：包括學習率、批次大小、優化器、訓練步數、觸覺前端的架構等，都需要詳細記載。單階段統一訓練雖然簡化流程，但也意味著各元件的協同優化更為敏感。

4. **模型權重**：若能釋出經過 Splash 訓練後的 Qwen2.5-VL-3B 與 InternVL-1B 權重，將有助於社群直接驗證其在通用 VL 基準上的保留性表現，並進行下游應用開發。

總體而言，Splash 的方法論描述相對清楚，但實際可重現性仍高度依賴作者後續是否釋出完整的實作資源。建議讀者在參考時，優先關注論文附錄與專案頁面是否有開源連結。

#### 未來研究方向

Splash 為 sMLLM 的觸覺整合開闢了一條新路径，未來研究可從以下幾個方向延伸：

1. **動態遮罩與持續學習**：目前的遮罩可能在訓練前或訓練初期即固定。未來可探索動態調整關鍵子空間與休眠子空間的機制，使模型能在持續學習（continual learning）情境下依序吸收多種新模態（如聽覺、嗅覺、本體感覺），而不遺忘既有能力。

2. **跨感測器泛化**：觸覺感測器種類繁多（如視覺觸覺感測器、壓力陣列、電阻式感測器等），未來可研究 Splash 是否能泛化到不同物理原理的觸覺輸入，並發展感測器無關（sensor-agnostic）的觸覺前端。

3. **理論分析**：目前參數重要性估計主要基於經驗統計。未來可從資訊理論或最佳化理論角度，分析為何特定參數子空間適合學習觸覺表徵，以及這種隔離策略的泛化上界。

4. **真實機器人應用**：將 Splash 應用於主動操作（active manipulation）與複雜具身決策（complex embodied decision-making）任務，例如根據觸覺回饋（tactile feedback）調整抓取力度、判斷表面滑溜程度（slippery）或柔順性（compliance），將是驗證其實用價值的關鍵下一步。

5. **與其他參數效率方法的結合**：可進一步比較 Splash 與 LoRA、Adapter、Prefix-tuning、BitFit 等方法在觸覺對齊上的優劣，甚至設計混合策略，在休眠子空間內再套用低秩更新，以進一步壓縮可訓練參數量。

6. **多模態融合機制**：目前 Splash 主要隔離 LLM 內部參數，但未來可研究如何在視覺編碼器、模態適配器（modality adapter）與 LLM 之間進行更細緻的模態融合，使觸覺與視覺訊號能在更早階段進行互補。

## 論文問答

【Background & Motivation】

**Q1：為什麼觸覺感知對具身機器人很重要？單靠視覺會遇到什麼瓶頸？**
A：人類在判斷物體是否滑溜、柔軟或堅硬時，經常會觸摸或按壓表面，以取得視覺無法直接觀察到的內在材料屬性，例如摩擦力與柔順性。對具身機器人而言，這類細粒度接觸動力學資訊是執行精細操作的關鍵回饋。然而，純視覺系統常因表面被遮蔽或紋理在視覺上難以區分，而無法準確推斷這些物理性質，因此需要引入觸覺模態來補強。

**Q2：現有的視覺-觸覺-語言（VTL）對齊方法為何不足以應對複雜的具身決策？**
A：過去的方法多透過對比學習建立共享的 VTL 表徵空間，雖然在檢索與分類等判別式任務上有效，但缺乏高層次語義推理與指令遵循能力。此外，它們學到的表徵對於具有視覺模糊紋理的新穎物體泛化性較差。相較之下，多模態大型語言模型（MLLM）能利用 LLM 骨幹中的世界知識進行開放詞彙推理，更適合複雜的物理互動決策。

**Q3：為什麼小型 MLLM（sMLLM）在加入觸覺模態時會面臨零和權衡？**
A：sMLLM（例如 ≤30 億參數規模）的參數預算有限，新增觸覺對齊會與原本已建立的視覺-語言表徵產生干擾。當直接對整個模型進行觸覺微調時，預訓練的視覺特徵容易被扭曲，導致災難性遺忘與視覺-語言推理能力下降。這形成了一個根本取捨：要不犧牲原有視覺-語言能力來換取觸覺感知，要不保留舊能力而無法有效整合新模態。

【Method & Innovation】

**Q4：Splash 的核心方法是什麼？它如何區分並使用「休眠子空間」與「關鍵子空間」？**
A：Splash 首先量化每個預訓練參數的重要性，並將參數空間劃分為休眠子空間與關鍵子空間。關鍵子空間被凍結，作為穩定錨點來保護一般視覺知識與視覺-語言推理能力；休眠子空間則被釋放出來進行梯度更新，以內化觸覺對齊。透過這種選擇性更新，Splash 能在不擾動核心視覺-語言表徵的前提下，將觸覺資訊整合進 sMLLM。

**Q5：相較於全量微調或加入額外 adapter，Splash 的「遮罩隔離觸覺對齊學習」有何關鍵創新？**
A：全量微調會同時改動所有參數，容易破壞預訓練知識；adapter 雖然能減少可訓練參數，但會在推論時引入額外模組與計算開銷。Splash 則直接在模型內部挑選並重新活化休眠權重，不需要新增外部模組，因此 LLM 部分不會產生額外推論開銷。這種非破壞性模態擴展讓模型在獲得觸覺能力的同時，仍維持原有規模與通用能力。

**Q6：Splash 如何估計參數重要性？為什麼選擇凍結關鍵子空間、更新休眠子空間？**
A：Splash 使用一種相對於視覺-語言任務的參數重要性指標，該指標結合權重與激活統計量來評估各參數對既有視覺-語言能力的重要性。對於重要性高的關鍵子空間，凍結可避免觸覺梯度破壞已學到的視覺-語言錨點；對於重要性低的休眠子空間，則允許其吸收新的觸覺對齊資訊。這種設計讓有限的參數預算能同時服務於舊能力保留與新模態整合。

【Experiments & Results】

**Q7：論文在哪些視覺-觸覺基準上進行評估？這些基準分別測試什麼能力？**
A：實驗主要在 SSVTP、TVL 與 TacQuad 三個視覺-觸覺基準上進行。SSVTP 通常評估跨視覺與觸覺的檢索與辨識能力；TVL 著重於視覺-觸覺-語言對齊與開放式問答；TacQuad 則測試模型在不同觸覺感測器與視覺輸入下的泛化與推理表現。這些基準共同涵蓋了從低階判別到高階語義推理的多元觸覺理解能力。

**Q8：Splash 的主要實驗結果為何？與先前方法相比有什麼突破？**
A：Splash-3B 在 SSVTP、TVL 與 TacQuad 上達到最先進表現，甚至超過了先前的 70 億參數規模方法。這顯示透過精準的參數隔離，小模型也能有效整合觸覺模態，而不必仰賴龐大的模型容量。此外，Splash 在 Qwen2.5-VL-3B 與 InternVL-1B 上都展現了穩定的增益，證明其方法具有跨緊湊骨幹的泛用性。

**Q9：消融實驗可能揭示哪些關鍵設計的重要性？**
A：消融實驗通常會比較「無遮罩引導對齊」與 Splash 的完整版本，結果應顯示缺少遮罩隔離時，模型會出現明顯的災難性遺忘與視覺-語言能力下降。另外，隨機選擇可更新參數或提高更新比例，可能會侵蝕預訓練知識；而完全凍結 LLM 則難以有效對齊觸覺特徵。這些對比凸顯了基於權重與激活統計的重要性估計，以及選擇性更新休眠子空間對維持非破壞性模態擴展的關鍵作用。

【Applications & Impact】

**Q10：Splash 在實際應用中適合部署在哪些場景？**
A：Splash 特別適合資源受限的邊緣機器人，例如家庭服務機器人、倉儲撿料手臂或醫療輔助機器人，這些場景需要即時判斷物體表面特性。由於模型緊湊且 LLM 部分無額外推論開銷，它能在低功耗硬體上執行視覺-觸覺推理。舉例來說，機器人可透過觸覺回饋判斷握持力道是否足夠，或辨識視覺上難以區分的材質。

**Q11：從產品化角度來看，Splash 帶來哪些優勢與設計考量？**
A：首先，Splash 不需要新增 adapter 等外部模組，降低了系統複雜度與記憶體佔用，對邊緣部署非常友善。其次，它採用單階段統一訓練，同時優化觸覺前端與 LLM 的休眠子空間，簡化了開發流程並減少多階段調校的工程成本。產品團隊只需準備視覺-觸覺-語言資料，即可在現有 sMLLM 上擴充觸覺能力，而不必擔心嚴重損害原有的通用視覺-語言功能。

**Q12：這項研究對視覺-觸覺 MLLM 領域可能產生什麼影響？**
A：Splash 將「參數隔離」原則從任務層級延伸到模態層級，為新感官模態的整合提供了一個非破壞性典範。它證明小模型透過精準選擇可更新參數，也能在觸覺推理上超越大模型，挑戰了「必須擴大模型規模才能新增模態」的直覺。未來這套框架可望推廣到聽覺、本體感覺等其他模態，促進更輕量且多感官融合的具身智慧系統。

【Limitations & Future】

**Q13：Splash 目前可能存在哪些限制或尚未充分探討的面向？**
A：論文主要聚焦於 ≤30 億參數規模的 sMLLM，對於更大模型的行為與最佳遮罩比例仍需進一步研究。此外，實驗資料多來自靜態觸覺影像或特定感測器格式，對於動態觸摸序列、力回饋或跨感測器泛化的探討相對有限。若要在真實機器人閉環控制中部署，還需補強對時間性接觸資訊與主動操作策略的處理。

**Q14：Splash 在什麼情況下可能出現失敗案例？**
A：當視覺與觸覺資訊互相矛盾，例如視覺顯示粗糙表面但觸覺回饋異常平滑時，模型可能難以正確權衡兩種模態。此外，若觸覺訓練資料中某些材質樣本過少，休眠子空間可能學到偏頗的對齊，導致對新穎或視覺模糊材質的判斷錯誤。圖 1 也顯示，若未使用遮罩引導對齊，模型會迅速遺忘原本可靠的視覺描述能力，這正是 Splash 試圖避免的典型失敗模式。

**Q15：未來研究可以朝哪些方向延伸 Splash 的框架？**
A：未來可將 Splash 擴展到主動觸摸與時間序列觸覺資料，讓機器人能根據初步觸覺回饋決定下一步觸摸位置與力道。也可以結合聽覺、本體感覺或溫度等更多感官模態，並為每種模態設計專屬的休眠子空間分配策略。此外，動態調整遮罩、在持續學習過程中自動更新關鍵與休眠參數，以及將方法驗證於真實機器人操作任務，都是值得深入探索的方向。

## 實務應用指南

### 適用場景

1. **家庭與服務機器人的材質辨識與安全抓取**  
   機器人在協助清潔、整理或遞送物品時，常需判斷表面是否滑溜、物體是否柔軟易碎。Splash 可在緊湊型 MLLM 中同時利用視覺與觸覺，推論「這個杯子表面濕滑，應降低夾持力」，避免僅靠視覺誤判。

2. **工業組裝與品質檢測**  
   在產線上判斷墊圈柔順性、螺絲鎖緊狀態或零件表面粗糙度時，視覺往往難以辨識細微接觸特性。透過觸覺對齊，機器人可進行開放詞彙的語義推理，例如「此密封圈過硬，可能導致洩漏」。

3. **倉儲物流的動態抓取與分類**  
   面對形狀、重量與表面材質各異的包裹或農產品，機器人可結合視覺外觀與觸壓回饋，即時決定抓取策略，減少滑落或壓損風險。

4. **醫療與復健輔助機器人**  
   在評估組織柔軟度、義肢觸覺回饋或物理治療中的按壓力道時，觸覺可提供視覺無法取得的內在材料屬性，並以自然語言向使用者或醫護人員說明狀態。

5. **零售與生鮮分選**  
   透過輕壓水果、麵包或包裝商品，判斷成熟度、新鮮度或包裝完整性，並以低成本邊緣模型部署於店內或產線終端。

### 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **資料** | 成對的視覺—觸覺—語言（VTL）資料，包含影像、觸覺訊號（如壓力分布、形變、震動）與對應語言標註或問答對；需涵蓋目標場景的材質、物體與操作方式。 |
| **運算資源** | 建議至少 1–2 張 A100 或同等 GPU 進行 sMLLM（如 Qwen2.5-VL-3B、InternVL-1B）的微調；推論端可使用 Jetson 等邊緣運算平台。 |
| **技術能力** | 熟悉 PyTorch、多模態大型語言模型微調流程、觸覺感測器訊號前處理，以及機器人系統整合（如 ROS 2）。 |
| **硬體** | 觸覺感測器（如 DIGIT、GelSight、BioTac 等）、相機、校正治具、機械手臂或夾爪，以及用於部署的邊緣運算單元。 |
| **評估基準** | 準備 VTL 評測資料（如 SSVTP、TVL、TacQuad）與一般視覺—語言能力評測，以驗證觸覺對齊後是否保留通用能力。 |

---

### 實作步驟建議

1. **定義任務並選擇基礎模型**  
   根據延遲與記憶體限制，選擇合適的 sMLLM（如 Qwen2.5-VL-3B 或 InternVL-1B）。明確觸覺推理任務：材質分類、滑動偵測、柔順性估計或開放式問答。

2. **建立觸覺前端（Tactile Front-end）**  
   設計輕量編碼器或投影層，將原始觸覺訊號轉換為可與視覺特徵對齊的 token 或嵌入。此部分為 Splash 中唯一新增的模組，LLM 本體不增加推論開銷。

3. **計算參數重要性遮罩**  
   使用論文提出的 VL-relative 指標，基於預訓練權重與視覺—語言任務的活化統計，將 LLM 參數劃分為「關鍵子空間」（critical subspace）與「休眠子空間」（dormant subspace）。

4. **執行單階段遮罩隔離訓練**  
   凍結關鍵子空間以保護既有視覺—語言知識，僅在休眠子空間上更新梯度，讓模型內化觸覺對齊。同時訓練觸覺前端，無需額外的多階段對齊與微調流程。

5. **驗證觸覺能力與通用能力保留**  
   在 SSVTP、TVL、TacQuad 等 VTL 基準測試觸覺推理表現；同時在一般視覺—語言基準測試檢查是否發生災難性遺忘。

6. **邊緣部署與持續監控**  
   將模型量化、編譯（如 ONNX、TensorRT、vLLM）後部署於邊緣裝置。建立線上監控機制，追蹤觸覺感測器漂移與模型輸出一致性，必要時進行小規模持續更新。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **災難性遺忘** | 若遮罩劃分不準，觸覺訓練可能破壞原有視覺—語言能力。 | 嚴格驗證關鍵子空間的重要性指標，並在訓練後進行完整 VL 能力評測。 |
| **感測器跨模態對齊誤差** | 觸覺訊號與視覺畫面在時間與空間上未對齊，會降低對齊品質。 | 建立精確的校正流程與資料同步機制，必要時加入時間戳對齊與空間標定。 |
| **領域落差** | 實驗室訓練資料與真實場景的材質、感測器特性不同。 | 收集目標場景資料進行領域適應，並使用資料增強提升泛化性。 |
| **小樣本過擬合** | 觸覺資料收集成本高，資料量可能不足。 | 採用正則化、早停、遷移學習，或利用合成資料補充。 |
| **推論延遲與安全** | 觸覺前端與機器人控制迴路可能增加延遲，物理接觸亦有安全風險。 | 設定最大接觸力與反應時間上限，將觸覺推理與低階安全控制器分離。 |

### 與其他技術的整合建議

- **機器人作業系統（ROS 2）**  
  將視覺與觸覺感測器訊號以 ROS 2 topic 發布，Splash 模型作為一個 inference node 訂閱資料並輸出語言推理結果，供下游規劃器使用。

- **現有視覺管線**  
  保留原有視覺偵測與分割模組作為備援；當觸覺訊號缺失或品質不佳時，可退回純視覺模式，提升系統魯棒性。

- **機器人控制迴路**  
  將 Splash 的材質／滑動推理結果轉換為夾爪力控或阻抗控制參數，形成「感知—推理—控制」閉迴路，例如偵測到滑動時自動增加夾持力。

- **LLM 代理規劃器**  
  將 Splash 的觸覺描述作為 high-level LLM agent 的觀察輸入，讓機器人執行更複雜的具身決策，如「這個表面太滑，先換個抓取點」。

- **邊緣推論框架**  
  使用 ONNX Runtime、TensorRT 或 vLLM 進行量化與加速，確保在資源受限的邊緣機器人上達到即時推論。

- **資料日誌與持續學習**  
  記錄現場操作中的觸覺—視覺—語言三元組，作為未來持續更新或擴充模態的資料來源，但更新時仍需使用遮罩隔離策略以避免遺忘。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先聚焦論文的動機與圖 1：為什麼觸覺對機器人很重要？為什麼小型 MLLM 加入觸覺後會遺忘視覺能力？理解「零和權衡」與 Splash 的核心概念——只更新不重要參數、保護重要參數——即可建立直覺，暫時不需要深入數學細節。

- **AI 工程師**  
  請重點閱讀第 3 節的實作方法，特別是參數重要性遮罩的計算方式、關鍵子空間與休眠子空間的劃分、單階段聯合訓練流程，以及觸覺前端的設計。這些內容直接影響微調腳本、超參數選擇與部署時的推論開銷。

- **研究人員**  
  建議關注論文的貢獻定位與相關工作：Splash 如何將「剪枝式多任務學習」從任務層級延伸到模態層級？其與持續學習、參數高效微調的異同為何？同時請檢視實驗設計、基準選擇與限制，思考未來可擴展至多觸覺感測器、多機器人平台或更複雜物理推理的方向。

- **產品經理**  
  請將重點放在價值主張與部署條件：Splash 讓小型邊緣模型具備觸覺推理能力，同時不犧牲原有視覺—語言能力，且 LLM 部分無額外推論開銷。評估時需同時考量資料收集成本、感測器硬體投資、邊緣運算資源、安全規範，以及與現有機器人軟體棧的整合難度。
