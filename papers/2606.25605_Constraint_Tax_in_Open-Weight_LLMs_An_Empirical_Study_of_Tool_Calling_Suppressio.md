## 摘要翻譯

工具呼叫（Tool Calling）與結構化輸出（Structured Output）是現代智慧體系統（Agent systems）的兩項核心能力，然而兩者在聯合部署（joint deployment）條件下的交互作用仍缺乏充分理解。本文報告了一個在生產環境智慧體系統（production Agent systems）中觀察到的可復現現象：當工具呼叫與 JSON Schema 限制（JSON Schema constraints）同時啟用時，多個開放權重模型（open-weight models）儘管維持高結構描述合規性（schema compliance），卻停止調用工具。我們將此行為稱為工具抑制（Tool Suppression）。透過在多個模型家族與部署設定下進行的控制實驗（controlled experiments），我們在同時限制（simultaneous constraints）下一致地復現了工具抑制，而工具執行（tool execution）與結構描述合規性在獨立評估時仍保持正常運作。進一步分析顯示，JSON Schema 限制會被編譯為基於語法的詞元遮罩（grammar-based token masks），導致工具呼叫詞元（tool-call tokens）在解碼（decoding）過程中變為不可達（unreachable）。這為觀察到的行為提供了實作層級解釋（implementation-level explanation）。為了詮釋此現象，我們提出了限制優先順序反轉（Constraint Priority Inversion, CPI）假說，該假說認為在多項同時限制下，結構描述滿足度（schema satisfaction）可能主導動作選擇行為（action-selection behavior）。我們將 CPI 視為一個與觀察證據一致的行為假說（behavioral hypothesis），而非已驗證的內部機制（internal mechanism）。為了緩解此問題，我們提出了透明雙階段執行（Transparent Two-Pass Execution），這是一種推論階段策略（inference-time strategy），可將工具執行與受結構描述限制的回應生成解耦。實驗結果顯示，此方法能恢復工具調用（tool invocation），同時保留結構化輸出的保證，且無需模型重新訓練（model retraining）。這些發現顯示，單獨評估工具使用與結構化輸出可能會忽略生產環境智慧體系統中的重要可靠性問題（reliability issues）。程式碼、資料與技術文件將釋出於 https://github.com/Fzsama/Constrain-Tax-26-06.git。

### 核心貢獻（3～5點）
- 發現並系統性復現「工具抑制（Tool Suppression）」現象：在聯合部署（joint deployment）工具呼叫

## 深度分析

#### 方法論解析

本文的核心方法論圍繞著 **Tool Suppression（工具抑制）** 現象的識別、根因定位、行為假說建立，以及推論階段緩解策略的設計，形成一條從現象觀察到實作層級解釋再到系統層級修正的完整研究鏈。

首先，作者透過在 **production Agent system（生產環境智慧體系統）** 中進行 **controlled experiments（控制實驗）**，系統性地比較 **Tool Calling（工具呼叫）** 與 **Structured Output（結構化輸出）** 在獨立評估與 **joint deployment（聯合部署）** 下的行為差異。實驗設計的關鍵在於隔離變因：當 **JSON Schema constraints（JSON Schema 限制）** 與工具定義同時存在時，觀察模型是否仍會執行 **tool invocation（工具調用）**。結果顯示，多個 **open-weight models（開放權重模型）** 家族在聯合條件下會停止產生 **tool-call tokens（工具呼叫詞元）**，但維持高 **schema compliance（結構描述合規性）**。

為定位根因，作者進行 **inference stack tracing（推論堆疊追蹤）**，發現 JSON Schema constraints 在底層被編譯為 **grammar-based token masks（基於語法的詞元遮罩）**。這些遮罩在 **decoding（解碼）** 階段強制限制下一個合法詞元的集合，卻同時使代表工具呼叫的特定詞元成為 **unreachable tokens（不可達詞元）**。這提供了具體的 **implementation-level explanation（實作層級解釋）**：問題並非出於模型權重或 **model preference（模型偏好）**，而是 **decoding-level constraint enforcement（解碼層級限制強制執行）** 的副作用。

在行為解釋層面，作者提出 **Constraint Priority Inversion (CPI)（限制優先順序反轉）** 假說。CPI 認為，在 **simultaneous constraints（同時限制）** 作用下，**schema satisfaction（結構描述滿足度）** 可能主導了 **action-selection behavior（動作選擇行為）**，導致模型為了滿足結構限制而繞過 **external actions（外部動作）**。作者明確將 CPI 定位為 **behavioral hypothesis（行為假說）**，而非經驗證的 **internal mechanism（內部機制）**，這體現了方法論上的嚴謹性。

針對緩解，本文提出 **Transparent Two-Pass Execution（透明雙階段執行）**，這是一種 **inference-time strategy（推論階段策略）**。該方法將原本單一階段的生成流程解耦為兩個階段：第一階段在無 schema constraints 的條件下進行 **tool execution（工具執行）**，使模型能自由產生工具呼叫；待取得 **retrieved information（檢索資訊）** 後，第二階段再將外部資料納入上下文，進行 **schema-constrained response generation（受結構描述限制的回應生成）**。此策略的「透明性」在於對 **downstream parsing（下游解析）**、**workflow automation（工作流程自動化）** 與 **API integration（API 整合）** 保持無縫相容，無需 **model retraining（模型重新訓練）**。

最後，作者建立 **Tool Suppression behavioral taxonomy（工具抑制行為分類法）**，將觀察到的壓抑模式歸納為 TS-A 至 TS-E 五類，提供一個描述性框架以比較不同模型與部署設定下的抑制行為特徵。

#### 實驗數據解讀

雖然提供的全文未包含完整量化表格，但從摘要與引言的實驗敘述中，仍可解讀出幾項關鍵的實證發現與其方法論意涵。

第一項核心發現是條件依賴的行為不一致性：當 Tool Calling 與 Structured Output 被分開評估時，兩項能力各自運作正常；然而一旦進入 joint deployment，**tool execution（工具執行）** 行為便會消失。這項對照實驗的設計排除了模型權重、提示詞（prompts）、工具定義與任務需求等混淆變因，唯一差異僅在於 JSON Schema constraints 的有無。這強烈暗示了現象並非源於模型本身的「弱工具學習」傾向，而是系統層級的限制互動所致。

第二項關鍵證據來自 **inference stack tracing（推論堆疊追蹤）**。作者透過追蹤推論堆疊，證實 JSON Schema 被編譯為 grammar-based token masks，導致 tool-call tokens 在解碼過程中被遮罩為 unreachable。這項發現將現象從行為層面下沉至實作層面，說明了 **output layer（輸出層）** 的 token 可達性才是決定工具是否被呼叫的關鍵閘門。換言之，模型可能「意圖」呼叫工具（從上下文與任務需求判斷），但解碼層的語法限制使其在物理上無法輸出對應詞元。

第三項實證結果驗證了 Transparent Two-Pass Execution 的有效性。實驗顯示，該策略能夠 **restore tool invocation（恢復工具調用）**，同時 **preserving structured output guarantees（保留結構化輸出保證）**。這代表雙階段解耦並未犧牲格式合規性來換取工具執行能力，而是同時滿足兩項原本互斥的約束條件。這對 **reliability issues（可靠性問題）** 的緩解具有直接工程價值。

第四項貢獻在於 **Tool Suppression behavioral taxonomy（工具抑制行為分類法）** 的歸納。TS-A 至 TS-E 的分類意味著抑制行為並非單一均質現象，而是存在光譜式的表現差異。這有助於未來研究在不同模型家族間進行系統性比較，並診斷特定部署設定下屬於哪一類抑制模式。

整體而言，這些實驗結果挑戰了現有評估典範中隱含的「獨立能力可加總」假設，證明在 production Agent systems 中，分開評估 tool use 與 structured generation 可能會掩蓋重要的系統性失效風險。

#### 與現有研究的比較

本文在 **Constraint Tax（限制稅）** 的研究脈絡中開闢了一條新的軸線。現有的 Constraint Tax 研究主要聚焦於 **text-generation tasks（文字生成任務）**，探討 Structured Output 限制對 **answer quality（答案品質）**、**factual accuracy（事實準確性）** 與 **token usage（詞元使用量）** 的負面影響。這些研究將限制視為對生成品質的「稅賦」，但本質上仍將模型視為被動的文字產生者。

相較之下，本文將研究場景轉移到 **Agent systems（智慧體系統）**，其中模型必須進行 **action-selection behavior（動作選擇行為）**，決定是否執行 **external actions（外部動作）**。這是一個本質上不同的執行設定：限制不再僅影響輸出「形式」，而是滲透到「決策過程」本身。因此，本文觀察到的 Tool Suppression 並非傳統 Constraint Tax 中品質下降的漸進式衰減，而是一種能力開關式的斷裂性失效（工具執行完全消失）。

在方法論上，現有研究多將 **tool use**、**structured generation** 與 **task completion** 分開評估，隱含假設獨立運作良好的能力在聯合部署時仍能正確運作。本文透過 controlled experiments 明確反駁此假設，並進一步提供 **implementation-level explanation（實作層級解釋）**，這在過往的 Agent 評估文獻中較為少見。多數既有研究停留在現象描述或模型行為層面的分析，較少深入 **decoding-level constraint enforcement（解碼層級限制強制執行）** 的技術細節。

本文提出的 Transparent Two-Pass Execution 與現有緩解方案相比，優勢在於其為 **inference-time strategy（推論階段策略）**，無需 **model retraining（模型重新訓練）**，這在生產環境中具備極高的部署彈性。相較於試圖透過微調或提示工程（prompt engineering）讓模型「學會」在限制下呼叫工具，本文選擇從系統架構層面解耦衝突來源，這是一種更為根本的工程解決方案。

然而，本文也存在可預期的限制。首先，**Constraint Priority Inversion (CPI)（限制優先順序反轉）** 被明確定位為 **behavioral hypothesis（行為假說）**，而非經驗證的 **internal mechanism（內部機制）**。這意味著現階段仍無法確定模型內部是否真正發生了「優先順序」的認知層級反轉，抑或僅是解碼遮罩的機械性後果。其次，研究對象限於 **open-weight models（開放權重模型）**，對於封閉式商業模型（如 GPT-4o、Claude 系列）的推論堆疊是否會產生相同現象，仍有待外部驗證。此外，現象的觀察與根因定位高度依賴特定的 grammar-based token masking 實作，若其他推論引擎採用不同的 JSON Schema 編譯方式，Tool Suppression 的嚴重程度可能有所差異。

#### 可重現性評估

本文在可重現性方面的承諾相當明確。作者宣告將釋出 **code（程式碼）**、**data（資料）** 與 **docs（文件）** 於公開儲存庫（https://github.com/Fzsama/Constrain-Tax-26-06.git）。這對於驗證 Tool Suppression 現象至關重要，因為該現象涉及 **inference stack（推論堆疊）** 層級的互動，單純依靠論文敘述難以完整重現。

研究採用 **open-weight models（開放權重模型）** 進行實驗，這些模型的權重通常公開可下載（如 Llama、Qwen、Mistral 等家族），降低了外部研究者復現的硬體與授權門檻。由於現象是在 **multiple model families and deployment settings（多個模型家族與部署設定）** 中一致重現，這暗示了實驗設計具備一定的跨模型泛化性，而非單一模型的特異行為。

不過，要達成完全的可重現性，仍需觀察釋出內容是否包含以下關鍵元件：第一，能夠編譯 JSON Schema constraints 為 **grammar-based token masks（基於語法的詞元遮罩）** 的推論框架程式碼（例如基於 Outlines、lm-format-enforcer 或 vLLM 的 constrained decoding 實作）；第二，用於 **inference stack tracing（推論堆疊追蹤）** 的中介層日誌或修改版本，以驗證 tool-call tokens 確實被標記為 unreachable；第三，完整的 **Tool Suppression behavioral taxonomy（工具抑制行為分類法）** 評估腳本與對應的 **schema-compliant response（符合結構描述的回應）** 判定邏輯。

若儲存庫僅包含高層次的實驗腳本而缺少底層遮罩邏輯的追蹤細節，則其他研究者可能只能復現現象本身，而難以驗證作者提出的 grammar-based token masking 根因解釋。此外，由於論文提及現象來自 **production Agent system（生產環境智慧體系統）** 的觀察，釋出的資料是否包含去識別化後的真實生產案例，或是僅使用合成基準（synthetic benchmarks），也會影響可重現性的生態效度（ecological validity）。

#### 未來研究方向

本文的發現為多個後續研究領域開啟了明確的切入點。

首先，**Constraint Priority Inversion (CPI)（限制優先順序反轉）** 假說需要更嚴格的驗證。未來研究可透過 **mechanistic interpretability（機制可解釋性）** 方法，例如探測模型內部啟動值（activations）或利用因果中介分析（causal mediation analysis），檢驗 schema satisfaction 與 action selection 在模型內部是否存在優先順序競爭。若 CPI 能被證實為 **internal mechanism（內部機制）** 而非僅是行為描述，將有助於設計更精準的訓練或對齊策略。

其次，研究範圍可從現有的 open-weight models 擴展至封閉式商業模型與多模態 **Agent systems（智慧體系統）**。若類似的 Tool Suppression 現象也存在於專有模型的推論 API 中，則意味著此問題具有跨生態系的普遍性，並可能影響 **multi-Agent coordination（多智慧體協調）** 與複雜 **workflow automation（工作流程自動化）** 的可靠性。

第三，在系統層級，未來可探索統一的 **constraint compilation（限制編譯）** 框架，使 **JSON Schema constraints（JSON Schema 限制）** 與 **tool-call tokens（工具呼叫詞元）** 在 **decoding（解碼）** 階段不再互斥。這可能涉及開發新的文法表示法，允許工具呼叫與結構化欄位在 token 層級共存，而非簡單地將兩者解耦為不同執行階段。

第四，**Tool Suppression behavioral taxonomy（工具抑制行為分類法）** 可進一步擴充與自動化。未來可建立自動化診斷工具，在部署前偵測特定模型與 schema 組合是否會觸發 TS-A 至 TS-E 中的某一類抑制模式，作為 **production Agent systems（生產環境智慧體系統）** 的上線前健康檢查機制。

最後，從 **training-time（訓練階段）** 角度解決此問題亦值得探索。例如，透過 joint fine-tuning（聯合微調）讓模型學習在維持 **schema compliance（結構描述合規性）** 的同時，於解碼早期即規劃 **tool invocation（工具調用）**，或設計特殊的詞元編碼方式使工具呼叫在 grammar-based masking 下仍保持可達。這將從根本上消除對 Transparent Two-Pass Execution 這類推論階段繞道策略的依賴，實現真正的單階段聯合生成。

## 論文問答

**Q1：什麼是「工具抑制」（Tool Suppression），它在何種部署條件下會發生？**
A：「工具抑制」是指當工具呼叫與 JSON Schema 限制同時啟用時，開放權重模型雖然能產生高度符合結構描述的回應，卻停止呼叫外部工具的現象。這種情況發生在聯合部署條件下，即使任務明確需要取得外部資訊，智慧體仍會在滿足結構化輸出要求的同時，完全繞過工具執行步驟。本文將此行為定義為一種在生產環境智慧體系統中可重現的失效模式，其特徵是模型優先達成格式合規性，卻犧牲了行動導向智慧體應有的外部動作能力。

**Q2：為何現有的評估方法無法發現工具抑制問題？**
A：現有的評估通常將工具使用、結構化生成與任務完成度分開檢驗，隱含地假設在隔離環境中運作正常的能力，在聯合部署時也會繼續正常運作。然而，這種分開評估的典範忽略了在解碼層級上，多項同時限制可能產生的交互作用，例如基於語法的詞元遮罩會使工具呼叫詞元變成不可達詞元。因此，生產環境中潛藏的可靠性問題——特別是結構化限制對動作選擇行為的影響——在單獨測試時無法被揭露，直到實際上線後才會浮現。

**Q3：為何研究工具呼叫與結構化輸出的交互作用對生產環境智慧體系統至關重要？**
A：現代生產環境智慧體系統的執行管線越來越常同時啟用工具呼叫與結構化輸出，例如智慧體必須先透過外部工具檢索資訊，再將結果整理成符合 JSON Schema 的回應以供下游解析。結構化輸出限制並非計算中性，它們不僅影響輸出形式，更可能透過解碼層級限制強制執行來干預執行過程本身。若這些限制壓抑了工具調用，智慧體將無法完成需要即時資訊獲取的任務，導致工作流程自動化與多智慧體協調中出現沉默式失效。

**Q4：作者採用什麼樣的實驗方法來調查工具抑制現象？**
A：作者在多個開放權重模型家族與不同部署設定下進行控制實驗，以系統性地重現工具抑制現象。他們結合生產環境系統觀察與推論堆疊追蹤，從實作層級定位根本原因，例如檢視 JSON Schema 限制如何被編譯為基於語法的詞元遮罩。透過在保持模型權重、提示詞與工具定義不變的前提下，單獨操縱結構化限制的啟用與否，研究人員得以精確隔離聯合限制所導致的行為變異。

**Q5：什麼是「透明雙階段執行」（Transparent Two-Pass Execution），它如何緩解工具抑制？**
A：透明雙階段執行是一種推論階段策略，它將工具執行與結構描述受限的回應生成解耦為兩個獨立階段。在第一階段，模型在沒有 JSON Schema 限制的情況下進行工具呼叫以取得外部資訊；第二階段則利用檢索到的資訊，在結構化限制下生成最終回應。實驗結果顯示，此方法能在無需模型重新訓練的情況下，恢復工具調用行為，同時保留結構化輸出的保證，有效解決了解碼過程中詞元遮罩造成的衝突。

**Q6：為何作者選擇推論階段策略，而非模型重新訓練來解決問題？**
A：由於研究發現工具抑制的根源在於解碼階段的基於語法詞元遮罩，修改推論程序比修改模型參數更能直接且即時地解決問題。模型重新訓練需要耗費大量計算資源與時間，且可能影響模型在其他任務上的通用能力，而推論階段策略則可在現有權重上直接部署。此外，這種設計選擇讓生產環境的開發者能夠透過調整執行協調邏輯，快速導入緩解措施，無需等待新模型訓練完成。

**Q7：實驗涵蓋了哪些模型與部署設定？**
A：實驗橫跨多個開放權重模型家族，並在隔離與聯合限制兩種條件下進行系統性比較。研究人員不僅在受控的實驗室環境中重現現象，也觀察了實際生產環境智慧體系統中的行為，以確保生態效度。透過在相同提示詞、工具定義與任務需求下，僅改變結構化限制的啟用狀態，研究證明了工具抑制並非單一模型特例，而是在多種開放權重模型與部署設定中一致出現的現象。

**Q8：關於聯合限制下的工具調用與結構描述合規性，實驗的主要發現為何？**
A：實驗發現，在聯合部署條件下，多個開放權重模型一致地停止呼叫工具，但同時仍維持高度的結構描述合規性。這顯示工具抑制並非源於模型本質上無法呼叫工具或生成結構化輸出，而是這兩項能力在結合時產生了有害的交互作用。關鍵在於，結構描述滿足度與工具執行並非獨立維度，當解碼層級的限制強制執行過於嚴格時，模型可能優先滿足格式要求，卻完全放棄必要的外部動作。

**Q9：針對工具呼叫詞元不可達的現象，作者找到了什麼實作層級的解釋？**
A：透過對推論堆疊的系統性追蹤，作者發現 JSON Schema 限制會被編譯成基於語法的詞元遮罩，並在解碼過程中即時套用。這些遮罩透過限制下一個合法詞元的集合來強制結構描述合規性，卻也意外使得代表工具呼叫動作的特定詞元在解碼圖中變成不可達詞元。這提供了具體的實作層級解釋：約束機制在模型尚未表達行動意圖之前，就從物理上阻斷了工具呼叫序列的生成路徑。

**Q10：工具抑制在哪些典型的生產工作流程中風險最高？**
A：工具抑制在需要智慧體先透過外部工具取得即時或專屬資訊，再將結果格式化輸出的工作流程中風險最高。例如，在企業工作流程自動化、API 整合或多智慧體協調場景中，系統常要求智慧體查詢資料庫或搜尋引擎，然後以嚴格的 JSON Schema 回傳結果供下游解析。一旦發生抑制，智慧體將僅依賴參數化知識生成格式正確但內容空洞的回應，導致後續自動化步驟基於錯誤或過時資訊運作。

**Q11：這項研究對同時啟用兩項能力的智慧體系統開發者有何實務啟示？**
A：這項研究提醒開發者，同時啟用工具呼叫與結構化輸出並非瑣碎的設定組合，而是必須在完整執行管線中進行聯合評估的關鍵決策。產品團隊不應假設單獨驗證過的能力在組合後仍能安全運作，必須特別測試解碼限制與動作選擇之間的交互效應。在實務上，導入透明雙階段執行等推論階段策略，或在設計 JSON Schema 時預留工具呼叫詞元的生成路徑，應成為生產部署的標準實踐。

**Q12：這項研究如何改變學術界評估工具呼叫與結構化輸出的方式？**
A：這項研究挑戰了學術界長期將工具使用與結構化輸出視為獨立能力進行基準測試的做法，揭露了這種評估方式可能掩蓋關鍵的可靠性問題。研究建議必須發展新的評估協定，在聯合部署條件下明確測試行動執行是否能在格式限制下持續運作。透過將「限制稅」的概念從純文字生成任務擴展到行動導向智慧體領域，本文促使學界將結構化輸出研究從單純的格式合規性，轉向關注執行完整性與動作選擇行為的保全。

**Q13：「限制優先順序反轉」（CPI）假說在本研究中的定位為何？**
A：「限制優先順序反轉」（CPI）假說被作者定位為一種與觀察證據一致的行為假說，而非經過驗證的內部機制。作者謹慎地將 CPI 作為解釋框架，用以說明當多項同時限制存在時，結構描述滿足度為何似乎會主導動作選擇行為，但他們並未宣稱已透過直接的機制驗證證明此假說。這項定位承認了本研究的限制：雖然已在實作層面找到詞元遮罩的阻斷機制，但模型在高層次行為上是否真正發生「優先順序反轉」，仍有待更深入的機械可解釋性研究加以確認。

**Q14：工具抑制行為分類法（TS-A 至 TS-E）揭示了哪些關於此現象的訊息？**
A：工具抑制行為分類法將在不同模型與部署設定中反覆出現的抑制模式歸納為 TS-A 至 TS-E 等類別，顯示此現象並非單一均質的失效模式。這些分類可能涵蓋從完全省略工具呼叫，到部分或畸形調用後被結構化限制遮罩過濾等多種變異形式。透過將這些模式形式化，該分類法提供了一個描述性框架，幫助實務工作者診斷自身系統中的特定失效模式，並理解抑制行為會依據模型架構與限制強度而呈現不同樣貌。

**Q15：這項工作為未來提升受限智慧體系統可靠性的研究指出了哪些方向？**
A：未來研究應探討除了 JSON Schema 之外，其他類型的限制——例如正規表示式或上下文無關語法限制——是否也會對工具呼叫產生類似的抑制效應，並將分析擴展至封閉權重商業模型。另一個重要方向是開發能夠在偵測到行動詞元對任務完成屬必要時，動態放鬆詞元遮罩的自適應解碼演算法，而非全程靜態強制結構描述。此外，透過機械可解釋性研究來驗證或反駁 CPI 假說，將有助於深化我們對大型語言模型如何在表徵層級權衡競爭目標的理解。

## 實務應用指南

### 適用場景

1. **企業內部知識檢索 Agent**：智慧體需先呼叫向量資料庫或企業搜尋工具取得文件片段，再將結果整理為符合內部 API 規格的 JSON Schema（如包含 `source_id`、`relevance_score` 欄位），供下游工作流程自動化系統解析。
2. **電商訂單處理 Agent**：模型需即時呼叫庫存查詢與物流估算工具，並將工具回傳資訊填入結構化訂單確認格式（JSON Schema），確保多智慧體協調場景中下游金流系統能正確讀取。
3. **金融風控報告生成**：透過工具呼叫取得即時市場數據與新聞摘要，再輸出符合監管要求的結構化報告（如特定欄位的 JSON Schema），此時若發生工具抑制，模型將直接以參數化知識生成過時數據，導致合規風險。
4. **醫療診斷輔助系統**：呼叫外部醫學資料庫或檢驗工具後，必須輸出結構化病歷摘要（JSON Schema）供醫院資訊系統匯入，聯合部署時工具呼叫消失將直接影響病人安全與資料完整性。
5. **多智慧體協作平台**：上游 Agent 執行工具後，需將結果以標準化結構描述傳遞給下游 Agent，若工具執行行為被結構化限制壓抑，將導致整個執行管線中斷或產生幻覺資料。

### 實作前置條件

**資料需求**：
- 完整的工具定義（Function Schemas）與對應的 JSON Schema 限制文件
- 涵蓋「必須呼叫工具」與「無需呼叫工具」兩類情境的對照測試案例集
- 生產環境日誌（用於復現 Tool Suppression 模式）

**運算資源**：
- 可本地部署的開放權重大型語言模型（如 Llama、Qwen、Mistral 系列）
- 支援 grammar-based constrained decoding 的推理框架（如 vLLM、SGLang、TGI、llama.cpp）
- 足夠的 GPU/CPU 記憶體以承載雙階段執行帶來的額外推理負載

**技能需求**：
- 熟悉 JSON Schema 設計與 OpenAI 相容工具呼叫 API 格式
- 具備推理堆疊追蹤與除錯能力，能檢視 token mask 與解碼層級行為
- 能修改中介層或 Agent 執行器（AgentExecutor）邏輯，實作推論階段策略

### 實作步驟建議

**步驟一：現況診斷與復現**
在現有系統中設計控制實驗：A 組僅啟用 Tool Calling，B 組僅啟用 Structured Output，C 組聯合部署。比較三組的工具調用成功率與結構描述合規性，確認是否出現工具抑制（Tool Suppression）現象。

**步驟二：根因定位**
追蹤推理框架的解碼層級，檢查 JSON Schema 限制是否被編譯為 grammar-based token masks，並確認工具呼叫詞元（tool-call tokens）在聯合限制下是否成為不可達詞元（unreachable tokens）。

**步驟三：導入透明雙階段執行（Transparent Two-Pass Execution）**
- **第一階段（行動選擇）**：關閉 JSON Schema 限制，僅保留 Tool Calling 能力，讓模型自由決定是否觸發外部動作。若產生工具呼叫，立即執行並取得外部資訊。
- **第二階段（結構化生成）**：將工具執行結果注入對話上下文，啟用 JSON Schema 限制，生成符合結構描述的回應。此階段不允許再次觸發工具，以確保結構滿足度。

**步驟四：驗證與評估**
建立回歸測試，量化比較單階段與雙階段策略在工具呼叫成功率、Schema 合規率、詞元使用量與端對端延遲的差異，並觀察是否出現 TS-A 至 TS-E 的抑制模式。

**步驟五：部署與監控**
上線後持續監控兩階段之間的狀態轉換，設定工具呼叫缺失告警，並定期抽樣檢查第一階段是否發生錯誤拒絕（錯誤地不呼叫工具）導致第二階段基於過時參數知識生成。

### 潛在風險與注意事項

- **延遲成本**：透明雙階段執行需兩次模型推理，可能顯著增加回應時間，對於即時互動場景需評估是否可接受，或考慮快取與非同步處理。
- **狀態管理複雜度**：兩階段之間的對話歷史、工具回傳結果與系統提示詞需妥善保存與傳遞，避免上下文遺失導致生成品質下降。
- **錯誤傳播風險**：若第一階段模型因幻覺或限制優先順序反轉（CPI）而錯誤拒絕呼叫工具，第二階段將基於錯誤前提產出結構化回應，此風險需透過獨立的工具呼叫驗證器或人工覆核機制來緩解。
- **框架黑箱性**：部分推理框架的 constrained decoding 實作未公開 token mask 細節，可能難以完全確認工具詞元是否被遮罩，建議優先選用可追蹤解碼行為的開源框架。
- **過度補償陷阱**：切勿為了規避抑制而完全放棄結構化輸出限制，否則將導致下游解析失敗，違背生產環境智慧體系統的可靠性要求。

### 與其他技術的整合建議

- **MCP（模型上下文協定）**：若工具層採用 MCP 標準化協定，需在中介層實作 Two-Pass 邏輯，確保第一階段能正確解析 MCP tool call 格式，並在第二階段將工具回傳結果轉換為符合 JSON Schema 的結構化輸出。
- **OpenAI-compatible API 閘道**：若透過相容層封裝對外服務，建議修改路由邏輯，使請求依據 `tool_choice` 與 `response_format` 參數自動分流：先執行無 Schema 限制的工具決策階段，再執行有 Schema 限制的回應生成階段，對上層應用保持透明。
- **現有 Agent 框架（LangChain / LlamaIndex）**：避免直接修改底層模型權重，改在 AgentExecutor 或 AgentRunner 層級透過自訂 Callback 或重寫 `plan` / `action` 方法來實作雙階段執行，降低維護成本。
- **結構化輸出驗證器（Outlines / Instructor）**：第一階段應完全停用此類驗證器，避免過早施加 grammar-based token masks；第二階段再啟用，以確保輸出格式合規性。
- **觀測平台（LangSmith / Arize / Phoenix）**：整合追蹤標記，分別記錄兩階段的詞元分佈、遮罩行為與動作選擇行為，建立工具抑制行為分類學（TS-A 至 TS-E）的自動化標籤，便於後續診斷與模型選型。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先分別理解「工具呼叫」與「JSON Schema」的基本功能，再聚焦第 1.3 節的生產觀察與緩解方案章節，暫時跳過限制優先順序反轉（CPI）假說與語法遮罩的技術細節，重點掌握「同時開啟兩項功能可能導致工具消失」的實務警訊，並學會使用透明雙階段執行來規避問題。

**給 AI 工程師**：需仔細研讀根因分析與推理堆疊追蹤章節，深入理解 JSON Schema 如何被編譯為 grammar-based token masks 並造成不可達詞元。請重點評估自身使用的推理框架（如 vLLM、SGLang）是否需客製化中介層，並參考本文實作透明雙階段執行，確保無需模型重新訓練即可恢復工具調用。

**給研究人員**：建議深入檢視 CPI 假說的實驗設計與工具抑制行為分類學（TS-A 至 TS-E），思考是否可透過修改解碼演算法（例如將工具呼叫詞元設為 grammar 中的可選中斷點）、動態遮罩調整，或訓練階段的多任務學習來根本解決結構描述滿足度與動作選擇之間的衝突，並驗證 CPI 是否為普遍存在的內部機制。

**給產品經理**：重點閱讀生產觀察與適用場景章節，理解此問題對生產環境可靠性的影響，將「結構化輸出與工具呼叫的聯合部署測試」納入上線前檢查清單。同時請評估透明雙階段執行帶來的延遲成本對使用者體驗的影響，並在產品設計中預留對應的效能緩衝與降級策略。
