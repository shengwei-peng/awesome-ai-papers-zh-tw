## ⚡ TL;DR

現有參數化工具檢索基準因查詢過於完整且使用受限解碼，無法揭露模型是否真正理解工具語義。
本文提出ToolSense診斷框架，自動生成真實檢索與事實探測基準，以自由解碼稽核參數化工具知識。
實驗發現知識與檢索嚴重解離：真實查詢表現暴跌50至64個百分點，部分模型事實探測接近隨機水準。

## 摘要翻譯

大型語言模型（Large Language Model, LLM）作為代理（Agent）部署於大型工具目錄（Tool Catalog）時，面臨嚴重的工具檢索瓶頸（tool-retrieval bottleneck）。由於基於嵌入的檢索（Embedding-based Retrieval）方法所依賴的緊湊編碼器（Compact Encoder）可能無法充分捕捉專門的工具語義（Tool Semantics），參數化工具檢索（Parametric Tool Retrieval）透過將每個工具編碼為附加至大型語言模型詞彙表（LLM Vocabulary）的虛擬詞元（Virtual Token）來解決此問題，並將模型分兩階段微調（Fine-tuning）（先記憶化（Memorization），再進行檢索監督式微調（Retrieval SFT）），使其作為檢索器，在標準 ToolBench 檢索基準上達到優異效能。然而，這些基準使用冗長的完整指定查詢（Fully-specified Query），且其評估採用受限解碼（Constrained Decoding），將輸出限制於有效的詞元路徑（Token Path），兩者皆無法揭示模型是否真正理解其工具。我們提出 ToolSense，一個開源（Open-source）且由大型語言模型驅動的診斷框架（Diagnostic Framework），該框架接受任何工具目錄作為輸入，並自動產生三項基準：包含三種歧義層級（Ambiguity Tier）查詢的真實檢索基準（Realistic Retrieval Benchmark, RRB）、選擇題探測基準（MCQ Probing Benchmark），以及問答探測基準（QA Probing Benchmark）。我們將 ToolSense 應用於 ToolBench（約 47,000 個工具），並評估五種參數化模型訓練配置，結果揭示了知識-檢索解離（Knowledge-Retrieval Dissociation）：在 RRB 查詢上，相較於完整指定的 ToolBench 基

## 深度分析

#### 方法論解析

ToolSense 是一個 open-source（開源）的 diagnostic framework（診斷框架），旨在 auditing（稽核） Large Language Models（LLMs, 大型語言模型）中透過 parametric tool retrieval（參數化工具檢索）所習得的 parametric tool knowledge（參數化工具知識）。現行的參數化檢索典範（以 ToolGen 為代表）將每一個工具編碼為一個 virtual token（虛擬詞元），並以 flat atomic identifier（扁平原子識別碼）的形式擴充至 LLM vocabulary（詞彙表），再透過兩階段 fine-tuning（微調）——Stage 1: memorization（記憶化）與 Stage 2: retrieval SFT（檢索監督式微調）——將工具目錄直接內化於模型參數中。然而，標準 ToolBench 評估採用 fully-specified query（完整指定查詢）並搭配 constrained decoding（受限解碼）與 DisjunctiveTrie 限制 beam search（束搜尋）的輸出僅能沿合法 token path（詞元路徑）生成，這使得模型只需學會「在固定 trie 中排序路徑」即可達成高 recall，而無需真正理解工具語義。

為揭露此診斷缺口，ToolSense 接受任意 tool catalog（工具目錄）作為輸入，並自動生成三項診斷基準。第一，Realistic Retrieval Benchmark (RRB)（真實檢索基準）捨棄冗長、完整的查詢，轉而設計三種 ambiguity tier（歧義層級）的 natural language query（自然語言查詢），模擬真實使用者以簡潔、模糊或不完整意圖進行檢索的情境。第二，MCQ probing benchmark（選擇題探測基準）以判別形式測試模型對工具能力（capabilities）的事實知識。第三，QA probing benchmark（問答探測基準）則以推論形式測試模型對工具屬性（properties）的深層理解。此外，作者提出 free-form evaluation protocol（自由形式評估協定），引入 Internalization Score (IS@k)（內化分數），定義為 IS@k = free@k / constrained@k，用以量化模型表現對 trie 結構的依賴程度：若 IS@k 遠低於 1，表示模型在移除 constrained decoding 後檢索能力急遽崩解，暗示其並未真正將工具知識內化為可自由召回的參數化表徵。

整體而言，ToolSense 的設計哲學並非提出新的檢索模型，而是建立一套「壓力測試」機制：透過 RRB 挑戰模型的語義泛化能力，透過 MCQ 與 QA 探測挑戰其知識深度，再透過 IS@k 診斷其對外部解碼結構的依賴性。這三個維度共同構成對 parametric tool knowledge 的全面體檢。

#### 實驗數據解讀

本研究將 ToolSense 應用於 ToolBench（約 47k tools），並系統性評估五種 parametric model training configurations（參數化模型訓練配置）。實驗結果揭示了一個核心現象：knowledge-retrieval dissociation（知識-檢索解離）。

在檢索層面，RRB 的實驗結果極具衝擊性：相較於標準 ToolBench 基準，多個配置在真實查詢上的表現崩解達約 50–64 percentage points（百分點），甚至低於 embedding-model baseline（嵌入模型基線）。這表示在 verbose query 與 constrained decoding 的「溫室環境」下所測得的高 recall（如 ToolGen 所宣稱的 ≈0.90）並無法遷移至真實場景；一旦查詢變得簡潔或模糊，parametric retrieval 的優勢便大幅消退，顯示其對查詢分佈的過度擬合以及對 trie 結構的隱性依賴。

更嚴峻的發現來自 factual probe（事實探測）。儘管部分模型在標準檢索指標上表現強勁，其在 MCQ 與 QA 探測上的得分卻接近 random（隨機）水準。這直接證明「高檢索分數」與「擁有工具知識」是兩個可分離的維度：模型可能僅習得了 query-to-token-identifier 的表面映射，而非工具語義（tool semantics）的深層表徵。

進一步分析兩階段訓練的交互作用發現，Stage 2（retrieval SFT, 檢索監督式微調）幾乎普遍破壞了 Stage 1（memorization, 記憶化階段）所習得的工具知識。這是 catastrophic interference（災難性干擾）在參數化檢索場景中的具體例證：模型為了學習「給定查詢生成正確 virtual token」的檢索任務，覆寫了原先在 Stage 1 中建立的「virtual token 與工具 metadata（中繼資料）之間的語義連結」。IS@k 指標進一步量化此現象，顯示模型在 free-form 生成下的能力遠低於 constrained decoding，再次驗證其檢索行為高度依賴外部 trie 結構，而非自主的參數化知識召回。

#### 與現有研究的比較

相較於傳統 embedding-based retrieval（基於嵌入的檢索），過去研究已指出 compact encoder（緊湊編碼器）在處理大規模、語義重疊的 API 時，其 dense vector（稠密向量）可能 underspecify 複雜的工具語義，且需透過 approximate nearest-neighbor search（近似最近鄰搜尋）進行檢索。Parametric tool retrieval 的原始訴求正是為了規避這些瓶頸，將工具目錄直接編碼進 LLM 參數以實現端到端檢索。然而，ToolSense 的診斷結果徹底翻轉了此敘事：參數化方法雖然擺脫了獨立編碼器的限制，卻在真實查詢下暴露出更嚴重的泛化缺陷，甚至輸給 embedding-model baseline。這說明檢索瓶頸（retrieval bottleneck）的本質並非僅在於「使用何種編碼器」，而在於「模型是否真正理解工具語義」。

與 ToolGen 等 parametric retrieval 先驅相比，ToolSense 的貢獻在於填補 diagnostic gap（診斷缺口）。ToolGen 在標準 ToolBench 上達成的高 recall 建立在兩個隱藏條件之上：verbose query 與 constrained decoding。ToolSense 首次系統性證明，這些高數字可能僅反映「在固定 trie 中進行路徑排序」的能力，而非 genuine memorization（真正的記憶化）。這對 downstream agentic fine-tuning（下游代理微調）具有重大警示意義：若代理模型在部署時無法使用 trie（例如需要 free-form 生成工具呼叫），則未經 ToolSense 診斷的 parametric retrieval 模型將成為 silent failure risk（潛在失效風險）。

在探測（probing）文獻脈絡中，Petroni et al. (LAMA) 與 Tenney et al. 主要針對 pre-trained LM 的固有知識或語言結構進行探測。ToolSense 則將此傳統延伸至 fine-tuning 期間才加入的 virtual token（虛擬詞元），探問這些新詞元是否承載語義內容，抑或僅為 task-relevant pointers（任務相關指標）。此舉開創了針對「動態擴充詞表」之表徵品質的診斷範式。

至於知識保留（knowledge retention）研究，McCloskey & Cohen 提出的災難性干擾、Hu et al. 以 LoRA 凍結 backbone weights 的策略，以及 Biderman et al. 對 full fine-tuning 與 LoRA 的比較，均聚焦於一般任務序列學習。本文則將此議題帶入 parametric retrieval 的獨特兩階段訓練，明確指出 Stage 2 retrieval SFT 對 Stage 1 知識的破壞性，為未來的訓練策略改良提供實證基礎。

本研究的主要限制在於其診斷範圍目前僅聚焦 retrieval stage，尚未直接連結至 multi-step agent loop（多步代理迴圈）中的 task success；此外，實證僅基於 ToolBench，雖然框架宣稱通用，但跨領域 tool catalog 的泛化性仍需更多驗證。

#### 可重現性評估

ToolSense 在可重現性方面採取積極的開源策略：framework（框架）本身以及針對 ToolBench 生成的 RRB、MCQ、QA 三項 diagnostic benchmarks（診斷基準）均已於 GitHub（https://github.com/SAP/toolsense）公開釋出。由於框架採用 LLM-powered 的自動化生成流程，研究者僅需提供符合格式的 tool catalog（工具目錄），即可復現完整的診斷資料建構流程，大幅降低人工設計探測題目的成本與主觀偏差。

在方法論層面，IS@k 的計算公式（free@k / constrained@k）與 free-form evaluation protocol（自由形式評估協定）均有明確定義，使不同研究團隊能在統一標準下比較各類 parametric retrieval 模型的 trie-dependency（trie 依賴度）。實驗所使用的 ToolBench 資料集亦為公開資源，確保資料層面的可及性。

然而，可重現性仍存在若干缺口。論文雖詳細描述五種訓練配置，但並未明確說明這些模型的 model weights（模型權重）與完整 training scripts（訓練腳本）是否一併釋出。Parametric retrieval 的訓練涉及大規模微調與 virtual token 的詞表擴充，若僅釋出評估基準而無模型檢查點（checkpoints），其他研究者將難以直接復現論文中「50–64 百分點崩解」的絕對數值，僅能對自有模型進行相對診斷。此外，由於生成 RRB 與探測題目依賴 LLM（可能涉及特定版本與 prompt 設計），未來若能釋出確切的 prompt template 與 generation seed，將進一步提升結果的嚴格可重現性。

#### 未來研究方向

首先，在訓練策略層面，如何緩解 Stage 1 memorization（記憶化）與 Stage 2 retrieval SFT（檢索監督式微調）之間的 catastrophic interference（災難性干擾）是當務之急。未來研究可探索彈性學習率調度、經驗回放（replay mechanism）或針對 virtual token（虛擬詞元）的 regularization-based approaches（正則化方法），以確保檢索能力上升時不犧牲事實知識。此外，系統性導入 LoRA 等 parameter-efficient fine-tuning（參數高效微調）技術，凍結部分 backbone weights 以保留 Stage 1 的語義表徵，亦是極具潛力的方向。

其次，在評估協定擴展方面，ToolSense 目前設計了三種固定的 ambiguity tier（歧義層級），未來可發展 dynamic ambiguity generation（動態歧義生成）機制，依據模型能力自動調整 RRB 的查詢難度，形成適性化的診斷流程。同時，將此框架應用於 ToolBench 以外更大規模或垂直領域的 tool catalog（工具目錄），驗證其泛化性與診斷靈敏度，亦是必要的後續工作。

第三，在與下游任務的連結上，當前診斷僅限於 retrieval stage，未來應建立 retrieval quality（檢索品質）與 downstream agentic task performance（下游代理任務表現）之間的因果橋樑。特別是在 multi-step agent loop（多步代理迴圈）中，檢索錯誤的累積效應可能遠大於單步檢索指標所暗示的影響。此外，探索 retriever 與 generator 的 joint optimization（聯合最佳化），使工具語義的學習目標與最終任務成功率對齊，或許能從根本上緩解知識-檢索解離。

第四，在模型架構創新方面，可設計具備顯式知識隔離機制的 virtual token 學習方法，例如為每個工具配置 dual-token（一個負責語義記憶、一個負責檢索對應），或採用混合式架構結合 embedding-based retrieval（基於嵌入的檢索）與 parametric retrieval（參數化檢索），讓兩者互補而非互斥。

最後，在解釋性研究上，未來可深入分析 virtual token 在 fine-tuning 前後的 representation geometry（表徵幾何），理解 Stage 2 訓練如何以及為何破壞 Stage 1 建立的語義結構。建立更細緻的 probing tasks（探測任務），區分語法層級、語義層級與語用層級的工具知識，將有助於精確定位參數化工具知識的薄弱環節，並指導下一代工具增強型 LLM 的設計。

## 論文問答

**Q1：大型語言模型作為代理面對大規模工具目錄時，其核心瓶頸為何？**
A：當大型語言模型被部署為代理並需從龐大工具目錄中選擇正確工具時，其核心瓶頸在於工具檢索的準確性與效率。傳統的基於嵌入的檢索方法依賴緊湊編碼器將工具描述壓縮為稠密向量，但這類編碼器往往難以充分捕捉專業化且語義高度重疊的應用程式介面特性，導致檢索品質下降。此外，檢索到的工具描述還必須注入模型上下文，在多步代理迴圈中造成額外的計算與記憶體開銷，進一步限制了整體系統的擴展性與回應速度。

**Q2：現有的標準基準測試（如 ToolBench）與評估方式為何無法真實反映模型對工具的理解程度？**
A：現有標準基準測試使用的查詢通常過於冗長且完整指定，與真實使用者自然、簡潔且時常模糊的提問方式存在巨大落差。更重要的是，評估過程普遍採用受限解碼機制，透過 DisjunctiveTrie 限制模型只能輸出有效的詞元路徑，這使得模型無需真正回憶或理解工具語義，僅需學會在固定的路徑結構中進行排序即可獲得高分。因此，這類評估方式掩蓋了模型可能只是進行表面模式匹配的風險，而無法區分其是否具備真正的參數化工具知識。

**Q3：為何區分「真正的工具知識」與「表面模式匹配」對實際應用至關重要？**
A：在實際的代理系統部署中，下游的代理微調通常需要模型進行自由形式的詞元生成，而無法持續依賴受限解碼或 Trie 結構的輔助。如果模型僅在受限制的評估環境中表現良好，卻未真正內化工具的中繼資料與語義，一旦面對真實使用者以不同方式表述的查詢，系統便可能發生沉默式失效。這種未被檢測出的記憶缺口將直接影響代理任務的成功率與使用者信任，因此診斷模型是否真正理解工具而非僅靠模式匹配，是確保系統可靠性的關鍵前提。

**Q4：ToolSense 框架的核心概念與設計目標是什麼？**
A：ToolSense 是一個開源且由大型語言模型驅動的診斷框架，其設計目標是針對參數化工具檢索系統進行全面的稽核與診斷。該框架接受任意工具目錄作為輸入，並自動生成三種針對性基準測試，以系統性評估模型對工具語義的理解深度。透過結合自由形式生成與探測式評估，ToolSense 能夠揭露傳統受限解碼所隱藏的知識缺陷，從而判斷模型是否真正將工具資訊內化為參數化知識。

**Q5：ToolSense 自動生成的三種基準測試分別是什麼？它們各自診斷哪些能力？**
A：ToolSense 自動生成真實檢索基準（RRB）、選擇題探測基準（MCQ）與問答探測基準（QA）這三種資料集。真實檢索基準包含三個歧義層級的查詢，模擬真實使用者從明確到模糊的提問方式，用以檢驗模型在貼近實務情境下的檢索穩健性；選擇題探測基準測試模型對工具能力的辨識性事實知識，而問答探測基準則進一步評估其對工具屬性的推論性事實知識。這三種基準從不同認知層面切入，共同診斷模型是否具備真正的語義理解，而非僅依賴查詢與詞元識別碼之間的表面對應。

**Q6：什麼是內化分數（IS@k），它在診斷框架中扮演什麼角色？**
A：內化分數（IS@k）定義為自由形式生成命中率（free@k）與受限解碼命中率（constrained@k）的比值，是 ToolSense 提出的關鍵診斷指標。此分數直接衡量模型在缺乏外部 Trie 結構輔助時，能否僅憑自身參數化知識正確召回工具，從而量化其對受限解碼的依賴程度。若 IS@k 顯著低於 1，表示模型的檢索表現高度依賴受限解碼所提供的捷徑，暗示其並未真正內化工具語義，這對於需要自由生成能力的下游代理應用而言是一項重要的預警訊號。

**Q7：將 ToolSense 應用於 ToolBench 後，實驗揭示了哪些關鍵發現？**
A：應用 ToolSense 於包含約四萬七千個工具的 ToolBench 後，實驗揭示了令人矚目的知識—檢索解離現象。具體而言，多個在標準基準上表現優異的參數化訓練配置，在面對真實檢索基準的查詢時，效能竟大幅崩潰約五十至六十四個百分點，甚至低於傳統嵌入模型基線。此外，儘管部分模型在受限解碼下展現強勁的檢索效能，其在事實探測題目上的得分卻接近隨機水準，明確顯示高檢索分數並不等同於真正的工具知識掌握。

**Q8：兩階段訓練（記憶化與檢索監督式微調）對工具知識的影響為何？**
A：實證診斷顯示，負責帶來檢索增益的第二階段訓練（檢索監督式微調）幾乎普遍性地破壞了第一階段（記憶化）所習得的工具知識。這意味著模型在學習將自然語言查詢對應到虛擬詞元的過程中，雖然提升了標準基準上的檢索表現，卻同時遺忘了原本在記憶化階段建立的豐富工具語義與中繼資料關聯。這種訓練階段間的災難性干擾，是導致知識—檢索解離的核心機制之一，也凸顯了現有參數化檢索範式在知識保留上的根本缺陷。

**Q9：在真實情境下，參數化模型與嵌入模型基線的表現如何比較？**
A：在 ToolSense 所設計的真實檢索基準中，原本在標準 ToolBench 評估中遙遙領先的參數化模型，其表現竟顯著低於非參數化的嵌入模型基線。這項結果表明，一旦移除過於詳盡的查詢提示與受限解碼的輔助，參數化模型難以應對真實使用者可能提出的簡潔或歧義查詢。相較之下，嵌入模型基線雖然同樣存在語義捕捉的限制，但在貼近實務的檢索場景中反而展現出更穩健的競爭力，挑戰了參數化檢索必然優於傳統方法的假設。

**Q10：ToolSense 在實際產品開發與部署中可以如何應用？**
A：ToolSense 可作為企業在部署大型代理系統前的標準化稽核工具，用於自動診斷任何客製化工具目錄中的參數化知識缺口。開發團隊能夠利用此框架快速生成針對自身 API 生態系的診斷基準，在產品上線前即識別出模型對哪些工具僅有表面記憶、哪些工具具備深度理解。透過這種前置診斷，產品團隊得以避免在真實使用者場景中遭遇沉默式失效，並據此調整訓練策略或檢索架構，以提升代理系統的可靠性與使用者體驗。

**Q11：這項研究對於在真實世界代理系統中部署參數化檢索有何實務啟示？**
A：本研究明確指出，開發者不能僅憑標準基準測試的高分就斷言參數化檢索已準備好投入生產環境，因為這些分數可能高度依賴受限解碼與過度指定的查詢。在真實世界的多步代理迴圈中，模型經常需要自由生成下一步行動或工具呼叫，此時缺乏 Trie 輔助的參數化模型可能暴露嚴重的召回缺陷。因此，實務部署應將 ToolSense 的診斷結果納入決策依據，並考慮在參數化檢索之外保留傳統嵌入檢索作為備援，或重新設計訓練流程以確保知識的真正內化。

**Q12：此項工作對大型語言模型工具學習與評估領域帶來什麼影響？**
A：ToolSense 為參數化工具檢索這一新興範式建立了首個系統性的診斷典範，將評估焦點從單純的命中率轉移至模型是否真正理解工具語義。透過開源框架與 ToolBench 診斷基準，研究者得以複現並擴展這些發現，促進社群對虛擬詞元與兩階段微調機制的深入探討。長遠而言，這項工作提醒整個領域：在設計新穎的檢索架構時，必須同步發展能夠揭露知識—檢索解離的嚴謹評估協定，否則將難以區分真正的語義學習與複雜的模式匹配。

**Q13：作者在本研究中承認了哪些限制？**
A：本研究主要聚焦於參數化檢索階段的診斷，雖然這是工具學習的關鍵環節，但並未全面涵蓋下游代理任務的端到端效能分析。此外，目前的診斷基準是針對 ToolBench 的工具目錄所生成，雖然框架設計為通用，但在其他領域專用或結構差異極大的工具目錄上，仍需進一步驗證其生成品質與診斷效力。最後，實驗主要圍繞 ToolGen 風格的兩階段訓練配置，對於其他參數化檢索變體或聯合訓練方法的適用性，仍有待後續研究補充。

**Q14：ToolSense 揭示了哪些具體的失效案例或潛在風險？**
A：ToolSense 最顯著的發現是部分模型在標準評估中看似表現卓越，實則在自由形式生成中幾乎完全失效，這是一種危險的沉默式失效模式。具體而言，第二階段檢索微調導致的災難性干擾，使得模型雖能正確輸出虛擬詞元識別碼，卻無法回答關於該工具基本功能或屬性的簡單事實問題。這種現象顯示模型可能僅學會了查詢字句與扁平原子識別碼之間的機械式對應，一旦使用者查詢偏離訓練分佈，系統便可能錯誤地呼叫工具或完全無法召回正確工具。

**Q15：根據本研究的發現，未來有哪些值得探索的研究方向？**
A：未來研究可著重於改良兩階段訓練流程，例如透過正則化技術或知識蒸餾來緩解檢索微調對記憶化知識的破壞，從而縮小知識—檢索解離的差距。另一個方向是探索檢索與生成階段的聯合最佳化，使模型在學習對應查詢與虛擬詞元的同時，仍能穩固保留工具的語義表徵。此外，將 ToolSense 的診斷方法擴展至更大規模、動態更新或多模態工具目錄，並發展能夠即時監測模型知識內化程度的線上稽核機制，亦是提升未來代理系統可信度的重要途徑。

## 實務應用指南

### 適用場景

1. **企業內部大型 API 目錄上線前驗收**：當組織準備將大型語言模型代理部署於數千個內部應用程式介面時，可用 ToolSense 在正式上線前稽核參數化工具檢索模型的真實能力，避免在真實使用者查詢下發生檢索崩潰。
2. **模型供應商選型與採購評估**：資訊長或採購團隊在評估不同參數化工具檢索方案時，可透過真實檢索基準與事實探測基準，識別那些僅在標準 ToolBench 受限解碼環境下表現優異、但在自由生成模式下解離的模型。
3. **微調管線的持續回歸測試**：在執行兩階段微調（記憶化與檢索監督式微調）時，於每個階段後執行 ToolSense 診斷，監控第二階段是否破壞第一階段習得的工具語義知識，作為檢查災難性遺忘的早期預警。
4. **RAG 與參數化架構的決策支援**：當工程團隊猶豫該採用基於嵌入的檢索還是參數化工具檢索時，可利用 ToolSense 在相同工具目錄上比較嵌入模型基線與虛擬詞元模型的內部化分數，作為架構選擇的客觀依據。
5. **生產環境代理的定期健康檢查**：針對已上線的多步代理迴圈系統，定期以真實檢索基準的三層歧義查詢進行壓力測試，確保模型未因資料漂移而在模糊或簡短查詢上效能衰退。

### 實作前置條件

- **資料需求**：結構化的工具目錄（至少包含工具名稱與描述），建議具備真實使用者查詢日誌以校準真實檢索基準的歧義層級分布；若進行事實探測，需額外準備工具的中繼資料欄位（如參數規格、回傳格式）。
- **運算資源**：需有足夠 GPU 記憶體載入待稽核的大型語言模型進行推論；生成三組診斷基準時需呼叫另一個大型語言模型 API 或本地端模型；儲存空間需容納萬級規模（如四萬七千個工具）的虛擬詞元與探測題目。
- **技術能力**：團隊需熟悉 Python 與 PyTorch 生態、理解受限解碼（如 DisjunctiveTrie）與自由生成解碼的差異、具備監督式微調經驗，並能解讀內部化分數（IS@k）與知識-檢索解離指標。

### 實作步驟建議

1. **目錄清洗與載入**：將內部工具目錄整理為 `(name, desc)` 格式，匯入 ToolSense 框架，確認每個工具對應的虛擬詞元或識別碼已正確建立索引。
2. **自動生成診斷基準**：啟動框架內的大型語言模型生成器，產出三組資料：真實檢索基準（涵蓋高、中、低歧義層級的簡短/模糊查詢）、選擇題探測基準（判別式工具語義測驗）、問答探測基準（推論式工具屬性測驗）。
3. **建立雙軌評估基線**：先以傳統嵌入模型執行近似最近鄰搜尋，取得基線分數；再以待測參數化模型在受限解碼（DisjunctiveTrie 束搜尋）下執行標準檢索評估。
4. **執行自由生成稽核**：關閉受限解碼機制，讓模型自由生成虛擬詞元，計算 IS@k（自由生成召回率除以受限解碼召回率）。若此值顯著低於 1.0，表示模型依賴詞元路徑約束而非真正內化知識。
5. **事實探測與解離分析**：運行選擇題與問答探測，比較第一階段（記憶化）與第二階段（檢索監督式微調）後的模型表現。若檢索分數高但探測分數接近隨機，即確認知識-檢索解離。
6. **診斷報告與補救**：針對特定歧義層級或工具類別的失敗模式，調整兩階段微調的資料配比、學習率，或改採 LoRA 等參數高效微調技術以保留第一階段知識，必要時導入混合式架構（參數化檢索＋嵌入檢索後備）。

### 潛在風險與注意事項

- **受限解碼的虛假安全感**：生產環境的多步代理迴圈往往無法使用 DisjunctiveTrie 即時約束每一個生成步驟，若僅以受限解碼分數作為上線標準，上線後在自由生成場景可能發生大規模檢索失敗。建議一律要求 IS@k 達到可接受門檻。
- **第二階段災難性遺忘**：檢索監督式微調雖能提升標準基準分數，卻可能摧毀記憶化階段習得的工具語義。建議在 Stage 2 訓練過程中保留 Stage 1 的驗證集探測分數作為早期停止條件。
- **生成基準的分布偏移**：ToolSense 自動生成的查詢與探測題可能與貴組織真實使用者的語言習慣存在差距。建議在執行框架後，以少量真實查詢日誌進行語義相似度抽樣檢查，必要時人工校正。
- **規模化運算成本**：針對四萬七千個工具等級的大型目錄，生成問答探測與執行自由生成推論的運算成本高昂。建議先以分層抽樣選取具代表性的工具子集進行試點，確認模型有明顯解離後再擴及至全量目錄。
- **探測格式的敏感度**：部分模型在選擇題或問答格式上可能因對齊（alignment）或指令遵循偏差而表現不佳，導致低估其知識。建議搭配少樣本提示（few-shot prompting）或校準分數後再解讀。

### 與其他技術的整合建議

- **CI/CD 管線整合**：將 ToolSense 診斷腳本嵌入模型持續整合流程，每次微調實驗產出新檢查點時，自動執行真實檢索基準與 IS@k 計算，未達門檻即阻擋部署。
- **混合式檢索架構**：當 ToolSense 顯示特定歧義層級或工具類別的內部化分數過低時，可對該類別啟用基於嵌入的檢索作為後備機制，形成「參數化優先、嵌入補位」的雙軌系統。
- **可觀測性平台串接**：將 ToolSense 的探測結果與生產環境的可觀測性工具（如 Langfuse、LangSmith）串接，把診斷發現的弱點工具清單同步至線上監控儀表板，作為異常檢索告警的規則來源。
- **參數高效微調（PEFT）工具鏈**：搭配 LoRA 或 QLoRA 進行兩階段微調時，利用 ToolSense 比較不同秩（rank）與學習率配置下的知識保留率，找出兼顧檢索效能與知識保留的適配器設定。
- **查詢改寫模組聯動**：將真實檢索基準中識別出的高歧義查詢模式，輸入至查詢擴展或重寫模組作為訓練資料，提升上游代理在接收模糊使用者輸入時的查詢澄清能力。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦「為什麼標準基準測試會騙人」這個核心概念。理解受限解碼就像考試時給學生選擇題，而真實檢索基準則像申論題；知識-檢索解離則是「會猜題但不會應用」的現象。建議從論文的圖一與附錄 A 的查詢範例開始，建立直覺。
- **AI 工程師**：請深入研讀兩階段微調的實作細節、自由生成與受限解碼的評估程式碼，以及內部化分數（IS@k）的計算邏輯。重點關注如何將 ToolSense 框架移植到您內部的工具目錄格式，並留意論文中五種訓練配置的消融實驗，以避開已知的訓練陷阱。
- **研究人員**：請關注本研究在探測虛擬詞元（fine-tuning 期間習得的新詞元）而非預訓練表徵上的方法論創新。建議細讀知識-檢索解離的實驗設計，以及選擇題與問答探測如何區分「表面模式配對」與「真正語義理解」，這對參數化檢索與災難性遺忘的研究具有啟發性。
- **產品經理**：請將重點放在商業風險與使用者體驗落差。標準 ToolBench 分數與真實使用者滿意度之間可能存在巨大鴻溝，ToolSense 可作為上線前的 go/no-go 閘門。建議掌握 RRB 三層歧義查詢對應的實際使用者情境（例如口語化、簡短、意圖不明確的對話），並將 IS@k 與探測分數轉化為產品驗收規格。
