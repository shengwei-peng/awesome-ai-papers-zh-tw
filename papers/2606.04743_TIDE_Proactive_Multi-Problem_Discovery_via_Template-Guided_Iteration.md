## 摘要翻譯

智慧代理人（Agents）廣泛部署為文件、工具與程式碼的助理。然而，它們通常僅針對明確的使用者請求（Explicit User Requests）採取行動，因而只會浮現使用者已察覺的問題；至於許多其他重要問題，則隱而未現地共存於更廣泛的使用者情境（Broader User Context）中，且總數事先未知。我們將此界定為從情境中發現多個隱藏問題（Discovering Multiple Hidden Problems from Context）的任務，其中共存問題（Coexisting Problems）應被揭露、基於支持證據（Supporting Evidence），並與具體行動（Concrete Actions）配對。為此，我們提出 TIDE，一個具備兩種互補機制的模板引導迭代（Template-Guided Iteration）框架。具體而言，基於單輪預測（Single-Pass Prediction）會錨定（Anchoring）於最顯著案例（Salient Cases）並產生籠統宣稱（Generic Claims）的觀察，我們提出迭代發現（Iterative Discovery）：每輪產生一小批次（Small Batch）的候選項目（Candidates），同時條件化於（Conditioning on）已發現的內容，使後續輪次得以擴展覆蓋範圍（Coverage）；以及思維模板（Thought Templates），即從先前已解決案例（Previously Solved Cases）中提煉出的可複用基模（Reusable Schemas），明確指定應關注（Attend to）哪些情境訊號（Contextual Signals）及如何連結，將每個預測錨定於可識別的問題類別（Recognizable Problem Class）。我們在個人工作空間（Personal Workspaces）與軟體儲存庫（Software Repositories）兩個真實場景中驗證 TIDE，橫跨四種模型骨幹（Model Backbones），顯示相較於單次基線模型（Single-Shot Baselines）與平行多智慧代理人基線模型（Parallel Multi-Agent Baselines），在任務覆蓋範圍（Task Coverage）、識別（Identification）與解決（Resolution）上均有顯著提升。

### 核心貢獻（3～5點）
- 界定「從情境中發現多個隱藏問題」之任務，要求揭露的共存問題必須基於支持證據，並與具體行動配對。
- 提出模板引導迭代框架 TIDE，包含迭代發現與思維模板兩種互補機制，以克服單輪預測的錨定與籠統宣稱問題。
- 迭代發現透過條件化於已發現內容並逐輪產生小批次候選項目，有效擴展問題覆蓋範圍。
- 思維模板從先前已解決案例中提煉可複用基模，引導模型關注情境訊號並錨定於可識別的問題類別。
- 在個人工作空間與軟體儲存庫的真實場景中，橫跨四種模型骨幹驗證，顯著優於單次與平行多智慧代理人基線模型。

### 適合對象
從事智慧代理人、主動式協助系統、大型語言模型應用、軟體工程與人機互動領域的研究人員與實務工作者，特別是關注如何從廣泛使用者情境中自動發現並解決多重隱藏問題者。

## 深度分析

#### 方法論解析

TIDE（Template-guided Iterative Discovery and rEsolution；模板引導迭代發現與解決框架）所針對的核心任務為 Discovering Multiple Hidden Problems from Context（從情境中發現多個隱藏問題）。與傳統僅回應 Explicit User Requests（明確的使用者請求）的 Reactive（反應式） Agents（智慧代理人）不同，此任務假設在 Broader User Context（更廣泛的使用者情境）——如 Personal Workspaces（個人工作空間）或 Software Repositories（軟體儲存庫）——中存在數量未知的 Coexisting Problems（共存問題）。這些 Hidden Problems（隱藏問題）往往因 Salient Cases（顯著案例）的 Anchoring（錨定）效應，使得 Single-Pass Prediction（單輪預測）僅能產出 Generic Claims（籠統宣稱），而遺漏大量潛在風險。

為此，作者提出兩項互補機制。第一項是 Iterative Discovery（迭代發現）：模型每輪僅生成一個 Small Batch（小批次）的 Candidates（候選項目），並透過 Conditioning on（條件化於）已累積的發現狀態，迫使後續輪次持續擴展 Coverage（覆蓋範圍）。此機制有效緩解了顯著案例對模型注意力的壟斷。對每個浮現的候選項目，系統進一步檢索 Supporting Evidence（支持證據／佐證），並提出 Concrete Actions（具體行動），使輸出同時完成 Identification（識別）、佐證與 Resolution（解決）。

第二項機制為 Thought Templates（思維模板）。這些是從 Previously Solved Cases（先前已解決的案例）中提煉出的 Reusable Schemas（可複用基模），每個模板對應一個 Recognizable Problem Class（可識別的問題類別）。它明確規範應 Attend to（關注）哪些 Contextual Signals（情境訊號），以及如何將這些訊號連結為證據鏈，從而讓每個預測都 Grounded in Supporting Evidence（基於支持證據），而非憑空推論。

兩者的協同在於：Iterative Discovery（迭代發現）負責廣度，確保多重問題的 Task Coverage（任務覆蓋範圍）；Thought Templates（思維模板）負責精度，透過可複用基模將預測錨定於已知模式，抑制推測性輸出。最終，TIDE 輸出一組結構化計畫，每項計畫皆包含問題描述、佐證來源與執行動作。

#### 實驗數據解讀

論文在兩個貼近現實的 Digital Environments（數位環境）中驗證 TIDE：Personal Workspaces（個人工作空間）與 Software Repositories（軟體儲存庫）。實驗橫跨四種 Model Backbones（模型骨幹），並與 Single-Shot Baselines（單次基線模型）及 Parallel Multi-Agent Baselines（平行多智慧代理人基線模型）進行比較。

評估指標涵蓋三個維度：Task Coverage（任務覆蓋範圍）、Identification（識別）與 Resolution（解決）。Task Coverage 衡量系統能否找出情境中所有共存的 Hidden Problems，而非僅止於最明顯的一項；Identification 評估模型對問題本質與證據鏈的判斷精準度；Resolution 則檢視所提出的 Concrete Actions 是否真能有效處理該問題。

根據文中描述，TIDE 在三項指標上均顯著優於兩類基線模型。其中，Single-Shot Baselines 受限於單輪推論的 Anchoring 效應，傾向輸出顯著案例的 Generic Claims，導致 Coverage 不足；Parallel Multi-Agent Baselines 雖能並行探索，但缺乏 Iterative Discovery 中的條件化累積機制，仍難以系統性地擴展問題集合。

進一步的分析指出，Iterative Discovery 與 Thought Templates 帶來的增益具有高度互補性：前者主要提升 Task Coverage，後者則強化 Identification 與 Resolution 的精確度。此外，Thought Templates 展現出跨 Model Backbones 的遷移能力（transfer across backbones），意味著從歷史案例中提煉的 Reusable Schemas 具備某種程度的模型無關性，能在不同底層模型間維持穩定的引導效果。

#### 與現有研究的比較

現有關於 Proactive Assistance（主動式協助）的文獻多聚焦於兩個較狹隘的面向：一是判斷「何時介入」（when to intervene），二是預測「單一局部需求」（single localized need）。這類研究雖然推動了 Agents 從純反應式走向主動，但本質上仍假設 User Context 中僅存在一項待解決的問題，且其數量與範圍事先可知。TIDE 則將 Proactive Assistance 重新框架為 Discovering Multiple Hidden Problems from Context 的顯式多步驟發現過程，直接挑戰「問題數量未知且共存」的真實 Working Context（工作情境）。

相較於僅回應 Explicit User Requests 的傳統 Agents，TIDE 的價值在於能夠發現「使用者根本沒想到要問」的問題。這種能力對於高風險的工作流程（如預算審批缺口、版本衝突、會議資源閒置）尤為關鍵，因為這些 Hidden Problems 往往就藏在文件、電子郵件與行事曆條目中，卻因缺乏顯著性而被忽視。

然而，從方法論細節觀察，TIDE 仍存在若干潛在限制。首先，Thought Templates 的品質高度依賴 Previously Solved Cases；若歷史案例分布偏頗或領域過窄，模板可能無法涵蓋新興的 Recognizable Problem Class。其次，Iterative Discovery 雖提升 Coverage，但多輪生成與條件化推論勢必增加推理延遲與計算成本，對於需要即時回應的場景可能構成挑戰。此外，論文尚未深入探討當發現的 Coexisting Problems 彼此衝突或具有相依性時，Agents 應如何排定優先順序或調解矛盾行動。

#### 可重現性評估

就本文提供的上下文而言，作者尚未明確提及是否釋出開源程式碼、資料集或模型權重。在缺乏公開實作與評估資料的情況下，外部研究者難以直接複現其在 Personal Workspaces 與 Software Repositories 中的完整實驗流程，也無法驗證 Thought Templates 在不同領域的泛化表現。

若要提升可重現性，建議後續公開以下項目：第一，用於建構 Thought Templates 的 Previously Solved Cases 集合，以及模板提煉的具體演算法；第二，Personal Workspaces 與 Software Repositories 任務的標準化資料集與評估腳本，特別是涵蓋 Supporting Evidence 與 Concrete Actions 的標註；第三，不同 Model Backbones 下的提示詞模板與 Iterative Discovery 的停止條件設定。這些資訊的釋出將有助於社群驗證 TIDE 相較於 Single-Shot Baselines 與 Parallel Multi-Agent Baselines 的實質增益。

#### 未來研究方向

基於 TIDE 的框架設計與實驗結果，以下幾個方向值得後續探索：

1. **動態模板演化**：目前的 Thought Templates 主要從靜態的 Previously Solved Cases 中提煉。未來可研究如何讓模板隨著 User Context 的演變而自動更新，甚至從失敗的發現嘗試中學習，避免 Reusable Schemas 僵化。

2. **即時主動式協助**：現行 Iterative Discovery 以多輪 Small Batch 方式進行，未來可探索串流式（streaming）或事件驅動的迭代策略，使 Agents 能在 Large Language Model（LLM）推理成本與即時性之間取得平衡，真正部署於持續運作的 Digital Environments。

3. **問題間相依性建模**：真實 Working Context 中的 Coexisting Problems 往往並非獨立，而是具有因果或資源衝突關係。後續研究可將問題間的相依結構納入 Iterative Discovery 的 Conditioning on 邏輯，讓 Agents 不僅列出 Hidden Problems，還能輸出優先順序建議或整合式解決方案。

4. **跨領域遷移與少量模板學習**：雖然實驗已顯示模板可跨 Model Backbones 遷移，但其跨領域（如從 Personal Workspaces 遷移至醫療或法律文件）的適應性仍待驗證。研究如何以極少量領域特定案例即可生成有效 Thought Templates，將大幅提升實用價值。

5. **人機協作式發現**：將 TIDE 從全自動發現擴展為互動式流程，允許使用者在每輪迭代後提供回饋或修正 Candidates，結合人類領域知識與模型的廣泛檢索能力，進一步提升 Identification 與 Resolution 的準確度。

6. **工具使用與行動執行驗證**：目前框架中的 Concrete Actions 仍屬計畫層級。未來可整合外部工具使用（tool use）與 API 執行，讓 Agents 在發現問題後實際驗證行動的可行性（例如真的建立行事曆事件或發出 pull request），形成發現—驗證—執行的閉環。

## 論文問答

**Q1：TIDE 旨在解決的核心問題是什麼？**
A：TIDE 旨在解決「從情境中發現多個隱藏問題」這項核心任務，因為現有的智慧代理人通常僅在收到明確的使用者請求後才會行動，導致許多共存問題被忽略。這些隱藏問題往往存在於更廣泛的使用者情境中，例如文件、電子郵件與行事曆項目，且其總數事先未知。由於這些問題就隱藏在顯而易見之處，傳統的被動式互動模式無法將其揭露，因此需要主動式協助來全面發現並處理。

**Q2：為何現有的單輪預測與主動式代理方法無法有效處理此類問題？**
A：單輪預測容易錨定於最顯著的案例，並產生籠統宣稱，導致較不明顯的共存問題被系統性地忽略。現有的主動式代理人研究大多聚焦於預測單一局部需求或決定介入時機，迴避了真實工作流程中多重問題並存且散布於廣泛脈絡的挑戰。因此，這些方法缺乏對競爭注意力的多個共存問題進行廣泛覆蓋的能力，無法滿足複雜數位環境的需求。

**Q3：主動式多重問題發現對實際工作流程為何重要？**
A：在實務中，最具影響力的問題往往是使用者尚未察覺的，例如口頭同意卻未書面記錄的預算核准，或內容衝突的報告副本。若智慧代理人只解決最顯著的問題而讓其餘問題未被觸及，將嚴重阻礙工作進度並錯過關鍵截止日期。因此，將主動式協助重新框架為從情境中發現多個隱藏問題，是確保數位助理能真正提升工作效率與降低風險的關鍵。

**Q4：TIDE 的核心方法論包含哪些互補機制？**
A：TIDE 的核心方法論結合了「迭代發現」與「思維模板」兩種互補機制，共同構成模板引導迭代框架。迭代發現透過每輪產出一小批次候選項目，並將已發現的問題作為後續輪次的條件，逐步擴展覆蓋範圍。思維模板則是從先前已解決的案例中提煉出的可複用基模，用於指定應關注哪些情境訊號以及如何連結它們，使每個預測都能錨定於可識別的問題類別。

**Q5：迭代發現與思維模板的關鍵創新之處為何？**
A：此框架的關鍵創新在於同時擴大問題覆蓋範圍並提升預測的精確度，而非僅追求單一指標。迭代發現透過條件化於累積發現狀態，迫使後續輪次超越最初顯眼的案例，從而發現被遮蔽的問題。思維模板則提供可複用的先驗知識，說明問題如何在證據中顯現，避免預測漂向籠統宣稱或推測性主張，確保每個候選項目都基於支持證據。

**Q6：TIDE 為何選擇小批次迭代發現，而非單輪預測？**
A：作者觀察到單輪預測會因顯著案例系統性地遮蔽較細微的共存問題，導致大多數隱藏問題未被發現。透過每輪僅產生小批次候選項目，並持續條件化於已發現內容，智慧代理人被迫逐步深入探索更廣泛的使用者情境。此外，每個候選項目都必須搭配支持證據與具體行動，確保輸出同時完成識別、佐證與解決，而非僅產生泛泛的推測。

**Q7：TIDE 在哪些實際場景與模型骨幹上進行驗證？**
A：TIDE 在兩個具有真實多重問題結構的場景上進行驗證：個人工作空間與軟體儲存庫。個人工作空間中存在許多散布於文件與行事曆的未解決瓶頸，而軟體儲存庫則蘊含版本衝突、風險相依等技術問題。實驗橫跨四種不同的模型骨幹進行，以證明該框架在不同底層語言模型上的通用性與穩健性。

**Q8：TIDE 的關鍵實驗結果為何？**
A：相較於單次基線模型與平行多智慧代理人基線模型，TIDE 在任務覆蓋範圍、識別與解決三項指標上均取得顯著提升。這些結果顯示，將主動式協助框架化為明確的多步驟情境探索過程，遠優於僅依賴單輪預測或使用者請求的反應式方法。分析進一步指出，迭代發現與思維模板帶來的增益具有高度互補性，證明兩者結合的必要性。

**Q9：消融實驗揭示了 TIDE 各組件的什麼特性？**
A：消融分析顯示，迭代發現與思維模板各自貢獻了高度互補的增益，兩者缺一不可。此外，思維模板能夠有效遷移至不同的模型骨幹，顯示其作為可複用基模的強大泛化能力。這些發現證實，廣泛的覆蓋範圍需要迭代機制來達成，而精確的識別則依賴模板提供的可識別問題類別先驗，兩者相輔相成。

**Q10：TIDE 能夠發現哪些具體的實務問題範例？**
A：在個人工作空間中，TIDE 可發現「專案簡報載有最終交付截止日期，但開發中的里程碑未追蹤該日期」等問題，或是團隊已默不出席卻仍佔據行事曆的過期會議。在軟體儲存庫中，則可識別版本衝突、未追蹤的風險相依性，或行動項目缺乏明確負責人的所有權模糊問題。每個發現都包含佐證文件與具體行動，形成可立即執行的多元素計畫。

**Q11：基於 TIDE 的設計，主動式協助應如何重新定位？**
A：主動式協助應從「預測單一使用者意圖」重新定位為「在更廣泛的使用者情境上進行明確的多步驟發現過程」。智慧代理人的目標不再是僅回應已知需求，而是主動浮現使用者未曾想到要詢問的隱藏問題，並指出解決方向。這種定位要求代理人針對每個發現的問題，同時輸出識別、支持證據與具體行動，而非僅提供片段資訊。

**Q12：TIDE 對智慧代理人研究領域的廣泛影響為何？**
A：TIDE 為建構能超越反應式任務執行的智慧代理人提供了一般性配方，特別是在文件、工具與程式碼等豐富數位環境中。它證明了透過模板引導迭代，代理人能夠揭露潛藏的共存問題，推動領域邁向真正主動式協助的典範。這項工作也指出，未來的代理人必須能處理數量未知且交錯於工作情境中的多重問題，而非僅處理孤立的使用者查詢。

**Q13：依賴從先前已解決的案例提煉思維模板，存在哪些內生限制？**
A：由於思維模板源自先前已解決的案例，當系統面對歷史資料中完全未出現過的新穎問題類別時，可能遭遇冷啟動困境。若當前情境中的問題顯著偏離既有可複用基模所捕捉的模式，代理人仍可能產生籠統宣稱或遺漏這些異常狀況。此外，發現能力的上限直接受限於模板庫的覆蓋範圍與代表性，難以處理極為罕見或高度個人化的問題結構。

**Q14：TIDE 在哪些情況下可能無法成功發現隱藏問題？**
A：當情境訊號極其微弱或淹沒在大量雜訊中，導致難以連結到任何可識別的問題類別時，TIDE 可能失效。若多個共存問題以複雜且非模組化的方式交互作用，小批次迭代條件化可能仍會忽略彼此相依的深層問題。此外，在問題鮮少重複出現或缺乏結構化模式的領域中，幾乎無法形成有效的可複用基模，模板引導的優勢將難以發揮。

**Q15：模板引導迭代發現的未來研究方向為何？**
A：未來研究可探索思維模板自動化提煉與動態擴展的機制，以降低對人工整理歷史案例的依賴。將迭代發現整合至即時串流情境，例如即時協作文件或持續整合管線，可進一步擴展其應用場景。另外，優化迭代過程以降低延遲，同時維持任務覆蓋範圍與識別精確度，將是使此框架適用於延遲敏感的生產環境的重要方向。

## 實務應用指南

### 適用場景

**1. 企業個人數位工作空間治理**
當員工的電子郵件、行事曆、即時通訊與文件分散於多個平台時，TIDE 可主動掃描跨來源情境，發現諸如「口頭核准未留書面紀錄導致採購卡關」「會議邀請與專案截止日衝突」「兩份同主題報告數據矛盾」等隱藏問題，並附上佐證與具體行動建議。

**2. 軟體開發與維運儲存庫維護**
在程式碼儲存庫、PR（Pull Request）、Issue 與技術文件交織的環境中，TIDE 能迭代發現「未追蹤的依賴風險」「已取消需求卻仍存在的每日站會」「里程碑未同步至開啟中的 PR」等共存問題，避免單輪預測只抓到最顯著的編譯錯誤而忽略結構性瓶頸。

**3. 客戶成功與帳戶管理**
整合客戶關係管理（CRM）系統、合約文件與支援工單，TIDE 可從看似正常的互動紀錄中，發現「續約條款與最新報價單不一致」「關鍵聯絡人離職未重新指派」「口頭承諾的服務等級協議未寫入正式附件」等多重隱藏風險。

**4. 法務與採購合規稽核**
面對大量內部政策、供應商合約與核准流程文件，TIDE 能以思維模板引導模型關注特定訊號（如「口頭同意但無書面紀錄」「截止日臨近卻無負責人」），主動發現合規缺口，而非僅在被問及時才檢索單一條文。

### 實作前置條件

**資料需求**
- **歷史已解決案例**：需蒐集數十至數百筆先前已識別並解決的問題實例，用以提煉可複用基模（思維模板）。
- **廣泛情境資料源**：必須能讀取待分析範圍內的原始資料，例如郵件內文、行事曆事件、文件版本、程式碼儲存庫提交紀錄、PR 描述等。
- **證據片段標註**：每筆歷史案例最好已標註支持證據所在位置，以便學習如何將情境訊號連結到問題類別。

**運算需求**
- **大型語言模型 API 或自建推理端點**：論文驗證使用四種模型骨幹，建議至少具備一種進階模型（如 GPT-4、Claude 3、Gemini Pro 等級）的穩定呼叫配額。
- **多輪迭代預算**：因採用小批次迭代發現，總 token 消耗顯著高於單次基線，需預留 3–5 倍的推理成本。
- **向量資料庫（建議）**：用於儲存與檢索思維模板及情境片段，加速每輪的條件化生成。

**技能需求**
- **提示工程與代理程式設計**：需熟悉多輪對話狀態管理、累積發現條件化（conditioning on cumulative state）的 prompt 設計。
- **領域知識**：需有領域專家協助驗證模板品質，避免模型產出籠統宣稱。
- **資料工程**：需具備串接異質資料源（Email、Calendar、Git、雲端硬碟）並統一格式的前置處理能力。

### 實作步驟建議

**步驟一：界定任務範圍與問題類別**
先定義目標情境（如個人工作空間或軟體儲存庫），並與領域專家列出預期可能共存的主要問題類別（如「遺漏截止日」「版本衝突」「負責人不明」），作為模板設計的初始骨架。

**步驟二：從歷史案例提煉思維模板**
蒐集先前已解決的案例，分析每個案例的情境訊號如何串成證據鏈，將其結構化為可複用基模。每個思維模板應明確指定：需關注哪些上下文欄位、如何連結這些訊號、以及對應的可識別問題類別。

**步驟三：建置情境資料索引層**
將分散的資料源（郵件、文件、程式碼、行事曆）統一抽取並建立索引，確保迭代發現引擎能於每輪快速檢索相關片段，作為支持證據的來源。

**步驟四：開發迭代發現引擎**
實作多輪生成迴圈：每輪只產出小批次（如 1–3 個）候選問題，並將已發現的問題列表與對應證據注入下一輪的 prompt，強制後續輪次擴展覆蓋範圍而非重複顯著案例。

**步驟五：證據檢索與行動計畫生成**
對每個候選問題，觸發檢索模組撈取原始佐證片段，並要求模型產出包含「問題識別、支持證據、具體行動」三元素的多元素計畫，確保輸出可執行而非僅止於描述。

**步驟六：設計人機協作驗證介面**
由於主動式協助涉及未經請求的介入，需建置審查介面讓使用者確認、編輯或駁回發現的問題，並將使用者回饋回流至模板更新流程。

**步驟七：部署監控與持續學習**
上線後追蹤任務覆蓋範圍、識別準確率與解決完成率。定期將新解決的案例重新餵入模板提煉流程，避免模板過時導致預測漂移。

### 潛在風險與注意事項

**1. 單輪預測慣性與覆蓋不足**
許多團隊會直覺地以單次基線模型處理，導致模型只錨定最顯著案例。務必落實多輪迭代，並在 prompt 中明確要求「不得與已發現項目重複」，以確保共存問題被充分揭露。

**2. 模板僵化與領域漂移**
思維模板若長期未更新，容易遺漏新興問題模式。建議每季或以固定週期審視模板，並將新案例納入提煉，維持可複用基模的時效性。

**3. 籠統宣稱與幻覺風險**
若缺乏證據檢索機制，模型可能產出看似合理但無根據的候選問題。每個輸出都必須強制綁定原始資料片段作為支持證據，並經過來源可追溯性檢查。

**4. 隱私與權限邊界**
主動掃描廣泛使用者情境（如電子郵件、私人行事曆）涉及高度敏感資料。實作時必須落實最小權限原則、去識別化處理，並讓使用者能明確設定掃描範圍與排除項目。

**5. 警報疲勞與過度干預**
迭代發現可能產生大量次要或低風險問題，反而干擾核心工作。建議導入嚴重程度評分與使用者回饋機制，優先推送高影響力問題，並允許一鍵忽略特定類別。

### 與其他技術的整合建議

**檢索增強生成（RAG）**
將 RAG 作為每輪迭代中的證據檢索層，負責從龐大情境資料中撈取與當前思維模板相關的原始片段，補強模型本身有限的上下文長度，並提升佐證的精確度。

**向量資料庫（如 Pinecone、Weaviate、Milvus）**
用於儲存思維模板的嵌入向量，當遇到新情境時，可先以相似度搜尋召回最相關的模板，再進行條件化生成，加速迭代過程並降低無關模板的干擾。

**現有協作與工單系統（如 Jira、Asana、Notion）**
將 TIDE 發現的問題與具體行動自動轉換為工單或資料庫項目，讓主動發現無縫銜接既有工作流程。建議保留人工確認閘道，避免自動建立過多工單。

**平行多智慧代理人架構**
雖然論文顯示 TIDE 優於平行多智慧代理人基線，但仍可將平行代理人用於「行動執行」階段（例如一個負責發會議邀請、一個負責開 Issue），而讓 TIDE 專注於「發現與識別」階段，形成前後端分工。

**自動化流程平台（如 Zapier、Make、n8n）**
對於個人工作空間場景，可透過自動化平台串接行事曆、郵件與雲端文件 API，讓 TIDE 產出的具體行動能直接觸發實際操作（如發送提醒信、建立行事曆事件），縮短從發現到解決的距離。

### 給不同背景讀者的閱讀建議

**給初學者**
把 TIDE 想像成一位不只等你開口、還會主動翻閱你桌上文件與行事曆的資深助理。核心概念在於：真正的智慧代理人不該只回應明確的使用者請求，而應主動從更廣泛的使用者情境中找出你還沒意識到的多重問題。閱讀時請聚焦論文圖一的概念示意，理解「反應式」與「主動式」協助的差異，以及為何單輪預測會漏掉重要線索。

**給 AI 工程師**
本文的實作價值在於兩個互補機制的工程細節：迭代發現的「累積狀態條件化」與思維模板的「可複用基模設計」。請特別留意第 2 節的方法論，思考如何在 prompt 中實作「每輪小批次產出 + 已發現列表注入」，以及如何從歷史案例自動化提煉模板。此外，證據檢索與具體行動的三元素輸出格式（識別、佐證、行動）可直接複用到你的代理程式架構中。

**給研究人員**
TIDE 將主動式協助重新框架為「從情境中發現多個隱藏問題」的顯性多步驟過程，而非單一意圖預測。請關注作者對「共存問題」「未知數量」「顯著案例遮蔽效應」的問題設定，以及迭代發現與思維模板在覆蓋範圍與識別精確度上的互補增益分析。實驗設計上，個人工作空間與軟體儲存庫的雙場景驗證、以及跨四種模型骨幹的穩健性測試，都提供了未來研究可參照的評估範式。

**給產品經理**
這篇論文提供了一個強大的產品敘事：你的用戶並不知道自己不知道什麼。TIDE 的價值主張在於提升任務覆蓋範圍與解決完成率，減少「明明有問題卻沒人發現」的業務損失。在規劃產品時，請特別注意人機協作介面的設計——主動發現若缺乏使用者信任與確認機制，極易淪為騷擾。建議將「具體行動」設計為一鍵執行的建議卡片，並讓用戶能輕鬆標記誤報，以持續優化推薦品質。
