## ⚡ TL;DR

智能體大型語言模型處理長程任務時上下文視窗有限，且缺乏委派智能的訓練資料。
本文設計導引架構促使主智能體分解任務並委派子智能體執行，並以高品質軌跡進行監督式微調內化委派智能。
SearchSwarm-30B在同規模模型中表現最佳，並開源導引架構與訓練資料促進研究。

## 摘要翻譯

大型語言模型（large language models）日益被期望處理複雜的長程（long-horizon）真實世界任務，這些任務的上下文（context）需求可能無限制地增長，然而模型的上下文視窗（context window）本質上仍是有限的。近期研究探索了一種範式，由主智能體（main agent）進行任務分解（task decomposition），並將子任務（subtasks）分派（dispatch）給子智能體（subagents）；子智能體執行後僅回傳摘要結果（summarized results），以節省主智能體的上下文預算（context budget）。然而，要妥善執行此機制，需要委派智能（delegation intelligence）：即分解複雜任務、判斷委派時機與內容，並將回傳結果整合至持續進行的工作流程中的能力。此能力所需的訓練資料在自然文本中相當稀少，且據我們所知，如何合成（synthesize）此類資料並訓練模型習得此能力，在開源（open-source）社群中在很大程度上仍未被探索。為彌補此缺口，我們針對深度研究（deep research）——一項具代表性的長程智能體（agent）任務——進行初步探索。具體而言，我們設計了一個導引架構（harness），引導模型進行高品質的任務分解（task decomposition）與委派（delegation），同時約束子智能體（subagents）適當地回傳結果，以支援主智能體（main agent）的工作流程。在導引架構（harness）引導下產生的軌跡（trajectories）自然蘊含了正確的委派決策，我們將其作為監督式微調（supervised fine-tuning）資料，以將委派智能（delegation intelligence）內化（internalize）至模型權重（model weights）中。我們最終訓練出的模型 SearchSwarm-30B-A3B 在 BrowseComp 上達到 68.1 分，在 BrowseComp-ZH 上達到 73.3 分，為所有同等規模（comparable scale）模型中的最佳表現。我們將公開釋出導引架構（harness）、模型權重（model weights）與訓練資料，以促進後續研究。

### 核心貢獻（3～5點）
- 針對深度研究此類長程智能體任務，首次於開源領域系統性探索如何合成資料並訓練模型習得委派智能，填補既有研究缺口。
- 設計導引架構，於訓練階段引導模型進行高品質任務分解與委派，同時約束子智能體適當回傳結果以支援主智能體的工作流程。
- 利用導引架構產出的正確軌跡建構監督式微調資料集，將委派智能內化至模型權重，建立可複製的能力建構管道。
- 訓練並釋出 SearchSwarm-30B-A3B 模型，於 BrowseComp（68.1 分）與 BrowseComp-ZH（73.3 分）基準達成同等規模模型中的最佳表現，並公開導引架構、模型權重與訓練資料促進後續研究。

### 適合對象
從事大型語言模型智能體、長程任務規劃、多智能體協作與工具使用研究的研究者與工程師；特別適合關注開源模型委派智能、上下文管理與深度研究能力建構的學術與產業界讀者。

## 深度分析

#### 方法論解析

本文提出之 main-distributes, sub-executes（主分派-子執行） paradigm（範式），旨在解決 long-horizon（長程） deep research（深度研究）任務中，context window（上下文視窗）有限與 interaction history（互動歷史）無限增長之根本張力。與早期 passive compression（被動壓縮）策略——如超過長度門檻後摘要 interaction history，或按固定規則截斷 tool output（工具輸出）——不同，SearchSwarm 採取 active context management（主動式上下文管理），透過 delegation intelligence（委派智能）預先規劃 task decomposition（任務分解）與資訊整合。

核心機制為 harness（導引架構），其圍繞四項設計原則運作：
1. **鼓勵委派（Encouraging delegation）**：main agent（主智能體）透過 `call_sub_agent` 工具，將 bounded subtask（有界子任務） dispatch（分派）至獨立上下文之 subagent（子智能體），避免 main agent 之 context budget（上下文預算）被低階執行細節耗盡。
2. **撰寫全面簡報（Comprehensive briefs）**：main agent 在委派時，不僅提供子任務描述，更須闡述該子任務之 rationale，包括其對整體研究目標之重要性與定位。此設計使 subagent 能進行聚焦研究，減少冗餘探索。
3. **保留核心判斷（Retaining core judgment）**：main agent 維持對整體研究進度之獨立理解，而非僅被動接收 subagent 回傳內容，確保整合階段之推理品質。
4. **要求引用來源的報告（Citation-grounded reporting）**：約束 subagent 輸出必須包含明確來源引用，使 main agent 得以驗證結論，並將引用傳遞至最終回應，提升可信度。

在執行流程上，main agent 遵循 ReAct（Yao et al., 2022）框架，每步由 Thought（τ_t）、Action（a_t）與 Observation 構成。當呼叫 `call_sub_agent` 時，subagent 在獨立環境中執行多輪工具互動，最終回傳 summarized results（摘要結果）至 main agent 之上下文，供後續推理與進一步委派決策使用。

為將上述行為 internalize（內化）至 model weights（模型權重），作者利用 harness 在推論階段產出高品質 trajectory（軌跡），並篩選編碼正確委派決策——包含分解時機、子任務範圍界定、簡報內容適切性——之樣本，以 supervised fine-tuning（監督式微調）訓練模型。此 synthetic data（合成資料）策略克服了自然語料中多智能體協調案例稀缺之困境，使初始不具 delegation intelligence 之模型得以習得系統性分派與整合能力。

#### 實驗數據解讀

SearchSwarm-30B-A3B 在四項 benchmark（基準測試）之表現如下：
- **BrowseComp**：68.1 分
- **BrowseComp-ZH**：73.3 分
- **GAIA**：82.5 分
- **xbench-DeepSearch-2505**：80.8 分

數據顯示，於 comparable scale（同等規模）之 lightweight model（輕量級模型）中，SearchSwarm 全數取得最佳成績；即便與規模大於十倍以上之大型 closed-source（閉源）或 open-source（開源）模型相比，仍具競爭力。

深入解讀可歸納三點：

1. **delegation intelligence 有效替代規模優勢**：在 BrowseComp 與 BrowseComp-ZH 上，SearchSwarm 透過 active context management 與 task decomposition，彌補了參數量劣勢。相較於 passive compression 方法需待上下文耗盡後才處理歷史資訊，預先規劃之委派機制保留了高價值之推理鏈，使有限容量集中於決策與整合。

2. **跨語言穩健性**：BrowseComp-ZH 達 73.3 分，相較英文版 BrowseComp（68.1 分）甚至更高，顯示 harness 所內化之委派模式具有跨語言遷移能力。這暗示 task decomposition 與簡報設計之邏輯結構可能為語言無關（language-agnostic）之元能力。

3. **深度研究綜合能力突出**：GAIA（82.5）與 xbench-DeepSearch-2505（80.8）之高得分，驗證了 subagent 引用來源之設計確實提升了證據導向（evidence-grounded）回答之品質。main agent 能夠驗證並彙整多路回傳之引用，對於需要多輪資訊搜集與驗證之長程任務至關重要。

值得注意的是，Figure 1 中部分超大規模模型（如 Claude 4.5 Opus、Gemini 3 Pro 等）在特定 benchmark 上與 SearchSwarm 接近，但考量參數規模差異，SearchSwarm 之效率優勢顯著。

#### 與現有研究的比較

本文定位於開源社群中首次系統性探索 delegation intelligence 之資料合成與模型訓練。與既有研究相較，其差異與精進如下：

**相較於被動式 context management**
Liu et al. (2025)、Zeng et al. (2026) 等方法採用摘要 interaction history 或截斷 tool output，本質上為後處理式之 passive compression。SearchSwarm 則於規劃階段即主動分派 bounded subtask，從源頭控制上下文增長，屬於更具前瞻性之資訊管理策略。

**相較於 AgentSwarm（Kimi Team, 2026）**
AgentSwarm 凍結 subagent 參數，以 reinforcement learning（強化學習）訓練 main agent 之分派策略。SearchSwarm 則採用 harness 產生 trajectory，並以 supervised fine-tuning 內化行為。兩者技術路線不同：RL 探索空間大但訓練成本高；SFT 路線在資料品質受控下，更利於開源社群復現與迭代。此外，SearchSwarm 提供涵蓋 harness 設計、訓練資料建構至模型訓練之完整配方（complete recipe）。

**相較於 Huang et al. (2026a, 2026b) 與 Xu et al. (2026)**
雖同屬 main-distributes, sub-executes 框架，SearchSwarm 在子任務簡報中強制納入 rationale（為何該子任務重要、如何銜接整體目標），並要求 subagent 報告附帶明確引用。這些約束減少了 subagent 之冗餘探索，並使 main agent 能進行可驗證之結論整合，在深度研究之證據鏈完整性上更勝一籌。

**侷限性**
作者自承此為 preliminary exploration（初步探索）。首先，實驗聚焦於 deep research 此一代表性任務，delegation intelligence 在軟體工程、多模態長程任務等情境之泛化性尚待驗證。其次，訓練資料依賴 harness 合成，若 harness 本身存在偏誤（bias），則可能透過 SFT 放大並固化於 model weights 中。最後，main agent 之委派決策目前主要透過靜態規則與範例驅動，動態適應不同 context budget 壓力之彈性仍有提升空間。

#### 可重現性評估

可重現性（reproducibility）是本文之重要承諾。作者明確表示將開源釋出 harness、model weights 與 training data（訓練資料）。對於開源社群而言，此舉大幅降低後續研究之進入門檻。

從方法論描述評估，復現所需之關鍵元件已具雛形：
- **系統架構**：main agent 與 subagent 之互動介面（`call_sub_agent`、獨立上下文、ReAct 循環）定義清晰。
- **導引架構原則**：四項設計原則（鼓勵委派、全面簡報、保留判斷、引用約束）提供了可轉化為提示模板（prompt template）之具體方向。
- **訓練流程**：harness-guided trajectories → 篩選 → SFT 之管線概念簡潔，便於移植至其他基礎模型。

然而，完整復現仍仰賴若干尚未公開之工程細節：
1. **trajectory 篩選準則**：如何定義「正確委派決策」之自動或人工過濾規則？
2. **負面樣本處理**：是否僅使用正向軌跡，抑或包含錯誤委派之對比學習？
3. **subagent 規模**：SearchSwarm-30B-A3B 之名稱暗示 main agent 為 30B，A3B 可能指 3B 之 subagent 或其他輔助模組，但論文未詳細說明兩者之訓練關係與參數配置。

綜合而言，若作者確實依約釋出完整資源，本文將成為開源社群研究多智能體協調與 delegation intelligence 之重要基準；反之，若僅釋出 model weights 而缺訓練管線細節，則後續研究者可能僅能進行推論階段之應用，難以複製訓練過程。

#### 未來研究方向

基於 SearchSwarm 之初步成果，以下為具潛力之後續研究方向：

1. **reinforcement learning 與 SFT 之結合**
   目前以 supervised fine-tuning 內化 harness 之行為，但未來可於 SFT 後進行 reinforcement learning，以環境回饋（如 BrowseComp 之正確性訊號）進一步優化委派策略。harness 本身亦可轉化為獎勵模型（reward model）之設計基礎。

2. **動態 context budget 分配**
   當前子任務之上下文分配似為固定或啟發式。未來可研究如何依據任務複雜度、資訊密度與剩餘 context budget，動態調整 main agent 與各 subagent 之上下文配額，以最大化整體推理效能。

3. **多層級委派階層（Hierarchical Delegation）**
   本文之 subagent 僅執行任務而未再委派。引入多層級 main-distributes, sub-executes 架構（如 subagent 再分派給孫智能體），可處理更複雜、更深之研究問題，但需同時解決資訊傳遞失真與延遲之挑戰。

4. **跨任務泛化與持續學習**
   將 delegation intelligence 從 deep research 擴展至軟體開發、科學實驗設計、多模態內容創作等其他長程任務。此外，可探索讓 main agent 在執行過程中持續反思並更新自身之 task decomposition 策略，實現自我改進（self-improvement）。

5. **引用驗證與事實性迴路（Factuality Loop）**
   subagent 已產生結構化引用，未來可加入自動化驗證模組，主動偵測引用衝突或缺失，並觸發新一輪 dispatch 以補強證據鏈，形成「研究-驗證-再委派」之閉迴路。

6. **與更大規模基礎模型之協同**
   測試當 main agent 規模提升至 70B 或更大時，delegation intelligence 是否仍具顯著邊際效益，抑或大型模型之單一上下文能力已足以涵蓋多數任務。此研究將釐清 delegation intelligence 在不同規模區間之價值分佈。

## 論文問答

**Q1：在長程智能體任務中，存在什麼根本性的張力？**
A：核心張力在於複雜真實世界任務的上下文需求可能無限增長，而大型語言模型的上下文視窗本質上是有限的。當智能體執行需要多輪互動的深度研究時，其互動歷史、工具輸出與觀察結果會迅速累積，最終超出模型可處理的上限。這使得單純依賴被動壓縮或截斷的方法難以維持長期推理的完整性，迫切需要更主動且智慧的上下文管理策略。

**Q2：現有的被動壓縮方法為何不足以應對長程任務？**
A：現有的被動方法（例如超過長度閾值後才摘要互動歷史，或僅保留部分工具輸出）本質上缺乏事前規劃，往往等到上下文預算耗盡後才進行壓縮。這類方法透過固定規則無差別地捨棄過往觀察，容易遺失對後續推理至關重要的關鍵資訊。相較於主動預判哪些資訊值得保留或委派，被動壓縮是一種消極的後處理手段，無法策略性地維護主智能體對任務全貌的理解。

**Q3：為何「委派智能」對智能體大型語言模型至關重要？**
A：委派智能是指主智能體能夠分解複雜任務、判斷何時與委派何種工作給子智能體，並將回傳結果整合至持續進行的工作流程中的能力。缺乏此能力，智能體將被執行細節與冗餘資訊淹沒，無法有效管理長程任務的上下文負載。它將上下文管理從被動的清理作業轉變為主動的規劃機制，使模型得以像人類管理者協調團隊般，在有限資源下完成深度研究。

**Q4：SearchSwarm 的核心方法論是什麼？**
A：SearchSwarm 採用「主分派-子執行」範式，由主智能體負責規劃並將有界子任務分派給具備獨立上下文的子智能體，再整合其摘要結果。主智能體在 ReAct 框架下運作，交替進行推理與工具呼叫，其中包含專門的 call_sub_agent 工具來觸發委派。每個子智能體在獨立環境中接收簡報後執行子任務，並回傳精簡的報告，從而有效節省主智能體寶貴的上下文預算。

**Q5：SearchSwarm 在獲取委派智能方面的關鍵創新是什麼？**
A：關鍵創新在於設計了一套導引架構，能在推論階段引發高品質的委派行為，並將產生的軌跡作為監督式微調資料，將這些決策模式內化至模型權重中。不同於先前僅聚焦高階架構或強化學習的研究，本文提供了涵蓋導引架構設計、訓練資料建構與模型訓練的完整開源配方。這種方法系統性地合成了自然語料中極為稀缺的委派協調資料，使原本不具備委派智能的模型能透過學習獲得此能力。

**Q6：導引架構的關鍵設計原則有哪些？**
A：導引架構包含四項核心原則：鼓勵主智能體將低階執行工作委派出去，同時保持對整體研究進度的獨立理解；要求主智能體撰寫全面簡報，不僅說明子任務內容，還須闡述其重要性與在整體目標中的定位；確保主智能體保留核心判斷力，而非盲目接受子智能體輸出；並約束子智能體提供附帶明確來源引註的報告。這些設計使子智能體能進行聚焦研究、避免冗餘探索，同時讓主智能體得以驗證結論並將引註傳遞至最終回覆，提升可信度。

**Q7：SearchSwarm 在哪些基準測試上進行了評估？**
A：SearchSwarm 在四項基準上接受評估，分別是測試英文與中文網頁瀏覽及資訊檢索能力的 BrowseComp 與 BrowseComp-ZH、評估通用 AI 助理能力的 GAIA，以及衡量深度搜尋表現的 xbench-DeepSearch-2505。這些基準均屬於需要多輪資訊搜集、驗證與綜合的長程智能體任務。透過跨語言與跨領域的多元測試，研究團隊得以驗證模型在不同深度研究情境下的穩健性。

**Q8：SearchSwarm-30B-A3B 取得了哪些關鍵實驗結果？**
A：SearchSwarm-30B-A3B 在 BrowseComp 獲得 68.1 分、BrowseComp-ZH 獲得 73.3 分、GAIA 獲得 82.5 分，並在 xbench-DeepSearch-2505 獲得 80.8 分，均為同等規模模型中的最佳表現。值得注意的是，它不僅超越了 EDSearcher、Morph 等輕量級對手，甚至能與規模大上十倍以上的閉源模型保持競爭力。這些結果證明，有效的委派智能能顯著放大中等規模模型的能力，無需僅仰賴參數量的暴力擴展。

**Q9：與 AgentSwarm 等其他多智能體方法相比，SearchSwarm 有何不同？**
A：AgentSwarm 採用凍結子智能體參數並以強化學習訓練主智能體分派策略的做法，而 SearchSwarm 則著重透過導引架構合成高品質監督式微調資料，將委派行為內化至模型權重。兩者雖皆採用主分派-子執行架構，但 SearchSwarm 提供了更完整的開源配方，涵蓋導引架構設計、軌跡篩選與訓練流程。其在 BrowseComp 等基準上的優越表現顯示，導引架構輔助的監督式微調可能是比純強化學習更具資料效率且可解釋的委派智能獲取途徑。

**Q10：在哪些實際應用場景中，SearchSwarm 的委派智能最具價值？**
A：SearchSwarm 的委派智能在需要廣泛多源研究的場景特別有價值，例如學術文獻回顧、市場競爭分析、法律案件準備以及複雜技術故障排除。這些領域的任務天然涉及數十次的搜尋查詢與工具互動，單一智能體的上下文視窗很快便會耗盡。透過將平行的子調查委派給專責子智能體，同時由主智能體維持連貫的監督，系統得以完成單體架構無法勝任的全面性研究。

**Q11：從產品層面來看，導引架構設計帶來哪些優勢？**
A：導引架構要求子智能體在報告中附上明確的來源引註，主智能體可據此驗證並將引註傳遞至最終答案，從而提升使用者信任與結果可驗證性。透過在簡報中闡述子任務在整體研究目標中的定位，也能避免子智能體進行冗餘探索，顯著提升執行效率。此外，由於主智能體保留了獨立的核心判斷力而非將全部推理過程外包，系統能維持連貫的敘事控制，並及時發現子智能體輸出中的不一致之處。

**Q12：這項工作可能對開源智能體社群帶來什麼影響？**
A：透過開源導引架構、模型權重與訓練資料，本研究提供了開發委派智能的完整配方之一，有望加速多智能體協調相關研究。它證明了先進的長程任務能力不必被鎖死在巨大的閉源模型之後，策略性的架構創新即可讓較小模型達到具競爭力的表現。這種委派智能的民主化可能為開源智能體框架如何處理上下文管理與任務分解樹立新標準，激發更多社群創新。

**Q13：作者承認了哪些方法上的局限性？**
A：作者將此工作定位為「初步探索」，暗示導引架構與訓練流程可能尚未完全最佳化，也未必能泛化至深度研究以外的所有長程任務類型。由於依賴導引架構產生的軌跡進行監督式微調，最終模型的品質上限受制於導引架構引發正確委派決策的能力，可能無法涵蓋所有邊緣案例。此外，評估主要聚焦於研究導向基準，對於如何遷移至物理機器人控制或多模態任務等其他領域，仍屬未解問題。

**Q14：哪些類型的任務或情境可能導致 SearchSwarm 失效？**
A：對於需要極度緊密串列依賴的任務，其中每個微步驟都必須由中央即時協調，主智能體與子智能體間的簡報溝通可能帶來延遲或對齊誤差。若主智能體錯誤分解任務或提供缺乏關鍵脈絡的簡報，子智能體可能執行有界但無關的子任務，導致上下文預算浪費在無用資訊上。此外，對於無法模組化為獨立研究線索、需要深度創造性綜合的任務，主分派-子執行的範式可能難以適用。

**Q15：這項工作指出了哪些未來研究方向？**
A：未來研究可將導引架構範式擴展至深度研究以外的長程領域，例如軟體工程、科學實驗設計或多模態內容創作。研究者亦可探索結合導引架構監督式微調與強化學習的混合訓練方法，根據任務結果進一步精煉委派策略。另一個有前景的方向是開發自適應導引架構，使其能依據任務複雜度與剩餘上下文預算的即時評估，動態調整子智能體簡報內容與回報約束條件。

## 實務應用指南

### 適用場景

**1. 企業級深度市場研究與競品分析**
當研究範圍橫跨多國市場、產品線與財報季，單一智能體的上下文視窗極易耗盡。SearchSwarm 適合由主智能體規劃研究架構，再將各國市場規模、競品定價策略、專利佈局等子任務委派給獨立子智能體，最終整合為具備明確引用來源的綜合報告。

**2. 法律與監管盡職調查**
法規查核通常需檢索跨司法管轄區的大量條文、判例與行政函釋。透過委派智能，主智能體可將「美國證券法第 10(b) 條解釋」、「歐盟 AI 法案合規性」等子任務分派給不同子智能體，並要求回傳結果附上法條出處，由主智能體進行核心判斷與交叉驗證。

**3. 學術文獻回顧與綜述生成**
在需要追蹤數十篇以上論文的研究領域，主智能體可依主題（如模型架構、訓練方法、評測基準）拆分任務，讓子智能體在獨立上下文中執行精讀與摘要，再將帶有明確引用標註的報告整合為連貫的文獻綜述，避免傳統單一模型常見的引用幻覺。

**4. 臨床醫療決策支援**
針對罕見疾病或跨科別診療，系統可委派子智能體分別檢索最新臨床試驗、藥物交互作用與診療指引。主智能體保留對病人整體病歷與治療目標的核心判斷權，僅將特定醫學問題外包查證，確保最終建議的證據等級與可追溯性。

**5. 金融投資深度研究報告**
涵蓋總體經濟指標、產業供應鏈、個股財務模型與 ESG 評分的長程研究，可由主智能體協調多個子智能體並行分析，各自回傳結構化摘要。主智能體再將這些有界結果納入自身的論證鏈，生成具備資料來源註記的最終投資建議。

### 實作前置條件

**資料需求**
- 基礎模型：建議採用 30B 規模左右、具備工具使用能力的開源模型（如本文使用的 SearchSwarm-30B-A3B 或同等級模型）作為起點。
- 合成訓練資料：需具備搜尋、網頁瀏覽與 Python 執行等工具環境，以運行導引架構（Harness）生成高品質委派軌跡；或直接使用作者開源的訓練資料與模型權重。
- 檢索基礎設施：可呼叫的搜尋引擎 API、學術資料庫（如 Google Scholar）與網頁瀏覽工具，供主智能體與子智能體使用。

**運算需求**
- 訓練階段：需具備多卡 A100 / H100 等級 GPU 叢集，以執行監督式微調（SFT）；30B 模型全參數微調通常需數十 GB 至上百 GB 的 VRAM，若資源有限可考慮 LoRA / QLoRA 等參數高效微調方法。
- 推論階段：需支援主智能體與多個子智能體並行運算的分散式推論架構，確保子任務能同時執行以降低總延遲。

**技能需求**
- 熟悉 ReAct 或類似工具使用框架，能設計 Thought-Action-Observation 循環。
- 具備大型語言模型微調經驗（資料清洗、損失函數設計、超參數調校）。
- 具備分散式系統基礎，能管理獨立上下文視窗與子智能體生命週期。

### 實作步驟建議

**步驟一：建構工具與檢索基礎設施**
部署搜尋 API、網頁瀏覽器工具與程式碼執行環境，確保主智能體與子智能體皆能發出工具呼叫並取得結構化結果。建議先以 BrowseComp 或內部評測集驗證基礎工具鏈的可靠性。

**步驟二：設計導引架構（Harness）**
依據本文四項原則實作導引機制：
1. **鼓勵委派**：在主智能體的系統提示中明確獎勵使用 `call_sub_agent` 工具，並懲罰過度冗長的單輪搜尋。
2. **撰寫全面簡報（Brief）**：要求主智能體在委派時提供「任務描述」與「委派理由」，說明子任務如何銜接整體研究目標。
3. **保留核心判斷**：限制主智能體不得將整體策略規劃與最終綜合判斷外包，僅委派執行層級的資訊搜集。
4. **要求引用標註**：強制子智能體回傳報告時必須包含明確來源引用，使主智能體能驗證並將引用傳播至最終回覆。

**步驟三：生成並過濾高品質軌跡**
在導引架構下執行大量深度研究任務，收集主智能體的分解決策、簡報內容與子智能體回傳結果。過濾條件應包含：子任務邊界是否清晰、簡報是否包含理由說明、子報告是否附帶引用、主智能體是否正確整合結果。僅保留通過品質閘道的軌跡作為訓練資料。

**步驟四：監督式微調（SFT）內化委派智能**
將過濾後的軌跡轉換為 SFT 格式（通常為對話或 ReAct 序列），對基礎模型進行全參數或參數高效微調。訓練目標是讓模型學習「何時分解」、「如何界定子任務範圍」、「如何撰寫有效簡報」以及「如何整合摘要結果」的決策模式。

**步驟五：部署主分派-子執行推論系統**
在生產環境中實作主智能體與子智能體的協作流程。主智能體運行於主要上下文，透過 `call_sub_agent` 觸發子智能體；每個子智能體在獨立上下文視窗中執行多輪工具互動，完成後回傳精簡報告並釋放資源。主智能體再將報告納入自身推理鏈，決定下一步行動或產出最終答案。

**步驟六：持續評估與迭代**
使用 BrowseComp、GAIA、xbench-DeepSearch 等基準進行自動化評估，同時輔以人工審查委派決策的合理性。針對錯誤案例（如過度委派導致資訊遺失、簡報不足導致子智能體偏離目標）重新生成軌跡並進行增量微調。

### 潛在風險與注意事項

**委派過度或委派不足**
若主智能體過度依賴子智能體，可能將應由自身保留的核心策略判斷外包出去，導致整體研究方向偏離；反之，若委派不足，則主智能體上下文迅速耗盡，喪失多智能體架構的優勢。建議在 Harness 中明確劃分「規劃與判斷」與「執行與檢索」的職責邊界。

**子智能體回傳品質不穩定**
子智能體可能產生未經查證的內容或遺漏關鍵引用。必須在 Harness 中強制要求回傳格式包含「來源引用」與「信心程度」，並讓主智能體具備驗證與拒絕低品質報告的能力，而非被動接受所有子結果。

**延遲與成本膨脹**
並行子智能體雖能縮短總執行時間，但每個子任務皆消耗額外的推論 token 與 API 呼叫成本。建議為子任務設定嚴格的輪次上限與輸出長度上限（有界子任務），並在產品層面提供「快速模式」（減少委派深度）與「深度模式」的選項。

**上下文同步與引用傳播錯誤**
主智能體在整合多份子報告時，可能錯誤歸因引用來源或遺漏關鍵證據。可在架構層面要求子智能體使用結構化輸出（如 JSON 格式的引用清單），並讓主智能體在最終生成階段強制執行引用一致性檢查。

**幻覺與責任歸屬**
多智能體系統的錯誤鏈條較長，當最終答案出現幻覺時，難以追溯是主智能體的整合錯誤還是子智能體的檢索失誤。建議建立完整的軌跡日誌（trajectory logging）與可解釋性介面，讓使用者能夠逐層檢視委派決策與資料來源。

### 與其他技術的整合建議

**與檢索增強生成（RAG）的整合**
SearchSwarm 並非取代 RAG，而是處理 RAG 難以應對的長程、多跳、動態規劃場景。建議將向量資料庫作為子智能體的局部知識來源，讓子智能體在執行特定領域子任務時先查詢內部知識庫，再輔以網路搜尋；主智能體則專注於協調與綜合，避免直接處理大量原始文件片段。

**與強化學習（RL）或偏好最佳化的整合**
本文採用監督式微調作為初步探索，但未來可將 Harness 生成的軌跡作為冷啟動資料，再進一步使用 RL（如 PPO、GRPO）或 DPO 對委派策略進行偏好對齊。例如，對同一問題的多條委派路徑進行勝出/落敗標註，訓練模型學習更精準的時機判斷。

**與現有工作流程編排工具的整合**
相較於 LangChain、LlamaIndex 等框架中常見的預先定義 DAG（有向無環圖），SearchSwarm 的委派智能讓主智能體能根據中間結果動態決定後續子任務。建議將 SearchSwarm 作為「動態規劃層」，嵌入現有編排框架中：由 SearchSwarm 負責高層次的任務分解與委派，底層仍使用既有工具節點執行具體操作。

**與可觀測性平台的整合**
多智能體系統的除錯難度遠高於單一模型。建議整合如 LangSmith、Weights & Biases 或自研追蹤系統，對每次 `call_sub_agent` 的輸入簡報、子智能體工具呼叫序列、回傳報告與主智能體的整合決策進行結構化記錄，並設置異常告警（如子任務超時、引用缺失率過高）。

### 給不同背景讀者的閱讀建議

**給初學者**
請將 SearchSwarm 想像成一位「研究專案經理」：一位經驗豐富的主智能體將龐雜的調查工作拆分給多位專員（子智能體），專員各自查資料後回報重點，經理再彙整成最終報告。閱讀時請先聚焦在論文的圖二與四項 Harness 原則，理解「為什麼要委派」與「如何確保品質」，暫時不必深入監督式微調的技術細節。

**給 AI 工程師**
本文的核心價值在於提供一套可落地的「委派智能」訓練配方。請重點研讀 Method 章節中 Harness 的設計細節，特別是簡報（Brief）的內容結構、子智能體的獨立上下文隔離機制，以及軌跡過濾的條件設定。在實作上，建議優先復現作者開源的 Harness 與訓練資料，再根據自身業務場景調整工具集與輸出格式約束。

**給研究人員**
SearchSwarm 提出了一個在開源社群中尚未被充分探索的問題：如何系統性地合成「委派智能」的訓練資料。請關注本文將「推論時間導引（inference-time harness）」轉化為「模型權重內化」的方法論，並思考其與 Kimi Team 的 AgentSwarm（強化學習路線）的互補性。未來研究可探索更複雜的委派層級（如子智能體再委派）、多模態場景下的上下文管理，以及主智能體的元認知（metacognition）能力。

**給產品經理**
SearchSwarm 的商業價值在於以輕量級模型（30B）達到媲美十倍以上規模模型的深度研究表現，同時提供可追溯的引用鏈。評估導入時，請權衡「深度模式」帶來的延遲與成本增加，以及使用者對「答案可驗證性」的需求。建議將本技術定位於專業研究場景（如金融、法律、醫療）的差異化功能，並在 UX 設計上凸顯主智能體的推理步驟與子任務來源，以建立使用者信任。
