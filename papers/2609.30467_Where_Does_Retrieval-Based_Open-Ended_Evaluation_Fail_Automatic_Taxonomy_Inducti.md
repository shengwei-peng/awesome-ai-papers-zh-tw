## 摘要翻譯

基於檢索的事實性評估（Retrieval-based factuality evaluation）——將大型語言模型生成的聲稱（LLM-generated claims）對照權威醫學語料庫（authoritative medical corpora）中的證據進行驗證——已成為高風險臨床場景（high-stakes clinical settings）中可擴展的幻覺檢測（hallucination detection）之主導典範。儘管可靠且透明的醫學事實驗證具有急迫性，大多數系統仍以 F1 分數（F1）等聚合指標（aggregate metrics）衡量效能，遮蔽了失敗發生的位置與原因。現有的 RAG 診斷（RAG diagnostics）需要黃金答案（gold answers）或註釋黃金證據（annotated gold evidence），而兩者在此範式下皆不存在。我們提出兩套全面的分類法（taxonomies），奠基於一項針對開放式 MedExpert 資料集（MedExpert dataset）與三個封閉式資料集（closed-ended datasets）的案例研究，將失敗拆解為檢索階段錯誤（retrieval-stage errors，沿五個品質維度（quality dimensions））與驗證器推理錯誤（verifier-reasoning errors，分為六個連續步驟）。我們調整一套以大型語言模型作為評判者（LLM-as-Judge）的自動模式歸納流程，大規模標註證據品質（evidence quality）並分類驗證器推理錯誤，接著橫跨四種檢索方法（retrieval methods）與六個前沿驗證器模型（verifier models）進行壓力測試。我們的分析顯示，擴增模型規模（scaling model size）、增加推理投入（reasoning effort）、擴展至權威網路來源（authoritative web sources），以及應用醫學微調（medical fine-tuning），都無法解決這些失敗模式，顯示它們代表了先檢索後驗證典範（retrieve-then-verify paradigm）在開放式醫學情境（open-ended medical settings）中的根本性限制，而非過時系統所造成的人為產物。我們於 https://anonymous.4open.science/r/Medical_RAG_eval-4AB5 公開釋出程式碼與資料，以確保研究結果的完整可重現性。

### 核心貢獻（3～5點）
- 提出兩套全面的錯誤分類法，分別針對檢索階段錯誤（五個品質維度）與驗證器推理錯誤（六個連續步驟），填補開放式醫學問答中缺乏黃金答案與註釋黃金證據的診斷缺口。
- 開發以大型語言模型作為評判者（LLM-as-Judge）的自動模式歸納流程，大規模標註證據品質並分類驗證器推理錯誤。
- 橫跨四種檢索方法與六個前沿驗證器模型進行壓力測試，發現擴增模型規模、增加推理投入、擴展至權威網路來源與醫學微調均無法解決既有失敗模式。
- 論證這些失敗並非過時系統的人為產物，而是先檢索後驗證典範在開放式醫學情境中的根本性限制。

### 適合對象
適合從事醫學問答系統、檢索增強生成（RAG）評估、大型語言模型（LLMs）事實性驗證與幻覺檢測的研究者與工程師，特別是關注高風險臨床場景中開放式醫學答案可信度與透明化診斷的讀者。

## 深度分析

#### 方法論解析（Methodology Analysis）

本研究聚焦於 **Retrieval-based open-ended evaluation（基於檢索的開放式評估）** 在 **Long-form medical answer（長篇醫學答案）** **Factuality verification（事實性驗證）** 中的失敗模式。核心方法並非提出一個新的驗證系統，而是建立一套可自動歸納的 **Error taxonomy（錯誤分類法）**，將 retrieve-then-verify pipeline（先檢索後驗證流程）的失敗拆解為兩大階段：**Retrieval-stage errors（檢索階段錯誤）** 與 **Verification-stage errors（驗證階段錯誤）**。

實驗資料包含開放式與封閉式兩類。開放式資料採用 **MedExpert dataset（MedExpert 資料集）**，涵蓋 540 組由臨床醫師標註事實性與嚴重程度的醫學問答，專注於心理健康（Mental Health）與產前照護（Prenatal Care）兩個專科。封閉式資料則選用 **SciFact**、**PubHealth** 等 **Closed-ended datasets（封閉式資料集）**，透過將其原有的小型證據語料替換為 30.3M 篇段的 **MEDIC** 語料庫，並轉換為統一的 `{id, claim}` 格式，使其能模擬開放式驗證情境。

方法流程分為兩個階段。第一階段是標準的 decompose-then-verify pipeline：將模型生成的長篇回應拆解為 **Atomic claims（原子聲稱）**，針對每個原子聲稱檢索 top-k（k=10）醫學段落，再由 **LLM verifier（大型語言模型驗證器）** 給出四向裁決（Supported／Refuted／No Evidence／Ambiguous）。第二階段則將 LLM verifier 的裁決與人類對母句的 True／False 標籤比對；當兩者不一致時，進入錯誤歸因分析。

本研究的創新在於利用 **LLM-as-Judge（以大型語言模型作為評判者）** 的 human-in-the-loop 自動模式歸納管線，對這些不一致案例進行大規模標註與分群。由於開放式場景中不存在 **Gold answers（黃金答案）** 或 **Annotated gold evidence（註釋黃金證據）**，因此該管線完全不需要參考答案即可歸納錯誤類型。

最終歸納出的檢索階段錯誤包含六個具體模式，橫跨五個品質維度：

- **R1 Irrelevant evidence（不相關證據）**：檢索結果與聲稱主題無關（35%）。
- **R2 Partial topical match（部分主題匹配）**：僅在表面主題上部分重疊（32%）。
- **R3 Mismatch clinical scope（臨床範圍不匹配）**：證據雖屬醫學領域，但臨床情境、族群或適應症不符（71.5%）。
- **R4 Trustworthiness（可信度不足）**：來源不可靠或權威性不足（62%）。
- **R5 Evidence polarity（證據極性問題）**：段落僅提及主題但未包含可驗證該命題的明確主張，例如「topic mention without proposition」（55%）。
- **R6 Chunking issues（分塊問題）**：段落切分導致語境斷裂或資訊遺漏（9%）。

驗證階段錯誤則對應 verifier 推理鏈的六個連續步驟：

- **V1 Incorrect evidence selection（錯誤的證據選擇）**：選擇性覆蓋（selective coverage，20.8%）。
- **V2 Failure in evidence comprehension（證據理解失敗）**：未能正確理解檢索內容（15.6%）。
- **V3 Insufficient reasoning（推理不足）**：推論過度延伸（inferential overreach，18.8%）。
- **V4 Inconsistency（不一致）**：無法整合衝突證據（conflict synthesis failure，11.5%）。
- **V5 Overconfidence（過度自信）**：在不確定情況下仍給出強烈裁決（12.5%）。
- **V6 Hallucinations（幻覺）**：無根據推理（ungrounded reasoning，4.2%）。

這種將錯誤歸因於「證據品質瓶頸」或「驗證器推理瓶頸」的設計，使得診斷不再僅止於最終的 **Aggregate metrics（聚合指標）**（如 **F1**），而能指出系統在何處、以何種方式失效。

#### 實驗數據解讀（Experimental Data Interpretation）

本研究進行了大規模壓力測試，橫跨 6 個 frontier **Verifier models（驗證器模型）**、4 種 **Retrieval methods（檢索方法）** 與 3 個 **Knowledge corpora（知識語料庫）**。最關鍵的發現是：**Scaling model size（擴增模型規模）**、增加 **Reasoning effort（推理投入）**、擴展至 **Authoritative web sources（權威網路來源）**、以及 **Medical fine-tuning（醫學微調）**，都無法顯著消解主要的失敗模式。這暗示這些問題並非舊系統的人為缺陷，而是 **Retrieve-then-verify paradigm（先檢索後驗證典範）** 在開放式醫學場景中的結構性限制。

從檢索階段的錯誤分佈來看，**R3 Scope mismatch（臨床範圍不匹配）** 以 71.5% 居首，顯示檢索器雖能找回醫學相關文本，卻經常無法對齊正確的臨床情境。其次 **R4 Unreliable source（不可靠來源）** 佔 62%，反映醫學資訊的 **Trustworthiness（可信度）** 是重大瓶頸；**R5 Topic mention without proposition（僅提及主題而無命題）** 佔 55%，則說明 lexical matching（詞彙匹配）容易產生「看起來相關、實則無法驗證」的段落。相較之下，**R6 Chunking issues（分塊問題）** 僅 9%，表示單純的段落切分並非當前最關鍵的問題。值得注意的是，這些百分比加總超過 100%，意味著單一錯誤案例可能同時具備多種檢索缺陷，進一步凸顯 **Evidence quality（證據品質）** 的複雜性。

在驗證階段，錯誤分佈相對分散：**V1 Selective coverage（選擇性覆蓋，20.8%）** 與 **V3 Inferential overreach（推論過度延伸，18.8%）** 最為突出，顯示 verifier 常在證據不足時做出推論，或只選擇性採納部分證據。**V2 Comprehension failure（理解失敗，15.6%）** 與 **V5 Overconfidence（過度自信，12.5%）** 則指出即使面對已檢索到的證據，模型仍可能誤讀或過度確信。這些結果意味著：提升 verifier 的參數量或加入更多推理步驟，並未從根本改善其對醫學證據的選擇、理解與校準能力。

整體而言，實驗數據挑戰了一個常見假設：只要使用更大的模型、更多資料、更權威的網路來源，就能解決醫學 **Hallucination detection（幻覺檢測）** 問題。相反地，數據顯示在 **Open-ended fact verification（開放式事實驗證）** 中，聲稱本身可能是 **Parametric fabrication（參數化虛構）**，或需要跨多篇文獻綜合，而 top-k 檢索片段往往無法提供充分、正確且可對齊臨床範圍的證據。因此，單純優化 end-to-end **F1** 會掩蓋這些結構性瓶頸。

#### 與現有研究的比較（Comparison with Existing Research）

在封閉式事實驗證領域，**FEVER**、**SciFact**、**HealthVer**、**CovidFact**、**PubHealth** 等 **Closed-ended datasets（封閉式資料集）** 都提供 **Gold answers（黃金答案）** 與 **Annotated gold evidence（註釋黃金證據）**，因此可以計算 **Evidence precision@k（證據精確率@k）** 與 **Evidence recall@k（證據召回率@k）**，並發展出 **RAG diagnostics（RAG 診斷）** 工具如 RAGChecker、MedRAGChecker 等。然而，這些方法都依賴參考答案或醫師撰寫的 must-have statements，無法直接應用於沒有標準答案的開放式醫學問答。

在開放式事實驗證方面，**FActScore** 與 **MedScore** 等先行研究已將 **Retrieval-based factuality evaluation（基於檢索的事實性評估）** 應用於長篇生成文本，但它們主要輸出聚合分數與 verifier 的純文字推理，對於檢索階段發生什麼問題、verifier 在哪一步推理失誤，仍然是一個 **Blackbox（黑箱）**。本研究首次在無參考答案的開放式醫學場景中，系統性地拆解 **Retrieval-stage errors（檢索階段錯誤）** 與 **Verifier-reasoning errors（驗證器推理錯誤）**，並透過自動歸納管線將分析規模化。

相較於既有研究，本論文的貢獻在於「診斷」而非「治療」：它不提供一個新的 SOTA 驗證模型，而是提供一套可重複使用的評估協議，讓研究者能更具體地定位失敗來源。這對 **High-stakes clinical settings（高風險臨床場景）** 尤其重要，因為在臨床應用中，知道系統「為何出錯」往往比知道「整體 F1 下降多少」更有價值。

然而，本研究也存在若干限制。首先，錯誤歸因依賴 **LLM-as-Judge（以大型語言模型作為評判者）**，而 LLM judge 本身可能帶有偏見或產生新的幻覺，特別是在醫學專業判斷上。其次，原子聲稱預設繼承母句的人類標籤，可能忽略同一句子中部分原子聲稱為真、部分為假的細微差別。第三，MedExpert 僅涵蓋兩個專科，且封閉式資料經轉換後未必能完整反映真實長篇醫學答案的複雜度。最後，由於沒有 gold evidence，檢索錯誤與驗證錯誤之間的界線有時難以完全確定，某些案例可能同時涉及兩者。

#### 可重現性評估（Reproducibility Assessment）

本論文宣稱將 **Code and data（程式碼與資料）** 釋出於 https://anonymous.4open.science/r/Medical_RAG_eval-4AB5，以達成完整可重現性。從研究設計來看，所使用的資料集多為公開資料（MedExpert、SciFact、PubHealth 等），理論上其他研究者可以取得原始資料並執行相同的轉換與檢索流程。釋出的程式碼應包含 decompose-then-verify pipeline、錯誤歸因邏輯，以及 **LLM-as-Judge（以大型語言模型作為評判者）** 的提示樣板，這對重現分類法歸納過程至關重要。

不過，可重現性仍面臨幾項挑戰。第一，6 個 frontier **Verifier models（驗證器模型）** 與 4 種 **Retrieval methods（檢索方法）** 若主要透過商業 API（如 OpenAI、Anthropic）呼叫，則 API 的溫度設定、模型版本更新、以及潛在的非確定性輸出，都可能使不同時間點的實驗結果產生差異。第二，若研究中使用了醫學微調模型，論文未明確說明是否釋出模型權重；若僅使用 API 或私有權重，則其他研究者難以完全複製「medical fine-tuning」條件下的結果。第三，匿名審查階段提供的連結通常為臨時性連結，正式發表後需要轉移至持久化儲存庫（如 Zenodo、GitHub、Hugging Face），並提供版本控制、隨機種子、API 版本紀錄，以及詳細的超參數與提示詞，才能稱得上真正可重現。

建議作者在未來版本中補充：每個模型的確切名稱與版本、所有 LLM-as-Judge 提示詞、檢索器的超參數、chunking 策略、以及人類標註與自動標註的一致性統計（inter-annotator agreement）。這些資訊將大幅提升社群對研究結論的信任度。

#### 未來研究方向（Future Research Directions）

基於本研究的發現，未來研究可從以下幾個方向推進：

1. **命題層級檢索（Proposition-level retrieval）**：目前的 top-k 段落檢索容易產生 R2、R5 等「主題相關但無命題」的問題。未來可發展以醫學命題或知識圖譜節點為單位的 dense retrieval，減少 lexical matching 帶來的雜訊。

2. **來源可信度動態評分（Dynamic source trustworthiness scoring）**：鑒於 R4 Unreliable source 佔比極高，未來系統應在檢索階段即納入來源權威性、發表期刊、證據等級（如 RCT、系統性回顧）等訊號，並在驗證時進行動態加權或過濾。

3. **可解釋的 verifier 架構**：設計具備明確證據選擇與 chain-of-thought auditing 的 verifier，讓 V1–V6 的每一個推理步驟都可被檢查與修正，並結合不確定性量化（uncertainty quantification）與適當的棄權機制。

4. **多跳檢索與跨文件綜合（Multi-hop retrieval & cross-document synthesis）**：許多醫學聲稱需要整合多份文獻才能驗證，未來應強化檢索器在文件間建立推理鏈的能力，以減少 V3 Inferential overreach 與 V4 Conflict synthesis failure。

5. **更精細的聲稱分解**：改進 atomic claim decomposition，使其能保留臨床範圍、否定詞、數值條件與適應症脈絡，從源頭降低 R3 Scope mismatch 的發生率。

6. **參數知識與檢索知識的混合驗證**：針對 **Parametric fabrication（參數化虛構）** 的聲稱，未來可探索如何讓 verifier 辨識「此聲稱在語料庫中無對應證據」與「此聲稱與語料庫矛盾」之間的差異，避免將無證據誤判為支持或反駁。

7. **人機協作驗證（Human-in-the-loop verification）**：在臨床部署中，可將本研究的錯誤分類法轉化為互動式警告介面，讓醫師快速理解系統不確定之處，並決定是否介入。

8. **擴展至多專科、多語言與真實臨床紀錄**：未來應在更多醫學專科、不同語言，以及真實電子病歷（EHR）或臨床筆記上驗證此分類法的通用性。

9. **建立中間標註基準**：推動社群建立包含證據品質、verifier 推理步驟等中間標註的開放式醫學事實驗證 benchmark，使未來的 **RAG diagnostics（RAG 診斷）** 能在開放式場景中進行更細緻的評估。

## 論文問答

**Q1：為什麼在開放式醫學問答中，傳統的 F1 等聚合指標無法充分評估檢索式事實性驗證系統的可靠性？**  
A：F1 分數只呈現整體正確率，無法區分錯誤究竟來自檢索階段還是驗證器推理階段。在開放式醫學答案中，原子聲稱來自大型語言模型的長篇生成，沒有黃金答案或註釋黃金證據可供對照，因此封閉式診斷方法難以定位問題根源。這會遮蔽不相關證據、臨床範圍不匹配、證據極性錯誤等關鍵失敗模式，使開發者誤以為系統整體表現良好。

**Q2：現有的 RAG 診斷工具（如 RAGChecker、MedRAGChecker）為何無法直接應用於開放式醫學事實驗證？**  
A：這些工具需要黃金答案或醫師撰寫答案中的必備陳述來錨定檢索結果，但開放式設定中根本不存在這類參考答案。此外，大型語言模型生成的原子聲稱過於多樣，有些甚至是參數化虛構，使證據召回率@k 在原則上無法定義。因此現有方法只能把檢索當成黑箱，無法對檢索品質進行系統性的錯誤分析。

**Q3：為什麼在高風險臨床場景中，診斷「先檢索後驗證」管線的失敗位置特別重要？**  
A：醫療錯誤資訊可能導致錯誤診斷或治療決策，因此必須釐清幻覺是來自檢索到的證據品質不佳，還是驗證器推理錯誤。只有區分檢索階段錯誤與驗證階段錯誤，開發者才能針對性地改進檢索器、證據分塊策略或驗證器提示。這種細粒度診斷比單純提升 F1 分數更能反映系統在真實臨床問答中的能力與風險。

**Q4：本文提出的錯誤分類法包含哪兩大階段，各自涵蓋哪些核心維度？**  
A：分類法分為檢索階段錯誤與驗證階段錯誤兩大部分。檢索階段從五個品質維度細分：不相關證據、臨床範圍不匹配、可信度、證據極性與分塊問題。驗證階段則細分為六個連續推理步驟的錯誤：錯誤的證據選擇、證據理解失敗、推理不足、過度自信、不一致與幻覺。

**Q5：作者如何利用 LLM-as-Judge 在沒有黃金答案或註釋黃金證據的情況下自動歸納錯誤模式？**  
A：他們先執行常見的分解—檢索—驗證管線，將大型語言模型生成的長篇答案拆成原子聲稱，並從 MEDIC 等權威醫學語料庫檢索前 10 篇段落。接著比較驗證器的四向裁決與人類對母句的真假標籤，針對不一致案例由 LLM-as-Judge 自動標註證據品質並歸類驗證器推理錯誤。這種人機協作的歸納流程可在無黃金證據的開放式情境中規模化地建立錯誤分類法。

**Q6：相較於既有開放式事實性評估方法（如 FActScore、MedScore），本文的診斷框架有何關鍵不同？**  
A：FActScore 與 MedScore 主要輸出端到端聚合分數與驗證器的純文字推理，難以定位管線失敗的確切環節。本文則把檢索與驗證兩個階段解耦，並提出多維度、可自動誘導的錯誤分類法。如此一來，研究者能直接觀察到是檢索證據本身有瓶頸，還是驗證器在證據選擇、理解或綜合推理上出錯。

**Q7：實驗使用了哪些資料集與知識語料庫來驗證分類法的泛用性？**  
A：開放式資料集使用 MedExpert，包含 540 道由臨床醫師標註真實性與嚴重程度的醫學問答。此外，作者將數個封閉式醫學事實查核資料集轉換為開放式格式，並以 3030 萬篇段落的 MEDIC 語料庫取代其原本的小型精選證據庫。這樣的設計能測試分類法在沒有黃金答案與註釋黃金證據時的適用性與泛化能力。

**Q8：實驗中發現哪些主要失敗模式，且這些模式是否會因為模型規模擴增、推理投入或醫學微調而消失？**  
A：檢索階段常見的失敗包括臨床範圍不匹配、不可靠來源、僅提及主題但無命題支撐的段落等；驗證階段則有選擇性覆蓋、推理過度延伸、衝突綜合失敗與過度自信等。研究發現，即使擴增驗證器模型規模、增加推理投入、擴展到權威網路來源或進行醫學微調，這些主要失敗模式仍然持續存在。這顯示它們並非舊系統的人為現象，而是「先檢索後驗證」典範在開放式醫學情境中的根本性限制。

**Q9：在檢索錯誤與驗證錯誤中，哪些子類型的比例特別值得注意？**  
A：根據錯誤模式歸納結果，檢索階段中臨床範圍不匹配約佔七成、不可靠來源約六成、主題提及但無命題支撐約五成以上，顯示檢索器難以精準對應臨床問題的專業範圍與證據可信度。驗證階段中，選擇性覆蓋約兩成、推理過度延伸約一成九、過度自信約一成三，反映驗證器容易忽略關鍵證據或做出超出證據的推論。這些比例說明單純改進檢索器或驗證器都不足以解決開放式醫學事實性驗證的挑戰。

**Q10：這套錯誤分類法與評估協議對實務上的醫療問答產品開發有何具體幫助？**  
A：產品團隊可以利用分類法進行多維度評估，先判斷錯誤是出在檢索到的證據品質，還是驗證器的推理過程，再針對性地優化。例如，若發現大量分塊問題導致證據不完整，可改進段落切分策略；若驗證器過度自信，則可加強不確定性校準或要求顯示證據鏈。這種任務導向的評估比只看聚合 F1 分數更能忠實反映系統能力，並降低患者面對錯誤醫療資訊的風險。

**Q11：在面向患者的問答、報告生成與摘要等應用中，為什麼不能僅依賴端到端事實性分數？**  
A：端到端分數無法區分「檢索到錯誤極性的文獻」與「驗證器誤讀正確文獻」這兩種性質完全不同的失敗。在面向患者的應用中，前者需要改善檢索與語料庫品質，後者則需要改進驗證器提示或後處理。若只看總分，開發者可能誤以為系統整體表現良好，卻忽略特定臨床範圍或證據極性上的系統性弱點。

**Q12：本文的研究對醫學 RAG 與幻覺檢測領域可能帶來什麼長期影響？**  
A：它首次在無黃金答案的開放式情境下系統分析檢索階段錯誤，並證明單純規模化與微調無法根除這些失敗模式。這會促使學界與業界重新思考「先檢索後驗證」典範的設計，例如發展更細緻的檢索品質指標、結構化證據表示或人機協作驗證流程。長期而言，這有助於建立更透明、可解釋且可診斷的醫療事實性評估標準。

**Q13：本文的研究有哪些主要限制？**  
A：分類法雖然透過 LLM-as-Judge 自動歸納，但仍需人類參與迴路進行品質控制，且 LLM 評判者本身可能產生偏誤或幻覺。實驗主要聚焦於醫學領域，分類法在其他高風險開放式領域的適用性仍需進一步驗證。此外，分析基於現有檢索器與驗證器，未來若出現全新的檢索或推理架構，錯誤模式的相對比例可能改變。

**Q14：哪些失敗案例顯示「先檢索後驗證」典範存在根本性限制？**  
A：當大型語言模型生成的聲稱是參數化虛構、在權威醫學語料庫中根本找不到對應證據時，證據召回率@k 在原則上無法定義，傳統檢索式方法無法判斷其真假。此外，即使檢索到正確文獻，驗證器仍可能因選擇性覆蓋或推理過度延伸而得出錯誤裁決。這些案例說明僅靠檢索外部語料庫並無法保證開放式醫學答案的事實正確性。

**Q15：未來研究可以朝哪些方向改進開放式醫學事實性驗證？**  
A：未來可發展結合檢索品質與驗證器中間步驟的聯合評估指標，並設計能主動偵測參數化虛構的機制。另一方向是建立動態、權威且結構化的醫學知識圖譜，以減少臨床範圍不匹配與來源可信度問題。最後，可探索人機協作驗證介面，讓臨床專家能根據分類法標註的錯誤模式快速介入，提升患者面對系統的可信度與安全性。

## 實務應用指南

### 適用場景

1. **醫療問答平臺的幻覺檢測**：在面向患者的長篇醫學問答系統中，自動將模型回答拆解為原子聲稱，並透過權威醫學語料庫檢索驗證，找出可能的事實性錯誤與無依據推論。
2. **臨床決策輔助文件的品質稽核**：對自動生成的病歷摘要、出院說明或檢查報告解釋進行事實性驗證，標示出檢索失敗或驗證器推理錯誤的段落，供醫療專業人員複審。
3. **醫學知識庫檢索系統的診斷與優化**：當 RAG 系統輸出結果不穩定時，利用多維度檢索錯誤分類法定位是證據不相關、臨床範圍不匹配、分塊問題還是來源可信度不足。
4. **醫療 LLM 微調與上線前的壓力測試**：在模型部署前，使用開放式與封閉式資料集進行跨檢索方法、跨驗證器模型的錯誤模式壓力測試，評估單純擴增模型規模或增加推理投入是否真的能降低失敗率。
5. **監管與風險管理報告**：將聚合指標（如 F1）無法呈現的失敗模式，轉化為可解釋的錯誤分佈報告，協助產品團隊向監管單位說明系統限制與改善計畫。

### 實作前置條件

- **資料需求**
  - 權威醫學語料庫：例如 PubMed、MEDIC 或經醫學專家審核的機構內部知識庫。
  - 開放式長篇醫學答案：如 MedExpert 資料集，或自行收集並經臨床專家標註真偽的問答對。
  - 可選的封閉式資料集：如 SciFact、PubHealth、HealthVer，用於轉換成開放式設定後進行交叉驗證。

- **運算需求**
  - 向量索引與檢索基礎建設：需支援大規模 passage 嵌入與 top-k 檢索（例如 30M 等級語料庫）。
  - LLM 推理資源：至少能呼叫 1–2 個前沿驗證器模型進行原子聲稱裁決與 LLM-as-Judge 自動標註。
  - 人機協作標註介面：用於臨床專家對句子真偽進行最終判斷，並與自動分類結果比對。

- **技能需求**
  - 熟悉檢索增強生成（RAG）流程與向量資料庫建置。
  - 具備 LLM prompt engineering 與評判者模型設計經驗。
  - 擁有醫學領域知識或能與臨床專家密切合作，以判斷證據臨床範圍與可信度。
  - 具備錯誤分析與分類法歸納能力，能從離散失敗案例中萃取出可重複的錯誤模式。

### 實作步驟建議

1. **建立開放式事實驗證管線**
   - 將長篇醫學答案分解為原子聲稱。
   - 對每個原子聲稱執行 top-k 檢索，取得權威醫學語料庫中的相關 passage。
   - 使用 LLM 驗證器產生四向裁決：Supported／Refuted／No Evidence／Ambiguous。

2. **取得人類真值標註**
   - 由臨床專家對原始回答句子標註 True／False，原子聲稱預設繼承該句子標籤。
   - 記錄專家判斷理由，作為後續錯誤歸因的參考依據。

3. **自動歸納錯誤分類法**
   - 比對 LLM 驗證器與人類標註的差異。
   - 使用 LLM-as-Judge 自動標註檢索階段錯誤（如不相關證據、臨床範圍不匹配、證據極性錯誤、分塊問題）與驗證器推理錯誤（如錯誤證據選擇、證據理解失敗、推理不足、過度自信、不一致、幻覺）。
   - 反覆迭代聚類，直到錯誤模式穩定。

4. **跨系統壓力測試**
   - 更換 3–4 種檢索方法與 4–6 種前沿驗證器模型。
   - 測試擴增模型規模、增加推理投入、醫學微調、擴展至權威網路來源等變因，觀察各錯誤模式是否顯著下降。

5. **轉化為產品級監控儀表板**
   - 將錯誤分佈視覺化，區分「檢索瓶頸」與「驗證器推理瓶頸」。
   - 建立告警規則：例如當某類臨床範圍不匹配或過度自信錯誤超過門檻時，自動將案例轉交人工複審。

6. **持續迭代與回饋迴路**
   - 定期將人工複審結果回流至分類法與驗證器 prompt。
   - 針對高頻錯誤模式更新檢索策略（如改進分塊、加入來源可信度過濾）或驗證器推理指引。

### 潛在風險與注意事項

- **過度依賴聚合指標**：F1 等指標會遮蔽檢索與驗證器各自的失敗模式，建議採用本文提出的多維度錯誤分類法進行細部診斷。
- **LLM-as-Judge 的標註偏差**：自動誘導分類法時，評判者模型本身可能產生幻覺或過度自信，應以人工抽樣審核並計算標註一致性。
- **開放式設定缺乏黃金證據**：無法使用傳統 evidence precision@k／recall@k，因此必須以錯誤模式分佈與人工標註取代直接證據比對。
- **臨床範圍與來源可信度難以自動判斷**：醫學證據常涉及劑量、族群、適應症等細微差異，自動分類結果需經臨床專家確認。
- **單純擴大模型或增加推理無法解決結構性問題**：本文發現這些手段對主要錯誤模式改善有限，產品團隊應避免將其視為萬靈丹，而需針對特定錯誤類型設計機制。
- **法規與責任歸屬**：高風險臨床場景中，任何自動驗證輸出都應標示為輔助參考，最終決策仍需合格醫療專業人員負責。

### 與其他技術的整合建議

- **與 RAG 管線整合**：將錯誤分類法嵌入現有檢索增強生成系統，作為檢索品質與驗證器行為的診斷層，而非僅作為最終分數。
- **與醫學知識圖譜結合**：針對臨床範圍不匹配與證據極性錯誤，可利用知識圖譜強化實體與關係對齊，提升檢索相關性。
- **與人機協作審查平臺整合**：將高風險錯誤模式（如過度自信、衝突合成失敗）自動路由至醫療專家，形成「模型初篩＋專家複審」的工作流程。
- **與可解釋性工具搭配**：將 LLM 驗證器的推理鏈與錯誤分類標籤一同呈現，幫助工程師與臨床人員理解模型為何出錯。
- **與持續學習系統連動**：將錯誤案例與對應分類標籤納入訓練資料，定期微調檢索器、驗證器或醫學領域適配模型。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先從「基於檢索的事實性評估」與「RAG 基本流程」開始理解，再聚焦圖 1 的兩階段錯誤分類示意，最後閱讀適用場景與潛在風險，建立對醫療 LLM 事實性問題的整體認識。

- **AI 工程師**：重點關注自動分類法歸納的實作細節、LLM-as-Judge 的 prompt 設計、跨檢索方法與跨驗證器模型的壓力測試結果，並參考實作步驟建議將方法落地為可監控的產品管線。

- **研究人員**：深入分析錯誤分類法的理論基礎、開放式與封閉式事實驗證的差異、以及為何擴增模型規模與推理投入無法解決主要失敗模式，並思考如何設計新的檢索或驗證架構來突破這些根本限制。

- **產品經理**：著重閱讀適用場景、潛在風險與注意事項、以及與其他技術的整合建議，理解如何將技術轉化為可解釋的風險管理工具，並規劃人工複審流程與監管合規路徑。
