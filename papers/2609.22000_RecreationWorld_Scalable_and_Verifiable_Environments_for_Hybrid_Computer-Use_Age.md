## ⚡ TL;DR

現有電腦使用代理多僅擅長圖形介面或命令列，難以勝任需兩者反覆交錯的軟體密集型任務。
提出RecreationWorld，以運行參考為神諭，在五平台用隱藏行為與視覺測試評分復刻任務。
復刻訓練可遷移至五項基準，GPT-6 Astra得58.1%但僅2.8%任務全過測試，資料集已開放。

## 摘要翻譯

電腦使用代理（Computer-use agents, CUA）的進展沿著兩條獨立路線：圖形化互動（graphical interaction），以及透過程式碼與命令列進行的軟體開發（software development）。真實的數位工作需要兩者兼備，且是交錯進行，而非前後堆疊。我們研究能夠自主決定何時探索介面、實作軟體，並執行與視覺驗證其產出物的混合式電腦使用代理（hybrid CUAs）。我們提出 RecreationWorld，一個以復刻任務（recreation task）為核心、支援五種平台的框架：給定一個執行中的參考實例（running reference），代理必須發現其行為，並在無預設工作流程（no prescribed workflow）下建構忠實實作（faithful implementation）。RecreationWorld 在 Ubuntu、macOS、Windows、Android 與 Web 上提供可重現環境（reproducible environments），並配備具備原生 GUI 控制（native GUI control）與程式設計工具（coding tools）的統一測試框架（unified harness）。執行中的參考實例可作為隱藏行為測試（hidden behavioral tests）的神諭（oracle），提供基於執行的獎勵（execution-grounded rewards）。我們利用高品質開源應用程式（high-quality open-source applications）擴大軌跡生成（trajectory generation）規模。在這些軌跡上訓練的模型在五個分佈外（out-of-distribution, OOD）的軟體開發與混合式電腦使用基準上均有提升，且更頻繁地驗證其渲染輸出（rendered outputs），顯示其能力可遷移（transfer）至復刻任務之外。針對保留評估（held-out evaluation），我們提出 RecreationBench，包含橫跨不同領域與平台的 250 個多樣化任務。以參考實例為基礎的程式化與視覺斷言（programmatic and visual assertions）涵蓋多種互動深度（interaction depths）下的動作條件化結果（action-conditioned outcomes）；每一項斷言都會在參考實例上驗證，並經由人工審查者確認，之後才將測試套件凍結以進行自動評分（automatic scoring）。GPT-6 Astra 以 58.1% 的總體分數（overall score）領先，但僅在 2.8% 的任務上通過所有程式化測試（programmatic tests）。代理重現靜態介面結構（static interface structure）的可靠度高於互動與計算輸出（computed outputs），而生成的應用程式相較於其參考實例仍然較小且更為單體式（monolithic）。我們公開釋出該基準、環境與測試套件。

### 核心貢獻（3～5點）
- 提出 RecreationWorld：一個支援 Ubuntu、macOS、Windows、Android 與 Web 五種平台的復刻任務框架，提供可重現環境與統一測試框架（unified harness），結合原生 GUI 控制與程式設計工具。
- 定義混合式電腦使用代理（hybrid CUAs）的核心挑戰：代理須自主決定探索、實作、執行與視覺驗證的順序，在無預設工作流程下重建執行中參考實例的行為。
- 建立 RecreationBench 保留測試集：250 個跨領域與跨平台的任務，透過參考實例驗證與人工審查的程式化／視覺斷言進行自動評分。
- 展示規模化軌跡生成與遷移學習效果：在 RecreationWorld 軌跡上訓練的模型在五個 OOD 基準上表現提升，並更頻繁驗證渲染輸出。
- 提供模型能力診斷：GPT-6 Astra 總體分數達 58.1%，但僅 2.8% 任務通過所有程式化測試，顯示代理在互動與計算輸出上仍遜於靜態介面結構。

### 適合對象
電腦使用代理（CUA）、圖形使用者介面自動化、軟體工程與程式合成，以及多模態大型語言模型研究者；特別適合關注混合式 GUI／命令列代理、長期範圍任務規劃、可驗證獎勵設計與跨平台基準建構的學術與產業研究團隊。

## 深度分析

#### 方法論解析

##### 1. 任務設計：復刻（recreation）作為混合式 CUA 的純粹形式

RecreationWorld 的核心任務是「復刻」：給定一個執行中的參考實例（running reference），代理必須自主探索其行為，並產出可執行的忠實實作（faithful implementation），且過程中沒有預設工作流程（no prescribed workflow）。這個設計刻意讓代理無法只靠圖形化互動（graphical interaction）或只靠命令列（command line）/程式碼完成任務。代理必須在單一長期過程（long-horizon process）中反覆進行：

- **探索（explore）**：操作參考實例以發現行為；
- **實作（implement）**：撰寫或修改程式碼；
- **執行與驗證（run and verify）**：建置、啟動候選程式，並以視覺驗證（visual verification）與行為測試檢查結果；
- **修訂（revision）**：根據回饋（feedback）持續修正。

這正是論文所稱的混合迴路（hybrid loop）：觀察影響實作，實作執行後又產生新的觀察對象，資訊必須在多次循環中雙向流動，而非兩個階段串接。

##### 2. 跨平台統一載具（unified harness）

RecreationWorld 提供可重現環境（reproducible environments）於 Ubuntu、macOS、Windows、Android 與 Web 五個平台。其技術貢獻在於：

- **統一執行契約**：雖然各平台使用各自的 UI 框架、建置系統、輔助功能（accessibility）與自動化堆疊，但透過統一測試框架（unified harness）標準化參考實例執行、候選交付與實驗記錄。
- **原生 GUI 控制（native GUI control）**：代理可直接對各平台原生圖形使用者介面（GUI）進行點擊與鍵盤輸入（clicks and keyboard inputs）。
- **程式設計工具（coding tools）**：同時提供命令列/終端機（terminal）操作、編輯器、建置與測試工具，讓代理在同一環境中切換模態（modalities）。

這種設計讓動作空間（action space）貼近人類實際工作情境：一會兒操作應用程式，一會兒修改驅動該應用程式的軟體。

##### 3. 以執行為基礎的獎勵與測試生成

RecreationWorld 的評分機制建立在「執行中的參考實例即神諭（oracle）」這個概念上：

- 從參考實例衍生出隱藏行為測試（hidden behavioral tests）；
- 這些測試對候選實作重播，產生與實作語言、框架、架構無關的獎勵；
- 一旦測試套件經過驗證並凍結（frozen），即可自動評分（automatic scoring），無需針對每個候選結果進行人工判斷。

這體現了驗證的不對稱性（asymmetry of verification）：驗證一個解是否正確，比人工寫規格再驗證更容易、更客觀。對訓練而言，這種基於執行的獎勵（execution-grounded rewards）是自我接地（self-grounding）的具體來源，使軌跡生成（trajectory generation）與模型自我改進（self-improvement）成為可能。

##### 4. 可擴展的軌跡資料來源

為了規模化，RecreationWorld 利用高品質開源應用程式（high-quality open-source applications）作為任務池。這些開源應用程式橫跨不同領域、UI 框架、實作語言與複雜度，因此擴充時引入的是真正不同的可執行系統，而非同一任務模板的變形。論文提到在任務隔離的工作節點（task-isolated workers）上進行復刻軌跡生成，並保留高分軌跡作為共享訓練集，這讓 RecreationWorld 同時具備評測與訓練功能。

#### 實驗數據解讀

##### 1. 訓練遷移：復刻監督可泛化至其他基準

論文在復刻軌跡上訓練兩個模型初始化，並在五個分佈外（OOD）基準上測試，涵蓋程式設計、視覺化程式設計與混合式電腦使用任務。結果顯示：

- 兩個訓練執行都在首次評估檢查點之後持續進步；
- 最高提升達 **17.9 個百分點**。

這提供初步證據：在復刻任務上學到的探索—實作—驗證行為，能遷移（transfer）到 RecreationWorld 以外的情境。值得注意的是，訓練過程中後期檢查點的代理更常檢查自己的渲染輸出（rendered outputs），顯示視覺驗證行為可能隨訓練浮現並帶來泛化效益。

##### 2. RecreationBench 的整體表現

RecreationBench 包含 250 個保留任務，每個平台 50 個。評估十個前沿模型後，主要發現：

- **GPT-6 Astra** 以 **58.1%** 的總體分數（overall score）領先；
- 然而，它僅在 **2.8%** 的任務上通過所有程式化測試（passes all programmatic tests）；
- GPT-6 Astra 是唯一在多個平台上達成完整程式化測試通過的模型。

這 58.1% 與 2.8% 之間的巨大落差值得深究：總體分數可能綜合了部分通過的程式化斷言（programmatic assertions）與視覺斷言（visual assertions），但「全部通過」的門檻極高。這意味著目前最前沿的模型距離「完全重建參考實例行為」仍非常遙遠。

##### 3. 代理的強項與弱點

結果分析指出代理在以下方面表現不均：

- **靜態介面結構（static interface structure）** 較容易被復刻，例如布局、可見元件、顏色等；
- **互動（interactions）** 與 **計算輸出（computed outputs）** 較難正確重建；
- 代理產生的應用程式通常比參考實例 **更小、更單體式（monolithic）**。

這暗示模型傾向於「複製外觀」而非「重建機制」。它們可能透過截圖或輔助功能樹捕捉到介面元素，但對於事件處理、狀態轉換、資料流與持久化等深層行為掌握不足。此外，產出程式較小且單體式，可能反映模型在長期規劃與模組化設計上的限制：難以將參考實例拆解為適當的元件、模組或檔案結構。

##### 4. 軌跡行為觀察

對 GPT-6 Astra 的軌跡分析顯示：

- 在開始實作後仍持續進行 GUI 互動；
- 結合廣泛的參考實例探索與以 GUI 為中心的工作流程。

這是描述性觀察，論文也謹慎指出尚未證明這些行為「導致」高分。但這與「混合式 CUA 應持續在觀察與實作間切換」的設計理念一致。

#### 與現有研究的比較

##### 1. 相對於僅 GUI 或僅終端機的 CUA

現有電腦使用代理（CUA）大致分為兩條路線：

- **僅 GUI 代理（GUI-only agent）**：透過螢幕畫面（screens）與點擊、鍵盤輸入操作真實應用程式，擅長觀察與探索，但很少建置或重構底層軟體；
- **僅終端機代理（terminal-only agent）**：透過命令列撰寫程式、呼叫工具，但無法看見其動作產生的介面，缺乏探索性視覺回饋。

RecreationWorld 明確定位為混合式電腦使用代理（hybrid CUAs），要求代理在單一長期過程中自主協調（autonomous coordination）兩種模態。這比單純將 GUI 代理與終端機代理串接更困難，因為資訊必須在迴路中反覆流動，而非一次性傳遞。

##### 2. 相對於傳統程式設計基準

傳統程式設計基準通常給定明確規格（如函式簽名、輸入輸出範例、單元測試），代理只需產出程式碼。RecreationWorld 的規格則「隱藏」在執行中的參考實例裡，代理必須先透過操作發現規格，再轉譯為實作。這更接近真實世界中的「逆向工程」或「重現既有系統」任務，對長期範圍（long horizons）與跨模態推理的要求更高。

##### 3. 相對於其他視覺或網頁代理基準

部分基準聚焦網頁操作或桌面自動化，但多數只評估代理能否完成特定指令（如「訂機票」或「設定應用程式」），而非要求代理產出可執行的軟體交付成果（deliverable）。RecreationWorld 的交付成果是原始碼，且必須滿足平台特定的建置與啟動契約，這讓評估更貼近軟體開發。

##### 4. 主要改進與貢獻

- **多平台覆蓋**：同時支援 Ubuntu、macOS、Windows、Android、Web，並保留各平台原生互動語意；
- **執行為基礎的客觀獎勵**：以參考實例為神諭產生隱藏行為測試，避免人工逐案評分；
- **可規模化**：利用開源應用程式持續產生新任務與已驗證軌跡，突破手寫基準的固定規模限制；
- **訓練與評估共用環境**：同一套環境既能產生訓練軌跡，也能進行保留評估。

##### 5. 限制

- **整體表現仍低**：即使最強模型 GPT-6 Astra 也僅在 2.8% 任務上完全通過程式化測試，顯示任務難度極高，現有模型尚未成熟；
- **視覺與行為測試的覆蓋率**：雖然測試經過參考驗證與人工審查，但任何隱藏測試集都無法保證涵蓋所有語意面向，可能存在假陰性（false negatives）；
- **平台差異**：Android 與 Web 的參考實例在某些情況下無法完全隱藏（例如 Web 原始碼可透過瀏覽器開發工具檢視），可能影響「必須透過操作發現行為」的任務難度一致性；
- **軌跡分析為描述性**：論文未建立因果關係，無法確定「更多 GUI 互動」或「更多視覺驗證」是否直接導致更高分數；
- **計算成本**：跨平台虛擬機池、長期軌跡生成與多次建置執行，意味著大規模訓練與評估需要大量運算資源。

#### 可重現性評估

##### 1. 已釋出資源

根據摘要與引言，作者承諾釋出：

- **RecreationBench**：250 個保留測試任務；
- **任務環境（environments）**：跨 Ubuntu、macOS、Windows、Android、Web 的可重現環境；
- **測試套件（test suites）**：經過參考驗證與人工審查的隱藏行為測試。

這些釋出對於後續研究至關重要，因為它們讓其他研究者能夠在相同條件下比較不同模型與方法。

##### 2. 未明確釋出的項目

從提供的文本中，無法確認以下項目是否公開：

- **訓練軌跡資料集**：雖然論文提到保留高分軌跡作為共享訓練集，但未明確說明是否會釋出這些軌跡；
- **模型權重（model weights）**：未提及是否會釋出經過復刻監督微調的模型檢查點；
- **完整原始碼與基礎設施**：統一測試框架（unified harness）、虛擬機排程、測試生成管線等實作細節是否開源，文本中未詳細說明。

##### 3. 可重現性挑戰

即使資源釋出，重現仍可能面臨挑戰：

- **跨平台授權與軟體相依性**：macOS、Windows、Android 模擬器與特定 UI 框架可能需要相應授權或授權金鑰；
- **長期軌跡的非確定性**：GUI 操作與建置過程可能受時序、網路狀態、快取影響，重現相同軌跡需要嚴格的環境隔離與種子控制；
- **硬體需求**：大規模軌跡生成與多平台並行評估需要可水平擴展的虛擬機池，對一般研究團隊而言門檻不低。

##### 4. 建議

為提升可重現性，作者可考慮：

- 提供容器化或虛擬機映像檔，預先安裝各平台工具鏈；
- 釋出最小可執行範例與評分腳本，讓研究者能快速驗證環境設定；
- 若無法釋出完整模型權重，至少提供訓練軌跡格式說明與資料產生流程，以便社群重建類似資料。

#### 未來研究方向

##### 1. 強化深層行為復刻

目前代理在靜態介面結構上表現較好，但在互動與計算輸出上較弱。未來研究可聚焦：

- **狀態機與事件模型學習**：讓代理從參考實例的操作軌跡中推斷隱藏狀態轉換與事件處理邏輯；
- **差異化測試（differential testing）**：自動產生更多樣化的輸入序列，比對參考實例與候選實作的輸出差異；
- **資料持久化與網路行為建模**：針對多步導航、持久化儲存與後端互動設計專門模組。

##### 2. 提升模組化與程式品質

代理產出的程式較小且單體式（monolithic），未來可探索：

- **架構規劃模組**：在撰碼前先產出檔案結構、元件介面與資料流設計；
- **程式重構獎勵**：在基於執行的獎勵之外，加入程式複雜度、可維護性與模組化指標；
- **參考實例結構分析**：利用靜態分析或執行追蹤，協助代理理解參考實例的模組邊界。

##### 3. 自主驗證與自我改進

RecreationWorld 的設計天然適合自我接地（self-grounding），未來可發展：

- **主動測試生成**：代理在實作過程中自行提出假設並設計實驗來驗證；
- **視覺回饋的細粒度利用**：不僅比對最終截圖，也分析動畫、過渡狀態與錯誤訊息；
- **軌跡篩選與強化學習**：利用執行為基礎的獎勵進行偏好學習或強化學習，進一步提升長期規劃能力。

##### 4. 擴展平台與應用領域

目前覆蓋五個平台，未來可延伸至：

- **嵌入式與物聯網裝置**：需要透過模擬器或實體裝置進行 GUI 與感測器互動；
- **遊戲與互動式媒體**：強調即時渲染、物理模擬與使用者輸入反應；
- **企業級軟體**：涉及資料庫、API、分散式服務與複雜業務邏輯的復刻。

##### 5. 人機協作與可解釋性

由於復刻任務長期且複雜，未來也可研究：

- **人類回饋整合**：在關鍵決策點引入人類提示或糾正；
- **可解釋軌跡**：讓代理產出自然語言摘要，說明其探索策略、設計決策與驗證結果；
- **錯誤診斷工具**：當候選實作未通過測試時，自動定位是觀察不足、實作錯誤還是驗證遺漏。

##### 6. 基準與評估方法精進

- **動態測試擴充**：讓測試套件能隨新任務自動生成，並持續擴大覆蓋面；
- **對抗性測試**：設計專門誘使代理產生「外觀正確但行為錯誤」候選程式的測試；
- **效率指標**：除了正確性，也評估代理使用的步驟數、運算資源與人類可比成本。

總結來說，RecreationWorld 為混合式電腦使用代理提供了一個兼具挑戰性、可擴展性與可驗證性的研究平台。儘管目前模型表現仍有顯著差距，但其所揭示的「外觀易仿、行為難復」現象，以及視覺驗證與長期規劃的重要性，為未來 CUA 研究指出了清晰的改進方向。

## 論文問答

**Q1：RecreationWorld 主要想解決什麼問題？**
A：RecreationWorld 針對的是現有電腦使用代理（CUA）長期被割裂為「僅 GUI 代理」與「僅終端機代理」兩條路線的問題，前者能觀察圖形介面卻難以建構或重構軟體，後者能撰寫程式卻看不見自己產生的介面。真實的軟體密集型任務需要兩種模態反覆交錯，而非先後堆疊，因此需要能自主決定何時探索、何時實作、何時執行與驗證的混合式電腦使用代理。現有基準大多只強調單一互動模式，無法衡量代理在長期範圍內自主協調這個混合迴路的能力，RecreationWorld 正是為了填補這個缺口而設計。

**Q2：為什麼單純的 GUI 代理或終端機代理無法勝任真實的數位工作？**
A：僅 GUI 代理雖然能觀察執行中的參考實例，卻很少能夠主動撰寫或重構背後驅動介面的程式碼；僅終端機代理雖然能編寫程式與呼叫工具，卻無法直接看到其動作所渲染出的圖形輸出，因此缺乏探索性的視覺回饋來判斷結果是否符合預期。許多任務要求理解系統的同時也要能改動系統，觀察會形塑實作，而執行實作又會回過頭來改變接下來該觀察什麼。這種資訊必須雙向流動的特性，使得單一模態的代理或把兩種代理簡單串接都無法達成真正的融合。

**Q3：混合式電腦使用代理為何重要，「自我接地」又代表什麼？**
A：混合能力能擴展代理的動作空間，使其更貼近人類實際工作環境，在操作應用程式與編輯驅動它的程式碼之間自然切換。更重要的是，混合迴路具有自我接地的特性：代理會產出自己可以執行並檢視的成品，每一次循環都能獲得具體執行與視覺回饋，這些回饋既客觀又可驗證。正因為獎勵來自於實際執行結果，這樣的設定不僅是更廣泛的能力評測，也成為自我改進與訓練軌跡篩選的有前景基質。

**Q4：RecreationWorld 的核心任務「復刻」是如何運作的？**
A：復刻任務給定一個執行中的參考實例，要求代理透過操作它來發現其行為，並建構一個忠實實作，且任務不預設任何工作流程。代理必須在參考實例的探索、程式碼撰寫、候選執行、視覺驗證與修訂之間反覆循環，無法只靠點擊或只靠寫程式成功。執行中的參考實例同時扮演規格來源與神諭，讓研究者能從中衍生隱藏行為測試，對任何候選實作給予實作無關的基於執行的獎勵。

**Q5：RecreationWorld 框架有哪些關鍵創新？**
A：RecreationWorld 提供跨 Ubuntu、macOS、Windows、Android 與 Web 五種平台的可重現環境，並透過統一測試框架保留各平台原生互動語意，同時暴露原生 GUI 控制與程式設計工具。它利用高品質開源應用程式進行大規模軌跡生成，把異質應用行為轉換成可自動評分的參考導向測試。測試設計同時涵蓋程式化斷言與視覺斷言，並跨越從單步狀態變化到多跳導航與持久化計算等多種互動深度，從而產生細緻的語義與視覺忠實度衡量。

**Q6：RecreationBench 的測試設計做了哪些重要選擇？**
A：RecreationBench 包含 250 個保留任務，每個平台各 50 個，測試沿著「觀察什麼」與「互動多深」兩個互補軸線設計。程式化斷言透過各平台的結構化輔助功能或自動化底層讀取文字、元件狀態與動作結果，視覺斷言則檢查布局、顏色、畫布內容等渲染屬性；每個測試都將觸發條件與其引發的動作條件化結果綁在一起。所有斷言必須先在參考實例上通過並經人工審查，才能進入固定隱藏測試套件，確保評分穩定且無需針對每個候選結果進行人為判斷。

**Q7：論文進行了哪些實驗與基準測試？**
A：作者利用高品質開源應用程式產生復刻軌跡，並用這些軌跡訓練兩個模型初始化，隨後在五個分佈外的程式設計、視覺程式設計與混合電腦使用基準上評估。訓練後的模型在這些基準上都高於最初檢查點，最高提升達 17.9 個百分點，顯示復刻監督能遷移到復刻環境之外的任務。在保留評估方面，則使用新提出的 RecreationBench，對十個前沿模型進行大規模自動評分。

**Q8：RecreationBench 上的主要結果是什麼？**
A：GPT-6 Astra 以 58.1% 的總體分數領先，也是唯一在多個平台上都有完整程式化測試通過紀錄的模型，但這樣的完全通過僅佔全部任務的 2.8%。結果顯示代理較能可靠地復刻靜態介面結構，卻較難重現互動行為與計算輸出；此外，代理生成的應用程式通常比參考實例更小、更單體式。這些發現指出目前前沿模型與參考級行為忠實度之間仍有顯著差距。

**Q9：軌跡分析與訓練過程揭示了什麼？**
A：軌跡分析顯示，即使在開始實作之後，代理仍會持續進行 GUI 互動，而 GPT-6 Astra 傾向結合廣泛的參考探索與以 GUI 為中心的工作流程。在訓練過程中，越後期的檢查點越常主動檢查自己的渲染輸出，顯示驗證行為隨訓練逐漸增強。雖然這些觀察是描述性的，並未證明因果關係，但結合在五個分佈外基準上的進步，提供了復刻訓練能促進混合能力遷移的初步證據。

**Q10：RecreationWorld 在實務上可以應用在哪些場景？**
A：RecreationWorld 可應用於自動復刻既有應用程式的外觀與行為、將軟體從一個平台移植到另一個平台，或從沒有書面規格的執行系統中學習隱含需求。由於規格僅存在於執行中的參考實例，這種設定特別適合快速原型開發、遺留系統現代化，以及需要同時理解介面與程式碼的維護任務。對企業而言，這能減少手動重寫介面的成本，並讓代理在真實軟體環境中持續學習。

**Q11：若要把 RecreationWorld 落地為產品，需要考慮哪些因素？**
A：產品化時必須確保每個任務都在隔離的工作節點中執行，並維護可水平擴展的虛擬機池以支援大規模軌跡生成與評估。由於涉及五種作業系統與各自的輔助功能、自動化與建置系統，環境的可重現性與維護成本是重大挑戰。此外，隱藏測試套件的設計、人工審查流程，以及平台授權與安全性，都需要納入長期營運規劃。

**Q12：這項研究對整個領域可能帶來什麼影響？**
A：RecreationWorld 提供了一個可擴展且可驗證的混合式 CUA 研究基礎設施，讓學界與業界能用統一標準比較不同模型在長期混合任務上的表現。它強調代理必須同時對圖形介面與程式碼進行聯合推理，推動模型從單一模態走向真正的融合。開放釋出的基準、環境與測試套件也有助於加速自我改進、強化學習與可驗證獎勵設計等後續研究。

**Q13：論文承認了哪些主要限制？**
A：即使是最強的 GPT-6 Astra，其總體分數也只有 58.1%，且能在所有程式化測試上完全通過的任務比例極低，顯示離參考級行為忠實度還很遠。代理在靜態介面結構上表現較好，但在互動行為、計算輸出與多步持久化方面仍然薄弱。此外，軌跡分析中觀察到的高分相關行為僅具描述性，並未確立因果關係，仍需更多實驗來驗證。

**Q14：代理在哪些類型的任務上最容易失敗？**
A：代理最容易在需要深層互動、複雜計算或多跳狀態持久化的任務上失敗，因為這些任務要求把從參考實例觀察到的行為正確轉譯為程式邏輯。它們也常產生比參考實例更小、更單體式的程式碼，導致可維護性與行為正確性下降。平台特定的細節，例如各作業系統的輔助功能行為或建置流程，也可能讓代理即使復刻了外觀，仍無法通過隱藏行為測試。

**Q15：未來可以朝哪些方向繼續發展？**
A：未來研究可著重提升代理對動態行為與計算輸出的復刻能力，並鼓勵生成更模組化、可擴展的程式架構。進一步強化參考探索策略與主動視覺驗證迴路，也有望縮小與參考實例之間的忠實度差距。此外，把 RecreationWorld 擴展到更多平台與應用領域，並結合強化學習進行大規模自我改進，將是邁向通用混合式電腦使用代理的重要下一步。

## 實務應用指南

## 適用場景

1. **遺留系統現代化與跨平台移植**  
   企業內部常有僅剩執行檔或舊版原始碼的業務應用程式。透過復刻任務，可讓混合式電腦使用代理在 Ubuntu、macOS、Windows、Android、Web 等平台上操作執行中的參考實例，自動發現其行為並產出對應平台的新實作，縮短重寫週期。

2. **自動化行為迴歸測試與視覺驗證**  
   將 RecreationWorld 的統一測試框架整合進 CI/CD，針對每次版本釋出自動執行隱藏行為測試。程式化斷言檢查 widget 狀態與動作條件化結果，視覺斷言檢查布局、顏色與 canvas 內容，補足傳統單元測試無法覆蓋的 UI 行為。

3. **CUA 訓練資料與驗證軌跡的大規模生成**  
   利用高品質開源應用程式作為持續更新的參考實例，自動產生大量可驗證的長期軌跡。這些軌跡可作為監督式微調或強化學習的訓練素材，並透過執行中的參考實例作為神諭進行自動篩選。

4. **無規格文件的功能重建與知識保存**  
   當產品文件過時或缺失時，代理可直接探索執行中的參考實例，重建其互動深度、計算輸出與視覺回饋，產出可執行且可維護的替代實作，降低關鍵業務系統因人員異動而失傳的風險。

5. **智慧開發輔助與快速原型驗證**  
   產品團隊可提供一個運作中的參考原型，讓代理在無預設工作流程的限制下自主探索、實作、執行與驗證，快速產出第一版可運行程式，再由工程師進行後續重構與最佳化。

## 實作前置條件

**資料準備**
- 可執行的參考實例與對應平台環境（Ubuntu、macOS、Windows、Android、Web）。
- 平台原生的可及性（accessibility）或自動化介面資訊，例如 UI 樹、元素 ID、座標語義。
- 明確的建置與啟動合約：原始碼、相依套件、編譯指令、啟動入口。
- 開源或自有授權允許複製與再訓練的應用程式，避免授權爭議。

**運算資源**
- 可水平擴展的虛擬機或容器叢集，用於任務隔離的 worker 執行復刻軌跡。
- GPU 叢集供模型推論與微調使用，特別是當需要從高品質軌跡進行遷移學習時。
- 足夠的儲存空間保存螢幕畫面、軌跡、候選實作與測試紀錄。

**技能需求**
- 熟悉混合式電腦使用代理的設計，能整合 GUI 控制與命令列/程式碼工具。
- 具備各平台自動化經驗，如 Selenium、Appium、pyautogui、作業系統可及性 API。
- 能設計並維護程式化斷言與視覺斷言，並理解互動深度與動作條件化結果的測試設計。
- 具備模型訓練、評估與 MLOps 部署經驗，以便將軌跡轉化為可持續改進的模型能力。

## 實作步驟建議

1. **選定目標應用與平台，建立可重現環境**  
   根據業務需求選擇參考實例，並在 RecreationWorld 支援的平台上準備好隔離、可重複建置的執行環境。

2. **掛載統一測試框架與原生 GUI 控制**  
   透過統一測試框架暴露平台原生 GUI 控制與程式設計工具，確保代理能在同一長期過程中自由切換探索、實作與驗證。

3. **從參考實例生成並凍結隱藏行為測試**  
   設計涵蓋不同互動深度的程式化斷言與視覺斷言，先在執行中的參考實例上驗證通過，再經人工審查，最後凍結為固定測試套件。

4. **執行復刻軌跡並評分候選實作**  
   讓混合式代理自主操作參考實例、撰寫程式碼、建置並啟動候選實作，再以上述凍結測試套件進行自動評分。

5. **保留高品質軌跡並進行模型訓練**  
   將高分軌跡納入訓練集，對基礎模型進行微調，並在五個分佈外基準上驗證遷移效果。

6. **部署至產品流程並持續監控**  
   將訓練後的模型與測試框架整合進開發或測試管線，定期以新的開源應用程式擴充任務池，維持資料新鮮度與模型泛化能力。

## 潛在風險與注意事項

- **過度擬合靜態介面結構**：代理可能只重建外觀而忽略互動與計算輸出。  
  *因應方式*：測試套件必須同時包含視覺斷言與動作條件化的程式化斷言，並覆蓋多步導航、持久化與端對端計算。

- **生成程式單體化且難以維護**：論文指出代理產出的應用程式通常比參考實例更小、更單體化。  
  *因應方式*：在提示中加入模組化與程式碼風格要求，並安排工程師進行後續重構審查。

- **平台自動化脆弱性**：不同作業系統版本、解析度或輔助功能設定會影響 GUI 控制穩定性。  
  *因應方式*：使用任務隔離 worker、固定環境映像檔，並對測試套件進行版本控制與回歸驗證。

- **測試神諭維護成本**：參考實例更新後，隱藏行為測試可能失效。  
  *因應方式*：建立測試凍結與重新驗證流程，任何參考實例變更都需重新通過人工審查與自動評分。

- **安全與授權風險**：代理會執行未知程式碼，且開源參考實例可能涉及授權限制。  
  *因應方式*：在沙箱環境中執行所有 worker，進行相依套件掃描，並確認訓練資料的授權條款。

- **運算成本高昂**：長期軌跡生成與大規模模型訓練需要大量運算資源。  
  *因應方式*：先從小型任務子集驗證概念，再逐步擴展；利用軌跡分數進行篩選，避免保留低品質資料。

## 與其他技術的整合建議

- **CI/CD 管線**：將 RecreationWorld 的自動評分機制作為一個測試階段，對每次程式碼提交或釋出候選版本執行行為與視覺迴歸測試。
- **現有測試框架**：把程式化斷言輸出為 pytest、JUnit 或各平台原生測試格式，讓開發團隊在熟悉的工具中檢視結果。
- **大型語言模型 API**：將 GPT-6 Astra 等模型作為代理的推理後端，並透過軌跡資料進行微調或強化學習，持續提升混合式決策能力。
- **IDE 與開發輔助工具**：把復刻任務的候選實作與驗證回饋整合進 IDE 外掛，提供即時的視覺驗證與行為比對。
- **知識庫與 RAG 系統**：將探索參考實例過程中擷取的行為描述、截圖與測試案例存入向量資料庫，支援後續查詢與故障排除。
- **MLOps 與可觀測性平台**：記錄每條軌跡的動作、分數與渲染輸出，搭配追蹤與監控工具，協助診斷代理在長期過程中的失敗模式。

## 給不同背景讀者的閱讀建議

**初學者**：建議先掌握本文的詞彙表與「復刻任務」的核心概念，理解混合式電腦使用代理為何需要同時操作圖形介面與命令列，並把「探索—實作—執行—驗證—修訂」的混合迴路當作理解全文的骨架，暫時不需要深入各平台的自動化技術細節。

**AI 工程師**：請重點閱讀統一測試框架的設計、隱藏行為測試的生成與凍結流程，以及如何利用高品質軌跡進行模型訓練與分佈外遷移；同時留意平台自動化、任務隔離與測試維護等實作細節，這些是將論文轉為產品時的關鍵工程挑戰。

**研究人員**：建議關注 RecreationBench 的設計原則，特別是程式化斷言與視覺斷言的互補性、互動深度的分層，以及「驗證不對稱性」如何讓執行中的參考實例成為可擴展的神諭；此外，代理在靜態介面結構與動態計算輸出上的表現落差，是值得進一步研究的瓶頸。

**產品經理**：請把焦點放在適用場景、總體分數與通過率的意義，以及部署後的風險與成本；理解 GPT-6 Astra 雖在 RecreationBench 上達到 58.1%，但僅有 2.8% 任務通過所有程式化測試，這代表目前技術仍適合作為輔助工具而非全自動替代方案，產品設計應保留人工審查與逐步上線的機制。
