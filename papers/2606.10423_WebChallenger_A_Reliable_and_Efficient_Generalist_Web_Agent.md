## ⚡ TL;DR

網頁智慧體缺乏人類的選擇性注意力、持久記憶與程序流暢性，導致自主導航效能低落且依賴昂貴專有模型。
提出WebChallenger，以結構化頁面為基底，透過分治觀察、持久記憶與複合動作實現認知優勢。
使用現成開源模型，在四大網頁基準測試達到同級模型最佳表現，以極低成本逼近前沿專有系統。

## 摘要翻譯

自主網頁導航（autonomous web navigation）對 LLM 智慧體（LLM agents）而言仍具挑戰性，而最強大的通用型系統仰賴專有推理模型（proprietary reasoning models），在這類智慧體最能發揮價值的重複性任務中，這些模型的推論成本（inference cost）過於高昂。我們認為這項差距並非源自模型能力不足，而是智慧體架構（agent architecture）未能複製三項人類認知優勢：對相關頁面區域的選擇性注意力（selective attention）、對網站結構的持久記憶（persistent memory），以及對常見互動模式的程序流暢性（procedural fluency）。我們提出 WebChallenger，這是一個網頁智慧體框架，透過架構設計而非模型規模來解決各項差距；其核心為 PageMem：一種從 DOM 以確定性方式建構的結構化頁面表示法（structured page representation），將每個頁面呈現為由附有簡短摘要（short summaries）的語意區塊（semantic sections）組成的語意階層（semantic hierarchy）。在此共享底層（shared substrate）之上，我們建構了三項對應上述認知優勢的機制：分治觀察管線（divide-and-conquer observation pipeline），讓智慧體瀏覽語意區塊的簡短摘要，並僅從任務相關區域（task-relevant regions）提取細節；輕量探索與記憶系統（lightweight exploration and memory system），僅需對每個網站遍歷一次，即可建立頁面與元素行為（element behaviors）的可複用地圖（reusable map）；以及複合動作工作流程（compound action workflows），將常見的多步驟互動折疊為單一智慧體動作，並自動處理部分狀態變更（partial state changes）。由於這三者皆在 PageMem 上運作，該框架無需特定網站轉接器（site-specific adapters）即可跨網站泛化。我們的系統使用現成的（off-the-shelf）且未經微調的開放權重模型（open-weight models），在 WebArena、VisualWebArena、Online-Mind2Web 與 WorkArena 上分別達到 56.3%、48.7%、51.0% 與 70.9%，以極低的成本逼近前沿專有系統（frontier proprietary systems）。

### 核心貢獻（3～5點）
- 提出 WebChallenger 框架，以智慧體架構（agent architecture）設計而非擴大模型規模，彌補現有 LLM 智慧體在自主網頁導航（autonomous web navigation）上的不足。
- 設計 PageMem 結構化頁面表示法（structured page representation），將網頁轉化為具簡短摘要（short summaries）的語意階層（semantic hierarchy），作為三大機制的共享底層（shared substrate）。
- 建立分治觀察管線（divide-and-conquer observation pipeline）、輕量探索與記憶系統（lightweight exploration and memory system），以及複合動作工作流程（compound action workflows），分別對應人類的選擇性注意力（selective attention）、持久記憶（persistent memory）與程序流暢性（procedural fluency）。
- 實現無需特定網站轉接器（site-specific adapters）的跨網站泛化，並以現成（off-the-shelf）開放權重模型（open-weight models）達到逼近前沿專有系統（frontier proprietary systems）的表現，顯著降低推論成本（inference cost）。

### 適合對象
從事網頁智慧體、自主網頁導航與 LLM 代理應用之研究的學者與工程師；特別適合關注如何透過架構設計（鷹架，scaffolding）與認知機制模擬，以開源模型逼近專有系統表現，並尋求低成本、高泛化性網頁自動化解決方案的開發者與研究團隊。

## 深度分析

#### 方法論解析

WebChallenger 的核心論點是：autonomous web navigation（自主網頁導航）的瓶頸並非來自模型能力不足，而是現有 agent architecture（智慧體架構）未能複現人類的三項認知優勢：selective attention（選擇性注意力）、persistent memory（持久記憶）與 procedural fluency（程序流暢性）。為此，作者提出以 PageMem（結構化頁面表示法）作為 shared substrate（共享底層），並在其上建構三大機制，使 off-the-shelf（現成的）開放權重模型（open-weight models）無需 fine-tuning（微調）即可在 zero-shot（零樣本）設定下達成最佳表現（state-of-the-art）。

**PageMem（結構化頁面表示法）**
不同於直接將 raw DOM 或 accessibility tree 餵給模型，PageMem 是從 DOM（文件物件模型）確定性建構的結構化抽象。每個網頁被表示為一個 semantic hierarchy（語意階層），由有序的 semantic sections（語意區塊）組成；每個區塊攜帶模型生成的 short summaries（簡短摘要）與 DOM 衍生屬性，並包含所屬的互動元素（interactive Elements）。這種表示讓智慧體能像閱讀目錄般快速瀏覽，並依據區塊類型派遣專屬處理流程，從而實現跨網站的通用性，無需 site-specific adapters（特定網站轉接器）。

**分治觀察管線（Divide-and-Conquer Observation Pipeline）**
傳統 LLM agents（LLM 智慧體）將整頁資訊序列化為 flat token sequences（詞元序列），導致無關脈絡稀釋了任務相關訊號。WebChallenger 將觀察拆解為三階段：(1) 瀏覽當前 PageMem 中各 section summaries，挑選與任務相關的 page regions（頁面區域）；(2) 僅從這些 task-relevant regions（任務相關區域）提取細節；(3) 將提取結果合成為 task-focused page summary ô_t。此機制對應人類的 selective attention（選擇性注意力），顯著降低每步推論所需的上下文長度與雜訊。

**輕量探索與記憶系統（Lightweight Exploration and Memory System）**
對應 persistent memory（持久記憶），系統在執行任何任務前，先進行離線探索：單次遍歷目標網站，建立 WebsiteMem M_w。這是一個以 URL 為索引的持久化 PageMem 集合，記錄頁面模板、導航路徑與 element behaviors（元素行為），形成一張 reusable map（可複用地圖）。執行任務 τ 時，智慧體從 M_{w0} 載入環境知識，並可選擇書籤 B_τ 作為全程可用的導航錨點。由於 WebsiteMem 建立一次即可跨任務重複使用，智慧體不再以「白紙」狀態面對網站。

**複合動作工作流程（Compound Action Workflows）**
對應 procedural fluency（程序流暢性），系統將常見 interaction patterns（互動模式）——如搜尋、下拉選單選擇、表單提交——封裝為 high-level compound actions（複合動作）。每個 compound action 會觸發 workflow ω(a_t)，內含固定的 LLM sub-calls（LLM 子呼叫）與瀏覽器操作序列，能自動處理 partial state changes（部分狀態變更）（例如下拉選單展開、欄位逐格填入），完成後才將控制權交還頂層迴圈。這避免了每個 atomic action（原子動作）都需重新觀察與推理全頁狀態的開銷。

**系統推論循環**
給定任務 τ = (I, u_0)，智慧體依序執行：(i) 取得當前頁面的 PageMem p_t；(ii) 透過觀察管線產生資訊密集的 ô_t；(iii) 從 candidate set A_t 選擇 action a_t，直接執行瀏覽器操作或觸發 workflow。循環在選擇 end-task action 並驗證完成，或 step budget（步驟預算）耗盡時終止。整體設計讓 32B LLM 與 7B VLM 在 zero-shot（零樣本）設定下即可運作，無需 fine-tuning（微調）。

#### 實驗數據解讀

論文在四個網頁導航基準測試上進行評估，success rate（成功率）如下：

- **WebArena（網頁導航基準測試）**：56.3%
- **VisualWebArena（視覺網頁導航基準測試）**：48.7%
- **Online-Mind2Web（網頁導航基準測試）**：51.0%
- **WorkArena（網頁導航基準測試）**：70.9%

這些數據是在使用 open-weight models（開放權重模型）——32B LLM 與 7B VLM——且未經微調的條件下取得。與先前 open-weight SOTA（最佳表現）相比（WebArena 約 48.4%、VisualWebArena 約 46.6%、Online-Mind2Web 約 48.6%），WebChallenger 在全部四個基準上都顯著領先，確立了新的 state-of-the-art（最佳表現）。

**關鍵解讀：**
1. **Scaffolding（鷹架）的邊際效益**：成果明確顯示，透過 agent architecture（智慧體架構）的重新設計，即使不增加模型規模或進行領域微調，也能大幅提升效能。這驗證了作者「瓶頸在架構而非模型能力」的假說。
2. **WorkArena 的突出表現**：70.9% 的成功率暗示本框架在重複性 knowledge work（知識工作）流程上特別有效，這與 compound action workflows（複合動作工作流程）能內化常見辦公軟體互動模式密切相關。
3. **VisualWebArena 的相對瓶頸**：48.7% 雖仍領先開放權重對手，但與其他基準相比提升幅度較小，且絕對值最低。這反映出 7B VLM 在視覺 grounding 與理解複雜版面時仍存在天花板，也說明視覺資訊的結構化摘要比純文字 DOM 更具挑戰性。
4. **成本效益**：論文強調其結果 approaching frontier proprietary systems（前沿專有系統）但僅需 a fraction of the inference cost（推論成本）。這對於需要重複執行的網頁自動化場景具有重大實務意義，因為 proprietary reasoning models（專有推理模型）的高昂單次推論費用往往使其難以部署在大量重複任務中。

#### 與現有研究的比較

**定位與差異**
現有最強的 generalist web agent（通用型網頁智慧體）多依賴 proprietary reasoning models（專有推理模型），透過巨大模型規模與長鏈推理達成高性能，但推論成本極高。另一方面，多數 open-weight 方案仍採用 monolithic prompt（單體提示）策略：將整頁 accessibility tree 或截圖序列化後一次性餵入模型，導致上下文過載。WebChallenger 則以認知科學視角切入，將人類瀏覽網頁的優勢轉譯為具體架構組件，實現了「以小博大」的 zero-shot（零樣本）通用性。

**相對優勢**
- **對抗莫拉維克悖論（Moravec's paradox）**：作者援引此悖論指出，對人類輕而易舉的網頁瀏覽對 AI 卻異常困難。透過 selective attention（選擇性注意力）機制，WebChallenger 解決了「資訊過載」問題；透過 persistent memory（持久記憶），解決了「每次重新認識環境」的浪費；透過 procedural fluency（程序流暢性），解決了「每步重新推理」的低效。
- **無特定網站轉接器（site-specific adapters）**：由於所有機制都運作在統一的 PageMem 之上，框架具備真正的跨網站通用性，不同於早期網頁智慧體常需為每個網站撰寫專用適配層。

**限制與潛在弱點**
- **DOM 依賴性**：PageMem 從 DOM（文件物件模型）確定性建構，若目標網站為重度動態渲染（如複雜 JavaScript SPA）或刻意混淆 DOM 結構，semantic sections（語意區塊）的切分品質可能下降。
- **離線探索成本**：WebsiteMem 需預先遍歷網站，對於頻繁更新的網站（如新聞首頁、電商促銷頁），探索結果可能快速過期，維護成本尚未被量化。
- **視覺理解上限**：雖然引入 7B VLM，但在 VisualWebArena 上的表現顯示，純視覺線索的結構化摘要仍有改善空間；對於高度依賴視覺語意（如圖片按鈕、圖表互動）的任務，vision-language models（視覺語言模型）可能仍不足。
- **複合動作的覆蓋率**：compound action workflows（複合動作工作流程）雖涵蓋常見互動模式，但面對新穎或非常規的網頁互動設計時，可能仍需 fallback（回退）到 atomic action（原子動作）推理，效率會隨之降低。

#### 可重現性評估

**有利因素**
- **程式碼開源**：作者已於 GitHub 釋出原始碼，提供具體實作細節。
- **模型可取得性**：採用 off-the-shelf open-weight models（現成的開放權重模型），無需依賴閉源 API 或特定商業服務，任何研究者皆可下載相同權重復現。
- **零樣本設定**：無需 fine-tuning（微調）或私有訓練資料，排除了資料取得門檻。
- **確定性表示**：PageMem 從 DOM 確定性建構，降低了環境表示層面的隨機性，有助於實驗結果的穩定復現。

**挑戰與不確定性**
- **目標網站的動態性**：WebsiteMem 的離線探索依賴目標網站在探索時與測試時的結構一致性。基準測試中的網站若發生改版，探索階段產生的 page templates 與 element behaviors（元素行為）可能失效，導致復現結果不穩定。
- **模型版本與超參數**：雖然論文提及使用 32B LLM 與 7B VLM，但具體模型版本（如 Qwen2.5-32B-Instruct、Llama-3.3-70B 等）與推論超參數（溫度、top-p、觀察管線的區塊選擇閾值、step budget 等）需從完整論文或程式碼中確認。
- **基礎設施需求**：WebArena、VisualWebArena 等基準測試需部署專屬瀏覽器環境與 Docker 容器，硬體與網路設定差異可能影響復現難度。

#### 未來研究方向

1. **動態與單頁應用（SPA）的適配**
   當前 PageMem 假設 DOM 結構相對穩定。未來可研究如何將結構化摘要與 DOM mutation observer 結合，使 WebsiteMem 能增量更新，以適應高度動態的現代網頁應用。

2. **視覺語言模型的深度整合**
   可探索讓 vision-language models（視覺語言模型）不僅作為輔助，而是直接參與 semantic sections（語意區塊）的生成與對齊，例如透過跨模態注意力機制將視覺版面資訊融入 PageMem，進一步提升 VisualWebArena 表現。

3. **複合動作的自動化發現**
   現有 compound action workflows（複合動作工作流程）可能由人工或啟發式定義。未來可引入 program synthesis（程式合成）或 learning from demonstration（示教學習），讓智慧體自動從探索階段發現並封裝新的 interaction patterns（互動模式）。

4. **與專有模型的混合架構**
   驗證 WebChallenger 的 scaffolding（鷹架）是否可與 frontier proprietary systems（前沿專有系統）疊加：若將觀察管線與記憶系統嫁接到更強大的專有推理模型上，是否能以更低成本超越現有最強閉源系統。

5. **多智慧體協作與長時程規劃**
   對於超長 horizon 的任務，可將 observation、memory、action planning 分配給不同專長的 agent（智慧體），透過分工降低單一模型的認知負荷，並研究如何在多智慧體間共享與同步 WebsiteMem。

6. **探索成本的量化與最佳化**
   建立 formal trade-off 分析，探討離線探索深度與線上任務推論節省量之間的關係，發展自適應探索策略，在「探索開銷」與「任務成功率」之間取得帕雷托最適。

## 論文問答

**Q1：WebChallenger 旨在解決自主網頁導航領域中的哪個核心問題？**
A：WebChallenger 主要針對通用型網頁智慧體過度依賴專有推理模型、導致推論成本過高而難以應用於重複性知識工作的困境。現有最強大的通用系統雖能處理長時程網頁任務，但其高昂的運算花費使得這類智慧體在實務部署上缺乏經濟可行性。作者主張，這道鴻溝並非源自模型本身的知識或推理能力不足，而是現有智慧體架構未能有效釋放大型語言模型的潛能，因此亟需透過架構層面的創新來彌補。

**Q2：為何現有的 LLM 智慧體在網頁導航上表現不佳，即便其底層模型具備強大的推理能力？**
A：根據作者的分析，現有系統的困境根源於未能複製人類的三項認知優勢：選擇性注意力、持久記憶與程序流暢性。具體而言，多數智慧體將整個網頁視為扁平的詞元序列餵給模型，導致任務相關資訊被大量無關內容稀釋；同時，它們每次對話都從零開始，缺乏對網站結構與元素行為的先驗記憶，且必須對每個原子動作重新觀察與推理。這種「從頭推理」的模式與人類能直覺化執行常見互動慣例的能力形成鮮明對比，恰好體現了莫拉維克悖論在網頁導航領域的困境。

**Q3：降低對專有推理模型的依賴對於網頁智慧體的發展為何至關重要？**
A：網頁自動化的主要商業價值在於處理大量重複性的知識工作，而這類應用場景對推論成本極為敏感，若每次執行任務都需呼叫昂貴的閉源 API，即便準確率再高也難以大規模部署。WebChallenger 透過開放權重模型搭配高效架構，證明了在可負擔的成本下仍能達到接近前沿專有系統的表現，這對推動技術的民主化與商業可行性具有關鍵意義。此外，減少對專有模型的依賴也有助於保障資料隱私，並使企業與研究人員能夠在本地或私有環境中自主運行高可靠度的網頁智慧體。

**Q4：PageMem 是什麼，它如何成為 WebChallenger 框架的運作基礎？**
A：PageMem 是一種從 DOM 確定性建構的結構化頁面表示法，它將每個網頁暴露為由語意區塊組成的階層，並為每個區塊附上簡短摘要，如同書本的目錄一般。這種表示法讓智慧體能夠快速瀏覽摘要，並選擇性地展開特定區塊以取得細節，而無需一次性處理整頁的原始標記。作為共享底層，PageMem 使得分治觀察管線、輕量記憶系統與複合動作工作流程能夠跨網站通用運作，從而免除為個別網站撰寫特定轉接器的必要。

**Q5：WebChallenger 的三大機制分別如何對應人類的認知優勢？**
A：第一項機制「分治觀察管線」對應人類的選擇性注意力，讓智慧體先瀏覽 PageMem 的區塊摘要，僅從任務相關區域提取細節，避免被無關內容干擾。第二項機制「輕量探索與記憶系統」模擬人類的持久記憶，在離線階段單次遍歷網站後建立可複用的網站地圖，記錄頁面結構與元素行為，使後續任務能直接調用先驗知識。第三項機制「複合動作工作流程」則體現程序流暢性，將搜尋、表單填寫等常見多步驟互動折疊為單一高階動作，自動處理中間狀態變更，無需智慧體在每一步都重新推理。

**Q6：作者為何選擇將觀察過程分解為多階段管線，而非採用現有框架常見的單一龐大提示？**
A：單一龐大提示會迫使模型同時處理大量無關的扁平化詞元，導致資訊稀釋與推理負擔過重，這正是現有 LLM 智慧體在網頁任務中表現不佳的關鍵原因之一。透過先篩選相關語意區塊、再提取細節、最後合成任務導向摘要的三階段流程，系統能產生資訊密度更高且更聚焦的觀察輸入。這種設計讓規模較小的開放權重模型也能專注於真正重要的內容，從而在不擴大模型規模或不進行微調的情況下，顯著提升決策品質與任務成功率。

**Q7：WebChallenger 在哪些基準測試上進行評估，其關鍵結果為何？**
A：WebChallenger 在四個網頁導航基準測試上進行評估，分別是 WebArena、VisualWebArena、Online-Mind2Web 與 WorkArena。在僅使用現成的 32B LLM 與 7B VLM 且未經微調的零樣本設定下，系統分別達到 56.3%、48.7%、51.0% 與 70.9% 的成功率。這些成績不僅在同規模開放權重模型中創下最佳表現，也顯示其已能逼近前沿專有系統的水準。

**Q8：與先前的開放權重系統及專有前沿系統相比，WebChallenger 的效能定位為何？**
A：與先前的開放權重最佳表現相比，WebChallenger 在四大基準上均設立了新的標竿，且其結果是在遠少於基線的運算資源下取得，因為基線方法往往依賴更大模型或微調。相較於動輒使用昂貴專有推理模型的前沿系統，WebChallenger 以極低的推論成本達到相近的成功率，證明了鷹架設計本身就能帶來巨大的效能躍升。這項對比強烈支持了作者的核心論點：當前 LLM 已具備足夠的網頁推理能力，缺的是正確的架構來釋放這些能力。

**Q9：這篇論文提供了什麼樣的證據，說明架構設計（鷹架）能夠替代模型規模或微調？**
A：論文提供的核心證據在於，WebChallenger 僅憑現成的 32B 語言模型與 7B 視覺語言模型，就超越了許多使用更大模型或經過微調的開放權重基線。由於所有效能提升都來自 PageMem 與三大機制的架構創新，而非來自增加參數量或訓練資料，這清楚顯示鷹架設計可以大幅替代模型規模。這項發現挑戰了「網頁導航必須依賴超大專有模型」的既有假設，為資源受限的應用場景開闢了新的可能性。

**Q10：在哪些實際的重複性知識工作場景中，WebChallenger 最能發揮其價值？**
A：WebChallenger 最適合應用於需要重複執行、涉及多步驟網頁互動的知識工作，例如跨網站的資料查詢與彙整、表單自動化填寫、電子商務比價與採購流程，或是企業內部網頁應用程式的例行操作。這些場景的共同特點是任務結構相對固定，但橫跨不同網站與介面，傳統腳本難以維護且缺乏泛化能力。由於 WebChallenger 具備跨網站通用性且推論成本低廉，它特別適合需要大規模、高頻率自動化的商業流程外包與個人生產力提升工具。

**Q11：從產品部署的角度來看，WebChallenger 相較於專有解決方案具備哪些經濟與營運優勢？**
A：WebChallenger 的經濟可行性來自於其完全採用開放權重模型，無需支付昂貴的專有 API 呼叫費用，且能在本地或私有雲環境中運行。其架構設計透過分治觀察與複合動作大幅減少每個任務所需的模型呼叫次數與處理的詞元數量，進一步壓低運算開銷。對於企業而言，這意味著可以在確保資料隱私與合規性的同時，以遠低於閉源替代方案的成本部署高可靠度的網頁自動化解決方案。

**Q12：WebChallenger 的研究方法可能對通用型網頁智慧體領域帶來什麼樣的深遠影響？**
A：WebChallenger 的研究路徑可能促使學界將焦點從「追求更大規模的專有模型」轉向「設計更貼近人類認知的智慧體鷹架」。透過示範架構創新如何釋放現有開放模型的潛能，這項工作鼓勵更多研究者探索觀察抽象化、持久環境記憶與高階動作原語等方向。長遠來看，這可能加速通用型網頁智慧體的生態系統發展，使其不再受限於少數科技巨頭的閉源模型，而是建立在可重現、可擴展的開放基礎設施之上。

**Q13：基於其架構設計，WebChallenger 可能存在哪些潛在的限制？**
A：一項潛在限制在於 PageMem 完全依賴 DOM 結構進行確定性建構，若網站使用極度非語意化的標籤或嚴重依賴 JavaScript 動態生成內容而無法從靜態 DOM 反映真實語意結構時，階層分割可能產生偏差。此外，對於視覺佈局與語意結構嚴重脫節的網頁，僅憑 DOM 導出的區塊摘要可能無法準確捕捉人類使用者實際關注的區域。雖然系統具備視覺語言模型，但當 DOM 結構與視覺呈現不一致時，觀察管線的篩選邏輯仍可能誤判任務相關區域。

**Q14：在什麼樣的情況下，分治觀察管線或複合動作工作流程可能會失效？**
A：分治觀察管線可能在任務目標涉及跨多個語意區塊的隱性關聯時失敗，例如需要比較頁面頂部導航列與底部頁尾資訊才能做出的決策，因為系統可能過早過濾掉看似無關的區塊。複合動作工作流程則可能在遭遇未預期的網站行為或異常狀態轉換時失效，例如下拉選單的非標準展開動畫或表單驗證的動態阻擋機制，這些偏離常見互動模式的情況可能使固定的工作流程序列無法正確處理中間狀態。在這些情況下，智慧體可能需要回退到原子動作層級進行細粒度推理，從而增加步驟數與失敗風險。

**Q15：未來研究可以從哪些方向進一步提升開放權重網頁智慧體的表現？**
A：未來研究可朝幾個方向延伸：首先，結合更強大的視覺理解與 DOM 語意分析，以處理動態渲染與視覺導向的現代網頁應用；其次，發展持續學習機制，讓智慧體在執行任務過程中不斷更新與修正 WebsiteMem，而非僅依賴單次離線探索；最後，可探索將大型語言模型與符號規劃或強化學習結合，使複合動作工作流程能夠自動適應新穎的互動模式，而非僅依賴預設的常見慣例。這些改進將有助於進一步縮小開放權重智慧體與人類表現之間的差距，並提升其在真實世界複雜網頁環境中的穩健性。

## 實務應用指南

### 適用場景

1. **重複性知識工作自動化**：例如跨部門的資料彙整、週期性報表下載、多頁面表單填寫。WebChallenger 的複合動作工作流程能將「搜尋→篩選→匯出」等慣例折疊為單一動作，並以持久記憶記住內部系統的頁面結構，顯著降低每次執行的推論成本。
2. **企業內部網站與 Legacy 系統操作**：許多組織使用的舊版 Web 系統缺乏 API，且介面穩定但操作繁瑣。由於框架無需特定網站轉接器，透過離線探索建立 WebsiteMem 後，即可讓開放權重模型穩定操作這些系統。
3. **電商與供應鏈的比價與庫存監控**：智慧體可利用分治觀察管線，在商品列表頁快速定位任務相關區域（如價格、庫存狀態），避免將整頁無關的推薦商品內容塞入提示，適合需要高頻率執行的監控任務。
4. **長時程申請與審批流程**：如請假系統、報帳平台、政府申辦網站等多步驟互動。程序流暢性機制讓智慧體內化常見互動模式（下拉選單、日期選擇器、分頁表單），減少每個原子步驟都重新推理全頁狀態的開銷。
5. **視覺網頁無障礙與功能巡檢**：結合 7B VLM 與結構化頁面表示法，可針對視覺網頁進行語意區塊層級的檢測，例如確認按鈕文字與視覺呈現是否一致，或驗證互動元素行為是否符合預期。

### 實作前置條件

**資料需求**：
- 目標網站的可存取 DOM 與操作流程樣本，用於離線探索階段建立 WebsiteMem。
- 任務指令的語料範例，用於校準分治觀察管線中「任務相關區域」的選擇邏輯，以及定義複合動作工作流程的觸發條件。

**運算資源**：
- 可本地部署的開放權重模型（論文使用 32B LLM 與 7B VLM，如 Qwen 或 Llama 系列），需具備足夠 VRAM 的 GPU 或高記憶體 CPU 環境。
- 瀏覽器自動化基礎設施（如 Playwright），用於執行離線探索與線上任務互動。
- 儲存空間用於持久化 WebsiteMem 與 PageMem 語意階層資料。

**技能門檻**：
- 熟悉 DOM 結構、HTML 語意標籤與現代前端框架（React/Vue）的渲染行為。
- 具備 LLM 提示工程經驗，能理解並設計多階段子提示（sub-prompt）的資訊流。
- 了解瀏覽器自動化、網頁認證機制（Cookie/SSO）與基本的資安隔離概念。

### 實作步驟建議

1. **模型與瀏覽器環境建置**：部署現成的 32B 等級 LLM 與 7B VLM，設定 Playwright 或同級自動化框架，確保能穩定取得頁面 DOM 與截圖。
2. **開發 PageMem 建構器**：實作從原始 DOM 到結構化頁面表示法的確定性轉換模組。核心是將頁面拆解為具簡短摘要的語意區塊（semantic sections），並保留互動元素的層級關係。
3. **執行離線探索建立記憶**：針對目標網站執行輕量探索與記憶系統，遍歷主要頁面與互動路徑，建立 WebsiteMem。此步驟只需執行一次，後續任務即可複用。
4. **實作分治觀察管線**：建構三階段流程—(i) 瀏覽當前 PageMem 的各區塊摘要；(ii) 由 LLM 選擇任務相關區域；(iii) 僅對選定區域提取細節並合成任務聚焦的觀察摘要。
5. **設計複合動作工作流程**：定義搜尋、下拉選單、表單提交等常見互動模式的固定序列，處理部分狀態變更（partial state changes），並在 workflow 內部以額外的 LLM 子呼叫處理中間狀態。
6. **整合測試與成本監控**：在內部測試環境或公開基準（WebArena、WorkArena）驗證端到端成功率。使用 Langfuse 等工具監控各子提示的 token 使用量，持續優化摘要長度與區塊選擇的精準度。

### 潛在風險與注意事項

- **動態網站與 SPA 的 DOM 漂移**：現代前端框架的動態更新可能使 PageMem 的確定性建構產生時序錯誤。建議整合 MutationObserver 或在關鍵互動後觸發重新建構，確保語意階層與實際頁面同步。
- **持久記憶的時效性**：WebsiteMem 在網站改版後可能過時，導致元素行為記錄失效。應建立版本偵測機制（如 DOM 結構雜湊比對）與定期重新探索的排程，或在偵測到異常時自動退回全頁觀察模式。
- **安全性與權限邊界**：自主網頁導航可能觸及敏感資料或不可逆操作（如刪除、付款）。務必在沙箱環境執行，實作動作白名單、網域限制，並在高風險步驟加入人類在環（human-in-the-loop）確認。
- **幻覺的階層式放大**：若上層 section summary 產生幻覺，下層的細節提取會繼承錯誤。建議在觀察管線中加入驗證檢查點，例如以輕量規則比對提取內容與原始 DOM 屬性。
- **視覺資訊的過濾風險**：過度依賴 DOM 可能遺漏以視覺布局傳達的語意（如顏色標記的狀態）。在 VisualWebArena 這類需要視覺理解的場景，應確保 VLM 路徑能在分治流程中適時補充截圖觀察。

### 與其他技術的整合建議

- **RAG 與企業知識庫**：將 WebsiteMem 的頁面摘要與元素行為向量化，存入 Milvus 或 Weaviate。執行任務前可先檢索歷史操作知識，進一步減少對超大上下文的需求。
- **低程式碼自動化與 RPA**：將 WebChallenger 封裝為標準節點，接入 n8n、Make 或企業現有 RPA 管線。傳統 RPA 處理固定流程，WebChallenger 則負責動態網頁的語意理解與異常處理，兩者互補。
- **可觀測性平台**：整合 LangSmith 或自研追蹤系統，記錄分治觀察管線中每個子提示的輸入輸出。這對於診斷「為何智慧體選錯任務相關區域」至關重要。
- **身份與機密管理**：與 HashiCorp Vault 或企業 SSO 整合，讓瀏覽器自動化環境安全取得登入憑證，避免將密碼或 Token 直接寫入提示或程式碼。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從圖 1 的基準測試結果與第 2.1 節的系統概覽開始，先建立「PageMem 如何把複雜網頁變成目錄」的直覺。接著對照附錄的推論演算法，理解分治觀察管線如何讓小模型也能處理長時程任務。不必急著深入 DOM 解析細節，重點放在「結構化表示法為何能降低推論成本」。
- **AI 工程師**：請聚焦 §2.2 至 §2.5 的機制實作，特別是複合動作 workflows 的狀態機設計與 partial state changes 的處理邏輯。建議直接參考開源程式碼中的提示模板，評估如何將論文使用的 32B/7B 模型替換為貴司內部已部署的模型，並注意離線探索階段與線上推論階段的資源切分。
- **研究人員**：關注作者對 Moravec’s paradox 的論證，以及三項人類認知優勢（選擇性注意力、持久記憶、程序流暢性）如何對應到架構設計。建議深入分析 PageMem 的確定性建構是否為效能提升的充分條件，並思考此鷹架設計能否擴展至非網頁的 GUI 環境（如桌面應用程式或行動介面）。
- **產品經理**：請聚焦第 1 節的問題陳述與圖 1 的成本效益對比。核心訊息是「架構設計勝過模型規模」。評估貴司的重複性知識工作場景中，哪些網站介面穩定且操作步驟繁瑣，最適合以離線探索建立持久記憶，從而估算導入後相較於呼叫專有推理模型的推論成本節省幅度。
