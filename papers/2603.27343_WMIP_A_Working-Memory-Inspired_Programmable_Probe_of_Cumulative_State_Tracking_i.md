## 摘要翻譯

人類的工作記憶使人們能夠維持並更新資訊。大型語言模型（LLMs）在單一提示詞中追蹤更新（且無須寫出中間狀態）時面臨類似需求，但現有的測試在書寫步驟的限制上有所不同。我們提出一個工作記憶啟發式的累積狀態追蹤探測器，其特色為程式計算答案、3 到 100 次更新操作，以及最終狀態、中間狀態或多目標查詢。它在相同的題目上比較不同的輸出協議。在 18 個大型語言模型中，單步算術的準確率為 84.9%，但在經過三到七次更新後需要輸出一個數字的核心題目上，準確率僅為 31.7%。從 50 次更新開始，沒有任何模型的準確率超過 10%。當給予更大的輸出預算，並指示寫出步驟、將答案置於最後一行時，核心題目準確率可達 88.0%，這主要歸因於指令的改變，而非預算的提升。核心題目準確率也與公開的柏克萊函式呼叫排行榜（BFCL）分數呈正相關。這些發現顯示，強大的單步算術能力並不能保證可靠的累積追蹤，且輸出協議會大幅改變所測得的準確率。我們釋出生成器、題目、評分程式碼以及回應，以便在不同深度、查詢類型和協議下進行可重現的比較。

## 深度分析

#### 方法論解析

WMIP（工作記憶啟發式探測器）的核心設計理念源自人類工作記憶（working memory）的更新任務，特別是 Miyake 等人（2000）所提出的「更新功能」（updating function）典範。論文的關鍵洞見在於：現有的 LLM 狀態追蹤測試（如 Minerva、BIG-Bench Hard、GSM-Infinite）雖然結構相似，但對「書寫步驟」（written steps）的限制程度不一，使得測試結果無法純粹反映模型在無外部輔助下的內部狀態維持能力。

**生成器設計（Generator Design）**

WMIP 的生成器採用程式化方式產生題目，具有以下特徵：

1. **三個具名實體（three named entities）**：每個題目初始化三個帶有整數的實體（如 Leo、James、Carol），初始值範圍為 5 至 20，這個範圍設計避免了過於簡單的數字（如個位數）與過於複雜的計算。

2. **三種更新操作類型**：
   - **增益（gains）**：範圍 1 至 10
   - **損失（losses）**：範圍 1 至 5
   - **轉移（transfers）**：範圍 1 至 3
   
   轉移操作的範圍較小是因為它涉及兩個實體的同步變化，較大的數值會使題目難度偏向算術而非狀態追蹤。

3. **可調深度（adjustable depth）**：K 值從 3 到 100 不等，這使得同一生成器可產生不同難度的題目，便於分析模型在不同序列長度下的表現衰減曲線。

4. **程式計算答案（program-computed answers）**：參考答案由短程式計算，確保答案的確定性與可重現性。程式同時計算每個實體被更新的次數（中位數在 K=3 時為 2，K=100 時為 45.5），這提供了額外的題目特徵資訊。

5. **重抽規則（redraw rule）**：排除被查詢實體從未被更新或最終值等於初始值的題目，這個設計避免了模型透過「複製初始值」來猜對答案的捷徑。

**協議設計（Protocol Design）**

WMIP 的方法論精髓在於「同題比較」（same-item comparisons）——同一組題目在不同協議下測試，以分離協議效應與題目難度效應。四種主要協議包括：

1. **核心協議（Core protocol）**：16 詞元預算（token budget）配合「僅回應最終數字」（Respond with ONLY the final number）的指令，採用單整數規則（one-integer rule）。這個設計刻意限制書寫步驟的空間，模擬人類「在腦中保持數值」的工作記憶需求。

2. **大預算核心協議（Large budget core protocol）**：保留核心提示詞但將預算擴增至 512 詞元，仍要求單整數輸出。

3. **書寫步驟協議（Written steps protocol）**：加入「逐步思考」（Think step by step）的指令，提供 512 詞元預算，並以最後一個整數作為答案。

4. **深度協議（Depth protocol）**：將核心協議延伸至 K≥10 的題目，測試長序列下的表現。

**查詢類型多樣性**

生成器支援三種查詢類型：
- **最終狀態查詢（final-state queries）**：詢問某實體在所有更新後的值
- **中間狀態查詢（intermediate-state queries）**：詢問某實體在特定更新步驟後的值
- **多目標查詢（multi-target queries）**：同時詢問多個實體的狀態

這種設計使得 WMIP 不僅是單一能力的測試，而是一個可程式化的探測框架。

**測量效度考量**

論文特別強調測量效度（measurement validity），遵循 Bean 等人（2025）的建議，報告了：
- 整數合規率（integer compliance）
- 截斷率（truncation）
- 種子與措辭敏感度（seed and wording sensitivity）

這些元數據的報告使得結果更具可信度，因為 LLM 評測常因格式問題而產生誤判。

#### 實驗數據解讀

**核心發現的數據意涵**

論文的實驗結果揭示了 LLM 在累積狀態追蹤任務上的嚴重能力落差：

1. **單步算術 vs. 核心題目的落差**：18 個模型在單步算術（K=1）上達到 84.9% 的平均準確率，但在核心題目（K=3 至 7）上僅有 31.7%。這個約 53 個百分點的落差說明了「強單步算術能力」並不能保證「可靠的累積追蹤能力」。

2. **長序列下的災難性衰減**：從 K=50 開始，沒有任何模型在核心協議下超過 10% 準確率。這呈現出一個陡峭的能力衰減曲線，暗示現有 LLM 在缺乏書寫輔助時，內部狀態維持能力存在根本性的瓶頸。

3. **協議效應的驚人幅度**：將核心協議改為書寫步驟協議，核心題目準確率從 31.7% 躍升至 88.0%，提升幅度達 56.3 個百分點。這個結果直接證明了「測量什麼取決於如何測量」（what is measured depends on how it is measured）。

**協議效應的歸因分析**

論文中特別指出，88.0% 的提升「主要由指令改變而非預算改變造成」（mainly due to the instruction changes rather than the budget）。這個發現極為重要，因為它意味著：

- 僅僅擴大詞元預算（大預算核心協議）並不能顯著提升表現
- 「逐步思考」這類指令本身才是關鍵，這與 Kojima 等人（2022）的思維鏈（chain-of-thought）發現一致
- 模型並非缺乏計算能力，而是缺乏在內部追蹤狀態的能力——當允許外部化（externalize）推理過程時，能力便恢復

**BFCL 相關性的意涵**

核心準確率與柏克萊函式呼叫排行榜（Berkeley Function Calling Leaderboard, BFCL）分數呈正相關，這個發現具有重要的實務意涵：

- BFCL 評測的是有狀態、多輪工具使用（stateful, multi-turn tool use）能力
- 兩者的正相關暗示 WMIP 測試的能力可能與實際工具使用場景中的狀態管理需求相關
- 論文採用了區辨效度（discriminant validation）的邏輯（Campbell and Fiske, 1959），將核心的 BFCL 相關性與單步算術、消去法控制組（cancellation controls）的相關性進行比較

**題目範例的直觀展示**

圖 1a 中的 Claude Haiku 4.5 範例生動展示了協議效應：
- 核心協議下回答「28」（錯誤）
- 書寫步驟協議下回答「15 + 2 = 17 … 15 - 3 = 12」（正確）

這個範例說明即使是先進模型，在無書寫輔助時也會犯錯，而錯誤的根源在於無法在內部維持正確的累積狀態。

#### 與現有研究的比較

**與 Minerva 的比較**

Minerva（Xia et al., 2025）的數量狀態任務（quantity-state task）在內容上與 WMIP 最為接近，但關鍵差異在於：
- Minerva 允許 4,096 個輸出詞元，足以讓模型逐步寫出所有運算
- WMIP 的核心協議僅允許 16 詞元，強制模型在內部維持狀態
- 這使得 Minerva 可能「無法充分測試工作記憶需求」（may not pose this demand）

**與 BIG-Bench Hard 的比較**

BIG-Bench Hard（Suzgun et al., 2023）追蹤的是物件之間的成對交換（pairwise object swaps），採用選擇題格式。WMIP 的差異在於：
- 採用自由回應的整數輸出，而非選擇題
- 應用整數更新（可增益、損失、轉移）而非僅交換
- 這使得 WMIP 更接近真實的數值狀態追蹤場景

**與 GSM-Infinite 的比較**

GSM-Infinite（Zhou et al., 2025）變化操作次數但要求逐步推理。WMIP 的設計哲學相反：
- 刻意限制書寫步驟以測試內部狀態維持
- 這形成了互補的測試視角：GSM-Infinite 測試「能寫出來時能做多難」，WMIP 測試「不能寫出來時能做多難」

**與 LLM 工作記憶研究的比較**

Gong 等人（2024）與 Zhang 等人（2024）使用 n-back 任務的匹配偵測（match detection），de Langis 等人（2026）測試模型在跨距任務（span tasks）上達到或超過人類水平。Wang 和 Sun（2026）詢問反覆覆寫的鍵的最後值。WMIP 的獨特貢獻在於：
- 保持所有初始值和更新可見（不像人類操作跨距任務那樣需要記住）
- 這使得 WMIP 測試的是「純粹的累積追蹤」而非「從記憶中提取」

**與表示探測研究的關係**

Li 等人（2025）與 Tang 等人（2026）使用表示探測（representation probes）和介入（interventions）來區分狀態追蹤演算法。WMIP 承認其侷限：最終答案無法顯示模型是「維持」還是「重新計算」狀態。這坦誠的定位使得 WMIP 與表示層級的研究形成互補。

**方法論優勢**

1. **可程式化（programmable）**：生成器支援可調深度、可執行答案、多種查詢類型
2. **同題比較**：分離協議效應與題目效應
3. **測量效度自覺**：報告格式合規率、截斷率、敏感度分析
4. **開放科學**：釋出生成器、題目、評分程式碼與模型回應

**方法論限制**

1. **未涵蓋表示層級**：僅觀察最終答案，無法區分「維持」與「重新計算」
2. **題目範圍有限**：僅使用三個實體與整數操作，未涵蓋更複雜的狀態結構
3. **協議數量有限**：四種協議雖有代表性，但未窮盡所有可能的輸出限制組合

#### 可重現性評估

WMIP 在可重現性方面表現優異，體現了開放科學的精神：

**釋出資源**

3. **評分程式碼（scoring code）**：用於計算準確率、整數合規率等指標
4. **模型回應（responses）**：18 個模型在所有協議下的完整回應

- 評分階段：純文字比對，無需 GPU。

**技能門檻**
- 基礎 Python 程式能力（執行生成器、批次呼叫 API、解析回應）。
- 熟悉 LLM API 的 token 限制與輸出截斷（truncation）處理。
- 統計基礎：理解相關性分析（與 BFCL 分數比較）、敏感度分析（不同措辭/種子）。
- 選修：熟悉 Baddeley 工作記憶理論，有助於設計更深入的研究變項。

### 實作步驟建議

**步驟 1：取得並驗證生成器**
從論文釋出的程式碼（generator）開始，安裝依賴後先用預設參數產生 60 題核心題（K=3, 5, 7）與若干深度題（K=10, 20, 50, 100）。驗證程式計算的參考答案與手算一致，並確認「紅重抽規則」（排除從未更新或回到初始值的實體）正常運作。

**步驟 2：建立協議配置檔**
依論文定義建立至少三種協議：
- **核心協議**：16 詞元上限、單整數規則、提示詞為「Respond with ONLY the final number」。
- **書寫步驟協議**：512 詞元、提示詞包含「Think step by step」，評分取最後一個整數。
- **大預算核心協議**：512 詞元但仍要求單整數，用於分離「預算效應」與「指令效應」。

**步驟 3：批次推論與回應收集**
對每個模型 × 每個協議 × 每道題目發送請求，記錄完整回應、詞元使用量、是否截斷。建議每題跑 3 次不同種子以評估穩定性，並保存原始 JSON 以利後續重現。

**步驟 4：評分與合規性檢查**
實作三層評分邏輯：
1. 提取回應中的整數（正則表達式）。
2. 套用規則：核心協議要求恰好一個整數；書寫步驟協議取最後一個整數。
3. 標記截斷回應（達到詞元上限）為「truncated」，不計入準確率或單獨報告。

**步驟 5：敏感度與相關性分析**
- **措辭敏感度**：用同義改寫的提示詞（如「Answer with just the number」vs「Respond with ONLY the final number」）重跑核心題，量化措辭造成的準確率波動。
- **BFCL 相關性**：取得目標模型的公開 BFCL 分數，計算與 WMIP 核心準確率、皮爾森/斯皮爾曼相關係數，並與「單步算術 vs BFCL」「消去法控制組 vs BFCL」做對比，驗證區辨效度。

**步驟 6：產出報告與決策建議**
輸出包含以下圖表的儀表板：
- 各模型在不同 K 值下的準確率曲線（重現論文圖 1b）。
- 協議 × 模型熱力圖，凸顯哪些模型對「書寫步驟」依賴最重。
- BFCL 散佈圖，標示哪些模型「函式呼叫強但狀態追蹤弱」的反常案例。

### 潛在風險與注意事項

**風險 1：將「核心協議高分」誤判為「真實工作記憶能力」**
核心協議限制輸出預算，但模型仍可能在內部以隱式思維鏈運算。論文明確指出「最終答案無法區分模型是『維持』還是『重算』狀態」。緩解：搭配表徵探測（representation probing）工具，或使用論文中提到的 Li 等人（2025）、Tang 等人（2026）的介入方法。

**風險 2：詞元預算被模型「聰明地」繞過**
部分模型可能在 16 詞元內塞入壓縮推理（如「12」其實是經過內部計算）。這不一定是作弊，但會讓「核心協議」與「書寫步驟協議」的比較失去純度。緩解：在報告中明確標示此一限制，並提供大預算核心協議作為對照。

**風險 3：題目分布偏差**
預設參數（初始值 5–20、增益 1–10、損失 1–5、轉移 1–3）可能不適用於所有應用場景。例如金融場景需要更大的數值範圍與小數。緩解：開放生成器參數，根據目標領域重新校準，並重新驗證紅重抽規則。

**風險 4：與 BFCL 的相關性可能因模型更新而失效**
BFCL 與 WMIP 的正相關是基於 2026 年 10 月的快照。模型版本更新後，相關性可能改變。緩解：每次評測新模型時重新計算相關係數，不要把歷史相關性當作永久預測因子。

**風險 5：單一語言/文化的偏誤**
論文題目以英文撰寫，數字與人名皆為英語文化。中文場景下的數字表達（如「一萬兩千」）可能引入額外難度。緩解：若用於中文模型評測，需本地化題目並重新驗證參考答案計算邏輯。

**風險 6：截斷回應被誤計為錯誤**
達到詞元上限的回應可能包含正確答案但被切斷。緩解：務必區分「truncated」與「wrong」，並在報告中單獨列出截斷率，作為模型「是否試圖書寫步驟」的代理指標。

### 與其他技術的整合建議

**與 BFCL 整合**
BFCL 評估函式呼叫的語法正確性與多步執行能力，WMIP 評估「在沒有書寫步驟空間下維持數字」的能力。兩者互補：建議在模型選型流程中，先用 BFCL 篩掉語法錯誤率高的模型，再用 WMIP 篩掉「需要書寫步驟才能正確追蹤」的模型。論文的區辨效度邏輯（discriminant validation）可作為整合框架——核心準確率應與 BFCL 正相關，但與「單步算術」「消去法」不相關或弱相關。

**與思維鏈（CoT）與自洽性（Self-Consistency）整合**
WMIP 的書寫步驈協議本質上就是強制 CoT。可進一步實驗：在核心協議下加入「內部 CoT」（透過 system prompt 鼓勵模型在心中推理但不輸出），觀察是否能逼近書寫步驈協議的 88.0%。若能，則代表模型本身具備追蹤能力，只是輸出介面限制了它。

**與 Agent 框架（如 LangGraph、AutoGen）整合**
Agent 框架通常會把中間狀態外顯化（寫入 state dict），繞過模型的內部追蹤需求。WMIP 可用來回答：「這個 Agent 是否真的需要外顯狀態？」若底層模型 WMIP 核心準確率 >70%，可考慮簡化 Agent 架構、減少 token 消耗；若 <30%，則外顯狀態是必要設計。

**與表徵探測（Representation Probing）整合**
如 Li 等人（2025）與 Tang 等人（2026）所示，可在模型隱層訓練線性探測器，判斷模型內部是否真的「維持」了某個實體的值。WMIP 提供行為層級的 ground truth，兩者結合可建立「行為—表徵」對齊分析。

**與 RAG 與長上下文模型整合**
WMIP 的 K=100 題目對應約 1k–2k tokens 的上下文。隨著長上下文模型（如 1M token 視窗）普及，可擴展 WMIP 至 K=500、1000，測試「上下文夠長時，模型是否會退化為『在長上下文中即時搜尋』而非『工作記憶追蹤』」。

### 給不同背景讀者的閱讀建議

**給初學者**：先讀摘要與圖 1，建立「LLM 在單步算術很強、但在多步累積追蹤上會崩潰」這個核心直覺。接著看第 3.1 節的題目範例（Leo、James、Carol），親手跑一次生成器產生幾道題，丟給你常用的聊天模型，觀察它在 K=3 與 K=20 的差異。不需要深入統計細節，重點是體驗「為什麼需要工作記憶」。

**給 AI 工程師**：重點讀第 3 節（探測設計）與第 4.6 節（BFCL 相關性）。把 WMIP 視為一個「黑盒壓力測試工具」，整合到你的模型評估 pipeline 中。特別注意協議設計的巧思：16 詞元、單整數規則、紅重抽規則——這些都是為了「純化」所測量的能力。實作時務必保留截斷率與整數合規率，這些指標比單一準確率更能反映真實部署風險。

**給研究者**：第 2 節（相關工作）與附錄 H 是寶庫。論文刻意與 Minerva、GSM-Infinite、n-back 任務做區隔，論證「為什麼需要新的探測」。建議從三個方向延伸：(1) 將 WMIP 擴展到非整數（浮點數、機率、向量）；(2) 結合表徵探測，回答「模型內部是否真的維持狀態」；(3) 跨語言、跨文化驗證，探討數字表達方式是否影響追蹤能力。論文的開放釋出（生成器、題目、回應）是極佳的起點。

**給產品經理**：把 WMIP 當作「模型選型的 X 光」。如果你的產品涉及多輪、有狀態的對話（例如 Agent、儀表板、遊戲），不要只看模型在標準 benchmark 上的排名——那些 benchmark 通常允許書寫步驟，掩蓋了真實部署中的瓶頸。WMIP 的核心協議模擬了「使用者期待模型即時回答、不會等它寫完推理」的情境。建議在採購或自訓練模型時，要求團隊提供 WMIP 核心協議在 K=10、20、50 的分數，這比單一步驟的算術分數更能預測產品體驗。
