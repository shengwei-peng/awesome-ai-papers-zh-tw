## ⚡ TL;DR

本文解決開源模型透明度不足、德語代表性低，以及長上下文高併發部署成本高昂的問題。
提出SoofiS，採Mamba-Transformer混合MoE，每詞元僅激活3B參數且快取近恆定。
在英德與程式碼基準領先開源及歐洲主權模型，長上下文吞吐量達稠密模型八至九倍，並開放權重與訓練產物。

## 摘要翻譯

我們提出 Soofi S 30B-A3B，一個適用於德語與英語、開源且自主可控（sovereign）、採用 Mamba-Transformer 混合架構（hybrid Mamba Transformer）的混合專家（Mixture-of-Experts, MoE）基礎模型（foundation model）。其混合設計每詞元（token）僅啟用 300 億參數中的 30 億（active parameters），並在上下文增長時保持推論快取（inference cache）近乎恆定，使其在長上下文（long-context）、高併發部署（high-concurrency deployment）情境中，相較於稠密模型（dense models）具有決定性的吞吐量（throughput）優勢。Soofi S 在約 27 兆詞元上進行預訓練（pretrained），並刻意對德語加權（up-weighted German），在英語與德語的綜合基準測試上與 140 億至 270 億參數的稠密模型相當，同時在 17 個開源基礎模型中於兩種語言均取得最佳程式碼綜合得分（code aggregates），並在我們的比較中超越所有歐洲主權基線模型（European sovereign baseline），包括啟用參數（active parameters）遠大於它的模型。在完全開源模型（fully open models）中，Soofi S 取得最高的英語與德語評估分數，領先 OLMo 3 32B 與 Apertus 70B。Soofi S 於德國工業人工智慧雲（German Industrial AI Cloud）全程端到端建置，這是由德國電信（Deutsche Telekom）在慕尼黑（Munich）營運的主權級 HPC 規模 AI 基礎設施（sovereign HPC scale AI infrastructure）。Soofi S 將以高度寬鬆的開放取用條款（open-access terms）釋出：模型權重（weights）、選定的中間檢查點（intermediate checkpoints）、完整的逐來源資料核算（per-source data accounting）、超參數（hyperparameters），以及訓練與評估程式碼（training and evaluation code）。在來源授權許可的範圍內，資料建構產物（data-construction artifacts）將以寬鬆授權釋出；商業授權來源（commercially licensed sources）則會以彙總統計（aggregate statistics）與精確的混合比例核算（mixture accounting）加以記錄。

### 核心貢獻（3～5點）
- 提出德英雙語自主可控開源基礎模型 Soofi S 30B-A3B，採用 MoE 與 Mamba-Transformer 混合架構，每詞元僅啟用 30 億參數，並在長上下文下維持近乎恆定的推論快取，顯著提升高併發部署的吞吐量。
- 在約 27 兆詞元上預訓練並刻意對德語加權，於英語與德語綜合基準測試上可與 140 億至 270 億參數的稠密模型媲美，並在 17 個開源基礎模型中取得雙語最佳程式碼綜合得分。
- 超越所有比較中的歐洲主權基線模型（包括啟用參數更大的模型），並在完全開源模型中領先 OLMo 3 32B 與 Apertus 70B。
- 全程於德國工業人工智慧雲（德國電信在慕尼黑營運的主權級 HPC 規模 AI 基礎設施）端到端建置，展現歐洲在地自主訓練大型基礎模型的能力。
- 以高度寬鬆的開放取用條款釋出，涵蓋模型權重、中間檢查點、逐來源資料核算、超參數、訓練與評估程式碼，以及（在授權允許下）資料建構產物。

### 適合對象
對開源大型語言模型、多語言（特別是德語與英語）基礎模型、混合專家（MoE）與 Mamba-Transformer 混合架構、長上下文與高併發推論效率，以及歐洲主權 AI 基礎設施與資料治理感興趣的研究人員、工程師與政策制定者。

## 深度分析

#### 方法論解析

Soofi S 30B-A3B 的核心方法論可拆解為「架構選用（architecture selection）」、「訓練配方（training recipe）」與「資料課程（data curriculum）」三個環節，三者共同指向一個目標：在德語（German）與英語（English）雙語場景中，同時達到開源模型頂尖能力與長上下文（long-context）高併發（high-concurrency）部署效率。

**架構：Nemotron 3 Nano 參考設計的混合 Mamba–Transformer MoE**

Soofi S 直接採用 NVIDIA 公開的 Nemotron 3 Nano 參考架構，屬於 **hybrid Mamba Transformer（Mamba-Transformer 混合架構）** 加上 **Mixture-of-Experts（MoE，混合專家模型）**。具體配置為 52 層：23 層 Mamba-2 序列混合層、23 層細粒度 MoE 層（含 shared experts），以及 6 層 Grouped-Query Attention（GQA，分組查詢注意力）層稀疏分佈於深度中。總參數量約 31.6B，但每個詞元（token）僅激活約 3.2B 參數（含嵌入層約 3.6B），即 **active parameters（啟用參數）** 僅約總量的十分之一。這種設計的關鍵優勢在於：只有 6 層 GQA 需要維護 **key-value（KV）cache（鍵值快取）**，而 Mamba-2 層使用固定大小的遞迴狀態（recurrent state）進行序列混合，因此 **inference cache（推論快取）** 隨上下文長度增長近乎恆定。這與 **full-attention dense models（全注意力稠密模型）** 的 KV cache 隨序列長度線性增長形成鮮明對比，也是 Soofi S 在長上下文與高批次（batch）服務時取得高 **throughput（吞吐量）** 的結構性原因。

選擇「直接複用公開參考架構」本身是一個值得注意的方法論決策。作者指出這麼做有三項理由：第一，可部署性（deployability），Nemotron 3 Nano 已被 vLLM 等主流開源推論與服務引擎支援，Mamba-2、GQA、MoE 等核心運算已有成熟優化 kernel；第二，可稽核性（auditability），公開架構的設計動機與消融實驗已被詳細記錄，避免閉門重新設計帶來的不透明；第三，工程風險控制，讓團隊能將資源集中於資料策劃與訓練穩定性。這種「不重新發明架構，而是將開放設計與在地資料、主權基礎設施結合」的策略，反映了當前開源大型語言模型（open language models）領域的一種務實範式轉移。

**訓練配方：Warmup–Stable–Decay 與分階段預訓練**

訓練採用 **Warmup–Stable–Decay（WSD）** 學習率排程，這是近年來大規模語言模型預訓練中逐漸受到重視的配方。WSD 的特點是在大部分訓練期間保持較高且穩定的學習率，只在最後階段快速衰減，以促進模型收斂。相較於傳統 cosine decay，WSD 被認為有助於持續學習與後續繼續預訓練（continual pretraining），並且能夠在 decay 階段顯著提升下游任務表現。Soofi S 的訓練分為三個階段，總共約 26.68T 詞元（tokens），作者承諾公開每階段的詞元預算（per-phase token budgets）、階段邊界、優化器（optimizer）與所有 **hyperparameters（超參數）**。這種透明度對於第三方重現（reproduce）與稽核至關重要。

**資料課程：德語加權的雙語與程式碼混合**

資料層面，Soofi S 刻意提高德語比例（up-weighted German），並維持德語：英語：程式碼（code）的明確混合比例。總預訓練量約 27T tokens，其中德語資料被加權以彌補一般多語言模型（multilingual models）對德語代表性不足的問題。作者強調會釋出完整的逐來源統計（per-source data accounting），區分資料集卡片（dataset card）的估計值與經 tokenizer 精確計算的 consumed-token counts（實際消耗詞元數）。這種做法直接回應了當前許多模型僅公布 aggregate tokencount（總詞元數）而缺乏 mixture accounting（混合比例核算）的批評。

**基礎設施：主權級 HPC 訓練**

Soofi S 全程在德國電信（Deutsche Telekom）於慕尼黑營運的 **German Industrial AI Cloud（德國工業人工智慧雲）** 上訓練，這是一個 **sovereign HPC scale AI infrastructure（主權級 HPC 規模 AI 基礎設施）**。這意味著訓練過程、資料儲存與模型權重（model weights）的生成均在歐盟境內完成，符合歐洲對於數位主權（digital sovereignty）與資料在地化的政策訴求，也為後續的商業與政府部署提供了合規基礎。

#### 實驗數據解讀

Soofi S 的實驗設計圍繞兩條主軸展開：一是與 16 個開源基線模型在英語與德語能力上的比較；二是在長上下文服務情境下的 **aggregate decode TPS/GPU（彙總解碼 TPS/GPU）** 測量。以下分別解讀。

**能力基準測試（benchmarks）表現**

作者報告 Soofi S 在以下幾個維度取得領先：

- **English aggregate（英語綜合）** 與 **German aggregate（德語綜合）**：在 17 個開源基礎模型中，Soofi S 的雙語綜合表現最高，超過 OLMo 3 32B 與 Apertus 70B 等 **fully open models（完全開源模型）**。
- **Code aggregates（程式碼綜合得分）**：Soofi S 在英語與德語程式碼基準測試中均取得最佳綜合分數，這對於一個以德英雙語為主的模型而言尤為突出，顯示其資料混合中 code 比例與品質經過精心設計。
- **數學與科學推理**：在 GSM8K（小學數學文字問題）與 GPQA-Diamond（研究生級科學問答）等任務上表現強勁，達到 dense 14B–27B 模型的水準。
- **European sovereign baseline（歐洲主權基線模型）**：Soofi S 在每個德語基準測試上均優於所有歐洲主權基線，包括啟用參數遠大於它的模型。

這些結果的意義在於：Soofi S 以僅約 3.2B active parameters 的推理成本，達到了通常需要 14B–27B active parameters 的 dense models（稠密模型）才具備的能力。這驗證了 MoE 架構「以稀疏激活換取容量」的設計假設，也顯示德語加權並未以犧牲英語能力為代價，反而因為雙語對齊與 code 資料的強化，在兩種語言上都取得競爭力。

**長上下文服務效率測量**

圖 1 是本文最具說服力的實驗證據之一。測量採用 TP=1、單張 NVIDIA B200 GPU、vLLM 引擎與 **latency-subtraction protocol（延遲減除協定）**，在 batch-32 協定下測量不同上下文長度的 **aggregate decode TPS/GPU（彙總解碼 TPS/GPU）**。

- 在 40K context（40K 上下文）時，Soofi S 的 aggregate decode TPS/GPU 是 dense 14B–24B 模型的 8–9 倍。
- 從 4K 到 256K 的輸入上下文長度（input context length）範圍內，Soofi S 的解碼吞吐量幾乎保持平坦；相對地，full-attention dense models 隨上下文增長而顯著下降。
- 圖 1(a) 的 Capability Index（能力指數）將 Code、GSM8K、GPQA-Diamond、English aggregate、German aggregate 五個 **benchmark groups（基準測試群組）** 標準化（normalizing）後取平均，顯示 Soofi S 同時位於能力與效率的前沿。

這些數據的實務意涵非常明確：在長上下文、高併發部署（long-context, high-concurrency deployment）場景中，決定生成成本的不是名義參數量，也不是每詞元參數（parameters per token），而是 **memory bandwidth（記憶體頻寬）**。由於 Soofi S 的 per-sequence state（每序列狀態）小且近乎恆定，它在批次處理時能顯著減少記憶體讀取壓力，從而降低單位詞元的服務成本。這對於需要處理長文件、程式碼庫、法律合約或科學文獻的應用特別有利。

**需要注意的解讀細節**

首先，實驗比較的是 base model（基礎模型），而非經過指令微調（instruction tuning）或對齊（alignment）後的 chat model。因此這些分數反映的是預訓練知識與推理能力，而非對話實用性。其次，部分對手如 Qwen3 35B-A3B 同樣是 MoE 架構，Soofi S 在效率上與其接近，但在德語能力上勝出，這凸顯了資料策劃的重要性。第三，圖 1 的測量環境是特定的（B200、vLLM、TP=1），在其他硬體或服務框架下數字會有所不同，但趨勢應保持一致。

#### 與現有研究的比較

Soofi S 的定位可從三個維度理解：相對於國際前沿 dense/MoE 模型、相對於歐洲主權模型、以及相對於完全開源（fully open）運動。

**相對於國際 dense 與 MoE 模型**

在國際開源模型中，Qwen3 系列、Gemma 3、Ministral、OLMo 3 等代表了當前主流方向。Soofi S 的 active parameters 僅約 3.2B，卻能在 English aggregate 與 German aggregate 上匹配 14B–27B dense models。這與 Qwen3 35B-A3B 等 MoE 模型類似，都利用稀疏激活降低推理成本。然而 Soofi S 的差異化在於：

1. **語言聚焦**：Qwen3、Gemma 3 等模型面向多語言或英語優化，德語僅是眾多語言之一；Soofi S 則將德語與英語並列為核心，並在資料混合中 up-weighted German。
2. **長上下文效率**：由於採用 hybrid Mamba Transformer，Soofi S 的 KV cache 僅存在於 6 層 GQA，而 Qwen3 35B-A3B 等傳統 Transformer-based MoE 仍須為所有注意力層維護 KV cache，因此在極長上下文時 Soofi S 的記憶體佔用與吞吐量優勢會進一步放大。
3. **程式碼能力**：Soofi S 在英語與德語 code aggregates 上均取得最佳，這在專注非英語的模型中較為少見。

**相對於歐洲主權模型**

歐洲近年推出多個強調數位主權的開源模型，包括 EuroLLM、Apertus、Teuken、Salamandra 等。這些模型通常強調多語言覆蓋與開放透明，但在 frontier capability（前沿能力）上往往落後於國際頂尖模型。Soofi S 的貢獻在於打破這個取捨：它同時具備歐洲主權屬性（德國基礎設施、德語聚焦、完整資料透明）與國際競爭力。作者明確指出 Soofi S 在每個德語基準測試上都優於所有歐洲主權基線，包括 active parameters 更大的模型。這對歐洲 AI 戰略具有指標意義。

**相對於完全開源運動**

OLMo 3 32B 與 Apertus 70B 是 fully open models 的代表，釋出權重、訓練資料與程式碼。Soofi S 在此基礎上進一步承諾釋出 selected intermediate checkpoints（選定中間檢查點）、full per-source data accounting（完整逐來源資料核算）、hyperparameters（超參數）、training and evaluation code（訓練與評估程式碼），並在授權允許下釋出 data-construction artifacts（資料建構產物）。這種「radically open」姿態回應了社群對 weight-only releases（僅釋出權重）的批評，也將成為未來開源模型透明度的參考標竿。

**限制與潛在弱點**

儘管成果顯著，Soofi S 仍存在若干限制：

1. **語言範圍有限**：僅聚焦德語與英語，對於其他歐洲語言（法語、義大利語、西班牙語等）並未優化，這限制了其作為泛歐多語言模型的適用性。
2. **架構非原創**：Soofi S 直接採用 Nemotron 3 Nano 參考設計，未提出新的架構創新；其貢獻主要在於資料、訓練與開放性，而非模型結構本身。
3. **Mamba 層的長程依賴風險**：雖然 Mamba-2 提供恆定狀態大小，但在極長上下文或需要精確檢索細節的任務（如 needle-in-a-haystack）上，狀態壓縮可能導致資訊遺失。本文未詳細報告此類針對性評估。
4. **基礎模型而非對話模型**：實驗僅評估 base model，未涉及指令遵循、安全性、幻覺（hallucination）或對齊後的實用性。
5. **資料授權複雜性**：雖然作者承諾完整記錄，但 commercially licensed sources（商業授權來源）無法直接釋出原始資料，第三方重現時仍需自行取得這些來源，這會影響完全可重現性。
6. **比較基線選擇**：作者選擇的 16–17 個模型雖具代表性，但未包含部分更大規模的國際模型（如 Llama 4、DeepSeek-V3 等），因此「最強開源模型」的宣稱應理解為在特定比較集合與任務範圍內成立。

#### 可重現性評估

可重現性（reproducibility）是 Soofi S 的核心賣點之一。作者承諾釋出的 artifact 包括：

- **模型權重（model weights）**：Soofi S 30B-A3B Base 的最終權重。
- **中間檢查點（intermediate checkpoints）**：選定的訓練階段檢查點，有助於研究訓練動態與遺忘行為。
- **完整逐來源資料核算（per-source data accounting）**：包括 Table 6、Table 8、Table 10 等詳細統計，區分 dataset-card 估計與 tokenizer-exact consumed-token counts。
- **超參數（hyperparameters）**：涵蓋學習率排程、優化器、批次大小、MoE 路由配置等。
- **訓練與評估程式碼（training and evaluation code）**：公開於 GitHub，讓第三方能夠重現訓練與評估流程。
- **資料建構產物（data-construction artifacts）**：在來源授權允許下，釋出可重現資料混合的腳本與中間產物；對於商業授權來源，則提供 aggregate statistics（彙總統計）與 exact mixture accounting（精確混合比例核算）。

這種釋出程度顯著優於常見的 weight-only releases。特別是 per-source data accounting 與 mixture accounting，能讓研究者稽核（audit）資料來源是否包含偏見、版權爭議或品質問題，也能讓社群基於相同資料配方訓練變體模型。

然而，可重現性仍有實務門檻：

1. **硬體門檻**：訓練 30B 參數的 MoE 模型需要大規模 GPU 叢集，雖然 Soofi S 在德國電信的主權級 HPC 上完成，但一般研究機構難以複製相同規模的運算資源。
2. **商業授權資料**：部分資料來源需商業授權，無法直接公開，第三方必須自行取得並驗證授權條款。
3. **隨機性與浮點運算**：大規模分散式訓練中的硬體拓撲、通訊順序、浮點精度差異可能導致細微差異，即使超參數相同，最終權重也可能不完全一致。
4. **評估環境依賴**：圖 1 的 throughput 測量依賴 B200、vLLM 特定版本與 latency-subtraction protocol，重現時需使用相同軟硬體配置才能獲得一致數字。

整體而言，Soofi S 在開放性上達到目前開源基礎模型（open-source foundation model）的前沿水準，尤其在資料透明度方面樹立了新標竿。對於無法完全重現訓練的研究者，釋出的中間檢查點與詳細資料統計仍能支援大量下游研究，例如分析訓練階段對語言能力的影響、進行遺忘學習（unlearning）實驗、或開發更高效的推論 kernel。

#### 未來研究方向

Soofi S 的發布為多個後續研究方向開啟了大門，以下從技術、應用、政策與社群四個層面提出可能的延伸。

**技術層面**

1. **指令微調與對齊（Instruction Tuning & Alignment）**：將 Soofi S Base 進一步發展為 chat/instruct 版本，探索德語與英語雙語指令遵循、RLHF（基於人類回饋的強化學習）或 DPO（直接偏好優化）的最佳配方。
2. **長上下文能力極限測試**：針對 Mamba-2 與稀疏 GQA 的組合，進行 needle-in-a-haystack、長文件問答、長程式碼庫理解等針對性評估，理解狀態壓縮對精確召回的影響。
3. **擴展至百萬級上下文（1M+ tokens）**：測試 Soofi S 在超過 256K 上下文時的穩定性與吞吐量，並開發對應的推論優化 kernel。
4. **MoE 路由與負載平衡研究**：分析德語、英語、code 等不同領域是否激活不同專家（expert specialization），並探索專家剪枝、專家合併等壓縮技術。
5. **與其他高效架構的比較**：將 hybrid Mamba Transformer 與 sparse attention（稀疏注意力）、linear attention（線性注意力）、或狀態空間模型變體進行系統性比較。

**應用層面**

6. **德語專業領域適配**：針對法律、醫療、工程、金融等德語專業領域進行 domain-specific continual pretraining（領域持續預訓練）或微調。
7. **程式碼生成與軟體工程工具**：利用 Soofi S 在德語與英語 code aggregates 上的強項，開發雙語程式碼助手、測試生成、程式碼審查等應用。
8. **多模態擴展（Multimodal Extension）**：將 Soofi S 的語言能力與視覺編碼器結合，發展德英雙語視覺語言模型。
9. **工具使用與代理系統（Tool Use & Agents）**：評估 Soofi S 在函數呼叫、檢索增強生成（RAG）、多步推理代理上的表現。

**政策與主權層面**

10. **數位主權與合規研究**：探討 Soofi S 在 GDPR、EU AI Act 等法規框架下的部署優勢與風險，建立歐洲主權 AI 的合規範本。
11. **資料授權與開放生態系統**：研究如何在保護商業授權資料權益的同時，最大化訓練資料的開放性與可稽核性。
12. **能源效率與綠色 AI**：由於 Soofi S 在長上下文服務上的高效率，可進一步量化其相較於 dense models 的碳排放減少量，推動永續 AI 部署。

**社群與生態層面**

13. **開放資料重建計畫**：鼓勵社群基於 Soofi S 釋出的資料配方，使用開放授權資料重建等價資料集，降低對商業授權來源的依賴。
14. **中間檢查點研究**：利用釋出的 intermediate checkpoints 研究能力湧現（emergence）、語言平衡演化、遺忘與災難性遺忘等現象。
15. **跨語言遷移學習**：研究 Soofi S 的德英雙語表徵是否能有效遷移至其他日耳曼語系或相近語言，作為低資源語言模型的起點。

總結來說，Soofi S 30B-A3B 不僅是一個性能強勁的德英雙語基礎模型，更是一個展示「主權基礎設施 + 公開參考架構 + 極致資料透明 + 長上下文效率」如何結合的範例。未來研究可在其開放的 artifact 基礎上，持續推動歐洲與全球開源語言模型的能力、效率與可信度。

## 論文問答

**Q1：當前開源語言模型在實際部署時存在哪些主要缺口，Soofi S 試圖一次解決哪些問題？**

A：現有開源模型大多面臨三個明顯缺口：第一，「開源」往往僅釋出權重，缺少資料、配方與決策細節，難以稽核或重現；第二，通用多語言模型常以英語為中心，德語的經濟與科學重要性未獲得相應的資料比例；第三，全注意力稠密模型在長上下文與高併發情境下，鍵值（KV）快取會隨序列長度快速膨脹，導致記憶體頻寬成為推論成本的瓶頸。Soofi S 30B-A3B 同時針對這三個缺口，提供一個德英雙語、主權可控且推論快取接近恆定的混合專家模型，並以高度開放的方式釋出完整訓練產物。

**Q2：為什麼全注意力稠密模型在長上下文、高併發部署中會變得昂貴？**

A：在生成階段，每個解碼詞元都必須重新讀取模型權重，而對於 Transformer 而言，還要重新讀取批次中每個序列的注意力快取；當上下文長度達到數萬甚至數十萬詞元時，KV 快取的大小會遠超過權重本身，成為記憶體頻寬的主要消耗來源。由於記憶體頻寬是決定推論速度的關鍵硬體指標，這使得全注意力稠密模型的吞吐量隨上下文增長而顯著下降。Soofi S 採用 Mamba-2 層作為主要序列混合機制，使每序列狀態保持固定且接近恆定，從而在長上下文與高併發情境中獲得結構性的吞吐優勢。

**Q3：為什麼需要一個主權的德英雙語基礎模型？**

A：德語是全球重要的經濟、科學與工業語言，但在許多多語言模型中，其訓練資料比例與實際影響力不成正比，導致德語能力相對不足。此外，對歐洲企業與公共機構而言，模型訓練、資料儲存與運算基礎設施的主權可控性日益重要，能避免對非歐洲雲端與模型的過度依賴。Soofi S 全程在德國電信於慕尼黑營運的德國工業人工智慧雲上訓練，並刻意對德語資料進行加權，展現了在地基礎設施也能支撐前沿級基礎模型的可能性。

**Q4：Soofi S 的核心架構是什麼，為何能在僅啟用約 3B 參數的情況下達到 30B 級容量？**

A：Soofi S 採用 Nemotron 3 Nano 的 Mamba-Transformer 混合專家模型參考設計，全網共 52 層，包含 23 層 Mamba-2 序列混合層、23 層細粒度 MoE 層，以及 6 層分組查詢注意力（GQA）層。總參數約 316 億，但每個前向傳播僅激活約 32 億參數，因此具備 30B 級模型的容量，卻只有約 3B 活躍參數的推論成本。此外，只有 6 層 GQA 層需要維護 KV 快取，其餘 Mamba-2 層使用固定大小的遞迴狀態，這是其在長上下文服務中保持高效率的關鍵。

**Q5：作者為何選擇直接採用 Nemotron 3 Nano 的參考設計，而非自行設計全新架構？**

A：這是一項經過深思熟慮的決定，主要基於可部署性、可重現性與工程務實三個理由。Nemotron 3 Nano 的架構已被整合進 vLLM 等主流開源推論與服務引擎，並具備針對 Mamba-2、GQA 與 MoE 元件高度優化的核心，能直接進行生產級部署與吞吐測量。同時，採用已公開且經過消融實驗驗證的參考設計，可避免重複進行大量架構搜尋，讓研究團隊專注於資料課程、德語加權與開放釋出等貢獻。

**Q6：Soofi S 所謂的「高度開放」具體包含哪些產物，與僅釋出權重的模型有何不同？**

A：不同於常見的僅釋出權重發布，Soofi S 將在高度開放的條款下釋出模型權重、選定的中間檢查點、完整的逐來源資料核算、超參數，以及訓練與評估程式碼。在來源授權允許的範圍內，團隊還會釋出資料建構產物與可重現的資料混合腳本；對於商業授權來源，則提供彙總統計與精確的混合比例核算。這使得第三方不僅能使用模型，更能稽核、延伸，甚至在條件允許時重建整個預訓練資料混合物。

**Q7：Soofi S 在英語與德語基準測試上的整體表現如何，與其他開源模型相比處於什麼位置？**

A：Soofi S 在英語綜合與德語綜合基準測試上達到同級最佳表現，並在 17 個開源基礎模型中取得德語與英語程式碼綜合得分的最佳成績。它能與 14B 至 27B 的稠密國際模型在英語與德語綜合表現上匹敵，但活躍參數成本僅為其一小部分；在所有歐洲主權基線模型中，Soofi S 也超越了包括啟用參數大得多的對手。在完全開源模型中，Soofi S 的英語與德語評估分數高於 OLMo 3 32B 與 Apertus 70B，顯示開放透明與前沿能力可以並存。

**Q8：Soofi S 在長上下文服務效率上的實測結果為何？**

A：在 40K 上下文長度與 batch-32 協定下，Soofi S 的彙總解碼 TPS/GPU 達到稠密 14B–24B 模型的 8 至 9 倍，顯示其在長上下文高併發情境中的結構性優勢。更關鍵的是，從 4K 到 256K 的輸入上下文長度範圍內，Soofi S 的彙總解碼 TPS 幾乎保持平坦；相對地，全注意力稠密模型則隨上下文增長而明顯衰退。這項結果證實，透過 Mamba-2 固定遞迴狀態與稀疏 MoE 的設計，可以在維持前沿能力的同時，顯著降低長上下文生產部署的成本。

**Q9：Soofi S 的預訓練資料課程與透明度有哪些具體內容？**

A：Soofi S 採用三階段、共約 26.68 兆詞元的德英雙語資料課程，並刻意對德語資料進行加權，以彌補德語在通用多語言模型中的代表性不足。團隊釋出完整的預訓練語料統計，包括每個資料來源在每個階段的詞元數量，並區分資料卡片估算值與經過分詞器精確計算後的實際消耗詞元數。此外，他們還公開德語、英語與程式碼的混合比例及其設計理由，這與僅報告總詞元數量的常見做法形成鮮明對比。

**Q10：Soofi S 最適合哪些實際部署情境？**

A：Soofi S 特別適合需要同時處理長上下文與高併發請求的生產環境，例如法律文件分析、財務報告摘要、技術手冊問答，以及需要持續對話歷史的客戶支援系統。在這些情境中，傳統全注意力稠密模型會因 KV 快取膨脹而導致吞吐量急劇下降，Soofi S 卻能維持接近恆定的每序列狀態與高彙總解碼 TPS。對於必須在本地主權基礎設施上運行、同時要求低延遲與高吞吐的歐洲企業與政府機構而言，這項優勢尤為重要。

**Q11：企業在評估 Soofi S 時，應如何權衡其能力與營運成本？**

A：企業應注意到 Soofi S 擁有約 30B 級模型的容量，但每個詞元僅激活約 3.2B 參數，這意味著在相同硬體上可達到遠低於稠密模型的記憶體頻寬需求與推論成本。由於只有 6 層 GQA 層維護 KV 快取，隨著上下文增長，快取佔用的額外記憶體非常有限，使其在長上下文服務中具備顯著的規模經濟效益。此外，模型在德國主權 HPC 規模 AI 基礎設施上訓練完成，對於有資料落地、合規與供應鏈自主需求的組織來說，也降低了地緣與監管風險。

**Q12：Soofi S 對歐洲與全球開源 AI 生態系可能帶來什麼影響？**

A：Soofi S 證明了歐洲主權基礎設施與完全開源釋出模式，也能訓練出與國際前沿模型競爭的基礎模型，這有助於減少對非歐洲模型供應商的依賴。其完整的資料核算、超參數與訓練程式碼釋出，為開源社群設立了更高的透明度標準，使第三方能夠進行獨立稽核、重現與後續研究。長遠而言，這種結合語言主權、硬體主權與開放科學的做法，可能推動更多在地化、可信任且可擴展的 AI 系統發展。

**Q13：Soofi S 目前有哪些已知的限制或適用範圍？**

A：Soofi S 的設計重點放在德語與英語，因此對其他語言的支援與表現尚未經過系統性評估，無法直接視為通用多語言模型。此外，本文報告的是基礎模型（Base model），尚未經過指令微調或安全對齊，因此在對話、指令遵循與有害內容拒絕等方面仍需後續處理。雖然 MoE 架構降低了活躍參數成本，但專家路由的負載平衡與大規模分散式訓練的穩定性，也對部署與維運提出了額外的工程要求。

**Q14：使用 Soofi S 時可能遇到哪些失敗案例或風險？**

A：作為基礎模型，Soofi S 可能會產生幻覺、重複或放大預訓練資料中的偏見與錯誤資訊，特別是在需要事實精確性的德語區域知識或法律應用中。雖然其在程式碼綜合得分上表現突出，但生成的程式碼仍可能包含錯誤、安全漏洞或不適用於特定執行環境，因此必須經過人工審查與安全測試。另外，由於訓練資料包含商業授權來源，使用者在二次分發或商業應用時，應仔細確認各資料來源與模型權重的授權條款，以避免合規風險。

**Q15：Soofi S 未來可能朝哪些方向進一步發展？**

A：未來最直接的方向是進行指令微調與安全對齊，將 Base 模型轉化為可靠且符合人類偏好的對話與助理模型。團隊也可能擴展資料課程至更多歐洲語言，並進一步探索更大規模或更長訓練詞元預算下的擴展行為，以提升模型在數學、科學與多語言任務上的表現。此外，針對 Mamba-Transformer 混合架構的推論優化、專家路由策略改進，以及與開源社群協作的獨立稽核與紅隊測試，都是值得持續投入的研究與工程方向。

### 實作步驟建議

1. **取得並稽核模型產物**  
   從 Hugging Face / GitHub 下載 Soofi S 30B-A3B 權重、選定中間檢查點、資料混合比例表與訓練/評估程式碼。先核對逐來源資料核算與論文 Table 6、8、10 是否一致，確認可稽核性。

2. **建立推論環境**  
   使用支援 Nemotron 3 Nano 參考設計的 vLLM 版本，確認 Mamba-2、GQA、MoE 核心已啟用。以 TP=1 在一張 B200 上進行基準複測，驗證 4K–256K 上下文下的彙總解碼 TPS/GPU。

3. **執行領域適應評估**  
   在自有德英任務上跑零樣本或少樣本評估，對照論文報告的 Code、GSM8K、GPQA-Diamond、英語綜合、德語綜合等基準測試群組，建立內部 Capability Index 作為部署基線。

4. **微調或持續預訓練（選用）**  
   若需領域強化，使用論文公開的 Warmup–Stable–Decay 學習率排程與優化器超參數，進行監督式微調或持續預訓練。建議先以 LoRA 驗證效果，再決定是否全參數微調。

5. **長上下文與高併發服務化**  
   將模型封裝為 API，設定批次大小、最大上下文長度與 KV 快取管理策略。利用 Mamba 層固定狀態的特性，優先服務長上下文、高併發請求，並持續監控每 GPU 彙總解碼 TPS 與延遲。

6. **上線後監控與迭代**  
   追蹤德語方言、專業術語、程式碼生成正確性與幻覺率；定期比對新釋出的中間檢查點，評估是否升級模型版本。

### 潛在風險與注意事項

| 風險 | 說明與緩解 |
|---|---|
| **MoE 推論與負載平衡** | 混合專家模型的路由與專家並行對框架版本與 GPU 通訊敏感，需使用已針對 Nemotron 3 Nano 優化的 vLLM/TensorRT-LLM，並在真實流量下測試專家負載平衡。 |
| **長上下文召回品質** | 雖然 Mamba 狀態恆定，但在極長上下文（>100K）的精細資訊召回任務上，仍建議與全注意力模型進行針頭藏 haystack 測試，確認符合應用需求。 |
| **資料授權與商業來源** | 論文釋出的資料建構產物中，部分來源為商業授權，僅提供彙總統計與混合比例核算。企業微調時必須自行確認授權範圍，避免侵權。 |
| **德語區域與方言偏差** | 訓練資料以德語加權為主，但可能仍偏向標準德語；瑞士德語、奧地利用語或低地德語等場景需額外領域資料微調與評估。 |
| **硬體與核心成熟度** | Mamba-2 與 MoE 核心在不同 CUDA 版本與硬體上的最佳化程度不一，建議在正式上線前完成與目標 GPU 世代（如 B200）的相容性與穩定性測試。 |
| **幻覺與安全風險** | 作為基礎模型，Soofi S 未經對齊，直接上線可能產生不當、偏見或幻覺內容。建議搭配 RLHF/DPO 或至少內容安全過濾層。 |

### 與其他技術的整合建議

- **檢索增強生成（RAG）**：將 Soofi S 作為生成端，搭配向量資料庫（如 Milvus、Weaviate、pgvector）儲存德英企業文件嵌入，可彌補基礎模型知識時效性不足，並降低幻覺風險。
- **現有企業系統 API**：透過 OpenAI-compatible API 閘道（如 LiteLLM、BentoML）將模型接入 CRM、ERP、客服平台，讓既有應用無縫呼叫德英雙語生成能力。
- **量化與適配器（Adapter）**：在資源受限邊緣環境，可評估 AWQ/GPTQ 量化或 LoRA 適配器，但需特別驗證 MoE 與 Mamba 層在量化後的長上下文吞吐量與品質。
- **監控與可觀測性**：整合 Langfuse、LangSmith 或自研日誌系統，記錄輸入上下文長度、批次大小、每 GPU 彙總解碼 TPS、錯誤率與德英語言偵測結果，作為成本與品質優化依據。
- **安全與合規層**：在模型前後加入 PII 偵測、輸出過濾、審計日誌與資料駐留控制，滿足主權部署與 GDPR 要求。

### 給不同背景讀者的閱讀建議

**初學者**：建議先從摘要與「適用場景」開始，理解 Soofi S 是專為德語與英語設計的開源基礎模型，重點在於「長上下文高併發推論快」與「資料透明」。接著閱讀「實作前置條件」與「潛在風險」，建立對部署門檻與授權議題的基本認識，不必一開始就深入 MoE 或 Mamba 數學細節。

**AI 工程師**：請聚焦第 2 節模型架構與訓練配方、第 4.3 節長上下文服務效率，以及資料混合比例表。重點掌握 Nemotron 3 Nano 參考設計、Warmup–Stable–Decay 排程、vLLM 部署配置與延遲減除協定測量方法，並據此規劃微調與服務化流程。

**研究人員**：建議深入第 3 節的 26.68T 詞元三階段資料課程與逐來源資料核算，以及第 4 節與 16 個開源模型的對比分析。可將 Soofi S 作為研究德英雙語預訓練、MoE 擴展、混合架構長上下文能力與開源可重現性的新基準。

**產品經理**：請優先閱讀摘要、第 1 節三個缺口與貢獻、以及「適用場景」與「潛在風險」。關注「主權自主可控」「完全開源稽核」「長上下文高併發成本優勢」等商業賣點，並評估資料授權、合規與德語市場定位對產品路線圖的影響。
