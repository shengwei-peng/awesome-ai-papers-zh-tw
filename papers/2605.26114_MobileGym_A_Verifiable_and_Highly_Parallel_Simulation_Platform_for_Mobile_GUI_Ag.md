## 摘要翻譯

我們提出 MobileGym，一個瀏覽器託管（browser-hosted）、輕量級（lightweight）、完全可控（fully controllable）的日常行動使用環境，在不複製專有後端（proprietary backends）的前提下，實現互動逼真度（interaction fidelity）。它為日常應用程式（everyday apps）帶來兩項以往難以達成的能力：透過對結構化 JSON 狀態（structured JSON state）進行確定性基於狀態的評判（deterministic state-based judging），提供可驗證的結果訊號；以及透過低成本的平行推展（parallel rollouts），實現可擴展的線上強化學習（online RL）。完整環境狀態（full environment state）以結構化 JSON 的形式被擷取、配置、分叉（fork）與比較，且單一伺服器可託管數百個平行實例，每實例僅約 400 MB 記憶體，冷啟動（cold start）時間約 3 秒。分層狀態模型（layered state model）與宣告式任務定義框架（declarative task-definition framework）確保狀態可程式化與任務創建於大規模下仍具實務可行性，而單一的程式化評判機制（programmatic judging mechanism）同時提供確定性評估裁決（deterministic evaluation verdicts）與密集強化學習獎勵（dense RL rewards）。隨附的 MobileGym-Bench 提供 416

## 深度分析

#### 方法論解析

MobileGym 的方法論建立在「互動逼真度（Interaction Fidelity）優於後端完全複製」的核心假設上。由於行動 GUI 代理（Mobile GUI Agent）僅透過螢幕截圖與自然語言指令（Natural Language Instructions）觀察環境，並以離散動作（如點擊、滑動）進行操作，作者主張無需執行真正的專有後端（Proprietary Backends），只要模擬畫面回饋與狀態轉換即可滿足研究需求。在此基礎上，平台採用瀏覽器託管（Browser-hosted）架構，將完整環境狀態（Full Environment State）——包含應用程式資料、作業系統狀態與裝置上下文——統一表示為結構化 JSON（Structured JSON）。

此設計帶來四項關鍵能力。第一，狀態可讀（readable）：透過分層狀態模型（Layered State Model），研究者能直接檢視內部狀態（Internal State），例如餘額、訂單或聯絡人，解決日常應用程式（Everyday Apps）在真實裝置上難以透過 Android 偵錯橋（ADB）或輔助功能樹（Accessibility Trees）讀取的問題。第二，狀態可寫（writable）：支援設定與重置至已知初始條件（Known Initial Conditions），使可重複評估與大規模線上訓練（Large-scale Online Training）成為可能。第三，狀態可分叉（Fork）：透過快照（snapshot）複製結構化 JSON 狀態，實現低成本的分叉（狀態）（Fork），這對於需要多條相同初始狀態軌跡的群組相對策略最佳化（GRPO）等演算法至關重要。第四，完全沙盒化（Fully Sandboxed）：高風險操作（High-consequence Actions）如購票或轉帳僅發生在模擬狀態中，不會產生真實副作用。

為了讓任務定義與驗證具備規模化能力，作者提出宣告式任務定義框架（Declarative Task-definition Framework）與參數化任務模板（Parameterized Task Templates）。任務以模板形式描述，透過參數帶入產生多樣化的具體實例。在驗證層面，MobileGym 採用單一的程式化評判機制（Programmatic Judging Mechanism）：系統比較執行後的狀態差異（state diff）與預期狀態，輸出確定性評估裁決（Deterministic Evaluation Verdicts）。同時，此機制將評判結果轉換為密集強化學習獎勵（Dense RL Rewards），例如任務進度獎勵（Progress Reward）與副作用懲罰（Side-effect Penalty），從而支援確定性基於狀態的評判（Deterministic State-based Judging）與可擴展的線上強化學習。

針對查詢型任務，平台設計 AnswerSheet 協定（AnswerSheet Protocol），要求代理在圖形介面中提交具型別（typed）的欄位，而非傳統的自由文本（free-text）。此舉根本性地避免了自由文本配對失敗（Free-text Matching Failures），並使答案驗證回歸結構化比對。最後，在系統工程層面，單一伺服器可託管數百個平行推展（Parallel Rollouts）實例，每實例僅耗費約 400 MB 記憶體，且冷啟動（Cold Start）時間約 3 秒，顯著降低了基於模擬器的環境（Emulator-based Environments）動輒數 GB 記憶體與漫長啟動時間所帶來的擴展瓶頸。

#### 實驗數據解讀

MobileGym-Bench 包含 416 個參數化任務模板（Parameterized Task Templates），涵蓋 28 個應用程式（12 個日常應用程式與 16 個系統應用程式），其中 256 個為測試模板、160 個為訓練模板。作者對 9 個不同的行動 GUI 代理進行基準測試，任務成功率（Success Rate, SR）分布於 9.4% 至 58.8% 之間。此寬廣的效能區間顯示該基準測試指標（Benchmark Metrics）具備足夠的鑑別度，且現有代理在複雜日常任務上仍有顯著提升空間。

在強化學習驗證方面，研究團隊以 Qwen3-VL-4B-Instruct 為基礎模型，採用 GRPO（群組相對策略最佳化）進行線上訓練。結果顯示，在 256 個測試任務上，模型相較於基線獲得 +12.8 百分點的 SR 提升。此結果直接證明了 MobileGym 所支援的平行推展（Parallel Rollouts）與密集獎勵訊號確實能有效驅動策略學習，且輕量級（Lightweight）架構讓大規模線上訓練在一般硬體上即可實現。

更具說服力的是 Sim-to-Real（模擬到真實）遷移實驗。研究者在 59 個可於真實裝置上取得訊號的任務子集上進行驗證，發現真實裝置執行保留了模擬端訓練增益的 95.1%。這項數據極為關鍵：它不僅緩解了「模擬環境是否過度簡化」的疑慮，也表明 MobileGym 的互動逼真度（Interaction Fidelity）已足以讓代理學到可遷移至真實世界的策略。當然，59 個任務僅佔 256 個測試任務的約 23%，未來仍需擴大驗證範圍。

此外，作者進行了一項 VLM-judge 稽核，發現視覺語言模型評判器在相同任務上產生 10.2% 的誤判率。這項數據有力地支持了確定性評判器（Deterministic Judges）的必要性：相較於將 MLLM 作為評判黑箱，MobileGym 的程式化評判機制（Programmatic Judging Mechanism）透過結構化 JSON 狀態比對，消除了人類難以察覺的評判隨機性與幻覺風險。

在評估指標設計上，平台不僅報告傳統的 SR，還引入任務進度（Task Progress, PR）、非預期副作用（Unexpected Side Effects, USE）、虛假完成（False Completion, FC）與逾期（Overdue, OT）等維度。這些指標讓研究者能診斷代理是「完全失敗」、「部分完成卻觸發副作用」，還是「在未滿足條件下被判成功」。對於 RL 訓練，這些細粒度訊號被轉化為密集獎勵，遠優於僅在最終步給予稀疏回饋的傳統設定。

#### 與現有研究的比較

相較於 AndroidWorld 與 AndroidLab 等基於模擬器的環境（Emulator-based Environments），MobileGym 的最大差異在於捨棄了重量級 Android 模擬器，改以瀏覽器託管（Browser-hosted）的輕量級模擬層實現。AndroidWorld 雖能透過 Android 偵錯橋（ADB）對系統工具與開源應用程式（Open-source Apps）進行確定性驗證，但其每實例記憶體消耗以 GB 計，難以支撐大規模線上訓練（Large-scale Online Training）所需的數百條平行推展（Parallel Rollouts）。MobileGym 以約 400 MB 記憶體與 3 秒冷啟動（Cold Start）的代價，換取了數量級上的擴展性，並將覆蓋範圍延伸至日常應用程式（Everyday Apps）的主要類別。

與 A3 或 MobileBench-OL 等嘗試觸及主流 Google Play 應用程式的研究相比，A3 採用 MLLM-as-judge 來處理動態內容，本質上是以犧牲確定性（determinism）為代價換取覆蓋率。MobileGym 則反其道而行：透過完全可控環境（Fully Controllable Environment）與結構化狀態，將確定性基於狀態的評判（Deterministic State-based Judging）內建於平台核心，從而避免 10.2% 級別的誤判。然而，這也意味著 MobileGym 並非執行真正的專有後端（Proprietary Backends）程式碼，其互動逼真度（Interaction Fidelity）存在理論上限，無法捕捉真實應用程式中所有動態 GUI 變化（Dynamic GUI Variations）。

在合成與軌跡回放環境方面，GUI-Genesis 雖能將真實應用程式重建為輕量網頁環境，但每個環境綁定於單一軌跡，難以支援需要多樣化初始狀態的強化學習。UISim 與 ViMo 採用圖像生成路線，但在長期互動中視覺預測誤差會不斷累積，導致狀態轉換不再可靠。MobileGym 透過分層狀態模型（Layered State Model）與宣告式框架，確保了長期軌跡的確定性狀態轉移，並允許任意狀態的分叉（狀態）（Fork）與重置。

OpenApps 與 MobileGym 共享輕量級（Lightweight）設計哲學，但前者聚焦於可靠性測量（reliability measurement）與 FastHTML 應用，目標與 MobileGym 的可擴展線上 RL 與確定性驗證不同。在跨領域比較上，WebArena、OSWorld 等可驗證互動環境已於網頁與桌面領域證明其價值，MobileGym 則填補了行動領域的同等級平台空缺。

儘管如此，MobileGym 仍存在若干侷限。首先，目前僅包含 28 個應用程式，相較於數百萬計的真實應用程式生態系，覆蓋率仍屬早期。其次，Sim-to-Real 驗證僅在 59 個任務上完成，佔測試集比例有限，且這些任務需能在真實裝置上取得對應訊號，暗示部分高風險操作（High-consequence Actions）或深層後端互動仍難以直接對齊真實世界。第三，由於狀態為結構化 JSON，平台較適合目標明確、狀態可列舉的任務；對於高度開放式、創造性或依賴即時外部資訊（如即時股價、多人協作）的場景，模擬難度將顯著提高。

#### 可重現性評估

MobileGym 在架構層面即為可重現性（reproducibility）提供了強大基礎。完整環境狀態（Full Environment State）以結構化 JSON（Structured JSON）捕捉，意味著任何實驗的初始條件、中間過程與最終結果皆可被精確序列化與比對。搭配參數化任務模板（Parameterized Task Templates），不同研究者只要使用相同參數，即可生成完全一致的任務實例，消除了傳統基準中因動態內容或人類標註差異所導致的變異。

在評判層面，確定性評判器（Deterministic Judges）透過狀態差異（state diff）進行裁決，而非依賴隨機性高的視覺語言模型。這使得基準測試指標（Benchmark Metrics）如任務成功率（SR）、虛假完成（FC）與逾期（OT）具備跨實驗室、跨時間點的可比性。AnswerSheet 協定（AnswerSheet Protocol）進一步排除了自由文本配對失敗（Free-text Matching Failures）所帶來的評估雜訊，讓查詢型任務的評分標準完全透明。

系統規格方面，作者明確給出每實例約 400 MB 記憶體與約 3 秒冷啟動（Cold Start）的數據，這讓其他研究者能據此估算硬體需求並重現大規模平行推展（Parallel Rollouts）的擴展性聲稱。

然而，就本文提供的資訊而言，可重現性仍存在一項不確定性：雖然作者提供了專案頁面（https://mobilegym.github.io），但文中未明確說明原始碼、資料集與模型權重是否完整開源。若僅有平台描述而無公開程式碼，其他團隊將難以直接複製該瀏覽器託管（Browser-hosted）環境與 MobileGym-Bench 的全部細節。因此，當前的可重現性優勢主要體現在方法論與協定設計的「結構性可重現」，而非已確認的「開源 artifact 可重現」。

#### 未來研究方向

第一，擴充應用程式覆蓋率。當前 28 個應用程式僅涵蓋日常行動使用的主要類別，未來可透過模組化應用程式架構（modular app architecture）擴展至更多專有後端（Proprietary Backends）情境，例如金融理財、健康醫療或多人遊戲，並探索自動化探勘技術以從真實應用程式使用中生成參數化任務模板（Parameterized Task Templates）。

第二，深化 Sim-to-Real 遷移研究。95.1% 的增益保留率雖令人鼓舞，但僅驗證於 59 個任務。未來應建立更大規模的真實裝置訊號子集，並發展「混合式訓練」範式：利用 MobileGym 的低成本平行推展（Parallel Rollouts）進行大規模探索與策略搜尋，再於真實裝置上進行微調與安全對齊（alignment）。這需要解決真實世界中專有儲存空間（Proprietary Storage）與快取狀態難以重置的問題。

第三，強化後果建模與安全研究。目前平台已透過完全沙盒化（Fully Sandboxed）隔離高風險操作（High-consequence Actions），但未來可進一步將副作用指標（如 USE、FC）整合至安全導向的強化學習目標中，發展具正式安全保證的行動代理，避免虛假完成（False Completion）或不可逆的狀態破壞。

第四，支援動態與隨機性內容。當前結構化 JSON 狀態本質上是確定性的；未來可引入「可控隨機性」（controllable stochasticity），例如模擬即時動態 GUI 變化（Dynamic GUI Variations）或網路延遲，以訓練更具魯棒性的代理，同時保持狀態可讀與可驗證。

第五，跨平台與多模態延伸。瀏覽器託管（Browser-hosted）架構理論上可擴展至 iOS 模擬或跨裝置場景。此外，除了視覺與 JSON 狀態，未來可納入音訊、觸覺回饋等多模態輸入，提升互動逼真度（Interaction Fidelity）至更高層次。

第六，結合離線軌跡（Offline Trajectories）與線上學習。雖然 MobileGym 主打線上 RL，但可設計機制將既有離線軌跡轉換為初始狀態或任務模板，結合離線預訓練與線上微調，進一步提升樣本效率。

## 論文問答

**Q1：為什麼現有的行動 GUI 代理環境難以支援日常應用程式的可重現實驗與大規模線上訓練？**
A：現有基於模擬器的環境（如 AndroidWorld 與 AndroidLab）雖能提供可重複評估，但主要僅涵蓋系統工具與開源應用程式，且每個實例需耗費數 GB 記憶體，使得大規模平行推展在一般硬體上幾乎不可行。日常應用程式的任務相關狀態分散在專有儲存空間、快取與遠端服務中，導致狀態難以讀取、寫入或重置至已知初始條件。此外，真實應用程式無法進行狀態分叉，且許多高風險操作具有不可逆性，這些結構性限制使得日常應用程式天然抗拒可重現的科學實驗。

**Q2：日常應用程式的哪些特性導致其對現有評估方法（如 ADB、輔助功能樹或 VLM 評判器）具有結構性抗性？**
A：日常應用程式的內部狀態（如餘額、訂單紀錄）無法透過 Android 偵錯橋（ADB）或輔助功能樹輕易檢視，造成狀態不可讀的困境。VLM 評判器本質上不可靠，且僅能依賴離散的截圖證據，無法完整掌握僅存在於後端的狀態變化，進一步加劇驗證的不確定性。同時，由於狀態碎片分散在專有後端與遠端服務中，傳統的程式化查詢難以取得確定性的驗證結果，使得評估流程難以標準化。

**Q3：作者為何認為「僅需互動逼真度」即可滿足 GUI 代理的訓練與評估需求，而無需完整複製專有後端？**
A：因為行動 GUI 代理僅透過截圖觀察環境，並以離散動作進行操作，所以只要模擬環境能根據代理動作產生逼真的畫面回饋，便足以支援其感知與決策迴路。完整複製專有後端不僅技術上極為困難，也會引入日常應用程式固有的不可控性、專有儲存限制與不可逆風險。因此，一個輕量級、狀態完全可程式化的模擬器，只要具備高互動逼真度，就能在保留研究可控性的同時，提供有效的訓練與評估場域。

**Q4：MobileGym 的核心架構如何透過結構化 JSON 狀態實現「可讀、可寫、可分叉、完全沙盒化」四大特性？**
A：MobileGym 將應用程式資料、作業系統狀態與裝置脈絡全部表示為結構化 JSON，使研究者能夠直接程式化讀取完整環境狀態，從而實現確定性的結果驗證。該 JSON 狀態可被任意設定、修補與重置，因此能夠快速建立已知初始條件，並透過狀態快照進行分叉以支援平行推展。由於所有高風險操作僅在完全沙盒化的模擬狀態中執行，不會影響真實帳戶或產生實際交易，確保了實驗的安全性與可重複性。

**Q5：相較於傳統的自由文本比對，AnswerSheet 協定在查詢型任務中解決了什麼問題，其運作方式為何？**
A：傳統自由文本比對容易因語意相近但表述不同而失敗，且難以精確驗證結構化答案（如日期、金額、聯絡人）。AnswerSheet 協定透過要求代理在圖形介面中提交具備明確型別的結構化欄位，取代了脆弱的自由文本配對。這種方式不僅避免了自由文本配對失敗，還能與程式化評判機制無縫整合，提供明確的對錯判定與可重現的評估結果。

**Q6：MobileGym 的分層狀態模型與宣告式任務定義框架，如何讓大規模任務建立與狀態程式化在實務上可行？**
A：分層狀態模型將複雜的環境狀態組織為邏輯清晰的層級結構，使研究者能夠針對特定層級進行精確的讀取、修改與重置，而無需處理整體狀態的龐雜細節。宣告式任務定義框架則允許研究者以參數化任務模板描述任務目標與初始條件，大幅降低了創建 416 個任務模板的工程負擔。兩者結合使得狀態操作與任務擴展具備模組化與可組合性，從而支援在單一伺服器上維護數百個平行實例的複雜實驗設定。

**Q7：MobileGym-Bench 的任務組成與評估設計有何特色，如何確保評估的嚴謹性與診斷價值？**
A：MobileGym-Bench 包含 416 個參數化任務模板，涵蓋 28 個應用程式，其中 256 個為測試模板、160 個為訓練模板，並覆蓋日常行動使用的主要類別。所有任務均配備確定性評判器，能針對任務成功（SR）、任務進度（PR）、副作用（USE）、虛假完成（FC）與逾期（OT）等基準測試指標進行精確計算。此外，任務經過經驗校準的難度分層設計，並提供診斷性指標，使研究者不僅能比較代理的整體表現，還能定位其在特定能力維度上的缺陷。

**Q8：GRPO 訓練在 Qwen3-VL-4B-Instruct 上取得了哪些具體成效，這些結果對模擬環境的訓練價值有何意涵？**
A：在 MobileGym 模擬環境中以 GRPO（群組相對策略最佳化）訓練 Qwen3-VL-4B-Instruct 後，該模型在 256 項測試任務上的成功率提升了 12.8 個百分點，顯示模擬環境能夠提供有效的強化學習訊號以改善策略。這項成果證明了輕量級、高平行度的模擬平台確實可以支援大規模線上 RL，而無需耗費大量硬體資源運行傳統模擬器。更重要的是，該訓練增益在後續的真實裝置驗證中得到了高度保留，確立了模擬到真實（Sim-to-Real）轉移的可行性。

**Q9：真實裝置驗證的結果如何說明 MobileGym 的模擬訓練增益能夠有效遷移至真實世界？**
A：在 59 項具備真實裝置訊號的任務子集上，於 MobileGym 中訓練所獲得的增益在真實裝置執行時保留了 95.1%，顯示模擬環境的互動逼真度已足以讓代理學到可遷移的操作策略。這項高保留率意味著模擬環境中的狀態轉換與獎勵訊號與真實應用程式的對應行為具有高度一致性。因此，研究者可以安心地在低成本、可分叉的模擬環境中進行大規模 RL 探索，再將成熟策略部署至真實裝置，顯著降低實驗成本與風險。

**Q10：MobileGym 的輕量級與高平行度特性，對行動 GUI 代理的強化學習研究帶來哪些實務上的突破？**
A：每個實例僅需約 400 MB 記憶體且冷啟動時間約 3 秒，使得單一伺服器即可託管數百個平行實例，徹底解決了傳統模擬器因資源耗用龐大而難以大規模平行化的瓶頸。這項特性對於需要多條從相同初始狀態出發的平行推展之群組式 RL 方法（如 GRPO）尤為關鍵，因為它讓狀態分叉與大量推展在經濟上變得可行。研究者因此能在一般硬體上快速迭代演算法，並針對高風險的日常應用場景（如購票、轉帳）進行安全的策略探索。

**Q11：對於需要測試高風險操作（如購票、下單、傳送訊息）的行動代理開發者，MobileGym 提供了哪些傳統環境無法比擬的優勢？**
A：MobileGym 將所有高風險操作完全沙盒化，代理在模擬環境中執行購票或轉帳等動作時，不會產生真實的交易、訊息或帳戶永久變更，從而消除了傳統真實裝置測試中的不可逆風險。同時，由於完整環境狀態以 JSON 表示，開發者可以精確重置任何任務到已知初始條件，進行無限次的可重現測試。這種結合了安全性與確定性驗證的能力，使得自動化回歸測試與大規模策略最佳化得以在日常應用場景中安全且高效地進行。

**Q12：MobileGym 的確定性評判機制對整個行動 GUI 代理研究領域的評估典範可能產生什麼影響？**
A：MobileGym 以結構化狀態差異進行確定性評估裁決，從根本上避免了 VLM 評判器約 10.2% 的誤判率，為領域提供了更可靠、可重現的評估基準。這種程式化評判機制不僅能輸出明確的任務成敗判定，還能同時產生密集強化學習獎勵訊號，彌合了評估與訓練之間的鴻溝。長遠來看，這可能推動領域從依賴不可靠的外部驗證器，轉向建構內建可驗證狀態的互動環境，從而提升研究結果的可比較性與科學嚴謹度。

**Q13：儘管 MobileGym 具備多項優勢，作者在設計上承認了哪些與真實世界日常應用程式之間的根本差異？**
A：MobileGym 明確定位為提供「互動逼真度」而非複製專有後端，這意味著其模擬的是前端互動行為與畫面回饋，而非真實應用程式背後複雜的專有服務、雲端同步與動態內容生成機制。因此，某些依賴真實後端狀態高度動態變化或特定專有演算法的極端案例，可能無法在模擬環境中完全重現。儘管如此，作者指出由於 GUI 代理僅透過截圖感知環境，這種程度的模擬對於策略學習與評估已經足夠。

**Q14：在 MobileGym-Bench 的基準測試中，現有代理的表現揭示了哪些尚未解決的挑戰或潛在的失敗模式？**
A：九個測試代理的成功率介於 9.4% 至 58.8% 之間，顯示即使在結構化且確定性的模擬環境中，行動 GUI 代理仍面臨顯著的任務完成難度，尤其是在需要多步規劃與精確操作的日常應用任務中。虛假完成（FC）與逾期（OT）等診斷指標的存在，暗示代理可能在未真正達成目標時過早終止，或在複雜流程中耗盡時間。這些失敗模式凸顯了現有模型在長程任務推理、狀態追蹤與精確執行上的根本限制，仍有待演算法與環境設計的進一步突破。

**Q15：基於 MobileGym 的模組化架構與宣告式框架，未來研究可以朝哪些方向擴展以提升模擬環境的覆蓋率與真實性？**
A：未來可以透過模組化應用架構持續擴充更多日常應用程式類別，並利用宣告式任務定義框架快速建立更豐富的參數化任務模板，以涵蓋更細緻的使用者場景與邊界案例。此外，可以進一步深化分層狀態模型，使其能模擬更複雜的後端互動（如網路延遲、部分同步失敗），從而在保留輕量級優勢的同時提升動態真實性。最後，結合更大型號的視覺語言模型與更先進的 RL 演算法，並在更大規模的真實裝置信號子集上驗證 Sim-to-Real 轉移，將是驗證與強化該平台實用價值的關鍵下一步。

## 實務應用指南

### 適用場景

1. **自動化 UI 測試與回歸驗證**：利用結構化 JSON 狀態與確定性評判器，建立可重現的行動 App 端對端測試流水線，特別適合電商、金融、旅遊類日常應用程式，能在每次版本發布前驗證核心用戶旅程（如購票、下單、轉帳）是否正確完成。
2. **行動 GUI 代理的強化學習訓練**：透過低成本的平行推展與狀態分叉能力，在單一伺服器上同時運行數百個輕量級實例，進行大規模線上 RL（如 GRPO），訓練能從截圖與自然語言指令中操作智慧型手機的視覺語言模型。
3. **任務導向對話系統的模擬驗證**：利用 AnswerSheet 協定與參數化任務模板，驗證虛擬助理在傳訊、訂餐、查詢餘額等複雜多步驟任務中的完成度，並透過副作用偵測（USE）與虛假完成（FC）指標避免「假成功」。
4. **Sim-to-Real 策略遷移研究**：在瀏覽器託管環境中快速迭代代理策略，再將驗證後的策略遷移至真實裝置執行，縮短行動代理從實驗室到實際部署的週期，並量化模擬與真實之間的效能落差。
5. **教育與訓練資料合成**：利用宣告式任務定義框架快速生成多樣化的互動軌跡與狀態變化，作為 VLM 監督式微調（SFT）或獎勵模型訓練的離線軌跡資料來源，解決真實環境中軌跡收集成本高昂的問題。

### 實作前置條件

- **運算資源**：至少一台具備 32 GB 以上 RAM 與多核心 CPU 的伺服器（可支援約 80 個平行實例），若進行 RL 訓練則需額外配置具備 GPU 的節點用於 VLM 推理與策略更新。
- **技術棧**：熟悉 JavaScript/TypeScript（環境擴充與 App 開發）、Python（代理控制與訓練腳本）、以及結構化 JSON 操作；具備強化學習基礎（特別是 PPO/GRPO）與視覺語言模型（VLM）推理經驗。
- **資料準備**：如需擴充日常應用程式，需準備對應的宣告式任務定義與分層狀態模型；若進行 Sim-to-Real 驗證，需備妥真實 Android 裝置與 Android 偵錯橋（ADB）環境作為對照組。
- **人力配置**：至少一名具備前端模擬器開發或強化學習工程經驗的 AI 工程師，以及熟悉目標 App 業務邏輯的領域專家協助設計確定性基於狀態的評判規則。

### 實作步驟建議

1. **環境建置與基線驗證**：部署 MobileGym 瀏覽器託管伺服器，驗證單一實例的冷啟動時間與記憶體佔用（約 400 MB / 3 秒），並以 MobileGym-Bench 的 256 個測試模板跑通基準測試指標（SR、PR、USE、FC、OT），確保環境穩定。
2. **任務客製化與評判器設計**：針對目標日常應用程式，使用分層狀態模型設計結構化 JSON 狀態，並以宣告式任務定義框架建立參數化任務模板；同時設計程式化評判機制，明確定義成功條件、預期副作用與虛假完成（FC）判定規則。
3. **代理整合與平行推展**：將目標 VLM（如 Qwen3-VL-4B-Instruct）透過 screenshot-to-action 迴路接入環境，利用狀態分叉機制啟動數十至數百個平行推展，收集多樣化軌跡並確保每個推展起點一致。
4. **強化學習訓練**：導入密集強化學習獎勵（進度獎勵 + 完成獎勵 − 副作用懲罰），執行 GRPO（群組相對策略最佳化）演算法，監控訓練過程中的基準測試指標變化，並利用狀態差異（State Diff）即時診斷代理行為。
5. **Sim-to-Real 驗證與迭代**：在真實裝置上執行經過訓練的策略子集（如 59 個具真實訊號的任務），比對模擬端與真實端的任務成功率落差；針對互動逼真度不足的畫面元素或動態 GUI 變化進行狀態模型微調。
6. **部署與持續監控**：將驗證後的代理整合至 CI/CD 流水線或產品後端，持續以 AnswerSheet 協定收集結構化答案，並定期審計確定性評判器與人工標註的一致性，防止獎勵駭入（Reward Hacking）。

### 潛在風險與注意事項

- **模擬偏差的累積**：雖然單步互動逼真度高，但長期軌跡仍可能因動態 GUI 變化與真實 App 不同而漂移。建議設定較短的任務時間上限，並在關鍵里程碑插入狀態檢查點（Checkpoint），同時保留逾期（OT）指標作為硬性約束。
- **評判器的過度擬合**：確定性評判器可能對特定 JSON 欄位過度敏感，導致代理學會「駭入」狀態而非正確操作 UI。應定期以人工審核軌跡，並將 FC（虛假完成）與 USE（非預期副作用）納入獎勵函數的硬性懲罰項。
- **記憶體與連線瓶頸**：雖然單實例僅約 400 MB，但數百個平行實例加上 VLM 推理伺服器可能壓榨網路頻寬與 CPU。建議採用容器化調度（如 Kubernetes），並將模擬環境與模型推理節點分離部署。
- **真實裝置的不可逆操作**：進行 Sim-to-Real 驗證時，高風險操作（如實際購票、轉帳）必須在完全沙盒化的測試帳號中執行，避免影響生產環境或產生真實費用與法律風險。
- **自由文本配對的陷阱**：查詢類任務若未採用 AnswerSheet 協定，仍可能遇到 VLM 輸出格式不一致的問題。務必以結構化欄位取代字串比對，並在訓練資料中強化格式遵循（Format Following）的獎勵，避免自由文本配對失敗。

### 與其他技術的整合建議

- **與現有 CI/CD 整合**：將 MobileGym 容器化後嵌入 Jenkins 或 GitLab CI，作為行動 App 每次發版前的自動化端對端測試閘道，利用確定性評估裁決產生明確的通過/失敗訊號，取代部分昂貴的真機回歸測試。
- **與雲端裝置農場（Device Farm）銜接**：模擬環境中訓練完成的策略，可透過 AWS Device Farm 或 Firebase Test Lab 進行真實裝置的抽樣驗證，形成「模擬訓練 → 雲端真機抽測 → 正式部署」的分級驗證架構。
- **與現有 VLM 服務整合**：MobileGym 的 screenshot-to-action 迴圈可對接 OpenAI GPT-4V、Claude 3 或自托管的 Qwen3-VL-4B-Instruct，透過標準化 API 介面讓研究團隊快速比較不同模型底座的效能，無需修改環境核心。
- **與資料標註工具鏈整合**：將平行推展產生的軌跡與狀態差異匯出至 Label Studio 或自製標註平台，供領域專家快速標註錯誤案例，再將標註結果回流至 SFT 或獎勵模型訓練，形成資料閉環。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從 MobileGym-Bench 的現成任務模板與預設評判器開始，先理解「結構化 JSON 狀態 → 截圖 → 代理動作 → 狀態差異驗證」的基本迴圈，不必急著修改分層狀態模型；重點觀察 Figure 2 的端對端工作流程，建立對確定性評估與平行推展的直覺。
- **AI 工程師**：請聚焦 §3 的模組化 App 架構與 §4.2 的程式化評判機制，評估如何將現有 VLM 代理接入瀏覽器託管環境；特別留意記憶體佔用與冷啟動時間的實測數據，這直接決定了你能否在單一伺服器上進行大規模 RL 訓練，並參考 §5 的 GRPO 實作細節來設計獎勵函數。
- **研究人員**：建議深入閱讀分層狀態模型與宣告式任務定義框架的設計哲學，思考如何將此框架擴展至其他作業系統或網頁環境；Sim-to-Real 的 95.1% 訓練增益保留率是值得追蹤的關鍵數據，可進一步探究剩餘 4.9% 落差來自視覺域差距還是互動邏輯差異，並考慮將 AnswerSheet 協定應用於其他需要避免自由文本配對失敗的互動評估場景。
- **產品經理**：請將閱讀重點放在「日常應用程式覆蓋率」與「高風險操作沙盒化」這兩個產品價值主張上；理解 416 個參數化任務模板如何對應到真實用戶旅程（如購票、傳訊、下單），並評估導入確定性評判器後，對現有 QA 流程與上線週期的影響——這是一個以輕量級模擬取代昂貴真機測試的商業機會。
