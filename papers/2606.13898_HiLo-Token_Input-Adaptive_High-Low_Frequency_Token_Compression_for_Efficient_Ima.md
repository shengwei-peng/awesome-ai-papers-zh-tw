## 摘要翻譯

創意影像編輯工具，例如 Photoshop 的 Remove Tool 或 Generative Fill 按鈕，是客戶日常使用的核心，並在 Photoshop 和 Lightroom 中佔據了主要的流量。然而，現有的生成式人工智慧（GenAI）模型面臨顯著的延遲挑戰，且在從基於卷積的 U-Net 轉向擴散 Transformer（DiT）時，這些挑戰變得更加明顯。在我們針對數百個涵蓋廣泛遮罩比例的具代表性的影像編輯樣本進行的評估中，單是 DiT 模組平均就佔了總模型延遲的 73%，即使該模組已從 50 個時間步蒸餾至 8 個時間步。為了解決這項挑戰，我們提出了 HiLo-Token，一個輸入自適應的 Token 壓縮框架，將較多 Token 預算分配給高頻且富含上下文資訊的區域，並將較少 Token 分配給低頻區域。具體而言，針對使用者遮罩指定的編輯區域，我們保留擴張遮罩內的所有 Token，以維持強局部性與上下文相關性。在編輯區域之外，我們提出了一個基於空間頻率、簡單而有效的高頻 Token 選擇策略，以捕捉重要局部細節，同時使用來自 16 倍下採樣影像的 Token 來表示低頻成分，並保留模糊但全域的結構。在生產級評估資料上進行的廣泛實驗驗證了所提出方法的有效性，針對平均遮罩比例分別為 6.38%、15.92% 與 35.36% 的小、中、大三類影像編輯任務，在 A100-80GB 上分別達到 3.13 倍、2.59 倍與 1.67 倍的 DiT 加速比，且未造成生成品質的任何退化。

### 核心貢獻（3～5點）
- 提出 HiLo-Token，一個輸入自適應的 Token 壓縮框架，依據空間頻率內容動態分配 Token 預算：將較多預算分配給高頻且富含上下文資訊的區域，將較少預算分配給低頻區域。
- 針對使用者遮罩指定的編輯區域，保留擴張遮罩內的所有 Token，以維持強局部性與上下文相關性，確保編輯品質。
- 在編輯區域外，提出基於空間頻率的高頻 Token 選擇策略以捕捉重要局部細節，並以 16 倍下採樣影像的 Token 表示低頻成分，保留模糊但全域的結構。
- 在生產級評估資料上進行廣泛實驗，針對平均遮罩比例分別為 6.38%、15.92% 與 35.36% 的小、中、大三類影像編輯任務，於 A100-80GB 上分別達到 3.13 倍、2.59 倍與 1.67 倍的 DiT 加速比，且未造成生成品質的任何退化。

### 適合對象
從事生成式人工智慧、擴散 Transformer（DiT）加速與創意影像編輯系統開發的研究人員及工程師，特別是關注生產級應用中延遲最佳化與生成品質兼顧的讀者。

## 深度分析

#### 方法論解析

HiLo-Token 是一個 input-adaptive（輸入自適應）的 token compression（Token 壓縮）框架，專為 creative image editing（創意影像編輯）場景設計。其核心假設在於：影像的 spatial frequency（空間頻率）分佈具有高度非均勻性，因此應將有限的 token budget（Token 預算）動態分配給 high-frequency regions（高頻區域）與 rich-context regions（富含上下文資訊區域），而對 low-frequency areas（低頻區域）進行積極壓縮。

該方法建構於 LazyDiffusion 之上，針對 user mask（使用者遮罩）所指定的 editing region（編輯區域）與非編輯區域採取差異化策略。在 editing region 內部，HiLo-Token 保留 dilated mask（擴張遮罩）範圍內的所有 tokens（Token），以確保 strong locality（強局部性）與 contextual relevance（上下文相關性）。作者指出，若僅嚴格保留原始 mask（遮罩）內的 Token，邊界處的上下文極易遺失；即便引入獨立的 context encoder，由於上下文與遮罩特徵需沿 feature dimension（特徵維度）拼接，多數有用的上下文 Token 仍會被捨棄以符合形狀要求。HiLo-Token 透過將額外上下文改沿 token dimension（Token 維度）拼接，解決了此形狀限制問題。

針對非編輯區域，作者提出雙路徑的頻率感知機制。第一路徑為 high-frequency token selection（高頻 Token 選擇）：僅使用兩個 convolution（卷積）運算計算 spatial edge/frequency map，選出包含 important local details（重要局部細節）的區域並保留其 Token。第二路徑處理 low-frequency components（低頻成分）：將影像進行 16× downsampled（16 倍下採樣），再經單一 linear layer（線性層）進行 patchify 操作，以極少量 Token 代表全域資訊，從而保留 blurry but global structure（模糊但全域的結構）。這兩類上下文 Token 最終沿 Token 維度拼接至編輯區域 Token 之後。

此方法具備輸入自適應特性：影像複雜度各異，簡單場景僅需極少上下文，而富含紋理或結構對稱性高的場景則自動獲得更多 Token 配額。與基於 attention（注意力）的重要性預測方法不同，HiLo-Token 無需在 diffusion process（擴散過程）中期進行高成本推論，也不依賴跨區域關係來判斷重要性，因此更適合早期 timesteps（時間步）的生成情境，且僅增加數毫秒（milliseconds）的 negligible overhead（可忽略開銷）。

#### 實驗數據解讀

論文採用 production-level evaluation data（生產級評估資料），涵蓋數百個具代表性的 image editing（影像編輯）樣本，並依 mask ratio（遮罩比例）分為三類：小遮罩（平均 6.38%）、中遮罩（平均 15.92%）與大遮罩（平均 35.36%）。實驗於 A100-80GB 上進行，結果顯示 HiLo-Token 分別達到 3.13×、2.59× 與 1.67× 的 DiT speedup（DiT 加速比）。

數據呈現明確的負相關趨勢：mask ratio 越低，可壓縮的非編輯區域越大，加速比越高；當遮罩比例升至 35.36% 時，由於需保留的 editing region Token 顯著增加，加速比自然遞減。這驗證了方法在實際應用場景中的經濟性——對於 Remove Tool 這類通常涉及較小 mask ratio 的應用，效益最為顯著。

在 latency（延遲）分析方面，作者指出即便經過 distillation（蒸餾）將 50 個 timesteps 壓縮至 8 個，DiT module（DiT 模組）仍佔 total model latency（總模型延遲）的 73%。這說明單純依靠 timestep distillation（時間步蒸餾）已難以進一步壓縮延遲，而 HiLo-Token 在不引入 generation quality（生成品質）regression（退化）的前提下，直接針對 DiT 的 Token 數量進行縮減，填補了現有優化手段的缺口。圖 1b 進一步展示雲端部署成本效益：採用 HiLo-Token 後，所需 Amazon AWS p5.48xlarge 節點（8×H100）數量顯著下降，每小時成本從約 1,200 美元降至約 400 美元（降幅約 67%），對於 Photoshop 與 Lightroom 等承載主要 traffic（流量）的產品具有重大商業價值。

#### 與現有研究的比較

相較於從 convolution-based U-Nets（基於卷積的 U-Net）過渡至 Diffusion Transformers (DiTs)（擴散 Transformer（DiT））的產業趨勢，本文坦承 DiT 雖然參數量僅為 U-Net 的 1.8 倍，但推論成本高達近 6 倍，且需要硬體升級（如 A100 至 H100 GPU）才能維持可接受的延遲。現有的 token-level compression（Token 層級壓縮）或 model-level compression（模型層級壓縮）、activation caching（啟用快取）與 low-bit quantization（低比特量化）等方法，要不效益有限（難以超越激進的 timestep distillation），要不必然伴隨 quality regression（品質退化），而對於生產環境而言，即使小規模失真亦不可接受。

在專門針對遮罩式影像編輯的文獻中，LazyDiffusion 與 DiffCR 僅於遮罩區域生成內容，但存在三項關鍵缺陷：其一，context encoder 成本高昂，且多數 Token 在後續被丟棄；其二，上下文與遮罩 Token 沿特徵維度拼接導致形狀限制與資訊損失；其三，缺乏 input-adaptive（輸入自適應）能力。HiLo-Token 直接回應這三項挑戰：以輕量級的 spatial frequency（空間頻率）選擇機制取代 Transformer 上下文編碼器，將額外上下文改沿 Token 維度拼接，並透過頻率分析實現依影像內容調整的 Token 分配。

然而，本方法仍建構於 LazyDiffusion 的基礎架構之上，並非通用於所有 DiT 架構的即插即用（Plug-and-Play）模組；此外，16 倍下採樣與邊緣檢測的閾值似乎為人工設計，未見針對不同解析度或領域的自動化調適機制。

#### 可重現性評估

就開源（Open-Source）角度而言，本文未提供原始碼、模型權重（Model Weights）或生產級評估資料的公開連結。作者來自 Adobe ART AI Lab 與 Adobe Research，方法緊密整合於 Adobe 內部的 Firefly Image models（Firefly 影像模型）與 Photoshop 的 Remove Tool / Generative Fill 產品流程中。這類工業界論文通常受限於商業機密與使用者資料隱私，難以完整開源。

學術界若欲重現，需自行建構類似的 DiT 編輯基線、收集涵蓋多樣 mask ratio 的影像編輯資料集，並實作空間頻率選擇與 16× 下採樣的 Token 化流程。雖然方法描述足夠具體（兩個卷積層、一個線性層、16× 下採樣），但諸如 dilated mask 的膨脹率（Dilation Rate）、高頻選擇的具體閾值、以及與 LazyDiffusion 整合的細節超參數並未於提供的摘要與引言中完整揭露，增加了重現難度。

#### 未來研究方向

首先，將 HiLo-Token 的高低頻 Token 壓縮概念擴展至影片編輯（Video Editing）極具潛力。時間維度上的連續性可與空間頻率分析結合，透過跨幀（Cross-Frame）的低頻共享與高頻殘差壓縮，進一步降低長序列生成的記憶體與計算負擔。

其次，目前的頻率分離依賴固定比例的下採樣與手工設計的邊緣檢測，未來可探索學習式（Learned）或資料驅動（Data-Driven）的頻率閾值預測，甚至將可變倍率的下採樣（如 8×、32×）納入輸入自適應框架，使 token budget 分配更為精細。

第三，HiLo-Token 可與其他互補的加速技術疊加，例如與 low-bit quantization 或 activation caching 結合，在 Token 數量與單次運算精度兩個維度同時優化。此外，針對 H100 等新一代 GPU 的專用推論核心（Inference Kernels）進行記憶體存取模式的最佳化，亦有機會進一步放大實測加速比。

最後，將此方法從 specialist editing models（專業編輯模型）拓展至通用 image generation（影像生成）或結合 Vision Language Models (VLMs)（視覺語言模型（VLM））與 DiT 的多模態架構，將是驗證其泛化能力的重要方向。特別是在無遮罩（Mask-Free）的全圖生成情境中，如何定義「編輯區域」並維持語義一致性，將是核心挑戰。

## 論文問答

**Q1：HiLo-Token 旨在解決創意影像編輯中的什麼核心問題？**
A：HiLo-Token 主要針對生成式人工智慧模型在創意影像編輯任務中所面臨的顯著延遲挑戰，特別是在模型架構從基於卷積的 U-Net 轉向擴散 Transformer（DiT）之後，延遲問題變得更加嚴重。根據論文評估，即使在將時間步從 50 步蒸餾至 8 步的情況下，DiT 模組單獨就佔據了總模型延遲平均 73% 的比例。這項延遲瓶頸對於需要服務數百萬用戶的 Photoshop 和 Lightroom 等產品而言，構成了極大的雲端部署與使用者體驗挑戰。

**Q2：為何現有的壓縮技術無法充分解決遮罩式影像編輯的延遲問題？**
A：現有的 Token 壓縮、模型級壓縮、啟動快取或低比特量化等技術，除了在激進的時間步蒸餾之外所能帶來的效益相當有限，否則就不可避免地會導致生成品質退化。更重要的是，極少數既有研究考量到以使用者遮罩為基礎的生成式模型所具備的獨特最佳化特性，例如 LazyDiffusion 僅在遮罩區域內生成內容的做法；傳統方法為了配合遮罩形狀往往會捨棄上下文 Token，導致資訊遺失，或是依賴昂貴的 Transformer 上下文編碼器，造成額外的運算負擔。因此，這些方法無法在維持生產級生成品質的同時，有效降低 DiT 的推理延遲。

**Q3：對於 Adobe 的創意工具而言，降低 DiT 延遲為何特別重要？**
A：Photoshop 的 Remove Tool 與 Generative Fill 等創意影像編輯功能佔據了日常使用者流量的主要部分，例如在 Photoshop v27.0 發布後的 28 天內，就有 110 萬用戶使用了 Generative Fill，產生 3620 萬次互動並消耗 8280 萬生成點數。由於 DiT 模型的雲端服務成本幾乎比 U-Net 高出 6 倍，且需要升級至 H100 等更昂貴的硬體才能達到可接受的延遲，這對大規模部署構成了沉重的經濟壓力。因此，在不造成品質退化的前提下降低 DiT 延遲，對於提升使用者體驗與降低營運成本具有關鍵性的戰略意義。

**Q4：HiLo-Token 的核心機制是如何實現高效的 Token 壓縮？**
A：HiLo-Token 是一個輸入自適應的 Token 壓縮框架，它會將較多的 Token 預算分配給高頻且富含上下文資訊的區域，而對低頻區域則分配較少的 Token。具體而言，對於使用者遮罩指定的編輯區域，系統會保留擴張遮罩內的所有 Token，以維持強局部性與上下文相關性。而在編輯區域之外，則透過基於空間頻率的高頻 Token 選擇策略捕捉重要局部細節，同時使用來自 16 倍下採樣影像的 Token 來表示低頻成分，從而保留模糊但全域的結構。

**Q5：相較於 LazyDiffusion 等先前方法，HiLo-Token 的關鍵創新為何？**
A：HiLo-Token 提出了以頻率感知為基礎的 Token 選擇策略，有效解決了僅保留擴張遮罩內 Token 所導致的上下文資訊遺失問題。與 LazyDiffusion 必須完整運算昂貴的 Transformer 上下文編碼器不同，HiLo-Token 僅使用兩個卷積運算來計算空間頻率圖以選擇高頻 Token，並以單一線性層處理下採樣影像的低頻 Token，額外開銷僅有數毫秒。此外，它避免了在擴散早期步驟使用成本高昂且不可靠的注意力機制來預測重要性，實現了真正的輸入自適應 Token 分配。

**Q6：HiLo-Token 為何選擇使用 16 倍下採樣影像來表示低頻，並以空間頻率選擇高頻 Token？**
A：16 倍下採樣影像能夠以極少的 Token 數量有效捕捉場景中模糊但全域的結構，因為低頻成分本身不需要精細的空間解析度。相較於依賴中間擴散步驟生成內容的學習式方法，透過簡單卷積運算分析空間頻率來選擇高頻 Token，能夠在擴散早期就穩定地識別出遮罩外的重要局部細節。這種將高頻與低頻分離表示的設計，在計算成本與上下文資訊保留之間取得了最佳的權衡。

**Q7：HiLo-Token 是在什麼樣的評估資料與硬體環境上進行驗證的？**
A：HiLo-Token 在數百個涵蓋廣泛遮罩比例的代表性影像編輯樣本上進行驗證，這些樣本屬於生產級評估資料，能夠反映真實的產品使用場景。實驗在 A100-80GB GPU 上進行，針對小、中、大三種遮罩比例類別分別測量 DiT 加速比。其中小、中、大遮罩比例的平均值分別為 6.38%、15.92% 與 35.36%，涵蓋了使用者常見的編輯範圍。

**Q8：HiLo-Token 取得了哪些關鍵的量化成果？**
A：在 A100-80GB 上，HiLo-Token 針對小、中、大遮罩比例類別分別達到了 3.13 倍、2.59 倍與 1.67 倍的 DiT 加速比。這些顯著的加速成果是在完全沒有造成生成品質退化的前提下達成的，證明了此方法在實際部署中的可行性。結果也顯示，當編輯區域越小時，遮罩外可壓縮的 Token 越多，因此能獲得越顯著的加速效果。

**Q9：從設計選擇中可以推導出哪些關於上下文保留與開銷降低的消融研究洞見？**
A：在擴張遮罩內保留所有 Token 的設計，驗證了維持編輯區域強局部性與上下文相關性的必要性，這是確保生成品質不退化的基礎。將昂貴的 Transformer 上下文編碼器替換為輕量級的卷積與線性層，證明了高頻 Token 選擇與 16 倍下採樣低頻 Token 已足以提供充分的上下文資訊，且不會帶來顯著的計算負擔。這些設計選擇共同說明，基於頻率感知的分解策略比學習式重要性預測更適合用於擴散模型中的輸入自適應 Token 分配。

**Q10：HiLo-Token 在哪些實際應用場景中能帶來最顯著的效益？**
A：HiLo-Token 在處理小至中等遮罩比例的影像編輯工作負載時效益最為顯著，例如物件移除或局部生成填補等操作，而這類操作佔據了真實使用者流量的極大比例。對於需要在雲端環境中服務數百萬用戶的產品而言，此方法能有效降低幾乎比 U-Net 昂貴 6 倍的 DiT 推理成本。透過減少所需的高階 GPU 節點數量，HiLo-Token 在維持創意工作者所需的像素級精確控制同時，大幅降低了基礎設施支出。

**Q11：哪些產品層級的需求塑造了 HiLo-Token 的特定設計限制？**
A：Adobe 的生產部署標準極為嚴格，即使是測試資料中少數影像的微小失真也無法接受，因為這會影響大量使用者並損害對創意工具的信任。這項嚴格的品質要求促使團隊開發出能在顯著加速的同時，完全不造成生成品質退化的壓縮方法。此外，為了支援 Photoshop 中使用者透過遮罩進行像素級精確控制的既定工作流程，方法必須保留編輯區域的強局部性與上下文相關性，而非對整張影像採用均勻的壓縮策略。

**Q12：HiLo-Token 可能對高效生成式影像編輯領域產生什麼更廣泛的影響？**
A：HiLo-Token 證明了以頻率感知與輸入自適應為基礎的 Token 壓縮，是在不犧牲品質的前提下加速擴散 Transformer 的一個極具前景的典範。它展示了輕量級的非學習式頻率分析可以取代昂貴的 Transformer 上下文編碼器，為專業編輯模型的更高效架構設計開闢了新的可能性。其在生產級部署上的成功，可能會鼓勵業界透過智慧化 Token 預算分配而非單純硬體升級，來解決 DiT 的主要延遲瓶頸，進而推動 DiT 式編輯系統的更廣泛採用。

**Q13：論文承認 HiLo-Token 的加速性能存在哪些限制？**
A：加速比會隨著遮罩比例的增加而顯著下降，例如大遮罩類別（平均 35.36%）僅達到 1.67 倍加速，遠低於小遮罩類別（平均 6.38%）的 3.13 倍，顯示當編輯區域擴大時效益會遞減。這表示當使用者遮罩覆蓋影像大部分區域時，遮罩外可捨棄的 Token 數量有限，整體壓縮潛力也隨之受限。此外，此方法建構於 LazyDiffusion 的遮罩區域生成框架之上，其優勢主要體現在以使用者遮罩為基礎的編輯場景，而非全圖生成任務。

**Q14：在什麼條件下，HiLo-Token 可能無法保留重要的上下文資訊？**
A：若場景中關鍵的上下文線索存在於低頻區域，而這些區域被高度壓縮為 16 倍下採樣的 Token，則可能遺失對於一致性編輯所需的微妙全域提示。此外，如果遮罩外重要的結構細節未能被基於空間頻率的高頻 Token 選擇策略捕捉，模型可能缺乏處理需要強烈非局部關係的複雜編輯所需的資訊。由於此方法依賴空間頻率而非語義理解，語意上重要但紋理平滑的區域可能會被意外捨棄，進而影響生成結果的協調性。

**Q15：HiLo-Token 為未來的高效影像編輯研究指出了哪些方向？**
A：未來研究可以探索設計輕量級且能在所有擴散時間步穩定運作的重要性預測器，以實現更靈活的輸入自適應 Token 分配。將 HiLo-Token 與其他互補的加速技術（如先進的量化方法或最佳化的注意力核心）結合，有望帶來進一步的累積加速效果。此外，將這種頻率感知壓縮的理念擴展至全圖生成與影片編輯領域，也是一個極具潛力的方向，能夠擴大輸入自適應 Token 預算分配方法的影響範圍。

## 實務應用指南

### 適用場景

1. **雲端創意影像編輯服務**：適用於 Photoshop、Lightroom 或 Express 等產品的雲端版本，需同時服務數百萬使用者執行 Generative Fill 或 Remove Tool 等高流量功能，透過 HiLo-Token 降低 DiT 模組延遲與 AWS/GCP 叢集成本。
2. **即時互動式桌面編輯軟體**：針對專業設計師在 Photoshop 桌面版中的互動式編輯流程，將 DiT 推理延遲壓低至可即時預覽，改善像素級精確控制的使用者體驗。
3. **行動裝置與邊緣運算影像編輯**：在運算資源受限的手機或平板環境中，透過輸入自適應的 Token 預算分配，讓複雜的擴散 Transformer 得以在記憶體與頻寬受限的裝置上執行高品質影像生成。
4. **電商與廣告批次內容生成**：針對需要大量重複性編輯（如商品去背、背景填補）的企業流程，利用小遮罩比例（平均 6.38%）下高達 3.13 倍的 DiT 加速比，提升批次處理吞吐量。
5. **多租戶 AI 繪圖平台**：為採用 DiT 架構的第三方影像生成或編輯 API 服務提供無生成品質退化的 Token 壓縮後端，顯著減少每小時所需 H100/A100 節點數量。

### 實作前置條件

- **資料需求**：需具備生產級評估資料，包含多樣化遮罩比例（小、中、大遮罩比例分佈）的影像編輯樣本，以及對應的使用者遮罩與編輯前後影像對，用以驗證無退化之生成品質。
- **運算資源**：至少需配備 A100-80GB 等級的 GPU 環境進行開發與評估；若為生產部署，需有支援 DiT 推理的雲端或地端 GPU 叢集（如 H100）。
- **技術能力**：團隊需熟悉擴散 Transformer（DiT）架構、PyTorch 或同等深度學習框架、CUDA 效能分析，並具備影像處理基礎（空間頻率分析、邊緣偵測、16 倍下採樣影像處理）與模型部署經驗。

### 實作步驟建議

1. **建立基線與延遲分析**：在現有基於 DiT 的影像編輯模型（如 LazyDiffusion）上，測量總模型延遲並確認 DiT 模組佔比，作為加速比對照基準。
2. **實作擴張遮罩區域保留**：針對使用者遮罩指定的編輯區域，建立擴張遮罩（dilated mask）邏輯，保留該區域內所有 Token 以確保強局部性與上下文相關性。
3. **建構高頻 Token 選擇器**：在非編輯區域外，以兩個卷積層實作輕量級空間頻率/邊緣圖計算，選取重要局部細節所在的高頻區域 Token。
4. **生成低頻上下文 Token**：將非編輯區域的影像進行 16 倍下採樣，透過單一線性層轉為 Patch Token，用以代表低頻成分並保留模糊但全域的結構資訊。
5. **設計輸入自適應預算分配**：依據輸入影像複雜度與遮罩比例，動態調整高頻與低頻 Token 的預算比例，確保簡單場景與富含紋理場景皆能獲得適當分配。
6. **生產級品質驗證**：於涵蓋小（6.38%）、中（15.92%）、大（35.36%）遮罩比例的生產級評估資料上進行完整測試，確認生成品質無任何退化。
7. **推理管線整合與監控**：將 HiLo-Token 嵌入現有推理管線，監控實際 DiT 加速比、端到端延遲與雲端成本節省效益，並針對不同遮罩比例設定服務層級目標（SLO）。

### 潛在風險與注意事項

- **高頻區域過度保留**：若空間頻率閾值設定過低，可能保留過多高頻區域 Token，導致實際加速比低於預期；建議依據生產資料分佈微調邊緣偵測靈敏度。
- **低頻結構資訊不足**：16 倍下採樣影像雖能保留全域結構，但對於極度依賴細微遠景結構的編輯任務，可能出現上下文斷裂；需確保高頻 Token 與低頻 Token 在特徵維度上的互補性。
- **大遮罩比例的加速天花板**：當遮罩比例極大（接近 35% 以上）時，由於編輯區域內 Token 無法壓縮，加速比會下降至約 1.67 倍，需於產品規劃階段設定正確的效能預期。
- **與蒸餾技術的相容邊界**：雖然本文已驗證與 50 步蒸餾至 8 步的設定相容，但若進一步極端壓縮時間步或結合其他積極量化手段，可能放大誤差並引發品質退化，建議分階段導入。
- **硬體架構差異**：論文數據基於 A100-80GB，不同 GPU 世代（如 H100）的記憶體頻寬與 Tensor Core 特性可能改變實際延遲分佈，需在目標硬體上重新評測。

### 與其他技術的整合建議

- **時間步蒸餾（Timestep Distillation）**：HiLo-Token 已與激進的時間步蒸餾（50 步降至 8 步）相容，可進一步探索與一致性模型（Consistency Models）或 LCM 結合，但須謹慎監控生成品質。
- **模型量化（Quantization）**：可與低比特權重量化（如 INT8/FP8）或啟動值量化技術併用，但建議與 HiLo-Token 分階段導入，以便隔離品質退化的根因。
- **跨層啟動值快取（Activation Caching）**：在靜態非編輯區域中，可搭配快取機制避免重複計算，進一步放大整體吞吐量；但需注意動態高頻 Token 選擇所帶來的記憶體存取模式變化。
- **Token 合併技術**：理論上可與 ToMe 或 DynamicViT 等 Token 合併方法互補，但由於 HiLo-Token 已針對編輯場景做輸入自適應設計，額外合併可能破壞強局部性，需嚴格驗證。
- **Vision Language Model（VLM）+ DiT 架構**：若產品採用 VLM 結合 DiT 的多模態架構，可將 HiLo-Token 專注應用於 DiT 模組，文字編碼器與跨模態對齊層則維持不變，以最小化整合風險。

### 給不同背景讀者的閱讀建議

**初學者**：建議先建立「使用者遮罩」與「擴散模型」的基礎概念，將閱讀重點放在論文的適用場景與圖 1，理解 HiLo-Token 如何讓 Photoshop 的 Generative Fill 與 Remove Tool 變得更快，無需深究空間頻率計算或 DiT 架構的數學推導。

**AI 工程師**：請聚焦方法實作細節，特別是兩個卷積層構成的高頻 Token 選擇機制、16 倍下採樣影像的 Patchify 流程，以及與 LazyDiffusion 的整合方式；同時留意生產環境中不同遮罩比例下的延遲評估方法與記憶體頻寬特性。

**研究人員**：建議深入探討輸入自適應 Token 預算分配的設計動機，對比現有通用 Token 壓縮方法在「編輯區域外上下文保留」與「無品質退化」之間的權衡，並思考如何將基於空間頻率的分析擴展至影片編輯、3D 生成或其他生成式架構。

**產品經理**：請優先關注圖 1(b) 的雲端成本節省數據，以及小、中、大遮罩比例對應的 DiT 加速比（3.13×、2.59×、1.67×），據此評估導入技術後對 AWS/GCP 基礎設施成本的影響，並權衡使用者體驗（延遲降低）與商業指標（如生成點數消耗、伺服器節點數量）之間的關係。
