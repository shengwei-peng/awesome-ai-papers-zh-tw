## ⚡ TL;DR

大型推理模型常對簡單題過度思考、對困難題思考不足，現有方法往往犧牲難題準確率。
本文提出 When2Think，透過難度感知獎勵塑形動態調配直接回答與深思推理。
在 AIME24 上 Pass@3 提升 10.0% 並減少 27.9% 詞元，AIME25 達 40.0% Pass@3。

## 摘要翻譯

大型推理模型（Large Reasoning Models, LRMs）在複雜任務上展現強大的性能，但存在系統性的推理效率低下（reasoning inefficiency）：它們經常對簡單問題過度思考（overthinking），對困難問題思考不足（underthinking）。現有基於統一長度懲罰（uniform length penalties）或剛性路由（rigid routing）的方法會產生效率稅（efficiency tax），在簡單實例上減少計算，卻以困難實例的準確率（accuracy）損失為代價。我們將高效率推理視為一個實例自適應計算分配（instance-adaptive computation allocation）問題，並提出 When2Think，一個用於混合推理（hybrid reasoning）的後訓練框架（post-training framework），能依據問題難度動態分配計算資源。我們的方法提出實例級難度感知控制（Instance-level Difficulty-Aware Control, IDAC），這是一種獎勵塑形機制（reward-shaping mechanism），利用預先計算的參考統計量（pre-computed reference statistics）（準確率與詞元使用量（token usage））來調節推理深度（reasoning depth）。結合基於驗證器的獎勵（verifier-based rewards）與批次標準化優勢（batch-wise standardized advantages），IDAC 能夠實現穩定的免 Critic（critic-free optimization）優化，無需學習式獎勵模型（learned reward models）或線上參考模型查詢（online reference-model queries）。When2Think 鼓勵對簡單實例直接回答（direct answering），同時對困難實例保留較長的推理過程，從而學習何時使用系統 1（System 1）（NoThink）、何時使用系統 2（System 2）（Think）。在數學基準測試上的實驗顯示出更佳的準確率–效率權衡（accuracy-efficiency trade-offs）：在 AIME24 上，相較於基礎模型（base model），Pass@3 提升了 10.0%，同時詞元使用量（token usage）減少 27.9%；在 AIME25 上，When2Think 達到 40.0% Pass@3，優於壓縮基線（compression baselines）與僅路由基線（routing-only baselines）。

### 核心貢獻（3～5點）
- 提出 When2Think 後訓練框架，將高效率推理形式化為實例自適應計算分配問題，並依據問題難度動態調整推理深度。
- 提出實例級難度感知控制（IDAC）獎勵塑形機制，利用預先計算的參考統計量（準確率與詞元使用量）調節模型在簡單與困難實例上的推理行為。
- 結合基於驗證器的獎勵與批次標準化優勢，實現穩定的免 Critic 優化，無需學習式獎勵模型或線上參考模型查詢。
- 在 AIME24 與 AIME25 數學基準測試上取得更佳的準確率–效率權衡，同時提升 Pass@3 並降低詞元使用量。

### 適合對象
本論文適合對大型推理模型（LRMs）效率優化、混合推理系統、強化式微調（RFT）與獎勵塑形有興趣的研究者與工程師，特別是關注如何在維持數學推理準確率的同時降低計算成本、以及希望學習動態控制模型何時使用直接回答（System 1）與深思熟慮（System 2）的讀者。

## 深度分析

#### 方法論解析

When2Think 的核心貢獻，是將「高效率推理」重新定義為**實例自適應計算分配（instance-adaptive computation allocation）**問題，而非單純的**詞元縮減（token reduction）**。整體框架屬於**後訓練（post-training）**的**強化學習（Reinforcement Learning, RL）**範式，並採用**可驗證獎勵強化學習（Reinforcement Learning with Verifiable Rewards, RLVR）**，以數學題等可驗證任務為應用場景。

##### 1. 雙重歷程理論（dual-process theory）作為概念透鏡

論文借用心理學中的雙重歷程理論，將模型行為區分為兩種模式：

- **系統 1（System 1）／NoThink**：快速、直覺的直接回答，適合簡單實例。
- **系統 2（System 2）／Think**：慢速、審議式的多步驟推理，適合困難實例。

When2Think 的目標是在單一模型中學會「何時使用 System 1、何時使用 System 2」，並進一步控制 System 2 的**推理深度（reasoning depth）**。

##### 2. 混合推理的動作空間：THINK / NOTHINK 模式詞元

與傳統壓縮方法不同，When2Think 透過一個顯式的**模式詞元（mode token）**來控制推理行為：

- 若選擇 **THINK**，模型會生成推理鏈（reasoning chain），直到出現結束推理的標記 **EOT（end-of-thinking token）**。
- 若選擇 **NOTHINK**，模型直接輸出最終答案，類似於「NoThinking」機制。

這使得「是否推理」與「推理多長」被統一在同一個策略（policy）下學習，而非透過剛性路由（rigid routing）或全域詞元預算來硬性限制。

##### 3. 重要性採樣（Importance Sampling, IS）與探索策略

為了避免訓練初期模型快速塌陷到 THINK 模式，When2Think 採用 AdaptThink 提出的**重要性採樣（Importance Sampling, IS）**機制：

- 資料收集時，由輔助探索策略 π_IS 均勻地選擇初始模式詞元（THINK 或 NOTHINK），確保兩種模式都有足夠樣本。
- 後續詞元則由當前策略 π_θ 生成。
- 訓練時利用重要性比率（importance ratio）ρ_i,k = π_θ(o_i,k|x_i) / π_IS(o_i,k|x_i) 對梯度進行加權，使目標策略的梯度估計保持無偏。

這種設計讓 When2Think 在不需要線上查詢參考模型（online reference-model queries）的情況下，仍能穩定學習混合行為。

##### 4. PPO 型裁剪代理目標（Clipped Surrogate Objective）

策略優化採用類似 **近端策略優化（Proximal Policy Optimization, PPO）** 的裁剪代理損失：

\[
\mathcal{L}(\theta) = -\mathbb{E}_{x_i \sim B, o_{i,k} \sim \pi_{IS}(\cdot|x_i)} \left[ \min\left( \rho_{i,k} A_{i,k}, \min(\max(\rho_{i,k}, 1-\epsilon), 1+\epsilon) A_{i,k} \right) \right]
\]

其中 A_i,k 為軌跡層級的優勢估計（advantage estimate），ϵ 為裁剪參數。透過裁剪，可防止策略更新幅度過大，提升訓練穩定性。

##### 5. 實例級難度感知控制（Instance-level Difficulty-Aware Control, IDAC）

IDAC 是 When2Think 的關鍵創新。它是一種**獎勵塑形（reward shaping）**機制，利用**預先計算的參考統計量（pre-computed reference statistics）**——即每個實例的**準確率（accuracy）**與**詞元使用量（token usage）**——來調節獎勵訊號，進而控制推理深度。

根據論文描述與圖 2 的框架，IDAC 的運作邏輯可理解為：

1. **參考預計算（Reference Pre-computation）**：在訓練前，先從某個參考策略（如基礎 LRM 或 LLM）收集每個問題實例 x_i 的表現統計，例如在不同推理長度下的準確率 α_i 與詞元數 τ_i。
2. **難度感知獎勵塑形**：在 RL 訓練中，IDAC 根據這些預先計算的統計量，對軌跡給予額外獎勵訊號。
   - 對於簡單實例，若參考統計顯示「少量詞元即可達到高準確率」，則獎勵機制傾向鼓勵 NOTHINK 或極短的 THINK，抑制過度思考（overthinking）。
   - 對於困難實例，若參考統計顯示「增加詞元顯著提升準確率」，則獎勵機制保留較長的 System 2 推理，避免思考不足（underthinking）。
3. **與驗證器獎勵結合**：IDAC 塑形獎勵與基於驗證器的正確性獎勵（verifier-based rewards）相加，確保效率提升不會以犧牲正確性為代價。

由於參考統計量只需預先計算一次，後續訓練無需線上查詢參考模型，這大幅降低了計算開銷。

##### 6. 批次標準化優勢（Batch-wise Standardized Advantages）與無評論家優化（Critic-free Optimization）

When2Think 不使用學習式獎勵模型（learned reward model），也不訓練額外的價值網路（critic network）。取而代之的是：

- 利用**批次標準化優勢（batch-wise standardized advantages）**，在同一個 mini-batch 內對優勢值進行標準化，降低梯度方差。
- 結合驗證器獎勵與 IDAC 塑形獎勵，實現**無評論家優化（critic-free optimization）**。

這簡化了訓練流程，減少了模型參數量與訓練不穩定性，同時避免了獎勵模型可能帶來的偏誤（reward-model bias）。

#### 實驗數據解讀

論文主要在數學推理基準測試上驗證 When2Think，包括 **MATH-500**、**AIME24** 與 **AIME25**。以下從指標與結果兩個層面進行解讀。

##### 1. 評估指標的意義

- **Pass@1**：單次生成中至少有一條正確答案的比例，反映單樣本準確率。
- **Pass@3**：生成三條答案後至少有一條正確的比例，衡量模型在多次採樣下的覆蓋能力與推理品質。
- **詞元使用量（token usage）**：每個實例平均生成的詞元數，直接對應推理成本與延遲。

Pass@3 的提升同時伴隨詞元減少，意味著模型不僅「省算力」，而且「算得更準」；這比單純壓縮推理鏈更具價值。

##### 2. MATH-500：難度分層分析

圖 1 將 MATH-500 按難度分為 Level 1 至 Level 5，比較 When2Think、R1-Distill-Qwen（LRM 基線）與 Qwen2-5-Math（LLM 基線）：

- **簡單實例（Level 1–2）**：When2Think 的詞元使用量接近 LLM 基線，顯著低於 LRM 基線，準確率則維持在相近水準。這說明 When2Think 成功抑制了過度思考。
- **困難實例（Level 4–5）**：When2Think 的準確率接近 LRM 基線，遠高於 LLM 基線，同時詞元使用量雖高於簡單實例，但仍控制在合理範圍。這顯示困難實例仍保留了足夠的 System 2 推理。

這正是論文所強調的「緩解效率稅（efficiency tax）」：不再為了省詞元而犧牲難題表現。

##### 3. AIME24：準確率與效率雙贏

在 AIME24 上，When2Think 相較於基礎模型：

- **Pass@3 提升 10.0%**
- **詞元使用量減少 27.9%**

這是一個強而有力的結果：在減少近三成計算量的同時，還能顯著提升多樣本採樣下的正確率。這暗示 When2Think 不僅減少了冗餘推理，也可能改善了推理軌跡的品質，使得採樣出的多條答案更有可能包含正確解。

##### 4. AIME25：與基線的比較

When2Think 在 AIME25 上達到 **40.0% Pass@3**，優於壓縮基線（compression baselines）與僅路由基線（routing-only baselines）。這說明：

- 單純的**詞元壓縮**雖能降低成本，但容易在困難題目上造成思考不足。
- 單純的**路由機制**雖能切換長短推理，但缺乏實例級的細粒度深度控制。
- When2Think 透過 IDAC 同時控制「是否推理」與「推理多長」，在兩者間取得更好的**準確率–效率權衡（accuracy-efficiency trade-offs）**。

##### 5. 結果的整體意涵

實驗數據支持了論文的核心假設：推理資源應根據問題難度動態分配，而非統一壓縮或統一延長。When2Think 的行為接近「計算最適分配」：在簡單實例上像 LLM 一樣高效，在困難實例上像 LRM 一樣強大。

#### 與現有研究的比較

##### 1. 相較於推理壓縮方法

現有壓縮方法如 Skip-Thinking、LC-R1、ThinkPrune、LASER、DLER 等，主要透過縮短推理軌跡來降低計算成本。這些方法雖然能有效減少簡單實例上的過度思考，但存在兩個問題：

- **靜態或全域約束**：例如硬性詞元預算或統一長度懲罰（uniform length penalties），無法根據個別問題難度調整。
- **效率稅（efficiency tax）**：壓縮後的模型在困難實例上容易出現思考不足，導致準確率下降。

When2Think 透過 IDAC 實現**實例級（instance-level）**的動態控制，避免了「一刀切」的壓縮策略。

##### 2. 相較於混合推理方法

ARM、LHRM、AdaptThink、ThinkLess 等方法嘗試在短推理與長推理之間切換，或透過學習控制器決定是否跳過推理。然而：

- 部分方法僅做二元路由（think / no-think），缺乏對推理長度的細粒度控制。
- 部分方法需要學習額外的控制器或獎勵模型，增加訓練複雜度。

When2Think 的差異在於：

- 統一策略同時學習「是否思考」與「思考多長」。
- 不需要學習式獎勵模型，也不需要在訓練期間線上查詢參考模型。
- 透過預先計算的參考統計量，將難度資訊直接嵌入獎勵塑形。

##### 3. 相較於 RLVR 與驗證器方法

Lambert 等人提出的 RLVR 強調以可驗證獎勵取代學習式獎勵模型。When2Think 延續了這一精神，但進一步引入 IDAC 來解決「效率與準確率權衡」的結構性問題。這使得 RLVR 不僅能對齊正確性，還能對齊計算效率。

##### 4. 限制與潛在弱點

儘管 When2Think 表現出色，仍存在一些限制：

- **領域侷限**：實驗主要集中在數學推理任務，對於開放式生成、程式碼、常識推理等領域的適用性仍需驗證。
- **依賴可驗證答案**：RLVR 需要正確答案可被自動驗證，這限制了其在主觀或開放式任務上的應用。
- **參考統計量的品質**：IDAC 的表現取決於預先計算的參考統計量。若參考策略本身有偏誤（例如在某些難度層級採樣不足），則塑形獎勵可能誤導學習。
- **難度標籤的取得**：論文使用 MATH-500 等基準測試內建的難度等級。在實際應用中，如何自動且穩定地估計問題難度仍是一個挑戰。
- **模式詞元的開銷**：雖然 THINK/NOTHINK 機制簡潔，但訓練初期需要透過均勻探索來避免塌陷，這可能增加初期樣本成本。
- **批次標準化的敏感性**：批次標準化優勢假設每個 mini-batch 具有足夠多樣性，若批次內難度分布極度偏斜，可能影響梯度穩定性。

#### 可重現性評估

根據目前提供的論文內容，When2Think 的可重現性面臨以下情況：

##### 1. 開源狀態

論文為 arXiv 預印本，文中並未明確提及是否釋出：

- 原始碼（source code）
- 訓練腳本與超參數配置
- 預先計算的參考統計量（reference statistics）
- 模型權重（model weights）
- 資料處理流程

在缺乏這些資源的情況下，其他研究者難以完全重現論文中的數據。

##### 2. 可重現的關鍵要素

若要提升可重現性，作者至少需要釋出：

- **參考策略的採樣細節**：包括使用的基礎模型、採樣溫度、每個實例的採樣次數、如何計算 α_i 與 τ_i 等統計量。
- **IDAC 獎勵塑形的具體公式**：目前論文僅描述概念，未給出完整的數學式與超參數。
- **訓練配置**：學習率、批次大小、PPO 裁剪參數 ϵ、IS 探索策略的實作方式、EOT 標記的設計等。
- **評估協議**：Pass@1 與 Pass@3 的計算方式、是否使用多數投票（majority voting）、採樣溫度等。

##### 3. 部分可重現性

由於 When2Think 建立在公開模型（如 R1-Distill-Qwen、Qwen2-5-Math）與公開基準測試（MATH-500、AIME24、AIME25）之上，具備經驗的研究者可以根據論文描述自行實作。然而，IDAC 的細節與參考統計量的建構方式將是重現過程中最大的不確定因素。

#### 未來研究方向

When2Think 為高效率混合推理開闢了多條後續研究路徑：

##### 1. 跨領域與跨任務驗證

將 IDAC 框架擴展到程式碼生成、科學問答、邏輯推理、甚至多模態推理任務，驗證其是否仍能維持準確率–效率權衡。

##### 2. 線上難度估計與動態參考統計更新

目前參考統計量是預先計算且靜態的。未來可研究如何隨著策略進步動態更新參考統計量，或讓模型本身學習問題難度的線上估計器。

##### 3. 結合過程監督獎勵模型（PRM）

雖然 When2Think 採用結果導向的驗證器，但引入**過程監督獎勵模型（Process-supervised Reward Models, PRMs）**可進一步細粒度控制每一步推理的價值，可能提升困難實例的穩定性。

##### 4. 無模式詞元的連續深度控制

探索不依賴 THINK/NOTHINK 二元模式詞元，而是透過連續隱變數或自適應停止機制來控制推理深度，可能進一步提升靈活性。

##### 5. 與推理壓縮技術的結合

When2Think 決定「是否推理」與「推理多長」後，可進一步結合 Skip-Thinking、LC-R1 等壓縮技術，對已決定要生成的長推理鏈進行內部精簡。

##### 6. 使用者可控的推理預算

將 IDAC 擴展為可接受外部預算約束（例如用戶指定的最大詞元數或延遲限制），在難度感知的基礎上進一步實現個人化的計算–準確率權衡。

##### 7. 理論分析

從計算最適化（compute-optimal inference）角度，建立推理長度與問題難度之間的理論關係，並分析 IDAC 在不同難度分布下的收斂性與最適性保證。

##### 8. 多模型協作與推測解碼（speculative decoding）

將 When2Think 與推測解碼、草稿模型（draft model）等加速技術結合，進一步降低實際推理延遲。

##### 9. 獎勵塑形的可解釋性

研究 IDAC 獎勵如何影響模型的推理策略，開發可視化工具來理解模型在哪些特徵上學會了「跳過推理」或「深入思考」。

##### 10. 獎勵駭客（reward hacking）的防範

隨著獎勵訊號變得更複雜（正確性 + 效率 + 難度塑形），模型可能學會欺騙驗證器或利用參考統計量的漏洞。未來需要設計更穩健的獎勵機制與評估協議。

## 論文問答

**Q1：When2Think 主要想解決什麼問題？**
A：大型推理模型（LRMs）雖然在複雜任務上表現優異，卻存在系統性的推理效率低下問題：它們常在簡單題目上過度思考，產生冗餘推理詞元，卻在困難題目上思考不足，導致推理鏈片段化或過早結束。傳統的靜態詞元縮減策略雖然能降低簡單實例的計算量，卻會對困難實例造成「效率稅」，也就是以犧牲難題準確率為代價換取整體詞元減少。When2Think 將高效率推理重新定義為實例自適應計算分配問題，目標是根據每個問題的難度動態決定是否進行深思熟慮以及思考多深。

**Q2：現有的統一長度懲罰或剛性路由方法為何會失敗？**
A：這類方法通常對所有實例施加相同的全域限制，例如固定的詞元預算或硬性的長度懲罰，無法區分題目的難易程度。當模型被強制縮短推理軌跡時，簡單題目確實減少了過度思考，但困難題目卻因為缺乏足夠的審議過程而準確率下降。這種「一體適用」的做法本質上是在效率與準確率之間做零和取捨，無法達到真正的難度感知分配。

**Q3：為什麼難度感知的計算分配對混合推理模型很重要？**
A：難度感知分配能讓模型把計算資源花在真正需要深思熟慮的實例上，對簡單問題使用系統 1（System 1）式的直接回答，對困難問題保留系統 2（System 2）式的多步驟推理。這不僅能改善準確率–效率權衡，也能避免靜態策略對難題造成的傷害。對於實際部署而言，這意味著在降低延遲與成本的同時，仍能維持對複雜查詢的高品質回應。

**Q4：When2Think 的核心方法架構是什麼？**
A：When2Think 是一個後訓練框架，結合了可驗證獎勵強化學習（RLVR）與實例級難度感知控制（IDAC）的獎勵塑形機制。它透過在推理軌跡前加入模式詞元（`<Think>` 或 `<NoThink>`）來統一控制「是否思考」與「思考多深」，並利用重要性採樣進行穩定的策略最佳化。訓練過程採用 PPO 風格的裁剪代理目標，並搭配批次標準化優勢與基於驗證器的獎勵，實現無需學習式獎勵模型或線上參考模型查詢的無評論家優化。

**Q5：IDAC（實例級難度感知控制）的關鍵創新在哪裡？**
A：IDAC 利用預先計算的參考統計量（每個實例的參考準確率與詞元使用量）來塑造獎勵，讓模型能根據題目難度調整推理深度。對於參考準確率高且可節省詞元的簡單實例，它鼓勵直接回答；對於需要長軌跡才能正確解出的困難實例，則保留延伸推理。這種實例級的細粒度控制無需額外訓練獎勵模型，也無需在訓練時反覆查詢參考模型，從而兼顧穩定性與可擴展性。

**Q6：為什麼選擇預先計算參考統計量與基於驗證器的獎勵？**
A：預先計算參考統計量可以在訓練前離線完成，避免訓練過程中進行昂貴的線上參考模型查詢，從而降低計算開銷。基於驗證器的獎勵則提供確定性的正確性信號，直接對齊任務目標，減少學習式獎勵模型可能帶來的偏誤與不穩定性。再配合批次標準化優勢，能夠有效降低不同小批次之間的梯度變異，使無評論家優化更加穩定。

**Q7：論文在哪些基準測試上進行實驗？**
A：實驗主要在數學推理基準測試上進行，包括 MATH-500、AIME24 與 AIME25。MATH-500 被用來觀察模型在不同難度等級（Level 1–5）上的行為與詞元分配；AIME24 與 AIME25 則是更具挑戰性的數學競賽測試，用來評估 When2Think 在困難問題上的準確率與效率。這些測試涵蓋了從相對簡單到極具挑戰性的多樣化數學問題。

**Q8：When2Think 取得了哪些關鍵實驗結果？**
A：在 AIME24 上，When2Think 相較於基礎模型在 Pass@3 提升了 10.0%，同時詞元使用量減少了 27.9%。在 AIME25 上，When2Think 達到 40.0% 的 Pass@3，優於壓縮基線與僅路由基線。在 MATH-500 上，When2Think 在簡單實例上達到接近 LLM 的詞元效率，同時在困難實例上維持接近 LRM 的準確率，顯示出良好的難度感知分配能力。

**Q9：論文提供了哪些消融研究或深入分析來支持方法設計？**
A：論文首先分析了「效率稅」現象，顯示靜態詞元縮減雖然減少簡單實例的過度思考，卻會在困難實例上造成思考不足。接著透過與壓縮基線和僅路由基線的比較，證明 When2Think 同時控制「是否思考」與「思考多深」的統一策略優於單純縮減長度或剛性切換。這些分析強調了實例級難度感知控制在改善準確率–效率權衡上的必要性。

**Q10：When2Think 適合應用在哪些實際場景？**
A：When2Think 適合查詢難度差異大的互動式應用，例如線上家教、程式輔助、自動定理證明或客戶支援系統。在這些場景中，簡單問題可以快速直接回答以節省成本與延遲，而複雜問題則保留完整推理以確保正確性。這種彈性對於需要大規模部署推理模型的商業產品特別有價值。

**Q11：將 When2Think 產品化時需要考慮哪些因素？**
A：首先需要校準難度估計，確保預先計算的參考統計量能反映真實使用者查詢的分佈。其次要監控困難查詢的準確率，避免模型為了節省成本而對複雜問題思考不足。此外，`<Think>` 與 `<NoThink>` 模式詞元提供了可解釋的控制介面，產品設計上可以根據延遲或成本預算設定 fallback 機制，必要時強制進入深思模式。

**Q12：When2Think 對人工智慧領域可能帶來什麼影響？**
A：When2Think 將研究焦點從單純的詞元縮減轉移到實例自適應的計算分配，為高效率混合推理模型提供了新的設計範式。它結合雙重歷程理論與可驗證獎勵強化學習，展示了如何在單一模型中學習何時使用系統 1、何時使用系統 2。這有助於推動大型推理模型在真實世界中的可擴展部署，並可能影響未來推理壓縮與自適應推理的研究方向。

**Q13：論文可能承認哪些限制？**
A：目前的方法主要在數學推理基準測試上驗證，對於其他領域（例如開放式問答或創意寫作）的泛化能力仍需進一步研究。難度感知控制依賴預先計算的參考統計量，若參考數據品質不佳或分佈偏移，可能影響控制效果。此外，對於缺乏明確驗證器的任務，如何設計有效的獎勵信號仍是一個挑戰。

**Q14：When2Think 可能出現哪些失敗案例？**
A：如果困難實例被錯誤判斷為簡單，模型可能選擇 `<NoThink>` 而導致思考不足與準確率下降。反之，若簡單實例的參考統計量存在雜訊，模型也可能不必要地進入 `<Think>` 模式，浪費計算資源。另外，當問題難度超出訓練分佈或驗證器無法正確評估答案時，IDAC 的獎勵塑形可能無法發揮預期效果。

**Q15：未來可以朝哪些方向延伸 When2Think？**
A：未來可以將 IDAC 擴展到更廣泛的領域，例如程式碼生成、科學推理或多輪對話，並結合過程監督獎勵模型（PRM）進行更細緻的步驟級控制。另一個方向是發展線上難度估計機制，讓模型在推理過程中動態調整深度，而不僅依賴預先計算的統計量。此外，可以探索無需模式詞元的連續深度控制，或將 When2Think 與更大的基礎模型結合，進一步提升在極困難任務上的表現。

## 實務應用指南

### 適用場景

1. **企業級數學與工程輔助系統**  
   在金融建模、結構計算、供應鏈優化等需要大量數學推理的場景中，When2Think 可依題目難度自動決定是否啟動深思熟慮（Think）模式。簡喷的單步計算直接以 System 1 回答，複雜證明或競賽級問題才展開 System 2 推理，顯著降低 API 詞元成本並縮短回應時間。

2. **線上教育與適性化解題輔導**  
   對於 K-12 到大學程度的數學題庫，系統可根據學生程度與題目難度動態調整推理深度。簡單題目給出快速答案，困難題目提供完整多步驟推理鏈，兼顧學習效率與解釋品質。

3. **程式碼輔助與軟體工程 Agent**  
   在程式碼生成、除錯或重構任務中，簡單的語法修正或常見函式補全可直接回答，複雜演算法設計或跨檔案依賴分析則啟動長鏈推理。這能減少冗餘詞元，提升開發者體驗。

4. **科學研究與文獻問答系統**  
   面對文獻摘要、簡喷事實查詢時採用 NoThink 直接回答；遇到需要推導公式、比較多篇論文方法或驗證實驗設計的問題時，才啟動深思熟慮模式，平衡研究效率與答案準確率。

5. **客服與知識庫問答**  
   常見問題（FAQ）與政策查詢可直接回答，降低延遲；涉及多條件判斷、退換貨規則推導或爭議處理時，再啟動結構化推理，提升首次解決率。

### 實作前置條件

**資料準備**

- 具備可驗證答案的任務資料集，例如數學題目與標準答案、程式測試案例、結構化問答對。  
- 預先計算的參考統計量（reference statistics）：針對每個實例或難度分群，記錄基礎模型的 Pass@1 準確率與平均詞元使用量，作為 IDAC 獎勵塑形的基準。  
- 若無現成難度標籤，需先建立難度評分機制（如以基礎模型正確率、題目長度、知識點數量分群）。

**運算資源**

- 至少一張可執行 7B–14B 模型 RLVR 訓練的 GPU（如 A100 80GB 或同等級）。  
- 能夠批次生成 K 條推理軌跡（reasoning trajectories）的推論環境，用於重要性採樣與優勢估計。  
- 驗證器（verifier）需能自動判斷最終答案正確性，例如數學答案正規化比對、程式執行測試。

**技術能力**

- 熟悉強化學習基礎，特別是 PPO / clipped surrogate objective 與 importance sampling。  
- 能修改或擴充 LLM 後訓練框架（如 TRL、OpenRLHF、verl），加入 mode token（THINK / NOTHINK）與 end-of-thinking token（EOT）控制。  
- 具備獎勵塑形（reward shaping）與批次標準化（batch-wise standardization）的實作經驗，以穩定無評論家（critic-free）訓練。

### 實作步驟建議

1. **建立可驗證任務與難度分群**  
   將業務問題轉換為答案可驗證的形式，並依據基礎模型表現或領域知識將實例分為數個難度等級。

2. **預先計算參考統計量**  
   使用基礎模型在每個難度等級上採樣，記錄平均準確率與詞元使用量。這些數值將成為 IDAC 獎勵塑形中的參考基準。

3. **設計混合推理策略與模式 token**  
   在 prompt 或生成開頭引入 `THINK` / `NOTHINK` 模式 token，並定義 `EOT` 結束深思熟慮。確保模型在訓練初期有均等機會探索兩種模式。

4. **實作 IDAC 獎勵塑形**  
   結合驗證器獎勵（正確與否）與難度感知長度獎勵：對簡單實例鼓勵短軌跡，對困難實例保留較長軌跡。使用預先計算的參考統計量正規化獎勵，避免統一長度懲罰造成的思考不足。

5. **導入重要性採樣與批次標準化優勢**  
   以輔助探索策略均勻抽樣模式 token，並用 importance ratio 重新加權軌跡。對優勢進行批次標準化，穩定 critic-free 訓練。

6. **小規模實驗與效率–準確率權衡分析**  
   先在內部驗證集上比較 When2Think、純壓縮基線與僅路由基線，繪製 Pass@K 與每實例平均詞元的權衡曲線，選擇符合業務目標的檢查點。

7. **部署與線上監控**  
   將訓練後模型部署為推理服務，監控實際請求的難度分佈、模式選擇比例、詞元使用量與錯誤率，並定期以新資料重新計算參考統計量。

### 潛在風險與注意事項

- **難度估計偏差**  
  若參考統計量無法反映真實難度，模型可能對困難題目過度節省詞元，導致思考不足。建議定期以最新基礎模型重新估計，並保留人工審核機制。

- **模式崩潰（mode collapse）**  
  訓練初期可能全部傾向 `NOTHINK` 或 `THINK`。透過重要性採樣強制均衡探索，並在獎勵中加入適度熵正則化，可降低此風險。

- **獎勵塑形過度敏感**  
  長度獎勵權重過大會壓抑正確答案所需的推理深度。應從小權重開始，逐步調整，並以困難實例的 Pass@K 作為主要監控指標。

- **驗證器限制**  
  對於開放式生成或無唯一答案的任務，驗證器可能不穩定。建議先從答案可正規化比對的領域（數學、程式）導入，再擴展到需要 LLM-as-a-judge 的場景。

- **分佈外（OOD）行為**  
  當線上輸入與訓練資料難度分佈差異過大時，模型可能錯誤選擇模式。可加入難度不確定性估計或 fallback 機制，在信心低時預設啟動 Think。

### 與其他技術的整合建議

- **與現有 LLM 服務整合**  
  When2Think 可作為後訓練模型部署在 vLLM、TGI 或自研推理引擎上。透過 API 層暴露 `mode=adaptive` 選項，讓上游應用決定是否強制 Think / NoThink 或交由模型自適應。

- **與檢索增強生成（RAG）結合**  
  在 RAG 流程中，簡單的檢索結果摘要可直接回答，複雜的多文件比較或數值推導啟動 When2Think 的深思熟慮模式，進一步降低整體詞元成本。

- **與模型路由（Model Routing）搭配**  
  對於擁有多個模型的系統，When2Think 可視為「單模型內路由」層，與跨模型路由（如小模型處理簡單查詢、大模型處理困難查詢）互補，減少模型切換開銷。

- **與監控與回饋迴路整合**  
  將驗證器結果、詞元使用量與使用者回饋寫入資料倉儲，定期重新計算參考統計量並觸發增量後訓練，形成持續優化的閉環。

- **與提示工程（Prompt Engineering）協作**  
  在導入 When2Think 前，可先用 few-shot 提示評估基礎模型在不同難度上的表現，作為 IDAC 參考統計量的來源；導入後，提示設計可專注於任務格式，而非控制推理長度。

**研究人員**

**產品經理**  
關注 AIME24 / AIME25 的準確率–效率權衡數據，以及 MATH-500 上依難度分層的表現。重點評估 When2Think 對 API 成本、延遲與使用者體驗的影響，並規劃從可驗證任務（數學、程式）開始落地的 MVP。
