## 摘要翻譯

大型語言模型（Large Language Model, LLM）代理經常遇到相關但相異的任務，這些任務共享可重用的解題模式（solution pattern）。然而，標準代理式強化學習（Agentic Reinforcement Learning）將任務視為獨立回合（episode），而現有的技能學習方法則專注於單一任務的重複嘗試，或使用將技能萃取（skill extraction）、技能檢索（skill retrieval）與技能執行（skill execution）糾纏在一起的多階段流程。我們提出 SkillRise，一個用於跨任務技能學習（cross-task skill learning）的統一強化學習框架。SkillRise 將相關實例組織成漸進式困難序列（progressively challenging sequence），並使用單一策略（single policy）在任務求解（task solving）與技能策展（skill curation）一個持續演化的技能文件（skill document）之間交替進行，並將該技能文件直接傳遞給下一個任務。跨任務的解耦信用分配（decoupled credit assignment）以當前任務結果監督求解，並以折扣的下游結果（discounted downstream outcome）監督策展。在 ALFWorld、WebShop 與 ScienceWorld 上的實驗顯示，SkillRise 在所有比較方法中達到最強的 Pass@1 效能，相較於最強基準方法（baseline）的效能增益（performance gain）介於 2.3 至 8.5 百分點（percentage points）。儘管在相異的任務上訓練，其學到的策展策略（curation policy）在對同一任務進行重複嘗試時仍然有效。進一步的分析揭示了跨任務的測試時間規模化（scaling at test time）：即使每個任務僅嘗試一次，效能仍隨著更長的相關任務序列而提升。此趨勢表明 SkillRise 是在跨任務中重用可遷移技能（transferable skill），而非受益於對同一任務的重複取樣（repeated sampling）。SkillRise 在大幅降低多階段技能學習流程的執行時間負擔（runtime overhead）的同時，仍保持強勁的效能。綜合而言，這些結果為 LLM 代理提供了一個簡單且高效的訓練範式（training paradigm），使其能夠跨任務萃取、精煉與重用可遷移技能。

### 核心貢獻（3～5點）
- **統一框架設計**：提出 SkillRise，以單一策略同時處理任務求解與技能策展，避免多階段流程中萃取、檢索與執行相互糾纏的問題。
- **解耦信用分配機制**：以當前任務結果監督求解、以折扣的下游結果監督策展，實現跨任務的端到端聯合優化。
- **卓越的下游效能**：在 ALFWorld、WebShop 與 ScienceWorld 三項基準上取得最強的 Pass@1 效能，相較最強基準方法提升 2.3 至 8.5 百分點。
- **跨任務測試時間規模化**：即使每個任務僅嘗試一次，效能仍隨相關任務序列的增長而提升，證明 SkillRise 確實在重用可遷移技能，而非依賴對同一任務的重複取樣。
- **高效率的訓練範式**：大幅降低多階段技能學習流程的執行時間負擔，提供簡單且高效的方法使 LLM 代理能跨任務萃取、精煉與重用可遷移技能。

### 適合對象
從事 LLM 代理、強化學習、自動化技能學習與遷移學習的研究者與工程師；對長時程任務求解、跨任務泛化、代理式 AI 訓練範式，或測試時間規模化等議題感興趣的學術界與產業界讀者。

## 深度分析

#### 方法論解析

SkillRise 提出了一種端到端（end-to-end）的代理式強化學習（agentic RL）框架，專門解決跨任務技能學習（cross-task skill learning）的問題。其方法論的核心在於將「任務求解」與「技能策展（skill curation）」兩個行為統一在同一個策略（policy）下，並透過精心設計的信用分配機制（credit assignment）來優化兩者的協作。

**1. 跨任務序列建構（Cross-Task Sequence Construction）**

傳統的代理式 RL 將每個任務視為獨立的回合（independent episode），無法讓技能在不同任務間遷移。SkillRise 的第一步是將同一任務系列（task family）中的相關但相異的任務實例（related yet distinct task instances）組織成一個有序序列 $x = (x_1, \ldots, x_K)$，並按照難度由簡至難進行排序。這種「漸進式困難序列（progressively challenging sequence）」設計的關鍵在於：雖然各任務的具體實體與目標不同，但它們共享可被抽象為可遷移技能（transferable skill）的共同互動規律（common regularity）。因此，較早任務中學到的技能可以指導較晚的任務，而較晚任務的表現則直接衡量技能的遷移品質。

**2. 共享策略的雙角色機制（Single Policy with Dual Roles）**

在每個回合（rollout）中，SkillRise 使用單一策略 $\pi_\theta$ 在兩個行為階段（behavioral phase）之間交替：
- **任務求解階段（Task Solving Phase）**：策略接收當前任務指令 $x_k$ 與當前技能文件（skill document）$S_{k-1}$，產生互動軌跡（interaction trajectory）$\tau_k$。
- **技能策展階段（Skill Curation Phase）**：策略根據剛完成的軌跡 $\tau_k$ 更新技能文件，產生 $S_k$，作為下一個任務的唯一資訊通道。

這種設計避免了傳統多階段技能學習流程（multi-stage skill learning pipeline）中萃取、檢索、執行三者糾纏的問題，使技能文件成為跨任務資訊傳遞的唯一媒介。

**3. 解耦的跨任務信用分配（Decoupled Cross-Task Credit Assignment）**

這是 SkillRise 最具理論深度的設計。鑑於任務求解與技能策展在時間序列上扮演不同角色，SkillRise 採用時序對齊的監督訊號（temporal role-aware supervision）：
- **任務求解**：以當前任務的結果獎勵 $R(\tau_k)$ 作為學習訊號。
- **技能策展**：以折扣後的下游任務獎勵（discounted downstream outcome）作為學習訊號，即 $\sum_{j=k+1}^{K} \gamma^{j-k-1} R(\tau_j)$，其中 $\gamma$ 為折扣因子。

這樣的設計使策展行為的好壞直接由其對後續任務的影響來評估，而非僅由當前任務表現決定。接著，採用群組相對優勢（group-relative advantage），在共享相同任務群組、序列位置與行為階段的試驗間計算，這進一步穩定了策略梯度估計。

**4. 整體訓練目標**

綜合上述設計，SkillRise 的優化目標可理解為：在序列 $x$ 上最大化經解耦信用加權的期望獎勵，使策略同時學會「解決當前任務」與「產出對未來任務有用的技能」。這是一個端到端的單階段訓練範式（training paradigm），無需預訓練的技能萃取器或外部技能庫（external skill bank）。

#### 實驗數據解讀

**1. 主要效能結果**

SkillRise 在三個代理基準（agentic benchmark）上進行評估：ALFWorld（家庭任務模擬）、WebShop（線上購物互動）、ScienceWorld（科學實驗模擬）。在所有三個環境中，SkillRise 均取得最強的 Pass@1 效能，相較最強基準方法（strongest baseline）提升幅度為 **2.3 至 8.5 百分點（percentage point）**。這個提升幅度在 RL 領域屬於顯著改進，特別是相較於已成熟的基準方法。

**2. 跨任務遷移的驗證**

論文中特別強調，SkillRise 的優勢不僅來自於重複嘗試同一任務所帶來的增益，而是真正實現了跨任務遷移（cross-task transfer）。具體而言：
- 與「重複嘗試同一任務並摘要先前軌跡」的方法相比，SkillRise 在不同任務實例間展現更強的遷移能力。
- 這說明其學到的技能文件捕捉的是任務系列層級的通用規律，而非個例特定（instance-specific）的記憶。

**3. 測試時間規模化（Test-Time Scaling）**

這是 SkillRise 最引人注目的發現之一：在測試階段，給定更長的相關任務序列，效能會持續提升，即使每個任務僅嘗試一次。這種「跨任務測試時間規模化（cross-task test-time scaling）」現象表明：
- 技能文件隨著序列推進而逐步精煉（refine）。
- 效能增益來自於技能的累積與重用，而非重複取樣（repeated sampling）帶來的統計優勢。
- 競爭方法未展現此增長趨勢，凸顯 SkillRise 學到的是可遷移的自我改進機制。

**4. 效率分析**

相較於多階段技能學習流程，SkillRise 的端到端設計大幅降低了執行時間負擔（runtime overhead）。這對於實際部署至關重要，因為多階段流程需要在萃取、檢索、執行間反覆切換，產生顯著的計算與延遲成本。

**5. 結果的侷限性**

雖然結果令人鼓舞，但需注意：
- 三個基準雖具代表性，但均屬於結構化環境，與真實世界的開放式任務仍有差距。
- 2.3 至 8.5 百分點的提升在不同基準上分布不均，具體數字需參照原論文表格。
- 測試時間規模化雖具理論吸引力，但實際應用中需考慮序列長度對延遲的影響。

#### 與現有研究的比較

**1. 相較於標準代理式 RL**

標準代理式 RL（如直接對任務獎勵進行策略優化）將每個任務視為獨立回合，無法累積跨任務經驗。SkillRise 透過序列化任務與技能文件機制，使策略能夠在任務間累積經驗，這是相對標準 RL 的根本性架構差異。

**2. 相較於重複嘗試型方法**

以 Jiang 等人（2025）為代表的方法反覆嘗試同一任務並摘要先前軌跡以改進後續嘗試。SkillRise 的優勢在於：
- **跨任務而非同任務**：技能在任務系列內遷移，而非僅在單一實例內累積。
- **無需額外互動**：不依賴同一任務的多輪嘗試，僅需一次互動即可萃取技能。
- **直接優化遷移**：策展行為以下游任務表現為監督，而非以當前軌跡品質為監督。

**3. 相較於外部技能庫方法**

以 Xia 等人（2026）與 Wu 等人（2025）為代表的方法維護外部經驗庫（external experience bank），並透過檢索機制將相關技能注入任務求解。SkillRise 的改進在於：
- **消除模組糾纏**：技能萃取、檢索、執行在同一策略下聯合優化，避免下游效能難以歸因（attribute）於技能品質的問題。
- **簡化資訊流**：技能文件作為唯一資訊通道，無需設計複雜的檢索匹配機制。
- **端到端可微**：整個流程可透過策略梯度統一訓練，無需分階段訓練。

**4. 相較於其他 RL 經驗萃取方法**

Zhang 等人（2026a）、Shi 等人（2026）、Wang 等人（2026a）亦探討使用 RL 訓練代理萃取可重用經驗。SkillRise 的獨特貢獻在於明確區分「任務求解」與「技能策展」兩個行為階段，並設計對應的解耦信用分配，這在現有文獻中較為少見。

**5. 現有方法的侷限性**

- **重複嘗試型方法**：知識可能停留在個例特定層級，缺乏跨任務泛化。
- **外部技能庫方法**：萃取、檢索、執行的聯合效能難以單獨評估技能品質。
- **多階段流程**：執行時間負擔高，且各階段錯誤可能累積放大。

SkillRise 透過統一框架同時解決了上述侷限，但其代價是對任務序列結構的依賴——需要事先將任務組織成相關但相異的序列，這在某些開放式應用場景中可能不易達成。

#### 未來研究方向

**1. 開放式任務序列的自動化建構**

SkillRise 目前依賴預先定義的任務系列與難度排序。未來可探索：
- 自動發現任務間的語義相似性，動態建構序列。
- 放寬「同一任務系列」的假設，允許跨領域的技能遷移。
- 結合課程學習（curriculum learning）理論，自適應調整序列難度。

**2. 技能文件的結構化與可解釋性**

當前的技能文件是一個扁平化的文字序列，未來可考慮：
- 引入階層化技能表示（如技能樹或技能圖）。
- 增強技能的可解釋性，使人類能審核與編輯。
- 結合符號式表示（如程式碼片段）以提升精確性。

**3. 多模態與真實世界部署**

目前實驗僅限於文字環境，未來可延伸至：
- 多模態環境（視覺、聽覺輸入）。
- 真實世界的機器人控制或 GUI 互動。
- 長時程任務中的技能組合（skill composition）問題。

**4. 理論分析**

SkillRise 的解耦信用分配雖具直覺吸引力，但缺乏形式化的理論保證。未來可：
- 分析折扣因子 $\gamma$ 對收斂性的影響。
- 證明在何種條件下技能文件能保證跨任務遷移。
- 探討群組相對優勢在跨任務設定下的統計性質。

**5. 與人類反饋的結合**

可探索將人類偏好（human preference）整合進技能策展的獎勵訊號，使策展行為不僅以任務成敗為依據，還能考慮技能的可讀性與可重用性。

**6. 安全性與對齊考量**

技能文件可能累積偏見或有害行為模式，未來需研究：
- 如何在策展階段引入安全過濾。
- 技能的可審計性（auditability）與回滾機制。
- 防止技能文件被對抗性輸入污染。

**7. 與其他範式的整合**

SkillRise 可與其他範式結合：
- 與模型蒸餾（distillation）結合，將策展能力蒸餾至較小模型。
- 與聯邦學習（federated learning）結合，使多個代理共享技能文件。
- 與持續學習（continual learning）結合，避免技能文件中的災難性遺忘（catastrophic forgetting）。

這些方向不僅能擴展 SkillRise 的適用範圍，也能深化我們對「代理如何在任務間累積與重用經驗」這一核心問題的理解。

## 論文問答

**Q1：SkillRise 主要解決的核心問題是什麼？**
A：SkillRise 試圖解決大型語言模型代理在面對一連串「相關但相異的任務」時，無法有效累積與遷移技能的問題。傳統的代理式強化學習將每個任務視為獨立的回合，導致代理在每次互動後便丟棄所學經驗，必須從零開始探索。論文中指出，理想的代理不僅應解決當前任務，更應從互動中萃取可遷移技能，並在後續任務中持續精煉與重用，從而隨時間變得愈來愈強。

**Q2：現有的技能學習方法為何無法有效支援跨任務遷移？**
A：現有方法大致可分為兩類，但都存在明顯缺陷。第一類方法反覆嘗試同一任務並摘要先前的軌跡，但所獲得的知識往往仍是個例特定的，需要額外的互動次數，且未直接針對跨任務遷移進行優化。第二類方法維護外部的技能庫或經驗庫，於新任務到來時更新並檢索相關技能，但由於下游效能同時受到技能萃取、檢索與執行的共同影響，難以將成敗歸因於技能本身的品質。SkillRise 正是為了克服這些限制而提出的端到端統一框架。

**Q3：為何跨任務技能學習對 LLM 代理如此重要？**
A：在實務部署中，LLM 代理經常會遇到一連串共享底層規律性與可重用解題模式的相關任務，例如同一任務系列中不同實例的處理。若代理無法從先前互動中萃取並遷移技能，便會在每個新任務上重複昂貴的探索成本，效率低落且難以擴展。論文中強調，跨任務技能學習使代理能夠「越用越強」，這對於長時程任務與真實世界應用場景中的可持續部署至關重要。

**Q4：SkillRise 的核心機制為何？**
A：SkillRise 的核心機制是將相關任務實例組織成由簡至難的漸進式序列，並讓單一策略在每個任務求解後，根據所產生的互動軌跡策展一份持續演化的技能文件，該文件會直接傳遞給下一個任務。這個設計使技能文件成為跨任務唯一的資訊通道，避免了多階段技能學習流程中萃取、檢索與執行相互糾結的問題。透過這樣的設計，後續任務的表現自然成為技能可遷移性的直接衡量依據。

**Q5：何謂「解耦的信用分配」，為何這種設計至關重要？**
A：解耦的信用分配是指 SkillRise 將任務求解與技能策展兩種行為分別賦予不同的學習訊號：任務求解接收當前任務的獎勵，而技能策展則接收來自後續任務的折扣下游結果。這種設計反映了兩種行為在時間軸上的不同角色——求解行為應對當下負責，策展行為則應為未來負責。論文中進一步採用角色感知的群組相對優勢計算，在共享相同任務群組、序列位置與行為角色的試驗間進行比較，使兩種行為能獲得各自適切的監督訊號。

**Q6：為何 SkillRise 選擇使用單一策略而非分離的求解與策展策略？**
A：使用單一策略同時負責任務求解與技能策展，能夠以端到端的方式聯合優化這兩種緊密耦合的行為，避免分離策略之間可能出現的目標不一致或介面協調問題。這種設計也大幅降低了執行時間負擔，因為不需要維護額外的技能管理模組或檢索機制。論文的實驗結果顯示，這種簡潔的設計在效能與效率之間取得了比多階段技能學習流程更好的平衡。

**Q7：論文中採用了哪些基準測試，為何選擇這些？**
A：論文中使用了 ALFWorld、WebShop 與 ScienceWorld 三個代理式基準測試。這三個基準涵蓋了不同類型的長時程任務：ALFWorld 涉及家庭環境中的文字互動、WebShop 模擬電子商務網站中的商品搜尋與購買、ScienceWorld 則涵蓋科學實驗的執行流程。選擇這些基準能夠全面評估 SkillRise 在異質任務領域中的跨任務技能遷移能力，並驗證其泛化性。

**Q8：SkillRise 的主要實驗結果為何？**
A：在三個基準測試上，SkillRise 一致地超越了基於提示的方法與標準強化學習基準，達到最強的 Pass@1 效能。相較於最強的基準方法，SkillRise 的效能增益介於 2.3 至 8.5 百分點之間。更值得注意的是，SkillRise 展現出跨任務測試時間規模化的特性：當測試時面對更長的相關任務序列時，效能會持續提升，而競爭方法則未呈現此趨勢，顯示其學到的是可遷移的技能機制而非針對單一任務的重複取樣效益。

**Q9：消融研究與分析揭示了哪些關鍵發現？**
A：分析顯示，儘管 SkillRise 是跨相異任務進行訓練，其學到的策展策略在重複嘗試同一任務時仍然有效，展現了良好的任務內泛化能力。此外，測試時間規模化分析表明，即使每個任務僅嘗試一次，效能仍會隨著相關任務序列的延長而提升，這印證了 SkillRise 確實重用了可遷移技能，而非僅僅受益於重複取樣。這些結果共同證明了 SkillRise 所學機制的可遷移性與穩健性。

**Q10：SkillRise 最適合應用於哪些實際場景？**
A：SkillRise 特別適合應用於代理需要持續處理一系列共享規律性的相關任務的場景，例如客服代理處理同一產品線下不同用戶的相似問題、軟體工程助理在相似程式碼專案間遷移除錯經驗，或研究助理在相關文獻任務間累積查詢與分析技能。在這些場景中，技能的可重用性與跨任務遷移能力直接影響部署成本與服務品質。

**Q11：將 SkillRise 整合至產品時需要考量哪些實務因素？**
A：產品整合時需考量幾項關鍵因素：首先，技能文件的設計與容量會直接影響代理的上下文視窗使用與推理成本，需要在文件豐富度與效率間取得平衡；其次，漸進式任務序列的建構需要事先對任務難度進行排序，這在實務中可能需要額外的標註或預處理流程；最後，由於 SkillRise 採用端到端訓練，部署時需要確保訓練資料的任務系列分布能夠代表實際應用場景，以避免領域漂移。

**Q12：SkillRise 對代理式強化學習領域的整體影響為何？**
A：SkillRise 提出了一種簡潔且高效的訓練範式，使 LLM 代理能夠萃取、精煉並重用跨任務的可遷移技能，這對領域的長期發展具有示範意義。它證明了單一策略結合解耦信用分配即可取代複雜的多階段技能學習流程，大幅降低了系統複雜度與執行時間負擔。此外，其測試時間規模化的特性為「代理隨經驗累積而持續成長」這一願景提供了實證基礎，可能激發後續更多關於跨任務自我改進的研究。

**Q13：論文中是否承認了哪些限制？**
A：雖然論文中未明確列出獨立的限制章節，但從方法設計與實驗設置可推論出若干限制：SkillRise 的效能仰賴任務序列中實例間共享的共同規律性，若任務之間的相似度過低，技能遷移的效果可能會受限。此外，漸進式困難序列的建構需要對任務難度進行預先排序，這在某些任務領域中可能並不容易自動化。技能文件的容量與表示方式也會影響可承載的技能複雜度。

**Q14：SkillRise 可能會在哪些情境下失效？**
A：當任務之間缺乏足夠的共同規律性時，技能策展可能無法萃取出對後續任務有用的可遷移技能，導致技能文件累積了無效甚至有害的經驗。此外，若任務序列的難度排序不準確，過早的策展行為可能基於尚未成熟的經驗進行總結，反而誤導後續任務。在極長的任務序列中，技能文件可能會超出上下文視窗容量或累積冗餘資訊，稀釋了關鍵技能的訊號強度。

**Q15：未來有哪些值得探索的研究方向？**
A：未來研究可朝多個方向延伸：首先是自動化任務序列的建構，包括難度排序與相關性度量，以減少對人工預處理的依賴；其次是探索更豐富的技能表示形式，例如階層式或圖結構的技能組織，以支援更複雜的技能組合；第三是將 SkillRise 與多代理協作結合，使不同代理能共享與貢獻技能庫；最後，將此框架擴展至多模態代理或真實世界機器人任務中，驗證其在更廣泛場景中的可遷移性。

## 實務應用指南

### 適用場景

**1. 企業客服與支援自動化**
在客服中心，代理需處理大量相似但相異的工單（退款申請、帳號問題、訂單修改等）。SkillRise 可讓代理從早期工單中萃取可重用的解決模式（如「先驗證身份再處理退款」），並在後續工單中直接套用，逐步建立跨案件類型的處理技能文件，減少重複探索。

**2. 程式碼除錯與重構助手**
開發團隊常面對相似但不同的 bug 模式（race condition、記憶體洩漏、API 呼叫錯誤）。SkillRise 可將相關 bug 案例組成漸進式序列，讓代理從簡單案例中萃取除錯啟發式（如「先檢查 log 時間戳」），並在後續更複雜的案例中重複使用，縮短平均除錯時間。

**3. 機器人流程自動化（RPA）跨流程遷移**
企業內部有多個相似流程（請假審批、採購申請、費用報銷），共享表單操作、欄位填寫、系統導航等共通模式。SkillRise 可讓代理在處理簡單流程時累積技能文件，並將其遷移至更複雜的流程，減少每個新流程的冷啟動成本。

**4. 個人化學習與家教助理**
學生在數學、物理、化學等科目中常遇到結構相似的題型（單元轉換、方程式建立、單位分析）。SkillRise 可將同類型但不同實例的題目組成序列，讓家教代理從基礎題萃取解題模板，並在進階題中重複使用，提供漸進式學習體驗。

**5. 資料分析與 BI 助理**
資料分析師常對不同資料集執行相似分析（清理、聚合、視覺化、異常偵測）。SkillRise 可讓代理在處理小型、結構良好的資料集時累積分析技能，並將其遷移至大型、雜訊較多的資料集，提升跨資料集的工作效率。

### 實作前置條件

**資料需求**
- **任務系列資料集**：需具備同一任務系列的多個相異實例（例如 ALFWorld 中的不同家庭任務、WebShop 中的不同商品類別）。每個實例需有可驗證的結果回報（verifiable outcome reward）。
- **難度標註或排序機制**：需能將實例由簡至難排序，可採人工標註、啟發式規則（如步驟數、目標數量），或以較小模型預測難度。
- **環境介面**：任務需具備可執行的環境（模擬器、API、互動式介面），能回傳觀察與獎勵訊號。

**計算資源**
- **GPU 叢集**：用於 LLM 策略的 RL 微調，建議至少配備 8 張以上 A100/H100 等級 GPU 以支援 GRPO 等群組式策略最佳化。
- **分散式推論基礎設施**：rollout 階段需大量平行環境互動，建議使用 vLLM、SGLang 等高效推論框架。
- **儲存空間**：技能文件隨序列長度成長，需規劃版本控管與檢索索引。

**技術能力**
- **強化學習基礎**：熟悉 PPO、GRPO 等策略梯度演算法，理解群組相對優勢（group-relative advantage）計算。
- **LLM 微調經驗**：具備 SFT、RLHF 或 agentic RL 的實作經驗，理解 LoRA、全參數微調的取捨。
- **環境工程能力**：能將任務包裝成符合介面規範的環境，處理觀察格式化、動作解析、獎勵計算。
- **評估管線**：能建立 Pass@1 等指標的自動化評估流程，並支援跨任務、跨序列長度的分析。

### 實作步驟建議

**步驟 1：任務系列定義與難度排序**
盤點目標業務領域，識別「同一任務系列」的多個實例。設計難度評估機制（人工標註、規則式評分或模型預測），並建立由簡至難的排序流程。建議先以 5–10 個實例的小規模序列進行概念驗證。

**步驟 2：環境與介面建置**
將任務包裝為可互動環境，定義觀察空間（文字、JSON、結構化狀態）、動作空間（工具呼叫、API 請求、自然語言指令）與獎勵函式（成功/失敗二元獎勵或稀疏獎勵）。確保環境可重置、可平行化。

**步驟 3：技能文件格式設計**
設計技能文件的結構（標題、觸發條件、操作步驟、注意事項），並定義策展動作的介面（新增、修改、刪除、重排）。技能文件應以純文字或結構化格式儲存，便於直接傳遞給下一個任務。

**步驟 4：策略初始化**
以具備基礎 agent 能力的開源 LLM（如 Qwen、Llama 系列）為起點，先進行任務求解的 SFT 預熱，再進入 RL 階段。設計 prompt 模板，明確區分「求解」與「策展」兩種角色指令。

**步驟 5：跨任務序列 rollout 實作**
實作序列 rollout 邏輯：對每個任務，先以當前技能文件求解，再根據軌跡策展更新技能文件，傳遞至下一任務。記錄每個階段的獎勵、軌跡與技能文件快照。

**步驟 6：解耦信用分配與策略更新**
實作解耦的獎勵分配：求解階段使用當前任務獎勵，策展階段使用後續任務的折扣回報（discounted return）。採用 GRPO 等群組式方法，針對相同任務群組、序列位置與行為角色計算群組相對優勢。

**步驟 7：評估與分析**
建立評估管線，量測 Pass@1、跨任務遷移效益、測試時間規模化趨勢（不同序列長度下的效能變化）。與基準方法（如標準 RL、重複嘗試式技能學習、多階段流程）進行比較。

**步驟 8：部署與監控**
將訓練後的策略部署至生產環境，建立技能文件的版本控管與監控機制。追蹤技能文件的成長軌跡，設定品質閾值以避免錯誤累積。

### 潛在風險與注意事項

**風險 1：技能文件錯誤累積（錯誤漂移）**
策展階段若產生低品質或錯誤的技能，會污染後續所有任務的輸入。
**緩解措施**：引入技能驗證機制（如定期以驗證集測試技能文件）、設定策展動作的獎勵塑形（鼓勵精簡且可驗證的技能）、保留原始軌跡以便回滾。

**風險 2：難度排序偏差**
若難度排序不準確，序列可能無法形成有效的漸進式學習訊號，導致早期任務過難或過易。
**緩解措施**：採用多種難度評估方式（人工 + 模型）並取交集、進行消融實驗驗證排序品質、允許動態調整序列順序。

**風險 3：負遷移（Negative Transfer）**
跨任務遷移的技能可能在某些任務上產生誤導，降低效能。
**緩解措施**：監控每個任務的技能使用情況、設定任務特定的技能過濾機制、保留「不使用技能」的選項讓代理可自行探索。

**風險 4：計算成本與延遲**
序列 rollout 需依序執行多個任務，訓練時間與推論成本較標準 RL 顯著增加。
**緩解措施**：使用高效推論框架（vLLM、SGLang）、平行化不同序列的 rollout、考慮使用 LoRA 等參數高效微調方法。

**風險 5：技能文件長度膨脹**
隨序列增長，技能文件可能無限膨脹，超出 LLM 上下文長度限制。
**緩解措施**：設定技能文件的長度上限、實作技能摘要與合併機制、採用階層式技能組織（高層策略 + 底層操作）。

**風險 6：獎勵稀疏與延遲**
策展階段的獎勵來自後續多個任務，存在稀疏性與延遲性，可能導致訓練不穩定。
**緩解措施**：使用折扣回報而非僅使用最終獎勵、引入稠密的中間獎勵（如技能被使用的次數）、採用優勢估計的 variance reduction 技巧。

### 與其他技術的整合建議

**與 RAG（Retrieval-Augmented Generation）整合**
SkillRise 的技能文件可作為 RAG 的知識庫來源，但兩者定位不同：RAG 強調從大量文件中檢索相關片段，SkillRise 強調技能的演化與策展。建議將技能文件視為「精煉後的策略記憶」，與 RAG 的「廣泛知識庫」互補使用——以 RAG 提供背景知識，以技能文件提供經過驗證的操作模式。

**與 Multi-Agent 系統整合**
在多代理架構中，可指定一個專門的「策展代理」負責技能文件的維護，其他「執行代理」專注於任務求解。SkillRise 的單一策略設計可擴展為多代理分工，但仍維持統一的訓練目標。

**與 RLHF / DPO 流程整合**
SkillRise 的 RL 階段可與人類回饋（RLHF）或偏好最佳化（DPO）結合：策展動作的品質可由人類評估，進一步微調策展策略。這對於技能文件的品質控管特別有價值。

**與持續學習（Continual Learning）系統整合**
SkillRise 天然適合持續學習場景：技能文件可作為「記憶回放」機制，避免災難性遺忘。建議將技能文件與模型參數的更新解耦，技能文件負責短期經驗累積，模型參數負責長期能力演化。

**與現有 Agent 框架（如 LangChain、AutoGen）整合**
可將 SkillRise 的策略包裝為自訂的 agent 模組，技能文件以系統提示（system prompt）或工具結果的形式注入。需注意框架的上下文管理機制是否能支援動態成長的技能文件。

**與 MLOps / LLMOps 平台整合**
技能文件的版本控管、評估指標的追蹤、模型的 A/B 測試皆可整合至現有 MLOps 平台。建議將技能文件視為一級模型產物，與模型權重一同納入版本管理。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先理解「代理式強化學習」的基本概念——LLM 代理在環境中互動、根據獎勵學習。閱讀時可先聚焦於第 1 節的問題動機（為何需要跨任務技能學習）與第 3.1 節的序列建構概念，跳過數學細節，重點掌握「技能文件隨任務序列演化」這個核心直覺。實作上可先從小規模的玩具環境（如簡化版 ALFWorld 任務）開始，體驗技能累積的過程。

**給 AI 工程師**
重點關注第 3 節的演算法細節，特別是解耦信用分配的實作（求解用當前獎勵、策展用折扣下游獎勵）與 GRPO 的群組相對優勢計算。建議直接閱讀論文的演算法虛擬碼，並嘗試在現有 agent 框架中實作一個最小可行版本。評估管線的設計（Pass@1、測試時間規模化分析）是工程上容易忽略但價值很高的部分，值得投入時間建立。

**給研究人員**
論文的關鍵創新在於「將技能策展視為可學習的行為，並以解耦的信用分配進行端到端最佳化」。建議深入分析第 3.2 節的數學推導，思考為何群組相對優勢需在「相同任務群組、序列位置、行為角色」三個維度上計算。此外，測試時間規模化的發現（效能隨序列長度成長）開啟了新的研究方向——可探索不同任務系列結構、難度排序策略、策展動作空間設計對規模化趨勢的影響。與現有技能學習方法（如 ExpeL、Self-Refine）的理論比較也是值得探討的議題。

**給產品經理**
SkillRise 的核心價值在於「讓代理越用越聰明」，這對需要長期部署的 agent 產品（如客服、助理、自動化工具）特別有吸引力。建議從業務角度思考：哪些場景的任務具有「相關但相異」的特性？哪些場景的代理會反覆遇到相似問題？論文中 ALFWorld、WebShop、ScienceWorld 的實驗結果顯示 2.3–8.5 百分點的效能提升，這在生產環境中可能代表顯著的成本節省或使用者滿意度提升。實作上需評估訓練成本（GPU、資料標註）與長期效益（技能累積帶來的可規模化性）的取捨，並關注技能文件的可解釋性——它可作為產品除錯與使用者信任建立的工具。
