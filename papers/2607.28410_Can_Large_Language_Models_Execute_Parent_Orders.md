## 摘要翻譯

母單執行（parent-order execution）是演算法交易（algorithmic trading）中的核心問題，其目標在於將大額母單（parent order）拆分（splitting）為較小訂單，同時降低執行成本（execution costs）。現有方法不是仰賴可能於實務中不成立的預設市場假設（pre-specified market assumptions），就是需要任務特定訓練（task-specific training），因而限制了對新情境的適應能力。為克服這些限制，我們首次針對大型語言模型（Large Language Models, LLMs）應用於母單執行進行系統性研究，將 LLMs 在金融領域的應用從「交易什麼」延伸至「如何執行」。我們提出 PACE（Plan-Ahead Controlled Execution，預先規劃控制執行），一個將母單執行分解為長期規劃（long-horizon planning）與短期執行（short-horizon execution）的階層式框架（hierarchical framework），既不需要明確市場假設（explicit market assumptions），也不需要任務特定訓練。以深圳證券交易所 Level-1 資料（Shenzhen Stock Exchange Level-1 data）進行的實驗顯示，PACE 優於 TWAP（Time-Weighted Average Price，時間加權平均價格）、Almgren-Chriss 以及基於學習的基準（learning-based baselines），較最強基準高出 0.65 基點（basis points, bps）。行為分析（behavioral analysis）顯示，LLMs 做出執行決策的方式與人類投資者（human investors）不同：模型信心度（model confidence）越高，預測的績效越好，而非報酬越差，且模型會較早交易，而非拖延至截止期限（deadline）。這些發現顯示，LLMs 可在執行決策方面輔助人類交易者。

### 核心貢獻（3～5點）
- 首次系統性探討大型語言模型（LLMs）應用於母單執行，將 LLMs 在金融領域的應用從「交易什麼」延伸至「如何執行」。
- 提出 PACE（預先規劃控制執行）階層式框架，將母單執行分解為長期規劃與短期執行，無需明確市場假設或任務特定訓練。
- 在深圳證券交易所 Level-1 資料上驗證，PACE 優於 TWAP、Almgren-Chriss 及基於學習的基準，較最強基準高出 0.65 基點。
- 透過行為分析發現 LLMs 與人類投資者的執行決策差異：高模型信心度對應較佳績效，且模型傾向提前交易而非拖延至截止期限。

### 適合對象
本論文適合對演算法交易、量化金融與大型語言模型應用感興趣的研究者與實務工作者，特別是關注母單執行策略設計、市場微結構，以及希望了解 LLMs 如何輔助或替代傳統交易執行方法之金融機構交易員、量化分析師與金融科技開發者。

## 深度分析

#### 方法論解析

##### 問題設定與核心動機
Parent-order execution（母單執行）是 algorithmic trading（演算法交易）中的經典問題：給定一筆 parent order（母單）  
\(O=(s,d,t_s,t_e,Q)\)，其中 \(s\) 為股票代號、\(d\) 為買賣方向、\([t_s,t_e]\) 為 execution window（執行區間）、\(Q\) 為總量，目標是產生一條 execution curve（執行曲線），決定每個時點的交易量，以降低 execution costs（執行成本）。傳統方法如 TWAP（Time-Weighted Average Price，時間加權平均價格）與 Almgren-Chriss（Almgren-Chriss 模型）仰賴預設的 intraday volume distribution（日內成交量分布）或 market impact model（市場衝擊模型）；learning-based baselines（基於學習的基準）則需要 task-specific rewards（任務特定獎勵）、states（狀態）與 actions（動作），並在環境改變時重新訓練。PACE（Plan-Ahead Controlled Execution，預先規劃控制執行）的出發點在於：利用 Large Language Models (LLMs)（大型語言模型）的 broad prior knowledge（廣泛先驗知識），在 inference time（推論階段）直接生成決策，無需 explicit market assumptions（明確市場假設）也無需 task-specific training（任務特定訓練）。

##### 階層式分解：長期趨勢與短期波動
論文以 HP filter（Hodrick-Prescott filter，HP 濾波）將 stock price series（股票價格序列）拆解為 long-horizon trend（長期趨勢）與 residual short-horizon fluctuation（殘差短期波動），如圖 1 所示。這一觀察直接催生了 PACE 的 hierarchical framework（階層式框架）：

- **Planner（規劃器）**：負責 long-horizon planning（長期規劃）。根據 market history（市場歷史資料）與 TWAP curve（TWAP 曲線）等輸入，生成一條較粗粒度的執行計畫，捕捉相對穩定的長期趨勢。
- **Executor（執行器）**：負責 short-horizon execution（短期執行）。在 Planner 給定的框架下，根據即時的短期波動調整交易量，避免在市場瞬間不利時過度交易，或在有利時增加交易。

這種分解的優勢在於：長期訊號雖然預測難度低，但需要全局視角；短期訊號雜訊高，但若完全交由 LLM 逐筆決策，容易受到 noise（雜訊）干擾。透過「先規劃、後微調」的設計，PACE 既保留了 LLM 對趨勢的判斷能力，又透過 Executor 的即時控制降低高頻雜訊的影響。

##### 輸入設計
根據文中第 3.2 節，PACE 的輸入包含三項：

1. **Parent order（母單）**：定義標的、方向、時間區間與總量。
2. **Market history（市場歷史資料）**：包含股價與成交量等資訊，供 LLM 推斷趨勢與波動。
3. **TWAP curve（TWAP 曲線）**：作為基準執行曲線，讓 LLM 在已知「平均執行」的前提下，決定何時偏離、偏離多少。

將 TWAP curve 納入輸入是關鍵設計：它提供了一個無模型偏見的參考點，使 LLM 的輸出可解釋為「相對於 TWAP 的調整」，同時也便於與傳統基準進行公平比較。

##### 方法論評價
PACE 的最大貢獻在於把 LLM 在金融領域的應用從「what to trade（交易什麼）」延伸到「how to execute（如何執行）」。然而，從目前可見的文本來看，論文尚未詳細說明：

- Planner 與 Executor 的具體 prompt（提示詞）設計與輸出格式（例如是否輸出每個時段的目標量、偏離比例、或自然語言建議）。
- 使用的 LLM 版本（如 GPT-4、GPT-3.5 或其他開源模型）與 sampling（取樣）參數。
- Executor 的調整頻率、約束條件（例如是否強制在 deadline（截止期限）前完成全部交易量），以及如何將 LLM 輸出轉換為可執行的訂單。

這些細節對於理解 PACE 的穩健性與可遷移性至關重要。

#### 實驗數據解讀

##### 資料集與基準
實驗使用 Shenzhen Stock Exchange Level-1 data（深圳證券交易所 Level-1 資料）。Level-1 資料通常為較粗粒度的市場快照（例如數秒一筆的 OHLC 與成交量），相較於 Level-2 資料缺少詳細的 order book（委託簿）深度與逐筆委託資訊。這意味著 PACE 的決策主要基於價格趨勢與成交量型態，而非微觀流動性結構。

比較的基準涵蓋三大類：

1. **Static strategies（靜態策略）**：TWAP、Almgren-Chriss（AC）。
2. **Learning-based baselines（基於學習的基準）**：XGBoost、LSTM。
3. **PACE**：無任務特定訓練的 LLM 方法。

##### 績效指標
主要指標為 execution costs（執行成本），以 basis points (bps)（基點）衡量。論文報告 PACE 相較於最強基準提升 **0.65 bps**。換算為經濟規模：若一家基金每年交易 USD 100 billion，可節省約 USD 6.5 million 的執行成本。

從數值來看，0.65 bps 相當於 0.0065%，單筆交易幾乎難以察覺；但對於大型機構投資人而言，由於交易規模龐大且頻繁，這樣的改善具有顯著的經濟價值。不過，也需注意：

- 文中未提供標準差或統計顯著性檢定，因此無法判斷 0.65 bps 的改善是否穩定，抑或來自少數極端樣本。
- 未說明 parent order（母單）的抽樣方式（標的、方向、規模、執行區間長度），這會直接影響結果的外部效度。
- Level-1 資料較粗，可能低估實際市場衝擊與 slippage（滑價）。

##### 行為分析
論文的行為分析是另一亮點，揭示 LLM 與 human investors（人類投資者）的差異：

1. **Model confidence（模型信心度）與績效正相關**：Planner 的信心越高，執行績效越好。這與人類投資人的 overconfidence（過度自信）現象相反——後者常導致較差的投資報酬。
2. **提前交易而非拖延**：Executor 傾向於在執行區間早期完成較多交易，而非像人類那樣拖延至 deadline（截止期限）附近。

這些發現暗示 LLM 在執行決策中可能較少受到情緒、時間壓力或認知偏誤影響。然而，也必須謹慎：LLM 的「信心」是基於文本輸出的機率分佈，與人類主觀信心不同；若 prompt 設計鼓勵早期交易，則可能出現人為誘導的行為模式。

#### 與現有研究的比較

##### 相較於傳統靜態策略
TWAP 與 Almgren-Chriss 等傳統策略依賴 simplifying assumptions（簡化假設），例如固定的日內成交量分布或特定的市場衝擊函數。當 model parameters（模型參數）隨時間漂移，或真實 market behavior（市場行為）偏離假設時，績效會下降。PACE 透過 LLM 的廣泛先驗知識，避免了對 price model（價格模型）的顯式假設，理論上更能適應不同的 market patterns（市場模式）。

##### 相較於基於學習的策略
XGBoost、LSTM 或 reinforcement learning（強化學習）方法需要 task-specific rewards、states 與 actions，並且通常需要針對新任務重新設計與重新訓練。PACE 的優勢在於無需 task-specific training，可透過調整 prompt 快速適應新的 task specifications（任務規格）。這對於金融機構而言極具吸引力，因為可以減少模型維護與重新訓練的成本。

##### 相較於 LLM 在金融的其他應用
既有 LLM 金融研究多集中於財報分析、factor mining（因子挖掘）、投資建議或 trading agents（交易代理人），核心問題是「what to trade」。PACE 首次將 LLM 應用於「how to execute」，填補了 parent-order execution 的研究空白，並提供完整的實驗框架與行為分析。

##### 限制與潛在風險
儘管 PACE 具有創新性，仍存在以下限制：

- **黑箱性**：LLM 的決策過程難以完全解釋，對於需要嚴格風險控管的機構執行系統而言，這是一大挑戰。
- **延遲與成本**：若使用大型商業 API，每次決策都需呼叫模型，可能無法滿足高頻或低延遲執行需求。
- **上下文長度限制**：長執行區間可能產生過長的 market history，超出 LLM 的 context window（上下文視窗）。
- **幻覺與安全性**：LLM 可能產生不合理的交易量或違反風險限制，需要額外的 guardrails（防護機制）。
- **單一市場驗證**：目前僅在 Shenzhen Stock Exchange Level-1 data 上驗證，尚不清楚在其他市場（如美股、期貨、加密貨幣）的泛化能力。

#### 可重現性評估

##### 開源程式碼
論文提供了 GitHub 程式碼倉庫：https://github.com/zaneopen/PACE。這是正向訊號，有助於其他研究者檢視實作細節、重現實驗流程，並在此基礎上進行擴展。

##### 資料集可取得性
Shenzhen Stock Exchange Level-1 data 屬於商業或受管制資料，通常需要授權或付費取得，論文未必能公開釋出原始資料。這會對外部可重現性造成限制：即使程式碼公開，若無法取得相同資料，其他研究者仍難以完全複製數值結果。建議作者提供：

- 資料預處理腳本與特徵說明。
- 若可能，釋出 anonymized sample（匿名化樣本）或公開可取得的替代資料集上的結果。

##### 模型與提示詞
由於 PACE 無 task-specific training，因此不存在「模型權重」釋出問題；但其所使用的 LLM 版本（例如 GPT-4、GPT-3.5、Llama 等）、API 參數（temperature、top-p、max tokens）以及 prompt 設計，對結果影響極大。若論文未詳細披露這些資訊，則：

- 不同 LLM 版本可能導致績效差異。
- LLM 的 stochasticity（隨機性）會使每次實驗結果不同，需使用 deterministic decoding（確定性解碼）或多次取樣報告區間。
- Prompt 的細微改動可能顯著改變行為，影響 reproducibility（可重現性）。

##### 建議
為提升可重現性，作者可考慮：

1. 在論文或補充材料中完整披露 prompt 模板。
2. 明確說明使用的 LLM 版本與 API 參數。
3. 提供 baseline（基準）的實作細節與超參數。
4. 報告多次實驗的標準差與顯著性檢定。
5. 在公開資料集上進行額外驗證，降低對單一私有資料的依賴。

#### 未來研究方向

##### 1. 多資產與投資組合執行
目前的 PACE 聚焦於單一股票的 parent-order execution。未來可擴展至 portfolio execution（投資組合執行），同時考慮多檔股票間的 correlation（相關性）與 cross-asset market impact（跨資產市場衝擊）。

##### 2. 整合 Level-2 與微觀結構資料
使用 Level-2 資料（包含委託簿深度、逐筆成交、掛單取消等）可讓 Executor 更精細地評估流動性與滑價，進一步降低執行成本。

##### 3. 混合式架構：LLM 規劃 + 學習式執行
可將 Planner 維持為 LLM，但將 Executor 替換為輕量化的強化學習或 model-predictive control（模型預測控制）模組，結合 LLM 的先驗知識與學習式控制的數學保證，提升安全性與效率。

##### 4. 線上適應與檢索增強生成
市場 regime（市場狀態）會隨時間改變。可引入 retrieval-augmented generation (RAG)（檢索增強生成），讓模型在決策時檢索相似的歷史執行案例，或透過 in-context learning（情境學習）快速適應新環境。

##### 5. 因果與反事實評估
現有評估多為歷史回測，難以排除 selection bias（選擇偏誤）。未來可建立更嚴謹的 market simulation（市場模擬）與 counterfactual analysis（反事實分析），估計 PACE 對市場價格的真實影響。

##### 6. 信心校準與風險管理
研究如何將 LLM 的 confidence（信心度）轉化為 risk-adjusted（風險調整後）的執行決策，並設計自動 guardrails，例如當信心過低或市場波動過大時，強制回退至 TWAP。

##### 7. 即時部署與延遲最佳化
針對生產環境，研究如何壓縮 prompt、使用較小的專用模型進行 Executor，或透過 caching（快取）與 streaming（串流）技術降低延遲。

##### 8. 跨市場與跨資產類別驗證
在美股、期貨、外匯、加密貨幣等不同市場驗證 PACE，以確認其泛化能力與限制。

##### 9. 人機協作與信任機制
探討 LLM 如何作為 human traders（人類交易員）的輔助工具，而非完全取代。研究人類對 LLM 建議的信任程度、over-reliance（過度依賴）風險，以及如何設計可解釋的決策介面。

##### 10. 理論分析
雖然 PACE 不依賴顯式市場模型，但未來可在特定簡化假設下分析其 regret bound（遺憾界）或收斂性質，為方法提供理論背書。

## 論文問答

**Q1：什麼是母單執行，為什麼它在演算法交易中如此重要？**
A：母單執行是演算法交易中的核心問題，目標是將一筆大額訂單拆分成多筆較小訂單，以降低整體執行成本。由於一次性提交大額訂單容易暴露交易者意圖，導致市場衝擊與較差的成交價格，因此需要透過時間與數量的分配來分散風險。有效的母單執行策略能幫助金融機構在買入時爭取較低價格、賣出時爭取較高價格，直接影響整體交易成本與投資績效。

**Q2：現有的靜態模型與基於學習的策略各自存在哪些主要限制？**
A：現有方法主要分為靜態模型與基於學習的策略兩類，但各自存在明顯限制。靜態模型如 Almgren-Chriss 依賴預設的市場假設，例如固定的日內成交量分布，然而真實市場往往不符合這些簡化條件，且模型參數會隨時間漂移。基於學習的策略雖然資料驅動，卻需要針對特定任務設計獎勵函數、狀態與動作空間，當市場模式或任務規格改變時，策略往往需要重新設計與訓練，適應性明顯不足。

**Q3：將大型語言模型應用於母單執行具有什麼樣的研究與實務意義？**
A：將大型語言模型應用於母單執行，標誌著 LLM 在金融領域的應用從「交易什麼」延伸到「如何執行」的重要轉變。過去相關研究多集中於選股、因子挖掘或文本理解，較少觸及執行層面的決策。母單執行需要處理高雜訊的價格序列與複雜的時間壓力，若 LLM 能在無需任務特定訓練的情況下做出穩健決策，將為金融機構提供更具彈性且可解釋的執行工具。

**Q4：PACE 的核心設計架構是什麼？**
A：PACE（Plan-Ahead Controlled Execution）是一個階層式框架，將母單執行拆解為長期規劃與短期執行兩個階段。Planner 負責根據長期趨勢產生整體的交易計畫，Executor 則根據短期市場波動動態調整每個時點的交易數量。這種設計讓模型能同時掌握價格序列中的長期趨勢與殘差波動，避免直接在高雜訊的原始價格上做出單一層次的決策。

**Q5：相較於傳統方法，PACE 的關鍵創新在哪裡？**
A：PACE 的關鍵創新在於不需要預設市場假設，也不需要針對母單執行任務進行特定訓練。傳統方法必須事先指定價格衝擊模型或成交量分布，而 PACE 利用 LLM 的廣泛先驗知識，在推論階段自適應地生成決策。這使得框架能夠更靈活地應對不同市場環境與任務規格的變化，降低了從一個場景遷移到另一個場景的成本。

**Q6：為什麼 PACE 要將價格序列分解為長期趨勢與短期波動？**
A：股票價格序列同時包含長期趨勢與短期雜訊，直接讓 LLM 處理原始價格會使決策受到隨機波動干擾。透過 HP 濾波將價格分解為長期趨勢與殘差短期波動後，Planner 可以專注於判斷未來的方向性走勢，Executor 則可針對即時價格偏離進行微調。這種分解符合金融時間序列的多時間尺度特性，也讓 LLM 的決策過程更具結構性與可解釋性。

**Q7：實驗使用了哪些資料集與基準策略進行比較？**
A：實驗使用深圳證券交易所 Level-1 資料進行評估，並與多個代表性基準策略比較，包括時間加權平均價格策略 TWAP、傳統執行成本模型 Almgren-Chriss，以及基於學習的 XGBoost 與 LSTM 基準。所有方法在相同的母單設定下進行測試，以確保比較的公平性。這樣的實驗設計能同時檢驗 PACE 相對於靜態規則與資料驅動方法的優勢。

**Q8：實驗的主要結果是什麼？**
A：實驗結果顯示 PACE 優於所有基準策略，相較最強的基準提升了 0.65 基點的執行成本表現。若以每年交易規模達一千億美元的基金來估算，這相當於每年可節省約六百五十萬美元的執行成本。這項結果顯示，即使沒有任務特定訓練，LLM 也能在真實市場資料上產生具有經濟顯著性的成本優勢。

**Q9：行為分析揭示了 LLM 哪些與人類投資者不同的決策模式？**
A：行為分析發現 LLM 的決策模式與人類投資者存在顯著差異。首先，Planner 的信心度越高，執行表現越好，這與人類常見的過度自信反而導致績效下降不同；其次，Executor 傾向於在執行窗口早期進行更多交易，而非像人類那樣拖延到截止期限前才集中下單。這些發現暗示 LLM 可能成為人類交易員的互補工具，協助克服行為偏誤。

**Q10：PACE 適合應用在哪些實務場景？**
A：PACE 可應用於各類需要執行大額訂單的金融機構場景，例如共同基金、避險基金或退休基金在調整投資組合時的買賣執行。由於框架無需針對每個新任務重新訓練，特別適合需要快速上線新策略或應對市場制度變化的機構。此外，對於缺乏大量歷史交易資料的新興市場或新上市股票，PACE 也能利用 LLM 的先驗知識提供合理的執行建議。

**Q11：在實際生產環境中部署 PACE 時需要考慮哪些因素？**
A：在實際部署時，需要考慮推論延遲、API 成本以及模型輸出的穩定性。由於 PACE 在每次決策時都需要呼叫 LLM，高頻或極短執行窗口的場景可能面臨延遲挑戰，因此需要設計快取或分層觸發機制。此外，金融機構應建立風險控管與人工覆核機制，確保模型在極端市場條件下不會產生異常的交易行為。

**Q12：這項研究可能對演算法交易領域帶來什麼影響？**
A：這項研究拓展了 LLM 在金融領域的應用邊界，從資產選擇與文本分析延伸到執行決策層面。它提供了一個無需任務特定訓練的替代範式，可能促使更多研究探索基礎模型在交易執行、風險管理與市場微結構中的應用。長期而言，這類方法可能改變演算法交易系統的開發流程，減少對專門模型訓練的依賴，並提升策略的適應性與可解釋性。

**Q13：PACE 目前有哪些已知的限制？**
A：雖然論文展示了 PACE 的潛力，但仍存在一些限制。首先，實驗僅使用深圳證券交易所 Level-1 資料，尚未驗證框架在其他市場、資產類別或更高頻資料上的泛化能力。其次，LLM 的決策過程雖然可透過信心度與行為模式進行部分解釋，但其內部推理鏈仍具有黑箱特性，對於需要嚴格審計的金融機構而言可能構成挑戰。

**Q14：在哪些市場條件下 PACE 可能表現不佳或失效？**
A：PACE 可能在極端市場事件或流動性急劇枯竭的情況下表現不佳，因為 LLM 的先驗知識主要來自歷史常態市場模式，對於罕見的尾部風險事件可能缺乏足夠反應。此外，若短期價格波動過於劇烈且無明確趨勢，Executor 的微調可能頻繁出錯，導致執行成本上升。在這些情境下，傳統的風險控制機制或人為干預仍然是必要的。

**Q15：未來有哪些值得探索的研究方向？**
A：未來研究可以從多個方向延伸 PACE 的架構。首先，可將框架擴展至多資產組合執行或跨市場場景，考慮資產間的相關性與共同流動性約束。其次，結合強化學習進行微調，或引入回饋機制讓模型從實際執行結果中學習，可能進一步提升長期表現。最後，發展更細緻的可解釋性工具與風險監控指標，將有助於 PACE 在真實交易環境中的安全部署。

## 實務應用指南

### 適用場景

1. **機構投資人大型換倉執行**：當基金、保險或資產管理公司需要在盤中執行數百萬至數億元等值股票買賣時，可用 PACE 將母單拆成多筆子單，降低市場衝擊成本與意圖暴露。
2. **被動與指數追蹤基金的再平衡**：ETF 或指數基金在成分股調整、權重再平衡時，需在有限時間窗口內完成大量交易，PACE 的長期規劃與短期調整機制可協助平滑執行曲線。
3. **券商或自營部門的演算法執行服務**：券商可將 PACE 作為智慧訂單路由（Smart Order Routing）或演算法交易引擎的一環，為機構客戶提供 TWAP、VWAP 之外的 LLM 驅動執行策略。
4. **量化交易團隊的策略下單模組**：在訊號產生後，需要把理論倉位轉換為實際成交時，PACE 可銜接「交易什麼」與「如何執行」，減少訊號到成交的滑價損耗。
5. **研究與模擬環境中的執行行為分析**：學術單位或金融科技實驗室可利用 PACE 探討 LLM 在母單執行中的決策模式，例如信心度與績效、時間壓力下的行為差異。

### 實作前置條件

- **資料**：
  - 即時與歷史 Level-1 行情資料（價格、成交量、五檔或最佳買賣價等）。
  - 母單規格資料：股票代號、買賣方向、執行起訖時間、總量。
  - 建議至少具備數月至數年的日內資料，以便進行回測與 HP 濾波趨勢分解。
- **運算資源**：
  - 可呼叫商用或開源 LLM API（如 GPT-4、Claude、Llama 等）的環境。
  - 低延遲推論部署能力：若用於真實交易，需評估 API 延遲與可用性，必要時採用本地部署或快取機制。
  - 回測與模擬伺服器，可執行大量日內路徑模擬。
- **技能與團隊**：
  - 熟悉演算法交易、執行成本衡量（如 Implementation Shortfall、bps）的量化研究員。
  - 具備 LLM 提示工程與系統整合經驗的 AI 工程師。
  - 了解市場微結構、合規與風控的交易營運人員。

### 實作步驟建議

1. **資料管線建置**
   - 接入深圳證券交易所或其他交易所的 Level-1 行情串流。
   - 清理異常價格、遺失值，並建立標準化的母單與市場歷史輸入格式。

2. **建立 TWAP 基準曲線**
   - 依據母單的執行窗口與總量，產生時間加權平均價格（TWAP）的參考執行曲線，作為 Planner 與 Executor 的對照基礎。

3. **價格序列分解**
   - 使用 HP 濾波（Hodrick-Prescott filter）將股票價格序列拆解為長期趨勢與短期殘差波動，分別餵給長期規劃模組與短期執行模組。

4. **設計 Planner（長期規劃）**
   - 將母單、市場歷史、長期趨勢與 TWAP 曲線編碼為結構化提示。
   - 請 LLM 在執行窗口內產生初步的時間—數量分配計畫，並輸出各時段建議交易量與信心度。

5. **設計 Executor（短期執行）**
   - 以 Planner 的計畫為約束，結合即時短期波動與最新市場資訊，設計短期提示。
   - 請 LLM 在每個短時段決定實際下單量，允許在計畫總量附近微調，但須控制偏離幅度。

6. **回測與模擬**
   - 在歷史資料上模擬成交，採用市場衝擊模型或真實成交價格紀錄。
   - 以 bps 為單位比較 PACE 與 TWAP、Almgren-Chriss、XGBoost、LSTM 等基準的執行成本。

7. **行為分析與提示迭代**
   - 分析 Planner 信心度與實際績效的關係、Executor 是否存在拖延或過早交易傾向。
   - 根據觀察結果調整提示、約束條件與信心度校準機制。

8. **紙上交易與小規模實盤**
   - 先在模擬或紙上交易環境驗證數週至數月。
   - 確認延遲、成本節省與風控指標穩定後，再以小額母單進入實盤。

9. **生產化部署**
   - 將 Planner 與 Executor 封裝為微服務，整合至訂單管理系統（OMS）與執行管理系統（EMS）。
   - 建立監控儀表板，追蹤執行偏差、API 延遲、成本節省與模型行為異常。

### 潛在風險與注意事項

- **幻覺與非結構化輸出**：LLM 可能產生不合邏輯的交易量或格式錯誤。應加入輸出格式約束、JSON Schema 驗證與後處理守門機制，確保總量、時間窗口與買賣方向正確。
- **延遲與可用性**：真實交易對延遲敏感，API 呼叫失敗或回應過慢可能錯失執行時機。建議設計本地備援模型、快取最近計畫，並設定逾時與降級策略（fallback 至 TWAP）。
- **過度擬合歷史模式**：雖然 PACE 不需要任務特定訓練，但提示設計與參數仍可能過度適配回測資料。應採用滾動回測、樣本外驗證與壓力測試。
- **市場噪音干擾**：短期價格波動高度隨機，Executor 可能對雜訊過度反應。可透過波動率門檻、最小交易單位限制與平滑化機制降低頻繁調整。
- **合規與風控**：需確保 LLM 驅動的下單行為符合市場法規、交易所規範與內部風險限額，例如最大單筆下單量、價格區間與市場操縱防範。
- **成本與擴充性**：頻繁呼叫 LLM API 會產生可觀費用。應評估每筆母單的推論成本，並在大量母單場景下考慮模型蒸餾、快取或本地部署。

### 與其他技術的整合建議

- **訂單管理系統（OMS）／執行管理系統（EMS）**：將 PACE 作為演算法策略模組嵌入 OMS/EMS，接收母單後輸出子單時間表，再由 EMS 負責實際下單、拆單與場所選擇。
- **市場資料與行情串流**：整合即時 Level-1 或 Level-2 資料餵給 Executor，並將歷史資料用於 Planner 與回測。
- **強化學習或監督式學習基準**：PACE 可與 XGBoost、LSTM 或強化學習策略並行運作，作為多策略執行引擎中的一個選項，依市場狀況動態切換或加權。
- **風險管理與合規系統**：在 PACE 輸出進入下單管線前，經過風控閘道檢查倉位、價格、成交量與合規限制；異常時自動攔截並通知人工交易員。
- **人機協作介面**：將 Planner 的長期計畫與信心度視覺化，讓交易員可覆寫或暫停執行，特別是在市場劇烈波動或重大新聞事件期間。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先理解母單執行的基本概念，例如為何大額訂單需要拆分、TWAP 與 Almgren-Chriss 的差異，再聚焦 PACE 的兩階段設計——Planner 負責「大方向怎麼分」，Executor 負責「當下怎麼調」。不必深究 HP 濾波數學，重點是體會 LLM 如何從「交易什麼」延伸到「如何執行」。

- **AI 工程師**：請特別關注提示工程、輸出結構化與系統延遲。本文的價值在於將 LLM 應用於高頻決策場景，你需要思考如何將 Planner 與 Executor 封裝成低延遲服務、如何設計 fallback 機制，以及如何驗證模型輸出在金融合規上的安全性。

- **研究人員**：本文開啟了 LLM 在執行成本最佳化領域的系統性研究，建議深入分析行為分析部分，特別是模型信心度與績效的正向關係、以及 LLM 與人類投資者在時間壓力下的行為差異。未來可延伸至多資產、多市場、考慮市場衝擊模型或與強化學習結合的方向。

- **產品經理**：重點評估 PACE 的商業價值與落地風險。0.65 bps 的成本節省在大型機構資金規模下相當可觀，但需同時評估 API 成本、延遲、合規與交易員接受度。建議將 PACE 定位為「輔助人類交易員的智慧執行建議」，而非完全自動下單，以降低導入阻力並建立信任。
