# Jev-Mem：系統一控制的主體記憶，實現高效率 AI 智能體

**原文標題：** Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents  
**作者：** Dongming Jiang、Yi Li、Bingzhe Li  
**發布日期：** 2026-09-21

## ⚡ TL;DR

現有主體記憶系統常以自迴歸大型語言模型控制記憶操作，導致高延遲與推論成本。
本文提出 Jev-Mem，以系統一／系統二架構將輕量記憶控制與審慎推理分離。
於 LoCoMo，Jev-Mem 評分 0.777 提升 11%，建構快 6.6 倍且查詢延遲降 36.7%。

## 摘要翻譯

主體記憶（agentic memory）對於長期 AI 智能體（long-horizon AI agents）日益重要，然而許多現有系統仍仰賴自迴歸大型語言模型（autoregressive LLMs）來控制記憶的組織、檢索與使用方式，使得成本高昂的生成過程成為記憶操作關鍵路徑上的一環。我們提出 Jev-Mem，一種受系統一／系統二認知（System-One/System-Two cognition）啟發的新型主體記憶架構。系統一（System One）體現快速、輕量的決策，而系統二（System Two）則執行較慢、審慎的推理。Jev-Mem 透過專屬的系統一控制平面（System-One control plane）、結構化的多關聯記憶平面（memory plane），以及系統二推理平面（reasoning plane），將此分工機制引入主體記憶。系統一控制器（System-One controller）在建構階段負責記憶類型標記（memory typing）與關聯式組織（relational organization），並在檢索階段動態執行查詢路由（query routing）、檢索預算分配（retrieval-budget allocation）、圖形遍歷（graph traversal）、候選評分（candidate scoring）與適應性停止（adaptive stopping）。系統二僅在複雜推理（complex reasoning）與答案合成（answer synthesis）時才會被觸發。此設計同時提升了記憶有效性與系統效率：在 LoCoMo 資料集上，Jev-Mem 的 LLM 作為評判者（LLM-as-a-Judge）整體分數達到 0.777，相較於最強基線（baseline）有 11.0% 的相對改善幅度（relative improvement）；同時將記憶建構時間（memory construction time）縮短至 158 秒，相較於現有最快的記憶系統有 6.6 倍的加速比（speedup），並將平均查詢延遲（query latency）降至 0.93 秒，降低 36.7%。

### 核心貢獻（3～5點）
- 提出 Jev-Mem，將系統一／系統二認知分工引入主體記憶架構，使快速決策與深度推理各司其職。
- 設計專屬的系統一控制平面，由輕量控制器統籌記憶建構與檢索流程，避免昂貴的 LLM 生成落在記憶操作的關鍵路徑上。
- 在檢索階段動態執行查詢路由、檢索預算分配、圖形遍歷、候選評分與適應性停止，兼顧檢索品質與效率。
- 僅在複雜推理與答案合成時觸發系統二，顯著降低平均查詢延遲與記憶建構時間。
- 在 LoCoMo 基準上同時達成效能提升（LLM-as-a-Judge 分數 0.777，相對改善 11.0%）與效率提升（建構時間 6.6 倍加速、查詢延遲降低 36.7%）。

### 適合對象
本論文適合從事大型語言模型智能體、長期對話系統、記憶架構設計，以及關注 LLM 推論效率與系統最佳化的研究者與工程師閱讀。對於希望降低記憶系統中 LLM 生成成本、同時維持檢索與問答品質的實務開發者尤具參考價值。

## 深度分析

### 方法論解析

Jev-Mem 的核心貢獻在於將 **System-One／System-Two cognition（系統一／系統二認知）** 的雙系統分工引入 **agentic memory（主體記憶）** 的完整生命週期。傳統方法要麼使用固定啟發式（heuristics）進行記憶控制，要麼在記憶建構與檢索的關鍵路徑上反覆呼叫 **autoregressive LLMs（自迴歸大型語言模型）**。Jev-Mem 則提出一個專屬的 **System-One control plane（系統一控制平面）**，把高頻、結構化的決策從昂貴的生成式推理中抽離出來，僅在需要複雜綜合時才啟用 **System-Two reasoning plane（系統二推理平面）**。

#### 三層架構

1. **System-One control plane（系統一控制平面）**  
   由 Jev（TypeSafe AI, 2026）實作，輸出型別化的機率決策（typed probabilistic decisions），無需 **autoregressive generation（自迴歸生成）**。它貫穿記憶的寫入與讀取兩條路徑：
   - **Memory construction（記憶建構）**：負責 **memory typing（記憶類型標記）**、冗餘過濾，以及語意（semantic）、時間（temporal）、因果（causal）、實體（entity）等多種關聯的建構。
   - **Memory retrieval（記憶檢索）**：負責 **query routing（查詢路由）**、**retrieval-budget allocation（檢索預算分配）**、**graph traversal（圖形遍歷）**、**candidate scoring（候選評分）**、證據評估與 **adaptive stopping（適應性停止）**。

2. **Memory plane（記憶平面）**  
   採用 **structured multi-relational memory（結構化多關聯記憶）**，將過往經驗組織成可支援多種關係視角的圖式結構。相較於僅依賴 **semantic similarity（語意相似度）** 的片段式檢索，多關聯組織能同時捕捉事件時序、因果鏈與實體連結，使檢索不再孤立。

3. **Reasoning plane（推理平面）**  
   即 **System Two（系統二）**，保留給 **complex reasoning（複雜推理）** 與 **answer synthesis（答案合成）**。它只在 System-One 完成證據篩選後才被喚起，從而避免在每一次記憶操作中都要執行完整的生成式推理。

#### 寫入路徑的輕量化控制

在寫入階段，觀察（observations）進入系統後，System-One controller（系統一控制器）首先決定該筆記憶的型別，再判斷是否與既有記憶冗餘，並據此建立或更新語意、時間、因果與實體關係。這些決策本質上是結構化、高頻的，適合以輕量分類或機率判斷完成；若交由 LLM 自迴歸生成，則會在記憶持續累積的過程中造成可觀的延遲與推論成本。

#### 讀取路徑的動態檢索流程

在讀取階段，面對使用者查詢 \(q_t\)，System-One 會動態執行以下步驟：
- **Query routing（查詢路由）**：判斷查詢應走哪一條關係路徑（語意、時間、因果或實體）。
- **Retrieval-budget allocation（檢索預算分配）**：決定可投入的檢索資源上限，避免無限制擴張。
- **Graph traversal（圖形遍歷）**：在結構化記憶圖上依選定關係進行搜尋。
- **Candidate scoring（候選評分）**：對遍歷得到的候選記憶打分。
- **Adaptive stopping（適應性停止）**：依據分數分佈或邊際增益決定何時停止搜尋。

這整套流程的關鍵在於：控制決策本身不產生長篇文字，而是以型別化機率輸出完成，因此能顯著降低 **query latency（查詢延遲）**，同時透過結構化記憶與動態預算維持檢索品質。

#### 設計權衡

作者明確提出一個挑戰：讓一個「較弱的推理者」控制記憶，會不會損害下游準確率？Jev-Mem 的解法是將控制決策侷限在結構化、可學習或可先驗定義的型別空間內，並讓 **System Two（系統二）** 專注於它最擅長的證據綜合與答案生成。這樣的分工使得輕量化控制不會取代深度推理，而是為其篩選出高品質的證據子集。

### 實驗數據解讀

論文在 **LoCoMo** 資料集上進行評估，採用 **LLM-as-a-Judge（LLM 作為評判者）** 作為主要評估指標，並同時報告效率指標。

#### 準確率表現

Jev-Mem 的整體 **LLM-as-a-Judge** 分數達到 **0.777**，相較於最強 **baseline（基線）** 提升 **11.0%**。這顯示將記憶控制從 LLM 生成中抽離，並未犧牲答案品質；相反地，結構化的多關聯記憶與動態檢索策略可能減少了雜訊，讓 **System Two（系統二）** 獲得更相關的證據。

#### 效率表現

- **Memory construction time（記憶建構時間）**：158 秒，相較於最快的競爭系統加速 **6.6×**。  
  這說明在寫入路徑上以 System-One 取代反覆的 LLM 生成，能帶來數量級的效率提升。對於需要長期運作的 **long-horizon AI agents（長期 AI 智能體）** 而言，記憶持續累積過程中的建構成本是關鍵瓶頸，Jev-Mem 在此取得顯著優勢。

- **Average query latency（平均查詢延遲）**：0.93 秒，相較於基線降低 **36.7%**。  
  讀取路徑上的 **query routing（查詢路由）**、**adaptive stopping（適應性停止）** 與 **retrieval-budget allocation（檢索預算分配）** 共同減少了不必要的圖形遍歷與 LLM 呼叫，使查詢回應更快。

#### 綜合意涵

實驗結果支持論文的核心主張：**記憶控制（memory control）本身應被視為一層獨立的系統問題**。透過把高頻決策輕量化，Jev-Mem 同時達到最佳準確率與最佳效率，打破了「靈活控制必然昂貴」的取捨。值得注意的是，目前提供的摘要與引言未詳細說明各項 **baseline（基線）** 的具體名稱、LoCoMo 的任務拆分，以及 **LLM-as-a-Judge（LLM 作為評判者）** 的評分維度，因此進一步的細部分析（例如在不同關係型別查詢上的表現）仍有待完整論文釋出。

### 與現有研究的比較

#### 相對於啟發式記憶系統

早期 **agentic memory（主體記憶）** 多採用固定啟發式進行儲存與檢索，例如基於 **semantic similarity（語意相似度）** 的向量召回或簡單的時間衰減。這類方法效率高，但缺乏彈性，難以處理因果、實體或多跳關係。Jev-Mem 透過 **System-One controller（系統一控制器）** 學習或推斷結構化決策，在保持輕量的同時提升了表達能力。

#### 相對於 LLM 控制的記憶系統

近期研究傾向於讓通用 **autoregressive LLMs（自迴歸大型語言模型）** 直接決定記憶的組織、檢索與使用。這類方法靈活，但將昂貴的生成置於記憶操作的關鍵路徑上，導致 **memory construction time（記憶建構時間）** 與 **query latency（查詢延遲）** 居高不下。Jev-Mem 的創新在於把「控制」與「生成」解耦：控制交給輕量的 System-One，生成保留給 System-Two。

#### 相對於知識圖譜與多關聯記憶

已有研究使用知識圖譜或多重圖視角來表示記憶，支援語意、時間、因果與實體關係。Jev-Mem 並非僅提出新的記憶結構，而是進一步提出與之匹配的輕量控制機制，使多關聯記憶在實際系統中可高效運作。換言之，結構化記憶平面與 System-One 控制平面是相輔相成的：沒有輕量控制，豐富的關聯結構會帶來過高的檢索開銷；沒有結構化記憶，輕量控制也缺乏足夠的語義基礎。

#### 限制與潛在弱點

1. **對 Jev 框架的依賴**：System-One 的具體實現仰賴 Jev（TypeSafe AI, 2026）產生型別化機率決策。若 Jev 的型別空間設計不當，可能限制系統泛化能力。
2. **型別與關係的覆蓋範圍**：目前強調語意、時間、因果、實體四類關係，對於更細緻的領域特定關係（例如程式碼中的呼叫關係、科學文獻中的方法論繼承）可能需要額外擴充。
3. **評估範圍**：目前僅在 LoCoMo 上報告結果，尚不清楚其在其他長期互動場景（如程式碼助手、個人助理、多智能體協作）上的泛化性。
4. **System-One 錯誤的累積風險**：輕量控制器若在記憶類型標記或關係建構階段出錯，可能透過圖結構放大影響，需要針對控制決策的校準與容錯機制進行更深入分析。

- **System-Two reasoning plane（系統二推理平面）** 應使用某種 **LLM（大型語言模型）** 進行複雜推理與答案合成，但具體模型版本、參數規模與提示詞設計尚未在提供的片段中說明。

Jev-Mem 的關係型別可擴展至程式碼、科學文獻、醫療記錄等領域，也可納入多模態訊號（影像、音訊、表格）。如何設計領域專用的 **memory typing（記憶類型標記）** 與關係模式，並維持 System-One 的輕量性，是值得探索的方向。

#### 3. 線上與終身學習

長期 AI 智能體需要在互動過程中持續更新記憶。未來可研究如何讓 Jev-Mem 支援線上記憶鞏固（memory consolidation）、遺忘與衝突解決，並避免知識漂移或冗餘累積。

#### 4. 多智能體與共享記憶

將 Jev-Mem 擴展至多智能體場景，讓不同智能體共享或交換結構化記憶，並透過 System-One 控制跨智能體的查詢路由與隱私存取權限，是具潛力的應用。

#### 5. 硬體感知的記憶系統

隨著記憶規模增長，圖形遍歷與向量檢索的延遲會受到儲存與計算硬體限制。未來可結合近似最近鄰搜尋、圖壓縮、快取策略與專用加速器，進一步降低 **query latency（查詢延遲）**。

#### 6. 可解釋性與人機協作

System-One 的型別化決策具有天然的可解釋性。未來可發展視覺化介面，讓使用者理解記憶為何被組織、為何被檢索，並允許人類回饋直接修正記憶結構，形成人機協作的記憶管理迴路。

#### 7. 更廣泛的評估基準

除了 LoCoMo，未來應在更多長期互動基準（如長篇程式碼理解、個人化對話、開放世界任務）上驗證 Jev-Mem，並引入人類評估與多維度指標（如事實正確性、連貫性、時序一致性），以補充 **LLM-as-a-Judge（LLM 作為評判者）** 的單一指標限制。

## 論文問答

**Q1：Jev-Mem 主要想解決主體記憶系統中的什麼問題？**

A：Jev-Mem 針對的是長期 AI 智能體在記憶建構與檢索過程中，過度依賴自迴歸大型語言模型所導致的高延遲與高推論成本問題。現有許多系統將記憶的組織、檢索與使用控制權交給生成式模型，使得昂貴的 token 生成成為記憶操作關鍵路徑上的瓶頸。Jev-Mem 認為這類高頻結構化決策應由輕量級的系統一來處理，而非每次都動用系統二進行審慎推理，從而提升整體效率。

**Q2：為什麼現有的啟發式方法或純 LLM 控制記憶方式會不足？**

A：純粹依賴固定啟發式規則的記憶系統雖然效率較高，但缺乏彈性，難以適應多樣化的語意關係與動態查詢需求。相反地，將所有記憶控制決策都交給自迴歸大型語言模型雖然具備語意彈性，卻會在記憶建構與檢索的每個步驟反覆觸發昂貴的生成運算。這兩種極端都無法同時滿足長期 AI 智能體對記憶有效性與系統效率的雙重要求，因此需要一種新的分工架構。

**Q3：高效率的主體記憶對長期 AI 智能體為何如此重要？**

A：長期 AI 智能體需要在多次互動中持續累積使用者偏好、任務歷史與環境知識，這些資訊很快就會超過固定上下文視窗所能承載的範圍。單純擴大上下文長度並無法解決問題，因為模型無法可靠地利用長輸入中的所有位置，且長期互動場景會帶來額外的索引、檢索與閱讀挑戰。因此，智能體必須具備能夠保存、組織、更新與檢索過往經驗的主體記憶，而記憶操作的效率將直接決定智能體能否即時回應並長期運作。

**Q4：Jev-Mem 的核心架構包含哪些主要組成部分？**

A：Jev-Mem 採用系統一／系統二認知分工，包含三個主要平面：負責快速結構化決策的系統一控制平面、儲存多關聯結構化記憶的記憶平面，以及保留給複雜推理與答案合成的推理平面。系統一控制器在記憶建構階段負責記憶類型標記、冗餘過濾與語意、時間、因果、實體等關係建構；在檢索階段則負責查詢路由、檢索預算分配、圖形遍歷、候選評分與適應性停止。系統二只在需要深度證據整合與最終答案生成時才被呼叫，從而避免在記憶控制的高頻決策中浪費生成能力。

**Q5：Jev-Mem 將系統一與系統二分離的關鍵創新是什麼？**

A：關鍵創新在於將記憶控制本身視為一個獨立的系統層級，並讓輕量級的系統一控制器負責記憶生命週期中的高頻結構化決策。不同於現有系統在記憶建構與檢索過程中反覆呼叫自迴歸大型語言模型，Jev-Mem 透過類型化的機率決策來完成這些控制任務，無需進行 token 生成。這種分工不僅減少了不必要的自迴歸推論，也保留了系統二在複雜綜合與推理上的強大能力，實現有效性與效率的雙重提升。

**Q6：為什麼 Jev-Mem 選擇使用類型化機率決策與多關聯記憶結構？**

A：類型化機率決策能夠在不進行自迴歸生成的情況下，快速產生結構化且可解釋的控制訊號，非常適合記憶類型標記、關係判斷與候選評分等高頻決策。多關聯記憶結構則讓系統能同時表達語意、時間、因果與實體等多種關係，使檢索不再侷限於孤立的語意相似度匹配。這兩項設計相輔相成：豐富的關聯結構為系統一提供了足夠的判斷依據，而輕量的類型化決策則讓複雜記憶結構的控制成本得以降低。

A：Jev-Mem 的效能部分依賴於系統一控制器在類型化決策上的準確度，若該控制器在特定關係類型或領域上訓練不足，可能會影響記憶組織與檢索品質。多關聯記憶結構雖然豐富，但也增加了儲存與維護的複雜度，在極大規模記憶場景中可能需要額外的最佳化。此外，系統一與系統二之間的分工邊界是根據目前任務特性設計的，對於某些高度模糊或需要深度交錯推理的查詢，這種固定分工可能不夠靈活。

**Q14：Jev-Mem 在什麼情況下可能表現不佳或失敗？**

A：當查詢需要跨越多種關係類型進行高度抽象推理，而系統一無法正確判斷檢索方向時，Jev-Mem 可能遺漏關鍵證據。若記憶內容中的關係極為稀疏或充滿雜訊，輕量級的關係建構與評分機制可能難以建立可靠的記憶圖結構。此外，在需要頻繁更新記憶且一致性要求極高的動態環境中，系統一的快速更新決策可能偶爾導致記憶狀態暫時不一致。

A：未來研究可以探索如何讓系統一控制器自動學習或適應不同領域的記憶控制策略，進一步提升其泛化能力。另一個方向是開發更高效的記憶平面儲存與索引技術，以支援更大規模、更長期的記憶累積。此外，研究如何動態調整系統一與系統二之間的分工邊界，讓架構能根據查詢複雜度自動決定何時需要更深度的推理，也是值得深入探討的課題。

## 實務應用指南

### 適用場景

**長期個人助理與生活秘書**
適合需要記住使用者偏好、習慣與長期目標的 AI 助理，例如健康管理、行程安排、購物建議等。Jev-Mem 的系統一控制平面能在每次互動中快速判斷該更新哪類記憶（偏好、事件、任務），並透過多關聯記憶結構在後續對話中快速召回相關脈絡，避免反覆詢問相同資訊。

**企業知識管理與智慧客服**
適合需要長期維護客戶關係、產品知識與處理歷史的 B2B 或 B2C 場景。系統一可在寫入階段自動進行記憶類型標記與關聯式組織，將客戶問題、解決方案、後續追蹤事項建立語意、時間與因果關係；在檢索階段則透過查詢路由與適應性停止快速定位正確知識，降低平均查詢延遲。

**軟體開發協作助手**
適合長期參與專案的 coding assistant，需要記住程式碼風格、設計決策、過往 bug 與重構歷史。Jev-Mem 能將程式碼片段、技術決策、審查意見組織成結構化記憶，並在開發者提問時透過圖形遍歷找到相關的程式脈絡與決策依據，僅在需要複雜推理時才呼叫系統二。

**研究與學術助理**
適合需要長期追蹤文獻、實驗記錄、研究假設與討論過程的場景。多關聯記憶可連結論文、實驗數據、因果推論與實體關係，系統一負責快速檢索預算分配與候選評分，系統二則用於綜合多篇文獻生成研究摘要或假設驗證。

**遊戲與虛擬角色陪伴**
適合需要長期記憶玩家行為、劇情選擇與角色關係的互動式敘事或 NPC。Jev-Mem 能以輕量級決策維持世界觀一致性，並在關鍵劇情點透過系統二進行情感推理與對話生成，兼顧即時回應與深度互動。

### 實作前置條件

**資料準備**
需要長期互動資料，例如多輪對話紀錄、使用者回饋、環境觀察、文件與任務歷史。資料應具備時間戳記與基本語意標註，以便建立時間關係與實體關係。若領域特定（如醫療、法律），建議準備領域本體論（ontology）與關係類型定義，以提升記憶類型標記與關聯式組織的準確度。

**運算資源**
系統一控制平面需要輕量級推論環境，可部署於 CPU 或邊緣裝置，強調低延遲與高吞吐量；系統二推理平面需要自迴歸大型語言模型，建議配置 GPU 資源。記憶平面需同時支援向量檢索（語意相似度）與圖形查詢（關係遍歷），因此需要向量資料庫與圖資料庫，或支援混合查詢的資料庫系統。

**技術能力**
團隊需具備 LLM 部署與微調經驗、向量檢索與圖資料庫設計能力、以及 agent 系統整合經驗。若使用 Jev 框架實作系統一，需熟悉 typed probabilistic decisions 的開發模式；若自行實作，則需具備分類模型、排序模型與強化學習或啟發式控制策略的設計能力。

### 實作步驟建議

**步驟一：定義記憶類型與關係本體論**
先根據應用場景定義記憶類型（如使用者偏好、任務、事件、程序性知識、實體關係）與關係類型（語意、時間、因果、實體）。這是系統一進行記憶類型標記與關聯式組織的基礎，建議從小規模本體論開始，再隨資料累積擴充。

**步驟二：建立系統一控制模型**
針對記憶建構與檢索的各項決策任務，訓練或配置輕量級模型：包括記憶類型分類、冗餘過濾、關係判斷、查詢路由、檢索預算分配、候選評分與適應性停止。可使用 Jev 框架產生 typed probabilistic decisions，或採用輕量分類器與排序模型，避免在控制路徑上引入自迴歸生成。

**步驟三：建構多關聯記憶平面**
選擇合適的儲存後端：向量資料庫負責語意相似度檢索，圖資料庫負責關係遍歷。設計記憶節點與邊的結構，確保系統一能快速寫入與讀取。實作記憶更新機制，包括新增、合併、過期與冗餘消除，避免記憶圖無限制膨脹。

**步驟四：設計檢索控制流程**
實作查詢路由邏輯，根據查詢類型決定使用語意檢索、圖形遍歷或混合策略。設計動態檢索預算分配與候選評分機制，讓系統一在檢索過程中持續評估是否已收集足夠證據，並觸發適應性停止條件，避免過度檢索。

**步驟五：整合系統二推理**
將系統二定位為複雜推理與答案合成元件，僅在系統一判斷需要深度推理、證據綜合或生成最終回應時呼叫。設計清晰的介面，讓系統二接收系統一篩選後的相關證據，減少無效上下文並降低推理成本。

**步驟六：評估與迭代**
使用 LLM-as-a-Judge 與延遲指標進行端到端評估，參考 LoCoMo 等長篇對話基準設計內部測試集。持續監控系統一決策錯誤案例，特別是錯誤的記憶類型標記、遺漏關鍵關係或過早停止檢索，並據此調整控制模型與記憶結構。

### 潛在風險與注意事項

**系統一錯誤決策的傳導效應**
系統一雖然輕量，但一旦在記憶類型標記、關係建立或查詢路由上出錯，錯誤會沿著記憶建構與檢索流程放大。建議保留可解釋的決策分數與備援路徑，例如當系統一信心度低於門檻時，自動降級為保守策略或交由系統二處理。

**記憶圖過度膨脹與雜訊累積**
長期運作下，記憶節點與邊的數量可能快速成長，導致檢索效率下降與雜訊增加。需定期執行記憶合併、去重與過期清理，並為系統一設計檢索預算上限與適應性停止條件，避免圖形遍歷無限擴散。

**關係品質依賴領域知識**
多關聯記憶的效果高度依賴關係抽取與分類的準確度。在開放領域中，因果與時間關係容易出錯。建議在領域本體論明確的場景先落地，並結合少量人工標註或規則進行關係驗證，再逐步擴展到開放領域。

**延遲與準確度的權衡**
雖然 Jev-Mem 強調效率，但過度壓縮系統一的檢索預算或過早停止可能犧牲答案品質。建議透過 A/B 測試與線上指標監控，針對不同查詢類型設定差異化的停止條件與預算配置，而非採用單一全域參數。

**隱私與資料安全**
長期記憶會累積敏感個人資訊與企業機密。需實作分級存取控制、記憶去識別化、加密儲存與審計日誌。特別是當記憶需要在雲端與邊緣裝置之間同步時，應評估資料駐留與合規要求。

### 與其他技術的整合建議

**與現有 RAG 系統整合**
Jev-Mem 可視為 RAG 的進階控制層，負責動態檢索預算分配與多關聯證據組織。可保留現有向量檢索管道作為語意檢索後端，並在上方加入系統一控制平面與圖形遍歷模組，逐步替換原本依賴自迴歸 LLM 的檢索決策。

**與向量資料庫整合**
使用現有向量資料庫（如 Milvus、Pinecone、Weaviate、Qdrant）儲存記憶節點的語意嵌入，支援快速語意相似度檢索。系統一可根據查詢路由決定是否啟動向量檢索，並動態調整 top-k 與檢索預算。

**與圖資料庫整合**
使用圖資料庫（如 Neo4j、Amazon Neptune、Dgraph）儲存記憶之間的語意、時間、因果與實體關係。系統一在圖形遍歷過程中可快速評估候選節點，並利用圖結構進行多跳推理前的路徑篩選。

**與 Agent 框架整合**
可將 Jev-Mem 作為 LangChain、LlamaIndex、AutoGen 等框架的長期記憶模組。系統一負責記憶讀寫控制，系統二則作為 agent 的推理核心。這種整合能讓現有 agent 獲得長期記憶能力，同時降低每次互動的 LLM 呼叫成本。

**與監控與評估工具整合**
建立針對系統一決策品質與系統二輸出品質的監控儀表板，追蹤記憶建構時間、平均查詢延遲、檢索停止率、候選評分分佈與 LLM-as-a-Judge 分數。透過持續監控，可及早發現記憶漂移或控制模型退化。

### 給不同背景讀者的閱讀建議

**給初學者**
這篇論文提出了一種讓 AI 更「省腦」地管理長期記憶的方法。你可以把系統一想成快速直覺，系統二想成深思熟慮；Jev-Mem 讓大多數記憶管理工作由快速直覺完成，只在真正需要時才動用深思熟慮。閱讀時建議先理解圖一的工作流程與三個平面的分工，再回頭看實驗結果，不需要一開始就深入每個技術細節。

**給 AI 工程師**
論文核心貢獻在於將記憶控制從自迴歸生成中抽離，形成獨立的系統一控制平面。建議重點關注記憶建構與檢索的決策拆解、Jev 框架如何產生 typed probabilistic decisions、以及多關聯記憶平面的實作權衡。實作時可優先評估哪些現有 pipeline 中的 LLM 呼叫可以被系統一替代，並設計明確的 fallback 機制。

**給研究人員**
Jev-Mem 提供了一個值得延伸的研究架構：雙系統認知理論在 agentic memory 中的具體化、輕量級控制器的錯誤傳導分析、以及多關聯記憶結構對檢索效率與推理品質的影響。建議關注論文中對系統一與系統二分工的論證，並思考如何將此架構擴展到多模態記憶、持續學習與記憶遺忘機制等方向。

**給產品經理**
這項技術適合需要長期互動、對延遲敏感且希望降低推理成本的 AI 產品。重點在於它同時提升了準確度與效率，而非傳統的取捨。評估落地時，建議先盤點產品中哪些場景累積了大量互動歷史、目前檢索延遲是否影響使用者體驗、以及現有 LLM 成本是否過高。可從單一長期場景（如個人助理或企業客服）開始試點，再擴展到其他產品線。
