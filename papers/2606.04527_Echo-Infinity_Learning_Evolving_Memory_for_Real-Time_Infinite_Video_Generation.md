## ⚡ TL;DR

現有自迴歸影片生成受限於無界KV快取記憶體與時間RoPE外推溢位，難以實現長時程即時串流。
提出Echo-Infinity，以可學習查詢動態壓縮任意歷史，並以統一相對RoPE解決訓測外推差距。
在長短影片基準達到最佳表現，並首次實現超過24小時、逾130萬幀的即時無限生成。

## 摘要翻譯

我們提出 Echo-Infinity，一個邁向即時無限影片生成（real-time infinite video generation）的自迴歸（Autoregressive, AR）框架，其採用可學習的演化記憶（Evolving Memory），能以恆定成本動態過濾、抽象化並壓縮任意長度的歷史資訊。現有方法主要透過預定義KV快取排程（predefined KV-cache schedules）、固定比例啟發式壓縮（fixed-ratio heuristic compression），或推論時RoPE適應（inference-time RoPE adaptation）來管理記憶。這些設計因快取視窗有限，且忽略了自迴歸生成雜訊，不可避免地遺失歷史資訊並放大複合誤差（compounding error）。受人類記憶鞏固（memory consolidation）啟發，Echo-Infinity 以可學習的記憶查詢（Memory Query）取代手工設計的記憶管理；當過去幀從局部視窗（local window）中被驅逐時，這些查詢透過注意力與門控機制（gating mechanism）進行更新。這些查詢與影片擴散轉換器（Diffusion Transformers, DiTs）進行端對端（end-to-end）最佳化，形成演化記憶，能以恆定計算量支援任意壓縮比，且與影片長度無關。它們亦作為可泛化的生成先驗（generation prior），即使僅使用最佳化後的初始狀態，亦能提升生成品質。我們進一步提出統一相對RoPE方案（Unified Relative RoPE Recipe），將錨點幀（sink frames）固定於編號 0，並使最新幀編號在訓練與推論全程中最多增長至 DiTs 的預訓練最大時間RoPE編號（pretrained maximum temporal RoPE id），使模型擺脫有限 RoPE 的限制，並彌合訓練-測試RoPE外推差距（train-test RoPE extrapolation gap）。在長影片與短影片生成方面，Echo-Infinity 達到最先進的效能，且據我們所知，首次展現了具前景的 24 小時（>130 萬幀）即時連續生成（rollouts），為無限影片生成指出一條實際可行的道路。

### 核心貢獻（3～5點）
- 提出可學習的演化記憶（Evolving Memory）機制：以記憶查詢（Memory Query）取代手工設計的 KV 快取管理，當過去幀離開局部視窗時，透過注意力與門控機制動態更新，實現與影片長度無關的恆定計算成本與任意壓縮比。
- 端對端（End-to-end）聯合最佳化：記憶查詢與擴散轉換器（DiTs）共同訓練，最佳化後的記憶狀態本身即為可泛化的生成先驗（generation prior），即使僅使用初始狀態亦能提升後續生成品質。
- 統一相對RoPE方案（Unified Relative RoPE Recipe）：將錨點幀（sink frames）固定於相對編號 0，並限制最新幀編號不超過預訓練最大時間RoPE編號，徹底消除訓練-測試RoPE外推差距（train-test RoPE extrapolation gap），使模型擺脫有限 RoPE 的長度限制。
- 實現即時無限影片生成（real-time infinite video generation）：在長短影片生成皆達最先進水準，並首次展示 24 小時（>130 萬幀）即時連續生成（rollouts）的可行性。

### 適合對象
從事影片生成、自迴歸（Autoregressive）模型、擴散轉換器（DiTs）與長時序序列建模之研究者與工程師；亦特別適合關注即時串流推論、記憶體效率與無限長內容生成之學術與產業界人士。

## 深度分析

#### 方法論解析

Echo-Infinity 是一個針對 real-time infinite video generation（即時無限影片生成）的 Autoregressive (AR, 自迴歸) 框架，其核心在於以可學習的 Evolving Memory（演化記憶）取代傳統手工設計的歷史管理策略，並透過 Unified Relative RoPE Recipe（統一相對RoPE方案）解決長時序列的位置編碼瓶頸。

在記憶體機制上，現有 AR Video Diffusion Transformers (DiTs, 擴散轉換器) 面臨兩大結構性限制：其一為 unbounded history KV caches（無界歷史KV快取）導致記憶體隨影片長度線性增長；其二為 temporal RoPE（時間性RoPE）的 frame id（幀編號）超出 pretrained maximum temporal RoPE id（預訓練最大時間RoPE編號）時引發 degradation and overflow（退化與溢位）。Echo-Infinity 的解法是引入一組可學習的 Memory Query（記憶查詢），作為固定容量的長期記憶狀態，與 Local window（局部視窗）內的 KV-cache（KV快取）以及 Sink frames（錨點幀）共同運作。當歷史幀被 evict 出局部視窗時，這些 Memory Query 並非被動丟棄資訊，而是主動透過 cross-attention（交叉注意力）機制從被逐出的 KV 狀態中提取與未來生成相關的特徵，再經由 sigmoid-gated residual（Sigmoid門控殘差）控制新舊記憶的融合比例。此設計對應認知神經科學中的 memory consolidation（記憶鞏固）三階段——filtering（過濾）、abstraction（抽象化）與 compression（壓縮）——將任意長度的歷史壓縮為一個 compact evolving state（緊湊演化狀態），並以「history echo（歷史迴響）」的形式為後續生成提供先驗。由於 Memory Query 的數量與維度固定，其計算成本與影片長度無關，實現了真正的 fixed-capacity memory（固定容量記憶）。更重要的是，這些查詢與 DiT 進行 end-to-end（端對端）聯合優化，使記憶內容直接服務於生成目標，而非依賴獨立的重建或壓縮損失。

在位置編碼方面，論文指出僅在推論階段進行 inference-time RoPE adaptation（推論時RoPE適應）無法根治 train-test RoPE extrapolation gap（訓練-測試RoPE外推差距）。為此提出的 Unified Relative RoPE Recipe（統一相對RoPE方案）在訓練與推論時採用一致的相對位置排程：將 Sink frames（錨點幀）固定於 frame id 0，讓最新幀的 id 成長至上限 f_max 後，將整段歷史向後旋轉（rotate backward），確保所有 active temporal RoPE id 恆處於預訓練範圍內。此舉從根本上消除了絕對位置編碼的溢位風險，並關閉了訓練與測試之間的外推間隙。

#### 實驗數據解讀

論文在長影片（30 s、60 s、240 s）與短影片（5 s）benchmarks 上進行評估，並宣稱達到整體 state-of-the-art (SOTA) 表現。其中最引人注目的極限實驗是在單張 NVIDIA H100 上完成 24 小時（>1.3 M frames）的 real-time rollouts，穩定維持 18.5 FPS。這不僅是量級上的突破，更具工程指標意義：相較無記憶基線，Evolving Memory 僅造成 10.6% throughput overhead，驗證了 constant cost 設計在實際硬體上的可行性。

與基線模型的對比同樣具有說服力。LongLive 在 absolute RoPE 限制下，生成 4.25 分鐘後即出現嚴重退化並發生 RoPE overflow（RoPE溢位）；即使為其配備推論階段的 relative RoPE（記為 LongLive*），其一致性仍因 unresolved train-test RoPE extrapolation 與有限的長期記憶而持續下降。Echo-Infinity 則同時解決了記憶體與位置編碼問題，實現 day-scale 的穩定輸出。

另一項值得深究的發現是 Memory Query（記憶查詢）作為 generation prior（生成先驗）的泛化性。在短影片生成實驗中，即使手動關閉記憶更新機制、僅使用優化後的 initial state，模型品質仍獲提升。這暗示 Memory Query 在訓練過程中學到的並非單純的歷史緩存，而是一種可泛化的影片分佈先驗，對於資源受限的部署場景具有實用價值。需注意的是，提供的上下文未揭露 FVD、IS 等客觀指標的絕對數值，論文將詳細數據歸於 §4.2–§4.4，因此當前解讀側重於架構與趨勢層面的分析。

#### 與現有研究的比較

現有長影片生成方法在記憶管理上可歸為三類，Echo-Infinity 與其存在本質差異：

1. **Window Truncation（視窗截斷）**：如部分 AR 串流方法僅保留局部視窗與少數 sink frames，雖控制記憶體，但必然丟棄遠端歷史，導致長期敘事一致性斷裂。
2. **Hand-Crafted KV-cache Management（手工設計KV快取管理）**：例如 MemFlow [21] 透過文字檢索規則決定保留哪些被逐出的 KVs。這類方法受固定快取預算束縛，且離線調參無法適應生成過程中的動態內容變化，更忽略 AR 生成中隨時間累積的 compounding error（複合誤差）。
3. **Heuristic Compression（啟發式壓縮）**：以預定義比例或獨立目標將歷史壓縮為緊湊表徵，但壓縮策略並非針對最終生成品質進行 end-to-end 優化，彈性與表達力均受限。

Echo-Infinity 的關鍵突破在於以可學習的 Memory Query 取代 handcrafted memory curation，使 filtering（過濾）、abstraction（抽象化）與 compression（壓縮）成為資料驅動的優化目標，支援 arbitrary compression ratios 且計算複雜度與影片長度脫鉤。相較於 concurrent methods [25, 40] 僅在推論時調整 RoPE，Unified Relative RoPE Recipe（統一相對RoPE方案）從訓練源頭消除 train-test mismatch，這是長時穩定生成的必要條件。

然而，從現有脈絡也可推論其潛在局限：首先，Memory Query 與特定 pretrained DiT 聯合優化，其跨架構或跨權重的遷移性尚未驗證；其次，Memory Query 的容量與數量屬於超參數，雖為固定成本，但仍需在細節保留度與計算開銷間權衡；最後，「無限」生成在理論上仍受浮點數精度與硬體壽命限制，24 小時的實驗雖具里程碑意義，但距離真正意義上的任意長度生成尚有距離。

#### 可重現性評估

根據提供的全文脈絡，作者並未明確提及原始碼、訓練資料集或模型權重（model weights）是否公開釋出，這對社群復現構成不確定性。不過，論文仍提供了若干關鍵的復現線索：硬體上採用單張 NVIDIA H100；效能上達成 18.5 FPS 與僅 10.6% throughput overhead；方法上詳細描述了 Memory Query 的更新邏輯與 Unified Relative RoPE Recipe 的排程規則。

目前欠缺的資訊包括：具體採用的資料集名稱（如 OpenVid-1M、InternVid 或自建資料）、Memory Query 的初始化策略、學習率與訓練步數等超參數、以及與 DiT 聯合微調時的凍結範圍。此外，§4.2–§4.4 雖宣稱包含詳細 benchmarks，但當前上下文未列出客觀指標的計算方式與資料集劃分。整體而言，在作者釋出程式碼、模型檢查點（checkpoints）及完整訓練配方（training recipe）之前，外部研究者僅能依據架構描述進行近似復現。

#### 未來研究方向

1. **階層式記憶擴展**：當前設計採用單一層級的 Memory Query，未來可借鑑更深層的 memory consolidation（記憶鞏固）理論，設計多層級或階層式記憶結構，分別處理不同時間粒度的事件（如秒級動作 vs. 小時級敘事），進一步提升超長影片的語義連貫性。
2. **多模態與互動式生成**：將 Evolving Memory（演化記憶）擴展至音訊、文字指令或使用者互動訊號，強化 interactive video generation（互動式影片生成）中的長期一致性，並探索跨模態的記憶對齊問題。
3. **理論極限與可解釋性**：量化分析 Memory Query 的資訊瓶頸（information bottleneck），建立 compression ratio 與生成品質的理論邊界；同時透過可視化或探針技術解析 Memory Query 實際編碼了哪些歷史語義（如場景佈局、物體運動趨勢）。
4. **邊緣裝置與效率優化**：進一步壓低 10.6% throughput overhead，或設計輕量化 Memory Query，使 real-time infinite video generation 可部署於記憶體與頻寬受限的邊緣裝置（edge devices）。
5. **跨模型泛化與即插即用**：驗證優化後的 initial Memory Query state 是否可遷移至不同預訓練權重或架構變體的 DiT，作為通用型的長影片生成外掛模組。
6. **跨領域應用**：將 constant-cost evolving memory 框架應用於其他長序列 AR 生成任務，例如長時音樂生成、3D 場景串流、或具身智慧（embodied AI）中的長期決策記憶，驗證其作為通用長程記憶機制的普適性。

## 論文問答

**Q1：現有的自迴歸影片擴散轉換器（AR DiTs）在朝向即時無限影片生成時，主要面臨哪兩個核心瓶頸？**
A：第一個瓶頸是無界歷史鍵值（KV）快取所導致的記憶體成本急遽上升，這使得隨影片長度增加，記憶體消耗變得難以負擔。第二個瓶頸是時間性旋轉位置編碼（RoPE）的索引會超出模型預訓練時所見的最大範圍，進而引發效能退化與數值溢位。這兩個問題共同限制了現有方法在長時間範圍內維持即時串流與高品質生成的能力。

**Q2：現有的記憶體管理策略（如視窗截斷與啟發式壓縮）為何無法有效保存長影片生成的歷史資訊？**
A：視窗截斷法僅保留有限的局部視窗與少數錨點幀，導致超出範圍的遠端歷史被直接丟棄，造成不可逆的資訊遺失。手工設計的KV快取管理雖然嘗試依據離線規則保留部分被驅逐的KV，但其固定預算無法適應動態內容，且忽略了自迴歸生成中固有的複合誤差。啟發式壓縮則多依賴預定義的壓縮比例或獨立目標，而非端對端學習出固定容量的最佳記憶表示，因此難以達成有效的歷史抽象化。

**Q3：本文為何從人類記憶鞏固（memory consolidation）中汲取靈感，這個類比如何具體指導Echo-Infinity的設計？**
A：認知神經科學指出人類記憶具有階層性，新鮮感知先進入工作緩衝區，再經過選擇性過濾、抽象化與壓縮，形成緊湊的長期儲存。這意味著長時程生成並不需要保存每一個過去的token，而是依賴一個精簡且不斷演化的狀態來維持關鍵資訊。受此啟發，Echo-Infinity以可學習的記憶查詢（Memory Queries）取代手工設計的記憶管理，透過交叉注意力與門控機制模擬過濾、抽象與壓縮的過程，實現與影片長度無關的常數計算成本。

**Q4：Echo-Infinity的核心演化記憶機制是什麼，當幀被驅逐出局部視窗時，記憶查詢（Memory Queries）是如何被更新的？**
A：核心機制是一組與預訓練DiT聯合優化的可學習記憶查詢，它們作為緊湊的長期記憶狀態，與局部KV快取及錨點幀並存。當過去幀被驅逐出局部視窗時，這些查詢會先對被驅逐的KV快取執行交叉注意力更新，以萃取與生成相關的資訊；隨後透過sigmoid門控殘差來控制記憶覆寫的程度。此設計讓模型能夠動態地過濾、抽象化並壓縮任意長度的歷史，且計算成本恆定不變。

**Q5：統一相對RoPE方案（Unified Relative RoPE Recipe）與現有僅在推論時調整RoPE的方法有何根本差異？為何這對無限影片生成至關重要？**
A：現有方法多在訓練時使用絕對RoPE，僅在推論階段透過旋轉舊快取來適應位置編碼，導致訓練與測試之間始終存在外推差距。統一相對RoPE方案則在訓練與推論時採用相同的邊界相對RoPE排程：將錨點幀固定於編號0，讓最新幀的編號最多成長至預訓練最大值，超出後便將較舊幀向後旋轉。這種一致性消除了訓練與測試的RoPE外推落差，從根本上避免了溢位問題，使模型能穩定生成極長影片。

**Q6：為何Echo-Infinity在記憶更新過程中採用sigmoid門控殘差與交叉注意力？這兩者在設計上各自扮演什麼角色？**
A：交叉注意力讓記憶查詢能主動關注被驅逐的KV快取，從帶有自迴歸雜訊的歷史中蒸餾出對未來生成有用的資訊。Sigmoid門控殘差則作為一種可學習的保護機制，精細控制新資訊對既有記憶狀態的覆寫比例，避免災難性遺忘。兩者協同運作，使演化記憶既能穩定保留長期脈絡，又能彈性地適應新進內容，達成類似人類記憶鞏固的選擇性更新。

**Q7：Echo-Infinity在哪些影片生成基準上進行了評估，評估重點涵蓋哪些面向？**
A：該框架在長影片基準（30秒、60秒與240秒）以及短影片基準（約5秒）上進行了全面評估。評估重點包括生成品質、時間一致性，以及模型在極長時間範圍下維持內容連貫性的能力。此外，研究也測量了即時串流的吞吐量與記憶體效率，以驗證其在實際部署場景中的可行性。

**Q8：Echo-Infinity在長時程影片生成中取得了哪些最關鍵的量化與質性成果？**

A：雖然固定容量設計確保了計算成本的恆定性，但對於極度複雜或高度動態的場景，有限數量的記憶token可能無法完整保存所有細節事件的豐富資訊。當畫面發生劇烈且快速的視覺變化時，抽象化過程可能會遺失對未來連貫性至關重要的細微特徵。因此，在面對極端複雜的長篇內容時，記憶查詢的容量可能需要進一步擴展，或結合階層式儲存結構來彌補這一理論上限。

**Q14：儘管具備演化記憶，Echo-Infinity在哪些情況下仍可能出現複合誤差或時間不一致的問題？**
A：雖然演化記憶透過過濾與抽象化減輕了誤差累積，但自迴歸生成本質上仍會在數百萬幀的過程中逐漸放大細微雜訊，記憶查詢最終可能傳播這些潛在的不一致性。若交叉注意力機制在幀驅逐過程中未能有效區分關鍵訊號與生成雜訊，錯誤資訊便可能被鞏固到長期記憶狀態中。此外，儘管RoPE方案防止了溢位，但對於訓練資料中極少出現的劇烈運動或場景轉換，模型仍可能難以維持完全的時間穩定性。

A：未來研究可探索階層式記憶架構，透過多層抽象在維持常數計算成本的同時處理更豐富的歷史脈絡。另一方向是發展依據場景複雜度動態調整容量的自適應記憶機制，或整合音訊、文字等多模態條件以強化互動式應用中的記憶查詢。此外，進一步降低現有的吞吐量開銷，並將框架擴展至更高解析度或三維時空生成，將是邁向完全實用化無限影片系統的重要途徑。

## 實務應用指南

### 適用場景

1. **24/7 即時監控與異常事件模擬**：利用即時無限影片生成能力，為智慧安防系統生成無限長的「正常情境」基線影片，當實際畫面偏離生成預測時觸發異常警報，降低儲存與傳輸真實監控畫面的成本。
2. **永續直播與數位人頻道**：打造無中斷的 AI 主播或虛擬偶像直播，透過演化記憶維持角色一致性、服裝細節與場景連貫性，無需人工介入即可連續串流數小時甚至數天。
3. **開放世界遊戲與互動敘事**：在遊戲引擎中作為即時過場動畫生成器，根據玩家行為動態產生無限延伸的劇情動畫，解決傳統預錄影片重複性高與分支成本昂貴的問題。
4. **長時程科學視覺化**：用於氣象模擬、細胞活動或天文現象的長時間視覺化，以固定記憶成本生成超高幀數的科學影片，輔助研究人員觀察長期趨勢與微觀變化。
5. **廣告與電商動態素材自動化**：根據產品敘述自動生成無限循環或長時程情境影片（如服飾動態展示、家居場景晝夜變化），降低拍攝與後製成本，並透過記憶查詢維持品牌視覺一致性。

### 實作前置條件

- **資料**：需要高品質、長時序的影片資料集進行微調（fine-tuning），建議至少數百小時目標領域影片（如監控、遊戲或直播場景），並搭配精確的時間戳與文字敘述標註。若僅使用預訓練模型進行推論，則需準備與訓練分佈相近的提示詞庫。
- **運算**：至少單張 NVIDIA H100（或同級 GPU）用於訓練與推論；若需 24 小時即時生成，需確保硬體穩定供電與散熱。雖然 Echo-Infinity 將歷史成本壓為常數，但仍需足夠 VRAM 載入預訓練擴散轉換器（DiT）骨干、局部 KV 快取與可學習的記憶查詢。
- **技術能力**：團隊需熟悉 DiT 架構、自迴歸生成流程、KV 快取管理，以及具備 PyTorch 的分散式訓練經驗。此外，需理解旋轉位置編碼（RoPE）與相對位置編碼的實作細節，以便正確部署統一相對 RoPE 方案，並能除錯長時序生成的複合誤差問題。

### 實作步驟建議

1. **環境建置與模型準備**：取得預訓練的因果影片 DiT 檢查點（checkpoint），確認其預訓練最大時間 RoPE 編號（pretrained maximum temporal RoPE id），作為後續統一相對 RoPE 方案的邊界條件。
2. **記憶查詢模組植入**：在現有 DiT 框架中嵌入可學習的記憶查詢（Memory Query）層，設計交叉注意力機制與 Sigmoid 門控殘差連接，確保當幀被逐出局部視窗時能正確觸發更新，實現過濾、抽象化與壓縮。
3. **統一相對 RoPE 方案實作**：將錨點幀（sink frames）固定於編號 0，並實作動態旋轉邏輯：當最新幀編號達到預訓練上限時，將舊幀向後旋轉，確保訓練與推論階段所有作用中時間編號均落在預訓練範圍內，消除訓練-測試 RoPE 外推差距。
4. **端對端微調**：在目標領域資料上進行聯合訓練，同時優化 DiT 參數與記憶查詢。建議先以較短影片（如 30–60 秒）驗證記憶鞏固效果與生成品質，再逐步拉長至數分鐘甚至數小時，觀察固定容量記憶的穩定性。
5. **推論服務化**：將訓練完成的模型封裝為即時串流服務，設定局部視窗大小與記憶查詢更新頻率。監控吞吐量（目標維持 18.5 FPS 以上）與記憶體佔用，確保長時間運行的穩定性，並建立自動重啟與檢查點儲存機制。
6. **品質與一致性驗證**：建立長時程評估指標（如角色一致性、場景漂移度、複合誤差累積率），定期抽樣檢查超過 1 小時的生成結果，必要時調整門控機制的閾值或增加錨點幀頻率。

### 潛在風險與注意事項

- **複合誤差累積**：自迴歸生成的雜訊會隨時間放大，即使記憶查詢能過濾歷史，仍可能出現細微的場景或物理規則漂移。建議定期插入「錨定幀」、使用者回饋迴路或結合外部檢索機制進行校正。
- **訓練-測試 RoPE 外推差距**：若未嚴格遵循統一相對 RoPE 方案，推論時仍可能發生位置編碼溢位或效能衰退。務必在訓練階段就模擬長時序的旋轉行為，而非僅在推論時補救。
- **領域適配挑戰**：預訓練 DiT 的視覺先驗可能與目標領域（如監控畫面或遊戲引擎輸出）存在分佈差異。微調資料不足時，記憶查詢可能學到錯誤的歷史抽象，導致生成品質快速劣化。
- **固定容量記憶的資訊瓶頸**：雖然記憶查詢提供常數成本，但若目標任務需要精確回憶遙遠過去的細節（如特定文字或微小物體），過度壓縮可能導致資訊遺失。可透過增加查詢數量或搭配輕量級外部向量資料庫緩解。
- **硬體長時運行風險**：24 小時不間斷生成對 GPU 與散熱系統負荷極大，需建立自動容錯與檢查點儲存機制，避免記憶體洩漏或驅動程式異常導致服務中斷。

### 與其他技術的整合建議

- **與遊戲引擎整合**：可將 Echo-Infinity 作為 Unreal Engine 或 Unity 的即時渲染外掛，接收引擎輸出的深度圖或語意遮罩作為條件輸入，生成高擬真過場動畫，並透過記憶查詢維持跨場景敘事連貫性。
- **與多模態大型語言模型（MLLM）整合**：利用 MLLM 即時分析生成畫面並產生下一秒的敘事提示詞（prompt），形成「生成→理解→再生成」的閉環，適用於互動式直播或開放世界遊戲劇情推進。
- **與向量資料庫 / RAG 整合**：對於需要精確事實一致性（如特定產品外觀、角色服裝細節）的商業應用，可將關鍵幀特徵額外儲存於向量資料庫，在記憶查詢更新時進行檢索增強，彌補固定容量記憶的細節損失。
- **與現有串流架構整合**：透過將模型封裝為 gRPC/REST API 或 WebRTC 串流節點，可無縫接入現有 CDN 與直播平台。建議在前端加入緩衝區（buffer）以平滑 18.5 FPS 生成與顯示幀率之間的差異。
