# NeoHorse-1：透過路由執行框架（Routing Harness）進行智能體後訓練，邁向遞迴自我改進

## ⚡ TL;DR

本文解決遞迴自我改進缺乏機制的問題，透過智慧路由執行框架觀察能力需求並將互動證據轉化為下一輪訓練。
NeoHorse-1結合異質模型池與路由框架，以能力引導課程微調和同策略蒸餾閉合評估選擇更新迴路。
後訓練使4B與9B宏觀平均分別從58.94、65.60提升至64.87、69.04，縮小兩者差距。

## 摘要翻譯

遞迴自我改進（Recursive Self-Improvement, RSI）需要一個具體機制，使 AI 系統得以觀察自身能力，並將這些證據轉化為下一輪學習的依據。本研究提出 NeoHorse-1，一系列原生智能體模型（Agent-Native Models），透過智能體後訓練（Agentic Post-Training）探索此一路徑。本系統結合異質模型池（Heterogeneous Model Pool）與智慧路由（Intelligent Routing），在每個使用者回合記錄預測能力需求（Predicted Capability Demand）、選定的服務層級（Selected Service Tier）與後續互動（Subsequent Interaction）。這些記錄被轉換為訓練範例（Training Examples），保留交錯推理（Interleaved Reasoning）、工具呼叫（Tool Calls）與執行框架上下文（Harness Context），並經結構驗證（Structural Validation）、六維語意評估（Six-Dimensional Semantic Evaluation）與子場景層級標註（Subscene-Level Labeling）後才納入訓練。路由訊號（Routing Signals）將監督式微調（Supervised Fine-Tuning, SFT）組織為三階段課程（Three-Stage Curriculum），並延伸至路由引導之同策略蒸餾（Routing-Guided On-Policy Distillation），由教師模型（Teacher）在相同的三階段進程下監督學生模型（Student）所生成的回應。隨後，能力引導分配（Capability-Guided Allocation）將評估回饋（Evaluation Feedback）轉化為下一個訓練混合資料（Training Mixture），形成評估–選擇–更新迴路（Evaluation-Selection-Update Loop）：系統學會執行什麼，決定了它下一輪將從何學習。在涵蓋基於執行框架的智能體（Harness-Based Agents）、工具使用（Tool Use）、程式編寫（Coding）與指令遵循（Instruction Following）的十一項基準測試上，後訓練使 4B 級別模型的宏觀平均（Macro-Average）從 58.94 提升至 64.87，9B 級別模型從 65.60 提升至 69.04，大幅縮小了後訓練 4B 模型與 9B 基礎模型（Base Model）之間的整體差距。NeoHorse-1 為這一回饋驅動流程（Feedback-Driven Process）提供了初步原型，也為在連續迭代（Successive Iterations）中實現由執行框架中介的遞迴自我改進（Harness-Mediated RSI）提供了一條途徑。

### 核心貢獻（3～5點）
- 提出結合異質模型池（Heterogeneous Model Pool）與智慧路由（Intelligent Routing）的路由執行框架（Routing Harness），於每個使用者回合記錄預測能力需求、選定服務層級與後續互動，作為可訓練的結構化資料來源。
- 設計多層次資料篩選機制，透過結構驗證、六維語意評估與子場景層級標註，確保自生成經驗（Self-Generated Experience）的品質與可用性。
- 以路由訊號（Routing Signals）將監督式微調（SFT）組織為三階段課程（Three-Stage Curriculum），並延伸至路由引導之同策略蒸餾（Routing-Guided On-Policy Distillation），使教師模型能依相同進程監督學生模型生成的回應。
- 建立評估–選擇–更新迴路（Evaluation-Selection-Update Loop），透過能力引導分配（Capability-Guided Allocation）將評估回饋轉化為下一個訓練混合資料，讓模型所學會的能力決定下一輪學習內容。
- 在十一項涵蓋基於執行框架的智能體、工具使用、程式編寫與指令遵循的基準測試上驗證，後訓練顯著提升 4B 與 9B 級別模型的宏觀平均表現，並縮小後訓練 4B 模型與 9B 基礎模型之間的差距。

### 適合對象
對大型語言模型後訓練、智能體系統（Agent Systems）、遞迴自我改進（RSI）及模型路由（Model Routing）有興趣的研究人員與工程師；特別適合關注如何透過資料飛輪（Data Flywheel）與執行框架（Harness）實現模型自我迭代改進的進階讀者。

## 深度分析

#### 方法論解析

NeoHorse-1 把遞迴自我改進（Recursive Self-Improvement, RSI）從抽象願景轉化為一個可執行的「執行框架（harness）中介之資料–訓練–評估迴路」。整個方法圍繞五個環節展開：**異質模型池（heterogeneous model pool）**、**路由執行框架（routing harness）**、**軌跡資料工程（trajectory data engineering）**、**路由引導之課程式監督式微調（routing-guided curriculum SFT）**，以及**路由引導之同策略蒸餾（routing-guided on-policy distillation, OPD）**。最後透過**能力引導分配（capability-guided allocation）**把評估回饋（evaluation feedback）重新注入下一輪訓練混合資料（training mixture），形成論文所稱的**評估–選擇–更新迴路（evaluation-selection-update loop）**。

**1. 異質模型池與路由執行框架**

系統並非仰賴單一模型，而是維護一個由不同能力與成本層級模型組成的**異質模型池（heterogeneous model pool）**，並透過**智慧路由（intelligent routing）**在每次使用者回合（user turn）根據**預測能力需求（predicted capability demand）**與當前**互動狀態（interaction state）**選擇適當的**服務層級（service tier）**。執行框架負責管理上下文、工具與環境互動，文中特別提到 OpenSquilla 等多個 harness。路由決策會留下結構化記錄：預測需求、實際選定的服務層級，以及後續互動（subsequent interaction）。這些記錄不只是日誌，而是後續訓練的組織訊號。

**2. 軌跡資料工程：從互動到訓練範例**

傳統智能體訓練常把軌跡（trajectory）切成獨立的（提示，回應）對，但 NeoHorse-1 強調保留**執行框架上下文（harness context）**。每個使用者回合被轉換成訓練範例（training example），內含交錯推理（interleaved reasoning）、**工具呼叫（tool calls）**與可見回應，讓模型學習在真實執行條件下產生連貫行為。為了避免低品質軌跡污染訓練，資料須通過**結構驗證（structural validation）**、**六維語意評估（six-dimensional semantic evaluation）**與**子場景層級標註（subscene-level labeling）**。這三道過濾暗示作者對資料品質有細粒度控管，雖然六個維度的具體定義在提供的摘要中尚未揭露。

**3. 路由引導之三階段課程式 SFT**

由於不同互動所需能力差異極大，NeoHorse-1 利用路由訊號（routing signals）把 SFT 資料組織成**三階段課程（three-stage curriculum）**：初期以較低能力需求、較易模仿的樣本為主，後期逐步引入高能力需求樣本，同時保留低分樣本的覆蓋率以避免災難性遺忘。這種由路由分數驅動的排序，相當於把「任務難度」與「模型當前能力」進行動態匹配。

**4. 路由引導之同策略蒸餾（OPD）**

SFT 的缺點在於訓練時看到的是固定教師軌跡，部署時卻是學生自己生成的 prefix。NeoHorse-1 將同樣的三階段課程延伸到 OPD：先讓學生模型（student）在 harness 中生成回應，再由教師模型（teacher）對學生已造訪的狀態提供 token-level 監督。這樣的**同策略蒸餾（on-policy distillation）**能縮小訓練與推論分佈差距，並讓課程隨學生行為演化。

**5. 能力引導分配：閉合 RSI 迴路**

最後，模型在評估後的表現被轉換成下一輪訓練混合資料的配比。這是整篇論文的核心機制：**能力引導分配（capability-guided allocation）**把「模型現在會什麼、不會什麼」變成「下一輪要學什麼」。更新後的模型再回到 harness 執行，產生新的互動軌跡與路由記錄，於是形成「所學決定所學」的遞迴結構。

#### 實驗數據解讀

論文在十一項基準測試上進行評估，涵蓋**基於執行框架的智能體（harness-based agents）**、**工具使用（tool use）**、**程式編寫（coding）**與**指令遵循（instruction following）**。整體結果以**宏觀平均（macro-average）**呈現：

- **4B 級別（4B track）**：基礎模型（base model）58.94 → NeoHorse-1-4B 64.87，提升約 5.93 分。
- **9B 級別（9B track）**：基礎模型 65.60 → NeoHorse-1-9B 69.04，提升約 3.44 分。

這兩組數字有幾層意義。首先，後訓練（post-training）在較小的 4B 模型上帶來更大幅度的相對增益，使 NeoHorse-1-4B 的宏觀平均（64.87）幾乎追平 9B 基礎模型（65.60），原本兩者差距約 6.66 分，後訓練後縮小到約 0.73 分。這顯示路由引導的智能體後訓練能有效把「執行經驗」蒸餾進較小參數量模型，對邊緣部署或成本敏感場景特別有價值。

其次，9B 模型雖然絕對分數更高，但增益幅度較小，可能原因包括：（1）基礎能力已較強，剩餘可壓縮的錯誤空間變小；（2）目前這一輪後訓練仍屬單次迭代，尚未進入真正的多輪遞迴；（3）部分基準可能已接近飽和，宏觀平均會稀釋單項進步。

圖 1 的六項**智能體基準測試（agentic benchmarks）**——VitaBench、PinchBench、WorkBuddy、QwenClaw、BFCL V4、t²-Bench——顯示 NeoHorse-1-4B 與 NeoHorse-1-9B 在多數項目中領先同級對照模型。這與文中「最大增益出現在基於執行框架與高執行負載的評估」一致，說明方法特別擅長把 harness 執行經驗轉化為模型內部能力。

不過，解讀時也應注意：**宏觀平均（macro-average）**會掩蓋單項波動；若某些非智能體基準（例如純指令遵循）進步有限，整體數字仍可能好看。此外，文中未提供標準差或多次訓練變異，難以判斷增益穩定性。最後，由於這是「初始原型（initial prototype）」，實驗本質上仍是單輪後訓練，而非嚴格意義上的多代 RSI。

#### 與現有研究的比較

NeoHorse-1 的方法定位處於多條研究線的交會點，並在幾個關鍵點上做出延伸。

**相對於軌跡式 SFT**

FireAct、AgentTuning、Agent-FLAN、AgentBank 與 Llama3 等研究已證明互動軌跡（interaction trajectories）是有效的監督來源。NeoHorse-1 的差異在於：（1）不僅模仿固定教師軌跡，而是透過路由訊號組織課程；（2）把 harness 上下文保留在訓練範例中，讓模型學習「在特定執行條件下該如何反應」；（3）進一步以 OPD 彌補 SFT 的訓練–推論差距。

**相對於同策略蒸餾（OPD）**

OPD 本身並非新概念，其核心價值在於學生生成狀態上的密集過程監督。NeoHorse-1 的貢獻是將 OPD 與**路由訊號（routing signals）**結合，使蒸餾過程也遵循由易到難的課程，而非均勻抽樣學生軌跡。

**相對於執行框架設計**

SWE-agent、Terminal-Lego、AgentLightning v1.0 與 Co-Harness 等研究強調 harness 設計對後訓練的影響。NeoHorse-1 採用多 harness（含 OpenSquilla）並引入路由，使單一模型能從多個執行環境與多個模型行為中學習。這比單一 harness、單一教師的設定更能產生多樣經驗。

**相對於 LLM 路由**

FrugalGPT、RouteLLM 等路由研究主要目標是成本–品質權衡。NeoHorse-1 則把路由從「推論時的模型選擇機制」提升為「訓練時的資料組織與能力評估機制」，這是方法論上的重要轉向。

**相對於智能體強化學習（Agentic RL）**

Search-R1、ReTool、RAGEN 等研究利用可執行環境回饋進行強化學習。NeoHorse-1 目前仍停留在 SFT 與 OPD，尚未引入以環境獎勵為導向的 RL。這既是限制，也是未來可擴展的空間：一旦把路由訊號與可執行獎勵結合，可能進一步提升長期規劃與錯誤修復能力。

**主要限制**

- 單輪迭代：雖然論文標題強調 RSI，目前實驗仍是「一次後訓練」，尚未展示多輪 compounding 增益。
- 教師依賴：OPD 與路由都需要更強的教師模型或模型池，系統改進上限部分受制於教師品質。
- 評估粒度：宏觀平均難以進行細粒度信用分配（credit assignment），無法直接指出哪些子能力真正被改善。
- 安全與對齊：RSI 相關研究必須面對能力快速增長的風險，但摘要與引言尚未討論 oversight、reward hacking 或對齊機制。

#### 可重現性評估

就現有文本而言，NeoHorse-1 的**可重現性（reproducibility）**處於中等偏低水準。論文為技術報告形式，提供了方法架構與高階數據，但尚未明確說明是否釋出以下關鍵資產：

- 基礎模型（base model）的確切架構與檢查點；
- 異質模型池（heterogeneous model pool）的組成與權重；
- OpenSquilla 等執行框架（harness）的設定檔與工具定義；
- 原始互動軌跡（interaction trajectories）與過濾後的訓練範例；
- 三階段課程（three-stage curriculum）的切分標準與路由分數門檻；
- 同策略蒸餾（OPD）中教師模型提供的 logits 與超參數；
- 六維語意評估（six-dimensional semantic evaluation）的具體維度與評分 prompt；
- 十一項基準測試的評估腳本與版本資訊。

在缺乏上述材料的情況下，其他研究者難以完整重現 58.94→64.87 與 65.60→69.04 的數字，也難以驗證路由訊號與課程設計的貢獻。若作者後續釋出模型權重、資料子集與訓練腳本，可重現性將大幅提升；但由於系統涉及多模型協作與動態執行環境，即使開源，重現門檻仍高於一般單一模型 SFT。

#### 未來研究方向

NeoHorse-1 作為「由執行框架中介的 RSI（harness-mediated RSI）」初始原型，開啟了幾條值得追蹤的研究路徑：

**1. 多輪遞迴驗證**

最優先的後續工作是進行連續迭代（successive iterations），觀察宏觀平均是否持續上升、收斂或飽和。這將決定「評估–選擇–更新迴路」是否真能產生複利效應，而非僅是單次資料增強。

**2. 與強化學習的結合**

把路由引導之同策略蒸餾（routing-guided OPD）擴展為路由引導之 RL，利用可執行任務（executable tasks）的環境回饋進行細粒度獎勵設計，特別是針對長期規劃與多步工具使用。

**3. 執行框架與模型共同演化**

參考 Co-Harness 思路，讓 harness 本身也根據模型失敗模式進行更新，例如自動新增工具、調整上下文視窗策略或改進錯誤回傳格式，形成「模型–harness」雙軌 RSI。

**4. 自動化能力評估與路由策略學習**

目前路由訊號似乎由既有模型或啟發式產生。未來可研究讓路由器（router）本身透過元學習（meta-learning）或線上回饋持續優化，並把能力需求預測變成可解釋的結構化輸出。

**5. 細粒度過程監督**

在子場景層級標註（subscene-level labeling）基礎上，建立過程獎勵模型（process reward model），對交錯推理（interleaved reasoning）中的每一步進行信用分配，而不只是對最終回應打分。

**6. 安全、對齊與可控性**

RSI 一旦運作，能力成長速度可能超過人類監督。未來需引入能力評估閘門、紅隊測試、獎勵駭客防禦與價值對齊機制，確保遞迴改進不會偏離設計目標。

**7. 規模與多模態擴展**

驗證方法在更大參數量（例如 30B+）以及多模態智能體（視覺、程式碼、網頁操作）上的效果，並探討路由課程是否隨模型規模改變而需要重新設計。

**8. 開放科學基礎建設**

釋出標準化的 RSI 追蹤協議、資料飛輪（data flywheel）工具與公開基準，讓社群能夠獨立驗證遞迴自我改進是否真正發生，並比較不同方法的穩定性與安全性。

## 論文問答

**Q1：什麼是遞迴自我改進（RSI），為什麼它難以實現？**
A：遞迴自我改進是指 AI 系統在自身改進過程中扮演越來越重要的角色，使單次的訓練努力能夠轉化為持續複利的進步。其困難之處在於，系統必須具備一個具體機制來觀察自己的能力，並把這些觀察證據轉化為下一輪學習訊號。若缺乏這樣的回饋迴路，改進仍將高度依賴人工整理的資料與人類監督，難以規模化與自動化。

**Q2：為什麼智能體（agent）被視為實現 RSI 的自然載體？**
A：智能體在撰寫程式、調查問題或操作軟體時，會留下決策、工具互動與任務結果的完整軌跡。這些互動軌跡不僅是可學習的經驗，也同時呈現了模型的強項與弱點，正好提供 RSI 所需的回饋證據。透過執行框架（harness）的中介，這些記錄能夠被系統化地轉換為訓練資料，從而連結執行與學習。

**Q3：現有的軌跡監督式微調與蒸餾方法存在哪些不足，促使 NeoHorse-1 提出新架構？**
A：傳統軌跡 SFT 主要是模仿固定的教師策略，但部署時模型面對的是自己生成的前綴，導致訓練與推論之間的分布偏移。雖然同策略蒸餾（OPD）讓學生在自身生成的狀態上接受教師指導，卻仍未系統性地利用能力需求訊號來組織學習內容。NeoHorse-1 因此引入路由訊號與能力引導分配，把評估回饋納入資料選擇，形成評估–選擇–更新閉環。

**Q4：NeoHorse-1 的核心方法由哪些元件組成？**
A：核心方法是「路由引導的智能體後訓練」，結合異質模型池、智慧路由與多個執行框架（如 OpenSquilla），針對每輪使用者互動記錄預測能力需求、選定服務層級與後續互動。這些記錄被轉換成保留交錯推理、工具呼叫與執行框架上下文的訓練範例，並經結構驗證、六維語意評估與子場景標註後納入訓練。路由訊號進一步將監督式微調組織為三階段課程，並延伸至路由引導的同策略蒸餾。

**Q5：路由執行框架（Routing Harness）在 NeoHorse-1 中的關鍵創新是什麼？**
A：關鍵創新在於把執行層從單純的運行環境轉變為資料飛輪與學習訊號的來源。路由記錄同時包含能力需求估計、實際選用的模型層級與互動結果，使訓練資料能夠按難度與執行條件被有系統地組織。此外，框架能調用異質模型池的經驗，並將這些多模型互動轉化為單一模型的能力成長。

**Q6：為什麼要同時採用三階段課程 SFT 與路由引導的同策略蒸餾？**
A：三階段課程 SFT 能依據路由分數由易到難地安排訓練資料，並保留低分覆蓋以避免遺漏基本能力。然而 SFT 仍學習自記錄的助手回應，與部署時學生自己生成前綴的狀況存在差距；同策略蒸餾則讓學生生成回應並由教師在相同狀態上提供 token 級監督，縮小這段分布差距。兩者相輔相成，把路由系統中多樣的執行經驗內化為統一模型的穩定能力。

**Q7：實驗使用了哪些基準測試，它們評估哪些能力？**
A：實驗涵蓋十一項基準，包括 VitaBench、PinchBench、WorkBuddy、QwenClaw、BFCL V4、t²-Bench 等基於執行框架的智能體測試，以及程式編寫、工具使用、指令遵循與互動任務。這些測試共同評估模型在真實世界環境中規劃、呼叫工具、執行程式與遵循複雜指令的能力。透過跨領域評估，作者能觀察後訓練對不同能力維度的影響。

**Q8：NeoHorse-1 的主要量化結果是什麼？**
A：在 4B 級別，後訓練將宏觀平均分數從 58.94 提升至 64.87；在 9B 級別則從 65.60 提升至 69.04。最大的進展出現在基於執行框架與執行密集的評估上，顯示路由引導的智能體訓練對實際操作能力特別有效。此外，經後訓練的 4B 模型大幅縮小了與 9B 基礎模型之間的整體差距，展現了後訓練在較小規模上的潛力。

**Q9：文中是否提供消融實驗？我們可以從設計中推論什麼？**
A：提供的摘要與引言並未詳細報告個別元件的消融實驗，而是強調整個評估–選擇–更新迴路的協同效果。從設計選擇可以推論，三階段課程旨在處理智能體互動在能力需求上的高度異質性，而同策略蒸餾則針對固定軌跡監督與部署行為之間的分布偏移。未來研究可能需要獨立驗證路由訊號定義、課程階段數量與模型池組成對最終表現的貢獻。

**Q10：NeoHorse-1 可應用於哪些實際場景？**
A：它適合需要持續與外部工具、程式碼或環境互動的智能體應用，例如軟體工程助手、自動化研究助理、客戶支援機器人與資料分析管線。智慧路由能根據任務難度選擇適當的服務層級，在成本與品質之間取得平衡。持續的回饋驅動流程也讓系統能隨著新任務與新環境逐步調整，減少對人工整理資料的依賴。

**Q11：在產品化部署異質模型池與路由執行框架時，需要考慮哪些問題？**
A：首先需要穩定且可擴展的執行框架來管理上下文、工具與環境互動，並確保安全性與錯誤處理。其次，路由決策會影響延遲與推論成本，因此需要監控能力需求預測的準確性與服務層級選擇的效益。最後，自生成訓練資料的品質控制至關重要，必須透過結構驗證與語意評估避免錯誤或偏差的軌跡進入下一輪訓練。

**Q12：這項研究對智能體 AI 與遞迴自我改進領域可能帶來什麼影響？**
A：NeoHorse-1 提供了一個由執行框架中介的 RSI 初步原型，證明可以把執行記錄、評估回饋與模型更新串接成閉環。它整合了 LLM 路由、課程學習與同策略蒸餾等多條研究線，展示了如何從多模型互動中提煉單一模型的能力。這為未來開發能夠自我觀察、自我選擇學習資料並持續改進的智能體系統奠定了方法基礎。

**Q13：作者承認了哪些限制？**
A：作者明確指出 NeoHorse-1 只是一個初步原型，目前展示的是單次或有限輪次的後訓練流程，而非已經實現長期自主的遞迴自我改進。隨著模型能力演進，這些增益是否能持續仍屬未知，需要更多連續迭代與更廣泛任務設定的驗證。因此，這份報告定位為探索性研究，而非已成熟的 RSI 系統。

**Q14：可能出現哪些失效案例或風險？**
A：如果路由對能力需求的預測失準，可能把過於困難的任務分配給較弱的模型，產生低品質軌跡並污染訓練資料。自生成經驗也可能放大既有錯誤或幻覺，使模型在後續迭代中愈學愈偏。此外，過度適應特定執行框架格式或工具介面，可能削弱模型在其他環境中的泛化能力。

**Q15：未來有哪些研究方向？**
A：未來可以將這個回饋驅動流程擴展到更多連續迭代與更廣泛的真實世界任務，並研究增益是否會隨模型能力演進而持續。也可以引入更強的環境回饋與獎勵訊號，例如可執行任務的成敗訊號，進一步強化學習迴路。此外，自動化改進執行框架本身、擴大異質模型池規模，以及探索模型協助 AI 研究的更高階 RSI 形式，都是值得深入的方向。

### 適用場景

1. **企業級多工具智能助理**  
   在需要同時操作內部知識庫、API、程式碼直譯器與協作軟體的場景中，NeoHorse-1 的路由執行框架可依據每輪對話的預測能力需求，自動選擇適當的服務層級模型，並把互動軌跡轉為下一輪訓練資料，持續提升任務完成率。

2. **軟體開發與維運代理（DevOps / Coding Agent）**  
   適用於自動化除錯、測試生成、部署腳本撰寫等可執行任務。透過執行框架記錄工具呼叫、環境回饋與最終結果，系統能針對程式編寫與工具使用能力進行課程式監督式微調與同策略蒸餾。

3. **客戶服務與問題排查系統**  
   面對查詢難度差異大的客服場景，路由機制可將簡單問題導向較小模型、複雜問題導向較強模型，並依據後續互動結果更新訓練混合資料，讓單一模型逐步吸收多層級的處理經驗。

4. **研究與資料分析自動化**  
   適合需要多步驟檢索、資料轉換、圖表生成與報告撰寫的知識工作。互動過程中的交錯推理與工具呼叫可被保留為訓練範例，並透過六維語意評估與子場景層級標註篩選高品質資料。

5. **多模型協作平台**  
   當組織已部署異質模型池（例如不同規模的開源模型、專有模型與第三方 API）時，NeoHorse-1 提供一個統一框架，把多模型執行經驗蒸餾到單一原生智能體模型中，降低長期推論成本並提升一致性。

**資料條件**
- 必須能夠記錄並回放每輪使用者互動，包含：預測能力需求、選定的服務層級、歷史對話、執行框架上下文、工具呼叫、觀察結果與最終回應。

- 建議具備結構驗證與語意評估的管線，能從原始軌跡中篩選合格範例並進行子場景層級標註。

**運算條件**
- 至少需支援 4B 至 9B 規模模型的微調與推論資源；若要走完論文中的兩個規模，建議配備多張高記憶體 GPU。

**技能條件**
- 熟悉大型語言模型後訓練流程，包括監督式微調、蒸餾、資料篩選與課程學習。
- 具備智能體執行框架開發或整合經驗，能管理上下文、工具註冊與環境互動。
- 需要資料工程與評估工程能力，以建立評估–選擇–更新迴路與能力引導分配機制。

### 實作步驟建議

1. **建構可記錄的路由執行框架**  
   部署一個能夠根據預測能力需求選擇模型的 Harness，並確保每輪互動都記錄：請求、路由分數、選定模型、工具呼叫、觀察結果與最終回應。可從 OpenSquilla 等現有框架開始擴充。

2. **建立異質模型池與服務層級**  
   依能力與成本將可用模型分為多個服務層級。初期可混合強教師模型與較小的學生模型，讓路由機制在真實流量中學習分配策略。

3. **收集並結構化互動軌跡**  
   將執行框架產生的原始軌跡轉換為以「使用者輪次」為單位的訓練範例，保留歷史上下文與執行框架上下文，使交錯推理、工具呼叫與可見回應不被拆散。

4. **執行結構驗證與語意篩選**  
   對訓練範例進行結構驗證，並透過六維語意評估與子場景層級標註過濾低品質或不可學的範例，確保進入訓練的資料具有一致性。

5. **設計三階段課程式監督式微調**  
   使用路由訊號將資料依能力需求排序，分階段引入較高難度的範例，同時保留低難度資料的覆蓋率，避免模型遺忘基本指令遵循能力。

6. **引入路由引導之同策略蒸餾**  
   讓學生模型在部署狀態下生成回應前綴，再由教師模型對這些學生生成的回應提供 token 層級監督，並沿用相同的三階段課程安排。

7. **建立評估–選擇–更新迴路**  
   在固定基準測試（涵蓋智能體、工具使用、程式編寫與指令遵循）上評估模型，將評估回饋轉換為下一輪訓練混合資料的能力引導分配，形成閉環迭代。

8. **持續部署與監控**  
   將更新後的模型重新掛回路由執行框架，監控其在新流量中的強弱項分布，並把新產生的互動軌跡再次餵入資料飛輪。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **資料品質惡化** | 自生成經驗可能包含錯誤推理或失敗軌跡，若未經篩選會污染訓練分布。 | 強制執行結構驗證、六維語意評估與子場景層級標註；僅採用可驗證成功的軌跡或經教師確認的範例。 |
| **能力遺忘** | 過度聚焦智能體任務可能削弱基礎指令遵循與一般語言能力。 | 在訓練混合資料中保留通用指令遵循與基礎推理資料，並定期在廣泛基準上評估。 |
| **分布偏移加劇** | 同策略蒸餾若未妥善引導，學生可能強化自身錯誤行為。 | 使用強教師模型提供密集過程監督，並在每一階段課程後進行能力驗證。 |
| **評估回饋延遲** | 真實世界任務的成功標記可能難以即時取得，導致迴路週期過長。 | 設計輕量代理指標（例如工具呼叫成功率、編譯通過率）作為早期訊號，再與最終任務指標結合。 |
| **安全與濫用** | 智能體可執行外部工具，錯誤路由或越權呼叫可能造成實際損害。 | 在沙箱環境中執行工具、設定權限邊界、對高風險操作加入人工核准或二次確認。 |
| **過度擬合基準** | 若訓練混合資料過度依賴少數評估任務，模型可能只在特定基準上表現好。 | 維持多樣化的真實世界任務來源，並使用保留測試集與線上 A/B 測試交叉驗證。 |

### 與其他技術的整合建議

- **與現有 LLM 路由系統整合**  
  若已使用 FrugalGPT、RouteLLM 等成本感知路由，可把其路由分數作為 NeoHorse-1 預測能力需求的輸入特徵之一，並將 NeoHorse-1 更新後的模型重新註冊為路由池中的可選服務層級。

- **與強化學習管線整合**  
  論文聚焦監督式微調與蒸餾，但未來可把執行框架產生的環境回饋（例如測試通過、任務完成）轉為獎勵訊號，與 Agentic RL、ReTool 等方法結合，進一步優化長期互動策略。

- **與可觀測性平台整合**  
  將路由記錄、能力需求分數與互動軌跡匯入可觀測性系統，可視化模型在不同任務類型上的強弱分布，並自動觸發資料重新採樣或模型再訓練。

- **與企業知識庫及 API 閘道整合**  
  把執行框架掛接在現有 API 閘道之後，讓 NeoHorse-1 透過標準化工具介面存取企業內部資料；同時利用現有身分驗證與授權機制控管工具呼叫權限。

- **與持續整合／持續部署（CI/CD）整合**  
  對程式編寫與維運場景，可將智能體執行框架嵌入 CI/CD 流程，讓模型在每次提交後自動產生測試、執行驗證，並把結果回饋到訓練混合資料中。

  請仔細閱讀資料飛輪、結構驗證、三階段課程與路由引導之同策略蒸餾的實作細節，並評估自身推論與訓練基礎建設是否足以支撐學生生成與教師監督同時進行。建議把論文方法視為一個可擴充的後訓練管線藍圖，而非即開即用的產品。

**研究人員**  
  本研究提供了一個「由執行框架中介的遞迴自我改進」原型，值得關注的是評估–選擇–更新迴路與能力引導分配如何形塑訓練分布。可進一步探討：當模型能力持續提升時，路由訊號是否會失效？自生成資料的品質保證與收斂條件為何？以及與強化學習、自動化 AI 研究的銜接點。

**產品經理**  
  本論文仍處於研究原型階段，但已展示 4B 與 9B 模型在智能體基準測試上的具體提升。建議將其視為「資料飛輪驅動的模型迭代」參考架構，評估在哪些高價值、可驗證的任務場景中，可以先用現有模型池與執行框架建立最小可行迴路，再逐步擴大到完整的能力引導分配與同策略蒸餾流程。
