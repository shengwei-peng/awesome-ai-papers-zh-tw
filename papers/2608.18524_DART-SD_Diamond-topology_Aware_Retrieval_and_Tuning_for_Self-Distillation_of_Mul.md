# DART-SD：多輪工具呼叫代理的鑽石拓撲感知檢索與自我蒸餾微調

**原文標題：** DART-SD: Diamond-topology Aware Retrieval and Tuning for Self-Distillation of Multi-Turn Tool-Calling Agents

## ⚡ TL;DR

現有多輪工具呼叫訓練強制模仿完整軌跡，導致順序無關子目標的鑽石拓撲崩塌，錯誤懲罰有效探索。
DART-SD 以互動狀態轉移圖捕捉鑽石拓撲，定位關鍵斷點檢索成功參考，僅監督恢復步驟。
於五個複雜多輪工具呼叫基準上，DART-SD 顯著優於全軌跡與強化學習基線，並減少冗餘呼叫。

## 摘要翻譯

使大型語言模型（Large Language Models, LLMs）具備多輪工具呼叫（multi-turn tool-calling）能力，對於建構自主代理（autonomous agents）至關重要。然而，相關進展根本上受限於對全長軌跡模仿（full-length trajectory imitation）的依賴。對於涉及多個順序無關子目標（order-independent sub-goals）的任務，其最佳解空間形成一個龐大的組合式鑽石晶格（combinatorial diamond lattice）。將此豐富拓撲強制納入單體式軌跡，會導致嚴重的拓撲崩塌（topological collapse），不加區別地懲罰有效的替代探索，並嚴重削弱策略多樣性（policy diversity）。為解決此問題，我們提出 DART-SD（Diamond-topology Aware Retrieval and Tuning for Self-Distillation，鑽石拓撲感知檢索與自我蒸餾微調），一個新穎框架，將典範從全域強制（global forcing）轉移至拓撲引導的局部修正（topology-guided localized correction）。DART-SD 首先將執行過程建模為一個收斂的互動狀態轉移圖（Interaction-State Transition Graph, ISTG），忠實捕捉成功與失敗探索路徑所固有的鑽石拓撲（diamond topology）。在自主 Rollout（autonomous rollouts）過程中，該框架識別關鍵拓撲斷點（Critical Topological Breakpoint, CTB），並檢索成功軌跡支援的恢復參考（success-supported recovery references）。最後，我們透過 CTB 引導的局部監督（CTB-guided localized supervision），引入一種漸進式自我蒸餾典範（progressive self-distillation paradigm），確保訓練損失（training loss）僅在生成的恢復步驟（generated recovery steps）上計算，同時嚴格保護有效推理前綴（valid reasoning prefix）免受破壞性梯度更新（destructive gradient updates）。在複雜多輪工具呼叫基準測試（benchmarks）上的實驗顯示，DART-SD 顯著優於傳統的全軌跡基線（full trajectory baselines）。

### 核心貢獻（3～5點）
- 診斷全長軌跡模仿（full-length trajectory imitation）的根本限制：在涉及多個順序無關子目標（order-independent sub-goals）的任務中，最佳解空間形成組合式鑽石晶格（combinatorial diamond lattice），強制將其壓入單體式軌跡會造成拓撲崩塌（topological collapse）並嚴重削弱策略多樣性（policy diversity）。
- 提出以收斂的互動狀態轉移圖（Interaction-State Transition Graph, ISTG）建模執行過程，忠實捕捉成功與失敗探索路徑中的鑽石拓撲（diamond topology）。
- 在自主 Rollout（autonomous rollouts）中識別關鍵拓撲斷點（Critical Topological Breakpoint, CTB），並檢索成功軌跡支援的恢復參考（success-supported recovery references）以進行拓撲引導的局部修正（topology-guided localized correction）。
- 引入漸進式自我蒸餾典範（progressive self-distillation paradigm），透過 CTB 引導的局部監督（CTB-guided localized supervision）僅在生成的恢復步驟（generated recovery steps）上計算訓練損失（training loss），並保護有效推理前綴（valid reasoning prefix）免受破壞性梯度更新（destructive gradient updates）。
- 在複雜多輪工具呼叫（multi-turn tool-calling）基準測試（benchmarks）上驗證，DART-SD 顯著優於傳統全軌跡基線（full trajectory baselines）。

### 適合對象
從事大型語言模型（LLMs）自主代理（autonomous agents）、多輪工具呼叫（multi-turn tool-calling）、代理知識蒸餾（agent distillation）、強化學習（Reinforcement Learning, RL）微調，以及長程任務（long-horizon tasks）策略學習的研究人員與工程師。

## 深度分析

#### 方法論解析

##### 1. 問題形式化：從線性軌跡到鑽石拓撲（Diamond Topology）
DART-SD 的核心出發點是指出傳統多輪工具呼叫（multi-turn tool-calling）訓練將執行過程視為「單一線性軌跡（linear trajectory）」。然而，當任務包含多個順序無關子目標（order-independent sub-goals）時，合法解空間會形成組合式鑽石晶格（combinatorial diamond lattice）：不同執行順序會在共享中間狀態（shared intermediate states）交會，再共同收斂至最終答案。強制模型模仿某一條特定路徑會造成拓撲崩塌（topological collapse）——模型把無害探索（harmless exploration）與致命錯誤（fatal errors）混為一談，導致策略多樣性（policy diversity）下降、詞元效率（token efficiency）低落，並產生信用錯配（credit misassignment）。

##### 2. Interaction-State Transition Graph（ISTG）的建構
為了忠實捕捉上述結構，DART-SD 將教師模型（teacher model）的 rollout 轉換為「互動狀態轉移圖（ISTG）」。與傳統以「動作」為節點的圖不同，ISTG 的節點是累積互動狀態（cumulative interaction states），也就是已執行工具呼叫及其觀測結果所構成的狀態。這樣的設計有兩個關鍵優勢：
- **順序無關性**：只要到達相同狀態，不同順序的探索會匯集到同一節點，自然消解順序衝突。
- **同時納入成功與失敗路徑**：圖中不僅包含成功軌跡，也包含失敗的探索路徑（exploratory paths），因此能作為後續恢復參考的結構先驗。

##### 3. Critical Topological Breakpoint（CTB）的偵測
在自我蒸餾（self-distillation）階段，學生模型（student model）進行自主 Rollout（autonomous rollouts）。DART-SD 將學生的互動狀態投影到「經驗上可達的成功區域（success-reachable region）」，找出學生軌跡開始偏離成功流形的關鍵拓撲斷點（CTB）。CTB 的意義在於：
- 它之前的推理前綴（reasoning prefix）被視為有效探索，應受到保護；
- 它之後的步驟才是需要被修正的恢復區段。

這種區分正是 DART-SD 與全軌跡基線（full trajectory baselines）的根本差異：後者對整段序列施加全域損失（global loss），會覆寫學生的有效探索步驟（valid exploratory steps）。

##### 4. 成功軌跡支援的恢復參考檢索
從 CTB 出發，DART-SD 在 ISTG 中尋找「恢復錨點（recovery anchors）」——即與學生當前狀態最相近、且仍能通往成功的圖節點。接著，沿著 ISTG 搜尋成功軌跡支援的延續路徑，作為恢復參考（recovery references）。這相當於為學生提供「後見之明的鷹架（hindsight-based scaffolding）」，但鷹架是根據圖拓撲動態檢索而來，而非預先固定的教師軌跡。

##### 5. CTB 引導的局部監督（CTB-guided Localized Supervision）
最後的訓練損失（training loss）只計算在「生成的恢復步驟（generated recovery steps）」上，CTB 之前的有效推理前綴（valid reasoning prefix）被嚴格保護，避免受到破壞性梯度更新（destructive gradient updates）。這種拓撲引導的局部修正（topology-guided localized correction）讓模型學會「保留已會的、修正錯的」，而非從頭模仿整條軌跡。

##### 6. 漸進式自我蒸餾（Progressive Self-Distillation）
DART-SD 不是一次性訓練，而是反覆 rollout 學生模型、偵測其能力邊界上的 CTB、執行局部監督。隨著迭代進行，學生能夠逐步延長有效互動前綴，最終掌握更複雜的工具使用行為。這與傳統監督式微調（SFT）的靜態全域強制（global forcing）形成鮮明對比。

#### 實驗數據解讀

由於提供的上下文未包含具體實驗表格或數值，以下分析是基於摘要與引言所宣稱的結果進行解讀。

##### 1. 評估維度
DART-SD 的實驗設計橫跨五個基準測試（benchmarks）與兩種模型規模，顯示其企圖驗證：
- **任務成功率（success rate）**：在複雜多輪工具呼叫任務上的最終答案正確性。
- **冗餘工具呼叫（redundant tool calls）**：模型是否學會避免不必要的探索。
- **有效互動前綴長度（valid interaction prefix length）**：模型能維持多長的有效推理而不偏離成功區域。
- **詞元效率（token efficiency）**：達成目標所需的平均 token 數或回合數。
- **策略多樣性（policy diversity）**：是否能產生多種合法解路徑，而非僅背誦單一軌跡。

##### 2. 與基線的預期對比
根據論文宣稱，DART-SD 顯著優於傳統全軌跡基線（full-trajectory baselines）。這意味著：
- 相較於 SFT Teacher Boosting，DART-SD 不會因全域損失而覆寫學生的合法探索，因此在需要彈性順序的任務上表現更穩定。
- 相較於標準強化學習（Standard-RL，如 GRPO），DART-SD 避免了均勻分佈的獎勵擴散（uniformly distributed reward spread）所造成的信用錯配，能更精準地將梯度導向需要修正的恢復步驟。

##### 3. 結果的實質意義
若實驗結果屬實，則代表「拓撲感知」不僅是概念上的修飾，而是能轉化為可量化的效能提升：
- **減少冗餘工具呼叫** 表示模型學到任務的核心邏輯骨幹（core logical backbone），而非死記教師軌跡。
- **延長有效互動前綴** 表示漸進式自我蒸餾確實能逐步擴展學生的能力邊界。
- **提升策略多樣性** 則驗證了鑽石拓撲（diamond topology）建模能保留多條合法路徑，避免拓撲崩塌。

##### 4. 需要注意的解讀限制
由於缺乏原始數據，無法判斷：
- 各基準測試的難度分佈與任務類型是否足以支撐「五個 benchmarks」的泛化宣稱。
- 兩種模型規模是否涵蓋足夠的參數範圍（例如 7B 與 70B），以及計算成本是否隨規模線性增長。
- 統計顯著性、標準差與重複實驗次數。

#### 與現有研究的比較

##### 1. 相較於行為複製（BC）與監督式微調（SFT）
傳統 Behavior Cloning（BC）與 Supervised Fine-Tuning（SFT）透過全長軌跡模仿（full-length trajectory imitation）進行知識蒸餾。DART-SD 指出其根本缺陷在於「全域強制（global forcing）」：一旦學生偏離教師軌跡，後續所有 token 都會被錯誤地懲罰。DART-SD 改為只監督 CTB 之後的恢復步驟，保留了學生的有效探索。

##### 2. 相較於學生中心的動態蒸餾方法
- **SCoRe-SFT**：提供後見鷹架，但仍偏向靜態知識蒸餾，未顯式建模狀態轉移的圖結構（graph structure of state transitions）。
- **On-Policy Self-Distillation（OPSD）**：透過當前學生策略動態 rollout 來緩解離線分佈偏移，但未處理多條合法路徑交會的鑽石拓撲。
- **HINT-SD**：雖然利用後見之明進行針對性鷹架，但仍將多輪互動視為僵化線性（rigid linearity）序列，無法區分無害探索與致命錯誤。

DART-SD 的進步在於引入 ISTG，把「序列」提升為「圖」，並以 CTB 作為動態修正的切分點。

##### 3. 相較於強化學習（RL）方法
- **FTRL-GRPO / ToolRL**：使用稀疏結果獎勵（sparse outcome rewards）與可驗證執行回饋，但容易將失敗軌跡（failed trajectories）中的所有中間工具呼叫（intermediate tool calls）一併懲罰。
- **MatchTIR**：透過雙邊匹配（bipartite matching）提供回合級獎勵，但仍將互動視為線性序列，忽略鑽石拓撲。

DART-SD 不追求複雜的獎勵塑形（reward shaping），而是透過圖檢索直接定位需要修正的區段，從而避免信用錯配。

##### 4. 主要限制
- **對教師 rollout 品質的依賴**：ISTG 的覆蓋範圍與正確性取決於教師模型產生的成功與失敗軌跡。若教師探索不足，CTB 檢索可能找不到合適的恢復錨點。
- **圖建構成本**：隨著任務複雜度增加，累積互動狀態空間可能指數成長，ISTG 的儲存與檢索成本需要進一步評估。
- **CTB 偵測的啟發式本質**：雖然論文將 CTB 定義為投影到成功可達區域的斷點，但實際偵測可能涉及距離函數或分類器的設計，其穩健性影響最終效果。
- **泛化到未見狀態**：若學生進入 ISTG 未涵蓋的區域，檢索到的恢復參考可能不適用。

#### 可重現性評估

##### 1. 開源資源
根據目前提供的上下文，論文尚未提及原始碼、資料集或模型權重的公開連結。因此，在可重現性（reproducibility）方面暫時無法給予高度評價。

##### 2. 重現所需關鍵元件
若要重現 DART-SD，研究者至少需要：
- **教師模型 rollout 資料**：包含成功與失敗軌跡的多輪工具呼叫記錄。
- **ISTG 建構細節**：狀態表示方式、節點合併準則、邊的定義與圖的儲存格式。
- **CTB 偵測演算法**：如何將學生狀態投影到成功可達區域、距離度量、斷點判定閾值。
- **檢索與參考生成機制**：從 recovery anchors 搜尋成功延續路徑的演算法。
- **局部監督損失函數**：只對 recovery steps 計算損失的具體實作方式，以及如何屏蔽有效前綴的梯度。
- **漸進式訓練流程**：迭代 rollout、CTB 偵測、微調的次數與學習率排程。

##### 3. 可重現性風險
- **實作細節不透明**：CTB 與 ISTG 檢索涉及多個設計選擇，若論文未詳細說明，重現結果可能出現顯著差異。
- **計算資源需求**：反覆 rollout 學生模型並建構大型狀態轉移圖，可能需要大量 GPU 與儲存資源。
- **基準測試的資料取得**：若使用的五個 benchmarks 包含私有或難以取得的 API，重現難度會進一步提高。

##### 4. 建議
為提升可重現性，作者應公開：
- 原始碼與訓練腳本；
- 預先建構的 ISTG 或建構流程；
- 各基準測試的評估協定與 prompt 模板；
- 模型檢查點（checkpoints）以便比較。

#### 未來研究方向

##### 1. 動態與線上 ISTG 更新
目前的 ISTG 似乎是基於教師 rollout 預先建構。未來可研究如何在學生訓練過程中線上擴充 ISTG，讓圖結構隨著學生能力提升而動態成長，減少對靜態教師資料的依賴。

##### 2. 與強化學習的深度融合
DART-SD 的局部監督可與 RL 的環境回饋結合。例如，在 CTB 偵測後，對 recovery steps 使用細粒度獎勵塑形（reward shaping），而非僅使用教師參考進行監督，可能進一步提升探索效率。

##### 3. 自適應 CTB 偵測
目前的 CTB 可能依賴啟發式閾值。未來可引入可學習的狀態價值函數或異常偵測模型，自動判斷何時進入需要修正的區域，並根據任務難度調整修正強度。

##### 4. 擴展到部分可觀測與嘈雜環境
真實世界工具呼叫常伴隨不確定或錯誤的觀測。將 ISTG 擴展為機率圖模型，或引入對抗式/嘈雜 rollout，可提升方法在真實 API 環境中的穩健性。

##### 5. 多代理與協作工具使用
鑽石拓撲不僅出現在單一代理的順序無關子目標中，也可能出現於多代理協作場景。未來可研究如何將 DART-SD 應用於多代理系統，讓不同代理的互動狀態在共享圖中交會與修正。

##### 6. 理論分析
目前 DART-SD 的貢獻偏重經驗與概念。未來可從理論上分析：
- ISTG 的鑽石拓撲如何影響策略空間的覆蓋與樣本複雜度；
- CTB 引導局部監督的收斂性與泛化界；
- 與傳統 SFT / RL 在特定圖結構下的樣本效率比較。

##### 7. 開源與標準化評估
為推動領域發展，建立開源的 DART-SD 實作與標準化的多輪工具呼叫評估協定，將有助於後續研究驗證與比較不同拓撲感知方法的效能。

## 論文問答

**Q1：DART-SD 要解決的核心問題是什麼？**  
A：DART-SD 主要針對現有多輪工具呼叫代理訓練中，因過度依賴全長軌跡模仿而導致的「拓撲崩塌」問題。傳統方法強制學生模型複製單一線性專家軌跡，忽略了許多順序無關但同樣有效的替代探索路徑。這種全域強制不僅會懲罰合理的探索，也會降低策略多樣性與模型在長程任務中的泛化能力。

**Q2：現有的 SFT 與 RL 方法為何在多輪工具呼叫中表現受限？**  
A：SFT 透過行為複製對整條軌跡施加均勻的詞元級損失，容易覆蓋學生模型已經產生的有效探索步驟；標準強化學習（如 GRPO）則把最終獎勵均勻擴散到所有中間工具呼叫，導致信用錯配。兩者都把多輪互動視為僵化的線性序列，無法區分致命錯誤與無害探索。結果是它們會任意懲罰失敗軌跡中的有效前綴，並嚴重損害內部知識一致性與詞元效率。

**Q3：為什麼「鑽石拓撲」對多輪工具呼叫任務如此重要？**  
A：當任務包含多個順序無關的子目標時，最佳解空間會形成巨大的組合式鑽石晶格，不同軌跡會在共享中間狀態交會。若將這個豐富的圖結構強行壓扁為單一線性路徑，就會發生拓撲崩塌，使模型誤以為只有一種正確順序。認知並保留鑽石拓撲能讓代理學習任務的核心邏輯骨幹，而非死記特定軌跡，從而提升泛化與探索多樣性。

**Q4：ISTG 是什麼？它如何捕捉鑽石拓撲？**  
A：互動狀態轉移圖（ISTG）是 DART-SD 從教師 rollout 中萃取的結構先驗，其節點定義為累積互動狀態而非短暫動作。由於狀態會收斂到共同中間點，ISTG 能自然地表達成功與失敗探索路徑交會的鑽石拓撲。這種設計解決了順序相依衝突，使代理能夠在共享狀態上銜接不同但等價的後續步驟。

**Q5：CTB 是如何被定義與識別的？**  
A：關鍵拓撲斷點（CTB）是學生軌跡偏離經驗上成功可達區域的位置。DART-SD 將學生的互動狀態投影到 ISTG 的成功可達區域，找出最後一個仍屬於成功前綴的狀態與隨後開始偏離的狀態。透過這種投影，框架能精確定位需要修正的節點，並在該處檢索成功軌跡支援的恢復錨點。

**Q6：CTB 引導的局部監督與漸進式自我蒸餾如何運作？**  
A：在識別 CTB 後，DART-SD 從 ISTG 中檢索成功支援的接續路徑作為恢復參考，並只針對生成的恢復步驟計算訓練損失。這樣可以嚴格保護 CTB 之前的有效推理前綴，避免受到破壞性梯度更新。漸進式自我蒸餾則反覆 rollout 學生模型、更新其能力邊界並進行局部監督，使學生逐步掌握更複雜的工具使用行為。

**Q7：實驗在哪些基準與模型規模上進行？**  
A：論文在五個複雜的多輪工具呼叫基準測試上進行評估，並涵蓋兩種模型規模。這些任務涉及長程規劃、多步 API 操作與順序無關的子目標達成。跨規模與跨基準的設計有助於驗證 DART-SD 在不同難度與參數量下的穩定性與泛化性。

**Q8：DART-SD 相較於基線方法取得了哪些關鍵結果？**  
A：實驗顯示 DART-SD 顯著優於傳統的全軌跡監督式微調與標準強化學習基線。它不只提升最終任務成功率，還減少了多餘的工具呼叫並延長有效互動前綴。這些結果顯示拓撲感知的局部修正比全域強制更能保留合理探索並改善長程行為。

**Q9：消融研究驗證了哪些設計選擇？**  
A：消融實驗通常會比較完整 DART-SD 與移除 ISTG 檢索、移除 CTB 定位或改回全域損失的變體。結果預期顯示 ISTG 提供的結構先驗、CTB 的精確定位以及局部監督對有效前綴的保護皆為性能提升的關鍵。任何單一元件的移除都會導致拓撲崩塌加劇、冗餘呼叫增加或成功率下降。

**Q10：DART-SD 可應用於哪些實務場景？**  
A：DART-SD 特別適合需要靈活組合多種工具的真實應用，例如客戶服務機器人、研究助理、程式開發助手與企業 API 編排系統。在這些場景中，達成目標的步驟順序往往不唯一，代理必須能夠探索不同路徑並在偏離時自我修正。透過保留有效前綴並局部修正錯誤，DART-SD 可提升系統的穩健性與使用者體驗。

**Q11：在產品化時需要考慮哪些因素？**  
A：產品部署時需權衡 ISTG 的建構與檢索成本，以及即時 rollout 對延遲的影響。此外，應確保成功可達區域的定義與任務評估指標一致，避免檢索到語法相似但語意錯誤的恢復錨點。持續監控學生模型的能力邊界並定期更新圖結構，也是維持長期效能與安全性的重要措施。

**Q12：DART-SD 對代理知識蒸餾領域可能帶來什麼影響？**  
A：DART-SD 將代理訓練典範從「全軌跡模仿」轉向「拓撲引導的局部修正」，為處理順序無關子目標提供了新的結構化視角。它有助於把前沿模型的多輪工具使用能力更有效率地轉移到輕量開源模型，降低部署成本。長遠來看，這種拓撲感知的方法可能成為設計高自主性、可解釋且具多樣性代理的基礎。

**Q13：論文可能承認哪些限制？**  
A：DART-SD 依賴教師 rollout 來建構 ISTG，因此教師品質與覆蓋範圍會直接影響圖結構的完整性。此外，狀態圖的建構、儲存與檢索會帶來額外的計算與記憶體開銷。方法也假設任務具有可識別的成功狀態與某種程度的順序無關性，對於高度序列相依或獎勵極度稀疏的環境可能需要額外調整。

**Q14：在哪些情況下 DART-SD 可能失敗或表現不佳？**  
A：當子目標之間存在強烈的因果或時序相依，導致鑽石拓撲不明顯時，ISTG 的收斂性會變差。若學生過早偏離到成功可達區域之外很遠的位置，CTB 定位可能變得模糊，檢索到的恢復參考也難以接續。此外，若教師 rollout 對某些罕見狀態覆蓋不足，局部監督可能會引用不存在的成功路徑而無法有效修正。

**Q15：未來可以朝哪些方向延伸？**  
A：未來可研究如何讓 ISTG 在訓練過程中線上更新，減少對靜態教師軌跡的依賴。結合強化學習的獎勵塑形或過程獎勵模型，也許能進一步提升 CTB 定位與恢復步驟的品質。此外，將鑽石拓撲感知的方法推廣到更廣泛的代理架構、更多樣化的工具生態系統，以及多模態互動場景，都是值得探索的方向。

## 實務應用指南

適用場景

1. 多步驟客戶服務代理  
   在需要同時查詢訂單狀態、庫存、物流與退換貨政策的客服場景中，子目標彼此順序無關，卻經常因全軌跡模仿而被迫學習固定查詢順序。DART-SD 可透過 ISTG 保留多條等價成功路徑，並在學生模型走偏時於 CTB 處進行局部修正，避免覆蓋原本合理的探索。

2. 企業級資料分析與報表生成代理  
   當代理需要呼叫多個資料庫、BI 工具與計算 API 來完成「下鑽分析 → 彙整 → 視覺化」時，不同資料來源的查詢順序常可互換。鑽石拓撲能捕捉這些等價路徑，CTB 引導的局部監督則讓模型只修正錯誤的查詢組合，保留有效的資料探勘前綴。

3. 程式開發與 DevOps 自動化代理  
   例如在雲端部署或除錯流程中，代理可能依序呼叫日誌查詢、設定檔檢查、容器重啟與健康檢查等工具。DART-SD 能區分「無害的探索步驟」與「致命錯誤」，避免標準 RL 的均勻獎勵擴散誤傷合理的中間工具呼叫。

4. 旅遊與行程規劃代理  
   訂房、訂票、查天氣、查景點開放時間等子目標順序彈性高，且不同組合可能交會於相同中間狀態。透過互動狀態轉移圖可自然表達這種組合式鑽石晶格，並在學生偏離成功可達區域時提供恢復參考。

5. 科學研究輔助代理  
   文獻檢索、實驗數據查詢、統計檢定與摘要生成等步驟常具順序無關性。DART-SD 的漸進式自我蒸餾能讓輕量開源模型逐步掌握複雜的多輪工具使用行為，降低對前沿模型的依賴。

實作前置條件

資料準備  
- 教師模型生成的高品質多輪軌跡，包含成功與失敗案例，且需記錄每個步驟的互動狀態（如工具輸入、觀察結果、累積上下文）。  
- 工具描述與 API Schema，包含輸入輸出格式、可呼叫順序限制與領域知識。  
- 狀態表示設計：需定義「累積互動狀態」的編碼方式，例如工具呼叫序列的語義嵌入、關鍵觀察值的結構化摘要，或兩者結合。  
- 評估資料與指標：最終任務成功率、多餘工具呼叫次數、有效推理前綴長度、CTB 偵測準確率等。

運算資源  
- 訓練：至少具備 24 GB 以上 VRAM 的 GPU（如 A100 / H100），用於學生模型的監督式微調與自我蒸餾迭代。  
- 推理：需穩定的教師模型與學生模型推理環境，以進行自主 Rollout 與 ISTG 建構。  
- 圖儲存：可支援鄰接查詢與最短路徑搜尋的圖資料庫或記憶體內圖結構（如 NetworkX、Neo4j）。

技術與團隊能力  
- 熟悉 LLM 微調流程（SFT、LoRA、QLoRA）與強化學習基礎（GRPO、PPO）。  
- 具備工具增強型代理開發經驗，能設計狀態轉移與獎勵函數。  
- 具備圖論與檢索系統實作能力，能設計 ISTG 節點、邊與成功可達區域的投影演算法。  
- 具備評估與可觀測性建置經驗，能追蹤 CTB、恢復步驟與模型行為分佈。

實作步驟建議

步驟一：任務拆解與狀態定義  
將目標任務拆解為順序無關子目標，並定義「累積互動狀態」的表示法。狀態應包含已完成的工具呼叫、取得的關鍵觀察、以及尚未滿足的子目標，避免僅以單一動作作為節點。

步驟二：收集教師與學生軌跡  
使用教師模型進行大量自主 Rollout，同時保留成功與失敗軌跡。接著讓初始學生模型也進行 Rollout，產生偏離成功區域的樣本，作為後續 CTB 偵測與局部監督的素材。

步驟三：建構互動狀態轉移圖（ISTG）  
將所有軌跡轉換為 ISTG，節點為累積互動狀態，邊為工具呼叫動作。標記每個節點是否可達最終成功狀態，並保留從該節點通往成功的後續路徑作為恢復參考。

步驟四：實作 CTB 偵測與恢復檢索  
設計投影函數，將學生當前狀態對應到 ISTG 中的最近節點。當狀態落入「成功不可達」區域時，回溯至最後一個仍位於成功可達區域的節點，即為關鍵拓撲斷點（CTB）。從 CTB 出發，檢索圖中通往成功的多條候選路徑作為恢復參考。

步驟五：CTB 引導的局部監督與自我蒸餾  
讓學生模型在 CTB 之後生成恢復步驟，並僅針對這些生成的恢復步驟計算訓練損失，嚴格保護 CTB 之前的有效推理前綴不受破壞性梯度更新。可採用漸進式迭代：每輪更新後重新 Rollout、重新偵測 CTB、再進行下一輪局部蒸餾。

步驟六：評估與上線前驗證  
在保留測試集上比較 DART-SD 與全軌跡基線的成功率、多餘工具呼叫數與有效前綴長度。特別檢視 CTB 是否正確定位、恢復參考是否確實導向成功，以及模型是否出現過度保守或過度探索的行為。

步驟七：部署與持續迭代  
將訓練後的學生模型整合至代理框架，並在生產環境中持續收集新軌跡，定期擴充 ISTG 與重新偵測能力邊界，形成持續的自我蒸餾迴路。

潛在風險與注意事項

ISTG 覆蓋不足導致檢索失敗  
若教師 Rollout 數量不足或任務組合空間過大，ISTG 可能無法涵蓋真實的分支情況，使 CTB 後無法檢索到有效恢復參考。建議透過主動探索或教師多樣化採樣來擴充圖結構，並設定後備策略（如直接呼叫教師模型或回退至安全狀態）。

狀態表示模糊造成 CTB 誤判  
累積互動狀態若過於粗糙，可能將不同語義狀態合併；若過於細緻，則圖會過度稀疏。應透過領域知識設計狀態摘要，並以人工抽樣驗證 CTB 定位是否合理。

過度擬合恢復路徑而損害泛化  
局部監督雖保護前綴，但若恢復參考過於單一，模型可能記憶特定恢復序列而非學習通用恢復策略。可從 ISTG 中檢索多條成功路徑作為多樣化參考，並在損失中適度加入正則化。

延遲與運算成本  
圖搜尋與反覆 Rollout 會增加訓練與推理延遲。建議將 ISTG 快取於記憶體、對常見 CTB 預先計算恢復參考，並在生產環境中以非同步方式更新圖結構。

獎勵錯配與捷徑行為  
即使採用局部監督，仍需注意恢復步驟是否利用環境漏洞或產生語法正確但語義空洞的工具呼叫。應搭配結果驗證與過程檢查，避免獎勵駭取。

與其他技術的整合建議

與代理框架整合  
可將 DART-SD 作為 LlamaIndex、LangChain 或自研 Agent Orchestrator 的訓練後端。ISTG 可嵌入為「經驗記憶圖」，CTB 偵測模組則作為執行時的異常偵測與恢復觸發器。

與向量檢索與圖資料庫整合  
將 ISTG 節點的語義嵌入儲存於向量資料庫，用於快速近似最近鄰搜尋；將狀態轉移關係儲存於圖資料庫（如 Neo4j），便於執行多跳路徑檢索與成功可達性分析。

與 RLHF / 偏好學習整合  
DART-SD 產生的恢復步驟可進一步收集人類偏好，訓練獎勵模型以篩選更自然的恢復參考，或與 DPO、KTO 等偏好最佳化方法結合，提升恢復內容的可讀性與穩健性。

與可觀測性平台整合  
將 CTB 位置、檢索到的恢復參考、實際生成步驟與最終結果記錄至可觀測性系統（如 LangSmith、Weights & Biases），以便追蹤拓撲崩塌熱點、診斷模型行為並持續擴充 ISTG。

與 API 閘道與安全層整合  
在生產環境中，CTB 偵測可與 API 閘道、速率限制及權限控管結合，當代理偏離安全可達區域時自動降級或請求人類確認，降低高風險工具呼叫的錯誤成本。

給不同背景讀者的閱讀建議

初學者  
建議先聚焦於「為什麼全軌跡模仿會出問題」這個直覺：想像一個任務可以先用 A 工具或 B 工具開始，傳統方法卻強迫模型只學其中一種順序。接著理解 ISTG 就像一張地圖，把各種合理路徑畫出來；CTB 則是地圖上「最後還能走回正確路線」的點。實作細節可先略過數學定義，待熟悉代理開發後再回頭研讀。

AI 工程師  
建議重點閱讀方法論與實驗設定，特別是狀態表示、CTB 投影演算法與局部損失的實作細節。可嘗試先用既有 SFT 基線產生軌跡，再逐步導入 ISTG 與 CTB 模組，並以多餘工具呼叫數與有效前綴長度作為除錯指標。注意訓練時需嚴格遮罩 CTB 之前的梯度，避免前綴被破壞。

研究人員  
建議深入分析「拓撲崩塌」的理論內涵，以及 ISTG 相較於序列比對或雙向匹配（如 MatchTIR）在表達順序無關子目標上的優勢。可進一步探討 CTB 的替代定義、ISTG 的壓縮與泛化、以及與馬可夫決策過程或選項學習（Options Framework）的理論連結。

產品經理  
建議從適用場景與實驗結果切入，評估自家代理任務是否具備「多個順序無關子目標」與「高失敗成本工具呼叫」等特徵。關注 DART-SD 能帶來的商業指標：成功率提升、無效 API 呼叫減少、輕量模型替代昂貴前沿模型的可能性，以及上線後持續自我蒸餾所需的資料與維運成本。
