## ⚡ TL;DR

現有搜尋代理使用生成式模型做頻繁決策，導致高延遲與信心度校準不良。
SearchJev以綱要評分與軟標籤學習，分離System-1決策與System-2推理。
決策速度快5.2倍以上，平均校準誤差降41–74%，端到端準確率從45%提升至54%。

## 摘要翻譯

搜尋代理（search agent）反覆針對相關性、證據充分性與搜尋動作做出簡短決策。使用生成式語言模型進行這些決策會帶來延遲，並產生不可靠的信心度。我們提出 SearchJev，一個快速且校準良好的 System-1（系統一）模型，可將搜尋決策與 System-2（系統二）的推理和生成分離開來。給定搜尋狀態與決策綱要，SearchJev 可直接為合法選項評分，無需自迴歸輸出生成。我們提出 SLCD（Soft-Label Learning for Calibrated Decisions，用於校準決策的軟標籤學習），從不確定監督中學習決策機率，並校準其信心度。在雙系統搜尋代理（dual-system search agent）中，SearchJev 處理簡短決策，並將不確定判斷委派給 System-2，後者仍負責規劃、查詢生成與答案撰寫。我們也提出 SearchDecision-Bench，一個統合六種搜尋決策類型、可用於訓練與評估的基準。在 SearchDecision-Bench 上，SearchJev 相較於同尺寸的 Qwen3.5 自迴歸模型提升了決策品質，決策速度提升 5.2–5.3 倍，並將平均期望校準誤差降低 41–74%。在 BrowseComp-Plus 上，雙系統代理在主動搜尋時間方面達到 3.7–4.7 倍的加速比，同時將答案準確率從 45% 提升至最高 54%。

### 核心貢獻（3～5點）
- 提出 SearchJev：一個快速且校準良好的 System-1（系統一）模型，能將搜尋決策與 System-2（系統二）的推理和生成分離，直接對合法選項評分而無需自迴歸輸出生成。
- 提出 SLCD（用於校準決策的軟標籤學習），從不確定監督中學習決策機率並校準其信心度。
- 提出 SearchDecision-Bench 基準，統合六種搜尋決策類型以用於訓練與評估。
- 在 SearchDecision-Bench 上，SearchJev 相較於同尺寸 Qwen3.5 自迴歸模型提升決策品質，決策速度提升 5.2–5.3 倍，並降低平均期望校準誤差 41–74%。
- 在 BrowseComp-Plus 上，雙系統代理達到 3.7–4.7 倍的主動搜尋時間加速比，並將答案準確率從 45% 提升至最高 54%。

### 適合對象
從事大型語言模型代理、搜尋代理、雙系統架構、模型校準與高效推論等領域的研究人員與工程師，特別是關注如何降低代理式搜尋延遲並提升決策信心度可靠性的讀者。

## 深度分析

#### 方法論解析

SearchJev 的核心方法論可拆解為三個層次：**schema-conditioned（綱要條件化）的 System-1（系統一）決策模型**、**Soft-Label Learning for Calibrated Decisions（SLCD，用於校準決策的軟標籤學習）**，以及**dual-system search agent（雙系統搜尋代理）**的協作架構。

##### 1. Schema-Conditioned System-1 Search Decision Model

傳統的 LLM-based search agent（基於大型語言模型的搜尋代理）在每次需要判斷時，都會啟動 autoregressive output generation（自迴歸輸出生成），即使只是要產生一個簡短的判斷（例如「這段 passage（段落）是否 relevant（相關）？」）。SearchJev 將這類 short decision（簡短決策）從 System-2 reasoning（系統二推理）中分離出來，改為直接對合法選項進行機率評分。

具體而言，給定一個 search state（搜尋狀態）\(s_t=(q,H_t,C_t)\) 與 decision schema（決策綱要）\(\sigma=\{f_1,\dots,f_k\}\)，模型會把每個 field（欄位）對應的自然語言問題與 legal option（合法選項）視為選項標籤，然後將 backbone（骨幹模型）第一個 output token（輸出詞元）的 logits 限制在這些選項標籤上，經過 softmax 後直接輸出決策分布。這種做法避免了 sequential decoding（循序解碼）與 JSON 格式生成，因此能顯著降低 latency（延遲）。

決策綱要統一了 heterogeneous search decision（異質搜尋決策）的輸入輸出格式。SearchDecision-Bench 將其歸納為六種 decision type（決策類型）：

- **Routing（路由）**：判斷查詢意圖、檢索需求程度等，例如 intent classification（意圖分類）、retrieval need（檢索需求）。
- **Rewriting（改寫）**：判斷 query equivalence（查詢等價性）或 rewrite equivalence（改寫等價性）。
- **Relevance（相關性）**：對文件、段落進行 relevance judgment（相關性判斷）、document usefulness（文件有用性）或 document quality（文件品質）評分。
- **Sufficiency（充分性）**：判斷已檢索的 evidence（證據）是否足以回答問題，即 evidence sufficiency（證據充分性）。
- **Navigation（導航）**：決定 next action（下一步動作）、next sub-query（下一個子查詢）或 query-fit assessment（查詢配適評估）。
- **Verification（驗證）**：進行 claim verification（主張驗證）或 evidence detection（證據偵測）。

每個欄位又對應三種 output type（輸出類型）之一：**Choice（多選一）**、**Noul（是非／二元判斷）**、**Score（序位評分）**。透過這種統一表示，單一 SearchJev 模型即可處理多種 search decision（搜尋決策），而不需要為每種任務訓練獨立的 reranker（重排模型）或 classifier（分類器）。

##### 2. Soft-Label Learning for Calibrated Decisions（SLCD）

搜尋決策的監督訊號往往帶有 noise（雜訊）與不確定性：不同標註者對「相關」的認定可能不同，evidence sufficiency（證據充分性）也沒有絕對標準。SLCD 透過 soft label（軟標籤）來表達這種 uncertain supervision（不確定監督），而不是強迫模型學習單一的 hard label（硬標籤）。

訓練時，SLCD 結合 proper scoring losses（適當評分損失），讓模型學習的 decision probability（決策機率）能夠真實反映事件發生的機率。訓練後再進行 temperature calibration（溫度校準），進一步調整 confidence（信心度）的可靠性。這使得 SearchJev 的輸出不只是「選哪個選項」，而是「選這個選項的機率是多少」，並且這個機率經過校準後能夠用來判斷是否該將決定交給 System-2（系統二）複查。

校準良好的 confidence 是 dual-system agent（雙系統代理）運作的關鍵：當 System-1 對某個決定很有信心時，可以直接採用；當信心不足時，則 delegate（委派）給 System-2 進行更深入的分析。

##### 3. Dual-System Search Agent

SearchJev 並非要取代大型語言模型，而是要與之協作。在 dual-system search agent（雙系統搜尋代理）中：

- **System-1（SearchJev）**：負責頻繁且簡單的 search decision（搜尋決策），例如 relevance（相關性）、evidence sufficiency（證據充分性）、next action（下一步動作）等。它以極低延遲輸出校準過的機率。
- **System-2**：保留需要規劃與生成的任務，包括 planning（規劃）、query generation（查詢生成）、answer composition（答案撰寫）等。當 SearchJev 對某個判斷的 confidence 低於門檻時，System-2 會接手進行 reasoning（推理）。

這種 division of labor（分工）讓代理在大部分情況下使用快速的直接預測，只在必要時才啟動昂貴的 generative language model（生成式語言模型），因此能同時達到高效率與高準確率。

#### 實驗數據解讀

論文在兩個層級進行評估：**decision-level（決策層級）**使用 SearchDecision-Bench，**agent-level（代理層級）**使用 BrowseComp-Plus。

##### 1. SearchDecision-Bench 上的決策表現

與 same-size model（同尺寸模型）的 Qwen3.5 AR（JSON）相比，SearchJev 在 0.8B 與 4B 兩個尺寸上均取得顯著進步：

- **Decision quality（決策品質）**：SearchJev 優於同尺寸的 Qwen3.5 autoregressive model（自迴歸模型）。這顯示直接對 legal option（合法選項）評分，比先生成 JSON 再解析的傳統方式更適合簡短決策。
- **Latency（延遲）**：SearchJev 的決策速度是 Qwen3.5 的 **5.2–5.3× faster（快 5.2 至 5.3 倍）**。這主要歸功於避免了 autoregressive output generation（自迴歸輸出生成），只需一次前向傳播即可得到分布。
- **Calibration（校準）**：平均 expected calibration error（ECE，期望校準誤差）降低 **41–74%**。這表示 SearchJev 的 confidence（信心度）更能真實反映決策正確的機率，對於後續的 delegation（委派）機制至關重要。

這些結果說明，SearchJev 在「快、準、校準好」三個目標上同時取得進展，而不需要在三者之間做明顯取捨。

##### 2. BrowseComp-Plus 上的端到端代理表現

在端到端 agentic search（代理式搜尋）任務 BrowseComp-Plus 上，dual-system search agent（雙系統搜尋代理）的表現如下：

- **Answer accuracy（答案準確率）**：System-2-only agent（僅 System-2 代理）的準確率為 45%；Jev 1.13 為 46%；而 SearchJev-0.8B + System-2 達到 46%，SearchJev-4B + System-2 達到 **54%**。這顯示適當的 System-1 輔助不僅不會降低準確率，反而能透過更好的中間決策提升最終答案品質。
- **Active search time（主動搜尋時間）**：相較於 System-2-only agent，dual-system agent 達到 **3.7–4.7× speedup（3.7 至 4.7 倍加速）**。
- **Output token（輸出詞元）**：減少 **3.3–4.8× fewer output tokens（3.3 至 4.8 倍）**，這也連帶降低推理成本與能耗。

值得注意的是，SearchJev-0.8B 已能與 Jev 1.13 達到相同的 46% 準確率，但體積遠小；SearchJev-4B 則進一步提升到 54%。這暗示在搜尋代理中，頻繁的 short decision（簡短決策）由專門的輕量模型處理，能讓大型 System-2 模型專注於真正需要 reasoning（推理）的步驟，從而提升整體效能。

#### 與現有研究的比較

##### 1. 相較於任務專用模型

過去常見的做法是為每種搜尋決策訓練獨立的模型，例如 reranker（重排模型，如 Nogueira et al., 2020）或 query-complexity classifier（查詢複雜度分類器，如 Jeong et al., 2024）。這些方法雖然在單一任務上有效，但缺點是：

- 每個任務需要獨立的 supervision（監督）與模型維護。
- 難以擴展到多種 heterogeneous search decision（異質搜尋決策）。

SearchJev 透過 decision schema（決策綱要）統一不同決策類型的輸入輸出，讓單一模型即可處理六種決策類型，大幅簡化系統架構。

##### 2. 相較於提示通用大型語言模型

另一種常見做法是 prompting（提示）general LLM（通用大型語言模型）來做各種判斷。這種方法雖然靈活，但存在兩個問題：

- **Latency（延遲）**：即使只是要做一個二元判斷，也需要進行 autoregressive output generation（自迴歸輸出生成），產生多個 output token（輸出詞元）。
- **Miscalibrated confidence（校準不良的信心度）**：無論是 verbalized confidence（言語化信心度）還是從 token probability（詞元機率）推導的信心，都常被發現校準不良（Kadavath et al., 2022; Tian et al., 2023; Xiong et al., 2024）。

SearchJev 直接對選項標籤評分，避免了解碼開銷；同時透過 SLCD 與 temperature calibration（溫度校準）獲得可靠的 confidence，解決了上述兩個問題。

##### 3. 與 Jev 的關係

SearchJev 受到 Jev（Almeida, 2026）的啟發，後者使用 typed probability（型別化機率）來支援自動化流程。SearchJev 將這個概念應用到搜尋代理領域，並進一步結合 Kahneman（2011）的 System-1 / System-2（系統一／系統二）框架，提出專門的 dual-system search agent（雙系統搜尋代理）架構。

##### 4. 限制與待釐清之處

儘管成果顯著，仍有幾點限制值得注意：

- **Schema 設計成本**：雖然 decision schema（決策綱要）能統一多種決策，但設計良好的 schema 仍需要領域知識。對於未涵蓋的決策類型，可能需要額外擴展。
- **Delegation 門檻的敏感性**：論文提到 uncertain judgment（不確定判斷）會被委派給 System-2，但門檻如何設定、在不同任務間是否通用，仍有待更多分析。
- **System-2 仍是瓶頸**：雖然 SearchJev 大幅減少 short decision 的延遲，但最終的 planning（規劃）與 answer composition（答案撰寫）仍依賴大型 System-2 模型。若 System-2 本身很慢，整體加速可能受限。
- **評估範圍**：SearchDecision-Bench 涵蓋六種決策類型，但現實世界中的搜尋代理可能需要處理更細緻或更動態的判斷，例如多輪對話中的意圖轉換、跨語言檢索等。

#### 可重現性評估

根據目前提供的論文內容，**尚未明確提及原始碼、資料集或模型權重是否公開釋出**。以下是可重現性方面的評估：

- **方法描述清晰度**：SearchJev 的方法論描述相當清楚，包括 schema 格式、第一個輸出詞元 logits 的處理方式、SLCD 的訓練目標與 temperature calibration（溫度校準）等，理論上具備重現的基礎。
- **資料集**：SearchDecision-Bench 是論文新提出的 benchmark（基準），其資料來自多種 heterogeneous resources（異質資源）並轉換為統一格式。若資料集未公開，其他研究者將難以直接比較。
- **模型權重與程式碼**：論文未說明是否會釋出 SearchJev 的模型權重或訓練程式碼。由於其基於 Qwen3.5 backbone（骨幹模型），理論上可用公開的 Qwen3.5 權重復現，但具體的訓練細節（如 soft label 的生成方式、損失函數權重、校準流程）仍需更多資訊。
- **評估協定**：BrowseComp-Plus 與 SearchDecision-Bench 的評估指標已於文中說明，但完整的實驗設定（如超參數、delegation 門檻、System-2 模型版本）對於嚴格重現仍屬必要。

整體而言，SearchJev 在方法層面具備良好的可重現潛力，但實際重現程度將取決於作者後續是否釋出程式碼、資料與模型權重。

#### 未來研究方向

基於 SearchJev 的貢獻與限制，以下幾個方向值得進一步探索：

##### 1. 擴展 Decision Schema 的覆蓋範圍

目前的 SearchDecision-Bench 涵蓋六種 decision type（決策類型），但未來可納入更多複雜判斷，例如：

- 多輪對話中的 context switch detection（情境切換偵測）
- 跨語言檢索中的語言識別與翻譯需求判斷
- 多模態搜尋中的圖片、表格相關性判斷

##### 2. 自適應 Delegation 機制

目前 uncertain judgment（不確定判斷）的 delegation（委派）門檻可能是固定或啟發式設定的。未來可研究：

- 根據任務難度、剩餘預算、System-2 負載動態調整門檻
- 學習最優 delegation 策略，以在準確率與延遲之間取得最佳平衡

##### 3. 線上校準與持續學習

SearchJev 使用訓練後的 temperature calibration（溫度校準），但在 deployment（部署）後可能面臨 distribution shift（分布偏移）。未來可探討：

- 線上校準（online calibration）技術
- 持續學習（continual learning）以適應新的搜尋領域與使用者行為

##### 4. 與其他 System-2 模型整合

論文使用 27B 的 System-2 模型。未來可研究 SearchJev 與不同尺寸、不同架構的 System-2 模型（例如 reasoning model、多模態模型）整合時的表現，並分析 System-1 與 System-2 之間的最適分工。

##### 5. 硬體與系統層級最佳化

SearchJev 已顯著降低決策延遲，但未來可進一步探索：

- 將 SearchJev 部署於 edge device（邊緣裝置）
- 與檢索引擎、瀏覽器環境更緊密整合，減少端到端軌跡中的 I/O 延遲

##### 6. 可解釋的決策信心度

校準良好的 confidence（信心度）已具實用價值，但未來可進一步研究如何將其轉化為人類可理解的解釋，例如指出模型不確定的是哪個證據片段、哪個選項之間最難區分，從提升搜尋代理的可信度與可除錯性。

## 論文問答

## 背景與動機（Background & Motivation）

**Q1：SearchJev 主要想解決什麼問題？**
A：在基於大型語言模型的搜尋代理中，代理會反覆做出許多簡短的 System-1 決策，例如判斷文件是否相關、證據是否充分，以及下一步該採取什麼搜尋動作。現有方法通常直接呼叫生成式語言模型來輸出這些判斷，導致每次決策都必須進行自迴歸輸出生成，帶來明顯的循序解碼延遲。此外，這類模型無論是透過言語化信心度還是詞元機率來估計信心，往往都存在校準不良的問題，因此難以判斷何時可以安全接受決策、何時需要進一步推理。

**Q2：現有的兩類常見做法為什麼不足以解決這個問題？**
A：第一類是針對單一功能設計的重排模型或查詢複雜度分類器，它們雖然效率高，但每種決策類型都需要獨立的模型與監督資料，難以擴展到異質搜尋決策。第二類是透過提示工程讓通用大型語言模型直接生成判斷，雖然能適應多樣任務，但仍需自迴歸輸出生成，對頻繁的短期決策來說開銷過大。更重要的是，這兩種路徑都難以同時滿足「高效率」與「校準良好的信心度」這兩個需求。

**Q3：為什麼決策信心度的校準對搜尋代理如此重要？**
A：校準良好的信心度是雙系統搜尋代理決定是否接受 System-1 判斷、或將不確定判斷委派給 System-2 的關鍵依據。如果信心度校準不良，代理可能會在應該謹慎時過度自信，導致錯誤決策被直接採用；也可能在應該快速行動時過度保守，浪費 System-2 的推理資源。因此，可靠的信心度不僅影響決策品質，也直接決定端到端搜尋的延遲與答案準確率。

## 方法與創新（Method & Innovation）

**Q4：SearchJev 的核心方法架構是什麼？**
A：SearchJev 的核心是一個以決策綱要為條件的 System-1 搜尋決策模型，它會根據搜尋狀態與文字化的決策綱要，直接對合法選項進行評分。具體來說，模型將骨幹語言模型在第一個輸出詞元上的 logits，正規化到決策綱要所定義的合法選項標籤上，從而直接產生決策機率分布，完全避免自迴歸輸出生成。此外，SearchJev 還包含 SLCD 訓練方法與溫度校準，並在雙系統代理中將低信心決策委派給負責規劃、查詢生成與答案撰寫的 System-2。

**Q5：什麼是 SLCD，它如何提升決策品質與校準？**
A：SLCD（Soft-Label Learning for Calibrated Decisions）是一種針對不確定監督的軟標籤學習方法，用於訓練 SearchJev 的決策機率。由於搜尋決策的標註往往帶有不確定性，SLCD 使用軟標籤來表示這種不確定程度，並結合適當的評分損失進行訓練。訓練後再透過溫度校準進一步調整信心度，使得模型輸出的機率更能真實反映決策正確的機會，從而降低期望校準誤差。

**Q6：SearchJev 在設計上有哪些關鍵選擇？**
A：首先，作者選擇將頻繁的短期 System-1 決策與需要深度推理的 System-2 生成任務明確分離，讓兩者各司其職。其次，他們採用決策綱要來統一描述不同類型的搜尋決策與其合法選項，使單一模型能處理異質決策。最後，SearchJev 不採用 JSON 等自迴歸輸出格式，而是直接對第一個輸出詞元的 logits 進行正規化，這是達成 5 倍以上決策加速的關鍵。

## 實驗與結果（Experiments & Results）

**Q7：論文使用了哪些基準來評估 SearchJev？**
A：論文提出了 SearchDecision-Bench，這是一個統一的搜尋決策基準，涵蓋路由、改寫、相關性、充分性、導覽與驗證等六種決策類型，並包含選擇題、評分與是非判斷三種輸出類型。該基準將來自不同來源的異質監督資料轉換為共同的狀態—綱要格式，並保留保留資料集與保留分割以評估泛化能力。在端到端層面，作者則使用 BrowseComp-Plus 來評估主動搜尋時間、輸出詞元數與答案準確率。

**Q8：SearchJev 在決策層級與代理層級取得了哪些關鍵結果？**
A：在 SearchDecision-Bench 上，與同尺寸的 Qwen3.5 自迴歸（JSON）模型相比，SearchJev 提升了決策品質，決策速度快了 5.2–5.3 倍，並將平均期望校準誤差降低 41–74%。在 BrowseComp-Plus 上，結合 SearchJev 的雙系統代理相較於僅使用 System-2 的代理，主動搜尋時間加速 3.7–4.7 倍，輸出詞元減少 3.3–4.8 倍，同時答案準確率從 45% 提升至最高 54%。這些結果顯示 SearchJev 同時改善了效率、校準與端到端準確率。

**Q9：從實驗設計來看，哪些因素分別貢獻了速度與校準的改善？**
A：速度提升主要來自於 SearchJev 直接對合法選項評分，而非透過自迴歸方式逐詞元生成 JSON 判斷，這消除了循序解碼帶來的開銷。校準改善則主要歸功於 SLCD 的軟標籤學習與後續的溫度校準，使模型能從不確定監督中學到更可靠的決策機率。此外，決策綱要所提供的結構化條件也有助於統一不同決策類型，進一步提升泛化與決策品質。

## 應用與影響（Applications & Impact）

**Q10：SearchJev 在實務上可以應用在哪些場景？**
A：SearchJev 特別適合需要頻繁進行微判斷的代理式搜尋系統，例如網頁搜尋助理、研究文獻探索工具、企業知識庫問答與客戶支援機器人。在這些場景中，代理需要不斷判斷檢索結果是否相關、證據是否足夠、下一步該點擊哪個連結，SearchJev 可以快速完成這些 System-1 決策。只有當模型對某個判斷缺乏信心時，才會觸發大型的 System-2 模型進行深度推理，從而降低整體延遲與成本。

**Q11：若要將 SearchJev 落地到產品中，需要考慮哪些因素？**
A：產品團隊需要為每個代理動作設計清晰且完整的決策綱要，確保合法選項能正確對應到實際業務需求。同時必須根據應用場景設定適當的信心度門檻，在「自動化率」與「正確率」之間取得平衡，例如對高風險判斷採用較保守的委派策略。此外，由於模型校準可能隨資料分布變化而退化，產品上線後應持續監控期望校準誤差，並定期以新資料進行溫度校準或微調。

**Q12：這項研究對整個代理式 AI 領域可能帶來什麼影響？**
A：SearchJev 展示了將 System-1 快速決策與 System-2 深度推理分離的具體架構，為未來的代理設計提供了一個可擴展的範式。它證明了輕量且校準良好的決策模型可以在不犧牲準確率的前提下顯著加速搜尋代理，這可能促使更多研究者與工程師重新思考「所有判斷都應由大型生成模型完成」的預設。更廣泛地說，這種雙系統分工思路也可延伸至工具使用、機器人控制與多步推理等其他需要頻繁微決策的領域。

## 限制與未來方向（Limitations & Future）

**Q13：SearchJev 目前有哪些潛在限制？**
A：SearchJev 目前主要處理由決策綱要預先定義的搜尋決策，對於需要開放式生成或創造性推理的任務仍須依賴 System-2。其效能也高度依賴決策綱要的設計品質與監督資料的可靠性，若綱要不完整或標註有偏誤，軟標籤學習的效果可能會受影響。此外，作為一個輕量的 System-1 模型，它在面對需要多跳推理或高度語境理解的細微判斷時，仍可能不如大型生成模型。

**Q14：在哪些情況下 SearchJev 可能會失敗或表現不佳？**
A：當證據本身含糊不清、需要跨文件進行多跳推理，或決策綱要無法清楚表達正確選項時，System-1 模型可能產生錯誤或過度不確定的判斷。如果信心度門檻設定不當，可能導致過多正確決策被不必要地委派給 System-2，或過多錯誤決策被錯誤接受。另外，在訓練資料分布以外的極端案例上，模型的校準可能會退化，使得信心度不再可靠。

**Q15：未來可以朝哪些方向延伸 SearchJev？**
A：未來可以將 SearchJev 擴展到更多類型的決策與多模態輸入，例如圖片、表格或結構化資料庫查詢。另一個方向是發展線上校準與適應機制，使模型能根據實際運行中的回饋動態調整信心度與委派門檻。此外，也可以將 SearchJev 與強化學習結合，讓雙系統代理在主動搜尋過程中學習最優的決策與查詢策略，或探索如何從更強大的教師模型蒸餾出更輕量且校準良好的 System-1 決策模型。

## 實務應用指南

### 適用場景

1. **企業內部知識搜尋助理**  
   員工在查詢技術文件、政策或過往專案時，代理需要頻繁判斷「這段內容是否相關？」「證據是否已足夠回答？」「下一步該搜尋、閱讀頁面還是給答案？」。SearchJev 可在毫秒級完成這些 System-1 決策，並把不確定判斷交給較大的 System-2 模型進行推理與答案撰寫。

2. **客戶支援對話代理**  
   在對話過程中，代理需持續做意圖分類、查詢改寫、檢索需求評估與下一步動作選擇。SearchJev 可統一處理這些異質決策，並透過校準良好的信心度決定何時詢問澄清、何時直接回覆，降低延遲與幻覺風險。

3. **研究文獻回顧與事實查核代理**  
   文獻搜尋代理需要在大量論文間判斷文件品質、相關性、證據充分性，並驗證主張是否被支持。SearchJev 的 verification 與 sufficiency 決策可加速篩選，並把高不確定性的主張驗證委派給 System-2 深度推理。

4. **電商產品探索與導購代理**  
   使用者的查詢常含糊或需要改寫，代理需判斷查詢清晰度、意圖、查詢等價性與下一步導航行為。SearchJev 可快速決定是否改寫查詢、推薦商品或請使用者補充條件，提升互動流暢度。

5. **法律與合規文件審查代理**  
   在審查合約或法規時，代理需判斷某條文是否為特定主張的證據、文件來源是否權威、證據是否充分。SearchJev 的 relevance、document quality 與 claim verification 決策可加速初篩，並把邊界案例交給專業人員或 System-2 複查。

### 實作前置條件

**資料條件**
- 已整理好的搜尋軌跡資料，包括查詢、已開啟文件、中間筆記與候選文件/連結。
- 各決策類型的標註或弱監督訊號，例如相關性標籤、是否足夠回答、下一步動作、主張驗證結果等。
- 決策綱要（decision schema）定義：每個決策欄位的自然語言問題與合法選項集合。
- 若標註存在不確定性，需準備軟標籤（soft label）或機率型標註，以便使用 SLCD 訓練。

**運算條件**
- 訓練：至少一張可載入 Qwen3.5-0.8B 或 4B 級別模型的 GPU（如 A100/L40 等），並能進行 LoRA 或全參數微調。
- 推理：SearchJev 僅需對第一個輸出詞元（first-output-token）計算 logits，延遲極低，可在單張 GPU 甚至 CPU 批次部署。
- System-2 模型：需可呼叫較大的 LLM API 或本地部署的 27B 級模型，用於處理被委派的不確定判斷與最終答案生成。

**技術與人才條件**
- 熟悉 Transformer 模型微調、損失函數設計與校準技術（如 temperature scaling）。
- 具備代理系統開發經驗，能設計狀態表示、決策綱要與委派邏輯。
- 能建立評估流程，包括決策品質、期望校準誤差（ECE）與端到端答案準確率。

---

### 實作步驟建議

1. **定義決策綱要與狀態格式**  
   根據產品需求，從 SearchDecision-Bench 的六種決策類型（routing、rewriting、relevance、sufficiency、navigation、verification）中選出需要的子集，為每個決策設計 schema：欄位名稱、自然語言問題、合法選項與輸出類型（choice / Noul / score）。

2. **收集與轉換監督資料**  
   將現有搜尋日誌、人工標註或規則產生的標籤，轉換為統一的 `(search state, schema, target)` 格式。對於不確定標註，將其轉為軟標籤機率分佈，作為 SLCD 的訓練目標。

3. **訓練 SearchJev 模型**  
   以 Qwen3.5-0.8B 或 4B 為骨幹，使用 SLCD 進行微調：對合法選項的 first-output-token logits 做正規化，並以 proper scoring loss（如 cross-entropy 對應軟標籤）學習決策機率。訓練後進行 temperature calibration，進一步降低 ECE。

4. **設定 System-1 / System-2 委派機制**  
   定義信心度門檻（例如 entropy 或最大機率門檻）。當 SearchJev 對某決策的信心低於門檻，或該決策本身屬於高風險類型（如 claim verification），則將完整狀態與問題交給 System-2 模型進行推理與生成。

5. **整合進代理流程**  
   在代理的搜尋迴圈中，以 SearchJev 取代原本由 LLM 自迴歸生成的簡短判斷；保留 System-2 負責規劃、查詢生成與答案組成。確保狀態更新與 schema 呼叫能批次化，以發揮速度優勢。

6. **評估與迭代**  
   先在 SearchDecision-Bench 的同尺寸與保留分割上評估決策品質與校準誤差；再於端到端基準（如 BrowseComp-Plus）測量主動搜尋時間、輸出詞元數與答案準確率。根據錯誤案例調整 schema、軟標籤策略與委派門檻。

---

### 潛在風險與注意事項

- **過度自信（overconfidence）**：即使 SearchJev 已透過 SLCD 與 temperature calibration 改善，仍可能在高風險決策上過度自信。建議對關鍵決策保留強制委派至 System-2 的規則，而非僅依賴機率門檻。
- **綱要覆蓋不足**：若產品場景出現訓練時未涵蓋的決策類型或選項，模型可能輸出非法選項或機率分佈失真。應在 inference 時強制遮罩（mask）非法選項，並持續擴充 schema。
- **分佈偏移（distribution shift）**：訓練資料來自特定領域時，部署到新領域可能導致校準失效。建議上線後持續監控 ECE，並定期用新資料重新校準 temperature。
- **錯誤連鎖（error propagation）**：System-1 的錯誤決策會影響後續檢索與 System-2 推理。可透過在軌跡層級加入「自我驗證」或「回溯」機制來降低影響。
- **延遲與品質權衡**：雖然 SearchJev 可達 5× 以上加速，但過度降低 System-2 參與度可能損及答案準確率。需根據產品容忍度動態調整委派門檻。

---

### 與其他技術的整合建議

- **檢索與重排系統**：SearchJev 可與現有向量資料庫、關鍵字檢索器及重排模型（reranker）並行運作。建議將 SearchJev 用於「是否進一步檢索」與「候選文件是否相關」的快速判斷，而重排模型專注於粗篩後的精細排序。
- **代理框架（LangChain、LlamaIndex 等）**：可將 SearchJev 包裝為一個快速決策工具節點，並在框架內設定條件邊緣：當 SearchJev 信心不足時，路由至 System-2 LLM 節點。
- **監控與可解釋性平台**：由於 SearchJev 輸出的是決策機率分佈，容易視覺化每個決策的信心度。建議將這些機率寫入日誌，供後續分析校準漂移與錯誤模式。
- **人機協作（Human-in-the-loop）**：對於校準不良或高風險的決策，可設計人工審核佇列。SearchJev 的信心度可直接作為優先排序依據。
- **System-2 LLM 服務**：建議將 System-2 模型以非同步或佇列方式呼叫，避免阻塞 System-1 的快速決策流程；同時可對常見的不確定案例建立快取。

### 給不同背景讀者的閱讀建議

**給初學者**  
這篇論文提出了一個「讓 AI 搜尋代理做快速判斷」的方法。你可以把 SearchJev 想像成一個專門回答選擇題的小模型，它不看長篇大論地生成文字，而是直接對選項打分數，並告訴你它有多確定。建議先讀「適用場景」與「實作步驟建議」，理解它如何讓搜尋變快、變準，再回頭看技術名詞。

**給 AI 工程師**  
重點關注 SearchJev 的 inference 方式：只取 first-output-token logits 並在合法選項上正規化，這讓它遠比自迴歸 JSON 輸出更快。SLCD 結合軟標籤與 temperature calibration 的實作細節，以及如何在代理流程中設計委派門檻，都是可直接落地的技術。建議搭配論文中的 SearchDecision-Bench 資料格式進行實驗。

**給研究人員**  
本文的核心貢獻在於將 System-1 / System-2 的分工形式化到搜尋代理中，並以型別化機率（typed probability）與決策綱要統一異質搜尋決策。可進一步探索的方向包括：更細緻的校準方法、動態委派策略、多步決策的錯誤傳播分析，以及將此框架擴展到非搜尋領域的代理決策。

**給產品經理**  
這項技術的商業價值在於「用更小、更快的模型處理大量重複判斷，只在必要時呼叫昂貴的大模型」。它能顯著降低延遲與 API 成本，同時維持甚至提升答案準確率。評估時請同時關注使用者體驗指標（回應速度）與品質指標（答案準確率、人工複核率），並預留 schema 擴充與門檻調整的彈性。
