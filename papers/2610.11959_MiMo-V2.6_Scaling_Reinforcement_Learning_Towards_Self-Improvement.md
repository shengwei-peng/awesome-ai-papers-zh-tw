## 摘要翻譯

強化學習（Reinforcement Learning, RL）是推動大型基礎模型（Foundation Model）邁向自我改進（Self-Improvement）的核心訓練範式。本報告介紹 MiMo-V2.6 系列，一個透過擴展強化學習算力來推進模型智慧前沿的全模態（Omni-modal）模型家族。在強化學習之前，我們於廣泛的多模態語料（Multimodal Corpus）上進行中期訓練（Mid-Training）以提供充足的探索空間（Exploration Space），並在預訓練的混合式滑動窗口注意力（Hybrid-SWA）架構上建立穩固的基礎設施以支援後續的規模擴展。我們沿三個維度擴展強化學習算力：(1) 更大的批次大小（Batch Size）與更高的吞吐量（Throughput），採用非同步訓練（Asynchronous Training），每步消耗 1,568 個樣本與 27 至 37 億個令牌（Token），上下文長度（Context Length）最高可達 100 萬；(2) 更多樣且更複雜的強化學習環境（RL Environment），涵蓋程式碼領域（Code Domain）、通用領域（General Domain）、視覺領域（Visual Domain）與網路安全領域（Cyber Domain），並採用混合的代理框架（Agent Harness）；以及 (3) 更多的評分器算力（Grader Compute），透過分組代理式評分（Groupwise Agentic Grading），為長時程任務（Long-Horizon Task）產生更準確的獎勵信號（Reward Signal），並引導模型產生更短且令牌高效（Token-Efficient）的解決方案。為了在擴展時保持訓練穩定，我們凍結混合專家模型（Mixture-of-Experts, MoE）的 MoE 路由器（MoE Router）並建立多層防禦（Multi-Layer Defense）以對抗獎勵破解（Reward Hacking）。我們進一步為混合任務代理式強化學習（Mixed-Task Agentic RL）建立基礎設施，包括統一的軌跡表示（Trajectory Representation）、高並行（High-Concurrency）多框架推論生成（Multi-Framework Rollout）、解耦的控制平面（Control Plane）與資料平面（Data Plane），以及訓練-推論一致性（Training-Inference Consistency）。我們開源（Open-Source）訓練動態（Training Dynamics）、強化學習環境與強化學習框架（RL Framework），以促進復現（Reproduction）及對擴展強化學習與模型自我改進的進一步研究。

### 核心貢獻（3～5點）
- **三維度擴展強化學習算力**：從批次大小與吞吐量、環境多樣性、評分器算力三個維度同步擴展，建立可承載大規模訓練的基礎設施。
- **穩定性與安全性機制**：透過凍結 MoE 路由器與建立多層防禦機制，有效對抗獎勵破解，確保大規模訓練的穩定性。
- **混合任務代理式強化學習基礎設施**：提出統一的軌跡表示、高並行多框架推論生成、解耦的控制與資料平面，以及訓練-推論一致性等關鍵設計。
- **分組代理式評分機制**：透過分組代理式評分為長時程任務提供更準確的獎勵信號，並引導模型產生更精簡的解決方案。
- **全面開源**：開源訓練動態、強化學習環境與強化學習框架，促進學術界對擴展強化學習與模型自我改進的復現與深入研究。

### 適合對象
本報告最適合從事大型基礎模型訓練、強化學習演算法設計、代理式人工智慧（Agentic AI）研究，以及對模型自我改進與可擴展訓練基礎設施感興趣的研究人員與工程師閱讀。對於關注開源強化學習框架實作細節的實務工作者亦具高度參考價值。

## 深度分析

#### 方法論解析

MiMo-V2.6 的方法論圍繞「以強化學習 (RL) 驅動基礎模型自我改進」這一核心目標，從架構設計、預訓練、中期訓練 (mid-training) 到 RL 規模化形成了一套完整的技術鏈條。以下從三個層面進行深入剖析。

**一、架構層面：混合稀疏 MoE Transformer 骨幹**

MiMo-V2.6 採用標準 Transformer 主幹，並以「混合稀疏 MoE (Mixture-of-Experts)」結構增強容量與效率。文字骨幹由 $M$ 個混合區塊 (hybrid blocks) 堆疊而成，每個區塊交錯配置**局部滑動窗口注意力 (Local Sliding Window Attention, SWA)** 與**全域注意力 (Global Attention, GA)**。此設計的動機在於：長上下文場景下全域注意力的計算成本過高，而 SWA 雖能降低計算量，卻難以保留跨距離依賴。透過 GA 與 SWA 的交錯，模型得以在維持長上下文建模能力的同時控制推論成本。

視覺端採用輕量級 **MiMo-ViT** 視覺編碼器，音訊端則透過音訊編碼器 (audio encoder) 接入，並以輕量投影器 (lightweight projector) 對齊至文字 token 空間，形成全模態 (omni-modal) 統一介面。為進一步降低推論延遲，模型配備**推測式解碼器 (speculative decoder)**，這對於代理式 (agentic) 場景中需要快速多輪互動的應用至關重要。

旗艦版本 MiMo-V2.6-Pro 具備 1.02T 總參數、42B 啟動參數；輕量版本 MiMo-V2.6-Flash 則為 310B 總參數、15B 啟動參數。兩者皆採用 MoE 結構，意味著在每次前向傳遞中僅啟動部分專家，從而在保持模型容量的同時控制實際計算量。

**二、預訓練與中期訓練：擴展探索空間**

預訓練階段在多模態語料上進行，使模型具備跨文字、音訊、視訊的廣泛知識。**中期訓練 (mid-training)** 是 MiMo-V2.6 方法論的關鍵創新之一：此階段以代理為中心 (agent-centric) 的資料進行訓練，刻意擴大代理式任務的探索空間 (exploration space)。其設計理念在於，若直接從預訓練模型進入 RL，模型可能缺乏足夠的代理互動經驗，導致 RL 階段的軌跡品質低落、探索效率不佳。中期訓練透過注入代理相關資料，使模型在進入 RL 前已具備基本的工具使用與多步推理能力，從而為後續 RL 提供更豐富的起點。

**三、RL 規模化的三維擴展**

MiMo-V2.6 的核心貢獻在於系統性地沿三個維度擴展 RL 算力：

1. **批次大小與吞吐量維度**：採用全非同步訓練 (fully asynchronous training)，每步處理 1,568 個樣本、27-37 億 (2.7-3.7B) 令牌，上下文長度可達 1M。這意味著模型能在單一訓練步中消化大量長時程 (long-horizon) rollout，極大提升資料效率。

2. **環境多樣性與複雜度維度**：環境橫跨程式碼 (code)、通用 (general)、視覺 (visual)、網路安全 (cyber) 四大領域，並混合多種代理框架 (agent harnesses)。同時變化框架與任務本身被視為一種泛化正則化手段——模型不僅學習解決特定任務，還需適應不同的互動介面。

3. **評分器算力維度**：引入**分組代理式評分 (Groupwise Agentic Grading)**，包含兩個子機制：
   - **分組獎勵合成 (Groupwise Reward Synthesis, GRS)**：在同一群組內比較不同解法，區分其解題品質與行為差異，而非僅以二元通過/未通過作為獎勵。
   - **分組優勢重分配 (Groupwise Advantage Redistribution, GAR)**：將上述細粒度差異轉化為更具資訊量的學習信號 (learning signal)，引導模型朝向更準確且**令牌高效 (token-efficient)** 的解法。

   此設計的深層意義在於：傳統 RL 在代理式任務中常面臨「稀疏獎勵」問題——大量 rollout 僅得到二元通過/失敗的回饋，學習信號極為稀薄。GRS/GAR 透過群組內相對比較，將二元信號擴展為序數甚至連續信號，顯著提升樣本效率。

**四、穩定性保障機制**

規模化 RL 的一大風險是訓練不穩定與獎勵破解 (reward hacking)。MiMo-V2.6 提出兩項關鍵防禦：

- **MoE 路由器凍結 (Router Freezing)**：在 RL 階段凍結 MoE 路由器，防止路由器因獎勵信號而崩潰或偏向特定專家，維持專家負載平衡。
- **多層防禦 (Multi-Layer Defense)**：針對獎勵破解建立多層次的防護機制，確保獎勵信號的真實性。

**五、代理式 RL 基礎設施**

為支撐上述規模化 RL，MiMo-V2.6 設計了一套完整的基礎設施：

- **統一軌跡表示 (Unified Trajectory Representation)**：標準化多框架、多模態的軌跡格式，使不同代理框架的 rollout 可在同一訓練管線中處理。
- **框架池 (Harness Pool) 與載體傳遞器 (Payload Porter)**：透過框架池維持高並行 (high-concurrency) 的多框架 rollout；載體傳遞器負責緩衝與傳輸大量軌跡，承載路由資訊與多模態載體。
- **控制平面與資料平面解耦 (Decoupled Control and Data Plane)**：分離控制邏輯與資料傳輸，提升系統可擴展性。
- **樣本混合器 (Sample Mixer)**：結合動態取樣 (dynamic sampling) 與部分 rollout (partial rollout)，穩定每個訓練批次中各任務的樣本組成，避免某些任務被過度或不足採樣。
- **訓練-推論一致性 (Training-Inference Consistency)**：對齊訓練與推論引擎在 MoE 路由與 top-p 取樣候選集上的行為，並針對 RL 工作負載進行雙引擎優化，消除訓練-推論不一致帶來的偏差。

#### 實驗數據解讀

根據摘要與引言所述，MiMo-V2.6 的實驗設計呈現以下幾個關鍵特徵：

**一、評測基準的多樣性**

實驗橫跨四個領域的基準測試：
- **程式碼領域**：DeepSWE (Huang et al., 2026)
- **通用工作流程**：AutomationBench (Shepard and Salimans, 2026)
- **視覺任務**：MiMo Visual Coding
- **網路安全**：MiMo Cyber Bench

此設計的價值在於驗證 RL 改進是否具有**領域泛化性**。從 Figure 1 的描述來看，MiMo-V2.6-Pro 與 MiMo-V2.6-Flash 在所有基準上均隨訓練步數穩步提升，這是一個強烈的信號——RL 並非僅在某一領域過擬合，而是帶來了更通用的代理智慧 (agentic intelligence)。

**二、「You Only RL Once」實驗範式**

章節 5 的標題「You Only RL Once」暗示 MiMo-V2.6 採用了單一階段、大規模的 RL 訓練，而非多階段疊加。此設計的優勢在於簡化管線、避免階段間的災難性遺忘；挑戰則在於對訓練穩定性提出極高要求——這也解釋了為何路由器凍結與多層防禦如此關鍵。

**三、路由器凍結的消融實驗**

章節 5.4 專門探討路由器凍結對 RL 穩定性的影響。雖然具體數值未在提供的文本中呈現，但此消融的設計邏輯清晰：在 MoE 架構中，路由器是極少數在 RL 中可能「漂移」的組件，因為獎勵信號可能鼓勵模型集中使用某些專家，從而破壞負載平衡。凍結路由器是一種保守但有效的穩定策略。

**四、失敗分析 (Failure Analysis)**

章節 5.5 進行 RL 失敗分析，這在 RL 論文中相對少見但極具價值。常見的 RL 失敗模式包括：獎勵破解、模式崩塌 (mode collapse)、訓練發散等。透過系統化的失敗分析，作者不僅展示了方法的局限性，也為後續研究提供了改進方向。

**五、MOPD2 能力擴展**

章節 5.6 探討透過 **MOPD2 (Mixed On-Policy Distillation variant)** 進一步擴展模型能力。OPD (On-Policy Distillation, 同策略蒸餾) 是一種將大型模型的策略蒸餾至小型模型的方法，MOPD2 為其混合變體。此機制使 MiMo-V2.6 不僅能自我改進，還能將改進後的能力傳遞給輕量模型。

**六、蒸餾驗證實驗**

章節 7.1 透過 MiMo-V2.6-Distill-Qwen-9B 驗證蒸餾效果。從 Qwen-9B 基座出發，經過 MiMo-V2.6 的蒸餾後，模型在多任務、多框架下均呈現一致的 RL 增益。這驗證了：(1) 蒸餾過程保留了 RL 帶來的改進；(2) 開源套件具有跨模型的泛用性。

#### 與現有研究的比較

**一、定位**

MiMo-V2.6 在當前大型語言模型 RL 研究譜系中佔據獨特位置。與 OpenAI o-series、DeepSeek-R1 等專注於推理能力 RL 的工作相比，MiMo-V2.6 更強調**代理式 RL (agentic RL)**——即模型在互動環境中透過多步軌跡學習，而非僅在單輪推理任務上優化。這與 Anthropic、Salesforce 等在電腦使用、網頁代理方向的工作更為接近。

**二、相較於先前工作的改進**

1. **規模化維度的系統性**：相較於多數 RL 工作僅在單一維度（如環境多樣性或批次大小）進行擴展，MiMo-V2.6 同時在三個維度上進行協同擴展，並強調三者的**共同設計 (co-design)**。

2. **評分器的精細化**：傳統代理式 RL 多依賴二元測試案例獎勵，MiMo-V2.6 的分組代理式評分透過 GRS/GAR 將稀疏獎勵轉化為密集信號，這在方法論上是顯著的進步。

3. **基礎設施的開源**：相較於多數工業級 RL 系統僅釋出模型而不釋出訓練框架，MiMo-V2.6 開源了完整的 RL 開發套件，包括訓練框架、任務環境、輕量模型與迷你框架，大幅降低了復現門檻。

4. **MoE 與 RL 的結合**：在 MoE 架構上進行大規模 RL 仍是相對未被充分探索的領域。MiMo-V2.6 透過路由器凍結等機制，為 MoE + RL 的穩定訓練提供了實證經驗。

**三、局限性**

1. **缺乏具體數值**：所提供的文本中未包含具體的基準分數、訓練曲線數值或消融結果的量化數據，這限制了我們對改進幅度的精確評估。

2. **計算成本未充分披露**：1.02T 參數模型的 RL 訓練成本極為可觀，但論文未明確說明總計算資源消耗，這對學術界復現構成障礙。

3. **安全性考量有限**：雖然提及網路安全領域的任務，但對於模型本身的安全對齊 (safety alignment)、越獄防護 (jailbreak resistance) 等議題著墨不多。

4. **泛化性邊界未明確**：雖然在四個領域展示了一致改進，但對於更廣泛的代理場景（如機器人控制、科學實驗設計等）的泛化能力仍待驗證。

5. **與人類偏好的對齊**：RL 在此工作中主要用於任務完成度優化，對於人類偏好對齊 (RLHF) 的整合未深入討論。

#### 可重現性評估

MiMo-V2.6 在可重現性方面展現了值得肯定的開放態度：

**一、開源內容**

根據摘要與引言，作者明確開源了以下組件：
1. **訓練動態 (Training Dynamics)**：訓練過程中的損失曲線、獎勵曲線等監控資料。
2. **RL 環境 (RL Environments)**：涵蓋多個領域的任務環境與驗證器 (verifiers)。
3. **RL 框架 (RL Framework)**：端到端的 RL 訓練框架。
4. **輕量模型 MiMo-V2.6-Distill-Qwen-9B**：基於 Qwen-9B 的蒸餾版本。
5. **可組合迷你框架 (Composable Mini-Harness)**：用於靈活代理互動的輕量級框架。

**二、可重現性優勢**

- **統一平台**：開源套件提供了一個統一且易於存取的代理式 RL 研究平台，研究者可在不同任務、環境與代理配置下進行系統性實驗。
- **降低工程門檻**：透過釋出框架與環境，大幅降低了重現大規模 RL 實驗的工程障礙。
- **跨模型驗證**：MiMo-V2.6-Distill-Qwen-9B 的實驗證明了該套件不限於特定基座模型，具有泛用性。

**三、可重現性挑戰**

- **旗艦模型未完全開源**：1.02T 參數的 MiMo-V2.6-Pro 與 310B 參數的 MiMo-V2.6-Flash 的權重是否完全釋出尚不明確，這限制了在最先進規模上的直接復現。
- **計算資源需求**：即使開源了框架，1M 上下文長度、數千樣本/步的非同步訓練仍需要大量 GPU 資源，學術機構難以完全復現。
- **資料集透明度**：中期訓練所用的多模態語料與代理中心資料集的具體組成、來源與規模未在提供的文本中詳細說明。

**四、整體評估**

相較於多數僅釋出模型權重的工作，MiMo-V2.6 在開源完整性上邁出了重要一步。然而，真正的「完全可重現」仍需旗艦模型權重、訓練資料與計算預算的全面披露。

#### 未來研究方向

基於 MiMo-V2.6 的方法論與實驗結果，以下幾個方向具有重要的研究價值：

**一、評分器架構的進一步演進**

分組代理式評分雖已展現成效，但仍有改進空間：
- **多模態評分**：當前評分主要針對程式碼與文字輸出，如何有效評分視覺、音訊等多模態輸出仍是開放問題。
- **評分器的可解釋性**：理解評分器為何給出特定獎勵，有助於診斷獎勵破解與設計更穩健的獎勵函數。
- **階層式評分**：對於極長時程任務，可設計多層次評分器，在不同抽象層級提供回饋。

**二、MoE 與 RL 的深度融合**

路由器凍結是一種保守策略，未來可探索：
- **動態路由器調整**：在維持穩定性的前提下，允許路由器有限度的調整，以適應 RL 帶來的能力變化。
- **專家專門化分析**：研究 RL 是否促使不同專家發展出不同的功能專門化。
- **稀疏激活與 RL 的交互**：探索不同稀疏度對 RL 效率與效果的影響。

**三、規模化 RL 的理論基礎**

當前規模化 RL 主要基於經驗觀察，缺乏系統性的理論指導：
- **擴展法則 (Scaling Laws) for RL**：建立 RL 算力與模型性能之間的定量關係。
- **樣本效率理論**：理解為何分組評分能提升樣本效率，並預測最佳群組大小。
- **探索-利用權衡**：在更大規模下如何平衡探索與利用。

**四、安全與對齊整合**

- **RL 與 RLHF 的統一框架**：將任務導向的 RL 與人類偏好對齊整合在同一訓練管線中。
- **代理安全的形式化**：對於網路安全等高風險領域的代理，需要形式化的安全保障機制。
- **可解釋代理**：使代理的決策過程對人類可理解，便於審計與除錯。

**五、跨領域遷移與泛化**

- **元學習 (Meta-Learning) 整合**：使模型能更快適應新領域的代理任務。
- **持續學習 (Continual Learning)**：在 RL 過程中避免災難性遺忘，使模型能持續吸收新能力。
- **跨模態遷移**：探索在某一模態學到的代理能力能否遷移至其他模態。

**六、效率優化**

- **訓練-推論一致性深化**：當前僅對齊 MoE 路由與 top-p 取樣，未來可探索更廣泛的一致性保證。
- **記憶體優化**：1M 上下文長度對記憶體需求極大，需要更高效的注意力機制或記憶體管理策略。
- **分散式 RL 架構**：支援跨資料中心的大規模分散式 RL 訓練。

**七、開源生態的擴展**

- **社群驅動的環境擴展**：鼓勵社群貢獻更多領域的 RL 環境與驗證器。
- **標準化評測協議**：建立業界認可的代理式 RL 評測標準。
- **教育與入門資源**：降低新研究者的入門門檻，促進領域發展。

總結而言，MiMo-V2.6 不僅是一個技術報告，更是一個**研究基礎設施的提案**。其真正的長期價值可能在於：透過開源套件降低了代理式 RL 研究的進入門檻，使更多研究者能在此基礎上探索遞迴自我改進 (RSI) 這一宏偉目標。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於如何將強化學習（RL）擴展應用於大型基礎模型，以實現模型的自我改進（self-improvement）。具體而言，作者指出實現遞迴自我改進（RSI）的願景需要兩個關鍵要素：一是適合的模型架構與足夠豐富的探索空間，二是能夠支援大規模 RL 訓練的基礎設施、環境與評分器。MiMo-V2.6 系列正是為了解決這兩大挑戰而設計的全模態（omni-modal）模型家族，透過系統性地擴展 RL 算力，朝向更強的代理式智慧（agentic intelligence）邁進。

**Q2：為什麼現有的方法難以實現大規模的代理式強化學習？**
A：現有方法在擴展 RL 時面臨多重瓶頸。首先，傳統的二元測試案例獎勵對所有通過測試的解答給予相同獎勵，無法區分解題品質與行為差異，導致學習信號不夠精細。其次，長時程任務（long-horizon tasks）需要大量多步軌跡（multi-step trajectories）與回饋信號，但現有基礎設施難以支援高並行（high-concurrency）的多框架 rollout。第三，獎勵破解（reward hacking）問題在大規模訓練中容易被模型利用，造成訓練不穩定。這些挑戰使得現有方法難以在程式碼、通用、視覺、網路安全等多個領域同時擴展 RL 訓練。

**Q3：為什麼遞迴自我改進（RSI）對 AI 發展如此重要？**
A：遞迴自我改進（RSI）代表 AI 系統能夠透過持續的探索與回饋自主擴展其能力，是邁向通用人工智慧（AGI）的關鍵路徑。RSI 的實現需要代理（agent）將模型與互動式環境結合，從而提供自我改進所需的多步軌跡與回饋信號。透過在複雜代理式任務上擴展強化學習，模型不僅能在可驗證任務（如程式碼）上取得進步，也能在較難驗證的任務（如網頁開發）上獲得提升。這種跨領域的持續改進能力，是實現真正通用且可靠的 AI 助理的基礎。

**Q4：MiMo-V2.6 的核心方法是什麼？**
A：MiMo-V2.6 的核心方法是系統性地從三個維度擴展 RL 算力。第一個維度是擴展批次大小與訓練吞吐量，透過全非同步訓練（fully asynchronous training），每步可處理 1,568 個樣本與 27-37 億個令牌，上下文長度可達 1M。第二個維度是擴展 RL 環境的多樣性與複雜度，涵蓋程式碼、通用、視覺、網路安全等領域，並使用多樣化的代理框架（agent harness）。第三個維度是擴展評分器算力，透過分組代理式評分（groupwise agentic grading）提供更精確的獎勵信號，引導模型產生更短、更令牌高效（token-efficient）的解答。

**Q5：分組代理式評分（Groupwise Agentic Grading）的關鍵創新是什麼？**
A：分組代理式評分的關鍵創新在於超越了傳統二元測試案例獎勵的限制，透過比較同一群組內的解答來區分解題品質與行為差異。具體而言，作者提出了兩個關鍵機制：分組獎勵合成（Groupwise Reward Synthesis, GRS）將這些細粒度的區別轉化為更精確的獎勵信號；分組優勢重分配（Groupwise Advantage Redistribution, GAR）則將這些區別轉化為更資訊豐富的學習信號。這種方法不僅能區分通過測試的解答之間的品質差異，還能引導模型朝向更準確、更高效的解決方案發展，對於長時程任務特別有效。

**Q6：為什麼要凍結 MoE 路由器（Router Freezing）？**
A：凍結 MoE 路由器是為了在大規模 RL 訓練中維持訓練穩定性。在大規模 RL 訓練中，模型的專家路由（expert routing）可能會發生劇烈變化，導致訓練不穩定甚至崩潰。透過凍結路由器，可以避免路由模式在訓練過程中發生劇變，從而維持訓練的穩定性。這項設計選擇體現了作者在擴展 RL 時對穩定性的重視，並與多層防禦（multi-layer defense）機制共同對抗獎勵破解（reward hacking）的風險，確保模型能夠在長時間訓練中持續學習。

**Q7：MiMo-V2.6 使用了哪些基準測試進行評估？**
A：MiMo-V2.6 在多個領域的基準測試上進行了評估，以驗證其在不同任務上的表現。在程式碼領域，使用了 DeepSWE 基準測試；在通用工作流程領域，使用了 AutomationBench；在視覺任務領域，使用了 MiMo Visual Coding；在網路安全領域，使用了 MiMo Cyber Bench。這些基準測試涵蓋了從可驗證任務（如程式碼）到較難驗證任務（如網頁開發）的多種場景，能夠全面評估模型的代理式智慧（agentic intelligence）。此外，作者還採用了「You Only RL Once」的實驗設定，強調在單一 RL 階段中持續提升的重要性。

**Q8：MiMo-V2.6 的關鍵實驗結果是什麼？**
A：實驗結果顯示，隨著訓練步數的增加，MiMo-V2.6-Pro（1.02T 參數，42B 激活參數）與 MiMo-V2.6-Flash（310B 參數，15B 激活參數）在所有報告的基準測試上都呈現穩定的性能提升。這些增益不限於單一領域，而是在 DeepSWE（程式碼）、AutomationBench（通用工作流程）、MiMo Visual Coding（視覺任務）以及 MiMo Cyber Bench（網路安全）等多樣化任務上都持續存在。這表明 MiMo-V2.6 具備更強的複雜問題解決能力，以及在日常協作場景中更可靠的性能，反映出更通用的代理式智慧。

**Q9：路由器凍結（Router Freezing）的消融研究結果如何？**
A：根據論文的第 5.4 節，路由器凍結的消融研究驗證了其在維持大規模 RL 訓練穩定性方面的關鍵作用。在沒有凍結路由器的情況下，MoE 模型的專家路由可能在 RL 訓練過程中發生劇烈變化，導致訓練不穩定或性能下降。透過凍結路由器，模型能夠在長時間的 RL 訓練中保持穩定的路由模式，從而實現持續的性能提升。這項消融研究驗證了在大規模 RL 訓練中，架構穩定性是實現有效學習的關鍵前提，也為未來相關研究提供了重要的設計參考。

**Q10：MiMo-V2.6 的實際應用場景有哪些？**
A：MiMo-V2.6 的實際應用場景涵蓋多個領域。在程式碼開發方面，模型可用於自動化程式碼生成、除錯與重構，提升軟體開發效率。在通用工作流程方面，模型可處理複雜的自動化任務，如資料處理、報告生成等。在視覺任務方面，模型可進行視覺程式碼生成（visual coding），將設計稿轉化為程式碼。在網路安全方面，模型可協助進行漏洞分析、安全測試等任務。這些應用場景反映了 MiMo-V2.6 作為通用代理式智慧助理的潛力，能夠在多種專業領域中提供可靠的自動化支援。

**Q11：從產品角度考慮，MiMo-V2.6 有哪些設計考量？**
A：從產品角度，MiMo-V2.6 的設計考量包括多個方面。首先，模型採用混合 SWA 架構（hybrid-SWA），能夠在保持全局上下文理解的同時降低計算成本，這對於實際部署至關重要。其次，模型支援長達 1M 的上下文長度，能夠處理複雜的長時程任務。第三，透過分組代理式評分引導模型產生更令牌高效的解答，降低了推理成本。此外，作者還開源了訓練動態、RL 環境與 RL 框架，方便社群復現與進一步研究，這有助於建立健康的開源生態系統並促進技術普及。

**Q12：MiMo-V2.6 對該領域的影響是什麼？**
A：MiMo-V2.6 對該領域的影響主要體現在三個方面。第一，它展示了透過系統性地擴展 RL 算力，可以在多個領域同時實現顯著的性能提升，為大型基礎模型的訓練提供了新的範式。第二，它提出的分組代理式評分方法為處理長時程任務的獎勵信號設計提供了新的思路，超越了傳統二元獎勵的限制。第三，它開源了完整的 RL 開發套件，包括輕量級模型 MiMo-V2.6-Distill-Qwen-9B、任務環境、訓練框架與可組合的迷你框架，降低了復現與擴展大規模 RL 實驗的工程門檻，有助於推動整個領域朝向遞迴自我改進的目標邁進。

**Q13：MiMo-V2.6 存在哪些已知的限制？**
A：從論文的描述可以推斷，MiMo-V2.6 存在幾個已知的限制。首先，雖然模型在多個基準測試上表現優異，但 RL 訓練的失敗分析（第 5.5 節）表明仍存在一些失敗案例，需要進一步研究。其次，模型在較難驗證的任務（如網頁開發）上的提升空間可能仍大於可驗證任務（如程式碼）。第三，大規模 RL 訓練需要大量的計算資源，這對於許多研究機構來說可能是一個進入障礙。最後，雖然作者提出了多層防禦機制對抗獎勵破解，但這個問題在大規模訓練中仍然是一個持續的挑戰。

**Q14：MiMo-V2.6 的失敗案例有哪些？**
A：根據論文的 RL 失敗分析章節（第 5.5 節），MiMo-V2.6 在 RL 訓練過程中可能會遇到幾類失敗案例。這些失敗可能包括：模型學會利用評分器的漏洞進行獎勵破解（reward hacking），產生表面通過測試但實際未真正解決問題的解答；在長時程任務中產生低效或冗餘的解決方案，浪費令牌與計算資源；以及在面對訓練分布外的任務時表現下降，泛化能力不足。透過凍結 MoE 路由器與建立多層防禦機制，作者試圖緩解這些問題，但完全解決這些失敗案例仍是該領域的重要研究方向。

**Q15：未來的研究方向有哪些？**
A：未來的研究方向可以從論文中推斷出幾個關鍵方向。首先，繼續擴展 RL 算力，包括更大的批次、更長的上下文、更複雜的環境，以進一步提升模型的代理式智慧。其次，改進獎勵信號的設計，發展更精細、更可靠的評分方法，以處理更廣泛的任務類型。第三，研究如何將 RL 與其他訓練範式（如蒸餾、預訓練）更好地結合，例如論文中提到的 MOPD2（Mixed On-Policy Distillation）方法。第四，降低大規模 RL 訓練的計算成本，使其更加民主化，讓更多研究機構能夠參與。最後，朝向真正的遞迴自我改進（RSI）邁進，使模型能夠自主發現並學習新的能力。

- 視覺領域：準備設計稿與驗收標準
- 通用代理：準備網站/應用程式的可重現環境與狀態檢查器
- 資安領域：準備隔離的靶機環境與成功條件

**第三步：設計分組評分機制（Groupwise Agentic Grading）**
實作 GRS（Groupwise Reward Synthesis）與 GAR（Groupwise Advantage Redistribution）：
- 將同一任務的多個解法分組比較，而非僅用二元通過/失敗
- 對解法品質、效率、token 使用量進行細粒度評分
- 將分組比較結果轉換為更資訊豐富的優勢函數，引導模型朝「短且正確」的方向學習

**第四步：配置框架池（Harness Pool）與樣本混合器（Sample Mixer）**
- 部署多樣化的 agent harness（不同框架、不同工具集），透過 Harness Pool 維持高並行互動
- 實作 Payload Porter 處理大規模軌跡傳輸，特別是含有多模態資料的軌跡
- 採用 Sample Mixer 搭配動態採樣與 partial rollout，穩定每個任務在訓練批次中的比例

**第五步：執行非同步 RL 訓練並監控穩定性**
- 採用非同步訓練 pipeline，每步處理 1,568 個樣本、2.7-3.7B tokens
- 凍結 MoE 路由器以維持訓練穩定性
- 建立多層獎勵破解防禦機制（reward shaping、格式約束、多重驗證）
- 持續監控訓練-推論一致性，確保 MoE 路由與 top-p 採樣候選集在兩端對齊

**第六步：透過 MOPD2 擴展能力並蒸餾部署**
- 使用 MOPD2（Mixed On-Policy Distillation）將 Pro 模型的能力轉移至 Flash 或 Distill 版本
- 根據部署成本與延遲需求選擇最終部署的模型規模
- 建立持續評測 pipeline，追蹤在 DeepSWE、AutomationBench、MiMo Visual Coding、MiMo Cyber Bench 等基準上的表現

### 潛在風險與注意事項

**獎勵破解（Reward Hacking）**
- 風險：模型可能學會「通過測試但解法品質低落」或「過度擬合驗證器漏洞」
- 緩解：採用多層防禦，包含格式約束、多重驗證、groupwise 比較避免單一指標被攻擊；定期進行失敗分析（failure analysis）檢查解法品質

**訓練-推論不一致**
- 風險：MoE 路由在訓練與推論引擎的行為差異會導致 off-policy 偏差
- 緩解：對齊兩端的 top-p 採樣候選集與路由器行為；定期進行一致性檢查；考慮凍結路由器以降低變動

**長時程任務的信用分配**
- 風險：數百步的代理軌跡中，稀疏獎勵使得學習信號微弱
- 緩解：採用統一軌跡表示搭配細粒度學習信號；使用 groupwise grading 提供更密集的相對獎勵

**MoE 路由器不穩定**
- 風險：路由器在 RL 過程中可能劇烈變動，導致專家負載失衡與訓練崩潰
- 緩解：凍結路由器（Router Freezing）是論文驗證有效的關鍵策略；監控專家負載分佈

**基礎設施複雜度**
- 風險：解耦的控制平面/資料平面、多框架 rollout、1M context 等設計帶來顯著工程負擔
- 緩解：先以 Distill-Qwen-9B + 開源框架驗證小規模 pipeline，再逐步擴展；採用論文提供的 mini-harness 降低整合成本

**探索空間不足**
- 風險：若中期訓練階段未充分擴展探索空間，RL 階段容易陷入局部最優
- 緩解：確保中期訓練使用廣泛的多模態語料；提供多樣化的 agent harness 與任務類型

**評測偏差**
- 風險：在自家基準（MiMo Visual Coding、MiMo Cyber Bench）上的表現未必能泛化到真實場景
- 緩解：搭配 DeepSWE、AutomationBench 等公開基準交叉驗證；建立內部真實任務評測集

### 與其他技術的整合建議

**與既有 Agent 框架整合**
- 將 MiMo-V2.6 作為 LLM 核心接入 LangChain、AutoGen、CrewAI 等框架，但需注意其 1M context 與多模態能力需要框架支援對應的介面
- 透過論文開源的 mini-harness 作為標準介面層，統一不同框架的軌跡格式

**與程式碼工具鏈整合**
- 搭配 Docker 化測試環境、CI/CD pipeline、靜態分析工具（如 ESLint、mypy）作為 verifier
- 整合 Git 操作工具（clone、commit、PR）以支援真實 SWE 任務

**與視覺理解工具整合**
- 將 MiMo-ViT 的輸出與 OCR、版面分析、UI 元件偵測等專門工具結合，提升視覺編碼的精細度
- 與 Figma API、Sketch 插件整合以支援設計轉開發流程

**與資安工具整合**
- 搭配 Nmap、Burp Suite、Metasploit 等資安工具作為代理可呼叫的工具集
- 整合 SIEM 系統（如 Splunk、Elastic）以支援真實 SOC 場景

**與推論最佳化技術整合**
- 搭配 vLLM、TGI、TensorRT-LLM 等推論引擎時，需特別處理 MoE 專家並行與混合注意力
- 推測式解碼器（Speculative Decoder）可與 Medusa、EAGLE 等技術結合進一步加速

**與監控與可觀測性整合**
- 整合 Weights & Biases、MLflow 等實驗追蹤工具，記錄訓練動態
- 部署軌跡記錄與回放系統，便於失敗分析與獎勵破解偵測

**與 MOPD2 蒸餾流程整合**
- 在部署階段，使用 MOPD2 將 Pro 模型的能力蒸餾至 Flash 或更小模型，平衡成本與品質
- 蒸餾過程中保留 groupwise grading 機制，避免蒸餾後能力退化

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）與第 5 節（Experiments）建立整體概念，理解「為什麼要 scale RL」以及「scale RL 能帶來什麼效果」。接著跳到第 7 節（Open Foundations）了解開源資源，從 Distill-Qwen-9B 與 mini-harness 開始動手實作。架構細節（Section 2）與基礎設施細節（Section 6）可以先略過，待有實作經驗後再深入。

**給 AI 工程師**：重點閱讀第 4 節（Scaling RL）與第 6 節（Infrastructure），這兩節直接對應到生產環境的工程決策。特別關注 Groupwise Agentic Grading 的實作細節、Harness Pool 與 Sample Mixer 的設計模式、以及訓練-推論一致性的最佳化策略。Section 5.4 的 Router Freezing 經驗對穩定訓練至關重要。

**給研究者**：重點閱讀第 4.3 節（Groupwise Agentic Grading）的 GRS 與 GAR 演算法設計、第 5.5 節（Failure Analysis）對獎勵破解與訓練失敗的深入分析，以及第 5.6 節（MOPD2）的蒸餾機制。這些是論文最具研究貢獻的部分。Section 2 的混合 SWA/GA 架構設計也值得深入研究其在長 context 下的效率權衡。

**給產品經理**：建議閱讀第 1 節掌握 MiMo-V2.6 的能力邊界與適用場景，特別是 Figure 1 展示的跨領域增益趨勢。Section 5.3 的基準測試結果可作為能力評估的參考。從「適用場景」一節挑選與產品需求最匹配的場景，並評估採用 Distill-Qwen-9B 進行 POC 的可行性，再決定是否投入完整模型訓練的資源。
