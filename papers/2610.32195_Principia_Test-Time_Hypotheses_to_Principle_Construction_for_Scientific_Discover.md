Principia 框架的核心設計理念在於模擬人類科學家從觀察中歸納出科學原理的認知過程，並將此過程自動化為一個可在測試時（test-time）持續運行的知識建構系統。該框架由三個相互串聯的核心組件構成，形成一個完整的「假設→原理→驗證→修正」迭代循環。

**（一）比較性因果假設生成（Comparative Causal Hypothesis Generation）**

傳統的假設生成方法通常依賴單一輸入與其對應觀察結果來推論因果關係，但這種方式面臨嚴重的歸因模糊性（attribution ambiguity）問題——同一觀察結果可能由多種輸入特徵共同造成，LLM 無法有效區分哪些特徵才是真正的因果因素。Principia 採用「比較性」策略解決此問題：它並非分析單一觀察，而是同時取用多個相關輸入及其對應的實驗結果進行對比分析。透過比較這些輸入之間的「共享特徵」（shared characteristics）與「差異特徵」（differing characteristics），LLM 能夠將候選解釋空間大幅縮窄，從而生成更具針對性的因果假設。這種方法論上的設計借鑑了人類科學研究中「控制變量」與「對照實驗」的思維模式。

**（二）歸納性原理建構（Inductive Principle Construction）**

單一假設僅能解釋有限範圍內的個別觀察，無法形成具有泛化能力的科學原理。Principia 在此階段將多個相關輸入分組，並從這些輸入對應的假設中提取「循環出現的關係」（recurring relationships），將其歸納整合為更高層次的原理。這一過程本質上是從「局部解釋」到「全域規律」的抽象化躍升。值得注意的是，這些歸納性原理並非靜態產物，而是會被編碼為可檢索的知識庫條目，供後續的預測或優化任務調用。

**（三）基於新觀察的假設修正（Hypothesis Revision via New Observations）**

科學發現是一個動態演進的過程，早期假設可能因新觀察的出現而被推翻或修正。Principia 透過將歸納性原理應用於下游任務（如分子優化、性質預測），獲取新的實驗觀察，並以此為證據重新評估先前使用的假設。當新觀察與現有假設產生矛盾時，框架會觸發假設的修正機制，並基於更新後的假設集合重建原理。這種「自我修正」機制使得知識庫能夠在測試時發現過程中持續演化，避免了靜態知識庫常見的「過時」或「錯誤固化」問題。

- 建議至少有數十到數百筆已標註結果的觀察，並能隨測試時間持續累積新資料。
- 若有領域專家撰寫的文獻摘要或既有知識庫（如 ChEMBL、UniProt），可作為外部知識的補充來源。

**運算面**
- 需要能呼叫大型語言模型（LLM）的 API，例如 GPT-4 級別或更新的推理模型，或部署開源權重（如 Llama 3、Qwen 2.5 等）於自有 GPU 叢集。
- 假設與原理的儲存需要向量資料庫（如 FAISS、Chroma、Pinecone）以支援檢索增強生成（RAG）。
- 整體運算成本主要來自 LLM 推理，建議準備可容納數千次 API 呼叫的預算；相較於純經驗摘要的基線，Principia 可減少約 55% 的實驗預算。

**技能面**
- 具備 Python 開發能力，熟悉 LangChain、LlamaIndex 或自建 prompt pipeline。
- 需理解 RAG、prompt engineering 與基本的假設檢定邏輯。
- 領域知識（化學、生物學、材料等）雖非必需，但能協助設計輸入特徵的呈現方式與評估原理品質。
- 建議至少有 1 位同時具備 LLM 工程與領域科學背景的成員，作為「領域提示工程師」。

### 實作步驟建議

1. **定義任務與輸入輸出格式**：明確界定要優化或預測的目標（例如分子對某蛋白的結合親和力），並將輸入轉換為 LLM 可理解的文字描述（SMILES、序列、基因名稱等），輸出則標準化為可比較的數值或類別。

2. **準備初始觀察資料集**：收集一批已完成的實驗結果，依「相關性」分組（例如結構相似的分子群、序列相近的突變群），這是比較性因果假設的基礎。

3. **建立比較性因果假設生成模組**：實作第一個核心元件——針對一組相關輸入與其不同輸出，提示 LLM 比較它們的共享與差異特徵，並產出「為何 A 比 B 表現更好／更差」的因果假設。建議使用 chain-of-thought 提示，並要求模型列出支持證據。

4. **建立歸納性原理建構模組**：將多組相關輸入的假設彙整，提示 LLM 找出跨群組反覆出現的因果關係，並提煉為更高層次的原理（例如「芳香環上吸電子基團有利於活性」）。原理應以可檢索的文字形式儲存於向量資料庫。

5. **建立檢索增強的預測／優化流程**：在新一輪實驗設計時，根據當前輸入檢索最相關的假設與原理，將其注入 LLM 的 prompt 中，引導候選生成或性質預測。

6. **建立假設修訂迴圈**：將新實驗結果回饋至系統，自動比對新觀察與既有假設的一致性；若出現矛盾，觸發假設修訂流程（重新生成或修正假設），並重建受影響的原理。

7. **建立評估與監控機制**：設計離線評估指標（如預測準確率、優化曲線下的面積）與線上監控（如原理隨時間的變化幅度、假設被推翻的頻率），確保系統持續可靠。

8. **小規模試點與迭代**：先在一個子任務上驗證（例如 100 個分子的子集），確認假設品質與原理一致性後，再擴展至完整任務。

9. **部署與持續運維**：將系統包裝為可重複執行的 pipeline，設定定期批次更新原理的排程，並建立人工覆審機制以把關關鍵決策。

### 潛在風險與注意事項

- **假設幻覺（hallucinated hypotheses）**：LLM 可能生成看似合理但缺乏實證支持的因果關係。**緩解方式**：要求每個假設附上「支持觀察編號」並由領域專家抽樣覆審；對高風險決策（如臨床前候選分子）保留人類最終決定權。

- **觀察覆蓋偏誤**：若累積的觀察僅來自輸入空間的一小區域，歸納出的原理可能過度狹隘。**緩解方式**：在實驗設計階段刻意引入「探索性樣本」（例如隨機突變或遠離當前最佳值的候選），以擴大覆蓋。

- **原理漂移（principle drift）**：隨新觀察累積，原理可能頻繁變動，導致下游決策不穩定。**緩解方式**：設定原理更新的「證據門檻」（例如需累積 N 筆支持或反對證據才觸發修訂），並保留原理版本歷史以便回溯。

- **API 成本與延遲**：每次假設生成與原理建構都需要多次 LLM 呼叫，累積成本可觀。**緩解方式**：對簡單案例使用較小模型、對關鍵決策使用較大模型；快取常見假設以減少重複推理。

- **領域術語理解錯誤**：LLM 可能誤讀 SMILES、突變記號或基因名稱。**緩解方式**：在 prompt 中提供明確的格式說明與範例；對關鍵輸入進行前置解析與驗證。

- **可重現性與審計**：自動生成的原理若未記錄依據，後續審查困難。**緩解方式**：完整記錄每次假設生成的 prompt、輸入觀察、模型回應與版本，便於追溯與監管合規。

- **過度擬合於歷史資料**：若歷史觀察存在系統性偏差（例如某些結構從未被測試），原理可能強化既有偏誤。**緩解方式**：定期以保留的「未見分布」樣本測試原理泛化能力。

### 與其他技術的整合建議

- **與分子生成模型整合**：將 Principia 歸納出的原理作為 reward shaping 或 conditional generation 的引導條件，與 REINVENT、GraphAF 等生成模型結合，使生成過程同時受「任務專屬原理」與「化學可行性」約束。

- **與活性預測 ML 模型整合**：將 LLM 生成的原理作為特徵工程的靈感來源，或將原理文字嵌入後與分子 fingerprint 串接，作為下游梯度提升或圖神經網路的額外輸入。

- **與文獻檢索系統整合**：在假設生成階段串接 PubMed、Semantic Scholar 等 API，讓 LLM 在提出因果假設時能引用真實文獻，提升可信度。

- **與實驗室自動化平台整合**：將 Principia 的輸出（候選分子、突變建議）對接機器人合成或高通量篩選系統，形成「假設→實驗→觀察→修訂」的閉環。

- **與知識圖譜整合**：將歸納出的原理存入企業內部科學知識圖譜，與既有本體（如 ChEBI、Gene Ontology）對齊，方便跨專案檢索與推理。

- **與 MLOps 平台整合**：將假設與原理視為一種「模型產物」，透過 MLflow 或 Weights & Biases 追蹤其版本、效能與下游影響，便於治理與回滾。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的圖 1 與「hypotheses-to-principle pipeline」的直觀說明，理解「比較相關輸入→形成假設→歸納為原理→用新觀察修訂」這個核心循環即可，不必急於深入 prompt 細節。可以把 Principia 想成一個會從實驗筆記本中自動整理出「實驗室眉角」的 AI 助理。

**給 AI 工程師**：重點關注第 1 節末段對三個核心元件（比較性因果假設生成、歸納性原理建構、假設修訂）的描述，以及論文中關於 RAG 檢索、向量資料庫與 prompt 設計的細節。實作時可參考 GitHub 程式碼，先重現一個最小可行版本，再逐步加入修訂迴圈與監控機制。

**給研究者**：建議仔細閱讀實驗章節中四個基準（分子優化、蛋白質工程、基因擾動、分子性質預測）的設定與結果，特別是 Principia 相較於「內部知識」「外部來源」「經驗摘要」三類基線的優勢來源。同時關注質性分析中原理與文獻的一致性，這是評估方法科學價值的關鍵。

**給產品經理**：聚焦於「55% 實驗預算縮減」這個商業價值點，以及 Principia 在四個不同領域的通用性——這意味著同一套框架可在多條產品線上複用。建議將導入分為「試點驗證→單一任務落地→跨任務橫向擴展」三階段，並在試點階段就建立 ROI 評估指標（如每輪實驗的 hit rate、原理被推翻率等）。
