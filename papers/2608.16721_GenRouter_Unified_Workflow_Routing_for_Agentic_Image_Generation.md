## ⚡ TL;DR

現有智能體圖像生成管線固定且孤立，簡單提示被迫耗用大量計算資源。
本文提出 GenCanvas 統一工作流空間，GenRouter 透過剖析、匹配與過濾動態路由提示。
實驗顯示 GenRouter 視覺對齊度更佳，成本降逾九成五、延遲減六成五，並能自我演化。

## 摘要翻譯

文字轉圖像（Text-to-Image, T2I）生成模型的快速演進，已有效解決原始像素合成（Raw Pixel Synthesis）的基礎挑戰，使研究社群的關注焦點轉向滿足日益複雜精細的使用者請求（User Requests）。儘管近期的智能體圖像生成（Agentic Image Generation）工作流通過外部知識檢索（External Knowledge Retrieval）與迭代推理（Iterative Reasoning）等先進能力強化了靜態推論（Static Inference），但它們大多在孤立筒倉（Isolated Silos）中以固定的「一體適用（One-Size-Fits-All）」拓撲（Topology）運作。這不可避免地導致嚴重的計算錯配（Compute-Mismatch），使簡單查詢（Simple Queries）被迫通過計算繁重的管線。為彌合此差距，我們提出 GenRouter，首個針對智能體圖像生成的統一工作流路由框架（Unified Workflow Routing Framework）。我們首先提出 GenCanvas，將多樣化的智能體管線標準化為一組通用的基礎原語（Foundational Primitives）與可執行工作流模板（Executable Workflow Templates）。在此統一工作流空間（Unified Workflow Space）之上運作，GenRouter 透過（i）需求剖析（Demand Profiling）、（ii）經驗匹配（Experience Matching）與（iii）帕累托過濾（Pareto Filtering），自適應地將異質提示（Heterogeneous Prompts）路由至其最佳工作流（Optimal Workflows）。跨越多個基準測試的大量實驗顯示，相較於重型靜態管線（Heavyweight Static Pipelines），GenRouter 在達到更優越的視覺對齊度（Visual Alignment）的同時，可將執行成本（Execution Cost）降低超過 95%，並將延遲（Latency）減少 65%。此外，該系統透過累積經驗（Accumulated Experience）持續自我演化（Self-Evolves），實現穩健的零樣本泛化（Zero-Shot Generalization），不僅提升效能，更將計算開銷（Computational Overhead）減半。

### 核心貢獻（3～5點）
- 提出 GenCanvas，將多樣化的智能體圖像生成管線標準化為一組通用的基礎原語（Foundational Primitives）與可執行工作流模板（Executable Workflow Templates），建立統一的工作流空間（Unified Workflow Space）。
- 提出 GenRouter，為首個針對智能體圖像生成的統一工作流路由框架，透過需求剖析（Demand Profiling）、經驗匹配（Experience Matching）與帕累托過濾（Pareto Filtering）三階段，自適應地將異質提示路由至最佳工作流。
- 相較於重型靜態管線（Heavyweight Static Pipelines），GenRouter 在達到更優越視覺對齊度（Visual Alignment）的同時，可降低超過 95% 的執行成本與 65% 的延遲。
- 系統透過累積經驗持續自我演化（Self-Evolves），具備穩健的零樣本泛化（Zero-Shot Generalization）能力，能將計算開銷（Computational Overhead）減半並持續提升效能。

### 適合對象
本論文適合從事文字轉圖像生成（T2I）、智能體系統（Agentic Systems）、工作流路由與最佳化、以及多模態大型語言模型應用的研究人員與工程師。特別是對於希望設計能根據使用者請求動態選擇生成管線、降低計算成本並提升視覺對齊度的讀者，本研究提供了具體的框架與實證結果。此外，關注測試時擴展（Test-Time Scaling）、自我演化系統與零樣本泛化機制的學術與產業研究者，亦能從中獲得啟發。

## 深度分析

#### 方法論解析

GenRouter 的核心方法論可以分為兩個層次：首先建立一個**統一工作流空間（unified workflow space）**——GenCanvas；其次在此空間上運作一個**自我演化（self-evolves）**的**工作流路由（workflow routing）**機制——GenRouter。整體設計的關鍵在於把「管線該怎麼走」與「後端該用哪個生成器」這兩個決策聯合考慮，而非像過去那樣預先固定。

##### 1. GenCanvas：將智能體圖像生成（agentic image generation）標準化為可組合原語

過去的智能體圖像生成框架（如 MindBrush、GEMS、SCOPE）各自發展出專用管線（specialized pipelines），彼此之間難以互通。GenCanvas 的做法是將所有這些管線**解構（deconstruct）**為一組**基礎原語（foundational primitives）**，例如：

- **檢索（search）**：進行外部知識檢索（external knowledge retrieval），補足模型缺乏的世界知識。
- **推理（reason）**：執行空間與邏輯推理（spatial and logical reasoning），拆解多約束生成（multi-constraint generation）任務。
- **驗證（verify）**：進行迭代驗證（iterative verification），檢查生成結果是否符合提示。
- **草圖繪製（sketch）**：先產生結構化佈局或視覺草圖，再交給生成器。

透過這些原語的**策略性組合（strategically composing）**，GenCanvas 建立了一個**標準工作流模板庫（library of standard workflow templates）**，從輕量級的 **DirectGen**（直接生成）到綜合型的 **HybridGen**（混合生成）。這樣的抽象有幾個優點：

1. **模組化（modularity）**：新增能力時只需增加原語或模板，不必從頭設計整條管線。
2. **可擴展性（scalability）**：模板可以組合出不同複雜度的**執行工作流（execution workflow）**。
3. **動態路由（dynamic routing）**：因為所有工作流都位於同一表示空間，路由器可以在它們之間自由選擇。

值得注意的是，GenCanvas 並非只是現有管線的**窮舉集合（exhaustive collection）**，而是對近期固定框架核心範式的系統化抽象與延伸。

##### 2. GenRouter：三階段經驗導向路由

在 GenCanvas 之上，GenRouter 負責把每個**異質提示（heterogeneous prompts）**對應到最佳的**工作流軌跡（workflow trajectories）**與後端生成器。其路由機制包含三個核心階段：

**(i) 需求剖析（demand profiling）**

此階段從提示中提取一個輕量的**任務特徵（task signature）**，用於量化捕捉提示的內在需求。這相當於對輸入進行快速分類：是簡單的美學描述（aesthetic descriptions），還是需要外部世界知識（external world knowledge）、精確文字渲染（text rendering）或多步驟推理（multi-step reasoning）的複雜請求。這個特徵必須輕量，否則路由本身會成為新的瓶頸。

**(ii) 經驗匹配（experience matching）**

GenRouter 利用歷史執行軌跡與蒸餾後的**經驗卡（experience cards）**來預測各個候選計畫的整體效用。這屬於**基於經驗的路由（experience-based routing）**：系統不需要從頭訓練大規模離線策略，而是持續累積**累積經驗（accumulated experience）**，並透過相似度匹配快速估計某個工作流在特定提示上的視覺表現（visual performance）與成本。

**(iii) 帕累托過濾（Pareto filtering）**

最後階段應用成本感知的帕累托過濾，動態剪除計算效率低下的配置。這裡的目標是平衡**視覺對齊度（visual alignment）**與**執行成本（execution cost）**／**延遲（latency）**。透過帕累托前沿（Pareto frontier）的概念，系統只保留那些在效能與成本上都不被其他方案全面支配的候選計畫，從而避免簡單提示被強制塞入重型靜態管線（heavyweight static pipelines）。

##### 3. 自我演化迴圈

GenRouter 並非一次性訓練完成後就固定不變。它透過「路由 → 執行 → 蒸餾」的連續迴圈持續自我演化（self-evolves）。每次執行後，系統會把新的軌跡與結果回饋到經驗庫中，逐步提升未來匹配的準確度。這也是為何論文強調它能達成強健的**零樣本泛化（zero-shot generalization）**：面對未見過的提示類型時，仍可藉由相似歷史經驗進行推斷，並隨時間降低計算開銷（computational overhead）。

#### 實驗數據解讀

雖然提供的上下文未包含完整的實驗章節，但從摘要與引言中已可歸納出幾項關鍵量化結果，並據此進行解讀：

##### 1. 成本與延遲的大幅降低

論文指出，與重型靜態管線（例如 GEMS）相比，GenRouter 能夠：

- 降低**執行成本（execution cost）超過 95%**
- 降低**延遲（latency）65%**

這兩個數字非常顯著，意味著 GenRouter 成功緩解了**計算錯配（compute-mismatch）**問題。對於簡單提示（simple prompts），系統會選擇 DirectGen 這類輕量級（lightweight）模板，避免執行不必要的外部知識檢索、迭代驗證或複雜推理。由於現實應用中簡單查詢（simple queries）通常佔大多數，這種動態選擇能帶來接近兩個數量級的成本節省。

##### 2. 視覺對齊度（visual alignment）的提升

儘管成本大幅下降，GenRouter 仍達到「superior visual alignment」。這說明路由不僅省資源，還能為複雜提示選到更適合的工作流。換句話說，簡單提示不會因為被強制經過過度複雜的管線而引入額外雜訊；複雜提示也不會因為使用過於簡單的模板而遺失關鍵細節。這正是帕累托過濾的價值所在：它不是單純選最便宜的方案，而是在效能與成本之間找到最佳平衡。

##### 3. 零樣本泛化與持續演化的效益

論文提到，隨著經驗累積，GenRouter 在零樣本設定下能「boosts performance and halves computational overhead」。這暗示：

- **資料效率**：不需要針對每種新任務重新訓練大模型，而是靠經驗庫的相似性進行推廣。
- **邊際成本遞減**：使用越久，系統對提示特徵的判斷越準，錯誤路由的次數減少，進一步降低平均開銷。
- **穩健性**：對於分布外（out-of-distribution）提示，經驗匹配提供了比純規則或純學習策略更靈活的後備機制。

##### 4. 尚待釐清的實驗細節

由於目前僅能看到摘要與前兩章，以下細節仍需要完整論文確認：

- 使用的基準測試（benchmarks）具體為何？是否涵蓋文字渲染、空間推理、知識密集型任務等不同維度？
- **視覺對齊度（visual alignment）**的衡量指標是 CLIP Score、Human Preference Score、GPT-4V 評分，還是綜合指標？

#### 與現有研究的比較

##### 1. 相對於早期測試時擴展方法

早期的**測試時擴展（test-time scaling）**策略，例如生成前提示精煉（prompt pre-generation refinement）或生成後重寫（post-generation rewriting），本質上仍是同質化（homogeneous）流程。它們對所有提示套用相同增強策略，面對多約束生成時容易失敗。GenRouter 則把「要不要增強、要哪種增強」變成可路由的決策，因此更具彈性。

##### 2. 相對於孤立筒倉式的智能體框架

MindBrush 專注外部知識檢索，GenClaw 透過可執行視覺程式碼控制空間佈局，GEMS 與 SCOPE 則強調結構化技能承諾與迭代修復。這些框架雖然在各自領域表現出色，但都是**孤立筒倉（isolated silos）**，使用**固定拓撲（fixed topologies）**。GenCanvas 的貢獻在於把這些能力抽象為可互通的原語，而 GenRouter 則進一步根據提示需求動態組合，避免一體適用（one-size-fits-all）的浪費。

##### 3. 相對於模型路由（model routing）研究

現有模型路由研究主要分為兩類：

- **基於學習的路由（learning-based routing）**：離線訓練預測策略，但難以適應任務分布變化。
- **基於經驗的路由（experience-based routing）**：利用即時執行回饋持續精進。

GenRouter 屬於後者，但超越了單純的「後端模型選擇」。過去的方法大多針對語言模型，而 RouteT2I 雖然把路由延伸到視覺領域，卻仍只在靜態管線內調度邊緣與雲端生成器。GenRouter 首次把路由對象擴展到**工作流模板（workflow templates）**與**多模態生成器（multimodal generators）**的聯合空間，這是方法論上的重要躍進。

##### 4. 潛在限制

儘管論文宣稱成效顯著，仍有幾點需要審慎看待：

- **路由開銷**：需求剖析、經驗匹配與帕累托過濾本身也需要計算資源。若提示極短或批量極大，這些額外開銷是否會侵蝕成本優勢，需要更多分析。
- **經驗庫的冷啟動（cold-start）**：在系統剛上線、累積經驗不足時，路由準確度可能較低。論文雖提到零樣本泛化，但冷啟動階段的表現仍需驗證。
- **模板覆蓋率**：GenCanvas 目前列出的原語是否足以涵蓋所有未來的智能體圖像生成需求？若出現全新能力（例如 3D 條件生成、影片風格遷移），模板庫需要持續擴展。
- **公平比較**：GEMS 等重型管線若被強制執行於簡單提示，本來就會浪費資源；GenRouter 的優勢部分來自於「不該做的就不做」。這雖然合理，但在學術比較上需要確認基線是否也具備某種簡單判斷機制。

- **資料集（datasets）**：未說明是否公開使用的基準測試或自行收集的提示集。

##### 2. 方法論的可重現性

即使沒有官方實作，GenCanvas 與 GenRouter 的概念描述相對清晰，具備一定程度的可重製潛力：

- 原語與模板的定義明確，研究者可以依據論文重建 DirectGen、HybridGen 等模板。

##### 3. 建議

為提升可重現性，作者可考慮釋出：

- GenCanvas 的模板實作與原語介面。
- 用於需求剖析的輕量分類器或特徵提取器。
- 經驗庫的格式與更新演算法。
- 評估用的提示集與對應的成本／延遲／視覺對齊度數據。

#### 未來研究方向

GenRouter 與 GenCanvas 的提出為智能體圖像生成開啟了多條後續研究路徑：

##### 1. 擴充基礎原語與模板庫

目前的原語包括檢索、推理、驗證與草圖繪製。未來可加入：

- **風格遷移（style transfer）**原語
- **多視角一致性（multi-view consistency）**原語
- **安全過濾（safety filtering）**與**偏見檢查（bias checking）**原語
- **人機協作（human-in-the-loop）**原語，用於需要使用者確認的場景

##### 2. 更精細的多目標最佳化

帕累托過濾目前主要平衡視覺對齊度與成本。未來可納入更多目標，例如：

- 碳排放（carbon footprint）
- 使用者主觀偏好（user preference）
- 生成多樣性（generation diversity）
- 版權與安全性風險

##### 3. 線上學習與主動學習結合

雖然 GenRouter 已具備自我演化能力，但可以進一步研究：

- 如何主動選擇具有資訊量的提示進行探索，以加速經驗庫成長？
- 如何遺忘過時經驗，避免分布飄移（distribution shift）導致路由退化？

##### 4. 跨模態與跨領域擴展

GenCanvas 的抽象思想不僅適用於圖像生成，也可延伸至：

- 影片生成（video generation）
- 3D 資產生成（3D asset generation）
- 多模態內容編輯（multimodal content editing）
- 音訊生成（audio generation）

##### 5. 可解釋性與透明度

未來可研究如何讓 GenRouter 的路由決策對使用者與開發者更透明，例如：

- 為每個提示提供「為何選擇此工作流」的自然語言解釋。
- 視覺化不同模板在帕累托前沿上的位置，協助使用者理解效能與成本的權衡。

##### 6. 與邊緣運算及雲端調度的整合

結合 RouteT2I 的後端調度思想，未來可發展出同時考慮「工作流複雜度」與「部署位置（邊緣 vs. 雲端）」的聯合最佳化系統，進一步降低實際部署成本。

##### 7. 建立標準化評測基準

目前智能體圖像生成領域缺乏統一的「成本—品質」評測基準。未來可基於 GenCanvas 建立一個公開的 routing benchmark，讓不同路由演算法在相同原語空間下公平比較。

## 論文問答

**Q1：GenRouter 主要想解決什麼問題？**
A：GenRouter 針對的是現有智慧體圖像生成系統中普遍存在的「碎片化」與「計算錯配」兩大瓶頸。現有方法多半以孤立筒倉的形式開發專用管線，並對所有提示採用固定的一體適用拓撲，導致簡單查詢也被迫流經昂貴的推理與驗證步驟。這種計算錯配不僅浪費大量計算資源，也帶來過高的延遲，因此 GenRouter 提出統一的工作流路由框架，將異質提示動態導向最適合的執行路徑，以兼顧視覺表現與執行成本。

**Q2：為什麼現有的智慧體圖像生成方法難以處理異質提示？**
A：現有框架通常針對特定能力設計專用管線，例如 MindBrush 專注外部知識檢索，GEMS 則強調結構化技能承諾與迭代修復，彼此難以整合或調整拓撲。此外，這些系統大多採用固定拓撲，無論提示是簡單的美學描述還是需要多步驟空間與邏輯推理的複雜請求，都使用同一套重型靜態管線。這種缺乏彈性的設計使得系統無法根據提示內在需求調度不同能力，從而產生嚴重的計算錯配與效能浪費。

**Q3：工作流路由對未來文字轉圖像系統為何重要？**
A：隨著文字轉圖像模型在原始像素合成上趨於成熟，使用者請求將變得更加多元與複雜，單一固定管線已無法同時滿足品質與效率。工作流路由能讓系統根據每個提示的實際需求，在輕量級直接生成與綜合型混合生成之間做出權衡，避免不必要的計算開銷。這不僅能提升使用者體驗、降低延遲，也為建立可擴展且模組化的智慧體圖像生成基礎設施提供關鍵支撐。

**Q4：什麼是 GenCanvas，它如何統一智慧體圖像生成？**
A：GenCanvas 是本文提出的第一個統一工作流空間，它將智慧體圖像生成的執行過程解構為一組普遍適用的基礎原語，例如檢索、推理、驗證與草圖繪製。透過策略性組合這些原語，GenCanvas 建立從輕量級 DirectGen 到綜合型 HybridGen 的標準工作流模板庫，涵蓋並延伸了近期固定框架的核心概念。這種模組化與可擴展的抽象不僅能封裝現有管線的能力，也為動態路由與多樣化下游應用提供了結構化的基礎。

**Q5：GenRouter 的路由機制由哪三個核心元件組成？**
A：GenRouter 的路由機制包含需求剖析、經驗匹配與帕累托過濾三個階段。需求剖析會從提示中提取輕量級任務特徵，定量捕捉其內在需求；經驗匹配則利用歷史執行軌跡與蒸餾出的經驗卡片，預測各候選計畫的整體效用；最後帕累托過濾根據成本意識動態剪除計算效率不佳的配置。這三個元件協同運作，使 GenRouter 能為每個請求選出帕累托最適的執行計畫與後端圖像生成器。

**Q6：相較於傳統模型級路由，GenRouter 的關鍵創新是什麼？**
A：傳統模型級路由多半只在不同語言模型或雲端與邊緣生成器之間做後端選擇，而 GenRouter 首次將路由提升到工作流層級，同時在「工作流模板」與「多模態生成器」的聯合空間中進行導航。它透過需求剖析與經驗匹配，將提示與最適合的智慧體配置配對，並藉由持續的執行—蒸餾迴路自我演化。這種設計不僅突破了單一後端分配的局限，也為智慧體圖像生成引入了動態、可學習且成本敏感的路由正規化。

**Q7：實驗結果如何證明 GenRouter 的有效性？**
A：作者在多元基準測試上進行大量實驗，結果顯示 GenRouter 在視覺對齊度上優於重型靜態管線，同時將執行成本降低超過 95%、延遲降低 65%。與 GEMS 等一體適用的重型管線相比，GenRouter 能針對不同提示選擇適當工作流，避免過度計算。此外，隨著經驗累積，GenRouter 展現出強健的零樣本泛化能力，不僅提升效能，還能將計算開銷再減半。

**Q8：GenRouter 如何在降低執行成本的同時維持視覺品質？**
A：GenRouter 透過需求剖析區分提示的複雜度，將簡單提示導向輕量級 DirectGen，而將需要外部知識、推理或驗證的複雜提示導向 HybridGen 等較重的工作流。接著經驗匹配與帕累托過濾會在視覺表現與執行成本之間尋找最佳平衡，避免對簡單查詢執行多餘的迭代推理。這種動態配置確保系統不會為了少數困難案例而對所有請求採用昂貴管線，從而在整體上維持高視覺對齊度並顯著降低成本。

**Q9：GenRouter 的自我演化能力在實證上帶來什麼貢獻？**
A：GenRouter 在每次路由、執行與蒸餾後都會累積經驗，持續改進對未來提示的預測精準度。實驗顯示，這種自我演化機制使系統在面對未見過的任務時，仍能保持強健的零樣本泛化，並進一步將計算開銷減半。換言之，GenRouter 不僅在初始部署時有效，還能隨著使用時間增長而變得更聰明、更高效。

**Q10：哪些實際應用場景最能從 GenRouter 受益？**
A：GenRouter 特別適合同時服務大量簡單與複雜請求的互動式創作工具、內容生成平台與設計助理。例如，社群媒體使用者可能只需要簡單的美學描述，而專業設計師則可能需要精確文字渲染或多約束生成，GenRouter 能自動為兩者選擇最適工作流。這不僅能顯著降低終端使用者等待的延遲，也能減少雲端服務供應商的計算成本與能源消耗。

**Q11：部署 GenRouter 時需要考慮哪些產品層面議題？**
A：首先，維護 GenCanvas 的基礎原語與標準工作流模板庫需要持續更新，以納入新的智慧體能力與後端模型。其次，經驗卡片與歷史執行軌跡的儲存、檢索與隱私管理必須妥善設計，才能支撐即時的經驗匹配。此外，系統還需監控提示分布的變化，避免經驗累積導致的偏差，並根據不同使用者的成本或品質偏好調整帕累托過濾標準。

**Q12：GenRouter 可能對智慧體圖像生成領域帶來什麼影響？**
A：GenRouter 將研究焦點從打造孤立專用管線，轉向建立統一、模組化且可動態路由的工作流空間。這種典範轉移鼓勵社群開發新的基礎原語與工作流模板，並透過標準化介面進行組合與比較。長遠來看，GenRouter 為成本敏感、可擴展且持續演化的智慧體圖像生成系統奠定了基礎，也可能啟發其他多模態生成任務的工作流路由研究。

**Q13：GenRouter 可能存在哪些限制？**
A：GenRouter 的路由品質高度依賴經驗卡片的覆蓋範圍與品質，對於極少見或全新的任務類型，歷史軌跡可能不足，導致預測不準確。此外，需求剖析雖然輕量，但可能無法完整捕捉提示中細微的多模態或語境需求，例如隱含的文化知識或風格偏好。最後，帕累托過濾基於預設的成本與品質權衡，若使用者偏好與系統預設不一致，可能選出對該使用者而言次佳的計畫。

**Q14：GenRouter 可能出現哪些失敗案例？**
A：一種典型失敗是將實際上需要外部知識或多步驟推理的複雜提示誤判為簡單提示，從而選擇 DirectGen，導致生成結果缺少關鍵資訊或邏輯錯誤。另一種情況是當提示分布發生顯著變化時，累積的歷史經驗可能變得過時，使經驗匹配產生偏差。此外，若帕累托過濾過度強調成本，可能會在需要高品質輸出的場景中選擇過於輕量的配置，犧牲視覺對齊度。

**Q15：未來有哪些值得探索的研究方向？**
A：未來可以將 GenCanvas 的基礎原語擴展到影片生成、3D 生成或其他多模態生成任務，建立更通用的智慧體生成路由框架。另一個方向是引入線上強化學習，使路由策略能根據即時回饋自動調整，而不僅依賴歷史經驗的蒸餾。此外，針對個別使用者或應用場景客製化帕累托偏好，並將安全性、公平性與對齊檢查也納入可路由的基礎原語，都是提升 GenRouter 實用性與可信度的 promising 方向。

## 實務應用指南

### 適用場景

1. **電商商品圖自動生成**  
   面對數萬筆商品描述，從簡單的白底圖需求到需要外部世界知識（如「復古 1970 年代風格收音機」）的複雜情境，GenRouter 可依提示異質性自動選擇 DirectGen 或 HybridGen，避免所有請求都進入重型管線，顯著降低批次生成成本。

2. **行銷素材與廣告創意量產**  
   行銷團隊常需要多版本視覺（不同風格、文案排版、品牌調性）。GenRouter 能將涉及文字渲染、多約束組合的提示導向具備推理與驗證能力的工作流，而單純美學描述則走輕量路徑，兼顧產出速度與視覺對齊度。

3. **遊戲資產快速原型**  
   遊戲開發中，概念草圖、角色設計、場景布局的需求差異極大。透過 GenCanvas 的基礎原語（search、reason、verify、sketch），可動態組合出適合「快速發想」或「精細空間布局」的最佳工作流軌跡。

4. **出版與插畫輔助創作**  
   對於需要精確事實一致性（歷史場景、科學插圖）的提示，GenRouter 會啟用外部知識檢索與迭代驗證；對於風格化插畫則直接生成，減少不必要的計算開銷與延遲。

5. **UI/UX 設計稿生成**  
   當提示涉及介面元件、文字標籤與空間邏輯推理時，系統可路由至具備 sketch 與 verify 原語的 HybridGen；相對簡單的 mood board 則使用 DirectGen，讓設計團隊在成本可控下獲得高品質稿件。

### 實作前置條件

- **資料準備**
  - 歷史執行軌跡：提示、所選工作流模板、後端生成器、視覺對齊度分數、執行成本與延遲。
  - 蒸餾後的經驗卡（experience cards）：用於需求剖析與效用匹配的結構化特徵。
  - 評測資料集：涵蓋簡單提示與複雜精細提示，並具備對應的視覺對齊度標註或人工評分。

- **運算資源**
  - 文字轉圖像（T2I）後端：至少一個輕量級與一個重型生成模型（如 Stable Diffusion 系列與進階微調模型）。
  - 路由模型：用於需求剖析的輕量語言模型，以及儲存經驗卡的向量資料庫。
  - 推論與監控基礎設施：可記錄每次路由決策、執行成本與延遲，並支援持續蒸餾迴圈。

- **技能與團隊**
  - 熟悉智能體圖像生成流程與提示工程。
  - 具備多模態評估能力，能設計視覺對齊度與計算錯配的衡量指標。
  - 具備 MLOps 與 API 整合經驗，能將 GenCanvas 原語封裝為可執行模板。

### 實作步驟建議

1. **建立 GenCanvas 工作流空間**  
   將現有管線拆解為基礎原語（search、reason、verify、sketch），並定義標準工作流模板庫，例如 DirectGen、HybridGen 及未來可擴充的專用模板。

2. **收集並標註執行軌跡**  
   在初期可採用少量固定路由或 A/B 測試，記錄每個提示對應的模板、後端生成器、視覺對齊度、執行成本與延遲，作為經驗匹配的種子資料。

3. **建構需求剖析模組**  
   設計輕量任務特徵（task signature），量化提示是否需要外部世界知識、文字渲染、空間與邏輯推理或多約束生成等內在需求。

4. **實作經驗匹配與帕累托過濾**  
   利用歷史軌跡預測各候選計畫的整體效用，再以成本感知的帕累托過濾動態剪除計算低效配置，留下視覺表現與執行成本的最佳平衡方案。

5. **整合多後端生成器**  
   將不同能力與成本的 T2I 模型掛載到 GenCanvas，使路由器能同時選擇「工作流模板 + 後端生成器」的聯合配置。

6. **部署持續執行—蒸餾迴圈**  
   每次實際執行後，將結果回寫至經驗卡庫，定期重新計算帕累托前沿，讓系統隨累積經驗自我演化並提升零樣本泛化能力。

7. **建立監控與降級機制**  
   設定視覺對齊度門檻與延遲上限，當路由器信心不足時自動降級至較穩定的重型管線，並持續追蹤計算錯配與路由錯誤率。

### 潛在風險與注意事項

- **錯誤路由導致品質下降**  
  複雜精細提示若被誤判為簡單提示，可能因缺少推理或驗證而產出失準圖像。建議設定信心門檻與人工回饋迴路，並保留 HybridGen 作為高風險提示的後備方案。

- **歷史資料分布偏移**  
  經驗匹配容易受過去任務分布影響，當新類型提示湧入時可能失效。應定期重新訓練或更新經驗卡，並結合線上學習機制。

- **路由器自身延遲**  
  需求剖析與匹配過程若過於複雜，可能抵銷執行成本節省。建議將剖析模型輕量化，並對經驗卡建立高效向量索引。

- **成本衡量不準確**  
  不同後端生成器的計價方式（API 呼叫次數、推理步數、快取命中率）各異，需建立統一成本模型，否則帕累托過濾會產生偏差。

- **模板維護負擔**  
  隨著 GenCanvas 擴充，模板數量增加可能導致組合爆炸。應以模組化原語為核心，避免過度客製化專用管線，並透過版本控制管理模板變更。

### 與其他技術的整合建議

- **T2I 後端服務**  
  可無縫對接 Stable Diffusion、DALL·E、Midjourney API 或企業自研模型，將其視為 GenCanvas 中的可替換生成節點。

- **智能體編排框架**  
  與 LangChain、LlamaIndex 或自研智能體系統整合，讓 search、reason、verify 等原語能呼叫外部工具、知識庫與記憶模組。

- **MLOps 與監控平台**  
  透過 Weights & Biases、MLflow 或自訂儀表板追蹤每次路由決策、視覺對齊度、執行成本與延遲，並自動觸發再訓練或告警。

- **成本與配額管理**  
  串接雲端計費 API 與配額控制系統，讓帕累托過濾能依即時預算與速率限制調整可行方案空間。

- **CI/CD 與模板版本控制**  
  將 GenCanvas 模板納入版本控制與自動化測試，每次新增原語或模板時，先在影子模式下驗證對整體路由效果的影響，再正式上線。

- **AI 工程師**  
  重點閱讀 GenCanvas 的基礎原語設計、需求剖析的任務特徵提取、經驗匹配的實作細節，以及帕累托過濾如何與成本模型結合；同時關注持續蒸餾迴圈的資料流與線上更新策略。

- **研究人員**  
  可深入探討統一工作流空間的形式化定義、零樣本泛化的理論基礎、帕累托最優性的保證，以及自我演化機制在分布偏移下的收斂性與樣本效率問題。

- **產品經理**  
  著重理解成本—品質權衡的商業價值、適用的落地場景與關鍵指標（視覺對齊度、執行成本、延遲），並評估如何分階段導入：從高頻簡單提示的成本節省開始，再逐步擴展到複雜精細提示的智慧路由。
