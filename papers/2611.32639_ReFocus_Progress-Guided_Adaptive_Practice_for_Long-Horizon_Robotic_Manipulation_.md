ReFocus 的核心設計理念在於解決長時序機器人操作強化學習中兩個相互關聯的核心挑戰：**獎勵不平衡 (Reward Imbalance)** 與 **瓶頸練習不足 (Limited Bottleneck Practice)**。整體框架採用全域-局部交替優化 (Global-Local Alternating Optimization) 的雙層結構，這在概念上類似於人類學習中的「整體練習」與「針對性弱點補強」。

**1. 任務結構化：基於 DAG 的子任務分解**

方法的第一步是將每個長時序任務分解為有向無環圖 (Directed Acyclic Graph, DAG) 形式的子任務結構。DAG 節點代表可驗證的子任務 (verifiable subtasks)，邊則表示前置依賴關係。值得注意的是，作者將具有共同前置條件的子任務群組為「階段 (stages)」，同一階段內的子任務可任意順序完成。這種分層結構同時捕捉了任務的時序依賴與並行可能性，比純線性的子任務序列更具表達力。

**2. DAG 進度獎勵 (DAG-based Progress Reward)**

傳統方法對每個子任務賦予均勻獎勵，這會導致分解粒度越細的階段獲得不成比例的獎勵權重。ReFocus 的關鍵創新在於採用**任務層級固定獎勵預算 (task-level fixed reward budget)**：先將總預算均分給各個階段，再將每個階段的份額均分給其內部子任務。這種兩階段均分機制確保獎勵分配與分解粒度解耦，從根本上解決了獎勵不平衡問題。此外，配合一次性獎勵 (one-time credit) 機制，避免重複完成同一子任務累積獎勵。

**3. 自適應練習窗口 (Adaptive Practice Window)**

這是 ReFocus 最具特色的設計。基於全域 RL 階段收集的瓶頸診斷資訊，LLM 驅動的排程器 (Scheduler) 識別策略反覆卡住的階段，並定義從起始階段 (entry stage) 到目標階段 (target stage) 的練習窗口。窗口內採用三種回合模式：

- **正常窗口 (Normal Window)**：集中練習選定瓶頸
- **前綴窗口 (Prefix Window)**：從任務起點執行至瓶頸起點，模擬真實任務中由前置階段繼承的狀態
- **後綴窗口 (Suffix Window)**：從瓶頸起點執行至任務結束，確保瓶頸練習與後續階段銜接

里程碑獎勵 (Milestone Rewards) 在選定區段內提供更細粒度的回饋。這三種模式的組合巧妙地將局部練習與全域任務的「遺傳狀態 (inherited states)」和「後續要求」相連接，避免了局部過擬合。

**4. 多輪交替優化**

每輪訓練結束後，評估結果、練習成本與歷史窗口資訊被記錄到歷史緩衝區 (History Buffer)，供排程器在下一輪決策時參考。排程器可選擇保留、修訂或跳過後續練習窗口，使練習資源隨訓練進度動態重新分配。

**與 RECAP [1] 的比較：**

RECAP 同樣針對長時序操作的稀疏獎勵問題，但 ReFocus 在三個真實任務上全面超越 RECAP（95% vs 70%、100% vs 90%、100% vs 85%）。差異可能來自於：RECAP 主要關注子任務完成獎勵，而 ReFocus 進一步引入階段級獎勵均分與自適應窗口機制，提供更結構化的進度信號。

π_{0.5} 作為強大的 VLA 基礎模型，提供監督式微調 (SFT) 初始化。ReFocus 並非取代 π_{0.5}，而是作為其上的 RL 改進層，這種「基礎模型 + 進度引導 RL」的範式具有可擴展性。

**與其他進度獎勵方法 [41, 51] 的比較：**

現有方法通常估計觀測間的進度或獎勵可驗證子任務完成，但未解決獎勵不平衡問題。ReFocus 的 DAG 結構與兩階段均分機制是對這類方法的形式化改進。

**侷限性：**

3. **家庭服務機器人**：例如「整理餐桌 → 清洗碗盤 → 歸位餐具 → 擦拭桌面」這類日常家務。任務 DAG 可由家務步驟自然構成，進度獎勵則對應每個可驗證的中間狀態（如「碗盤已放入水槽」）。

4. **工業多階段組裝**：在電子產品或機械零件組裝中，每個組裝步驟都有明確的完成條件（如「螺絲已鎖緊」），非常適合 DAG 結構與可驗證子任務獎勵的設計。

5. **實驗室樣本處理自動化**：例如「開蓋 → 吸取試劑 → 注入樣本 → 封蓋 → 標記」這類需要精確操作的流程，瓶頸通常出現在精細動作階段，ReFocus 的局部強化學習可針對性強化。

### 實作前置條件

**資料需求**
- 專家示範資料：用於 VLA 策略（如 π_{0.5}）的監督式微調（SFT）初始化
- 任務 DAG 結構定義：需領域專家或 LLM 協助拆解任務為子任務與依賴關係
- 子任務驗證器（Subtask Verifier）：每個子任務需有可程式化偵測的完成條件（感測器讀數、視覺檢測、力覺回饋等）
- 環境介面：需支援狀態讀取、子任務完成判定、回合重置

**運算資源**
- 多 GPU 叢集（建議 8 張以上 A100/H100 等級）用於 VLA 模型的線上 RL 微調
- 大量平行環境模擬器（如 Isaac Sim、MuJoCo）以支援密集的回合採集
- LLM 推論服務（用於排程器 Scheduler），可使用 API 或本地部署
- 儲存空間需容納完整的 rollout 軌跡與歷史緩衝區（History Buffer）

**技能門檻**
- 熟悉 VLA 模型架構（π_{0.5}、OpenVLA、RT-2 等）及其微調流程
- 具備強化學習實作經驗（PPO、GRPO 等線上 RL 演算法）
- 了解任務規劃與 DAG 設計
- 具備機器人模擬器操作經驗
- 基本的 LLM Prompt Engineering 能力（用於排程器）

### 實作步驟建議

**階段一：任務形式化（第 1–2 週）**
1. 盤點目標任務流程，繪製子任務 DAG，明確每個節點的前置條件
2. 為每個子任務設計可驗證的完成偵測器（verifier）
3. 將任務分群為「階段（Stage）」，每個階段內子任務可任意順序完成
4. 定義任務層級獎勵預算（task-level reward budget）並平均分配至各階段

**階段二：策略初始化（第 3–4 週）**
1. 收集或使用現成的專家示範資料
2. 以 π_{0.5} 為基礎進行 SFT 初始化
3. 在模擬環境中驗證 SFT 策略的基準成功率
4. 建立評估流程（full-task success rate 與各階段進度追蹤）

**階段三：全域強化學習實作（第 5–7 週）**
1. 實作 DAG-based Progress Reward 計算模組
2. 整合進度獎勵至線上 RL 訓練迴圈（建議從 PPO 或 GRPO 開始）
3. 建立子任務完成記錄系統，用於瓶頸診斷
4. 訓練一輪全域 RL，記錄每個階段的失敗集中度

**階段四：瓶頸診斷與排程器（第 8–9 週）**
1. 設計 LLM-based Scheduler 的 prompt 與決策邏輯
2. 將「失敗集中度 + 互動成本 + 歷史窗口」作為排程器輸入
3. 實作 Adaptive Practice Window 的選擇機制（保留、修訂、跳過）
4. 定義三種 rollout 模式：normal、prefix、suffix

**階段五：局部強化學習整合（第 10–12 週）**
1. 實作 Local RL 的 milestone reward 機制
2. 整合三種 rollout 模式至訓練流程
3. 設計「Restored Entry」機制，從歷史軌跡恢復進入狀態
4. 串接 Global RL ↔ Local RL 的交替迭代流程

**階段六：評估與部署（第 13 週以後）**
1. 在 LIBERO-Long、RoboCasa365 等基準上驗證
2. 進行真實世界適應（real-world adaptation），處理 sim-to-real gap
3. 建立持續監控機制，追蹤瓶頸隨訓練輪次的演變
4. 部署前進行安全性與失敗容忍度測試

### 潛在風險與注意事項

**獎勵設計風險**
- **獎勵 hacking**：進度獎勵可能被策略「鑽漏洞」，例如以非預期方式觸發子任務驗證器。**緩解方式**：設計多樣化的驗證條件、加入隨機化檢查、定期人工審查 rollout 影片。
- **階段劃分偏差**：若 DAG 設計不當，可能將本應獨立的子任務錯誤分組。**緩解方式**：邀請領域專家審視 DAG、由 LLM 交叉驗證、進行消融實驗。

**訓練穩定性風險**
- **策略退化**：Local RL 集中練習瓶頸可能導致策略在非瓶頸階段退化。**緩解方式**：保留 Global RL 的定期介入、監控全任務成功率而非僅瓶頸成功率。
- **互動預算錯配**：排程器可能誤判瓶頸，將預算投入非關鍵階段。**緩解方式**：設定預算上限、加入「跳過」機制、保留人工覆寫介面。

**工程實作風險**
- **子任務驗證器可靠性**：在真實世界中，視覺驗證器可能受光照、遮擋影響。**緩解方式**：使用多模態感測器融合、加入信心閾值、設置人工標註 fallback。
- **狀態恢復不一致**：Local RL 的「Restored Entry」可能無法完美重現真實部署時的進入狀態。**緩解方式**：在恢復狀態中加入微小隨機化、定期用真實 rollout 校準。
- **LLM 排程器幻覺**：LLM 可能產生不合理的練習窗口建議。**緩解方式**：限制 LLM 輸出為結構化格式、加入規則式後處理、人工審查高風險決策。

**部署風險**
- **Sim-to-Real Gap**：模擬器訓練的策略在真實機器人上可能表現下降。**緩解方式**：領域隨機化（domain randomization）、真實資料微調、安全監控。
- **長尾失敗**：某些罕見失敗模式可能未被訓練覆蓋。**緩解方式**：建立失敗案例庫、持續線上學習、設定人工接管機制。

### 與其他技術的整合建議

**與現有 VLA 模型整合**
- ReFocus 可作為 π_{0.5}、OpenVLA、RT-2 等 VLA 模型的「線上微調層」，無需修改底層架構
- 建議保留 SFT 初始化權重作為錨點，避免線上 RL 過度偏離專家行為

**與任務規劃系統整合**
- 任務 DAG 可由高階任務規劃器（如 LLM-based planner）自動生成，再交由 ReFocus 處理 RL 訓練
- 排程器的決策可回饋至任務規劃器，用於動態調整 DAG 結構

**與模擬環境整合**
- 與 Isaac Sim、MuJoCo、Genesis 等模擬器深度整合，利用平行化加速 rollout 採集
- 可整合 LIBERO、RoboCasa 等基準環境的評估流程

**與安全監控系統整合**
- 在 Local RL 訓練中加入安全約束層，避免策略產生危險動作
- 整合即時監控儀表板，視覺化瓶頸演變與訓練進度

**與持續學習系統整合**
- ReFocus 的多輪迭代機制可與持續學習（Continual Learning）框架結合，避免災難性遺忘
- 歷史緩衝區可作為經驗回放（Experience Replay）的來源

**與多機器人協作整合**
- DAG 結構可擴展為多機器人任務分配圖
- 不同機器人的瓶頸可共享至中央排程器，進行聯合練習預算分配
