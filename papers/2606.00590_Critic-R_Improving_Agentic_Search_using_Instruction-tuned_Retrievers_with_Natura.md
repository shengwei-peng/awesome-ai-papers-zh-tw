# Critic-R：利用指令微調檢索器與自然語言內省回饋改進代理式搜尋

**原文標題：** Critic-R: Improving Agentic Search using Instruction-tuned Retrievers with Natural Language Introspective Feedback

**發布日期：** 2026-05-30

## ⚡ TL;DR

現有代理式搜尋的檢索器優化需大量聯合訓練或黃金標註，難以實際應用。
本文提出Critic-R，以批判模型評估內省推理軌跡，並透過推論時查詢精煉與自動監督微調檢索模型。
在多項多跳問答基準測試中，Critic-R顯著提升檢索品質與答案準確率，整體相對進步達一成以上。

## 摘要翻譯

代理式搜尋系統（agentic search systems）透過與檢索模型（retrieval models）反覆互動，以回答複雜查詢（complex queries）。儘管已有顯著進展，針對代理式搜尋（agentic search）最佳化檢索器（retrievers）仍具挑戰性，通常需要大量的聯合訓練（co-training）或黃金標準標註（gold-standard annotations），而這些都限制了實際應用性。我們提出 Critic-R，一個在推論（inference）與訓練（training）階段均明確閉合推理代理（reasoning agent）與檢索模型（retrieval model）間回饋迴路（feedback loop）的框架。Critic-R 引入一個批判模型（critic model），在代理處理檢索證據（retrieved evidence）後，評估其內省推理軌跡（introspective reasoning trace），以判斷所檢索的上下文是否充分支持下一個推理步驟（reasoning step）。Critic-R 具備兩個互補機制：Critic-R-Zero，一個推論時查詢精煉迴路（inference-time query refinement loop），迭代改寫查詢（queries）與檢索指令（retrieval instructions）；以及 Critic-Embed，一個針對檢索模型（retrieval model）的最佳化方法，利用成功與失敗的精煉軌跡（refinement trajectories）作為自動監督（automatic supervision），無需人工相關性標註（manual relevance annotation）。我們在 HotpotQA、2WikiMultihopQA、MuSiQue 與 Bamboogle 上評估 Critic-R。結果顯示，Critic-R 顯著提升了檢索品質（retrieval quality）與下游答案準確率（downstream answer accuracy）。

### 核心貢獻（3～5點）
- 提出 Critic-R 框架，於推論與訓練雙階段明確閉合推理代理與檢索模型間的回饋迴路，強化兩者的協同互動。
- 引入批判模型，透過評估代理的內省推理軌跡，動態判斷檢索證據是否充分支持下一個推理步驟。
- 設計 Critic-R-Zero 機制，於推論階段透過迭代改寫查詢與檢索指令，實現無額外訓練成本的查詢精煉迴路。
- 提出 Critic-Embed 方法，利用成功與失敗的精煉軌跡作為自動監督，無需人工相關性標註即可最佳化檢索模型。
- 在 HotpotQA、2WikiMultihopQA、MuSiQue 與 Bamboogle 等資料集上同時顯著提升檢索品質與下游答案準確率。

### 適合對象
從事檢索增強生成（RAG）、代理式搜尋、多跳問答與大型語言模型應用之研究者與工程師，特別是尋求以自動監督機制取代人工標註、並希望在推論階段動態精煉查詢以提升檢索效能的讀者。

## 深度分析

#### 方法論解析

Critic-R 框架旨在解決代理式搜尋（Agentic search）中檢索器（Retriever）優化的核心挑戰。傳統檢索增強生成（Retrieval-Augmented Generation, RAG）仰賴單輪生成前檢索（Single-turn pre-generation retrieval），難以處理需要分解（Decomposition）與資訊綜合（Information synthesis）的複雜查詢（Complex queries）。Critic-R 透過建立推理代理（Reasoning agent）與檢索模型（Retrieval model）之間的回饋迴路（Feedback loop），在推論（Inference）與訓練（Training）階段同時提升檢索品質（Retrieval quality）。

核心設計為引入獨立運作的批判模型（Critic model）。作者將其外置於底層模型（Underlying model）有兩項關鍵考量：首先，使框架可適用於任意推理代理，無需內建自我批判（Self-criticism）機制或修改代理本身；其次，在多步驟軌跡（Multi-step trajectories）中，累積上下文（Accumulated context）與推理雜訊（Reasoning noise）容易導致推理模型過度自信（Overconfident），降低對檢索失敗的敏感度，因此需要專用評估組件（Dedicated evaluation component）。具體而言，批判模型分析推理代理在消費檢索證據（Retrieved evidence）後產生的內省推理軌跡（Introspective reasoning trace）——即緊接在檢索後生成的即時推理內容——以判斷檢索上下文是否足以支撐下一個推理步驟（Reasoning step）。

此驗證訊號驅動兩項互補機制：

1. **Critic-R-Zero（推論階段方法）**：即推論時查詢精煉迴路（Inference-time query refinement loop），完全在推論時運作，無需任何額外梯度更新。當批判模型判定檢索證據不足時，會觸發查詢精煉（Query refinement），重寫檢索指令（Retrieval instructions）與查詢內容，再次執行迭代檢索動作（Iterative retrieval actions）。此精煉迴路（Refine Loop）持續直到推理代理滿意或達到預設的精煉預算上限。重要的是，推理代理本身保持凍結，僅與檢索文件互動，精煉過程由外部批判模型處理。此機制動態分配額外推論計算，以從檢索失敗中恢復。

2. **Critic-Embed（訓練階段方法）**：為攤銷迭代精煉帶來的計算開銷，利用 Critic-R-Zero 產生的精煉軌跡（Refinement trajectories）作為自動監督（Automatic supervision）。具體分為三階段：
   - **軌跡收集（Trajectory Collection）**：執行 Critic-R-Zero 收集成功與失敗的精煉軌跡。
   - **監督池（Supervision Pools）**：分為兩池。Pool 1 為對比式精煉呼叫（Contrastive refined calls）：被推理代理接受的文件列為正向文件（Positive documents），在失敗精煉嘗試中被拒絕的文件則作為困難負樣本（Hard negatives），即軌跡內負樣本；Pool 2 為僅正向（Positive-only）池，收錄首次嘗試即正確的查詢，僅含正向文件，不使用困難負樣本。
   - **對比訓練（Contrastive Training）**：以 Stella-400M 骨幹模型（Backbone）為基礎，採用 InfoNCE 目標函式。Pool 1 使用批次內負樣本（In-batch negatives，即批次內其他 B-1 個正向）搭配軌跡內困難負樣本；Pool 2 則為純正向訓練。最終產出經微調、具備指令感知能力的密集檢索器。

兩者可整合為統一的 Critic-R 系統：Critic-Embed 提供經訓練的檢索器，再於推論時疊加 Critic-R-Zero 的精煉能力，形成訓練與推論的閉環。

#### 實驗數據解讀

評估涵蓋四個具挑戰性的多跳問答（Multi-hop QA）資料集：HotpotQA、2WikiMultihopQA、MuSiQue 與 Bamboogle。這些資料集涵蓋不同複雜度的知識密集型任務（Knowledge-intensive tasks），適合驗證代理式搜尋系統（Agentic search systems）的極限效能。

實驗結果呈現三個層次的提升：

- **Critic-R-Zero 單獨使用**：在不同規模的推理代理上，透過迭代評估檢索證據並精煉查詢，顯著緩解檢索失敗，整體相對提升達 **12.4%**。這證明僅靠推論時計算擴展（Inference-time scaling）與內省推理回饋（Introspective Reasoning Feedback），無需重新訓練任何模型，即可有效改善下游答案準確率（Downstream answer accuracy）。

- **Critic-Embed 單獨使用**：相較於現成檢索器與既有聯合訓練（Co-training）基線，微調後的密集檢索器整體相對提升達 **7.5%**。這顯示利用成功與失敗軌跡作為自動監督，無需人工相關性標註（Manual relevance annotation）或黃金標準標註（Gold-standard annotations），即可有效優化檢索模型。

- **完整 Critic-R 系統（Critic-R-Zero + Critic-Embed）**：結合訓練後的檢索器與推論時精煉迴路，達到整體相對提升 **10.9%**。值得注意的是，此數值略低於 Critic-R-Zero 單獨使用的 12.4%，這可能暗示當檢索器本身已經過 Critic-Embed 優化後，推論時精煉的邊際效益會動態調整，或兩者間存在部分重疊的修正空間。然而，整體而言，明確在代理式推理迴路中建模檢索品質，確實能穩定提升最終答案正確性。

#### 與現有研究的比較

相較於早期 RAG 的單輪生成前檢索，Critic-R 針對需要多步驟內部審議（Internal deliberation）與迭代檢索的複雜查詢進行設計。與 IRCoT、ReAct 等透過提示工程交錯推理與檢索的方法相比，Critic-R 不僅交錯動作，更進一步引入外部批判模型來評估每次檢索的充分性，並將此回饋用於查詢重寫與檢索器微調。

與近期同樣關注代理式搜尋瓶頸的研究相比，差異更為明顯：

- **Agentic-R** 採用聯合訓練（Co-training）策略，同時建模區域查詢-段落相關性與全域答案正確性，並迭代地與代理共同優化檢索器。Critic-R 則選擇將問題拆分：Critic-R-Zero 完全在推論時運作，無需任何梯度更新；Critic-Embed 則利用推論軌跡產生自動監督，避免繁複的聯合訓練。

- **CoSearch** 透過神諭檢索實驗量化瓶頸，並以強化學習聯合訓練生成式重排器與推理代理，使用排名品質與最終答案正確性的複合獎勵。Critic-R 同樣診斷出檢索瓶頸，但採用模組化路徑：批判模型獨立於推理代理，檢索器透過對比訓練（Contrastive Training）微調，無需設計複雜的強化學習獎勵函式。

Critic-R 的主要優勢在於**模組化**與**資料效率**。由於不需要黃金標準標註，僅依賴推理代理的內省軌跡即可產生監督訊號，擴展性與實務應用性更高。然而，其限制亦顯而易見：Critic-R-Zero 的迭代精煉會增加推論延遲與計算成本；此外，系統效能高度依賴批判模型判斷檢索充分性的準確度，若批判模型誤判，可能導致不必要的精煉或過早終止。目前實驗以 Stella-400M 骨幹模型為基礎，雖然證明概念可行，但對於更大規模或跨語言語料庫的泛化能力仍需驗證。

#### 可重現性評估

論文明確聲明將釋出程式碼、資料與訓練模型，這對未來研究至關重要。實驗採用公開標準資料集（HotpotQA、2WikiMultihopQA、MuSiQue、Bamboogle），確保基線可比性。方法細節如 Stella-400M 骨幹模型、InfoNCE 目標函式、兩階段監督池設計等均有具體描述，理論上具備良好可重現性。

不過，由於釋出內容的實際託管位置、模型權重下載連結與確切資料處理流程在提供的上下文片段中未完整呈現，實際可重現性仍需視作者是否完整公開訓練軌跡與超參數設定而定。尤其 Critic-Embed 依賴 Critic-R-Zero 產生的精煉軌跡作為自動監督，若未公開這些中間軌跡資料，其他研究者需自行執行推論階段收集，將增加重現門檻。

#### 未來研究方向

基於 Critic-R 的架構，以下幾個方向值得深入探索：

1. **推論效率優化**：Critic-R-Zero 的迭代精煉雖提升準確率，但多次呼叫檢索模型與批判模型造成延遲。未來可研究動態預算分配策略，依據查詢複雜度或批判模型的不確定性，自適應決定精煉次數上限，甚至發展輕量級批判模型以加速每次評估。

2. **批判模型與檢索器的聯合學習**：目前批判模型與檢索器分開訓練。未來可探索在保持模組化優勢的前提下，讓批判模型與 Critic-Embed 進行輕度聯合微調，使批判訊號更貼近檢索器的表示空間，進一步提升回饋精準度。

3. **擴展至更大規模骨幹模型與多模態檢索**：當前使用 Stella-400M 作為骨幹模型，未來可驗證 Critic-Embed 在更大規模嵌入模型上的效益。此外，內省推理（Introspective reasoning）回饋的概念可擴展至多模態代理式搜尋，例如評估圖像或表格檢索結果是否支撐推理步驟。

4. **跨領域與開放領域驗證**：現有評估集中於多跳問答。未來可將 Critic-R 應用於更廣泛的知識密集型任務，如長文件分析、程式碼生成檢索、或即時資訊查證，檢驗其在非結構化、動態更新語料庫中的穩健性。

5. **負樣本挖掘策略的精進**：Critic-Embed 利用軌跡內困難負樣本進行對比訓練。未來可結合跨軌跡負樣本或基於批判模型分數的難度加權，設計更細緻的對比學習目標，以進一步區分語義相近但推理無用的文件。

6. **與生成式重排器的整合**：受 CoSearch 等研究啟發，可將 Critic-R 的檢索優勢與生成式重排結合，讓批判模型不僅判斷充分性，更直接產生重排分數或摘要，縮短檢索與推理之間的語義落差。

## 論文問答

**Q1：代理式搜尋系統在處理複雜查詢時面臨哪些核心挑戰？為何現有的檢索器優化方法難以在真實場景中規模化？**
A：代理式搜尋系統在處理需要資訊分解與多來源綜合的複雜查詢時，往往面臨檢索品質不足的瓶頸，因為單輪生成前檢索無法滿足動態且多步驟的資訊需求。現有方法若要優化檢索器，通常必須依賴繁重的聯合訓練或昂貴的黃金標準標註，這些需求在真實世界應用中不僅成本高昂，也難以隨資料量擴展。此外，這類方法往往缺乏彈性，無法輕易適用於不同的推理代理或領域，從而限制了其廣泛部署的可能性。

**Q2：現有的代理式搜尋方法（如 Agentic-R 與 CoSearch）存在什麼樣的根本限制，促使作者提出 Critic-R？**
A：Agentic-R 與 CoSearch 雖然正確診斷出檢索瓶頸，但它們仍透過與推理代理聯合訓練或設計複雜的強化學習獎勵函數來共同優化檢索器，導致訓練過程繁瑣且緊密耦合。這種設計不僅需要修改或深度整合底層推理模型，也限制了檢索器在不同代理之間的通用性與即插即用能力。相較之下，Critic-R 選擇將問題拆解為純推論階段的外部回饋迴路與無需人工標註的檢索器微調，從而避免了對推理代理本身進行任何修改或繁重聯合訓練的需求。

**Q3：為什麼在長程多步驟的代理式搜尋軌跡中，單靠推理代理自身的內省能力不足以評估檢索品質？**
A：在長程多步驟軌跡中，累積上下文與推理雜訊會導致推理模型變得過度自信，或對檢索失敗的敏感度逐漸下降。這種現象使得推理代理難以客觀判斷已檢索的文件是否真正包含繼續下一步推理所需的資訊，進而可能基於不足的證據做出錯誤決策。因此，作者主張需要一個專用的外部評估組件（即批判模型），獨立檢視代理的內省推理軌跡，以確保檢索品質獲得可靠且穩定的驗證。

**Q4：Critic-R 框架的核心設計包含哪兩個互補機制，它們分別在推論階段與訓練階段扮演什麼角色？**
A：Critic-R 包含 Critic-R-Zero 與 Critic-Embed 兩個互補機制。Critic-R-Zero 是一個純推論時的查詢精煉迴路，它透過批判模型評估檢索證據是否充分支持下一步推理，並在不足時迭代重寫檢索查詢與指令，整個過程無需任何梯度更新。Critic-Embed 則利用 Critic-R-Zero 執行過程中產生的成功與失敗精煉軌跡作為自動監督訊號，透過對比訓練微調密集檢索器，從而將推論階段的經驗內化為模型能力，並攤銷迭代精煉所帶來的計算開銷。

**Q5：批判模型（Critic Model）是如何利用「內省推理軌跡」來判斷檢索證據的充分性？這種設計有什麼獨特優勢？**
A：批判模型會分析推理代理在消費檢索證據後立即生成的內省推理軌跡，從中觀察代理是否明確指出已檢索文件包含繼續推理所需的資訊。這種設計的獨特優勢在於，它直接利用代理自身產生的文字回饋作為評估依據，而非僅依賴相關性分數或人工標註。此外，由於批判模型是獨立於推理代理的外部組件，因此可以應用於任意現成的推理代理，無需修改其底層架構或內建自我批判能力，具備極高的通用性與模組化彈性。

**Q6：Critic-Embed 如何在不依賴人工相關性標註的情況下，從執行軌跡中自動建構對比學習所需的正樣本與困難負樣本？**
A：Critic-Embed 將 Critic-R-Zero 執行過程中滿足推理代理、使其得以繼續推理的文件視為正樣本，而將在失敗精煉嘗試中被代理拒絕的文件視為軌跡內的困難負樣本。這些自動產生的監督訊號被納入對比訓練的監督池中，結合批次內負樣本與 InfoNCE 目標函數進行訓練。透過這種軌跡內對比學習，檢索模型能夠學習區分對推理有幫助與無幫助的文件，而完全不需要黃金段落或人工相關性標註，大幅降低了訓練資料的取得成本。

**Q7：作者在哪些多跳問答基準上評估 Critic-R？這些資料集的選擇反映了什麼樣的評估意圖？**
A：作者在 HotpotQA、2WikiMultihopQA、MuSiQue 與 Bamboogle 上進行評估。這些資料集涵蓋了不同難度、領域與類型的多跳推理需求，能夠全面檢驗方法在複雜查詢分解、資訊綜合與迭代檢索上的穩健表現。選擇這些基準的意圖在於證明 Critic-R 不僅能提升中間檢索品質，還能顯著改善最終的下游答案準確率，並且在不同挑戰程度的場景中皆具備良好的泛化能力。

**Q8：實驗結果顯示 Critic-R-Zero、Critic-Embed 以及兩者結合的 Critic-R 分別帶來了多少相對效能提升？**
A：實驗結果顯示，Critic-R-Zero 在推論階段透過迭代評估與查詢精煉，為不同規模的推理代理帶來了整體 12.4% 的相對改善。Critic-Embed 作為微調後的密集檢索器，相較於現成檢索器與先前聯合訓練的基線，最高可達到 7.5% 的相對提升。當兩者結合為完整的 Critic-R 系統時，整體相對改善達到 10.9%，顯示推論時精煉與檢索器微調之間具有強大的互補效應，能夠共同推動代理式搜尋的效能邊界。

**Q9：從實驗設計來看，Critic-R-Zero 在不同規模推理代理上的表現驗證了什麼樣的關鍵假設？**
A：Critic-R-Zero 在不同規模推理代理上皆能顯著緩解檢索失敗，這驗證了外部批判模型作為獨立評估組件具有跨模型的通用性與穩健性。此結果表明，檢索品質的瓶頸可以透過推論時的顯式回饋迴路來有效緩解，而無需針對特定代理進行重新訓練或修改其內部架構。這也強力支持了作者的核心主張：將檢索品質的評估與精煉機制外掛到現有代理上，是提升代理式搜尋系統效能的一條務實且可擴展的途徑。

**Q10：在實際產品部署中，Critic-R 的「無需修改底層推理代理」特性具有什麼樣的工程價值？**
A：這項特性使得 Critic-R 能夠以即插即用的方式整合到現有的 RAG 或代理式搜尋產品中，無需重新訓練昂貴的大型語言模型或調整其內部提示工程。對於企業而言，這大幅降低了導入新檢索優化技術的門檻與風險，因為可以在不影響既有推理管線的前提下，透過外掛批判模型與檢索器來提升整體問答品質。此外，這種解耦設計也便於獨立迭代與維護檢索元件，使系統更具模組化、可解釋性與長期可擴展性。

**Q11：Critic-R-Zero 的推論時迭代精煉雖然有效，但可能帶來計算開銷；Critic-Embed 如何從系統設計角度回應這項顧慮？**
A：Critic-Embed 的核心價值正是透過一次性地微調檢索器，將 Critic-R-Zero 在推論過程中累積的成功與失敗經驗內化為檢索模型的參數知識。這樣一來，經過微調的檢索器在後續推論中能更準確地返回相關文件，從而減少迭代精煉所需的次數，達到攤銷計算成本的效果。這種「以訓練換推論」的設計權衡，使得系統在保持高效能的同時，也能控制延遲與計算資源的消耗，更適合高吞吐量的生產環境部署。

**Q12：Critic-R 對於代理式搜尋與檢索增強生成領域的研究範式可能帶來什麼樣的深遠影響？**
A：Critic-R 示範了無需聯合訓練或人工標註即可優化檢索器的新路徑，這可能促使研究社群更重視「執行軌跡作為自動監督訊號」的價值。它將焦點從「如何讓推理代理學會檢索」轉向「如何建立顯式的外部回饋迴路來診斷並修正檢索失敗」，從而豐富了 RAG 系統的設計維度。長遠來看，這種批判式的外掛架構可能成為未來複雜 AI 代理系統的標準配備，推動知識密集型應用朝更模組化、可解釋與可維護的方向發展。

**Q13：儘管 Critic-R 表現優異，但推論時的迭代精煉機制存在什麼樣的內在限制？**
A：Critic-R-Zero 依賴預先定義的精煉預算，這意味著若在預算耗盡前仍未能檢索到充分證據，系統將無法進一步恢復檢索失敗，只能以不完整的資訊繼續推理。此外，每次迭代都會呼叫批判模型與檢索器，增加了推論延遲與計算成本，對於延遲敏感的應用場景可能構成挑戰。更重要的是，若批判模型本身對內省推理軌跡做出錯誤判斷，可能導致錯誤的查詢重寫方向，進而使精煉迴路陷入無效循環，反而浪費計算資源。

**Q14：在什麼樣的情境下，Critic-R 的批判模型可能會誤判檢索證據的充分性，導致精煉迴路失效？**
A：當推理代理的內省推理軌跡本身含糊不清、過度簡略，或受到累積上下文的嚴重雜訊干擾時，批判模型可能難以準確判斷證據是否充分支持下一步推理。此外，若查詢涉及高度專業、邊緣或新興知識，批判模型可能缺乏足夠的背景知識來評估檢索結果與推理步驟之間的邏輯關聯。在這些情況下，批判模型可能錯誤地將不充分的證據標記為足夠，或反之過度挑剔而發起不必要的精煉，導致後續的查詢精煉方向偏離正確答案。

**Q15：基於 Critic-R 的架構，未來研究可以從哪些方向進一步擴展或改進？**
A：未來研究可以探索讓批判模型本身具備更強的領域適應能力，以處理超越開放領域問答的專業任務，例如醫療診斷、法律檢索或科學文獻分析。另一個方向是將 Critic-R 的回饋機制擴展到答案生成階段，不僅評估檢索證據的充分性，也同時監督生成內容的忠實度與事實正確性，形成更完整的品質控管迴路。此外，開發更輕量化的批判模型，或將精煉決策與終止條件建模為可學習的策略而非固定的迭代預算，也有助於進一步降低推論開銷並提升系統的自主決策能力。

## 實務應用指南

### 適用場景

1. **企業內部知識庫多跳問答**：法務或合規團隊查詢「某合約條款在最新法規修訂後的風險為何」，需從多份文件進行資訊綜合與分解，單輪生成前檢索難以滿足。
2. **醫療文獻與病歷交叉檢索**：醫師詢問「某罕見疾病在特定基因型患者上的用藥禁忌」，需串連疾病資料庫、藥物資料庫與臨床試驗報告，透過迭代檢索動作逐步收斂證據。
3. **金融研究與投資盡職調查**：分析師追問「某公司董事長在過去三年擔任其他董監事期間，那些公司發生的重大違規事件」，涉及人物關係圖譜與新聞事件的複雜查詢。
4. **複雜技術支援與故障排除**：處理需拆解成多個子問題的查詢，例如「此錯誤碼在混合雲架構且使用特定版本 Kubernetes 時的根因」，代理式搜尋系統需逐步確認各層檢索證據。
5. **學術研究輔助系統**：協助研究人員進行文獻回顧，回答需要跨論文比較方法論差異的問題，如「比較近五年使用對比學習於醫學影像分割的兩種不同正負樣本選擇策略」。

### 實作前置條件

- **資料**：需具備領域相關的外部語料庫（如 PDF、HTML、結構化資料庫），以及用於初始化批判模型的內省推理軌跡資料。若採用 Critic-Embed，需先以 Critic-R-Zero 收集成功與失敗的精煉軌跡作為自動監督訊號，無需人工相關性標註，但建議至少準備數萬筆查詢以建立穩定的監督池。
- **運算**：推論階段需能同時部署推理代理與批判模型兩個大型語言模型（LLM）的 GPU 資源，並支援迭代檢索的 I/O 吞吐量；若進行 Critic-Embed 的對比訓練，需額外具備可微調稠密檢索器（如 Stella-400M 等骨幹模型）的運算資源，建議至少單張 A100 或同等級顯卡。
- **技能**：團隊需熟悉檢索增強生成（RAG）管線建置、對比訓練與多代理系統設計，並具備將內省推理軌跡轉換為批判模型輸入提示的工程能力，同時理解無需黃金標準標註的自動監督資料建構邏輯。

### 實作步驟建議

1. **基線 RAG 建置**：先建立現有的單輪或簡單多輪 RAG 系統作為基線，確認語料庫已建立索引，且推理代理能產生明確表達檢索證據是否足夠的內省推理軌跡。
2. **部署 Critic-R-Zero**：引入獨立的批判模型作為專用評估組件，設定推論時查詢精煉迴路。定義檢索證據充分性的判斷準則，讓批判模型檢視推理代理在消耗檢索文件後的內省推理軌跡，決定是否重寫檢索指令與查詢。
3. **軌跡收集與監督池建構**：運行 Critic-R-Zero 於訓練集查詢上，自動收集成功精煉軌跡（最終被接受的文件作為正向文件）與失敗軌跡（被批判模型拒絕的文件作為困難負樣本與負向文件），形成自動監督資料並分別匯入監督池。
4. **Critic-Embed 訓練**：利用收集到的軌跡進行對比訓練，採用批次內負樣本與軌跡內困難負樣本，微調檢索模型使其成為具指令感知能力的稠密檢索器，提升後續檢索品質。
5. **整合與部署**：將微調後的 Critic-Embed 檢索器與 Critic-R-Zero 的推論時精煉迴路整合為完整的 Critic-R 系統，並設定精煉預算（如最多重試次數）以控制延遲與成本，持續監控下游答案準確率。

### 潛在風險與注意事項

- **延遲與成本膨脹**：Critic-R-Zero 的迭代精煉會顯著增加推論延遲與 LLM 呼叫成本，建議設定明確的精煉預算上限，並在延遲敏感場景中優先部署 Critic-Embed 以降低迭代次數。
- **批判模型誤判**：若批判模型過度保守，可能導致無意義的重複檢索；若過度寬鬆，則無法過濾不相關文件。需透過驗證集校準批判模型的判斷閾值，維持其獨立性。
- **錯誤累積與過度自信**：在多步驟軌跡中，推理代理可能因累積上下文與推理雜訊而過度自信，因此必須避免批判模型與推理代理共用參數或過早融合狀態，確保回饋迴路的客觀性。
- **領域遷移落差**：Critic-Embed 的自動監督來自特定領域的精煉軌跡，若部署領域與訓練領域差異過大，檢索品質可能下降，建議保留持續收集軌跡與定期重新微調的機制。

### 與其他技術的整合建議

- **與現有 RAG 管線整合**：Critic-R 可視為現有 RAG 系統的增強層，無需修改底層推理代理。可將 Critic-R-Zero 封裝為查詢重寫與檢索驗證的中介服務，插入於原有檢索器與生成器之間。
- **與向量資料庫整合**：Critic-Embed 微調後的稠密檢索器可直接替換現有向量資料庫的嵌入模型，只需重新建立索引即可提升召回品質，無需更換資料庫本身。
- **與強化學習或 GRPO 整合**：若系統已採用 Agentic-R 或 CoSearch 等聯合訓練框架，可將 Critic-R 作為輕量替代方案，先利用其無需黃金標準標註的特性以自動監督訓練檢索器，再視需求銜接強化學習進行端到端最佳化。
- **與監控系統整合**：將批判模型的判斷結果（接受、拒絕或精煉）與最終答案正確性記錄至可觀測平台，作為後續改善批判模型與檢索器的回饋迴路數據。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先理解 RAG 與代理式搜尋的基本概念，再聚焦於圖一與 Critic-R-Zero 的運作流程。本論文的核心價值在於「讓另一個模型檢查檢索結果是否足夠」，這個直覺概念比技術細節更重要；遇到對比訓練或 InfoNCE 等術語時，可先略過數學細節，掌握「用成功與失敗的搜尋紀錄自動訓練檢索器」這個設計思想即可。
- **AI 工程師**：請重點關注 Critic-R-Zero 的推論時查詢精煉迴路實作細節，以及 Critic-Embed 的三階段訓練流程（軌跡收集、監督池建構、對比訓練）。實作時需特別注意批判模型提示詞的設計，確保其能正確解析推理代理的內省推理軌跡；同時評估 Stella-400M 等骨幹模型在自身語料庫上的微調成本與效益。
- **研究人員**：本論文與 Agentic-R、CoSearch 等聯合訓練方法形成鮮明對比，建議深入分析「分離式批判模型」相對於「內建自我批判」在長程多步驟軌跡中的優勢與限制。此外，自動監督訊號的品質與負樣本採樣策略（軌跡內困難負樣本 vs. 批次內負樣本）是值得延伸探討的技術點。
- **產品經理**：請將閱讀重心放在「適用場景」與「實作前置條件」。Critic-R 的價值主張是「在不需要昂貴人工相關性標註的前提下，顯著提升複雜查詢的檢索品質」，但需權衡推論時迭代精煉帶來的延遲成本。建議評估產品中複雜查詢的比例，若多跳問答佔比高且現有 RAG 召回率不足，則 Critic-R 具備高投資報酬率。
