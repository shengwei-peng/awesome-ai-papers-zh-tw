# ToolSmith：一個用於多模態搜尋代理的自動工具生成框架

## ⚡ TL;DR

多模態搜尋代理仰賴固定的手工工具庫，難以因應新型查詢與失敗模式。
本文提出ToolSmith框架，透過軌跡挖掘、重用決策、工具生成與雙重驗證四階段自動擴充工具庫。
在三個領域內與十個領域外基準測試中，工具庫效能顯著提升，且骨幹模型越大增益越明顯。

---

## 摘要翻譯

近期，多模態搜尋代理透過編排一個小型的手工打造搜尋與視覺工具庫，在多個回合中結合推理、視覺與即時網路搜尋，以回答超出參數化知識範疇的問題。然而，該工具庫的建立與維護相當費力，且在實際應用中遇到新的查詢類型、證據格式與失敗模式時便會凍結而無法靈活調整。相較之下，人類實務工作者會以熟悉的元件打造新工具並跨任務重複使用，以應對工具不足的問題。受此啟發，我們提出了 ToolSmith——一個在精簡基礎工具庫之上擴展並重複使用模組的自動工具生成框架。我們在視覺語言模型即評審（VLM-as-a-Judge）協議下，於三個領域內多模態搜尋基準測試與十個領域外基準測試上評估 ToolSmith。ToolSmith 在已部署的各種規模代理上皆持續優於基礎工具庫，且主幹模型（Backbone）越大，增益越為顯著，展現了此方法的可擴展性（Scalability）。我們的程式碼與資料已公開於 https://threesr.github.io/toolsmith/。

### 核心貢獻（3～5點）
- **問題洞察**：揭示現有多模態搜尋代理所依賴的手工打造工具庫存在建立維護成本高、面對新查詢類型、證據格式與失敗模式時缺乏彈性的根本瓶頸。
- **方法創新**：提出 ToolSmith 框架，模仿人類實務工作者「以熟悉元件組裝新工具並跨任務重用」的思路，在精簡基礎工具庫之上自動生成並重複使用模組。
- **實驗驗證**：在視覺語言模型即評審協議下，於三個領域內與十個領域外多模態搜尋基準測試上進行系統性評估，證實 ToolSmith 對不同規模代理皆有一致且穩定的效能提升。
- **可擴展性證明**：實驗結果顯示主幹模型規模越大，ToolSmith 所帶來的增益越為顯著，驗證了該框架的可擴展性與實務部署潛力。

### 適合對象
從事多模態大型語言模型、視覺語言代理、自動化工具合成（Tool Synthesis）、檢索增強生成（RAG）與代理系統（Agentic Systems）研究的學者與工程師；亦適合關注 AI 代理在開放世界與線上系統中自主能力建構之業界實務人員。

## 深度分析

#### 方法論解析

ToolSmith 提出一個**模型無關 (model-agnostic)** 的四階段管線 (pipeline)，目標是讓多模態搜尋代理 (multimodal search agent) 在面對既有工具庫無法解決的查詢時，能夠自主「打造」新工具，而非僅止於「使用」既有工具。以下逐一解析各階段的設計邏輯與技術意涵。

**階段一：軌跡挖掘 (Trajectory Mining)**
此階段的核心任務是從代理執行失敗的軌跡 (agent trajectory) 中萃取出「能力缺口 (capability gaps)」。具體做法是將失敗的多輪對話軌跡進行聚類 (clustering)，把表現出相似失敗模式的案例歸為同一缺口。這借鑑了自我反思型代理 (Shinn et al., 2023) 與經驗回放 (Andrychowicz et al., 2017) 的概念，但特別強調「軌跡層級」的失敗模式識別，而非單純的獎勵信號回放。對多模態搜尋而言，軌跡中混合了影像、連結引用、工具輸出等異質資訊，使得缺口識別比純文字環境更具挑戰性。

**階段二：重用或生成決策 (Reuse-or-Grow Decision)**
此階段將識別出的能力缺口與一個精簡的基礎工具庫 (lean base tool library，僅含八個基本元件 primitives) 進行比對，決定該缺口是否能透過既有工具的組合 (reuse) 解決，或必須生成新工具 (grow)。這個決策機制避免了「過度生成」的問題——若既有工具已足夠，便無須引入新的複雜度。這呼應了人類專家「先試試看現有工具，不行再打造新工具」的認知經濟學原則 (Goodall, 1964; Beck, 1980)。

**階段三：工具生成 (Tool Generation)**
此階段使用生成式視覺語言模型 (generator VLM) 撰寫新工具的 Python 原始碼，並以「結構性約束 (structural constraints)」與「反硬編碼約束 (anti-hardcode constraints)」加以限制。前者確保生成的工具符合型別化結構描述 (typed schema)，能被代理的推理迴圈 (reasoning loop) 正確呼叫；後者則避免生成僅針對特定案例硬編碼 (hardcode) 的「假工具」，迫使模型產出可泛化的通用工具。這是 ToolSmith 設計中最關鍵的環節，因為它直接決定了新工具的可重用性。

**階段四：雙重驗證 (Two-Gate Verification)**
此階段借鑑人類專家在採用新工具前會進行測試驗證的行為 (Schön, 1983)，設置兩道把關機制：
- **沙盒健全性檢查 (sandboxed sanity check)**：在隔離環境中執行新工具，確認其能正常運作且無安全風險。
- **LLM 靜態程式碼審查 (LLM static code-review)**：由另一個 LLM 對程式碼進行靜態分析，檢查邏輯正確性與是否符合規範。

只有通過兩道驗證的工具才會被納入擴充工具庫 (expanded tool library)，供代理在推論 (inference) 時自由調用。

整體而言，ToolSmith 的方法論體現了「使用 + 打造 + 驗證」三位一體的設計哲學，與人類專家的工具使用模式高度對齊。

#### 實驗數據解讀

**基準測試設計**
實驗涵蓋 **3 個領域內基準 (in-domain benchmarks)**：FVQA、InfoSeek、EncyclopedicVQA，以及 **10 個領域外基準 (out-of-domain benchmarks)**，並採用 **VLM-as-a-Judge (視覺語言模型即評審)** 協議進行評估。這樣的設計能同時檢驗工具生成在「熟悉環境」與「陌生環境」下的泛化能力。

**主要結果**
- 當使用 **Qwen3-VL-8B-Instruct** 作為代理主幹模型 (backbone) 時，ToolSmith 在領域內任務上提升 **+2.20 個百分點 (pp)**，在領域外任務上提升 **+1.33 pp**。
- 當升級至 **Qwen3-VL-32B-Instruct** 時，領域外增益擴大至 **+2.98 pp**，呈現明顯的「主幹模型越大，增益越大」的可擴展性 (scalability) 趨勢。
- 在 **GPT-5** 上亦觀察到一致的提升 (consistent uplift)，證實框架對不同模型家族的通用性。

**數據解讀的關鍵意涵**

1. **領域外增益的價值**：領域外基準的提升尤為重要，因為它證明生成的新工具具備**跨任務的可遷移性 (transferability)**，而非僅是針對訓練分布的過擬合 (overfitting)。這呼應了論文中強調的「模組可重用 (module reuse)」特性。

2. **可擴展性曲線**：主幹模型容量與增益的正相關，暗示較強的模型能更有效地「理解」新工具的能力邊界，並在合適的時機調用它們。這與工具學習 (tool learning) 文獻中觀察到的「湧現能力 (emergent ability)」現象一致。

3. **消融研究的覆蓋面**：作者進行了全面的消融研究 (ablation study)，分析**開銷 (overhead)、新工具使用率 (new-tool usage)、工具呼叫分佈 (tool-call distribution)、工具過濾 (tool-filtering) 與失敗模式 (failure modes)**。這提供了客觀的效能景觀 (objective landscape)，有助於理解每個設計選擇的邊際貢獻。

4. **基準選擇的代表性**：所選基準涵蓋了從事實型視覺問答 (FVQA) 到百科型問答 (EncyclopedicVQA) 的不同難度層級，能有效檢驗工具生成在不同視覺理解需求下的表現。

#### 與現有研究的比較

**定位差異**
ToolSmith 與現有研究存在三條明顯的分野：

1. **vs. 記憶學習型方法 (Xiao et al., 2025)**：後者學習的是「如何在固定工具庫中更聰明地使用工具」，屬於**使用層面的優化**；ToolSmith 則擴展了**工具本身的範疇**，屬於**生成層面的創新**。

2. **vs. 工具使用效率訓練 (Gao et al., 2025; Wu et al., 2026)**：這些方法透過訓練讓代理更熟練地操作既有工具，但同樣不改變工具庫的組成。ToolSmith 突破了這個限制。

3. **vs. 其他領域的工具生成研究 (Chen et al., 2024; Yuan et al., 2024; Wölflein et al., 2025; Wang et al., 2023, 2025)**：這些工作已在視覺語言理解、數學與表格問答、一般 NLP、具身 (embodied) 與電腦使用 (computer-use) 代理等領域探索過工具生成，但**尚未被移植到多模態搜尋**。ToolSmith 填補了這個空白，並指出移植的關鍵挑戰在於「搜尋代理軌跡較長，且代理狀態混合了影像、連結引用與工具輸出」。

**理論基礎的深化**
ToolSmith 的靈感來自人類學與認知科學的經典文獻：Goodall (1964) 觀察到野生黑猩猩會改造工具；Beck (1980) 記錄人類祖先的石器製作；Tomasello (1999) 從發展心理學角度論述工具使用的社會學習。這些引用並非裝飾，而是用來論證「**使用 + 打造**」是人類工具認知的雙引擎，現有代理僅實現了前者。

**改進幅度**
相較於固定工具庫的基線，+2.20 pp (領域內) 與 +1.33–2.98 pp (領域外) 的提升在多模態搜尋基準上屬於**實質性進步**，因為這類基準的隨機猜測基線通常較低，且涉及多步推理與證據整合，每提升一個百分點都代表顯著的能力突破。

**侷限性**
- 論文中未明確說明**生成工具的數量上限**與**工具庫膨脹 (tool library bloat)** 的控制機制。
- **雙重驗證的成本**（沙盒執行 + LLM 程式碼審查）會帶來額外的計算開銷，論文中雖提及「overhead」消融，但具體數字未在提供的文本中呈現。
- 對於**安全敏感的領域**（如醫療、法律），自動生成的程式碼可能引入未預見的風險，論文的驗證機制是否能完全防堵此類問題，仍待進一步驗證。

#### 可重現性評估

**優點**
- 程式碼與資料已公開於專案網站 **https://threesr.github.io/toolsmith/**，符合現代機器學習研究的可重現性標準。
- 框架設計為**模型無關 (model-agnostic)**，理論上可與任何支援工具呼叫的視覺語言模型整合，這大幅降低了復現的門檻。
- 評估採用 **VLM-as-a-Judge** 協議，雖然依賴評審模型的判斷，但避免了人工標註的高成本與不一致性。

**潛在挑戰**
- **評審模型的偏見**：VLM-as-a-Judge 可能對某些答案形式存在系統性偏見，例如傾向選擇較長或較詳細的回應。論文中未詳細說明如何緩解此問題。
- **基準的可得性**：3 個領域內基準 (FVQA、InfoSeek、EncyclopedicVQA) 與 10 個領域外基準的具體名稱與下載方式需透過專案網站確認，部分基準可能需要額外的授權或申請流程。
- **工具生成的隨機性**：由於新工具是由生成式 VLM 撰寫，不同的隨機種子 (random seed) 可能產生不同的工具集，進而影響最終效能。論文中是否提供了固定的工具集快照 (snapshot) 以確保完全可重現，仍需查閱程式碼庫確認。
- **GPT-5 的存取成本**：實驗涉及 GPT-5，這是一個閉源模型，第三方研究者復現時需承擔相應的 API 成本，可能限制研究的可及性。

**整體評估**
可重現性處於**中等偏上**的水準。公開程式碼與資料是基本要求，ToolSmith 已滿足；但若能進一步提供預生成的工具庫快照、固定的隨機種子設定，以及評審模型的校準細節，將有助於提升研究的可信度與可比較性。

#### 未來研究方向

**1. 工具庫的動態剪枝 (Dynamic Pruning)**
隨著代理持續生成新工具，工具庫可能膨脹至難以管理的規模。未來可研究**自動淘汰 (automatic retirement)** 機制，例如根據使用頻率、貢獻度或冗餘度，主動移除低價值工具，以維持工具庫的精簡與高效。

**2. 工具組合的自動發現 (Automatic Tool Composition)**
ToolSmith 目前聚焦於「單一工具的生成」。未來可探索**工具組合 (tool composition)** 的自動化，即讓代理不僅生成新工具，還能發現既有工具之間的非顯而易見的串接模式，形成更高階的工作流 (workflow)。

**3. 跨模態工具的統一表示 (Unified Representation)**
當前工具的輸入輸出混合了文字、影像、URL 等異質模態。未來可設計**統一的型別化結構描述 (typed schema)**，使工具之間的介面更加標準化，降低整合成本並提升可組合性。

**4. 安全性與可解釋性強化 (Safety & Interpretability)**
自動生成的程式碼存在安全風險。未來可引入**形式化驗證 (formal verification)** 或**符號執行 (symbolic execution)** 技術，補強現有的雙重驗證機制。同時，應研究如何讓生成的工具具備**可解釋性 (interpretability)**，例如自動產生工具的功能說明文件與使用範例。

**5. 從工具生成到工具學習的閉環 (Closed-Loop Tool Learning)**
ToolSmith 目前是「離線生成、線上使用」的模式。未來可探索**線上學習 (online learning)** 的可能性，讓代理在使用過程中持續觀察工具的表現，並動態調整或優化工具庫，實現真正的終身學習 (lifelong learning)。

**6. 應用領域的擴展 (Domain Expansion)**
雖然 ToolSmith 聚焦於多模態搜尋，但其框架可望移植至其他需要長程推理與多工具協作的場景，例如**科學文獻回顧 (scientific literature review)**、**自動化資料分析 (automated data analysis)** 或**智慧助理 (intelligent assistant)** 等。

**7. 人機協作的工具精煉 (Human-in-the-Loop Refinement)**
完全自動的工具生成可能產生品質不穩定的工具。未來可設計**人機協作 (human-in-the-loop)** 機制，讓人類專家對生成的工具進行審閱、修改與標註，藉此建立高品質的工具資料集，並用於訓練更強大的工具生成模型。

**8. 理論分析：工具生成的必要條件 (Theoretical Analysis)**
目前缺乏對「**何時應該生成新工具**」的理論分析。未來可從資訊理論 (information theory) 或計算複雜度 (computational complexity) 的角度，形式化定義工具生成的邊界條件，為框架的設計提供更堅實的理論基礎。

## 論文問答

**Q1：多模態搜尋代理（Multimodal Search Agent）目前面臨的核心問題是什麼？為什麼這個問題值得研究？**
A：當前的多模態搜尋代理仰賴一套固定且手工打造的工具庫（hand-crafted tool library），其中包含文字搜尋、圖片搜尋、瀏覽網頁、放大檢視、光學字元辨識、視覺定位、程式碼執行與深度估計等基本元件。這套工具庫的建置與維護成本極高，且在開發者預期的覆蓋範圍之外就會「凍結」，一旦遇到新型態的查詢、未見過的證據格式或失敗模式，便需要人工介入修改。更關鍵的是，現有研究雖然透過學習記憶或訓練更有效率地使用工具來強化代理，卻從未擴展代理「擁有」哪些工具，因此這個工具覆蓋率的瓶頸成為多模態搜尋領域中尚未被解決的根本問題。

**Q2：為什麼現有的「學習如何使用工具」或「記憶增強」方法無法解決工具不足的問題？**
A：互補性的研究方向，例如學習在固定工具庫上的記憶（Xiao et al., 2025）或訓練代理更有效率地使用既有工具（Gao et al., 2025；Wu et al., 2026），雖然能強化代理「如何」使用工具，卻無法擴展代理「擁有」哪些工具。這類方法本質上是在固定的工具清單上做最佳化，無法因應真實世界中持續湧現的新查詢類型與失敗模式。換言之，它們解決的是工具使用效率的問題，而非工具覆蓋率的問題，因此無法從根本上突破手工打造工具庫的限制。

**Q3：人類實務工作者在面對工具不足時是如何應對的？這個觀察如何啟發 ToolSmith 的設計？**
A：人類實務工作者在探索世界時，不僅會使用既有工具，還會在現有工具不足時，從熟悉的零件中「打造」新工具，並在跨任務中重複使用與精煉這些工具（Goodall, 1964；Beck, 1980；Tomasello, 1999）。此外，人類並不會盲目採用每一個新設計的實作，而是會在將其納入工作工具庫之前，先透過測試案例進行驗證（Schön, 1983）。ToolSmith 正是受到這種人類行為的啟發，試圖讓多模態搜尋代理同時具備「使用」與「打造」工具的能力，並在納入新工具前進行嚴格的驗證，以兼顧擴展性與可靠性。

**Q4：ToolSmith 的四階段流程（Trajectory Mining、Reuse-or-Grow Decision、Tool Generation、Two-Gate Verification）各自負責什麼任務？**
A：在「軌跡挖掘」（Trajectory Mining）階段，系統會將代理失敗的軌跡聚類為能力缺口（capability gaps），以找出工具不足的具體模式。接著在「重用或生成決策」（Reuse-or-Grow Decision）階段，系統會將每個缺口與精簡的八個基本元件工具庫比對，決定應該重用既有工具還是生成新工具。第三階段「工具生成」（Tool Generation）則提示一個生成式視覺語言模型，在結構性與反硬編碼的限制下，以 Python 原始碼撰寫新工具。最後在「雙重閘門驗證」（Two-Gate Verification）階段，新工具必須通過沙盒化的健全性檢查與基於 LLM 的靜態程式碼審查，才會被正式納入工具目錄。

**Q5：ToolSmith 最核心的創新點是什麼？它與傳統的工具整合方法有何本質差異？**
A：ToolSmith 最核心的創新在於將工具生成從「人類開發者的工作」轉變為「代理自身的可學習能力」，並透過嚴格的雙重驗證機制確保生成品質。與傳統方法相比，ToolSmith 不再依賴凍結的工具清單，而是讓代理能根據實際失敗經驗，自動識別能力缺口、生成對應的新工具，並在驗證後納入工具庫。這種「邊做邊學、邊學邊擴充」的模式，使代理能夠持續適應真實世界中不斷演變的查詢類型與證據格式，而無需等待人類工程師手動更新工具。

**Q6：ToolSmith 在設計上做了哪些關鍵的取捨？例如「精簡基礎工具庫」的選擇與「雙重驗證」的設計理念為何？**
A：ToolSmith 選擇以八個基本元件構成精簡基礎工具庫，目的是讓重用與生成的決策更清晰，並避免基礎庫本身就過於龐雜而失去模組化的意義。在驗證方面，雙重閘門（沙盒健全性檢查 + LLM 靜態程式碼審查）的設計則體現了「寧缺勿濫」的原則：只有通過嚴格檢查的工具才會被納入，以避免低品質或帶有硬編碼偏見的工具污染工具庫。此外，生成過程中還加入了「反硬編碼限制」（anti-hardcode constraints），確保新工具具有泛化能力而非僅針對特定案例，這些設計共同保證了擴充後的工具庫既豐富又可靠。

**Q7：ToolSmith 在哪些基準測試上進行了評估？為什麼選擇這些特定的基準？**
A：ToolSmith 在三個領域內基準（FVQA、InfoSeek、EncyclopedicVQA）與十個領域外基準上進行了評估，並採用 VLM-as-a-Judge 協議進行評分。選擇這些基準是因為它們涵蓋了多模態搜尋的核心挑戰：視覺事實問答、資訊尋求與百科式視覺問答，能夠全面檢驗代理在跨模態資訊整合上的能力。領域外基準的設計則是為了驗證 ToolSmith 生成工具的泛化性，確保其在未見過的查詢類型上仍能帶來穩定的效能提升。

**Q8：ToolSmith 的主要實驗結果為何？不同規模的模型呈現怎樣的趨勢？**
A：使用 Qwen3-VL-8B-Instruct 模型時，ToolSmith 生成的工具在領域內任務上帶來 +2.20 個百分點的提升，在領域外任務上則有 +1.33 個百分點的增益。值得注意的是，效能提升會隨著主幹模型（backbone）規模的擴大而擴大：在 Qwen3-VL-32B-Instruct 上，領域外任務的提升達到 +2.98 個百分點，並在 GPT-5 上也觀察到一致的增益。這顯示 ToolSmith 的方法具有良好的可擴展性（scalability），主幹模型越強，越能善用自動生成的新工具。

**Q9：ToolSmith 進行了哪些消融研究（Ablation Study）？這些研究揭示了哪些關鍵發現？**
A：ToolSmith 進行了多面向的消融研究，包括不同工具生成模型的影響、訓練樣本數量的影響、開銷分析、新工具使用率、工具呼叫分佈、工具過濾效果與失敗模式分析。這些研究共同描繪出 ToolSmith 的客觀應用景觀：例如，較大的生成模型能產出更高品質的工具；適當的訓練樣本數量能平衡生成多樣性與品質；雙重驗證機制能有效過濾掉不穩定的工具；而失敗模式分析則揭示了 ToolSmith 在哪些情境下仍有改進空間，例如極度複雜的多步驟推理或需要高度專業領域知識的工具生成。

**Q10：ToolSmith 在實際應用中適合哪些場景？例如新聞查證、學術研究或商業分析？**
A：ToolSmith 特別適合需要跨模態資訊整合且查詢類型持續演變的場景，例如新聞查證（如同論文中「馬尼拉人質事件」的範例，需要從圖片中識別事件並交叉驗證細節）、學術研究中的多模態文獻溯源，以及商業分析中的視覺化資料探索。在這些場景中，固定的工具庫往往無法預先覆蓋所有可能的查詢模式，而 ToolSmith 的自動工具生成能力使代理能夠即時適應新的證據格式與失敗模式，大幅提升實用價值。

**Q11：如果要將 ToolSmith 整合到實際產品中，需要考量哪些工程與產品面向？**
A：在工程層面，需要考量沙盒化執行的安全性（避免生成的程式碼造成系統損害）、工具呼叫的延遲成本（自動生成與驗證會帶來額外的推論時間），以及工具庫的版本管理與回滾機制。在產品層面，則需要設計使用者介面來呈現代理的工具使用軌跡與新工具的生成過程，以建立使用者信任；同時也要考量不同垂直領域的客製化需求，例如醫療或法律領域可能需要更嚴格的驗證標準與領域專屬的基本元件工具庫。

**Q12：ToolSmith 對多模態代理研究領域可能帶來哪些長遠影響？**
A：ToolSmith 開啟了「代理自我擴展工具能力」的研究方向，可能促使學術界與工業界重新思考代理的設計範式：從「人類預先定義所有工具」轉向「代理在實踐中自主擴充工具」。這種範式轉移將推動相關研究的發展，例如更高效的工具驗證機制、更可靠的程式碼生成模型，以及跨任務的工具重用理論。長遠來看，ToolSmith 所代表的方向可能是邁向更自主、更通用人工智慧代理的重要一步。

**Q13：ToolSmith 存在哪些已知的限制？例如對生成模型品質的依賴或驗證機制的不足？**
A：ToolSmith 的效能高度依賴生成式視覺語言模型的程式碼撰寫能力，若生成模型本身品質不足，則產出的工具可能無法通過驗證或泛化能力不佳。此外，雙重驗證機制雖然能過濾明顯有問題的工具，但對於語意層面的正確性（例如工具是否真正解決了預期的能力缺口）仍難以完全保證。論文的失敗模式分析也顯示，在極度複雜的多步驟推理或需要高度專業領域知識的情境下，ToolSmith 的表現仍有改進空間。

**Q14：ToolSmith 在哪些特定情境下可能會失敗？論文中提到的失敗模式有哪些？**
A：論文的消融研究中分析了 ToolSmith 的失敗模式，其中可能包括：生成模型無法理解複雜的能力缺口導致工具設計錯誤、生成的程式碼在特定輸入下崩潰、工具雖然通過驗證但在實際使用中與其他工具產生衝突，以及在領域外基準上由於訓練資料不足而難以生成有效的工具。這些失敗模式凸顯了 ToolSmith 在泛化性、穩定性與工具間協調等方面仍有進一步優化的空間。

**Q15：ToolSmith 未來可以朝哪些方向發展？例如更強的驗證機制、跨領域遷移或與其他技術的結合？**
A：未來的研究方向包括：開發更強大的驗證機制，例如結合形式化方法或執行追蹤分析來確保工具的語意正確性；探索跨領域的工具遷移學習，使在一個領域生成的工具能自動適配到其他領域；將 ToolSmith 與持續學習（continual learning）結合，讓代理能隨時間累積並精煉工具庫；以及與人類專家協作的人機混合驗證流程，讓人類專家能對生成工具進行最終把關。此外，將 ToolSmith 擴展到更多模態（如音訊、影片）與更多任務類型（如具身代理、電腦使用代理）也是值得探索的方向。

## 實務應用指南

### 適用場景

1. **新聞事實查核平台**：媒體編輯部或第三方查核組織可部署 ToolSmith 來自動擴充工具庫，處理新型態的視覺謠言（如合成圖片、擷取片段、來源不明的現場照片）。當遇到「圖中事件」這類無法用既有 OCR 或視覺定位直接回答的查核任務時，系統會自動生成「Event In Image」之類的新工具，並透過雙閘門驗證後納入工具庫，跨任務重複使用。

2. **電商商品溯源與比價系統**：跨境電商平台需要驗證商品圖片是否真實、辨識品牌型號、追溯供應鏈來源。ToolSmith 可在代理反覆失敗的軌跡中（例如無法辨識特定 LOGO、無法比對限量款序號）自動生成「視覺實體搜尋」或「知識驗證」工具，減少人工維護特徵工程的成本。

3. **智慧客服與售後視覺申訴處理**：保險公司、電商退換貨部門常需處理客戶上傳的照片（車禍現場、商品瑕疵、包裹損壞）。ToolSmith 能根據新型申訴型態自動生成對應的視覺分析工具，例如「車牌辨識＋事故類型分類」、「瑕疵區域量化」，並在後續類似案件中重複呼叫。

4. **學術研究助理與文獻溯源工具**：研究生或科學記者需要從圖表、實驗照片中追溯原始資料來源。ToolSmith 可擴充工具庫以處理特殊圖表類型（如古生物化石照片、天文影像、考古文物），自動生成「影像來源比對」或「跨資料庫實體連結」工具。

5. **數位典藏與博物館互動導覽**：博物館或檔案館可讓代理在使用者提問時自動生成針對館藏特色的工具，例如辨識特定年代畫派的風格、連結藏品與歷史事件、解析古文字，無需館方逐一撰寫工具。

- 一台具備 GPU 的機器（建議 A100/H100 等級或以上），用於執行視覺語言模型（VLM）作為代理與工具生成器。

- 視需求部署多個不同規模的 VLM 主幹模型（如 Qwen3-VL-8B/32B-Instruct、GPT-5）以評估可擴展性。

**技能門檻**
- 熟悉 Python 程式設計、型別化結構描述（typed schema，例如 Pydantic 或 JSON Schema）設計。
- 具備 VLM 提示工程（prompt engineering）能力，能撰寫結構化約束（structural constraints）與反硬編碼（anti-hardcode）規範的生成提示。
- 了解代理框架（如 LangChain、AutoGen、VoltAgent）的工具註冊與呼叫機制。
- 具備基本的程式碼靜態分析與安全審查概念，以設計雙閘門驗證邏輯。

### 實作步驟建議

1. **建立精簡基礎工具庫**：先準備 8 個基本元件（文字搜尋、圖片搜尋、瀏覽網頁、放大檢視、光學字元辨識、視覺定位、程式碼執行、深度估計），每個都以型別化結構描述封裝為可呼叫的 Python 工具，並註冊到代理可存取的目錄中。

2. **執行基礎代理並收集失敗軌跡**：讓代理在目標任務集上跑一輪，完整記錄每個回合的輸入、工具呼叫、輸出與最終答案。標註失敗案例的錯誤類型（幻覺、工具誤用、無法解析的證據格式等）。

3. **Trajectory Mining（軌跡探勘）**：將失敗軌跡聚類為「能力缺口」（capability gaps），例如「無法辨識圖中事件」、「無法驗證跨頁面數字一致性」。每個缺口對應一個或多個失敗模式。

4. **Reuse-or-Grow Decision（重用或擴充決策）**：對每個能力缺口，檢查是否能以既有 8 個基本元件組合解決。若可，標記為「重用」；若否，標記為「需生成新工具」，進入下一階段。

5. **Tool Generation（工具生成）**：以生成器 VLM 為每個「需生成」缺口撰寫新的 Python 工具原始碼。提示中需明確要求結構化輸入／輸出、結構性與反硬編碼約束（例如不得將特定答案寫死、必須具備泛化能力）。

6. **Two-Gate Verification（雙閘門驗證）**：
   - **第一閘（沙箱健全性）**：在隔離環境中執行候選工具，跑過一組測試案例，確認無例外拋出、輸入輸出符合型別。
   - **第二閘（LLM 靜態程式碼審查）**：讓另一個 VLM 檢視原始碼，檢查是否有硬編碼、資安漏洞、與缺口不相符的邏輯。
   - 通過雙閘的工具才正式納入擴充工具庫。

7. **部署擴充後的代理並評估**：以 VLM-as-a-Judge 協議在領域內與領域外基準上評估，比較基礎工具庫與擴充工具庫的表現。記錄新工具的使用率、呼叫分佈與失敗模式。

8. **迭代與監控**：將新一輪的失敗軌跡再次餵入 Trajectory Mining，持續擴充工具庫。建議設置工具版本控管與自動回滋機制，避免低品質工具污染目錄。

### 潛在風險與注意事項

- **硬編碼與缺乏泛化**：生成器 VLM 可能產出將特定答案或案例寫死的「假工具」，看似通過測試但無法處理新輸入。**緩解**：在提示中明確列出反硬編碼規範，並在第二閘讓審查 VLM 專門檢查常數與分支條件。

- **沙箱逃逸與資安風險**：自動生成的程式碼可能執行任意檔案存取、網路請求或系統呼叫。**緩解**：務必在受限 Docker 環境中執行，禁用 `os.system`、`subprocess`、網路外連等高風險 API，並設置資源使用上限。

- **工具膨脹與目錄污染**：隨著迭代，工具庫可能累積大量低使用率或功能重疊的工具，增加代理決策負擔。**緩解**：定期執行工具呼叫分佈分析，淘汰長期未被呼叫或與其他工具功能高度重疊的項目。

- **評估偏差（VLM-as-a-Judge 偏差）**：以 VLM 評審可能對特定模型家族有偏好評分。**緩解**：交叉使用不同家族的 VLM 評審，或在關鍵任務上以人類標註覆核。

- **領域外效能衰退**：在領域內基準上表現良好的工具，可能在領域外任務上產生負遷移。**緩解**：保留領域外基準的持續監控，若發現效能下滑，啟用工具篩選或回退機制。

- **生成成本與延遲**：每次迭代都需呼叫生成器 VLM 與審查 VLM，成本與時間不容忽視。**緩解**：採用批次生成、增量更新策略，並對高頻失敗模式優先處理。

### 與其他技術的整合建議

- **代理框架整合**：ToolSmith 的擴充工具庫可直接接入 LangChain、AutoGen、VoltAgent 等主流代理框架，工具以標準化的型別化結構描述註冊即可，無需修改代理核心推理迴圈。

- **RAG 系統整合**：將 ToolSmith 生成的「知識驗證」或「視覺實體搜尋」工具與既有 RAG 檢索管線串接，作為後置驗證步驟，提升回應可信度。

- **MCP（Model Context Protocol）相容**：若目標部署環境支援 MCP，建議將自動生成的工具封裝為 MCP 伺服器端點，方便跨平台、跨代理共用。

- **持續學習與記憶機制**：可將 ToolSmith 與代理記憶系統（如經驗回放、案例庫）結合，把成功使用新工具的軌跡存入記憶，強化未來類似任務的決策。

- **監控與可觀測性**：整合 OpenTelemetry、LangSmith 等可觀測平台，追蹤每個工具的呼叫頻率、延遲、錯誤率，便於後續工具庫治理。

- **人類審核工作流**：在雙閘門驗證之外，可加入「人類審核」第三閘，特別針對高風險領域（醫療、法律、金融）部署時，由領域專家覆核通過的工具。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的圖 1 範例，理解「固定工具庫」與「擴充工具庫」的差異；接著跳過技術細節，專注於「為何需要自動生成工具」的動機與四階段流程的直覺說明，再回頭看相關術語（軌跡、能力缺口、沙箱驗證）。實作上可先從複製官方程式碼、跑通最小範例開始。

**給 AI 工程師**：重點研讀第 1 節貢獻列表與四階段管線的具體實作（Trajectory Mining 的聚類方法、Reuse-or-Grow 的決策邏輯、Tool Generation 的提示工程、Two-Gate Verification 的閘門設計）。建議直接以官方程式碼為基礎，將其整合進現有代理框架，並設計工具版本控管與監控儀表板。

**給研究者**：第 2 節相關工作提供了完整的多模態搜尋代理與工具生成文獻地圖，建議從中找出 ToolSmith 與既有方法（如 CRAFT、Toolformer、Chameleon）的差異點。實驗章節的消融研究（不同生成模型、訓練樣本、過濾機制）是延伸研究的最佳切入點，可考慮探索更嚴格的驗證閘門、跨語言工具生成、或理論化的能力缺口分析。

**給產品經理**：聚焦於「適用場景」與「潛在風險」兩節，理解 ToolSmith 能解決的具體業務痛點（工具維護成本、新查詢類型適應速度）以及部署時需考量的成本（VLM 呼叫、沙箱基礎設施）與治理議題（工具品質、領域外效能）。建議以試點專案形式，先在一個高價值、低風險的場景（如內部查核工具）驗證，再逐步擴展至對外服務。
