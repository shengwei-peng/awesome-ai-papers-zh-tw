## 摘要翻譯

儘管自主資料科學智能體（autonomous data science agents）在資料理解與決策方面具備強大能力，它們仍高度依賴涉及高成本計算（expensive computation）的試誤法工作流程（trial-and-error workflows）。此一瓶頸催生了能夠在真實執行（real-world execution）前預測資料科學操作（data science operations）影響的模型。本文提出資料科學世界模型（Data Science World Model）的概念，其根據當前工作流程狀態（current workflow states）與候選操作（candidate operations），預測環境狀態轉移（environment state transitions），從而對資料科學執行環境（data science execution environment）進行建模。我們進一步提出 DSWorld，一個結合結構化狀態建構（structured state construction）、成本感知路由（cost-aware routing）、輕量級真實執行（lightweight real execution），以及針對高成本操作、基於大型語言模型模擬器（LLM-based simulator）的實用框架。為支援訓練，我們建構了一個 8K 規模轉移軌跡資料集（8K-scale transition trajectory dataset），並提出反思式世界模型最佳化（Reflective World Model Optimization），一種用於改進轉移預測（transition prediction）的錯誤感知強化學習（error-aware reinforcement learning）策略。實驗顯示，DSWorld 在維持具競爭力表現的同時，將基於強化學習的智能體訓練（RL-based agent training）加速約 14 倍，並將基於搜尋的推論（search-based inference）加速約 3 至 6 倍；且在轉移預測任務（transition prediction tasks）上，相較於最強大型語言模型基線（strongest LLM baseline）提升 35.6%。程式碼可於 https://anonymous.4open.science/r/DSWorld 取得。

### 核心貢獻（3～5點）
- 提出資料科學世界模型（Data Science World Model）概念，透過預測環境狀態轉移（environment state transitions）來建模資料科學執行環境（data science execution environment）。
- 設計 DSWorld 框架，整合結構化狀態建構（structured state construction）、成本感知路由（cost-aware routing）、輕量級真實執行（lightweight real execution）與基於大型語言模型模擬器（LLM-based simulator）。
- 建構 8K 規模轉移軌跡資料集（8K-scale transition trajectory dataset），並提出反思式世界模型最佳化（Reflective World Model Optimization）以改進轉移預測（transition prediction）。
- 實驗驗證 DSWorld 可將基於強化學習的智能體訓練（RL-based agent training）加速約 14 倍、基於搜尋的推論（search-based inference）加速 3–6 倍，並在轉移預測任務上超越最強大型語言模型基線（strongest LLM baseline）35.6%。

### 適合對象
適合對資料科學自動化、自主智能體（autonomous agents）、世界模型（world models）及強化學習（reinforcement learning）感興趣的研究人員與工程師，特別是關注如何降低資料科學工作流程中高昂計算成本、加速模型開發與推論效率的讀者。

## 深度分析

#### 方法論解析

DSWorld 的核心貢獻在於將「世界模型（World Model）」的概念從物理世界與數位世界延伸至資料科學執行環境（data science execution environment），提出 Data Science World Model（資料科學世界模型）。其目標是：給定當前工作流程狀態（current workflow state）與候選操作（candidate operation），預測下一個環境狀態（next environment state），使自主資料科學智能體（autonomous data science agents）能在執行高成本計算（expensive computation）前先評估後果。

在形式化定義上，DSWorld 將狀態 \(S_t\) 拆解為任務描述、資料集（datasets）、模型狀態（model states）、執行歷史（execution history）、中間輸出與環境狀態（environment status）等結構化欄位；動作 \(A_t\) 則對應特徵工程（feature engineering）、模型訓練（model training）、評估（evaluation）等資料科學操作（data science operations）。世界模型即學習條件轉移機率 \(P(S_{t+1} \mid S_t, A_t)\)，並輸出資料集與模型變化（dataset and model changes）、執行回饋（execution feedback）、錯誤（errors）與效能訊號（performance signals）。

DSWorld 框架包含四個關鍵模組：

1. **State Constructor（狀態建構器）**：將原始資料科學環境（raw data science environments）轉換為結構化狀態表示（structured state representations）。這一步至關重要，因為 LLM（Large Language Model，大型語言模型）直接處理原始程式碼、資料表與日誌時容易遺漏關鍵語義，結構化狀態能顯著降低預測難度。

2. **Router（成本感知路由器）**：實現 cost-aware routing（成本感知路由）。針對每個 agent action（智能體動作），Router 判斷其是否屬於高成本計算。輕量級操作（lightweight actions）直接交由 Compiler（編譯執行器）進行真實執行，以確保準確性；昂貴操作則導向 Simulator（模擬器）。

3. **Compiler（編譯執行器）**：負責 lightweight real execution（輕量級真實執行），例如語法檢查、小規模資料轉換等。這保留了關鍵細節，避免模擬器在簡單操作上累積誤差。

4. **Simulator（基於 LLM 的模擬器）**：針對模型訓練、交叉驗證、大規模資料處理等昂貴操作，直接預測 next environment state（下一個環境狀態）而無需真實執行。這是達成推論加速（inference acceleration）與訓練加速的核心。

在訓練流程上，DSWorld 採用兩階段策略：

- **Supervised Fine-Tuning（SFT，監督式微調）**：使用 DSWorld-8K 資料集進行初始化。該資料集包含 8,000 條高品質轉移軌跡（transition trajectories），來源包括真實自主資料科學任務軌跡，以及透過 LLM 與 MMTU 大規模資料來源合成的 Chain-of-Thought（CoT，思維鏈）軌跡。合成動作會在真實環境中執行並驗證，僅保留驗證通過的樣本，並進一步生成解釋轉移邏輯的 CoT。

- **Reflective World Model Optimization（反思式世界模型最佳化）**：這是一種 error-aware reinforcement learning（錯誤感知強化學習）策略。模型在預測後比對參考狀態，根據預測誤差計算 reward（獎勵）與 advantage（優勢），並透過 error-aware reflection（錯誤感知反思）與 iterative refinement（迭代細化）來改進 next-state prediction（下一狀態預測）。這使模型不僅模仿正確轉移，還能主動修正高風險錯誤模式。

整體而言，DSWorld 的設計哲學是「準確性與效率的權衡」：簡單操作真實執行以保證正確，昂貴操作由 LLM-based simulator 預測以節省時間，並透過結構化狀態與反思式 RL 提升預測品質。

#### 實驗數據解讀

論文在兩個實際下游場景中評估 DSWorld：

1. **作為自主資料科學智能體訓練的轉移模型（transition model for RL-based agent training）**  
2. **作為智能體推論階段的轉移模型（transition model for search-based inference）**

主要實驗結果如下：

- **RL training speedup（強化學習訓練加速）約 14×**：在與 ML-Master、AIDE、AutoMLGen 等基線比較時，DSWorld 能將 agent training（智能體訓練）的 wall-clock time 大幅縮短。這與論文觀察一致：現有系統如 ML-Master 在 MLE-Bench 上超過 86% 的執行時間（execution time）耗費在模型訓練。透過以 Simulator 替代真實訓練，DSWorld 消除了主要計算瓶頸。

- **Inference acceleration（推論加速）約 3–6×**：在 search-based inference（基於搜尋的推論）中，智能體需要探索大量候選解（candidate solutions）。DSWorld 讓智能體在「想像」不同操作後果後再選擇執行，從而減少實際 trial-and-error workflows（試誤法工作流程）次數。

- **維持競爭性效能（competitive performance）**：加速並未以犧牲 agent performance（智能體效能）為代價，顯示 Simulator 的預測品質足以支撐下游任務。

- **轉移預測任務（transition prediction tasks）上超越最強 LLM baseline（大型語言模型基線）35.6%**：這驗證了結構化狀態建構（structured state construction）與 Reflective World Model Optimization 的有效性。相較於直接使用通用 LLM 進行端到端預測，DSWorld 透過明確的狀態分解、真實執行驗證資料與錯誤感知強化學習，顯著提升 transition prediction（轉移預測）準確率。

這些數據的意義在於：資料科學智能體的瓶頸往往不是「推理（agent reasoning）」本身，而是「分析計算（analytical computation）」。DSWorld 將計算開銷（computational overhead）從訓練與推論迴路中抽離，使 test-time scaling strategies（測試時縮放策略）在實際應用中更具可擴展性（scalability）。

#### 與現有研究的比較

**定位**  
現有 world models（世界模型）主要聚焦兩大領域：物理世界（physical world），如影片生成、3D 場景與潛在動力學建模；以及數位世界（digital world），如網頁與 GUI 智能體的狀態轉移模擬。DSWorld 首次系統性地將世界模型應用於資料科學工作流程（data science workflows），其狀態空間由結構化資料、程式碼、模型與執行日誌組成，而非像素或網頁 DOM。

**相較於自主資料科學智能體的改進**  
ML-Master2、AIDE、AutoMLGen 等現有方法主要依賴 test-time scaling 與 iterative trial-and-error workflows，透過大量真實執行來篩選解決方案。DSWorld 不取代這些智能體，而是作為其底層的 transition prediction model（轉移預測模型），使其能夠：

- 在執行前預測資料科學操作（data science operations）的影響；
- 透過 cost-aware routing 在準確性與效率間動態取捨；
- 利用 DSWorld-8K 與 Reflective World Model Optimization 提升預測品質。

**主要優勢**

1. **結構化狀態表示（structured state representations）**：降低 LLM 處理原始環境的負擔。
2. **成本感知路由（cost-aware routing）**：避免「所有操作都模擬」或「所有操作都執行」的極端。
3. **可擴展資料合成管線（scalable data synthesis pipeline）**：結合真實軌跡與 LLM 合成，解決資料稀缺的問題。
4. **錯誤感知強化學習（error-aware reinforcement learning）**：透過反思機制持續修正預測錯誤。

**限制**

1. **LLM-based simulator 的幻覺風險**：雖然結構化狀態與 RL 優化可減少錯誤，但對於複雜程式碼執行結果，Simulator 仍可能產生看似合理卻不正確的預測。
2. **長期誤差累積（compounding errors）**：多步 rollouts 中，單步預測誤差可能隨時間放大，論文對此的量化分析有限。
3. **路由閾值的領域依賴**：cost-aware routing 的輕重劃分標準可能需要針對不同任務調整。
4. **資料覆蓋範圍**：DSWorld-8K 主要基於 MMTU 與 MLE-Bench 相關來源，對於極小眾或高度客製化的資料科學任務，泛化能力仍需驗證。
5. **與真實執行的語義差距**：某些效能訊號（performance signals）如交叉驗證分數，可能受隨機種子、硬體與程式碼版本影響，Simulator 難以完全重現。

#### 可重現性評估

論文指出原始碼已公開於 `https://anonymous.4open.science/r/DSWorld`，並說明建構了 DSWorld-8K 資料集。從可重現性（reproducibility）角度評估：

- **正向因素**：
  - 提供匿名開源程式碼倉庫，便於檢視實作細節。
  - 明確描述訓練資料規模（8K-scale transition trajectory dataset）與合成流程。
  - 框架模組（State Constructor、Router、Compiler、Simulator）介面清晰，理論上可複製。

- **挑戰與不確定性**：
  - 論文未明確說明是否釋出模型權重（model weights）。若僅釋出程式碼而無預訓練權重，重現完整實驗仍需大量計算資源。
  - DSWorld-8K 的資料合成依賴先進 LLM 與大規模 MMTU 資料來源，若這些資料或 API 存取受限，將影響資料集重建。
  - 真實執行驗證（real execution verification）需要穩定的資料科學執行環境，包括特定套件版本、GPU 資源與 MLE-Bench 任務設定，重現門檻不低。
  - 匿名連結暗示論文可能仍處於審查階段，最終釋出內容可能與目前連結不同。

整體而言，DSWorld 在方法描述與程式碼公開方面具備良好基礎，但完整重現仍受計算成本、資料可取得性與模型權重釋出狀況所限制。

#### 未來研究方向

1. **長期一致性與誤差累積控制**  
   未來可發展多步 rollout consistency（多步推展一致性）機制，例如引入 rollout-level reward 或蒙特卡羅樹搜尋（MCTS），降低長期 compounding errors。

2. **不確定性量化與自適應路由**  
   讓 Simulator 輸出預測不確定性（uncertainty estimation），並據此動態調整 Router 決策：不確定性高時轉交真實執行，不確定性低時使用模擬。

3. **混合神經—符號模擬器**  
   結合 LLM 的語義理解與符號執行（symbolic execution）或程式碼直譯器，對資料轉換與模型訓練進行更精確的模擬，減少幻覺。

4. **擴展至更廣泛的資料科學環境**  
   目前聚焦 MLE-Bench 與 MMTU 類型的預測建模任務。未來可涵蓋 SQL 分析、大規模分散式資料處理、AutoML 管線調度與即時推論系統。

5. **線上學習與持續適應**  
   讓 DSWorld 在真實 agent rollouts 中持續收集新轉移樣本，透過 online learning 更新 Simulator，減少對靜態 DSWorld-8K 的依賴。

6. **因果與可解釋轉移建模**  
   除了預測 next state，可進一步學習操作—效果之間的因果關係，並生成可解釋的 transition explanation，輔助智能體除錯與決策。

7. **與規劃與強化學習的更深整合**  
   將 DSWorld 作為環境模型嵌入 model-based RL（基於模型的強化學習）與 hierarchical planning（階層式規劃），進一步提升 sample efficiency（樣本效率）。

8. **安全與可靠性機制**  
   在真實部署前加入 sanity check（健全性檢查）與 rollback（回滾）機制，防止 Simulator 錯誤預測導致智能體採取破壞性操作。

9. **開放模型權重與標準化評測**  
   釋出預訓練權重並建立資料科學世界模型專用 benchmark，將有助於社群進行公平比較與後續研究。

## 論文問答

**Q1：DSWorld 旨在解決自主資料科學智能體在執行資料科學任務時面臨的什麼核心問題？**  
A：現有的自主資料科學智能體大多依賴迭代式試誤工作流程，在探索大量候選解決方案時必須反覆執行資料處理、模型訓練與評估等高成本計算，導致絕大部分執行時間都耗費在計算而非智能體推理上。這種沉重的計算開銷嚴重限制了系統的效率與可擴展性，使得在大型資料科學任務上進行廣泛搜尋或強化學習訓練變得昂貴且緩慢。DSWorld 透過建立資料科學世界模型，讓智能體在執行前就能預測資料科學操作所造成的環境狀態轉移，從而減少不必要的真實世界執行。

**Q2：為什麼現有的測試時縮放策略難以滿足高效率自主資料科學的需求？**  
A：現有方法通常採用測試時縮放策略，透過反覆試誤來探索眾多候選解決方案，但每一次迭代都可能涉及完整的資料處理、模型訓練、評估與工作流程更新。以 ML-Master 為例，它在 MLE-Bench 上超過 86% 的執行時間都花在模型訓練，顯示計算成本已成為主要瓶頸。由於這些策略將大量資源投入在實際執行而非策略推理，因此難以在維持效能的同時顯著提升訓練與推論速度。

**Q3：能夠預測資料科學操作效應的轉移預測模型為何重要？**  
A：轉移預測模型使智能體能夠在執行高成本計算之前，先預測資料集與模型變化、執行回饋、錯誤訊息與效能訊號等下一個環境狀態。這種能力讓智能體可以像視覺世界模型想像物理世界未來狀態一樣，在資料科學執行環境中進行規劃與評估，避免每次嘗試都付出真實計算代價。因此，它不僅能加速基於強化學習的智能體訓練與基於搜尋的推論，也為自主資料科學系統的規模化應用奠定基礎。

**Q4：DSWorld 框架的核心組成與運作流程為何？**  
A：DSWorld 首先利用狀態建構器將原始資料科學環境轉換為結構化狀態表示，內容包含任務資訊、資料集、執行歷史、輸出與環境狀態。接著，成本感知路由機制會判斷智能體動作是否屬於高成本計算：輕量級操作由 Compiler 直接真實執行以確保準確性，而昂貴操作則交由基於大型語言模型的模擬器預測下一個環境狀態。這種混合式設計兼顧預測正確性與執行效率，使 DSWorld 能夠在不實際執行高成本步驟的情況下推進工作流程。

**Q5：DSWorld 相較於純粹使用大型語言模型或純粹真實執行的方法，其關鍵創新為何？**  
A：DSWorld 的關鍵創新在於提出成本感知路由與輕量級真實執行、基於大型語言模型的模擬器之間的協同機制，而非單純仰賴 LLM 推論或全部真實執行。對於計算成本低的操作，直接執行可確保狀態轉移的精確度；對於模型訓練等昂貴操作，則以 LLM 模擬器進行快速預測，從而避免成為瓶頸。這種針對資料科學操作特性設計的混合模擬策略，是將世界模型概念成功應用於資料科學執行環境的重要突破。

**Q6：Reflective World Model Optimization 在 DSWorld 中扮演什麼角色？**  
A：Reflective World Model Optimization 是一種反思式世界模型最佳化策略，透過錯誤感知強化學習來改進轉移預測。它會讓模型在預測錯誤後進行反思，並以迭代精煉的方式調整下一個環境狀態的預測結果，使模擬器逐漸學會糾正自身的失誤。這種訓練方式特別適合資料科學環境中狀態轉移複雜、錯誤訊息豐富的特性，有助於提升長期預測的穩定性與準確度。

**Q7：DSWorld 使用了哪些資料集與實驗設定來驗證其有效性？**  
A：為了訓練資料科學世界模型，作者建構了 DSWorld-8K，這是一個包含約八千條高品質轉移軌跡的資料集，結合了真實世界自主資料科學任務的軌跡與由大型語言模型合成的 Chain-of-Thought 軌跡。此外，他們還開發可擴展的資料合成管線，利用先進 LLM 與 MMTU 的大規模資料來源產生多樣化的工作流程狀態與資料科學操作，並在真實環境中執行與驗證後才保留樣本。實驗方面，DSWorld 被評估為兩種下游設定：作為訓練自主資料科學智能體的轉移模型，以及作為智能體推論時的轉移模型，同時也在多項轉移預測任務上進行測試。

**Q8：DSWorld 在實驗中取得了哪些關鍵效能結果？**  
A：在加速方面，DSWorld 實現了約 14 倍的強化學習訓練加速，以及約 3 至 6 倍的推論加速，同時仍能保持具競爭力的下游智能體效能。在轉移預測任務上，DSWorld 的平均表現比最強的大型語言模型基線高出 35.6%，顯示其對資料科學操作效應的預測能力顯著優於單純使用 LLM 的方法。這些結果說明 DSWorld 能夠在大幅減少計算開銷的同時，維持甚至提升預測與決策品質。

**Q9：DSWorld 的設計中，哪些元件對效能與效率的權衡最為關鍵？**  
A：成本感知路由機制是決定何時真實執行、何時進行模擬的核心，它確保輕量級操作不會因模擬誤差而累積錯誤，同時讓昂貴操作避開實際計算。基於大型語言模型的模擬器則負責學習並預測高成本資料科學操作的狀態轉移，是達成加速的關鍵。反思式世界模型最佳化進一步透過錯誤感知強化學習與迭代精煉提升模擬器準確度，三者相輔相成，使 DSWorld 在速度與正確性之間取得良好平衡。

**Q10：DSWorld 可應用於哪些實際的資料科學場景？**  
A：DSWorld 可應用於類似 Kaggle 競賽任務的自動機器學習平台、企業內部的預測建模流程，以及需要反覆探索特徵工程與模型組合的資料科學管線。在這些場景中，智能體可以利用世界模型快速試驗多種候選操作，而無需每次都實際訓練模型或處理大規模資料。這不僅能縮短實驗週期，也能降低雲端計算成本，使資料科學團隊能夠更專注於高層次的問題分析與決策。

**Q11：若將 DSWorld 產品化，需要考慮哪些工程與安全議題？**  
A：產品化時必須確保狀態建構器能夠穩定解析多樣化的原始資料科學環境，並與不同程式語言、函式庫及執行環境無縫整合。同時，基於大型語言模型的模擬器可能產生幻覺或錯誤的狀態轉移，因此需要建立驗證機制與人類可理解的解釋，讓使用者在關鍵決策點能夠檢查模擬結果。此外，成本感知路由的閾值、模擬逼真度與真實執行之間的權衡，也需要根據實際應用場景持續調校與監控。

**Q12：DSWorld 對自主資料科學智能體領域可能帶來什麼長遠影響？**  
A：DSWorld 將世界模型的研究從物理世界與網頁／圖形介面等數位世界，拓展到資料科學執行環境這類高度分析性的領域，填補了既有研究的空白。它展示了透過預測環境狀態轉移來減少試誤計算的可行性，可能促使未來的智能體從單純的試誤式搜尋轉向模型導向的規劃與推理。長遠來看，這種典範轉移有助於建構更高效、可擴展且能在有限計算資源下處理複雜資料科學任務的自主系統。

**Q13：DSWorld 目前可能存在哪些限制或挑戰？**  
A：儘管 DSWorld 在轉移預測與加速方面表現出色，其基於大型語言模型的模擬器對於訓練資料中較少出現的操作或極端資料分佈，可能產生較大的預測誤差。此外，長期模擬過程中的錯誤可能會逐步累積，影響多步決策的可靠性。雖然 DSWorld-8K 已具備一定規模，但資料覆蓋範圍仍可能無法窮盡所有真實世界的資料科學工作流程與環境配置。

**Q14：在哪些情況下 DSWorld 的模擬器可能會失效或表現不佳？**  
A：當資料科學操作具有高度隨機性，例如受隨機種子、硬體差異或分散式訓練影響的模型訓練結果時，模擬器可能難以準確預測下一個環境狀態。若狀態表示遺漏了影響轉移的關鍵細節，例如特定資料欄位的細微分佈或外部依賴版本，模擬結果也會偏離真實執行。此外，在長期規劃中，單步預測的小誤差會隨著步數增加而放大，最終導致模擬軌跡與實際工作流程顯著分歧。

**Q15：未來研究可以從哪些方向進一步提升資料科學世界模型？**  
A：未來可以擴大並多樣化轉移軌跡資料集，涵蓋更多領域、資料規模與操作類型，以提升模擬器的泛化能力。同時，引入不確定性量化與線上適應機制，能讓模型在面對新環境時主動偵測預測風險並即時修正。此外，將資料科學世界模型與多智能體協作、人機互動回饋或持續學習結合，也有助於建構更穩健且能處理真實世界複雜性的自主資料科學系統。

## 實務應用指南

### 適用場景

1. **Kaggle / 資料科學競賽自動化沙盒**  
   在參與 Kaggle 競賽或企業內部建模比賽時，可用 DSWorld 作為「虛擬執行環境」，讓智能體在不上傳真實算力的前提下，快速試驗特徵工程、模型選擇與超參數調整的組合，顯著降低試誤成本。

2. **MLOps / AutoML 平台的事前影響評估**  
   在 AutoML 或 MLOps 管線中，DSWorld 可預測「下一個資料科學操作」對資料集、模型指標與執行日誌的影響，幫助平台在觸發昂貴的模型訓練或分散式運算前，先篩選掉低潛力路徑。

3. **資料科學教育與互動式教材**  
   將 DSWorld 嵌入教學系統，學生輸入一段資料處理或建模程式碼後，系統可即時模擬執行結果、錯誤訊號與效能變化，無需等待真實訓練完成，適合大規模線上課程與程式碼輔導工具。

4. **企業內部資料分析助理的推理加速**  
   針對業務分析師常用的探索式資料分析（EDA）、報表生成與預測建模流程，DSWorld 可作為推論階段的「世界模型引擎」，讓 LLM 驅動的分析智能體在數秒內預覽多條工作流，再決定真正執行哪一條。

5. **強化學習資料科學智能體的訓練基礎設施**  
   若以 RL 訓練自主資料科學智能體，DSWorld 可取代大量真實環境互動，將原本需數千小時的模型訓練與評估壓縮為模擬轉移，加速策略學習與獎勵塑形。

### 實作前置條件

**資料前置條件**
- 需具備真實或合成的資料科學工作流軌跡，包含：任務描述、當前資料集狀態、候選操作（程式碼或高階動作）、執行後的下一狀態、執行回饋與效能訊號。
- 若缺乏真實軌跡，需準備可執行的資料科學環境（Python、常見 ML 套件）與 LLM API，以產生並驗證合成轉移樣本。
- 建議預先建立結構化狀態表示的 Schema，例如：任務、資料集摘要、模型配置、執行日誌、任務進度等欄位。

**運算前置條件**
- 至少需一張可執行 LLM 微調的中高階 GPU（如 A100 / H100 或同等級），用於訓練狀態轉移模型與 Reflective World Model Optimization。
- 需配備可執行真實資料科學操作的運算節點，用於產生與驗證訓練資料；若採用成本感知路由，輕量級操作可在 CPU 或小型容器執行。
- 推論階段若僅使用 LLM-based Simulator，則主要成本來自 LLM API 呼叫，需評估 token 消耗與延遲預算。

**技能前置條件**
- 熟悉 Python 資料科學生態（pandas、scikit-learn、PyTorch 等）與 LLM 微調流程（SFT、RL）。
- 具備強化學習基礎，能理解獎勵設計、優勢估計與錯誤感知反思機制。
- 需有能力設計狀態建構器與路由規則，區分「輕量級真實執行」與「高成本模擬」的邊界。

### 實作步驟建議

1. **定義狀態與動作空間**  
   參考 DSWorld 的 State Constructor，將原始資料科學環境轉換為結構化狀態表示；同時定義動作空間，例如特徵工程、模型訓練、評估、超參數調整等高階操作。

2. **收集與合成轉移資料**  
   先從真實任務收集高品質轉移軌跡，再透過 LLM 與可執行環境擴充合成資料，並驗證每筆樣本的下一狀態是否正確，建立類似 DSWorld-8K 的訓練集。

3. **訓練基礎轉移模型（SFT）**  
   使用監督式微調初始化世界模型，讓模型學會根據當前狀態與候選操作預測下一環境狀態、執行回饋與效能訊號。

4. **引入 Reflective World Model Optimization**  
   在 SFT 基礎上，透過錯誤感知強化學習進行迭代精煉：讓模型對預測錯誤進行反思，並根據獎勵與優勢估計更新策略，提升轉移預測準確度。

5. **部署成本感知路由**  
   上線 Router，依據動作成本決定直接執行（Compiler）或交由 LLM-based Simulator 預測；輕量級操作優先真實執行以確保準確，昂貴操作優先模擬以提升效率。

6. **整合至智能體訓練與推論管線**  
   在 RL-based 智能體訓練中以 DSWorld 取代部分真實環境互動；在推論階段用於搜尋與規劃，先模擬多條路徑再執行最佳方案。

7. **持續監控與迭代**  
   建立轉移預測誤差監控機制，定期將真實執行結果回饋至訓練資料，並重新微調模型，避免模擬漂移。

### 潛在風險與注意事項

- **模擬誤差累積（Compounding Error）**  
  世界模型在多步預測後誤差可能放大，導致智能體在錯誤狀態上繼續決策。建議採用短程滾動模擬，並定期以真實執行校正狀態。

- **高成本操作與輕量級操作的邊界不清**  
  若路由規則設計不當，可能將昂貴操作誤判為輕量級而真實執行，或將簡單操作過度模擬而降低準確度。應根據實際執行時間與資源消耗動態調整閾值。

- **訓練資料分布偏移**  
  合成資料可能無法涵蓋真實業務場景中的邊緣案例。建議保留一定比例真實軌跡作為驗證集，並持續收集線上回饋資料。

- **LLM 模擬器的不穩定性**  
  LLM-based Simulator 可能產生幻覺或不符合語法的程式碼狀態。可透過結構化輸出、語法檢查與後驗驗證機制降低風險。

- **智慧財產與資料隱私**  
  若使用企業內部資料訓練，需注意敏感資料去識別化，並評估將資料傳送至外部 LLM API 的合規風險。

### 與其他技術的整合建議

- **與現有 AutoML / MLOps 平台整合**  
  可將 DSWorld 作為「模擬層」嵌入現有管線，在觸發模型訓練、特徵轉換或超參數搜尋前，先由世界模型預測結果，再決定是否執行。

- **與 LLM Agent 框架整合**  
  DSWorld 可作為 LLM 驅動資料科學智能體的「環境模擬工具」，讓智能體在 ReAct、Tree-of-Thoughts 或蒙特卡洛樹搜尋中進行低成本試驗。

- **與強化學習訓練框架整合**  
  將 DSWorld 包裝為 Gym / Gymnasium 環境，替代或輔助真實資料科學執行環境，加速策略梯度或 PPO 等演算法的訓練。

- **與可觀測性工具整合**  
  結合 MLflow、Weights & Biases 或自研監控系統，追蹤預測狀態與真實狀態的差異，作為再訓練與模型更新的依據。

- **與程式碼執行沙盒整合**  
  輕量級真實執行需搭配安全的程式碼執行環境（如 Docker、Kubernetes 沙盒），避免惡意或錯誤程式碼影響主系統。
