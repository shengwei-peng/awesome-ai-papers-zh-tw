## 摘要翻譯

大型推理模型（Large Reasoning Models, LRMs）透過延伸式思維鏈（Chain-of-Thought, CoT）生成，達成卓越的問題解決能力，但隨之產生的鍵值（Key-Value, KV）快取會隨序列長度（Sequence Length）線性增長，造成嚴重的記憶體瓶頸（Memory Bottleneck），在長篇推理軌跡（Reasoning Traces）中經常超出圖形處理器（GPU）的容量。現有的鍵值快取壓縮（Key-Value Cache Compression）方法仰賴近期查詢（Recent Queries）來估計未來標記重要性（Future Token Importance），隱含地假設這些查詢（Query）可作為未來注意力模式（Future Attention Patterns）的可靠代理。我們證明此假設在長程推理（Long-Horizon Reasoning）中不成立：某些解碼步驟（Decoding Steps）會生成思維回溯標記（Thought Revisiting Tokens, TRT），重新關注遙遠的先前上下文（Distant Previous Context），例如在推理軌跡早期形成的解題計畫（Task-Solving Plans）。透過系統性分析，我們發現對應於 TRT 的查詢在嵌入空間（Embedding Space）中會聚集成少數相似性群組（Similarity Groups）。根據此一洞見，我們提出 BeaconKV，一種免訓練（Training-Free）的鍵值快取壓縮方法，它維護一組信標查詢（Beacon Queries），即每個全域查詢叢集（Global Query Cluster）的精簡代表元（Compact Representatives），以預測哪些鍵值對（KV Pairs）將被重新關注，而無需儲存完整的查詢歷史。在四個開源大型推理模型（Open-Source LRMs）與多樣化的推理基準測試（Reasoning Benchmarks）中，BeaconKV 普遍優於現有的壓縮方法，記憶體減量（Memory Reduction）最高達 5.8 倍，同時幾乎保留完整快取準確率（Full Cache Accuracy），並將吞吐量（Throughput）提升超過 4.3 倍。

### 核心貢獻（3～5點）
- 揭示現有鍵值快取壓縮方法在長程推理中的根本限制：以近期查詢推估未來注意力模式的假設會失效，因為某些解碼步驟會生成重新關注遙遠上下文的思維回溯標記（TRT）。
- 發現對應於 TRT 的查詢在嵌入空間中會聚集成少數相似性群組，可作為預測未來鍵值對重訪行為的穩定訊號。
- 提出 BeaconKV，一種免訓練的鍵值快取壓縮方法，以信標查詢作為全域查詢叢集的精簡代表元，在不儲存完整查詢歷史的前提下預測將被重訪的鍵值對。
- 在四個開源大型推理模型與多樣化推理基準測試上驗證，BeaconKV 可達最高 5.8 倍記憶體減量、幾乎保留完整快取準確率，並將吞吐量提升超過 4.3 倍。

### 適合對象
本論文適合從事大型語言模型推論系統最佳化、鍵值快取壓縮、長序列推理加速，以及大型推理模型（LRM）高效率部署的研究人員與工程師閱讀。對於關注如何在不犧牲推理準確率的前提下降低 GPU 記憶體瓶頸、提升推論吞吐量的實務工作者，亦具有高度參考價值。

## 深度分析

#### 方法論解析

##### 1.1 問題設定：長程推理（Long-Horizon Reasoning）下的 KV 快取（KV Cache）瓶頸

大型推理模型（Large Reasoning Models, LRMs）透過延伸的思維鏈（Chain-of-Thought, CoT）生成來提升解題能力，但這也導致鍵值快取（Key-Value Cache, KV Cache）隨序列長度（Sequence Length）線性增長。以 Qwen3-4B 為例，當生成 32K 個標記（Token）且批次大小（Batch Size）為 16 時，KV 快取（KV Cache）單獨即可超過 77 GB，幾乎佔滿單張 80 GB GPU 的記憶體容量。因此，如何在自迴歸解碼（Autoregressive Decoding）過程中壓縮 KV 快取（KV Cache），成為部署 LRMs 的關鍵挑戰。

現有的 KV 快取壓縮（KV Cache Compression）方法大多屬於「以近期查詢（Recent Queries）為代理」的典範：它們在驅逐（Eviction）時使用最近產生的查詢（Query）來計算注意力權重（Attention Weights），並據此估計未來標記重要性（Future Token Importance）。這類方法隱含假設近期查詢（Recent Queries）能可靠地代表未來注意力模式（Future Attention Patterns）。

##### 1.2 核心觀察：思維回溯標記（Thought Revisiting Tokens, TRT）

BeaconKV 指出上述假設在長程推理（Long-Horizon Reasoning）中會失效。LRMs 在生成過程中會出現一類特殊的解碼步驟（Decoding Steps），其對應的查詢（Query）會重新關注遙遠的先前上下文（Distant Previous Context），例如早期形成的任務解決計畫（Task-Solving Plans）。這類標記被命名為思維回溯標記（Thought Revisiting Tokens, TRT）。

更具體地說，查詢（Query）可被區分為兩種幾何與語義上截然不同的型態：

- **局部查詢（Local Queries）**：主要關注鄰近的鍵（Key），反映區域性、連續的推理延續。
- **全域查詢（Global Queries）**：對應於 TRT，會關注推理軌跡（Reasoning Traces）中遠端的鍵值對（KV Pairs），用來維持全局一致性。

若僅依賴近期查詢（Recent Queries）進行驅逐，這些將在後續被 TRT 重新造訪的歷史標記會被過早移除，導致模型遺失關鍵的解題計畫，進而損害推理準確率。

##### 1.3 第二個關鍵發現：全域查詢叢集（Global Query Cluster）的結構

透過系統性分析，作者發現對應於 TRT 的全域查詢（Global Queries）在嵌入空間（Embedding Space）中並非隨機分佈，而是會聚集成少數相似性群組（Similarity Groups）。這表示：

- 雖然整體推理軌跡（Reasoning Traces）可能長達數萬個標記（Token），但會觸發遠距回溯的查詢（Query）型態其實相當有限。
- 因此，可以用一組精簡代表元（Compact Representatives）來近似這些全域查詢叢集（Global Query Clusters），而不需要儲存完整的查詢歷史。

這組精簡代表元即為**信標查詢（Beacon Queries）**。它們的作用是「預期」哪些鍵值對（KV Pairs）將來會被重新造訪，從而在壓縮時保留這些高風險標記。

##### 1.4 Continual Farthest Point Sampling（FPS）：線上且記憶體有界的信標選取

為了在推論過程中高效地維護信標查詢（Beacon Queries），BeaconKV 提出 **Continual Farthest Point Sampling（FPS）**。這是一種線上（Online）演算法，具有以下特性：

- **漸進式選取**：隨著解碼步驟（Decoding Steps）推進，持續從新產生的查詢（Query）中挑選與現有信標集合幾何上最分散的樣本。
- **記憶體有界**：不需要儲存所有歷史查詢（Query），只需維護固定大小的信標集合，因此額外開銷可控。
- **幾何多樣性**：透過最大化信標查詢（Beacon Queries）之間的距離，確保能覆蓋不同的全域查詢叢集（Global Query Clusters）。

這使得 BeaconKV 成為一種**免訓練（Training-Free）**的方法：不需要對模型進行微調或額外訓練，即可在推論時動態建構信標查詢（Beacon Queries）。

##### 1.5 整體推論流程：以信標查詢（Beacon Queries）為導向的壓縮

綜合以上組件，BeaconKV 的推論流程可概括如下：

1. **查詢產生**：在每一個解碼步驟（Decoding Step）產生新的查詢（Query）。
2. **信標更新**：使用 Continual FPS 判斷是否將新查詢（Query）納入信標查詢（Beacon Queries）集合，以維持對全域查詢叢集（Global Query Clusters）的代表性。
3. **重要性評分**：同時使用**近期查詢（Recent Queries）**與**信標查詢（Beacon Queries）**對 KV 快取（KV Cache）中的所有鍵值對（KV Pairs）計算注意力權重（Attention Weights），並綜合得到每個歷史標記的重要性分數。
4. **快取驅逐**：在固定預算（Budget）下，移除重要性分數較低的鍵值對（KV Pairs），僅保留高機率被未來查詢重新關注的標記。
5. **自迴歸生成**：基於壓縮後的 KV 快取（KV Cache）繼續生成下一個標記（Token）。

透過引入信標查詢（Beacon Queries），BeaconKV 同時捕捉了「局部連續性」與「全局回溯性」兩種注意力模式（Attention Patterns），這是僅使用近期查詢（Recent Queries）的方法所無法做到的。

#### 實驗數據解讀

##### 2.1 評估設定

論文在四個開源大型推理模型（Open-Source LRMs）上進行評估：

- R1-Distill-Qwen-7B
- R1-Distill-Llama-8B
- Qwen3-4B
- Qwen3-14B

測試的推理基準測試（Reasoning Benchmarks）涵蓋數學、科學與程式設計：

- AIME24
- MATH-500
- LiveCodeBench
- GPQA-Diamond

對照方法包括現有的 KV 快取壓縮（KV Cache Compression）方法 RPC 與 R-KV，以及未壓縮的完整快取（Full Cache）作為上限基準。

##### 2.2 準確率（Accuracy）表現

實驗結果顯示，BeaconKV 在多種預算配置下通常優於 RPC 與 R-KV，相較於現有方法可帶來最高 **31.7 個百分點（percentage points）** 的準確率（Accuracy）提升。更重要的是，BeaconKV 在多數設定下「幾乎保留完整快取準確率（Full Cache Accuracy）」。

這個結果的意義在於：

- **TRT 假設得到驗證**：當壓縮方法能正確保留未來會被思維回溯標記（Thought Revisiting Tokens, TRT）重新關注的鍵值對（KV Pairs）時，模型就不會因為遺失早期計畫而犯錯。
- **近期查詢（Recent Queries）的局限性被量化**：RPC 與 R-KV 在較激進的壓縮下準確率下降，正是因為它們無法預測遠距回溯行為。

##### 2.3 記憶體減量（Memory Reduction）與吞吐量（Throughput）

BeaconKV 可達到最高 **5.8 倍** 的記憶體減量（Memory Reduction），並將吞吐量（Throughput）提升超過 **4.3 倍**。

這兩個指標之間存在緊密關聯：

- 在 LRMs 的長序列推論中，KV 快取（KV Cache）通常是 GPU 記憶體（GPU Memory）的主要消耗來源。
- 當 KV 快取（KV Cache）被壓縮後，相同的 GPU 可容納更大的批次大小（Batch Size）或更長的序列長度（Sequence Length），從而提升整體吞吐量（Throughput）。
- 5.8 倍的記憶體減量（Memory Reduction）意味著原本需要多卡或高階 GPU 的部署場景，可能可以在單張消費級 GPU 上執行。

##### 2.4 跨模型與任務的一致性

BeaconKV 在四個模型與四個基準測試（Benchmarks）上「普遍」表現最佳，這顯示該方法具有相當的泛化性：

- 對於數學與程式設計任務，長推理軌跡（Reasoning Traces）中經常出現「回頭檢查假設」或「重新評估計畫」的行為，因此 TRT 現象特別顯著，BeaconKV 的優勢也更明顯。
- 在科學問答任務（如 GPQA-Diamond）中，雖然推理長度可能較短，但全局一致性同樣重要，BeaconKV 仍能保持競爭力。

不過，論文目前揭露的片段未提供各模型、各基準測試（Benchmarks）的詳細數據表格，因此無法進一步分析不同預算（Budget）下的準確率—壓縮率權衡曲線。

#### 與現有研究的比較

##### 3.1 相較於 RPC 與 R-KV

現有方法與 BeaconKV 的核心差異在於「未來注意力模式（Future Attention Patterns）」的估計方式：

| 方法 | 估計未來重要性的依據 | 主要限制 |
|---|---|---|
| RPC | 使用近期查詢（Recent Queries）計算注意力權重（Attention Weights） | 無法預測遠距回溯 |
| R-KV | 在 RPC 基礎上加入基於鍵（Key）相似度的冗餘分數 | 仍依賴近期查詢（Recent Queries）作為主要代理 |
| **BeaconKV** | 近期查詢（Recent Queries）+ 信標查詢（Beacon Queries） | 需要維護信標集合，但可線上完成 |

RPC 與 R-KV 都隱含假設「未來的查詢（Query）會與近期的查詢（Query）相似」。這對於一般長上下文（Long Context）任務或許成立，但在 LRMs 的長程推理（Long-Horizon Reasoning）中，TRT 會突然轉向關注早期上下文，導致該假設失效。

BeaconKV 透過信標查詢（Beacon Queries）明確建模這種全局回溯行為，因此能在相同壓縮率下保留更多關鍵鍵值對（KV Pairs）。

##### 3.2 概念定位

BeaconKV 屬於**免訓練（Training-Free）**的 KV 快取壓縮（KV Cache Compression）方法，這使其具有以下優勢：

- **即插即用（Plug-and-Play）**：可直接應用於現有的開源大型推理模型（Open-Source LRMs），無需重新訓練或微調。
- **與其他技術互補**：可與 KV 快取量化（KV Cache Quantization）、稀疏注意力（Sparse Attention）、推測解碼（Speculative Decoding）等方法結合，進一步降低記憶體瓶頸（Memory Bottleneck）。
- **專注於 LRMs 的特性**：不同於一般針對長文件理解的快取壓縮方法，BeaconKV 特別針對 CoT 生成中「計畫—執行—回溯」的動態注意力模式（Attention Patterns）進行設計。

##### 3.3 限制與風險

儘管 BeaconKV 概念上具有吸引力，仍存在一些潛在限制：

- **信標集合大小的超參數（Hyperparameter）**：信標查詢（Beacon Queries）的數量需要在代表性與記憶體開銷之間權衡。若數量過少，可能遺漏某些罕見但關鍵的全域查詢叢集（Global Query Clusters）。
- **Continual FPS 的開銷**：雖然論文強調其記憶體有界，但線上計算查詢（Query）之間距離並更新信標集合仍會帶來額外計算成本，對延遲敏感（Latency-Sensitive）的應用可能需進一步優化。
- **叢集假設的適用範圍**：全域查詢（Global Queries）聚集成少數相似性群組（Similarity Groups）的現象是在四個模型上觀察到的，但若模型架構或推理風格顯著不同（例如極長的多輪對話、非 CoT 模型），該假設是否仍然成立仍需驗證。
- **驅逐決策的延遲性**：信標查詢（Beacon Queries）是基於已觀察到的查詢（Query）分佈來預測未來，對於首次出現的新型回溯模式可能反應較慢。

##### 4.1 開源資源

根據目前提供的論文片段，可確認以下資源為公開可用：

然而，**原始碼（Source Code）與實作細節**在目前片段中並未明確提及是否公開釋出。若作者未提供官方實作，則其他研究者需要根據論文描述自行實現 Continual FPS、重要性評分函數與驅逐策略，這會增加重現難度。

##### 4.2 實作細節透明度

要完整重現 BeaconKV，至少需要以下資訊：

1. **信標查詢（Beacon Queries）的維護細節**：Continual FPS 的距離度量（例如餘弦相似度、歐氏距離）、更新頻率、最大集合大小。
2. **重要性評分函數**：如何結合近期查詢（Recent Queries）與信標查詢（Beacon Queries）的注意力權重（Attention Weights），是否加權、是否跨層（Layer-Wise）或跨頭（Head-Wise）處理。
3. **驅逐策略**：當 KV 快取（KV Cache）超過預算（Budget）時，是一次性驅逐最低分標記，還是採用漸進式閾值（Thresholding）。
4. **超參數（Hyperparameters）**：不同模型與序列長度（Sequence Length）下的預算設定、信標數量、近期查詢（Recent Queries）窗口大小。

目前片段對這些細節著墨有限，因此可重現性評估為**中等**：概念清晰且資源公開，但具體實作仍需更多細節或官方程式碼才能確保一致。

#### 未來研究方向

##### 5.1 與量化（Quantization）與稀疏化（Sparsity）的結合

BeaconKV 從「選擇保留哪些鍵值對（KV Pairs）」的角度進行壓縮，未來可與以下技術結合：

- **KV 快取量化（KV Cache Quantization）**：對保留的鍵值對（KV Pairs）進行低精度量化，進一步降低記憶體使用量。
- **結構化稀疏性（Structured Sparsity）**：根據信標查詢（Beacon Queries）的重要性分數，設計硬體友好的稀疏模式。
- **分層預算（Layer-Wise Budgeting）**：不同 Transformer 層（Layer）可能具有不同的注意力模式（Attention Patterns），可為每層動態分配壓縮預算。

##### 5.2 自適應信標查詢（Adaptive Beacon Queries）

目前信標查詢（Beacon Queries）的數量可能是固定或預設的。未來可研究：

- **動態叢集數量（Dynamic Cluster Number）**：根據當前推理軌跡（Reasoning Traces）的複雜度自動調整全域查詢叢集（Global Query Clusters）數量。
- **語義感知信標（Semantic-Aware Beacons）**：除了幾何多樣性，也可考慮將推理階段（如「計畫」、「驗證」、「結論」）納入信標選取準則。
- **可學習的信標（Learnable Beacons）**：雖然 BeaconKV 強調免訓練（Training-Free），但對特定領域進行輕量微調以學習更緊湊的信標查詢（Beacon Queries）可能進一步提升壓縮率。

##### 5.3 擴展至多模態與多輪推理

BeaconKV 目前針對文字型 CoT 推理設計。未來可探索：

- **多模態推理（Multimodal Reasoning）**：在視覺—語言推理模型中，圖像特徵也可能被遠距回溯，信標查詢（Beacon Queries）的概念可擴展至多模態嵌入空間（Embedding Space）。
- **多輪對話（Multi-Turn Dialogue）**：將信標查詢（Beacon Queries）應用於跨輪次的 KV 快取（KV Cache）管理，避免重複保留無關歷史。

##### 5.4 理論分析與硬體協同設計

- **注意力模式（Attention Patterns）的理論建模**：建立數學模型來描述 TRT 出現的機率與分佈，從而設計更穩健的壓縮演算法。
- **硬體感知驅逐（Hardware-Aware Eviction）**：將信標查詢（Beacon Queries）的更新與驅逐決策與 GPU 記憶體排程、頁式 KV 快取（Paged KV Cache）等系統技術整合，降低實際部署延遲。

##### 5.5 與推測解碼（Speculative Decoding）的整合

推測解碼（Speculative Decoding）可透過並行驗證草稿標記來加速生成。未來可研究如何在草稿模型與目標模型之間共享信標查詢（Beacon Queries），使得兩者在壓縮後的 KV 快取（KV Cache）上保持一致，進一步提升 LRMs 的端到端吞吐量（Throughput）。

## 論文問答

**Q1：BeaconKV 主要想解決什麼問題？**
A：BeaconKV 旨在解決大型推理模型（LRM）在進行長程 Chain-of-Thought 生成時，鍵值快取（KV cache）隨序列長度線性增長所造成的嚴重記憶體瓶頸。由於 LRM 會產生數萬個 token 的推理軌跡，KV cache 很容易超過單張 GPU 的記憶體容量，例如 Qwen3-4B 在批次大小為 16 且生成 32K token 時，KV cache 就可能超過 77GB。這個問題限制了 LRM 在資源受限環境中的實際部署，因此 BeaconKV 提出一種免訓練的壓縮方法，在降低記憶體需求的同時盡量維持推理準確率。

**Q2：為什麼現有的 KV cache 壓縮方法在 LRM 中會失效？**
A：現有方法如 RPC 和 R-KV 主要依賴近期查詢來估計未來標記的重要性，並隱含假設近期查詢能可靠地代表未來的注意力模式。然而，在長程推理中，這個假設會失效，因為某些解碼步驟會產生思維回溯標記（TRT），這些標記會重新關注遙遠的先前上下文，例如早期形成的解題計畫。如果只根據近期查詢進行驅逐，這些後續推理所需的關鍵 KV 對會被過早移除，導致模型遺失重要資訊並降低推理品質。

**Q3：什麼是 Thought Revisiting Tokens（TRT），為什麼它們很重要？**
A：思維回溯標記（TRT）是指在長程推理過程中，某些解碼步驟產生的標記會重新關注遠距離的先前上下文，以維持整體推理的一致性與連貫性。這些標記對應的查詢被稱為全域查詢，與主要關注附近鍵值的區域查詢形成鮮明對比。TRT 的重要性在於它們會存取早期形成的關鍵資訊，若相關 KV 對被錯誤驅逐，將嚴重影響最終推理結果，因此識別並保留這些標記所需的 KV 對是壓縮方法的核心挑戰。

**Q4：BeaconKV 的核心方法是什麼？**
A：BeaconKV 的核心思想是維護一組信標查詢（beacon queries），作為全域查詢叢集的精簡代表元，以預測哪些 KV 對會在後續被重新關注。研究發現對應 TRT 的全域查詢在嵌入空間中會聚集成少數相似性群組，因此可以用少量代表元有效捕捉其分佈。透過同時保留信標查詢和近期查詢，BeaconKV 無需儲存完整查詢歷史，就能更準確地估計未來標記重要性，並指導 KV cache 的壓縮決策。

**Q5：Continual Farthest Point Sampling（FPS）在 BeaconKV 中扮演什麼角色？**
A：Continual Farthest Point Sampling 是 BeaconKV 提出的線上演算法，用於在記憶體受限的情況下逐步選擇幾何上彼此分散的查詢。該演算法能夠持續更新並維護一組具有代表性的信標查詢，同時保持有界的記憶體佔用，避免儲存所有歷史查詢。這使得 BeaconKV 在推論過程中即可動態識別全域查詢叢集，而無需額外的訓練或離線分析，非常適合實際部署場景。

**Q6：信標查詢與現有方法使用的近期查詢有何不同？**
A：現有方法使用的近期查詢主要反映當前解碼位置附近的注意力需求，適合預測局部上下文的重要性，但難以捕捉長程依賴。相對地，信標查詢是從整個推理軌跡中選出的精簡代表元，能夠捕捉會重新關注遙遠先前上下文的全域查詢模式。這種差異使 BeaconKV 能同時兼顧局部和長程注意力需求，避免因僅依賴近期查詢而過早驅除對後續推理至關重要的 KV 對。

**Q7：實驗使用了哪些模型和基準測試？**
A：實驗在四個開源大型推理模型上進行，包括 R1-Distill-Qwen-7B、R1-Distill-Llama-8B、Qwen3-4B 和 Qwen3-14B。評估涵蓋多樣化的推理基準測試，如 AIME24、MATH-500、LiveCodeBench 和 GPQA-Diamond。這些模型和資料集涵蓋數學、科學和程式碼等不同領域，能夠全面驗證 BeaconKV 在長程推理任務上的有效性與泛化能力。

**Q8：BeaconKV 的關鍵實驗結果有哪些？**
A：BeaconKV 在多種預算配置下通常優於 RPC 和 R-KV 等現有壓縮方法，準確率提升最高可達 31.7 個百分點。在記憶體方面，該方法可實現最高 5.8 倍的記憶體減量，同時幾乎保持完整快取的準確率。此外，BeaconKV 還能將吞吐量提升超過 4.3 倍，顯示其在記憶體效率與推論速度之間取得了良好的平衡。

**Q9：論文進行了哪些比較或消融實驗？**
A：論文將 BeaconKV 與現有方法（包括 RPC 和 R-KV）在不同壓縮預算下進行比較，並在多個模型和基準上評估準確率與記憶體效益。核心驗證圍繞著信標查詢能否有效代表全域查詢叢集、以及 Continual FPS 在線上維護代表元的可行性。這些比較結果顯示，BeaconKV 在激進壓縮條件下仍能保持較高的推理品質，證明其設計選擇的合理性。

**Q10：BeaconKV 最適合應用在哪些實際場景？**
A：BeaconKV 最適合部署在需要長程 Chain-of-Thought 生成的場景，例如數學解題、科學問答、程式碼生成與複雜多步驟推理任務。在這些應用中，模型會產生大量中間推理標記，導致 KV cache 迅速膨脹，而 BeaconKV 能顯著降低記憶體壓力。此外，對於在單張 GPU 上部署中大型 LRM 的線上服務，BeaconKV 也能幫助提升批次大小與處理量，使資源運用更有效率。

**Q11：在產品化部署 BeaconKV 時需要考慮哪些因素？**
A：在產品化部署時，需要考量信標查詢的儲存與更新開銷，以及與現有推論引擎和排程系統的整合難度。由於 BeaconKV 是免訓練方法，無需額外的模型微調或資料準備，這降低了導入成本與維護負擔。然而，開發者仍需根據目標硬體的記憶體容量與延遲需求，調整壓縮預算和信標查詢數量，以在準確率與效率之間取得最佳平衡。

**Q12：BeaconKV 可能對高效能 LLM 推論領域帶來什麼影響？**
A：BeaconKV 為高效能 LRM 推論提供了一個新的設計範式，即透過理解查詢在嵌入空間中的幾何結構來指導 KV cache 壓縮。這種方法挑戰了僅依賴近期查詢的傳統假設，並為未來的壓縮技術開啟了結合全域注意力模式的可能性。隨著 LRM 的推理軌跡越來越長，BeaconKV 這類能夠識別並保留關鍵長程依賴的技術將對降低部署成本、擴大應用範圍產生深遠影響。

**Q13：BeaconKV 有哪些已知的限制？**
A：BeaconKV 作為一種基於查詢叢集的啟發式方法，其效果可能受限於叢集數量和代表元選擇策略。如果全域查詢的分佈過於分散或叢集結構不明顯，信標查詢可能無法完整捕捉未來的注意力需求。此外，Continual FPS 雖然記憶體效率高，但在極長序列下仍需權衡更新頻率與代表性之間的取捨，可能影響壓縮效果的穩定性。

**Q14：BeaconKV 在什麼情況下可能會失效？**
A：BeaconKV 的潛在失效情況包括：當推理軌跡中的全域查詢模式快速變化且超出既有叢集範圍時，信標查詢可能無法及時反映新的注意力需求。另外，若某些關鍵 KV 對僅被極少數特殊查詢存取，而這些查詢未被選為信標代表元，則相關資訊可能被過早驅逐。在極端壓縮預算下，即使保留信標查詢，仍可能因可用容量不足而犧牲部分準確率。

**Q15：未來可以朝哪些方向延伸 BeaconKV 的研究？**
A：未來研究方向包括將 BeaconKV 與其他壓縮技術（如量化、稀疏化）結合，進一步提升記憶體效率與推論速度。也可以探索更動態的信標查詢更新機制，使其能根據當前任務特性自適應調整叢集數量與代表元。此外，將信標查詢的概念擴展到多模態推理模型，或與推測解碼、推論時縮放等技術整合，也是值得深入探討的方向。

## 實務應用指南

### 適用場景

1. **長思維鏈（CoT）推理 API 服務**  
   數學解題、科學問答或程式輔助等場景，模型常生成 32K 以上標記的推理軌跡。BeaconKV 可將鍵值快取記憶體壓縮數倍，讓單張 GPU 能服務更長的推理鏈或更大的批次。

2. **資源受限環境中的開源大型推理模型部署**  
   在 24GB 或 80GB VRAM 的工作站 / 邊緣伺服器上運行 DeepSeek-R1-Distill、Qwen3 等模型時，BeaconKV 能在幾乎不損失準確率的前提下，緩解長序列帶來的記憶體瓶頸。

3. **多步驟程式生成與除錯助手**  
   程式碼生成過程中，模型會先擬定解題計畫，之後在遠處再次回顧這些計畫（思維回溯標記）。BeaconKV 透過信標查詢保留這類遠距上下文，避免過早淘汰關鍵 KV 對。

4. **大規模推理基準測試與離線評估**  
   批次執行 AIME、MATH-500、LiveCodeBench 等長序列評估時，壓縮 KV 快取可提升吞吐量並降低硬體租賃成本。

5. **具備長期記憶的 Agent 工作流**  
   需要持續生成推理軌跡並偶爾回顧早期計畫或檢索文件的 Agent 系統，可利用 BeaconKV 在有限記憶體內維持全局一致性。

### 實作前置條件

- **模型與框架**：使用開源 decoder-only Transformer 大型推理模型（如 Qwen3、DeepSeek-R1-Distill、Llama），並具備可修改的推論框架（Hugging Face Transformers、vLLM、SGLang 或自訂 CUDA kernel）。
- **資料**：準備具代表性的推理提示集，用於校準壓縮比例、信標查詢數量與驗證準確率；最好涵蓋數學、程式與科學推理任務。
- **運算資源**：至少一張可運行目標模型的 GPU；需額外預留少量記憶體給信標查詢緩衝區與相似度計算。
- **技術能力**：熟悉 Python、KV cache 管理、注意力機制、模型前向傳播 hook、記憶體分析工具（如 PyTorch profiler、Nsight Systems）。
- **程式碼基礎**：需要能在注意力層截取查詢向量，並在解碼過程中動態更新信標集合與執行淘汰策略。

---

### 實作步驟建議

1. **建立完整快取基線**  
   測量不同序列長度下的 KV 快取記憶體用量、峰值記憶體與吞吐量，找出記憶體瓶頸層與目標壓縮比。

2. **決定壓縮預算與信標數量**  
   根據可用 VRAM 與期望準確率，設定每層 / 每頭保留的 KV 對數量、近期查詢窗口大小，以及信標查詢數量（通常遠少於序列長度）。

3. **截取查詢向量並維護信標集合**  
   在 Q 投影後加入 hook，收集生成過程中的查詢；使用 Continual Farthest Point Sampling 在嵌入空間中選出能代表全域查詢叢集的精簡信標查詢。

4. **實作 KV 重要性評分與淘汰**  
   對每個新解碼步驟，利用信標查詢與近期查詢計算注意力權重，為歷史 KV 對打分；淘汰低分 KV，並保留因果遮罩正確性。

5. **準確率驗證與參數調校**  
   在代表性基準上比較完整快取與 BeaconKV 的表現；若準確率下降過多，增加信標數量或放寬淘汰門檻。

6. **吞吐量最佳化**  
   將信標選取與評分邏輯融合進 attention kernel、減少 CPU-GPU 同步，並測試不同批次大小下的延遲與處理量。

7. **部署與監控**  
   上線後持續追蹤壓縮比、信標查詢命中率、推理準確率漂移，並設計 OOM 時自動降級為較保守策略的保護機制。

### 潛在風險與注意事項

- **準確率下降**：信標數量過少或任務的思維回溯標記分佈與評估資料不同時，可能遺失關鍵遠距上下文。建議針對目標任務校準參數。
- **額外計算開銷**：Continual Farthest Point Sampling 與信標評分會帶來少量 overhead，需確認其低於記憶體節省所換取的吞吐量增益。
- **與其他最佳化技術的相容性**：與 KV 量化、推測解碼、張量平行等技術併用時，可能產生數值精度或同步問題，需逐一驗證。
- **推理分佈漂移**：真實使用者的推理模式可能與基準不同，信標查詢叢集會隨之改變，應設計線上監控與動態調整機制。
- **因果遮罩正確性**：淘汰 KV 對時必須確保不會影響未來 token 的因果注意力計算，保留必要的安全窗口。
- **多 GPU 部署**：信標緩衝區在張量平行或流水線平行下需妥善同步，避免各裝置信標不一致。

### 與其他技術的整合建議

- **KV 快取量化**：將 BeaconKV 與 INT8 / FP8 KV 量化結合，可達到乘法級記憶體節省；注意在評分階段保留足夠精度。
- **Chunked Prefill 與 Prefix Caching**：在 vLLM / SGLang 等服務框架中，搭配區塊化預填充與前綴快取，減少重複計算。
- **動態批次調度**：記憶體減量後可提升最大批次大小，建議重新調整請求調度器與最大併發數。
- **自訂 Attention Backend**：將 BeaconKV 封裝為 vLLM / SGLang 的客製化 attention backend 或 plugin，便於生產環境維護。
- **推測解碼與早期退出**：若使用 draft model 或 early-exit，需額外驗證草稿 token 產生的查詢分佈是否會干擾信標叢集穩定性。
