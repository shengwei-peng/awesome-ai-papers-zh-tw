## 摘要翻譯

Robotic Learning（機器人學習）發生在 Dynamic Environments（動態環境）中，且其 Behavior Spaces（行為空間）龐大。Terminal Success Signal（最終成功訊號）僅能告知機器人任務是否完成，卻無法說明當前行為正在取得進度、停滯不前，還是抵消了先前的進度。因此，近期研究日益關注能在 Task Execution（任務執行）過程中提供回饋的 Progress Rewards（進度獎勵）。然而，現有文獻缺乏一個 Shared Framework（共享框架）；不同方法使用各異的 Observations（觀測）、Goal Specifications（目標規格）、Output Signals（輸出訊號）、Supervision Sources（監督來源）與 Evaluation Protocols（評估協議），使得我們難以比較這些方法，也難以釐清其結果究竟驗證了什麼。在本綜述中，我們針對機器人學習的 Progress Reward Modeling（進度獎勵建模）提供一個 Unified View（統一觀點）。本文以三個相互關聯的步驟來組織本領域。首先，我們研究 Progress Model（進度模型）的介面，從外部定義問題：探討模型接收哪些資訊，以及產生何種形式的進度訊號。接著，我們深入模型內部，研究建構此訊號的方法，揭示 Progress Estimation（進度估計）與 Reward Generation（獎勵生成）背後的不同假設與機制。最後，我們檢視支撐這些方法的資料與 Benchmarks（基準測試），說明 Progress Supervision（進度監督）如何取得，以及不同的評估方式實際衡量了哪些面向。這三個視角共同連結了進度模型的本質、建構方式與品質驗證。本文進一步總結現有方法的主要限制，並討論未來研究方向。

## 深度分析

#### 方法論解析

本文的核心方法論並非提出單一演算法，而是建立一套針對 Progress Reward Modeling（進度獎勵建模）的統一分類架構（unified taxonomy）。作者將紛雜的文獻拆解為三個相互銜接的視角：Interface of Progress Models（進度模型介面）、Internal Signal Construction（內部訊號建構方法）、以及 Data and Benchmarks（資料與基準測試）。這種由外而內的組織方式，讓不同方法能夠在共同的輸入–輸出結構下被比較，而不會因為術語相近卻解決不同問題而混淆。

在介面層級，作者首先檢視 Current State Representation（當前狀態表徵）。文獻中常見的輸入包括：Single Observation（單張影像或單一狀態）、Video Clip（短片段）、History-Aware Trajectory（具歷史意識的軌跡）、以及包含 Action Sequences（動作序列）的完整執行紀錄。進度估計本質上是 history-dependent（歷史相依）的，因為同一張影像在不同任務或不同前置步驟下可能代表截然不同的進度。例如，一個「把杯子放回桌面」的畫面，在「收拾桌面」任務中可能是進度完成，但在「把杯子放到櫃子」任務中卻是進度倒退。因此，是否納入過去狀態與動作，是介面設計的關鍵區分。

其次是 Goal Specifications（目標規格）。目標可以是 Visual Goal Image（視覺目標影像）、Language Instruction（語言指令）、Task Specification（任務規格描述）、或 Goal State（目標狀態）。不同目標形式決定了模型需要處理的模態：視覺相似度、語義理解、或結構化任務描述。這也直接影響後續的 Progress Estimation（進度估計）方式，例如以 CLIP（Contrastive Language-Image Pre-training）為基礎的相似度分數，適合語言目標；而以目標影像嵌入距離為基礎的方法，則適合視覺目標。

第三是 Output Interface（輸出介面）。作者區分多種輸出形式：State-wise Score（狀態層級分數，如 0–1 的完成機率或百分比）、Pairwise Comparison（成對比較，判斷兩個狀態何者進度較高）、Trajectory-Level Score（軌跡層級分數）、Dense Rewards（密集獎勵，每個時間步都提供回饋）、Sparse Rewards（稀疏獎勵，僅在特定事件觸發）、Success Detection（成功偵測，二元輸出）、以及 Textual Explanation（文字解釋）。這些輸出並非互斥，許多方法會同時輸出進度分數並將其轉換為 Reward Shaping（獎勵塑造）訊號。

在內部訊號建構層級，作者進一步剖析各方法如何將輸入映射到進度訊號。早期研究多從 Demonstrations（示範資料）與 Temporal Ordering（時間順序）學習目標鄰近表徵，例如利用對比學習讓時間上接近目標的狀態在嵌入空間中更靠近。這類方法假設「離目標越近的狀態越相似」，但對於需要繞路或暫時遠離目標的任務可能不適用。後續研究引入 Foundation Models（基礎模型），例如 CLIP、Vision-Language Models（VLM，視覺語言模型）、以及 Large Language Models（LLM，大型語言模型），透過預訓練的語義相似度或程式生成能力來產生獎勵。這類方法的優勢在於減少對任務特定資料的依賴，但挑戰在於如何將高層語義對齊到低層物理進度。

另一條路線是 Preference-Based Reward Learning（基於偏好的獎勵學習），透過人類或自動產生的偏好對（例如哪段軌跡進度較高）來訓練 Reward Function（獎勵函數）。還有 Automatic Reward Generation（自動獎勵生成），利用 LLM 直接產生可執行的獎勵程式或程式碼，例如 CodeAsReward 或 Text2Reward 這類方法。近期則出現更多 Explicit Progress Modeling（顯式進度建模），直接預測任務完成百分比、子目標完成狀態、或狀態轉移的進度變化，並結合 Temporal Memory（時間記憶）處理長期執行。

整體而言，這套方法論的價值在於把「進度模型是什麼」與「進度模型怎麼做」分開討論。介面層回答問題的定義與輸入輸出形式；內部層則揭露各種假設，例如是否假設單調遞增進度、是否依賴語義相似度、是否考慮動作歷史等。這種分層有助於識別不同方法的可比較性與適用場景。

#### 實驗數據解讀

作為一篇 Comprehensive Survey（全面綜述），本文並未提出新的實驗結果，而是對現有文獻中的 Evaluation Protocols（評估協議）與 Metrics（指標）進行系統性解讀。作者指出，目前領域內的評估方式高度異質，導致不同研究結果難以直接比較。常見的評估維度可歸納為以下幾類：

第一類是 Progress Prediction Accuracy（進度預測準確度）。這類評估通常需要 Ground-Truth Progress（真實進度）標註，例如在模擬環境中根據任務狀態機計算完成百分比，或在真實環境中由人類標註每個時間步的進度。常用指標包括 Mean Squared Error（MSE，均方誤差）、Mean Absolute Error（MAE，平均絕對誤差）、以及 Rank Correlation（排序相關性，如 Spearman’s ρ 或 Kendall’s τ）。這些指標衡量模型輸出的標量分數是否與真實進度一致，但缺點是真實進度本身難以定義，尤其在多路徑任務中，不同執行軌跡的「進度」可能沒有唯一標準。

第二類是 Temporal Ordering（時間順序）正確性。由於進度理應隨時間推進而增加，許多方法透過判斷同一軌跡中較晚狀態的進度是否高於較早狀態來評估。這類指標不需要真實進度數值，只需相對順序，因此較易取得。然而，它無法捕捉進度停滯或倒退的情況，也無法區分「緩慢前進」與「快速前進」。

第三類是 Preference Accuracy（偏好準確度）。在 Preference-Based Reward Learning 中，評估重點在於模型是否能正確預測人類或專家對兩段軌跡的偏好。這類指標與人類判斷對齊，但偏好標註成本高，且人類對「進度」的判斷可能受視覺顯著性影響，而非真正的任務進展。

第四類是 Success Detection（成功偵測）表現。許多方法雖然名為進度建模，但最終評估卻只報告最終狀態的成功與否，使用 Accuracy（準確率）、Precision-Recall（精確率–召回率）、或 F1 Score。這類評估混淆了 Progress Estimation 與 Terminal Success Signal，無法驗證模型在中間過程是否提供有意義的回饋。

第五類是 Downstream Policy Performance（下游策略表現）。這被視為最終端的評估：將進度模型作為 Dense Rewards 訓練 Reinforcement Learning（RL，強化學習）或 Imitation Learning（IL，模仿學習）策略，觀察 Sample Efficiency（樣本效率）、Final Success Rate（最終成功率）、或 Learning Curve（學習曲線）。這類評估能直接反映進度獎勵對策略學習的幫助，但缺點是結果受策略演算法、超參數、環境動態等多重因素影響，難以單獨歸因於進度模型的好壞。

第六類是 Auxiliary Task Performance（輔助任務表現），例如 Trajectory Reranking（軌跡重排）、Data Filtering（資料過濾）、Failure Detection（失敗偵測）、或 Planning（規劃）。這些評估顯示進度訊號除了作為獎勵外，還能支援其他機器人學習流程。

綜合來看，現有實驗數據的解讀必須謹慎。一個在 Temporal Ordering 上表現優異的模型，不一定能產生對 RL 有用的 Dense Rewards；一個在下游任務成功的模型，其進度訊號也可能只是間接相關。本文的貢獻之一，正是提醒讀者注意這些評估各自驗證了什麼屬性，避免將不同指標混為一談。

#### 與現有研究的比較

在本文之前，Progress Reward Modeling 領域雖然已有大量研究，但缺乏 Shared Framework（共享框架）。許多方法在名稱上都涉及「reward」或「progress」，實際上卻處理截然不同的問題。例如，VIP、R3M 等方法學習視覺表徵距離作為獎勵，本質上是 Goal Proximity（目標鄰近度）估計；CLIP-Reward、VLC 等方法利用 Foundation Models 的語義相似度產生 Language-Conditioned Rewards（語言條件獎勵）；Eureka、Text2Reward、CodeAsReward 則偏向 Automatic Reward Generation；而 Robometer、ProgressLM、RL-VLM-F 等近期工作則更強調顯式的進度百分比或成功偵測。

本文的統一觀點將這些方法重新組織到共同的介面與內部機制下，使得研究者能夠清楚區分：該方法接收的是 Single Observation 還是 Trajectory、目標是 Visual 還是 Linguistic、輸出是 Scalar Progress 還是 Binary Success、監督來源是 Demonstration、Preference、還是 LLM-Generated Label。這種分類方式比單純按年份或技術路線回顧更具結構性，也有助於發現文獻中的空白。

相較於過去較為片段的 survey 或 review，本文的改進在於：

1. **區分 Progress 與 Success**：過去許多研究將「成功偵測」與「進度估計」混用。本文明確指出 Progress 是 latent and history-dependent（潛在且歷史相依）的任務狀態，而非僅是當前觀測的屬性。
2. **強調輸入輸出介面**：透過介面分類，讀者可以快速判斷某方法是否適用於自己的設定，例如語言目標、長軌跡、或需要 Dense Rewards 的場景。
3. **揭露方法背後的假設**：例如，基於視覺嵌入距離的方法假設進度與目標視覺相似度單調相關；基於時間順序的方法假設執行過程中進度大致遞增；基於 LLM 的方法則假設語言描述能準確對應物理狀態變化。
4. **系統化評估視角**：本文指出不同 Evaluation Protocols 驗證不同性質，這對於未來設計更嚴謹的 Benchmarks 具有指導意義。

然而，本文作為一篇綜述，也存在一些侷限。首先，它並未提出新的統一 Benchmark 或標準化評估流程，讀者仍須自行在不同論文的設定間轉換。其次，由於領域發展快速，部分引用文獻標註為 2025、2026 年，可能是預印本或尚未經過同儕審查的工作，這在綜述中需要讀者特別留意其可靠性。此外，本文雖然涵蓋廣泛，但對於每個子領域的數學細節與實作差異只能點到為止，深入理解仍需回歸原始論文。

#### 可重現性評估

在可重現性方面，本文提供了一個 GitHub 資源庫：https://github.com/sterzhang/Awesome-Progress-Models，作為論文列表與相關資源的彙整。這對於研究者快速定位相關文獻、資料集與程式碼具有實質幫助。然而，作為一篇 Comprehensive Survey，本文本身並未釋出新的程式碼、模型權重或實驗腳本；其可重現性主要體現在文獻彙整的透明度與可追蹤性。

進一步評估各方法的可重現性，可以從以下幾個層面來看：

1. **Open-Source Code（開源程式碼）**：近年來許多進度獎勵相關研究，如 VIP、R3M、CLIP-Reward、Eureka、Text2Reward、VLC、RL-VLM-F 等，都已公開程式碼。但仍有部分方法僅提供論文描述，未釋出實作，這限制了直接比較與驗證。
2. **Datasets（資料集）**：進度監督的來源多樣，包括人類示範、偏好標註、模擬環境自動標註、以及 LLM 生成標籤。部分 Benchmarks（如 Meta-World、CALVIN、LIBERO、RoboSkills、Open X-Embodiment）已被廣泛使用，但進度特定的標註並非總是公開可用。
3. **Model Weights（模型權重）**：基於 Foundation Models 的方法通常依賴公開的預訓練權重，例如 CLIP、LLaVA、GPT-4V 等，這些權重可透過官方管道取得。然而，針對特定機器人任務微調後的進度模型權重，則取決於個別作者是否釋出。
4. **Evaluation Protocols（評估協議）**：由於目前缺乏統一協議，即使程式碼與資料公開，不同研究使用的訓練細節、環境版本、策略演算法、超參數可能大相逕庭，導致結果難以直接重現或比較。

整體而言，本文提升了領域的可重現性意識，但真正的可重現性改善仍有賴於未來建立標準化的 Benchmark、統一的評估腳本、以及 Progress Model Zoo（進度模型庫），讓不同方法能在相同條件下被測試與比較。

#### 未來研究方向

基於對現有文獻的統整，本文指出了若干 Limitations（侷限）並暗示了未來研究方向。以下進一步延伸與討論：

1. **統一基準與標準化評估**：目前最迫切的需要是建立專門針對 Progress Reward Modeling 的 Benchmark，涵蓋不同目標形式（視覺、語言、結構化）、不同軌跡長度、以及多種進度變化模式（前進、停滯、倒退、繞路）。評估指標應同時包含 Progress Prediction Accuracy、Temporal Consistency（時間一致性）、Downstream RL Performance、以及 Robustness to Distribution Shift（對分佈偏移的穩健性）。

2. **歷史感知與時間一致性**：現有許多方法僅使用 Single Observation，難以處理進度被撤銷或暫時遠離目標的情況。未來應發展更強大的 History-Aware Progress Models，結合 Temporal Memory 與因果推理，確保進度估計在長期執行中保持一致。

3. **多模態目標對齊**：隨著 VLM 與 LLM 的發展，未來進度模型需要同時處理 Visual Goal、Language Instruction、以及 Task Specification，並學習將高層語義對齊到低層物理狀態變化。這需要更好的 Multimodal Representation Learning（多模態表徵學習）與 Grounding Mechanisms（接地機制）。

4. **因果進度與獎勵駭入防禦**：許多基於相似度的獎勵容易受到 Reward Hacking（獎勵駭入）影響，例如機器人可能找到讓視覺相似度提高但實際未完成的捷徑。未來需要發展 Causal Progress Modeling（因果進度建模），辨識真正導致任務完成的狀態轉移，而非僅依賴表面相似度。

5. **線上適應與校準**：進度模型在部署時可能面臨新任務、新環境或新物體。未來研究可探索 Online Adaptation（線上適應）與 Calibration（校準）技術，讓模型能根據少量互動回饋調整進度估計，並提供不確定性估計。

6. **結合大型語言模型的推理能力**：LLM 與 VLM 不僅能產生獎勵程式，也能進行顯式推理，例如判斷「目前處於哪個子階段」、「下一步應該完成什麼」。未來可發展 Progress Reasoning Models，將進度估計與 High-Level Planning（高層規劃）、Failure Recovery（失敗恢復）結合。

7. **真實世界評估與資料效率**：目前大多數方法仍在模擬環境中驗證。未來需要更多 Real-World Benchmarks，並發展能從少量人類示範或偏好中學習的 Sample-Efficient Progress Models，以降低資料收集成本。

8. **進度訊號的多工應用**：除了作為 Dense Rewards，進度訊號還可用於 Data Filtering、Curriculum Learning（課程學習）、Trajectory Reranking、以及 Human-Robot Interaction（人機互動）。未來可系統性研究如何設計通用進度模型，使其能同時支援多種下游任務。

總結來說，Progress Reward Modeling 正從早期的視覺距離估計，逐步演進為結合 Foundation Models、顯式時間推理、與多模態目標理解的綜合性研究領域。本文所提供的 Unified View 為這一轉變奠定了分類與對話的基礎，但未來仍需在標準化評估、因果推理、真實世界驗證與多工應用等方向上持續努力。

## 論文問答

**Q1：進度獎勵建模試圖解決機器人學習中的什麼核心問題？**
A：在動態且高維度的環境中，機器人僅靠最終成功訊號難以理解中間執行過程的優劣。終端訊號只能告知任務是否完成，卻無法說明當前行為是推進、停滯還是倒退。進度獎勵建模旨在提供密集的過程回饋，使機器人在任務執行期間就能獲得有意義的學習訊號。

**Q2：為什麼傳統的終端成功訊號在長期任務中特別不足？**
A：長期任務的成功結果稀少且延遲，機器人在獲得任何回饋前必須做出大量決策。稀疏的終端訊號無法區分有效行為與無關動作，也難以辨識已完成的子目標是否被後續動作撤銷。這會導致信用分配困難，並顯著降低強化學習與模仿學習的樣本效率。

**Q3：相較於成功偵測，進度估計為何更為困難？**
A：成功偵測通常只需對最終狀態做二元判斷，而進度估計必須將當前觀測放入整個任務執行脈絡中。模型需要推斷哪些子目標已完成、目前處於哪個階段，以及距離目標還有多遠。此外，進度具有任務條件性與歷史依賴性，同一畫面在不同任務或不同先前動作下可能代表完全不同的進度。

**Q4：本文提出的統一觀點包含哪三個相互連結的步驟？**
A：第一步是進度模型的介面，從外部定義模型接收什麼資訊以及輸出何種進度訊號。第二步深入模型內部，探討建構進度訊號的方法與其背後的假設與機制。第三步則檢視資料與基準測試，說明進度監督如何取得以及不同評估究竟在衡量什麼。

**Q5：進度模型介面的關鍵維度有哪些？**
A：關鍵維度包括當前狀態表徵、目標規格與輸出介面。狀態表徵可以是單張影像、影片片段、歷史軌跡或成對軌跡；目標規格可以是目標影像、語言指令、獎勵程式或示範軌跡；輸出則可能是純量分數、成對比較、密集獎勵、成功機率或文字解釋。透過這些維度，不同架構的方法可以在共同的輸入輸出結構下進行比較。

**Q6：目前建構進度訊號的主要方法家族有哪些？**
A：早期方法多從示範、時間順序與視覺目標結構學習目標鄰近表徵；後續研究利用基礎模型的相似度分數與語言條件獎勵。近年則發展出基於偏好的獎勵學習、利用大型語言模型自動生成獎勵，以及使用大型視覺語言模型結合顯式時間記憶來估計任務進度。每個家族對監督來源與進度語義的假設各不相同。

**Q7：文獻中常用哪些基準測試與資料集來評估進度模型？**
A：常見的模擬環境包括 MetaWorld、RLBench、CALVIN 與 LIBERO 等機器人操作基準，也有真實機器人收集的資料集。評估指標涵蓋時間順序正確率、純量進度預測誤差、偏好分類準確率、成功偵測表現，以及下游策略的最終任務成功率。這些多樣的評估協議反映了進度建模問題本身的多面性。

**Q8：關於監督來源，文獻中有哪些主要實證發現？**
A：使用密集人工標註或示範軌跡的方法通常能產生較可靠的進度訊號，但收集成本高昂。自監督的時間順序學習與基礎模型先驗雖然更具規模性，卻可能與特定任務的進度定義不一致。基於偏好的學習能降低標註負擔，但需要謹慎設計採樣策略；而視覺語言模型方法雖具潛力，仍容易出現幻覺與粒度過粗的問題。

**Q9：文獻中的消融或比較分析揭示了哪些設計權衡？**
A：比較顯示，單張影像模型計算效率高但無法捕捉歷史脈絡，影片模型能建模時間資訊但推論成本較高。語言目標有助於跨任務泛化，卻需要穩健的視覺 grounding；成對比較較易收集但難以給出絕對進度值。整體而言，將進度訊號用於獎勵塑造通常能顯著加速學習，優於僅使用稀疏終端獎勵。

**Q10：除了策略學習，進度訊號還能支援哪些實際應用？**
A：進度訊號可用於線上監控任務執行狀況，及時發現停滯或倒退。它也能協助軌跡重排、資料過濾、規劃與動作選擇，並在失敗發生前觸發恢復機制。因此，可靠的進度模型不僅是獎勵函數，更是一種通用的機器人行為評估器。

**Q11：在產品化或實際部署時，進度獎勵模型需要考慮哪些因素？**
A：即時推論延遲是關鍵，因為機器人控制需要高頻回饋。模型還必須具備對領域偏移的穩健性、對人類進度觀念的校準能力，以及可解釋的獎勵輸出。此外，與現有強化學習或模仿學習管線的整合，以及低成本適應新任務的能力，都是部署成功的重要條件。

**Q12：進度獎勵建模可能對整個機器人學習領域帶來什麼影響？**
A：它有助於銜接低階控制與高階任務理解，為長期任務提供密集回饋。透過減少對手工設計獎勵與人工成功偵測器的依賴，它能提升資料效率並促進可規模化的獎勵工程。同時，它也為基於基礎模型的機器人系統提供了評估與引導行為的統一機制。

**Q13：目前進度獎勵建模方法有哪些主要限制？**
A：文獻中的問題定義與評估協議過於分散，導致方法間難以公平比較。許多方法假設任務目標固定，難以處理多階段、可逆或目標動態變化的任務。此外，現有進度訊號常缺乏可解釋性與校準性，且基於基礎模型的方法容易帶入偏見，真實世界評估也相對不足。

**Q14：文獻中強調了哪些典型的失敗案例？**
A：模型可能將看似接近目標的無關動作誤判為高進度，也可能把可逆動作的前後往返視為持續進步。當目標僅部分滿足或語義模糊時，模型容易給出錯誤訊號；在視覺領域偏移或未曾見過的任務描述下，表現也會顯著下降。這些錯誤訊號若直接用於策略學習，可能誤導機器人收斂到錯誤行為。

**Q15：未來研究可以朝哪些方向發展？**
A：未來需要建立統一的基準測試與評估指標，讓不同方法能在相同標準下比較。研究者也可探索從弱監督或自然監督中學習進度，並結合世界模型進行反事實的進度評估。此外，發展可解釋且經過校準的進度模型、將因果任務結構與時間推理結合，並擴展到多任務與終身學習場景，都是值得深入的方向。

## 實務應用指南

### 適用場景

**長期家庭服務任務**
掃地、整理桌面、準備簡易餐點等任務通常包含數十到數百個步驟，最終成功訊號稀疏且延遲。進度獎勵建模可在每個中間執行步驟提供回饋，例如判斷「杯子是否已靠近咖啡機」「桌面雜物是否減少」，讓機器人更快學會正確的行為序列。

**工業裝配與品質檢測**
在產線上，機器人需要依序完成取件、對位、鎖附、檢查等子任務。進度模型可以監控任務執行過程，偵測停滯或倒退，並在異常發生時即時觸發警報或啟動失敗恢復流程，降低整線停機風險。

**倉儲物流與揀貨作業**
揀貨機器人需在貨架間移動、辨識目標商品、抓取並放置到正確容器。進度估計能協助判斷「是否已找到正確貨架」「抓取姿態是否正確」，並支援軌跡重新排序與資料過濾，提升整體揀貨效率。

**醫療復健輔助機器人**
復健動作需要持續追蹤患者完成度，例如「手臂是否已舉起到目標角度」「動作是否回到起始位置」。進度獎勵可提供密集回饋，協助調整輔助力道與運動節奏，同時記錄長期復健趨勢。

**自動駕駛與移動機器人導航**
在長距離導航或複雜路口場景中，僅靠抵達終點的成功訊號難以學習細緻駕駛行為。進度模型可估計「是否正沿規劃路徑前進」「是否偏離車道」，作為獎勵塑造或線上監控的依據。

### 實作前置條件

**資料準備**
需要收集與任務相關的觀測資料，例如 RGB-D 影像、機器人關節狀態、夾爪狀態、末端執行器位置等。同時需要目標規格，可以是目標影像、自然語言指令、目標狀態編碼，或示範軌跡。若採用偏好學習，還需準備成對軌跡的偏好比較標註；若採用大型視覺語言模型，則需要相應的提示設計與少樣本範例。

**運算資源**
進度模型訓練通常需要 GPU 進行視覺表徵學習或視覺語言模型推論。若使用強化學習進行策略訓練，建議具備多核心 CPU 叢集或雲端運算資源以平行執行模擬環境。真實機器人部署則需邊緣運算裝置支援即時推論。

**技術與領域知識**
團隊需熟悉強化學習、電腦視覺、自然語言處理，以及機器人模擬器如 MuJoCo、Isaac Gym 或 Habitat。此外，對任務領域的理解至關重要，例如裝配順序、物品物理特性、安全規範等，這會直接影響進度監督的設計與獎勵生成方式。

### 實作步驟建議

**步驟一：定義進度模型介面**
首先明確模型接收哪些觀測、目標如何規格化、輸出訊號是純量分數、成功機率、成對比較結果，還是可執行的獎勵程式。這個介面決定了後續監督來源與評估協議的選擇。

**步驟二：選擇監督來源**
根據可取得的資料決定監督方式。若有大量專家示範，可採用示範軌跡學習；若有人類偏好回饋，可使用偏好獎勵學習；若任務已有語言說明，可結合大型語言模型自動生成獎勵函數；若資料有限，可考慮無監督或自監督的時間順序學習。

**步驟三：建立進度估計原型**
從簡單的狀態表徵或目標距離估計開始，逐步加入歷史資訊與任務條件。初期可使用預訓練的視覺表徵或視覺語言模型作為基礎，再針對特定任務進行微調。

**步驟四：在模擬環境中驗證**
先在模擬器中評估進度模型的預測準確度、時間順序正確性、偏好預測能力，以及對下游策略學習的幫助。此階段應測試獎勵駭入、目標歧義、停滯偵測等邊界案例。

**步驟五：部署到真實系統並持續監控**
將模型部署到真實機器人後，持續收集執行資料並監控進度訊號的穩定性。建立回饋迴路，讓操作人員能標註異常案例並重新訓練模型，以縮小模擬與真實環境之間的差距。

### 潛在風險與注意事項

**獎勵駭入**
模型可能找到捷徑來最大化進度分數，但實際上並未完成任務。緩解方式包括加入多樣化評估指標、使用成對軌跡比較、結合人類回饋，以及定期檢視高獎勵但低成功率的案例。

**目標規格歧義**
自然語言指令或目標影像可能有多種解釋，導致進度估計不一致。建議在設計目標規格時盡量具體，並透過多組標註者驗證目標理解的一致性，必要時結合結構化狀態描述。

**模擬到真實的差距**
在模擬器中表現良好的進度模型，可能因視覺外觀、物理動力學或感測器雜訊而在真實環境失效。可透過領域隨機化、模擬到真實遷移學習、以及持續的真實資料微調來降低風險。

**計算與延遲成本**
大型視覺語言模型雖然理解能力強，但推論延遲高，可能不適合需要毫秒級反應的任務。可考慮模型蒸餾、輕量化架構，或將複雜推理離線執行，線上僅使用輕量進度估計器。

**安全與倫理**
在醫療、工業或與人互動的場景中，錯誤的進度訊號可能導致危險行為。應設置獨立的安全監控層，並確保進度模型不會覆蓋關鍵的安全限制。

### 與其他技術的整合建議

**與大型視覺語言模型結合**
可將大型視覺語言模型作為進度理解與獎勵生成的後端，負責高階語言推理與目標解析，再將其輸出蒸餾成輕量的進度估計模型，用於即時策略學習。

**與現有強化學習框架整合**
進度獎勵可作為外部獎勵塑造模組，與 PPO、SAC 或模仿學習等方法搭配。建議將進度訊號與原始任務獎勵分開記錄，方便分析其對策略收斂與樣本效率的影響。

**與模擬器與數位孿生整合**
在模擬環境中自動產生大規模進度監督資料，並透過數位孿生驗證模型在真實場景中的表現。可將進度模型嵌入模擬器的獎勵函數介面，加速策略迭代。

**與資料管線整合**
將進度訊號用於資料過濾與軌跡重新排序，協助挑選高品質示範資料或移除停滯、倒退的無效片段。這能提升後續模仿學習與離線強化學習的資料品質。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先從本文的介面觀點開始理解，把進度模型想像成一個「黑盒子」：它接收現在看到的畫面或狀態、知道任務目標是什麼，然後輸出一個分數表示「做得怎麼樣」。不必急著深入每種演算法，重點是理解為什麼最終成功訊號不夠用，以及進度回饋如何幫助機器人學得更快、更穩定。

**給 AI 工程師**
本文最實用的部分在於將各種方法統整成共同的輸入輸出結構，方便你在選型時快速比較。建議特別關注監督來源與評估協議這兩個面向，因為它們直接影響資料管線設計與上線後的監控指標。實作時可先選定一個具體任務，定義清楚觀測與目標規格，再決定要套用哪一類進度估計方法。

**給研究人員**
本文指出的文獻碎片化問題是重要的研究機會。建議深入閱讀進度估計與獎勵生成的方法論章節，思考不同假設之間的關係，例如單張影像與影片輸入、純量分數與成對比較、示範監督與語言監督之間的取捨。未來可朝統一基準測試、可解釋的進度表示，以及跨任務泛化能力等方向探索。

**給產品經理**
這份綜述能幫助你判斷進度獎勵建模是否適合你的應用場景，以及導入時需要哪些資源與風險控管。建議聚焦在適用場景、實作前置條件與潛在風險這幾節，並與工程團隊討論資料取得難度、運算成本與真實部署的驗證計畫，避免將模擬環境中的指標直接當作產品成效。
