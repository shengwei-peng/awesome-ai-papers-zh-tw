## 摘要翻譯

模型–外殼共同演化已成為遞迴自我改進 (RSI) 代理的一個日益受到重視的典範，共同演化其執行支架與內在能力。我們研究此典範中一個持續存在卻常被忽視的腦–體不匹配問題：演化中的外殼（體）要求其模型（腦）尚未學會的行為，或限制其已具備的能力。我們提出 CoEvo-RSI，一個透過代理驅動的雙向歷史繼承來推進模型–外殼共同演化的 RSI 框架。基於共享的演化典藏庫與執行回饋，元代理從歷史設計中協調外殼開發，並進行模型檢查點選擇或合併，接著在選定外殼下進行後續適應，使繼承的能力與演化的執行需求對齊，以減少腦–體不匹配。僅使用監督式微調 (SFT) 對自身的拒絕取樣軌跡進行訓練，CoEvo-RSI 便使 Qwen3.5-9B 在多樣的垂直領域應用中與更大模型相當，包括多代理失敗歸因、角色感知文字轉 SQL，以及智慧家庭指令遵循。它在 TraceElephant 上超越 DeepSeek-V4-Pro（代理準確率 +14.16），並在 HomeBench VM 上超越 GLM-5.3（成功率 +4.90），彰顯了腦–體對齊的必要性，以及雙向歷史繼承在推進代理共同演化上的潛力。

### 核心貢獻（3～5點）
- **問題識別**：系統性地指出模型–外殼共同演化典範中持續存在卻常被忽視的「腦–體不匹配」問題，揭示演化中的外殼（體）可能要求模型（腦）尚未學會的行為，或限制其已具備的能力。
- **框架提出**：提出 CoEvo-RSI 框架，透過代理驅動的雙向歷史繼承機制，結合共享的演化典藏庫與執行回饋，由元代理協調外殼開發、模型檢查點選擇或合併，以及後續適應過程。
- **方法簡潔性**：僅使用監督式微調 (SFT) 對自身拒絕取樣軌跡進行訓練，無需複雜的強化學習或大規模人類標註，即能有效推進遞迴自我改進。
- **實證成果**：使 Qwen3.5-9B 在多個垂直領域應用中與更大模型競爭，包括多代理失敗歸因、角色感知文字轉 SQL、智慧家庭指令遵循等，並在 TraceElephant 上超越 DeepSeek-V4-Pro（代理準確率 +14.16）、在 HomeBench VM 上超越 GLM-5.3（成功率 +4.90）。
- **概念啟示**：彰顯腦–體對齊的必要性，並展示雙向歷史繼承在推進代理共同演化上的潛力，為 RSI 研究開闢新方向。

### 適合對象
- 研究遞迴自我改進 (RSI)、AI 代理自我演化或模型–外殼共同演化的學者與工程師
- 從事大型語言模型微調、模型合併、檢查點選擇等技術研發的實務工作者

## 深度分析

#### 方法論解析

**問題形式化：腦–體不匹配的精確定義**

本文最核心的理論貢獻在於將「腦–體不匹配」（Brain–Body Mismatch）從一個直觀現象提升為可形式化的優化問題。在模型–外殼共同演化（Model–Harness Co-evolution）的框架下，每一代代理由一對 $(H_t, \theta_t)$ 構成，其中 $H_t$ 代表外殼（harness，即「體」，定義工具介面、動作空間、記憶與執行流程），$\theta_t$ 代表模型（即「腦」，負責推理與動作選擇）。不匹配的發生有兩種典型情境：(1) **介面不匹配**（Interface Mismatch），例如模型輸出 XML 格式的工具呼叫，但演化後的外殼僅接受 JSON，導致語意正確的呼叫被拒絕；(2) **能力不匹配**（Capability Mismatch），外殼引入了新的操作（如主動式上下文管理工具），但當前模型缺乏相關訓練經驗，或反過來，外殼限制了模型已具備的能力。這種形式化使得後續的診斷指標與演算法設計有了明確的優化目標。

**雙向歷史繼承的演算法架構**

CoEvo-RSI 的方法論核心是「雙向歷史繼承」（Bidirectional Historical Inheritance），透過一個共享的演化典藏庫（Evolutionary Archive）$\mathcal{A}_{<t}$ 來記錄所有歷史上的外殼設計、模型檢查點、開發歷程與執行結果。每輪演化包含以下階段：

1. **回饋收集與策展（Curator）**：從當前 $(H_t, \theta_t)$ 對的執行回饋 $F_t$ 中萃取證據，並由策展模組組織成結構化資訊。
2. **外殼編輯（Harness Editors）**：瀏覽典藏庫，自主選擇歷史起點設計，產生子代外殼。這一步保留了設計多樣性與結構經驗的累積。
3. **模型繼承（Model Inheritance）**：對每個子代外殼，從歷史檢查點中選擇或合併（merging）出候選模型，形成候選 $(H, \theta)$ 配對。
4. **評估與驗證**：透過推演（rollout）與驗證分數，篩選有潛力的配對進行模型適應（model adaptation），最終決定晉升到下一輪的配對。

此設計的關鍵洞見在於：外殼演化從歷史結構經驗中汲取養分，而模型初始化則從適合新外殼的能力中選擇起點，兩者透過典藏庫協調，使「腦–體對齊」（Brain–Body Alignment）成為演化過程的組織原則。

**診斷指標：回合級介面不匹配率（TIMR）**

為了提供可觀察、低成本的回饋訊號，本文提出回合級介面不匹配率（Turn-level Interface Mismatch Rate, TIMR），用於量化介面契約（Interface Contract）的違反程度。TIMR 作為一種「廉價診斷訊號」，使得在演化過程中能即時偵測介面層級的失調，而無需仰賴昂貴的端到端評估。

**訓練策略的精簡性**

值得注意的是，CoEvo-RSI 僅使用監督式微調（SFT）於自身拒絕取樣軌跡（rejection-sampled trajectories）上，便能使 Qwen3.5-9B 與更大模型競爭。這顯示出方法論的價值不僅在於演算法本身，更在於其對訓練流程的精簡化——無需複雜的強化學習或大規模人類標註，僅靠自我生成的優質軌跡即可達成顯著改進。

#### 實驗數據解讀

**跨垂直領域的全面驗證**

實驗在三個差異極大的垂直領域上進行評估，每個領域考驗代理的不同能力面向：

| 領域 | 基準 | 對比模型 | 關鍵指標 | 提升幅度 |
|------|------|----------|----------|----------|
| 多代理失敗歸因 | TraceElephant | DeepSeek-V4-Pro | 代理準確率 | +14.16 |
| 智慧家庭指令遵循 | HomeBench VM | GLM-5.3 | 成功率 | +4.90 |
| 多代理失敗歸因 | Who&When Pro | Qwen3.8-Max | 代理準確率 | +4.40 |

**結果的深層意涵**

1. **以小搏大的能力**：Qwen3.5-9B 在共同演化後能超越參數量更大的 DeepSeek-V4-Pro 與 GLM-5.3，這暗示了「腦–體對齊」所帶來的系統性增益，可能比單純擴大模型規模更具效率。在 TraceElephant 上 +14.16 代理準確率的提升尤為顯著，顯示在多代理除錯場景中，外殼與模型的協調比模型本身的絕對能力更為關鍵。

2. **TIMR 與步驟準確率的權衡**：圖 2 顯示 CoEvo-RSI 在十個演化版本中達到 37.50% 步驟準確率（Step Accuracy）與 0% TIMR，而僅最新版本（Latest-Only）基線僅達 36.96% 步驟準確率且 TIMR 為 0.118%。+13.05 個百分點的差距（從圖中標註）凸顯了歷史繼承機制在維持介面一致性上的顯著效果。

3. **領域多樣性的驗證**：三個基準涵蓋結構化輸出（Text-to-SQL）、多代理協調（Failure Attribution）與裝置控制（Smart-Home），證明 CoEvo-RSI 並非針對特定領域過擬合，而是具有跨領域的泛化能力。

**實驗設計的嚴謹度**

從摘要與引言可知，實驗採用了三輪共同演化（three-round run），每輪評估十個版本，這提供了統計上的穩健性。同時，與「僅最新版本」基線的比較，直接隔離了「歷史繼承」這一變因的貢獻，使因果歸因更為清晰。

#### 與現有研究的比較

**在自我演化代理文獻中的定位**

本文將現有研究劃分為三條主線：(1) 遞迴外殼改進（Recursive Harness Improvement），如 ReAct、Reflexion、Voyager 等早期系統，以及後續的 AutoHarness、Meta-Harness；(2) 遞迴模型改進（Recursive Model Improvement），透過自我蒸餾（self-distillation）將生成經驗轉化為策略更新；(3) 模型–外殼共同演化，如 Darwin Gödel Machine 等。CoEvo-RSI 的獨特之處在於：**它不僅演化兩者，更強調兩者之間的歷史對應關係**。

**相較於 Darwin Gödel Machine 的改進**

Darwin Gödel Machine 雖然也維護一個自我修改代理的典藏庫，允許早期分支成為後續改進的墊腳石，但其焦點在於代理程式碼本身的演化。CoEvo-RSI 則將此思想擴展到「模型–外殼」雙重空間，並引入雙向繼承機制，使模型選擇能對應到特定的外殼需求，這是更細粒度的協調。

**相較於僅演化外殼或僅演化模型的方法**

僅演化外殼的方法（如 Meta-Harness）受限於固定模型的既有行為模式；僅演化模型的方法則受限於固定外殼的能力邊界。CoEvo-RSI 透過雙向繼承打破了這種單向限制，允許「外殼設計從歷史結構經驗中學習，模型初始化從適合新外殼的能力中選擇」，這在概念上是更全面的。

**限制與未解決問題**

1. **計算成本未明確量化**：典藏庫的維護、檢查點合併、外殼編輯的搜尋空間都會帶來顯著的計算開銷，但本文未提供詳細的成本分析。
2. **TIMR 的侷限性**：作為介面不匹配的代理指標，TIMR 無法捕捉語意層級的失調，例如模型「理解」了外殼意圖但執行方式不當的情況。
3. **對基礎模型的依賴**：方法的有效性可能受限於初始模型的內在能力上限；若起點模型過於薄弱，歷史繼承也無法創造新能力。
4. **領域遷移的驗證不足**：雖然在三個垂直領域上驗證，但這些領域的共同特徵（如結構化輸出、工具呼叫）可能限制了結論的普適性。

#### 未來研究方向

**1. 腦–體不匹配的理論深化**

當前形式化主要聚焦於介面契約的違反，未來可進一步探討：(1) 語意層級的失調，例如模型「理解」外殼意圖但執行方式不當；(2) 長期演化中的「能力漂移」現象，即模型在多輪適應後逐漸偏離原始能力分布；(3) 不匹配的可預測性研究，是否能從早期回饋預測後續失調。

**2. 診斷指標的擴展**

TIMR 目前僅捕捉介面層級的失調，未來可發展：(1) 語意不匹配率（Semantic Mismatch Rate），衡量模型意圖與外殼期望的語意距離；(2) 能力利用率（Capability Utilization），量化外殼是否充分調用了模型的內在能力；(3) 演化穩定性指標，衡量跨代配對的相容性變化。

**3. 演算法層面的改進**

(1) **自動化典藏庫管理**：當前典藏庫的增長可能導致搜尋空間爆炸，未來可研究基於重要性或冗餘度的剪枝策略；(2) **更精細的繼承機制**：除了選擇與合併，可探索基於注意力或路由的動態繼承；(3) **多目標優化**：在腦–體對齊之外，同時考慮效率、安全性、可解釋性等多重目標。

**4. 跨領域與跨模態的擴展**

本文驗證的三個領域均以文字與結構化輸出為主，未來可探索：(1) 視覺–語言代理的共同演化；(2) 機器人控制中的腦–體對齊；(3) 多語言代理的演化，其中外殼的語言契約與模型的語言能力需特別協調。

**5. 與人類回饋的結合**

當前方法僅依賴執行回饋，未來可研究如何將人類偏好或領域專家知識融入演化過程，使腦–體對齊不僅是技術性的，更能對齊人類價值觀。

**6. 安全與對齊的考量**

隨著代理能力的增強，共同演化可能引入新的安全風險：(1) 外殼演化可能繞過原有的安全約束；(2) 模型適應可能產生獎勵 hacking；(3) 典藏庫可能保留有害的歷史設計。未來需發展對應的安全審核機制與價值對齊保證。

**7. 理論保證與收斂性分析**

目前缺乏對共同演化過程收斂性或穩定性的理論分析，未來可借鑑演化計算的理論工具，研究在何種條件下腦–體對齊能夠達成，以及達成對齊所需的演化輪數與資源下界。

## 論文問答

**Q1：什麼是「腦–體不匹配」（brain–body mismatch）問題？為何它在模型–外殼共同演化中特別關鍵？**
A：腦–體不匹配指的是在共同演化過程中，外殼（body）所要求的行為與模型（brain）已學會的行為產生分歧，或外殼限制了模型既有能力的發揮。具體而言可分為兩類：介面不匹配（interface mismatch），例如模型輸出 XML 工具呼叫但外殼期待 JSON，導致正確意圖被拒絕；以及能力不匹配（capability mismatch），例如外殼新增主動式上下文管理工具，但模型缺乏相關操作經驗而無法善用。此問題之所以關鍵，是因為共同演化是一個遞迴過程，每一輪的偏差都會累積放大，使後續世代的模型與外殼越來越難以相容，最終侵蝕代理整體效能。

**Q2：現有的遞迴自我改進方法為何未能有效處理這個問題？**
A：現有方法大致可分為僅優化外殼（harness-only）或僅優化模型（model-only）兩類，前者固定模型只調整提示、工具與控制流程，後者則固定外殼只更新模型參數，兩者皆缺乏雙向協調機制。即使是近期提出的共同演化系統，也多採用「僅最新版本」（latest-only）策略——每輪僅以當前的模型–外殼配對作為起點，忽略了歷史演化過程中累積的設計多樣性與能力軌跡。這種單點繼承方式使得介面契約一旦漂移就難以回溯修正，因為歷史檢查點與歷史外殼的相容性資訊已被丟棄。

**Q3：為什麼腦–體對齊（brain–body alignment）應該成為共同演化的組織原則？**
A：代理的能力並非單獨由模型決定，而是模型與外殼的聯合函數；若兩者朝不同方向演化，再強的模型也會因外殼介面錯誤而失效，再精巧的外殼也會因模型缺乏對應能力而無法發揮。將對齊作為組織原則，能讓每一輪演化都同時考慮「外殼需要模型做什麼」與「模型能為外殼做什麼」，使搜尋空間聚焦於真正可相容的配對。論文中以 TIMR（回合級介面不匹配率）作為廉價診斷訊號，正是為了讓對齊狀態在演化過程中可被持續觀測與修正。

**Q4：CoEvo-RSI 的核心運作機制為何？**
A：CoEvo-RSI 的核心是一個由元代理（meta-agent）協調的雙向歷史繼承流程：每一輪從當前模型–外殼配對的執行回饋出發，由策展人（Curator）整理證據，再由外殼編輯者從演化典藏庫中挑選歷史設計作為起點產生後代外殼。對每個後代外殼，框架會從典藏庫中選擇或合併歷史模型檢查點形成候選配對，經推演（rollout）評估後挑選有潛力的配對進行監督式微調，最後由驗證決定晉級到下一輪的配對，並將新設計、檢查點與結果回填典藏庫。

**Q5：何謂「雙向歷史繼承」（bidirectional historical inheritance）？它與單向繼承有何不同？**
A：雙向歷史繼承意味著演化同時沿兩個方向進行：外殼側繼承歷史設計的結構經驗，模型側則繼承與新外殼相容的能力檢查點。相較之下，僅最新版本方法只繼承上一輪的單一配對，無法利用歷史中已存在的相容組合。論文中以「介面不匹配」為例說明：當新外殼期待 JSON 而當前模型只會輸出 XML 時，可從典藏庫中挑選一個歷史檢查點 θᵢ，該檢查點已具備相關能力，作為新外殼下的適應起點，從而避免從零開始重新學習。

**Q6：為何採用演化典藏庫與元代理的設計？這樣的設計選擇帶來哪些權衡？**
A：演化典藏庫保留了外殼、檢查點、開發歷史與執行結果的多元紀錄，使後續世代能從中挑選「墊腳石」而非僅依賴單一最新版本，這對維持設計多樣性與避免局部最優至關重要。元代理則負責協調策展、外殼編輯、檢查點選擇與驗證等角色，使整個流程可由代理自主驅動而非依賴人工設計的控制迴路。權衡方面，典藏庫會隨時間膨脹，需要管理儲存與檢索成本；元代理的決策品質也會影響整體演化效率，因此論文中以拒絕取樣軌跡進行監督式微調來穩定其行為。

**Q7：實驗涵蓋哪些基準測試？為何選擇這些任務？**
A：實驗橫跨三個垂直領域：多代理失敗歸因（TraceElephant、Who&When）、角色感知文字轉 SQL（角色感知 Text-to-SQL）以及智慧家庭指令遵循（HomeBench VM）。這些任務分別考驗代理在多代理協作除錯、結構化查詢生成與長期上下文操作上的能力，皆屬於外殼設計會顯著影響表現的場景。選擇這些垂直應用是為了驗證 CoEvo-RSI 在不同領域皆能維持腦–體對齊，而非僅在通用基準上有效。

**Q8：CoEvo-RSI 的關鍵實驗結果為何？**
A：經共同演化後的 Qwen3.5-9B 在多項任務上超越體型更大的模型：在 TraceElephant 上以 +14.16 代理準確率超越 DeepSeek-V4-Pro，在 HomeBench VM 上以 +4.90 成功率超越 GLM-5.3，並在 Who&When Pro 上以 +4.40 代理準確率超越 Qwen3.8-Max。值得注意的是，這些成果僅透過對自身拒絕取樣軌跡進行監督式微調達成，並未依賴外部更大模型的蒸餾。此外，論文中圖 2 顯示 CoEvo-RSI 在步驟準確率與 TIMR 的聯合分布上明顯優於僅最新版本基線，達到 37.50% 準確率與 0% TIMR，相較基線提升 +13.05 個百分點。

**Q9：消融研究揭示了哪些設計元件的貢獻？**
A：論文中以「僅最新版本」作為關鍵消融對照，結果顯示其 TIMR 高達 0.118% 且步驟準確率僅 36.96%，證明放棄歷史繼承會直接導致介面不匹配累積。相對地，CoEvo-RSI 透過譜系繼承（lineage inheritance）從典藏庫中重組歷史外殼與檢查點，使 TIMR 降至 0% 並顯著提升準確率，凸顯雙向繼承機制的必要性。這也間接驗證了演化典藏庫與檢查點選擇／合併機制的價值——若僅繼承外殼而不挑選合適的歷史模型，仍會面臨能力不匹配的風險。

**Q10：CoEvo-RSI 適合哪些實際應用場景？**
A：對於需要長期演化的代理系統特別適合，例如企業級工具整合代理（外殼會隨業務需求持續新增工具）、智慧家庭或物聯網助理（介面與裝置規格經常變動），以及多代理協作平台（角色與溝通協議會動態調整）。在這些場景中，外殼與模型都會隨時間演化，腦–體對齊的需求最為迫切。此外，需要在有限模型規模下追趕大型模型能力的場景也很適合，因為 CoEvo-RSI 證明 9B 等級模型經共同演化後可與遠大於自身的模型競爭。

**Q11：將 CoEvo-RSI 部署到產品中需要考量哪些工程因素？**
A：首先，演化典藏庫的儲存與檢索效率是關鍵工程瓶頸，因為每輪都會新增外殼設計、檢查點與執行軌跡，需要設計索引與淘汰策略以控制規模。其次，元代理的決策延遲與成本會直接影響迭代速度，產品化時需考慮以較小的模型或快取機制降低單輪時間。此外，監督式微調的資料來源完全依賴自身拒絕取樣軌跡，因此軌跡品質與多樣性的把關機制（如過濾低品質樣本、避免獎勵 hacking）至關重要。

**Q12：這項研究對遞迴自我改進領域的整體影響為何？**
A：CoEvo-RSI 將「腦–體對齊」從隱含假設提升為顯式設計原則，促使後續研究在評估 RSI 系統時必須同時報告介面相容性指標（如 TIMR）而非僅看任務準確率。雙向歷史繼承的概念也為達爾文式機器學習（如 Darwin Gödel Machine）提供了更具體的實作藍圖，證明典藏庫不僅可保留程式碼，也可保留模型能力軌跡。更宏觀地看，本研究挑戰了「模型越大越好」的預設，展示了透過聰明的共同演化，小模型也能在垂直領域達到甚至超越大模型的表現。

**Q13：論文承認哪些限制？**
A：論文中所有實驗均以 Qwen3.5-9B 為基礎模型，雖然證明了方法在小模型上的有效性，但對於極大模型（如百億參數以上）或不同架構（MoE、混合專家）下的可擴展性尚未驗證。此外，演化典藏庫的成長缺乏明確的剪枝或合併策略，長期運行下可能面臨儲存與計算成本上升的問題。最後，監督式微調僅使用拒絕取樣軌跡，未引入強化學習或偏好優化，這限制了模型在需要探索新行為的任務上的潛力。

**Q14：可能存在哪些失敗案例或邊界情境？**
A：當任務領域的歷史設計與新需求差異過大時，典藏庫中可能找不到合適的歷史外殼或檢查點作為起點，導致繼承機制失效而退化為僅最新版本行為。此外，若元代理本身的決策能力不足，可能錯誤挑選不相容的歷史元件，反而放大腦–體不匹配。在執行回饋稀疏或雜訊高的環境中，策展人整理出的證據可能誤導後續演化方向，使整個流程陷入次優循環。

**Q15：未來有哪些值得探索的研究方向？**
A：未來可將 TIMR 等介面診斷指標擴展為演化過程中的獎勵訊號，結合強化學習進行更細粒度的腦–體對齊優化。另一方向是將雙向歷史繼承應用於多代理場景，使不同代理間的介面契約也能透過共同演化自動協調。此外，演化典藏庫的理論分析（如收斂性、多樣性下界）以及與神經架構搜尋的結合，都是值得深入探索的開放問題。最終，若能將此框架擴展至跨模態代理（視覺、語音、動作），將更能驗證其通用性。

## 實務應用指南

### 適用場景

1. **企業內部多代理協作系統的長期迭代**：當組織內已部署多個專責代理（如客服分流、訂單處理、知識檢索），且需要隨業務規則變動持續調整其工具介面與協作流程時，CoEvo-RSI 的演化典藏庫能保留每一輪的設計與成效紀錄，避免「換了外殼、模型卻跟不上」或「模型會做、外殼卻不讓它做」的腦–體不匹配。

2. **垂直領域代理的快速客製化**：在醫療、零售、智慧家庭等領域，需要把通用模型（如 Qwen3.5-9B 等中型開源模型）調校到能與領域專屬工具（病歷查詢 API、ERP 介面、IoT 指令集）對接。CoEvo-RSI 透過拒絕取樣軌跡的 SFT，可在不依賴昂貴人類標註的情況下，讓中型模型逼近大型模型的表現。

3. **工具介面頻繁變動的代理系統**：當工具的呼叫格式（XML、JSON、結構化描述）在不同版本或不同廠商間變動時，介面契約的漂移會讓原本正確的意圖被拒絕。CoEvo-RSI 的 TIMR 診斷與歷史繼承機制特別適合處理這類「介面契約變更」情境。

4. **從小型開源模型建立具競爭力的代理**：預算或資安考量下無法使用頂級閉源模型時，可利用 CoEvo-RSI 讓 7B–9B 級別的模型在特定垂直任務上超越數倍參數量的對手（如論文中 Qwen3.5-9B 在 TraceElephant 上超越 DeepSeek-V4-Pro +14.16 代理準確率）。

5. **需要可追溯演化歷程的代理開發**：在金融、醫療等受監管產業，代理的決策與工具呼叫必須可審計。CoEvo-RSI 的譜系繼承與典藏庫天然提供「為什麼這個版本會這樣設計、它繼承自哪些前代」的審計線索。

### 實作前置條件

**資料面**
- **執行回饋日誌**：每一輪代理執行需蒐集完整軌跡（工具呼叫、輸出、回應、是否成功），這是 Curator 整理證據與拒絕取樣的基礎。
- **歷史設計與檢查點**：需有可追溯的版本控制系統儲存每一代外殼程式碼、提示詞、模型權重（即模型檢查點），以及對應的成效指標。
- **領域任務集**：至少需要數百到數千筆領域內的「任務–成功軌跡」配對，用於 SFT 訓練；論文中以拒絕取樣自動產生，因此也需要可評估任務成敗的環境或評測器。

**運算面**
- **SFT 訓練基礎設施**：能對 7B–9B 級模型進行監督式微調的 GPU 叢集（建議 A100/H100 等級，視資料量而定）。
- **模型合併工具鏈**：若要實作檢查點合併（model merging），需準備對應的權重平均或任務向量（task arithmetic）工具。
- **代理執行沙箱**：可重現、可評估的代理執行環境，用於 rollout 與驗證。

**技能面**
- **代理工程經驗**：熟悉工具呼叫格式、提示詞工程、控制流程設計。
- **基礎 ML 訓練能力**：能操作 SFT 流程、理解過擬合與資料品質的關係。
- **版本管理與譜系追蹤**：能設計典藏庫結構，記錄「誰從誰演化而來、為何被選中」。
- **評測設計能力**：能設計任務級與回合級（turn-level）的成效指標，特別是 TIMR 這類介面契約違規偵測。

### 實作步驟建議

**階段一：建立最小可行典藏庫（MVP Archive）**
1. 定義外殼的版本化結構（提示詞、工具清單、控制流程、記憶體配置）。
2. 為每一個外殼版本綁定一個模型檢查點與成效紀錄。
3. 實作 Curator 模組：將執行回饋整理成「外殼版本 × 檢查點 × 成效」三元組。

**階段二：實作單輪共同演化迴圈**
1. 從當前配對 $(H_t, \theta_t)$ 收集執行回饋 $F_t$。
2. 由元代理（meta-agent）驅動外殼編輯器，從典藏庫挑選歷史設計作為起點，重組產生下一代外殼候選。
3. 對每個外殼候選，從典藏庫挑選或合併歷史檢查點，形成候選配對。
4. 在沙箱中 rollout，計算任務成功率與 TIMR。
5. 選出最具腦–體對齊潛力的配對進行 SFT 適應。
6. 驗證後將新設計、新檢查點、新成效寫回典藏庫。

**階段三：導入雙向歷史繼承**
1. **外殼側繼承**：編輯器不只修改當前版本，而是從歷史設計中挑選結構相近者作為起點。
2. **模型側繼承**：除「僅最新版本」外，加入「歷史檢查點選擇」與「檢查點合併」兩個選項。
3. 設計繼承策略的啟發式：例如優先選擇 TIMR 低且任務成功率高的前代，或在能力不匹配時合併多個歷史檢查點。

**階段四：診斷與監控**
1. 將 TIMR 作為常駐監控指標，設定告警閾值。
2. 視覺化譜系樹，標註每一代的腦–體對齊狀態。
3. 定期審視典藏庫的多樣性，避免早熟收斂。

**階段五：產品化與持續迭代**
1. 將演化迴圈包裝為可排程的批次任務，定期（例如每週）產出新版本。
2. 建立 A/B 測試框架，讓新版本在受控流量上驗證後再全面上線。
3. 保留「僅最新版本」作為基線對照組，量化雙向繼承的實際增益。

### 潛在風險與注意事項

**風險一：典藏庫膨脹導致搜尋成本失控**
- *現象*：每一輪產生數十個外殼與檢查點候選，數十輪後典藏庫爆炸。
- *緩解*：設定保留策略（保留成效前 K%、淘汰長期無用的分支）、對歷史設計做嵌入索引以加速相似度搜尋、定期對典藏庫做剪枝。

**風險二：拒絕取樣偏差放大錯誤行為**
- *現象*：若評測器本身有缺陷，被拒絕的軌跡可能其實是正確的，導致 SFT 學到錯誤模式。
- *緩解*：定期以人工抽樣檢核拒絕取樣的正確性；對評測器做交叉驗證；保留少量「黃金軌跡」作為評測器的校正基準。

**風險三：腦–體對齊過度擬合特定外殼**
- *現象*：模型過度適應某一外殼版本，當外殼再次演化時又出現不匹配。
- *緩解*：在 SFT 資料中混入不同外殼版本的軌跡；保留多個歷史檢查點作為「保險」；在驗證階段加入外殼變動的壓力測試。

**風險四：模型合併產生能力抵消**
- *現象*：合併兩個歷史檢查點時，任務向量互相干擾，導致某些能力反而下降。
- *緩解*：採用經驗證的合併方法（如 TIES-MERGING、Task Arithmetic）；合併後立即在驗證集上評估；保留未合併的原始檢查點以便回退。

**風險五：演化方向漂移與目標不一致**
- *現象*：元代理在多輪演化後追求的目標偏離原始業務需求。
- *緩解*：在 Curator 中嵌入固定的業務 KPI 約束；定期由人類審視演化方向；保留「人類在迴圈中」（human-in-the-loop）的覆寫機制。

**風險六：TIMR 低不代表真的對齊**
- *現象*：模型可能學會「怎樣呼叫才不會被拒絕」，但呼叫的語意正確性仍不足。
- *緩解*：TIMR 必須與任務級成功率、步驟準確率等語意指標並用，不可單獨作為對齊證據。

---

### 與其他技術的整合建議

**與既有代理框架整合**
- **LangChain / LlamaIndex**：可將 CoEvo-RSI 的「外殼」抽象為這些框架的 Chain 或 Agent 物件，演化操作對應到框架的元件替換；典藏庫則映射到框架的版本化配置。
- **AutoGen / CrewAI**：在多代理協作場景中，每個代理可視為一個「腦–體配對」，演化迴圈可同時作用於多個代理並協調其介面契約。

**與模型訓練管線整合**
- **Hugging Face Transformers + PEFT/LoRA**：對 7B–9B 模型進行 SFT 時，建議採用參數高效微調以降低運算成本；檢查點合併可與 PEFT 適配器合併工具鏈銜接。
- **vLLM / TGI 等推論引擎**：rollout 階段使用高效推論引擎加速評估；TIMR 監控可作為推論階段的日誌鉤子。

**與 MLOps / LLMOps 整合**
- **MLflow / Weights & Biases**：用於追蹤每一輪的檢查點、外殼版本、成效指標；典藏庫可作為這些工具的「自訂後端」。
- **DVC / Git LFS**：外殼程式碼與模型權重皆需版本化；譜系樹可由 Git 分支圖衍生。

**與評測基準整合**
- **Who&When / TraceElephant / HomeBench VM**：論文中驗證的基準，可直接作為初期評測環境；建議擴充至自身業務的私有基準。
- **客製化評測器**：對於無標準基準的領域，需自行實作可程式化評測的任務集，這是 Curator 與拒絕取樣的基礎。

**與監控與可觀測性整合**
- **OpenTelemetry / LangSmith**：將每一輪的執行回饋接入可觀測性平台，使 TIMR、步驟準確率等指標可即時儀表板化。
- **審計日誌**：在受監管產業，典藏庫的演化紀錄應與企業審計系統對接，確保可追溯。

### 給不同背景讀者的閱讀建議

**給初學者**：先讀第 1 節的「腦–體不匹配」兩個具體例子（XML vs JSON 介面不匹配、active context management 工具的能力不匹配），這能幫助你在沒有 ML 背景的情況下直觀理解問題。接著看圖 2 的右側散佈圖，體會 TIMR 與步驟準確率的反向關係。暫時跳過數學符號，專注在「為什麼外殼與模型會脫節」這個直覺問題。

**給 AI 工程師**：重點放在第 1 節後半的 CoEvo-RSI 流程描述與「實作步驟建議」中的階段二、階段三。具體關注三個工程細節：(1) Curator 如何將執行回饋結構化、(2) 檢查點選擇 vs 合併的取捨條件、(3) SFT 資料如何從拒絕取樣軌跡產生。建議直接動手做一個最小版本（單一外殼、單一檢查點、無合併），驗證腦–體不匹配是否真的會發生，再逐步加入典藏庫與繼承機制。

**給研究者**：第 1 節的「Problem Definition」是形式化核心，建議仔細推敲其與既有概念（如 distribution shift、capability–environment mismatch）的關係與差異。圖 2 的左側譜系圖與右側散佈圖是論文的視覺化重點，可思考 TIMR 是否足以捕捉所有腦–體不匹配類型（例如語意層級的不匹配）。第 2 節的相關工作分類（遞迴外殼改進 vs 遞迴模型改進 vs 共同演化）提供了清晰的文獻地圖，值得對照自身研究定位。

**給產品經理**：聚焦於「適用場景」與「潛在風險」兩節。理解 CoEvo-RSI 解決的是「代理系統長期演化時的相容性問題」，而非單純的模型效能提升。關注三個產品決策點：(1) 是否值得為中型模型投入共同演化管線，以換取對閉源大型模型的替代、(2) 演化迴圈的迭代頻率與人力審查成本、(3) 典藏庫的保留策略對儲存與合規成本的影響。論文中 Qwen3.5-9B 超越 DeepSeek-V4-Pro 的數字可作為內部提案時的成本效益佐證。
