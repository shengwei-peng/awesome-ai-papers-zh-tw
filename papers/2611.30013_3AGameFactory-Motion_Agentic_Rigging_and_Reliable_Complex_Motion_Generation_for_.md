## ⚡ TL;DR

現有動作生成模型難以處理多形態3D資產的長時序、多階段複雜指令控制。
作者提出DivDynBench基準與代理式動作框架，以LLM編寫緊湊參數化骨架與動作程式。

## 摘要翻譯

根據指令為任意 3D 資產進行動畫生成，需要同時進行結構推論與動作控制，然而現有的動作基準測試（benchmark）大多僅涵蓋傳統的人類或動物骨架，且指令較為簡單。我們提出 DivDynBench，用以評估六種形態類別（morphology categories）的骨架綁定（rigging）與動作生成（motion generation），其指令要求多階段（multi-phase）部位協調（part coordination）以及明確的時間（timing）、角度、重複（repetition）與軌跡（trajectory）約束。透過大型語言模型（Large Language Models, LLMs），我們系統性地比較三種常見範式（paradigm）：專用動作生成（Specialized Motion Generation）、影片生成（Video Generation）後再進行動作重建（Motion Recovery），以及直接代理驅動生成（Direct Agent-driven Generation），並分析其控制能力、跨形態適應性（Cross-morphology Adaptability）與生成成本。基於此比較，我們提出一個代理式動作框架（Agentic Motion Framework），其中代理會撰寫緊湊的參數化骨架（Parametric Skeleton）與動作程式（Motion Programs），並由確定性的（Deterministic）執行器（Executor）負責骨架綁定、運動學求解（Kinematic Solving）與幾何修正（Geometric Correction）。緊湊參數控制（Compact Parameter Control）降低了生成開銷（Generation Overhead），並提升了骨架綁定的可靠性與動作控制精度（Control Accuracy），為部署複雜 3D 動作生成提供實務指引（Practical Guidance）。

### 核心貢獻（3～5點）
- **提出 DivDynBench 基準測試**：涵蓋六種形態類別（人形 Humanoid、多足類 Multiped、軸向類 Axial、有翅類 Winged、混合肢體類 Mixed-limb、機械類 Mechanical），並要求多階段部位協調與明確的時間、角度、重複與軌跡約束，突破既有基準測試僅限於人類或動物骨架的限制。
- **系統性比較三種動作生成範式**：透過大型語言模型，針對專用動作生成、影片生成搭配動作重建、以及直接代理驅動生成三種常見範式，進行控制能力、跨形態適應性與生成成本的全面分析。
- **提出代理式動作框架（Agentic Motion Framework）**：採用「代理撰寫程式＋確定性執行器執行」的分工架構，由代理產出緊湊的參數化骨架與動作程式，再由確定性執行器執行骨架綁定、運動學求解與幾何修正。
- **緊湊參數控制機制**：透過精簡的參數化表示降低生成開銷，同時提升骨架綁定的可靠性與動作控制精度。
- **提供實務部署指引**：為複雜 3D 動作生成系統的實際部署提供具體的設計建議與參考依據。

### 適合對象
本論文最適合以下讀者閱讀：從事 3D 角色動畫、遊戲開發、虛擬數位人、機器人模擬或電腦圖學研究的學者與工程師；對大型語言模型驅動之代理系統（agentic systems）及其在結構化程式合成（program synthesis）應用有興趣的人工智慧研究者；以及需要評估或選用動作生成管線（motion generation pipelines）的業界從業者，特別是面臨跨形態、多階段、細粒度控制（fine-grained control）需求的團隊。

## 深度分析

#### 方法論解析

本論文提出了一套完整的「代理式動作生成」(Agentic Motion Generation) 系統，核心目標是解決從文字指令生成多形態 3D 資產複雜動作的難題。其方法論可從三個層面深入剖析：

**一、基準測試設計：DivDynBench**

作者首先指出既有動作生成基準的侷限性——多數僅涵蓋人型或動物骨架，且指令過於簡單。因此提出 DivDynBench，橫跨六種形態學 (morphology) 類別：
- **人形 (Humanoid)**：傳統雙足骨架
- **多足類 (Multiped)**：如四足、六足生物
- **軸向類 (Axial)**：如蛇、魚等以軀幹為主的結構
- **有翅類 (Winged)**：如鳥、龍、飛蟲
- **混合肢體類 (Mixed-limb)**：如半人馬、奇幻生物
- **機械類 (Mechanical)**：如機器人、工業設備

此分類的設計邏輯在於：真實 3D 資產的關節拓樸 (joint topology) 差異極大，傳統綁定 (rigging) 流程難以泛化。基準測試的指令設計特別強調**多階段部位協調 (multi-phase part coordination)** 與**顯式約束**——包含時序 (timing)、角度 (angle)、重複次數 (repetition) 與軌跡 (trajectory) 四類數值化條件。評估方式區分為**文字語意合規性**與**程式驗證的數值準確度**，並進一步評估階段完整性、形態適配性與動畫品質，這種多維度拆解避免了單一指標的偏誤。

**二、三種範式的系統性比較**

論文歸納出三種基於 LLM 的主流動作生成範式（對應 Table 1）：

1. **LLM + 專用動作生成器 (Specialized Motion Generation)**：以 Motion-Agent 搭配 MoMask、UniMate 等專用模型為代表。LLM 將複雜指令分解為片段，由專用模型合成。優點是低成本且動作自然，但受限於模型的固定骨架與粗粒度語意，無法處理細粒度控制。

2. **LLM + 影片生成與動作重建 (Video Generation + Motion Recovery)**：以 Seedance 2.0、KlingOmni 生成影片，再透過 DuoMo、GENMO 重建動作並重定向 (retarget) 至 3D 資產。視覺先驗 (visual priors) 帶來高品質動作，但生成成本高昂，且重建模型主要為人體設計，時序與幅度容易在轉換過程中流失。

3. **直接代理驅動生成 (Direct Agent-driven Generation)**：以 Claude Opus 5.5、GPT-6、GenRA 為代表，透過時空推理 (spatiotemporal reasoning) 直接生成動作程式或關鍵幀。優勢在於跨形態適應性強、細粒度控制能力高，但逐幀輸出所有關節座標會消耗大量 token，且缺乏運動學約束 (kinematic constraints)。

此三種範式的比較揭示了一個關鍵取捨：**自然性 vs. 可控性 vs. 成本**。專用模型自然但不可控；影片重建視覺佳但成本高且精度差；直接代理生成可控但效率低且物理一致性弱。

**三、代理式動作框架 (Agentic Motion Framework)**

基於上述分析，作者提出核心方法論——將「規劃」與「執行」分離：

- **代理 (Agent) 角色**：負責高階語意規劃。將指令分解為動作階段與時序，選擇關鍵部位與末端效應器 (end-effectors)，規劃每階段的軌跡與目標值。代理僅輸出一小組語意參數，而非逐幀關節座標。

- **執行器 (Executor) 角色**：負責確定性 (deterministic) 的低階運算。透過運動學求解 (kinematic solving) 從代理的參數中推導全身姿態，並利用變形後的網格 (deformed mesh) 修正穿插 (interpenetration) 與地面接觸問題。

此架構的關鍵洞見在於**緊湊參數控制 (compact parameter control)**：代理只需輸出語意層級的參數（如「左翅在 2 秒內抬升至 60 度」），而非整段動作的所有關節角度。這大幅降低了 token 消耗與生成開銷 (generation overhead)，同時將物理一致性與運動學約束交由確定性演算法處理，避免了 LLM 直接輸出關節座標時缺乏約束的問題。

此外，框架還包含**動畫驗證 (animation validation)** 步驟，確保匯出的動畫符合預期，這形成了一個閉環的品質控制機制。

#### 實驗數據解讀

雖然提供的全文僅至 Related Works 段落，但從方法論與 Table 1 的設計可推導出實驗的核心發現：

**一、範式比較的關鍵結論**

Table 1 以 ✓（強）、△（部分支援）、×（關鍵限制）標記三種範式在四個維度的表現：

| 維度 | 專用動作生成 | 影片+重建 | 直接代理生成 |
|------|-------------|----------|-------------|
| 低成本 | ✓ | × | △ |
| 自然動作 | ✓ | ✓ | △ |
| 複雜形狀生成 | × | △ | ✓ |
| 細粒度控制 | × | × | ✓ |

此表格揭示了一個**互補性結構**：沒有任何單一範式在所有維度上表現優異。專用模型在成本與自然性上勝出，但無法處理複雜形態；影片重建在自然性上表現良好，但成本與精度是瓶頸；直接代理生成在形態適應性與控制精度上最具潛力，但成本與自然性仍有改善空間。

**二、DivDynBench 的評估意涵**

基準測試的設計本身即是一項實驗貢獻。透過六種形態的系統性測試，能夠揭示模型在**跨形態泛化**上的真實能力——這是現有基準無法捕捉的。指令中的數值約束（時序、角度、重複、軌跡）則考驗模型的**精確遵循能力**，而非僅僅是語意相似度。

區分「文字語意合規性」與「程式驗證數值準確度」的評估方式特別值得注意：前者衡量動作是否符合指令描述的「意圖」，後者衡量是否符合指令規定的「數值」。這兩者經常被混淆，但在複雜指令下可能出現「語意正確但數值錯誤」的情況（例如：動作確實是拍翅，但角度不對）。

**三、代理式框架的預期效益**

從方法論推導，該框架相較於直接代理生成的改進在於：
- **Token 消耗降低**：從逐幀所有關節座標縮減為語意參數
- **物理一致性提升**：運動學求解確保骨骼長度不變
- **幾何正確性提升**：網格層級的穿插修正
- **可控性提升**：參數化設計使數值約束可直接對應

然而，具體的量化數據（如各範式在六種形態上的成功率、誤差分佈、生成時間對比）需參閱完整論文的實驗章節。

#### 與現有研究的比較

**一、相關工作定位**

論文在 Related Works 中梳理了三條主要技術路線：

1. **3D/4D 生成路線**：從零樣本最佳化方法（如 DreamFusion 類）到前饋重建方法（如 Hunyuan3D 1.0），再到 4D 動態內容生成（如 Animate3D）。這些方法提升了視覺品質與效率，但論文指出「視覺真實性本身並不能確保執行涉及協調部位、有序階段與精確約束的複雜指令」——這是對純視覺生成路線的關鍵批評。

2. **代理式生成路線**：從 Holodeck、SceneCraft 到世界模型統一方法，這些工作展示了 LLM 代理在場景建構、工具使用與迭代精修上的能力。然而，論文強調「建構視覺豐富的動態場景」與「為具有多樣關節結構的化身生成精確、遵循指令的動作」是本質不同的任務——前者重視空間佈局與視覺效果，後者重視時序精確性與物理一致性。

3. **化身動作生成路線**：涵蓋擴散模型（如 MDM）與離散動作表示（如 MoMask），以及人體與動物動作資料集。然而，這些方法多數假設固定骨架結構，難以泛化至任意形態。

**二、本文的獨特貢獻**

相較於上述工作，本文的差異化在於：

- **從「視覺品質」轉向「指令遵循」**：既有研究多關注動作的自然性與視覺效果，本文則強調對複雜數值指令的精確執行。
- **從「固定形態」轉向「任意形態」**：既有動作生成模型多為人體或特定動物設計，本文提出可適應任意關節拓樸的框架。
- **從「單一範式」轉向「範式比較」**：既有研究多各自為政，本文首次系統性比較三種 LLM 輔助範式。
- **從「端到端生成」轉向「規劃-執行分離」**：既有代理式方法多由 LLM 直接輸出動作，本文將高階規劃與低階確定性執行解耦。

**三、潛在限制**

儘管方法論新穎，仍可預見以下限制：
- **運動學求解的適用性**：對於高度非樹狀結構（如機械裝置中的閉環約束），標準運動學求解可能不足。
- **代理推理的可靠性**：LLM 在數值推理上仍有誤差，複雜指令的分解可能失敗。
- **基準測試的覆蓋偏誤**：六種形態雖具代表性，但真實 3D 資產的形態空間遠大於此。
- **評估主觀性**：動畫品質的視覺評分本質上具有主觀性。

#### 未來研究方向

本論文開啟了多個值得深入探索的研究方向：

**一、形態學擴展與自動化綁定**

當前框架涵蓋六種形態，但真實世界的 3D 資產形態遠多於此。未來可研究：
- **自動骨架推斷 (Automatic Skeleton Inference)**：從任意網格自動推導關節層級與約束，而非依賴預定義的形態類別。
- **形態表徵學習**：學習一個連續的形態嵌入空間，使代理能夠在相似形態間遷移動作。
- **非剛體與混合結構**：處理軟體、流體、剛柔耦合等更複雜的物理結構。

**二、代理推理能力的強化**

LLM 在數值推理上的侷限性是當前瓶頸，可探索：
- **專門化的動作語言模型**：在大量動作資料上微調 LLM，提升其時空推理能力。
- **符號-神經混合架構**：結合符號推理（運動學約束）與神經生成（自然動作）。
- **多代理協作**：將規劃代理、驗證代理、精修代理分離，各自負責不同子任務。

**三、評估方法的標準化**

DivDynBench 是重要的一步，但評估方法仍有改進空間：
- **物理模擬驗證**：將生成動作放入物理模擬器，檢查其是否符合物理規律。
- **使用者研究標準化**：建立統一的動畫品質評分協議。
- **跨基準泛化測試**：在多個基準上測試，提升結果的穩健性。

**四、應用場景拓展**

該技術可應用於多個領域：
- **遊戲開發**：快速為遊戲資產生成動作，降低開發成本。
- **電影預覽 (Previs)**：為概念設計快速生成動作參考。
- **機器人模擬**：為機器人模擬訓練生成多樣化動作。
- **AR/VR 內容創作**：讓使用者透過自然語言控制虛擬角色。

**五、與其他模態的融合**

- **多模態指令**：結合文字、圖像、影片、示範動作的混合指令。
- **即時互動**：支援使用者在動畫過程中即時修改指令。
- **風格控制**：在動作生成中融入藝術風格控制（如「卡通風格的拍翅」）。

**六、理論基礎的深化**

- **動作的組合語意**：研究動作的組合性 (compositionality)，使代理能夠組合基本動作生成複雜動作。
- **因果推理**：讓代理理解動作的因果結構，而非僅僅是時序關聯。
- **物理直覺**：將物理直覺編碼至代理推理中，使其能預測動作的物理後果。

   - **運動學求解（Kinematic Solving）**：以代理給定的軌跡與目標點，透過 IK/FK 求解每幀的關節角度，並套用骨長與接觸約束。
   - **幾何修正（Geometric Correction）**：利用變形後的網格偵測穿模與穿地，進行局部修正並回饋至下一輪求解。

4. **建立驗證與回饋迴圈**：將匯出的動畫以程式化方式驗證時間、角度、重複次數與軌跡是否符合指令；不符時將錯誤訊息回傳給代理進行重試或修正，形成閉環。

5. **整合至下游引擎**：將執行器輸出封裝為 FBX、USD 或引擎原生格式，匯入 Unity、Unreal、Blender 或自製管線；同時提供 API 或 CLI 介面供外部系統呼叫。

6. **以 DivDynBench 進行基準測試**：在六類形態上各選數個資產與多階段指令，評估指令合規率、階段完整性、形態適配度與動畫品質，作為迭代依據。

7. **優化成本與延遲**：由於代理僅輸出緊湊參數，可透過快取常見骨架模板、批次處理與非同步執行降低單次生成開銷；對於即時互動場景，可預先生成常用動作庫並以參數微調。

### 潛在風險與注意事項

- **LLM 輸出不確定性**：代理可能產生語法錯誤或語意偏差的骨架/動作程式。**緩解方式**：採用結構化輸出（JSON/DSL）、語法驗證器與語意檢查；對關鍵參數（角度、重複次數）設定硬約束，違反時自動重試。

- **運動學奇異點與不可達姿態**：代理給定的目標可能超出關節極限或導致 IK 求解失敗。**緩解方式**：在模板中預設關節角度上下界，求解器加入奇異點避讓與阻尼最小二乘法；失敗時回饋代理重新規劃。

- **穿模與接地錯誤**：缺乏骨長與接觸約束時，動作容易出現部位穿模或懸浮。**緩解方式**：執行器必須整合網格碰撞偵測與地面約束；對機械類等剛體資產可採用更嚴格的碰撞容差。

- **跨形態泛化失敗**：代理可能將人形語意誤用於非人形資產（例如把「手」套用到機械臂）。**緩解方式**：在提示詞中明確標註資產形態與可用部位詞彙，並以 DivDynBench 持續監測跨形態表現。

- **生成成本與延遲**：雖然緊湊參數控制已降低開銷，但長時序、多階段指令仍可能消耗大量 token。**緩解方式**：採用分階段生成（先骨架、後動作）、快取中間結果、限制最大階段數；對即時應用預先生成動作庫。

- **評估主觀性**：動畫品質（自然度、流暢度）難以純以程式驗證。**緩解方式**：結合視覺評分（人工或視覺語言模型）與程式驗證的數值指標，並建立多人標註流程以降低偏誤。

- **智慧財產與授權**：使用第三方 LLM 與影片生成模型時，需注意輸出內容的授權條款與訓練資料合規性。

### 與其他技術的整合建議

- **與遊戲引擎整合**：將執行器輸出直接匯入 Unity（透過 Unity Animation API）或 Unreal（透過 Control Rig + Sequencer）；可進一步封裝為引擎插件，提供「文字輸入 → 動畫片段」的即時預覽面板。

- **與 Blender 整合**：利用 Blender Python API 將骨架程式轉為實際骨架與動作關鍵幀，並透過 Geometry Nodes 進行幾何修正；適合工作室內部的 previs 流程。

- **與 LLM 代理框架整合**：可將動作生成代理掛載於 LangChain、AutoGen 或自製代理框架中，與場景生成、材質生成、燈光代理協同，構成完整的 3D 內容創作代理系統。

- **與影片生成模型互補**：對於需要極高視覺擬真度但時序精度要求較低的場景（如電影預覽），可採用「影片生成 + 動作重建」範式作為後備方案；本框架的確定性執行器可作為重建後的精修步驟。

- **與動作捕捉（MoCap）資料整合**：將既有 MoCap 資料轉換為參數化骨架模板與動作片段庫，代理可從中選取最接近的片段並進行參數微調，兼顧自然度與可控性。

- **與機器人模擬平台整合**：將運動學求解器與 ROS、Gazebo、Isaac Sim 等模擬環境對接，使生成的動作可直接用於機器人控制策略測試；需注意實體機器人的動態約束與本框架的運動學假設差異。

- **與版本控制與資產管理整合**：將骨架程式與動作參數以文字形式存入 Git 等版本控制系統，便於追蹤變更、協作與審查；網格與最終動畫則以二進位格式管理。

### 給不同背景讀者的閱讀建議

**初學者**：建議先閱讀摘要與第 1 節的「三種 LLM 範式比較表」（Table 1），建立對「專用動作生成、影片生成+動作重建、直接代理驅動」三條路線的直觀理解；接著瀏覽 DivDynBench 的六類形態說明，體會為何現有基準不足以評估多樣化資產；無需深究運動學細節，重點在於掌握「代理寫參數、執行器做求解」的核心分工概念。

**AI 工程師**：應聚焦於第 1 節末段的 Agentic Motion Framework 設計與第 2.2 節的代理生成相關工作；實作上需特別注意 LLM 輸出格式的結構化設計、執行器的運動學約束整合，以及幾何修正的回饋迴圈；可借鏡 Holodeck、SceneCraft 等代理系統的程式碼生成與視覺回饋機制，並評估將本框架整合至既有 LLM 代理管線的成本與效益。

**研究者**：本論文的核心貢獻在於 DivDynBench 的設計（涵蓋六類形態、多階段指令、程式驗證與視覺評分）以及三種範式的系統性比較；建議深入分析基準的評估指標拆解（語意合規 vs. 數值精度、階段完整性、形態適配度），並思考如何擴展至更複雜的物理約束、互動動作或多角色協調場景；代理式框架的緊湊參數控制與確定性執行分離，也為後續研究（如可微分運動學、強化學習微調）提供了清晰的切入點。

**產品經理**：應關注此技術對內容生產流程的顛覆性——從「動畫師逐幀製作」轉為「策劃以文字指令生成」，可大幅降低人力成本與迭代週期；評估導入價值時，需權衡 LLM API 成本、跨形態泛化能力（是否能覆蓋自家資產庫）、以及與現有引擎/管線的整合難度；對於遊戲、影視、教育、元宇宙等不同場景，建議先以單一形態（如機械類）進行 POC 驗證，再逐步擴展至全形態部署。
