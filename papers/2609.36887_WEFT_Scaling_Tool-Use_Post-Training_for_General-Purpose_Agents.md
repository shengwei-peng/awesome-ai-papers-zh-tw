## ⚡ TL;DR

現有工具使用後訓練僅擴展可執行環境，但系統各元件不一致會產生誤導性學習訊號。
本文提出WEFT，以執行驅動自我演化改進全系統，並透過保留前綴採樣、原子回合功勞分配與MegaMCP穩定後訓練。
WEFT模型在多項工具使用基準與長期工作流程測試中均顯著優於同規模基線。

## 摘要翻譯

近期擴展工具使用後訓練（tool-use post-training）的研究大多聚焦於可執行環境（executable environments）的合成，而這僅是更廣泛的代理互動系統（agentic interaction system）中的一個元件；該系統由環境（environment）、任務（task）、代理測試架（agent harness）與評估器（evaluator）組成。然而，單獨擴展環境並無法保證模型效能獲得相應提升，因為可靠的學習訊號（learning signals）取決於代理互動系統所有元件之間協調一致的互動。為了解決此問題，我們提出 WEFT（Whole-system Evolution For Tool-use Post-training，工具使用後訓練的全系統演化），它結合了可擴展的代理互動系統建構、執行驅動自我演化（execution-driven self-evolution）與穩定後訓練（stable post-training）。WEFT 在環境廣度（environment breadth）、任務複雜度（task complexity）與互動多樣性（interaction diversity）等面向擴展代理互動系統的建構。執行驅動自我演化會反覆利用執行軌跡（execution traces）與狀態證據（state evidence）來進行失敗歸因（failure attribution），並修正肇因元件；再透過全新 rollout（推演）評估這些變更，並為後續演化回合提供證據。為了實現大規模穩定後訓練，WEFT 同時兼顧最佳化可靠性（optimization reliability）與執行可靠性（execution reliability）：保留前綴採樣（prefix-preserving sampling）可維持已驗證的進展（verified progress），原子回合功勞分配（atomic-turn credit assignment）則能定位學習訊號；而 MegaMCP 在共享工具服務（shared tool services）上進行並行 rollout（concurrent rollouts，推演）時，維持隔離且可復原的狀態（isolated, recoverable state）。跨越多種模型與基準測試（benchmarks）的廣泛實驗證實了 WEFT 在工具使用後訓練上的有效性。WEFT-8B 與 WEFT-14B 在 BFCL V4、τ²-Bench 與 Claw-Eval 上，優於所有受評估的相同規模的環境擴展基線（matched-size environment-scaling baselines）。特別是，WEFT-14B 相較於 Agent-World-14B 分別提升了 6.41、2.23 與 12.27 百分點（percentage points）。WEFT-35B-A3B 進一步將這些增益擴展至更具挑戰性的長期工作流程基準測試（long-horizon workflow benchmarks），包括 Toolathlon-Verified 與 AutomationBench。

### 核心貢獻（3～5點）
- 提出 WEFT 框架，將「可擴展的代理互動系統建構」「執行驅動自我演化」與「穩定後訓練」三者結合，突破僅擴展環境的侷限。
- 設計執行驅動自我演化機制，利用執行軌跡與狀態證據進行失敗歸因，並針對肇因元件進行修正，再以全新 rollout 驗證改進。
- 提出多項穩定後訓練技術：保留前綴採樣維持已驗證進展、原子回合功勞分配定位學習訊號，以及 MegaMCP 在共享工具服務上維持並行 rollout 的隔離且可復原狀態。
- 在多個基準測試上驗證有效性：WEFT-8B 與 WEFT-14B 在 BFCL V4、τ²-Bench 與 Claw-Eval 上超越所有相同規模的環境擴展基線；WEFT-35B-A3B 進一步在 Toolathlon-Verified 與 AutomationBench 等長期工作流程基準測試上擴展優勢。

### 適合對象
適合對大型語言模型代理（LLM agents）、工具使用後訓練、代理自我演化與自動化工作流程有興趣的研究者與工程師，特別是關注如何透過全系統設計與穩定後訓練來提升通用型代理效能的讀者。

## 深度分析

#### 方法論解析

WEFT（Whole-system Evolution For Tool-use Post-training，工具使用後訓練的全系統演化）將過去僅聚焦於 executable environments（可執行環境）的規模化視角，擴展到完整的 agentic interaction system（代理互動系統）。該系統包含四個核心元件：environment（環境）、task（任務）、agent harness（代理測試架）與 evaluator（評估器）。WEFT 認為，單獨擴展 environment 無法保證可靠的 learning signals（學習訊號），因為任務失敗可能源於 faulty tool implementations（有缺陷的工具實作）、infeasible tasks（不可行任務）或 verification errors（驗證錯誤），而非單純是 policy（策略）能力不足。因此，WEFT 透過三大支柱進行端到端後訓練：**可規模化的 agentic interaction system 建構**、**執行驅動自我演化（execution-driven self-evolution）** 與 **穩定的 post-training（後訓練）**。

##### 1. 可規模化的 agentic interaction system 建構

WEFT 同時在三個維度進行擴展：

- **Environment breadth（環境廣度）**：透過 stateful environment synthesis（有狀態環境合成）與 programmatic synthesis（程式化合成），擴充可用工具與場景的覆蓋範圍。
- **Task complexity（任務複雜度）**：採用 verifiable cross-tool task composition（可驗證跨工具任務組合），將經過執行驗證的 atomic tasks（原子任務）透過 dependencies（依賴關係）、entity bindings（實體綁定）與 grounded initial state（具體初始狀態）串連成共享長期目標的複雜任務。
- **Interaction diversity（互動多樣性）**：針對同一 grounded task，設計多種 task-disclosure settings（任務揭露設定）與 native agent harnesses（原生代理測試架），使模型能接觸不同格式的指令與互動介面，降低對單一提示形式的過度擬合。

這種「全系統」規模化不同於僅生成大量環境的做法，它強調 environment、task、harness 與 evaluator 之間的 coherence（一致性），確保產生的 interaction trajectories（互動軌跡）具備訓練價值。

##### 2. 執行驅動自我演化（execution-driven self-evolution）

這是 WEFT 的核心創新。傳統 pipeline 在收集 rollout（推演）軌跡後，通常直接將失敗歸因於 policy 並進行 SFT（Supervised Fine-Tuning，監督式微調）或 RL（Reinforcement Learning，強化學習）。WEFT 則在每次 rollout 後，利用 execution traces（執行軌跡）與 state evidence（狀態證據）進行 failure attribution（失敗歸因），區分以下幾類失敗：

- **Policy failures（策略失敗）**：模型在 valid tasks（有效任務）上採取了錯誤行動。
- **Environment issues**：工具實作或環境狀態有誤。
- **Task issues**：任務本身 infeasible（不可行）或目標定義不清。
- **Verifier issues（驗證器問題）**：evaluator 錯誤地懲罰了 valid behavior（有效行為）。

根據歸因結果，WEFT 對相應元件進行 targeted component revisions（針對性元件修正），例如修復工具實作、重寫任務描述、調整 verifier 邏輯等。接著透過 fresh rollouts（全新 rollout）評估修正效果，並發掘新的問題，形成迭代閉環。這種機制能持續提升 learning signals 的 reliability（可靠性），避免將非模型錯誤的懲罰訊號餵入 policy learning（策略學習）。

##### 3. 穩定的 post-training

為了在大規模 rollout 下維持訓練穩定，WEFT 在演算法與系統層面同步設計：

- **Prefix-preserving rejection sampling（保留前綴採樣）**：在軌跡篩選時保留已驗證的 verified progress（已驗證的進展），僅對失敗的 atomic turn（原子回合）重新採樣。這樣可以高效建構高品質 SFT 資料，避免丟棄整條長軌跡。
- **Task filtering for RL**：在 reinforcement learning 階段，先評估 verifier reliability（驗證器可靠性），篩選出適合訓練的任務，降低錯誤獎勵訊號。
- **Atomic-turn credit assignment（原子回合功勞分配）**：將學習訊號細化到單一回合層級，使模型能更精準地理解哪一步行動導致成功或失敗。
- **MegaMCP**：為了解決並行 rollout 時重複部署 MCP（Model Context Protocol）服務的問題，MegaMCP 讓多個 rollout 共享 shared tool services（共享工具服務），同時為每個 rollout 維持 isolated, recoverable state（隔離且可復原的狀態）。透過 snapshot（快照）機制，支援 retries（重試）與 candidate sampling（候選採樣）從相同狀態出發，提升 execution reliability（執行可靠性）與運算效率。

整體而言，WEFT 的方法論是一個「建構 → 執行 → 歸因 → 修正 → 再執行」的閉環，並透過穩定的訓練技術將高品質軌跡轉化為模型能力。

#### 實驗數據解讀

WEFT 的實驗涵蓋多個模型規模與五項 benchmarks（基準測試），分別檢驗工具呼叫、多輪互動與長期工作流程執行能力。

##### 主要結果

- **WEFT-8B 與 WEFT-14B**：在 BFCL V4、τ²-Bench（τ²-Bench）與 Claw-Eval 的 aggregate scores（總分）上，均優於所有相同規模的 matched-size environment-scaling baselines（相同規模的環境擴展基線）。
- **WEFT-14B 相較於 Agent-World-14B**：在 BFCL V4 提升 **6.41 percentage points（百分點）**、在 τ²-Bench 提升 **2.23 percentage points**、在 Claw-Eval 提升 **12.27 percentage points**。這顯示單純擴展 environment 的 baseline 難以與全系統演化的 WEFT 抗衡。
- **WEFT-35B-A3B**：在更具挑戰性的 long-horizon workflow benchmarks（長期工作流程基準測試）上取得 **45.99%** 的 Toolathlon-Verified 分數與 **26.50%** 的 AutomationBench 分數，顯示方法可擴展到更大模型與更複雜任務。

##### 控制實驗：自我演化的價值

在固定 task set（任務集）與 rollout budget（推演預算）的情況下，進行三輪 self-evolution（自我演化）後：

- 所選訓練軌跡中的 tool-call error rate（工具呼叫錯誤率）相較於初始建構降低 **45.5%**。
- 三項 downstream benchmark scores（下游基準測試分數）提升 **3.65–5.25 percentage points**。

這項結果強有力地證明：即便不增加資料量，單靠改善 agentic interaction system 的品質，就能顯著提升 policy learning 的效果。這也呼應了本文的核心論點——**可靠的 learning signals 比單純的資料規模更重要**。

##### 消融實驗與系統實驗

- **Diverse task-disclosure views 與 agent harnesses**：實驗顯示增加任務揭露視角與測試架多樣性可帶來效能增益，說明 interaction diversity 有助於提升泛化能力。
- **Prefix-preserving rejection sampling**：相較於完全重新生成整條軌跡，保留前綴的採樣方式能更有效利用已驗證進展，提升訓練資料品質。
- **Atomic-turn credit assignment**：細粒度的功勞分配對 RL 階段有正面影響，使模型更能定位關鍵行動。
- **MegaMCP**：系統層面實驗顯示 MegaMCP 能減少 concurrent rollouts 時的 data transfer（資料傳輸）、memory use（記憶體使用）與 cold-start latency（冷啟動延遲），對大規模 post-training 的執行效率至關重要。

##### 數據意涵

整體實驗設計從「小模型、標準工具呼叫」到「大模型、長期工作流程」形成完整光譜。WEFT 不僅在傳統 tool-use benchmarks 上勝出，更在需要多步驟狀態追蹤的長期任務上展現優勢，說明其全系統演化機制確實能產生更高品質的訓練訊號。然而，值得注意的是，WEFT-35B-A3B 在 AutomationBench 上僅達 26.50%，顯示長期工作流程領域仍有極大進步空間，也暗示這類任務的 verifier 與環境穩定性仍是瓶頸。

#### 與現有研究的比較

##### 定位

WEFT 屬於 tool-use post-training 領域，與近年強調 environment scaling 的研究（如 Agent-World、Song et al., 2026b；Tu et al., 2026；Wang et al., 2026）處於同一脈絡，但將焦點從「環境擴展」轉向「全系統品質提升」。相關研究可大致分為三類：

1. **Environment 與 task scaling**：如 Hu et al., 2025a；Sullivan et al., 2025；Shi et al., 2026a 等，著重於自動化生成環境與任務。WEFT 與其差異在於強調 cross-tool task composition 與 execution-verified 的任務鏈結。
2. **Agent interaction 與 rollout systems**：如 Wang et al., 2025a；de Chezelles et al., 2025；Yao et al., 2026 等，探討 harness 設計與執行框架。WEFT 進一步將 harness 與 task disclosure 納入規模化維度，並提出 MegaMCP 解決並行狀態隔離問題。
3. **Self-improvement**：如 Madaan et al., 2023；Shinn et al., 2023；Wang et al., 2024 等，多聚焦於模型輸出或行為的自我改進。WEFT 則將 self-evolution 應用於整個 agentic interaction system，包括 environment、task 與 verifier，而非僅修正 policy。

##### 相較於既有研究的改進

- **從 environment scaling 到 whole-system scaling**：過去研究主要擴展 executable environments，但 WEFT 證明這不足以保證模型進步。透過同時優化 task、harness 與 evaluator，WEFT 能產生更可靠的訓練訊號。
- **Failure attribution 的系統化**：過去雖有研究指出 verifier 錯誤會造成 misleading learning signals（Cai et al., 2025a；Xu et al., 2026b），但 WEFT 提出具體的執行驅動歸因流程，並將其整合進自我演化迴路。
- **訓練穩定性機制**：prefix-preserving rejection sampling 與 atomic-turn credit assignment 是針對長期工具使用任務設計的演算法創新，能處理長軌跡中部分成功、部分失敗的複雜情況。
- **基礎設施創新**：MegaMCP 解決了 MCP 服務在並行 rollout 下的狀態隔離與復原問題，這是過往 rollout systems 較少觸及的工程挑戰。

##### 限制

儘管 WEFT 表現突出，仍有以下潛在限制：

- **模型家族侷限**：實驗僅基於 Qwen3-8B、Qwen3-14B 與 Qwen3.5-35B-A3B，尚未驗證於其他架構（如 Llama、Gemini 或 GPT 系列），因此難以斷言方法對所有模型均同等有效。
- **自我演化的歸因準確性**：failure attribution 依賴於 state evidence 與 verifier 設計。若歸因邏輯本身存在偏差，可能導致錯誤修正，甚至放大系統性錯誤。
- **運算成本**：三輪以上的 self-evolution 加上 MegaMCP 並行 rollout，雖提升效率，但整體訓練成本仍可能遠高於單純 environment scaling。
- **長期任務表現仍有瓶頸**：WEFT-35B-A3B 在 AutomationBench 僅 26.50%，顯示對於極長 horizon 的 workflow，現有 verifier 與環境穩定性仍不足以支撐高成功率。
- **任務合成的可解釋性**：大規模 programmatic synthesis 產生的任務可能缺乏人類可讀性，難以進行細緻的品質檢視。

- **程式碼（Code）**：WEFT 涉及複雜的 agentic interaction system 建構、MegaMCP 基礎設施與 self-evolution pipeline，若無開源實作，其他研究者難以精確復現其流程。
- **資料集（Datasets）**：訓練所用的合成環境、任務與軌跡若未釋出，則無法直接比較或延伸研究。
- **模型權重（Model Weights）**：WEFT-8B、WEFT-14B 與 WEFT-35B-A3B 的釋出狀態未在摘要與引言中說明。若未公開，社群將難以驗證其泛化能力或進行下游應用。

若作者後續能釋出以下項目，將大幅提升可重現性與影響力：

1. WEFT 的完整訓練 pipeline 程式碼，包含 environment synthesis、task composition、self-evolution loop 與 MegaMCP 實作。
2. 訓練所使用的 environment、task 與 rollout 軌跡資料。
3. 微調後的模型權重與推論程式碼。
4. 詳細的超參數設定、硬體配置與訓練時間，便於其他研究者估算成本與復現結果。

在缺乏上述資源的情況下，WEFT 的可重現性評估為**中等偏低**：方法論描述詳盡，但實作細節與資料未公開，仍屬於「概念可理解、實作難復現」的階段。

#### 未來研究方向

WEFT 開啟了多個值得後續探索的研究方向：

1. **跨模型家族的驗證與遷移**：將 WEFT 應用於 Llama、Gemini、GPT 等不同架構，檢驗其是否為通用方法，並探討模型初始能力對 self-evolution 效果的影響。
2. **更強大的 failure attribution 機制**：引入形式化驗證（formal verification）或對比執行（contrastive execution）來提升歸因準確性，降低錯誤修正的風險。
3. **線上自我演化（online self-evolution）**：將 WEFT 的演化迴路從訓練階段延伸至部署階段，使代理能根據真實世界回饋持續修正環境理解與工具使用策略。
4. **多模態工具使用（multimodal tool-use）**：擴展 WEFT 至視覺、音訊或具身機器人工具，處理更豐富的 state evidence 與感知訊號。
5. **與 RL 更深度的整合**：目前 WEFT 已使用 atomic-turn credit assignment，但未來可探索更細緻的 reward shaping（獎勵塑形）或 offline-to-online RL 轉換，以進一步提升長期任務表現。
6. **動態難度調整（dynamic difficulty adjustment）**：根據模型當前能力自動調整 task complexity，使訓練過程更接近 curriculum learning（課程學習）。
7. **人機協作驗證（human-in-the-loop verification）**：對於高風險或高度複雜的任務，引入人類審核來解決 verifier 無法判斷的邊界案例。
8. **開放式評估基準**：建立能夠持續接收新環境與新任務的動態 benchmark，以評估代理在真實世界中的 lifelong learning（終身學習）能力。
9. **安全性與對齊（safety and alignment）**：當代理能自我演化並修改環境與任務時，如何防止其學到有害或欺騙 verifier 的策略，將是重要的研究議題。
10. **知識蒸餾與輕量化**：將 WEFT-35B-A3B 等大型模型的能力蒸餾至更小模型，使通用型代理能在資源受限環境中部署。

總結來說，WEFT 不僅提出了一個強大的 tool-use post-training 框架，更重新定義了「規模化」的內涵：未來的進步將不僅來自於更多環境，而是來自於更可靠、更一致、更能自我修正的 agentic interaction system。

## 論文問答

**Q1：WEFT 旨在解決工具使用後訓練中的什麼核心問題？**
A：WEFT 主要解決「僅擴展可執行環境無法保證模型效能提升」的核心問題。在工具使用後訓練中，可靠的學習訊號來自於代理互動系統各個元件——包括環境、任務、代理測試架與評估器——之間的協調互動，而非單靠環境規模化。當任務不可行、工具實作有缺陷，或驗證器判斷錯誤時，模型可能因正確行為被懲罰，進而產生誤導性學習訊號，損害策略學習。

**Q2：為何現有的環境擴展方法難以帶來相應的效能增益？**
A：現有方法多半只聚焦於程式化合成可執行環境，卻忽略了代理互動系統中的其他關鍵元件。即使環境本身設計良好，也無法確保任務可行、代理測試架合適，或評估器能正確判斷結果。因此，訓練資料中可能充斥著歸因錯誤的失敗案例，導致模型被錯誤地懲罰，反而損害策略學習而非強化正確行為。

**Q3：全系統規模化對工具使用後訓練為何重要？**
A：全系統規模化之所以重要，是因為訓練經驗源於環境、任務、代理測試架與評估器之間的動態互動。只要任一元件存在缺陷，學習訊號就會變得不可靠，導致模型學到錯誤行為或對有效動作產生畏縮。WEFT 透過同時改進所有元件，確保失敗能被正確歸因，並讓模型獲得穩定且可信的監督訊號。

**Q4：WEFT 提出的核心方法是什麼？**
A：WEFT 提出了一個端到端框架，整合可擴展的代理互動系統建構、執行驅動自我演化，以及穩定的後訓練流程。該方法同時擴展環境廣度、任務複雜度與互動多樣性，並利用執行軌跡與狀態證據來歸因失敗、修正問題元件。隨後透過全新 rollout 評估修正成效，並為下一輪演化提供進一步證據，形成持續改進的迴路。

**Q5：WEFT 的關鍵創新有哪些？**
A：WEFT 的關鍵創新在於將規模化範圍從可執行環境擴展到完整的代理互動系統，並引入執行驅動自我演化機制。此機制利用真實執行回饋來持續提升系統可靠性，區分策略失敗與系統元件問題。此外，WEFT 在演算法與基礎設施層面提出保留前綴採樣、原子回合功勞分配，以及 MegaMCP 並行 rollout 狀態隔離等設計，確保大規模後訓練的穩定性。

**Q6：WEFT 在穩定後訓練方面做了哪些重要設計選擇？**
A：為了提升最佳化可靠性，WEFT 採用保留前綴採樣，保留已驗證的進展，僅對失敗的原子任務重新採樣，避免從頭開始浪費運算。在強化學習階段，則透過原子回合功勞分配將學習訊號定位到更細微的回合層級，使模型能更精確地學習。在執行基礎設施方面，MegaMCP 讓多個並行 rollout 能共享工具服務，同時維持資料庫與工作空間狀態的隔離與可復原性。

**Q7：WEFT 使用了哪些基準測試進行評估？**
A：WEFT 在五個涵蓋工具呼叫、多輪互動與長期任務執行的基準測試上進行評估，包括 BFCL V4、τ²-Bench、Claw-Eval、Toolathlon-Verified 與 AutomationBench。這些測試從單一函式呼叫到複雜多步驟工作流程，涵蓋了工具使用能力的不同面向。實驗涵蓋 WEFT-8B、WEFT-14B 與 WEFT-35B-A3B 三種不同規模的模型，以驗證方法在不同容量下的有效性。

**Q8：WEFT 的關鍵實驗結果為何？**
A：WEFT-8B 與 WEFT-14B 在 BFCL V4、τ²-Bench 與 Claw-Eval 的綜合分數上，超越了所有相同規模的環境擴展基線模型。具體而言，WEFT-14B 相較於 Agent-World-14B 分別提升了 6.41、2.23 與 12.27 個百分點。WEFT-35B-A3B 更進一步將優勢延伸到更具挑戰性的長期工作流程基準，在 Toolathlon-Verified 達到 45.99%，在 AutomationBench 達到 26.50%。

**Q9：消融實驗揭示了哪些重要發現？**
A：在任務集與 rollout 預算固定的情況下，三輪自我演化使選定訓練軌跡中的工具呼叫錯誤率相較初始建構降低了 45.5%。同時，下游基準測試分數提升了 3.65 至 5.25 個百分點，顯示系統元件品質對模型表現有直接影響。其他消融實驗也顯示，多樣的任務揭露視角與代理測試架、保留前綴採樣，以及原子回合功勞分配，均對最終效能有顯著貢獻。

**Q10：WEFT 可應用於哪些實務場景？**
A：WEFT 適用於建構能與多樣有狀態環境互動的通用型代理，例如資料庫、網頁服務、軟體工程工具與終端機環境。它特別適合需要複雜多步驟工作流程的場景，因為這類應用對任務可行性與正確評估有高度要求。其全系統方法使其可應用於企業流程自動化、個人助理與自主軟體代理等領域，提升代理在真實世界工具鏈中的可靠性。

**Q11：部署 WEFT 時需要考慮哪些產品化因素？**
A：部署 WEFT 時，必須確保共享工具服務在並行 rollout 下不會發生狀態污染，而 MegaMCP 透過狀態隔離與快照機制解決了這個問題。產品團隊也應持續監控驗證器與任務的可靠性，因為執行驅動自我演化仰賴正確的失敗歸因才能產生有效修正。此外，多輪自我演化與大規模 rollout 所帶來的運算成本與延遲，也應納入生產管線的規劃考量。

**Q12：WEFT 可能對工具使用代理研究領域帶來什麼影響？**
A：WEFT 將研究焦點從單純的環境擴展轉向全系統演化，促使學界同時重視任務、測試架與評估器的品質。其執行驅動自我演化範式提供了一種有原則的方法，可反覆提升訓練資料的可靠性，而非僅僅增加資料量。此框架也可能啟發新的基礎設施設計，以支援可擴展、有狀態的代理訓練，推動通用型代理的實用化。

**Q13：WEFT 有哪些可能的限制？**
A：WEFT 的成效取決於初始代理互動系統各元件的品質與覆蓋範圍，若初始建構不足，自我演化的改善空間也會受限。自我演化需要大量運算資源進行重複 rollout 與元件修正，對於資源有限的研究團隊可能構成門檻。此外，當多個元件以複雜方式交互作用時，失敗歸因仍可能面臨挑戰，需要更精細的診斷機制。

**Q14：WEFT 在哪些失敗案例中可能表現不佳？**
A：當失敗無法清楚歸因於單一元件時，例如環境缺陷與代理錯誤以微妙方式交互作用，WEFT 可能難以有效修正。對於需要超出所提供工具能力進行推理的任務，或無法自動驗證的評估器，WEFT 也可能遇到困難。此外，若初始任務分布存在偏差，自我演化過程可能會強化既有侷限而非突破它們，導致改進天花板。

**Q15：WEFT 未來有哪些有前景的研究方向？**
A：未來可將 WEFT 擴展到更多樣的領域，例如機器人、多代理協作與真實世界 API 生態系統，驗證其跨領域泛化能力。進一步提升失敗歸因與元件修正的自動化程度，可減少對人工監督的依賴，使自我演化更加高效。另一個方向是將 WEFT 與線上學習結合，使代理能在與新環境和任務互動的過程中持續演化，而非僅限於離線後訓練。

## 實務應用指南

## 適用場景

1. **企業級多工具自動化助理**  
   適合需要同時操作 CRM、ERP、郵件、行事曆與內部資料庫的場景，例如「查詢客戶紀錄 → 更新訂單狀態 → 發送確認信」。WEFT 透過擴展代理互動系統的環境廣度、任務複雜度與互動多樣性，能讓模型在真實有狀態環境中學會追蹤狀態變化並調整動作。

2. **長期工作流程執行平台**  
   適用於動輒數十個步驟的長期工作流程，如財務月結、供應鏈追蹤或 DevOps 管線。WEFT 的保留前綴採樣與 MegaMCP 隔離復原機制，可支撐高失敗率下的穩定後訓練與並行推演。

3. **工具呼叫品質驗證與持續迭代系統**  
   當現有模型頻繁因工具實作缺陷、不可行任務或驗證器錯誤而被誤判時，可導入 WEFT 的執行驅動自我演化，透過執行軌跡與狀態證據進行失敗歸因，針對性修正環境、任務、代理測試架或評估器。

4. **多租戶共享工具服務的代理訓練基礎設施**  
   適合需要在同一套共享工具服務上同時執行大量 rollout 的雲端平台，MegaMCP 能隔離各 rollout 的資料庫與工作空間狀態，並利用快照支援重試與候選採樣。

5. **垂直領域工具使用模型微調**  
   例如醫療、法律或製造業的專業工具鏈，可透過 WEFT 的可驗證跨工具任務組合與任務揭露設定，產生符合領域語意與執行邏輯的訓練資料。

## 實作前置條件

**資料條件**
- 可執行的有狀態環境與工具服務（建議以 MCP 或類似協定封裝）。
- 種子任務與對應的驗證器，能判斷任務是否完成。
- 真實或合成的執行軌跡，用於初始策略學習與後續失敗歸因。
- 領域文件或 API 規格，以支援任務揭露設定的多樣化。

**運算條件**
- 至少可執行 8B–14B 等級模型後訓練的 GPU 叢集（如 A100 / H100）。
- 並行 rollout 所需的容器或虛擬化資源，以承載 MegaMCP 的隔離狀態。
- 足夠的儲存空間保存快照、執行軌跡與中間狀態證據。

**技能條件**
- 熟悉 LLM 後訓練流程（SFT、RL）與工具使用評估基準測試。
- 具備將外部 API 封裝為可執行環境的能力。
- 能設計與維護驗證器，並依執行回饋進行除錯。
- 具備分散式系統經驗，以部署共享工具服務與狀態隔離機制。

## 實作步驟建議

1. **建構可執行的代理互動系統**  
   將目標工具封裝為 MCP 服務，並建立環境、任務、代理測試架與評估器四個元件。確保任務可驗證、狀態可觀察。

2. **產生多樣化任務與揭露視角**  
   利用程式化合成產生跨工具任務組合，並透過不同任務揭露設定與代理測試架，擴展互動多樣性。

3. **執行初始 rollout 並收集軌跡**  
   在隔離環境中執行大量 rollout，記錄執行軌跡、最終狀態與驗證結果，作為後續失敗歸因的狀態證據。

4. **執行驅動自我演化**  
   分析失敗案例，區分策略失敗、環境錯誤、不可行任務與驗證器問題。針對性修正對應元件後，重新執行全新 rollout 評估改善效果，反覆數輪。

5. **建構高品質 SFT 資料**  
   使用保留前綴採樣，保留已驗證的進展，僅對失敗的原子回合重新採樣，產生穩定的訓練軌跡。

6. **強化學習微調**  
   透過任務篩選挑選驗證器可靠的有效任務，並以原子回合功勞分配提供細粒度學習訊號，進行 RL 訓練。

7. **部署 MegaMCP 基礎設施**  
   在共享工具服務上為每個 rollout 建立隔離且可復原的狀態，利用快照支援重試與候選採樣，降低冷啟動延遲。

8. **持續監控與迭代**  
   上線後持續收集真實執行軌跡，定期重新執行自我演化循環，修正環境漂移與新任務類型。

## 潛在風險與注意事項

- **誤導性學習訊號**  
  若未做好失敗歸因，可能將環境或驗證器問題錯誤歸因於策略，導致模型學到無效行為。建議在每次訓練前執行任務篩選，並保留狀態證據供人工複查。

- **驗證器不可靠**  
  驗證器錯誤會直接污染訓練資料。應將驗證器視為系統元件之一，納入自我演化循環持續修正。

- **狀態隔離不足**  
  並行 rollout 若未妥善隔離，可能互相污染資料庫或工作空間狀態。MegaMCP 雖提供隔離機制，但仍需在部署時確認快照與復原邏輯正確。

- **運算成本膨脹**  
  自我演化與保留前綴採樣會產生大量 rollout。建議設定預算上限，並優先針對高影響力任務進行演化。

- **過度擬合訓練任務**  
  多樣化的任務揭露設定與代理測試架有助泛化，但仍需在 BFCL V4、τ²-Bench、Claw-Eval 等獨立基準測試上驗證。

## 與其他技術的整合建議

- **MCP 生態系**  
  直接將現有 MCP 工具服務掛載至 MegaMCP，無需重複部署。若工具服務本身無狀態，可透過資料庫與檔案系統快照補足隔離能力。

- **現有 LLM 訓練管線**  
  WEFT 的 SFT 與 RL 階段可銜接現有的 TRL、LLaMA-Factory 或自研訓練框架，只需將保留前綴採樣與原子回合功勞分配封裝為資料前處理與獎勵函式模組。

- **可觀測性平台**  
  將執行軌跡、狀態證據與失敗歸因結果匯出至追蹤系統（如 LangSmith、Langfuse），方便維運團隊介入審核。

- **企業知識庫與 RAG**  
  在任務合成階段引入領域知識庫，可提升跨工具任務組合的語意正確性；同時利用 WEFT 產生的軌跡反過來擴充知識庫案例。

- **CI/CD 與自動化測試**  
  將自我演化循環嵌入持續整合流程，每次工具或驗證器更新後自動執行一輪 rollout，確保學習訊號持續可靠。

**產品經理**
