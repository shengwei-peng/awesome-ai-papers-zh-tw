## 摘要翻譯

現有網頁代理程式（Web Agent）基準測試絕大多數衡量深度（Depth）——將單一隱晦答案（Obscure Answer）隱藏於約束鏈（Chain of Constraints）之後——而廣度（Breadth），即窮盡枚舉一封閉集合（Closed Set）並填寫每個項目之屬性（Attribute），則幾乎未被評估，尤以非英語語言為甚。廣度基準測試亦難以建構：確認黃金標準集合（Gold Set）之完整性及每個儲存格之正確性，成本遠高於檢查單一答案。本文提出 Ko-WideSearch，一個由自動化合成驗證管線（Synthesize-and-Verify Pipeline）建構之韓語廣度搜尋基準測試。每項任務指定一個集合母實體（Set-Parent Entity）——如電視季、王朝、聯盟、行政區、選舉——並要求列出其完整成員清單（Membership）以及一張逐項目屬性表（Per-Item Attribute Table），以項目 F1（Item-F1）、欄位 F1（Column-F1）與資料列 F1（Row-F1）評分。本基準涵蓋 228 張表格、橫跨 190 個實體（Entity）與十六個類別，分佈於三個難度層級（Difficulty Tier）；難度層級由兩個可獨立調節之結構旋鈕（Structural Knob）控制——表格寬度（Table Width）與二維複合鍵（2-D Composite Key）——使得交叉乘積成員涵蓋率（Cross-Product Membership）在各層級間從 0% 攀升至 100%。黃金標準建構（Gold Construction）與評分階段共用單一正規化感知比較器（Normalization-Aware Comparator），因此穩定之日期與計數欄位不會僅因格式設定（Formatting）而遭過度剔除。橫跨二十個網頁代理程式之測試顯示一致的失敗模式：代理程式能復原集合，但無法復原完整資料列（例如項目 F1 達 92.8，資料列 F1 僅 53.7）；隨著結構旋鈕調緊，準確率穩定下降，且無論增加搜尋量或開銷均無法彌合差距。細分至儲存格層級，困難之處在於找出正確數值，而非格式設定：開放式（Open-Ended）自由文字儲存格（Free-Text Cell）之失敗率最高，而具有標準答案（Standard Answer）之儲存格結果通常正確。

### 核心貢獻（3～5點）
- 提出首個韓語廣度搜尋基準測試 Ko-WideSearch，填補非英語語境下窮盡集合枚舉能力評估之空白。
- 設計自動化合成驗證管線（Synthesize-and-Verify Pipeline），以可擴展方式建構經驗證之黃金標準集合，降低廣度基準測試之建構成本。
- 透過表格寬度（Table Width）與二維複合鍵（2-D Composite Key）兩大結構旋鈕，系統性劃分三級難度層級，並以單一正規化感知比較器確保評分穩定。
- 發現網頁代理程式在廣度搜尋上之系統性瓶頸：能復原成員清單（高 Item-F1）卻難以正確填寫完整屬性資料列（低 Row-F1），且增加搜尋量與開銷無法彌合差距；自由文字儲存格為主要失敗來源。

### 適合對象
從事網頁代理程式（Web Agent）、資訊檢索、大語言模型評測與資料集建構之研究者，以及關注非英語語境下多語言代理系統廣度推理與窮盡枚舉能力之開發者與工程師。

## 深度分析

#### 方法論解析

Ko-WideSearch 的核心方法論在於將 breadth（廣度）評測形式化為一個可自動化建構、可精細校準難度，且能區分「集合召回」與「屬性組裝」兩類能力的基準測試框架。其設計可拆解為四個環節：評測指標的階層式設計、合成驗證管線（synthesize-and-verify pipeline）的三道閘門、雙軸難度調節機制，以及正規化感知比較器（normalization-aware comparator）的一致性約束。

首先，評測指標採用 Item-F1（項目 F1）、Column-F1（欄位 F1）與 Row-F1（資料列 F1）的三層階層。Item-F1 僅衡量 exhaustive set enumeration（窮盡集合枚舉）的完備性，即代理程式是否遺漏或虛構了 set-parent entity（集合母實體）下的成員；Column-F1 進一步檢視個別 attribute（屬性）欄位的正確率；Row-F1 則要求「成員識別」與「跨欄位屬性填寫」同時正確，才能計入單筆資料列。這種設計的深刻之處在於：它強迫研究者正視「找到所有拼圖碎片」與「把碎片正確拼成圖畫」是兩種截然不同的能力。實驗中 Item-F1 高達 92.8 而 Row-F1 僅 53.7，正是這套指標設計所揭露的結構性缺口。

其次，為了解決 gold construction（黃金標準建構）在 breadth 任務中的規模化瓶頸，作者設計了 synthesize-and-verify pipeline（合成驗證管線）。該管線由一個 build agent（建構代理程式）透過 exhaustive web search 窮舉網頁資訊，再經三道獨立閘門過濾：non-memorizability（避免模型記憶）、completeness（確認集合完備性），以及 cross-source attribute verification（跨來源屬性驗證）。這裡的關鍵洞察是：在 depth 基準中，驗證只需核對單一 obscure answer（隱晦答案）是否正確；但在 breadth 任務中，驗證者必須證明「沒有遺漏任何成員」且「每個儲存格皆正確」，成本遠高於前者。自動化管線以機器驗證取代手工標註，使資料規模從原始 WideSearch 的 200 張手工表格，擴展至 228 張表格、4,262 筆 gold rows（黃金標準資料列）與 14,560 個 attribute cells（屬性儲存格），且涵蓋 190 個 entities（實體）與 16 個類別。

第三，難度校準採用兩個可獨立調節的 structural knob（結構旋鈕）：table width（表格寬度）與 2-D composite key（二維複合鍵）。Table width 控制屬性欄位數量，從 Easy 的中位數 3 欄提升至 Hard 的 7 欄；2-D composite key 則控制 cross-product membership（交叉乘積成員涵蓋率），從 Easy 的 0%（單一成員清單）遞增至 Hard 的 100%（如 17 個行政區 × 2 屆選舉的完整交叉乘積）。這兩個旋鈕的獨立性讓研究者得以區分「屬性填寫負擔」與「組合成員列舉負擔」各自對代理程式的影響，而非將兩者混為一談。以 Government/HARD 為例，任務要求列出韓國所有廣域市道的首長，並以（province × round）作為 composite key（複合鍵），產生 34 列資料，且每列屬性（如當選人年齡）需從不同結果頁面 cross-source 查詢，這正是 WideSearch-grade hard breadth（WideSearch 等級的硬廣度）之體現。

最後，作者發現若採用 naive（樸素）的屬性交叉比對，stable date 與 count columns 會因 formatting（格式設定）差異而被過度剔除，導致 gold set（黃金標準集合）與模型輸出同時受損。因此設計了 normalization-aware comparator（正規化感知比較器），並將其共用於 gold construction 與 grading（評分）兩階段。這確保了「建構標準」與「評分標準」使用同一套語意比對規則，避免代理程式因日期格式（如「2025-01-01」與「2025年1月1日」）或數字格式差異而被誤判。此外，作者亦將 single-page 與 cross-source 的來源標記進行 web-grounded 處理，因為實驗顯示 LLM 對此類標記的猜測準確率僅約 72%，不足以支撐可信的 gold verification。

#### 實驗數據解讀

在 20 個 web agents（網頁代理程式）上的評測呈現出一致且深刻的失敗模式：代理程式普遍能夠 recover the set（召回集合），卻無法完成 the rows（組裝資料列）。具體而言，Item-F1（項目 F1）達到 92.8，代表九成以上的集合成員都能被找出；然而 Row-F1（資料列 F1）僅有 53.7，意味著一旦納入屬性填寫與跨欄位一致性要求，過半的資料列即告失效。這將近 40 個百分點的落差，揭示了當前 browsing agent（瀏覽代理程式）在「結構化組裝」上的系統性脆弱。

進一步觀察 difficulty tier（難度層級）的趨勢，準確率隨 structural knob（結構旋鈕）的收緊而穩定下降。無論是增加 table width（表格寬度）或引入 2-D composite key（二維複合鍵），都會對代理程式造成顯著壓力。更值得警惕的是，neither more search nor more spend closes the gap：單純增加搜尋次數或推理預算並無法彌補表現缺口。這暗示當前的失敗並非源於「資訊檢索不足」的淺層問題，而是根源於代理程式的內部狀態管理、長程記憶或結構化輸出機制。換句話說，給予更多 token（詞元）或更多瀏覽步數，並不能自動轉化為「維持 set boundary（集合邊界）並正確配對多維屬性」的能力。

細粒度（cell-level）的錯誤分解則指出：困難之處在於 finding the right value（找到正確值），而非 formatting it（格式化）。Open-ended free-text cell（開放式自由文字儲存格）的失敗率最高，相對地，具備 standard answer（標準答案）形式的儲存格——如日期或人名——通常能被正確填寫。這項發現具有重要的方法論意涵：若未來僅針對「格式正規化」進行後處理優化，對整體 Row-F1 的提升將極為有限；真正的瓶頸在於資訊抽取與事實查核本身。特別是在 cross-source 情境下，代理程式必須從不同網頁分別取得「誰當選」與「其年齡為何」，再將兩者對應至同一個 composite key（複合鍵）上。這種跨頁面、跨來源的屬性綁定，正是 open-ended 欄位錯誤叢聚之處。

此外，Column-F1（欄位 F1）的表現雖優於 Row-F1，但仍顯著低於 Item-F1，說明即便代理程式偶爾能正確填寫某些欄位，卻難以在同一筆資料列中維持多欄位同時正確。這種「欄位正確但列錯誤」的現象，指向了列層級的一致性（row-level consistency）問題：代理程式可能在不同時間點、不同頁面中抓取到彼此矛盾的資訊，卻缺乏足夠的機制進行衝突消解與一致性檢查。

#### 與現有研究的比較

Ko-WideSearch 在兩個軸向上與現有文獻形成鮮明對比：一是 depth（深度）與 breadth（廣度）的典範差異，二是自動化建構與手工標註的方法論差異。

在任務典範上，現有的 web-agent 基準測試——如 BrowseComp、BrowseComp-ZH（BrowseComp 中文版本）與 K-BrowseComp（BrowseComp 韓語版本）——幾乎清一色測量 depth。這類基準透過 chain of constraints（約束鏈）、multi-hop（多跳）或 parallel-constraint（並行約束）將單一 obscure answer（隱晦答案）隱藏在多層條件之後，評測的是代理程式「按圖索驥」的縱深檢索能力。相對地，Ko-WideSearch 與其前身 WideSearch 開創了 breadth 軸向：任務目標並非單一答案，而是 set-valued task（集合值任務），要求代理程式窮舉整個 closed set（封閉集合）並填寫 per-item attribute table（逐項目屬性表）。這兩種能力幾乎互不覆蓋：擅長在多層約束中挖掘單一答案的代理，未必具備在大量頁面間維持 exhaustiveness（完備性）與 set boundary（集合邊界）的能力。實驗中 Item-F1 與 Row-F1 的懸殊差距，正是這種能力脫鉤的實證。

在語言與文化覆蓋上，Ko-WideSearch 填補了非英語 breadth-search 評測的空白。雖然 K-BrowseComp 已將 depth 基準延伸至韓語，但 browsing ability（瀏覽能力）本質上具有 language-bound 與 culture-bound 特性：代理程式必須理解韓國入口網站的結構、術語與搜尋慣例（如 Naver 的知識百科與新聞版面配置），這些都無法透過英文能力的遷移自動獲得。Ko-WideSearch 以 228 張韓語表格、涵蓋選舉、體育、媒體、政府官員等 16 個類別，提供了首個大規模的韓語廣度搜尋評測場域。

在建構方法論上，原始 WideSearch 以手工方式建置約 200 張表格，annotation cost（標註成本）高昂，且難以擴展。Ko-WideSearch 的 synthesize-and-verify pipeline（合成驗證管線）則將建構流程自動化，並透過三道閘門確保 gold set（黃金標準集合）的可信度。這不僅提升了規模，更關鍵的是引入了 normalization-aware comparator（正規化感知比較器）來統一建構與評分標準——這在手工建置時代較少被系統性處理，因為人類標註者往往會「直覺地」忽略格式差異，而機器比對則需要顯式的正規化規則。

然而，Ko-WideSearch 亦存在可預見的限制。其任務設計僅涵蓋靜態的 closed set（封閉集合），例如已結束的選舉、已發行的專輯或已確認的行星；對於動態開放集合（如「2026 年 6 月當下韓國的低成本航空公司」），由於成員會隨時間變動，自動化管線的 completeness gate 難以給出確定性驗證。此外，目前的 2-D composite key（二維複合鍵）雖已能有效區分難度，但是否能無縫擴展至三維或更高維度的交叉乘積，仍有待後續研究驗證。

#### 可重現性評估

從方法論透明度來看，Ko-WideSearch 對於 synthesize-and-verify pipeline（合成驗證管線）的運作邏輯有相當清楚的描述：三道閘門（non-memorizability、completeness、cross-source attribute verification）的檢查目的、兩個 structural knob（結構旋鈕）的調節方式，以及 normalization-aware comparator（正規化感知比較器）的設計原則（保護 stable date/count columns 不因 formatting 差異被過度刪除）均有明確交代。Gold construction（黃金標準建構）與 grading（評分）共用同一 comparator 的設計，也大幅降低了因評分腳本與標準答案建構邏輯不一致而導致的 scoring bias（評分偏差）。

儘管如此，就提供的文本片段而言，論文並未明確提及原始碼（source code）、資料集下載連結或模型權重之公開釋出。對於一個高度依賴自動化管線與網頁內容的基準測試，這構成一定程度的再現性挑戰。具體而言，build agent（建構代理程式）的 exhaustive web search 行為細節（如使用的搜尋引擎、爬蟲策略、頁面解析規則）若未完整開源，其他研究者將難以完全複製出相同的 228 張 gold tables。

另一方面，該管線的設計本身具備良好的「方法論再現性」（methodological reproducibility）。由於難度由 table width（表格寬度）與 2-D composite key（二維複合鍵）兩個可量化的參數控制，研究者理論上可以在不同時間點或不同語言環境中，套用相同的閘門條件與旋鈕設定，重新合成一組結構等價的 benchmark。這種「參數化建構」的特性，使得 Ko-WideSearch 比傳統手工標註基準更容易在異地、異時複製其難度結構，即便表格內容因網頁更新而有所變動。

需要特別指出的是，web-grounded 資料本質上具有時效性。190 個 set-parent entities（集合母實體）的屬性資訊（如選舉結果、體育冠軍紀錄）雖屬歷史事實，但其所依附的網頁來源可能隨時間改版或失效。若 benchmark 未附帶網頁快照（web snapshot）或去識別化後的原始 HTML 特徵，長期的嚴格再現將面臨挑戰。建議後續版本能釋出網頁快取或至少提供來源 URL 與擷取時間戳記，以強化可重現性。

#### 未來研究方向

基於 Ko-WideSearch 所揭露的結構性缺口，未來研究可沿著五個方向深化：

第一，代理程式架構的結構化記憶設計。當前 Row-F1（資料列 F1）的低落，反映瀏覽代理程式缺乏顯式的 set boundary（集合邊界）追蹤機制。未來可探索引入外部結構化記憶體（如以關聯式表格或圖形資料庫作為 scratchpad（草稿板）），讓代理程式在跨頁面檢索時，能即時標記已完成的 composite key（複合鍵）配對與待填屬性，降低因上下文長度限制而遺漏或重複列舉的機率。

第二，開放式自由文字儲存格的抽取強化。實驗顯示 open-ended free-text cell（開放式自由文字儲存格）是錯誤重災區，而 standard answer（標準答案）欄位相對容易。這暗示未來可發展混合架構：對於日期、人名等結構化欄位沿用 LLM 生成，但對於開放式描述（如政策立場、作品風格）則輔以專屬的資訊抽取模型或檢索增強生成（Retrieval-Augmented Generation, RAG）管線，以提升事實正確性。

第三，多語言與跨文化遷移。Ko-WideSearch 的 synthesize-and-verify pipeline（合成驗證管線）理論上具備 language-agnostic（語言無關）潛力。將此管線遷移至 Traditional Chinese（繁體中文）、Japanese 或其他語言，不僅能驗證其泛化能力，更能揭露不同文化脈絡下的網頁結構差異（如臺灣的行政區劃、日本的選舉制度）如何影響 breadth-search 的難度分佈。

第四，動態與開放集合的廣度搜尋。目前僅評估靜態 closed set（封閉集合），未來可研究動態集合（如「現役低成本航空公司」或「本週音樂排行榜」）的即時窮舉與屬性更新。這需要結合網頁版本控制、快照比對或即時 API，以解決 web-grounded benchmark 的時效性問題，並將 completeness gate 擴展為機率式或時窗式的驗證邏輯。

第五，評測指標的再細緻化。除了現有的 Item-/Column-/Row-F1，可引入 partial credit（部分給分）機制，例如對於「成員正確但屬性部分錯誤」的資料列給予折抵分數；或針對 cross-source verification（跨來源驗證）設計專屬指標，區分「來源歸因錯誤」（選錯網頁）與「值提取錯誤」（讀錯數字）。這將使研究者更精準地定位代理程式的弱點所在。

## 論文問答

**Q1：現有網頁代理程式基準測試在評估廣度搜尋方面存在什麼樣的根本缺陷？**
A：現有基準測試絕大多數只衡量深度搜尋能力，也就是透過一連串約束條件來找出隱藏的單一答案，卻幾乎不評估廣度搜尋所需的窮盡集合枚舉能力。這種偏重深度的評測方式忽略了代理程式是否能完整列舉一個封閉集合的所有成員，並為每個項目填寫正確的屬性表格。尤其在英語以外的語言環境中，針對廣度搜尋的評估資源更是極度稀缺，導致該領域的發展受到限制。

**Q2：為什麼現有的深度搜尋基準測試無法有效檢驗網頁代理程式的廣度搜尋能力？**
A：深度搜尋任務只需要驗證單一答案的正確性，而廣度搜尋則要求代理程式同時恢復完整的成員集合並為每個成員填寫多項屬性，這兩者在驗證成本與能力需求上截然不同。現有基準如 BrowseComp 及其韓語版本 K-BrowseComp 僅要求代理程式在多跳或並行約束後找到單一短答案，並未測試代理程式跨多個頁面維持集合邊界與結構化資料完整性的能力。因此，即使是最先進的代理程式，在面對需要規模化與完備性的集合值任務時，仍然會出現遺漏資料列、錯填儲存格或失去集合邊界等問題。

**Q3：為什麼在韓語環境中建構廣度搜尋基準測試特別重要？**
A：網頁瀏覽能力具有獨特的語言與文化綁定性，代理程式必須能夠理解韓語來源的網頁結構、專業術語與搜尋慣例，這與英語環境的運作邏輯存在顯著差異。目前韓語的代理程式基準測試資源非常稀少，現有的 K-BrowseComp 仍屬於深度搜尋導向，無法評估代理程式處理韓語結構化集合的能力。建立 Ko-WideSearch 能夠填補這一評測缺口，為韓語網頁代理程式的廣度搜尋能力提供可信賴且可擴展的評估標準。

**Q4：Ko-WideSearch 的核心建構方法是什麼，它如何確保黃金標準資料的品質？**
A：本研究提出一套自動化的「合成驗證管線」，透過建構代理程式進行窮盡式網頁搜尋來產生每一張黃金標準表格，並設置三道獨立的驗證閘門來確保資料品質。這三道閘門分別檢驗表格的非記憶性、集合的完整性，以及跨來源屬性的正確性，從而避免人工標注在高成本下可能出現的遺漏或錯誤。這種自動化流程不僅大幅降低了建構廣度搜尋基準所需的人力成本，也讓大規模產出 228 張涵蓋 190 個實體的韓語表格成為可能。

**Q5：本研究提出的「正規化感知比較器」解決了什麼樣的關鍵問題？**
A：在廣度搜尋基準的建構與評分過程中，單純的屬性交叉比對會因為日期或數字等穩定欄位的格式差異而過度刪除正確答案，導致評分失真。作者設計了一個在建構黃金標準與評分模型輸出時共用的正規化感知比較器，能夠在比對前將資料格式標準化，避免因單純的格式設定不同而誤判正確儲存格。這項設計確保了評估結果的穩定性與公平性，使得代理程式的真實能力不會被表面的格式差異所掩蓋。

**Q6：Ko-WideSearch 如何透過結構設計來系統性地調控任務難度？**
A：作者設計了兩個可獨立調節的結構旋鈕：「表格寬度」與「二維複合鍵」，藉由這兩個參數的組合將任務劃分為簡單、中等與困難三個層級。表格寬度決定了代理程式需要填寫的屬性欄位數量，而二維複合鍵則控制集合成員是否由兩個維度的交叉乘積構成，其成員涵蓋率從簡單層級的 0% 逐漸提升至困難層級的 100%。這種設計讓研究者能夠精確地觀察代理程式在面對更多屬性欄位與更複雜的集合結構時，其表現如何系統性地下降。

**Q7：Ko-WideSearch 的規模與涵蓋範圍為何？**
A：該基準測試共包含 228 張表格，涵蓋 190 個集合母實體與 16 個類別，總計包含 4,262 筆黃金資料列與 14,560 個屬性儲存格。這些類別橫跨政府官員、體育賽事、媒體藝人、科學天體等多個領域，並且所有表格均來自網頁資料並經過去汙染處理。這樣的規模與多樣性使其成為目前韓語網頁代理程式廣度搜尋評估中最全面的資源之一。

**Q8：二十個網頁代理程式在 Ko-WideSearch 上的整體表現呈現什麼樣的規律性失敗？**
A：實驗結果顯示，代理程式在恢復集合成員方面表現相對較好，項目 F1 達到 92.8，但在完整資料列的正確性上卻大幅滑落至資料列 F1 僅 53.7，顯示它們能找回大部分成員卻無法正確填寫每個成員的所有屬性。隨著兩個結構旋鈕的難度增加，代理程式的準確率呈現穩定下降的趨勢，而且單純增加搜尋次數或花費更多運算資源並無法彌補這個差距。這項發現凸顯了廣度搜尋中「集合恢復」與「屬性完整填寫」之間存在顯著的能力斷層，是當前網頁代理程式尚未克服的核心挑戰。

**Q9：從儲存格層級的分析來看，代理程式在哪類屬性上最容易失敗？**
A：細部分析顯示，代理程式的困難之處在於找到正確的值，而非將其格式化，因為開放式的自由文字儲存格失敗率最高，而具有標準答案形式的日期或姓名欄位通常表現較好。這表示代理程式在處理需要綜合判斷或跨來源查證的開放式屬性時，其資訊整合與事實查核能力仍然不足。相對地，對於格式明確且易於驗證的標準答案類型，代理程式較能依賴網頁上的結構化資訊完成填寫。

**Q10：Ko-WideSearch 所評估的廣度搜尋能力在實際應用中有哪些具體場景？**
A：廣度搜尋能力在許多實務場景中至關重要，例如列舉韓國所有低成本航空公司的完整名單，並為每家業者查詢母公司、成立年份、主要樞紐機場與現有機隊數量等結構化屬性。類似的需求也存在於政府治理領域，如彙整特定選舉中所有行政區的當選人及其黨籍、得票率與年齡，或是在體育領域中整理聯盟每個球隊跨賽季的排名與主場資訊。這些任務都要求代理程式不僅能窮盡搜尋所有成員，還能跨頁面維持資料的一致性與完整性。

**Q11：在將廣度搜尋評估機制導入實際產品時，開發者應特別注意哪些設計考量？**
A：開發者在設計評分系統時，應採用類似本研究所提出的正規化感知比較器，避免因日期格式或數字呈現方式的細微差異而錯誤地排除正確答案，進而影響使用者體驗。此外，由於廣度搜尋涉及大量的集合成員與屬性欄位，產品必須建立有效的集合邊界追蹤機制，防止代理程式在長時間的多頁面瀏覽中遺漏資料列或重複計算。自動化的合成驗證管線也提供了一個可參考的範本，說明如何在不依賴昂貴人工標注的情況下，持續擴充與更新結構化知識庫。

**Q12：Ko-WideSearch 對網頁代理程式研究領域可能帶來什麼樣的影響？**
A：Ko-WideSearch 首次為韓語環境提供了大規模、可擴展且經過驗證的廣度搜尋基準，填補了過去僅聚焦深度搜尋的評測空白。它明確揭示了現有代理程式在集合枚舉與屬性填寫之間的能力落差，為未來的研究者指出了一個亟需強化的技術方向。透過提供結構化的難度分級與細粒度的評估指標，該基準將有助於推動更具完備性與跨語言適應性的下一代瀏覽代理程式之發展。

**Q13：作者在論文中承認了哪些建構過程上的限制？**
A：作者指出，廣度搜尋基準的建構本質上比深度搜尋更為困難且成本高昂，因為驗證一個集合是否完整以及每個儲存格是否正確，遠比檢查單一答案要耗費更多資源。雖然本研究透過自動化管線降低了成本，但在區分單一頁面來源與跨來源查證的標記上，即使使用大型語言模型進行判斷，準確率也僅約 72%，顯示來源歸因的自動化標記仍有改進空間。此外，原始 WideSearch 是以人工方式建構 200 張表格，凸顯了在缺乏自動化技術前，這類基準的規模化幾乎是不可行的。

**Q14：在困難層級的任務中，代理程式通常會出現什麼樣的具體失敗模式？**
A：在困難層級中，由於集合成員由二維複合鍵的交叉乘積構成，代理程式經常無法完整涵蓋所有組合，導致資料列遺漏或集合邊界模糊。即使代理程式成功識別了大部分成員，它們在填寫需要跨來源查證的屬性時，仍容易出現錯填或留空的情況，例如無法正確查找每位當選人的年齡或學歷。這些失敗模式顯示，當表格寬度增加且成員結構從簡單列表轉為網格狀複合集合時，代理程式的記憶體管理與多步驟規劃能力會面臨嚴峻挑戰。

**Q15：基於 Ko-WideSearch 的發現，未來研究可以朝哪些方向發展？**
A：未來研究可以針對代理程式在開放式自由文字儲存格上的弱點，開發更強大的跨來源資訊整合與事實驗證演算法，以縮小項目 F1 與資料列 F1 之間的差距。此外，將自動化合成驗證管線擴展至其他非英語語言，有助於建立更全面的多語言廣度搜尋評估生態系。另一個重要方向是改進代理程式的集合邊界感知能力，使其在長時間瀏覽多個網頁時，仍能有效追蹤已收集的成員與待填寫的屬性，從而提升結構化資料萃取的完備性與正確性。

## 實務應用指南

### 適用場景

1. **金融合規與供應鏈盡職調查**：當法規要求窮盡集合枚舉特定類別之所有交易對手（如某國籍之全數低成本航空公司、特定產業登記法人）並逐項填寫資本額、母公司、成立日期等屬性時，可採用本文之廣度搜尋框架，確保集合邊界無遺漏且逐項目屬性表完整。

2. **電商與旅遊平台之目錄完整性稽核**：平台需確認「某品牌全機型」「某航線所有可售艙等」等封閉集合的成員清單無缺漏，並比對每個 SKU 之規格、價格、庫存等欄位。透過項目 F1 與資料列 F1 監控，可量化爬蟲或 AI 代理程式之資料列遺失率。

3. **多語言企業知識庫與競品監測**：針對中文、韓文等非英語市場，建立「歷屆選舉結果」「聯賽冠軍紀錄」等結構化表格時，利用合成驗證管線自動產生黃金標準集合，解決人工標註成本高且難以驗證完備性之痛點。

4. **政府開放資料品質檢驗**：驗證官方公開之行政區首長、政府機關職位等資料是否構成完整交叉乘積（如每個行政區 × 每屆任期），並透過正規化感知比較器比對不同機關釋出之日期、計數格式，避免因格式設定差異而過度刪除正確資料。

5. **學術與醫療之系統性文獻屬性萃取**：在系統性回顧中，窮盡集合枚舉符合條件之所有試驗，並為每篇試驗萃取介入方式、樣本數、追蹤年期等屬性，利用二維複合鍵（如機構 × 試驗階段）管理難度遞增之表格寬度。

### 實作前置條件

- **資料**：需預先定義集合母實體清單（如電視季、王朝、聯盟、行政區、選舉）及其預期成員邊界規則；至少具備一個可驗證之權威來源（官方網站、統計資料庫）作為交叉驗證基礎；若為非英語場景，需準備在地化詞表與日期／數字格式慣例。
- **運算**：可呼叫網頁代理程式之大型語言模型 API 端點（建議具備工具使用與瀏覽能力）；足以執行分散式網頁檢索與表格合成之運算叢集；用於執行正規化感知比較器與三階段驗證閘道之額外推理預算。
- **技能**：團隊需具備提示工程與大型語言模型工具呼叫設計經驗、結構化資料正規化（特別是日期與數字）之處理能力、以及設計評估指標（項目 F1、欄位 F1、資料列 F1）之資料工程背景。

### 實作步驟建議

1. **定義結構旋鈕與難度層級**：先從表格寬度（三欄以下之列表任務）與單一成員鍵開始建立 EASY 原型，確認代理程式能穩定召回集合後，再逐步導入二維複合鍵（如省份 × 選舉屆次）與更多屬性欄位，將交叉乘積成員涵蓋率推升至 MEDIUM 與 HARD。

2. **建置合成驗證管線**：部署建構代理程式執行窮盡網頁搜尋，接著設置三道獨立驗證閘門——防記憶化檢查、完備性認證、跨來源屬性查核——確保黃金標準集合之可信度，避免人工標註瓶頸。

3. **統一正規化感知比較器**：在黃金標準建構階段與最終評分階段共用同一套比較器，針對日期、計數、人名等標準答案欄位預先定義正規化規則，防止代理程式輸出因格式設定差異（如「2025/06/01」與「2025-06-01」）而被錯誤降分。

4. **分階段監控與迭代**：上線後先追蹤項目 F1，確認集合邊界正確；再追蹤欄位 F1 識別哪些屬性欄位（尤其是開放式自由文字儲存格）最容易遺失；最終以資料列 F1 作為整體資料品質指標。若資料列 F1 顯著低於項目 F1，代表代理程式雖能找回成員，但無法完整填寫每列屬性，需加強跨頁面屬性檢索能力。

5. **產品化部署**：將驗證後之黃金表格寫入結構化資料庫，並設置定期重新整理排程，因為集合母實體之成員會隨時間變動（如新任首長、新賽季），需持續維護窮盡集合枚舉之時效性。

### 潛在風險與注意事項

- **格式過度刪除**：若未使用正規化感知比較器，穩定欄位（如日期、數字）容易因呈現格式不同而被誤判為錯誤，導致評分失真與資料列 F1 虛降。務必在比對前統一標準化處理。
- **集合邊界漂移**：網頁代理程式可能憑空生成不存在的成員，或遺漏冷門項目。建議在合成驗證管線中引入權威來源交叉驗證閘門，並以項目 F1 作為第一道防線。
- **跨來源屬性錯置**：當屬性需從不同頁面查找（如人名在主頁、年齡在個人檔案頁），代理程式容易張冠李戴。應在管線中明確標註單頁面來源與跨來源來源標籤，並驗證大型語言模型對來源分類之準確度（論文顯示僅約百分之七十二）。
- **自由文字儲存格失敗率偏高**：論文發現開放式自由文字儲存格最容易出錯，而標準答案（日期、人名）相對穩定。產品設計上應優先將屬性欄位標準化為列舉型或日期型，降低生成難度；若必須使用自由文字，需預留人工複審機制。
- **成本遞增**：隨著二維複合鍵與表格寬度增加，驗證每個儲存格正確性之成本遠高於檢查單一答案。建議依難度層級分攤運算預算，HARD 任務僅用於高價值場景。

### 與其他技術的整合建議

- **RAG（檢索增強生成）系統**：將廣度搜尋結果作為結構化檢索層，補強傳統 RAG 在集合完整性上的弱點。當用戶詢問「請列出所有符合條件之項目」時，先以窮盡集合枚舉確保無遺漏，再逐列生成摘要。
- **資料倉儲與 ETL 管線**：將合成驗證管線嵌入 ETL 之擷取階段，作為動態網頁資料來源之結構化萃取器。正規化感知比較器可直接作為資料品質閘道，確保載入倉儲前之日期與計數格式一致。
- **主資料管理（MDM）平台**：利用項目 F1／資料列 F1 作為實體完整性指標，自動偵測主資料紀錄之缺漏。例如比對 CRM 中客戶子公司清單與網頁代理程式窮舉之結果，觸發補全工作流程。
- **搜尋引擎與知識圖譜**：將逐項目屬性表轉換為知識圖譜之三元組（實體-關係-屬性），並以集合母實體為錨點，強化搜尋引擎對完整列表類查詢之結構化答案呈現。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦深度與廣度之差異——深度是像解謎般層層剝開約束鏈找到隱晦答案，廣度則是像編目般窮舉一整個封閉集合並填齊每個成員的屬性。接著理解項目 F1、欄位 F1、資料列 F1 三個指標如何從不同層面衡量一張表格的完整度，這將幫助你快速掌握為何「找回九家航空公司」卻「填不對它們的機隊數量」是兩回事。

- **AI 工程師**：重點研讀合成驗證管線的架構設計與正規化感知比較器的實作細節。論文的核心工程貢獻在於讓黃金標準建構與評分模型輸出共用同一套比對邏輯，這大幅降低了管線不一致的風險；同時注意兩個結構旋鈕（表格寬度與二維複合鍵）如何被獨立調節，這是你在設計可擴展難度之資料萃取系統時可直接複用的設計模式。

- **研究人員**：請關注廣度搜尋在非英語場景下的方法論缺口與本基準測試的設計哲學。論文揭示了一個被忽略的評測軸向——集合值任務的完備性——並提出自動化建構大規模黃金標準集合的可行路徑。建議深入分析二十款網頁代理程式在自由文字儲存格與標準答案儲存格上的失敗模式差異，這對未來設計更強大的瀏覽代理程式具有重要啟發。

- **產品經理**：請將閱讀重心放在適用場景與成本結構。廣度搜尋的價值在於解決資料完整性而非單點正確性的商業問題，但驗證成本隨集合大小與屬性欄位數量急遽上升。建議參考論文的三級難度層級設計產品上線策略：先以 EASY 列表任務驗證市場需求與資料品質，再逐步擴展至 MEDIUM 與 HARD 的網格任務，並預留足夠預算處理跨來源屬性查證與自由文字欄位的人工複審。
