## 摘要翻譯

大型語言模型（Large Language Model, LLM）與視覺語言模型（Vision-Language Model, VLM）通常在部署後即被凍結，因此無法從其解決的案例中學習。這在醫學領域尤其令人擔憂，因為新的臨床證據（Clinical Evidence）、更新的指引以及新的療法都可能改變既定的臨床實務（Clinical Practice）。微調（Fine-tuning）可以更新模型，但需要存取模型權重（Model Weights）並進行額外訓練。無參數方法（Parameter-free Method）可避免訓練，但它們可能會對固定的驗證集（Validation Set）產生過擬合（Overfitting）、缺乏可靠的領域知識（Domain Knowledge），或因僅以文字儲存經驗而遺失視覺細節（Visual Detail）。

為了解決這些限制，我們提出一個與模型無關的框架（Framework），使凍結的 LLM 與 VLM 能透過三種形式的外部專業知識（External Expertise）從部署經驗（Deployment Experience）中學習：技能（Skill）——引導推理（Reasoning）與工具使用（Tool Use）；知識記憶體（Knowledge Memory）——儲存由先前案例或可信外部證據（Trusted Evidence）所支持的可靠事實；以及多模態知識庫（Multimodal Knowledge Base, MMKB）——保存視覺範例，並引導模型將每個檢索案例（Retrieved Case）與當前影像（Image）建立關聯。

我們的驗證策略（Validation Strategy）不依賴固定的驗證集，而是僅在更新（Update）有助於新案例且不會降低先前案例效能（Performance）時才予以保留。在涵蓋臨床診斷（Clinical Diagnosis）、臨床工作流程（Clinical Workflow）、醫療推理（Medical Reasoning）以及醫療與非醫療視覺推理（Visual Reasoning）的六個基準測試（Benchmark）中，並以四個開放權重（Open-weight Model）與閉源（Closed-source Model）基礎模型（Base Model）進行評估，我們的框架在線上部署（Online Deployment）期間，於醫療任務上相較於基礎模型提升了最多 34.2% 的效能，能泛化（Generalization）至未見案例（Unseen Case）、無需進一步最佳化（Optimization）即可遷移（Transfer）至其他模型，並適用於非醫療領域（Non-medical Domain）。

### 核心貢獻（3～5點）
- 提出一個與模型無關的框架，使凍結的 LLM 與 VLM 無需重新訓練即可從部署經驗中持續學習，適用於閉源與開放權重模型。
- 設計三種形式的外部專業知識元件：技能（Skill）、知識記憶體（Knowledge Memory）與多模態知識庫（MMKB），分別負責引導推理與工具使用、儲存可靠事實，以及保留視覺範例以避免視覺細節流失。
- 提出不依賴固定驗證集的驗證策略，僅在更新有助於新案例且不損害先前案例效能時予以保留，有效緩解過擬合問題。
- 在六個涵蓋臨床診斷、臨床工作流程、醫療推理及視覺推理的基準測試中，於醫療任務上相較基礎模型提升最多 34.2% 的效能，並展現對未見案例的泛化能力與跨模型遷移能力。

### 適合對象
從事醫療人工智慧（Medical AI）、多模態學習、模型部署與持續學習研究的學者與工程師；關注閉源模型更新策略、臨床決策支援系統及大型語言模型／視覺語言模型實際應用的臨床資訊學研究者；以及希望了解如何在不存取模型權重的情況下提升模型表現的 AI 產品開發者與技術決策者。

## 深度分析

#### 方法論解析

本文提出一個**與模型無關的學習框架**（model-agnostic learning framework），其核心思想是讓**凍結模型**（frozen model）在部署過程中透過累積與更新**外部專業知識**（external expertise）來持續改進，而無需修改模型參數。整個方法論可從三個核心元件與一個驗證機制來理解。

**一、三大外部專業知識元件**

1. **技能（Skill）**：這是一份可重複使用的推理與**工具使用**（tool use）指引文件。系統會定期根據先前案例中哪些推理步驟或工具呼叫步驟獲得了高或低的**任務分數**（task score）來修訂技能內容。技能的本質類似於一份動態更新的「最佳實務手冊」，引導模型在面對新案例時採取更有效的推理路徑。

2. **知識記憶體（Knowledge Memory）**：儲存經由先前案例或**可信外部證據**（trusted external evidence）所支持的可靠**醫療事實**（medical fact）。這解決了純粹從**互動軌跡**（interaction trajectory）學習可能缺乏可靠**領域知識**（domain knowledge）的問題。知識記憶體中的每一條事實都附帶證據來源，可被追溯與驗證。

3. **多模態知識庫（MMKB, Multimodal Knowledge Base）**：這是本文最具創新性的元件。MMKB 保存先前的**視覺案例**（visual case），包括原始影像、來源答案與可用解釋。在推理時，系統會引導模型檢視每個檢索答案背後的證據，並將相關觀察與條件與當前案例進行比較。這避免了傳統方法（如 Reflexion、ExpeL、ACE）將經驗僅以文字形式儲存而遺失**視覺細節**（visual detail）的問題。

**二、聯合驗證策略（Validation Strategy）**

這是本文方法論中防止**過擬合**（overfitting）的關鍵設計。傳統的**無參數方法**（parameter-free method）如 EvoSkill 與 SkillOpt 使用固定的**驗證集**（validation set）來選擇更新，反覆在相同案例上最佳化會導致對該集合過擬合而無法**泛化**（generalization）到新案例。本文的策略改為：每個候選更新都必須同時在新案例與先前案例的代表性緩衝區上測試，只有當更新能幫助新案例且不損害先前案例表現時才被保留。這是一種「雙重保護」機制，確保所學到的專業知識既不過時也不過度特化。

**三、運作流程**

從圖 1 可看出，整個系統形成一個閉環：
- **推理階段**：模型載入技能、從知識記憶體檢索事實、從 MMKB 檢索相關視覺案例，綜合產生答案。
- **學習階段**：每完成一批案例後，系統根據執行軌跡與任務回饋產生候選更新，經聯合驗證後決定是否替換現有專業知識。
- **部署階段**：更新後的專業知識立即用於下一批案例，模型參數始終不變。

這種設計使得框架同時適用於**開放權重模型**（open-weight model）與**閉源模型**（closed-source model），因為它完全在模型外部運作。

#### 實驗數據解讀

**一、基準測試覆蓋面**

實驗在六個**基準測試**（benchmark）上進行，涵蓋四類任務：
- **臨床診斷**（clinical diagnosis）：互動式診斷場景
- **臨床工作流程**（clinical workflow）：模擬真實醫療流程
- **醫療推理**（medical reasoning）：純文字醫療推理
- **視覺推理**（visual reasoning）：包含醫療與非醫療影像

這種多面向的評估設計有助於驗證框架的**泛化能力**（generalization）——不僅限於單一任務類型。

**二、效能提升幅度**

最關鍵的數據是：在醫療任務上，框架相較於**基礎模型**（base model）帶來最高 **34.2%** 的**線上部署**（online deployment）效能提升。這個數字相當可觀，意味著在不改變模型參數的情況下，僅透過外部專業知識的累積，就能讓模型表現接近甚至超越經過微調的模型。

**三、模型相容性**

實驗使用了四個**基礎模型**（base model），包含開放權重與閉源模型。這顯示框架不依賴特定模型的內部結構或訓練機制，具有真正的「與模型無關」特性。

**四、遷移能力**

一個特別值得注意的結果是：用某個模型學到的專業知識可以**遷移**（transfer）到其他模型而無需進一步最佳化。這意味著當基礎模型更新（例如從 GPT-4 升級到 GPT-5）時，累積的專業知識可以無縫銜接，不需重新學習。這對實際部署具有重要意義。

**五、跨領域適用性**

框架在非醫療**視覺推理**（visual reasoning）任務上同樣有效，證明其設計並非僅針對醫療領域特化，而是具有更廣泛的適用性。

**六、實驗結果的深層意義**

這些數據共同說明：模型參數並非知識的唯一載體。透過精心設計的外部結構，**部署經驗**（deployment experience）可以轉化為可累積、可遷移的**外部專業知識**（external expertise），這對資源受限或無法微調的場景（如使用閉源 API）特別有價值。

#### 與現有研究的比較

**一、相較於 EvoSkill 與 SkillOpt**

這兩個方法同屬**無參數方法**（parameter-free method），透過生成候更新並在驗證集上選擇來改進技能文件。差異在於：
- EvoSkill/SkillOpt 使用**固定驗證集**（fixed validation set），容易過擬合
- 本文使用**聯合驗證策略**（joint validation strategy），同時測試新案例與歷史案例
- 本文額外引入**知識記憶體**（Knowledge Memory）與 **MMKB**，提供更全面的專業知識來源

**二、相較於 Reflexion、ExpeL、ACE**

這些方法將學習到的經驗以純文字形式儲存：
- 文字形式會遺失**視覺細節**（visual detail），對多模態任務特別不利
- 本文透過 **MMKB** 保留原始影像與視覺證據
- 本文還引入了帶證據來源的**知識記憶體**，比純反思文字更可靠

**三、相較於微調與強化學習方法**

基於**監督微調**（supervised fine-tuning）或**強化學習**（reinforcement learning）的方法（如 Chen et al., 2023; Yuan et al., 2025）：
- 需要存取**模型權重**（model weights），無法用於閉源模型
- 訓練成本高，且需大量可靠軌跡
- 每換一個基礎模型都需重新訓練
- 本文方法完全在模型外部運作，無上述限制

**四、相較於軟提示方法（Soft Prompting）**

Gare et al. (2026) 凍結 VLM 主幹僅訓練少量連續提示詞：
- 仍需梯度通過模型權重，僅適用於開放權重模型
- 本文方法完全不需訓練，適用範圍更廣

**五、本文方法的侷限性**

儘管優勢明顯，仍需注意：
- 外部專業知識的容量與檢索效率可能成為瓶頸
- 對於需要極精細視覺理解的任務，文字描述與影像之間的語意鴻溝仍可能存在
- 驗證策略的計算成本（需在新案例與歷史案例上反覆測試）在大規模部署時需考量
- 34.2% 的提升是「最高」值，平均提升幅度需參考完整實驗數據

#### 未來研究方向

**一、專業知識的動態剪枝與壓縮**

隨著部署時間增長，技能文件、知識記憶體與 MMKB 可能持續膨脹。如何在保留關鍵知識的同時壓縮儲存空間、維持檢索效率，是一個值得探索的方向。可以借鑑**向量量化**（vector quantization）或**重要性採樣**（importance sampling）技術。

**二、跨機構聯邦式專業知識共享**

在醫療場景中，不同醫院累積的專業知識具有互補性但又涉及**隱私**（privacy）問題。未來可探索**聯邦學習**（federated learning）式的專業知識共享，讓多家機構在不洩露原始資料的前提下共同豐富共享知識庫。

**三、主動學習與不確定性引導的案例收集**

目前的學習是被動的——模型處理所有案例。未來可引入**主動學習**（active learning）機制，讓模型主動標記不確定性高的案例，優先從中學習，提升學習效率。

**四、專業知識的可解釋性與審計**

在醫療等高風險領域，外部專業知識的決策依據需可追溯、可審計。未來可發展專門的視覺化工具，展示技能、知識記憶體與 MMKB 如何影響最終決策，增強臨床醫師對 AI 系統的信任。

**五、與基礎模型更新的協同機制**

當基礎模型更新時（例如從 GPT-4 升級到 GPT-5），現有專業知識可能部分過時或與新模型能力不匹配。未來可研究**知識蒸餾**（knowledge distillation）式的機制，將舊模型累積的專業知識轉換為新模型更易使用的形式。

**六、多語言與跨文化醫療知識**

目前的評估主要基於英文基準。醫療實務具有強烈的文化與地域特性，未來可將框架擴展至多語言場景，並研究如何整合不同地區的臨床指引差異。

**七、與其他推理增強技術的整合**

本文框架可與**思維鏈**（chain-of-thought）、**思維樹**（tree-of-thought）、**自我一致性**（self-consistency）等推理增強技術結合，探索更強的組合效果。特別是 MMKB 提供的視覺證據如何與這些推理結構互動，是一個開放問題。

**八、即時學習與邊緣部署**

對於需要在邊緣裝置（如醫療影像即時分析設備）上運行的場景，外部專業知識的存取延遲可能成為瓶頸。未來可研究輕量化的本地專業知識快取機制，兼顧隱私與效率。

## 論文問答

**Q1：為什麼「凍結模型無法從部署經驗中學習」這個問題在醫療領域特別嚴重？**
A：醫療領域的臨床證據、治療指引與新藥物會持續更新，已建立的臨床實務可能因此改變，但部署後的模型參數通常被凍結，無法自動吸收這些新資訊。當模型遇到一個新案例並產生錯誤時，若無法將這次經驗保存下來，下次遇到類似案例時就會重蹈覆轍。這在醫療場景中可能直接影響診斷正確性與病人安全，因此讓凍結模型具備從部署經驗中持續學習的能力，是醫療 AI 能否真正落地應用的關鍵問題。

**Q2：現有的「讓模型從經驗中學習」方法各自有哪些根本性的限制？**
A：基於微調或強化學習的方法需要存取模型權重，對閉源模型不可行，且訓練成本高昂、需仰賴大量可靠的互動軌跡，並須為每個基礎模型重新訓練。EvoSkill、SkillOpt 等無參數方法雖然避免重新訓練，但仰賴固定的驗證集來篩選技能文件更新，反覆在同一組案例上最佳化容易造成過擬合，難以泛化到未見過的新案例。此外，Reflexion、ExpeL、ACE 等方法僅將經驗以文字形式儲存，會遺漏對視覺醫療任務至關重要的影像細節。

**Q3：為什麼「模型無關（model-agnostic）」這個設計選擇在實務上如此重要？**
A：醫療機構在部署 AI 系統時，往往會同時使用多家廠商提供的閉源模型（如 GPT 系列）或自行託管的開放權重模型，若學習機制綁定特定模型權重，就必須為每個模型重複訓練與維護，成本極高且不切實際。一個真正模型無關的框架只需更新「外部專業知識」，就能讓不同基礎模型共享同一套累積經驗，大幅降低部署與更新的工程複雜度。這也使得當基礎模型升級或更換時，過去累積的寶貴臨床經驗不會因此作廢。

**Q4：本框架的核心方法是什麼？它如何讓凍結模型「學習」？**
A：本框架透過累積並更新三種「外部專業知識」來讓凍結的 LLM 與 VLM 持續進步：技能（Skill）提供可重複使用的推理與工具使用指引、知識記憶體（Knowledge Memory）儲存由先前案例或可信外部證據支持的可靠事實、多模態知識庫（MMKB）則保存先前的視覺案例與原始影像。模型參數在整個過程中保持不變，所有學習都發生在外部知識的更新上，因此適用於任何無法或不便微調的模型。

**Q5：本框架相較於既有方法最關鍵的創新是什麼？**
A：最關鍵的創新在於結合「持續更新的多模態外部專業知識」與「動態驗證策略」，前者解決了純文字經驗會遺失視覺細節的問題，後者則打破了固定驗證集導致過擬合的瓶頸。具體而言，MMKB 不只儲存影像，還引導模型檢視每個參考答案背後的證據，並將相關觀察與當前案例進行比較，使過去學到的視覺模式能真正用於新影像的推理。驗證策略則要求每次更新都必須同時在新案例與過去案例的代表性緩衝上表現良好，才能被保留。

**Q6：為什麼框架選擇「技能、知識記憶體、MMKB」三個元件，而非單一整合的記憶體？**
A：這三個元件各自對應醫療 AI 的不同需求：技能處理「如何推理與使用工具」的程序性知識、知識記憶體處理「可靠事實」的陳述性知識、MMKB 則處理「視覺模式」的感知性知識。將它們分開設計可以針對不同類型的經驗採用不同的更新與驗證策略，避免單一儲存結構被迫承載異質內容而降低效果。實驗結果也顯示，三者聯合使用時在視覺任務上能進一步提升效能，證明這種分工設計具有互補價值。

**Q7：本研究使用了哪些基準測試？它們如何涵蓋不同的醫療 AI 能力？**
A：研究採用了六個基準測試，涵蓋互動式臨床診斷、臨床工作流程、純文字醫療推理，以及醫療與非醫療的視覺推理等多種任務類型。這樣的設計不只測試模型在單一領域的表現，也驗證框架在不同推理模式（純文字 vs. 多模體）與不同領域（醫療 vs. 通用）下的泛用性。透過同時納入開放權重與閉源模型作為基礎模型，實驗也證實了框架的模型無關特性。

**Q8：本框架最令人印象深刻的主要實驗結果是什麼？**
A：在醫療任務上，框架相較於基礎模型可帶來最高 34.2% 的線上效能提升，這個幅度對於醫療 AI 應用而言相當可觀。更重要的是，學到的專業知識不只能泛化到未見過的新案例，還能「遷移」到其他模型而無需額外最佳化，顯示外部知識確實捕捉到了可重用的經驗而非模型特定的捷徑。此外，框架在非醫療視覺推理任務上同樣有效，證明其設計並非僅限於醫療場景。

**Q9：本框架進行了哪些消融研究來驗證各元件的貢獻？**
A：雖然全文未完整列出所有消融細節，但從方法描述可推論，框架分別驗證了技能、知識記憶體與 MMKB 單獨使用時的效果，以及三者聯合使用的整體表現。實驗特別強調「聯合使用」在視覺任務上能進一步提升效能，凸顯 MMKB 對視覺推理的關鍵貢獻。同時，動態驗證策略（在新案例與過去案例上同時測試）也被獨立驗證，以證明其相較於固定驗證集能避免過擬合並提升泛化能力。

**Q10：本框架在實際醫療場景中有哪些潛在應用？**
A：在臨床診斷支援系統中，框架可讓模型從真實病例的回饋中持續累積診斷程序與可靠的醫療事實，逐步提升對罕見或複雜病例的處理能力。在臨床工作流程自動化上，技能元件可學習並優化多步驟的推理與工具呼叫流程，使模型更貼近特定醫院或專科的工作慣例。對於醫學影像分析，MMKB 能保存具代表性的視覺案例，幫助模型在面對新影像時援引過去相似案例的視覺證據，提升診斷的可解釋性與可信度。

**Q11：若要將此框架產品化，需要考量哪些工程與倫理議題？**
A：工程上需要設計穩定的外部知識儲存與檢索機制、可靠的任務評分回饋管道，以及能處理大量視覺資料的 MMKB 基礎設施；同時還需考量如何在不同基礎模型間無縫切換而不中斷服務。倫理與法規上，醫療 AI 的決策依據必須可追溯，框架的「知識記憶體」與「MMKB」正好提供了事實與視覺證據的引用來源，有助於符合可解釋性與問責要求。此外，任何來自真實病例的學習都須經過去識別化與隱私保護程序，以符合 HIPAA 等醫療資料法規。

**Q12：本研究對醫療 AI 與整個 AI 領域可能產生哪些長遠影響？**
A：本研究證明了「凍結模型 + 外部專業知識」這條路徑在醫療 AI 上的可行性，挑戰了「必須微調才能讓模型進步」的傳統假設，為閉源模型在專業領域的持續優化開啟了新方向。「模型無關」與「跨領域遷移」的特性也意味著，未來醫療機構可以建立跨模型、跨任務共享的經驗庫，大幅提升 AI 投資的回報率。更廣泛地，這種「從部署經驗中學習」的範式可推廣到法律、金融、工程等知識同樣快速演進的專業領域。

**Q13：本框架有哪些已承認的限制？**
A：框架的效能高度仰賴任務評分的品質，若回饋訊號本身不可靠或帶有偏誤，學到的技能與知識也可能繼承這些錯誤。雖然動態驗證策略降低了過擬合風險，但若新案例與過去案例的分布差異過大，框架仍可能難以即時適應。此外，MMKB 的儲存與檢索成本會隨視覺案例累積而增加，在大規模長期部署時需要額外的工程優化。

**Q14：在哪些情境下本框架可能會失敗？**
A：當任務缺乏明確、可量化的評分回饋時（例如開放式病歷摘要或主觀性高的臨床判斷），框架難以判斷哪些技能更新值得保留，可能導致學習停滯。若基礎模型本身的視覺理解能力極為薄弱，即使有 MMKB 提供視覺參考，模型仍可能無法有效比對影像間的細微差異。在面對與過去案例分布截然不同的全新疾病或罕見症狀時，外部知識庫可能無法提供足夠的相關參考，框架的優勢會被削弱。

**Q15：本研究的未來發展方向有哪些？**
A：未來可探索更細粒度的知識組織方式，例如按專科、子任務或患者族群區分的專業知識庫，以提升檢索效率與相關性。另一個方向是結合主動學習，讓模型能識別自身不確定的案例並主動請求專家回饋，加速高品質經驗的累積。此外，將框架擴展到多語言與跨機構場景，使不同醫院能以保護隱私的方式共享經驗，也是值得探索的醫療 AI 協作模式。

## 實務應用指南

### 適用場景

1. **醫院臨床決策支援系統（CDSS）**：在急診或門診場域中，部署凍結的 VLM 透過 MMKB 累積過去影像案例（如胸部 X 光、CT 切片），結合 Knowledge Memory 收錄最新臨床指引，協助醫師在不改動底層模型的前提下，隨部署時間持續提升診斷一致性。

2. **遠距醫療與基層照護分流**：基層診所使用閉源 LLM（如 GPT 系列）進行症狀初步分流。透過 Skill 元件學習「何時該轉診、何時可觀察」的推理程序，並以 Knowledge Memory 儲存可信的在地流行病學資料，降低誤判風險。

3. **病理切片與細胞學影像分析**：病理科將已確診的珍貴案例（含 H&E 染色、免疫組織化學影像）存入 MMKB，讓 VLM 在面對新切片時能檢索視覺相似的歷史案例並比對差異，輔助判讀。

4. **醫學教育與個案討論平台**：教學醫院將住院醫師與 AI 的互動軌跡作為回饋來源，Skill 會自動演化出更清楚的推理步驟教學提示，Knowledge Memory 則收錄被指導教師標註為正確的臨床事實。

5. **跨機構模型遷移部署**：當醫院從 GPT-4o 換到 Claude 或自架開源模型時，過去累積的 Skill、Knowledge Memory 與 MMKB 可直接遷移，無需重新訓練或重新收集資料。

### 實作前置條件

**資料需求**
- 至少一批具備「問題—執行軌跡—任務分數」三元組的種子案例（建議 200–500 例），用於初始化 Skill 與 Knowledge Memory。
- 影像任務需準備具備「影像—來源答案—可取得解釋」的參考資料集，並建立影像與問題的聯合檢索索引（建議使用 CLIP 類視覺編碼器）。
- 可信外部證據來源：臨床指引 PDF、UpToDate 摘要、藥物資料庫等，需有可程式化擷取的介面。

**運算資源**
- 基礎模型推理資源：依所選 LLM/VLM 而定，閉源模型僅需 API 金鑰；開源模型（如 Qwen2-VL、InternVL）建議至少單張 A100/H100 等級 GPU。
- 檢索系統：向量資料庫（如 Milvus、Qdrant、pgvector）儲存文字與影像嵌入。
- 最佳化迴圈：每批次（batch）後需執行候選更新驗證，計算量約為一次完整推理的 1–3 倍。

**技能門檻**
- LLM/VLM API 串接與提示工程能力。
- 向量檢索與 RAG 系統建置經驗。
- 基本的臨床領域知識（用於設計任務分數與驗證閾值）。
- 對閉源模型無法微調的限制有正確認知，並熟悉無參數方法（parameter-free）的設計哲學。

### 實作步驟建議

1. **界定任務與評分機制**：先選定單一臨床任務（如「胸部 X 光異常偵測」），定義可量化的任務分數（與放射科醫師共識、診斷準確率等），這是後續驗證策略能否運作的基石。

2. **建立三元件的初始狀態**：
   - **Skill**：以基礎提示詞或既有最佳實務作為起點，記錄推理與工具使用的步驟模板。
   - **Knowledge Memory**：從可信外部證據（指引、教科書）抽取事實，建立「事實—證據來源」對照表。
   - **MMKB**：將參考資料集的影像、來源答案、解釋入庫，並建立影像+問題的聯合檢索函式。

3. **設計批次更新流程**：將部署流量切分為批次（建議每 50–100 例一批），每批結束後由「Optimizer」根據執行軌跡與任務分數產生候選更新（新的 Skill 段落、新的 Knowledge Memory 條目、MMKB 新增案例）。

4. **實作聯合驗證策略**：對每個候選更新，在「新案例」與「過去案例的代表性緩衝區」上同時測試，僅當新案例效能提升且過去案例效能不下降時才接受更新。這是避免過擬合固定驗證集的關鍵。

5. **線上部署與監控**：將三元件整合進推理管線（載入 Skill 指令 → 檢索 Knowledge Memory 與 MMKB → 產出答案），並持續記錄任務分數、案例難度分布、模型版本，作為日後遷移或回滾的依據。

6. **跨模型遷移測試**：當更換基礎模型時，直接載入既有 Skill、Knowledge Memory 與 MMKB，無需重新訓練；只需在新模型上做小規模驗證以確認相容性。

7. **擴展到非醫療領域**：同一框架可應用於工業瑕疵檢測、文件審核等視覺推理任務，僅需替換領域知識與評分標準。

### 潛在風險與注意事項

- **驗證集代表性偏差**：若「過去案例緩衝區」未能涵蓋任務的多樣性，聯合驗證可能誤接受有害更新。**緩解**：定期重抽緩衝區，並加入難度分層採樣。
- **Knowledge Memory 累積錯誤事實**：模型自生成的「事實」若未經可信來源驗證，可能污染記憶體。**緩解**：強制要求每條記憶附上證據來源，並由領域專家定期稽核。
- **MMKB 影像隱私與合規**：醫療影像涉及 PHI（受保護健康資訊），儲存與檢索需符合 HIPAA/GDPR。**緩解**：去識別化、加密儲存、存取稽核日誌。
- **Skill 過度膨脹**：隨部署時間增加，Skill 文件可能變得冗長，導致提示超出模型上下文窗口或稀釋關鍵指令。**緩解**：定期精簡、合併相似步驟、設定長度上限。
- **閉源模型版本變動**：API 提供商升級模型可能改變行為，使既有 Skill 失效。**緩解**：在版本變動時自動觸發小規模回測，必要時回滾 Skill。
- **任務分數設計不當**：若分數無法反映真實臨床價值，框架會朝錯誤方向最佳化。**緩解**：邀請臨床專家共同設計評分，並設置「安全閾值」阻止高風險任務的自動更新。
- **延遲與成本**：每例推理需額外檢索與驗證，可能增加回應時間與 API 成本。**緩解**：快取常見案例的檢索結果，並對高信心案例跳過深度驗證。

### 與其他技術的整合建議

- **與電子病歷系統（EMR/EHR）整合**：透過 FHIR 介面將結構化病歷資料餵入 Knowledge Memory，並將 AI 輸出回寫為臨床決建議紀錄。
- **與既有 RAG 系統共存**：本框架的 Knowledge Memory 可視為「可信子集」的 RAG，與一般文件檢索並行；MMKB 則補強視覺層次的 RAG。
- **與 Agent 框架（如 LangChain、AutoGen）整合**：Skill 本身即為 Agent 的系統提示與工具使用規範，可直接嵌入既有 Agent 流程。
- **與 MLOps/LLMOps 平台整合**：將三元件的版本化、驗證結果、部署狀態納入模型 registry（如 MLflow、Weights & Biases），便於審計與回滾。
- **與人類專家回饋迴圈整合**：將醫師的修正意見作為「高權重任務分數」來源，加速 Skill 與 Knowledge Memory 的演化。
- **與聯邦學習或去中心化部署整合**：在跨機構合作時，各機構可獨立累積 Skill/Knowledge Memory，再以加密方式共享彙總後的更新，兼顧隱私與知識流通。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解「為什麼凍結的模型還能變聰明」這個核心問題，再讀第 1 節的框架總覽與圖 1。三元件（Skill、Knowledge Memory、MMKB）的比喻可以想成「筆記本（程序）、維基百科（事實）、相簿（視覺案例）」，理解這個類比後再深入技術細節會比較順。

**給 AI 工程師**：重點放在第 2 節的相關工作比較與方法章節的驗證策略設計。特別注意「聯合驗證」如何避免過擬合固定驗證集，這是本框架相較 EvoSkill、SkillOpt 的關鍵差異。實作時可先以單一任務、單一模型做最小可行產品（MVP），再逐步擴展。

**給研究者**：本框架開啟了「無參數持續學習」在醫療 AI 的新方向，值得探索的方向包括：更嚴謹的驗證理論保證、Skill 與 Knowledge Memory 的形式化表示、跨語言與跨文化的醫療知識遷移、以及與聯邦學習結合的隱私保護機制。圖 1 的設計也提示了「外部專家知識」可作為模型自我修正的代理訊號。

**給產品經理**：本框架的最大商業價值在於「不需重新訓練即可持續改善」，這對採用閉源模型的醫療產品尤其關鍵——既避開了資料外洩與合規風險，又能隨時間累積領域專家知識。建議在產品 roadmap 中預留「部署經驗回饋」的設計位置，並將臨床專家的標註成本視為核心投資而非附屬功能。
