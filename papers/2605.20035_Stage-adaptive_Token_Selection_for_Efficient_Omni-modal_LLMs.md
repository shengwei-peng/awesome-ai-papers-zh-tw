# 針對高效全模態大型語言模型之階段自適應詞元選擇

**原文標題：** Stage-adaptive Token Selection for Efficient Omni-modal LLMs  
**作者：** Zijie Xin、Jie Yang、Ruixiang Zhao 等 7 位作者  
**發布日期：** 2026-05-19

## ⚡ TL;DR

現有全模態模型處理大量非文本詞元計算成本高昂，且固定比例剪枝無法反映跨模態重要性隨層數演變的問題。
提出免訓練的SEATS方法，依層級遞減保留比例並按查詢相關性動態分配視音詞元預算。
在Qwen-Omni上僅保留10%詞元，實現9.3倍運算縮減與4.8倍加速，維持96.3%效能。

## 摘要翻譯

全模態大型語言模型（omni-modal large language models, om-LLMs）透過將視訊與音訊編碼為在視窗層級（window level）上交錯的時間對齊的詞元序列（temporally aligned token sequences），實現統一的音視覺理解（audio-visual understanding）。然而，在整個 LLM 中處理這些密集的非文本詞元（non-textual tokens）會產生龐大的計算開銷。雖然免訓練詞元選擇（training-free token selection）可降低此成本，但現有方法若非僅聚焦於視覺輸入，便是僅於 LLM 前置階段以固定的逐模態比例（fixed per-modality ratios）剪枝 om-LLM 詞元，無法捕捉跨模態詞元重要性（cross-modal token importance）如何隨層次推移而變化。為解決此限制，我們首先分析 om-LLM 的逐層詞元依賴性（layer-wise token dependency）。我們發現視覺與音訊依賴性呈現區塊化模式（block-wise pattern），並隨深度逐漸減弱，顯示許多深層非文本詞元在跨模態融合（cross-modal fusion）後趨於冗餘。基於此觀察，我們提出 SEATS（階段自適應詞元選擇，StagE-Adaptive Token Selection），一種免訓練、階段自適應（stage-adaptive）的詞元選擇方法，以提升 om-LLM 的推論效率（inference efficiency）。於 LLM 前置階段，SEATS 透過注意力加權多樣性選擇（attention-weighted diversity selection）移除時空冗餘（spatiotemporal redundancy）。於 LLM 內部階段，它逐步於各區塊間剪枝詞元，並利用查詢相關性分數（query relevance scores），將保留預算（retention budget）從時間視窗（temporal windows）動態分配至各模態。於深層區塊，一旦跨模態融合完成，即移除所有剩餘的非文本詞元。於 Qwen2.5-Omni 與 Qwen3-Omni 上的實驗顯示，SEATS 有效提升推論效率。僅保留 10% 的視覺與音訊詞元，即可達成 9.3 倍的浮點運算次數（FLOPs）縮減與 4.8 倍的預填充加速（prefill speedup），同時維持 96.3% 的原始效能。

### 核心貢獻（3～5點）
- 揭示 om-LLM 的逐層詞元依賴性規律：視覺與音訊依賴性呈現區塊化模式，並隨網路深度逐漸減弱，深層非文本詞元在跨模態融合後具有高度冗餘性。
- 提出免訓練的階段自適應詞元選擇方法 SEATS，整合 LLM 前置與內部雙階段策略，依據推論階段動態調整詞元保留比例。
- 於 LLM 前置階段引入注意力加權多樣性選擇，有效移除視訊與音訊的時空冗餘。
- 於 LLM 內部階段依據查詢相關性分數，將保留預算從時間視窗動態分配至各模態，並於深層區塊完全移除剩餘非文本詞元。
- 於 Qwen2.5-Omni 與 Qwen3-Omni 上驗證，僅保留 10% 視覺與音訊詞元即可達成 9.3 倍浮點運算次數縮減與 4.8 倍預填充加速，同時維持 96.3% 原始效能。

### 適合對象
研究全模態大型語言模型、多模態推論加速、免訓練模型壓縮與詞元剪枝之研究者與工程師；需將 om-LLM 部署於資源受限環境（如邊緣裝置、即時音視覺應用）之開發者；以及對跨模態注意力機制、Transformer 層級依賴性分析與計算效率最佳化有興趣之學術讀者。

## 深度分析

#### 方法論解析

本文提出 SEATS（階段自適應詞元選擇，StagE-Adaptive Token Selection），一套針對全模態大型語言模型（omni-modal large language model, om-LLM）設計的免訓練（training-free）推論加速框架。其核心設計建立在作者對 om-LLM 逐層詞元依賴性（layer-wise token dependency）的觀察之上：視覺與音訊詞元的依賴呈現區塊化模式（block-wise pattern），隨著網路深度增加而逐漸減弱。淺層區塊（shallow blocks）強烈依賴非文本詞元（non-textual tokens）以完成跨模態融合（cross-modal fusion），中層區塊（middle blocks）依賴度逐步降低，而深層區塊（late blocks）在融合大致完成後幾乎不再需要視覺或音訊資訊。基於此洞察，SEATS 將詞元選擇（token selection）劃分為三個階段，分別對應不同的冗餘型態與選擇準則。

第一階段為 LLM 前置階段（pre-LLM stage）。在進入語言模型之前，影片幀與音軌已被編碼為時間對齊的詞元序列（temporally aligned token sequences），並以時間視窗（temporal windows）為單位交錯排列。此階段的冗餘主要來自時空冗餘（spatiotemporal redundancy），即相鄰幀或局部時段內的視覺與音訊資訊高度重複。SEATS 採用注意力加權多樣性選擇（attention-weighted diversity selection），在每個時間視窗內部保留具備多樣性且顯著的詞元，從而在不參考使用者查詢的前提下，先對輸入序列進行初步壓縮，縮短進入 LLM 前的序列長度（sequence length）。

第二階段為 LLM 內部階段（inner-LLM stage）。此階段的詞元已與文本查詢產生語義交互，因此選擇準則必須從「時空多樣性」轉為「查詢相關性」。SEATS 引入區塊化詞元保留比例（token-retention-ratio, TRR）遞減機制：隨著層數加深，模型對非文本詞元的依賴降低，因此 TRR 逐步下降，剪枝強度相應提升。這有別於傳統固定比例或僅在單一層進行一次性剪枝的做法。更具體地，SEATS 採用自上而下的雙層預算分配策略（top-down two-level allocation strategy）：第一層將保留預算（retention budget）分配給各個時間視窗，第二層再將各視窗的預算動態分配給視覺與音訊模態，而分配的依據是查詢相關性分數（query relevance scores）。這使得預算配置具備模態彈性（modality-flexible），能夠回應不同時間區段中視覺或音訊何者提供關鍵證據的動態變化，而非採用固定的逐模態比例（fixed per-modality ratios）。

第三階段為深層收尾階段。當模型進入後期層，跨模態融合已大致完成，剩餘的非文本詞元對最終推理的邊際貢獻極低。SEATS 在此直接移除所有剩餘的非文本詞元，使後續層僅處理文本詞元（text tokens）。這一步驟顯著降低了深層自注意力（self-attention）的計算與記憶體開銷（computation and memory overhead），因為序列長度在後期被大幅壓縮。

整體而言，SEATS 的設計體現了「階段自適應（stage-adaptive）」與「深度感知（depth-aware）」的雙重邏輯：前置階段處理時空冗餘，內部階段處理查詢相關性與模態動態，深層階段則果斷捨棄已融合的多模態資訊。三階段彼此銜接，形成從「多樣性過濾」到「相關性精簡」再到「完全移除」的連續光譜。

#### 實驗數據解讀

作者在兩個代表性的全模態模型上進行驗證：Qwen2.5-Omni-7B 與 Qwen3-Omni-30B，並於五個音視覺理解（audio-visual understanding）基準上進行測試。實驗結果圍繞效率與效能的權衡（efficiency-performance trade-off）展開，核心數據可從三個層次解讀。

首先，在極端壓縮情境下（僅保留 10% 的視覺與音訊詞元），SEATS 達到 9.3 倍的浮點運算次數（floating-point operations, FLOPs）縮減與 4.8 倍的預填充加速（prefill speedup），同時保留 96.3% 的原始效能。這組數據具有高度的實務意義：9.3 倍 FLOPs 降低代表計算複雜度（computational complexity）趨近於僅處理文本查詢的開銷；4.8 倍 prefill speedup 則直接反映在前向傳播（forward pass）階段的延遲改善，對於需要即時回應的互動式應用至關重要。而 96.3% 的效能保留率顯示，對於 om-LLM 而言，高達 90% 的非文本詞元在統計意義上屬於可替換或冗餘資訊，前提是剪枝策略必須精準對齊層級依賴性與查詢語義。

其次，在較為溫和的壓縮設定下（文中提及約 33% 的計算成本），Qwen2.5-Omni-7B 上的表現與使用全部詞元的原始模型相當。這暗示存在一個「甜蜜點」（sweet spot）：在此點之前，詞元移除幾乎不造成效能損失；超過此點後，效能才隨保留比例下降而顯著衰減。這種非線性衰減特性符合作者對「深層依賴性趨近於零」的觀察——只要保留足夠詞元供淺中層完成跨模態融合，深層的激進剪枝對最終輸出品質影響有限。

第三，從模型規模的角度觀察，實驗同時涵蓋 7B 與 30B 參數量級。這驗證了 SEATS 的免訓練特性在不同規模模型上皆具可遷移性，無需針對特定模型重新訓練或微調。然而，文中未詳細拆解視覺與音訊模態各自的保留比例對最終效能的獨立貢獻，也未呈現不同時間視窗長度對雙層預算分配策略的敏感度分析，這些是數據解讀中較為可惜之處。

#### 與現有研究的比較

SEATS 在現有詞元選擇（token selection）研究光譜中的定位，可透過表一的比較架構釐清。現有方法大致可依目標模態與執行階段分為三類：針對圖像大型語言模型（image-LLMs）的前置方法（pre-LLM methods）如 VisionZip、DivPrune、SCOPE，以及內部方法（inner-LLM methods）如 FastV、PyramidDrop（PDrop）、HiDrop；針對視訊大型語言模型（video-LLMs）的 FastVID、DyCoke、HoliTom、FlashVID、UniST；以及針對 om-LLM 的 OmniZip、EchoingPixels、OmniSIFT。

相較於 image-LLM 與 video-LLM 方法，SEATS 的根本差異在於處理對象為時間交錯的音視覺結構（temporally interleaved audio-visual structure）。多數 video-LLM 方法僅處理單一視覺模態（visual modality），即使將其平行套用於視覺與音訊流，也無法捕捉兩者在時間視窗層級的動態重要性變化。SEATS 的雙層預算分配機制正是為了解決此問題，使保留預算（retention budget）能夠跨模態流動。

在 om-LLM 領域中，現有的 OmniZip、EchoingPixels 與 OmniSIFT 均僅在 LLM 前置階段（pre-LLM stage）進行選擇，且採用固定的逐模態比例。這意味著它們無法回應兩項關鍵動態：一是跨模態詞元重要性（cross-modal token importance）隨層級演變的事實；二是不同查詢對於視覺或音訊證據的需求差異。SEATS 同時具備前置與內部雙階段選擇能力，並引入查詢感知剪枝（query-aware pruning）與階段自適應（stage-adaptive）的 TRR 調度，填補了上述空白。

特別值得比較的是 HiDrop。HiDrop 同樣在 LLM 內部採用層級相關的保留比例，但其調度為凹函數（concave schedule），主要針對圖像模態且未處理多模態預算分配。SEATS 則採用漸進遞減（progressive decay）的區塊化 TRR，並專為音視覺融合設計。簡言之，SEATS 是迄今少數同時具備「前置多樣性過濾」、「內部相關性引導」、「深度遞減排程」與「晚期完全移除」四項特徵的 om-LLM 專用方法。

然而，SEATS 亦存在可預見的限制。其一，作為免訓練方法，其 TRR 遞減曲線與雙層分配閾值可能係依據經驗觀察手動設計，對於不同模型家族（如非 Qwen 架構）或不同任務型態（如生成式任務相較於理解式任務）是否具備同等穩健性，文中尚未驗證。其二，現有比較基線在 om-LLM 領域仍相對稀少，實驗僅與完整模型（full-token baseline）對比，未與 OmniZip 等方法進行直接的數據層級對決，使得「相較於現有 om-LLM 專用方法提升多少」尚難量化。其三，當輸入影片極短或音訊資訊極度稀疏時，過度依賴查詢相關性分數可能導致關鍵但低顯著度的背景詞元被過早移除。

#### 可重現性評估

從可重現性（reproducibility）角度評估，SEATS 具備若干有利條件，但也伴隨部分不確定性。

有利條件方面，SEATS 屬於免訓練（training-free）方法，這大幅降低了重現門檻。研究者無需準備額外的訓練資料、GPU 叢集或微調（fine-tuning）流程，僅需在推論（inference）階段注入詞元選擇邏輯即可。實驗採用的基礎模型 Qwen2.5-Omni-7B 與 Qwen3-Omni-30B 均為阿里巴巴開源釋出的公開模型，其模型權重（model weights）與推論框架可公開取得，這確保了硬體與軟體基礎環境的可複製性。此外，文中提及的五個音視覺基準（audio-visual benchmarks）應屬該領域標準資料集，原則上具公開存取性。

不確定性方面，在提供的文本範圍內，作者並未明確宣告原始碼（source code）或實作細節（如注意力加權多樣性選擇的確切演算法、查詢相關性分數的計算公式、TRR 遞減的數學排程）是否將公開釋出。雖然方法論概念描述清晰，但諸如「區塊化（block-wise）」的具體層數切分點、雙層分配中的閾值參數、以及「晚期層」的判定準則等工程細節，若無開源實作輔助，其他研究者可能需要耗費額外成本進行逆向工程與超參數搜尋。此外，由於實驗僅聚焦於 Qwen Omni 系列，方法對其他具備不同編碼器架構或融合策略的 om-LLM（例如採用不同音訊編碼器或視覺投影層設計的模型）是否可直接套用，仍需獨立驗證。

綜合而言，SEATS 的可重現性處於「中高」等級：概念層次完整且無需訓練，但實作層次的細節透明度與跨架構泛化性仍有待原始碼公開與社群驗證。

#### 未來研究方向

基於 SEATS 的現有框架與未盡之處，以下幾個方向值得後續研究探索。

第一，將固定或手動設計的 TRR 遞減排程，進階為資料驅動或輸入自適應的動態排程。雖然免訓練（training-free）特性具有部署優勢，但透過少量校準資料（calibration data）學習每層的最佳保留比例，或依據輸入序列的複雜度（如場景切換頻率、音訊事件密度）即時調整 TRR，有機會在相同計算預算下進一步提升效能保留率。

第二，將詞元選擇與鍵值快取壓縮（KV cache compression）深度整合。SEATS 目前專注於減少前向傳播中的活躍詞元數量，但在自迴歸生成（autoregressive generation）階段，過去層的鍵值（key-value）快取仍可能保留大量歷史非文本資訊。未來可研究如何在 SEATS 的晚期層完全移除非文本詞元後，同步對 KV cache 進行對應的跨模態清理，以實現解碼階段（decoding stage）的記憶體與延遲雙重優化。

第三，拓展至串流（streaming）或即時音視覺理解場景。當前 SEATS 的假設似乎基於離線影片（offline video）輸入，所有時間視窗（temporal windows）的詞元在推論前已完整存在。若將框架延伸至串流情境，需處理時間視窗持續滑入、查詢相關性分數無法預先取得全局資訊的挑戰，這可能需要在線（online）或因果（causal）的詞元重要性估計機制。

第四，理論層次的跨模態融合完備性分析。SEATS 的晚期移除策略依賴於「融合已大致完成」的經驗觀察，但未提供量化的融合完備性指標。未來可發展基於資訊瓶頸（information bottleneck）或互資訊（mutual information）的理論工具，以嚴謹判定「何時可以安全移除某模態詞元」，從而使階段自適應（stage-adaptive）策略具備更強的理論保證。

第五，硬體協同設計（hardware co-design）。SEATS 在不同階段對記憶體頻寬與計算單元的需求不同：前置階段需處理高吞吐量的編碼器輸出，內部階段則涉及動態的稀疏注意力（sparse attention）。針對這些特性設計專用的稀疏加速核心或記憶體排程器，可將 9.3 倍 FLOPs 降低進一步轉化為實際的能耗（energy consumption）與尾延遲（tail latency）改善。

## 論文問答

**Q1：全模態大型語言模型（om-LLM）在推論時面臨的主要計算挑戰是什麼？為什麼傳統的文本型 LLM 優化方法無法直接解決這個問題？**

A：全模態大型語言模型需要同時處理影片、音訊與文本等多種模態的詞元，其中視覺與音訊詞元會隨影片長度迅速增長，經常達到數萬個。由於自注意力機制的計算複雜度與序列長度呈平方關係，將所有非文本詞元完整送入 LLM 會造成巨大的計算與記憶體開銷。傳統針對純文本 LLM 的優化方法通常未考慮多模態詞元的時空冗餘特性，也無法處理視覺與音訊在時間視窗上交錯對齊的獨特結構，因此難以直接套用。

**Q2：現有的免訓練詞元選擇方法在應用於 om-LLM 時存在哪些根本性的缺陷？**

A：現有方法大多僅針對單一視覺模態設計，例如圖像或視訊 LLM 的詞元剪枝技術，未能處理 om-LLM 中時間交錯的音視覺結構。即使是專為 om-LLM 設計的方法，如 OmniZip、EchoingPixels 與 OmniSIFT，也只在 LLM 前置階段進行選擇，並採用固定的逐模態保留比例。這些方法忽略了跨模態詞元重要性會隨著模型深度演變的事實，導致淺層可能過度剪枝而損失融合所需的關鍵資訊，或在深層保留過多已無必要的冗餘詞元。

**Q3：作者透過逐層分析發現了什麼樣的依賴模式？這個發現為何對設計高效的詞元選擇策略至關重要？**

A：作者發現 om-LLM 對視覺與音訊詞元的依賴呈現明顯的區塊化模式：淺層區塊強烈依賴非文本詞元以進行跨模態融合，中層區塊逐漸降低依賴，而深層區塊在融合完成後幾乎不再需要視覺或音訊資訊。這個發現揭示了許多深層的非文本詞元在跨模態融合後其實是多餘的，為動態調整各層保留比例提供了理論依據。若缺乏此深度感知，任何固定比例的剪枝策略都會在淺層過於激進或在深層過於保守，無法兼顧效率與效能。

**Q4：SEATS 的核心設計理念是什麼？它如何將「階段自適應」與「深度感知」結合到單一免訓練框架中？**

A：SEATS 的核心在於依據 om-LLM 不同推論階段的特性，動態調整詞元選擇策略與保留預算。在 LLM 前置階段，它利用注意力加權的多樣性選擇去除時空冗餘；在 LLM 內部，則採用區塊化的詞元保留比例遞減排程，隨著深度增加而逐步擴大剪枝強度。這種設計讓模型在淺層保留足夠的音視覺資訊以完成跨模態融合，同時在深層果斷移除冗餘詞元，且整個過程無需額外訓練或微調模型參數。

**Q5：SEATS 在 LLM 內部採用了「由上而下的兩層分配策略」，具體是如何在時間視窗與模態之間動態分配保留預算的？**

A：在 LLM 內部階段，SEATS 首先根據查詢相關性分數，將當前區塊的總保留預算分配給各個時間視窗，使與使用者查詢高度相關的時段獲得更多詞元配額。接著，在每個時間視窗內部，系統再次依據查詢相關性將預算動態分配給視覺與音訊模態，而非採用固定的視覺／音訊比例。這種雙層動態配置能夠精準捕捉不同時間點上哪個模態提供了關鍵證據，例如某個視窗可能由音訊主導答案，而另一個視窗則依賴視覺細節。

**Q6：為什麼 SEATS 選擇在「深層區塊」完全移除所有剩餘的非文本詞元？這樣的設計會不會導致資訊遺失？**

A：根據作者的觀察，當模型進入深層區塊時，跨模態融合已大致完成，視覺與音訊資訊已被充分整合到文本表示中，因此剩餘的非文本詞元對最終推理的邊際貢獻極低。在此階段完全移除這些詞元，可以讓後續層僅處理文本詞元，大幅節省計算資源而不顯著影響效能。實驗結果也證實，即使僅保留 10% 的視覺與音訊詞元，模型仍能維持 96.3% 的原始效能，顯示深層移除策略在實務上是安全且高效的。

**Q7：SEATS 在哪些模型與基準測試上進行了驗證？主要的效率與效能指標為何？**

A：實驗在 Qwen2.5-Omni-7B 與 Qwen3-Omni-30B 這兩個具代表性的全模態模型上進行，涵蓋五個音視覺理解基準測試。評估指標包括浮點運算次數（FLOPs）的縮減倍率、預填充（prefill）階段的加速比，以及相較於完整詞元序列的效能保留比例。結果顯示 SEATS 在大幅削減計算量的同時，能夠維持與原始模型相近的任務表現，展現出優異的效率與效能權衡。

**Q8：當僅保留 10% 的視覺與音訊詞元時，SEATS 達到了什麼樣的具體成果？這與完整詞元基線相比代表什麼意義？**

A：在僅保留 10% 視覺與音訊詞元的設定下，SEATS 實現了 9.3 倍的 FLOPs 縮減與 4.8 倍的預填充加速，同時保留了 96.3% 的原始效能。這代表模型幾乎可以只用原本十分之一的非文本詞元運算量，就完成絕大多數的音視覺理解任務。對於部署在資源受限環境中的 om-LLM 而言，這樣的壓縮率意味著顯著的延遲降低與能耗節省，而效能損失卻微乎其微。

**Q9：相較於現有的免訓練詞元選擇方法（如 OmniZip、FastV、HiDrop），SEATS 在方法定位與實際表現上有何獨特之處？**

A：與 OmniZip 等僅在 LLM 前置階段操作的方法不同，SEATS 是同時涵蓋前置與內部階段的混合策略，並且針對 om-LLM 的時間交錯音視覺結構設計。相較於 FastV 等僅處理單一視覺模態的內部剪枝方法，SEATS 能動態調整視覺與音訊的保留預算，並採用隨深度遞減的保留比例排程。從實驗來看，SEATS 在 Qwen2.5-Omni-7B 上僅需 33% 的計算成本即可達到與完整詞元基線相當的表現，這是固定比例或單一階段方法難以比擬的整體效益。

**Q10：SEATS 的免訓練特性對於實際產品部署與模型迭代具有什麼樣的商業與工程價值？**

A：SEATS 作為免訓練方法，無需額外的微調資料或昂貴的 GPU 訓練資源，即可直接應用於已部署的 om-LLM 服務，大幅降低導入門檻。對於需要頻繁更新模型版本或支援多種硬體規格的產品團隊而言，這種即插即用的特性可以縮短上線時程，並避免每次模型迭代都需重新設計壓縮流程。此外，由於 SEATS 不修改模型權重，企業可以在不影響原始模型授權或安全對齊的前提下，直接提升推論吞吐量與降低服務成本。

**Q11：在哪些具體的應用場景中，SEATS 所帶來的預填充加速與 FLOPs 縮減最能發揮關鍵作用？**

A：對於即時音視覺問答、直播內容監控、以及長影片分析等需要低延遲回應的場景，預填充階段的加速能顯著縮短使用者等待時間。在行動裝置或邊緣運算節點上，FLOPs 的大幅縮減意味著更低的功耗與散熱需求，使全模態模型得以在終端本地運行。此外，對於同時處理大量使用者請求的雲端 API 服務，SEATS 能夠提升單卡吞吐量，降低單次請求的計算成本，從而改善服務的經濟規模。

**Q12：SEATS 的研究成果對於多模態大型語言模型領域的未來發展可能帶來什麼樣的影響或啟發？**

A：SEATS 驗證了「深度感知」與「模態彈性」在免訓練詞元選擇中的重要性，未來研究可能會更廣泛地探索不同模態在 Transformer 各層的貢獻曲線。這項工作也啟發後續方法可以將查詢感知機制與階段性壓縮進一步結合，發展出更細緻的層級化或自適應推論架構。長遠來看，SEATS 為建立更高效的統一多模態架構鋪路，使得在有限資源下處理更長的影片、更高解析度的音訊，或甚至更多模態（如觸覺、感測器資料）成為可能。

**Q13：儘管 SEATS 表現出色，作者在方法設計上可能承認哪些潛在的限制或適用範圍的邊界？**

A：雖然文中未明確詳列所有限制，但從方法設計可推知，SEATS 的假設建立在 om-LLM 的跨模態融合會隨深度遞減這一觀察上，若未來模型架構改變導致依賴模式不同，則區塊化遞減排程可能需要重新校正。此外，SEATS 目前針對的是時間對齊的音視覺詞元結構，對於模態間未經過時間同步或採用非交錯式架構的模型，其兩層分配策略可能需進行調整。最後，極端低預算情境（例如保留低於 5% 的詞元）下，效能衰減的幅度與任務類型高度相關，這可能是實際部署時需要針對特定領域進行微調的邊界。

**Q14：在什麼樣的輸入條件或任務類型下，SEATS 可能會出現效能下降或詞元選擇失靈的情況？**

A：對於需要精細時空定位的任務，例如逐幀動作辨識或毫秒級音畫同步分析，過度依賴查詢相關性分數可能會過濾掉看似不相關、但實際上對精確時間定位至關重要的背景詞元。如果查詢本身過於模糊或開放式，查詢感知機制可能無法正確識別關鍵時間視窗，導致保留預算分配失當。此外，當影片或音訊內容極度稀疏、幾乎無冗餘時，前置階段的多樣性選擇可能誤刪唯一具有辨識性的特徵詞元，進而影響後續推理的正確性。

**Q15：未來研究可以從哪些方向延伸 SEATS 的框架，以進一步提升全模態模型的推論效率？**

A：未來可以將 SEATS 與硬體感知的推論優化結合，例如針對 KV Cache 壓縮或稀疏注意力硬體加速器進行協同設計，以突破純演算法層面的效率上限。另一個方向是將階段自適應的概念擴展到生成階段（decoding stage），目前 SEATS 主要聚焦於預填充階段，而生成階段的長序列快取管理仍有優化空間。此外，引入輕量化的學習式閾值預測器，在保持免訓練主體框架的同時，針對特定任務動態微調保留比例與區塊邊界，或許能在極端壓縮率下進一步縮小效能差距。

## 實務應用指南

### 適用場景

1. **即時音視覺會議摘要與客服輔助**：企業內部會議或客戶服務錄影同時包含簡報畫面、與會者影像及語音對話。SEATS 可在 LLM 前置階段先壓縮時空冗餘，並於深層區塊移除已完成融合的非文本詞元，使長時間會議能在邊緣裝置上即時生成摘要，顯著降低 GPU 記憶體與計算開銷。

2. **智慧城市多模態監控分析**：交通路口或公共場域的攝影機同時輸出高解析度視訊與環境音訊。透過 SEATS 的查詢導向兩層預算分配，系統可依當下查詢（如「辨識救護車警笛」或「偵測路口事故」）動態保留較高比例的音訊或視覺詞元，在維持關鍵證據完整性的同時，將序列長度壓縮至可即時推理的範圍。

3. **自駕車艙內外多感知決策**：自動駕駛系統需同步處理車外環境視訊、車艙內駕駛監控影像及車內語音指令。SEATS 的區塊化保留比例（TRR）遞減排程，允許淺層區塊保留充足詞元進行跨模態融合，深層區塊則大幅裁減，適合車載運算單元有限的記憶體頻寬與算力預算。

4. **直播與短影音內容審查與推薦**：短影音平台每日需處理海量上傳內容。SEATS 作為免訓練外掛模組，可直接套用於現有全模態大型語言模型（如 Qwen2.5-Omni），在 prefill 階段達到 4.8 倍加速，使高吞吐量審查管線能以更低成本同時分析影片畫面、背景音樂與語音旁白。

5. **遠距醫療與復健動作評估**：物理治療師透過視訊觀察患者動作，同時接收患者口述症狀。此場景對視覺細節（肢體角度）與音訊細節（症狀描述）的跨模態對齊要求極高。SEATS 在 LLM 內部依查詢相關性分數動態調整視覺與音訊保留預算，避免固定逐模態比例導致關鍵臨床線索遺失。

### 實作前置條件

**資料需求**：時間對齊的原始音視訊資料（建議具備時間戳記對應關係）、用於評估的查詢文本與標準答案（如 NextQA、AVQA 等音視覺問答基準），以及少量領域驗證資料以確認壓縮後的語義保留度。

**運算需求**：至少配備 24 GB 以上 VRAM 的 GPU（如 NVIDIA A10/A100）以載入 Qwen2.5-Omni-7B 或 Qwen3-Omni-30B；若為 30B 級模型，需多卡推論或採用量化版本。此外，需預留資源進行全詞元基線與 SEATS 壓縮版本的對比實驗。

**技術能力**：團隊需熟悉 Transformer 自注意力機制與 KV Cache 管理，具備 PyTorch 或 vLLM 客製化修改經驗，並能處理多模態編碼器（視覺編碼器與音訊編碼器）的輸出對齊與前處理。了解稀疏注意力或詞元剪枝相關研究將有助於快速除錯。

### 實作步驟建議

**步驟一：建立全詞元推論基線**
部署 Qwen2.5-Omni 或 Qwen3-Omni，關閉任何壓縮機制，針對目標任務測量原始序列長度、prefill 延遲、峰值記憶體與任務準確率。此基線將作為後續 TRR（Token-Retention-Ratio）調校的參照。

**步驟二：實作前置階段時空冗餘壓縮**
在 LLM 前置階段導入注意力加權多樣性選擇（attention-weighted diversity selection）。針對每個時間視窗內的視覺與音訊詞元，計算其在編碼器端的注意力分數，並以 max-min 多樣性準則挑選具代表性的詞元，優先移除空間重複幀與時間連續冗餘。

**步驟三：設計區塊化 TRR 遞減排程**
依據論文觀察到的區塊化依賴模式，為淺層、中層、深層區塊分別設定遞減的保留比例。例如：淺層區塊（前 1/3）保留 50% 以上非文本詞元以確保跨模態融合；中層區塊（中 1/3）降至 20%；深層區塊（後 1/3）進一步降至 10% 或更低。

**步驟四：實作查詢導向的兩層預算分配**
在 LLM 內部每個區塊的詞元選擇點，先依查詢相關性分數（query relevance scores）決定各時間視窗的保留預算，再於視窗內部依分數動態分配至視覺與音訊模態。避免使用固定逐模態比例，確保「警笛聲為主」的查詢能保留較多音訊詞元，而「手勢辨識為主」的查詢則保留較多視覺詞元。

**步驟五：深層全剪枝與效能驗證**
在跨模態融合大致完成的後段層（late blocks），實作全部非文本詞元移除機制，使後續層僅處理文本詞元。驗證整體 FLOPs 降幅是否接近預期（如 9.3 倍），並檢查任務準確率損失是否控制在可接受範圍（如保留 96.3% 原始效能）。

**步驟六：推論引擎整合與服務化**
將 SEATS 邏輯封裝為 vLLM 或 SGLang 的客製化前置/中間處理模組，整合 chunked prefill 與 prefix caching，並建立 API 服務。進行壓力測試，確認高並發下的吞吐量提升與記憶體穩定性。

### 潛在風險與注意事項

**淺層過度剪枝導致融合失敗**：若在前置階段或淺層區塊過度裁減視覺或音訊詞元，跨模態融合尚未完成，模型可能遺失關鍵對齊資訊。建議嚴格遵守淺層高 TRR 原則，並以消融實驗確認最低安全保留量。

**音視覺重要性動態失衡**：固定逐模態比例雖實作簡單，但無法因應查詢語義變化。若省略查詢相關性分數的兩層分配，可能在「聽音辨位」類任務中誤刪音訊詞元。務必確保查詢文本已完整編碼並參與相關性計算。

**時間視窗對齊誤差**：視覺編碼器與音訊編碼器的取樣率不同，若前置處理導致時間視窗邊界偏移，將使查詢導向分配誤判詞元所屬時段。實作時需維護原始幀率與音訊取樣率的對應索引表。

**延遲與吞吐量權衡**：SEATS 主要加速 prefill 階段（降低首次推理延遲），對 decode 階段的自迴歸生成幫助有限。若產品瓶頸在於長文本生成而非多模態輸入處理，需評估整體端到端效益是否仍具投資報酬率。

**領域適配限制**：作為免訓練方法，SEATS 依賴模型既有的注意力模式。若部署於高度專業領域（如醫學音視訊診斷），其注意力分數分佈可能與通用領域不同，建議先以領域驗證集測試，必要時放寬 TRR 或改採微調後的專用模型。

### 與其他技術的整合建議

**推論引擎深度整合**：將 SEATS 的詞元選擇邏輯嵌入 vLLM、SGLang 或 TensorRT-LLM 的 prefill 管線中，與 existing prefix caching 機制協作。由於 SEATS 會動態改變每層的 KV Cache 形狀，需修改記憶體配置器以支援可變長度快取，避免記憶體碎片化。

**結合 KV Cache 壓縮技術**：SEATS 裁減的是當前層輸入詞元，可與 H2O、SnapKV 等 KV Cache 逐層壓縮方法並行使用。前者降低每層的 Q/K/V 計算量，後者降低歷史快取儲存成本，兩者互補可進一步提升長序列推論效率。

**邊緣運算與硬體加速**：在 NVIDIA Jetson、Qualcomm 平台或 Apple Silicon 部署時，建議將前置階段的注意力加權多樣性選擇以 ONNX/Core ML 格式固化，並利用 NPU 執行編碼器端計算，減少 CPU-GPU 資料搬運延遲。

**串流處理管線**：針對直播或監控串流，可與 Kafka、Redis Stream 或 Apache Flink 整合，採用滑動時間視窗方式增量餵入音視訊區塊。SEATS 的視窗級設計天然適合此架構，每個視窗獨立執行前置壓縮後再送入 LLM。

**多模態 RAG 前置過濾**：在音視覺檢索增強生成（RAG）系統中，SEATS 可作為向量化前的輕量過濾器，先移除冗餘幀與背景音訊詞元，降低向量資料庫的儲存與檢索負擔，同時提升檢索精度。

### 給不同背景讀者的閱讀建議

**初學者**：建議先建立「序列長度與自注意力計算成本呈平方關係」的直覺，再聚焦論文核心發現——為何深層區塊可以大膽移除非文本詞元。暫時略過 TRR 排程的數學細節，把重點放在「階段自適應」與「查詢導向分配」這兩個設計概念上，即可理解 SEATS 的價值。

**AI 工程師**：請優先研讀論文第 3 節的逐層詞元依賴性分析與方法章節的兩層預算分配實作細節。實務上需特別關注如何將 SEATS 無縫接入現有 vLLM 推論管線，包括修改 attention backend 以支援動態詞元掩碼，以及確保 KV Cache 在區塊間正確更新與釋放。

**研究人員**：建議深入檢視論文揭示的區塊化依賴模式（block-wise pattern），思考此現象是否普遍存在於其他全模態模型架構。可進一步探索將階段自適應思想擴展至觸覺、雷達、熱成像等更多模態，或與訓練式剪枝、神經架構搜尋（NAS）進行聯合優化。

**產品經理**：請掌握論文關鍵數字——僅保留 10% 視覺與音訊詞元即可達成 9.3 倍 FLOPs 降幅與 4.8 倍 prefill 加速，同時維持 96.3% 原始效能。據此評估在即時音視覺產品（如互動直播、智慧監控 SaaS）中的成本節省空間與使用者體驗提升潛力，並規劃與現有模型服務的整合時程。
