## ⚡ TL;DR

現有技能使用訓練受限於固定環境，且社群技能缺乏可驗證任務。
SkillGym透過建構者-審查者流程，自動生成四類可驗證技能任務環境。
2B至122B模型經微調後皆提升，9B模型勝過397B未訓練模型，技能閱讀率由28%升至96%。

## 摘要翻譯

技能（Skills）為大型語言模型智能體（LLM Agents）提供專業知識（Expertise）與任務指引（Task Guidance），以完成長期任務（Long-Horizon Tasks）與複雜任務（Complex Tasks）。儘管技能已在近期的智能體範式（Agent Paradigms）與框架（Harnesses）中廣泛採用，如何合成可靠的訓練資料（Training Data），以及如何訓練智能體使用技能，仍屬未充分探索的議題。在本研究中，我們提出 SkillGym，一個用於建構可驗證環境（Verifiable Environments）、收集軌跡（Trajectories），以及訓練技能使用智能體（Skill-Use Agents）的自動化流程（Automatic Pipeline）。SkillGym 首先從網際網路爬取（Crawls）大量技能，並保留那些工作流程（Workflows）可在離線環境中重現執行（Reproducibly Offline）的技能。我們使用建構者-審查者流程（Builder-Reviewer Pipeline）來建構難度控制任務（Difficulty-Controlled Tasks），涵蓋四種任務類型（Task Types），每個任務皆包含參考解（Reference Solution）與可執行驗證器（Executable Verifier）。透過此流程，我們建構了 6.8k 個環境（Environments），並收集 19k 條已驗證成功軌跡（Verified Successful Trajectories）以進行監督式微調（Supervised Finetuning, SFT）。在這些軌跡上進行微調，可提升不同系列與規模的大型語言模型（LLMs）表現，涵蓋從 2B 到 122B 參數（Parameters），橫跨四個技能使用基準測試（Skill-Use Benchmarks）；我們的 Qwen3.5-9B SFT 模型在其中兩項基準測試上優於 397B 參數的未訓練模型（Untrained Model）。進一步分析顯示，訓練教會智能體調用技能，讓相關技能的讀取率從 28% 提升至 96%；且這些增益在不同推理結構（Reasoning Structures）中皆能維持，並可推廣至僅佔訓練資料少數的任務類型，以及保留技能（Held-Out Skills）。

### 核心貢獻（3～5點）
- 提出 SkillGym，一個自動化流程（Automatic Pipeline），可自動從網際網路爬取（Crawl）技能（Skills）、建構可驗證環境（Verifiable Environments）、收集已驗證成功軌跡（Verified Successful Trajectories），並以監督式微調（SFT）訓練技能使用智能體（Skill-Use Agents）。
- 設計建構者-審查者智能體系統（Builder-Reviewer Agent System），自動生成涵蓋四種任務類型（Task Types）與四種推理結構（Reasoning Structures）的難度控制任務（Difficulty-Controlled Tasks），並提供參考解（Reference Solution）與可執行驗證器（Executable Verifier）。
- 建立大規模訓練資料：6.8k 個任務環境（Task Environments）與 19k 條已驗證成功軌跡，顯著提升 2B 至 122B 參數（Parameters）的大型語言模型（LLMs）在四個技能使用基準測試（Skill-Use Benchmarks）上的表現。
- 展現強泛化能力：Qwen3.5-9B SFT 模型在兩項基準測試上超越 397B 未訓練模型（Untrained Model）；訓練後智能體調用技能的讀取率由 28% 提升至 96%，且效果可推廣至少數任務類型與保留技能（Held-Out Skills）。

### 適合對象
從事大型語言模型智能體（LLM Agents）、技能使用訓練（Skill-Use Training）、自動化訓練資料合成、可驗證環境生成，以及長期／複雜任務推理研究的學者與工程師；特別適合希望以自動化流程降低訓練資料建構成本，並提升智能體在真實世界技能應用表現的研究團隊。

## 深度分析

#### 方法論解析

SkillGym（自動化技能使用智能體訓練流程）的核心設計可拆解為三個階段：Skill Curation（技能篩選）、Skill-Grounded Task Construction（以技能為基礎的任務建構）與 Agent Training（智能體訓練）。整體目標是將網路上社群撰寫的 skills（技能）轉換成可執行、可驗證且難度受控的訓練環境，並透過 Supervised Finetuning（SFT，監督式微調）讓 LLM（Large Language Model，大型語言模型）學會主動查閱與使用外部技能。

第一階段是技能篩選。SkillGym 從 skills.sh、GitHub 等來源 crawls（爬取）大量 community-written skills（社群撰寫技能），涵蓋 software engineering（軟體工程）、science（科學）、finance（金融）、document processing（文件處理）、marketing（行銷）等 18 個領域。篩選的關鍵條件是該 skill 的 workflow（工作流程）必須能夠 reproducibly offline（離線重現）執行，這確保後續任務不需要依賴即時網路、第三方付費 API 或難以複製的外部狀態。經過 deduplication（去重）、annotation（標註）與 selection（挑選）後，形成 curated skill pool（精選技能集合）。

第二階段是任務建構，也是 SkillGym 最具特色的部分。系統根據四種 reasoning structures（推理結構）來設計任務：procedural execution（程序執行）、abductive diagnosis（溯因診斷）、constraint satisfaction（約束滿足）與 partial-order planning（偏序規劃）。這四種結構對應不同的認知需求：依序執行、從現象推論根因、滿足多項條件、以及在部分順序限制下規劃行動。透過這樣的分類，訓練資料能夠覆蓋多樣的決策模式，而不只是單純的步驟複製。

任務建構採用 Builder-Reviewer Pipeline（建構者-審查者流程）。Builder（建構者）負責 raw environment building（原始環境建置）與 task authoring（任務撰寫），產出 task instruction（任務指令）、initial workspace（初始工作空間）、reference solution（參考解）以及 executable verifier（可執行驗證器）。Reviewer（審查者）則進行 quality review（品質審查），偵測 ambiguous requirements（模糊需求）、information leakage（資訊洩漏）、overly restrictive verification（過度嚴格的驗證）或 insufficient verification（驗證不足）等問題，並將修正意見回饋給 Builder。這個 loop（迴圈）會反覆執行，直到任務品質達標。

任務設計遵循 skill-critical（技能關鍵）原則：正確使用 skill 應該顯著影響任務成敗，但任務本身仍保留不用 skill 也能嘗試解決的空間。這樣的設計迫使 agent 學習「何時該查閱 skill」以及「如何將 skill 內容轉譯為正確動作」，而不是單純靠內部知識硬解或繞過 skill。此外，透過 golden skills（正確技能）與 distractor skills（干擾技能）的組合，系統能進行 difficulty-controlled tasks（難度控制任務）設計。

第三階段是軌跡收集與微調。SkillGym 在多個 agent harnesses（智能體框架）上，使用三個 teacher models（教師模型）收集 19k verified successful trajectories（已驗證成功軌跡）。這些 trajectories（軌跡）包含 think（思考）、act（行動）、observation（觀察）等完整互動序列，並經過 augmentation（擴增），例如 prompt variants（提示變體）與 tool variants（工具變體）。最後，這些軌跡被用來對多個模型進行 SFT，讓模型學會在觀察到環境回饋後選擇合適動作，並在關鍵時刻 invoke skills（呼叫技能）。

#### 實驗數據解讀

SkillGym 的實驗規模相當可觀：共建構 6.8k task environments（任務環境），收集 19k verified successful trajectories，涵蓋約 3.5k skills 與 18 個領域。這個數量雖然遠小於 LLM 預訓練資料，但對於 SFT 來說已經足夠密集，因為每筆資料都經過 executable verifier（可執行驗證器）確認，品質高於一般合成資料。

在模型表現上，實驗顯示 SFT 能提升六個來自三個模型家族的 LLMs，參數量從 2B 到 122B 不等，在四個 skill-use benchmarks（技能使用基準測試）上都有進步。這表示 SkillGym 學到的不是單一模型的特殊技巧，而是一種可遷移的 skill-use inductive bias（技能使用歸納偏置）。其中最引人注目的結果是：Qwen3.5-9B SFT 模型在兩個基準測試上超過了未經訓練的 Qwen3.5-397B-A17B 模型。這說明在特定能力上，高品質的專項 SFT 可以彌補甚至超越參數規模的劣勢，也凸顯了「學會使用技能」這項能力並非單純靠放大模型就能自動湧現。

從行為機制來看，訓練前後的對比非常明確：agent 閱讀相關 skill 的比例從 28% 提升到 96%。這是一個強烈的因果指標，顯示 SFT 確實教會了 agent 主動查閱外部知識，而不是依賴參數中可能已過時或不完整的內部知識。這對於需要 domain knowledge（領域知識）或 expertise（專業知識）的長期任務尤其重要。

泛化能力方面，實驗發現訓練帶來的增益能跨四種 reasoning structures（推理結構）保持，甚至延伸到在訓練資料中佔少數的任務類型，以及 held-out skills（保留技能／未見技能）。這點至關重要，因為它暗示模型學到的是一種通用的「如何使用 skill」的 meta-skill（後設技能），而不是記住特定 skill 的內容。若只是記憶，則在未見 skill 上應該會明顯衰退。

不過，數據也帶來一些需要謹慎解讀的地方。首先，雖然 verifier 能確認執行結果，但 verifier 本身是由 LLM 或規則自動生成，仍可能出現 false positives（偽陽性）或 false negatives（偽陰性），特別是在接受 valid alternative solutions（有效替代解）與排除 superficially plausible outputs（表面合理輸出）之間的拿捏。其次，teacher model 的偏好可能會滲透到訓練資料中，導致學生模型複製特定推理風格而非真正理解 skill。最後，實驗主要採用 SFT，對於錯誤累積與長期探索的修正能力有限，因為 SFT 本質上是在模仿成功軌跡，而非透過 trial-and-error（試誤）學習。

#### 與現有研究的比較

在 skill-use 的研究光譜中，現有方法大致可分為 training-free（無訓練）與 training-based（基於訓練）兩類。Training-free 方法如 Voyager、SkillWeaver、AgentSkillOS 主要在 inference time（推論時間）檢索、組合或發現 skills，不進行 weight updates（權重更新）。這類方法的優點是靈活、可隨插即用，但缺點是每次都需要額外的檢索與規劃開銷，且無法將「如何有效使用 skill」內化為模型能力。SkillGym 選擇 training-based 路線，透過 SFT 將 skill-use 行為寫入模型權重，推論時更直接。

在 training-based 方法中，Skill-to-LoRA、SAGE、SkillRL 等研究多從 fixed environments（固定環境）中的 agent experience（智能體經驗）提取 skills，或將特定 skills 編譯進模型權重。這些方法的限制在於 skill 的來源與環境域較窄，且學到的技能往往與特定任務綁定。SkillGym 反轉了這個方向：它從公開社群的 skills 出發，自動建構對應的 environments（環境）與 tasks（任務），並保持 skills 外部化。這樣做的好處是訓練出的 agent 能使用未在訓練中見過的 held-out skills，且能橫跨 18 個領域。

在 task and environment synthesis（任務與環境合成）方面，EndlessTerminals 與 CLI-Universe 屬於 task-driven synthesis（任務驅動合成），先設計任務再建構環境；EnvScaler 與 Agent-World 屬於 environment-driven synthesis（環境驅動合成），先收集環境主題再生成任務；SKT 則是 skill-driven synthesis（技能驅動合成），但偏向模板生成。SkillGym 同樣是 skill-driven，但更進一步強調 verifiable environments（可驗證環境）、difficulty-controlled tasks、builder-reviewer quality loop，以及 multi-harness（多框架）軌跡收集。這些設計讓 SkillGym 的輸出不只是「看起來合理的任務」，而是「可執行、可驗證、可重複」的訓練單元。

SkillGym 的主要限制也來自其設計選擇。由於它要求 skills 能 reproducibly offline 執行，因此無法直接處理需要即時網頁、動態資料庫或付費 API 的 skills。Verifier 的自動生成雖然降低人工成本，但在複雜任務上仍可能出現語意偏差。此外，目前的訓練僅使用 SFT，尚未結合 Reinforcement Learning（RL，強化學習）來進一步優化長期決策與錯誤恢復。

#### 可重現性評估

從提供的文本來看，SkillGym 目前是以 preprint（預印本）形式呈現，尚未明確說明是否公開 source code（原始碼）、dataset（資料集）、model weights（模型權重）或 executable task packages（可執行任務套件）。由於整個 pipeline（流程）涉及多個外部元件，包括不同 agent harnesses（智能體框架）、teacher models（教師模型）與社群 skills，若沒有完整的釋出，重現門檻會相當高。

為了提升可重現性，建議作者至少釋出以下項目：

1. Curated skill pool K（精選技能集合）與原始爬取來源，讓研究者能追蹤技能內容與授權。
2. 6.8k executable task packages T，包含 instruction（指令）、initial workspace（初始工作空間）、reference solution（參考解）、assets（資源）與 verifier（驗證器）。
3. Docker images 或 dependency manifests（依賴清單），確保 environments 能在不同機器上離線重現。
4. 19k verified successful trajectories（已驗證成功軌跡）與對應的 prompt / tool variants（提示與工具變體）。
5. SFT training configs（訓練設定），包括資料混合比例、學習率、序列長度等超參數。
6. Fine-tuned model checkpoints（微調後模型檢查點），特別是 Qwen3.5-9B SFT 版本，以便與 397B untrained model（未訓練模型）進行直接比較。

目前論文強調 verifier 是 executable（可執行）的，這本身已經是可重現性的重要基礎，因為它提供了客觀的成功標準。然而，若 verifier 的實作細節未公開，則不同團隊可能會對「何謂成功」產生不同解讀。因此，verifier code 的透明釋出對於學術驗證至關重要。

#### 未來研究方向

SkillGym 為 skill-use agents 的訓練開闢了一條可規模化的路徑，未來可以從以下幾個方向延伸：

1. **從 SFT 走向 RL**：目前使用 SFT 模仿成功軌跡，下一步可引入 RL，將 executable verifier（可執行驗證器）的輸出轉為 reward signal（獎勵訊號），讓 agent 在失敗中學習錯誤恢復與長期規劃，而不只是複製教師行為。

2. **線上與動態技能使用**：現有流程受限於 offline reproducible skills。未來可探索如何讓 agent 在推論時動態發現、評估並使用線上 skills，例如即時 API、網頁工具或企業內部知識庫。

3. **更精細的難度控制與課程學習**：目前的 difficulty-controlled tasks 已經有初步設計，但未來可結合 curriculum learning（課程學習），根據 agent 的學習進度動態調整 golden skills 與 distractor skills 的比例，進一步提升樣本效率。

4. **跨框架統一動作空間**：SkillGym 在多個 agent harnesses 上收集軌跡，但不同框架的 action space（動作空間）與 observation format（觀察格式）可能不同。未來可研究如何標準化這些介面，讓單一模型能無縫遷移到新框架。

5. **Verifier 的穩健性提升**：自動生成的 verifier 仍有誤判風險。未來可結合 formal verification（形式驗證）、fuzzing（模糊測試）或 human-in-the-loop review（人類參與審查），提高 verifier 對 valid alternative solutions 的包容性與對 superficially plausible outputs 的辨識力。

6. **多模態技能**：目前技能主要以文字與程式碼為主。未來可擴展到 GUI skills、robotics skills 或科學實驗技能，讓 agent 能處理更豐富的感知與動作模態。

7. **技能創造與使用的聯合學習**：SkillGym 專注於使用現有 skills，但未來可同時訓練 agent 創造新 skills 並使用舊 skills，形成自我增強的 skill ecosystem（技能生態系統）。

8. **安全性與對齊**：當 agent 學會自動執行外部 skills 時，必須防範惡意或 buggy skills。未來需要更強的 sandboxing（沙箱隔離）、權限控制與對齊機制，確保 skill-use agents 不會執行有害操作。

9. **蒸餾到更小模型**：Qwen3.5-9B SFT 已能擊敗 397B 模型，顯示小模型在專項能力上的潛力。未來可進一步將 skill-use 能力蒸餾到更小的 on-device models（裝置端模型），降低部署成本。

10. **標準化評估 rubric**：論文已對三個基準測試使用 shared rubric（共享評分標準）。未來可建立更廣泛的 skill-use evaluation benchmark，統一衡量 agent 在閱讀、選擇、適應與執行 skills 上的能力。

## 論文問答

**Q1：SkillGym 旨在解決什麼核心問題？**
A：SkillGym 旨在解決「如何為大型語言模型智能體生成可靠且可驗證的技能使用訓練資料」這一尚未被充分探索的問題。雖然技能（skills）已成為現代智能體框架的標準配備，但現有研究大多聚焦於如何設計或檢索技能，對於如何自動將社群撰寫的技能轉換為可訓練的任務環境、參考解與可執行驗證器仍缺乏系統性方法。SkillGym 透過自動化流程，從網際網路爬取大量技能、篩選可離線重現的工作流程，並建構出具備難度控制與可驗證結果的任務，從而填補這項缺口。

**Q2：現有的技能使用訓練方法存在哪些主要限制？**
A：現有方法大多讓智能體在固定環境中累積自身經驗，再從中萃取技能，這會將學習範圍侷限在少數任務領域。這種「由環境產生技能」的方向難以利用網路上豐富多元的社群撰寫技能，也限制了模型對新領域與未見技能的泛化能力。相較之下，SkillGym 反轉了這個方向，改為「由技能建構環境」，讓訓練資料能夠涵蓋軟體工程、科學、金融、文件處理與行銷等 18 個領域。

**Q3：為什麼訓練智能體有效使用外部技能很重要？**
A：有效使用技能需要智能體理解技能內容、判斷當前任務是否適用，並將其轉譯為正確的動作序列，這對長期且複雜的任務尤為關鍵。技能提供了專業知識與可執行腳本，能顯著提升智能體在需要領域專長任務上的表現，但前提是智能體必須學會「主動查閱並正確應用」技能。透過訓練，智能體可以將學到的使用行為遷移到新技能與新任務，而不必針對每個技能都重新調整模型權重。

**Q4：SkillGym 的核心方法架構是什麼？**
A：SkillGym 是一個自動化的智能體流程，可將社群撰寫的技能轉換為可執行的訓練環境。整體流程分為技能篩選、原始環境建構與任務編寫三個階段，其中後兩者由「建構者—審查者」智能體系統負責，分別產生初始工作空間、任務指令、參考解與可執行驗證器。最後，系統會透過執行檢查確認參考解能完成初始未解任務，並收集已驗證成功軌跡用於監督式微調。

**Q5：SkillGym 相較於先前研究的關鍵創新為何？**
A：SkillGym 最大的創新在於反轉了技能與環境的生成方向：從現成的社群技能出發，自動建構圍繞該技能應用的任務環境，而非從固定環境中萃取技能。此外，它提出了一個兩階段的建構者—審查者智能體系統，能夠迭代修正環境、參考解與驗證器，確保任務品質。該流程還涵蓋程序執行、溯因診斷、約束滿足與偏序規劃四種推理結構，使訓練資料具備結構多樣性。

**Q6：SkillGym 在任務設計上有哪些重要設計選擇？**
A：首先，任務必須是「技能關鍵的」，也就是正確應用技能會決定成敗，但任務在沒有技能的情況下仍須可解，以避免智能體學會繞過技能。其次，驗證結果必須可靠，能夠反映任務需求、接受有效替代解，並排除表面合理但實際錯誤的輸出。最後，建構者—審查者流程會透過執行驗證與品質審查，修復需求模糊、資訊洩漏或驗證過嚴／過鬆等問題。

**Q7：實驗使用了哪些基準測試與評估方式？**
A：論文在四個技能使用基準測試上進行評估，其中包括作者自行建構的測試集以及 SkillEval 等公開基準。實驗橫跨多個智能體框架（harnesses），並使用不同規模與家族的模型進行監督式微調與測試。透過統一的評分標準，研究團隊進一步分析模型在四種推理結構上的表現差異，以及對訓練中少見結構與保留技能的泛化能力。

**Q8：SkillGym 的主要實驗結果有哪些？**
A：在 SkillGym 資料上進行監督式微調後，六個來自三個模型家族、參數規模從 2B 到 122B 的大型語言模型在四個基準測試上均有顯著提升。其中，Qwen3.5-9B 的 SFT 模型甚至在兩個基準上超過了 397B 的未訓練模型，顯示微調後的小模型在技能使用任務上具備與大模型競爭的潛力。此外，訓練顯著提升了智能體查閱相關技能的比率，從 28% 提升至 96%。

**Q9：論文進行了哪些深入分析或消融研究？**
A：分析結果顯示，訓練後的智能體更懂得主動調用技能，閱讀相關技能的比率從 28% 大幅提升至 96%。研究也發現，性能提升橫跨四種推理結構，並能遷移到在訓練資料中佔少數的任務類型。更重要的是，這些增益也能泛化到訓練時保留未見的技能，證明 SkillGym 培養的是通用技能使用能力，而非單純記憶特定技能內容。

**Q10：SkillGym 在實務上可以應用於哪些場景？**
A：SkillGym 可應用於任何擁有豐富社群技能的專業領域，例如軟體工程、科學計算、金融分析、文件處理與行銷自動化等。它能自動將這些技能轉換為可執行的訓練環境，大幅降低人工設計任務與驗證器的成本。對於需要快速建構領域專屬智能體的企業或研究團隊而言，SkillGym 提供了一個可規模化的訓練資料生成方案。

**Q11：若將 SkillGym 落地為產品，需要考慮哪些因素？**
A：產品化時必須確保技能能夠在離線環境中穩定重現，並具備可靠的執行驗證器，否則生成的訓練資料品質會大打折扣。建構者—審查者流程需要持續監控與品質控制，以避免任務需求模糊、資訊洩漏或驗證條件過於嚴格等問題。此外，系統應能處理有效替代解，避免驗證器僅接受單一參考解，從而提升訓練資料的涵蓋度與公平性。

**Q12：SkillGym 可能對智能體研究領域帶來什麼影響？**
A：SkillGym 展示了如何利用公開社群技能自動生成大規模、可驗證的訓練資料，這可能降低領域專屬智能體的開發門檻。它也證明經過適當微調的較小模型，有機會在技能使用任務上媲美甚至超越未經訓練的超大模型，對於資源有限的研究者與開發者具有重要意義。整體而言，SkillGym 為「外部技能驅動的智能體訓練」提供了一個可擴展且可複製的研究範式。

**Q13：SkillGym 目前存在哪些限制？**
A：SkillGym 的成效高度依賴社群技能的品質與可離線重現性，部分技能可能因依賴項複雜或文件不完整而無法轉換為訓練環境。建構者—審查者流程雖能自動修正許多問題，但仍可能產生不完美的任務或驗證器，需要額外的人工或自動檢查。此外，目前流程主要針對可執行的工作流程設計，對於需要大量常識推理或開放式創作的技能，其適用性可能較有限。

**Q14：SkillGym 可能出現哪些失敗案例？**
A：一種常見失敗是驗證器設計不當，例如過於嚴格而拒絕有效替代解，或過於寬鬆而接受表面合理但實際錯誤的輸出。另一種情況是技能本身依賴外部網路資源或特定執行環境，導致無法在離線環境中穩定重現。此外，建構者—審查者系統可能未能察覺任務指令中的資訊洩漏，使得智能體無需真正理解技能內容即可完成任務。

**Q15：未來可以朝哪些方向延伸 SkillGym？**
A：未來研究可以將 SkillGym 擴展到更多推理結構與應用領域，並進一步提升驗證器的穩健性與泛化能力。另一個方向是結合強化學習，讓智能體在可驗證環境中透過試誤持續優化技能使用策略，而不僅止於監督式微調。此外，如何處理無法離線執行的技能、提升對開放式任務的支援，以及將學到的技能使用行為遷移到真實世界環境，都是值得深入探索的課題。

## 實務應用指南

## 適用場景

1. **企業內部工具智能體**：將公司內部 Wiki、Runbook、腳本套件轉為可驗證任務環境，訓練智能體使用這些技能完成報表生成、資料庫查詢、CI/CD 操作等長期任務。
2. **開源軟體開發助手**：把社群撰寫的開發技能（如 `skills.sh`、GitHub Skills）轉換成程式修復、套件升級、測試新增等任務，微調出能在多種程式碼庫上使用外部技能的程式智能體。
3. **科學與金融領域自動化**：針對需要專業知識與可重現工作流程的領域（如實驗數據處理、財務模型計算），建立離線可執行的驗證環境，訓練智能體依技能指引完成任務。
4. **教育與培訓平台**：把教學文件與範例腳本變成難度分級的實作題目，透過自動驗證器即時回饋學習者，並收集高品質軌跡進一步改善教學智能體。
5. **客戶支援與文件處理智能體**：利用文件處理、行銷或客服相關技能，建立可驗證的任務（如格式轉換、內容摘要、合規檢查），讓智能體學會在真實工作空間中正確呼叫技能。

## 實作前置條件

- **資料**：
  - 一批結構化的技能套件（至少包含 `SKILL.md` 說明、參考腳本、依賴清單）。
  - 可離線重現執行的工作流程，避免依賴外部網路或動態服務。
  - 領域相關的初始工作空間範本與測試資產。

- **運算資源**：
  - 能執行隔離沙箱（Docker/container）的運算節點，用於安全執行技能與驗證器。
  - 教師模型 API 或本地推理資源，用於收集已驗證成功軌跡。
  - 微調所需 GPU（視目標模型大小，9B 級模型約需數張 A100/H100 等級顯卡）。

- **技能與工具**：
  - 熟悉 Python、Shell、Docker 與常見智能體框架（如 OpenClaw、mini-swe-agent、Terminus-2、OpenCode）。
  - 具備監督式微調（SFT）經驗，能處理軌跡資料格式與對齊（alignment）。
  - 有能力撰寫可執行驗證器（executable verifier），並設計參考解（reference solution）。

## 實作步驟建議

1. **技能蒐集與篩選**
   - 從公開社群或內部知識庫爬取技能套件。
   - 去重、分類，並只保留能在離線沙箱中可重現執行的工作流程。

2. **建立可執行環境**
   - 對每個技能自動建立 Docker/container 工作空間。
   - 安裝依賴項、放置腳本與資產，確保技能可在隔離環境中運行。

3. **建構者-審查者任務生成**
   - **建構者（Builder）**：根據技能內容產生任務指令、初始狀態、參考解與驗證器。
   - **審查者（Reviewer）**：檢查任務是否技能關鍵（skill-critical）、是否存在資訊洩漏、驗證器是否過於嚴格或寬鬆。
   - 反覆修復直到參考解能讓初始未解任務通過驗證。

4. **軌跡收集**
   - 使用多個教師模型在不同智能體框架上執行任務。
   - 只保留經可執行驗證器確認為成功的軌跡。
   - 進行資料增強（prompt/tool 變體、弱軌跡對齊）以提升多樣性。

5. **監督式微調**
   - 將成功軌跡轉換為 SFT 資料（包含 think/act/observation 序列）。
   - 在 2B–122B 參數規模的目標模型上進行微調。
   - 特別關注模型是否學會主動查閱與呼叫技能。

6. **評估與迭代**
   - 在保留技能（held-out skills）與少數推理結構任務上測試泛化能力。
   - 監控技能查閱率、驗證通過率與有效替代解接受率。
   - 根據失敗案例回流更新任務生成與驗證器。

7. **部署與持續維運**
   - 將微調後模型接入現有智能體框架。
   - 建立技能版本管理與驗證器回歸測試，避免技能更新後任務失效。

## 潛在風險與注意事項

- **驗證器品質**：過於寬鬆會接受表面合理輸出，過於嚴格會拒絕有效替代解。建議引入審查者智能體反覆檢驗，並以人工抽樣審核。
- **執行安全**：技能與參考解可能包含任意程式碼，必須在隔離沙箱中執行，限制網路存取與檔案系統權限。
- **智慧財產權與授權**：社群技能與程式碼可能受授權限制，商用前需確認授權條款並建立內部技能審查流程。
- **分布偏移與過擬合**：訓練軌跡可能過度依賴參考解路徑，導致模型在真實環境中缺乏彈性。應保留部分技能與推理結構作為測試集，並進行多樣性增強。
- **技能更新維護**：技能內容或依賴版本變動會使任務環境失效。建議將環境建立與驗證流程自動化，並定期重新執行回歸測試。
- **模型幻覺與技能誤用**：即使經過 SFT，模型仍可能錯誤解讀技能內容。應保留人機協作審查機制，特別是高風險操作。

## 與其他技術的整合建議

- **RAG 與向量檢索**：將技能套件向量化，讓智能體在推論時先檢索相關技能，再根據 SkillGym 訓練出的使用能力執行任務。
- **現有智能體框架**：可將生成的可執行任務環境與驗證器接入 LangChain、AutoGen、Claude Code、Codex 等框架，作為技能使用訓練與評測後台。
- **CI/CD 與 MLOps**：把環境建構、軌跡收集、驗證與微調流程納入 CI/CD，實現技能更新後自動重新生成訓練資料與模型版本。
- **可觀測性與日誌**：記錄智能體的技能查閱率、動作序列與驗證結果，便於追蹤模型在生產環境中的行為並進行迭代。
- **人機協作審查**：對於高風險或高價值任務，將智能體輸出與執行計畫提交給人類審查者確認後再執行。

## 給不同背景讀者的閱讀建議

- **初學者**：建議先聚焦在「技能是什麼」以及「為什麼需要可驗證環境」這兩個核心概念。可以從適用場景與實作步驟開始，理解整個流程如何從網路上的技能套件變成會用技能的智能體，技術細節如 builder-reviewer 與 SFT 可暫時略過。

- **AI 工程師**：重點閱讀建構者-審查者流程、可執行驗證器設計與軌跡收集策略。這些是將論文方法落地為產品的關鍵，建議同時評估自身資料是否符合「可離線重現」與「技能關鍵」兩大條件，並規劃沙箱安全與微調基礎建設。

- **研究人員**：值得深入分析四種推理結構（程序執行、溯因診斷、約束滿足、偏序規劃）的設計動機，以及保留技能泛化、技能查閱率提升等實驗結果。可進一步探討如何將此方法擴展到更多推理結構，或結合強化學習進行後續優化。

- **產品經理**：請優先關注適用場景、潛在風險與整合建議。判斷公司內部是否有足夠的技能資產與驗證需求，並評估導入 SkillGym 所需的資料整理、運算成本與維運人力，再決定從哪一個垂直領域先做概念驗證。
