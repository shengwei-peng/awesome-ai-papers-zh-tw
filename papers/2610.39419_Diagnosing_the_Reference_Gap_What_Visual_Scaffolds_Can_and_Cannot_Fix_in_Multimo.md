本論文提出了一個核心概念——「參考間隙」(reference gap)，用以描述多模態大型語言模型 (MLLMs) 在視覺推理中無法維持語言與視覺元素之間穩定綁定 (bindings) 的現象。作者區分了「視覺感知失敗」與「參考間隙失敗」：前者是模型未能識別視覺內容，後者則是模型雖然看見了所有物件，卻在多步推理過程中無法穩定地「指回」(refer back to) 這些視覺實體 (visual entities)、區域 (visual regions) 或位置 (visual locations)。

**理論基礎：視覺常規理論 (Visual Routines)**

方法論的理論根基來自 Ullman (1984) 提出的視覺常規理論，該理論將複雜的視覺推理分解為一系列基本操作，包括：焦點轉移 (shifting processing focus)、有界激活 (bounded activation)、邊界追蹤 (boundary tracing)、索引 (indexing) 與標記 (marking)。作者假設 MLLMs 缺乏執行這些視覺常規所需的內部參考框架 (internal reference frames)，因此需要透過外部視覺支架 (visual scaffolds) 來外化中間視覺狀態。

**三類視覺參考系統**

論文設計了三種對應不同視覺常規的外部參考：

1. **編號 (Numbering)**：對應標記與索引操作。將描述依賴的視覺元素轉化為可定址的實體，例如用「形狀 7」取代「左上方的三角形」。這使得模型能夠在多步推理中穩定地重新定位項目並追蹤已處理的項目。

2. **陰影 (Shading)**：對應有界激活操作。透過為角度內部或形狀內部填上陰影，使區域本身變得可見，而不僅僅是可描繪的輪廓。

3. **網格線 (Grid lines)**：對應系統性焦點轉移與邊界追蹤操作。將影像劃分為規則的網格區間，提供位置、寬度、高度、位移與對齊的參考。

**ReGap-Bench 的配對設計**

這是方法論的核心創新。ReGap-Bench 採用嚴格的配對控制 (paired control) 設計：五個視覺推理任務（形狀計數、角度排序、大小排序、時鐘排序、變換預測）中，每個底層場景都以「有視覺參考」與「無視覺參考」兩種版本渲染，而任務相關的物件、幾何、提問與標準答案保持完全不變。這種設計使得任何效能差異都可以歸因於參考本身，而非場景或問題的變化。

## 論文問答

**Q1：什麼是「參考間隙」（reference gap），為什麼這個問題值得特別關注？**
A：「參考間隙」指的是多模態大型語言模型在進行多步驟視覺推理時，無法在語言與相關視覺實體、區域或位置之間維持穩定綁定的現象。這個問題之所以重要，是因為它揭示了一個介於視覺感知與高階推理之間的瓶頸——模型可能正確辨識出畫面中的所有物件，卻在推理過程中遺失對這些物件的追蹤，導致重複計數或遺漏。論文中以計數任務為例，模型可能看見所有形狀，卻因為使用「左側」這類模糊描述而把同一個橢圓算了兩次。這顯示單純提升感知能力並不足以解決多步驟視覺推理的困難，必須正視語言與視覺之間的綁定機制。

**Q2：為什麼現有方法（如高解析度編碼器、更細粒度的視覺特徵）無法有效解決這個問題？**
A：現有方法主要聚焦於提升模型的視覺感知能力，例如採用更高解析度的編碼器或提取更細粒度的視覺特徵，但這些做法預設失敗源自「看不見」或「看不清楚」。然而，論文的分析顯示，許多推理失敗其實發生在感知之後——模型已經正確辨識物件，卻在跨步驟推理中失去對它們的參考。這意味著單純強化感知前端無法觸及問題的核心，因為瓶頸不在於「看見什麼」，而在於「如何持續指稱看見的東西」。因此，必須從視覺常規（visual routines）的角度出發，設計支援語言—視覺綁定的外部參考機制。

**Q3：「參考間隙」與傳統的視覺感知失敗有何本質差異？**
A：視覺感知失敗指的是模型無法正確辨識畫面中的物件、形狀或空間關係，而「參考間隙」則發生在感知成功之後，模型在多步驟推理中無法穩定地「回到」或「區分」已辨識的視覺元素。換言之，感知失敗是「看不見」，參考間隙則是「看見了卻指不回來」。這個區別至關重要，因為它決定了該採取何種解決方案——前者需要更好的編碼器或特徵，後者則需要支援標記、索引、區域活化等視覺常規的外部支架。這也解釋了為何模型規模從 2B 提升到 235B 仍無法消除參考間隙，因為規模擴大主要強化的是感知與語言能力，而非視覺參考框架。

**Q4：ReGap-Bench 是什麼？它如何診斷「參考間隙」？**
A：ReGap-Bench 是一個配對式（paired）基準測試，涵蓋五個視覺推理任務：形狀計數、角度排序、大小排序、時鐘排序與轉換預測。其核心設計在於「場景、題目、答案皆固定，僅改變視覺參考」，因此當模型表現出現差異時，可以歸因於參考本身的效果，而非感知或題目理解的因素。這種控制變因的設計讓研究者能精準衡量不同視覺支架對推理的影響，區分「感知提升」與「參考支援」兩種介入的貢獻。透過這種診斷框架，論文得以驗證「任務匹配的參考能改善表現」這一核心假設。

**Q5：論文中提出哪三類視覺參考？它們如何對應到視覺常規？**
A：論文提出三類視覺參考：編號（numbering）、著色（shading）與格線（grid lines）。編號支援標記（marking）與索引（indexing）兩種視覺常規，讓模型能用「形狀 7」這類明確標籤取代「左上方的三角形」等模糊描述；著色則支援區域活化（bounded activation），例如將角度內部塗色使角度區域本身可見；格線則提供空間標記，支援系統性的焦點切換與邊界追蹤，可用於定位、寬度、高度、位移等空間屬性。這三類參考分別對應不同視覺常規，因此「哪種參考對哪個任務有效」並非任意，而是取決於任務所需的視覺操作類型。

**Q6：什麼是「無需訓練的視覺技能」（training-free visual skill）？它如何動態選擇參考？**
A：這項視覺技能是一個無需微調的機制，讓代理（agent）能在推理時動態辨識任務所需的視覺常規，並據此選擇對應的視覺支架。具體而言，代理會先分析任務類型，判斷需要的是標記、區域活化還是空間追蹤，再從編號、著色、格線中挑選最合適的參考施加於圖像上。這種設計的優勢在於它把「選擇參考」這個決策從模型內部轉移到外部流程，避免了重新訓練的成本。論文在 CartoMapQA 上驗證了這個技能，證明它能在不微調模型的前提下，透過自主選擇參考來改善複雜地圖理解。

**Q7：ReGap-Bench 涵蓋的五個任務是如何設計的？為什麼選這些任務？**
A：五個任務分別為形狀計數、角度排序、大小排序、時鐘排序與轉換預測，每個任務都對應到不同的視覺常規需求。形狀計數需要標記與索引以追蹤已計數項目；角度與大小排序需要區域活化以凸顯角度或形狀的範圍；時鐘排序需要系統性的空間參考以比較時間位置；轉換預測則需要格線支援空間位移的追蹤。這樣的設計讓每個任務都能與特定的視覺參考類型形成「匹配」或「不匹配」的對照，進而驗證「任務—參考匹配」是否為表現提升的關鍵。

**Q8：任務匹配的參考帶來多大的表現提升？有哪些關鍵數據？**
A：論文顯示任務匹配的參考能在所有五個任務上提升模型表現，其中編號在形狀計數上帶來最高 17.5% 的增益，在時鐘排序上更高達 25%；著色改善了角度與大小排序；格線則改善了大小排序與轉換預測。這些數據說明，只要參考類型與任務所需的視覺常規對齊，就能取得顯著且穩定的進步。值得注意的是，這些提升是在不改變場景語義、題目與答案的前提下達成的，因此可歸因於參考本身對推理過程的支援效果。

**Q9：消融實驗（不匹配、不完整、模型規模）揭示了哪些重要發現？**
A：消融實驗從三個面向驗證了論點：首先，當參考與任務不匹配時，表現幾乎沒有改善甚至下降，證明「加任何標記都有幫助」的假設並不成立，關鍵在於匹配；其次，「不完整的參考」（例如只給部分物件編號）效果也大打折扣，顯示參考必須系統性地涵蓋所有相關視覺元素；最後，從 2B 到 235B 的 Qwen3-VL 模型規模測試顯示，參考間隙並不會因模型變大而自動消失，意味著這是一個獨立於規模的結構性問題。這三項消融共同強化了「參考必須匹配任務所需視覺常規」的核心結論。

**Q10：這項研究能應用到哪些實際場景？**
A：這項研究的應用場景相當廣泛，特別是在需要多步驟視覺推理的任務中，例如地圖理解（已在 CartoMapQA 上驗證）、醫療影像分析（追蹤多個病灶或量測結構）、工業檢測（計數瑕疵或比較尺寸）、教育輔助（解題過程中的圖形標記），以及自動駕駛（追蹤多個行人或車輛的相對位置）。這些場景的共同特徵是：模型不只需要「看見」，還需要在多個推理步驟中持續指稱同一個視覺元素，而這正是參考間隙最容易造成錯誤的地方。透過任務匹配的視覺支架，可以顯著降低這類錯誤率。

**Q11：從產品化的角度，這項研究帶來哪些設計考量？**
A：在產品設計上，這項研究提示我們不應只追求更大的模型或更好的編碼器，而應考慮在推理流程中加入「視覺支架生成」這個環節。具體而言，系統可以根據任務類型自動決定是否要疊加編號、著色或格線，並在使用者介面上清楚呈現這些輔助標記，以提升可解釋性與使用者信任。此外，由於這是無需訓練的方法，部署成本低，適合整合到現有的多模態應用中；但設計上也需考量視覺支架對原始圖像的遮擋或干擾，必須在輔助效果與畫面清晰度之間取得平衡。

**Q12：這項研究對多模態 AI 領域的整體影響是什麼？**
A：這項研究的影響在於重新定位了多模態推理失敗的歸因——從「感知不足」轉向「參考缺失」，並提供了一個可操作的診斷與介入框架。它提醒研究者與工程師，視覺推理的瓶頸未必在編碼器或模型規模，而在於語言與視覺之間的綁定機制。同時，「無需訓練的視覺技能」這個概念為多模態代理開啟了一條輕量化的改進路徑，不必動輒微調大型模型就能取得顯著改善。長期來看，這可能推動領域從「端到端黑箱」走向「感知＋支架＋推理」的模組化設計。

**Q13：這項研究有哪些已承認的限制？**
A：論文承認的限制包括：ReGap-Bench 僅涵蓋五個任務與三類參考，未必能涵蓋所有視覺推理場景；測試的模型以 Qwen3-VL 系列為主，跨模型的泛化性仍待更多驗證；視覺支架的效果可能因任務難度、物件數量或圖像複雜度而有所不同，論文中對這些變因的系統性分析仍有限。此外，「無需訓練的視覺技能」仰賴代理正確判斷任務所需的視覺常規，若判斷錯誤，支架本身可能成為干擾而非助力。

**Q14：在哪些情況下，這項方法可能仍然失敗？**
A：這項方法可能在以下情況失效：當任務所需的視覺常規超出編號、著色、格線三類支架所能支援的範圍時；當圖像本身極為擁擠或物件高度重疊，導致編號或著色難以清楚區分時；當代理錯誤判斷任務類型而選錯參考時；以及當任務需要跨多張圖片的參考追蹤，而現有設計僅處理單張圖片時。此外，對於需要極精細空間量測的任務，格線的解析度可能不足以提供足夠的參考精度。

**Q15：這項研究開啟了哪些值得探索的未來方向？**
A：未來方向包括：擴展視覺支架的類型（例如箭頭、虛線框、動畫標記）以覆蓋更多視覺常規；將參考選擇機制從「任務級」推向「實例級」，讓代理能根據具體圖像內容動態決定最適合的支架；探索如何讓模型內部學會產生參考，而非完全依賴外部疊加；以及將這套框架應用於影片或多張圖片的時序推理。此外，研究參考間隙與其他推理瓶頸（如規劃、記憶）之間的交互作用，也是值得深入的方向。

## 實務應用指南

### 適用場景

1. **複雜地圖與導航問答系統**：將地圖影像自動加上網格線或區域標號，使模型能穩定參照特定座標或區塊，回答「從 A 點到 B 點最短路徑經過幾個交叉口」這類多步驟問題，適用於物流路徑規劃、旅遊行程助手。

2. **醫療影像報告輔助**：在 CT、MRI 或病理切片影像中對病灶加上編號或陰影標記，協助模型依序描述每個病灶的大小、位置與數量，減少遺漏或重複計數，提升放射科報告初稿品質。

3. **工業品管視覺檢測**：在產線影像中對瑕疵區域加上編號或陰影，使模型能逐一列舉瑕疵類型、位置與嚴重程度排序，支援 SPC 統計與異常追蹤。

4. **幾何與科學教育輔助**：對幾何圖形加上角度陰影、長度編號或座標網格，讓學生提問「比較這些三角形角度大小」時，模型能給出可驗證的逐步推理，而非含糊描述。

5. **圖表與儀表板理解**：對長條圖、折線圖加上資料點編號或區塊陰影，使模型能正確回答「第三季到第四季哪個產品成長最多」這類需要跨多個視覺元素比較的問題。

### 實作前置條件

- **資料準備**：
  - 具備目標任務的影像資料集，且每張影像需能產出「無參考」與「有參考」兩種版本（場景、題目、答案固定，僅改變參考標記）。
  - 標註資料需包含視覺實體清單（物件、區域、座標），用於自動產生編號、陰影或網格。
  - 建議先以 ReGap-Bench 的五類任務（形狀計數、角度排序、大小排序、時鐘排序、轉換預測）作為驗證基準。

- **運算資源**：
  - 推論階段需部署多模態大型語言模型（MLLM），論文實驗涵蓋 Qwen3-VL 2B 至 235B；中小規模場景可用 7B–30B 等級模型搭配高效推論框架（如 vLLM、SGLang）。
  - 影像前處理（標記生成、座標計算）僅需輕量 GPU 或 CPU 即可。
  - 若需訓練參考選擇代理，則需額外 GPU 資源進行監督微調或 RLHF。

- **技能需求**：
  - 熟悉 MLLM 提示工程（prompt engineering）與視覺標記生成（可使用 OpenCV、Pillow 或 SVG 編輯器）。
  - 具備影像理解任務的評估能力，能設計配對測試以分離「參考效果」與「模型能力」差異。
  - 若要實作訓練自由的視覺技能代理，需具備 agent 框架設計經驗（如 LangChain、AutoGen）。

### 實作步驟建議

1. **診斷現有系統的參考間隙**：先挑選 50–100 個典型失敗案例，分析是屬於感知錯誤（物件沒看到）還是參考錯誤（看到了但推理時遺失綁定）。若屬後者，本方法才有幫助。

2. **建立任務–參考對映表**：依據視覺常規理論，將業務任務分類：
   - 需要「標記/索引」→ 編號（計數、列舉、追蹤）
   - 需要「區域活化」→ 陰影（角度、面積、範圍比較）
   - 需要「系統性掃描/邊界追蹤」→ 網格線（位置、位移、對齊）

3. **產生配對影像**：撰寫腳本自動為每張原圖生成對應的參考版本，確保題目與答案不變。可參考 ReGap-Bench 的渲染流程，使用 SVG 或 PIL 標註層。

4. **建立參考選擇代理（訓練自由的視覺技能）**：
   - 步驟一：讓 MLLM 先讀題，輸出所需的視覺常規類型（標記/區域/掃描）。
   - 步驟二：依類型自動呼叫對應的影像處理工具，加上編號、陰影或網格。
   - 步驟三：將加上參考的影像與原題目送回 MLLM 推理。
   - 此流程無需微調模型本體，僅需設計良好的工具呼叫 prompt。

5. **A/B 驗證與迭代**：在內部資料集上比較「無參考」與「任務匹配參考」的準確率，預期可獲得 10–25% 的提升；若提升有限，檢查參考類型是否真的對應任務需求。

6. **部署與監控**：將參考生成管線整合到推論服務前端，記錄每次任務使用的參考類型與效果，持續監控是否出現「不匹配反而傷害」的情況。

### 潛在風險與注意事項

- **不匹配參考反而降低效能**：論文明確指出，錯誤的參考（例如在計數任務用網格）幾乎無助益甚至有害。上線前務必驗證任務–參考對映的正確性。
- **參考遮蔽視覺內容**：過度密集的編號或陰影可能遮擋關鍵細節，需控制標記密度與透明度。
- **模型規模無法消除參考間隙**：論文實驗顯示從 2B 到 235B 仍存在參考問題，不要期待「換更大的模型就會自動解決」。
- **泛化性未知**：ReGap-Bench 涵蓋五類任務，若業務場景超出此範圍（如動態影片、3D 點雲），效果可能不同，需自行驗證。
- **標記生成成本**：每張影像都需額外前處理，若延遲敏感場景（如即時客服）需評估管線總延遲。
- **評估指標偏誤**：單看整體準確率可能掩蓋部分任務的退化，建議分任務、分參考類型報告結果。

### 與其他技術的整合建議

- **與 Chain-of-Thought (CoT) 結合**：在加上視覺參考後，要求模型以「參考編號」逐步推理（例如「先看 3 號形狀，再看 7 號…」），可進一步強化多步驟推理穩定性。
- **與 RAG 整合**：將參考標記的視覺實體與外部知識庫連結，例如編號 5 對應到資料庫中的特定產品 ID，使模型能跨視覺與文字模組引用。
- **與視覺工具（Grounding DINO、Segment Anything）整合**：先用偵測/分割模型自動產生物件 bounding box 或 mask，再轉成編號或陰影標記，自動化整個管線。
- **與 Agent 框架整合**：將參考選擇代理包裝為工具，讓上層 agent 根據任務動態決定是否呼叫視覺支架工具，支援更複雜的多步驟工作流。
- **與人類回饋強化學習（RLHF）結合**：蒐集使用者對「有/無參考」回答品質的偏好，可用於微調參考選擇策略，但模型本體仍維持訓練自由。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先讀第 1 節的圖 1 範例，理解「參考間隙」的概念——模型看得到物件，卻在多步驟推理中遺失對物件的綁定。接著瀏覽第 2.2 節關於三種視覺參考（編號、陰影、網格）的說明，建立直覺後再回頭看實驗結果。

- **AI 工程師**：重點放在第 2 節的視覺常規對映與第 3 節的訓練自由視覺技能實作。可直接參考 ReGap-Bench 的任務設計與 CartoMapQA 的評估方式，將其改造為內部基準；提示工程與影像標記管線是落地關鍵。

- **研究者**：第 4 節的模型規模分析（2B 到 235B 參考間隙仍存在）與不匹配參考的負面結果，是值得延伸的方向。可考慮探索更多視覺常規類型、跨模態綁定機制，或將參考間隙理論應用於影片、3D 等其他模態。

- **產品經理**：核心訊息是「換更大的模型無法解決所有視覺推理問題」，但「加上對的視覺標記可以無需訓練地提升 10–25% 準確率」。評估自家產品的視覺推理失敗案例時，應區分感知問題與參考問題，並將視覺支架視為低成本、高回報的優化手段。
