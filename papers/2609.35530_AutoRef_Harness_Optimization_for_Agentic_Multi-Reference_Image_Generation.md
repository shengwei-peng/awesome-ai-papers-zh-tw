## ⚡ TL;DR

多參考圖像生成中，人工設計的Harness難以兼顧各參考角色與整體自然度，常出現遺漏、重複或拼貼感。
本文提出AutoRef，讓編碼代理在凍結模型下迭代重寫Harness，以分離任務的束搜尋進行最佳化。
使FLUX.2 4B於MultiBanana四參考測試從5.72→7.37，匹敵專有模型跨設定泛化。

## 摘要翻譯

近期圖像生成模型（Image Generation Models）已能接受多張參考圖像（reference images）作為輸入，並將其組合成一張新圖像。然而，多參考圖像生成（Multi-Reference Image Generation）仍具挑戰：模型可能遺漏或重複參考圖像中的主體，也可能使多個主體呈現不自然的拼貼感（Pasted Appearance）。近期研究提出了圖像生成代理（Image Generation Agents），結合圖像生成模型、推理模型（reasoning models）以及一個 Harness（可執行控制架構）；此可執行程式（Executable Program）指定如何解讀參考圖像、如何執行生成、如何診斷輸出（Output Diagnosis），以及如何選擇最終圖像（Output Selection）。然而，在多參考生成中，參考圖像扮演不同角色，且輸出必須同時滿足多項標準，例如對每張參考圖像的保真度（Fidelity）以及整體圖像的自然度（Naturalness），因此 Harness 的許多環節都有改進空間，從參考圖像的處理方式到輸出的診斷方式皆然。這使我們難以預測哪些改變會提升表現以及提升多少，也讓良好的 Harness 難以手工設計；事實上，人工撰寫的 Harness（Human-Written Harnesses）表現差異甚大。因此，我們提出 AutoRef，在保持圖像生成模型與推理模型均凍結（Frozen Models）的前提下，自動最佳化 Harness（Harness Optimization）：一個編碼代理（Coding Agent）會迭代重寫（Iterative Rewriting）Harness 程式碼（Harness Code）。AutoRef 將「用於提供回饋以形成提案的任務」與「用於選擇候選（Candidates）的任務」分開，並從在選擇任務上排名最高的 Harness 所組成的束（Beam）中繼續搜尋。透過此流程，我們發現 AutoRef-Harness，它使開放權重（Open-Weight）的 FLUX.2 [klein] 4B 在 MultiBanana 基準測試（MultiBanana Benchmark）保留的四參考任務（Held-Out Four-Reference Tasks）上，從 5.72 提升至 7.37，達到或超越包括 Nano Banana Pro 與 GPT-Image-1.5 在內的專有模型（proprietary models）。無需重新最佳化，當生成器（Generator）、參考圖像數量、基準測試（Benchmark）、評估器（Evaluator）或推理模型與搜尋時使用的設定不同時，相同的 Harness 仍能改善結果。

### 核心貢獻（3～5點）
- 提出 AutoRef，首個針對代理式多參考圖像生成（Agentic Multi-Reference Image Generation）之 Harness（可執行控制架構）進行自動最佳化的框架，無需重新訓練或微調任何圖像生成與推理模型。
- 設計基於編碼代理（Coding Agent）的迭代重寫（Iterative Rewriting）與束搜尋（Beam Search）機制，將回饋任務與選擇任務分離，以降低雜訊視覺評估（Noisy Visual Evaluation）對搜尋的干擾。
- 發現 AutoRef-Harness，顯著提升開放權重模型 FLUX.2 [klein] 4B 在 MultiBanana 基準測試保留四參考任務上的表現，並達到或超越多項專有模型。
- 驗證 AutoRef-Harness 具備良好的泛化能力：在生成器、參考圖像數量、基準測試、評估器或推理模型與搜尋設定不同時，無需重新最佳化即可持續改善結果。

### 適合對象
從事圖像生成、多模態代理系統、自動化機器學習（AutoML）與視覺評估研究的學者與工程師；特別是對於希望在不重新訓練模型的前提下，透過最佳化控制架構來提升多參考圖像生成品質的實務工作者與研究人員。

## 深度分析

#### 方法論解析

AutoRef 的核心目標是在**凍結模型（Frozen Models）**—即不更新圖像生成模型（Image Generation Models）與推理模型（Reasoning Models）權重的情況下—自動最佳化 **Harness（可執行控制架構）**。這裡的 Harness 是一段**可執行程式碼（Harness Code）**，決定了參考圖像如何被解讀、提示詞（prompts）如何建構、候選圖像（Candidates）如何生成與評估，以及最終輸出如何被選出。由於多參考圖像生成（Multi-Reference Image Generation）中，每張參考圖像可能扮演不同角色（如身份 Identity、背景 Background、風格 Style），且輸出必須同時滿足對每張參考的**保真度（Fidelity）**與整體**自然度（Naturalness）**，人工設計 Harness 的效果差異極大，因此自動化搜尋成為必要。

AutoRef 將 Harness 最佳化形式化為：

\[
H^\star = \arg\max_H J(H), \quad J(H)=\mathbb{E}_{x\sim p_{\text{task}}, y\sim H(M_\theta,G_\phi,x)}[R(y,x)]
\]

其中 \(R(y,x)\) 是視覺**評估器（Evaluator）**給出的純量分數。與數學或程式驗證任務不同，圖像生成面臨的是**雜訊視覺評估（Noisy Visual Evaluation）**：單一純量分數難以提供足夠的**診斷資訊（Diagnostic Information）**，且反覆在同一組任務上搜尋容易對搜尋任務與評估器產生過擬合。為此，AutoRef 提出兩項關鍵設計：

1. **提議任務與選擇任務分離**：用於產生 Harness 修改建議的任務（proposal tasks）與用於評比候選 Harness 的任務（selection tasks）被切開，避免選擇過程重複使用命題者已見過的樣本，從而降低過擬合風險。
2. **迭代式束搜尋（Iterative Beam Search）**：每一輪由**編碼代理（Coding Agent）**根據當前 Harness 與歷史紀錄（包含過去 Harness 實作、分數、執行軌跡 Trajectory）提出修改；接著在選擇任務上評分，保留排名最高的數個 Harness 作為下一輪的父代（Parents），而非讓命題者自行挑選。這樣的「beam」機制讓搜尋同時維護多條有潛力的控制策略，並透過保留任務上的實證表現決定存續。

經由上述流程，AutoRef 發現了 **AutoRef-Harness**。該 Harness 具備幾個可解釋的策略性元件：

- **Reference-Grounded Prompting（參考接地提示）**：將多張參考圖像的資訊明確編入生成提示，降低模型遺漏或重複主體的機率。
- **Structurally Diverse Drafts（結構多樣的草稿）**：一次生成多個結構差異較大的候選圖像，增加涵蓋不同構圖與佈局的可能性。
- **Explicit Complaints（明確抱怨）**：對較好的草稿進行具體缺陷描述，再據此修正，類似於人類設計師的迭代批註流程。
- **Failure-Aware Comparisons（失敗感知比較）**：在最終**候選選擇（Candidate Selection）**階段，不只看整體分數，而是考量常見失敗模式（如主體遺漏、重複、**拼貼感 Pasted Appearance**）來比較候選。

整體而言，AutoRef 並非改進生成器本身的參數，而是透過程式層級的搜尋，學習如何更有效地調度凍結模型，屬於一種「推理時間規模化（inference-time scaling）」或「控制策略搜尋」的範式。

#### 實驗數據解讀

論文的主要實驗結果圍繞 **MultiBanana 基準測試（MultiBanana Benchmark）** 的保留四參考任務（Held-Out Four-Reference Tasks）展開。使用開放權重模型 **FLUX.2 [klein] 4B** 作為**生成器（Generator）**，原始 Harness 得分為 5.72，經 AutoRef 最佳化後的 AutoRef-Harness 得分提升至 7.37。這個增幅約為 1.65 分，相當於近 29% 的相對提升，顯示 Harness 設計對最終表現具有決定性影響。

更具指標意義的是，AutoRef-Harness 讓 FLUX.2 [klein] 4B 能夠**匹配或超越**多個專有模型（Proprietary Models），包括 **Nano Banana Pro** 與 **GPT-Image-1.5**。這意味著在凍結開放權重生成器的前提下，僅透過控制程式的自動搜尋，就能達到與閉源、可能經過大量後訓練或專用調整的模型相當的水準。這對於重視可部署性、成本與透明度的應用場景具有重要價值。

另一組關鍵結果是**跨條件泛化性（generalization）**：AutoRef-Harness 在未重新最佳化的情況下，當下列條件改變時仍能提升表現：

- 更換**生成器（Generator）**
- 改變參考圖像數量（number of references）
- 更換**基準測試（Benchmark）**
- 更換**評估器（Evaluator）**
- 更換**推理模型（Reasoning Model）**

這顯示 AutoRef-Harness 學到的並非僅是對 FLUX.2 [klein] 4B 或 MultiBanana 評估器的過擬合技巧，而是某種相對通用的多參考生成控制原則。然而，論文未詳細說明泛化實驗的具體數據分布與統計顯著性，這是讀者在解讀時需要留意的部分。此外，所有分數皆來自自動化視覺評估器，雖然客觀，但未必完全對應人類主觀偏好；若評估器本身對某些視覺屬性（如自然度或身份保真度）有偏，最佳化後的 Harness 可能會針對這些偏誤進行適應。

#### 與現有研究的比較

在多參考圖像生成領域，近期研究主要朝兩個方向發展：一是透過擴充參考條件訓練資料與微調底層模型來提升能力；二是透過代理式流程（Agentic Workflows）進行迭代式規劃、生成與診斷。AutoRef 屬於後者，但與先前工作有明顯區別。

相較於 **MultiBanana** 中展示的簡單代理式精修（simple agentic refinement），AutoRef 證明僅把強生成器包上一層固定代理流程是不夠的；真正重要的是 Harness 程式碼本身的結構與策略。相較於 **DreamBooth** 等針對單一主體個人化的方法，AutoRef 處理的是更一般化的多參考組合場景，且無需修改模型權重。

在自動化代理最佳化方面，過去研究多聚焦於提示詞（Prompts）、模組化管線（Modular Pipelines）或固定程式內的提示調整。例如 **Meta-Harness** 讓編碼代理閱讀程式碼、分數與執行軌跡後選擇父代並修改 Harness，但其候選評分與反饋來源使用同一組任務，較易過擬合。**AutoDesign** 則將 Harness 最佳化應用於學術海報生成。AutoRef 的創新在於針對圖像生成的特性，明確分離提議與選擇任務，並採用迭代式束搜尋，這對於雜訊大、診斷資訊稀少的視覺評估尤為重要。

然而，AutoRef 也存在一些限制。首先，最佳化目標完全依賴可取得的自動化評估器分數，若評估器無法捕捉某些失敗模式（例如細微的身份不一致或文化語境錯誤），Harness 可能無法學會避免這些問題。其次，搜尋過程需要反覆執行圖像生成與評估，計算成本顯著高於單次生成，雖然論文未明確報導總運算量，但這是實際部署時必須考量的因素。第三，Harness 的表現上限仍受限於凍結生成器與推理模型的固有能力；對於模型完全無法理解的組合關係，AutoRef 無法透過控制程式彌補。

#### 可重現性評估

可重現性（Reproducibility）是評估此類方法的重要面向。根據論文所述，作者已釋出程式碼與 AutoRef-Harness，這對社群是正面訊號。由於使用的底層生成器 FLUX.2 [klein] 4B 是**開放權重（Open-Weight）**模型，其他研究者原則上可以取得相同模型進行比較。MultiBanana 基準測試若為公開資料集，則主要實驗條件可被複製。

不過，仍有幾個潛在的可重現性挑戰：

- **評估器（Evaluator）**：若論文使用的視覺評估器是專有模型或未公開的評分流程，則即使 Harness 與生成器相同，其他團隊也可能難以重現完全一致的分數。這會影響結果的比較基準。
- **編碼代理（Coding Agent）**：AutoRef 依賴具備程式理解與修改能力的強大語言模型作為命題者。若該代理是閉源 API（例如 GPT-4 等級模型），則不同版本、溫度參數或 API 行為變化都可能導致搜尋軌跡不同，進而產生不同的最佳 Harness。
- **搜尋隨機性**：迭代式束搜尋涉及多次隨機生成與代理決策，若未固定亂數種子與詳細記錄搜尋歷史，重複執行可能得到略有差異的結果。
- **硬體與執行環境**：圖像生成與大規模評估需要 GPU 資源，論文若未提供完整的執行腳本與環境設定，重現門檻會較高。

整體而言，AutoRef 在開源釋出方面優於許多僅報告閉源結果的研究，但要達成嚴格可重現，仍需評估器、代理模型版本與完整搜尋配置的透明化。

#### 未來研究方向

AutoRef 為多參考圖像生成的自動化控制策略搜尋開啟了多條後續研究路徑：

1. **與模型微調的聯合最佳化**：目前 AutoRef 完全凍結生成器與推理模型。未來可探索「Harness 最佳化」與「輕量模型適應（如 LoRA 或提示微調）」的交替進行，以突破純控制策略的上限。
2. **更豐富的回饋訊號**：除了純量分數，可引入語言形式的詳細批註、人類偏好比較、或視覺語言模型（VLM）產生的結構化診斷報告，作為 Harness 修改的依據。
3. **擴展至影片與多模態生成**：多參考概念同樣適用於影片生成、3D 場景合成與跨模態編輯。將 AutoRef 的 Harness 搜尋框架延伸至時間一致性與多模態一致性任務，是具潛力的方向。
4. **減少獎勵駭取（Reward Hacking）**：由於最佳化目標是評估器分數，Harness 可能學會利用評估器盲點。未來可發展對抗式評估器集合或人機協作驗證，提升最佳化結果的真實品質。
5. **可解釋與模組化 Harness 設計**：AutoRef 發現的 Harness 雖具可解釋元件，但仍可能包含冗餘或隱晦邏輯。研究如何將搜尋結果整理為可重複使用的模組庫，並讓人類設計師理解與調整，有助於實務應用。
6. **元學習與跨基準遷移**：進一步研究 AutoRef-Harness 的泛化機制，發展能夠在新基準或新任務上快速適應的元 Harness，降低每次面對新任務都需重新搜尋的成本。
7. **人類在迴路中的最佳化**：將人類審美判斷與 AutoRef 的自動搜尋結合，可在廣告、虛擬試穿（Virtual Try-On）、內容創作（Content Creation）等需要品牌一致性與主觀品質的應用中取得更好平衡。

總結來說，AutoRef 不僅提出了一個具體的 Harness 最佳化方法，更示範了在凍結強大生成模型的時代，如何透過自動化程式搜尋來釋放現有模型的潛能。其對任務分離、束搜尋與失敗感知設計的強調，為未來代理式視覺生成系統的設計提供了重要參考。

## 論文問答

**Q1：什麼是多參考圖像生成，目前面臨哪些核心挑戰？**

A：多參考圖像生成是指模型同時接收多張參考圖像，並將其中的元素（如人物、物品、服裝、背景或風格）融合成一張新圖像的任務。然而，這類任務極具挑戰性，因為模型可能遺漏或重複某些參考主體，也可能讓不同主體看起來像被硬貼上去，無法形成連貫場景。這些問題源於每張參考圖像扮演不同角色，而輸出必須同時滿足對每張參考的保真度以及整體自然度等多重標準。

**Q2：為什麼現有的人工撰寫 Harness 無法充分解決多參考圖像生成的問題？**

A：人工撰寫的 Harness 效能差異很大，因為設計者難以預測每一處修改對最終生成品質的影響。在多參考情境中，參考圖像可能代表身份、背景或風格等不同語義角色，輸出又必須同時兼顧多項評估準則，使得 Harness 的設計空間極為複雜。因此，單靠人工經驗很難系統性地找到高品質的執行流程，導致現有方法表現參差不齊。

**Q3：相較於數學或程式碼等可驗證任務，為何圖像生成的自動化代理最佳化特別困難？**

A：數學與程式碼任務通常具有離散且可驗證的正確答案，而圖像生成依賴的是帶有雜訊的視覺評估，僅靠單一數值分數難以診斷問題所在。視覺評估器的主觀性與不穩定性會讓最佳化過程容易過度擬合到搜尋任務與評估器本身。此外，生成失敗的原因往往無法從純量獎勵中直接推導，這使得自動化 Harness 最佳化在圖像領域面臨獨特的挑戰。

**Q4：AutoRef 的核心方法是什麼？**

A：AutoRef 提出在凍結圖像生成模型與推理模型的前提下，自動最佳化周圍的 Harness 程式碼。具體而言，它使用一個編碼代理反覆重寫 Harness，並透過迭代式束搜尋維護表現最佳的候選 Harness。整個過程不更新模型權重，而是針對提示建構、候選生成、輸出診斷與選擇等執行流程進行最佳化。

**Q5：AutoRef 相較於先前 Harness 最佳化方法的關鍵創新為何？**

A：AutoRef 的關鍵創新在於將「用於產生修改建議的任務」與「用於挑選候選 Harness 的任務」分開，避免選擇過程重複使用命題者已見過的樣本而導致過度擬合。此外，它採用迭代式束搜尋，讓下一輪修改是從在選擇任務上排名最高的多個 Harness 出發，而非僅依賴命題者挑選的單一 Harness。這兩項設計共同提升了在雜訊視覺評估環境下的搜尋穩定性與泛化能力。

**Q6：AutoRef 在設計上做了哪些重要選擇來確保搜尋效果？**

A：AutoRef 選擇同時維護一個 Harness 束，讓搜尋過程保留多樣性的高品質父代，而非只追蹤單一最佳解。它也刻意區分訓練證據與選擇任務，使候選 Harness 的評分能反映其對未見樣本的泛化表現。此外，透過讓編碼代理能檢視歷史 Harness 實作、分數與執行軌跡，AutoRef 讓後續修改能基於失敗模式進行診斷式改進。

**Q7：AutoRef 使用了哪些基準測試與模型進行評估？**

A：AutoRef 在 MultiBanana 基準測試上進行評估，並使用開放權重的 FLUX.2 [klein] 4B 作為圖像生成器。實驗特別關注保留的四參考任務，以檢驗方法對未見樣本的泛化能力。同時，研究也將結果與 Nano Banana Pro、GPT-Image-1.5 等專有模型進行比較。

**Q8：AutoRef 取得了哪些關鍵實驗結果？**

A：AutoRef 發現的 AutoRef-Harness 讓 FLUX.2 [klein] 4B 在保留的四參考 MultiBanana 測試集上從 5.72 分提升至 7.37 分。這一成績已達到或超越 Nano Banana Pro 與 GPT-Image-1.5 等專有模型的表現。更重要的是，該 Harness 無需重新最佳化即可在不同生成器、參考數量、基準測試、評估器與推理模型上持續帶來改善。

**Q9：AutoRef 的泛化與消融結果透露了什麼訊息？**

A：實驗顯示 AutoRef-Harness 在生成器、參考數量、基準測試、評估器與推理模型改變時仍能提升結果，顯示其學到的是具有通用性的執行策略，而非僅針對特定設定過度擬合。這也說明 Harness 層級的最佳化能夠補強底層生成器的不足，並在不同評估標準下保持穩健。這樣的泛化能力是 AutoRef 相較於單純針對固定流程進行提示調整的重要優勢。

**Q10：多參考圖像生成在哪些實際應用場景中具有價值？**

A：多參考圖像生成在廣告、虛擬試穿與內容創作等領域具有直接應用價值，因為使用者可以分別用不同圖像指定人物、物品、服裝、背景與風格。例如，在廣告製作中，行銷人員可以將產品圖、模特兒照片與場景風格圖結合，快速產出符合品牌需求的視覺素材。這種細粒度的控制方式大幅降低了專業圖像創作的門檻與時間成本。

**Q11：從產品化角度來看，AutoRef 有哪些值得注意的考量？**

A：AutoRef 在最佳化過程中保持生成模型與推理模型凍結，僅修改可執行的 Harness 程式碼，這意味著部署時無需重新訓練昂貴的基礎模型。此外，一旦發現優質 Harness，便可跨不同模型與任務設定重複使用，減少人工提示工程的需求。這種設計特別適合需要快速適應多種生成場景的產品系統。

**Q12：AutoRef 對整個圖像生成與代理系統領域可能帶來什麼影響？**

A：AutoRef 證明了透過自動化 Harness 最佳化，開放權重模型也能在複雜多參考任務上匹敵甚至超越專有模型。它將自動化代理最佳化從可驗證任務拓展到雜訊視覺領域，為多模態代理系統的設計提供了新範式。未來，這類方法可能成為結合強大生成模型與靈活執行流程的標準做法。

**Q13：AutoRef 目前存在哪些主要限制？**

A：AutoRef 仍依賴視覺評估器提供的分數，而這些分數本身帶有雜訊且可能無法完整捕捉人類對圖像品質的判斷。由於每一輪都需要實際執行 Harness 並評估多個候選，整體搜尋過程在計算成本上可能相當高昂。此外，Harness 的搜尋空間龐大，AutoRef 並不保證能找到全局最佳解。

**Q14：AutoRef 在哪些情況下可能仍然失敗？**

A：當任務涉及極為複雜的空間關係或少見的參考組合時，即使經過最佳化的 Harness 也可能無法產生理想結果。雜訊評估分數有時會導致系統選擇看似分數高、但實際視覺品質較差的候選 Harness。此外，若評估指標未能涵蓋某些失敗模式，例如文化語境或細微風格不一致，這些問題可能無法在搜尋過程中被有效發現與修正。

**Q15：AutoRef 未來可以朝哪些方向發展？**

A：未來可將 AutoRef 拓展至影片生成、3D 合成等其他多模態生成任務，進一步驗證其通用性。另一個方向是開發能提供更豐富診斷資訊的評估器，例如能指出具體失敗區域或給出結構化批評的視覺模型。此外，結合 Harness 最佳化與基礎模型微調，或許能同時發揮執行流程改進與模型能力增強的綜效。

## 實務應用指南

## 適用場景

1. **電商與廣告素材生成**：行銷團隊可上傳產品主圖、品牌色調參考、模特兒姿勢與背景風格四張圖，由 AutoRef-Harness 自動生成符合品牌一致性且構圖自然的廣告圖，減少反覆人工合成。
2. **虛擬試穿與造型搭配**：使用者提供人物照片、服裝正面、服裝細節與場景參考，系統生成人物穿著該服裝、處於指定場景的自然影像，避免衣服浮貼或人物特徵遺失。
3. **遊戲與影視概念美術**：美術師以角色設計、武器/道具、氛圍參考與風格參考進行多參考生成，快速產出連貫場景草圖，再從結構多樣的候選中挑選最符合敘事需求的版本。
4. **室內設計與空間改造**：輸入空間照片、家具單品、材質紋理與風格參考，生成家具自然擺放後的空間效果圖，降低「物件被硬貼上去」的不自然感。
5. **社群內容創作**：創作者以主體照片、背景、濾鏡風格與構圖參考，批次產出風格統一但構圖多樣的內容，並透過失敗感知比較機制篩選最佳成品。

## 實作前置條件

- **資料準備**：
  - 每個任務需 2–4 張（或更多）參考圖像，並清楚標示每張圖的角色（身份、背景、風格、物件等）。
  - 對應的使用者提示（user prompt）與期望輸出描述。
  - 用於搜尋與最終驗證的保留測試集，且兩者不可重疊，以避免過度擬合評估器。
- **運算資源**：
  - 可執行開放權重圖像生成模型（如 FLUX.2 [klein] 4B）的 GPU。
  - 可呼叫推理模型（reasoning model）與視覺評估器（evaluator）的 API 或本地端點。
  - 執行 AutoRef 迭代束搜尋所需的額外運算預算，因為每次迭代都需生成並評估多個候選 Harness。
- **技術能力**：
  - 熟悉 Python 與可執行程式碼（executable code）開發。
  - 具備提示工程（prompt engineering）與多模態評估設計經驗。
  - 能夠閱讀與修改 Harness 程式碼，並理解候選生成、輸出診斷與候選選擇的流程。

## 實作步驟建議

1. **定義任務與成功指標**：明確每張參考圖的角色（身份、背景、風格、物件），並設定可量化的評估維度，例如對每張參考的保真度（fidelity）、整體自然度（naturalness）、主體是否遺漏或重複。
2. **建立分層資料集**：將資料分為「用於編碼代理提出修改的任務集」與「用於選擇候選 Harness 的任務集」，兩者必須分離，以降低過度擬合風險。
3. **選定凍結模型**：選擇圖像生成器（generator）與推理模型（reasoning model），並在整個 Harness 最佳化過程中保持其權重凍結。
4. **設計初始 Seed Harness**：撰寫第一版 Harness，包含參考解讀、提示建構、候選生成、輸出診斷與輸出選擇等基本模組，作為 AutoRef 搜尋的起點。
5. **執行 AutoRef 迭代束搜尋**：
   - 讓編碼代理（coding agent）根據歷史分數與執行軌跡（execution trajectories）重寫 Harness 程式碼。
   - 每輪保留在選擇任務上表現最佳的若干 Harness 作為下一輪父代（parents）。
   - 持續收集所有候選（包含被拒絕者）的訓練證據，供後續診斷使用。
6. **驗證與泛化測試**：在完全保留的測試集上評估最佳 Harness，並嘗試更換生成器、參考圖數量、基準測試（benchmark）、評估器或推理模型，確認 AutoRef-Harness 是否仍具穩定提升。
7. **部署與監控**：將最佳化後的 Harness 整合至產品流程，持續收集使用者回饋與失敗案例，定期重新啟動搜尋或進行局部調整。

## 潛在風險與注意事項

- **過度擬合評估器與搜尋任務**：視覺評估分數具有雜訊（noisy visual evaluation），若反覆在同一批任務上最佳化，Harness 可能學會取悅評估器而非真實品質。應嚴格區分「提出修改用任務」與「選擇候選用任務」，並使用獨立保留集驗證。
- **主體遺漏、重複或拼貼感**：即使 Harness 已最佳化，仍可能出現 omission、duplication 或 pasted appearance。建議在 Harness 中加入明確抱怨（explicit complaints）修正與失敗感知比較（failure-aware comparisons）機制，並保留人工最終審核。
- **運算與成本爆炸**：每次迭代都需生成多張候選圖像並呼叫推理模型，成本可能快速累積。應先以小規模資料驗證搜尋設定，再擴大至完整資料集。
- **版權與隱私**：參考圖像可能涉及人物身份、品牌素材或受版權保護內容。需建立授權審查、去識別化與內容過濾機制，確保生成與部署符合法規。
- **分佈偏移脆弱性**：AutoRef-Harness 在論文中展現了跨模型與跨基準的泛化能力，但若實際應用場景與搜尋時的任務分佈差異過大，仍可能衰退。建議持續監控並定期以新資料微調 Harness。

## 與其他技術的整合建議

- **數位資產管理（DAM）與產品資訊管理（PIM）**：將參考圖像與角色標籤（身份、背景、風格、物件）儲存於 DAM/PIM，讓 Harness 自動讀取並對應到正確的參考角色。
- **內容管理系統（CMS）與廣告投放平台**：將 AutoRef-Harness 包裝為 API 服務，嵌入 CMS 或廣告素材工作流，實現批次生成、版本控制與一鍵發布。
- **MLOps 與 CI/CD**：把 Harness 程式碼納入版本控制，建立自動化測試管線，對每次 Harness 變更執行保留集評估，確保新版本的 Harness 不會在關鍵指標上倒退。
- **A/B 測試與使用者回饋迴路**：將 Harness 產生的多個候選圖像投入 A/B 測試，收集點擊率、轉換率或使用者偏好，並將這些訊號回傳作為下一輪 AutoRef 搜尋的輔助評估依據。
- **人工審核與安全過濾層**：在 Harness 輸出後加入內容安全模型與人工審核閘道，特別是針對人物身份、品牌標誌與敏感場景，避免不當輸出直接上線。

## 給不同背景讀者的閱讀建議

- **初學者**：建議先從「多參考圖像生成」的基本概念與常見失敗模式（主體遺漏、重複、拼貼感）讀起，理解 Harness 如何像一個「指揮程式」協調生成器與推理模型，再逐步認識 AutoRef 的迭代束搜尋流程。
- **AI 工程師**：請聚焦第 3、4 節的 Harness 形式化定義與 AutoRef 演算法細節，特別是「提出修改用任務」與「選擇候選用任務」分離的設計，以及如何利用執行軌跡與分數引導編碼代理重寫程式碼，並思考如何將其整合至現有 MLOps 管線。
- **研究人員**：建議深入分析 AutoRef 與 Meta-Harness、AutoDesign 等自動化代理最佳化方法的差異，並關注視覺評估雜訊、過度擬合與跨模型泛化等研究問題，這些都是未來可延伸的理論與實證方向。
- **產品經理**：請把重點放在適用場景、商業價值與風險控管上，理解 AutoRef-Harness 能在不重新訓練模型的情況下提升生成品質，並評估將其導入廣告、電商或內容創作產品所需的資料、運算與合規成本。
