#### 實驗數據解讀

**整體效能差距**

2,151 次評分執行 (scored rollouts) 來自九個前沿代理系統、六間實驗室。GPT-6 Astra 與 Claude Opus 5.5 分居第一、二名，且此排名在 VLM 評審與人類標註員 (human annotators) 間一致。然而，最強系統僅在 76.3% 的任務上滿足所有核心需求——這意味著即使最佳代理，仍有近四分之一的任務存在核心需求缺失。這個數字應被理解為「基準遠未飽和」(far from saturated)，而非「基準太容易」。

**交付作為第二軸度**

論文中最具洞察力的發現之一：將缺失影片計為零分會「顯著改變排名」。Gemini 4 Argon 僅交付 77% 的影片，從第四名跌至第七名。這揭示了一個常被忽略的評測陷阱——「品質分數」與「交付率」是兩個獨立維度。一個系統可能平均品質尚可，但若經常無法在時限內交付，其實用價值大打折扣。論文的「雙軸報告」（delivered-only 與 no-video-as-zero）是對此問題的方法論自覺。

**失敗模式的時間分析**

224 次無可播放影片的執行中，169 次（75%）是「最終渲染問題」：開始太晚、跑得太慢（如逐幀瀏覽器擷取 frame-by-frame browser capture）、或從未開始。Opus 是唯一沒有此類失敗的系統，且其完成時間中位數比截止時間早 24 分鐘。這暗示「時間管理」是代理成熟度的關鍵指標，而非單純的程式碼生成能力。

**自我檢查的悖論**

95% 的執行會檢視自身畫面 (frame inspection)，但檢視量與品質的相關係數為 ρ = −0.07——統計上接近零且略為負值。這是反直覺的發現：直覺上「更多自我檢查 = 更好品質」，但實驗顯示並非如此。論文進一步指出，最終報告常宣稱已驗證某些事項，但實際上並未成立。這暗示代理的「自我檢查」目前更像是儀式性行為而非真正的品質控制機制。

**評審可靠性的精細邊界**

三個評審小組的平均排名與人類偏好的相關性高達 ρ = 0.98——這驗證了 VLM 評審在「系統排名」層級的可靠性。但對單一影片的成對比較 (pairwise comparison)，評審與人類僅 73% 一致。這是重要的方法論區分：評審適合宏觀排名，不適合微觀個案判斷。這對未來基準設計有直接啟示——應以「系統排名」而非「單題分數」作為主要比較單位。

**渲染管線的生態觀察**

每個系統都發展出自身的「內部渲染堆疊」(house rendering stack)：cairo、PIL/numpy、瀏覽器 canvas、three.js 等。這顯示代理在工具選擇上呈現「生態位分化」(ecological niche differentiation)，而非收斂到單一最佳實踐。

#### 與現有研究的比較

**與影片生成基準的比較**

相較於 VBench 與 EvalCrafter 等像素生成基準，VibeVideoBench 評測的是完全不同的範式：後者評測「幾秒鐘無聲片段看起來多逼真」，前者評測「多模態代理能否在時限內產出可編輯、可驗證的完整影片」。兩者並非競爭關係，而是互補——前者測試「像素層級的擬真度」，後者測試「結構層級的可控性與完整性」。論文中明確指出，像素生成器無法保證精確文字、規則一致的狀態變化、多分鐘結構、事件對齊的聲音，這些正是程式碼生成影片的天然優勢。

**與程式碼到視覺基準的比較**

ArtifactsBench 等基準評測單一程式或靜態產物（圖表、網頁、SVG）。VibeVideoBench 將此範式擴展到「時間性、感知性、視聽性」的影片產出，並加入音訊維度——這是現有基準完全未涵蓋的。

**與代理基準的比較**

SWE-bench 等代理基準以單元測試 (unit tests) 驗證文字或功能性結果。VibeVideoBench 論證的核心點在於：影片是「感知性、時間性、視聽性」的結果，沒有單元測試可用，因此需要發展全新的評估協議。這填補了「純文字代理基準」與「純生成模型基準」之間的空白。

**與領域專用系統的比較**

現有「論文轉影片」或「課程轉影片」系統（如基於 Manim 的工作流程）是「為單一領域、單一渲染器手動設計工作流程的語言模型管線」(language-model pipelines)——模型在預設步驟被呼叫，並非真正的通用代理。VibeVideoBench 測試的是通用代理在開放領域的端到端能力，這是質的躍進。

**方法論侷限**

(1) 評測「完整系統」而非分離模型與外殼，犧牲了純粹模型比較；(2) 一小時預算雖合理但仍是任意選擇，不同預算可能產生不同排名；(3) 239 個任務雖具多樣性，但相較於 SWE-bench 等基準規模仍小；(4) VLM 評審在個案層級僅 73% 與人類一致，限制了細粒度分析的可靠性。

#### 可重現性評估

**正面因素**

論文明確承諾釋出「輸入素材與可重現沙盒」(input assets and a reproducible sandbox)，這對基準的可重現性至關重要。任務規格、評分規準、評審協議皆在論文中詳細描述，三層評估架構的設計邏輯透明可審查。「自足任務」設計本身有利於重現——無需依賴外部 API 或私有資料。

**限制因素**

(1) 代理系統本身（GPT-6 Astra、Claude Opus 5.5 等）為商業閉源產品，其內部行為不可審計；外部研究者僅能在相同 API 條件下重現結果，無法控制模型版本或外殼更新。(2) VLM 評審的具體型號、提示詞、溫度參數等細節未在摘錄中完整披露，但完整論文應有說明。(3) 「最高努力設定」(highest effort its provider accepts) 本身是模糊的——不同供應商對「最高努力」的定義可能不同，且可能隨時間變化。(4) 沙盒環境的具體配置（CPU、記憶體、網路限制）會直接影響渲染時間，論文中未見詳細規格。

**評估可重現性**

評估協議的階層化設計本身有利於重現——L1 程式檢查完全可重現；L2 評分規準雖依賴 VLM，但因每條規準皆「可追溯至其強制執行的需求」，審計性高；L3 品質評分依賴 VLM 評審的隨機性，但三小組平均的排名穩定性（ρ = 0.98）提供了統計信心。

**人類偏好評測的設計**

盲測成對人類偏好評測 (blind pairwise human preference study) 涵蓋全部 239 個任務，這是基準驗證 (benchmark validation) 的黃金標準——若 VLM 排名與人類排名高度一致，則基準具備外部效度。

#### 未來研究方向

**時間管理與規劃能力**

論文揭示的「75% 失敗來自時間管理」是最具行動性的研究方向。可能的探索包括：(1) 為代理設計顯式的時間預算分配機制；(2) 訓練代理在渲染前進行「時間可行性預檢」(time feasibility pre-check)；(3) 發展「漸進式渲染」(progressive rendering) 策略，先產出低品質版本再迭代。

**自我檢查機制的根本性重設計**

ρ = −0.07 的相關性意味著現有自我檢查機制幾乎無效。未來方向：(1) 從「被動檢視」轉為「主動驗證」——檢查特定規條而非整體印象；(2) 將自我檢查與 L2 評分規準對齊，使檢查目標明確化；(3) 探索「對抗式自我檢查」(adversarial self-inspection)——代理嘗試找出自己影片的問題。

**評審協議的個案層級改進**

73% 的個案一致性是明顯瓶頸。可能方向：(1) 引入更多評審小組以提升統計穩定性；(2) 為困難個案設計「人類專家仲裁」機制；(3) 訓練專門的影片評審模型，而非依賴通用 VLM。

**音訊維度的深化**

目前音訊僅作為「音訊策略」被評估，但音訊與影像的時序對齊 (audio-visual alignment)、音訊品質本身、語音清晰度等維度尚未充分探索。這是 VibeVideoBench 可自然延伸的方向。

**跨語言與跨文化評測**

任務涵蓋中英文，但未深入分析語言對代理效能的影響。未來可探索：(1) 不同語言任務的難度差異；(2) 代理在多語言混合任務中的表現；(3) 文化特定內容（如中文教學素材）的評測挑戰。

**程式碼驅動 vs. 像素生成的混合範式**

兩種範式各有優勢：程式碼保證精確性與可編輯性，像素生成保證擬真度與視覺衝擊力。未來可探索「混合代理」(hybrid agents)——以程式碼為骨架、以像素模型為裝飾層，在兩者間智慧切換。

**長時程任務的代理能力**

一小時預算已是現有基準中最長之一，但真實影片製作可能需要數小時甚至數天。未來可發展「多日代理」(multi-day agent) 評測，測試代理在更長時間尺度上的規劃、恢復與持續學習能力。

**領域專用代理的比較**

VibeVideoBench 測試通用代理，但領域專用系統（如為 Manim 設計的工作流程）在特定任務上可能更強。系統性的「通用 vs. 專用」比較將揭示代理泛化能力的真實邊界。
