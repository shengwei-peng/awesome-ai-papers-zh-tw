## 摘要翻譯

我們推出 Boogu-Image-0.1，一個開源的統一多模態理解與生成（Unified Multimodal Understanding and Generation）模型家族，包含 Base、Turbo、Edit 與 Edit-Turbo 等模型變體。該模型在高品質文生圖（Text-to-Image Generation）、快速推論（Fast Inference）、基於指令的圖像編輯（Instruction-Based Editing），以及雙語（中文與英文）文字渲染（Bilingual Text Rendering）等任務上展現出具競爭力的表現。Nano-Banana-Pro 與 GPT-Image-2 等閉源多模態系統透過系統級整合（System-Level Integration）而非仰賴單一模型達到優異表現，但其內部做法大多未公開。在本研究中，我們證明針對模型理解、資料品質（Data Quality）與訓練流程（Training Pipeline）進行改善，並結合具代理推論時擴展（Agentic Inference-Time Scaling），即使在運算預算（Compute Budget）高度受限的情況下，也能顯著提升生成與編輯表現。全面的評測顯示，Boogu-Image-0.1 在標準基準上始終能與其他開源模型匹敵甚至超越，並達到接近領先閉源系統的成果。值得注意的是，此成果僅以 2.0862 億張不重複影像（Unique Images）達成。Base 模型的理論訓練成本（Theoretical Training Cost）僅約 40 萬美元。我們分享實務討論，相信對更廣泛的研究社群有所助益，並在 Apache 2.0 授權條款下釋出權重（Weights）、程式碼與訓練配方（Recipes），以推動統一多模態理解與生成的開放生態系統。我們的程式碼可於此處取得：https://github.com/Boogu-Project/Boogu-Image。

### 核心貢獻（3～5點）
- 提出開源的統一多模態理解與生成模型家族 Boogu-Image-0.1，包含 Base、Turbo、Edit 與 Edit-Turbo 四種變體，涵蓋文生圖、快速推論、指令編輯與雙語文字渲染等核心能力。
- 在僅約 2.0862 億張不重複影像與理論訓練成本約 40 萬美元的受限運算預算下，達到可與領先閉源系統接近的生成與編輯表現。
- 驗證透過強化模型理解、提升資料品質與優化訓練流程，並結合具代理推論時擴展，能顯著改善開源模型的生成與編輯能力。
- 完整釋出模型權重、程式碼與訓練配方，採用 Apache 2.0 授權條款，促進統一多模態理解與生成領域的開放生態發展。

### 適合對象
本論文最適合從事多模態學習（Multimodal Learning）、開源生成模型開發、文生圖與圖像編輯研究的學者與工程師閱讀；對於關注如何在有限運算預算下提升生成品質、想了解資料品質與訓練流程設計，以及希望取得可復現開源配方以進行後續研究的社群成員，亦具有高度參考價值。

## 深度分析

#### 方法論解析

Boogu-Image-0.1 的核心方法論可視為一場從傳統 Text-to-Image（文字到圖像生成）邁向 Requirement-to-Image Generation（需求到圖像生成）的典範轉移。其方法論並非單純追求模型參數量或資料規模的擴張，而是將「理解能力（understanding）」提升為與資料品質（data quality）、訓練配方（training recipe）及推論流程（inference pipeline）並列的一級設計目標。具體而言，方法論可拆解為以下幾個相互協同的層次：

**1. Instruction Encoder（指令編碼器）作為語言感測器**

作者將 text encoder（文字編碼器）重新定位為「語言感測器（sensor of language）」，強調其對使用者需求解析的決定性作用。透過系統化比較不同規模的語言模型，研究確認更強大的 LLM（Large Language Model，大型語言模型）能帶來更強的文字編碼能力，進而提升生成模型對複雜提示的遵循度。最終選用 Qwen3-VL-8B 作為平衡能力與開源社群可接受參數量的折衷方案。這項選擇的關鍵在於：生成模型不再只是將 prompt（提示）映射為像素，而是必須先正確理解隱含約束、多層級指令與跨模態語境。

**2. Agentic Inference-Time Scaling（具代理推論時擴展）**

Boogu-Image-0.1 將模型包裹在一個 agent（代理）框架中，使生成過程具備主動理解與決策能力。此框架包含三個主要機制：

- **Prompt Rewriter（提示重寫器）**：作為 translator（翻譯器）而非 enhancer（增強器），其任務是將使用者原始需求轉譯為模型更能精確理解的表達形式，而非無限制地添加華麗修飾。這呼應了「好的監督需要理解使用者需求」的觀點。
- **Model Router（模型路由器）**：依據任務複雜度、成本與延遲需求，在 Base、Turbo、Edit、Edit-Turbo 等變體間動態選擇。這體現了「為正確任務選擇正確模型」的系統思維。
- **Reflection（反思機制）**：透過推論階段的自我檢視與迭代修正，進一步提升生成品質。

這種 agentic 設計使得理解能力不僅來自訓練資料，也在 inference time（推論時間）被持續注入，形成「理解—生成—反思—再生成」的閉環。

**3. 資料品質導向的訓練流程**

在高度受限的 compute budget（運算預算）下，Boogu-Image-0.1 採用「品質重於數量」的資料篩選策略。整個 base model（基礎模型）僅使用 208.62 million unique images（2.0862 億張不重複影像）從頭訓練，理論訓練成本約 400K 美元。這顯示作者認為資料的 curated quality（策展品質）、caption design（圖說設計）與 filtering pipeline（篩選流程）遠比單純堆疊資料量來得關鍵。

**4. 統一多模態理解與生成架構**

模型家族包含 Base、Turbo、Edit 與 Edit-Turbo 四個變體，分別對應高品質文生圖、快速推論、指令式圖像編輯（instruction-based editing）及快速編輯等應用場景。這種模組化設計讓單一系統能同時覆蓋 understanding（理解）與 generation（生成）任務，並透過 Model Router 根據需求彈性調度。

#### 實驗數據解讀

由於目前可取得的上下文主要為摘要與引言，具體數值表格尚未完整揭露，但從文中仍可提煉出以下實驗設計與結果解讀的重點：

**1. 評測基準的選擇與批判**

作者在 2.1 節提出「Rethinking Open-Source Research Evaluation（重新思考開源研究評估）」，暗示現有 public benchmarks（公開基準）雖有價值，但若使用不當容易失真。Boogu-Image-0.1 採用多維度評測組合：

- **BooguArena Benchmark（BooguArena 基準）**：自製的競技場式評測，強調人類偏好與真實使用情境。
- **Qwen-Image Benchmark（Qwen-Image 基準）**：近期釋出的外部基準，用於與其他開源模型進行標準化比較。
- **LongText Benchmark（LongText 基準）**：專注於雙語（Chinese-English，中文—英文）長文字渲染能力。
- **ImgEdit Benchmark（ImgEdit 基準）**：評估 image-to-image generation（圖生圖）與指令式編輯。

這種組合反映出作者對「單一指標無法捕捉真實需求」的警覺，並試圖透過自製與外部基準並重的方式，提供更全面的性能圖像。

**2. 主要結果趨勢**

根據摘要與引言，Boogu-Image-0.1 在以下面向達成顯著成果：

- 在 BooguArena 上取得 top-tier performance（頂尖表現）。
- 在 Qwen-Image-Bench 上達到 open-source models（開源模型）中的 state-of-the-art（最先进水平）。
- 在長文字渲染與指令式編輯上具備競爭力。
- 整體性能接近 leading closed-source systems（領先閉源系統），如 Nano-Banana-Pro 與 GPT-Image-2。

值得注意的是，這些成果是在僅 208.62 million unique images 與約 400K 美元訓練成本下達成，顯示方法論在資料效率（data efficiency）上的優勢。

**3. 消融實驗的設計意涵**

目錄中提及多項消融研究：

- **Data Ablation Evaluation（資料消融評估）**：「Just Enough Data Is Not Enough（僅有足夠資料並不足夠）」暗示單純增加資料量並不能保證性能提升，資料品質與分佈策展更為關鍵。
- **Ablation Experiments on Multimodal Learning and Understanding（多模態學習與理解的消融實驗）**：驗證理解能力對生成品質的因果影響。
- **Boosted Orthogonal Guidance（Boosted Orthogonal Guidance）**：附錄中的技術方法，可能涉及推論階段的引導強化。

這些消融實驗的設計凸顯了作者對「可解釋性」與「工程細節決定性」的重視，試圖將過去工業界隱藏的 trial-and-error（試誤經驗）轉化為可公開檢驗的知識。

#### 與現有研究的比較

**1. 相對於閉源系統的定位**

Nano-Banana-Pro、GPT-Image-2、Seedream 等閉源系統的強大性能往往來自 system-level integration（系統級整合），例如結合 web search（網路搜尋）、多模型協作與複雜後處理，但其內部實踐鮮少公開。Boogu-Image-0.1 的貢獻在於證明：透過針對性的模型理解、資料品質與訓練流程改進，再加上 agentic inference-time scaling，開源模型即使運算預算高度受限，也能逼近閉源系統的表現。這為開源社群提供了一條不依賴封閉基礎設施的替代路徑。

**2. 相對於其他開源模型的差異**

FLUX、Ideogram、Qwen-Image、Z-Image、Hunyuan-Image 等開源模型主要透過兩種策略縮小差距：提升視覺品質，或附加輔助 LLM 進行 prompt rewriting（提示重寫）。Boogu-Image-0.1 的差異化在於：

- 將 understanding（理解）內建為系統核心，而非僅作為前處理外掛。
- 透過 Model Router 在多個專精變體間動態調度，兼顧品質、速度與編輯需求。
- 強調 captions（圖說）與資料篩選的品質，而非單純擴充資料量。

**3. 主要創新與改進**

- **理解即感測器**：將 Instruction Encoder 視為語言感測器，並系統化驗證 LLM 規模與編碼能力的關係。
- **Prompt Rewriter 的角色澄清**：明確區分 translator 與 enhancer，避免過度修飾導致語意漂移。
- **Agentic 推論擴展**：將 reflection、routing 與 rewriting 整合為統一的推論階段增強框架。
- **極致訓練效率**：以遠低於業界常規的資料量與成本達到可比性能。

**4. 限制與潛在風險**

- **資料規模的通用性**：雖然 208.62 million images 在成本上極具吸引力，但是否能支撐更廣泛的 world knowledge（世界知識）與罕見概念生成，仍需更多驗證。
- **閉源系統的不可比性**：由於 Nano-Banana-Pro、GPT-Image-2 的內部細節未公開，所謂「接近」可能受限於評測條件與 prompt 設計。
- **Agentic 系統的複雜度**：Model Router、Prompt Rewriter、Reflection 等模組增加了系統複雜度，可能帶來延遲、錯誤傳播與維護成本。
- **評測基準的偏見**：BooguArena 為自製基準，雖能反映真實需求，但也可能存在與模型設計目標一致的隱性偏見。

#### 可重現性評估

**1. 開源釋出內容**

Boogu-Image-0.1 承諾在 Apache 2.0 授權下釋出：

- **Weights（權重）**：模型權重可供下載。
- **Code（程式碼）**：推論與訓練相關程式碼。
- **Recipes（配方）**：訓練配置與實作流程。

這對於開源社群而言是高度正面的訊號，因為它不僅釋出模型本身，還試圖揭露過去被視為「隱藏工程成本」的實作細節。

**2. 可重現性的強項**

- **低成本訓練配方**：理論訓練成本約 400K 美元，相較於動輒數百萬美元的工業級模型，對學術界與中小型研究團隊更為可行。
- **明確的資料規模**：公開使用 208.62 million unique images，雖未完整揭露資料來源與篩選細節，但提供了可參考的規模基準。
- **模組化設計**：Base、Turbo、Edit、Edit-Turbo 的分工清楚，便於研究者針對特定任務進行復現與改進。

**3. 可重現性的挑戰**

- **資料來源與策展細節**：儘管強調資料品質，但完整資料集、篩選規則與 caption 生成流程是否完全公開，將直接影響重現難度。
- **Agentic 系統的依賴**：Prompt Rewriter、Model Router、Reflection 等模組可能依賴額外的 LLM 服務或內部啟發式規則，若未完整文件化，重現時可能出現性能落差。
- **硬體與推論優化**：Turbo 變體的 fast inference（快速推論）可能涉及特定的硬體優化或量化技術，這些細節對重現同樣關鍵。

#### 未來研究方向

**1. 理解能力的進一步內化**

未來可探索將 agentic 理解能力更深度地內化為單一模型的一部分，減少對外部 Prompt Rewriter 與 Reflection 模組的依賴，從而降低系統複雜度與推論延遲。這可能涉及更大規模的 multimodal pretraining（多模態預訓練）或 reasoning-enhanced generation（推理增強生成）。

**2. 世界知識與檢索增強生成**

閉源系統如 GPT-Image-2 已結合 web search 以擴展 world knowledge。Boogu-Image-0.1 未來可研究如何將 retrieval-augmented generation（檢索增強生成，RAG）整合至圖像生成流程，以處理更專業、時事性或罕見概念的需求。

**3. 更細緻的 Model Router 與成本感知生成**

目前的 Model Router 已能依任務選擇變體，但未來可發展更動態的成本—品質權衡機制，例如根據使用者預算、延遲要求與品質期望進行自適應決策，甚至支援 user-controllable inference budget（使用者可控推論預算）。

**4. 多語言與文化適應**

Boogu-Image-0.1 已強調 bilingual text rendering（雙語文字渲染），但未來可進一步擴展至多語言語境理解、文化符號生成與區域化審美偏好，這對於全球部署的開源模型尤為重要。

**5. 評測方法論的持續演進**

作者已意識到 leaderboard（排行榜）文化的局限。未來可發展更貼近真實使用者需求的 evaluation protocols（評估協定），例如長期使用者滿意度、編輯一致性、生成結果的可編輯性與可解釋性，並建立開放的 human evaluation（人工評估）平台。

**6. 資料效率與可持續訓練**

在僅 208.62 million images 即達成強勁性能的基礎上，未來可進一步研究資料選擇演算法、主動學習（active learning）與合成資料（synthetic data）策略，以在更低資料量與能耗下訓練高品質生成模型。

## 論文問答

**Q1：Boogu-Image-0.1 主要想解決什麼問題？**
A：本研究指出，圖像生成正從傳統的 Text-to-Image（文生圖）邁向 Requirement-to-Image Generation（需求到圖像生成），使用者不再滿足於單一描述句，而是期待模型能理解複雜意圖、隱含限制與跨模態脈絡。然而，諸如 GPT-Image-2、Nano-Banana-Pro 等閉源系統雖然表現強勁，卻是透過未公開的系統級整合達成，造成開源社群難以複製與追趕。因此，Boogu-Image-0.1 旨在以可負擔的運算預算，建立一個真正重視「理解能力」的開源統一多模態理解與生成模型家族。

**Q2：現有的開源方法為什麼不足以追上閉源系統？**
A：現有開源努力大多聚焦於提升視覺品質，並額外掛載一個輔助 LLM 來重寫使用者提示，但這種做法並未系統性地把「理解」視為核心設計目標。結果是模型難以準確詮釋模糊需求、多層次指令，也無法依據不同場景在速度與品質間做適當取捨。相較之下，閉源系統透過推論時擴展、模型路由與其他系統級技巧強化理解，但這些實作細節通常不對外揭露，使開源社群處於資訊不對稱的劣勢。

**Q3：為什麼「理解能力」被提升為與資料品質、訓練流程同等重要的設計目標？**
A：理解能力是連結模糊人類需求與精確視覺生成之間的關鍵橋樑，能決定模型是否能把複雜要求轉譯成正確的圖像內容與構圖。此外，真實世界需求極為多元，從簡單快速到精細高品質都有，單一模型配置很難同時滿足所有情境，因此需要理解來驅動模型路由與推論策略。唯有將理解視為第一級設計目標，開源模型才能擺脫單純追求視覺擬真的路徑，真正進入 Requirement-to-Image 的時代。

**Q4：Boogu-Image-0.1 的核心方法架構是什麼？**
A：該模型家族包含 Base、Turbo、Edit 與 Edit-Turbo 四個變體，分別對應高品質生成、快速推論、指令式編輯與快速編輯等不同應用場景。核心方法圍繞三大軸線：強化模型理解能力、提升資料品質與訓練配方，以及導入具代理推論時擴展（Agentic Inference-Time Scaling）。在推論階段，系統會透過提示重寫、模型路由與 Reflection 等機制，把理解能力注入生成流程，逐步提升生成與編輯表現。

**Q5：Boogu-Image-0.1 的關鍵創新元件有哪些？**
A：作者將系統拆解為數個關鍵元件：Instruction Encoder（指令編碼器）被視為語言感測器，Prompt Rewriter（提示重寫器）被定位為「翻譯者」而非單純的「增強器」，Model Router（模型路由器）則負責為不同任務選擇最適合的模型變體。此外，圖說（Captions）的設計強調「好的監督訊號必須理解使用者需求」，而非僅是詳盡描述。這些元件協同運作，使理解、生成與編輯能夠在統一框架下互相強化。

**Q6：為什麼選擇 Qwen3-VL-8B 作為 Instruction Encoder？**
A：作者系統性地比較了不同規模的語言模型，確認更強大的 LLM 能帶來更強的文字編碼能力，而文字編碼器正是文生圖模型感知語言的「感測器」。在開源社群可接受的參數預算下，Qwen3-VL-8B 在編碼能力與運算成本之間取得了良好平衡。這個選擇也呼應了本研究的核心信念：生成品質的上限，很大程度取決於模型對使用者語言需求的理解深度。

**Q7：論文使用了哪些評測基準來驗證成效？**
A：研究團隊採用了 BooguArena（自製基準）、Qwen-Image Benchmark、LongText Benchmark（雙語長文字渲染）以及 ImgEdit Benchmark（圖像編輯）進行全面評估。此外，作者也特別討論了「不使用的基準」以及對排行榜導向評估的反思，強調公開基準只有在正確使用與解讀時才有價值。這種評估態度凸顯了本研究對透明與務實評測的重視。

**Q8：Boogu-Image-0.1 取得了哪些關鍵實驗結果？**
A：綜合評測顯示，Boogu-Image-0.1 在多項標準基準上持續達到或超越其他開源模型，並在 BooguArena 上取得頂尖表現，在 Qwen-Image-Bench 上達到開源模型中的最佳成績。更令人矚目的是，Base 模型僅使用 2.0862 億張不重複影像進行從頭訓練，理論訓練成本僅約 40 萬美元。這證明即使在高度受限的運算預算下，透過精準的資料篩選、訓練優化與推論時擴展，仍能逼近領先閉源系統的表現。

**Q9：消融實驗揭示了哪些重要發現？**
A：資料消融評估指出，僅有「剛好足夠」的資料量並不足夠，資料的品質、篩選與圖說設計才是決定訓練效率的關鍵。多模態學習與理解能力的消融實驗則進一步驗證，更強大的指令編碼器與貼近使用者需求的圖說，能顯著提升生成與編輯表現。這些結果支持了作者的主張：理解、資料與訓練流程的協同改進，遠比單純擴大資料規模更有效。

**Q10：Boogu-Image-0.1 適合哪些實際應用場景？**
A：該模型家族可應用於高品質文生圖、快速推論、基於指令的圖像編輯，以及中英雙語文字渲染等多元任務。透過 Model Router，系統能依據使用者對速度與品質的需求，自動選擇 Base 或 Turbo 變體。對於複雜提示，Agentic Prompt Rewriting 與 Reflection 機制還能進一步細化需求，使生成結果更符合使用者意圖。

**Q11：從產品化角度來看，Boogu-Image-0.1 有哪些設計考量？**
A：由於真實世界需求在延遲、成本與品質上差異極大，單一模型配置難以服務所有使用者，因此系統透過模型路由與推論時擴展來動態調整策略。Prompt Rewriter 與 Reflection 雖然能提升品質，但也會增加推論延遲，需在產品中根據場景權衡。此外，研究團隊以 Apache 2.0 授權釋出權重、程式碼與訓練配方，降低開發者重複試錯的成本。

**Q12：這項研究對開源多模態領域可能帶來什麼影響？**
A：Boogu-Image-0.1 證明了 targeted improvements（針對性改進）加上 agentic inference-time scaling，即使運算預算有限，也能顯著縮小與閉源系統的差距。更重要的是，作者公開了許多工業界通常隱藏的工程細節，例如評估協定、資料篩選與圖說設計，有助於降低開源社群的隱性工程成本。這不僅推進了統一多模態理解與生成的開放生態，也為未來理解導向的生成研究提供了實用參考。

**Q13：作者承認了哪些限制？**
A：儘管 Boogu-Image-0.1 已能逼近領先閉源系統，但在某些極端複雜或需要大量世界知識的任務上，仍可能落後於具備更大規模資料與系統級整合的商業模型。目前雙語文字渲染主要聚焦於中文與英文，對其他語言的支援仍有限。此外，推論時擴展機制雖然提升品質，卻也帶來額外延遲與計算成本，在資源極度受限的邊緣裝置上可能需要進一步取捨。

**Q14：Boogu-Image-0.1 可能在哪些情況下出現失敗案例？**
A：當使用者指令包含多層次、相互衝突或高度隱含的約束時，即使經過提示重寫，模型仍可能產生語意不一致或構圖錯誤的結果。在長文字渲染任務中，若遇到罕見字體、特殊排版或極長段落，也可能出現錯字、漏字或版面失衡。Model Router 若對任務難度判斷失準，也可能選擇過快的 Turbo 變體而犧牲品質，或選擇 Base 變體而浪費運算資源。

**Q15：未來可以朝哪些方向繼續發展？**
A：未來可擴展至更多語言與多模態輸入，並進一步強化 Reflection 與代理協調機制，使模型能處理更複雜的長程規劃與多輪互動。結合檢索或網路搜尋來補充世界知識，也是縮小與閉源系統差距的重要方向。此外，發展更全面、超越排行榜的評估方法，將有助於社群更真實地衡量理解導向的圖像生成系統。

## 實務應用指南

### 適用場景

1. **電商與廣告素材快速生成**  
   利用 Base 或 Turbo 變體，依據商品描述、風格關鍵字與中英雙語標語，自動生成高品質商品圖、廣告 Banner 與社群貼文配圖。Turbo 適合需要大量草稿或 A/B 測試的高速場景，Base 則用於最終精稿。

2. **出版與行銷的長文字圖像設計**  
   針對海報、書籍封面、簡報投影片等需要準確渲染長篇中英文字的應用，使用 LongText 能力較強的 Base 變體，並搭配 Prompt Rewriter 將使用者需求轉為結構化提示，降低錯字與排版錯誤。

3. **創意圖像編輯與迭代設計**  
   透過 Edit / Edit-Turbo 變體執行基於自然語言指令的圖像修改，例如「把背景換成夜景」、「將 T 恤顏色改成紅色並加上品牌 Logo」。適合設計師在現有稿基礎上快速迭代，或讓非專業使用者以對話方式修圖。

4. **多語言內容在地化生成**  
   結合雙語文字渲染能力，為跨國產品生成同樣構圖但文字語言不同的素材，例如同一張海報分別輸出中文與英文版本，減少重複設計成本。

5. **智慧型創意代理（Agentic Creative Assistant）**  
   將 Boogu-Image-0.1 包裝成創意代理：先由模型理解複雜需求，再透過 Model Router 自動選擇 Base / Turbo / Edit，並可加入 Reflection 機制進行多輪修正，應用於行銷自動化、遊戲資產生成或個人化頭像服務。

### 實作步驟建議

1. **環境建置與權重取得**  
   從官方 GitHub 下載對應變體權重，安裝相依套件，並依硬體設定適當的推論精度（FP16/BF16/INT8）。

2. **建立提示理解層**  
   不要直接將使用者原始文字餵給生成模型。先部署 Instruction Encoder / Prompt Rewriter，將口語化需求轉譯為結構化、細節完整的生成提示；對於編輯任務，則產生明確的「原圖 → 修改指令」配對。

3. **設計 Model Router**  
   依據任務複雜度、文字長度、品質要求與延遲預算，決定呼叫 Base、Turbo、Edit 或 Edit-Turbo。例如：簡單概念草圖走 Turbo；需精確長文字或高細節走 Base；修改現有圖片走 Edit 系列。

4. **加入推論時擴展機制**  
   對於高價值輸出，啟用 Agentic Inference-Time Scaling：先重寫提示、生成多張候選、透過 Reflection 或 CLIP/美學評分模型篩選最佳結果，必要時進行多輪編輯。

5. **領域適應與資料清洗**  
   若效果不足，使用自有資料進行持續預訓練或 LoRA 微調。重點在於圖說品質：應包含風格、構圖、材質、文字內容與使用者意圖，並過濾低解析度、重複或標註錯誤樣本。

6. **評估與上線監控**  
   不要只依賴單一排行榜分數。建立結合自動指標（如 FID、CLIP Score、OCR 正確率）與人工評審的 BooguArena 式評測流程，並在產品上線後追蹤使用者滿意度與失敗案例。

### 潛在風險與注意事項

- **文字渲染錯誤**  
  即使支援雙語文字，長文字、罕見字或特殊符號仍可能出現錯字、缺字。建議對關鍵文字進行後製 OCR 驗證，或將文字圖層分開生成再合成。

- **指令理解偏差**  
  複雜需求（多物件、空間關係、數量）容易遺漏或誤解。可透過 Prompt Rewriter 將需求拆解為子項目，並在 UI 上提供預覽與再編輯入口。

- **版權與不當內容**  
  生成模型可能複製訓練資料風格或產生有害內容。應部署輸入過濾、輸出安全分類器，並在服務條款中明確使用限制。

- **延遲與成本權衡**  
  Base 品質高但推論慢；Turbo 快但細節較弱。若未設計 Router，可能導致簡單任務浪費高成本運算，或複雜任務品質不足。

- **評估指標陷阱**  
  標準基準（如 FID）未必反映真實使用者偏好。論文強調應 Rethinking Open-Source Research Evaluation，因此建議搭配人類評比與業務指標，避免過度優化排行榜。

### 與其他技術的整合建議

- **與 LLM / Agent 框架整合**  
  將 Boogu-Image-0.1 視為 Agent 的工具之一，由 LLM 負責需求解析、任務拆解與多輪對話，再呼叫對應變體生成或編輯圖像。可結合 LangChain、LlamaIndex 或自研 Agent 管線。

- **與向量資料庫與 RAG 結合**  
  對於品牌風格一致性要求高的場景，可將品牌素材、風格描述與過往成功案例存入向量庫，生成前檢索相似參考並注入提示。

- **與傳統圖像處理管線串接**  
  生成後可接續使用傳統 CV 工具（如 OpenCV、PIL、Segment Anything）進行去背、超解析度、色彩校正或局部修復，彌補生成模型在像素級控制上的不足。

- **與 MLOps 平台整合**  
  將 Model Router、Prompt Rewriter 與生成服務封裝為 API，並透過 Kubernetes + Triton/vLLM 等推論伺服器進行自動擴展與 A/B 測試。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從官方釋出的範例程式碼與 Turbo 變體開始，體驗「輸入需求 → 獲得圖像」的完整流程，再回頭閱讀論文的第 1 章與第 2 章評測部分，理解為何「理解能力」會影響生成品質，不必一開始就深入訓練配方。

**AI 工程師**  
重點閱讀第 3 章的實驗分析與討論，特別是 Instruction Encoder、Prompt Rewriter、Model Router 與資料消融實驗，這些章節直接對應到如何將論文方法落地為可維護的產品管線，並留意附錄中的 Boosted Orthogonal Guidance 等推論技巧。

**研究人員**  
建議深入探討第 2.1 節對開源評估的反思、第 3.2 節的資料消融，以及 Agentic Inference-Time Scaling 的設計哲學。這些部分揭示了當前開源社群在資料、評測與系統整合上的隱性成本，適合作為後續研究的切入點。

**產品經理**  
可聚焦摘要、第 1 章引言與第 2 章的 BooguArena / Qwen-Image Benchmark 結果，快速掌握 Base、Turbo、Edit、Edit-Turbo 四個變體的定位與效能差距，並據此規劃產品功能分級、定價策略與使用者體驗流程。
