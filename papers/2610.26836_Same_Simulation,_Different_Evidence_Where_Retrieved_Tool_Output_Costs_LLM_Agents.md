# 相同的模擬，不同的證據：檢索式工具輸出在何處使大語言模型代理付出準確率代價

## ⚡ TL;DR

探討LLM代理使用檢索式工具輸出時，準確率究竟在哪個階段流失。
以PHREEQC確定性模擬器搭配158題執行驗證選擇題，區分建構、暴露、閉合三階段定位損失。
GPT模型因「證據替代」損失7.9至11.3百分點；指定權威輸出可回升6至8百分點。

## 摘要翻譯

即使計算出正確答案，大語言模型代理（LLM agents）仍可能回答錯誤。代理執行框架（agent harness）日益將冗長的工具輸出（tool output）排除於上下文視窗（context window）之外，將其儲存為檔案，由代理按需（on demand）搜尋或讀取。我們透過一個真實的科學工具，探問此做法在何處付出準確率代價：PHREEQC，一個由美國地質調查局（USGS）廣泛使用的地質化學模擬器（geochemistry simulator），其報告可達 846.8k 字元，且其確定性（determinism）使每個列印值皆可追溯。代理使用它來回答 158 題經執行驗證（execution-verified）的選擇題（multiple-choice items）。

當代理透過章節索引（section index）而非內嵌（inline）於上下文中讀取模擬器報告時，GPT-5.1 與 GPT-5.2 分別損失 11.3 與 7.9 個百分點（percentage points）的準確率（accuracy），而 Claude Opus 4.6 與 Claude Sonnet 4.6 則未顯示可偵測的成本（detectable cost）。重新執行（re-run）全部 11,007 筆記錄的模擬器呼叫（logged simulator calls）顯示，兩個 GPT 模型計算出答案值（keyed value）的頻率與先前大致相同；改變的是它們據以作答的證據。在檢索（retrieval）時，它們經常略過報告，改從自身更高精度（higher-precision）的輸出檔案作答，並錯誤捨入（misround）至相鄰選項（neighboring option）——我們將此失敗稱為證據替代（evidence substitution）。

在模擬固定不變的情況下，檢索仍使 GPT-5.2 付出 9.4 個百分點的代價。對 GPT-5.4 而言，更頻繁的正確模擬（frequent correct simulations）掩蓋（mask）了約十個百分點的證據使用損失（evidence-use loss），使淨變化（net change）與零無顯著差異（indistinguishable from zero）。對三個 GPT 模型而言，指定權威輸出（authoritative output）使其準確率較純檢索（plain retrieval）提升 6.3 至 7.9 個百分點；對 GPT-5.1 與 GPT-5.2 而言，將可容納的輸出進行內嵌處理（inlining）同樣有效，但要求正確捨入（correct rounding）則無效。代理執行框架中的上下文管理（context-management）決策，應依據準確率損失發生的位置（location）來評估，而非僅看最終準確率（final accuracy）。

### 核心貢獻（3～5點）
- **提出「證據替代」（evidence substitution）失敗模式**：揭示代理在檢索式工具輸出情境下，會略過權威報告，改從自身更高精度的輸出檔案作答並錯誤捨入至相鄰選項，導致準確率損失。
- **精準定位損失階段**：透過 11,007 筆記錄的模擬器呼叫重新驗證（re-verified），將準確率損失歸因於「暴露（exposure）」與「閉合（closure）」階段，而非「建構（build）」階段——即使模擬本身正確，證據使用仍會出錯。
- **量化 GPT-5.4 的遮蔽效應**：更頻繁的正確模擬掩蓋了約十個百分點的證據使用損失，使淨變化與零無顯著差異，凸顯僅看最終準確率會誤判系統表現。
- **驗證補救措施（remedies）的有效性**：指定權威輸出（authoritative output）可提升 6.3–7.9 個百分點；對 GPT-5.1 與 GPT-5.2 而言，將可容納的輸出進行內嵌處理（inlining）同樣有效，但捨入提示（rounding hint）則無效。
- **呼籲以「損失位置」取代「最終準確率」作為評估依據**：主張代理執行框架的上下文管理決策應聚焦於建構、暴露、閉合三階段中損失發生的具體環節，方能有效診斷與改進。

### 適合對象
從事大語言模型代理（LLM agents）系統設計、代理執行框架（agent harness）開發、上下文管理（context-management）策略研究，以及將 LLM 應用於科學計算（如水溶液地質化學模擬）的研究者與工程師；亦適合關注 AI 系統可信度、評估方法論與失敗模式分析的學術界與產業界讀者。

## 深度分析

#### 方法論解析

本論文的核心方法論貢獻在於建立一個**三階段分解框架**（three-stage decomposition），用以定位 LLM 代理（LLM agents）在工具輸出傳遞過程中的準確率損失來源。這個框架將代理的答題過程拆解為三個可獨立觀察的階段：

1. **建構階段（build stage）**：模擬器是否實際產生了與答案鍵（answer key）相符的數值。
2. **暴露階段（exposure stage）**：該數值是否成功進入代理可讀取的內容中。
3. **閉合階段（closure stage）**：代理在看到該數值後是否正確作答。

此分解的關鍵在於利用 PHREEQC 這一**確定性模擬器**（deterministic simulator）的特性——其輸出完全可重現，使得研究者能夠對所有 11,007 筆記錄的模擬器呼叫（logged simulator calls）進行重新執行（re-run），並比對每個軌跡（trajectory）中代理所讀取的內容與模擬器實際產生的內容。這種設計讓「代理是否計算出正確值」、「是否看到正確值」、「是否從正確值推導出正確答案」三者得以分離。

在實驗設計上，論文採用了**單一變數操弄**（single-variable manipulation）的原則：所有條件僅改變模擬器報告（simulator report）如何送達代理——內嵌（inline）方式將報告直接放入上下文視窗（context window），而檢索（retrieval）方式則僅提供章節索引（section index），讓代理透過行範圍讀取（ranged reads）按需取得內容。這種嚴格的對照設計避免了混淆變數，使因果歸因更為可靠。

另一個方法論亮點是**答案鍵的執行驗證**（execution-verified answer keys）。研究者重新執行了原始 200 題中的每一題，僅保留那些在 PHREEQC 3.8.6 與固定 phreeqc.dat 下能精確匹配、且在更嚴格的收斂條件下仍穩定的題目，最終保留 158 題。這種驗證機制確保了「正確答案」本身是可信的，避免將代理的錯誤歸因於題目設計瑕疵。

在干預實驗（intervention experiments）方面，論文設計了三種變體：純檢索（plain retrieval）作為基準、加入「報告提示」（report hint）明確指定權威輸出（authoritative output）、以及加入「捨入提示」（rounding hint）要求正確捨入而非截斷（truncation）。這種設計使得研究者能夠**針對性地測試閉合階段的失敗原因**——究竟是因為代理讀錯檔案，還是因為代理對數值處理不當。

#### 實驗數據解讀

**主要準確率結果**揭示了模型間的顯著差異。在 158 題的整體表現上，Claude Opus 4.6 與 Claude Sonnet 4.6 在內嵌與檢索條件下的準確率差異落在 −0.6 至 +0.2 百分點（percentage points, pp）之間，信賴區間包含零，顯示**檢索對 Claude 模型無可偵測的成本**（no detectable cost）。然而，GPT-5.1 與 GPT-5.2 分別損失 11.3 與 7.9 個百分點，GPT-5.4 的淨變化（net change）則與零無顯著差異（indistinguishable from zero）。

**三階段分解的數據**進一步揭示了損失的具體位置。GPT-5.1 與 GPT-5.2 在所有介面下產生答案值的頻率大致相同（建構階段無差異），但**在檢索條件下跳過報告的比率大幅上升**——圖 1 右側的數據顯示 GPT-5.1 在 158 題中有 53 次跳過報告、GPT-5.2 有 60 次。當代理確實看到答案值時（暴露階段成功），閉合階段的失敗率（即 100 減閉合率）在 137 個數值題上仍相當可觀。

**證據替代（evidence substitution）** 是本論文最具洞察力的發現。PHREEQC 的模擬器報告（result.out）以答案選項的精度印製數值（例如 pH = 2.751），而代理若自行加入 SELECTED_OUTPUT 區塊，則會在 sel.out 中以更高精度（higher-precision）寫入同一數值（例如 2.75065）。在內嵌條件下，代理直接讀取 result.out 並選擇 B（2.751）；但在檢索條件下，代理傾向跳過 result.out、改讀 sel.out，並將 2.75065 **截斷**而非四捨五入（rounding）為 2.750，誤選鄰近選項（neighboring option）A。這種失敗模式在約四分之三的證據替代案例中發生。

**GPT-5.4 的淨效應為零但內部損失顯著** 是另一個關鍵發現。GPT-5.4 在檢索條件下同樣出現證據替代，在數值題上損失約 10 個百分點的證據使用（evidence-use loss）；然而它在檢索條件下計算出答案值的頻率更高，兩種效應相互抵消，使得最終準確率變化在統計上與零無顯著差異。這凸顯了**僅觀察最終準確率可能掩蓋實質損失**的方法論警示。

**干預實驗的數據**驗證了閉合階段的診斷。加入「報告提示」後，GPT-5.1、GPT-5.2、GPT-5.4 的報告跳過率降至 2% 以下，閉合率提升至 99%，相較於所有純檢索執行，準確率分別上升 6.3、7.9、7.8 個百分點。對於 GPT-5.1 與 GPT-5.2，將可容納的報告內嵌（inlining）效果相當；但**僅要求正確捨入的提示完全無效**——代理即便被告知「四捨五入而非截斷」，仍傾向截斷，這證實了問題根源在於讀取來源而非數值處理方式。

**固定模擬的對照實驗**進一步強化了因果歸因：當模擬結果被固定、僅改變輸出傳遞方式時，GPT-5.2 仍損失 9.4 個百分點，證明損失確實來自證據使用環節而非模擬計算環節。

#### 與現有研究的比較

本論文與近期關於 LLM 代理上下文管理（context-management）的研究形成互補與推進的關係。

相較於 Sen et al.（2026）發現「以檔案形式傳遞搜尋結果在大多數框架-模型配對（harness-model pairs）中降低準確率」，本論文**不僅確認了該現象，更定位了損失的具體機制**。Sen 等人止步於觀察最終準確率差異，而本論文透過三階段分解指出：損失不在於代理「算錯」，而在於代理「讀錯」——這是對前人觀察的機制性深化。

相較於 Rajasekaran et al.（2025）主張檔案式傳遞可減少上下文使用量，本論文提供了**重要的反面證據**：減少上下文使用量的代價可能是準確率損失，且此代價因模型而異。這挑戰了「更精簡的上下文必然更好」的隱含假設。

相較於 Xie et al.（2026）與 Joren et al.（2025）指出「模型並非總是使用其上下文中所需的一切」，本論文將此現象**具體化為可命名的失敗模式**——證據替代——並展示了其觸發條件（檢索介面下代理傾向跳過權威來源）。

本論文的方法論優勢在於**利用確定性模擬器實現完全可追溯性**。相較於多數代理評估基準（如 SWE-bench、HumanEval）僅能觀察最終答案正確性，本研究的 PHREEQC 設定允許研究者對每一筆工具呼叫（tool call）進行精確比對，這是現有基準難以達成的觀察粒度。

**限制方面**，本研究的題目僅 158 題，且集中在水溶液地質化學（aqueous-geochemistry）領域，題型為四選一選擇題（multiple-choice），這限制了結論對開放式問答、長程任務、或非數值推理的泛化性。此外，PHREEQC 的報告具有明確的章節結構（section-structured reports），這使得 TOC 介面特別適合——對於結構較鬆散的輸出（如日誌、搜尋結果），檢索的表現可能不同。論文的 Grep 條件實驗（使用正則表達式搜尋）結果顯示「不使用模擬器特定結構的搜尋並未帶來改善」，部分支持了這一顧慮。

#### 可重現性評估

本論文在可重現性方面提供了**中等程度的支援**，但仍有若干關鍵細節需進一步確認。

**正面因素**包括：（1）PHREEQC 3.8.6 與 phreeqc.dat 均為公開可取得的開源軟體與資料庫；（2）題目來源（Zhang et al., 2026b）為已發表基準；（3）所有模型均透過 API 呼叫，溫度設定明確（Claude 為 0，GPT 與 Gemini 使用 API 預設）；（4）論文詳述了答案鍵驗證程序，包括對 42 題被排除的具體原因分類；（5）附錄 B 列出了系統提示（system prompt）的具體內容；（6）Table 8 列出了所有執行的條件組合。

**不足之處**包括：（1）論文未明確聲明程式碼與資料是否開源釋出，arXiv 預印本通常不附帶程式碼儲存庫連結；（2）代理執行框架（agent harness）的具體實作——包括工具定義、24 步上限的設定、檔案系統隔離機制——需要從附錄推敲；（3）GPT-5.4 等模型版本可能隨時間變動，API 預設值的不透明性增加了重現難度；（4）統計信賴區間的計算方法（是否為自助法〔bootstrap〕或貝氏方法）需從附錄確認。

**對獨立重現的建議**：研究者可使用 PHREEQC 開源版本與 Zhang et al.（2026b）的題目集重建基準，但需自行實作代理框架。論文中「重新執行所有 11,007 筆模擬器呼叫」的設計是可重現的關鍵——任何重現者只需取得原始軌跡日誌，即可驗證三階段分解的數值。

#### 未來研究方向

本論文開啟了多條值得深入探索的研究路線。

**第一，跨領域泛化研究**。PHREEQC 的特性——確定性、結構化報告、數值精度敏感——使其成為理想的「實驗室」，但結論是否適用於其他類型的長輸出工具值得檢驗。具體方向包括：（1）程式碼執行工具（如 Python 直譯器的完整輸出）；（2）網路搜尋結果的批次傳遞；（3）資料庫查詢的大型結果集；（4）日誌檔案分析任務。不同領域可能觸發不同類型的證據替代。

**第二，代理行為的認知機制研究**。為何 GPT-5.1 與 GPT-5.2 在檢索條件下傾向跳過權威報告？這是否反映訓練資料中「自行生成的輸出更可信」的偏誤？或是工具使用微調（tool-use fine-tuning）過程中形成的捷徑？透過注意力視覺化（attention visualization）或探針（probing）技術分析代理在面對多個輸出檔案時的決策過程，可能揭示更深層的機制。

**第三，動態介面設計**。論文的干預實驗顯示「明確指定權威輸出」可有效解決問題，但這需要事先知道哪個輸出是權威的。對於結構較不明確的工具輸出，可研究**自適應介面**——例如代理先以低精度摘要瀏覽，再根據摘要中的關鍵詞決定深入讀取哪個檔案，或由框架根據任務類型自動選擇內嵌或檢索。

**第四，閉合階段失敗的細粒度分類**。本論文將閉合失敗歸因於「證據替代」，但可能存在其他子類型——例如代理讀取了正確檔案卻誤解了數值含義（單位錯誤、符號錯誤）、或是在多步推理中遺失了中間結果。建立更細緻的失敗分類法將有助於針對性補救。

**第五，評估指標的重新思考**。GPT-5.4 的案例凸顯了**最終準確率作為唯一指標的危險性**。未來研究可考慮採用「診斷性指標組」——同時報告建構率、暴露率、閉合率——以避免「淨效應為零」掩蓋實質損失的情況。這對代理基準的設計具有方法論意義。

**第六，模型規模與訓練策略的影響**。為何 Claude Opus 4.6 與 Sonnet 4.6 不受影響，而 GPT-5.1 與 GPT-5.2 受影響？這是否與模型規模、訓練資料組成、或對齊方法有關？系統性地改變這些因素並觀察證據替代的發生率，可能為模型行為預測提供實證基礎。

**第七，人機協作介面**。在現實部署中，使用者通常會指定「以官方報告為準」或「以系統輸出為準」。研究此類自然語言指示在不同模型上的有效性，以及如何讓代理更可靠地遵循此類指示，是連接本研究成果與實務應用的橋樑。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文探討的是一個看似矛盾但極為重要的問題：大語言模型代理（LLM agents）即使透過工具計算出正確的答案，仍可能在最終回答時出錯。具體而言，當代理執行框架（agent harness）將長工具輸出（如模擬器報告、搜尋結果、紀錄檔）以檔案形式儲存、讓代理按需檢索（retrieval）而非直接內嵌（inline）到上下文視窗時，會造成準確率損失。然而，先前研究雖觀察到此現象，卻無法定位損失究竟發生在哪個環節——是模擬計算錯誤、未讀到正確值，還是讀到卻仍答錯。本研究正是要釐清這個「損失發生在哪裡」的問題。

**Q2：為什麼現有的上下文管理方法會失敗？**
A：現有的基於檔案的傳遞（file-based delivery）方法雖然能有效節省上下文視窗空間，但研究顯示在大多數框架-模型配對（harness-model pairs）中會降低準確率。失敗的原因並非單一：模型並不一定會使用已包含所需資訊的上下文（context），而代理在面對長報告時往往傾向跳過權威來源（authoritative output），改從自己產生的高精度輸出檔案中擷取證據，並錯誤地截斷（truncate）至相鄰選項（neighboring option）。這種「證據替代」（evidence substitution）的失敗模式說明，僅靠擴大上下文預算或單純改用檢索介面並無法解決問題，必須從代理「讀什麼」與「如何讀」兩方面介入。

**Q3：為什麼這項研究對領域很重要？**
A：這項研究的重要性在於它把「最終準確率」這個單一指標拆解為三個可診斷的階段——建構（build，模擬是否產生答案值）、暴露（exposure，值是否送達代理）、閉合（closure，代理是否據此正確作答）。這種拆解讓研究者與工程師能針對損失發生的具體位置採取對應補救措施（remedy），而非盲目調整整體系統。更重要的是，論文揭示了「淨變化與零無顯著差異」（net change indistinguishable from zero）可能掩蓋實質損失的現象，提醒領域不能僅憑最終準確率判斷框架設計的優劣。

**Q4：本研究採用的核心方法是什麼？**
A：本研究選用 PHREEQC 這個由美國地質調查局（USGS）開發的水溶液地質化學模擬器作為實驗工具，因為它具有確定性（deterministic）——同一輸入必產生同一輸出，且其結構化章節報告（section-structured reports）最長可達 846.8k 字元。研究團隊準備了 158 題經執行驗證（execution-verified）的選擇題（multiple-choice items），涵蓋 pH、飽和指數、運輸單元莫耳濃度等真實地質化學問題，並透過重新執行所有 11,007 筆記錄的模擬器呼叫（logged simulator calls），追蹤每個軌跡（trajectory）中答案值是否被計算、是否被讀取、是否被正確使用。

**Q5：本研究的關鍵創新是什麼？**
A：本研究最關鍵的創新在於提出「建構-暴露-閉合」（build-exposure-closure）三階段診斷框架，使每一階段的失敗都能對應到不同的補救策略：建構缺陷指向更好的模擬輸入，暴露或閉合損失則指向改變代理的閱讀行為。另一個重要創新是發現並命名了「證據替代」（evidence substitution）這種新型失敗模式——代理在檢索模式下傾向跳過模擬器報告，改從自己寫的 SELECTED_OUTPUT 檔案中讀取更高精度的數值，再錯誤地截斷到選項精度，導致選到相鄰的誘答選項（distractor）。這個概念填補了先前文獻中「只知道有損失，卻不知道損失在哪」的空白。

**Q6：本研究在實驗設計上做了哪些關鍵選擇？**
A：在設計上，本研究刻意只改變一個變數——模擬器報告送達代理的方式——以隔離上下文管理（context-management）對準確率的影響。具體條件包括：Raw100k（內嵌報告，截斷至 100k 字元）、TOC（僅提供章節索引，由代理以行範圍讀取）、Grep（僅提供中繼資料，由代理用正則表達式搜尋）、Hybrid（適合時內嵌、不適合時改用 TOC），以及兩個介入條件 TOC+Report（明確告知從報告作答）與 TOC+Round（要求正確捨入）。此外，所有題目的答案皆經作者親自重新驗證，剔除 42 道有瑕疵的題目，確保實驗結果的可信度。

**Q7：本研究使用了什麼樣的基準測試與題目？**
A：本研究採用 Zhang 等人（2026b）所設計、由單一領域專家撰寫的四選項選擇題，內容涵蓋 PHREEQC 模擬設定與其輸出量值（如反應步驟後的 pH、飽和指數、運輸單元中的莫耳濃度）。研究團隊以 PHREEQC 3.8.6 搭配固定的 phreeqc.dat 重新執行全部 200 題，僅在作者提供輸入時使用其原始輸入，否則以題目文字與 PHREEQC 預設值進行字面編碼，且絕不為了對應答案而調整輸入。最終保留 158 題（涵蓋 19 種設定），其中數值題的誘答選項通常僅在最後一位有效數字上與答案不同，迫使代理必須實際計算而非估算。

**Q8：本研究最重要的實驗結果是什麼？**
A：最重要的結果是檢索的成本高度依賴模型：Claude Opus 4.6 與 Claude Sonnet 4.6 在 TOC 模式下相對於內嵌模式的準確率變化僅 −0.6 至 +0.2 百分點（pp），區間包含零，無可偵測的成本（detectable cost）；然而 GPT-5.1 與 GPT-5.2 分別損失 11.3 與 7.9 個百分點。更深層的發現是，這些損失並非來自模擬計算錯誤——GPT 模型在各種介面下產生答案值的頻率幾乎相同——而是來自證據替代：代理跳過報告、改從高精度檔案截斷到相鄰選項。此外，GPT-5.4 雖在數值題上因證據使用損失約 10 個百分點，但因檢索下模擬正確率提升，淨變化與零無顯著差異。

**Q9：本研究進行了哪些消融實驗與介入測試？**
A：本研究設計了多項消融與介入實驗來驗證失敗位置與補救方式。首先，Grep 條件（純關鍵字搜尋）表現不優於 TOC，顯示問題並非介面本身，而是代理選擇讀取內容的傾向。其次，介入實驗顯示：明確告知「從 result.out 報告作答」（TOC+Report）可將 GPT-5.1、GPT-5.2、GPT-5.4 的準確率分別提升 6.3、7.9、7.8 個百分點，並將報告跳過率降至 2% 以下、閉合率提升至 99%。相對地，僅要求「正確捨入」（TOC+Round）則毫無效果，證明問題不在捨入行為，而在讀取來源。Hybrid 條件（適合時內嵌）對 GPT-5.1 與 GPT-5.2 也有同等效果。

**Q10：本研究的發現適用於哪些實際應用場景？**
A：本研究的結論適用於任何代理執行框架處理長工具輸出的場景，包括但不限於：程式碼執行紀錄、搜尋引擎結果批次、科學模擬器報告、資料庫查詢結果、系統日誌（logs）等。特別是當同一工具會產生多個輸出檔案，且其中只有一個是「權威輸出」（authoritative output）時，代理極易發生證據替代。例如在科學計算代理、程式碼助理、自動化研究助理等產品中，只要工具輸出超過上下文預算（fixed budget），就必須面臨內嵌或檢索的取捨，本研究提供了具體的設計準則。

**Q11：本研究對代理產品設計有何具體啟示？**
A：對產品設計而言，本研究提出三項具體建議：第一，當工具輸出能內嵌進上下文時，優先採用內嵌（inline），因為這對 GPT-5.1 與 GPT-5.2 效果等同於明確指定權威來源；第二，當必須使用檢索時，應在系統提示中明確命名權威輸出檔案（naming the authoritative output），這能帶來 6.3 至 7.9 個百分點的準確率提升；第三，僅要求「正確捨入」的提示無效，因此不應依賴捨入指令來彌補證據使用損失。這些發現意味著產品團隊應將「指定證據來源」視為一階設計決策，而非事後補救。

**Q12：本研究對整個領域將產生什麼樣的影響？**
A：本研究最重要的領域影響在於改變評估代理框架的方式：上下文管理選擇應以「損失發生在哪裡」而非僅以最終準確率來評判。這促使未來的基準測試與研究須能區分建構、暴露、閉合三階段的失敗，而非僅回報總分。此外，「證據替代」概念的提出為後續研究開啟了新方向——例如探討其他形式的證據錯用、跨工具的權威來源標記機制、以及代理在多檔案環境中的閱讀策略。對學術界與工業界而言，這都是重新審視「長上下文 vs. 檢索」此一經典取捨的契機。

**Q13：本研究承認有哪些限制？**
A：本研究的限制包括：題目數量僅 158 題，雖然經嚴格驗證但規模有限；實驗僅使用 PHREEQC 一個模擬器，雖然其確定性是研究優勢，但也意味著結論未必能直接外推到所有長輸出工具；測試的模型僅限 Claude Opus 4.6、Claude Sonnet 4.6、GPT-5.4、GPT-5.2、GPT-5.1 與 Gemini 3 Flash Preview 六款，未涵蓋其他模型家族；此外，研究聚焦於單一工具（PHREEQC）的單一輸出類型（報告），未涉及多工具協作或更複雜的代理工作流程。

**Q14：本研究揭示了哪些值得關注的失敗案例？**
A：最值得關注的失敗案例是圖 1 中 GPT-5.1 在第 121 題的表現：模擬同時寫出 result.out（pH = 2.751，答案 B）與 sel.out（2.75065，精度更高）。在內嵌模式下代理正確選 B，但在 TOC 模式下代理從未開啟 result.out，僅讀取 sel.out 並將 2.75065 截斷為 2.750（誘答選項 A）。更令人警覺的是，即使加上「請四捨五入而非截斷」的提示，GPT-5.1 仍以 46 vs 18 的比例選 A，顯示代理並未真正改變捨入行為；唯有明確告知「請從 result.out 作答」才能將錯誤比降至 2 vs 1。此案例凸顯了證據替代的頑固性與介入設計的精細要求。

**Q15：本研究開啟了哪些未來研究方向？**
A：本研究開啟了多條值得探索的未來方向：首先，可將建構-暴露-閉合框架應用於其他類型的工具（如網頁瀏覽、程式碼執行、資料庫查詢），檢驗證據替代是否為跨領域普遍現象；其次，可研究如何讓代理自動識別權威輸出，而非依賴人類在系統提示中指定；第三，可探討代理在多檔案環境中的閱讀策略最佳化，例如自動產生章節摘要、預先標記關鍵數值；最後，本研究也暗示需要發展新的評估指標，能同時反映最終準確率與證據使用正確性，以避免「淨變化為零」掩蓋實質損失的陷阱。

## 實務應用指南

### 適用場景

1. **科學模擬工具的代理整合**：當 LLM 代理需要呼叫 PHREEQC、Gaussian、COMSOL、OpenFOAM 等會產生數十萬字元結構化報告的科學模擬器時，採用本研究的「建構—暴露—閉合」三階段診斷法，可精準定位準確率下降究竟發生在模擬錯誤、報告未送達、還是代理讀錯證據。

2. **長輸出日誌的客服與維運代理**：在 SIEM、Splunk、雲端審計紀錄等場景中，工具輸出常超過上下文視窗。當代理需從長日誌中找出單一關鍵數值（如錯誤碼、IP、交易金額）時，可套用本研究的「權威輸出命名」介入法，避免代理跳過主日誌、改讀自己寫的高精度檔案而截斷錯誤。

3. **多檔案證據管線的法務與合規審查**：當代理同時讀取合約 PDF、附件、補充文件並需從中選取具法律效力的版本時，可使用「指定權威來源」指令（report hint）取代單純的「請正確捨入」指令，後者已被證實無效。

4. **RAG 系統中混合證據來源的問答**：當檢索結果同時包含摘要檔、原始檔、衍生檔時，可參考本研究的證據替代（evidence substitution）失敗模式，設計讓模型優先讀取「與答案選項同精度」的權威檔，而非「位數更多」的衍生檔。

5. **基準測試與代理評估平台**：評估新模型時，不應只比較最終準確率，應同時報告建構率、暴露率、閉合率，以避免 GPT-5.4 類型的「淨變化為零但內部損失十點」的被遮蔽效應。

### 實作前置條件

**資料需求**
- 一組具確定性、可重現的工具（模擬器、查詢引擎、API），以便分離「計算錯誤」與「證據使用錯誤」。
- 經執行驗證的答案鍵（execution-verified answer keys），且答案選項的精度與工具主報告的列印精度一致。
- 完整的代理軌跡日誌，包含每次工具呼叫的輸入、輸出、讀取範圍與最終答案。

**運算資源**
- 支援範圍讀取（ranged reads）、章節索引（TOC）、正規表達式搜尋三種檢索模式的代理執行框架。
- 至少 24 步以上的代理執行預算，以容納多次讀取與重試。
- 隔離的工作目錄，避免不同代理的輸出互相污染。

**技能需求**
- 熟悉代理執行框架（如 LangChain、AutoGen、自建 harness）的上下文管理 API。
- 能撰寫並比對三階段診斷腳本（build / exposure / closure）的工程師。
- 具備目標領域（如地質化學、財報分析）基本素養，以判斷「權威輸出」應為哪一份檔案。

### 實作步驟建議

1. **建立確定性基準**：選用具確定性的工具與可執行驗證的題庫，確認每題的答案鍵在多次執行下穩定不變，並記錄工具主報告的列印精度。

2. **實作三種輸出傳遞模式**：
   - `Inline`：將工具輸出直接貼入上下文，必要時截斷至固定字元預算。
   - `TOC`：僅回傳章節索引與起始行號，由代理以 `read_file` 範圍讀取。
   - `Hybrid`：報告可容納時內嵌，否則改用 TOC。

3. **記錄三階段指標**：對每條代理軌跡，計算
   - **建構率**：模擬是否產出與答案鍵相符的數值。
   - **暴露率**：該數值是否出現在代理讀過的檔案中。
   - **閉合率**：代理讀到後是否答對。
   三者相乘即為最終準確率的上限，便於定位損失階段。

4. **診斷失敗模式**：若閉合率低於暴露率且代理讀的是自己寫的高精度衍生檔（如 `SELECTED_OUTPUT`），即可判定為「證據替代」。此時應進入步驟 5 的介入。

5. **施加權威輸出指令**：在系統提示中加入三句指令，明確指定「請從 `result.out`（主報告）讀取答案，而非從你自己寫的衍生檔」。實測顯示此介入可為 GPT-5.1、GPT-5.2、GPT-5.4 分別帶來 +6.3、+7.9、+7.8 百分點的準確率提升。

6. **優先採用內嵌而非捨入提示**：若報告可容納於上下文，直接內嵌效果等同於權威輸出指令；但單獨加入「請正確捨入、不要截斷」指令已被證實無效，應避免僅依賴此類提示。

7. **監控淨變化與內部損失**：當某模型的最終準確率變化「與零無顯著差異」時，務必拆解建構率與閉合率的反向變動，避免 GPT-5.4 類型的「建構率上升掩蓋閉合率下降十點」的被遮蔽效應。

### 潛在風險與注意事項

- **模型差異極大**：同一種檢索介面對 GPT-5.1、GPT-5.2 是致命傷（−11.3、−7.9 pp），對 Claude Opus 4.6、Sonnet 4.6 卻無可偵測成本。切勿將單一模型的結論外推至全模型族，部署前必須在目標模型上重跑基準。

- **「正確捨入」指令的陷阱**：直覺上以為告訴代理「請四捨五入、不要截斷」就能解決問題，但實測顯示此指令對 GPT-5.1、GPT-5.2 幾乎無效（仍大量截斷至相鄰選項）。應改用「指定權威輸出檔」指令。

- **淨變化為零不等於無損失**：GPT-5.4 在檢索下建構率上升、閉合率下降約十點，淨變化為零。若只看最終準確率，會誤判該介面「對 GPT-5.4 無害」，實際上證據使用已嚴重退化。

- **關鍵字搜尋並非萬靈丹**：本研究測試的 Grep 模式（純正規表達式搜尋）並未優於 TOC，因為它同樣允許代理跳過主報告。結構化章節索引並非檢索成敗的關鍵，「代理會不會去看主報告」才是。

- **答案選項精度必須對齊主報告**：若選項精度（如 pH = 2.751）與主報告列印精度一致，閉合率才會高；若選項要求更多位數，代理會傾向讀衍生檔，惡化證據替代。

- **介入可能改變建構率以外的行為**：權威輸出指令主要改善閉合率，不會讓模擬本身變正確；若題目失敗的主因是建構缺陷（模擬寫錯輸入），此指令無效，應先修補輸入。

### 與其他技術的整合建議

- **與 RAG 系統整合**：將本研究的「權威輸出」概念映射為 RAG 中的「具引用編號的原文段落」，在系統提示中明確指示「請引用 [n] 標記的段落作答」，可緩解 LLM 傾向讀取摘要或自身重寫段落的問題。

- **與函式呼叫 / Tool Use 框架整合**：在 OpenAI Function Calling、Anthropic Tool Use 的 schema 中，為每個工具輸出加上 `authority_rank` 欄位，由框架自動注入「請優先讀取 rank 最高的檔案」指令，取代各團隊各自撰寫提示詞。

- **與評估平台整合**：在 HELM、lm-evaluation-harness 等基準中加入「三階段診斷指標」作為選用報表，讓模型發布時同時揭露建構、暴露、閉合的細部表現。

- **與觀測性平台整合**：將代理每次 `read_file` 的範圍、命中與否、是否最終影響答案，串接至 LangSmith、Langfuse 等追蹤系統，建立「證據使用儀表板」，供產品團隊監控證據替代率。

- **與傳統軟體工程整合**：在 CI/CD 中加入「證據替代回歸測試」——固定題庫、隨機抽樣代理軌跡，若閉合率低於閾值即阻擋合併，避免新提示詞或新模型悄悄退化證據使用。

### 給不同背景讀者的閱讀建議

**初學者**：先讀圖 1 的單題範例，理解「同一模擬、不同證據」如何讓 GPT-5.1 在內嵌下答對、在檢索下答錯；再讀第 1 節的四點結論，掌握「建構—暴露—閉合」三階段的直覺意義，不必急於進入數據細節。

**AI 工程師**：重點放在第 2.2 節的介面設計與第 5 節的介入實驗，特別是「權威輸出指令」的三句範本與「Hybrid 模式」的容量閾值邏輯；可將三階段指標直接整合進現有的代理評估管線，並在部署新模型前重跑基準。

**研究者**：第 3、4 節是方法論核心，特別是「固定模擬、僅改變傳遞」的控制變項設計如何分離計算與證據使用；GPT-5.4 的「淨變化為零但內部損失十點」是值得延伸的現象，可探討其他模型族是否存在類似遮蔽效應，並考慮將此框架推廣至非模擬類工具。

**產品經理**：核心訊息是「上下文管理選擇不能只看最終準確率」——同一介面對不同模型效果差異可達 11 百分點，且「請正確捨入」這類直覺提示無效；建議在產品路線圖中為代理框架加入「權威輸出指定」與「三階段診斷報表」兩項功能，並在模型升級時同步重跑基準。
