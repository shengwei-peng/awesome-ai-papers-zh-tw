## 摘要翻譯

測試時間擴展（Test-Time Scaling, TTS）透過投入額外的推論計算來提升大型語言模型（Large Language Model, LLM）的推理能力。現有改善TTS效率的方法大多僅針對單一資源維度來最佳化準確率，僅推進準確率-成本或準確率-延遲的帕累托前沿（Pareto frontier）。然而，使用者需求是多維度的：使用者可能同時指定準確率、延遲與推論成本需求，且不同的需求可能偏好不同的控制器。我們將個性化測試時間擴展（Personalized Test-Time Scaling）形式化為：發現可執行的控制器，以最大化使用者特定需求的聯合滿足率（Joint satisfaction rate）。為降低針對新使用者配置重複的策略發現開銷，我們提出PersonTTS，一個攤銷式代理策略發現（Amortized agentic policy discovery）框架，透過需求匹配控制器初始化（Requirement-matched controller initialization）與源蒸餾程序性指導（Source-distilled procedural guidance）重用先前的搜尋經驗，同時仍對每個候選進行目標配置評估（Target-profile evaluation）。在AIME與HMMT上的實驗顯示，PersonTTS在未見使用者配置（Unseen user profiles）與保留問題（Held-out problems）上的聯合滿足率方面，大幅超越強勁的TTS基線方法。在相同的候選評估預算（Candidate-evaluation budget）下，跨使用者經驗重用（Cross-user experience reuse）進一步提升了策略品質，同時大幅降低了發現代理（Discovery agent）的時間與成本。

### 核心貢獻（3～5點）
- **問題形式化**：將「個性化測試時間擴展」（Personalized Test-Time Scaling）定義為發現可執行的控制器，以最大化使用者特定需求的聯合滿足率，突破既有TTS方法僅最佳化單一資源維度的限制。
- **框架提出**：設計PersonTTS——一個攤銷式代理策略發現框架，透過需求匹配控制器初始化與源蒸餾程序性指導重用先前的搜尋經驗，大幅降低重複策略發現的開銷。
- **評估機制保留**：在重用經驗的同時，仍對每個候選策略進行目標配置評估，確保所選控制器真正符合目標使用者的多維度需求。
- **實驗驗證**：於AIME與HMMT數學推理基準上證明，PersonTTS在未見使用者配置與保留問題上的聯合滿足率均大幅超越強勁的TTS基線方法。
- **效率優勢**：在相同的候選評估預算下，跨使用者經驗重用進一步提升策略品質，同時大幅降低發現代理的時間與成本。

### 適合對象
從事大型語言模型推論效率最佳化、測試時間擴展技術、代理式AI系統設計，以及多目標最佳化（帕累托最佳化）研究的學者與工程師；特別適合關注如何將TTS技術從單一資源維度最佳化推向多維度使用者需求滿足的研發團隊，亦適合數學推理應用領域中需要兼顧準確率、延遲與成本約束的實務從業者。

## 深度分析

#### 方法論解析

本文提出了一個全新的問題形式化——**個性化測試時間擴展**（Personalized Test-Time Scaling），並設計了對應的解決框架 **PersonTTS**。其方法論可從問題定義、框架設計與核心機制三個層面進行深入剖析。

**問題形式化的關鍵轉變**

傳統測試時間擴展（TTS）研究主要沿著「準確率-成本」或「準確率-延遲」二維帕累托前沿（Pareto frontier）進行最佳化，這種做法將使用者的多維需求簡化為單一資源維度的權衡。然而，實際應用場景中，使用者通常同時指定準確率下限、延遲上限與推論成本上限三項聯合約束。不同需求組合可能偏好截然不同的控制器（controller）——例如高準確率需求可能偏好深度精煉策略，而低延遲需求則偏好早期剪枝策略。本文將此問題形式化為：給定使用者配置 $u = (a_u, L_u, C_u)$（分別為準確率、延遲、成本需求），尋找可執行的控制器 $\pi_u$，使其在保留問題集上的**聯合滿足率**（joint satisfaction rate）最大化。此形式化從「帕累托」轉向「偏好」，強調多約束聯合可行性（joint feasibility）而非單一前沿的支配關係。

**PersonTTS 框架的三大核心機制**

第一，**需求匹配控制器初始化**（requirement-matched controller initialization）。框架從源使用者（source users）的搜尋經驗中，根據需求相似度檢索最接近的控制器作為目標配置的起始點。這一設計基於一個關鍵觀察：相近需求下的有效控制器往往共享相似的策略結構（例如相似的分支擴展模式或剪枝閾值）。然而，僅靠相似度匹配並不足夠，因為控制器對需求的敏感性可能非線性，因此仍需在目標配置下重新評估。

第二，**源蒸餾程序性指導**（source-distilled procedural guidance）。框架從多個源使用者的搜尋歷史中蒸餾出一個**凍結指南**（Frozen Guide）$G$，該指南以**條件式修訂規則**（conditional revision rules）的形式編碼了「在何種回放反饋模式下應採取何種控制器修訂」的經驗知識。這種設計將程序性知識（procedural knowledge）從具體控制器中抽離，使其能跨需求配置遷移。凍結設計避免了指南在目標搜尋中被污染，確保其作為穩定的先驗引導。

第三，**目標配置評估**（target-profile evaluation）。儘管初始化與指導來自源經驗，每個候選控制器仍必須在目標使用者配置下通過**回放評估器**（replay evaluator）進行評估。回放評估器收集控制器觀察（controller observation）、展開動作（rollout action）、分支狀態（branch state）、答案觀察（answer observation）與資源帳本（resource ledger），以計算聯合滿足率。這一機制保證了控制器對目標需求的真實適配性，避免了跨使用者直接遷移可能帶來的偏差。

**控制器動作空間與搜尋迴圈**

可執行控制器透過五類動作協調推理過程：生成（Spawn, $m, n$）決定並行分支數量與深度；繼續（Continue, $l$）延伸現有分支；精煉（Refine, $l$）改進特定分支；剪枝（Prune, $l$）淘汰低價值分支；結束（Finish, $y$）終止推理並彙總答案。LLM 發現代理（discovery agent）以目標需求、回放反饋與累積搜尋歷史為輸入，迭代提出候選策略 $\pi_{u,t}$，並依聯合滿足率選取最佳控制器 $\pi_u^{best}$。整個過程在固定的**候選評估預算**（candidate-evaluation budget）下運作，確保不同方法間的公平比較。

**攤銷機制的理論意涵**

「攤銷式」（amortized）一詞在此具有雙重意涵：其一，跨使用者的搜尋成本被分攤——源使用者的探索經驗以初始化與指南的形式被重用，避免每個新配置都從零開始搜尋；其二，單一使用者的搜尋成本隨經驗庫擴展而遞減。文中提及完整策略發現需耗費約 39.9 美元與 160 分鐘，攤銷機制的引入使這一成本得以顯著降低。

#### 實驗數據解讀

**實驗設計的嚴謹性**

實驗在兩個具有挑戰性的數學推理基準上進行：**AIME**（美國數學邀請賽）與 **HMMT**（哈佛-麻省理工數學錦標賽），兩者均為高難度競賽題目，能有效區分不同 TTS 策略的效能差異。模型選用六個 **Qwen3** 系列模型，涵蓋不同規模與能力等級，有助於驗證方法的泛化性。更關鍵的是，實驗採用了嚴格的分離設計：源使用者配置與目標使用者配置獨立採樣，且使用獨立的**保留問題集**（held-out problems），這避免了資訊洩漏並確保了對**未見使用者配置**（unseen user profiles）的泛化評估。

**核心結果的解讀**

PersonTTS 在聯合滿足率上「實質性地超越」（substantially outperforms）強基線 TTS 方法。這一結果的意義在於：傳統基於帕累托前沿的方法即使在各自的二維前沿上表現優異，仍可能在三維聯合需求下失效，因為其最佳化目標與聯合可行性之間存在系統性偏差。PersonTTS 直接最佳化聯合滿足率，因此能發現那些在任一二維前沿上可能不突出、但在三維聯合約束下表現優異的控制器。

**跨使用者經驗重用的效益**

在相同的候選評估預算下，跨使用者經驗重用不僅提升了策略品質，還大幅降低了發現代理的時間與金錢成本。這一結果驗證了攤銷機制的有效性：源使用者的探索經驗並非冗餘資訊，而是提供了有價值的先驗，使目標搜尋能更快收斂到高品質區域。值得注意的是，策略品質的提升與成本降低是同時發生的，這意味著經驗重用並非以犧牲探索品質為代價的捷徑，而是真正的效率增益。

**消融研究的意涵**

消融實驗分別檢驗了需求匹配初始化與程序性指導的獨立貢獻。這種分離設計有助於理解兩個機制的互補性：初始化提供了良好的起點，避免搜尋從低品質區域開始；程序性指導則提供了搜尋方向的先驗，加速向高品質區域的移動。兩者的結合產生了超越各自獨立貢獻的協同效應，說明它們在搜尋過程中扮演互補而非冗餘的角色。

**評估指標的選擇**

採用聯合滿足率作為核心指標，而非單一的準確率或成本，是本文方法論立場的直接體現。這一指標直接對應問題形式化中的最佳化目標，避免了傳統 TTS 評估中常見的「以單一指標掩蓋多維度權衡」的問題。

#### 與現有研究的比較

**相較於傳統帕累托式 TTS 方法的定位**

既有 TTS 效率研究（如自適應採樣 [adaptive sampling]、提前停止 [early stopping]、選擇性分支剪枝 [selective branch pruning] 等）主要沿著單一資源維度推進帕累托前沿。本文的核心論點是：這種做法在多維聯合需求下存在系統性盲區——如圖 1 所示，兩個二維前沿的 3D 支配區域（3D-dominated region）的聯集仍可能遺漏某些聯合可行的控制器。PersonTTS 透過直接最佳化聯合滿足率，繞過了帕累托前沿的局部性限制，能發現那些在任一二維前沿上不突出但在三維聯合約束下表現優異的策略。

**相較於 Zheng et al. (2026b) 的改進**

文中提及 Zheng et al. (2026b) 的完整策略發現需耗費 39.9 美元與 160 分鐘，這對實際部署構成顯著障礙。PersonTTS 的攤銷機制透過跨使用者經驗重用，將這一成本大幅降低，同時提升了策略品質。這一改進對於 TTS 系統的實用化具有重要意義——若每個新使用者配置都需要如此高昂的發現成本，個性化 TTS 將難以規模化。

**方法論的侷限性**

儘管 PersonTTS 展現了顯著優勢，仍存在若干侷限性。首先，框架效能依賴於源使用者經驗庫的品質與覆蓋範圍；若源配置與目標配置差異過大，需求匹配初始化可能提供誤導性的起點。其次，凍結指南的蒸餾品質受源搜尋歷史多樣性的影響，若歷史中缺乏某些需求區域的探索，指南在對應區域的指導可能不可靠。第三，框架仍需在目標配置下進行完整的回放評估，這意味著對單一使用者的最低成本仍非零——攤銷機制降低的是邊際成本而非固定成本。

**與其他代理式方法的區隔**

近年湧現的代理式 LLM 應用（如自動機器學習、代理式程式碼生成）通常採用單一任務的搜尋迴圈。PersonTTS 的獨特之處在於將「跨任務經驗重用」明確納入框架設計，這與元學習（meta-learning）或遷移學習的精神相通，但在 TTS 控制器發現的具體語境下實現。這一架構選擇使其在多使用者場景下具有結構性優勢。

#### 可重現性評估

**程式碼與資料的開放性**

本文明確聲明程式碼與資料已釋出於 GitHub 倉庫（https://github.com/WangXinglin/PersonTTS），這為重現實驗提供了基礎。對於方法論類論文而言，程式碼的開放性是評估可重現性的首要指標。

**資料集的可及性**

實驗使用的 AIME 與 HMMT 題目均為公開可取得的數學競賽題目集，無授權問題。HMMT 引用了 Dekoninck et al. (2026) 的資料來源，讀者可依循該引用取得原始資料。

**模型的開放性**

實驗採用 Qwen3 系列模型，該系列模型在 Hugging Face 等平台公開發布，支援本地部署與推理。這避免了對閉源模型 API 的依賴，使實驗可在受控環境下完整重現。

**超參數與設定的透明度**

雖然現有文本未完整列出所有超參數，但 GitHub 倉庫通常會包含完整的設定檔與執行腳本。建議讀者關注以下細節：候選評估預算的具體數值、源使用者配置的採樣分佈、回放評估器的問題集規模，以及 LLM 發現代理的提示模板。

**重現的潛在挑戰**

儘管基礎資源齊全，仍存在若干重現挑戰：其一，LLM 發現代理的行為可能受底層模型版本影響，若 Qwen3 模型更新，搜尋軌跡可能產生變異；其二，跨使用者經驗庫的構建需要多次完整的策略發現運行，這本身需要可觀的計算資源；其三，聯合滿足率的計算依賴於精確的延遲與成本測量，硬體環境的差異可能影響絕對數值。建議重現實驗時採用相對比較（與基線的增益）而非絕對數值作為主要評估依據。

#### 未來研究方向

**擴展至非數學領域**

本文聚焦於數學推理任務，但 TTS 技術同樣適用於程式碼生成、開放領域問答、科學推理等場景。未來研究可探索 PersonTTS 在這些領域的適配性，特別是控制器動作空間是否需要針對不同任務特性進行調整。例如，程式碼生成任務可能需要「測試驅動剪枝」等領域特定動作。

**更細緻的使用者需求建模**

當前的使用者配置僅包含三個標量維度（準確率、延遲、成本）。實際應用中，使用者需求可能更為複雜：可能包含對特定錯誤類型的容忍度、對推理過程可解釋性的要求，或對資源消耗隨時間變化的動態約束。未來工作可探索將這些高階需求納入形式化框架，並設計相應的控制器發現機制。

**線上學習與動態適配**

本文假設使用者配置在策略發現前已完全指定。然而，實際系統中使用者需求可能隨時間演變（例如，使用者根據初步體驗調整延遲容忍度）。未來研究可探索線上學習機制，使控制器能在運行過程中根據使用者反饋動態調整，避免每次需求變更都觸發完整的策略發現流程。

**理論分析攤銷效益**

本文以實驗方式驗證了攤銷機制的效益，但缺乏對「為何經驗重用能提升策略品質」的理論分析。未來工作可從最佳化理論或學習理論的角度，分析源經驗在何種條件下能提供有效的先驗，以及需求匹配度與策略品質提升之間的定量關係。這將有助於設計更系統化的經驗庫管理策略。

**多模態與工具整合推理**

隨著多模態推理與工具增強 LLM 的發展，TTS 控制器可能需要協調視覺模型、搜尋引擎、程式碼執行器等多種資源。這將使控制器的動作空間與資源維度大幅擴張，對聯合滿足率最佳化提出新的挑戰。PersonTTS 的攤銷框架可作為起點，但需要發展新的機制來處理異質資源的聯合最佳化。

**安全性與對齊考量**

TTS 控制器在最佳化聯合滿足率的過程中，可能發現一些「投機取巧」的策略——例如在特定問題集上表現優異但泛化能力薄弱的控制器。未來研究應探討如何在聯合滿足率最佳化中納入穩健性與泛化性約束，避免過擬合到特定問題分佈。同時，當控制器涉及工具調用或外部資源存取時，需考慮對齊與安全邊界。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文提出「個性化測試時間擴展」（Personalized Test-Time Scaling）這一新問題設定，旨在發現可執行的控制器，使其能最大化使用者特定需求（同時包含準確率、延遲與推論成本三個維度）的聯合滿足率。傳統的測試時間擴展方法通常只針對單一資源維度進行最佳化，但實際使用者的需求是多維度且聯合的，因此需要一個能同時考量三者的框架。這個問題的核心挑戰在於，不同的使用者需求組合可能會偏好完全不同的控制器策略，因此必須為每個使用者配置量身打造合適的策略。

**Q2：為什麼現有的基於帕累托前沿的 TTS 方法無法有效解決這個問題？**
A：現有方法主要在「準確率-成本」或「準確率-延遲」這兩個二維帕累托前沿上進行最佳化，每次只考慮一個資源維度與準確率的權衡。這種成對最佳化的方式會產生所謂的「三維支配區域」，但這些區域可能會錯過能同時滿足三維需求的聯合可行控制器。換言之，即使一個控制器在三維空間中能滿足所有需求，它在任一二維投影上可能都不是帕累托最優的，因此會被既有方法忽略。這說明了為何需要從帕累托典範轉向偏好典範，直接以聯合滿足率作為最佳化目標。

**Q3：為什麼這個問題在實務上很重要？**
A：在實際部署場景中，使用者通常會同時對準確率、延遲與成本提出聯合要求，例如「準確率至少 80%、延遲不超過 5 秒、單次推論成本低於 0.01 美元」。不同應用場景（如即時客服、批次分析、邊緣裝置部署）對這三個維度的容忍度差異極大，因此單一通用控制器無法滿足所有使用者。此外，為每個新使用者配置從頭執行完整的策略搜尋成本極高（單次執行約需 39.9 美元與 160 分鐘），這使得大規模個人化部署變得不切實際，因此需要一個能攤銷設計成本的高效框架。

**Q4：PersonTTS 的核心方法是什麼？**
A：PersonTTS 是一個攤銷式代理策略發現框架，其核心思想是跨使用者重用先前的搜尋經驗。具體而言，它透過兩個關鍵機制實現攤銷：一是「需求匹配控制器初始化」，從具有相似需求的源使用者配置中檢索控制器，並在目標配置下重新評估以初始化發現過程；二是「源蒸餾程序性指導」，透過一個從源發現歷史中蒸餾而來的凍結指南（Frozen Guide）來告知後續的控制器提案。一個由 LLM 驅動的發現代理會結合目標需求、回放反饋與累積的搜尋歷史來提出可執行的控制器，每個候選控制器都在目標配置下進行評估，最終選出聯合滿足率最高的控制器。

**Q5：PersonTTS 的關鍵創新點是什麼？**
A：PersonTTS 的關鍵創新在於將「跨使用者經驗重用」與「目標專屬評估」這兩個看似矛盾的需求巧妙結合。傳統的遷移學習方法可能假設策略可以跨使用者直接轉移，但本文認識到候選控制器必須在目標配置下重新評估，因為個人化不僅影響評估方式，也影響控制器的執行邏輯。透過同時實現控制器重用（從相似需求的源使用者取得起始點）與程序性指導重用（透過凍結指南傳遞搜尋經驗），PersonTTS 在保留目標專屬評估嚴謹性的同時，大幅降低了重複搜尋的成本，這是對代理式策略發現範式的重要擴展。

**Q6：PersonTTS 在設計上有哪些重要的選擇？**
A：PersonTTS 在設計上做了多項關鍵選擇：首先，它採用「回放評估器」（Replay Evaluator）作為外部評估模組，能重現控制器執行過程並收集資源帳本（Resource Ledger）以追蹤延遲與成本；其次，控制器被設計為可執行代碼形式，能協調模型選擇、推理寬度與深度、精煉、剪枝與停止等動作（如 Spawn、Continue、Refine、Prune、Finish 等展開動作）；第三，凍結指南採用「條件式修訂規則」的形式，使其能根據目標需求動態調整建議；最後，框架保留了完整的搜尋歷史記錄（代碼與反饋歷史），使發現代理能從過去的嘗試中學習並持續改進候選策略。

**Q7：實驗使用了哪些基準測試集與模型？**
A：實驗在兩個具有挑戰性的數學競賽基準上進行：AIME（美國數學邀請賽）與 HMMT（哈佛-麻省理工數學錦標賽），這兩個資料集都是測試大型語言模型數學推理能力的標準基準。研究使用了六個不同規模的 Qwen3 模型（Yang et al., 2025）作為基礎推理模型，以涵蓋不同的能力與成本特性。此外，實驗設計特別強調了泛化性測試：源使用者配置與目標使用者配置是獨立採樣的，並使用獨立的保留問題集（held-out problems）來評估方法的真實泛化能力，這比簡單的同分布測試更能反映實際部署情境。

**Q8：PersonTTS 的關鍵實驗結果為何？**
A：PersonTTS 在聯合需求滿足率上大幅優於強基線 TTS 方法，這一結果在未見使用者配置與保留問題集上都得到了驗證，顯示出良好的泛化能力。更重要的是，在相同的候選評估預算下，跨使用者經驗重用不僅提升了策略品質（聯合滿足率更高），還大幅降低了發現代理的時間與金錢成本。這意味著 PersonTTS 不僅能找到更好的控制器，還能更高效地找到它，實現了品質與效率的雙重提升。具體而言，相較於獨立的目標側發現，攤銷式方法在保持或超越策略品質的同時，顯著減少了搜尋所需的計算資源。

**Q9：消融研究揭示了哪些設計組件的重要性？**
A：消融研究釐清了「需求匹配初始化」與「程序性指導」這兩個核心組件在個性化策略發現中的獨特角色。實驗結果顯示，移除任一組件都會導致效能下降，但兩者的影響可能體現在不同面向：需求匹配初始化主要影響搜尋的起點品質，使發現代理能從一個更接近最優解的區域開始探索；程序性指導則影響搜尋過程中的提案品質，幫助代理避免重複過去的錯誤並更快收斂。這兩個組件的互補性說明了為何 PersonTTS 採用雙重重用機制，而非僅依賴其中之一，這也為未來的改進方向提供了明確的指引。

**Q10：PersonTTS 適用於哪些實際應用場景？**
A：PersonTTS 特別適合需要為不同使用者群體提供差異化 AI 推理服務的場景，例如：企業級 AI 助手需要根據客戶的 SLA（服務等級協議）調整推理策略；教育科技平台需要根據學生的裝置能力與網路條件提供不同品質的解題服務；邊緣運算部署需要在嚴格的延遲與成本限制下維持足夠的準確率。在這些場景中，使用者需求的異質性很高，單一通用策略無法同時滿足所有需求，而 PersonTTS 的攤銷式發現機制使得為大量不同需求配置提供個人化策略變得經濟可行。

**Q11：將 PersonTTS 應用於實際產品時需要考量哪些因素？**
A：將 PersonTTS 整合到實際產品中需要考量幾個關鍵因素：首先，需要建立完善的源使用者配置資料庫與相似度匹配機制，以支援需求匹配初始化；其次，凍結指南的蒸餾品質直接影響跨使用者遷移的效果，因此需要持續收集與更新發現歷史；第三，雖然 PersonTTS 大幅降低了單次策略發現的成本，但首次建立框架仍需投入資源，因此適合需求異質性高、部署規模大的場景；最後，產品的監控系統需要能追蹤不同控制器的實際表現，以便在需求分布漂移時觸發重新發現流程。

**Q12：這項研究對學術與工業界的影響是什麼？**
A：這項研究最重要的影響在於典範轉移：將測試時間擴展的研究焦點從「帕累托最佳化」轉向「偏好驅動的個人化」，這與當前 AI 服務從通用化走向個人化的趨勢一致。在學術上，它為「代理式策略發現」這一新興領域提供了具體的方法論與實證基礎，展示了 LLM 代理在自動化設計高效推理策略方面的潛力。在工業界，它提供了一條降低個人化 AI 部署成本的可行路徑，使得為不同客戶群提供量身打造的推理服務成為可能，這對於 AI 服務的商業化與普及具有重要意義。

**Q13：這篇論文存在哪些已承認的限制？**
A：雖然論文展示了令人印象深刻的結果，但仍存在一些可推論的限制：首先，實驗僅在數學推理任務（AIME 與 HMMT）上驗證，尚未涵蓋程式設計、開放域問答等其他推理任務，泛化性有待進一步驗證；其次，框架假設使用者需求可以表示為準確率、延遲與成本的三元組，但實際需求可能更複雜（如多目標權重、動態約束等）；第三，源使用者與目標使用者的需求分布假設存在某種相似性，若分布差異過大，需求匹配初始化的效果可能會下降；最後，框架依賴於 LLM 發現代理的能力，因此其效能上限受到基礎模型能力的制約。

**Q14：PersonTTS 在哪些情況下可能會失敗？**
A：PersonTTS 在以下幾種情況下可能表現不佳：第一，當目標使用者的需求與所有源使用者需求都不相似時，需求匹配初始化將退化为隨機初始化，攤銷效益將大打折扣；第二，當問題領域發生顯著變化（如從數學推理轉到程式設計）時，從源歷史蒸餾的凍結指南可能無法提供有用的指導；第三，當目標需求極為嚴苛（如要求極高準確率同時極低延遲）時，可能根本不存在滿足需求的控制器，此時框架的聯合滿足率會趨近於零；第四，若 LLM 發現代理在特定需求組合下反覆提出無效的控制器代碼，可能會浪費大量評估預算而無法收斂。

**Q15：這項研究的未來發展方向有哪些？**
A：基於本文的框架，未來有多個值得探索的方向：首先，可以將應用領域從數學推理擴展到更廣泛的任務（如程式碼生成、多步驟規劃、科學推理），以驗證框架的通用性；其次，可以引入更豐富的需求表示（如動態約束、多目標權重、機率性需求），使框架能處理更複雜的個人化場景；第三，可以探索更高效的經驗重用機制，如跨任務（而非僅跨使用者）的策略遷移；第四，可以研究如何讓框架在部署過程中持續學習，自動發現新的需求模式並更新源資料庫；最後，可以將 PersonTTS 與其他 AI 個人化技術（如個人化微調、檢索增強生成）結合，構建更全面的個人化 AI 系統。

## 實務應用指南

### 適用場景

1. **多層級訂閱制的 AI 數學家教平台**：平台同時提供免費（低延遲、低成本、容忍中等準確率）、專業版（中等延遲與成本、高準確率）與企業版（高準確率、可接受較高延遲與成本）三種方案。PersonTTS 可為每個方案自動發現專屬的 TTS 控制器，避免為每個新方案重新從零搜尋策略。

2. **教育科技公司的智慧題庫批改系統**：學校與補習班對批改速度（延遲）、API 費用（成本）與正確率有不同要求。透過 PersonTTS 預先為不同客戶配置（profile）建立控制器，新客戶上線時只需重用相近需求的控制器並做目標配置評估，大幅縮短部署時間。

3. **企業內部 LLM 推理閘道（Inference Gateway）**：公司內不同部門（客服、研發、法務）對延遲與成本的容忍度差異極大。PersonTTS 可作為閘道內的策略路由器，根據部門 SLA 自動選擇對應的 TTS 控制器，並在新增部門時透過跨使用者經驗重用快速收斂。

4. **行動裝置上的混合雲端推理**：行動 App 需在裝置端與雲端間動態分配推理，網路狀況決定延遲預算、電池與資費決定成本預算。PersonTTS 可根據即時使用者配置（網速、剩餘電量、訂閱等級）即時挑選最合適的控制器。

5. **競賽級 AI 解題服務（如 AIME/HMMT 模擬訓練）**：不同使用者希望針對特定難度的題目設定不同「速度 vs 正確率」權重。PersonTTS 能在保留題目（held-out problems）上驗證控制器泛化能力，並依個人偏好動態調整。

### 實作前置條件

**資料準備**
- 一批帶有「需求標註」的使用者配置資料集：每筆包含目標準確率門檻 $a_u$、延遲上限 $L_u$、成本上限 $C_u$，以及對應的滿意度標籤（joint satisfaction rate）。
- 來源使用者（source users）的策略發現歷史紀錄：包含每輪候選控制器、回放評估結果、修改理由，用於蒸餾「凍結指南」（Frozen Guide）。
- 目標使用者（target users）的保留題目集（held-out problems），需與來源題目集嚴格分離，避免資料洩漏。

**運算資源**
- 至少 6 種不同規模的 LLM（如 Qwen3 系列）作為候選推理模型，以支援控制器內的模型選擇決策。
- 一個可執行回放（replay）的沙盒環境，需能追蹤「資源帳本」（resource ledger）以記錄每次展開動作的延遲與成本。
- 候選評估預算（candidate-evaluation budget）需事先設定，例如每輪允許 $m$ 個候選、$n$ 次展開，這是控制總成本的核心旋鈕。

**技能門檻**
- 熟悉 LLM 代理（agentic）設計模式：能撰寫讓 LLM 根據代碼與反饋歷史提出新控制器的提示工程。
- 具備多目標最佳化與帕累托前沿分析基礎，能正確解讀三維支配區域（3D-dominated region）。
- 程式能力：Python 為主，需能實作控制器動作（Spawn / Continue / Refine / Prune / Finish）的狀態機。
- 具備分散式推理經驗，能管理多模型並行回放以控制總發現時間。

### 實作步驟建議

**步驟一：問題形式化與需求空間設計**
將業務需求映射為三元組 $(a_u, L_u, C_u)$，定義「使用者需求區域」$R$ 與「系統可行區域」$S$，並以聯合滿足率 $|S \cap R| / |R|$ 作為單一最佳化目標。避免落入「成對帕累托前沿」的陷阱——單看準確率-成本或準確率-延遲前沿，可能錯過三維聯合可行的控制器。

**步驟二：建立來源使用者經驗池**
為一組具代表性的來源使用者各執行一次完整的策略發現流程，記錄每輪的候選控制器、回放分數與修改理由。這些歷史將用於兩個用途：(1) 訓練「凍結指南」中的條件式修訂規則；(2) 建立可重用的「需求匹配控制器庫」。

**步驟三：實作凍結指南（Frozen Guide）**
從來源歷史中蒸餾出程序性指導，例如「當延遲超標時優先 Prune 而非降低模型規模」「當成本超標時減少 Spawn 數量」。指南一旦凍結就不再更新，避免在目標端搜尋時發生災難性遺忘（catastrophic forgetting）。

**步驟四：實作需求匹配初始化**
對新到位的目標使用者 $(a_u, L_u, C_u)$，從控制器庫中以距離度量（如三維歐氏距離或加權距離）找出最相近的來源控制器作為 Round-0 初始控制器，並立即在目標配置下做回放評估，確認其轉移可行性。

**步驟五：設計 LLM 發現代理的提示與動作空間**
提示詞需包含三項輸入：目標需求三元組、當前控制器代碼、累積的回放反饋歷史。動作空間限定為五種高階操作（Spawn / Continue / Refine / Prune / Finish），避免代理提出無法回放驗證的任意程式碼。

**步驟六：迭代搜尋與預算控制**
每輪由代理提出 $m$ 個候選控制器，全部在目標配置下做回放評估，選出聯合滿足率最高者進入下一輪。設定總候選評估預算（例如 50 個候選）作為硬性停止條件，確保發現成本可控。

**步驟七：保留題目驗證與上線**
在與來源題目集分離的保留題目集上做最終驗證，確認控制器對未見題目同樣有效。通過後即可部署為推理閘道中的策略選項，並持續收集新使用者回饋以擴充來源經驗池。

### 潛在風險與注意事項

**風險一：來源與目標配置分布偏移**
若新使用者的需求落在來源經驗池覆蓋範圍之外，需求匹配初始化可能挑到不相關的控制器，反而拖慢收斂。**緩解**：在控制器庫中保留少量「極端配置」控制器（如最低成本、最高準確率）作為錨點；對分布外的需求啟用純目標端搜尋（不重用）。

**風險二：回放評估的高昂成本**
論文中一次完整策略發現約需 \$39.9 與 160 分鐘，若每個新使用者都跑一次會迅速耗盡預算。**緩解**：嚴格設定候選評估預算；優先重用而非重新搜尋；對低價值使用者配置使用啟發式預設控制器。

**風險三：凍結指南的過時風險**
來源經驗池擴充後，凍結指南可能不再反映最新最佳實務，但更新指南需要重新蒸餾並承擔風險。**緩解**：採「版本化指南」策略，保留多個版本的指南並依來源池規模自動選擇；定期以小規模 A/B 測試驗證新指南。

**風險四：控制器泛化失敗**
在來源題目集表現良好的控制器，可能在保留題目集上聯合滿足率顯著下降。**緩解**：保留題目驗證為強制閘門；控制器設計時避免過度擬合特定題型（例如限制分支深度上限）。

**風險五：代理提出不可執行程式碼**
LLM 代理可能產生語法錯誤或語意不明的控制器代碼，導致回放失敗浪費預算。**緩解**：在回放前加入靜態語法檢查與單元測試；動作空間限定為五種高階操作而非任意 Python 代碼。

**風險六：三維需求空間的稀疏性**
當準確率、延遲、成本三個維度的需求都很嚴苛時，聯合可行區域可能極小甚至為空。**緩解**：在預搜尋階段先估算 $|S \cap R|$，若過小則主動放寬某一維度需求並通知使用者。

### 與其他技術的整合建議

**與既有 TTS 框架整合**
PersonTTS 並非取代自適應採樣（adaptive sampling）、提前停止（early stopping）、選擇性分支剪枝（selective branch pruning）等技術，而是將它們組合成「可發現的控制器」。建議將既有 TTS 技術封裝為控制器內的子模組，讓 LLM 代理只需決定何時呼叫哪個子模組，而非從零設計。

**與模型路由（Model Routing）系統整合**
控制器內的「模型選擇」決策可與外部模型路由器解耦：路由器負責根據題目難度挑選候選模型，控制器負責決定推理寬度、深度與停止時機。兩者透過標準化介面（如 OpenAI-compatible API）對接。

**與監控與可觀測性平台整合**
將「資源帳本」（resource ledger）與 Prometheus / Grafana 等監控系統對接，即時追蹤每個使用者的延遲與成本消耗。當實際資源偏離需求時，可觸發控制器的線上再發現（online re-discovery）。

**與快取與結果重用層整合**
對於相同題目與相似使用者配置，可快取先前發現的控制器與其回放結果，避免重複評估。建議以需求三元組的雜湊作為快取鍵。

**與 A/B 測試平台整合**
新控制器上線前，透過 A/B 測試平台與現行控制器並行運行，以聯合滿足率作為主要指標、成本與延遲作為次要指標，避免單一指標最佳化造成的隱性退化。

**與 RAG 與工具呼叫整合**
控制器可擴充動作空間，加入「呼叫外部工具」或「檢索補充知識」動作，特別適用於需要即時資訊的場景。建議將工具呼叫包裝為標準化動作以維持回放可行性。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先專注於第 1 節的「問題動機」與圖 1 的視覺對比，理解「為什麼單看準確率-成本或準確率-延遲的帕累托前沿會錯失聯合可行的控制器」。接著閱讀「PersonTTS 框架」段落，掌握「重用來源經驗 + 目標端評估」的核心思想。數學形式（如三維支配區域）可先跳過，待熟悉概念後再回頭補強。

**給 AI 工程師**：重點閱讀方法章節中的「需求匹配初始化」與「凍結指南」實作細節，特別關注候選評估預算（candidate-evaluation budget）的設計——這是控制總發現成本的關鍵旋鈕。建議直接 clone 官方程式碼（GitHub: WangXinglin/PersonTTS），先在小型題目集上重現實驗，再逐步擴展到生產規模。注意回放評估器的資源帳本實作，這是整個系統的瓶頸。

**給研究者**：本文的核心貢獻在於「將帕累托最佳化轉為偏好最佳化」的問題重定義，以及「攤銷式代理策略發現」的演算法設計。建議從附錄中的理論分析切入，特別是聯合滿足率與帕累托支配的關係證明。可進一步探索的方向包括：將需求空間從三維擴展到更高維度、放寬凍結指南以支援線上蒸餾、以及在多代理協作場景下的控制器發現。與 Zheng et al. (2026b) 的工作做縱向比較，能更清楚定位本文的增量貢獻。

**給產品經理**：本文的核心訊息是「不同使用者對 AI 推理的需求是多元且聯合的，單一最優策略不存在」。建議從圖 1 的左半部（既有方法的盲點）開始閱讀，理解為什麼現有 TTS 優化無法滿足多層級訂閱或差異化 SLA 的商業需求。PersonTTS 的商業價值在於「為新使用者配置快速找到合適控制器」的能力——這直接影響客戶上線時間、API 成本與使用者滿意度。評估導入價值時，應以「每新增使用者配置的發現成本」與「聯合滿足率提升幅度」作為關鍵指標。
