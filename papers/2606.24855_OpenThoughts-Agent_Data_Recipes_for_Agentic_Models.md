## 摘要翻譯

代理式語言模型（agentic language models）大幅擴展了人工智慧（AI）的應用，然而外界對於如何為具備廣泛能力的智慧代理（agents）整理訓練資料（training data）仍所知甚少。現有的開源成果如 SWE-Smith、SERA 與 Nemotron-Terminal 通常僅針對單一基準測試（benchmark），使得「如何訓練出能泛化（generalize）於多樣代理式任務的模型」仍懸而未決。OpenThoughts-Agent（OT-Agent）專案透過一套完全開放的資料整理管線（data curation pipeline）來填補此缺口，以訓練代理式模型（agentic models）。我們進行了超過 100 項控制變因消融實驗（controlled ablation experiments），系統性地研究管線（pipeline）的每個階段，從而得出關於任務來源（task sources）與多樣性（diversity）之重要性的洞見。接著，我們從管線中彙整出包含 10 萬筆範例的訓練集（training set），並以此資料集微調（fine-tune）Qwen3-32B，在七項代理式基準測試（agentic benchmarks）上達到 44.8% 的平均準確率（average accuracy），相較於現有最強大的開放資料集代理式模型 Nemotron-Terminal-32B（40.9%）提升了 3.9 個百分點（percentage point）。此外，我們的訓練資料展現出強大的擴展特性（scaling properties），在運算受控比較（compute-controlled comparisons）中，在每個訓練集規模（training set size）下均優於其他替代性開放資料集。我們在 openthoughts.ai 公開釋出訓練集、資料管線、實驗資料與模型，以支援未來關於代理式模型訓練的開放研究。

### 核心貢獻（3～5點）
- 提出一套完全開放的資料整理管線（data curation pipeline），填補現有開源資料集僅針對單一基準測試（benchmark）而難以泛化（generalize）至多樣代理式任務的缺口。
- 以逾 100 項控制變因消融實驗（controlled ablation experiments）系統性驗證管線各階段，揭示任務來源（task sources）與多樣性（diversity）對代理式模型訓練的關鍵影響。

## 深度分析

#### 方法論解析

OpenThoughts-Agent（OT-Agent）專案的核心方法論在於建立一套六階段監督式微調（Supervised Fine-Tuning, SFT）資料整理管線（data curation pipeline），專門用於產生代理式模型（agentic models）所需的後訓練資料（post-training data）。有別於過往開源資料集多採用單點突破策略，本研究透過超過 100 組消融實驗（ablation experiments），系統性地拆解資料整理管線中每個階段對模型泛化（generalize）能力的因果影響，從中提煉出四項關鍵資料配方（data recipes）原則。

第一，指令（instruction）的選擇與設計是整個管線中最重要的變因之一，其影響力堪比推理模型訓練中的推理資料設計，顯示代理式能力並非單純仰賴執行軌跡（execution traces）的數量，而是高度依賴任務描述與互動格式的品質。第二，基準測試表現（benchmark performance）最強的教師模型（teacher model）未必能產生最優質的訓練資料；這項發現挑戰了「模型越強，蒸餾效果越好」的直覺，暗示存在最適教師強度的門檻效應，過強的模型可能產生過於簡潔或跳步的軌跡，反而不利於學生模型學習長程規劃（long horizon）的細節。第三，過濾執行軌跡時，優先保留具有較多模型回合數（model turns）的軌跡能顯著提升訓練集（training set）品質，這凸顯了多輪互動細節對於培養代理式語言模型（agentic language models）連貫推理（reason coherently）與工具使用（tools）能力的重要性。第四，在最大規模的訓練運行中，單純重複頂尖任務來源（task sources）會迅速遭遇報酬遞減（diminishing returns），因此必須主動擴展資料來源以提升多樣性（diversity），此現象在訓練集規模（training set size）達到 100K 量級時尤為明顯。

除了 SFT 資料配方，本研究亦將視角延伸至強化學習（Reinforcement Learning, RL）階段，指出現有開源 RL 資料整理在可重現性（reproducibility）、易用性（usability）與擴展特性（scaling properties）上的結構性缺陷，並據此建構一套新整理的 RL 資料集。研究團隊進一步採用兩階段後訓練策略——先進行 SFT，再接續 RL——在 8B 規模模型上驗證其成效，證明 RL 資料整理並非 SFT 的簡單附屬，而是能額外提升平均準確率（average accuracy）的獨立優化維度。

#### 實驗數據解讀

在模型訓練層面，研究以 Qwen3-32B 為基礎模型（base model），使用經由上述管線篩選出的 100K 資料點（data points）進行微調（fine-tuning）。結果顯示，OT-Agent-32B 在七項代理式基準測試（agentic benchmarks）上達到 44.8% 的平均準確率，較現有最強開放資料模型 Nemotron-Terminal-32B（40.9%）提升 3.9 百分點（percentage points）。這項提升並非來自單一基準測試（benchmark）的極端優化，而是跨域整體進步的結果。

分項數據顯示，OT-Agent-32B 在 SWE-Bench Verified 達到 54.0%，顯著領先 Nemotron-Terminal-32B 的 41.9%；在 Terminal-Bench 2.0 達到 26.2%，同樣優於對手的 25.1%。更值得注意的是，該模型在開發過程中未使用的分布外（Out-of-Distribution, OOD）評估項目亦表現穩健：Aider-Polyglot（32.4%）、BFCL-Parity（85.9%）、MedAgentBench（47.8%）、GAIA-127（23.6%）與 FinanceAgent-Terminal（44.0%）均優於或逼近現有最強基線（baselines）。其中 BFCL-Parity 高達 85.9% 的準確率，暗示此資料管線在函數呼叫與工具參數推理方面具有顯著優勢。

從擴展特性（scaling properties）角度觀察，本研究在運算受控比較（compute-controlled comparisons）下發現，無論訓練集規模處於何種量級，OT-Agent 的訓練集均穩定優於其他開放資料集。這項結果具有高度科學價值，因為它排除了「僅靠資料量取勝」的質疑，證明其資料整理管線本身具備更高的樣本效率（sample efficiency）。此外，在 8B 規模實驗中，採用 SFT 加上 RL 的兩階段訓練進一步超越單一階段最佳 8B 模型與現有最強 <=8B 基線，顯示 RL 階段對代理式能力的補強作用在較小模型上同樣成立。

#### 與現有研究的比較

現有開源代理式資料集如 SWE-Smith、SERA、Nemotron-Terminal 與 OpenSWE，雖在個別領域推動了開放研究，但其共同局限在於「單點突破」思維：這些資料集通常僅針對單一基準測試（如 SWE-Bench 或 Terminal-Bench）進行優化，導致訓練出的模型難以跨域泛化。相對地，OT-Agent 明確將「跨多樣代理式任務的泛化」設為核心目標，其資料配方從一開始即考量多工平衡，這在開放文獻中屬於少見的系統性嘗試。

與工業界釋出的大型模型相比，DeepSeekV4 雖公開模型權重（model weights）並詳述架構（architecture）與訓練過程（training process），但其訓練資料（training data）僅以兩段文字高層次帶過，形成開放研究中的「資料黑箱」。OT-Agent 則透過 100 組以上的消融實驗，將資料整理的隱性知識轉化為可驗證、可複製的科學發現，大幅提升了代理式模型訓練的透明度。

在評估方法論上，本研究採用雙評估框架（harness）策略：同時以 Terminus-2 與各模型原始評估框架進行測試，並取兩者中的最大準確率作為最終結果。這種設計降低了因評估框架差異導致的偏差，使跨模型比較更具公信力。整體而言，在 Qwen3 或更早系列、參數量不超過 32B 的開放資料模型中，OT-Agent-32B 是目前平均表現最先進的（state-of-the-art）模型。

然而，本研究亦存在若干可進一步檢視的局限。首先，所有比較模型統一使用 Qwen3-32B 作為基礎模型，雖確保了實驗的內部效度，但也意味著資料配方是否適用於其他架構（如 Llama 或 Mistral 系列）仍有待驗證。其次，採取雙評估框架取最大值的報告方式，雖在論文中已說明是為了公平比較，但在某種程度上可能呈現較為樂觀的表現上限。最後，RL 資料整理相較於 SFT 部分僅屬初步探索，摘要中亦自承僅「簡要記錄」（briefly document）現有挑戰，顯示 RL 階段的資料配方尚未達到 SFT 階段的成熟深度。

#### 可重現性評估

本研究在可重現性層面樹立了開源代理式研究的新標竿。研究團隊於 openthoughts.ai 完整釋出訓練集（training sets）、資料整理管線原始碼、所有實驗數據以及訓練完成的模型權重。這種「全開放」策略允許後續研究者直接複製管線、驗證消融實驗結果，並在此基礎上進行改進，有效解決了代理式領域長期存在的「可取得但不可複製」困境。

在工程實作層面，SFT 階段採用 Llama-Factory 的分支版本，並擴充支援 ALST 長序列訓練（long-sequence training），以因應代理式任務中常見的長執行軌跡。RL 階段則基於 SkyRL 框架進行擴展，填補了開源社群在代理式 RL 基礎設施上的缺口。評估環節採用 Evalchemy 與 Harbor 等標準化評估平台，確保基準測試結果的可負擔性與可重現性。所有主要比較模型統一使用 Qwen3-32B 作為基礎模型，排除了因基礎模型世代差異所導致的混淆變因，使實驗結論更具內部效度。

#### 未來研究方向

儘管 OT-Agent 已建立堅實的資料配方基礎，仍有數個值得深入探索的方向。首先，基礎模型的世代效應尚未被充分解構：將現有資料改進移植至 Qwen-3.5 等新世代基礎模型，並系統性研究基礎模型與 SFT/RL 資料之間的交互作用，將是銜接未來研究的重要橋樑。其次，SFT 與 RL 的交會點目前仍缺乏公開文獻深入探討，多數現有研究僅聚焦單一階段；如何設計能同時服務兩階段的統一資料整理管線，或是探討 SFT 資料品質對 RL 訓練穩定性與最終收斂的影響，皆是高價值的後續課題。

第三，本研究指出工程實踐是代理式資料整理的核心挑戰之一，未來可針對長程規劃訓練的基礎設施、分散式執行軌跡收集系統，以及大規模模型回合數過濾演算法進行最佳化，以降低資料整理的運算門檻。第四，雖然 OT-Agent 已涵蓋七項基準測試並引入 OpenThoughts-TB-Lite 作為新評估工具，但代理式應用（agentic applications）的場景持續擴張，納入更多領域特定任務並檢驗資料配方的跨域遷移能力，將有助於建構真正通用的代理式語言模型。最後，探索不同訓練集規模與模型規模之間的聯合擴展律（joint scaling laws），特別是 8B 與 32B 在資料配方上的差異化需求，亦是連結理論與實務的關鍵下一步。

## 論文問答

**Q1：OpenThoughts-Agent 專案旨在解決的核心問題是什麼？**
A：OpenThoughts-Agent（OT-Agent）專案旨在填補目前公開文獻中對於如何整理具備廣泛能力的代理式模型訓練資料所知甚少的缺口。雖然代理式語言模型已大幅擴展人工智慧的應用範圍，但現有的開源努力大多僅針對單一基準測試，導致難以訓練出能夠在多樣化代理任務上泛化的模型。這個問題使得開放的人工智慧研究社群難以理解並改進最先進代理式模型的訓練方法，也阻礙了相關技術的民主化發展。

**Q2：為何現有的開源資料整理工作難以產出具備廣泛能力的智慧代理？**
A：現有的開源資料集如 SWE-Smith、SERA 與 Nemotron-Terminal 通常一次只聚焦於單一基準測試，例如 SWE-Bench 或 Terminal-Bench，這限制了他們的泛化能力。由於這些資料集針對狹隘的任務分布進行最佳化，因此無法提供如何讓模型在多樣代理式基準測試上都有良好表現的系統性洞見。結果是，開放社群缺乏一套全面的理解架構，來說明如何為跨領域的代理式效能整理與篩選訓練資料。

**Q3：為何公開釋出資料整理管線與訓練集對代理式模型研究如此重要？**
A：公開釋出這些資源能夠讓代理式模型訓練的研究民主化，使更廣泛的社群得以在其基礎上建構、驗證並改進相關工作。前沿模型的釋出往往對訓練資料細節著墨甚少，例如 DeepSeekV4 的論文雖有超過 50 頁的架構與訓練過程細節，卻僅用兩個段落描述訓練資料，這對開放研究形成了嚴重的資訊不對稱。透過將管線、資料集與模型完全開源，OT-Agent 得以支持可重現的科學研究，並加速邁向更具能力與通用性的智慧代理之發展。

**Q4：OpenThoughts-Agent 提出的核心方法是什麼？**
A：本專案提出了一個完全開源的六階段資料整理管線，專門設計用於代理式模型的監督式微調（SFT）。研究團隊針對每個階段執行了超過 100 組消融實驗，系統性地探討任務來源、教師模型選擇以及執行軌跡篩選等關鍵面向。基於這些實驗洞見，他們建構了一個包含 10 萬筆資料點的訓練集，強調多樣性與在多項代理式基準測試上的強大擴展特性，並以此微調基礎模型。

**Q5：從消融實驗中得出的關鍵創新或發現有哪些？**
A：消融實驗揭示了幾項違反直覺的發現：指令的選擇是資料管線中最重要的因素之一，而基準測試表現最強的模型未必是最適合的教師模型。此外，篩選訓練資料以保留具有更多模型回合數的執行軌跡，能夠提升最終訓練集的品質；而重複使用少數頂尖資料來源則會導致報酬遞減，因此必須擴展資料來源以增進多樣性。這些洞見挑戰了常見假設，並為建構代理式模型提供了可操作的資料配方。

**Q6：OT-Agent 的管線與先前工作相比，有哪些關鍵的設計選擇？**
A：與先前僅聚焦於 SFT 或強化學習、且通常針對單一基準測試的工作不同，OT-Agent 的管線專為跨多樣代理式任務的泛化而設計，並探究 SFT 與 RL 的交會點。團隊選擇保留具有較長模型互動的執行軌跡，並優先考量多樣性而非單純對高效能來源進行上採樣。此外，為了確保比較的一致性，他們選用 Qwen3-32B 作為基礎模型，同時也針對較小的 8B 模型驗證了兩階段 SFT 加 RL 的後訓練策略。

**Q7：OpenThinkerAgent-32B 在哪些基準測試上接受評估，關鍵結果為何？**
A：OpenThinkerAgent-32B 在七項代理式基準測試上接受評估，包括 SWE-Bench-Verified、Terminal-Bench 2.0、Aider-Polyglot、BFCL-Parity、MedAgentBench、GAIA-127 與 FinanceAgent-Terminal。經過微調的 Qwen3-32B 達到了 44.8% 的平均準確率，超越了現有最強開源資料代理式模型 Nemotron-Terminal-32B 的 40.9%。特別值得注意的是，該模型在 SWE-Bench-Verified 上取得 54.0%、在 Terminal-Bench 2.0 上取得 26.2%，顯示其在核心與分布外評估上都有強勁表現。

**Q8：擴展實驗揭示了 OT-Agent 訓練集的哪些特性？**
A：該訓練集展現出強大的擴展特性，這意味著隨著訓練集規模增加，效能能夠穩定提升，且在運算受控比較中，於每個規模都持續優於其他替代開源資料集。這顯示資料的品質與多樣性足以支持不同規模下的有效學習。這樣的擴展趨勢至關重要，因為它說明該資料集不僅受益於龐大的規模，其本質上對於訓練代理式能力也更為高效。

**Q9：關於教師模型與執行軌跡的具體消融洞見為何？**
A：消融實驗顯示，基準測試表現最強的模型並不一定是產生訓練資料的最佳教師模型，這暗示蒸餾品質取決於超越原始準確率的其他因素。此外，保留包含更多模型回合數的執行軌跡——代表更長的推理或互動鏈——能夠持續提升訓練集品質。這些發現凸顯了在整理代理式 SFT 資料時，流程層級的資料特性比單純結果層級的表現更為重要。

**Q10：OT-Agent 的資料管線可以應用在哪些實務場景？**
A：此管線可應用於開發通用型程式編寫代理、自動化軟體工程工具、財務分析助理，以及能在終端機與圖形介面環境中運作的通用電腦使用代理。由於訓練資料涵蓋了從程式碼編輯、網頁瀏覽到金融分析等多元任務，實務工作者可以依循相同的整理原則來適應特定領域。完全開源的釋出讓新創公司與研究實驗室無需依賴專有資料或不透明的訓練流程，即可建構專門的代理式模型。

**Q11：開發者在使用 OT-Agent 資料集時，應考慮哪些產品層面的因素？**
A：開發者應留意此資料集主要針對監督式微調與強化學習的後訓練進行最佳化，因此需要足夠的運算資源來支援長序列訓練。由於管線強調多樣性與擴展特性，若產品需要狹窄但深厚的專業能力，則可能需要在通用資料混合之外，額外補充特定領域的執行軌跡。此外，基礎模型的選擇也會影響最終成效；雖然 OT-Agent 使用 Qwen3-32B，但將資料改進移植到 Qwen-3.5 等較新的基礎模型上，仍是達到巔峰表現的重要方向。

**Q12：這項工作可能對更廣泛的開放人工智慧研究領域帶來什麼影響？**
A：透過提供完全開放的資料管線、實驗紀錄與模型，OT-Agent 為代理式模型開發的透明度樹立了新標竿，直接回應了目前公開資訊稀缺的現況。它將研究焦點從追逐單一基準測試分數，轉向理解跨多樣代理式任務的泛化能力，而這對於建構穩健的實際應用代理至關重要。這種開放性讓全球研究社群能夠進行可重現的研究、迭代資料配方，並共同推進代理式人工智慧的最新技術。

**Q13：論文承認了哪些當前 OT-Agent 研究的限制？**
A：論文指出，本專案聚焦於 SFT 與 RL 的後訓練資料，但並未窮盡探索基礎模型選擇與資料整理策略之間的所有可能互動。此外，雖然管線能泛化至七項基準測試，但仍可能未涵蓋所有可能的代理式領域或真實世界部署環境。作者也承認，為了維持比較的一致性，他們選用 Qwen3 而非更新的 Qwen-3.5 作為基礎模型，這可能限制了當前實驗所能達到的絕對效能上限。

**Q14：依賴特定資料整理選擇暗示了哪些潛在的失敗案例或風險？**
A：研究發現重複使用頂尖資料來源會導致報酬遞減，這暗示過度依賴狹隘的高效能任務集可能損害泛化能力，並導致次佳的擴展效果。若實務工作者忽視執行軌跡長度或指令多樣性的重要性，可能會訓練出僅能記憶模式、卻無法應對複雜多步驟互動的代理。此外，由於最佳教師模型未必是基準測試表現最強的模型，若未經消融實驗就盲目使用前沿模型進行知識蒸餾，可能會產生效率不彰或品質較低的訓練資料。

**Q15：論文建議哪些未來研究方向以延伸此項工作？**
A：作者認為將資料改進移植到 Qwen-3.5 等較新的基礎模型，並深入研究基礎模型能力與 SFT／RL 資料之間的互動，是接下來的關鍵步驟。他們也建議進一步探究 SFT 與 RL 資料整理的交會點，並指出現有開源 RL 工作在可重現性、易用性與擴展性方面仍面臨挑戰。最後，擴充基準測試套件並開發更多元的任務來源，對於推動代理式模型朝向更廣泛的真實世界應用與穩健性而言，將是不可或缺的方向。

## 實務應用指南

### 適用場景

1. **企業級軟體開發自動化**：自動化 GitHub issue 修復、程式碼審查與重構，適用於 SWE-Bench Verified 類型的工程任務，可作為 Claude Code 或 Codex 的開源替代方案。
2. **雲端與終端機維運代理**：透過自然語言指令執行伺服器維運、日誌分析與環境設定，對應 Terminal-Bench 2.0 的 IT 操作場景。
3. **跨領域專業顧問系統**：整合金融（FinanceAgent-Terminal）、醫療（MedAgentBench）與多語言程式設計（Aider-Polyglot）的複合式代理服務。
4. **自動化資料分析與決策助理**：處理 GAIA-127 類型的多步驟資訊檢索、數據驗證與報告生成，適用於研究或商業情報單位。
5. **工具呼叫與 API 編排平台**：建構能連貫使用多種外部工具、執行長程規劃的通用代理式應用。

### 實作前置條件

- **資料**：需準備基礎模型權重（如 Qwen3-32B）、多樣化的任務來源（涵蓋軟體工程、終端機操作、金融等領域），以及可產生執行軌跡的教師模型與沙箱環境。
- **運算**：微調 32B 規模模型需多張高記憶體 GPU（如 A100/H100），並支援長序列訓練（ALST）；若進行強化學習後訓練，需額外配置推理與獎勵運算資源。
- **技能**：團隊需具備監督式微調（SFT）與資料整理管線建置經驗、基準測試評估框架（Harness）的部署能力，以及特定領域的任務設計知識。

### 實作步驟建議

1. **任務來源規劃與多樣性設計**：避免僅聚焦單一基準測試，應同時收斂軟體工程、終端機操作、工具呼叫等異質任務來源。根據論文發現，重複頂尖單一來源會導致報酬遞減，因此需主動擴展資料多樣性。
2. **教師模型選型與執行軌跡生成**：挑選教師模型時，不應直接採用基準測試表現最強的模型，而需驗證其產生的執行軌跡品質。透過沙箱環境生成帶有多回合模型互動（model turns）的軌跡。
3. **資料篩選與指令優化**：優先保留模型回合數較多的執行軌跡，並將指令設計視為管線中最關鍵的環節。進行運算受控比較，驗證不同篩選策略下的擴展特性。
4. **監督式微調（SFT）**：使用整理後的資料集（如 100K 規模）對基礎模型進行微調。建議採用 Llama-Factory 等成熟框架，並擴充支援長序列訓練。
5. **擴展特性驗證**：在不同訓練集規模下驗證模型表現，確保資料具備良好的擴展特性，而非僅靠資料量取勝。
6. **選擇性強化學習（RL）後訓練**：若資源允許，可採用 SFT + RL 兩階段訓練。論文顯示此方式在 8B 規模上能進一步提升跨基準測試的平均準確率。
7. **多框架評估與部署**：使用 Terminus-2 及原始評估框架進行交叉驗證，確保模型在核心與分布外（OOD）任務上的泛化能力。

### 潛在風險與注意事項

- **單一基準過擬合**：僅針對單一基準測試（如 SWE-Bench）整理資料，容易導致模型在其他代理式任務上泛化不足。應維持跨領域任務來源的比例平衡。
- **教師模型迷思**：最強的教師模型未必能產生最適合訓練的資料。建議透過小型消融實驗驗證教師模型的實際蒸餾效果，而非僅看其原始準確率。
- **資料重複的報酬遞減**：在最大規模訓練中，重複頂尖資料來源的效益會快速遞減。需持續引入新任務來源以維持邊際效益。
- **評估框架不一致**：不同評估框架（如 SWE-agent 與 Terminus-2）可能產生顯著差異。建議同時採用多個框架驗證，並標準化評估環境（如 Evalchemy）。
- **長序列訓練穩定性**：代理式任務的執行軌跡通常較長，長序列訓練可能帶來記憶體與收斂挑戰。需確保訓練框架支援 ALST 等長序列優化技術。

### 與其他技術的整合建議

- **CI/CD 與容器化平台**：將代理式模型整合至 GitHub Actions 或 GitLab CI，並透過 Docker 沙箱執行終端機指令，確保安全性與可重現性。
- **現有 LLM 服務架構**：透過 vLLM 或 TGI 部署微調後的模型，並結合 OpenAI-compatible API 閘道，無縫銜接既有應用程式。
- **檢索增強生成（RAG）**：針對金融、醫療等專業領域，搭配向量資料庫與 RAG 管線，彌補訓練資料中專業知識的時效性缺口。
- **可觀測性與追蹤系統**：整合 LangSmith、Langfuse 或自建追蹤系統，記錄模型回合數與執行軌跡，便於後續資料整理管線的迭代優化。
- **多模態與程式碼工具鏈**：結合程式碼編輯器外掛（如 VS Code extension）與瀏覽器自動化工具（如 Playwright），擴展代理式應用的操作邊界。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從「代理式應用的基本概念」與「為何資料多樣性比資料量更重要」開始理解。可先瀏覽論文的圖表與表一，掌握 OT-Agent 在七個基準測試上的整體表現，再逐步了解資料整理管線的六個階段。
- **AI 工程師**：請重點研讀第三節的 100 多組消融實驗，特別是「指令設計的影響力」「教師模型選型」與「執行軌跡篩選」的具體做法。論文公開的資料管線、Llama-Factory 訓練設定與 SkyRL 框架擴充細節，可直接作為復現與部署的技術參考。
- **研究人員**：建議深入分析資料整理管線中的控制變因實驗設計，以及 SFT 與 RL 兩階段訓練的交互作用。論文對「擴展特性」與「跨基準測試泛化」的系統性研究，為後續基礎模型（如 Qwen-3.5）與資料配方之間的關係提供了重要假設與驗證方向。
- **產品經理**：請聚焦表一的商業意涵：OT-Agent 在 SWE-Bench Verified 與 Terminal-Bench 2.0 等關鍵基準測試上超越現有開源方案，且具備良好的分布外泛化能力。評估時需留意「運算受控比較」所隱含的成本效益，以及多評估框架驗證對產品上線前品質確保的重要性。
