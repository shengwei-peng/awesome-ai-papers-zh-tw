## 摘要翻譯

大型語言模型 (LLM) 的後訓練透過強化學習 (RL) 與同策略蒸餾 (OPD) 生成自我生成 rollout，然而一旦策略進步，這些經驗常被視為過時。歷史 rollout 可與後續策略保持相容，同時保留策略已無法可靠表達的行為。然而，這些 rollout 也可能包含不應被模仿的錯誤、放棄的嘗試與冗餘動作，這促使我們需要更細緻的選擇性監督。我們提出 ROSS（透過選擇性監督從自我生成 Rollout 重新學習），保留完整的歷史軌跡作為上下文，僅對選定的模型生成的延續計算訓練損失。在領域特定強化學習、多教師同策略蒸餾與智能體強化學習中，ROSS 持續改善上游檢查點，並在數學、程式碼生成、指令遵循與軟體工程上超越基準方法。在 Qwen3.6-35B-A3B 上，ROSS 將六基準 MOPD 平均從 58.40% 提升至 62.20%，並將 SWE-bench Verified 從 64.20% 提升至 68.40%。這些結果顯示，自我 rollout 訓練會留下可重複使用的行為經驗，無需額外的策略 rollout，即可透過離線監督式微調 (SFT) 帶來進一步的提升。

### 核心貢獻（3～5點）
- **重新審視歷史 rollout 的價值**：指出自我生成的 rollout 並非策略更新後即應丟棄的過時資料，其中仍蘊含與後續策略相容且值得保留的行為經驗。
- **提出 ROSS 框架**：透過「保留完整歷史軌跡作為上下文、僅對選定延續施加訓練損失」的選擇性監督機制，避免模型模仿錯誤、放棄的嘗試與冗餘動作。
- **跨場景的泛用性驗證**：在領域特定強化學習、多教師同策略蒸餾與智能體強化學習三類訓練場景中均持續改善上游檢查點，涵蓋數學、程式碼生成、指令遵循與軟體工程四大領域。
- **具體的效能提升**：於 Qwen3.6-35B-A3B 上將六基準 MOPD 平均由 58.40% 提升至 62.20%，SWE-bench Verified 由 64.20% 提升至 68.40%。
- **離線 SFT 即可獲益**：證明自我 rollout 訓練所遺留的可重用行為經驗，無需額外策略 rollout，僅透過離線監督式微調即可帶來進一步的模型增益。

### 適合對象
從事大型語言模型後訓練、強化學習、知識蒸餾與智能體系統研究的學者與工程師；尤其適合關注如何有效利用歷史訓練資料、提升樣本效率，以及在離線環境下持續改進模型性能的實務研究者與技術決策者。

## 深度分析

#### 方法論解析

ROSS（Relearning from Self-Generated Rollouts through Selective Supervision，透過選擇性監督從自我生成 Rollout 重新學習）的核心設計理念在於解決一個被忽略的問題：LLM 後訓練（post-training）過程中累積的大量自我生成 rollout 經驗往往被視為「過時」而直接丟棄，但這些歷史軌跡（historical trajectory）實際上仍蘊含可被後續檢查點（checkpoint）利用的行為訊號。

**雙層選擇機制的設計邏輯**

ROSS 的方法論建立在兩個互補的維度上：

1. **相容性（Compatibility）**：衡量歷史行為與當前策略（policy）的對齊程度。論文以回應層級的負對數似然（NLL, Negative Log-Likelihood）作為代理指標——歷史 rollout 的 NLL 顯著低於外部教師（如 GLM-5.2）的軌跡，接近當前策略的 rollout，說明歷史行為在分布上仍屬「近策略」（near-on-policy）範疇。

2. **互補性（Complementarity）**：衡量歷史行為是否提供當前策略無法可靠產生的行為覆蓋（behavioral coverage）。論文透過 pass@k 分析揭示一個關鍵現象：對於歷史上曾成功解決的 98 個困難問題，當前策略的 pass@1 僅 37.7%，但 pass@32 達到 99.0%。這意味著相關行為仍存在於策略的行為支撐集（behavioral support）中，只是未被穩定地表達出來——這正是「未鞏固」（under-consolidated）的狀態。

**片段級選擇性監督的實作**

在軌跡層級篩選之後，ROSS 更進一步在片段層級（segment level）進行選擇性監督。其關鍵設計是：

- **保留完整軌跡作為上下文（context）**：模型在訓練時仍能看見整個推理過程，包括錯誤嘗試、冗餘步驟等。
- **僅對選定的模型生成延續（model-generated continuations）施加損失（loss）**：避免模型模仿已被捨棄的錯誤行為或不必要的繞路。

這種「全上下文 + 局部監督」的設計區別於傳統的軌跡級監督（trajectory-level supervision），後者會對整條軌跡施加均勻的損失，容易強化錯誤行為。ROSS 的設計哲學更接近「從自身經驗中精選值得學習的部分」，而非「全盤模仿」。

**作為離線 SFT 階段的定位**

ROSS 並非替代 RL 或 OPD，而是作為這些訓練流程之後的一個額外離線監督式微調（offline SFT, Supervised Fine-Tuning）階段。這一定位的優勢在於：

- 不需要額外的策略 rollout（policy rollouts），節省計算成本。
- 可直接利用訓練過程中已產生的 rollout 資料。
- 適用於三種不同的後訓練場景：領域特定強化學習（domain-specific RL）、多教師同策略蒸餾（MOPD, Multi-teacher On-Policy Distillation）、以及智能體強化學習（agentic RL）。

#### 實驗數據解讀

**核心結果的意義**

論文報告的兩個最突出的數據點值得深入解讀：

1. **Qwen3.6-35B-A3B 在六基準 MOPD 平均上從 58.40% 提升至 62.20%**：3.8 個百分點的絕對提升在 LLM 基準測試中屬於顯著進步，尤其考慮到這是在 MOPD 訓練已經完成後的「二次提升」。這表明 MOPD 過程中產生的歷史 rollout 含有未被充分利用的訓練訊號。

2. **SWE-bench Verified 從 64.20% 提升至 68.40%**：4.2 個百分點的提升在軟體工程（software engineering）這類長視野（long-horizon）智能體任務上尤為重要。SWE-bench Verified 衡量的是模型解決真實 GitHub issue 的能力，涉及多步驟推理、工具使用與程式碼生成——ROSS 在此場景的有效性說明選擇性監督能幫助模型鞏固在長程任務中發現的成功策略。

**跨領域一致性**

ROSS 在數學（mathematics）、程式碼生成（code generation）、指令遵循（instruction following）、以及軟體工程四個領域均顯示提升，這種跨領域一致性是方法泛化性的有力證據。值得注意的是，這四個領域對模型的行為要求差異極大：

- 數學任務強調精確推理鏈。
- 程式碼生成要求語法正確性與邏輯完整性。
- 指令遵循考驗格式約束與語義理解。
- 軟體工程需要長程規劃與環境互動。

ROSS 在所有這些場景中均有效，暗示其選擇性監督機制捕捉的是某種跨任務通用的「行為鞏固」原理，而非特定領域的啟發式。

**pass@k 分析的深層意涵**

圖 3(c) 的 pass@k 曲線揭示了 ROSS 之所以有效的根本原因：當前策略的 pass@1 與 pass@32 之間存在巨大鴻溝（37.7% vs 99.0%），這意味著策略「知道」如何解決問題，但無法穩定地「做到」。透過選擇性監督歷史 rollout 中的成功片段，ROSS 實際上是在幫助模型將「偶爾成功」轉化為「穩定成功」——這是一種行為層面的固化（consolidation），而非知識層面的擴展。

#### 與現有研究的比較

**與靜態 SFT 及策展語料的區別**

傳統的 SFT 通常依賴靜態語料（static SFT）或人工策展的資料集（curated corpus），這些資料與當前策略的分布可能存在顯著偏差。ROSS 的歷史 rollout 來自策略自身的演化軌跡，因此天然具有高相容性。圖 2 的分類框架清楚區分了四種歷史經驗的價值類型：採用（Adopt）、重新對齊（Realign）、捨棄（Discard）、冗餘（Redundant），而 ROSS 的雙層選擇機制正是為了自動識別這四類。

**與外部教師蒸餾的比較**

外部模型軌跡（external model trajectory）雖然可能包含高品質的示範，但其 NLL 遠高於歷史 rollout（圖 3a），意味著直接模仿會迫使模型跨越較大的分布差距。ROSS 的歷史 rollout 則處於「近策略」區域，學習難度更低。這與同策略蒸餾（on-policy distillation）的精神一致，但 ROSS 進一步利用了「跨時間點」的歷史，而非僅限於當前策略的 rollout。

**與現有 OPD 方法的關係**

MOPD 等 OPD 方法已經利用了學生軌跡（student trajectories）進行教師監督（teacher supervision），但 ROSS 展示了一個未被充分探索的方向：即使在 OPD 完成後，歷史軌跡中仍有可提取的訓練訊號。這暗示 OPD 的「一次性」使用可能低估了 rollout 資料的長期價值。

**潛在限制**

儘管結果令人印象深刻，該方法仍存在若干限制：

1. **對歷史 rollout 品質的依賴**：如果訓練早期的策略產生大量低品質 rollout，ROSS 的可用素材將受限。
2. **選擇性監督的標準**：論文未詳細說明片段選擇的具體準則，這可能影響方法的透明度與可調節性。
3. **計算成本**：雖然不需要新的策略 rollout，但儲存與處理大量歷史軌跡仍需額外的記憶體與運算資源。
4. **泛化至極長視野任務**：雖然 SWE-bench 結果正面，但對於更長程的智能體任務，歷史軌跡的上下文長度可能成為瓶頸。

#### 可重現性評估

根據提供的論文內容，可重現性資訊有限但可做以下評估：

**模型與權重**：論文使用了 Qwen3.6-35B-A3B 作為主要實驗模型，並提及 GLM-5.2 作為外部教師對照。這些模型若為公開模型，則實驗可重現；但 Qwen3.6-35B-A3B 的具體版本與可獲得性需進一步確認。

**資料集**：實驗涵蓋六個 MOPD 基準以及 SWE-bench Verified，這些均為公開基準，評估本身可重現。然而，訓練過程中產生的歷史 rollout 資料是訓練流程的副產物，其產生依賴於具體的 RL/OPD 訓練配置，這部分的可重現性受限於訓練管線的公開程度。

**程式碼**：論文中未明確提及程式碼開源計畫。作為一個涉及雙層選擇機制的方法論論文，程式碼的開源對於社群驗證與後續研究至關重要。建議作者釋出選擇性監督的實作細節，包括片段選擇的具體演算法。

**超參數與訓練配置**：論文中提及了採樣預算 k=32 等設定，但完整的超參數清單（學習率、批次大小、選擇性監督的片段長度閾值等）需在附錄或程式碼中確認。

**整體可重現性評級**：中等。主要的實驗結果（基準提升數字）可透過公開模型與基準重現，但方法的精確實作細節需要程式碼與訓練配置的公開。

#### 未來研究方向

**1. 片段選擇準則的形式化**

當前論文的片段級選擇性監督機制雖然有效，但選擇準則的理論基礎尚待加強。未來研究可探索：

- 基於信心度（confidence）或熵（entropy）的自動片段評分機制。
- 引入對比學習（contrastive learning）來區分「值得模仿」與「應避免」的片段。
- 結合過程獎勵模型（process reward model）進行更細粒度的品質評估。

**2. 跨訓練階段的經驗累積**

ROSS 目前作為單一離線 SFT 階段，未來可探索：

- 迭代式 ROSS：在多輪訓練中反覆應用選擇性監督，形成「經驗蒸餾」的良性循環。
- 跨任務經驗遷移：將一個任務的歷史 rollout 應用於相關但不同的任務。
- 經驗回放緩衝區（experience replay buffer）的設計：類比深度強化學習中的 prioritized experience replay。

**3. 與其他訓練範式的整合**

- **與 RLHF 的結合**：在人類回饋強化學習（RLHF, Reinforcement Learning from Human Feedback）框架中嵌入 ROSS，利用人類偏好標註來指導片段選擇。
- **與自我對戰（self-play）的整合**：在對抗性訓練中，ROSS 可用於鞏固自我對戰中發現的成功策略。
- **與憲法 AI（Constitutional AI）的結合**：以原則為基礎的片段篩選。

**4. 理論分析**

- 為什麼「近策略」的歷史 rollout 比「分布外語料」（off-distribution corpus）更有效？需要更嚴格的收斂性分析。
- 片段級選擇性監督與全軌跡監督之間的偏差-方差（bias-variance）權衡。
- ROSS 與課程學習（curriculum learning）之間的理論聯繫——歷史 rollout 本質上構成了一個由易到難的隱式課程。

**5. 應用擴展**

- **多模態模型**：將 ROSS 擴展至視覺語言模型的 rollout 經驗。
- **長上下文模型**：探索在百萬級 token 上下文場景下的選擇性監督機制。
- **即時學習系統**：在持續學習（continual learning）設定中，ROSS 可作為防止災難性遺忘（catastrophic forgetting）的機制。

**6. 效率優化**

- 歷史 rollout 的壓縮儲存：透過蒸餾或量化減少記憶體佔用。
- 選擇性監督的硬體加速：設計專門的 GPU kernel 來高效處理「全上下文 + 局部損失」的訓練模式。
- 主動式歷史 rollout 篩選：在訓練過程中即時決定哪些 rollout 值得保留，降低儲存壓力。

ROSS 的核心洞見——「自我 rollout 訓練留下的不僅是更強的策略，還有可重複利用的行為經驗」——為 LLM 後訓練開啟了一個新維度。隨著訓練計算投入的不斷增長，如何有效利用訓練過程中累積的經驗將成為提升訓練效率的關鍵課題，而 ROSS 正是朝此方向邁出的重要一步。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文要解決的核心問題是大型語言模型後訓練過程中，歷史自我生成的 rollout 經驗被視為「過時」而遭到丟棄的浪費問題。隨著策略在訓練中不斷演進，先前檢查點所產生的 rollout 雖然仍可能與當前策略相容，卻往往被當作無用資料丟棄。論文的關鍵洞察在於：歷史 rollout 中保留了當前策略無法穩定表達的行為，這些行為構成了寶貴的互補訓練訊號，因此如何有效再利用這些「被遺忘的經驗」成為一個重要且未被充分探討的研究問題。

**Q2：為什麼現有的後訓練方法無法有效利用這些歷史 rollout？**
A：現有方法主要存在兩個層次的不足。第一，整體層次上，許多方法將歷史 rollout 視為完全過時而直接丟棄，未意識到其中仍含有與當前策略相容且互補的行為。第二，片段層次上，即使保留整條軌跡進行監督式學習，也可能因為軌跡中夾雜錯誤嘗試、冗餘步驟或不必要的繞路而引入雜訊，導致模型模仿到不良行為。單純以「最終結果成功」作為篩選標準並不足以保證軌跡中每個中間步驟都值得學習，因此需要更細粒度的選擇性監督機制。

**Q3：為什麼這個問題在 LLM 訓練領域特別重要？**
A：這個問題的重要性在於它直接影響訓練效率與資料利用率。現代 LLM 的後訓練（如 RL 和 OPD）會產生大量 rollout 經驗，但這些經驗通常只被使用一次後即被丟棄，造成巨大的計算與資料浪費。更關鍵的是，論文的分析顯示歷史成功行為在當前策略下的 pass@1 僅有 37.7%，但 pass@32 可達 99.0%，代表這些行為確實存在於策略的行為支援中，只是尚未被穩定鞏固。因此，若能有效重用這些經驗，將能在不產生額外 rollout 的情況下，透過離線 SFT 進一步提升模型性能，具有極高的實務價值。

**Q4：ROSS 方法的核心機制是什麼？**
A：ROSS 的核心機制是「保留完整歷史軌跡作為上下文，但僅對選定的模型生成延續片段施加監督損失」。具體而言，方法分為兩個層次的選擇：首先在 rollout 層次識別哪些歷史軌跡仍具有相容性與互補性，其次在片段層次判斷軌跡中的哪些部分值得學習。這種設計讓當前策略能在完整推理脈絡下鞏固先前發現的有用行為，而不會盲目模仿整條軌跡或強化錯誤步驟，從而實現更精準的經驗再利用。

**Q5：ROSS 的關鍵創新點相較於既有方法有何不同？**
A：ROSS 的關鍵創新在於它同時解決了「選擇哪些 rollout」與「選擇 rollout 中的哪些片段」這兩個層次的問題，並以「相容性」與「互補性」兩個互補維度作為篩選依據。相較於傳統靜態 SFT 使用策展語料或外部模型軌跡，ROSS 充分利用了自我 rollout 訓練所留下的「近策略」經驗；相較於簡單的成功軌跡模仿，ROSS 透過選擇性片段監督避免了對錯誤與冗餘步驟的學習。這種雙層選擇機制讓 ROSS 能夠在保留完整上下文的前提下，進行更精細的行為鞏固。

**Q6：ROSS 在設計上做了哪些重要的取捨？**
A：ROSS 在設計上做了幾項重要取捨。第一，它選擇保留完整軌跡作為上下文而非僅使用選定片段，以維持推理的連貫性與脈絡資訊。第二，它採用離線 SFT 形式而非線上 RL，這避免了額外的策略 rollout 開銷，使訓練更為高效。第三，雖然論文中未完整說明選擇標準的細節，但從概念上來看，方法需要在「保留更多有用訊號」與「避免引入雜訊」之間取得平衡，這也是為何需要選擇性而非全面監督的原因。

**Q7：ROSS 在哪些基準測試上進行了驗證？**
A：ROSS 在多個領域的基準測試上進行了廣泛驗證，涵蓋數學（如 MOPD 六基準平均）、程式碼生成、指令遵循，以及軟體工程（如 SWE-bench Verified）。具體而言，實驗橫跨三種訓練場景：領域特定強化學習、多教師同策略蒸餾（MOPD），以及智能體強化學習。這種跨領域、跨訓練範式的評估設計，使得 ROSS 的有效性結論具有更強的泛化性與可信度。

**Q8：ROSS 的關鍵實驗結果為何？**
A：ROSS 的關鍵實驗結果顯示其在多個基準上都帶來顯著且一致的提升。在 Qwen3.6-35B-A3B 模型上，六基準 MOPD 平均從 58.40% 提升至 62.20%，SWE-bench Verified 從 64.20% 提升至 68.40%。更重要的是，這些提升是在不產生額外策略 rollout 的情況下，僅透過離線 SFT 對既有歷史經驗進行選擇性監督而達成的。這代表自我 rollout 訓練不僅產生了更強的策略，還留下了可重複利用的行為經驗，後續檢查點能透過 ROSS 進一步鞏固這些行為。

**Q9：論文中進行了哪些分析性實驗來支撐方法設計？**
A：論文中進行了兩項重要的分析性實驗來支撐方法設計。第一是相容性分析（Figure 3a），透過測量歷史 rollout 在當前策略下的 token-level NLL，證實歷史 rollout 的 NLL 接近當前策略 rollout，且遠低於外部教師（如 GLM-5.2）的軌跡，說明歷史行為仍與當前策略自然相容。第二是互補性分析（Figure 3b、3c），顯示歷史成功行為在當前策略下的平均 pass@1 僅 37.7%，但 pass@32 可達 99.0%，證明這些行為確實存在於策略支援中，只是尚未被穩定表達，為選擇性監督提供了明確的動機。

**Q10：ROSS 在實際應用場景中適合部署於哪些情境？**
A：ROSS 特別適合部署於需要大量計算資源進行 rollout 採樣的訓練流程中，例如大型模型的強化學習後訓練階段。在這些場景中，每次 rollout 都涉及昂貴的推理成本，而 ROSS 能讓既有 rollout 經驗「二次利用」，在不增加 rollout 開銷的前提下提升模型性能。此外，對於多教師蒸餾場景，ROSS 可作為一個額外的離線 SFT 階段，進一步鞏固從不同教師學到的行為；在智能體 RL 場景中，長程任務的歷史軌跡往往包含豐富的恢復行為與替代策略，ROSS 的選擇性監督能有效提取這些有價值片段。

**Q11：將 ROSS 整合到實際產品訓練流程中需要考慮哪些工程因素？**
A：將 ROSS 整合到實際產品訓練流程中需考慮多項工程因素。首先，需要建立完整的 rollout 儲存與索引機制，以便在後續 SFT 階段能高效檢索歷史軌跡。其次，選擇性監督的標準需要明確且可計算，這可能涉及額外的評估模型或啟發式規則，增加了流程複雜度。再者，訓練時需要同時處理完整上下文與選定片段的損失遮罩，對資料處理管線提出了更高要求。最後，由於 ROSS 是作為上游訓練的「附加」階段，需要評估其在不同模型規模與訓練階段上的成本效益比。

**Q12：ROSS 對 LLM 訓練領域可能產生哪些長遠影響？**
A：ROSS 對 LLM 訓練領域的長遠影響可能體現在幾個方面。第一，它挑戰了「歷史經驗即過時」的傳統觀念，開啟了「經驗重用」作為訓練範式的研究方向，可能促使更多工作探索如何系統性地利用訓練過程中產生的中間產物。第二，它示範了「近策略」資料相較於「分布外語料」的優勢，可能影響未來資料策劃策略的設計。第三，隨著訓練計算成本持續攀升，ROSS 所代表的「不產生額外 rollout 即可提升性能」的路徑，對於降低 LLM 訓練的整體碳足跡與經濟成本具有積極意義。

**Q13：ROSS 方法存在哪些已知的限制？**
A：ROSS 方法存在幾項已知限制。第一，論文中對於「選擇性監督」的具體標準與演算法細節描述較為有限，讀者難以直接重現其片段選擇機制。第二，方法的有效性高度依賴於歷史 rollout 的品質與多樣性，若訓練過程中 rollout 本身存在系統性偏差，選擇性監督可能無法完全糾正這些偏差。第三，雖然 ROSS 在多個基準上表現優異，但其在更大規模模型或不同訓練範式（如純 SFT 後的模型）上的泛化性仍待驗證。第四，離線 SFT 階段可能引入與線上 RL 不同的偏差，需要謹慎評估其對整體訓練動態的影響。

**Q14：ROSS 在哪些情況下可能會失敗或表現不佳？**
A：ROSS 在幾種情況下可能表現不佳。第一，當歷史 rollout 與當前策略的相容性過低時（例如經過多輪重大策略更新後），選擇性監督的訊號可能變得不可靠。第二，當歷史軌跡中「值得學習的片段」比例極低時（例如任務極具挑戰性且錯誤率很高），保留完整上下文但僅監督少數片段的設計可能無法提供足夠的訓練訊號。第三，對於需要精確動作序列的任務（如某些程式碼生成場景），片段級的選擇性監督可能破壞動作間的依賴關係，導致學習效果下降。第四，若選擇標準設計不當，可能誤將「已掌握」的冗餘片段標記為值得學習，造成訓練效率低落。

**Q15：基於 ROSS 的研究，未來有哪些值得探索的方向？**
A：基於 ROSS 的研究，未來有幾個值得探索的方向。第一，可以發展更精細的片段選擇機制，例如基於重要性採樣、資訊理論度量或學習到的價值模型來自動識別值得學習的片段。第二，可以將 ROSS 的「經驗重用」理念擴展到跨任務、跨模型的設定，探索不同訓練 run 間的經驗轉移。第三，可以研究 ROSS 與其他訓練範式（如 RLHF、DPO）的結合方式，探索其在整體後訓練流程中的最佳定位。第四，隨著 agentic 任務日益重要，可以進一步研究 ROSS 在長程、多步驟決策場景中的應用，特別是如何處理工具呼叫與環境回饋的選擇性監督。第五，從理論角度，可以分析「近策略經驗重用」與傳統 off-policy 修正之間的關係，建立更嚴格的理論基礎。

## 實務應用指南

### 適用場景

1. **領域專屬 LLM 的後訓練強化**：在已完成領域 RL（如數學、程式碼、指令遵循）的檢查點上，導入 ROSS 作為額外的離線 SFT 階段，鞏固先前 rollout 中被低估的成功行為。例如將 Qwen3.6-35B-A3B 在 MOPD 六基準平均從 58.40% 提升至 62.20%。

2. **多教師同策略蒸餾 (MOPD) 的二次精煉**：當學生模型已從多位教師（同家族、跨家族、長思維鏈教師）學習後，可再用 ROSS 對學生自身歷史軌跡做選擇性監督，避免被「已掌握前綴」或「重複已解案例」拖累。

3. **長時程智能體任務的經驗回收**：在 SWE-bench Verified 等軟體工程基準上，agentic RL 過程中累積大量工具呼叫軌跡，ROSS 可挑出「罕見有效工具呼叫」與「新穎正確分支」進行監督，將分數從 64.20% 推升至 68.40%。

4. **算力受限團隊的「免費」性能提升**：在不增加新策略 rollout 的前提下，把訓練過程中已生成但被丟棄的歷史 rollout 重新利用，特別適合無法負擔大規模線上 RL 的中小型團隊。

5. **持續學習與版本迭代**：當模型從 v1 升級到 v2 時，可將 v1 訓練留下的 rollout 倉庫作為 v2 的補充監督來源，避免每次迭代都從頭採樣。

### 實作前置條件

**資料面**
- 需保存完整訓練過程的 rollout 倉庫：每筆軌跡應包含 prompt、模型生成的完整 token 序列、中間狀態、獎勵/成功標記、對應的策略版本（checkpoint ID）。
- 必須能區分「成功 rollout」與「失敗 rollout」，並具備問題難度標籤或教師來源標籤（MOPD 場景）。
- 建議至少保留數萬至數十萬筆軌跡，且覆蓋多個訓練階段，以利相容性與互補性分析。

**算力面**
- 一張以上能跑目標模型（如 Qwen3.6-35B-A3B 等 MoE 或 dense LLM）推論與微調的 GPU（如 H100 / A100 叢集）。
- 需具備標準 SFT 訓練框架（Megatron-LM、DeepSpeed、Transformers + FSDP 等）。
- 額外的離線評估算力，用於計算 token-level NLL 與 pass@k 來做相容性/互補性診斷。

**技能面**
- 熟悉 LLM 後訓練流程（RLHF、RLAIF、OPD、SFT）。
- 具備軌跡資料處理經驗：能切割 segment、計算 per-token loss mask、處理長上下文。
- 理解 NLL、pass@k、KL 散度等分布距離指標，並能用於診斷歷史 rollout 的價值。

### 實作步驟建議

1. **建立 rollout 倉庫與元資料**：在既有 RL/OPD 訓練管線中，於每個 checkpoint 落地時將所有採樣軌跡序列化保存，記錄策略版本、獎勵、問題 ID、教師來源等欄位。

2. **執行相容性分析（Sec. 2.1）**：以當前策略對三類來源（歷史 rollout、當前策略 rollout、外部教師軌跡）計算 token-level NLL，確認歷史 rollout 的 NLL 接近當前策略且顯著低於外部教師，作為「可採用」的門檻。

3. **執行互補性分析（Sec. 2.2）**：對歷史上解過的困難問題，用當前策略重採 k 次（如 k=32），計算 pass@1 與 pass@k。若 pass@1 低但 pass@k 高，代表行為存在但未鞏固，屬於高互補性樣本。

4. **設計選擇性監督機制**：保留完整歷史軌跡作為 context context，但 loss 只施加於「資訊豐富片段」。可採用的選擇策略包含：
   - 成功 rollout 中非冗餘的推理片段。
   - 與當前策略分布差異顯著但仍相容的 segment。
   - 過濾掉「已掌握前綴」、「重複已解案例」、「樣板 SFT」式段落。

5. **建立兩階段 SFT 訓練**：第一階段以完整軌跡作為 context 輸入；第二階段僅在被選中的 segment 上計算 cross-entropy loss，其餘位置以 `-100` 遮罩。

6. **上游檢查點微調**：以 ROSS 資料對上游 checkpoint 做標準離線 SFT，學習率建議低於原始 RL 階段（如 1e-6 ~ 5e-6 區間），避免覆蓋既有能力。

7. **多場景驗證**：在數學、程式碼生成、指令遵循、軟體工程四類基準上評估，確認 ROSS 一致性提升而非單點過擬合。

8. **建立再訓練循環**：將 ROSS 後的 checkpoint 重新上線後，其新產生的 rollout 又可進入下一輪 ROSS，形成「訓練 → 回收 → 再訓練」的閉環。

### 潛在風險與注意事項

- **過擬合到歷史分布**：若選擇性監督設計不當，模型可能過度擬合早期策略的行為模式，反而降低對新分布的適應力。**緩解**：保留完整軌跡作為 context，僅在 segment 上施加 loss，並監控與當前策略的 KL 散度。

- **錯誤 rollout 的污染**：歷史倉庫中可能混入「幻覺軌跡」或被獎勵 hacking 污染的成功樣本。**緩解**：嚴格的成功標記過濾、雙重驗證（reward model + 規則檢查）、必要時人工抽樣審核。

- **冗餘片段放大偏見**：若未過濾「已掌握前綴」與「重複已解案例」，模型會在已會的內容上反覆訓練，造成災難性遺忘或過度自信。**緩解**：以 pass@1 與 NLL 聯合門檻剔除低互補性樣本。

- **MoE 路由偏移**：Qwen3.6-35B-A3B 為 MoE 架構，歷史 rollout 對應的專家路由可能與當前策略不同，導致 segment 級監督訊號失真。**緩解**：在選擇性監督前先做路由對齊檢查，或對 MoE 模型採用較低學習率。

- **軌跡儲存成本**：完整保存多階段 rollout 對儲存與 I/O 是沉重負擔。**緩解**：採用分段儲存、壓縮 tokenization、按價值預篩選後再持久化。

- **評估洩漏風險**：若選擇性監督的 segment 來自與測試集重疊的問題，可能高估實際效益。**緩解**：嚴格分離訓練問題與評測基準，並做去污染檢查。

- **「重新對齊」誤判**：部分歷史行為看似有用但實際已過時（如舊版 API 呼叫），盲目採用會引入回歸。**緩解**：對 segment 做時效性與領域一致性檢查。

### 與其他技術的整合建議

- **搭配 RLHF / RLAIF**：將 ROSS 視為 RL 後的「經驗回收」階段，而非取代 RL。可在 PPO/GRPO 收斂後接上 ROSS，避免線上採樣成本。

- **搭配 DPO / SimPO 等偏好學習**：先用 ROSS 做行為鞏固，再用 DPO 對齊人類偏好，兩者互補：ROSS 鞏固「會做但做不穩」的行為，DPO 修正「不該做」的行為。

- **搭配 RAG / 工具增強**：在智能體場景中，ROSS 可專注於監督「罕見有效工具呼叫」與「新穎正確分支」，與 RAG 的檢索增強形成「內化經驗 + 外掛知識」雙軌。

- **搭配模型合併 (Model Merging)**：將 ROSS 後的 checkpoint 與原 RL checkpoint 做線性合併，可進一步穩定性能，類似於「經驗回收 + 知識保留」的權重平均。

- **搭配資料策展管線**：將 ROSS 的選擇性監督邏輯封裝為可重用的「軌跡評分器」，與既有靜態 SFT 語料、curated corpus 統一管理，形成混合訓練資料池。

- **搭配 MLOps 監控**：在 rollout 倉庫中追蹤每筆軌跡的「被採用次數」與「貢獻度」，建立可解釋的訓練資料血緣，方便日後審計與除錯。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先讀摘要與第 1 節的問題動機，理解「為什麼歷史 rollout 不是垃圾」這個核心洞見；接著看圖 2 的相容性 × 互補性二維分類，建立直覺後再進入方法細節。實作上可先在小模型（如 7B）上重現 Sec. 2 的 NLL 與 pass@k 分析，體會「行為存在但未鞏固」的現象。

**給 AI 工程師**：重點關注 Sec. 2 的診斷方法與選擇性監督的 loss mask 設計，這是將論文落地為訓練管線的關鍵。建議直接從既有 RL/OPD 流程中抽出 rollout 倉庫，實作 segment-level loss 遮罩，並以 Qwen 系列或自家領域模型做 A/B 對照，驗證 MOPD 與 SWE-bench 上的提升幅度。

**給研究者**：Sec. 2 的相容性/互補性分析框架值得延伸，可探討：(1) 選擇性監督的理論依據（為何 segment-level 比 trajectory-level 更優）；(2) 與 offline RL、replay buffer 的關聯；(3) 在多模態或長上下文模型上的可推廣性。圖 3 的 pass@1 vs pass@k 曲線是很好的出發點，可進一步分析「未鞏固行為」的統計特性。

**給產品經理**：可將 ROSS 視為「用既有投資換取額外性能」的低成本升級路徑——不需要新一輪線上 RL 採樣，只需把訓練過程中已生成的資料聰明地再利用。對應到產品決策上，意味著：(1) 務必保留完整的訓練 rollout 倉庫，不要為了省儲存而提前清理；(2) 在模型迭代週期中預留「經驗回收」階段的時間與算力；(3) 關注數學、程式碼、指令遵循、軟體工程四類基準的一致性提升，這代表方法具有跨領域泛化能力，而非單點優化。
