**BioAgent-DF 框架的核心設計理念**

本文提出 BioAgent-DF（Biomedical Agent Decision Fidelity），這是一個專門針對生物醫學研究代理（Biomedical Research Agent）進行決策溯源（Decision Provenance）審計的框架。其方法論的核心洞見在於：科學代理的最終判定（Verdict）僅能反映決策過程的一個面向，兩個執行可能在判定上一致，卻在證據選擇（檢索、讀取、引文）上完全不同。這種「判定-證據分離」現象是審計方法必須正視的根本挑戰。

**工具狀態介入（Tool-state Intervention）機制**

框架採用「配對值保存-還原-移植」三階段方法論：

1. **狀態擷取（Capture）**：在相同的計算節點（Computation Site）保存參考值 $h$ 與候選值 $c$，兩者共享形狀、座標索引 $I$ 與表示方式。殘差 $r = FP32(c) - FP32(h)$ 被記錄下來，用於後續驗證。

2. **還原操作（Restoration）**：$R_S = \text{select}(S, h, c)$，在座標子集 $S$ 內採用第一個狀態，其餘採用第二個。這對應於「將候選值替換回參考值」的復原操作。

3. **移植操作（Transplantation）**：$T_S = \text{select}(S, c, h)$，方向相反，用於測試跨執行環境的狀態傳播效應。

此設計的精妙之處在於：審計者能在「健全硬體」（Healthy Hardware）上重現原本發生於「故障硬體」（Faulty Hardware）的數值錯誤，從而分離硬體故障與代理行為的因果關係。

**端點映射（Endpoint Mapping）與保真度定義**

框架定義兩層保真度：
- **證據路徑保真度（Evidence-path Fidelity）**：聚焦於檢索端點（Retrieval Endpoint）、讀取端點（Read Endpoint）、引文端點（Citation Endpoint）的一致性。
- **科學決策保真度（Scientific Decision Fidelity）**：涵蓋行動、項目選擇與判定的更廣泛審計。

形式化定義為：對於執行環境 $e \in \{A, B\}$ 與初始狀態 $z$，$\tau_e(z) = F^e(z)$ 表示結果。還原測試驗證 $D(F(R_S)) = D(F(h))$，移植測試驗證 $D(F(T_S)) = D(F(c))$，其中 $D$ 為端點映射函數。

**靜默資料損毀（SDC）的數值檢測**

針對分散式訓練中 GPU 故障產生的靜默資料損毀，框架採用多層次檢測策略：
- **算術約束驗證**：基於乘法、累加、中間捨入與最終轉換的捨入誤差界。
- **整數探測（Exact-integer Probes）**：在 FP32 表示下，允許的部分和必須為整數。例如觀測值 405613.25 對比精確值 405760，違反整數性即可判定錯誤。
- **指令級隔離**：透過張量核心矩陣乘累加（MMA）與純量 FP32 融合乘加（FFMA）的對比，識別故障執行路徑。實驗顯示 MMA 產生 38、24、54 個不一致輸出，而 FFMA 為零。

**hERG 應用的雙路徑復原**

在心臟安全性檢測（Cardiac-safety Assay）配置情境中，框架對比兩種復原策略：
- **預測檔案替換（Prediction File Replacement）**：僅替換最終輸出檔案。
- **執行狀態還原（Execution State Restoration）**：還原代理使用錯誤值之前的執行狀態，並供給經認證分數（Certified Scores）。

- **錯誤影響**：靜默數值錯誤改變了測試決策（Testing Decision），但固定預算短名單（Fixed-budget Shortlist）仍將相同數量的化合物標記為阻斷劑（Blockers）。這顯示表面指標（化合物計數）可能掩蓋底層決策變更。

- **復原效果對比**：
  - 還原執行狀態 + 供給認證分數：**全部 39 項變更決策復原**
  - 替換預測檔案：**零項復原**
  - 結論：「無錯誤行動被執行」（No Incorrect Action Committed）

此結果極具說服力：39 vs 0 的鮮明對比證明了「執行狀態層級還原」相較於「輸出檔案層級替換」的絕對優勢。

**效能最佳化結果**

串流實作（Streaming Implementation）的算術檢查相較於原始 FP64 實作：
- **總時間縮減**：42.4%
- **一致性保證**：相同的旗標（Identical Flag）與復原輸出（Recovery Output）

此結果在不改變審計語義的前提下，顯著提升了實用性，使框架能部署於大規模分散式訓練環境。

**互補實驗的區分能力**

工具實驗（Tool Experiment）與優化器實驗（Optimizer Experiment）成功區分三類復原：
1. **數值狀態復原（Numerical State Recovery）**：恢復精確數值。
2. **排序列表復原（Ranked List Recovery）**：恢復項目排序。
3. **可見歷史還原（Visible History Restoration）**：恢復代理可觀察的執行記錄。

此三分法對應於工具輸出的不同抽象層級，是方法論的重要細粒度貢獻。

#### 與現有研究的比較

**相較於傳統 SDC 研究的定位**

傳統靜默資料損毀研究多聚焦於訓練階段的數值異常檢測（如 Checksum、Algorithm-based Fault Tolerance），本文將視角延伸至**推理階段的科學代理**，這是顯著的領域拓展。傳統方法關心「訓練是否收斂」，本文關心「代理決策是否可信」。

**相較於 LLM 代理評估研究的創新**

現有 LLM 代理評估（如 ToolBench、AgentBench）多以任務成功率為指標，本文提出**雙軌審計**——同時追蹤證據與最終答案。這填補了「結果正確但過程可疑」的研究空白。

**相較於可解釋性研究的差異**

可解釋 AI（XAI）研究致力於理解模型內部決策邏輯，本文則採用**外部介入式審計**——透過受控的數值替換觀察代理行為變化。這種「因果介入」方法論更接近實驗科學傳統，而非純觀察性研究。

**方法論優勢**

1. **可分離性（Separability）**：透過健全硬體上的受控實驗，分離硬體故障與代理行為。
2. **可重現性（Repeatability）**：強調「可重現變更」（Repeatable Change）作為有效審計發現的標準。
3. **實用性（Practicality）**：hERG 應用展示從基準測試到真實科學決策的橋接能力。

**侷限性與待改進之處**

1. **模型覆蓋面有限**：僅測試 Qwen3.5-4B 與 Gemma 3 4B IT 兩個 4B 參數級模型，未涵蓋更大規模模型（如 70B+）或閉源模型（如 GPT-4、Claude）。
2. **領域侷限**：SciFact 為科學事實查證，hERG 為單一藥理應用，未涵蓋更廣泛的生物醫學任務（如蛋白質結構預測、基因序列分析）。
3. **故障模型簡化**：僅考慮兩類 GPU 故障（依規模故障 Size-dependent Fault 與擴展觸發故障 Expanded-trigger Fault），未涵蓋更複雜的故障模式。
4. **審計粒度**：端點定義聚焦於檢索、讀取、引文，未深入代理的內部推理狀態（如注意力模式、隱層表示）。

**短期延伸（1-2 年）**

1. **跨模態代理審計**：擴展至視覺-語言代理（如用於醫學影像分析的多模態模型），研究圖文證據分離現象。

2. **因果溯源理論**：建立形式化的「代理決策因果圖」（Agent Decision Causal Graph），將工具狀態、證據選擇、最終判定建模為因果變數，支援反事實推理（Counterfactual Reasoning）。

3. **隱私保護審計**：在醫療等敏感領域，審計過程本身可能洩漏患者資料，需研究聯邦審計（Federated Audit）與差分隱私（DP）技術的整合。

4. **即時審計系統**：基於串流實作的 42.4% 時間縮減成果，開發生產環境的即時決策溯源監控系統，支援大規模科學代理部署。

**長期願景（5-10 年）**

1. **科學代理的可信賴 AI 框架**：將決策溯源納入 AI 代理的標準可信賴屬性，類似於傳統軟體的「可審計性」（Auditability）要求。

2. **自我審計代理（Self-auditing Agent）**：讓代理具備內建審計能力，能自動記錄、驗證、解釋自身決策過程，減少對外部審計工具的依賴。

3. **跨學科審計標準**：與科學哲學、科學社會學合作，建立「科學代理決策品質」的跨學科評估標準，涵蓋認識論（Epistemology）與倫理學維度。

4. **監管科學整合**：與 FDA、EMA 等藥物監管機構合作，將 BioAgent-DF 類方法納入藥物開發決策的審計要求，特別是 AI 輔助決策的場景。

**關鍵開放問題**

1. **判定-證據分離的本質**：為何代理能在錯誤證據下得出正確判定？這是 LLM 的「魯棒性」還是「僥倖」？

3. **代理自主性與審計的張力**：隨著代理自主性增強，外部審計的可及性如何維持？
4. **跨執行環境的可比性**：不同硬體、軟體棧下的審計結果如何對齊與比較？

A：在 SciFact 的八個批次中，Qwen3.5-4B 在三個擷取-聲明組合中展現可重現的引文變更（repeatable citation change），而 Gemma 3 4B IT 則在四個組合中同時出現可重現的讀取與引文變更，這七個組合共涵蓋兩項命題。值得注意的是，完整還原（full restoration）能恢復參考證據集，但判定結果維持不變，證實了「證據」與「判定」確實可被分離。在 hERG 案例中，靜默數值錯誤改變了 39 項測試決策，但透過還原較早的執行狀態並供給認證分數（certified scores），全部 39 項決策皆被成功復原，而僅替換預測檔案則無法復原任何一項，且整個過程未產生錯誤行動。

**Q9：BioAgent-DF 進行了哪些消融與對照實驗？**
A：BioAgent-DF 設計了多項互補實驗以區辨不同層次的復原效果，包括工具實驗（tool experiment）與優化器實驗（optimizer experiment），前者聚焦於數值狀態的恢復，後者則檢驗排序列表與可見歷史的還原效果。在硬體層面，作者使用精確整數探測（exact-integer probes）作為簡化驗證手段，因為其乘積與部分和在 FP32 下必須為整數，觀察到的 405613.25 等非整數值即可直接判定為異常。此外，作者以 FFMA 替換 MMA 指令並搭配目標 SM 與非目標 sham 路由，進一步定位兩類 GPU 故障的受影響執行路徑。在提示工程層面，則比較了基線提示詞與顯式範例提示詞下判定變更是否復現，以排除提示敏感性的混淆效應。

**Q10：BioAgent-DF 適用於哪些實際應用情境？**
A：BioAgent-DF 適用於任何依賴科學代理進行文獻檢索、證據彙整與決策支援的場景，特別是生物醫學研究中的文獻綜述、系統性回顧與證據等級評估。在製藥領域，框架可直接應用於 hERG 等心臟安全性檢測的化合物配置，協助研究人員在固定預算下識別哪些化合物應進入下一階段的濕實驗驗證。此外，對於依賴分散式 GPU 叢集進行大規模模型推論的組織，BioAgent-DF 提供了一套可操作的審計流程，能在不中斷生產線的情況下診斷 SDC 對下游科學決策的影響。

**Q11：將 BioAgent-DF 整合至實際產品時需考量哪些因素？**
A：在產品化層面，首先需考量工具狀態保存的儲存與效能成本，因為每個計算節點都需記錄參考值與候選值的配對，這對大規模分散式系統會帶來額外的 I/O 負擔。其次，串流實作（streaming implementation）雖已將總時間縮減 42.4% 並維持相同的旗標與復原輸出，但實際部署時仍需評估其在不同硬體架構下的可移植性。再者，產品應明確區分「證據保真度」與「判定保真度」兩類指標的告警閾值，因為兩者對使用者的意義不同——證據偏差可能影響可重現性，而判定偏差則直接影響行動決策。

**Q12：BioAgent-DF 對科學代理領域的整體影響為何？**
A：BioAgent-DF 對領域的核心貢獻在於將「決策溯源」（decision provenance）從概念推向可操作的審計框架，促使未來的科學代理設計必須同時記錄證據路徑與最終判定。論文的結論明確指出，審計應「同時追蹤代理使用的證據與其最終答案」，這將成為科學決策審計的新基準。此外，框架揭示了 SDC 在科學代理中的隱性傳播路徑，提醒研究社群在評估 LLM 代理時，不能僅依賴最終答案的正確性，還必須檢驗其推理過程的數值與邏輯完整性。這對建立可信賴的 AI 輔助科學研究生態系具有深遠的影響。

**Q13：BioAgent-DF 存在哪些已知的限制？**
A：BioAgent-DF 的限制之一在於其實驗範圍僅涵蓋兩個 LLM（Qwen3.5-4B 與 Gemma 3 4B IT）與兩個資料集（SciFact 與 hERG），尚未擴展至更大規模的模型或多樣化的科學領域。其次，框架依賴「相同計算節點」的假設來配對參考與候選值，但在實際分散式系統中，計算節點的動態調度可能使此假設難以滿足。此外，框架對於「可重現變更」的判定仰賴多次重複實驗，這在計算成本上仍是顯著的開銷，特別是當應用於大型代理工作流程時。

**Q14：BioAgent-DF 在哪些情境下可能失效？**
A：BioAgent-DF 可能在其代理行為本身具有高度隨機性的情境下失效，因為若代理的證據選擇與判定結果對微小數值差異極度敏感，則「可重現變更」的判定將變得困難。此外，當 SDC 發生在框架監測範圍之外的位置（例如非數值的字串編碼錯誤或模型權重損毀）時，配對值的介入將無法有效模擬真實的故障路徑。再者，若代理使用了框架未涵蓋的工具類型（例如多模態工具或外部 API），則還原與移植操作的座標定義將需要重新設計，現有方法無法直接套用。

**Q15：BioAgent-DF 的未來研究方向為何？**
A：未來研究方向可朝三個維度延伸：首先是擴大模型與領域的覆蓋範圍，將框架應用於更大規模的 LLM（如 70B 以上的模型）以及其他科學領域（如材料科學或氣候模擬）。其次是發展自動化的故障診斷機制，使框架不僅能偵測 SDC 對決策的影響，還能主動定位故障的 GPU 與計算節點，以加速硬體維護流程。最後，可將 BioAgent-DF 的審計理念整合至代理開發生命週期，從訓練階段就引入證據路徑與判定結果的雙重記錄機制，使科學代理在設計之初即具備可審計性，這將是建立可信賴 AI 科學助理的關鍵一步。

## 實務應用指南

### 適用場景

1. **製藥研發中的文獻審查自動化**：在藥廠的標靶驗證（target validation）流程中，部署基於 LLM 的文獻檢索代理時，使用 BioAgent-DF 框架定期審查代理是否在引用相同證據的情況下產生一致的判定，避免因 GPU 靜默錯誤導致證據路徑偏移而誤導後續實驗設計。

2. **hERG 心臟安全性篩選的決策溯源**：在化合物早期安全性評估階段，將代理用於依據預測分數分配有限的 hERG 檢測資源時，套用此框架驗證「還原執行狀態 + 認證分數」是否能完整復原所有 39 項變更決策，確保預算約束下的化合物標記正確。

3. **臨床決策支援系統的證據鏈稽核**：在醫療 AI 系統引用最新臨床指引與系統性綜述時，使用證據路徑保真度（evidence-path fidelity）檢查代理是否在維持最終建議不變的前提下，悄悄替換了引用的文獻段落，作為合規審計的技術基礎。

4. **多代理科學工作流程的版本控制**：在跨機構的蛋白質結構預測、分子動力學模擬與文獻挖掘串接流程中，將 BioAgent-DF 的「擷取-聲明組合」（capture-claim combination）作為工作流程節點的審計單元，識別哪個工具節點的數值錯誤會向下傳播至最終行動。

5. **AI 製藥監管申報的決策可重現性驗證**：在準備 IND（Investigational New Drug）申請時，使用此框架證明 AI 輔助決策的證據路徑與最終判定均可被獨立第三方還原，符合 FDA 對 AI/ML 醫療器材的「預定變更控制計畫」（PCCP）要求。

### 實作前置條件

**資料需求**：
- 領域標註語料庫（如 SciFact 風格的證據-聲明配對資料），用於建立參考證據集
- 工具輸出快照系統：能在每個計算節點（computation site）保存參考值與候選值的配對記錄
- 領域專家標註的「正確證據」基準線，用於判定代理引用的證據是否偏離

**運算資源**：
- 健全 GPU 叢集（healthy hardware）作為基準執行環境
- 故障注入（fault injection）測試環境：能重現 Case 1（依規模故障）與 Case 2（擴展觸發故障）兩類 GPU 行為
- FP64 雙精度運算支援，用於算術邊界檢查的參考實作
- 串流（streaming）算術檢查的實作基礎設施，以達成 42.4% 的時間縮減

**技能要求**：
- 分散式訓練與 GPU 架構知識（理解 SM 路由、tensor-core MMA、FFMA 指令差異）
- LLM 代理開發經驗（熟悉 Qwen3.5-4B、Gemma 3 4B IT 等模型的工具呼叫介面）
- 數值分析基礎（浮點數誤差邊界、BF16 還原誤差傳播）
- 領域專業知識（生物醫學文獻檢索、hERG 離子通道藥理學）
- 提示工程能力（基線提示詞 vs 顯式範例提示詞的對照實驗設計）

### 實作步驟建議

**階段一：建立審計基礎設施（2-4 週）**
1. 在代理工具鏈的每個計算節點插入狀態保存鉤子（state-saving hook），記錄形狀、座標索引與表示法
2. 實作 `select(S, h, c)` 函式，支援還原（restoration, R_S）與移植（transplantation, T_S）兩種操作
3. 部署健全硬體上的參考執行管線，產出可重現的基準證據集

**階段二：算術驗證層建置（3-5 週）**
4. 實作 FP32 殘差計算 `r = FP32(c) − FP32(h)`，並在轉換至儲存表示 Q 後進行空、滿、零殘差對照
5. 整合精確整數探測器（exact-integer probes），用於偵測無法以 FP32 表示的異常輸出（如 405613.25 對 405760）
6. 將算術檢查重構為串流實作，目標是維持相同旗標與復原輸出的前提下，達成 42.4% 的時間縮減

**階段三：代理層審計整合（4-6 週）**
7. 在代理的可見歷史（visible history）介面層加入端點記錄器，覆蓋檢索、讀取、引文三類端點
8. 設計擷取-聲明組合的批次實驗框架（參考論文中 8 個 SciFact 批次、3+4=7 個組合的規模）
9. 實作重複性測試：對每個組合執行多次，區分「可重現變化」與隨機變異

**階段四：領域應用驗證（4-8 週）**
10. 在 hERG 檢測配置情境中，建立「預測檔案替換」與「執行狀態還原 + 認證分數供給」兩條對照路徑
11. 量化「全部 39 項復原」vs「零項復原」的差異，驗證「無錯誤行動被執行」的結論
12. 整合提示詞敏感性測試：比較基線提示詞與顯式範例提示詞下的判定變化是否可重現

**階段五：產品化部署（持續）**
13. 將審計結果匯入決策溯源儀表板，追蹤證據路徑與最終答案的雙重指標
14. 建立定期審計排程與異常告警機制，特別針對靜默數值錯誤的傳播路徑

### 潛在風險與注意事項

**風險一：靜默資料損毀（SDC）通過常規監測**
- 現象：有限錯誤輸出能通過 NaN/Inf 監測並抵達工具結果
- 緩解：部署精確整數探測器與 FP32 殘差邊界檢查；不要僅依賴異常值監測

**風險二：還原與替換的混淆**
- 現象：替換預測檔案無法復原任何變更決策（論文中 0/39），但容易被誤認為「已修正」
- 緩解：嚴格區分「數值狀態還原」、「排序列表還原」、「可見歷史還原」三類操作；建立還原層級的標準作業程序

**風險三：提示詞敏感性導致誤判**
- 現象：基線提示詞下觀察到的判定變更，在顯式範例提示詞下不再重現
- 緩解：審計實驗必須在多個提示詞設定下重複進行，單一提示詞的結論不應作為最終判定依據

**風險四：證據路徑偏移但判定不變**
- 現象：代理可能在維持最終 SUPPORT/REFUTE 標籤不變的情況下，引用完全不同的句子（論文中 claim 431 的案例）
- 緩解：審計指標必須同時追蹤證據與答案，不可僅監控最終判定；圖 1 顯示的「相同判定、不同引文」是此風險的典型表現

**風險五：GPU 故障分類的複雜性**
- 現象：依規模故障（Case 1）與擴展觸發故障（Case 2）需要不同的偵測策略
- 緩解：使用 FFMA 替換與非目標 SM 偽路由（sham routing）識別受影響的執行路徑；不要假設單一偵測方法能覆蓋所有故障類型

**風險六：審計成本與延遲**
- 現象：完整的算術檢查與狀態還原會增加運算負擔
- 緩解：採用串流實作（論文中達成 42.4% 時間縮減），並將審計頻率與任務關鍵性掛鉤

### 與其他技術的整合建議

**與 MLOps 平台整合**：
- 將 BioAgent-DF 的端點記錄器接入 MLflow 或 Weights & Biases 的追蹤系統，把證據路徑作為模型行為的額外維度記錄
- 利用現有的模型版本控制機制管理「參考執行」與「候選執行」的配對

**與溯源追蹤系統整合**：
- 與 OpenLineage 或 Marquez 等資料溯源工具對接，將工具狀態保存納入統一的溯源圖譜
- 在 W3C PROV 框架下，將「擷取-聲明組合」建模為 PROV 實體與活動的關聯

**與科學工作流程管理整合**：
- 整合 Nextflow 或 Snakemake 等工作流程引擎，在每個計算節點自動觸發審計檢查
- 與電子實驗記錄本（ELN）系統對接，將審計結果寫入實驗記錄的可追溯層

**與提示工程平台整合**：
- 將基線提示詞與顯式範例提示詞的管理整合到 PromptLayer 或 LangSmith 等工具
- 利用 A/B 測試框架自動評估不同提示詞下的判定穩定性

**與硬體監控整合**：
- 將 GPU 健康監控（如 NVIDIA DCGM）與 BioAgent-DF 的故障偵測對接，建立「硬體-工具-代理」三層的故障傳播可視化
- 整合 DCGM 的 SDC 偵測功能與本框架的算術邊界檢查，形成互補的偵測體系

**與合規審計系統整合**：
- 將審計輸出格式化為符合 GxP（Good Practice）規範的稽核記錄
- 整合至製藥公司的品質管理系統（QMS），支援監管檢查時的決策可重現性證明

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與第 1 節，理解「相同判定、不同證據」這個核心問題——也就是 LLM 代理可能在最終答案不變的情況下，悄悄改變它所引用的證據。圖 1 是最好的起點，它直觀展示了 claim 431 的案例：兩個執行分支都回傳正確的 SUPPORT 標籤，但引用的句子完全不同。接著閱讀第 2.1 節的算術約束部分，了解為什麼 GPU 故障能產生「有限但錯誤」的輸出。

**給 AI 工程師**：重點關注第 2.2 節的工具狀態介入方法，特別是 `select(S, h, c)` 的還原與移植操作如何對應到實際的代理實作。算術驗證層（精確整數探測器、FP32 殘差計算、串流實作的 42.4% 時間縮減）是可直接整合到現有代理框架的工程元件。建議同時閱讀附錄 A 與 B，理解 FFMA 替換與 SM 偽路由如何定位受影響的執行路徑，這對除錯 GPU 故障至關重要。

**給研究者**：本論文的核心方法論貢獻在於將「證據路徑保真度」與「科學決策保真度」分離為兩個可獨立審計的維度，這對 LLM 代理的可解釋性研究具有方法論意義。建議仔細分析 8 個 SciFact 批次、7 個擷取-聲明組合的實驗設計，特別是「可重現變化」的統計判定標準。hERG 案例（39 項變更決策的完整復原 vs 零項復原的對照）是驗證「還原層級」理論的關鍵實驗，可作為後續研究（如藥物篩選代理的審計框架設計）的基礎。

**給產品經理**：本框架回答的核心商業問題是：「當我們的 AI 代理在製藥研發中做出決策時，我們能否向監管機構證明這個決策是可重現的？」hERG 案例的「無錯誤行動被執行」結論，以及「還原執行狀態 + 認證分數」相較於「替換預測檔案」的顯著優勢，直接對應到產品設計中的「可審計性」與「故障恢復」兩個關鍵指標。在規劃 AI 製藥產品時，應將 BioAgent-DF 的審計層視為必要的合規基礎設施，而非可選的附加功能。
