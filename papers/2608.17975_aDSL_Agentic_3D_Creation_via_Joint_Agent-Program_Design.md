## ⚡ TL;DR

現有 LLM 代理式三維程式生成因介面與語言模型推理能力不匹配而過於脆弱。
本文協同設計 aDSL 與角色專業化多代理系統，以計畫-執行-評論者迴圈迭代創作。
實驗顯示本方法在文字與影像生成形狀任務上超越既有基線，並保有可編輯結構。

## 摘要翻譯

程式化表示法（Programmatic representations）為三維內容創作（3D content creation）提供了一個極具吸引力的典範，能實現細粒度編輯（Fine-grained edits）、可解釋性（Interpretability）以及顯式結構控制（Explicit structural control）。然而，依賴大型語言模型（Large language models, LLMs）來編寫三維程式的代理式工作流程（Agentic workflows）仍相當脆弱，經常無法將高階意圖（High-level intent）轉化為一致的低階幾何（Low-level geometry）。我們將此脆弱性歸因於現有程式化介面與 LLMs 推理優勢之間的不匹配：LLMs 更擅長語義結構（Semantic structure）與空間關係（Spatial relations），而非脆弱的數值選擇（Numeric choices）。在本文中，我們協同設計了一種以代理為中心的領域特定語言（Agent-centric Domain-Specific Language, aDSL）以及一個角色專業化多代理系統（Role-specialized multi-agent system），以彌合此差距。aDSL 透過強調可組合性（Composability）與空間推理（Spatial reasoning），橋接語義邏輯（Semantic logic）與幾何約束（Geometric constraints）；它使代理（Agent）能夠透過關係運算子（Relational operators）而非脆弱的絕對座標（Absolute coordinates）來操作幾何形體。基於 aDSL，我們的無需訓練（Training-free）多代理系統遵循計畫-執行-評論者迴圈（Plan-Execute-Critic loop），以分解需求、合成程式碼，並利用執行回饋（Execution feedback）迭代修復錯誤與約束違反（Constraint violations）。實驗顯示，此協同設計（Co-design）提升了穩健性（Robustness）、可控性（Controllability）以及對使用者意圖的忠實度（Faithfulness to user intent）。我們的方法在文字生成形狀（Text-to-shape）與影像生成形狀（Image-to-shape）任務上優於先前基於 LLM 的基線方法，同時保留了顯式結構（Explicit structure）、可編輯性（Editability）與可解釋性。此方法亦支援下游應用（Downstream applications），例如關節式物體創建（Articulated object creation）與結構化場景組合（Structured scene composition）。我們的程式碼已公開於 https://github.com/sig-pku/aDSL。

### 核心貢獻（3～5點）
- 提出以代理為中心的領域特定語言 aDSL，透過關係運算子與空間推理橋接高階語義意圖與低階幾何約束，避免脆弱的絕對數值選擇。
- 設計無需訓練的角色專業化多代理系統，採用 Plan-Execute-Critic 迴圈並結合執行回饋進行迭代修復，提升程式碼合成的穩健性。
- 在文字生成形狀與影像生成形狀任務上超越既有 LLM 基線，同時保留程式化表示的顯式結構、可編輯性與可解釋性。
- 展示下游應用潛力，包括關節式物體創建與結構化場景組合，驗證方法在複雜三維創作情境的通用性。

### 適合對象
適合對電腦圖學、三維生成、LLM 代理系統及程式化建模有興趣的研究者與工程師，特別是關注如何結合大型語言模型與結構化程式表示以提升三維內容創作穩健性、可控性與可解釋性的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心問題意識：為何 LLM 驅動的 3D 程式生成仍不穩健？

本文指出，現有以大型語言模型（LLMs）為基礎的代理式三維創作（Agentic 3D Creation）雖然具備可解釋性（interpretability）與細粒度編輯（fine-grained edits）的潛力，卻經常無法將高階意圖（high-level intent）穩定轉譯為一致的低階幾何（low-level geometry）。作者將此歸因於「程式化表示法（programmatic representations）」與「LLM 推理強項」之間的錯配：LLM 擅長語義結構（semantic structure）與空間關係（spatial relations），卻不擅長處理易碎的數值選擇（numeric choices）。例如，代理可以輕易判斷「椅腳應位於椅座下方且連接四個角落」，卻難以精確給出椅腳與椅座的絕對座標（absolute coordinates）。因此，單純提升語言的表達力並不足夠，必須同時讓語言與代理系統協同設計（joint agent-program design / co-design）。

##### 2. aDSL 語言設計：以代理為中心的領域特定語言

為了彌合語義邏輯（semantic logic）與幾何約束（geometric constraints）之間的鴻溝，本文提出 aDSL（以代理為中心的領域特定語言，agent-centric Domain-Specific Language）。aDSL 並非一般用途的建模程式（general-purpose modeling programs，如 Blender Python scripts 或 parametric CAD code），而是針對代理推理特性設計的高階 DSL，強調三大設計原則：

- **表達力（expressiveness）**：能夠涵蓋多樣的形狀（shape）與場景（scene）結構，包括物件層級、部件層級乃至關節式物體（articulated object creation）。
- **可組合性（composability）**：支援模組化組裝與階層式複用，讓代理可以將複雜場景逐步拆解為「場景 → 物件 → 部件」，並重複使用既有程式片段。
- **空間推理（spatial reasoning）**：提供關係運算子（relational operators），例如「place A on top of B」、「attach A to B」，讓代理以空間關係而非絕對座標來操作幾何。

透過這種設計，aDSL 讓代理能夠專注於高階結構與語義意圖（semantic intent），將低階數值細節交由語言執行環境或幾何約束求解器處理，從而減少因微小數值誤差導致的無效幾何（如懸浮的椅腳）或約束違反（constraint violations）。

##### 3. 角色專業化多代理系統：Plan–Execute–Critic 迴圈

在 aDSL 之上，本文設計了一個無需訓練（training-free）的角色專業化多代理系統（role-specialized multi-agent system）。該系統採用 Plan–Execute–Critic 迴圈，將創作流程拆解為三個主要階段：

- **Plan（規劃）**：代理根據文字描述或參考影像，將高階使用者意圖（user intent）分解為可組合的階層式子任務。例如，生成一張椅子可分解為椅座、椅背、四支椅腳等部件，並定義它們之間的空間關係。
- **Execute（執行）**：代理將規劃結果合成為 aDSL 程式碼（code synthesis），並執行程式以產生實際幾何。此階段強調利用 aDSL 的關係運算子與組合機制，避免直接指定易碎的絕對座標。
- **Critic（評論者）**：系統檢查執行結果是否滿足設計約束（design constraints），例如部件是否正確接觸、比例是否合理、結構是否穩定。若發現錯誤或約束違反，則將執行回饋（execution feedback）返回給代理，進行迭代修復（iterative repair）。

這種迴圈的關鍵在於「共享表示法（shared representation）」：規劃、編碼與評論三個階段都基於相同的 aDSL，使得錯誤定位、意圖對齊與約束滿足能夠在同一語義層次上進行，而不需要在自然語言與低階幾何表示之間反覆轉譯。

##### 4. 方法論的整體價值

整體而言，本文的方法論並非單純提出一種新語言或一個新代理架構，而是強調兩者的協同設計（co-design）：aDSL 的語法與語義是為了配合 LLM 的推理強項而設計；而多代理系統則是為了充分發揮 aDSL 的結構化特性而設計。這種雙向匹配是本文相較於早期僅將 LLM 視為「程式碼生成器」的研究之主要區別。

#### 實驗數據解讀

由於目前可取得的上下文僅包含摘要與引言，以下分析主要基於作者所描述的實驗設計與宣稱的趨勢，並對可能採用的評估指標進行推論。

##### 1. 評估任務

本文在兩大主流任務上進行評估：

- **文字生成形狀（text-to-shape）**：根據自然語言描述生成對應的 3D 形狀。
- **影像生成形狀（image-to-shape）**：根據單張參考影像重建或生成對應的 3D 形狀。

此外，作者還展示了一系列下游應用（downstream applications），包括關節式物體創建（articulated object creation）與結構化場景組合（structured scene composition），以證明 aDSL 在複雜結構與可編輯性（editability）方面的優勢。

##### 2. 比較基線

作者將方法與多個近期的 LLM 驅動基線進行比較，包括：

- Du et al. 2024、Lu et al. 2025、Zhang et al. 2025a,b 等以程式化表示法為基礎的方法。
- Ahuja and Contributors 2025 等通用 LLM 代理基線。

這些基線涵蓋了從通用建模程式（如 Blender Python scripts）到專門 DSL 的不同光譜，能夠較全面地驗證 aDSL 與多代理系統協同設計的價值。

##### 3. 評估面向與指標推論

根據摘要與引言，本文強調以下評估面向：

- **穩健性（robustness）**：在迭代精修（iterative refinement）過程中，生成結果是否會退化或產生無效幾何。由於 aDSL 使用關係運算子與執行回饋修復，預期在多次迭代後仍能保持結構一致性。
- **可控性（controllability）**：使用者是否能透過高階語義指令精確控制生成結果的結構與參數（parameters）。aDSL 的顯式結構（explicit structure）與參數化設計使其在這方面優於隱式擴散模型（diffusion models）。
- **對使用者意圖的忠實度（faithfulness to user intent）**：生成結果是否準確反映文字或影像中的語義與空間關係。多代理的 Plan–Execute–Critic 迴圈有助於縮小高階意圖與低階幾何之間的差距。
- **約束滿足度（constraint satisfaction）**：幾何約束（如接觸、對稱、支撐）是否被正確滿足。Critic 階段專門負責檢測並修復約束違反。

具體的量化指標可能包括：結構正確率、約束違反次數、使用者研究中的偏好分數、與參考形狀的幾何相似度（如 Chamfer Distance、IoU），以及編輯操作的成功率等。由於目前缺乏完整論文數據，無法給出確切數值，但作者明確指出其方法在這些面向「優於先前基線」。

##### 4. 定性結果的意義

除了量化比較，本文特別強調 aDSL 保留了程式化表示法的優勢：顯式結構（explicit structure）、可編輯性（editability）與可解釋性（interpretability）。這意味著生成結果不僅是一個靜態網格，而是一份可讀、可修改、可重複使用的程式。對於需要後續調整的應用場景（如遊戲、電影製作、具身人工智慧，embodied AI），這種特性具有顯著實用價值。

#### 與現有研究的比較

##### 1. 相對於學習式 3D 生成方法

近年來，3D 生成領域的主流是基於擴散模型（diffusion models）與大規模 3D 資料集（3D datasets）訓練的方法，例如 Hunyuan3D、Shap-E、3DTopia 等。這類方法通常將幾何映射到緊湊的可學習表示法（geometric representations），如 triplanes、3D Gaussians、sparse voxel grids 或 latent vector sets，能夠在視覺保真度（visual fidelity）上達到令人驚豔的效果。

然而，這些方法通常需要大量訓練基礎設施與 curated 資料集（如 ShapeNet、Objaverse），並且在可控性（controllability）、可編輯性（editability）與可解釋性（interpretability）方面較弱。相較之下，aDSL 採取無需訓練（training-free）的代理式路徑，透過顯式結構與程式化表示，讓使用者能夠精確控制生成過程與結果。

##### 2. 相對於早期 LLM 驅動的程式生成

早期研究如 Alrashedy et al. 2024、Du et al. 2024、Lu et al. 2025、Yuan et al. 2024 等，嘗試直接讓 LLM 生成通用建模程式，例如 Blender Python scripts、參數化 CAD 程式碼（parametric CAD code）或程序式/規則式程式（procedural/rule-based programs）。這些表示法雖然表達力強，但抽象層次過低（low level of abstraction），使得 LLM 難以一致地編碼語義意圖，且在局部修改時容易崩潰。

aDSL 的改進在於：它不是讓 LLM 直接操作低階數值，而是提供高階的關係運算子與組合機制，讓 LLM 發揮其語義結構與空間關係的推理強項。

##### 3. 相對於近期專門 DSL

近期如 Jones et al. 2025、Zhang et al. 2025a,b 等工作也提出了針對物件與場景的領域特定語言（DSL）。這些 DSL 提升了表達力，但大多隱含假設 LLM 能夠可靠地撰寫與修訂有效程式，較少關注代理系統如何利用 DSL 結構進行穩健生成、驗證與修訂。

aDSL 的差異化在於「代理與程式協同設計（joint agent-program design）」：語言不僅是為了人類或可執行性設計，更是為了配合 LLM 代理的規劃、執行與評論能力而設計。同時，角色專業化的多代理系統進一步彌補了單一 LLM 在數值精度與約束滿足上的不足。

##### 4. 本文方法的限制

儘管 aDSL 在穩健性與可控性方面具有優勢，但仍存在若干潛在限制：

- **表達力上限**：aDSL 為了配合代理推理而做了抽象層次的取捨，對於極度複雜或高度不規則的有機形狀，可能不如低階建模程式或學習式方法靈活。
- **對 LLM 能力的依賴**：雖然 aDSL 降低了數值推理負擔，但規劃與語義分解仍高度依賴 LLM 的常識與空間推理能力。對於訓練資料中少見的物件類別，可能出現結構誤判。
- **Critic 的完備性**：執行回饋與約束檢查的覆蓋範圍決定了迭代修復的上限。若某些幾何或語義錯誤難以被自動檢測，則可能無法完全修復。
- **計算與延遲**：多代理迴圈與迭代修復可能帶來較高的推理成本與延遲，對於需要即時生成的應用場景可能構成挑戰。

#### 可重現性評估

##### 1. 程式碼開放性

根據摘要，本文的程式碼已公開於：

> https://github.com/sig-pku/aDSL

這對於可重現性（reproducibility）是正面訊號。開源程式碼通常包含 aDSL 的語法定義、多代理系統的實作、執行環境、範例腳本以及可能的評估工具。研究者與開發者可以基於此進行驗證、擴展或應用於自身場景。

##### 2. 資料集與模型權重

本文強調方法為「無需訓練（training-free）」，因此不像擴散模型方法那樣依賴大規模 3D 資料集或預訓練模型權重。這降低了重現門檻：只要具備適當的 LLM API 存取權限（如 GPT-4、Claude 等）與幾何執行環境，即可運行系統。

然而，若論文進行定量比較時使用了特定的測試資料集（如 ShapeNet 子集、ABO、3D-FUTURE 等），則仍需確認這些資料集是否公開可用，以及作者是否提供了相應的資料處理腳本。目前從摘要與引言無法確定具體使用了哪些資料集。

##### 3. 重現的潛在挑戰

- **LLM API 依賴**：由於系統基於 LLM，重現結果可能受到模型版本、溫度參數（temperature）、提示詞設計（prompt engineering）等因素影響。若作者未提供完整的提示詞與模型設定，重現的精確數值可能有所差異。
- **幾何執行環境**：aDSL 需要對應的幾何引擎來執行關係運算子與約束求解。該引擎的穩定性與實作細節會直接影響生成結果。
- **評估指標實作**：若作者開放了評估程式碼，將有助於社群進行公平比較；否則，其他研究者可能需要自行實作指標。

整體而言，aDSL 在可重現性方面優於需要大量訓練資源與模型權重的學習式方法，但仍需依賴完整的開源文件與環境設定才能達到高度可重現。

#### 未來研究方向

##### 1. 與學習式方法的混合架構

未來可以探索將 aDSL 與擴散模型（diffusion models）或 3D Gaussians 等學習式表示法結合。例如，利用擴散模型生成高保真細節或紋理，再由 aDSL 提供結構化骨架與語義控制；或者讓 aDSL 作為擴散模型的條件輸入，提升可控性與可編輯性。

##### 2. 自動化 aDSL 語言擴展

目前 aDSL 的語法與關係運算子由人類設計。未來可以研究如何讓 LLM 或程式合成系統自動發現新的組合模式與空間運算子，進一步擴展語言的表達力，同時保持對代理推理的友善性。

##### 3. 更強大的 Critic 與約束推理

現有的 Critic 階段主要依賴執行回饋與幾何約束檢查。未來可以引入更形式化的驗證技術，例如基於物理的模擬（physics-based simulation）、結構穩定性分析、或甚至形式化方法（formal methods），以確保生成結果在功能上正確且可製造。

##### 4. 多模態輸入與互動式編輯

除了文字與影像，未來可以支援草圖、影片、點雲（point clouds）或語音等多模態輸入。同時，發展互動式編輯介面，讓使用者可以在 aDSL 程式層次上直接修改結構與參數，並即時看到幾何更新，將大幅提升實用價值。

##### 5. 降低 LLM 成本與延遲

多代理迴圈與迭代修復雖然提升穩健性，但也增加推理成本。未來可以研究如何透過快取、程式片段複用、輕量級本地模型（如微調後的開源 LLM）或更緊湊的規劃策略來降低延遲與 API 費用，使系統更接近實際生產環境的需求。

##### 6. 應用於具身人工智慧與機器人

aDSL 的顯式結構與語義資訊對於具身人工智慧（embodied AI）與機器人任務特別有價值，例如物件操作、場景理解、導航與任務規劃。未來可以探索將 aDSL 作為機器人與 3D 場景之間的橋樑，讓機器人能夠基於結構化程式表示進行推理與行動規劃。

##### 7. 建立標準化評估基準

目前 agentic 3D creation 領域缺乏統一的評估基準與資料集。未來可以建立針對程式化表示法的標準測試集，涵蓋不同類別、複雜度與約束條件，並定義明確的穩健性、可控性、可編輯性與忠實度指標，以促進該領域的公平比較與持續進步。

## 論文問答

**Q1：aDSL 試圖解決什麼核心問題？現有基於 LLM 的程式化三維創作為何仍顯脆弱？**

A：aDSL 針對的核心問題是：現有代理式三維創作流程難以將高階使用者意圖穩定地轉譯為一致的低階幾何。這種脆弱性源於程式化介面與大型語言模型推理強度之間的不匹配——LLM 擅長語義結構與空間關係，卻不擅長處理易碎的絕對數值選擇。因此，當代理被要求直接撰寫 Blender Python 或參數化 CAD 程式時，常出現浮動零件、接觸遺失或約束違反等幾何錯誤，導致生成結果偏離使用者意圖。

**Q2：通用建模程式與程序式／規則式程式各有哪些不足，為何無法滿足代理式創作的需求？**

A：Blender Python 指令碼與參數化 CAD 程式碼雖然表達力強，但抽象層次過低，迫使代理在大量易碎的數值參數中做決策，難以穩定編碼語義意圖，並且在局部修改時容易崩潰。相對地，程序式或規則式形式雖然提供較強的參數控制，卻往往難以擴展到多樣的物件類別、風格變化與細粒度約束。這兩類現有表示法都未充分考量 LLM 的推理特性，因此無法在表達力與代理可生成性之間取得平衡。

**Q3：為何必須「協同設計」領域特定語言與代理系統，而非單獨改進表示法或單獨設計代理？**

A：單純提升語言的表達力並不足夠，因為即使語言更強大，代理仍可能在低階數值上出現微小失誤，進而產生無效幾何或違反設計約束。反之，若只改進代理系統卻使用與 LLM 推理特性不符的低階介面，代理仍會被絕對座標與數值參數所困。透過聯合設計，aDSL 提供語義結構、可組合性與空間關係運算子，而多代理系統則在計畫、執行與評論階段充分利用這些結構，形成相互強化的閉環。

**Q4：aDSL 的設計圍繞哪三個互補面向？它們如何對應 LLM 的推理強度？**

A：aDSL 圍繞表達力、可組合性與空間推理三個互補面向設計。表達力讓語言能夠捕捉多樣的形狀與結構；可組合性支援模組化組裝與階層式重用，使代理能專注於高階結構而非重造低階細節；空間推理則提供關係運算子，讓代理以「將 A 放在 B 上方」這類語義關係取代易碎的絕對座標。這三者共同對應 LLM 擅長的語義結構與空間關係推理，同時迴避其數值精確度較弱的弱點。

**Q5：多代理系統的 Plan–Execute–Critic 迴圈如何運作？各代理角色負責什麼？**

A：系統採用無需訓練的角色專業化多代理架構，將長期創作任務分解為可組合的階層子任務，例如從場景到物件再到零件。在計畫階段，代理將使用者請求拆解為結構化步驟；在執行階段，代理合成 aDSL 程式並執行以取得幾何結果；在評論階段，代理根據執行回饋檢查錯誤與約束違反，並驅動迭代修復。這種迴圈讓系統能夠在不重新訓練模型的情況下，持續改進生成結果的穩健性與意圖忠實度。

**Q6：aDSL 為何強調關係運算子而非絕對座標？這對幾何穩健性有何幫助？**

A：絕對座標要求代理精確決定每個零件的數值位置，這正是 LLM 容易出錯的地方，微小的數值偏差就可能造成浮動椅腳或錯位接合。aDSL 透過關係運算子讓代理以語義空間關係來描述配置，例如「椅腳位於座椅下方並接觸四個角落」，由語言執行層自動解析為幾何約束。這不僅降低了代理的認知負擔，也讓局部修改與迭代修復更容易維持整體結構一致性。

**Q7：實驗在哪些任務上進行？與哪些基線方法比較？主要結果為何？**

A：論文在文字生成形狀（text-to-shape）與影像生成形狀（image-to-shape）任務上評估所提方法，並與近期基於 LLM 的基線方法進行比較。結果顯示，aDSL 與多代理系統的協同設計在穩健性、可控性與對使用者意圖的忠實度上均優於這些基線。更重要的是，該方法在提升生成品質的同時，仍保留了程式化表示所具備的顯式結構、可編輯性與可解釋性。

**Q8：有哪些實驗證據支持「協同設計」優於單獨改進語言或代理？**

A：論文透過對比與設計分析指出：當計畫、程式碼合成與評論共享同一套 aDSL 表示時，代理能更準確地將高階意圖轉譯為結構化程式，並在迭代修復中一致地檢查與修正約束違反。這種共享表示消除了傳統流程中不同階段使用不同抽象層次所造成的語義落差。實驗顯示，該設計顯著改善了意圖忠實度與約束滿足程度，證明語言與代理系統必須同步設計才能發揮最大效益。

**Q9：相較於擴散模型等學習式三維生成方法，aDSL 在結構保留與後續編輯方面有何優勢？**

A：擴散模型通常將形狀編碼為隱式表示，雖然能產生高擬真結果，但難以提供顯式結構與可解釋的參數控制。aDSL 採用程式化表示，使每個零件、關係與約束都清楚可見，使用者可以直接修改程式來進行細粒度編輯。此外，由於結構與語義關係被顯式編碼，生成結果更易於重複使用、組合與驗證，這對於需要精確控制的設計與模擬應用尤為重要。

**Q10：論文展示了哪些下游應用？aDSL 如何支撐這些應用？**

A：論文展示了結構化場景組合、關節式物體創建與結構化形狀編輯等下游應用。aDSL 的可組合性讓場景能夠以階層方式由物件與零件組裝而成，而空間關係運算子則確保各物件之間的相對配置符合語義約束。對於關節式物體，aDSL 能夠顯式編碼零件之間的連接與運動關係，從而支援可動結構的生成與後續操控。

**Q11：若將 aDSL 整合到實際的內容創作工具中，有哪些產品層面的考量與優勢？**

A：由於系統無需訓練，僅依靠現成的大型語言模型與執行回饋即可運作，因此整合門檻較低，無需蒐集大規模三維資料集或重新訓練擴散模型。其程式化輸出可直接嵌入現有的建模、動畫與遊戲引擎管線，設計師能透過自然語言或圖像輸入快速產生可編輯的初稿。此外，迭代式的 Plan–Execute–Critic 迴圈適合互動式創作，讓使用者在每個階段檢視結構、提出修改並獲得即時修正。

**Q12：這項研究對三維生成、電腦圖學與具身人工智慧等領域可能帶來什麼影響？**

A：aDSL 將代理式工作流程與程式化表示結合，為三維生成提供了一條兼具語義控制與幾何精確度的新路徑，補充了以擴散模型為主的隱式生成典範。在電腦圖學中，這種顯式結構化的輸出有利於動畫、物理模擬與可重複使用的資產管線。對於具身人工智慧，結構化且可解釋的三維場景表示能夠支援機器人推理、導航與物件操作，因為語義關係與幾何約束都被明確編碼。

**Q13：作者可能承認哪些限制？這些限制對方法的適用範圍有何影響？**

A：雖然論文未詳盡列出所有限制，但從設計選擇可推知：aDSL 的表達範圍受限于其內建的原語與關係運算子，對於高度自由或有機形狀可能不如專業雕刻或擴散模型靈活。此外，迭代修復的效果取決於執行回饋的品質與 LLM 對錯誤診斷的能力，若回饋過於隱晦或錯誤根源超出語言描述範圍，修復可能收斂緩慢。這些因素意味著該方法在結構化、零件可分解的物件與場景上表現最佳，而對極端複雜或風格化的形狀可能需要額外擴展。

**Q14：典型的失敗案例可能出現在哪些情境？系統如何處理或可能無法處理？**

A：典型失敗案例包括使用者意圖過於模糊、目標物件類別罕見或超出 aDSL 原語覆蓋範圍，以及多個設計約束相互衝突而無法同時滿足。在這些情況下，代理可能產生語法正確但語義不符的程式，或在多次迭代後仍無法消除所有約束違反。雖然 Plan–Execute–Critic 迴圈能透過執行回饋修正許多局部錯誤，但若錯誤源於高階語義誤解或原語不足，則需要使用者介入或擴充語言原語才能解決。

**Q15：未來研究可以朝哪些方向延伸 aDSL 與代理式三維創作？**

A：未來可擴充 aDSL 的原語庫以涵蓋更豐富的材質、紋理、變形與有機形狀，並結合學習式模組來輔助代理提出更合理的初始佈局。另一方向是將 aDSL 與擴散模型或神經表示融合，讓程式化結構負責高階語義與約束，而學習式模型補充細節與真實感。此外，支援多模態輸入、即時協同編輯，以及將代理系統延伸至具身智慧體的場景理解與操作規劃，都是具有潛力的發展路徑。

## 實務應用指南

### 適用場景

**1. 遊戲與影視前期視覺開發**
aDSL 適合需要快速將文字分鏡或概念草圖轉為可編輯 3D 原型的團隊。由於輸出是結構化的程式化表示法，美術人員可在代理生成後直接調整參數、替換元件或修改空間關係，縮短從發想到可迭代資產的週期。

**2. AR/VR 與元宇宙內容生產**
對於需要大量模組化物件與場景組合的虛擬空間，aDSL 的可組合性與關係運算子能協助生成具一致結構的資產。例如生成「擺在圓桌上的四張椅子」時，系統可透過相對關係維持幾何約束，減少人工對齊與碰撞修復。

**3. 具身人工智慧與機器人模擬場景**
具身 AI 研究常需構建帶有語義結構與物理合理性的室內場景。aDSL 的顯式結構與空間推理能力，使其適合生成可解析、可程式化操控的模擬環境，並支援後續加入關節式物體以進行操作任務。

**4. 產品設計與參數化造型探索**
在工業設計早期，設計師可利用文字或圖像驅動 aDSL 快速產生多種結構方案。由於每個形狀皆保留參數與約束，團隊能進行細粒度編輯與設計空間探索，再銜接至傳統 CAD 流程進行工程細化。

**5. 程式化建模教育與互動創作工具**
aDSL 可作為教學媒介，幫助學生理解幾何、結構與程式之間的對應關係。同時，其訓練-free 的多代理系統也適合嵌入互動式創作應用，讓使用者透過自然語言逐步精煉 3D 內容。

### 實作前置條件

**資料需求**
aDSL 方法本身為無需訓練，因此不需要大規模 3D 資料集。但實務上仍需準備：領域相關的基元元件庫、可重用的形狀模板、以及少量高品質的 aDSL 程式範例，作為多代理系統在規劃與程式碼合成時的上下文學習素材。

**運算資源**
主要成本來自大型語言模型 API 呼叫與幾何執行回饋迴圈。建議具備穩定的 LLM 服務存取權限，以及可執行 aDSL 並進行約束檢查的幾何核心。對於中小型場景，一般雲端運算實例已足夠；若需高頻互動，則應評估快取與並行策略。

**技能需求**
團隊需熟悉 Python 與基礎 3D 幾何概念，並具備設計領域特定語言與 LLM 提示工程的能力。若涉及下游應用，還需有人員了解目標平台格式，如 USD、Blender、遊戲引擎或參數化 CAD 系統。

### 實作步驟建議

**步驟一：部署 aDSL 執行環境**
從論文開源程式碼出發，建置 aDSL 解析器、幾何執行器與視覺化工具。確認關係運算子與絕對座標轉換機制運作正常，並建立錯誤回報機制，讓代理能讀取執行結果。

**步驟二：定義領域本體與元件庫**
根據目標應用梳理常見物件類別、部件與空間關係。將高頻元件封裝為可重用的 aDSL 模組，例如桌椅的腿、座面、靠背等，並為每個模組設計穩定的介面與預設參數。

**步驟三：設計角色專業化多代理系統**
實作 Plan-Execute-Critic 三個角色：規劃代理負責將使用者意圖分解為階層式子任務；執行代理負責合成 aDSL 程式碼；評論者代理則檢查語法、幾何約束與語義一致性。為每個角色撰寫專用提示詞，並明確定義其輸入輸出格式。

**步驟四：建立執行回饋與迭代修復迴圈**
將 aDSL 執行後的幾何狀態、約束違反資訊與錯誤訊息回傳給評論者代理。設計修復策略，例如浮動部件自動貼合、碰撞檢測後的相對位置調整，並限制迭代次數以控制成本。

**步驟五：整合多模態輸入與使用者介面**
支援文字生成形狀與影像生成形狀兩種模式。對於影像輸入，可結合視覺模型萃取結構描述後再交由 aDSL 代理處理。前端介面應讓使用者能檢視程式、修改參數並重新生成。

**步驟六：銜接下游製作管線**
將 aDSL 輸出轉換為目標格式，如匯入 Blender、遊戲引擎或 CAD 系統。建立版本控制流程，使程式化表示法可納入資產管理與協作審查。

### 潛在風險與注意事項

**數值推理仍有限制**
儘管 aDSL 透過關係運算子降低對絕對座標的依賴，但某些精確尺寸或對稱比例仍可能需要人工介入。建議在 DSL 中提供更高階的約束語法，並在關鍵步驟保留設計師覆寫權限。

**幾何約束檢查的完備性**
自動約束檢查可能無法涵蓋所有領域規則，例如風格一致性或製造可行性。應將領域知識編碼為可擴充的檢查規則，並讓評論者代理能依據不同應用切換檢查策略。

**複雜場景的組合爆炸**
當場景層級過深或物件數量過多時，Plan-Execute-Critic 迴圈的推理與修復成本會顯著上升。建議採用分層生成與區域化規劃，先產生骨架再逐步細化局部。

**執行回饋延遲與成本**
每次迭代都涉及 LLM 呼叫與幾何執行，可能導致回應時間過長。可透過快取常見修復模式、使用較小模型處理簡單錯誤，以及非同步執行來改善使用者體驗。

**智慧財產權與內容安全**
由於系統依賴 LLM 生成程式碼，需留意訓練資料帶來的潛在版權風險，以及生成內容的審查機制。建議在產品中建立內容過濾、來源追蹤與人工審核流程。

### 與其他技術的整合建議

**與擴散模型互補**
aDSL 負責結構與可編輯性，擴散模型則可補強紋理、材質與高頻幾何細節。兩者結合可兼顧程式化表示的可控性與生成模型的視覺豐富度。

**與 USD、Blender 及遊戲引擎整合**
將 aDSL 輸出轉譯為 USD 場景描述或 Blender Python 指令碼，可無縫銜接現有 3D 製作管線。對於遊戲引擎，可進一步匯出帶有語義標註的 Prefab 或 Blueprint。

**與參數化 CAD 系統銜接**
aDSL 可作為 CAD 前段的概念設計層，先快速生成結構方案，再轉換為參數化 CAD 程式碼進行工程約束與製造分析。

**與版本控制系統整合**
由於輸出為文字形式的程式碼，aDSL 天然適合 Git 管理。可實作 diff、merge 與程式碼審查流程，提升團隊協作與資產可追溯性。

**與多模態大型語言模型結合**
利用視覺語言模型處理影像輸入，萃取結構與風格描述後再餵入 aDSL 代理系統，可強化影像生成形狀任務的語義理解與對齊能力。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先從論文的動機與圖例開始，理解「為何要用程式化表示法做 3D 創作」以及「絕對座標為何容易出錯」。接著觀察 aDSL 的語法範例，體會關係運算子如何讓程式更像人類的空間描述，最後再瀏覽多代理系統的整體流程即可，不必一開始就深入每個模組的實作細節。

**給 AI 工程師**
請聚焦於 Plan-Execute-Critic 的架構設計、提示詞分工與執行回饋機制。特別留意作者如何將 DSL 結構轉化為代理可規劃、可驗證、可修復的單元，並思考如何在你的應用中設計類似的角色專業化與迭代修復迴圈。

**給研究人員**
本論文的核心貢獻在於「協同設計」觀點：語言設計與代理能力必須互相匹配。建議深入分析 aDSL 在可組合性、空間推理與幾何約束上的取捨，並評估這種設計原則能否推廣到其他需要結構化輸出的生成領域，如機器人任務規劃或建築設計。

**給產品經理**
請將重點放在適用場景、可控性與可編輯性的商業價值上。aDSL 的優勢不在於一次性生成最終成品，而在於建立可迭代、可審查、可銜接製作管線的 3D 內容工作流。評估時請同時考量 LLM 呼叫成本、生成延遲與目標使用者對程式化介面的接受度。
