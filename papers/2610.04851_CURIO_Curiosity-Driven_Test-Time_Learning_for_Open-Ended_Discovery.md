# CURIO：好奇心驅動的測試時學習以實現開放式發現

**原文標題：** CURIO: Curiosity-Driven Test-Time Learning for Open-Ended Discovery

**發布日期：** 2026-10-04

## ⚡ TL;DR

開放式發現中，凍結LLM無法從測試經驗學習，純強化學習則可能過早壓抑低獎勵方向。
CURIO利用內在好奇心世界模型學習隱藏狀態轉移，對非top-k詞元施加預測誤差獎勵。
在六項數學發現與單細胞去噪任務上，於Qwen3 8B至235B皆優於任務強化學習基準，最高相對增益18.3%。

## 摘要翻譯

開放式發現需要在反覆嘗試中學習，同時持續探索其價值尚未顯現的方向。使用凍結的大型語言模型 (LLM) 進行搜尋可以在上下文中重複使用先前的解法，但無法根據其在測試問題上的成功與失敗來更新模型。強化學習 (RL) 能實現這種適應；然而，強烈偏好高獎勵軌跡可能會過早抑制低獎勵但極具潛力的方向。我們提出 CURIO，一個好奇心驅動的測試時學習框架，透過內在好奇心世界模型 (ICWM) 來補充任務回饋。ICWM 在策略的隱藏狀態表示中學習狀態轉移，並在策略 Top-k 選擇之外的採樣詞元上提供預測誤差獎勵。Epoch 正規化與退火權重調節其對策略更新的貢獻。在六個數學發現任務與單細胞去噪上，使用 8B 至 235B 的 Qwen3 骨幹模型，三次執行平均值在五個數學目標上優於匹配的純任務 RL 控制，在圓填充 (Circle Packing) 上達到最佳已報導表現，並在每個測試規模下皆改善兩個保留測試語料庫上的去噪分數 (Score) 與均方誤差 (MSE)。相對增益在 Hadamard（哈達瑪）上達到 18.3%，在去噪分數上達到 10.8%。程式碼多樣性測量顯示生成的程式之間存在更大的結構變異，支持好奇心作為開放式發現中學習的補充探索信號。

### 核心貢獻（3～5點）
- **提出 CURIO 框架**：首個將好奇心驅動的內在動機與測試時強化學習相結合的系統，用於開放式發現任務，解決了純任務獎勵導致過早抑制低獎勵潛力方向的問題。
- **設計內在好奇心世界模型 (ICWM)**：在策略的隱藏狀態表示中學習狀態轉移，並透過預測誤差獎勵為策略 Top-k 選擇之外的採樣詞元提供探索信號，補充任務回饋。
- **引入 Epoch 正規化與退火權重機制**：有效調節好奇心獎勵對策略更新的貢獻，避免探索信號過強或過弱，平衡探索與利用。
- **跨規模實驗驗證**：在六個數學發現任務（含 Circle Packing、Hadamard、Erdős 等）與單細胞去噪任務上，使用 8B 至 235B 的 Qwen3 骨幹模型進行測試，於五個數學目標上超越純任務 RL 控制，並在去噪分數與 MSE 上全面改善，相對增益最高達 18.3%。
- **程式碼多樣性分析**：實證好奇心機制促使生成的程式呈現更大的結構變異，證明好奇心作為開放式發現中補充探索信號的有效性。

### 適合對象
本論文最適合以下讀者閱讀：從事強化學習、大型語言模型、開放式發現或自動研究 (Auto-Research) 的研究人員與工程師；對好奇心驅動探索、內在動機機制設計感興趣的機器學習學者；以及希望將測試時學習應用於數學構造、演算法發現或單細胞生物資訊學等領域的跨學科研究者。亦適合關注 AI 研究與開發 (AI R&D) 自動化、程式碼生成與科學發現前沿進展的業界從業者作為參考。

## 深度分析

#### 方法論解析

CURIO 的核心設計在於解決一個根本性的探索-利用張力（exploration-exploitation tension）：當測試時強化學習（test-time RL）過度強化高獎勵軌跡時，可能過早抑制（premature suppression）當前獎勵低但具有潛力的方向。論文提出的解法是將任務回饋（task feedback）與一個學習式的內在好奇心信號相結合。

**整體架構**：CURIO 嵌入在 RL 發現迴圈中，包含三個關鍵組件：

1. **提案策略（proposing policy）π_θ**：從存檔庫（archive）中的父代解 p 與問題描述 d 構造提示詞 x = x(p, d)，生成包含程式碼與可選推理的完成 y。

2. **內在好奇心世界模型（Intrinsic Curiosity World Model, ICWM）**：這是 CURIO 的核心創新。ICWM 在策略的隱藏狀態表示（hidden-state representation）中學習 token 層級的轉移（transitions），其輸入包含編碼後的策略隱藏狀態特徵 s_t、s_{t+1} 以及取樣 token 的嵌入（embedding）a_t。ICWM 的預測殘差（prediction residual）即為好奇心獎勵的來源。

3. **任務評估器（evaluator）**：決定候選解的品質，提供標量訓練獎勵 R(x, y)。

**關鍵設計選擇**：

- **選擇性應用（selective application）**：好奇心獎勵僅在取樣 token 落在策略 top-k 選擇之外時才被保留。這避免了對每個 token 都施加好奇心信號而分散任務進展的注意力。直觀上，若策略已經高度自信地選擇某 token，則該處的「驚奇」並非真正的探索需求；反之，當策略選擇了非 top-k 的 token 時，預測誤差更能反映有意義的探索。

- **Epoch 正規化（epoch normalization）**：在每個 epoch 內對好奇心獎勵進行正規化，使其與任務獎勵的尺度匹配，避免單一極端值主導策略更新。

- **退火權重（annealed weight）**：隨訓練進度調整好奇心獎勵的相對貢獻，允許早期更強的探索激勵，後期逐漸讓位於任務驅動的精煉。

**目標函數**：基於 Yuksekgonul 等人的發現導向目標（discovery-oriented objective），CURIO 使用指數獎勵加權：

$$J_\beta(\theta; x) = \log \mathbb{E}_{y \sim \pi_\theta(\cdot|x)}[e^{\beta R(x,y)}], \quad \beta > 0$$

其中好奇心獎勵以加法形式與任務係數 β 結合，形成組合係數 β(π + ε)，其中 ε 為退火的好奇心貢獻。

**理論意涵**：ICWM 建模的是策略表示動力學（representation dynamics），而非語義新穎性本身。論文明確指出，高預測誤差並不自動意味著語義新穎或未來任務改進——這是一個重要的認識論謹慎（epistemic caution），避免了將好奇心模組過度神話化的傾向。

#### 實驗數據解讀

**實驗設置的廣度與深度**：

論文在兩個截然不同的領域評估 CURIO，展現了方法的通用性：

1. **數學發現任務（六項）**：包括 Erdős、圓填充（Circle Packing）、Hadamard 等開放式數學構造問題。這些任務的特點是沒有單一正確答案，目標是在預算內找到最優可行解。

2. **單細胞去噪（single-cell denoising）**：在保留測試的 PBMC 和 Tabula 語料庫上進行，使用 Score 和均方誤差（MSE）作為指標。

3. **模型規模跨度**：Qwen3 骨幹模型（backbone）從 8B 到 235B，涵蓋了兩個數量級的參數規模。

**關鍵結果**：

- **五次數學目標的改進**：三次執行平均值（three-run means）在五個數學目標上優於匹配的純任務 RL 對照組，顯示好奇心信號的穩定增益。

- **圓填充的匹配表現**：在 Circle Packing 上匹配最佳報告性能，雖然未超越，但考慮到該任務已有大量先前工作，這是一個有意義的結果。

- **去噪任務的全規模改進**：在 PBMC 和 Tabula 兩個語料庫上，Score 和 MSE 在每個測試規模上都獲得改進，顯示方法在不同領域的一致性。

- **相對增益的規模**：Hadamard（235B）達到 18.3%，Tabula Score（8B）達到 10.8%。值得注意的是，最大增益出現在最大模型（235B）上，這暗示好奇心信號在更大模型中可能更具價值。

**程式碼多樣性分析**：

圖 1 和圖 3 顯示 CURIO 在 Erdős 和 Circle Packing 的所有訓練階段（Early、Mid、Late、Final）都展現出比 TTT-Discover 更高的程式碼結構變異（structural variation）。這是一個重要的診斷指標——它表明好奇心信號確實促使策略探索更多樣的程式結構，而非僅僅在現有解附近進行微調。

**消融實驗（ablations）**：

論文檢驗了三個維度：
- 好奇心強度（curiosity strength）
- 預測器架構（predictor architecture）
- 表示耦合（representation coupling）

這些消融有助於理解各組件的相對貢獻，但具體數值需參照附錄。

**結果的邊界與詮釋**：

論文坦誠地指出，程式碼多樣性和預測誤差「仍與語義新穎性不同」（remain distinct from semantic novelty）。這是一個重要的方法論聲明——多樣性是手段而非終點，最終的任務指標才是驗證標準。

#### 與現有研究的比較

**定位於三大研究脈絡**：

1. **基於搜尋的自動研究方法**（如 Novikov 等人、Lange 等人、Ye 等人）：這些方法重複從凍結 LLM 取樣，通過提示詞、存檔庫和族群（populations）組織先前嘗試。CURIO 的優勢在於能夠更新模型參數，從測試問題的成功與失敗中學習，而搜尋方法僅能改善上下文供應。

2. **基於 RL 的發現方法**（如 Wang 等人、Yuksekgonul 等人）：這些方法將發現轉化為測試時 RL，更新提案策略。CURIO 在此基礎上補充了好奇心信號，解決了純獎勵驅動更新可能過早收斂的問題。

3. **內在動機（intrinsic motivation）研究傳統**：ICWM 的設計與 Pathak 等人的好奇心驅動探索一脈相承，但 CURIO 將其應用於 LLM 的隱藏狀態空間而非環境狀態，並加入了 top-k 選擇性機制，這是針對語言模型生成過程的特殊設計。

**相對於 TTT-Discover 的改進**：

TTT-Discover（Yuksekgonul 等人）是直接的純任務 RL 基線。CURIO 的改進在於：
- 保留了任務驅動的利用（exploitation）
- 同時維持了對未充分探索方向的激勵
- 通過選擇性應用避免了好奇心信號的干擾效應

**限制與未解決問題**：

- **語義新穎性的測量**：論文承認程式碼多樣性和預測誤差不等於語義新穎性。未來需要更嚴格的多樣性指標。
- **計算成本**：ICWM 的引入增加了每步的計算開銷，雖然未在論文中量化，但對於 235B 模型而言，這是實際部署的考量。
- **任務泛化邊界**：雖然涵蓋了數學和生物學任務，但對於需要長期規劃或多步推理的開放式任務（如完整定理證明），效果尚待驗證。
- **ICWM 的訓練穩定性**：作為一個學習組件，ICWM 本身的訓練動態可能影響整體穩定性，論文中未深入討論。

#### 可重現性評估

**正面因素**：

- **明確的基線對照**：使用匹配的純任務 RL 控制（matched task-only RL control），確保比較的公平性。
- **多次執行報告**：三次執行平均值提供了統計穩健性的基本保障。
- **模型規模透明**：明確報告 Qwen3 從 8B 到 235B 的所有測試規模。
- **任務描述具體**：六個數學發現任務和兩個去噪語料庫均有明確指定。

**可重現性疑慮**：

- **超參數設置**：退火權重的具體調度（schedule）、epoch 正規化的具體方式、top-k 的 k 值等關鍵超參數未在提供的文本中明確。
- **隨機種子**：未提及是否控制了隨機種子以確保三次執行的可重現性。

#### 未來研究方向

**直接延伸**：

1. **好奇心信號的理論分析**：目前 ICWM 的設計是啟發式的，未來可探索預測誤差與語義新穎性之間的理論聯繫，建立好奇心信號的收斂性保證。

2. **更精緻的選擇性機制**：目前的 top-k 選擇是二元決策，未來可考慮連續的「驚奇度」權重，或基於不確定性估計（如 ensemble disagreement）的更細粒度選擇。

3. **多任務 ICWM**：當前 ICWM 為每個測試問題單獨訓練，未來可探索跨問題共享的 ICWM，利用不同發現任務的共同結構。

**跨領域應用**：

4. **程式碼生成與軟體工程**：將 CURIO 應用於更複雜的程式合成任務，如競賽程式設計或自動化程式修復，其中探索多樣解策略尤為重要。

5. **科學假說生成**：在材料設計、藥物發現等領域，開放式發現的框架可直接應用，好奇心信號可能有助於跳出局部最優。

6. **多代理協作發現**：將 CURIO 擴展到多個提案策略的場景，其中不同代理的 ICWM 可提供互補的探索信號。

**方法論深化**：

7. **好奇心與任務獎勵的動態平衡**：目前的退火權重是手動調度的，未來可探索自適應調度，根據策略的收斂狀態自動調整好奇心貢獻。

8. **表示空間的選擇**：目前使用策略的隱藏狀態，未來可探索專門為好奇心預測訓練的表示空間，或對比學習式的表示。

9. **因果分析**：論文坦承程式碼多樣性不等於因果機制。未來可設計實驗直接測量好奇心信號對特定探索行為的因果效應。

10. **效率優化**：對於 235B 模型，ICWM 的額外計算成本值得量化。未來可探索蒸餾或稀疏化技術，在保持探索效益的同時降低開銷。

**長期願景**：

11. **與人類發現過程的對齊**：人類科學家在探索中結合好奇心與任務導向，CURIO 的框架可進一步融入人類反饋（如對「有趣性」的判斷），實現更自然的人機協作發現。

12. **安全與可解釋性**：當 LLM 自主進行開放式發現時，好奇心信號的行為需要可解釋。未來可發展視覺化工具，展示 ICWM 認為「驚奇」的具體轉移，這對於在高風險領域（如藥物設計）部署至關重要。

## 論文問答

**Q1：開放式發現（Open-Ended Discovery）的核心挑戰是什麼？為何需要新的學習方法？**
A：開放式發現的核心挑戰在於其目標並非找出一個預先定義的單一答案，而是要在有限預算內持續尋找「漸進式更佳」的解。這類問題橫跨數學構造（如 Erdős 圓填充、Hadamard 矩陣）與 AI 研究開發任務，必須同時兼顧「利用」已知成功路徑與「探索」當前獎勵低但潛力未明的方向。傳統的監督式或單次推理方法無法在測試階段持續累積經驗，因此需要能在測試時動態學習的機制。CURIO 正是為了解決這個「探索—利用」張力而設計的框架。

**Q2：為何基於凍結 LLM 的搜尋式方法（frozen-LLM search）不足以解決此問題？**
A：凍結 LLM 的搜尋方法雖然能透過提示詞、存檔庫（archive）與族群（population）等機制，把過去嘗試的成果整理進上下文供模型參考，但模型的參數本身無法從測試問題的成功與失敗中學習。這意味著每次抽樣都是「無狀態」的，模型無法內化在當前問題上發現的有用模式。當問題需要多輪精煉（refinement）時，這種限制會嚴重拖慢收斂速度，也無法針對特定問題結構形成專門的策略。

**Q3：純粹的測試時強化學習（test-time RL）為何會過早抑制有潛力的方向？**
A：測試時強化學習雖然能讓提案策略（proposing policy）從評估器回饋中更新參數，但當目標函數（如指數加權獎勵 Jβ）使用較大的 β 時，會強烈傾向高獎勵軌跡，使策略快速集中於目前看起來成功的構造。然而，當前低獎勵的方向未必真的無價值，可能只是尚未被充分探索或精煉；過早壓縮策略分布會讓這些方向失去未來的抽樣機會。這正是 CURIO 試圖以「好奇心」信號緩解的核心問題。

**Q4：CURIO 的核心創新——內在好奇心世界模型（ICWM）是如何運作的？**
A：ICWM 學習的是策略隱藏狀態（hidden-state representation）之間的 token 級轉移，並以抽樣 token 的嵌入（embedding）作為動作輸入。它會預測下一個隱藏狀態，並將預測殘差（prediction residual）作為「驚奇程度」的代理指標。這個設計的關鍵在於：表面上看起來差異很大的長程式碼序列，未必代表不同的解決策略；而隱藏狀態空間更能反映策略內部的語義動態，因此是衡量「可預測性」更合適的層級。

**Q5：為什麼 CURIO 只在抽樣 token 落在策略 top-k 選擇「之外」時才給予好奇心獎勵？**
A：這個選擇性規則的設計動機是避免干擾任務進展。若對每個 token 都施加好奇心獎勵，模型會被「驚奇」本身分散注意力，反而妨礙它完成高品質的候選解。只有當抽樣 token 並非策略最可能的前 k 個選擇時，才代表模型正在「偏離熟悉路徑」，此時好奇心獎勵才有探索價值。這樣的遮罩機制讓好奇心信號成為任務驅動更新的補充，而非喧賓奪主。

**Q6：Epoch 正規化（epoch normalization）與退火權重（annealed weight）在 CURIO 中扮演什麼角色？**
A：Epoch 正規化會在每個訓練週期內對預測誤差獎勵進行統計縮放，避免好奇心信號的尺度隨訓練進程漂移而失控；這保證了它與任務獎勵能在可比擬的範圍內相加。退火權重則隨時間逐步降低好奇心的相對貢獻，使早期鼓勵探索、晚期回歸利用，符合「先廣後深」的發現節奏。兩者結合讓 ICWM 的內在信號既能引導探索，又不會在後期壓過任務評估器的判斷。

**Q7：CURIO 採用了哪些基準任務？為何選擇這些任務？**
A：實驗涵蓋六個數學發現任務（包括 Erdős 圓填充、Hadamard 矩陣等）以及單細胞去噪（single-cell denoising）任務，並使用 Qwen3 從 8B 到 235B 的不同規模骨幹模型。數學任務代表封閉式、可由評估器精確評分的開放式構造問題，而單細胞去噪則擴展到保留測試語料庫（held-out corpora）上的實際科學資料。這樣的組合既驗證了演算法在「合成式發現」上的能力，也檢驗了它在真實生物資料上的泛用性。

**Q8：CURIO 的關鍵量化結果為何？**
A：在三次執行的平均值下，CURIO 在六個數學目標中的五個上優於匹配的純任務 RL 對照組，並在 Circle Packing 上與最佳已報導表現持平；單細胞去噪在兩個保留語料庫的所有測試規模上，分數（Score）與均方誤差（MSE）皆有所改善。相對增益最高達 235B 規模 Hadamard 上的 18.3%，以及 8B 規模 Tabula 分數上的 10.8%。此外，程式碼多樣性（code diversity）測量顯示 CURIO 在所有訓練階段都產生更高的結構變異，支持好奇心作為探索補充信號的論點。

**Q9：消融實驗（ablation）揭示了哪些關於好奇心強度、預測器架構與表示耦合的洞見？**
A：消融實驗分別檢驗了好奇心強度的影響、ICWM 預測器的架構選擇，以及其與策略隱藏狀態的耦合方式。這些實驗共同說明：好奇心並非「越多越好」，而是需要精細調節；ICWM 的有效性依賴於它學習的是策略自身的表示，而非外部特徵；表示耦合的鬆緊會直接影響預測誤差是否反映語義新奇，而非表面雜訊。這些結果為未來設計類似內在動機機制提供了具體的工程指引。

**Q10：CURIO 適合哪些實際應用場景？**
A：凡是需要在測試階段持續精煉解的場景都適合 CURIO，包括自動數學研究（如尋找新構造或反例）、演算法發現（algorithm discovery）、科學實驗設計最佳化，以及生物資訊中的單細胞資料處理等。在這些場景中，評估器可程式化地給出品質分數，但單次抽樣難以達到最佳解，需要多輪迭代。CURIO 的測試時學習能力讓模型能在特定問題上累積專門經驗，而無需重新訓練或微調骨幹模型。

**Q11：將 CURIO 應用於實際產品時，需要考慮哪些工程與成本因素？**
A：產品化 CURIO 必須考慮 ICWM 帶來的額外計算與記憶體開銷，因為它需要在策略更新的同時訓練一個世界模型；模型規模從 8B 到 235B 的實驗顯示，這種開銷會隨規模放大。此外，評估器的可靠性是關鍵前提——若評估器本身有雜訊或偏誤，好奇心信號可能放大錯誤方向。部署時還需設計合適的 epoch 數、退火時程與 top-k 參數，使其適配不同任務的探索需求。

**Q12：CURIO 對「AI for Science」與自動研究領域的更廣泛影響是什麼？**
A：CURIO 展示了在測試階段結合任務回饋與學習式探索信號的可行性，為「AI 參與科學發現」提供了一條新路徑。它挑戰了「凍結 LLM + 精巧提示」的主流範式，證明讓模型在測試時學習是值得的投入。這種思路若被廣泛採用，可能促使更多自動化研究系統從「搜尋式」轉向「學習式」，並催生專門針對開放式發現設計的基準與競賽，推動整個領域走向更自主的科學助理。

**Q13：CURIO 論文本身承認了哪些限制？**
A：作者明確指出，程式碼多樣性與預測誤差並不等於語義新奇（semantic novelty），因此圖 1 的多樣性診斷並不能單獨證明語義層面的多樣性或因果機制。ICWM 學習的是策略表示的轉移可預測性，高預測誤差未必代表對任務有幫助的探索方向。此外，框架假設評估器能可靠給出獎勵，這在某些開放問題中未必成立。這些限制提醒讀者將結果詮釋為「互補探索信號的證據」，而非「好奇心萬能」的結論。

**Q14：CURIO 可能會在哪些情境下失效或表現不佳？**
A：當評估器獎勵極度稀疏或雜訊很大時，好奇心信號可能把策略推向與任務無關的「驚奇」區域，反而拖慢收斂。若問題的解空間高度結構化、且最佳解可由少數高獎勵軌跡直接定位，則額外的探索機制可能只是浪費預算。對於極短或極受限的輸出（例如固定格式的短答案），token 級的好奇心獎勵可能缺乏足夠的統計基礎，無法產生有意義的探索壓力。

**Q15：基於 CURIO 的未來研究方向有哪些？**
A：未來可探索的方向包括：將 ICWM 擴展到多模態或多代理設定，使其能在更複雜的環境中學習轉移；研究好奇心信號與語義新奇之間的更嚴格對應關係，以解決當前「預測誤差 ≠ 語義價值」的限制；以及把測試時學習與持續學習（continual learning）結合，讓模型在跨任務間累積可遷移的探索策略。此外，設計更高效的 ICWM 架構、降低其在 235B 等大規模模型上的計算成本，也是值得投入的工程方向。

## 實務應用指南

### 適用場景

1. **數學構造與組合最佳化研究**：在 Erdős 圓填充、Hadamard 矩陣等開放式數學問題上，自動搜尋比已知紀錄更優的構造。實驗室或數學競賽團隊可將 CURIO 部署於長時間運行的搜尋任務，自動產生並精煉候選程式碼。

2. **單細胞基因體學去噪**：針對 PBMC、Tabula 等保留測試語料庫的單細胞定序資料，使用 8B–235B 的 Qwen3 模型搭配 CURIO 框架產生去噪候選方案。相較單純任務獎勵的 RL 基準，可同時改善 Score 與 MSE 兩項指標。

3. **AI R&D 自動化研究流程**：在程式碼生成、模型架構搜尋、神經網路設計等任務中，部署 CURIO 作為「測試時學習代理」，讓 LLM 從自身成功與失敗中持續累積經驗，而非僅依賴凍結模型的上下文檢索。

4. **演算法發現與競賽式程式設計**：對於需要反覆嘗試、逐步逼近最佳解的演算法問題（例如 NP-hard 啟發式設計），CURIO 的好奇心獎勵可避免策略過早收斂至次優區域。

5. **企業內部基準測試與紅隊演練**：在需要持續探索未知輸入空間的安全性測試或基準建構任務中，利用好奇心信號維持生成樣本的多樣性，避免攻擊面或測試覆蓋率過早飽和。

### 實作前置條件

**資料需求**
- 目標任務的問題描述、評估器（evaluator）介面與獎勵函數定義
- 候選解的存檔庫（archive）結構與父代選樣策略
- 對於去噪類任務：已配對的雜訊／乾淨單細胞資料集作為保留測試語料庫

**運算資源**
- 至少一張可承載 Qwen3-8B 的 GPU（建議 ≥ 24 GB VRAM）；235B 等級需多機多卡或專用推論叢集
- 足夠的 CPU 記憶體以保存存檔庫與 rollout 軌跡
- 長時間（數小時至數天）連續運行的排程與監控機制

**技能門檻**
- 熟悉 PyTorch 與分散式訓練／推論管線
- 具備強化學習基礎（policy gradient、reward shaping）
- 了解 LLM 隱藏狀態擷取與 token-level 介入技術
- 能撰寫任務專屬的評估器與可行性檢查邏輯

---

### 實作步驟建議

1. **建立任務定義層**：依據 §2.1 設計問題描述 `d`、候選解空間、評估器 `R(x, y)`，並決定獎勵轉換規則（最大化或最小化目標的對應）。

2. **實作 RL 探索迴圈**：以 §2.2 的指數加權目標 `J_β` 為基礎，先建立任務專屬的 RL 基準（即 TTT-Discover 對照組），確認收斂行為與獎勵分佈。

3. **建構 ICWM**：設計一個輕量預測器，輸入為策略隱藏狀態特徵與採樣 token 嵌入，輸出下一狀態預測；以預測殘差作為好奇心原始信號。

4. **加入選擇性遮罩**：僅在採樣 token 落在策略 top-k 機率分布之外時保留好奇心獎勵，避免干擾高信心區域的任務學習。

5. **套用 Epoch 正規化與退火權重**：在每個 epoch 內對預測誤差做正規化，並以退火曲線控制好奇心對策略更新的相對貢獻，防止早期過度探索或晚期探索不足。

6. **整合存檔庫與父代取樣**：將 ICWM 獎勵併入策略梯度更新，維持「提案 → 評估 → 存檔 → 重新提案」的閉環，並定期記錄程式碼多樣性指標作為診斷。

7. **執行多規模消融實驗**：在 8B / 32B / 235B 等不同 Qwen3 骨幹上重複三次以上，比較 CURIO 與任務專屬 RL 基準的最終指標與程式碼結構多樣性。

8. **部署與監控**：將訓練完成的策略與 ICWM 打包為推論服務，提供 API 給下游應用；持續監控獎勵漂移、好奇心殘差分佈與存檔庫成長速率。

---

### 潛在風險與注意事項

- **好奇心不等於語意新穎性**：高預測誤差僅代表策略表示空間中的轉移難以預測，未必對應真正有價值的探索方向。應搭配語意層級的多樣性指標交叉檢視。
- **退火權重設定不當**：權重過高會稀釋任務獎勵導致收斂緩慢；過低則使好奇心信號失效。建議以網格搜尋搭配小規模驗證集調整。
- **top-k 遮罩的副作用**：若 top-k 設得過嚴，可能完全抑制好奇心信號；過寬則失去選擇性，使每個 token 都受到探索干擾。
- **隱藏狀態擷取成本**：在大型骨幹（235B）上存取中間層隱藏狀態會顯著增加記憶體與頻寬需求，需評估是否僅取特定層或使用蒸餾特徵。
- **評估器漏洞與獎勵 hacking**：好奇心信號可能放大評估器弱點造成的偽陽性高分；必須維持嚴格的可行性檢查與人工抽樣審核。
- **長時間運行的成本控管**：測試時 RL 會持續消耗推論與訓練算力，需設定預算上限與早停條件，避免無止境地追求微小增益。

---

### 與其他技術的整合建議

- **與 RAG / 存檔庫檢索整合**：CURIO 的存檔庫可作為檢索增強生成的來源，將過去成功軌跡注入新一輪提案的提示詞，兼顧記憶與學習。
- **與程式碼執行沙箱整合**：評估器應部署於隔離沙箱（Docker / Firecracker）中，避免惡意或錯誤程式碼影響主機；同時支援並行 rollout。
- **與分散式推論框架整合**：在 235B 等級骨幹上，建議結合 vLLM、SGLang 或 TensorRT-LLM 等高效推論引擎，並使用 ZeRO / FSDP 進行策略更新。
- **與 MLOps 平台整合**：將每次發現任務的指標、程式碼多樣性、好奇心殘差等記錄至 Weights & Biases 或 MLflow，便於跨任務比較與回歸分析。
- **與人類專家審核流程整合**：在數學構造或科學發現場景，保留「人類在迴圈中」節點，由領域專家定期檢視存檔庫中的最佳候選，避免完全自動化造成的可信度風險。

---

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀 §1 與 §2，理解「為何凍結 LLM 無法在測試問題上學習」以及「任務獎勵為何會過早抑制探索」這兩個核心動機；圖 1 的程式碼多樣性比較是直觀的切入點，無需深入數學即可掌握 CURIO 的價值主張。

**給 AI 工程師**：重點研讀 §3 的 ICWM 設計、top-k 遮罩規則、Epoch 正規化與退火權重機制，並對照 §2.2 的指數加權目標理解策略梯度的修改方式；實作時可先以 8B 模型在小型數學任務上重現結果，再逐步擴展規模。

**給研究者**：應關注 §3.2 中關於「隱藏狀態表示 vs. 表面程式碼差異」的討論，以及好奇心信號與語意新穎性之間的因果缺口；圖 3 提供的六項任務程式碼多樣性軌跡，以及消融實驗（好奇心強度、預測器架構、表示耦合）是延伸研究的重要起點。

**給產品經理**：聚焦於 §1 的應用範疇（數學發現、單細胞去噪、AI R&D）與相對增益數字（最高 18.3% Hadamard、10.8% 去噪 Score），理解 CURIO 在「需要持續探索且無單一正確答案」任務上的定位；同時留意「潛在風險」章節中關於成本與評估器可靠性的提醒，作為導入決策的參考。
