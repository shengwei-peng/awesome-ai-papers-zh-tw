## ⚡ TL;DR

現有自我改進程式代理僅依賴單一失敗軌跡，忽略存檔中豐富的比較訊號。
本文提出孟德爾哥德爾機器，透過反應規範突變與跨譜系雜交等受控遺傳機制進行自我修改。
理論與模擬證明其收斂更快更優，並在 SWE-bench 與 Polyglot 上顯著提升效能與泛化能力。

## 摘要翻譯

能反覆重寫自身原始碼（source code）的自我改進程式設計代理（self-improving coding agents），已在程式設計任務上展現優異效能。然而，現有方案通常每次僅依據單一失敗軌跡（failure trajectory）來產生自我修改（self-modification），忽略了代理不斷擴充存檔（expanding archive）中，過去嘗試（past attempts）所蘊含的豐富比較訊號（comparative signals）。依循孟德爾原理（Mendelian principles）所體現的受控遺傳（controlled inheritance）思想，我們提出孟德爾哥德爾機器（Mendel Gödel Machine, MGM）。除了一般的單一軌跡（single-trajectory）克隆突變（clonal mutation, Φ_CM）外，MGM 還引入兩種更能充分善用累積證據的新型自我修改：反應規範突變（reaction-norm mutation, Φ_RM）同時根據其在多個參考任務（reference tasks）上的軌跡（trajectory）來編輯該代理；跨譜系雜交（cross-lineage hybridization, Φ_CH）則利用來自另一譜系（lineage）的參考代理（reference agent）在目標任務（target task）上的軌跡來編輯代理。在加成適應度地形模型（additive fitness landscape model）下，我們從理論上證明，並透過受控代理模擬（controlled surrogate simulation）驗證，新策略相較於單一軌跡基線（single-trajectory baselines）能達到更快且更好的收斂。在 SWE-bench 與 Polyglot 上的實驗證實，MGM 在效能（performance）、效率（efficiency）與泛化能力（generalizability）方面均有穩定提升。

### 核心貢獻（3～5點）
- 提出孟德爾哥德爾機器（MGM），將比較式演化（Comparative Evolution）引入遞迴自我改進的程式設計代理，突破僅仰賴單一失敗軌跡的局限。
- 設計兩種新型自我修改機制：反應規範突變（Φ_RM）利用同一基因型在多個參考任務上的軌跡，跨譜系雜交（Φ_CH）利用不同譜系參考代理在目標任務上的軌跡，以充分運用存檔中的比較證據。
- 在加成適應度地形模型下進行理論分析，並透過受控代理模擬驗證，證明新策略相較於單一軌跡基線具有更快的收斂速度與更優的最終適應度。
- 在 SWE-bench 與 Polyglot 基準上進行實證，顯示 MGM 在效能、效率與泛化能力上均穩定提升。

### 適合對象
適合對自我改進 AI、自動化程式設計代理、遞迴自我修改系統、演化式演算法，以及大型語言模型（LLMs）應用於軟體工程感興趣的研究人員與工程師；特別是關注如何透過比較訊號與受控遺傳機制提升代理長期演化效能的讀者。

## 深度分析

#### 方法論解析

MGM 的核心貢獻在於把「自我修改（self-modification）」從單一失敗軌跡（single failure trajectory）的診斷，擴展成三種互補的孟德爾式（Mendelian）受控遺傳（controlled inheritance）運算子。整體框架延續 DGM（Zhang et al., 2026a）與 HGM（Wang et al., 2026）的存檔（archive）樹搜尋：存檔維護一棵譜系樹（lineage tree），每個節點儲存代理變體（agent variant）的原始碼作為基因型（genotype），以及其在各任務上的評估結果作為表現型（phenotype）。每一步透過 π-sampling 決定要執行評估（evaluation）或擴展（expansion），再透過 φ-evaluation 執行新任務並記錄軌跡（trajectory）。

在此基礎上，MGM 把擴展運算子 Φ 細分為三種：

1. **克隆突變（clonal mutation, Φ_CM）**  
   這是現有方法最常見的單一代理、單一任務、單一失敗軌跡修改。證據集合僅包含目標任務 τ_t 上的失敗軌跡：  
   E_CM(i, τ_t) = {(φ(a_i, τ_t), r(a_i, τ_t))}。  
   編輯器（editor）根據這次失敗診斷並修改 a_i。此運算子適用於資訊不足、無法形成可靠對比時，但容易把任務特定偶發事件（task-specific accidents）誤判為基因型層級缺陷（genotype-level defects）。

2. **反應規範突變（reaction-norm mutation, Φ_RM）**  
   靈感來自反應規範（reaction norm）概念：同一基因型（genotype）在不同環境（environment，此處即不同任務）下會呈現穩定的表現型輪廓（phenotype profile）。當代理 a_i 在多個參考任務（reference tasks, τ_r）上已有軌跡時，Φ_RM 同時檢視它在目標任務與參考任務上的成功／失敗模式，藉此區分「反覆出現的失敗模式（recurring failure modes）」與「單一任務的偶然失敗」。證據集合擴展為：  
   E_RM(i, τ_t, τ_r) = {(φ(a_i, τ), r(a_i, τ)) | τ ∈ {τ_t} ∪ τ_r}。  
   這種多任務對比能讓編輯器鎖定真正源於原始碼的缺陷，減少對單一軌跡的過度擬合。

3. **跨譜系雜交（cross-lineage hybridization, Φ_CH）**  
   當不同譜系（lineage）的代理曾嘗試過同一目標任務時，它們的軌跡構成可遷移的行為特徵（transferable behavioral traits）。Φ_CH 選取一個來自其他譜系的參考代理（reference agent, a_r），把其在相同任務上的軌跡作為對比證據（contrastive evidence），用來編輯當前代理：  
   E_CH(i, r, τ_t) = {(φ(a_i, τ_t), r(a_i, τ_t)), (φ(a_r, τ_t), r(a_r, τ_t))}。  
   這相當於孟德爾遺傳中的雜交實驗：透過比較不同基因型在相同環境下的表現型，把參考代理的成功策略遷移到目標代理，減少冗餘探索（redundant exploration）。

三種運算子都直接運用日常存檔評估中累積的軌跡，**不產生額外的任務評估成本**。為了嚴格分析它們的貢獻，作者提出一個**加成適應度地形模型（additive fitness landscape model）**：把每個代理表示為基因型空間中的二元向量，以與神諭基因型（oracle genotype）的漢明距離（Hamming distance）衡量改進進度。理論上證明 MGM 的期望收斂速度嚴格快於單一軌跡基線（single-trajectory baselines），並透過受控代理模擬（controlled surrogate simulation）加以驗證。

#### 實驗數據解讀

論文在兩個程式設計基準測試上驗證 MGM：**Polyglot** 與 **SWE-bench**。

**Polyglot 結果**（見圖 2）最具視覺衝擊力：  
- 以 Qwen3.6-35B-A3B 為骨幹，透過純粹演化代理腳手架（scaffold），準確率從 50.8% 提升至 **93.3%**。  
- 這不僅超越多個閉源大型模型（如 GPT-5 的 88.0%），而且參數量僅約為後者的 **1/117**。  
- 更進一步，把在 Qwen 上演化出的 scaffold 遷移到 DeepSeek-V4-Pro，準確率達到 **96.9%**，顯示 MGM 發現的是**可重複使用的工作流程層級（workflow-level）改進**，而非僅對特定骨幹模型過度擬合。

這些數據的意義可從三個層次解讀：

1. **效能（performance）**：MGM 讓相對輕量的開源模型在特定基準上逼近甚至超越頂尖閉源模型，說明自我改進的 scaffold 設計能彌補部分模型規模差距。  
2. **效率（efficiency）**：由於三種運算子都利用既有存檔軌跡，無需為每次修改重新執行額外任務，整體搜尋成本較單一軌跡方法更低。  
3. **泛化能力（generalizability）**：跨骨幹遷移（Qwen → DeepSeek）與跨基準表現（SWE-bench 亦有一致提升）顯示，反應規範與跨譜系證據能萃取出較通用的編碼策略。

**SWE-bench 結果**方面，摘要指出 MGM 在效能與效率上均優於基線。雖然提供的上下文未給出具體數字，但結合 Polyglot 的趨勢可推論：透過比較式證據（comparative evidence）進行的自我修改，能減少無效編輯次數，並在真實軟體工程任務上產生更穩定的修復。

需要謹慎的是，圖 2 中部分閉源模型參數量為估計值（Li, 2026），且 HGM* 標記係來自較小的 Polyglot-60 子集，與完整 Polyglot-2251 的分數並非完全可比。因此「超越 GPT-5」應理解為在 Polyglot 這一特定多語言程式設計基準上的 scaffold 優勢，而非全面性的模型能力超越。

#### 與現有研究的比較

MGM 的定位可從三條研究脈絡來看：

1. **哥德爾機器（Gödel Machine）與自我指涉修改（self-referential modification）**  
   Schmidhuber（2003; 2007）提出在可證明效益（provable benefit）下進行數學嚴謹的自我修改。MGM 並未在 LLM 設定中恢復形式化證明，而是採用「受控比較（controlled comparisons）」的孟德爾精神，把可測量效益（measurable benefit）透過存檔軌跡具體化。

2. **近期 LLM 編碼代理的自我改進實踐**  
   Yang et al.（2024）、Hu et al.（2025）、Gao et al.（2026）以及 Robeyns et al.（2025）展示代理能重構自身程式碼。這些工作多聚焦於「能否自我修改」，而 MGM 進一步問「**用什麼證據修改最有效**」。

3. **DGM / HGM 的存檔導向演化**  
   DGM 把自我改進視為開放式演化（open-ended evolution），維護不斷擴充的代理存檔；HGM 則將其形式化為固定預算樹搜尋，利用 Thompson sampling 與枝系（clade）層級後驗來決定評估與擴展。這些方法主要改善「**選擇哪個代理進行下一步**」的取樣策略（sampling policy），而自我修改過程本身仍多依賴單一軌跡。MGM 的差異化在於：**把存檔從單純的排行榜（leaderboard）轉化為比較診斷的資料來源**，讓擴展運算子能同時利用跨任務與跨譜系的對比訊號。

**主要優勢**：
- 更豐富的證據來源，降低單一失敗軌跡的雜訊。  
- 透過反應規範區分基因型缺陷與任務雜訊，提升修改方向性。  
- 跨譜系雜交促進能力遷移，避免不同譜系重複探索相同錯誤。  
- 理論模型與代理模擬雙重驗證，提供收斂速度保證。

**限制與未解問題**：
- **存檔豐富度門檻**：反應規範突變需要代理在多個任務上已有軌跡；跨譜系雜交需要不同譜系嘗試過同一任務。在演化早期或任務分佈稀疏時，這些運算子可能難以啟動。  
- **編輯器品質**：所有證據最終仍須由 LLM 編輯器轉化為原始碼修改。若編輯器無法理解對比證據，理論優勢無法兌現。  
- **加成模型的簡化**：理論分析假設適應度地形為加成性（additive）且基因型為二元向量，真實程式碼修改中存在上位效應（epistasis）與非線性交互作用，模型僅為初步近似。  
- **安全性與可控性**：自我修改代理能改寫自身原始碼，論文未深入討論如何防止有害或自我複製式修改，這是實際部署前必須補強的環節。

#### 可重現性評估

根據目前提供的上下文，論文並未明確提及是否公開原始碼、演化後的 scaffold、模型權重或完整實驗紀錄。因此，從可重現性（reproducibility）角度可做出以下評估：

- **資料集**：Polyglot（Gauthier, 2024）與 SWE-bench（Jimenez et al., 2024）均為公開基準，第三方原則上可取得相同任務集合。  
- **骨幹模型**：Qwen3.6-35B-A3B 與 DeepSeek-V4-Pro 可透過 API 或開放權重取得（視作者實際使用管道而定），但論文未說明版本、溫度參數、推論設定等細節。  
- **演化的 scaffold**：這是 MGM 真正的產出物，包含提示詞（prompts）、工具定義、工作流程與自我修改邏輯。若作者未釋出，外界難以完全複製 50.8% → 93.3% 的躍升。  
- **超參數**：存檔樹的 widening 參數 α、Thompson sampling 的 concentration 參數 κ、三種運算子的選擇機制等，對結果影響重大，但上下文未提供具體數值。  
- **計算成本**：自我改進需要大量 LLM 呼叫與任務評估，論文未詳述總運算預算，這會影響其他研究者是否能以可負擔資源重現。

總結來說，MGM 的可重現性處於「**概念與基準可複製，但完整數據與最佳化 scaffold 再現需依賴作者釋出額外資源**」的狀態。建議作者未來提供：原始碼倉庫、演化後的 scaffold 快照、實驗配置檔、存檔樹結構與軌跡紀錄，以及估算的運算成本。

#### 未來研究方向

MGM 開啟了幾個值得延伸的研究方向：

1. **更豐富的遺傳運算子**  
   除了克隆、反應規範與跨譜系雜交，可引入更正式的基因重組（recombination）、基因重複（duplication）或物種形成（speciation）機制，並研究它們在程式碼空間中的表現。

2. **超越加成適應度地形的理論分析**  
   發展考慮上位效應、NK 地形或動態任務分佈的收斂理論，使理論保證更貼近真實程式碼演化。

3. **學習式編輯器（learned editor）**  
   目前編輯器多為通用 LLM。未來可訓練專門的編輯模型，使其擅長從反應規範與跨譜系對比中產生修改，進一步提升修改成功率。

4. **安全性與可證明效益的橋接**  
   把 Gödel Machine 的形式化精神帶回 LLM 自我修改：例如透過靜態分析、單元測試或形式化驗證，確保每次自我修改至少不降低已通過任務的表現，並提供可檢驗的修改契約。

5. **跨領域遷移**  
   將 MGM 的比較式演化框架應用於數學證明、機器人控制、科學實驗設計或網頁代理，檢驗其是否為通用的自我改進範式。

6. **動態與開放式任務環境**  
   目前基準多為固定任務集合。未來可研究任務分佈持續變化時，反應規範如何幫助代理追蹤自身的優劣勢領域，並進行持續學習（continual learning）。

7. **元學習取樣與擴展策略**  
   除了改進自我修改運算子，也可讓 π-sampling 本身成為可學習對象，根據存檔結構動態調整三種運算子的使用頻率與資源分配。

8. **人機協作式自我改進**  
   在關鍵自我修改步驟引入人類審查或偏好回饋，平衡自動化與可控性，降低災難性自我修改風險。

## 論文問答

**Q1：本文要解決的核心問題是什麼？為什麼現有的單一軌跡自我修改方法不足？**

A：本文要解決的核心問題是，現有自我改進的程式設計代理通常只在一次失敗軌跡上進行自我修改，這種單一軌跡基線忽略了擴充存檔中累積的大量比較訊號。孟德爾哥德爾機器（MGM）針對此問題，提出透過受控比較來利用多條軌跡，從而更精確地診斷基因型層級缺陷。這樣的設計能讓代理不只是從最近一次失敗學習，而是從整體表現型模式中獲取改進線索，進而發現更具通用性的工作流程層級改進。

**Q2：MGM 辨識出哪兩類被忽略的「比較訊號」？它們分別對應什麼生物學概念？**

A：第一類是反應規範，即同一代理在多個任務上的成功與失敗模式，可形成基因型特異性輪廓；第二類是跨譜系比較，即不同譜系代理在相同任務上的軌跡差異，能揭示可遷移的行為特徵。MGM 借用孟德爾原理中的受控遺傳概念，將這兩類訊號分別轉化為反應規範突變與跨譜系雜交。透過這兩種操作，代理能區分任務特定偶發事件與真正的程式碼缺陷，並減少冗餘探索。

**Q3：為什麼僅把存檔當作排行榜來取樣是不夠的？**

A：存檔不僅記錄了所有代理變體的評估結果，也保存了它們在各式各樣任務上的完整軌跡，這些都是可重複使用的診斷證據。如果只把存檔當作排行榜，就等於只利用最終分數來決定下一步，而沒有深入分析失敗背後的結構性原因。MGM 因此將存檔視為比較證據的來源，讓自我修改過程能基於更豐富的對比證據做出決策，從而提升編輯的精準度與效率。

**Q4：MGM 的三種自我修改運算子各是什麼？它們的證據來源有何不同？**

A：三種運算子分別是克隆突變、反應規範突變與跨譜系雜交。克隆突變只使用單一代理在單一目標任務上的失敗軌跡，是傳統的單一軌跡修改；反應規範突變則同時參考該代理在多個參考任務上的軌跡；跨譜系雜交則使用來自不同譜系的參考代理在同一任務上的軌跡。這三種操作都直接運用日常存檔評估累積的軌跡，因此不會產生額外的任務評估成本。

**Q5：反應規範突變如何幫助代理區分真正的程式碼缺陷與任務特定偶發事件？**

A：反應規範突變讓代理同時檢視自己在多個參考任務上的表現型輪廓，從中找出反覆出現的失敗模式。如果某種失敗在多種不同環境下都出現，就較可能是基因型層級缺陷；若只在單一任務出現，則可能只是任務特定偶發事件。這種比較式診斷能讓編輯更有針對性，避免過度調整只為了迎合單一特例，從而提升自我改進的穩定性。

**Q6：跨譜系雜交如何實現「目標能力遷移」？它與克隆突變有何本質差異？**

A：跨譜系雜交會挑選來自另一條譜系、曾嘗試過相同任務的參考代理，並以其成功軌跡作為對照證據來編輯當前代理。這種做法能將其他譜系已發現的可遷移行為特徵直接引入目標代理，實現目標能力遷移。與克隆突變只檢視自身失敗不同，跨譜系雜交透過對比不同基因型在相同環境下的表現，找出更具通用性的改進方向，並避免重複探索其他譜系已走過的路徑。

**Q7：作者在哪些基準測試與模型上驗證 MGM？主要對照是什麼？**

A：實驗主要在 SWE-bench 與 Polyglot 兩個基準測試上進行，並使用 Qwen3.6-35B-A3B、DeepSeek-V4-Pro 等大型語言模型作為骨幹。對照方法包括單一軌跡基線以及 HGM 等現有的存檔取樣強化方法。結果顯示 MGM 在效能、效率與泛化能力上均有穩定提升，並能將相對小型的開源模型推進到超越大型封閉源模型的水準。

**Q8：MGM 在 Polyglot 上取得了哪些關鍵量化結果？**

A：透過純粹演化代理腳手架，MGM 將 Qwen3.6-35B-A3B 在 Polyglot 上的表現從 50.8% 提升至 93.3%，超越了參數量約為其 117 倍的封閉源 GPT-5。此外，把在 Qwen 上演化出的腳手架遷移到 DeepSeek-V4-Pro 後，更達到 96.9% 的成績。這顯示 MGM 發現的是可重複使用的工作流程層級改進，而非僅針對單一模型的過擬合調整。

**Q9：除了真實基準測試，作者還用什麼方式驗證 MGM 的有效性？**

A：作者建立了一個加成適應度地形模型，將代理表示為二元基因型向量，並以與神諭基因型的漢明距離來衡量改進進度。在該模型下，他們從理論上證明 MGM 比單一軌跡基線具有更快的期望收斂速度。接著透過受控的蒙特卡羅代理模擬，進一步驗證了理論預測在模擬環境中成立，為方法提供了嚴謹的理論與實證基礎。

**Q10：MGM 在實務上可以應用在哪些程式設計代理場景？**

A：MGM 可應用於需要長期自我演化的自動化程式設計代理，例如持續維護大型程式碼庫、自動修復軟體缺陷或多語言程式生成系統。由於它能利用過去所有嘗試累積的比較證據，代理可以隨著時間不斷精進自身腳手架與工作流程。這對於需要高頻迭代與大規模評估的開發環境特別有價值，能夠降低人工調校與重複實驗的成本。

**Q11：若要把 MGM 產品化，需要考慮哪些工程與資源議題？**

A：產品化時必須維護一個結構化的譜系樹存檔，並能高效追蹤每個代理變體的基因型、表現型與完整軌跡。評估預算與擴展時機由公式中的加寬參數與 Thompson 取樣策略控制，因此需要仔細調校探索與利用之間的平衡。幸運的是，MGM 的三種運算子都直接使用既有評估軌跡，不會額外增加任務評估次數，有助於控制整體運算成本並提升部署可行性。

**Q12：MGM 對自我改進代理與人工智慧領域可能帶來什麼影響？**

A：MGM 顯示透過比較式演化，可以在相對小的開源模型上發現可重複使用的工作流程層級改進，甚至超越大得多的封閉源模型。這為未來自我改進代理的發展提供了一個可擴展的範式，強調利用存檔中的對比證據而非僅依賴單次失敗。長遠來看，這可能改變我們設計與訓練編碼代理的方式，使其更接近開放式演化系統，並推動遞迴自我改進技術的實用化。

**Q13：MGM 有哪些潛在限制或前提假設？**

A：MGM 假設存檔中累積的軌跡具有足夠多樣性，才能產生有意義的反應規範與跨譜系比較。此外，它的效能也受限於底層大型語言模型作為編輯器的能力，若模型無法從對比證據中提煉出正確診斷，改進效果會大打折扣。目前理論分析主要基於加成適應度地形模型，對於更複雜、非加成或動態變化的適應度地形，保證可能不再成立，需要進一步研究。

**Q14：在什麼情況下，反應規範突變或跨譜系雜交可能失效？**

A：如果參考任務與目標任務過於相似或缺乏多樣性，反應規範突變可能無法區分基因型層級缺陷與任務特定偶發事件。跨譜系雜交則可能在參考代理與目標代理的腳手架差異過大時失效，導致引入無法相容或難以遷移的行為特徵。此外，當存檔中的成功軌跡來自過度擬合特定測試案例時，比較證據也可能誤導後續編輯，使改進方向偏離真正的通用能力。

**Q15：未來研究可以朝哪些方向延伸 MGM？**

A：未來可以將 MGM 擴展到連續或多目標的表現型空間，而不僅限於二元成功或失敗。也可以探索更複雜的基因型表示，例如模組化程式結構或神經網路權重，並發展更廣泛適用的理論收斂保證。另一個方向是結合主動學習，讓系統自動選擇最能區分不同譜系的診斷任務，進一步提升比較式演化的效率與可解釋性。

## 實務應用指南

### 適用場景

1. **企業級遺留程式碼現代化**：當組織需要長期維護大量異質語言的遺留系統時，可將 MGM 的「基因型」設為代理的 scaffold、提示詞與工具呼叫策略，讓它在 SWE-bench 類任務上持續演化，自動產生修補、重構與測試生成能力，並透過反應規範突變辨識跨專案反覆出現的缺陷模式。

2. **多儲存庫內部開發平台**：大型企業內部常有多個程式碼庫共用相似框架。MGM 的跨譜系雜交能讓在某個儲存庫學到的修復策略，轉移到處理相同任務類型但不同譜系的代理上，減少重複探索，加速新專案 onboarding。

3. **開源軟體自動化議題分類與修復**：開源社群可部署 MGM 作為持續運行的機器人，針對 issue 與 PR 描述產生修補。存檔中累積的失敗軌跡與成功軌跡可形成反應規範，協助區分「代理程式碼缺陷」與「任務特定偶發事件」，降低誤修率。

4. **領域特定語言（DSL）或內部框架的協同演化**：當公司維護自訂 DSL、API 或測試框架時，可讓 MGM 同時演化代理 scaffold 與範例任務集；反應規範突變能捕捉代理在多個 DSL 任務上的表現型輪廓，引導更穩定的能力遷移。

5. **程式教育與個人化輔助代理**：在程式學習情境中，MGM 可根據學生在多種題目上的反覆失敗軌跡，調整解釋策略與提示詞模板；跨譜系雜交則能借鏡其他學習者代理的成功軌跡，提供個人化但經過對比驗證的提示。

### 實作前置條件

- **資料準備**
  - 一組可重複執行的評估任務分佈 \(D\)，例如 SWE-bench、Polyglot 或內部單元測試集合。
  - 每個任務需有明確的二元或連續結果 \(r(a,\tau)\)，並能記錄完整執行軌跡 \(\phi(a,\tau)\)。
  - 建議預留未公開的 holdout 任務，用於驗證泛化能力，避免過度擬合到訓練基準。

- **運算資源**
  - 可呼叫的骨幹大型語言模型（如 Qwen、DeepSeek、GPT 系列）API 或自建推理端點。
  - 安全的沙箱執行環境，用於執行代理產生的程式碼與測試。
  - 足夠的運算預算支援反覆評估—擴展循環；論文使用固定預算樹搜尋，實務上可先以代理模擬（surrogate simulation）估算成本。

- **技術與團隊能力**
  - 熟悉代理 scaffold 設計（提示詞、工具呼叫、檔案編輯器）。
  - 具備建置譜系樹存檔與軌跡資料庫的後端能力。
  - 理解 Thompson 取樣、Beta 後驗與基本演化演算法概念。
  - 具備程式碼安全審查與沙箱維運經驗，以控管自我修改風險。

### 實作步驟建議

1. **定義基因型與表現型**：將代理的「基因型」明確化，包括系統提示詞、工具描述、推理步驟格式、重試策略與輸出解析器；「表現型」則是任務成功率與軌跡記錄。

2. **建置存檔與譜系樹**：實作可持久化的 archive，記錄每個代理變體的原始碼、父節點、子節點，以及在所有已評估任務上的軌跡與結果，支援日後的克隆突變、反應規範突變與跨譜系雜交。

3. **打造評估管線（φ-evaluation）**：建立自動化沙箱，能對任務執行代理、擷取軌跡、判定二元結果，並將資料寫回存檔。確保評估可重現且具備超時與資源限制。

4. **實作三種孟德爾自我修改運算子**：
   - **克隆突變 \(\Phi_{CM}\)**：針對單一失敗軌跡診斷並修改原始碼。
   - **反應規範突變 \(\Phi_{RM}\)**：同時輸入代理在多個參考任務上的軌跡，讓模型辨識基因型層級缺陷。
   - **跨譜系雜交 \(\Phi_{CH}\)**：選取不同譜系中曾嘗試相同目標任務的參考代理，以其軌跡作為對比證據進行編輯。

5. **實作 \(\pi\)-sampling 與預算控制**：依據論文式 (4)–(7) 的 Thompson 取樣策略，決定每步要進行評估或擴展，並設定 widening 參數 \(\alpha\) 與 concentration 參數 \(\kappa\)。

6. **啟動演化循環並監控**：在固定預算下反覆執行「取樣 → 評估／擴展 → 更新存檔」。即時追蹤最佳節點適應度、譜系多樣性與每次擴展的資源消耗。

7. **驗證與篩選**：在 holdout 任務上測試最終代理變體，比較單一軌跡基線與 MGM 的效能、效率與泛化能力。

8. **產品化部署**：將演化出的 scaffold 包裝成可部署的代理服務，搭配版本控制、人工審查閘道與持續監控，避免直接讓生產系統無限制自我修改。

---

### 潛在風險與注意項事項

- **災難性自我修改**：代理可能改壞自己的核心邏輯，導致後續無法正常運作。  
  *緩解*：所有修改必須在隔離沙箱中驗證，並保留完整譜系樹與原始碼快照，支援一鍵回滾到任一父節點。

- **過度擬合基準**：反覆在同一組任務上演化，可能使代理學到針對特定測試的捷徑而非通用能力。  
  *緩解*：使用反應規範突變強制跨任務比較，並定期在未見過的 holdout 任務上驗證；論文中的加成適應度地形模型也可作為診斷工具。

- **譜系多樣性崩潰**：若取樣策略過度集中於少數高適應度分支，可能錯失更好的長期解。  
  *緩解*：監控譜系樹的葉節點數量與分支深度，適度調高 \(\alpha\) 以維持探索；可引入多樣性獎勵或族群大小上限。

- **運算成本膨脹**：每次擴展都可能觸發多次 LLM 呼叫與沙箱執行。  
  *緩解*：先以受控代理模擬估算收斂速度，再決定真實評估預算；並對低潛力分支進行早期剪枝。

- **安全與權限風險**：自我修改的代理若擁有檔案系統或網路權限，可能產生惡意或意外行為。  
  *緩解*：採用最小權限原則，禁止代理直接修改生產程式碼；所有產出須經靜態分析、單元測試與人工核准。

- **評估雜訊**：LLM 與沙箱執行具有隨機性，可能導致適應度估計不穩。  
  *緩解*：對關鍵節點進行多次重複評估，並在 Thompson 取樣中使用適當的 concentration 參數平滑後驗。

### 與其他技術的整合建議

- **CI/CD 管線**：將 MGM 的評估管線嵌入持續整合系統，讓每次程式碼提交都能觸發代理在相關任務上的軌跡收集，並自動更新存檔中的表現型紀錄。

- **IDE 與開發者工具**：透過 Language Server Protocol 或外掛形式，將演化後的 scaffold 與提示詞模板整合進 VS Code、JetBrains 等 IDE，讓開發者在撰寫程式時即時獲得經過對比驗證的建議。

- **議題追蹤系統**：對接 GitHub Issues、Jira 或內部工單系統，自動將新任務加入任務分佈 \(D\)，並將代理產生的修補以 PR 形式提交，保留人工審查閘道。

- **模型路由與閘道**：在 MGM 的 \(\pi\)-sampling 之上疊加模型路由層，依據任務難度與成本選擇不同骨幹 LLM，例如簡單任務使用輕量模型，複雜任務才呼叫大型模型。

- **可觀測性平台**：將軌跡、適應度與譜系關係匯入可觀測性工具（如 OpenTelemetry、自製儀表板），協助團隊視覺化演化過程、診斷反覆出現的失敗模式，並支援審計。

- **檢索增強生成（RAG）**：把存檔中的成功軌跡與修補範例建立向量索引，讓代理在執行克隆突變或跨譜系雜交時，能先檢索歷史對比案例，提升編輯品質。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從圖 1 的整體架構與孟德爾遺傳類比開始，先理解「基因型＝代理原始碼、表現型＝任務結果」這個核心對應關係，再逐步認識三種運算子的差異，暫時不需要深入 Thompson 取樣或加成適應度地形的數學細節。

- **AI 工程師**：請重點閱讀第 3 節的三種自我修改運算子與實作細節，特別注意反應規範突變與跨譜系雜交所需的軌跡格式與提示詞設計；同時評估自身系統是否已具備安全的沙箱、版本化存檔與可重複評估管線。

- **研究人員**：建議深入第 2 節的數學形式化與加成適應度地形模型，關注論文對收斂速度的理論保證與受控代理模擬的驗證設計；可進一步思考如何將此框架擴展到非二元獎勵、多目標最佳化或更複雜的程式空間。

- **產品經理**：請聚焦適用場景、圖 2 的效能提升數據以及潛在風險與注意事項，評估 MGM 是否適合貴組織的程式碼維護流程；重點關注運算預算、安全審查閘道與泛化能力驗證，這些是決定能否從實驗走向產品的關鍵因素。
