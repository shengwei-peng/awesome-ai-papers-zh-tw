## ⚡ TL;DR

現有深度研究智能體因盲目依賴工具與表演式推理，陷入運算浪費的效率陷阱。
本文提出SlimSearcher框架，結合帕雷托效率過濾與自適應獎勵閘控進行訓練。
在長程基準測試中，工具呼叫輪次降低17%至58%，且維持或提升準確率。

## 摘要翻譯

深度研究智能體（Deep research agents）在複雜資訊搜尋任務中展現了卓越的能力，然而這種能力伴隨著高昂的運算成本（computational cost）。在以準確性為中心的訓練範式（accuracy-focused training paradigms）驅動下，現有模型採用暴力策略（brute-force strategies），其特徵為盲目工具依賴（blind tool dependency）與表演式推理（performative reasoning）——生成冗長且冗餘的軌跡（trajectories），而這些軌跡對於解決任務遠非必要，導致浪費性的工具呼叫與過度的詞元消耗（token consumption）。為了克服此效率陷阱（efficiency trap），我們提出 SlimSearcher，一個有原則的框架，在監督式微調（Supervised Fine-Tuning, SFT）與強化學習（Reinforcement Learning, RL）兩個階段中推進準確性（accuracy）與運算成本之間的帕雷托前沿（Pareto frontier）。在 SFT 階段，SlimSearcher 採用帕雷托效率過濾（Pareto-efficient filtration）來篩選既成功又經濟的軌跡，引導模型發展出本質上具效率感知的搜尋行為。在 RL 階段，我們引入自適應獎勵閘控（Adaptive Reward Gating），這是一種動態獎勵塑形機制（dynamic reward-shaping mechanism），能在抽樣群組（sampled cohort）內評估工具與詞元使用的相對效率。透過級聯這些自適應效率指標與嚴格的正確性閘門（correctness gate），我們的方法有效避免了與絕對懲罰（absolute penalties）相關的簡潔偏誤（brevity bias），並緩解了獎勵駭取（reward hacking）。在 GAIA、BrowseComp 與 XBenchDeepSearch 等長程基準測試（long-horizon benchmarks）上進行的大量實驗顯示，SlimSearcher 在維持或提升準確性的同時，將平均工具呼叫輪次（tool-call rounds）降低了 17%–58%。

### 核心貢獻（3～5點）
- 提出 SlimSearcher 框架，整合監督式微調（SFT）與強化學習（RL），系統性地推進準確性與運算成本之間的帕雷托前沿。
- 設計帕雷托效率過濾機制，於 SFT 階段篩選成功且經濟的軌跡，引導模型建立本質上的效率感知搜尋行為。
- 提出自適應獎勵閘控，透過動態獎勵塑形機制評估抽樣群組內的相對效率，並級聯正確性閘門以避免簡潔偏誤與獎勵駭取。
- 在 GAIA、BrowseComp、XBenchDeepSearch 等長程基準測試上驗證，平均工具呼叫輪次降低 17%–58%，同時維持或提升準確性。

### 適合對象
從事大型語言模型智能體、工具整合推理與強化學習系統設計的研究人員與工程師，特別是關注長程開放式任務中運算效率與準確性權衡之學術與產業界讀者。

## 深度分析

#### 方法論解析

現有深度研究智能體（Deep research agents）雖在複雜資訊搜尋任務上展現強大能力，卻深陷效率陷阱（efficiency trap）。本研究將此陷阱歸因於兩種失效模式：盲目工具依賴（Blind Tool Dependency）與表演式推理（Performative Reasoning）。前者屬於認知卸載（cognitive offloading）的濫用，智能體對可透過內部知識（internal knowledge）直接解決的查詢，不當呼叫外部工具（external tools），造成多餘的 API 開銷與延遲（latency）；後者則出現在確需外部搜尋的複雜任務中，推理過程充斥冗餘迴圈（redundant loops）、重複驗證（verification）與死路分支（dead-end branches），最終生成膨脹軌跡（Bloated Trajectory）。這些行為根源於現行以準確性為中心的訓練範式（accuracy-focused training paradigms）——特別是 Acc-only Rejection Sampling（僅依準確性的拒絕採樣）——只要軌跡（trajectories）正確即視為正樣本，導致模型內化暴力策略（brute-force strategies），並在強化學習（RL）階段因單純優化端到端成功率（end-to-end success rates）而引發效率崩潰（efficiency collapse）。

SlimSearcher 提出雙階段訓練框架以對抗上述問題。第一階段為監督式微調（SFT）階段的帕雷托效率過濾（Pareto-efficient filtration）。與傳統僅過濾正確軌跡的做法不同，此方法同時評估軌跡的成功性與經濟性，從大量軌跡中提煉出兼具高準確率與低運算成本（computational cost）的資料子集。其目標並非單純縮短長度，而是引導模型學習趨近最小必要路徑（Minimal Necessary Path）的搜尋行為，從根源抑制冗餘步驟（Redundant Step）的產生。

第二階段為強化學習（RL）階段的自適應獎勵閘控（Adaptive Reward Gating）。此獎勵塑形機制（reward-shaping mechanism）包含兩大核心：自適應效率錨定（Adaptive Efficiency Anchoring, AEA）與正確性閘門（correctness gate）。AEA 在抽樣群組（sampled cohort）內動態評估相對工具效率與詞元消耗（token consumption），將效率獎勵錨定於該群組中發現的經驗最小必要路徑，而非採用固定數值的絕對懲罰（absolute penalties）。這避免了簡潔偏誤（brevity bias）——即模型為獲取高分而過度縮短軌跡、甚至犧牲答案品質的傾向。正確性閘門則作為硬性約束，確保僅在輸出正確時才給予效率獎勵，從而有效抑制獎勵駭取（reward hacking）。透過串接自適應效率指標與嚴格正確性篩選，SlimSearcher 在推動模型朝向高效率智能體（Efficient Agent）行為收斂的同時，維持任務準確率，實質推進了準確率與運算成本之間的帕雷托前沿（Pareto frontier）。

#### 實驗數據解讀

實驗於 GAIA、BrowseComp 與 XBenchDeepSearch 等長程基準測試（long-horizon benchmarks）上進行，這些任務需要多輪工具整合推理（tool-integrated reasoning），非常適合驗證深度研究智能體的效率極限。數據顯示，SlimSearcher 能將平均工具呼叫輪次（tool-call rounds）降低 17%–58%，同時維持或提升準確率。

這項結果的關鍵意義在於其並非單純的「長度縮減」，而是質性行為的改變。模型不再依賴盲目增加搜尋引擎（search engines）與程式碼解譯器（code interpreters）的呼叫次數來確保正確，而是學會辨識何時應運用內部知識、何時該停止無效的驗證迴圈。這證明了框架成功將效率感知內化為模型的策略偏好，而非僅是推理時的外部啟發式規則。從帕雷托前沿的角度觀之，實驗達成了效率—準確率的帕雷托改善（Pareto improvement）：在沒有犧牲任務成功率的條件下，顯著壓低了運算成本。這對於需要大規模部署的開放式任務（open-ended tasks）尤為重要，因為工具呼叫的延遲與詞元消耗直接關係到基礎設施資源與營運成本。

#### 與現有研究的比較

現有網頁智能體方法大致分為兩類：提示工程框架（Prompting and Engineering Frameworks）與以訓練為中心的智能體演化（Training-Centric Agent Evolution）。前者如 SelfDC、AutoGen 與 GPT-Researcher，雖具彈性，但高度依賴基礎大型語言模型（LLMs）的固有能力，且常因冗長的上下文管理導致高詞元消耗。SlimSearcher 屬於後者，但突破了現有訓練範式的瓶頸。

現有強化學習策略多聚焦於端到端成功率，這種單一目標優化會觸發效率崩潰：隨著訓練迭代，模型傾向透過過度探索（over-exploration）——增加搜尋輪數與上下文長度——來最大化正確機率。SlimSearcher 的自適應獎勵閘控則透過相對效率評估，將優化目標重新校準至最小必要路徑，從而避免此現象。

相較於早期嘗試以絕對懲罰控制軌跡長度的做法，SlimSearcher 的動態獎勵結構解決了簡潔偏誤與獎勵駭取的兩難。絕對懲罰容易導致模型在面對複雜查詢時過早放棄必要推理步驟；而 SlimSearcher 的抽樣群組相對比較機制，讓效率獎勵具備任務適應性（task-adaptive），能隨問題難度自動調整。

限制方面，本研究主要針對資訊搜尋場景中的搜尋與驗證行為進行優化。對於需要頻繁使用程式碼解譯器或其他非搜尋類外部工具的任務，其效率指標的設計是否同樣適用，仍需進一步驗證。此外，AEA 依賴抽樣群組的品質與多樣性，若群組內軌跡普遍偏離最佳路徑，錨定效果可能受限。

#### 可重現性評估

論文作者已將程式碼釋出於 GitHub（https://github.com/AQ-MedAI/AntAFu-DeepResearch），這為社群重現與驗證提供了基礎。實驗所採用的 GAIA、BrowseComp 與 XBenchDeepSearch 均為公開長程基準測試，資料層面具備可重現性。

然而，有幾項因素可能影響重現的難度。首先，深度研究智能體的訓練與推論高度依賴搜尋引擎與程式碼解譯器等外部工具 API，大規模重現實驗將產生可觀的 API 費用與延遲。其次，帕雷托效率過濾的具體實作細節——例如經濟性指標的權重、帕雷托邊界的計算方式——若未在程式碼中完整揭露，可能導致不同實作間的差異。最後，論文未明確說明是否釋出微調後的模型權重或僅提供訓練腳本；若缺乏預訓練檢查點（checkpoints），其他研究者需從頭執行監督式微調（SFT）與強化學習（RL），這對運算資源的要求極高。

#### 未來研究方向

1. 異質工具鏈的泛化：將自適應獎勵閘控擴展至更廣泛的工具類型，例如資料庫查詢、多模態檢索、或具狀態的 API 互動，並設計對應的效率指標，超越現有的工具呼叫輪次與詞元消耗框架。

2. 線上適應與預算感知推理：發展無需重新訓練的線上機制，使智能體能依據即時運算預算動態調整搜尋深度。這可結合自適應效率錨定的概念，在推理階段即實現預算約束下的最佳化。

3. 最小必要路徑的理論形式化：目前最小必要路徑主要透過經驗抽樣群組相對界定。未來研究可探討其在特定任務分佈下的資訊理論下界，或分析自適應獎勵閘控在強化學習中的收斂性與樣本複雜度。

4. 多目標成本模型：除了工具呼叫次數，納入實際牆上時鐘時間（wall-clock time）、API 金錢成本、與能源消耗等多維度運算成本，建立更貼近真實部署場景的帕雷托前沿評估體系。

5. 人機協作中的效率感知：在 human-in-the-loop 架構中，讓效率感知機制成為人類監督者的輔助工具。例如，當智能體偵測到自身進入死路分支或冗餘迴圈時，主動請求人類確認是否終止或修正路徑，進一步提升開放式任務的協作效率。

## 論文問答

**Q1：什麼是「效率陷阱」，現有的深度研究智能體為何會陷入其中？**
A：「效率陷阱」指的是當前深度研究智能體在追求任務準確率的過程中，過度依賴暴力策略而導致運算成本急劇上升的現象。具體而言，這些智能體表現出「盲目工具依賴」與「表演式推理」兩種行為缺陷，前者會對無需外部查詢的常識問題重複呼叫搜尋工具，後者則在複雜任務中產生冗餘迴圈與死路分支，模仿嚴謹推理卻未增加實質資訊。這些行為共同造成工具呼叫與詞元消耗的大量浪費，使得軌跡遠超完成任務所需的「最小必要路徑」。

**Q2：現有以準確性為中心的訓練範式為何無法產生高效率的智能體？**
A：現有範式普遍採用「僅準確率拒絕採樣」，只要軌跡最終正確便視為正樣本，導致模型將冗長、多餘的膨脹軌跡內化為標準行為模式。在強化學習階段，若僅以端到端成功率作為獎勵信號，智能體傾向透過擴大搜尋輪次與上下文長度來提升準確率，引發「效率崩潰」。這種單一目標的優化缺乏對工具與詞元經濟性的約束，因此無法引導模型學習精簡且有效的問題解決策略。

**Q3：為何在準確率與運算成本之間推進帕雷托前沿對網頁智能體至關重要？**
A：當前開源網頁智能體回答單一問題常需數百輪推理，大規模部署時將消耗龐大的基礎設施資源並顯著增加營運成本。若僅追求準確率而忽視效率，這類系統在商業化與實際應用中將難以擴展，且過長的延遲會嚴重損害使用者體驗。因此，同時維持或提升準確率並降低運算開銷，是使深度研究智能體從實驗室走向實用產品的關鍵。

**Q4：SlimSearcher 的核心方法包含哪兩個階段，它們如何協同運作？**
A：SlimSearcher 在監督式微調階段採用「帕雷托效率過濾」，從原始資料中篩選出既成功又具經濟性的軌跡，為模型建立效率感知的行為先驗。隨後在強化學習階段引入「自適應獎勵閘控」，透過動態評估抽樣群組內的相對工具與詞元效率，並疊加嚴格的正確性閘門來塑形獎勵。這兩個階段前後銜接，先以精煉資料引導模型遠離冗餘模式，再以相對優化機制微調行為，避免簡潔偏誤與獎勵駭取。

**Q5：「自適應獎勵閘控」的關鍵創新是什麼，它與傳統的絕對懲罰有何不同？**
A：自適應獎勵閘控的核心在於動態評估抽樣群組中的相對效率，並將優化目標錨定於該群組內發現的經驗性最小必要路徑，而非使用固定數值的長度懲罰。傳統絕對懲罰容易導致簡潔偏誤，使模型為了獲得高分而過度縮減必要步驟，甚至犧牲答案正確性。相對地，這種任務適應性的梯度信號能根據不同查詢的複雜度彈性調整，在鼓勵精簡軌跡的同時嚴格守住準確率底線。

**Q6：為何在強化學習中需要將自適應效率指標與「嚴格正確性閘門」串聯使用？**
A：若僅以效率指標作為獎勵依據，智能體可能利用獎勵函數的漏洞，透過輸出錯誤但極短的答案來獲取高分，即所謂的獎勵駭取。嚴格正確性閘門確保只有在答案正確的前提下，效率優化才會被賦予正向回饋，從而將模型的探索空間限制在「正確且精簡」的區域內。這種設計有效分離了效率與正確性的優化風險，使模型不會為了節省成本而妥協任務成敗。

**Q7：SlimSearcher 在哪些基準測試上進行評估，這些測試有何代表性？**
A：論文在 GAIA、BrowseComp 與 XBench-DeepSearch 等長程基準測試上進行廣泛實驗。這些基準測試涵蓋了需要多輪外部工具互動的複雜資訊搜尋任務，能夠充分檢驗智能體在長期規劃、工具整合與資訊驗證上的綜合能力。由於任務本身具有高難度與長期依賴特性，它們是衡量深度研究智能體能否同時達成高準確率與高效率的理想場域。

**Q8：實驗的主要結果顯示 SlimSearcher 在效率與準確率上取得了哪些具體成效？**
A：實驗結果顯示，與基線模型相比，SlimSearcher 能夠將平均工具呼叫輪次降低 17% 至 58%，同時維持甚至提升任務準確率。這證明了該框架成功推進了準確率與運算成本之間的帕雷托前沿，打破了過去認為減少搜尋次數必然犧牲表現的迷思。如此顯著的效率增益意味著在實際部署中可大幅節省 API 開銷與基礎設施負載。

**Q9：SlimSearcher 具體改善了基線智能體的哪些行為缺陷，這些缺陷在實驗中如何呈現？**
A：該框架針對「盲目工具依賴」與「表演式推理」兩種缺陷進行改善；前者表現為智能體對無需外部搜尋的常識問題仍重複呼叫工具，後者則是在成功軌跡中出現冗餘迴圈與死路分支。基線模型在面對簡單查詢時產生不必要的工具呼叫，在複雜查詢時則生成大量無助於最終答案的驗證步驟。SlimSearcher 透過帕雷托效率過濾與自適應獎勵塑形，有效抑制了這些膨脹軌跡的生成。

**Q10：SlimSearcher 的效率提升在哪些實際應用場景中最具影響力？**
A：其效率提升對於需要大規模處理查詢的商業應用最具價值，例如自動化深度研究助理、企業級客戶支援系統與即時數據分析管線。在這些場景中，工具呼叫輪次減少 58% 可直接轉化為顯著的 API 成本節省與更低的回應延遲。此外，基礎設施負載的降低也使服務商能夠以相同資源支援更多並發用戶，提升整體系統的擴展性與獲利空間。

**Q11：SlimSearcher 的設計理念如何影響未來商業化深度研究產品的開發？**
A：此框架證明了在訓練階段即將效率視為與準確率同等重要的目標，是打造可持續商業化產品的可行路徑。未來產品開發可借鏡其帕雷托效率過濾與自適應獎勵機制，在模型訓練時便內建成本感知能力，而非僅在推理階段透過提示工程進行限縮。這將使產品能夠依據不同用戶層級或任務複雜度動態調整搜尋深度，在確保答案品質的前提下實現精細化的資源控管。

**Q12：這項研究對工具整合推理與智能體訓練領域的研究方向帶來什麼啟發？**
A：本研究將研究焦點從單純的準確率優化轉向聯合效率—準確率優化，並提出「最小必要路徑」作為理想行為的參照標準。它揭示了現有訓練範式因缺乏效率約束而導致的系統性缺陷，促使學界重新審視軌跡品質的評估指標。未來研究可能會更廣泛地採用相對效率評估與動態獎勵塑形，並將運算成本納入智能體基準測試的標準評比維度之一。

**Q13：SlimSearcher 在面對高度開放或目標模糊的任務時，可能存在哪些限制？**
A：當任務目標極度開放或具有高度模糊性時，例如探索性研究或創意發想，「最小必要路徑」往往難以事先定義，導致帕雷托效率過濾缺乏明確的篩選依據。此外，若資料集中成功且精簡的參考軌跡極為稀少，SFT 階段的過濾機制可能無法提供足夠的高品質正樣本供模型學習。這些情況可能限制框架在非常規、非結構化任務上的通用性與效益。

**Q14：在哪些條件下，SlimSearcher 仍可能產生低效或錯誤的軌跡？**
A：若強化學習階段的抽樣群組整體效率偏低，自適應錨點可能將次優軌跡誤設為相對標準，導致模型僅收斂到「較不糟」而非真正精簡的行為。對於需要大量反覆驗證才能確保正確性的複雜任務，模型可能難以區分「必要的驗證步驟」與「表演式推理的冗餘步驟」。此外，若正確性閘門的判定標準過於寬鬆，模型仍可能透過簡化關鍵推理環節來投機取巧，產生看似精簡實則錯誤的輸出。

**Q15：這項工作為未來提升智能體效率的研究指出了哪些方向？**
A：未來研究可探索以元學習預測不同任務的最小必要路徑，在執行前便動態規劃最精簡的工具呼叫策略。另一方面，發展能同時優化延遲、金錢成本與準確率的多目標強化學習演算法，將使效率優化更具實務意義。此外，將此框架擴展至多智能體協作場景，解決因協調溝通而產生的額外開銷，也是極具潛力的後續研究方向。

### 適用場景

1. **企業內部知識問答與研究助理**：部署於需要頻繁查詢外部資料庫、內部文件與網頁的企業環境，例如法務或市場研究部門。SlimSearcher 可將平均工具呼叫輪次降低 17%–58%，顯著減少搜尋引擎 API 與內部檢索系統的調用成本，同時維持答案準確度。

2. **自動化金融與法律盡職調查**：在需要跨多個網頁驗證數據、比對法條或追蹤財經訊息的長程任務中，避免智能體陷入「表演式推理」所產生的冗餘迴圈與死路分支，將調查時間從數百輪推理收斂至最小必要路徑。

3. **醫療資訊深度檢索系統**：針對需要整合最新醫學文獻、臨床指引與藥物資料的複雜查詢（如論文所述之醫療 AI 應用場景），透過帕雷托效率過濾剔除過度依賴外部搜尋的膨脹軌跡，讓模型優先動用內部知識處理常見問題，僅對高複雜度查詢啟動外部工具。

4. **大規模客戶服務代理**：在電商或電信產業的客服場景中，處理涉及庫存查詢、訂單追蹤與政策比對的開放式任務。透過自適應獎勵閘控抑制盲目工具依賴，降低每次對話的詞元消耗與延遲，提升即時回應體驗。

5. **競爭情報與內容策展平台**：用於自動化監控競品動態、彙整產業新聞或生成深度報告。效率感知訓練可避免智能體在資訊已充足時仍持續發起無意義的驗證步驟，直接輸出精煉摘要。

### 實作前置條件

**資料需求**
- 具備工具呼叫標註的軌跡資料集：需收錄智能體執行任務的完整行動路徑，包含每次搜尋引擎或程式碼解譯器的呼叫內容、對應觀察結果、推理鏈（Chain-of-Thought）以及最終答案正確性標籤。
- 效率指標標註：每條軌跡需記錄工具呼叫輪次、總詞元消耗與執行延遲，以便執行帕雷托效率過濾。
- 抽樣群組資料：強化學習階段需能批次採樣同一任務的多條軌跡，以計算相對效率錨點。

**運算資源**
- **監督式微調（SFT）**：至少 4–8 張 A100/H100 GPU，用於微調 7B–70B 參數等級的大型語言模型。
- **強化學習（RL）**：需額外配置 GPU 叢集支援 PPO 或類似演算法，並預留充足的外部工具 API 預算（搜尋引擎、瀏覽器自動化服務），因訓練過程中智能體將大量探索。
- **評測基準**：需能執行 GAIA、BrowseComp 或 XBenchDeepSearch 等長程基準測試的評估環境。

**技術能力**
- 熟悉 RLHF 流程與獎勵塑形（Reward Shaping），具備建構自訂獎勵函數的經驗。
- 掌握網頁智能體框架（如 BrowserUse、Playwright 或 Selenium）與分散式訓練（DeepSpeed / FSDP）。
- 具備建構正確性閘門（Correctness Gate）自動評判系統的能力，例如透過規則引擎或 GPT-4 等強模型進行答案比對。

### 實作步驟建議

**步驟一：建立認知基線與收集原始軌跡**
先以現有的以準確性為中心的訓練範式（Acc-only Rejection Sampling）訓練基線模型，讓其在目標任務上自由探索，收集大量成功與失敗的軌跡。此階段目的在於觀察並量化盲目工具依賴與表演式推理的發生頻率，作為後續優化的對照組。

**步驟二：帕雷托效率過濾與資料精煉**
對收集到的成功軌跡進行聯合評估：以「答案正確」為必要條件，篩選出同時具備低工具呼叫輪次與低詞元消耗的前緣樣本（Pareto-efficient）。剔除僅正確但路徑膨脹的負面教材，建構精煉的 SFT 訓練集，引導模型學習最小必要路徑的行為模式。

**步驟三：監督式微調（SFT）**
使用過濾後的精煉資料集對基礎模型進行 SFT。重點在於讓模型內化「效率感知」的搜尋策略：例如常識問題直接動用內部知識回答，複雜問題則規劃精簡的查詢序列，避免冗餘步驟。

**步驟四：實作自適應獎勵閘控（Adaptive Reward Gating）進行強化學習**
設計動態獎勵函數：針對每個訓練批次中的抽樣群組（Sampled Cohort），計算各軌跡的相對工具效率與詞元效率，並將其與嚴格的正確性閘門串接（Cascade）。只有通過正確性閘門的軌跡，才能獲得基於相對效率的額外獎勵。此設計可避免絕對懲罰所導致的簡潔偏誤，並抑制獎勵駭取。

**步驟五：長程基準測試與錯誤分析**
在 GAIA、BrowseComp 與 XBenchDeepSearch 上進行端到端評估。除了準確率，更需監控平均工具呼叫輪次、總詞元消耗與延遲。針對模型仍產生死路分支或過度簡短的案例，調整 RL 的獎勵權重或正確性閘門的嚴格程度。

**步驟六：生產環境部署與持續監控**
將訓練完成的 SlimSearcher 部署至生產環境，並建立即時觀測儀表板，追蹤每筆請求的工具呼叫次數與成本。針對真實使用者查詢設定回饋迴路，定期將新生成的高效率軌跡納入資料池，進行週期性微調。

### 潛在風險與注意事項

- **獎勵駭取與簡潔偏誤**：若正確性閘門設計不夠嚴謹，模型可能學會以過度簡短的軌跡騙取高效率獎勵，導致答案品質下滑。建議採用多維度正確性評判（例如事實正確性、邏輯完備性、引用完整性），並在獎勵閘控中維持「正確性優先、效率次之」的階層式結構。

- **外部工具 API 的成本與速率限制**：RL 訓練初期的探索行為可能產生巨量工具呼叫，造成搜尋引擎或瀏覽器自動化服務的帳單激增。建議在訓練前期使用快取機制儲存頻繁查詢結果，或設置單軌跡的最大呼叫上限（Hard Cap）。

- **分布偏移（Distribution Shift）**：基準測試中的網頁結構與真實網路環境可能存在差異，導致訓練時學到的最小必要路徑在實際部署時失效。建議保留一定比例的即時網頁資料於訓練與評估中，並設計線上適應（Online Adaptation）機制。

- **過度擬合特定基準測試模式**：模型可能針對 GAIA 或 BrowseComp 的常見題型記憶捷徑，而非真正學會效率推理。建議定期以未見過的任務類型進行零樣本（Zero-shot）壓力測試，檢驗泛化能力。

- **延遲與準確率的權衡誤判**：不同業務場景對延遲的容忍度不同（如客服要求秒級回應，研究助理可接受分鐘級）。部署前需依據產品需求重新校準帕雷托前沿，而非直接套用論文預設的獎勵權重。

### 與其他技術的整合建議

- **與 RAG 管線整合**：將 SlimSearcher 作為檢索增強生成（RAG）系統中的「智能檢索規劃器」。在發起向量資料庫或網頁搜尋前，先由 SlimSearcher 判斷是否可透過內部知識回答，或規劃最少的檢索步驟，降低向量搜尋與重排序的運算開銷。

- **結合模型蒸餾（Distillation）**：將經過 SlimSearcher 訓練後的大模型（如 70B）所產生的高效率軌跡，作為蒸餾資料來源，訓練更小的專用模型（如 7B–13B）。這可在邊緣裝置或低成本 API 服務上實現兼具準確率與效率的部署。

- **接入可觀測性平台**：整合 LangSmith、Weights & Biases 或自研監控系統，視覺化每條軌跡的工具呼叫圖譜與詞元消耗熱力圖。當發現異常的膨脹軌跡時，可即時觸發告警並回送資料至 RL 訓練管線。

- **搭配快取與記憶機制**：對於重複性高的常見查詢，在 SlimSearcher 前端部署語義快取層（Semantic Cache）。當快取命中時直接返回結果，完全規避工具呼叫；未命中時才啟動 SlimSearcher 的動態搜尋，形成雙層效率防護。

- **多智能體框架中的角色分工**：在 AutoGen 或類似多智能體架構中，將 SlimSearcher 設定為專責「資訊檢索與驗證」的角色，與負責程式碼生成或報告撰寫的其他智能體協作。其效率感知特性可避免檢索角色拖累整體任務的執行延遲。

### 給不同背景讀者的閱讀建議

**初學者**：建議先聚焦論文圖一與摘要，理解「效率陷阱」的核心概念——即追求準確率反而導致暴力策略與冗餘軌跡。掌握 SlimSearcher 的兩階段架構（SFT 過濾冗餘資料、RL 動態獎勵塑形）即可建立整體認知，無需深入數學推導，重點在於理解「為何不能只用正確性篩選訓練資料」。

**AI 工程師**：請仔細研讀帕雷托效率過濾的實作細節與自適應獎勵閘控的程式邏輯。特別注意論文中如何計算抽樣群組內的相對效率錨點，以及如何將正確性閘門與效率獎勵串接以避免簡潔偏誤。建議直接參考作者開源程式碼，關注軌跡資料格式、獎勵函數實作與基準測試的評估腳本，以確保訓練流程可復現。

**研究人員**：核心貢獻在於 Adaptive Reward Gating 的理論設計——透過相對效率評估而非絕對懲罰來引導行為，並以嚴格正確性閘門抑制獎勵駭取。建議深入分析作者對「盲目工具依賴」與「表演式推理」這兩種失效模式的拆解，以及其如何推動帕雷托前沿。可進一步思考如何將此獎勵塑形機制推廣至其他工具整合推理領域，例如多模態智能體或機器人任務規劃。

**產品經理**：請將閱讀重點放在實驗結果的商業意涵：17%–58% 的工具呼叫輪次降低直接對應 API 成本縮減與使用者等待時間縮短，而準確率維持或提升代表無需犧牲產品品質。需理解本方案適用於「長程、多步驟、高工具依賴」的場景，若產品僅涉及單輪問答則投資報酬率可能有限。建議與工程團隊討論時，以「最小必要路徑」作為產品設計語言，推動以效率為核心的智能體體驗優化。
