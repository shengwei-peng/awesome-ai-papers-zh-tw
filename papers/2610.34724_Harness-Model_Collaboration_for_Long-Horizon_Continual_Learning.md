HaMo（Harness-Model）框架的核心設計理念在於將持續學習（continual learning）拆解為兩個互補時間尺度的適應機制：快速的非參數化經驗累積（fast non-parametric experience accumulation）與慢速的參數化適應（slow parametric adaptation）。這種雙軌設計直接回應了長時程代理（long-horizon agents）在面對序列式分布偏移（sequential distribution shifts）時所遭遇的兩難困境——單純依賴模型層級適應（model-level adaptation）雖能產生持久行為能力（persistent behavioral competence），但更新成本高昂且容易引發災難性遺忘（catastrophic forgetting）；而單純依賴框架層級適應（harness-level adaptation）雖能立即重用經驗，卻無法讓模型內化（internalize）執行策略所需的程序性能力（procedural competence）。

**框架層級機制（Harness-Level Mechanism）**

在框架層級，HaMo 將每一條軌跡（trajectory）蒸餾為一張精簡的「策略層級經驗卡」（strategy-level experience card）。每張經驗卡包含三個核心要素：（1）任務情境（task context）、（2）初始條件（initial conditions）、以及（3）策略層級的解決方案綱要（strategy-level solution outline）。這種設計的關鍵在於「策略層級」的抽象粒度——既非原始的低階動作序列，也非過於抽象的高階概念，而是介於兩者之間、可被檢索並在不同環境中對接地（grounding）的程序性知識（procedural knowledge）單元。經驗卡被存入持久化的非參數化記憶體（persistent non-parametric memory），使新獲得的程序性知識能夠立即供未來任務使用，無需觸發參數更新。

**模型層級機制（Model-Level Mechanism）**

在模型層級，HaMo 採用單一的參數高效適配器（parameter-efficient adapter）進行持續更新，並結合歷史回放（historical replay）以緩解遺忘問題。值得注意的是，模型的訓練目標並非單純的「從情境到動作」的直接映射，而是「經驗條件式持續學習目標」（experience-conditioned continual learning objective）——模型在訓練時同時接收從框架檢索到的策略層級經驗，學習如何在不同觀察、物件、狀態與互動歷史下詮釋（interpret）並實例化（instantiate）該策略。這種條件式設計使得模型學會的是「如何使用經驗」的能力，而非僅僅是「如何完成任務」的能力。

**推論階段的介面統一**

HaMo 在訓練與推論階段使用相同的介面：框架負責檢索相關經驗，適配後的模型負責決定該經驗在當前環境中應如何執行。這種介面統一性確保了訓練與推論的一致性，避免了訓練-推論偏差（train-inference mismatch）。

**檢索覆蓋率選擇機制（Retrieval-Coverage-Based Selection）**

此機制解決了持續監督訊號的冗餘問題。雖然外部儲存經驗的成本低廉，但對所有觀察到的軌跡進行訓練是不必要的，因為許多軌跡編碼了相似的策略。HaMo 引入兩條選擇原則：（1）優先選擇能透過檢索支援許多其他任務的經驗（即高覆蓋率的經驗）；（2）所選集合應覆蓋不同的策略情境（即互補性）。前者透過檢索覆蓋率量化，後者透過策略情境的多樣性鼓勵。這種選擇機制將參數更新集中於廣泛可重用的程序性知識上，避免冗餘訓練。

**方法論的理論意涵**

從理論角度觀察，HaMo 的雙時間尺度設計與人類認知中的「快速學習—慢速鞏固」（fast learning-slow consolidation）機制具有結構上的相似性。經驗卡對應於工作記憶或情節記憶中的可快速提取元素，而參數更新則對應於睡眠期間的記憶鞏固過程。此外，「內化程序性能力」的目標超越了單純的記憶——它要求模型具備跨任務的遷移能力，這與傳統遷移學習（transfer learning）有所不同，因為後者通常假設有明確的源任務與目標任務劃分，而 HaMo 面對的是持續湧現的新任務流。

#### 實驗數據解讀

HaMo 在三個基準環境上進行評估：ScienceWorld、ALFWorld 與 WebShop，涵蓋域內偏移（within-domain shifts）與跨域偏移（cross-domain shifts）兩種設定。WebShop 提供互動式網頁代理環境，直接對應論文中強調的網頁代理應用場景；ScienceWorld 與 ALFWorld 則用於驗證所提出的學習機制是否能泛化至單一領域之外。

**核心實驗結論**

實驗結果揭示了清晰的互補性模式：
- **僅框架學習（harness-only）**：能實現經驗的快速重用，但會遭遇性能平台期（plateau），無法持續提升。
- **僅模型學習（model-only）**：能獲得強任務特定能力，但在分布偏移下遭受顯著的災難性遺忘。
- **HaMo（框架-模型協作）**：結合兩者優勢，實現更強的持續適應能力，同時更好地保留先前獲得的能力。

**指標層面的解讀**

論文中強調的兩個關鍵指標為「保留能力」（retention）與「適應能力」（adaptation）。這兩個指標的設計反映了持續學習的核心張力——既要記住舊的，又要學會新的。HaMo 在兩者上的同時提升，意味著它並非以犧牲一方為代價換取另一方，而是真正實現了雙贏。這對於實際部署的長時程代理至關重要，因為使用者既期望代理能記住過去的成功經驗，也期望它能適應新的任務變化。

**跨域設定的意義**

跨域偏移（cross-domain shifts）的實驗尤為重要，因為它模擬了代理在真實世界中面臨的場景變化——例如從一個網站遷移到另一個結構迥異的網站。在這種設定下，僅模型學習的遺忘問題會被放大，因為不同領域的策略可能相互干擾。HaMo 的框架層級經驗卡在此提供了「策略隔離」的效果——不同領域的經驗被獨立儲存，避免了參數空間中的直接衝突。

**選擇機制的有效性**

雖然論文中未提供選擇機制的詳細消融數據，但從方法論推斷，檢索覆蓋率選擇機制應在兩個層面產生效益：（1）減少訓練計算量，因為只需對精選軌跡進行參數更新；（2）提升訓練訊號品質，因為所選軌跡具有更高的覆蓋率與互補性。這對於長期部署的代理尤為重要，因為隨著時間推移，累積的軌跡數量會迅速膨脹，若無有效選擇機制，訓練成本將不可持續。

現有的外部記憶方法（如基於文字回饋、技能、工作流或結構化記憶的系統）主要關注「如何儲存」與「如何檢索」，但 HaMo 進一步追問「哪些經驗應保留為可檢索形式，哪些應驅動參數更新」。這種雙層次的決策框架是 HaMo 相對於純外部記憶方法的關鍵差異。

參數化持續學習方法（如參數保護、回放、持續策略適應、多重保留錨點）主要關注「如何更新參數而不遺忘」，但 HaMo 將部分適應責任外包給了非參數化記憶，從根本上改變了問題的結構。這種設計避免了參數空間中所有知識的擁擠，也降低了災難性遺忘的風險。

EvolvingAgent 結合了演化經驗與持續世界模型學習，與 HaMo 在「結合外部經驗與內部學習」這點上有共通之處。然而，HaMo 的獨特之處在於：（1）明確區分了策略層級與動作層級的抽象；（2）引入了檢索覆蓋率選擇機制來控制訓練集；（3）強調了「程序性能力」的內化，而非僅僅是策略的儲存。

Dong et al. 強調了外部經驗與內化能力之間的更廣泛連結，HaMo 可被視為這一觀點的具體實作——它不僅概念性地連結兩者，更提供了可操作的機制來協調兩者的時間尺度。

1. **時間尺度分離**：明確區分快速重用與慢速內化，避免了兩者的相互干擾。

3. **適配器架構**：參數高效適配器的具體形式（如 LoRA、Adapter、Prefix Tuning）會顯著影響結果。
4. **持續學習的任務序列**：實驗結果高度依賴於任務序列的設計，不同的序列可能導致不同的結論。

**建議的重現策略**

對於希望重現此研究的團隊，建議：
1. 優先聯繫作者取得程式碼（若尚未公開）。
2. 若無法取得，應從論文中提取所有超參數與架構細節，並在 ScienceWorld 上進行小規模驗證。
3. 特別注意經驗卡蒸餾的提示模板，因為這是品質的關鍵決定因素。
4. 在跨域實驗中，謹慎控制任務序列的隨機性，以確保結果的可比較性。

#### 未來研究方向

**短期延伸方向**

1. **更豐富的經驗抽象層次**：目前的經驗卡採用單一抽象層次，未來可探索多層次經驗表示——例如同時儲存高階策略、中階子程序與低階動作模板，以支援不同粒度的重用需求。

2. **動態適配器組合**：當前的單一參數高效適配器可能在跨域設定下面臨容量限制。未來可探索動態適配器組合機制，根據當前任務的領域自動選擇或組合不同的適配器子集。

3. **檢索機制的深化**：現有的檢索機制（推測為基於相似度的匹配）可進一步深化，例如引入基於因果推理的檢索，或基於策略效果預測的檢索，以提升檢索的精確性。

**中期探索方向**

4. **理論分析**：HaMo 的雙時間尺度設計缺乏形式化的理論分析。未來可從優化角度探討快速重用與慢速內化之間的收斂性，從遺忘動態角度分析框架層級如何緩解參數空間中的災難性遺忘。

5. **與人類反饋的整合**：在真實部署中，代理可能會收到來自使用者的人類反饋（human feedback）。未來可探索如何將人類反饋整合進 HaMo 的雙層機制——例如將人類反饋作為高品質的經驗卡來源，或作為參數更新的額外監督訊號。

6. **多代理協作場景**：當多個代理同時運行時，它們的經驗可以共享。未來可探索分散式 HaMo，其中多個代理的經驗卡被彙聚到共享記憶體中，同時各自的模型參數保持獨立，從而實現「經驗共享但能力專精」的協作模式。

**長期願景方向**

7. **從程序性知識到程序性推理**：目前的 HaMo 側重於「執行已知策略」，未來可探索「推導新策略」的能力——即從累積的經驗卡中歸納出更高階的策略模板，並將其應用於前所未見的任務結構。

8. **與世界模型的整合**：若代理具備環境的世界模型（world model），則可在內部模擬中測試檢索到的策略，預測其效果後再執行。這將使 HaMo 從「被動重用」進化為「主動驗證」，進一步提升可靠性。

9. **安全與可解釋性**：隨著代理在真實世界中承擔更重要的任務，其決策的可解釋性變得至關重要。HaMo 的經驗卡天然提供了決策的可解釋性——每個動作都可追溯到特定的經驗卡。未來可探索如何進一步形式化這種可解釋性，使其滿足監管與審計需求。

10. **終身學習的硬體支援**：隨著經驗卡數量的持續增長，檢索效率成為瓶頸。未來可探索專門的硬體支援（如基於內容可定址記憶體（CAM）的近記憶體檢索），以支援終身學習場景下的即時檢索需求。

總體而言，HaMo 提出了一個優雅的雙時間尺度框架，解決了長時程代理持續學習中的核心張力。其核心洞見——「快速重用與慢速內化應被視為互補而非替代」——具有超越具體方法的普適價值，為未來的終身學習代理研究提供了重要的設計原則。

## 論文問答

**Q1：為什麼長時程代理需要持續學習機制？**
A：長時程互動自然會產生可重用的程序性知識，例如網頁代理反覆執行的資訊搜尋、產品搜尋、交易型任務等多步驟工作流程。然而，缺乏跨任務學習機制的代理會把每個任務視為獨立回合，無法系統性地累積經驗。換言之，今天完成一個長時程任務所獲得的策略，理應能讓代理明天在相關任務上表現得更好，這正是持續學習機制要解決的核心問題。

**Q2：為什麼僅依靠模型層級適應不足以解決問題？**
A：模型層級適應雖然能將過去的互動轉化為持久行為能力，但頻繁的參數更新成本高昂，且在序列式分布偏移下容易干擾先前獲得的能力，引發災難性遺忘。這意味著單純依賴參數更新的方法難以兼顧穩定性與適應性——模型可能在某些任務上變強，卻在其他任務上退化。論文的圖1清楚展示了模型單獨適應時的不穩定性與遺忘問題。

**Q3：為什麼僅依靠框架層級適應也不足夠？**
A：框架層級適應透過外部儲存經驗並檢索，能讓新獲得的知識立即影響行為而無需重新訓練，但模型本身並不一定會變得更善於解釋和執行檢索到的經驗。這使得框架層級方法雖然能快速重用經驗，卻容易達到性能平台期，無法持續提升。論文的圖1顯示harness-only方法雖然起步快，但很快就停滯不前。

**Q4：HaMo框架的核心方法是什麼？**
A：HaMo將適應過程分離為兩個緊密耦合的機制：在框架層級，每條軌跡被蒸餾成包含任務情境、初始條件和策略層級解決方案綱要的精簡經驗卡，儲存在持久非參數化記憶中，使新獲得的程序性知識立即可用於未來任務。在模型層級，HaMo使用選定的軌跡結合歷史回放，持續更新單一參數高效適配器，提升模型利用累積經驗的同時保留先前獲得的能力。

**Q5：經驗條件式適應的關鍵創新是什麼？**
A：經驗條件式適應讓模型不僅學習從互動情境到動作的直接映射，還額外以從框架檢索到的策略層級經驗為條件。這使模型學會如何在不同觀察、物件、狀態和互動歷史下解釋並實例化檢索到的策略，推理時使用相同介面：框架檢索相關經驗，適應後的模型決定該經驗應如何在當前環境中執行。這種設計讓框架保留可重用的程序性知識，而模型適應則逐步內化跨任務轉移和執行該知識的能力。

**Q6：為什麼需要基於檢索覆蓋率的選擇機制？**
A：雖然外部儲存經驗成本低廉，但對每條觀察到的軌跡重複訓練並無必要，因為許多軌跡編碼相似的策略。基於檢索覆蓋率的選擇機制能識別一組精簡且具代表性的互補軌跡進行參數適應——優先選擇能透過檢索支援許多其他任務的經驗，同時鼓勵選定集合覆蓋不同的策略情境。這種機制將參數更新集中於廣泛可重用的程序性知識，避免冗餘訓練造成的計算浪費和潛在的負面干擾。

**Q7：HaMo在哪些基準上進行評估？**
A：HaMo在ScienceWorld、ALFWorld和WebShop三個基準上進行評估，涵蓋域內偏移和跨域偏移兩種設定。WebShop提供互動式網頁代理環境，直接對應論文的Web agent應用場景，而ScienceWorld和ALFWorld則用於測試所提出的學習機制是否能泛化到單一領域之外。這種多基準設計有助於驗證HaMo在不同類型長時程任務中的通用性。

**Q8：HaMo的主要實驗結果是什麼？**
A：實驗結果顯示框架層級和模型層級適應之間存在明顯的互補性：僅框架學習能快速重用經驗但達到性能上限，而僅模型適應能獲得強大的任務特定能力但在分布偏移下遭受嚴重遺忘。HaMo結合兩者優勢，在域內偏移下實現穩定提升，在跨域偏移下更好地保留先前獲得的能力。這些結果凸顯了聯合保留程序性經驗和內化跨任務執行能力的重要性。

**Q9：HaMo的消融研究揭示了哪些設計選擇的重要性？**
A：從方法描述可推斷經驗卡設計、經驗條件式訓練目標和檢索覆蓋率選擇機制都是關鍵組件，每一個都對應特定的設計動機：經驗卡實現快速重用、條件式目標實現內化、選擇機制避免冗餘訓練。論文的整體實驗結果——HaMo同時優於harness-only和model-only——本身就構成了一種隱式消融，證明了兩個層級缺一不可。

**Q10：HaMo在實際網頁代理場景中有哪些應用？**
A：在實際網頁代理場景中，HaMo可用於電子商務平台、客戶服務系統和資訊聚合工具等需要反覆執行多步驟工作流程的應用。例如，代理可以從先前的產品搜尋和交易任務中累積策略，快速適應新商品類別，同時保留處理退款、查詢物流等已學會的工作流程能力。這種持續學習能力對於長期運行的生產環境尤為重要，因為任務分布會隨時間漂移。

**Q11：部署HaMo時需要考慮哪些產品化因素？**
A：產品化部署需考慮：經驗卡的儲存規模與檢索效率的平衡、參數高效適配器的更新頻率與計算成本、跨域偏移下的記憶管理策略，以及如何處理隱私敏感的軌跡資料。此外，框架與模型之間的介面設計需要標準化，以便支援不同基礎模型和任務領域。實際部署時還需設計監控機制，追蹤經驗檢索命中率、模型適應效果等關鍵指標。

**Q12：HaMo對持續學習和代理研究領域有何影響？**
A：HaMo強調了聯合保留程序性經驗和內化跨任務轉移執行能力的重要性，挑戰了將模型適應和外部記憶視為互斥方案的傳統觀點。這種雙時間尺度協調的思路——快速非參數化重用加上慢速參數化內化——可能啟發後續研究探索其他互補機制的組合，例如推理時計算與經驗重用的結合，或符號化知識與神經網路參數的協同演化。

**Q13：HaMo有哪些已知的局限性？**
A：從方法描述可推斷HaMo的局限性包括：經驗卡的蒸餾品質依賴於底層模型的摘要能力，若蒸餾失敗則後續檢索和訓練都會受影響；參數高效適配器雖然比完整微調更輕量，但仍需定期更新；選擇機制可能遺漏某些罕見但重要的策略；以及在極大規模任務流中，外部記憶的擴展性和檢索延遲可能成為瓶頸。

**Q14：HaMo在哪些情況下可能失敗？**
A：HaMo可能在以下情況下表現不佳：當任務之間缺乏可重用的策略結構時（例如完全隨機或對抗性環境），經驗卡的價值有限；當經驗檢索失敗時，模型可能缺乏足夠的獨立解決能力；當分布偏移極為劇烈使得檢索到的經驗產生負面遷移時，反而會干擾當前任務；以及在多語言或多模態場景中，經驗卡的表示可能無法充分捕捉任務語義。

**Q15：HaMo的未來研究方向是什麼？**
A：未來研究方向可能包括：將HaMo擴展到多代理協作場景，讓代理之間共享經驗卡以加速集體學習；結合更強的推理模型來提升經驗蒸餾品質；探索理論框架來分析雙時間尺度學習的收斂性和遺忘邊界；以及將該方法應用於機器人、遊戲AI等其他長時程領域，驗證其在不同環境下的泛化能力。

## 實務應用指南

### 適用場景

HaMo 框架特別適合以下需要「跨任務累積程序性知識」的長時程代理應用：

1. **電商營運助理（WebShop 類場景）**：每日處理大量重複性的商品上架、價格調整、促銷設定、訂單查詢等工作流程。HaMo 可將「處理退貨流程」「比價並下單」「跨平台搬運商品資訊」等策略蒸餾為經驗卡，後續相似任務即時檢索；同時透過參數化適應讓模型學會在不同商店介面、不同促銷規則下執行相同策略。

2. **企業內部 SaaS 操作代理**：在 ERP、CRM、HR 系統中執行多步驟工作流，例如「季末結帳」「新人到職設定」「客戶投訴升級處理」。同一公司內不同部門的流程高度相似但介面欄位略有差異，HaMo 的跨域保留能力可避免模型在學習新部門流程時遺忘舊部門的處理方式。

3. **IT 維運與故障排除代理**：處理重複出現的伺服器告警、網路診斷、補丁部署等 runbook。HaMo 能將「某類告警的標準排查步驟」存為經驗卡立即重用，同時讓模型內化「如何把通用策略對接到當前主機的特定環境（IP、服務版本、依賴）」的程序性能力。

4. **科學研究助理（ScienceWorld 類場景）**：在模擬實驗環境中執行「測量物質沸點」「配製特定濃度溶液」「驗證化學反應」等多步驟實驗。研究者會反覆執行相似實驗但每次條件不同，HaMo 可累積實驗策略並在不同器材、不同初始條件下穩定執行。

5. **智慧家居與 IoT 排程代理**：管理跨裝置的場景聯動（「早晨起床」「離家模式」「睡眠模式」），每個場景涉及多個裝置的協調操作。HaMo 可將成功的聯動策略沉澱為經驗卡，並在使用者新增裝置或調整習慣時持續適應而不遺忘既有偏好。

### 實作前置條件

**資料需求**
- 一組長時程任務環境（建議從 WebShop、ALFWorld、ScienceWorld 等開源基準起步，再遷移至自有環境）
- 每個任務至少需要數十至數百條成功軌跡作為初始經驗來源；軌跡需包含任務描述、初始狀態、完整動作序列、最終結果
- 領域內與跨域任務分流的標註或環境配置，用以驗證保留能力
- 用於評估的任務集需涵蓋「已見任務」「域內新任務」「跨域新任務」三類

**運算資源**
- 基底模型建議為 7B–70B 等級的開源 LLM（如 Llama 3、Qwen 2.5），需具備長上下文視窗（≥8K tokens）以容納軌跡與經驗卡
- 訓練階段：單張 A100/H100 等級 GPU 即可執行 LoRA/QLoRA 等參數高效微調；若使用更大模型需多卡並行
- 推理階段：需支援向量檢索（如 FAISS、Milvus、Qdrant）的服務，端到端延遲需控制在可接受範圍（建議 <2 秒）
- 儲存：經驗卡資料庫規模隨任務量線性成長，需預留可擴展的向量索引空間

**技能前提**
- 熟悉 LLM 微調流程（PEFT、LoRA、adapter 合併）
- 具備 prompt engineering 與策略蒸餾（trajectory summarization）能力
- 了解向量檢索與語意相似度計算
- 具備 continual learning 評估經驗（避免資料洩漏、區分 within-domain 與 cross-domain 設定）
- 對自家業務流程具備 domain knowledge，能撰寫高品質的策略模板

### 實作步驟建議

**階段一：環境與基準建立（2–4 週）**
1. 選定目標業務場景，盤點可重用的多步驟工作流程
2. 蒐集並清洗歷史軌跡資料，標註成功/失敗與任務類型
3. 建立「域內任務集」與「跨域任務集」兩套評估基準
4. 選定基底模型並部署推理服務

**階段二：經驗卡蒸餾管線（3–5 週）**
1. 設計經驗卡 schema：任務情境、初始條件、策略級解決綱要、關鍵動作摘要
2. 實作 trajectory-to-card 蒸餾模組（可使用較強的 LLM 作為蒸餾器）
3. 建立向量索引並實作檢索介面（top-k 相似度檢索 + 篩選機制）
4. 驗證「檢索到的經驗卡」對人類或強模型而言是否真的可執行

**階段三：經驗條件式適配器訓練（4–6 週）**
1. 設計 experience-conditioned 訓練格式：將檢索到的經驗卡與當前任務情境拼接後再產生動作
2. 實作 retrieval-coverage-based 選擇機制：優先選擇能覆蓋多數其他任務的軌跡進入訓練集
3. 加入歷史 replay buffer 以緩解災難性遺忘
4. 以 LoRA/QLoRA 訓練參數高效適配器，並定期評估保留率

**階段四：上線與持續運作（持續）**
1. 部署「harness 檢索 + 模型執行」的雙層推理管線
2. 設定觸發條件：當新軌跡累積到一定量或檢索覆蓋率變化時觸發再訓練
3. 建立監控儀表板：保留率、適應速度、檢索命中率、人工介入率
4. 設計 A/B 框架，比較 HaMo 與純 prompt / 純微調方案的實際表現

**階段五：跨域遷移驗證（2–3 週）**
1. 引入新領域任務，驗證模型是否保留舊領域能力
2. 調整經驗卡 schema 與選擇機制的權重
3. 收集失敗案例並回饋至蒸餾管線

### 潛在風險與注意事項

**風險一：經驗卡品質不穩定**
- *現象*：蒸餾出的策略過於籠統或過於具體，導致檢索後無法有效執行
- *緩解*：建立人工抽檢機制；以「執行成功率」作為蒸餾器的隱式獎勵；保留原始軌跡作為 fallback

**風險二：災難性遺忘仍可能發生**
- *現象*：跨域任務大量湧入時，舊領域表現顯著下滑
- *緩解*：嚴格執行 replay buffer 比例（建議 ≥20%）；定期評估 backward transfer；採用多個 retention anchor 而非單一適配器

**風險三：檢索覆蓋率偏差**
- *現象*：選擇機制偏好「被檢索次數高」的軌跡，造成訓練集過於集中、缺乏多樣性
- *緩解*：在選擇函數中加入 diversity bonus；監控策略類型分布；定期注入長尾任務

**風險四：經驗卡資料庫膨脹導致延遲**
- *現象*：隨時間累積，檢索時間與上下文長度都增加
- *緩解*：定期合併相似經驗卡；採用分層索引（粗排 + 精排）；設定經驗卡生命週期

**風險五：基底模型升級導致既有適配器失效**
- *現象*：更換基底模型後，原本的 LoRA 權重無法直接遷移
- *緩解*：保留訓練資料與蒸餾管線，重新微調；設計基底模型無關的經驗卡 schema

**風險六：評估偏差**
- *現象*：在自家資料上表現良好，但基準測試（如 ScienceWorld）表現不佳
- *緩解*：堅持使用公開基準做為 sanity check；避免在評估集中混入訓練軌跡

### 與其他技術的整合建議

1. **與 RAG 系統整合**：HaMo 的經驗卡本質上是結構化記憶，可與企業既有的 RAG 知識庫共用向量索引基礎設施。建議將「程序性經驗」與「事實性知識」分開儲存，但共用檢索層。

2. **與 Agent 框架整合（LangChain、AutoGen、CrewAI）**：將 HaMo 的 harness 層實作為 agent 的 tool/retriever，模型層則作為 agent 的核心 LLM。可在現有框架中以 middleware 形式接入，無需重寫整個代理。

3. **與 RLHF / DPO 流程整合**：將人類對「執行結果」的偏好回饋作為經驗卡的品質分數，或作為模型適配器的獎勵訊號，進一步提升策略選擇的精準度。

4. **與監控與可觀測性平台整合（Langfuse、Phoenix、Datadog）**：把經驗卡的檢索、命中率、執行成功率納入追蹤，方便診斷「為什麼某個任務失敗」。

5. **與工作流程自動化平台整合（Zapier、n8n、Airflow）**：將 HaMo 蒸餾出的策略卡同步至自動化平台，讓人類使用者也能檢視與編輯，促進人機協作。

6. **與多代理系統整合**：不同代理可共享同一個經驗卡資料庫，但各自維護獨立的適配器，避免互相干擾。

### 給不同背景讀者的閱讀建議

**給初學者**：先閱讀第 1 節的動機圖（Figure 1）理解「為什麼需要同時做 harness 與 model 兩層適應」，再跳到第 3 節 Method 了解經驗卡的結構。建議搭配閱讀 RAG 與 LoRA 的基礎教學，建立術語基礎後再回頭看細節。

**給 AI 工程師**：重點關注第 3 節的「experience-conditioned 訓練格式」與「retrieval-coverage-based 選擇機制」——這兩個是工程實作的核心。建議直接動手在 WebShop 或 ALFWorld 上重現最小可行版本，再逐步替換為自有資料。

**給研究者**：第 2 節 Related Work 提供了 continual learning 與 long-horizon agent 的完整脈絡；建議進一步追蹤 EvolvingAgent（文獻 [6]）與 Dong et al.（文獻 [4]）的原始論文，理解 HaMo 在「外部經驗 vs. 內化能力」光譜上的定位。可考慮的延伸方向：選擇機制的理論分析、跨域遷移的理論保證、與世界模型學習的結合。

**給產品經理**：聚焦於第 1 節的問題陳述與第 4 節以後的實驗結論，理解「harness-only 會遇到天花板」「model-only 會遺忘」「HaMo 兩者兼顧」這個 trade-off。在評估導入時，應優先盤點自家業務中「重複但有變化」的工作流程比例，這是 HaMo 價值最大的場景。
