## ⚡ TL;DR

線上策略自蒸餾中特權資訊的內容與建構方式影響訓練成效，但缺乏事前評估方法。
本文系統評估十六種特權資訊配置，並提出基於 KL 散度的離線指標以預測其效用。
結果顯示資訊密集軌跡效果最佳，錯誤步驟 KL 對比能有效引導特權資訊選擇，且結合 GRPO 可超越基線。

## 摘要翻譯

線上策略自蒸餾（On-policy self-distillation, OPSD）使大型語言模型（Large Language Models, LLMs）能夠在沒有獨立教師模型的情況下從特權資訊（Privileged Information, PI）中學習。然而，先前的研究大多將 PI 視為固定的設計選擇，使其內容與建構方式的影響仍未被充分理解。這項挑戰在多輪代理設定（multi-turn agentic settings）中尤為重要，因為軌跡（trajectories）包含動作（actions）、觀察（observations）和推理（reasoning），可以多種方式轉換為 PI。我們在三個多輪代理基準（multi-turn agentic benchmarks）和三個在規模與推理模式上不同的學生模型（student models）上，系統性地評估了 16 種 PI 配置。我們發現 PI 的有效性取決於其內容、生成來源（generation source）和學生模型。資訊密集軌跡（information-dense trajectories）和由更有能力的生成器（capable generators）所產生的 PI 通常能帶來更大的增益，而思考模型（thinking models）則受益情況較不一致。為了在訓練前評估 PI，我們將 PI 效用（PI utility）與兩個基於 KL 的指標進行比較：採樣 token 反向 KL（sampled-token reverse KL, D）和錯誤步驟 KL 對比（error-step KL contrast, Δd⁻_err）。基於 KL 的指標比 PI 效用更能持續地追蹤訓練後效能（post-training performance），而 PI 效用可能會因資訊洩漏（information leakage）而失真。實證上，透過 Δd⁻_err 為每個任務選擇 PI，相較於隨機選擇（random selection）也能改善訓練後效能，當 PI 候選（PI candidates）之間差異較大時效果最為顯著。最後，有效的 PI 在與 GRPO（Group Relative Policy Optimization）結合時仍然有益，使組合目標（combined objective）能夠超越強 GRPO 基線（strong GRPO baseline）。總體而言，我們的結果為 OPSD 訓練中 PI 的建構與評估提供了實用指導（practical guidance）。

### 核心貢獻（3～5點）
- **系統性實證分析**：在三個多輪代理基準（ALFWorld、AppWorld、τ2-retail）與三個不同規模及推理模式的學生模型上，評估了 16 種 PI 配置，揭示 PI 有效性取決於其內容、生成來源與學生模型本身。
- **關鍵依賴因素發現**：資訊密集軌跡與由更有能力的生成器所產生的 PI 通常帶來更大增益；然而思考模型受益情況較不一致，顯示 PI 設計需考量學生模型特性。
- **訓練前預測指標**：提出以 KL 為基礎的指標（採樣 token 反向 KL D 與錯誤步驟 KL 對比 Δd⁻_err）作為 PI 預選工具，其追蹤訓練後效能的能力優於 PI 效用，且不受資訊洩漏失真影響。
- **實務選擇策略驗證**：實證顯示以 Δd⁻_err 為每個任務預選 PI，相較於隨機選擇能穩定改善訓練後效能，且當 PI 候選之間差異較大時效果最為顯著。
- **與 GRPO 的相容性**：證實有效的 PI 與 GRPO 結合時仍具加成效用，組合目標能超越強 GRPO 基線，為 OPSD 訓練中的 PI 建構與評估提供實用指導。

### 適合對象
從事大型語言模型訓練（特別是線上策略自蒸餾、強化學習如 GRPO）的機器學習研究人員與工程師；關注多輪代理（agentic LLM）後訓練方法、模型自我改進與知識蒸餾的學者；以及需要在編碼代理（coding agents）或長期專業任務（long-horizon professional tasks）等代理領域（agentic domains）中設計有效訓練訊號（training signals）的實務團隊。

## 深度分析

#### 方法論解析

本文的核心方法論建立在**線上策略自蒸餾 (On-Policy Self-Distillation, OPSD)** 框架之上，並系統性地探討**特權資訊 (Privileged Information, PI)** 的設計與評估機制。OPSD 的關鍵創新在於消除對獨立教師模型的需求——學生與教師共用參數 θ，但僅教師能觀察 PI。具體而言，給定學生軌跡 τ = (y₁, ..., y_Lτ)，其中 s_t 為 token y_t 之前的上下文，OPSD 透過最小化學生策略 π^S_θ 與 PI 條件化教師策略 π^T_θ 之間的**反向 KL 散度 (KL divergence, D_KL)** 來進行訓練：

$$L_{OPSD}(\theta) = E_{\tau \sim \pi^S_\theta}\left[\frac{1}{L_\tau}\sum_{t=1}^{L_\tau} D_{KL}\left(\pi^S_\theta(\cdot|s_t) \| sg[\pi^T_\theta(\cdot|s_t, I)]\right)\right]$$

此處 sg 表示停止梯度傳播，確保教師僅作為監督訊號來源而不被反向傳播更新。

**PI 格式的系統化設計**是本文方法論的核心。本文將 PI 劃分為兩大類共七種格式：

1. **軌跡類 (Trajectories)**：從專家模型採樣成功軌跡，並保留不同組成部分——僅動作 (Action, A)、動作加觀察 (Action + Obs., A+O)、動作加思考 (Action + Thou., A+T)、以及完整版本 (Action + Obs. + Thou., A+O+T)。此設計旨在隔離有效 PI 是否僅需專家動作、環境脈絡或推理過程。

2. **壓縮提示類 (Compressed hints)**：包含三種形式——**摘要 (Summary)** 為軌跡的簡明概述；**技能 (Skill)** 包含錯誤分析與可重複使用的策略；**檢查清單 (Checklist)** 源自參考軌跡與失敗學生軌跡的任務需求。

**離線指標 (Offline metrics) 的設計**是本文另一方法論亮點，用於在訓練前評估 PI 品質：

- **PI 效用 (PI utility)**：比較教師在有/無 PI 時的獎勵增益，但易受**資訊洩漏 (information leakage)** 影響而失真。
- **採樣 token 反向 KL (Sampled-token reverse KL, D)**：測量 PI 在學生採樣 token 上引起的機率偏移幅度，但不指示偏移方向是否有利。
- **錯誤步驟 KL 對比 (Error-step KL contrast, Δd⁻_err)**：測量 PI 是否在已識別錯誤處比同一任務的匹配步驟更強烈地抑制 token，是方向性指標。

**實驗設計**涵蓋三個多輪代理基準 (multi-turn agentic benchmarks)：ALFWorld、AppWorld 與 τ2-retail，以及三個學生模型——Qwen3-4B-Instruct、Qwen3-4B-Thinking 與 Qwen3-30B-A3B-Instruct，橫跨指令模型與**思考模型 (thinking models)** 以及不同模型規模。PI 由 GLM-5.2 與 Qwen3.7-Plus 兩種生成器產生，共形成 16 種 PI 配置組合。

#### 實驗數據解讀

**PI 內容對有效性的影響**：實驗結果顯示**資訊密集軌跡 (information-dense trajectories)** 通常優於壓縮提示。在 ALFWorld 與 AppWorld 上，加入環境觀察 (A+O) 一致性地提升 Instruct 學生的表現。然而，額外的教師推理對思考模型的增益較不穩定，有時甚至降低其表現。這暗示思考模型本身已具備內在推理能力，額外的推理 PI 可能造成冗餘或干擾。

**PI 來源與生成器能力**：在提示格式中，**技能 (Skill)** 通常最強，顯示包含錯誤分析與可重複使用策略的指導比純粹的軌跡摘要更有效。更關鍵的是，**有能力的生成器 (capable generators)** 傾向產生更有效的 PI，特別是對於提示格式——這表明 PI 品質同時取決於格式與來源。

**離線指標的預測能力**：

- **PI 效用** 因資訊洩漏而不可靠。圖 3 的控制實驗顯示，PI 效用可被資訊洩漏膨脹或壓低，使其無法作為可靠的預測指標。
- **採樣 token 反向 KL (D)** 在九個設定中的八個能追蹤訓練後效能，但無法捕捉偏移方向——可能將有害的偏移也視為高分。
- **錯誤步驟 KL 對比 (Δd⁻_err)** 是最可靠的指標，能區分有用 PI 與僅使教師在 PI 存在時更強的資訊。當 PI 候選在來源或強度上差異較大時，使用 Δd⁻_err 進行逐任務 PI 選擇比隨機選擇更能提升訓練後效能。

**與 GRPO 的組合**：使用最有效的 PI 格式時，OPSD 與 GRPO 的組合目標能超越強 GRPO 基線。這表明 PI 並非與強化學習方法競爭，而是互補——PI 提供密集的 token 級監督訊號，而 GRPO 提供序列級獎勵訊號。

**模型規模與推理模式的差異**：思考模型 (Qwen3-4B-Thinking) 從 PI 中獲益較不穩定，可能因為其內建推理機制已部分內化了 PI 所提供的資訊。Instruct 模型則更穩定地從資訊密集軌跡中獲益，特別是包含環境觀察的版本。

#### 與現有研究的比較

**相較於既有 OPSD 研究的改進**：

1. **PI 設計的系統化**：既有研究如 Penaloza et al. [19]、Wang et al. [26]、Zhou et al. [33] 等僅評估有限的 PI 格式與模型組合。本文首次進行跨 16 種 PI 配置、3 個基準、3 個學生模型的受控研究，填補了「PI 內容與建構如何影響 OPSD」這一知識缺口。

2. **離線評估指標的提出**：既有工作將 PI 視為固定設計選擇，缺乏訓練前評估機制。本文提出的兩個 KL 診斷指標——特別是 Δd⁻_err——使研究者能在昂貴的 OPSD 訓練前篩選 PI 候選，節省大量計算資源。

3. **資訊洩漏問題的識別**：本文明確指出 PI 效用指標的局限性，並透過控制實驗展示其失真機制，這是先前研究未充分探討的問題。

**相較於獨立教師蒸餾的優勢**：傳統蒸餾需要維護一個獨立的教師模型，成本高昂且可能存在訓練-推論不一致問題。OPSD 透過共用參數消除此問題，已被用於訓練 Composer 2.5 等編碼代理 (coding agents) 與長期專業任務 (long-horizon professional tasks) 代理 [4, 8]。本文進一步推進此方向，探討在無獨立教師的情況下如何最大化 PI 的效用。

**相較於 GRPO 等強化學習方法**：GRPO 等方法依賴獎勵訊號，在稀疏獎勵環境中可能面臨探索困難。OPSD 提供密集的 token 級監督，與 GRPO 形成互補。本文證實兩者組合能超越純 GRPO 基線，為代理訓練提供了新範式。

**局限性**：

1. **基準與模型的範圍**：僅在三個多輪代理基準與三個 Qwen 系列模型上評估，結論的泛化性需在更多基準（如網頁代理、工具使用）與其他模型家族（如 Llama、Claude）上驗證。

2. **PI 生成器的限制**：僅使用 GLM-5.2 與 Qwen3.7-Plus 兩種生成器，未涵蓋更廣泛的開源與閉源模型。

3. **計算成本**：雖然 Δd⁻_err 比完整 OPSD 訓練便宜，但仍需在學生採樣的軌跡上計算 KL 散度，對於長軌跡任務仍有計算負擔。

4. **思考模型表現不穩定的根因**：本文觀察到思考模型從 PI 中獲益不穩定，但未深入分析其機制——是因為思考模型已內化類似推理？還是因為 PI 與其推理風格衝突？

## 論文問答

**Q1：這篇論文主要解決什麼核心問題？**
A：這篇論文聚焦於線上策略自蒸餾（OPSD）中特權資訊（PI）的有效性預測問題。傳統上，PI 在 OPSD 中被視為固定的設計選擇，但其內容與建構方式對訓練成效的影響卻缺乏系統性理解。具體而言，論文試圖回答：哪些 PI 格式、生成來源與學生模型組合能產生最佳學習訊號，以及能否在訓練前預測 PI 的品質，從而避免昂貴的反覆試錯。

**Q2：為什麼現有的 OPSD 研究無法充分理解 PI 的效果？**
A：現有研究通常僅評估有限的 PI 格式，且僅在少量模型與任務上進行測試，難以歸納出普遍性的結論。此外，多數研究將 PI 視為固定的設計選擇，未深入探討其內容、來源與學生模型之間的交互作用。這種不足在多輪代理設定中尤其明顯，因為軌跡中的動作、觀察與推理可被轉化為多種 PI 形式，使得選擇空間大幅擴大。

**Q3：為什麼多輪代理設定是研究 PI 的關鍵場景？**
A：在多輪代理設定中，軌跡包含動作、觀察與推理等多種元素，每種元素都可被轉化為不同形式的 PI，使得 PI 設計空間極為龐大。此外，代理任務通常涉及長期專業任務與編碼代理等複雜場景，PI 的微小差異可能對訓練成效產生顯著影響。因此，理解 PI 在此類設定下的有效性，對於實際部署 OPSD 至關重要。

**Q4：OPSD 的核心方法論是什麼？**
A：OPSD 的核心在於讓學生模型與教師模型共享參數，但僅有教師模型能觀察特權資訊（PI）。具體而言，學生策略 πS_θ 與教師策略 πT_θ 共享參數 θ，差異僅在於後者額外接收資訊 I。訓練時，模型最小化學生策略到 PI 條件化教師策略之間的反向 KL 散度，從而讓學生內化推論時間無法取得的資訊。

**Q5：本論文提出的關鍵創新是什麼？**
A：本論文提出兩個基於 KL 的離線指標——採樣 token 反向 KL（D）與錯誤步驟 KL 對比（Δd⁻_err），用於在訓練前評估 PI 品質。其中，Δd⁻_err 透過比較 PI 在已識別錯誤步驟與同任務匹配步驟上的偏移程度，能更準確地反映 PI 是否針對性地修正學生弱點。這項創新使得研究者在進行昂貴的 OPSD 訓練前，能預先篩選最具潛力的 PI 候選。

**Q6：論文設計了哪些 PI 格式與生成來源？**
A：論文設計了 16 種 PI 配置，涵蓋四種軌跡變體（僅動作 A、動作加觀察 A+O、動作加思考 A+T、動作加觀察加思考 A+O+T）以及三種壓縮提示（摘要 Summary、技能 Skill、檢查清單 Checklist）。在生成來源上，採用 GLM-5.2 與 Qwen3-7-Plus 兩種專家模型，並結合參考軌跡與失敗的學生軌跡來建構不同強度的 PI。這種系統化設計使得研究者能隔離分析內容、格式與來源對 PI 有效性的個別影響。

**Q7：實驗使用了哪些基準測試與模型？**
A：實驗採用三個多輪代理基準：ALFWorld、AppWorld 與 τ2-retail，涵蓋家庭任務、應用程式互動與零售對話等不同代理領域。學生模型則選用 Qwen3-4B-Instruct、Qwen3-4B-Thinking 與 Qwen3-30B-A3B-Instruct 三種，橫跨指令模型與思考模型以及不同模型規模。這樣的配置使研究者能評估 PI 效果在不同領域與模型類型間的泛化性。

**Q8：論文的主要實驗結果為何？**
A：結果顯示 PI 有效性取決於其內容、生成來源與學生模型三者的交互作用。資訊密集軌跡通常優於壓縮提示，加入環境觀察能穩定提升指令模型在 ALFWorld 與 AppWorld 上的表現，而額外的教師推理對思考模型的助益較不一致。在提示格式中，技能（含錯誤分析與可重複使用的策略）通常最強，顯示有能力的生成器所產生的 PI 品質更佳。

**Q9：離線指標的消融研究揭示了什麼？**
A：消融研究顯示 PI 效用指標容易因資訊洩漏而失真，可能高估或低估 PI 的實際價值。採樣 token 反向 KL（D）在九個設定中的八個能追蹤訓練後效能，但無法指示偏移方向；錯誤步驟 KL 對比（Δd⁻_err）則能更可靠地區分有用 PI，並在 PI 候選差異較大時改善每任務選擇效果。這些發現強調了設計無洩漏離線指標的重要性。

**Q10：這項研究的實際應用場景為何？**
A：本研究的成果可直接應用於訓練編碼代理（如 Composer 2.5）與長期專業任務代理，透過系統化選擇 PI 來提升 OPSD 訓練效率。在實際部署中，開發者可先使用 Δd⁻_err 篩選 PI 候選，再進行完整訓練，從而節省大量計算資源。此外，結合 GRPO 的組合目標在多輪代理基準上超越強 GRPO 基線，為工業級應用提供了具體的訓練策略。

**Q11：從產品角度，這項研究帶來哪些考量？**
A：產品開發者需考量 PI 格式與生成來源的選擇對最終模型行為的影響，特別是在不同推理模式下（指令 vs. 思考）效果可能不一致。此外，資訊洩漏風險提示開發者在設計 PI 時需謹慎，避免評估指標失真導致錯誤的設計決策。結合 GRPO 的組合目標則提供了一條務實路徑，讓現有 RLHF 流程能無縫整合 OPSD 增益。

**Q12：這項研究對學術與工業界的廣泛影響是什麼？**
A：本論文為 OPSD 提供了首個系統化的 PI 設計指導，填補了該領域缺乏實用指南的空白。KL 診斷指標的提出將研究焦點從「事後評估」轉向「事前預測」，有望成為 OPSD 研究的標準工具。在工業界，這些發現可降低訓練大型代理模型的試錯成本，加速編碼代理與長期專業任務代理的開發進程。

**Q13：論文承認哪些研究限制？**
A：論文主要在三個多輪代理基準上進行評估，結論的泛化性可能受限於特定任務類型。學生模型僅涵蓋 Qwen3 系列，未涵蓋其他模型家族（如 Llama、Claude 等），因此 PI 效果對不同架構的普適性仍待驗證。此外，PI 格式的設計空間雖已擴展至 16 種配置，但相對於所有可能的 PI 建構方式仍屬子集。

**Q14：哪些情況下 PI 可能失效或產生負面效果？**
A：當 PI 來自較弱生成器時，特別是對於需要高品質推理的提示格式，可能無法產生有效學習訊號。對於思考模型，額外的教師推理有時反而會降低訓練成效，顯示 PI 並非「越多越好」。此外，當 PI 候選間差異不大時，Δd⁻_err 的選擇增益也會減弱，意味著該指標在高度相似的 PI 選項間的區辨力有限。

**Q15：未來的研究方向有哪些？**
A：未來可將研究擴展至更多模型家族與任務類型，驗證 PI 設計原則的跨領域普適性。另一個方向是開發更精細的 KL 診斷指標，例如結合多步驟偏移分析或考慮資訊洩漏的校正機制。此外，將 OPSD 與其他 RL 演算法（如 PPO、DPO）的結合效果，以及 PI 在持續學習與多任務設定中的角色，都是值得探索的後續方向。

## 實務應用指南

### 適用場景

1. **企業內部編碼代理（Internal Coding Agents）**：在大型程式碼倉庫中，代理需要依賴測試輸出、靜態分析結果、CI 紀錄等環境回饋來修正錯誤。可將這些環境觀察（Observations）作為 PI 餵給教師策略，讓學生模型學會在沒有這些回饋時仍能產生正確動作。

2. **長時程專業任務代理（Long-Horizon Professional Agents）**：例如律師助理、財務分析師、研究助理等需要多步驟工具呼叫的場景。可使用專家示範軌跡（Actions + Observations + Thoughts）作為 PI，並搭配技能型提示（Skill hints）來強化可重複使用的策略。

3. **多輪客服與銷售代理（Multi-Turn Customer Service Agents）**：在 τ2-retail 等零售對話基準中，可從成功對話抽取檢查清單（Checklist）作為 PI，幫助模型記住任務需求並避免遺漏關鍵步驟。

4. **工具使用型研究助理（Tool-Using Research Assistants）**：在 AppWorld 等需要操作多個 API 的場景中，可將成功的工具呼叫序列與其輸出（Action + Obs.）作為 PI，讓模型學會正確的工具組合。

5. **持續學習代理（Continual Learning Agents）**：當代理需要在多個任務間累積經驗時，可將先前任務的成功軌跡與技能摘要作為 PI，幫助模型在學習新任務時保留舊能力。

---

### 實作前置條件

**資料需求**
- 至少一批成功的專家示範軌跡（reference trajectories），涵蓋目標任務的典型場景。
- 環境回饋日誌（環境觀察、工具輸出、錯誤訊息等），用於建構 Action + Obs. 格式 PI。
- 失敗的學生軌跡（failed student trajectories），用於錯誤步驟 KL 對比（Δd⁻_err）計算與檢查清單生成。
- 黃金解答或任務規範（gold solutions / task requirements），用於衍生 Checklist 與 Skill 提示。

**計算資源**
- 至少一張能跑 30B 級模型推論的 GPU（如 A100/H100），用於生成 PI 候選與計算 KL 指標。
- 多 GPU 訓練叢集（建議 8 卡以上）以執行 OPSD 與 GRPO 聯合訓練。
- 充足的磁碟空間儲存軌跡、PI 候選與檢查點。

**技能前提**
- 熟悉分散式 LLM 訓練（DeepSpeed / FSDP / Megatron）。
- 具備 RLHF / RLAIF 經驗，理解策略梯度與 KL 正則化。
- 能撰寫軌跡解析與 PI 構造流水線（建議使用 vLLM 或 SGLang 加速生成）。
- 具備評估代理任務的能力（任務成功率、回合數、工具呼叫正確率等）。

---

### 實作步驟建議

**步驟一：定義任務與盤點可用資訊**
盤點目標代理任務中哪些資訊在訓練時可取得、推論時不可取得。常見 PI 來源包含：環境觀察、專家示範動作、推理鏈、任務規範、錯誤分析。

**步驟二：建構 PI 候選池**
針對每個任務產生 16 種 PI 候選配置：
- 軌跡類：A、A+O、A+T、A+O+T（分別保留動作、加入觀察、加入思考、同時加入）。
- 提示類：Summary（摘要）、Skill（錯誤分析 + 可重複策略）、Checklist（任務需求清單）。
- 每種格式分別用「自生成」（學生模型本身）與「專家生成」（如 GLM-5.2、Qwen3.7-Plus 等更強模型）兩種來源產生。

**步驟三：計算離線指標篩選 PI**
對每個 PI 候選計算三項指標：
- **PI utility**：比較教師在有/無 PI 時的獎勵差異。注意：此指標易受資訊洩漏扭曲，僅作參考。
- **採樣 token 反向 KL（D）**：測量 PI 引起的學生採樣 token 機率分佈偏移幅度。較大的 D 通常代表較強的學習訊號，但無法判斷方向。
- **錯誤步驟 KL 對比（Δd⁻_err）**：測量 PI 是否在已識別錯誤步驟上產生更大的抑制效果。**這是本文推薦的主要篩選指標**。

**步驟四：依 Δd⁻_err 進行每任務 PI 選擇**
當 PI 候選差異大時，依 Δd⁻_err 為每個任務挑選最佳 PI；若候選差異小，可退而使用 D 或隨機選擇。實驗顯示此策略優於隨機選擇。

**步驟五：執行 OPSD 訓練**
使用選定 PI 進行線上策略自蒸餾：學生與教師共用參數 θ，但教師額外接收 PI。損失函式為學生軌跡上每步的 reverse KL（公式 1）。梯度僅流經學生分支，教師分支以 stop-gradient 處理。

**步驟六：與 GRPO 聯合訓練（選用）**
將 OPSD 與 GRPO 結合：保留 PI 帶來的 token 級監督，同時加入群組相對策略優化的獎勵訊號。實驗顯示此組合可超越純 GRPO 基線。

**步驟七：評估與監控**
追蹤任務成功率、平均回合數、KL 偏移量等指標，並定期重新計算 Δd⁻_err 以偵測訓練過程中的 PI 漂移。

---

### 潛在風險與注意事項

**風險一：PI utility 受資訊洩漏扭曲**
PI utility 比較教師有/無 PI 的獎勵，但若 PI 直接洩漏答案（如 Checklist 包含完整任務需求），會人為抬高 utility，卻未必帶來好的訓練訊號。**緩解**：以 Δd⁻_err 作為主要指標，僅將 PI utility 作為輔助參考。

**風險二：思考模型受益不一致**
實驗顯示思考模型（thinking models）從 PI 的獲益較不穩定，額外的教師推理有時反而降低增益。**緩解**：對思考模型優先嘗試資訊密集軌跡（A+O+T），避免過度冗長的 Skill 提示。

**風險三：PI 品質依賴生成器能力**
較弱的生成器會產生低品質 PI，特別是 Skill 與 Checklist 等需要推理的格式。**緩解**：使用比學生更強的模型（如本文的 GLM-5.2、Qwen3.7-Plus）生成 PI，並對生成結果做品質過濾。

**風險四：Δd⁻_err 需要失敗軌跡**
計算錯誤步驟 KL 對比需要已標註的失敗軌跡，若無此資料則無法計算。**緩解**：先用學生模型在任務上跑一批 rollout，收集失敗案例並標註錯誤步驟。

**風險五：訓練成本高**
每個 PI 候選都需要一次完整 OPSD 訓練才能驗證效果。**緩解**：先用 Δd⁻_err 篩選至 2–3 個候選，再執行昂貴的訓練驗證。

**風險六：PI 與推論時行為不一致**
學生在訓練時模仿「有 PI 的教師」，但推論時沒有 PI，可能產生 distribution shift。**緩解**：監控學生與教師的 KL 偏移量，避免偏移過大導致推論時行為崩壞。

---

### 與其他技術的整合建議

**與 GRPO 整合**
本文證實 OPSD + GRPO 聯合訓練可超越純 GRPO 基線。建議將 PI 帶來的 token 級監督作為「形塑訊號」，將 GRPO 獎勵作為「探索訊號」，兩者互補。

**與 RLHF / DPO 整合**
OPSD 可視為一種不需要偏好對的蒸餾形式，可與 RLHF 流程串接：先用 PI 蒸餾做冷啟動，再做人類偏好微調。

**與持續學習整合**
在多任務持續學習設定中，可將先前任務的成功軌跡與技能摘要作為 PI，幫助模型在學習新任務時保留舊能力（類似 [22] 的做法）。

**與工具增強生成（RAG / Tool-Use）整合**
若代理本身具備工具呼叫能力，可將工具輸出（Observations）作為 PI 的一部分，讓模型學會在沒有即時工具回饋時仍能預測正確動作。

**與現有代理框架整合**
可將 OPSD 訓練模組化為獨立元件，掛載在 LangChain、AutoGen、CrewAI 等框架之上，僅需替換其內部的策略更新步驟。

---

### 給不同背景讀者的閱讀建議

**給初學者**：建議先理解「線上策略自蒸餾」的核心概念——學生與教師共用參數，但教師在訓練時多看了「特權資訊」。閱讀時可先跳過 KL 指標的數學細節，專注在「哪些 PI 格式有效」與「為什麼資訊密集軌跡通常比壓縮提示好」這類直觀結論，再回頭補上公式。

**給 AI 工程師**：重點關注實作步驟二到四——如何建構 16 種 PI 候選、如何計算 Δd⁻_err、如何用它做每任務 PI 選擇。建議將 Δd⁻_err 實作成可重用的離線評估工具，並建立 PI 候選池的版本管理，以便在不同任務間複用。

**給研究者**：本文最大的貢獻在於提出 Δd⁻_err 作為 PI 品質的離線代理指標，並透過控制實驗驗證其有效性。建議深入閱讀第 3 節的指標設計動機、第 4 節的消融實驗，以及附錄中的 PI 構造協議，並思考如何將此框架推廣到非代理任務（如單輪問答、程式碼生成）。

**給產品經理**：核心訊息是「特權資訊的選擇會直接影響代理訓練效果」，且「我們可以在訓練前預測哪種 PI 有效」。這代表產品團隊可以更積極地設計任務專屬的提示與回饋機制，而不必盲目嘗試所有組合。建議關注「與 GRPO 聯合訓練」的結論——這意味著 OPSD 可作為現有 RL 微調流程的補強，而非取代。
