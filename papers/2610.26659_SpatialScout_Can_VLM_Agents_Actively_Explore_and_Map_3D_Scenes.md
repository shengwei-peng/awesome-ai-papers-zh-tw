## 摘要翻譯

空間智能要求智能體主動獲取視覺證據，並將觀測整合為對三維世界的連貫表示。然而，空間問答僅能提供有限的證據，無法充分說明模型是否能透過自主探索建構精確的度量地圖。我們提出 SpatialScout，一個用於評估視覺語言模型（VLM, Vision-Language Model）智能體在主動物件層級三維建圖上表現的基準測試。SpatialScout 包含 80 個多樣化的室內場景，內含 3,140 個目標物件。給定物件清單、RGB 觀測、相機校準與相機位姿，智能體控制相機探索每個場景，並在共享座標系中估計物件中心。此任務需要在有界互動預算下協調視點選擇、跨視角關聯、幾何估計與地圖修正。評估透過物件尺度重疊分數同時衡量定位準確度與目標覆蓋率，該分數會對缺失預測進行懲罰。對前沿視覺語言模型的實驗揭示了顯著的限制：表現最強的評估模型 Claude Opus 5.5 達到 41.71% 的平均重疊分數，其中 47.23% 的目標超過交並比（IoU, Intersection-over-Union）閾值 0.5，僅有 3.25% 超過 0.9。這些結果揭示了從重建粗略物件佈局到建構完整、精確度量地圖之間存在顯著差距。SpatialScout 提供了一個量化測試平台，用於開發能透過主動感知建構可靠三維空間表示的智能體。程式碼可於 https://github.com/JesseZZZZZ/SpatialScout 取得。

## 深度分析

#### 方法論解析

SpatialScout 提出了一套以「主動物件層級三維建圖」(active object-level 3D mapping) 為核心的基準測試框架，其方法論設計在多個層面具有顯著創新性。

**任務形式化定義**

該基準測試將空間智能問題形式化為一個閉環決策過程：給定一個包含 N 個目標的物件清單 (object inventory) $\mathcal{E} = \{(i, c_i, g_i)\}_{i=1}^{N}$，其中包含實例識別碼 $i$、類別 $c_i$ 與等價群組 $g_i$，智能體需在共享座標系 (shared coordinate frame) 中估計所有目標物件中心的三維座標 $\hat{\mathcal{P}} = \{\hat{p}_i : i \in \mathcal{S}\}$。此設計的關鍵在於將「識別物件」與「定位物件」分離——前者僅需語意理解，後者則需整合幾何推理與跨視角關聯 (cross-view association)。

**幾何目標的精確定義**

每個目標中心定義為渲染幾何體的世界座標軸對齊邊界框 (AABB) 的中點。對於關節物件 (articated object)，邊界框涵蓋所有連桿幾何的聯集。這種定義避免了視覺中心與物理中心的歧義性，並確保評估基準的一致性。

**智能體介面設計**

SpatialScout 提供了一套統一且最小化的工具集（見表 2），包含十個核心操作：list_entities、get_camera_pose、get_camera_intrinsics、set_camera_position、move_camera、rotate_camera、capture_image、triangulate_observations、submit_positions 與 finish_mapping。值得注意的是，這套介面刻意不洩漏真實座標或評分資訊，迫使智能體必須透過自主探索獲取證據。其中 triangulate_observations 工具提供從多視角估計三維點的能力，這是一個重要的幾何輔助機制，降低了純視覺估計的難度，但同時也保留了跨視角關聯的核心挑戰。

**評估指標的雙重設計**

評估採用「物件尺度重疊分數」(object-scale overlap score)，同時考量定位準確度 (localization accuracy) 與目標覆蓋率 (target coverage)。此指標對缺失預測 (missing prediction) 施加懲罰，避免智能體僅透過提交少數高信心預測來獲得高分數。這種設計有效區分了「粗略物件佈局」(coarse object layout) 與「精確度量地圖」(precise metric map) 的能力差異。

**場景建構的多樣性**

基準測試涵蓋 80 個室內場景 (indoor scene) 與 3,140 個目標物件，每場景 30–40 個目標，刻意包含多樣化的空間佈局、物件尺度與重複類別實例。這種設計考驗智能體在面對同類別多實例時的區分能力，是空間智能的關鍵瓶頸。

#### 實驗數據解讀

**核心結果的深層意涵**

最強的受測模型 Claude Opus 5.5 僅達到 41.71% 的平均重疊分數，這一數字揭示了當前前沿視覺語言模型 (frontier VLM) 在主動三維建圖任務上的根本性限制。更具啟發性的是 IoU 閾值的分布：47.23% 的目標超過 IoU 0.5，但僅 3.25% 達到 IoU 0.9 以上。這種分布形態表明：

1. **粗略定位能力存在**：近半數目標能達到中等精度，說明模型具備基本的空間感知能力。
2. **精確建圖能力嚴重不足**：僅 3.25% 達到高 IoU 閾值，顯示從「大致正確」到「精確度量」的跨越是當前技術的關鍵瓶頸。

**覆蓋率與精度的權衡**

物件尺度重疊分數對缺失預測的懲罰機制，使得模型無法透過「只提交最有把握的少數預測」來規避挑戰。這迫使模型必須在「廣泛探索以覆蓋所有目標」與「深入觀察以精確定位」之間取得平衡。實驗結果暗示，當前模型可能傾向於其中一端——要麼覆蓋廣但精度低，要麼精度高但遺漏多。

**閉環探索的價值驗證**

雖然論文中未詳細列出不同互動預算 (interaction budget) 下的性能曲線，但任務設計本身驗證了閉環主動探索的必要性。靜態影像問答無法測試「觀察→推理→行動→更新地圖」的完整循環，而 SpatialScout 透過要求模型在每一步根據當前地圖狀態選擇下一個視點，實現了對空間智能的端到端評估 (end-to-end assessment)。

**模型間差異的解讀**

GPT-6 Astra 與 Claude Opus 5.5 之間的性能差距（雖然具體數字未在提供的文本中完整列出）反映了不同模型架構在空間推理上的策略差異。Claude Opus 5.5 的相對優勢可能來自其在長鏈推理 (long-chain reasoning) 與工具使用 (tool use) 上的能力，這對於協調多步驟的主動探索至關重要。

#### 與現有研究的比較

**基準測試生態的定位**

從表 1 的比較來看，SpatialScout 在多個維度上具有獨特定位：

| 維度 | SpatialScout 的獨特貢獻 |
|------|------------------------|
| 輸出格式 | 三維座標（連續數值），而非離散答案 |
| 評估目標 | 定位準確度與覆蓋率，而非答案正確性 |
| 主動互動 | 完整支援 |
| 多輪探索 | 完整支援 |
| 顯式空間構建 | 完整支援 |
| 直接三維座標評分 | 完整支援 |

相較之下，VSR、BLINK、VSI-Bench 與 OpenEQA 等基準測試僅評估答案正確性，無法區分「透過猜測或語言先驗 (language prior) 得到的正確答案」與「透過真實空間理解得到的正確答案」。E3VS-Bench 與 ESI-Bench 雖引入主動互動，但仍以問答形式評估。Theory of Space 雖然探討認知地圖 (cognitive map) 構建，但聚焦於離散表示。IR3D-Bench 雖涉及三維場景參數，但缺乏主動探索機制。

**三大核心創新**

1. **顯式空間構建 (explicit spatial construction)**：將三維座標作為直接輸出，使評估從「答案是否正確」轉變為「地圖是否精確且完整」。
2. **閉環主動探索 (closed-loop active exploration)**：建立觀察、推理、決策的完整循環，反映真實具身智能體 (embodied agent) 的運作模式。
3. **長程端到端能力評估 (long-horizon end-to-end capability evaluation)**：要求模型在多步驟中協調觀測規劃、物件識別、跨視角關聯、幾何估計與地圖更新。

**現有方法的局限性**

儘管 SpatialScout 設計完善，仍存在以下局限：

- **場景規模有限**：80 個室內場景雖然多樣，但相較於真實世界的空間複雜度仍有差距。
- **物件類別偏向**：室內場景的選擇可能限制了對戶外或大規模環境的泛化能力評估。
- **互動預算的設定**：有界互動預算 (bounded interaction budget) 的具體數值未在提供的文本中明確說明，這對結果的可比較性有影響。
- **缺乏人類基線**：未提供人類表現作為對照，使得「41.71%」的絕對意義難以完全詮釋。

#### 可重現性評估

**程式碼與資料的開放性**

論文明確聲明程式碼已開源於 GitHub（https://github.com/JesseZZZZZ/SpatialScout），這為後續研究提供了重要的基礎設施。然而，僅有程式碼連結不足以保證完整可重現性，需進一步考量：

1. **資料集可用性**：80 個室內場景與 3,140 個目標物件的具體來源、授權狀態與下載方式需在程式碼庫中明確說明。
2. **相機校準參數**：基準測試提供的相機內參 (camera intrinsics) 與位姿 (pose) 格式需標準化，以便不同研究團隊使用。
3. **評估腳本**：物件尺度重疊分數的計算需有明確的參考實作，避免不同實驗室之間的評分差異。
4. **模型權重**：雖然評估的是前沿商業模型（GPT-6 Astra、Claude Opus 5.5），但若涉及任何微調或特定提示工程 (prompt engineering)，相關配置也應公開。

**可重現性的潛在挑戰**

- **商業模型的版本變動**：GPT-6 Astra 與 Claude Opus 5.5 作為商業 API，其行為可能隨版本更新而變化，影響長期可重現性。
- **隨機性管理**：主動探索任務中的隨機性來源（初始視點、隨機化策略）需明確記錄。
- **硬體依賴**：若涉及特定 GPU 或運算資源，需在論文中說明最低需求。

#### 未來研究方向

**短期可探索的改進路徑**

1. **混合式架構**：將 VLM 的語意理解能力與傳統電腦視覺方法（如 SLAM、結構光運動 SfM）結合，可能在幾何估計上取得顯著提升。SpatialScout 提供的 triangulate_observations 工具已為此方向鋪路。

2. **記憶增強機制**：當前模型可能在長程探索中遺失早期觀察的資訊。引入顯式的場景記憶模組（如神經輻射場 NeRF、3D Gaussian Splatting）作為輔助表示，可能提升跨視角關聯的準確性。

3. **階層式探索策略**：將探索任務分解為「全域覆蓋」與「局部精化」兩階段，可能更符合人類的空間認知策略。

**中長期研究方向**

1. **從室內到開放世界**：將 SpatialScout 擴展至戶外場景、大規模城市環境，甚至動態場景，考驗模型在更複雜空間中的泛化能力。

2. **多智能體協作建圖**：探索多個 VLM 智能體如何分工協作，共同建構更大規模的場景地圖，這對機器人協作具有實際意義。

3. **語言引導的空間推理**：結合自然語言指令（如「找出廚房裡的所有杯子」）進行目標導向的探索，測試語意與空間的深度整合。

4. **不確定性量化**：要求模型不僅輸出座標，還輸出信心區間，這對真實應用中的決策制定至關重要。

5. **因果空間推理**：從「物件在哪裡」擴展至「為什麼物件在這裡」、「如果移動某個物件會如何」，這涉及更高層次的空間理解。

**對 VLM 發展的啟示**

SpatialScout 的結果（41.71% 平均重疊分數）凸顯了當前 VLM 在「從感知到度量」轉化上的根本性挑戰。未來的 VLM 架構可能需要：

- **原生三維表示**：將三維幾何作為模型的第一類表示，而非從二維影像推導。
- **內建探索機制**：將主動感知 (active perception) 作為模型的核心能力，而非外掛的工具。
- **可驗證的空間推理**：發展能夠產生可檢驗中間表示（如佔據網格、語意地圖）的推理過程。

這些方向不僅對學術研究有價值，對自動駕駛、機器人導航、擴增實境等實際應用同樣具有深遠影響。SpatialScout 作為首個專注於「主動物件層級三維建圖」的基準測試，為這一系列探索提供了堅實的量化基礎。

## 論文問答

**Q1：什麼是「空間智能」，為什麼它對視覺語言模型（VLM）智能體如此重要？**
A：空間智能是指具身智能體在三維環境中主動觀察、推理並行動的能力，涵蓋解決遮擋與視角模糊性、推斷物件位置與空間關係，以及將跨視角的證據整合為一致的三維表示。對 VLM 智能體而言，空間智能是其在真實世界中導航、操作與互動的基礎，因為僅靠單張影像或被動觀察無法處理遮擋與尺度變化。SpatialScout 的研究正是為了檢驗前沿 VLM 是否具備這種主動建構三維空間表示的能力，而非僅僅回答空間相關的語言問題。

**Q2：現有的空間智能基準測試（如 VSR、BLINK、VSI-Bench、OpenEQA）有哪些根本性的不足？**
A：現有基準測試大多採用基於影像或影片的問答形式，僅評估答案正確性，而這對空間理解的約束力有限。有限答案選項（如選擇題、數值題）讓模型可以透過猜測或排除法得到正確答案，語言先驗與答案分佈偏見也可能讓模型依賴非空間線索作答。更關鍵的是，這些基準測試無法評估模型自主收集證據、更新空間表示並據此引導後續動作的多步驟過程，因此無法完整反映真實世界對空間智能的需求。

**Q3：為什麼「主動探索」與「建構度量地圖」對評估空間智能至關重要？**
A：主動探索反映了真實場景中智能體必須自主決定「下一步看哪裡」的能力，這是空間智能的核心組成部分。建構度量地圖則要求模型輸出精確的三維座標，而非僅僅給出語言層面的空間描述，這對評估定位準確度與目標覆蓋率至關重要。SpatialScout 將這兩者結合成一個端到端的閉環任務，使評估能直接衡量模型從局部觀察轉化為完整、精確度量空間表示的能力。

**Q4：SpatialScout 的核心任務定義是什麼？它如何區別於傳統的空間問答？**
A：SpatialScout 的核心任務是讓 VLM 智能體在給定物件清單、RGB 觀測、相機校準與位姿的前提下，主動控制相機探索場景，並在共享座標系中估計每個目標物件的中心位置。這個任務要求模型協調視點選擇、跨視角關聯、幾何估計與地圖修正等多項能力，並在有界互動預算下完成。與傳統空間問答不同，SpatialScout 直接以三維座標作為輸出格式，並透過物件尺度重疊分數進行量化評估，而非僅判斷答案是否正確。

**Q5：SpatialScout 的三大核心特色是什麼？它們如何共同構成一個完整的評估框架？**
A：第一是「顯式空間構建」，模型必須輸出一組三維物件位置，使空間表示品質可透過定位準確度與目標覆蓋率進行量化評估。第二是「閉環主動探索」，模型根據現有觀測與當前地圖選擇後續視點，再用新證據更新位置估計，形成感知證據獲取與空間理解之間的反饋迴圈。第三是「長程端到端能力評估」，模型需在多個互動步驟中協調觀測規劃、物件識別、跨視角關聯、幾何估計與地圖更新，最終以地圖品質作為整體表現指標。這三者結合超越了短推理鏈的問答任務，更貼近真實世界的空間理解需求。

**Q6：SpatialScout 提供了哪些共享智能體介面工具？這些設計選擇背後的理念是什麼？**
A：SpatialScout 提供了十項工具，包括 list_entities（列出目標與元資料）、get_camera_pose（取得相機位姿）、get_camera_intrinsics（取得相機校準）、set_camera_position、move_camera、rotate_camera（控制相機）、capture_image（擷取 RGB 影像）、triangulate_observations（從多視角估計點位）、submit_positions（更新中心地圖）以及 finish_mapping（結束任務）。這些工具刻意不揭露真實目標位置或評估分數，避免模型透過捷徑作弊；同時提供幾何輔助工具（如三角測量）讓模型能專注於高層次的探索與關聯策略，而非從頭推導基本幾何運算。

**Q7：SpatialScout 在資料規模與場景多樣性上有何特點？**
A：SpatialScout 包含 80 個室內場景與 3,140 個目標物件，平均每個場景有 30 至 40 個目標，涵蓋多樣化的空間佈局、物件尺度與重複類別實例。這種規模足以支撐統計上可靠的評估，同時場景與物件的多樣性也避免了模型在單一場景類型上的過擬合。透過統一固定的場景目錄與共享互動介面，SpatialScout 確保了不同模型之間的可比較性，並支援對模型在各種空間配置下的泛化能力進行細緻分析。

**Q8：SpatialScout 的評估指標是如何設計的？為什麼選擇「物件尺度重疊分數」？**
A：SpatialScout 採用物件尺度重疊分數（object-scale overlap score），結合幾何估計誤差、相對於物件尺度的定位準確度以及目標覆蓋率進行聯合評估。這個指標會懲罰缺失預測，並透過交並比（IoU）閾值（如 0.5 與 0.9）來區分粗略定位與精確定位。選擇這種尺度相關的評估方式，是因為絕對距離誤差在大小物件間不具可比性，而 IoU 能同時反映定位精度與預測完整性，更貼近「建構可靠度量地圖」這一核心目標。

**Q9：前沿 VLM 在 SpatialScout 上的表現如何？這些結果揭示了什麼？**
A：表現最強的 Claude Opus 5.5 僅達到 41.71% 的平均重疊分數，47.23% 的目標超過 IoU 閾值 0.5，但只有 3.25% 的目標超過 0.9。這顯示模型能透過自主探索恢復部分物件佈局，但在全面覆蓋與精確定位上仍面臨重大挑戰。不同模型在目標遺漏與中心定位準確度上差異顯著，而滿足嚴格尺度相對精度標準的目標比例仍然偏低，說明識別物件或做出粗略空間判斷並不等同於建構可靠的度量地圖。

**Q10：SpatialScout 的研究成果對機器人與自主系統領域有何實際應用價值？**
A：對於需要在未知環境中導航、操作與互動的機器人系統而言，建構精確的物件層級度量地圖是執行抓取、避障與人機協作等任務的前提。SpatialScout 揭示了當前 VLM 在這方面的不足，可指引研究者改進模型的主動感知與幾何推理能力。此外，該基準提供的閉環探索框架與量化評估方法，可直接應用於評估家用機器人、倉儲自動化與無人機巡檢等場景中的空間智能模組。

**Q11：若將 SpatialScout 的方法整合到產品中，需要考量哪些實務因素？**
A：實務整合首先需考量互動預算與即時性，因為真實場景中相機移動與影像擷取都有時間與能耗成本，模型必須在有限步驟內完成高效探索。其次，產品的相機硬體差異（如魚眼、深度相機）會影響校準與幾何估計的精度，需要介面設計上保留彈性。此外，物件清單的完整性與類別歧義性（例如「椅子」與「辦公椅」）會直接影響跨視角關聯的正確性，因此產品端需要明確的類別層級定義與歧義處理機制。

**Q12：SpatialScout 對「空間智能」研究領域的整體影響是什麼？**
A：SpatialScout 將空間智能的評估從「答案正確性」推進到「地圖品質」，強調了主動感知、跨視角關聯與幾何估計的整合能力。這促使研究者重新思考 VLM 的能力邊界，不再僅以問答表現衡量空間理解，而是關注模型能否建構可操作的空間表示。長期而言，該基準可作為發展更可靠三維空間表示方法的統一測試平台，推動整個領域從「語言層面的空間推理」走向「可落地的度量空間智能」。

**Q13：SpatialScout 本身存在哪些已知的局限性？**
A：首先，SpatialScout 僅聚焦於室內場景與物件中心定位，未涵蓋室外環境、動態物件或更複雜的空間關係推理。其次，評估以物件尺度重疊分數為主，可能無法完全捕捉語義層面的空間理解，例如物件間的功能關係或場景語境。此外，基準測試的互動預算設定會影響模型表現，過於寬鬆可能掩蓋效率問題，過於嚴格則可能讓模型無法完成基本探索，這之間的平衡需要進一步研究。

**Q14：在 SpatialScout 上，模型可能出現哪些典型的失敗案例？**
A：常見的失敗案例包括：模型在遮擋嚴重的區域反覆嘗試而無法定位物件，導致互動預算耗盡；跨視角關聯錯誤，將同一物件的不同觀測誤判為多個獨立目標，造成重複預測；以及幾何估計偏差，特別是在小物體或遠距離觀測下，三角測量的誤差被放大。此外，模型可能在面對重複類別實例（如多張相同的椅子）時難以區分，導致位置估計混淆，這些都反映了當前 VLM 在精細空間推理上的不足。

**Q15：基於 SpatialScout 的發現，未來的研究方向有哪些？**
A：未來可從幾個方向推進：一是改進模型的閉環探索策略，使其能更高效地選擇資訊量最大的視點；二是強化跨視角關聯與幾何估計的整合，特別是在小物體與遮擋場景下的魯棒性；三是將評估從靜態室內場景擴展到動態環境與戶外場景，檢驗模型的泛化能力。此外，結合深度學習與傳統幾何方法（如 SLAM、結構光運動）的混合架構，以及引入記憶機制來支援長程探索，都是值得探索的方向。最終目標是讓 VLM 智能體能像人類一樣，透過主動觀察建構精確、完整且可更新的三維空間表示。

## 實務應用指南

### 適用場景

1. **倉儲機器人盤點與物件定位**：在大型倉儲環境中，機器人需主動探索貨架並建立每件物品的三維座標地圖，用於庫存核對、缺貨偵測與自動揀貨。SpatialScout 的主動探索與物件中心估計機制可直接對應此任務。

2. **室內 AR 內容錨定**：擴增實境應用需要在共享座標系中精確放置虛擬物件（例如在牆上掛虛擬畫作、在桌面擺放虛擬模型）。SpatialScout 評估的「物件中心定位」能力可作為 AR 錨點生成的基準測試。

3. **智慧居家與服務機器人導航**：服務機器人需理解室內物件佈局以規劃路徑、避開障礙物或執行「把杯子放到桌上」等指令。SpatialScout 的閉環探索機制可訓練機器人在有限互動預算下建立可靠空間表示。

4. **建築與室內設計的竣工建模（As-built Modeling）**：透過主動拍攝與三維重建，建立室內場景的物件級佈局文件，用於裝修建議、空間規劃或設施管理。

5. **室內搜救與安防巡檢**：在陌生或受損的室內環境中，無人機或地面機器人需快速建立場景物件地圖以識別異常（例如遺留物品、結構損壞）。SpatialScout 強調的「有限互動預算下的地圖品質」對此類時間敏感任務至關重要。

### 實作前置條件

**資料需求**
- 室內三維場景資料集：可使用 Habitat-Sim、AI2-THOR、Replica 或 Matterport3D 等具備完整網格、紋理與相機校準的模擬環境
- 物件清單與類別標註：每個場景需提供目標物件的實例 ID、類別與等價群組資訊
- 相機內參與外參真值：用於評估與輔助三角測量
- 物件尺度資訊：用於計算物件尺度重疊分數（Object-scale Overlap Score）

**運算資源**
- VLM API 存取權限：GPT-6 Astra、Claude Opus 5.5 等前沿模型的 API 金鑰
- GPU 運算資源：用於場景渲染（建議 NVIDIA RTX 4090 或以上）與本地輔助模型推論
- 充足的 API 額度：每個場景需多次 API 呼叫（探索、推理、提交），80 個場景 × 每場景數十次呼叫將產生顯著成本

**技能需求**
- 三維電腦視覺基礎：相機模型、座標系轉換、三角測量原理
- 提示工程（Prompt Engineering）：設計能有效引導 VLM 進行視點規劃與跨視角關聯的指令
- Python 程式設計：熟悉 Habitat-Sim API、向量運算（NumPy）、三維幾何函式庫（Open3D、Trimesh）
- 評估指標理解：熟悉 IoU、定位誤差、覆蓋率等空間評估概念

### 實作步驟建議

**步驟一：建立模擬環境與資料管線**
- 部署 Habitat-Sim 或類似模擬器，載入 80 個室內場景
- 為每個場景生成物件清單（類別、實例 ID、等價群組）並計算世界軸對齊邊界框（AABB）中心作為幾何真值
- 實作相機控制介面，確保能取得 RGB 觀測、深度圖（可選）、相機內參與位姿

**步驟二：設計 VLM 智能體的工具介面**
- 依照論文中 Table 2 的共享介面實作 10 個工具：`list_entities`、`get_camera_pose`、`get_camera_intrinsics`、`set_camera_position`、`move_camera`、`rotate_camera`、`capture_image`、`triangulate_observations`、`submit_positions`、`finish_mapping`
- 確保工具呼叫具備冪等性與錯誤處理機制，避免因 API 失敗導致探索中斷
- 設計結構化輸出格式（例如 JSON），讓 VLM 能明確提交物件中心座標

**步驟三：實作閉環探索迴圈**
- 初始化：給予 VLM 初始觀測與物件清單
- 規劃階段：提示 VLM 根據當前地圖與觀測決定下一個視點
- 觀測階段：執行相機移動、旋轉與影像擷取
- 推理階段：將新觀測與歷史觀測整合，更新物件中心估計
- 提交階段：定期呼叫 `submit_positions` 更新地圖
- 終止條件：達到互動預算上限或 VLM 主動呼叫 `finish_mapping`

**步驟四：實作三角測量輔助機制**
- 提供 `triangulate_observations` 工具，從多視角二維觀測估計三維點
- 整合深度資訊（若可用）以提升幾何估計精度
- 實作跨視角關聯邏輯，處理同一物件在不同視角下的對應問題

**步驟五：建立評估管線**
- 實作物件尺度重疊分數：對每個預測中心與真值中心建立以物件尺度為半徑的球體，計算 IoU
- 統計不同 IoU 閾值（0.5、0.7、0.9）下的通過率
- 記錄探索過程中的地圖更新軌跡，用於分析模型行為
- 產生視覺化報告：將預測地圖與真值地圖疊加顯示

**步驟六：迭代優化與基準比較**
- 在不同 VLM（GPT-6 Astra、Claude Opus 5.5 等）上執行基準測試
- 分析失敗案例：目標遺漏、跨視角關聯錯誤、幾何估計偏差
- 根據發現的瓶頸優化提示策略或輔助機制

### 潛在風險與注意事項

**風險一：定位精度不足**
- 現象：最強模型 Claude Opus 5.5 平均重疊分數僅 41.71%，僅 3.25% 的目標達到 IoU > 0.9
- 緩解：結合傳統電腦視覺方法（如 PnP 解算、束束調整）作為後處理；引入深度資訊輔助三角測量；採用多模型集成降低單一模型偏差

**風險二：目標遺漏率高**
- 現象：47.23% 的目標未達到 IoU > 0.5 閾值，顯示大量物件未被正確定位
- 緩解：設計系統性的探索策略（如網格掃描、資訊增益最大化）；提供「未觀測區域」提示；允許 VLM 標記不確定區域以進行重點探索

**風險三：API 成本與延遲**
- 現象：每場景需數十次 API 呼叫，80 個場景的評估成本可能極高
- 緩解：實作本地快取機制；對簡單查詢使用較小模型；採用批次處理；設定合理的互動預算上限

**風險四：跨視角關聯錯誤**
- 現象：VLM 可能將不同視角中的同一物件誤判為不同物件，或將不同物件誤關聯為同一物件
- 緩解：提供物件外觀特徵描述輔助關聯；實作基於幾何一致性的關聯驗證；設計明確的關聯提示模板

**風險五：模擬到真實的轉移差距**
- 現象：SpatialScout 使用模擬場景，實際部署時面臨感測器雜訊、光照變化、動態物件等挑戰
- 緩解：在訓練與評估中加入雜訊注入；使用領域隨機化（Domain Randomization）；先在受控環境中驗證再逐步推廣

**風險六：互動預算的設定**
- 現象：過少的預算導致探索不完整，過多的預算使任務失去實用性
- 緩解：根據應用場景設定分級預算；分析預算-精度曲線以找出最佳平衡點

### 與其他技術的整合建議

**與 SLAM 系統整合**
- SpatialScout 的物件中心地圖可作為語義 SLAM 的高階輸出層，與 ORB-SLAM3、RTAB-Map 等視覺 SLAM 系統的位姿估計互補
- SLAM 提供的精確相機軌跡可作為 VLM 探索的先驗資訊，減少視點選擇的盲目性

**與三維重建技術整合**
- 結合 NeRF 或 3D Gaussian Splatting 提供密集三維表示，VLM 負責語意理解與物件層級抽象
- 重建的網格可作為 VLM 的額外觀測輸入，提升遮擋區域的物件定位精度

**與機器人中介軟體整合**
- 將 SpatialScout 的工具介面封裝為 ROS 2 節點，使其能直接部署於真實機器人
- 利用 ROS 的訊息傳遞機制實現多機器人協作探索，共享物件地圖

**與大型語言模型整合**
- 使用 LLM 進行高階任務規劃（例如「盤點廚房所有電器」），將子任務分解為 SpatialScout 的探索動作
- LLM 可協助處理自然語言指令到工具呼叫的轉換，降低 VLM 的推理負擔

**與 AR/VR 框架整合**
- SpatialScout 輸出的物件中心座標可直接用於 ARKit/ARCore 的空間錨點
- 整合 OpenXR 標準，使探索結果能跨裝置共享

**與知識圖譜整合**
- 將物件地圖與語意知識圖譜連結，實現「空間 + 語意」的雙重查詢（例如「找廚房裡能裝水的容器」）
- 支援更複雜的空間推理任務，如路徑規劃、任務規劃

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與 Figure 1，理解 SpatialScout 的核心概念——「讓 AI 學會像探險家一樣主動探索空間並建立地圖」。重點關注「為什麼現有的空間問答測試不夠」這段論述，以及最終的關鍵數字（41.71% 平均重疊分數），這能幫助你直觀理解當前 AI 在空間智能上的真實水準。技術細節可先跳過，待有基礎後再回頭研讀。

**給 AI 工程師**：重點研讀 Section 2 的任務定義與 Table 2 的工具介面設計，這是實作此系統的藍圖。特別注意「閉環探索」與「跨視角關聯」的實作挑戰——這兩個環節往往是效能瓶頸。建議直接從 GitHub 程式碼入手，在小型場景上重現基準測試，再逐步擴展。同時關注評估指標的設計，理解為何選擇「物件尺度重疊分數」而非傳統的歐氏距離誤差。

**給研究者**：SpatialScout 的基準設計本身值得深入分析——它如何從「答案正確性」轉向「地圖品質」評估？如何設計「物件尺度重疊分數」來同時衡量定位精度與覆蓋率？這些設計選擇對未來空間智能基準的發展具有示範意義。此外，論文中揭示的「粗略佈局可恢復但精確度量地圖困難」的現象，是值得追蹤的重要研究方向。建議將其與 ESI-Bench、Theory of Space 等基準進行比較分析，探索統一評估框架的可能性。

**給產品經理**：SpatialScout 揭示的數字（41.71% 平均重疊分數、僅 3.25% 達到高精度）應作為產品規劃的重要參考——目前的 VLM 技術尚未達到商業部署所需的可靠性。在評估相關產品（如機器人盤點、AR 室內導航）時，應將 SpatialScout 作為技術成熟度的參考基準，並預留足夠的容錯機制與人工監督環節。建議關注「適用場景」中列出的五個應用領域，評估哪些場景對精度要求較低、可作為近期落地目標，哪些需要等待技術進一步成熟。
