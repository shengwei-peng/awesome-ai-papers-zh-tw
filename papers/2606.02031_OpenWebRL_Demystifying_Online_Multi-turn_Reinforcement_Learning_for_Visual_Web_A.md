## ⚡ TL;DR

現有開源視覺網頁代理依賴昂貴靜態資料，難以擴展且落後專有系統。
本文提出 OpenWebRL，透過即時瀏覽器基礎設施與多輪強化學習訓練視覺網頁代理。
OpenWebRL-4B 僅用極少資料即創開源最佳成績，並與 GPT-5 等專有系統匹敵。

## 摘要翻譯

建構具備實務能力的視覺網頁代理（visual web agents）需要長程推理（long-horizon reasoning）、精確定位（precise grounding），以及與動態真實世界網站的強健互動。儘管近期進展迅速，最強大的系統仍大多為專有系統（proprietary systems），而開源代理仍高度依賴基於大量精選網頁軌跡（curated web trajectories）的監督式後訓練（supervised post-training）。這種依賴造成了重大的可擴展性瓶頸（scalability bottleneck）：高品質示範資料收集成本高昂，且靜態資料集對於多樣且不斷變化的開放網路涵蓋範圍有限。雖然線上強化學習（online RL）在文字代理（text-based agents）上已展現潛力，但其在即時網站（live websites）上直接訓練視覺網頁代理的潛力仍大多未被探索。在本論文中，我們提出 OpenWebRL，一個在真實網站上以線上多輪強化學習（online multi-turn RL）訓練視覺網頁代理的開源框架。OpenWebRL 涵蓋完整的訓練流程，包括可擴展的即時

## 深度分析

#### 方法論解析

本文將視覺網頁代理（visual web agents）的訓練形式化為部分可觀察馬可夫決策過程（Partially Observable Markov Decision Process, POMDP）\(M=(S,O,A,T,R)\)。在每一步驟 \(t\)，代理（agent）觀察到的狀態 \(o_t\) 包含文字化的瀏覽器資訊 \(x_t\)（如 URL、分頁資訊、環境回饋）以及網頁截圖 \(I_t\)，並透過策略模型 \(\pi_\theta\) 生成包含推理過程（reasoning）與結構化瀏覽器動作（structured browser action）的回應 \(y_t\)。整段互動軌跡（trajectory）\(\tau\) 僅在回合結束後，透過基於規則的驗證（rule-based verification）或評判模型（judge model）進行軌跡層級成功判定（trajectory-level success judging）。

OpenWebRL 的核心方法論可拆解為三大元件與一項底層基礎設施：

**1. 監督式暖啟動（supervised warm start）**
不同於現有開源代理動輒依賴數十萬條精選網頁軌跡（curated web trajectories）進行監督式後訓練（supervised post-training），本文僅使用 0.4K 的初始化軌跡對 4B 參數的骨幹模型進行微調。此舉的目的並非追求最終效能，而是將策略模型置入高效探索模式（productive exploration regime），使其在後續線上強化學習（online reinforcement learning）階段具備基本的網頁操作與任務理解能力，避免因隨機探索而導致訓練初期即陷入無效互動。

**2. 代理控制架構（agent harness）**
為了銜接多模態大型模型與動態真實網頁環境，作者設計了代理控制架構，整合三項關鍵功能：
- **多工具動作執行（multi-tool action execution）**：支援點擊、輸入、滾動等多樣化瀏覽器操作；
- **文字環境回饋（textual environment feedback）**：將環境狀態變化轉譯為自然語言形式的回饋訊號，輔助代理進行錯誤修正與狀態追蹤；
- **多模態上下文管理（multimodal context management）**：有效管理長期互動歷史中的視覺與文字資訊，降低雜訊並控制上下文長度，以提升多輪策略最佳化（multi-turn policy optimization）的穩定性。

**3. 多模態多輪 GRPO 目標函數（multimodal multi-turn GRPO objective）**
本文採用 Group Relative Policy Optimization（GRPO）作為策略最佳化演算法，並將其擴展至多模態多輪場景。有別於傳統逐步獎勵（step-wise reward）可能導致信用分配（credit assignment）困難的問題，OpenWebRL 採用軌跡層級成功判定（trajectory-level success judging），僅在完整回合結束後給予二元或連續的成功訊號。為降低評估成本，作者提出可選用的雙軌評判機制：基於 GPT 的評判模型（GPT-based judge）作為高品質但昂貴的監督來源，以及經知識蒸餾（distillation）得到的蒸餾 8B 評判模型（distilled 8B judge）。後者在維持與專有系統（proprietary systems）相近評判品質的前提下，可將單次實驗的評估成本降低約 545.5 美元。

**底層基礎設施：即時瀏覽器基礎設施（live-browser infrastructure）**
訓練視覺網頁代理需要大規模與真實網頁互動的資料流。OpenWebRL 建構了可擴展的即時瀏覽器基礎設施，支援平行軌跡收集（parallel rollout collection），以緩解即時網站（live websites）互動緩慢且脆弱（brittle）所造成的訓練瓶頸。

整體訓練流程為：先以少量監督資料進行監督式初始化（supervised initialization），再於 2.2K 個開放式強化學習訓練任務（open-ended RL training tasks）上執行線上強化學習，直接於即時網站（live websites）上進行探索與策略更新。

#### 實驗數據解讀

OpenWebRL-4B 在三項具挑戰性的即時網頁基準測試（live-web benchmarks）上進行評估：

- **WebVoyager**：成功率達 74.1%
- **Online-Mind2Web**：成功率達 67.0%
- **DeepShop**：成功率達 64.0%

這些數據標誌著開源視覺網頁代理（open visual web agents）的新突破。首先，在模型規模僅 4B 參數的條件下，OpenWebRL-4B 不僅超越同規模或更大規模的開源對手（如 FARA-7B、MolmoWeb-8B），甚至優於擁有 235B 參數的 Qwen3-VL-235B-A22B-Thinking。這顯示線上強化學習（online RL）在資料效率與策略最佳化上相較於純粹監督式後訓練（supervised post-training）具有顯著優勢——後者往往需耗費數十萬條精選網頁軌跡（例如 MolmoWeb 使用 278K 條軌跡），而 OpenWebRL 僅以 0.4K 初始化軌跡與 2.2K 開放式任務即達到更優異的表現。

其次，與專有系統（proprietary systems）相比，OpenWebRL-4B 能與 OpenAI CUA、Gemini CUA 乃至 GPT-5 等閉源商業模型維持競爭力。這在過往開源網頁代理研究中相當罕見，因為後者通常受限於靜態資料集覆蓋率不足，難以應對多樣且不斷變化的開放網頁。實驗結果表明，透過直接於即時網站（live websites）上進行多輪強化學習（multi-turn reinforcement learning），代理能學習到更具泛化性的長程推理（long-horizon reasoning）與精確定位（precise grounding）能力，而非僅僅記憶靜態示範軌跡。

此外，軌跡層級成功判定（trajectory-level success judging）的設計對效能至關重要。由於開放式任務難以設計完善的基於規則的驗證（rule-based verification），作者引入評判模型作為獎勵訊號來源。實驗證實，蒸餾 8B 評判模型（distilled 8B judge）不僅大幅降低每次實驗約 545.5 美元的評估成本，其評判品質亦足以支撐有效的策略梯度更新，使學術單位得以在有限預算下重現高階網頁代理的訓練流程。

#### 與現有研究的比較

透過表 1 的橫向對比，可清楚定位 OpenWebRL 在現有網頁代理訓練管線中的獨特性：

**相較於文字代理（text-based agents）與模擬環境（simulated environments）**
現有多輪強化學習研究如 WebRL、AgentRL、RAGEN、WebAgent-R1 等主要聚焦於文字觀察與模擬或自建環境（self-hosted environments），例如 WebShop 或 WebArena。這些設定簡化了觀察空間與環境動態，但無法反映真實網頁的視覺複雜度與非平穩性（non-stationary）。OpenWebRL 則直接面對多模態輸入（截圖與文字）與即時網站（live websites），其挑戰性與實用性顯著更高。

**相較於過濾式行為複製（Filtered BC）與純監督式微調（SFT）**
PAE、WebGym、WebSTAR 等方法雖然也在開放網頁上運作，但其核心仍屬於過濾式行為複製或步驟篩選的監督式微調，並非真正的線上策略最佳化。MolmoWeb、ScaleCUA、FARA-7B 等目前最強的開源代理同樣依賴大規模監督式後訓練。相較之下，OpenWebRL 採用 SFT 後接 MM-GRPO 的兩階段範式，透過與環境互動自主探索，突破了靜態資料集的可擴展性瓶頸（scalability bottleneck）。

**相較於閉源多模態代理**
UI-TARS-2 雖然採用多輪 PPO 且支援多模態輸入，但其訓練於封閉的電腦使用沙盒（computer-use sandbox）中，且模型權重、資料與程式碼均未公開。OpenWebRL 則是少數同時具備多模態觀察、真實開放網頁訓練、且完整開源（權重、資料、程式碼皆釋出）的框架。

**既有侷限**
儘管成果顯著，OpenWebRL 仍存在若干限制。首先，軌跡層級判定依賴評判模型，可能引入獎勵駭取（reward hacking）或評判偏誤，尤其當代理學會操弄評判器而非真正完成任務時。其次，4B 參數規模雖然證明了資料效率，但在極端複雜的長程規劃任務上，其推理深度可能仍不及 GPT-5 等超大規模專有模型。此外，即時瀏覽器基礎設施的延遲與脆弱性意味著訓練吞吐量受限，大規模平行軌跡收集（parallel rollout collection）的硬體門檻仍是實際部署的挑戰。

#### 可重現性評估

可重現性（reproducibility）是本文最核心的貢獻之一。根據表 1 與作者聲明，OpenWebRL 同時釋出模型權重（weights）、訓練資料（data）與完整程式碼（code），在現有文獻中達到最高程度的開放性：

- **與專有系統（proprietary systems）的對比**：OpenAI CUA、Gemini CUA 與 GPT-5 等系統僅提供 API 推論端點，訓練資料、模型權重與演算法細節完全封閉，研究者無法驗證或延伸其方法。
- **與部分開源研究的對比**：FARA-7B 未釋出資料；UI-TARS-2 未釋出權重、資料與程式碼；WebGym 與 PAE 雖開源，但採用 Filtered BC 而非完整的線上 RL 管線。
- **成本可負擔性**：透過蒸餾 8B 評判模型（distilled 8B judge）替代基於 GPT 的評判模型（GPT-based judge），單次實驗可節省約 545.5 美元。對於學術實驗室而言，這大幅降低了進入門檻，使得在真實網頁上進行多輪強化學習（multi-turn reinforcement learning）研究不再侷限於擁有大量運算與 API 預算的工業界團隊。

然而，可重現性仍受制於外部環境的非平穩性（non-stationary）：即時網站（live websites）的內容與結構持續演變，特定基準測試（benchmark）的絕對分數可能隨時間波動。儘管作者提供即時瀏覽器基礎設施（live-browser infrastructure）的實作，重現者仍需維護穩定的瀏覽器自動化環境與網頁快取機制，以確保實驗條件的一致性。

#### 未來研究方向

基於 OpenWebRL 建立的開源基礎，未來研究可沿以下方向延伸：

**1. 獎勵訊號的去評判模型化**
目前軌跡層級成功判定（trajectory-level success judging）仍高度依賴外部評判模型，未來可探索結合基於規則的驗證（rule-based verification）與模型自我評判（self-judging）的混合機制，或利用過程獎勵模型（Process Reward Model, PRM）進行細粒度的步驟級信用分配，以降低獎勵駭取風險並提升學習效率。

**2. 模型規模與長程推理的擴展**
本文以 4B 參數驗證了線上 RL 的資料效率，但未來可將多模態多輪 GRPO 目標函數（multimodal multi-turn GRPO objective）擴展至 7B、13B 乃至更大規模的視覺語言模型（VLMs）。這將有助於解決目前 4B 模型在極複雜多步驟導覽（multi-step navigation）與資訊擷取（information extraction）任務上的推理瓶頸。

**3. 課程式線上學習（Curriculum Online Learning）**
當前 2.2K 開放式強化學習訓練任務（open-ended RL training tasks）的難度分佈可能影響學習動態。引入自適應課程機制，根據代理當前能力動態調整任務難度與網站領域，有望進一步提升樣本效率並減少早期訓練的失敗率。

**4. 基礎設施的穩健性與效率提升**
即時瀏覽器基礎設施（live-browser infrastructure）的延遲與脆弱性仍是訓練吞吐量的主要瓶頸。未來可研究輕量級瀏覽器模擬、網頁狀態快取、或部分互動的離線預演（offline rehearsal）技術，以加速平行軌跡收集（parallel rollout collection）而不犧牲真實性。

**5. 跨領域代理遷移**
OpenWebRL 的訓練範式原則上可泛化至其他需要視覺感知與多輪互動的代理任務，例如桌面應用程式操作（computer-use）、行動裝置 GUI 導覽，或複雜的產品搜尋（product search）與電子商務決策流程。探索統一的多模態代理控制架構（agent harness）與跨領域 RL 訓練，將是邁向通用代理（generalist agents）的重要一步。

## 論文問答

**Q1：視覺網頁代理在發展上遇到了什麼樣的核心瓶頸，使得現有開源系統難以與專有系統競爭？**

A：目前視覺網頁代理面臨的主要瓶頸在於對大規模精選網頁軌跡資料的高度依賴，例如領先的開源代理 MolmoWeb 需要多達 27.8 萬條經過人工整理的互動軌跡進行監督式後訓練。這類資料的收集成本極高，且靜態資料集無法涵蓋真實網路環境中多樣且不斷變化的內容，導致代理的泛化能力與適應性受到嚴重限制。此外，最強大的系統多為專有系統且閉源，加上昂貴的 API 評估與封閉的訓練流程，使得開源研究社群難以複現、研究並縮小與商業系統之間日益擴大的效能差距。

**Q2：為什麼現有的強化學習方法難以直接應用於即時視覺網頁代理的訓練？**

A：現有的線上強化學習研究大多聚焦於文字代理，並且在模擬環境或自建環境等受控場景中進行，這與真實開放網頁的複雜性有本質上的差異。即時網站具有動態且非平穩的特性，頁面內容會隨時間不斷變化，加上即時瀏覽器互動速度慢且容易出錯，使得大規模平行軌跡收集變得相當困難。此外，開放式網頁任務往往缺乏可靠的基於規則的驗證機制，難以自動判斷任務是否成功完成，這也讓傳統依賴明確獎勵訊號的強化學習演算法難以直接套用。

**Q3：推動「線上多輪強化學習」對於視覺網頁代理領域為何至關重要？**

A：線上強化學習提供了一個原則性的替代方案，讓代理能夠透過與即時網站的直接互動，從任務結果中學習並持續自我改進，而非僅僅模仿固定的示範資料。這種方式能夠突破靜態資料集的可擴展性瓶頸，使代理更有效地適應真實世界中不斷變化的網頁環境與新任務類型。對於開源社群而言，建立有效的線上強化學習框架是縮小與專有系統差距、建構更具能力且可複現的開放網頁代理的關鍵一步。

**Q4：OpenWebRL 框架的核心架構包含哪三大元件，各自扮演什麼角色？**

A：OpenWebRL 框架由三大核心元件組成：首先是「監督式暖啟動」，僅使用 0.4K 條軌跡即可將策略模型初始化至高效探索模式，大幅降低對大規模標註資料的依賴；其次是「代理控制架構」，整合了多工具動作執行、文字環境回饋與多模態上下文管理，確保代理在即時網頁環境中進行多輪互動時的穩定性與效率；最後是「多模態多輪 GRPO 目標函數」，搭配軌跡層級成功判定機制，針對完整的互動序列進行多輪策略最佳化，使模型能從長期的任務成敗中學習。

**Q5：相較於過往研究，OpenWebRL 在「軌跡層級成功判定」上有何創新設計？**

A：OpenWebRL 針對開放式網頁任務難以用規則自動驗證的問題，提出了軌跡層級成功判定機制，在完整互動結束後才評判任務是否成功，而非僅對單一步驟給予獎勵。此機制支援使用基於 GPT 的評判模型，同時也提供了一個經蒸餾的 8B 輕量評判模型，其效能可媲美專有模型，卻能將每次實驗的評估成本降低約 545.5 美元。這種設計不僅解決了即時網頁缺乏可靠規則驗證的難題，也讓大規模線上強化學習的訓練成本變得更加可控。

**Q6：OpenWebRL 如何解決即時瀏覽器互動「慢且脆弱」所帶來的訓練挑戰？**

## 實務應用指南

### 適用場景

1. **自動化網頁驗收測試與回歸驗證**：針對動態電商後台或 SaaS 產品，訓練能自動執行跨頁面操作流程、判斷 UI 狀態並回報異常的視覺代理，降低人工 QA 負擔。
2. **開放式網路資訊擷取與知識庫更新**：用於需要即時瀏覽多個即時網站、執行多步驟檢索並結構化擷取資訊的場景，例如競品價格追蹤、法規變動監控或學術文獻調查。
3. **企業內部 Web 流程自動化**：串接僅提供網頁介面的舊有系統（legacy systems），讓代理自動完成表單填寫、資料下載、跨系統資料搬運等重複性業務流程。
4. **無障礙網頁輔助與長輩友善導航**：為視障或高齡使用者打造能「看懂」網頁視覺排版、執行精確點擊與輸入的代理，協助完成購物、訂票或政府服務申辦。
5. **電商與旅遊平台的個人化採購代理**：在真實即時網站上執行多輪條件篩選、庫存查詢與比價，並根據使用者偏好動態調整搜尋策略。

### 實作前置條件

- **資料準備**：至少 400–1,000 條高品質的精選初始化軌跡（curated trajectories）用於監督式暖啟動；2,000 條以上的開放式任務定義（含起始 URL 與自然語言指令）；若採用蒸餾評判模型，需額外準備軌跡層級的成功／失敗標註資料。
- **運算資源**：訓練 4B 等級多模態模型需至少數張 A100／H100 等級 GPU；即時瀏覽器基礎設施需能支援大規模平行軌跡收集（建議以 Docker 或 Kubernetes 管理數十至數百個無頭瀏覽器實例）；評判模型若使用 GPT API 需預留呼叫預算，或準備一張額外 GPU 部署 8B 蒸餾評判模型。
- **技術能力**：團隊需熟悉強化學習（特別是 GRPO／PPO 類演算法）、多模態模型微調與推理加速、瀏覽器自動化（Playwright／Puppeteer／Selenium），以及網頁前端結構與動態渲染機制。

### 實作步驟建議

1. **建置即時瀏覽器叢集**：部署可水平擴展的無頭瀏覽器基礎設施，確保每個代理實例都能獨立運作並回傳截圖、HTML 與執行狀態。建議加入容錯重試與資源回收機制，避免因網頁載入超時或 JavaScript 異常導致訓練中斷。
2. **執行監督式暖啟動（Warm Start）**：在目標網域收集少量高品質軌跡（約 0.4K–1K），對 4B 等級的 VLM 進行監督式微調（SFT）。此步驟目的是將策略模型推進「高效探索模式」，避免後續線上 RL 階段因隨機探索而產生過多無效軌跡。
3. **設計評判系統（Trajectory-level Judging）**：優先訓練蒸餾 8B 評判模型以取代 GPT-based 評判，可大幅降低實驗成本（每輪實驗約節省五百美元以上）。評判模型需以完整軌跡為輸入，輸出二元或細粒度的成功分數。
4. **開發 Agent Harness**：實作多工具動作執行介面（點擊、輸入、滾動、返回、完成等）、文字環境回饋機制（例如將瀏覽器錯誤訊息轉為自然語言提示），以及多模態上下文管理（有效壓縮歷史截圖與動作序列，避免超過模型上下文長度）。
5. **啟動多模態多輪 GRPO 訓練**：以暖啟動後的模型為基底，在即時網站上執行線上強化學習。每個訓練任務需包含起始 URL 與開放式指令，讓模型透過與真實環境互動、接收軌跡層級獎勵來更新策略。建議從 2K 左右的任務開始，逐步擴充。
6. **持續評估與迭代**：在 WebVoyager、Online-Mind2Web 或自建的 live-web 測試集上定期評估成功率。針對失敗案例進行錯誤分析，並將高品質修正軌跡回注至暖啟動資料集或作為 RL 的偏好資料，形成資料閉環。

### 潛在風險與注意事項

- **網頁非平穩性導致策略漂移**：即時網站經常改版、調整版面或更新反爬蟲機制，訓練完成的代理可能在數週後效能驟降。建議建立持續監控管線（monitoring pipeline），定期在少量先導任務上驗證代理表現，並觸發增量 RL 微調。
- **即時瀏覽器基礎設施的脆弱性**：大規模平行操作真實瀏覽器容易出現記憶體洩漏、分頁崩潰或 IP 被封鎖等問題。需實作健全的超時處理、瀏覽器實例回收機制，以及代理伺服器輪替策略。
- **評判模型的偏差與成本**：軌跡層級判定若僅依賴單一規則或輕量模型，可能出現獎勵駭客（reward hacking）或誤判。建議採用混合評判（mixed judges）機制，結合規則檢查與模型評分，並保留人工稽核抽樣。
- **法律與倫理風險**：自動化代理大規模操作第三方網站可能違反服務條款（ToS）。實務上應設定合理的請求速率限制（rate limiting）、避免自動化登入敏感帳戶，並在生產環境保留人類介入開關（human-in-the-loop）。
- **上下文長度與記憶限制**：多輪網頁互動容易產生長序列，導致模型遺忘早期目標或忽略關鍵視覺細節。需設計主動式上下文摘要機制，或在關鍵決策點讓模型重新陳述目標。

### 與其他技術的整合建議

- **與現有 RAG／知識庫系統整合**：將 OpenWebRL 代理作為動態資訊收集器，把擷取到的網頁內容經結構化後寫入向量資料庫（如 Milvus、Pinecone），供企業內部問答系統或分析管線使用。
- **嵌入 LLM 編排框架**：透過 LangChain、LlamaIndex 或自研 Agent Orchestrator，將視覺網頁代理視為一項特殊「工具」（tool），與程式碼執行、API 呼叫等其他工具協同完成複合任務。
- **與傳統瀏覽器自動化工具分層協作**：底層保留 Playwright 或 Selenium 負責穩定的瀏覽器控制與元素定位，上層由 OpenWebRL 負責高階決策與視覺推理。這種分層架構可兼顧 RL 代理的彈性與傳統腳本的可靠性。
- **與專有系統形成混合架構**：在成本敏感或高風險場景，可將 OpenWebRL-4B 作為主要決策引擎，僅在成功率過低的任務類型上呼叫 OpenAI CUA 或 Gemini CUA 等專有 API，達成成本與效能的平衡。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先聚焦論文的「適用場景」與「框架架構」章節，理解視覺網頁代理與一般聊天機器人的差異。不必急著深入 GRPO 數學推導，但應掌握「監督式暖啟動」與「線上強化學習」這兩階段訓練流程的基本概念，並嘗試從作者釋出的開源程式碼與 0.4K 初始化資料開始實作。
- **AI 工程師**：請深入研讀多模態多輪 GRPO 目標函數的實作細節、Agent Harness 的上下文管理機制，以及即時瀏覽器基礎設施的平行化設計。特別關注作者如何以僅 2.2K 開放式任務與蒸餾 8B 評判模型降低訓練成本，這些工程取捨對實際落地至關重要。
- **研究人員**：建議將閱讀重心放在作者對「線上 RL 如何改善視覺網頁代理的代理推理能力」的系統性分析，以及與純 SFT 方法（如 MolmoWeb）的對照實驗。可進一步思考如何將此框架擴展至其他非平穩、視覺 grounding 需求高的決策環境，例如行動裝置操作或桌面 GUI 自動化。
- **產品經理**：請優先關注論文中的成本效益數據與商業競爭力分析。OpenWebRL-4B 僅需 0.4K 初始化軌跡與 4B 參數量，即可在 live-web 基準上與 GPT-5、OpenAI CUA 等專有系統抗衡，這代表極高的部署彈性與較低的資料收集門檻。評估時請同時考量即時網頁環境的維護成本與法規遵循風險。
