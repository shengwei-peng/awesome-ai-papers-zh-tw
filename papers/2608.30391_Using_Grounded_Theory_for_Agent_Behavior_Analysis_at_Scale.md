## 摘要翻譯

理解智慧代理人行為（agent behavior）需要能擴展至數千條軌跡（trajectories）的方法，並能在漫長且通常不熟悉的任務中發掘新模式——這類任務往往超出預先建置分類器（pre-built classifiers）的能力。我們提出將紮根理論（grounded theory）引入智慧代理人軌跡（agent trajectories）分析：這是來自社會科學、已有六十年歷史的質性研究方法，具備原則性的飽和（saturation）準則，以及從資料到理論的可稽核軌跡（auditable trail）。我們提出 AutoTraceGT（Automated Trace analysis through Grounded Theory，透過紮根理論的自動化軌跡分析），這是首個將紮根理論自動化應用於智慧代理人軌跡分析的多智慧代理人管線（multi-agent pipeline）。它反覆進行開放、主軸與理論編碼（open, axial, and theoretical coding），直到達成飽和，並產生針對各項任務量身打造的行為分類法（behavioral taxonomy）。橫跨六個軌跡語料庫，AutoTraceGT 產生的編碼手冊（codebooks）能重現人工標註分類法中 73% 至 91% 的失效模式（failure modes），並發掘這些分類法遺漏的額外模式（additional patterns）。浮現出的理論敘事與先前專家的描述一致。作為演繹特徵空間（deductive feature space）使用時，該編碼手冊在下游失效預測上優於零樣本與少樣本大型語言模型（LLM）基線（zero-shot and few-shot LLM baselines）。這些結果顯示，紮根理論為機器學習研究者與智慧代理人開發者（agent developers）提供了一個可擴展的分析工具，用以探究智慧代理人的實際行為。

### 核心貢獻（3～5點）
- 提出 AutoTraceGT，首個將紮根理論自動化應用於智慧代理人軌跡分析的多智慧代理人管線。
- 透過反覆進行開放、主軸與理論編碼直至飽和，為每項任務產生量身打造的行為分類法。
- 在六個軌跡語料庫中，自動產生的編碼手冊能重現 73% 至 91% 的人工標註失效模式，並發掘額外模式。
- 編碼手冊作為演繹特徵空間使用時，在下游失效預測上優於零樣本與少樣本 LLM 基線。

### 適合對象
機器學習研究者、智慧代理人開發者，以及關注可擴展質性方法、代理人行為分析與失效模式發掘的研究人員。

## 深度分析

#### 方法論解析

本文的核心方法論貢獻在於將社會科學中已發展六十餘年的 **Grounded Theory（紮根理論）** 引入機器學習（Machine Learning, ML）領域，用以進行大規模的 **Agent Behavior（智慧代理人行為）** 分析。不同於傳統依賴預設類別的行為分類器，紮根理論強調從資料本身歸納出行為模式，並透過反覆抽樣與比較達到 **Theoretical Saturation（理論飽和）**，即新增資料不再產生新的結構性類別為止。

作者提出的 **AutoTraceGT（Automated Trace analysis through Grounded Theory，透過紮根理論的自動化軌跡分析）** 是一個多智慧代理人（multi-agent）流程，將紮根理論的三階段編碼工作分配給不同角色的代理模組：

1. **OpenCode（開放編碼）**：針對單一 **Agent Trajectory（智慧代理人軌跡）** 進行描述性標註，回答「在哪些步驟發生了什麼事」。此階段著重於從原始軌跡（包含行動、觀察、推理文字）中提取具體行為片段，並保留步驟層級的引證（quoted evidence）。
2. **AxialCode（主軸編碼）**：跨軌跡地將開放編碼產生的標籤進行分群與連結，形成更高層次的行為類別（behavioral categories）。此階段類似於在資料中尋找因果、條件或後果關係，並將離散標籤組織成結構化的 **Codebook（編碼手冊）**。
3. **TheoreticalCode（理論編碼）**：將已飽和的類別整合為一個連貫的理論敘事（theoretical narrative），解釋智慧代理人在特定任務中的整體行為模式，例如「持續行動但缺乏診斷性檢查」。

與此同時，**Manage（管理模組）** 負責驅動整個流程的迭代核心：策略性抽樣（strategic sampling）與 **Constant Comparison（持續比較）**。它會不斷將新抽樣的軌跡與現有的編碼手冊進行比對，決定是否需要新增、合併或細分類別，直到達到理論飽和為止。

此方法論的幾個關鍵設計值得深入討論：

- **Inductive（歸納式）特性**：不同於專家預先定義的 **Behavioral Taxonomy（行為分類法）**，AutoTraceGT 的類別是從資料中湧現（emerge）的，因此對於新穎任務與未曾預期的代理人行為具有較強的適應性。
- **Auditable Trail（可稽核軌跡）**：每一個類別與理論宣稱都連結到原始的軌跡片段與引文，這對於 ML 研究中的可解釋性與除錯至關重要。
- **Saturation Criterion（飽和準則）**：提供了一個原則性的停止條件，避免無止盡的資料探索，同時也讓分析規模化具備理論基礎。

然而，方法論上也存在值得檢視的議題。首先，雖然紮根理論強調「無預設假設」，但 LLM 作為編碼代理人的 **Backbone Model（骨幹模型）** 本身帶有強烈的語言與世界知識偏見，這可能影響何種行為會被標註為「顯著」。其次，理論飽和在傳統質性研究中是由人類研究者透過長期沉浸於資料來判斷，而 AutoTraceGT 必須將其操作化為可自動偵測的指標，其敏感度與穩健性需要更多細節支撐。

#### 實驗數據解讀

作者在超過 7,500 條軌跡、六個資料集與四個骨幹 LLM 上評估 AutoTraceGT，評估軸線分為 **Process Reliability（流程可靠性）** 與 **Artifact Quality（產出品質）**。

在流程可靠性方面，實驗顯示 AutoTraceGT 能夠在多個資料集與不同骨幹模型下趨近飽和，並且獨立執行所產生的 **Codebook（編碼手冊）** 具有可重複性（reproducible），且明顯區別於「不同資料或模型歸納偏誤所造成的雜訊底線」。這表示 AutoTraceGT 並非只是隨機產生類別，而是能從資料中穩定地提煉出行為結構。

在產出品質方面，最重要的量化結果是：AutoTraceGT 產生的編碼手冊能夠涵蓋人工建構分類法中 **73% 至 91%** 的 **Failure Mode（失敗模式）**。這代表自動化方法可以捕捉絕大多數專家已辨識出的問題類型。更具價值的是，它還能發現那些人類分類法系統性遺漏的 **Additional Patterns（額外模式）**，這正是歸納式方法的優勢所在——它不僅複製人類的既有知識，還能拓展知識邊界。

此外，AutoTraceGT 產生的 **Theoretical Narrative（理論敘事）** 與先前專家提出的「錯誤連鎖反應」（cascade-of-errors）帳戶相互吻合。這顯示自動化紮根理論不僅能產生離散的類別，還能重建出與領域專家一致的整體行為解釋框架。

在下游應用方面，作者將 AutoTraceGT 產生的編碼手冊作為 **Deductive Feature Space（演繹特徵空間）**，用於 **Failure Prediction（失敗預測）**。結果顯示，該特徵空間在多個骨幹模型上均優於 **Zero-shot（零樣本）** 與 **Few-shot（少樣本）** 的 LLM 基線。這驗證了紮根理論產出的類別不僅具有詮釋價值，也具備實用的預測能力。

綜合來看，這些結果支持了以下幾點結論：

- AutoTraceGT 在規模化與自動化之間取得了平衡，能夠處理數千條軌跡。
- 自動化編碼的品質已達到可與人工分類法高度重疊的水準。
- 歸納式方法確實能發現預設分類器難以捕捉的新興行為模式。
- 編碼手冊具有跨任務遷移與下游預測的再利用價值。

不過，實驗數據也留下一些詮釋空間。例如，73–91% 的覆蓋率雖高，但仍有部分失敗模式未被捕捉，這可能來自於 LLM 對特定領域細微差異的辨識限制，也可能與飽和準則過早觸發有關。此外，下游預測的優勢是否來自於特徵空間的語意豐富度，還是僅因為編碼手冊提供了更多的人工結構化資訊，也值得進一步拆解。

#### 與現有研究的比較

現有的代理人行為分析大致可區分為三種取徑，而 AutoTraceGT 試圖填補它們之間的缺口：

1. **輕量量化後設資料分析**：例如軌跡長度、**Action Counts（行動次數）**、任務成功率等。這類方法雖然可擴展，但對於「為何失敗」的解釋力薄弱，屬於 **Process-blind（過程盲）** 的分析。
2. **人工質性分析**：研究者親自閱讀與標註軌跡，雖然具高度可解釋性，但成本高昂，尤其當軌跡包含數百個步驟時，難以擴展至數千條軌跡。
3. **預設行為分類器**：基於專家先驗知識建立行為類別，再訓練分類模型。這類方法雖然結合了量化規模與質性概念，但過於僵化，難以泛化到新穎任務或新興行為。

相較之下，AutoTraceGT 的優勢在於：

- **兼具規模性與歸納開放性**：透過多代理人自動化，能處理大量軌跡，同時保持對新興模式的開放性。
- **可稽核的推論鏈**：每個類別都有原始引證，這在現有的黑箱式 LLM 分析中較為少見。
- **理論飽和作為停止條件**：提供了一個比單純「增加更多資料」更為原則化的分析終止標準。

在 LLM 輔助質性分析的研究脈絡中，已有學者將 LLM 應用於訪談稿的主題分析（thematic analysis）或階層式歸納編碼。AutoTraceGT 的差異在於它專注於 **Agent Trajectory（智慧代理人軌跡）** 這種特殊資料型態，並將紮根理論的三階段編碼完整自動化，而非僅協助單一編碼階段。此外，它強調從開放編碼到理論編碼的閉環迭代，並以飽和為目標，這在現有 LLM 輔助質性研究中較為少見。

然而，本文也面臨一些侷限與挑戰：

- **LLM 偏見問題**：骨幹模型的訓練資料與歸納偏誤會影響何種行為被視為顯著，這與傳統紮根理論中研究者「懸置預設」的理想仍有差距。
- **飽和操作化的爭議**：理論飽和在質性方法論中本身就有多種詮釋，將其自動化可能簡化了這個複雜概念。
- **驗證基準的依賴**：以人工分類法作為覆蓋率的黃金標準，某種程度上仍受制於人類專家的既有框架，可能低估真正新穎發現的價值。
- **計算成本**：雖然比人工分析便宜，但多輪 LLM 推理與迭代編碼在大量軌跡上的運算成本仍不容忽視。

#### 可重現性評估

本文在可重現性方面提供了相對積極的基礎設施。作者公開了原始碼，連結為 `https://github.com/ZhuoranLu/Qual-Agent-Behavior-Analysis`，這使得其他研究者可以檢視 AutoTraceGT 的實作細節、重複實驗流程，並應用於自己的軌跡資料。

然而，可重現性的完整程度仍取決於幾個因素：

- **資料集可用性**：文中提到使用六個軌跡語料庫，但這些資料集是否全部公開、授權條款為何，會影響外部研究者能否完全複製結果。若部分資料來自專有或需申請的來源，則完全重現會有困難。
- **骨幹模型版本**：實驗使用四個不同的 LLM 作為骨幹。由於 LLM 的行為會隨版本更新而變化，若未明確記錄模型版本、API 參數（如溫度、top-p、最大輸出長度）與提示詞（prompts），未來的重現可能會產生差異。
- **隨機性控制**：LLM 推理與抽樣過程中的隨機性需要適當的種子設定與多次執行報告，才能評估結果的穩定性。
- **中間產物的可讀性**：文中強調每個中間產物都是機器可讀且可稽核的，這對於重現與後續分析非常有幫助，但實際上這些產物的格式、metadata 結構與文件說明是否完整，仍需檢視開源倉庫才能確認。

整體而言，AutoTraceGT 在可重現性上採取了開放的態度，但如同許多 LLM 驅動的研究，其結果仍受到模型 API、版本與參數設定的影響，未來若能提供容器化環境、固定模型快照（model snapshots）與詳細的超參數設定，將進一步提升可重現性。

#### 未來研究方向

AutoTraceGT 的提出開啟了多個值得後續探索的研究方向：

1. **跨領域泛化與遷移學習**：目前 AutoTraceGT 針對每個任務產生專屬的 **Behavioral Taxonomy（行為分類法）**。未來可研究如何將一個任務上學到的編碼手冊遷移到另一個相關任務，或建立跨任務的通用代理人行為本體論（ontology）。
2. **人機協作編碼**：完全自動化的編碼雖然可擴展，但人類專家的領域知識仍具價值。未來可發展互動式介面，讓研究者在 OpenCode 或 AxialCode 階段介入、修正或補充類別，形成人機協作的質性分析流程。
3. **飽和準則的精進**：目前的飽和判斷可能基於新增類別數量的穩定化。未來可探索更細緻的飽和指標，例如類別內部變異度、語意嵌入空間的收斂程度，或結合統計檢定來決定何時停止抽樣。
4. **因果與反事實分析**：AutoTraceGT 目前主要描述「什麼行為導致失敗」。未來可結合因果推論方法，分析若改變某些行為模式，任務結果是否會改變，從而提供更具行動導向的改進建議。
5. **多模態軌跡分析**：目前的軌跡主要包含文字形式的行動與觀察。未來可擴展至包含螢幕截圖、網頁結構、程式碼差異（diff）等多模態資訊，使行為描述更為精確。
6. **即時監控與干預**：將 AutoTraceGT 從離線分析工具轉化為線上監控系統，在代理人執行過程中即時偵測高風險行為模式並觸發干預機制，例如重新規劃或請求人類協助。
7. **方法論反思與評估框架**：隨著 LLM 越來越多地參與質性研究，需要建立專門的評估框架來衡量自動化紮根理論的效度、信度與倫理影響，例如如何避免模型偏見被包裝為「資料驅動的發現」。

總結來說，AutoTraceGT 不僅是一個技術工具，更是一種方法論倡議：它邀請 ML 社群重新思考如何在規模化與解釋性之間取得平衡，並從社會科學的豐富傳統中汲取靈感。未來若能持續深化其方法論基礎、強化可重現性，並拓展至多模態與即時應用場景，將有潛力成為智慧代理人研究中的標準分析工具。

## 論文問答

**Q1：這篇論文處理的核心問題是什麼？**
A：這篇論文處理的核心問題是如何大規模理解智慧代理人在解決長期、複雜任務時實際上做了什麼。現有的輕量化量化後設資料（例如行動次數、任務成功與否）雖然容易擴展，卻無法解釋背後的問題解決過程與失敗原因。相對地，人工分析雖然可解釋，但面對數千條、每條數百步的智慧代理人軌跡時，成本過高且難以規模化。

**Q2：現有方法為何不足？**
A：現有方法主要落入兩個方法論上的局限：輕量化量化後設資料雖可大規模處理，但對底層問題解決過程的解釋力薄弱；人工分析雖具解釋性，卻難以負擔大規模軌跡的成本。此外，基於預先定義、專家推導行為模式所建構的分類器過於僵化，無法泛化到新穎任務與新興的智慧代理人行為。因此，機器學習社群目前缺乏一種既可擴展又具泛化性的方法來研究智慧代理人行為。

**Q3：為何這個問題重要？**
A：隨著大型語言模型使智慧代理人能處理軟體工程、網頁瀏覽、電腦使用與深度研究等複雜任務，代理人可能在長串局部合理的決策後仍然失敗。理解這些行為對於提升智慧代理人可靠性、診斷失敗模式至關重要。若缺乏可規模化的分析方法，開發者將無法系統性地辨識哪些行為促成成功、哪些行為導致失敗。

**Q4：論文提出的核心方法是什麼？**
A：論文提出將紮根理論（Grounded Theory）這個來自社會科學、已有六十年歷史的質性研究方法引入機器學習，作為分析智慧代理人軌跡的新方法。作者設計了 AutoTraceGT（透過紮根理論的自動化軌跡分析），這是第一個自動化執行紮根理論的多智慧代理人流程。此流程反覆進行開放編碼、主軸編碼與理論編碼，直到達到理論飽和，並產生針對各任務量身打造的行為分類法。

**Q5：AutoTraceGT 的關鍵創新是什麼？**
A：AutoTraceGT 是第一個端到端將紮根理論操作化用於智慧代理人軌跡分析的流程。它採用三個角色專精的編碼智慧代理人：OpenCode 負責描述單一軌跡中「哪些步驟發生什麼事」；AxialCode 將批次軌跡的分組標籤聚合成行為類別；TheoreticalCode 則將這些類別整合成理論敘事。同時，Manage 智慧代理人負責驅動方法論的核心：策略性取樣、持續比對與迭代，直到飽和為止。

**Q6：有哪些重要的設計選擇？**
A：設計上採用角色專精的智慧代理人分工，而非由單一模型完成所有編碼工作，以模擬紮根理論中不同層次的語義壓縮。流程以理論飽和作為原則性的停止準則，確保新取樣不再產生新結構時才終止。所有中間產物都保持機器可讀且可稽核，形成從原始軌跡到理論主張的透明軌跡。

**Q7：實驗使用了哪些資料集與模型？**
A：實驗使用了超過七千五百條軌跡，橫跨六個資料集與四個骨幹大型語言模型。這些資料集涵蓋網頁瀏覽、軟體工程、電腦使用與深度研究等多種智慧代理人任務。如此多樣的設定有助於檢驗方法在不同領域與模型後端上的泛化能力與穩健性。

**Q8：論文的主要實驗結果是什麼？**
A：AutoTraceGT 產生的編碼本能夠涵蓋人工標註分類法中 73% 至 91% 的失敗模式，同時還能發現那些人類分類法系統遺漏的額外模式。所產生的編碼本能達到飽和，並在獨立執行間具有可重現性。當把編碼本作為演繹特徵空間用於下游失敗預測時，其表現優於零樣本與少樣本的大型語言模型基線。

**Q9：是否有消融實驗或穩健性檢驗？**
A：作者在獨立執行與不同骨幹大型語言模型上評估了編碼本的可重現性，結果顯示其明顯區別於不同資料或模型歸納偏誤所造成的雜訊水準。他們也將自動誘導的編碼本與獨立建構的人工分類法進行比較，驗證其涵蓋率與發現額外模式的能力。此外，作者在多個後端模型上測試編碼本作為演繹特徵空間的失敗預測表現，確認其下游效用。

**Q10：這項方法有哪些實際應用場景？**
A：AutoTraceGT 可協助智慧代理人開發者診斷系統在複雜任務中為何失敗，從原始軌跡中歸納出行為模式。它能在不需要預先定義專家類別的情況下，為不同任務建構專屬的行為分類法。此外，產生的編碼本還可作為下游預測模型的特徵空間，支援失敗預測等應用。

**Q11：在產品化時需要考慮哪些因素？**
A：此方法產生的所有產物皆可稽核，對於生產環境中的信任建立與除錯非常重要。然而，由於需要反覆執行多個大型語言模型智慧代理人直到飽和，計算成本可能相當可觀。產品團隊應權衡洞察深度與計算開銷，並考慮是否採用漸進式取樣或人機協作來降低成本。

**Q12：這項研究對領域的廣泛影響是什麼？**
A：這篇論文顯示紮根理論能成為機器學習研究者與智慧代理人開發者研究「代理人實際做了什麼」的可擴展分析工具。它搭起了質性社會科學方法與量化機器學習分析之間的橋樑。這可能促使研究社群從僵化的預建分類器，轉向以資料為導向的歸納式行為分類法。

**Q13：作者承認哪些限制？**
A：自動化紮根理論可能繼承所使用骨幹大型語言模型的偏誤，例如對特定領域或行為模式的解讀偏差。編碼本的品質高度依賴模型理解長軌跡與推理行為的能力。此外，反覆迭代直到飽和的過程計算成本較高，可能限制即時或資源受限場景的應用。

**Q14：這個方法在哪些情況下可能失敗？**
A：當骨幹模型無法準確解讀智慧代理人的推理過程，或軌跡過長且雜訊過多時，此方法可能產生品質不佳的編碼。若模型在特定領域存在盲點，誘導出的編碼可能遺漏關鍵行為。此外，若軌跡分布過於異質或稀疏，理論飽和可能難以收斂，導致分類法不完整。

**Q15：未來研究方向為何？**
A：未來研究可引入人機協作驗證，以提升編碼本品質與可信度。研究者也可探索更高效的策略性取樣方法，在維持飽和的前提下降低計算成本。另一個方向是將此方法擴展到即時監控與互動式除錯，使開發者能在智慧代理人運行過程中動態理解其行為。

## 實務應用指南

## 適用場景

1. **生產環境智慧代理人事故根因分析**  
   當線上代理程式在真實任務中失敗、但僅有「成功／失敗」或「行動次數」等量化後設資料時，可用 AutoTraceGT 從軌跡中的推理文字歸納出行為模式，例如「忽略自身線索」「未經診斷即重試」，協助工程師定位失敗機轉。

2. **基準測試失敗模式分類法建構**  
   在建立新 benchmark 或評測現有框架（如 WebArena、SWE-bench）時，可用自動化紮根理論產生任務專屬的 codebook，補充專家預設分類法未涵蓋的額外模式，並提供可稽核軌跡。

3. **紅隊測試與合規稽核**  
   對話型或工具使用型代理程式的安全審查中，可用此方法大規模掃描軌跡，歸納出未預期的行為類別（如繞過提示、過度依賴單一工具），作為風險盤點與治理報告的證據基礎。

4. **客戶服務或流程自動化代理的品質監控**  
   將每日產生的數千條軌跡投入 AutoTraceGT，持續更新行為分類法，並把飽和後的 codebook 轉為特徵空間，用於下游失敗預測與異常偵測。

5. **多智慧代理人系統的協作問題診斷**  
   當多個代理程式互動產生長軌跡且失敗難以歸因時，可透過開放編碼標註各代理程式的局部行為，再經主軸編碼與理論編碼收斂出系統層級的失效敘事。

## 實作步驟建議

1. **界定研究問題與分析單位**  
   明確要回答的問題，例如「此代理程式在網頁瀏覽任務中為何失敗？」，並決定分析粒度（整段軌跡、子任務、或單一步驟）。

2. **收集與清理軌跡資料**  
   確保每條軌跡包含行動、觀察與推理文字；移除敏感資訊；將長軌跡切分為適合模型上下文長度的片段。

3. **執行自動化紮根理論管線**  
   依序運行：(1) **OpenCode**：為單條軌跡生成描述性編碼並附引用證據；(2) **AxialCode**：跨軌跡聚類並建立行為類別；(3) **TheoreticalCode**：整合類別為理論敘事。Manage 角色負責策略性抽樣與恆常比較，直到達到理論飽和。

4. **評估飽和度與再現性**  
   在不同隨機種子或不同骨幹模型下重複執行，計算 codebook 的穩定度；確認新增抽樣不再產生新類別，避免過早停止。

5. **與人工分類法對照與補充**  
   將產生的 codebook 與現有專家分類法比較，量化覆蓋率（如論文所述 73–91%），並檢視額外模式是否為真實新發現或雜訊。

6. **轉換為演繹式特徵空間**  
   將飽和 codebook 作為特徵字典，對新軌跡進行零樣本或少量樣本分類，訓練下游失敗預測模型，並監控特徵重要性。

7. **部署與持續迭代**  
   將 codebook 與分類器整合至觀測平台，定期以新軌跡重新執行 AutoTraceGT，更新行為分類法以捕捉新興行為。

## 潛在風險與注意事項

- **模型幻覺與虛構編碼**  
  LLM 可能產生看似合理但缺乏軌跡證據的編碼。應要求每個編碼都附帶原始引用，並以人工抽樣審查驗證可稽核軌跡。

- **假性飽和**  
  若抽樣策略過於同質，可能過早宣稱理論飽和。建議採用分層抽樣（成功／失敗、不同任務類型、不同長度），並以多輪獨立運行檢驗穩定度。

- **模型歸納偏誤**  
  不同骨幹模型可能偏好不同類別用詞。可透過跨模型比較與語意對齊（例如 embedding 相似度）降低單一模型的偏誤。

- **遺漏稀有但關鍵的失敗模式**  
  紮根理論以頻繁出現的模式為主，罕見安全事件可能被忽略。對於高風險場景，應結合規則式紅隊測試與專家標註。

- **資料隱私與機敏內容**  
  軌跡可能包含使用者輸入、程式碼或企業內部資料。上傳至第三方 LLM API 前應進行去識別化或採用本地部署模型。

- **過度擬合於特定任務**  
  產生的 codebook 具有任務專屬性，跨任務遷移時需重新執行管線，不宜直接套用。

## 與其他技術的整合建議

- **觀測與日誌系統**  
  將 AutoTraceGT 接入現有的代理程式觀測平台（如 LangSmith、Langfuse、自研日誌系統），自動擷取軌跡並觸發批次分析。

- **評測框架**  
  與 benchmark 執行環境（如 WebArena、SWE-bench、OSWorld）整合，在每次評測後自動產生失敗模式報告，補充成功率數字。

- **標註與審查工具**  
  將 OpenCode 產生的引用證據匯入標註介面，供人類質性研究者快速審核、修正編碼，形成人機協作迴路。

- **下游預測模型**  
  把 codebook 作為結構化特徵空間，與傳統機器學習（如梯度提升機）或輕量語言模型分類器結合，用於即時失敗風險預測。

- **CI/CD 與回歸測試**  
  在模型或代理程式框架更新後，比較新舊版本軌跡的 codebook 差異，偵測行為漂移或新引入的失敗模式。

- **向量資料庫與檢索**  
  將編碼與對應軌跡片段存入向量資料庫，支援以自然語言查詢類似失敗案例，加速除錯。

## 給不同背景讀者的閱讀建議

**初學者**  
建議先從圖 1 與摘要讀起，理解「量化後設資料無法解釋失敗原因」這個核心動機，再聚焦於「開放編碼→主軸編碼→理論編碼」的三階段流程，暫時跳過模型實作細節，把 AutoTraceGT 想像成「讓 AI 幫忙做質性研究的助理」即可。

**AI 工程師**  
請重點閱讀方法論中 OpenCode、AxialCode、TheoreticalCode 與 Manage 四個角色的分工、提示設計與飽和判斷機制，並參考論文的再現性實驗來評估是否適合自己的軌跡資料格式與規模；實作時優先確保每個編碼都有原始軌跡引用。

**研究者**  
建議深入檢視理論飽和的運作化定義、跨模型與跨資料集的穩定度分析，以及 codebook 與人工分類法之間的覆蓋率與額外模式比較；可進一步探討自動化紮根理論在方法論上的效度、偏誤與可解釋性問題。

**產品經理**  
請關注適用場景與實務價值：AutoTraceGT 能將大量難以閱讀的軌跡轉化為結構化行為分類法與可稽核軌跡，協助團隊從「知道失敗」進展到「理解為何失敗」，並支援下游監控與產品迭代決策。評估時請同時考量 LLM API 成本與人工審查所需資源。
