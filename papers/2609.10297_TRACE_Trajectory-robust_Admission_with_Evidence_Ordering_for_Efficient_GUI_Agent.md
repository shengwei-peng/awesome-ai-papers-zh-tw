## ⚡ TL;DR

GUI代理累積高解析度截圖使推論成本上升，快取重用下視覺令牌剪枝成不可逆承諾，須處理軌跡與覆蓋挑戰。
TRACE提出佈局先驗、巢狀排序、覆蓋修復與單調KV收縮四機制，實現一次性視覺證據承諾與單調縮減。
在六個GUI基準測試中驗證有效性，於嚴格預算下顯著降低延遲與KV記憶體，同時維持準確率。

## 摘要翻譯

GUI 代理在軌跡（Trajectory）展開過程中累積高解析度截圖（High-resolution Screenshot），導致推論延遲（Inference Latency）與記憶體使用量（Memory Usage）增加。無需訓練（Training-free）的視覺令牌剪枝（Visual Token Pruning）雖能降低此成本，但快取重用（Cache Reuse）引入了一項根本性的限制：一旦令牌被丟棄（Discard），對應的視覺證據（Visual Evidence）便無法在不重新編碼（Re-encoding）的情況下恢復（Recover）。因此，剪枝成為一項不可逆（Irreversible）的准入決策（Admission Decision），必須在嚴格預算（Tight Budget）下同時對未知的未來目標保持效用，並保留對可操作區域（Operable Regions）的覆蓋。為應對這些挑戰，我們提出 **TRACE**，一個無需訓練的框架，用於**軌跡穩健准入與覆蓋感知（Coverage-aware）證據排序**。具體而言，我們結合與查詢無關（Query-independent）的佈局衍生互動先驗（Layout-derived Interaction Prior）、指令相關性（Instruction Relevance）與特徵新穎性（Feature Novelty），根據潛在的未來效用（Future Utility）與多樣性（Diversity）對視覺證據進行排序。接著，我們保留部分預算（Budget）給分佈於螢幕各處的原生視覺令牌（Native Visual Tokens），在不破壞排序的前提下修復缺失的空間覆蓋（Spatial Coverage）。這些機制共同產生巢狀令牌順序（Nested Token Order），使保留的視覺證據能在不同預算下單調遞減，同時在整個軌跡中保持可重用性。最後，我們的單調 KV 收縮（Monotone KV Contraction）將已退役幀（Retired Frames）增量式收縮為精簡的會話狀態（Session State），避免重複的視覺編碼或剪枝。在六個 GUI 基準測試（Benchmark）及多種模型上的大量實驗驗證了 **TRACE** 在嚴格預算下的有效性。原始碼（Source Code）將公開釋出。

### 核心貢獻（3～5點）
- **問題重新詮釋**：將視覺令牌剪枝重新定位為不可逆的准入決策，揭示快取重用下「丟棄即永久失去視覺證據」的根本限制，並據此設計排序準則。
- **三維排序機制**：結合與查詢無關的佈局衍生互動先驗、指令相關性與特徵新穎性，依「潛在未來效用 × 多樣性」對視覺證據進行排序。
- **覆蓋感知修復**：預留部分預算給分佈於螢幕各處的原生視覺令牌，在不破壞巢狀順序的前提下修復缺失的空間覆蓋，避免覆蓋崩潰。
- **單調可重用性**：巢狀令牌順序使保留證據可隨預算單調遞減，並在整個軌跡中保持可重用；單調 KV 收縮將已退役幀增量式收縮為精簡會話狀態，省去重複編碼與剪枝成本。

### 適合對象
從事 GUI 代理（GUI Agent）、多模態大型語言模型（MLLM）推論優化、視覺令牌剪枝、KV 快取管理及高效視覺編碼研究之學者與工程師；亦適合關注長程多步任務（Multi-step Task）中視覺冗餘（Redundancy）處理與推論成本（Inference Cost）控制之實務應用開發者。

## 深度分析

#### 方法論解析

TRACE 的方法論核心在於重新定義視覺令牌剪枝（visual token pruning）在 GUI 代理（GUI agent）多步推理情境下的本質——從可重新修訂的查詢依賴選擇，轉變為**寫入時承諾（write-time commitment）**。這個轉變的根源在於快取重用（cache reuse）機制：當歷史截圖的視覺狀態被寫入會話快取（session cache）後，後續步驟只能從快取讀取而非像素，因此被丟棄的令牌無法在不重新編碼（re-encoding）整個幀的情況下恢復。這使得剪枝從「可逆選擇」變為「不可逆准入決策（irreversible admission decision）」。

**第一個組件 LIP（Layout-derived Interaction Prior，佈局衍生互動先驗）** 解決的是軌跡不確定性（trajectory uncertainty）問題。任務目標在准入時已知，但後續步驟的細粒度目標仍未知。LIP 利用介面佈局偵測結果，將可操作區域（operable regions）映射為一個與查詢無關（query-independent）的互動先驗，使准入決策能夠傾向於未來可能需要操作的區域。論文中 Fig. 1(c) 的實證顯示，當同一畫面在不同步驟重複出現時，基於指令的剪枝（如 CDPruner）會在後續步驟遺漏目標，而基於佈局的剪枝則能持續保留目標。

**第二個組件 NEO（Nested Evidence Ordering，巢狀證據排序）** 是整個框架的數學骨架。它將 LIP 提供的佈局先驗、指令相關性（instruction relevance）以及特徵新穎性（feature novelty）三種訊號融合為單一排序，並且這個排序必須滿足**巢狀性質（nested property）**：較緊預算下的保留集合必須是較寬鬆預算保留集合的子集（即前綴關係）。這個設計的關鍵在於，每個預算等級的保留集合都可以透過截取同一排序的前綴來實現，無需重新選擇或重新編碼。論文中 Fig. 1(b) 的數據顯示，獨立重新選擇（re-selection）需要對大多數幀重新編碼，而巢狀排序在準確率上幾乎沒有損失。

**第三個組件 NCR（Native-token Coverage Repair，原生令牌覆蓋修復）** 處理空間覆蓋（spatial coverage）問題。在嚴格預算（tight budget）下，偏置剪枝會將預算集中於少數顯著區域，導致其他可操作區域出現零令牌（zero-token）的情況。NCR 從預算中保留一部分用於分佈在整個螢幕上的原生視覺令牌（native visual tokens），修復缺失的空間覆蓋，同時不破壞 NEO 建立的巢狀順序。這是一個精巧的設計取捨：犧牲部分排序純度換取空間覆蓋的均勻性。

**第四個組件 MKC（Monotone KV Contraction，單調 KV 收縮）** 將上述准入決策轉化為可重用的會話狀態（session state）。當一個幀從當前幀退役為歷史幀時，MKC 將其收縮到歷史前綴（history prefix），並在下一個預填充（prefill）中重放保留的原生行。這避免了對歷史幀的反覆視覺編碼或剪枝，使得視覺證據（visual evidence）能夠單調縮減（shrink monotonically）跨預算等級。

整體而言，TRACE 的方法論展現了**生命週期感知（lifecycle-aware）** 的設計哲學：視覺證據在准入時承諾一次，之後單調收縮。這與傳統的查詢依賴剪枝方法（如 FastV、DivPrune、CDPruner、PruMerge）形成根本對比——後者假設每次查詢都可以重新選擇，而 TRACE 認識到在快取重用下這個假設不再成立。

#### 實驗數據解讀

從提供的 Fig. 1 數據可以解讀出幾個關鍵實驗發現：

**Fig. 1(a) — 快取重用的延遲效益**：圖表顯示隨著回合內步驟（step within episode）增加，TTFT（首令牌時間，Time to First Token）在三種配置下的表現。密集重新預填充（dense re-prefill）的 TTFT 隨步驟數線性增長至約 4000ms，而採用 MKC 重用（MKC reuse）後 TTFT 維持在接近 0ms 的水平。這驗證了快取重用機制對於多步 GUI 任務延遲控制的必要性——若無重用，每步都需要重新處理所有歷史截圖，延遲將無法控制。

**Fig. 1(b) — 巢狀排序的零成本**：Δ 準確率（Δ Acc.）的箱型圖顯示，在寬鬆預算（mild budget，50%/10%）和嚴格預算（tight budget，25%/5%）下，重新選擇與巢狀排序的準確率差異集中在 0 附近。這是一個重要的實證：巢狀順序作為一個看似更受限的設計選擇，並未犧牲準確率。這意味著設計者可以免費獲得「跨預算可重用性」這個額外性質。

**Fig. 1(c) — 佈局先驗的目標保留能力**：在 ScreenSpot-v2 基準上，佈局引導剪枝（LIP-guided pruning）的目標保留率（within-goal target retention）顯著高於指令剪枝（CDPruner）和多樣性剪枝（DivPrune）。這個結果支持了論文的核心論點：在軌跡不確定性下，查詢無關的佈局先驗比查詢相關的指令訊號更能預測未來目標。

**Fig. 1(d) — 覆蓋崩潰與修復**：圖表顯示隨著保留比率（keep ratio r）從 50% 降至 5%，均勻基線（uniform baseline）的零令牌比率（zero-token ratio）上升，而 TRACE 的零令牌比率始終低於均勻基線。相比之下，FastV 和 CDPruner 在嚴格預算下出現覆蓋崩潰（coverage collapse），零令牌比率急劇上升。這驗證了 NCR 組件在維持空間覆蓋方面的有效性。

雖然具體的數字表格未在提供的文本中，但 Fig. 1 的視覺化數據已足以說明 TRACE 在四個維度上的優勢：延遲控制、跨預算穩定性、目標保留能力、以及空間覆蓋維持。論文中提到實驗涵蓋六個 GUI 基準、多種模型規模以及跨家族骨幹網路，這暗示了結果的穩健性。

#### 與現有研究的比較

TRACE 在視覺令牌剪枝的演進譜系中佔據獨特位置。**FastV** 基於注意力分佈（attention distribution）剪枝，**DivPrune** 強調特徵多樣性（feature diversity），**CDPruner** 聚焦指令相關性（instruction relevance），**PruMerge** 則將冗餘令牌合併為合成摘要（synthetic summary）。這些方法的共同假設是：剪枝可以隨查詢變化而重新計算。

TRACE 的根本差異在於**問題重新定義**：它不將剪枝視為查詢時的選擇問題，而是寫入時的承諾問題。這使得傳統方法在快取重用場景下失效——因為被丟棄的令牌無法恢復。TRACE 透過巢狀順序設計，使得「一次承諾、多預算可用」成為可能，這是現有方法無法提供的性質。

在 GUI 代理效率方面，**CogAgent** 採用訓練式方法，結合低解析度骨幹與高解析度交叉注意力模組；**ReVision** 則學習削減時間視覺冗餘。這些訓練式設計需要昂貴的預訓練成本，而 TRACE 作為無需訓練（training-free）的方法，在部署靈活性上具有優勢。

然而，TRACE 也有其**限制**：

1. **佈局偵測的依賴性**：LIP 組件依賴於介面佈局偵測的準確性。對於動態或非標準化介面，佈局偵測可能不準確，從而影響先驗品質。

2. **原生令牌的覆蓋與排序張力**：NCR 從預算中撥出一部分用於空間覆蓋的原生令牌，這本質上是與 NEO 排序的取捨。在極度嚴格的預算下，這個取捨可能變得困難。

3. **單調收縮的資訊損失**：MKC 的單調收縮意味著一旦令牌被收縮，就無法恢復。雖然這在巢狀順序下是合理的設計，但對於需要偶爾回顧早期視覺細節的任務可能不夠靈活。

4. **評估範圍**：雖然涵蓋六個基準，但 GUI 任務的多樣性極高，特定領域（如遊戲介面、專業軟體）的泛化能力仍需驗證。

#### 可重現性評估

從提供的文本來看，論文中明確聲明「原始碼將會釋出（The source code will be released）」，這是一個積極的信號，但具體的釋出時間和平台（如 GitHub）未在文本中說明。

**可重現性的有利因素**：

1. **無需訓練的方法**：TRACE 是無需訓練的框架，這消除了預訓練權重、訓練資料和超參數調優的不確定性。
2. **明確的組件定義**：四個組件（LIP、NEO、NCR、MKC）都有清晰的功能劃分，便於獨立實作和驗證。
3. **多基準評估**：六個 GUI 基準的評估提供了多角度的驗證機會。
4. **跨模型測試**：涵蓋多種模型規模和跨家族骨幹網路，這有助於驗證方法的泛化性。

**可重現性的潛在挑戰**：

1. **佈局偵測器的選擇**：LIP 依賴於佈局偵測，論文中未明確說明使用的是哪種偵測器及其權重。
2. **融合權重的設定**：NEO 中三種訊號（佈局先驗、指令相關性、特徵新穎性）的融合權重如何設定，這些超參數的選擇對結果有影響。
3. **原生令牌的分配策略**：NCR 中原生令牌的數量和分佈策略需要明確說明。
4. **MKC 的實作細節**：歷史前綴的具體收縮策略和重放機制需要詳細的實作說明。

整體而言，TRACE 的可重現性處於中等偏上水平——方法論清晰且無需訓練，但部分實作細節需要等待原始碼釋出後才能完全驗證。

#### 未來研究方向

TRACE 開啟了「生命週期感知視覺剪枝」這個研究方向，有幾個值得探索的延伸：

**1. 自適應預算分配**：目前的設計中，NCR 的原生令牌數量是固定的。未來可以探索根據畫面複雜度或任務階段動態調整原生令牌與排序令牌的預算比例。

**2. 跨幀資訊共享**：雖然 MKC 處理了單幀內的單調收縮，但跨幀的視覺證據關聯尚未被充分利用。可以探索如何在不同幀之間共享視覺證據，例如透過跨幀的注意力機制或記憶體網路。

**3. 動態佈局先驗**：LIP 目前使用靜態的佈局偵測結果。可以探索隨著代理與介面互動，動態更新佈局先驗，使其更貼近實際的可操作區域。

**4. 與其他效率技術的整合**：TRACE 專注於視覺令牌剪枝，可以與其他效率技術（如投影片注意力、量化、推測解碼）結合，進一步降低 GUI 代理的推論成本。

**5. 理論分析巢狀順序的必要性**：目前巢狀順序的設計是經驗性的，未來可以從資訊理論或最佳化角度分析為什麼巢狀順序在快取重用下是必要的，以及是否存在更優的排序結構。

**6. 擴展到其他多模態代理**：TRACE 的問題定義不限於 GUI 代理，可以探索其在機器人視覺、影片理解等其他多步多模態任務中的適用性。

**7. 錯誤恢復機制**：雖然 MKC 的單調收縮在正常情況下是合理的，但對於代理犯錯需要回溯的情境，目前的設計缺乏恢復機制。未來可以探索如何在保持巢狀性質的同時，允許有限的視覺證據恢復。

這些方向不僅能深化 TRACE 本身的理論基礎，也能將其影響擴展到更廣泛的多模態代理效率研究領域。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於 GUI 代理在多步任務中視覺推論成本過高的問題。隨著軌跡展開，代理會累積大量高解析度截圖，每張截圖都包含大量視覺令牌，導致推論延遲與記憶體使用量急劇上升。雖然快取重用機制能在幀粒度上緩解時間冗餘，但每張保留的截圖內部仍存在大量空間冗餘。因此，核心問題在於決定哪些視覺令牌應該進入每幀的可重用狀態，以在嚴格預算下維持代理的可操作性。

**Q2：為什麼現有的視覺令牌剪枝方法在 GUI 代理場景下會失效？**
A：現有方法如 FastV、DivPrune、CDPruner 與 PruMerge 都是在查詢變動時可重新計算的選擇機制，但 GUI 代理的多步服務打破了這個前提。一旦視覺狀態變得可重用，每張截圖只在首次預填充時編碼並寫入會話快取，後續步驟從快取讀取歷史而非像素，因此被丟棄的令牌對未來查詢永遠消失，只能透過重新編碼整個畫面來恢復。這使得視覺令牌剪枝從可重新審視的選擇，變成寫入時的不可逆承諾，而現有方法並未針對這種不可逆性進行設計。

**Q3：為什麼這個問題在實務上很重要？**
A：GUI 代理正被廣泛部署以完成多步任務，每一步都需要處理高解析度截圖並結合早期互動的上下文。視覺計算很快就會主導推論成本，因為每張歷史截圖都帶有大量視覺令牌並在後續步驟中重複出現。若無法有效控制視覺令牌的數量與分佈，代理的回應速度與可擴展性將受到嚴重限制，進而影響其在實際產品中的可用性與部署成本。

**Q4：TRACE 框架的核心方法是什麼？**
A：TRACE 是一個無需訓練的框架，結合了四個關鍵組件：佈局衍生互動先驗（LIP）、巢狀證據排序（NEO）、原生令牌覆蓋修復（NCR）與單調 KV 收縮（MKC）。LIP 將佈局偵測結果映射為互動先驗，使准入決策能在後續目標出現前就傾向可操作區域。NEO 則將這個先驗與指令相關性及特徵新穎性融合成單一巢狀順序，讓每個更嚴格的預算都能以前綴形式實現，而非重新選擇。

**Q5：TRACE 的關鍵創新點為何？**
A：TRACE 的關鍵創新在於將視覺令牌剪枝重新詮釋為「寫入時的視覺證據承諾」，並提出生命週期感知的視覺剪枝機制。不同於傳統可重新選擇的剪枝方法，TRACE 強調一旦視覺證據被准入就必須在整個軌跡中可重用，並透過巢狀順序確保歷史保留集合嵌套於當前集合中。此外，單調 KV 收縮機制讓已退役的幀能夠單調地收縮為緊湊的會話狀態，避免重複的視覺編碼或剪枝。

**Q6：TRACE 在設計上做了哪些重要取捨？**
A：TRACE 在設計上選擇結合三種互補的訊號：查詢無關的佈局先驗、指令相關性與特徵新穎性，以同時兼顧未來效用與多樣性。為了避免嚴格預算下覆蓋崩潰的問題，NCR 保留部分預算給分散於螢幕的原生視覺令牌，以修復缺失的空間覆蓋卻不破壞巢狀順序。這些設計取捨使 TRACE 能在不重新編碼歷史幀的前提下，於不同預算下維持單調縮減的可重用視覺證據。

**Q7：實驗使用了哪些基準測試？**
A：實驗橫跨六個 GUI 基準測試，涵蓋單步與多步設定，並包含多種模型規模與跨家族骨幹網路。這樣的設計是為了驗證 TRACE 在不同任務複雜度與模型架構下的泛用性與穩健性。具體的基準測試細節在論文中以表格形式呈現，並搭配 ScreenSpot-v2 等知名基準進行空間覆蓋與目標保留的深入分析。

**Q8：主要的實驗結果為何？**
A：實驗結果顯示 TRACE 在嚴格預算下仍能維持優異的準確率，並顯著降低首令牌時間（TTFT）與 KV 快取使用量。圖 1 的結果顯示，與密集重新預填充相比，TRACE 的 MKC 重用機制能有效減少重複編碼；在巢狀順序方面，重新選擇與巢狀順序之間的準確率差異幾乎為零，證明巢狀化並無準確率損失。此外，TRACE 在 ScreenSpot-v2 等基準上於不同保留比率下皆優於 FastV、CDPrune 與均勻基線。

**Q9：是否有進行消融研究？**
A：是的，論文中透過圖 1 的多個子圖展示了各組件的必要性與互補性。圖 1(c) 顯示指令式剪枝會在後續步驟錯失目標，而佈局式剪枝能保留目標；圖 1(d) 則說明僅依賴顯著區域的剪枝會導致覆蓋崩潰，而 TRACE 的覆蓋修復機制能避免此問題。這些可視化結果驗證了 LIP、NCR 與 NEO 等組件各自對整體效能的關鍵貢獻。

**Q10：TRACE 在哪些實際場景中特別有用？**
A：TRACE 特別適用於需要長時間多步互動的 GUI 自動化場景，例如網頁表單填寫、軟體測試自動化、跨應用程式工作流程等。在這些場景中，代理會反覆處理高解析度截圖並累積大量歷史視覺資訊，而 TRACE 的單調 KV 收縮機制能有效控制記憶體增長，使代理能在不丟失關鍵視覺證據的前提下持續運作。這對於需要在企業環境中長時間執行的批次任務尤其重要。

**Q11：在產品化時需要考慮哪些工程因素？**
A：產品化時需要考慮佈局偵測的計算成本與延遲，因為 LIP 依賴於介面元素的即時偵測結果。此外，會話快取的大小與單調收縮的時機需要仔細設計，以避免在邊緣裝置上造成記憶體瓶頸。同時，由於 TRACE 是無需訓練的方法，可以直接整合到現有的 MLLM 推論管線中，但需要確保 KV 收縮操作與預填充、解碼階段的排程正確銜接。

**Q12：這項研究對 GUI 代理領域的影響為何？**
A：這項研究將視覺令牌剪枝從「可重新選擇的篩選」轉變為「寫入時的承諾」，為 GUI 代理的效率優化提供了新的理論框架。TRACE 提出的生命週期感知剪枝概念，可望啟發後續研究重新思考視覺證據在多步代理中的管理方式。同時，巢狀順序與單調收縮的設計理念也可能被推廣到其他需要可重用視覺狀態的多模態代理場景。

**Q13：論文是否承認了哪些限制？**
A：論文雖然展示了廣泛的實驗驗證，但主要聚焦於 GUI 代理場景，對於其他多模態代理（如機器人視覺或影片理解）的適用性仍待探索。此外，佈局先驗的品質高度依賴於底層的佈局偵測模型，若偵測結果不準確，可能會影響 LIP 的有效性。嚴格預算下的效能雖然優於基線，但相較於寬鬆預算仍可能有可觀察的準確率下降。

**Q14：在哪些情況下 TRACE 可能會失敗？**
A：當介面佈局極為非標準或佈局偵測模型無法正確識別可操作區域時，LIP 的先驗可能會誤導准入決策，導致關鍵區域的令牌被過度剪枝。此外，在動態或高度動畫化的介面中，靜態的佈局先驗可能無法捕捉到短暫出現的可操作元素。若任務目標完全偏離佈局先驗所偏好的區域，且指令相關性訊號也較弱時，TRACE 可能會面臨取捨困難。

**Q15：未來的研究方向有哪些？**
A：未來可以探索將生命週期感知剪枝的概念擴展到影片理解與機器人視覺等其他多模態代理場景，以驗證其通用性。此外，佈局先驗可以進一步與學習式方法結合，例如透過小型 adapter 動態調整先驗權重，以適應不同類型的介面。另一個有前景的方向是研究如何在不重新編碼的前提下，允許已退役幀進行有限的視覺證據更新，以處理需要回溯查詢的特殊任務場景。

## 實務應用指南

### 適用場景

1. **企業內部 RPA 自動化代理**：在 ERP、CRM 等高解析度業務系統中，代理需連續多步操作表單、按鈕與下拉選單。TRACE 的佈局衍生互動先驗（LIP）能預先標記可操作區域，避免在嚴格預算下遺漏關鍵按鈕；單調 KV 收縮（MKC）則讓長流程任務的歷史截圖不會反覆重新編碼，顯著降低 TTFT 與記憶體峰值。

2. **行動裝置 UI 測試代理**：在 Android/iOS 自動化測試中，代理需在多個畫面間切換並驗證元件狀態。巢狀證據排序（NEO）允許測試平台動態調整視覺令牌預算（從寬鬆到嚴格），而無需重新編碼歷史幀；原生令牌覆蓋修復（NCR）則確保小尺寸元件（如核取方塊、開關）在 5%–10% 嚴格預算下仍被保留。

3. **網頁爬取與資料擷取代理**：面對動態載入的網頁，代理需在多個分頁間導航。TRACE 的訓練免費特性使其可直接部署於現有多模態大型語言模型（MLLM）後端，無需重新訓練；佈局先驗能優先保留導航列、表單欄位等高機率可操作區域。

4. **無障礙輔助代理**：為視障使用者操作複雜軟體介面時，代理需在嚴格延遲預算下維持高準確率。TRACE 在 ScreenSpot-v2 等基準上驗證的覆蓋感知機制，能避免「覆蓋崩潰」導致代理錯失關鍵可操作區域。

5. **雲端 GUI 代理服務（SaaS）**：在多租戶環境中，服務需同時服務數百個代理會話。TRACE 的單調 KV 收縮機制能將已退役幀壓縮為緊湊的會話狀態，使單一 GPU 可容納更多並發會話，降低單位任務成本。

### 實作步驟建議

**階段一：環境準備與基線建立**
1. 選定骨幹 MLLM（論文中涵蓋 Qwen2-VL、InternVL2 等），並部署標準推論管線。
2. 實作 Dense Re-prefill 基線，量測 TTFT、KV 記憶體與 ScreenSpot-v2 等基準的準確率，作為對照組。
3. 整合版面配置偵測模型，產出每幀的可操作區域熱圖，作為 LIP 的輸入。

**階段二：核心模組實作**
4. **LIP 模組**：將版面配置偵測結果映射為互動先驗分數，建議使用 sigmoid 校準使分數與「可操作機率」對齊。
5. **NEO 模組**：將 LIP 分數、指令相關性（來自骨幹的注意力分佈）、特徵新穎性（特徵間餘弦距離）融合為單一巢狀排序。實作時需確保排序結果的前綴性質——即較小預算的保留集合必須是較大預算保留集合的子集。
6. **NCR 模組**：在排序完成後，從預算中保留一部分（如 10%–20%）用於均勻分佈的原生視覺令牌，修復空間覆蓋。建議以網格採樣或基於版面配置的採樣策略實作。
7. **MKC 模組**：當幀從當前上下文退役為歷史時，將其 KV 快取收縮為對應預算的歷史前綴；下一輪預填充時，僅重播保留的原生視覺令牌行。

**階段三：整合與評估**
8. 將四個模組整合進代理推論迴圈，確保每幀僅在首次預填充時執行 LIP + NEO + NCR，後續步驟僅觸發 MKC。
9. 在六個 GUI 基準（含單步與多步設定）上評估，特別關注 5%–25% 嚴格預算下的覆蓋率與目標保留率。
10. 進行消融實驗，驗證 LIP、NEO、NCR、MKC 各模組的獨立貢獻。

**階段四：產品化優化**
11. 將版面配置偵測卸載至獨立服務或預計算快取，降低主推論管線的延遲。
12. 實作動態預算調整策略，根據任務複雜度自動選擇寬鬆或嚴格預算。
13. 加入監控儀表板，追蹤零令牌比率、TTFT、KV 記憶體等關鍵指標。

### 潛在風險與注意事項

**風險一：版面配置偵測失效**
- **情境**：在自訂 UI、遊戲介面或低對比度截圖上，版面配置偵測模型可能漏偵關鍵元素。
- **緩解**：保留指令相關性作為備援訊號；當 LIP 分數低於閾值時，自動提高指令相關性的權重。

**風險二：巢狀順序破壞**
- **情境**：若 NEO 的排序演算法不具備嚴格前綴性質（如使用隨機採樣或非確定性排序），則 MKC 無法正確收縮。
- **緩解**：在排序階段使用穩定排序演算法，並加入單元測試驗證任意兩個預算的保留集合滿足子集關係。

**風險三：覆蓋崩潰**
- **情境**：在極嚴格預算（5% 以下）下，即使有 NCR，仍可能出現大面積無令牌區域。
- **緩解**：設定 NCR 的最低保留比例（如 15%），並在監控中對零令牌比率設定告警閾值。

**風險四：跨模型泛化**
- **情境**：LIP 的校準參數可能針對特定骨幹（如 Qwen2-VL）過擬合，遷移到其他模型時效能下降。
- **緩解**：在多個骨幹上進行校準，使用小型驗證集調整融合權重；或將 LIP 設計為可學習的輕量適配器。

**風險五：會話狀態一致性**
- **情境**：MKC 收縮後，若代理需要回溯到更早的歷史幀，可能因預算不足而遺失關鍵視覺證據。
- **緩解**：為關鍵幀（如任務起點、確認對話框）設定最低保留預算；或實作選擇性重新編碼機制，僅針對高優先級幀觸發重編碼。

### 與其他技術的整合建議

**與視覺令牌剪枝方法整合**
- TRACE 可作為「骨幹層」與其他剪枝方法（如 FastV、DivPrune、CDPruner）組合。建議將 FastV 的注意力分佈作為 NEO 的指令相關性輸入，將 DivPrune 的多樣性選擇作為特徵新穎性輸入，再以 LIP 進行加權。
- 與 PruMerge 等令牌合併方法互補：TRACE 負責決定保留哪些原生令牌，PruMerge 負責將被剪枝的令牌合併為合成摘要，兩者可串接使用。

**與 MLLM 骨幹整合**
- 對於支援動態視覺令牌數的骨幹（如 Qwen2-VL），可直接將 TRACE 的巢狀排序結果映射為保留令牌的索引。
- 對於固定視覺令牌數的骨幹，建議在骨幹前端加入輕量適配層，將保留的原生令牌與填充令牌組合為固定長度輸入。

**與代理框架整合**
- 在 LangChain、AutoGen 等代理框架中，將 TRACE 封裝為視覺預處理中介層；代理只需呼叫標準介面，無需感知底層的剪枝與收縮邏輯。
- 與 ReAct、Reflexion 等推理框架整合時，建議在推理步驟前觸發 LIP 重新評估，以處理版面配置變化。

**與快取管理系統整合**
- MKC 的會話狀態可整合至 vLLM、TensorRT-LLM 等推論引擎的 KV 快取管理模組；建議將其實作為自訂快取淘汰策略。
- 對於分散式部署，可將會話狀態儲存於 Redis 或共享記憶體，使多個推論實例能共享退役幀的收縮結果。

**與監控與可觀測性整合**
- 將零令牌比率、目標保留率、TTFT 等指標匯出至 Prometheus/Grafana，建立視覺證據健康度儀表板。
- 整合 OpenTelemetry，追蹤每幀的 LIP、NEO、NCR、MKC 執行時間，定位效能瓶頸。

**給初學者**：建議先閱讀第 1 節的動機說明（特別是圖 1 的四個子圖），理解「為什麼 GUI 代理需要視覺令牌剪枝」以及「為什麼快取重用會改變剪枝的本質」。接著跳過技術細節，直接看第 1 節末尾的貢獻總結，建立對 TRACE 四大模組（LIP、NEO、NCR、MKC）的高階認知。實作上可先從跑通論文的開源程式碼開始，使用預設配置在 ScreenSpot-v2 上重現結果，再逐步調整參數觀察行為變化。

**給 AI 工程師**：重點閱讀第 1 節中關於「生命週期感知視覺剪枝」的問題定義，理解「寫入時承諾」與「巢狀保留集合」這兩個核心約束。實作時建議先單獨實作 LIP 模組並驗證其在版面配置偵測失效時的降級行為，再逐步整合 NEO 的融合邏輯。特別注意 NEO 的排序演算法必須具備嚴格前綴性質，否則 MKC 將無法正確運作。整合至現有推論管線時，建議將 TRACE 封裝為視覺預處理中介層，以降低對骨幹程式碼的侵入。

**給研究者**：本文的核心理論貢獻在於將視覺令牌剪枝重新定義為「軌跡不確定性下的寫入時視覺證據承諾」，並提出巢狀順序作為解決方案。建議從這個抽象框架出發，探索以下方向：(1) 將巢狀順序推廣到其他模態（如音訊、視訊）；(2) 研究理論上界，分析巢狀順序相對於最佳重新選擇的效能損失；(3) 將 LIP 的佈局先驗與其他類型的先驗（如時序先驗、使用者偏好先驗）結合。此外，論文中關於「覆蓋崩潰」的分析（圖 1d）值得深入探討，可考慮將其形式化為資訊理論問題。

**給產品經理**：TRACE 的商業價值在於「在嚴格預算下維持高準確率」與「降低單位任務成本」這兩個面向。具體而言，TRACE 能讓 GUI 代理服務在相同硬體上服務更多並發用戶（透過 MKC 降低 KV 記憶體），或在邊緣裝置上部署更複雜的代理（透過視覺令牌剪枝降低推論延遲）。評估導入價值時，建議關注三個指標：(1) 嚴格預算（5%–10%）下的任務完成率；(2) 平均 TTFT 與 P99 TTFT；(3) 單 GPU 可服務的並發會話數。導入時建議先在內部 RPA 場景試點，驗證穩定性後再推廣至客戶-facing 場景。
