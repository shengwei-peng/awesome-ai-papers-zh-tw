## ⚡ TL;DR

現有視覺鋼琴轉譜僅用短片段、收音差且忽略力度，音訊轉譜更因延音踏板而混淆真實放鍵時刻。
本文提出V2N，以共享時序骨幹搭配多任務預測頭，逐幀監督起音、收音、按鍵持續與力度。
多任務監督與更長時序脈絡同步提升起音、收音與力度預測，並在PianoVAM與R3創下最佳表現。

## 摘要翻譯

基於音訊的鋼琴轉譜（Audio-based Piano Transcription）在起音（Onset）、音高（Pitch）與觸鍵力度（Velocity）上已有良好表現，但延音踏板（Sustain Pedal）會使聲音在琴鍵放開後仍持續良久，因此音訊系統預測的是延音踏板延伸的收音（Pedal-extended Offset），而非實際琴鍵放開（Physical Key Release）。然而，現有的視覺鋼琴轉譜（Visual Piano Transcription, VPT）系統僅聚焦於短影片視窗（Short Video Windows）內的起音偵測，收音（Offset）準確率遠落後於起音，且音符層級力度（Note-level Velocity）預測迄今尚未見諸報導。為填補這些缺口，本文提出 V2N（Video to Notes，影片到音符），作為首個完整的 VPT 系統：共享時間骨幹網路（Shared Temporal Backbone）將時序特徵饋入針對起音、收音、琴鍵按住狀態（Key Hold）與力度（Velocity）的任務特定頭部（Task-specific Heads），並以逐幀監督（Per-frame Supervision）進行聯合訓練，而非僅於視窗中心（Window Center）幀進行監督。消融實驗顯示，多任務監督（Multi-task Supervision）不僅能實現收音與力度預測，同時亦能提升起音準確率；更長的時間上下文（Temporal Context）則帶來進一步提升。V2N 在 PianoVAM 與 R3 上創下新的最佳水準（State-of-the-art）。

### 核心貢獻（3～5點）
- 提出首個完整的視覺鋼琴轉譜系統 V2N，同時預測起音、收音、琴鍵按住狀態與音符層級力度。
- 採用共享時間骨幹網路搭配多任務特定頭部，並以逐幀監督進行聯合訓練。
- 證明多任務監督能同時實現收音與力度預測，並進一步提升起音準確率。
- 顯示更長的時間上下文有助於提升視覺鋼琴轉譜表現。
- 在 PianoVAM 與 R3 資料集上創下新的最佳水準。

### 適合對象
適合對電腦視覺、音樂資訊檢索及自動音樂轉譜（AMT）有興趣的研究者與工程師，特別是關注視覺鋼琴轉譜（VPT）、多任務學習與細粒度音符事件預測的讀者。

## 深度分析

#### 方法論解析

V2N（Video to Notes，影片到音符）的核心貢獻在於把 Visual Piano Transcription（視覺鋼琴轉譜，VPT）從過去僅預測「視窗中心幀（window center）」的單一 onset（起音）任務，擴展成同時預測 onset、offset（收音）、key hold（琴鍵按住狀態）與 velocity（力度）四個任務的完整系統。其方法論可從「任務定義」「網路架構」「監督方式」「解碼策略」四個層面拆解。

**1. 任務定義：以實體琴鍵狀態取代聲音結束時刻**

不同於 Audio-based Piano Transcription（基於音訊的鋼琴轉譜）在 sustain pedal（延音踏板）踩下時會把 offset 延伸到「聲音結束（end of sound）」，V2N 直接以影片觀察到的 physical key release（實際琴鍵放開）作為 ground truth。作者定義四個幀級（frame-level）預測目標：

- onset：琴鍵按下瞬間，與音訊系統共享同一事件概念。
- offset：琴鍵實際回彈，對應 MIDI Note Off event（MIDI 音符關閉事件）。
- key hold：標註 [onset, offset) 區間內琴鍵持續被按住的實體狀態，相當於音訊領域的 audio active（音訊活躍狀態）但不受踏板影響。
- velocity：每個音符的 normalized MIDI velocity（歸一化 MIDI 力度值），在 onset 發生時賦予該音符。

這樣的定義讓 VPT 首次能夠輸出與 MIDI 符號完全對齊的 NoteOn/NoteOff/Velocity 三元組，並在踏板介入時仍保持物理正確性。

**2. 網路架構：共享時序骨幹 + 任務特定頭部**

V2N 的網路由三階段組成：

- **視覺特徵抽取器（Visual Feature Extractor）**：採用 S2S（Sight-to-Sound）的 ResNet-18 前端，並加入 learnable slope prior（可學習的斜率先驗）把水平像素位置對應到 88 個琴鍵。每個輸入幀以 5-frame window（5 幀視窗，約 0.2 秒）進行局部聚合，再經 Global Average Pooling（GAP）與線性投影進入後續骨幹。
- **共享時序骨幹（Shared Temporal Backbone）**：使用 L=3 層 Conformer ConvModule block，但刻意省略 self-attention，僅保留 FFN → depthwise 1D convolution（kernel size 31）→ FFN 的結構。三層卷積提供約 1 秒的有效感受野，讓模型能觀察更長的 temporal context（時間上下文）。
- **任務特定頭部（Task-specific Heads）**：四個並行的 BiLSTM → Linear head，分別輸出 onset、offset、key hold 與 velocity。其中 onset、offset、key hold 使用 sigmoid 輸出並以 threshold τ=0.5 二值化；velocity 使用線性輸出，並在推論時裁剪到 [0,1] 再映射到 0–127。

**3. 監督方式：逐幀監督與多任務聯合訓練**

過去 VPT 方法只在視窗中心幀進行監督，導致時間解析度受限。V2N 改採 per-frame supervision（逐幀監督），對每一個影像幀都給予標註：

- onset 與 offset 標籤使用 soft triangular kernel（軟三角核），在事件幀為 1.0，向兩側線性衰減至 0（ℓ=2）。這種設計對標註抖動（labeling jitter）更具容忍度，並把梯度分散到鄰近幀。
- key hold 為二元標籤，在 [onset, offset) 區間內皆為 1，提供 dense supervision（密集監督）。
- velocity 僅在 onset 位置計算損失（onset-masked loss），避免非起音幀的干擾。

多任務監督（multi-task supervision）是方法論的關鍵：作者透過消融實驗指出，同時預測 offset、key hold 與 velocity 不僅讓後兩者成為可能，還能回過頭提升 onset 的準確率。這呼應了音訊領域 Onsets and Frames 的經驗——onset 與 frame-activity 的互補性能顯著改善轉譜表現。

**4. 解碼策略：峰值偵測與 key hold 兜底**

推論時，V2N 先偵測 onset 機率序列的峰值（peak）作為音符起點，並把該幀的 velocity 預測值賦予該音符；再偵測對應 key 的 offset 峰值作為音符終點。若 key hold 訊號先結束，則以 key hold 的終點作為 note end。這種設計結合了 onset/offset 的事件偵測優勢與 key hold 的區間連續性，降低單一 offset 峰值漏檢造成的音符過長問題。

#### 實驗數據解讀

雖然提供的上下文未包含完整表格，但從摘要與內文仍可歸納出幾項重要的實驗發現與其意涵。

**1. 多任務監督的效益**

消融實驗顯示，單獨預測 onset 時模型已能達到一定水準，但加入 offset、key hold 與 velocity 的聯合訓練後，onset 表現進一步提升。這說明：

- key hold 提供了「琴鍵是否被按住」的密集訊號，可作為 onset 與 offset 之間的橋樑，減少誤判。
- offset 任務迫使模型學習琴鍵回彈的視覺線索（例如鍵帽上升、手指離鍵），這些線索與 onset 的按鍵動作共享底層運動特徵。
- velocity 任務雖然只在 onset 幀計算損失，但其梯度仍會影響視覺特徵抽取器，使其對「按鍵速度與深度」更敏感，進而改善 onset 偵測。

**2. 更長時間上下文的重要性**

現有 VPT 方法（S2S、Video2RollNet、PPAN）最多只處理 0.2 秒的短影片視窗（short video windows），相當於 5–6 幀。V2N 將有效感受野擴展到約 1 秒，並透過三層 Conformer ConvModule 進行時序建模。更長的 temporal context 帶來兩大好處：

- 對於快速音群或裝飾音，模型能觀察前後文以區分真正的 onset 與視覺雜訊。
- 對於 offset 預測，模型需要判斷琴鍵是否真正回彈，而非暫時放鬆，長期脈絡有助於抑制誤報。

作者也指出，雖然 V2N 的 FLOPs 約為 PPAN 的 1.7 倍，但 wall-clock time（實際執行時間）與 PPAN 相當，因此 1 秒視窗並未造成實務延遲。

**3. Offset 與 Velocity 的首次系統性評估**

過去 VPT 文獻中，offset accuracy（收音準確率）明顯落後 onset accuracy，例如 PPAN 在 PianoVAM 上的 offset F1 僅 45.9%（50 ms tolerance）。V2N 透過多任務與長時序建模，顯著縮小這段差距，並首次報告 note-level velocity（音符層級力度）的表現。這讓 VPT 從「只能判斷何時按下」進步到「能輸出完整 MIDI 事件」。

**4. 跨資料集遷移的瓶頸**

作者在 cross-dataset transfer（跨資料集遷移）實驗中發現，V2N 與先前系統在面對不同資料集時會出現類似的失敗模式。這指出問題不在模型容量，而在 fixed-geometry preprocessing（固定幾何預處理）：所有方法都依賴裁剪好的鍵盤區域與固定的鍵位對應，一旦攝影機角度、解析度或鍵盤佈局改變，模型就難以泛化。這項發現對未來研究具有警示作用——追求單一資料集上的 state-of-the-art（最先進表現）並不能解決真實場景的部署問題。

#### 與現有研究的比較

**1. 相較於 Audio-based Piano Transcription**

音訊轉譜在 onset、pitch、velocity 上已相當成熟，並發展出 Transformer architectures（Transformer 架構）、high-resolution onset/offset regression（高解析度起音／收音迴歸）、neural semi-CRF event-based decoding（神經半條件隨機場事件解碼）等技術。然而，這些方法在 sustain pedal 踩下時，會把 offset 延伸到 pedal release，導致預測的 offset 與 MIDI Note Off 可能相差數秒。V2N 的優勢在於：

- 直接觀察 physical key release，不受踏板狀態影響。
- 在音訊退化、混音、缺失或環境嘈雜時仍可使用。
- 首次把 multi-task paradigm（多任務典範）從音訊移植到視覺，並針對視覺線索（finger motion，手指動作）重新設計。

**2. 相較於既有 VPT 方法**

| 方法 | 時間上下文 | 監督方式 | Offset | Velocity | 備註 |
|---|---|---|---|---|---|
| S2S | 5 幀（0.2 s） | 中心幀 | 有限 | 無 | 首次端到端學習 |
| Video2RollNet | 5 幀（0.2 s） | 中心幀 | 有限 | 無 | 用於音訊生成前端 |
| PPAN | 6 幀（0.2 s） | 中心幀 | 45.9% F1 | 無 | Vision Transformer 前端 |
| V2N | 約 1 秒 | 逐幀監督 | 顯著提升 | 首次報告 | 完整四任務輸出 |

V2N 相對於這些方法的主要進展包括：

- 從「視窗中心幀分類」升級為「逐幀時序迴歸」。
- 從單一 onset/pressed-key 預測擴展為 onset + offset + key hold + velocity 的完整音符表示。
- 使用 Conformer ConvModule 作為 shared temporal backbone，兼顧長程建模與計算效率。

**3. 限制與未解決的挑戰**

儘管 V2N 在 PianoVAM 與 R3 上達到 state-of-the-art，仍存在以下限制：

- **固定幾何預處理**：模型依賴裁剪後的鍵盤影像與 slope prior，無法直接處理任意拍攝角度或不同鍵盤佈局。
- **無音訊融合**：雖然視覺在踏板場景下更準確，但音訊在判斷 pitch 與細微力度上仍有優勢；V2N 未探索 audio-visual fusion（音視覺融合）。
- **未建模踏板事件**：V2N 預測 physical key release，但沒有額外輸出 sustain pedal 狀態，對於需要完整演奏表情的應用仍不足。
- **灰階輸入**：僅使用 grayscale frame，可能忽略了顏色與光影變化對手指與琴鍵狀態的提示。
- **資料集規模**：PianoVAM 與 R3 相對音訊領域的 MAESTRO 資料集規模較小，限制了更大模型的訓練潛力。

**1. 開源資源**

實驗使用兩個 VPT 資料集：

- **PianoVAM**：視覺鋼琴轉譜資料集，用於評估 onset、offset、velocity 等任務。
- **R3**：rehearsal dataset，先前 PPAN 等研究也使用。

雖然文中未詳細說明資料集的下載與授權方式，但這兩個資料集在 VPT 社群中已被廣泛使用，通常可透過論文作者或官方網站取得。

**3. 訓練細節透明度**

提供的上下文未包含完整的超參數（如 batch size、optimizer、learning rate、訓練 epoch 數、資料增強策略等），但由於原始碼已公開，這些細節可從程式碼中還原。對於重現性而言，開源程式碼與檢查點的組合已達到相當高的水準。

**4. 評估協定**

V2N 的評估應採用與音訊轉譜類似的標準：通常以 50 ms evaluation tolerance（評估容差）計算 onset、offset、note 等事件的 F1 score。由於 V2N 預測的是 physical key release，在與 audio-based methods 比較時必須注意 ground truth 的定義差異，否則會造成不公平比較。作者已意識到這一點，並在任務定義中明確區分 physical key release 與 pedal-extended offset（延音踏板延伸的收音）。

#### 未來研究方向

**1. 幾何自適應預處理**

跨資料集遷移實驗顯示，fixed-geometry preprocessing 是主要瓶頸。未來可發展：

- 鍵盤關鍵點偵測（keypoint detection）或語意分割，自動對齊 88 鍵。
- 透視校正與相機姿態估計，支援非正視角拍攝。
- 可學習的鍵位對應模組，讓模型適應不同尺寸的數位鋼琴或平台鋼琴。

**2. 音視覺融合**

V2N 目前純粹依靠視覺。未來可在保留 physical key release 優勢的同時，加入音訊分支：

- 在音訊清晰時利用 spectral transients（頻譜瞬態）輔助 onset。
- 在視覺遮蔽或快速音群時利用音訊補強。
- 設計 cross-attention 或 late fusion 機制，讓兩種模態互補。

**3. 踏板與表情建模**

完整的鋼琴演奏不僅是 NoteOn/NoteOff/Velocity，還包括：

- sustain pedal、soft pedal、sostenuto pedal 的狀態預測。
- 觸鍵深度、離鍵速度等更細緻的演奏參數。
- 把 key hold 擴展為連續按壓深度，進而估計 aftertouch 等進階 MIDI 控制器。

**4. 更大規模資料集與預訓練**

VPT 資料集規模遠小於音訊領域。未來可：

- 收集更多樂曲、演奏者、拍攝角度的影片。
- 利用 self-supervised learning（自監督學習）在大量無標註鋼琴影片上預訓練視覺特徵抽取器。
- 引入 audio-visual correspondence（音視覺對應）作為預訓練任務，減少對昂貴 MIDI 標註的依賴。

**5. 事件級解碼與即時應用**

V2N 目前使用幀級峰值偵測。未來可借鏡音訊領域的 neural semi-CRF event-based decoding，直接輸出事件序列，減少後處理依賴。此外，目前模型以約 1 秒上下文運作，若要部署為 real-time transcription（即時轉譜）系統，需開發因果（causal）版本與串流解碼策略。

**6. 多樂器與更廣泛的音樂場景**

VPT 目前聚焦單一鋼琴鍵盤。未來可擴展到：

- 多手、多演奏者的鍵盤場景。
- 管風琴、大鍵琴等具有不同機械結構的鍵盤樂器。
- 結合手部姿態估計（hand pose estimation）以區分左右手與指法，產生更具可讀性的樂譜。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**
A：這篇論文聚焦於視覺鋼琴轉譜（Visual Piano Transcription, VPT）中長期被忽略的完整音符屬性預測問題。傳統基於音訊的鋼琴轉譜雖然在起音（onset）、音高（pitch）與力度（velocity）上表現成熟，但延音踏板（sustain pedal）會讓聲音在琴鍵放開後持續，導致音訊系統只能預測「踏板延伸的收音」而非實際琴鍵釋放。現有 VPT 方法又多只處理極短影片視窗、僅監督視窗中心幀，造成收音（offset）準確率遠低於起音，也幾乎不報告音符層級的力度，因此本文提出 V2N 來填補這些缺口。

**Q2：為什麼現有的視覺鋼琴轉譜方法在收音與力度上表現不佳？**
A：現有方法如 S2S、Video2RollNet 與 PPAN 大多只處理約 0.2 秒的短影片視窗，並且只在每個視窗的中心幀進行監督，這使得模型難以觀察琴鍵從按下到放開的完整時序過程。收音預測需要看到琴鍵實際回到靜止狀態的連續變化，而力度預測則需要從手指下壓的細微視覺線索中估計觸鍵力道，這些都無法僅靠單一中心幀或短上下文充分學習。此外，過去方法多採用單任務設計，沒有利用起音、收音、按鍵持續與力度之間的互補關係，因此整體表現受限。

**Q3：為什麼預測「實際琴鍵放開」比預測「聲音結束」更重要？**
A：MIDI 中的 NoteOff 事件對應的是琴鍵的實體釋放，也就是演奏者手指離開琴鍵的時刻，但音訊系統常把收音延伸到延音踏板放開為止，兩者可能相差數秒。對於樂譜生成、演奏分析或機器人模仿學習等應用來說，真實的按鍵狀態比聲音持續與否更具語意意義。影片可以直接觀察琴鍵的物理狀態，因此視覺轉譜有潛力提供比音訊更精確、更符合 MIDI 標準的音符結束時間。

**Q4：V2N 的核心方法架構是什麼？**
A：V2N 採用「共享時間骨幹網路＋多任務預測頭」的設計，首先以視覺特徵抽取器將每個影片幀轉成特徵向量，再經由共享的時序骨幹學習跨幀關係，最後分接到四個任務專屬頭部分別預測起音、收音、按鍵持續與力度。與過去只在視窗中心幀監督不同，V2N 對每一個時間幀都給予標註，進行逐幀監督。這種多任務多幀的聯合訓練讓模型能同時學習音符開始、結束、持續狀態與觸鍵強度。

**Q5：本文提出的關鍵創新有哪些？**
A：首先，V2N 是首個同時預測起音、收音、按鍵持續與音符層級力度的完整 VPT 系統，填補了過去方法缺少力度與準確收音的空白。其次，它引入多任務監督與逐幀監督，讓不同任務之間共享互補線索，例如按鍵持續區間能幫助定位收音，而起音資訊則能輔助力度估計。再者，模型使用更長的時序上下文，使遠距離的琴鍵狀態變化能被有效捕捉，進而提升所有任務的表現。

**Q6：為什麼選擇 Conformer ConvModule（不含 self-attention）與 BiLSTM 頭部作為主要設計？**
A：Conformer ConvModule 中的深度可分離 1D 卷積能夠有效率地建模局部時序依賴，並透過三層堆疊擴大感受野，同時省略 self-attention 可降低計算成本，對於高幀率影片序列更為實用。BiLSTM 任務頭則能針對每個任務進一步細化時序模式，例如收音頭需要辨識琴鍵回彈的連續變化，而力度頭需要根據按鍵前後幀估計觸鍵強度。這樣的組合在保持合理運算量的同時，兼顧了多任務預測所需的時序精細度。

**Q7：論文在哪些資料集上進行評估？**
A：實驗主要在視覺鋼琴轉譜常用的 PianoVAM 與 R3 兩個資料集上進行。PianoVAM 提供了鋼琴演奏的影片與對應 MIDI 標註，適合評估視覺方法的轉譯能力；R3 則是另一個包含排練場景的視覺鋼琴資料集，能測試模型在較真實環境下的表現。這兩個資料集都讓研究者能直接比較起音、收音、按鍵持續與力度等多項指標。

**Q8：V2N 取得了哪些關鍵實驗結果？**
A：V2N 在 PianoVAM 與 R3 上都達到了新的最佳水準（state-of-the-art），並首次在 VPT 中報告了音符層級的力度預測結果。消融實驗顯示，多任務監督不僅讓收音與力度預測成為可能，還能進一步提升起音準確率；而引入更長的時序上下文後，各項指標又獲得額外改善。這證明了完整的多任務多幀設計對視覺鋼琴轉譜具有顯著的正面影響。

**Q9：消融研究揭示了哪些重要發現？**
A：消融研究指出，若只使用單一任務監督，模型難以同時學會收音與力度，因為這些任務需要從彼此共享的視覺線索中獲得約束。加入多任務監督後，起音、收音、按鍵持續與力度之間形成互補，例如按鍵持續區間能抑制錯誤的收音預測，而起音位置則能引導力度頭關注正確的按鍵時刻。此外，延長時序上下文讓模型能看到按鍵按下後的完整動態過程，對於判斷收音與重複音尤其有幫助。

**Q10：這項技術適合哪些實際應用場景？**
A：V2N 特別適合音訊品質不佳或完全缺失的場合，例如嘈雜環境、高度混響空間、多樂器同時演奏，或影片音軌損壞的情況。由於它直接觀察琴鍵狀態，也能應用於靜音鍵盤、電子琴或演奏分析系統，無需依賴麥克風收音。此外，音樂教育平台可利用視覺轉譜自動評估學生的指法與觸鍵時機，檔案數位化專案也能從歷史鋼琴影片中還原可演奏的 MIDI。

**Q11：若要將 V2N 產品化，需要考慮哪些工程與使用者因素？**
A：首先，現有方法包含 V2N 在內都依賴固定幾何預處理，因此產品需要穩定的攝影機視角與鍵盤區域校正，或額外開發自動鍵盤偵測模組。其次，雖然 1 秒視窗的運算量與 PPAN 相當，但在即時應用中仍需考慮延遲、記憶體與邊緣裝置部署的平衡。最後，隱私與資料授權也是重要因素，因為視覺轉譜需要拍攝演奏者的手部與鍵盤，產品設計應清楚告知使用者並提供離線處理選項。

**Q12：這項研究對音樂資訊檢索領域可能帶來什麼影響？**
A：V2N 將音訊鋼琴轉譜中成熟的多任務典範成功移植到視覺領域，證明影片不僅是音訊的輔助，更能獨立提供精確的音符狀態資訊。這有助於推動多模態音樂理解，讓未來研究更積極探索音訊與視覺的互補融合。同時，它為視覺音樂轉譜設立了更完整的評估基準，包含音符層級力度，將促使後續研究在更嚴謹的任務定義上持續進步。

**Q13：作者承認了哪些主要限制？**
A：作者指出，無論是 V2N 或先前的 VPT 系統，在跨資料集遷移時都表現相似地不佳，顯示固定幾何預處理是共同瓶頸。這意味著模型對攝影機角度、鍵盤位置與影像解析度的變化相當敏感，限制了其在真實世界多樣場景中的泛化能力。此外，目前方法仍需要預先裁切好的鍵盤區域，尚未達到完全端到端的任意視角輸入。

**Q14：在哪些情況下 V2N 可能會失敗？**
A：當琴鍵被手指、樂譜或其他物體遮擋時，模型可能無法正確判斷按鍵狀態；極端光照變化或陰影也可能讓按鍵按下與放開的視覺差異變得不明顯。快速連續音或顫音會造成嚴重的動態模糊，使起音與收音的時刻難以精確定位。此外，若攝影機角度與訓練資料差異過大，固定幾何預處理失效，整體預測品質也會顯著下降。

**Q15：未來可以朝哪些方向繼續發展？**
A：未來可以發展視角不變的預處理或端到端鍵盤偵測，讓模型能適應任意拍攝角度與不同鋼琴外觀。另一方面，將 V2N 擴展為線上串流架構，並結合音訊進行多模態融合，有望進一步提升穩健性與準確率。此外，建立更大規模、更多樣化的視覺鋼琴資料集，並把方法推廣到其他鍵盤樂器或打擊樂器，也是值得探索的方向。

## 實務應用指南

### 適用場景

1. **鋼琴教學與練習回饋系統**  
   將單一攝影機對準鍵盤，V2N 可自動產生學生彈奏的 MIDI，比對參考樂譜以標示錯音、節拍偏差與力度不足，特別適合無法收音或環境吵雜的琴房。

2. **音樂會與比賽影片的後製轉譜**  
   從已錄製的鋼琴演奏影片直接輸出符號化樂譜，用於生成字幕、視覺化琴鍵動畫，或作為版權監測與內容檢索的結構化後設資料。

3. **延音踏板使用分析與演奏研究**  
   由於 V2N 預測的是「實際琴鍵放開」而非「聲音結束」，可用於量化演奏者手指離鍵時機、踏板銜接習慣，協助音樂學或自動演奏（player piano）研究。

4. **音訊受損或缺失場合的備援轉譜**  
   當現場錄音品質差、麥克風故障，或影片來自多樂器合奏而音訊難以分離時，僅靠影像即可取得可靠的音符起始、結束與力度資訊。

5. **互動式鋼琴遊戲與 AR 視覺效果**  
   在即時或近即時的鍵盤影像串流上跑 V2N，驅動落球遊戲、光效或虛擬樂器，讓使用者無須 MIDI 線即可體驗互動。

### 實作前置條件

- **資料準備**
  - 固定視角的鍵盤影片，建議至少 25 fps，琴鍵區域清晰、對比足夠。
  - 若需微調，準備少量帶有 MIDI 對齊標註的影片（含 Note On、Note Off、Velocity），格式可參考 PianoVAM / R3。
  - 預處理需將鍵盤做幾何校正（透視校正、裁切為固定 88 鍵區域），因論文指出固定幾何預處理是跨資料集遷移的主要瓶頸。

- **運算資源**
  - 訓練：建議具備 16 GB 以上 VRAM 的 GPU（如 NVIDIA V100 / A100 / RTX 4090），搭配 PyTorch。
  - 推論：現代中高階 GPU 可達近即時；CPU 推論可行但幀率會受限。
  - 儲存：原始影片、抽取幀與 MIDI 標註需預留數百 GB 空間。

- **技術能力**
  - 熟悉深度學習訓練流程（PyTorch、資料載入、損失函數調整）。
  - 具備電腦視覺基礎，能處理影像校正、ROI 裁切與幀級標註。
  - 了解 MIDI 規範與音樂資訊檢索（MIR）評估指標（如 onset/offset F1）。

### 實作步驟建議

1. **環境建置與模型取得**  
   從論文提供的 GitHub 下載程式碼與預訓練檢查點，安裝相依套件，確認能跑通 PianoVAM / R3 的推論範例。

2. **鍵盤幾何校正與前處理**  
   針對自有攝影機視角，建立固定前處理流程：偵測鍵盤四邊、做透視變換、裁切為灰階 88 鍵輸入。此步驟對跨場景穩定性影響最大。

3. **領域適應（選用）**  
   若畫面風格、解析度或攝影機角度與訓練資料差異大，使用自有標註資料進行微調。建議凍結視覺特徵抽取層、先微調共享時間骨幹與任務預測頭，以避免過擬合。

4. **多任務聯合訓練或微調**  
   同時監督起音、收音、琴鍵按住狀態與力度，採用逐幀監督。若資料標註不完整，可優先保留起音與琴鍵按住任務，再逐步加入收音與力度。

5. **推論與後處理**  
   對輸入影片逐幀預測四種輸出，使用峰值偵測產生 Note On / Note Off，並將力度頭輸出裁剪至 [0,1] 後縮放為 0–127 MIDI Velocity。可額外加入簡單的時間平滑或最短音符長度限制。

6. **評估與上線**  
   以 50 ms 容差計算 onset/offset F1，並與音訊轉譜結果做差異分析（特別是延音踏板區間）。確認穩定後封裝為 API 或邊緣裝置推論服務。

### 潛在風險與注意事項

- **固定幾何預處理的泛化限制**  
  論文發現 V2N 與既有 VPT 系統在跨資料集遷移時表現相近地下降。若部署場景的攝影機角度、光照或鍵盤外觀不同，必須重新校正或收集微調資料，不能直接使用預訓練權重。

- **快速連音與遮擋**  
  手指或琴譜遮擋、快速琶音可能使個別琴鍵狀態難以辨識。建議確保攝影機位於鍵盤正上方或斜前方，並維持足夠幀率（≥25 fps）。

- **力度預測的絕對準確度**  
  V2N 雖首次報告音符層級力度，但視覺力度本質上比音訊困難（需從按鍵速度推估）。對於需要精確動態標記的應用，建議與音訊力度估計融合使用。

- **延音踏板與收音語義差異**  
  若下游系統預期的是「聲音結束」（傳統音訊轉譯），V2N 的物理琴鍵放開會明顯提前。必須在產品文件中清楚區分「key release」與「end of sound」，或額外加入踏板偵測模組。

- **計算與延遲權衡**  
  雖然 1 秒時間上下文在 FLOPs 上較高，但論文指出 wall-clock 與短視窗方法相近。若需極低延遲互動，仍建議做實際端到端延遲測試。

### 與其他技術的整合建議

- **與音訊轉譜系統互補**  
  在音質良好時，以音訊系統（如 Onsets and Frames 或 neural semi-CRF）為主；當音訊受損或存在延音踏板歧義時，切換或融合 V2N 的視覺結果。可設計簡單規則：音訊起音置信度高時採用音訊，否則採用視覺起音。

- **與光學音樂辨識（OMR）結合**  
  將 V2N 輸出的 MIDI 與樂譜影像比對，可實現「看譜彈奏」自動評分；OMR 提供參考音高與節拍，V2N 提供實際演奏事件。

- **與踏板偵測或音訊活動度模型串接**  
  若產品需要傳統「聲音結束」時間，可在 V2N 琴鍵按住狀態基礎上，疊加延音踏板狀態估計，重建踏板延伸的收音區間。

- **部署為邊緣或雲端服務**  
  推論模組可封裝為 REST/gRPC API，或透過 ONNX/TensorRT 加速後部署於邊緣裝置。前處理（幾何校正）建議在客戶端完成，以減少傳輸頻寬。

### 給不同背景讀者的閱讀建議

- **初學者**  
  建議先從「為什麼要用影片轉譜」這個動機開始理解：延音踏板會讓聲音在放開琴鍵後繼續，所以音訊轉譜的「收音」不等於「手離開琴鍵」。接著把 V2N 想像成「看鍵盤影片寫 MIDI 的 AI」，四個任務分別對應「按下、放開、按住、多用力」。實作時最困難的通常不是模型，而是把鍵盤影像裁切對齊。

- **AI 工程師**  
  重點關注多任務聯合訓練與逐幀監督的設計：為何同時預測起音、收音、琴鍵按住狀態與力度能彼此互補，以及 Conformer ConvModule 去掉 self-attention 後的權衡。實作時請優先處理前處理管線的穩定性與跨資料集遷移問題，並預留微調流程。

- **研究人員**  
  本論文的核心貢獻在於將音訊轉譜的多任務典範移植到視覺領域，並明確區分 physical key release 與 pedal-extended offset。可進一步探索的方向包括：更長的時序上下文、自監督預訓練、可變形幾何前處理以突破跨資料集瓶頸，以及視覺與音訊在事件層級的深度融合。

- **產品經理**  
  本技術最適合「無法穩定收音」或「需要真實按鍵動作」的利基場景，例如琴房教學、演奏分析、版權監測。上線前需確認攝影機架設規範、前處理校正成本，以及下游系統對「琴鍵放開」與「聲音結束」兩種語義的期待。建議以 MVP 驗證特定場景的端到端準確度後，再擴展至多機型與多環境部署。
