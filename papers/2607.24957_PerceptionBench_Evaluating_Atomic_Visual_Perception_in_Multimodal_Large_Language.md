## ⚡ TL;DR

現有基準常將視覺感知與推理、知識混為一談，難以精準評估原子級感知能力。
PerceptionBench 從 42 個基準失敗歸納十項原子感知能力，並建構三千道單一能力驗證題。
十六個前沿模型無一超越 60% 準確率，感知幻覺最弱，且相近總分掩蓋能力分布差異。

## 摘要翻譯

我們提出 PerceptionBench，一個專為評估多模態大型語言模型（MLLMs）原子級視覺感知能力（atomic visual perception）而設計的基準。現有基準往往無法將感知獨立出來：整體評估（holistic evaluations）會把感知錯誤（perceptual errors）與推理（reasoning）或領域知識（domain knowledge）的失誤混為一談；而應用導向基準（application-driven benchmarks）僅涵蓋由啟發式設計（heuristic designs）所形塑的狹窄且片段化領域。為克服這些限制，PerceptionBench 採用自下而上方法（bottom-up approach）：我們診斷前沿多模態大型語言模型（frontier MLLMs）在 42 個現有基準回應中最早出現的失敗點（failure points），據此建立錯誤分類法（error taxonomy），其感知分支（perception branch）定義了十項原子感知能力（atomic perceptual capabilities）。在該分類法的指導下，我們建構了 3,000 道驗證問題（verified questions），並要求簡短明確答案（short, unambiguous answers）；每道題目均隔離單一能力，且難度來自感知而非推理或知識。針對十六個前沿多模態大型語言模型的基準結果顯示，原子級視覺感知在很大程度上仍未解決——沒有任何模型達到 60% 準確率（accuracy），平均而言感知相關幻覺（perception-related hallucination）是最弱的能力，而相似的整體分數掩蓋了截然不同的能力分布（capability profiles）。因此，PerceptionBench 提供了一個能力層級標準（capability-level standard），用於衡量與診斷多模態大型語言模型的視覺感知邊界（visual perception boundaries）。

### 核心貢獻（3～5點）
- 提出 PerceptionBench，一個專門針對原子級視覺感知能力設計的評估基準，能將感知錯誤與推理、領域知識失誤區隔開來。
- 透過診斷前沿 MLLM 在 42 個現有基準中最早出現的失敗點，建立錯誤分類法，並在感知分支下定義十項原子感知能力。
- 建構 3,000 道驗證問題，每題隔離單一原子感知能力，難度源自感知本身而非推理或知識。
- 對十六個前沿 MLLM 進行評估，發現原子級視覺感知仍未解決，且相似整體分數背後存在差異顯著的能力分布。
- 提供能力層級標準，作為衡量與診斷 MLLM 視覺感知邊界的工具。

### 適合對象
本論文適合多模態人工智慧、電腦視覺與大型語言模型領域的研究者與工程師，特別是關注 MLLM 感知能力診斷、基準設計與模型能力剖析的讀者；對於希望了解前沿模型在細粒度視覺感知任務上瓶頸的從業人員與學生亦具參考價值。

## 深度分析

#### 方法論解析

PerceptionBench 的核心方法論可概括為「自下而上（bottom-up）」的錯誤歸因與能力解構，而非傳統基準常見的「自上而下（top-down）」領域切分。具體而言，作者群首先針對 42 個現有開源基準（open-source benchmarks），對前沿多模態大型語言模型（frontier MLLMs）的錯誤回應進行逐題追溯，將每個失敗點（failure point）歸因到其最早出錯的認知步驟。透過對這些錯誤標籤進行聚類，研究團隊歸納出一套錯誤分類法（error taxonomy），其中感知分支（perception branch）定義了十項原子感知能力（atomic perceptual capabilities）。這十項能力涵蓋 Localization（定位）、Attribute recognition（屬性辨識）、Counting（計數）、Relation（關係）、Depth & 3D（深度與三維）、OCR（光學字元辨識）、Comparison（比較）、Fine-grained recognition（細粒度辨識）、Integration（整合）以及 Perception-related hallucination（感知相關幻覺）。

相較於由設計者直覺決定類別的應用導向基準（application-driven benchmarks），PerceptionBench 的能力分類直接來自模型實際失敗的經驗分布，因此更能反映「模型真正缺乏什麼」。在題目建構階段，研究團隊採取兩條路徑：一部分題目是將既有基準中被歸因為感知錯誤（perceptual errors）的樣例，拆解為只測試單一原子能力的子問題；另一部分則是依據分類法全新撰寫。所有 3,000 道題目都經過驗證（verified questions），確保答案簡短明確（short, unambiguous answers），且困難度來自視覺感知（visual perception）本身，而非推理（reasoning）、數學運算或領域知識（domain knowledge）。這種「難度平衡（difficulty-balancing）」的設計，使得最終分數能較純粹地反映模型的視覺感知邊界（visual perception boundaries）。

從方法論層次看，PerceptionBench 的貢獻在於把「感知」從「感知＋推理＋知識」的混雜體中隔離出來。傳統整體評估（holistic evaluations）如 MMMU 或 MathVista 雖然能衡量最終答案正確性，但無法判斷錯誤是源自於沒看懂圖、還是看懂圖但推理錯誤。PerceptionBench 透過原子化與驗證機制，讓每道題目只對應單一能力，從而實現能力層級標準（capability-level standard）的診斷。

#### 實驗數據解讀

研究團隊評估了十六個前沿 MLLM，包括 GPT-5.6-Sol、Kimi-K3、Claude-Fable-5、Gemini-3.1-Pro、GPT-5.5、Seed-2.1、Gemini-3.5-Flash、Qwen3、Qwen-Plus、Claude-Opus-4.8、Kimi-K2.6、Grok-4.5、Gemma-4-31B、GLM-5V-Turbo、Minimax-M3 與 GLM-4.6V。整體準確率（accuracy）顯示，目前沒有任何模型突破 60% 門檻：GPT-5.6-Sol 以 59.7% 暫居第一，Kimi-K3 以 58.5% 緊追在後，其餘模型則明顯落在 40%–55% 區間。這項結果強調原子級視覺感知（atomic visual perception）仍是未解決的難題。

更值得關注的是細粒度能力分布（capability profiles）。研究發現，感知相關幻覺（perception-related hallucination）是平均表現最弱的能力，顯示即使是最先進的模型，仍然會在沒有對應視覺證據的情況下虛構內容。此外，整體分數相近的模型，其能力分布（capability profiles）可能截然不同：例如兩個模型總準確率相差不到 1%，但一個可能在 OCR 與 Counting 表現突出，另一個則在 Localization 與 Depth & 3D 較強。這意味著單一總分會掩蓋模型在個別原子能力上的顯著差異，也說明為何需要 PerceptionBench 這類細粒度診斷工具。

另一項重要發現是感知的樣本級不穩定性：即使聚合分數（aggregate scores）穩定，仍有相當比例的題目在多次執行中無法穩定答對。這暗示 MLLM 的視覺內容（visual content）提取並非決定性過程，而是帶有隨機性，對於需要高可靠性的下游應用（如機器人環境互動、醫療影像判讀）而言，這是不可忽視的風險。

從圖 3 的失敗類型覆蓋率也可看出，現有 42 個基準的失敗高度集中於一兩種錯誤類型，彼此覆蓋的感知能力片段狹窄且重疊有限；相對地，PerceptionBench 的十項感知能力橫跨多個基準反覆出現，顯示過去評估工具對感知能力的探測既不完整也不系統化。

#### 與現有研究的比較

相較於 MMMU、MathVista 等整體評估（holistic evaluations），PerceptionBench 的差異在於「隔離」而非「綜合」。MMMU 與 MathVista 評量的是最終答案，其表現同時取決於視覺感知、邏輯推理、數學能力與領域知識；因此無論答案正確與否，都無法乾淨地歸因到感知。PerceptionBench 則透過簡短明確答案與單一能力設計，把感知錯誤從推理錯誤中區分出來。

另一方面，OCRBench、ScreenSpot 等應用導向基準（application-driven benchmarks）雖然更直接測量感知，但它們屬於「自上而下」的啟發式設計（heuristic designs）：類別由設計者根據特定應用領域預先決定，只能測量感知的某一切片，且覆蓋範圍受限於設計者先驗。PerceptionBench 則從模型實際失敗出發，確保每項原子感知能力都對應到真實的模型弱點，從而提供更全面的能力層級標準。

然而，PerceptionBench 也有其定位限制。首先，它聚焦於靜態影像的原子感知，尚未涵蓋動態視訊、時序感知或跨幀追蹤。其次，為了隔離感知，題目被設計為簡短答案，這雖然有利於自動評分，但也可能簡化了真實世界中需要連貫描述或長篇推理的感知任務。此外，基準主要針對英文語境與主流西方視覺文化素材，對於多語言文字閱讀（multilingual OCR）或不同文化脈絡的視覺符號，覆蓋可能不足。最後，由於 frontier MLLMs 更新迅速，當前領先模型（如 GPT-5.6-Sol、Kimi-K3）的表現可能在數月內被新版本超越，因此分類法與題庫需要持續更新以維持診斷效力。

#### 可重現性評估

PerceptionBench 在可重現性（reproducibility）方面表現良好。作者群已公開部落格（blog）說明基準設計理念，並在 GitHub 釋出程式碼與資料（code and data：https://github.com/MoonshotAI/PerceptionBench）。這使得其他研究者可以取得完整題目、評分腳本與實驗流程，進行獨立驗證或擴充。論文本身也上傳至 arXiv，便於學術社群追蹤與引用。

不過，可重現性仍受到模型存取方式的限制。評估對象多為商業 API 模型（如 GPT-5.6-Sol、Gemini-3.1-Pro、Claude-Opus-4.8），其權重（model weights）並未公開，且 API 行為可能隨時間更新（包括系統提示、溫度參數與後處理）。這意味著即使使用相同題目，不同時間點呼叫同一模型名稱，也可能得到不同結果。開源權重的模型如 Gemma-4-31B 雖可本地重現，但硬體需求與推論設定（如解析度、採樣策略）仍會影響最終分數。因此，未來若能在論文中更詳細記載 API 版本、溫度（temperature）、最大輸出長度、圖片解析度與提示模板（prompt template），將進一步提升跨研究比較的可信度。

#### 未來研究方向

PerceptionBench 的出現為 MLLM 感知研究開啟了多條後續路徑。第一，可將原子感知能力擴展至動態視訊與多幀情境，建立 VideoPerceptionBench 或 StreamingPerceptionBench，評估模型在時序變化、動作辨識與事件偵測中的原子感知表現。第二，可結合具身智能（embodied AI）與環境互動（environmental interaction），設計需要主動感知（active perception）的基準，例如機器人根據視覺回饋調整視角後再作答，以測量感知與行動的閉環能力。

第三，感知相關幻覺（perception-related hallucination）既然是最弱環節，未來研究可深入探討其成因：是視覺編碼器（vision encoder）的特徵遺失、還是語言模型（language model）的過度推論？可透過對照實驗，比較不同視覺編碼器、解析度與訓練資料對幻覺率的影響。第四，可發展針對單一原子能力的訓練與微調方法，例如專門強化 Counting、Depth & 3D 或 Fine-grained recognition 的資料增強與損失函數，並以 PerceptionBench 作為診斷工具驗證改善效果。

第五，可將 PerceptionBench 與推理基準結合，建立「感知—推理」聯合評估框架，分析當感知錯誤被修正後，下游推理表現能提升多少，從而量化感知作為基礎先決條件（foundational prerequisite）的槓桿效應。第六，可推動多語言與跨文化擴充，特別是中文、日文、阿拉伯文等複雜書寫系統的 OCR 與視覺語義理解，以檢驗模型感知能力的公平性與泛化性。

最後，隨著模型能力持續演進，PerceptionBench 的分類法與題庫也應定期更新，並引入自動化、可擴展的驗證流程，降低人工驗證成本，使這套能力層級標準能持續反映前沿 MLLMs 的視覺感知邊界。

## 論文問答

**Q1：PerceptionBench 主要想解決什麼問題？**
A：現有的多模態大型語言模型（MLLMs）評估基準通常把視覺感知與推理、領域知識混為一談，導致我們無法判斷錯誤究竟來自「看不準」還是「想不對」。另一方面，應用導向的基準（如 OCRBench、ScreenSpot）只覆蓋特定場景，難以系統性地描繪模型的感知邊界。PerceptionBench 因此提出一套專門評估「原子級視覺感知」的標準，把感知能力拆開來逐項檢驗，讓研究者能精準定位模型最早出錯的地方。

**Q2：為什麼整體式評估（holistic evaluations）無法準確衡量視覺感知？**
A：整體式評估通常要求模型回答多步驟問題，最終答案正確與否同時取決於感知、推理與外部知識，因此無法把錯誤乾淨地歸因到感知層面。舉例來說，一道數學圖表題答錯，可能是因為模型沒讀懂圖表文字，也可能是計算或公式用錯。PerceptionBench 透過設計簡短且答案明確的題目，確保難度來自視覺內容本身，而不是後續的推理或知識需求。

**Q3：原子級視覺感知對 MLLMs 為什麼如此重要？**
A：準確的視覺感知是下游推理與環境互動的基礎先決條件，如果模型一開始就看漏、看錯或產生幻覺，後續再強的推理也無法挽回錯誤的輸入。視覺感知並非單一整體能力，而是由屬性辨識、計數、定位、文字閱讀等原子能力組成。掌握這些原子感知能力因此被視為提升 MLLMs 的關鍵槓桿點，能直接決定模型在真實應用中的可靠性。

**Q4：PerceptionBench 的「自下而上方法」具體是怎麼做的？**
A：研究團隊先讓前沿 MLLMs 在 42 個現有開源基準上作答，再追蹤每個錯誤回應中最早出錯的步驟，並將這些錯誤標籤聚類成一套錯誤分類法。這套分類法的感知分支進一步定義出十項原子感知能力，因此每項能力都來自真實觀察到的模型弱點，而非研究者憑空設計的類別。這種做法確保 PerceptionBench 測量的正是模型真正缺乏、且會影響下游任務的感知能力。

**Q5：PerceptionBench 定義的十項原子感知能力有哪些？**
A：根據錯誤分類法的感知分支，這十項能力包括視覺定位（localization）、視覺屬性辨識（attribute recognition）、視覺計數（counting）、視覺關係理解（relation）、深度與三維感知（depth & 3D）、光學字元辨識／文字閱讀（OCR / text reading）、視覺比較（comparison）、細粒度辨識（fine-grained recognition）、情境整合（context integration），以及感知相關幻覺（perception-related hallucination）。這些能力涵蓋了從「在哪裡」、「是什麼」、「有幾個」到「是否真實存在」等不同層面的感知挑戰。透過這樣的細粒度拆分，PerceptionBench 能描繪出每個模型獨特的能力分布。

**Q6：PerceptionBench 的題目是如何建構與驗證的？**
A：部分題目是從已歸因的失敗案例中拆解出來的原子子問題，並繼承原本的能力標籤；另一部分則是根據分類法全新撰寫，以補足特定能力的覆蓋度。所有 3,000 道題目都經過驗證，確保答案簡短明確、題目難度來自視覺感知而非推理或領域知識。這種設計讓評估結果能直接反映模型在單一原子感知能力上的表現，避免其他因素干擾。

**Q7：PerceptionBench 評估了哪些模型？最關鍵的整體結果是什麼？**
A：研究評估了十六個前沿多模態大型語言模型，包括 GPT-5.6-Sol、Kimi-K3、Claude-Fable-5、Gemini-3.1-Pro、Qwen3、Grok-4.5 等。結果顯示沒有任何模型整體準確率超過 60%，目前最高的是 GPT-5.6-Sol（59.7%）與 Kimi-K3（58.5%）。這說明原子級視覺感知仍然是一個尚未被解決的重大挑戰，即使是最先進的模型也離「掌握感知」有很大距離。

**Q8：PerceptionBench 的能力分布（capability profiles）揭示了什麼？**
A：整體分數相近的模型，在不同原子能力上的表現可能差異很大，例如某個模型擅長定位卻在計數上表現不佳，另一個模型則相反。平均而言，感知相關幻覺是所有模型最弱的能力，顯示模型經常「看到不存在的事物」或忽略關鍵細節。這也證明只看總體準確率會掩蓋重要的能力差異，必須細分到能力層級才能真正診斷模型。

**Q9：PerceptionBench 在穩定性方面還觀察到什麼現象？**
A：研究發現即使整體分數在多次測試中保持穩定，仍有相當比例的「正確答案」無法在重複執行時被穩定複現。這表示每個樣本層級的感知表現其實並不可靠，模型可能在某些題目上只是碰巧答對。這種不穩定性對需要高可靠性的實際應用來說是重要警訊，也凸顯原子感知不僅要「準」，還要「穩」。

**Q10：原子級視覺感知在哪些實際場景中特別重要？**
A：在自動駕駛、機器人操作、醫學影像判讀、使用者介面自動化與運動賽事分析等場景中，模型必須精確定位物件、計數、辨識文字或判斷空間關係。如果模型在這些原子能力上出錯，例如把行人位置判錯、把藥丸數量數錯，後續決策就可能造成嚴重後果。PerceptionBench 提供的細粒度診斷，能幫助開發者針對特定應用選擇或改進最適合的模型。

**Q11：在產品開發層面，PerceptionBench 帶來哪些考量？**
A：產品團隊不應只依賴整體排行榜分數來選型，而應根據產品場景所需的原子能力（例如 UI 自動化需要 OCR 與定位，電商搜尋需要細粒度辨識）來檢視模型的能力分布。同時，PerceptionBench 能清楚標示出模型的主要失效模式，有助於在設計安全機制或人工覆核流程時優先處理高風險能力。這也能指導資料收集與微調方向，讓研發資源投入到真正薄弱的感知環節。

**Q12：PerceptionBench 對整個 MLLM 研究領域可能產生什麼影響？**
A：它為視覺感知評估提供了一個能力層級的標準，讓不同模型能在相同、細緻的維度上被比較與診斷。這將促使未來研究更關注感知模組本身的改進，例如更好的視覺編碼器、注意力機制或訓練資料。長遠來看，PerceptionBench 也有助於區分「感知問題」與「推理問題」，推動更精準的基準設計與模型發展。

**Q13：PerceptionBench 有哪些已知的限制？**
A：目前資料集僅包含 3,000 道驗證問題，雖然已涵蓋十項原子能力，但仍無法窮盡所有視覺概念與真實世界場景。此外，題目採用簡短答案形式，雖然便於評分，卻可能無法完全捕捉開放式生成任務中的感知挑戰。未來也需要更多樣化的影像來源與難度分布，以確保基準能持續反映前沿模型的感知邊界。

**Q14：PerceptionBench 觀察到哪些典型的失敗案例？**
A：感知相關幻覺是最普遍的弱點，模型經常聲稱圖片中有不存在的物件，或錯誤描述細節。深度與三維感知、細粒度辨識以及計數也是多數模型表現較差的能力，顯示空間理解與精確數量估計仍是難題。此外，重複測試中答案不一致的現象也說明，許多「正確」回應並非來自穩定的感知能力，而是帶有隨機性的猜測。

**Q15：未來可以朝哪些方向延伸 PerceptionBench？**
A：未來可以擴充錯誤分類法與題目數量，並加入動態、對抗式或互動式測試來提高難度與真實性。也可以針對感知模組設計專屬的訓練目標，把 PerceptionBench 納入模型開發與微調的迴圈中。更進一步，還可以將這套方法延伸到影片、三維場景與多幀感知，讓原子級感知評估涵蓋更豐富的多模態應用。

## 實務應用指南

## 適用場景

1. **多模態產品上線前的感知體檢**：在視覺問答、AI 導購、圖文檢索等應用上線前，使用 PerceptionBench 診斷模型在屬性辨識、計數、定位、OCR 等原子感知能力上的短板，避免把感知錯誤帶入下游推理。
2. **模型選型與採購決策**：比較 GPT-5.6-Sol、Kimi-K3、Claude-Opus-4.8、Gemini-3.1-Pro 等前沿多模態大型語言模型的能力分布，避免僅憑整體準確率選擇模型。
3. **模型迭代與微調方向設定**：根據錯誤分類法定位最早失敗點，針對感知相關幻覺、細粒度辨識、深度與三維等弱項收集資料並進行微調或提示工程。
4. **高風險場景的風險評估**：在醫療影像輔助、自動駕駛視覺、工業檢測等領域，評估模型關鍵感知能力的穩定性與可重現性，作為人機協作與人工覆核的依據。
5. **學術與開源社群的標準化評測**：作為能力層級標準，補充 MMMU、MathVista 等整體評估，提供可重複、可診斷的視覺感知邊界測量。

## 實作前置條件

- **資料**：需取得 PerceptionBench 的 3,000 道驗證問題與對應圖像（可從論文提供的 GitHub 取得），以及欲評估模型的 API 權限或開源權重。若要擴充到特定領域，需額外準備目標場景的圖像與簡短明確答案標註。
- **運算資源**：若僅透過 API 評測前沿模型，主要需要穩定網路與足夠預算；若本地部署開源模型（如 Gemma-4-31B、GLM 系列），建議準備 1–4 張 A100 / H100 等級 GPU 與充足記憶體。錯誤歸因與統計分析可在一般 CPU 環境完成。
- **技能**：熟悉 Python、多模態模型推論流程、資料標註與品質驗證；具備基礎統計分析與視覺化能力；若需擴展錯誤分類法，應邀請領域專家協助確認題目難度確實來自感知，而非推理或領域知識。

## 實作步驟建議

1. **環境準備**：下載 PerceptionBench 程式碼與資料，安裝相依套件，設定模型 API 金鑰或本地推論環境。
2. **基線評測**：在十項原子感知能力上執行模型推論，記錄每題答案與整體準確率。
3. **錯誤歸因**：對錯誤與不穩定樣本進行人工或半自動歸因，標記最早失敗點屬於哪一項原子能力（例如定位、OCR、感知相關幻覺）。
4. **能力分布分析**：繪製雷達圖或長條圖，比較不同模型或版本在屬性辨識、計數、關係、深度與三維等維度的表現。
5. **弱項優先改善**：針對最低分的原子能力收集對應真實場景資料，進行微調、提示工程或結合專用感知模組。
6. **穩定性測試**：對關鍵樣本進行多次重複推論，評估 per-sample 感知的可重現性，並設定信心閾值或人工覆核機制。
7. **產品化監控**：將原子能力指標納入上線後的模型監控儀表板，持續追蹤新版本表現。

## 潛在風險與注意事項

- **整體準確率陷阱**：兩個模型總分可能相近，但能力分布卻大相逕庭，不能僅用單一分數做決策。
- **感知與推理混淆**：題目設計必須確保難度來自視覺感知，而非數學推理、常識或領域知識，否則診斷會失焦。
- **幻覺與不穩定性**：同一題多次推論結果可能不同，高風險應用應加入一致性檢查或人機協作。
- **資料偏誤**：PerceptionBench 源於 42 個現有基準的失敗樣本，可能偏重某些視覺領域；擴充時需加入目標領域資料。
- **過度擬合基準**：模型可能在 PerceptionBench 上表現良好，但在真實複雜場景仍失敗，建議搭配端到端任務評估。

## 與其他技術的整合建議

- **與整體評估基準搭配**：PerceptionBench 提供原子感知診斷，MMMU、MathVista 等整體基準驗證下游任務表現，兩者互補。
- **與專用感知模組結合**：對 OCR、定位、計數等弱項，可串接專用模型（如 OCR 引擎、物件偵測器）作為前置或後置校正。
- **與 RLHF / DPO 流程整合**：將錯誤分類法的標籤轉為獎勵信號或偏好對，針對感知相關幻覺進行對齊訓練。
- **與 MLOps 監控整合**：將十項能力的準確率與穩定性指標匯入監控系統，設定告警與自動回滾條件。
- **與 RAG / 知識庫區隔**：PerceptionBench 測的是「看到什麼」，不是「知道什麼」，應避免把知識不足誤判為感知不足。

## 給不同背景讀者的閱讀建議

- **初學者**：先理解「視覺感知不是單一整體能力」這個核心概念，再對照圖 2 看 PerceptionBench 如何把感知拆成十項原子能力；不必深究錯誤歸因的統計細節，重點放在為什麼整體準確率會隱藏模型弱點。
- **AI 工程師**：重點閱讀第 2 節的資料建構與第 3 節的評估結果，學習如何將錯誤分類法落地為自動化診斷流程，並參考論文附錄的提示與評分腳本。
- **研究人員**：深入分析錯誤分類法的歸納過程與感知分支的理論基礎，思考如何擴展到更多模態（影片、3D）或設計針對感知相關幻覺的訓練目標。
- **產品經理**：把圖 1 與能力分布當作選型與溝通工具，理解「沒有模型超過 60% 準確率」代表產品仍須保留人工覆核，並用十項能力指標向團隊與客戶說明模型邊界。
