## 摘要翻譯

我們提出 Wan-Streamer v0.3，以單一統整觀點重新詮釋我們的原生串流互動模型（native-streaming interaction model）：影片即為世界（world）加上事件流（event stream）。世界（world）是影片在其中展開的持續性上下文（persistent context），包含環境、場景、主體、環境聲學條件（ambient acoustic conditions）、語音特徵（voice characteristics），以及其他相對穩定的條件。事件流（event stream）則是該世界（world）中隨時間變化的所有內容，包含場景或環境變化（scene/environmental changes）、主體行為（subject behavior）、語音（speech）以及其他聲音。這衍生出一個通用預訓練任務（pretraining task）：在大規模真實影片上，給定一個世界（world）與持續傳入的使用者輸入（user input），預測世界（world）如何即時移動、變化並回應。由此獲得的能力可進一步特化至廣泛的即時下游任務。我們將其具現（instantiate）於即時全雙工音視訊互動（full-duplex audio-visual interaction），其中事件流（event stream）即為智能體（agent）的語言形式語音（language-form speech）與自由形式行為（free-form behavior）。就功能而言，模型的多模態理解（multimodal understanding）過程類似視覺-語言-動作（vision-language-action）的運作方式：它將多模態使用者輸入（multimodal user input）對應至語言形式語音（language-form speech）與行為動作（behavior actions）。Wan-Streamer v0.3 維持 v0.2 的運作點（operating point）：640×368 影片解析度（video resolution）、25 FPS 幀率（frame rate）、160 ms 串流單元（streaming unit）、約 200 ms 模型端回應延遲（model-side response latency），以及在 350 ms 雙向網路預算（bidirectional network budget）下約 550 ms 的總互動延遲（total interaction latency）。

### 核心貢獻（3～5點）
- 提出「世界（World）+ 事件流（Event Stream）」的統整性觀點，將影片重新形式化為持續性上下文（persistent context）與隨時間變化內容的組合。
- 設計通用預訓練任務（pretraining task）：給定世界（world）與持續傳入的使用者輸入（user input），預測世界如何即時移動、變化與回應。
- 在即時全雙工音視訊互動（full-duplex audio-visual interaction）中具現（instantiate）此框架，使智能體（agent）能同步生成語言形式語音（language-form speech）與行為動作（behavior actions）。
- 維持低延遲運作點（operating point）：模型端回應延遲（model-side response latency）約 200 ms，總互動延遲（total interaction latency）約 550 ms。

### 適合對象
從事多模態學習、即時互動系統、視覺-語言-動作（vision-language-action）模型、生成式影片模型，以及人機互動研究的學術研究者與工程師；特別適合關注端到端低延遲音視訊智能體（audio-visual agent）與原生串流互動模型（native-streaming interaction model）的讀者。

## 深度分析

#### 方法論解析

本研究的核心論點是將影片重新形式化為 **world（世界）** 加上 **event stream（事件流）**。在這個框架下，**world（世界）** 指影片中持續存在、相對穩定的 **persistent context（持續性上下文）**，包括場景環境、視覺風格、主體身份與外觀、**ambient acoustic conditions（環境聲學條件）**、**voice characteristics（語音特徵）** 等；而 **event stream（事件流）** 則是在該世界中隨時間變化的一切，例如場景變化、**subject behavior（主體行為）**、**camera motion（鏡頭運動）**、語音與其他聲音。這種分解把「影片」從單純的像素序列提升為「在特定世界中展開的事件實現（realization）」，從而讓互動式生成成為同一物件的特例：只是事件流改為在線上（online）根據使用者輸入即時產生。

在此基礎上，作者提出一個通用的 **pretraining task（預訓練任務）**：給定一個 **world（世界）** 與持續進入的輸入，模型需逐個 **streaming unit（串流單元）** 預測世界如何移動、變化與回應。由於幾乎所有自然影片都可以視為「世界 + 事件流」的實例，這個目標具備高度可擴展性，並能讓模型習得關於場景如何合理演化的 **world knowledge（世界知識）**。這與傳統針對單一下游任務（如對話代理）進行端到端訓練不同，v0.3 先把能力提煉為通用預訓練，再透過改變世界上下文與驅動事件流的輸入來遷移到特定應用。

在下游任務的具體實例化上，v0.3 延續 v0.1/v0.2 的 **full-duplex audio-visual interaction（全雙工音視訊互動）**，但擴展了代理能表達的內容。此處的 **world（世界）** 設定了場景、角色、環境音與聲音；**event stream（事件流）** 則是代理對使用者串流文字、音訊與影片輸入的回應。關鍵改變在於代理的事件流現在除了語音外，還包含 **free-form behavior（自由形式行為）**。作者採用角色扮演對話格式，在語言流中交錯出現口說文字與括號內的行為指令，例如：

> “(frowning slightly) What did you say?”  
> “(picks up the mug and glances toward the window) Sure, one moment.”

這種設計讓 **behavior actions（行為動作）** 不再受限於固定動作詞表（例如 v0.2 漫遊任務中的 w/a/s/d），而是可以根據世界上下文進行開放詞彙（open-vocabulary）的動作生成。

從模型功能來看，其 **multimodal understanding（多模態理解）** 過程呈現 **vision-language-action（視覺-語言-動作）** 的特徵：模型將多模態使用者輸入映射為 **language-form speech（語言形式語音）** 與行為動作，再由這些預測出的語言標記去條件化同步的音訊與影片生成。架構上仍使用單一 **Transformer**，所有模態共享一條 **causal timeline（因果時間軸）**，並以 block-causal attention（區塊因果注意力）協調輸入與輸出。**world context（世界上下文）** 在串流開始前只會被 tokenized 並 prefilled（預填充）一次，之後每個 160 ms 的串流單元逐步處理，因此不會在互動過程中反覆編碼世界資訊。

在運作點（operating point）上，v0.3 繼承 v0.2 的設定：**video resolution（影片解析度）** 640×368、**frame rate（幀率）** 25 FPS、**streaming unit（串流單元）** 160 ms、**model-side response latency（模型端回應延遲）** 約 200 ms，並在 **bidirectional network budget（雙向網路預算）** 350 ms 下達到約 550 ms 的 **total interaction latency（總互動延遲）**。由於行為指令是透過既有的語言流表達，並未引入新的延遲關鍵路徑，因此能在增加行為表達能力的同時維持低延遲。背後的 **latent generation（潛在特徵生成）** 與 **Ulysses-style context-parallel performer（Ulysses 風格上下文平行執行器）** 則繼承自 v0.2，用於支撐高解析度下的即時推論。

#### 實驗數據解讀

由於提供的全文僅包含引言與圖例，未見實驗章節與量化表格，因此本節主要根據文中可推論的實驗主張與資料格式進行分析，並指出有待原文補充之處。

最明確的實驗主張是「在新增自由形式行為輸出的情況下，仍保留 v0.2 的運作點」。這意味著模型在 640×368@25 FPS、160 ms 串流單元、約 200 ms 模型端延遲的條件下，仍能同時生成語音與自由形式行為。這一結果若經獨立驗證，將顯示括號行為指令並未顯著增加計算負擔，因為它們被整合進原有的語言標記流中，並由同一組 decoder 產生，再共同條件化音訊與影片生成。

圖一展示了通用預訓練資料的格式：每個樣本包含一段 **world（世界）** 描述（場景、聲音環境、角色外觀）以及時間對齊的 **event stream（事件流）** 標註。括號內為行為，引號內為語音。這種結構化標註是方法論能夠運作的關鍵，因為它強迫模型學習「哪些資訊屬於穩定世界、哪些屬於動態事件」。然而，這也暗示實驗成功與否高度依賴標註品質、時間對齊精度，以及世界描述是否足夠完整以支撐事件預測。

若論文包含量化實驗，合理的評估面向應包括：

- **視覺品質**：FVD（Fréchet Video Distance）、LPIPS、PSNR 等，衡量生成影片的真實度與連貫性。
- **音訊品質**：FAD（Fréchet Audio Distance）、MOS（Mean Opinion Score），評估語音與環境音的自然度。
- **語音可懂度**：WER（Word Error Rate），透過外部 ASR 檢驗生成語音是否清晰可辨。
- **行為-語言一致性**：檢查括號行為指令與口說內容、情境是否匹配，例如「(frowning slightly)」是否伴隨相應的視覺表情。
- **回應時機與全雙工行為**：測量模型在被打斷、重疊語音、靜音等待等情境下的反應，評估 **response timing（回應時機）** 與 **visible listening（可見傾聽）** 能力。
- **人類主觀評估**：針對互動自然度、代理存在感、整體滿意度進行使用者研究。

目前尚缺的資訊包括：與 v0.2 的直接對照實驗、有無 world-event 預訓練的消融研究、固定動作詞表與開放行為詞表的比較、訓練資料規模與多樣性、以及各項延遲指標的測量方法與標準差。這些都是判斷方法進步幅度的關鍵。

#### 與現有研究的比較

**與 Wan-Streamer 前版本的關係**  
v0.1 首次提出 **end-to-end formulation（端對端形式化）** 的 **native-streaming interaction model（原生串流互動模型）**，將使用者與代理的文字、音訊、影片放在同一條 **causal timeline（因果時間軸）** 上，由單一 Transformer 同時學習感知、回應時機、說話、可見傾聽與 **synchronized video（同步影片）**。v0.2 在不改變形式化的前提下，將互動串流從 192×336 提升至 640×368，並透過 **Ulysses-style context-parallel performer（Ulysses 風格上下文平行執行器）** 維持約 200 ms 的模型端延遲。v0.3 則進一步將訓練目標從「對話代理」抽象為「世界 + 事件流」的通用預訓練，並加入自由形式行為，但保留相同的運作點與服務拓撲。

**與級聯式系統的比較**  
傳統互動式數位人通常採用 **cascaded modules（級聯模組）**：ASR → 大型語言模型 → TTS → 臉部動畫或影片生成。這類管線的缺點包括錯誤傳播、各模組延遲堆疊、回應時機與視覺表情難以協調。Wan-Streamer 將這些能力統一為單一模型行為，能夠端到端地學習何時開口、何時傾聽、如何同步音視訊，這是其相較於級聯系統的最大優勢。

**與離線影片生成模型的比較**  
近年如 Sora、VideoPoet、CogVideo 等模型能從文字或圖片生成高品質影片，但它們通常是離線、非因果、非互動的：模型一次性產生完整片段，無法在生成過程中根據即時多模態輸入調整。Wan-Streamer 則強調因果、串流、低延遲的互動生成，並以 **world（世界）** 作為持續上下文，這使其更接近「可互動的影片模擬器」而非「影片生成器」。

**與互動式語音助理/數位人的比較**  
GPT-4o voice mode、Gemini Live 等系統已能進行低延遲全雙工語音對話，但大多缺乏與語音同步的可視化身體與行為；而 NVIDIA ACE、HeyGen 等方案雖有虛擬角色，但動作常由預設動畫庫或獨立動作模組驅動。Wan-Streamer v0.3 的差異在於：行為是透過語言流中的開放詞彙指令直接生成，並與語音、影片在單一模型中聯合建模。

**與世界模型/強化學習的關聯**  
在強化學習領域，world models（世界模型）如 Dreamer、World Models 等也試圖學習環境的潛在動力學以支援控制。Wan-Streamer 的「世界 + 事件流」與其精神相通，但定位不同：此處的 **world（世界）** 更偏向敘事與感知上下文，**event stream（事件流）** 則是生成性回應，而非用於規劃或控制的最佳化目標。

**限制**  
首先，方法高度依賴大規模且高品質的世界-事件結構化標註，這類資料取得與清洗成本高昂。其次，括號行為指令雖具開放性，但從文字描述映射到具體像素動作時可能存在歧義，例如「(frowning slightly)」的視覺詮釋可能因人而異。第三，目前針對即時全雙工音視訊互動的標準化評量基準仍不成熟，難以客觀比較不同系統。此外，長期互動中的世界一致性、物理合理性、以及安全與倫理問題（如未經同意模仿真人聲音與外貌）都是尚未充分討論的挑戰。

#### 可重現性評估

根據提供的文本，目前未見任何關於開源程式碼、資料集或模型權重釋出的資訊。Wan-Streamer v0.3 作為一個強調低延遲、高解析度、多模態端到端生成的系統，其重現門檻相當高，主要障礙包括：

- **資料**：需要大規模真實影片，並具備世界描述與時間對齊事件標註。文中雖展示圖一的資料格式，但未說明標註流程、資料來源、規模與品質控管方法。
- **模型與訓練**：單一 Transformer 同時處理文字、音訊、影片三種模態，需要龐大計算資源；Tokenizer、Encoder、Decoder 的具體設計、損失函數權重、訓練超參數等細節均未揭露。
- **低延遲推論基礎設施**：要達到約 200 ms 的 **model-side response latency（模型端回應延遲）**，必須實作 **Ulysses-style context-parallel performer（Ulysses 風格上下文平行執行器）** 與相應的服務拓撲，這些細節雖繼承自 v0.2，但 v0.2 的具體實作同樣未在本文中重述。
- **評估工具**：延遲測量、音視訊同步檢驗、全雙工打斷測試等都需要標準化腳本，目前文本未提供。

較正面的因素是：作者對 **world（世界）** 與 **event stream（事件流）** 的資料格式描述相對清楚，圖一提供了可參考的標註範例；同時 v0.3 的服務拓撲繼承自 v0.2，意味著若 v0.2 的實作細節未來公開，v0.3 的推論架構將較易復現。

為提升可重現性，建議作者至少釋出：推論程式碼與模型檢查點、小規模示範資料、延遲與品質評估腳本、以及訓練設定的關鍵超參數。即使無法公開完整訓練資料，釋出資料格式轉換工具與標註規範也能大幅降低社群復現難度。

#### 未來研究方向

**長期世界記憶與動態更新**  
目前的 **world（世界）** 在串流前預填充後似乎保持固定。未來可研究如何在長期互動中逐步更新世界上下文，例如記住使用者偏好、場景變化或角色狀態，並讓 **event stream（事件流）** 與動態世界保持一致。

**多智能體事件流**  
現有範例多為單一角色。擴展到多個 **agent（智能體/代理）** 或使用者與多個虛擬角色同時互動，將涉及更複雜的輪替、打斷、視線與空間關係建模。

**即時世界編輯**  
讓使用者在互動過程中改變世界設定（例如切換場景、更換角色服裝或聲音），並觀察 **event stream（事件流）** 如何自適應新上下文，是極具應用價值的方向。

**以人類回饋強化互動品質**  
可引入 RLHF（Reinforcement Learning from Human Feedback）或 DPO（Direct Preference Optimization），針對回應時機、禮貌性、情感適切性、行為自然度等互動品質指標進行微調，而不僅是優化下一個 token 的似然。

**規模化與資料多樣性**  
探索更大的模型、更長的訓練影片、更多樣的場景與文化背景，將有助於提升 **world knowledge（世界知識）** 的廣度與深度，並改善少見情境下的泛化能力。

**更嚴謹的評量基準**  
建立針對即時全雙工音視訊互動的標準化測試集與指標，涵蓋打斷處理、輪替、唇形同步、行為-語言一致性、長期視覺一致性等，將對整個領域的發展至關重要。

**物理與因果一致性**  
目前的行為指令雖開放，但不一定保證符合物理法則。未來可結合物理模擬或因果推理機制，確保例如「(picks up the mug)」會正確反映手部與物體的互動，而非僅是視覺上的近似。

**安全與倫理機制**  
隨著此類模型能即時生成與真人高度相似的音視訊內容，必須發展即時內容過濾、深度偽造（deepfake）防範、使用者同意機制與明確的數位身份標示，以降低濫用風險。

## 論文問答

**Q1：Wan-Streamer v0.3 想要解決的核心問題是什麼？它與 v0.1/v0.2 的主要差異在哪裡？**

A：Wan-Streamer v0.3 試圖把「即時全雙工音視訊互動」背後的通用能力抽取出來，而不是只針對單一代理任務進行端到端訓練。v0.1 與 v0.2 雖然已經建立了原生串流、單一 Transformer 的互動形式，但它們仍以「會說話、會反應的代理」作為直接訓練目標。v0.3 則進一步將影片重新框架為「世界 + 事件流」，透過大規模普通影片的通用預訓練來學習世界如何隨輸入演變，再將這個能力遷移到各種下游任務。

**Q2：為什麼傳統級聯模組方法難以勝任即時全雙工音視訊互動？**

A：傳統方法通常把感知、回應時機、語音合成、嘴型同步與影片生成拆成多個獨立模組，這會造成額外的串接延遲與同步誤差。每個模組只優化局部目標，難以學到「何時該傾聽、何時該打斷、如何同時用聲音與動作回應」這種整體行為。Wan-Streamer 採用單一 Transformer 把使用者與代理的文字、音訊、影片放在同一條因果時間軸上，讓感知、回應時機、說話與可見傾聽成為同一個端到端行為。

**Q3：「世界 + 事件流」的分解對於可擴展預訓練為什麼重要？**

A：這種分解把任何自然影片都轉換成同一個學習問題：給定持續性世界上下文，預測事件流如何隨時間展開。由於幾乎所有真實影片都可以視為某個世界中的事件流實現，因此預訓練目標非常廣泛且可擴展。模型能從中學到世界知識，例如場景如何合理演變、人物如何行動，這些知識再透過改變世界上下文與輸入驅動方式，遷移到不同的下游應用。

**Q4：請具體說明「世界」與「事件流」各自包含哪些內容，兩者如何構成一部影片？**

A：「世界」指的是影片中持續存在的背景，包括環境與場景、視覺風格、主體及其身分與外觀、環境聲學條件、語音特徵等相對穩定的條件。相對地，「事件流」則是世界中隨時間變化的所有內容，例如場景變化、主體行為、鏡頭運動、語音與其他聲音。一部被記錄下來的影片，就是某個給定世界中的一條事件流實現；而互動體驗則是同一個世界，只是事件流改為根據即時輸入線上產生。

**Q5：Wan-Streamer v0.3 提出的通用預訓練任務是什麼？**

A：通用預訓練任務是：給定一個世界與一個持續進來的輸入，模型要逐單元預測這個世界如何移動、變化與回應。這個目標讓模型學會即時串流前推的能力，而不只是靜態描述或離散動作分類。由於輸入與世界上下文可以根據下游任務調整，同一套串流回應邏輯就能被特化到不同的應用場景。

**Q6：相較於 v0.2，v0.3 在下游行為介面上的關鍵創新是什麼？**

A：v0.3 讓代理的事件流除了語音之外，還能表達自由形式行為。模型採用角色扮演對話格式，在語言狀態流中將說出的話與括號內的行為指令交錯，例如「（微微皺眉）你說什麼？」。這些行為指令可以是任何能用語言描述的動作，因此代理不再受限於固定的動作詞彙，而能根據世界上下文執行開放詞彙的行為。由於這個交錯的語言流直接承接原本 v0.2 的語音條件位置，所以並未引入新的延遲關鍵路徑。

**Q7：v0.3 保留了哪些運作點與延遲數據？為什麼能夠維持不變？**

A：v0.3 保留了與 v0.2 相同的運作點：640×368 解析度、25 FPS、160 毫秒串流單元、約 200 毫秒模型端回應延遲，以及在 350 毫秒雙向網路預算下約 550 毫秒的總互動延遲。這是因為建模契約與部署拓樸並未改變，昂貴的潛在特徵生成仍由 Ulysses 風格上下文平行執行器處理。即使新增了自由形式行為輸出，由於它透過語言流條件化音視訊生成，沒有增加額外的延遲瓶頸。

**Q8：模型架構如何以低延遲產生同步的音訊與影片？**

A：模型使用單一 Transformer，並透過區塊因果注意力讓語言、音訊與影片輸入輸出共享同一條因果時間軸。世界上下文在串流開始前只會被 token 化並預填一次，之後每個 160 毫秒的串流單元依因果順序處理。預測出的語言 token 同時條件化音訊與影片生成，因此語音、嘴型與身體動作可以在同一個端到端流程中保持同步。

**Q9：通用預訓練資料長什麼樣子？如何標註事件與角色？**

A：預訓練資料由大量普通影片組成，每段影片會配上一段持續性世界上下文的摘要，以及與時間對齊的事件序列。事件標籤會用括號標示角色行為，用引號標示說出的話，並將每個事件對應到相關角色，或以明確的無角色標記表示與角色無關的事件。雖然圖一為了清晰只展示單一角色的例子，但訓練本身支援多個角色同時出現在同一個世界中的情況。

**Q10：這項技術最適合應用在哪些實際場景？**

A：Wan-Streamer v0.3 適合任何需要代理在持續世界中同時說話與做出自由形式視覺行為的場景，例如遊戲中的非玩家角色、虛擬助教、即時互動式敘事、遠端陪伴機器人或沉浸式客服。由於代理的行為可以用自然語言描述，開發者能夠快速為不同角色與情境設計行為，而不必預先建立龐大的動作資料庫。低延遲與全雙工能力也讓它特別適合需要自然對話節奏與即時反應的產品。

**Q11：在產品化時，延遲與串流單元的選擇會帶來哪些考量？**

A：160 毫秒的串流單元在回應即時性與計算批次效率之間取得了平衡，過短會增加推理開銷，過長則會讓對話感覺遲鈍。約 550 毫秒的總互動延遲對於一般對話式應用來說已經接近可接受範圍，但在音樂合奏或競技遊戲等對延遲極敏感的場景仍可能不足。此外，350 毫秒的雙向網路預算意味著雲端部署時必須確保使用者與伺服器之間的網路品質穩定，否則實際體驗會偏離論文宣稱的運作點。

**Q12：這項研究可能對即時多模態 AI 領域帶來什麼影響？**

A：它把即時多模態互動從「針對特定任務設計級聯系統」轉向「透過通用世界事件預訓練學習可遷移能力」，這可能成為該領域的新範式。由於幾乎所有影片都能納入這個框架，預訓練資料的規模與多樣性可以大幅提升，進而增強模型的世界知識與開放行為生成能力。長遠來看，這種統一影片理解與生成的視角，也可能影響機器人、虛擬實境與人機互動的發展方向。

**Q13：論文目前承認了哪些限制？**

A：雖然訓練支援多角色，但圖一為了清晰只呈現單一角色的範例，實際多角色互動的複雜度尚未在提供的內容中深入討論。自由形式行為完全依賴語言描述，若描述模糊或與世界物理不一致，生成的行為可能不自然。此外，世界上下文的摘要品質會直接影響預訓練與下游任務的表現，而自動化產生高品質世界摘要本身就是一個尚未充分探討的挑戰。

**Q14：模型可能出現哪些失敗案例？**

A：當輸入行為指令與世界物理或角色能力不一致時，模型可能產生不合常理的動作，例如讓角色穿過障礙物或拿起不存在的物品。在多角色互動或快速輪替對話中，模型可能混淆說話者身分，導致語音與嘴型、視線方向不同步。若遇到預訓練資料中極少見的世界上下文，模型也可能出現過度泛化或生成重複、呆板的反應。

**Q15：未來可以朝哪些方向進一步發展？**

A：未來可以延長世界記憶，讓代理在長時間互動中持續記住場景狀態與使用者偏好，而不只是依賴預填的上下文。也可以引入更豐富的物理動態與多智能體社交互動，並結合人類回饋強化學習來改善行為合理性與安全性。此外，進一步降低延遲、提升解析度，以及將此框架遷移到真實機器人等具身平台，都是值得探索的方向。

## 實務應用指南

## 適用場景

1. **即時虛擬陪伴與情感互動**  
   在視訊通話或 AR/VR 空間中，Wan-Streamer v0.3 可扮演具有一致外貌、聲音與個性的虛擬角色，根據使用者的語音、表情與動作即時回應，並透過 `(微笑)`、`(歪頭)` 等自由形式行為指令展現可見傾聽與情緒反應。

2. **遊戲與元宇宙中的全雙工 NPC**  
   將「世界」設定為遊戲場景與角色背景，「事件流」即為 NPC 的對話與行為。模型能即時接收玩家語音與畫面輸入，輸出同步的語音、嘴型與動作，取代傳統腳本化或級聯模組 NPC。

3. **沉浸式遠端客服與導覽**  
   在零售、金融或文旅場域，代理可同時「看」到使用者分享的畫面、聽取問題，並以自然語音與手勢即時引導操作，適合需要高互動臨場感的服務情境。

4. **互動式教育與訓練模擬**  
   例如語言學習、醫療問診或設備維修演練：世界上下文固定為教室、診間或機房，事件流則是教練/學員的即時行為與對話，模型可持續維持情境一致性並給予即時回饋。

5. **直播與內容共創的即時共演者**  
   作為直播主的虛擬搭檔，根據彈幕、主播語音與畫面即時生成回應影片，並保持角色設定、聲線與視覺風格一致。

## 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **資料** | 大量真實影片，並能拆解為「世界」描述（場景、角色、聲學環境、語音特徵）與「事件流」標註（時間對齊的行為、語音、環境變化）。下游任務需準備角色扮演對話與自由形式行為語料。 |
| **算力** | 預訓練需要大規模 GPU/TPU 叢集；推論端需支援 640×368@25 FPS 的即時潛在特徵生成，並搭配 Ulysses 風格上下文平行執行器以維持約 200 ms 模型端回應延遲。 |
| **網路** | 雙向網路預算建議控制在 350 ms 以內，才能達到約 550 ms 總互動延遲；需部署低延遲串流協議（如 WebRTC）。 |
| **技術能力** | 熟悉 Transformer、多模態 Tokenizer、音視訊編解碼、分散式訓練、即時推論服務化，以及因果時間軸與區塊因果注意力機制。 |
| **合規與安全** | 需建立內容審核、使用者同意、肖像/聲音授權與幻覺行為防護機制。 |

## 實作步驟建議

1. **定義產品情境與世界上下文**  
   先確定代理的角色、場景、視覺風格、環境聲學條件與語音特徵，撰寫成穩定的「世界」描述，作為後續預填（prefill）的上下文。

2. **建構 world + event stream 資料集**  
   將影片切分為 160 ms 串流單元，標註每段事件：誰（角色）、做什麼（行為）、說什麼（語言形式語音）、環境如何變化。行為可使用開放詞彙描述，例如 `(拿起杯子並看向窗外)`。

3. **預訓練世界事件模型**  
   以「給定世界與輸入，預測世界如何即時展開」為目標進行通用預訓練，讓模型學習場景、物理與社交行為的世界知識。

4. **微調至特定下游互動任務**  
   將預訓練模型專門化為全雙工音視訊互動：固定世界上下文，讓事件流成為代理的語音與自由形式行為，並採用 `(行為) 說話內容` 的交錯格式。

5. **搭建即時推論管線**  
   部署 Text / Audio / Video 的 Tokenizer、Encoder、Decoder，確保語言、音訊、影片共享同一因果時間軸；透過上下文平行與串流解碼將模型端延遲壓在約 200 ms。

6. **同步生成與延遲優化**  
   讓預測的語言 Token 同時條件化音訊與影片生成，避免新增延遲關鍵路徑；持續監控 160 ms 串流單元內的音視訊同步與抖動。

7. **上線評測與迭代**  
   在真實網路環境測量總互動延遲、回應時機、行為合理性與使用者滿意度，並根據回饋調整世界上下文與事件流策略。

## 潛在風險與注意事項

| 風險 | 說明與因應 |
|---|---|
| **幻覺與不當行為** | 開放行為詞彙可能產生不符合角色或場景的動作。建議加入行為白名單、即時安全過濾器與人類在環（human-in-the-loop）機制。 |
| **延遲抖動** | 網路預算超過 350 ms 會明顯影響互動體驗。應實施自適應位元率、串流單元緩衝與降級策略（例如暫時只輸出音訊）。 |
| **音視訊不同步** | 需持續驗證嘴型、語音與動作的時間對齊，並在 Decoder 端加入同步約束。 |
| **隱私與肖像權** | 世界上下文中的角色外觀與語音特徵必須取得明確授權；使用者輸入的影片與音訊應加密傳輸與儲存。 |
| **資料偏誤** | 預訓練影片可能帶有文化、性別或場景偏誤。建議進行資料審計與多樣性增強，並在產品層提供透明說明。 |
| **過度擬真詐騙** | 高擬真代理可能被濫用。應加入數位浮水印、身份驗證與使用情境限制。 |

## 與其他技術的整合建議

- **與遊戲引擎（Unity/Unreal）整合**  
  將 Wan-Streamer v0.3 作為即時角色控制器，透過網路串流接收渲染後的畫面與玩家語音，並回傳代理的音視訊幀或行為描述給引擎驅動虛擬人。

- **與後端知識系統結合**  
  雖然模型為端對端形式化，但仍可在外部串接 RAG、使用者畫像或任務規劃模組，將檢索結果與角色狀態以文字形式注入世界上下文，提升專業領域回應品質。

- **與低延遲串流協議整合**  
  使用 WebRTC 或 SRT 傳輸 640×368@25 FPS 的影片與音訊，並在邊緣節點部署模型以縮短雙向網路預算。

- **與現有 ASR/TTS/臉部動畫管線並存**  
  在過渡期可將 Wan-Streamer 的語言輸出作為中繼，驅動既有 TTS 與臉部動畫系統；長期則逐步轉向完整的端對端原生串流互動模型。

- **與監控與 A/B 測試平台整合**  
  持續收集事件流日誌、延遲指標與使用者回饋，用於微調世界上下文與事件流生成策略。

## 給不同背景讀者的閱讀建議

**初學者**：先聚焦「世界 + 事件流」這個核心概念——把影片想成「固定背景」加上「隨時間發生的事」。接著看圖一與圖二的例子，理解模型如何從看影片學習，轉變成能即時對話的虛擬代理，不必一開始深入 Transformer 或延遲優化細節。

**AI 工程師**：重點閱讀端對端形式化、因果時間軸、區塊因果注意力與 Ulysses 風格上下文平行執行器的實作方式，並評估 160 ms 串流單元、約 200 ms 模型端回應延遲與 550 ms 總互動延遲在自身硬體與網路條件下是否可達成。

**研究人員**：關注 world + event stream 的通用預訓練任務設計、開放詞彙行為控制的表徵學習、模型如何泛化到不同世界上下文，以及全雙工互動中的回應時機、輪替判斷與長期一致性等評估議題。

**產品經理**：從適用場景與延遲預算出發，判斷產品是否適合採用原生串流互動模型；同時優先評估角色一致性、使用者隱私、內容安全與總互動延遲對使用者體驗的影響，再決定資料收集與上線範圍。
