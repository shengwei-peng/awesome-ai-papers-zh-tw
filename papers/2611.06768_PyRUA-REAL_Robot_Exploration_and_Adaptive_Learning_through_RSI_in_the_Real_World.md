PyRUA-REAL 提出了一個具身遞迴自我改進（Embodied RSI）的框架，其核心設計理念在於將「程式碼」視為高階推理與物理行為之間的介面，並透過雙代理（dual-agent）協作機制實現持續的能力累積。整體方法論可從以下幾個層次進行剖析：

**1. 雙代理分工架構**

框架採用 Researcher 與 Engineer 兩種角色分工：
- **Researcher 代理**：負責選擇實驗目標與技術路線，處理任務層級的重新評估（task-level reassessment），避免陷入局部修改的盲區。
- **Engineer 代理**：負責實作程式、執行機器人試驗、診斷失敗原因，處理區域性的程式碼改進（local code improvement）。

這種分工模擬了人類工程師的工作模式——高層次的策略決策與低層次的實作細節分離，使代理能在不同抽象層級上運作，避免反覆進行不適當的感知或控制策略的局部修改。

**2. 持久化記憶與可重用技能**

框架維護一個持續性儲存庫（persistent repository），記錄四類資訊：
- **環境事實（Environmental Facts）**：場景的物理與幾何特性。
- **嘗試過的方法（Attempted Approaches）**：曾經探索過的技術路線。
- **執行結果（Execution Outcomes）**：包含成功與失敗的診斷資訊。
- **可重用的實作（Reusable Implementations）**：已驗證可執行的技能模組。

此設計使後續實驗能建立在先前經驗之上，而基礎模型參數保持固定。這呼應了「經驗式適應」（experience-based adaptation）的研究路線，與傳統的線上學習或 fine-tuning 路線形成對比。

**3. RSI 迭代迴圈**

改進過程遵循「執行 → 探索 → 診斷 → 修訂」（Execute → Explore → Diagnose → Revise）的循環。值得注意的是，框架強調「診斷」階段——因為執行回饋（execution feedback）本質上是模糊的：表面上的任務失敗可能源自運動、感知或驗證程序的問題，因此需要明確的診斷步驟來定位真正的失敗根因。

**4. 部署階段的去代理化**

一個關鍵設計是將開發階段產生的程式碼「凍結」（frozen）後，可在無需執行階段語言模型呼叫的情況下獨立運行。這使高頻控制迴路（closed-loop control）由可執行程式負責，而高階推理僅在開發階段介入。這種分離不僅降低了部署成本，也提供了對部署行為的可分析性。

**5. 程式碼即策略（Code as Policy）**

框架將策略表示為可執行程式碼，而非權重參數。這帶來幾項優勢：可解釋性、可重用性、以及在不改變模型參數下進行修改的靈活性。程式碼模組化後可作為「技能」被後續任務檢索與組合。

A：論文中討論了幾類 RSI 失效情境。第一類是**回饋歸因錯誤**：當任務失敗時，代理可能誤判原因（例如將感知問題歸咎於運動控制），導致修訂方向錯誤，浪費多輪迭代。第二類是**局部最佳化陷阱**：代理反覆改進某個子模組，但底層策略本身就不適合該任務，需要 Researcher 層級的重新評估才能突破。第三類是**過擬合特定配置**：在某個特定物件位置或方向下成功的程式，可能在稍微變化的條件下失敗，這需要刻意設計的變化測試來暴露。論文中提到的乙太網路插接任務成功率僅 58.82%，相對低於其他任務，可能正是這類挑戰的體現——精細接觸操作對感知精度與運動控制的雙重要求，使得 RSI 過程更為艱難。

**Q15：基於這項研究，未來有哪些值得探索的研究方向？**
A：基於 PyRUA-REAL 的成果，未來研究有多個值得探索的方向。第一是**跨平台遷移**：目前技能與特定硬體平台（雙臂 Franka）緊密耦合，如何將累積的技能抽象化並遷移至不同機器人形態是重要課題。第二是**多機器人協作**：將 RSI 擴展至多機器人系統，讓機器人之間能共享經驗、協作完成複雜任務。第三是**模擬-真實整合**：結合模擬環境的低成本探索與真實世界的高保真回饋，加速 RSI 過程。第四是**安全性與可解釋性**：隨著 RSI 自主修改程式碼，如何確保修改不會引入安全風險、如何讓人類理解並信任這些修改，是實際部署的關鍵。第五是**長期持續學習**：探索 RSI 在數週、數月時間尺度上的穩定性，以及如何處理環境漂移與任務演進。這些方向將共同推動「具身遞迴自我改進」從實驗室概念走向成熟的技術範式。
