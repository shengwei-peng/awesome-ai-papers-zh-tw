## ⚡ TL;DR

LLM代理在系統研究中依賴模擬器評估設計，但難以判斷建模限制是否會使推薦失效。
本文提出SIRIS框架，透過擾動模擬器並配對工作負載，評估十三個前沿LLM的判斷能力。
結果顯示多數LLM即使識別出限制仍難以正確判斷，自我修正雖有助部分模型卻也引入新錯誤。

大型語言模型（LLM）代理日益驅動系統研究，並依賴模擬器（Simulator）來大規模評估候選設計（Candidate Designs）。模擬器天生即不完美：其建模限制（Modeling Limitation）可能扭曲預測（Predictions），卻仍使推薦的設計保持正確，或改變應選擇的設計。我們提出SIRIS來測試大型語言模型是否能區分這些情況，根據其系統理解（Systems Understanding）判斷限制何時會使模擬器的推薦（Recommendation）失效。SIRIS透過擾動（Perturbation）模擬器，建構出候選設計、限制與模擬器推薦皆相同的工作負載對（Workload Pairs）。該擾動會改變兩個工作負載上的預測，但參考模擬器（Reference Simulator）僅在其中一個工作負載上支持該推薦。我們針對大型語言模型服務（LLM Serving）設計問題，評估了十三個前沿大型語言模型（Frontier LLMs），發現識別限制並不能確保正確的選擇，即使是最強的模型有時也會放棄有效推薦（Valid Recommendation）。透過審查輪次（Review Turn）進行的自我修正（Self-Correction）有助於這些模型恢復有效選擇，但卻在其他幾個模型中引入了新的錯誤。這些發現促使我們透過在不完美模擬器（Imperfect Simulator）下的設計決策（Design Decisions）來評估系統理解。

- 涵蓋十三個前沿大型語言模型的大型語言模型服務設計問題實證：提供具體且可量化的基準，揭示當前模型在模擬器輔助評估（Simulator-Assisted Evaluation）下的系統性弱點。

## 深度分析

#### 方法論解析

SIRIS 的方法論核心在於將「模擬器建模限制對設計決策的影響」這個抽象問題，轉化為可量化的對比實驗框架。其設計哲學體現了三個關鍵的方法論選擇：

**1. 擾動注入機制（Perturbation Injection）**

SIRIS 並非直接使用真實模擬器的既有缺陷，而是透過「受控擾動」（controlled perturbations）——即對模擬器程式碼進行小型修改，改變其對工作、成本或資源互動的表示方式。這種方法具有雙重優勢：第一，可重現性高，因為擾動是明確的程式碼變更而非模糊的建模假設；第二，可控制性強，研究者能精確指定擾動的類型與幅度。這與傳統模擬器研究中僅記錄「已知限制」（如 Table 1 所列 APEX、Vidur、ASTRA-sim 2.0 等模擬器的省略行為）但缺乏系統化評估的方式形成對比。

**2. 工作負載對配對設計（Workload Pair Construction）**

框架的精妙之處在於構造「upheld」與「overturned」兩類問題對：對於同一擾動與同一組候選設計，擾動後的模擬器在兩個工作負載上推薦相同設計，但參考模擬器（reference simulator）僅在其中一個工作負載上支持該推薦。這種配對設計巧妙地隔離了「識別限制」與「判斷決策影響」這兩個認知任務——LLM 即使正確指出限制存在，仍需判斷該限制是否足以逆轉設計排名。

**3. 判斷（Judgment）與傾向（Disposition）的雙維度量化**

SIRIS 提出兩個互補指標：
- **整體準確率（Overall Accuracy）**：upheld 與 overturned 兩類問題準確率之平均值。這避免了「總是接受推薦」或「總是拒絕推薦」的捷徑策略——任何固定偏好最多只能正確解決配對中的一個問題。
- **傾向（Disposition）**：兩類準確率之間的不平衡程度，揭示 LLM 系統性地偏向接受或拒絕模擬器推薦。

**4. 自我修正機制（Self-Correction via Review Turn）**

針對 RQ3，框架引入「審查輪次」（review turn），讓 LLM 在給出初始判斷後有機會重新審視。這模擬了 ADRS 迭代流程中的反思環節，但實驗結果顯示此機制存在雙刃劍效應——對部分模型提升判斷力，卻在其他模型上引入新錯誤。

#### 實驗數據解讀

實驗設計聚焦於 LLM 服務（LLM serving）設計問題，這是一個高度實用且建模複雜的領域，涉及 KV 快取、批次處理、排程策略等多個相互作用的元件。

**核心發現一：識別限制 ≠ 正確決策**

這是論文最具啟發性的發現。LLM 即使能正確指出模擬器的建模限制（例如「忽略網路頻寬競爭」），仍可能選擇被該限制誤導的設計。這揭示了系統理解（systems understanding）的一個深層結構：它不僅需要識別問題，還需要評估問題的嚴重性與方向性。換言之，LLM 具備「診斷能力」但缺乏「預後判斷」。

**核心發現二：最強模型也會放棄有效推薦**

即使是評估中的頂尖模型，在面對 overturned 問題時仍會放棄原本有效的推薦。這暗示前沿 LLM 在面對模擬器證據時存在過度反應傾向——當識別到任何建模限制時，可能傾向於全面懷疑模擬器輸出，而非評估該限制對當前決策的具體影響。

**核心發現三：自我修正的異質性效應**

審查輪次的效果呈現顯著的模型依賴性：
- 對部分模型：自我修正恢復了原本放棄的有效推薦，顯示反思機制能幫助模型重新權衡證據
- 對其他模型：自我修正引入了新的錯誤，可能因為模型在審查階段過度修正，或受到自身先前判斷的錨定效應影響

**指標設計的深意**

「傾向」（Disposition）指標的引入特別值得注意。單看整體準確率可能掩蓋系統性偏差——例如一個模型若總是接受推薦，在 upheld 問題上表現優異但 overturned 問題上完全失敗，整體準確率可能仍達 50%。傾向指標揭示了這種結構性偏差，對於部署 LLM 代理於真實 ADRS 流程至關重要，因為系統性偏差會在迭代過程中被放大。

#### 與現有研究的比較

**相較於 ADRS 系統本身的評估（AlphaEvolve、ShinkaEvolve、Glia、Database ADRS）**

現有 ADRS 研究主要關注端到端的設計發現效能——最終找到的設計品質。然而 SIRIS 指出，這些評估混淆了「模擬器正確」與「設計正確」兩個概念。當 ADRS 系統依賴不完美模擬器時，端到端成功可能源於模擬器恰好在關鍵決策點上正確，也可能源於 LLM 幸運地避開了誤導性預測。SIRIS 透過分離「模擬器證據」與「設計決策」，提供了更細粒度的評估維度。

**相較於 Ranking-and-Selection 分析（Song et al., 2015）**

傳統的 ranking-and-selection 文獻已建立「等量加性誤差在配對差異中抵消」的理論基礎。SIRIS 將此理論操作化為 LLM 可執行的判斷任務，並發現 LLM 並未內化此原理——它們傾向於將任何建模限制視為決策無效的證據，而非評估誤差的候選相依性（candidate-dependency）。

**相較於架構研究中的相對趨勢警告（Nowatzki et al., 2015）**

架構研究社群早已警示模擬器誤差可能與被評估技術產生交互作用，使相對趨勢無法泛化。SIRIS 將此警示轉化為可測試的假設：LLM 是否能識別此類交互作用？實驗結果顯示答案並不樂觀。

**方法論限制**

1. **領域範圍**：實驗僅限於 LLM 服務設計問題。雖然這是一個重要且複雜的領域，但結論是否能泛化至資料中心排程、負載平衡、資料庫優化等其他 ADRS 應用場景仍待驗證。

2. **擾動的代表性**：受控擾動雖然可控，但可能無法完全捕捉真實模擬器限制的複雜性。真實限制往往是多個近似假設的累積效應，而非單一可隔離的擾動。

3. **參考模擬器的選擇**：框架依賴「參考模擬器」作為 ground truth，但參考模擬器本身也是不完美的。這引入了循環依賴的風險。

4. **評估的靜態性**：當前評估是單輪判斷，尚未捕捉 ADRS 迭代過程中證據累積與判斷演化的動態特性。

#### 可重現性評估

從論文提供的資訊來看，可重現性評估呈現混合態：

**正面因素**
- 框架基於「受控擾動」而非真實模擬器的黑箱行為，理論上具有高度可重現性
- 評估 13 個前沿 LLM，提供了跨模型的基準比較
- 問題配對設計（upheld/overturned）允許獨立驗證

**待確認因素**
- 論文未明確說明 SIRIS 框架程式碼是否開源
- 擾動的具體實作細節需要從附錄或補充材料確認
- 評估使用的具體 LLM 版本、提示模板（prompt templates）、超參數設定需要完整記錄才能重現
- LLM 服務設計問題的具體內容、候選設計空間的定義需要公開

**建議的可重現性增強**
- 開源 SIRIS 框架程式碼與擾動實作
- 公開完整的問題集與參考答案
- 提供標準化的評估協議，包括提示工程指南
- 記錄所有模型的 API 呼叫參數與隨機性控制

#### 未來研究方向

**1. 跨領域泛化研究**

將 SIRIS 擴展至其他 ADRS 應用領域是自然的下一步。具體而言：
- **資料中心排程**：評估 LLM 對排程模擬器（如 CloudSim 衍生工具）建模限制的判斷力
- **負載平衡**：測試 LLM 在網路模擬器（如 ns-3）輔助下能否正確識別影響負載平衡決策的限制
- **資料庫優化**：檢驗 LLM 對查詢最佳化器模擬中成本模型近似的判斷

跨領域研究將揭示 SIRIS 發現是否為 LLM 的通用限制，或是特定於 LLM 服務領域的特性。

**2. 增強型自我修正機制**

當前審查輪次的異質性效應提示需要更精密的修正策略：
- **結構化反思提示**：設計引導 LLM 評估「誤差方向性」而非僅「誤差存在性」的提示模板
- **多代理辯論**：引入多個 LLM 代理進行對抗性辯論，可能比單一代理的自我審查更穩健
- **外部驗證整合**：結合形式化方法或輕量級分析來輔助 LLM 的判斷

**3. 動態與迭代評估**

當前 SIRIS 評估單輪判斷，但真實 ADRS 是迭代過程：
- **證據累積研究**：追蹤 LLM 在多輪模擬器證據下的判斷演化
- **錯誤恢復能力**：評估 LLM 在迭代中發現先前判斷錯誤時的修正效率
- **探索-利用平衡**：研究 LLM 在面對不完美模擬器時如何平衡遵循證據與維持信念

**4. 模擬器輔助決策的理論框架**

SIRIS 的發現呼籲建立更嚴格的理論基礎：
- **LLM 模擬器推理的形式化**：將 ranking-and-selection 理論轉化為 LLM 可學習的推理模式
- **校準方法**：開發讓 LLM 輸出「判斷信心度」的方法，使下游系統能根據信心度調整對 LLM 建議的依賴程度
- **風險敏感評估**：區分「高風險逆轉」（如安全關鍵設計）與「低風險逆轉」（如效能微調）的評估協議

**5. 與真實 ADRS 系統的整合驗證**

最終，SIRIS 的實用價值需透過與真實 ADRS 系統的整合來驗證：
- **外掛評估模式**：將 SIRIS 作為 ADRS 系統的診斷工具，定期檢查 LLM 代理的判斷品質
- **A/B 測試框架**：比較「使用 SIRIS 訓練過的 LLM」與「未訓練 LLM」在真實 ADRS 任務中的表現差異
- **人機協作介面**：設計讓人類研究者能有效審查 LLM 模擬器判斷的介面，特別是在 LLM 傾向指標顯示系統性偏差時

**6. 模擬器限制的自動發現**

長期願景是讓 LLM 不僅判斷已知限制的影響，還能主動發現模擬器的未知限制：
- **對抗性測試生成**：讓 LLM 設計壓力測試工作負載以暴露模擬器弱點
- **跨模擬器一致性檢查**：利用多個模擬器的預測分歧來識別潛在限制
- **限制影響的定量預測**：從「限制是否影響決策」推進到「限制如何影響決策」的定量預測

這些方向不僅擴展 SIRIS 的技術邊界，更回應了論文的核心論點——在 AI 驅動的系統研究中，模擬器使用的智慧本身需要被系統性地研究與評估。

## 論文問答

**Q1：SIRIS 論文主要解決什麼核心問題？**
A：SIRIS 論文主要解決的是大型語言模型（LLM）在 AI 驅動系統研究（ADRS）中能否正確判斷模擬器建模限制是否會影響設計決策的問題。由於模擬器為了保持可擴展性會省略或近似某些系統行為，這些建模限制可能扭曲預測結果，有時不改變最佳候選設計，有時則會徹底翻轉推薦結果。SIRIS 旨在測試 LLM 是否具備這種「決策影響判斷」能力，亦即能否辨識模擬器的限制何時會使推薦失效。

**Q2：為什麼現有的評估方法無法有效衡量 LLM 的系統理解能力？**
A：現有評估方法通常聚焦於 LLM 能否預測系統效能或產生程式碼，但並未隔離「判斷模擬器限制是否影響決策」這一特定能力。傳統基準測試無法區分 LLM 是因為理解了模擬器限制而做出正確選擇，還是僅僅依賴表面證據或固定偏好。此外，現有方法也無法衡量 LLM 在面對不完美模擬器時的判斷傾向（disposition），例如是否總是接受或總是拒絕模擬器的推薦。

**Q3：為什麼這種判斷能力對 ADRS 至關重要？**
A：在 ADRS 的迭代流程中，LLM 代理負責提出候選設計、透過模擬器評估它們，並根據結果改進設計。若 LLM 無法判斷模擬器限制是否會使推薦失效，可能會盲目接受錯誤的設計決策，導致整個研究流程偏離正確方向。這種判斷能力是 ADRS 所依賴的「系統理解」的核心形式——LLM 不必自行預測系統效能，但必須知道何時可以信任模擬器的推薦，從而避免在錯誤的基礎上進行後續迭代。

**Q4：SIRIS 的核心方法論是什麼？**
A：SIRIS 的核心方法論是透過「受控擾動」（controlled perturbations）來模擬真實模擬器的建模限制，這些擾動是對模擬器如何表示工作、成本或資源互動的小幅程式碼修改。對於每個擾動，SIRIS 會建構一對工作負載（workload pairs），使得被擾動的模擬器在兩個工作負載上推薦相同的設計，但參考模擬器（reference simulator）只在其中一個工作負載上支持該推薦（upheld），而在另一個工作負載上支持不同的設計（overturned）。這種配對設計使得評估能夠精確衡量 LLM 的判斷能力。

**Q5：使用「工作負載對」（workload pairs）的關鍵創新是什麼？**
A：使用工作負載對的關鍵創新在於它能夠控制混淆變數，確保 LLM 面對的是相同的候選設計、相同的建模限制以及相同的模擬器推薦，唯一不同的是該推薦在參考模擬器下是否仍然成立。這種設計排除了固定候選偏好或簡單規則（如總是接受或總是拒絕推薦）可能帶來的偏差，因為這類策略在每對問題中最多只能解決一個。此外，配對設計也使得「判斷」（judgment）與「傾向」（disposition）這兩個指標能夠被獨立測量與分析。

**Q6：SIRIS 如何衡量 LLM 的判斷與傾向？**
A：SIRIS 將「判斷」操作化為在 upheld 和 overturned 兩類問題上的正確設計選擇準確率，並以兩者的平均值作為整體判斷分數。「傾向」（disposition）則總結了 LLM 在兩類問題上的準確率不平衡程度，例如是否傾向於接受或拒絕模擬器的推薦。這兩個指標會在每個層級的模擬器證據下進行測量，並在審查輪次（review turn）前後進行比較，以評估自我修正對判斷能力的影響。

**Q7：SIRIS 實驗使用了哪些基準測試與模型？**
A：SIRIS 實驗聚焦於 LLM 服務（LLM serving）設計問題，這是 ADRS 中一個重要的應用領域。實驗評估了十三個前沿級大型語言模型（frontier-level LLMs），涵蓋了當前最具代表性的商用與開源模型。這些模型在面對不同擾動類型與不同強度的模擬器證據時進行測試，以全面評估其判斷能力。

**Q8：SIRIS 實驗的主要發現是什麼？**
A：實驗發現，即使是最強的模型也會在某些情況下放棄原本有效的推薦，顯示出有限的判斷能力。更重要的是，識別出一個建模限制並不保證能做出正確的設計選擇，這表明 LLM 的「識別能力」與「決策能力」之間存在明顯落差。此外，許多模型展現出系統性的傾向偏差，例如傾向於接受或拒絕模擬器的推薦，而非根據實際證據進行判斷。

**Q9：自我修正（self-correction）對 LLM 判斷能力有何影響？**
A：自我修正機制透過引入審查輪次讓 LLM 重新檢視其決策，結果顯示這種機制對不同模型產生不一致的效果。對於某些模型，自我修正能夠幫助它們恢復原本放棄的有效推薦，提升整體判斷分數；然而，對於其他模型，自我修正反而引入了新的錯誤，導致判斷能力下降。整體而言，檢查指令與自我修正往往更多地改變模型的傾向（disposition），而非實質提升判斷（judgment）能力。

**Q10：SIRIS 的研究成果適用於哪些實際場景？**
A：SIRIS 的研究成果適用於所有依賴模擬器進行設計評估的 ADRS 場景，包括資料中心排程、服務策略、負載平衡以及資料庫優化等領域。在這些場景中，LLM 代理需要根據模擬器輸出做出設計決策，而 SIRIS 提供了一個評估框架來測試 LLM 是否能在這些場景中做出可靠的判斷。研究成果也適用於任何使用模擬器輔助程式碼搜尋或設計迭代的系統，例如 AlphaEvolve 和 ShinkaEvolve 等。

**Q11：SIRIS 對實際產品開發有何考量？**
A：對於實際產品開發而言，SIRIS 提醒開發者在部署 LLM 代理進行系統研究時，必須謹慎處理模擬器輸出的可信度問題。產品設計應該考慮到 LLM 可能會盲目接受或拒絕模擬器推薦的傾向，並設計相應的機制來緩解這種風險。此外，自我修正機制雖然有時有益，但並非萬靈丹，產品設計不應假設審查輪次一定能提升決策品質，而應進行實證評估。

**Q12：SIRIS 對系統研究領域的更廣泛影響是什麼？**
A：SIRIS 對系統研究領域的更廣泛影響在於它提出了一種新的評估範式，主張應透過「在不完美模擬器下的設計決策」來衡量 LLM 的系統理解能力。這種範式轉移了評估焦點，從「LLM 能否預測效能」轉向「LLM 能否判斷模擬器何時可信」，更貼近 ADRS 的實際需求。這也促使研究社群重新思考如何設計模擬器、如何呈現模擬器證據，以及如何訓練 LLM 以更好地處理不完美的評估工具。

**Q13：SIRIS 論文承認哪些研究限制？**
A：SIRIS 論文承認其評估目前聚焦於 LLM 服務設計問題，這限制了結論在其他系統研究領域的泛化性。此外，擾動的設計雖然基於真實模擬器的文件化建模選擇，但仍屬於受控環境，可能無法完全捕捉真實模擬器限制的複雜性。論文也指出，評估的十三個模型雖然涵蓋前沿級 LLM，但無法代表所有可能的模型行為，特別是未來可能出現的新架構或訓練方法。

**Q14：SIRIS 觀察到哪些失敗案例？**
A：SIRIS 觀察到的主要失敗案例包括：即使是最強的模型也會在 overturned 問題上錯誤地接受模擬器的推薦，顯示出對建模限制影響的低估；某些模型在自我修正後反而做出更差的決策，顯示出審查機制的潛在風險；以及許多模型展現出強烈的傾向偏差，例如總是選擇特定類型的設計或總是遵循/拒絕模擬器推薦，這些策略性偏差使其在配對問題中最多只能解決一半。

**Q15：SIRIS 提出了哪些未來研究方向？**
A：SIRIS 提出的未來研究方向包括：將評估框架擴展到 LLM 服務以外的其他系統研究領域，以驗證結論的泛化性；探索更有效的提示工程或訓練方法，以提升 LLM 對模擬器限制的判斷能力；研究如何設計更好的自我修正機制，使其能穩定提升而非偶爾惡化決策品質；以及探討如何將 SIRIS 的評估結果整合到 ADRS 系統的設計中，例如作為 LLM 代理選擇或模擬器選擇的依據。這些方向共同指向一個更成熟的 ADRS 評估生態系統。

### 實作步驟建議

**步驟一：定義評估問題集**
從目標領域（如 LLM 服務）選取 5–10 個典型設計決策場景，每個場景包含 2–4 個候選設計與 3–5 種工作負載變體。記錄每個場景的「真實最佳設計」（由參考模擬器或實機測量決定）。

**步驟二：建立參考模擬器基準**
使用高保真模擬器或實機測量結果作為 ground truth，標註每個（設計, 工作負載）組合的預期排名。確保參考模擬器本身不包含待測模擬器的特定建模限制。

**步驟三：實作擾動機制**
參考 SIRIS 的方法，識別待測模擬器中的建模限制（例如 Vidur 將每個請求的 context length 簡化為總 KV 讀取數）。將這些限制抽象為可參數化的程式碼修改，設計成「開關式」擾動。

**步驟四：建構配對問題**
對每個擾動，搜尋兩個工作負載 $W_1, W_2$，使得：
- 擾動後的模擬器在 $W_1$ 與 $W_2$ 上都推薦同一設計 $D^*$
- 參考模擬器在 $W_1$ 上支持 $D^*$（upheld），但在 $W_2$ 上偏好另一設計 $D'$（overturned）

**步驟五：設計 LLM 評估提示**
為每個問題設計結構化提示，包含：候選設計描述、工作負載規格、擾動後模擬器的推薦結果、限制說明。要求 LLM 輸出最終設計選擇與理由。準備「審查輪次」提示，鼓勵 LLM 重新檢視其判斷。

**步驟六：執行評估並計算指標**
對每個 LLM 計算：
- **判斷準確率** = (upheld 正確率 + overturned 正確率) / 2
- **傾向** = upheld 正確率 − overturned 正確率（衡量是否偏向接受或拒絕推薦）
- 比較審查輪次前後的指標變化

**步驟七：分析與迭代**
識別 LLM 表現最差的限制類型與工作負載特徵，針對性地擴充問題集或調整提示設計。

### 潛在風險與注意事項

**風險一：擾動的代表性不足**
若擾動僅模擬「教科書式」的建模限制，可能無法反映真實模擬器的複雜偏差。**緩解措施**：從模擬器原始文件的「已知限制」章節出發，並邀請領域專家審核擾動的真實性。

**風險二：參考模擬器本身不夠權威**
若 ground truth 來自另一個簡化模擬器，可能將「限制對限制」誤判為正確。**緩解措施**：在關鍵問題上使用實機測量或經過驗證的分析模型作為最終仲裁。

**風險三：自我修正的雙刃劍效應**
論文發現審查輪次雖能讓部分模型恢復有效推薦，但也會讓其他模型產生新錯誤。**緩解措施**：不要將審查輪次視為「總是更好」的步驟，而應比較前後指標，僅在確認有淨改善時啟用。

**風險四：固定偏好策略的偽正確**
若 LLM 總是接受或總是拒絕模擬器推薦，可能在 upheld 或 overturned 問題上分別達到 100% 與 0%，平均後看似「隨機」。**緩解措施**：務必同時報告 upheld 與 overturned 的分項準確率，並監控傾向指標。

**風險五：評估洩漏（evaluation leakage）**
若 LLM 在訓練資料中已見過特定模擬器的輸出模式，可能產生虛高的判斷能力。**緩解措施**：使用新發布的模擬器版本或自製擾動，並定期更新問題集。

**風險六：成本與時間失控**
13 個前沿 LLM × 數百個問題 × 兩輪評估的 API 成本可能極高。**緩解措施**：先以小型子集（3–5 個 LLM、20–30 個問題）做先導實驗，篩選後再擴大規模。

### 與其他技術的整合建議

**與 ADRS 框架整合**：將 SIRIS 作為 AlphaEvolve、ShinkaEvolve 等 LLM 驅動程式搜尋系統的「可信度閘門」——當模擬器推薦與 SIRIS 判斷衝突時，觸發人工審查或額外驗證。

**與模擬器基準測試整合**：將 SIRIS 的擾動機制擴充為標準化的「模擬器壓力測試套件」，類似 ML 領域的 adversarial benchmark（如 ImageNet-C），用於版本發布前的回歸測試。

**與 LLM 評估平台整合**：將 SIRIS 整合至 HELM、lm-evaluation-harness 等開源評估框架，使其成為「系統理解」維度的標準基準。

**與可解釋性工具整合**：結合 SHAP、LIME 等可解釋 AI 工具，分析 LLM 在判斷模擬器限制時依賴哪些特徵，協助除錯與提示優化。

**與 CI/CD 流程整合**：在模擬器或 ADRS 系統的持續整合流程中，自動執行 SIRIS 子集，確保程式碼變更不會引入新的「決策敏感」限制。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的圖 1 與第 2.2 節的決策影響概念，理解「建模限制如何反轉設計排名」這個核心直覺，再回到第 1 節的三大研究問題。實作上可先跳過擾動機制，僅以「是否接受模擬器推薦」的二元問題體驗 upheld 與 overturned 的差異。

**給 AI 工程師**：重點關注第 3 節的 SIRIS 框架設計與第 4 節的實驗結果，特別是「識別限制 ≠ 正確選擇」這個反直覺發現。實作時建議先複製論文中的 Vidur 擾動範例，再擴展至自身領域的模擬器。注意審查輪次的雙刃劍效應，在生產環境中謹慎啟用。

**給研究者**：第 3 節的配對問題構造方法是核心方法論貢獻，值得深入理解其數學基礎（與 ranking-and-selection 文獻的連結）。第 5 節的討論與未來工作方向提供了豐富的研究線索，特別是將 SIRIS 擴展至多設計、多限制場景，以及與人類專家判斷的對比研究。
