# D²-Monitor：透過猶豫感知路由（Hesitation-Aware Routing）實現擴散式大型語言模型（Diffusion Large Language Models, D-LLMs）的動態安全性監控（Dynamic Safety Monitoring）

## ⚡ TL;DR

擴散式語言模型的安全監控仍待探索，其多步去噪軌跡蘊含單步難以捕捉的安全訊號，卻缺乏有效監測機制。
提出 D²-Monitor，以輕量探針監測去噪軌跡的安全猶豫，並於猶豫過高時動態切換至重型探針分類。
跨四模型三資料集，D²-Monitor 以極小參數達最佳效能，並於八基線中取得效能與效率最佳平衡。

## 摘要翻譯

儘管擴散式大型語言模型（Diffusion Large Language Models, D-LLMs）作為自迴歸大型語言模型（Autoregressive Large Language Models, AR-LLMs）的替代方案已經興起，針對 D-LLMs 的安全性監控（Safety Monitoring）仍鮮少被探討。與 AR-LLMs 不同，D-LLMs 透過多步驟去噪過程（Multi-step Denoising Process）生成文本，暴露出可能包含安全相關資訊的中間隱藏表徵（Intermediate Hidden Representations），而這些資訊在標準單步驟監控設定中無法取得。基於輕量級探針（Lightweight Probes）適合於常時監控（Always-on Monitoring）的特性，我們分析哪些軌跡層級訊號（Trajectory-level Signals）最能指示此類探針在何種情況下可能難以正確分類。我們發現最具資訊性的訊號是安全性猶豫（Safety Hesitation）：中間隱藏狀態（Intermediate Hidden States）反覆落入探針決策邊界（Decision Boundary）的小餘裕區域。D-LLM 軌跡中此類猶豫步驟（Hesitation Steps）的數量能有效預測探針失效（Probe Failure），提供了樣本難度

## 深度分析

#### 方法論解析

本研究的核心方法論建立在對擴散式大型語言模型（Diffusion large language models, D-LLMs）多步驟去噪過程（multi-step denoising process）的機制性發現（mechanistic discovery）之上。不同於自迴歸大型語言模型（Autoregressive large language models, AR-LLMs）僅在最終輸出層暴露表徵，D-LLMs 在迭代去噪的每一個時間步都會產生中間隱藏表徵（intermediate hidden representations），形成一條完整的去噪軌跡（denoising trajectory）。作者發現，這條軌跡中蘊含了標準單步驟監控架構無法取得的安全相關訊號。

**安全性猶豫（Safety Hesitation）的定義與量化**
作者系統性分析軌跡層級訊號（trajectory-level signals）後，識別出最具預測力的指標為「安全性猶豫」。具體而言，在每一個去噪步驟（denoising step）$s$，輕量級探針（lightweight probe）會計算該步隱藏狀態（hidden states）到其決策邊界（decision boundary）的距離，即逐步餘裕（stepwise margins）$d_s$。若 $|d_s| < \tau$（其中 $\tau$ 為餘裕閾值），則該步被視為落入猶豫區域（hesitation region）。整條軌跡中落入此區域的次數記為猶豫步驟（hesitation steps）$n_\tau$。作者證明，$n_\tau$ 與探針失效（probe failure）機率呈強烈正相關：猶豫步驟越多，代表該樣本對輕量探針而言越困難，可作為樣本難度（sample difficulty）的有效代理指標（proxy of sample difficulty）。

**雙層級監控架構（Bi-level Safety Monitor）**
基於上述發現，D²-Monitor 採用雙層級設計，包含：
1. **基礎探針（Base probe）**：一個常時監控器（always-on monitor），參數量極小（線性或輕量架構），負責兩項任務：(a) 對每個去噪步驟輸出基礎分類（base classification）；(b) 同步估計該軌跡的猶豫嚴重度（hesitation severity）。此探針在推論（inference）階段持續運行，成本極低。
2. **進階探針（Advanced probe / Heavy probe）**：一個高容量、高運算成本的重型探針（heavy probe），僅在必要時啟動。其訓練資料並非全部樣本，而是透過猶豫嚴重度篩選出的困難樣本（即猶豫軌跡），使其專精於基礎探針容易誤判的邊界案例。

**動態路由機制（Dynamic Routing Mechanism）**
在測試時（test time），基礎探針逐步讀取 D-LLM 的去噪軌跡，計算逐步餘裕序列 $(d_1, \dots, d_S)$，並統計猶豫步驟數 $n_\tau$。若 $n_\tau$ 超過路由閾值 $\lambda$，動態路由機制（dynamic routing mechanism）便觸發進階探針進行第二階段分類；反之，則直接採用基礎探針的預測結果。這種設計讓簡單樣本（easy/stable trajectories）僅需負擔輕量探針的運算，而困難或對抗性樣本（hard/hesitant trajectories）才會啟動額外防護，實現在效能與效率權衡（effectiveness-efficiency trade-off）上的動態資源分配。

**訓練流程**
訓練分為兩階段：首先以全部資料訓練基礎探針；接著利用 $K$-fold 交叉驗證，以基礎探針在訓練集上產生的逐步餘裕，篩選出 $n_\tau > 0$ 的猶豫樣本，用以訓練進階探針。這種「以輕量模型自身的猶豫訊號來策展困難樣本」的策略，避免了昂貴的人工標註或外部模型標記，形成自給自足的難度評估與資料篩選迴路。

#### 實驗數據解讀

**評估設定**
實驗涵蓋三個安全性資料集（safety datasets）：WildGuardMix、ToxicChat 與 OpenAI-Moderation，並在四個 D-LLM 上進行評估：LLaDA-8B-Base、LLaDA-8B-Instruct、LLaDA-1.5 與 LLaDA-2.0-mini。測試場景包含同資料集（intra-dataset）與跨資料集（cross-dataset）設定，以驗證泛化能力。比較基線（baselines）多達八組，涵蓋不同參數量與架構的監控器。

**核心結果：效能與效率的帕累托最優**
論文圖一右側呈現了預期測試時參數量（expected test-time parameters）與 F1 分數（F1 score）的散佈圖。D²-Monitor 的變體位於圖的左上角：相較於所有基線，其在維持極小參數規模（parameter footprint，$\leq 0.85\text{M}$，僅佔 $8\text{B}$ 模型參數的 $0.01\%$）的同時，達到最高的 F1 分數。這顯示 D²-Monitor 並非僅在絕對準確率上取得最佳化，而是在「每單位參數所能換取的監控效能」上顯著優於傳統單一層級的探針或靜態混合架構。

**猶豫訊號的預測力驗證**
雖然完整數據表格未在提供片段中詳列，但從方法論推論，作者應已驗證 $n_\tau$ 與探針錯誤率之間的單調關係。這意味著猶豫嚴重度（hesitation severity）不僅是一個理論上優美的概念，更是在實務上可穩定偵測「即將失效」的預警指標。對於部署者而言，這提供了可解釋的監控訊號：當系統觀察到去噪軌跡中出現大量低餘裕步驟（low-margin steps）時，即代表該輸入可能經過對抗性擾動或處於語意邊界，需要升級審查。

**穩健性（Robustness）**
額外分析指出，D²-Monitor 在不同生成設定（generation configurations）、重新遮罩策略（remasking strategies）與超參數（hyperparameters）下均保持穩定。這點極具實務價值，因為 D-LLMs 的推論過程涉及諸如步驟數、遮罩排程等變因，若監控器對這些變化過於敏感，將難以在生產環境中維護。

#### 與現有研究的比較

**相對於 AR-LLM 監控典範的典範轉移**
現有安全性監控文獻幾乎完全圍繞 AR-LLMs 展開，分為兩大類：LLM-as-monitors（以額外大型語言模型進行分類）與探針式監控器（probe-based monitors）。前者雖準確但運算成本高昂；後者輕量，但傳統上僅作用於單一時間點的隱藏狀態。D²-Monitor 的關鍵突破在於指出：D-LLMs 的多步驟去噪軌跡（denoising trajectory）本身即是一種新的、 richer 的訊號來源，這是 AR-LLMs 的循序解碼（sequential decoding）所無法提供的。因此，本研究不僅是將現有探針「移植」到 D-LLMs，而是針對 D-LLMs 的生成機制定義了全新的監控問題與解決方案。

**與對齊（Alignment）技術的互補性**
既有 D-LLM 安全性研究多聚焦於模型內部的對齊技術（alignment techniques），例如透過訓練提升模型自身的安全意識。然而，對齊本身無法抵禦對抗性攻擊（adversarial attacks）。D²-Monitor 作為外部安全性監控器（external safety monitor），與對齊形成互補：對齊降低模型生成有害內容的傾向，而 D²-Monitor 則在部署時（deployment-time）偵測惡意輸入或問題行為，尤其針對刻意繞過對齊的輸入。

**相對於基線的優勢**
相較於八組基線，D²-Monitor 的優勢體現在三個維度：
1. **訊號利用**：基線可能僅使用最終隱藏狀態或簡單聚合特徵，而 D²-Monitor 系統性地利用軌跡層級訊號（trajectory-level signals）。
2. **計算彈性**：靜態重型探針雖準確但永遠耗費高成本；靜態輕量探針雖快但對困難樣本失效。D²-Monitor 的動態路由機制（dynamic routing mechanism）首次在監控領域實現「依樣本難度動態調整計算量」。
3. **參數效率**：以 $\leq 0.85\text{M}$ 參數達到最佳 F1，顯示其極適合邊緣部署或高吞吐量服務。

**侷限與未竟之處**
儘管成果顯著，本研究仍存在若干可預見的侷限。首先，猶豫區域（hesitation region）的閾值 $\tau$ 與路由閾值 $\lambda$ 目前似為全域固定值，對於不同資料集或不同 D-LLM 架構可能需要個別調校。其次，實驗模型主要集中於 LLaDA 系列，雖具代表性，但是否能直接推廣至其他架構的 D-LLMs（例如基於不同去噪排程或離散擴散公式的模型）仍需更多驗證。此外，進階探針雖僅在必要時啟動，但對於攻擊者而言，若其輸入被設計為刻意觸發大量猶豫步驟，可能變相成為一種針對監控器本身的計算耗盡攻擊（compute exhaustion attack），此點在論文中尚未深入討論。

#### 可重現性評估

**公開資料集與模型**
本研究使用的三個資料集——WildGuardMix、ToxicChat 與 OpenAI-Moderation——均為已公開之安全性評估基準，有利於社群復現。評估對象採用的 LLaDA 系列模型（LLaDA-8B-Base、LLaDA-8B-Instruct、LLaDA-1.5、LLaDA-2.0-mini）亦為開源權重，降低了環境建置的門檻。

**程式碼與權重釋出狀況**
然而，從提供的論文片段觀察，作者並未明確提及是否釋出 D²-Monitor 的原始碼、訓練腳本或預訓練探針權重。由於本論文標註為 Preprint（預印本），完整的可重現性（reproducibility）仍取決於後續是否開源。對於一個涉及雙層級訓練流程、$K$-fold 資料策展與動態路由推論的系統而言，實作細節（如探針的確切架構、如何從隱藏狀態抽取特徵、重新遮罩策略的實作方式）對復現至關重要。若僅依賴論文描述，第三方研究者可能在重現猶豫步驟（hesitation steps）的計算邏輯與進階探針（advanced probe）的訓練資料篩選流程時遭遇歧義。

**超參數與實作透明度**
論文提及方法對超參數（hyperparameters）設定具有穩健性，但未在片段中詳列 $\tau$、$\lambda$、$K$ 值、學習率或優化器等細節。這些資訊的完整揭露將是決定本研究能否被大規模獨立驗證的關鍵。建議作者在未來版本中提供包含資料處理管線、探針架構圖與完整超參數設定的附錄，或釋出模組化實作於 GitHub 等平臺。

#### 未來研究方向

**架構擴展與通用化**
當前 D²-Monitor 主要驗證於 LLaDA 架構的 D-LLMs。未來研究可將此框架擴展至其他擴散語言模型範式，例如連續擴散（continuous diffusion）或基於分數匹配（score matching）的文本生成模型，甚至跨足多模態擴散模型（multimodal diffusion models），檢驗「猶豫」現象是否普遍存在於各類迭代生成過程。此外，針對商業化模型如 Mercury（Cohere 推出的 D-LLM），由於其權重未公開，可探索以黑箱或灰箱方式僅透過 API 暴露的中間輸出進行猶豫估計。

**自適應與學習式路由**
目前的動態路由機制依賴手工設定的餘裕閾值 $\tau$ 與猶豫閾值 $\lambda$。未來可發展端到端可微分的路由網路（differentiable routing network），讓系統在訓練階段聯合學習基礎探針、進階探針與路由決策函數，甚至引入強化學習（reinforcement learning）以直接優化「預期測試時計算量 $\times$ 錯誤率」的組合目標。另一方向是讓 $\tau$ 與 $\lambda$ 依據輸入分佈動態調整，實現樣本適應性路由（sample-adaptive routing）。

**多類別與細粒度安全性猶豫**
現有評估似乎聚焦於二元安全分類（safe/unsafe）。OpenAI-Moderation 資料集本質上包含多類別違規標籤（如仇恨、暴力、自殺等）。未來可將猶豫訊號擴展至多標籤或層級式分類，探討不同違規類型是否在去噪軌跡中產生不同模式的猶豫分佈。例如，隱晦的社會偏見可能在去噪早期呈現高猶豫，而直接的毒性語言可能在後期才顯現，這類時間解析度（temporal resolution）的細緻分析將大幅提升監控器的可解釋性（interpretability）。

**對抗 Robustness 與攻擊視角**
從攻擊者角度，可研究「反猶豫攻擊」（anti-hesitation attacks）：攻擊者是否可透過特定擾動，讓有害輸入在去噪過程中維持高餘裕（即不觸發猶豫），從而繞過 D²-Monitor 的進階探針？相對地，防禦方可發展「猶豫正規化」（hesitation regularization）技術，在訓練 D-LLM 時刻意讓有害樣本產生更明顯且難以掩飾的猶豫訊號，形成生成模型與監控器共同演化的安全賽局。

**系統整合與三層式監控**
D²-Monitor 可與現有 LLM-as-monitors 整合為三層式防禦：第一層輕量探針進行常時篩檢；第二層 D²-Monitor 的進階探針處理猶豫案例；第三層則呼叫完整 LLM 進行深度語意分析。這種「快→中→慢」的級聯架構（cascade architecture）將是生產環境中平衡延遲（latency）、成本與安全性的終極解決方案，值得在未來的系統研究中深入探討。

## 論文問答

**Q1：本文旨在解決什麼核心問題？為何擴散式大型語言模型的安全性監控特別具有挑戰性？**
A：本文聚焦於擴散式大型語言模型（D-LLMs）的安全性監控問題，這一領域在現有研究中仍屬於大幅未被探索的範疇。與自迴歸大型語言模型（AR-LLMs）不同，D-LLMs 透過多步驟去噪過程生成文本，其去噪軌跡中會暴露一系列中間隱藏表徵，這些表徵蘊含了單一步驟監控所無法取得的安全相關資訊。因此，現有針對 AR-LLMs 設計的監控方法無法直接套用，必須發展能夠善用軌跡層級訊號的新型監控架構，才能有效應對 D-LLMs 獨特的生成範式所帶來的挑戰。

**Q2：為何現有的安全性監控方法（針對自迴歸模型設計）在應用於 D-LLMs 時會顯得不足？**
A：現有的安全性監控文獻主要圍繞自迴歸模型展開，大致分為以額外大型語言模型作為監控器，或是基於內部單一步驟表徵的探針式監控。然而，D-LLMs 採用迭代式去噪生成，其安全相關的不確定性會沿著整個去噪軌跡浮現，而非僅呈現在最終輸出或單一隱藏狀態中。若僅使用傳統的單步探針或外部 LLM 監控，將會忽略中間步驟中反覆出現的猶豫訊號，導致對於困難或對抗性樣本的檢測能力不足，無法充分發揮 D-LLMs 暴露中間表徵的優勢。

**Q3：為何此時為 D-LLMs 開發專屬的安全性監控器至關重要？**
A：前沿的大型語言模型已顯著降低了惡意行為者執行有害任務的門檻，而單靠模型內部對齊技術並不足以抵禦對抗性攻擊，因此部署階段的外部監控不可或缺。與此同時，D-LLMs 如商業化的 Mercury 與開源的 LLaDA 系列已在生成速度與規模上展現出強大潛力，逐漸成為自迴歸模型的重要替代方案。若缺乏針對其多步驟生成特性設計的專屬監控機制，這些高效能模型在實際部署時將面臨嚴重的安全風險，阻礙其負責任地商業化與大規模應用。

**Q4：D²-Monitor 的核心架構為何？其主要組成元件各自扮演什麼角色？**
A：D²-Monitor 是一個針對 D-LLMs 設計的動態雙層級安全監控器，由路由器、輕量級基礎探針與高容量進階探針三個核心元件構成。基礎探針作為常時監控器，在每一個去噪步驟持續運行，同時執行基礎分類與估計軌跡的猶豫嚴重度；當偵測到的猶豫程度超過預設閾值時，路由器便會啟動進階探針進行第二階段的分類判斷。這種分工讓系統能夠在大多數簡單樣本上僅使用輕量元件，而將運算資源動態分配給真正需要深入檢視的困難樣本。

**Q5：支撐 D²-Monitor 的關鍵機制性發現是什麼？它如何促成動態路由機制的設計？**
A：作者發現了「安全性猶豫」現象，即 D-LLMs 在去噪過程中，其中間隱藏狀態會反覆落入探針決策邊界附近的小餘裕區域，形成所謂的猶豫步驟。研究進一步證實，軌跡中包含越多猶豫步驟，輕量級線性探針就越容易分類錯誤，因此猶豫嚴重度可作為樣本難度與探針失效的有效代理指標。基於此發現，D²-Monitor 得以利用猶豫訊號作為測試時的路由依據：僅當猶豫程度夠高時才呼叫重型進階探針，實現計算資源的精準投放。

**Q6：作者為何選擇雙層級架構，而非對所有樣本一律使用單一重型探針？**
A：若對每個輸入都啟動高容量探針，將在測試時產生龐大且不必要的計算開銷，抵消 D-LLMs 本身在生成效率上的優勢。雙層級設計讓輕量級基礎探針承擔常時監控與初步篩選，確保系統在面對大量簡單或良性樣本時仍保持極低延遲與記憶體佔用；只有在基礎探針對樣本感到「猶豫」時，才動態啟動進階探針進行深度判斷。這種設計讓 D²-Monitor 在僅使用不超過 0.85M 參數的緊湊規模下，同時達到頂尖效能與最佳的成本效益權衡。

**Q7：D²-Monitor 在哪些基準資料集與模型上進行了評估？**
A：實驗涵蓋了三個廣泛使用的安全性資料集，分別為 WildGuardMix、ToxicChat 與 OpenAI-Moderation，以檢驗模型在不同類型有害內容偵測上的表現。模型方面則選用了四個 D-LLMs，包括 LLaDA-8B-Base、LLaDA-8B-Instruct、LLaDA-1.5 與 LLaDA-2.0-mini，橫跨不同規模與訓練設定。評估設計同時包含資料集內測試與跨資料集測試，用以驗證方法在分布內與分布外場景的泛化能力。

**Q8：D²-Monitor 的主要實驗結果為何？與基線方法相比表現如何？**
A：D²-Monitor 在三個資料集與四個 D-LLMs 上均達到最先進的效能，且僅使用極為緊湊的參數規模（不超過 0.85M 參數，相當於 8B 模型的 0.01%）。與八個基線方法相比，D²-Monitor 在 F1 分數與預期測試時參數量的權衡圖中穩居左上角，代表它在維持高準確度的同時，顯著降低了計算成本。這些結果顯示，透過猶豫感知路由動態分配監控資源，能夠同時超越靜態輕量探針與靜態重型模型的表現。

**Q9：作者進行了哪些額外分析來驗證 D²-Monitor 的設計合理性？**
A：除了主要的準確率比較，作者還針對不同的生成配置、重新遮罩策略與超參數設定進行穩健性測試，確認 D²-Monitor 的優勢並非來自特定設定下的過擬合。分析進一步證實，猶豫嚴重度與線性探針效能之間存在強烈相關性，且猶豫步驟數量確實能有效預測探針失效的時機。跨資料集評估的結果也顯示，以猶豫訊號為基礎的路由機制具備良好的泛化性，能在未見過的資料分布上維持可靠的效能與效率權衡。

**Q10：D²-Monitor 在哪些實際部署場景中最具應用價值？**
A：D²-Monitor 特別適合需要高吞吐量且必須持續監控安全性的 D-LLM 生產環境，例如即時內容審查 API 或面向終端使用者的對話式人工智慧服務。在這些場景中，絕大多數的正常查詢可以由輕量級基礎探針快速處理，確保低延遲與流暢的使用者體驗；而當系統偵測到猶豫訊號時，則自動升級至進階探針，對潛在的對抗性輸入或邊界案例進行更嚴格的審查。這種動態機制讓服務提供商無需在安全性與營運成本之間做出二元取捨，能夠根據實際風險動態調整計算投入。

**Q11：D²-Monitor 的緊湊參數規模對產品團隊帶來哪些實務上的好處？**
A：由於整體參數量不超過 0.85M，D²-Monitor 相較於動輒數十億參數的主模型幾乎不增加額外的記憶體負擔，產品團隊可以輕易將其作為外部防護層部署於現有推論管線中。輕量級基礎探針的常時運行成本極低，有助於控制雲端運算支出，而進階探針的條件式啟動則避免了在離峰時段或面對良性流量時浪費 GPU 資源。對於需要兼顧使用者安全、回應速度與基礎設施預算的產品而言，這樣的設計提供了一個可立即落地且具成本效益的解決方案。

**Q12：這項研究可能對人工智慧安全領域與擴散式語言模型的發展產生什麼影響？**
A：本研究首次系統性地揭示了 D-LLMs 去噪軌跡中存在可解釋的安全性猶豫訊號，證明中間隱藏表徵蘊含了單步監控無法捕捉的豐富資訊，為後續的機制性研究開闢了新方向。透過展示輕量探針可根據內在猶豫程度進行動態路由，本文為超越自迴歸範式的新一代生成模型提供了一套可擴充的監控模板。這不僅有助於彌補 D-LLMs 在效率與部署安全性之間的落差，更可能加速擴散式語言模型在實務應用中的負責任採用，推動整個領域從單純的模型對齊走向更精細的測試時動態防護。

**Q13：本文承認或暗示了 D²-Monitor 的哪些限制？**
A：本文聚焦於外部安全性監控器的設計，這意味著 D²-Monitor 是對模型內部安全對齊的補充而非取代，若基礎模型本身存在嚴重偏見或漏洞，監控器僅能事後偵測而無法從根源消除風險。此外，猶豫感知路由的有效性高度依賴基礎探針的品質與校準程度，若面對與訓練時差異極大的 D-LLM 架構，猶豫訊號的分布可能改變，進而影響路由準確性。目前評估也集中於文字安全性資料集，對於多模態內容或超長上下文生成情境下的適用性，仍有待後續研究進一步驗證。

**Q14：在什麼情況下 D²-Monitor 可能失效或表現不佳？**
A：若對抗性輸入在去噪過程中刻意產生看似高信心、遠離決策邊界的中間表徵，但在最終步驟卻輸出有害內容，基礎探針可能因未偵測到足夠的猶豫步驟而未能觸發進階探針，導致漏判。反之，若閾值設定過於保守，使得大量正常樣本被誤認為具有高度猶豫，將導致進階探針被頻繁啟動，喪失動態路由帶來的效率優勢。此外，當部署環境的資料分布與訓練時的猶豫模式顯著不同時，系統可能出現過度觸發或觸發不足的問題，影響整體監控的穩定性。

**Q15：這項研究指出了哪些未來的研究方向？**
A：未來研究可將猶豫感知監控擴展至多模態擴散模型或長文件生成任務，探索不同模態與長度下的軌跡動態是否仍具類似的難度代理訊號。另一方向是設計能根據即時流量模式自動調整閾值的自適應路由策略，在安全性與效率之間取得更靈活的平衡。此外，將猶豫訊號直接整合進 D-LLMs 的去噪過程，使模型能在生成中期即進行自我修正或提前終止有害軌跡，而非僅作為外部分類依據，也是極具潛力的後續探索路徑。

## 實務應用指南

### 適用場景

1. **高頻即時內容審查服務**  
   社交媒體、即時通訊或論壇平台採用擴散式大型語言模型（D-LLM）作為對話生成核心時，需在極低延遲下持續過濾有害內容。D²-Monitor 的基礎探針僅需 ≤0.85M 參數即可常時運行，適合以邊緣運算或共享 GPU 資源部署，僅對猶豫軌跡啟動進階探針，兼顧吞吐量與安全性。

2. **企業級 D-LLM API 安全閘道**  
   針對 Mercury、LLaDA 等商業或開源 D-LLM 的對外 API，可在閘道層嵌入 D²-Monitor 作為動態安全層。基礎探針處理一般查詢，遇到對抗性輸入（adversarial prompts）或越獄攻擊（jailbreaks）導致去噪軌跡出現大量低餘裕步驟時，自動路由至進階探針進行深度檢測，避免全量啟用重型模型造成的成本激增。

3. **金融與醫療合規對話系統**  
   在需嚴格法遵的領域，D-LLM 可能因雙向注意力機制而重新權衡敏感資訊。D²-Monitor 利用軌跡層級訊號捕捉生成過程中的安全性猶豫，對於意圖模糊、可能觸發法規風險的請求（如投資建議、病症診斷）啟動第二階段審查，降低單一步驟監控的漏檢風險。

4. **邊緣裝置上的輕量 D-LLM 部署**  
   手機、車載系統或 IoT 閘道器運行輕量化 D-LLM 時，記憶體與電力預算極度受限。基礎探針的極小參數規模使其可常駐於裝置端；僅在偵測到高猶豫嚴重度時，才將軌跡特徵上傳至雲端進階探針，實現「端側常時監控、雲端按需增援」的分層架構。

5. **自動化紅隊測試與樣本難度評估**  
   安全團隊可利用猶豫步驟數（n_τ）作為樣本難度的代理指標，自動從大規模測試集中篩選出使 D-LLM 產生高度猶豫的困難案例，優先供紅隊進行人工分析，顯著提升對抗性測試的效率與覆蓋率。

### 實作前置條件

**資料需求**
- 已標註安全／不安全標籤的對話資料集，格式相容於 WildGuardMix、ToxicChat 或 OpenAI-Moderation 等基準。
- 目標 D-LLM 在多步驟去噪過程中的中間隱藏表徵（intermediate hidden states），需能按去噪步驟索引提取，形成完整去噪軌跡。

**運算需求**
- **訓練階段**：需具備足夠 VRAM 的 GPU（如 A100 / H100）以批次提取 D-LLM 各層隱藏狀態，並同時訓練基礎探針與進階探針。
- **推論階段**：基礎探針計算量極低，可於 CPU 或邊緣裝置常時運行；進階探針雖容量較大，但僅對少數高猶豫樣本啟動，整體預期參數量仍遠小於常規 LLM-as-a-Judge 方案。

**技術與技能需求**
- 熟悉 PyTorch 或 JAX，並能透過 forward hook 或模型修改提取 D-LLM 內部層級輸出。
- 具備線性探針（linear probe）與輕量分類器訓練經驗，理解決策邊界、餘裕（margin）計算與閾值調校。
- 了解 D-LLM 的重新遮罩（remasking）策略與生成配置（如擴散步數、採樣參數），因這些因素會影響去噪軌跡的穩定性。

### 實作步驟建議

**步驟一：去噪軌跡提取與特徵工程**  
對目標 D-LLM 執行前向傳播，於每個去噪步驟記錄指定層的隱藏狀態，構成軌跡序列 {h₁, ..., hₛ}。建議同時記錄對應的輸入遮罩與時間步編碼，以便後續分析。

**步驟二：訓練基礎探針與計算逐步餘裕**  
在全部訓練樣本上訓練輕量級線性基礎探針，輸入為各步驟隱藏狀態。對每個樣本計算逐步餘裕（stepwise margins）dₛ，即該步驟隱藏狀態到決策邊界的帶符號距離。

**步驟三：定義猶豫區域與標註猶豫嚴重度**  
設定餘裕閾值 τ，將 |dₛ| < τ 的步驟標記為低餘裕步驟（落入猶豫區域）。統計每條軌跡的猶豫步驟數 n_τ，作為該樣本的猶豫嚴重度與難度代理指標。

**步驟四：進階探針訓練資料策展**  
依據 n_τ 將訓練集分層，篩選出 n_τ 高於某分位數的困難樣本（猶豫軌跡）。可採 K-fold 交叉驗證避免資料洩漏，確保進階探針專注於學習基礎探針易失效的邊界案例。

**步驟五：訓練進階探針**  
在步驟四策展的猶豫樣本上，訓練高容量進階探針（如多層感知器或輕量 Transformer）。輸入可擴展為猶豫窗口（hesitation window）內的局部軌跡特徵，而非單一步驟，以捕捉時間維度的猶豫模式。

**步驟六：部署動態路由機制**  
於推論管線中整合雙層級監控器：基礎探針常時運行，即時輸出基礎分類與當前軌跡的 n_τ。設定猶豫閾值 λ，當 n_τ > λ 時，由路由模組觸發進階探針進行第二階段分類，並融合兩者結果輸出最終安全標籤。

**步驟七：系統驗證與超參數穩健性測試**  
在不同擴散步數、重新遮罩策略與溫度參數下進行壓力測試，觀察猶豫分佈是否穩定。針對延遲敏感場景，量測進階探針觸發率與端到端延遲，確保動態路由的實際效益符合預期。

### 潛在風險與注意事項

**閾值設定敏感**  
τ（猶豫區域寬度）與 λ（路由觸發門檻）對系統效能影響極大。τ 過大將使過多正常樣本被視為猶豫，導致進階探針頻繁啟動；τ 過小則可能漏掉真正困難的軌跡。建議在驗證集上針對 F1 與預期參數使用量進行帕累托最優搜尋，而非單一準則調校。

**軌跡提取的工程開銷**  
部分 D-LLM 推理框架（如某些優化過的擴散推論引擎）預設不暴露中間隱藏狀態，需自行插入 forward hook 或修改模型原始碼。此舉可能破壞現有記憶體優化（如 KV-cache 或圖編譯），需在提取完整性與生成吞吐量之間權衡。

**跨領域分佈偏移**  
論文顯示跨資料集（cross-dataset）設定下仍有良好表現，但實務上不同應用場景的猶豫模式可能差異顯著。部署至新領域時，應以少量目標領域資料重新校準基礎探針，或採用領域適應技術調整決策邊界，避免猶豫指標失效。

**對抗性繞過風險**  
攻擊者可能經由精心設計的提示，使 D-LLM 在去噪過程中壓制猶豫訊號（例如讓軌跡快速遠離決策邊界但仍生成有害內容）。D²-Monitor 應作為縱深防禦的一環，搭配輸入淨化、提示過濾與模型內部對齊，而非唯一防線。

**推論延遲抖動**  
進階探針啟動雖為少數事件，但會造成延遲峰值（latency spike）。對於需嚴格 QoS 保障的服務，建議預留非同步緩衝佇列，或採用提前觸發（look-ahead）策略：當基礎探針偵測到連續低餘裕步驟時，在猶豫嚴重度正式超標前即開始預載進階探針權重。

### 與其他技術的整合建議

**嵌入 API 閘道與中介層**  
將 D²-Monitor 實作為 D-LLM 服務前的輕量中介層（middleware）。基礎探針常駐於與生成模型共享的記憶體空間，進階探針則以 serverless 或容器化方式常駐待命，僅於路由訊號觸發時毫秒級載入，最大化資源利用率。

**搭配 LLM-as-a-Judge 形成三級管線**  
對於進階探針輸出信心值仍處於邊界（如機率接近 0.5）的案例，可進一步路由至小型裁判模型（如專用安全分類器或 Gemini Guardrails）進行三階仲裁。此架構讓 D²-Monitor 處理絕大多數明確案例，僅將極少量疑難雜症交給成本最高的裁判層。

**與模型內部對齊機制協同**  
D²-Monitor 作為外部監控器，應與模型內部的安全對齊（如 SFT、RLHF 或擴散專用的對齊技術）並行運作。當雙層級監控皆判定高風險時，可即時觸發生成中斷、重新遮罩（remasking）修正或回覆模板替換，形成「預防（對齊）＋ 偵測（監控）」的閉環。

**接入可觀測性平台**  
將每條請求的猶豫嚴重度 n_τ、基礎探針餘裕分佈與進階探針觸發率作為結構化日誌，送入 Prometheus、Grafana 或 Datadog。維運團隊可據此建立告警規則，例如當平均猶豫嚴重度在短時間內異常攀升時，推測可能遭遇新型態攻擊或模型版本漂移。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從圖一右側的效能與效率權衡圖開始，理解 D²-Monitor 的核心價值：它用極小的參數量（比主模型小數千倍）保護擴散式模型。重點掌握「安全性猶豫」的直覺——就像人說話時吞吐猶豫代表心虛，D-LLM 在去噪過程中反覆靠近決策邊界，也代表它對內容是否安全不確定。文中第 3.2 與 3.3 節的機制性發現以視覺化方式呈現，適合建立直覺。

**給 AI 工程師**  
請聚焦第 3.3 節的猶豫步驟計算方式與第 4 節的雙層級架構實作細節。實務上需特別注意如何在不破壞 D-LLM 推論優化的前提下提取多步驟隱藏狀態，以及 τ 與 λ 的聯合調校策略。論文附錄中的超參數穩健性分析與不同重新遮罩策略的比較，可直接作為生產環境調參的參考依據。

**給研究人員**  
本文的機制性發現——以探針餘裕衡量去噪軌跡的穩定性，並將猶豫嚴重度作為樣本難度的代理指標——為擴散模型可解釋性開啟了新方向。建議深入閱讀第 3 節的量化分析，思考安全性猶豫是否也存在於其他生成模態（如擴散圖像或語音），以及動態路由框架能否擴展至其他「輕量篩選＋重型驗證」的測試時運算（test-time compute）場景。

**給產品經理**  
請將閱讀重點放在摘要與第 1 節的應用動機，以及圖一的效率曲線。D²-Monitor 的商業價值在於以 ≤0.85M 參數達到最先進的 F1，顯著降低安全監控的常態性運算成本，同時保留對抗高難度攻擊的彈性。評估導入時，請對照貴司 D-LLM 服務的請求延遲 SLO 與安全合規要求，確認「基礎探針常時運行、進階探針按需付費」的成本模型是否符合預期。
