## ⚡ TL;DR

數學語句依賴在非形式論文與形式函式庫間嚴重失衡。
提出TheoremGraph，統一建構非形式與形式數學的語句級依賴圖，並以語義嵌入橋接雙方。
建構千萬級語句依賴圖，LLM驗證4.8萬筆跨形式配對，檢索效能逼近LeanSearch v2。

## 摘要翻譯

數學知識圍繞著語句及其依賴關係組織而成，但這種結構的呈現並不均勻：非形式數學（informal mathematics）論文大多僅在文件層級引用，而形式數學（formal mathematics）函式庫雖記錄細粒度依賴，卻僅涵蓋規模小得多的數學內容。我們提出 TheoremGraph，一個橫跨非形式數學與形式數學的統一語句級別依賴圖（statement-level dependency graph）。在非形式數學方面，我們從 arXiv 數學分類中解析出 1170 萬個類定理環境，並抽取出 1830 萬個候選有向依賴，每個依賴皆由提出它的抽取器標註，使下游使用者得以在覆蓋率與精確率之間取捨。在形式數學方面，我們發布 LeanGraph，一個 Lean 4 elaborator 層級的抽取器，自 25 個 Lean 專案中產生 388,105 個宣告節點與 1130 萬個具型別邊。我們將生成的自然語言簡述嵌入共享語意空間，藉此銜接兩張圖譜，並連結跨論文、跨形式與非形式分界的相關語句；LLM 評判器確認了 47,952 組餘弦相似度高於 0.8 門檻的配對，其在 ≥0.8 的整體區間接受率為 48%，而在 ≥0.9 的層級則升至 87%。在形式概念檢索上，我們以名稱與簽章表示法結合

## 深度分析

#### 方法論解析

TheoremGraph 的核心方法論在於建構一個跨足非形式數學（informal mathematics）與形式數學（formal mathematics）的統一語句級別依賴圖（statement-level dependency graph）。此系統並非單純地將兩種來源的語句各自向量化後進行語意檢索，而是先分別建立具備結構化邊（typed edges）的依賴圖，再透過自然語言標語（natural-language slogans）與共享語意空間（shared semantic space）完成跨形式橋接。

在非形式圖（Informal Graph）端，研究者從 arXiv 數學預印本中解析出 1,170 萬個類定理環境（theorem-like environments），並設計三種具備不同覆蓋率（coverage）與精確度（precision）權衡的提取器（extractor）來恢復依賴關係：
1. **Deterministic Extractor**：解析 \ref 與 \cite 指令，並將引用鍵（citation keys）對應至參考文獻清單，若引用明確指名特定定理則進一步解析至語句層級。此類邊的品質最高，經獨立 LLM judge（Kimi K2.5）驗證可達 98.8% 的精確度。
2. **Heuristic Extractor**：利用鄰近引用、反向話語線索（backward discourse cues）以及散文式指稱（如 “Theorem 3.2”）補充依賴邊，並強制限制邊的方向僅能指向文件前方（backward in document order），以降低未來資訊洩漏與虛假依賴。
3. **Notation Extractor**：採用 Qwen3-235B-A22B-Instruct-2507 識別每個語句中定義與使用的數學符號（notation），並將使用處連結至最近的前方相容定義。此提取器貢獻了 788 萬條邊，且全為文件內（within-paper）邊。

值得強調的是，每條邊都保留其提取器標籤（extractor label），使下游使用者能根據應用場景彈性調整覆蓋率與精確度的權衡（trade coverage for precision）。這種「來源可溯源」的設計在大型自動建構的知識圖譜中至關重要。

在形式圖（Formal Graph）端，本文提出 **LeanGraph**，一個基於 Lean 4 精化器（elaborator）層級的提取器。與現有工具（如 Jixia 或 Lean Atlas）不同，LeanGraph 直接透過 Lean kernel API 分類依賴關係，並以文件對齊（documentation-aligned）的節點集合過濾精化過程中的核心假影（kernel artifacts）。其邊類型（edge taxonomy）進一步細分為結構性邊（sig/extends/field）與邏輯性邊（proof/def），且具備跨 25 個 Lean 專案的多函式庫規模（multi-library scale），共產出 388,105 個宣告節點（declaration nodes）與 1,130 萬條型別邊（typed edges）。

為了橋接非形式與形式兩張圖，研究团队為形式語句生成自然語言標語（slogans），將其嵌入共享語意空間，再透過餘弦相似度（cosine similarity）與 LLM judge 的雙重過濾，建立跨形式的語句對應。具體而言，僅保留餘弦相似度不低於 0.8 門檻（floor）的配對，並由 LLM judge 從中篩選出 47,952 組 affirmed matches。此處 LLM judge 的接受率（acceptance rate）隨相似度層級顯著上升：在 >=0.8 區間僅 48%，但在 >=0.9 高階層則達 87%，顯示該語意空間具備良好的品質相關性校準（quality-correlated calibration）。

在檢索應用上，TheoremGraph 採用名稱與特徵簽章（name-and-signature representation）結合圖擴展（graph expansion）作為形式概念檢索（formal concept retrieval）的表示法。值得注意的是，此輕量級表示法在未使用語言模型重排器（LM reranker）的條件下，Recall@10 達到 0.775，僅與 LeanSearch v2 經重排後的 0.780 相差 0.5 個百分點（0.5pp），證明結構化依賴資訊本身即蘊含強大的語意判別力。

#### 實驗數據解讀

從規模層面觀察，非形式圖的 1,170 萬語句與 1,830 萬候選有向依賴邊（candidate directed dependencies）已達到文獻中罕見的量級。表 1 的提取器分工顯示：Deterministic Extractor 產出 523 萬邊，其中 192 萬為跨文件（external）邊，是外部依賴的主要來源；Heuristic Extractor 產出 647 萬邊，跨文件邊為 170 萬；Notation Extractor 則專注於文件內部，產出 788 萬邊。由於各提取器之間允許重疊（overlap），「Any」列經去重後為 1,832 萬邊。這種重疊設計意味著高置信度區域（如同時被 deterministic 與 heuristic 提取的邊）可視為更可靠的子圖。

驗證數據方面，以 500 篇抽樣論文為基準，Deterministic Extractor 的 98.8% judge-verified precision 確立了其作為黃金標準（gold-standard）近似來源的地位。然而，Heuristic 與 Notation Extractor 的個別精確度並未在提供的文本中完整揭露，這暗示它們可能以覆蓋率換取精確度，需由下游應用根據 extractor label 自行過濾。

跨形式橋接的 47,952 組 LLM-affirmed matches 在絕對數量上雖然可觀，但相對於非形式語句總量（千萬級）與形式宣告總量（數十萬級）而言，比例仍然偏低。這客觀反映了非形式數學與形式數學之間的「詞彙鴻溝」（vocabulary gap）與「語法鴻溝」依然巨大。餘弦相似度門檻與 judge 接受率的關係曲線（0.8 處 48% → 0.9 處 87%）則提供了一個可操作的品質控制機制：若應用場景要求高精度（如自動形式化驗證），可選擇 >=0.9 層級；若需廣泛探索（如文獻導覽），則可放寬至 >=0.8。

在形式概念檢索任務上，TheoremGraph 的 0.775 Recall@10 與 LeanSearch v2 的 0.780 之間僅 0.5pp 的差距，具有兩重意義。首先，它證明「名稱 + 特徵簽章 + 圖鄰域擴展」這種無需線上推論重排的輕量方案，已可逼近需要語言模型重排器的先進系統。其次，這也暗示未來若將 TheoremGraph 的結構化特徵與 LeanSearch v2 的神經重排器結合，可能進一步推升檢索上限。

#### 與現有研究的比較

在數學資訊檢索（Mathematical Information Retrieval, MathIR）領域，早期研究如 NTCIR-11 Math-2、NTCIR-12 MathIR 與 ARQMath 聚焦於公式感知（formula-aware）檢索與關鍵字匹配，強調符號佈局樹（Symbol Layout Trees）與運算子樹（Operator Trees）等結構化表示。近期工作如 zbMath-BERT、NaturalProofs 與 TheoremSearch 則轉向學習型嵌入（learned representations）。TheoremGraph 的差異化貢獻在於：它不僅檢索語句內容，更顯式地將語句間的依賴結構（explicit dependency structure）納入表示，使檢索結果具備可解釋的數學脈絡（mathematical context）。

在文獻計量學（Bibliometrics）方面，傳統引用圖（citation graphs）與影響力指標（如 h-index、Eigenfactor）僅能建模文件層級（document-level）或作者層級的關係。TheoremKB 與 AutoMathKG 雖已嘗試建構非形式來源的定理級圖譜，但規模較小且未涵蓋形式數學。TheoremGraph 首次將定理級依賴視角同時擴展至非形式 arXiv 全文與 Lean 4 形式函式庫，並提供跨形式的對齊。

在形式數學工具鏈中，Jixia（LeanSearch v2 背後的提取器）輸出原始精化後常數引用圖（raw post-elaboration constant-reference graph）；Lean Atlas 進一步區分型別層級與數值層級邊並加入信心分數（confidence scores）與可達性分析；leanblueprint 則提供作者手動標註的 \lean{} 連結。LeanGraph 的定位是互補而非取代：它透過 kernel API 進行更精細的邊分類，並以文件對齊節點集合解決核心假影問題，適合需要高品質、多函式庫圖譜的場景。

然而，本研究仍存在若干限制。首先，非形式語料僅限於 arXiv 數學預印本，未涵蓋教科書、Math Stack Exchange、維基百科（Wikipedia）或演講筆記等同樣重要的非形式來源，這可能導致領域偏差（field bias）。其次，跨文件外部依賴僅 346 萬條（其中經 deterministic 提取且驗證的僅 7.9 萬條），相對於文件內依賴（1,486 萬條）比例懸殊，顯示跨論文語句級引用解析仍是未完全解決的難題。第三，橋接機制依賴 LLM 生成標語與 LLM judge 驗證，雖然 Qwen3-235B 與 Kimi K2.5 具備強大能力，但其內部偏見與版本漂移（version drift）可能影響跨形式對齊的穩定性與可重現性。

#### 可重現性評估

TheoremGraph 在開放科學（open science）層面的承諾相當紮實：研究团队釋出了資料集（dataset）、提取器（extractors）、HTTP API 與 MCP（Model Context Protocol）介面，並託管於 HuggingFace 與 theoremsearch.com。這種多層次的釋出策略——從原始資料、工具程式到應用程式介面——大幅降低了後續研究的進入門檻。

LeanGraph 的提取流程基於 Lean 4 精化器，只要使用相同的原始碼版本與工具鏈（toolchain），其輸出具有高度確定性（deterministic），這是形式數學相較於非形式處理的固有優勢。非形式端的 Deterministic Extractor 同樣具備規則明確、可重現性高的特點。

然而，可重現性仍存在若干挑戰：
1. **專有模型依賴**：驗證階段使用 Kimi K2.5 作為 LLM judge，該模型為閉源 API，其行為可能隨供應商更新而變化，導致精確度數字（如 98.8%）在不同時間點難以完全復現。
2. **提示工程細節**：雖然 Notation Extractor 採用的 Qwen3-235B 為開放權重模型，但論文未詳細揭露標語生成（slogan generation）與 judge 評分的完整提示模板（prompt templates），這對於精確復現跨形式橋接結果構成障礙。
3. **嵌入模型與圖擴展演算法**：name-and-signature representation 的具體編碼方式、圖擴展（graph expansion）的跳數（hop count）與權重衰減機制，在提供的文本中著墨有限，可能影響檢索任務的嚴格復現。

整體而言，TheoremGraph 在資料與工具釋出上已達到領域內的高標準，但若能在後續版本中補充提示模板、嵌入模型訓練細節與圖擴展的完整超參數（hyperparameters），將進一步鞏固其作為基礎設施（infrastructure）的地位。

#### 未來研究方向

基於 TheoremGraph 的架構與釋出成果，以下幾個方向具有高度潛力：

**1. 語料擴充與多語言化**
當前非形式圖僅覆蓋 arXiv 英文預印本。未來可整合 Math Stack Exchange、zbMath 文獻評論、維基百科（Wikipedia）以及各國數學教材，建構真正全面的數學知識圖譜。多語言場景下，如何維持跨語言的語句級依賴解析與形式數學對齊，將是極具挑戰性的課題。

**2. 動態圖譜與時序分析**
數學知識具有明確的演化軌跡。mathlib4 與 arXiv 均持續增長，未來可建立版本化的動態依賴圖（versioned dynamic dependency graph），分析定理的「影響力擴散」、社群結構變遷，以及新興領域如何從既有節點衍生。這將使文獻計量學從靜態引用計數邁向動態過程建模。

**3. 雙向自動形式化（Autoformalization）**
目前的橋接主要服務「非形式 → 形式」的檢索與對齊。未來可利用已建立的 47,952 組高品質對應作為訓練資料，發展監督式自動形式化模型，將非形式語句翻譯為 Lean 4 宣告。反向地，亦可利用形式圖的結構化資訊，為非形式論文自動生成證明草圖或結構化摘要。

**4. 檢索增強推理（Retrieval-Augmented Reasoning）與智能體（Agentic Systems）**
TheoremGraph 已提供 MCP 介面，這使其天然適合成為數學智能體（mathematical agents）的外部記憶（external memory）。未來研究可探索如何讓定理證明智能體（theorem-proving agents）在證明規劃（proof planning）過程中，主動查詢依賴圖以發現可用引理（lemma retrieval），並結合形式圖的型別資訊進行子目標分解（subgoal decomposition）。

**5. 高精度外部依賴解析**
當前跨文件依賴（external dependencies）在數量上遠少於文件內依賴。未來可結合更強大的多文件語境理解模型（如長上下文 LLM 或專門的 discourse parser），提升跨論文語句級引用的解析率與精確度，從而建構更完整的數學研究網路。

**6. 因果推論與知識發現**
在擁有大規模語句級依賴圖後，可應用圖神經網路（Graph Neural Networks）或因果發現演算法，識別數學領域中的「關鍵節點」（pivotal theorems）——即那些一旦移除將大幅改變圖連通性的定理。這不僅具有知識論意義，也能為教育與研究導覽提供新的視角。

## 論文問答

**Q1：TheoremGraph 旨在解決數學知識組織中的什麼核心問題？**
A：數學知識的本質建立在離散的語句及其依賴關係之上，然而現有的非形式數學文獻（如 arXiv 論文）僅在文件層級進行引用，無法呈現語句層級的細緻結構。相對地，形式數學函式庫（如 Lean 的 mathlib4）雖然記錄了細粒度的依賴，但其涵蓋的數學範圍遠小於整體非形式文獻。TheoremGraph 旨在解決這種結構暴露不均的問題，建立一個同時覆蓋非形式與形式數學的統一語句級別依賴圖，以填補兩者之間的鴻溝。

**Q2：現有的方法為何無法有效橋接非形式與形式數學？**
A：現有的數學資訊檢索系統通常只專注於單一領域：例如 TheoremSearch 與 NaturalProofs 主要處理非形式數學的神經檢索，而 LeanSearch v2 則僅針對 Lean 形式語句進行檢索，缺乏跨領域的橋接機制。此外，傳統的文獻計量方法僅建模文件層級的引用圖，無法捕捉定理與定理之間的細緻依賴關係。這種分裂導致形式化方法難以大規模地導航或驗證當代數學研究，也限制了檢索增強推理系統同時利用兩種知識來源的能力。

**Q3：建立統一的依賴圖對於數學與人工智慧領域為何重要？**
A：建立統一的依賴圖對於數學研究與人工智慧應用至關重要，因為它能讓研究者與 AI 系統在整個數學知識體系中進行精確的語句層級搜尋與導航。這種結構化表示不僅能改善學術歸因與影響力分析，還能為自動形式化與神經定理證明提供豐富的上下文與對齊訊號。透過將非形式文獻與形式證明連結起來，TheoremGraph 有助於擴展形式化方法的覆蓋範圍，並提升大型語言模型在數學推理上的可靠性與可解釋性。

**Q4：TheoremGraph 的核心方法架構是什麼？**
A：TheoremGraph 的核心方法分為三個階段：首先針對非形式數學，從 arXiv 論文中解析出超過 1170 萬個類定理環境，並透過多種抽取器復原 1830 萬條候選依賴邊；其次針對形式數學，開發 LeanGraph 從 Lean 4 編譯專案中抽取型別化的宣告級別依賴，產生超過 38 萬個節點與 1130 萬條邊。最後，系統為形式語句生成自然語言標語（slogan），並將其與非形式語句嵌入共享的語義空間，從而在兩個圖譜之間建立跨形式性的橋接。

**Q5：跨形式性橋接的關鍵技術創新是什麼？**
A：跨形式性橋接的關鍵創新在於利用大型語言模型生成形式宣告的自然語言標語，並將這些標語與非形式論述嵌入同一語義空間進行比對。這種方法突破了傳統上僅依靠符號匹配或關鍵字檢索的限制，能夠捕捉語義層面的相似性，即使語句的表達方式與符號系統不同。此外，作者引入 LLM 評審機制對候選配對進行過濾，在餘弦相似度大於 0.8 的門檻下確認了 47,952 組高品質的（非形式, 形式）配對，確保橋接結果的可靠性。

**Q6：為何作者選擇為非形式依賴設計多個抽取器並保留標籤，而非使用單一抽取器？**
A：作者選擇為非形式依賴設計多個抽取器並保留標籤，是因為單一抽取器難以同時滿足覆蓋率與精確率的需求。決定性抽取器雖然能達到 98.8% 的評審驗證精確率，但僅能產生約 523 萬條邊；啟發式與符號抽取器則能大幅提升覆蓋範圍，但可能引入較多雜訊。透過為每條邊標註其來源抽取器，下游使用者可以根據應用場景彈性調整覆蓋率與精確率的權衡，例如在需要高確信度的推理任務中僅使用決定性邊，而在探索式搜尋中納入更多候選。

**Q7：作者使用了哪些評估設定與基準來驗證 TheoremGraph？**
A：在非形式圖譜的驗證方面，作者從抽取的論文中取樣 500 篇，使用 Kimi K2.5 作為獨立的 LLM 評審，先自行提出語句內依賴再驗證抽取器遺漏的邊，以評估整體管線的品質。在形式檢索的評估上，則將 TheoremGraph 的名稱與特徵表示結合圖擴展的檢索結果，與 LeanSearch v2 重新排序後的 Recall@10 進行比較。跨形式性橋接的評估則採用 LLM 評審接受率作為指標，分析不同餘弦相似度區間（如 ≥0.8 與 ≥0.9）內配對品質的變化。

**Q8：本研究報告了哪些最重要的量化成果？**
A：本研究最重要的量化成果包括：非形式圖譜涵蓋 1170 萬個語句與 1830 萬條有向依賴邊；形式圖譜 LeanGraph 涵蓋 388,105 個宣告節點與 1130 萬條型別化邊。在跨形式性對齊方面，系統在餘弦相似度大於 0.8 的門檻下獲得 LLM 評審確認的 47,952 組配對，且評審接受率從 0.8 門檻的 48% 提升至 0.9 以上區間的 87%。在形式概念檢索任務中，僅靠名稱與特徵表示加上圖擴展，Recall@10 達到 0.775，與 LeanSearch v2 重新排序後的 0.780 僅差距 0.5 個百分點，且無需語言模型重新排序器。

**Q9：不同的設計選擇與抽取器如何影響整體表現？**
A：不同抽取器的組合顯著影響了非形式依賴圖的規模與品質：單獨使用決定性抽取器雖然精確率極高，但僅能覆蓋部分語句內引用；加入啟發式與符號抽取器後，總邊數從 523 萬擴增至 1832 萬，大幅提升了外部跨文件與符號使用的覆蓋。在形式檢索方面，圖擴展與名稱–特徵表示的設計證明即使不依賴昂貴的語言模型重新排序，也能達到接近最先進系統的表現。跨形式性橋接的分析則顯示，提高餘弦相似度門檻能有效篩選出更高品質的配對，顯示語義相似度與 LLM 評審判斷之間存在強烈正相關。

**Q10：TheoremGraph 的主要實務應用場景有哪些？**
A：TheoremGraph 的主要實務應用包括建立橫跨非形式論文與形式函式庫的統一數學搜尋引擎，使研究者能透過語句層級查詢快速定位相關定理與證明。它也能作為檢索增強生成系統的知識基礎，讓大型語言模型在進行數學推理時能夠引用結構化的依賴脈絡，減少幻覺並提升可驗證性。此外，語句層級的歸因功能有助於學術影響力分析與知識溯源，超越傳統僅以論文為單位的引用計量。

**Q11：為了支援實際應用，作者釋出了哪些基礎設施與產品化考量？**
A：為了支援真實世界的使用，作者釋出了完整的資料集、抽取工具、HTTP API 以及 MCP 介面，讓使用者、應用程式與 AI 代理程式能夠直接查詢依賴資料。這些基礎設施降低了學術界與開發者重現與擴展此工作的門檻，並支援即時的程式化存取。所有資源均可透過 theoremsearch.com 與 Hugging Face 平台取得，確保了資料的可近性與社群的協作潛力。

**Q12：TheoremGraph 可能對相關領域產生什麼樣的深遠影響？**
A：TheoremGraph 可能對數學資訊檢索與自動推理領域產生深遠影響，因為它首次在大規模上實現了非形式與形式數學的語句級別統一表示。這種表示不僅超越了傳統文件層級的文獻計量圖，也彌補了孤立形式函式庫的覆蓋不足，為跨領域研究提供了新的基礎設施。透過釋出公開資料與 API，本研究有望加速自動形式化、神經定理證明與數學知識圖譜的後續發展，並促進形式化方法在當代數學研究中的大規模應用。

**Q13：作者承認了哪些系統層面的限制？**
A：作者坦承目前的形式覆蓋範圍仍受限於 Lean 4 生態系，尚未納入 Coq、Isabelle 或其他證明輔助器的函式庫，這限制了跨形式語言的通用性。非形式依賴抽取雖然規模龐大，但許多邊仍屬候選性質，需要下游使用者根據抽取器標籤進行過濾，且跨論文的外部邊相對稀疏。此外，跨形式性橋接依賴 LLM 生成的標語與自動評審，這些過程可能引入模型偏誤或語義理解上的錯誤，尤其在處理高度抽象或新興領域的數學概念時。

**Q14：在提出的管線中，可能出現哪些類型的失敗案例或錯誤？**
A：管線中可能出現的失敗案例包括：啟發式抽取器因為歧義的篇章線索而錯誤地將後文語句標記為前文語句的依賴，即使兩者僅為例證或對比關係。符號抽取器在面對多個相容或近似的符號定義時，可能將符號使用錯誤連結到不符合當前語境的定義，導致語義偏差。在跨形式性橋接方面，若形式語句與非形式語句在表面語言上相似但數學內涵不同，LLM 評審可能無法完全排除這類偽陽性配對，特別是在餘弦相似度處於中間區間時。

**Q15：作者暗示了哪些未來的研究方向？**
A：作者暗示的未來方向包括將形式圖譜擴展至 Lean 以外的證明輔助器，例如 Coq 與 Isabelle，以建構真正跨語言的數學知識圖譜。另一個方向是透過更強大的嵌入模型或引入人工驗證機制，進一步提升跨論文與跨形式性連結的精確率，減少對 LLM 自動評審的依賴。最終，將 TheoremGraph 深度整合到互動式定理證明器與 AI 代理程式的推理迴路中，實現即時的檢索增強證明，將是推動自動化數學推理邁向實用化的重要下一步。

## 實務應用指南

### 適用場景

1. **學術文獻溯源與歸因**：追蹤特定定理在非形式 arXiv 論文與形式化 mathlib4 函式庫之間的傳播路徑，解決「此引理最早出現於哪篇文獻」或「該形式定義對應哪句非形式敘述」的精細歸因需求。
2. **形式化證明的檢索增強生成（RAG）**：在 Lean 4 證明過程中，透過 MCP 介面即時檢索相關非形式數學直觀（slogan）與依賴定理，降低證明工程師在龐大函式庫中的認知負荷。
3. **數學教育與互動式知識導航**：建構語句級定理網路，讓學生從本科教材定理出發，沿著依賴邊探索前沿論文或對應的 Lean 形式化定義，視覺化理解「證明這一步需要哪些前置知識」。
4. **自動化形式化（Autoformalization）管線**：在將 arXiv 論文轉譯為 Lean 4 時，先透過 TheoremGraph 對齊已形式化的語句，避免重複勞動並確保命名與結構一致性。
5. **跨領域數學發現**：利用 slogan embedding 的共享語義空間，發現代數、拓撲、分析等不同領域之間潛在的定理類比或推廣關係。

### 實作前置條件

- **資料**：需能存取 arXiv LaTeX 源碼（Kaggle 快照）與目標 Lean 4 專案之完整編譯環境；若使用現成服務，則需申請 theoremsearch.com API 金鑰。
- **運算**：自建管線時，非形式端須 GPU 執行 Qwen3-235B-A22B-Instruct（或同等級 LLM）進行 notation extraction 與 slogan 生成；形式端建議 32 GB 以上 RAM 以編譯 mathlib4，並預留儲存空間存放 11.7 M 語句與 18.3 M 邊之中間結果。
- **技能**：團隊需熟悉 Python（處理依賴圖與 API）、Lean 4 語法與 elaborator 架構（調整 LeanGraph）、以及圖資料庫（如 Neo4j）或向量資料庫（如 Milvus、Weaviate）操作。
- **基礎建設**：需部署 LLM-as-a-judge（如 Kimi K2.5 或同等級模型）以支援跨形式橋接驗證，並建立 HNSW 索引加速 slogan embedding 的近似最近鄰搜尋。

### 實作步驟建議

1. **環境建置與資料取得**：從 Hugging Face 下載 `uw-math-ai/theorem-matching` 資料集，或透過 arXiv Kaggle 快照與 mathlib4 git 倉儲建立本地語料；安裝 Lean 4 toolchain 與 LeanGraph elaborator plugin。
2. **非形式依賴抽取**：對 arXiv LaTeX 執行 regex-based statement parser，依序運行 deterministic、heuristic、notation 三組 extractor，產生帶標籤的候選邊；建議先以 deterministic 邊（98.8% judge-verified precision）建立高信心基線圖，再視需求疊加 heuristic 與 notation 邊。
3. **形式依賴抽取**：編譯目標 Lean 專案，掛載 LeanGraph 攔截 kernel API 呼叫，輸出 388K+ declaration-level 節點與 sig/extends/field/proof/def 分類邊；過濾 kernel artifacts 並對齊文件註釋節點。
4. **跨形式橋接**：為非形式語句與 Lean declaration 分別生成自然語言 slogan，透過共享 embedding 模型投射至同一語義空間；設定 cosine similarity >= 0.9 門檻並以 LLM judge 過濾，取得高品質（87% 接受率）匹配對。
5. **圖整合與索引**：將非形式圖、形式圖、跨形式匹配邊匯入統一圖資料庫；對 slogan embedding 建立 HNSW 索引，對 declaration 建立 name-and-signature 索引以支援 graph expansion 檢索。
6. **產品化介面**：封裝 HTTP API 與 MCP（Model Context Protocol）介面，讓外部 AI agent、編輯器插件或學術搜尋前端可查詢語句級依賴與檢索相關定理。

### 潛在風險與注意事項

- **覆蓋率與精確度的權衡**：heuristic 與 notation extractor 雖提升覆蓋率，但可能引入偽依賴邊；生產環境應根據應用場景動態調整 extractor 權重，例如自動形式化管線優先使用 deterministic 邊，探索式搜尋可放寬至 any。
- **LLM judge 的偏差與成本**：跨形式橋接依賴 LLM judge，其 48%–87% 的接受率區間意味著高門檻設定會遺漏真實匹配，低門檻則帶來噪音；建議採用人機協同驗證迴圈，並監控 judge 在不同數學領域的一致性。
- **形式端編譯脆弱性**：LeanGraph 需在 elaboration 階段攔截，任何 mathlib4 版本升級或 breaking change 都可能導致 extractor 失效；應將 extractor 與特定 Lean toolchain 版本鎖定，並建立 CI 回歸測試。
- **版權與授權**：arXiv 論文與 mathlib4 分屬不同授權條款，商用時需確認 LaTeX 源碼與 Lean declaration 的再散布與衍生利用限制；API 回傳內容應明確標示來源與 extractor 信心標籤。
- **語義漂移**：slogan embedding 對高度專業或新興領域的術語可能表現不佳，需持續以領域語料微調 embedding 模型，避免檢索結果偏向通用數學詞彙。

### 與其他技術的整合建議

- **證明輔助器與 IDE**：將 TheoremGraph MCP 介面整合至 VS Code 或 Neovim 的 Lean 4 插件，使證明工程師在撰寫 proof 時能一鍵檢索相關非形式直觀與 mathlib4 宣告；可與 LeanSearch v2 互補，以其重排序模型進行第二階段精排。
- **LLM Agent 與自動形式化**：在自駕式形式化管線中，將 TheoremGraph 作為工具提供給 ReAct 或 CodeAct 架構的 agent，讓模型在產生 Lean 程式碼前查詢已存在語句，減少重複定義與命名衝突。
- **學術搜尋引擎**：對接 Semantic Scholar 或 OpenAlex API，將論文級引用圖細化為語句級依賴圖；可將 TheoremGraph 的邊權重納入 PageRank 變體，計算定理影響力分數。
- **企業知識庫**：對於擁有內部數學模型（如量化金融、密碼學證明）的組織，可仿照 LeanGraph 建立私有形式依賴圖，並透過 slogan embedding 與公開 TheoremGraph 對齊，實現內外部知識的語義聯邦搜尋。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從「適用場景」與「與其他技術的整合建議」兩節入手，先理解 TheoremGraph 能解決什麼問題（例如「找定理」或「看懂證明需要哪些前置知識」），再透過 theoremsearch.com 的公開 API 實際查詢幾個熟悉的數學定理，建立直觀感受後再回頭閱讀技術細節。
- **AI 工程師**：重點閱讀第 3、4 節（Informal Graph、Formal Graph）與跨形式橋接方法，關注 extractor 的標籤機制與 LLM judge 的過濾邏輯；實作時可直接採用 Hugging Face 釋出的資料集與現成 API，將心力放在如何將 name-and-signature + graph expansion 檢索模式嵌入你的 RAG 管線。
- **研究人員**：深入分析 LeanGraph 的 elaborator-level 邊分類（sig/extends/field vs. proof/def）與 slogan embedding 的共享語義空間設計，這兩者是本文相較於 Jixia、Lean Atlas 等前作的理論貢獻；建議進一步探討 cosine similarity 門檻與 LLM judge 接受率之間的 Pareto 前沿，以及在不同數學分支上的泛化性。
- **產品經理**：聚焦「適用場景」與「潛在風險與注意事項」，評估將 TheoremGraph 整合至學術出版、教育科技或企業研發流程的商業價值與法務風險；特別注意 extractor 信心標籤對使用者體驗的影響，以及 LLM judge 成本對規模化服務的經濟性衝擊。
