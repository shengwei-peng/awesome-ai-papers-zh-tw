## ⚡ TL;DR

訓練電腦使用代理在真實環境中成本高且具風險，現有合成方法多僅支援單一介面並依賴專有模型。
WildAWM以開源模型合成支援GUI、CLI、MCP的可執行電腦環境，用閘門確保任務可解且具挑戰。
合成341個長時程任務，GPT-6-Astra僅解決60%，訓練Qwen在8個分布外基準大幅提升。

## 摘要翻譯

代理學習正從基於人類資料的學習，轉向透過與世界互動來學習。然而，直接在真實世界的電腦系統中規模化此類學習具有挑戰性，並可能帶來重大的安全風險。因此，我們提出野外代理世界模型 (Agent World Model in the Wild, WildAWM)，這是一個可擴展的流程，用於合成可控環境與任務，以訓練通用電腦使用代理 (Computer-Use Agent, CUA)。現有方法通常專注於單一代理互動介面，而我們建構的可執行環境同時支援圖形使用者介面 (Graphical User Interface, GUI)、模型上下文協定 (Model Context Protocol, MCP) 服務與命令列介面 (Command-Line Interface, CLI)，使代理能夠靈活地結合視覺互動、工具使用與程式碼執行。WildAWM 完全由開源模型驅動，證明了無需專有前沿模型即可生成高品質的電腦使用環境。除了環境之外，我們透過引入基於執行的品質閘門 (Quality Gate)，結合異質代理推演 (Heterogeneous Agent Rollout)、跨評判一致性檢查 (Cross-Judge Consistency Check) 與評判穩健性 (Judgment Robustness) 的反事實探測 (Counterfactual Probe)，來解決任務合成中三個反覆出現的挑戰：確保可解性 (Solvability)、維持足夠的難度，以及產生可靠的驗證器 (Verifier)。此流程合成了 341 個長時程 (Long-Horizon) 環境-任務配對 (Environment-Task Pair)，這些配對可能需要超過 100 個代理步驟才能解決，且即使對前沿模型 (Frontier Model) 而言仍具挑戰性，其中 GPT-6-Astra 僅解決了 60%。我們僅在這些合成世界中訓練了兩個不同規模的 Qwen 模型。兩個模型在橫跨網頁 (Web)、Claw 與電腦使用代理的 8 個分布外 (Out-of-Distribution, OOD) 基準測試 (Benchmark) 中均取得了顯著的提升，顯示在 WildAWM 合成世界中的學習能夠廣泛地泛化至未見的電腦使用任務。程式碼已公開於 https://github.com/MSR-Orchard/WildAWM。

### 核心貢獻（3～5點）
- 提出 WildAWM，一個可擴展的環境-任務合成流程，能同時支援 GUI、MCP 與 CLI 三種代理互動介面，使代理可靈活結合視覺互動、工具使用與程式碼執行。
- 引入基於執行的品質閘門機制，結合異質代理推演、跨評判一致性檢查與反事實探測，系統性地解決任務合成中的可解性、難度與驗證器可靠性三大挑戰。
- 證明完全使用開源模型即可生成高品質的電腦使用環境，無需依賴專有前沿模型。
- 合成 341 個長時程環境-任務配對（部分需超過 100 步），即使前沿模型 GPT-6-Astra 也僅能解決 60%，凸顯任務的挑戰性。
- 在 WildAWM 合成世界中訓練的 Qwen 模型，於 8 個分布外基準測試（涵蓋網頁、Claw 與電腦使用代理）均取得顯著提升，展現優異的泛化能力。

### 適合對象
本論文特別適合以下讀者閱讀：從事電腦使用代理 (Computer-Use Agent)、強化學習 (Reinforcement Learning)、世界模型 (World Model)、合成資料生成與代理基準測試 (Benchmark) 研究的學者與工程師；對 GUI 代理、網頁代理與工具使用代理之訓練環境建構感興趣的 AI 研究人員；以及尋求可擴展、安全且可控之代理訓練基礎設施的業界實務工作者。

## 深度分析

#### 方法論解析

WildAWM（野外代理世界模型）的核心方法論建立在「代理學習正從人類示範轉向與世界互動」這一範式轉移之上，試圖解決在真實電腦系統中直接進行強化學習（RL）所面臨的成本與安全風險問題。其方法論架構可從以下幾個層面深入剖析：

**1. 跨介面統一環境建構**

WildAWM 最關鍵的設計理念是將電腦使用代理（CUA）視為一個跨越圖形使用者介面（GUI）、模型上下文協定（MCP）服務、以及命令列介面（CLI）的統一操作空間。這與現有方法僅專注於單一介面（如純瀏覽器、純工具呼叫、或純終端工作流）形成鮮明對比。具體而言，WildAWM 從使用者角色（persona）與日常活動出發，建構可執行的個人電腦（PC）環境，其中網站、應用程式、MCP 服務與本地檔案共存於同一可執行環境中。這種設計反映了真實電腦使用任務的特徵——任務的定義基於「能完成什麼」而非「透過什麼介面完成」。

**2. 從零開始與基於種子的混合合成策略**

WildAWM 採用「從零開始（From-Scratch）+ 基於種子（Seed-Grounded）」的混合合成來源。從零開始部分允許生成全新的應用程式與環境狀態，而基於種子部分（特別是利用 WebHarbor 的網站作為 GUI 底層與影像內容來源）則提供了視覺真實性與結構合理性。這種混合策略在可控性與真實性之間取得了平衡，避免了純從零開始可能產生的視覺簡化問題，也避免了純基於參考可能帶來的版權與多樣性限制。

**3. 執行式多代理品質閘門（Execution-Based Multi-Agent Quality Gates）**

這是 WildAWM 在任務合成方面的核心創新。針對任務合成中三個反覆出現的挑戰——可解性（solvability）、足夠難度（sufficient difficulty）、以及可靠驗證器（reliable verifier）——WildAWM 引入了基於執行的品質閘門機制：

- **異質代理推演（Heterogeneous Agent Rollouts）**：使用來自不同模型與不同執行框架（harness）的代理來執行每個任務，提供可解性的多重證據。若所有代理都無法解決，則任務可能不可解；若所有代理都能輕易解決，則任務難度不足。
- **跨評判一致性檢查（Cross-Judge Consistency Check）**：透過多個評判模型對任務完成狀態進行獨立判斷，檢驗評判之間的一致性，避免依賴單一前沿模型作為「必然正確」的評判者。
- **反事實探測（Counterfactual Probes）**：利用 LLM 的「諂媚性（sycophancy）」傾向，刻意提供錯誤的結果回饋來測試驗證器的穩健性。若驗證器在錯誤回饋下仍能正確判斷任務失敗，則證明其具有真正的判斷能力而非僅僅順應表面敘述。

**4. 開放源模型驅動的合成流程**

WildAWM 整個合成流程完全由開放源模型驅動，這在現有工作中是獨特的。對比表中顯示，其他方法如 AWM、WebArena-Infinity、Gym-Anything、TMax、Synth. Computers、CUA-Gym、CUA-Universe 等均依賴 GPT-5、Opus 4.5/4.6、Sonnet 4.6、Gemini-3-Pro 等專有模型。WildAWM 的這一設計不僅提升了可重現性與透明度，也證明了高品質電腦使用環境的合成並非前沿專有模型的專利。

**5. 跨代理介面（XAI）任務生成**

WildAWM 生成的任務被稱為「跨代理介面任務」，這意味著每個任務至少需要三種介面類型的協同使用。這種設計迫使代理學習介面選擇（interface selection）與介面協調（interface coordination）能力，而非僅僅精通單一操作模式。

#### 實驗數據解讀

**1. 合成規模與任務特性**

WildAWM 最終合成了 341 個環境-任務配對（environment-task pairs），每個配對至少需要三種介面類型，且工作流屬於長時程（long-horizon）性質，可能需要超過 100 個代理步驟才能完成。這一規模雖然相對有限，但考慮到每個任務的複雜度與品質要求，實際上是相當可觀的成果。

**2. 前沿模型表現的基準意義**

GPT-6-Astra 僅能解決約 60% 的合成任務，這一數據具有重要的基準意義。它表明：
- WildAWM 生成的任務確實具有足夠的難度，不會因為過於簡單而失去訓練價值；
- 即使是最前沿的模型，在跨介面、長時程的真實電腦使用任務上仍有顯著的能力缺口；
- 60% 的解決率為後續研究提供了清晰的改進空間與評估基準。

**3. 訓練後的泛化表現**

實驗在兩個 Qwen 模型上進行了純粹在 WildAWM 合成世界中訓練的實驗：
- Qwen3.6-35B-A3B（較大模型）
- Qwen3.5-4B（較小模型）

兩者均使用 OpenCode CLI 執行框架（配備 GUI 與 MCP 工具）進行線上強化學習。關鍵發現是：兩個模型在 8 個分布外（OOD）基準測試上均取得了實質性提升，這些基準測試橫跨網頁（web）、claw、以及電腦使用代理三大類別。這一結果強烈支持了「在合成世界中學習能夠泛化到未見的真實電腦使用任務」的核心假設。

**4. 訓練框架的選擇意義**

選擇 OpenCode CLI 框架（而非純 GUI 框架）作為訓練環境具有方法論意義：它使得代理必須學習在程式碼執行環境中呼叫 GUI 與 MCP 工具，這更接近真實的電腦使用場景，也更能體現 WildAWM 跨介面設計的價值。

**5. 數據解讀的注意事項**

需要注意的是，論文中未提供具體的基準測試數值表格（從提供的文本片段來看），因此無法對各基準測試的具體提升幅度進行精確分析。此外，341 個任務對於大規模 RL 訓練而言規模偏小，這可能限制了訓練效果的進一步提升空間。

#### 與現有研究的比較

**1. 介面覆蓋面的全面性優勢**

從對比表來看，WildAWM 是唯一同時支援 GUI、MCP 與 CLI 三種介面的方法，且目標代理類型為 OpenCode（編碼代理）。其他方法的介面覆蓋情況如下：
- AWM、WebArena-Infinity、Gym-Anything、CUA-Gym：僅 GUI
- TMax、Synth. Computers：僅 CLI
- CUA-Universe：GUI + CLI（但缺少 MCP）

WildAWM 的三介面覆蓋反映了其對「真實電腦使用任務」更全面的理解——現代電腦使用場景中，純 GUI 操作已不足以應對複雜任務，必須結合程式化操作與外部工具服務。

**2. 環境範圍的擴展**

WildAWM 將環境範圍從「單一應用（Single App）」或「多應用（Multi App）」擴展到「個人電腦（PC）」層級。這意味著任務可以在同一環境中跨越網站、桌面應用、本地檔案系統與 MCP 服務，這更接近真實使用者的數位工作空間。

**3. 模態支援的完整性**

WildAWM 同時支援文字與影像模態（Text+Image），這對於 GUI 代理至關重要，因為許多視覺資訊無法僅從文字（如 HTML 或無障礙樹）推斷。相較之下，AWM、WebArena-Infinity、TMax、Synth. Computers、CUA-Gym 等僅支援文字模態。

**4. 開放源模型的差異化定位**

WildAWM 是對比表中唯一使用開放源模型進行合成的方法。這一差異化定位帶來多重優勢：
- 可重現性：任何研究者都可以重複整個合成流程
- 透明度：合成過程中的每一步都可審查
- 可訪問性：降低了研究門檻，無需依賴昂貴的 API 存取
- 知識產權：避免了使用專有模型可能帶來的內容爭議

**5. 現有方法的侷限性**

WildAWM 在論文中明確指出了現有方法的侷限：
- 現有方法通常合成視覺簡化的應用程式
- 現有方法將每個應用程式建構為孤立環境
- 現有方法難以處理跨介面協調問題
- 現有方法在任務驗證上常依賴「前沿模型必然正確」的簡化假設

**6. WildAWM 的潛在限制**

儘管 WildAWM 有諸多優勢，仍存在一些潛在限制：
- 合成規模（341 個任務）相對有限，可能不足以支撐大規模 RL 訓練
- 開放源模型的合成品質上限可能低於前沿專有模型
- 環境的視覺真實性仍依賴 WebHarbor 等種子來源
- 品質閘門的計算成本可能較高（需要多代理推演與多評判檢查）

#### 可重現性評估

**1. 程式碼公開性**

WildAWM 的程式碼已在 GitHub 公開（https://github.com/MSR-Orchard/WildAWM），這為可重現性提供了基礎設施保障。研究者可以存取完整的合成流程程式碼，進行獨立驗證與改進。

**2. 開放源模型的全面使用**

整個合成流程使用開放源模型，這是可重現性的關鍵優勢。相較於依賴專有模型的方法，WildAWM 不會受到 API 變更、模型下架、或存取限制的影響。研究者可以使用相同的開放源模型重現實驗結果。

**3. 環境與任務資料的釋出**

論文提及釋出了 341 個環境-任務配對，這些資料可以直接用於訓練與評估。然而，從提供的文本中無法確認是否同時釋出了：
- 環境的可執行映像或配置檔案
- 任務的完整描述與驗證器程式碼
- 訓練資料的具體格式與結構

**4. 訓練細節的可重現性**

實驗使用了 Qwen3.6-35B-A3B 與 Qwen3.5-4B 兩個模型，這些模型本身是公開的。訓練框架 OpenCode CLI 也是開源的（anomalyco, 2025）。然而，完整的訓練超參數、獎勵設計、以及 RL 演算法細節對於完全重現實驗結果至關重要，這些資訊在提供的文本片段中未充分展示。

**5. 評估的可重現性**

8 個 OOD 基準測試橫跨網頁、claw 與電腦使用代理類別，但具體的基準測試名稱、評估協議、以及評測環境配置在提供的文本中未明確列出。完整的評估細節對於結果的可重現性同樣重要。

**6. 可重現性評估總結**

整體而言，WildAWM 在可重現性方面表現優於多數現有方法，特別是在合成流程的開放性方面。然而，要達到完全可重現，仍需要更詳細的訓練細節、評估協議、以及資料格式說明。

#### 未來研究方向

**1. 合成規模的擴展**

當前的 341 個環境-任務配對規模有限，未來可以探索：
- 自動化程度更高的合成流程，以降低每個任務的生成成本
- 利用課程學習（curriculum learning）策略，從簡單任務逐步擴展到複雜任務
- 結合自適應採樣，根據代理的能力缺口動態生成對應難度的任務

**2. 環境真實性的提升**

WildAWM 的環境仍依賴 WebHarbor 等種子來源，未來可以探索：
- 從真實使用者工作流中提取環境模板
- 整合更多類型的應用程式與服務
- 提升環境的視覺真實性與互動真實性

**3. 驗證器設計的深化**

雖然 WildAWM 引入了反事實探測等創新機制，但驗證器的設計仍有改進空間：
- 探索更細粒度的部分成功評估
- 結合程序性驗證（procedural verification）與結果驗證
- 研究驗證器對抗攻擊的穩健性

**4. 跨介面學習理論的建立**

WildAWM 展示了跨介面任務的可行性，但缺乏對介面選擇與協調策略的理論分析。未來可以：
- 分析不同介面組合的效率差異
- 研究代理如何學習介面選擇策略
- 建立介面使用的形式化模型

**5. 安全性與風險控制**

雖然 WildAWM 解決了在真實環境中訓練的安全問題，但合成環境本身可能引入新的風險：
- 研究合成環境中的偏見傳播
- 探索環境污染（environment contamination）的檢測方法
- 建立合成環境的安全審計框架

**6. 多模態與多代理擴展**

未來可以將 WildAWM 擴展到：
- 音訊、視訊等多模態介面
- 多代理協作場景
- 人機協作環境

**7. 遷移學習與元學習**

WildAWM 展示了在合成世界中學習能泛化到真實任務，但泛化的機制尚不清楚。未來可以：
- 分析合成世界與真實世界之間的領域差距
- 研究元學習如何加速跨領域遷移
- 探索預訓練-微調的新範式

**8. 開放源模型的持續改進**

WildAWM 證明了開放源模型可以驅動高品質合成，但開放源模型的能力仍有提升空間。未來可以：
- 專門針對環境合成任務訓練開放源模型
- 建立合成品質的標準化評估
- 推動開放源模型在代理研究中的更廣泛應用

**9. 與人類工作流的對齊**

WildAWM 從使用者角色與日常活動出發，但這些活動的來源與代表性需要進一步研究。未來可以：
- 從真實使用者行為日誌中提取活動模式
- 研究不同職業、文化、年齡群體的電腦使用差異
- 建立更具代表性的使用者角色庫

## 論文問答

**Q1：為什麼訓練電腦使用代理（CUA）需要合成環境，而不是直接在真實世界的電腦系統中學習？**
A：在真實世界的電腦系統中直接進行強化學習面臨多重挑戰。首先，環境狀態難以重置，代理的一次探索性動作可能產生不可逆的後果，例如誤刪檔案或發送錯誤訊息。其次，線上服務會隨時間變化，導致訓練環境不穩定。此外，真實系統中的探索行為可能帶來嚴重的安全風險，例如 OpenAI 近期就曾發布過真實世界強化學習的事件報告。因此，合成可控、可重置的環境成為訓練通用電腦使用代理的必要前提。

**Q2：現有的環境合成方法有哪些不足之處？**
A：現有方法通常只專注於單一代理互動介面，例如僅支援瀏覽器操作、工具呼叫或終端機工作流，無法反映真實電腦使用中跨介面協作的需求。此外，許多方法傾向合成視覺上過於簡化的應用程式，並將每個應用程式建構為獨立的環境，忽略了真實電腦使用中網站、應用程式、MCP 服務與本地檔案共存於同一可執行個人電腦環境的特點。更關鍵的是，現有方法在任務合成時往往難以同時保證可解性、足夠的難度與可靠的驗證器，且多半依賴專有前沿模型，限制了可重現性與可及性。

**Q3：為什麼電腦使用代理的訓練特別具有挑戰性與重要性？**
A：電腦使用代理代表了一個極為廣泛的環境合成場景，因為單一任務可能需要透過 GUI 互動、CLI 操作或 MCP 伺服器呼叫來完成，介面選擇與協調成為關鍵能力。真實的電腦使用任務橫跨應用程式、網站與本地檔案，定義任務的是「能完成什麼」而非「使用哪種互動模態」。這種跨介面的特性使得環境合成必須涵蓋整個連貫的數位工作空間，而非孤立的單一應用程式，從而對合成管線的可擴展性與品質控制提出了更高要求。

**Q4：WildAWM 的核心方法是什麼？**
A：WildAWM 是一個可擴展的合成流程，從使用者角色（persona）與日常活動出發，自動建構包含網站、MCP 服務與本地檔案的可執行個人電腦環境，並在這些世界中合成跨代理介面（XAI）任務。其核心在於引入了基於執行的多代理品質閘門：由來自不同模型與執行框架的異質代理執行每個任務，以提供可解性、難度與評判一致性的證據。最終，該流程產生了 341 個長時程的環境-任務配對，每個任務至少需要三種介面類型，且可能需要超過 100 個代理步驟才能完成。

**Q5：WildAWM 的關鍵創新點有哪些？**
A：WildAWM 的關鍵創新在於三個層面：第一，它聯合支援 GUI、MCP 與 CLI 三種介面，讓代理能靈活組合視覺互動、工具使用與程式碼執行；第二，它提出了基於執行的品質閘門，結合異質代理推演、跨評判一致性檢查，以及利用 LLM 逢迎傾向（sycophancy）的反事實探測來測試驗證器的穩健性；第三，整個流程完全由開源模型驅動，證明了無需依賴專有前沿模型也能合成高品質的電腦使用環境，大幅提升了可重現性與透明度。

**Q6：WildAWM 在設計上有哪些重要的選擇？**
A：在合成來源上，WildAWM 採用「從零開始」與「基於種子」相結合的策略，既能從使用者角色生成全新環境，也能利用如 WebHarbor 等來源的種子 GUI 底層與影像內容。在目標代理方面，WildAWM 選擇 OpenCode CLI 執行框架並配備 GUI 與 MCP 工具，使代理能夠存取所有介面。此外，作者刻意選擇全程使用開源模型進行合成，這不僅是技術上的展示，也是一種設計哲學的宣示——開源模型足以勝任高品質環境合成的任務。

**Q7：WildAWM 使用了哪些基準測試來評估泛化能力？**
A：WildAWM 在 8 個分布外（OOD）基準測試上評估了訓練後的代理，這些基準涵蓋了網頁代理、claw 代理與電腦使用代理三大類別。這種跨多個領域的評估設計是為了驗證「在合成世界中學習是否能泛化到未見的真實電腦使用任務」。由於訓練完全在 WildAWM 合成的世界中進行，這些 OOD 基準的表現直接反映了合成環境的遷移價值，而非簡單的過擬合驗證。

**Q8：WildAWM 的關鍵實驗結果是什麼？**
A：實驗結果顯示，WildAWM 合成的 341 個環境-任務配對對前沿模型仍具高度挑戰性——即便是 GPT-6-Astra 也僅能解決約 60% 的任務。在兩個 Qwen 模型（Qwen3.6-35B-A3B 與 Qwen3.5-4B）上進行線上強化學習後，兩個模型在全部 8 個 OOD 基準上都獲得了顯著提升。這證明了在 WildAWM 合成世界中進行的訓練能夠廣泛泛化到未見的電腦使用任務，無論是較大的 35B-A3B 模型還是較小的 4B 模型皆然。

**Q9：WildAWM 如何驗證其品質閘門與設計選擇的有效性？**
A：WildAWM 透過多層次的執行證據來驗證品質閘門的有效性：異質代理推演提供了任務可解性與難度的實證；跨評判一致性檢查確保不同評判者對任務成功與否的判斷具有一致性；反事實探測則透過刻意提供錯誤的結果回饋來測試驗證器是否會受到 LLM 逢迎傾向的影響而誤判。這些設計共同避免了「前沿模型必然正確」這種過於簡化的假設，使得合成出的任務與驗證器更具可靠性。

**Q10：WildAWM 的實際應用場景有哪些？**
A：WildAWM 的直接應用是為通用電腦使用代理提供大規模、可控的訓練環境，可用於線上強化學習以提升代理在桌面自動化、網頁導航與多應用程式工作流等場景中的表現。由於其環境支援 GUI、CLI 與 MCP 聯合操作，訓練出的代理能處理需要跨介面協調的複雜任務，例如同時操作瀏覽器、終端機與外部服務的綜合性工作。此外，釋出的 341 個環境-任務配對本身也可作為評估基準，用於衡量其他電腦使用代理的能力。

**Q11：將 WildAWM 應用於實際產品時需要考慮哪些因素？**
A：產品化時首先需考量安全性，雖然 WildAWM 解決了真實世界訓練的風險，但合成環境仍需確保不會在訓練過程中產生有害行為的代理。其次，可擴展性是關鍵——隨著任務複雜度提升，合成管線的計算成本與品質控制難度都會增加。此外，由於 WildAWM 完全依賴開源模型，產品化時需評估這些模型在不同語言、地區與應用生態下的覆蓋能力，以及如何持續更新合成內容以跟上真實軟體環境的演進。

**Q12：WildAWM 對電腦使用代理領域有什麼更廣泛的影響？**
A：WildAWM 最重要的領域影響在於示範了「從人類資料學習」轉向「透過與世界互動學習」這一範式轉移的可行性。它證明了開源模型足以合成高品質的訓練環境，挑戰了「必須依賴專有前沿模型」的隱含假設。此外，透過釋出 341 個環境-任務配與完整的開源程式碼，WildAWM 為社群提供了可重現、可擴展的研究基礎，可能激發更多關於環境合成、跨介面代理訓練與驗證器設計的研究方向。

**Q13：WildAWM 有哪些已承認的限制？**
A：WildAWM 的限制之一在於其合成品質仍依賴種子內容的品質，例如 WebHarbor 提供的 GUI 底層與影像內容會直接影響最終環境的多樣性。其次，即便前沿模型 GPT-6-Astra 也僅能解決 60% 的任務，這意味著仍有相當比例的任務可能存在品質問題或過於困難。此外，雖然 WildAWM 強調開源模型的能力，但開源模型在某些複雜推理或特定領域知識上仍可能不及專有前沿模型，這可能限制合成環境的覆蓋範圍。

**Q14：WildAWM 可能會遇到哪些失敗案例？**
A：WildAWM 在處理需要高度特定領域知識的任務時可能會失敗，例如涉及專業醫療軟體或工業控制系統的操作。在需要罕見或高度專門化應用程式的場景中，合成環境可能無法準確反映真實軟體的行為。此外，對於成功標準較為模糊或需要人類創造力的任務（例如設計類工作），驗證器可能難以可靠地區分成功與失敗。涉及高度動態線上服務或需要即時資訊的任務，也是 WildAWM 合成環境難以完全模擬的場景。

**Q15：WildAWM 未來的研究方向有哪些？**
A：未來研究可朝幾個方向延伸：首先，可探索更多元的任務類型與更複雜的環境結構，例如涵蓋更多專業應用程式或跨裝置的工作流。其次，驗證器的穩健性仍可進一步強化，例如引入更細粒度的反事實探測或多模態評判機制。此外，將 WildAWM 與更多代理框架整合、擴展至更大規模的環境合成，以及研究如何將在合成世界中學到的技能更有效地遷移到真實世界部署，都是值得探索的方向。最終，如何讓合成環境跟上真實軟體生態的快速演進，也將是持續的挑戰。

**運算資源**
- **推論用 GPU 叢集**：執行開源模型（Qwen 系列）進行環境與任務合成，建議至少數張 A100/H100 等級 GPU 以支援批次 rollouts。

- 熟悉 LLM agent 框架（如 OpenCode、ReAct、harness-based agent）與 tool-use 設計。

### 實作步驟建議

**階段一：環境合成（從論文到最小可行產品）**

1. **定義 persona 與活動模板**：蒐集 50–100 個目標領域的 persona，撰寫其典型一日活動腳本（早上檢查郵件、中午處理訂單、下午產出報表等）。

2. **建立可執行 PC 環境骨架**：使用 Docker 映像封裝 Linux 桌面環境，搭配 VNC/X11 對 GUI 代理暴露畫面，並預裝 CLI 工具鏈（bash、git、curl）與 MCP server runtime。

3. **合成 GUI 應用與網站**：以開源模型（如 Qwen3.5-4B）根據 persona 需求生成網站 HTML 與桌面應用程式碼，部署到環境中並驗證可正常互動。

4. **註冊 MCP 服務**：為每個環境定義 3–5 個領域相關的 MCP 工具（如「查詢訂單」「提交審批」「發送通知」），並實作其後端邏輯。

5. **填充本地檔案系統**：生成對應 persona 的文件、試算表、郵件、程式碼專案等初始狀態。

**階段二：任務合成與品質閘門**

6. **合成跨介面任務**：提示模型基於環境狀態生成需同時使用 GUI、CLI、MCP 的長時程任務，每個任務至少需 3 種介面。

7. **執行異質代理 rollouts**：使用 2–3 個不同模型（如 Qwen3.5-4B、Qwen3.6-35B-A3B）搭配不同 harness 執行每個任務，記錄成功率與軌跡。

8. **施加可解性閘門**：剔除所有代理都失敗（可能不可解）與所有代理都成功（可能太簡單）的任務，保留具挑戰性的中間難度樣本。

9. **跨評判一致性檢查**：對同一任務的成功/失敗結果使用多個 judge 模型評分，僅保留評判一致的任務。

10. **反事實探測**：刻意將成功軌跡的最終狀態替換為錯誤狀態餵給 judge，驗證 judge 是否會被 LLM 逢迎傾向誤導；剔除通過此探測的不可靠驗證器。

**階段三：訓練與部署**

11. **建立 reward signal**：將通過品質閘門的驗證器作為 RL 的 reward function。

12. **線上 RL 訓練**：在合成環境中對目標模型（如 Qwen3.5-4B）進行線上 RL，使用 OpenCode CLI harness 搭配 GUI 與 MCP 工具。

13. **OOD 評測**：在 8 個分布外基準（網頁、claw、電腦使用）上評估，確認泛化能力。

14. **部署與監控**：將訓練後的代理部署到目標場景，持續監控其動作安全性並蒐集失敗案例以迭代環境。

### 潛在風險與注意事項

**合成環境與真實環境的分布差異**
- 風險：合成環境可能過於「乾淨」或結構化，導致代理在真實世界的雜亂介面（廣告、彈窗、版本差異）上表現下降。
- 緩解：在合成階段刻意注入噪聲、錯誤訊息、UI 變體；定期以真實環境案例進行 few-shot 校正。

**驗證器的 LLM 逢迎漏洞**
- 風險：judge 模型可能因提示中的正向語氣而誤判失敗為成功（論文已指出此問題並提出反事實探測）。
- 緩解：採用基於執行結果的硬性檢查（如檔案內容 hash、API 回傳值、資料庫狀態）作為最終仲裁，而非僅依賴 LLM judge。

**長時程任務的信用分配困難**
- 風險：超過 100 步的任務中，reward signal 稀疏，難以判斷哪一步動作導致最終成敗。
- 緩解：採用 process reward model 或將長任務拆解為多個子任務里程碑，給予中間 reward。

**開源模型合成品質上限**
- 風險：完全依賴開源模型可能限制合成任務的多樣性與複雜度上限。
- 緩解：以開源模型為主力、輔以少量人工精修高價值任務；定期用前沿模型抽樣評估合成品質。

**環境重置與狀態洩漏**
- 風險：若環境重置不徹底，代理可能學會利用殘留狀態走捷徑。
- 緩解：每次 rollout 前強制重建容器快照；驗證器檢查初始狀態是否符合預期。

**安全性與越獄風險**
- 風險：代理在訓練中可能學會繞過驗證器或執行未授權動作（如刪除檔案、對外發送資料）。
- 緩解：環境中預設所有外部網路呼叫為阻擋或 mock；對 CLI 指令實施白名單與審計日誌。

---

### 與其他技術的整合建議

**與既有 agent 框架整合**
- WildAWM 訓練出的代理可直接掛載於 OpenCode CLI、Claude Code 或各類 harness-based agent 框架，無需修改介面層。建議在部署時保留 GUI、CLI、MCP 三種工具的並存，讓代理依任務特性自行選擇介面。

**與 RL 訓練框架整合**
- 可將 WildAWM 的環境註冊為 Gymnasium 相容介面，接入 verl、OpenRLHF 或 TRL 等框架進行線上 RL。reward function 直接呼叫任務的執行式驗證器。

**與 MCP 生態系整合**
- 合成環境時應採用標準 MCP server 規格，使訓練出的代理能直接用於真實 MCP 服務。建議建立 MCP tool registry，將合成環境中的工具與企業真實 MCP 服務做映射。

**與評測基準整合**
- 將 WildAWM 釋出的 341 個環境-任務配對作為持續評測集，定期評估自家模型的泛化能力。也可作為 red-teaming 工具，主動發現代理的失敗模式。

**與監控與可觀測性平台整合**
- 部署階段串接 OpenTelemetry 或 LangSmith，記錄代理每步動作、工具呼叫與狀態變化，便於除錯與合規稽核。

**與知識庫與 RAG 整合**
- 對於需要查閱文件的任務，可在 MCP 層掛載 RAG 工具，讓代理透過標準 tool call 取得領域知識，避免在 prompt 中塞入過長上下文。

---

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的問題動機（為何需要合成環境）與第 3 節的整體流程圖，建立「環境合成 → 任務合成 → 品質閘門 → RL 訓練」的高階心智模型。實作上可先從小規模開始：用一個簡單 persona、一個網站、一個 MCP 工具，嘗試合成 10 個任務並用單一模型 rollout 驗證可行性，再逐步擴展。

**給 AI 工程師**：重點關注第 3 節的品質閘門設計（異質 rollouts、跨評判一致性、反事實探測）與第 4 節的 RL 訓練細節。工程師應將「執行式驗證器」視為核心元件，優先投資於可重現、可審計的 reward function 設計；同時注意開源模型在 judge 角色上的局限性，必要時引入規則式檢查作為補強。

**給研究者**：本論文在環境合成領域提出三個關鍵貢獻——跨介面統一環境、執行式品質閘門、完全開源流程。建議從 Table 1 的比較表出發，分析 WildAWM 相較 AWM、WebArena-Infinity、Gym-Anything 等方法的設計權衡；並深入探討反事實探測如何量化 LLM judge 的逢迎偏差，這對整個 agent 評測領域都有方法論意義。

**給產品經理**：WildAWM 解決的核心商業問題是「如何安全、可擴展地訓練能操作真實電腦的 AI 代理」。產品經理應關注三個面向：(1) 訓練成本——完全使用開源模型大幅降低對前沿 API 的依賴；(2) 安全性——合成環境讓探索性訓練無需觸碰生產系統；(3) 泛化性——在 8 個 OOD 基準上的提升證明投資報酬率。建議將 WildAWM 視為內部 agent 訓練基礎設施的候選方案，優先評估其在自家業務流程中的 persona 覆蓋率與任務可合成性。
