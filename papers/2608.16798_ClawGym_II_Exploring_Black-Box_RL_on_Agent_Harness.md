## ⚡ TL;DR

如何透過複雜且不透明的代理執行框架，以黑箱強化學習穩定訓練通用代理，是本研究要解決的核心問題。
本研究提出統一黑箱RL框架，以沙箱隔離、服務代理攔截呼叫，用前綴樹重建軌跡作PPO/GRPO最佳化。
以Qwen3為骨幹，於ClawGym-Bench提升9.98與14.81點，數百步穩定且可混合訓練。

## 摘要翻譯

代理執行框架（Agent Harness）透過協調代理與環境之間的互動，已大幅提升長程任務（Long-Horizon Tasks）上的表現。然而，透過複雜代理執行框架進行強化學習（Reinforcement Learning, RL）仍較少被研究，因為將此類訓練擴展到長程代理任務會帶來根本性的挑戰。在本研究中，我們提出一個統一的黑箱強化學習（Black-Box RL）框架，可在複雜代理執行框架上對通用代理（General Agents）進行穩定且可擴展的最佳化（Stable and Scalable Optimization）。具體而言，我們首先建構一個基於沙箱的執行基礎設施（Sandbox-Based Execution Infrastructure），將任務環境與代理執行框架隔離於臨時沙箱（Temporary Sandboxes）中，以支援大規模並行 Rollout（Large-Scale Concurrent Rollouts）。接著，我們將策略最佳化（Policy Optimization）與不透明的工具束執行（Opaque Harness Execution）解耦，並在模型邊界（Model Boundary）部署服務代理（Serving Proxy）以攔截模型呼叫（Model Calls）。為了重建多輪軌跡（Multi-Turn Trajectories）並提升訓練效率，我們將攔截到的呼叫組織成前綴樹（Prefix Trees），並進一步調適基於評論家的 PPO（Critic-Based PPO）與無評論家的 GRPO（Critic-Free GRPO），以在重建的樹狀結構（Recovered Tree Structure）上進行最佳化。同時，我們在整個最佳化過程中維持訓練-推論一致性（Training-Inference Consistency）。最後，我們引入混合工具束訓練（Mix-Harness Training），使單一模型能同時接受多種異質工具束（Heterogeneous Harnesses）的聯合最佳化。在使用 Qwen3-30A3B 的設定下，黑箱強化學習透過 OpenClaw 與 Claude Code 分別將 ClawGym-Bench 上的 Pass@1 提升 9.98 與 14.81 個百分點，並在 200 至 400 個最佳化步驟（Optimization Steps）期間仍保持穩定。此外，本框架在更具挑戰性的任務如 JobBench 與 OfficeQA 上亦取得穩定增益。總體而言，我們的框架能透過黑箱代理執行框架對通用代理進行有效、穩定且可擴展的最佳化，並支援跨異質執行系統（Heterogeneous Execution Systems）的統一訓練。

### 核心貢獻（3～5點）
- 建構基於沙箱的執行基礎設施，將任務環境與代理執行框架隔離於臨時沙箱中，以支援大規模並行 Rollout。
- 在模型邊界部署服務代理以攔截模型呼叫，並利用前綴樹重建多輪軌跡，使策略最佳化與不透明的工具束執行解耦。
- 調適基於評論家的 PPO 與無評論家的 GRPO，使其能在重建的樹狀結構上進行穩定最佳化，並維持訓練-推論一致性。
- 提出混合工具束訓練，讓單一模型能同時接受多種異質工具束的聯合最佳化。
- 在 ClawGym-Bench、JobBench 與 OfficeQA 等基準上驗證，顯著提升 Pass@1，並在數百個最佳化步驟內保持訓練穩定。

### 適合對象
本論文適合對強化學習、自主代理系統、大型語言模型工具使用，以及代理執行框架設計有興趣的研究人員與工程師，特別是關注如何以黑箱方式對複雜代理執行框架進行穩定且可擴展訓練的讀者。

## 深度分析

#### 方法論解析

本研究的核心貢獻在於提出一個統一的黑箱強化學習（Black-Box RL）框架，讓單一語言模型能夠透過複雜且不透明的 Agent Harness（代理執行框架）進行穩定、可擴展的策略最佳化（Policy Optimization）。以下從問題設定、執行基礎設施、軌跡重建、策略最佳化與異質訓練五個層面進行剖析。

##### 問題設定：有狀態長程任務的決策結構

論文將通用代理（General Agents）任務形式化為一個包含使用者指令與初始工作空間的配對 \(q=(u, W_0)\)，並在 Stateful Environment（有狀態環境）\(E_q\) 中執行。代理必須透過多輪外部工具呼叫（如 Shell、程式碼執行、API 呼叫）逐步改變環境狀態，最終以生成產物或完成操作作為任務結局。這本質上是一個部分可觀察馬可夫決策過程（POMDP），但與傳統 RL 環境不同之處在於：互動邏輯被包覆在 Agent Harness（代理執行框架）內部，研究者無法直接觀察其 Internal Control Flow（內部控制流程）與 Execution Logic（執行邏輯）。

##### 基於沙箱的執行基礎設施

為了解決大規模並行 Rollout（Rollout）在長程任務中的穩定性問題，作者建構了 Sandbox-Based Execution Infrastructure（基於沙箱的執行基礎設施）。每一次 Rollout 都會在 Temporary Sandbox（臨時沙箱）中動態建立任務環境與對應的 Harness，並在結束後銷毀。這帶來幾項關鍵優勢：

- **隔離性（Isolation）**：不同 Rollout 之間的檔案系統、執行狀態與副作用不會互相污染，避免 Stateful Environment（有狀態環境）的殘留狀態影響後續軌跡。
- **容錯性（Fault Tolerance）**：單一沙箱內的延遲、當機或工具失敗可被限制在該次 Rollout 內，不會拖垮整個訓練管線。
- **可擴展性（Scalability）**：沙箱能夠按需佈建，支援 Large-Scale Concurrent Rollouts（大規模並行 Rollout），這對於需要大量採樣的 RL 訓練至關重要。

##### 服務代理與模型邊界解耦

論文將 Policy Optimization（策略最佳化）與 Opaque Harness Execution（不透明的工具束執行）解耦，關鍵機制是在 Model Boundary（模型邊界）部署 Serving Proxy（服務代理）。該代理會攔截 Harness 對語言模型發出的每一次 Model Calls（模型呼叫），並將其導向當前正在訓練的策略模型或參考模型。這樣的設計有幾項好處：

- Harness 可以保留其原生執行邏輯（包括 System Prompts（系統提示）、Context Management（上下文管理）、Retry and Recovery Mechanisms（重試與恢復機制）與 Workflow Orchestration（工作流程編排）），無需為訓練而修改。
- 訓練端只需處理標準化的 token-in-token-out 介面，降低與各種異質 Harness 整合的成本。
- 所有進出模型的請求與回應都被記錄下來，成為後續軌跡重建的原始資料。

##### 前綴樹軌跡重建

現實中的 Agent Harness（代理執行框架）並不會產生乾淨的線性 Multi-Turn Trajectories（多輪軌跡），而是會因重試、並行工具呼叫、上下文截斷等原因產生 Fragmented Traces（片段化軌跡）、Forked Model Calls（分叉的模型呼叫）與 Redundant Model Calls（冗餘的模型呼叫）。為此，作者將 Capture Model Calls（攔截模型呼叫）所得的記錄組織成 Prefix Trees（前綴樹）：

- 共享前綴的呼叫會被合併到同一樹枝，減少重複計算與儲存。
- 分叉點對應 Harness 內部的不同決策路徑（例如重試、分支探索），每一條路徑形成獨立的後續軌跡。
- 透過 Recovered Tree Structure（重建的樹狀結構），訓練演算法可以將原本片段化的 Black-Box Traces（黑箱軌跡）還原為可用於 RL 的結構化資料。

這種樹狀表示比傳統的序列式經驗回放更適合處理 Harness 產生的非線性互動，並且能夠在後續最佳化中利用共享前綴進行更高效的梯度計算。

##### 樹狀結構上的 PPO 與 GRPO

在重建的樹狀結構上，作者分別調適了兩種演算法：

- **Critic-Based PPO（基於評論家的 PPO）**：透過 Critic（評論家）估計每個樹節點的價值，並沿著樹枝傳播 Advantage，從而進行近端策略更新。由於前綴共享，價值函數可以在共同前綴上重複使用，提升樣本效率。
- **Critic-Free GRPO（無評論家的 GRPO）**：在樹的同一群組內比較不同分支的相對回報，無需額外訓練 Critic（評論家）。這對於長程任務特別有吸引力，因為訓練穩定的價值函數在複雜 Harness 中往往困難且昂貴。

兩種方法都必須處理 Variable-Length Trajectories、部分完成的 Episode 以及 Harness 內部隱藏狀態所帶來的非馬可夫性。論文透過樹狀結構將這些挑戰轉化為可在批次內統一處理的計算圖。

##### 訓練-推論一致性與穩定性機制

由於 Harness 在推論時可能使用與訓練引擎不同的採樣參數、停止條件或工具解析邏輯，Training-Inference Consistency（訓練-推論一致性）是黑箱 RL 穩定的關鍵。作者採用兩項技術：

- **Black-Box Token-In-Token-Out Mechanism（黑箱 token-in-token-out 機制）**：確保訓練階段與實際推論階段使用相同的輸入輸出格式，降低因介面不一致造成的分佈偏移。
- **Token-Level Importance-Sampling Rollout Correction（token-level 重要性採樣 Rollout 校正）**：修正由推論引擎與訓練引擎差異所引入的偏差，使得舊策略採樣的軌跡能夠正確地用於新策略的梯度更新。

此外，論文還加入額外的保護機制來穩定 Rollout 執行與策略更新，例如超時處理、失敗恢復與軌跡驗證，這些都是讓訓練能夠穩定進行 200–400 Optimization Steps（最佳化步驟）的基礎。

##### 混合工具束訓練

最後，作者提出 Mix-Harness Training（混合工具束訓練）：將每一個 task-harness 配對視為基本訓練實例，並讓來自多個 Heterogeneous Harnesses（異質工具束）的 Rollout 共同最佳化單一模型。由於沙箱隔離了各 Harness 的執行細節，而 Serving Proxy（服務代理）統一了模型邊界介面，因此不同設計哲學與互動協議的 Harness 可以在同一訓練管線中協同運作。這不僅提升了框架的 Extensibility（可擴展性），也讓模型有機會學到跨 Harness 的通用策略。

#### 實驗數據解讀

本研究的實驗以 Qwen3-30A3B 為基礎模型，分別透過 OpenClaw 與 Claude Code 兩個結構迥異的 Agent Harness（代理執行框架）進行 Black-Box RL（黑箱強化學習）訓練，並在多個基準上評估 Pass@1（Pass@1）表現。

##### 主要結果

| 模型 | Harness | PinchBench | ClawGym-Bench |
|---|---|---|---|
| 基礎模型 | — | 基線 | 基線 |
| ClawII-OC-30A3B | OpenClaw | +11.71 | +9.98 |
| ClawII-CC-30A3B | Claude Code | +17.28 | +14.81 |

數據顯示：

- **絕對提升顯著**：在 ClawGym-Bench（ClawGym-Bench）上，OpenClaw 提升 9.98 點，Claude Code 提升 14.81 點；在 PinchBench 上則分別提升 11.71 與 17.28 點。這代表單純透過 Black-Box RL（黑箱強化學習）訓練，就能顯著釋放現有 Harness 的潛能。
- **Claude Code 的增益更大**：可能原因包括 Claude Code 是更成熟、功能更豐富的 Harness，其 Internal Control Flow（內部控制流程）與 Execution Logic（執行邏輯）更複雜，因此未經訓練的模型難以充分利用；一旦透過 RL 學會配合其 Workflow Orchestration（工作流程編排）與 Retry and Recovery Mechanisms（重試與恢復機制），性能空間更大。
- **訓練穩定性**：模型在 200–400 Optimization Steps（最佳化步驟）內保持穩定，這在長程任務的 RL 訓練中並不常見，顯示沙箱基礎設施與一致性機制的實質效果。

##### 混合工具束訓練的表現

Mix-Harness Training（混合工具束訓練）的結果顯示，同時使用 OpenClaw 與 Claude Code 訓練的單一模型，其表現能夠匹配甚至超越僅使用單一 Harness 訓練的模型。這具有幾層意義：

- **正交性與互補性**：兩個 Harness 的錯誤模式與探索空間不同，聯合訓練可視為一種正則化，降低模型過度擬合到單一 Harness 特定行為的風險。
- **統一框架的可行性**：證明透過 Serving Proxy（服務代理）與 Sandbox（沙箱）抽象後，Heterogeneous Harnesses（異質工具束）確實可以在同一 Policy Optimization（策略最佳化）流程中協同。
- **實用價值**：在實際部署中，不同任務可能適合不同 Harness；混合訓練讓單一模型具備跨 Harness 的通用能力，減少為每個 Harness 單獨訓練模型的成本。

##### 跨領域遷移：JobBench 與 OfficeQA

除了 ClawGym（ClawGym）系列任務，作者還將框架延伸至更具挑戰性的 JobBench（JobBench）與 OfficeQA（OfficeQA）。在這兩個基準上，Black-Box RL（黑箱強化學習）同樣帶來一致的提升，說明該方法不僅適用於特定任務類型，也具備一定的跨領域泛化能力。這對於推廣到 Software Engineering（軟體工程）、Office Applications（辦公應用程式）與 AI Assistant Workflows（AI 助理工作流程）等真實場景具有指標意義。

##### 數據解讀的限制

儘管結果亮眼，仍有幾點值得注意：

- 論文僅報告 Pass@1（Pass@1），未提供 Pass@k、平均步數、執行延遲或 API 呼叫成本等指標，難以全面評估效率與實用性。
- 未清楚說明 Reward Function（獎勵函數）的設計細節，這對於理解模型究竟學到什麼策略至關重要。
- 實驗主要聚焦兩個 Harness，雖然已具代表性，但對於更廣泛的 Heterogeneous Harnesses（異質工具束）生態系統，仍需更多驗證。

#### 與現有研究的比較

##### 從推論端進展到訓練端最佳化

過去 Agent Harness（代理執行框架）的進展主要集中在 Inference-Side Advances（推論端進展），例如 Claude Code（Claude Code）、Codex（Codex）、OpenClaw（OpenClaw）等系統透過精緻的 System Prompts（系統提示）、Context Management（上下文管理）與 Self-Evolution（自我演化）來提升效能。本研究則從另一個角度出發：假設 Harness 已經設計良好，如何透過 RL 讓底層模型學會更好地「駕馭」這些 Harness。這兩條路線互補，未來可能出現 Harness 設計與模型訓練共同演化的典範。

##### 黑箱 RL 的複雜度躍升

早期的 LLM RL 研究多集中在簡單的單輪或輕量代理環境，軌跡明確且可直接觀察。本研究面對的是現代 Harness 所帶來的 Black-Box Traces（黑箱軌跡）：Fragmented Traces（片段化軌跡）、Forked Model Calls（分叉的模型呼叫）與 Redundant Model Calls（冗餘的模型呼叫）。透過 Prefix Trees（前綴樹）進行軌跡重建，是將傳統序列式 RL 擴展到複雜 Harness 環境的重要創新。

##### 與 PPO / GRPO 的關係

PPO（近端策略最佳化）與 GRPO（Group Relative Policy Optimization）原本多用於單輪或簡短對話的 RLHF 場景。本研究的貢獻在於將它們調適到樹狀結構的長程軌跡上，並結合 Token-Level Importance-Sampling Rollout Correction（token-level 重要性採樣 Rollout 校正）來維持 Training-Inference Consistency（訓練-推論一致性）。這比直接套用標準 PPO 更為細緻，也更能應對 Harness 內部的不透明操作。

##### 優勢總結

- **統一性**：單一框架可支援任意 Harness，並透過 Mix-Harness Training（混合工具束訓練）進行聯合最佳化。
- **穩定性**：在長程任務上維持 200–400 Optimization Steps（最佳化步驟）的穩定訓練。
- **可擴展性**：Sandbox-Based Execution Infrastructure（基於沙箱的執行基礎設施）支援 Large-Scale Concurrent Rollouts（大規模並行 Rollout）。
- **實證廣度**：在 OpenClaw、Claude Code、JobBench（JobBench）與 OfficeQA（OfficeQA）上均取得提升。

##### 限制與不足

- **Harness 數量有限**：僅驗證兩個 Harness，且 Claude Code（Claude Code）為閉源系統，難以完全控制變因。
- **缺乏細部消融**：沙箱、前綴樹、一致性校正、Mix-Harness Training（混合工具束訓練）等元件各自貢獻多少，論文未提供詳細消融實驗。
- **獎勵設計不透明**：對於長程任務，Reward Function（獎勵函數）的稀疏性或設計細節會大幅影響學習結果，但文中著墨較少。
- **計算成本未披露**：大規模沙箱佈建與多輪 Rollout 的開銷可能相當高，對於資源有限的團隊而言是重要考量。
- **理論分析不足**：樹狀結構上的策略梯度收斂性、Credit Assignment（信用分配）性質等仍有待深入探討。

#### 未來研究方向

基於本研究的成果與限制，以下幾個方向值得進一步探索：

##### 1. 擴展至更多異質工具束

目前僅驗證 OpenClaw（OpenClaw）與 Claude Code（Claude Code）。未來可納入 Codex（Codex）、MCP-Enabled Tool Use（MCP 啟用的工具使用）框架、瀏覽器代理、機器人控制 Harness 等，進一步驗證 Unified Framework（統一框架）的通用性。

##### 2. 樹狀結構 RL 的理論分析

Prefix Trees（前綴樹）上的 Policy Optimization（策略最佳化）涉及複雜的 Credit Assignment（信用分配）問題。未來可研究樹狀軌跡的方差下界、收斂條件，以及共享前綴對梯度估計的影響，為演算法設計提供更堅實的理論基礎。

##### 3. 聯合工具束與策略共同演化

本研究將 Harness 視為固定不透明的執行引擎。未來可探索 Harness 設計與模型策略的 Co-Evolution（共同演化）：例如讓 Harness 的 System Prompts（系統提示）或 Workflow Orchestration（工作流程編排）也成為可學習的參數，與模型一起最佳化。

##### 4. 學習型獎勵函數與中間監督

長程任務的獎勵往往稀疏。未來可結合 Outcome-Based Reward Model（基於結果的獎勵模型）或 Process-Based Reward Model（基於過程的獎勵模型），在 Prefix Trees（前綴樹）的中間節點提供細粒度回饋，改善 Credit Assignment（信用分配）。

##### 5. 更高效的沙箱與 Rollout 系統

Large-Scale Concurrent Rollouts（大規模並行 Rollout）成本高昂。未來可研究沙箱的快照與快取、增量環境初始化、推測性 Rollout 排程，以及根據模型不確定性動態分配計算資源的策略。

##### 6. 安全與對齊

當模型學會深度利用 Harness 的 Execution Logic（執行邏輯）時，可能出現 Reward Hacking（獎勵作弊）、繞過安全檢查或濫用工具等風險。未來需要發展針對 Black-Box Harness（黑箱工具束）訓練的安全監控與對齊機制。

##### 7. 模型蒸餾與輕量化

將透過複雜 Harness 訓練得到的大型模型能力，蒸餾到較小的模型上，讓資源受限的場景也能受益於 Black-Box RL（黑箱強化學習）的效能提升。

##### 8. 與推論時搜尋的結合

本研究專注於訓練階段的最佳化。未來可探討如何將訓練得到的策略與 Inference-Time Search（推論時搜尋）、Monte Carlo Tree Search（蒙地卡羅樹搜尋）或 Best-of-N Sampling 結合，進一步提升長程任務的成功率。

##### 9. 動態混合工具束課程

Mix-Harness Training（混合工具束訓練）目前採用固定混合。未來可根據模型在各家 Harness 上的表現動態調整採樣比例，形成 Adaptive Curriculum（適應性課程），加速收斂並提升最終泛化。

##### 10. 跨真實世界工作空間的泛化

最終目標是讓 General Agents（通用代理）能夠在未曾見過的 Real-World Workspaces（真實世界工作空間）中運作。未來需要建立更廣泛的跨領域評估協議，並研究 Domain Adaptation（領域適應）與 Meta-Learning（元學習）在黑箱 Harness 訓練中的應用。

## 論文問答

**Q1：這篇論文想要解決的核心研究問題是什麼？為什麼透過代理執行框架進行黑箱強化學習很重要？**
A：本論文聚焦的核心問題是：如何透過代理執行框架（agent harness）對通用代理進行穩定的黑箱強化學習。現代生產級框架如 Claude Code、OpenClaw 的內部控制流程極為複雜且不透明，傳統針對簡單文字環境設計的強化學習演算法無法直接處理這些長程、多輪且狀態持續變化的互動。因此，建立一套能將框架視為黑箱、同時穩定擴展訓練的統一方法，對於讓底層模型充分發揮先進框架的潛能至關重要。

**Q2：相較於傳統強化學習環境，透過複雜框架進行訓練會遇到哪些根本挑戰？**
A：作者歸納出三大挑戰：首先是可擴展且穩定的執行基礎設施，長程任務需要在有狀態環境中進行大規模並行 rollout，任何延遲或失敗都可能累積並毀掉整條軌跡；其次是從片段化黑箱軌跡中進行有效的策略最佳化，框架只暴露分叉、冗餘的模型呼叫，而非完整軌跡，容易造成訓練-推論不一致；最後是跨異質框架的可擴展性，不同框架在互動協定、工具介面與工作流程上差異甚大，實用系統必須能以最小適配成本統一訓練。

**Q3：為什麼現有的單輪或輕量代理強化學習方法難以直接套用到 Claude Code 這類成熟框架上？**
A：現有方法通常假設互動過程是明確且可直接觀察的，模型軌跡單一且沒有複雜的隱藏執行邏輯；然而 Claude Code 等框架內建了系統提示、工具介面、上下文管理、重試恢復與工作流程編排等機制，會產生大量無法直接觀察的內部控制流程。這些框架向模型發出的呼叫可能是並行、重試或分叉的，導致軌跡片段化且冗餘，違反了傳統演算法對完整軌跡與穩定環境的假設。若忽視這些特性，訓練過程將出現嚴重的不穩定與訓練-推論落差。

**Q4：ClawGym II 的統一黑箱強化學習框架包含哪些核心元件？**
A：框架首先建立基於沙箱的執行基礎設施，將每個任務環境與框架封裝在臨時沙箱中，以支援大規模並行 rollout；接著在模型邊界部署服務代理，攔截所有模型呼叫，將策略最佳化與不透明的框架執行解耦。被攔截的呼叫會被組織成前綴樹以重建多輪軌跡，並據此調整 PPO 與 GRPO 進行樹狀結構最佳化；同時透過 token-in-token-out 機制與 token-level 重要性抽樣 rollout 校正來維持訓練-推論一致性，最後支援混合框架訓練。

**Q5：基於沙箱的執行基礎設施如何確保大規模並行 rollout 的穩定性？**
A：每次 rollout 都會動態建立一個臨時沙箱，內含任務專屬的初始工作空間與對應的代理執行框架，完成後立即銷毀，從而避免不同 rollout 之間的狀態污染與資源衝突。這種按需配置與隔離的設計讓系統能同時執行大量長程互動，並將執行失敗或延遲限制在單一沙箱內，不會擴散到整個訓練管線。藉此，訓練資料生成變得更及時、可靠，也能忠實保留模型在真實框架下的行為。

**Q6：前綴樹重建與樹狀結構最佳化如何解決片段化模型呼叫的問題？**
A：服務代理攔截到的模型呼叫往往是片段化、分叉且冗餘的，直接將它們視為獨立軌跡會浪費訓練資料並破壞多輪結構；因此系統將共享前綴的呼叫合併成前綴樹，把重複的推理路徑只計算一次，從而還原出可靠的多輪軌跡。在這棵樹上，作者進一步調整了基於評論家的 PPO 與無評論家的 GRPO，使其能夠在樹狀結構上進行策略更新，提升樣本效率並穩定訓練。

**Q7：論文在哪些基準與框架上驗證了方法？最關鍵的量化結果是什麼？**
A：實驗選用 OpenClaw 與 Claude Code 兩個結構迥異的框架，並以 Qwen3-30A3B 為骨幹模型，在 ClawGym-Bench、PinchBench 以及更具挑戰性的 JobBench、OfficeQA 上進行評估。結果顯示，黑箱強化學習讓 ClawGym-Bench 的 Pass@1 分別提升 9.98 分（OpenClaw）與 14.81 分（Claude Code），PinchBench 則提升 11.71 分與 17.28 分。更重要的是，訓練在 200 至 400 個最佳化步驟內仍保持穩定，顯示方法在複雜框架上具備良好的收斂性與魯棒性。

**Q8：什麼是混合框架訓練（mix-harness training）？實驗結果說明了什麼？**
A：混合框架訓練讓單一模型同時接受來自多個異質框架的 rollout 資料進行聯合最佳化，每個任務-框架配對都是一個基本訓練實例。實驗發現，透過 mix-harness training 訓練出的模型表現能夠匹配甚至超越僅用單一框架訓練的模型，這證明該框架能無縫整合不同執行系統的資料。這項能力對於實際部署尤為重要，因為它允許模型同時學習多種互動協定與工作流程，而不需要為每個框架單獨訓練一個模型。

**Q9：為了維持訓練-推論一致性，作者採取了哪些具體機制與安全防護？**
A：作者採用黑箱 token-in-token-out 機制，使訓練階段與實際推論階段的輸入輸出格式保持一致，並輔以 token-level 重要性抽樣 rollout 校正來彌補底層推論引擎與訓練引擎之間的差異。這些設計能減少因引擎不一致所帶來的偏差，避免策略在訓練時表現良好卻在實際框架中失效。此外，論文還加入額外的 safeguards 來穩定 rollout 執行與策略最佳化，確保長時間訓練不會發散。

**Q10：這個框架在實務上可以應用到哪些場景？**
A：該框架適用於任何需要透過複雜代理執行框架完成長程多輪任務的場景，例如軟體工程中的程式碼編輯與終端操作、辦公應用中的文件簡報生成、AI 助理工作流程以及透過 MCP 使用外部工具的任務。由於它把框架視為黑箱，因此幾乎不需要修改框架內部邏輯就能進行強化學習訓練。這讓企業與研究人員能夠直接對現有的生產級框架進行模型最佳化，加速通用代理在真實工作空間中的落地。

**Q11：若要在產品環境中部署這套系統，需要考慮哪些工程與安全議題？**
A：首先必須確保沙箱隔離的完整性，因為代理會執行 shell 指令、程式碼與外部 API 呼叫，任何隔離失效都可能帶來安全風險；其次需要規劃足夠的運算資源以支援大規模並行 rollout，並設計有效的失敗重試與超時機制來處理長程任務中的延遲與錯誤。此外，服務代理的整合、異質框架協定的適配、訓練-推論一致性的監控，以及模型輸出的安全審核，都是產品化過程中不可忽視的環節。

**Q12：這項研究對自主代理與強化學習領域可能帶來什麼影響？**
A：這項研究首次系統性地展示了如何在生產級不透明框架上進行穩定且可擴展的強化學習，彌補了推論端框架快速進步與訓練端模型最佳化之間的落差。透過統一管線支援異質框架與混合訓練，它降低了將新框架納入訓練循環的門檻，有助於加速通用代理的發展。長遠來看，這種黑箱最佳化範式可能成為連接大型語言模型與多樣化真實世界工作空間的標準訓練方法之一。

**Q13：作者承認的方法限制有哪些？**
A：雖然論文展示了顯著進展，但方法仍依賴框架會向模型發出可攔截的呼叫，若某些框架完全封閉或不遵循標準介面，則服務代理難以部署；此外，沙箱 rollout 與前綴樹重建都需要額外的運算與儲存開銷，對於極長軌跡或高頻互動任務成本會顯著增加。由於框架內部邏輯被視為黑箱，演算法也無法主動利用框架內部的結構化資訊來進一步提升樣本效率。

**Q14：在哪些情況下，這套黑箱強化學習框架可能表現不佳或難以應用？**
A：當任務的回饋極為稀疏且互動步數極長時，信用分配會變得非常困難，即使透過樹狀結構也難以有效學習；若框架執行本身具有高度不確定性或頻繁出現無法復現的錯誤，則 rollout 資料會充滿雜訊，導致策略更新不穩定。另外，對於需要與無法沙箱化的真實世界系統直接互動的任務，例如某些需要實體裝置或受監管外部服務的場景，隔離與可重複性都會成為重大挑戰。

**Q15：未來可以朝哪些方向延伸這項研究？**
A：未來可以將框架擴展到更多異質框架與多模態互動場景，例如結合視覺觀察或語音指令的代理任務；同時可針對黑箱設定設計更專門的評論家架構與長程信用分配機制，以進一步提升樣本效率。另一方面，也可探索如何降低 rollout 成本，例如透過世界模型進行部分模擬或知識蒸餾，並將框架的自我演化與模型強化學習訓練結合，形成代理執行框架與底層模型共同進步的閉環。

## 實務應用指南

## 適用場景

1. **企業級 AI 助理與自動化流程**  
   當組織已經導入 Claude Code、OpenClaw 或內部開發的 agent harness，卻發現基座模型在長程、多步驟任務（例如跨系統填表、產生報告、排程協調）上表現不穩定時，可使用本框架進行黑箱強化學習，讓單一模型同時適應多種執行框架。

2. **軟體工程智慧代理**  
   適用於需要長時間與終端機、程式碼倉庫、測試環境互動的場景，例如自動化除錯、重構、產生 PR、執行 CI/CD 驗證。透過 sandbox 隔離每次 rollout，可在不污染開發環境的前提下大規模訓練。

3. **辦公應用與文件處理代理**  
   針對 OfficeQA、JobBench 這類需要操作文件、試算表、簡報或企業內部系統的任務，利用 mix-harness training 讓模型學會在不同工具介面與上下文管理策略下完成任務。

4. **多工具整合的 MCP 代理**  
   當代理需要透過 Model Context Protocol（MCP）呼叫多個外部工具（搜尋、API、資料庫、程式執行），但 harness 內部控制流程複雜難以解析時，可將 harness 視為黑箱，僅攔截模型呼叫進行策略最佳化。

5. **異質執行系統的統一訓練**  
   若組織同時運行多個執行系統（例如開源 harness、商業 harness、內部 workflow orchestration），本框架可將它們封裝為獨立訓練實例，聯合最佳化單一模型，降低為每個系統個別微調的成本。

## 實作前置條件

### 資料條件
- **任務資料集**：需準備帶有初始工作空間（workspace）與明確成功準則的長程任務，例如 ClawGym-Bench、JobBench、OfficeQA 或自建的企業任務集。
- **獎勵標註**：每個任務需可自動化判斷最終環境狀態是否達成目標（Pass@1 或自訂 reward），並能回傳 scalar reward。
- **模型呼叫日誌**：若已有 harness 運行紀錄，可先用於分析呼叫模式，但訓練時仍需透過 serving proxy 即時攔截。

### 運算條件
- **基座模型**：建議使用至少 7B–30B 等級的大型語言模型（論文使用 Qwen3-30A3B），並具備 vLLM、SGLang 或類似推論引擎。
- **推論與訓練叢集**：需支援大規模並行 rollout，包含足夠的 GPU 用於模型推論、CPU/記憶體/儲存用於 sandbox 執行，以及高速網路連接兩者。
- **沙箱基礎設施**：需可動態建立與銷毀臨時沙箱（如 Docker、Kubernetes、Firecracker、gVisor），並支援有狀態環境的快照與重置。

### 技能條件
- 熟悉強化學習基礎，特別是 PPO、GRPO 與 importance sampling。
- 具備分散式系統與容器化部署經驗，能設計高可靠度的 rollout pipeline。
- 理解 agent harness 的運作方式，雖然內部視為黑箱，但仍需能整合其 API 與錯誤處理機制。

## 實作步驟建議

1. **建立沙箱化執行基礎設施**  
   為每個任務與 harness 組合建立臨時沙箱模板，確保每次 rollout 都在乾淨、可重現的環境中執行，並在結束後自動銷毀。設計超時、重試與失敗清理機制，避免長程任務累積延遲。

2. **部署 Serving Proxy 攔截模型呼叫**  
   在模型邊界放置服務代理，讓 harness 的所有模型呼叫都經過 proxy。Proxy 需記錄請求內容、回應內容、時間戳與呼叫間的父子關係，同時支援訓練時的 token-in-token-out 一致性。

3. **將片段化呼叫重建為前綴樹**  
   收集 rollout 後的模型呼叫，依據共享前綴與呼叫順序組織成前綴樹。去除冗餘呼叫、處理因重試產生的分叉，還原出可用的多輪軌跡。

4. **選擇並調整最佳化演算法**  
   根據資源與任務特性選擇 PPO（需訓練 critic）或 GRPO（critic-free）。將重建的樹狀結構轉為訓練樣本，並加入 token-level importance-sampling correction 以維持訓練-推論一致性。

5. **啟動大規模並行 Rollout 與訓練迴圈**  
   同時產生大量 rollout，將結果回傳至訓練節點進行策略更新。監控 reward 曲線、KL 散度與 value loss，確保 200–400 個最佳化步驟內穩定收斂。

6. **導入 Mix-Harness Training（選用）**  
   當單一 harness 訓練收斂後，可將其他異質 harness 納入同一訓練流程。每個 task-harness pair 視為獨立訓練實例，統一抽樣後聯合更新模型。

7. **評估與部署**  
   在獨立測試集上測量 Pass@1 與任務完成率，驗證模型在實際推論環境中的表現。部署時保留 proxy 與監控機制，持續收集線上軌跡以供下一輪迭代。

## 潛在風險與注意事項

- **訓練-推論不一致**  
  若訓練時使用的 tokenizer、取樣參數或推論引擎與實際 harness 不同，模型可能學到無法在真實環境複現的行為。務必透過 token-in-token-out 機制與 importance-sampling correction 對齊兩者。

- **沙箱資源耗盡與狀態污染**  
  長程任務容易產生殘留檔案、背景程序或網路連線。若沙箱清理不完全，會導致後續 rollout 狀態錯誤。建議每次 rollout 後強制銷毀沙箱，並對有狀態環境使用快照還原。

- **獎勵稀疏或延遲**  
  長程任務常在最後才給予 reward，中間步驟缺乏訊號。可考慮加入中間獎勵（例如工具執行成功、檔案正確產生），或利用 GRPO 的群組相對優勢來穩定訓練。

- **前綴樹重建錯誤**  
  若 proxy 未正確記錄呼叫間的父子關係，重建出的軌跡會出現順序錯亂或遺漏。需在資料處理階段加入軌跡完整性檢查與人工抽樣驗證。

- **異質 harness 的獎勵尺度差異**  
  Mix-harness training 時，不同 harness 的任務難度與 reward 分布可能不同，導致訓練偏向某一 harness。建議對 reward 做標準化，或依任務難度動態調整抽樣權重。

## 與其他技術的整合建議

- **與現有 LLM 推論服務整合**  
  Serving proxy 可部署為反向代理，無需修改 harness 內部程式碼即可接入現有的 vLLM、TGI 或 OpenAI-compatible API。這讓企業能在不改動現有系統的前提下導入黑箱 RL。

- **與 MLOps 與實驗追蹤工具整合**  
  將 reward、KL 散度、value loss、rollout 成功率與沙箱執行狀態記錄到 Weights & Biases、MLflow 或自訂監控平台，方便追蹤長期訓練趨勢與異常。

- **與現有 agent harness 生態整合**  
  對於 Claude Code、OpenClaw 或內部 harness，可透過標準化 adapter 將它們封裝進 sandbox。未來新增 harness 時，只需實作環境初始化、任務提交與 reward 提取介面。

- **與 RLHF / SFT pipeline 銜接**  
  在進入黑箱 RL 前，可先以 SFT 或偏好學習建立基礎策略，縮短 RL 收斂時間。RL 訓練後也可再進行偏好微調，進一步對齊輸出風格與安全準則。

- **與企業身份驗證與稽核系統整合**  
  由於代理會執行 shell、API 與檔案操作，建議將 sandbox 接入企業的 IAM、日誌稽核與網路隔離政策，確保訓練與部署符合資安規範。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從「適用場景」與「實作前置條件」讀起，理解 agent harness、黑箱強化學習與沙箱隔離的基本概念。不必急著深入 PPO/GRPO 的數學細節，重點是掌握「為什麼要把 harness 當成黑箱」以及「為什麼需要前綴樹重建軌跡」這兩個核心設計動機。

**AI 工程師**：請聚焦「實作步驟建議」與「與其他技術的整合建議」，特別注意 serving proxy 的部署方式、前綴樹的資料處理流程，以及訓練-推論一致性的實作細節。這些是將論文方法落地到生產環境的關鍵。

**研究人員**：建議深入閱讀方法論部分，包括黑箱 RL 的問題建模、PPO 與 GRPO 在樹狀結構上的適配、mix-harness training 的取樣與最佳化設計。可進一步思考如何將此方法擴展到更複雜的多代理環境或連續決策任務。

**產品經理**：請優先參考「適用場景」與「潛在風險與注意事項」，評估導入本框架的商業價值與成本。重點關注需要哪些資料、運算資源與跨團隊協作（ML、infra、資安），以及 mix-harness training 如何降低未來維護多個 agent 系統的長期成本。
