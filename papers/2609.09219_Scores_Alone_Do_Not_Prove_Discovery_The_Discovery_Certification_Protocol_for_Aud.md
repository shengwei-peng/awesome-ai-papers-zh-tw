# 單靠分數無法證明發現：用於稽核 AI 研究代理的發現認證協定（DCP）

## ⚡ TL;DR

AI研究代理的分數難以證明真正發現，需區分原創成果、公開資訊復現與回饋效應。
提出發現認證協定DCP，以密封評估、匹配代理復現測試與回饋對照來認證成果。
在SQLite最佳化與虛擬催化劑控制稽核中，零復現且回饋效應顯著，並可由確定性驗證器重現。

## 摘要翻譯

AI 研究代理（AI research agents）結合先驗知識（prior knowledge）、公開來源（public sources）與實驗回饋（experimental feedback），以產生有用成果（useful outcomes）。發現認證協定（Discovery Certification Protocol, DCP）將關於這些成果的宣稱轉化為可執行的復現與回饋測試（executable recovery and feedback tests）。閘門 1（Gate 1）在密封評估（sealed evaluation）上驗證有用改進（useful improvement）。閘門 2（Gate 2）提供匹配代理（matched agents）註冊起始資訊（registered starting information）與觀測到的網頁內容（observed Web content），但隱藏目標研究歷程（target research history）。每個達到數值目標（numerical target）的有效路徑（valid route）都會提供一個復現見證（recovery witness），並觸發核心否決（Core veto）。DCP 核心（DCP Core）要求具備適當對照（adequate controls）、零次觀察到復現（zero observed recoveries），並針對單一全新註冊回合（fresh registered episode）中的復現（recovery）提供有限樣本上界（finite-sample bound）。選用的閘門 3（Gate 3）從共享檢查點（shared checkpoint）出發，測量真實回饋（truthful feedback）相對於特定中性策略（neutral policy）的平均效應（average effect of truthful feedback）。DCP 證據（DCP Evidence）在獨立虛無校準（independent null calibration）與註冊效應邊際（registered effect margin）之後加入此效應。兩項受控稽核（controlled audits）在不同模型下，於 SQLite 最佳化（SQLite optimization）與虛擬催化劑控制（virtual catalyst control）領域演練完整協定。兩者在 96 個回合中均觀察到零次復現，復現機率上界（upper bound）為 0.0468。每項配對研究（paired study）產生 30 次真實回饋下的復現（truthful recoveries）與零次中性回饋下的復現（neutral recoveries），並通過 60 對虛無研究（null studies）。其他案例則演練核心（Core）、已復現（recovered）與稽核不完整（audit-incomplete）決議。一個確定性、無 LLM 的驗證器（deterministic, LLM-free verifier）可從凍結證據（frozen evidence）重現這些決議。DCP 為 AI 研究中有用成果（useful outcomes）、替代路徑（alternative routes）與回饋效應（feedback effects）提供通用證據語言（common evidence language）。

### 核心貢獻（3～5點）
- 提出 DCP，將關於 AI 研究代理成果的宣稱轉化為可執行的復現與回饋測試，並以通用證據語言貫穿有用成果、替代路徑與回饋效應。
- 設計三階段認證架構：閘門 1 驗證密封評估上的有用改進；閘門 2 透過復現見證觸發核心否決；選用閘門 3 測量真實回饋相對於中性策略的平均效應。
- 確立 DCP 核心的嚴格條件：適當對照、零次觀察到復現，以及單一全新註冊回合中復現機率的有限樣本上界。
- 在 SQLite 最佳化與虛擬催化劑控制兩個真實領域執行受控稽核，展示完整協定的實證可行性與統計結果。
- 提供確定性、無 LLM 的驗證器，可從凍結證據重現 DCP 決議，確保認證結果的可重現性與可稽核性。

### 適合對象
AI 研究代理的開發者與研究者、關注 AI 研究可重現性與可驗證性的稽核人員、AI 安全與政策制定者，以及從事自動化科學發現與實驗設計方法學研究的學術社群。

## 深度分析

#### 方法論解析

本文提出「發現認證協定（Discovery Certification Protocol, DCP）」，其核心命題是：單一數值分數（score）不足以證明一項 AI 研究代理（AI research agent）的成果來自真正的研究過程，而必須透過可執行的復現（recovery）與回饋（feedback）測試，把宣稱轉換成可檢驗的證據。DCP 圍繞三個可測量問題設計：閘門 1（Gate 1）驗證成果在封存評估（sealed evaluation）上是否有用；閘門 2（Gate 2）測試在保留註冊起始資訊（registered starting information）與觀測到的網頁內容（observed Web content）但隱藏目標研究歷程（target research history）的條件下，匹配代理（matched agents）能否復現該數值目標（numerical target）；選用的閘門 3（Gate 3）則從共享檢查點（shared checkpoint）出發，隨機比較真實回饋（truthful feedback）與中性策略（neutral policy）的平均效應。

DCP 把一次稽核（audit）組織為五個物件：背景知識 K（background）、與目標執行研究動作無關的初始觀測 E₀（initial observations）、目標執行中產生的研究歷程 L*（research history）、最終輸出 A*（final output），以及判定復現的機器檢查 P（validity predicate）。這五個物件的關鍵在於資訊來源（provenance）的區分：E₀ 是任務開始前就固定的觀測，L* 則是代理選擇行動後才獲得的回饋。透過這條邊界，DCP 能將「先驗知識（prior knowledge）＋公開來源（public sources）」與「實驗回饋（experimental feedback）驅動的適應性研究」區分開來。

在方法論上，DCP 強調預先登記（precommitment／registration）：在目標執行之前，必須固定任務、模型、資訊邊界、介面、工具、預算（budget）、基線（baseline）、有效性規則、選取與停止規則，以及統計分析方法。這種預先登記消耗預先分配的錯誤預算，並確保後續的封存測試（sealed test）與復現測試不是事後挑選的。閘門 1 在此框架下驗證 A* 相對於基線具有有用改進（useful improvement）。

閘門 2 是 DCP Core 的關鍵。它讓新鮮的匹配代理在與目標執行相同的註冊背景（registered background）、工具、預算與擷取的網頁內容（captured Web content）下運行，但刻意不給予 L*。任何達到分數閾值（score threshold）且通過有效性檢查（validity check）的執行，都構成復現見證（recovery witness），並觸發核心否決（Core veto）——即該成果無法取得 DCP Core 認證。值得注意的是，DCP 承認所有「有效路徑（valid route）」：挑戰者可以組合已知元件、跨領域遷移技術（transfer a technique across domains），或提出不同實作（implementation），只要達到相同的數值目標即算復現。這使得復現規則具有跨領域可攜性（portability），同時也避免把「歷史優先權（historical priority）」這種學術判斷混進技術認證。

DCP Core 的正面決議（positive Core decision）需要三個條件：適當對照（adequate controls）、零次觀察到復現（zero observed recoveries），以及對全新註冊回合（fresh registered episode）復現機率（recovery probability）的有限樣本界限（finite-sample bound）。復現見證與復現機率在證據結構中扮演互補角色：前者只要存在就足以終結稽核（標記為 recovered decisions），後者則在沒有見證時提供統計保證，說明復現機率被壓在註冊上界 ρ 以下。

選用的閘門 3 對應 DCP Evidence。它從共享檢查點出發，隨機分配真實回饋或中性回饋（neutral feedback），測量真實回饋的平均效應（average effect of truthful feedback）。為了避免中性通道本身攜帶訊號，協定要求獨立虛無校準（independent null calibration），並使用預先登記的效應邊際（registered effect margin）。只有當真實回饋顯著優於中性策略、且通過虛無研究（null studies）時，DCP Evidence 才會把這個效應加入證據包。這樣的設計把「目標執行成功」、「成果可被復現」與「回饋確實有用」三種主張分離，避免單一分數同時承載因果、統計與實用性宣稱。

最後，DCP 強調證據的可重播性：一個確定性、無 LLM 的驗證器（deterministic, LLM-free verifier）能從凍結證據（frozen evidence）重現所有決議，這讓認證結果不依賴於大型語言模型的隨機性，也降低外部審查者重製判斷的門檻。

#### 實驗數據解讀

本文在兩個差異顯著的領域進行受控稽核（controlled audits）：SQLite 最佳化（SQLite optimization）與虛擬催化劑控制（virtual catalyst control），並使用不同模型，以展示 DCP 的可攜性。兩項稽核均執行了閘門 1、閘門 2 與閘門 3 的完整流程。

在閘門 2 的復現測試中，每個領域都進行了 96 個全新註冊回合，結果觀察到零次復現，並報告復現機率的上界（upper bound）為 0.0468。這個數字是 DCP Core 能夠通過的統計基礎：在沒有發現任何復現見證的前提下，有限樣本界限把單一新回合的復現機率壓在約 4.68% 以下。若註冊時設定的可接受上界 ρ 大於或等於此值，則該成果在註冊範圍（registered scope）內通過核心認證。需要強調的是，這並非證明「絕對無法復現」，而是證明「在給定的資訊邊界、預算與統計信心下，沒有觀察到復現，且復現機率被有效控制」。

在閘門 3 的配對研究（paired study）中，每個領域都產生了 30 次真實回饋下的復現（truthful recoveries）與 0 次中性回饋下的復現（neutral recoveries），並通過了 60 對虛無研究（60-pair null studies）。這顯示：當代理從共享檢查點出發，獲得真實實驗測量作為回饋時，達成目標的機率遠高於獲得中性回饋的對照組。30 比 0 的對比是一個強烈的效應訊號，支持「實驗回饋確實驅動了有用成果」這一因果宣稱，從而為 DCP Evidence 提供正向結論。

此外，作者還報告了額外案例，用來演練三種決議：DCP Core 通過、已復現決議（recovered decisions）與稽核不完整決議（audit-incomplete decisions）。這些案例說明協定能夠區分「證據足夠支持認證」、「發現替代路徑因而否決」以及「稽核設計或執行不完整而無法下結論」等不同情境，避免把「無法認證」誤報為「已認證」。

整體而言，實驗數據傳達的訊息是：單靠分數無法區分「真正由實驗回饋驅動的發現」與「僅由先驗知識或公開資訊即可達成的結果」；但結合封存評估、零復現的有限樣本界限，以及真實回饋相對中性策略的隨機化效應，DCP 提供了一個比傳統排行榜更嚴謹的證據鏈。

#### 與現有研究的比較

在 AI 研究代理的評估光譜中，DCP 位於一個獨特的位置。AlphaTensor、AlphaDev、FunSearch、AlphaEvolve 等系統強調以目標評估（objective evaluation）驅動搜尋，但它們通常不區分「成果來自內部先驗知識」還是「來自實驗回饋」。The AI Scientist、AI co-scientist 等則進一步自動化假設生成與論文撰寫，但同樣缺乏針對資訊邊界與回饋效應的正式稽核。DCP 的貢獻在於把「成果層級復現測試」與「回饋介入測試」引入這些評估框架，使其能夠區分不同來源的研究貢獻。

與 Ning 等人（2026a）的專家代理研究相比，該研究移除先前試驗歷史但保留當前最佳程式與分數；DCP 則進一步系統化，明確定義註冊背景、初始觀測、擷取網頁內容與研究歷程的邊界，並允許挑戰者透過任何有效路徑達標。與分子／材料科學代理中「凍結特定介入進行保留評估」的做法（Ning et al., 2026b,c）相比，DCP 提供了一個可執行的、以數值閾值為基礎的復現規則，而不僅是固定某些實驗條件。

在基準測試方面，MLE-bench、MLGym、MLR-Bench、PaperBench、DiscoveryWorld、FIRE-Bench 等分別評估工程能力、開放式研究、論文複製、科學行動與解釋性知識、以及已發表科學見解的再發現。DCP 並非要取代這些基準，而是為它們提供一種通用的證據語言（common evidence language）：任何產生數值成果的任務，都可以附加一個 DCP 稽核，說明該成果是否可被復現、以及回饋是否帶來增益。

在迭代回饋文獻中，ReAct、Tree of Thoughts、Reflexion、Self-Refine 等發展出工具使用、反思與回饋機制，但大多缺乏隨機化對照。DCP 的閘門 3 借鑑 Rubin（1974）的潛在結果框架，以成對隨機化比較（randomized comparison）評估回饋效應，並透過獨立虛無校準與預先登記確認性選擇（preregistered confirmatory choices）降低假陽性。這與 Nosek 等人（2018）倡議的預先登記精神一致。

在評估完整性與過程認證方面，既有研究關注資料污染（contamination）、記憶化（memorization）與先驗暴露的影響；DeepResearchGym 提供固定網頁語料庫的穩定檢索；SWE-bench 強調可執行輸出；Proof-of-Learning 記錄訓練狀態以證明訓練過程。DCP 的獨特之處在於把「可執行成果」與「註冊的反事實實驗（registered counterfactual experiments）」結合：它不僅問「模型是否記得答案」，更問「在相同先備資訊下，其他代理能否不經目標研究歷程就達成同樣結果」。

DCP 的主要優勢包括：（1）以數值復現規則接受替代路徑（alternative routes），避免過度狹隘地定義「抄襲」；（2）把效用、可復現性、回饋效應三種宣稱分離；（3）提供有限樣本界限與確定性驗證器，增強統計與操作上的可重播性。

然而其限制也同樣明顯。首先，有效性規則 P 與中性策略的設計高度依賴領域知識，不同領域可能對「何謂中性回饋」爭議不休。其次，擷取的網頁內容無法完美重現動態或受授權限制的公開來源，可能低估外部資訊的可及性。第三，DCP 不保證歷史新穎性（historical novelty），只認證在註冊範圍內的非復現性。第四，96 個回合的稽核雖然給出約 4.68% 的上界，但這仍是機率性保證，而非邏輯上的不可能。最後，執行完整 DCP 稽核需要大量運算與實驗資源，可能限制其在快速迭代研究中的普及。

#### 可重現性評估

DCP 在可重現性（reproducibility）方面的最強主張，是存在一個確定性、無 LLM 的驗證器，能夠從凍結證據重現所有決議。這意味著一旦證據包被固定，任何第三方都不需要重新呼叫大型語言模型，也不需要擔心取樣隨機性，就能獨立檢查 DCP Core 與 DCP Evidence 的判斷。這對於科學審查極具價值，因為它把「信任模型輸出」轉化為「信任可執行的證據與確定性程式」。

然而，根據目前提供的全文脈絡，關於開源程式碼、資料集、模型權重或完整證據包是否公開釋出，並沒有具體說明。要讓 DCP 真正達到獨立可重現，至少需要釋出以下內容：（1）凍結的註冊協定，包括任務描述、模型版本、工具與預算；（2）目標執行的完整研究歷程 L* 與最終輸出 A*；（3）擷取的網頁內容與重播機制；（4）匹配代理的實作、種子與執行腳本；（5）有效性規則 P、分數閾值與統計分析計畫；（6）共享檢查點、中性策略與真實回饋通道的實作；（7）確定性驗證器的原始碼與輸入格式說明。

此外，即使驗證器本身是確定性的，底層環境（例如 SQLite 版本、虛擬催化劑模擬器版本、網頁內容授權）仍可能影響重現結果。擷取網頁內容涉及版權與動態內容問題，可能無法完全公開；模型權重若來自專有 API，也會限制外部審查。因此，DCP 的「可重現性」在概念上很強，但在實務上仍取決於作者是否願意釋出足夠的凍結證據與執行環境快照。

總結來說，DCP 提供了一個可重播決議的架構，但從「架構可重播」到「社群可獨立驗證」之間，還需要完整的開源釋出與標準化的證據格式。

#### 未來研究方向

DCP 的提出為 AI 研究代理的證據評估開啟了多條後續研究路徑。

第一，擴展到難以定義數值目標的開放式科學發現。目前 DCP 依賴可執行的有效性規則 P 與分數閾值，對於數學定理、概念性見解或質性發現，如何設計適當的復現測試仍是一大挑戰。未來可研究以形式化證明、同行評審模擬或結構化知識圖譜作為替代的有效性規則。

第二，自動化中性策略與有效性規則的設計。現階段 P 與 neutral policy 需要領域專家手工設計，容易引入偏見。可以發展「後設協定（meta-protocol）」，讓社群或自動化程序競爭提出最保守但仍有意義的中性策略，並透過對抗性挑戰（adversarial challenges）檢驗其嚴謹性。

第三，降低稽核成本。96 個回合的零復現雖已給出有限樣本界限，但對於高運算成本的科學模擬而言仍屬昂貴。未來可結合序列檢定（sequential testing）或適應性取樣（adaptive sampling），在維持統計保證的同時減少所需回合數。

第四，將 DCP 整合進代理訓練流程。目前 DCP 主要作為事後稽核工具；未來可探索在訓練階段就把「復現難度」與「回饋效應」納入獎勵 shaping，鼓勵代理發展出真正依賴實驗回饋而非先驗記憶的策略。

第五，處理人機協作與多代理情境。DCP 目前區分 E₀ 與 L* 的邊界在人類提供指導時可能變得模糊。未來需要更細緻的「人類—代理譜系（human-agent lineage）」追蹤機制，以判斷哪些指導屬於預先固定的背景，哪些屬於適應性回饋。

第六，建立標準化的 DCP 證據登錄平台。類似臨床試驗預先登錄系統，AI 研究社群可以建立 DCP 註冊庫，讓研究者在執行目標執行前公開其協定、錯誤預算與分析計畫，從而提升整體研究的透明度與可累積性。

第七，研究模型規模與搜尋預算對復現機率的影響。隨著基礎模型能力增強，許多過去需要實驗回饋才能發現的結果，可能僅靠強大的先驗知識與大規模推理就能復現。系統性地刻畫「何時復現變得不可避免」，有助於校準 DCP 的認證標準。

第八，延伸回饋效應估計方法。目前閘門 3 聚焦於二元復現與平均效應；未來可發展連續結果變數、異質性處理效應（heterogeneous treatment effects），以及長期序列回饋的因果推論方法。

最後，DCP 也呼應了更廣泛的 AI 治理議題：如何合法且倫理地擷取、儲存與重播網頁內容與專有資料，將是該協定從研究原型走向實務應用時必須面對的制度挑戰。

## 論文問答

【背景與動機】

**Q1：DCP 要解決什麼問題？為何單靠分數不足以證明 AI 研究代理的發現？**
A：DCP 針對的是 AI 研究代理在自動化研究後，僅以分數或效用宣稱「發現」時，難以區分真正來自實驗回饋的創新與先驗知識、公開資料或記憶內容的問題。單靠密封評估只能確認最終產出有用，卻無法說明該結果是否可由相同起始資訊與公開資源輕易復現，也無法證明實驗回饋確實推動了改進。因此 DCP 把「高分」當成起點，進一步透過可執行的復現測試與回饋效應測試，建立測量結果與研究過程之間的證據連結。

**Q2：現有評估方法為何不足以稽核 AI 研究代理？**
A：現有方法多聚焦於密封測試分數或任務成功率，但較少同時檢驗「相同資訊邊界下能否復現」以及「回饋是否帶來因果效應」。實作與基線選擇會顯著影響測得增益，而同一固定構想由不同獨立實作執行時，排名也可能改變，這使得單一數值難以反映真正的研究貢獻。此外，既有污染研究與記憶研究雖能檢測先驗暴露，但缺乏把執行結果、註冊對照與實驗回饋整合成可重現證據包的機制。

**Q3：為何需要把「有用成果」「可復現性」與「回饋效應」分開檢驗？**
A：這三個問題具有不同的證據意義：高分只代表產出有用，復現見證代表該結果在註冊範圍內可被替代路徑達成，而回饋效應則能說明實驗觀測是否真正改變了代理找到解決方案的機率。把它們混為一談會導致過度推論，例如把可輕易復現的結果誤認為需要實驗回饋才能發現。DCP 透過閘門 1、閘門 2 與選用的閘門 3 分別處理這三個問題，使核心認證、統計結論與因果推論各司其職。

【方法與創新】

**Q4：DCP 的三個閘門各自驗證什麼？**
A：閘門 1 在封存資料上驗證最終產出 A* 相對基線具有有用改進，確保宣稱的數值目標確實成立。閘門 2 給予全新匹配代理已註冊的起始資訊與觀測到的網頁內容，但隱藏目標研究歷程 L*，任何有效達到 x−ε 的復現見證都會觸發核心否決。選用的閘門 3 則從共享檢查點隨機比較真實回饋與中性策略，透過獨立虛無校準與註冊效應邊際來估計回饋的平均效應，形成 DCP Evidence。

**Q5：DCP 的核心設計選擇「承認所有達成相同數值結果的有效路徑」有何意義？**
A：這項選擇承認挑戰者可以組合熟悉元件、跨領域遷移技術，或提出不同實作，只要通過有效性檢查與分數閾值即視為復現。它讓稽核規則可跨研究領域移植，並避免把「歷史優先性」與「結果可復現性」混為一談。同時，這也確保 DCP Core 的認證焦點在於：在目標執行所依賴的實驗回饋與研究歷程被隱藏後，結果是否仍然難以在註冊範圍內重現。

**Q6：DCP 如何透過五個物件與預先登記界定資訊邊界？**
A：DCP 以背景 K、初始觀測 E0、目標研究歷程 L*、最終輸出 A* 與有效性謂詞 P 五個物件來區分哪些資訊屬於先備知識、哪些來自實驗回饋。E0 與 L* 的區分依據資訊來源：實驗開始前即提供的觀測屬於 E0，因代理選擇行動而產生的測量則屬於 L*。在目標執行前，必須完成註冊，固定任務、模型、工具、預算、基線、有效性規則與統計分析，並預先分配錯誤預算，以確保後續所有對照與檢驗都是確認性而非探索性的。

【實驗與結果】

**Q7：兩項受控稽核的關鍵結果是什麼？**
A：論文在 SQLite 最佳化與虛擬催化劑控制兩個領域執行了完整協定，並在不同模型下進行測試。每項稽核在 96 個全新註冊回合中皆觀察到零次復現，復現機率的有限樣本上界為 0.0468，滿足 DCP Core 的條件。在配對研究中，真實回饋組各產生 30 次復現，而中性回饋組為零次，且通過 60 對的虛無研究校準，支持 DCP Evidence 的效應宣稱。

**Q8：復現上界 0.0468 在 DCP Core 中具有什麼意義？**
A：0.0468 是基於 96 回合零復現觀察所計算的有限樣本復現機率上界，代表在註冊條件下，匹配代理於全新回合中達到數值目標的機率被統計地限制在很低水準。這個上界與適當對照、零觀察復現共同構成正向核心決議的必要條件。它並非證明絕對不可能復現，而是提供一個可重現、可審查的量化保證，說明目標結果在隱藏研究歷程後並未輕易出現。

**Q9：論文還展示了哪些額外案例與驗證機制？**
A：除了兩項通過核心認證的稽核外，論文還演練了「已復現決議」與「稽核不完整決議」等案例，說明協定在不同證據狀態下的輸出。所有決議都由一個確定性、無 LLM 的驗證器根據凍結證據重新產生，確保判斷不依賴大型語言模型的隨機詮釋。這些設計讓 DCP 的結論具備可移植的證據包與獨立可重播性，便於第三方審查。

【應用與影響】

**Q10：DCP 在實務上可以如何應用？**
A：DCP 可用於稽核 AI 研究代理所報告的程式、模型、資料產品或實驗配方，把宣稱轉換成可執行的復現與回饋測試。研究團隊在發表前可註冊任務與資訊邊界，並提供凍結證據包供審查者以確定性驗證器重播決議。這種通用證據語言能跨越軟體最佳化、虛擬實驗控制等不同領域，讓「有用成果」「替代路徑」與「回饋效應」的溝通標準化。

**Q11：在產品與營運層面導入 DCP 需要哪些考量？**
A：導入時必須在目標執行前完成註冊，固定模型、預算、基線、選擇規則與統計分析，並預先分配錯誤預算給每一項確認性稽核。營運流程需要擷取並重播觀測到的網頁內容，保存凍結證據，並確保匹配代理無法取得目標研究歷程。此外，使用確定性、無 LLM 的驗證器可降低審查成本與爭議，使認證決議能在不同時間與環境下被獨立重現。

**Q12：DCP 對 AI 研究評估領域可能帶來什麼影響？**
A：DCP 把證書資格、統計結論與因果推論分離，提供了一個跨領域通用的證據框架，可補充現有的 MLE-bench、SWE-bench、FIRE-Bench 等評估基準。它強調可執行產出與註冊反事實實驗的結合，有助於減少因基線或實作選擇造成的測量偏差。長遠來看，這能促進 AI 研究代理從「分數競賽」轉向更具可審查性與可重現性的研究協作。

【限制與未來】

**Q13：DCP 有哪些已承認的限制？**
A：DCP 並不直接判定歷史優先性或心理新穎性，而是專注於結果在註冊資訊邊界內的可復現性與回饋效應。它需要嚴格的預先登記與資源投入，包括執行大量匹配代理回合與配對研究，對於探索性研究可能成本過高。此外，有限樣本上界是保守的統計保證，無法排除所有未來可能出現的替代路徑。

**Q14：協定如何處理「已復現」與「稽核不完整」等失敗案例？**
A：一旦出現任何有效復現見證，即觸發核心否決，因為這表示目標結果可在不取得目標研究歷程的情況下於註冊範圍內達成。若對照不足、預算耗盡或證據凍結不完整，則會產生稽核不完整決議，表示無法給予核心認證。這些案例的演練顯示 DCP 的決議規則是明確且可執行的，能區分「證據反駁」「證據不足」與「證據支持」三種狀態。

**Q15：DCP 未來可以朝哪些方向發展？**
A：未來可將協定擴展到更多研究領域，例如數學構造、藥物分子設計或硬體加速器設計，以測試其可移植性。也可發展更精細的回饋介入設計與更緊的有限樣本界，降低稽核所需的回合數。最後，結合歷史優先性評估與領域專家審查，可進一步把 DCP 的結果層級證據轉化為完整的學術發現認定。

## 實務應用指南

## 適用場景

1. **自動化機器學習模型搜尋的宣稱驗證**  
   當 AI 研究代理聲稱發現新的模型架構、訓練技巧或超參數組合，並在公開排行榜上取得分數時，可用 DCP 封存一部分測試資料作為密封評估，再讓匹配代理在僅有註冊起始資訊與觀測到的網頁內容下嘗試復現，避免「分數高但只是過擬合或記憶」。

2. **AI 生成程式碼最佳化的可信稽核**  
   例如代理聲稱最佳化 SQLite 查詢、編譯器 pass 或資料結構實作。DCP 可將目標執行的執行歷程保留，僅釋出註冊背景與工具，讓獨立挑戰者嘗試達到相同數值目標；若無法復現，再透過 Gate 3 檢驗真實回饋相對於中性策略的平均效應。

3. **虛擬催化劑／材料／藥物發現的實驗設計審查**  
   在科學模擬環境中，代理透過反覆實驗回饋提出新配方或控制策略。DCP 可區分「先驗知識就能達標」與「實驗回饋真的帶來有用改進」，並以復現上界量化目標研究歷程的獨特貢獻。

4. **自主資料產品與分析管線的產出認證**  
   當代理自動產生特徵工程流程、資料清理腳本或視覺化報告時，DCP 可定義有效性檢查與分數閾值，確認最終資料產品在封存資料上的效用，並檢驗是否僅靠公開模板即可復現。

5. **LLM 研究助理產出論文主張的證據化**  
   對於聲稱「發現」某個數學構造、演算法變體或實驗洞見的 AI 系統，DCP 提供通用證據語言：把主張轉成可執行的復現與回饋測試，讓審查者用確定性、無 LLM 的驗證器重現決議。

## 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **資料** | 需預先註冊並封存：背景知識 K、獨立於目標執行的初始觀測 E₀、密封測試資料、觀測到的網頁內容 W_obs、目標執行歷程 L*。 |
| **運算** | 需能重複執行多個全新註冊回合（論文使用 96 個復現回合與 60 對回饋配對研究），並保留每回合的完整日誌與中繼檢查點。 |
| **技能** | 團隊需熟悉預先登記（preregistration）、實驗追蹤、統計假設檢定（有限樣本上界、等價區間檢定）、以及可重現容器化部署。 |
| **基礎設施** | 需有版本控制、模型倉儲、凍結證據儲存庫，以及能重播網頁內容與工具呼叫的確定性環境。 |
| **治理** | 需定義人機互動邊界：哪些人工指引屬於 E₀、哪些屬於目標執行歷程 L*，並在註冊時固定選擇規則與停止條件。 |

## 實作步驟建議

1. **定義有用成果與資訊邊界**  
   明確最終輸出 A*（程式、模型、資料產品或實驗配方）、有效性檢查 P、分數閾值，以及哪些資訊屬於 K、E₀、L*、W_obs。

2. **預先登錄完整實驗協定**  
   在執行目標代理前，註冊任務、模型、工具、預算、基線、選擇規則、停止條件與統計分析方法，並分配錯誤預算。

3. **執行目標執行並封存證據**  
   執行目標代理，記錄完整執行歷程 L*、擷取的網頁內容、中繼檢查點與最終輸出 A*。

4. **閘門 1：密封評估**  
   在封存資料上驗證 A* 是否達到宣稱的有用改進，確認分數 x 與相對基線的增益。

5. **閘門 2：復現測試與核心決議**  
   對多個匹配代理釋出 K、E₀、W_obs 與預算，但隱藏 L*。若出現任何復現見證，則觸發核心否決；若零次復現，則計算復現機率的有限樣本上界，決定是否通過 DCP Core。

6. **閘門 3：回饋效應證據（選用）**  
   從共享檢查點出發，隨機分配真實回饋與中性回饋，進行配對研究；透過獨立虛無校準與註冊效應邊際，評估 DCP Evidence。

7. **打包凍結證據並執行確定性驗證器**  
   將所有資料、程式碼、配置與決策規則打包成凍結證據，使用無 LLM 的確定性驗證器重現 DCP Core 與 DCP Evidence 決議。

## 潛在風險與注意事項

| 風險 | 說明與因應 |
|---|---|
| **密封資料過擬合** | 若代理反覆調參後才進行密封測試，分數可能不穩定。應嚴格區分開發、校準與封存資料，並在註冊時固定評估流程。 |
| **資訊經由網頁或工具外洩** | 觀測到的網頁內容若包含目標執行歷程的提示，會使復現測試失效。需完整擷取並審查 W_obs。 |
| **對照條件不足** | 若基線太弱或預算不匹配，「零次復現」可能不具說服力。應設計適當對照與多組挑戰者。 |
| **挑櫻桃式選擇回合** | 只報告未復現的回合會扭曲復現上界。必須預先登記回合數，並將所有已開始的稽核納入錯誤預算。 |
| **LLM 非確定性導致重現困難** | 匹配代理若使用隨機取樣，需固定亂數種子、溫度與工具回傳，或採用確定性後端。 |
| **混淆 Core 與 Evidence** | DCP Core 僅處理「目標成果是否難以復現」；DCP Evidence 才處理「回饋是否有效」。兩者決議不可混為一談。 |
| **人工指引污染** | 人類在執行中途給予的提示應歸入 L*，而非 E₀；註冊時必須清楚劃分。 |

## 與其他技術的整合建議

- **評測平台**：可將 DCP 疊加於 MLE-bench、SWE-bench、MLGym 或 PaperBench，把現有分數轉換成可執行的復現與回饋測試。
- **實驗追蹤工具**：透過 Weights & Biases、MLflow 或 Neptune 記錄 L*、超參數與中繼檢查點，確保每個全新註冊回合可追溯。
- **持續整合／部署**：在 CI/CD 中嵌入確定性驗證器，讓每次程式碼或模型更新都能自動重跑 DCP 決議。
- **容器與環境管理**：使用 Docker/Singularity 凍結工具鏈與依賴，並以 DVC 或 Quilt 版本化資料集，避免「在我機器上可以跑」的問題。
- **預先登記平台**：與 OSF、AsPredicted 或自建的註冊系統整合，確保 K、E₀、預算與分析方法在執行前即固定。
- **模型倉儲**：將 A* 與共享檢查點存入模型倉儲（如 Hugging Face Hub、MLflow Model Registry），方便匹配代理載入與比較。

## 給不同背景讀者的閱讀建議

**初學者**：先從圖 1 的三個閘門與詞彙表開始，理解「分數高不等於發現」的核心訊息；接著閱讀第 3 節的「成果與資訊邊界」表格，掌握 K、E₀、L*、A*、P 五個物件的區別，不必急著深入統計推導。

**AI 工程師**：重點看第 3 節的方法與兩個受控稽核案例，學習如何設計有效性檢查、封存資料流程、匹配代理環境，以及如何用確定性驗證器重現決議；實作時請特別注意版本控制、亂數種子與工具回傳的凍結。

**研究人員**：建議從第 1、2 節的動機與相關工作切入，比較 DCP 與現有評測基準、污染研究、實驗設計文獻的差異；深入閱讀 Core 與 Evidence 的統計定義，思考如何將其應用於自身領域的宣稱驗證。

**產品經理**：聚焦「適用場景」與「潛在風險」，把 DCP 視為一種產品信任機制：它能將 AI 研究代理的產出轉換成可審查、可重現的證據包，有助於對內控管研發品質、對外建立客戶與監管機構的信任；評估導入時請預留運算與預先登記流程的成本。
