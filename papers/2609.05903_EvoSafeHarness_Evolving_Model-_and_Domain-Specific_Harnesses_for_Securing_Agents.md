## ⚡ TL;DR

現有固定式安全約束器難以兼顧異質模型與領域的安全效用權衡。
本文提出 EvoSafeHarness，針對凍結模型與目標領域共同演化自然語言策略與可執行程式碼邏輯。
在四個代理基準上達到更優的安全效用前沿，顯著降低攻擊成功率且效用損失低。

## 摘要翻譯

大型語言模型（Large Language Model, LLM）代理正將語言轉化為真實世界影響，因此必須確保安全以抵禦間接提示注入（indirect prompt injection）與直接有害請求（direct harmful request）。系統層級安全約束器（system-level safety harness）在模型層級防禦（model-level defense）之外增加強制執行層（enforcement layer），但現有安全約束器（safety harness）通常由專家一次性設計，並套用於異質模型與領域（heterogeneous models and domains）。有效防護具有部署相依性（deployment-dependent）：不同模型在效用（utility）下降前所需的強制執行程度各異，而不同領域在必須管控的影響、狀態與行動序列上也有所不同。對某個模型而言足夠嚴格的安全約束器，可能對另一個模型造成過度阻擋（over-block）；而能跨領域遷移的策略（policy），也可能忽略應用專屬的安全關係（safety relations）。

我們提出 EvoSafeHarness，一個以安全為目標的最佳化框架，能為目標領域（target domain）中的凍結模型（frozen model）合成可部署的安全約束器。它同時搜尋自然語言策略（natural-language policy）與可執行程式碼邏輯（executable code logic），並以模型行為、領域規格以及全新上下文對抗性審查（fresh-context adversarial review）為引導，以排除基準特定規則（benchmark-specific rules）。橫跨四個代理基準家族，EvoSafeHarness 達成比固定式專家設計防禦（fixed expert-designed defense）更優的安全–效用前沿（safety-utility frontier）。在 DecodingTrust-Agent 上，它以 3.3 個百分點的效用成本（utility cost），將平均攻擊成功率（attack success rate, ASR）從 45.6% 降至 10.0%，並在 15 個格位中拿下 14 個最佳分數。在 AgentDojo 上，它在 0.0% ASR 下達到 82.8% 效用，是相同運作點（operating point）下 CaMeL 效用的兩倍，並能無需修改即遷移至未見的 AgentDyn 測試套件。它在 Agent-SafetyBench 上對每個受害者模型都取得最佳分數，並在精煉預算（refinement budget）為 16 的自適應 PAIR 攻擊（adaptive PAIR attacks）下，平均 ASR 仍低於 20%。分析顯示，領域語意（domain semantics）決定了需要哪些安全關係與軌跡狀態（trajectory state），而模型與執行階段行為（runtime behavior）則決定了這些關係應如何、在何處強制執行。

### 核心貢獻（3～5點）
- 提出 EvoSafeHarness，一個以安全為目標的最佳化框架，可針對凍結模型與目標領域自動合成可部署的模型專用與領域專用安全約束器。
- 聯合搜尋自然語言策略與可執行程式碼邏輯，並透過全新上下文對抗性審查排除基準特定規則，確保生成策略的泛化性與權威性。
- 在四個代理基準家族上達成優於固定式專家設計防禦的安全–效用前沿，顯著降低攻擊成功率並控制效用成本。
- 展現良好的跨領域遷移能力：AgentDojo 上訓練的安全約束器可無需修改直接套用於未見的 AgentDyn 測試套件。
- 透過實證分析指出領域語意決定所需安全關係與軌跡狀態，而模型與執行階段行為決定強制執行方式與位置。

### 適合對象
適合對 LLM 代理安全、系統層級防禦、自動化策略合成，以及安全–效用權衡有興趣的研究人員與工程師；特別是關注間接提示注入攻擊、直接有害請求防禦，以及需要為異質模型與多樣領域部署可適應安全約束器的實務開發者。

## 深度分析

#### 方法論解析

EvoSafeHarness 的核心命題是：**有效的代理（agent）安全防護必須同時是「模型專用（model-specific）」與「領域專用（domain-specific）」**。這是因為代理面對的威脅來自兩條不同通道：一是間接提示注入攻擊（indirect prompt injection attack），對手將有害指令嵌入電子郵件、網頁或文件等外部內容（external content），讓代理在處理資料時誤把不受信任內容（untrusted content）當成受信任指令（trusted instructions）；二是直接攻擊（direct attack），惡意使用者透過名義使用者通道（nominal user channel）直接下達有害指令（harmful instruction），例如要求轉帳超出核准上限（approved limit）、刪除生產資料（production data）或洩漏受保護憑證（protected credentials）。模型層級防禦（model-level defense）雖能提升模型辨識能力，但無法提供獨立於模型行為的系統層級強制邊界（enforcement boundary），因此需要安全約束器（safety harness）作為額外的強制執行層（enforcement layer）。

然而，現有的固定式專家設計防禦（fixed expert-designed defense）通常把同一套策略與控制流程套用到異質模型與領域（heterogeneous models and domains）上，導致兩種失效模式：對已經高度安全對齊的模型（如 Claude Opus）過度阻擋（over-block），使效用（utility）崩潰；對防禦較弱的模型則防禦不足，攻擊成功率（ASR，attack success rate）仍高。同時，不同領域需要不同的安全關係（safety relations）與軌跡狀態（trajectory state）：檔案系統領域需檢查命令效果、敏感路徑與機密移動；金融領域則需區分交易與資金外流、限制收款方並維護交易歷史，以偵測跨步驟的洗售交易（wash trading）。單一固定策略無法同時滿足這些語意差異。

EvoSafeHarness 因此將安全約束器設計視為一個**針對凍結模型（frozen model）與目標領域（target domain）的最佳化問題**。它聯合搜尋兩類互補元件：

1. **自然語言策略（natural-language policy）**：例如系統層級提醒、工具呼叫前的有害行為判斷（harmful-action check）、範圍審查（scope auditor）等，用於引導或約束模型的推理與工具選擇。
2. **可執行程式碼邏輯（executable code logic）**：例如命令與檔案過濾器、機密檔案偵測、資金流向追蹤器、交易分類帳、軌跡驗證（trajectory validation）與執行點控制等，用於在執行階段強制攔截或改放行為。

這兩類元件會根據**模型行為**、**領域規格**（領域中的效果、狀態與動作序列）以及**全新上下文對抗性審查（fresh-context adversarial review）**進行迭代評估。其中，全新上下文對抗性審查是避免搜尋過程走捷徑的關鍵：它讓一個獨立的審查者在沒有先前上下文的情況下檢視候選約束器，找出僅針對基準特定規則（benchmark-specific rules）或表層特徵（如檔名、路徑）過度擬合的防禦，並拒絕這類規則。如此一來，最佳化目標不只是降低 ASR，而是同時維持效用，避免「全部拒絕」這種效用崩潰的偽安全解。

在執行架構上，EvoSafeHarness 會在軌跡（trajectory）的多個位置插入強制點：工具呼叫前（before tool-call）進行有害性與範圍判斷、工具呼叫時進行命令或交易過濾、工具呼叫後（after tool-call）追蹤資料流與狀態更新，並在軌跡層級維護所需狀態。領域語意（domain semantics）決定需要哪些安全關係與軌跡狀態；模型與執行階段行為（runtime behavior）則決定這些關係應在何處、以多強的力度強制執行。例如，對 Claude Sonnet 4.6 這類對齊良好的模型，輕量級法官（judge）即可達到高安全性；而對 GLM-5 這類較易受對抗指令影響的模型，則需要層層過濾（layered filters）才能有效降低 ASR。

#### 實驗數據解讀

論文在四個代理基準家族上進行評估，數據呈現出一致的安全–效用權衡（safety–utility trade-off）優勢：

- **DecodingTrust-Agent**：EvoSafeHarness 將平均攻擊成功率（ASR）從 45.6% 降至 10.0%，而效用僅下降 3.3 個百分點，並在 15 個評估格子中拿下 14 個最佳成績。這表示該方法在多種攻擊情境與受害者模型組合中，幾乎全面優於固定防禦，且沒有為了安全性而大幅犧牲正常任務完成率。
- **AgentDojo**：在 0.0% ASR 的運作點（operating point）下，EvoSafeHarness 仍達到 82.8% 的效用，是 CaMeL 在相同運作點下效用的兩倍。這直接說明固定式能力強制執行（capability enforcement）雖然能擋下攻擊，卻會對正常任務造成過度阻擋；而模型專用調整能精準找到「安全且有用」的設定。
- **AgentDyn（AgentDojo 的未見測試套件）**：EvoSafeHarness 能夠原封不動地遷移到未見過的 AgentDyn 套件上。這點非常重要，因為它證明搜尋出的約束器並非單純記憶基準題目，而是捕捉了領域層級的安全語意，具備一定程度的領域內泛化能力。
- **Agent-SafetyBench**：對於每一位受害者模型，EvoSafeHarness 都取得最佳分數；即使在精煉預算（refinement budget）為 16 的自適應 PAIR 攻擊（adaptive PAIR attacks）下，平均 ASR 仍低於 20%。這顯示該方法對自動化越獄攻擊具備相當的穩健性，對手即使能迭代調整攻擊提示，也難以輕易繞過搜尋出的約束器。

綜合來看，實驗結果支持論文的核心論點：**安全–效用前沿（safety-utility frontier）的提升來自於同時針對模型與領域進行客製化**。單純提高防禦強度會壓垮效用；單純放寬限制會讓風險殘留。EvoSafeHarness 透過行為回饋找到每個模型×領域部署的最佳中間點。

#### 與現有研究的比較

相較於模型層級防禦（model-level defense），EvoSafeHarness 的定位是**互補的系統層級防禦（system-level defense）**。模型層級方法致力於讓模型更懂得區分受信任指令與不受信任內容、更傾向拒絕不安全請求（unsafe request），但它們無法提供獨立於模型行為的強制邊界。EvoSafeHarness 則在模型之外建立一個可驗證、可更新的執行層，即使模型被繞過，約束器仍可攔截有害行動。

在系統層級防禦中，現有研究涵蓋來源標記（provenance marking）、注入偵測（injection detection）、軌跡驗證、能力強制執行（capability enforcement）與生命週期層級執行控制（lifecycle-level execution control）等機制。CaMeL 是其中一個代表性的固定式專家設計防禦，透過限制模型可使用的工具能力來降低風險。然而 CaMeL 的實驗數據顯示：對 Claude 會造成效用崩潰（utility crash），對 GLM-5 則仍有顯著 ASR，呈現「對某些模型過度防禦、對某些模型防禦不足」的問題。EvoSafeHarness 透過模型專用調整解決了這個問題。

與 Meta-Harness 相比，兩者都採用基於行為回饋的代理式程式碼搜尋來自動設計約束器。但 Meta-Harness 原本針對的是一般任務效能，若直接將獎勵函數替換為攻擊成功率，會出現三個危險捷徑：全部拒絕導致效用崩潰、過度擬合評估集中的表層特徵、以及產生僅適用於特定基準的規則。EvoSafeHarness 針對安全性任務加入了三項關鍵設計：明確的效用保留目標、領域規格引導的語意搜尋，以及全新上下文對抗性審查來剔除過擬合規則。這使其能夠搜尋出真正可部署、可泛化的約束器，而非僅在評估數字上好看的偽解。

**限制方面**，EvoSafeHarness 仍有一些值得注意的弱點。首先，它需要高品質的目標領域規格與足夠的行為回饋資料，若領域規格不完整，搜尋出的約束器可能遺漏關鍵安全關係。其次，自動生成的可執行程式碼邏輯可能存在錯誤或被對手利用的漏洞，目前並無形式化驗證保證。第三，雖然在自適應 PAIR 攻擊下表現穩健，但面對更強大、擁有更大精煉預算或完全了解約束器內部的對手時，安全性仍可能下降。此外，實驗集中在幾個公開基準，真實世界部署中的多樣威脅與長尾情境可能未被充分覆蓋。最後，搜尋過程本身需要多次評估模型行為，計算成本可能不低。

#### 可重現性評估

就本文提供的上下文而言，**作者並未明確說明是否釋出原始碼、資料集或模型權重**。評估所使用的基準——DecodingTrust-Agent、AgentDojo、AgentDyn 與 Agent-SafetyBench——屬於公開的代理安全基準，理論上其他研究者可以取得；但 EvoSafeHarness 本身依賴的搜尋演算法、提示模板（prompt templates）、領域規格格式、以及用於全新上下文對抗性審查的審查者模型設定，目前尚未在提供的內容中揭露。

由於方法涉及對多個可能為專有 API 的模型（如 Claude Opus、GLM-5、Kimi、DeepSeek）進行行為回饋評估，即使程式碼開源，若無法取得相同模型版本與 API 行為，重現 exact 數字仍有困難。因此，在論文正式釋出實作與完整超參數之前，可重現性（reproducibility）可評估為**中等偏低**：概念與高階流程可復現，但端到端重現論文報告的數據需要額外的工程細節與模型存取權限。

為提升可重現性，建議作者未來釋出：搜尋演算法的虛擬碼與實作、每個領域的領域規格範例、自然語言策略與可執行程式碼邏輯的候選空間定義、評估協議（包括 benign utility 與 ASR 的計算方式）、以及所用模型版本與 API 設定。

#### 未來研究方向

EvoSafeHarness 開啟了自動化安全約束器設計的研究方向，未來可從以下幾個面向延伸：

1. **形式化驗證與沙箱執行**：目前生成的可執行程式碼邏輯依賴測試回饋，未來可結合靜態分析、符號執行或形式化方法，證明約束器在特定領域規格下不會產生誤放行為，並在沙箱中安全執行自動生成的程式碼。
2. **線上適應與持續學習**：現有框架針對凍結模型與固定領域進行一次性最佳化。未來可發展線上版本，在部署後根據新的攻擊樣本與事件回饋持續精煉約束器，同時避免災難性遺忘與效用漂移。
3. **跨領域元約束器學習**：雖然 EvoSafeHarness 已能遷移到同一領域家族的未見任務，但跨領域（如從金融到醫療或 IoT）仍需重新搜尋。可研究元學習（meta-learning）方法，讓約束器設計知識在不同領域間遷移，降低每次部署的搜尋成本。
4. **更強大的對抗性評估**：除了 PAIR 攻擊，未來應測試對手完全知道約束器結構的白盒攻擊、多輪對話攻擊、以及結合社會工程學的複合攻擊，以建立更可信的安全邊界。
5. **與模型層級防禦的聯合最佳化**：EvoSafeHarness 假設模型已凍結。未來可同時最佳化模型微調與約束器設計，讓兩層防禦協同演化，達到更優的安全–效用權衡。
6. **人機協作與可解釋性**：自動生成的自然語言策略與程式碼邏輯需要對營運團隊透明。未來可發展可解釋的約束器表示、互動式政策審查介面，以及人類在迴路（human-in-the-loop）的治理機制。
7. **效率與部署成本**：搜尋過程涉及大量模型呼叫與軌跡評估，未來可研究輕量化搜尋、快取機制、或將搜尋出的約束器蒸餾（distillation）成更輕量的執行元件，使其適合低延遲生產環境。
8. **多代理與分散式系統**：當多個代理協作或競爭時，單一代理的約束器可能不足以保證整體安全。未來可將 EvoSafeHarness 擴展至多代理系統，設計跨代理的安全協議與集體軌跡監控。

## 論文問答

**Q1：EvoSafeHarness 主要想解決什麼問題？**
A：隨著大型語言模型（LLM）代理被部署到金融帳戶、生產系統與外部服務等真實環境，單一回應的安全性已不足以保障整個反應軌跡的安全。現有的模型層級防禦雖然能提升模型辨識有害指令的能力，但無法提供獨立於模型行為的系統層級強制邊界。EvoSafeHarness 針對的就是這個缺口：為凍結模型在目標領域中自動合成一套可部署的系統層級安全約束器，以同時應對間接提示注入攻擊與直接有害請求。

**Q2：為什麼現有的固定式專家設計防禦無法滿足不同部署需求？**
A：現有方法通常由專家一次性設計，然後跨異質模型與領域套用同一套策略與控制流程，忽略了部署相依性。模型之間的差異會改變所需強制執行的強度：對安全對齊良好的模型過度限制會造成效用崩潰，而對較脆弱的模型則可能防禦不足。領域之間的差異更會改變安全關係、軌跡狀態與執行點，例如檔案系統需要檢查命令與機密外洩，金融領域則需追蹤資金流向與洗錢交易，單一固定策略無法同時適配這兩種語意。

**Q3：為什麼「部署相依的保護」對代理安全如此重要？**
A：因為安全約束器的邊際安全效益與邊際效用成本都會隨著目標模型而變化，對某個模型有利的安全–效用權衡不見得適用於另一個模型。同時，不同應用領域需要治理的效果、狀態與行動序列各不相同，這意味著策略必須根據領域語意進行調整。若忽視這兩種變異，就會出現過度阻擋或防禦不足的情況，因此必須針對每一個模型×領域的組合設計專屬的安全約束器。

**Q4：EvoSafeHarness 的核心方法是什麼？**
A：EvoSafeHarness 是一個專注於安全的最佳化框架，它會針對一個已凍結的模型在目標領域中，聯合搜尋自然語言策略與可執行程式碼邏輯。整個搜尋過程由模型行為、領域規格以及全新上下文對抗性審查共同引導，確保產生的安全約束器能真正反映部署需求。最終輸出的是一套可部署的安全約束器，而不是僅供參考的高層次原則。

**Q5：EvoSafeHarness 相較於先前自動化框架的關鍵創新在哪裡？**
A：雖然 Meta-Harness 等框架已展示可用行為回饋自動搜尋程式碼，但直接把任務獎勵換成攻擊成功率會導致危險捷徑，例如全部拒絕造成效用崩潰，或過度擬合評估資料中的表面特徵。EvoSafeHarness 透過全新上下文對抗性審查來拒絕基準特定規則，避免過度擬合。此外，它同時演化自然語言策略與可執行程式碼邏輯，使安全約束器能同時適配模型行為與領域語意。

**Q6：哪些設計選擇讓 EvoSafeHarness 能同時做到模型專用與領域專用？**
A：它把安全約束器視為自然語言策略與可執行程式碼邏輯的組合，並在搜尋空間中同時決定判斷器、過濾器、狀態追蹤與執行點。領域語意決定了需要哪些安全關係與軌跡狀態，例如金融領域的轉帳紀錄或作業系統領域的機密檔案過濾。模型與執行階段行為則決定這些關係應該在何處、以何種強度強制執行，從而實現模型與領域的雙重客製化。

**Q7：論文在哪些基準上進行評估，使用了什麼指標？**
A：實驗涵蓋四個代理安全基準家族，包括 DecodingTrust-Agent、AgentDojo（含未見的 AgentDyn 測試套件）以及 Agent-SafetyBench。評估指標主要使用效用（utility）與攻擊成功率（ASR），用來刻畫安全–效用權衡。這些基準同時包含間接提示注入攻擊與直接有害請求，能夠檢驗安全約束器在不同威脅模型下的表現。

**Q8：EvoSafeHarness 取得了哪些關鍵實驗結果？**
A：在 DecodingTrust-Agent 上，它將平均攻擊成功率從 45.6% 降至 10.0%，僅付出 3.3 個百分點的效用成本，並在 15 個評估格子中拿下 14 個最佳成績。在 AgentDojo 上，它達到 82.8% 效用且 0.0% ASR，是同樣運作點下 CaMeL 效用的兩倍，並能原封不動地轉移到未見的 AgentDyn 套件。在 Agent-SafetyBench 上，它對每個受害者模型都取得最佳分數，即使在精煉預算為 16 的自適應 PAIR 攻擊下，平均 ASR 仍低於 20%。

**Q9：從消融與分析中可以得到什麼結論？**
A：分析顯示，領域語意決定了需要哪些安全關係與軌跡狀態，而模型與執行階段行為則決定了這些關係應該如何以及在何處被強制執行。這解釋了為什麼單一固定式防禦無法在所有部署中達到最佳安全–效用前沿。換句話說，沒有萬用的安全約束器，只有針對特定模型與領域演化出的約束器才能逼近最佳權衡。

**Q10：EvoSafeHarness 在實務上可以應用在哪些場景？**
A：在金融代理場景中，它可以自動生成追蹤交易歷史、限制收款人清單與偵測洗錢交易的安全約束器。在作業系統代理場景中，它可以設計檢查危險命令、敏感檔案讀取與機密外洩的過濾器與範圍審計器。無論是電信、雲端維運或企業自動化流程，只要提供目標領域規格，框架就能為該部署合成對應的安全約束層。

**Q11：若將 EvoSafeHarness 產品化，需要考慮哪些因素？**
A：首先必須持續監控安全–效用權衡，避免過度阻擋導致使用者體驗下降。其次，自然語言策略與程式碼邏輯都需要可解釋與可審查，以便安全團隊理解並核准自動生成的規則。最後，由於模型與領域會隨時間演變，產品必須支援週期性重新演化或增量更新，並與現有的模型層級防禦協同運作。

**Q12：這項研究對代理安全領域可能帶來什麼影響？**
A：它將代理安全的焦點從「設計一個通用防禦」轉向「為每個部署自動演化專屬防禦」，凸顯系統層級安全約束器應該是模型與領域專用的。這種範式轉移可能影響未來代理系統的安全標準與認證流程。同時，它也為結合大型語言模型的程式合成與對抗性審查提供了一個具體的安全應用範例。

**Q13：EvoSafeHarness 有哪些已知的限制？**
A：框架的成效高度依賴目標領域規格的完整性與對抗性審查的品質，若規格遺漏關鍵安全關係，生成的約束器也可能遺漏對應防護。此外，搜尋與評估過程需要一定的運算與標註預算，對於資源受限的部署可能構成挑戰。全新上下文對抗性審查雖然能減少過度擬合，但無法保證發現所有潛在的攻擊面。

**Q14：在什麼情況下 EvoSafeHarness 可能會失效？**
A：如果評估資料中存在重複出現的表面特徵，而對抗性審查未能成功識別，生成的規則可能會過度擬合到這些基準特定規則。當面對能力極強、擁有極大精煉預算的自適應攻擊者時，自動生成的約束器仍可能被繞過。此外，若部署環境與目標領域出現顯著的分布偏移，原本演化出的安全關係與執行點可能不再適用。

**Q15：未來可以朝哪些方向延伸這項研究？**
A：未來可以發展部署後的線上適應機制，讓安全約束器能根據實際運作回饋持續更新。也可以引入更強大的對抗性審查器或形式化驗證技術，以提升規則的穩健性與可證明性。此外，將方法擴展到多代理系統、多模態代理，以及結合人類專家審查的混合式策略生成，都是值得探索的方向。

## 實務應用指南

### 適用場景

1. **企業級 AI 助理（Email、行事曆、檔案系統、Shell）**  
   代理需要讀取外部郵件、開啟附件、執行指令。EvoSafeHarness 可針對特定模型與作業系統領域，演化出阻擋間接提示注入與機密外洩的程式碼邏輯，例如攔截 `curl`、`cron` 與讀取 `.env` 金鑰的行為。

2. **金融交易與轉帳代理**  
   在轉帳、交易、投資建議場景中，領域語意涉及收款人白名單、單筆上限、洗錢式連續交易。EvoSafeHarness 可學習追蹤金流狀態與軌跡歷史，而非僅套用通用命令過濾器。

3. **DevOps / SRE 自動化代理**  
   代理被賦予生產環境工具（如資料庫、Kubernetes、雲端 API）。模型專用安全約束器可根據模型對抗社會工程提示的能力，調整能力強制執行（capability enforcement）的強度，避免過度阻擋合法的緊急維修指令。

4. **客戶服務代理（CRM、訂單、退款）**  
   代理透過使用者通道接收直接請求（如大額退款、修改帳戶）。領域專用策略可辨識「符合政策」與「惡意繞過」的語意差異，並維護跨步驟的軌跡狀態。

5. **醫療行政代理（病歷排程、保險申請）**  
   涉及受保護健康資訊（PHI）與敏感操作。EvoSafeHarness 可針對該領域的資料流與授權關係，產生可執行的存取控制與稽核邏輯。

### 實作前置條件

**資料**
- 目標領域規格：工具 schema、可執行動作、敏感資源清單、合法工作流程、業務規則。
- 凍結模型的行為樣本：良性軌跡與攻擊軌跡（可來自 DecodingTrust-Agent、AgentDojo、Agent-SafetyBench 或內部紅隊資料）。
- 效用評估標準：任務成功率、延遲、使用者滿意度等。
- 安全評估標準：攻擊成功率（ASR）、誤擋率、覆蓋的攻擊類別。

**運算**
- 目標模型推理端點（API 或本地部署）。
- 用於演化策略的提案模型與對抗性審查模型（可使用較強的 LLM）。
- 可重複執行代理軌跡的沙箱環境（容器、VM、模擬工具）。
- 足夠的迭代預算（論文使用精煉預算 16 等級別）。

**技能**
- Python 與代理框架（如 LangChain、AutoGen、OpenAI Agents SDK）。
- 提示工程與安全紅隊測試經驗。
- 領域知識（金融、DevOps、醫療等）以設計初始規格與審查產出。
- 基礎程式碼審查能力，因為最終產出包含可執行程式碼邏輯。

### 實作步驟建議

1. **鎖定模型 × 領域組合**  
   選定一個凍結模型與一個目標領域。避免一開始就追求跨模型通用，先驗證單一部署的安全–效用權衡。

2. **建立領域規格與評估環境**  
   將工具、狀態、敏感動作、合法業務流程形式化。搭建沙箱與軌跡記錄，確保可以重放與評分。

3. **設計初始安全約束器**  
   可從現有專家設計防禦（如 CaMeL）或簡單規則開始，作為演化演算法的種子，避免從零開始。

4. **執行 EvoSafeHarness 最佳化迴圈**  
   - 同時搜尋自然語言策略與可執行程式碼邏輯。  
   - 在良性與對抗軌跡上評估每個候選約束器。  
   - 使用全新上下文對抗性審查檢查候選策略是否過度依賴基準特定規則或過度阻擋。

5. **挑選 Pareto 最適運作點**  
   根據產品需求選擇「高安全低效用成本」或「零 ASR 可接受效用」等運作點，而非單一最佳解。

6. **在保留測試集與未見任務上驗證**  
   類似 AgentDojo 轉移到 AgentDyn，保留一部分真實或合成任務，確認沒有過擬合。

7. **部署為系統層級強制邊界**  
   將約束器置於代理編排器與工具執行之間，作為獨立強制執行層，而非僅依賴模型層級防禦。

8. **建立監控與再訓練週期**  
   記錄阻擋事件、誤擋事件、新型攻擊。當模型更新或領域流程改變時，重新執行演化。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **過度阻擋（Over-block）** | 策略過嚴導致合法任務失敗，效用崩潰。 | 多目標最佳化同時追蹤效用；保留人工審查閘道。 |
| **過擬合基準** | 約束器學到檔名、路徑等表面特徵，換環境即失效。 | 全新上下文對抗性審查；使用未見測試集與真實軌跡驗證。 |
| **全拒絕捷徑** | 演化過程發現「全部阻擋」可得到最低 ASR。 | 效用成本納入適應函數；設定最低可用性門檻。 |
| **自適應攻擊** | 攻擊者針對已部署約束器設計繞過。 | 持續紅隊測試；監控異常軌跡；定期精煉策略。 |
| **程式碼邏輯缺陷** | 自動生成的可執行程式碼可能有 bug，造成可用性或安全性問題。 | 程式碼審查、單元測試、沙箱隔離、最小權限執行。 |
| **模型更新後失效** | 目標模型換版後，原約束器強度不再適用。 | 將約束器版本與模型版本綁定；模型更新後重新評估。 |
| **延遲與成本** | 多層判斷與軌跡驗證增加推理延遲。 | 在關鍵路徑上快取常見判斷；非同步審計。 |

### 與其他技術的整合建議

- **模型層級防禦**：EvoSafeHarness 是系統層級防禦，應與模型安全對齊訓練、提示防護等互補，而非取代。
- **身份與存取管理（IAM）**：將約束器的判斷結果與現有授權系統串接，例如 OAuth scope、RBAC，形成雙重把關。
- **代理編排框架**：透過中介件（middleware）形式嵌入 LangChain、AutoGen、OpenAI Agents SDK 的工具呼叫前後。
- **安全資訊與事件管理（SIEM）**：將阻擋事件、軌跡狀態、異常行為送至 SIEM，供資安團隊分析。
- **CI/CD**：把約束器視為可版本化程式碼，透過自動化測試與金絲雀部署上線。
- **API 閘道**：在對外服務閘道層整合約束器決策，統一控管多個代理實例。

### 給不同背景讀者的閱讀建議

**初學者**：先理解核心概念——代理安全不能只靠模型本身，而需要針對「用什麼模型」與「做什麼任務」量身打造安全約束器。重點看適用場景與風險表格，建立「安全–效用權衡」的直覺。

**AI 工程師**：聚焦實作步驟與整合建議。理解如何將 EvoSafeHarness 的演化迴圈落地為產品：沙箱設計、軌跡記錄、自然語言策略與可執行程式碼邏輯的產生與評估、以及如何嵌入現有代理框架。

**研究人員**：深入分析全新上下文對抗性審查的設計、Pareto 前沿的搜尋機制、以及為何領域語意決定安全關係而模型行為決定執行強度。可進一步探討自適應 PAIR 攻擊下的穩健性與理論保證。

**產品經理**：關注適用場景與風險緩解。評估導入成本時，需同時看運算預算、領域專家投入、維護週期，以及合規與品牌風險的降低效益。建議從單一高風險領域試點，再逐步擴展。
