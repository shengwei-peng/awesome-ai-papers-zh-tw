## 摘要翻譯

預填充（Prefill）與解碼（Decode）階段各自偏好不同的量化方法：低精度運算（low-precision arithmetic）可加速提示處理（prompt processing），而緊湊權重（compact weights）則能減少生成（generation）階段的記憶體流量（memory traffic）。我們提出「分離式量化」（Disaggregated Quantization, DQ），針對這兩個階段分別設計專屬的運算格式、權重與儲存配置。在 Qwen 3 與 Gemma 3 上，特別針對解碼（Decode）階段移除激活值量化（activation quantization），即可在不增加推論成本（inference cost）的情況下，提升解碼為主任務（decode-heavy tasks）的準確率（accuracy）。訓練獨立的原生運算預填充權重（compute-native prefill weights），相較於僅權重量化推論（weight-only inference）可加速提示處理，同時在解碼為主與預填充為主（prefill-heavy tasks）的任務上，於 2–3 位元解碼（2-3-bit decode）設定達到或超越其準確率。使用已釋出的 Qwen3.8-27B GGUF 解碼器（decoders），訓練一個 NVFP4 預填充器（NVFP4 prefiller）可在不修改解碼檢查點（decode checkpoint）的情況下，將 1 位元解碼在 MMLU-Pro 上的準確率提升 32.5 個百分點，在 MMMU-Pro 上提升 35.3 個百分點。為了在單一裝置上容納額外的檢查點，卸載式分離預填充（Offloaded Disaggregated Prefill, ODP）會從 SSD 串流載入其權重，並將載入成本隨提示長度（prompt length）攤平。在相同的 27B 模型上，ODP 在 llama.cpp 中相較於僅權重量化基線（weight-only baseline），於 8K 提示長度下將首 Token 時間（time-to-first-token, TTFT）加速 1.78 倍。我們在 vLLM 中評估分離式服務（disaggregated serving）下的準確率，並進一步透過對參數量高達 2.8T 的模型進行訓練後量化（post-training quantization），驗證共享權重格式分離（shared-weight format disaggregation）。

### 核心貢獻（3～5點）
- 提出分離式量化（DQ）框架，針對預填充與解碼階段分別設計運算格式、權重與儲存配置。
- 發現於解碼階段移除激活值量化，可在不增加推論成本的前提下提升解碼為主任務的準確率。
- 訓練獨立的原生運算預填充權重，在 2–3 位元解碼下加速提示處理，並維持或超越僅權重量化推論的準確率。
- 提出卸載式分離預填充（ODP），透過 SSD 串流載入預填充權重，於 8K 提示長度達成 1.78× 首 Token 時間（TTFT）加速。
- 驗證共享權重格式分離可透過訓練後量化擴展至 2.8T 參數模型。

### 適合對象
本論文適合從事大型語言模型推論系統、模型量化與壓縮、以及邊緣／資料中心 LLM 服務的研究人員與工程師，特別是關注預填充延遲、解碼效率、低精度運算與記憶體頻寬最佳化的讀者。

## 深度分析

#### 方法論解析

本研究提出**分離式量化（Disaggregated Quantization, DQ）**，核心概念是將大型語言模型（Large Language Model, LLM）推論中的**預填充（Prefill）**與**解碼（Decode）**兩個階段視為性質迥異的工作負載，並分別為其設計權重儲存格式、計算精度與部署位置。傳統量化方法通常對整個模型使用單一格式，但這忽略了預填充階段多為**計算受限（Compute-bound）**、適合低精度矩陣乘法（GEMM），而解碼階段多為**記憶體受限（Memory-bound）**、適合高壓縮率的**僅權重量化（Weight-only Quantization）**這一事實。

##### 1. 三種分離式量化方案

論文將 DQ 劃分為由淺至深的三大層級，對應圖 2 中的三種線性層設計：

- **非分離式量化線性層（Non-disaggregated Quantized Linear）**：預填充與解碼共用同一組權重與格式，例如同時使用 LUT3（3.5 bit/weight 的查表量化格式）進行計算與儲存。這是現行大多數量化框架的作法。
- **格式分離式量化線性層（Format-disaggregated Quantized Linear）**：權重仍共用，但在預填充階段將權重與激活值（Activation）重新量化為硬體原生計算格式（如 NVFP4），解碼階段則維持低比特僅權重量化。這樣可在不增加儲存成本的前提下，提升計算效率與準確率。
- **完全分離式量化線性層（Fully-disaggregated Quantized Linear）**：預填充與解碼擁有各自獨立的權重與格式。預填充權重可訓練成原生計算格式（如 NVFP4），解碼權重則維持極低比特的僅權重量化格式（如 IQ1_S、IQ1_M 等 GGUF 格式）。這是論文所稱的 **Prefillers（預填充器）** 概念。

##### 2. 量化感知蒸餾與分離（QADD）

為了讓分離後的兩條路徑仍朝向相同的輸出目標（Output Objective）優化，作者提出 **Quantization-aware Distillation with Disaggregation（QADD）**。其訓練流程如圖 3 所示：

- 使用一個凍結的 BF16 **教師模型（Teacher Model）**作為參考。
- 學生模型在預填充階段走經過量化的預填充路徑，在解碼階段走解碼路徑。
- 損失函數僅在回覆 token（Reply Tokens）上計算線性層的 KL 散度（KL Divergence），並利用原本監督式微調（Supervised Fine-Tuning, SFT）中的助理 token 遮罩（Assistant Token Mask）來選擇要更新哪一條計算路徑。
- 支援**共享主權重（Shared Master Weights）**或**分離主權重（Separate Master Weights）**，也支援僅對預填充路徑進行適應性訓練，而解碼檢查點（Decode Checkpoint）保持凍結。

這種設計的關鍵優勢在於：當解碼權重已經是釋出的低比特 GGUF 檢查點時，研究者可以只訓練一個輕量的 NVFP4 預填充器（NVFP4 Prefiller），無需重新訓練或修改解碼權重，就能顯著提升整體準確率。

##### 3. 卸載式分離預填充（ODP）

完全分離會帶來額外的權重檢查點，增加裝置記憶體（Device Memory）佔用。為此，論文提出 **Offloaded Disaggregated Prefill（ODP）**：將預填充權重儲存在 **SSD（固態硬碟）**，透過區塊緩衝區（Block Buffers）以串流方式載入，並與計算重疊。由於預填充階段的計算量隨提示長度（Prompt Length）增加而增加，SSD 載入延遲可以被攤平（Amortize）到大量 token 的計算中。這使得在單一裝置上同時容納解碼權重與預填充權重成為可能，而不會額外增加常駐記憶體（Resident Memory）開銷。

#### 實驗數據解讀

論文在 Qwen 3 與 Gemma 3 模型家族上進行驗證，並涵蓋文字領域推理（Text-domain Reasoning）與圖像領域推理（Image-domain Reasoning）任務。以下從幾個關鍵結果進行解讀。

##### 1. 格式分離對解碼為主任務的幫助

實驗顯示，在解碼階段移除激活值量化（Activation Quantization），僅保留權重量化，可以在不增加推論成本的前提下，提升**解碼為主任務（Decode-heavy Tasks）**的準確率。這是因為解碼階段本來就是記憶體受限，激活值量化帶來的額外量化誤差會直接影響生成品質，而節省的記憶體頻寬相對有限。因此，對解碼階段採用較高精度的 BF16 激活值，是性價比很高的選擇。

##### 2. 完全分離預填充器在低比特解碼上的準確率躍升

圖 1 左側與中間展示了在 Qwen3.8-27B 上使用 IQ1_S（約 1-bit 的 GGUF 格式）作為解碼權重時，加入 NVFP4 預填充器後的表現：

- 在 **MMLU-Pro** 上，準確率從原本極低的水平提升超過一倍，具體為提升 32.5 個百分點。
- 在 **MMMU-Pro** 上，提升更高達 35.3 個百分點。

這說明當解碼權重被壓縮到 1-bit 時，預填充階段的表示品質成為整體準確率的瓶頸。透過訓練專屬的 NVFP4 預填充權重，可以在提示處理階段保留更豐富的語義資訊，從而彌補極低比特解碼權重帶來的損失。

##### 3. 預填充速度與首 Token 時間（TTFT）

圖 1 右側顯示在真實 llama.cpp 服務環境（DGX Spark）中，ODP 相較於純 IQ1_S 僅權重量化基線（Baseline）的 **首 Token 時間（Time-to-First-Token, TTFT）**：

- 在 4K 上下文長度（Context Length）以上，ODP 開始比基線更快。
- 在 8K 上下文長度時，ODP 達到 **1.78× 加速比（Speedup）**。

這驗證了兩個假設：第一，NVFP4 等硬體原生計算格式在長提示的預填充階段確實比僅權重量化格式更快；第二，透過 SSD 串流載入預填充權重的開銷可以被長提示的計算充分攤平。

##### 4. 跨模型家族的泛化性

論文同時在 Qwen 3（0.6B、1.7B、4B、8B）與 Gemma 3（1B、4B、12B）上進行平均評估，顯示分離式量化在不同架構與規模上都能帶來一致性的準確率提升，並且在**預填充為主任務（Prefill-heavy Tasks）**與**解碼為主任務**上均表現良好。這降低了方法僅適用於特定模型家族的疑慮。

#### 與現有研究的比較

##### 1. 相較於傳統訓練後量化（Post-training Quantization）

傳統 **訓練後量化（Post-training Quantization, PTQ）** 通常對整個模型使用單一格式，並在準確率與壓縮率之間取捨。DQ 的貢獻在於將這個取捨拆解到兩個推論階段：預填充階段可以承受較高儲存成本以換取計算效率與準確率，解碼階段則可以極致壓縮權重以減少記憶體流量。這種分工使得整體推論系統在相同裝置權重（Device Weights）預算下達到更好的 Pareto 前沿。

##### 2. 相較於僅權重量化推論（Weight-only Inference）

現有僅權重量化方法（如 GGUF 的各種 IQ 格式）在解碼階段表現優異，因為它們減少了權重載入量。但它們在預填充階段需要將權重反量化（Dequantize）或重新量化為計算格式，並且通常需要對激活值進行量化，導致準確率損失與計算效率下降。DQ 透過訓練原生運算預填充權重（Compute-native Prefill Weights），在預填充階段超越了僅權重量化推論的速度與準確率。

##### 3. 相較於分離式服務（Disaggregated Serving）

現有的 **分離式服務（Disaggregated Serving）** 已將預填充與解碼部署在不同加速器上，並主要優化 KV 快取（KV Cache）的通訊與排程。DQ 與之互補：它進一步將「權重量化格式」也納入分離設計，並提出 ODP 來解決額外檢查點的記憶體佔用問題。論文也在 vLLM 中驗證了分離式服務下的準確率，顯示 DQ 可以無縫整合到現代服務框架中。

##### 4. 限制與潛在缺點

儘管 DQ 概念上很吸引人，仍存在一些限制：

- **額外檢查點管理**：完全分離需要維護兩組權重，增加了部署與版本控制的複雜度。
- **SSD 頻寬依賴**：ODP 的效益取決於 SSD 讀取頻寬與預填充計算量的比例；在極短提示或低速儲存裝置上，載入延遲可能無法被完全隱藏。
- **硬體特定性**：NVFP4 是 NVIDIA 專屬格式，方法的通用性受限於支援該格式的硬體平台。
- **訓練成本**：QADD 需要額外的量化感知蒸餾訓練，雖然論文顯示可以只訓練預填充器，但對於超大規模模型（如 2.8T 參數）的訓練可行性仍需更多工程細節。

從提供的上下文來看，以下內容的可重現性較弱：

#### 未來研究方向

##### 1. 動態格式選擇

目前的 DQ 採用固定的預填充／解碼格式配對。未來可以研究根據提示長度、批次大小（Batch Size）或硬體狀態動態選擇最適格式的策略，例如在極短提示下自動切換回非分離式量化以避免 ODP 的載入開銷。

##### 2. KV 快取與權重的聯合量化

論文主要聚焦於權重與激活值的量化，但 **KV Cache（KV 快取）** 在長上下文推論中同樣佔用大量記憶體。將 DQ 與 KV Cache 量化、壓縮或驅逐（Eviction）技術結合，可能進一步降低整體記憶體佔用。

##### 3. 擴展至多模態與編碼器–解碼器架構

雖然論文在 Qwen 3 與 Gemma 3 上驗證了多模態能力，但 DQ 的核心思想源自編碼器–解碼器 Transformer（Encoder–Decoder Transformer）中編碼器與解碼器本來就分離的傳統。未來可以系統性地將 DQ 應用於視覺–語言模型（Vision-Language Models）、語音模型，以及真正的編碼器–解碼器架構。

##### 4. 跨硬體平台的格式泛化

NVFP4 目前主要支援 NVIDIA 最新硬體。未來可以探索在其他平台（如 AMD、Intel、Apple Silicon 或自研 AI 加速器）上的等價低精度計算格式，並發展與硬體無關的 DQ 訓練框架。

##### 5. 理論分析與最佳化

目前 DQ 的設計主要基於經驗觀察。未來可以從理論上分析：在給定記憶體頻寬、計算能力與準確率約束下，預填充與解碼的最佳位元寬度（Bit Width）與格式組合是什麼。這將有助於自動化設計 DQ 配置，減少人工調參成本。

##### 6. 與推論排程系統的深度融合

ODP 已經展示了儲存層與計算層協同設計的潛力。未來可以將 DQ 與請求排程、投機解碼（Speculative Decoding）、連續批處理（Continuous Batching）等技術結合，進一步提升資料中心規模部署的吞吐量與延遲表現。

## 論文問答

**Q1：分離式量化（DQ）試圖解決的核心問題是什麼？**

A：在現代僅解碼器語言模型中，預填充與解碼兩個階段共享同一組參數，但它們的硬體瓶頸截然不同：預填充是計算受限階段，適合使用低精度運算加速；解碼則是記憶體受限階段，適合使用緊湊權重減少記憶體流量。傳統的階段無關量化只能選擇單一格式，無法同時優化兩個階段，導致準確率或效率上的折損。DQ 的核心思想就是針對預填充與解碼分別設計量化策略，使兩個階段都能採用最適合的表示方式。

**Q2：為什麼現有的僅權重量化或低精度運算格式無法同時滿足預填充與解碼的需求？**

A：僅權重量化雖然能減少解碼階段的記憶體流量，但這些緊湊編碼通常不是硬體原生計算格式，若要用於預填充的低精度 GEMM，往往需要重新量化權重並對激活值進行量化，反而損失準確率。相反地，NVFP4 等硬體原生計算格式雖然能加速預填充，卻會對解碼階段施加不必要的激活值量化，進而影響解碼為主任務的表現。因此，單一格式無法兼顧預填充的計算效率與解碼的記憶體效率，這正是 DQ 要解決的結構性矛盾。

**Q3：針對預填充與解碼分別設計量化策略，在實務上為什麼重要？**

A：在指令遵循等真實應用中，使用者輸入提示與模型生成回覆本質上是兩個不同角色，而大型部署系統也已經將預填充與解碼執行在不同的加速器實例上。若能在量化層級也配合這種分離，就能在不增加記憶體佔用的前提下降低首 Token 時間（TTFT）並提升整體吞吐量。此外，這也讓開發者可以針對已釋出的低位元解碼檢查點，額外訓練一個預填充器來提升準確率，而無需修改原始解碼權重。

**Q4：分離式量化（DQ）包含哪三種互補方案？**

A：第一種是格式分離（format disaggregation），即預填充與解碼共享同一組權重，但在兩個階段使用不同的計算格式，例如預填充使用 NVFP4 等低精度運算、解碼使用僅權重量化。第二種是完全分離（full disaggregation），即為預填充與解碼訓練各自獨立的計算原生權重，讓兩個階段都能使用最適合的權重表示。第三種是卸載式分離預填充（ODP），它將額外的預填充權重從 SSD 串流載入區塊緩衝區，以避免同時佔用大量裝置記憶體。

**Q5：QADD（Quantization-Aware Distillation with Disaggregation）在方法上的關鍵創新是什麼？**

A：QADD 透過單次前向與反向傳播，同時訓練預填充與解碼兩條階段專屬路徑，並讓它們朝向共同的輸出目標進行量化感知蒸餾。它利用原本只用於損失計算的 SFT assistant token mask，來決定線性層要走預填充路徑還是解碼路徑，從而實現階段分離。此方法支援共享或獨立的 FP32 主權重，也能在解碼檢查點凍結的情況下單獨訓練預填充器，極具彈性。

**Q6：為什麼在解碼階段移除激活值量化，卻在預填充階段保留低精度運算？**

A：解碼階段是記憶體受限的矩陣–向量運算，主要瓶頸在於載入權重，因此不需要透過激活值量化來節省記憶體流量；移除激活值量化可以避免不必要的準確率損失，特別是在解碼為主任務上。相對地，預填充階段是計算受限的通用矩陣乘法，使用 NVFP4 等低精度格式能顯著加速提示處理。這種不對稱設計正是格式分離的核心：讓每個階段只承擔對其真正有益的量化成本。

**Q7：論文在哪些模型、任務與系統上進行了評估？**

A：準確率實驗涵蓋 Qwen 3 與 Gemma 3 系列的多種模型尺寸，並在 MMLU-Pro（文字領域推理）與 MMMU-Pro（圖像領域推理）等基準上測試。針對 Qwen3.8-27B，作者使用釋出的 GGUF 解碼檢查點，並訓練 NVFP4 預填充器進行驗證。系統層面則在 llama.cpp 上測量 TTFT 與 ODP 加速，同時在 vLLM 中評估分離式服務的準確率，並對高達 2.8T 參數的模型進行共享權重格式分離的訓練後量化驗證。

**Q8：論文報告了哪些最關鍵的準確率與加速成果？**

A：在 Qwen3.8-27B 上，訓練 NVFP4 預填充器搭配 IQ1_S 解碼權重，使 MMLU-Pro 準確率提升 32.5 點、MMMU-Pro 提升 35.3 點，且無需修改解碼檢查點。完全分離訓練的預填充權重，在 2–3 位元解碼設定下，於解碼為主與預填充為主任務上都能達到或超越僅權重量化推論的準確率。在系統效能方面，ODP 在 llama.cpp 中對 8K 上下文長度的 Qwen3.8-27B 達到相較於 IQ1_S 僅權重量化基線 1.78 倍的首 Token 時間加速。

**Q9：圖 1 與圖 5 等實驗結果揭示了哪些關於階段專屬量化的洞見？**

A：圖 1 左側與中間顯示，為現成的 Qwen3.8-27B GGUF IQ1_S 解碼檢查點加上 NVFP4 預填充器後，MMLU-Pro 與 MMMU-Pro 準確率都提升超過一倍，證明極低位元解碼模型可透過階段專屬預填充顯著改善。圖 5 則說明格式分離能同時保留 NVFP4 預填充的計算速度與 LUT3 解碼的記憶體效率，並獲得更高的準確率。這些結果凸顯了「為每個階段選擇最適合的格式與權重」比強迫單一格式更能在速度與準確率之間取得平衡。

**Q10：在什麼情境下應該選擇 ODP，什麼情境下應該選擇完全分離？**

A：當單一裝置無法同時容納預填充與解碼兩份完整檢查點，但又希望提升長提示的預填充速度時，ODP 是較佳選擇，因為它透過 SSD 串流與區塊緩衝區避免額外的裝置記憶體佔用。若部署環境擁有足夠記憶體，或已採用分離式服務將兩個階段放在不同實例上，則完全分離能發揮最大效益，因為兩組權重都可常駐於裝置記憶體。簡言之，ODP 適合記憶體受限的邊緣裝置，而完全分離適合資料中心或記憶體較充裕的場景。

**Q11：DQ 在產品化與生態系整合上需要考慮哪些因素？**

A：DQ 的一大優勢是它可以不改動現有解碼檢查點，直接為其加上預填充器，例如論文針對 Qwen3.8-27B GGUF 解碼檢查點訓練 NVFP4 預填充器，便於在 llama.cpp 生態中部署。在 vLLM 等資料中心服務引擎中，則需要支援分離式服務，讓預填充實例與解碼實例分別載入對應權重並交換 KV cache。產品化時還需考慮額外檢查點的儲存與分發、SSD 頻寬規劃，以及與現有排程與快取系統的整合。

**Q12：分離式量化可能對 LLM 量化研究與產業帶來什麼影響？**

A：DQ 將研究焦點從「尋找單一最佳量化格式」轉向「針對不同推論階段共同設計格式、權重與儲存配置」。它證明即使解碼權重被壓到 1 位元，仍可透過專屬預填充器維持可用準確率，這為極低位元邊緣模型開闢了新方向。此外，它結合了訓練時蒸餾與訓練後量化，讓大型模型在資料中心與邊緣裝置上都能獲得更好的速度–準確率權衡。

**Q13：DQ 目前存在哪些限制或額外開銷？**

A：完全分離需要額外訓練並儲存一份預填充權重，這會增加總模型儲存空間與部署複雜度。ODP 雖然不增加裝置記憶體佔用，但其效能取決於 SSD 頻寬與提示長度，若提示過短，串流載入的開銷可能無法被攤平。此外，分離式服務需要基礎設施支援階段間的路由與 KV cache 相容性，這對現有系統而言是額外的工程負擔。

**Q14：在哪些情況下 DQ 可能無法帶來改善，甚至表現變差？**

A：如果提示長度太短，ODP 從 SSD 載入預填充權重的時間可能無法被後續計算掩蓋，導致首 Token 時間反而比單純的僅權重量化基線更慢。若預填充器與凍結的解碼檢查點之間對齊不佳，蒸餾過程中的目標不一致可能會損害最終輸出品質。另外，共享權重的格式分離雖然節省儲存，但在某些情況下可能無法達到完全分離獨立權重的準確率上限。

**Q15：未來研究可以從哪些方向延伸分離式量化的概念？**

A：未來可以將 DQ 擴展到更多硬體原生格式與核心，例如針對不同加速器設計專屬的預填充與解碼格式。另一個方向是將 DQ 與 KV cache 壓縮、動態批次排程等技術結合，進一步降低端到端推論成本。此外，自動化選擇每層最適合的格式、開發更輕量的預填充器以省去 ODP，以及將分離式量化應用於多模態與更大規模模型，都是值得探索的研究課題。

## 實務應用指南

### 適用場景

1. **邊緣裝置上的長提示應用**  
   在筆電、DGX Spark 等記憶體有限的裝置上執行 Qwen3.8-27B 等大型模型時，可將 1-bit GGUF 解碼檢查點常駐於裝置記憶體，並透過 ODP 把 NVFP4 預填充器從 SSD 串流載入。這樣不增加裝置權重記憶體佔用，卻能在 8K 上下文長度達到 1.78× 首 Token 時間加速，同時讓 MMLU-Pro / MMMU-Pro 準確率顯著提升。

2. **資料中心分離式服務（Disaggregated Serving）**  
   在 vLLM 等資料中心推論引擎中，預填充與解碼本來就分開部署。可讓預填充實例使用 NVFP4 等低精度運算格式提升計算吞吐量，解碼實例則使用 2–3-bit 僅權重量化格式降低記憶體頻寬壓力，並透過共享權重格式分離減少檢查點管理成本。

3. **長文件 / 多模態問答 Agent（預填充為主）**  
   法律、醫療或財經領域的長文件摘要與問答，通常提示很長、答案相對短。此時採用完全分離式量化，訓練專屬的原生運算預填充權重，可加速提示處理，同時維持低 bit 解碼權重的準確率。

4. **程式輔助 / 創作型 Chatbot（解碼為主）**  
   程式碼生成、故事接龍等場景提示短、輸出長，解碼階段佔比高。使用格式分離式量化，在預填充階段維持低精度運算，但在解碼階段移除激活值量化，可在不增加推論成本與權重儲存的前提下，改善解碼為主任務的準確率。

5. **已釋出低 bit 解碼檢查點的升級**  
   當社群或廠商已釋出 IQ1_S、IQ1_M 等 GGUF 解碼檢查點，但準確率不足時，可不改動解碼檢查點，額外訓練一個 NVFP4 預填充器來「外掛」提升準確率，適合快速迭代既有產品線。

### 實作步驟建議

1. **工作負載剖析**  
   收集實際請求日誌，量化「預填充佔比 / 解碼佔比」、「平均與 P99 上下文長度」、「批次大小」，判斷瓶頸是首 Token 時間（TTFT）還是每 Token 延遲。

2. **選擇分離式量化策略**  
   - 解碼為主、不想增加記憶體：格式分離式量化。  
   - 預填充為主、要加速提示處理：完全分離式量化 + NVFP4 預填充器。  
   - 裝置記憶體不足：完全分離式量化 + ODP。

3. **準備教師模型與資料**  
   用 BF16 教師模型對目標資料集產生輸出；保留 SFT 的 assistant token mask，作為 QADD 中選擇線性層計算路徑的依據。

4. **以 QADD 訓練階段專屬路徑**  
   - 若已有釋出的解碼檢查點，可凍結解碼權重，僅訓練預填充路徑。  
   - 若從頭訓練，可選擇共享 FP32 主權重或各自獨立主權重，並以 KL 散度對齊兩階段輸出。

5. **轉換與匯出檢查點**  
   將解碼權重量化為目標 GGUF 格式（如 IQ1_S、IQ2_K_XL、IQ3_XXS）；將預填充權重量化為 NVFP4 計算原生格式，並確保兩者注意力架構與 KV cache 表示相容。

6. **整合進推論系統**  
   - llama.cpp：啟用 ODP，設定區塊緩衝區大小，將預填充權重放置於 SSD。  
   - vLLM：在分離式服務配置中分別載入預填充 / 解碼檢查點，並確認 KV cache 傳輸與排程正常。

7. **端對端準確率驗證**  
   在分離式服務環境下執行 MMLU-Pro、MMMU-Pro 或自有領域基準，確認兩階段銜接不會引入額外誤差；特別檢查長上下文下的 KV cache 一致性。

8. **效能調校**  
   調整 ODP 區塊大小、預填充批次、解碼量化 bit 寬，監測 TTFT、吞吐量、裝置記憶體佔用與 SSD I/O 延遲，找到成本與準確率的甜蜜點。

9. **上線與監控**  
   建立雙檢查點版本控制、A/B 測試與 Canary 機制；持續追蹤領域準確率漂移、SSD 壽命與延遲 SLO。

### 潛在風險與注意事項

| 風險 | 說明與緩解 |
|---|---|
| **額外預填充檢查點的記憶體開銷** | 完全分離會產生第二份權重。可透過 ODP 將預填充權重放 SSD，以區塊緩衝區重複使用裝置記憶體；或採用共享權重格式分離，只保留一份權重。 |
| **預填充 / 解碼 KV cache 不相容** | 兩階段必須使用相同的注意力架構、RoPE 設定與層數。任何一側的微調都需重新驗證端對端輸出。 |
| **短提示下 ODP 反而變慢** | SSD 載入延遲只有在上下文夠長時才會被攤平（論文顯示約 4K 以上才開始獲益）。短提示應自動 fallback 到權重常駐路徑。 |
| **1-bit 解碼準確率仍可能不足** | 雖然 NVFP4 預填充器可大幅提升準確率，但關鍵任務建議使用 2–3-bit 解碼，並以領域資料驗證。 |
| **QADD 訓練不穩定或災難性遺忘** | 使用較低學習率、凍結解碼權重、加強 KL 蒸餾限制；在預填充為主與解碼為主任務上都做驗證。 |
| **硬體與軟體支援限制** | NVFP4 需要較新 GPU 與對應 kernel；部署前確認目標硬體與 llama.cpp / vLLM 分支支援。 |

### 與其他技術的整合建議

- **vLLM 分離式服務**：DQ 與此架構天然契合，可直接將預填充 / 解碼檢查點掛載到不同實例，並沿用現有的 KV cache 傳輸與排程優化。
- **llama.cpp**：ODP 實作可與現有 GGUF 解碼檢查點並存，只需額外指定 NVFP4 預填充器路徑與區塊緩衝設定，適合邊緣裝置快速導入。
- **NVIDIA TensorRT-LLM / Triton**：可將 NVFP4 預填充路徑對接到 TensorRT-LLM 的 NVFP4 GEMM kernel，解碼路徑維持 weight-only kernel，統一由 Triton 排程。
- **MLOps / 模型倉庫**：建議將預填充器與解碼器視為同一模型版本的兩個 artifact，確保版本同步與原子更新，避免線上出現版本錯配。
- **現有量化管線**：可保留現有的 GPTQ / AWQ / GGUF 解碼量化流程，僅額外訓練預填充器，降低導入門檻。

### 給不同背景讀者的閱讀建議

**初學者**：先聚焦圖 1 與圖 2，理解「預填充像載重爬坡需要大馬力運算、解碼像市區走走停停需要省記憶體頻寬」這個直覺；分離式量化就是針對兩種路況換檔，不需要一開始就搞懂所有 kernel 細節。

**AI 工程師**：建議細讀第 1.1 節的硬體成本分析與 QADD 訓練流程，評估你們服務的瓶頸是 TTFT 還是每 Token 延遲；接著實際在 llama.cpp 或 vLLM 上跑一輪 ODP 與分離式服務，觀察真實延遲與記憶體數據。

**研究人員**：可深入探討 QADD 中共享主權重 vs. 獨立主權重的最佳化、KV cache 表示的一致性理論保證，以及將 DQ 擴展到 MoE、2.8T 參數模型或更激進的 1-bit 以下解碼權重的可能性。

**產品經理**：重點關注論文的數據——ODP 在 8K 上下文帶來 1.78× TTFT 加速、NVFP4 預填充器讓 1-bit 解碼在 MMLU-Pro 提升 32.5 分、MMMU-Pro 提升 35.3 分；評估這些數字對使用者體驗與硬體成本的實際意義，並確認目標裝置是否支援 NVFP4。
