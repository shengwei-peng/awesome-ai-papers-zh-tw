## 摘要翻譯

多模態深度搜尋 (Multimodal Deep Search) 要求代理透過串接搜尋、工具使用與視覺推理 (Visual Reasoning)，於持續演進的文字與視覺脈絡中解決開放世界 (Open-World) 問題。現行系統受兩項瓶頸限制。首先，現有工具使用框架 (Tool-Use Harness) 將搜尋、瀏覽或轉換所回傳之影像視為暫時性輸出，導致中間視覺證據 (Intermediate Visual Evidence) 無法供後續工具再次取用。其次，訓練資料通常由固定策展流程所建構，無法追蹤目標代理持續演進的能力。為解決上述挑戰，我們首先提出一個以影像庫參考協議 (Image Bank Reference Protocol) 為核心的視覺原生代理工具框架 (Visual-Native Agent Harness)，該框架將每張工具回傳影像 (Tool-Returned Image) 登錄為可定址參考 (Addressable Reference)，使中間視覺證據成為可重用視覺證據 (Reusable Visual Evidence)，供後續工具再次取用。在此框架之上，策略內資料演化 (On-policy Data Evolution, ODE) 運行一個閉環資料生成器 (Closed-Loop Data Generator)，根據受訓策略之策略推演 (Rollout)，於各輪中逐輪自我精煉。此每輪優化 (Per-Round Refinement) 使每輪資料對應當前策略 (Current Policy) 仍需學習之內容。同一框架同時支援多樣化監督式微調資料 (Diverse Supervised Fine-Tuning Data) 與策略感知強化學習資料策展 (Policy-Aware Reinforcement Learning Data Curation)，涵蓋目標代理之完整訓練生命週期 (Full Training Lifecycle)。在 8 個多模態深度搜尋基準 (Multimodal Deep Search Benchmarks) 上，ODE 將 Qwen3-VL-8B 代理之平均分數 (Average Score) 由 24.9% 提升至 39.0%，於標準代理工作流程設定 (Standard Agent-Workflow Setting) 下超越 Gemini-2.5 Pro (37.9%)。在 30B 規模下，ODE 將平均分數由 30.6% 提升至 41.5%。進一步分析驗證了影像庫重用 (Image-Bank Reuse) 之效益，特別是在需要迭代視覺優化 (Iterative Visual Refinement) 之複雜任務 (Complex Tasks) 上；同時，Rollout 回饋演化 (Rollout-Feedback Evolution) 相較於靜態合成 (Static Synthesis)，能產生更紮根的監督式微調軌跡 (Grounded SFT Traces) 與更佳的策略匹配強化學習任務 (Policy-Matched RL Tasks)。

### 核心貢獻（3～5點）
- **視覺原生代理工具框架 (Visual-Native Agent Harness)**：提出以影像庫參考協議 (Image Bank Reference Protocol) 為核心之代理工具框架，將每張工具回傳影像登錄為可定址參考，使中間視覺證據成為可重用視覺證據，供後續工具再次取用，解決現有框架將影像視為暫時性輸出之瓶頸。
- **策略內資料演化 (On-policy Data Evolution, ODE)**：設計閉環資料生成器，根據受訓策略之策略推演 (Rollout) 進行每輪優化 (Per-Round Refinement)，使每輪訓練資料精準對應當前策略仍需學習之內容，解決固定策展流程無法追蹤策略演進之瓶頸。
- **統一訓練生命週期支援**：同一 ODE 框架同時支援多樣化監督式微調資料 (Diverse SFT Data) 與策略感知強化學習資料策展 (Policy-Aware RL Data Curation)，涵蓋目標代理之完整訓練生命週期。
- **顯著實驗成效**：在 8 個多模態深度搜尋基準上，ODE 將 Qwen3-VL-8B 代理之平均分數由 24.9% 提升至 39.0%，於標準代理工作流程設定下超越 Gemini-2.5 Pro (37.9%)；在 30B 規模下，平均分數由 30.6% 提升至 41.5%。
- **分析驗證**：影像庫重用機制於需要迭代視覺優化之複雜任務上效益尤為顯著；Rollout 回饋演化相較於靜態合成，能產生更紮根之監督式微調軌跡與更佳之策略匹配強化學習任務。

### 適合對象
- 從事多模態大型語言模型 (MLLMs) 與視覺語言代理 (Vision-Language Agents) 研究之學者與工程師
- 關注代理式工具使用 (Agentic Tool Use)、強化學習 (RL) 與合成資料生成 (Synthetic Data Generation) 之研究者
- 對多模態深度搜尋、視覺推理及開放世界問題求解感興趣之人工智慧領域專業人士
- 從事大型語言模型後訓練 (Post-Training) 與資料策展 (Data Curation) 流程設計之實務工作者

## 深度分析

#### 方法論解析

本文提出之框架由兩個互補的核心元件組成：**視覺原生代理工具框架 (Visual-Native Agent Harness)** 與**策略內資料演化 (On-policy Data Evolution, ODE)**。兩者採協同設計 (co-design) 方式，共同解決多模態深度搜尋 (multimodal deep search) 中「視覺證據無法跨工具重用」與「訓練資料無法隨策略演進」兩大瓶頸。

**一、視覺原生代理工具框架 (Visual-Native Agent Harness)**

傳統多模態搜尋代理 (multimodal search agents) 將工具回傳影像 (tool-returned images) 視為一次性輸出，後續工具無法引用先前步驟所產生之視覺證據 (visual evidence)。本文提出之框架將 9 個核心工具統一於共享工作空間 (shared workspace) 中，包含：網路搜尋 (web search)、影像搜尋 (image search)、學術搜尋 (scholar search)、瀏覽 (visit)、視覺搜尋 (visual search, Google Lens)、放大 (zoom-in)、旋轉 (rotation)、翻轉 (flip) 與 Python 執行 (Python execution)。

其核心機制為**影像庫參考協議 (Image Bank Reference Protocol)**：所有工具回傳之影像皆被註冊為可定址參考 (addressable reference)，儲存於影像庫 (image bank) 中，並以 `<Image: 0>`、`<Image: 1>` 等標記進行索引。當前步驟之工具呼叫可透過參考標記直接引用先前步驟產生之影像作為輸入參數，使中間視覺證據 (intermediate visual evidence) 成為持久化視覺狀態 (persistent visual state)。此設計將多模態搜尋從「以原任務影像 (task image) 為中心之單輪互動」轉變為「具證據累積特性之鏈式視覺工作流 (chained visual workflow)」。

此架構之關鍵意義在於：對於需要迭代視覺優化 (iterative visual refinement) 之複雜任務 (例如先以視覺搜尋找到候選、再以 zoom-in 放大局部細節、再以 visual search 比對)，代理可逐步累積視覺證據鏈，而非每次皆從原圖重新開始。

**二、策略內資料演化 (On-policy Data Evolution, ODE)**

ODE 將資料生成視為一個自適應優化過程，而非一次性策展。其運作流程為閉環 (closed-loop)：

1. **前向策展 (Forward Curation)**：在當前配置下，資料生成器合成候選任務；
2. **策略推演 (Rollout)**：目標策略 (target policy) 在視覺原生工具框架中執行這些任務；
3. **軌跡分析 (Trace Analysis)**：以評分規準 (rubric) 對推演軌跡進行評分；
4. **反向優化 (Backward Optimization)**：根據分析結果調整下一輪之生成配置。

評分規準在此扮演類似損失函數 (loss function) 之角色，識別生成資料是否過於簡單、過於脆弱、視覺成分不足、缺乏紮根性 (groundedness)，或與代理當前訓練需求不匹配。ODE 支援兩種模式：

- **SFT 模式**：評分規準涵蓋資訊複雜度 (information complexity)、工具使用品質 (tool usage quality)、工具模式多樣性 (tool pattern diversity) 等，傾向選擇紮根、工具有效、且具多樣性之教師軌跡；
- **RL 模式**：評分規準涵蓋捷徑洩漏 (shortcut leakage)、難度匹配 (difficulty match)、學習效用 (learning utility) 等，傾向選擇位於策略學習前沿 (policy's learning frontier) 附近之可驗證任務。

此設計之核心洞見在於：每輪優化 (per-round refinement) 使該輪資料精準對應當前策略仍需學習之內容，從而避免靜態合成 (static synthesis) 中「資料過時」或「難度失配」之問題。

#### 實驗數據解讀

本文於 8 個多模態深度搜尋基準 (multimodal deep search benchmarks) 上進行評估，涵蓋 MMBC、HLE-VL、BC-VL、MMSearch、VDR、MMSearch+、SimpleVQA 與 FVQA，橫跨閉域視覺問答 (VQA)、開放域網路搜尋、與多模態推理等任務類型。

**主要結果：**

| 模型 | 平均分數 | 提升幅度 |
|------|---------|---------|
| Qwen3-VL-8B (baseline) | 24.9% | — |
| Qwen3-VL-8B + ODE | **39.0%** | +14.1% |
| Gemini-2.5 Pro (標準代理工作流程設定) | 37.9% | — |
| Qwen3-VL-30B (baseline) | 30.6% | — |
| Qwen3-VL-30B + ODE | **41.5%** | +10.9% |

關鍵觀察：

1. **超越旗艦模型**：8B 規模之 Qwen3-VL 經 ODE 訓練後，平均分數 (39.0%) 超越 Gemini-2.5 Pro (37.9%)，顯示 ODE 在小模型上之槓桿效應極為顯著；
2. **規模效應**：30B 模型之絕對分數更高 (41.5%)，但相對提升幅度 (+10.9%) 小於 8B (+14.1%)，暗示 ODE 對較弱策略之增益更大，符合「學習前沿」假設；
3. **消融實驗**：移除影像庫重用 (image-bank reuse) 在需要次級影像使用 (secondary image use) 之任務上損失最大；將 ODE 替換為靜態合成在相同資料預算下，SFT 與 RL 增益皆降低，驗證兩元件之互補必要性。

**結果之意涵：**

- 影像庫重用之有效性主要體現於「需要迭代視覺優化」之複雜任務，與本文之設計動機一致；
- Rollout 回饋演化 (rollout-feedback evolution) 產生之 SFT 軌跡比靜態合成更紮根 (grounded)，RL 任務與策略更匹配，驗證閉環設計之必要性。

#### 與現有研究的比較

**相較於既有方法之定位：**

| 既有方法 | 核心特點 | 本文差異化 |
|---------|---------|-----------|
| MMSearch-R1 | 半自動 VQA 策展 + RL | 採用固定策展配方，無法隨策略演進 |
| DeepMMSearch-R1 | 網路基礎任務合成 + 迭代查詢優化 | 視覺證據無法跨工具重用 |
| WebWatcher | 合成多模態工具使用軌跡 | 軌跡生成為一次性，無閉環優化 |

本文之主要進展在於：(1) 將視覺狀態從「一次性輸出」提升為「持久化、可重用之工作空間元素」；(2) 將資料生成從「靜態策展」提升為「隨策略演進之閉環優化」。

**優勢：**

- 統一框架同時支援 SFT 與 RL 資料策展，覆蓋完整訓練生命週期 (full training lifecycle)；
- 評分規準驅動之優化使資料生成具有可解釋性與可調整性；
- 在 8B 模型上超越 Gemini-2.5 Pro，顯示方法之實用價值。

**限制：**

1. **評分規準設計之依賴性**：ODE 之效果高度依賴評分規準之品質，若規準設計不當，可能導致資料偏誤；
2. **計算成本**：閉環優化需反覆執行策略推演 (rollout)，訓練成本顯著高於靜態合成；
3. **工具集範圍**：目前僅整合 9 個核心工具，對於需要特殊工具 (例如 OCR、文件解析、影片處理) 之任務可能不足；
4. **基準偏誤**：8 個基準雖具多樣性，但皆為英文/通用領域，未涵蓋特定垂直領域 (例如醫學、法律) 之深度搜尋；
5. **與 Gemini-2.5 Pro 之比較**：僅在「標準代理工作流程設定」下進行，未比較 Gemini-2.5 Pro 在自訂工具框架下之表現，比較基準之公平性有待商榷。

#### 可重現性評估

**正面因素：**

- 本文基於開源模型 Qwen3-VL-8B 與 Qwen3-VL-30B 進行實驗，模型權重可公開取得；
- 8 個評估基準皆為公開基準 (MMBC、HLE-VL、BC-VL、MMSearch、VDR、MMSearch+、SimpleVQA、FVQA)，便於結果驗證；
- 框架設計詳述於方法章節，包含工具介面、影像庫協議、ODE 流程與評分規準。

**不足因素：**

- 截至本文版本 (arXiv:2605.10832v2)，**未明確聲明程式碼是否開源**；
- **訓練資料之具體組成、規模與來源未完整披露**，僅描述生成流程；
- **評分規準之具體定義與權重設定未公開**，影響 ODE 之可重現性；
- **閉環優化之超參數 (例如輪數、每輪資料量、推演預算) 未詳細說明**；
- **工具框架之具體實作細節 (例如影像庫之儲存格式、參考解析機制) 缺乏偽程式碼或 API 規格**。

整體而言，本文之方法論描述清晰，但完整重現仍需作者提供程式碼、資料與超參數配置。

#### 未來研究方向

1. **評分規準之自動化學習**：目前評分規準需人工設計，未來可探索以元學習 (meta-learning) 或 LLM-as-a-judge 方式自動學習規準，降低人力成本並提升適應性；

2. **影像庫協議之擴展**：將可重用視覺狀態擴展至影片、音訊、3D 點雲等模態，並支援跨模態引用 (例如以音訊特徵引用對應影像幀)；

3. **多代理協作與 ODE**：將 ODE 擴展至多代理設定，使不同代理之推演軌跡可互相作為訓練資料，提升協作能力；

4. **效率優化**：閉環優化之計算成本為主要瓶頸，可研究 (a) 推演劇本之蒸餾 (distillation)、(b) 評分規準之近似估計、(c) 主動學習式之資料選擇；

5. **理論分析**：ODE 之收斂性、評分規準與策略學習前沿之關係、影像庫重用對策略表達能力之影響等，皆缺乏理論分析；

6. **垂直領域應用**：將框架應用於醫學影像、法律文件、工業檢測等垂直領域，驗證跨領域泛化能力；

7. **安全性與可解釋性**：深度搜尋代理之決策鏈長且涉及外部工具，需研究 (a) 視覺證據鏈之可追溯性、(b) 工具呼叫之安全性審查、(c) 幻覺 (hallucination) 檢測機制；

8. **與人類回饋之整合**：將 ODE 與 RLHF (Reinforcement Learning from Human Feedback) 結合，使閉環優化同時考慮自動化評分與人類偏好；

9. **長程任務之記憶機制**：對於需要數十步工具呼叫之任務，影像庫之容量管理與優先級排序將成為關鍵問題，可研究基於注意力或重要性之分層記憶架構。

## 論文問答

**Q1：多模態深度搜尋（Multimodal Deep Search）的核心任務是什麼？為什麼它比傳統的視覺問答更具挑戰？**
A：多模態深度搜尋要求代理在開放世界環境中，透過搜尋引擎、瀏覽、視覺操作等多種工具的鏈式呼叫，從演化的文字與視覺脈絡中收集證據並產出紮根答案。相較於傳統視覺問答（VQA）只需對單張任務影像進行識別與推理，多模態深度搜尋需要處理開放式資訊需求，往往無法僅靠單一影像或淺層檢索滿足使用者意圖。這意味著代理不僅要識別視覺內容，還必須建立從視覺線索到外部證據、再到最終答案的可靠路徑，因此對工具整合、視覺推理與規劃能力的要求都大幅提升。

**Q2：現有工具增強搜尋系統在「視覺證據」處理上有哪些根本性的不足？**
A：現有的多模態搜尋代理雖然已整合影像搜尋、文字搜尋、裁剪條件影像搜尋與迭代查詢優化等機制，但普遍將工具回傳的影像視為「短暫輸出」，僅圍繞原始任務影像進行推理，而忽略了工具在過程中產生的新視覺證據。這種設計使得早期步驟取得的影像無法被後續工具再次引用，限制了代理進行多輪視覺—文字探索的能力。當任務需要迭代視覺優化（例如先放大局部再以視覺搜尋比對）時，這種「一次性視覺消費」的模式便成為嚴重瓶頸。

**Q3：為什麼「靜態資料合成」無法跟上代理能力的演化？這對訓練資料建構意味著什麼？**
A：現有方法如 MMSearch-R1、DeepMMSearch-R1 與 WebWatcher 多採用半自動視覺問答策展、網路基礎任務合成或合成多模態工具使用軌跡等方式生成訓練資料，但這些生成食譜通常在規模化前就已固定，無法根據目標代理的回饋動態調整。這意味著當代理能力提升後，訓練資料仍停留在原先難度與分佈，容易產生「過於簡單」或「與策略不匹配」的問題。真正的閉環建模應將資料生成視為一個隨策略共同演化的優化過程，而非一次性的策展任務。

**Q4：視覺原生代理工具框架（Visual-Native Agent Harness）的核心設計理念是什麼？它如何不同於傳統的工具整合方式？**
A：視覺原生代理工具框架的核心設計理念是將多模態搜尋從「以原始任務影像為中心的單次互動」轉變為「以視覺證據累積為基礎的鏈式工作流程」。它在一個共享工作空間中統一了 9 個核心工具——網路搜尋、影像搜尋、學術搜尋、瀏覽、視覺搜尋（Google Lens）、放大、旋轉、翻轉與 Python 執行程式碼，使代理能在同一環境中靈活切換操作。透過影像庫參考協議，每張工具回傳的影像都被註冊為可定址參考，後續工具可隨時引用，使視覺證據成為跨步驟可重用的持久化視覺狀態。

**Q5：影像庫參考協議（Image Bank Reference Protocol）具體是如何運作的？它解決了什麼樣的技術問題？**
A：影像庫參考協議將原始任務影像以及每一張由工具回傳的影像統一儲存於影像庫中，並為每張影像分配可定址的參考編號（如 `<Image: 1>`、`<Image: 2>` 等），使後續的工具呼叫能以參考編號而非影像本身作為參數。這解決了傳統流程中「中間視覺證據無法被後續工具重新消費」的問題：例如代理可以先以視覺搜尋取得相似影像，再針對其中某張影像執行放大操作，最後以放大後的局部影像再次進行視覺搜尋，形成迭代視覺優化的閉環。這種設計讓多輪視覺—文字探索成為可能，也讓視覺推理不再受限於最初的單一影像。

**Q6：策略內資料演化（ODE）的閉環機制是如何運作的？為何它能同時支援監督式微調（SFT）與強化學習（RL）兩種訓練模式？**
A：ODE 將資料生成視為一個類似模型優化的過程：每一輪中，資料生成器在當前配置下合成候選任務，目標策略在工具框架中執行 rollout，再由基於評分規準（rubric）的軌跡分析給予回饋，用以修正下一輪的生成配置。在這個閉環中，rubric 扮演類似損失函數的角色，能識別資料是否過於簡單、過於脆弱、視覺成分不足或紮根性不足等問題。針對 SFT 模式，ODE 偏好紮根、工具使用有效且模式多樣的教師軌跡；針對 RL 模式，則尋找位於策略學習前沿且可驗證的任務，使同一演化原則能覆蓋完整的訓練生命週期。

**Q7：實驗選用了哪些多模態深度搜尋基準？這些基準各自測試了什麼樣的能力？**
A：研究在 8 個多模態深度搜尋基準上進行評估，包括 MMBC、HLE-VL、BC-VL、MMSearch、VDR、MMSearch+、SimpleVQA 與 FVQA。這些基準涵蓋了從基礎視覺問答到需要深度搜尋與多輪推理的複雜任務，能全面檢驗代理在不同難度與場景下的表現。選擇如此多樣化的基準是為了驗證框架在各種視覺推理與工具使用情境下的泛化能力，而非僅在單一類型任務上取得高分。

**Q8：ODE 在主要實驗中帶來了多大的提升？這些結果說明了什麼？**
A：在 8 個基準的平均表現上，ODE 將 Qwen3-VL-8B 代理從 24.9% 提升至 39.0%，並在標準代理工作流程設定下超越了 Gemini-2.5 Pro 的 37.9%；在 30B 規模下，平均分數也從 30.6% 提升至 41.5%。這些結果顯示，視覺原生代理工具框架結合 ODE 能在不同模型規模上帶來穩定且顯著的增益，並使開源模型在標準設定下超越頂級商業模型。更重要的是，這證明了「視覺證據重用」與「資料隨策略共同演化」這兩個設計對於多模態深度搜尋能力的培養具有關鍵作用，而非單純的規模擴展所能達成。

**Q9：消融研究揭示了哪些關鍵發現？影像庫重用與 ODE 各扮演了什麼角色？**
A：消融研究顯示，若移除影像庫重用機制，代理在需要次級影像使用（secondary image use）的複雜任務上表現下降最為顯著，證明了可重用視覺證據對於迭代視覺優化的必要性。另一方面，若將 ODE 替換為靜態合成食譜，在相同資料預算下，SFT 與 RL 的增益都明顯降低，說明 rollout 回饋演化能產生更紮根的 SFT 軌跡與更貼近策略學習前沿的 RL 任務。這兩個消融結果共同驗證了框架中兩個核心元件缺一不可，且各自對不同面向的能力提升具有不可替代的貢獻。

**Q10：視覺原生代理工具框架與 ODE 適用於哪些實際應用場景？**
A：這套框架特別適用於需要結合視覺線索與外部知識的開放世界任務，例如：以圖搜圖的商品辨識與比價、學術論文中的圖表與公式溯源、旅遊景點影像辨識並結合網路資訊的深度問答，以及需要多輪視覺驗證的鑑識或醫療影像分析。在這些場景中，使用者往往只提供一張影像，但真正的答案需要從影像出發、串接多個工具才能取得，因此視覺證據的可重用性與資料的策略匹配性都至關重要。

**Q11：在實際產品部署這套框架時，需要考量哪些工程與產品因素？**
A：實際部署時首先需考量工具呼叫的成本與延遲：9 個核心工具中，網路搜尋、瀏覽與視覺搜尋屬於高延遲操作，必須設計合理的執行預算與快取機制。其次，影像庫的儲存與管理需要兼顧隱私與效率，特別是在處理使用者上傳影像時，應設計影像生命週期與存取控制。此外，rubric 的設計需要領域專家參與，以避免評分偏差導致資料演化偏離真實需求；最後，rollout 的計算成本也是一大考量，需要在資料品質與訓練成本間取得平衡。

**Q12：這項研究對多模態代理領域的整體影響是什麼？它改變了哪些研究範式？**
A：這項研究最重要的影響在於將「資料建構」從一次性策展轉變為與策略共同演化的閉環優化過程，挑戰了過去「先設計食譜、再規模化」的靜態範式。同時，它強調了視覺原生設計的重要性——視覺證據不應只是輸入或輸出，而應成為代理工作空間中的一等公民，可被持續引用與操作。這種「工作空間」與「資料演化」的協同設計思路，可能成為未來多模態代理研究的新範式，並推動整個領域從「單次互動」走向「證據累積型推理」。

**Q13：這項研究存在哪些已知的限制？**
A：首先，雖然框架涵蓋了 9 個核心工具，但對於需要專業領域工具（如醫療影像分析、工業檢測）的任務仍可能不足，限制了其在垂直領域的應用。其次，rubric 的設計品質直接影響 ODE 的演化方向，若 rubric 設計不夠全面或存在偏差，可能導致資料演化偏離真實需求。此外，rollout-feedback 機制需要大量計算資源進行策略推演，在資源受限的環境中可能難以實施。最後，評估集中在 8 個基準上，對於真實開放世界場景的泛化能力仍需更多驗證。

**Q14：在哪些情況下 ODE 可能無法帶來預期效果？**
A：當 rubric 無法準確捕捉任務的關鍵挑戰時，ODE 的演化方向可能偏離，例如 rubric 若過度強調工具呼叫次數，可能導致代理學會冗長但低效的軌跡。此外，若目標策略已接近能力上限，學習前沿上的可學習任務可能不足，使 ODE 難以產生有意義的新資料。在任務過於簡單或過於困難的極端情況下，rollout 回饋的訊號可能過於稀疏或過於雜訊，使得配置優化難以收斂。最後，若初始種子資料的品質過低，演化過程可能陷入局部最優，無法產生真正多樣化且紮根的訓練樣本。

**Q15：基於這項研究，未來有哪些值得探索的研究方向？**
A：未來可朝幾個方向延伸：第一，擴展工具集與工作空間設計，例如引入多模態資料庫查詢、專業領域工具或代理間協作機制，使框架能處理更複雜的真實任務。第二，深化閉環演化機制，例如將 rubric 本身也納入學習過程，或探索多目標演化以同時優化多項能力指標。第三，將 ODE 應用於其他模態或任務（如純文字深度搜尋、影片理解），驗證其通用性。第四，研究如何在有限計算資源下進行高效 rollout，例如透過重要性抽樣或蒸餾。最後，探討視覺原生設計與人類認知過程的對齊，使代理的視覺推理路徑更具可解釋性與可信度。

## 實務應用指南

### 適用場景

以下列舉五個適合導入本框架的具體實務場景：

**1. 電商商品溯源與比價助理**
消費者上傳商品圖片後，代理需透過視覺搜尋（Google Lens）找出同款或相似商品，再以網路搜尋與瀏覽工具取得價格、評價與規格。影像庫重用機制可讓代理在第一輪視覺搜尋後，針對回傳影像中的局部細節（如品牌標籤、型號）執行 Zoom In 二次搜尋，避免反覆上傳同一張圖。

**2. 旅遊地標辨識與深度導覽**
使用者拍攝地標照片，代理透過視覺搜尋定位地點，再以網路搜尋與瀏覽取得歷史背景、開放時間、交通資訊。當第一輪搜尋回傳的網頁截圖包含地圖或文字標示時，代理可將該截圖存入影像庫，後續以 Zoom In 放大細節區域做更精準的二次查詢。

**3. 學術論文與圖表解析**
研究人員上傳論文中的圖表，代理透過 Scholar Search 找出原始出處，再以 Visit 工具瀏覽論文頁面取得方法說明。影像庫可保存論文中的圖表影像，後續 Python 執行工具可直接引用該影像進行數值估算或繪圖驗證。

**4. 醫療影像輔助查詢（教育用途）**
醫學生上傳 X 光或病理切片影像，代理透過視覺搜尋比對相似案例，再以 Scholar Search 取得相關文獻。影像庫重用讓代理能在多輪搜尋中累積視覺證據，逐步縮小鑑別診斷範圍（此場景僅限教育輔助，不可作為臨床診斷工具）。

**5. 智慧客服中的產品故障排查**
使用者上傳故障設備照片，代理透過視覺搜尋辨識型號，再以網路搜尋取得維修建議。當搜尋結果包含零件圖或電路圖時，代理可將影像存入影像庫，後續以 Flip 或 Rotation 工具調整視角，再進行細節比對。

### 實作前置條件

**資料需求**
- 初始種子資料集：需準備一批涵蓋目標領域的圖文對（image-question-answer triples），可從 MMSearch、VDR、SimpleVQA 等公開基準擷取或自行策展。
- 評分標準（Rubric）：需為 SFT 模式定義「資訊複雜度」「工具使用品質」「工具模式多樣性」等維度；為 RL 模式定義「捷徑洩漏」「難度匹配」「學習效用」等維度。
- 工具回傳影像的快取空間：影像庫需持久化儲存所有工具回傳影像，建議預留每輪數 GB 至數十 GB 的儲存空間（視任務量而定）。

**算力需求**
- 訓練階段：8B 模型的全參數微調建議至少 8 張 A100/H100 GPU；30B 模型建議 16 張以上 A100/H100 或使用 ZeRO-3 分散式訓練。
- Rollout 階段：每輪 ODE 演化需對目標策略執行大量軌跡推演，建議配置獨立的推理 GPU 叢集（如 vLLM 或 TGI 服務），避免與訓練資源競爭。
- 工具呼叫環境：網路搜尋、瀏覽、視覺搜尋等工具需穩定的 API 配額與低延遲回應。

**技能需求**
- 熟悉 MLLM 微調流程（LoRA、全參數 SFT、GRPO/PPO 等 RL 演算法）。
- 具備工具增強代理（tool-augmented agent）的開發經驗，理解 ReAct、Reflexion 等代理框架。
- 能撰寫評分標準（rubric）並設計閉環回饋機制。
- 具備分散式訓練與推理服務的部署能力。

### 實作步驟建議

**步驟一：建構視覺原生代理工具框架**
1. 實作 9 個核心工具的介面：Web Search、Image Search、Scholar Search、Visit、Visual Search、Zoom In、Rotation、Flip、Python Execution。
2. 設計影像庫參考協議：為每張影像分配唯一識別碼（如 `<Image: 0>`、`<Image: 1>`），讓後續工具呼叫可透過參考碼引用先前影像，而非重新上傳。
3. 將原始任務影像與所有工具回傳影像統一註冊至影像庫，確保中間視覺證據可被後續步驟重用。

**步驟二：設計 ODE 閉環資料生成流程**
1. 定義可演化配置（Evolvable Config）：包括種子提案、探索、圖組織、任務策展、驗證、工具配置、執行預算、策略與評審設定等模組。
2. 實作前向策展管線（Forward Curation）：根據當前配置合成候選任務，執行目標策略的 rollout，收集軌跡資料。
3. 實作後向優化管線（Backward Optimization）：使用基於評分標準的軌跡分析結果，調整下一輪的配置參數。

**步驟三：執行 SFT 階段的資料演化**
1. 初始化第一輪配置，合成一批 SFT 候選任務。
2. 讓目標策略在視覺原生框架中執行 rollout，收集成功軌跡。
3. 根據「資訊複雜度」「工具使用品質」「工具模式多樣性」等評分維度篩選高品質軌跡。
4. 用篩選後的軌跡微調策略模型，並將更新後的策略用於下一輪 ODE。

**步驟四：執行 RL 階段的資料演化**
1. 切換至 RL 模式，根據「捷徑洩漏」「難度匹配」「學習效用」等維度合成任務。
2. 優先選擇位於策略學習前沿的任務（策略成功率約 30%–70% 的任務最有學習價值）。
3. 使用 GRPO 或 PPO 等演算法進行策略優化。
4. 重複 ODE 循環，直到策略在驗證集上收斂。

**步驟五：評估與部署**
1. 在 MMBC、HLE-VL、BC-VL、MMSearch、VDR、MMSearch+、SimpleVQA、FVQA 等 8 個基準上評估。
2. 比較啟用與停用影像庫重用的效能差異，確認視覺原生框架的貢獻。
3. 將訓練好的策略部署至生產環境，搭配視覺原生框架提供服務。

### 潛在風險與注意事項

**風險一：影像庫膨脹導致上下文溢位**
隨著軌跡長度增加，影像庫中的影像數量可能快速累積，超出 MLLM 的上下文視窗限制。
*緩解措施*：實作影像摘要機制，將已充分使用的影像壓縮為文字描述後從影像庫中淘汰；或採用階層式影像管理，僅保留最近 N 張影像於活躍上下文。

**風險二：ODE 陷入局部最優**
閉環演化可能使資料分布過度集中於當前策略擅長的任務類型，削弱泛化能力。
*緩解措施*：在評分標準中加入「任務多樣性」懲罰項；定期注入外部種子資料以維持分布廣度；監控驗證集效能以偵測過擬徵兆。

**風險三：工具呼叫成本失控**
每輪 ODE 需執行大量 rollout，若工具 API 按呼叫計費，成本可能快速攀升。
*緩解措施*：設定每輪的執行預算上限；對工具回應做快取以避免重複呼叫；優先使用開源工具（如自架搜尋引擎）取代付費 API。

**風險四：評分標準（Rubric）設計偏差**
若評分標準過度獎勵特定工具使用模式，可能導致策略學會投機行為（例如刻意呼叫無關工具以滿足多樣性指標）。
*緩解措施*：採用多維度評分並設定權重平衡；定期以人工抽樣檢核評分結果；引入「工具呼叫必要性」獨立審查機制。

**風險五：視覺搜尋工具的版權與隱私爭議**
Google Lens 等視覺搜尋工具的回傳結果可能涉及第三方內容的版權問題。
*緩解措施*：在服務條款中明確告知使用者資料使用範圍；對回傳影像做來源標註；避免將第三方影像直接用於商業再散布。

**風險六：基準過擬合**
若 ODE 演化過程中過度參考 8 個評估基準的任務分布，可能在基準上表現優異但實際應用泛化不佳。
*緩解措施*：保留獨立的「未見測試集」用於最終驗證；在 ODE 演化中混入未在評估基準中出現的領域資料。

### 與其他技術的整合建議

**與 RAG（Retrieval-Augmented Generation）系統整合**
視覺原生框架的 Visit 工具可作為 RAG 的多模態延伸：當傳統文字 RAG 無法回答視覺相關問題時，代理可透過 Visit 取得網頁截圖並存入影像庫，再以視覺推理補充答案。建議將影像庫設計為可與現有向量資料庫（如 Milvus、Qdrant）共存的獨立模組，文字證據走 RAG 管線，視覺證據走影像庫管線。

**與代理框架（LangChain、AutoGen）整合**
本框架的 9 個工具可封裝為 LangChain 的 Tool 物件或 AutoGen 的 Function，影像庫參考協議則透過自訂的訊息格式傳遞。建議保留框架原有的軌跡記錄機制，以便與既有監控與除錯工具相容。

**與 RLHF 流程整合**
ODE 的 RL 模式可與現有的人類回饋強化學習流程並行：人類回饋用於對齊安全性與風格，ODE 用於提升工具使用能力。建議將 ODE 置於 RLHF 之前，避免人類回饋的獎勵模型干擾工具使用策略的學習。

**與 MLLM 蒸餾流程整合**
若需將 30B 模型的策略蒸餾至更小的部署模型，可將 ODE 演化過程中收集的高品質軌跡作為蒸餾資料來源。蒸餾時需保留影像庫參考協議的標記，讓小模型學會引用中間視覺證據。

**與視覺基礎模型（CLIP、Grounding DINO）整合**
視覺搜尋工具可改用自架的視覺基礎模型取代 Google Lens，以降低對外部 API 的依賴並提升可控性。影像庫中的影像可預先透過 CLIP 編碼為向量，加速後續相似度比對。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先理解「多模態大型語言模型」與「工具增強代理」的基本概念，再閱讀本論文的第 1 節與第 2.1 節。視覺原生框架的核心精神是「不要把工具回傳的影像丟掉，而是讓後續步驟能引用它」，這個直覺比技術細節更重要。實作上可先從小規模的 2–3 個工具開始，體驗影像庫重用帶來的差異，再逐步擴充至完整 9 個工具。

**給 AI 工程師**
重點關注第 2.2 節的 ODE 閉環設計與評分標準的工程實作。建議先在現有 MLLM（如 Qwen3-VL-8B）上重現基準實驗，確認視覺原生框架的效益後，再投入 ODE 的閉環開發。閉環系統的除錯比單次訓練更具挑戰性，建議建立完善的軌跡記錄與評分視覺化工具，以便追蹤每輪演化的資料分布變化。

**給研究者**
本論文的核心貢獻在於「將資料生成視為適應性優化過程」的視角轉換，以及影像庫參考協議的形式化。建議從這個視角出發，思考是否能將 ODE 推廣至其他代理任務（如純文字深度搜尋、程式碼生成代理），或探索更高效的評分標準設計（例如以小型評審模型取代人工定義的 rubric）。此外，影像庫重用對長程視覺推理的影響是值得深入探討的方向。

**給產品經理**
本框架的商業價值在於讓 MLLM 代理能處理「需要多輪視覺證據累積」的複雜任務，而非僅限於單輪的圖文問答。導入時應優先評估目標場景是否確實需要迭代視覺優化（例如電商比價、旅遊導覽），若僅需單輪視覺理解，則不必採用完整框架。建議以 8B 模型進行概念驗證（PoC），確認效益後再評估 30B 模型的部署成本與效能提升幅度。
