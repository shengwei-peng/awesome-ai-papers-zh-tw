## ⚡ TL;DR

現有遊戲 AI 評測涵蓋遊戲狹隘、缺乏語言指令，或仰賴高變異的線上 rollout。
本文提出 GameHorizon Suite，含自動化多層級指令標註、大規模遊戲資料集與評測基準。
評測 47 個模型逾百萬次呼叫，發現任務難度層級與模型能力差異，且離線分數能預測線上表現。

## 摘要翻譯

現代電子遊戲為 AI 模型提供了一個可量測的測試平台（testbed），結合視覺理解、指令分解、目標規劃，以及跨越多個時程（temporal horizons）的精確動作控制等能力。然而，現有的資料集（datasets）與評測基準（benchmarks）往往僅涵蓋少數遊戲、缺乏語言指令，或仰賴高變異性的線上 rollout 軌跡。為了解決這些挑戰，我們提出 GameHorizon Suite（GameHorizon 套件），一個統一的資料與評估套件，用於衡量不同模型家族（model families）在不同時程（horizons）下的遊戲進行能力（gameplay capabilities）。GameHorizon Suite 包含三個組成部分。首先，GameHorizon-Annotator（GameHorizon 標註工具）是一個可擴展且自動化的多時程指令標註管線（annotation pipeline）。其次，利用此管線，我們建構了 GameHorizon-Data（GameHorizon 資料集），這是首個大規模 AAA 級遊戲實機資料集，包含時間對齊的影片、玩家動作與多時程指令。該資料集包含來自 21 款遊戲、由 100 名人類專家玩家所收集的 5,000 小時遊戲紀錄。第三，我們建構了 GameHorizon-Bench（GameHorizon 評測基準），具備可重現的離線測試（offline track），以及逐步的線上測試（online track）。離線測試軌道利用數千個標準化問題進行可重現的評估，這些問題分為三項主要任務與一系列診斷性變體（diagnostic variants）；線上測試軌道則檢驗離線分數是否能反映實際遊戲進行能力，並將失敗定位到長時程遊戲進行中的特定步驟。基於 GameHorizon Suite，我們透過超過一百萬次的模型呼叫（model invocations）評估了 47 個模型，揭示了有意義的任務難度層級，以及模型能力之間的顯著差異。本研究可為跨時程、跨模型家族的遊戲進行能力評估提供標準化衡量基準。我們將公開釋出資料集、標註工具與評測基準，以促進後續研究。

### 核心貢獻（3～5點）
- 提出 GameHorizon Suite（GameHorizon 套件），一個統一的多時程遊戲資料與評估套件，涵蓋資料建構、自動標註與標準化評測。
- 設計 GameHorizon-Annotator（GameHorizon 標註工具），一個可擴展且自動化的多時程指令標註管線。
- 建構 GameHorizon-Data（GameHorizon 資料集），首個大規模 AAA 級遊戲實機資料集，包含 5,000 小時、21 款遊戲、100 名專家玩家的時間對齊影片、動作與多時程指令。
- 建立 GameHorizon-Bench（GameHorizon 評測基準），提供可重現的離線測試與逐步線上測試，能將失敗定位到長時程遊戲進行中的特定步驟。
- 透過超過一百萬次模型呼叫評估 47 個模型，建立跨時程、跨模型家族的遊戲能力標準化衡量基準。

### 適合對象
本論文適合對遊戲 AI、多模態基礎模型、長時程決策與規劃、以及 AI 評測基準設計感興趣的研究人員與工程師；特別適合需要大規模遊戲實機資料、多時程語言指令標註方法，以及可重現離線／線上評估框架的讀者。

## 深度分析

#### 方法論解析

GameHorizon Suite（GameHorizon 套件）的核心設計理念，是將「遊戲玩法（gameplay）」視為一個跨越多重時間尺度（multi-horizon）的統一問題：無論目標是幾秒內撿起物品、幾分鐘內贏得戰鬥，或整場遊戲中執行策略，最終都體現在同一串原始操作（primitive actions），例如按鍵（keystrokes）與滑鼠移動（mouse movements）。因此，套件必須同時衡量「規劃（planning）」與「執行（acting）」兩種能力，並且能對比專用遊戲 agent 與通用視覺語言模型（Vision-Language Models, VLMs）。

整個套件分為三大元件：

1. **GameHorizon-Annotator（GameHorizon 自動標註器）**  
   這是一個可擴展（scalable）且自動化的多時間尺度指令標註管線。與 Game-TARS 等依賴人工標註的工作不同，GameHorizon-Annotator 採用**由下而上（bottom-up）**的抽象機制：先從最細微的短期操作（short-horizon operations）開始，再逐步聚合為中期目標（medium-horizon goals），最後形成長期策略（long-horizon strategies）。這種金字塔式（pyramid）結構讓模型能夠學習不同層級的語言目標與對應動作之間的對齊關係，而不需要為每個時間尺度分別設計標註流程。

2. **GameHorizon-Data（GameHorizon 資料集）**  
   利用上述標註管線，作者建構了首個大規模 AAA 遊戲玩法資料集，包含 **5,000 小時**的遊戲錄影、玩家操作記錄，以及與時間對齊（temporally aligned）的多層級自然語言指令。資料來自 **21 款遊戲**、由 **100 位人類專家玩家**錄製，涵蓋開放世界（open-world）、動作角色扮演（action role-playing, ARPG）、競技射擊（competitive shooter）、沙盒生存（sandbox survival）、生物收集冒險（creature-collecting adventure）等多種類型。這使得資料集在異質性（heterogeneity）與規模上都超過 D2E、gaming-500-hours 等先前語料。

3. **GameHorizon-Bench（GameHorizon 評測基準）**  
   評測分為兩條軌道：
   - **Offline track（離線評測軌道）**：透過數千道標準化題目進行可重現評估，包含三大主任務：
     - **Single-horizon action（單一時間尺度動作預測）**：根據當前畫面與指令預測下一步操作；
     - **Multi-horizon instruction decomposition（多時間尺度指令分解）**：將高層目標拆解為子目標；
     - **Cross-horizon consistency（跨時間尺度一致性）**：檢查不同層級指令之間是否邏輯一致。
     此外還設有一系列診斷式變體（diagnostic variants），用於更細粒度地定位模型缺陷。
   - **Online track（線上評測軌道）**：透過在長期遊戲流程中執行短期子任務，驗證離線分數是否真能反映實際遊玩能力。此軌道包含**順序相依的因果任務（order-dependent causal tasks）**與**順序彈性的主題任務（order-flexible thematic tasks）**，並利用環境重置（environment reset）進行逐步驗證與失敗定位（failure localization）。

整體方法論的關鍵創新在於「統一量尺（unified yardstick）」：同一套資料與評測框架同時服務於專用遊戲 agent（擅長動作執行但規劃能力弱）與通用 VLMs / GUI agents（擅長規劃但動作執行未經系統衡量），從而讓不同模型家族（model families）可以在相同標準下比較。

#### 實驗數據解讀

作者基於 GameHorizon Suite 對 **47 個模型**進行了超過 **一百萬次模型呼叫（model invocations）**，涵蓋通用 VLMs、統一多模態模型（Unified Multimodal Models, UMMs）、程式與 GUI agent，以及專用遊戲 agent。實驗結果呈現出幾個值得注意的現象：

1. **任務難度具有明確層級（hierarchy of task difficulty）**  
   實驗顯示，預測當前動作（single-horizon action）相對最容易；而規劃未來動作、將複雜目標分解為子目標（multi-horizon decomposition）則困難得多。這與引言中對兩類模型家族的觀察一致：專用遊戲 agent 在動作層級表現較好，但在高層規劃上可能落後於通用模型。

2. **離線分數與線上表現呈正相關**  
   Online track 的結果顯示，任務成功率（task success rates）與 offline track 的分數之間存在明顯正相關。這驗證了離線標準化題目可以作為實際遊玩能力的有效代理指標（proxy），解決了過去線上評測樣本數少、變異大的問題。

3. **多時間尺度指令能顯著提升規劃能力**  
   相較於僅使用視覺輸入（vision-only input），加入中期與長期指令後，未來動作規劃（future-action planning）提升了 **7.2 個百分點**。這證明了 GameHorizon-Annotator 產生的多層級語言目標不僅是標註副產品，更是能實際改善模型規劃表現的監督訊號。

4. **模型能力差異顯著**  
   不同模型家族之間的表現差距明顯，且這種差距會隨著時間尺度拉長而放大。這意味著目前尚不存在一個「萬能」模型同時擅長感知、規劃與精確控制；也說明 GameHorizon Suite 能夠有效區分模型在不同維度的強弱。

5. **失敗模式可被定位**  
   透過 offline track 的診斷變體與 online track 的逐步驗證，作者能夠區分模型是「看錯當前動作」、「推論下一個目標錯誤」，還是「無法將目標對應到正確控制」。這種細粒度診斷是過去僅用 aggregate success rate 無法達成的。

#### 與現有研究的比較

GameHorizon Suite 在數個關鍵面向超越了現有資料集與基準：

| 面向 | 先前研究 | GameHorizon Suite |
|---|---|---|
| **遊戲覆蓋範圍** | GameWorld 僅限簡單小遊戲；STEVE-1、MineDojo 僅限 Minecraft；WildWorld 僅限單一遊戲 Monster Hunter Wilds | 21 款 AAA 等級遊戲，跨越多種類型 |
| **語言指令標註** | NitroGen、GameVerse 完全無指令；Open-P2P 僅有極稀疏標註 | 自動產生並時間對齊短期、中期、長期三層指令 |
| **評測規模與重現性** | Lumine 每場景僅 3 次試驗；GameVerse 僅 3–20 個案例；高度依賴特定環境與 agent harness | 離線軌道數千道標準化題目；線上軌道可環境重置並逐步驗證 |
| **標註成本** | Game-TARS 等依賴人工標註，難以擴展 | GameHorizon-Annotator 自動化、可擴展 |
| **模型家族比較** | 多數基準僅針對單一類型模型（如專用 game agent 或通用 VLM） | 同時評測 47 個模型，涵蓋 VLMs、UMMs、GUI agents、專用遊戲 agents |

**主要改進**：
- 從單一遊戲或小遊戲走向**多樣化 AAA 遊戲**，提升結論的泛化性（generalizability）。
- 從稀疏或無語言標註走向**密集、多層級、時間對齊的指令金字塔**，使指令遵循（instruction following）、目標規劃（goal planning）與動作執行（action execution）可被系統性評估。
- 從高變異、小樣本的線上 rollout 走向**可重現的離線題庫 + 可定位失敗的線上軌道**，提升評測信心與診斷價值。

**限制**：
- 雖然涵蓋 21 款遊戲，但仍無法代表整個電子遊戲產業；某些類型（如即時戰略 RTS、格鬥遊戲、競技 MOBA）可能仍不足。
- 資料來自人類專家玩家，可能偏向高技能玩法，對於學習「從新手成長」或「探索性行為」的模型較不適用。
- 離線評測雖然標準化，但終究是基於靜態題目；某些動態互動能力（如即時適應對手策略）仍需線上環境才能完整捕捉。
- 線上軌道雖引入環境重置，但仍需特定遊戲環境與控制介面，跨研究室的完全重現仍可能受授權與技術整合限制。

#### 可重現性評估

可重現性（reproducibility）是 GameHorizon Suite 強調的重點之一，其設計在以下幾個層面提升了透明度：

1. **資料與工具將公開釋出**  
   作者明確表示將釋出 GameHorizon-Data、GameHorizon-Annotator 與 GameHorizon-Bench。這是讓其他研究者能夠重現結果、進一步訓練模型與設計對照實驗的基礎。

2. **離線軌道高度可重現**  
   Offline track 使用數千道標準化題目，搭配固定的動作與指令選項，理論上只要取得資料集與題目即可在不同硬體與 API 上重複執行，無需遊戲執行環境。這大幅降低了重現門檻。

3. **線上軌道引入環境重置與子任務設計**  
   雖然線上評測本質上仍依賴遊戲環境與 agent harness，但透過將長期任務拆解為短期子任務、並允許環境重置，研究者可以在相同初始狀態下重複測試特定步驟，從而提升線上結果的穩定性與可比較性。

4. **模型權重與 API 依賴**  
   評測涉及 47 個模型，其中部分為商業 API（如 Gemini、Claude、GPT-4V 等），其權重未公開，且 API 行為可能隨時間更新。這意味著未來重現時，相同 prompt 與輸入可能得到略有不同的輸出。建議作者釋出完整 prompt、取樣參數（temperature、top-p 等）與版本資訊，以最大化可重現性。

5. **標註管線的自動化**  
   GameHorizon-Annotator 的自動化特性讓其他研究者可以將相同流程應用於新遊戲，進行擴展研究，而不必從頭建立人工標註團隊。

整體而言，GameHorizon Suite 在資料、評測工具與方法論上的開放承諾，使其可重現性顯著優於過去依賴私有環境或人工標註的基準；但商業模型的 API 變異性與部分遊戲環境的授權問題，仍是未來需要持續完善的環節。

#### 未來研究方向

基於 GameHorizon Suite 的設計與實驗發現，以下幾個方向值得後續研究深入探索：

1. **擴展遊戲類型與多樣性**  
   將資料集從 21 款遊戲擴展到更多類型，例如即時戰略（Real-Time Strategy, RTS）、多人線上戰術競技（Multiplayer Online Battle Arena, MOBA）、格鬥遊戲（fighting games）、模擬經營與體育遊戲，以測試模型在不同決策節奏與資訊不完全環境下的表現。

2. **從評測走向訓練**  
   目前 GameHorizon Suite 主要作為評測基準，但未來可利用其多層級指令與動作對齊資料，訓練新一代的 vision-language-action（VLA）模型，特別是強化「規劃—執行」聯合學習（joint planning-acting learning）的能力。

3. **分層式強化學習（Hierarchical Reinforcement Learning, HRL）**  
   短期操作、中期目標、長期策略的金字塔結構，天然適合設計分層式 RL agent。未來可研究如何讓高層策略模組自動產生子目標，並由低層控制模組執行。

4. **即時互動式評測（real-time interactive evaluation）**  
   目前的 online track 仍偏重可重置的短期子任務。未來可設計真正即時、不可重置的長期對戰或合作任務，評估模型在動態對手與突發狀況下的適應能力。

5. **多語言與跨文化遊戲指令**  
   現有資料與評測可能以英文為主。未來可擴展至多語言指令，研究模型對不同語言結構與遊戲術語的理解，並促進全球研究社群使用。

6. **人機協作與可解釋性（human-AI collaboration & interpretability）**  
   利用多層級指令結構，研究模型如何向人類解釋其當前目標與下一步計畫，並支援人類即時介入或給予高層策略指導。

7. **失敗診斷與自動修復工具**  
   基於 offline track 的診斷變體，開發自動化工具來分析模型在哪些時間尺度、哪些遊戲類型、哪些動作類別上最容易失敗，並據此進行針對性微調或資料增強。

8. **標準化遊戲控制介面（standardized game harness）**  
   為了進一步提升可重現性，社群可共同開發開源的通用遊戲控制介面，讓不同模型能在相同環境、相同輸入輸出協定下被評測，減少因 harness 差異造成的比較偏差。

9. **長期因果推理與策略適應**  
   針對 order-dependent causal tasks，未來可設計更強調長期因果鏈與對手建模（opponent modeling）的任務，推動模型從「執行預定計畫」進步到「根據環境反饋動態調整策略」。

10. **安全性與對齊（safety & alignment）**  
    遊戲作為複雜互動環境，也可用來研究 AI 的安全性問題，例如模型是否會為了達成遊戲目標而採取非預期或有害策略，以及如何透過多層級目標對齊來避免這類行為。

## 論文問答

**Q1：GameHorizon Suite 旨在解決 AI 遊戲玩法研究中的什麼根本問題？**

A：GameHorizon Suite 旨在建立一個統一且標準化的評估框架，用於衡量不同時間跨度和模型家族在遊戲玩法上的能力。現代電玩遊戲要求模型同時具備視覺理解、指令分解、目標規劃與精確動作控制等多種能力，但現有基準測試無法一致地衡量這些整合能力。此套件提供了一個低成本、可重現的衡量標準，能夠在相同的遊戲任務上比較專用遊戲代理模型與通用視覺語言模型。

**Q2：為何現有的遊戲資料集與基準測試無法滿足全面 AI 評估的需求？**

A：現有基準測試存在三大限制：因標註成本而導致的遊戲覆蓋範圍狹窄、缺乏完整的語言指令與目標標註，以及依賴樣本數少且變異高的線上 rollout。例如，許多資料集僅聚焦於 Minecraft 或《魔物獵人 荒野》等單一遊戲，有些則完全省略指令或只提供稀疏標註。此外，少數試驗的線上評估結果對特定環境與代理框架非常敏感，難以重現和解釋。

**Q3：為何跨越多個時間跨度的遊戲玩法評估對 AI 能力特別重要？**

A：遊戲目標自然涵蓋不同的時間尺度，從數秒內收集物品到整場遊戲中執行策略，而這些目標都體現在相同的原始動作串流中，例如按鍵與滑鼠移動。這種多時間跨度結構使電玩成為評估模型能否橋接高層規劃與低層執行的理想試驗場。若未跨時間跨度評估，我們將無法判斷模型是否真正理解長期目標、中期子目標與即時動作之間的關係。

**Q4：GameHorizon Suite 的三個核心組成是什麼，彼此如何關聯？**

A：此套件包含 GameHorizon-Annotator、GameHorizon-Data 與 GameHorizon-Bench，形成從資料生成到評估的完整流程。Annotator 透過可擴展的自下而上抽象流程自動產生多時間跨度指令；Data 元件利用此流程建立大規模資料集，將遊戲畫面、玩家動作與多層次指令對齊；Bench 則提供標準化的離線與線上評估協定，以衡量模型能力。三者結合，使跨多元遊戲與模型家族的可重現研究成為可能。

**Q5：相較於先前的標註方法，GameHorizon-Annotator 的關鍵創新是什麼？**

A：GameHorizon-Annotator 引入了自動化且可擴展的流水線，能夠在三個時間跨度上產生自然語言指令金字塔，包括短期操作、中期目標與長期策略。與 Game-TARS 等人工標註方法不同，它採用自下而上的方式，將細粒度指令抽象為高層目標，使數千小時的遊戲過程標註成為可行。這種自動化方法克服了過去限制基準覆蓋範圍與指令豐富度的成本問題。

**Q6：GameHorizon-Bench 如何設計離線與線上軌道，以確保評估的可重現性與意義性？**

A：離線軌道使用數千道標準化題目，分為三大主要任務：單一時間跨度動作、多時間跨度指令分解，以及跨時間跨度一致性，並輔以診斷變體進行細粒度分析。線上軌道則透過短期子任務評估長期遊戲玩法，並利用環境重置實現逐步驗證與精確的失敗定位。這種雙軌設計確保離線分數能與實際遊戲表現相互驗證，同時保留純線上 rollout 所缺乏的可重現性。

**Q7：GameHorizon Suite 的實驗涉及哪些模型與評估規模？**

A：作者評估了 47 個模型，進行超過一百萬次的模型呼叫與 API 請求，涵蓋通用視覺語言模型、統一多模態模型、程式與圖形介面代理，以及專用遊戲代理。這項大規模評估橫跨 Gemini、GPT-4、SIMA 2 與多種專業遊戲代理等多元模型家族。如此龐大的規模使統計上具意義的跨模型比較成為可能，並清楚呈現任務難度的層級結構。

**Q8：離線評估中關於任務難度與模型能力的關鍵發現是什麼？**

A：結果顯示出有意義的任務難度層級，其中規劃未來動作與分解複雜目標比決定當前動作更具挑戰性。模型在三項主要任務上的能力差異顯著，顯示某方面表現強並不保證其他方面同樣出色。這些發現證明 GameHorizon-Bench 能有效區分模型的視覺理解、規劃與動作執行能力。

**Q9：消融實驗與線上實驗揭示了多時間跨度指令的什麼價值？**

A：納入中期與長期指令後，未來動作規劃相較於僅使用視覺輸入提升了 7.2 個百分點，顯示結構化目標資訊的有效性。線上軌道進一步顯示離線分數與實際任務成功率之間存在明顯正相關，驗證了離線評估可作為真實遊戲能力的可靠代理指標。此外，逐步線上設計使研究者能將失敗定位到長期遊戲中的特定步驟，提供超越整體成功率的診斷洞見。

**Q10：除了學術研究，GameHorizon Suite 還可應用於哪些實務場景？**

A：GameHorizon Suite 可作為遊戲 AI 代理開發與品質保證的標準化工具，協助開發者比較不同架構並識別規劃或控制上的特定弱點。它也能透過提供多時間跨度推理與可執行動作對齊的具體基準，指導通用視覺語言模型的設計。此外，資料集與標註流水線可支援互動式遊戲助理、自動化遊戲測試系統，以及面向玩家的教學工具之開發。

**Q11：在產業環境中部署 GameHorizon Suite 時應考慮哪些產品層面因素？**

A：產業部署需考量執行數百萬次模型呼叫的運算成本、環境重置與標準化框架的需求以確保線上評估可重現，以及使用 AAA 遊戲畫面所涉及的授權與隱私問題。此套件的模組化設計使企業可僅採用離線基準進行快速迭代，或整合完整線上軌道進行最終驗證。此外，由於資料集涵蓋 21 款多元遊戲，產品團隊可選擇相關子集進行領域特定模型開發，同時受益於標準化指標。

**Q12：GameHorizon Suite 可能如何影響更廣泛的具身 AI 與多模態研究領域？**

A：透過提供連結視覺、語言與動作的統一基準，GameHorizon Suite 能加速遊戲之外具身 AI 的進展，包括機器人與自動化系統。它建立了一套將長期目標分解為可衡量子任務並在特定步驟診斷失敗模式的方法論。此套件強調可重現、低成本的離線評估與真實線上測試並重，可能成為複雜互動環境未來基準測試的範本。

**Q13：透過診斷分析，論文揭示了當前模型哪些已呈現的限制？**

A：診斷結果顯示，當前模型在規劃未來動作與分解複雜目標方面比即時動作識別更為困難，暴露了長期推理的瓶頸。專用遊戲代理通常擅長控制但缺乏規劃能力，而通用模型雖能規劃，卻缺乏系統性的動作執行衡量與可靠性。這些發現顯示目前沒有任何單一模型家族能主宰所有時間跨度，在高層推理與低層控制的對齊上仍需重大進展。

**Q14：逐步線上評估凸顯了哪些失敗案例？**

A：線上軌道能將失敗定位到長期遊戲中的特定步驟，區分當前動作誤判、下一目標推論錯誤，以及目標無法對應到適當未來控制等不同情況。這種細粒度診斷揭示整體成功率可能掩蓋性質迥異的失敗模式，而這些模式需要不同的解決方案。例如，模型可能理解整體策略，卻在關鍵的順序相依因果子任務上失敗；或者規劃正確，但在關鍵時刻執行不精確的控制。

**Q15：GameHorizon Suite 為遊戲 AI 研究開啟了哪些未來方向？**

A：未來研究可擴充資料集以納入更多遊戲、語言與玩家技術水平，並開發能同時優化所有時間跨度規劃與動作執行的更強模型。研究者也可探索互動式學習設定，讓模型透過實際遊玩經驗而非僅靠離線問答來改進。此外，標註流水線可擴展至機器人或軟體自動化等其他領域，將多時間跨度指令框架轉移到電玩之外的應用場景。

## 實務應用指南

### 適用場景

1. **遊戲 AI 模型的標準化選型與能力評估**：企業或研究團隊可利用 GameHorizon-Bench 的離線與線上評測，比較不同通用視覺語言模型（VLM）、專用遊戲代理（Game Agent）與統一多模態模型（UMM）在動作執行、目標規劃與指令分解上的表現，作為採購或技術路線選擇的依據。

2. **專用遊戲代理的訓練與微調**：GameHorizon-Data 提供對齊的遊戲畫面、玩家原始操作與多時間尺度語言指令，適合用來訓練或微調 VLA（Vision-Language-Action）架構，補強現有遊戲代理在長期規劃與語言理解上的不足。

3. **多模態規劃與指令分解研究**：研究者可利用 GameHorizon-Annotator 自動產生的短、中、長期指令金字塔，分析模型如何將高階策略拆解為可執行子目標，並診斷失敗發生在「理解現況」「推論目標」或「映射操作」哪一階段。

4. **遊戲品質保證（QA）與自動化測試**：將 GameHorizon-Bench 的 stepwise online testing 整合至 CI/CD 流程，可自動驗證遊戲任務在版本更新後是否仍可被 AI 代理完成，並定位特定步驟的迴歸問題。

5. **互動式遊戲教學與新手引導**：基於多層次指令資料，可開發能根據玩家當前狀態即時生成「下一步操作提示」「階段目標說明」或「整體策略建議」的 AI 教練系統。

### 實作前置條件

**資料需求**
- 取得 GameHorizon-Data 的使用授權，包含 21 款 AAA 遊戲共 5,000 小時的錄影、玩家操作軌跡與多層次指令。
- 確認目標遊戲具備可重現的執行環境（遊戲授權、存檔、版本鎖定），以便進行 online track 的環境重置與 stepwise 驗證。
- 若使用自有資料，需準備原始遊戲影片、動作日誌（keystroke / mouse movement）以及對應的語言指令或任務描述。

**運算需求**
- **離線評估**：中等規模 GPU（如 A100 / H100）用於執行 47 個等級模型的推論與百萬次 API 呼叫；大量儲存空間用於存放高解析度遊戲影片與特徵快取。
- **線上評估**：需可穩定執行遊戲實例的運算叢集，支援環境重置、狀態截圖與動作注入；建議搭配容器化或虛擬化方案以確保可重現性。
- **資料處理**：GameHorizon-Annotator 的 bottom-up 抽象流程需要影片解析、動作聚類與語言模型批次生成，建議具備分散式處理能力。

**技能需求**
- 熟悉多模態模型（VLM / VLA）的推論與評估流程。
- 具備遊戲引擎、API 或模擬環境的整合經驗（如讀取畫面、注入鍵鼠事件）。
- 能設計評估指標與診斷任務，並理解離線準確率與線上成功率之間的關聯。
- 具備資料工程能力，能處理時間對齊的影片—動作—語言三元組。

### 實作步驟建議

1. **環境建置與資料準備**
   - 下載並驗證 GameHorizon-Data 的完整性，建立影片、動作軌跡與多層次指令的索引。
   - 針對目標遊戲建立可重現的執行環境，包含固定遊戲版本、存檔與設定檔。

2. **執行多層次指令生成**
   - 使用 GameHorizon-Annotator 對原始遊戲軌跡進行 bottom-up 抽象：先產生短期操作指令，再聚類為中期目標，最後歸納為長期策略。
   - 人工抽樣驗證自動生成指令的品質，必要時針對特定遊戲類型調整 prompt 與聚類閾值。

3. **建立離線評估管線**
   - 在 GameHorizon-Bench 的 offline track 上執行三類主任務：single-horizon action、multi-horizon instruction decomposition、cross-horizon consistency。
   - 加入診斷變體任務，細粒度定位模型在視覺理解、目標規劃或動作映射上的弱點。

4. **建立線上評估管線**
   - 設計 order-dependent causal tasks 與 order-flexible thematic tasks。
   - 實作環境重置機制，讓模型從長期任務的任意步驟重新開始，以 stepwise 方式驗證並定位失敗步驟。

5. **大規模模型評測與比較**
   - 對目標模型（VLM、UMM、GUI agent、專用遊戲代理）執行超過百萬次推論，記錄各任務與各遊戲類型的表現。
   - 比較離線分數與線上成功率的相關性，驗證離線評估是否為實際遊玩能力的有效代理指標。

6. **迭代優化與產品整合**
   - 根據診斷結果，針對模型弱點進行資料增強、微調或架構調整。
   - 將評估管線整合至開發流程，作為模型發布前的標準化閘道。

### 潛在風險與注意事項

1. **遊戲授權與版權風險**：公開釋出或商業使用遊戲畫面與操作資料時，需確認已取得遊戲發行商的授權，或僅使用允許學術研究的資料子集。建議與法務團隊確認授權範圍。

2. **線上評估的高變異性**：online track 的結果易受遊戲環境、代理框架與隨機因素影響。應透過環境重置、多次獨立 rollout 與標準化 harness 來降低變異，並以離線評估作為初步篩選。

3. **動作空間與遊戲引擎差異**：不同遊戲的輸入方式（鍵盤、滑鼠、手把）與觀測空間差異極大。整合時需為每款遊戲設計統一的動作抽象層，避免直接將某款遊戲的動作格式套用至其他遊戲。

4. **過度擬合離線指標**：模型可能在 GameHorizon-Bench 的標準化問題上取得高分，卻在實際長期遊玩中失敗。建議同時進行 offline 與 online 評估，並分析兩者分數的相關性，而非僅依賴單一指標。

5. **資料隱私與玩家行為**：若使用真人玩家錄影，需去除或匿名化帳號、聊天紀錄等敏感資訊，並遵守資料保護法規。

### 與其他技術的整合建議

1. **與現有 VLM / VLA 框架整合**：可將 GameHorizon-Data 作為微調資料，搭配 LLaVA、Qwen-VL、GPT-4V、Gemini 或 RT-X 等模型進行訓練；GameHorizon-Bench 則可作為這些模型的標準化評測工具。

2. **與遊戲引擎及模擬環境整合**：透過 Unreal Engine、Unity、Minecraft API 或專用遊戲模組，將 GameHorizon-Bench 的 online track 部署為可重現的評估環境，並支援畫面擷取與動作注入。

3. **與 MLOps 平台整合**：將離線與線上評估結果接入 Weights & Biases、MLflow 或自研實驗追蹤系統，持續監控模型在不同遊戲類型與時間尺度上的表現變化。

4. **與強化學習（RL）管線整合**：利用 GameHorizon-Data 的專家軌跡進行模仿學習或離線 RL 的初始策略學習，再以 GameHorizon-Bench 的 stepwise online testing 作為獎勵塑形與策略驗證的依據。

5. **與雲端遊戲串流平台整合**：透過雲端遊戲服務取得穩定的遊戲執行環境，降低本地硬體與授權管理的複雜度，並支援大規模平行評測。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先從圖 1 的「指令金字塔」與「多時間尺度」概念入手，理解短期操作、中期目標與長期策略的區別，再瀏覽 GameHorizon-Data 的資料結構與 GameHorizon-Bench 的離線／線上評估流程，無需一開始深入模型架構細節。

**給 AI 工程師**：請重點閱讀 GameHorizon-Annotator 的自動化標註流程、GameHorizon-Bench 的 offline track 題目設計與 online track 的環境重置機制，並關注作者如何透過標準化動作與指令實現跨模型、跨遊戲的可比較評估，這對實際建置評測管線最有幫助。

**給研究人員**：建議深入分析三類主任務與診斷變體的設計邏輯，特別是 cross-horizon consistency 如何檢驗模型對視覺、語言與動作之間的對齊能力，以及離線分數與線上成功率的相關性分析，這些都是可延伸的研究方向。

**給產品經理**：請聚焦於適用場景與商業化限制，例如 GameHorizon Suite 可用於遊戲 AI 選型、自動化 QA 與新手教學，但需評估遊戲授權成本、運算資源投入，以及離線指標與實際使用者體驗之間可能存在的落差。
