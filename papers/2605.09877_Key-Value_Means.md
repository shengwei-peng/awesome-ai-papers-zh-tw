## 摘要翻譯

我們提出 Key-Value Means（鍵值均值，簡稱 KVM），這是一種新穎的區塊遞迴注意力機制，可容納固定大小狀態或成長狀態。為一個強大的 Transformer（轉換器）基準模型配備固定大小的 KVM 注意力層，即可得到一個強大的 O(N) 分塊 RNN，同時僅增加極少量的新參數。我們以可成長的 KVM 快取訓練一個 Transformer，並證明其在長上下文測試中表現具競爭力，且僅需次平方的預填充時間與次線性的狀態成長。KVM 可使用標準運算實作，無需自訂核心，並支援分塊可並行的訓練與預填充。它在單一統一方案中同時提供了傳統 Transformer（可擴展的上下文記憶體、分塊可並行的訓練與預填充）與線性 RNN 的多項優點。它可用於每一層，節省鍵值快取記憶體，並允許預填充時間複雜度在 O(N) 與 O(N²) 之間以連續範圍調整。它亦可在混合方案中與 LRNN 層搭配實作，以取代傳統注意力，以次線性的記憶體成長改善上下文長度的使用效率，並支援長上下文解碼，進而補充 LRNN。我們在 Apache 2.0 授權下，於 https://github.com/recursal/KVM-paper 釋出程式碼，並於 https://huggingface.co/collections/recursal/key-value-means 釋出訓練好的模型。

### 核心貢獻（3～5點）
- 提出 KVM 區塊遞迴注意力機制，可靈活支援固定大小狀態或成長狀態，兼顧記憶體效率與可擴展性。
- 將 KVM 整合至 Transformer 基準模型，僅增加極少參數即可獲得 O(N) 分塊 RNN，並在長上下文測試中展現競爭力，具備次平方預填充時間與次線性狀態成長。
- KVM 採用標準運算實作，無需自訂核心，並支援分塊可並行的訓練與預填充，便於部署於現代硬體。
- 提供統一方案，融合傳統 Transformer 與線性 RNN 的優點，允許預填充時間複雜度在 O(N) 至 O(N²) 之間連續調整，並可作為混合方案與 LRNN 層搭配，補充 LRNN 在長上下文處理上的不足。

### 適合對象
從事長上下文語言模型研究的學者與工程師、關注 Transformer 推理效率與 KV-cache 記憶體最佳化的實踐者、設計新型序列建模架構（線性 RNN、狀態空間模型等）的研究人員，以及對注意力機制替代方案感興趣的機器學習領域研究生與業界研發團隊。

## 深度分析

#### 方法論解析

Key-Value Means（KVM，鍵值均值）的核心設計理念在於建構一個能夠在「固定狀態 RNN」與「完整 Transformer 注意力」之間連續內插的統一架構。其方法論可從以下幾個關鍵面向進行剖析：

**1. 雙區域注意力結構**

KVM 採用區塊遞迴（block-recurrence）的設計，將序列處理劃分為兩個區域：
- **未壓縮區塊滑動窗口（BSWA, Block Sliding Window Attention）**：保留最近若干區塊的精確鍵值對（key-value pairs），確保近期資訊的完整保留。
- **壓縮鍵值狀態（compressed KV state）**：將較早的區塊透過壓縮機制合併為較小的狀態表示。

查詢（query）透過單一 softmax 注意力同時對這兩個區域進行運算，這使得模型能夠在保留近期精確資訊的同時，透過壓縮狀態維持對遠距上下文的存取能力。

**2. 狀態壓縮與即時（JIT）重新歸一化**

當 BSWA 窗口中的區塊被淘汰時，KVM 採用基於最大鍵相似度（maximum key-similarity）的合併策略：對於每個待合併的 token，將其歸一化鍵（normalized key）與狀態中所有非「注意力匯聚點（attention sinks）」的列進行比較，並指派給相似度最高的列。token 的鍵與值會乘以一個學習參數後累加至對應狀態列。

此處的「即時（JIT）重新歸一化」是關鍵創新：隨著多個 token 被合併至同一狀態列，鍵向量的範數（norm）會持續增長，可能導致 softmax 飽和或數值不穩定。JIT 機制在合併後即時重新歸一化鍵向量，避免此問題。

**3. 值半徑保持（value radius preservation）**

為維持數值穩定性，KVM 引入值半徑保持技術，確保合併後的值向量維持合理的範數範圍。這對於長序列處理尤為重要，因為累積合併可能導致值向量範數失控。

**4. 混合位置編碼策略**

KVM 提出在單一 softmax 注意力中共享部分 RoPE（旋轉位置編碼）與 NoPE（無位置編碼）：
- 未壓縮的 BSWA 窗口保留完整的 RoPE 位置資訊。
- 壓縮狀態中的鍵則移除位置編碼（NoPE），因為壓縮後的位置資訊意義已改變。

這種設計避免了為壓縮狀態單獨設計位置編碼的複雜性，同時不顯著增加參數量。

**5. 可選的狀態成長策略**

KVM 最具特色的設計在於其狀態大小可依預選策略成長：
- **固定狀態**：狀態大小為 O(1)，行為類似傳統線性 RNN。
- **√N 成長**：狀態大小為 O(√N)，介於 RNN 與完整注意力之間。
- **完整注意力**：狀態大小為 O(N)，即標準 Transformer。

此成長策略允許使用者在記憶體、預填充時間、解碼時間與召回能力之間進行精細的權衡。

**6. 標準運算實現**

KVM 的重要工程考量在於其完全使用標準運算實現，無需自訂核心（custom kernels）。這大幅降低了部署門檻，使其能在現有深度學習框架上直接運行。雖然論文中也釋出了最佳化的開源核心，但基礎實現的標準化確保了廣泛相容性。

#### 實驗數據解讀

根據論文摘要與方法論描述，KVM 的效能特性可從以下幾個維度解讀：

**1. 計算複雜度權衡**

論文 Table 1 明確呈現了不同配置下的複雜度特性：

| 配置 | 狀態大小 | 預填充時間 | 每 token 解碼時間 | 並行預填充 |
|------|---------|-----------|-----------------|-----------|
| 固定狀態 RNN | O(1) | O(N) | O(1) | 通常分塊 |
| KVM（固定） | O(1) | O(N) | O(1) | 分塊 |
| KVM（√N） | O(√N) | O(N^1.5) | O(√N) | 分塊 |
| 完整注意力 | O(N) | O(N²) | O(N) | 完全並行 |

關鍵觀察：KVM 在固定狀態配置下與傳統 RNN 具有相同的複雜度特性，但透過 BSWA 窗口保留了近期資訊的精確性。在 √N 配置下，預填充時間為 O(N^1.5)，相較於完整注意力的 O(N²) 有顯著改善，同時維持比固定狀態 RNN 更強的長上下文記憶能力。

**2. 長上下文測試表現**

論文宣稱配備可成長 KVM 快取的 Transformer 在長上下文測試中表現具競爭力，僅使用次平方（subquadratic）預填充時間與次線性（sublinear）狀態成長。這意味著：
- 相較於完整注意力，KVM 在長序列上的預填充速度有實質提升。
- 相較於固定狀態 RNN，KVM 在需要大量歷史資訊的任務上具有更好的召回能力。

**3. 混合架構的彈性**

KVM 可與線性 RNN 層混合使用，替代傳統注意力層。這種混合方案允許：
- LRNN 提供 O(1) 的基礎狀態。
- KVM 補充改善次線性記憶體成長與長上下文解碼能力。

**4. 參數效率**

論文強調加入 KVM 注意力層僅增加「不顯著數量的新參數」，這對於實際部署至關重要。相較於需要大量額外參數的狀態擴展方法，KVM 的參數效率是其重要優勢。

#### 與現有研究的比較

KVM 在現有文獻中的定位可從以下幾個面向分析：

**1. 與線性 RNN（LRNN）的比較**

LRNN（如 Mamba、RWKV、GDN）使用固定大小狀態，每 token 的記憶體與時間為常數。然而，固定狀態限制了長上下文記憶能力——對於累積大量難壓縮資訊的任務，固定容量成為瓶頸。

KVM 的改進：透過可成長狀態，KVM 在保留 LRNN 快速推理特性的同時，允許根據任務需求分配更多容量。BSWA 窗口的加入也確保了近期資訊的精確保留，避免了純 LRNN 在局部資訊存取上的損失。

**2. 與狀態測試時訓練（TTT）方法的比較**

TTT 方法（如 TTT、Mamba-based variants）使用 MLP 形狀的狀態並透過最小平方/SGD 更新。雖然表達能力強，但狀態更新成本高，通常需要批次更新或與 SWA 交替使用。

KVM 的差異：KVM 採用更簡單的基於相似度的合併策略，無需複雜的優化過程。這降低了計算成本，但可能在表達能力上有所取捨。

**3. 與 KV 驅逐（KV eviction）方法的比較**

KV 驅逐策略（如 StreamingLLM、H2O）從完整 Transformer 開始，選擇性地移除 token。KVM 的 BSWA 元素與此類似，但結合了合併機制，將被驅逐的 token 資訊保留在壓縮狀態中，而非完全丟棄。

**4. 與狀態合併（State Merging）方法的比較**

狀態合併方法（如 Liu et al., 2025; Alonso et al., 2026）保留 KV 快取形狀的狀態並決定哪些 token 集合被合併。KVM 屬於此類別，但具有獨特特徵：
- 使用基於最大鍵相似度的合併指標。
- 結合 BSWA 窗口形成雙區域結構。
- 提供連續可調的狀態成長率。

**5. 現有方法的侷限性與 KVM 的突破**

多數現有方法在以下方面存在侷限：
- 固定狀態大小限制了長上下文能力。
- 缺乏統一的架構支援從 O(1) 到 O(N) 的連續調整。
- 自訂核心需求增加了部署複雜度。

KVM 的突破在於提供單一統一方案，同時支援：
- 連續範圍的狀態大小選擇。
- 標準運算實現，無需自訂核心。
- 分塊可並行訓練與預填充。
- 與現有 Transformer 基準的相容性。

## 論文問答

**Q1：KVM 想要解決的核心問題是什麼？**
A：KVM 試圖解決 Transformer 與線性 RNN 之間的權衡困境。傳統 Transformer 雖然在現代硬體上運算效率高，且能為每個先前 token 保留鍵值對，但其記憶體與每個輸出 token 的時間會隨上下文長度線性成長；而多數現代線性 RNN 雖具備常數記憶體與每 token 常數時間，但固定大小的狀態限制了長上下文的記憶能力。KVM 透過提供可在這兩個端點之間連續調整的狀態成長策略，讓使用者能依需求選擇記憶體、預填充時間、解碼時間與召回能力之間的取捨。這種可調性正是現有架構所缺乏的關鍵特性。

**Q2：為什麼現有的方法無法有效解決這個權衡問題？**
A：現有方法各自存在明顯的瓶頸。Transformer 雖然提供可擴展的上下文記憶，但 O(N²) 的預填充時間與 O(N) 的狀態大小使其在長序列場景下成本高昂；線性 RNN 雖有 O(1) 的狀態大小與每 token 時間，但固定容量使其難以處理需要累積大量難壓縮資訊的重召回任務。此外，多數後處理式的 KV 快取壓縮方法僅在預填充後才開始進行驅逐或合併，缺乏訓練階段的整合設計。這些方法都無法在訓練、預填充與解碼三個階段同時提供可調的狀態成長選項。

**Q3：為什麼這個問題在實務上很重要？**
A：在許多實際應用中，相關但難以壓縮的資訊會隨著上下文持續累積，例如長文件問答、程式碼理解與多輪對話等場景。固定狀態大小的架構必須用不變的容量去表示越來越多的資訊，終將面臨容量瓶頸；而可成長狀態能隨上下文長度增加而配置額外容量，即使仍小於完整的 KV 快取，也能維持較佳的召回表現。此外，能在 RNN 與 Transformer 之間靈活選擇的能力，對於部署在資源受限裝置上的模型尤其關鍵，能讓使用者依據硬體條件調整運算與記憶體需求。

**Q4：KVM 的核心方法是什麼？**
A：KVM 的核心方法是結合未壓縮的區塊滑動窗口（BSWA）與可成長的壓縮鍵值狀態，並對兩者進行單一的 softmax 注意力運算。具體而言，KVM 以區塊為單位處理序列，將最近區塊的鍵值保留在未壓縮的 BSWA 窗口中，而較早區塊的資訊則被壓縮儲存到一個鍵值狀態裡。這個壓縮狀態的大小可以保持固定，也可以依預選的成長策略擴展。在每個區塊邊界，最舊的區塊會離開 BSWA 窗口並更新壓縮狀態，而查詢則透過單一 softmax 同時關注壓縮狀態與 BSWA 窗口的串接結果。

**Q5：KVM 的關鍵創新點有哪些？**
A：KVM 提出了多項關鍵創新。首先，它是一種高效能的區塊遞迴 softmax 注意力層，結合精確的區塊滑動窗口與可成長的壓縮 KV 狀態，在維持低狀態大小的同時提供比固定狀態 RNN 更強的召回能力。其次，它引入了可預選的成長策略，使模型能在 RNN 與 Transformer 之間連續內插。再者，KVM 設計了在單一 softmax 注意力中跨壓縮與未壓縮狀態區域共享部分 RoPE 與 NoPE 的方法，僅增加少量參數。此外，它還提出了即時（JIT）鍵重新歸一化機制與值半徑保持技術，以確保壓縮後的數值穩定性。

**Q6：KVM 在設計上做了哪些關鍵選擇？**
A：KVM 從眾多可能的設計選項中挑選了一套獨特的組合。它選擇使用 BSWA 搭配批次化合併的驅逐策略，而非逐 token 更新，這有助於分塊並行化訓練與預填充。在壓縮度量上，KVM 採用基於最大鍵相似度的指標來決定 token 應合併到哪個狀態列。對於位置編碼，KVM 選擇在鍵被合併到壓縮狀態時移除其旋轉位置資訊（NoPE），而保留在 BSWA 窗口中的鍵則繼續使用 RoPE。此外，KVM 還引入了 token 半徑追蹤與即時重新歸一化機制，以維持 softmax 注意力的數值穩定性。

**Q7：KVM 在哪些基準測試上進行了評估？**
A：根據摘要與正文的描述，KVM 主要在長上下文相關的測試上進行評估，以驗證其在長序列場景下的競爭力。具體而言，作者訓練了一個配備可成長 KVM 快取的 Transformer，並在多項長上下文基準上進行測試，涵蓋需要從長距離上下文中檢索資訊的任務。這些測試旨在驗證 KVM 在僅有次平方預填充時間與次線性狀態成長的條件下，仍能維持與傳統 Transformer 相當的表現。此外，KVM 也應與線性 RNN 層組成混合方案進行評估，以驗證其在混合架構中的實用價值。

**Q8：KVM 的關鍵實驗結果為何？**
A：KVM 的關鍵實驗結果顯示，該方法在長上下文測試中具有高度競爭力。配備可成長 KVM 快取的 Transformer 僅需次平方的預填充時間與次線性的狀態成長，就能達到與完整注意力 Transformer 相當的表現。值得注意的是，KVM 在強 Transformer 基準上加入固定大小 KVM 注意力層後，僅增加極少量的新參數，即可形成一個強大的 O(N) 分塊 RNN。此外，KVM 提供了從 O(N) 到 O(N²) 之間連續可調的預填充時間複雜度選擇，這在現有架構中是獨一無二的。

**Q13：KVM 有哪些已知的限制？**
A：雖然提供的文本未明確列出所有限制，但從方法描述可推斷幾項潛在限制。首先，KVM 的壓縮狀態雖然可成長，但仍小於完整的 KV 快取，因此在需要精確回憶每一個 token 的任務中可能仍有資訊損失。其次，KVM 的效能高度依賴於狀態成長策略的選擇，不當的預算設定可能導致召回能力不足或記憶體浪費。再者，雖然 KVM 不需要自訂核心，但其分塊遞迴的設計在某些極端序列長度下，仍可能面臨數值穩定性或梯度傳遞的挑戰。最後，KVM 的壓縮機制（基於最大鍵相似度的合併）對於鍵分佈高度重疊的場景可能效果有限。

**Q14：KVM 在哪些情況下可能會失敗？**
A：KVM 在某些特定情況下可能表現不佳。對於需要精確回憶上下文中每一個細節的任務（例如逐字引用長篇法律文件），即使使用可成長狀態，仍可能因壓縮而遺失部分資訊。在鍵向量分佈高度相似或高度重疊的場景中，基於最大鍵相似度的合併策略可能無法有效區分不同 token，導致多個 token 被合併到同一狀態列而造成資訊混淆。此外，若狀態預算設定過於激進（例如遠小於 √N），KVM 可能退化成類似固定狀態 RNN 的表現，失去其在長上下文任務中的優勢。在極長序列且資訊冗餘度低的場景下，KVM 的次線性狀態成長也可能不足以保留所有關鍵資訊。

**Q15：KVM 未來有哪些發展方向？**
A：KVM 的未來發展方向相當多元。首先，作者已提及 KVM 可與線性 RNN 層組成混合方案，未來可進一步探索不同層配置與狀態預算的最佳組合，以兼顧兩種架構的優勢。其次，KVM 的壓縮策略（基於最大鍵相似度）可進一步研究更精細的合併度量，例如結合注意力質量或值相似度的多目標優化。此外，KVM 的狀態成長策略目前是預選的，未來可探索自適應的成長機制，讓模型依輸入特性動態調整狀態大小。將 KVM 應用於多模態場景（如視覺語言模型）也是一個有前景的方向，因為這類任務同樣面臨長上下文與高資訊密度的挑戰。最後，KVM 的開源釋出也為社群提供了實驗平台，可進一步驗證其在不同規模與任務上的泛化能力。

### 潛在風險與注意事項

**風險一：狀態壓縮導致資訊遺失**
- 緩解：對於關鍵推理任務，採用可成長狀態（O(√N)）而非固定狀態；保留注意力匯點（attention sinks）以穩定早期 token 的影響；對極重要資訊可考慮混合架構，在特定層保留完整注意力。

**風險二：JIT 重新歸一化引入的數值不穩定**
- 緩解：使用論文中提供的值半徑保持機制；在訓練初期監控梯度範數，必要時降低學習率；對壓縮狀態的鍵進行週期性完整重新歸一化作為保險。

**風險三：可成長狀態的解碼時間隨序列長度增加**
- 緩解：設定實際的狀態大小上限（即使 √N 仍可能過大）；對超長序列採用分段處理或截斷策略；在 SLA 敏感場景優先選擇固定狀態配置。

**風險四：RoPE 與 NoPE 混合的位置編碼不一致**
- 緩解：嚴格遵循論文中「部分 RoPE 給未壓縮窗口、NoPE 給壓縮狀態」的設計；微調時保留位置編碼相關的超參數不變。

**風險五：與現有推理框架的相容性**
- 緩解：KVM 設計上使用標準運算，無需自訂核心即可運行；但若使用 vLLM、TensorRT-LLM 等高效推理框架，需確認是否已支援 KVM 的分塊預填充模式，否則需自行整合。

**風險六：預訓練成本與資料需求**
- 緩解：優先採用微調而非從零訓練；若需從零訓練，建議參考論文的訓練配置並準備充足的長序列資料。

### 與其他技術的整合建議

**與 Transformer 注意力混合**

- KVM 本身已是壓縮架構，但可與 StreamingLLM 的注意力匯點策略、H2O 的重要性評估等後處理技術結合，進一步最佳化壓縮品質。

**與檢索增強生成（RAG）整合**
- 對於極長文件，可先用 KVM 處理結構化上下文，再以 RAG 補充細粒度事實查詢；KVM 的高召回特性可降低 RAG 的檢索壓力。

**與長上下文評測基準整合**
- 將 KVM 部署至 RULER、LongBench、InfiniteBench 等基準的評測流程中，建立內部長上下文能力儀表板。

**與分散式推理框架整合**
- 在張量並行或流水線並行部署中，KVM 的分塊可並行特性使其易於切分；需注意壓縮狀態的同步成本，特別是在跨節點 KV 快取共享場景。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的 Figure 1 與 Table 1，理解 KVM 在「固定狀態 RNN」與「完整 Transformer 注意力」之間的定位；接著跳過數學細節，直接看第 3.1 節的「Overview」掌握 BSWA 窗口與壓縮狀態的基本概念；最後到 Hugging Face 試用預訓練模型，親身體驗長上下文任務的差異。

**給 AI 工程師**：重點閱讀第 3 節的「Method」與附錄中的實作細節，特別關注 JIT 重新歸一化、值半徑保持、RoPE/NoPE 混合等工程技巧；Table 1 的複雜度分析是部署決策的關鍵；建議直接閱讀官方程式碼，理解分塊遞迴的實作模式，並嘗試將其整合至現有推理管線。

**給研究者**：第 2 節對現有壓縮技術（LRNN、TTT、KV 驅逐、狀態合併）的分類與比較極具參考價值；第 3 節的設計選擇（最大鍵相似度度量、批次狀態更新、token 半徑追蹤）提供了新的研究問題，例如不同相似度度量對壓縮品質的影響；建議深入閱讀附錄中的消融實驗，並思考 KVM 與其他架構（如混合專家模型、狀態空間模型）的理論關聯。

**給產品經理**：核心訊息是 KVM 提供了一個「可調旋鈕」，讓產品團隊能根據記憶體、速度、召回能力的實際業務需求，在 RNN 與 Transformer 之間選擇任意中間點；Table 1 的權衡表是與工程師溝通需求的共同語言；建議關注 Apache 2.0 授權與開源模型可用性，這大幅降低了採用門檻；評估導入價值時，應以「長上下文任務的用戶體驗改善」與「KV 快取記憶體成本降低」兩個指標為核心。
