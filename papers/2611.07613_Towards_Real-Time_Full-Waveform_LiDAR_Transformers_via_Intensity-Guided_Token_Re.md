本文提出兩個相互獨立但目標互補的方法模組，共同解決全波形光達 Transformer (FWLT) 部署中的兩大瓶頸：推論效率與泛化能力。

**FWL-ToPM（強度引導式 Token 剪枝與合併機制）**

FWL-ToPM 的核心設計理念在於利用 FWL 資料的物理稀疏性 (physical sparsity)。傳統光達僅記錄每個雷射脈衝的峰值強度，而 FWL 則以直方圖形式儲存完整的時間強度波形 (temporal intensity waveform)，其資料格式為 (u × v × t)，其中 u、v 為方位角與仰角，t 為飛行時間 (Time-of-Flight, ToF) 的時間軸。這種資料呈現高度稀疏的物理結構——絕大多數像素的強度值接近零，僅有少數位置對應物體反射的峰值。

FWL-ToPM 採用兩階段處理：

1. **Token 剪枝 (Token Pruning)**：根據強度分布 (intensity distributions) 識別並移除低強度背景 Token。這些背景區域不包含物體相關的反射資訊，移除後可大幅降低計算量。值得注意的是，本文發現即使剪枝高達 70% 的 Token 仍能持續提升準確率，這與影像 Transformer 中激進剪枝會破壞訓練穩定性的經驗形成鮮明對比。

2. **Token 合併 (Token Merging)**：對剪枝後保留的 Token 進行合併，進一步減少序列長度，同時保留關鍵波形內容。

此設計與現有的影像/影片 Token 削減方法（如 DynamicViT、ToMe 等）有本質差異。後者假設資訊內容在二維空間中均勻分布，因此會無差別地丟棄稀疏的高強度 Token——而這些 Token 恰恰是 FWL 資料中編碼物體反射的關鍵資訊。FWL-ToPM 透過將剪枝準則從「空間分布均勻性」轉變為「強度分布稀疏性」，實現了針對 FWL 物理結構的專用機制。

**FWLAug（物理感知資料增強框架）**

FWLAug 被設計為一種正則化方法 (regularization method)，其核心約束在於兩個物理不變量：

1. **ToF 波形結構保持**：每條射線的時間強度波形必須被保留，因為波形形狀本身即為反射特徵的編碼（例如多路徑回波、弱訊號等）。
2. **視錐幾何保持 (Frustum Geometry Preservation)**：資料的空間幾何結構（方位角、仰角構成的視錐）不可被扭曲。

標準的影像增強（如旋轉、裁切、色彩抖動）與點雲增強（如隨機平移、旋轉、點丟棄）均會破壞上述物理約束。例如，對影像的空間翻轉會改變波形與空間位置的對應關係；對點雲的隨機旋轉則違反了 FWL 感測器的固定視錐幾何。FWLAug 透過在保持這些物理約束的前提下擴展訓練多樣性，緩解了少數類別（如玻璃、水）樣本不足導致的過擬合問題。

3. **礦區、港口等工業場域自主載具**：粉塵、雨水、霧氣瀰漫的工業環境中，FWL 的多路徑回波資訊能區分真實障礙物與懸浮微粒造成的偽點，提升礦車、AGV 的安全性。

4. **透明障礙物偵測（玻璃門、落地窗）**：商辦大樓、購物中心內的自動門機器人或清潔機器人常因玻璃牆面產生鬼影，本方法可作為透明障礙物偵測模組。

5. **邊緣運算裝置上的即時感知**：53.2 FPS 的吞吐量已符合多數機器人控制迴路（10–30 Hz）需求，可部署於車載邊緣運算平台（如 NVIDIA Orin、Qualcomm Ride）。

### 潛在風險與注意事項

**風險一：過度剪枝導致關鍵資訊遺失**
- 雖然論文顯示 70% 剪枝仍可提升準確度，但不同場域的稀疏度差異極大
- **緩解**：建立 per-scene 剪枝比例搜尋機制；保留「安全閾值」確保高強度 token 不被誤刪；定期以人類標註驗證

**風險二：FWLAug 違反物理約束**
- 若增強操作不當（如錯誤旋轉視錐、扭曲 ToF 時間軸），會產生物理上不可能的波形
- **緩解**：實作單元測試驗證增強後波形的物理一致性；保留原始資料作為 ground truth 對照

**風險三：OOD 場域泛化失效**
- 訓練資料場域有限，部署到新地理環境（不同建築材質、植被、氣候）可能失效
- **緩解**：建立持續學習（continual learning）流程；定期以 OOD 測試集評估；保留 fallback 至傳統 LiDAR 處理

**風險四：硬體成本與維護**
- FWL 設備成本高於傳統 LiDAR，且波形資料儲存需求大
- **緩解**：評估是否僅在關鍵節點（如高速公路入口、隧道）部署 FWL；採用資料壓縮與分層儲存

**風險五：標註成本高昂**
- 鬼影標註需要專業知識，且類別不平衡（玻璃、水等少數類別樣本稀少）
- **緩解**：結合 FWLAug 與主動學習（active learning）優先標註高不確定性樣本

**風險六：與現有感知堆疊的相容性**
- FWL 資料格式與傳統點雲不同，整合至現有 pipeline 可能需要中介層
- **緩解**：設計雙輸出介面（FWL 波形 + 衍生點雲），保留向下相容性

### 與其他技術的整合建議

**與相機感知融合**
- FWL 鬼影偵測結果可作為相機物件偵測的先驗，過濾相機誤判
- 建議採用 late fusion 架構，於決策層整合 FWL 與相機結果，避免早期融合帶來的維度災難

**與傳統 LiDAR 點雲處理整合**
- FWL 可作為「前置濾波器」，先去除鬼影再交給傳統點雲處理管線（如 PointPillars、CenterPoint）
- 介面設計：FWL 模組輸出 (x, y, z, confidence) 點雲，與傳統 LiDAR 點雲格式一致

**與 SLAM 系統整合**
- 將 FWL 鬼影偵測結果回饋至 SLAM 的迴路閉合（loop closure）與因子圖最佳化
- 鬼影點不應進入地圖，僅作為暫時性觀測

**與高精地圖（HD Map）整合**
- FWL 透明障礙物偵測結果可與 HD Map 中的玻璃帷幕標註交叉驗證
- 用於偵測臨時障礙物（如施工圍籬、臨時玻璃牆）

**與車聯網（V2X）整合**
- 多車 FWL 感知結果可透過 V2X 共享，提升對稀疏區域的覆蓋率
- 需注意頻寬限制，FWL 原始波形不適合傳輸，建議傳輸衍生特徵或鬼影偵測結果

**與邊緣運算框架整合**
- TensorRT / ONNX Runtime 已支援 Transformer 加速
- 建議採用 NVIDIA Triton Inference Server 進行模型版本管理與 A/B 測試
