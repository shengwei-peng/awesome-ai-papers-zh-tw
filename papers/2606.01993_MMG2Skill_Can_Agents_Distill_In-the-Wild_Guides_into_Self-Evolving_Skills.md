## 摘要翻譯

網路上豐富的程序性知識（procedural knowledge）極具潛力，可協助智能體解決長期任務（long-horizon tasks）。然而，這類知識通常具備多模態（multimodal）、異質性（heterogeneous）與雜訊（noisy）等特性，且隱含假設執行者為人類，使其難以直接用作智能體所需的技能。為了彌合面向人類的指南（human-oriented guides）與智能體可執行技能（agent-executable skills）之間的落差，我們將此問題形式化為指南轉技能學習（guide-to-skill learning）：將真實環境指南（in-the-wild guides）轉換為可執行技能（executable skills），並根據智能體可觀察軌跡（observable trajectories）持續改進它們。為了評估現有智能體在此任務上的能力，我們提出了 MMG2Skill-Bench，這是首個針對此問題所設計的基準測試（benchmark）。我們進一步提出 MMG2Skill，這是一個閉環框架（closed-loop framework），可將指南編譯為可編輯技能，在執行期間將這些技能作為固定視覺語言模型（VLM）智能體的決策條件，並根據軌跡層級（trajectory-level）的根本原因回饋修訂技能，且無需使用基準測試分數。橫跨 GUI 控制、開放式遊戲玩法與策略性卡牌遊戲，並使用六種 VLM 骨幹模型（VLM backbone），MMG2Skill 在每個模型-領域設定中始終優於原始基線智能體，在各骨幹模型間達到 +12.8 至 +25.3 百分點的宏觀平均（macro-average）增益。消融實驗（ablation studies）顯示，直接使用原始指南提示智能體可能降低效能，而結構化技能建構與軌跡驅動技能修訂（trajectory-driven skill revision）兩者對於觀察到的改善皆屬必要。在成功與否可推斷的任務（success-inferable tasks）上，基於分析器的提前停止機制進一步防止後期效能衰退，並在成功訊號經適當校準時節省 25%–53% 的嘗試次數。

### 核心貢獻（3～5點）
- 形式化「指南轉技能學習（guide-to-skill learning）」問題，將真實環境指南轉為可執行技能並透過可觀察軌跡持續演化。
- 提出首個針對此問題設計的基準測試 MMG2Skill-Bench。
- 設計閉環框架 MMG2Skill，結合技能提取、固定 VLM 智能體條件化執行與軌跡驅動技能修訂，且無需依賴基準測試分數。
- 跨 GUI 控制、開放式遊戲與策略卡牌三大領域及六種 VLM 骨幹模型驗證，相較基線達成 +12.8 至 +25.3 百分點的宏觀平均增益。
- 透過消融實驗證明結構化技能建構與軌跡驅動修訂的必要性，並於成功與否可推斷的任務中透過分析器提前停止節省 25%–53% 嘗試次數。

### 適合對象
從事視覺語言模型（VLM）智能體、長期任務規劃、自動化技能學習、GUI 自動化與開放式遊戲 AI 等領域的研究者與工程師，特別是關注如何將網路上異質性多模態知識轉化為智能體可執行程序性知識的讀者。

## 深度分析

#### 方法論解析

##### 問題形式化：指南轉技能學習（Guide-to-Skill Learning）
本文將核心問題形式化為「指南轉技能學習（guide-to-skill learning）」，旨在彌合面向人類的真實環境指南（in-the-wild guides）與智能體可執行技能（agent-executable skills）之間的根本落差。不同於傳統檢索增強生成（Retrieval-Augmented Generation, RAG）僅將指南視為上下文提示，此處的技能（skill）被定義為可執行、可編輯、可持續的程序性物件（procedural objects）。這些物件必須具備三項能力：判斷行為適用時機（when）、追蹤中間狀態以確認進度（which intermediate states）、以及偏離時提供恢復策略（how to recover）。因此，問題不僅是「讀取」程序性知識（procedural knowledge），而是將其錨定（anchor）在智能體的執行期狀態（runtime state）中，並透過可觀察軌跡（observable trajectories）持續演進。

##### MMG2Skill 閉環框架的三階段設計
MMG2Skill 作為一個閉環框架（closed-loop framework），其運作可拆解為三個緊密耦合的階段：

1. **技能提取（Skill Extraction）**：將多模態（multimodal）、異質性（heterogeneous）且帶有雜訊（noisy）的原始指南編譯為結構化的 `SKILL.md` 程序。此階段需過濾掉導航文字、人類專屬的先決假設（prerequisite assumptions），以及與當前任務無直接關聯的旁支程序（sibling procedures）。最終產出的是緊湊、可編輯（editable）的技能集合，而非原始指南的逐字副本。

2. **條件化執行（Conditioned Execution）**：在執行回合（rollout）期間，固定不變的視覺語言模型骨幹（VLM backbone）被條件化（conditioned）於當前技能集合。智能體根據當前觀測（observation）諮詢（consult）相關技能，進行下一步動作推理。此設計確保程序性知識在執行期間保持「可諮詢」與「可定位」（localize）的狀態，而非僅在提示階段出現一次。

3. **軌跡驅動技能修訂（Trajectory-Driven Skill Revision）**：這是框架最具區別性的設計。修訂信號完全來自軌跡層級的根本原因回饋（trajectory-level root-cause feedback），而非基準測試分數（benchmark scores）。這意味著在真實部署環境中，即使沒有外部評分器，框架仍能根據智能體自身可觀察的執行歷程，診斷技能與運行時狀態之間的接地差距（grounding gaps），並對 `SKILL.md` 進行針對性修正。此設計刻意將評估資訊邊界與部署資訊邊界對齊，避免方法論對隱藏標籤（hidden evaluation labels）的依賴。

##### 關鍵設計選擇與技術細節
- **固定 VLM 骨幹**：框架不微調（fine-tune）底層模型，而是透過外部技能記憶體來擴展智能體能力。這降低了計算成本，並使方法適用於黑箱 API 模型。
- **成功可推斷（Success-Inferable）限制**：主評估僅納入可從智能體可見軌跡或公開最終狀態推斷成敗的任務。這確保了軌跡驅動修訂與早期停止（early stopping）在部署時同樣可行。
- **分析器式早期停止（Analyzer-Based Early Stopping）**：由於修訂增益呈現非單調性（non-monotonic），框架引入基於分析器的停止機制，在偵測到後期性能衰退（late-stage regressions）時中斷嘗試，避免過度修訂造成的傷害。

#### 實驗數據解讀

##### MMG2Skill-Bench 的評估規模與協定
MMG2Skill-Bench 是首個針對指南轉技能學習設計的基準測試，涵蓋三大互動領域：桌面圖形使用者介面控制（GUI，基於 OSWorld）、開放式遊戲玩法（Game，基於 OpenHA Minecraft）以及策略卡牌（Strategy，基於 RLCard 的鬥地主與麻將）。總計包含 130 個成功可推斷（success-inferable）任務，每個任務配對來自公開網路的人類撰寫多模態指南。評估協定嚴格控制資料洩漏（leakage）：指南不含基準測試的黃金動作序列（gold action sequences）、隱藏標籤或環境特定軌跡，確保測量的是程序性接地（procedural grounding）而非檢索能力。

##### 主要性能增益與跨模型一致性
實驗橫跨六個 VLM 骨幹模型，結果顯示 MMG2Skill 在「每一個」模型–領域設定中均穩定勝過純基線（vanilla baseline）。宏觀平均（macro-average）增益達到 +12.8 至 +25.3 百分點（percentage points）。這種跨骨幹、跨領域的一致性極具意義：它不僅證明真實環境指南蘊含寶貴的程序性知識，更顯示該框架具備良好的模型無關性（model-agnostic），無論底層是較強或較弱的 VLM，結構化技能提取與軌跡修訂都能帶來顯著邊際效益。

##### 消融實驗：原始指南提示的負面效應
消融研究揭示了一個反直覺的現象：直接將原始指南作為提示（raw guide prompting）輸入智能體，反而可能損害性能。這驗證了本文的核心假設——「取得指南」與「使用指南」之間存在結構性鴻溝。原始指南包含人類導向的敘事、冗餘資訊與隱含前提，對必須精確對齊運行時狀態的 VLM 智能體而言，這些雜訊會造成干擾。相比之下，結構化技能建構（structured skill construction）提供了一個更安全的程序性先驗（procedural prior），而軌跡驅動修訂則進一步修復指南與運行時之間的接地差距。

##### 非單調修訂與早期停止（Early Stopping）的效益
數據顯示修訂增益並非單調遞增，後期可能出現性能衰退（regressions）。在成功信號經過適當校準（properly calibrated）的任務上，分析器式早期停止可節省 25% 至 53% 的嘗試次數。這項發現對實際部署至關重要：它意味著在資源受限或 API 呼叫成本敏感的場景中，智能體可以自主判斷何時停止「自我演化」，避免無謂的過度迭代。

#### 與現有研究的比較

##### 相較於上下文學習基準測試（In-Context Learning Benchmarks）
現有上下文學習研究（如 Dou et al., 2026）雖探討模型如何利用外部資訊，但多使用經過整理的文本（curated text），且未將真實環境多模態指南與環境接地的執行（environment-grounded execution）配對。MMG2Skill-Bench 的獨特之處在於，它要求智能體不僅「理解」指南，還必須在互動環境中將其轉化為可執行、可修訂的技能，並面對真實指南的異質性與雜訊。

##### 相較於技能發現與自我改進智能體（Skill Discovery & Self-Improving Agents）
現有技能基準與自我改進方法（Li et al., 2026; Wang et al., 2023; Zhao et al., 2024 等）通常依賴專家提供（expert-provided）、模型生成（model-generated）或智能體自身經驗發現（experience-discovered）的技能。這些方法缺乏系統性證據，證明公開的人類指南材料能否轉化為智能體可執行技能。MMG2Skill 填補了此空白，並進一步提出無需基準測試分數即可進行修訂的閉環機制，這在現有自我改進框架中較為罕見——多數方法仍隱含依賴外部獎勵或評分信號來引導改進。

##### 核心貢獻與現有局限
本文的核心貢獻在於建立了從「人類知識容器」（即網路指南）到「智能體執行單元」（即可編輯技能）的完整管道，並證明該管道在固定 VLM 下即可運作。然而，現有研究也存在可識別的局限：
- **任務範圍限制**：主評估排除如無限注德州撲克（No-Limit Hold’em）等涉及對手私人資訊（private information）的任務，因為其報酬無法僅從智能體可見軌跡推斷。這限制了框架在部分可觀測（partially observable）且對抗性情境的適用性。
- **指南相關性假設**：實驗中每個任務配對的是已預先篩選的任務相關指南子集（task-relevant subset），未深入探討從大規模語料庫中動態檢索與過濾的挑戰。
- **規模上限**：130 個任務雖橫跨三域，但相較於網路上數以百萬計的指南，仍屬中等規模，尚未驗證方法在極大規模語料下的可擴展性（scalability）。

#### 可重現性評估

##### 基準測試文件的完整性
從提供的文本脈絡觀察，MMG2Skill-Bench 的實驗協定具備相當高的文件完整度。作者詳細說明了任務選擇細節（附錄 C.2）、各領域指南來源與洩漏控制（附錄 C.1）、終止規則與超參數（附錄 B.3），以及軌跡推斷成功與否的殘餘誤差量化（附錄 E.5.1）。這種層級的細節記載，理論上有助於其他研究者重現評估環境與控制條件。

##### 開源釋出狀態與再現挑戰
儘管方法論與基準測試的內部邏輯描述詳盡，但提供的文本中**並未明確提及**原始碼、資料集或模型權重的公開釋出連結。在當前 AI 研究領域，可重現性（reproducibility）高度依賴於：
1. **基準測試任務與指南語料庫的公開取得**：若指南語料涉及版權或網頁爬蟲後處理細節未公開，再現將受限。
2. **SKILL.md 的編譯與修訂提示模板**：框架依賴結構化提取與根本原因分析，若提示工程（prompt engineering）細節未完整釋出，難以完全復現。
3. **VLM API 版本與溫度參數**：由於實驗涉及六個不同骨幹模型，其 API 行為的隨機性與版本漂移可能影響跨研究比較。

綜合而言，該研究在方法論層面具備可重現的潛力，但實際能否被社群複製，仍取決於作者後續是否釋出完整的實作程式碼與處理後資料。

#### 未來研究方向

##### 技能表示法的形式化升級
當前 MMG2Skill 使用 `SKILL.md` 作為技能載體，雖具備可讀性與可編輯性，但未來可探索更形式化的表示法，例如階層式有限狀態機（hierarchical finite-state machines）、時序邏輯（temporal logic）或規劃領域定義語言（Planning Domain Definition Language, PDDL）。形式化表示有助於引入自動驗證（automatic verification）與合成（synthesis），降低對自然語言修訂的依賴，並提升在安全性關鍵領域（如醫療或工業控制）的可靠性。

##### 動態指南檢索與衝突消解
目前框架假設已獲得任務相關的指南子集。未來研究可朝向「開放式指南轉技能學習」發展：智能體首先從整個網際網路或大型指南庫中檢索相關文件，再處理多份指南之間的衝突（conflicting advices）與冗餘。這需要結合資訊檢索（Information Retrieval, IR）與論證挖掘（argument mining）技術，以處理真實環境中異質性更高的知識來源。

##### 超越成功可推斷（Success-Inferable）任務的邊界擴展
主評估刻意限制在成功可推斷任務，但未來可探索如何將框架擴展至部分可觀測或長期延遲獎勵的環境，例如無限注德州撲克（No-Limit Hold’em）或需要人類回饋的開放式創作任務。潛在路徑包括引入貝葉斯信念更新（Bayesian belief updating）來推斷隱藏狀態，或結合強化學習（Reinforcement Learning, RL）的信用分配（credit assignment）機制，以處理軌跡中無法直接觀察的成敗信號。

##### 修訂動態的理論理解與人機協作
實驗觀察到修訂增益的非單調性（non-monotonicity），但其背後的理論機制尚不明朗。未來可從學習理論角度分析：技能空間的結構、回饋信號的雜訊程度，以及 VLM 的推理偏差如何交互作用導致後期衰退。此外，軌跡驅動修訂可與人機協作（human-in-the-loop）結合，允許人類專家在關鍵節點審核或修正 `SKILL.md`，形成「人類專家–智能體軌跡–自動修訂」的三方閉環，進一步提升技能品質與安全性。

## 論文問答

**Q1：MMG2Skill 旨在解決什麼核心問題？為何這個問題對長期任務的智能體至關重要？**

A：MMG2Skill 旨在解決「指南轉技能學習」的核心問題，也就是如何將網路上豐富但雜亂的真實環境指南，轉換為智能體可執行且可持續改進的技能。這些面向人類的指南雖然蘊含大量程序性知識，卻具有多模態、異質性與雜訊等特性，並預設由人類執行，導致智能體難以直接將其用於長期任務。因此，研究的核心挑戰在於建立一座橋樑，使這些原始資料能夠被編譯成可編輯、可執行，且能根據智能體執行時狀態進行定位與修訂的程序性物件，從而彌補智能體在程序性知識落地能力上的不足。

**Q2：現有的方法或基準測試為何無法充分解決指南轉技能的問題？**

A：現有的情境學習基準測試通常僅使用經過整理的文本資料，並未將真實環境中的多模態指南與實際的環境互動執行配對，因此無法評估指南在動態場景中的實用性。另一方面，現有的技能基準與自我改進智能體方法多依賴專家提供、模型生成或智能體自行探索發現的技能，而非來自公開的人類撰寫指南。這導致學界缺乏系統性證據來證明公開的網路指南材料能否轉化為智能體可執行的技能，也缺乏能在不依賴基準測試分數的情況下進行修訂的框架，使得指南與執行之間的鴻溝始終存在。

**Q3：為什麼不能直接將真實環境指南餵給智能體，或讓智能體完全自行探索，而非要大費周章地轉換成技能？**

A：直接將原始指南提示給智能體可能會損害效能，因為這些資料包含針對人類設計的導航文字、前置假設與偏離路徑後即失效的恢復建議，容易造成執行時的混淆與錯誤。相較於為每項任務手寫技能所需的大量人力，以及僅靠智能體自行探索時受限於自身失敗經驗並浪費額外嘗試來重建已知知識的缺點，利用網路上既有的公開指南能夠以規模化的方式取得程序性知識。將這些真實環境指南蒸餾為可執行技能，不僅能為智能體提供一個更安全的程序性先驗，還能透過持續修訂彌補指南與執行時狀態之間的落差，從而顯著提升解決長期任務的效率與穩定性。

**Q4：MMG2Skill 框架的核心運作流程為何？它如何形成閉環？**

A：MMG2Skill 是一個閉環框架，其核心工作流程包含三個階段：首先，系統會將真實環境的多模態指南編譯成可編輯的 SKILL.md 技能文件，使其成為結構化的程序性物件。接著，在執行階段，一個固定的視覺語言模型（VLM）智能體會根據當前的技能集合進行條件化操作，以完成長期任務。最後，框架會從智能體可觀察的執行軌跡中收集軌跡層級的根本原因回饋，並在不使用基準測試分數的情況下自動修訂技能內容，形成持續自我演進的閉環。

**Q5：與先前的自我改進智能體方法相比，MMG2Skill 的關鍵創新是什麼？**

A：MMG2Skill 的關鍵創新在於首次系統性地將來自網路的真實環境多模態指南蒸餾為智能體可執行且可編輯的技能，並建立對應的基準測試來評估此能力。與許多依賴基準分數或專家示範來進行自我改進的方法不同，MMG2Skill 僅利用智能體執行過程中可觀察到的軌跡，進行軌跡驅動技能修訂，從根源分析失敗原因並更新技能。此外，該框架在整個過程中保持 VLM 骨幹模型固定不變，無需進行模型微調，僅透過外部技能文件的動態修訂來提升執行表現，這大大降低了部署成本並提高了通用性。

**Q6：為什麼 MMG2Skill 選擇以軌跡層級的根本原因回饋來修訂技能，而非直接使用基準測試分數？**

A：選擇僅依賴軌跡層級的根本原因回饋而非基準分數進行修訂，是為了確保修訂過程與實際部署時的信息邊界保持一致，使框架在真實應用場景中更具可行性。在 MMG2Skill-Bench 中，主要評估聚焦於「成功可推斷」任務，即智能體能從自身可觀察的軌跡或公開的最終狀態推斷任務成敗，因此無需仰賴外部評分者或隱藏標籤。這種設計不僅避免了對環境特定評分函數的依賴，也確保了閉環修訂機制能在缺乏基準測試基礎設施的真實環境中運作，從而提升方法的泛化能力與實用價值。

**Q7：MMG2Skill-Bench 有哪些關鍵特性？它如何設計以公平評估指南轉技能的能力？**

A：MMG2Skill-Bench 是首個專為指南轉技能學習設計的基準測試，涵蓋了桌面圖形介面控制、開放式遊戲玩法與策略卡牌遊戲三大互動領域，共計 130 個成功可推斷的任務。此基準為每項任務配對了來自公開網路的人類撰寫指南材料，包含網頁 HTML 內容與圖像資源，以保留步驟順序與視覺線索，同時嚴格排除可直接複製答案的任務與基準解決軌跡，確保評估的是程序性知識的落地能力而非檢索能力。透過這樣的設計，MMG2Skill-Bench 能夠系統性地檢驗視覺語言模型智能體是否真的能將真實環境中的多模態指南轉化為在互動環境中持續有用的程序性知識。

**Q8：MMG2Skill 在實驗中展現了哪些主要的量化成果？**

A：實驗結果顯示，MMG2Skill 在每一個模型與領域的設定下都穩定優於原始基線智能體，橫跨六種 VLM 骨幹模型的宏觀平均提升幅度達到 +12.8 至 +25.3 個百分點。值得注意的是，消融研究發現直接將原始指南作為提示輸入反而可能損害效能，凸顯了結構化技能建構與軌跡驅動修訂的必要性。此外，在成功可推斷的任務上，基於分析器的早期停止機制能有效防止後期效能衰退，並在成功信號經過適當校準的情況下節省 25% 至 53% 的嘗試次數，顯著提升了實際部署的效率。

**Q9：消融研究揭示了 MMG2Skill 各個組件的什麼重要性？**

A：消融研究揭示了幾個關鍵洞察：首先，直接將未經處理的原始指南提示給智能體可能導致效能下降，這證明了單純接觸指南資料並不足以保證性能提升。其次，結構化的技能建構提供了一個更安全的程序性先驗，而軌跡驅動的技能修訂則能修復指南內容與執行時狀態之間的銜接落差，兩者缺一不可。最後，研究也發現修訂帶來的增益並非單調遞增，若缺乏適當的停止機制，智能體在後期可能出現效能衰退，這凸顯了校準成功信號與早期停止策略在閉環學習中的重要性。

**Q10：MMG2Skill 在哪些實際應用場景中最能發揮價值？**

A：MMG2Skill 特別適用於需要執行長期程序性任務且存在大量公開人類指南的場景，例如操作複雜桌面軟體的圖形介面控制、在開放世界遊戲中完成需要探索與合成的多步驟目標，以及進行需要策略規劃的回合制卡牌遊戲。在這些領域中，網路上充斥著產品說明文件、教學文章、維基頁面與攻略指南，但傳統智能體難以直接消化這些異質性高的資料。透過將這些真實環境指南自動轉換為可執行技能並持續修訂，MMG2Skill 能夠顯著降低為每項新任務手寫專用程序的人工成本，並加速智能體在實際互動環境中的上手速度。

**Q11：若要在生產環境中部署 MMG2Skill，實務上需要考慮哪些關鍵因素？**

A：在實際部署 MMG2Skill 時，開發者首先必須注意修訂過程中的增益並非單調上升，因此需要設計經過適當校準的成功信號與早期停止機制，以避免後期效能衰退並節省不必要的嘗試成本。其次，應優先將框架應用於「成功可推斷」的任務類型，即智能體能從自身可觀察軌跡判斷成敗的場景，因為涉及私有資訊的任務可能無法僅靠軌跡進行準確的結果推論與修訂。此外，由於 MMG2Skill 在整個閉環過程中保持 VLM 骨幹模型固定，產品團隊無需承擔模型微調或重新訓練的基礎設施成本，只需維護與更新 SKILL.md 技能文件即可，這使其在快速迭代與多工部署上具備明顯優勢。

**Q12：MMG2Skill 可能對智能體學習與程序性知識領域的未來研究帶來什麼影響？**

A：MMG2Skill 為智能體學習領域開創了一個新的研究問題——指南轉技能學習，並提供了首個專用的基準測試與系統性框架，這將引導未來研究更關注如何有效利用網路上現有的人類知識資產。它證明了公開的真實環境指南確實可以透過適當的蒸餾與修訂機制轉化為智能體的執行能力，從而改變過去依賴專家手寫技能或純粹自我探索的兩極化研究路徑。這項工作也凸顯了程序性知識落地的重要性，未來可能激發更多關於多模態知識萃取、軌跡層級錯誤分析與無分數自我改進機制的研究，進一步推動長期任務智能體的實用化發展。

**Q13：MMG2Skill 框架與基準測試有哪些已知的限制？**

A：MMG2Skill-Bench 的主要評估範圍目前僅限於成功可推斷的任務，這意味著對於那些必須依賴私有資訊才能判斷結果的場景，框架的適用性會受到限制。此外，儘管研究盡量以軌跡作為推論依據，但在僅憑軌跡推斷最終結果時仍可能存在殘餘誤差，這是評估與修訂過程中無法完全避免的資訊邊界問題。同時，MMG2Skill 也承認修訂帶來的效能提升並非單調遞增，若缺乏適當的停止機制，智能體可能在後期出現效能衰退，且未經處理的原始指南提示反而可能對執行產生負面影響。

**Q14：在哪些類型的任務或情境下，MMG2Skill 較可能失敗或表現不佳？**

A：MMG2Skill 可能在成功無法僅由智能體可觀察軌跡推斷的任務中表現不佳，例如涉及隱藏資訊或對手私有狀態的博弈場景，因為此時難以從執行軌跡中萃取出正確的成敗信號來驅動技能修訂。此外，當提供的真實環境指南包含過多雜訊、錯誤步驟或強烈依賴人類常識與前置假設時，即使經過結構化處理，仍可能導致智能體建立錯誤的程序性先驗或在執行中迷失方向。若未妥善校準成功信號或缺少早期停止機制，智能體也可能在多次修訂循環後遭遇後期效能衰退，浪費大量嘗試次數卻無法收斂到穩定的解決方案。

**Q15：基於 MMG2Skill，未來有哪些有前景的研究方向值得探索？**

A：未來研究可以朝幾個方向延伸：首先，開發更強大的軌跡分析器與結果推論方法，以處理目前被排除在主要評估之外、涉及私有資訊或難以僅憑觀察判斷成敗的複雜任務。其次，可以探索更穩健的技能提取技術，使框架能夠在指南品質參差不齊、雜訊極高甚至存在相互矛盾資訊的情況下，依然能萃取出可靠的程序性知識。此外，將指南蒸餾與強化學習或其他互動學習範式結合，並設計更通用的跨領域技能遷移與更精準的自動停止準則，也有望進一步提升智能體在更廣泛的真實環境中的自我演進能力與長期任務表現。

## 實務應用指南

### 適用場景

1. **企業軟體自動化（RPA 2.0）**：將散落的產品說明、操作教學與內部 Wiki 轉為可執行的 GUI 自動化技能，例如自動化跨應用報表產出、軟體設定遷移，讓智能體能依據畫面狀態動態載入對應步驟並自我修正。
2. **遊戲測試與動態 NPC**：利用遊戲維基與通關攻略，自動生成具備探索、合成、資源收集能力的開放世界遊戲智能體，用於自動化 QA 測試、動態難度調整或陪伴型 NPC 的行為腳本生成。
3. **客服與內部流程機器人**：將標準作業程序（SOP）與客服知識庫轉為結構化技能，讓智能體在對話或後台操作中依據當前狀態載入對應程序，並從失敗對話或操作軌跡中持續精進。
4. **策略決策輔助系統**：把公開規則書、合規指南或初階策略教材轉為可執行的回合制決策技能，應用於合規審查流程、招標評分或棋類／牌類對弈輔助，降低人工判讀規則的負擔。

### 實作前置條件

- **資料**：真實環境多模態指南（HTML、截圖、教學關鍵幀）、任務指令集、互動環境 API 或模擬器、可觀察軌跡日誌；指南不得包含黃金解答或隱藏評估標籤。
- **運算資源**：VLM 推理端點（API 或本地 GPU 叢集）、環境互動運算節點、技能版本儲存與比對系統（如 Git-based 或向量資料庫）。
- **能力前提**：團隊需具備 VLM prompt 工程與 agent 架構設計經驗、熟悉目標環境的觀測與動作空間，並能建構軌跡分析器以產生根因回饋（無需依賴 benchmark 分數）。

### 實作步驟建議

1. **建立評估場景與指南語料**：盤點互動環境（桌面 GUI、遊戲引擎、策略模擬器），收集對應領域的真實環境多模態指南，建立類似 MMG2Skill-Bench 的任務對照表，並確認指南已做 leakage control。
2. **結構化技能提取**：將原始指南編譯為可編輯的技能物件（如 SKILL.md），明確定義觸發條件、中繼狀態檢查點與異常恢復路徑；切勿直接將原始指南全文塞入 VLM prompt。
3. **固定 VLM 骨幹與技能條件化執行**：選定固定 VLM 骨幹模型，在每次決策前依據當前環境狀態召回相關技能，讓智能體「諮詢」技能而非「背誦」原始指南。
4. **軌跡收集與根因分析**：記錄完整可觀察軌跡，設計軌跡分析器從失敗案例中提煉根因回饋（例如步驟順序錯誤、前置條件未滿足、觀測對齊失敗），而非僅使用最終分數。
5. **閉環技能修訂**：將根因回饋應用於技能文件的局部修訂，填補面向人類的指南與智能體執行環境之間的 grounding gap，實現軌跡驅動技能修訂。
6. **校準式早期停止與產品化**：在成功訊號可從軌跡推斷的任務上，部署 analyzer-based early stopping，防止晚期效能衰退；通過驗證後將技能庫封裝為版本化服務或 API。

### 潛在風險與注意事項

- **原始指南雜訊與異質性**：真實環境指南常包含導航文字、廣告、人類專屬假設，直接 prompting 原始指南可能導致效能不升反降，必須先經過結構化提取。
- **非單調修訂曲線**：軌跡驅動修訂的增益並非單調遞增，過度迭代可能破壞原本有效的技能，需嚴格監控並設置停止條件。
- **人類執行者偏誤**：指南隱含「人類常識」（如「點擊這裡」的視覺歧義），智能體需透過軌跡回饋重新對齊觀測空間。
- **成功訊號校準**：early stopping 與修訂品質高度依賴軌跡分析器能否正確推斷成功或失敗，校準不良將導致過早停止或無效嘗試。
- **安全性與權限**：在 GUI 控制等場景，VLM 可能產生幻覺動作，必須在沙箱環境中執行並限制敏感操作權限。

### 與其他技術的整合建議

- **RAG 與向量資料庫**：將 SKILL.md 技能庫作為動態檢索目標，依據當前環境狀態嵌入召回最相關的程序性知識，降低長期任務的上下文長度壓力。
- **傳統 RPA / Low-code 平台**：以 MMG2Skill 作為動態知識層，補充固定腳本無法適應介面變化的缺點，形成「靜態腳本 + 動態技能」的混合架構。
- **強化學習（RL）**：將提取出的技能視為高階選項（options）或策略初始化，降低探索成本，特別適合開放式遊戲與長期任務。
- **可觀測性平台**：整合現有 APM / 日誌系統，將生產環境的真實軌跡回流至修訂管線，實現持續演化的技能庫。
- **人機協作（Human-in-the-loop）**：在涉及金流、個資或關鍵業務的 GUI 任務中，於技能修訂與執行閘道加入人工審核。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從圖 1 與第 1 節的動機出發，建立「為何不能把網路教學直接貼給 AI」的核心直覺，再透過 MMG2Skill-Bench 的三個領域（GUI、遊戲、策略）理解長期任務的難點，無需深入技術細節即可掌握「結構化技能優於原始指南」這一關鍵結論。
- **AI 工程師**：應聚焦第 3 節框架與附錄實作細節，特別是 SKILL.md 的結構設計、如何在不使用 benchmark 分數的前提下設計軌跡分析器 prompt、以及 early stopping 的校準邏輯，並留意不同 VLM 骨幹在跨領域的穩定性差異。
- **研究人員**：著重第 2 節 benchmark 的設計哲學，包括 success-inferable 的界定、leakage control 與對照組設置，以及消融實驗所揭示的「原始指南 prompting 可能損害效能」與「結構化建構搭配軌跡修訂缺一不可」的因果關係。
- **產品經理**：核心在於理解論文的商業假設——企業與網路上已存在大量未被充分利用的程序性知識資產；評估自身產品時，應檢視是否具備「可觀察軌跡」與「可推斷的成功訊號」這兩項前提，以判斷導入閉環修訂的 ROI 與落地可行性。
