## ⚡ TL;DR

現有基於LLM的代理人缺乏對文字環境動態演化的明確模型，相關研究亦分散且缺乏系統性回顧。
本文提出文字世界模型的系統性框架，依建構方式、訓練與推論應用及評估方法進行全面回顧。
此工作整合該新興領域的文獻，釐清設計空間並揭示未來研究的開放挑戰。

## 摘要翻譯

基於大型語言模型（LLM）的代理人（LLM-based agent）日益廣泛應用於互動式文字環境，從網頁導覽、程式碼編輯到工具使用與長期對話。然而，許多代理人仍大致上屬於反應式，僅將觀察映射至動作，而缺乏這些環境如何建構與演變的顯式模型。這促使了文字世界模型（Text World Model, TWM）的發展：針對文字狀態（textual state）的轉移模型（transition model），在給定狀態與候選動作（candidate action）時，預測產生的網頁、終端機輸出、API 回應或使用者回覆，從而支援規劃（planning）、高效學習與原則性的評估。我們系統性地回顧針對基於 LLM 的代理人之文字世界模型，並以形式化框架與代理人生命週期為架構：（1）基礎：定義文字世界模型，並以狀態表徵（state representation）與基礎領域（grounding domain）刻畫其特徵；（2）建構：對 LLM 作為世界模型（LLM-as-WM）與程式碼作為世界模型（Code-as-WM）等典範進行分類，並回顧建構它們的方法；（3）應用：探討世界模型（world model）如何於訓練階段透過經驗合成（experience synthesis）、於推論階段透過規劃、驗證與適應來支援代理人；（4）評估：涵蓋世界模型本身的評估，以及其作為代理人評估環境的用途。我們旨在整合這個快速發展的領域，釐清其設計空間，並突顯未來研究的開放性挑戰。

### 核心貢獻（3～5點）
- 提出文字世界模型（TWM）作為文字狀態上的轉移模型，以彌合當前 LLM 代理人在互動式文字環境中缺乏顯式環境演變模型的鴻溝。
- 建立涵蓋基礎、建構、應用與評估的形式化框架，系統性回顧 TWM 的文獻與方法論。
- 分類兩大建構典範——LLM-as-WM 與 Code-as-WM——並回顧其具體建構方法。
- 闡明 TWM 如何於訓練階段透過經驗合成、於推論階段透過規劃、驗證與適應來支援代理人。
- 討論 TWM 本身的評估方法，以及其作為代理人評估環境的用途與價值。

### 適合對象
從事大型語言模型代理人、世界模型、互動式文字環境（如網頁導覽、程式碼編輯、工具使用）相關研究之學者與工程師，以及對代理人規劃、模擬環境建構與評估方法論有興趣之研發人員。

## 深度分析

#### 方法論解析

本文提出一套針對基於大型語言模型（LLM）之代理人（LLM-based agent）的**文字世界模型（Text World Model, TWM）**生命週期框架，將離散的文獻整合為系統性調查。其核心方法論可從三個層次解析：

**1. 形式化定義與雙軸分類（Foundations）**
作者將 TWM 定義為文字狀態（Textual State）上的**轉移模型（Transition Model）**，形式化為 $M: \mathcal{S} \times \mathcal{A} \to \mathcal{T}_\mathcal{S}$，即給定代理人可觀測狀態 $s_t$ 與**候選動作（Candidate Action）** $a_t$，模型輸出後繼狀態的文字呈現 $\hat{s}_{t+1}$。此處「文字」泛指網頁原始碼、終端機輸出、應用程式介面（API）回傳值或自然語言描述。為跨越網頁導航、程式碼編輯、工具使用與長期對話等不同場域，作者提出雙軸特徵化：**狀態表徵（State Representation）**（如結化任務狀態、可觀測文字軌跡或環境語意描述）與**基礎領域（Grounding Domain）**（Web、Code、Tool、Dialogue 等），以此統合原本碎片化的文獻。

**2. 建構典範分類（Construction）**
在建構層面，本文區分三大典範：
- **LLM 作為世界模型（LLM-as-WM）**：透過提示工程（Prompting）、檢索增強生成（Retrieval-Augmented Generation, RAG）或情境式學習（In-Context Learning, ICL）驅動凍結權重的 LLM 模擬環境動態。優勢在於開放詞彙（open-vocabulary）泛化與知識蘊含推論，適合語意複雜、規則難以窮舉的領域。
- **程式碼作為世界模型（Code-as-WM）**：以程式化或混合式（hybrid）建構，將環境轉移邏輯寫死為規則、符號模擬器或輕量神經網路。適合轉移函數明確、需要高保真度（fidelity）與可重複執行的場景（如程式碼編譯、確定性 API 呼叫）。
- **學習式轉移模型（Learned Neural Transition Models）**：在特定領域資料上微調（fine-tuning）或從頭訓練轉移模型，試圖在泛化與精確性之間取得平衡。

**3. 生命週期導向的使用框架（Application）**
本文將 TWM 的應用依代理人生命週期劃分為：
- **訓練時間（Training Time）**：TWM 作為合成環境基質（substrate），透過**經驗合成（Experience Synthesis）**產生合成軌跡（synthetic rollouts），供代理人進行離線強化學習（Reinforcement Learning, RL）或模仿學習，降低對真實環境的高成本互動需求。
- **推論時間（Inference Time）**：TWM 作為前瞻（lookahead）引擎，支援**規劃（Planning）**（如蒙地卡羅樹搜尋 MCTS）、驗證（verification）與適應（adaptation）。代理人可在模擬中評估候選動作的長期後果，再於真實環境執行。

此生命週期框架（圖 2）明確劃分「建構 → 使用 → 評估」的回饋迴路，並強調 TWM 並非靜態元件，而是可透過下游任務表現回饋迭代精進的動態模組。

#### 實驗數據解讀

作為一篇調查論文（survey），本文並未提出單一統一實驗，而是系統性梳理評估方法論與跨研究的實證趨勢。其對「實驗數據」的解讀應聚焦於**評估框架（Evaluation Framework）**與文獻中的經驗模式：

**1. 四維評估軸線**
作者將 TWM 的評估分為四個遞進層次：
- **單步正確性（Single-step Accuracy）**：衡量 $M(s_t, a_t)$ 與真實後繼狀態 $s_{t+1}$ 的匹配程度。在文字領域中，此指標面臨獨特挑戰：由於文字狀態具有開放詞彙與語意模糊性，「正確」往往非單一確定解，而是多重合理後繼的機率分佈。
- **多步一致性（Multi-step Consistency）**：評估長期展開（long-horizon rollout）中狀態軌跡的邏輯自洽性。對 LLM-as-WM 而言，錯誤會隨時間複合累積（compounding error），此為目前主要瓶頸。
- **行為保留度（Behavior Preservation）**：衡量在 TWM 中訓練的代理人策略（policy）遷移至真實環境後的表現落差，即 Sim-to-Real gap 在文字領域的對應。
- **下游代理人效用（Downstream Agent Utility）**：最終評判標準——TWM 是否提升真實任務成功率、減少互動成本或加速學習收斂。

**2. 領域擴張趨勢**
圖 1 的時序文獻地圖顯示，TWM 研究在 2023–2024 年處於萌芽期（如早期探索性工作 WebArena、SWE-bench 相關模擬），至 2025 年後呈現爆發式成長，橫跨網頁（WebWorld、WebDreamer）、程式碼（Code2World、SWE-World）、工具使用（Tool-as-WM 相關）與對話（UserRL、MINDSTORES）。此趨勢反映社群已從「反應式代理人（reactive agent）」轉向「模型化代理人（model-based agent）」的典範轉移。

**3. 典範間的實證權衡**
跨文獻比較顯示：
- **LLM-as-WM** 在開放領域（如長期對話、網頁語意變化）中單步預測的語意覆蓋率較高，但推論成本高昂，且長期展開中易產生幻覺（hallucination），導致多步一致性下降。
- **Code-as-WM** 在確定性環境（如程式碼編譯、結構化 API）中可達近乎完美的單步精確度與多步一致性，但面對開放詞彙或隱含語意規則時，覆蓋率不足且維護成本劇增。
- **混合式（Hybrid）**方法（如部分規則 + LLM 修補）在下游任務效用指標上目前展現最佳性價比，但系統複雜度最高。

#### 與現有研究的比較

本文的核心定位在於填補文獻缺口，其與現有研究的比較可從三個維度展開：

**1. 與視覺/控制領域世界模型調查的區隔**
既有世界模型綜述主要聚焦於像素（pixel-based）或狀態向量（state-vector）環境，如生成式影片（generative video）、自動駕駛（autonomous driving）與具身智慧（embodied intelligence）。這些調查的評估軸線（如像素級重建誤差、物理軌跡誤差）無法直接遷移至文字領域。本文首次針對**文字操作體制（textual operating regime）**建立專屬分類學，強調語意保真度（semantic fidelity）、知識依賴動態（knowledge-laden dynamics）與主觀正確性（subjective correctness）等獨有張力。

**2. 與單一領域代理人研究的比較**
在網頁導航、程式碼生成或對話系統等子領域中，雖已有個別研究使用「模擬器」或「環境模型」，但這些工作缺乏共享詞彙，且往往將世界模型視為特定任務的附屬工具。本文將 TWM 提升為**獨立研究對象（distinct object of study）**，透過形式化轉移函數與生命週期框架，使跨領域方法得以在同一基準上比較。

**3. 與傳統強化學習世界模型的關係**
本文繼承了強化學習中世界模型的長期角色（如 Ha & Schmidhuber, 2018; Hafner et al., 2024 在 Dreamer 系列中的工作），但明確指出文字領域的新挑戰：狀態非固定維度向量、轉移函數受背景知識制約、且「正確後繼狀態」常無唯一解。相較於視覺世界模型透過變分自編碼器（VAE）或離散化標記（token）壓縮觀測，TWM 必須在開放詞彙空間中維持語意與語法結構，這使得建構與評估邏輯根本不同。

**限制（Limitations）**
作為調查論文，本文受限於文獻發表時程（截至 2026 年初），對極新興的「世界模型即服務」或超大規模多模態基礎模型（如原生支援圖文交錯轉移的模型）著墨有限。此外，由於文字領域缺乏如 MuJoCo 或 Atari 的統一模擬平台，文中難以進行嚴格的跨方法數值排名，更多依賴概念性分類。

#### 可重現性評估

可重現性（Reproducibility）在 TWM 領域呈現**高度不均衡**的圖像，本文對此有間接但關鍵的啟示：

**1. 開源資源的可及性**
- **Code-as-WM 典範**：傾向具備較高的可重現性。由於此類方法以明確程式碼或規則定義轉移邏輯（如基於 TextWorld、SWE-bench 或輕量符號模擬器），原始碼與環境設定通常可公開取得。例如文中提及的程式化建構（programmatic construction）往往伴隨開源儲存庫（repository）。
- **LLM-as-WM 典範**：可重現性面臨系統性挑戰。此類方法高度依賴專有模型（proprietary models）如 GPT-4、Claude 或 Gemini，其權重未公開、版本迭代頻繁，且對溫度（temperature）、提示模板（prompt template）與上下文長度極度敏感。即使提示文字開源，不同 API 版本或模型更新可能導致轉移函數 $M$ 的行為漂移，使實驗難以嚴格復現。
- **學習式模型**：部分新近工作（如 Chae et al., 2025; Xiao et al., 2026）釋出神經轉移模型的權重與訓練資料，但由於文字狀態空間龐大，訓練所需的運算資源與資料管線（data pipeline）往往僅有大型研究機構能負擔。

**2. 基準測試（Benchmark）的碎片化**
本文指出，目前尚無橫跨 Web、Code、Tool、Dialogue 的統一 TWM 基準。各子領域使用不同的任務指標（如網頁的成功率、程式碼的單元測試通過率、對話的用戶滿意度），導致跨研究比較困難。這種基準碎片化本質上降低了社群層次的可重現性與可累積性。

**3. 調查論文本身的可重現性**
作為綜述性質的論文，其貢獻在於概念框架而非實驗數據，因此不涉及模型權重或資料集釋出問題。然而，文中圖 1 的文獻時序與圖 3 的分類地圖為後續研究者提供了可擴充的元資料（metadata）結構，具備方法論層次的可重複檢視性。

#### 未來研究方向

本文在整合現有文獻的基礎上，揭示了數個跨越建構、使用與評估階段的開放挑戰，這些即為最具潛力的後續研究方向：

**1. 混合式建構典範（Hybrid LLM + Code-as-WM）**
未來研究可探索如何動態結合 LLM 的語意泛化能力與程式碼的精確執行保證。例如，以程式碼處理結構化、確定性轉移（如 API 呼叫、語法檢查），同時以 LLM 處理開放語意變化（如用戶意圖轉移、網頁內容語意演變）。關鍵問題在於如何設計**路由機制（routing mechanism）**，使系統能自動判斷當前轉移應由規則或神經模擬處理。

**2. 長期一致性與錯誤抑制機制**
LLM-as-WM 在多步展開中的錯誤累積（compounding error）仍是核心瓶頸。未來可發展：
- **自我修正世界模型（Self-correcting TWM）**：讓模型在展開過程中對照內部知識庫或檢索外部資料，驗證狀態轉移的合理性。
- **階層式模擬（Hierarchical Simulation）**：在高層次以抽象語意規劃，低層次才展開具體文字狀態，減少不必要的細節幻覺。

**3. 跨領域統一評估框架**
亟需建立文字領域的「世界模型基準」（如 TextWorld Model Benchmark），涵蓋：
- 標準化的單步/多步預測資料集；
- 行為保留度的統一度量（如從模擬到真實環境的策略遷移分數）；
- 成本-效用權衡指標（推論成本 vs. 下游任務增益）。

**4. 主觀正確性與語意保真度的形式化**
由於文字轉移的正確性常具主觀性（如用戶回覆可能有多種合理版本），未來需發展**基於語意相似度而非精確字串匹配**的評估指標，或引入人類偏好模型（human preference model）來判斷模擬軌跡的合理性。

**5. 世界模型的主動學習與線上適應**
目前多數 TWM 為靜態建構。未來可讓代理人在真實環境中執行時，持續將新觀測回饋至 TWM 進行線上更新（online update），縮小模擬與真實的動態差距。這涉及如何在不破壞既有知識的前提下，進行持續學習（continual learning）與記憶增強（如圖 2 虛線所示的回饋迴路）。

**6. 安全對齊與對抗性穩健性**
當 TWM 用於大規模經驗合成時，模型中的偏誤（bias）或盲點將被大量複製至訓練資料。未來需研究 TWM 的**對抗性穩健性**（如對抗提示攻擊的抵抗力）以及合成環境中的**安全對齊**（safety alignment），避免代理人在模擬中學會有害行為後遷移至真實世界。

## 論文問答

**Q1：基於 LLM 的代理人在互動式文字環境中運作時，其核心痛點為何？為什麼這個痛點會促使文字世界模型（TWM）的發展？**
A：當前許多基於 LLM 的代理人本質上仍屬於反應式系統，僅將當前觀察映射為下一步動作，缺乏對環境結構與演化過程的顯式、可檢視之理解。這種缺失使得代理人無法在網頁導航、程式碼編輯或長期對話等任務中，有效預測「執行動作後狀態將如何改變」，從而難以進行長程規劃與高效學習。文字世界模型正是為了填補這道「代理人—世界鴻溝」而提出，透過建立文字狀態上的轉移模型，使代理人能夠在採取行動前模擬後果，進而支援規劃、經驗合成與有原則的評估。

**Q2：為什麼現有的世界模型相關綜述與方法無法充分滿足以文字為基礎的代理人之需求？**
A：現有的世界模型文獻與綜述絕大多數聚焦於視覺與控制領域，例如生成式影片、自動駕駛與具身智慧，其狀態表徵以像素或狀態向量為主。這些領域所發展出的分類軸線與評估協定，並無法直接遷移至文字轉移場景，因為文字狀態具有開放詞彙、語義模糊、知識密集以及正確性主觀等獨特張力。因此，文字領域長期缺乏專屬的分類架構與共享詞彙，導致相關研究在網頁、程式碼、工具使用與對話等不同基礎領域中呈現碎片化，難以進行系統性比較。

**Q3：相較於單純依賴反應式策略，發展專門的文字世界模型為何重要？**
A：反應式策略僅能針對當前觀察做出單步決策，無法捕捉環境作為一個結構化、動態演化系統的本質，這在長期互動中會導致錯誤累積與目標偏離。文字世界模型作為顯式的轉移模型，能夠在給定文字狀態與候選動作的條件下預測後繼狀態，使代理人具備「先模擬、後執行」的能力。這不僅是進行長程規劃與動作驗證的基礎，也讓代理人能透過合成經驗在訓練階段減少對真實環境的昂貴互動需求，並在推論階段透過前瞻推演提升決策品質。

**Q4：本文針對文字世界模型提出了什麼樣的形式化定義？其輸入與輸出的特性為何？**
A：本文將文字世界模型定義為一個轉移函數 M：S × A → T_S，其中在給定代理人可見的狀態 s_t 與候選動作 a_t 後，模型輸出後繼狀態的文字呈現 ŝ_{t+1}。此處的「文字」指的是轉移結果向代理人暴露的形式，輸出可以是自然語言描述、結化紀錄或程式碼片段等；而輸入狀態本身則不限於純文字，亦可為對話歷史、終端機軌跡或網頁截圖等多模態資訊。此外，實作該模型的底層基質亦不受限，無論是透過提示從凍結 LLM 中誘發、以學習方式訓練，或以程式碼生成，皆符合此形式化框架。

**Q5：建構文字世界模型的兩大主要典範為何？它們在本質上有什麼差異？**
A：本文將建構方法歸納為「LLM 作為世界模型（LLM-as-WM）」與「程式碼作為世界模型（Code-as-WM）」兩大典範。前者直接利用大型語言模型的內化知識，透過提示工程或學習式調適來模擬文字狀態的轉移動態，具備較高的泛化性與快速部屬的優勢；後者則透過程式化或混合式建構，以顯式程式碼或符號規則定義狀態演化邏輯，通常在特定領域中可提供更確定、可解釋且可檢視的轉移行為。兩者的核心差異在於，LLM-as-WM 將領域動態內化於模型參數中，而 Code-as-WM 則將動態外顯為可執行的結構，各有其適用的權衡情境。

**Q6：圍繞代理人生命週期，本文從哪些關鍵設計選擇來刻畫文字世界模型？**
A：本文以「建構—使用—評估」的生命週期為主軸，並輔以兩個跨階段的刻畫軸線：狀態表徵與基礎領域，前者決定模型追蹤何種資訊，後者界定模型所對應的真實應用場景（如網頁、程式碼、API 或對話）。在建構階段，研究者需在學習式、提示式與程式化方法之間權衡，以取得 fidelity 與泛化性的平衡；在使用階段，模型可於訓練時作為合成經驗的環境基質，或於推論時扮演規劃器、驗證器與推演引擎。這些設計選擇彼此連動，共同決定了文字世界模型在代理人堆疊中的定位與效用。

**Q7：本文歸納了哪些評估文字世界模型的準則與面向？**
A：本文將評估方法有系統地組織為四個層次：單步預測正確性、多步一致性、行為保留度與下游代理人效用。單步正確性衡量模型預測的後繼文字狀態與真實環境輸出之間的吻合程度；多步一致性則檢視長期推演出來的軌跡是否隨時間保持語義與結構上的連貫，避免發散至不合理狀態。行為保留度與下游效用更進一步確認模型是否捕捉了對任務成敗至關重要的動態特徵，以及代理人是否因使用該世界模型而在真實環境中獲得性能提升。

**Q8：從圖一的時間軸與文獻回顧來看，文字世界模型的發展呈現哪些關鍵趨勢？**
A：如圖一所示，該領域自 2025 年起快速擴張，從早期少數探索性工作迅速發展為涵蓋網頁、程式碼、遊戲與對話等多領域的豐富文獻。早期研究多依賴提示式模擬與簡單的程式化建構，而近期方法則逐漸融入學習式神經轉移模型與混合式架構，試圖結合 LLM 的廣泛知識與程式碼的精確控制。整體趨勢顯示，文字世界模型正從狹隘的領域專用模擬器，朝向能處理開放詞彙、知識密集且語義複雜的通用文字轉移模型演進。

**Q9：針對不同建構典範，本文提供了哪些比較性洞見或權衡分析？**
A：本文指出，以 LLM 作為世界模型的提示式方法雖能快速原型化並覆蓋廣泛的文字動態，但在多步推演中容易出現幻覺與不一致，導致軌跡隨時間發散。相對地，程式碼作為世界模型在定義明確的領域中可提供更高的可解釋性與確定性保證，卻需付出可觀的工程成本，且難以應對開放式、高度依賴背景知識的轉移情境。混合式方法試圖兼顧兩者優勢，然而如何在神經組件與程式組件之間取得最佳整合，仍是目前研究中尚未完全解決的開放問題。

**Q10：文字世界模型在哪些實際應用場景中能夠提升基於 LLM 的代理人表現？**
A：文字世界模型可應用於網頁導航以模擬點擊後的頁面變化、應用於程式碼編輯以預測原始碼修改如何傳播至執行時行為，以及應用於長期對話以推演使用者目標的演變與回覆內容。在訓練階段，它們可作為環境基質進行經驗合成，產生大量合成軌跡供強化學習或模仿學習使用，從而減少與真實網站、終端機或真人互動的高昂成本。在推論階段，它們則充當前瞻規劃器與動作驗證器，讓代理人在執行高風險操作前先探索假設性的動作序列，顯著提升決策的穩健性。

**Q11：將文字世界模型整合進代理人系統時，需要考量哪些產品與工程面的問題？**
A：整合文字世界模型首先需面對延遲與運算成本的挑戰，因為無論是呼叫 LLM 進行模擬或執行生成的程式碼，其開銷都遠高於單步反應式策略。工程團隊必須在模型逼真度與覆蓋範圍之間謹慎權衡，確保模擬器能捕捉關鍵領域語義，卻又不至於比真實環境更難維護。此外，由於文字狀態常具歧義且正確性往往帶有主觀色彩，產品端必須設計穩健的驗證迴路與降級機制，以防範世界模型預測偏離現實時造成錯誤連鎖反應。

**Q12：文字世界模型的形式化與系統性回顧，可能對自主代理人與強化學習領域帶來什麼廣泛影響？**
A：透過建立共享的形式化框架與生命週期分類法，本文將原本分散於網頁、程式碼、工具使用與對話等領域的碎片化文獻加以整合，使研究者得以進行跨領域的系統性比較。這項工作搭起了當前以反應式觀察—動作為主的 LLM 代理人典範，與強化學習中長期以世界模型為核心的規劃及樣本效率傳統之間的橋樑。其影響力將體現在促進經典規劃演算法適配於文字狀態空間，並推動能夠處理語義與知識密集特性之全新評估協定的發展。

**Q13：當前文字世界模型方法普遍存在哪些被作者指出的根本限制？**
A：一項根本限制在於開放詞彙的通用性與確定性逼真度之間的張力：文字狀態本質上具有歧義，且合理的轉移往往依賴難以顯式 grounding 的背景知識。現有方法在多步推演中也面臨一致性衰減的問題，單步預測的微小誤差會在長期軌跡中不斷放大，導致模擬偏離真實環境動態。此外，文字正確性的主觀與語義本質意味著許多轉移並不存在單一的 ground-truth 後繼狀態，這同時為模型訓練與性能評估帶來了額外的複雜度。

**Q14：在哪些失敗情境或極端案例中，文字世界模型仍然不可靠或難以實用？**
A：在高度動態或對抗性的文字環境中，細微的上下文變化可能導致劇烈不同的結果，而這些結果往往難以從靜態訓練資料或提示中預先推知，使得世界模型特別不可靠。當領域動態涉及精確的執行語義時——例如低階系統呼叫或複雜的多檔案程式碼重構——現有 LLM 模擬器或手寫近似程式碼的解析度通常不足以忠實重現行為。此外，在面對真人對話者的系統中，由於人類意圖演化具有本質上的不可預測性，要維持一個穩定且準確的使用者目標模型至今仍是一大挑戰。

**Q15：本文指出了哪些未來研究方向與開放性挑戰？**
A：未來研究亟需解決多步推演中的一致性問題，並降低長期軌跡中的誤差累積，可能的途徑包括設計能緊密結合神經與程式化組件的混合架構。另一項開放挑戰是發展出超越表面形式相似度的評估指標，使其能真正衡量文字轉移在語義逼真度與任務相關行為保留上的表現。最後，本文呼籲更多關於適應性世界模型的研究，讓模型能夠在真實環境變化時進行線上自我更新，從而閉合代理人執行、模型預測與持續改進之間的回饋迴路。

## 實務應用指南

### 適用場景

1. **高風險網頁自動化流程**：應用於金融申報、醫療預約掛號或企業內部系統操作，在實際點擊前透過文字世界模型（TWM）模擬頁面狀態轉移與表單驗證結果，避免不可逆的錯誤操作。
2. **軟體工程代理人的程式碼重構**：在實際修改原始碼前，預測 patch 後的終端機輸出、測試結果與依賴傳播行為，降低編譯錯誤與迴歸風險，支援長程除錯與重構規劃。
3. **長程客戶服務與對話系統**：維護使用者目標與偏好的文字狀態，模擬使用者可能的回覆與情緒演變，使對話代理人能進行多輪策略規劃，而非僅採反應式回應。
4. **多工具編排與 API 串接**：在呼叫真實外部 API 前，透過 TWM 預測回傳格式、錯誤碼與內容，用於規劃工具呼叫順序、參數組合與容錯路徑，減少實際試錯成本。
5. **自動化回歸測試沙箱**：將 TWM 作為輕量評估環境，快速驗證代理人策略在網頁、終端機或文字遊戲介面中的行為一致性，並作為合成訓練資料的來源。

### 實作前置條件

- **資料**：領域內的狀態–動作–次狀態三元組（state-action-next state triples），例如網頁 DOM 差異、終端機 log、API request/response 對話紀錄；領域知識文件如 API 規格書、設計規格與使用者手冊。
- **運算**：LLM 推論端點（若採 LLM-as-WM 典範）；若採學習式轉移模型，則需 GPU 叢集進行微調；獨立的沙箱執行環境（容器或虛擬機器）供 Code-as-WM 驗證與行為保留度測試。
- **技能**：具備代理人框架與強化學習基礎；提示工程能力以設計模擬提示；軟體工程能力以封裝領域邏輯為程式碼模擬器；領域專家以定義主觀正確性標準與評估門檻。

### 實作步驟建議

1. **界定基礎領域與設計狀態表徵**：明確定義文字狀態的範圍（自然語言描述、結構化紀錄、程式碼片段或 DOM 樹），決定狀態是純文字或多模態（如截圖搭配 HTML），並確保表徵對代理人可觀測。
2. **選擇建構典範**：高知識密度、開放詞彙且語意主觀的領域（如對話、開放式網頁）優先採用 LLM-as-WM；具確定性規則的領域（如標準 API、語法嚴謹的程式碼編譯）優先採用 Code-as-WM；兩者可透過混合架構互補，以程式碼處理結構化轉移、LLM 處理語意變化。
3. **建立轉移函數與資料管線**：蒐集真實環境的轉移軌跡，建立 M: S×A→T_S 的資料管線；若採學習式方法，需處理文字狀態的開放詞表與模糊性；若採提示式，需設計 few-shot 範例與 RAG 機制注入領域知識。
4. **訓練階段整合（Training-Time）**：將 TWM 作為合成環境基板，產生虛擬 rollout 以擴增代理人訓練資料（經驗合成），或作為 Dyna-style 架構中的模擬器進行策略學習與離線探索。
5. **推論階段部署（Inference-Time）**：整合 TWM 為規劃模組，支援蒙特卡洛樹搜尋（MCTS）或前瞻驗證（lookahead verification）；在執行高風險動作前，先於世界模型中模擬數步後的狀態，並作為驗證器過濾不合法動作。
6. **分層評估與回饋迭代**：從單步預測準確率開始，逐步驗證多步一致性（multi-step consistency）與行為保留度（behavior preservation），最終測量下游代理人任務指標；建立回饋迴路持續修正 TWM，縮小模擬與真實環境落差。

### 潛在風險與注意事項

- **語意模糊與開放詞表漂移**：文字狀態無唯一正確後繼狀態，需事先與領域專家定義「足夠好」的語意相似度門檻，避免過度追求字面一致而忽略任務層級的等價性。
- **多步誤差累積（Compounding Errors）**：TWM 在長程 rollout 中容易發散，建議限制模擬深度（planning horizon），或與真實環境定期重新對齊（re-grounding），防止想像軌跡偏離現實。
- **LLM-as-WM 的知識幻覺**：動態轉移依賴背景知識時，模型可能生成看似合理但違反領域規則的狀態，需搭配 RAG、程式化驗證器或人類回饋機制進行約束。
- **模擬與真實環境的行為落差（Sim-to-Real Gap）**：即使單步準確率高，長期行為可能偏離真實使用者或系統，需設計行為保留度指標並保留真實環境的 A/B 測試閘道，避免完全依賴模擬結果上線。
- **運算成本陷阱**：LLM-as-WM 每步模擬都需呼叫大型模型，長程規劃成本可能遠超直接試錯，需評估「規劃節省的錯誤成本」是否高於「模擬運算成本」，並考慮快取常見轉移結果。

### 與其他技術的整合建議

- **檢索增強生成（RAG）與上下文學習（ICL）**：將領域文件、API 規格書動態注入 LLM-as-WM 的提示，降低知識幻覺並提升轉移可信度，特別適用於網頁與工具使用場景。
- **現有模擬器與容器化環境**：Code-as-WM 可封裝為 Docker 容器或輕量函數，與現有 CI/CD 管線整合；對於網頁領域，可結合瀏覽器自動化框架（如 Playwright）作為部分可程式化轉移的後端，形成混合模擬。
- **強化學習（RL）框架**：將 TWM 視為 Gym 風格的環境（如 TextWorld、CLI-Gym），供策略模型進行離線訓練；支援 Dyna-Q 或 MCTS 等需大量模擬軌跡的演算法，並作為獎勵函數設計的測試床。
- **代理人編排框架（LangChain、AutoGen）**：將 TWM 獨立為「規劃器」或「驗證器」節點，與實際執行節點分離，讓代理人在執行前具備「想像」與「驗證」的能力，並透過事件驅動架構觸發重新規劃。
- **可觀測性平台**：建立結構化 log 記錄 TWM 的預測狀態與真實狀態的差異，作為持續微調或提示迭代的資料來源，形成圖 2 所示的生命週期回饋迴路。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從第 2 節的基礎定義與圖 2 的生命週期架構入手，先理解「文字世界模型」作為轉移預測器的核心角色，暫時略過形式化符號，重點掌握 LLM-as-WM 與 Code-as-WM 兩種建構方式的直觀差異，再對照適用場景建立整體概念。
- **AI 工程師**：請聚焦第 3 節的建構分類與第 4、5 節的訓練／推論整合模式，特別關注狀態表徵設計、提示工程與現有 RL／Agent 框架的銜接細節；建議直接參考文中提到的 WebWorld、SWE-World、SPA 等代表性實作，評估自身領域適合的混合架構。
- **研究人員**：建議深入閱讀第 2 節的形式化框架與第 6 節的評估方法論，思考開放詞表、語意主觀正確性與多步一致性等文字領域特有的挑戰；可從生命週期的回饋迴路與行為保留度指標切入，尋找建構更輕量、更可信賴之 TWM 的研究破口。
- **產品經理**：請優先閱讀適用場景與潛在風險章節，評估導入 TWM 的投資報酬率：區分「訓練時資料合成」與「推論時規劃驗證」兩種價值主張，並留意運算成本、模擬與真實落差及主觀正確性所帶來的品質控管難度，規劃階段性導入路徑。
