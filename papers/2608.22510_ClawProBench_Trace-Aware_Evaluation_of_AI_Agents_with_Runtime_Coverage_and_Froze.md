# ClawProBench：以執行環境覆蓋度與凍結工作場景風格保留集進行人工智慧智能體的軌跡感知評估

**原文標題：** ClawProBench: Trace-Aware Evaluation of AI Agents with Runtime Coverage and Frozen Workplace-Style Holdouts  
**作者：** YuanHang Xiao  
**發布日期：** 2026-08-23  
**HF 連結：** [https://huggingface.co/papers/2608.22510](https://huggingface.co/papers/2608.22510)  
**arXiv：** [https://arxiv.org/abs/2608.22510](https://arxiv.org/abs/2608.22510)

## ⚡ TL;DR

現有智能體基準僅評最終答案，忽略具狀態執行環境中的證據取得、路由、安全與重複執行失效。
本文提出 ClawProBench，於 OpenClaw 軌跡評測 102 即時與 68 凍結情境，依安全閘控計分。
結果顯示原生表面弱於工作空間任務，嚴格三次通過遠低於 pass@k-any，正確性亦異於軌跡感知排名。

## 摘要翻譯

智能體基準測試通常僅評估最終答案（final answer），即使智能體執行於具狀態執行環境（stateful runtime）上亦然。我們認為此舉對所評估對象的界定不足：適當的單位應為一組宣告式模型加執行環境配置（declared model-plus-runtime configuration），其失效可能發生於證據取得（evidence acquisition）、執行環境路由（runtime routing）、安全邊界（safety boundary）或重複執行（repeated execution）之中。我們提出 ClawProBench，一個用於原生執行環境智能體評估（runtime-native agent evaluation）的軌跡感知基準測試（trace-aware benchmark），並在即時智能體執行環境（live agent runtime）OpenClaw 上實例化；OpenClaw 具備工作空間工具（workspace tools），以及用於瀏覽（browsing）、記憶（memory）、訊息傳送（messaging）、排程（scheduling）、技能（skills）與子智能體（subagents）的原生表面（native surfaces）。ClawProBench 定義了兩個賽道：一個包含 102 個情境的完整設定檔（full profile），內含工作空間即時任務（workspace-live task）與原生執行環境路由任務（native-runtime routing task）；以及一個凍結的 68 個情境保留集（frozen holdout），採用封閉世界 JSON 輸出契約（closed-world JSON output contract）以進行穩健排名。試驗是根據執行軌跡（execution trace），透過結合正確性（correctness）、流程品質（process quality）與效率（efficiency）的安全閘控計分公式（safety-gated formula）進行評分，並保留失敗證據（failure evidence）以供稽核（audit）。我們的匿名研究成果套件（artifact）包含基準測試定義（benchmark definition）、計分程式碼（scoring code）、清單（manifest）與去識別化軌跡（sanitized trace）。我們在完整設定檔上評估 68 種配置，在保留集上評估 37 種配置。最高的安全閘控平均軌跡分數為 0.7671。原生執行環境任務的表現低於工作空間即時任務（0.5238 相較於 0.6415）。在保留集上，pass@k-any 優於嚴格三次試驗通過（strict three-trial pass）（0.6638 相較於 0.2890），而完整設定檔與保留集的排名呈現弱對齊（Spearman 0.1300）。僅基於正確性的排名與流程感知、安全閘控及嚴格通過視角有顯著差異。以最終答案為準的排行榜可能隱藏原生表面弱點（native-surface weakness）、一次性成功（one-off success）以及軌跡局部智能體失效模式（trace-local agent failure mode）。

### 核心貢獻（3～5點）
- 提出「宣告式模型加執行環境配置」作為智能體評估的適當單位，強調僅評估最終答案會低估執行環境、流程與重複執行帶來的失效風險。
- 設計並實作 ClawProBench，結合軌跡感知評估、執行環境覆蓋度與凍結工作場景風格保留集，支援可稽核且可重複的計分流程。
- 建立雙軌道評測架構：102 情境完整設定檔用於廣泛診斷，68 情境凍結保留集搭配封閉世界 JSON 輸出契約用於穩健排名。
- 透過大規模實證（68 組完整設定檔配置、37 組保留集配置）揭示：原生執行環境任務顯著難於工作空間即時任務；pass@k-any 與嚴格三次試驗通過的結果差異懸殊；僅看正確性的排行榜會遮蔽流程品質與安全邊界問題。

### 適合對象
本論文最適合從事人工智慧智能體評估、基準測試設計、語言模型與執行環境整合研究的學者與工程師閱讀；對於關注智能體可靠性、可稽核性、執行環境覆蓋度，以及希望建構更嚴謹的即時智能體排行榜的研究機構與產品團隊亦具高度參考價值。

## 深度分析

#### 方法論解析

ClawProBench 的核心方法論主張是：對 AI 智能體（AI agent）的評測單位應該是「宣告式模型加執行環境配置（declared model-plus-runtime configuration）」，而非僅僅是模型對單一提示（prompt）產生的最終答案（final answer）。在具狀態執行環境（stateful runtime）中，智能體的失敗可能發生在證據取得（evidence acquisition）、執行環境路由（runtime routing）、安全邊界（safety boundary）或重複執行（repeated execution）等多個環節。因此，評測必須同時涵蓋終態正確性、執行軌跡（execution trace）品質、執行狀態（status）與可稽核性（auditability）。

為實現這一目標，作者設計了兩條互補的測試軌道（track）：

1. **完整設定檔（full profile）**：共 102 個主動情境（active scenario），其中 66 個為工作空間即時任務（workspace-live task），36 個針對 OpenClaw 的原生執行環境表面（native runtime surface），包括瀏覽器（browser）、記憶（memory）、訊息傳送（messaging）、排程（scheduling）、技能（skill）、子智能體（subagent）、工作階段（session）、目錄（directory）、Cron 與智能體委派（agent delegation）等。此軌道強調執行環境覆蓋度（runtime coverage）與原生路由（native routing）能力。

2. **凍結真實保留集（frozen realistic holdout）**：共 68 個工作場景風格（workplace-style）的封閉世界情境（closed-world scenario），採用固定不變的 JSON 輸出契約（closed-world JSON output contract）。該保留集透過穩定標籤（stable tag）在經過校準（calibration）與修剪（pruning）後凍結，確保情境識別（scenario identity）、終態契約（end-state contract）與檢查器介面（checker interface）固定，從而支援重複試驗可靠性（repeated-trial reliability）與固定契約跨執行環境比較（fixed-contract cross-runtime comparison）。

評分機制採用「安全閘控計分公式（safety-gated formula）」，結合正確性（correctness）、流程品質（process quality）與效率（efficiency）。安全閘控（safety gate）會根據嚴重程度對違反安全邊界的行為進行扣分或取消資格，確保流程證據（process evidence）與失敗證據（failure evidence）得以保留。每次試驗都會產生執行軌跡，並透過軌跡擷取（trace capture）與狀態回報（status reporting）機制，記錄執行狀態標籤（status label）與檢查器細節（checker detail），供後續稽核（audit）。

此外，作者提出了一個「執行環境適應契約（runtime adaptation contract）」，作為明確介面（explicit interface）。該契約規範了表面註冊（surface registration）、軌跡事件（trace events）、後置條件（postconditions）、檢查器（checkers）與列來源（row provenance）等項目，使得評測契約（evaluation contract）可以在不同執行環境（OpenClaw、IronClaw、NanoClaw）之間調適，而不預設工具完全相同。

#### 實驗數據解讀

論文報告了兩組主要實驗結果。在完整設定檔（full profile）上評測了 68 種配置，在凍結保留集（frozen holdout）上評測了 37 種配置。整體而言，最高的安全閘控平均軌跡分數（safety-gated average trace score）為 0.7671，顯示目前最佳系統仍有約 23% 的改進空間，任務尚未飽和。

一個關鍵發現是原生執行環境表面任務的表現明顯落後於工作空間即時任務：原生表面（native surface）平均分數僅 0.5238，而工作空間即時任務（workspace-live task）為 0.6415。這表示現有智能體在處理檔案、瀏覽、記憶、訊息、排程等產品級原生功能介面時，仍比處理相對封閉的工作空間任務更為薄弱。這也呼應了論文的核心論點：僅看最終答案（final answer）的排行榜可能掩蓋原生表面弱點（native-surface weakness）。

在凍結保留集上，作者比較了兩種可靠性指標：pass@k-any（至少通過一次指標，pass-at-least-once metric）與嚴格三次試驗通過（strict three-trial pass）。結果顯示 pass@k-any 分數為 0.6638，而嚴格三次試驗通過僅 0.2890，兩者差距極大。這說明許多配置依賴一次性成功（one-off success），在重複執行（repeated execution）下並不可靠。對於需要穩定運作的生產環境智能體而言，嚴格通過率可能比 pass@k-any 更具參考價值。

另一個重要數據是完整設定檔與凍結保留集之間的排名相關性很低，斯皮爾曼（Spearman）等級相關係數僅 0.1300。這意味著兩條軌道測量到的能力並不完全一致：在開放、覆蓋廣泛的執行環境中表現好的配置，不一定在封閉、固定契約的工作場景中同樣出色。因此，單一排行榜難以完整反映智能體的綜合能力，必須同時參考多個診斷視角（diagnostic view）。

此外，作者發現僅基於正確性（correctness）的排名與結合流程品質、安全閘控（safety-gated）及嚴格通過（strict-pass）的視角有顯著差異。這進一步證明，若只採用最終答案是否正確來排名，會忽略執行過程中的軌跡局部失效模式（trace-local failure mode），例如使用了錯誤的表面、跳過必要證據、違反核准邊界（approval boundary）或浪費重試次數。

#### 與現有研究的比較

ClawProBench 與現有研究的關係可從三個層面理解：執行基板（execution substrate）、評分證據（scoring evidence）與治理風險（governance risk）。

在執行基板方面，網頁基準測試（web benchmark）如 WebArena、Visual WebArena、Mind2Web 與 WebCanvas 專注於瀏覽器互動；桌面基準測試（desktop benchmark）如 OSWorld 聚焦作業系統環境（operating-system environment）；工作場景基準測試（workplace benchmark）如 TheAgentCompany、WorkArena 與 CLAWSBench 則模擬服務支援任務（service-backed task）與 API 使用（API use）。ClawProBench 與這些工作共享系統級目標，但更進一步將評測對象固定為「宣告式模型加執行環境配置」，並同時納入工作空間證據處理（workspace evidence processing）與原生執行環境表面（native runtime surface）兩大診斷切片（diagnostic slice）。

在評分證據方面，軌跡感知基準測試（trajectory-aware benchmark）如 Claw-Eval、WildClawBench 與 REALBench 已經開始重視執行軌跡（execution trace）、安全性與穩健性（robustness）。ClawProBench 的差異化貢獻不在於單獨強調即時執行（live execution）、軌跡或安全性，而在於將這些元素整合為「聯合每配置診斷（joint per-configuration diagnosis）」：透過原生表面設定檔、有界軌跡計分、狀態保留報告與凍結保留集，提供可定位失敗來源的多維視角。

在治理風險方面，資料污染（data contamination）與基準測試洩漏（benchmark leakage）是靜態公開評測的已知問題。ClawProBench 並未宣稱完全消除這些風險，而是將暴露狀態（exposure status）視為可報告的中繼資料（metadata）：凍結保留集透過選擇器與雜湊（hash）固定，排行榜列資料附帶狀態標籤（status label），並在附錄中規範分階段發布（staged release）、暴露標籤與退役紀錄（retirement records）。這種做法比單純靜態公開測試更具可稽核性（auditability），但仍需配合持續更新的保留集才能長期有效。

在安全風險方面，近期針對 OpenClaw 的研究指出，智能體失敗往往源於模型行為、受信任上下文、工具路由與框架腳手架之間的交互，而非單純的文字層級拒絕行為。ClawProBench 將安全情境嵌入正常任務執行中，透過嚴重性感知閘控（severity-aware gates）、稽核狀態檢查（audit-state checks）與明確執行狀態回報，回應了這一研究趨勢。

不過，ClawProBench 也有其限制。首先，它目前以 OpenClaw 生態系為主要實例化對象，雖然凍結工作空間保留集可在 IronClaw 與 NanoClaw 上運行，但原生表面任務仍高度依賴 OpenClaw 的特定功能。其次，102 個情境雖然涵蓋八種原生表面，但相較於大規模網頁或工具基準測試，情境數量仍屬中等，可能無法涵蓋所有邊緣案例。第三，計分公式中的流程品質與效率權重需要人為設計，不同應用場景可能對這些維度有不同偏好。

#### 可重現性評估

可重現性（reproducibility）是 ClawProBench 設計的重要承諾之一。論文提到匿名研究成果套件（anonymous artifact）包含基準測試定義（benchmark definition）、計分程式碼（scoring code）、清單（manifest）與去識別化軌跡（sanitized trace）。專案頁面與原始碼已公開於 https://suyoumo.github.io/bench/ 與 https://github.com/suyoumo/ClawProBench，這為其他研究者重現實驗提供了基礎。

在評測契約層面，凍結保留集（frozen holdout）透過穩定標籤（stable tag）與發布雜湊（release hash）固定情境識別與終態契約，確保不同時間、不同團隊執行時使用的是同一組測試。這對於重複試驗可靠性（repeated-trial reliability）至關重要。此外，執行環境適應契約（runtime adaptation contract）明確定義了表面註冊、軌跡事件、後置條件、檢查器與列來源等介面，使得不同執行環境（OpenClaw、IronClaw、NanoClaw）可以在固定契約下進行比較。

然而，可重現性仍面臨一些挑戰。首先，OpenClaw 是一個即時智能體執行環境（live agent runtime），部分測試涉及真實線上服務與動態狀態，這使得完全確定性重現困難。其次，論文中評測的 68 種與 37 種配置涉及不同模型與腳手架（scaffolding）組合，但未必所有模型權重（model weights）與提示範本（prompt templates）都會公開，這可能限制外部研究者完全複製特定配置。第三，雖然去識別化軌跡有助於稽核，但敏感的工作空間資料與執行環境內部狀態可能無法完全公開，影響細粒度重現。

整體而言，ClawProBench 在開源程式碼、固定契約與狀態標註方面做出了紮實努力，但在涉及即時服務、模型權重與敏感資料時，仍屬於「可稽核（auditable）」重現而非「位元對位元（bit-for-bit）」重現。

#### 未來研究方向

ClawProBench 的設計為後續研究開啟了多個方向：

1. **擴展原生執行環境表面覆蓋**：目前 36 個原生表面情境涵蓋八種介面，但未來可進一步納入更複雜的多步驟委派、跨工作階段狀態管理、長期 Cron 排程與異步訊息處理，以測試智能體在更真實產品環境中的原生路由能力。

2. **長期與多智能體互動**：現有情境多為單次或短程任務。未來可參考 ClawMark 的多日同事智能體（multi-day coworker agent）設定，設計需要持續數小時甚至數日的任務，評估記憶一致性、排程可靠性與智能體委派（agent delegation）的長期穩定性。

3. **自動化診斷與根因分析**：目前檢查器細節與狀態標籤仍需人工檢視。未來可結合大型語言模型（language model）開發自動化軌跡分析工具，自動歸類軌跡局部失效模式（trace-local failure mode），例如識別「證據取得失敗」、「錯誤表面選擇」或「重試策略不當」等根因。

4. **安全嚴重性分級與動態閘控**：現有安全閘控（safety gate）已具嚴重性感知，但未來可進一步研究不同應用場景下的風險權重，並設計動態核准邊界（approval boundary），在安全性與任務完成率之間取得更細緻的平衡。

5. **跨執行環境標準化**：執行環境適應契約（runtime adaptation contract）是重要起點，但未來可推動成為更廣泛的社群標準，讓更多執行環境（如開源智能體框架、企業級 RPA 平台）都能以相同契約參與評測。

6. **動態與持續更新的凍結保留集**：為了對抗資料污染與過度擬合，未來可設計定期輪替的凍結保留集，同時保留舊版本的退役紀錄（retirement records），形成可追蹤的評測演進歷史。

7. **人機協同稽核介面**：雖然去識別化軌跡（sanitized trace）已可稽核，但未來可開發互動式視覺化介面，讓稽核人員能快速瀏覽執行軌跡、檢查證據鏈與安全事件，提升稽核效率。

8. **腳手架與重試策略的系統性研究**：論文發現同一模型在不同配置（harness）下表現差異顯著。未來可針對提示範本、工具選擇邏輯、重試次數上限與錯誤恢復機制進行更系統性的消融研究，以區分模型能力與執行環境工程（runtime engineering）的貢獻。

9. **結合人類偏好與流程品質**：流程品質（process quality）目前由檢查器規則定義，但未來可引入人類評分者或偏好模型，評估執行軌跡是否自然、可解釋且符合使用者預期。

10. **即時排行榜與持續評測**：最後，可將 ClawProBench 擴展為持續運作的即時基準測試（live benchmark），定期在新版本模型與執行環境上執行，並公開狀態標註的排行榜（leaderboard），以追蹤整個領域的進展。

## 論文問答

**Q1：ClawProBench 指出現有智慧體基準測試存在什麼核心問題？**

A：現有許多基準測試只根據智能體的最終答案評分，卻忽略了智能體是在具狀態執行環境（stateful runtime）中運作的事實。這種做法對評測對象的界定過於寬鬆，因為真正的失敗可能發生在證據取得、執行環境路由、安全邊界或重複執行等環節。因此，ClawProBench 主張評測的適當單位應該是「宣告式模型加執行環境配置」（declared model-plus-runtime configuration），而非單純的模型或提示。

**Q2：為什麼僅依賴最終答案的排行榜不足以評估執行環境中的智能體？**

A：一個正確的最終答案可能掩蓋了智能體使用錯誤表面、跳過必要證據、違反核准邊界、浪費地重試，或留下無法稽核的執行軌跡等問題。現有的網頁、桌面與工作場景基準測試雖然涵蓋了部分互動能力，但很少同時檢視模型—執行環境—軌跡這一整體系統。結果，最終答案導向的排行榜容易隱藏原生表面弱點與軌跡局部失效模式，導致評估結論過於樂觀。

**Q3：軌跡感知評估對實際部署的人工智慧智能體為何重要？**

A：在真實產品中，智能體會讀取檔案、呼叫工具、瀏覽網頁、搜尋記憶、傳送訊息、排程提醒，甚至委派子智能體，這些行為都會在執行環境中留下狀態。軌跡感知評估能保留執行證據、狀態標籤與失敗證據，讓使用者與稽核者可以檢視智能體如何達成答案。若缺少這種評估，潛在的安全邊界違規與流程品質問題將難以被發現，進而增加部署風險。

**Q4：ClawProBench 的兩個測試軌道各是什麼，彼此如何互補？**

A：第一個軌道是包含 102 個主動情境的完整設定檔，其中有 66 個工作空間即時任務與 36 個針對 OpenClaw 原生執行環境表面的任務。第二個軌道是凍結真實保留集，包含 68 個工作場景風格的封閉世界 JSON 情境，具有固定的情境識別、終態契約與檢查器介面。前者提供廣泛的執行環境覆蓋度與原生路由診斷，後者則提供可重複試驗可靠性與固定契約跨執行環境比較的穩定基礎。

**Q5：ClawProBench 的安全閘控計分公式包含哪些維度？**

A：該公式從執行軌跡中結合正確性、流程品質與效率三個維度進行評分，並加入安全閘控與執行狀態語意。流程分數是有上限的，安全違規則會依嚴重程度被閘控機制懲罰。這種設計讓評分不只看最終答案是否正確，也能反映智能體在執行過程中是否遵守安全邊界與流程規範。

**Q6：為什麼 ClawProBench 要設計一個凍結的封閉世界 JSON 輸出契約保留集？**

A：凍結保留集透過穩定標籤固定情境識別、終態契約與檢查器介面，使多次試驗之間的變異降到最低。封閉世界 JSON 輸出契約讓輸出範圍明確且易於驗證，從而支援嚴格三次試驗通過等可靠性指標。同時，這個可攜式契約能在 OpenClaw、IronClaw 與 NanoClaw 等不同執行環境上重複執行，實現固定契約跨執行環境比較。

**Q7：完整設定檔涵蓋了哪些原生執行環境表面？**

A：完整設定檔包含八個 OpenClaw 原生執行環境表面：技能、瀏覽器、記憶、訊息傳送、工作階段、目錄、Cron 與智能體委派。這些表面用於測試智能體的原生路由能力，也就是能否在執行環境中選擇並正確使用正確的功能介面。相較之下，凍結保留集則聚焦於可跨執行環境移植的工作空間風格任務。

**Q8：ClawProBench 的主要實證發現有哪些？**

A：在完整設定檔上，最高的安全閘控平均軌跡分數為 0.7671，顯示目前仍未達飽和。原生執行環境任務的平均分數僅 0.5238，明顯低於工作空間即時任務的 0.6415，反映出原生表面弱點。在凍結保留集上，pass@k-any 達到 0.6638，但嚴格三次試驗通過率只有 0.2890，顯示智能體的重複試驗可靠性仍有很大落差。

**Q9：不同計分視角對排行榜排名有何影響？**

A：研究發現，僅基於正確性的排名與流程感知、安全閘控及嚴格通過視角的排名有顯著差異。此外，完整設定檔與凍結保留集的排名之間斯皮爾曼相關係數僅為 0.1300，顯示兩軌道的對齊程度很低。這些結果說明計分語意與分母設計會強烈影響排名，也凸顯單一最終答案排行榜的不足。

**Q10：ClawProBench 在產品開發中可以如何實際應用？**

A：開發團隊可以用它來評估不同宣告式智能體配置在工作空間與原生表面上的綜合表現。軌跡感知報告能夠定位失敗發生在證據取得、原生路由、安全邊界或效率哪個環節。這有助於在部署前進行迴歸測試、偵錯與核准邊界驗證，降低上線後的營運風險。

**Q11：適應契約對不同執行環境的產品化有何意義？**

A：適應契約明確定義了表面註冊、軌跡事件、後置條件、檢查器與列來源等介面，使 IronClaw 或 NanoClaw 等執行環境也能實作相同的工作空間保留集。它並不預設各環境的工具完全相同，而是要求將工作空間狀態、執行證據與證據後設資料對應到共同契約。這讓評測契約既具有可適應性，又能維持固定契約跨執行環境比較的公平性。

**Q12：ClawProBench 可能對人工智慧智能體的基準測試實務帶來什麼影響？**

A：它將評測焦點從單純的最終答案指標，轉移到可稽核的模型—執行環境—軌跡系統。透過揭露原生表面弱點與一次性成功，它有助於減少針對答案排行榜的過度擬合。長期而言，這種狀態保留、軌跡導向的評估方式可能成為評估生產級智能體的常規標準。

**Q13：作者承認 ClawProBench 有哪些限制？**

A：作者並未宣稱能消除資料污染或基準洩漏的風險，而是將暴露程度與狀態視為可回報的後設資料。公開任務仍可能在提示、測試框架、工具路由或重試策略層面被過度擬合。此外，論文報告的是特定宣告式配置的表現快照，而非對純模型智慧進行基質無關的宣稱。

**Q14：ClawProBench 能發現哪些最終答案評分會遺漏的失敗案例？**

A：它能發現智能體使用錯誤原生表面、跳過必要證據、違反核准邊界、無意義地反覆重試，以及未留下可檢視執行軌跡等問題。這些軌跡局部失效模式有時仍會產生正確的最終答案，因此傳統評分無法偵測。安全閘控計分與流程品質指標則能將這些隱藏風險浮現出來。

**Q15：ClawProBench 暗示了哪些未來研究方向？**

A：未來可擴展至更多執行環境表面與多日多智能體協作的工作流程，並納入更細緻的嚴重程度安全閘控模型。同時可強化污染暴露追蹤與情境退休機制，並研究如何提升完整設定檔與凍結保留集排名之間的對齊度。此外，將人類參與的稽核流程與軌跡證據進一步整合，也是值得探索的方向。

## 實務應用指南

### 適用場景

1. **企業智能體選型與採購驗收**  
   當組織要評估不同語言模型或智能體框架時，可用 ClawProBench 的「模型加執行環境配置」作為統一比較單位，避免只看最終答案而忽略執行過程中的證據取得、原生表面路由與安全邊界表現。

2. **原生執行環境開發驗證**  
   若團隊正在開發或維護類似 OpenClaw 的即時智能體執行環境，可透過 102 情境完整設定檔中的 36 個原生執行環境表面任務，系統性檢視瀏覽器、記憶、訊息傳送、排程、技能、子智能體、目錄與 Cron 等表面的穩定性。

3. **安全與合規稽核**  
   金融、醫療或高度監管產業可將安全閘控計分流程嵌入日常評測，透過執行軌跡與狀態標籤確認智能體是否越過核准邊界，並保留失敗證據供內部或外部稽核。

4. **CI/CD 中的回歸測試**  
   將凍結保留集的 68 個工作場景風格情境納入持續整合管線，每次更新模型、工具註冊或重試策略時，以固定契約驗證是否造成效能衰退或可靠性下降。

5. **多執行環境適配驗證**  
   若產品需同時支援 OpenClaw、IronClaw、NanoClaw 等多種執行環境，可利用封閉世界 JSON 輸出契約進行固定契約跨執行環境比較，確保不同後端對使用者承諾一致。

### 實作前置條件

**資料準備**
- 取得 ClawProBench 的基準測試定義、計分程式碼、情境清單與去識別化軌跡。
- 若使用自有情境，需設計工作場景風格任務，並為每個情境定義封閉世界 JSON 輸出契約、終態契約與檢查器介面。
- 準備版本控制與發布雜湊紀錄，以便追蹤曝光與退休狀態。

**運算資源**
- 可部署即時執行環境（如 OpenClaw）的運算節點。
- 能重複執行三次試驗以上的批次運算資源。
- 軌跡儲存空間，並支援雜湊驗證與去識別化處理。

**技能需求**
- 熟悉語言模型智能體架構、工具呼叫與執行環境路由。
- 理解執行環境表面（瀏覽、記憶、訊息、排程、技能、子智能體等）的運作方式。
- 具備評測指標設計、安全閘控計分、可稽核報告與版本控制經驗。

### 實作步驟建議

1. **宣告模型加執行環境配置**  
   明確記錄模型版本、執行環境版本、工具註冊表、重試策略與安全邊界設定，作為評測的最小單位。

2. **部署即時執行環境與軌跡擷取**  
   安裝 OpenClaw 或相容執行環境，確保所有原生表面事件都能被記錄為執行軌跡，並輸出標準化的狀態標籤。

3. **選擇評測軌道**  
   - 使用 **102 情境完整設定檔** 進行全面診斷，覆蓋工作空間即時任務與原生執行環境表面。  
   - 使用 **68 情境凍結保留集** 進行固定契約排名與跨版本比較。

4. **執行三次試驗並收集軌跡證據**  
   對每個情境執行三次，記錄執行軌跡、檢查器細節、狀態回報與任何安全邊界觸發事件。

5. **套用安全閘控計分公式**  
   結合正確性、流程品質與效率進行評分，並讓安全閘控影響最終分數；同時保留失敗證據供後續分析。

6. **產生狀態報告與發布雜湊**  
   為每次評測產生包含分數、狀態標籤與軌跡雜湊的報告，確保結果可重現、可稽核。

7. **依診斷切片迭代改進**  
   針對原生表面弱點、工作空間證據處理、安全邊界違規與重複試驗可靠性等切片定位問題並優化。

8. **整合進產品發版流程**  
   將凍結保留集納入 CI/CD 與發版閘道，作為回歸測試、排行榜更新與採購驗收的依據。

### 潛在風險與注意事項

- **只看最終答案會隱藏弱點**  
  最終答案正確不代表智能體可靠，可能掩蓋原生表面弱點、一次性成功或流程品質問題。應同時檢視軌跡分數與嚴格三次試驗通過率。

- **指標選擇影響結論**  
  pass@k-any 與 strict three-trial pass 可能差異極大，避免用單一指標宣稱可靠性；建議同時報告兩者並說明語意。

- **安全閘控不可關閉**  
  若未將安全情境納入計分，可能誤把越過核准邊界的行為視為正確。安全閘控計分公式應為預設流程。

- **執行環境變動會破壞凍結契約**  
  工具註冊、表面實作或執行環境版本更新都可能改變情境行為。需固定穩定標籤與發布雜湊，並在變更時重新校準。

- **軌跡涉及敏感資料**  
  執行軌跡可能包含使用者資料或內部系統狀態，必須進行去識別化處理並設定存取控管。

- **跨執行環境比較需對齊契約**  
  不同執行環境的原生表面實作可能不同，應透過可攜式契約對齊狀態、事件與檢查器介面，避免不公平比較。

- **過度擬合凍結保留集**  
  長期使用同一組凍結保留集可能導致過度擬合。應建立曝光標籤、輪換與退休機制，並搭配完整設定檔進行廣泛評測。

### 與其他技術的整合建議

- **CI/CD 管線**  
  在 GitHub Actions、GitLab CI 或 Jenkins 中設定凍結保留集的自動化評測任務，於每次合併或發版前執行三次試驗並檢查嚴格通過率。

- **MLOps / 實驗追蹤**  
  使用 MLflow、Weights & Biases 或類似工具記錄模型加執行環境配置、軌跡雜湊、分數與狀態標籤，建立可追溯的實驗紀錄。

- **可觀測性平台**  
  透過 OpenTelemetry 或類似框架匯出執行軌跡事件，讓維運團隊能即時監控智能體在生產環境中的表面使用與異常狀態。

- **LLM 閘道與代理層**  
  搭配 LiteLLM、Langfuse 等閘道統一模型路由，並記錄所有工具呼叫與重試行為，補強軌跡證據的完整性。

- **安全與合規系統**  
  將安全閘控結果輸出為 SARIF 或 OPA 可讀格式，整合進現有合規稽核流程與漏洞管理系統。

- **瀏覽器自動化與 API 測試**  
  針對瀏覽器表面可結合 Playwright 或 Selenium；針對技能與 API 使用可結合 MCP-Bench 或自有 API 測試框架，形成更完整的工具使用評測。
