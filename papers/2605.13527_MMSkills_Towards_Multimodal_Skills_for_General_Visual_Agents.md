## ⚡ TL;DR

現有技能套件多為純文字或程式碼，無法滿足視覺智能體在執行階段辨識狀態與解讀視覺證據的需求。
提出 MMSkills 框架，以軌跡生成器與分支載入機制自動建構並應用多模態技能套件。
在 GUI 與遊戲視覺智能體基準測試中，MMSkills 顯著提升前沿與小型多模態模型的表現。

## 摘要翻譯

可複用技能（Reusable Skills）已成為提升智能體能力的核心基底，然而大多數現有的技能套件（Skill Packages）主要將可複用行為編碼為文字提示（Textual Prompts）、可執行程式碼（Executable Code）或學習到的常規（Learned Routines）。然而，對於視覺智能體（Visual Agents）而言，程序性知識（Procedural Knowledge）本質上即為多模態：複用不僅取決於要執行什麼操作，還取決於辨識相關狀態、詮釋有關進度或失敗的視覺證據（Visual Evidence），以及決定下一步該做什麼。我們將此需求形式化為多模態程序性知識（Multimodal Procedural Knowledge），並解決三項實務挑戰：（I）多模態技能套件（Multimodal Skill Package）應包含什麼；（II）此類套件可從公開互動經驗（Public Interaction Experience）中的何處衍生；以及（III）智能體如何在推論階段（Inference Time）參酌多模態證據，同時避免過多的圖像上下文（Image Context）或對參考截圖（Reference Screenshots）的過度錨定（Over-Anchoring）。我們提出 MMSkills，一個用於表徵、生成及使用可複用多模態程序以進行執行階段視覺決策（Runtime Visual Decision Making）的框架。每個 MMSkill 都是一個精簡的狀態條件式（State-Conditioned）套件，結合了文字程序、執行階段狀態卡片（Runtime State Cards）與多視角關鍵幀（Multi-View Keyframes）。為了建構這些套件，我們開發了一個智能體式的（Agentic）軌跡到技能生成器（Trajectory-to-Skill Generator），透過工作流程分群（Workflow Grouping）、程序歸納（Procedure Induction）、視覺基礎對應（Visual Grounding）以及元技能引導稽核（Meta-Skill-Guided Auditing），將公開的非評估軌跡（Non-Evaluation Trajectories）轉換為可複用的多模態技能。為了使用這些套件，我們提出了一個分支載入式多模態技能智能體（Branch-Loaded Multimodal Skill Agent）：選定的狀態卡片（State Cards）與關鍵幀將於臨時分支（Temporary Branch）中接受檢視，與即時環境（Live Environment）對齊，並提煉為主智能體（Main Agent）的結構化引導（Structured Guidance）。橫跨圖形使用者介面（GUI）與基於遊戲的視覺智能體基準測試（Game-Based Visual-Agent Benchmarks）的實驗顯示，MMSkills 能穩定提升前沿智能體（Frontier Agents）與較小型的多模態智能體，意味著外部的多模態程序性知識能補充模型內部先驗知識（Model-Internal Priors）。

### 核心貢獻（3～5點）
- 形式化「多模態程序性知識（Multimodal Procedural Knowledge）」概念，並從「內容、來源、使用方式」三個維度界定視覺智能體在複用技能時的實務挑戰。
- 提出 MMSkills 框架，以精簡的狀態條件式（State-Conditioned）技能套件結合文字程序、執行階段狀態卡片（Runtime State Cards）與多視角關鍵幀（Multi-View Keyframes），表徵可複用的多模態程序。
- 開發智能體式的（Agentic）軌跡到技能生成器（Trajectory-to-Skill Generator），透過工作流程分群、程序歸納與視覺基礎對應，將公開的非評估軌跡（Non-Evaluation Trajectories）自動轉換為可複用的多模態技能。
- 設計分支載入式多模態技能智能體（Branch-Loaded Multimodal Skill Agent），在推論階段（Inference Time）透過臨時分支（Temporary Branch）檢視狀態卡片與關鍵幀，並將其對齊即時環境（Live Environment）後提煉為結構化引導（Structured Guidance），避免過度錨定（Over-Anchoring）於參考截圖。
- 在圖形使用者介面（GUI）與基於遊戲的視覺智能體基準測試（Game-Based Visual-Agent Benchmarks）上驗證，證實外部多模態程序性知識能有效補充模型內部先驗知識（Model-Internal Priors），並同時提升前沿智能體（Frontier Agents）與較小型多模態智能體的表現。

### 適合對象
從事多模態大型語言模型、視覺智能體（Visual Agents）、自動化圖形使用者介面（GUI）操作與遊戲智能體研究的研究者與工程師；特別適合關注技能學習、程序歸納（Procedure Induction）、視覺基礎對應（Visual Grounding）與推論階段外部知識引入等議題的讀者。

## 深度分析

#### 方法論解析

本文提出 MMSkills 框架，核心貢獻在於將「可複用技能（Reusable Skills）」從純文字或程式碼層次的抽象，提升為**多模態程序性知識（Multimodal Procedural Knowledge）**。這不僅是技術實作的改進，更代表了對視覺智能體（Visual Agents）決策本質的重新理解：程序性知識的重用不僅取決於「執行什麼操作」，更取決於「如何透過視覺證據（Visual Evidence）辨識相關狀態、判斷進度或失敗、並決定下一步」。

**多模態技能套件（Multimodal Skill Package）的結構設計**
單一 MMSkill 並非文字指令附加示意圖，而是一個緊湊的、**狀態條件式（State-Conditioned）** 的決策單元，包含三個互相綁定的元件：
1. **文字程序（Textual Procedure，Skill.md）**：描述可複用的動作模式，例如「在目標工作表建立指定標題與類型的圖表」。這提供高層次的語意錨點。
2. **執行階段狀態卡片（Runtime State Cards，State_cards.json）**：這是 MMSkills 最具區別性的設計。每張狀態卡片（State Card）編碼了**何時使用（when-to-use）**與**何時不使用（when-not-to-use）**的條件、關鍵的視覺線索（Visual Cues）、驗證線索（Verification Cue）以及可用的觀察視角（Available Views）。例如，在圖表建立任務中，狀態卡片會區分「尚未選取正確儲存格範圍」、「已插入但位於錯誤工作表」、「完成且可見於目標工作表」等決策邊界。這將被動的指令轉化為主動的狀態相關決策（State-Dependent Decisions）。
3. **多視角關鍵幀（Multi-View Keyframes）**：為關鍵狀態提供視覺基礎對應（Visual Grounding）。包含**完整畫面（Full Frame）**以提供全域脈絡、**聚焦裁切（Focus Crop）**以突顯局部介面元素，以及可選的前後對比幀。這種多視角設計解決了單一截圖的歧義性，使智能體能對齊（Align）即時環境（Live Environment）與參考狀態。

**軌跡到技能生成器（Trajectory-to-Skill Generator）**
為了從公開互動經驗（Public Interaction Experience）中自動建構上述套件，作者設計了一個**智能體式的（Agentic）**生成管線，處理非評估軌跡（Non-Evaluation Trajectories）。此生成器面臨的挑戰遠比傳統文字技能擷取複雜：它不只要壓縮動作序列，還必須識別可複用的視覺狀態、選取診斷性影格，並將視覺線索綁定到決策規則。管線包含四個階段：
- **工作流程分群（Workflow Grouping）**：將相關的互動軌跡分群，找出潛在的可複用程序。
- **程序歸納（Procedure Induction）**：從分群後的軌跡中歸納出候選文字程序。
- **視覺基礎對應（Visual Grounding）**：將候選程序對應到真實軌跡影格，識別關鍵狀態的視覺特徵。
- **元技能引導稽核（Meta-Skill-Guided Auditing）**：利用預先定義的元技能（Meta-Skill）作為「技能工廠」的品質管控機制，自動審查產出的多模態技能套件是否完整、一致且可重用。這種自我參照式的設計（用技能來製造技能）提升了擴展性。

**分支載入式多模態技能智能體（Branch-Loaded Multimodal Skill Agent）**
在推論階段（Inference Time），直接將整個技能套件（含多張狀態卡片與截圖）塞入主智能體（Main Agent）的上下文，會造成嚴重的圖像上下文（Image Context）壓力，並導致**過度錨定（Over-Anchoring）**—即智能體過度依賴參考截圖（Reference Screenshots）而忽略即時環境的差異。為此，作者提出**分支載入（Branch Loading）**機制：
當主智能體考慮調用某技能時，會開啟一個**臨時分支（Temporary Branch）**。該分支僅載入必要的狀態卡片與關鍵幀，將其與即時畫面進行對齊與比對，執行適用性判斷（Applicability Judgment）。隨後，分支將多模態證據蒸餾為精簡的**結構化引導（Structured Guidance）**—包含適用性結論、子目標（Subgoal）與下一步計畫—回傳給主軌跡。主智能體接收的是決策支援而非原始技能包，這是一種針對多模態證據的漸進式揭露（Progressive Disclosure）策略，有效避免了視覺干擾與上下文爆炸。

#### 實驗數據解讀

根據摘要與引言所述，實驗橫跨圖形使用者介面（GUI）與基於遊戲的視覺智能體基準測試（Game-Based Visual-Agent Benchmarks），包括 OSWorld、macOS-World、Visual Agent Bench 中的 VAB-Minecraft，以及 LMGameBench 中的 Super-Mario。評估對象涵蓋**前沿智能體（Frontier Agents）**與較小型的多模態模型。

**核心發現的詮釋**
實驗結果顯示，相較於「無技能（No-Skill）」與「純文字技能（Text-Only Skills）」基線，MMSkills 能持續提升各類模型的表現。這一趨勢具有三層意義：

1. **驗證多模態程序性知識的必要性**：純文字技能雖能描述操作步驟，但在視覺任務中往往過於冗長卻又規格不足（Verbose yet Underspecified）。MMSkills 的增益證明，對於視覺智能體而言，僅有文字程序不足以支撐準確的狀態辨識與驗證；必須將視覺線索與決策規則顯式編碼，才能彌補語言抽象化的落差。

2. **外部知識對模型內部先驗（Model-Internal Priors）的互補性**：無論是前沿大型模型或較小模型，MMSkills 均帶來改善，這說明視覺決策的瓶頸不僅在於模型參數量或預訓練資料規模，更在於缺乏結構化的外部視覺程序記憶。MMSkills 作為外部多模態程序知識庫，有效補充了模型內部先驗知識的不足，尤其在需要精確視覺對應的步驟上。

3. **跨領域的泛化性**：GUI 任務（如 OSWorld、macOS-World）要求精確的介面元件識別與順序操作，屬於審議式（Deliberative）控制；而遊戲任務（如 Minecraft、Super-Mario）則涉及動態環境中的即時反應與進度追蹤，屬於反應式（Reactive）控制。MMSkills 在兩類環境中皆有效，暗示**狀態卡片（State Cards）**的設計具有足夠的通用性，能同時支援「精確程序遵循」與「視覺狀態驗證」兩種決策邏輯。

雖然摘要未提供具體數值，但「持續改善（Consistently Improve）」的表述在智能體研究中具有高度訊號性——這意味著該框架並非僅在特定模型或任務上過擬合，而是具備穩健的跨模型、跨領域效益。

#### 與現有研究的比較

**相較於文字與程式碼中心的技能表示**
現有技能系統（如 Wang et al., 2023a; Zheng et al., 2025; Chen et al., 2026 等）大多將可複用行為編碼為文字提示（Textual Prompts）、可執行程式碼（Executable Code）、執行圖（Execution Graphs）或學習到的常規（Learned Routines）。這些方法共享一個基本假設：相關狀態可以被語言充分抽象化。然而，對於視覺智能體，此假設往往不成立。MMSkills 突破了這一限制，主張程序性知識本質上是多模態的，並透過狀態條件式套件將動作、視覺證據與驗證邏輯綁定為單一可重用單元。

**相較於示範（Demonstrations）與軌跡回放**
原始示範保留了視覺脈絡，但通常是特定實例的（Instance-Specific）、冗長且難以適應新情境。MMSkills 的生成器從公開互動經驗中提煉出緊湊的技能套件，而非儲存原始軌跡。這類似於從「範例」升級為「規則」，既保留了視覺決策的關鍵證據，又具備跨任務的抽象與重用能力。

**相較於既有技能擷取管線**
近期研究（如 Zheng et al., 2025; Wang et al., 2026a; Alzubi et al., 2026 等）已能將成功軌跡、失敗分析或累積痕跡壓縮為可重用的文字指令或動作抽象。然而，這些管線無需處理視覺狀態識別與診斷影格選取的問題。MMSkills 的生成器額外引入了視覺基礎對應與元技能引導稽核，使產出的技能不再是「文字摘要」，而是「多模態決策包」。這在自動化程度上邁出了一大步，因為它將視覺證據的選擇與綁定也納入了自動化流程。

**相較於直接的技能檢索與注入**
現有技能智能體通常將檢索到的技能直接插入主互動上下文。MMSkills 指出這種做法對多模態技能尤其危險：多張參考截圖會與即時觀察競爭注意力，並造成過度錨定。**分支載入（Branch Loading）**可視為一種新型的技能諮詢架構，它將技能使用從「上下文檢索」重新定義為「分支對齊與蒸餾」，這與 Xu and Yan (2026) 提出的漸進式揭露概念在多模態語境下形成了具體的技術實現。

**局限性**
儘管方法新穎，仍有一些潛在限制。首先，技能品質高度依賴公開軌跡資料的分佈與品質；對於長尾（Long-Tail）任務，若公開互動經驗稀少，則難以生成有效技能。其次，生成管線包含多個複雜階段（分群、歸納、對應、稽核），其錯誤可能會在管線中傳播，而元技能稽核雖能緩解但無法完全消除。第三，分支載入在推論階段引入了額外的對齊與蒸餾計算，可能增加延遲與 API 呼叫成本，對於需要高頻反應的即時遊戲場景，其效率仍有優化空間。

#### 可重現性評估

**資料集與評估環境的可取得性**
本文使用的評估基準—OSWorld、macOS-World、VAB-Minecraft、LMGameBench—均為已發表的公開資料集，這為獨立驗證提供了堅實基礎。此外，技能生成所使用的來源為**公開互動經驗（Public Interaction Experience）**或**非評估軌跡（Non-Evaluation Trajectories）**，若這些軌跡同樣來自公開資料集（例如網路上的操作示範、開放的智能體互動紀錄），則資料層面的可重現性較高。

**方法論透明度**
從引言與摘要來看，MMSkills 的架構描述相當詳盡：多模態技能套件的三元結構、生成器的四階段管線、以及分支載入的推論機制均有清楚定義。狀態卡片（State Cards）的欄位設計（如 state_id、when_to_use、verification_cue、available_views）與多視角關鍵幀的類型（Full Frame、Focus Crop）也具體明確，這有助於研究者依據描述進行復現。

**開源程式碼與權重的可得性**
然而，在提供的文本脈絡中，作者並未明確提及是否釋出原始碼、預先生成的技能庫，或是用於元技能稽核的提示模板（Prompt Templates）。軌跡到技能生成器涉及複雜的智能體式流程（Agentic Pipeline），包括視覺基礎對應的實作細節、分支載入中的對齊演算法（Alignment Algorithm），以及結構化引導的蒸餾邏輯，這些都高度依賴具體的實作與超參數設定。在缺乏官方開源實作的情況下，其他研究者雖能依據論文描述重建原型，但要達到完全一致的實驗結果仍有顯著難度。

**整體評估**
MMSkills 的可重現性處於「概念清晰、實作待確認」的狀態。公開基準的使用與明確的模組化設計是重大優勢；然而，生成器與分支載入機制的複雜性意味著，若無後續的程式碼與技能庫釋出，社群的獨立驗證將面臨不小的工程門檻。

#### 未來研究方向

**1. 動態與線上技能演化**
目前的框架似乎主要從離線的公開軌跡中批次生成技能。未來可探索**線上技能更新（Online Skill Updating）**機制：讓智能體在部署過程中遭遇失敗或新情境時，即時修正狀態卡片中的視覺線索、增補新的關鍵幀，甚至生成新的驗證規則。這將使 MMSkills 從靜態知識庫轉變為持續學習的視覺程序記憶系統。

**2. 跨領域與跨模態的技能遷移**
當前實驗涵蓋 GUI 與遊戲兩大領域，但未探討技能在兩者之間的遷移。未來研究可致力於領域無關（Domain-Agnostic）的狀態卡片抽象，例如將「確認物件已選取」或「驗證視窗已開啟」等程序性概念提升為更高層次的表示，從而實現跨平台（Web、Desktop、Mobile、VR）的技能轉移。此外，可將框架擴展至包含音訊或觸覺回饋，邁向更全面的多模態程序性知識。

**3. 層級式與組合式技能推理**
複雜任務往往需要多個 MMSkills 的序列或階層式組合。未來可發展**技能組合語言（Skill Composition Language）**，明確定義技能之間的依賴關係、前置條件與後置條件，並讓分支載入機制支援多層級的臨時分支（例如子技能分支嵌套），以處理更長程的視覺決策規劃。

**4. 以人為本的技能精煉與協作生成**
雖然生成器已能自動化產出技能，但人類專家對於狀態邊界的判斷仍可能更精準。引入**人機協作（Human-in-the-Loop）**機制，允許使用者透過自然語言回饋修正狀態卡片的 when_to_use 條件，或在關鍵幀上標註注意力區域，可顯著提升技能品質，並降低對大規模公開軌跡的依賴。

**5. 從關鍵幀到動態視覺證據**
目前的視覺證據以靜態多視角關鍵幀為主。對於高度動態的環境（如即時戰略遊戲或影片編輯軟體），單一影格可能不足以捕捉狀態轉換。未來可將關鍵幀擴展為**短片段關鍵影格序列（Keyframe Clips）**或**動態驗證規則**，利用時序視覺資訊進行更穩健的狀態確認。

**6. 效率優化與輕量化分支載入**
分支載入雖解決了上下文壓力，但推論階段的額外分支對齊與蒸餾可能帶來延遲與成本。未來可研究專用的輕量對齊模型（如小型視覺語言模型專門負責狀態卡片比對），或開發**快取式分支（Cached Branch）**機制，對常見的即時環境狀態直接匹配預先計算的引導，以降低對 frontier 模型的重複查詢。

## 論文問答

**Q1：現有視覺智能體在可複用技能上面臨的核心問題是什麼？**
A：現有技能套件大多將可複用行為編碼為文字提示、可執行程式碼或學習到的常規，這種設計假設相關狀態能夠僅透過語言充分抽象化。然而，對於視覺智能體而言，程序性知識本質上是多模態的，因為重複使用不僅取決於執行什麼操作，還取決於如何辨識相關狀態、解讀進度或失敗的視覺證據，以及決定下一步行動。因此，純文字技能往往變得冗長卻仍規格不足，而原始示範雖保留了視覺上下文，卻過於冗長且難以適應不同實例，這凸顯了建立多模態程序性知識的必要性。

**Q2：為何純文字技能與原始示範軌跡無法滿足通用視覺智能體的需求？**
A：純文字技能在描述視覺狀態時容易變得過於繁瑣，卻仍無法精確指定何時應該或根本不應該應用某個程序，導致智能體可能知道正確操作卻無法辨識對話方塊尚未就緒等關鍵狀態。另一方面，原始示範雖然保留了完整的視覺上下文，但這些軌跡通常是特定實例的、長度過長且難以調整重用。MMSkills 正是為了彌補這兩種極端之間的落差，提出一種緊湊且狀態條件式的多模態技能套件，使視覺智能體能夠根據視覺證據做出狀態相關決策。

**Q3：多模態程序性知識對於視覺智能體為何至關重要？**
A：多模態程序性知識將操作程序與視覺證據及狀態相關決策綁定在一起，這與人類程序性學習中視覺資訊能夠補充言語解釋的現象一致。舉例來說，桌面智能體可能需要透過視覺線索來判斷某個工作表是否為作用中狀態，而遊戲智能體則需要區分任務進行中與真正完成的視覺差異。若缺乏這種知識，智能體僅能依賴模型內部先驗知識，容易在面對細微但關鍵的視覺狀態變化時做出錯誤判斷。

**Q4：MMSkills 框架的核心方法包含哪三個主要部分，各自解決什麼問題？**
A：MMSkills 框架圍繞「表示」、「生成」與「利用」三個層面展開，分別對應論文提出的三大實務挑戰。在表示層面，每個多模態技能套件都是一個緊湊的狀態條件式套件，結合了文字程序、執行階段狀態卡片與多視角關鍵幀，以定義何時使用、何時不使用以及驗證線索。在生成層面，軌跡到技能生成器透過工作流程分群、程序歸納、視覺基礎對應與元技能引導稽核，將公開互動經驗轉化為可複用知識；在利用層面，分支載入式多模態技能智能體透過臨時分支檢視與對齊視覺證據，避免主智能體在推論階段承受過多圖像上下文。

**Q5：什麼是「分支載入」（branch loading），它為何是 MMSkills 的關鍵創新？**
A：分支載入是一種多模態形式的漸進式揭露機制，當主智能體考慮使用某項技能時，會開啟一個臨時分支來載入所需的狀態卡片與關鍵幀視圖。該分支會將技能中的參考截圖與即時環境進行對齊，並將完整的技能套件蒸餾為包含適用性判斷、子目標與下一步計畫的結構化引導，再回傳給主智能體。這種設計有效避免了直接將大量圖像插入主軌跡所造成的上下文壓力，同時防止主智能體過度錨定到表面上相似但實際不同的參考截圖。

**Q6：MMSkills 為何選擇以「狀態卡片」搭配「多視角關鍵幀」，而非僅附加參考截圖到文字指令？**
A：狀態卡片以結構化方式編碼了何時使用或不使用技能的條件、重要視覺線索以及驗證線索，使技能具備明確的狀態條件式決策邊界。多視角關鍵幀則透過完整畫面、聚焦裁切以及必要的前後對比視圖，為關鍵狀態提供視覺基礎對應，讓智能體能夠比對即時環境。這種組合使得 MMSkill 不是「附帶插圖的文字指令」，而是一個能夠根據視覺證據指導智能體決定遵循、跳過或驗證程序的獨立可複用單元。

**Q7：實驗選用了哪些基準測試來評估 MMSkills，涵蓋哪些類型的視覺智能體任務？**
A：實驗橫跨圖形使用者介面（GUI）與基於遊戲的視覺智能體基準測試，具體包含 OSWorld、macOSWorld、Visual Agent Bench 中的 VAB-Minecraft，以及 LMGameBench 中的 Super-Mario。這些環境涵蓋了桌面應用程式操作與開放式遊戲場景，要求智能體具備多樣化的執行階段視覺決策能力。選擇這些基準有助於驗證 MMSkills 在不同視覺複雜度與互動邏輯下的通用性與穩健性。

**Q8：MMSkills 的主要實驗結果呈現了什麼趨勢？**
A：實驗結果顯示，無論是前沿的大型多模態模型還是較小的模型，在導入 MMSkills 後其表現都持續優於無技能以及純文字技能的對照條件。這項發現表明，外部的多模態程序性知識能夠有效補充模型內部先驗知識，而非僅僅是多餘的附加資訊。整體而言，具備視覺證據與狀態條件式引導的技能套件，顯著提升了視覺智能體在實際執行任務時的準確度與穩定性。

**Q9：相較於純文字技能，MMSkills 在具體任務中展現了什麼決定性優勢？**
A：以圖表建立任務為例，純文字指引可能因為遺漏了「作用中工作表」這一關鍵視覺狀態，導致智能體將圖表建立在錯誤的 Sheet1 而非目標的 Sheet2 上。相對地，透過分支載入式多模態技能智能體，MMSkills 能夠對齊技能證據與即時畫面，並回傳具備狀態覺察的指引，例如先切換至 Sheet2 再插入圖表並驗證。這證明了僅有文字程序而缺乏視覺狀態辨識與驗證線索時，智能體難以在複雜 GUI 環境中正確完成多步驟操作。

**Q10：MMSkills 在哪些實務應用場景中最能發揮價值？**
A：MMSkills 特別適用於需要精確辨識介面狀態的桌面自動化場景，例如當智能體必須判斷對話方塊是否載入完成、按鈕是否可點擊，或確認檔案是否已成功儲存。在遊戲領域中，它也能幫助智能體透過視覺線索區分子目標進度與最終完成狀態，避免過早終止或重複執行動作。任何依賴動態視覺回饋進行決策的通用視覺智能體，都能透過這種可複用的多模態技能套件降低錯誤率並提升執行效率。

**Q11：若要在生產環境中部署 MMSkills，需要考量哪些實務因素？**
A：首先，組織需要建立自動化管道，從公開互動經驗或非評估軌跡中持續生成與更新技能套件，以確保技能庫的覆蓋率與時效性。其次，雖然分支載入會增加額外的推論步驟來對齊與蒸餾視覺證據，但它避免了將大量參考截圖直接塞入主智能體的上下文，從而在記憶體與注意力機制上取得平衡。最後，必須透過元技能引導稽核機制定期審查技能品質，防止過時或錯誤的狀態卡片與關鍵幀影響智能體的決策正確性。

**Q12：MMSkills 可能對視覺智能體研究領域帶來什麼深遠影響？**
A：MMSkills 推動了技能表示典範從純文字或程式碼中心，轉向本質上即為多模態的設計，強調視覺證據在程序性知識中的核心地位。它證明了外部視覺程序性知識不僅能補充模型內部先驗，更能透過檢索與組合機制擴展智能體的能力邊界，而無需重新訓練基礎模型。這為未來建構大規模、可共享的多模態技能庫奠定了基礎，使不同視覺智能體能夠在面對新環境時快速繼承並應用人類或自動化累積的操作經驗。

**Q13：MMSkills 在資料來源與生成流程上存在哪些潛在限制？**
A：由於技能套件是從公開互動經驗與非評估軌跡中自動生成，其品質與多樣性高度依賴原始資料的覆蓋範圍與正確性，若公開軌跡缺乏特定邊界案例或失敗恢復策略，技能庫便會出現結構性缺口。此外，軌跡到技能生成器必須在大量雜訊中辨識出可複用的工作流程，並進行視覺基礎對應與程序歸納，這個過程本身仍具挑戰性，可能產生過度概括或過度特定的候選技能。這也意味著在資料稀疏或領域差異大的環境中，生成器的自動化稽核與過濾機制將面臨更大壓力。

**Q14：在什麼情況下 MMSkills 可能失效或表現不佳？**
A：當即時環境的視覺外觀與技能套件中的參考關鍵幀存在顯著差異時，例如軟體介面經過重大改版或遊戲場景光照與視角劇變，對齊機制可能失敗並導致錯誤的適用性判斷。如果智能體遭遇的狀態完全未被任何現有狀態卡片覆蓋，則缺乏相應的視覺線索與決策規則來引導下一步行動。此外，若主智能體過度依賴檢索到的技能而未能靈活處理新穎情境，仍可能在動態變化的視覺環境中做出不當決策。

**Q15：基於 MMSkills 的架構，未來研究可以朝哪些方向延伸？**
A：未來研究可探索如何將多個 MMSkills 進行動態組合，以處理需要長期規劃與複雜子目標分解的多步驟任務，而不僅是單一程序的重複使用。另一個方向是強化視覺基礎對應技術，使其能夠處理三維環境、動態影片串流或更細微的介面元素變化。此外，開發能夠在執行階段自主更新元技能、並根據主智能體的即時回饋自動稽核與修正技能庫的自我改進機制，將進一步提升整體系統在開放世界中的自主能力與持續學習潛力。

## 實務應用指南

### 適用場景

1. **企業級 GUI 流程自動化（如財務報表製作、ERP 系統操作）**  
   適用於需要辨識正確視覺狀態（如「對話框尚未就緒」）的場景，避免操作錯誤頁面。MMSkills 的狀態卡片可明確標註何時應等待、何時可點擊，降低傳統純文字腳本因狀態誤判而失敗的機率。

2. **跨應用程式個人數位助理（如桌面作業系統環境）**  
   在 OSWorld、macOS 等場景中執行多步驟任務時，根據即時環境畫面判斷下一步。透過可複用的多模態技能套件（如「開啟檔案」「設定系統偏好」），讓視覺智能體在不同 App 間順暢切換，而不需針對每個介面版本重寫指令。

3. **遊戲自動化測試與教練系統（如 Minecraft、Super Mario）**  
   將公開遊玩軌跡轉換為可複用的多模態程序性知識。利用視覺線索區分「進行中」與「完成」狀態，並透過驗證線索確認子目標是否達成，實現策略的重複使用與自動化驗證。

4. **視覺化軟體 QA 與迴歸測試**  
   利用狀態條件式技能套件自動確認 UI 變更是否符合預期。當介面微調時，多視角關鍵幀與狀態卡片能幫助智能體對齊新舊畫面，降低純文字腳本因元素位移即失效的維護成本。

5. **複雜創作工具輔助（如試算表圖表製作、簡報排版）**  
   重複使用「建立圖表」等多模態技能套件，確保視覺成果正確落在目標區域。透過執行階段狀態卡片判斷「圖表標題是否已輸入」「作用中工作表是否正確」，避免操作成功但結果位置錯誤的問題。

### 實作前置條件

**資料（Data）**
- **公開互動經驗與非評估軌跡**：大量成對的螢幕畫面（Observation）與動作序列（Action），建議涵蓋成功與失敗案例，以供程序歸納與負面條件提取。
- **現有操作手冊或純文字技能庫（選用）**：作為程序歸納的輔助輸入，可加速收斂可複用步驟。

**運算（Compute）**
- **多模態大型語言模型（MLLM）**：用於程序歸納、視覺基礎對應、主智能體推論與元技能引導稽核。需支援多圖像輸入與長上下文。
- **視覺嵌入模型**：用於多視角關鍵幀的相似度比對、狀態對齊與檢索。
- **儲存與檢索基礎設施**：存放結構化的 Skill.md、State_cards.json 與關鍵幀圖像，並支援向量與 Metadata 混合檢索。

**技能先決條件（Skill Prerequisites）**
- 具備建構視覺-語言-動作（VLA）迴路的經驗，能讓智能體接收畫面並輸出操作。
- 資料工程能力：清洗、分群與去識別化公開軌跡。
- 熟悉結構化資料處理：能設計與維護 Skill.md 與 State_cards.json 的 Schema。

---

### 實作步驟建議

1. **軌跡收集與清洗**  
   彙整公開非評估軌跡，移除含有個人識別資訊（PII）的畫面，建立標準化的 (Observation, Action, Timestamp) 資料流。

2. **工作流程分群**  
   依據應用程式領域與任務目標（如「建立圖表」「寄送郵件」）將軌跡分群，分離出可重複出現的操作模式。

3. **程序歸納**  
   從每群軌跡中歸納出文字程序 Skill.md，提取可複用步驟、決策分支與預期結果。

4. **視覺基礎對應與狀態卡片建構**  
   識別關鍵決策狀態，建立 State_cards.json，包含 when_to_use、verification_cue、available_views；並從原始軌跡擷取多視角關鍵幀（完整畫面、聚焦裁切、前後對比）。

5. **元技能引導稽核**  
   部署元技能（Meta-Skills）自動稽核生成的多模態技能套件，檢查狀態條件是否完整、視覺線索是否具診斷性，並補充 when-not-to-use 條件。

6. **分支載入式推論管線開發**  
   建構主智能體，在推論階段當需要查詢技能時開啟臨時分支。分支內載入選定的狀態卡片與關鍵幀，與即時環境畫面進行視覺對齊，產出結構化引導（包含適用性判斷、子目標與下一步計畫）後關閉分支。

7. **持續迭代與產品化**  
   將結構化引導餵入主流水線執行，並建立回饋迴路。根據主智能體在生產環境的成敗紀錄，回流更新狀態卡片與關鍵幀，形成閉環優化。

### 潛在風險與注意事項

1. **過度錨定（Over-Anchoring）**  
   主智能體可能過度依賴參考截圖的表層特徵，忽略即時環境的細微差異。**Mitigation**：嚴格落實分支載入機制，確保參考圖像僅在臨時分支中處理，並強制執行與即時環境的視覺對齊，最終只將蒸餾後的決策傳回主軌跡。

2. **圖像上下文過長（Excessive Image Context）**  
   直接將整個多模態技能套件插入主軌跡會造成上下文爆炸，推論成本飆升。**Mitigation**：在分支內僅載入與當前狀態最相關的狀態卡片與必要視角，並透過結構化引導壓縮資訊。

3. **狀態卡片覆蓋不全**  
   程序歸納若遺漏邊界狀態，智能體會在異常畫面中誤用技能。**Mitigation**：元技能稽核必須包含負面範例（失敗軌跡），明確定義 when-not-to-use 條件，並定期擴充狀態卡片。

4. **公開軌跡的領域偏移**  
   用於生成的公開互動經驗可能與目標任務分佈不同。**Mitigation**：在分群階段加入目標領域的少量標註資料，或建立領域適應層（Domain Adaptation Layer）。

5. **隱私與合規**  
   螢幕截圖極易包含敏感資訊。**Mitigation**：在軌跡收集階段即進行去識別化與敏感區域遮罩，並對關鍵幀進行自動化 PII 檢測。

### 與其他技術的整合建議

1. **與現有 RPA / 低程式碼平台整合**  
   將 MMSkills 作為視覺感知層，補強傳統 RPA 純依賴 DOM 或絕對座標的脆弱性。建議透過 API 將結構化引導餵入現有的自動化腳本引擎，實現「視覺判斷 + 既有執行」的混合架構。

2. **與檢索增強生成（RAG）整合**  
   將多模態技能套件視為知識單元，存入支援多模態嵌入的向量資料庫。檢索時同時比對文字語意與視覺嵌入，實現跨模態技能檢索，讓智能體在執行階段視覺決策前快速召回最相關的狀態條件式程序。

3. **與現有 LLM Agent 框架（如 LangChain、AutoGen）整合**  
   將分支載入設計為獨立的 Tool 或 Agent Node，專責「技能諮詢」，主智能體維持原有的規劃與記憶迴路。此設計可避免改造整體 Agent 架構，僅將 MMSkills 作為具視覺能力的專家模組插入。

4. **與雲端裝置農場（Device Farm）整合**  
   用於大規模收集公開互動軌跡，並在真實裝置上執行元技能稽核與迴歸測試，確保技能套件在實際 UI 版本上的有效性，避免只在模擬環境中有效的问题。

### 給不同背景讀者的閱讀建議

**初學者**：建議先從圖 1 的具體範例入手，理解「純文字技能」與「多模態技能」在相同試算表任務上的差異。重點掌握「狀態卡片」與「分支載入」這兩個直覺概念，暫時略過程序歸納與元技能稽核的技術細節，將 MMSkills 想像成「會看圖的標準作業程序（SOP）」即可。

**AI 工程師**：請聚焦於系統架構與推論管線的實作細節。特別關注分支載入如何在不污染主軌跡圖像上下文的前提下，將參考截圖與即時畫面對齊並蒸餾出結構化引導。同時評估你目前使用的多模態模型上下文長度，是否足以支撐臨時分支內的多視角關鍵幀輸入，並規劃快取策略。

**研究人員**：本文的核心貢獻在於將程序性知識從文字空間擴展到多模態空間，並提出自動化的軌跡到技能生成管線。建議深入分析 Generator 中的工作流程分群與視覺基礎對應機制，思考如何將此框架擴展至機器人操作或醫療影像導航等需要細粒度視覺狀態辨識的領域。分支載入亦可視為一種新型的 in-context learning 互動模式，值得從認知負荷與注意力機制的角度進一步研究。

**產品經理**：請將閱讀重點放在適用場景與風險章節。MMSkills 的價值主張在於降低視覺自動化任務的維護成本：過去需要為每個 UI 變更重寫腳本，現在可透過狀態條件式技能套件適應介面微調。評估導入時，請優先盤點團隊是否擁有足夠的公開互動軌跡資料，並規劃「人機協同稽核」流程，確保自動生成的技能在生產環境安全可用。
