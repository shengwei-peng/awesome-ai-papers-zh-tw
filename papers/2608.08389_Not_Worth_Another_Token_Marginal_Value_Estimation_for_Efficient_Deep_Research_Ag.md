## 摘要翻譯

長程研究智慧體（Long-horizon Research Agents）透過迭代式檢索（Iterative Retrieval）、彙整（Aggregation）與綜合（Synthesis）來解決開放式任務（Open-ended Tasks），但上下文（Context）迅速增長，而額外證據（Additional Evidence）的邊際價值（Marginal Value）卻經常下降。這導致最終報告生成（Final Report Generation）時出現不必要的 token 成本（Token Cost）、更高的延遲（Latency），以及雜訊更高的輸入（Noisier Inputs）。我們研究用於深度研究智慧體（Deep Research Agents）上下文管理（Context Management）的邊際價值估計（Marginal Value Estimation），並首次系統性地對整個流程進行階段感知（Stage-aware）的剪枝策略（Pruning Strategies）比較。我們在檢索前（Pre-retrieval）、檢索後（Post-retrieval）與綜合前（Pre-synthesis）等介入點（Intervention Points），評估輕量啟發式準則（Lightweight Heuristic Criteria）與學習式價值模型（Learned Value Model）。研究結果顯示，剪枝效益（Pruning Effectiveness）更取決於剪枝所應用的位置，而非特定的評分規則（Scoring Rule）：早期剪枝帶來最大的端到端節省（End-to-end Savings），後期剪枝則主要精煉最終綜合上下文（Final Synthesis Context）。輕量啟發式方法（Lightweight Heuristics）可將 token 使用量（Token Usage）減少高達 73%，且品質下降（Quality Degradation）甚微；學習式剪枝（Learned Pruning）在選定的品質–效率權衡（Quality-efficiency Trade-offs）上仍具競爭力；沒有任何單一方法在品質（Quality）、效率（Efficiency）與忠實度（Faithfulness）上全面主導。這些發現為設計高效的長程智慧體系統（Long-horizon Agentic Systems）提供了實務指引。

### 核心貢獻（3～5點）
- 提出以邊際價值估計為核心的上下文管理框架，針對深度研究智慧體中額外證據價值遞減的問題進行系統性分析。
- 首次階段感知地比較橫跨檢索前、檢索後與綜合前的剪枝策略，涵蓋輕量啟發式準則與學習式價值模型。
- 發現剪枝效益主要取決於介入位置而非評分規則：早期剪枝帶來最大端到端節省，後期剪枝則用於精煉最終綜合上下文。
- 實證顯示輕量啟發式方法可減少高達 73% 的 token 使用量且品質下降甚微，學習式剪枝在特定權衡下仍具競爭力。
- 為設計兼顧品質、效率與忠實度的高效長程智慧體系統提供具體實務指引。

### 適合對象
本論文適合從事長程智慧體、檢索增強生成（RAG）、提示工程、上下文管理與大型語言模型（LLM）應用研究的學者與工程師，特別是關注深度研究智慧體在品質、成本與延遲之間權衡的實務開發者與系統設計師。

## 深度分析

#### 方法論解析

本研究將深度研究智慧體（Deep Research Agents）的上下文管理重新定義為「階段感知剪枝（Stage-aware Pruning）」問題，核心概念是估計每一個候選項目對最終報告品質的邊際價值（Marginal Value）。與傳統只在最終輸入前壓縮提示（Prompt Compression）的做法不同，作者提出在三個不同的介入點（Intervention Points）進行剪枝：Pre-Retrieval（檢索前）、Post-Retrieval（檢索後）與 Pre-Synthesis（綜合前）。

**1. 問題形式化**

作者將整體目標寫成在成本預算（Cost Budget）限制下最大化報告品質（Report Quality）：

\[
\max R(C_T, Q) \quad \text{s.t.} \quad \text{Cost}(C_T) \le B
\]

其中 \(C_T\) 是經過 \(T\) 步累積後的上下文（Accumulated Context），\(Q\) 是使用者查詢。由於聯合最佳化所有子集在計算上不可行（intractable），作者透過拉格朗日鬆弛（Lagrangian Relaxation）將其轉為：

\[
\max_{C_T} R(C_T, Q) - \eta \,\text{Cost}(C_T)
\]

其中 \(\eta \ge 0\) 控制品質–效率前沿（Quality-efficiency Frontier）上的運作點（Operating Point）。接著，這個全域問題被拆解成三個局部的剪枝決策，每個階段各自使用一個統一的評分函數 \(V(x \mid C_t, Q)\) 與門檻值（threshold）\(\tau\)。

**2. 三階段剪枝機制**

- **Pre-Retrieval（檢索前）**：候選項目是子查詢（Subqueries）\(s \in S\)。系統在真正呼叫檢索工具前，先估計該子查詢預期能帶來多少新資訊；低價值的子查詢會被直接捨棄，從源頭避免檢索呼叫（Retrieval Calls）與後續 token 消耗。
- **Post-Retrieval（檢索後）**：候選項目是檢索到的內容（Retrieved Content）\(c \in C_{st}\)。這些項目會與目前已累積的上下文 \(C_t\) 比較，移除重複或弱相關的證據（Evidence），避免它們進入分支擴展（Branching）與後續迭代。
- **Pre-Synthesis（綜合前）**：在進入最終報告生成（Report Generation）前，對累積上下文 \(C_T\) 進行最後一次篩選，只保留高價值資訊，降低最終綜合上下文（Final Synthesis Context）的雜訊。

**3. 配置組合**

作者進一步將剪枝策略組合成單階段（One-stage）、雙階段（Two-stage）與三階段（Three-stage）配置。單階段只在 Post-Retrieval 或 Pre-Synthesis 剪枝；雙階段結合 Post-Retrieval + Pre-Synthesis；三階段則在三個點都剪枝。值得注意的是，作者刻意排除「僅在 Pre-Retrieval 剪枝」的組合，因為 Pre-Retrieval 的決策必須在尚未看到檢索結果前做出，預測誤差較大，單獨分析難以公平比較。

**4. 評分規則（Scoring Rules）**

在同一框架下，作者比較了多種 \(V(\cdot)\) 的實例化：

- **輕量啟發式方法（Lightweight Heuristics）**：例如基於相關性–冗餘性（Relevance-redundancy）的最大邊際相關性（Maximal Marginal Relevance, MMR）。MMR 透過參數 \(\lambda\) 平衡查詢相關性與相對於已選集合的新穎性，是計算成本極低的規則。
- **學習式價值模型（Learned Value Model）**：訓練一個模型來預測每個候選項目的邊際價值，能捕捉更細緻的語義訊號，但推論成本與訓練資料需求較高。
- **基於 LLM 的剪枝（LLM-based Pruning）**：利用大型語言模型（Large Language Models, LLMs）直接評估項目價值，通常品質較高但 token 成本與延遲（Latency）也較高。

整體流程可參考 Algorithm 1：在每次迭代中，先進行 Pre-Retrieval 過濾，再檢索、進行 Post-Retrieval 過濾，然後更新累積上下文並可能產生新的子查詢；當搜尋結束後，再執行 Pre-Synthesis 過濾，最後生成報告。

#### 實驗數據解讀

雖然提供的全文片段未包含完整表格，但從摘要與內文可歸納出以下關鍵實證發現：

**1. 剪枝位置比評分規則更重要**

研究最核心的結論是：剪枝效益（Pruning Effectiveness）主要取決於「在哪個階段剪枝」，而非使用哪一種評分規則。這是因為不同階段的剪枝會產生不同的連鎖效應：

- **早期剪枝（Pre-Retrieval / Post-Retrieval）** 能帶來最大的端到端節省（End-to-end Savings）。因為一旦在某個子查詢或檢索結果被納入累積上下文，它就可能觸發更多後續子查詢、更多檢索呼叫，並佔用更多 token。早期移除低價值項目，能同時減少檢索次數、上下文增長（Context Growth）與最終輸入長度。
- **晚期剪枝（Pre-Synthesis）** 主要作用是精煉最終綜合上下文，減少雜訊更高的輸入（Noisier Inputs），對報告品質與來源根據（Source Grounding）有較直接的影響，但對整體 token 使用量與延遲的節省幅度較小。

**2. 輕量啟發式方法表現驚人**

輕量啟發式準則（Lightweight Heuristic Criteria）——特別是 MMR——可將 token 使用量降低多達 **73%**，而報告品質（Report Quality）下降甚微。三階段 MMR（Three-stage MMR）更具體達到 **73.3%** 的 token 減少量（Token Reduction）。這顯示在許多應用場景中，簡單的相關性–冗餘性啟發式（Relevance-redundancy Heuristics）已足以有效控制成本，無需動用昂貴的學習式或 LLM-based 方法。

**3. 沒有單一方法全面稱霸**

實驗顯示品質、效率與忠實度（Faithfulness）之間存在明顯的權衡：

- **相關性–冗餘性啟發式** 在「早期成本控制」上最優，適合預算優先的場景。
- **學習式剪枝（Learned Pruning）** 在某些選定的品質–成本權衡（Quality-cost Trade-offs）上具有競爭力，特別是當目標是報告品質或來源根據時。
- **基於 LLM 的剪枝** 可能提供更高的語義理解與品質，但伴隨更高的 token 成本與延遲。

因此，方法選擇應根據實際的運作點（Operating Point）與成本預算（Cost Budget）而定，而非盲目採用最複雜的模型。

**4. 對評估指標的推論**

從研究問題可推斷，實驗至少評估了以下幾類指標：

- **效率指標**：token 使用量（Token Usage）、檢索呼叫次數（Retrieval Calls）、延遲（Latency）。
- **品質指標**：最終報告（Final Report）的整體品質，可能透過自動指標（如 ROUGE、BERTScore）或 LLM 評判（LLM-as-a-judge）衡量。
- **忠實度指標**：輸出內容與來源資訊的一致性，即來源根據（Source Grounding）與忠實度（Faithfulness）。

作者強調在共享評估設定（Shared Evaluation Setup）下進行控制式實證比較（Controlled Empirical Comparison），這有助於隔離不同剪枝階段與策略的貢獻。

#### 與現有研究的比較

**1. 相對於長程檢索智慧體（Long-horizon Retrieval Agents）**

過去研究如 ReAct、Tree of Thoughts（思維樹）與 Parallel Research（平行研究）主要聚焦於「如何探索」——即如何分解查詢（Query Decomposition）、如何進行分支（Branching）與平行探索（Parallel Exploration）。這些工作提升了多步驟搜尋軌跡（Multi-step Search Trajectories）的覆蓋率（Coverage），但較少關注累積上下文（Accumulated Context）的增長問題。本研究則補充了「如何控制上下文規模」這一環，與探索策略形成互補。

**2. 相對於上下文壓縮與提示效率方法**

Selective Context、DYCP、LLMLingua、LongLLMLingua 與 RECOMP 等技術主要在最終模型輸入附近進行提示壓縮（Prompt Compression）或提示效率（Prompt-efficiency）優化。它們雖能縮短最終提示，但無法減少前期的檢索呼叫與中間上下文的膨脹。本研究的 Pre-Retrieval 與 Post-Retrieval 剪枝則從更上游介入，能夠同時降低檢索成本與最終輸入長度，這是與既有壓縮方法最關鍵的區別。

**3. 相對於智慧體編排（Agent Orchestration）研究**

部分近期研究探討多步驟智慧體系統（Agentic Systems）如何排程行動、根據中間訊號反應或決定何時停止搜尋。本研究與這些工作互補：它提供了一個以邊際價值估計（Marginal Value Estimation）為核心的階段感知剪枝框架，可與現有的停止準則（Stopping Criterion）或排程策略結合使用。

**4. 研究限制**

- **未涵蓋所有階段組合**：作者排除 Pre-Retrieval-only 配置，雖有其方法論理由，但也意味著我們無法得知在某些極低成本預算下，僅在檢索前剪枝是否可能更有效。
- **方法選擇依賴任務特性**：沒有單一策略在所有指標上稱霸，表示在實際部署時仍需針對不同領域、查詢類型與成本結構進行調校。
- **學習式與 LLM-based 方法的額外成本**：雖然這類方法可能提升品質，但其本身的推論成本與訓練資料需求可能削弱整體效率優勢，尤其在低延遲場景中。
- **評估範圍**：目前提供的片段未說明實驗涵蓋的資料集、領域分布與人類評估規模，因此難以判斷結論的泛化性。

#### 未來研究方向

基於本研究的框架與發現，可延伸出以下幾個有潛力的研究方向：

**1. 動態與適應性門檻（Adaptive Thresholds）**

目前的門檻值 \(\tau_{\text{pre}}, \tau_{\text{post}}, \tau_{\text{syn}}\) 可能是固定或經驗調校的。未來可研究根據查詢難度、目前上下文規模與剩餘預算動態調整門檻，以在不同運作點（Operating Point）間自動切換。

**2. 強化學習式剪枝策略（RL-based Pruning Policy）**

將邊際價值估計視為序列決策問題，使用強化學習（Reinforcement Learning）訓練一個端到端的剪枝策略，同時考慮檢索成本、上下文品質與最終報告獎勵，可能超越局部貪婪剪枝。

**3. 聯合探索與剪枝最佳化（Joint Exploration and Pruning）**

目前探索（Exploration）與剪枝被視為相對獨立的模組。未來可設計聯合最佳化框架，讓查詢分解（Query Decomposition）與子查詢選擇同時考慮預期邊際價值，從源頭減少低價值分支。

**4. 線上邊際價值估計（Online Marginal Value Estimation）**

發展無需離線訓練資料的線上估計方法，例如利用 LLM 的自我評估（Self-evaluation）或資訊增益（Information Gain）指標，在執行過程中即時估計每個項目的邊際價值。

**5. 忠實度感知的剪枝（Faithfulness-aware Pruning）**

目前的品質指標可能偏重流暢度與覆蓋率。未來可設計專門保留「對忠實度（Faithfulness）與來源根據（Source Grounding）至關重要」證據的剪枝目標，避免為了省 token 而刪除關鍵支撐資訊。

**6. 跨領域與多語言驗證**

在更多領域（如醫療、法律、科學文獻）與多語言場景中驗證階段感知剪枝的泛化性，並探討不同領域是否適合不同的評分規則（Scoring Rules）。

**7. 與提示壓縮技術的混合架構**

將 Pre-Retrieval / Post-Retrieval 剪枝與 LLMLingua、RECOMP 等提示壓縮方法結合：先用剪枝移除低價值項目，再對保留項目進行語義壓縮，可能進一步逼近品質–效率前沿（Quality-efficiency Frontier）的極限。

**8. 因果邊際價值估計（Causal Marginal Value Estimation）**

現有方法多基於相關性或預測價值進行剪枝。未來可引入因果推論概念，估計「若移除某證據，最終報告品質會如何變化」，從而更精準地識別真正具有高邊際價值的項目。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**
A：這篇論文針對長程研究智慧體在處理開放式任務時，累積上下文快速膨脹但額外證據的邊際價值卻逐漸下降的問題。隨著系統反覆進行迭代式檢索、彙整與綜合，上下文會不斷增長，導致不必要的 token 成本、更高的延遲，以及最終綜合階段更雜訊的輸入。作者將此問題形式化為階段感知剪枝問題，並系統性地比較不同剪枝策略在三個介入點上的效果，以提供實用的設計指引。

**Q2：現有的相關方法為何無法有效解決這個問題？**
A：現有的長程檢索智慧體研究大多聚焦於如何分解查詢、進行迭代檢索與多步推理，但較少關注如何控制累積上下文的增長。另一方面，上下文壓縮與提示效率的研究通常只在最終模型輸入附近進行壓縮，未能從整體流程的角度考慮不同階段的剪枝效益。因此，這些方法無法充分利用早期剪枝所帶來的端到端節省，也缺乏對不同階段策略效果的系統性比較。

**Q3：為何邊際價值估計對深度研究智慧體特別重要？**
A：邊際價值估計能幫助智慧體判斷每個額外檢索項目或子查詢所貢獻的新資訊是否值得保留，從而避免無謂的資源消耗。在長程研究中，早期步驟往往能發現核心事實，而後期檢索容易帶來冗餘或弱相關內容，因此準確估計邊際價值對於平衡品質與成本至關重要。透過適當的邊際價值估計，系統可以在維持報告品質的同時，顯著降低 token 使用量與延遲。

**Q4：論文提出的核心方法是什麼？**
A：論文將上下文管理重新框架為階段感知剪枝問題，並在三個介入點——檢索前、檢索後與綜合前——進行邊際價值估計。作者提出統一的評分函數 V(x | C_t, Q)，根據候選項目 x 相對於累積上下文 C_t 與查詢 Q 的邊際價值來決定是否保留。當項目的分數超過階段特定的閾值時才會被保留，否則會被剪枝，從而在不同階段控制上下文的規模與品質。

**Q5：這個方法的主要創新與關鍵設計選擇為何？**
A：主要創新在於將剪枝視為貫穿整個深度研究流程的階段感知決策問題，而非僅在最終輸入前進行一次性壓縮。作者特別區分了檢索前、檢索後與綜合前三個階段，並指出不同階段對相關性、新穎性、多樣性與覆蓋率的需求可能不同。此外，論文系統性地比較了輕量啟發式方法、學習式價值模型與基於 LLM 的剪枝策略，提供了實用的設計指引。

**Q6：三個介入點的設計有何不同？**
A：檢索前剪枝針對的是候選子查詢，透過預測其邊際價值來決定是否執行檢索，從源頭減少不必要的檢索呼叫。檢索後剪枝則是在每次檢索完成後，評估檢索到的內容相對於當前累積上下文的價值，並在影響後續分支擴展前移除低價值項目。綜合前剪枝則是在最終報告生成前，對累積的完整上下文進行最後篩選，以精煉傳給綜合模組的輸入。

**Q7：論文使用了什麼評估設定與比較對象？**
A：論文在共享的評估設定下，比較了單階段、雙階段與三階段配置中的多種剪枝策略，包括輕量啟發式準則、學習式價值模型與基於 LLM 的方法。評估涵蓋了報告品質、token 使用量、延遲與忠實度等多個面向。這種控制式實證比較讓作者能夠在相同基礎上檢驗不同策略與階段組合的效果。

**Q8：論文的主要實驗結果是什麼？**
A：實驗結果顯示，剪枝效果主要取決於剪枝應用的階段，而非特定的評分規則，其中早期剪枝能帶來最大的端到端成本節省。輕量啟發式方法在幾乎不降低品質的情況下，可將 token 使用量減少高達 73%，而學習式剪枝在特定品質–效率權衡下仍具競爭力。沒有任何單一方法能在品質、效率與忠實度上同時稱霸，相關性–冗餘性啟發式適合早期成本控制，而較豐富的方法則更適合追求報告品質或來源根據。

**Q9：論文進行了哪些消融研究或階段組合分析？**
A：作者比較了單階段、雙階段與三階段配置，其中單階段僅在檢索後或綜合前剪枝，雙階段結合檢索後與綜合前剪枝，三階段則在三個介入點都進行剪枝。結果顯示三階段 MMR 可達到 73.3% 的 token 減少量，顯示多階段協同剪枝的效益。論文也排除了僅在檢索前剪枝的配置，因為檢索前決策較為預測性且容易出錯，需要與後續階段搭配才能穩定發揮效果。

**Q10：這項研究有哪些實際應用場景？**
A：這項研究可應用於需要長程、多步驟檢索的開放式研究任務，例如學術文獻綜述、市場調查報告生成、法律案例研究與政策分析等。在這些場景中，系統需要反覆檢索與綜合大量資訊，而有效的上下文管理能顯著降低運作成本與回應時間。透過階段感知剪枝，開發者可以根據應用需求選擇最適合的成本控制策略。

**Q11：在產品化時需要考慮哪些因素？**
A：產品化時需要根據目標權衡選擇剪枝策略，例如若重視成本與延遲可優先採用輕量啟發式方法，若重視報告品質則可考慮學習式或基於 LLM 的剪枝。此外，不同階段的閾值設定會影響最終輸出品質與資源消耗，因此需要針對特定領域與使用情境進行調校。開發者也應注意忠實度與來源根據，避免過度剪枝導致報告遺失關鍵證據或引用。

**Q12：這項研究對智慧體領域有何影響？**
A：這項研究為長程智慧體系統的上下文管理提供了系統性的實證基礎，強調了階段感知設計的重要性。它挑戰了「單一最佳剪枝方法」的假設，顯示不同策略在不同目標下各有所長，有助於引導未來研究與工程實踐。這些發現也促進了更高效、可擴展的深度研究智慧體設計，對降低大規模部署成本具有重要意義。

**Q13：論文承認哪些限制？**
A：論文指出檢索前剪枝本質上較為預測性且容易出錯，因為此時系統尚未看到實際檢索內容，必須依賴對子查詢價值的估計。此外，沒有任何單一方法能在所有評估面向同時達到最佳，顯示現有策略仍有改進空間。由於評估是在特定共享設定下進行，結果在不同領域、不同模型或不同檢索後端上的泛化能力仍需進一步驗證。

**Q14：哪些情況可能導致方法失效？**
A：當查詢需要高度新穎或多樣化的證據時，過度依賴相關性–冗餘性啟發式可能過早排除有價值的子查詢或檢索結果。若檢索前價值估計不準確，可能導致核心資訊未被檢索，進而影響最終報告的完整性與忠實度。此外，在需要精細來源根據的任務中，過度剪枝可能移除支撐關鍵論述的證據，導致生成內容缺乏根據。

**Q15：未來可以朝哪些方向發展？**
A：未來研究可探索更精準的檢索前價值估計模型，以降低早期剪枝的錯誤風險並提升端到端效益。也可以發展能夠動態調整階段閾值的自適應策略，根據查詢特性與中間回饋即時優化品質–效率權衡。此外，將剪枝與主動停止準則、查詢規劃與多智慧體協調機制結合，也是提升長程研究智慧體效率與可靠性的重要方向。

## 實務應用指南

### 適用場景

**1. 企業級知識問答與研究助理**
適合需要跨越多份內部文件、產業報告與外部新聞進行長程分析的情境，例如法務盡職調查、投資研究、競品追蹤。透過在檢索前（Pre-Retrieval）篩選子查詢，可避免無謂的搜尋擴散，將 token 成本與延遲壓低 70% 以上，同時維持報告品質。

**2. 醫療與科學文獻綜述**
在 PubMed、臨床試驗資料庫或專利庫中進行開放式文獻回顧時，後檢索（Post-Retrieval）與綜合前（Pre-Synthesis）剪枝能過濾重複或邊際貢獻低的論文摘要，減少「Lost in the Middle」導致的關鍵證據遺失，並提升最終報告的來源根據性。

**3. 客戶支援與技術文件診斷**
當智慧體需要在多輪對話中反覆檢索知識庫、API 文件與歷史工單時，階段感知剪枝可防止累積上下文過度膨脹，讓最終回覆更聚焦於真正相關的錯誤訊息與解決步驟。

**4. 政策與法規追蹤系統**
針對需要持續監控法規異動、判例與政策文件的長期任務，邊際價值估計可動態決定是否值得為一條新子查詢發起檢索，避免在已知資訊上重複打撈。

**5. 教育與個人化學習導師**
在生成客製化學習路徑或研究導讀時，輕量啟發式方法（如 MMR）能以極低運算成本控制上下文規模，適合預算有限但需要多步驟探索的應用。

### 實作前置條件

**資料條件**
- 已具備可查詢的語料庫或檢索索引（向量資料庫、Elasticsearch、關聯式資料庫均可）。
- 擁有或能夠建構查詢–證據–報告品質的評估資料，至少包含數百筆帶有參考答案或人工評分的樣本，用於校準閾值與訓練學習式價值模型。
- 能夠取得每次檢索步驟的中間上下文（子查詢、檢索結果、累積上下文），否則無法在三個介入點分別部署剪枝。

**運算條件**
- 輕量啟發式方法（MMR、相關性–冗餘性分數）僅需標準 CPU 與嵌入模型即可運行，適合低延遲場景。
- 學習式價值模型需要 GPU 進行微調，建議至少一張 A100/L40 等級顯卡；若採用基於 LLM 的剪枝，則需額外預留 LLM 推理預算。
- 需具備完整的實驗追蹤與評估管線，才能比較單階段、雙階段與三階段配置。

**技能條件**
- 熟悉檢索增強生成（RAG）管線與提示工程。
- 具備嵌入模型、相似度計算與基本最佳化（如拉格朗日鬆弛概念）的理解。
- 若要走學習式路線，需具備模型微調與損失函數設計經驗。
- 產品團隊需能定義「品質」與「成本」的權衡指標，例如報告正確性、來源忠實度、平均延遲與每筆查詢 token 成本。

---

### 實作步驟建議

**步驟一：建立未剪枝基線**
先部署完整的深度研究管線（查詢分解 → 迭代檢索 → 上下文彙整 → 報告生成），記錄報告品質、token 使用量、檢索呼叫次數與延遲。這是後續所有權衡的比較基準。

**步驟二：選擇第一個介入點**
根據業務目標決定優先剪枝位置：
- 若目標是最大化端到端節省：優先從 **Pre-Retrieval** 著手，過濾低邊際價值的子查詢。
- 若目標是提升最終報告品質：優先從 **Pre-Synthesis** 著手，壓縮傳入綜合模組的上下文。
- 若兩者皆要：採用 **Post-Retrieval + Pre-Synthesis** 雙階段配置作為起點。

**步驟三：部署輕量啟發式方法**
先以 MMR 或相關性–冗餘性啟發式進行實驗，調整閾值 τ_pre、τ_post、τ_syn。論文顯示三階段 MMR 可達約 73% token 減少量，且品質下降有限。此階段應快速迭代，找到可接受的品質–效率運作點。

**步驟四：引入學習式價值模型（可選）**
在輕量方法無法滿足特定權衡時，於選定的階段訓練專屬價值模型。例如針對 Pre-Retrieval 訓練一個預測「執行該子查詢後能帶來多少新資訊」的評分器。注意學習式方法需要更多資料與運算，且不一定在所有指標上勝過啟發式。

**步驟五：進行跨階段比較**
在共享評估設定下，系統性比較單階段、雙階段與三階段配置。不要假設「越多階段越好」：論文發現沒有任何單一方法能在品質、效率與忠實度上同時稱霸。

**步驟六：上線與監控**
將選定配置部署至生產環境，持續監控：
- 報告品質指標（正確性、完整性、來源根據性）
- 成本指標（token 使用量、檢索呼叫次數、延遲）
- 錯誤模式（是否因過度剪枝遺失關鍵證據）

並保留 A/B 測試閘道，方便在未來資料分布改變時重新校準閾值。

### 潛在風險與注意事項

**過度剪枝導致關鍵證據遺失**
尤其在 Pre-Retrieval 階段，錯誤地過濾子查詢可能讓整條探索分支消失，後續再也無法補救。建議保留一條「安全網」機制：對於高不確定性查詢，降低閾值或允許少量探索性檢索。

**閾值對資料分布敏感**
在某一領域校準好的 τ 值，換到另一領域可能過嚴或過鬆。應將閾值視為可配置參數，並建立自動化評估流程定期重新校準。

**輕量方法與學習方法的權衡誤判**
不要預設學習式價值模型一定更好。論文顯示輕量啟發式在成本控管上表現優異，而學習式方法僅在特定品質–效率運作點具競爭力。應以實際評估數據為準。

**忠實度與來源根據性下降**
過度壓縮 Pre-Synthesis 上下文可能讓最終報告失去來源支撐，產生幻覺。建議在評估時將 faithfulness 與 source grounding 列為獨立指標，而非只看整體報告品質。

**延遲與 token 成本並非同義詞**
某些剪枝策略可能減少 token 使用量，但增加額外推理步驟（例如 LLM-based 評分），反而提高延遲。需同時追蹤兩項指標。

### 與其他技術的整合建議

**與 RAG 管線整合**
可將 Pre-Retrieval 視為「查詢過濾層」、Post-Retrieval 視為「重排序與去重層」、Pre-Synthesis 視為「提示壓縮層」，直接疊加在現有 RAG 架構上，無需重新設計整個系統。

**與提示壓縮技術整合**
Pre-Synthesis 剪枝可與 LLMLingua、RECOMP 等提示壓縮方法互補：先以邊際價值估計移除低價值項目，再對保留項目進行語句級壓縮，進一步縮減最終綜合上下文。

**與多智慧體編排框架整合**
在 ReAct、Tree of Thoughts 或 Parallel Research 等框架中，可將邊際價值估計嵌入「是否繼續探索」的決策邏輯，作為動態停止準則或分支剪枝機制。

**與評估與觀測平台整合**
建議將每個階段的評分、閾值與保留率記錄到可觀測系統（如 LangSmith、Weights & Biases、自研追蹤平台），以便在生產環境中診斷品質退化原因。

**與成本控管機制整合**
可將 η（品質–效率權衡參數）暴露為產品層級設定，讓使用者或營運團隊依據任務重要性選擇「高品質模式」或「節省模式」。

### 給不同背景讀者的閱讀建議

**給初學者**
這篇論文討論的是「如何讓 AI 研究助理不要讀太多無用資料」。你可以把它想像成幫智慧體裝上一個「值不值得再查」的判斷器：在還沒檢索前先刪掉沒價值的子問題，檢索後刪掉重複或無關的網頁，最後生成報告前再精簡一次資料。重點結論是「先刪最省錢」，而且簡單規則往往就夠用，不一定需要複雜的 AI 模型來決定。

**給 AI 工程師**
本文提供了一套可落地的階段感知剪枝框架，建議你直接關注第 3 節的問題形式化與 Algorithm 1，並將 MMR 作為第一個 production baseline。實作時請注意三個閾值 τ_pre、τ_post、τ_syn 的聯合影響，並建立共享評估設定來比較單階段、雙階段與三階段配置。若你正在優化 latency，請特別檢視 LLM-based 評分帶來的額外開銷是否抵銷了 token 節省。

**給研究人員**
這份工作將邊際價值估計重新框架為階段感知決策問題，並強調「在哪裡剪枝」比「用什麼規則剪枝」更重要。未來可延伸的方向包括：針對 Pre-Retrieval 設計更好的不確定性估計、結合強化學習聯合最佳化三階段策略、以及在不同領域與更長視野任務上驗證跨階段發現的穩健性。此外，faithfulness 與 source grounding 的權衡仍值得更細緻的理論分析。

**給產品經理**
這篇論文的核心商業訊息是：你可以用簡單且低成本的規則，將深度研究產品的運算成本砍掉七成以上，同時維持可接受的報告品質。建議你將「階段感知剪枝」視為一組可調整的成本控管旋鈕，並向用戶提供不同模式選項。同時要留意過度節省可能損害來源根據性與輸出正確性，因此必須在產品指標儀表板中同時追蹤品質、成本與忠實度，而非只看成本下降。
