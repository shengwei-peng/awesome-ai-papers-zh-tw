# 方法越多，智能體越好？智能體強化學習中自蒸餾的現實檢驗

**原文標題：** More Methods, Better Agents? A Reality Check on Self-Distillation in Agentic Reinforcement Learning  
**作者：** Linhao Zhong、Bozhen Fang、Xuehao Wang 等 10 位作者  
**發布日期：** 2026-10-14  
**HF 連結：** [https://huggingface.co/papers/2610.19789](https://huggingface.co/papers/2610.19789)  
**arXiv：** [https://arxiv.org/abs/2610.19789](https://arxiv.org/abs/2610.19789)  

---

## ⚡ TL;DR

智能體強化學習的自蒸餾方法激增，但評測常沿用舊基線分數，缺乏公平比較。
作者建立統一基準，在四個環境與三種模型規模上比較十種方法與GRPO，共耗費逾一萬二千GPU小時。
結果顯示無方法能穩定超越GRPO，強最終分數可能掩蓋訓練不穩定，且高成本未必帶來更好效能。

## 摘要翻譯

智能體強化學習（Agentic Reinforcement Learning）中的自蒸餾（Self-Distillation）已產出日益增多的方法。然而，現有評測常在不同實驗條件（Experimental Condition）下重複使用已發表的基線（Baseline）分數，對同時期方法（Contemporaneous Method）之間的直接比較（Direct Comparison）較少，且對訓練穩定性（Training Stability）與計算成本（Computational Cost）的關注有限。這些限制掩蓋了報告增益（Reported Gain）的真正來源，以及競爭方法的實際優缺點。昂貴的智能體訓練（Agent Training）進一步凸顯了建立共同比較基礎的必要性。為了解決這些差距，我們在三種模型規模（Model Scale）下，於 ALFWorld、ScienceWorld、Search-QA 與 WebShop 上比較了十種具代表性的方法與 GRPO。我們的研究包含 132 次訓練運行（Training Run），總計記錄 12,124.4 個 H800 GPU-小時（GPU-Hours），並對預訓練骨幹模型（Pretrained Backbone）及全部十一種訓練方法在八個推展種子（Rollout Seed）下進行重複評估（Repeated Evaluation）。除最終任務效能（Task Performance）外，我們亦檢視訓練進度（Training Progress）、穩定性以及測量成本（Measured Cost）。我們的評測得出三項關鍵發現。首先，相較於 GRPO 的增益在範圍上仍有限，沒有任何方法能在所有設定中持續超越它。其次，優異的最終效能可能掩蓋訓練的不穩定性。第三，額外的訓練成本並未穩定地轉化為更好的效能。我們建立此基準測試（Benchmark）以支援公平（Fair Comparison）且全面的比較，並引導未來研究朝向可靠且具成本效益（Cost-Effective）的智能體訓練改進。專案頁面（Project Page）：https://aim-uofa.github.io/Self-Distillation-AgentRL/

### 核心貢獻（3～5點）
- **大規模且系統化的實證比較**：在四個基準測試（ALFWorld、ScienceWorld、Search-QA、WebShop）與三種模型規模下，針對十種自蒸餾方法與 GRPO 進行全面對照，涵蓋 132 次訓練運行與 12,124.4 個 H800 GPU-小時的計算投入。
- **嚴謹的評測協議設計**：對預訓練骨幹模型與全部十一種訓練方法，在八個推展種子下進行重複評估，避免沿用不同實驗條件下發表的基線分數，確保比較的公平性與可復現性。
- **揭示自蒸餾方法的實際局限**：透過三項關鍵發現指出——相較於 GRPO 的增益有限、最終效能可能掩蓋訓練不穩定性、額外訓練成本未必帶來更好效能——釐清報告增益的真正來源。
- **建立可重複使用的比較基準**：提供一個涵蓋訓練進度、穩定性與計算成本的綜合評測框架，作為未來智能體強化學習方法研究的共同參考依據。

### 適合對象
- 從事大語言模型智能體（LLM Agent）與強化學習（Reinforcement Learning）研究，特別關注自蒸餾、策略優化或獎勵塑形（Reward Shaping）等技術的學者與研究生。
- 正在設計或選擇智能體訓練（Agent Training）方法、需要評估方法論進展（Methodological Progress）與訓練成本取捨的業界工程師與技術主管。
- 關注機器學習實證研究方法論、評測協議（Evaluation Protocol）設計與可復現性（Reproduction）的讀者。

## 深度分析

#### 方法論解析

本篇論文並非提出新方法，而是建立一套**獨立基準測試（independent benchmark）**，對智能體強化學習（agentic reinforcement learning）領域中十種自蒸餾（self-distillation）方法進行系統性比較。其方法論核心在於解決現有研究中「評測不一致」的問題，採用統一評測協議（common protocol）來揭示方法間的真實差異。

**基準測試架構設計**

研究團隊設計了一個三維度的評測矩陣：

1. **方法維度（Method Dimension）**：選取十種代表性自蒸餾方法與 GRPO（Group Relative Policy Optimization）基線進行對比。這十種方法依其運作機制可分為四類：
   - **輔助損失類（Auxiliary Loss）**：Skill-SD、GRPO+OPSD、SDAR、ICSD、PCSD
   - **優勢調控類（Advantage Modulation）**：RLSD、OCSD、AgentOPSD
   - **獎勵塑形類（Reward Shaping）**：ADRS
   - **環境驗證延續類（Environment-Verified Continuation）**：OVCSD

2. **環境維度（Environment Dimension）**：涵蓋四個基準——ALFWorld（文字家庭任務環境）、ScienceWorld（科學實驗環境）、Search-QA（問答基準）、WebShop（網路購物環境），代表異質性的智能體互動場景。

3. **模型規模維度（Model Scale Dimension）**：橫跨 2B、4B、9B 三種參數規模，以檢驗方法在不同模型容量下的可擴展性。

**評測維度的創新設計**

論文最關鍵的方法論貢獻在於提出三個**先前研究普遍忽略的評測維度**：

- **重複評估（Repeated Evaluation）**：使用 8 個 rollout seeds 對預訓練骨幹模型（pretrained backbone）與所有十一種訓練後方法進行評估，共計 1,152 次評估掃描（evaluation sweeps），以量化結果的統計顯著性而非僅依賴單一隨機種子的表現。
- **訓練失敗分析（Training Failure Analysis）**：追蹤 2,772 次訓練時驗證掃描（training-time validation sweeps），捕捉訓練過程中的不穩定性，而非僅關注最終分數。
- **測量成本（Measured Cost）**：記錄所有訓練運行的實際 GPU-小時（GPU-hours），共 12,124.4 H800 GPU-小時，使成本效益分析成為可能。

**同策略自蒸餾（OPSD）的理論框架**

論文將自蒸餾方法統一在一個理論框架下：教師分支（teacher branch）以訓練階段專屬的特權資訊（privileged information）為條件，對學生生成軌跡（student-generated trajectory）提供更密集的監督信號。這種設計試圖緩解稀疏結果獎勵（sparse outcome reward）在長程任務中對個別決策指導不足的問題。

#### 實驗數據解讀

**核心發現一：增益的範圍有限且依設定而異**

論文最重要的實驗結論是：沒有任何方法能在所有設定中持續超越 GRPO。這意味著現有文獻中報告的「方法 A 優於基線」之類結論，往往是**設定依賴（setting-dependent）**的，而非普遍適用的方法論進展。從 Table 1 的覆蓋率分析可見，先前十項研究中僅有 1/10 進行了重複評估，5/10 進行了訓練失敗分析，僅 3/10 測量了計算成本——這意味著大多數所謂的「增益」缺乏統計嚴謹性。

**核心發現二：最終分數掩蓋訓練不穩定性**

此發現揭示了智能體強化學習中的一個關鍵陷阱：訓練曲線可能在不同階段劇烈波動，最終收斂到一個看似優異的分數，但中間過程可能經歷嚴重的策略退化（policy degradation）。論文透過訓練時驗證掃描捕捉到這些動態，證明僅報告最終分數會誤導研究者對方法可靠性的判斷。

**核心發現三：成本與效能的非線性關係**

12,124.4 H800 GPU-小時的測量數據顯示，額外的訓練成本並未一致地轉化為更好的智能體效能。這對實務部署具有重要意涵：在資源受限的情況下，簡單的 GRPO 可能比複雜的自蒸餾方法更具成本效益（cost-effective）。

**實驗規模的統計意義**

132 次訓練運行橫跨 12 個模型-任務設定（4 環境 × 3 規模），每個設定都包含完整的基線與十種方法比較。這種規模的基準測試在智能體強化學習領域屬於罕見的大規模復現研究，其數據可信度遠高於單一論文中報告的對比結果。

#### 與現有研究的比較

**對現有研究局限的批判性定位**

論文精準指出當前自蒸餾方法研究的三大系統性問題：

1. **基線分數重用（Baseline Score Reuse）**：多數論文直接引用先前發表的基線分數，而非在共同協議下重新訓練基線。這導致訓練條件、超參數調整（hyperparameter tuning）、評測協議的差異被誤認為方法論的進步。

2. **同時期方法缺乏直接比較**：個別論文僅展示「我優於基線」，但未與同期提出的其他方法進行頭對頭比較，使得領域無法判斷哪個方法真正更優。

3. **評測維度不完整**：如表 1 所示，僅 OCSD 同時進行了重複評估與測量成本；大多數研究缺乏對訓練穩定性與計算成本的系統性檢驗。

**相較於單一方法論論文的優勢**

本基準測試的核心價值在於其**獨立性（independence）**與**全面性（comprehensiveness）**。單一方法論論文天然存在「證明自己方法優越」的動機偏差，而獨立基準測試則能以中立的視角評估所有方法。此外，132 次訓練運行的規模使得結論具有較高的外部效度。

**與相關領域研究的關聯**

論文將自蒸餾置於更廣泛的脈絡中：從 Hinton 等人的經典知識蒸餾（knowledge distillation），到 Ross 等人的 DAgger 處理分佈不匹配的學生-教師學習（student-teacher learning），再到推理增強的監督方法。這種定位有助於讀者理解自蒸餾在智能體訓練中的理論基礎與創新空間。

**論文的局限性**

儘管規模龐大，本研究仍有其邊界：僅選取十種「代表性」方法，可能遺漏某些新興方法；評測集中於四個基準，對其他領域（如程式碼生成、多步驟規劃）的適用性未經驗證；H800 GPU 的成本測量未必能直接推廣到其他硬體。

#### 可重現性評估

**專案資源的可用性**

論文提供了專案頁面（https://aim-uofa.github.io/Self-Distillation-AgentRL/），這是評估可重現性的首要指標。從論文結構來看，作者承諾提供：

- 統一的評測協議文件
- 所有十種方法的實作細節
- 132 次訓練運行的配置與超參數
- 評估結果的完整記錄

**可重現性的優勢**

相較於原始方法論文，本基準測試的可重現性優勢在於：

1. **共同評測協議**：所有方法在相同條件下訓練與評估，消除了「蘋果對橘子」的比較問題。
2. **多種子評估**：8 個 rollout seeds 的使用使得結果具有統計意義，其他研究者可直接驗證。
3. **成本透明**：12,124.4 H800 GPU-小時的明確記錄使後續研究者能預估復現所需的資源。

**可重現性的潛在挑戰**

- 訓練運行涉及大量 GPU-小時，即使有完整程式碼，獨立復現仍需可觀的硬體資源。
- 不同方法可能有其特定的超參數敏感性，基準測試中的「方法特定設定」是否完全公平仍需審視。
- 預訓練骨幹模型的版本固定性需要明確記錄，以避免模型更新導致的結果漂移。

#### 未來研究方向

**基於論文發現的優先研究方向**

1. **訓練穩定性機制研究**：鑑於「最終分數掩蓋不穩定性」的發現，未來研究應優先開發能夠在訓練過程中提供穩定性保障的機制，例如自適應學習率調整、優勢函數的正則化、或早停策略的理論基礎。

2. **成本感知的方法設計**：論文證明額外成本未必帶來效能提升，這促使研究者設計**內在具成本效益（intrinsically cost-effective）**的方法，而非僅追求最終分數的提升。

3. **跨設定泛化能力**：既然沒有方法能持續超越 GRPO，未來研究應聚焦於理解「為何某些方法在特定設定下有效」，並發展能預測方法適用條件的理論框架。

**方法論層面的改進方向**

4. **標準化評測協議的推廣**：本論文建立的基準可作為領域標準化的起點，未來可擴展至更多環境（如程式碼生成、數學推理）、更多模型規模（如 70B 以上）、以及更多評測維度（如安全性、效率）。

5. **失敗模式的系統分類**：論文提及「監督不一致性（supervision inconsistency）」與「特權資訊偏差（privileged-information bias）」作為潛在失敗模式，未來可對這些失敗模式進行更細緻的分類與診斷。

6. **理論分析與實證結合**：目前自蒸餾方法多為經驗性設計，缺乏對「為何特權資訊能改善學生策略」的理論分析。結合資訊理論、最佳化理論的分析將有助於釐清方法的適用邊界。

**實務應用導向**

7. **領域特定的自蒸餾設計**：不同任務（家庭任務、科學實驗、網路購物）可能需要不同形式的特權資訊，未來可探索任務自適應的蒸餾機制。

8. **與其他訓練範式的整合**：自蒸餾可與課程學習（curriculum learning）、多任務學習、或其他 RL 演算法結合，探索混合方法的可能性。

最後，本論文最重要的「元貢獻（meta-contribution）」在於示範了一種**獨立基準驅動的研究文化**：在快速發表新方法的領域中，系統性的獨立評估應優先於提出更多方法。這種研究範式的轉變，可能比任何單一技術突破更能推動領域的健康發展。

## 論文問答

**Q1：這篇論文試圖解決什麼核心問題？**
A：這篇論文聚焦於智能體強化學習（Agentic RL）中自蒸餾（Self-Distillation）方法評估的可靠性問題。隨著自蒸餾方法以約每兩天一篇預印本的速度快速增加，但現有評估往往沿用先前論文所報告的基線分數，而非在共同實驗條件下重新復現，使得不同方法之間的比較缺乏公平基礎。作者主張在提出新方法之前，應優先進行獨立且系統化的評估，以釐清哪些方法真正值得作為後續研究的基礎。

**Q2：為什麼現有的自蒸餾方法評估方式不足以支撐可靠的結論？**
A：現有評估存在三大主要缺陷：第一，多數研究僅報告相對於先前論文的增益，卻未在統一協議下直接比較同期方法；第二，基線分數常被直接沿用，但不同論文的訓練條件、超參數調整與評測設定各異，使得所謂的「方法論進展」可能其實只是實驗條件差異的反映；第三，絕大多數研究只關注最終分數，較少系統性地檢視訓練穩定性與計算成本，因此難以判斷增益是否穩健且具成本效益。

**Q3：為什麼獨立評估比提出新方法更迫切？**
A：由於智能體訓練的計算成本極高（單一訓練運行即需大量 GPU-小時），每篇新方法論文若各自重新復現所有基線，將造成資源的重複浪費。因此，建立一個共享、系統化的基準測試，能讓整個社群在共同基礎上比較方法優劣，避免「方法數量爆炸但可比證據稀缺」的困境，這也是作者強調「獨立評估應優先於提出新方法」的核心論點。

**Q4：本研究的核心方法論是什麼？**
A：本研究採用統一基準測試（Unified Benchmark）的方法論，在四個基準環境（ALFWorld、ScienceWorld、Search-QA、WebShop）與三種模型規模（2B、4B、9B）下，針對十個具代表性的自蒸餾方法與 GRPO 基線進行系統性比較。整個研究共執行 132 次訓練運行、累計 12,124.4 個 H800 GPU-小時，並在八個 rollout 種子上對所有預訓練骨幹與十一個訓練後方法進行重複評估，以提供統計上可靠的比較基礎。

**Q5：本研究在評估設計上有何關鍵創新？**
A：本研究的關鍵創新在於「評估維度的完整性」：除了最終任務效能外，還系統性地納入訓練進度、訓練穩定性與實測計算成本三個維度。具體而言，作者透過重複評估（repeated evaluation）來量化效能變異，透過訓練失敗分析（training failure analysis）來揭示不穩定性，並透過測量成本（measured cost）來檢驗「更高成本是否換來更好效能」的命題，這是過往論文普遍缺乏的。

**Q6：在追求公平比較的設計上，作者做了哪些關鍵選擇？**
A：作者選擇保留各方法原始論文所建議的訓練超參數與方法專屬設定，以反映各方法「在其最佳使用情境下」的表現，而非強加統一的超參數。同時，所有方法共享相同的環境、評測程序與 rollout 種子，並對預訓練骨幹進行基準化，從而將方法差異與實驗條件差異區隔開來，使比較結果能反映真實的方法論進展而非評測協議的偏差。

**Q7：本研究使用了哪些基準測試與模型規模？**
A：本研究選用四個互補的基準環境：ALFWorld（文字家庭任務）、ScienceWorld（科學實驗環境）、Search-QA（問答任務）與 WebShop（網路購物環境），涵蓋了不同類型的智能體互動情境。模型規模方面則橫跨 2B、4B 與 9B 三個等級，共構成 12 個「模型—任務」設定，使結論能在不同模型容量下檢驗其穩健性。

**Q8：本研究歸納出的三大關鍵發現為何？**
A：第一，相較於 GRPO 的增益在範圍上仍然有限，沒有任何方法能在所有設定中穩定地超越 GRPO；第二，強勁的最終分數可能掩蓋訓練過程中的不穩定性，意味著僅看終點表現會誤判方法的可靠性；第三，額外的訓練成本並不一致地轉化為更好的效能，凸顯了「成本—效益」分析在方法比較中的必要性。

**Q9：本研究如何分析訓練穩定性與計算成本？**
A：在訓練穩定性方面，作者透過多次 rollout 種子的重複評估來量化效能變異，並對訓練曲線進行檢驗以識別訓練失敗的情況。在計算成本方面，則以實際記錄的 H800 GPU-小時作為客觀指標，比較不同方法達到特定效能水準所需的資源，從而檢驗「更高成本是否換來更好效能」的命題。這種多維度的分析揭示了單看最終分數所無法察覺的問題。

**Q10：本基準測試適用於哪些實際應用情境？**
A：本基準測試特別適用於需要部署 LLM 智能體於真實互動環境的場景，例如家庭服務機器人、科學研究助理、資訊檢索系統與電子商務自動化等。由於這些應用對訓練成本與部署可靠性極為敏感，本研究提供的「成本—效能」分析能幫助實務工程師在資源受限的情境下選擇最合適的訓練方法。

**Q11：從產品化的角度，本研究的發現帶來哪些考量？**
A：產品化角度的核心啟示是：追求最新自蒸餾方法未必能帶來實質效益，因為沒有任何方法能在所有設定中穩定超越 GRPO 這個簡單且成熟的基線。產品團隊應優先考慮訓練穩定性與計算成本，而非僅以最終分數作為方法選擇依據，否則可能在生產環境中遭遇訓練不穩定或成本失控的問題。

**Q12：本研究對整個領域的影響為何？**
A：本研究透過建立共享基準，呼籲社群從「方法數量競賽」轉向「證據品質優先」的評估文化。其影響包括：促使未來論文在統一協議下報告結果、推動訓練穩定性與成本效益成為方法論評估的標準維度，以及引導資源投入於真正能帶來穩健增益的方向，而非僅追求表面上的分數提升。

**Q13：本研究自承有哪些限制？**
A：本研究的限制包括：僅涵蓋四個基準環境與三種模型規模，可能無法完全代表所有智能體應用場景；保留各方法原始超參數雖反映「最佳使用情境」，但無法完全排除超參數調整不充分的可能性；此外，12,124.4 個 GPU-小時的預算雖然龐大，但對於某些需要更長訓練週期才能顯現優勢的方法而言，仍可能不足以觀察到完整的效能差異。

**Q14：本研究觀察到哪些具體的失敗案例？**
A：研究發現部分方法雖然在最終分數上看似具有競爭力，但在訓練過程中表現出明顯的不穩定性，例如效能劇烈波動或在某些設定下完全無法收斂。此外，有些方法雖然引入了額外的蒸餾機制與相應的計算開銷，卻未在效能上帶來對應的提升，構成了「高成本但低效益」的失敗案例，凸顯了僅以最終分數作為評估指標的危險。

**Q15：本研究對未來研究方向有何建議？**
A：作者建議未來研究應朝三個方向推進：第一，發展能在不同設定間穩定超越 GRPO 的方法，而非僅在特定基準上表現出色；第二，將訓練穩定性列為方法設計的核心目標，而非事後才檢驗的附屬指標；第三，建立更具成本效益的訓練機制，使效能提升與計算開銷之間維持合理的比例。整體而言，研究的最終願景是引導社群走向「可靠且具成本效益」的智能體訓練方法。

## 實務應用指南

### 適用場景

1. **企業內部智能體訓練方法的選型決策**：當團隊需要在 GRPO 與十種自蒸餾方法（如 GRPO+OPSD、SDAR、Skill-SD、RLSD、OCSD、OVCSD、AgentOPSD、ADRS、ICSD、PCSD）之間抉擇時，可直接引用本基準的 132 次訓練運行結果，避免依賴各原論文中不一致的基線分數。

2. **新自蒸餾方法的公平驗證**：研究團隊提出新的智能體強化學習方法時，可將其置於本基準的共同評測協議下，與 GRPO 及十種代表方法在 ALFWorld、ScienceWorld、Search-QA、WebShop 四個環境、2B/4B/9B 三種規模下直接比較。

3. **訓練預算與成本效益評估**：在投入數千 GPU-小時訓練智能體之前，可參考本基準 12,124.4 H800 GPU-小時的測量成本資料，判斷「更高訓練成本是否換來更好效能」，避免在無實證增益的方法上浪費資源。

4. **訓練穩定性稽核**：當生產環境中的智能體表現時好時壞時，可採用本基準的訓練失敗分析方法（涵蓋 5/10 種方法），檢查最終分數背後是否存在訓練崩潰或退化行為。

5. **可重現研究的基準建立**：學術或工業界團隊欲建立自家智能體評測流程時，可採用本基準的八個推展種子重複評估機制，取代單一隨機種子的不可靠分數。

### 實作前置條件

**資料需求**
- 四個基準環境的完整設定：ALFWorld（文字家庭任務）、ScienceWorld（科學實驗環境）、Search-QA（問答資料集）、WebShop（網路購物環境）。
- 各方法的原始實作程式碼與超參數設定（依原論文與官方實作庫）。
- 預訓練骨幹模型權重（涵蓋 2B、4B、9B 三種規模）。

**計算資源**
- NVIDIA H800 GPU，建議至少 8 卡節點用於分散式訓練。
- 預估總訓練成本：完整基準約需 12,124.4 H800 GPU-小時；單一方法單一規模單一環境的最小重現約需數百 GPU-小時。
- 儲存空間需容納 132 次訓練運行的 checkpoint、log 與評測紀錄。

**技能前提**
- 熟悉強化學習演算法（特別是 GRPO 及其變體）。
- 具備大語言模型分散式訓練經驗（DeepSpeed、FSDP 或 Megatron-LM）。
- 能撰寫環境互動介面（處理動作、觀察、獎勵的閉環）。
- 具備統計分析能力，能處理多種子評估的變異數與信賴區間。

---

### 實作步驟建議

**步驟一：建立共同評測基礎設施**
- 統一四個環境的介接層，確保所有方法在相同的狀態-動作-獎勵定義下訓練。
- 設定八個固定的推展種子，用於預訓練骨幹與所有十一種訓練方法的評估。
- 建立訓練時驗證（2,772 次 sweep）與最終評測（1,152 次 sweep）的分離流程。

**步驟二：依方法特性分組訓練**
- 將十種方法依機制分類：輔助目標類（Skill-SD、GRPO+OPSD、SDAR、ICSD、PCSD）、優勢調控類（RLSD、OCSD、AgentOPSD）、獎勵塑形類（ADRS）、環境驗證延續類（OVCSD）。
- 保留各方法的特化超參數，但統一訓練步數、batch size 與評估頻率，以利橫向比較。

**步驟三：記錄三類關鍵證據**
- **重複評估**：每個 checkpoint 在八個種子上評估，計算平均與變異。
- **訓練失敗分析**：監控策略熵、獎勵曲線、KL 散度，標記訓練崩潰點。
- **測量成本**：記錄每個方法的實際 GPU-小時、記憶體峰值與推展延遲。

**步驟四：產出三維度比較報告**
- 最終分數比較（橫軸：方法，縱軸：12 個模型-任務設定）。
- 訓練穩定性比較（曲線圖呈現訓練過程中的效能波動）。
- 成本-效能散點圖（標示每方法每設定的 GPU-小時與最終分數）。

**步驟五：將基準整合至產品決策流程**
- 將比較結果彙整為內部選型矩陣，標註每方法的「適用情境」、「不適用情境」、「成本區間」。
- 設定定期重評機制（每季），追蹤新方法是否真的優於既有選擇。

### 潛在風險與注意事項

**風險一：訓練不穩定性被最終分數掩蓋**
- 現象：方法 X 在最終評估中勝出 GRPO，但訓練中期曾發生策略退化。
- 緩解：務必檢視完整訓練曲線，而非僅看終點分數；本基準已揭示「強最終表現不代表穩定訓練」。

**風險二：依設定而異的增益導致錯誤結論**
- 現象：方法在 2B 模型上有效，但 4B/9B 上無效；或在 ALFWorld 有效但 WebShop 無效。
- 緩解：至少在兩個模型規模與兩個環境下驗證；避免在單一設定下宣稱方法優越。

**風險三：訓練成本與效能不成正比**
- 現象：方法 Y 訓練成本為 GRPO 的 3 倍，但效能僅提升 1-2%。
- 緩解：以「每 GPU-小時的效能增益」作為決策指標；本基準已證實「更高成本不一定換來更好表現」。

**風險四：基線分數複用導致誤判**
- 現象：直接引用其他論文的 GRPO 分數，未在自家環境下重現。
- 緩解：所有基線必須在共同評測協議下重新訓練，禁止跨論文引用分數。

**風險五：單一推展種子的高變異**
- 現象：單一隨機種子的評估分數波動 ±5%，可能掩蓋真實差異。
- 緩解：採用本基準的八種子重複評估，並報告信賴區間。

**風險六：特權資訊偏差**
- 現象：自蒸餾方法依賴訓練時才有的特權資訊，若部署環境無法提供，效能可能下降。
- 緩解：明確區分「訓練可用資訊」與「部署可用資訊」，並在部署環境下重新評估。

### 與其他技術的整合建議

**與既有 RL 框架整合**
- 可將本基準的評測流程封裝為 plug-in，接入 TRL、OpenRLHF、Verifiers 等開源框架。
- 建議將 GRPO 作為預設基線，所有新方法以「相對 GRPO 的增益」呈現，而非絕對分數。

**與 MLOps 平台整合**
- 將 132 次訓練運行的 metadata（超參數、GPU-小時、checkpoint 雜湊）整合至 MLflow 或 Weights & Biases。
- 設定自動化儀表板，即時顯示各方法的訓練曲線、成本與穩定性指標。

**與分散式訓練系統整合**
- 採用 Ray 或 Kubernetes 排程 132 次訓練運行，自動分配 H800 資源。
- 整合 spot instance 機制以降低成本，但需注意訓練中斷對穩定性分析的影響。

**與評測服務整合**
- 將四個基準環境容器化（Docker），提供 API 供外部方法提交評測。
- 整合 LangSmith 或 Helicone 等 LLM 觀測工具，追蹤每次推展的 token 用量與延遲。

**與既有智能體產品整合**
- 在生產環境中部署前，先在 Search-QA 或 WebShop 等較低成本環境驗證方法穩定性。
- 採用 canary release 策略，將新方法與 GRPO 並行運行，比較真實使用者互動指標。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的動機說明，理解「為什麼不能只看最終分數」；再跳讀圖 1 的基準總覽，掌握 132 次訓練運行與 12,124.4 GPU-小時的規模感；最後聚焦三項關鍵發現（增益有限、穩定性被掩蓋、成本不成正比），建立對自蒸餾方法的批判性視角，避免被單一論文的樂觀結果誤導。

**給 AI 工程師**：重點閱讀第 2 節的相關工作分類，理解十種方法依「輔助目標、優勢調控、獎勵塑形、環境驗證」四種機制的差異；實作時直接參考專案頁面（https://aim-uofa.github.io/Self-Distillation-AgentRL/）的評測協議，採用八種子重複評估與訓練失敗分析流程；在自家產品中部署前，務必在 Search-QA 等低成本環境驗證訓練穩定性與成本效益。

**給研究者**：本論文的核心貢獻在於「獨立基準」而非新方法，建議仔細檢視表 1 的證據覆蓋矩陣，理解十種方法在「重複評估、訓練失敗分析、測量成本」三維度的缺口；設計新方法時，應將本基準作為最低驗證標準，並在論文中明確報告三項指標；引用本基準時，務必採用其共同評測協議下的重現分數，而非其他論文的二手數據。

**給產品經理**：本論文的結論對產品決策有直接意涵——「更多方法不等於更好效能」，因此在評估供應商或內部團隊提出的新方法時，應要求提供（1）相對 GRPO 的實測增益、（2）訓練穩定性證據、（3）每 GPU-小時的效能成本；避免為追求微幅效能提升而投入不成比例的訓練預算；將本基準作為選型 RFP 的技術附件，確保供應商在公平條件下競爭。
