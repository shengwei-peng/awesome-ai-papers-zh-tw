# 邁向智慧體搜尋之互動空間檢索

**原文標題：** Towards Retrieving Interaction Spaces for Agentic Search  
**作者：** Shengyao Zhuang、Yuansheng Ni、Hengxin Fun 等 5 位作者  
**發布日期：** 2026-06-05

## ⚡ TL;DR

傳統片段檢索與無限制語料互動分別在證據細緻度與擴展性上失效，無法滿足智慧體搜尋需求。
本文提出RISE，以BM25建構具邊界的互動空間，並於索引時處理文件結構，支援Shell式導航。
RISE以四分之一的成本達到78%準確率，於百萬文件規模維持81%且顯著優於DCI。

## 摘要翻譯

搜尋智慧體的檢索機制仍繼承自非智慧體資訊檢索（non-agentic information retrieval）：檢索器對語料庫（corpus）進行排序，而智慧體僅讀取少量回傳的文件。近期的直接語料庫互動（Direct Corpus Interaction, DCI）研究顯示，智慧體可改為透過 grep、檔案讀取（file reads）等 Shell 工具（shell tools）與原始語料庫（raw corpus）互動。然而無限制的互動無法擴展：每個大範圍的 Shell 命令都會對整個語料庫進行掃描，且隨著語料庫增長，延遲（latency）將急遽增加。我們主張，智慧體搜尋（agentic search）中的檢索角色不僅僅是選擇能容納於 LLM 上下文視窗（context window）的文件，而是建構一個互動空間（interaction space）：一個邊界有限、可供智慧體利用相關工具探索的語料子集。由此產生兩項設計意涵：該空間需要由檢索（retrieval）提供邊界，且其中的物件應經過處理以供互動。作為概念驗證，我們提出 RISE（Retrieving Interaction SpacE）：我們使用 BM25 建構互動空間；同時，其中的文件於索引建立（indexing）階段即進行處理，以支援 Shell 風格導航（shell-style navigation）。在 BrowseComp-Plus 上，RISE 以 gpt-5.4-mini 達到與純 Shell DCI 基線相同的 78% 準確率（accuracy），而每查詢成本（per-query cost）僅約四分之一。在 100 萬份文件規模下，RISE-BM25 以 gpt-5.4-mini 達到 81%，而 DCI 在 gpt-5.4-nano 上則下降至 60%，且 100 次中有 33 次發生實際時間失敗（wall-clock failures）。

### 核心貢獻（3～5點）
- 重新定義智慧體搜尋中的檢索角色：從單純選擇文件轉向建構邊界有限的互動空間，使智慧體能在檢索提供的邊界內主動探索。
- 提出互動空間的兩大設計原則：空間邊界由檢索機制提供，且空間內的文件物件需於索引建立階段預處理，以支援後續互動。
- 提出 RISE（檢索互動空間）方法：以 BM25 建構互動空間，並預先處理文件以支援 Shell 風格導航，兼顧檢索效率與語料探索彈性。
- 在 BrowseComp-Plus 基準上達成與純 Shell DCI 基線相當的 78% 準確率，但每查詢成本僅約四分之一，顯著降低計算開銷。
- 驗證百萬級語料庫的擴展性：RISE-BM25 達 81% 準確率，而 DCI 在輕量模型上效能大幅下降且伴隨大量實際時間失敗。

### 適合對象
從事檢索增強式生成（RAG）、智慧體系統與大規模語料

## 深度分析

#### 方法論解析

本文提出一個根本的範式轉移：在 agentic search（智慧體搜尋）中，retrieval（檢索）的角色應從傳統的 snippet selection（片段選擇）——即挑選能塞入 context window（上下文視窗）的短文段——轉變為 constructing an interaction space（建構互動空間）。此 interaction space（互動空間）是一個 bounded subset（有界子集）of the corpus（語料庫），搭配 associated tools（關聯工具），供 agent（智慧體）在視窗外持續探索。

作者從此命題推導出兩個設計後果，並據此建構 RISE（Retrieving Interaction SpacE，檢索互動空間）：

第一，bounded workspace（有限邊界工作區）。檢索系統必須提供一個 explicit persistent set（顯式持久集合），其存在於 context window（上下文視窗）之外，且能以 shell tools（Shell 工具）重複遍歷。這明確排除了三種替代方案：其一，DCI（Direct Corpus Interaction，直接語料庫互動）式的「全語料庫無邊界」設計，因為 absence of a candidate set（缺乏候選集合）會導致每個 grep 指令都淪為 full scan（全掃描）；其二，傳統 snippet retrieval（片段檢索）將證據塞入提示本身，使邊界等同於 context window（上下文視窗）長度；其三，implicit ranking（隱式排序）清單，因為 agent（智慧體）無法以工具重新遍歷之。

第二，navigable objects（可導航物件）。被納入 interaction space（互動空間）的文件必須在 indexing（索引建立）階段即被處理，產生 in-place structural metadata（就地結構性中繼資料），使 shell tools（Shell 工具）能跳躍至 sub-document evidence（子文件層級證據），而無需讀取整份文件。這同樣排除三種形式：raw text（原始文字）迫使任何查詢都得掃描全文；retrieval-time chunks（檢索時區塊）預先決定 agent（智慧體）能看到的證據範圍；summaries（摘要）則喪失 verbatim grounding（原文依據）所需的精確引用能力。

RISE 同時實現上述兩層；而 RISE-BM25 則是僅實現第一層的 boundary-only ablation（僅邊界消融實驗），用於隔離第二層的貢獻。具體實作上，RISE 以 BM25（BM25）作為邊界供應機制，並在 indexing（索引建立）期間為文件注入支援 shell-style navigation（Shell 風格導航）的結構化資訊。

#### 實驗數據解讀

評估採用 BrowseComp-Plus（BrowseComp-Plus）基準，這是一個針對瀏覽式複雜問答的固定語料庫測試。核心結果顯示，RISE 在 gpt-5.4-mini（gpt-5.4-mini）上達到 78% 的 accuracy（準確率），與純 shell 的 DCI baseline（基線）持平，但 per-query cost（每查詢成本）僅約四分之一。這證明「有界互動空間」加上「預處理導航結構」能在維持效能的前提下大幅壓縮開銷。

進一步檢視 ablation（消融實驗）：移除文件處理步驟後的 RISE-BM25（僅保留邊界）在各模型層級上 accuracy（準確率）下降 1–4 個百分點。此差異雖不大，卻明確 isolates the contribution（隔離出貢獻）of consequence (ii)——即 navigable objects（可導航物件）在評估規模下具有穩定的正向效果。

更具說服力的是語料庫規模擴展實驗。當文件數從 100k 擴增至 1M 時，RISE-BM25 在 gpt-5.4-mini（gpt-5.4-mini）上仍維持 81% 的 accuracy（準確率），展現出極佳的穩定性。相對地，DCI 在 gpt-5.4-nano（gpt-5.4-nano）上的 accuracy（準確率）衰退至 60%，且 100 筆查詢中出現 33 次 wall-clock failures（實際時間失敗）。這凸顯 unbounded interaction（無邊界互動）在語料成長時的結構性缺陷：每個廣泛的 shell command（Shell 命令）都是對整個語料庫的掃描，導致 latency（延遲）急遽惡化、tool budget（工具預算）耗盡，最終使 agent loop（智慧體迴圈）無法在時限內完成。

數據的整體意涵是：邊界機制（boundary）解決了 scalability（規模化）問題，而索引期間的結構化處理則在成本與 accuracy（準確率）之間取得最佳平衡。

#### 與現有研究的比較

本文將現有文獻依「檢索返回給智慧體的內容」分為三類，並明確定位 RISE 的差異。

第一類是傳統 RAG（Retrieval-Augmented Generation，檢索增強式生成）與 browser-assisted question answering（瀏覽器輔助問答）管線，如 Lewis et al. [2020]、Nakano et al. [2021] 與 ReAct-style search agents（ReAct 式搜尋智慧體）[Yao et al., 2023]。這類方法將 ranked list of snippets（排序片段清單）塞入 context window（上下文視窗），其根本缺陷是 evidence resolution（證據細緻度）受限：一旦關鍵事實未出現在頂部片段中，agent（智慧體）便無從驗證。

第二類以 DCI [Li et al., 2026b] 為代表，採用 direct corpus interaction（直接語料庫互動），將 raw corpus（原始語料庫）完整暴露給 shell tools（Shell 工具）。這雖然保留了最高解析度，但 unbounded interaction（無邊界互動）不具規模性：每個 grep 都是 full scan（全掃描），語料從 100k 增至 200k 時平均 tool calls（工具呼叫）從 38.5 暴增至 86.9，latency（延遲）與成本翻倍，accuracy（準確率）更大幅下滑。

第三類返回 bounded set of candidate documents（有界候選文件集合），但形式不同。PI-SERINI [Hsu et al., 2026] 與 RISE 同屬此類，皆使用 BM25（BM25）界定 candidate space（候選空間）；然而 PI-SERINI 將其呈現為 cached ranking（快取排序），agent（智慧體）只能分頁瀏覽，無法像 RISE 般以檔案系統語義重新導航。換言之，RISE 是此類別中的 filesystem-workspace variant（檔案系統工作區變體），其物件攜帶 in-place structural metadata（就地結構性中繼資料），支援子文件層級的跳轉。

另一方面，AgentIR [Chen et al., 2026]、Agentic-R [Liu et al., 2026] 與 SAGE [Hu et al., 2026] 等研究聚焦於改進 ranking component（排序元件），例如利用 reasoning traces（推理軌跡）或 multi-turn correctness（多輪正確性）訊號來訓練檢索器。RISE 與這些工作呈 orthogonal（正交）關係：RISE 不改變排序模型本身（刻意維持簡單的 BM25），而是改變 retrieval（檢索）回傳的「物件型態」——從排序清單轉為可互動的工作空間。

本文的主要限制在於僅使用 lexical search（詞彙搜尋）建構邊界，尚未探討 dense retrieval（密集檢索）或學習式稀疏檢索對 interaction space（互動空間）品質的影響。

#### 可重現性評估

就現有文本脈絡而言，作者並未明確提及 open-source code（開源程式碼）、datasets（資料集）或 model weights（模型權重）的釋出狀態。評估所使用的 BrowseComp-Plus（BrowseComp-Plus）基準來自先前研究 [Wei et al., 2025; Chen et al., 2025]，若原始作者已公開該固定語料庫，則資料層面的重現具備基礎；然而 RISE 系統本身的實作細節——特別是 indexing（索引建立）階段如何產生 in-place structural metadata（就地結構性中繼資料）、shell tools（Shell 工具）的具體指令集，以及 agent loop（智慧體迴圈）的 harness（測試架構）參數——在提供的節錄中尚未完整揭露。

BM25（BM25）屬於經典演算法，理論上易於復現；但「為 shell-style navigation（Shell 風格導航）預處理文件」的具體方法（例如是否建立行號索引、段落錨點、或結構化標記）缺乏詳細說明。此外，實驗涉及 gpt-5.4-mini（gpt-5.4-mini）與 gpt-5.4-nano（gpt-5.4-nano）等尚未廣泛公開的模型，其 API 行為與版本差異可能成為重現門檻。綜合而言，在缺乏原始碼與詳細系統設計文件的情況下，本研究的可重現性僅能評估為「部分受限」。

#### 未來研究方向

第一，邊界建構機制的升級。本文刻意採用 BM25（BM25）以證明概念，但未來可探索以 dense retrieval（密集檢索）或學習式稀疏表示作為 boundary supplier（邊界供應器），甚至將 interaction space construction（互動空間建構）與 agent policy（智慧體策略）進行 end-to-end（端到端）聯合訓練。

第二，動態邊界調適。當前 RISE 的邊界在檢索階段即固定；未來可研究在 agent loop（智慧體迴圈）中依據 reasoning traces（推理軌跡）或初步發現，動態收斂或擴展 candidate space（候選空間），結合 AgentIR [Chen et al., 2026] 的嵌入技術或 Agentic-R [Liu et al., 2026] 的全域正確性訊號。

第三，interaction space（互動空間）的物件型態多樣化。除了 shell tools（Shell 工具）與 structural metadata（結構性中繼資料），可引入資料庫查詢介面、圖譜導航、或支援多模態證據（如表格、圖片）的複合式互動空間。

第四，極大規模語料庫的階層式互動空間。當語料達 10M 甚至 100M 文件時，單層 BM25（BM25）邊界可能過於龐大；可研究 hierarchical interaction spaces（階層式互動空間），先以主題或群組建立高層邊界，再於內部展開子空間。

第五，可解釋性與人機協作。讓人類使用者能視覺化 agent（智慧體）所處的 interaction space（互動空間），並在必要時手動調整邊界或標註關鍵文件，以提升 deep research agents（深度研究智慧體）的可信度與可控性。

## 論文問答

**Q1：傳統非智慧體資訊檢索的介面繼承到智慧體搜尋時，其根本限制是什麼？**
A：傳統檢索將智慧體視為被動的閱讀者，每次僅返回一小段經過排序的文件片段，強迫證據必須塞進上下文視窗內。這種片段選擇的典範假設檢索的唯一任務是決定智慧體下一步讀什麼，卻喪失了證據的細緻度與探索彈性。因此，它無法支援智慧體搜尋所需的主動式證據查核與多步驟語料探索。

**Q2：直接語料庫互動（DCI）在語料規模擴大時為何無法有效擴展，其結構性成本為何？**
A：DCI 將整個原始語料庫毫無邊界地暴露給 Shell 工具，導致每一次廣泛的 grep 命令都相當於對全語料庫進行全掃描。當語料從 10 萬擴增到 20 萬文件時，平均工具呼叫次數從 38.5 暴增到 86.9，延遲與成本隨之翻倍，準確率更下滑 13.6 個百分點。這種結構性成本使得智慧體在語料變大時，必須耗費大量預算去分類 Shell 輸出，而非真正用於回答問題。

**Q3：為何作者認為建構「互動空間」是智慧體搜尋中檢索角色的典範轉移？**
A：作者主張檢索不應僅挑選能塞進 LLM 上下文視窗的文件，而應建構一個有邊界、可探索且附帶工具的互動空間。這種重新定位將智慧體從固定證據視窗的被動消費者，轉變為可在語料中主動探索的行動者。透過提供邊界與經過互動處理的物件，檢索從單純的排序機制成為支撐智慧體探索的基礎設施。

**Q4：RISE 的兩個運作層次為何，它們如何對應到作者提出的設計後果？**
A：第一層是「有邊界的工作空間」，實現了設計後果（i）：以 BM25 建構一個明確且持續存在的候選文件集合，使其存在於上下文視窗之外，並能以 Shell 工具重新遍歷。第二層是「可導航的物件」，實現了設計後果（ii）：在索引建立階段就對文件進行處理，附加就地結構性中繼資料，讓 Shell 工具無需讀取整份文件即可跳轉到相關片段。這兩層共同將檢索從片段遞送服務轉變為可供智慧體操作的檔案系統工作空間。

**Q5：RISE 與同樣返回有邊界候選集合的 PI-SERINI 有何關鍵差異？**
A：PI-SERINI 雖然也使用 BM25 來限制候選集合，但它將該集合呈現為快取的排序清單，智慧體只能逐頁瀏覽。相較之下，RISE 返回的是一個有邊界且可重新探索的互動空間，其中的物件帶有就地結構性中繼資料，支援 Shell 風格導航與子文件層級的跳轉。因此，RISE 屬於檔案系統工作空間的變體，智慧體能在其中使用原生工具主動操作，而非被動接收排序結果。

**Q6：作者為何刻意選擇簡單的 BM25，而非採用密集檢索或學習式排序器？**
A：作者刻意維持 BM25 的簡潔，是為了隔離「檢索究竟返回什麼」這一變因，也就是互動空間的介面設計，而非改進排序元件本身。這種正交設計證明了即使基礎的詞彙搜尋，只要搭配經過互動處理的物件，就能成為有效的邊界供應者。此選擇顯示從排序清單到可導航工作空間的典範轉移，並不依賴於排序技術的複雜度。

**Q7：作者為何選擇 BrowseComp-Plus 作為評估基準，它測量了什麼能力？**
A：BrowseComp-Plus 是針對智慧體搜尋機制設計的困難瀏覽複雜度評估基準，它以固定語料庫取代不透明的即時網頁搜尋，使不同系統的檢索選擇具有可比性。該基準測試智慧體在受控環境下執行多步驟證據收集與綜合回答的能力。採用此基準讓作者能在擴充語料規模的同時，公平比較 RISE 與 DCI 基線的穩健性。

**Q8：RISE 與純 Shell 的 DCI 基線相比，在準確率與成本上的關鍵結果為何？**
A：在 BrowseComp-Plus 上，RISE 使用 gpt-5.4-mini 達到 78% 的準確率，與純 Shell 的 DCI 基線持平，但每查詢成本僅約為四分之一。這顯示為互動空間設置邊界並不會犧牲答案品質，卻能顯著提升效率。此結果驗證了建構互動空間是兼顧效能與成本的有效替代方案。

**Q9：RISE 與 RISE-BM25 的比較，揭示了文件互動處理的哪些貢獻？**
A：RISE-BM25 是僅實現邊界（後果 i）的消融實驗，在 10 萬文件規模下，其準確率比完整 RISE 低 1 至 4 個百分點。這隔離了後果（ii）——即為互動而處理物件——的具體貢獻，顯示就地結構性中繼資料能帶來可測量的增益。然而，在 100 萬文件時 RISE-BM25 仍維持 81% 準確率，而 DCI 卻大幅退化並出現大量實際時間失敗，這說明邊界本身才是規模化時的決定性因素。

**Q10：在哪些真實應用場景中，RISE 會比傳統 RAG 或 DCI 系統更具優勢？**
A：RISE 特別適合企業知識庫或法律研究等擁有百萬級文件、且智慧體必須進行深度多步驟查核的場景。相較於傳統 RAG，它保留了在上下文視窗之外探索原文依據的能力；相較於 DCI，它避免智慧體在廣泛掃描時被無關的 Shell 輸出淹沒。任何需要可擴展、低成本且具備精確來源歸因的智慧體搜尋領域，都能受惠於這種有邊界的工作空間設計。

**Q11：部署 RISE 相較於維護完整 DCI 管線時，工程師需考量哪些權衡取捨？**
A：工程師必須權衡索引建立階段處理文件與儲存結構性中繼資料的前置成本，以及後續每次查詢所節省的成本與延遲改善。RISE 需要設計並維護能解讀就地中繼資料的 Shell 工具，這相較於直接存取原始文字增加了智慧體套件的複雜度。然而，工具呼叫次數的大幅降低，以及大規模時實際時間失敗的消除，顯示這項基礎設施投資對於服務大型語料庫的生產系統而言是值得的。

**Q12：「互動空間」的概念可能如何影響未來檢索增強式生成與深度研究智慧體的研究方向？**
A：互動空間的概念將研究社群的焦點從開發更好的排序演算法，轉向設計更優秀的語料介面與智慧體環境邊界。這暗示檢索與智慧體套件的設計應該共同演進，因為檢索物件的形式決定了智慧體能有效使用哪些工具。未來研究可能探索自適應邊界、學習式互動空間，或結合片段遞送與可導航工作空間的混合介面，以因應不同複雜度的查詢。

**Q13：論文在 RISE 的評估範圍或方法上，承認了哪些限制？**
A：論文主要在 BrowseComp-Plus 上以特定模型層級進行評估，因此對於其他基準、領域或更強大前沿模型的泛化性仍屬未知。文件處理步驟的描述偏向概念層次，且結構性中繼資料的具體形式並未與其他替代方案進行詳盡比較。此外，研究聚焦於 Shell 風格導航，這可能無法涵蓋多模態或結構化資料環境中所有相關的互動典範。

**Q14：在哪些條件下，RISE 可能相對於無邊界 DCI 或密集檢索方法表現較差或失敗？**
A：若初始 BM25 邊界未能將任何相關文件檢索進互動空間，智慧體將被根本地限制，無法像 DCI 那樣透過全語料庫掃描來挽回。對於需要在看似無關的文件間進行偶然發現的查詢，明確邊界可能排除掉理論上無邊界 grep 能找到的關鍵證據。此外，若結構性中繼資料處理遺漏了某些細微語意或未能索引特定片段類型，Shell 工具可能錯失原始檔案讀取能捕捉到的子文件證據。

**Q15：從 RISE 框架出發，未來有哪些自然延伸的研究方向？**
A：未來研究可探索自適應或動態邊界，讓互動空間能根據智慧體的推理軌跡動態擴張或收縮，而非僅依賴單次初始檢索。研究者亦可發展針對特定智慧體工具套件生成最佳結構性中繼資料的學習式文件處理技術，超越本文概念驗證階段的索引設計。另一個有前景的方向是將 RISE 與 AgentIR 或 Agentic-R 等訓練過的智慧體檢索器整合，同時結合精緻排序與互動空間介面，以兼顧邊界品質與可導航性。

## 實務應用指南

### 適用場景

1. **企業內部知識庫深度研究**  
   當組織累積數十萬至百萬級內部文件（技術規格、會議紀錄、產品文件），傳統片段檢索（Snippet Retrieval）無法讓智慧體逐層推敲，而直接開放完整語料庫的 Shell 權限又會導致每查詢都觸發全掃描。RISE 可為智慧體建立一個以 BM25 邊界劃定的互動空間，讓它在有限候選空間內以 Shell 風格導航，兼顧探索深度與每查詢成本。

2. **法律與合規盡職調查**  
   律師或法務團隊需從大量合約、判決書與監管文件中交叉比對條文。此場景要求**原文依據**（Verbatim Grounding），不能僅依賴摘要。RISE 在索引階段預先嵌入結構性中繼資料（如條款編號、段落錨點），使智慧體能直接跳轉到特定條文，避免讀取整份文件，同時保留精確引用能力。

3. **技術文件與程式碼庫探索**  
   開發者希望智慧體能在大型 API 文件或程式碼庫中自主查找函式定義、範例與相依關係。RISE 將語料庫視為可導航的檔案系統工作區，透過就地（In-Place）結構標記（如函式簽名、標題錨點）支援 `grep` 與區段讀取，讓智慧體在長上下文處理時不必反覆載入無關檔案。

4. **學術文獻回顧與綜整**  
   研究助理型智慧體需在百萬篇論文集中追蹤實驗數據與方法論。RISE 提供的互動空間讓智慧體先以詞彙搜尋縮小候選範圍，再於邊界內反覆檢索、比對與收斂，解決固定證據視窗（Fixed Evidence Window）無法回溯的問題。

5. **大規模客戶服務歷史紀錄分析**  
   客服中心累積大量歷史工單與對話紀錄。RISE 可針對每張新工單動態建構互動空間，讓智慧體在相關歷史案例中游標式探索，找出過去類似問題的處理脈絡，而非一次性塞入上下文視窗（Context Window）導致雜訊過高。

### 實作前置條件

**資料面**
- 已清洗的原始語料庫（Raw Corpus），建議預先處理為純文字或結構化格式（如 Markdown、JSON）。
- 文件層級的中繼資料（標題、時間、類別），用於強化 BM25 邊界篩選。
- 若需評估效果，需準備類似 BrowseComp-Plus 的硬瀏覽複雜度測試集，包含需要多步驟探索才能回答的問題。

**運算面**
- 索引建立（Indexing）叢集：需支援全文索引引擎（如 Elasticsearch、OpenSearch 或輕量級替代方案）以執行 BM25 檢索。
- 文件處理管線：額外運算資源用於抽取結構性中繼資料（標題樹、段落錨點、實體位置），並寫入索引側欄位。
- LLM 推論端點：支援函式呼叫（Function Calling）或工具呼叫（Tool Calls）的模型 API（如 gpt-5.4-mini 等級），以及足夠的工具預算（Tool Budget）配額。
- 沙箱化執行環境：因智慧體將操作 Shell 工具，需容器化（如 Docker/Kata Containers）以隔離檔案系統權限。

**技術與人力面**
- 具備資訊檢索（IR）基礎的後端工程師，熟悉詞彙搜尋與排序函數。
- 熟悉智慧體迴圈（Agent Loop）設計的 AI 工程師，能實作 ReAct 式推理與工具回傳解析。
- DevOps 能力：維護索引叢集、監控延遲（Latency）與每查詢成本（Per-Query Cost）。

---

### 實作步驟建議

**Step 1：定義互動空間的邊界策略**  
從產品需求出發，決定 BM25 回傳的候選空間大小（例如 Top-K 文件數）。這是論文中「後果 (i)」的產品化：邊界不能太鬆（否則退化成 DCI 全掃描），也不能太緊（否則遺失證據）。建議從 100–500 份文件開始實驗，並以召回率為錨點調整。

**Step 2：建構雙層索引管線**  
第一層建立標準 BM25 索引，支援全文檢索；第二層在索引階段為每份文件注入結構性中繼資料。例如：解析 HTML/Markdown 標題樹產生行號對照表、標記表格與列表邊界、抽取關鍵實體位置。這對應論文中「後果 (ii)」：讓物件在放入互動空間前即具備導航能力。

**Step 3：設計受限 Shell 工具組**  
不要直接給予智慧體無限制的 `grep` 與 `cat`。改為提供三類工具：
- `search_in_space(query)`：僅在 BM25 劃定的互動空間內搜尋。
- `jump_to_anchor(doc_id, anchor)`：根據結構性中繼資料跳轉到文件內特定錨點。
- `read_span(doc_id, start_line, end_line)`：讀取指定行號範圍，避免全檔案讀取。
這確保智慧體的每次操作都落在有限候選空間內。

**Step 4：整合智慧體迴圈**  
將 RISE 嵌入 ReAct 或類似架構。檢索器不再回傳片段，而是回傳一個「工作區路徑」與可用工具清單。智慧體的觀察（Observation）來自於對工作區的 Shell 操作，而非預先擷取的上下文。實作時需處理工具輸出的分頁與截斷，防止單次回傳過長。

**Step 5：建立成本與準確率的監控儀表板**  
追蹤三項指標：準確率（Accuracy）、平均工具呼叫次數、每查詢成本。論文顯示在 1M 文件規模下，純 DCI 會出現實際時間失敗（Wall-Clock Failures）與準確率驟降，因此產品化時必須設定硬性工具預算（Maximum Tool Budget）與逾時中斷機制。

**Step 6：漸進式擴量與 A/B 測試**  
先以 100k 文件規模驗證 RISE-BM25（僅邊界）與完整 RISE（邊界＋導航物件）的差異，確認結構性中繼資料帶來 1–4 點準確率提升後，再擴展至 1M 文件。同時與現有片段檢索基線進行 A/B 測試，觀察在複雜多跳問題上的勝率。

### 潛在風險與注意事項

- **邊界過緊導致召回損失**：若 BM25 初始篩選過於嚴格，智慧體可能根本無法在互動空間內找到答案。建議保留一條「擴大邊界」的逃生通道（例如當空間內工具呼叫多次無果時，允許一次性的外部檢索擴充）。
- **索引成本與儲存膨脹**：結構性中繼資料的預處理會增加索引體積與建立時間。需評估中繼資料的顆粒度——過細（逐字索引）會爆炸，過粗（僅章節）則失去跳轉意義。
- **安全性與沙箱隔離**：提供 Shell 工具給智慧體本質上具有風險。即使操作範圍被限制在互動空間，也必須透過唯讀掛載、禁止網路呼叫與命令注入過濾，確保智慧體無法逃逸至宿主系統。
- **模型行為偏差**：輕量級模型（如 gpt-5.4-nano）在面對大量 Shell 輸出時，可能傾向於「 triaging shell output rather than answering」。需在提示工程（Prompt Engineering）中明確限制反覆試錯次數，並要求模型在證據充分時盡早作答。
- **延遲與使用者體驗的權衡**：雖然 RISE 降低了每查詢成本，但智慧體的多輪 Shell 互動仍可能使端到端延遲達到數十秒。產品介面應設計進度指示（如「正在檢視第 3 份文件…」），避免使用者因等待而中斷對話。

### 與其他技術的整合建議

- **現有 RAG 管線**：RISE 可視為「檢索增強式生成」的進化版，直接替換原有的 Retriever 與上下文組裝（Context Assembly）層。保留原有的生成模型與後處理邏輯，僅將輸入從「片段清單」改為「可導航工作區」。
- **全文搜尋引擎**：無需捨棄現有的 Elasticsearch 或 OpenSearch 投資。將其作為 BM25 邊界層，並利用 Ingest Pipeline 或外掛程式在索引階段注入結構性中繼資料，即可快速產品化。
- **Agent 開發框架**：無論使用 LangChain、LlamaIndex 或自研框架，只需自定義一個 `RISETool` 類別，封裝「建立互動空間＋執行 Shell 導航」的邏輯，即可嵌入現有的 ReAct / Plan-and-Solve 迴圈。
- **向量資料庫**：RISE 的核心邊界使用詞彙搜尋（Lexical Search），但向量資料庫可作為輔助召回手段。例如先用向量檢索擴充 BM25 的候選空間（Hybrid Retrieval），再於 RISE 框架內進行 Shell 導航，兼顧語意相關性與導航效率。
- **Coding Agent 平台**：若產品本身已具備讓智慧體操作檔案系統的能力（如 IDE 外掛或 Devin 類平台），RISE 的互動空間可映射為一個臨時掛載的目錄，讓智慧體使用原生工具（Native Tools）直接操作，降低整合門檻。

### 給不同背景讀者的閱讀建議

**給初學者**：這篇論文的核心概念是「檢索器不該只丟給智慧體一段文字，而應該給它一個有圍牆的工作區」。請把重點放在第一段與第三段的動機說明，理解為什麼「給太多（整個語料庫）」和「給太少（片段）」都不好，而「給一個有邊界、可探索的空間」才是平衡點。不需要一開始就深入 BM25 的數學或 Shell 指令的實作細節。

**給 AI 工程師**：請聚焦於方法章節的兩層架構——(i) 邊界層與 (ii) 導航物件層。你需要理解如何將現有索引管線改造成「索引時即產生結構性中繼資料」，以及如何設計受限的 Shell 工具 API 來防止全掃描。實驗章節中關於 gpt-5.4-mini 與 gpt-5.4-nano 在不同語料規模下的成本與準確率曲線，是你評估是否值得在產品中導入 RISE 的關鍵依據。

**給研究人員**：本文的理論貢獻在於重新定義了「智慧體搜尋中的檢索角色」——從片段選擇（Snippet Selection）轉向互動空間建構（Interaction Space Construction）。請仔細閱讀作者如何透過「排除法」論證邊界與導航物件的必要性，以及 RISE-BM25 消融實驗如何隔離兩個設計後果的個別貢獻。未來工作可思考：能否以學習型檢索器（如 Agentic-R）取代 BM25 作為邊界供應者？能否將互動空間的邊界動態調整納入智慧體的推理軌跡？

**給產品經理**：這篇論文提供了一個明確的商業權衡框架：在維持準確率的前提下，如何隨語料規模擴大控制每查詢成本與延遲。請注意 1M 文件規模下，純 Shell 方案（DCI）出現 33% 實際時間失敗，而 RISE 仍維持 81% 準確率。你的決策重點在於：當產品從「問答型 RAG」走向「深度研究型 Agent」時，是否願意投入索引前置成本，換取智慧體在超大語料上的可擴展性與穩定性。

| Interaction space | 互動空間 | 檢索系統為智慧體建構的有限邊界探索範圍 |
| Latency | 延遲 | 查詢回應的實際等待時間 |
| Lexical search | 詞彙搜尋 | 基於字詞匹配的檢索方式 |
| Long-context processing | 長上下文處理 | 處理長文本輸入的模型能力 |
| Maximum tool budget | 最大工具預算 | 單次查詢允許的工具呼叫次數上限 |
| Native tools | 原生工具 | 作業系統或執行環境內建的工具 |
| Non-agentic information retrieval | 非智慧體資訊檢索 | 傳統由檢索器主導、智慧體被動接收結果的模式 |
| Per-query cost | 每查詢成本 | 處理單一查詢的計算開銷 |
| Raw corpus | 原始語料庫 | 未經處理的文件集合 |
| ReAct-style search agents | ReAct 式搜尋智慧體 | 結合推理（Reasoning）與行動（Acting）的代理架構 |
| Retrieval-augmented generation | 檢索增強式生成 | RAG，結合外部檢索與語言生成的架構 |
| Retrieval-time chunks | 檢索時區塊 | 在檢索階段預先切分的文本片段 |
| RISE (Retrieving Interaction SpacE) | RISE（檢索互動空間） | 本文提出的方法，以 BM25 建構互動空間並預處理文件 |
| Shell-style navigation | Shell 風格導航 | 以命令列方式在語料中移動與探索 |
| Shell tools | Shell 工具 | 命令列層級的語料操作工具總稱 |
| Snippet retrieval | 片段檢索 | 只返回文件片段的傳統檢索方式 |
| Snippet selection | 片段選擇 | 挑選適合放入提示的短片段 |
| Structural metadata | 結構性中繼資料 | 附加於文件、輔助快速跳轉的結構化資訊 |
| Tool budget | 工具預算 | 智慧體可發出工具呼叫的總額度 |
| Tool calls | 工具呼叫 | 智慧體對外部工具的使用次數 |
| Verbatim grounding | 原文依據 | 以逐字原文作為證據基礎，保留精確引用 |
| Wall-clock failures | 實際時間失敗 | 在實際經過時間內未完成而導致的失敗（如逾時） |
