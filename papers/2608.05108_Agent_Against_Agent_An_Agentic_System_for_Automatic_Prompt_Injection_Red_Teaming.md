# 智慧體對抗智慧體：用於自動化提示注入紅隊測試的智慧體系統

**原文標題：** Agent Against Agent: An Agentic System for Automatic Prompt Injection Red Teaming  
**作者：** Yanting Wang、Chenlong Yin、Runpeng Geng 等 4 位作者  
**發布日期：** 2026-08-05

## ⚡ TL;DR

本文解決現有提示注入紅隊測試方法對新目標模型泛化性差、查詢成本高，且難以累積攻擊知識的問題。
作者提出PIMiner智慧體系統，透過策略庫與分層記憶機制，將攻擊經驗轉化為可重複使用的策略。
在IPIArena與AgentDojo上，PIMiner對多個前沿模型僅需約十次查詢即達高攻擊成功率。

---

## 摘要翻譯

提示注入（prompt injection）對大型語言模型（Large Language Model, LLM）智慧體（agent）構成重大安全風險。因此，高效且有效的紅隊測試（red-teaming）至關重要，無論是用於評估這些風險，或是收集訓練資料以強化防禦。現有的最先進提示注入紅隊測試方法主要依賴強化學習（Reinforcement Learning, RL），所產生的攻擊者模型（attacker model）往往難以泛化至新的目標大型語言模型（target LLM）。在本研究中，我們開發了 PIMiner，一個用於提示注入紅隊測試的智慧體系統。在訓練階段，PIMiner 以一系列的（資料集、目標模型）配對進行訓練，並從頭建立策略庫（strategy library）。在測試階段，學習到的策略庫可直接遷移（transfer）至先前未見過的目標大型語言模型，無需額外訓練。對於每個測試樣本（test sample），PIMiner 僅需對目標智慧體（target agent）進行少量查詢（query）（例如 10 次）。實驗結果顯示，PIMiner 展現優異的表現。在 IPIArena 上，它對 Gemini-2.5-Pro 達到 76.2% 的攻擊成功率（Attack Success Rate, ASR），對 GPT-5.1 達到 61.9% 的 ASR，對 Claude-Sonnet-4.5 達到 42.9% 的 ASR。在 AgentDojo 上，它對 Gemini-2.5-Pro 達到 86.7% 的 ASR，對 GPT-5.1 達到 53.3% 的 ASR，對 Claude-Sonnet-4.5 達到 40.0% 的 ASR。

### 核心貢獻（3～5點）
- 提出 PIMiner，一個專為提示注入紅隊測試設計的智慧體系統，能自動生成並精煉攻擊策略。
- 在訓練過程中，PIMiner 透過多組（資料集、目標模型）配對從頭建立可重複使用的策略庫。
- 學習到的策略庫具備良好的可遷移性（transferability），可直接應用於未見過的目標大型語言模型，無需額外訓練。
- 每個測試樣本僅需極少量查詢（例如 10 次），在運算預算（compute budget）有限的情況下仍具實用性。
- 在 IPIArena 與 AgentDojo 兩大基準測試（benchmark）上，對 Gemini-2.5-Pro、GPT-5.1 與 Claude-Sonnet-4.5 等前沿大型語言模型（frontier LLM）均達到高攻擊成功率。

### 適合對象
本論文適合對大型語言模型安全、智慧體對齊（alignment）、紅隊測試與對抗防禦感興趣的研究人員與工程師，特別是關注提示注入攻擊自動化、攻擊策略可遷移性，以及如何在低查詢成本下評估自主智慧體（autonomous agent）穩健性（robustness）的讀者。

## 深度分析

#### 方法論解析

本研究提出的 **PIMiner** 是一個以 **agentic system（智慧體系統）** 形式運作的 **prompt injection（提示注入）** **red-teaming（紅隊測試）** 框架。其核心設計理念是：將過往攻擊經驗轉化為可重複使用的攻擊知識，並透過層級式記憶機制加以組織，從而彌補 **search-based approaches（基於搜尋的方法）** 無法累積知識的缺陷，同時避免 **reinforcement learning (RL)（強化學習）** 方法在訓練階段需要大量 **query（查詢）** 與對新 **target LLM（目標大型語言模型）** 泛化性差的問題。

##### 問題設定

在訓練階段，PIMiner 觀察一連串的 **(dataset, target model)（資料集、目標模型）** 配對：

\[
\mathcal{T} = \{(\mathcal{D}_t, \mathcal{M}_t)\}_{t=0}^{T-1}
\]

例如 \((\text{AgentDojo}_{tr}, \text{GPT-5-nano})\)。系統在這些配對上逐步建立 **strategy library（策略庫）**。在測試階段，面對一個先前未見過的 **target model（目標模型）**，PIMiner 可直接轉移已學得的策略庫，無需額外訓練，且每個 **test sample（測試樣本）** 僅需約 10 次對目標智慧體的查詢。

##### 四大核心元件

PIMiner 由以下四個主要元件組成：

1. **Strategy Library（策略庫）**  
   這是系統的長期記憶，儲存從過去攻擊經驗中萃取出的可重用 **attack patterns（攻擊模式）**。策略庫並非預先定義，而是從零開始自動建構，並隨著處理更多資料集與目標模型而不斷擴充與精煉。

2. **Strategy Router（策略路由器）**  
   針對每一個測試樣本，router 會從策略庫中選出最相關的攻擊策略。這相當於在長期記憶中進行檢索，確保後續攻擊生成有適當的先驗知識作為引導。

3. **Iterative Attack Module（迭代攻擊模組）**  
   此模組負責在少量迭代內（例如 10 步）逐步精煉注入提示。該模組具備三層記憶結構：
   - **Long-term memory（長期記憶）**：來自策略庫的已路由策略檔案。
   - **Intra-dataset memory（資料集內記憶）**：針對同一組 **dataset–model pair（資料集–模型配對）**，濃縮先前樣本的攻擊經驗。
   - **Intra-sample memory（樣本內記憶）**：記錄當前樣本的攻擊歷史，用於在單一樣本內進行局部調整。

   這三層記憶由粗到細，兼顧跨任務、跨樣本與單次攻擊軌跡的知識累積。

4. **Experience Digestor（經驗消化器）**  
   當所有樣本攻擊完成後，digestor 分析攻擊結果，更新策略庫。這個閉迴路機制讓 PIMiner 在面對新目標時，能持續將成功與失敗經驗轉化為結構化知識。

##### 方法論特色

PIMiner 的關鍵創新在於將「攻擊歷史」轉化為「可遷移策略」，而非像 RL 方法那樣將知識內化於 **attacker model（攻擊者模型）** 的權重中。這帶來幾項優勢：

- **可遷移性（transferability）**：策略庫以顯式形式儲存，可跨不同 **target LLM（目標大型語言模型）** 與 **attacker LLM（攻擊者大型語言模型）** 直接套用。
- **資料效率**：測試時每樣本僅需少量查詢，遠低於 RL 方法在訓練期間動輒數萬次的互動。
- **模組化與可解釋性**：策略庫的內容可被檢視與審計，有助於理解何種 **malicious instructions（惡意指令）** 模式對特定模型有效。

然而，作者也坦承，由於 red-teaming 任務的評估成本極高，PIMiner 採用 **heuristic design（啟發式設計）**，而非透過自動化智慧體優化框架來搜尋架構。

#### 實驗數據解讀

本研究在兩個主流的 agent prompt injection **benchmark（基準測試）** 上進行評估：**IPIArena** 與 **AgentDojo**，並針對多個 **frontier LLM（前沿大型語言模型）** 進行測試，包括 Gemini-2.5-Pro、GPT-5.1、Claude-Sonnet-4.5 等。評估指標為 **ASR (Attack Success Rate)（攻擊成功率）**。

##### IPIArena 結果

| Target LLM | ASR |
|---|---|
| Gemini-2.5-Pro | 76.2% |
| GPT-5.1 | 61.9% |
| Claude-Sonnet-4.5 | 42.9% |

##### AgentDojo 結果

| Target LLM | ASR |
|---|---|
| Gemini-2.5-Pro | 86.7% |
| GPT-5.1 | 53.3% |
| Claude-Sonnet-4.5 | 40.0% |

##### 數據解讀

1. **Gemini-2.5-Pro 相對脆弱**  
   在兩個基準測試中，Gemini-2.5-Pro 的 ASR 均最高（IPIArena 76.2%、AgentDojo 86.7%）。這可能顯示該模型在面對經過策略引導的提示注入時，對 **untrusted context sources（不受信任的上下文來源）** 的防禦較弱，或其對於隱藏於正常任務中的惡意指令較難區分。

2. **GPT-5.1 表現居中**  
   GPT-5.1 的 ASR 分別為 61.9% 與 53.3%，顯示其具備一定程度的穩健性，但仍有一半以上的測試樣本可被成功攻擊。這也暗示即使經過對齊與安全微調，現有 frontier LLM 在 agent 場景中仍難以完全抵禦提示注入。

3. **Claude-Sonnet-4.5 相對穩健**  
   Claude-Sonnet-4.5 的 ASR 最低（IPIArena 42.9%、AgentDojo 40.0%）。這可能反映 Anthropic 在模型對齊與提示注入防禦上的投入，但 40% 左右的攻擊成功率仍然相當高，顯示仍有顯著風險。

4. **AgentDojo 上整體 ASR 更高**  
   相較於 IPIArena，PIMiner 在 AgentDojo 上對 Gemini-2.5-Pro 與 GPT-5.1 的攻擊成功率明顯更高。這可能與兩個基準的任務設計、工具呼叫複雜度或評分標準有關，也可能代表 AgentDojo 的某些樣本更容易受到策略庫中累積的攻擊模式影響。

5. **少量查詢即可達成高攻擊成功率**  
   每個測試樣本僅需約 10 次查詢即可達到上述 ASR，這在實務上極具威脅性，因為攻擊者無需大量互動即可有效操控 **autonomous agents（自主智慧體）**。

#### 與現有研究的比較

##### RL-based Approaches（基於強化學習的方法）

- **RL-Hammer** 與 **PISmith** 透過 RL 訓練攻擊者模型，能在特定資料集與目標模型上達到強大攻擊效果。
- 然而，這類方法需要與目標智慧體進行數萬次互動才能收斂，運算成本高。
- 更關鍵的是，學得的攻擊模式對新 **target LLM** 的 **transferability（可遷移性）** 有限。
- **GPT-Red** 雖然透過多樣化 defender agents（防禦者智慧體）提升泛化能力，但需要相當於完整 RL 後訓練的 **compute budget（運算預算）**，門檻極高。

相較之下，PIMiner 不將知識儲存在模型權重中，而是儲存在可讀取、可轉移的策略庫裡，因此能在未見過的目標模型上直接套用，且測試查詢量極低。

##### Search-based Approaches（基於搜尋的方法）

- **TAP**、**PAIR** 等方法針對每個測試樣本獨立優化攻擊，無需訓練攻擊者模型。
- 但它們每次都從頭開始搜尋，無法系統性地累積與重用攻擊知識，因此效果通常遜於 RL 方法。
- **Strategy-based Search** 與 **DTap-Red** 雖然引入策略庫，但這些策略庫是預先定義的，不會隨新任務動態更新。

PIMiner 的差異化在於：策略庫是從攻擊經驗中自動發現並持續更新的，能夠跨不同使用者任務、注入任務與目標模型進行知識累積。

##### Jailbreak 領域的相關工作

- **AutoDAN-Turbo** 在 **jailbreak（越獄）** 領域維護並更新策略庫，但 jailbreak 與 prompt injection 在本質上不同：jailbreak 策略主要依賴有害目標，而 prompt injection 策略必須同時考量 benign user task（良性使用者任務）與 injected malicious task（注入的惡意任務）。

因此，PIMiner 的策略庫設計必須更細緻地建模兩種任務之間的衝突與掩飾關係。

##### 主要貢獻與限制

**主要貢獻：**
- 提出首個針對 prompt injection 的 agentic red-teaming 系統，結合搜尋方法的低訓練成本與 RL 方法的知識累積能力。
- 在 IPIArena 與 AgentDojo 上對多個 frontier LLM 達到高 ASR，並展現跨目標與跨攻擊者模型的可遷移性。

**限制：**
- 採用啟發式設計，部分元件（如 router 與 digestor）的設計選擇依賴人工經驗，未經大規模自動化搜尋驗證。
- 實驗主要集中於英文與文字型 agent 任務，對於多語言、多模態或更複雜工具鏈的泛化性尚需驗證。
- 策略庫的品質高度依賴過往經驗的多樣性與 digestor 的萃取能力，若初期經驗不足，可能影響後續表現。

#### 未來研究方向

1. **結合 RL 與策略庫的混合式方法**  
   未來可探索將 PIMiner 的策略庫作為 RL 的初始知識來源，或利用 RL 進一步優化 router 與 digestor，兼顧知識累積與策略發現能力。

2. **自動化智慧體架構搜尋**  
   隨著評估成本下降，可嘗試以自動化框架（如 agent optimization）搜尋更優的記憶結構、路由演算法與消化機制，減少對啟發式設計的依賴。

3. **對抗動態防禦機制**  
   現有防禦如 **guardrail models（護欄模型）**、輸入過濾與異常檢測會不斷演進。未來研究可讓 PIMiner 在對抗環境中持續更新策略庫，形成攻擊者與防禦者之間的動態博弈。

4. **跨語言與跨模態擴展**  
   將策略庫擴展至多語言提示注入、多模態輸入（如圖像、PDF、網頁截圖）以及更複雜的 **external tools（外部工具）** 互動場景。

5. **理論理解與可解釋性**  
   深入分析策略庫中哪些語義或結構模式對特定模型家族有效，並建立 prompt injection 脆弱性的理論模型，有助於設計更穩健的 **backbone LLMs（骨幹大型語言模型）**。

6. **應用於防禦性訓練資料生成**  
   PIMiner 產生的成功攻擊可作為高品質 **training datasets（訓練資料集）**，用於微調護欄模型或改善模型 **alignment（對齊）**，形成紅隊測試與安全強化的正向循環。

7. **降低攻擊查詢足跡**  
   雖然 PIMiner 已將測試查詢降至約 10 次，但在某些高風險場景中，即使少量查詢也可能被偵測。未來可研究單次或少次查詢即可成功的攻擊策略，並相應設計防禦機制。

## 論文問答

**Q1：什麼是提示注入攻擊，為何它對大型語言模型智慧體構成重大安全風險？**
A：提示注入攻擊是指對抗者將惡意指令嵌入不受信任的上下文來源，例如網頁、檢索文件或工具輸出，藉此操縱自主智慧體的行為。由於現代大型語言模型智慧體能夠與外部工具互動、檢索資訊並在動態環境中自主執行動作，一旦處理了被污染的內容，就可能偏離原本的使用者任務。這類攻擊不僅可能洩漏敏感資訊，還可能導致未經授權的操作，因此對部署於真實應用中的智慧體構成嚴重的安全威脅。

**Q2：現有的強化學習方法與基於搜尋的方法在提示注入紅隊測試上各有什麼缺陷？**
A：現有的紅隊測試方法主要分為基於強化學習與基於搜尋兩大類，但各自存在明顯缺陷。強化學習方法雖然攻擊效果較強，卻需要在訓練過程中與目標智慧體進行數萬次互動，且學到的攻擊模式對新目標大型語言模型的可遷移性有限。相對地，基於搜尋的方法雖然無需訓練攻擊者模型，但每個測試樣本都從頭開始搜尋，無法累積並重用先前的攻擊知識，因此整體效果通常不如強化學習方法。

**Q3：為何有效的紅隊測試不僅對安全評估重要，對模型訓練也具有關鍵價值？**
A：有效的紅隊測試不僅能系統化評估部署系統中的提示注入漏洞，還能產生高品質的訓練資料集。這些資料集可用於微調護欄模型、改善骨幹大型語言模型的對齊，以及訓練更強大的攻擊者模型以支援未來的紅隊測試工作。因此，自動化攻擊生成流程已成為主要人工智慧公司強化部署系統、進行基準測試與識別潛在弱點的關鍵手段。

**Q4：PIMiner 的核心構想是什麼，它與既有方法的主要差異為何？**
A：PIMiner 的核心構想是將攻擊歷史轉化為可重複使用的攻擊知識，並透過層級式記憶機制加以組織。與強化學習方法不同，PIMiner 不需要針對每個新目標模型重新訓練攻擊者模型；與傳統基於搜尋的方法不同，它不會在每個樣本上從頭開始。這種設計讓 PIMiner 能夠在面對未見過的目標大型語言模型時，直接轉移已學習的策略庫，同時只需少量查詢即可達到強大的攻擊效果。

**Q5：PIMiner 包含哪四個主要元件，它們之間如何協同運作？**
A：PIMiner 由四個主要元件組成：策略庫、策略路由器、迭代攻擊模組與經驗消化器。策略路由器會先為每個樣本選擇最相關的攻擊策略；迭代攻擊模組則在少數幾個步驟內逐步精煉攻擊。當所有樣本攻擊完成後，經驗消化器會分析攻擊結果並更新策略庫，使系統隨著應用於更多目標大型語言模型與智慧體資料集而變得更加全面。

**Q6：PIMiner 的三層記憶機制分別是什麼，為何這種設計對攻擊效果至關重要？**
A：PIMiner 採用三層記憶機制：長期記憶來自策略庫中的策略檔案、資料集內記憶儲存同一資料集與目標模型配對下先前樣本的濃縮經驗、樣本內記憶則記錄當前樣本的攻擊歷史。這種層級設計讓系統能同時掌握跨任務的通用攻擊模式、同一資料集內的局部規律，以及針對單一樣本的微調軌跡。因此，PIMiner 不僅能累積可遷移的攻擊知識，也能在每次攻擊中靈活地結合全局與局部資訊。

**Q7：本研究在哪些基準測試與目標模型上評估 PIMiner？**
A：本研究在 IPIArena 與 AgentDojo 兩個智慧體提示注入紅隊測試基準上評估 PIMiner。目標模型包含多個前沿大型語言模型，例如 Gemini-2.5-Pro、GPT-5.1、Claude-Haiku-4.5、Claude-Sonnet-4.5 與 Claude-Opus-4.5。這些基準與模型涵蓋了不同的使用者任務、注入任務與目標模型特性，能夠充分檢驗學習到的攻擊策略是否具備跨目標與跨攻擊者模型的可遷移性。

**Q8：PIMiner 在實驗中取得了哪些關鍵結果？**
A：實驗結果顯示 PIMiner 在多個設定下都達到強勁的攻擊成功率。在 IPIArena 上，它對 Gemini-2.5-Pro 達到 76.2% 的攻擊成功率、對 GPT-5.1 達到 61.9%、對 Claude-Sonnet-4.5 達到 42.9%。在 AgentDojo 上，它對 Gemini-2.5-Pro 達到 86.7%、對 GPT-5.1 達到 53.3%、對 Claude-Sonnet-4.5 達到 40.0%，顯示其策略庫能有效轉移到未見過的目標模型。

**Q9：作者如何驗證 PIMiner 各項設計選擇的有效性？**
A：論文透過全面的消融研究來驗證各項設計選擇，包括層級式記憶機制、策略路由器的效用，以及經驗消化器對策略庫更新的貢獻。由於自動化智慧體設計在提示注入紅隊測試中面臨高昂的評估成本，作者採用啟發式設計並以實證方式驗證每個元件。這些消融研究有助於理解長期記憶、資料集內記憶與樣本內記憶各自對最終攻擊成功率的影響。

**Q10：PIMiner 在實務上可以如何應用於智慧體安全測試？**
A：PIMiner 可應用於部署前的智慧體安全評估，協助模型開發者系統化地發現提示注入漏洞。由於它只需對目標智慧體進行少量查詢，例如每個測試樣本僅需十次互動，因此適合在成本敏感或查詢受限的生產環境中使用。此外，它所產生的成功攻擊樣本能作為訓練資料，進一步強化護欄模型與骨幹大型語言模型的防禦能力。

**Q11：產品團隊在導入 PIMiner 這類自動化紅隊測試系統時，應考量哪些實務議題？**
A：產品團隊在部署 PIMiner 時應注意倫理與法律邊界，確保紅隊測試僅針對授權系統進行。此外，雖然 PIMiner 查詢次數較少，但仍需監控對目標模型的呼叫成本與延遲，特別是在大規模評估時。團隊也應持續更新策略庫並檢視經驗消化器產生的新策略，以避免攻擊知識過時或產生偏離真實威脅模式的虛假策略。

**Q12：這項研究可能對人工智慧安全與紅隊測試領域帶來什麼影響？**
A：這項工作為人工智慧安全領域提供了一種介於強化學習與基於搜尋方法之間的新範式，證明搜尋式紅隊測試也能透過知識累積達到接近甚至超越強化學習的效果。它有助於降低對昂貴重新訓練的依賴，使更多研究團隊與企業能負擔大規模的提示注入評估。長遠來看，這類自動化紅隊測試系統將成為持續監控與強化智慧體穩健性的基礎設施。

**Q13：PIMiner 有哪些已承認的限制？**
A：儘管 PIMiner 表現強勁，它仍依賴啟發式設計而非自動化智慧體最佳化框架，因此某些架構選擇可能未達理論最優。此外，策略庫的品質與覆蓋範圍會受到過去攻擊經驗的限制，若面對全新類型的智慧體任務或防禦機制，可能需要較多樣本才能建立有效策略。論文也指出，與 GPT-Red 等方法相比，PIMiner 雖然查詢成本較低，但在極端複雜或多步驟推理的攻擊場景中可能仍有提升空間。

**Q14：在哪些情況下 PIMiner 可能會攻擊失敗或表現不佳？**
A：PIMiner 可能在目標模型採用全新防禦架構或攻擊面與訓練資料顯著不同的情況下遇到困難。例如，當目標智慧體的任務結構、工具呼叫格式或安全護欄與策略庫中記錄的經驗差異過大時，策略路由器可能選不到合適策略。此外，若目標模型對提示注入具有高度穩健性，例如 Claude-Sonnet-4.5 在實驗中攻擊成功率相對較低，則即使經過迭代精煉，攻擊仍可能難以成功。

**Q15：基於這項研究，未來有哪些值得探索的研究方向？**
A：未來研究可朝幾個方向延伸：一是結合自動化智慧體設計技術，在控制評估成本的前提下進一步最佳化 PIMiner 的架構；二是擴展策略庫至多語言、多模態或更長上下文的智慧體場景；三是將攻擊知識與防禦知識結合，發展對抗性訓練迴圈，使紅隊測試與防禦強化能夠同步進行。這些方向都有助於建立更通用、更自動化且更負責任的智慧體安全評估生態系統。

## 實務應用指南

### 適用場景

1. **部署前 LLM 智慧體安全評估**  
   在將具備工具呼叫、檢索與自動執行能力的智慧體上線前，使用 PIMiner 對其進行提示注入紅隊測試，找出因不受信任上下文（網頁、檢索文件、工具輸出）導致的指令劫持風險。

2. **防禦資料集生成**  
   利用 PIMiner 對強大目標模型（如 GPT-5.1、Claude-Sonnet-4.5、Gemini-2.5-Pro）產生成功的提示注入攻擊樣本，作為微調護欄模型、強化骨幹大型語言模型對齊，或訓練未來攻擊者模型的訓練資料。

3. **第三方 API 與 Agent 平台風險稽核**  
   企業採購或整合外部 LLM Agent 服務時，可運用 PIMiner 在僅需少量查詢（例如每個測試樣本約 10 次）的條件下，快速評估不同目標模型的穩健性差異。

4. **持續性安全監控與迴歸測試**  
   將 PIMiner 的策略庫納入 CI/CD 流程，當目標模型或系統提示更新時，自動執行提示注入迴歸測試，確認新版本是否引入新的攻擊面。

5. **跨模型攻擊知識累積研究**  
   針對多組（資料集，目標模型）配對進行紅隊測試，讓 PIMiner 從無到有建立策略庫，並觀察策略在不同目標大型語言模型之間的可遷移性。

---

### 實作前置條件

**資料需求**
- 目標智慧體資料集：如 IPIArena、AgentDojo 等支援提示注入評估的基準測試資料，或自訂的（使用者任務、注入任務、評估準則）樣本。
- 目標模型 API 存取權：需能呼叫待測試的目標 LLM（例如 GPT-5.1、Claude-Sonnet-4.5、Gemini-2.5-Pro）並取得回應。
- 攻擊者模型 API：用於生成與迭代優化注入提示，可選用成本較低但具備遵循指令能力的模型。

**運算需求**
- 相較於 RL-based 方法（如 RL-Hammer、PISmith）需要數萬次目標模型互動與大量 GPU 訓練，PIMiner 無需微調攻擊者模型，主要成本在於目標模型查詢與策略庫維護。
- 每個測試樣本約需 10 次目標模型查詢；完整建立策略庫則需視資料集規模與目標模型數量而定，建議預留中等規模的 API 預算與儲存空間。

**技能需求**
- 熟悉 Python 與 LLM API 串接。
- 理解提示注入攻擊原理、智慧體工具呼叫流程與評估指標（如攻擊成功率 ASR）。
- 具備設計與維護結構化記憶體（長期策略庫、資料集內記憶、樣本內記憶）的能力。

---

### 實作步驟建議

1. **環境與資料準備**
   - 選定目標智慧體資料集與目標模型，建立評估腳本以判斷攻擊是否成功。
   - 初始化空策略庫，並準備攻擊者模型（負責生成與改寫提示）。

2. **建立策略庫（Training Phase）**
   - 依序餵入多組（資料集，目標模型）配對。
   - 對每個配對執行以下流程：
     - **策略路由（Strategy Router）**：根據當前樣本特性，從策略庫中選取最相關的攻擊策略。
     - **迭代攻擊（Iterative Attack Module）**：在最多約 10 步內，反覆生成、測試並修正注入提示；同時利用三層記憶體——長期策略庫、資料集內經驗、樣本內歷史——引導搜尋。
     - **經驗消化（Experience Digestor）**：該配對所有樣本測試完成後，分析成功與失敗案例，提煉新的攻擊模式並更新策略庫。

3. **轉移至未見目標模型（Test Phase）**
   - 面對新的目標 LLM 時，直接載入已學習的策略庫，無需重新訓練。
   - 策略路由會為每個測試樣本挑選合適策略，再由迭代攻擊模組進行少量查詢優化。

4. **產出與應用**
   - 輸出攻擊成功率（ASR）、成功攻擊樣本、失敗案例分析。
   - 將成功攻擊樣本轉換為防禦訓練資料，或回饋給產品團隊進行系統提示與護欄強化。

5. **持續維運**
   - 定期加入新的資料集與目標模型，讓策略庫隨經驗累積而擴充。
   - 監控策略庫品質，移除過時或過度特化的策略，避免策略膨脹。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **目標模型查詢成本** | 雖然每樣本僅約 10 次查詢，但大規模評估仍可能產生可觀 API 費用。 | 先在小規模驗證集上測試策略庫品質，再擴大到完整資料集。 |
| **策略庫過度擬合特定模型** | 若訓練配對過度集中於單一目標模型，策略可能無法遷移到未見模型。 | 刻意納入多樣化的目標模型與資料集進行訓練。 |
| **誤判攻擊成功** | 評估函式設計不當可能將未真正達成惡意目標的輸出判為成功。 | 使用基準測試提供的官方評估器，或設計嚴謹的多重檢查機制。 |
| **倫理與法律風險** | 自動生成惡意提示可能觸及法規或企業政策。 | 僅在授權環境與自有系統上執行，並建立完整的測試紀錄與存取控管。 |
| **對生產環境造成副作用** | 若在目標智慧體的正式環境測試，可能意外執行真實操作（發信、下單等）。 | 使用隔離沙箱、模擬工具輸出與僅讀環境進行紅隊測試。 |
| **策略庫維護負擔** | 隨著經驗累積，策略數量可能快速成長，影響路由效率。 | 定期由經驗消化模組合併相似策略、刪除低效用策略。 |

### 與其他技術的整合建議

- **與 RL-based 紅隊方法互補**  
  PIMiner 適合快速評估與資料收集，RL-based 方法（如 RL-Hammer、PISmith）則可在特定目標模型上進一步微調攻擊者模型。建議先用 PIMiner 建立高品質策略庫與初始成功樣本，再針對高風險目標投入 RL 精煉。

- **與護欄模型（Guardrail Models）串接**  
  將 PIMiner 產生的成功攻擊樣本作為負樣本，微調輸入/輸出過濾器；同時把護欄部署後的攔截結果回饋給 PIMiner，形成「攻擊—防禦—再攻擊」的迭代迴圈。

- **與 CI/CD 及 MLOps 整合**  
  將 PIMiner 包裝成自動化紅隊測試任務，在模型版本更新、系統提示變更或工具新增時自動觸發，並將 ASR 趨勢納入模型上線閘道。

- **與對齊（Alignment）訓練流程結合**  
  把成功攻擊案例轉為 DPO/RLHF 的偏好資料，強化骨幹大型語言模型對惡意注入指令的抵抗力。

- **與日誌分析平台整合**  
  將每次攻擊的查詢、回應與策略路由決策記錄下來，搭配向量資料庫進行檢索，進一步提升長期記憶體的查詢效率與可解釋性。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦於「提示注入」的基本概念與 PIMiner 的四個元件（策略庫、策略路由、迭代攻擊模組、經驗消化器），理解它如何像一位會累積經驗的紅隊測試員，逐步學會攻擊不同目標模型。可先略過強化學習與記憶體設計的技術細節，重點掌握適用場景與風險注意事項。

**AI 工程師**  
本論文提供了一個無需微調攻擊者模型、僅靠少量目標模型查詢即可運作的實作架構。建議仔細研究三層記憶體的設計與策略庫的更新機制，並思考如何將其整合進現有的 LLM Agent 評估流程、CI/CD 管線或護欄訓練管線中。

**研究人員**  
論文的核心貢獻在於將「知識累積」引入基於搜尋的提示注入紅隊測試，縮小與 RL-based 方法的效能差距。建議深入分析策略庫的可遷移性實驗、與 RL-Hammer / PISmith / GPT-Red 的比較，以及三層記憶體對樣本內與跨樣本學習的影響，並思考是否能擴展至多輪對話或更複雜的工具使用場景。

**產品經理**  
本技術可協助團隊在部署前以較低成本發現 LLM Agent 的提示注入風險，並持續產出防禦訓練資料。建議關注其「少量查詢即可轉移至未見模型」的特性，評估將其納入產品安全閘道、第三方模型選型評估與合規稽核流程的商業價值與實施成本。
