## ⚡ TL;DR

現有技能優化方法僅依賴昂貴的代理 rollout，忽略大量公開技能的累積知識。
本文提出 RASO 框架，透過 RASI 與 RASU 兩階段結合跨環境適配機制。
在四個基準測試與兩個模型上，RASO 持續優於 TextGrad、GEPA 等基線方法。

## 摘要翻譯

代理技能（Agent Skill）是一種可重複使用、可執行的自然語言工件（Natural-Language Artifact），用於引導代理在特定執行環境（Harness）下有效完成任務。近期研究探討了代理技能的優化，促成涵蓋多元任務、領域與執行環境的公開技能持續累積。儘管已有數百萬筆公開分享的技能，現有的技能優化方法卻大多忽略這些累積知識，僅依賴昂貴的代理 rollout（Agent Rollout）來為目標任務迭代精煉技能。為解決此問題，我們提出檢索增強技能優化（Retrieval-Augmented Skill Optimization, RASO），這是一個在整個技能優化過程中將外部技能語料庫（External Skill Corpus）作為先驗知識（Prior Knowledge）運用的框架。RASO 從既有技能中擷取相關知識，並透過跨執行環境適配（Cross-Harness Adaptation）將其調整至目標任務與執行環境，同時考量領域不匹配（Domain Mismatch）與執行環境不匹配（Harness Mismatch）兩方面的差異。RASO 包含兩個互補階段：檢索增強技能初始化（Retrieval-Augmented Skill Initialization, RASI）在無需代理 rollout 的情況下建構基於知識的初始技能（Knowledge-Grounded Initial Skill），而檢索增強技能更新（Retrieval-Augmented Skill Update, RASU）則透過以執行回饋（Execution Feedback）引導的外部知識擷取來迭代精煉技能。在四個代理基準測試（Agent Benchmark）與兩個模型上的大量實驗顯示，RASO 持續優於未採用檢索增強技能初始化與更新的基線方法（Baseline）。

### 核心貢獻（3～5點）
- **提出 RASO 框架**：首次將外部技能語料庫作為先驗知識系統性地引入技能優化流程，突破現有方法僅依賴昂貴代理 rollout 的限制。
- **設計跨執行環境適配機制**：同時考量領域與執行環境兩方面的差異，使擷取自來源的技能能有效遷移至目標任務與目標執行環境。
- **提出 RASI 與 RASU 雙階段互補設計**：RASI 無需代理 rollout 即可建構基於知識的初始技能，大幅降低初始化成本；RASU 則透過執行回饋引導的外部知識擷取進行迭代精煉，持續提升技能品質。
- **廣泛實驗驗證**：在四個代理基準測試與兩個模型上，RASO 持續優於未採用檢索增強初始化與更新的基線方法，展現跨任務、跨模型的穩健泛化能力。

### 適合對象
- 從事 **大型語言模型（LLM）代理** 與 **自主代理（Autonomous Agent）** 研究的學者與工程師，特別關注代理能力建構、技能學習與工具使用等議題者。
- 投入 **檢索增強生成（RAG）** 與 **知識擷取** 應用的研究者，可參考本文將外部語料庫作為先驗知識融入優化流程的設計思路。
- 關注 **代理基準測試（Agent Benchmark）** 效能提升、追求降低代理 rollout 成本並提升任務完成率的實務開發者。
- 對 **程序性知識（Procedural Knowledge）表示、自然語言工件的可審核性（Auditable）與可遷移性（Transferable）** 議題有興趣的 NLP 與 AI 從業者。

## 深度分析

#### 方法論解析

RASO（Retrieval-Augmented Skill Optimization，檢索增強技能優化）的核心設計理念在於將「外部技能語料庫」視為先驗知識來源，並透過兩階段流程將其整合進技能優化過程中。這個框架的設計動機來自一個關鍵觀察：儘管現有公開技能語料庫（如 GitSkills）已累積數百萬筆技能，但現有技能優化方法幾乎完全依賴代理自身的 rollout 經驗進行迭代精煉，忽略了這些已存在的程序性知識。

**第一階段：RASI（Retrieval-Augmented Skill Initialization，檢索增強技能初始化）**

RASI 的設計目標是「無需代理 rollout 即可建構有效的初始技能」。其運作流程如下：

1. **任務與環境描述輸入**：接收目標任務與目標執行環境（target harness）的描述。
2. **語料庫檢索**：從外部技能語料庫中檢索 Top-k 段落，這些段落可能來自不同的領域與執行環境。
3. **跨執行環境適配（Cross-Harness Adaptation）**：對檢索結果進行適配處理，將來源技能中特定於原領域或原環境的指令抽象化，並以目標環境支援的物件、命令與單位重新表述。
4. **知識基礎初始技能生成**：輸出一個基於知識的初始技能（knowledge-grounded initial skill），作為後續優化的起點。

這個階段的關鍵優勢在於「零 rollout 成本」——傳統方法需要昂貴的代理執行才能產生初始技能，而 RASI 透過檢索與適配直接生成高品質的起點。

**第二階段：RASU（Retrieval-Augmented Skill Update，檢索增強技能更新）**

RASU 採用迭代式的回饋驅動機制：

1. **執行與回饋收集**：代理使用當前技能執行任務，收集執行回饋（execution feedback）。
2. **失敗分析**：當觀察到失敗時，識別導致失敗的「缺失知識」。
3. **引導式檢索**：根據失敗分析，從語料庫中檢索能補足該缺失知識的內容。
4. **跨執行環境適配**：同樣透過 Cross-Harness Adaptation 處理檢索結果。
5. **技能更新**：將新知識整合進現有技能，產生更新後的技能（updated skill）。

**核心機制：Cross-Harness Adaptation（跨執行環境適配）**

這是 RASO 最重要的技術貢獻。論文中以 SpreadsheetBench 為例指出，高達 92.9% 的檢索技能來自不同的執行環境，這意味著「直接使用檢索結果」會因為環境不匹配（harness mismatch）而失效。Cross-Harness Adaptation 並非簡單的文本改寫，而是：

- **抽象化來源特定指令**：移除來源技能中對特定工具、檔案格式或 API 的依賴。
- **重新表述底層程序**：保留程序性知識（procedural knowledge）的核心邏輯，但以目標環境的詞彙重新表達。
- **雙重處理**：同時處理領域不匹配（domain mismatch）與執行環境不匹配（harness mismatch）。

這個機制在 RASI 與 RASU 中共享使用，形成統一的知識轉移管道。

#### 實驗數據解讀

**基準測試與模型選擇**

論文選用四個具有代表性的代理基準測試：
- **OfficeQA**：辦公室文件問答任務，測試結構化文件處理能力。
- **SpreadsheetBench**：試算表操作任務，測試程式化資料處理。
- **ALFWorld**：文字遊戲環境中的家庭任務，測試多步驟規劃與工具使用。
- **WebShop**：網頁購物環境，測試自然語言理解與網頁互動。

模型選用 Qwen-3.5-9B 與 GPT-5.6-Luna，涵蓋開源與閉源模型，增強結論的泛化性。

**關鍵實驗結果**

1. **RASI 的有效性**：RASI 合成的初始技能在效能上優於「直接使用檢索技能」與「無檢索初始化」，且完全不需要代理 rollout。這驗證了「檢索 + 適配」相較於「直接檢索」的優勢。

2. **RASO 整體表現**：在四個基準測試與兩個模型上，RASO 一致性地優於以下強基線：
   - **TextGrad**：基於梯度的提示優化方法。
   - **GEPA**：基因式提示優化演算法。
   - **SkillOpt**：現有的技能優化方法。
   - **WikiSkill**：基於維基百科知識的技能建構方法。

3. **跨執行環境分布的實證**：在 SpreadsheetBench（GPT-5.6-Luna）上，92.9% 的檢索技能來自其他執行環境，僅 7.1% 來自目標環境。這強烈支持了 Cross-Harness Adaptation 的必要性——若不進行適配，這些「跨環境」技能將難以直接使用。

**結果的深層意涵**

- **效能提升的來源**：論文的分析顯示，效能增益來自於「適配多樣化的外部知識」，而非依賴特定的來源文件。這意味著 RASO 的成功來自於知識的多樣性，而非檢索的精確性。
- **成本效益**：RASI 階段無需 rollout，大幅降低了初始技能建構的成本；RASU 階段雖然仍需 rollout，但透過檢索引導，能更快收斂到高品質技能。
- **泛化能力**：在四個差異極大的基準測試（從結構化文件到網頁互動）上的一致性表現，顯示 RASO 具有跨任務類型的泛化能力。

#### 與現有研究的比較

**與現有方法的定位差異**

| 方法類型 | 代表方法 | 核心特徵 | RASO 的差異化 |
|---------|---------|---------|--------------|
| 從執行經驗學習 | TextGrad、GEPA、SkillOpt | 依賴代理 rollout 迭代優化 | RASO 引入外部先驗，減少 rollout 需求 |
| 從外部來源重用 | WikiSkill | 從維基百科等結構化來源檢索 | RASO 從技能語料庫檢索，處理程序性知識 |
| 直接檢索使用 | （隱含基線） | 檢索後直接套用 | RASO 加入 Cross-Harness Adaptation |

**RASO 的核心改進**

1. **從「參數化知識」到「檢索增強」**：傳統方法僅依賴 LLM 的參數化知識（parametric knowledge）生成技能，RASO 則將外部技能語料庫作為先驗知識來源。
2. **從「單一環境」到「跨環境適配」**：現有方法假設檢索結果可直接使用，RASO 透過 Cross-Harness Adaptation 處理領域與環境不匹配。
3. **從「昂貴初始化」到「零 rollout 初始化」**：RASI 階段無需代理執行，大幅降低初始技能建構成本。

**現有方法的侷限性**

- **SkillOpt 等方法的瓶頸**：完全依賴代理自身經驗，無法利用已累積的數百萬筆公開技能。
- **直接檢索方法的失敗**：如論文中所示，92.9% 的檢索結果來自不同環境，直接使用會因環境不匹配而失效。
- **WikiSkill 的範圍限制**：僅限於維基百科等結構化知識來源，無法處理程序性知識。

**論文的侷限性**

1. **語料庫依賴**：RASO 的效能高度依賴外部技能語料庫的品質與覆蓋範圍。若語料庫缺乏相關領域的技能，檢索效果將受限。
2. **適配成本**：Cross-Harness Adaptation 需要額外的 LLM 呼叫進行文本轉換，雖然低於 rollout 成本，但仍非零成本。
3. **評估範圍**：雖然涵蓋四個基準測試，但這些測試可能無法完全代表所有代理任務類型（如程式設計、科學推理等）。
4. **理論分析不足**：論文未深入分析 Cross-Harness Adaptation 的理論基礎，例如適配失敗的條件或檢索品質與最終效能的關係。

#### 未來研究方向

**1. 理論基礎的深化**

- **適配失敗分析**：系統性地研究 Cross-Harness Adaptation 在哪些情況下會失敗，例如當來源與目標環境的抽象層級差異過大時。
- **檢索品質與效能的關係**：建立理論模型，分析檢索召回率、精確率與最終技能品質之間的定量關係。
- **收斂性分析**：研究 RASU 迭代過程的收斂性質，例如在何種條件下能保證找到全域最優技能。

**2. 方法的擴展**

- **多模態技能**：現有技能以自然語言為主，未來可擴展至包含程式碼、圖表、影片等多模態元素的技能。
- **階層式技能**：將技能組織為階層結構，高層技能呼叫低層技能，提升可組合性與可重用性。
- **動態語料庫**：隨著代理執行產生新技能，動態更新語料庫，形成自我強化的良性循環。

**3. 應用領域的拓展**

- **專業領域代理**：將 RASO 應用於醫療、法律、金融等專業領域，這些領域的技能語料庫可能更稀疏但價值更高。
- **多代理協作**：研究多個代理如何共享與檢索彼此的技能，形成集體智慧。
- **人機協作**：讓人類專家能夠編輯、審核與貢獻技能，與 RASO 的自動化流程結合。

**4. 效率與可持續性**

- **降低適配成本**：研究更輕量的適配機制，例如使用小型模型或預計算的適配模板。
- **增量學習**：當新任務到來時，無需從頭檢索，而是基於歷史檢索結果進行增量更新。
- **節能評估**：量化 RASO 相較於純 rollout 方法的能耗與碳排放差異。

**5. 安全與可解釋性**

- **技能審核機制**：當從外部語料庫檢索技能時，如何確保技能的安全性與合規性。
- **可解釋的適配過程**：讓 Cross-Harness Adaptation 的轉換過程對人類可讀、可審核。
- **偏見檢測**：檢測檢索結果是否帶有特定來源的文化偏見或領域偏見。

**6. 與其他技術的整合**

- **與強化學習結合**：將 RASO 的檢索機制與 RL 的探索策略結合，兼顧先驗知識與探索能力。
- **與因果推理結合**：使用因果模型來判斷檢索技能的適用性邊界。
- **與聯邦學習結合**：在保護隱私的前提下，從分散的技能語料庫中學習。

這些研究方向不僅能深化 RASO 本身的理論與實務，也能推動整個「代理技能優化」領域的發展，使其從「單一代理的孤立優化」走向「集體智慧的累積與重用」。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？為什麼代理技能（agent skill）的優化在當前 LLM 代理應用中如此重要？**
A：這篇論文聚焦的核心問題是：現有的代理技能優化方法幾乎完全依賴代理自身的執行經驗（agent rollouts）來迭代精煉技能，卻忽略了已經累積在公開語料庫中的數百萬筆既有技能知識。這是一個重要的問題，因為代理技能是以自然語言形式表達的可重用工件，具備可審核、可遷移、跨模型無需修改等優勢，已成為 LLM 代理在執行環境中表現優劣的關鍵程序性策略。當技能品質不佳時，代理即使擁有強大的參數化知識，仍可能在工具呼叫、檔案操作與任務流程上表現失敗，因此如何有效率地建構高品質技能，直接影響代理在真實場景中的可靠性與部署成本。

**Q2：為什麼現有的技能優化方法無法有效利用外部技能語料庫？它們的主要限制是什麼？**
A：現有方法（如 TextGrad、GEPA、SkillOpt、WikiSkill 等）主要將技能視為一個文字決策變數，僅透過代理在目標任務上的執行回饋進行迭代優化，因此其知識來源被限制在「代理自身觀察到的 rollout」範圍內。這種做法存在兩個明顯限制：第一，每次優化都需要昂貴的代理 rollout，計算成本高且探索空間受限；第二，無法利用已經公開共享的數百萬筆技能所累積的程序性知識，導致每個任務都從零開始學習。此外，論文中特別指出，即使嘗試直接檢索外部技能，92.9% 的檢索結果來自與目標不同的執行環境（以 SpreadsheetBench 為例），若不進行適配就直接使用，會因為領域與執行環境不匹配而無法發揮作用。

**Q3：為什麼「跨執行環境不匹配」是技能復用的一個關鍵障礙？論文中如何量化這個問題的嚴重性？**
A：技能通常是在特定的執行環境下撰寫的，會內含該環境專屬的工具名稱、指令語法、檔案格式與領域假設，因此當直接套用到不同的執行環境時，這些隱含假設往往會失效，造成所謂的「harness mismatch」與「domain mismatch」。論文中以 SpreadsheetBench（搭配 GPT-5.6-Luna）為例進行實證，發現檢索到的技能中有 92.9% 來自與目標不同的執行環境，只有 7.1% 來自目標環境本身，這個懸殊的比例凸顯了「直接復用檢索技能」策略在實務上的不可行性，也說明了為何需要一個專門的適配機制來處理跨環境的知識遷移問題。

**Q4：RASO 框架的核心方法是什麼？它如何將外部技能語料庫整合進技能優化流程？**
A：RASO（Retrieval-Augmented Skill Optimization）的核心方法是將外部技能語料庫作為先驗知識，貫穿整個技能優化流程，並透過兩個互補階段來運作。第一階段稱為 RASI（Retrieval-Augmented Skill Initialization），從語料庫中檢索相關知識並直接建構一個基於知識的初始技能，整個過程不需要任何代理 rollout，因此能大幅降低初始化成本。第二階段稱為 RASU（Retrieval-Augmented Skill Update），在代理執行任務並觀察到失敗時，識別失敗背後所缺少的知識，再從語料庫中檢索對應內容來補充，藉此迭代精煉技能。這種「初始化＋更新」雙階段設計，使 RASO 能同時兼顧冷啟動效率與後續精煉品質。

**Q5：什麼是「跨執行環境適配（Cross-Harness Adaptation）」？它為什麼是 RASO 的關鍵創新？**
A：跨執行環境適配是 RASO 中一個被 RASI 與 RASU 共享使用的核心操作，其目的是將檢索自外部語料庫的程序性知識，轉換為符合目標領域與目標執行環境的表達形式。具體而言，它會「抽象化」來源技能中與特定領域相關的指令，並將其底層程序重新表述為目標環境所支援的物件、指令與單位，從而消除領域與執行環境不匹配的問題。這個機制之所以是關鍵創新，是因為它使得 RASO 不需要在語料庫中擁有與目標完全匹配的技能——即使檢索到的技能 92.9% 來自不同執行環境，仍能透過適配後有效遷移，這大幅放寬了對語料庫覆蓋率的要求。

**Q6：RASO 在設計上做了哪些關鍵的取捨？為什麼選擇「檢索＋適配」而非「直接使用檢索結果」或「純粹從 rollout 學習」？**
A：RASO 的關鍵設計取捨在於：它既不採用「直接將檢索技能當作最終技能使用」的捷徑（因為這會遭遇嚴重的執行環境不匹配），也不採用「完全依賴代理 rollout 從零學習」的純粹路線（因為這會浪費既有語料庫的知識且成本高昂）。取而代之的是「檢索作為先驗、適配作為橋接、rollout 作為回饋」的混合策略：在初始化階段完全不需要 rollout 以節省成本，在更新階段則僅在必要時（觀察到失敗）才觸發檢索與適配。這種設計選擇體現了對「知識來源多樣性」與「計算效率」的平衡，也讓 RASO 能同時勝過「無檢索初始化」與「直接檢索復用」兩類基線。

**Q7：論文中使用了哪些代理基準測試與模型來評估 RASO？為什麼選擇這些特定的測試集？**
A：論文中選用了四個代理基準測試：OfficeQA、SpreadsheetBench、ALFWorld 與 WebShop，並搭配兩個 LLM（Qwen-3.5-9B 與 GPT-5.6-Luna）進行評估。這些基準測試的選擇具有明確的代表性：OfficeQA 與 SpreadsheetBench 屬於辦公室生產力場景，涉及試算表、文件等結構化操作；ALFWorld 是文字版的居家環境模擬，強調多步驟決策；WebShop 則是網頁購物代理任務，測試代理在真實網頁環境中的導航與操作能力。透過同時覆蓋「結構化資料操作」、「模擬環境互動」與「真實網頁操作」三類截然不同的執行環境，論文得以驗證 RASO 在跨領域、跨執行環境下的泛化能力。

**Q8：RASO 在實驗中相較於基線方法的關鍵結果為何？哪些發現最值得強調？**
A：實驗結果顯示，RASO 在四個基準測試與兩個模型上皆穩定優於所有基線方法，包括 TextGrad、GEPA、SkillOpt 與 WikiSkill。其中兩個發現特別值得強調：第一，RASI 僅憑檢索與適配（完全不使用代理 rollout）所產生的初始技能，就已經能超越「直接使用檢索技能」與「無檢索初始化」兩種基線，證明了「檢索＋跨環境適配」在冷啟動階段就具有顯著價值；第二，RASU 在 RASI 的基礎上，透過執行回饋引導的檢索更新，能進一步穩定提升效能，顯示「初始化」與「更新」兩個階段具有互補性，而非彼此冗餘。

**Q9：論文中是否有進行消融實驗（Ablation Study）來驗證各元件的貢獻？**
A：雖然提供的全文段落未完整展示消融實驗的細節，但從論文的整體論述與圖 1 的對比可以推斷，RASO 的設計中至少包含兩個可被消融的關鍵元件：跨執行環境適配（Cross-Harness Adaptation）以及檢索增強的初始化（RASI）與更新（RASU）機制。論文明確指出「這些增益與適配多樣化的外部知識有關，而非依賴特定的來源文件」，這本身就是一種消融式的論證，說明 RASO 的成功來自於對外部知識的整體運用，而非偶然選中某一筆特別相關的技能。此外，圖 1 中將 RASO 與「直接使用檢索技能」、「無檢索初始化」兩種基線並列比較，也間接驗證了「檢索」與「適配」各自對最終效能的貢獻。

**Q10：RASO 在實際應用中適合哪些場景？哪些產業或產品最能受惠於這項技術？**
A：RASO 特別適合那些「任務類型多樣、執行環境異質、且已有大量歷史技能可復用」的代理應用場景。舉例而言，企業內部的自動化助理（如處理試算表、文件、CRM 系統）能藉由 RASO 從過去累積的技能語料庫中快速建構新任務的初始技能，無需為每個新流程都從零 rollout；客服或電商領域的網頁操作代理（如類似 WebShop 的購物代理）則能透過 RASU 在遇到新網頁結構時，自動檢索並適配相關的導覽與操作知識。此外，任何需要頻繁部署新代理技能的 SaaS 平台，都能從 RASO 降低初始化成本、提升技能品質的特性中獲益。

**Q11：從產品化的角度來看，部署 RASO 需要考量哪些基礎建設與成本因素？**
A：將 RASO 產品化時，至少需要考量三項基礎建設：首先是「技能語料庫的建立與維護」，需要一個可擴展且可檢索的技能儲存系統，並設計良好的中繼資料（包含任務類型、領域、執行環境等）以利檢索；其次是「跨執行環境適配模組」，需要一個能理解來源技能語意並將其轉換為目標環境詞彙的 LLM 呼叫流程，這會帶來額外的推論成本；最後是「執行回饋與更新迴圈」，需要將代理的執行結果結構化為可被 RASU 使用的失敗訊號，並設計合適的觸發條件以避免不必要的檢索。整體而言，雖然 RASO 能減少昂貴的 rollout 次數，但會增加檢索與適配的 LLM 呼叫，產品設計上需要在「rollout 成本」與「檢索＋適配成本」之間做取捨。

**Q12：RASO 對「代理技能」這個研究領域與更廣泛的 LLM 應用生態可能產生什麼影響？**
A：RASO 的提出可能對研究領域與應用生態產生多層面的影響：在研究層面，它將「技能優化」從過去以 rollout 為中心的範式，轉向「檢索＋適配＋精煉」的混合範式，開啟了「如何有效利用累積的程序性知識」這個新研究方向；在實務層面，它示範了一種可擴展的技能建構模式，使得社群共享的技能語料庫能真正成為下一代代理的「集體記憶」；在更廣泛的 LLM 應用生態中，RASO 也呼應了 RAG（Retrieval-Augmented Generation）的成功經驗，顯示「檢索增強」同樣能應用於程序性知識與代理行為優化，而不僅限於事實性問答，這為未來整合事實性與程序性知識的代理架構奠定基礎。

**Q13：RASO 存在哪些已知的限制？論文中是否有特別指出其適用邊界？**
A：雖然提供的全文段落未完整列出所有限制，但從方法設計可以推論出幾項已知限制：第一，RASO 的效能高度依賴外部技能語料庫的品質與覆蓋範圍，若語料庫中缺乏與目標任務相關的技能，即使經過適配也無法產生有意義的增益；第二，跨執行環境適配仰賴 LLM 對來源技能語意的正確理解，若來源技能本身撰寫不清或過於隱晦，適配品質會下降；第三，RASO 目前主要針對「文字形式的技能」進行優化，對於需要精細數值操作、複雜多模態感知或即時反應的任務，其適用性仍待驗證；最後，論文中的實驗僅涵蓋四個基準測試與兩個模型，對於更大規模或更專門的領域（如醫療、法律），其泛化能力尚未被充分檢驗。

**Q14：RASO 在什麼情況下可能會失敗？有哪些潛在的失敗案例值得關注？**
A：RASO 可能的失敗案例包括以下幾類：第一，當目標任務在語料庫中完全沒有相關技能時，檢索階段會返回不相關內容，此時即使經過適配，也可能引入雜訊而非有用知識，反而干擾初始技能的建構；第二，當來源技能與目標執行環境的差異過大（例如從純文字環境遷移到需要精細 GUI 操作的環境），跨執行環境適配可能無法正確轉譯關鍵操作步驟；第三，當任務需要即時反應或高度精確的數值計算時，文字形式的技能可能無法承載足夠細節，導致代理在執行階段仍然出錯；第四，若執行回饋本身不夠精確或具有誤導性（例如評分函數有缺陷），RASU 的更新方向可能偏離正確軌道，使技能品質不升反降。

**Q15：基於 RASO 的研究成果，未來有哪些值得探索的研究方向？**
A：基於 RASO 的成果，未來值得探索的方向至少包括以下幾項：第一，擴展跨執行環境適配的範圍，從目前的文字技能延伸到多模態技能（如包含螢幕截圖、座標資訊的技能），以支援更複雜的 GUI 代理；第二，研究「技能語料庫的動態成長機制」，讓代理在執行過程中自動產生高品質技能並回饋到語料庫，形成正向循環；第三，結合事實性 RAG 與程序性 RASO，建構同時具備「知道什麼」與「知道怎麼做」的整合型代理架構；第四，探索更高效的檢索策略，例如學習式檢索或階層式技能組織，以降低大規模語料庫下的檢索成本；第五，將 RASO 應用於多代理協作場景，研究如何讓多個代理共享並共同優化一套技能語料庫，進一步放大集體知識的價值。

## 實務應用指南

### 適用場景

**1. 企業內部跨工具代理部署**
企業常同時使用多套執行環境（例如內部 CRM 系統、Notion 工作區、Salesforce），但僅有部分環境累積了成熟的代理技能。RASO 的跨執行環境適配機制可從既有技能語料庫擷取相關程序性知識，再將其轉寫為目標環境可理解的指令，使新環境的代理無需從零開始累積 rollout 經驗。

**2. 試算表與辦公室自動化代理**
SpreadsheetBench、OfficeQA 等基準測試顯示，92.9% 的檢索結果來自不同執行環境。實務上，企業內部常見「舊版 Excel 巨集知識」需遷移至新版 Google Sheets 代理、或從 LibreOffice 流程遷移至雲端試算表 API，RASO 的 RASI 階段可在不執行昂貴 rollout 的前提下，直接生成可用的初始技能。

**3. 網頁代理（WebShop、ALFWorld）的快速冷啟動**
對於需要即時上線的網頁購物或居家模擬代理，傳統技能優化需數十次 rollout 才能收斂。RASO 可從公開技能語料庫（如 GitSkills）擷取相似任務的程序性策略，透過跨執行環境適配後直接作為初始技能，縮短上線時間。

**4. 多模型遷移場景**
當企業從 GPT-5.6-Luna 切換至 Qwen-3.5-9B，或反之，技能以自然語言形式存在，可無需修改直接遷移。RASO 的檢索增強機制進一步確保新模型能繼承既有語料庫的累積知識，避免模型切換造成的效能衰退。

**5. 領域專屬代理的知識蒸餾**
在金融、醫療、法律等高度專業領域，公開技能語料庫規模有限，但可從通用技能中擷取「如何處理結構化資料」、「如何驗證輸出」等通用程序性知識，再透過跨執行環境適配嫁接到專業領域的執行環境中。

### 實作前置條件

**資料面**
- **外部技能語料庫**：需具備一定規模的可檢索技能集合（建議至少數千筆），可使用 GitSkills 等公開語料庫，或自行累積內部技能庫。技能需以自然語言工件形式儲存，並附帶任務描述、執行環境標記。
- **目標任務與執行環境描述**：每個目標任務需提供清楚的任務說明與執行環境規格（可用工具清單、檔案存取權限、評分程序），供 RASI 階段生成初始技能時參考。
- **執行回饋收集機制**：RASU 階段需要從代理執行軌跡中萃取失敗訊號與改進要點（Lessons），因此需建立 rollout 執行與日誌收集的基礎設施。

**運算資源**
- **基礎 LLM 推論能力**：需具備呼叫目標 LLM（如 Qwen-3.5-9B 或 GPT-5.6-Luna 等級模型）的 API 或自架推論環境，用於技能生成、檢索查詢改寫、跨執行環境適配等環節。
- **嵌入模型與向量資料庫**：技能檢索仰賴語意相似度比對，建議準備嵌入模型（如 text-embedding-3-large 或開源替代方案）與向量資料庫（如 Milvus、Qdrant、pgvector）。
- **代理執行環境**：需部署目標代理的執行環境（harness），包含工具呼叫介面、檔案系統存取、評分函式等。

**技能門檻**
- **提示工程基礎**：理解如何設計 LLM 提示詞以引導技能生成與改寫。
- **檢索增強生成（RAG）經驗**：熟悉文檔切段、嵌入、相似度檢索的基本流程。
- **代理框架操作能力**：能使用 LangChain、AutoGen、Claude Agent SDK 等框架串接工具與執行環境。
- **評估方法設計**：理解如何設計任務評分函式與基準測試，以驗證技能優化成效。

### 實作步驟建議

**步驟一：建立並索引外部技能語料庫**
收集並整理現有技能文件，每筆技能應包含：任務描述、適用執行環境、程序性指令、範例輸出。將技能切段後透過嵌入模型編碼，存入向量資料庫，並為每筆技能標記其來源執行環境，供後續跨執行環境適配使用。

**步驟二：實作 RASI（檢索增強技能初始化）**
針對目標任務與執行環境描述，從技能語料庫中檢索 Top-k 相關段落。將檢索結果連同任務與環境規格送入 LLM，透過跨執行環境適配機制生成初始技能。此階段**不需執行任何代理 rollout**，可直接產出可用技能。

**步驟三：建立代理執行與回饋收集管線**
部署目標代理的執行環境，串接 rollout 執行流程。每次執行後收集：任務輸入、代理動作序列、最終輸出、評分結果、失敗原因。將這些資訊整理為結構化執行回饋，供 RASU 階段使用。

**步驟四：實作 RASU（檢索增強技能更新）**
當代理執行失敗時，從回饋中萃取出「缺失的知識」或「經驗教訓（Lessons）」。以這些教訓作為查詢，從技能語料庫中檢索相關程序性知識，再次透過跨執行環境適配機制，將新知識融入現有技能中，完成一次迭代更新。

**步驟五：設計跨執行環境適配機制**
這是 RASO 的核心創新。實作時需建立一個「適配器」模組，能夠：辨識來源技能中提及的特定工具、物件、單位；將其映射至目標執行環境的詞彙表；移除來源領域特有的假設；重新表述程序性步驟使其可在目標環境執行。

**步驟六：迭代優化與評估**
重複步驟三至五，直到技能在驗證集上收斂或達到預設迭代上限。建議同時記錄每次迭代的技能版本、執行回饋、改進幅度，以便後續分析哪些類型的檢索結果對效能提升貢獻最大。

**步驟七：部署與監控**
將最終技能部署至生產環境的代理執行環境中。建議建立技能版本管理與 A/B 測試機制，持續監控代理效能，並定期從新的執行回饋中更新技能語料庫，形成正向循環。

### 潛在風險與注意事項

**風險一：跨執行環境適配失真**
若來源技能與目標執行環境差異過大（例如從網頁代理遷移至試算表代理），適配器可能無法正確轉寫程序性步驟，導致生成的技能語意偏離原意。
**緩解措施**：在適配器中加入「自我驗證」步驟，要求 LLM 在適配後檢查輸出是否仍保留原始程序性意圖；對高風險轉換保留少量 rollout 進行人工抽樣驗證。

**風險二：檢索結果的領域偏誤**
若技能語料庫中某些領域或執行環境的技能占比過高，檢索結果可能系統性地偏向這些來源，忽略少數但更相關的技能。
**緩解措施**：在檢索階段引入來源多樣性懲罰項，或使用最大邊際相關性（MMR）等機制平衡相關性與多樣性；定期審查檢索結果的來源分布。

**風險三：執行回饋的雜訊**
代理 rollout 的執行結果可能因隨機性、評分函式不完美等因素產生雜訊回饋，導致 RASU 迭代時引入錯誤的「經驗教訓」。
**緩解措施**：對同一任務執行多次 rollout 並取平均或投票結果作為回饋；設定回饋信心閾值，僅在多次失敗一致時才觸發技能更新。

**風險四：技能語料庫的品質參差不齊**
公開技能語料庫中可能包含低品質、過時或錯誤的技能，若直接檢索使用會拖累優化效果。
**緩解措施**：在技能入庫前進行品質過濾（例如以 LLM 評分或人工抽樣）；為每筆技能標記品質分數，檢索時作為加權因子。

**風險五：迭代更新的計算成本**
雖然 RASI 階段免 rollout，但 RASU 階段仍需執行代理 rollout 來收集回饋，整體成本仍可能高於預期。
**緩解措施**：設定明確的停止條件（例如連續 N 次迭代無改善則停止）；對簡單任務使用較小的 rollout 預算；考慮使用模擬環境或快取機制降低重複執行成本。

**風險六：技能的可解釋性與合規性**
技能以自然語言形式存在雖利於審核，但在金融、醫療等受監管產業，需確保技能內容符合法規要求。
**緩解措施**：在技能部署前加入合規審查流程；保留技能的完整版本歷史與生成記錄，便於稽核追溯。

### 與其他技術的整合建議

**與 TextGrad、GEPA 等提示優化框架整合**
RASU 階段的迭代更新機制可與 TextGrad（基於 LLM 反思的梯度式提示優化）或 GEPA（遺傳式提示演化）結合，將檢索增強的「外部知識注入」作為這些演算法的額外變數，提升收斂速度與最終效能。

**與 RAG 系統整合**
RASO 本質上是 RAG 思想在技能優化領域的延伸。實務上可將 RASO 的技能語料庫與企業既有的 RAG 知識庫統一管理，共享嵌入模型與向量資料庫基礎設施，降低維運成本。

**與 Agent 框架整合**
可將 RASO 生成的技能注入 LangChain 的 system prompt、AutoGen 的 agent profile、或 Claude Agent SDK 的 skills 欄位。建議設計標準化的技能載入介面，使同一技能可在不同框架間無縫切換。

**與 MLOps / LLMOps 平台整合**
將技能視為模型 artifact 的一種，納入版本控制（Git LFS 或 DVC）、CI/CD 流程、A/B 測試框架。每次技能更新都應觸發自動化評估，僅在通過品質門檻後才部署至生產環境。

**與人類回饋強化學習（RLHF）整合**
RASO 的執行回饋可作為 RLHF 訓練資料的補充來源。將代理的成功與失敗軌跡轉化為偏好對，用於微調基礎 LLM，使其在無需顯式技能的情況下也能表現得更好。

**與知識圖譜整合**
對於結構化知識豐富的領域（如企業流程、合規規則），可將技能語料庫與知識圖譜連結，使檢索不僅基於語意相似度，還能考慮實體關係與因果依賴，提升檢索精準度。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先理解「代理技能」的概念——它不是模型參數，而是指導代理如何執行任務的自然語言文件。閱讀本文時，可先聚焦於圖 1 的整體框架圖，理解 RASO 如何從「直接生成技能」進化到「檢索後再適配技能」的設計動機，再回頭閱讀 RASI 與 RASU 的細節。實作上可從小規模技能語料庫（數十筆）開始，體驗跨執行環境適配的效果。

**給 AI 工程師**
重點關注跨執行環境適配機制的工程實作——這是 RASO 相較於傳統 RAG 的核心差異。建議深入分析論文中關於「92.9% 檢索結果來自不同執行環境」的實證數據，理解為何單純的語意檢索不足以解決問題。在實作時，應特別注意適配器的設計：如何讓 LLM 正確辨識並轉寫來源技能中的環境特定詞彙，是系統成敗的關鍵。

**給研究者**
本文的核心研究問題是「如何利用累積的程序性知識加速技能優化」，這在 prompt optimization 與 agentic learning 的交叉領域具有重要意義。建議從相關工作（TextGrad、GEPA、SkillOpt、WikiSkill）的比較出發，理解 RASO 在「知識來源」維度上的獨特貢獻。延伸研究方向可包括：跨執行環境適配的理論分析、檢索多樣性與效能的權衡、技能的組合性與可組合性等。

**給產品經理**
RASO 的商業價值在於「縮短代理上線時間」與「降低 rollout 成本」。傳統方法需數十次昂貴的代理執行才能優化技能，而 RASO 透過檢索增強可在零 rollout 的情況下產出可用初始技能。實務上，這意味著企業可以更快地將代理部署到新環境、新模型或新領域，同時維持高品質。建議在產品規劃中將「技能語料庫的累積」視為長期資產，建立跨團隊的技能共享機制。
