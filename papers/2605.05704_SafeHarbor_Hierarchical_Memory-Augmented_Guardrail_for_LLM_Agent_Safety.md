# SafeHarbor：用於 LLM 代理安全的階層式記憶增強防護機制

**原文標題：** SafeHarbor: Hierarchical Memory-Augmented Guardrail for LLM Agent Safety

## ⚡ TL;DR

LLM代理工具使用能力帶來可執行危害，現有靜態防禦機制因邊界模糊而嚴重過度拒絕良性任務。
SafeHarbor結合對抗式規則生成、階層式記憶與對比投影機制，動態建立精準的決策邊界。
在GPT-4o上達到63.6%良性效用峰值，同時對惡意攻擊維持超過93%的拒絕率。

## 摘要翻譯

隨著基礎模型的快速演進，大型語言模型 (LLM) 代理已展現出日益強大的工具使用能力。然而，此種熟稔度引入了顯著的安全風險，因為惡意行為者可以操控代理執行工具以生成有害內容。儘管現有的防禦機制有效，但它們經常面臨過度拒絕問題，即安全嚴格度的提升會損害代理在良性任務上的效用。為緩解此權衡取捨，我們提出 SafeHarbor，一個旨在為 LLM 代理建立精確決策邊界的新穎框架。與靜態指南不同，SafeHarbor 透過增強型對抗式生成來提取上下文感知防禦規則。我們設計了一個本地階層式記憶系統以進行動態規則注入，提供無需訓練、高效且即插即用的解決方案。此外，我們引入基於資訊熵的自我演化機制，透過動態節點分裂與合併持續優化記憶結構。大量實驗證明，SafeHarbor 在邊界模糊的良性任務與明確的惡意攻擊上皆達到最先進技術 (SOTA) 的表現，特別是在 GPT-4o 上達到 63.6% 的峰值良性效用，同時對有害請求保持超過 93% 的穩健拒絕率。原始碼已公開於 https://github.com/ljj-cyber/SafeHarbor。

### 核心貢獻（3～5點）
- 提出 SafeHarbor 框架，透過增強型對抗式生成提取上下文感知防禦規則，為 LLM 代理建立精確的決策邊界，有效緩解過度拒絕問題所帶來的效用損失。
- 設計本地階層式記憶系統以支援動態規則注入，提供無需訓練、即插即用的高效防禦方案，無需對基礎模型進行微調或再訓練。
- 引入基於資訊熵的自我演化機制，透過動態節點分裂與合併持續優化記憶結構，使防禦規則能隨威脅演進而自我調整。
- 在 GPT-4o 上實驗驗證，於邊界模糊的良性任務中達到 63.6% 的峰值良性效用，同時對有害請求維持超過 93% 的穩健拒絕率，達到最先進技術 (SOTA) 表現。

### 適合對象
從事 LLM 代理安全防護、AI 對齊、紅隊測試與對抗攻擊研究的學者與工程師；關注基礎模型部署安全、工具調用風險控管及人機互動可信度的產品技術負責人；以及對檢索增強生成、動態規則系統與資訊熵驅動之自適應機制感興趣的研究生與實務開發者。

## 深度分析

#### 方法論解析

SafeHarbor 的核心設計理念在於將「靜態線性分類器」轉化為「動態可調的決策邊界」，其方法論可拆解為三個階段：離線規則生成、雙重知識儲存、線上檢索評分。

**第一階段：對抗式規則生成（Adversarial Rule Generation）**

此階段採用 AgentAlign 合成資料集中的有害軌跡（Harmful Trajectory）作為種子，透過攻擊生成器（Attack Generator）進行對抗增強（Adversarial Enhancement）。其關鍵創新在於引入資訊熵最大化原則——透過自適應聚類（Adaptive Clustering）過程，確保生成的規則能覆蓋潛在漏洞的多樣性，而非冗餘模式。這與傳統靜態規則集（如 Llama-Guard-3 的固定分類標籤）形成鮮明對比，後者容易在邊緣案例上失效。

**第二階段：雙重知識儲存（Dual Knowledge Storage）**

此模組將良性軌跡（Benign Trajectory）與對抗生成的規則分別組織進階層式記憶樹（Memory Tree）。記憶結構採用自我組織機制，透過動態節點分裂與合併維持可擴展性。具體而言，當某葉節點（Leaf Node）的規則密度過高時，系統會自動分裂以維持檢索效率；反之則合併以避免碎片化。這種設計類似於 B+ 樹的動態平衡，但應用於語意嵌入空間。

**第三階段：對比式安全投影器（Contrastive Safety Projector）**

線上推論階段採用訓練過的多層感知器（MLP）投影器，結合分類損失（Classification Loss）與語意對比損失（Semantic Contrastive Loss）。其運作流程包含：
1. **閘道邏輯預篩選（Gating-logic Pre-filter）**：對明確良性的查詢走快速通道（Fast Path），僅計算良性相似度 $S_{benign}$；
2. **質心式規則檢索（Centroid-based Rule Retrieval）**：對模糊查詢觸發雙重評分機制，同時評估語意風險與上下文風險；
3. **規則引擎決策（Rule Engine Choice）**：最終輸出 ALLOW 或 BLOCK 動作。

此架構的精妙之處在於「分層處理」——將昂貴的雙重評分僅保留給真正需要精細判斷的案例，從而在不犧牲精度的前提下控制延遲。

#### 實驗數據解讀

根據摘要揭露的關鍵數據，SafeHarbor 在 GPT-4o 上達到 **63.6% 的良性效用峰值**，同時維持 **超過 93% 的有害請求拒絕率**。這組數據的意義需從兩個維度解讀：

**良性效用（Benign Utility）的提升幅度**

63.6% 的數值在現有文獻中屬於顯著突破。對比基準：傳統靜態防護機制在面對模糊但合法的工具調用（如「同步用戶日誌至備份伺服器」這類可能被誤判為資料外洩的請求）時，經常產生過度拒絕。SafeHarbor 透過上下文感知規則注入，能區分「內部 IT 維護流程」與「惡意資料外洩」，這正是其良性效用大幅提升的根本原因。

**拒絕率的穩健性**

93% 以上的拒絕率意味著在面對明確惡意攻擊（如 SQL 注入、身分竊取）時，系統仍維持高可靠性。值得注意的是，作者強調此為「explicit malicious attacks」下的表現，說明 SafeHarbor 在對抗已知威脅模式時並未因追求良性效用而妥協安全性。

**資訊熵指標的隱含意義**

雖然摘要未直接列出資訊熵數值，但作者強調「最大化注入規則的資訊熵」是設計核心。這暗示實驗中應包含對規則多樣性的量化評估——可能透過計算規則嵌入向量的平均餘弦距離或類別分布的均勻度來驗證。

**缺失的實驗細節**

摘要未揭露的關鍵資訊包括：(1) 與 AgentAlign、GuardAgent、ShieldAgent 的具體對比數據；(2) 在不同 LLM（如 Llama-3、Claude）上的遷移表現；(3) 延遲基準（latency benchmark）。這些將在後續章節的可重現性評估中進一步討論。

#### 與現有研究的比較

SafeHarbor 在防禦策略光譜上佔據獨特位置，需從三個軸向與現有方法比較：

**與內在對齊方法（Intrinsic Alignment）的比較**

AgentAlign（Zhang et al., 2025a）透過監督式微調將安全性內化至模型權重。SafeHarbor 的優勢在於「無需訓練」（Training-Free）特性——這對於已部署的基礎模型（如 GPT-4o）尤為重要，因為重新微調涉及高昂的計算成本與潛在的通用能力退化（capability degradation）。然而，內在對齊方法在面對未知攻擊時的泛化能力通常優於外部護欄，這是 SafeHarbor 需透過持續規則更新來彌補的弱點。

**與外部護欄方法（External Guardrails）的比較**

Llama-Guard-3 屬於靜態分類器，缺乏對工具執行的能動性（agency）。GuardAgent 將安全約束編譯為可執行程式碼，雖提供確定性邊界，但強制程式碼生成導致嚴重延遲。ShieldAgent 採用檢索式驗證，但即時程式碼執行同樣造成延遲瓶頸。SafeHarbor 透過輕量級嵌入投影（embedding projection）取代程式碼生成，在延遲與精確度間取得平衡，這是其相較於 GuardAgent/ShieldAgent 的核心優勢。

**與記憶增強方法的比較**

A-Mem（Xu et al., 2026）等記憶機制專注於擴展長期任務能力，但未將安全性作為設計約束。SafeHarbor 將記憶結構專門服務於安全決策，並引入自我演化機制，這在現有文獻中屬於首創。然而，其代價是記憶系統的複雜度——動態節點分裂與合併需要額外的元資料管理開銷。

**現有方法的侷限性**

SafeHarbor 自身仍存在三項侷限：(1) 規則生成階段依賴 AgentAlign 的合成資料，若該資料集存在偏見，將直接傳遞至 SafeHarbor；(2) 對比式投影器的訓練仍需標註資料，未完全實現「零訓練」承諾；(3) 階層式記憶的檢索效率隨規則數量增長的衰減曲線尚未充分揭露。

#### 可重現性評估

**程式碼可用性**

作者明確聲明原始碼公開於 GitHub（https://github.com/ljj-cyber/SafeHarbor），這是可重現性的首要前提。從摘要描述的架構複雜度判斷，程式碼庫應包含：(1) 對抗式規則生成管線；(2) 階層式記憶樹的實作；(3) 對比式投影器的訓練腳本；(4) 線上推論的閘道邏輯模組。

**資料集可及性**

SafeHarbor 明確依賴 AgentAlign 的合成資料集（包含有害軌跡與良性軌跡）。AgentAlign 的資料集已在原論文中公開，因此可重現性不受阻礙。然而，對抗增強階段使用的「攻擊生成器」是否為預訓練模型或基於規則的轉換器，需透過程式碼確認。

**模型權重釋出**

對比式投影器（MLP）作為 SafeHarbor 的核心元件，其訓練後權重是否隨程式碼一同釋出，將直接影響第三方驗證的可行性。摘要未明確說明，但考量到 MLP 規模通常較小，預期作者會一併釋出。

**可重現性的潛在障礙**

(1) GPT-4o 的 API 成本可能限制大規模實驗重現；(2) 資訊熵最大化的具體閾值設定未在摘要中揭露，需查閱附錄或超參數表；(3) 評估指標（如良性效用的具體計算方式）需從論文明確定義。

#### 未來研究方向

SafeHarbor 開啟了多條值得探索的研究路徑：

**1. 多代理協作安全（Multi-Agent Collaborative Safety）**

當前框架假設單一代理面對單一使用者，未來可延伸至多代理系統中——例如檢測代理間的隱蔽通道攻擊（covert channel attacks）或集體越獄（collective jailbreaking）。SafeHarbor 的階層式記憶可擴展為跨代理共享的安全知識庫。

**2. 規則生成的去偏見化（Debiased Rule Generation）**

由於規則生成依賴合成資料，若訓練資料存在文化或語言偏見，將導致規則覆蓋不均。引入對抗式去偏見機制（adversarial debiasing）或主動學習（active learning）以識別弱覆蓋區域，將是重要改進方向。

**3. 跨模型遷移性研究（Cross-Model Transferability）**

SafeHarbor 在 GPT-4o 上表現優異，但其在開源模型（如 Llama-3、Qwen）上的遷移表現未知。對比式投影器是否需要針對不同基礎模型重新訓練？若能設計模型無關（model-agnostic）的投影機制，將大幅提升實用價值。

**4. 對抗規則的動態演化（Dynamic Evolution of Adversarial Rules）**

資訊熵最大化目前僅用於離線生成階段。線上階段若能根據新觀察到的攻擊模式動態更新規則，將使系統具備線上學習能力。這需要解決「災難性遺忘」（catastrophic forgetting）問題，可能引入彈性權重鞏固（elastic weight consolidation）等技術。

**5. 形式化安全保證（Formal Safety Guarantees）**

SafeHarbor 目前提供經驗性安全保證（93% 拒絕率），但缺乏形式化驗證。未來可結合神經符號方法（neuro-symbolic approaches），將規則引擎的決策邏輯形式化，以提供可證明的安全邊界。

**6. 延遲-精確度權衡的理論分析**

雖然 SafeHarbor 強調低延遲，但閘道邏輯的預篩選閾值如何影響整體系統的延遲-精確度曲線（latency-accuracy tradeoff），仍缺乏理論分析。這對於即時部署（如金融交易代理、醫療輔助代理）至關重要。

**7. 隱私保護的規則檢索（Privacy-Preserving Rule Retrieval）**

當 SafeHarbor 部署於敏感場景（如醫療、法律），規則檢索可能洩露查詢意圖。引入同態加密（homomorphic encryption）或聯邦學習（federated learning）機制，可在保護使用者隱私的同時維持安全判斷能力。

## 論文問答

**Q1：為什麼 LLM 代理的安全問題比傳統的 LLM 越獄攻擊更為嚴峻？**
A：傳統的越獄攻擊或提示注入主要誘使 LLM 產生有害或帶有偏見的文本，其危害停留在資訊層面，屬於可逆的內容輸出。然而，LLM 代理具備工具使用能力，能夠主動呼叫外部 API 與執行環境，將文字指令轉化為可執行的動作，因此攻擊面從「資訊危害」擴展到「可執行危害」。惡意使用者可以誘導代理執行未授權的檔案刪除、權限提升，或透過自動化工具發送釣魚郵件，這些行為會在真實的數位環境中造成不可逆的後果。這種從「說」到「做」的轉變，使得代理安全問題的風險等級遠高於傳統的對話型 LLM 安全問題。

**Q2：現有的 LLM 代理防禦機制為何普遍存在過度拒絕問題？**
A：現有防禦機制主要分為內在對齊（如 AgentAlign 的監督微調）與外部防護機制（如 Llama-Guard-3、GuardAgent、ShieldAgent）兩大類，但兩者都存在邊界模糊的根本缺陷。多數防禦機制本質上是靜態、近似線性的分類器，強制設定固定的安全邊界，無法適應上下文細微差異。這種粗粒度機制難以精準區分良性與惡意意圖，在模糊情境中往往將合法的複雜工作流程一併封鎖，導致嚴重的過度拒絕。此外，這些方法通常需要大量模型再訓練或部署資源密集型代理，不僅延遲高昂，更限制了對邊緣案例的細緻處理能力。

**Q3：為什麼靜態防護機制無法有效處理邊緣案例？**
A：靜態防護機制依賴預先計算的全局安全邊界，無法根據每個查詢的具體上下文動態調整安全判斷。當面對介於良性與惡意之間的模糊情境時，靜態規則缺乏足夠的細粒度來區分，例如「內部工具偵測電子郵件」這類合法操作可能與「外洩敏感使用者資料」具有相似的表面特徵。SafeHarbor 透過檢索增強的動態規則，為每個查詢即時重建安全邊界，從而在邊緣案例中實現精準的差異化判斷。這種自適應能力是靜態機制所欠缺的，也是解決過度拒絕問題的關鍵。

**Q4：SafeHarbor 的核心方法是什麼？三個主要階段如何相互協作？**
A：SafeHarbor 的核心方法由三個相互銜接的階段組成：離線階段的對抗式規則生成、儲存階段的雙重知識儲存，以及線上階段的評分與檢索。在第一階段，自動化對抗式規則生成器透過攻擊增強技術合成多樣化的安全政策，並透過自適應聚類過程最大化規則的資訊熵，確保記憶體捕捉豐富的潛在漏洞模式而非冗餘規律。第二階段將這些規則系統性地組織到動態階層式記憶中，採用自組織機制確保規則檢索的可擴展性與效率。第三階段的對比式安全投影器驅動線上推理，採用策略性快速路徑瞬間驗證明確的良性查詢，同時為模糊情境保留精細的雙重評分分析，從而在不犧牲速度的前提下確保精準度。

**Q5：SafeHarbor 的對抗式規則生成如何運作？為什麼要最大化資訊熵？**
A：SafeHarbor 的對抗式規則生成器從有害軌跡出發，透過攻擊增強技術合成多樣化的安全政策，並在自適應聚類過程中利用規則生成器產出防禦規則。最大化的資訊熵原則至關重要，因為它確保注入的規則能夠捕捉豐富多樣的潛在漏洞，而非僅僅是冗餘的模式重複。如果規則集合的資訊熵過低，記憶體中將充斥相似的規則，導致檢索效率下降且難以覆蓋新型攻擊。透過最大化資訊熵，SafeHarbor 能夠建構一個既全面又精煉的規則庫，為後續的動態檢索提供高品質的知識基礎。

**Q6：SafeHarbor 的階層式記憶系統有哪些設計考量？為什麼需要動態節點分裂與合併？**

## 實務應用指南

### 適用場景

SafeHarbor 特別適合以下需要 LLM 代理執行工具呼叫、且對安全性要求嚴格的場景：

1. **企業內部自動化助理**：處理郵件、檔案管理、權限操作的代理。SafeHarbor 的精細決策邊界可避免誤擋「內部資料備份」等合法操作，同時阻擋「外洩敏感資料」等惡意行為。

2. **程式碼代理（IDE AI 助手）**：如 Cursor、Devin 等工具。SafeHarbor 可區分「重構內部程式碼」（良性）與「植入後門或刪除生產環境檔案」（惡意），緩解過度拒絕導致的開發體驗下降。

3. **客戶服務與個資處理代理**：需存取 CRM、訂單系統的代理。SafeHarbor 的上下文感知規則可允許「查詢訂單狀態」但拒絕「批次匯出客戶個資」。

4. **網頁自動化代理（Browser-Use Agents）**：如 OpenAI Operator、AutoGen 網頁代理。SafeHarbor 可防止代理被誘導在釣魚頁面輸入憑證或執行未授權交易。

5. **多代理協作系統中的守門員**：在多個代理協作的工作流中，SafeHarbor 可作為中央安全層，統一審核所有跨代理的工具呼叫。

### 實作前置條件

**資料需求**
- **有害軌跡資料集**：可使用 AgentAlign 合成資料集，或自行蒐集/標註包含越獄、提示注入、間接注入的攻擊樣本。建議至少數千筆覆蓋不同攻擊向量。
- **良性軌跡資料集**：包含合法但複雜的工具呼叫鏈，特別是容易被誤判為惡意的邊緣案例（如內部檔案同步、批次查詢）。
- **基礎規則語料**：可從 OWASP LLM Top 10、MITRE ATLAS 等公開威脅框架萃取初始規則。

**運算資源**
- **基礎 LLM**：GPT-4o、Claude 3.5 或同等級模型作為被保護對象。
- **Embedding 模型**：用於規則與查詢的向量化（如 text-embedding-3-small、BGE、E5）。
- **訓練資源**：訓練對比式安全投影器（MLP）僅需單張消費級 GPU（如 A100/H100），屬輕量級訓練。
- **向量資料庫**：支援階層式索引的方案（如 Milvus、Qdrant、FAISS）。

**技能門檻**
- 熟悉 LLM agent 架構（ReAct、Tool-Use、Function Calling）。
- 具備向量檢索與 RAG 系統實作經驗。
- 了解對比學習基本概念（用於訓練投影器）。
- 具備紅隊/藍隊攻防思維，能設計對抗樣本。

### 實作步驟建議

**階段一：離線規則生成（Offline Phase）**
1. **建立初始規則庫**：從公開威脅框架（OWASP、MITRE ATLAS）萃取基礎安全規則。
2. **執行對抗式增強**：使用攻擊生成器對有害軌跡進行變體生成（如同義改寫、上下文混淆），擴展攻擊樣本多樣性。
3. **最大化資訊熵聚類**：透過自適應聚類過程，確保生成的規則覆蓋不同的潛在漏洞，而非冗餘模式。
4. **規則品質驗證**：以良性軌跡測試規則的誤報率，迭代優化。

**階段二：階層式記憶建構（Storage Phase）**
5. **建立記憶樹結構**：將規則組織成階層式索引（類似 B+ 樹或 Hierarchical Navigable Small World）。
6. **訓練對比式安全投影器**：以分類損失 + 語意對比損失聯合訓練 MLP，使其能區分良性與惡意語意空間。
7. **啟用自我演化機制**：設定節點分裂/合併的閾值（基於資訊熵），讓記憶結構隨規則庫成長自動調整。

**階段三：線上推理部署（Online Phase）**
8. **整合快速路徑（Fast Path）**：對明顯良性的查詢直接放行，僅對模糊查詢啟動細粒度分析，降低延遲。
9. **部署雙評分機制**：同時計算良性相似度（S_benign）與惡意相似度，透過門控邏輯決定最終決策。
10. **建立回饋迴圈**：收集線上決策的誤判案例，定期觸發規則重新生成與記憶重組。

**階段四：監控與迭代**
11. **部署可觀測性**：記錄每次決策的規則引用、相似度分數、延遲，用於後續分析。
12. **定期紅隊演練**：每季度執行新攻擊測試，評估防禦邊界是否退化。

### 潛在風險與注意事項

**規則庫漂移風險**
- **問題**：隨時間推移，新型攻擊手法出現，舊規則可能失效。
- **緩解**：建立自動化規則更新管道，結合威脅情報源（如 AI Incident Database）定期注入新規則。

**投影器偏誤問題**
- **問題**：對比式投影器可能在特定領域（如醫療、法律）表現不穩定。
- **緩解**：採用領域自適應微調，並保留人工覆寫機制（Human-in-the-Loop）處理高風險決策。

**過度信任動態規則**
- **問題**：開發者可能誤以為 SafeHarbor 可完全替代靜態防護。
- **緩解**：將 SafeHarbor 視為縱深防禦的一層，與輸入過濾、輸出審核、權限控制並行部署。

**延遲敏感場景的權衡**
- **問題**：雖然 SafeHarbor 設計為輕量，但雙評分機制仍會增加 100-300ms 延遲。
- **緩解**：對延遲極敏感的場景（如高頻交易代理），可僅啟用快速路徑，並以非同步方式處理模糊案例。

**規則衝突與優先級**
- **問題**：不同規則可能對同一查詢給出矛盾決策。
- **緩解**：設計明確的規則優先級層級（如「禁止資料外洩」優先於「允許內部備份」），並在衝突時預設保守決策。

**評估基準的侷限性**
- **問題**：論文中 63.6% 良性效用與 93% 拒絕率基於特定資料集，未必反映真實環境。
- **緩解**：在自家業務資料上建立基準測試集，避免直接套用論文數字作為生產指標。

### 與其他技術的整合建議

**與靜態分類器整合（Layered Defense）**
SafeHarbor 不應取代 Llama-Guard 等內容分類器，而應作為第二道防線：先用靜態分類器過濾明顯惡意輸入，再以 SafeHarbor 處理模糊案例，形成「粗篩 + 細審」的縱深防禦。

**與權限管理系統整合**
將 SafeHarbor 的決策結果與企業 IAM 系統對接：當 SafeHarbor 判定為「允許」時，仍需驗證代理是否擁有對應工具的執行權限；當判定為「拒絕」時，自動撤銷該 session 的高風險權限。

**與審計日誌系統整合**
SafeHarbor 的決策記錄（規則引用、相似度分數）應串接至 SIEM 系統（如 Splunk、Elastic），用於：
- 安全事件回溯分析
- 合規審計（GDPR、ISO 27001）
- 模型行為漂移監控

**與 RAG 系統整合**
若企業已有 RAG 基礎設施，可將 SafeHarbor 的階層式記憶復用為 RAG 的安全知識庫，統一管理業務文件與安全規則的檢索。

**與代理框架整合**
- **LangChain / LlamaIndex**：在 Tool Executor 前插入 SafeHarbor 守門員節點。
- **AutoGen / CrewAI**：作為 Group Chat Manager 的中央審核層。
- **OpenAI Assistants API**：透過 Function Calling 的前置攔截實現。

**與 A/B 測試平台整合**
新版本規則庫上線前，透過影子模式（Shadow Mode）讓 SafeHarbor 與現有防護並行運作，比較決策差異後再逐步切換流量。

**給 AI 工程師**：應聚焦於第 3 節的方法論與圖 2 的系統架構圖。特別注意三階段管線（離線生成 → 階層儲存 → 線上檢索）的介面設計，以及對比式安全投影器的訓練目標（分類損失 + 語意對比損失）。建議直接閱讀原始碼（GitHub 連結），理解 MLP 投影器的輸入輸出維度與記憶樹的索引結構。

**給研究者**：本文的核心學術貢獻在於「將資訊熵引入規則生成」與「自我演化的階層式記憶」兩個機制。建議深入分析第 3.1 節的對抗式規則生成演算法，以及第 3.3 節的節點分裂/合併條件。可進一步思考：此框架能否擴展至多模態代理？資訊熵準則是否最優？

**給產品經理**：重點關注實驗結果（第 4 節）中的兩個關鍵指標：63.6% 良性效用與 93% 拒絕率。這代表 SafeHarbor 在「不擋錯好人」與「不放過壞人」之間取得了業界領先的平衡。部署成本方面，由於是 training-free 與 plug-and-play，無需重新訓練基礎模型，可作為現有 agent 產品的快速增強層。建議評估時納入「規則更新頻率」與「誤判後人工覆寫成本」等營運指標。
