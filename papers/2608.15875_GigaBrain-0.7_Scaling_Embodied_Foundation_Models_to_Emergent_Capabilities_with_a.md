# GigaBrain-0.7：透過三系統架構將具身基礎模型擴展至湧現能力

**原文標題：** GigaBrain-0.7: Scaling Embodied Foundation Models to Emergent Capabilities with a Three-System Architecture  
**作者：** GigaBrain Team、Angen Ye、Axiang Sun 等 59 位作者

## ⚡ TL;DR

現有視覺-語言-動作模型難以擴展異質資料、跨本體泛化，且理解、預測與執行缺乏協調。
GigaBrain-0.7 提出三系統架構與單階段多本體預訓練，整合理解、規劃、預測與連續動作生成。
於多種真實與模擬機器人上，零樣本、指令遵循與後訓練成功率均顯著優於先前最佳模型。

## 摘要翻譯

視覺-語言-動作（Vision-Language-Action, VLA）模型已成為通用型具身智能體的主流典範，在結構化環境中展現出強大的複雜長程任務完成能力。然而，當前的 VLA 系統是否能從更有效的架構設計中受益、擴展至規模更大且異質性更高的資料情境（data regimes），並在任務與本體（embodiments）上實現更廣泛的泛化，仍是一個開放問題。為此，我們提出 GigaBrain-0.7，一個在跨多樣機器人本體（robot embodiments）泛化能力上顯著提升的具身基礎模型（embodied foundation model）。具體而言，GigaBrain-0.7 透過三系統架構（three-system architecture）統一理解、預測與動作，將預訓練（pretraining）規模擴展至超過 37,000 小時的異質具身資料（heterogeneous embodied data），並引入單階段對齊訓練（one-stage alignment training），聯合優化視覺-語言理解（vision-language understanding）與多本體動作生成（multi-embodiment action generation）。相較於先前的 GigaBrain-0 系列以及包含 π_{0.5} 在內的現有最先進模型，GigaBrain-0.7 在基礎模型的零樣本能力（foundation zero-shot capabilities）、語言條件化指令遵循（language-conditioned instruction following）以及後訓練任務成功率（post-training task success rates）方面均有顯著提升。特別是在我們自有的 Maker H01 平台（Maker H01 platform）與主流機器人本體上，GigaBrain-0.7 在家庭與工業場景中均展現出強大的任務適應性與完成能力。所有訓練程式碼與預訓練模型權重都將公開釋出。

### 核心貢獻（3～5點）
- 提出三系統架構（three-system architecture），統一理解、預測與動作三大能力。
- 將預訓練規模擴展至超過 37,000 小時的異質具身資料（heterogeneous embodied data）。
- 引入單階段對齊訓練（one-stage alignment training），聯合優化視覺-語言理解與多本體動作生成。
- 在基礎模型的零樣本能力、語言條件化指令遵循與後訓練任務成功率上，顯著超越前代 GigaBrain-0 系列與 π_{0.5} 等最先進模型。
- 在自有的 Maker H01 平台與主流機器人本體上，驗證家庭與工業場景的任務適應性與完成能力，並承諾開源訓練程式碼與模型權重。

### 適合對象
機器人學、具身智慧與多模態基礎模型研究者，以及希望將視覺-語言-動作模型部署於真實機器人平台、關注跨本體泛化與開源實作的工程師與開發者。

## 深度分析

#### 方法論解析

GigaBrain-0.7 的核心貢獻在於提出一個「單階段對齊訓練（one-stage alignment training）」與「三系統架構（three-system architecture）」相結合的具身基礎模型（embodied foundation model）。與傳統多階段 Vision-Language-Action（VLA，視覺-語言-動作）訓練管線不同，本研究將預訓練視覺-語言模型骨幹（pretrained VLM backbone）、連續動作專家（continuous-action expert）與多模態理解目標（multimodal understanding objectives）放在同一個優化階段中聯合訓練，藉此消除「優化碎片化（optimization fragmentation）」問題。這種設計的關鍵在於：視覺-語言理解與機器人動作生成並非先後獨立學習，而是共享表示並互相正則，從而提升跨本體泛化（generalization across embodiments）能力。

為了避免動作梯度過度破壞 VLM 的通用視覺-語言能力，GigaBrain-0.7 採用 Soft Knowledge Insulation（Soft KI，軟知識隔離）。相較於完全阻斷動作梯度進入 VLM 骨幹的 Knowledge Insulation，Soft KI 選擇「衰減」而非「封鎖」這些梯度，使 VLM 能夠在受控條件下適應具身控制任務，同時保留其原本的多模態理解能力。這對於單階段聯合訓練尤為重要，因為動作目標與語言理解目標的梯度尺度與分佈可能差異極大。

在模型架構層面，GigaBrain-0.7 明確區分三個功能系統：

- **System 1（Action and Control，動作與控制）**：負責生成連續動作區塊（action chunks）。它採用 flow matching（流匹配）作為生成式建模手段，輸入包含多模態觀測（multimodal observations）、語言指令（language instructions）、本體感覺狀態（proprioceptive states）以及來自上層系統的情境訊號。動作生成由一個具本體感知動作專家（embodiment-aware action expert）執行，能夠適應不同機器人形態的自由度（degrees of freedom, DoF）與控制模式（control modes）。Flow matching 的優勢在於可以建模高維連續動作分佈，並支援較長的預測視野，這對於需要平滑軌跡的機器人控制至關重要。

- **System 2（Understanding and Planning，理解與規劃）**：負責對當前與歷史視覺觀測進行時間上下文建模（temporal context modeling），追蹤任務進度，並透過階層式提示（hierarchical prompts）將長程任務（long-horizon tasks）分解為可執行的子任務（subtasks）。這使得模型不僅是反應式觀測到動作預測（reactive observation-to-action prediction），而是具備某種程度的規劃與語義理解能力。

- **System 3（Prediction and Evaluation，預測與評估）**：內建一個世界模型（world model），用於預測未來視覺狀態（以子目標影像 subgoal images 的形式呈現）並估計狀態價值（state values）。這兩種輸出分別作為視覺條件與價值條件，提供兩個互補的介面給 System 1，從而改善動作生成的遠見與目標導向性。

三個系統之間透過結構化語義介面（structured semantic interfaces）、視覺介面與基於價值的介面（value-based interfaces）進行溝通，但各自保留專屬的目標函數。這種「功能解耦、表示共享」的設計，讓理解、預測與動作執行能夠協調運作，而不會因為單一目標主導而壓抑其他能力。

在資料層面，GigaBrain-0.7 的預訓練資料規模達到 37,000 小時以上的異質具身資料（heterogeneous embodied data），涵蓋 16 種機器人形態（robot morphologies）與約 2.7 億個視覺-語言樣本（vision-language samples）。所有軌跡資料都經過統一處理管線：轉換為 LeRobot v3.0 格式、跨本體狀態-動作正規化（cross-embodiment state-action normalization）、以大型語言模型（LLM）輔助重寫語言指令與標註子任務，以及多階段品質控管。這樣的資料工程是模型能夠從大規模異質資料中學到可遷移知識的基礎。

#### 實驗數據解讀

論文的實驗設計圍繞三個層次展開：大規模預訓練的擴展性研究（scaling studies）、基礎能力評估（foundation capability evaluation），以及真實機器人與模擬環境中的任務執行測試。

首先，在擴展性研究中，作者觀察到隨著機器人資料規模增加，驗證損失（validation loss）呈現穩定下降，且一些在較小規模下難以穩定出現的真實機器人行為（challenging real-robot behaviors）變得越來越可靠。這暗示大規模異質預訓練可能帶來某種「湧現能力（emergent capabilities）」的跡象。不過，由於目前提供的摘要與引言並未給出具體數值，我們無法判斷這種湧現是連續改善還是存在明確的相變臨界點。此外，System 3 的消融實驗（ablations）與分佈外評估（out-of-distribution evaluations）也被用來佐證預測與評估模組對泛化的貢獻。

其次，在基礎能力方面，GigaBrain-0.7 在多模態理解基準（multimodal understanding benchmarks）以及多個模擬環境（涵蓋桌面操作 tabletop、移動機器人 mobile、家庭操作 household manipulation）中進行測試。這類評估的重要性在於確認模型在進行機器人控制之餘，並未犧牲 VLM 原本的視覺-語言理解能力，這也呼應了 Soft KI 的設計動機。

第三，在真實機器人評估中，論文使用了 AgileX PiPER / PiPER-X 以及自有的 Maker H01 platform（Maker H01 平台）。測試項目包括零樣本執行（zero-shot execution）、多任務執行（multi-task execution）、語言條件化指令遵循（language-conditioned instruction following）、分佈外泛化（out-of-distribution generalization）以及長程操作（long-horizon manipulation）。這些任務同時覆蓋家庭與工業場景，顯示模型具備一定的任務適應性（task adaptability）。

針對 System 3 的貢獻，作者進行了控制實驗，分析未來狀態預測（future-state predictions）與基於價值的評估訊號（value-based evaluation signals）各自的影響，以及兩者聯合作用的效果。這有助於釐清世界模型（world model）在動作生成中究竟扮演「提供額外視覺目標」還是「提供內在獎勵訊號」的角色。

最後，在與基線模型的比較中，GigaBrain-0.7 超越了前代 GigaBrain-0 系列以及 π0.5（在經過任務特定後訓練 post-training 後）的表現，並在基礎零樣本能力（foundation zero-shot capabilities）、語言條件化指令遵循與後訓練任務成功率（post-training task success rates）上取得顯著提升。此外，透過人類在迴路（human-in-the-loop）的 rollout 資料與修正回饋（corrective feedback），模型還能進行經驗驅動的策略改進（experience-driven policy improvement）。

整體而言，實驗結果支持「規模化異質資料 + 三系統協同 + 單階段對齊」這一組合的有效性。但由於目前可見的文本未提供詳細數據表格，我們尚無法評估各項改進的統計顯著性與任務間差異。

#### 與現有研究的比較

GigaBrain-0.7 置身於當前 VLA（視覺-語言-動作）研究的三大家族之中，並試圖取長補短：

1. **自迴歸 VLM-as-Actor 家族**：代表工作包括 RT-2、OpenVLA、FAST 與 Galaxea G0.5。這類方法將連續動作離散化為 token 序列，並直接由 VLM 進行 next-token prediction。其優點是保留了語言建模與動作生成之間的直接介面，但缺點是當控制頻率、預測視野與動作維度增加時，序列解碼成本會急遽上升。GigaBrain-0.7 選擇不將動作離散化，而是透過 flow matching 生成連續動作區塊，並由獨立的 action expert 負責低階控制，因此在計算效率與動作表達力上具有優勢。

2. **串接式（cascaded）VLM–action-expert 家族**：代表工作包括 GR00T N1、Gemini Robotics 與 Qwen-RobotManip。這類方法將多模態推理與連續動作生成分離，與 GigaBrain-0.7 的 System 1 + System 2 設計理念相近。然而，GigaBrain-0.7 進一步引入 System 3 的世界模型（world model）作為預測與評估模組，並採用單階段對齊訓練（one-stage alignment training）與 Soft KI，使理解、預測與動作在訓練階段就能協同優化，而不只是將 VLM 編碼器與動作解碼器簡單拼接。

3. **GigaBrain 系列自身演進**：GigaBrain-0 提出以世界模型作為可擴展資料引擎與具身推理監督；GigaBrain-0.5M* 則透過 RAMP 發展出世界模型條件化的策略學習（world-model-conditioned policy learning）。GigaBrain-0.7 將這些元素整合為一個涵蓋資料整理（data curation）、預訓練（pretraining）、規劃（planning）、預測（prediction）、執行（execution）與持續改進（continual improvement）的協調學習系統。

相較於 π0.5，GigaBrain-0.7 在基礎零樣本能力、語言條件化指令遵循與後訓練任務成功率上均有顯著提升。這顯示三系統架構與大規模異質資料預訓練確實能帶來實質進展。然而，目前文本未說明比較是否在同一組任務、相同機器人平台與相同後訓練資料量下進行，因此我們在解讀時應保留一定謹慎。

可能的限制包括：實驗主要集中於 AgileX PiPER 系列與 Maker H01 平台，對於更廣泛的機器人本體（embodiments）與感測器配置（例如僅有 RGB、無力覺回饋）的泛化能力仍需更多驗證；世界模型的預測品質與長程規劃的穩定性也可能成為瓶頸；此外，模型的訓練與推論成本在現有文本中並未詳細披露，這對於學術界與產業界的實際部署至關重要。

#### 可重現性評估

可重現性（reproducibility）是衡量具身基礎模型研究價值的關鍵指標。根據摘要與引言，作者承諾將公開所有訓練程式碼（training code）與預訓練模型權重（pretrained model weights）。若此承諾完整兌現，將大幅提升研究社群驗證與延伸此工作的可能性。

資料處理管線採用 LeRobot v3.0 這一開放格式，並進行跨本體狀態-動作正規化（cross-embodiment state-action normalization）與 LLM 輔助的語言指令重寫，這些步驟若伴隨詳細腳本與配置文件釋出，將有助於其他研究者複製資料前處理流程。然而，37,000 小時以上的異質具身資料（heterogeneous embodied data）本身規模龐大，且涉及多個機器人平台與資料來源，完整公開原始軌跡資料的可能性較低。因此，未來的可重現性可能主要依賴於：
- 預訓練權重與推論程式碼；
- 資料處理與訓練配置的詳細文件；
- 評估協議（evaluation protocols）與任務定義的標準化。

若作者能進一步提供模型架構圖、超參數、訓練硬體配置、損失曲線以及各基準測試的詳細數據，將使本研究成為具身 AI 領域的重要開放資源。反之，若僅釋出權重而缺少訓練細節，則其他團隊難以判斷各設計選擇的個別貢獻，可重現性將大打折扣。

#### 未來研究方向

基於 GigaBrain-0.7 的架構與實驗設計，未來研究可朝以下方向延伸：

1. **進一步擴展資料與模型規模**：目前預訓練已達 37,000 小時與 16 種機器人形態，但未來可納入更多樣化的本體（embodiments）、動作空間（action spaces）與執行條件，並探索資料規模與湧現能力（emergent capabilities）之間的明確關係。

2. **強化世界模型（world model）的長程規劃能力**：當前任務仍偏向中短程操作，未來可讓世界模型支援更長的未來狀態預測、反事實推理（counterfactual reasoning）與多步驟規劃，並結合 System 2 的階層式提示（hierarchical prompts）進行更複雜的任務分解。

3. **線上適應與持續學習**：GigaBrain-0.7 已初步展示透過 rollout 與修正回饋（corrective feedback）進行經驗驅動改進的能力。未來可發展自動化的錯誤偵測與自我修正機制，減少對人類在迴路（human-in-the-loop）的依賴，並避免災難性遺忘（catastrophic forgetting）。

4. **安全性與穩健性**：在真實環境部署時，需要引入不確定性量化（uncertainty quantification）、風險感知的狀態價值估計（risk-aware state value estimation）與安全中斷機制，特別是在家庭與工業場景中人機共存的應用。

5. **效率與邊緣部署**：三系統架構雖然功能強大，但推論成本可能較高。未來可研究模型蒸餾（distillation）、量化（quantization）與系統級推論優化，使模型能夠在資源受限的機器人硬體上即時運行。

6. **跨本體遷移的理論理解**：目前跨本體泛化（generalization across embodiments）主要透過實驗驗證，未來可建立更嚴謹的理論框架與標準化基準，以量化不同本體之間的知識轉移效率。

7. **多模態理解與具身推理的更深整合**：除了視覺與語言，未來可納入觸覺、力覺、聽覺等更多感知模態，並探索這些模態如何透過三系統架構與動作生成協同作用。

總結來說，GigaBrain-0.7 透過單階段對齊訓練與三系統架構，為具身基礎模型（embodied foundation models）的規模化與泛化提供了一個有潛力的範式。未來若能進一步開放資料細節、強化長程規劃與線上學習，並解決部署效率與安全問題，將有望推動通用機器人（general-purpose robots）朝更實用的方向邁進。

## 論文問答

**Q1：GigaBrain-0.7 主要想解決什麼問題？**
A：GigaBrain-0.7 旨在探討現有的視覺-語言-動作模型是否能透過更有效的架構設計，擴展到更大規模且更多樣的異質具身資料，並在跨任務與跨本體的場景中獲得更廣泛的泛化能力。現有 VLA 雖然在結構化環境中表現出色，但大多仍侷限於反應式觀測到動作預測，缺乏對未來狀態的預判與行為進度的評估機制。此外，機器人資料在不同本體、動作空間與執行條件下差異極大，若缺乏適當對齊，單純增加資料規模反而可能帶來干擾而非可遷移知識。

**Q2：為什麼現有的 VLA 方法難以有效規模化？**
A：現有 VLA 大多以反應式觀測到動作預測為核心，難以在完整學習週期中協調理解、規劃、預測判斷、動作執行與經驗驅動改進。機器人資料在本體、動作空間與執行條件上高度異質，若未經適當對齊與情境化，規模化只會加強干擾而非促進知識遷移。此外，多階段訓練管線常造成優化碎片化，使視覺-語言理解與動作生成無法被聯合優化。

**Q3：規模化具身基礎模型為何重要？**
A：規模化具身基礎模型是邁向通用型機器人的關鍵，因為它有潛能讓單一模型跨越多樣本體、任務與環境，並減少針對特定任務的工程調整。論文指出，大規模異質具身預訓練能催生出湧現的具身能力，使複雜的真實機器人行為變得更加穩定可靠。這將使機器人更接近基礎模型級別的泛化，能在家居、工業與其他真實場景中實現開箱即用的部署或僅需少量下游適應。

**Q4：GigaBrain-0.7 的核心方法是什麼？**
A：GigaBrain-0.7 的核心是一套三系統架構，將理解、預測與動作統整為協調運作的學習系統。System 1 負責動作與控制，透過流匹配從多模態觀測、語言指令、本體感覺狀態與高階情境訊號生成連續動作區塊。System 2 負責理解與規劃，透過時間上下文建模追蹤任務進度，並以階層式提示將長程指令分解為可執行子任務。System 3 則負責預測與評估，利用世界模型預測未來視覺狀態並估計狀態價值，為 System 1 提供兩種互補的條件化介面。

**Q5：GigaBrain-0.7 的關鍵創新有哪些？**
A：關鍵創新包括三系統協調架構、單階段多本體 VLA 預訓練框架，以及 Soft Knowledge Insulation 機制。單階段訓練能同時聯合優化預訓練視覺-語言模型骨幹、連續動作專家與多模態理解目標，消除傳統多階段管線的優化碎片化問題。具本體感知動作專家可適應不同機器人形態的自由度與控制模式，而 System 3 同時提供未來狀態預測與基於價值的評估訊號，強化動作生成的規劃性與穩健性。

**Q6：GigaBrain-0.7 的設計選擇與現有 VLA 家族有何不同？**
A：不同於將連續動作離散化為 token 序列的自迴歸 VLM-as-Actor 模型，GigaBrain-0.7 採用流匹配直接生成連續動作區塊，避免高維度與長預測區間帶來的序列解碼成本。相較於串接式 VLM–動作專家架構，GigaBrain-0.7 以單階段對齊訓練同時優化理解與動作生成，使兩者能相互適應。此外，三系統架構透過結構化語義、視覺與基於價值的介面進行溝通，讓執行、規劃與預測評估能協調運作，而非各自獨立。

**Q7：論文使用了哪些評估基準與實驗設定？**
A：實驗首先在多模態理解基準以及涵蓋桌面、移動與家庭操作的模擬環境中評估基礎能力。真實世界評估則在 AgileX PiPER／PiPER-X 與自有 Maker H01 平台上進行，涵蓋零樣本與多任務執行、語言條件化指令遵循、分佈外泛化與長程操作。此外，作者也進行系統性的規模化研究與控制變因消融實驗，分析機器人資料規模、資料來源組成、VLM 骨幹容量、VLA 耦合架構，以及 System 3 中未來狀態預測與價值評估訊號的個別與聯合影響。

**Q8：論文的主要實驗結果是什麼？**
A：GigaBrain-0.7 在基礎零樣本能力、語言條件化指令遵循與後訓練任務成功率上，相較於前代 GigaBrain-0 系列與 π0.5 等先進模型都有顯著提升。規模化研究顯示，隨著預訓練資料規模增加，驗證損失持續下降，且困難的真實機器人行為變得更加可靠。System 3 的消融實驗與分佈外評估也顯示，大規模異質具身預訓練開始出現湧現的具身能力跡象。

**Q9：消融實驗揭示了什麼？**
A：消融實驗顯示，System 3 的未來狀態預測與基於價值的評估訊號對動作生成具有互補作用，兩者結合能顯著提升規劃品質與執行穩健性。規模化研究則證明，資料規模、VLM 骨幹容量與 VLA 耦合架構的選擇都會系統性地影響模型表現，且更大規模預訓練能持續降低驗證損失。這些結果共同指出，架構設計、資料規模與預測性訓練目標之間存在協同效應，而非單純的加成關係。

**Q10：GigaBrain-0.7 可應用於哪些實務場景？**
A：GigaBrain-0.7 在 Maker H01 平台與主流機器人本體上展現出家居與工業場景的任務適應性與完成能力，適用於家庭輔助、製造、物流與服務型機器人。其跨本體泛化能力使同一模型能部署於不同自由度和控制模式的機器人硬體，降低為每種平台單獨開發策略的成本。模型對自然語言指令的遵循能力與長程操作能力，也使其適合人機協作與需要彈性調適的自適應自動化應用。

**Q11：部署 GigaBrain-0.7 時需要考慮哪些產品化因素？**
A：部署時需處理不同機器人本體的自由度、控制模式與本體感覺狀態差異，而具本體感知動作專家正是為此設計。統一的資料處理管線，包括轉換為 LeRobot v3.0 格式與跨本體狀態-動作正規化，有助於與現有機器人軟體堆疊整合。此外，訓練程式碼與預訓練權重的公開釋出，能降低產品團隊針對特定機器人與任務進行後訓練與適應的門檻。

**Q12：GigaBrain-0.7 可能對機器人領域帶來什麼影響？**
A：GigaBrain-0.7 證明大規模異質具身預訓練搭配協調式三系統架構能催生出湧現的具身能力，可能推動機器人領域朝向更統一的通用型學習系統發展。訓練程式碼與模型權重的公開釋出，將加速學術界與產業界的研究與應用開發。此研究也強化了視覺-語言基礎模型與物理控制之間的連結，使機器人更有可能以接近人類的方式進行理解、規劃、預測與行動。

**Q13：論文承認或暗示了哪些限制？**
A：儘管結果顯著，論文並未對所有 16 種機器人本體與所有可能的分佈外情境進行詳盡的失敗案例分析。預訓練依賴超過 37,000 小時的精選資料，意味著資料收集與品質控制成本高昂，可能限制小型研究團隊的重現性。此外，三個專門系統之間的協調增加了架構複雜度，可能使除錯、即時推論與資源受限機器人上的部署變得更具挑戰性。

**Q14：GigaBrain-0.7 可能出現哪些失敗案例？**
A：當世界模型遇到未見過的物體配置或動力學時，System 3 可能產生錯誤的子目標影像，進而導致 System 1 生成不適當的動作。在長程任務中，若 System 2 錯誤解讀任務進度或產生次優的階層式提示分解，整體執行也可能失敗。跨本體遷移時，若目標機器人的動作空間或動力學超出預訓練資料的涵蓋範圍，模型表現也可能顯著下降。

**Q15：這項工作暗示了哪些未來研究方向？**
A：未來可進一步強化經驗驅動改進機制，例如發展無需人類介入的自動 rollout 收集與自我修正能力。將預訓練規模擴展到超過 37,000 小時，並納入更多樣的本體、模態與真實世界環境，有望解鎖更多湧現能力。另一個方向是讓預測、規劃與動作系統在部署過程中線上共適應，從而實現開放世界中的持續終身學習。

## 實務應用指南

### 適用場景

1. **智慧家庭長程任務執行**  
   GigaBrain-0.7 適用於需要多步驟規劃與語言條件化指令遵循的家庭場景，例如「把餐桌收拾乾淨並將碗盤放入洗碗機」。透過 System 2 的階層式提示與 System 3 的子目標影像預測，模型能將長程指令分解為可執行子任務，並由 System 1 輸出連續動作區塊。

2. **工業製造與組裝線彈性自動化**  
   在 Maker H01 或 AgileX PiPER 等平台上，可用於零樣本或少量後訓練的精密操作，如零件抓取、插銷、鎖螺絲。具本體感知動作專家能適應不同自由度的機械手臂，並透過跨本體泛化降低產線換線成本。

3. **倉儲物流與移動操作**  
   結合移動底盤與操作手臂的異質本體，執行「從貨架取下指定箱子並搬運至包裝區」等任務。時間上下文建模與世界模型可協助機器人在動態環境中追蹤任務進度並預測未來狀態。

4. **服務型機器人多輪互動**  
   適用於需要理解自然語言、視覺場景並持續修正行為的場景，例如接待機器人根據使用者口語指令調整遞送物品的位置與順序，並利用 rollout 與修正回饋進行經驗驅動改善。

5. **多機器人協作與資料共享**  
   當企業擁有多種機器人形態與資料來源時，可利用 GigaBrain-0.7 的單階段多本體預訓練框架，將異質具身資料整合為統一策略，避免每種機器人各自訓練策略網路。

### 實作前置條件

**資料條件**
- 至少需要數百到數千小時的具身軌跡資料，若要發揮規模效應則建議朝向數千小時以上累積。
- 資料需涵蓋多種機器人形態、動作空間與執行條件，並透過統一處理流程轉換為 LeRobot v3.0 格式。
- 每筆軌跡應包含視覺觀測、語言指令、本體感覺狀態、動作序列，並建議輔以 LLM 協助的指令重寫與子任務標註。

**運算條件**
- 需要具備多張高效能 GPU 的叢集，以支撐預訓練視覺-語言模型骨幹、連續動作專家與世界模型的聯合訓練。
- 需有足夠儲存空間存放約 2.7 億組視覺-語言樣本與對應的異質具身資料。
- 推論端需支援流匹配動作生成與多系統間的結構化語義介面通訊。

**技術與人才條件**
- 熟悉視覺-語言模型微調、擴散模型或流匹配、以及機器人控制介面（如 ROS 2）。
- 具備資料品質控管與跨本體狀態-動作正規化經驗。
- 建議有機器人安全工程背景，能設計即時停止機制與人機協作安全協定。

---

### 實作步驟建議

1. **資料盤點與標準化**  
   收集來自不同機器人平台的軌跡資料，統一轉換為 LeRobot v3.0 格式，執行跨本體狀態-動作正規化，並利用 LLM 進行語言指令重寫與子任務標註。接著進行多階段品質控管，剔除異常軌跡與低品質樣本。

2. **建立三系統架構**  
   部署 System 1（動作與控制）負責基於流匹配生成連續動作區塊；System 2（理解與規劃）負責時間上下文建模與階層式提示分解；System 3（預測與評估）負責訓練世界模型以產生子目標影像與狀態價值估計。

3. **單階段對齊預訓練**  
   在單一訓練階段中聯合優化預訓練視覺-語言模型骨幹、連續動作專家與多模態理解目標。採用 Soft Knowledge Insulation 控制動作梯度進入 VLM 骨幹的程度，以保留通用視覺-語言能力並適應具身控制。

4. **後訓練與任務適應**  
   針對目標任務進行下游適應，利用特定場景資料微調動作專家與世界模型。可透過 System 3 的未來狀態預測與價值評估訊號，強化長程任務與開箱即用的真實機器人執行表現。

5. **真實環境部署與持續改善**  
   將模型部署至目標機器人平台，設計 rollout 收集機制與人類修正回饋流程。定期將新收集的軌跡資料回流至訓練管線，實現經驗驅動的策略改善。

### 潛在風險與注意事項

- **異質資料干擾而非遷移**  
  不同機器人本體與動作空間的資料若未妥善對齊，可能導致負遷移。應透過跨本體正規化、具本體感知動作專家與 Soft KI 等機制降低干擾。

- **優化碎片化**  
  若採用多階段訓練，視覺-語言理解與動作生成目標可能不一致。建議採用論文提出的單階段對齊訓練，避免 VLM 與動作專家各自為政。

- **長程任務累積誤差**  
  反應式觀測到動作預測容易在長程任務中累積錯誤。應善用 System 3 的子目標影像與狀態價值作為中間檢查點，並搭配階層式提示進行任務分解。

- **安全與即時性風險**  
  流匹配生成與多系統通訊可能增加推論延遲。部署時應保留獨立的安全監控層與緊急停止機制，避免模型錯誤動作造成設備或人員傷害。

- **過度依賴預訓練規模**  
  雖然資料規模提升通常降低驗證損失，但並非所有任務都會線性改善。應針對目標任務進行系統性的後訓練與分布外評估，確認泛化能力。

### 與其他技術的整合建議

- **機器人中介軟體**  
  可透過 ROS 2 或機器人專用 SDK 將 GigaBrain-0.7 的動作輸出轉換為各平台可執行的控制指令，並將感測資料回傳至 System 2 與 System 3。

- **模擬環境與數位孿生**  
  在 Isaac Sim、MuJoCo 或自建的數位孿生環境中進行大規模 rollout 與策略驗證，再將表現良好的策略遷移至真實機器人，降低實機測試成本。

- **大型語言模型代理系統**  
  將 GigaBrain-0.7 作為 LLM 代理的低階執行層，由 LLM 負責高階任務規劃與對話管理，GigaBrain-0.7 負責視覺理解、子目標預測與連續動作生成。

- **資料管理平台**  
  整合 MLOps 與資料標註管線，持續收集、清洗並標註新的具身軌跡資料，支援單階段預訓練的資料規模擴展需求。

- **邊緣運算與模型壓縮**  
  針對資源受限的機器人平台，可結合模型量化、知識蒸餾或動作專家輕量化技術，在保留三系統架構的前提下降低部署門檻。

**產品經理**
