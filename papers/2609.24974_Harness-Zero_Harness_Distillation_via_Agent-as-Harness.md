## ⚡ TL;DR

現有 harness 的效能提升受限於部署時的固定 harness，難以泛化到不同領域與模型。
Harness-Zero 以輔助智慧體把最佳化 harness 的引導轉為目標動作空間的訓練示範。
成功率從 23.3% 提升至 44.3%，超越仍掛載 harness 的 41.7%，並恢復 82.3% 誘導行為。

## 摘要翻譯

Agent harness 為中介模型與環境互動的外部系統，能顯著提升智慧體表現，但其增益仍與部署時的 harness 綁定。由於最佳 harness 會隨領域、實例與模型而異，通用智慧體只能退而求其次採用次佳的共享 harness，或在日益增多的 specialized harness 之間切換。因此，我們研究 agent harness distillation：以針對領域或實例最佳化的 harness（optimized harness）作為訓練階段的引導，將其誘導出的行為轉移至模型權重，使其增益能在單一固定的 target harness（h）下保留下來。挑戰在於兩個 harness 的動作空間與可用資訊不同，因此來自 optimized harness 的引導無法直接作為 target harness 的監督訊號。我們提出 Harness-Zero，透過 agent-as-harness 實現 harness distillation。在 optimized harness 的引導下，harnessing agent 會在 target harness 依學生回應執行動作前，先修正學生回應，將 harness 引導轉化為訓練示範。對產生的軌跡進行微調，可將 harness-induced behaviors 內化至模型中，使 specialized harness 能在部署時移除。我們橫跨知識工作、工具使用與科學領域的實驗顯示：(1) 對於使用相同 evolved harness 的前沿大型語言模型（frontier LLMs），agent-as-harness 優於 code-as-harness。(2) 在部署時移除 specialized harness 的情況下，Harness-Zero 將基礎模型（base model）的宏平均任務成功率從 23.3% 提升至 44.3%，甚至超過該 harness 仍搭配使用時所能達到的 41.7%。(3) Harness-Zero 能恢復基礎模型（base model）中原本不存在的 harness-induced behaviors，在三個領域的 28 種模式中，平均恢復率達 82.3%。

### 核心貢獻（3～5點）
- 提出 agent harness distillation 框架，將 optimized harness 於訓練階段誘導出的行為轉移至模型權重，使部署時僅需單一固定的 target harness（h）即可保留 specialized harness 的增益。
- 設計 Harness-Zero 方法，透過 agent-as-harness 機制讓 harnessing agent 在 target harness 的動作空間中審查並修正學生回應，把 harness 引導轉化為可微調的訓練示範。
- 在知識工作、工具使用與科學領域的實驗顯示，對於使用相同 evolved harness 的前沿大型語言模型（frontier LLMs），agent-as-harness 優於 code-as-harness。
- 移除 specialized harness 後，base model 的宏平均任務成功率從 23.3% 提升至 44.3%，甚至超過保留 harness 時的 41.7%，顯示 harness 能力已成功內化至模型權重。
- Harness-Zero 能有效恢復 base model 中缺失的 harness-induced behaviors，在三個領域共 28 種行為模式中平均恢復率達 82.3%。

### 適合對象
從事大型語言模型智慧體、工具使用系統、模型微調與知識蒸餾研究的學者與工程師，特別是關注如何將領域專用 harness 能力內化至模型權重、以簡化部署架構的 AI 應用開發者。

## 深度分析

#### 方法論解析

##### 問題設定與核心挑戰

這篇論文將 **agent harness（外部中介系統）** 視為影響 LLM agent（大型語言模型智慧體）能力的關鍵變因：它組織工具使用、管理上下文與狀態、控制模型與環境的互動。近年來 **harness optimization（harness 最佳化）** 與 **Meta-Harness** 等方法能自動產生針對特定領域、實例或模型的 **optimized harness（最佳化 harness）**，但這些進步本質上是「外部鷹架」的進步，其效益在部署時仍綁定於該 harness。由於最佳 harness 會隨領域、實例與模型而變，通用 agent 面臨兩難：使用單一共享 harness 會犧牲專屬增益，維護大量 specialized harnesses（專用 harness）則需要路由與持續的推論成本。

**Harness-Zero** 提出的解法是 **agent harness distillation（agent harness 蒸餾）**：在訓練階段以最佳化 harness 作為引導，將它誘導出的行為轉移到模型權重中，使部署時只需使用單一固定的 **target harness（h）** 即可保留原本需要 specialized harness 才能達到的能力。

核心困難在於 **source harness（來源 harness，即 h\*）** 與 target harness（h）可能在 **action space（動作空間）** 與可用資訊上都不相同。直接模仿在 h\* 下收集的 **trajectories（軌跡）** 不可行，因為這些動作在 h 中可能無法執行，或 h 根本沒有 h\* 所依賴的中介規則、記憶與子智慧體。因此需要一種機制，把 h\* 的「引導」重新表達成 h 的動作空間中可執行的示範。

##### Agent-as-Harness 的運作機制

論文的關鍵創新是 **agent-as-harness**：在學生智慧體的 **response boundary（回應邊界）** 外包裹一個 **harnessing agent（輔助審查智慧體）**。具體角色如下：

- **target harness（h）**：學生部署時使用的固定 harness，例如實驗中採用的 minimal mini-SWE-agent，僅提供一個 Bash execute tool。
- **evolved / optimized harness（h\*）**：透過 Meta-Harness 等方法針對任務最佳化的 harness，作為訓練引導。
- **private reference harness（K）**：將 h\* 的規則改寫給 harnessing agent 使用的私有參考 harness。例如 h\* 中一條會直接阻擋 **risky actions（高風險動作）** 的 **middleware rule（中介軟體規則）**，在 K 中會變成審查階段的 **review-time warning（審查階段警告）**。

資料收集流程為：

1. 學生模型根據目前 **student-visible trajectory（學生可見軌跡）** 產生 **proposed response（提案回應）**。
2. harnessing agent 依據 K 審查該提案，但**不能**查看學生 sandbox 或隱藏解答；其內部討論也不會進入學生軌跡。
3. 若提案合理（**sound proposals**），直接通過；否則 harnessing agent 給出最小的 **coherent correction（連貫修正）**，並以學生動作空間中的 **complete response（完整回應）** 形式呈現。
4. 被接受的回應透過 target harness（h）執行，產生的 **observation（觀察）** 再附加到學生軌跡。
5. 最後對這些經過審查的 rollout（展開軌跡）進行 **supervised fine-tuning（SFT，監督式微調）**，將 harness 誘導的行為內化到模型權重。

這個設計的精髓在於：harnessing agent 扮演的是「跨 harness 的動態翻譯器」，把 h\* 的規則與資訊優勢逐回合轉譯成 h 能執行的動作，而不是要求學生直接複製 h\* 的原始軌跡。

##### Private Reference Harness K 的角色

K 是讓整個蒸餾可行的關鍵中介。h\* 可能包含複雜的程式碼邏輯、記憶體管理、子 agent 協作等，但這些無法直接移植到 h。K 的作用是把 h\* 的「策略意圖」改寫成 harnessing agent 可以理解的審查準則，並且只在訓練時使用。由於 K 的討論過程對學生不可見，學生軌跡保持乾淨：它只包含在 h 下可執行的動作與環境回饋。這確保了 SFT 的資料分佈與部署時一致，避免學生學到無法在 target harness 執行的動作。

##### 訓練流程與與傳統模仿學習的差異

傳統 **distillation（蒸餾）** 通常假設教師與學生共享相同的輸入輸出空間，可以直接模仿教師輸出。Harness-Zero 面對的是「教師 harness」與「學生 harness」空間不一致的設定，因此不能直接使用 h\* 下產生的 trajectories。Agent-as-harness 透過在回應邊界進行「即時修正」，把 h\* 的引導轉換成 h 空間中的有效示範，這是一種跨 action space 的模仿學習。最終模型學到的不是 harness 的程式碼，而是 harness 想要強化的行為模式。

#### 實驗數據解讀

##### 評估領域與設定

論文在三大領域驗證：

1. **SpreadsheetBench Verified**：以試算表為主的知識工作。
2. **AppWorld**：多應用程式工具使用。
3. **USPTO Retrosynthesis**：科學推理（逆合成）。

Target harness（h）統一採用極簡的 mini-SWE-agent，僅提供一個 Bash 執行工具。這種設定刻意放大 h 與 h\* 之間的差距，以檢驗蒸餾是否真的能彌補 harness 能力的落差。

##### Agent-as-Harness 優於 Code-as-Harness

在未經訓練的 frontier LLMs（前沿大型語言模型）上，作者比較了以 agent 實現 harness 功能與傳統 **code-as-harness（以程式碼規則實現 harness）**。結果顯示：

- **agent-as-harness**：平均 81.1%
- **code-as-harness**：平均 78.1%

雖然差距約 3 個百分點，但在六個 benchmark–model 設定中穩定領先。這說明對於強大模型，彈性、可根據上下文判斷的 agent 審查，比硬編碼規則更能有效落實 harness 意圖。這也呼應了論文主張：當模型能力夠強時，「agent 作為 harness」可能比「程式碼作為 harness」更自然且更有效。

##### 蒸餾成效：移除 h\* 後仍保留甚至超越原有效益

在 Qwen3.5-9B 上的主要結果極具說服力：

| 設定 | Macro-average task success（宏平均任務成功率） |
|---|---|
| Base model（基礎模型）+ target harness（h） | 23.3% |
| Base model + optimized harness（h\*） | 41.7% |
| Harness-Zero（ distilled model）+ target harness（h） | 44.3% |

關鍵解讀：

- **保留增益**：移除 h\* 後，Harness-Zero 仍能將表現從 23.3% 提升到 44.3%，證明 harness-induced behaviors（harness 誘導行為）確實被內化到模型權重。
- **超越原 harness**：44.3% 甚至高於 base model 搭配 h\* 時的 41.7%。這可能意味著，當行為被內化後，模型不再受 h\* 的額外上下文消耗、中介延遲或過度保守規則所限制，反而能更流暢地執行。
- **對小模型的價值**：基礎模型在 h 下僅 23.3%，顯示小模型極度依賴外部 harness；蒸餾後的進步幅度（+21%）非常顯著。

##### 消融實驗：Harness-Guided Review 的獨特價值

消融結果顯示，harness-guided review 遠優於其他監督來源：

- Harness-guided review：約 30%
- 其他替代來源（更強模型的直接軌跡、h\* 下產生的軌跡、沒有 K 的審查、僅給定答案的審查）：3–15%

這強調了幾點：

1. 單純用更強模型產生軌跡並不足以彌補 harness 差異，因為動作空間與資訊不對齊。
2. 直接在 h\* 下收集的軌跡對 h 來說是「不可執行」或「分佈不一致」的。
3. 沒有 K 的審查缺乏 harness 的最佳化知識；僅給答案則無法提供過程中的行為引導。
4. Harness 本身蘊含的「如何行動」資訊，比「正確答案」更有蒸餾價值。

##### 行為恢復分析

論文進一步分析 28 種 harness-induced behaviors，發現 distilled model 平均恢復了 82.3% 原本由 h\* 誘導、但 base model 不具備的行為模式。這表示 Harness-Zero 不只是提升最終成功率，也確實復現了中間行為，例如：

- 更適當的工具呼叫順序
- 驗證與自我檢查
- 對環境狀態的追蹤
- 針對領域的特定推理模式

高行為恢復率增強了結論的可信度：模型學到的是可解釋、可重複的行為，而不只是任務層面的捷徑。

#### 與現有研究的比較

##### 相對於 Code-as-Harness 與 Meta-Harness

過去 **harness engineering** 主要透過程式碼規則（code-as-harness）或自動化搜尋（Meta-Harness）來改進外部系統。這些方法的共同限制是：部署時必須繼續攜帶該 harness。Harness-Zero 的貢獻在於把這些外部改進「編譯」進模型權重，使部署時只需固定 target harness。此外，實驗顯示 agent-as-harness 在 frontier LLMs 上優於 code-as-harness，暗示未來 harness 設計可能從「寫更多規則」轉向「訓練一個會審查的輔助智慧體」。

##### 相對於 Co-evolution 與 Joint Optimization

近年有許多研究交替或聯合最佳化 harness 與模型權重（co-evolution of model and harness）。這些方法雖然能讓 harness 與模型互相強化，但最終增益往往仍與特定 harness 耦合。Le et al. [2026] 的對照研究甚至發現：改變評估 harness 對表現的影響大於訓練方法本身，且跨 harness 收集回饋並未改善對 minimal ReAct harness 的遷移。

Harness-Zero 與這些研究的關鍵區別在於：它明確把 harness 視為「訓練時的教師」，透過 agent-as-harness 把其引導轉譯為 target harness 空間中的示範，最終目標是「去 harness 化」的部署。這解決了 co-evolution 中增益與 harness 綁定的問題。

##### 相對於 Privileged Distillation

與 **EvoHarness-RL**（在 ALFWorld 上讓 agent 學會管理外部狀態）和 **OPHSD**（將特權工作流程輸出蒸餾到單一模型）相比，Harness-Zero 處理更廣泛的 harness 差異：不僅是狀態管理或草稿–驗證流程，還包括不同的 action space、工具集合、中介規則與記憶機制。Agent-as-harness 提供了一個通用框架，讓任何 optimized harness 都能成為 target harness 的訓練教師。

##### 限制與未解決問題

儘管成果顯著，論文仍存在一些限制：

1. **蒸餾對象單一**：主要蒸餾實驗僅在 Qwen3.5-9B 上進行，尚未廣泛驗證於其他規模或架構的模型。
2. **SFT 的局限性**：目前僅使用監督式微調，未結合 RL（強化學習）進一步對齊。若審查後的軌跡仍有偏差，SFT 可能無法完全修復。
3. **K 的設計成本**：K 需要將 h\* 的規則改寫為 harnessing agent 的審查準則，這個過程可能需要領域知識，論文未詳細說明其自動化程度。
4. **訓練階段推論成本**：harnessing agent 在資料收集時需要額外模型呼叫，雖然部署時會移除，但大規模資料生成仍可能昂貴。
5. **多 harness 路由問題**：論文聚焦於把單一 optimized harness 蒸餾進模型，但現實中可能需要整合多個 specialized harness 的優勢，這部分未深入探討。
6. **泛化到未見 harness 差異**：若未來 target harness 與訓練時的 h 差異過大，蒸餾效果可能下降。

#### 可重現性評估

##### 公開資源現況

根據目前提供的全文內容，論文並未明確提及原始碼、模型權重或資料生成腳本是否公開釋出。因此現階段可重現性評估如下：

- **資料集**：使用的三個 benchmark——SpreadsheetBench Verified、AppWorld、USPTO Retrosynthesis——皆為已公開或即將公開的學術資料集，理論上可取得。
- **基礎模型**：蒸餾實驗使用 Qwen3.5-9B，屬於開放權重模型，可下載。
- **Frontier 模型**：評估 agent-as-harness 時使用的 frontier LLMs 多為商業 API，需透過相應平台取得。
- **Target harness**：實驗採用 mini-SWE-agent，基於開源的 SWE-agent 簡化而來，但論文未說明是否公開其實作細節。
- **Optimized harness（h\*）**：來自 Meta-Harness 等自動最佳化方法，其產生的 harness 程式碼與配置未必公開。
- **Private reference harness（K）** 與 harnessing agent 的提示設計：這是方法核心，但目前未見釋出。

##### 重現所需關鍵元件

若要完整重現 Harness-Zero，至少需要：

1. h\* 的產生流程（Meta-Harness 或對應最佳化方法）。
2. 從 h\* 到 K 的改寫規則與提示範本。
3. harnessing agent 的模型選擇、提示設計與審查協議。
4. 資料收集與 SFT 的完整 pipeline，包括超參數。
5. 評估腳本與 mini-SWE-agent 的確切設定。

在這些元件公開之前，其他研究者只能復現概念層面，難以完全複製論文數據。

#### 未來研究方向

##### 1. 結合強化學習進一步內化行為

目前 Harness-Zero 僅使用 SFT。未來可探索將審查後的 rollout 作為偏好資料，使用 **DPO（Direct Preference Optimization）** 或 **PPO（Proximal Policy Optimization）** 進行強化學習，讓模型在 target harness 中透過環境回饋進一步優化，而不僅是模仿審查後的軌跡。

##### 2. 自動化 Private Reference Harness K 的生成

K 的設計是方法中的關鍵人工環節。未來可研究如何自動將 h\* 的程式碼規則轉譯為 harnessing agent 的審查準則，例如透過規則抽取、程式碼註解生成或另一個「meta-harnessing agent」來完成改寫。

##### 3. 多 Harness 的整合蒸餾

現實應用中可能需要針對不同領域維護多個 specialized harnesses。未來可研究如何從多個 h\* 同時蒸餾，或訓練一個能根據任務類型自動切換行為模式的單一模型，從而避免 harness 路由成本。

##### 4. 擴展到更廣泛的 Agent 領域

論文驗證了知識工作、工具使用與科學推理三個領域。未來可將 Harness-Zero 應用於網頁 agent、機器人控制、多模態 agent 等更複雜的環境，檢驗 agent-as-harness 在 action space 差異更大時的穩健性。

##### 5. 蒸餾規模律與模型大小效應

目前僅在 Qwen3.5-9B 上進行蒸餾。未來可系統性研究：不同規模的學生模型對 harness-induced behaviors 的吸收能力、所需資料量、以及蒸餾後與直接使用 h\* 的效益交叉點。

##### 6. 線上自我改進迴路

可將 Harness-Zero 與線上 harness 最佳化結合：蒸餾後的模型成為新的 base model，再為其搜尋更強的 h\*，形成「harness 最佳化 → 蒸餾 → 更強模型 → 更強 harness」的迭代迴路。

##### 7. 安全性與對齊議題

當 harness 的安全規則（如阻擋高風險動作）被蒸餾進模型後，需要確保這些行為在部署時穩定觸發，而不會因分佈偏移而失效。未來可研究如何驗證與監控蒸餾後的安全行為。

## 論文問答

**Q1：Harness-Zero 想解決的核心問題是什麼？什麼是 agent harness distillation？**

A：Harness-Zero 要解決的問題是：agent harness 雖然能顯著提升智慧體表現，但這些增益通常綁定在特定的外部 harness 上，無法隨著模型一起部署。由於最佳 harness 會隨領域、任務實例與基礎模型而變，通用型智慧體往往只能在共享 harness 與眾多專用 harness 之間取捨。agent harness distillation 就是在訓練時以最佳化 harness 作為引導，把其誘導出的行為轉移到模型權重中，使部署時只需單一固定的 target harness 就能保留原本需要專用 harness 才能達到的能力。

**Q2：為什麼不能直接在部署時使用最佳化 harness，或同時維護多個專用 harness？**

A：直接使用最佳化 harness 部署的困難在於，最佳 harness 會隨情境改變，很難找到一個適用所有情況的通用 harness。若為每個領域都維護專用 harness，則會產生高昂的系統複雜度與執行成本，包括路由、上下文、模型呼叫、工具呼叫與編排等開銷。更重要的是，這些做法都沒有把 harness 帶來的改進內化到模型本身，導致模型能力仍然依賴外部系統。

**Q3：現有的 code-as-harness 或共同演化方法為什麼無法解決這個問題？**

A：現有的 code-as-harness 或 harness 共同演化方法主要強化外部鷹架，而非模型權重本身。共同演化雖然交替更新 harness 與模型，但實證研究顯示，改變評估 harness 對表現的影響甚至大於訓練方法，且跨 harness 收集回饋訓練後仍無法轉移到簡約的 ReAct harness。這表示即使 harness 與模型一起進化，最終增益仍可能與特定 harness 綁定，無法在移除該 harness 後保留。

**Q4：agent-as-harness 是什麼？它如何橋接不同的 harness？**

A：agent-as-harness 是 Harness-Zero 的核心機制，它用一個 harnessing agent 在學生智慧體的回應邊界進行審查與修正。這個輔助智慧體讀取最佳化 harness 的引導，並把其建議重新表達為學生 target harness 動作空間中可執行的完整回應。透過這種方式，即使 source harness 與 target harness 的動作空間和可取得資訊不同，也能產生適合模仿學習的訓練軌跡。

**Q5：target harness（h）、optimized harness（h*）與 private reference harness（K）各自扮演什麼角色？**

A：target harness（h）是學生智慧體在部署時固定使用的最小化 harness，例如實驗中僅有一個 Bash execute tool 的 mini-SWE-agent。optimized harness（h*）是針對特定領域或實例透過 Meta-Harness 等方法演化出來的來源 harness，只在訓練時提供引導。private reference harness（K）則是 h* 為 harnessing agent 改寫的版本，用於在審查階段評估學生提案，例如把 h* 中封鎖高風險動作的中介軟體規則轉換為審查時的警告。

**Q6：Harness-Zero 有哪些關鍵設計選擇，讓蒸餾能夠成功？**

A：Harness-Zero 的關鍵設計包括在學生回應即將被執行前進行審查，確保所有進入軌跡的動作都符合 target harness 的動作空間。harnessing agent 對不合理提案只做最小且語意連貫的修正，避免過度干預學生原有的推理結構。此外，輔助智慧體的審查對話與內部推理不會出現在學生可見的軌跡中，從而避免學生直接依賴私有資訊，而是學習到可被內化的行為模式。

**Q7：實驗涵蓋哪些領域與基準測試？target harness 是如何設定的？**

A：實驗橫跨三個領域：試算表知識工作（SpreadsheetBench Verified）、多應用程式工具使用（AppWorld），以及科學推理（USPTO Retrosynthesis）。這些任務分別涉及試算表操作、跨應用自動化與化學逆合成規劃，能夠檢驗 harness distillation 在不同動作空間與知識需求下的效果。實驗中的 target harness h 採用固定且極簡的 mini-SWE-agent，僅提供單一 Bash execute tool，以凸顯模型本身學到的行為。

**Q8：Harness-Zero 的主要實驗結果有哪些？**

A：在移除 specialized harness 後，Harness-Zero 把 Qwen3.5-9B 的宏平均任務成功率從 23.3% 提升到 44.3%，甚至超過基礎模型在 h* 仍然掛載時的 41.7%。在前沿大型語言模型上，agent-as-harness 在六個 benchmark–model 設定中平均達到 81.1%，優於 code-as-harness 的 78.1%。行為分析也發現，蒸餾後的模型平均能恢復 82.3% 原本由 h* 誘導但基礎模型不具備的行為模式。

**Q9：消融實驗揭示了什麼關於監督來源的重要性？**

A：消融實驗比較了多種監督來源，結果顯示以最佳化 harness 引導的審查所產生的訓練資料效果最佳，蒸餾後表現達到約 30%。相較之下，直接使用更強模型的軌跡、在 h* 下產生的軌跡、沒有 K 的審查，或僅給定任務答案的審查，只能帶來 3–15% 的成功率。這說明並非任何高品質軌跡都有效，關鍵在於把 harness 引導轉譯成 target harness 動作空間中可執行且連貫的示範。

**Q10：在實務產品中，Harness-Zero 能帶來什麼價值？**

A：Harness-Zero 讓開發者能夠在訓練時利用針對各領域最佳化的 harness，卻在部署時只維護一個簡單、通用的 target harness。這大幅降低了生產環境的系統複雜度，避免了多 harness 路由與編排帶來的延遲與成本。同時，模型能力不再受限於部署時能掛載哪些外部系統，讓通用型智慧體更容易跨領域部署。

**Q11：部署與維護上需要考慮哪些因素？**

A：Harness-Zero 只需要保留學生 target harness，訓練時的 h*、K 與 harnessing agent 都可以移除。這意味著更新模型權重即可傳遞新的 harness 改進，而不需要同步升級或協調多個外部 harness。不過，訓練階段仍需要產生審查軌跡的運算成本，且 private reference harness K 的品質會直接影響蒸餾效果，因此需要持續維護 K 與資料產生流程。

**Q12：這項研究可能對 agent harness 設計領域帶來什麼影響？**

A：這項研究可能改變 agent harness 工程的設計思維：harness 不再只是部署時必要的外部依賴，也可以成為訓練階段的「教練」來提升模型本身。當 harness 的最佳化成果能被蒸餾進模型權重，未來的 harness 設計可能更偏向產生可學習的示範行為，而非僅追求推理時的即時控制。長期來看，這有助於縮小專用智慧體與通用智慧體之間的差距，並促進模型與外部工具之間更明確的分工。

**Q13：Harness-Zero 有哪些主要限制？**

A：Harness-Zero 目前主要透過監督式微調來內化行為，對於需要大量試錯或長期回饋的複雜策略，可能不如強化學習深入。此外，並非所有 h* 誘導的行為都能在目標動作空間中表達，例如依賴特定中介軟體狀態或記憶機制的行為可能難以完整轉移。最後，整個流程依賴 private reference harness K 與 harnessing agent 的品質，若 K 設計不當，審查後的軌跡可能引入錯誤或過度保守的行為。

**Q14：在哪些情況下，harness distillation 可能會失敗？**

A：蒸餾可能失敗的情況包括：h* 的行為高度依賴其專屬工具或資訊，而 target harness 無法提供對應表達方式；或者學生模型容量不足，無法學會 h* 誘導的複雜行為模式。當任務實例與訓練分佈差異過大時，模型也可能無法正確泛化，因為它不再能呼叫 h* 的即時引導。此外，若 harnessing agent 的修正過於頻繁或過度偏離學生原始意圖，學生可能學到不一致的策略。

**Q15：未來有哪些值得探索的研究方向？**

A：未來方向包括結合強化學習與 harness distillation，以進一步內化需要長期回饋的行為；也可以探索從多個領域專用 harness 同時蒸餾，並研究如何自動產生或更新 private reference harness K。另一個有潛力的方向是將 agent-as-harness 應用於線上 harness 最佳化，讓 harnessing agent 隨著模型進步動態調整審查策略。最後，發展理論框架來預測哪些 harness-induced behaviors 可被轉移、哪些會遺失，將有助於設計更可蒸餾的 harness。

## 實務應用指南

### 適用場景

1. **跨部門企業 Agent 統一部署**  
   財務試算、客服多應用操作、研發科學推理等不同部門各自有最佳化 harness，但產品上希望只維護一套固定 target harness。Harness-Zero 可把各領域 harness 誘導的行為蒸餾進單一模型，部署時無需路由多套 harness。

2. **邊緣或低資源環境的 Agent**  
   雲端上可使用複雜的 evolved harness 收集高品質軌跡，再透過 agent-as-harness 把行為轉移到輕量模型（如 Qwen3.5-9B），部署時僅保留最小化 target harness，降低延遲與運算成本。

3. **多租戶 SaaS Agent 平台**  
   為不同客戶或任務演化專屬 harness 後，若直接維護會產生大量路由與 orchestration 成本。Harness-Zero 可將這些 harness 的專長內化為模型權重，對外提供統一 API，同時保留客製化能力。

4. **合規優先的 Coding Agent**  
   把審查高風險動作、強制測試流程、限制檔案操作等 harness 規則，透過 private reference harness K 轉化為訓練示範，讓模型在無中介程式碼的情況下仍遵守安全與品質規範。

5. **科學研究輔助 Agent**  
   在化學合成規劃、文獻回顧或實驗設計等領域，把研究型 harness 組織的假設生成與證據收集流程蒸餾進模型，使精簡 target harness 也能執行複雜研究行為。

### 實作前置條件

**資料**
- 目標任務實例與評估標準（如 SpreadsheetBench Verified、AppWorld、USPTO Retrosynthesis 等）。
- target harness \(h\) 的完整規格：動作空間、工具定義、上下文管理與執行環境。
- optimized / evolved harness \(h^\star\) 的規則或程式碼，作為訓練引導來源。
- 為 harnessing agent 改寫的 private reference harness \(K\)，需把 \(h^\star\) 的中介規則轉為審查階段指令。
- 學生智慧體可執行的觀察回饋與成功標籤。

**運算**
- 訓練資源：足以對目標模型（如 9B 參數模型）進行 SFT 的 GPU（建議 A100 / H100 等級）。
- 推理資源：用於 frontier LLM 擔任 harnessing agent 的 API 或叢集，以審查每個 proposed response。
- 沙箱環境：能安全執行 Bash、檔案系統與多應用工具互動的隔離環境。

**技能**
- LLM 微調與資料處理經驗。
- Agent harness 設計與 prompt engineering。
- 環境沙箱化與動作空間定義。
- 領域知識：用於設計 \(K\) 的審查規則與行為檢查清單。
- 評估指標設計：macro-average task success 與 harness-induced behavior recovery。

---

### 實作步驟建議

1. **定義 target harness \(h\)**  
   選擇固定、最小化的動作空間與工具集合（例如 mini-SWE-agent 配單一 Bash execute tool）。這是部署時唯一保留的 harness。

2. **取得 optimized harness \(h^\star\)**  
   使用 Meta-Harness、人工設計或領域專家規則，針對目標任務產生專用 harness。此 harness 只在訓練時使用。

3. **建構 private reference harness \(K\)**  
   將 \(h^\star\) 的中介規則改寫為 harnessing agent 的審查指令。例如把「封鎖高風險動作」改為「審查階段警告並要求修正」。確保 \(K\) 不洩漏隱藏答案或學生沙箱狀態。

4. **部署 harnessing agent 於 response boundary**  
   在學生產生 proposed response 後、target harness 執行前，由 harnessing agent 依 \(K\) 審查。合理提案直接通過；不合理者給出 smallest coherent correction，並以學生動作空間的 complete response 表達。

5. **收集 reviewed rollouts**  
   執行 accepted response 於 \(h\)，將 observation 加入學生可見 trajectory。確保涵蓋多領域、多實例與成功/失敗後的修正軌跡。

6. **對學生可見軌跡進行 SFT**  
   只使用最終被接受的回應與學生可見上下文進行監督式微調，讓模型內化 harness-induced behaviors。

7. **在僅有 \(h\) 的環境下評估**  
   移除 \(h^\star\)、\(K\) 與 harnessing agent，測量 macro-average task success 與各項行為模式的 recovery 比例。

8. **迭代補強**  
   針對未恢復的行為模式，調整 \(K\) 的審查粒度、補充資料或改用更強的 harnessing model，再重新蒸餾。

9. **產品化部署**  
   包裝 target harness、加入監控與基本安全檢查，並建立定期以新最佳化 harness 重新蒸餾的更新流程。

### 潛在風險與注意事項

- **動作空間不匹配**  
  source 與 target harness 的動作與資訊不同，不能直接模仿。務必透過 agent-as-harness 逐回應轉譯，避免把無法執行的動作餵給學生。

- **\(K\) 過度干預**  
  若 harnessing agent 修改幅度過大，學生會失去自主決策的學習信號。應堅持 smallest coherent correction 原則。

- **資訊洩漏與作弊**  
  \(K\) 不能存取 hidden task solutions 或學生沙箱內部狀態，否則軌跡會變成「開卷答案」，導致部署時失效。

- **訓練與部署分佈偏移**  
  訓練時每步都有 \(K\) 把關，部署時沒有。需特別評估模型在無審查下的自主糾錯能力，並保留 target harness 的基本容錯機制。

- **行為恢復不全**  
  部分 harness-induced behaviors 需要大量示範或更強基礎模型才能內化。建議建立 20–30 項行為檢查清單，逐項追蹤 recovery 比例。

- **安全風險內化**  
  高風險動作若被模型學會且無 harness 攔截，可能在部署時造成危害。target harness 仍應保留沙箱、權限限制與動作審計。

- **資料收集成本**  
  frontier LLM 擔任 harnessing agent 的審查成本高昂。可先用強模型產生固定高品質資料集，再對小模型進行一次性或週期性蒸餾。

---

### 與其他技術的整合建議

- **Meta-Harness / Auto-Harness**  
  用於自動產生 \(h^\star\)，再將其輸出餵入 Harness-Zero 進行蒸餾，形成「搜尋 harness → 蒸餾進模型」的閉環。

- **RLHF / DPO**  
  在 SFT 後，可進一步用強化學習或偏好最佳化對齊 target harness 下的長期行為與任務獎勵。

- **RAG 與 Memory 系統**  
  對於 harness 提供的 skills、經驗與可重用知識，可轉為外部檢索知識庫，補充模型未完全內化的部分。

- **Multi-agent Orchestration**  
  harnessing agent 本身就是一種臨時輔助智慧體。訓練完成後可移除，僅在困難實例保留動態路由作為備援。

- **Test-time Compute**  
  對於極複雜任務，可保留少數 specialized harness 作為 test-time 增強，而非全部移除，以平衡成本與效能。

- **Monitoring 與 Guardrails**  
  部署時整合輸出過濾、動作審計、人機協同審批，彌補無 \(K\) 審查後可能產生的風險。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先理解「agent harness」是什麼——它就像智慧體的外部作業系統，負責工具、記憶與流程控制。接著把 Harness-Zero 想像成「讓一位老師 harness 在訓練時幫學生改答案，最後學生畢業後就能獨立作業」。重點看論文的動機、實驗結果與主要圖表，技術細節可暫時略過。

**AI 工程師**  
請聚焦於 \(K\) 的設計、response boundary 的實作方式，以及 SFT 資料的過濾與評估流程。建議從 mini-SWE-agent 設定開始重現，嘗試把現有 harness 的中介規則改寫成 harnessing agent 的審查 prompt，並觀察哪些行為能被成功蒸餾。

**研究人員**  
本論文把 harness distillation 定位為一個新問題，值得與 model–harness co-evolution、privileged distillation 與 test-time strong-to-weak transfer 等方向對照。可進一步探討結合 RL 的蒸餾、移除 harness 後的泛化理論，以及 agent-as-harness 在不同動作空間距離下的轉譯極限。

**產品經理**  
核心商業價值在於降低多套 harness 的維護與路由成本，同時讓單一模型在多領域維持高效能。評估時請同時考慮 frontier LLM 審查資料的收集成本、部署安全風險，以及從「最佳化 harness」到「無 harness 部署」的產品路徑與里程碑規劃。
