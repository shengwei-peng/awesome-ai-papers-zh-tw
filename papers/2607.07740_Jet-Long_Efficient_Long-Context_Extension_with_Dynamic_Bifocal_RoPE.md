## 摘要翻譯

現代大型語言模型（Large Language Models, LLMs）日益廣泛地部署於長上下文應用（long-context applications），例如檢索增強生成（Retrieval-Augmented Generation, RAG）、儲存庫層級程式編寫（repository-level coding），以及智慧體工作流程（agentic workflows）；其累積的推理與工具追蹤經常使輸入長度超出預訓練視窗（pretraining window）達一個數量級，令零樣本上下文延伸（zero-shot context extension）成為開放權重檢查點（open-weight checkpoints）的主流部署途徑。大多數現有的零樣本方法（zero-shot methods）預先固定單一重新縮放因子（rescaling factor），因此激進的因子會犧牲短上下文保真度（short-context fidelity），而保守的因子則在長上下文時失效。我們提出 Jet-Long，一種免微調（tuning-free）的零樣本方法，結合局部 RoPE 忠實視窗（local RoPE-faithful window）與長程視窗（long-range window），其中長程視窗的重新縮放因子會根據當前序列長度動態調整，在短輸入時精確還原基礎模型（base model），同時在長輸入時平滑外插（extrapolate）。包含-排除注意力合併（inclusion-exclusion attention merge）與即時 RoPE 校正旋轉（on-the-fly RoPE correction rotation）讓雙焦結構（bifocal construction）在推論（inference）時幾乎無額外成本；將其融合為單一 CuTe 核心（CuTe kernel）後，長上下文預填充（long-context prefill）在 H100 上可達 FlashAttention-2（FA2）吞吐量的 1.39 倍（逼近僅限 Hopper 的 FlashAttention-4（FA4）），且單批次生成（single-batch generation）在任何長度下僅帶來不超過 4% 的額外開銷。在 Qwen3-1.7B/4B/8B 上，上下文長度達 128K 時，Jet-Long 於 RULER 上相較最強基線分別領先 +4.79/+2.18/+2.03 個百分點（依序對應 1.7B/4B/8B），於 HELMET-RAG（HELMET 認定為最能有效預測下游長上下文效能的基準測試（benchmark））達到最佳整體準確率（accuracy），並取得最低的 PG-19 困惑度（PG-19 perplexity）。Jet-Long 亦可泛化至混合注意力架構（hybrid attention architectures）（如 Jet-Nemotron），無需重新訓練即可進一步提升長上下文表現，且具備超參數穩健性（hyperparameter-resilient），便於部署（deployment）。

### 核心貢獻（3～5點）
- 提出動態雙焦 RoPE（Dynamic Bifocal RoPE）機制，結合局部 RoPE 忠實視窗與依序列長度動態調整的長程視窗，在短輸入時精確還原基礎模型，並在長輸入時平滑外插。
- 設計包含-排除注意力合併與即時 RoPE 校正旋轉，使雙焦結構在推論時幾乎無額外成本。
- 將整體機制融合為單一 CuTe 核心，長上下文預填充在 H100 上達到 FA2 吞吐量的 1.39 倍，單批次生成開銷不超過 4%。
- 在 Qwen3-1.7B/4B/8B 上驗證達 128K 上下文，於 RULER、HELMET-RAG 與 PG-19 困惑度均領先最強基線。
- 可泛化至混合注意力架構（如 Jet-Nemotron），無需重新訓練，且具備超參數穩健性，便於實際部署。

### 適合對象
從事長上下文大型語言模型研究與部署的工程師與研究人員，特別是關注零樣本上下文延伸、開放權重模型推論加速、檢索增強生成、儲存庫層級程式編寫，以及智慧體工作流程等應用的讀者。

## 深度分析

#### 方法論解析

Jet-Long 的核心貢獻在於提出一種**動態雙焦 RoPE（Dynamic Bifocal RoPE）**機制，用於解決現有零樣本上下文延伸（zero-shot context extension）方法中「短上下文保真度（short-context fidelity）」與「長上下文外插能力（extrapolation）」之間的根本權衡。

##### 1. 問題設定：固定重新縮放因子（rescaling factor）的兩難

現有方法如 Position Interpolation（PI）、NTK-aware scaled RoPE、YaRN、Self-Extend 與 DCA 等，大多在推論前固定一個單一的重新縮放因子或分組大小（grouping size）。這導致兩種極端：

- **過度激進的因子**：雖然能將長序列壓回預訓練視窗（training window）內，但會嚴重扭曲短距離相對位置，損害短上下文表現。
- **過於保守的因子**：短上下文保真度較好，但在極長輸入下仍會出現分佈外 RoPE 旋轉（out-of-distribution RoPE rotations），導致長程注意力失準。

Jet-Long 的解法是讓重新縮放因子成為「當前序列長度（sequence length）」的函數，而非固定常數。

##### 2. 雙焦視窗（bifocal window）設計

Jet-Long 將注意力分為兩個互補視窗：

- **局部 RoPE 忠實視窗（local RoPE-faithful window）**：在基礎模型（base model）的原生上下文（native context）範圍內，完全保留原始位置編碼，確保短輸入時與基礎模型行為完全一致。
- **長程視窗（long-range window）／遠端視窗（remote window）**：超出原生範圍後，採用動態分組策略，將位置索引進行壓縮或別名（aliasing），使得每一個遠端旋轉角度都落在預訓練分佈內（in-distribution）。

關鍵在於：分組大小並非固定，而是隨當前序列長度動態調整——在原生素長內為恆等映射（identity），超出後僅放大到「剛好足夠」讓所有遠端旋轉保持分佈內。這種動態調度策略（dynamic schedule）讓 Jet-Long 在短輸入時完全復現基礎模型，在長輸入時乾淨外插。

##### 3. 包含-排除注意力合併（inclusion-exclusion attention merge）

為了將局部視窗與遠端視窗的注意力結果正確合併，Jet-Long 採用包含-排除原理（inclusion-exclusion principle），將計算拆成三個 FlashAttention 路徑：

1. 僅在局部視窗內計算注意力。
2. 僅在遠端視窗內計算注意力。
3. 計算兩個視窗重疊區域的注意力，並從總和中扣除，避免重複計算。

這種注意力合併（attention merge）確保每個 token 對的貢獻恰好被計算一次，同時維持 softmax 的歸一化正確性。

##### 4. 即時 RoPE 校正旋轉（on-the-fly RoPE correction rotation）

在生成階段（generation），KV 快取（KV cache）若因重新縮放而需要重新編碼，會帶來巨大開銷。Jet-Long 透過即時 RoPE 校正旋轉（on-the-fly RoPE correction rotation）在查詢端動態修正旋轉角度，而**不修改 KV 快取**。這意味著：

- 生成時無需重新計算或重新儲存鍵值（keys/values）。
- 記憶體佔用與標準推論幾乎相同。
- 單批次生成（single-batch generation）在所有長度下的額外開銷 ≤4%。

##### 5. 單一 CuTe 核心（CuTe kernel）融合

為了實際部署效率，Jet-Long 將上述三個 FlashAttention 路徑與即時校正旋轉融合為單一 CuTe 核心（CuTe kernel）。在 H100 上：

- 長上下文預填充（prefill）吞吐量達到 FlashAttention-2（FA2）的 **1.28–1.39 倍**。
- 效能已接近僅支援 Hopper 架構的 FlashAttention-4（FA4）。

這使得 Jet-Long 不僅在準確率上領先，也具備可實際部署的系統效率。

##### 6. 超參數設計

Jet-Long 僅需一個超參數：局部視窗大小 \(w\)。論文指出此參數對選擇相當穩健（hyperparameter-resilient），大幅降低部署時的調校負擔。

#### 實驗數據解讀

論文在 Qwen3-1.7B/4B/8B 上進行最高達 128K 的評估，涵蓋三類互補指標：合成召回（RULER）、真實 RAG 效能（HELMET-RAG）與長文語言建模困惑度（PG-19 perplexity）。

##### 1. RULER：合成長上下文召回

RULER 包含 13 項合成任務，測試模型在極長序列中定位與整合分散資訊的能力。Jet-Long 相較最強基線的領先幅度為：

- Qwen3-1.7B：**+4.79 百分點（pp）**
- Qwen3-4B：**+2.18 百分點**
- Qwen3-8B：**+2.03 百分點**

值得注意的是，較小模型獲得的相對提升更大。這可能意味著小型模型對位置分佈外（position out-of-distribution）更敏感，而 Jet-Long 的動態別名策略能有效緩解此問題。

##### 2. HELMET-RAG：下游 RAG 效能預測指標

HELMET 研究指出 HELMET-RAG 是預測下游長上下文表現最有效的綜合基準。Jet-Long 在此取得最佳整體準確率（accuracy），顯示其不僅在合成任務有效，也能遷移到檢索增強生成（retrieval-augmented generation, RAG）等真實場景。

##### 3. PG-19 困惑度（perplexity）

PG-19 是長篇書籍級語言建模的標準測試。Jet-Long 達到最低困惑度，代表其在長序列上的條件機率估計更穩定，生成流暢度與一致性較佳。

##### 4. 系統效能

在 H100 上的效率數據顯示：

- 長上下文預填充（prefill）吞吐量為 FA2 的 1.28–1.39 倍。
- 單批次生成（single-batch generation）在所有測試長度下額外開銷 ≤4%。

這說明 Jet-Long 的準確率提升並非以犧牲延遲或吞吐量為代價，反而因為核心融合與避免 KV 快取重算而達到接近甚至超越標準 FA2 的預填充效率。

##### 5. 跨架構遷移：Jet-Nemotron

Jet-Long 可直接套用到混合注意力架構（hybrid attention architectures）Jet-Nemotron，無需重新訓練即可進一步提升長上下文表現。這顯示方法對不同注意力設計具有一定通用性。

##### 6. 超參數穩健性

單一超參數 \(w\) 在多種設定下表現穩健，對實際部署極為有利——工程師無需針對每個目標長度進行繁瑣搜尋。

#### 與現有研究的比較

##### 1. 相較於頻率重新縮放方法

- **Position Interpolation（PI）**：線性壓縮所有位置，雖簡單但會同時壓縮高頻成分，短上下文細粒度位置資訊受損。Jet-Long 在原生素長內保持恆等映射，短上下文完全不失真。
- **NTK / Dynamic NTK（DNTK）**：透過調整 RoPE 基底（base）來區分高低頻；DNTK 雖讓基底隨長度變化，但仍使用單一全局縮放。Jet-Long 進一步引入雙焦視窗與動態分組，局部保持原始解析度、遠端才進行別名。
- **YaRN**：結合維度分區與注意力溫度校正，同時處理位置分佈外與 softmax 注意力擴散（softmax-attention diffusion）。Jet-Long 主要針對位置分佈外問題，並透過動態調度避免固定因子的權衡；但未像 YaRN 般顯式引入注意力溫度機制。

##### 2. 相較於分組／區塊位置方法

- **Self-Extend**：使用固定分組大小將遠端 token 映射到鄰近位置。Jet-Long 與其同屬分組位置家族，但將分組大小改為序列長度的函數，使短輸入時自動退化為基礎模型。
- **Dual Chunk Attention（DCA）**：將序列切成區塊，並在跨區塊注意力中使用不對稱查詢／鍵索引以維持相對距離在預訓練範圍內。Jet-Long 的雙焦設計概念上更簡潔，只需區分局部與遠端視窗，並透過包含-排除合併處理重疊。
- **ReRoPE**：以兩段式注意力混合處理視窗內外位置，但主要針對預填充（prefill）。Jet-Long 透過三個 FlashAttention 路徑與即時校正旋轉，同時支援預填充與生成階段，且不改變 KV 快取。

##### 3. 相較於訓練式方法

持續預訓練（continued pretraining）雖能延伸上下文，但面臨運算成本隨序列長度二次增長、長上下文資料稀缺，以及短上下文表現退化等風險。Jet-Long 作為免微調（tuning-free）方法，可直接套用於開放權重檢查點（open-weight checkpoints），無需額外訓練。

##### 4. 限制與待釐清之處

- **未直接處理注意力擴散與 lost-in-the-middle 偏差**：Jet-Long 主要解決位置分佈外旋轉問題；雖然局部視窗有助於保留中短距離結構，但對於 softmax 分佈扁平化與 U 型位置偏差的處理不如 YaRN 明確。
- **依賴 RoPE**：方法針對旋轉位置編碼（RoPE, Rotary Position Embedding）設計，對於無位置編碼（NoPE）或其他編碼方案需額外調整。雖然論文展示可遷移至 Jet-Nemotron 混合架構，但通用性仍需更多驗證。
- **核心實作複雜度**：包含-排除合併與 CuTe 核心融合雖帶來效率，但增加了實作與除錯難度，對開源重現構成挑戰。
- **評估模型範圍**：主要結果集中在 Qwen3 系列與 Jet-Nemotron，對於 Llama、Mistral 等其他廣泛使用的開放權重模型（open-weight LLMs）的適用性尚待驗證。

#### 可重現性評估

##### 1. 資料與模型可取得性

- **資料集**：RULER、HELMET-RAG 與 PG-19 均為公開基準，具備可重現性。
- **模型**：Qwen3-1.7B/4B/8B 為開放權重模型，可公開下載。Jet-Nemotron 雖在文中提及，但目前尚不確定是否已全面開放權重與實作細節。

##### 2. 方法層面的可重現性

Jet-Long 是免微調（tuning-free）方法，僅需設定單一超參數 \(w\)，理論上可在現有模型推論流程中實作。然而，根據提供的上下文，論文並未明確給出：

- 動態重新縮放調度（dynamic schedule）的完整數學公式。
- 三個 FlashAttention 路徑的確切遮罩（mask）與合併權重。
- CuTe 核心（CuTe kernel）的原始碼或偽碼。
- 各模型對應的建議 \(w\) 值與實驗配置。

缺少這些細節，獨立研究者雖可復現概念版本，但難以完全重現論文報告的吞吐量與準確率數字。

##### 3. 開源釋出建議

若要達成高可重現性，作者應釋出：

1. PyTorch 參考實作與 CuTe 核心程式碼。
2. 動態調度公式與各模型建議超參數。
3. 評估腳本與預處理流程。
4. 若 Jet-Nemotron 為新模型，應一併釋出檢查點（checkpoint）與架構細節。

在這些資源釋出前，Jet-Long 的結果屬於「概念可重現、工程細節需確認」的階段。

#### 未來研究方向

##### 1. 結合注意力擴散抑制機制

Jet-Long 可與 YaRN 的注意力溫度校正、LM-Infinite 的 Λ 型遮罩，或針對 lost-in-the-middle 偏差的顯式懲罰相結合，同時解決位置分佈外與 softmax 注意力擴散兩大失效模式。

##### 2. 動態調度的理論分析

目前動態分組大小是啟發式設計。未來可建立理論框架，給定預訓練長度與目標長度，推導最優別名間隔，並分析對注意力銳度（attention sharpness）與困惑度（perplexity）的影響。

##### 3. 擴展至非 RoPE 與多模態架構

雖然 Jet-Long 針對 RoPE 設計，但可探索將雙焦概念遷移至無位置編碼（NoPE）模型、狀態空間模型（state-space models）或長上下文多模態模型（如長影片、長語音序列）。

##### 4. 與稀疏注意力及線性注意力整合

將 Jet-Long 與稀疏注意力（sparse attention）、線性注意力（linear attention）或環狀注意力（Ring Attention）結合，可在更長序列（如 1M+ 詞元）上降低二次運算成本，同時維持位置別名帶來的分佈內特性。

##### 5. 多尺度雙焦或多焦設計

除了單一局部視窗與單一遠端視窗，可考慮多個遠端視窗，每個視窗對應不同解析度，以捕捉不同距離尺度的依賴關係。

##### 6. KV 快取壓縮與量化

在即時 RoPE 校正旋轉不改變 KV 快取的前提下，可進一步研究與 KV 快取量化、剪枝或壓縮方法的相容性，以支援更長的單批次生成。

##### 7. 真實智慧體與程式編寫工作負載評估

未來應在真實智慧體工作流程（agentic workflows）、儲存庫層級程式碼理解（repository-level code understanding）與多輪工具使用（multi-step tool use）場景中進行端對端評估，驗證 128K 甚至更长上下文下的實用價值。

##### 8. 自動化超參數選擇

雖然 \(w\) 已相當穩健，仍可開發基於序列長度、任務類型或模型大小的自適應選擇演算法，進一步簡化部署。

## 論文問答

**Q1：為什麼長上下文應用會讓現代大型語言模型面臨部署挑戰，而零樣本上下文延伸為何成為主流？**

A：現今大型語言模型（LLMs）被廣泛用於長文件問答、儲存庫層級程式碼理解、檢索增強生成（RAG）與多步驟智慧體工作流程，這些場景的輸入動輒累積到 10 萬詞元以上，遠超過模型預訓練時的上下文視窗。由於開放權重檢查點必須在部署後支援各種未知的序列長度，開發者難以針對每一種長度重新訓練或微調模型，因此零樣本上下文延伸成為最實際的部署路徑。這種方式希望模型在不修改權重的情況下，直接將預訓練視窗外推到更長的輸入，但同時也帶來了短上下文保真度與長上下文效能之間的緊張關係。

**Q2：原始 Transformer 在超過訓練視窗後會出現哪些失效模式？現有零樣本方法為何難以兼顧短、長上下文？**

A：RoPE 型 LLM 外插失敗主要來自兩個互補的問題：第一是分佈外 RoPE 旋轉（position out-of-distribution），低頻 RoPE 分量在訓練未見過的位置上產生過大的旋轉角，使注意力分數異常；第二是 Softmax 注意力擴散與 U 型位置偏誤，隨著鍵值集合變大，機率質量被攤平，且模型傾向忽略位於中間的證據。現有零樣本方法如 PI、NTK、YaRN、Self-Extend 與 DCA 大多在部署前固定單一重新縮放因子或分組大小，導致激進的縮放會損害短上下文表現，而保守的縮放則在長上下文下崩潰。Jet-Long 正是為了解決這種「一個因子打天下」的兩難，才提出隨當前序列長度動態調整的雙焦策略。

**Q3：為什麼不直接以長上下文繼續預訓練來解決問題？零樣本延伸的價值在哪裡？**

A：直接延長上下文進行繼續預訓練雖然有效，但計算量仍隨序列長度呈二次成長，且長上下文高品質資料稀少，微調過程還可能導致短上下文能力退化。對於開放權重模型而言，使用者通常只有一個釋出的檢查點，卻需要支援從數千到數十萬詞元不等的任意輸入長度，重新訓練在成本與時間上都不切實際。零樣本上下文延伸因此成為主導部署模式，它讓同一個基礎模型無需額外訓練即可服務多種長度，大幅降低長上下文應用的門檻。

**Q4：Jet-Long 的核心方法「動態雙焦 RoPE」是什麼？局部視窗與長程視窗各自扮演什麼角色？**

A：Jet-Long 將注意力分成兩個視窗：一個是局部 RoPE 忠實視窗（local RoPE-faithful window），在這個範圍內完全保留原始位置編碼，使模型在短輸入時與基礎模型行為一致；另一個是長程視窗（long-range window），對超過原生視窗的遠端詞元使用動態重新縮放因子，把位置索引對應回預訓練時見過的旋轉網格。這種雙焦結構讓近處的細粒度位置資訊不受影響，同時讓遠端位置保持在分佈內，從而兼顧短上下文保真度與長上下文外插能力。

**Q5：Jet-Long 的「動態」重新縮放因子與 YaRN、Self-Extend、DCA 等基線有何根本不同？**

A：YaRN、Self-Extend 與 DCA 等方法在部署前便固定一個分組大小或縮放因子，無法根據實際輸入長度調整，因此面對短序列會過度壓縮位置、面對長序列又可能縮放不足。Jet-Long 則讓長程視窗的重新縮放因子成為當前序列長度的函數，序列越長時分組越大，確保每一個遠端 RoPE 旋轉都落在預訓練分佈內。這種動態調度策略使 Jet-Long 在短輸入時能精確還原基礎模型，在長輸入時又能乾淨地外插，突破了傳統方法「魚與熊掌不可兼得」的限制。

**Q6：Jet-Long 的「包含－排除注意力合併」與「即時 RoPE 校正旋轉」是為了解決什麼問題？它們如何讓推論幾乎無額外成本？**

A：雙焦結構需要同時計算局部與長程兩組注意力，若直接實現會增加記憶體與計算開銷；Jet-Long 透過包含－排除注意力合併（inclusion-exclusion attention merge）將兩個視窗的結果用三個 FlashAttention 路徑組合起來，避免重複計算並維持正確的機率分佈。即時 RoPE 校正旋轉（on-the-fly RoPE correction rotation）則在生成階段不更動 KV 快取內容，僅在需要時對查詢進行角度修正，從而保持鍵值快取不變並降低記憶體頻寬壓力。整個流程被融合成單一 CuTe 核心，使得長上下文預填充吞吐量達到 FlashAttention-2 的 1.28–1.39 倍，單批次生成在每個長度下的額外開銷都不超過 4%。

**Q7：論文使用了哪些基準測試來評估 Jet-Long？這些測試分別衡量什麼能力？**

A：實驗主要採用 RULER、HELMET-RAG 與 PG-19 困惑度三項指標。RULER 是一組合成長上下文召回任務，涵蓋 13 種不同類型的檢索與推理挑戰，用來檢驗模型在極長序列中定位與使用關鍵資訊的能力；HELMET-RAG 被 HELMET 研究認為是預測下游長上下文任務整體表現最有效率的指標，綜合評估 RAG 場景下的準確率；PG-19 困惑度則衡量模型在長篇連貫文本上的語言建模品質，數值越低代表外插後的機率預測越穩定。

**Q8：Jet-Long 在 Qwen3 系列上的主要實驗結果為何？推論效能表現如何？**

A：在 Qwen3-1.7B、4B 與 8B 上測試至 128K 上下文時，Jet-Long 在 RULER 上相較最強基線分別領先 +4.79、+2.18 與 +2.03 個百分點，並在 HELMET-RAG 取得最佳或平手的整體準確率，同時達到最低的 PG-19 困惑度。在 H100 上，融合後的 CuTe 核心讓長上下文預填充吞吐量達到 FlashAttention-2 的 1.28–1.39 倍，已接近僅支援 Hopper 的 FlashAttention-4 水準。單批次生成階段則在所有測試長度下僅產生不超過 4% 的額外開銷，顯示方法在準確率與效率間取得了良好平衡。

**Q9：Jet-Long 的超參數穩健性與跨架構泛化能力如何？**

A：Jet-Long 只需要一個主要超參數（局部視窗寬度），論文顯示該參數對選擇相當穩健，降低了實際部署時的調校負擔。此外，該方法無需重新訓練即可遷移到混合注意力架構，例如 Jet-Nemotron，並進一步提升其長上下文表現，顯示雙焦設計對不同注意力變體具有良好的相容性。這種超參數穩健性與架構泛化能力對於希望快速上線的開放權重模型部署者來說尤為重要。

**Q10：Jet-Long 最適合哪些實際應用場景？**

A：Jet-Long 特別適合輸入會動態增長且難以預先決定長度的應用，例如檢索增強生成需要一次性處理大量檢索文件、儲存庫層級程式碼理解必須同時納入原始碼與執行追蹤、以及多步驟智慧體工作流程中累積的推理與工具輸出。在這些場景中，詞元數量往往從數千迅速膨脹到十萬以上，傳統固定縮放方法容易在某一長度區間失效。Jet-Long 的動態調度讓單一檢查點能穩定服務從短到長的各種輸入，減少為不同長度維護多個模型版本的麻煩。

**Q11：從產品部署的角度來看，Jet-Long 有哪些優勢？**

A：Jet-Long 是免微調的零樣本方法，部署時不需要收集長上下文資料或進行昂貴的繼續預訓練，能直接套用於現有開放權重檢查點。其推論實現幾乎不增加成本，預填充吞吐量甚至高於 FlashAttention-2，生成階段開銷也控制在 4% 以內，對線上服務的延遲與吞吐量影響極小。再加上單一超參數且對選擇穩健，工程團隊可以快速整合並上線，顯著降低長上下文功能的產品化門檻。

**Q12：Jet-Long 對長上下文研究與開放權重模型生態可能帶來什麼影響？**

A：Jet-Long 顯示零樣本延伸不必在短上下文保真度與長上下文能力之間做固定取捨，動態調度策略為後續研究提供了一條新的設計軸線。由於它能無縫應用於現有開放權重檢查點，並可遷移至混合注意力架構，有助於加速長上下文能力在開源社群與商業產品中的普及。此外，其在 HELMET-RAG 與 RULER 上的強勁表現也強化了「零樣本延伸足以支撐實際長上下文應用」的論點，可能促使更多研究聚焦於推論階段的動態位置調度與高效核心實現。

**Q13：Jet-Long 有哪些已知的限制或未能完全解決的問題？**

A：Jet-Long 主要針對第一種失效模式，也就是位置分佈外（position out-of-distribution）的 RoPE 旋轉問題，透過動態別名對應回預訓練旋轉網格；但對於第二種失效模式——Softmax 注意力擴散與 U 型位置偏誤——並未直接引入注意力溫度調整或稀疏機制來處理。因此，在極長序列中，模型仍可能因為注意力分佈攤平而遺失中間位置的關鍵資訊。此外，作為一種基於 RoPE 的位置調度方法，它對於完全無位置編碼（NoPE）或某些非 RoPE 架構的適用性仍需額外驗證。

**Q14：在什麼情況下 Jet-Long 可能表現不佳或失效？**

A：當任務高度依賴遠端詞元之間的精確相對位置關係時，長程視窗的分組別名可能會壓縮過多細粒度位置資訊，導致模型難以區分遠處詞元的先後順序。如果目標長度遠超過動態調度設計範圍，重新縮放因子可能仍會讓部分低頻旋轉角落在分佈外，進而引發外插失敗。另外，對於原生預訓練視窗極小、而目標延伸倍率極大的模型，遠端視窗的分組會變得非常粗糙，可能影響需要細緻位置感知的下游任務表現。

**Q15：未來研究可以如何延伸或改進 Jet-Long？**

A：未來可以將 Jet-Long 與注意力溫度調整、稀疏注意力或狀態空間模型結合，同時處理位置分佈外與注意力擴散兩大失效模式。也可以探索讓動態調度策略本身從資料中學習，而非依賴單一超參數，以進一步提升在不同模型族與任務上的適應性。此外，將雙焦設計擴展到更廣泛的混合架構、非 RoPE 位置編碼，以及多模態長序列場景，並針對更多 GPU 世代優化核心實現，都是值得深入的方向。

## 實務應用指南

## 適用場景

1. **多輪智慧體工作流程（Multi-step Agentic Workflows）**  
   客服、研究助理或程式編寫智慧體在多次工具呼叫與推理後，累積的對話、工具輸出與執行追蹤常超過 100K 詞元。Jet-Long 可在不重新訓練檢查點的情況下，讓開放權重模型直接處理這些長軌跡。

2. **儲存庫層級程式碼理解與生成（Repository-level Coding）**  
   當模型需要同時參考多個原始碼檔案、依賴關係與執行追蹤時，Jet-Long 的雙焦結構能保留局部程式碼區塊的精細 RoPE 位置資訊，同時讓遠端檔案區塊維持分佈內旋轉。

3. **檢索增強生成（RAG）與長文件問答**  
   在長文件或大量檢索片段中，Jet-Long 的動態重新縮放因子可依當前序列長度調整，避免短上下文保真度下降，並在 128K 等長序列維持穩定的召回率與困惑度。

4. **即時長上下文推論服務**  
   對於已部署 FlashAttention-2 的推論引擎，Jet-Long 的 CuTe 核心可在 H100 上達到 1.28–1.39× FA2 預填充吞吐量，且單批次生成額外開銷 ≤4%，適合對延遲與成本敏感的線上服務。

5. **混合注意力架構的零樣本延伸**  
   若採用 Jet-Nemotron 等混合注意力模型，Jet-Long 可直接套用而無需重新訓練，進一步提升長上下文表現，適合想快速驗證新架構長程能力的團隊。

## 實作前置條件

### 資料
- **無需長上下文微調資料**：Jet-Long 是免微調的零樣本方法，不需要額外收集或標註長文件、長對話或領域資料。
- **建議準備驗證資料**：為了選定單一超參數 `w`（局部 RoPE 忠實視窗大小），建議準備少量代表目標場景的序列，例如 32K–128K 的 RAG 文件或程式碼片段，用於測量困惑度與下游任務準確率。

### 運算
- **GPU**：若要發揮論文所述的 1.28–1.39× FA2 預填充吞吐量，建議使用 NVIDIA H100（Hopper 架構）。方法本身可在其他 CUDA GPU 執行，但峰值效能與核心融合程度會隨硬體而異。
- **記憶體**：與基礎模型相同的 KV 快取需求；Jet-Long 不改變 KV 快取格式，因此不需要額外記憶體來儲存多組位置編碼。
- **軟體堆疊**：需要支援 CuTe 的 CUDA 工具鏈、FlashAttention-2/4 相容的推論框架，以及目標模型（如 Qwen3 或 Jet-Nemotron）的權重檢查點。

### 技能
- **熟悉 Transformer 注意力與 RoPE**：需理解旋轉位置編碼、相對位置、注意力合併與 KV 快取機制。
- **CUDA 核心或推論框架整合經驗**：若要自行融合 CuTe 核心，需要核心開發能力；若使用現成實作，則需具備推論引擎（如 vLLM、TensorRT-LLM、Triton）的整合與調校經驗。
- **評估能力**：能執行 RULER、HELMET-RAG、PG-19 困惑度等長上下文基準測試，或建立領域專屬的端到端評估。

## 實作步驟建議

1. **確認基礎模型相容性**  
   檢查目標模型是否使用 RoPE（如 Qwen3-1.7B/4B/8B）或混合注意力架構（如 Jet-Nemotron）。Jet-Long 對這兩類架構皆可零樣本套用。

2. **選定局部視窗超參數 `w`**  
   將 `w` 設為接近模型原生訓練視窗（例如 4K–32K）。論文顯示此參數相當穩健，建議以目標場景的困惑度與召回率為準，在 `{原生視窗, 原生視窗一半, 原生視窗兩倍}` 中快速掃描即可。

3. **實作或接入雙焦注意力模組**  
   將序列分為：
   - **局部 RoPE 忠實視窗**：最近 `w` 個詞元使用原始 RoPE，完全還原基礎模型行為。
   - **長程視窗**：超過 `w` 的詞元使用動態重新縮放因子，使旋轉角度維持分佈內。  
   透過包含-排除注意力合併（inclusion-exclusion attention merge）將三個 FlashAttention 計算（局部、長程、重疊區）組合成最終注意力分數。

4. **加入即時 RoPE 校正旋轉**  
   在生成階段，對新產生的查詢詞元即時套用校正旋轉，確保 KV 快取無需重寫或重新編碼，維持與基礎模型相同的快取格式。

5. **融合 CuTe 核心並優化預填充**  
   將上述三個注意力路徑與校正旋轉融合為單一 CuTe 核心。若使用 Hopper GPU，可預期接近 FA4 的預填充吞吐量；若非 Hopper，則至少應確保記憶體存取模式與 FlashAttention 對齊。

6. **端到端驗證**  
   - 短上下文：確認輸出與基礎模型完全一致（Jet-Long 在原生視窗內應精確還原）。
   - 長上下文：在 64K/128K 執行 RULER、HELMET-RAG 與 PG-19 困惑度測試，並與 YaRN、Self-Extend、DCA、Dynamic NTK 等基線比較。
   - 效能：測量首 token 延遲（prefill throughput）與逐 token 生成延遲，確認 ≤4% 開銷。

7. **部署與監控**  
   將 Jet-Long 封裝為推論引擎的後端選項，並在生產環境監控長序列的命中率、KV 快取命中率與異常輸出（如重複、幻覺）。

## 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **短上下文回歸** | 若 `w` 過小或動態調度過於激進，可能影響短序列表現。 | 在原生訓練視窗內驗證輸出與基礎模型一致；`w` 建議不小於模型原生視窗的一半。 |
| **核心融合複雜度** | 三個注意力路徑與即時校正旋轉若未融合，可能增加記憶體搬運與延遲。 | 優先使用 Hopper GPU 與 CuTe 實作；非 Hopper 環境可考慮分階段核心並評估 overhead。 |
| **動態因子調度誤設** | 雖然超參數穩健，但極端長度下調度曲線仍需驗證。 | 在最大目標長度（如 128K）執行 RULER 與領域測試，觀察遠端 token 的注意力權重分佈。 |
| **與現有快取系統相容性** | 雖然 KV 快取格式不變，但某些推論框架會對位置編碼做額外假設。 | 在整合前確認框架不會覆寫或重新計算 RoPE；必要時修改 attention backend 的介面。 |
| **非 RoPE 模型不適用** | NoPE 或 ALiBi 模型無法直接套用 Jet-Long。 | 僅對 RoPE 或 Jet-Nemotron 等已驗證架構啟用；其他架構需改用對應的長上下文方法。 |

## 與其他技術的整合建議

- **FlashAttention / FlashAttention-4**  
  Jet-Long 的包含-排除注意力合併本質上是三次 FlashAttention 呼叫的數學重組，因此可無縫嵌入 FA2/FA4 的記憶體排程與分塊策略中。建議在 Hopper 上直接以 FA4 作為底層，以逼近論文所述的最大吞吐量。

- **vLLM / TensorRT-LLM / Triton**  
  可將 Jet-Long 實作為客製化的 attention backend。由於 KV 快取格式不變，現有的分頁式 KV 快取（paged KV cache）、連續批處理（continuous batching）與推測解碼（speculative decoding）皆可繼續使用。

- **RAG 管線**  
  在檢索增強生成中，可將檢索到的文件區塊標記為長程視窗，而使用者的最近查詢與少數高相關片段保留在局部 RoPE 忠實視窗，兼顧局部精確度與長程召回。

- **智慧體框架（LangChain、AutoGen、NVIDIA NeMo Microservices 等）**  
  在智慧體工作流程中，Jet-Long 可作為「長記憶」層的底層模型後端，讓多輪工具軌跡無需截斷即可完整輸入，減少因遺失早期上下文而導致的決策錯誤。

- **混合注意力模型（Jet-Nemotron）**  
  對於已採用混合注意力的模型，Jet-Long 可直接套用在 softmax 層而無需重新訓練，進一步提升長上下文能力，適合做為模型升級的零樣本延伸方案。

## 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦於「為什麼長上下文很難」以及 Jet-Long 的核心直覺：把輸入分成「最近、需要精確位置」與「較遠、可以粗略一點」兩個區域，並且讓遠區的縮放因子隨長度自動調整。可先略過 CuTe 核心與包含-排除合併的數學細節，重點理解它「免微調、不改 KV 快取、短上下文不變」這三個優勢。

**AI 工程師**  
請深入閱讀方法論（Section 3）與推論實作細節，特別是動態調度策略、三個 FlashAttention 路徑的合併方式，以及即時 RoPE 校正旋轉如何讓 KV 快取保持不變。實作時應優先關注核心融合、與現有推論框架的介面對接，以及在不同長度下的延遲與吞吐量測量。

**研究人員**  
建議從失敗模式分析（Section 2.1）與相關工作比較（Section 2.2）開始，理解 Jet-Long 在「頻率重新縮放」與「分組位置」兩條軸線上的定位。可進一步探討動態調度函數的設計空間、與 NoPE 或狀態空間模型的理論關聯，以及在不同架構（如 Jet-Nemotron）上的泛化機制。

**產品經理**  
重點關注適用場景、效能數據與部署風險。Jet-Long 的價值在於讓單一開放權重檢查點無需重新訓練即可服務多種長上下文應用，並在 H100 上達到接近 FA4 的預填充速度。評估時請確認目標場景是否屬於 RoPE 模型、序列長度分佈，以及是否有足夠的 GPU 資源來發揮其核心融合優勢。
