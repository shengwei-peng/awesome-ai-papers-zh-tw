#### 與現有研究的比較

Frontier3DBench 相較於既有基準，在三個維度上實現了統一化突破。

**步驟二：建構評測管線**
- 視覺評估：對 L1/L2 提交進行多視角渲染，使用 SSIM、LPIPS、CLIP score 評估外觀。
- 結構評估：透過 Blender 原生場景檢查（bpy）量測幾何、佈局、構圖。
- 行為評估：對 L3 提交撰寫獨立觀察者腳本，模擬玩家操作並驗證動作淨空（motion clearance）與有狀態工作流程（stateful workflows）。

**步驟三：部署代理框架**
選擇模型-框架配置（model-harness configuration）。論文實測 11 組配置，建議先以 GPT-6.1-sol 與 GPT-6-astra 作為基準，再依成本與任務特性挑選替代方案。框架需支援：
- 接收任務輸入並產生引擎專屬程式碼。
- 自動執行產出並回傳執行結果。
- 失敗時具備重試與錯誤回饋機制。

**步驟四：分層級迭代**
- **L1 物件層**：先驗證代理在 Text2Code 與 Img2Code-SingleView 的表現，這是相對容易的起點。
- **L2 場景層**：當物件層通過後，進入場景組合與編輯任務，特別注意參考重建（Ref2Scene）通常分數較低。
- **L3 開放世界層**：最後挑戰互動式世界建構，預期局部機制分數高（~83/100）但協調活動分數低（~30/100），需特別設計提示詞與範例。

**步驟五：瓶頸優化**
針對論文指出的兩個核心瓶頸進行專項優化：
- **參考保真度**：在提示詞中加入多視角一致性約束、幾何細節描述、參考圖像的特徵標註。
- **協調活動完成度**：為 L3 任務提供明確的狀態機範例、動作序列範本，並在評測腳本中給予部分回饋以利代理自我修正。

**步驟六：成本與效能監控**
記錄每個配置的 API 成本、執行時間、成功率，建立 ROI 報表。論文強調「API 成本」是配置差異的關鍵維度，產品化時需權衡品質與成本。

### 潛在風險與注意事項

**風險一：參考保真度瓶頸導致客戶期望落差**
- **現象**：所有配置在參考重建任務上的分數都低於文字驅動生成，意味著代理容易「自由發揮」卻難以「忠實還原」。
- **緩解**：在交付前加入人工審核環節；對高保真需求場景（如電商產品圖）保留人工建模流程，僅將代理用於初稿生成。

**風險二：L3 互動邏輯的隱性失效**
- **現象**：局部機制看似正常（83.08/100），但完整活動完成度僅 30.26/100，意味著代理可能產出「能跑但不能玩」的世界。
- **緩解**：部署獨立的自動化測試套件，模擬完整玩家路徑而非單一動作；對 L3 任務設定較高的測試覆蓋率門檻。

**風險三：引擎版本與 API 漂移**
- **現象**：Blender 與 Unreal Engine 持續更新，代理產出的程式碼可能在未來版本失效。
- **緩解**：鎖定引擎版本並建立 CI/CD 流程定期回歸測試；維護一個「已知可執行」的範本庫作為代理的參考。

**風險四：評測標註洩漏**
- **現象**：若評測用的 ground truth 幾何、佈局、視覺細節被洩漏至訓練資料，基準將失去鑑別力。
- **緩解**：嚴格分離訓練與評測資料集；對評測腳本進行權限控管；定期更新任務與標註。

**風險五：API 成本失控**
- **現象**：145 個任務 × 11 個配置 × 多次重試可能產生可觀的 API 費用。
- **緩解**：設定每任務的 token 上限；採用快取機制避免重複呼叫；對簡單任務使用較便宜的模型。

**風險六：可編輯性與可執行性的權衡**
- **現象**：代理可能產出「可執行但難以編輯」的程式碼（如將所有幾何烘焙成單一 mesh），降低後續修改彈性。
- **緩解**：在評測指標中加入「結構化程度」檢查，鼓勵代理使用 parametric 建模、命名規範、模組化程式碼。

### 與其他技術的整合建議

**與傳統 3D 建模工具的整合**
- Blender 插件：將代理包裝為 Blender 插件，讓設計師在熟悉介面中呼叫代理生成初稿，再手動精修。
- Unreal Editor Utility：將代理整合為 Unreal Editor 的 Utility Widget，允許關卡設計師直接在編輯器內觸發世界生成。

**與資產管理系統的整合**
- 將代理輸出自動上傳至資產庫（如 Unity Asset Store、Sketchfab、內部 DAM），並標註來源（代理生成 vs 人工建模）以便追溯。
- 整合版本控制（Git LFS + Perforce）管理代理產生的 .blend 與 Unreal 專案檔案。

**與 CI/CD 流程的整合**
- 每次代理提交觸發自動化評測管線，產出視覺、結構、行為三類報告。
- 將 Frontier3DBench 的評測結果作為合併請求的品質門檻（quality gate）。

**與其他 AI 模型的整合**
- 視覺語言模型：用於評估代理產出的渲染圖是否符合文字指令（取代或補充 CLIP score）。
- 程式碼專用語言模型：對 Blender Python 與 Unreal C++/Blueprint 進行專項微調，提升代理在引擎 API 上的準確度。
- 物理模擬引擎：對 L3 任務加入物理正確性檢查（碰撞、動量、摩擦），補強現有「動作淨空」指標。

**與遊戲引擎的 AI 行為樹整合**
- L3 任務的「有狀態工作流程」可與 Unreal 的 Behavior Tree、State Tree 整合，讓代理產出的互動邏輯可直接掛載到 NPC 或可互動物件上。
