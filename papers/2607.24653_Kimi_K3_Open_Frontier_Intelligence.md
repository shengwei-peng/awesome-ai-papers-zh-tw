## 摘要翻譯

我們介紹 Kimi K3，一個總參數量（total parameters）2.8T 的混合專家模型（Mixture-of-Experts, MoE），具備 1040 億（104B）啟動參數（activated parameters）、原生視覺能力（native vision capabilities），以及百萬 token 上下文視窗（1-million-token context window）。Kimi K3 以 Kimi Delta Attention（KDA）與注意力殘差（Attention Residuals / AttnRes）為基礎，可改善跨序列長度與模型深度的資訊流動。結合 Stable LatentMoE（穩定潛在混合專家），其每個 token 可有效啟動 896 個路由專家（routed experts）中的 16 個，並搭配經過精煉的訓練與資料配方（training and data recipes），這些進展使整體擴展效率（scaling efficiency）相較於 Kimi K2 提升約 2.5 倍。後訓練（post-training）著重於跨通用、代理式（agentic）與程式設計領域（coding domains），以及多種推理努力等級（reasoning-effort levels）的強化學習（reinforcement learning, RL），從而實現組合式泛化（compositional generalization）與穩健的長程執行（long-horizon execution）。在 2.8T 規模下，Kimi K3 在多個面向的基礎設施上取得進展，包括：針對 KDA 的演算法–系統協同設計（algorithm-system co-design）、具備高效記憶體管理（memory management）的完美平衡專家平行訓練（perfectly balanced expert-parallel training）、具備持久化 rollout（persistent rollout）與沙盒狀態（sandbox states）的百萬 token 代理式強化學習（million-token agentic RL），以及部署創新（deployment innovations）。大量評估顯示，Kimi K3 在長程程式設計（long-horizon coding）、代理式（agentic）、知識（knowledge）、推理（reasoning）與視覺（vision）等任務上均達到前沿級表現（frontier-level performance）。儘管其整體表現仍落後於最強大的專有模型（proprietary models），即 Claude Fable 5 與 GPT-5.6 Sol，Kimi K3 仍持續優於我們評測套件中所評估的其他開放模型（open models）與專有模型（proprietary models）。我們釋出完整的 Kimi K3 模型權重（model weights），以促進未來研究，並加速前沿智慧（frontier intelligence）更廣泛的部署與採用。

### 核心貢獻（3～5點）
- **架構創新與擴展效率：** 結合 Kimi Delta Attention（KDA）、注意力殘差（AttnRes）與 Stable LatentMoE，在 2.8T 總參數 / 104B 啟動參數的規模下，整體擴展效率相較 Kimi K2 提升約 2.5 倍。
- **大規模訓練基礎設施：** 透過演算法–系統協同設計、完美平衡的專家平行訓練與高效記憶體管理，支撐極度稀疏 MoE 模型的高效訓練。
- **跨領域後訓練強化學習：** 在通用、代理式與程式設計領域進行強化學習，並支援多種推理努力等級，實現組合式泛化與穩健的長程執行。
- **百萬 token 長上下文代理能力：** 具備百萬 token 上下文視窗與百萬 token 代理式強化學習，結合持久化 rollout 與沙盒狀態，支援長程程式設計與複雜代理式任務。
- **開放釋出完整模型權重：** 釋出 Kimi K3 完整模型權重，促進未來研究並加速前沿智慧的廣泛部署與採用。

### 適合對象
本論文適合大型語言模型與混合專家模型研究者、AI 系統與分散式訓練工程師、從事代理式系統（agentic systems）、長上下文建模、強化學習後訓練與多模態推理的從業人員，以及關注開放模型（open models）與專有模型（proprietary models）性能差距的學術界與產業界讀者。對於希望了解如何在大規模參數規模下實現高效訓練、長程執行與開放釋出的研究團隊尤其具有參考價值。

## 深度分析

#### 方法論解析

Kimi K3 的核心方法論可視為「雙軸擴展（dual-axis scaling）」的具體實踐：一方面將預訓練基礎模型（pre-trained foundation）的總參數量（total parameters）推升至 2.8 兆（2.8T）、啟動參數（activated parameters）達 1,040 億（104B）的 3 兆級（3T-class）規模；另一方面在測試時擴展（test-time scaling）上，透過強化學習（reinforcement learning, RL）與多級推理努力（multi reasoning-effort levels）支援長達一百萬 token（1M-token）的上下文視窗（context window）。整體方法論可拆解為架構、後訓練（post-training）與基礎設施三個層次。

##### 1. 架構設計：沿序列長度、網路深度與模型寬度三維擴展資訊流

Kimi K3 的骨幹圍繞三種資訊混合機制建構：

- **Token 混合：Hybrid Attention（混合注意力）**  
  每個區塊（block）採用 3:1 的比例交錯三層 Kimi Delta Attention（KDA）與一層 Gated MLA（門控多頭潛在注意力，Gated Multi-head Latent Attention）。KDA 基於 delta-rule recurrence 並加入通道遺忘閘（channel-wise forget gate），以線性複雜度進行長序列混合；Gated MLA 則保留高容量的全域互動（global interaction）。最後一層固定為 Gated MLA，確保輸出層具備完整全域注意力。

- **深度混合：Attention Residuals（AttnRes，注意力殘差）**  
  傳統殘差連接僅累加前一層輸出，AttnRes 讓每一層透過可學習的 pseudo-query 產生注意力權重，選擇性地關注嵌入層（embedding）與所有先前區塊的表徵。這突破了順序殘差累加的資訊瓶頸，使深層網路能直接檢索淺層語意與結構資訊。

- **寬度混合：Stable LatentMoE（穩定潛在混合專家）**  
  路由專家（routed experts）擴充至 896 個，每個 token 僅啟動 16 個，並搭配共享專家（shared expert）。為了在極度稀疏性（extreme sparsity）下穩定優化，引入正規化（normalization）、SiTU-GLU 啟動函數與 Quantile Balancing（分位數平衡）。這種稀疏通道混合在保持總參數量巨大的同時，控制每次前向傳播的實際計算量。

- **原生視覺路徑：MoonViT-V2**  
  以 MoonViT-V2 編碼影像與影片，再經輕量投影器（projector）映射至與語言共享的嵌入空間，使 Kimi K3 成為原生多模態（native multimodal）模型，支援視覺在環工具使用（vision-in-the-loop tool use）。

- **最佳化：Per-Head Muon**  
  針對注意力頭層級的最佳化器設計，進一步穩定大規模訓練動態。

這些架構創新與精煉的訓練與資料配方（training and data recipes）共同達成相較 Kimi K2 約 2.5 倍的整體擴展效率（scaling efficiency）提升。

##### 2. 後訓練：多領域、多努力程度的強化學習與策略整合

Kimi K3 的後訓練明確針對 1M 上下文測試時擴展設計：

- **多領域 RL**：涵蓋長程程式設計（long-horizon coding）、通用代理（general agents）、通用推理與知識任務（general reasoning and knowledge tasks）、軟體工程與核心最佳化（software engineering and kernel optimization）、多模態推理、網頁開發（web development）與自主執行任務（autonomous execution tasks）。
- **多 reasoning-effort 等級**：訓練模型在不同思考預算（thinking budgets）下運作，從快速回應到深度推理皆可調適。
- **通用迴路**：在數百至數千次工具呼叫（tool calls）與數百萬累積上下文 token（accumulated context tokens）的軌跡中，學習「推理–行動–觀察–驗證–調適」的迴路。
- **多教師 on-policy 蒸餾（multi-teacher on-policy distillation）**：將各領域與各努力程度專精的策略（domain- and effort-specialized policies）整合為單一統一模型，避免災難性遺忘並提升組合式泛化（compositional generalization）。

##### 3. 基礎設施：演算法–系統協同設計

Kimi K3 的規模若無對應系統層級創新將難以實現：

- **KDA 系統協同設計**：融合核心（fused kernels）、KDA Context Parallelism（KDA 上下文平行）與 state-aware prefix caching（狀態感知前綴快取），分別優化單一裝置內、跨裝置與跨請求的長序列效率。
- **MoonEP**：針對 2.8T MoE 預訓練，提供完美平衡的專家平行訓練（perfectly balanced expert-parallel training），具靜態計算形狀與零複製通訊（zero-copy communication），並透過記憶體高效訓練與多模態編碼器最佳化在有限記憶體內維持高利用率。
- **百萬 token 代理式 RL 系統**：採用 co-located 架構，結合 partial rollouts（部分軌跡展開）、外部 KV-cache 保留、自適應節流（adaptive throttling）與可恢復的微虛擬機沙盒（resumable microVM sandboxes），以維持長生命週期的模型與環境狀態。
- **部署創新**：專用核心與快取及預算感知的叢集排程（cache-and-budget-aware fleet scheduling），將上述創新轉化為可預測的生產級服務。

#### 實驗數據解讀

根據論文摘要與引言，Kimi K3 的評估橫跨長程程式設計（long-horizon coding）、代理式任務（agentic tasks）、知識任務（knowledge tasks）、推理任務（reasoning tasks）與視覺任務（vision tasks）。整體結論可歸納為三點：

1. **開源模型中的新前沿**：Kimi K3 在評測套件中持續優於其他開放模型（open models）與多數專有模型（proprietary models）。
2. **仍落後於最頂尖專有系統**：整體表現仍次於 Claude Fable 5 與 GPT-5.6 Sol。
3. **雙軸擴展的驗證**：結果顯示同時擴大預訓練基礎模型規模與測試時運算（test-time computation）能帶來可觀的綜效。

##### 數據解讀的注意事項

由於目前僅能取得摘要與部分引言，缺乏完整表格與統計檢定，以下為基於現有資訊的合理推論：

- **自評測試的潛在偏差**：論文由模型開發團隊撰寫，基準選擇、提示設計（prompt design）與評分標準可能存在有利於 Kimi K3 的設定。獨立第三方評估（如 LMSYS Chatbot Arena、LiveBench）將是驗證其相對排名的關鍵。
- **「整體表現」的聚合方式不明**：不同任務的權重如何分配、是否涵蓋安全性（safety）、多語言（multilingual）與低資源場景，將影響「次於 Claude Fable 5 / GPT-5.6 Sol」這一結論的解讀空間。
- **長上下文評估的挑戰**：1M-token 的代理式任務難以用單一數字概括。需要區分「檢索準確率（retrieval accuracy）」、「長程依賴推理（long-range dependency reasoning）」、「多步工具執行成功率（multi-step tool execution success rate）」與「累積錯誤傳播（error propagation）」等指標。
- **效率指標的重要性**：2.5 倍擴展效率提升是相對於 Kimi K2 的內部指標，可能綜合訓練成本、收斂速度與推論吞吐量。對研究社群而言，公開的訓練 FLOPs、推論延遲與記憶體佔用將更具參考價值。

#### 與現有研究的比較

Kimi K3 的定位可從「預訓練規模」與「測試時擴展」兩個軸線與現有研究對照。

##### 1. 相較於開源推理模型

- **DeepSeek-R1** 與 **Kimi K1.5** 證明大規模 RL 可從強預訓練模型中激發複雜推理行為，但它們的基礎模型規模多停留在 1T 級以下或相近水準。Kimi K3 將基礎模型推升至 2.8T，並在 RL 階段引入 1M 上下文與代理式環境，屬於「基礎模型規模 + 推理」的同步擴展。
- **Kimi K2.5 Agent Swarm** 強調平行代理協調（parallel agent coordination），Kimi K3 則進一步將單一模型本身強化為能處理百萬 token 長程軌跡的通用代理基礎。

##### 2. 相較於專有前沿模型

- **OpenAI o-series** 代表以 RL 與測試時推理為主的擴展路線；**Anthropic extended-thinking models** 強調自適應思考預算與工具交錯推理。Kimi K3 在概念上與之呼應，但透過開放模型權重（open model weights）降低研究與部署門檻。
- 論文坦承 Kimi K3 整體仍落後於 Claude Fable 5 與 GPT-5.6 Sol，這顯示專有系統可能在資料品質、對齊（alignment）、推論基礎設施或未公開的規模上仍具優勢。

##### 3. 相較於其他 1T 級開源模型

近期多數開源模型仍處於 1T 級參數規模（1T-class parameter regime）。Kimi K3 以 2.8T 總參數、104B 啟動參數與 1M 上下文，在規模與能力廣度上形成差異化。然而，這也帶來更高的推論與部署成本。

##### 4. 主要限制

- **推論成本**：雖然 MoE 架構降低每次前向傳播的啟動參數，但 2.8T 總參數的記憶體佔用、896 個專家的路由開銷，以及 1M 上下文的 KV-cache，仍對硬體與服務系統提出極高要求。
- **長上下文可靠性**：百萬 token 代理式任務中，錯誤會隨工具呼叫次數累積，模型是否能穩定維持長程目標與狀態一致性，仍需更多公開案例驗證。
- **與頂尖專有模型的差距**：在部分高難度推理或安全性場景，Kimi K3 可能仍不及 Claude Fable 5 / GPT-5.6 Sol。
- **可解釋性與可控性**：Stable LatentMoE 的稀疏路由與 AttnRes 的跨層注意力權重增加了模型行為分析的複雜度。

#### 可重現性評估

可重現性（reproducibility）是評估此類前沿技術報告的關鍵維度，可從以下面向檢視：

##### 1. 模型權重開放

論文明確宣布釋出完整 Kimi K3 模型權重（model weights），這是開放前沿智慧（open frontier intelligence）的核心承諾。釋出權重使研究者能進行：

- 推論行為分析與錯誤案例研究；
- 領域適應（domain adaptation）與微調（fine-tuning）；
- 與其他模型的對照實驗；
- 安全性與對齊研究。

##### 2. 訓練細節與程式碼

目前提供的摘要與引言未詳細說明：

- 完整資料來源、清洗流程與資料配比；
- 訓練超參數（learning rate schedule、batch size、RL 獎勵設計）；
- KDA、AttnRes、Stable LatentMoE 的實作細節；
- MoonEP 與百萬 token RL 系統的原始碼。

缺乏這些資訊，社群難以從頭復現（reproduce from scratch）整個訓練過程。對於 2.8T 模型而言，即使細節公開，絕大多數研究機構也無法負擔對應算力，因此「可重現性」在此更多指「可驗證性（verifiability）」與「可延伸性（extensibility）」。

##### 3. 評估基準與提示

論文提及廣泛評估但未列出完整基準清單、評分腳本與提示模板。未來若能公開評估套件，將大幅提升結果的可比較性與可信度。

##### 4. 基礎設施依賴

KDA Context Parallelism、MoonEP、resumable microVM sandboxes 等創新高度依賴 Moonshot AI 內部軟硬體堆疊。外部研究者即使取得權重，也可能難以在通用框架（如 vLLM、SGLang）上完全發揮其長上下文與 MoE 效率，需要社群進行適配與核心移植。

#### 未來研究方向

Kimi K3 的發表為多個研究方向開啟新機會：

##### 1. 超越 3T 級的預訓練擴展

探索總參數量（total parameters）進一步擴大時，Stable LatentMoE 的稀疏路由、AttnRes 的跨層資訊流與 KDA 的長序列效率是否仍能維持線性或次線性擴展效益，並研究相對應的硬體記憶體與通訊瓶頸。

##### 2. 動態與可解釋的專家路由

目前每 token 固定啟動 16 個專家。未來可研究自適應專家數量、任務相關專家聚類，以及透過可視化路由決策來提升模型可解釋性（interpretability）。

##### 3. 原生多模態強化學習

Kimi K3 已具備原生視覺能力，但未來可發展以視覺觀察為主要獎勵訊號的 RL 環境，例如機器人控制、圖形介面操作（GUI automation）與科學實驗模擬。

##### 4. 超過 1M 的上下文與外部記憶

將上下文視窗（context window）擴展至數百萬甚至無限長度，並結合可檢索的外部記憶（external memory）與持久化狀態（persistent state），使代理式模型能在數週甚至數月的任務中保持連貫性。

##### 5. 測試時運算與模型規模的最佳權衡

研究在不同任務難度下，應如何動態分配「增加模型規模」與「增加測試時運算（test-time computation）」的資源，以達到給定成本下的最佳表現。

##### 6. 開放評估與安全對齊

建立針對長程代理式任務、多模態工具使用與百萬 token 上下文的公開基準，並研究開放權重模型在自主執行任務（autonomous execution tasks）中的安全性、對齊與濫用風險。

##### 7. 模型壓縮與邊緣部署

將 Kimi K3 的知識蒸餾（distillation）至更小、更高效的模型，使其能在消費級硬體或邊緣裝置上執行，同時保留長上下文與代理式能力。

##### 8. 演算法–系統協同設計的泛化

將 KDA Context Parallelism、MoonEP 與 resumable sandbox 的設計原則應用於其他架構（如 Transformer 變體、狀態空間模型），推動下一代大規模模型訓練與服務系統的標準化。

## 論文問答

**Q1：Kimi K3 試圖解決大型語言模型發展中的什麼核心問題？**

A：Kimi K3 針對的是開源模型在「預訓練規模」這條軸線上進展緩慢的問題；雖然測試時擴展與推理強化學習快速進步，但許多開源模型仍停留在 1 兆級參數規模，導致與最強專有模型的差距可能持續擴大。Kimi K3 同時推進預訓練規模與測試時擴展兩條軸線，將基礎模型推進到 3 兆級參數，並在百萬 token 上下文長度上進行代理式強化學習。這樣的雙軸擴展旨在打破開源生態的收斂風險，建立真正的開放前沿智慧。

**Q2：為什麼單純的測試時擴展無法彌補開源模型與頂尖專有系統之間的差距？**

A：測試時擴展雖然能透過強化學習、推理預算與工具使用提升推理能力，但如果所有開源模型都建立在相似的 1 兆級預訓練基礎上，先進的後訓練方法會讓它們趨於同質化。相對地，最強的專有系統同時擁有更大的預訓練規模與更成熟的測試時機制，因此僅靠後者難以追趕。Kimi K3 認為必須把預訓練基礎也擴展到前沿，才能讓開源模型具備足夠的表徵容量來支撐複雜推理與長程執行。

**Q3：同時擴展預訓練規模與測試時運算為何對前沿研究很重要？**

A：預訓練規模決定了模型儲存世界知識與語言理解能力的上限，而測試時運算則決定模型能否在推理、規劃與工具使用中有效調用這些知識。兩者結合才能實現組合式泛化與長程代理任務，例如需要數百到數千次工具呼叫的軟體工程或網頁開發流程。Kimi K3 透過這種雙軸策略，讓開源社群能夠在研究與部署上接觸到過去只有閉源系統才能達到的能力水準。

**Q4：Kimi K3 的核心架構設計包含哪些主要組件？**

A：Kimi K3 是一個擁有 2.8 兆總參數、1040 億啟動參數的原生多模態混合專家模型，並支援高達百萬 token 的上下文視窗。其核心架構包括 Kimi Delta Attention（KDA）、注意力殘差（AttnRes）、Stable LatentMoE、Hybrid Attention 中的 Gated MLA 層，以及原生視覺編碼器 MoonViT-V2。這些組件分別強化序列長度、網路深度與模型寬度三個維度的資訊流動，並透過精煉的訓練與資料配方達成約 2.5 倍的整體擴展效率提升。

**Q5：Kimi Delta Attention（KDA）的關鍵創新與設計動機是什麼？**

A：KDA 在 delta-rule 遞迴的基礎上加入通道級遺忘閘門，使其能夠以較低成本進行長序列 token 混合，同時保留足夠的注意力容量。為了彌補線性注意力可能損失的全域互動，Kimi K3 採用 3:1 的 KDA 與 Gated MLA 混合比例，每個區塊包含三層 KDA 後接一層 Gated MLA。此外，團隊針對 KDA 進行演算法與系統協同設計，包括融合核心、KDA 上下文平行與狀態感知前綴快取，以提升訓練與推論效率。

**Q6：Stable LatentMoE 的設計選擇如何支撐極度稀疏的專家路由？**

A：Stable LatentMoE 將路由專家空間擴大到 896 個，但每個 token 只啟動 16 個，並透過正規化、SiTU-GLU 與分位數平衡等技術來穩定極度稀疏下的優化。這種設計讓模型在不線性增加計算成本的前提下，大幅提升通道混合容量與參數效率。為了支援 2.8 兆參數規模的訓練，MoonEP 提供完美平衡的專家平行執行、靜態計算形狀與零複製通訊，確保大規模稀疏訓練的穩定性與記憶體效率。

**Q7：Kimi K3 在哪些基準測試與任務上進行評估？**

A：Kimi K3 的評估涵蓋長程程式設計、代理式任務、知識任務、推理任務與視覺任務等多個領域。測試對象包括其他開源模型與專有模型，其中特別提到 Claude Fable 5 與 GPT-5.6 Sol 這兩個最強的專有系統。這些評估旨在檢驗模型在複雜、長上下文且需要多步推理與工具使用情境下的綜合能力。

**Q8：Kimi K3 的關鍵實驗結果是什麼？**

A：Kimi K3 在整體表現上僅次於 Claude Fable 5 與 GPT-5.6 Sol，但在論文評估套件中持續優於其他開源與專有模型。相較於 Kimi K2，Kimi K3 透過架構與訓練改進達到約 2.5 倍的整體擴展效率提升。此外，它成功支援百萬 token 的上下文長度，並能在長程代理式強化學習中進行數百到數千次工具呼叫。

**Q9：關於 Kimi K3 的效率與消融分析，我們能從文中得知什麼？**

A：文中指出 KDA、AttnRes、Stable LatentMoE 與精煉資料配方共同帶來相對於 Kimi K2 約 2.5 倍的整體擴展效率提升，但具體的逐項消融數據在提供的摘要與前言片段中並未詳列。這項效率指標應理解為在模型品質與計算或參數成本之間的綜合權衡結果。未來完整技術報告可能會公布更細緻的消融實驗，以說明各項架構貢獻的比重。

**Q10：Kimi K3 適合哪些實際應用場景？**

A：Kimi K3 特別適合需要長程規劃與大量工具互動的場景，例如軟體工程、GPU 核心最佳化、網頁開發、可驗證搜尋與專業知識工作。其原生視覺能力與視覺在環工具使用也讓它能處理多模態推理任務，例如根據圖片或影片內容進行分析與操作。百萬 token 上下文則支援持久化助理工作流程，讓模型在長時間互動中維持狀態並累積數百萬個上下文 token。

**Q11：在產品化與部署層面，Kimi K3 有哪些關鍵基礎設施創新？**

A：為了讓 2.8 兆參數與百萬 token 上下文能夠實際運作，團隊發展了多項基礎設施創新，包括 KDA 的演算法與系統協同設計、MoonEP 的完美平衡專家平行訓練，以及記憶體高效訓練與多模態編碼器最佳化。在代理式強化學習方面，採用共置系統結合部分 rollout、外部 KV 快取保留、適應性節流與可恢復的微虛擬機沙盒，以維護長期模型與環境狀態。部署階段則透過專用核心與快取及預算感知的叢集排程，將這些創新轉化為可預測的生產級服務。

**Q12：Kimi K3 對開源人工智慧領域可能帶來什麼影響？**

A：Kimi K3 公開釋出完整的 2.8 兆參數模型權重，使研究人員與開發者能夠直接接觸過去僅屬於閉源前沿系統的規模與能力。它將開源模型的預訓練規模從 1 兆級推進到 3 兆級，並整合長上下文代理式強化學習，為後續研究提供新的基礎。這不僅有助於加速前沿智慧的廣泛部署與創新，也可能促進更多針對長程推理、多模態代理與大規模稀疏架構的後續研究。

5. **多努力等級推理的互動式問答與決策支援**  
   根據問題難度動態調整推理努力等級，Kimi K3 可用於教育輔導、醫療決策輔助、金融風險評估等場景，讓使用者在「快速回應」與「深度驗證」之間取得平衡。

- **資料準備**

- **技術能力**  
  團隊應熟悉大型語言模型推論優化、MoE 架構、分散式訓練、強化學習流程（RLHF / RL for reasoning）、容器化沙盒（microVM sandbox）以及工具使用框架（如 LangChain、MCP 或自研 agent 框架）。

- **基礎建設**  
  需要支援長上下文快取、狀態恢復、請求調度與安全隔離的推論服務平台。若使用 Kimi K3 進行代理式任務，建議建立可觀察、可中斷、可審計的執行環境。

### 實作步驟建議

1. **環境建置與模型載入**  
   取得 Kimi K3 模型權重後，依官方推論框架或 vLLM / SGLang 等相容引擎設定多節點部署。確認 KDA、Stable LatentMoE 與 AttnRes 的對應 kernel 與平行策略已正確載入，並啟用 prefix caching 以加速長上下文請求。

2. **建立評估基線**  
   在目標任務上先以零樣本（zero-shot）或少樣本（few-shot）方式測試模型表現，記錄不同推理努力等級下的準確率、延遲與成本，作為後續優化的基準。

3. **設計工具與沙盒介面**  
   為代理式應用定義清晰的工具描述、輸入輸出格式與錯誤處理機制。搭配可恢復的沙盒環境，讓模型能在長期任務中安全地執行程式碼、查詢資料庫或操作瀏覽器。

4. **領域適應與後訓練（選用）**  
   若基線不足，可收集領域資料進行監督式微調（SFT），再進一步使用可驗證獎勵進行強化學習。對於程式設計任務，建議使用單元測試或編譯結果作為獎勵訊號；對於知識工作，則可採用人工或規則式驗證。

5. **多教師蒸餾與統一化**  
   若針對不同領域或努力等級訓練了多個專精策略，可參考論文中的多教師 on-policy 蒸餾方法，將能力整合到單一模型，簡化部署並維持泛化能力。

6. **部署與監控**  
   上線後持續監控長上下文命中率、KV cache 使用量、工具呼叫成功率與輸出品質。建立回饋迴路，定期將高價值失敗案例納入再訓練資料。

### 潛在風險與注意事項

- **幻覺與長上下文遺忘**  
  即使支援百萬 token，模型仍可能在極長文件中遺漏細節或產生不一致資訊。建議將長文件分段索引、搭配檢索增強生成（RAG），並要求模型在回應中引用來源位置。

- **工具使用安全性**  
  代理式任務可能執行外部程式碼或操作敏感系統。務必在隔離沙盒中運行、限制網路與檔案系統權限，並對所有工具呼叫進行日誌記錄與人工覆核閘門。

- **成本與延遲**  
  2.8T 參數模型與 1M 上下文的推論成本高昂。應根據任務難度選擇適當的推理努力等級，並利用快取、批次處理與彈性調度來控制開支。

- **領域偏誤與資料隱私**  
  微調資料中的偏誤可能放大為系統性錯誤。同時，長上下文可能包含個人隱私或商業機密，需落實資料去識別化、存取控制與合規審查。

- **過度依賴自動化**  
  Kimi K3 雖具備長程執行能力，但關鍵決策仍應保留人工監督。特別是在醫療、法律與金融等高風險領域，模型輸出應作為輔助而非最終判斷。
