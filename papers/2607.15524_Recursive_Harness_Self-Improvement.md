## 摘要翻譯

在模型與 harness 共同演化（model--harness co-evolution）的框架下，harness 不僅是推論時間支架（inference-time scaffold），更是資料生成元件（data-generating component），其執行軌跡（execution trace）可形塑未來的基礎模型（foundation model）。這催生了 harness 在環學習（harness-in-the-loop learning）：同時最佳化 harness，以提升當下的代理程式效能（agent performance），以及未來模型訓練所用執行軌跡的品質。然而，持續更新提供者建構的支架（provider-built scaffold）既昂貴又耗費人力。因此，我們探討是否能以任務特定方式最佳化使用者建構的 harness（user-constructed harness），在保持運算輕量且僅需少數更新迭代（update iteration）的前提下，提升執行軌跡品質。為此，我們提出遞迴式 Harness 自我改進（Recursive Harness Self-Improvement, RHI），將 harness 表示為代理程式迴圈（agent loop）的提示詞層級規格（prompt-level specification），並依據其自身的修訂歷史（revision history），透過成對回饋（pairwise feedback）迭代地精煉該 harness。橫跨量化金融（quantitative finance）、機器人學（robotics）與藥學（pharmacy）等 30 項合成機器學習研究任務（synthetic machine-learning research task），僅需少數 RHI 迭代，即可顯著提升低推理努力代理程式（low-reasoning-effort agent）的效能上限（performance ceiling），超越相應的最大推理努力設定（maximum-reasoning-effort setting），同時將推論成本（inference cost）降低多達 60%。我們發現，這些增益主要源於透過更有效的代理程式間資訊流動（inter-agent information flow）所改善的任務特定上下文管理（task-specific context management），而非更長的推理軌跡（reasoning trace）。最後，我們將此行為形式化為關於 RHI 隱含最佳化目標（implicit optimization objective）的資訊理論假說（information-theoretic hypothesis），並指出 RHI 可作為模型與 harness 共同演化典範中持續學習（continual learning）的實用演算法。

### 核心貢獻（3～5點）
- 提出遞迴式 Harness 自我改進（RHI）方法，將 harness 視為提示詞層級規格，並利用成對回饋與修訂歷史迭代精煉，使使用者能針對特定任務最佳化 harness。
- 在 30 項跨領域（量化金融、機器人學、藥學）合成機器學習研究任務上驗證，少數 RHI 迭代即可顯著提升低推理努力代理程式的效能上限，甚至超越最大推理努力基線。
- 顯著降低推論成本（最多 60%），並證明效能增益主要來自更有效的代理程式間資訊流動與任務特定上下文管理，而非更長的推理軌跡。
- 將 RHI 的行為形式化為資訊理論假說，闡明其隱含最佳化目標，並定位 RHI 為模型與 harness 共同演化典範中的持續學習實用演算法。

### 適合對象
適合對基礎模型與外圍工具架構共同演化、LLM 代理程式提示詞工程、測試時間擴展與推論成本最佳化，以及持續學習感興趣的研究人員與工程師。特別適合希望以輕量、任務特定方式提升代理程式效能並產生高品質訓練軌跡的實務工作者。

## 深度分析

#### 方法論解析

本研究提出的核心方法為 **Recursive Harness Self-Improvement（遞迴式 Harness 自我改進，RHI）**，其目標是在固定基礎模型（foundation model）的前提下，透過輕量化的迭代方式最佳化使用者自行建構的 harness（工具架構／框架），以提升代理程式（agent）的即時效能，同時產生更高品質的執行軌跡（execution trace），供未來的模型訓練使用。

##### 問題設定與 harness 的重新定位

傳統上，harness 被視為推論時間支架（inference-time scaffold），用於組織多代理程式工作流程。然而，在模型與 harness 共同演化（model--harness co-evolution）的觀點下，harness 同時也是資料生成元件（data-generating component）：其執行過程產生的軌跡可成為未來基礎模型的訓練資料。因此，最佳化 harness 不僅是為了當前任務表現，也涉及 harness 在環學習（harness-in-the-loop learning）的長期資料品質。相較於提供者建構的支架（provider-built scaffold）必須泛化到多樣任務、難以頻繁更新，使用者建構的 harness（user-constructed harness）可以針對單一任務特化，成為輕量且實用的最佳化對象。

##### Harness 的提示詞層級規格

RHI 將 harness 定義為代理程式迴圈（agent loop）的提示詞層級規格（prompt-level specification），而非可執行程式碼。具體而言，harness 由四個互動因素組成：

- **Roles（角色）與 Instructions（指令）**：決定任務分配與各代理程式的行為準則。
- **Contracts（通訊契約）**：規範代理程式間資訊流動（inter-agent information flow）的格式與內容。
- **Hops（跳躍／控制流程）**：決定協調器（orchestrator）與子代理程式（subagent）何時啟動推理、何時交接控制權。

這樣的表示法使 harness 成為可直接被大型語言模型讀取、修改與評估的自然語言物件，避免了程式碼層級最佳化所需的安全沙箱、執行環境與語法檢查等高昂成本。

##### RHI 的迭代機制

RHI 的關鍵設計在於以**軌跡區域自我比較（trajectory-local self-comparison）**取代昂貴的群體層級搜尋。演算法流程可概括如下：

1. 初始化一個針對任務設計的 harness。
2. 在每次更新迭代（update iteration）中，讓當前 harness 與其前一個版本進行成對比較（pairwise feedback）。
3. 根據比較結果與修訂歷史（revision history）中的偏好訊號，產生下一版 harness。
4. 重複少數幾次迭代後，固定 harness 並用於後續推理。

這種「只與前一版比較」的策略大幅降低了每次更新的計算負擔，也使得整個過程能在少數幾次迭代內收斂。相較於需要維護大量候選 harness 的演化式搜尋或強化學習方法，RHI 更適合資源有限的使用者場景。

##### 隱含最佳化目標的資訊理論假說

作者進一步將觀察到的學習動態形式化為一個資訊理論假說（information-theoretic hypothesis）。他們推論 RHI 實際上在隱含最佳化目標（implicit optimization objective）：

- 增加每個 harness 元件與任務之間的互資訊（mutual information），即提升元件中任務相關資訊的含量（以 \(f_{\text{ext}}\) 表示）。
- 減少不同元件之間的重複資訊，即降低內部冗餘（以 \(f_{\text{int}}\) 表示）。

換句話說，RHI 並非單純讓代理程式產生更長的推理軌跡（reasoning trace），而是重新組織 harness 內部的資訊流動，使角色、指令、契約與控制流程更緊密地對齊任務需求，並減少不必要的重複溝通。這也解釋了為何 RHI 能在輸出權杖使用量（output-token usage）幾乎不變的情況下提升效能。

#### 實驗數據解讀

本研究在 **30 個合成機器學習研究任務（synthetic machine-learning research task）**上進行評估，任務橫跨量化金融（quantitative finance）、機器人學（robotics）與藥學（pharmacy）三個領域。每個任務都要求代理程式產生一個完整的程式碼倉庫與標準化交付物，並透過 **LLM 作為評審的評估（LLM-as-a-judge evaluation）**進行成對比較。

##### 主要實驗發現

研究提出三項核心主張：

**Claim 1：少樣本 RHI（few-shot RHI）提升測試時間擴展（test-time scaling）的效能上限（performance ceiling）**

實驗結果顯示，在 sonnet-4.6、opus-4.7 與 opus-4.8 等模型上，僅需少數幾次 RHI 迭代，就能讓低推理努力代理程式（low-reasoning-effort agent）的表現超過最大推理努力設定（maximum-reasoning-effort setting），包括 `xhigh`、`max` 與 `ultracode` 等更強的測試時間擴展基線。更值得注意地是，這些增益會隨著基礎模型變強而持續存在，顯示 harness 最佳化與模型規模提升具有互補性，而非僅是彌補弱模型的不足。

**Claim 2：效能增益無法用輸出權杖增加來解釋**

在 RHI 迭代過程中，輸出權杖使用量幾乎維持不變，但任務表現持續上升。這與許多測試時間擴展方法（例如更長的 chain-of-thought 或更多推理步驟）形成對比，說明 RHI 的進步並非來自「讓模型想得更久」，而是來自 harness 結構本身的改善。

**Claim 3：RHI 透過降低快取讀寫使用量（cache read/write usage）提升成本效率**

對於 opus-4.8，RHI 相較於 `ultracode` 基線可減少高達 **60%** 的推論成本（inference cost）。這主要歸因於 harness 學會更有效的任務特定上下文管理（task-specific context management）：代理程式間的資訊傳遞變得更精簡，重複載入上下文的次數減少，因此快取讀寫開銷隨之下降。

##### 消融研究（Ablation Study）的啟示

- **對訓練時間擴展（train-time scaling）的影響**：RHI 不僅提升測試時間表現，也能提高訓練時間擴展的效能高原（performance plateau）。這呼應了模型與 harness 共同演化的核心論點：更好的 harness 產生更高品質的執行軌跡，進而成為未來基礎模型更有效的訓練資料。

- **哪些 harness 因素（harness factor）驅動增益？**：完整 harness 演化（full-harness evolution）通常優於僅針對單一元件的 harness 元件演化（harness-component evolution）。進一步分析顯示，**contracts** 與 **hops** 是兩個最關鍵的因素：通訊契約變得更任務特定，控制流程更精準地決定何時該進行推理。相對地，roles 與 instructions 提供基礎結構，但其單獨演化的邊際效益較低。

- **隱含目標的實證證據**：作者觀察到隨著 RHI 迭代進行，外部資訊量指標 \(f_{\text{ext}}\) 上升，而內部冗餘指標 \(f_{\text{int}}\) 下降。這與資訊理論假說一致，支持 RHI 確實在隱含地重新組織 harness 內的資訊結構。

#### 與現有研究的比較

##### 相對於傳統擴展範式

過去的 AI 擴展進展主要歸因於更大的模型（Kaplan et al., 2020）、更多的訓練計算量（training compute）（Hoffmann et al., 2022）以及更好的訓練後處理（post-training）（Guo et al., 2025）。近年則興起測試時間擴展（Wang et al., 2025a），透過在推理階段增加計算來提升表現。RHI 與這些方法不同：它將效能提升的來源從「模型本身」或「更多推理計算」轉移到「harness 結構的最佳化」，並且強調 harness 與基礎模型之間的共演關係。

##### 相對於提供者建構與使用者建構的 Harness

現代編碼代理程式通常結合兩種 harness 來源：提供者建構的通用 harness（如 Anthropic、Google、LangChain、OpenAI 的框架）以及使用者針對任務設計的專用 workflow、skills 與子代理程式。前者的缺點在於必須泛化到廣泛使用者與任務，持續更新成本高昂；後者雖具任務專一性，但過去多依賴人工設計。RHI 填補了這中間的缺口：它自動化、輕量化地最佳化使用者建構的 harness，使其在少數迭代內達到接近甚至超越高推理努力設定的表現。

##### 相對於自動提示工程與程式搜尋

自動提示工程（如 OPRO、DSPy）主要聚焦於單一提示或少量提示模板的最佳化。RHI 則在更高層次運作：它同時最佳化多代理程式的角色分配、通訊契約與控制流程。此外，許多 harness 或 workflow 最佳化方法採用群體層級搜尋、強化學習或神經符號程式合成，這些方法通常需要大量評估與複雜執行環境。RHI 以成對回饋與修訂歷史為基礎的區域搜尋，顯著降低了計算與工程門檻。

##### 限制與潛在弱點

儘管 RHI 展現出強勁的實證結果，仍存在若干限制：

1. **任務範圍局限於合成任務**：30 個任務雖涵蓋多個領域，但仍為人工設計的開放式 ML 研究問題，與真實世界軟體工程或科學研究的複雜度仍有差距。
2. **評估依賴 LLM-as-a-judge**：成對比較由語言模型執行，可能受到輸出長度、風格或表面結構的偏誤影響，儘管作者已觀察到輸出權杖並未增加。
3. **僅限提示詞層級 harness**：RHI 不修改底層工具程式碼、檢索機制或狀態機，這限制了它在需要深層系統整合場景中的應用。
4. **區域比較可能陷入區域最佳解**：每次只與前一版比較，可能錯過需要較大結構變更才能達到的全局最佳解。
5. **對基礎模型批判能力的依賴**：harness 的修訂品質取決於模型是否能正確評估兩版 harness 的優劣，弱模型可能產生無效或錯誤的更新方向。
6. **缺乏真實部署軌跡的驗證**：研究聚焦於第一半的共同演化迴路（提升 harness 軌跡品質），但尚未將這些軌跡實際用於訓練下一代模型並驗證效果。

#### 可重現性評估

##### 開放資源現況

根據目前提供的論文內容，**並未明確提及公開原始碼、資料集或模型權重**。附錄中雖包含 harness 範例（Appendix B）、harness 最佳化提示詞（Appendix C）、任務範例（Appendix D）以及評審提示詞（Appendix E），但完整的任務產生器、評估流程、成本正規化（normalized cost）公式與原始修訂軌跡是否釋出，仍不得而知。

##### 模型與環境依賴

實驗使用的 sonnet-4.6、opus-4.7 與 opus-4.8 均為專有模型，必須透過 API 存取。這帶來兩個可重現性挑戰：

- **模型版本漂移**：API 背後的模型可能隨時間更新，即使名稱相同，行為也可能略有差異。
- **成本與快取指標綁定特定服務**：推論成本與 cache read/write usage 的計算依賴特定供應商的計價模型，其他環境難以直接複製。

##### 可重現性程度

- **方法論層面**：可重現性為中等到高。核心演算法描述清楚，harness 表示法與最佳化提示詞在附錄中有詳細範例，具備足夠資訊讓研究者重新實作。
- **實證層面**：可重現性為中等到低。缺乏公開的程式碼倉庫與完整任務資料，使得精確復現數據變得困難；此外，專有模型與 API 計價機制也提高了門檻。

##### 提升可重現性的建議

為了增強本研究的可重現性，建議作者釋出：

1. 完整的任務模板與程式碼倉庫 scaffold。
2. Harness 最佳化器與 LLM-as-a-judge 評估流程的開源實作。
3. 所有模型的版本資訊、API 參數與成本正規化方法。
4. RHI 迭代過程中產生的修訂歷史與成對比較紀錄。
5. 若無法公開模型權重，至少提供可與開源模型（如 Llama、Qwen）對照的補充實驗。

#### 未來研究方向

##### 1. 擴展到真實世界開放式任務

未來可在真實軟體工程、科學研究或企業自動化場景中驗證 RHI，並引入人類評審與執行導向指標（如單元測試通過率、執行正確性），以降低 LLM-as-a-judge 的偏誤。

##### 2. 結合提供者建構與使用者建構的 Harness

研究可探討如何將 RHI 應用於提供者建構的通用 harness，或設計一個「通用 harness + 任務特定 RHI 適配層」的混合架構，兼顧泛化能力與專一效能。

##### 3. 理論收斂與擴展法則

目前 RHI 的收斂性與隱含目標仍屬假說。未來可建立更嚴謹的理論框架，分析區域成對比較的收斂條件，並研究 harness 最佳化與測試時間計算、訓練時間計算之間的權衡關係，形成類似「harness scaling laws」的理論。

##### 4. 多目標與持續學習（Continual Learning）

RHI 目前主要最佳化單任務效能與軌跡品質。未來可將其擴展為多目標最佳化，同時考量效能、推論成本、軌跡多樣性與可解釋性。此外，可將 RHI 整合進持續學習迴路：利用 RHI 產生的高品質軌跡重新訓練基礎模型，再於新模型上重新執行 RHI，觀察共同演化是否產生湧現能力。

##### 5. 跨任務遷移與元學習

目前 RHI 針對每個任務獨立執行。未來可研究元 harness 最佳化器（meta-harness optimizer），讓模型從多個任務的修訂歷史中學習，從而在新任務上以更少迭代達到良好表現。

##### 6. 程式碼層級 Harness 最佳化

將 RHI 從提示詞層級擴展到程式碼層級，包括工具定義、檢索架構、狀態機與錯誤處理邏輯。這將使 RHI 能處理需要深層系統整合的複雜任務，但也會帶來安全性與執行環境的挑戰。

##### 7. 安全性、可解釋性與審計

隨著 harness 能夠自我修改，必須建立機制防止獎勵駭取（reward hacking）、隱藏目標或不安全的工具使用。未來研究可聚焦於修訂歷史的可解釋性、變更影響評估，以及人機協同的 harness 審查流程。

## 論文問答

**Q1：在模型與 harness 共同演化的背景下，本文試圖解決什麼核心問題？**

A：本文聚焦於「執行軌跡品質」這個瓶頸，因為在模型與 harness 共同演化的範式中，harness 產生的執行軌跡會成為未來基礎模型的訓練資料，軌跡品質直接影響後續模型的能力上限。然而，對於固定的基礎模型，如何提升 harness 以產生更高品質的執行軌跡，仍缺乏輕量且可擴展的方法。因此，作者探討如何在僅需少數更新迭代、計算成本低廉的前提下，最佳化使用者自行建構的 harness，以突破代理程式測試時間擴展的效能高原。

**Q2：為何單靠提供者建構的支架或單純增加推理努力，無法充分解決這個問題？**

A：提供者建構的支架必須通用於多樣化的使用者與任務，持續更新這類支架在人力與成本上都非常昂貴，難以針對個別任務快速調整。另一方面，單純提高推理努力（例如使用 max 或 ultracode 設定）只是增加推論階段的計算量，並未重新組織代理程式間的資訊流動與工作流程結構。本文實驗顯示，經過少樣本 RHI 最佳化的低推理努力代理程式，反而能超越最大推理努力設定的表現，同時降低推論成本，這說明結構化的 harness 改進比單純堆疊推理更有效。

**Q3：為什麼「輕量且只需少數迭代」的 harness 最佳化在實務上如此重要？**

A：在實際應用中，使用者需要針對大量開放式任務快速客製化代理程式，若每次最佳化都需要大量計算或長時間迭代，將難以規模化。RHI 只需少數幾次更新迭代即可顯著提升效能，使得每個任務都能在有限預算內完成專門化。此外，這種輕量特性讓 harness 在環學習成為可行，有助於持續累積高品質執行軌跡，推動模型與 harness 的長期共同演化。

**Q4：什麼是 Recursive Harness Self-Improvement（RHI）？其核心運作方式是什麼？**

A：RHI 是本文提出的遞迴式 harness 自我改進方法，它將 harness 視為代理程式迴圈的提示詞層級規格，包含角色分配、指令、代理程式間的溝通契約（contracts），以及決定控制流程的推理跳點（hops）。在每次迭代中，RHI 會將當前 harness 與其前一個版本進行成對比較，並根據比較結果產生的偏好回饋來指導下一次修訂。這種基於自身修訂歷史的軌跡局部自我比較，取代了昂貴的族群級 harness 搜尋，使整個過程既輕量又高效。

**Q5：RHI 相較於現有的 harness 搜尋或程式碼層級最佳化方法，關鍵創新在哪裡？**

A：RHI 的關鍵創新在於將 harness 視為可透過自然語言提示詞直接操作的物件，而非需要重新編譯或部署的執行程式碼。它利用成對回饋與修訂歷史進行遞迴式自我改進，避免了對大量候選 harness 進行全面評估的高昂成本。這種設計讓使用者能夠在固定基礎模型上，以極少的迭代次數針對特定任務調整 harness，實現計算輕量且收斂迅速的任務特定最佳化。

**Q6：RHI 為何選擇以角色、契約與跳點來定義 harness？這樣的設計帶來什麼好處？**

A：角色與指令負責定義任務分配，契約規範代理程式間的資訊交換格式與內容，跳點則決定協調器與子代理程式工作流程中的控制流程。這種拆解讓 RHI 能夠精確地改善任務特定的上下文管理，特別是代理程式間的資訊流動，而不是單純拉長推理軌跡。實驗結果也支持這一點：RHI 帶來的效能提升主要來自更有效率的溝通契約與工作流程跳點，而非增加輸出權杖數量。

**Q7：本文使用什麼樣的評測任務與評估方式來驗證 RHI？**

A：本文在 30 個合成機器學習研究任務上進行評估，這些任務橫跨量化金融、機器人學與藥學三個領域，每個任務都要求生成包含標準化交付物的完整程式碼倉儲。輸出品質透過 LLM 作為評審的成對比較來判定，這種方式能夠處理開放式、難以用單一數值衡量的研究型任務。該評估設計強調真實世界中複雜任務的完成度，而非僅限於選擇題或簡短問答的正確率。

**Q8：RHI 在實驗中取得了哪些關鍵效能與成本結果？**

A：實驗顯示，少樣本 RHI 應用於高推理努力代理程式時，在 sonnet-4.6、opus-4.7 與 opus-4.8 上都能勝過 xhigh、max 與 ultracode 等更強的測試時間擴展設定。特別是在 opus-4.8 上，RHI 相較於 ultracode 基線可降低高達 60% 的推論成本，同時達到更高的效能水準。這些增益隨著基礎模型變強而持續存在，顯示 RHI 能夠有效提升代理程式的效能上限，而非僅限於較弱模型。

**Q9：消融研究指出 RHI 的效能提升主要來自什麼機制？**

A：消融研究發現，RHI 的增益並非來自更長的輸出軌跡，因為隨著迭代進行，輸出權杖使用量幾乎維持不變，但效能卻持續提升。相反地，這些提升主要來自改善的任務特定上下文管理，包括更精準的代理程式間溝通契約、更有效率的工作流程跳點，以及減少 harness 元件間的冗餘資訊。這表示 RHI 實際上是在重新組織 harness 內部的資訊流動，使每個元件攜帶更多與任務相關的資訊，而非單紀增加計算量。

**Q10：RHI 最適合應用在哪些實務場景？**

A：RHI 特別適合需要使用者針對特定任務自行設計 harness 的場景，例如研究自動化、程式碼生成代理、多代理協作流程，以及需要標準化交付物的專業領域如量化金融、機器人學與藥學。由於它只需少數迭代即可收斂，使用者可以快速為大量開放式任務建立專門化的代理程式工作流程。此外，RHI 也可作為現有提供者建構支架之上的輕量層，進一步針對個人化需求進行微調。

**Q11：若要将 RHI 整合到現有的 AI 產品或平台中，需要考慮哪些因素？**

A：首先，RHI 以提示詞層級規格操作 harness，因此可以無縫疊加在現有提供者建構的支架之上，無需修改底層程式碼或基礎模型。其次，平台需要提供成對回饋機制，讓系統能比較 harness 的相鄰版本並累積修訂歷史。最後，由於 RHI 強調輕量與少數迭代，產品設計上應控制每次更新的計算成本，並讓使用者在有限預算內看到明確的效能提升。

**Q12：RHI 對模型與 harness 共同演化這個研究領域可能帶來什麼影響？**

A：RHI 具體展示了共同演化迴路的前半段：在固定基礎模型下，透過最佳化 harness 來產生更高品質的執行軌跡，這些軌跡未來可用於訓練更強大的基礎模型。作者進一步將 RHI 的學習動態形式化為資訊理論假說，提出其隱含最佳化目標可能是提升各 harness 元件與任務間的互資訊，同時抑制冗餘。這不僅為 harness 在環學習提供了理論直覺，也讓 RHI 成為持續學習範式中一個實用且可解釋的演算法。

**Q13：本文有哪些已知的限制或適用範圍上的提醒？**

A：本文的實驗主要使用合成機器學習研究任務，雖然涵蓋多個領域，但與真實世界中更混亂、需求更動態的任務仍有差距。此外，評估採用 LLM 作為評審，可能存在模型偏好或評判偏差，特別是在衡量創意性與研究品質時。最後，RHI 目前聚焦於提示詞層級的 harness 規格，對於需要深層程式碼或系統架構變更的場景，其適用性可能有限。

**Q14：在什麼情況下 RHI 可能無法帶來預期的改善？**

A：如果初始 harness 與任務需求差距過大，或者基礎模型本身不具備完成任務所需的核心能力，那麼即使經過 RHI 迭代也難以彌補根本能力不足。此外，当成對回饋存在雜訊或評審標準不一致時，修訂歷史可能導向錯誤方向，降低最佳化效果。最後，對於某些資訊流動無法透過現有角色、契約與跳點結構充分表達的任務，RHI 的提示詞層級設計可能會遇到表達能力上的瓶頸。

**Q15：未來研究可以朝哪些方向延伸 RHI 的貢獻？**

A：未來可以將 RHI 應用到真實世界的開放式任務上，驗證其在更複雜、動態環境中的泛化能力與穩定性。另一個方向是將 RHI 與提供者建構支架的更新機制結合，讓使用者層級與平台層級的 harness 改進能夠相互回饋。此外，可以進一步以資訊理論假說為基礎，設計更明確的目標函式，並將 RHI 產生的高品質執行軌跡實際用於訓練下一代基礎模型，從而完整實現模型與 harness 的遞迴共同演化。

## 實務應用指南

### 適用場景

1. **量化交易策略研發**  
   在量化金融團隊中，研究員經常需要反覆生成、回測與調整交易策略程式碼。RHI 可把「資料清理 → 特徵工程 → 模型建構 → 回測報告」的代理程式迴圈視為一個 harness，透過少數幾次迭代優化角色分工與資訊傳遞契約，讓低推理努力設定產出接近甚至超越最高推理努力基線的策略程式碼，同時降低 API 成本。

2. **機器人學模擬與實驗程式碼生成**  
   機器人研究任務通常涉及感測器資料處理、控制演算法與模擬環境整合。RHI 能針對特定機器人平台（如 ROS、Isaac Sim）調整 harness 的 workflow hops 與子代理溝通契約，使代理在有限推理預算下產出更高品質的執行軌跡，並減少快取讀寫開銷。

3. **藥物發現與生醫資料分析管線**  
   藥學研究需要整合文獻檢索、分子資料處理、統計分析與報告撰寫。RHI 可將這些步驟封裝成 prompt-level harness，透過成對回饋精煉各子代理間的資訊流，提升任務特定上下文管理，讓低階模型也能產出符合領域規範的研究交付物。

4. **企業內部程式碼遷移與自動化腳本開發**  
   當企業需要將舊系統（如 COBOL、舊版 Python）遷移至新架構，或批量產生自動化腳本時，RHI 可在使用者自建的 harness 上快速迭代，優化「解析 → 重構 → 驗證 → 文件化」的代理流程，減少對高推理成本設定的依賴。

5. **法律／財務文件生成與審查輔助**  
   對於需要高度領域知識的文件工作（如合約初稿、財務報告附註），RHI 能針對特定文件類型調整 harness，強化代理間的資訊流動與上下文保留，在維持輸出品質的同時降低推論成本。

### 實作前置條件

| 類別 | 需求說明 |
|---|---|
| **模型與 API** | 可調用不同 reasoning effort 設定的基礎模型 API（如 Claude Sonnet/Opus、OpenAI o 系列或 GPT-Codex），並能取得執行軌跡、輸出 token 數、快取讀寫量與成本資料。 |
| **初始 Harness** | 一份 prompt-level 的代理程式迴圈規格，至少包含角色（roles）、指令（instructions）、代理間契約（contracts）與控制流程 hops。 |
| **任務資料與評估基準** | 20–30 個具代表性的任務實例，並定義標準化交付物；需準備 LLM-as-a-judge 的評審提示詞或人工評分機制，以產生成對回饋。 |
| **成對比較機制** | 能穩定比較「當前 harness」與「前一版 harness」產出的執行軌跡，並記錄 revision history。 |
| **運算與成本預算** | 雖然 RHI 強調輕量，但仍需預留數輪迭代的 API 費用；建議設定每輪成本上限與快取使用監控。 |
| **團隊技能** | 提示詞工程、代理系統編排、領域專業知識，以及基礎的評估指標設計與資料分析能力。 |

### 實作步驟建議

1. **將現有工作流程封裝為 Harness**  
   把目前的代理程式迴圈寫成一份 prompt-level 規格，明確定義 orchestrator、子代理角色、每個角色的指令、代理間傳遞的資訊契約，以及何時觸發推理的 hops。

2. **建立低推理努力基線**  
   使用低 reasoning effort 設定（如 `low` 或 `medium`）執行初始 harness，記錄效能、輸出 token 數、快取讀寫量與推論成本，作為後續比較基準。

3. **設計成對評審機制**  
   準備一個 LLM-as-a-judge 提示詞，針對任務交付物進行 pairwise 比較；評分維度可包含正確性、完整性、可維護性與領域合規性。

4. **執行第一輪 RHI 迭代**  
   將當前 harness 與其直接前版進行比較，根據成對回饋產生下一版 harness。建議使用論文附錄中的 harness optimizer prompt 風格，要求優化器具體說明修改了哪些角色、契約或 hops。

5. **監控迭代過程中的指標**  
   每輪記錄 win rate、輸出 token 使用量、快取讀寫量與正規化成本。若發現效能提升但成本飆升，應檢視是否來自冗餘資訊流，而非有效的上下文管理。

6. **限制迭代次數並驗證**  
   根據論文結果，少數幾次迭代（如 3–5 次）通常已足夠。達到目標 win rate 或成本降幅後，進行人工抽樣驗證，避免過度擬合評審模型。

7. **部署與持續更新**  
   將收斂後的 harness 部署到生產環境，並定期用新任務實例重新觸發 RHI，讓 harness 隨任務分佈漂移持續演進。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **過度擬合評審模型** | LLM-as-a-judge 的偏好可能與人類專家不一致，導致 harness 針對評審提示詞「鑽漏洞」。 | 引入人工抽樣驗證、使用多個評審模型、設計對抗性測試案例。 |
| **Prompt 不穩定** | 自動產生的 harness 可能在不同輸入上表現不一致，或出現格式錯誤。 | 建立 harness 版本控制、每輪執行語法與結構檢查、保留可回滾的穩定版本。 |
| **資訊流過度複雜化** | 為了提升效能，harness 可能加入過多 hops 或契約，反而增加維護難度。 | 定期進行消融研究，檢視哪些元件真正貢獻效能；遵循「最小有效 harness」原則。 |
| **成本與快取使用失控** | 雖然 RHI 通常降低成本，但不當的契約設計可能導致快取讀寫增加。 | 設定每輪與每任務成本上限，監控 cache read/write 佔比。 |
| **資料隱私與洩漏** | 執行軌跡可能包含敏感業務資料，未來若用於模型訓練需特別注意。 | 去識別化處理軌跡、限制 trace 儲存範圍、建立資料使用政策。 |
| **收斂不保證** | RHI 依賴成對回饋，某些任務可能出現震盪或收斂緩慢。 | 設定最大迭代次數、引入早停機制、必要時改採較穩定的全 harness 演化策略。 |

### 與其他技術的整合建議

- **與提供者內建 scaffold 搭配**：RHI 並非要取代 Claude Code、OpenAI Codex 或 LangChain 等提供者建構的支架，而是針對特定任務在使用者層級進行輕量特化。可將 RHI 視為「使用者 harness 層」，疊加在提供者 scaffold 之上。
- **整合 CI/CD 管線**：將 RHI 迭代納入持續整合流程，每次 harness 更新後自動執行標準化任務集，確保效能回歸不會發生。
- **結合 RAG 與向量資料庫**：對於需要大量領域知識的任務，可在 harness 的 contracts 中引入檢索增強生成（RAG），讓子代理透過向量資料庫取得最新上下文。
- **對接模型訓練資料管線**：RHI 產生的高品質執行軌跡可經過篩選與去識別化後，成為未來基礎模型微調或 post-training 的資料來源，實現模型與 harness 共同演化。
- **串接可觀測性工具**：使用 LangSmith、Weights & Biases 或自研監控系統追蹤每輪 RHI 的輸出 token、快取使用、成本與 pairwise win rate，便於診斷與優化。
