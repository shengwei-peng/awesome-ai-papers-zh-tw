## ⚡ TL;DR

現有語言世界模型專注預測高熵工具回饋，且歷史中未經證實的假設與過時計畫會污染後續決策。
本文提出AEWM，以動作判斷器區分決策類型，並透過狀態修訂改寫雜訊推理—動作延續後真實執行。

## 摘要翻譯

近期大型語言模型（large language models, LLM）的進展使智慧體（agents）得以在多元環境中處理長期任務（long-horizon tasks）。為了進一步提升智慧體表現，現有的語言世界模型（language world models）通常預測環境觀察（environment observations），但在可取得真實回饋（real feedback）的情況下，重建高熵（high-entropy）且執行相依的（execution-dependent）工具回應（tool responses）所能帶來的價值有限。與此同時，智慧體面臨任務狀態污染（task-state contamination）的問題：未經證實的假設（unsupported assumptions）與過時計畫（outdated plans）會留存於智慧體歷史紀錄（agent history）中，並扭曲後續決策（subsequent decisions）。我們提出智慧體編輯世界模型（Agent-Editing World Model, AEWM），其建模推理與動作（reasoning and actions）如何形塑未來任務的解決進度（solution progress），而非模擬工具回應。AEWM 結合動作判斷器（Action Judge）以區分關鍵決策（Critical decisions）、探索性決策（Exploratory decisions）與雜訊決策（Noisy decisions），並搭配狀態修訂（State Revision），從相同的觀察歷史紀錄（observed history）中編輯雜訊的推理–動作延續（reasoning–action continuation）。EditAct（EditAct）將這些能力與真實執行（real execution）整合，直接改變後續決策所依據的底層狀態（underlying state），而非僅提供批評（critiques）。我們在搜尋（Search）、終端機（Terminal）與軟體工程（Software Engineering）領域，透過中期訓練（mid-training）與監督式微調（supervised fine-tuning, SFT）訓練 AEWM。AEWM 在我們的動作判斷器基準測試（Action Judge benchmark）上達到 70.5% 的 macro-F1（macro-F1），超越最強前沿基線（strongest frontier baseline）10.6 分。橫跨六個基準測試（benchmarks）與三個智慧體骨幹模型（agent backbones），EditAct 相較最強基線（strongest baseline）提升平均分數（average scores）3.2–6.7 分。此外，以已驗證的 EditAct 軌跡（verified EditAct trajectories）進行拒絕採樣微調（rejection sampling fine-tuning, RFT），稱為 AEWM-RFT（AEWM-RFT），在三個領域中無需線上 AEWM 引導（online AEWM guidance），即可相較 Self-RFT（Self-RFT）提升 2.2–2.6 分。

### 核心貢獻（3～5點）
- 重新定位世界模型目標：提出智慧體編輯世界模型（AEWM），從模擬高熵、執行相依的工具回應，轉向建模推理與動作如何影響未來任務解決進度。
- 解決任務狀態污染：透過動作判斷器（Action Judge）區分關鍵、探索性與雜訊決策，並以狀態修訂（State Revision）從相同觀察歷史中編輯雜訊的推理–動作延續。
- 結合真實執行：提出 EditAct，將 AEWM 的判斷與修訂能力與真實執行整合，直接改變後續決策的底層狀態，而非僅提供後驗批評。
- 跨領域訓練與微調：在搜尋、終端機與軟體工程領域透過中期訓練與監督式微調訓練 AEWM，並提出 AEWM-RFT，以已驗證的 EditAct 軌跡進行拒絕採樣微調，無需線上 AEWM 引導即可持續提升表現。
- 顯著實證提升：在 Action Judge 基準測試、六個基準測試與三個智慧體骨幹模型上，分別帶來 10.6、3.2–6.7 與 2.2–2.6 分的平均分數提升，顯示方法的有效性与泛化性。

### 適合對象
對大型語言模型智慧體、世界模型、長期任務推理、工具使用與智慧體訓練（如 SFT/RFT）有興趣的研究者與工程師；特別適合關注搜尋、終端機、軟體工程等真實工具互動場景，以及希望透過狀態修訂與決策分類來減少歷史污染、提升多步驟決策品質的讀者。

## 深度分析

#### 方法論解析

##### 1. 問題重構：從觀察預測轉向智慧體狀態建模

傳統世界模型（world model）通常學習動作條件化下一狀態（action-conditioned next state）或動作條件化觀察預測（action-conditioned observation prediction），即在給定狀態與動作後預測環境觀察（environment observation）。這在具身人工智慧（embodied AI）或互動式影片生成（interactive video generation）中有效，因為觀察本身蘊含可學習的物理規律。然而，對於任務導向的大型語言模型智慧體（task-oriented LLM agent），工具回應（tool response）往往具有高熵（high-entropy）與執行相依（execution-dependent）特性：搜尋結果隨網頁內容與排名變動，終端機輸出（terminal output）與測試結果取決於檔案系統與執行時狀態。重建這些觀察不僅困難，且在真實回饋（grounded feedback）可取得時價值有限，甚至可能產生虛構證據（fabricated evidence）。

因此，本文提出 Agent-Editing World Model（智慧體編輯世界模型，AEWM），將世界模型的預測目標從「環境觀察重建」轉為「智慧體決策對未來任務進展的影響」。具體而言，AEWM 建模的是執行前狀態（pre-execution state）：

\[
s_t = h_t \oplus (\hat{r}_t, \hat{a}_t)
\]

其中 \(h_t\) 為智慧體歷史紀錄（agent history），包含任務、過往推理–動作配對（reasoning–action pair）與環境觀察；\((\hat{r}_t, \hat{a}_t)\) 為當前提議的推理與動作。AEWM 不預測 \(o_t\)，而是判斷並修正 \((\hat{r}_t, \hat{a}_t)\) 對後續任務狀態的影響。

##### 2. 核心能力一：Action Judge（動作判斷器）

Action Judge 將每個執行前的推理–動作延續（reasoning–action continuation）分為三類：

- **Critical decision（關鍵決策）**：預期能直接推進解決進度（solution progress），例如執行正確的程式碼修改、下達能取得關鍵資訊的搜尋指令。
- **Exploratory decision（探索性決策）**：不立即帶來進展，但能有效降低不確定性（uncertainty reduction），例如嘗試不同關鍵字的搜尋、列出目錄以確認檔案結構。
- **Noisy decision（雜訊決策）**：朝向無成效方向（unproductive direction），例如基於未經證實的假設（unsupported assumption）繼續搜尋、在缺少執行檢查（execution check）的情況下解讀終端機輸出、或堅持已被反駁的搜尋候選（contradicted search candidate）。

這種三分法比單純的「好／壞」二分更貼近長期任務的本質：探索性動作雖然短期無產出，但對後續決策具有資訊價值，不應被直接刪除；而雜訊決策則會污染智慧體歷史紀錄，需要被修正。

##### 3. 核心能力二：State Revision（狀態修訂）

對於被判斷為 Noisy 的決策，State Revision 並非僅產生一段批評文字，而是直接從當前狀態 \(s_t\) 生成替代性的推理–動作配對 \((\tilde{r}_t, \tilde{a}_t)\)，用以替換原有延續。這意味著 AEWM 直接改變後續決策所依賴的狀態，而非僅提供外部建議。這是與傳統自我反思（self-reflection）或批評生成（critique generation）的關鍵差異：後者通常讓智慧體在讀取批評後自行重新生成，容易受原有污染狀態影響；State Revision 則是對智慧體狀態進行編輯。

##### 4. 推論框架：EditAct（編輯與執行）

EditAct 將上述兩項能力與真實執行結合：

1. 智慧體根據歷史 \(h_t\) 生成初始推理–動作配對 \((\hat{r}_t, \hat{a}_t)\)。
2. Action Judge 對其分類：
   - Critical 或 Exploratory：保留原配對。
   - Noisy：觸發 State Revision，以 \((\tilde{r}_t, \tilde{a}_t)\) 替換。
3. 執行選定的動作於真實環境，取得真實回饋。
4. 將選定的推理–動作配對與實際觀察加入歷史，進入下一步。

此流程確保「有成效的決策（productive decision）」被執行，「雜訊決策」在進入歷史前即被修正，從而減緩任務狀態污染（task-state contamination）的累積。

##### 5. 訓練流程：兩階段與資料合成

AEWM 的訓練包含兩個階段：

- **中期訓練（mid-training）**：在 520 億 token 的互動資料上進行，旨在建立廣泛的互動知識（interaction knowledge）。
- **監督式微調（supervised fine-tuning, SFT）**：在 12 萬筆精心篩選的範例上進行，用以啟動並校準 Action Judge 與 State Revision。

資料合成採用多智慧體協作：

- **Annotation Agent（標註智慧體）**：進行回合層級（turn-level）標註，產生 Action Judge 訓練資料。
- **Proposal Agent（提議智慧體）** 與 **Revision Agent（修訂智慧體）**：共同產生 State Revision 範例。Proposal Agent 生成雜訊決策，Revision Agent 則從相同觀察歷史中生成修正後的推理–動作延續。

這種合成方式降低了大規模人工標註的成本，並確保訓練資料涵蓋搜尋（Search）、終端機（Terminal）與軟體工程（Software Engineering, SWE）三個領域。

##### 6. 知識蒸餾：AEWM-RFT

為了將 AEWM 引導的決策模式轉移回基礎智慧體，作者提出 AEWM-RFT：先以 EditAct 在真實環境中執行並驗證，產生已驗證的 EditAct 軌跡（verified EditAct trajectory），再以此進行拒絕採樣微調（rejection sampling fine-tuning, RFT）。這使得智慧體在推論時無需線上 AEWM 引導（online AEWM guidance），即可內化 AEWM 的判斷與修訂模式。

#### 實驗數據解讀

##### 1. Action Judge 基準測試

作者建立了一個跨領域的 Action Judge 基準測試（benchmark），包含 3,000 個決策。AEWM 在 macro-F1（macro-F1）上達到 **70.5%**，超越所有對比的前沿基線（frontier baseline），並較最強基線（strongest baseline）高出 **10.6 個百分點**。

這顯示 AEWM 在區分 Critical、Exploratory 與 Noisy 三類決策上具有顯著優勢，且能跨 Search、Terminal、SWE 三個領域泛化。macro-F1 對三類等權重計算，意味著 AEWM 對少數類（如 Noisy）的辨識能力也優於基線，這對實際應用尤為重要，因為雜訊決策正是導致長期任務失敗的主要來源。

##### 2. EditAct 任務表現

EditAct 在六個基準測試與三個智慧體骨幹模型（agent backbone）上進行評估：

| 骨幹模型 | 相較最強基線的平均分數（average score）提升 |
|---|---|
| Qwen3.5-4B | +6.7 點 |
| Qwen3.5-9B | +5.2 點 |
| Qwen3.5-35B-A3B | +3.2 點 |

幾點觀察：

- **EditAct 全面優於 ReAct 以及步驟層級與軌跡層級的 Best@3**：這說明單純增加採樣數量（Best@3）並無法有效解決任務狀態污染問題，因為錯誤的推理一旦進入歷史，後續步驟會在其基礎上繼續放大錯誤。
- **提升幅度隨模型變大而遞減**：Qwen3.5-4B 提升最大（6.7 點），35B-A3B 提升較小（3.2 點）。這符合預期：較大模型本身具備較強的自我糾錯與規劃能力，因此 AEWM 的輔助邊際效益較小；但即便如此，3.2 點的平均提升在六個基準測試上仍屬顯著。
- **直接替換狀態優於批評引導重生成**：消融實驗顯示 EditAct 勝過智慧體重新採樣（agent resampling）與推理提示（reasoning hints），支持「直接替換當前推理–動作延續」比「僅提供批評後讓智慧體自行重生成」更有效的設計選擇。

##### 3. AEWM-RFT 的轉移效果

AEWM-RFT 在三個領域上較 Self-RFT（Self-RFT）提升 **2.2–2.6 點**，且推論時無需線上 AEWM 引導。這具有重要意義：

- **可轉移性**：AEWM 的判斷與修訂知識可以蒸餾到基礎智慧體中，降低部署成本。
- **真實回饋的價值**：由於 EditAct 軌跡 grounded in real feedback，其監督訊號比單純自我採樣產生的軌跡更可靠，因此 RFT 效果更佳。
- **推論效率**：AEWM-RFT 在推論時不需要額外的世界模型前向傳播，適合延遲敏感的應用場景。

##### 4. 整體意義

實驗結果支持本文的核心論點：對於長期任務中的 LLM 智慧體，世界模型的價值不在於預測高熵的環境觀察，而在於判斷與修正智慧體自身的決策狀態。Action Judge 的高 macro-F1、EditAct 的跨模型與跨領域提升、以及 AEWM-RFT 的成功蒸餾，共同構成一個完整的證據鏈。

#### 與現有研究的比較

##### 1. 與觀察預測型世界模型的差異

現有語言世界模型（language world model）多繼承環境中心目標，預測工具回應，例如 FAIR CodeGen team 與 Zuo et al.、Sun et al. 的工作。這類方法在以下情境面臨挑戰：

- **高熵觀察**：搜尋引擎結果、網頁內容、測試輸出難以穩定預測。
- **執行相依性**：相同動作在不同時間或環境狀態下可能產生不同回應。
- **價值錯配**：即使準確預測觀察，也不保證智慧體能正確解讀或據此調整計畫。

AEWM 則完全放棄觀察重建，轉而建模「智慧體解讀與動作如何形塑後續任務進展」。這與傳統世界模型在概念上有根本差異：前者預測環境，後者預測並編輯智慧體狀態。

##### 2. 與自我反思、批評與重規劃方法的差異

現有許多方法讓智慧體在執行後進行反思（reflection）、產生批評（critique）或重新規劃（replanning）。這些方法雖然能修正部分錯誤，但存在以下限制：

- **狀態污染持續存在**：錯誤的推理與動作已進入歷史，後續決策仍可能受其影響。
- **批評與行動分離**：批評僅作為額外文字輸入，智慧體需要自行決定是否採納，容易流於表面。
- **缺乏決策分類**：未區分探索性與雜訊決策，可能過度懲罰有價值的探索。

AEWM 的 State Revision 直接替換雜訊決策，從根源上改變後續狀態；Action Judge 的三分類則保留探索性動作的價值。這使得 AEWM 在機制上更為精細。

##### 3. 與 Best-of-N 採樣與樹搜尋的差異

Best@3 等採樣方法透過生成多個候選並選擇最佳者來提升表現。然而：

- **候選選擇不等同狀態修正**：Best-of-N 仍從相同污染歷史出發，候選之間共享錯誤前提。
- **缺乏對決策類型的理解**：無法區分 Critical、Exploratory、Noisy，因此可能浪費計算資源在無意義的候選上。

AEWM 的 EditAct 不僅選擇候選，更能主動修訂狀態，並結合真實執行回饋，形成「判斷–修訂–執行」的閉環。

##### 4. 優勢總結

- **目標更貼近任務需求**：對任務導向智慧體而言，正確的決策比準確的觀察預測更重要。
- **機制更精細**：Action Judge 的三分類與 State Revision 的狀態替換，比單純批評或重採樣更能針對性地解決任務狀態污染。
- **可蒸餾**：AEWM-RFT 證明所學模式可轉移至基礎智慧體，降低部署門檻。

##### 5. 限制與潛在弱點

- **資料合成品質依賴標註智慧體**：Action Judge 與 State Revision 的訓練資料由其他智慧體生成，若標註智慧體本身存在偏誤，將影響 AEWM 的判斷標準。
- **領域覆蓋仍有限**：雖涵蓋 Search、Terminal、SWE，但尚未驗證於更廣泛的網頁操作、多智慧體協作或具身環境。
- **計算與資料成本**：中期訓練使用 520 億 token、SFT 使用 12 萬筆資料，對於資源有限的研究者而言門檻較高。
- **未與觀察預測結合**：在部分可觀察或真實回饋不可得的情境下，完全放棄觀察預測可能損失資訊。未來可考慮混合建模。

#### 可重現性評估

根據目前提供的論文內容，**並未明確提及原始碼、資料集或模型權重是否公開釋出**。因此，從可重現性（reproducibility）角度可做出以下評估：

##### 1. 方法描述的可重現性

- 方法論層面描述相對完整：AEWM 的狀態定義、Action Judge 的分類標準、State Revision 的替換機制、EditAct 的推論流程，以及兩階段訓練架構均有清楚說明。
- 資料合成流程也大致交代：Annotation Agent、Proposal Agent、Revision Agent 的角色分工明確，但具體提示詞（prompt）、篩選準則、品質控制機制未詳細說明。
- 實驗設定（基準測試、骨幹模型、評估指標）有列出，但缺少超參數、訓練硬體、訓練時間等細節。

#### 未來研究方向

##### 1. 擴展至更廣泛的任務領域

目前 AEWM 驗證於 Search、Terminal 與 SWE。未來可探索：

- **網頁操作與 GUI 智慧體**：觀察包含視覺資訊，任務狀態污染可能以不同形式出現。
- **科學實驗與資料分析**：需要結合數值推理與多步驟驗證。
- **多智慧體系統**：任務狀態污染可能來自其他智慧體的錯誤訊息，需要擴展 State Revision 以處理跨智慧體溝通。

##### 2. 結合觀察預測與智慧體狀態建模

雖然本文主張放棄觀察重建，但在真實回饋不可得或部分可觀察環境中，適度的觀察預測仍有價值。未來可研究：

- **混合世界模型**：同時預測決策效果與關鍵觀察摘要，在需要時提供模擬回饋。
- **選擇性觀察預測**：僅對低熵、結構化的觀察進行預測，避免浪費模型容量。

##### 3. 線上適應與持續學習

AEWM-RFT 展示了一次性蒸餾的可行性，但未涉及持續更新。未來可研究：

- **線上 AEWM 適應**：根據新任務或新環境動態調整 Action Judge 與 State Revision。
- **從失敗軌跡中學習**：自動收集並標註失敗案例，持續擴充訓練資料。

##### 4. 不確定性量化與安全機制

Action Judge 本質上是一個分類器，其信心分數可用於：

- **不確定性導向的探索**：當模型對 Critical/Exploratory/Noisy 分類不確定時，主動請求更多資訊或人類介入。
- **安全閘門**：對高風險動作（如刪除檔案、部署程式碼）增加額外確認機制。

##### 5. 可解釋性與人機協作

- 研究 Action Judge 的決策依據，讓使用者理解為何某個動作被標記為 Noisy。
- 開發人機協作介面，讓領域專家審核 State Revision 的建議，進一步提升系統可信度。

##### 6. 與規劃與搜尋演算法整合

EditAct 目前採用貪婪式的單步判斷與修訂。未來可與以下技術結合：

- **蒙地卡羅樹搜尋（Monte Carlo Tree Search, MCTS）**：將 Action Judge 作為節點價值估計器，State Revision 作為節點擴展機制。
- **啟發式搜尋**：利用 Critical/Exploratory/Noisy 分類指導搜尋方向，減少無效探索。

##### 7. 輕量化與邊緣部署

AEWM 的兩階段訓練成本高昂。未來可研究：

- **知識蒸餾至更小模型**：讓 Action Judge 與 State Revision 能在邊緣裝置上執行。
- **參數高效微調（parameter-efficient fine-tuning）**：如 LoRA、Adapter 等技術，降低訓練與部署成本。

總結而言，AEWM 為語言世界模型開闢了一條新路徑：從模擬外部世界轉向編輯智慧體內部狀態。這一範式轉移不僅在實驗上取得顯著成效，也為未來長期任務智慧體的設計提供了重要的理論與實務基礎。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？為什麼現有的語言世界模型被認為不足？**

A：本文指出，現有語言世界模型大多繼承「以環境為中心」的目標，試圖預測工具回應或環境觀察，但這些觀察往往具有高熵且執行相依的特性，例如搜尋結果會隨網頁內容與排名變動、終端機輸出取決於檔案系統與執行時狀態。當真實工具能提供真實回饋時，重建這些細節不僅困難，也對智慧體後續決策的幫助有限，甚至可能引入虛構證據。因此，論文重新思考語言世界模型應該預測什麼，並將焦點轉移到智慧體自身的決策效應與任務狀態演變。

**Q2：什麼是「任務狀態污染」？它為何會損害長期任務的表現？**

A：任務狀態污染是指智慧體在探索未知環境時，把未經證實的假設當成事實、保留與新回饋矛盾的過時計畫，或誤將部分進展當成已完成，並讓這些錯誤持續累積在歷史紀錄中。由於後續推理與動作都建立在這段被污染的歷史上，即使環境提供了真實回饋，智慧體仍可能沿著局部合理但整體錯誤的方向前進。這種污染會隨著互動步數不斷放大，最終導致長期任務失敗。

**Q3：為什麼不直接模擬環境觀察？本文提出的替代建模目標是什麼？**

A：直接模擬環境觀察需要重現高熵、執行相依的細節，這在搜尋、終端機與軟體工程等領域既困難又容易出錯，而且模擬結果無法保證改善智慧體對任務的理解。相較之下，本文主張世界模型應該建模「智慧體的推理與動作如何塑造未來任務進展」，也就是決策效應而非觀察重建。AEWM 透過預測決策類別與修訂雜訊決策，直接改變後續決策所依賴的狀態。

**Q4：AEWM 的兩大核心能力是什麼？它們如何協同運作？**

A：AEWM 包含「動作判斷器」與「狀態修訂」兩項能力：動作判斷器會將智慧體提出的推理–動作配對分類為關鍵決策、探索性決策或雜訊決策；若被判斷為雜訊決策，狀態修訂則會從當前狀態出發，重新生成一段更合理的推理–動作延續來取代原配對。在 EditAct 機制中，這兩者與真實執行結合：保留有成效的決策、修訂雜訊決策，再將選定的動作真正執行於環境中。

**Q5：EditAct 與傳統的批判再生成或 Best-of-N 選擇有何不同？**

A：傳統方法通常只對智慧體的輸出提供批判意見，或從多個候選中挑選一個較好的答案，但並未直接改變後續決策所依賴的內部狀態。EditAct 則是「直接替換」當前的推理–動作延續，從相同的觀察歷史出發生成新的狀態，因而能改變後續推理的基礎。消融實驗顯示，EditAct 優於智慧體重新採樣與僅提供推理提示的方法，證明直接修訂狀態比單純批判或重抽更有效。

**Q6：AEWM 的訓練流程與資料合成方式是什麼？**

A：AEWM 採用兩階段訓練：先在 520 億個 token 上進行中期訓練以學習互動知識，再透過監督式微調在 12 萬筆精心篩選的範例上啟動並校準判斷與修訂能力。資料合成方面，由註釋智慧體進行回合層級標註以產生動作判斷器資料，並由提案智慧體與修訂智慧體共同建構狀態修訂範例。此外，論文還提出 AEWM-RFT，利用已驗證的 EditAct 軌跡進行拒絕採樣微調，把 AEWM 引導的決策模式轉移回智慧體。

**Q7：實驗涵蓋哪些領域與基準測試？最主要的量化結果為何？**

A：實驗橫跨搜尋、終端機與軟體工程三大領域，並在六個基準測試與三個 Qwen 智慧體骨幹模型上進行評估。AEWM 在動作判斷器基準測試上達到 70.5% 的 macro-F1，超越最強前沿基線 10.6 分；EditAct 相較最強基線平均分別提升 6.7、5.2 與 3.2 分（對應 Qwen3.5-4B、9B 與 35B-A3B）。AEWM-RFT 在沒有線上 AEWM 引導的情況下，仍比 Self-RFT 高出 2.2 至 2.6 分。

**Q8：動作判斷器基準測試測量什麼？10.6 分的差距為何重要？**

A：該基準測試包含 3,000 個決策，要求模型把智慧體提出的推理–動作配對正確分類為關鍵、探索性或雜訊決策，並橫跨多個領域。10.6 分的 macro-F1 差距顯示，即使是前沿基線模型，也難以準確判斷哪些決策會推進任務、哪些只是雜訊。這驗證了「建模決策效應」而非「重建觀察」的必要性，也說明 AEWM 的專項訓練能顯著提升判斷能力。

**Q9：論文提到了哪些消融實驗？它們帶來什麼啟示？**

A：論文將 EditAct 與智慧體重新採樣以及僅提供推理提示的方法進行比較，結果顯示 EditAct 表現更優，代表直接替換推理–動作延續比單純給提示或重抽樣更能改善決策品質。另一項關鍵比較是 AEWM-RFT 與 Self-RFT：AEWM-RFT 在推論時不需要線上 AEWM 引導，仍能穩定提升表現，說明經過驗證的 EditAct 軌跡具有可轉移的監督訊號。這些消融結果支持 AEWM 的設計選擇，並顯示其效益不僅來自候選選擇。

**Q10：AEWM 最適合應用在哪些真實世界的智慧體系統？**

A：AEWM 特別適合需要長期互動且工具回饋高熵的場景，例如自動化網頁搜尋智慧體、自主軟體工程開發智慧體，以及基於終端機的維運或資料分析智慧體。在這些系統中，智慧體容易累積過時計畫或錯誤假設，而 AEWM 能在執行前過濾雜訊決策並修訂狀態。這不僅能減少無效或錯誤的工具呼叫，也能降低後續修復成本。

**Q11：部署 AEWM 時需要考慮哪些產品層面的問題？**

A：首先，動作判斷與狀態修訂都需要額外的模型呼叫，會帶來延遲與運算成本，因此需要權衡效益與開銷。其次，狀態修訂雖然能直接改變智慧體的內部狀態，但若修訂錯誤，可能引入新的偏差，因此需要搭配真實執行回饋與驗證機制來確保安全。最後，不同領域的決策分類標準可能不同，產品化時需要針對目標場景進行校準與監控。

**Q12：AEWM 可能對世界模型與智慧體架構的研究方向產生什麼影響？**

A：AEWM 將研究焦點從「如何精準模擬環境」轉向「如何建模智慧體狀態的動態演變與決策效應」，這可能催生針對工具使用智慧體的新型世界模型訓練目標。它也鼓勵未來的智慧體架構更明確地維護並修訂內部任務狀態，而不只是被動接收環境觀察。長遠來看，這種典範轉移有助於建立更可靠、更能自我修正的長期任務智慧體。

**Q13：論文暗示或承認了哪些限制？**

A：AEWM 目前主要在搜尋、終端機與軟體工程三個領域進行訓練與評估，對其他類型環境的泛化能力仍有待驗證。此外，訓練資料依賴合成產生，註釋智慧體與修訂智慧體的品質會直接影響 AEWM 的上限。狀態修訂雖然能在執行前修正雜訊決策，但無法處理所有來源的任務狀態污染，例如歷史中已根深蒂固的錯誤假設。

**Q14：即使使用了 AEWM，仍可能出現哪些失敗案例？**

A：動作判斷器可能誤把關鍵決策判為雜訊而捨棄，或把雜訊決策判為關鍵而保留，導致任務偏離正軌。狀態修訂雖然能生成看似合理的推理–動作延續，但這些修訂仍可能與真實環境不一致。若互動歷史已經嚴重受到污染，後續的判斷與修訂都可能建立在錯誤基礎上；此外，在回饋極為稀疏的領域中，判斷決策類別也會更加困難。

**Q15：論文暗示了哪些未來研究方向？**

A：未來可以將 AEWM 擴展到更多樣化的工具環境，甚至整合多模態觀察，例如圖形介面或感測器資料。資料合成方面，可引入更強大的驗證器或外部知識來提升標註與修訂品質。另外，將 AEWM 與線上學習或強化學習結合，讓智慧體能根據真實執行回饋持續調整判斷與修訂策略，也是值得探索的方向；同時，發展更輕量、即時的狀態修訂模型也有助於實際部署。

## 實務應用指南

## 適用場景

1. **企業級智慧客服與多步驟問題排解**  
   當使用者詢問需要查詢知識庫、比對帳務紀錄並執行退款或開票等動作時，AEWM 可作為「決策守門員」，判斷目前推理–動作配對是關鍵、探索性還是雜訊，避免智慧體在歷史紀錄中累積未經證實的假設，導致後續給出錯誤答案。

2. **自動化軟體工程助理（SWE Agent）**  
   在程式碼理解、測試失敗定位與修補的長期任務中，智慧體常會基於過時計畫或部分進度誤判任務已完成。透過 State Revision 在執行前修訂雜訊決策，EditAct 能減少「在未驗證的程式碼上繼續堆疊修改」的風險，提升修復成功率。

3. **金融/法規研究搜尋代理**  
   面對高熵且不斷變動的網頁內容與搜尋排名，傳統觀察重建式世界模型容易產生虛構證據。AEWM 不預測工具回應，而是建模決策對解決進度的影響，讓搜尋智慧體在發現已被反駁的候選答案時，能即時修訂狀態而非繼續鑽研無成效方向。

4. **DevOps 與終端機自動化**  
   在需要執行多條 shell 指令、檢查日誌與部署狀態的場景中，智慧體可能忽略必要的執行檢查而直接解讀終端機輸出。Action Judge 可標記這類雜訊決策，State Revision 則在真正下指令前補上驗證步驟，降低誤刪檔案或錯誤部署的機率。

5. **多工具協作的企業流程自動化（RPA 2.0）**  
   當智慧體串接 CRM、ERP、文件系統與電子郵件等多種工具時，任務狀態污染會隨著步數增加而放大。AEWM-RFT 可將已驗證的 EditAct 軌跡透過拒絕採樣微調轉移給骨幹模型，使模型在沒有線上 AEWM 引導的推理階段仍保留良好的決策模式。

## 實作前置條件

- **資料準備**  
  需要蒐集或合成三類資料：(1) 真實互動軌跡，包含任務、歷史紀錄、推理–動作配對與環境觀察；(2) Action Judge 標註，可由評分較強的註釋智慧體進行回合級標記，區分關鍵、探索性與雜訊決策；(3) State Revision 範例，由提案智慧體與修訂智慧體協同產生雜訊決策的替代推理–動作延續。

- **運算資源**  
  參考論文規模，中期訓練約需 52B token 等級的語料與相對應的 GPU 叢集；監督式微調則可在 120K 筆精選範例上進行。若僅想驗證概念，可先以較小模型（如 Qwen3.5-4B 等級）與單一領域資料進行 SFT，再評估是否擴展。

- **領域知識與工具環境**  
  必須具備可重現、可驗證的真實工具回饋環境，例如可控的搜尋引擎、容器化終端機、可執行測試的程式碼倉儲。缺乏真實回饋將難以產生已驗證的 EditAct 軌跡，也會削弱 AEWM-RFT 的效果。

- **團隊技能**  
  需要熟悉 LLM 微調流程（mid-training、SFT、RFT）、具備智慧體框架開發經驗（ReAct 或類似架構），並有領域專家協助定義「解決進度」與「不確定性降低」的判斷標準。

## 實作步驟建議

1. **定義任務狀態與決策空間**  
   釐清你的應用中「執行前狀態」由哪些元素組成：任務描述、智慧體歷史紀錄、當前推理–動作配對。並定義動作類型與可觀察的環境回饋格式。

2. **建立真實互動軌跡資料集**  
   讓基礎智慧體在真實環境中執行任務，收集包含成功與失敗案例的軌跡。失敗軌跡尤其重要，因為它們是任務狀態污染的主要來源。

3. **合成 Action Judge 訓練資料**  
   使用較強的註釋智慧體對每一回合的推理–動作配對進行標註，判斷其屬於關鍵決策、探索性決策或雜訊決策。建議從宏觀的解決進度與不確定性降低兩個維度設計評分準則。

4. **合成 State Revision 訓練資料**  
   針對被標為雜訊的決策，讓提案智慧體產生多個替代延續，再由修訂智慧體或領域專家挑選能從相同觀察歷史導向更正確狀態的版本。

5. **兩階段訓練 AEWM**  
   先進行中期訓練以注入互動知識，再進行監督式微調以啟動並校準 Action Judge 與 State Revision。若資源有限，可優先執行 SFT 並保留擴展空間。

6. **部署 EditAct 推理流程**  
   在每次執行前，先由 Action Judge 評分當前推理–動作配對；若為雜訊，則以 State Revision 替換為修訂後的延續，再執行動作並將真實觀察納入歷史紀錄。

7. **產生已驗證軌跡並執行 AEWM-RFT**  
   收集經 EditAct 修正後且最終成功的軌跡，透過拒絕採樣微調將其轉移回骨幹智慧體，使其在無線上 AEWM 引導時仍能維持較佳決策品質。

8. **持續監控與迭代**  
   建立 Action Judge 的 macro-F1 評估基準，定期檢視雜訊決策的修訂成功率，並隨著環境變化（如搜尋引擎演算法更新、程式碼庫重構）重新合成資料與微調。

## 潛在風險與注意事項

- **過度依賴模擬而忽略真實回饋**  
  AEWM 的核心價值在於避免觀察重建。若實作時仍試圖讓模型預測工具回應細節，將回到高熵、執行相依的困境，並可能產生虛構證據。應專注於「決策如何影響任務進展」。

- **修訂後的決策仍可能出錯**  
  State Revision 並非萬靈丹，修訂智慧體本身也可能帶入新的偏誤。建議保留人工或更強模型的稽核機制，並在關鍵動作（如刪除資料、部署服務）前加入二次確認。

- **延遲與成本增加**  
  每次執行前都需執行 Action Judge，必要時還要產生修訂延續，會增加推理延遲與 API 成本。可透過快取常見決策判斷、設定閾值只在信心低時啟動修訂，或後續以 AEWM-RFT 降低線上依賴。

- **領域遷移挑戰**  
  在搜尋領域訓練的 AEWM 不一定能直接遷移到終端機或軟體工程。論文雖展示跨領域效果，但實務上仍需針對新領域重新合成部分資料並校準標註標準。

- **任務狀態污染的隱蔽性**  
  未經證實的假設與過時計畫可能已深埋於長歷史紀錄中。除了修訂當前決策，也應考慮定期摘要或壓縮歷史，並讓 Action Judge 能回顧更早的上下文。

## 與其他技術的整合建議

- **與 ReAct / Reflexion 等智慧體框架整合**  
  EditAct 可視為 ReAct 的執行前強化層：在產生 reasoning–action pair 後、執行動作前，插入 Action Judge 與 State Revision。Reflexion 則可在軌跡結束後提供額外的軌跡級反思，兩者可互補。

- **與檢索增強生成（RAG）結合**  
  在搜尋與知識密集型任務中，RAG 負責提供 grounded feedback，AEWM 負責判斷檢索結果是否被正確詮釋。避免智慧體將檢索到的片段斷章取義後當作已驗證事實。

- **與強化學習或 DPO 搭配**  
  已驗證的 EditAct 軌跡除了用於 RFT，也可轉換為偏好資料，透過 DPO 或 RLHF 進一步對齊智慧體的決策偏好，特別適合強調安全與可靠性的應用。

- **與可觀測性平台整合**  
  將 Action Judge 的判斷、State Revision 的替換紀錄與最終執行結果寫入可觀測性系統，便於後續審計、錯誤追蹤與持續微調。

- **與多模態世界模型分工**  
  若應用同時涉及視覺觀察（如網頁截圖、機器人感測），可讓視覺世界模型負責低階觀察預測，AEWM 負責高階任務狀態與決策效果建模，形成分層架構。

## 給不同背景讀者的閱讀建議

**初學者**  
建議先從「任務狀態污染」這個直覺概念入手：想像一個助理在沒有確認事實的情況下，把猜測當成已確認資訊寫進筆記，之後所有判斷都建立在錯誤基礎上。接著理解 AEWM 如何像一位編輯，在智慧體真正行動前幫它修正筆記中的錯誤，而不是去預測外界會怎麼回應。技術細節如 mid-training 與 RFT 可先略讀，重點放在 EditAct 的運作流程圖。

**AI 工程師**  
請聚焦第 2 節的模型架構與訓練流程，特別是 Action Judge 的三分類標準、State Revision 的資料合成方式，以及 EditAct 如何與真實執行銜接。實作時應優先建立可重現的真實工具環境與軌跡收集管線，並評估是否能在現有智慧體框架中以「執行前攔截層」的形式導入 AEWM，降低對現有系統的侵入性。

**研究人員**  
本文對語言世界模型的基本假設提出挑戰：從「預測環境觀察」轉向「建模決策對任務進展的影響」。建議深入檢視作者如何論證觀察重建在長期任務中的局限性，以及 Action Judge 的標註方法論與評估基準設計。未來可延伸的方向包括：將 agent-state editing 擴展到多智慧體協作、結合形式化驗證強化 State Revision 的可靠性，以及探索更高效的線上學習機制。

**產品經理**  
請把重點放在「這項技術能解決什麼商業問題」與「導入成本」。AEWM 適合已經有智慧體在執行多步驟任務、但經常因為錯誤假設或過時計畫而失敗的產品。導入時需評估是否有足夠的真實回饋環境、能否承擔額外的推理延遲，以及是否願意投入資料合成與領域標註。短期可從單一高風險場景（如軟體工程修復或財務查核）試點，驗證效果後再擴展。
