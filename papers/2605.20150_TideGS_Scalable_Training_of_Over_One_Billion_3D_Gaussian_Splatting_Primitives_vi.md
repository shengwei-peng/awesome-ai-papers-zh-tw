## ⚡ TL;DR

3DGS訓練受記憶體限制，單GPU僅能處理數千萬高斯基元，難以擴展至十億級規模。
提出TideGS核外框架，透過區塊虛擬化與差分流式傳輸，動態管理SSD–CPU–GPU階層參數。
在單張24GB GPU上實現逾十億高斯基元訓練，重建品質優於現有單GPU基線，突破記憶體規模瓶頸。

## 摘要翻譯

在十億級基元規模（billion-primitive scale）下訓練 3D 高斯潑濺（3D Gaussian Splatting, 3DGS）本質上是記憶體受限（memory-bound）的：每個高斯基元（Gaussian primitive）均帶有大型屬性向量（attribute vector），且聚合參數表（aggregate parameter table）很快就會超出 GPU 容量（GPU capacity），使先前系統僅能在消費級單 GPU 硬體（commodity single-GPU hardware）上處理數千萬個高斯基元。我們觀察到，3DGS 訓練本質稀疏（inherently sparse）且為軌跡條件化（trajectory-conditioned）：每次迭代僅有當前相機批次（camera batch）可見的高斯基元會被啟用，因此 GPU 記憶體可作為工作集快取（working-set cache），而非持久參數儲存（persistent parameter store）。基於此洞見，我們提出 TideGS，一個核外訓練框架（out-of-core training framework），透過三項協同技術（synergistic techniques）在 SSD-CPU-GPU 階層（SSD-CPU-GPU hierarchy）間管理參數：區塊虛擬化幾何（block-virtualized geometry）以達成 SSD 對齊之空間局部性（SSD-aligned spatial locality）、階層式非同步管線（hierarchical asynchronous pipeline）以實現 I/O 與計算重疊（overlap I/O with computation），以及軌跡自適應差分流式傳輸（trajectory-adaptive differential streaming），僅傳輸迭代間之增量工作集差量（incremental working-set deltas）。實驗顯示，TideGS 能在單張 24 GB GPU 上訓練超過十億個高斯基元，並在大規模場景（large-scale scenes）中，於所有受評估的單 GPU 基線方法（single-GPU baselines）中達到最佳重建品質（reconstruction quality），其擴展規模超越先前的核外基線方法（out-of-core baselines）（例如約一億個高斯基元）與標準記憶體內訓練（in-memory training）（例如約一千一百萬個高斯基元）。

### 核心貢獻（3～5點）
- 提出 TideGS，一個基於核外最佳化的訓練框架，首次在單張 24 GB 消費級 GPU 上實現超過十億個高斯基元的 3D 高斯潑濺訓練。
- 揭示 3DGS 訓練之本質稀疏與軌跡條件化特性，提出將 GPU 記憶體視為工作集快取而非持久參數儲存之核心設計洞見。
- 設計三項協同技術——區塊虛擬化幾何、階層式非同步管線與軌跡自適應差分流式傳輸——以在 SSD-CPU-GPU 階層間高效管理參數並重疊 I/O 與計算。
- 在大規模場景中達到優於所有受評估單 GPU 基線方法與核外基線方法之重建品質，顯著擴展可訓練之基元規模上限。

### 適合對象
適合從事三維電腦視覺、神經渲染、新視角合成與大規模場景重建之研究者與工程師，特別是關注記憶體受限環境下可擴展訓練、顯式場景表徵最佳化，以及需於消費級單 GPU 硬體上處理城市規模或十億級基元資料之讀者。

## 深度分析

#### 方法論解析

TideGS 的核心方法論建立在對 3D 高斯潑濺（3D Gaussian Splatting, 3DGS）訓練動態的深刻觀察之上：相較於將視訊記憶體（VRAM）視為持久參數儲存（persistent parameter store），作者發現 3DGS 訓練本質稀疏（inherently sparse）且軌跡條件化（trajectory-conditioned）——每個相機批次（camera batch）僅激活可見的高斯基元（Gaussian primitive），而相鄰迭代間的工作集（working set）因相機軌跡平滑而高度重疊。基於此，TideGS 將 VRAM 重新定位為工作集快取（working-set cache），並透過三項協同技術（synergistic techniques）管理橫跨 SSD-CPU-GPU 階層（SSD-CPU-GPU hierarchy）的聚合參數表（aggregate parameter table）。

首先，**區塊虛擬化幾何（block-virtualized geometry）** 解決了核外（out-of-core）儲存的基本單位問題。由於單一高斯基元無法有效率地隨機存取 SSD，TideGS 將空間上連貫的高斯基元打包為對齊 SSD 的區塊（block）。這創造了 SSD 對齊之空間局部性（SSD-aligned spatial locality），使循序讀取效率最大化。此設計同時引入雙重粒度分離：區塊層級工作集（block-level working set）作為傳輸與快取單位，而高斯層級的激活集則保留標準光柵化渲染管線（rasterization-based rendering pipeline）與梯度更新語義。這種虛擬化（virtualization）策略讓系統能以區塊為單位進行核外記憶體管理，同時維持 3DGS 原有的演算法正確性。

其次，**階層式非同步管線（hierarchical asynchronous pipeline）** 針對 SSD 頻寬低、延遲高的物理限制，將資料搬移與計算重疊。具體而言，系統透過多級佇列同時排程 SSD 讀取、主機–裝置傳輸（host–device transfer）、反向傳播後的髒資料寫回（write-back），以及 GPU 上的前向/反向傳播（forward/backward propagation）。這實現了 I/O 與計算重疊（overlap I/O with computation），避免 GPU 因等待核外資料而閒置，是讓 SSD 層級訓練具備實用性的關鍵工程貢獻。

第三，**軌跡自適應差分流式傳輸（trajectory-adaptive differential streaming）** 利用了 3DGS 訓練獨特的時間局部性。由於相機軌跡通常平滑，第 t 迭代與第 t+1 迭代的工作集往往大量重疊。TideGS 在 VRAM 中保留重疊區塊，僅於迭代間傳輸增量工作集差量（incremental working-set deltas）。這大幅壓縮了每輪迭代所需的通訊量，使通訊開銷從「與總模型大小成正比」降為「與視角變化量成正比」。對於城市規模（city-scale）場景中動輒十億級基元規模（billion-primitive scale）的模型，此技術是單張消費級單 GPU 硬體（commodity single-GPU hardware）能夠負荷的核心設計。

整體而言，TideGS 的方法論並非單純的系統工程優化，而是將 3DGS 的「顯式場景基元（explicit scene primitives）表徵特性」與「稀疏嵌入表訓練」的系統觀點相結合，從演算法特性出發重新設計儲存階層。

#### 實驗數據解讀

論文提供的規模數據呈現清晰的數量級躍遷：在 24 GB VRAM 的消費級 GPU 上，標準記憶體內訓練（in-memory training）約於 1,100 萬（∼11M）高斯基元即耗盡記憶體；既有核外基線方法（out-of-core baselines）透過主機卸載（host-offloading）可擴展至約 1 億（∼100M）高斯基元；而 TideGS 成功訓練超過十億（1B+）高斯基元，相當於在單一 GPU 上達成約兩個數量級相較於標準方法、以及約十倍相較於先前核外方法的擴展。

此規模提升的意義不僅在於數字本身。作者明確指出，在 5.9 × 7.9 km² 的城市規模場景中，TideGS 在所有評估的單 GPU 基線方法（single-GPU baselines）中達到最佳重建品質（reconstruction quality）。這項結果至關重要：它證明了核外最佳化（out-of-core optimization）並未因額外的 I/O 開銷或近似而犧牲收斂品質。相反地，由於模型容量（model capacity）得以突破 VRAM 天花板，更多的高斯基元與可學習外觀參數（learned appearance parameters）能夠被部署，直接轉化為高保真（high-fidelity）的新視角合成（novel view synthesis）能力。這也反過來驗證了作者的核心假設——3DGS 的記憶體受限（memory-bound）特性可透過稀疏性與階層式快取有效繞過，而非必須依賴無止境的硬體記憶體擴張。

值得注意的是，實驗強調「單 GPU」設定。這意味著效能提升並非來自多 GPU 叢集的記憶體聚合，而是來自對單一運算單元儲存階層的極致利用，對學術界與中小型團隊的硬體可及性（accessibility）具有重大意義。

#### 與現有研究的比較

與隱式神經表徵（implicit neural representations）如 NeRF 相比，3DGS 將場景表徵從神經網路權重轉移至顯式基元表（primitive table），這雖然帶來了即時渲染（real-time rendering）與明確幾何解釋性的優勢，卻也將瓶頸轉移至記憶體容量。TideGS 並未退回隱式表徵，而是透過核外訓練框架（out-of-core training framework）直接解決顯式表徵的記憶體瓶頸，維持了 3DGS 的核心優勢。

在系統層面，先前研究如 Lee et al. (2025) 與 Zhao et al. (2025) 已嘗試利用主機記憶體擴展 3DGS 訓練，但這些方法仍將關鍵幾何資料常駐 GPU，實質上僅將階層延伸至 CPU DRAM，導致單 GPU 上限約束在 ∼100M 高斯基元。TideGS 的差異在於將儲存階層進一步推進至 SSD，並透過軌跡自適應差分流式傳輸克服 SSD 的頻寬與延遲劣勢。這使 TideGS 成為首個真正實現 SSD 層級、單 GPU 十億規模 3DGS 訓練的系統。

相較於多 GPU 分散式訓練方案（Zhao et al., 2024; Li et al., 2024），TideGS 選擇了截然不同的擴展路徑：後者透過聚合多裝置記憶體與引入複雜的分散式通訊來換取規模，而 TideGS 則證明單一消費級 GPU 配合階層式非同步管線即可達成同等甚至更大的場景規模。這降低了大規模場景（large-scale scenes）重建的基礎設施門檻與工程複雜度。

然而，此方法仍存在若干內建限制。首先，差分流式傳輸的效益高度依賴相機軌跡的時間局部性；若輸入視角為非連續跳躍式採樣（非軌跡條件化），則工作集重疊率下降，SSD 傳輸量將逼近完整區塊交換，效能可能顯著退化。其次，固定大小的區塊劃分雖利於 SSD 對齊，但在幾何密度極度不均的場景中可能導致冗餘傳輸，空間局部性與傳輸效率之間的權衡（trade-off）仍有優化空間。最後，雖然非同步管線隱藏了大部分延遲，SSD 的循序讀取頻寬仍是理論上的天花板，極端情況下仍可能限制迭代吞吐量。

#### 可重現性評估

論文明確提供了專案網站（https://sponge-lab.github.io/TideGS）與 GitHub 儲存庫（https://github.com/sponge-lab/TideGS），這對可重現性（reproducibility）是極為正面的訊號。原始碼（source code）、資料集（datasets）設定與潛在的預訓練模型權重（model weights）若完整釋出，將使其他研究者能夠直接驗證十億級基元的訓練流程，並在此基礎上進行擴展研究。

不過，作為一項重度依賴儲存階層效能的核外訓練框架，TideGS 的復現結果對硬體規格極為敏感。SSD 的循序讀寫頻寬、IOPS 表現、CPU DRAM 大小，乃至 PCIe 匯流排頻寬，皆會顯著影響階層式非同步管線的實際效率。目前提供的摘要與初步內文尚未詳細說明實驗所使用的 SSD 型號、CPU 記憶體容量與詳細的環境設定，這些資訊對於確保不同實驗室間的結果一致性至關重要。建議作者在未來釋出程式碼時，一併提供標準化的硬體規格描述與復現腳本（reproduction scripts），以降低變因。

#### 未來研究方向

第一，**硬體協同設計**。隨著 GPUDirect Storage 等技術成熟，未來可讓 SSD 資料繞過 CPU 記憶體直接傳輸至 GPU，進一步壓縮核外資料路徑。將 TideGS 的階層式管線與 RDMA 或 NVMe-oF 結合，甚至可能實現單 GPU 搭配網路儲存的極大規模訓練。

第二，**動態與 4D 場景擴展**。當前 TideGS 聚焦於靜態大規模場景。若將核外最佳化延伸至時序維度（4D Gaussians），處理動態場景中隨時間變化的工作集，將需要設計新的時間差分編碼與區塊置換策略，以應對時間維度帶來的額外記憶體爆炸。

第三，**自適應區塊與參數壓縮**。未來可探索非均勻區塊劃分（如根據幾何密度調整區塊大小），或在工作集載入時引入 FP16/INT8 量化與稀疏編碼，進一步縮減增量工作集差量的傳輸量與 VRAM 佔用，突破現有 SSD 頻寬天花板。

第四，**多 GPU 混合擴展**。TideGS 的單 GPU 核外機制可與多 GPU 資料平行（data parallelism）正交結合。未來研究可探討如何在多節點環境中，讓每張 GPU 維護本地 SSD 快取並透過差分同步降低節點間通訊，朝向兆級（trillion-primitive）基元規模邁進。

第五，**一般化稀疏參數表訓練**。TideGS 的洞見——稀疏更新、軌跡條件化、差分快取——本質上適用於任何具有大型嵌入表（embedding table）或稀疏網格的深度學習應用。將此框架推廣至其他領域（如大規模推薦系統或稀疏神經輻射場）是值得探索的跨領域方向。

## 論文問答

**Q1：標準 3DGS 在擴展到十億級基元時，其核心記憶體瓶頸為何？**
A：標準 3DGS 採用密集的聚合參數表，每個高斯基元需儲存 59 個浮點數的幾何屬性與球諧係數，而訓練過程還需額外保存梯度與 Adam 最佳化器狀態，導致記憶體需求隨基元數量線性膨脹。當場景達到一億個高斯時，總訓練狀態已逼近 90 GB，遠超消費級單 GPU 常見的 24 GB 視訊記憶體上限。因此，傳統記憶體內訓練通常僅能支援約 1,100 萬個基元，根本無法滿足城市規模等大型場景的模型容量需求。

**Q2：現有的主機卸載或多 GPU 方案為何仍無法充分解決此擴展性挑戰？**
A：現有的主機卸載方法雖然將部分資料移至 CPU 記憶體，但仍需讓關鍵幾何資料常駐於 GPU，這使得單 GPU 可擴展性被限制在大約一億個高斯的量級，無法突破至十億級別。多 GPU 叢集雖可透過聚合裝置記憶體來擴展，卻伴隨高昂的基礎設施成本、複雜的工程實作與維護難度，難以普及化。更重要的是，這些方法皆未充分利用 3DGS 訓練中由視域條件化所帶來的本質稀疏性，也未能將 GPU 視訊記憶體視為暫態工作集快取，因而無法從根本上解除記憶體受限的束縛。

**Q3：將 3DGS 擴展到十億級基元規模為何具有重要研究與應用價值？**
A：先前研究指出，增加高斯基元數量能顯著提升渲染保真度，尤其對於空拍影像與城市街景等大規模環境，細緻的幾何與外觀細節需要龐大的模型容量才能完整捕捉。若無法達到十億級規模，這類廣闊的真實世界場景將因基元不足而產生模糊或缺失細節的重建結果。在單張消費級 GPU 上實現此規模的訓練，不僅能降低高品質新視角合成的門檻，更能讓研究人員與開發者無需依賴昂貴的分散式叢集即可處理城市級場景。

**Q4：TideGS 的核心設計原則是什麼？它如何重新組織記憶體階層？**
A：TideGS 的核心洞見在於 3DGS 最佳化並非每一步都需要存取完整的聚合參數表，而是僅有當前相機批次可見的高斯基元會參與光柵化並接收梯度。基於此，TideGS 將 GPU 視訊記憶體重新定位為高頻寬的工作集快取，而非持久參數儲存空間，並將完整訓練狀態管理於 SSD–CPU–GPU 三層階層之中。在訓練過程中，系統僅將軌跡條件化啟動的工作集具體化到視訊記憶體，其餘絕大部分參數則存放於容量更大但速度較慢的 SSD 儲存層。

**Q5：TideGS 提出的三項協同技術為何？它們之間如何交互作用？**
A：第一項是區塊虛擬化幾何，它將空間上連貫的高斯基元打包成對齊 SSD 存取粒度的區塊，以提升空間局部性並支援高效的大量讀取。第二項是階層式非同步管線，透過將 SSD 讀取、主機與裝置間傳輸、寫回操作與 GPU 渲染及反向傳播重疊執行，有效隱藏 I/O 延遲。第三項是軌跡自適應差分流式傳輸，利用相機軌跡的時間局部性，在相鄰迭代間保留重疊的工作集，僅傳輸增量區塊差量，從而大幅削減跨階層通訊頻寬需求，使三項技術形成相輔相成的加速效果。

**Q6：TideGS 為何選擇以「區塊」作為傳輸與快取單位，而非單獨的高斯基元？**
A：核外儲存系統無法針對單一高斯基元進行高效隨機存取，因為 SSD 的高延遲與粗粒度存取特性使得逐個載入基元極度沒有效率，而區塊層級的讀取能攤銷 I/O 開銷。透過將空間鄰近的基元歸入同一區塊，系統在載入區塊時即可同時將空間連貫的區域帶入記憶體，提高後續相機視點命中快取的機率。此設計讓粗粒度的區塊快取與細粒度高斯層級的渲染及梯度更新解耦，既保留了標準 3DGS 的前後向語義，又最佳化了儲存階層的運作效率。

**Q7：實驗採用了哪些硬體設定與場景規模來評估 TideGS？**
A：實驗證明 TideGS 僅需一張配備 24 GB 視訊記憶體的消費級單 GPU，即可訓練超過十億個高斯基元的場景。評估場景涵蓋了面積達 5.9 × 7.9 平方公里的城市規模環境，這遠遠超出標準記憶體內訓練與現有核外基線方法所能處理的範圍。此單 GPU 設定被明確用來對比昂貴且複雜的多 GPU 叢集方案，突顯其在硬體可及性上的壓倒性優勢。

**Q8：TideGS 在量化與質化層面與先前單 GPU 基線方法相比表現如何？**
A：TideGS 在大規模場景上達到了所有受評估單 GPU 基線方法中最優的重建品質，同時將可訓練規模推進至十億級高斯。相較之下，標準記憶體內訓練約在 1,100 萬個基元時即飽和，而現有核外基線方法僅能達到約一億個基元，TideGS 分別實現了約十倍與百倍的規模躍升。在質化層面，這種規模優勢轉化為更高保真的新視角合成，能呈現出更豐富的幾何細節與外觀紋理。

**Q9：軌跡自適應差分流式傳輸在實驗中對整體訓練效率與可擴展性有何具體貢獻？**
A：軌跡自適應差分流式傳輸充分利用了相機軌跡的時間局部性，因為沿平滑路徑相鄰迭代所啟動的高斯基元集合往往高度重疊。透過在迭代間保留這些重疊的工作集，並僅傳輸區塊層級的增量差量，系統大幅減少了 SSD、CPU 與 GPU 之間的冗餘資料搬移。這種通訊量的削減對於 SSD 層級的核外訓練至關重要，因為若採用全量工作集重新載入，SSD 的有限頻寬與高延遲將迅速成為無法逾越的瓶頸。

**Q10：TideGS 預期在哪些真實應用領域能產生最立即的影響？**
A：TideGS 對於大規模城市重建與空拍攝影測量領域特別具有衝擊力，因為這類場景動輒涵蓋數平方公里，需要數十億顯式基元才能精確捕捉建築與街道層級的細節。它同樣適用於自動駕駛資料集與數位孿生應用，這些場景通常受限於單 GPU 工作站的硬體配置，卻又迫切需要高保真的城市級模型。透過免除多 GPU 叢集的需求，TideGS 讓小型研究團隊與商業工作室都能在可負擔的硬體上訓練巨量 3DGS 模型。

**Q11：相較於分散式多 GPU 系統，單 GPU 部署在產品化方面具備哪些實務優勢？**
A：單張消費級 GPU 的部署能顯著降低硬體採購成本、功耗與維運複雜度，無需承擔多節點叢集的機房與散熱開銷。在軟體層面，單 GPU 環境簡化了驅動相容性、記憶體管理與部署流程，開發者無需處理跨裝置通訊、同步或分散式檢查點等棘手問題。這些因素共同降低了將十億級 3DGS 整合至消費級應用、雲端渲染服務與邊緣工作站的門檻。

**Q12：TideGS 可能如何影響顯式神經或混合式三維表徵的未來研究方向？**
A：TideGS 為顯式基元表徵建立了將 GPU 記憶體視為工作集快取的重要範例，未來可能啟發點雲或網格化神經渲染等其他記憶體受限圖形管線採用類似的核外設計。它的成功證明，善用儲存階層最佳化—例如利用 SSD 並挖掘時空局部性—對於擴展三維視覺模型的貢獻不亞於演算法本身的創新。後續研究可能將此快取中心哲學延伸至動態場景、生成式三維模型，以及大規模資產的即時串流等領域。

**Q13：儘管 TideGS 已進行多項最佳化，SSD–CPU–GPU 階層仍對其施加哪些根本限制？**
A：即便透過非同步管線與差分流式傳輸大幅隱藏延遲，SSD 層的頻寬仍比 GPU 視訊記憶體慢上數個數量級，當工作集因視點劇烈變化而突然改變或空間局部性不佳時，訓練仍可能受到 I/O 瓶頸拖累。區塊虛擬化幾何引入了粒度不匹配問題：載入整個區塊時可能一併帶入當前視點不可見的非活躍基元，進而浪費寶貴的視訊記憶體與傳輸頻寬。此外，系統假設相機軌跡具有一定平滑度以最大化時間局部性，若採用高度不規則或隨機的視點取樣策略，差分流式傳輸的效益將顯著下降。

**Q14：在哪些情況下，TideGS 可能無法相較於較小規模基線展現顯著的加速或品質提升？**
A：若場景規模小到足以讓完整參數表輕鬆容納於 GPU 視訊記憶體內，則區塊虛擬化與非同步資料搬運所帶來的額外開銷反而會使訓練慢於標準記憶體內 3DGS。當相機軌跡極度稀疏或不連續—例如隨機存取的影片幀或非均勻分佈的視點—相鄰迭代間的工作集重疊度將大幅降低，迫使系統頻繁從 SSD 進行完整區塊傳輸。同樣地，若場景幾何呈現高度非局部或碎形分佈，將破壞區塊虛擬化的空間局部性假設，導致快取命中率下滑並加劇 I/O 停頓。

**Q15：未來有哪些最具前景的方向可將 TideGS 的範疇進一步延伸？**
A：一個極具潛力的方向是整合動態與可變形高斯，以支援時變場景，這將需要擴展差分流式傳輸機制來同時處理相機軌跡與物體運動的時空連貫性。另一個方向是結合壓縮或量化技術，進一步縮減每個高斯基元的記憶體佔用，從而支援更大規模的模型或加速 SSD 至 GPU 的傳輸。最後，將此核外框架適配至多 GPU 或混合雲端–本地環境，可在保持單 GPU 易用性的同時，利用分散式系統的聚合記憶體挑戰兆級基元規模的訓練。

## 實務應用指南

### 適用場景

1. **城市級數位孿生與智慧都市平台**：利用 TideGS 在單張消費級 GPU 上訓練十億級基元規模的城市規模場景，支援高保真新視角合成與即時渲染，無需部署昂貴的多 GPU 叢集。
2. **大規模自駕車與機器人場景重建**：處理連續街景或長距離軌道影像，將異向性高斯的聚合參數表卸載至 SSD，突破視訊記憶體瓶頸，實現記憶體受限環境下的可擴展訓練。
3. **文化資產與大型建築數位典藏**：針對古蹟、體育場或大型建築的密集影像採集，透過核外訓練框架維持高重建品質，管理數億個顯式場景基元與其球諧係數。
4. **基礎建設巡檢與礦區測繪**：應用於空拍影像的大規模三維重建，利用可見性誘導稀疏更新，僅活化當前視野內的高斯基元，降低大場景的訓練門檻。
5. **開放世界遊戲與元宇宙資產生產**：作為內容生產管線的後端，產生超大場景的顯式場景基元，並透過區塊虛擬化幾何實現資產的串流載入與局部更新。

### 實作前置條件

**資料需求**：連續軌跡影像（空拍、車載或環景序列）、精確的相機內外參（可透過 COLMAP 或 GNSS/INS 解算取得）、對應的初始點雲。SSD 需預留充足空間存放完整的聚合參數表與 Adam 優化器狀態（十億級基元約需數百 GB 至 TB 級）。

**運算需求**：單張 24 GB 以上視訊記憶體（VRAM）的 GPU（如 RTX 3090/4090）、128 GB 以上 CPU 記憶體作為第二級快取、高速 NVMe SSD（建議 PCIe 4.0/5.0 企業級，避免與系統碟共用）。

**技能需求**：熟悉 PyTorch 底層記憶體管理與 CUDA 程式設計、具備 3DGS 或 NeRF 訓練實務經驗、能進行 I/O 效能分析與儲存系統調校，並理解工作集與空間局部性的概念。

### 實作步驟建議

1. **資料預處理與空間分塊**：依據區塊虛擬化幾何，將點雲與相機批次按空間座標劃分為 SSD 對齊之區塊，確保相鄰高斯基元落在同一區塊，以最大化空間局部性。
2. **硬體階層配置**：建立 SSD-CPU-GPU 階層，設定 CPU DRAM 為中間快取層，並規劃視訊記憶體作為工作集快取而非持久參數儲存，預留足夠空間容納活躍的屬性向量與梯度。
3. **軌跡批次規劃**：設計連續的相機批次以最大化工作集時間局部性，使相鄰迭代的工作集重疊，利於軌跡自適應差分流式傳輸僅傳輸增量工作集差量。
4. **框架部署與參數調校**：部署 TideGS 核外訓練框架，調整區塊大小、階層式非同步管線深度、以及增量工作集差量的傳輸閾值，確保 I/O 與計算重疊效率最大化。
5. **增量驗證與品質確保**：先以百萬級基元驗證重建品質與數值穩定性，再擴展至十億級基元規模，全程監控 GPU 利用率、SSD 讀寫頻寬及快取命中率。
6. **產品化整合**：將訓練完成的顯式場景基元匯出為標準格式，或轉換至即時渲染引擎與數位孿生平台，銜接後續的應用開發。

### 潛在風險與注意事項

1. **I/O 頻寬瓶頸**：SSD 讀寫頻寬可能成為訓練瓶頸，建議採用企業級 NVMe 並預留足夠的過度配置空間；若頻寬不足，階層式非同步管線將無法有效遮蔽延遲。
2. **軌跡不連續風險**：若相機批次跳躍過大（如隨機抽樣而非連續軌跡），可見性誘導稀疏更新帶來的工作集重疊度將下降，導致軌跡自適應差分流式傳輸效益遞減，訓練速度可能驟降。
3. **區塊尺寸權衡**：區塊過大會傳輸過多非活躍高斯基元，浪費頻寬；過小則增加 I/O 請求數量與中繼資料負擔，需針對場景密度與 SSD 特性實驗調整。
4. **優化器狀態一致性**：核外最佳化涉及參數與 Adam 動量狀態的進出，需確保寫回（write-back）與讀取之間的版本一致性，避免數值錯置或梯度遺失。
5. **硬體壽命與散熱**：頻繁的隨機讀寫與長時間滿載運算會影響 SSD 壽命與 GPU 散熱，建議配置主動散熱並定期監控硬體健康度，重要場景應配置冗餘儲存。

### 與其他技術的整合建議

1. **與 COLMAP / 3DGS 生態整合**：將 TideGS 作為現有光柵化渲染管線的後端訓練引擎，直接接收標準點雲與相機參數，無需改動前端資料流程。
2. **與模型壓縮技術整合**：在 TideGS 完成可擴展訓練後，可銜接向量量化、蒸餾或剪枝技術，進一步壓縮屬性向量與球諧係數，降低部署時的模型容量與傳輸成本。
3. **與即時渲染引擎整合**：將輸出匯入 Unreal Engine、Unity 或自研渲染器，利用顯式場景基元實現城市規模場景的即時渲染，並結合區塊虛擬化實現資產的動態串流。
4. **與雲端儲存整合**：可將本地 SSD 層擴展至網路儲存（如 NVMe-oF 或高速物件儲存），支援多使用者協作與超大型場景的核外訓練，但需評估網路延遲對工作集切換的影響。
5. **與多 GPU 系統整合**：雖 TideGS 聚焦單 GPU 核外訓練，但可作為多節點叢集中的單卡訓練單元，進一步擴展模型容量並降低叢集整體的記憶體需求與成本。

### 給不同背景讀者的閱讀建議

**初學者**：建議先建立 3D 高斯潑濺與記憶體受限問題的基本直覺，理解「將視訊記憶體視為工作集快取而非持久參數儲存」的核心概念；實作細節如階層式非同步管線與差分流式傳輸可暫時略過，待熟悉標準記憶體內訓練後再深入。

**AI 工程師**：應重點研究區塊虛擬化幾何的程式碼實作與記憶體排程邏輯，評估自身資料集的相機軌跡是否具備足夠的時間局部性，以發揮軌跡自適應差分流式傳輸的最大效益，並針對 SSD 特性調校 I/O 與計算重疊的參數。

**研究人員**：可深入分析可見性誘導稀疏更新的理論基礎，並思考如何將此核外最佳化框架泛化至其他顯式神經表徵（如點雲神經網路）或結合隱式神經表徵的混合架構，探索更廣泛的核外訓練框架設計空間。

**產品經理**：建議聚焦單 GPU 硬體成本與大規模場景重建品質的商業權衡，評估 TideGS 取代昂貴多 GPU 叢集的可行性，並規劃與現有數位孿生平台或即時渲染管線的整合時程、資料流程與風險控管。
