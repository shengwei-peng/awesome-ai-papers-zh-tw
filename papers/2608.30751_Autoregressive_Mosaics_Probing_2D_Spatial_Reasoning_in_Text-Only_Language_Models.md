# 自迴歸馬賽克：探究純文字語言模型中的二維空間推理

## ⚡ TL;DR

純文字語言模型能否真正理解二維空間佈局，而非僅將描述轉譯為程式碼？
提出 AM-Bench，以翻譯任務控制程式碼能力，並以佈局任務測試開放式空間構圖。
模型皆能翻譯幾何，但佈局表現差異大；原始 SVG 可提升分數，且生成前僅存在提示隱含的粗略計畫。

## 摘要翻譯

僅以文字和程式碼訓練的大型語言模型（Large Language Models, LLMs）有時能夠生成可繪製可辨識圖像的程式。然而，目前尚不清楚這是否反映了二維空間佈局（2D spatial layout）的內部表徵（internal representation），抑或僅僅是將空間描述（spatial descriptions）翻譯為程式碼的能力。我們提出自迴歸馬賽克（Autoregressive Mosaics）基準 AM-Bench（自迴歸馬賽克基準），用以區分這些因素：首先，翻譯任務（translation task）會以文字描述一張圖片的完整指定幾何結構（fully specified geometry），並將其作為提示輸入模型，要求生成能產生該圖像的程式碼。其次，佈局任務（layout task）要求模型根據欠規範提示（underspecified prompt）組合一張圖像。在八個開放權重模型（open-weight models）的純文字與程式碼模型（text-and-code-only models）中，所有模型都能可靠地將指定的幾何結構翻譯為程式碼，但它們在開放式佈局任務上的表現卻有顯著差異，顯示這些差異無法單靠程式碼生成能力（code-generation ability）來解釋。輸出媒介消融實驗（output-medium ablation）進一步顯示，模型所使用的表達介面或媒介具有影響：將程序式程式碼（procedural code）改為原始 SVG（raw SVG），可提升所有模型的佈局分數。最後，探測模型啟動值（model activations）發現，生成前便已存在粗略的佈局計畫（coarse layout plan），但該計畫僅反映提示所隱含的佈局（layout implied by the prompt）。在生成過程中，模型追蹤的是演變中的幾何狀態（evolving geometric state），而非執行初始固定的計畫（initially fixed plan）。總體而言，這些結果表明，純文字語言模型（text-only language models）的二維空間表現同時取決於模型本身與輸出媒介（output medium），而無法單以程式碼生成能力來解釋。

### 核心貢獻（3～5點）
- 區分「翻譯能力」與「佈局能力」：透過翻譯任務（translation task）與佈局任務（layout task）的對照，說明模型在開放式佈局上的差異無法僅以程式碼生成能力（code-generation ability）解釋。
- 輸出媒介的重要性：輸出媒介消融實驗（output-medium ablation）顯示，將程序式程式碼（procedural code）改為原始 SVG（raw SVG）可提升所有模型的佈局表現。
- 內部表徵的動態性：探測模型啟動值（model activations）發現，模型在生成前雖有粗略佈局計畫（coarse layout plan），但生成過程中追蹤的是演變中的幾何狀態（evolving geometric state），而非執行初始固定計畫（initially fixed plan）。

### 適合對象
對大型語言模型空間推理、純文字模型視覺生成，以及程式碼生成介面設計感興趣的研究者與工程師；亦適合從事多模態評測基準設計與模型可解釋性研究的學者參考。

## 深度分析

#### 方法論解析

本研究提出 **AM-Bench（Autoregressive Mosaics Benchmark，自迴歸馬賽克基準）**，核心目標是將「空間構圖（spatial composition）」與「空間表達（spatial expression）」兩個能力分離。整個評測流程可視為一條四階段管線：**提示（prompt）→ 內部計畫（internal plan）→ 程式碼（program code）→ 光柵化幾何（rasterized geometry）**。在這個框架下，圖像被定義為一種 **自迴歸馬賽克（autoregressive mosaic）**：由模型輸出的程式碼經由 **確定性執行器（deterministic executor）** 執行後，渲染成小型光柵圖像。由於執行器是確定的，評分可以完全聚焦在模型產生的幾何描述是否正確，而不受渲染隨機性干擾。

AM-Bench 包含兩個互補任務：

1. **翻譯任務（translation task）**：提示中已經 **完整指定的幾何結構（fully specified geometry）** 以文字描述，模型只需將其轉譯為可執行程式碼。此任務作為 **程式碼生成能力（code-generation ability）** 的對照組，若模型在此失敗，問題出在語法或表達媒介，而非空間理解。
2. **佈局任務（layout task）**：提示是 **欠規範提示（underspecified prompt）**，模型必須自行決定圖像的 **空間佈局（spatial layout）**。此任務測量模型是否具備內部的二維空間構圖能力。

評分方式也配合任務性質區分：翻譯任務使用基於連續座標的 **精確面積幾何指標（exact-area geometric metric）**，不依賴畫布解析度，能精確比對模型輸出與參考幾何；佈局任務因無參考幾何，改由 **視覺語言模型（Vision Language Models, VLMs）** 擔任評判，並以人工評分者驗證 VLM 的排名訊號，確保自動評分的可靠性。

此外，研究設計了三組實驗：
- **實驗一（Exp. 1）**：行為層面比較所有模型在翻譯與佈局任務的表現差異。
- **實驗二（Exp. 2）**：進行 **輸出媒介消融實驗（output-medium ablation）**，比較 **程序式程式碼（procedural code）** 與 **原始 SVG（raw SVG）** 兩種輸出媒介對佈局分數的影響。
- **實驗三（Exp. 3）**：透過殘差流探針（residual stream probe）檢驗生成前是否存在可解碼的 **粗略佈局計畫（coarse layout plan）**，並輔以對幾何狀態的因果介入，判斷模型在生成過程中是依賴初始固定計畫，還是追蹤 **演變中的幾何狀態（evolving geometric state）**。

#### 實驗數據解讀

根據論文摘要與引言，實驗結果可歸納為四個主要發現：

1. **翻譯任務普遍可解，佈局任務差異顯著**  
   八個 **開放權重模型（open-weight models）** 在翻譯任務上都能可靠地將完整幾何描述轉為程式碼，顯示這些模型具備基本的繪圖語法能力。然而，在開放式佈局任務中，各模型表現出明顯落差。這說明佈局任務的瓶頸並非單純的程式碼生成能力，而是涉及更高階的空間構圖與內部知識。

2. **輸出媒介顯著影響空間表現**  
   當把輸出媒介從程序式程式碼換成原始 SVG 後，所有模型的佈局分數都提升。這是強有力的證據，指出 **輸出媒介（output medium）** 本身會限制或促進模型的空間表達。換句話說，模型腦中可能已有不錯的佈局，但受限於必須用特定程式語言表達，導致最終圖像變差；原始 SVG 由於更直接地對應幾何形狀，降低了表達負擔。

3. **生成前存在粗略佈局表徵，但僅反映提示所隱含的佈局**  
   透過探針模型 **啟動值（model activations）**，研究發現在生成程式碼之前，殘差流中已可解碼出粗略的空間佈局。然而，這個佈局只反映 **提示所隱含的佈局（layout implied by the prompt）**，而非模型自主規劃出的完整構圖。這暗示純文字 LLMs 在生成前並未進行類似人類的「先構思整張圖再下筆」的完整規劃。

4. **生成過程採用增量式幾何追蹤，而非執行固定計畫**  
   因果介入實驗顯示，模型在生成過程中持續追蹤 **演變中的幾何狀態（evolving geometric state）**，而非嚴格執行一個 **初始固定計畫（initially fixed plan）**。這與自迴歸模型逐 token 生成的本質一致：模型更像是「邊畫邊調整」，根據已產生的程式碼與對應幾何狀態決定下一步，而不是先完整規劃後再一次性輸出。

綜合來看，這些結果挑戰了「純文字 LLMs 只是學會把空間描述翻譯成程式碼」的簡化觀點，也同時反駁「模型內部已具備完整且獨立於媒介的 2D 空間表徵」的過度樂觀看法。真正的情況介於兩者之間：模型確實擁有某種程度的空間知識與動態追蹤能力，但其最終表現同時受限於模型本身與輸出媒介。

#### 與現有研究的比較

本研究在幾個關鍵點上與既有文獻形成對照與補充：

- **相較於識別基準（recognition benchmarks）**：傳統需要 **視覺輸入（visual input）** 的視覺理解基準無法評估純文字模型。AM-Bench 透過文字提示與程式碼輸出，讓僅接受文字與程式碼訓練的模型也能被系統性評測。
- **相較於生成式評估（generative evaluations）**：過去觀察到 GPT-4 能用 TikZ 畫出可辨識的獨角獸（unicorn），但這類評估通常只檢視 **最終輸出（final output）**，無法區分「模型不會構圖」與「模型不會用程式碼表達構圖」。AM-Bench 透過翻譯任務與佈局任務的分離，首次明確拆解這兩個因素。
- **與 Othello-GPT 及棋類探針研究的關聯**：Othello-GPT 證明僅看序列的模型內部可恢復棋盤表徵，後續在西洋棋（chess）等領域被複製與擴展。本研究的 **實驗三（Exp. 3）** 採用類似的探針方法，但將問題從離散棋盤推廣到連續二維幾何空間，並加入容量控制探針與對照任務，降低虛假相關的風險。
- **對「湧現能力（emergent abilities）」討論的呼應**：Schaeffer 等人曾警告，表面上的湧現現象可能是評量指標造成的假象。AM-Bench 透過連續座標的精確面積指標與 VLM+人工雙重驗證，試圖避免單一指標過度簡化模型能力。

主要限制在於：實驗僅涵蓋 **開放權重模型（open-weight models）**，未納入 GPT-4 等閉源模型；此外，佈局任務依賴 VLM 評判，雖然有人工驗證，但對於抽象或風格化圖像的評分仍可能存在主觀偏差。最後，研究所用的光柵圖像尺寸較小，是否能推廣到高解析度或複雜場景，仍有待檢驗。

#### 可重現性評估

本研究在可重現性方面表現良好。作者明確表示將釋出所有程式碼、提示與生成結果於專案頁面（Project Page）。由於實驗對象是 **開放權重模型（open-weight models）**，其他研究者可以下載相同權重、使用相同提示複製實驗。評測流程中的 **確定性執行器（deterministic executor）** 也確保了渲染階段不會引入額外隨機性，進一步提升可重複性。

不過，仍有幾點值得注意：
- 若專案頁面未同時公開完整的超參數（如溫度、top-p、最大生成长度）與模型清單，重現時可能出現細微差異。
- VLM 評判器的版本與提示模板對佈局分數影響可能很大，建議未來釋出完整的 VLM judge prompt 與人工評分協議。
- 原始 SVG 與程序式程式碼兩種媒介的轉換細節（例如座標系、顏色編碼、形狀語法）需要完整文件，才能確保消融實驗可被精確複製。

整體而言，AM-Bench 在開源資料與透明流程上的承諾，使其成為一個適合後續研究接續使用的基準。

#### 未來研究方向

基於本研究的發現，以下幾個方向值得進一步探索：

1. **擴展至閉源與多模態模型**  
   將 AM-Bench 應用於 GPT-4、Claude 等閉源模型，並與開放權重模型比較，可更清楚了解模型規模與訓練資料對空間構圖的影響。也可納入具視覺能力的模型，觀察視覺輸入是否改變內部佈局表徵。

2. **多樣化輸出媒介的系統性比較**  
   除了程序式程式碼與原始 SVG，可進一步測試 TikZ、Matplotlib、ASCII art、HTML/CSS 甚至 3D 描述語言，建立「輸出媒介—空間表現」的對照圖譜，幫助設計更適合 LLMs 的繪圖介面。

3. **從增量追蹤到主動規劃**  
   研究發現模型傾向邊畫邊調整，未來可探討是否能透過 chain-of-thought、scratchpad 或顯式規劃提示，促使模型在生成前形成更完整的佈局計畫，並檢驗這種規劃是否真的能提升最終圖像品質。

4. **機械式可解釋性與表徵編輯**  
   既然殘差流中可解碼出粗略佈局，下一步可嘗試直接編輯這些表徵，觀察是否能因果性地改變生成圖像的佈局，從而確認內部表徵的因果角色，而不只是相關性。

5. **微調與專門訓練**  
   針對佈局任務收集大規模（提示、佈局計畫、程式碼）三元組，進行監督式微調或強化學習，觀察是否能顯著提升純文字模型的空間構圖能力，並分析改善來自於空間理解還是輸出格式學習。

6. **跨解析度與真實世界圖表生成**  
   將光柵尺寸擴大、引入更複雜的場景（如建築平面圖、科學圖表、漫畫分鏡），檢驗 AM-Bench 的結論是否仍能成立，並發展更貼近實際應用的評測版本。

7. **三維空間推理的延伸**  
   若二維佈局已能在純文字模型中部分浮現，可進一步探討三維空間表徵（如 OBJ、GLTF 描述）是否同樣存在，以及輸出媒介對 3D 構圖的影響是否更為顯著。

## 論文問答

**Q1：這篇論文試圖回答什麼核心問題？**

A：這篇論文探討純文字與程式碼訓練的大型語言模型（LLMs）是否具備可用的二維空間佈局內部表徵，還是僅僅學會把空間描述翻譯成程式碼。作者以先天失明畫家能畫出透視場景，以及 GPT-4 能用 TikZ 畫出可辨識獨角獸為例，指出人類與模型都可能在不直接接收視覺輸入的情況下，表現出某種空間能力。因此，核心問題在於：模型究竟是在「構圖」還是在「轉譯」？這個區分對理解模型內部機制至關重要。

**Q2：為什麼現有的識別基準與生成式評估無法區分空間構圖與空間表達？**

A：現有的識別基準通常需要視覺輸入，因此不適用於純文字語言模型；而生成式評估只檢視最終輸出的圖像，無法拆解「模型是否構想出好佈局」與「模型是否能用程式碼或標記語言把佈局表達出來」。一張失敗的圖像可能源於三種不同原因：內部沒有合適佈局、無法把佈局轉成可執行表徵，或是輸出媒介本身限制了表達方式。這些因素互相糾纏，使得單看最終圖像難以判斷真正的瓶頸所在。

**Q3：區分空間構圖與空間表達為什麼重要？**

A：只有將兩者分離，才能判斷模型是否真正擁有內部二維空間模型，還是僅具備程式碼生成能力。這對改進模型架構、設計更適合的輸出媒介，以及建立更精確的評測基準都有直接幫助。如果問題出在表達媒介而非構圖能力，那麼改換輸出格式就可能顯著提升生成品質，而不必重新訓練整個模型。

**Q4：AM-Bench 的核心設計是什麼？它包含哪兩項互補任務？**

A：AM-Bench（自迴歸馬賽克基準）把圖像視為由程式生成、再經確定性執行器渲染的小型光柵圖像，稱為自迴歸馬賽克。第一項是翻譯任務，提示中完整指定圖片的幾何結構，模型只需把這段空間描述轉成程式碼；第二項是佈局任務，提示僅提供欠規範描述，模型必須自行決定空間安排。翻譯任務作為對照，可隔離程式碼生成能力；佈局任務則用來測量真正的空間構圖能力。

**Q5：相較於以往研究，AM-Bench 的主要創新在哪裡？**

A：AM-Bench 首次系統性地將空間構圖與空間表達分開評估，並提供連續座標下的精確面積幾何指標，使翻譯任務的分數不受畫布解析度影響。對於沒有參考幾何的佈局任務，則採用經人類評分者驗證的視覺語言模型（VLM）進行評判。此外，研究還加入輸出媒介消融實驗與模型啟動值探測，從行為與內部表徵兩個層面檢驗空間推理。

**Q6：為什麼選擇程序式程式碼、原始 SVG 與光柵渲染作為輸出媒介？**

A：程序式程式碼能測試模型把空間描述轉換為可執行繪圖指令的能力，是評估空間表達的關鍵介面；原始 SVG 則作為對照，用來檢驗輸出媒介本身是否會限制佈局表現。最終透過確定性執行器將程式渲染為光柵圖像，確保所有模型在相同條件下被評估，並讓視覺語言模型與人類評分者能一致地檢視結果。

**Q7：實驗評估了哪些模型？翻譯任務的整體表現如何？**

A：研究評估了八個開放權重的純文字與程式碼模型。結果顯示，所有模型都能可靠地將完整指定的幾何結構翻譯成程式碼，代表程式碼生成能力本身並非主要瓶頸。這項發現也確認，若僅用翻譯任務評估，會高估模型的實際空間構圖能力。

**Q8：佈局任務的結果揭示了什麼？**

A：在開放式佈局任務中，不同模型的表現出現顯著差異，顯示空間構圖能力並非所有模型都具備。由於所有模型在翻譯任務上都表現良好，這些差異無法單純用程式碼生成能力來解釋。換句話說，能寫出正確繪圖程式並不代表模型能自行構想出合理的二維空間佈局。

**Q9：輸出媒介消融實驗發現了什麼？**

A：當研究者把程序式畫布程式碼換成原始 SVG 後，所有模型的佈局分數都提升了。這個結果清楚顯示，輸出媒介或表達介面會顯著影響模型的空間表現，甚至可能成為限制因素。因此，模型在程序式程式碼上表現不佳，不一定代表它缺乏內部佈局能力，而可能只是因為該媒介不利於表達空間結構。

**Q10：AM-Bench 在實務上可以如何應用？**

A：AM-Bench 可用來評估文字模型在生成圖表、使用者介面佈局、技術插圖或程式化圖像時的能力。透過分離翻譯與佈局兩項任務，開發者能精確定位失敗來源，是模型理解不足、還是輸出格式不合適。這有助於在產品設計階段選擇最適合的繪圖介面，並針對弱項進行改進。

**Q11：對於想要部署繪圖能力語言模型的產品團隊，這篇研究有什麼啟示？**

A：產品團隊不應假設模型程式碼生成能力強就等同於空間推理能力強，兩者需要分開檢驗。在選擇輸出媒介時，原始 SVG 可能比程序式程式碼更容易讓模型產生合理佈局，值得優先考慮。此外，若佈局表現不佳，可以透過改變介面、增加多輪確認或引入外部幾何驗證來補強，而不一定需要重新訓練模型。

**Q12：這項研究如何改變我們對純文字 LLM 空間推理的理解？**

A：研究指出，二維空間表現同時取決於模型本身與輸出媒介，不能只用程式碼生成能力來解釋。它也挑戰了「模型能畫出可辨識圖像就代表有內部空間模型」的直覺，因為失敗可能來自表達限制而非理解缺失。此外，探測結果顯示模型在生成過程中是逐步追蹤演變中的幾何狀態，而非執行一開始就固定的佈局計畫，這與傳統規劃式執行有明顯區別。

**Q13：這項研究有哪些限制值得注意？**

A：本研究主要使用開放權重模型，結果是否能直接推廣到閉源商業模型仍需進一步驗證。佈局任務依賴視覺語言模型評分，雖然已用人類評分者驗證，但 VLM 仍可能存在特定偏誤。此外，啟動值探測只能揭示提示所隱含的粗略佈局，並未證明模型在生成前就已形成完整且獨立的空間計畫。

**Q14：模型在哪些情況下容易出現佈局失敗？**

A：當提示屬於欠規範、需要模型自行決定元素位置與關係時，模型容易出現佈局失敗。由於模型在生成過程中傾向追蹤演變中的幾何狀態，而非嚴格執行初始固定計畫，長序列生成可能導致整體結構不一致或偏離提示語意。此外，若輸出媒介對空間表達不友善，即使模型具備某種內部佈局概念，也難以正確轉譯成最終圖像。

**Q15：這篇論文為未來研究指出了哪些方向？**

A：未來可以設計更適合空間表達的輸出媒介，例如結合原始 SVG 與高階結構約束的混合介面。研究者也可以探索在訓練階段加入明確的佈局目標，以強化模型的內部空間表徵。此外，將啟動值探測與因果干預進一步結合，並把評測擴展到更複雜的真實場景與多模態模型，將有助於更全面理解語言模型中的二維空間推理。

## 實務應用指南

### 適用場景

1. **文字驅動的向量圖示與圖表生成**  
   當產品需要將規格書、技術文件或自然語言描述轉為可執行的 SVG／Canvas 程式碼時，可採用 AM-Bench 的「翻譯任務」模式，先驗證模型是否能穩定將完整幾何描述轉為程式碼，再進入開放式佈局生成。

2. **UI／線框稿（Wireframe）快速原型**  
   設計師或產品經理可用欠規範提示要求模型生成介面佈局。由於研究顯示原始 SVG 較程序式程式碼更能提升佈局表現，建議優先讓模型輸出 SVG，再匯入 Figma、Sketch 等設計工具進行人工調整。

3. **程式化幾何教學與輔助學習**  
   在數學或程式教育場景中，可利用翻譯任務讓學生比對「文字幾何描述」與「程式碼輸出」，並用佈局任務評估學生提示工程能力；同時藉由確定性執行器即時渲染結果，提供視覺化回饋。

4. **資料視覺化草圖生成**  
   將資料敘事需求（如「長條圖比較三個季度營收」）轉為初步視覺草圖。由於模型在生成過程中追蹤的是演變中的幾何狀態而非固定計畫，建議將生成過程拆解為多輪增量建構，以降低整體佈局錯誤。

5. **無障礙觸覺圖形輔助**  
   將空間描述轉為可執行的向量圖形後，再輸出至觸覺繪圖機或 3D 列印流程。翻譯任務可確保幾何關係精確，佈局任務則用於從簡略敘述產生可辨識的圖形。

---

### 實作前置條件

**資料準備**
- 一組「完整指定幾何結構」的提示與對應程式碼／原始 SVG 配對，用於翻譯任務的監督與評估。
- 一組「欠規範提示」，用於佈局任務的開放式生成。
- 視覺語言模型（VLM）評判提示範本，以及經人類驗證的小型標準集，用於校正 VLM 評分偏差。
- 若進行啟動值探測，需準備殘差流標記與幾何狀態標籤。

**運算資源**
- 可執行開放權重模型推論的 GPU（建議至少 24 GB VRAM，依模型規模調整）。
- 確定性執行器環境（如隔離的 Python／Node.js 容器）用於渲染程式碼並產生光柵圖像。
- 若進行探針實驗，需額外儲存中間啟動值與訓練輕量探針模型。

**技能需求**
- 熟悉 Python、SVG 語法與 Canvas／TikZ 等程序式繪圖介面。
- 具備 LLM 推論、提示工程與基礎評測設計經驗。
- 了解幾何度量（如面積重疊、IoU）與視覺語言模型評判流程。
- 若要做因果介入或探針，需具備 Transformer 內部表徵分析基礎。

---

### 實作步驟建議

1. **區分任務類型**  
   先將應用場景對應到「翻譯任務」（輸入已完整描述幾何）或「佈局任務」（輸入僅有主題或粗略描述），兩者評測方式不同，不可混用。

2. **設計提示模板**  
   為翻譯任務撰寫結構化幾何描述；為佈局任務保留適度開放性，但可加入風格或構圖關鍵字以引導輸出。

3. **選擇輸出媒介**  
   根據論文發現，原始 SVG 通常優於程序式程式碼。建議優先採用 SVG 作為輸出媒介，若業務需要程式碼可執行性，再考慮 Canvas／TikZ。

4. **建置確定性執行與渲染管線**  
   將模型輸出的程式碼或 SVG 送入固定版本的執行環境，產生統一尺寸的光柵圖像，作為後續評分與人工檢視的依據。

5. **實作翻譯任務評分**  
   使用連續座標下的面積型幾何度量，比對渲染結果與參考幾何，避免解析度造成的評分偏差。

6. **建立佈局任務評判機制**  
   採用至少兩個 VLM 作為評委，並以人類評分進行校正；記錄評委間一致性，必要時調整提示或引入人類最終裁決。

7. **執行基線評測與輸出媒介消融實驗**  
   在相同提示下比較不同輸出媒介的佈局分數，量化媒介對任務表現的影響。

8. **視需求進行內部表徵探測**  
   若需理解模型是否具備內部佈局計畫，可在生成前後擷取殘差流，訓練輕量探針並搭配因果介入驗證。

9. **迭代優化與產品化**  
   根據評測結果調整提示、輸出媒介或後處理流程，並將執行器與評分模組封裝為可重複呼叫的 API。

---

### 潛在風險與注意事項

- **混淆程式碼生成能力與空間推理能力**  
  模型可能擅長寫繪圖程式碼，卻不擅長構圖。應同時執行翻譯與佈局任務，避免將佈局失敗誤判為語法問題。

- **輸出媒介會顯著影響結果**  
  不要預設某種程式語言或格式最適合。建議在產品上線前進行輸出媒介消融實驗，並保留切換媒介的彈性。

- **模型傾向增量建構而非執行固定計畫**  
  生成過程中模型追蹤演變中的幾何狀態，因此長提示或複雜場景容易累積錯誤。可透過分段生成、中間檢查點或人機協作來降低風險。

- **VLM 評委存在偏差**  
  視覺語言模型可能偏好特定風格或構圖，需以人類驗證校正，並在關鍵應用中保留人工最終審核。

- **欠規範提示導致輸出不穩定**  
  佈局任務本質上無唯一正解，不同執行間結果差異大。建議設定明確的評分維度（如正確性、美觀性、可辨識度）並多次採樣。

- **安全與程式碼執行風險**  
  執行模型生成的程式碼時，必須使用沙箱環境，防止惡意程式碼或無限迴圈影響系統。

### 與其他技術的整合建議

- **與擴散模型或圖像編輯模型搭配**  
  將純文字語言模型產生的向量佈局作為結構草圖，再交由擴散模型進行風格化或細節渲染，可兼顧結構正確性與視覺品質。

- **匯入向量圖形編輯器**  
  原始 SVG 輸出可直接匯入 Figma、Adobe Illustrator 或 Inkscape，讓設計師在自動生成基礎上進行後續精修。

- **作為 CAD 或建築繪圖的前處理器**  
  將自然語言需求轉為初步幾何配置後，再輸入參數化 CAD 工具進行工程驗證與尺寸調整。

- **結合多模態模型進行雙重驗證**  
  使用 VLM 或人機協作檢查生成圖像是否符合提示語意，並將回饋納入下一輪提示工程。

- **嵌入 RAG 系統以引用設計模式**  
  在佈局任務中檢索既有的優秀 SVG 範例或幾何模板，可提升模型對特定主題（如國旗、圖示、流程圖）的佈局穩定度。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先聚焦論文的核心區分：「翻譯任務」測試模型會不會把文字幾何描述轉成程式碼，「佈局任務」測試模型會不會自己構圖。接著注意「輸出媒介很重要」這個發現——同樣的模型，改用原始 SVG 通常畫得更好。理解這兩點，就能掌握這篇論文對實際應用的最大啟示。

**AI 工程師**  
請重點閱讀評測管線與輸出媒介消融實驗的實作細節，包括確定性執行器、連續座標幾何度量、VLM 評委校正，以及殘差流探針的設計。這些方法可直接遷移到其他需要評估文字模型空間能力的專案，並幫助你在選擇輸出格式時做出資料導向的決策。

**研究人員**  
論文對「內部表徵是否存在」的探討值得深入：生成前的粗略佈局計畫僅反映提示所隱含的佈局，而生成過程中模型追蹤的是演變中的幾何狀態。建議關注探針方法、因果介入設計，以及這些結果對「純文字模型是否具備可用二維空間表徵」這一理論問題的意涵。

**產品經理**  
這篇論文提醒：不要因為模型會寫繪圖程式碼，就以為它懂得構圖。在規劃文字生成圖像功能時，應優先選擇原始 SVG 這類對模型較友善的輸出媒介，並為開放式生成預留人工審核與多次採樣的機制。同時，可將翻譯任務作為技術可行性門檻，佈局任務作為產品體驗的上限指標。
