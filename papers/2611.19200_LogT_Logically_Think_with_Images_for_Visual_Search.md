## ⚡ TL;DR

視覺語言模型在細粒度視覺搜尋任務上表現不佳，難以邏輯地判斷何時及如何有效使用放大工具。
本文提出全自動 SFT 資料引擎 LogT，以邏輯鏈引導生成結構化工具使用軌跡，模擬人類解題策略。
LogT-SFT 以更少資料與 GPU 時數超越 SOTA，搭配簡單 RL 領先 9.59 分，工具使用更準確高效。

## 摘要翻譯

運用圖像進行思考使視覺語言模型 (VLMs) 能夠使用外部放大工具進行細粒度視覺搜尋。近期研究採用監督式微調 (SFT) 與強化學習 (RL) 並結合工具專屬設計來實現此能力。然而，在實現邏輯推理的同時兼顧準確且高效的工具使用仍是一項重大挑戰。為解決此問題，我們將焦點從增加 RL 複雜度轉移開來，轉而將 SFT 資料品質識別為關鍵瓶頸。接著，我們提出 LogT（全名為 Logically Think with Images），一個全自動的 SFT 資料引擎，明確要求邏輯鏈引導推理。LogT 生成一個 SFT 資料集，其特色在於包含挑戰性的視覺基礎問題，以及具備類人邏輯的結構化工具使用軌跡。我們透過在該資料集上微調兩個基礎模型——Qwen2.5-VL-7B 與 InternVL3.5-8B，並在七個基準測試集上進行評估，以驗證我們的方法。我們證明，基於 Qwen2.5-VL-7B 的 LogT-SFT 在效能上超越了結合 SFT 與 RL 訓練的最先進技術，儘管其使用的資料量少 3.1 倍，GPU 小時數更是少超過 120 倍。此外，在 LogT-SFT 上套用無需工具專屬設計的簡單 RL 方法，所得到的模型以 9.59 分的顯著領先幅度超越了採用複雜 RL 設定的先前方法。除了顯著的效能提升之外，我們的模型展現出更高的工具使用準確率與效率，以及更為結構化且邏輯一致的推理軌跡，直接驗證了我們方法的有效性。

### 核心貢獻（3～5點）
- **問題重新定位**：跳脫「增加 RL 複雜度」的傳統思路，首創性地指出 SFT 資料品質才是瓶頸所在，為視覺搜尋領域開闢新研究方向。
- **LogT 資料引擎**：提出全自動 SFT 資料引擎 LogT，強制執行邏輯鏈引導推理，自動生成兼具挑戰性視覺基礎問題與類人邏輯結構化工具使用軌跡的高品質資料集。
- **極高訓練效率**：基於 Qwen2.5-VL-7B 的 LogT-SFT 以少 3.1 倍的資料量與少超過 120 倍的 GPU 小時數，效能仍超越結合 SFT 與 RL 的最先進技術。
- **簡單 RL 即可大幅領先**：在 LogT-SFT 基礎上僅套用無工具專屬設計的簡單 RL 方法，即以 9.59 分的顯著幅度超越採用複雜 RL 設定的先前方法。
- **多面向品質提升**：模型在工具使用準確率、效率，以及推理軌跡的結構化與邏輯一致性方面皆有具體提升，全面驗證方法有效性。

### 適合對象
從事視覺語言模型 (VLMs)、多模態推理、強化學習後訓練 (post-training)、思維鏈 (CoT) 與工具整合使用 (tool-use) 研究之學者與工程師；以及對自動化高品質訓練資料生成、視覺搜尋與細粒度視覺理解應用感興趣之業界研發人員。

## 深度分析

#### 方法論解析

LogT 的核心方法論建立在對現有「思考影像」(thinking with images) 訓練範式的批判性反思之上。論文首先指出，現有方法普遍採用「監督式微調 (SFT) + 強化學習 (RL)」的兩階段後訓練 (post-training) 流程，但實際上 SFT 階段僅教會模型熟悉 Zoom-in 工具的呼叫格式，而真正困難的「何時呼叫」與「如何精確定位感興趣區域 (region-of-interest)」的邏輯推理能力並未有效建立。基於此觀察，作者將研究重心從設計更複雜的 RL 機制轉向提升 SFT 資料品質。

**資料生成引擎的雙軌設計**

LogT 採用全自動化的資料合成流程，僅依賴開源模型，分為兩個品質維度進行優化：

1. **問答品質 (QA Quality)**：在合成問題時，除了提供完整影像外，還注入詳細的視覺上下文 (detailed visual contexts)，使生成的問題更具挑戰性，能針對細粒度視覺細節 (fine-grained visual details) 進行提問。接著透過嚴格的過濾機制保留高品質的問答對。

2. **推理軌跡品質 (Reasoning Trace Quality)**：這是 LogT 最具創新性的部分。系統首先建構模仿人類解題策略的「邏輯鏈」(logic chains) 作為骨架，再以此引導視覺語言模型 (VLM) 生成結構化的工具使用軌跡 (tool-use traces)。

**三種人類解題策略的邏輯鏈設計**

LogT 根據基礎模型在 average@8 指標下的表現，將問題分為三類並對應不同的邏輯鏈模板：

- **直接回答 (Direct Answering)**：當 average@8 = 1 時，代表基礎模型已能穩定正確回答，此時合成不呼叫 Zoom-in 的直接推理軌跡，避免不必要的工具呼叫以提升效率。
- **多跳推理 (Multi-hop Reasoning)**：針對中等難度問題，邏輯鏈指定依序聚焦於不同影像區域，逐步提取資訊後整合得出答案。
- **窮舉搜尋 (Exhaustive Search)**：針對高難度問題，邏輯鏈要求系統性地檢查多個候選區域，逐一排除後定位正確答案。

這種分層設計使生成的推理軌跡不僅格式正確，更具備人類解題時的策略性思維。

**邏輯鏈引導的軌跡合成**

邏輯鏈作為「骨架」明確指定關鍵工具使用步驟（例如「Step #1: Building (zoom-in on) I0」、「Step #2: Text (zoom-in on) I1」），然後引導 VLM 據此生成完整的結構化推理軌跡。這種「先設計骨架再填充內容」的兩階段生成方式，有效避免了直接讓模型自由生成時容易出現的邏輯跳躍或工具誤用問題。

#### 實驗數據解讀

**核心效能結果**

論文以 Qwen2.5-VL-7B 與 InternVL3.5-8B 兩個基礎模型進行實驗，在七個基準測試集 (benchmark test sets) 上評估。關鍵數據如下：

- **LogT-SFT (基於 Qwen2.5-VL-7B)**：僅使用 5.4k 至 7.1k 筆合成資料進行 SFT，即超越採用 SFT + RL 完整訓練流程的最先進模型 Mini-o3-RL，且資料量減少 3.1 倍、GPU 小時減少超過 120 倍。
- **LogT-RL**：在 LogT-SFT 基礎上施加「無工具專屬設計的簡單 RL 方法 (simple RL recipe without tool-specific design)」，最終以 9.59 點的顯著領先幅度 (substantial margin) 超越所有先前方法。

**效率指標的雙重驗證**

除了整體效能提升外，LogT 在兩個關鍵維度上展現優勢：

1. **工具使用準確率 (Tool-use Accuracy)**：模型能更精確地判斷何時該呼叫 Zoom-in，避免在簡單問題上過度使用工具。
2. **工具使用效率 (Tool-use Efficiency)**：在需要工具的場景中，呼叫次數更少且定位更準確，減少冗餘的視覺搜尋。

**人類評估的質性驗證**

論文進一步進行人類評估，結果顯示 LogT 生成的推理軌跡在「連貫性」與「邏輯一致性 (logically consistent)」上優於基線方法。這項結果直接驗證了邏輯鏈引導機制的有效性——不僅最終答案正確，推理過程本身也更具結構性與可解釋性。

**消融實驗的隱含訊息**

雖然完整消融實驗細節未在提供的文本中展開，但從方法論描述可推斷：移除邏輯鏈引導、直接讓模型生成軌跡，會導致推理品質顯著下降，這凸顯了「先建構邏輯骨架」這一步驟的關鍵貢獻。

#### 與現有研究的比較

**相較於 DeepEyes-RL 與 Chain-of-Focus 系列**

DeepEyes 與 Chain-of-Focus 同樣採用 SFT + RL 兩階段訓練，並設計了工具相關獎勵 (tool-related rewards) 來激勵 Zoom-in 使用。LogT 的差異化在於：(1) 不依賴複雜的獎勵工程；(2) 將資源投入前置的 SFT 資料品質，而非後續的 RL 調優；(3) 最終以更少的計算成本達到更高效能。

**相較於 Pixel Reasoner 系列**

Pixel Reasoner 採用 SFT 與 RL 並重的策略，試圖透過兩階段訓練同時提升工具熟悉度與推理能力。LogT 的實驗結果顯示，當 SFT 資料品質足夠高時，RL 階段的複雜度可以大幅降低——簡單的基於結果的獎勵 (outcome-based rewards) 即足以帶來顯著提升。

**相較於 Mini-o3 系列**

Mini-o3 是目前最強的開源對手，採用 SFT + RL 完整流程。LogT-SFT 以純 SFT 方式即超越 Mini-o3-RL，而 LogT-RL 更以 9.59 點的大幅領先確立新標竿。這項結果對「RL 必要性」的傳統認知提出了挑戰。

**方法論層面的定位**

LogT 的研究定位可歸納為「資料中心」(data-centric) 路線，與「模型/演算法中心」(model/algorithm-centric) 路線形成對比。論文的隱含主張是：在後訓練階段，資料品質的邊際效益高於 RL 演算法複雜度的邊際效益。

**現有方法的侷限性反思**

論文也坦誠點出先前方法的根本挑戰：(1) 過程獎勵模型 (PRMs) 雖在非視覺工具上展現潛力，但用於訓練 VLM 思考影像時面臨可擴展性 (scalability) 不足與計算成本 (compute cost) 過高的問題；(2) 現有 RL 設計難以同時兼顧工具呼叫的「準確性」與「效率」。

#### 可重現性評估

**資料集的可重現性**

LogT 聲稱其資料引擎「全自動化」且「僅依賴開源模型」，這在可重現性上是正面訊息。然而，論文中未明確說明：

- 開源模型的具體版本與組合
- 邏輯鏈模板的完整規格
- 過濾機制的具體準則與閾值

這些細節對於完全重現資料合成流程至關重要，但從提供的文本中尚無法確認其公開程度。

**模型權重的可重現性**

論文基於 Qwen2.5-VL-7B 與 InternVL3.5-8B 兩個公開基礎模型進行訓練，這兩個模型本身已開源。然而，LogT-SFT 與 LogT-RL 的最終權重是否釋出、訓練超參數是否完整公開，在提供的文本中未明確說明。

**訓練流程的可重現性**

論文中提及「簡單的 RL 方法 (simple RL recipe) 無需工具專屬設計」，但具體的 RL 演算法（例如 GRPO、PPO 等）、獎勵函數設計、訓練超參數等關鍵細節需要查閱完整論文才能評估。

**整體評估**

從方法論描述來看，LogT 的核心創新在於「邏輯鏈引導的資料合成策略」，這是一個相對易於實作的概念。但要達到論文中聲稱的效能，可能需要在多個工程細節上進行精細調校，這對獨立重現構成一定挑戰。建議關注後續是否釋出完整的程式碼、資料集與模型權重。

#### 未來研究方向

**邏輯鏈機制的擴展**

當前 LogT 的邏輯鏈僅針對 Zoom-in 工具設計，未來可探索：

1. **多工具整合**：將邏輯鏈擴展至其他視覺工具（如裁切、OCR、物件偵測），構建統一的工具使用推理框架。
2. **動態邏輯鏈生成**：目前邏輯鏈依賴預定義模板，未來可研究讓模型自主生成邏輯鏈，實現更靈活的解題策略。
3. **跨任務遷移**：將邏輯鏈的概念從視覺搜尋擴展至視覺推理、視覺問答等更廣泛的視覺任務。

**資料品質的進一步提升**

1. **難度分層的細化**：目前僅以 average@8 = 1 作為簡單問題的判準，可探索更細粒度的難度分層，使邏輯鏈設計更精準。
2. **多模態邏輯鏈**：將邏輯鏈從純文本擴展為包含視覺元素的結構化表示，可能更貼近人類的視覺推理過程。
3. **資料規模的擴展實驗**：目前僅使用 7.1k 筆資料即達到 SOTA，系統性地探索資料規模與效能的關係將是有價值的研究方向。

**RL 階段的重新定位**

LogT 的結果顯示，當 SFT 品質足夠高時，簡單的 RL 即可帶來顯著提升。這開啟了新的研究方向：

1. **RL 的邊際效益分析**：系統性研究在不同 SFT 品質水準下，RL 的邊際貢獻如何變化。
2. **RL 獎勵設計的簡化**：探索在高品質 SFT 基礎上，最簡單且最有效的 RL 獎勵設計。
3. **過程監督的復興**：當 SFT 已建立良好的推理骨架後，過程獎勵模型 (PRMs) 可能重新變得可行且有效，這值得進一步探索。

**評估方法的完善**

1. **推理品質的自動化評估**：目前依賴人類評估推理軌跡品質，未來可開發自動化的推理品質評估指標。
2. **工具使用效率的標準化**：建立統一的工具呼叫效率基準，使不同方法間的比較更公平。
3. **泛化能力的深入分析**：評估 LogT 訓練的模型在未見過的視覺搜尋任務上的泛化表現。

**實際應用探索**

1. **醫療影像分析**：將邏輯鏈引導的視覺搜尋應用於醫療影像的細粒度分析。
2. **遙感影像解讀**：處理大尺寸遙感影像中的目標定位與識別。
3. **文件理解**：結合 OCR 與視覺搜尋，處理複雜文件版面中的資訊提取。

**理論層面的深化**

LogT 的成功也提出了有趣的理論問題：為什麼高品質 SFT 資料能如此顯著地降低對複雜 RL 的需求？這與「獎勵設計空間的簡化」或「策略空間的有效約束」有何關聯？這些問題的解答將有助於建立更系統性的後訓練理論框架。

## 論文問答

**Q1：視覺語言模型（VLMs）在處理視覺搜尋任務時面臨什麼根本性問題？為什麼這個問題難以解決？**
A：視覺語言模型透過視覺編碼器與投影層將高階視覺線索對齊到文本嵌入空間，但這個對齊過程會造成不可逆的資訊損失，使得模型在需要細粒度視覺搜尋的任務上表現不佳。即使加入文本思維鏈（CoT）推理也無法解決此問題，因為純文本推理無法恢復已經遺失的視覺細節資訊。這正是促使研究者引入「以圖思考」（thinking with images）機制，讓模型能夠透過外部工具（如 Zoom-in 放大工具）擷取額外視覺資訊並與文本推理交錯進行的根本原因。

**Q2：現有「以圖思考」方法的主要限制是什麼？為什麼單純增加強化學習（RL）的複雜度無法有效解決？**
A：現有方法通常採用「監督式微調（SFT）冷啟動 + 強化學習（RL）」的兩階段後訓練流程，但作者分析發現，效能提升主要來自模型對工具呼叫格式的熟悉度，而非真正學會邏輯性地推理「何時」與「如何」呼叫工具。雖然使用過程獎勵模型（PRMs）進行逐步過程監督在非視覺工具的推理上展現初步成效，但訓練專門用於「以圖思考」的 PRMs 仍處於探索不足的狀態，主要受限於可擴展性與高昂的計算成本。因此，與其設計更複雜的 RL 機制，不如從根本上改善 SFT 資料品質。

**Q3：為什麼作者認為 SFT 資料品質是關鍵瓶頸？這個觀點對整個領域有何重要啟示？**
A：作者透過實驗分析指出，現有 SFT 資料的品質限制了模型學會邏輯推理與精確工具使用的能力，這使得後續的 RL 階段只能進一步強化格式遵循，而非真正改善推理品質。這項洞察挑戰了領域內普遍認為「必須仰賴複雜 RL 才能突破效能天花板」的假設，轉而強調在 SFT 階段投入更多算力與心力來提升資料品質，反而能帶來更顯著且更高效的整體提升。這對資源有限的研究團隊尤其重要，因為它提供了一條不需龐大 RL 計算資源也能達到最先進效能的可行路徑。

**Q4：LogT 方法的核心設計理念是什麼？它如何運作？**

### 與其他技術的整合建議

**與 RAG 系統整合**
- 將 LogT 的視覺搜尋能力作為多模態 RAG 的視覺檢索模組，處理包含圖片的知識庫查詢。
- 文字推理部分可與現有的 RAG pipeline 串接，實現「視覺證據 + 文字知識」的混合推理。

**與 Agent 框架整合**
- 將 LogT 訓練的 VLM 作為視覺感知代理，嵌入 LangChain、AutoGen 等多代理框架。
- 透過 function calling 介面，讓其他代理可呼叫 Zoom-in 工具並接收結構化回傳。

**與 OCR 與文件理解系統整合**
- 結合傳統 OCR 引擎（如 PaddleOCR、Tesseract）處理文字內容，再由 LogT 模型負責版面理解與區域定位。
- 適用於需要同時處理圖表、表格與自由文字的複雜文件。

**與邊緣部署整合**
- 將 LogT-SFT 模型搭配量化技術（GPTQ、AWQ）部署至邊緣裝置。
- 對於即時性要求高的場景（如產線檢測），可預先快取常見區域的放大結果，降低重複計算。

**與監控與可觀測性系統整合**
- 整合 Langfuse、Weights & Biases 等工具，記錄每次 Zoom-in 呼叫的座標、放大倍率與推理內容。
- 建立工具呼叫準確率與效率的儀表板，持續追蹤模型在生產環境的表現。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀論文第 1 節的 Figure 1，理解「thinking with images」與「Zoom-in 工具」的基本概念；接著閱讀第 4 節的實驗結果，掌握 LogT 在資料效率與效能上的核心優勢。實作上可從小規模資料（數百筆）開始，嘗試重現「直接回答 vs. 多跳推理」的差異，建立直觀理解。

**給 AI 工程師**：重點關注第 3 節的 LogT 資料引擎設計，特別是邏輯鏈生成與工具使用軌跡合成的具體流程；以及第 4 節的訓練細節，包括 SFT 與 RL 的超參數設定。建議直接以 Qwen2.5-VL-7B 為起點，在自有領域資料上驗證 LogT 方法的可遷移性，並評估整合至現有 VLM 推論管線的可行性。

**給研究者**：論文的關鍵 insight 在於「將研究重心從複雜 RL 設計轉向 SFT 資料品質」，這對整個 post-training 領域具有方法論上的啟發。建議深入分析邏輯鏈的設計原則、三種推理策略的理論基礎，以及為何簡單 RL 即可在高品質 SFT 基礎上取得顯著提升。此外，可探索 LogT 框架在其他視覺工具（如裁切、旋轉、OCR）上的擴展可能性。

**給產品經理**：核心訊息是「資料品質比演算法複雜度更重要」——LogT 僅用 7.1k 資料與簡單 RL，即超越使用 3.1 倍資料與複雜 RL 的競品，意味著在資源有限時，投資於高品質資料合成往往比堆疊更複雜的訓練流程更具性價比。在產品規劃上，建議將資料品質工程（data engine）視為核心競爭力，而非單純的模型訓練環節。
