多頁文件視覺語言模型（vision-language model）對每頁進行獨立編碼，導致頁面邊界處出現特徵層級的不連續性（feature-level discontinuity）：視覺標記（visual token）在形成時無法存取相鄰頁面的內容，而語言模型必須基於這些孤立形成的頁面表徵進行推理。我們提出 DocSEAM（Document Selective Enrichment via Anchored Masking，透過錨定遮罩進行文件選擇性強化），一個輕量化模組，插入於預訓練（pretrained）視覺編碼器（visual encoder）與語言模型之間，將局部跨頁上下文（cross-page context）的歸納偏置（inductive bias）注入視覺表徵中。針對每個頁面，DocSEAM 與其兩個相鄰頁面形成一個局部三元組（local triplet），採用中心錨定遮罩自注意力（center-anchored masked self-attention）搭配方向顯著性閘門（directional salience gate）來融合來自相鄰頁面的資訊，並僅回傳強化後的中心頁標記（center-page token），保持視覺標記數量不變。經過監督式（supervised）跨頁預熱（cross-page warm-up），並在凍結（frozen）的 DocSEAM 狀態下進行多頁微調（multi-page fine-tuning）後，我們的 90 億參數模型在五個多頁文件視覺問答（Visual Question Answering, VQA）基準上，於參數量最高達 100 億的開放權重模型（open-weight model）中達到最先進（state-of-the-art, SOTA）的效能。我們進一步證明，在受控的重新分頁（re-pagination）條件下，DocSEAM 降低了對邊界位置的敏感性，並改善了跨頁範圍定位（cross-page span localization）。

DocSEAM 的核心設計理念在於解決一個被既有文獻忽略的結構性問題：當前多頁文件視覺語言模型 (VLM) 採用「逐頁獨立編碼」(page-wise encoding) 策略，每一頁的視覺表徵在形成過程中完全無法存取相鄰頁面的內容，這導致了所謂的「特徵層級不連續性」(feature-level discontinuity)。這個問題在實際文件場景中尤為嚴重——段落跨越頁面邊界、表格列延續到下一頁、章節標題與其內容分屬不同頁面等情況極為常見。

**模組架構設計**

DocSEAM 是一個插入在預訓練視覺編碼器與語言模型之間的輕量化模組，僅增加約 2.35 億參數（約佔 9B 主幹網路的 2.6%）。其運作流程可分為以下幾個關鍵步驟：

1. **三元組構建 (Triplet Formation)**：對於每一頁 $p$，DocSEAM 將其與前後相鄰頁面 $p-1$ 與 $p+1$ 組合形成局部三元組 $X_p = [Z_{p-1}; Z_p; Z_{p+1}]$，其中 $Z$ 代表各頁的視覺標記序列。對於首頁與末頁，則以自身作為邊界填充。

2. **中心錨定遮罩自注意力 (Center-Anchored Masked Self-Attention)**：這是 DocSEAM 最具巧思的設計之一。遮罩矩陣的設計使得：
   - 中心頁 $p$ 可以同時關注前一頁 $p-1$ 與後一頁 $p+1$
   - 前一頁 $p-1$ 與後一頁 $p+1$ 之間的注意力被阻斷（設為 $-\infty$）
   
   此設計的深層意義在於「強制所有跨頁資訊流必須經由中心頁」，避免非相鄰頁面之間的「兩跳洩漏」(two-hop leakage)。這種歸納偏置 (inductive bias) 確保了跨頁資訊的傳遞是有結構、可解釋的，而非任由注意力機制自由擴散。

3. **方向顯著性閘門 (Directional Salience Gates)**：每個標記配備四個可學習的閘門參數 $r_i^{\leftarrow}$、$s_i^{\leftarrow}$、$r_i^{\rightarrow}$、$s_i^{\rightarrow}$，分別控制來自前頁與後頁的查詢-鍵 (query-key) 注意力分數。這些閘門透過 $\sigma$ (sigmoid) 函數產生方向性偏置矩陣 $B_{qk} = \log\sigma(r_q) + \log\sigma(s_k)$，加諸於注意力 logits 之上。這使得模型能夠學習「在哪裡」跨頁通訊是有用的，而非對所有標記一視同仁。

4. **中心頁標記提取 (Center Extraction)**：經過若干層自注意力與 FFN 處理後，DocSEAM 僅返回強化後的中心頁標記 $E_p$，捨棄鄰頁標記。這意味著視覺標記總數維持不變，下游語言模型接收的標記數量與無 DocSEAM 的基線完全相同。

5. **無操作初始化 (No-op Initialization)**：模組初始化為恆等映射，確保訓練起點即為預訓練模型的「已知良好工作點」，避免訓練初期的不穩定性。

**兩階段訓練策略**

DocSEAM 的訓練採用精心設計的兩階段流程：

- **第一階段：監督式跨頁預熱 (Supervised Cross-Page Warm-up)**：在此階段，DocSEAM 模組在跨頁對齊任務上進行訓練，使其學習如何融合來自相鄰頁面的資訊。
- **第二階段：多頁微調 (Multi-page Fine-tuning)**：在下游任務微調過程中，DocSEAM 被凍結 (frozen)，僅更新其餘模型參數。這種設計使得學習到的跨頁先驗知識能夠無縫遷移至各種下游任務。

這種「預熱後凍結」的策略類似於遷移學習中的特徵提取器凍結機制，但應用於跨頁表徵學習的場景，具有相當的工程實用價值。

#### 實驗數據解讀

**主要效能結果**

根據圖 1 右側的數據，DocSEAM 在五個多頁文件視覺問答基準上取得了優於所有評估的開放權重模型（最多 10B 參數）的最先進 (SOTA) 結果：

- **MMLongBench-Doc**：BreakPreserve 條件下達到 63.0
- **LongDocURL**：達到 89.2
- **MP-DocVQA**：達到 58.3
- **DUDE**：達到 62.9
- **SlideVQA**：達到 40.1

相較於基線模型，DocSEAM 在多數基準上展現了顯著且一致的改進，特別是在結構保留 (structure-preserving) 與結構破壞 (structure-breaking) 兩種重新分頁條件下的表現差距大幅縮小。

**分頁敏感性診斷實驗**

這是本文最具洞察力的實驗設計之一。作者透過「受控重新分頁」(controlled re-pagination) 診斷工具，系統性地量化了分頁敏感性：

- **結構保留分頁 (Structure-Preserving)**：頁面中斷發生在內容區塊之間
- **結構破壞分頁 (Structure-Breaking)**：頁面中斷發生在表格、段落等內容區塊內部

實驗結果顯示：
- 基線模型在結構破壞分頁下效能顯著下降
- DocSEAM 將 MMLongBench-Doc 上的效能差距縮小至 0.8 個百分點
- 在 LongDocURL 上縮小至 0.7 個百分點

這個結果的深層意義在於：DocSEAM 不僅提升了絕對效能，更重要的是使模型對分頁位置的選擇變得不敏感，這對於實際應用中文件分頁方式不可控的場景具有重要價值。

**跨頁範圍定位分析**

作者透過注意力視覺化展示了 DocSEAM 如何幫助模型更早（在更淺的 LLM 層）集中注意力於跨頁邊界的證據。這種「早期聚焦」現象暗示 DocSEAM 將跨頁推理的負擔從語言模型部分轉移到了視覺表徵階段，使得語言模型能夠在更輕鬆的條件下完成跨頁問答。

**參數效率**

僅增加 2.6% 的參數量（235M / 9B）即能帶來顯著效能提升，這在當前追求參數效率的趨勢下尤為難得。模組的輕量化特性也意味著推理時的計算開銷相對可控。

#### 與現有研究的比較

**三大方法族系的定位**

作者將現有多頁文件 VLM 方法歸納為三大族系，並指出 DocSEAM 與它們的關鍵差異：

1. **檢索增強方法 (Retrieval-Augmented Methods)**：如 VisRAG、SV-RAG、VDocRAG 等。這些方法在閱讀前先選擇相關頁面，但仍以逐頁獨立方式編碼。DocSEAM 的差異在於它直接修改視覺表徵，而非僅做頁面選擇。

2. **代理式方法 (Agentic Methods)**：如 MACT 等。這類方法將推理分解為多步驟工作流程或多代理管線，但從未修改逐頁視覺表徵。DocSEAM 屬於端到端方法，與代理式方法形成互補。

3. **端到端方法 (End-to-End Methods)**：如 GRAM、DocSeeker、mPLUG-DocOwl2、URaG、Leopard 等。這些方法壓縮或重新分配視覺標記，但仍將每頁視為獨立編碼單元。DocSEAM 與這些方法最為相近，但引入了「跨頁上下文」的歸納偏置，這是先前工作所缺乏的。

**相對優勢**

- **vs. 檢索增強方法**：DocSEAM 不需要顯式的頁面選擇步驟，避免了檢索錯誤的傳播問題
- **vs. 代理式方法**：DocSEAM 保持端到端可微性，訓練更為簡潔
- **vs. 既有端到端方法**：DocSEAM 是首個明確引入「跨頁鄰域上下文」歸納偏置的模組

**侷限性與待驗證面向**

- 雖然在五個基準上取得 SOTA，但作者明確限定為「最多 10B 參數的開放權重模型」，對於更大規模的閉源模型（如 GPT-4V、Gemini 等）的相對表現未進行比較
- 模組設計假設文件具有明確的頁面結構，對於非標準化文件（如網頁截圖、發票等）的適用性有待驗證
- 三元組的固定鄰域大小（僅考慮前後各一頁）可能限制了其捕捉更長距離跨頁依賴的能力

**Q2：什麼是「特徵層級不連續性」(feature-level discontinuity)？為什麼這對多頁文件理解特別重要？**

A：特徵層級不連續性指的是視覺編碼器在沒有鄰頁資訊的情況下所形成的頁面表徵，與該頁在完整文件脈絡中應有的表徵之間的落差。這個問題在多頁文件理解中特別關鍵，因為文件內容本質上是連續的——表格、段落、章節都經常跨越頁面邊界。當視覺編碼器對表格最後一列形成表徵時，它不知道下一頁有該表格的延續列，因此無法為「跨頁實體」(cross-page entity) 形成統一的視覺表徵。這迫使下游的語言模型必須從已經「凍結」的標記中推測跨頁關聯，而這種補償機制在分頁位置改變時會變得脆弱，因為模型從未在訓練中見過同一內容在不同分頁下的多種視覺呈現。

A：DocSEAM 是一個輕量化的模組，插入在預訓練視覺編碼器與語言模型之間，為每個頁面 p 形成一個由前一頁、當前頁、下一頁組成的局部三元組 (Z_{p-1}, Z_p, Z_{p+1})。模組在這個串接的三元組上應用少量自注意力層，並透過中心錨定遮罩 (center-anchored mask) 與方向顯著性閘門 (directional salience gates) 融合跨頁資訊，最後只回傳強化後的中心頁標記 E_p 給語言模型。這個設計的關鍵優勢在於：視覺標記的總數不變（語言模型看到的標記數量與基線相同），但每個中心頁標記現在已經融入了來自鄰頁的局部脈絡。整個模組約 235M 參數，僅佔 9B 主幹模型的約 2.6%，並以「無操作」(no-op) 初始化，使訓練從預訓練模型的已知良好操作點開始。

A：中心錨定遮罩自注意力是一種特殊的注意力遮罩機制，允許中心頁同時關注前一頁與下一頁，但阻擋前一頁與下一頁之間的直接互動。論文中 Figure 2 顯示的遮罩矩陣中，前一頁到下一頁以及下一頁到前一頁的注意力權重被設為 -∞（被阻擋），而所有涉及中心頁的注意力路徑都被允許。這樣設計的關鍵理由是：強制所有跨頁資訊都必須「流經」中心頁，防止非相鄰頁面之間在單一層內產生「兩跳洩漏」(two-hop leakage)。換句話說，模型不能跳過中心頁直接讓前一頁影響下一頁，這確保了跨頁融合的結構性——每一頁的強化表徵都明確地以自己為中心，吸收來自兩個方向的鄰頁資訊，這更符合文件閱讀時「以當前頁為焦點、向前後頁借鑑」的認知過程。

### 潛在風險與注意事項

**1. 首尾頁的邊界處理**
DocSEAM 對第 1 頁與最後一頁需要鄰居填充。論文採用重複或零填充，但這可能引入偏差。**緩解方式**：在訓練時對首尾頁進行資料增強（如隨機複製鄰居），或學習專門的首尾標記。

**2. 跨頁注意力計算成本**
雖然視覺標記總數不變，但中間計算需處理三元組拼接後的注意力，對長文件（>50 頁）會增加記憶體峰值。**緩解方式**：採用梯度檢查點（gradient checkpointing）、分塊注意力計算，或限制鄰居頁的標記數量。

**3. 預熱階段的任務設計風險**
若預熱任務與下游任務差異過大，學到的跨頁先驗可能無法遷移。**緩解方式**：預熱任務應涵蓋多種類型（表格、段落、章節），並在驗證集上監控遷移效果。

**4. 凍結策略的雙刃劍**
DocSEAM 凍結可避免災難性遺忘，但也限制其適應特定領域的能力。**緩解方式**：對高度專業化領域（如醫療、法律），可考慮解凍 DocSEAM 並以極低學習率微調。

**5. 評估基準的侷限性**
論文的 SOTA 結果限於 10B 參數以下的開放權重模型，未與更大規模模型或商業系統比較。**緩解方式**：在自家場景中與 GPT-4V、Claude 等商業模型進行 head-to-head 評估，避免過度解讀基準結果。

**6. 重新分頁實驗的外部效度**
論文的受控重新分頁實驗是診斷工具，但實際文件分頁由排版決定，可能無法完全模擬。**緩解方式**：在真實業務文件上進行 A/B 測試，驗證分頁敏感性改善是否帶來實際業務價值。

**7. 視覺編碼器的相容性**
DocSEAM 設計假設視覺編碼器產生頁面級標記序列，若骨幹採用不同的視覺標記化策略（如 patch token + OCR token 混合），需調整介面。**緩解方式**：實作前先確認骨幹模型的視覺標記結構。

### 與其他技術的整合建議

**1. 與 RAG 系統整合**
DocSEAM 可作為 RAG 流程中的「視覺重讀器」（visual re-reader）：先用文字檢索找出相關頁面，再以 DocSEAM 強化後的視覺表徵進行精讀。**整合方式**：在檢索階段保留頁面順序資訊，將相鄰頁面一併送入 DocSEAM 編碼。

**2. 與 OCR 引擎整合**
若骨幹模型依賴 OCR 文字標記，建議在 DocSEAM 之前完成 OCR，並將 OCR 標記與視覺 patch 標記統一編碼。**整合方式**：使用如 PaddleOCR、EasyOCR 等引擎產生結構化文字，再與視覺特徵拼接。

**3. 與 Agent 系統整合**
DocSEAM 可作為 MACT 等 Agent 框架中的視覺編碼增強模組，在「定位」步驟中提供更精準的跨頁證據。**整合方式**：將 DocSEAM 嵌入 Agent 的視覺編碼層，無需修改 Agent 的決策邏輯。

**4. 與文件版面分析整合**
搭配 LayoutLMv3、DINO-Doc 等版面分析模型，可在 DocSEAM 之前加入版面結構標記（如表格區、段落區），幫助方向顯著性閘門學習更精準的跨頁注意力。**整合方式**：將版面類型作為附加特徵注入 DocSEAM 的閘門輸入。

**5. 與長上下文 LLM 整合**
若骨幹 LLM 本身已支援長上下文（如 128K tokens），DocSEAM 的價值在於「視覺層級」的跨頁融合，而非文字層級。**整合方式**：保留 DocSEAM 的視覺增強，同時利用 LLM 的長上下文能力進行最終推理。

**6. 與多模態檢索整合**
在多模態文件檢索系統中，可將 DocSEAM 強化後的視覺標記用於跨頁相似度計算，提升表格跨頁、圖表延續等場景的檢索召回率。
