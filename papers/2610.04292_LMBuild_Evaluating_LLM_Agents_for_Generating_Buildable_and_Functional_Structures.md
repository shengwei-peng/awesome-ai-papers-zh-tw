## ⚡ TL;DR

現有評測偏重幾何品質，忽略結構能否實際建造與運作。
本文提出LMBuild基準，透過互動環境與四維評估架構檢驗代理。

## 摘要翻譯

大型語言模型代理（LLM Agents）日益能夠生成複雜的三維結構（3D Structures），並有望重塑物體在真實世界中的設計與實現方式。然而，生成優雅的幾何形狀與生成能夠實際建造並執行預定功能的物體，在本質上截然不同。現有評估大多聚焦於幾何品質（Geometric Quality），卻忽略了物理可實現性（Physical Realizability）。我們提出 LMBuild，一個用於評估大型語言模型代理（LLM Agents）生成可建造且具功能性結構（Buildable and Functional Structures）之能力的基準測試（Benchmark）。LMBuild 將生成的物體表示為組裝結構（Assembled Structures），包含部件分解（Part Decompositions）、接合點（Joints）、材料（Materials）與序列（Sequences）。為了支援可重現的評估，我們提供一個統一框架，包含：(1) 互動式環境（Interactive Environment），代理可在其中使用建造工具（Construction Tools）檢索部件（Retrieve Components）、建立新部件（Create New Parts）與放置部件（Place Components）以建構物體；(2) 精心整理的核心基準資料集（Core Benchmark Dataset），重新利用既有 CAD 資料集（CAD Datasets），並以維基百科（Wikipedia）知識擴增；以及 (3) 一個涵蓋結構穩固性（Structural Soundness）、功能性可供性（Functional Affordance）、設計品質（Design Quality）與物理實現（Physical Realization）的評估框架。針對 30 個系統的評估揭示出幾項值得注意的發現：(a) 對前沿閉源模型（Frontier Closed-source Models）而言，結構穩固性（Structural Soundness）與對齊（Alignment）已不再是主要瓶頸，而功能性可供性（Functional Affordance）與物理可操作性（Physical Operability）仍相當具挑戰性；(b) 較強的模型更能有效地建立新部件（Create New Parts），而較弱的模型則傾向依賴檢索部件（Retrieve Components）；以及 (c) 提供功能規格能顯著提升部件完整性（Part Completeness）、運動學（Kinematics）與物理可操作性（Physical Operability）。這些結果顯示，生成真實世界中的結構需要對功能性可供性（Functional Affordance）、力學以及新穎部件（Novel Components）的設計與創造進行更深入的推理。我們期望 LMBuild 能為衡量進展奠定基礎，並激勵相關研究，以發展能生成可建造且具功能性結構（Buildable and Functional Structures）之代理。

### 核心貢獻（3～5點）
- 提出 LMBuild 基準測試，將生成物件表示為包含部件分解、接合點、材料與序列的組裝結構，並提供互動式環境、核心資料集與多面向評估框架。
- 建立涵蓋結構穩固性、功能性可供性、設計品質與物理實現的自下而上評估層級，支援可重現的物理可實現性評測。
- 對 30 個系統進行大規模評估，發現前沿閉源模型在結構穩固性與對齊上已非瓶頸，但功能性可供性與物理可操作性仍具重大挑戰。
- 揭示功能規格與創建新穎部件對提升部件完整性、運動學與物理可操作性的關鍵作用。

### 適合對象
從事大型語言模型代理、三維生成、電腦輔助設計、機器人學與可製造性設計之研究者與工程師，以及關注真實世界物理可實現性與功能性結構生成之學術與產業界讀者。

## 深度分析

#### 方法論解析

LMBuild 的核心貢獻在於將 LLM Agents（大型語言模型代理）的 3D Structure Generation（三維結構生成）評估，從傳統的幾何與視覺層面，推進到 Buildable Structures（可建造的結構）與 Functional Structures（具功能性的結構）層面。其方法論可拆解為三大支柱：互動式生成環境、資料集建構流程，以及自下而上的四維評估層級。

**1. 互動式生成環境與 Agent Harness（代理框架）**

LMBuild 為受測模型提供一個標準化的 Agent Harness（代理框架），使其能透過一組 Construction Tools（建造工具）與 3D 環境互動。根據圖 1 與第 2.1 節描述，這些工具包含：

- `List_available_parts()`：檢索 Sub-part Pool（子部件池）中的現成部件；
- `Create_part(part_id, position)`：建立具有任意幾何形狀的新部件；
- `Place_part(part_id, position)` / `Move_part(...)`：放置與調整 Component Poses（部件姿態）；
- `Inspect_part(...)` / `Inspect_current_scene()`：檢視目前場景狀態；
- `Decide_Joints()`：決定 Joints（接合點）與 Kinematic Relationships（運動學關係）；
- `Decide_Material()`：指定 Materials（材料）；
- `Decide_Sequence()`：輸出 Assembly Sequences（組裝序列）。

Baseline Interaction Protocol（基線互動協定）設計為「單輪、無中間回饋」：使用者僅提供目標結構標籤與一張 Reference Image（參考影像），不提供幾何規格或部件級指令。代理必須自主決定要 Retrieve Components（檢索部件）或 Create New Parts（建立新部件），並在候選部件池至少為所需部件數量三倍的情況下完成組裝。這種設計刻意放大代理在長程規劃、場景狀態追蹤與功能推理上的負擔。對於 Domain-specific Systems（領域特定系統），LMBuild 保留其原生輸入輸出協定，避免強加不支援的能力，這提升了跨類型系統的可比性。

**2. 資料集建構：從 CAD Datasets（CAD 資料集）到真實世界知識擴增**

LMBuild 的 Benchmark（基準測試）資料來自對現有 3D/CAD 資料集的重新利用。流程為：從約 368K 的原始資料中，依類別與模型品質篩選出 2,549 個 Reference Targets（參考目標），再進一步挑選 200 個作為 Core Benchmark Dataset（核心基準資料集）。關鍵在於這些目標會透過 Wikipedia（維基百科）擴增，取得 Functional Parts（功能部件）、Object Attributes（物件屬性）、Joints（接合點）與 Kinematic Relationships（運動學關係）等資訊。這些 Textual Anchors（文本錨點）不僅提供語義監督，也成為評估 Physical Realizability（物理可實現性）的依據，例如判斷輪椅是否具備「輪子—軸—框架」的正確運動鏈。

**3. 四維 Bottom-up Evaluation Hierarchy（自下而上的評估層級）**

LMBuild 提出由基礎到高階的評估架構：

- **Structural Soundness（結構穩固性）**：檢查部件是否形成 Valid and Stable 3D Assemblies（有效且穩定的三維組裝體），例如無漂浮、無穿透、幾何封閉；
- **Functional Affordance（功能性可供性）**：評估 Functional Parts（功能部件）是否齊全、Joints（接合點）與 Kinematics（運動學）是否支援預定功能；
- **Design Quality（設計品質）**：衡量 Part Decompositions（部件分解）合理性、Aesthetics（美學）與整體結構設計；
- **Physical Realization（物理實現）**：評估 Materials（材料）選擇、Assembly Sequences（組裝序列）可行性，以及最終是否能在模擬或真實世界中操作。

這個層級呼應了論文的核心論點：生成「看起來像」的結構，與生成「能建造、能運作」的結構，是兩個不同層次的問題。

#### 實驗數據解讀

論文評估了 30 個系統，涵蓋 6 個 Closed-source APIs（閉源 API）、13 個 Open-source LLMs（開源大型語言模型），以及 11 個 Domain-specific Systems（領域特定系統）。雖然提供的摘錄未包含完整數據表格，但從摘要與引言的結論可歸納出四項關鍵發現，並進行如下解讀：

**1. Structural Soundness（結構穩固性）與 Alignment（對齊）已非前沿閉源模型的主要瓶頸**

Frontier Closed-source Models（前沿閉源模型）在幾何有效性、部件無穿透、整體穩定性上已接近飽和。這顯示當前頂尖模型具備良好的空間擺放與基本物理常識。然而，Open-source Models（開源模型）在 Aesthetics（美學）與 Fine-grained Visual Alignment（細粒度視覺對齊）上仍有進步空間，意味著開源社群在視覺品質與精確對位方面尚未追上閉源前沿。

**2. Functional Affordance（功能性可供性）與 Physical Operability（物理可操作性）仍是最大能力缺口**

所有模型家族在以下三項任務上表現薄弱：

- 生成完整的 Functional Parts（功能部件）清單；
- 建立正確的 Joints（接合點）與 Kinematics（運動學）；
- 在模擬評估中保持結構可操作。

這說明 LLM Agents（大型語言模型代理）雖能「拼出」形狀，卻難以內化機械功能知識。例如輪椅的輪子必須能繞軸旋轉、扶手需與框架有適當連接，這類推理需要結合物理、機構學與功能語義，遠超單純的幾何擺放。

**3. 模型強弱決定「檢索」與「創造」策略的差異**

實驗發現，較強的模型更傾向 Create New Parts（建立新部件），而較弱的模型則高度依賴 Retrieve Components（檢索部件）。這可解讀為：建立新部件需要額外的幾何推理、參數化設計與自我驗證能力，對模型是更大的認知負荷；弱模型為降低風險，傾向從現成部件池中挑選最接近的物件，但這也限制了其表達複雜或新穎結構的能力。此現象也呼應後續診斷結果：Open-source LLM Agents（開源大型語言模型代理）在 Part-creation Capability（部件創造能力）與 Scene-state Tracking（場景狀態追蹤）上存在明顯缺陷。

**4. 功能規格提示能顯著提升物理可操作性**

當 Prompt（提示）中明確加入期望屬性與功能需求時，模型在 Part Completeness（部件完整性）、Kinematic Correctness（運動學正確性）與 Physical Operability（物理可操作性）上均有顯著改善。這顯示功能規格可作為一種「強制推理」機制，促使模型從被動的形狀複製轉向主動的功能設計。對未來應用而言，這意味著使用者提供的規格越具體，生成結果越可能具備真實可用性。

#### 與現有研究的比較

**定位與改進**

現有 3D Generation（三維生成）研究大多聚焦於 Geometric Quality（幾何品質）、Visual Consistency（視覺一致性）與 Semantic Alignment（語義對齊），例如判斷生成物體是否像目標類別、視角是否一致、紋理是否合理。LMBuild 則首次系統性地將評估焦點轉移到 Physical Realizability（物理可實現性），提出 Buildable and Functional Structures（可建造且具功能性的結構）這一更高標準。

相較於過往僅評估最終網格或點雲的方法，LMBuild 的改進包括：

1. **互動式建構範式**：代理不是直接輸出最終模型，而是透過工具逐步 Retrieve（檢索）、Create（創造）、Place（放置）、Decide（決定），這更接近真實設計與製造流程；
2. **部件級與機構級評估**：引入 Part Decompositions（部件分解）、Joints（接合點）、Kinematics（運動學）與 Assembly Sequences（組裝序列）等中間表示，使評估可解釋、可診斷；
3. **真實世界知識擴增**：利用 Wikipedia（維基百科）將 CAD 資料轉化為具有功能語義的 Textual Anchors（文本錨點），彌補純幾何資料缺乏功能資訊的問題；
4. **跨系統統一比較**：同時容納通用 LLM Agents（大型語言模型代理）與 Domain-specific Systems（領域特定系統），避免評估框架過度偏向某一技術路線。

**限制**

儘管 LMBuild 開創性地擴展了評估維度，仍存在若干限制：

- **資料規模與類別覆蓋**：Core Benchmark Dataset（核心基準資料集）僅 200 個物件，雖然經過篩選，但對於涵蓋廣泛的製造類別與複雜機構仍顯有限；
- **單輪互動協定**：Baseline 不允許中間回饋，雖然能測試自主能力，但與真實設計過程中反覆迭代、人機協作的情境有落差；
- **物理模擬的簡化**：目前評估側重 Structural Soundness（結構穩固性）與基本 Kinematics（運動學），對於材料強度、摩擦、公差、疲勞、製造誤差等更深層的物理因素著墨較少；
- **材料與序列評估的複雜性**：Materials（材料）與 Sequences（序列）的正確性難以自動化驗證，可能需要大量領域專家知識或高成本物理實驗；
- **未涵蓋成本與可製造性**：實際建造還需考慮成本、工具可及性、加工難度等，這些尚未納入評估框架。

#### 可重現性評估

從提供的摘錄來看，LMBuild 在可重現性方面具備以下基礎：

- **標準化 Agent Harness（代理框架）**：附錄 A.1 詳述代理介接方式；
- **明確的 Construction Tools（建造工具）清單**：附錄 A.2 說明工具細節；
- **資料來源透明**：基於公開的 CAD Datasets（CAD 資料集）與 Wikipedia（維基百科）知識，理論上可重建 Reference Targets（參考目標）與 Textual Anchors（文本錨點）；
- **評估維度具體**：Structural Soundness（結構穩固性）、Functional Affordance（功能性可供性）、Design Quality（設計品質）、Physical Realization（物理實現）四個維度有清楚定義，便於後續實作對應指標。

然而，由於目前僅取得論文前段內容，無法確認以下關鍵項目是否已公開：

- 互動式 3D 環境的原始碼與模擬器；
- 2,549 個 Reference Targets（參考目標）與 200 個 Core Benchmark Dataset（核心基準資料集）的完整清單與標註；
- 從 Wikipedia（維基百科）擷取與對齊知識的自動化管線；
- 各項評估指標的具體實作程式碼；
- 30 個受測系統的 Prompt（提示）與 Hyperparameters（超參數）。

Model Weights（模型權重）在此研究中並非主要議題，因為 LMBuild 評估的是現有 API 與開源模型，而非訓練新模型。整體而言，若作者能釋出環境、資料與評估程式碼，LMBuild 將具備高度可重現性；在尚未確認釋出前，可重現性評估為「中等潛力，待原始碼公開驗證」。

#### 未來研究方向

基於 LMBuild 所揭示的能力缺口與方法論，未來研究可朝以下方向延伸：

**1. 多輪人機協作式建構**

將目前的單輪 Baseline 擴展為 Multi-turn Interactive Construction（多輪互動式建構），允許使用者在過程中提供回饋、修正部件選擇或指定功能細節。這能更貼近真實設計流程，並測試代理的對話式推理與迭代修正能力。

**2. 更深層的物理模擬**

整合 Dynamics（動力學）、Stress Analysis（應力分析）、Friction（摩擦）、Tolerances（公差）與 Collision Detection（碰撞偵測）等模擬，使 Physical Realization（物理實現）評估不僅止於「能否組裝」，更能判斷「能否承受實際負載與長期運作」。

**3. 製造導向的約束建模**

引入 3D Printing（3D 列印）、CNC Machining（CNC 加工）、Sheet Metal Forming（鈑金成型）等製程限制，讓代理在生成部件時同時考慮 Fabrication Constraints（製造約束）、Assembly Tool Accessibility（組裝工具可及性）與 Cost（成本）。

**4. 專業化部件創造模組**

針對目前弱模型在 Create New Parts（建立新部件）上的不足，可發展結合 LLM（大型語言模型）與 Parametric CAD Generators（參數化 CAD 生成器）或 Programmatic Design（程式化設計）模組的混合代理，使其能根據功能需求自動產生符合工程語義的新穎部件。

**5. 機構運動學推理強化**

設計專門針對 Joints（接合點）與 Kinematics（運動學）的推理模組，例如將 LLM 與 Mechanism Synthesis（機構合成）、Constraint Solving（約束求解）或 Symbolic Planning（符號規劃）結合，以提升 Functional Affordance（功能性可供性）。

**6. 真實世界機器人組裝驗證**

將模擬中通過的結構輸出至真實機器人平台進行實體組裝與操作測試，建立從數位設計到物理驗證的閉環，這是驗證 Physical Operability（物理可操作性）的最終標準。

**7. 開源代理的訓練與微調

利用 LMBuild 的軌跡與評估訊號，對 Open-source LLMs（開源大型語言模型）進行 Reinforcement Learning（強化學習）或 Supervised Fine-tuning（監督式微調），特別針對 Scene-state Tracking（場景狀態追蹤）與 Part-creation Capability（部件創造能力）進行專項提升。

**8. 跨類別泛化與組合式設計**

研究代理是否能將已學機構知識遷移到全新類別，或進行 Compositional Design（組合式設計），例如將輪椅的輪軸機構應用到推車或自行車上，從而評估其對功能原型的抽象理解能力。

**9. 多模態感知與場景狀態追蹤**

結合 Vision-language Models（視覺語言模型）強化代理對 3D 場景的感知，使其在 Inspect and Revise（檢查與修正）階段能更準確地追蹤已放置部件、偵測碰撞與評估穩定性。

**10. 時間與成本感知的組裝序列規劃**

未來的 Assembly Sequences（組裝序列）評估可納入 Time（時間）、Cost（成本）與 Parallelizability（可並行性），使代理不僅產生可行序列，更能產生高效且經濟的製造流程。

總結而言，LMBuild 為「可建造且具功能性的結構生成」奠定了評估基礎，未來研究應持續強化代理在功能推理、機構設計、物理模擬與製造約束上的能力，最終實現從語言描述到真實可用物體的端到端生成。

## 論文問答

**Q1：LMBuild 主要想解決什麼問題？**
A：LMBuild 針對的是現有 3D 結構生成評測過度重視幾何品質與視覺一致性，卻忽略物理可實現性的問題。許多模型能產生看起來合理的形狀，但這些形狀可能無法實際建造或運作。因此，LMBuild 提出一個基準測試，用來評估大型語言模型代理是否能生成可建造且具功能性的結構。

**Q2：為什麼現有的 3D 生成評估方法不足以衡量真實世界的可用性？**
A：現有方法多半聚焦於幾何品質、視覺一致性與語義對齊，缺乏對結構穩固性、接合點、材料與組裝序列的檢驗。它們通常只確認數位模型是否好看或符合描述，而不確認物件能否在真實世界中組裝與操作。這導致模型可能產生外觀合理但實際上無法建造或運作的結構。

**Q3：物理可實現性為什麼對 3D 生成很重要？**
A：因為真實世界的應用——例如輔具、家具、機械零件或機器人硬體——都需要物件能夠被製造、組裝並執行預定功能。如果生成結果僅具視覺吸引力卻缺乏功能性可供性，那麼它只能停留在概念階段。LMBuild 強調將數位設計與物理建造連結起來，使生成模型真正具備實用價值。

**Q4：LMBuild 的核心架構包含哪三個主要部分？**
A：LMBuild 包含互動式生成環境、 curated 基準資料集，以及層級式評估框架三大部分。互動環境提供標準化的代理框架與建造工具，讓模型能檢索、建立、放置與調整部件。基準資料集結合 CAD 資料集與維基百科知識，評估框架則從結構穩固性、功能性可供性、設計品質到物理實現進行系統性評分。

**Q5：LMBuild 相較於以往評測的關鍵創新是什麼？**
A：LMBuild 將生成物件視為包含部件分解、接合點、材料與組裝序列的組裝結構，而不只是單純的網格或點雲。它允許代理在統一環境中檢索現成部件或建立新穎部件，並進行擺放與修正。這種設計讓評估能同時涵蓋幾何、力學、運動學與製造可行性，填補了過去只看外觀的缺口。

**Q6：為什麼 LMBuild 同時允許代理「檢索部件」與「建立新部件」？**
A：因為真實建造過程中，設計者既會使用現成零件，也會根據需求製作新零件。檢索部件考驗模型對標準零件的辨識與選擇能力，而建立新部件則需要更深層的幾何推理與創新設計能力。實驗也發現，較強的模型更善於建立新部件，而較弱的模型傾向過度依賴檢索，這正好凸顯了能力差距。

**Q7：LMBuild 的基準資料集是如何建構的？**
A：研究團隊重新利用約 36.8 萬筆現有 3D 資料，經過類別與模型品質篩選後得到 2,549 個參考目標，再從中選出 200 個物件作為核心基準資料集。這些物件進一步透過維基百科擴增真實世界知識，包括功能部件、物件屬性、接合點與運動學關係。這些文本錨點為後續評估物理屬性提供了可依據的標準。

**Q8：LMBuild 評估 30 個系統後，有哪些主要發現？**
A：前沿閉源模型在結構穩固性與視覺對齊上已接近瓶頸不再，表現相當出色。然而，功能性可供性與物理可操作性仍然是所有模型家族最大的能力缺口。無論是功能部件完整性、正確的接合點與運動學，還是模擬環境中的可操作表現，都仍有顯著提升空間。

**Q9：加入功能性規格對生成結果有什麼影響？**
A：在提示中補充期望屬性與功能需求，能迫使模型進行更深層的推理，從而顯著改善部件完整性、運動學正確性與物理可操作性。這顯示提示工程對於建造導向的生成任務相當重要。不過，即便提示更豐富，開源模型與部分閉源模型在功能實現上仍存在明顯落差。

**Q10：LMBuild 這類技術可能應用在哪些實際場景？**
A：LMBuild 可應用於產品設計、輔具開發、家具設計、機械組件與機器人硬體等領域。使用者只需用自然語言描述需求，代理就能快速生成可建造的原型。這有助於縮短設計到製造的週期，並確保生成結構不只是視覺概念，而是具備實際功能。

**Q11：若要將 LMBuild 的代理真正產品化，需要考慮哪些問題？**
A：首先必須進行安全驗證，確保結構在真實負載下穩定且不會造成危險。其次需要納入材料特性、製造公差、成本與組裝可行性等實務因素。此外，模擬環境中的物理可操作性必須能轉移到真實世界，因此人機協作與人工確認仍是不可或缺的環節。

**Q12：LMBuild 對 3D 生成研究領域可能帶來什麼影響？**
A：LMBuild 將研究焦點從單純的幾何與視覺品質，轉移到功能性可供性、力學與物理可實現性。它提供了一個標準化的測量基礎，能激勵研究者開發更擅長推理接合點、材料與組裝序列的代理。長遠來看，這有助於推動從「生成好看模型」走向「生成能真正建造並運作的物件」。

**Q13：LMBuild 有哪些可能的限制？**
A：LMBuild 的物理模擬仍是對真實世界的近似，材料與製造限制可能尚未完全涵蓋。此外，設計品質中的美學與細粒度視覺對齊評估仍具主觀性與挑戰性。核心基準資料集僅 200 個物件，雖具代表性，但可能無法覆蓋所有應用領域與邊緣案例。

**Q14：實驗中觀察到哪些常見的失敗模式？**
A：開源大型語言模型代理在建立新部件與追蹤場景狀態方面表現較弱，容易遺漏功能部件或設置錯誤的接合點。部分模型會產生結構不穩定、運動學不正確，或選用不適當材料與組裝順序的結果。較弱的模型也常過度依賴檢索現成部件，無法針對特殊需求創造合適的新穎部件。

**Q15：未來研究可以朝哪些方向發展？**
A：未來可以強化模型的功能性推理與運動學模擬能力，並將真實製造回饋整合到生成流程中。發展閉環式的檢查與修正機制，讓代理能根據模擬或實體測試結果自動改進設計。此外，擴展基準測試到更多領域、結合真實機器人組裝，以及多模態感知，都是值得探索的方向。

### 適用場景

1. **快速產品原型設計與驗證**  
   工業設計團隊可利用 LMBuild 的互動式環境，讓 LLM 代理根據文字與圖片規格自動生成可組裝的產品結構，例如輪椅、腳踏車或家具，並透過結構穩固性、功能性可供性與物理實現等指標快速篩選可行方案，縮短從概念到原型的週期。

   針對個別使用者的身形與需求，代理可生成包含正確接合點、材料與組裝序列的輔具結構。例如依據使用者指令設計輪椅時，自動決定輪框、扶手、腳踏板等關鍵功能部件，並確保機構在模擬中可實際運作。

3. **機器人與自動化設備機構設計**  
   在機器人開發中，LMBuild 可用於評估代理是否能產生具備正確運動學關係的機構，例如關節連桿、齒輪傳動或夾爪組件。這有助於在進入實體製造前，先驗證機構的可動性與組裝可行性。

4. **建築與室內裝潢構件規劃**  
   將 LMBuild 的評估框架延伸至建築元件層級，例如門窗框架、樓梯或模組化隔間，檢驗代理生成的結構是否具備穩定的三維組裝體、合理的材料指定以及可執行的施工順序。

5. **教育與 Maker 領域的動手做學習**  
   在工程教育或 maker 社群中，LMBuild 可作為教學工具，讓學習者透過自然語言描述生成可建造的結構，並從失敗模式中理解功能部件完整性、接合點設計與物理可操作性等核心工程概念。

### 實作前置條件

**資料準備**
- 高品質的 3D CAD 資料集與部件庫，建議至少涵蓋目標應用領域的主要物件類別。
- 結構化的真實世界知識，例如從維基百科擷取的功能部件、物件屬性、接合點與運動學關係，作為評估時的文本錨點。
- 材料資料庫與組裝序列範本，用於物理實現維度的驗證。

**運算資源**
- 可執行大型語言模型推理的 GPU 或 API 存取權限，閉源前沿模型通常表現較佳，但開源模型可降低長期成本。
- 可執行物理模擬的運算環境，用於檢驗結構穩固性與物理可操作性。
- 足夠的儲存空間存放 3D 模型、中間生成結果與評估紀錄。

**技能需求**
- 熟悉 LLM 代理開發與工具呼叫（tool use）機制。
- 具備基礎機械工程或機構設計知識，能判斷接合點與運動學是否合理。
- 熟悉 3D 建模、CAD 軟體或至少一種程式化設計工具。
- 具備 Python 與模擬環境整合能力。

### 實作步驟建議

1. **定義目標物件與功能需求**  
   明確指定要生成的結構類別、預定功能、關鍵功能部件以及必須滿足的物理限制。建議同時提供文字描述與參考圖片，作為代理的輸入條件。

2. **建置互動式環境與工具鏈**  
   部署 LMBuild 的代理框架，讓 LLM 能夠呼叫檢索部件、建立新部件、放置與調整部件、決定接合點、指定材料與組裝序列等工具。

3. **準備子部件池與知識擴增**  
   從現有 CAD 資料集篩選高品質物件，建立至少為所需部件數量三倍的候選部件池，並以維基百科等來源擴增功能部件、屬性與運動學關係。

4. **開發代理推理流程**  
   設計代理的單輪或多輪工具呼叫流程，讓模型能夠先檢視場景、選擇或創建部件、擺放與調整姿態，再決定接合點與運動學，最後指定材料與組裝順序。

5. **建立自下而上的評估層級**  
   依序檢驗結構穩固性、功能性可供性、設計品質與物理實現。特別要關注功能部件完整性、接合點運動學正確性以及模擬中的物理可操作性。

6. **迭代優化與產品化**  
   根據評估結果調整提示詞、豐富功能規格、強化代理的場景狀態追蹤能力，並將通過驗證的結構匯出至 CAD/CAE 或製造流程。

### 潛在風險與注意事項

- **功能部件不完整**  
  模型可能遺漏關鍵功能部件，導致結構無法執行預定功能。建議在提示詞中明確列出所需功能部件，並以功能規格強制模型進行完整推理。

- **接合點與運動學錯誤**  
  接合點類型或運動學關係設定錯誤會使機構無法運作。應透過物理模擬驗證，並將運動學約束明確寫入評估標準。

- **物理可操作性不足**  
  即使幾何上合理，結構仍可能因材料選擇或組裝順序不當而無法實際建造。建議將材料資料庫與組裝序列驗證納入自動化檢查。

- **過度依賴檢索而非創建新部件**  
  較弱的模型傾向從子部件池中檢索現成部件，而非建立新穎部件，可能限制設計彈性。可透過提示詞鼓勵或強制創建必要的新部件。

- **場景狀態追蹤失敗**  
  代理在長期互動中可能遺忘已放置部件的狀態，導致重複放置或遺漏。建議引入結構化的場景記憶機制，並在每次工具呼叫後更新狀態。

### 與其他技術的整合建議

- **CAD/CAE 軟體**  
  將 LMBuild 生成的組裝結構、接合點與材料資訊匯出為標準 CAD 格式，銜接 SolidWorks、Fusion 360 或 CATIA 進行細部設計與工程分析。

- **數位孿生平台**  
  將通過驗證的結構部署至數位孿生環境，持續監控實體物件的運作狀態，並回饋至代理以優化未來設計。

- **機器人流程規劃**  
  結合機器人組裝路徑規劃系統，將 LMBuild 產生的組裝序列轉換為機器手臂可執行的動作指令，實現自動化製造。

- **產品生命週期管理（PLM）**  
  將生成結果、評估紀錄與版本資訊整合至 PLM 系統，確保設計可追溯並符合產品開發流程。

- **擴增實境（AR）與虛擬實境（VR）**  
  利用 AR/VR 技術讓使用者以沉浸式方式檢視與操作代理生成的結構，進一步驗證功能性可供性與使用者體驗。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先從摘要與適用場景開始，理解「可建造的結構」與「好看的 3D 模型」之間的差異，再逐步認識結構穩固性、功能性可供性與物理實現這四個評估維度。不必急著深入技術細節，重點是掌握 LMBuild 想解決的核心問題：讓 AI 不只是畫出東西，而是能設計出真正做得出來、用得上的物件。

**給 AI 工程師**  
請聚焦於第 2.1 節的互動式環境、代理框架與工具設計，以及評估框架的實作細節。實作時應特別注意工具呼叫的穩定性、場景狀態追蹤，以及如何在提示詞中有效注入功能規格以提升部件完整性與運動學正確性。建議將閉源前沿模型作為基線，再針對開源模型進行微調或強化學習。

**給研究人員**  
本文提供了一個從幾何品質邁向物理可實現性的新評估方向，值得關注功能性可供性與物理可操作性這兩個仍具挑戰性的維度。未來研究可探討如何提升代理創建新穎部件的能力、強化長期場景推理，或將評估框架擴展至更多工程領域，例如軟性機構、生物力學結構或永續材料設計。

**給產品經理**  
請將本文視為評估與選型 LLM 代理在 3D 結構生成應用上的參考框架。重點不在於模型能否生成漂亮圖片，而在於它能否產出可製造、可組裝、可運作的設計。導入時應優先定義清楚產品的功能需求與驗收標準，並預留與 CAD、PLM 及製造流程整合的資源。
