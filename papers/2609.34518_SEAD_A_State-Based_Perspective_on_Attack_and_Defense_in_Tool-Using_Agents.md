# SEAD：基於狀態的視角探討使用工具的智慧代理之攻擊與防禦

## ⚡ TL;DR

工具代理的動作會改變環境狀態，使後續看似正常的操作產生危害，且互動紀錄難以呈現完整狀態。
SEAD 以部分可觀測狀態控制刻畫攻防，DART 適應分解步驟，SAGE 執行前以唯讀查詢把關。
DART語義攻擊增18.8–35.9百分點；SAGE保留九成六良性軌跡，線上攻擊率自48%降至4%。

## 摘要翻譯

語言模型智慧代理（language-model agents）日益使用工具來對外部系統採取行動。先前的工具動作（tool actions）可能改變檔案（files）、權限（permissions）、資料庫記錄（database records）或其他狀態（state），使得後續看似例行的具體動作（concrete actions）變得有害。然而，可見的互動未必能揭示評估該動作所需的底層狀態。我們在 SEAD 中將攻擊與防禦（attack and defense）形式化為部分可觀測狀態控制（partially observed state control），並從此共同的執行過程推導出兩者的設計需求。由於攻擊者提供攻擊者指令（attacker instructions），而目標模型（target model）選擇具體動作，DART 將有害目標（harmful goals）分解為局部合理步驟（locally plausible steps），並利用來自實際工具執行的執行回饋（execution feedback）來引導軌跡（trajectory）搜尋。防禦者必須在執行前（pre-execution）根據不完整的狀態證據做出決定。因此，SAGE 可在允許或阻擋每個待執行動作（pending action）之前，透過唯讀查詢（read-only queries）查證相關狀態，包括遭阻擋後所提出的動作。我們建構了一個環境可驗證資料集（environment-verifiable dataset），整合受控初始狀態（controlled initial states）、可重播工具環境（replayable tool environments）以及任務專屬可執行檢查（task-specific executable checks）。在四個目標模型上，DART 將語義攻擊（semantic attack）成功率相較於競爭基線提升 18.8 至 35.9 個百分點，且在可執行驗證（executable verification）下仍維持穩定提升。在已記錄的軌跡上，SAGE 保留了 95.79% 的良性軌跡（benign trajectories），同時在危害啟用邊界（harm-enabling boundary）前攔截了 92.73% 的有害路徑（harmful paths）。在線上攻防評估（online attack-defense evaluation）中，SAGE 將 DART 的可執行攻擊成功率從 48.0% 降至 4.0%。SAGE 橫跨四種攻擊方法均保持有效，並能泛化至領域外環境（out-of-domain environments）。本研究的程式碼與資料可於 https://github.com/EverywhereSafety/SEAD 取得。

### 核心貢獻（3～5點）
- 提出 SEAD 框架，將使用工具的智慧代理之攻擊與防禦統一形式化為部分可觀測狀態控制問題，並從共同的執行過程推導出攻擊者與防禦者的設計需求。
- 提出 DART 攻擊方法，透過適應式分解把有害目標轉為局部合理步驟，並利用執行回饋引導軌跡搜尋，在四個目標模型上將語義攻擊成功率提升 18.8–35.9 個百分點。
- 提出 SAGE 執行期防禦方法，於動作執行前透過唯讀查詢查證相關狀態，在保留 95.79% 良性軌跡的同時，於危害啟用邊界前攔截 92.73% 的有害路徑。
- 建構環境可驗證資料集，整合受控初始狀態、可重播工具環境與任務專屬可執行檢查，支援在真實環境中重播並驗證攻擊與防禦軌跡。
- 在線上攻防評估中，SAGE 將 DART 的可執行攻擊成功率從 48.0% 降至 4.0%，並能泛化至領域外環境與多種攻擊方法。

### 適合對象
對語言模型智慧代理、代理安全性、對抗性機器學習與執行期防禦有興趣的研究人員與工程師；特別適合關注工具使用代理在真實環境中狀態變化、攻擊軌跡搜尋與動態防禦決策的讀者。

## 深度分析

#### 方法論解析

SEAD（State-based perspective on Attack and Defense）將使用工具的智慧代理（Tool-using agents）之安全性重新框架化為「部分可觀測狀態控制（Partially observed state control）」。其核心論點是：語言模型智慧代理（Language-model agents）的輸出一旦經由工具執行，就會成為環境狀態轉移（State transition）；而危害是否發生，取決於執行後到達的狀態，而非僅取決於單一動作的字面意義。因此，攻擊者、目標模型（Target model）與防禦者共享同一條執行迴圈，但各自只看到與角色相關的部分狀態觀測（Partial state observations）。

在形式化模型中，第 n 次嘗試由三元互動組成：攻擊者指令 x_n、目標代理提出的待執行動作（Pending action）u_n，以及防禦者閘門 Γ_D 的決策 d_n ∈ {PASS, BLOCK}。環境狀態 s_n 包含檔案、權限、資料庫記錄（Database records）等累積效應。執行後的狀態轉移由 F 決定，工具回饋由 Ω 產生。危害目標 g 透過指示函數 H_g(s) 判斷是否達成，而實務上以任務專屬可執行檢查（Task-specific executable checks）V_g 作為 H_g 的操作型代理。特別值得注意的是「危害啟用邊界（Harm-enabling boundary）」β_g(s,u)：當且僅當在狀態 s 執行動作 u 會使目標 g 從未達成轉為達成時，β_g(s,u)=1。這個邊界把防禦時機從「看起來可疑」提升到「即將造成不可逆狀態改變」的臨界點。

基於上述框架，作者分別提出 DART 與 SAGE：

- **DART（Decomposition and Adaptive Trajectory Search）**：攻擊者的挑戰在於只能下指令，但具體動作（Concrete actions）由目標代理選擇。DART 因此將有害目標（Harmful goal）分解為局部合理步驟（Locally plausible steps），這些步驟單獨看來像正常準備工作（例如「尋找工作階段檔案（Session files）」），但串連後可達成危害（例如上傳包含認證資料（Authentication data）的 cookie 資料庫）。DART 進一步利用執行回饋（Execution feedback）與拒絕回饋（Refusal feedback）進行適應式分解（Adaptive decomposition）：當某條軌跡（Trajectory）分支被阻擋或失敗時，演算法會根據觀察到的中間狀態（Intermediate states）與已達成的進度，回溯並探索替代指令。這種「執行—觀測—再規劃」的搜尋讓攻擊不再依賴靜態提示工程，而是動態回應目標代理的實際行為。

- **SAGE（State-Aware Gate for Execution）**：防禦者的決策點在執行前（Pre-execution），且只能依據不完整的歷史 h_n^D 做判斷。SAGE 因此可在放行前發出私有的唯讀查詢（Read-only queries），主動調查與待執行動作相關的環境狀態，再決定 PASS 或 BLOCK。關鍵設計在於：當動作被阻擋後，目標代理可能會重新規劃另一個工具動作，攻擊者也可能修改攻擊者指令（Attacker instructions）；SAGE 將每一個新提出的動作都重新送回閘門檢查，形成「阻擋—再規劃—再檢查」的迴圈。這種設計把防禦從單純的對話內容審查，轉變為以狀態證據為基礎的執行期防禦（Runtime defenses）。

整體而言，SEAD 的方法論貢獻在於把攻擊與防禦放在同一個狀態控制問題下推導：持久效應（Persistent effects）決定了攻擊成功與防禦時機，部分狀態觀測決定了雙方都需要主動蒐集證據，而執行回饋則讓兩方都能適應調整。DART 與 SAGE 並非獨立技巧，而是從這個共享執行迴圈中自然導出的角色專屬方法。

#### 實驗數據解讀

本研究建構了一個環境可驗證資料集（Environment-verifiable dataset），結合受控初始狀態（Controlled initial states）、可重播工具環境（Replayable tool environments）與任務專屬可執行檢查（Task-specific executable checks）。這讓「攻擊是否成功」不再只是由人工或模型判斷語意，而是能在真實環境中執行檢查程式確認狀態改變。此外，研究也從 OpenAgentSafety 取得良性軌跡（Benign trajectories），用於衡量防禦對正常執行的干擾。

主要實驗結果可從三個層次解讀：

1. **DART 的攻擊效能**：在四個目標模型上，DART 相較於競爭基線，將語義攻擊（Semantic attack）成功率提升 18.8–35.9 個百分點，且在可執行驗證（Executable verification）下仍維持一致增益。這表示 DART 的適應式分解確實能產生更具體、更符合目標代理執行語境的指令序列，而不只是生成看似合理但無法落地的攻擊提示。數據也顯示，把執行回饋納入搜尋能顯著提高跨模型泛化性。

2. **SAGE 的靜態軌跡表現**：在已記錄的軌跡上，SAGE 能保留 95.79% 的良性軌跡，同時在危害啟用邊界（Harm-enabling boundary）攔截 92.73% 的有害路徑（Harmful paths）。這個安全—效用權衡（safety–utility trade-off）相當理想：絕大多數正常操作不被誤擋，而絕大多數真正會造成狀態危害的轉移被阻斷。值得注意的是，攔截點設在「危害啟用邊界」意味著 SAGE 並非一看到可疑關鍵字就阻擋，而是等到動作即將把環境推入不可逆危害狀態時才介入，這解釋了為何誤擋率能維持這麼低。

3. **線上攻防評估（Online attack-defense evaluation）**：當 DART 與 SAGE 同時運作時，DART 的可執行攻擊成功率從 48.0% 驟降至 4.0%。這是最具說服力的結果，因為它測試的是適應性攻擊對抗適應性防禦的動態場景。DART 會根據阻擋調整策略，但 SAGE 同樣會對每個重新規劃的動作再次檢查，最終仍能有效壓制攻擊。此外，SAGE 在四種不同攻擊方法上都維持有效，並能泛化到領域外環境（Out-of-domain environments），顯示其狀態導向的判斷邏輯不完全依賴特定任務模式。

綜合來看，實驗設計的強項在於同時評估「攻擊強度」與「防禦強度」，並且使用可執行驗證把結果錨定在真實環境狀態，而非僅仰賴語言模型的自我評分。不過，部分數據（例如 4.0% 的殘留攻擊成功率）也暗示仍有少數軌跡能繞過 SAGE，這可能來自於唯讀查詢無法完整覆蓋狀態、或是攻擊者找到防禦者觀測不到的隱蔽狀態通道。

#### 與現有研究的比較

SEAD 與現有研究的關係可從攻擊與防禦兩條線分別定位。

在攻擊研究方面，AgentDojo、TRACE 與 AgentHarm 等已開始評估針對會執行工具之代理的多步攻擊。相較於這些工作，DART 的差異在於把「執行回饋」與「到達狀態」納入搜尋目標：它不僅根據模型回應調整提示，還會根據工具實際產生的中間狀態與最終可執行驗證結果，選擇要繼續探索或回溯的分支。這讓 DART 更接近強化學習中的樹狀搜尋，而非單純的對話式越獄（jailbreak）。此外，DART 明確區分「攻擊者指令」與「目標代理選擇的具體動作」，這點在過去許多攻擊框架中常被忽略——後者往往假設攻擊者能精確控制每一步工具呼叫。

在防禦研究方面，R-Judge 著重於已完成軌跡的風險評分，TurnGate 與 ToolSafe 檢查待執行動作，StepGuard 則同時支援軌跡審計與執行前檢查。更近一步的 GuardAgent、ShieldAgent、AIRGuard、AttriGuard 與 SafeMCP 分別從政策推理、工具權限、意圖歸因與環境預測等角度強化決策。SAGE 的獨特之處在於：它把防禦決策點明確放在「執行前」，並允許防禦者主動發出唯讀查詢以補足部分狀態觀測的不足。這不同於僅依賴可見對話歷史或靜態政策的方法，也與 SafeMCP 的環境預測互補——SAGE 是實際查詢當前狀態，而非僅靠模型推測未來狀態。

整體而言，SEAD 的最大貢獻是提出一個統一的狀態控制視角（State-based perspective），讓攻擊與防禦的設計需求從同一組假設（持久效應、部分可觀測、執行回饋）中推導出來。這避免了過去攻擊與防禦研究各自為政、難以比較的問題。

然而，SEAD 也存在若干限制。首先，SAGE 的唯讀查詢假設查詢本身不會改變環境狀態，但在某些系統中（例如資料庫的 `SELECT` 可能觸發日誌或鎖定），「純唯讀」並非絕對成立。其次，框架高度依賴可執行驗證與受控初始狀態，這在開放、動態的真實世界環境中可能難以複製。第三，雖然 SAGE 能攔截絕大多數有害轉移，但殘留的攻擊成功率顯示，當攻擊者找到防禦者觀測盲點時，仍可能成功。最後，目前評估主要針對特定任務與工具環境，對於高度連續或高維狀態空間（例如即時作業系統、大型網頁生態系）的擴展性仍有待驗證。

#### 可重現性評估

本研究承諾開放原始碼與資料，程式碼與資料集可於 https://github.com/EverywhereSafety/SEAD 取得。資料集具備三項有利於重現的特性：受控初始狀態、可重播工具環境與任務專屬可執行檢查。這意味著其他研究者可以在相同的起點重播軌跡，並以相同的檢查程式驗證攻擊是否成功，大幅降低主觀判斷帶來的變異。

不過，可重現性仍面臨幾項挑戰。第一，論文未明確說明目標模型是否為公開權重；若四個目標模型包含專有 API（例如 GPT-4、Claude 等），則即使程式碼與資料公開，其他團隊也可能因 API 版本、溫度參數或存取權限不同而得到略有差異的結果。第二，可重播工具環境需要特定版本的作業系統、資料庫與雲端儲存（Cloud storage）模擬器，若相依環境未完整容器化，重現過程可能出現環境漂移。第三，DART 與 SAGE 都涉及多次模型呼叫與狀態查詢，執行成本與延遲可能讓小型研究團隊難以完全複製大規模實驗。

建議作者未來可進一步提供：Docker 或類似的容器化環境、目標模型 API 版本與參數設定、每項實驗的隨機種子與完整執行日誌，以及一個輕量級的示範腳本，讓社群能快速驗證核心主張。若能釋出部分攻擊軌跡與 SAGE 查詢紀錄，將更有助於理解防禦決策的透明度與可解釋性。

#### 未來研究方向

SEAD 開啟了數個值得後續探索的方向：

1. **更強的適應性攻擊者**：DART 已展現執行回饋的價值，但未來可研究攻擊者是否能主動操縱防禦者的觀測（例如透過大量無害查詢淹沒 SAGE 的查詢預算），或利用狀態空間中防禦者未涵蓋的維度繞過檢查。

2. **學習式防禦策略**：目前 SAGE 的查詢與決策策略可能基於啟發式規則或提示工程。未來可將其形式化為部分可觀測馬可夫決策過程（POMDP），透過強化學習學習最優查詢與阻擋策略，以在查詢成本與安全性之間取得更好平衡。

3. **因果歸因與可解釋性**：當 SAGE 阻擋某個動作時，如何向使用者解釋「為何這個動作會導致危害」？引入因果推論方法，讓防禦者不僅能判斷 β_g(s,u)=1，還能指出是哪一個狀態變化導致危害，將提升系統透明度與使用者信任。

4. **擴展到連續與隨機環境**：目前框架主要針對離散工具動作與可檢查狀態。未來可研究如何應用於連續控制（例如機器人、自動駕駛）或具有高隨機性的網頁環境，其中狀態轉移與觀測都更為複雜。

5. **多代理與對抗性生態系**：現有設定主要是一對一的攻擊者—目標—防禦者。未來可探討多個攻擊者協作、多個防禦者分工，或目標代理本身具備自我防禦機制的場景。

6. **隱私與查詢效率**：SAGE 的唯讀查詢可能洩露防禦者的檢查策略，也可能帶來顯著延遲。研究如何以差分隱私或壓縮查詢減少資訊洩露與計算開銷，是實務部署的關鍵。

7. **與記憶體、審計機制整合**：工具動作的持久效應不僅存在於外部環境，也可能存在於代理自身的記憶體中。將 SAGE 與記憶體攻擊防禦、長期軌跡審計結合，可形成更完整的代理安全防線。

8. **形式化驗證與安全保證**：最終目標應是為代理執行提供可證明的安全邊界，例如證明在給定觀測能力與查詢預算下，SAGE 能保證攔截所有滿足特定條件的危害啟用轉移。這將把經驗性防禦提升為可驗證的安全保證。

## 論文問答

**Q1：SEAD 試圖解決什麼核心問題？為什麼工具使用型代理的安全性必須從「狀態」切入？**

A：SEAD 針對的是語言模型代理透過工具對外部系統執行動作時，早期行為會改變檔案、權限或資料庫等環境狀態，使後續看似平常的動作變成有害攻擊的問題。由於同一個工具動作（例如上傳檔案）在不同狀態下可能無害也可能洩露認證資料，僅檢視對話歷史或單一步驟無法判斷其真實風險。因此，SEAD 將攻擊與防禦都視為對共享執行流程中「狀態轉移」的控制問題，強調必須以實際環境狀態作為安全評估的基礎。

**Q2：現有的攻擊或防禦方法為何在這類情境下不足？**

A：現有攻擊研究多聚焦於對話層面的語義操縱，而現有執行期防禦則常只檢查即將執行的單一工具呼叫或已完成軌跡，忽略了跨步驟的持久效應與部分可觀測狀態。這些方法未能統一考量攻擊者下指令、目標代理選擇具體動作、以及防禦者在執行前僅有不完整證據這三個角色共享的執行迴路。SEAD 指出，唯有把攻擊與防禦放在同一個部分可觀測狀態控制框架下，才能正確推導出各自需要的設計條件。

**Q3：為什麼必須在執行前檢查環境狀態，而不能只看代理的動作描述？**

A：因為動作的危害與否取決於當前環境狀態，例如同樣是「上傳偵錯檔案」，若檔案內含工作階段 Cookie 資料庫且雲端儲存空間可被攻擊者存取，就會造成認證資料外洩。代理與防禦者能看到的互動歷史並不一定包含檔案內容或權限設定等關鍵狀態資訊。因此，SAGE 必須在執行前發出私有的唯讀查詢來調查相關狀態，才能準確判斷該待執行動作是否會跨越危害啟用邊界。

**Q4：SEAD 的核心數學化框架是什麼？它如何統一攻擊與防禦？**

A：SEAD 將整個互動建模為部分可觀測的狀態控制迴路，其中環境狀態 \(s_n\) 會因目標代理提出的工具動作 \(u_n\) 而轉移，而攻擊者、目標代理與防禦者各自只看到角色專屬的互動歷史 \(h_n^T\) 與 \(h_n^D\)。攻擊者的目標是讓狀態達成有害目標 \(g\)，即 \(H_g(s)=1\)；防禦者則需在執行前透過閘門函數 \(\Gamma_D\) 決定放行或阻擋。由於三者共享同一個執行流程，SEAD 能從持久效應、部分狀態觀測與執行回饋這三個共同特徵，分別推導出 DART 與 SAGE 的設計需求。

**Q5：DART 的攻擊策略與傳統攻擊方法有何不同？**

A：DART 不僅將有害目標分解為局部合理步驟，還會利用目標代理實際執行後產生的回饋來動態調整後續指令與搜尋方向。由於攻擊者只能下指令，真正的具體動作由目標代理選擇，DART 會把執行結果、拒絕回饋與中間狀態納入搜尋，持續探索不同軌跡。相較於靜態提示攻擊，DART 能適應目標代理的實際行為與環境變化，從而顯著提升語義攻擊的成功率。

**Q6：SAGE 的防禦設計為什麼強調「執行前」與「唯讀查詢」？**

A：SAGE 在動作實際執行之前設置閘門，因為一旦有害狀態轉移發生，其造成的檔案外洩或權限改變可能已無法挽回。為了在只有部分證據的情況下做出判斷，SAGE 可以主動發出私有的唯讀查詢來調查與待執行動作相關的環境狀態，而不會改變環境本身。當 SAGE 決定阻擋後，目標代理可能會重新規劃並提出新動作，SAGE 會再次將新動作送回閘門檢查，形成持續的執行期防禦。

**Q7：本研究使用了哪些資料集與評估方式？**

A：研究以 MT-AgentRisk 任務為基礎，建構了環境可驗證資料集，包含受控初始狀態、可重播工具環境以及針對各任務設計的可執行檢查程式。此外，研究也從 OpenAgentSafety 取得良性軌跡，用來衡量防禦機制對正常執行的影響。這種設計讓攻擊成功與否不再僅憑語義判斷，而是能在真實環境中透過可執行驗證確認狀態變化。

**Q8：實驗中的關鍵量化結果有哪些？**

A：在四個目標模型上，DART 相較於對照基線將語義攻擊成功率提升了 18.8 至 35.9 個百分點，且在可執行驗證下仍保持一致增益。SAGE 在記錄軌跡上保留了 95.79% 的良性軌跡，同時在危害啟用邊界攔截了 92.73% 的有害路徑。在線上攻防評估中，SAGE 更將 DART 的可執行攻擊成功率從 48.0% 大幅降低至 4.0%。

**Q9：SAGE 的泛化與穩健性表現如何？**

A：SAGE 不僅對 DART 有效，在四種不同攻擊方法下都能維持良好的攔截能力，顯示其不依賴特定攻擊提示的結構。此外，SAGE 還能泛化到領域外環境，說明透過狀態調查進行執行前判斷的策略具有跨任務潛力。這些結果也伴隨可執行驗證，進一步確認防禦決策確實對應到真實環境中的狀態變化。

**Q10：SEAD 的框架在實際應用中可能對應哪些場景？**

A：典型場景包括代理被指示搜尋並上傳偵錯檔案，結果卻把內含認證資料的工作階段檔案上傳到可被攻擊者存取的雲端儲存空間。類似風險也存在於軟體倉庫修改、資料庫記錄操作、作業系統檔案權限變更等功能性網站導航任務中。SEAD 的狀態視角能幫助產品在這些高風險操作發生前，先確認檔案內容、目的地權限與其他狀態細節。

**Q11：若將 SAGE 部署到實際產品，需要考慮哪些工程與安全議題？**

A：首先必須確保唯讀查詢確實不會改變環境狀態，並限制查詢範圍以保護使用者隱私與系統效能。其次，閘門決策需要平衡安全性與可用性，避免過度阻擋正常但複雜的多步驟任務。最後，產品必須支援攻擊被阻擋後的持續檢查，因為目標代理與攻擊者都可能根據拒絕回饋重新規劃並提出新的待執行動作。

**Q12：這篇研究對代理安全領域可能帶來什麼影響？**

A：SEAD 將攻擊與防禦從各自獨立的研究路線整合到同一個以狀態為中心的執行模型，促使未來研究更關注工具執行後的真實環境效應。它強調評估不應只停留在對話層面，而應透過可重播環境與可執行檢查來驗證危害是否真正發生。這種環境可驗證的觀點有望成為代理安全性評估的新標準，並推動更穩健的執行期防禦機制發展。

**Q13：作者可能承認哪些限制？**

A：SAGE 的判斷品質取決於其能夠調查的狀態範圍與任務專屬可執行檢查的設計，若檢查不完整可能遺漏新型危害路徑。此外，持續發出唯讀查詢會帶來額外的計算與延遲成本，在延遲敏感的應用中需要權衡。框架目前主要針對單一代理與已知工具環境，對於更開放、多代理協作或高度動態的環境仍需進一步擴展。

**Q14：SAGE 或 DART 在哪些情況下可能失效？**

A：如果攻擊者能設計出不需要明顯狀態變化即可達成危害的路徑，SAGE 的唯讀查詢可能無法在執行前取得足夠證據。另一方面，若良性任務的動作在局部看來與有害路徑高度相似，SAGE 可能產生誤判而阻擋正常執行。DART 則可能在目標模型具備強大安全對齊且持續拒絕所有可疑分解步驟時難以找到可行的攻擊軌跡。

**Q15：未來研究可以朝哪些方向延伸？**

A：未來可以發展更強大的狀態估計與預測模型，使防禦者在無法直接查詢所有狀態時仍能推斷潛在風險。也可以結合主動學習來適應不斷演化的攻擊策略，並將 SAGE 擴展到多輪、多代理與真實世界工具環境。此外，設計更通用、無需大量任務專屬設定的可執行檢查機制，將是讓這類執行期防禦大規模落地的關鍵挑戰。

## 實務應用指南

## 適用場景

**企業內部程式碼與資料庫管理代理**
開發者代理被授權修改程式碼倉儲、查詢資料庫或部署服務。攻擊者可透過偽裝成除錯或重構指令，誘導代理先讀取敏感設定檔，再將內容寫入公開可見的位置。SAGE 可在每次工具執行前檢視檔案內容與目標路徑權限，於危害啟用邊界阻擋資料外洩。

**雲端儲存與檔案同步代理**
負責備份、同步或分享檔案的代理常見於企業協作場景。攻擊者可能要求代理「尋找並上傳工作階段檔案以便除錯」，使無害的前置搜尋銜接到上傳認證資料的動作。透過狀態可驗證的環境與唯讀查詢，SAGE 能判斷待上傳檔案是否包含 session cookie 或金鑰。

**客戶支援與系統管理代理**
此類代理可操作使用者帳號、權限與服務設定。惡意指令可分解為多個局部合理步驟，例如先查詢帳號狀態，再修改角色權限。DART 可用於紅隊測試，檢驗代理是否會在持續對話中逐步達成權限提升；SAGE 則在每次權限變更前檢查狀態影響。

**財務與交易執行代理**
能夠查詢餘額、建立付款或轉帳的代理面臨資金竊取風險。攻擊者可能先要求代理彙整帳戶資訊，再誘導其執行小額測試轉帳至攻擊者控制的帳戶。SEAD 的狀態視角可將「資金離開受控帳戶」定義為危害啟用邊界，並於執行前透過可執行檢查驗證收款方與金額。

**開發環境與 CI/CD 自動化代理**
自動化代理可觸發建置、測試與部署流程。攻擊者可能透過修改設定檔或注入惡意相依套件，使後續建置步驟產生後門。SAGE 可在執行部署或合併前，檢查原始碼狀態、相依套件版本與權限變更，避免有害狀態轉移被寫入生產環境。

## 實作前置條件

**資料準備**
需要能夠重播並驗證的受控初始狀態，包括乾淨的環境快照、任務專屬可執行檢查程式，以及成對的良性與有害軌跡。良性軌跡用於衡量 SAGE 對正常執行的保留率，有害軌跡則用於評估攔截率與 DART 的攻擊成功率。建議從現有代理評估資料集或內部操作日誌中萃取常見任務，再針對每項任務定義明確的狀態完成條件。

**運算資源**
需要可呼叫的目標語言模型 API、執行工具動作的沙箱環境，以及用於大規模軌跡評估的運算叢集。沙箱必須支援狀態還原與並行實驗，因為 DART 與 SAGE 都需要反覆執行與回滾。若採用本地模型，則需準備足夠的 GPU 記憶體與推論吞吐量。

**技能組合**
團隊需具備語言模型代理開發經驗、工具環境建置能力，以及資安紅隊思維。具體而言，需要有人能夠設計可執行驗證程式、定義危害啟用邊界、撰寫唯讀查詢工具，並能解讀執行回饋以調整攻擊與防禦策略。熟悉部分可觀測馬可夫決策過程或強化學習者，在理解 SEAD 框架與設計搜尋策略時會更有優勢。

## 實作步驟建議

**步驟一：建立狀態可觀測的環境模型**
將代理的操作環境抽象為狀態轉移系統，明確定義每個工具動作如何改變檔案、資料庫、權限與其他資源。為每個角色建立可見的證據集合：攻擊者僅看到指令與部分回饋，目標代理看到互動歷史，防禦者則可透過唯讀查詢取得額外狀態證據。

**步驟二：定義危害啟用邊界與可執行驗證**
針對每項任務，明確劃分「尚未造成危害」與「已造成不可逆危害」的臨界點，並撰寫可在環境中執行的檢查程式。例如，資料外洩任務的邊界可定義為「敏感檔案內容出現在未授權位置」，並由腳本比對檔案雜湊或存取控制清單。

**步驟三：部署 SAGE 作為執行期閘道**
在目標代理與工具執行之間插入 SAGE 閘道。當代理提出待執行動作時，SAGE 先根據目前可見證據與動作語義，決定是否需要發動唯讀查詢；查詢後再判斷 PASS 或 BLOCK。若動作被阻擋，必須將新的待執行動作重新送回閘道檢查，因為攻擊者與代理都可能適應性地調整後續步驟。

**步驟四：建立紅隊測試與 DART 評估管線**
使用 DART 對目標模型進行自動化紅隊測試。將有害目標分解為局部合理步驟，並利用執行回饋與拒絕回饋引導軌跡搜尋。記錄成功與失敗的軌跡，作為改進 SAGE 決策規則與查詢策略的訓練資料。

**步驟五：持續監控與迭代**
在生產環境中收集 SAGE 的阻擋紀錄、誤擋案例與攻擊嘗試，定期更新危害啟用邊界、唯讀查詢工具與目標模型。由於攻擊者會適應防禦機制，建議將 DART 評估納入持續整合流程，確保新版本的代理與防禦規則仍能維持安全與效用平衡。

## 潛在風險與注意事項

**誤擋良性軌跡影響使用者體驗**
SAGE 雖然在論文中保留了 95.79% 的良性軌跡，但在實際產品中，過於嚴格的規則可能中斷正常業務流程。建議採用分級處理：對於高風險動作要求額外確認，對於低風險動作快速放行，並保留人工覆核機制。

**唯讀查詢帶來的成本與延遲**
每次執行前發動額外查詢會增加延遲與模型呼叫成本。可透過快取常見狀態、限制查詢次數，以及根據動作風險等級動態決定查詢深度來緩解。同時需確保查詢工具確實為唯讀，避免防禦機制本身意外改變環境狀態。

**攻擊者會適應阻擋策略**
當 SAGE 阻擋某個動作後，攻擊者可能改寫指令或誘導代理提出替代動作。因此不能將單次阻擋視為終點，而必須將每次重新規劃的動作都送回閘道檢查，並持續用 DART 等自適應攻擊方法驗證防禦強度。

**狀態隱私與查詢權限**
防禦者透過唯讀查詢取得的狀態可能包含敏感資訊。需嚴格限制 SAGE 的查詢範圍與日誌存取權限，遵循最小權限原則，並對查詢紀錄進行去識別化或加密儲存。

**過度依賴語義判斷**
僅憑動作名稱或參數文字判斷安全性，容易忽略狀態脈絡。實作時應優先採用環境可驗證的證據，例如檔案內容、資料庫記錄與權限設定，而非單純依賴語言模型的語義理解。

## 與其他技術的整合建議

**LLM 閘道與 API 代理**
SAGE 可部署於現有 LLM 閘道之後、工具執行層之前，作為動作級別的最後一道防線。這樣既能保留既有提示過濾與速率限制機制，又能補充執行前的狀態感知檢查。

**SIEM 與 SOAR 平台**
將 SAGE 的阻擋事件、查詢紀錄與軌跡摘要傳送至 SIEM，可協助資安團隊關聯多個代理的攻擊嘗試。對於高風險阻擋，可觸發 SOAR  playbook 進行自動化調查，例如隔離相關帳號或通知管理員。

**沙箱與容器化執行環境**
將工具動作限制在可還原的沙箱或容器中，確保 DART 紅隊測試與 SAGE 查詢不會影響生產環境。容器快照功能也能加速狀態回滾與大規模軌跡評估。

**RBAC 與最小權限原則**
SAGE 不應取代權限控管，而應與之互補。在代理帳號層面實施嚴格的 RBAC，限制工具可操作的資源範圍；SAGE 則負責在權限允許的範圍內，進一步判斷特定動作在當前狀態下是否安全。

**可觀測性與軌跡審計平台**
整合軌跡記錄、狀態變更日誌與 SAGE 決策理由，建立完整的代理行為審計鏈。這不僅有助於事後調查，也能為 DART 提供高品質的執行回饋資料，持續提升攻防兩端的設計。

## 給不同背景讀者的閱讀建議

**給初學者**
建議先從圖 1 的三角色循環與表 1 的符號對照開始，理解「攻擊者下指令、目標代理選動作、防禦者在執行前把關」這個基本流程。接著閱讀第 1 節的動機範例，例如偽裝除錯指令上傳工作階段檔案，就能具體體會為何單看動作名稱無法判斷安全，而必須檢查背後的環境狀態。技術細節如 DART 的搜尋演算法與 SAGE 的查詢策略可暫時略過，重點放在「狀態」與「危害啟用邊界」這兩個核心概念。

**給 AI 工程師**
請聚焦於第 3 節的形式化框架與 DART、SAGE 的實作細節，理解如何將提示工程、工具執行與狀態回饋整合成一個可運作的代理安全管線。特別注意 SAGE 的閘道設計：它並非單純的內容過濾器，而是需要在執行前動態發動唯讀查詢、根據狀態證據做決策，並在阻擋後持續檢查重新規劃的動作。建議搭配論文提供的程式碼與資料集，實際跑一次軌跡評估，觀察良性與有害軌跡在狀態層面的差異。

**給研究人員**
本論文的核心貢獻在於將代理安全重新框架為「部分可觀測狀態控制」，並從這個共同形式推導出攻擊與防禦的設計需求。建議深入檢視第 3 節的數學模型、DART 如何結合執行回饋進行適應式分解，以及 SAGE 在資訊不完全條件下的決策理論基礎。此外，環境可驗證資料集的建構方式與危害啟用邊界的操作性定義，對於未來設計更嚴謹的代理安全基準具有重要參考價值。

**給產品經理**
請將重點放在商業風險與產品權衡：SEAD 提供的是一種「在執行前用狀態證據把關」的防禦思維，能夠降低資料外洩、權限濫用與財務損失等實際風險，但同時也會增加延遲與開發成本。閱讀時可特別關注實驗結果中的安全–效用權衡、線上攻防評估成效，以及 SAGE 對良性軌跡的保留率，這些數據有助於評估導入時對使用者體驗的影響，並向利害關係人說明投資報酬。
