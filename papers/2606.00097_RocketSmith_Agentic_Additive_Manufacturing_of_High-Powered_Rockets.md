## ⚡ TL;DR

針對高功率火箭開發中設計與製造工具整合困難、迭代耗時的問題，本研究提出解決方案。
提出RocketSmith代理系統，以大型語言模型協調飛行模擬、參數化設計與積層製造。
成功開發並試射四枚火箭，全數穩定升空，其中兩枚可回收重複使用，實測高度達預測八成。

## 摘要翻譯

RocketSmith 是一個代理型系統（Agentic System），能夠智慧地自動化面向積層製造之設計（Design for Additive Manufacturing, DFAM）流程，以開發適於發射的高功率火箭（High-Powered Rocket）。該系統利用大型語言模型（Large Language Model, LLM）協調軟體工具（Software Tool）之執行，以驗證飛行穩定性（Flight Stability）等設計特性（Design Characteristic），並生成用於火箭組裝之參數化設計（Parametric Design）元件。多個子代理（Subagent）與技能（Skill）可透過迭代，於零樣本（Zero-Shot）與人在迴路（Human-in-the-Loop）等運作模式中，實現飛行參數（Flight Parameter）之最佳化工作流程（Optimization Workflow）。藉由本系統，我們利用積層製造（Additive Manufacturing, AM）獨特的設計能力，開發出四款具備不同推進器（motor）與組裝配置的高功率火箭。這些組裝元件以多種 FDM 列印機製造，並經人工評估其飛行就緒狀態，再於發射活動中進行飛行測試。測試結果顯示，所有火箭均達成穩定發射，且四支火箭中有兩支成功回收並處於可再次飛行之狀態。高度計資料證實，火箭所達高度為代理型系統（Agentic System）預測之預期遠地點的 80%，確立了模擬與實驗間的一致性。

### 核心貢獻（3～5點）
- 提出 RocketSmith 代理型系統，利用大型語言模型協調多項軟體工具，自動化高功率火箭之面向積層製造設計流程。
- 整合子代理與技能，於零樣本與人在迴路等運作模式中建立飛行參數之最佳化迭代工作流程。
- 運用積層製造之設計自由度，開發並製造四款具不同推進器與組態的高功率火箭，驗證積層製造於航太結構之可行性。
- 完成實際發射測試，所有火箭均穩定發射，四支中有兩支成功回收並處於可再次飛行之狀態；高度計資料證實實測遠地點達系統預測值之 80%，確立模擬與實驗的高度一致性。

### 適合對象
從事積層製造、航太工程、智能體系統與自動化設計領域之研究人員與工程師，以及對大型語言模型應用於實體硬體開發、多工具協調與參數化最佳化有興趣之讀者。

## 深度分析

#### 方法論解析

RocketSmith 作為一個 Agentic System (代理型系統)，實踐了 Agentic Additive Manufacturing (代理型積層製造) 的願景，專注於高功率火箭 (High-Powered Rocket) 的 DFAM (面向積層製造之設計) 全流程自動化。其架構遵循 Model Context Protocol (MCP) 標準，並以 Claude Code 的 Plugin (外掛) 形式實作，確保與支援 MCP 的 Agent Harness (代理框架) 相容。系統的核心協調器為 Large Language Model (LLM, 大型語言模型)，透過高階推理能力編排各類 Software Tool (軟體工具) 的執行順序與資料傳遞。

在具體工作流程上，RocketSmith 採用階層式的 Subagent (子代理) 與 Skill (技能) 設計，涵蓋 Component Tree (元件樹) 建構、Flight Simulation (飛行模擬)、Part Generation (零件生成)、Component Assembly (元件組裝)、Validation (驗證)、Manufacturing (製造)、Launch (發射) 與 Recovery (回收)。首先，系統依據使用者輸入的約束條件（如特定 Motor (推進器) 型號與 Flight Parameter (飛行參數)），在 OpenRocket 中建立參數化的 Component Tree (元件樹)。隨後，CADSmith 依據元件樹所規定的尺寸執行 Parametric Design (參數化設計)，生成可供製造的幾何模型。有別於早期 Text-to-CAD 方法將建模視為 Sequence Modeling (序列建模) 而導致 Parametric Error (參數誤差) 累積，RocketSmith 透過外部驗證訊號打破誤差傳遞鏈。

此系統最具架構意識的設計在於對數值精確任務的處理策略。針對 RocketBench 所揭示的 Frontier LLM (前沿大型語言模型) 難以將 Simulation Feedback (模擬回饋) 轉化為有意義 Design Update (設計更新) 之 Fundamental Limitation (根本性限制)，RocketSmith 不讓 LLM 直接推導或迭代數值參數，而是透過 Tool Calling (工具呼叫) 將 Stability Calculation (穩定性計算)、Trajectory Simulation (彈道模擬)、Slicing (切片) 與 Mass Estimation (質量估算) 委派給專用軟體。例如，PrusaSlicer 被用於取得列印後零件的精確質量，以此修正 Center of Gravity (重心) 並迭代優化 Flight Stability (飛行穩定性) 與其他 Design Characteristic (設計特性)。這種「各階段產生可驗證輸出，供下階段確定性消費」的 Deterministic Pipeline (確定性管線)，有效規避了 LLM 在數值推理上的瓶頸。

在操作模式上，系統支援 Zero-Shot (零樣本) 的全自動生成，亦保留 Human-in-the-Loop (人在迴路) 的介入彈性，使工程師能在關鍵決策點注入領域知識，調整 Assembly Configuration (組裝配置) 或修正製造參數，形成兼具自主性與可控性的 Optimization Workflow (最佳化工作流程)。

#### 實驗數據解讀

本研究以四款相異的 High-Powered Rocket (高功率火箭) 進行端到端驗證，分別搭載 AeroTech H100W、H219T（兩枚）與 J425R 等 Motor (推進器)，涵蓋多種動力與組裝情境。所有火箭的 Airframe (箭體) 結構皆透過 Fused Deposition Modeling (FDM, 熔融沉積成型) 進行 Additive Manufacturing (AM, 積層製造)，並經手動 Flight Readiness Evaluation (飛行就緒評估) 後進行實彈發射。

飛行結果呈現出雙面性。正面而言，四枚火箭均達成 Stable Launch (穩定發射)，證明 Agentic System (代理型系統) 在氣動外形與 Stability (穩定性) 設計上具備基本可靠性，能滿足 Class 2 高功率火箭的最低安全門檻。然而，僅有兩枚火箭在著陸後處於 Reflyable Condition (可再次飛行狀態)，回收成功率僅 50%。此結果強烈暗示 Recovery System (回收系統) 的結構設計存在餘裕不足之處，可能涉及降落傘部署時機、著陸衝擊耐受度，或是 FDM 薄壁結構在撞擊下的脆性問題。由於論文未詳述另外兩枚火箭的損壞模式與其 Apogee (遠地點/最高點) 數據，難以完整評估系統的 Robustness (穩健性)。

在預測準確度方面，Altimeter (高度計) 數據顯示實際達到的最高點約為 Agentic System (代理型系統) 預測值的 80%。對於涉及風切變、推力曲線誤差、表面粗糙度誘導拖曳及滾轉耦合的高功率火箭領域而言，80% 的 Simulation-Experiment Consistency (模擬實驗一致性) 已屬可接受範圍，顯示系統的物理建模與質量估算具備一定可信度。此 20% 的差距可能源自 FDM 零件的實際表面粗糙度、接合公差、未建模的頭部阻力效應，或是大氣條件的即時變化。若能將飛行後的實測數據自動回饋至 Simulation Model (模擬模型)，此差距有望進一步收斂。

#### 與現有研究的比較

相較於 Jadhav 等人的 LLM-3D Print，該研究聚焦於 FDM 列印過程中的 In-Situ (原位) 光學監控與缺陷修正，屬於製造階段的微觀品質控制；RocketSmith 則從系統層級出發，覆蓋設計、模擬、製造到發射的完整生命週期，屬於宏觀的端到端 DFAM (面向積層製造之設計) 自動化。兩者互補：前者確保製造過程的品質，後者確保設計到製造的整體一致性。

與 Simonds 等人的 RocketBench 相比，RocketBench 作為 Benchmarking Tool (基準測試工具)，明確指出標準 LLM 在 Iterative Refinement (迭代細緻化) 過程中無法有效利用模擬回饋進行設計更新。RocketSmith 直接回應此痛點，其架構核心在於「不讓 LLM 做算術，而讓 LLM 做決策」。透過將數值密集型任務外掛給 OpenRocket、PrusaSlicer 等專業 Software Tool (軟體工具)，RocketSmith 建立了 Deterministic Pipeline (確定性管線)，使設計更新基於可驗證的物理計算而非語言模型的機率推論。這是從「LLM 中心」到「工具增強型代理」的範式轉移。

相較於早期 Text-to-CAD 方法如 CAD-LLM 與 LLM4CAD，這些方法將 CAD 生成視為 Sequence Modeling (序列建模) 問題，容易在指令序列中累積 Parametric Error (參數誤差) 且缺乏外部校正機制。RocketSmith 則透過 CADSmith 產生 Parametric Model (參數化模型)，並以 PrusaSlicer 的實際質量數據與 OpenRocket 的飛行數據作為外部校正訊號，形成閉迴路驗證，避免誤差傳遞。

然而，RocketSmith 仍存在明顯局限。首先，其驗證範圍僅限於 Class 2 High-Powered Rocket (二級高功率火箭) 與 FDM 製程，未觸及金屬 AM (積層製造) 或更高動力等級所需的熱防護與結構強度問題。其次，50% 的回收率顯示 Recovery System (回收系統) 的設計尚未充分整合結構衝擊模擬。此外，Human-in-the-Loop (人在迴路) 的具體介入點、頻率與對最終設計的影響權重缺乏量化分析，使得系統的自主程度難以精確衡量。

#### 可重現性評估

在程式碼可用性方面，作者已將 RocketSmith 以 Plugin / Extension (外掛/擴充功能) 形式公開於 GitHub，並遵循 Model Context Protocol (MCP) 標準。由於系統核心依賴現成軟體（OpenRocket、CADSmith、PrusaSlicer）與商用 LLM API，無需額外的 Model Weight (模型權重) 或專屬 Dataset (資料集)，軟體層面的重現門檻相對較低。

然而，資料透明度仍有改善空間。論文未明確說明是否公開飛行實驗的原始 Altimeter (高度計) 數據、各火箭的完整 Component Tree (元件樹) 參數檔，或 PrusaSlicer 的 Slicing Profile (切片設定檔)。這些資料的缺失會使第三方難以執行完全一致的復現與對照實驗。

硬體與法規層面則構成高昂的重現成本。重現完整實驗需具備 FDM 列印設備、特定的高功率 Motor (推進器)、符合安全規範的發射場域，以及相應的監管許可。此外，文本中對 CADSmith 的技術細節、版本資訊與相依性揭露有限，且部分流程（如手動 Flight Readiness Evaluation (飛行就緒評估)）的標準作業程序未定義，精確重現仍具挑戰。

#### 未來研究方向

製程擴展與材料創新：未來應超越 FDM，整合 SLA (光固化)、SLS (選擇性雷射燒結) 或金屬 Additive Manufacturing (AM, 積層製造)，以提升 Structure Integrity (結構完整性) 與耐熱性，滿足更高級別 Motor (推進器) 與超音速飛行條件的需求。

閉迴路自主校正：建立從 Altimeter (高度計) 與 IMU (慣性測量單元) 到 Agentic System (代理型系統) 的自動數據回饋機制。利用實際飛行數據自動校正 Simulation Model (模擬模型) 的參數（如拖曳係數、推力損失與風阻模型），將目前 80% 的 Apogee (遠地點) 預測準確度進一步提升，邁向真正的自主迭代設計。

回收系統強化：針對 50% 回收率的短板，引入 Topology Optimization (拓撲最佳化) 與 Landing Impact Simulation (著陸衝擊模擬)，對 Recovery System (回收系統) 與箭體著陸段進行結構強化。可考慮整合可壓潰結構或氣動減速翼，降低對降落傘單一失效點的依賴。

領域知識增強：建構 High-Powered Rocket (高功率火箭) 專屬的 Domain-Specific Dataset (領域特定資料集)，透過 Fine-Tuning (微調) 或 RAG (檢索增強生成) 強化 LLM (大型語言模型) 在火箭工程領域的推理深度，逐步降低對 Human-in-the-Loop (人在迴路) 的依賴，並提升 Zero-Shot (零樣本) 設計的首次成功率。

多物理場耦合設計：將 Aerodynamic (空氣動力)、Thermal (熱力) 與 Structural (結構) 分析更緊密地整合至 Optimization Workflow (最佳化工作流程) 中，而非僅以質量與重心作為迭代依據。這將使系統能處理更複雜的 Flight Parameter (飛行參數) 權衡，如最大高度與橫向漂移的平衡。

法規與安全自動化：探索將發射許可、安全檢查清單與法規遵循編碼為 Skill (技能)，使 Agentic System (代理型系統) 能自動生成符合當地監管要求的文件，進一步壓縮從設計到 Launch (發射) 的時間，實現真正意義上的端到端無人化火箭開發。

## 論文問答

**Q1：在高功率火箭開發過程中，傳統設計與製造流程面臨哪些核心挑戰，促使 RocketSmith 這類代理型系統的誕生？**
A：傳統高功率火箭開發是一個高度迭代的過程，設計規格常因製造條件、零件取得或其他不可預見因素而變動，導致開發週期冗長且複雜。此外，飛行模擬、結構設計與積層製造之間存在顯著的流程摩擦，工程師必須在不同軟體工具間反覆切換與手動校正資料。這些多面向的設計與製造挑戰，使得單純依靠人工協調各項工具變得效率低下且容易出錯，因此迫切需要能自動化統籌整體流程的代理型系統來加速開發並降低迭代成本。

**Q2：現有的大型語言模型在火箭設計任務中存在哪些根本限制，而 RocketSmith 如何針對這些限制提出解決方案？**
A：根據 RocketBench 的研究發現，雖然前沿大型語言模型具備基礎工程直覺，但它們在迭代優化過程中難以將模擬回饋轉化為有意義的設計更新，性能始終低於人類專家水準。早期文字轉 CAD 的方法也面臨尺寸精度不足的問題，因為參數化錯誤會在連續建模序列中不斷累積，且缺乏外部修正機制來及時導正。RocketSmith 透過將數值精確的任務（如穩定性計算、彈道模擬、切片與質量估算）委派給專業軟體工具，而非讓語言模型直接推論與修改參數，從而克服了這些根本限制並確保設計精度。

**Q3：為何積層製造技術特別適合應用於高功率火箭開發，而代理型系統的導入又能為此帶來何種附加價值？**
A：積層製造具備傳統製程難以實現的迭代設計、快速原型製作與零件整合能力，這對於開發資源受限且成本彈性高的航太產業極具吸引力。高功率火箭的開發環境正好需要處理多面向的設計與製造整合問題，而積層製造能提供獨特的零件整合與飛行優化解決方案。代理型系統的導入進一步將大型語言模型的複雜推理能力與工具呼叫能力結合，自動協調飛行模擬、參數化設計與製造檔案生成，顯著提升了整體開發效率與設計一致性。

**Q4：RocketSmith 的核心運作架構為何，它如何透過子代理與技能來完成高功率火箭的端到端開發？**
A：RocketSmith 是一個符合模型上下文協定（MCP）標準的代理型系統，以大型語言模型作為核心協調器，並以外掛形式整合於 Claude Code 中運作。系統內建多個子代理與技能，能夠依據使用者提供的限制條件（如特定推進器與飛行特性），自動執行 OpenRocket 飛行模擬、CADSmith 參數化模型生成，以及 PrusaSlicer 精確質量計算等任務。這些子代理透過最佳化工作流程，在零樣本或人在迴路模式下持續迭代調整飛行參數，最終輸出可用於積層製造的設計檔案與製造指令。

**Q5：相較於讓大型語言模型直接進行設計參數的迭代優化，RocketSmith 在架構設計上的關鍵創新為何？**
A：RocketSmith 的關鍵創新在於採用「工具委派」的架構設計，將需要數值精確度的任務（如穩定性計算、彈道模擬、切片與重心估算）從語言模型的推理過程中分離出來。這種設計確保每個階段都能產生可驗證的輸出結果，並由下一個階段以確定性的方式接收與處理，避免了標準大型語言模型難以將模擬回饋轉化為有效設計更新的核心失敗模式。透過這種結構化流程，系統不僅提升了設計精度，也建立了從數位模擬到實體飛行的一致性驗證基礎。

**Q6：RocketSmith 在設計上為何選擇整合 OpenRocket、CADSmith 與 PrusaSlicer 等特定工具，這些工具在系統中各自扮演什麼角色？**
A：OpenRocket 負責建立火箭的元件樹與基礎飛行模擬，提供符合使用者限制條件的整體架構與氣動力學驗證，是設計流程的邏輯起點。CADSmith 則依據元件樹所規定的尺寸，生成可供積層製造使用的參數化幾何模型，確保設計意圖能準確轉化為實體結構。PrusaSlicer 的導入是為了取得更精確的零件重量計算，這些數據能顯著改善重心估算的準確度，使系統能在製造前迭代優化火箭的飛行穩定性。

**Q7：為了驗證 RocketSmith 的實際性能，研究團隊設計了什麼樣的實驗與測試流程？**
A：研究團隊利用 RocketSmith 開發了四款配置各異的高功率火箭，分別採用不同的推進器與組裝設定，以驗證系統在面對多樣化設計需求時的適應能力與穩健性。這些火箭的組裝零件透過多臺不同的熔融沉積成型（FDM）印表機製造完成，並在發射前經過人工飛行準備評估以確保基本安全。隨後，所有火箭皆在實際發射活動中進行飛行測試，並透過高度計收集定量數據，同時記錄飛行穩定性與回收狀態等質性指標。

**Q8：飛行測試的結果顯示 RocketSmith 的設計與模擬之間具有何種程度的一致性，具體數據為何？**
A：飛行測試結果顯示，四枚火箭全數達成穩定發射，證明系統在飛行穩定性設計上的可靠性與安全性。高度計數據進一步驗證，火箭實際達到的最高點（apogee）為代理型系統預測高度的百分之八十，顯示模擬與實驗之間具有可接受的相關性與一致性。雖然存在百分之二十的落差，但這樣的結果仍初步確立了從數位模擬到實體飛行之間的預測有效性，為後續優化提供了基準。

**Q9：RocketSmith 如何透過實驗結果回應 RocketBench 所揭示的標準大型語言模型在迭代設計中的局限性？**
A：RocketBench 指出標準大型語言模型難以將模擬回饋轉化為有意義的設計更新，而 RocketSmith 透過四枚火箭的成功穩定發射，驗證了其工具委派架構能有效克服此一瓶頸。系統不直接要求語言模型推論數值參數，而是讓各專業工具產生可驗證的輸出，再將結果餵入下一個確定性階段，這種設計在實體飛行中獲得了直接驗證。最終百分之八十的預測高度達成率，也證明這種分階段、工具導向的迭代流程，能夠產出足以實際飛行且符合工程標準的設計。

**Q10：RocketSmith 在實務上最適合應用於哪些高功率火箭開發情境，其自動化能力能為開發團隊帶來什麼具體助益？**
A：RocketSmith 特別適合需要快速迭代與客製化設計的第二類（Class 2）高功率火箭開發專案，尤其是當設計規格可能因製造條件或零件供應狀況而頻繁變動時。開發團隊可利用此系統在零樣本模式下快速生成符合特定推進器與飛行特性限制的初始設計，或在人在迴路模式中讓工程師介入關鍵決策以確保安全。這種自動化協調能力大幅減少了工程師在不同模擬、設計與製造軟體間手動轉換資料的時間，顯著壓縮了從概念到發射的開發週期。

A：RocketSmith 採用模型上下文協定（MCP）標準進行開發，確保其架構具備良好的互通性與模組化擴充潛力，便於未來整合更多外部工具。系統以 Claude Code 外掛程式的形式發布，並將原始碼公開於 GitHub，降低了其他開發者或研究人員的導入門檻與客製化成本。這種外掛式設計不僅讓使用者能在熟悉的開發環境中呼叫代理功能，也便於未來無縫整合更多不同的模擬引擎、CAD 工具或積層製造設備。

**Q12：RocketSmith 的研究成果對於代理型積層製造與航太工程領域可能產生什麼樣的深遠影響？**
A：RocketSmith 首次展示了代理型系統如何將大型語言模型的推理能力與實體工程工具鏈深度整合，成功完成從設計、模擬到飛行驗證的完整高功率火箭開發流程。這項研究證明了在航太這類對精度與安全性要求極高的領域，透過工具委派與確定性階段銜接，可以有效降低單純依賴語言模型推論所帶來的風險與不確定性。其方法論不僅可推廣至其他需要面向積層製造之設計（DFAM）的應用場景，也為未來自主工程設計系統的發展提供了重要的架構參考。

**Q14：從實驗結果來看，哪些具體的失敗或部分失敗案例揭示了 RocketSmith 在實際應用中的脆弱環節？**
A：四枚火箭中僅兩枚能被成功回收且處於可再次飛行的狀態，另外兩枚的回收失敗暗示系統在降落傘部署時機、結構強度或降落預測等環節可能存在設計盲點與穩健性不足。實際飛行高度與預測高度存在百分之二十的偏差，也暴露出系統在質量估算、空氣阻力模型或推進器性能預測方面可能不夠精確。這些結果顯示，儘管火箭能穩定發射，但從飛行頂點到安全回收的完整任務週期仍需更穩健的設計驗證機制與容錯設計。

**Q15：基於現有的實驗成果與限制，RocketSmith 未來的研究與開發可以朝哪些方向進行改進與擴展？**
A：未來研究可針對回收系統進行專項優化，透過更精細的降落模擬與多重部署機制設計，提升火箭的安全回收率並縮小模擬與實際落點的落差。系統亦可進一步整合即時感測資料與數位孿生技術，在飛行過程中動態修正參數，以彌補目前靜態模擬與真實環境之間的百分之二十高度偏差。此外，將自動化飛行就緒檢查納入代理工作流程，並擴展至更大型或更複雜的火箭級別，將是提升系統自主化程度與工程適用性的重要方向。

## 實務應用指南

### 適用場景

1. **業餘與學術高功率火箭快速開發**：大專院校航太工程課程或業餘火箭俱樂部可利用 RocketSmith 在短週期內完成從設計約束輸入到 FDM 列印件產出之全流程，縮短傳統需數週之手動參數化設計與穩定性驗證流程。
2. **新創航太次系統概念驗證**：針對探空火箭或酬載平台的次系統（如回收艙段、酬載支架），新創團隊可透過代理型積層製造快速迭代不同馬達與組裝配置，在實體試飛前以零樣本方式生成多組候選設計並透過 OpenRocket 進行彈道篩選。
3. **積層製造服務商之客製化載具代工**：具備 FDM 產能的代工廠可導入此系統作為前端工程自動化層，直接接收客戶以自然語言描述之飛行需求（如目標遠地點、穩定度邊際），自動輸出可列印之參數化 CAD 與切片檔案，降低工程溝通成本。
4. **人在迴路之雙重部署回收系統開發**：對於需採用雙重部署（drogue + main parachute）之 Class 2 高功率火箭，RocketSmith 可協調飛行參數最佳化工作流程，讓具有 Level 2/3 認證之工程師在關鍵節點審查開傘高度與下降速率，再交由子代理重新生成艙段與繩具固定結構。

### 實作前置條件

**資料（Data）**
- 推進器資料庫：須具備目標馬達（如 AeroTech H100W、H219T、J425R）之官方推力曲線與質量屬性，供 OpenRocket 進行六自由度彈道模擬。
- 材料物性表：FDM 線材（建議使用 ABS、PETG 或尼龍）之密度、層間抗拉強度與熱變形溫度，用於 PrusaSlicer 精確估算重心與 CADSmith 結構設計。
- 發射場環境資料：歷年風速、氣溫與海拔數據，作為飛行模擬之邊界條件與降落傘尺寸選型依據。

**運算（Compute）**
- LLM 推論端：可呼叫 Claude 系列模型之 API 權限，或本地部署支援 MCP（Model Context Protocol）之代理型系統主機。
- 工程工作站：可執行 OpenRocket、CADSmith 與 PrusaSlicer 之 x86 或 ARM 工作站；若為教育用途，建議配備可進行中等規模 FDM 列印（build volume ≥ 250×250×300 mm）之 3D 印表機群。
- 飛行記錄硬體：具備資料記錄功能之高度計（altimeter），用於回收後驗證實際遠地點與代理預測之一致性。

**技能（Skill）**
- 系統整合：熟悉 Python 外掛開發與 MCP 通訊協定，能將 RocketSmith 作為 Claude Code 外掛部署。
- 領域知識：至少一名團隊成員須持有 Tripoli Rocketry Association 或 NAR 之 Level 2（含）以上高功率火箭認證，熟悉 FAA Part 101 或當地民航主管機關之發射法規。
- 製造工藝：具備 FDM 列印參數調校、方向性強度補償（如徑向 vs. 軸向受力層取向）與後處理（支撐移除、表面打磨、螺紋孔攻牙）之實務經驗。

### 實作步驟建議

1. **工具鏈串接與外掛部署**：依據 MCP 標準將 RocketSmith 安裝為 Claude Code 外掛，確認子代理能成功呼叫 OpenRocket（生成零組件樹）、CADSmith（參數化建模）與 PrusaSlicer（切片與質量估算）之 API 或 CLI。
2. **設計約束輸入**：由使用者在自然語言介面中指定飛行參數（目標遠地點、馬達型號、穩定度邊際、單／雙重部署模式），代理型系統據此建立初始 component tree。
3. **零樣本設計生成與模擬**：LLM 協調子代理執行首次飛行模擬，取得預測彈道、重心與壓心位置；此階段不應由 LLM 直接修改數值，而應透過軟體工具輸出確定性結果。
4. **迭代式穩定性最佳化**：將 PrusaSlicer 回傳之精確列印質量代入 OpenRocket，重新計算穩定度；若未達標，由子代理自動調整鼻錐長度、尾翼尺寸或配重，並在關鍵節點觸發人在迴路審查。
5. **參數化模型與製造檔案輸出**：凍結設計後，CADSmith 生成火箭箭體、回收艙段與尾翼之參數化模型，並轉出 STL／STEP；PrusaSlicer 自動生成 G-code，並依據列印方向標註層間受力風險。
6. **積層製造與組裝驗證**：以 FDM 印製各組件，進行手動裝配與干涉檢查；特別驗證回收系統之繩具通道與彈射機構（ejection charge bay）之尺寸公差。
7. **飛行測試與資料閉迴路**：於合規發射場進行試飛，記錄高度計之實際遠地點與回收狀態；將實測數據回饋至 RocketSmith，比對模擬預測偏差並更新未來任務之空氣阻力或質量估算係數。

### 潛在風險與注意事項

- **LLM 數值推理誤差**：RocketBench 研究已揭示，標準 LLM 難以將模擬反饋轉化為有意義的設計更新。務必將穩定性計算、彈道模擬與質量估算等數值精確任務委派給專業軟體工具，僅讓 LLM 負責流程編排與異常判斷，避免參數漂移。
- **模擬與實飛之系統性偏差**：論文顯示實際遠地點僅達代理預測值之 80%，可能源於風阻係數、實際推進器總衝偏差或 FDM 表面粗糙度。建議在模擬階段預留 20–25% 高度餘裕，並於首次飛行採用過尺寸降落傘以降低回收損傷風險。
- **結構強度與方向性失效**：FDM 零件之層間結合強度顯著低於同材料之射出或纖維複合件。承受推進器應力之尾翼座與回收艙段卡扣必須避免層間剝離方向與主要受力軸重合；必要時應在切片階段由 PrusaSlicer 模擬驗證，或改掦高強度列印參數（如提高填充率、使用碳纖維複合線材）。
- **法規與安全責任**：高功率火箭之發射須符合當地空域管理法規，並經過發射場 Range Safety Officer（RSO）檢查。代理型系統產出之設計文件應附帶材料安全資料表（MSDS）與推進器儲存規範，且最終飛行許可必須由具認證之人類工程師簽署，不可全權交由自動化系統決策。
- **人在迴路延遲凍結設計**：過度頻繁之人機迭代將抵銷自動化帶來之週期優勢。建議設定明確之設計凍結檢查點（如模擬穩定度邊際 ≥ 1.5 且結構應力通過閾值後即鎖定 CAD），避免無止境之參數微調。

### 與其他技術的整合建議

- **產品生命週期管理（PLM）系統**：將 RocketSmith 生成之零組件樹與參數化 CAD 自動寫回 PLM（如 Siemens Teamcenter 或開源 OpenPLM），實現設計版本追溯與構型管理，確保每一次代理迭代皆留下不可竄改之數位足跡。
- **高階結構模擬（CAE）**：OpenRocket 僅提供剛體彈道分析，建議在製造前將 CADSmith 輸出之 STEP 檔案導入 ANSYS Mechanical 或 Abaqus，針對鼻錐著陸衝擊與開傘瞬間過載進行顯式動力學分析，補強飛行穩定性驗證之不足。
- **機器視覺即時品管**：參考 LLM-3D Print 之架構，在 FDM 列印過程中加裝光學層析相機，由獨立視覺子代理監控翹曲、層間分離等缺陷，並即時調整熱床溫度或列印速度，提升回收級零件之良率。
- **數位孿生（Digital Twin）閉迴路**：建立以飛行測試高度計數據為回饋訊號之數位孿生平台。每次試飛後，將實測彈道與代理預測之偏差自動歸因至質量、阻力或風場模型，持續精煉未來任務之預測準確度。
- **低程式碼自動化平台**：透過 MCP 標準將 RocketSmith 之技能（Skills）封裝為 RESTful 端點，使企業內部之低程式碼平台（如 n8n、Make）或 RPA 流程得以呼叫，讓非程式背景之工程師也能以表單觸發火箭設計自動化流程。

### 給不同背景讀者的閱讀建議

**初學者（Beginners）**：建議先建立高功率火箭之基本時序概念——從點火、燃燒結束、遠地點到回收部署——並理解積層製造之層向強度限制。閱讀時可略過 MCP 協定與外掛開發細節，將重點放在「人在迴路」章節，觀察人類工程師如何在代理系統中扮演安全守門員與設計凍結決策者之角色。

**AI 工程師（AI Engineers）**：請聚焦於 RocketSmith 之架構決策——為何選擇透過 MCP 將 LLM 與 OpenRocket、CADSmith、PrusaSlicer 等異質工具串接，而非直接讓模型生成數值參數。這種「工具呼叫優先於數值推理」之設計模式，對於建構其他硬體領域（如無人機、機器人）之代理型系統具有高度可遷移性。

**研究人員（Researchers）**：值得深入探討論文揭示之模擬-實驗一致性問題——實際遠地點僅達預測 80%。可進一步研究如何透過更精細之 FDM 表面粗糙度模型、即時風場耦合或推進器總衝機率分布，縮小代理預測與物理實現之差距；亦可延伸至多級火箭或主動導控系統之代理型設計方法。
