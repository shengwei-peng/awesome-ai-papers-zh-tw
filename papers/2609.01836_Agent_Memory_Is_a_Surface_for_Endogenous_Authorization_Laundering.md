## ⚡ TL;DR

本文揭示 LLM 智慧體的持久記憶會內生地「洗白」授權，使未授權請求看似合法。
作者提出 EAL-Bench，分離記憶中虛假權限的形成與後續執行傳播，評估多領域與記憶設計。
實驗顯示寫入模型對逾半未授權請求製造虛假權限，執行器幾乎全數執行；兩種防護可降低洗白但犧牲實用性。

## 摘要翻譯

長時間運作的大型語言模型（LLM）智慧體仰賴持久記憶（Persistent Memory）來跨互動保存狀態，包括權限（Permissions）、限制（Restrictions）與撤銷（Revocations）。當記憶錯誤呈現這種不斷演變的授權狀態（Authorization State）時，智慧體自身的記錄可能會授予底層歷史從未允許的權限，導致在沒有任何外部攻擊的情況下出現行為錯配（Misaligned Behavior）。

我們將這種失效稱為內生性授權洗白（Endogenous Authorization Laundering）：寫入記憶中的偽造權限（Spurious Permissions）會因其來源（Provenance）被抹除，而導致未經授權的動作（Unauthorized Actions）。接著，我們提出 EAL-Bench，用於衡量持久記憶保存不斷演變之授權狀態的準確性，以及錯誤是否會傳播至下游的未經授權動作（Downstream Unauthorized Actions）。

我們評估五個大型語言模型作為記憶寫入模型（Memory Writers），以及兩個作為執行模型（Executors），涵蓋採購（Procurement）、網路安全（Cybersecurity）與金融（Finance）領域。我們發現，在增量式記憶更新（Incremental Memory Updates）下，記憶寫入模型會為高達 50.2% 的未經授權請求（Unauthorized Requests）創造虛假權限（False Authority）；一旦虛假權限存在，執行模型會在 98.6% 的試驗中據此行動。兩種防護機制——要求儲存的權限必須有有效的來源事件（Source Events）作為依據，以及透過有界事件溯源（Bounded Event Sourcing）追蹤權限變更——能顯著降低洗白現象，但兩者也會拒絕更多合法動作，凸顯出安全性–實用性權衡（Safety-Utility Tradeoff）。

因此，持久記憶不僅僅是效能元件，更是大型語言模型智慧體實際授權政策的一部分。

### 核心貢獻（3～5點）
- 提出「內生性授權洗白」（Endogenous Authorization Laundering）這一新的失效模式，說明 LLM 智慧體的持久記憶可能因錯誤表徵授權狀態而自行產生虛假權限，無需外部攻擊即可導致未經授權的行為。
- 建立 EAL-Bench 評測基準，用於量化持久記憶保存演變授權狀態的準確性，並追蹤記憶錯誤如何傳播至下游的未經授權動作。
- 在採購、網路安全與金融三個領域進行實證評估，發現增量式記憶更新下，記憶寫入模型可為高達 50.2% 的未經授權請求創造虛假權限，而執行模型一旦看到虛假權限便有 98.6% 的機率據此行動。
- 提出並評估兩種防護機制：要求權限須有有效來源事件作為依據，以及透過有界事件溯源追蹤權限變更；兩者雖能顯著降低洗白，卻也會拒絕更多合法動作，揭示安全性–實用性權衡。

### 適合對象
從事 LLM 智慧體安全、記憶系統設計、存取控制與授權政策研究的學者與工程師；特別適合關注智慧體長期運作安全、內生風險評估，以及企業應用（如採購、網路安全、金融）中授權治理的讀者。

## 深度分析

#### 方法論解析

本研究將「智慧體記憶（Agent Memory）」視為一種隱性的授權政策（authorization policy）介面，並提出「內生性授權洗白（Endogenous Authorization Laundering, EAL）」這一失效模式。其核心洞見在於：當大型語言模型智慧體（LLM Agents）把長時間的互動歷程壓縮成持久記憶（Persistent Memory）時，記憶中保存的「授權狀態（Authorization State）」可能與真實歷史脫節，進而讓未經授權的請求（Unauthorized Requests）看起來合法，並在沒有外部攻擊的情況下導致未經授權的動作（Unauthorized Actions）。

為了把問題結構化，作者將整個流程拆成兩個階段：

1. **虛假權限形成（False Authority Formation）**：記憶寫入模型（Memory Writer）\(W\) 將組織歷史（Organizational History）\(H=(B_1,\dots,B_T)\) 轉換為持久記憶 \(M_T\)。若 \(M_T\) 認定某動作 \(a_q\) 被授權，但隱藏的標準帳本（Canonical Ledger）\(S_t=R(B_1,\dots,B_t)\) 實際上並未授權，則形成虛假權限（False Authority）。數學上以指標函數表示：
   \[
   F(M_T,a_q)=\mathbf{1}\{A(S_T,a_q)=0 \land A_M(M_T,a_q)=1\}
   \]

2. **下游傳播（Downstream Propagation）**：執行模型（Executor）\(E\) 僅根據 \(M_T\) 與後續請求 \(q\) 決定行動。若執行器執行了被記憶錯誤授權的動作，則傳播發生：
   \[
   G(E,M_T,q)=\mathbf{1}\{E(M_T,q)=a_q\}
   \]

端到端的洗白機率因此可分解為：
\[
P(F=1)\,P(G=1\mid F=1)
\]
這種分解是本方法論的關鍵：它讓研究者能夠區分「記憶寫錯」與「執行器太聽話」這兩種不同來源的錯誤，而不會把執行器的忠實性誤判為記憶本身的問題。

為了實現上述分解，EAL-Bench 設計了幾項重要機制：

- **隱藏式決定性帳本（Hidden Deterministic Ledger）**：作為真實授權狀態（Ground-Truth State）的黃金標準，用來判定任何動作是否真正被授權。
- **成對的授權–未授權請求（Paired Authorized–Unauthorized Requests）**：每個測試案例同時包含應該通過與不應通過的請求，藉此檢驗記憶是否同時避免過度授權（over-grant）與過度拒絕（under-grant）。
- **忠實記憶對照組（Faithful-Memory Controls）**：把執行器放在「記憶正確」的條件下，測量執行器本身的可靠性。
- **精確狀態修復（Exact-State Repair）**：把寫入模型產生的記憶直接替換為標準帳本中的真實狀態，觀察未經授權動作是否消失。這項介入能夠把失敗定位到記憶層，而非執行層。

在記憶格式方面，EAL-Bench 比較了自由文字記憶（Free-Text Memory）與型別化記憶（Typed Memory），並比較一次性（One-Shot）與增量式記憶更新（Incremental Memory Updates）。型別化記憶的優勢在於 \(A_M(M_T,x)\) 可以決定性評估，讓虛假權限的檢測更為精確；增量更新則更貼近真實長時間運作智慧體的維護方式，但也更容易因為上下文壓縮（Context Compaction）或摘要遺漏而喪失關鍵授權資訊。

整體而言，這套方法論把「記憶」從單純的效能元件重新框定為「授權政策的具體化身」。當記憶出錯時，即使執行器完全按照提示行事，整個系統仍然會產生違規行為。

#### 實驗數據解讀

實驗橫跨三個高風險領域：採購（Procurement）、網路安全（Cybersecurity）與金融（Finance），並使用五個大型語言模型作為記憶寫入模型（Memory Writer）、兩個經過校準（Calibration）的模型作為執行模型（Executor）。測試情境涵蓋自由文字與型別化記憶，以及一次性與增量式更新。

主要結果可歸納為以下幾點：

1. **虛假權限形成率顯著**：在增量式記憶更新下，記憶寫入模型最多會為 **50.2%** 的未經授權請求創造出虛假權限（False Authority）。這表示當歷史中發生權限撤銷（Revocations）、限制（Restrictions）或範圍替換時，模型很容易在摘要或更新過程中遺漏這些變化，導致舊權限繼續存在，或把非權威來源的類別誤認為有效授權。

2. **傳播率極高**：一旦記憶中出現虛假權限，執行模型在 **98.6%** 的匹配試驗中會據此執行未經授權的動作（Unauthorized Actions）。這說明執行器對記憶高度忠實，問題主要不在執行器「太叛逆」，而在於記憶本身已經被洗白。

3. **精確狀態修復可消除違規**：當研究者把錯誤記憶替換為標準帳本（Canonical Ledger）中的真實授權狀態（Ground-Truth State）後，未經授權動作幾乎完全消失。這進一步把失敗來源定位到記憶層，確認是「記憶寫入」而非「執行決策」造成洗白。

4. **緩解策略的安全–實用性權衡（Safety-Utility Tradeoff）**：作者評估了兩種防護機制：
   - 要求儲存的權限必須有有效的來源事件（Source Events）作為依據；
   - 透過有界事件溯源（Bounded Event Sourcing）追蹤權限變更。

   兩者都能顯著降低內生性授權洗白（Endogenous Authorization Laundering）的發生率，但同時也會提高對合法請求的拒絕率。這揭示了一個典型的安全–實用性權衡：過度嚴格的來源驗證可能讓原本有效的行動因為缺乏「可接受的證明格式」而被擋下。

5. **領域與記憶設計的差異**：雖然摘要中未提供每個領域的細部分數，但從論述可推論，採購（Procurement）中的 ERP 類別（ERP Category）授權、網路安全中的系統變更權限、以及金融中的交易限制，都是容易因記憶壓縮而失真的環節。型別化記憶雖然便於決定性檢查，但並不保證寫入模型不會填入錯誤欄位；自由文字記憶則更難追蹤來源（Provenance）。

整體數據傳達的訊息相當明確：在長時間運作的 LLM 智慧體中，記憶不是單純的「效能優化快取」，而是決定行為是否合規的關鍵政策表面。只要記憶層出錯，即使執行器表現完美，系統仍會大規模違規。

#### 與現有研究的比較

本研究在記憶完整性（Memory Integrity）與授權安全兩條研究線之間找到了一個過去較少被明確測量的縫隙。作者透過表 1 清楚定位 EAL-Bench 與相關工作的差異：

- **AUTHMEM-BENCH**：聚焦於「權限崩潰（authority collapse）」，即在固定主張與下游任務下，改變來源權威性來觀察行為變化。EAL-Bench 則反過來讓歷史本身演變，追蹤權限（Permissions）、限制（Restrictions）、撤銷（Revocations）與替換（Replacements）在多次記憶更新後的命運，並區分虛假權限形成與其後續傳播。

- **PPMF**：從對抗或不可信觀察出發，形式化「來源權威不放大（source-authority non-amplification）」。EAL-Bench 的起點是真實、非惡意的歷史，並透過精確狀態修復（Exact-State Repair）區分「來源不可信」與「來源可信但範圍/生命週期被記憶扭曲」這兩類錯誤。

- **GATEMEM**：強調在檢索時強制執行生命週期感知的存取邊界。EAL-Bench 與之互補：GATEMEM 關注「檢索時的閘門是否正確」，EAL-Bench 則關注「閘門背後的狀態是否一開始就被正確記住」。

- **HARNESSAUDIT**：評估完整智慧體軌跡中的權限、資源存取與資訊流違規，但假設執行器所參考的狀態是正確的。EAL-Bench 直接挑戰這個假設，研究當參考狀態本身被記憶扭曲時會發生什麼。

- **MASDRIFT**：研究多智慧體委派（multi-agent delegation）造成的授權約束弱化，屬於「跨智慧體漂移」。EAL-Bench 則研究「單一智慧體內部持久狀態隨時間漂移」，兩者形成互補的內生性失效光譜。

相較於現有研究，EAL-Bench 的主要貢獻在於：

- 明確區分 **formation**（記憶中產生虛假權限）與 **propagation**（執行器據此行動）兩個階段；
- 引入隱藏式決定性帳本（Hidden Deterministic Ledger）與精確狀態修復，提供可定位錯誤來源的實驗設計；
- 覆蓋增量式記憶更新（Incremental Memory Updates），這是實際部署中最常見卻也最難評估的設定；
- 同時評估緩解措施的安全效益與實用成本，避免只報告單一指標。

不過，這項研究也有其侷限。首先，實驗中的歷史與領域雖然貼近真實，但仍屬於合成或半合成資料，真實世界中的雜訊、模糊授權與人類例外處理可能更難建模。其次，執行器僅有兩個，且都經過校準，可能無法完全代表未經校準或高度創意化的模型行為。最後，緩解策略雖然有效，但拒絕合法行動的代價在實際商業系統中可能難以接受，需要更細緻的調校。

#### 可重現性評估

根據摘要與內文，EAL-Bench 被描述為「開源且可擴充（open-source and extensible）」的評測基準，涵蓋採購、網路安全與金融三個領域，並提供標準帳本（Canonical Ledger）作為真值。這對可重現性（Reproducibility）是正面訊號：若資料集、評分腳本與實驗設定確實公開，其他研究者應能在相同條件下複製虛假權限形成率與傳播率的測量。

然而，從提供的上下文來看，有幾點需要進一步確認：

- **程式碼與資料集連結**：文中雖強調開源，但並未在摘錄中給出 GitHub、Hugging Face 或專案網頁的具體 URL。完整的可重現性評估需要這些資源實際可用，並包含環境設定、相依套件版本與隨機種子。
- **模型權重**：實驗使用五個記憶寫入模型與兩個執行模型。若這些是公開模型（如 GPT-4、Claude、Llama 等），則可透過 API 或開源權重重現；若包含私有或內部校準模型，則部分結果可能難以完全複製。
- **標準帳本與領域規則**：由於授權判定依賴隱藏的決定性函數 \(R\) 與 \(A\)，這些規則必須完整公開，否則外部研究者無法驗證「真實授權狀態」的定義是否合理。
- **提示模板（Prompt Templates）**：記憶寫入與執行階段的提示設計對結果影響極大。為了可重現，這些模板、少樣本範例（few-shot examples）與輸出解析邏輯都應一併釋出。
- **增量更新協定**：增量式記憶更新涉及如何壓縮、何時壓縮、保留哪些欄位等實作細節，這些協定的公開程度會直接影響實驗能否被複製。

總體而言，EAL-Bench 在設計層面具備良好的可重現性潛力：問題形式化清楚、指標可計算、介入方法（精確狀態修復）可重複執行。但實際可重現性仍取決於作者是否釋出完整的程式碼、資料、提示與模型存取資訊。建議後續版本補充這些細節，並提供一鍵執行的重現腳本。

#### 未來研究方向

這篇論文為 LLM 智慧體的授權記憶安全開啟了多條值得深入的研究路徑：

1. **形式化驗證記憶寫入模型**：目前 EAL-Bench 採用經驗性評估，未來可發展形式化方法或符號執行技術，證明某個記憶寫入程序在特定歷史類別下不會產生虛假權限。

2. **混合神經–符號授權狀態表示**：將大型語言模型的靈活性與決定性授權資料結構結合，例如讓 LLM 負責自然語言理解，但把權限生命週期儲存在可由標準帳本驗證的型別化記憶中。

3. **來源追蹤與可解釋性**：設計能夠在記憶中保留每條權限的來源事件（Source Events）與變更鏈的機制，並讓執行器在決策時說明「根據哪一條記憶條目採取行動」。

4. **線上監控與異常偵測**：在智慧體運行時持續比對記憶內容與原始事件日誌，當發現記憶授權與事件溯源（Event Sourcing）不一致時觸發警報或凍結行動。

5. **授權感知的上下文壓縮**：開發專門的壓縮演算法，在減少記憶長度的同時，優先保留授權狀態的關鍵資訊，避免行動前確認（Confirm-Before-Acting）或撤銷指令被摘要掉。

6. **多智慧體與委派鏈的擴展**：結合 MASDRIFT 的視角，研究當授權在多個智慧體之間委派時，記憶洗白與委派漂移如何交互作用。

7. **動態安全–實用性權衡調適**：目前的緩解措施會同時拒絕更多合法行動。未來可研究根據領域風險、請求敏感度和不確定性，動態調整來源驗證的嚴格程度。

8. **對抗穩健性與記憶污染防禦**：雖然 EAL-Bench 聚焦內生性錯誤，但其框架也可用於評估記憶污染（Memory Poisoning）與提示注入攻擊（Prompt Injection Attacks）如何與正常摘要錯誤交互放大。

9. **真實部署審計與使用者研究**：將 EAL-Bench 的方法應用於實際的電子郵件智慧體（Email Agent）、企業助理或金融交易系統，並研究人類監督者能否及時發現記憶洗白。

10. **跨語言與跨文化授權語義**：不同語言與組織文化對「限制（Restrictions）」、「撤銷（Revocations）」與「例外」的表達方式不同，未來可擴充 EAL-Bench 以評估多語言與跨文化情境下的授權記憶保真度。

總結來說，這項研究不僅提出了一個具體的失效模式與評測工具，更重要的是把「記憶」重新定位為智慧體安全架構中的核心政策元件。未來的工作若能從形式化保證、混合架構、線上監控與真實部署四個方向同時推進，將有助於建立更值得信賴的長時間運作 LLM 智慧體。

## 論文問答

**Q1：什麼是「內生性授權洗白」（endogenous authorization laundering），它與外部攻擊有何不同？**

A：內生性授權洗白是指智慧體自身的持久記憶產生了底層歷史從未授予的虛假權限，使得後續執行器依據這份錯誤記憶採取未經授權的動作。這種失效並非來自外部的記憶污染或提示注入攻擊，而是源於記憶寫入、壓縮或更新過程中的普通內部錯誤。由於權限的原始出處（provenance）在記憶中被「洗掉」，執行時看起來一切合法，違規行為因此難以被即時察覺。

**Q2：現有的記憶評估方法為何難以發現這類問題？**

A：現有評估多半聚焦於召回率、對抗情境或下游任務表現，並未系統性地檢驗授權狀態是否隨著權限、限制與撤銷事件而正確演變。它們通常把記憶視為提升效能的元件，而非授權決策的依據，因此會遺漏「記憶中形成虛假權限」這一關鍵環節。EAL-Bench 正是為了填補這個缺口，將授權狀態的保存與傳播獨立出來進行測量。

**Q3：為何作者主張「持久記憶本身就是授權政策的一部分」？**

A：因為長時間運作的 LLM 智慧體會把權限、限制與撤銷等授權狀態存放在持久記憶中，後續所有行動是否被允許都取決於這份記憶。一旦記憶遺漏撤銷或錯誤保留已失效的權限，它就實質上改變了智慧體的有效授權政策。因此，記憶的設計與維護不僅是效能議題，更是安全與治理的核心環節。

**Q4：EAL-Bench 的核心架構是什麼？它如何隔離記憶導致的失效？**

A：EAL-Bench 包含三個主要角色：記憶寫入模型負責把演變歷程轉換為持久記憶，執行模型依據該記憶對後續請求選擇動作，而隱藏的決定性標準帳本則定義真實授權狀態。透過成對的授權與未授權請求，以及忠實記憶對照組，研究者可以區分錯誤是來自記憶失真還是執行器本身的問題。此外，精確狀態修復會把錯誤記憶替換為真實狀態，進一步確認未經授權行動是否確實由記憶錯誤所引起。

**Q5：EAL-Bench 如何區分「虛假權限形成」與「下游傳播」兩個階段？**

A：它用兩個指標分別刻畫：第一個指標衡量記憶是否把未經授權的請求錯誤標記為合法，即虛假權限的形成；第二個指標則衡量一旦虛假權限存在，執行器是否會據此採取行動，即授權洗白的傳播。這種分離讓研究者能判斷問題主要出在記憶寫入階段，還是執行階段過於輕信記憶。最終的端到端洗白率等於形成率乘以在虛假權限存在下的執行率。

**Q6：EAL-Bench 在記憶設計上有哪些關鍵變因？**

A：評測同時納入自由文字記憶與型別化記憶，並比較一次性生成與增量式記憶更新兩種維護方式。型別化記憶具有明確結構，便於直接檢查記憶中的授權謂詞；增量更新則更貼近真實長時間運作智慧體的運作模式，但也更容易在多次壓縮中遺失或扭曲授權資訊。實驗橫跨採購、網路安全與金融三個高風險領域，以確保結果具有跨域代表性。

**Q7：實驗的主要量化結果是什麼？**

A：在增量式記憶更新下，記憶寫入模型最高會為 50.2% 的未經授權請求創造虛假權限；一旦虛假權限出現在記憶中，執行器在 98.6% 的對應試驗中會據此採取未經授權的動作。這顯示問題的關鍵在於記憶形成階段，而執行器幾乎不會質疑記憶內容。當研究者以精確狀態修復把記憶換成真實狀態後，這些未經授權行動隨之消失，進一步定位失效根源在記憶本身。

**Q8：作者測試了哪些緩解措施，效果如何？**

A：他們評估兩種安全機制：一是要求記憶中的權限必須有有效的來源事件作為依據，二是透過有界事件溯源追蹤權限變更。兩者都能顯著降低內生性授權洗白的發生率，但同時也會提高對合法行動的拒絕率。這揭示了明確的安全性–實用性權衡：過度嚴格的驗證雖然減少虛假授權，卻可能讓智慧體變得過於保守而無法完成正當任務。

**Q9：不同記憶設計與更新策略對結果有何影響？**

A：實驗發現增量式記憶更新特別容易產生虛假權限，因為每次更新都可能在壓縮或摘要過程中遺漏撤銷或限制條件。相較之下，一次性重寫雖然資訊較完整，卻不適用於長時間運作的智慧體。型別化記憶雖然便於稽核，但若寫入模型在轉換過程中誤判事件屬性，同樣會把未授權請求包裝成合法行動。

**Q10：這項研究在實際應用中有哪些具體風險場景？**

A：論文舉例，2026 年一款電子郵件智慧體因上下文壓縮遺失了「行動前確認」的限制，結果把僅需審閱的兩百多封信件直接刪除。在採購、網路安全與金融領域，錯誤記憶可能讓智慧體未經批准就下單採購、變更系統設定或執行交易。這些場景的共同點是：工具權限一旦錯誤保留，就會直接轉化為真實世界中的高風險動作。

**Q11：對於產品開發與部署，這篇論文帶來哪些重要啟示？**

A：開發者應把持久記憶視為授權政策的一環，而非單純的效能優化元件，並為記憶內容建立來源追溯與生命週期管理機制。在設計安全機制時，必須正視安全性–實用性權衡，避免為了降低風險而過度犧牲合法任務完成率。此外，產品應提供稽核介面，讓管理者能檢視記憶中的權限變更紀錄，並在發現異常時進行精確狀態修復或人工覆寫。

**Q12：這項研究對整個 LLM 智慧體領域可能產生什麼影響？**

A：它改變了人們評估智慧體記憶的方式，從單純的召回或任務表現轉向對授權狀態忠實度的系統性檢驗。這也補充了 GATEMEM 等只在檢索時強制存取邊界的研究，指出若記憶背後的狀態本身錯誤，檢索閘門也無法防止違規。長遠來看，這將推動結合事件溯源、來源驗證與記憶稽核的新一代授權架構發展。

**Q13：這項研究有哪些已知的限制？**

A：EAL-Bench 使用隱藏的決定性標準帳本與領域特定授權謂詞，雖然能精確評估，但真實世界的授權規則可能更為模糊且動態。評測目前聚焦於採購、網路安全與金融，尚未涵蓋所有高風險應用場景。此外，執行器經過校準，實際部署中的模型行為可能因提示、工具介面或組織流程不同而有所差異。

**Q14：還有哪些失效情境未被本文深入探討？**

A：本文主要關注內生性錯誤，對於外部攻擊如記憶污染或提示注入攻擊則未納入核心分析。多智慧體之間的授權漂移，例如 MASDRIFT 所研究的委派弱化問題，也屬於互補但不同的失效模式。另外，跨存取邊界的記憶檢索錯誤雖然與授權安全相關，卻更偏向資訊流控制，而非記憶狀態本身的忠實度。

**Q15：未來研究可以朝哪些方向延伸？**

A：未來可以發展結合自動來源驗證與有界事件溯源的記憶架構，並在每次更新時主動比對權限變更是否與原始事件一致。也可以探索人機協同的稽核機制，讓管理者在關鍵授權變更時介入確認。最後，將 EAL-Bench 擴展到更多領域、更長的互動歷程，以及真實部署環境中的線上評估，將有助於進一步驗證緩解措施的實用性與穩健性。

## 實務應用指南

### 適用場景

1. **企業採購助理智慧體**  
   長時間運作的採購智慧體會在多次對話中累積核准紀錄、預算限制與品類黑名單。當上下文壓縮或增量式記憶更新遺漏了「撤銷某供應商權限」的事件，智慧體可能把未經授權的採購單當成有效請求。EAL-Bench 的評測邏輯可直接用來檢驗記憶是否仍正確保存「誰能在什麼條件下買什麼」。

2. **網路安全事件回應（SOC）智慧體**  
   資安智慧體常被賦予暫時性的調查權限，例如「僅限讀取日誌」或「僅限隔離特定 IP」。若持久記憶把「限時權限」寫成「常駐權限」，或把「撤銷防火牆規則變更權」遺漏，智慧體可能在後續事件中主動修改防火牆，造成未經授權的動作。此場景適合用型別化記憶與有界事件溯源來追蹤權限生命週期。

3. **金融交易與財富管理助理**  
   交易智慧體需要記住客戶的風險等級、可投資標的、單日交易上限與口頭撤銷指令。當記憶寫入模型把「客戶曾拒絕某檔基金」壓縮遺失，或把「試算請求」誤記為「執行交易授權」，就會產生未經授權的交易。此處可套用 EAL-Bench 的成對授權–未授權請求設計，定期稽核記憶是否仍與真實狀態一致。

4. **電子郵件與行事曆管理智慧體**  
   使用者可能下達「先確認再刪除」或「只整理未讀郵件」等限制，這些限制會在多次互動後被寫入持久記憶。若上下文壓縮把限制條款摘要掉，智慧體可能擅自刪除或轉寄郵件。此場景強調自由文字記憶的風險，適合導入「來源事件必須有效」的 safeguard。

5. **多步驟醫療或法律合規助理**  
   在需要嚴格遵循授權鏈的領域，智慧體必須記住「誰核准了什麼文件」「哪份同意書已過期」「哪項限制於何時被撤銷」。記憶一旦洗白權限來源，可能導致未經授權的資料存取或決策建議。此處可借鏡 EAL-Bench 的精確狀態修復機制，在發現異常時以標準帳本覆寫記憶並重新執行。

### 實作前置條件

**資料準備**
- 必須有一份結構化的**組織歷史**資料，包含權限授予、限制、撤銷與替換事件，並標註時間順序。
- 需要建立隱藏的**標準帳本（Canonical Ledger）**，以決定性方式推導每一時刻的真實授權狀態，作為評測與修復的依據。
- 建議準備成對的**授權請求與未授權請求**，用於區分記憶錯誤與執行器錯誤。

**運算資源**
- 記憶寫入模型與執行模型可選用現成的大型語言模型 API，實作上不需要從頭訓練。
- 評測需要多次呼叫寫入器與執行器，建議預留足夠的 API 配額與快取空間；若採用增量式記憶更新，實驗次數會顯著增加。
- 型別化記憶需要額外的結構驗證與解析流程，可能需部署輕量規則引擎或型別檢查器。

**技能與團隊配置**
- 至少一名熟悉 LLM 提示工程與智慧體架構的 AI 工程師。
- 一名了解領域授權規則的領域專家，負責定義標準帳本的決定性規則與授權謂詞。
- 一名具備資安或合規背景的成員，負責設計 safeguards 與審查安全性–實用性權衡。
- 建議具備事件溯源、資料結構設計與評測指標設計的基礎知識。

### 實作步驟建議

1. **定義授權狀態與標準帳本**  
   先與領域專家合作，把業務規則轉換為決定性的授權狀態函數 `R` 與授權謂詞 `A`。這是整個系統的「真相來源」，必須能夠對任何歷史片段輸出「某動作是否被授權」。

2. **建立歷史資料集與測試案例**  
   收集或合成涵蓋權限授予、限制、撤銷、替換與過期的組織歷史。為每段歷史設計成對的授權與未授權請求，並標註預期結果。

3. **選擇並校準記憶寫入模型與執行模型**  
   挑選適合的 LLM 作為記憶寫入模型與執行模型。對執行器進行校準，確保當記憶正確時，它會依照記憶內容採取正確行動。

4. **實作記憶格式**  
   決定採用自由文字記憶或型別化記憶。型別化記憶雖然開發成本較高，但便於自動檢查 `A_M(M_T, x)`；自由文字記憶則更靈活，但需要額外的解析與驗證。

5. **建立 EAL-Bench 評測管線**  
   依序執行：寫入模型讀取歷史 → 產生持久記憶 → 執行模型根據記憶與請求選擇動作 → 與標準帳本比對。分別計算虛假權限形成率 `P(F=1)` 與下游傳播率 `P(G=1|F=1)`。

6. **執行精確狀態修復對照實驗**  
   把錯誤記憶替換為標準帳本的真實狀態，觀察未經授權動作是否消失。若消失，即可確認問題根源在記憶而非執行器。

7. **導入並調校 Safeguards**  
   根據評測結果，選擇導入「來源事件必須有效」或「有界事件溯源」等機制。注意這些機制可能降低合法行動的接受率，需與業務方共同決定可接受的門檻。

8. **持續監控與定期稽核**  
   部署後持續抽樣檢查記憶內容與標準帳本的偏差，並在權限變更事件發生後自動觸發記憶一致性檢查。

### 潛在風險與注意事項

- **虛假權限難以在執行時被察覺**  
  一旦記憶寫入模型產生虛假權限，執行模型在 98.6% 的情況下會照單全收。因此不能僅依賴執行階段的拒絕機制，必須在記憶寫入階段就進行把關。

- **增量式更新比一次性更新更容易累積錯誤**  
  每次增量更新都可能遺漏或扭曲先前的授權狀態。建議在關鍵權限變更後進行完整重算或差異比對，而非單純追加摘要。

- **過度嚴格的 safeguard 會傷害實用性**  
  要求每項權限都有有效來源事件，或強制追蹤完整事件鏈，可能導致合法但來源紀錄不完整的要求被拒絕。需在安全性與業務流暢度之間取得平衡。

- **自由文字記憶的解析歧義**  
  自由文字記憶容易產生「看起來有授權、實際上沒有」的模糊表述。若業務場景對授權準確度要求高，建議優先採用型別化記憶。

- **標準帳本本身必須被保護**  
  標準帳本是評測與修復的依據，若其規則或資料被竄改，整個評測與 safeguard 都會失效。應對其存取與變更進行嚴格控管。

- **不要將 EAL-Bench 結果直接等同實際風險**  
  評測中的未授權動作是相對於標準帳本定義的；實際部署時，業務規則可能更複雜或存在灰色地帶，需由領域專家參與詮釋。

---

### 與其他技術的整合建議

- **與現有身份與存取管理（IAM）系統整合**  
  標準帳本可對接企業 IAM 或 RBAC/ABAC 系統，讓授權狀態的「真相來源」與現有權限基礎設施保持一致，避免智慧體記憶與企業政策脫節。

- **與事件溯源（Event Sourcing）或審計日誌系統整合**  
  有界事件溯源的 safeguard 可直接建立在現有審計日誌之上，讓每次權限變更都有可追溯的來源事件，並限制回溯範圍以降低記憶負擔。

- **與檢索增強生成（RAG）結合**  
  可將歷史事件與授權文件作為 RAG 知識庫，讓記憶寫入模型在產生摘要時能檢索原始來源，減少憑空生成虛假權限的機會。

- **與智慧體監控與可解釋性平台整合**  
  將 `P(F=1)` 與 `P(G=1|F=1)` 等指標接入監控儀表板，並在發生虛假權限時觸發告警，同時記錄記憶版本與對應的歷史區段以便事後稽核。

- **與人機協作（Human-in-the-Loop）流程整合**  
  對於高風險動作，可在執行器決策前加入人工確認；同時把這些確認結果寫回標準帳本，作為後續記憶更新與評測的依據。

### 給不同背景讀者的閱讀建議

**給初學者**  
這篇論文在講一個直覺但危險的問題：智慧體為了記住很多事情，會把長長的對話歷史壓縮成筆記，但這個筆記可能會「記錯」誰被允許做什麼。你可以把重點放在引言的電子郵件智慧體例子，以及「虛假權限形成」與「下游傳播」這兩個概念；技術細節如 `R`、`A`、`A_M` 等符號可以先略過，重點理解為什麼「記憶不只是效能問題，而是安全問題」。

**給 AI 工程師**  
請聚焦於第三節的問題形式化與第四節的實驗設計。你會需要理解如何將 `F(M_T, a_q)` 與 `G(E, M_T, q)` 拆開評估，並在實作中建立標準帳本、成對測試案例與精確狀態修復對照組。建議直接參考 EAL-Bench 的開源實作，把評測管線整合進你現有的智慧體框架，並優先評估你目前使用的記憶格式（自由文字或型別化）在增量更新下的表現。

**給研究人員**  
本文的核心貢獻在於提出「內生性授權洗白」這個新的失效模式，並將其拆解為記憶形成與執行傳播兩個階段。建議深入閱讀與相關工作的比較（特別是 Table 1），思考 EAL-Bench 與 AUTHMEM-BENCH、PPMF、GATEMEM 等研究的互補性。未來研究方向可包括：設計更強大的記憶寫入架構、開發不犧牲實用性的 safeguard、以及將此框架擴展到多智慧體授權漂移場景。

**給產品經理**  
這篇論文對你的意義是：智慧體的「記憶功能」不是單純的體驗優化，而是會直接影響產品是否會做出未經授權的行為。請把重點放在「安全性–實用性權衡」與各領域（採購、網路安全、金融）的實際案例上。在規劃產品時，建議把記憶一致性稽核、來源事件驗證與人機協作確認納入需求，並與法務、合規與資安團隊討論可接受的誤拒率。
