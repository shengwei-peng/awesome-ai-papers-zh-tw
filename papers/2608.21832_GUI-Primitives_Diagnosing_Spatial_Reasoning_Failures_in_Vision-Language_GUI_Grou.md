# GUI-Primitives：診斷視覺-語言 GUI 定位中的空間推理失敗

**原文標題：** GUI-Primitives: Diagnosing Spatial Reasoning Failures in Vision-Language GUI Grounding  
**作者：** Md Abrar Jahin、Md Rizwan Parvez  
**發布日期：** 2026-08-22  
**HF 連結：** [https://huggingface.co/papers/2608.21832](https://huggingface.co/papers/2608.21832)  
**arXiv：** [https://arxiv.org/abs/2608.21832](https://arxiv.org/abs/2608.21832)  

---

## ⚡ TL;DR

現有基準無法區分模型在 GUI 空間關係理解上的失敗原因。
提出 GUI-Primitives，以對比式指令對診斷七種空間關係定位能力。
十九個模型最高僅 32% 準確率，多數失敗源於候選元素定位而非關係理解。

---

## 摘要翻譯

電腦使用代理（Computer-Use Agents）將自然語言指令（Natural-Language Instructions）對應至螢幕截圖（Screenshots），以定位介面元素（Interface Elements），但現有基準無法隔離模型是否將關係語言（Relational Language）綁定到正確元素。我們提出 GUI-Primitives，一個包含 994 個項目的對比式指令對（Contrastive Instruction Pairs）基準，涵蓋圖形使用者介面（Graphical User Interface, GUI）中的七種空間關係（Spatial Relations）（左／右（Left/Right）、上／下（Above/Below）、包含關係（Containment）、對齊（Alignment）、鄰近（Proximity）、清單序數（List Ordinal）、遮擋（Occlusion））。每一對固定螢幕截圖與錨點（Anchor），僅改變空間關係描述（Relation Expression），使正確目標（Target）在兩個指定候選（Designated Candidates）之間切換。五位評估者驗證了 196 個項目的子集（語句良構性（Well-Formedness）κ = 0.94；目標選擇（Target Selection）κ = 0.79）。十九個視覺-語言模型（Vision-Language Models, VLMs）在嚴格點在框內準確率（Strict Point-in-Box Accuracy）上最高僅達 32%。由於模型輸出無約束座標（Unconstrained Coordinates），我們根據每個預測落入的候選區域（Candidate Region）進行分類。在 60–92% 的項目中，預測落在兩個候選之外。在預測座標已落入候選區域的前提下，水平位置（Horizontal Position）、垂直位置（Vertical Position）、鄰近與清單序數的目標選擇達到 0.82–0.90，但包含關係與遮擋則與 0.50 無顯著差異：大多數失敗反映的是候選定位（Candidate Localization）問題，而非關係理解（Relation Understanding）。在十個模型中，基準準確率（Benchmark Accuracy）與 ScreenSpot-Pro 準確率呈正相關（斯皮爾曼等級相關係數（Spearman ρ）= +0.74），這在此樣本數（Sample Size）下僅為探索性關聯。標示出兩個指定候選可將選擇準確率（Selection Accuracy）提升 35–57 個百分點，這是一種提供候選集合的神諭式診斷（Oracle Diagnostic），而非可部署方法（Deployable Method）。我們公開釋出該基準、預測結果與程式碼。

### 核心貢獻（3～5點）
- 提出 GUI-Primitives 基準，透過對比式指令對（Contrastive Instruction Pairs）隔離模型在 GUI 中的空間關係理解能力。
- 涵蓋七種 GUI 空間關係，並以固定螢幕截圖與錨點的控制式設計，使正確目標僅在兩個指定候選間切換。
- 發現現有視覺-語言模型整體嚴格點在框內準確率偏低，且多數失敗源於候選定位（Candidate Localization）而非關係理解（Relation Understanding）。
- 透過神諭式診斷（Oracle Diagnostic）分析，顯示標示候選集合可大幅提升選擇準確率，凸顯定位瓶頸。
- 公開釋出基準、模型預測結果與程式碼，供後續研究複現與改進。

### 適合對象
從事電腦使用代理（Computer-Use Agents）、視覺-語言模型（VLMs）、GUI 定位（GUI Grounding）與空間推理（Spatial Reasoning）研究的學者與工程師，特別是關注模型如何將自然語言指令對應到圖形使用者介面中介面元素、並希望診斷模型空間推理弱點的研究者。

## 深度分析

#### 方法論解析

##### 對比式指令對（contrastive instruction pairs）的設計
GUI-Primitives 的核心方法論是建構一組**對比式指令對（contrastive instruction pairs）**，總計 994 題、497 對。每一對題目固定同一張**螢幕截圖（screenshot）**與同一個**錨點（anchor）**，僅改變**空間關係描述（relation expression）**，使得正確**目標（target）**在兩個預先指定的**候選（candidate）**之間切換。例如：「在 Save 的右邊」與「在 Save 的左邊」會讓模型應該點擊的目標從右側候選元素換成左側候選元素。這種設計源自語言學評估中的 minimal-pair 傳統，能夠控制截圖本身的顯著性（saliency）與模型對特定位置的偏好：若模型總是點擊最顯眼或最中央的元件，則會在其中一題正確、另一題錯誤，從而暴露其並未真正理解**關係語言（relational language）**。

##### 七種空間基元（spatial primitives）
基準涵蓋七種 GUI 常見的**空間關係（spatial relations）**：
- **水平位置（horizontal position）**：left／right
- **垂直位置（vertical position）**：above／below
- **包含關係（containment）**：inside／outside
- **對齊（alignment）**
- **鄰近（proximity）**
- **清單序數（list ordinal）**：如「第三個項目」
- **遮擋（occlusion）**

其中 253 對在改變關係詞的同時，也會變化動詞、中心名詞或錨點引述方式，但這些詞彙變化與關係詞並未混淆（Appendix J.2），因此可進一步檢驗模型是否確實依賴關係語言而非模板捷徑。

##### 評估指標
由於現代**視覺-語言模型（VLM）**輸出的是**無約束座標（unconstrained coordinates）**，作者不只用傳統的 **strict point-in-box accuracy**（預測點是否落在正確目標邊界框內），還引入**候選區域層級（candidate-level）**分析：
1. **嚴格點在框內準確率（strict point-in-box accuracy）**：預測點落在正確目標邊界框的比例。
2. **候選區域分類（candidate-region classification）**：將預測點歸類到「正確候選區域」、「錯誤候選區域」或「兩者之外」。
3. **條件式目標選擇準確率（conditional target selection accuracy）**：在預測點已落入某個候選區域的前提下，選中正確候選的比例。
4. **成對一致性（pair consistency）**：同一對比對中兩題是否呈現預期的對稱反轉行為。

##### 人類驗證與品質控制
五位標註者獨立驗證 196 題子集，**語句良構性（well-formedness）**的 Fleiss κ = 0.94，**目標選擇（target selection）**的 κ = 0.79，顯示題目品質與人類可解讀性均高。值得注意的是，此處的 96.9% 人類目標選擇率是在兩候選任務上的表現，並非與模型輸出座標對應的 grounding 分數。

##### 診斷性介入（diagnostic interventions）
為了區分「找不到候選」與「選錯候選」，作者測試三種不須重新訓練的介入：
- **Set-of-Marks（SoM）**：在截圖上標出兩個指定候選，相當於提供**候選集合（candidate set）**的**神諭式診斷（oracle diagnostic）**。
- **Chain-of-Thought（CoT）**：要求模型逐步推理。
- **Activation steering**：透過調整模型內部激活值引導空間推理。

此外還有三項捷徑控制（shortcut controls）：空白畫布（blank canvas）、打亂指令（shuffled instructions）、重度模糊（heavy blur），用以確認基準確實依賴視覺-語言 grounded 資訊而非純文字捷徑。

#### 實驗數據解讀

##### 整體準確率極低，候選定位是主要瓶頸
19 個模型在 GUI-Primitives 上的 **strict point-in-box accuracy** 最高僅 32%（Claude Opus 4.7 在人類清理過的 196 題子集上）。更關鍵的是，模型預測落在兩個候選區域之外的比率介於 **60%–92%**。這顯示當前 VLM 的主要失敗並非「理解錯關係」，而是**候選定位（candidate localization）**能力不足：模型無法將語言指令對應到截圖中任何一個合理的介面元素。

##### 條件式選擇揭示關係理解的差異
一旦將分析條件化在「預測點已落入某候選區域」，結果出現明顯的關係差異：
- **水平位置（horizontal position）**、**垂直位置（vertical position）**、**鄰近（proximity）**、**清單序數（list ordinal）**的條件式選擇準確率達 **0.82–0.90**，顯示模型在「找到候選」後，對這些關係的判斷相當可靠。
- **包含關係（containment）**與**遮擋（occlusion）**的條件式選擇準確率則未顯著高於 0.50，代表即使候選已被標出，模型仍難以區分 inside／outside 或判斷哪個元素被遮蔽。

這項發現對未來模型改進具有重要意義：提升定位能力可大幅改善 left／right、above／below、proximity、list ordinal 等任務；但 containment 與 occlusion 需要額外的關係理解機制，例如對層級結構、z-order、部分可見物件的推理。

##### 真實桌面截圖更困難
在來自 UI-Vision 的真實桌面截圖子集上，準確率更低，且 **96.2%** 的預測落在兩個候選區域之外。這強調 GUI-Primitives 不僅是合成場景的問題，在真實高解析度、複雜佈局的螢幕上，**候選定位（candidate localization）**的困難被進一步放大。

##### 神諭式標記帶來大幅提升，但非可部署方法
當作者在截圖上直接標出兩個指定候選（SoM）後，**選擇準確率（selection accuracy）**提升 **35–57 個百分點**：GPT-5 從 30% 升至 87%，OS-Atlas 從 10% 升至 52%。這證明若候選區域已知，多數模型能做出正確的關係判斷。然而，這只是**神諭式診斷（oracle diagnostic）**，因為實際部署中並無法預先知道候選集合；它提供的是能力上界，而非可用方法。

##### CoT 與 Activation Steering 效果不顯著
相較於 SoM，**Chain-of-Thought（CoT）**提示與 **activation steering** 均未帶來顯著提升。這暗示：
1. 單純要求模型「多想一步」無法彌補視覺定位缺陷；
2. 現有模型的內部表徵可能缺乏可操控的空間關係方向，或 steering 向量並未對準正確的語義子空間。

##### 與下游 GUI 定位的相關性
在 10 個同時測試 ScreenSpot-Pro 的模型中，GUI-Primitives 準確率與 ScreenSpot-Pro 準確率呈 **Spearman ρ = +0.74（p = 0.015）**。項目層級邏輯迴歸（n = 15,810 模型-題目對）也支持此關聯（pseudo-R² = 0.40）。這顯示 GUI-Primitives 不僅是孤立的能力測驗，也能預測模型在更廣泛、更專業的 GUI **定位（grounding）**基準上的表現。但作者謹慎指出，此樣本數（sample size）下仍屬探索性關聯。

##### 成對一致性低於獨立回應預期
由於載體模板變化與預測落在候選之外等因素，成對一致性低於假設兩題獨立時的期望值。這再次說明不能僅看整體準確率，必須進行**候選區域層級（candidate-level）**分析才能正確解讀失敗來源。

#### 與現有研究的比較

##### 相較於端到端基準（end-to-end benchmarks）
OSWorld 等**端到端基準（end-to-end benchmarks）**同時評估規劃、動作執行與定位，失敗時難以歸因。GUI-Primitives 則將問題拆解為單純的**基本空間推理（elementary spatial reasoning）**，讓研究者能精確定位哪一項**空間基元（spatial primitive）**出錯。這類控制式診斷（controlled diagnostic）對於改進電腦使用代理（computer-use agents）的基礎能力至關重要。

##### 相較於粗略定位基準（coarse grounding benchmarks）
ScreenSpot 與 ScreenSpot-Pro 屬於**粗略定位基準（coarse grounding benchmarks）**，只測量點擊是否落在目標邊界框內，但不區分失敗類型。GUI-Primitives 的貢獻在於進一步區分：
- **候選定位失敗**：預測點落在兩個候選之外；
- **關係理解失敗**：預測點落在錯誤候選上。

這種細粒度診斷是 ScreenSpot 系列所無法提供的。

##### 相較於其他 GUI 評估
MMBench-GUI 加入層級式多平台評估，但仍偏向綜合能力；UI-Vision 提供真實桌面截圖，但並未針對空間關係進行對比式控制。GUI-Primitives 填補了「細粒度空間關係診斷」這一缺口，並同時納入合成與真實截圖進行驗證。

##### 方法上的創新與限制
**創新之處**：
- 首次將 minimal-pair 方法系統性地應用於 GUI 空間關係診斷；
- 明確區分 candidate localization 與 relation understanding；
- 提供可解釋的候選區域層級指標；
- 透過 SoM 介入量化能力上界。

**限制**：
- 樣本數（sample size）相對有限，特別是與 ScreenSpot-Pro 的相關性分析僅基於 10 個模型；
- 神諭式標記雖能大幅提升表現，但並非**可部署方法（deployable method）**；
- 真實截圖子集比例較小，且準確率極低，可能限制對特定關係的細部分析；
- 目前僅涵蓋七種空間關係，未涉及時間、動態變化、多步驟指令或跨視窗關係；
- 題目語言可能以英文為主，對多語言 GUI 的泛化性尚待驗證。

#### 可重現性評估

##### 開放資源
作者已公開釋出：
- **原始碼（source code）**：https://github.com/Abrar2652/gui-primitives/
- **資料集（dataset）**：https://huggingface.co/datasets/kagnlp/gui-primitives/
- **專案網站（website）**：https://abrar2652.github.io/gui-primitives/
- 所有模型的**預測結果（predictions）**與分析程式碼

這些釋出大幅提升了研究的可重現性與後續比較的便利性。

##### 可重現性優點
1. **資料與程式碼齊全**：研究者可直接下載 994 題資料、對比對結構、人類驗證標註與模型預測。
2. **評估指標透明**：strict point-in-box、candidate-level classification、conditional selection accuracy、pair consistency 均有明確定義。
3. **模型覆蓋廣泛**：19 個模型橫跨開源與專有系統，便於比較不同架構與訓練策略。
4. **介入方法可複製**：SoM、CoT、activation steering 的實作細節若於附錄中完整說明，將進一步降低重現門檻。

##### 可重現性挑戰
1. **專有模型 API 變動**：GPT-5、Claude Opus 4.7 等模型的版本與 API 行為可能隨時間改變，未來重現時需記錄確切模型版本與提示模板。
2. **高解析度截圖處理**：ScreenSpot-Pro 與真實桌面截圖涉及高解析度影像，不同解析度縮放策略可能影響座標轉換與結果。
3. **Activation steering 細節**：該方法對模型內部層與方向的選擇敏感，若附錄未充分揭露，重現難度較高。
4. **人類驗證子集**：196 題核心子集的標註雖已釋出，但若後續擴充題目，仍需維持相同的標註品質與 κ 標準。

#### 未來研究方向

##### 1. 候選定位能力的根本提升
由於主要失敗來自預測落在候選區域之外，未來可發展結合**物件偵測（object detection）**、**可及性樹（accessibility tree）**與 VLM 的混合架構，先產生候選集合再進行關係推理。這與 SoM 的發現一致：提供候選後模型表現大幅提升，因此關鍵在於如何自動且穩健地產生高品質候選。

##### 2. 針對 containment 與 occlusion 的關係強化
這兩類關係即使在候選已知時仍接近隨機水準，需要專門的表徵學習或資料增強。可考慮：
- 設計強調 z-order、巢狀結構、滾動區域的預訓練任務；
- 利用合成資料大量產生 inside／outside 與遮擋變化；
- 引入圖形結構（graph structure）或場景圖（scene graph）輔助推理。

##### 3. 可部署的 Set-of-Marks 替代方案
SoM 是神諭式輔助，未來可研究如何讓模型自行生成標記，例如透過：
- 視覺提示工程（visual prompting）；
- 互動式定位：模型先提出候選，再由使用者或環境確認；
- 弱監督學習，讓模型從截圖中學會標記重要元件。

##### 4. 擴展關係類型與場景
目前僅七種**空間基元（spatial primitives）**，可擴展至：
- 相對大小、顏色、文字內容與空間的組合關係；
- 跨視窗、跨螢幕、多頁籤關係；
- 動態 GUI 中的時空關係（例如「點擊後出現的選單」）；
- 多語言與跨文化介面佈局的空間推理。

##### 5. 結合代理迴圈（agent loop）的診斷
GUI-Primitives 目前測試單輪定位。未來可將診斷延伸至**代理迴圈（agent loop）**，觀察模型在錯誤點擊後能否透過截圖回饋自我修正，並分析空間推理錯誤如何隨時間累積或傳播。

##### 6. 更細緻的錯誤歸因方法
可發展自動化的錯誤歸因框架，例如：
- 將預測點分類為「背景」、「文字區域」、「鄰近元件」、「正確候選」、「錯誤候選」；
- 利用注意力視覺化（attention visualization）檢視模型是否關注錯誤區域；
- 建立模型行為與人類眼動軌跡的比較。

##### 7. 訓練導向的基準使用
GUI-Primitives 不僅是評估工具，也可作為**課程學習（curriculum learning）**的訓練資料。未來可研究依據關係難度安排訓練順序，例如先學 left／right，再學 containment 與 occlusion，以提升資料效率。

##### 8. 解析度與視覺編碼器的影響
高解析度 GUI 截圖對小元件定位至關重要。未來可系統性研究不同視覺編碼器、解析度縮放策略與 patch 大小對**候選定位（candidate localization）**的影響，並發展適合 GUI 的專用視覺編碼器。

## 論文問答

**Q1：GUI-Primitives 想要解決的核心問題是什麼？**
A：GUI-Primitives 旨在診斷視覺-語言模型（VLM）在 GUI 定位任務中，是否能正確將空間關係語言綁定到對應的介面元素。現有的端到端或粗略定位基準無法區分模型是「找不到目標」還是「誤解了關係詞」，因此當代理程式點錯按鈕時，研究者難以判斷根本的失敗原因。透過固定截圖與錨點、僅改變關係描述，GUI-Primitives 把空間推理能力獨立出來進行精細評估。

**Q2：為什麼現有的端到端基準與粗略定位基準無法診斷空間推理失敗？**
A：端到端基準（如 OSWorld）同時評估規劃、操作與定位，無法單獨檢視空間關係理解；而 ScreenSpot、ScreenSpot-Pro 等粗略定位基準只檢查點擊座標是否落在目標邊界框內，並未細分是哪一種空間基元出錯。換句話說，這些基準只能告訴我們「點錯了」，卻無法說明是候選定位失敗還是關係語言理解失敗。GUI-Primitives 透過對比式指令對與候選區域分析，填補了這項診斷缺口。

**Q3：診斷 GUI  grounding 中的空間推理為何重要？**
A：電腦使用代理的核心能力之一，就是根據「在 Save 右邊」、「在圖層面板內」、「選單第三項」等關係描述找到正確控制項；一旦空間推理出錯，代理就會執行錯誤點擊，導致整個任務失敗。若無法區分失敗來自候選定位或關係理解，開發者就難以針對性地改進模型或設計補償機制。GUI-Primitives 提供的細粒度診斷，能幫助研究者把資源投入到真正薄弱的環節。

**Q4：GUI-Primitives 的核心方法是什麼？**
A：作者建構了 994 組對比式指令對，涵蓋左／右、上／下、包含、對齊、鄰近、清單序數與遮擋七種空間關係；每組題目都有一對孿生指令，固定截圖與錨點，只改變關係表達式，使正確目標在兩個指定候選之間切換。這種設計借鑑語言學中的最小對比對（minimal pair）傳統，能控制截圖顯著性與答案偏好等干擾因素。由於模型輸出的是無約束座標，研究者再將預測點分類到其所落入的候選區域，以進行候選層級分析。

**Q5：相較於既有基準，GUI-Primitives 的關鍵創新在哪裡？**
A：關鍵創新在於「對比式指令對」加上「指定候選區域」的雙重控制：一個總是點擊最顯眼或最中央元素的模型，會在其中一題答對、另一題答錯，因此無法靠捷徑取得高分。這讓基準能同時測量候選定位能力與關係理解能力，並把兩者分離。此外，它首次系統性地將 GUI 截圖中的七種空間基元納入同一診斷框架，填補了過去只報告整體準確率的不足。

**Q6：為了確保基準的有效性，作者做了哪些設計選擇？**
A：首先，五位標註者獨立驗證 196 題核心子集，語句良構性的 Kappa 係數達 0.94，目標選擇一致性達 0.79，顯示題目品質可靠。其次，約半數題目在動詞、中心名詞或錨點引述方式上進行詞彙變化，但這些變化與關係詞並未混淆，避免模型單純靠語言捷徑作答。最後，作者加入空白畫布、打亂指令與重度模糊等捷徑控制組，確認基準確實依賴視覺-語言 grounded 資訊，而非記憶或文字模式。

**Q7：實驗評估了哪些模型與指標？**
A：研究評估了 19 個視覺-語言模型，涵蓋開源與專有系統共五個模型家族；主要指標為嚴格點在框內準確率（strict point-in-box accuracy），並因模型輸出無約束座標而輔以候選區域分類。此外，作者在 10 個模型上同時執行 ScreenSpot-Pro，以探討 GUI-Primitives 與下游 GUI 定位表現的相關性。結果顯示，所有模型的嚴格準確率最高僅約 32%，且 60%–92% 的預測落在兩個候選區域之外。

**Q8：實驗的主要結果是什麼？**
A：最強模型 Claude Opus 4.7 在人工清理子集上的嚴格點在框內準確率也只有 31%；在包含、遮擋、對齊與鄰近四種基元上，所有受測模型都低於兩候選隨機基準的 0.50。然而，若條件化於預測已落入某候選區域，水平位置、垂直位置、鄰近與清單序數的目標選擇準確率可達 0.82–0.90，顯示這些關係大多能被理解；但包含與遮擋的選擇準確率不顯著高於 0.50，代表這兩種關係本身也難以掌握。

**Q9：消融與診斷分析進一步揭示了什麼？**
A：候選層級分析指出，絕大多數失敗並非關係理解錯誤，而是模型無法將點擊落在任何一個指定候選區域內，即「候選定位」是主要瓶頸。當作者以神諭方式標記兩個指定候選時，選擇準確率提升 35–57 個百分點，例如 GPT-5 從 30% 升至 87%，這證明了若候選集合已知，模型判別關係的能力其實不錯。另一方面，Set-of-Mark（SoM）干預能跨開源與封閉模型帶來顯著增益，但思維鏈（CoT）提示與激活引導（activation steering）則無顯著幫助。

**Q10：GUI-Primitives 在實務上可以怎麼使用？**
A：產品團隊可以在部署電腦使用代理前，用 GUI-Primitives 快速檢視模型在七種空間關係上的弱點，例如發現模型經常無法定位候選區域，或特別不擅長「在…內部」與「被遮擋」的描述。根據診斷結果，開發者可以針對性地收集訓練資料、設計候選感知的定位模組，或在使用者介面中提供額外提示。這種精細診斷能避免僅憑整體準確率就誤判模型能力，從而降低上線後的錯誤點擊風險。

**Q11：對於電腦使用代理的產品設計，有哪些啟示？**
A：研究結果顯示，即使關係理解正確，若模型無法把座標落在候選區域內，整體表現仍然很差，因此產品設計應優先強化候選定位能力。在實際系統中，可以結合 UI 無障礙樹（accessibility tree）或物件偵測模組，先產生候選集合，再讓 VLM 進行關係判別，類似 Set-of-Mark 的精神。此外，當模型對包含或遮擋關係表現不佳時，產品可考慮以明確標號或重新描述來輔助使用者指令，減少歧義與失誤。

**Q12：這項研究可能對整個領域帶來什麼影響？**
A：GUI-Primitives 將評估焦點從單一準確率轉向空間基元的細粒度診斷，推動未來基準更強調「失敗原因」而非僅「是否失敗」。它提供了一個可重複使用的工具，讓研究者比較不同模型在相同控制條件下的表現，並追蹤特定技能的進步。與 ScreenSpot-Pro 的顯著正相關（Spearman ρ = +0.74）也暗示，基礎空間推理能力可能是下游 GUI 定位表現的重要預測指標，值得進一步驗證與利用。

**Q13：作者承認了哪些限制？**
A：首先，與 ScreenSpot-Pro 的相關性分析僅基於 10 個模型，樣本數較小，因此 ρ = +0.74 被視為探索性結果，尚需更多模型驗證。其次，神諭式兩候選標記雖能大幅提升準確率，但它預先提供了候選集合，並非可部署的實際方法，只能作為診斷上界。此外，真實桌面截圖子集（UI-Vision）的表現更低，且 96.2% 的預測落在兩候選之外，顯示真實場景的挑戰遠大於合成情境。

**Q14：主要的失敗案例有哪些？**
A：最常見的失敗是模型預測的座標落在兩個指定候選區域之外，比例高達 60%–92%，尤其在包含、遮擋與真實截圖中更為嚴重。即使條件化於預測已落入候選區域，包含與遮擋的選擇準確率仍接近隨機，顯示這兩種關係的語意理解本身也有問題。此外，由於載體模板變化與偏離候選的預測，孿生題目之間的一致性低於獨立回應的假設，這也說明必須透過候選層級分析才能正確解讀結果。

**Q15：未來可以朝哪些方向發展？**
A：未來研究可聚焦於改善候選定位，例如發展候選感知的 grounding 架構，或將 Set-of-Mark 與 UI 元素偵測結合為可部署的管線。針對包含與遮擋這兩個特別困難的關係，可以設計專門的訓練課程或資料增強策略，並探討其困難是否來自視覺特徵不足或語言歧義。最後，擴充基準以涵蓋更多空間關係、動態介面與更大規模的模型樣本，將有助於更穩固地驗證基礎空間推理與下游 GUI 任務之間的關聯。

## 實務應用指南

## 適用場景

1. **GUI 代理程式上線前的空間推理體檢**：在部署電腦操作代理（computer-use agents）之前，使用 GUI-Primitives 評估模型對「在 Save 右邊」、「在圖層面板內」、「選單第三項」等空間關係語言的理解程度，優先找出 containment、occlusion 等高風險關係的失敗模式。

2. **針對性模型改善與資料篩選**：當發現代理經常點錯按鈕時，利用對比式指令對區分「候選定位失敗」（點擊落在兩個候選區域之外）與「關係理解失敗」（選到錯誤候選），據此決定要加強元素偵測、微調空間關係資料，還是改進提示詞。

3. **RPA 與無障礙語音操作介面測試**：將診斷流程整合到機器人流程自動化（RPA）或語音控制 UI 的品質保證中，驗證模型是否能正確將「點選上方第二個按鈕」這類口語指令對應到實際介面元素。

4. **GUI 定位訓練資料策展**：利用七種空間基元（spatial primitives）的對比結構，自動產生或過濾訓練資料，特別是針對目前模型表現最差的 containment 與 occlusion 關係擴增樣本。

5. **第三方 VLM 選型與採購評估**：在選擇閉源或開源視覺-語言模型時，以 GUI-Primitives 作為標準化診斷工具，比較不同模型在相同截圖與錨點條件下的候選定位與關係選擇能力。

## 實作前置條件

**資料**：需要帶有邊界框（bounding box）標註的 GUI 截圖，且至少能標定出錨點（anchor）與兩個指定候選（designated candidates）。若自行建構對比式指令對，需準備七種空間關係的語句模板，並確保截圖、錨點固定而僅改變關係表達式。

**運算**：可透過 API 呼叫閉源模型（如 GPT-4o、Claude 系列），或在配備 GPU 的伺服器上執行開源 VLM（如 Qwen2-VL、OS-Atlas）。評估階段只需對 994 項樣本進行推論，運算成本相對可控；若擴充至自有資料集，則需依樣本數估算 API 費用或推論時間。

**技能**：團隊需具備 Python 程式能力、基礎電腦視覺知識（座標轉換、邊界框判斷）、VLM 提示工程經驗，以及能進行人工驗證的標註流程。若要實作 Set-of-Marks（SoM）診斷，還需熟悉元素偵測或視覺標記工具。

## 實作步驟建議

1. **建立或採用標準化資料格式**：將截圖、錨點框、兩個候選框、關係語句與正確目標整理成統一格式，優先使用論文釋出的 994 項資料進行概念驗證。

2. **設計對比式評估提示詞**：對每一對樣本，固定截圖與錨點，僅改變關係表達式（如 left ↔ right、inside ↔ outside），要求模型輸出點擊座標。

3. **執行模型推論並收集無約束座標**：讓模型輸出任意座標，不預先限制在候選區域內，以真實反映其定位行為。

4. **進行候選區域分類**：將每個預測座標歸類為「落在正確候選區域」、「落在錯誤候選區域」或「落在兩個候選區域之外」，計算 strict point-in-box 準確率與選擇準確率（selection accuracy）。

5. **區分失敗類型**：若大量預測落在兩個候選之外，代表候選定位（candidate localization）是主要瓶頸；若預測落在候選內但選錯，則代表關係理解（relation understanding）不足。

6. **導入 SoM 作為診斷性干預**：在截圖上標記兩個指定候選，觀察選擇準確率是否提升 35–57 百分點，以確認模型在獲得候選集合後能否正確判斷關係。

7. **將發現回饋到產品迭代**：針對 containment、occlusion 等關係理解薄弱的項目擴增訓練資料，或在前端系統中先以元素偵測產生候選集合，再交由 VLM 進行關係選擇。

## 潛在風險與注意事項

- **過度擬合基準**：GUI-Primitives 是控制式診斷工具，而非真實操作環境。模型在基準上表現提升，不一定代表在複雜端到端任務（如 OSWorld）中同等進步，建議搭配實際應用場景驗證。

- **合成與真實截圖的落差**：論文顯示真實桌面截圖（UI-Vision）的失敗率更高，且多數預測落在候選區域之外。在產品中應保留真實 UI 資料進行測試，不要僅依賴合成或清理過的樣本。

- **SoM 並非可部署方法**：標記指定候選雖能大幅提升準確率，但它假設已經知道正確的候選集合。在實際系統中，仍需先解決元素偵測與候選生成的問題，SoM 只能作為診斷上限參考。

- **API 成本與延遲**：對比式指令對會使每張截圖至少推論兩次，若擴大到自有資料集或高頻評估，需評估 API 費用與回應時間，並考慮在本地部署開源模型。

- **標註品質影響結論**：人工驗證的目標選擇一致性（κ = 0.79）雖屬良好，但仍需建立內部標註準則，特別是對於 alignment、proximity 等較主觀的關係，避免將標註歧義誤判為模型失敗。

## 與其他技術的整合建議

- **與元素偵測模型結合**：將 GUI-Primitives 的診斷結果與專用 UI 元素偵測器（如 OmniParser、SeeClick）串接，先由偵測器產生候選集合，再讓 VLM 執行關係選擇，可降低候選定位失敗的風險。

- **整合至 CI/CD 評估流程**：在 GUI 代理程式的持續整合管線中，定期對最新模型版本執行 GUI-Primitives 子集，監控七種空間基元的表現退化，特別是在模型更新後。

- **與端到端基準互補**：將 GUI-Primitives 與 ScreenSpot-Pro、OSWorld 等基準並行使用。GUI-Primitives 負責定位失敗的細因診斷，ScreenSpot-Pro 負責整體像素級定位能力，OSWorld 負責完整代理迴路表現。

- **作為資料增強與過濾模組**：利用對比式指令對的結構，自動生成大量「固定截圖、改變關係」的訓練樣本，並過濾掉模型已能穩定答對的項目，專注於困難樣本進行主動學習。

- **與規劃模組協作**：在電腦使用代理的規劃層中，當指令包含空間關係時，可將其拆解為「先定位錨點 → 再依關係尋找目標」的兩步驟，並以 GUI-Primitives 的失敗模式決定是否需要 SoM 輔助。

## 給不同背景讀者的閱讀建議

**初學者**：建議先從摘要與第一章了解核心問題——為什麼現有 GUI 定位基準無法區分「點錯地方」與「理解錯關係」。重點掌握「對比式指令對」、「候選定位」與「關係理解」三個概念，以及「標記候選可大幅提升表現」這項發現，無需深入統計細節。

**AI 工程師**：請聚焦於實作方法與評估指標，包括如何從無約束座標分類到候選區域、strict point-in-box 與 selection accuracy 的差異，以及 Set-of-Marks 的實作方式。建議直接參考論文釋出的程式碼與預測結果，並嘗試將診斷流程套用到自己維護的 GUI 代理系統上。

**研究人員**：建議細讀對比式指令對的建構方式、五名標註者的驗證流程，以及候選層級分析的統計處理。特別值得關注的是論文如何將「低於兩候選隨機基準的準確率」重新詮釋為候選定位失敗而非關係理解失敗，並思考這項方法論如何遷移到其他視覺-語言推理任務。

**產品經理**：請將閱讀重點放在適用場景、限制與商業風險。理解 GUI-Primitives 是診斷工具而非可直接上線的功能，SoM 雖能顯著提升準確率但需要額外的元素偵測支援。評估時應將其視為模型選型、品質保證與改善優先順序判斷的依據，而非單一的性能數字。
