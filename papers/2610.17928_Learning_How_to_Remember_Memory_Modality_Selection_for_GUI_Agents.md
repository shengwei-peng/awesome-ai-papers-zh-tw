## ⚡ TL;DR

現有記憶體增強 GUI 代理採用固定的記憶體模態，但最佳表示方式隨互動步驟而異。
作者提出 SwitchMem 路由框架，透過 D-CoE 分析隱藏狀態，動態選擇文字或視覺記憶體。
在三個 GUI 基準測試中，SwitchMem 皆優於靜態記憶體基線，證實模態選擇應為步驟相依決策。

---

## 摘要翻譯

視覺語言模型（VLMs）的近期進展大幅提升了圖形使用者介面代理的能力，而記憶體增強已成為重複利用過去互動知識的一種前景可期的方法。然而，現有的記憶體增強型 GUI 代理通常採用固定表示策略，以靜態模態形式提供檢索經驗。目前仍不清楚單一記憶體模態是否始終為最佳選擇，也不清楚模態偏好如何隨著互動步驟而變化。在本研究中，我們對基於 VLM 的 GUI 代理中的記憶體模態進行了系統性研究。在多個圖形使用者介面基準測試中，我們發現偏好的記憶體表示高度取決於步驟。基於此發現，我們提出了 SwitchMem——一個在每個步驟中動態選擇文字與視覺記憶體表示的路由框架。在三個圖形使用者介面基準測試中，SwitchMem 優於依賴靜態記憶體表示的記憶體增強基線方法。我們的發現驗證了此論點：記憶體模態是一個步驟相依決策，而非固定的設計選擇。程式碼與專案資源可於以下網址取得：https://txxnrd.github.io/switchmem

### 核心貢獻（3～5點）
- **揭示記憶體模態選擇的步驟相依性**：透過系統性研究證明，GUI 代理中偏好的記憶體表示並非固定不變，而是高度取決於當前的互動步驟，挑戰了現有方法普遍採用的固定表示策略。
- **提出 SwitchMem 路由框架**：設計一個能夠在每個互動步驟中動態選擇文字記憶體或視覺記憶體表示的路由機制，使代理能依據當前情境彈性調整記憶體模態。
- **跨基準測試的實證優越性**：在三個圖形使用者介面基準測試上，SwitchMem 均優於依賴靜態記憶體表示的記憶體增強基線方法，驗證了動態模態選擇的實用價值。
- **確立記憶體模態為設計決策而非預設選擇**：研究結果強調記憶體模態應視為步驟相依決策，為未來記憶體增強型 GUI 代理的設計提供了新的方法論指引。

### 適合對象
本研究特別適合以下讀者閱讀：從事視覺語言模型（VLMs）與圖形使用者介面代理（GUI Agents）研究的學者與工程師；關注記憶體增強技術、長時程決策與長時程推理的研究人員；以及對多模態學習、動態路由機制與 AI 代理自主互動感興趣的產學界實踐者。

## 深度分析

#### 方法論解析

本論文提出 **SwitchMem**，一個針對視覺語言模型（Vision-Language Models, VLMs）驅動之圖形使用者介面代理（GUI Agents）的動態記憶體模態選擇框架。其核心方法論可從以下幾個層面深入剖析：

**1. 問題形式化（Problem Formulation）**

作者將 GUI 互動過程形式化為序列決策問題。在步驟 $i$ 中，當前 GUI 狀態定義為 $x_i = (g_i, o_i)$，其中 $g_i$ 為任務指令（task instruction），$o_i$ 為當前螢幕截圖（screenshot）。每個記憶體候選項（memory candidate）從包含過去 GUI 狀態及其成功示範動作（demonstrated action）的示範庫中檢索。為了隔離記憶體表示（memory representation）效果與檢索品質（retrieval quality）的混淆，作者刻意採用共享的文字檢索器（shared text-based retriever），確保兩種模態使用相同的檢索來源。

**2. 雙模態記憶體實例化（Dual-Modality Memory Instantiation）**

對於檢索到的示範 $j_i$，SwitchMem 將其實例化為兩種形式：
- 文字記憶體（Textual Memory）：$m^T_i = (g_{j_i}, t_{j_i}, a_{j_i})$，其中 $t_{j_i}$ 為 GUI 狀態的結構化文字描述
- 視覺記憶體（Visual Memory）：$m^I_i = (g_{j_i}, v_{j_i}, a_{j_i})$，其中 $v_{j_i}$ 為對應的螢幕截圖

此設計的關鍵在於「控制變數」原則：保持檢索內容不變，僅改變呈現模態，從而純化模態效果的測量。

**3. 步驟級效用估計（Step-Level Utility Estimation）**

作者採用基於採樣的效用估計方法。對於模態 $z \in \{T, I\}$，其效用透過從凍結執行者（frozen actor）採樣 $K$ 個動作來估計：

$$\hat{u}^z_i = \frac{1}{K} \sum_{k=1}^{K} S_b(a^z_{i,k}, a^*_i)$$

其中 $S_b$ 為基準測試特定的動作評分函數（benchmark-specific action scorer），$a^*_i$ 為真實動作（ground-truth action）。步驟級模態偏好定義為 $\hat{\Delta}_i = \hat{u}^I_i - \hat{u}^T_i$，正值表示影像模態更佳，負值則表示文字模態更優。

**4. 方向性嵌入鏈分析（Directional Chain-of-Embedding, D-CoE）**

這是本論文最具方法論創新性的部分。D-CoE 分析揭示了模態偏好訊號存在於模型的內部隱藏狀態（internal hidden states）中。具體而言，作者透過分析 Transformer 各層的隱藏表示，發現模態偏好是可預測且可泛化的訊號。圖 4 顯示層級 AUROC 曲線，證實在特定 Transformer 層中，模態偏好分類達到高 AUROC 值（接近 0.8），這意味著模型內部已隱含地「知道」哪種模態更適合當前步驟。

**5. 路由框架設計（Routing Framework Design）**

SwitchMem 的路由機制（routing mechanism）基於 D-CoE 發現的表示層訊號，在每個互動步驟動態選擇文字或影像記憶體。這與現有方法形成鮮明對比：現有方法一旦選定表示策略便固定不變，而 SwitchMem 將記憶體模態視為步驟級決策（step-level decision）。

**6. 執行者架構（Actor Architecture）**

主要實驗使用 Qwen3.5-9B 作為執行者（actor），這是一個中等規模的 VLM，平衡了效能與計算成本。值得注意的是，作者使用凍結（frozen）執行者進行效用估計，避免了在評估過程中引入策略偏差。

#### 實驗數據解讀

**1. 模態偏好分佈（Modality Preference Distribution）**

圖 2 揭示了核心實驗發現：在 AITW 基準測試中，非平手步驟（non-tied steps）中文字模態佔 48.0%，影像模態佔 52.0%；在 LearnGUI 中，文字佔 47.7%，影像佔 52.3%。雖然影像模態略佔優勢，但比例接近 50:50，**明確否定了單一模態一致最優的假設**。這個數據是整篇論文的基石——它證實了「步驟相依決策」（step-dependent decision）的必要性。

**2. 固定模態 vs. 步驟預言機（Fixed Modality vs. Step Oracle）**

圖 3 顯示了關鍵的效能差距：
- AITW：最佳固定模態達 49.3%，步驟預言機（step oracle）達 55.9%
- LearnGUI：最佳固定模態僅 37.4%，步驟預言機達 43.4%

這個 **6.6 個百分點（AITW）和 6.0 個百分點（LearnGUI）的差距** 代表了動態選擇的理論上限。它證明了：(a) 固定模態策略存在顯著效能損失；(b) 若能完美預測每步的最佳模態，可大幅超越靜態方法。

**3. SwitchMem 效能（SwitchMem Performance）**

SwitchMem 在三個 GUI 基準測試中均優於依賴靜態記憶體表示的記憶體增強基線方法（memory-augmented baselines）。雖然具體數字未在提供的文本中完整列出，但「consistently outperforms」的表述暗示了跨基準測試的穩定改進。

**4. D-CoE 層級分析（D-CoE Layer-wise Analysis）**

圖 4 顯示 AUROC 隨 Transformer 層深度變化的曲線。值得注意的是，模態偏好的可預測性在特定中間層達到峰值，這與 VLM 文獻中觀察到的「概念湧現」（concept emergence）現象一致——中間層往往編碼最豐富的語意資訊。

**5. 結果的深層意涵（Implications of Results）**

實驗數據共同支持三個關鍵論點：
- **模態偏好是步驟相依的**：圖 2 的接近 50:50 分佈排除了一致最優假設
- **動態選擇具有實質價值**：圖 3 的效能差距證明了非平凡的改進空間
- **偏好訊號可從內部表示中提取**：圖 4 的高 AUROC 證實了 D-CoE 的可行性

#### 與現有研究的比較

**1. 定位差異（Positioning Differences）**

現有 GUI 記憶體增強方法可分為三類：
- **情境示範方法**（Agashe et al., 2025; Xu et al., 2025a）：將檢索經驗作為情境內範例（in-context examples），通常以文字形式呈現
- **軌跡轉換方法**（Li et al., 2026b; Qin et al., 2026）：將互動軌跡轉換為可重用的文字追蹤、結構化程序或可執行知識
- **視覺記憶體方法**（Rawles et al., 2025; Choi et al., 2026）：保留螢幕截圖或動作相關區域以紮根於過去介面狀態

SwitchMem 的根本差異在於：**它不創造新的記憶體類型，而是質疑現有方法中固定模態選擇的合理性**。這是一個「橫切」式的貢獻，可與上述任何方法正交結合。

**2. 理論基礎的對比（Theoretical Foundation Comparison）**

本論文借鑒了 VLM 文獻中關於模態互補性的研究（Pezeshkpour et al., 2025; Yang et al., 2026; Long et al., 2026; Roh et al., 2026b），這些研究指出：
- 文字提供緊湊的語意抽象（semantic abstraction），但可能丟失細粒度資訊（fine-grained information）
- 視覺保留空間（spatial）和外觀（appearance）資訊，但可能缺乏結構化抽象

SwitchMem 將這些一般性觀察具體化到 GUI 代理的步驟級決策中，並提供了實證驗證。

**3. 改進幅度（Improvement Magnitude）**

相較於靜態記憶體基線，SwitchMem 的改進來自兩個來源：
- **避免錯誤模態**：在文字更優的步驟避免使用影像，反之亦然
- **充分利用互補性**：在某些步驟，特定模態可能提供獨特資訊

**4. 局限性（Limitations）**

- **檢索器依賴性**：實驗使用共享文字檢索器，這可能低估了視覺檢索的潛力。若使用模態特定檢索器，結果可能不同
- **計算開銷**：每步進行動態選擇增加了推理延遲，雖然路由器本身輕量，但整體流程更複雜
- **基準測試範圍**：三個 GUI 基準測試的覆蓋面有限，特別是桌面環境（desktop environments）的代表性不足
- **路由器訓練資料**：D-CoE 訊號的泛化能力依賴於訓練資料的多樣性，對未見過的應用類型可能表現下降

#### 未來研究方向

**1. 多模態記憶體融合（Multimodal Memory Fusion）**

當前的 SwitchMem 僅在文字與影像間二選一。未來可探索：
- **軟路由（soft routing）**：以機率分佈形式結合兩種模態，而非硬選擇
- **注意力融合**：學習兩種模態的加權組合，權重隨步驟動態調整
- **跨模態增強**：在某些步驟同時使用兩種模態，觀察是否產生互補增益

**2. 路由器架構演進（Router Architecture Evolution）**

D-CoE 分析揭示了表示層訊號，未來可探索：
- **更輕量的路由器**：設計專門的輕量分類器，而非依賴完整 Transformer 層分析
- **預測信心度**：路由器不僅輸出模態選擇，還輸出信心度，用於不確定時的保守策略
- **線上學習**：讓路由器在互動過程中持續適應使用者偏好

**3. 檢索器與模態選擇的聯合優化（Joint Optimization of Retriever and Modality Selection）**

當前方法將檢索與模態選擇解耦。未來可：
- 設計模態感知檢索器（modality-aware retriever），根據當前需求選擇最佳檢索策略
- 探索端到端訓練，使檢索器與路由器協同優化

**4. 跨領域泛化（Cross-Domain Generalization）**

將方法從 GUI 代理擴展至：
- **網頁代理（web agents）**：處理更複雜的視覺佈局
- **機器人操作（robotic manipulation）**：將記憶體模態選擇應用於物理動作規劃
- **多步驟視覺問答（multi-step VQA）**：在需要多輪視覺推理的任務中驗證動態模態選擇的價值

**5. 理論分析深化（Theoretical Analysis Deepening）**

- **形式化模態偏好理論**：建立數學框架解釋為何某些步驟偏好文字、某些偏好影像
- **資訊理論視角**：從互資訊（mutual information）角度量化每種模態對最終決策的貢獻
- **因果分析**：透過因果推斷（causal inference）區分模態選擇的相關性與因果效應

**6. 人機協作整合（Human-AI Collaboration Integration）**

- **可解釋模態選擇**：讓路由器解釋為何選擇特定模態，增強使用者信任
- **使用者偏好整合**：允許使用者根據個人偏好覆寫自動選擇
- **錯誤恢復機制**：當路由器選擇錯誤時，提供回退策略

**7. 效率優化（Efficiency Optimization）**

- **預測性預載（predictive prefetching）**：根據路由器預測提前載入可能需要的模態
- **快取策略**：設計模態特定的快取機制，減少重複計算
- **蒸餾小型路由器**：將大型路由器的知識蒸餾到輕量模型，降低部署成本

**8. 評估基準擴展（Benchmark Expansion）**

- **更多 GUI 環境**：涵蓋桌面、網頁、嵌入式系統等
- **更長時程任務**：測試在數十步甚至上百步任務中的穩定性
- **對抗性測試**：設計刻意誘導錯誤模態選擇的測試案例，評估魯棒性

這些方向不僅能延伸 SwitchMem 的技術貢獻，還能深化我們對「代理何時應記住什麼、以何種形式記住」這一根本問題的理解。

## 論文問答

**Q1：為什麼 GUI 代理需要記憶體增強機制？**
A：GUI 互動任務通常涉及長時程決策，代理需要在多個步驟中持續推理並執行操作，而單一步驟的錯誤可能會傳播到後續決策中。透過從過去的互動軌跡、示範或視覺觀察中提取可重用的知識，記憶體增強能幫助代理避免重複犯錯並做出更明智的決策。此外，GUI 環境中的任務往往具有相似性，從成功經驗中學習可以顯著提升代理在新任務上的泛化能力與執行效率。

**Q2：現有的記憶體增強 GUI 代理方法存在哪些根本性的限制？**
A：現有方法普遍採用預定義的記憶體表示策略，無論是純文字、純視覺還是兩者的固定組合，一旦選定便在所有互動步驟中保持不變。這種固定表示策略忽略了不同步驟對於資訊需求的差異性，可能在某些步驟提供冗餘資訊而在其他步驟缺乏關鍵細節。更根本的問題在於，這些方法從未質疑「單一表示模態是否適用於所有互動步驟」這個基本假設，導致次優的整體表現。

**Q3：為什麼記憶體模態的選擇對 GUI 代理至關重要？**
A：文字表示能提供緊湊的語意抽象，便於結構化推理，但將影像轉換為語言時可能遺失細粒度的空間與外觀資訊。視覺表示則保留了細緻的空間佈局與視覺特徵，但當所需資訊可被結構化文字捕捉時，視覺形式反而可能成為負擔。由於 GUI 任務的不同步驟需要不同類型的資訊——例如某些步驟需要精確的座標定位，而其他步驟則需要語意層面的操作理解——單一模態無法在所有情境下都達到最佳表現。

**Q4：SwitchMem 的核心方法論是什麼？**
A：SwitchMem 是一個輕量級的路由框架，能在每個互動步驟動態地於文字記憶體與視覺記憶體之間進行選擇。其核心洞見在於，記憶體模態偏好並非固定的設計選擇，而是隨著互動狀態變化的步驟相依決策。透過在每一步根據當前 GUI 狀態選擇最合適的記憶體表示形式，SwitchMem 能夠充分利用兩種模態的互補優勢。

**Q5：什麼是 Directional Chain-of-Embedding (D-CoE) 分析，它如何揭示模態偏好？**
A：D-CoE 分析是一種表示層級的探測技術，通過檢查 VLM 內部的隱藏狀態來識別模態偏好信號。具體而言，該分析發現 Transformer 不同層的隱藏狀態中編碼了可重現的「文字/影像偏好」信號，這些信號能夠泛化到未見過的 GUI 軌跡。這項發現的關鍵意義在於，模態偏好並非黑箱現象，而是可以從模型的內部表示中被可靠地提取出來，為路由決策提供了理論基礎。

**Q6：SwitchMem 在設計上有哪些重要的取捨與考量？**
A：SwitchMem 選擇將記憶體模態視為步驟層級的決策，而非任務層級或軌跡層級的決策，這使得框架能夠對每個互動狀態做出細粒度的回應。路由器本身設計為輕量級，避免對主要 VLM 造成過大的計算負擔。此外，框架刻意保持模態選擇空間的簡潔性（僅文字與影像兩種），這既降低了路由的複雜度，也便於在實際部署中進行分析與除錯。

**Q7：實驗評估使用了哪些 GUI 基準測試？**
A：研究在三個 GUI 基準測試上進行了系統性評估，其中包括 AITW（Android in the Wild）這項知名的行動裝置 GUI 基準測試，以及 LearnGUI 等涵蓋不同任務類型的測試集。這些基準測試涵蓋了桌面與行動環境下的多樣化互動場景，能夠全面檢驗 SwitchMem 在不同 GUI 領域的泛化能力。實驗中使用 Qwen3.5-9B 作為執行者模型，以確保結果的可比較性。

**Q8：SwitchMem 的主要實驗結果顯示了什麼樣的效能提升？**
A：SwitchMem 在所有評估基準測試上均一致地超越了依賴靜態記憶體表示的基線方法，驗證了動態模態選擇的價值。更具啟發性的結果是，步驟級的「oracle」模態選擇（即在每一步選擇最佳模態）與最佳固定模態之間存在顯著的效能落差，這證明了模態偏好的步驟相依性確實存在且具有實質影響。此外，在非平手步驟中，文字與影像模態的勝率分佈相當接近（AITW 約 48% vs 52%，LearnGUI 約 47.7% vs 52.3%），進一步說明了沒有單一模態能持續主導。

**Q9：論文中進行了哪些消融研究與分析來驗證方法？**
A：論文中包含了逐層的 AUROC 分析（圖 4），展示了不同 Transformer 層中模態偏好信號的可預測性，證明了 D-CoE 分析在不同深度都能有效捕捉偏好資訊。此外，圖 3 明確展示了固定模態與步驟級 oracle 模態之間的效能差距，定量說明了動態選擇的必要性。這些分析共同構成了從「現象觀察」到「表示層級驗證」再到「方法有效性」的完整證據鏈。

**Q10：SwitchMem 在實際應用中可能適用於哪些場景？**
A：在行動裝置自動化領域，SwitchMem 可用於處理跨應用程式的工作流程，例如從電子郵件中擷取資訊並填入行事曆等需要多步驟協調的任務。在桌面環境中，它能支援複雜的軟體操作，如文件編輯、資料整理或系統設定調整。此外，對於需要從過去成功經驗中學習的個人化助理，SwitchMem 的動態記憶體選擇機制能讓代理更靈活地適應不同類型的操作需求。

**Q11：將 SwitchMem 整合到實際產品中需要考量哪些工程因素？**
A：部署時需要考量路由器的計算延遲，雖然路由器本身設計為輕量級，但仍會在每個步驟增加額外的推理時間，因此需要評估對整體互動流暢度的影響。記憶體儲存方面，由於需要同時保留文字與視覺兩種形式的記憶體，儲存成本會比單一模態系統更高。此外，路由器的訓練資料與泛化能力也是關鍵考量，產品化時需要確保其在目標使用者的常見任務上表現穩定。

**Q12：這項研究對 GUI 代理領域的整體影響是什麼？**
A：本研究挑戰了記憶體增強系統中「固定模態」的普遍假設，證明了模態選擇應該是動態的、步驟相依的決策，這將促使未來的研究重新審視記憶體系統的設計原則。D-CoE 分析揭示了 VLM 內部表示中蘊含的模態偏好信號，為可解釋性研究開啟了新方向。更廣泛地說，這項工作強調了「設計選擇應隨情境變化」的觀點，可能影響記憶體增強以外的其他 GUI 代理設計面向。

**Q13：這篇論文存在哪些已承認的限制？**
A：論文的模態選擇空間僅限於文字與影像兩種，未涵蓋其他可能的表示形式，如音訊、結構化資料或混合的多模態組合。實驗主要使用 Qwen3.5-9B 作為執行者，雖然這提供了可比較的結果，但對於其他 VLM 架構的泛化性仍需進一步驗證。此外，路由器的訓練與評估集中在特定的 GUI 基準測試上，對於真實世界中更為多樣化或非標準的介面，其有效性尚未充分探討。

**Q14：SwitchMem 在哪些情況下可能會失敗或表現不佳？**
A：當模態偏好信號在模型的隱藏狀態中表現微弱時（例如某些罕見或異常的 UI 設計），路由器可能難以做出可靠的選擇。在文字與影像模態表現相當接近的「平手」步驟中，路由決策的隨機性可能引入不必要的變異性。此外，對於需要同時利用兩種模態資訊的複雜步驟，僅選擇單一模態可能無法提供完整的推理依據，這是當前二元選擇框架的固有局限。

**Q15：基於這項研究，未來有哪些值得探索的方向？**
A：未來可以將模態選擇空間擴展到更多類型，例如結合結構化表格、程式碼片段或使用者偏好資料，形成更豐富的多模態記憶體系統。改進路由機制本身也是重要方向，例如探索基於強化學習或元學習的自適應路由器，使其能從互動經驗中持續優化選擇策略。此外，將 SwitchMem 的動態選擇理念推廣到 GUI 代理以外的其他領域（如機器人控制、網頁自動化）也是值得探索的延伸方向。

## 實務應用指南

### 適用場景

**1. 行動應用程式自動化測試**
在 CI/CD 流程中部署 SwitchMem 驅動的 GUI 代理，自動執行跨裝置、跨版本的回歸測試。當測試代理需要導航深層選單時偏好文字記憶體（結構化 UI 資訊更精簡），而需要比對視覺元素位置或圖示外觀時則切換至視覺記憶體，可顯著降低測試腳本的維護成本。

**2. 企業內部系統（SaaS、ERP、CRM）流程自動化**
針對 Salesforce、SAP、Workday 等複雜企業系統建構助理代理。員工示範一次操作流程後，系統可將該流程的記憶體儲存為混合模態，後續執行時由 SwitchMem 自動決定每個步驟該用文字描述還是螢幕截圖參考，特別適合需要重複執行但介面會更新的長時程任務。

**3. 無障礙輔助工具**
為視障或行動不便使用者打造的螢幕閱讀與操作輔助代理。當使用者需要填寫表單時，文字記憶體提供欄位語意資訊；當需要辨識圖像按鈕或圖示時，視覺記憶體保留外觀細節。動態切換可讓輔助系統在不同互動階段提供最合適的引導。

**4. 客服與技術支援自動化**
在客服系統中部署能學習過往成功處理案例的代理。對於需要查詢訂單狀態、修改帳號設定等任務，文字記憶體提供結構化流程指引；對於需要引導使用者操作特定介面（如截圖教學、視覺確認）的場景，視覺記憶體則更為有效。

**5. 跨平台 UI 一致性檢查與遷移**
在桌面與行動環境間進行 UI 測試或介面遷移時，代理需要判斷「同一個功能在不同平台上的視覺呈現是否一致」。SwitchMem 可在需要比對視覺外觀的步驟自動採用視覺記憶體，在需要理解功能語意的步驟採用文字記憶體。

### 實作前置條件

**資料需求**
- **示範軌跡庫**：需蒐集大量成功完成任務的 GUI 互動軌跡，每個步驟應包含任務指令、螢幕截圖、結構化 UI 資訊（XML/JSON 樹狀結構）以及執行的動作。
- **基準測試資料**：建議準備 AITW、LearnGUI 等公開 GUI 基準測試資料集作為離線評估環境。
- **標註資料**：若要訓練自訂路由器，需準備每步的「最佳模態」標註（即在該步驟下文字 vs. 影像記憶體何者效用較高）。

**運算資源**
- **VLM 推論**：需部署 Qwen3.5-9B 等視覺語言模型作為執行者（Actor），單次推論需約 16–24 GB GPU 記憶體。
- **路由器訓練**：D-CoE 分析與路由器訓練可在單張 A100/H100 上完成。
- **記憶體檢索**：文字檢索器（如 BM25 或稠密向量檢索）需支援快速 top-k 查詢，建議搭配向量資料庫（如 FAISS、Milvus）。

**技能門檻**
- 熟悉 VLM 的 prompt engineering 與多模態輸入處理。
- 具備 Transformer 內部表示（hidden states、attention）的分析能力，以重現 D-CoE 偏好訊號。
- 了解 GUI 自動化框架（如 AndroidEnv、Mobile-Env、WebArena）的介接方式。
- 具備基本的分類器/路由器訓練經驗（logistic regression、淺層 MLP 即可）。

### 實作步驟建議

**階段一：建立記憶體庫（2–4 週）**
1. 選定目標 GUI 環境並蒐集示範軌跡，確保每步都包含螢幕截圖、結構化 UI 描述與動作標籤。
2. 為每個軌跡建立雙模態記憶條目：文字形式（任務指令 + UI 文字描述 + 動作）與視覺形式（任務指令 + 截圖 + 動作）。
3. 建立文字檢索器索引，將每個記憶條目的任務指令與 UI 文字描述編入索引。

**階段二：分析模態偏好訊號（2–3 週）**
1. 在基準測試上執行執行者，分別以文字與視覺記憶體產生動作。
2. 使用基準測試內建的動作評分器計算每步的效用差 Δ̂ᵢ。
3. 抽取 VLM 各 Transformer 層的隱藏狀態，執行 D-CoE 分析：對每層的隱藏向量計算「文字偏好方向」與「影像偏好方向」之間的餘弦相似度或線性可分性（AUROC）。
4. 找出 AUROC 最高的層（依圖 4 約在第 16–23 層之間），作為路由器的特徵來源。

**階段三：訓練路由器（1–2 週）**
1. 使用階段二得到的層級隱藏狀態作為輸入，特徵為「該步驟在偏好方向上的投影值」。
2. 標籤為 Δ̂ᵢ 的正負號（正表示偏好影像、負表示偏好文字）。
3. 訓練輕量分類器（logistic regression 或單層 MLP），輸出每步應採用的記憶體模態。
4. 在驗證集上評估路由器的預測準確率與下游任務的成功率提升。

**階段四：整合與部署（2–4 週）**
1. 將路由器封裝為推論服務，於每個互動步驟即時呼叫。
2. 設計 fallback 機制：當路由器信心度低時，採用文字與視覺記憶體的串接或投票機制。
3. 整合至目標 GUI 自動化框架，設定監控指標（成功率、平均步驟數、模態切換頻率）。
4. 進行 A/B 測試，比較 SwitchMem 與單一模態基線的實際表現。

**階段五：持續優化（持續進行）**
1. 蒐集線上軌跡，定期重新訓練路由器以適應介面更新。
2. 監控模態偏好分布是否隨時間漂移，必要時更新 D-CoE 方向。

### 潛在風險與注意事項

**風險一：模態偏好訊號在分布外資料上失效**
D-CoE 分析得到的偏好方向是從特定基準測試中學得的，若部署環境的 UI 風格、任務類型與訓練資料差異過大，路由器可能給出錯誤判斷。
**緩解措施**：在路由器推論時加入信心度門檻，低信心度時退回預設模態（建議預設為文字模態，因其推論成本較低）；定期用部署環境的軌跡重新校準 D-CoE 方向。

**風險二：路由器增加推論延遲**
每步都需要先取得 VLM 隱藏狀態再呼叫路由器，會增加整體回應時間。
**緩解措施**：僅在 Transformer 的單一層（例如第 20 層）抽取特徵，避免完整推論後再回傳；將路由器部署為非同步服務，與主推論並行；對高頻步驟快取路由結果。

**風險三：記憶體檢索品質影響整體表現**
論文中刻意將檢索品質固定以隔離模態效應，但實際部署時若檢索器回傳不相關的示範，無論選擇哪種模態都會失敗。
**緩解措施**：採用混合檢索（文字 + 視覺 embedding）並設置相似度門檻，過濾低品質檢索結果；建立檢索品質監控指標。

**風險四：介面更新導致視覺記憶體失效**
視覺記憶體依賴截圖的視覺相似性，若應用程式改版（按鈕位置、配色改變），舊的視覺記憶可能誤導代理。
**緩解措施**：為視覺記憶體加上時間戳記與版本標記；定期清理過期記憶體；在路由器中加入「介面變更偵測」訊號，觸發時自動偏向文字模態。

**風險五：標註成本高**
訓練路由器需要「每步最佳模態」的標註，這需要對每個步驟同時跑兩種模態並比較結果。
**緩解措施**：採用弱監督方式——以「Δ̂ᵢ 的正負號」作為自動產生的標籤，無需人工介入；只在關鍵任務類型上做精細標註。

### 與其他技術的整合建議

**與 RAG（Retrieval-Augmented Generation）系統整合**
SwitchMem 的記憶體檢索階段可與企業既有的 RAG 基礎設施共用向量資料庫與檢索管道。建議將 GUI 示範軌跡的「任務指令 + UI 文字描述」編入現有 embedding 索引，並新增「截圖 embedding」通道支援視覺檢索。路由器輸出可作為後設資料（metadata）寫入檢索結果，輔助下游 LLM 判斷該採用哪個欄位。

**與既有 GUI 代理框架整合**
SwitchMem 可作為外掛模組接入 AndroidWorld、Mobile-Agent、WebArena 等框架。具體整合點為：(1) 在代理的 `act()` 函式前插入路由器呼叫；(2) 將記憶體注入從單一格式改為動態格式；(3) 在框架的評估器中加入模態切換頻率作為診斷指標。

**與 Agent 軌跡日誌系統整合**
將每步的「採用模態、路由器信心度、實際效用」寫入軌跡日誌，可用於：(1) 離線分析哪些任務類型特別受益於動態切換；(2) 自動產生新的訓練資料以持續改進路由器；(3) 除錯時快速定位「模態選擇錯誤」導致的失敗案例。

**與人類回饋強化學習（RLHF）整合**
路由器輸出可作為 RL 中的動作空間擴充：代理不僅要選動作，還要選模態。將人類對「代理在某步是否提供了有用記憶體」的回饋作為獎勵訊號，可進一步優化路由器。

**與多代理系統整合**
在多代理架構中，可讓一個專門的「記憶體管理代理」負責執行 SwitchMem 路由器邏輯，主代理只需專注於動作決策，降低耦合度。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）與圖 1、圖 2，理解「同一段記憶用文字或影像呈現，效果竟然不同」這個核心觀察即可。第 3.1 節的實驗設定涉及較多公式，可先跳過，重點放在「為什麼需要動態選擇模態」的直覺理解。

**給 AI 工程師**：重點閱讀第 3 節的 D-CoE 分析方法與第 4 節的 SwitchMem 路由器設計。理解如何在不重新訓練 VLM 的前提下，從現有模型的隱藏狀態中萃取模態偏好訊號，這對你設計其他多模態路由系統（如文件理解、影片分析）會很有啟發。建議實際動手重現圖 4 的層級 AUROC 實驗。

**給研究者**：本論文的核心貢獻在於揭示「模態偏好是步驟相依的」這個現象，並提出可解釋的偏好訊號來源（D-CoE）。可進一步探索的方向包括：(1) 將此框架推廣到文字/音訊、影像/影片等其他模態對；(2) 研究路由器在跨任務、跨領域的泛化能力；(3) 探討是否能從理論上預測哪些步驟會偏好哪種模態，而無需資料驅動的路由器。

**給產品經理**：本論文的商業價值在於「用同一套記憶體基礎設施，透過聰明的路由機制提升代理表現」，無需為不同任務維護多套系統。建議關注第 5 節的實驗結果（SwitchMem 在三個基準測試上全面超越靜態基線），以及實作步驟中的「階段四：整合與部署」，評估導入至現有產品的工程成本與預期效益。特別是對於介面會持續更新的 SaaS 產品，動態模態切換可顯著降低維運成本。
