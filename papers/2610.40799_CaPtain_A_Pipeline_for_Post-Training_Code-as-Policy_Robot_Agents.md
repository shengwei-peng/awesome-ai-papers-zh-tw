# CaPtain：用於訓練後程式即策略機器人代理的流程

## ⚡ TL;DR

現有程式即策略機器人代理仰賴封閉前沿模型或凍結技能，小型開放式視覺語言模型無法直接控制機器人。
論文提出CaPtain流程，先以監督式微調合成軌跡訓練，再用物理評估器進行多輪強化學習。
CaPtain-4B在LIBERO-PRO達78.5%超越前沿模型，並以僅模擬適應遷移至真實機器人。

## 摘要翻譯

在程式設計 (Coding)、網頁導航 (Web navigation) 與工具使用 (Tool use) 等任務中，語言模型代理 (Language model agents) 如今普遍採用相同的訓練配方：先以監督式微調 (Supervised Fine-Tuning, SFT) 學習介面，再以多輪強化學習 (Multi-turn RL) 精通該介面。程式即策略 (Code-as-Policy, CaP) 將機器人操作 (Robot manipulation) 以相同形式表達——策略 (Policy) 對機器人 API (Robot APIs) 撰寫程式碼並讀回執行結果，因此同一套訓練配方理應適用。然而現有的 CaP 代理迴避了訓練：它們要麼提示封閉式前沿模型 (Closed frontier model)，要麼將操作委派給預先訓練好的視覺語言動作模型 (Vision-Language-Action model, VLA) 與高階技能 (High-level skills)，而小型開放式視覺語言模型 (Small open Vision-Language Model, VLM) 則完全失敗。我們提出 CaPtain，一個開放式的訓練後 (Post-training) 流程 (Pipeline)，能將小型開放式 VLM 轉化為能力出眾的 CaP 代理，且在測試時 (Test time) 無需 VLA、前沿模型 (Frontier model) 或特權狀態 (Privileged state)。CaPtain 在 CaPtain-Harness 內訓練並部署策略，該執行環境 (Execution harness) 同時涵蓋模擬與實際硬體 (Real hardware)，提供低階感知 (Low-level perception)、幾何資訊 (Geometry) 與防護式運動基元 (Guarded-motion primitives)。我們首先以 SFT 在由 GPT-6 Astra 生成的合成軌跡 (Synthetic trajectories) 上對齊基礎模型，再施加多輪強化學習。多輪強化學習必須從單一的回合結束結果 (End-of-episode outcome) 中，將信用分配 (Credit assignment) 至數十次代理請求，而這些請求的物理效應往往延遲數輪後才會顯現。因此我們引入一個物理評估器 (Physical critic)，讀取特權模擬器狀態 (Privileged simulator state，策略從未得見)，並依據每次請求對預測成功率 (Predicted chance of success) 的改變幅度來進行信用分配。從 Qwen3.5-4B（零樣本 (Zero-shot) 表現 0%）出發，CaPtain-4B 在 SFT 後於保留測試 (Held-out) 的 LIBERO 基準測試 (Benchmark) 上達到 55.4% 成功率 (Success rate)，在 RL 後達到 73.8%。在 LIBERO-PRO 上，它達到 78.5%，超越多個前沿模型代理，且其 RL 增益在三套擾動測試套件 (Perturbation suites) 上持續存在（+17.6 至 +21.2 分）。在無目標領域訓練 (Target-domain training) 的情況下，它於 SimplerEnv WidowX 上達到 83.3%，在 CaP-Bench 上超越前沿模型，並在僅模擬適應 (Simulation-only adaptation) 後即可於實際機器人 (Real robot) 上運行。我們釋出所有程式碼、資料與模型權重 (Weight updates)。

### 核心貢獻（3～5點）
- **提出 CaPtain 開放式訓練後流程**：將小型開放式視覺語言模型 (VLM) 轉化為能力出眾的程式即策略 (CaP) 代理，在測試時無需視覺語言動作模型 (VLA)、前沿模型或特權狀態。
- **設計 CaPtain-Harness 統一執行環境**：橫跨模擬與實際硬體，提供低階感知、幾何資訊與防護式運動基元，使策略可在同一介面下完成訓練與部署。
- **引入物理評估器解決多輪信用分配難題**：讀取策略從未得見的特權模擬器狀態，依據每次代理請求對預測成功率的改變幅度進行信用分配，有效處理物理效應延遲顯現的問題。
- **全面的實證成果與優異的泛化能力**：在 LIBERO、LIBERO-PRO、SimplerEnv WidowX、CaP-Bench 等多項基準測試上表現優異，RL 增益在三套擾動測試套件上穩定維持（+17.6 至 +21.2 分），且僅經模擬適應即可部署至實際機器人。
- **完整開源釋出**：釋出所有程式碼、合成資料與模型權重，促進社群後續研究。

### 適合對象
- 從事機器人基礎模型（Robot Foundation Models）與視覺語言動作模型 (VLA) 研究的學者與工程師。
- 關注語言模型代理在程式即策略 (Code-as-Policy)、工具使用 (Tool use) 等領域應用的研究人員。
- 對強化學習 (RL) 中信用分配 (Credit assignment)、多輪 RL 演算法設計感興趣的機器學習研究者。
- 從事模擬到真實 (Sim-to-Real) 遷移、機器人操作 (Robot manipulation) 系統整合的實務工程團隊。
- 欲評估小型開放式模型在機器人代理任務中潛力的產業研發人員。

## 深度分析

#### 方法論解析

CaPtain 的核心論點建立在兩個關鍵觀察之上：第一，現有的程式即策略 (Code-as-Policy, CaP) 機器人代理要麼依賴封閉式前沿模型 (closed frontier model) 的提示，要麼將操作委派給預訓練的視覺語言動作模型 (Vision-Language-Action model, VLA) 或高階技能 (high-level skills)，使得代理本身無法學習改進操作決策；第二，小型開放式視覺語言模型 (small open VLM) 在直接控制機器人時完全失敗（Qwen3.5-4B 在 LIBERO 上零樣本成功率為 0%）。因此，作者提出一個完整的「監督式微調 (SFT) + 多輪強化學習 (multi-turn RL)」訓練後 (post-training) 流程，將小型開放式 VLM 訓練成獨立的 CaP 代理。

**CaPtain-Harness 的設計哲學**

CaPtain-Harness 是整個系統的執行骨幹，其設計刻意排除語意化的高階技能。系統僅暴露 22 個低階基元 (low-level primitives)，分為三大類：(1) 低階感知 (low-level perception)，回傳遮罩與點；(2) 幾何測量 (geometry)，提供空間量測功能；(3) 防護式運動基元 (guarded-motion primitives)，接受明確的末端執行器 (end-effector) 姿態或夾爪 (gripper) 指令。每一次呼叫都會回傳結構化的文字回執 (text receipt)，記錄實際發生的物理事件，例如量測到的姿態、接觸力、或運動停止的原因。這種設計的關鍵在於：策略必須自行決定從哪個方向接近、何時閉合夾爪，而非依賴預定義的「抓取 (grasp)」、「放置 (place)」技能。這迫使策略學習真正的操作決策，而非僅僅是技能排序。

值得注意的是，CaPtain-Harness 的策略面向 API 在 LIBERO、RoboTwin 2.0、RoboDojo、SimplerEnv、CaP-Bench 以及實際機器人之間保持不變，這為跨基準測試的零樣本遷移提供了基礎。

**兩階段訓練流程**

第一階段是 SFT。作者使用 GPT-6 Astra 在 CaPtain-Harness 內生成合成軌跡 (synthetic trajectories)，並以部署時完全相同的多輪格式渲染。這種「in-harness」資料生成方式確保了訓練與測試之間的格式一致性，避免了常見的模擬到真實差距 (sim-to-real gap) 中的格式偏差問題。

第二階段是多輪 RL，這是論文最具技術創新性的部分。機器人操作面臨一個語言代理中不存在的信用分配 (credit assignment) 難題：每個回合包含數十次代理請求，其中大多數僅用於感知或驗證，而真正的物理效果往往在數輪後才顯現。僅使用回合結束結果 (end-of-episode outcome) 的 RL 會對所有請求給予相同信用，而語言模型評估器 (critic) 只能從文字與影像間接推斷物理進展。

**物理評估器 (Physical Critic) 的非對稱設計**

論文的關鍵洞察是：機器人學習存在語言代理所缺乏的非對稱性——訓練在模擬器中進行，因此物體的精確姿態、抓取狀態、子目標進展都是已知的，即使部署時策略只能從攝影機影像行動。基於此，作者設計了物理評估器，它能讀取策略不可見的特權模擬器狀態 (privileged simulator state)，並根據每次請求改變預測成功率 (predicted chance of success) 的程度來分配信用。

這個設計結合了 SAO 的串流 RL 公式化與非對稱 actor-critic 訓練 (asymmetric actor-critic training)。由於信用是在固定時間索引上測量的變化量，僅執行感知或驗證的請求會獲得接近零的信用，而信用會集中在抓取與放置等物理操作決策上。物理評估器僅在訓練期間使用，測試時策略僅依賴攝影機影像與回執，這保證了部署的實用性。

#### 實驗數據解讀

**LIBERO 上的基準表現**

從 Qwen3.5-4B 的 0% 零樣本成功率開始，CaPtain-4B 在保留測試 (held-out) LIBERO 上達到 SFT 後 55.4%、RL 後 73.8% 的成功率。這展示了兩階段訓練的互補性：SFT 教會模型使用 API 介面，RL 則從互動結果中精煉行為。

**LIBERO-PRO 上的競爭力**

在更具挑戰性的 LIBERO-PRO 上，CaPtain-4B 達到 78.5%，超越了多個前沿模型代理，包括 K1 (77.2%)、WAA (75.6%) 和 ASPIRE (71.7%)。這個結果特別值得注意，因為 CaPtain-4B 僅有 4B 參數，而這些前沿模型代理通常規模大得多且運算成本高昂。

**RL 在低階基元上的增益更大**

一個重要的對比實驗顯示：RL 在低階基元上的增益（為 SFT 模型增加 19.4 點）遠大於在凍結 VLA 上的增益（AgenticRoboRL 僅增加 5.9 點）。雖然兩者的起點不同，但這個差異暗示了讓策略控制所有操作決策（而非僅排序預訓練技能）能讓 RL 更有效地優化行為。

**擾動穩健性**

在三個擾動測試套件 (perturbation suites) 上，RL 帶來的增益持續存在，範圍從 +17.6 到 +21.2 點。在 LIBERO-Plus 的全部七個擾動維度上都有顯著改善。相比之下，端到端策略如 π0.5 在 LIBERO 上達到 97%，但在 LIBERO-PRO 上驟降至 12.8%；RL 調校的 RIPT-VLA 在 LIBERO-Plus 上得分不超過其基礎模型。這些對比表明 CaPtain 的程式即策略形式提供了更好的擾動穩健性，可能因為程式合成允許在測試時進行更靈活的適應。

**跨基準的零樣本遷移**

無需目標領域訓練 (target-domain training)，CaPtain-4B 在 SimplerEnv WidowX 上達到 83.3%，在 CaP-Bench 上得分 75.0，超過前沿模型以及一個在該基準上用 RL 訓練的 7B 編碼器。這展示了 CaPtain-Harness 統一 API 設計的遷移優勢。

**真實機器人部署**

經過僅在粗略模擬孿生環境中的適應後，CaPtain-4B 能在實際機器人上完成任務，無需任何真實世界資料。這是模擬到真實遷移的重要驗證。

**已知限制**

在 RoboTwin 2.0 和 RoboDojo 上，遷移仍然有限（分別為 22.6% 和 0.8%），這些基準需要雙臂協調與不熟悉的手臂運動學。這表明 CaPtain 目前在高度特定運動學要求的任務上仍有不足。

#### 與現有研究的比較

**與前沿模型直接提示的比較**

GPT-6 Astra 直接用作機器人策略時，在 RoboDojo 排行榜上排名高於所有公開條目；搭配程式碼執行環境 (coding harness) 時解決了 94.0% 的 LIBERO-PRO 回合。然而，這類方法有三大限制：(1) 每次回合呼叫前沿模型的財務成本高昂；(2) 無法針對新機器人或任務進行微調；(3) 無法在車載運算 (onboard compute) 上運行。CaPtain 透過訓練小型開放式模型解決了所有這些問題，雖然在絕對成功率上可能略低，但提供了部署靈活性與成本效益。

**與委派給 VLA/技能的方法比較**

PyRUA 訓練 4B 編碼器搭配凍結的 VLA 與運動規劃器 (motion planner)；AgenticRoboRL 在凍結的 LIBERO 訓練 VLA 周圍訓練規劃器；SenseNova-RoboRSI 建構 27B 代理搭配可重用技能與可選 VLA 呼叫；Gemini 4 Argon 透過抓取、放置等技能暴露程式即策略。這些系統中，程式碼決定呼叫哪個技能，但技能決定如何抓取、接近與放置。因此，代理受限於技能訓練所用的資料，RL 至多只能學習排序技能。CaPtain 的根本區別在於：沒有 VLA、沒有高階技能，所有操作決策都由策略本身做出。

**與其他小型 VLM 訓練嘗試的比較**

先前訓練小型 VLM 控制機器人的努力主要依賴 SFT 或單輪純文字 RL (single-turn text-only RL)。CaPtain 提供了完整的 SFT-and-RL 配方，教會小型開放式 VLM 透過低階基元進行操作。

**RL 增益的比較**

CaPtain 的 RL 在 LIBERO-PRO 四個套件上為 SFT 模型增加 19.4 點，而 AgenticRoboRL 在凍結 VLA 上僅增加 5.9 點。雖然起點不同，但這個差距暗示了讓策略控制所有操作決策能讓 RL 更有效。

**擾動穩健性的比較**

π0.5 從 LIBERO 的 97% 驟降至 LIBERO-PRO 的 12.8%；RIPT-VLA 在 LIBERO-Plus 上不超過其基礎模型。相比之下，CaPtain 的 RL 增益在所有三個擾動套件上持續存在。這表明程式即策略形式在擾動下更穩健。

#### 可重現性評估

CaPtain 在可重現性方面表現出色，作者明確釋出了所有相關資源：

1. **程式碼**：完整的訓練程式碼與 CaPtain-Harness 實作均已開源。
2. **資料**：SFT 階段使用的合成軌跡資料已釋出，這對於其他研究者重現或基於此工作至關重要。
3. **模型權重**：CaPtain-4B 的權重已公開釋出，使其他研究者能直接使用或進行後續實驗。

這種全面的開源策略與論文中強調的「開放式」理念一致——不僅模型是開放的，整個訓練流程也是可存取且可驗證的。CaPtain-Harness 統一 API 設計也降低了跨基準重現的技術門檻。

然而，需要注意的潛在可重現性挑戰包括：(1) 合成軌跡的生成依賴 GPT-6 Astra，其 API 存取成本可能限制部分研究者的重現能力；(2) 物理評估器的精確實作細節需要仔細審查程式碼才能完全理解；(3) 真實機器人部署的具體適應流程可能需要額外的硬體特定調整。

#### 未來研究方向

**1. 擴展到更複雜的操作任務**

CaPtain 目前在需要雙臂協調的 RoboTwin 2.0 和 RoboDojo 上表現有限（22.6% 和 0.8%）。未來工作可以探索如何擴展 CaPtain-Harness 以支援雙臂操作，以及如何讓策略學習更複雜的運動學約束。

**2. 物理評估器的改進**

雖然物理評估器利用了模擬器的特權狀態，但其設計仍有改進空間。未來方向包括：(1) 探索更細粒度的信用分配機制；(2) 研究如何將物理評估器的知識蒸餾到不依賴模擬器的純視覺評估器中；(3) 將物理評估器擴展到更長期的任務規劃。

**3. 從模擬到真實的遷移增強**

雖然 CaPtain 展示了僅用模擬適應即可部署到真實機器人，但適應過程仍需要在「粗略模擬孿生環境」中進行。未來可以研究：(1) 完全消除模擬到真實差距的技術；(2) 利用真實世界回饋進行線上學習；(3) 開發更高效的領域隨機化 (domain randomization) 策略。

**4. 與其他代理範式的結合**

CaPtain 的程式即策略形式可以與其他範式結合：(1) 整合世界模型 (world model) 進行前瞻規劃；(2) 結合人類示範進行模仿學習；(3) 探索多代理協作框架。

**5. 安全與可解釋性**

程式即策略的一個重要優勢是可解釋性——策略輸出的程式碼可以被檢查。未來可以研究：(1) 如何利用這一特性進行安全驗證；(2) 如何在程式碼層面引入安全約束；(3) 如何讓人類更容易理解和修正策略行為。

**6. 效率優化**

雖然 CaPtain-4B 比前沿模型小得多，但仍有優化空間：(1) 蒸餾到更小的模型；(2) 優化推理延遲以支援即時控制；(3) 探索專用硬體加速。

**7. 跨領域遷移**

CaPtain-Harness 的統一 API 為跨領域遷移提供了基礎。未來可以探索從機器人操作到其他領域（如導航、操控軟體工具）的遷移，以及如何設計通用的代理執行環境。

## 論文問答

**Q1：為什麼現有的 Code-as-Policy (CaP) 機器人代理無法直接套用「監督式微調 + 多輪強化學習」這個通用訓練食譜？**
A：現有 CaP 代理大致分為兩條路線，但都迴避了真正的訓練。第一條路線直接呼叫封閉式前沿模型（如 GPT-6 Astra），雖然表現優異，但每次回合都要付出高昂的 API 成本、無法針對新機器人或新任務微調，也無法在機器人本機運算資源上運行。第二條路線則把操作本身外包給預先訓練好的視覺語言動作模型 (VLA) 或高階技能庫（如 PyRUA、AgenticRoboRL、SenseNova-RoboRSI），由程式碼決定「呼叫哪個技能」，但技能本身決定「如何抓取、接近、放置」。這種分工使得代理永遠被技能背後的訓練資料所限制，強化學習最多只能學會排列組合技能，而無法真正學會低階操作決策。因此，雖然「SFT + 多輪 RL」在程式設計、網頁導航、工具使用等領域已是標準食譜，機器人操作領域卻缺少一個能讓小型開放模型從頭學會低階操作的完整訓練流程。

**Q2：小型開放式視覺語言模型 (VLM) 在直接控制機器人時為何會「完全失敗」？這對機器人學習領域意味著什麼？**
A：論文中明確指出，Qwen3.5-4B 在 CaPtain-Harness 中對 LIBERO 回合的零樣本成功率為 0%，這代表小型開放式 VLM 缺乏直接寫出可執行機器人程式碼的能力。這樣的失敗凸顯了機器人操作相較於純文字任務的特殊性：模型不僅要理解視覺與語言，還必須理解三維幾何、接觸力、夾爪開閉時機等物理概念，而這些概念在一般網路語料中幾乎沒有監督訊號。對機器人學習領域而言，這意味著「單純把大型語言模型的食譜搬過來」是不夠的，必須設計專門的執行環境、合成資料與信用分配機制，才能讓小型模型跨越從「看得懂」到「做得到」的鴻溝。

**Q3：為什麼將操作任務「外包」給預訓練的視覺語言動作模型 (VLA) 或高階技能會限制代理的學習上限？**
A：當程式碼只負責決定「呼叫哪個技能」，而技能本身決定「如何抓取、從哪個方向接近、何時關閉夾爪」時，強化學習所能優化的空間就被壓縮到技能排列組合的層級。論文中以 AgenticRoboRL 為例，圍繞凍結 VLA 訓練規劃器時，RL 僅帶來 5.9 點的提升；而 CaPtain 在低階基元上做 RL，則帶來 19.4 點的提升。這樣的對比說明，當操作決策被外包給無法再學習的元件時，整個系統的學習天花板就被預訓練資料的覆蓋範圍所限制，無法透過更多互動來持續改進真正的操作策略。

**Q4：CaPtain 的核心訓練流程是什麼？SFT 階段與 RL 階段各自扮演什麼角色？**
A：CaPtain 採用兩階段訓練流程。第一階段是監督式微調 (SFT)，使用 GPT-6 Astra 在 CaPtain-Harness 內實際執行所產生的合成軌跡，並以部署時完全相同的多輪格式渲染，讓模型學會介面呼叫與結構化回傳的解析方式。第二階段是多輪強化學習 (RL)，採用 SAO 的串流式 RL 公式結合非對稱的 actor-critic 訓練，並引入一個能讀取特權模擬器狀態的物理評估器，根據每個請求對預測成功率的改變量來分配稠密信用。SFT 負責讓模型「會用工具」，RL 則負責讓模型「用得好」，兩者缺一不可——沒有 SFT，模型連 API 都不會呼叫；沒有 RL，模型就只能模仿示範者而無法從自身互動中持續改進。

**Q5：什麼是「物理評估器 (physical critic)」？它如何解決多輪強化學習中的信用分配問題？**
A：物理評估器是 CaPtain 引入的關鍵創新，它在訓練時讀取策略永遠看不到的特權模擬器狀態（例如精確的物體姿態、夾爪接觸狀態、子目標進度），並估計每一步請求對「預測成功率」的改變量。由於這個改變量是在固定時間索引上測量，純粹的感知或驗證請求會得到接近零的信用，而真正的抓取與放置決策則會獲得集中且稠密的信用。這樣的設計巧妙利用了機器人學習相較於純語言代理的獨特優勢：訓練在模擬器中進行，因此可以獲得真實物理進度的精確訊號，但部署時策略仍只靠攝影機影像與結構化回傳運作，從而兼顧了稠密監督與測試時的現實可行性。

**Q6：CaPtain-Harness 為何刻意只暴露 22 個低階基元而不提供抓取、放置等高階技能？這樣的設計選擇帶來哪些權衡？**
A：CaPtain-Harness 僅提供 22 個低階的感知、幾何量測與防護式運動基元，沒有任何「抓取」、「放置」、「開抽屜」之類的語意化技能，也不依賴 VLA。這樣的設計迫使策略必須自己決定從哪裡抓取、從哪個方向接近、何時關閉夾爪，使得所有操作決策都能被強化學習所優化。回傳的結構化文字收據會報告實際發生的物理事件，例如量測到的姿態、接觸力或運動停止的原因，讓策略能從結果中學習。權衡在於：低階基元對小型模型來說學習難度更高，需要更多訓練資料與信用分配機制；但回報是策略不再被預訓練技能的覆蓋範圍所限制，能在擾動下展現更強的穩健性，並能跨基準與跨硬體遷移。

**Q7：CaPtain-4B 在 LIBERO 與 LIBERO-PRO 上的關鍵數據為何？這些結果說明了什麼？**
A：在保留測試的 LIBERO 上，CaPtain-4B 從 Qwen3.5-4B 的 0% 零樣本成功率，經過 SFT 提升到 55.4%，再經過 RL 提升到 73.8%。在更困難的 LIBERO-PRO 上，CaPtain-4B 達到 78.5%，超越了多個前沿模型代理，包括 K1（77.2%）、WAA（75.6%）與 ASPIRE（71.7%）。這些數據說明了三件事：第一，SFT 與 RL 兩個階段對小型開放模型都是必要的，單獨使用任一階段都無法達到最佳表現；第二，在低階基元上做 RL 比在高階技能上做 RL 帶來更大的增益；第三，一個 4B 的小型開放模型在經過完整訓練後，可以在困難基準上超越遠比它大的前沿模型代理，同時運行成本僅是後者的一小部分。

**Q8：在擾動測試套件 (perturbation suites) 中，CaPtain-4B 的表現如何？這對實際部署有何意義？**
A：CaPtain-4B 在 LIBERO-PRO、LIBERO-Plus 與 LIBERO-MAX 三個擾動測試套件上，RL 帶來的增益分別落在 +17.6 到 +21.2 點之間，且 LIBERO-Plus 的全部七個擾動維度都顯著改善。相較之下，論文中報導的端到端政策 π0.5 在 LIBERO 上達到 97%，但在 LIBERO-PRO 上驟降到 12.8%；經 RL 調整的 RIPT-VLA 在 LIBERO-Plus 上的表現也不超過其基礎模型。這樣的對比凸顯了 CaPtain 路線的穩健性優勢：因為策略是在低階基元上組合程式碼，而不是直接輸出動作，當環境出現擾動時，程式碼可以根據結構化回傳即時調整，而端到端 VLA 的反應則更受限於訓練資料的分布。對實際部署而言，這代表 CaPtain 代理在面對光照變化、物體位置偏移、新背景等真實世界的雜訊時，更有可能維持任務成功率。

**Q9：跨基準與跨硬體的零樣本遷移表現如何？哪些任務成功轉移，哪些失敗？**
A：在沒有目標領域訓練的情況下，CaPtain-4B 在 SimplerEnv WidowX 上達到 83.3%，在 CaP-Bench 上得到 75.0 分，超越了前沿模型以及一個專門用 RL 在 CaP-Bench 上訓練的 7B 編碼器，並且在僅經過粗略模擬雙胞胎適應後就能在真實機器人上完成任務。然而，遷移在 RoboTwin 2.0 與 RoboDojo 上表現有限，分別只有 22.6% 與 0.8% 的成功率。這樣的結果呈現一個清楚的模式：當目標任務的單臂操作語意與訓練時相似時，零樣本遷移非常成功；但當任務需要雙臂協調或面對陌生的手臂運動學時，僅靠模擬訓練的策略仍力有未逮，需要額外的適應。

**Q10：CaPtain 對於機器人產業的實務部署有何潛在影響？相較於前沿模型方案有哪些成本與可調控性優勢？**
A：對機器人產業而言，CaPtain 最大的實務價值在於把「機器人操作策略」從依賴閉源 API 的服務，轉變為可在車載運算資源上運行的開源權重。一個 4B 模型可以在不連網的情況下即時產生控制程式碼，省去每次回合呼叫前沿模型的高昂費用，也避免了將感測器影像上傳到外部伺服器所帶來的隱私與延遲問題。此外，由於模型權重完全開放，製造商可以針對自家機器人的運動學、感測器配置與任務需求進行微調，而不必受限於前沿模型固定的介面。這對中小型機器人公司、學術研究單位以及重視資料主權的應用場景（如醫療、國防）尤其關鍵。

**Q11：在僅使用模擬資料的情況下，CaPtain-4B 為何能成功部署到真實機器人？這對資料收集成本有何意義？**
A：CaPtain-4B 之所以能在僅經過模擬適應後就部署到真實機器人，關鍵在於策略在測試時只依賴攝影機影像與結構化文字回傳，而這些介面在模擬與真實之間的差距比「直接輸出動作」要小得多。當策略寫出「移動到某個座標並關閉夾爪」這樣的程式碼時，模擬器與真實機器人都會回報實際的物理結果，策略可以根據回傳即時修正。這種「以程式碼為介面、以回傳為監督」的設計大幅降低了模擬到真實的轉移成本，使得資料收集不再需要昂貴的真實機器人示範，也讓研究團隊能在不具備大規模硬體資源的情況下推進機器人研究。

**Q12：CaPtain 對機器人研究社群與開源生態系的貢獻為何？**
A：論文的貢獻涵蓋四個層面：完整的 SFT 與 RL 訓練程式碼、CaPtain-4B 的模型權重、CaPtain-Harness 這個可攜式執行環境，以及合成訓練資料。這樣的全套釋出讓其他研究者可以在 LIBERO、RoboTwin 2.0、RoboDojo、SimplerEnv、CaP-Bench 甚至自有的機器人平台上重現並擴展 CaPtain 的結果。更重要的是，物理評估器的設計提供了一個可重複使用的範本，讓未來的工作可以把同樣的「特權狀態 → 稠密信用」思路應用到其他機器人任務或甚至其他領域的代理訓練中。這對開源機器人學習生態系的長期發展具有基礎建設性質的價值。

**Q13：CaPtain 在哪些場景下表現不佳？論文中承認的限制有哪些？**
A：論文坦承 CaPtain 在兩個場景上表現有限：在 RoboTwin 2.0 上僅達到 22.6%，在 RoboDojo 上僅達到 0.8%。這兩個基準的共同特徵是需要雙臂協調以及面對訓練時未見過的手臂運動學。論文的分析指出，當任務的語意結構（例如「雙手交接物體」）或硬體的運動學特性與訓練分布差距過大時，僅靠模擬訓練的策略無法有效泛化。此外，由於 CaPtain-Harness 刻意不提供高階技能，所有複雜操作都必須由策略自己組合低階基元來完成，這對於需要精細雙臂時序協調的任務來說學習難度特別高。

**Q14：物理評估器依賴模擬器特權狀態，這在實際部署時會帶來什麼樣的「訓練-測試不一致」風險？**
A：物理評估器在訓練時讀取特權模擬器狀態來分配信用，但測試時策略只能依賴攝影機影像與結構化回傳，這種「訓練-測試不對稱」雖然是 CaPtain 設計上的刻意選擇，卻也帶來風險：當真實世界的物理現象（例如物體滑落、夾爪打滑、感測器雜訊）無法被模擬器精確重現時，訓練時學到的「哪些步驟重要」的判斷可能與真實情況不符。論文中 CaPtain-4B 在真實機器人上能成功部署，部分歸功於 CaPtain-Harness 的結構化回傳提供了豐富的物理訊號，但若未來要應用到更複雜或更不可預測的真實環境，仍需要研究如何讓評估器對模擬-真實差距更為穩健，例如引入領域隨機化或真實資料的微調。

**Q15：未來可以從哪些方向延伸 CaPtain 的方法？例如雙臂操作、新硬體適應或更複雜的任務？**
A：CaPtain 的方法論為多條未來研究方向鋪好了路。第一，針對雙臂操作，可以設計專屬的低階基元與雙臂物理評估器，並蒐集更多雙臂示範資料來縮小 RoboTwin 2.0 與 RoboDojo 上的轉移差距。第二，針對新硬體適應，可以利用 CaPtain-Harness 的可攜性，在新機器人的模擬雙胞胎中快速生成 SFT 資料並進行 RL 調整，避免昂貴的真實示範。第三，針對更複雜的長期任務，可以探索階層式 CaP：讓一個高階代理負責子目標分解，而低階代理（如 CaPtain-4B）負責執行每個子目標。第四，物理評估器的設計可以推廣到其他需要稠密信用但缺乏中間回報的領域，例如網頁導航或工具使用，開啟跨領域的代理訓練新範式。

## 實務應用指南

### 適用場景

1. **中小型工廠的取放作業（Pick-and-Place）**：在電子零件組裝、藥品分裝、烘焙食品包裝等場域，CaPtain-4B 可作為單臂機器人的通用策略，僅需在模擬器中收集資料即可部署到實體手臂，無需昂貴的閉源模型 API 呼叫費用。

2. **倉儲物流中的單臂分揀**：在 LIBERO-PRO 擾動測試中展現的穩健性（+17.6 至 +21.2 分）使其適合用於光線變化、物件位置隨機的倉儲分揀任務，特別是 SKU 經常變動、無法為每個新物件重新收集大量真機資料的情境。

3. **實驗室自動化（Lab Automation）**：CaP-Bench 上 75.0 分的表現顯示其在「程式即策略」形式的科學實驗操作（如樣本搬移、儀器按鈕操作）上優於前沿模型，適合生技、化學實驗室的自動化升級。

4. **家用服務機器人雛型開發**：對於新創團隊而言，僅用一台搭載消費級 GPU 的工作站即可完成從 SFT 到 RL 的完整訓練鏈，無需依賴雲端前沿模型，適合開發原型機。

5. **教育與研究用的機器人教學平台**：CaPtain-Harness 統一了 LIBERO、RoboTwin 2.0、SimplerEnv、CaP-Bench 與實體機器人的 API 介面，是教授「語言模型 + 機器人」整合課程的理想實驗平台。

### 實作前置條件

**資料需求**
- **合成 SFT 軌跡**：需使用 GPT-6 Astra（或同等級前沿模型）在 CaPtain-Harness 中產生多輪互動軌跡，格式必須與部署時完全一致。建議每個目標任務至少準備數百至數千條成功軌跡。
- **模擬器環境**：需具備可讀取特權狀態（物件姿態、夾爪接觸力、子目標進度）的模擬器，例如 LIBERO、RoboTwin 2.0、SimplerEnv。
- **保留測試集**：LIBERO-PRO、LIBERO-Plus、LIBERO-MAX 等擾動套件用於驗證泛化能力。

**運算資源**
- **訓練硬體**：4B 規模的 VLM 進行 SFT + 多輪 RL，建議至少配備 8 張 A100/H100 等級 GPU（具體視 batch size 與序列長度而定）。
- **推論硬體**：部署階段可在單張消費級 GPU（如 RTX 4090）甚至邊緣裝置上執行 4B 模型，符合「onboard compute」需求。
- **模擬並行**：RL 訓練需大量平行模擬環境以收集軌跡，建議使用 Isaac Gym、MuJoCo MPC 等高效能模擬後端。

**技能門檻**
- 熟悉 SFT 訓練流程（資料格式化、LoRA 或全參數微調）。
- 具備多輪 RL 實作經驗，特別是 SAO 串流式 RL 與非對稱 Actor-Critic 的整合。
- 理解機器人學基礎（正向運動學、夾爪控制、防護式運動）。
- 能撰寫或擴充 CaPtain-Harness 的 22 個低階基元。

### 實作步驟建議

**步驟一：建置 CaPtain-Harness**
在目標機器人平台上實作 22 個低階基元，分為三類：(1) 低階感知（影像、遮罩、特徵點）、(2) 幾何量測（距離、姿態、接觸偵測）、(3) 防護式運動（末端執行器移動、夾爪開閉）。每個呼叫必須回傳結構化的文字回執（receipt），描述實際發生的物理結果，例如「夾爪在 (x, y, z) 接觸到物件，量測力為 F 牛頓」。確保 LIBERO、SimplerEnv、實體機器人之間的 API 介面完全一致。

**步驟二：產生 SFT 訓練資料**
使用 GPT-6 Astra 在 CaPtain-Harness 中執行目標任務，收集成功的多輪軌跡。關鍵在於軌跡必須以「部署時完全相同的多輪格式」呈現，包括影像觀察、文字回執、程式碼生成。過濾掉失敗軌跡，並對軌跡進行資料增強（不同初始物件配置、光照變化）。

**步驟三：執行監督式微調（SFT）**
以 Qwen3.5-4B 為基礎模型，在合成軌跡上進行 SFT。預期可將 LIBERO 成功率從 0% 提升至約 55.4%。注意保留一部分任務作為 held-out 測試集，避免資料洩漏。

**步驟四：建置物理評估器（Physical Critic）**
實作一個僅在訓練時使用的評估器模組，讀取模擬器的特權狀態（物件 6DoF 姿態、夾爪接觸狀態、子目標完成度），估計每個時間步的「預測成功率」。此評估器對策略完全不可見，部署時僅依靠攝影機影像與回執。

**步驟五：執行多輪強化學習（RL）**
採用 SAO 串流式 RL 結合非對稱 Actor-Critic 訓練。評估器在固定時間索引測量「預測成功率」的變化量，作為每個請求的稠密信用。預期可將 LIBERO 成功率從 55.4% 提升至 73.8%，並在 LIBERO-PRO 上達到 78.5%。

**步驟六：跨領域評估與擾動測試**
在 LIBERO-PRO、LIBERO-Plus、LIBERO-MAX 三個擾動套件上驗證穩健性。對於 SimplerEnv WidowX 與 CaP-Bench，無需目標領域訓練即可達到 83.3% 與 75.0 分。

**步驟七：僅模擬適應後部署至實體機器人**
在模擬器中針對目標實體機器人建立粗略的數位孿生（coarse simulated twin），進行少量微調後即可部署至真機，無需收集真實世界資料。

### 潛在風險與注意事項

**風險一：雙手臂協調能力不足**
CaPtain-4B 在 RoboTwin 2.0（22.6%）與 RoboDojo（0.8%）表現不佳，主因是這兩個基準需要雙手臂協調與非熟悉的運動學結構。**緩解方式**：若目標任務涉及雙手臂，需擴充 CaPtain-Harness 加入雙手臂基元，並重新收集 SFT 軌跡。

**風險二：模擬到真實的差距（Sim-to-Real Gap）**
雖然論文宣稱可「僅模擬適應」部署至實機，但實際部署仍需建立粗略數位孿生。**緩解方式**：在模擬器中加入域隨機化（光線、紋料、物理參數），並準備少量真機資料用於最終微調。

**風險三：對特權狀態的依賴**
物理評估器依賴模擬器內部狀態，這在真實世界中不可得。**緩解方式**：評估器僅用於訓練階段，部署時策略僅依靠攝影機與回執；可考慮在真實世界中以物件追蹤器（如 AprilTag、深度相機）部分模擬特權狀態。

**風險四：合成資料的品質偏差**
SFT 資料完全由 GPT-6 Astra 生成，可能帶有前沿模型的偏見與失敗模式。**緩解方式**：在 RL 階段讓策略自行探索，校正 SFT 的偏差；定期檢查失敗案例並補充人類示範。

**風險五：API 變更導致部署失效**
若 CaPtain-Harness 的基元在部署後變更，策略可能產生無效呼叫。**緩解方式**：建立版本化的 API 規範，並在策略輸出後加入語法與語意驗證層。

**風險六：小型模型的長序列衰減**
4B 模型在極長 episode 中可能出現注意力衰退或重複生成。**緩解方式**：限制 episode 最大長度，並在回執中明確標示任務進度，幫助模型維持上下文。

### 與其他技術的整合建議

**與預訓練 VLA 整合**
CaPtain 並非取代 VLA，而是提供另一條路線。若團隊已部署 VLA（如 π0.5、RIPT-VLA），可將 CaPtain 作為高階規劃器，負責任務分解與例外處理，VLA 負責低階動作執行，發揮兩者互補優勢。

**與前沿模型 API 整合**
在 CaPtain-4B 信心不足時，可設定回退機制（fallback）呼叫 GPT-6 Astra 等前沿模型處理困難案例，兼顧成本與能力。CaPtain-Harness 的統一 API 介面讓此整合無需修改策略。

**與 ROS 整合**
將 CaPtain-Harness 的 22 個基元封裝為 ROS 2 節點或服務，即可與現有的機器人作業系統生態系互通，包括 MoveIt 運動規劃、Nav2 導航等。

**與運動規劃器整合**
雖然 CaPtain 內建防護式運動基元，但對於複雜避障任務，可將 MoveIt 或 cuRobo 作為底層運動規劃器，CaPtain 僅負責高階決策。

**與視覺感知管線整合**
CaPtain-Harness 的低階感知基元可與 Segment Anything（SAM）、DINOv2 等視覺基礎模型串接，提升遮罩與特徵點品質。

**與監控與日誌系統整合**
部署時應將所有回執、影像、程式碼記錄至結構化日誌系統（如 MLflow、W&B），便於事後分析失敗案例與持續改進。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的「程式即策略」概念介紹，理解為什麼「讓語言模型寫程式來控制機器人」是一個強大的範式。接著跳到結論部分，認識 CaPtain-4B 在各基準上的數字（73.8%、78.5%、83.3%），建立直觀印象。實作上可從安裝 CaPtain-Harness、在 LIBERO 上重現 SFT 訓練開始，無需深入 RL 部分。

**給 AI 工程師**：重點閱讀第 1 節中關於「物理評估器」與「多輪信用分配」的段落，理解如何將特權模擬器狀態轉換為稠密的每請求信用。實作上應關注 SAO 串流式 RL 與非對稱 Actor-Critic 的整合細節，並評估將 CaPtain-Harness 移植到自有機器人平台的工程量。建議先在 LIBERO 上重現結果，再考慮部署到實體機器人。

**給研究者**：本論文的核心貢獻在於揭示「機器人學習的非對稱性」——訓練時可讀取特權狀態，部署時僅依靠影像。建議深入分析物理評估器的設計選擇、信用分配的數學推導，以及為何在低階基元上 RL 的增益（+19.4 分）遠高於在凍結 VLA 上的增益（+5.9 分）。可進一步探索的方向包括：雙手臂擴充、跨機器人形態遷移、評估器蒸餾到純視覺版本等。

**給產品經理**：CaPtain 的商業價值在於「以小型開放模型達到前沿模型等級的機器人操作能力」，且無需支付 API 呼叫費用、無需收集大量真實世界資料。關鍵決策點包括：目標任務是否為單臂操作（CaPtain 表現優異）還是雙手臂（表現受限）；是否能接受僅模擬訓練；團隊是否具備 GPU 訓練基礎設施。建議先以單臂取放任務作為 POC，驗證後再擴展到更複雜的應用場景。
