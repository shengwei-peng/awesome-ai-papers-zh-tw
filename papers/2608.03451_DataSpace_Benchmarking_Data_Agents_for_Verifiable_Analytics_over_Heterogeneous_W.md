# DataSpace：異質工作空間上可驗證分析的資料代理基準測試

**原文標題：** DataSpace: Benchmarking Data Agents for Verifiable Analytics over Heterogeneous Workspaces

**發布日期：** 2026-08-04

## ⚡ TL;DR

現有基準多孤立結構查詢、檢索與開放分析，缺乏異質證據發現、完整表格輸出與確定性評估的統一。
本文提出 DataSpace與DataSpace-Builder，實現異質工作空間可驗證表格分析。
該基準亦為KDD Cup 2026官方評測，最佳準確率達66.34%，框架選擇造成15.36分差距。

---

## 摘要翻譯

Data agents（資料代理）讓使用者得以在組織工作空間中進行 natural-language analytics（自然語言分析），而相關證據可能分散於資料庫、structured files（結構化檔案）、long documents（長文件）與 multimedia（多媒體）之中。現有基準測試大多將結構化查詢、檢索或開放式分析各自獨立處理，使得 heterogeneous evidence discovery（異質證據發現）、complete tabular outputs（完整表格輸出）與 deterministic evaluation（確定性評估）未能充分統合。我們提出 DataSpace，一個讓資料代理從各任務所屬的 heterogeneous workspaces（異質工作空間）中產出 verifiable tabular results（可驗證表格結果）的基準測試。其包含 410 項 cross-language tasks（跨語言任務）與 7,439 個 artifacts（資料物件），總計 15.01 GB，涵蓋 CSV、JSON、SQLite、Markdown、PDF 與 video（影片）格式。DataSpace 亦擔任 KDD Cup 2026 Data Agents for Complex Data Analysis（複雜資料分析資料代理）競賽的官方評估基準。每個代理僅接收問題與工作空間，並回傳所要求的完整表格結果。我們以 DataSpace-Builder 建構 DataSpace，這是一個 execution-grounded framework（基於執行的框架），包含 cross-language transformation（跨語言轉換）、constraint-aware relational sampling（約束感知關聯式取樣）、modality routing（模態路由）與 artifact rendering（資料物件渲染），並由 11 位 domain experts（領域專家）進行 human review（人工審查）與 task repair（任務修復）。Deterministic evaluator（確定性評估器）執行 header-invariant column alignment（表頭不變欄位對齊）、type- and precision-aware normalization（型別與精度感知正規化），以及 order-aware row comparison（順序感知列比較）。在六個近期發布的 frontier multimodal models（前沿多模態模型）與五個廣泛使用的 agent harnesses（代理框架）上，最佳 accuracy（準確率）達到 66.34%，而在固定 backbone（骨幹模型）的情況下，框架選擇會造成 15.36 個百分點的差距。Multimodal evidence integration（多模態證據整合）與 joins（Join 操作）在所有六個骨幹模型上均一致降低準確率。這些結果顯示 DataSpace 仍有提升空間，並指出改善資料代理可靠性的關鍵挑戰。

### 核心貢獻（3～5點）
- 提出 DataSpace 基準測試，統合異質工作空間中的可驗證表格分析，填補現有基準在異質證據發現、完整表格輸出與確定性評估方面的缺口。
- 設計 DataSpace-Builder 建構框架，透過跨語言轉換、約束感知關聯式取樣、模態路由與資料物件渲染，並結合領域專家的人工審查與任務修復，確保任務品質。
- 建立確定性評估器，支援表頭不變欄位對齊、型別與精度感知正規化與順序感知列比較，實現不依賴模型判斷的客觀評分。
- 對六個前沿多模態模型與五個代理框架進行大規模評測，揭示框架選擇、多模態證據整合與 Join 操作對資料代理準確率的影響。

### 適合對象
從事資料代理、自然語言驅動資料分析、異質資料整合與多模態推理研究的學者與工程師；特別適合關注基準測試設計、可驗證評估方法，以及希望將研究成果應用於企業級複雜資料分析場景的研究人員。

## 深度分析

#### 方法論解析

DataSpace 的核心設計可從「任務介面（task interface）」與「建構流程」兩條主軸理解。在任務層級，一個資料代理（data agent）只收到自然語言問題與一個任務本地化的異質工作空間（heterogeneous workspace），必須自主探索、選擇工具、對齊跨模態資訊，最後回傳一張完整的表格結果（complete tabular result）。這張結果以 CSV 序列化，評估時再與參考答案進行確定性比對。這樣的設計把「工作空間求解器（workspace solver）」的角色具體化：代理不只要做單一查詢或檢索，而是要在多種資料物件（artifacts）之間完成證據發現（evidence discovery）、多步運算與結果彙整。

為了系統化產生這類任務，作者提出 DataSpace-Builder，一個基於執行的框架（execution-grounded framework），包含四個階段：

1. **跨語言轉換（Cross-Language Transformation）**  
   原始素材來自 EHRSQL 與 BULL 這兩個英文 Text-to-SQL 基準，分別涵蓋臨床與金融分析。DataSpace-Builder 將問題、資料庫綱要（schema）與資料內容轉換為中英夾雜的跨語言任務（cross-language tasks），使問題與工作空間中的資料物件可能同時出現中文與英文。這強迫代理必須具備跨語言語意對齊能力，而不能單純依賴英文欄位名稱或問題關鍵字直接對應。

2. **約束感知關聯式取樣（Constraint-Aware Relational Sampling）**  
   從原始關聯式資料庫中取出子集時，框架會保留外鍵、函數相依與業務邏輯等約束，確保取樣後的工作空間仍然具備可執行的分析路徑。這一步是讓「可執行 SQL（executable SQL）」能夠轉譯為異質工作空間的基礎：原始查詢邏輯被保留，但資料被重新分佈到不同模態的資料物件中。

3. **模態路由與資料物件渲染（Modality Routing & Artifact Rendering）**  
   同一筆關聯式資料會被路由到 CSV、JSON、SQLite、Markdown、PDF 與 Video 等不同模態。例如，某些表格保留為結構化檔案（structured files），某些紀錄被渲染成長文件（long documents）或影片（video）。這裡的「渲染」並非單純格式轉換，而是模擬真實組織工作空間中「同樣資訊以不同形式散落」的狀況，因此代理必須根據問題主動決定要讀取哪些模態、如何從 PDF 或影片中抽取結構化紀錄。

4. **人工審查與任務修復（Human Review & Task Repair）**  
   由 11 位領域專家（domain experts）對產生的問題、工作空間、參考答案與評估語意進行交叉審查；有爭議的樣本會被討論並修復。這個階段彌補了自動轉換可能造成的語意漂移，也確保每個任務都有明確且可執行的參考答案。

在評估端，DataSpace 提供一個確定性評估器（deterministic evaluator），其設計對應真實分析中「等價表示應被接受」的需求。它包含三個機制：

- **表頭不變欄位對齊（Header-Invariant Column Alignment）**：比對時不受欄位名稱措辭或順序影響，因此代理輸出的 `patient_id` 與參考答案的 `患者編號` 可被視為同一欄。
- **型別與精度感知正規化（Type- and Precision-Aware Normalization）**：針對數值、日期、貨幣等型別進行統一正規化，並依任務需求容許特定精度差異。
- **順序感知列比較（Order-Aware Row Comparison）**：評估配置檔會記錄每個參考欄位的語意型別以及「列順序是否重要」，從而在需要時進行排序無關比對，在順序有意義時嚴格檢查。

整體而言，DataSpace 的方法論把「可驗證分析（verifiable analytics）」從「產生一段可能正確的 SQL」提升為「在異質工作空間中產生可被確定比對的完整表格輸出（tabular outputs）」。這種執行導向（execution-grounded）的建構方式，讓每個任務的參考答案都能透過實際執行取得，從而避免 LLM judge 的主觀性，也確保評估是無模型（model-free）的。

#### 實驗數據解讀

作者在 DataSpace 上測試了六個近期釋出的前沿多模態模型（frontier multimodal models）與五個常用的代理框架（agent harnesses）。實驗結果可歸納為三個重點：

1. **整體準確率（accuracy）仍有顯著提升空間**  
   最佳組合僅達到 **66.34%** 的準確率。這表示即使使用當前最強的多模態骨幹模型（backbone）與經過設計的代理框架，仍有超過三分之一的任務無法正確完成。對於一個強調確定性評估、且參考答案明確的基準而言，這個數字說明 DataSpace 並未飽和，確實能區分出不同系統的能力差距。

2. **代理框架（harness）的選擇影響巨大**  
   在固定骨幹模型的情況下，不同代理框架之間造成 **15.36 個百分點** 的準確率差距。這個現象凸顯：在異質工作空間中，「如何組織工具呼叫、記憶體管理與多步推理」與「使用哪個基礎模型」同樣重要。換句話說，資料代理（data agents）的瓶頸不只在於感知或語言理解，更在於工作空間求解器（workspace solver）層面的規劃與執行策略。

3. **多模態證據整合（multimodal evidence integration）與 Join 操作一致性地降低表現**  
   實驗發現，當任務需要整合來自不同模態的證據，或需要執行關聯式 Join 操作時，所有六個骨幹模型的準確率都會下降。這兩項能力恰好是 DataSpace 與傳統 Text-to-SQL 基準最大的差異所在：傳統基準通常提供單一資料庫與預先對齊的綱要，而 DataSpace 要求代理先從 PDF、影片、Markdown 等非結構化或半結構化資料物件中抽取紀錄，再與 CSV/JSON/SQLite 進行 Join。結果顯示，目前的模型在「跨模態綱要對齊」與「結構化連接推理」上仍顯脆弱。

綜合來看，66.34% 的天花板與 15.36 點的框架差距，意味著 DataSpace 成功地把「異質工作空間中的可驗證分析」塑造成一個有挑戰性的研究問題。實驗也指出兩個具體的改進方向：一是強化多模態資料物件的解析與紀錄抽取（特別是 PDF 與 Video），二是提升代理在發現相關資料來源後執行正確 Join 與彙整的能力。

#### 與現有研究的比較

DataSpace 在現有文獻中的定位，可透過 Table 1 的對照清楚看出。現有基準大多只覆蓋異質工作空間中的部分面向：

- **結構化資料基準**（如 Spider、BIRD、Spider2.0）強調關聯式推理（relational reasoning）與可執行 SQL，但通常預先指定相關表格或資料庫，較少涉及資料發現與跨檔案整合。
- **非結構化資料基準**（如 HotpotQA、CRAG、MMLongBench-Doc）聚焦檢索、多文件推理與長文件理解，但答案形式多為事實片段、選項或自由文本，不要求完整的表格輸出。
- **資料代理基準**（如 DABStep、KramaBench、LongDA、DataCross、FDABench）進一步納入多步分析與多種資料來源，但在「工作空間範圍（workspace scope）」、「輸出契約（output contract）」與「評估語意（evaluation semantics）」三個維度上仍未統一。

相較之下，DataSpace 同時滿足以下三個核心性質：

- **L1 Workspace scope**：每個任務都包含資料庫、結構化檔案、長文件與多媒體（影片），並且問題與資料物件跨中英語言。
- **L2 Output contract**：統一要求「完整表格結果」，而非片段答案、SQL 查詢或開放式報告。
- **L3 Evaluation semantics**：採用確定性評估（deterministic evaluation），接受等價表示但拒絕不完整或錯誤輸出，且不依賴 LLM judge。

這三點使 DataSpace 比 FDABench 等更貼近「真實組織工作空間」的設定：使用者不會先告訴代理答案在哪個檔案，也不會接受一段無法驗證的自然語言回覆。

然而，DataSpace 也存在一些相對限制：

- **規模與領域**：410 個任務在數量上遠小於 Spider、BIRD 或 HotpotQA；且原始素材來自臨床與金融兩個領域，領域廣度有限。
- **模態覆蓋**：雖然號稱多媒體，目前主要強調影片（video），未涵蓋音訊或其他感測器資料。
- **輸出形式**：嚴格的表格輸出雖然可驗證，但也排除了某些合理的分析回覆形式（例如摘要、視覺化圖表或機率區間），未來若要擴展到更廣泛的自然語言分析，評估器需要額外設計。
- **靜態工作空間**：每個任務的工作空間是固定的，尚未引入動態更新、資料版本差異或互動式澄清（clarification）等真實場景。

儘管如此，DataSpace 在「統一異質工作空間、完整表格輸出、確定性無模型評估」這三個維度上，確實填補了既有基準之間的缺口。

#### 可重現性評估

DataSpace 在可重現性（reproducibility）方面的表現相當積極。作者已公開：

- **程式碼**：`https://github.com/HKUSTDial/DataSpace`
- **資料集**：`https://huggingface.co/datasets/HKUSTDial/DataSpace`

這兩個資源讓研究者可以取得完整的 410 個跨語言任務、7,439 個資料物件（總計約 15.01 GB）以及對應的參考答案。由於評估器是確定性（deterministic）且無模型（model-free）的，任何團隊都能以相同規則重現準確率（accuracy）分數，這大幅降低了因評判模型差異造成的重現障礙。

此外，DataSpace 已被選為 **KDD Cup 2026 Data Agents for Complex Data Analysis** 的官方評估基準，這代表競賽期間會有標準化的提交與評分流程，進一步強化其可重現性與社群採用度。

需要注意的限制包括：

- **建構過程中的專有模型依賴**：DataSpace-Builder 的某些階段（如跨語言轉換、資料物件渲染）可能仰賴大型語言模型或多模態模型，若原始建構腳本未完全釋出或需要特定 API 金鑰，則從頭重建整個資料集會有門檻。
- **骨幹模型與框架的封閉性**：實驗中的六個前沿多模態模型與五個代理框架，部分可能是商業 API（如 GPT-4V、Gemini 等），模型權重並未公開。因此雖然基準本身可重現，但要完全複製某個特定模型的分數，仍需取得對應 API 或開源權重。
- **資料規模**：15 GB 的資料物件對於個人研究者或小型實驗室而言，儲存與運算成本不低，尤其是需要處理 PDF 與影片時。

整體而言，DataSpace 在「資料公開、評估透明、競賽標準化」三個層面都達到高水準的可重現性，是少數同時釋出程式碼與大規模異質資料的資料代理基準。

#### 未來研究方向

DataSpace 的實驗結果與設計揭示了多個值得後續探索的方向：

1. **強化多模態證據抽取**  
   目前 PDF 與影片（video）是主要瓶頸。未來可研究專門的視覺-文件編碼器、影片時間軸對齊技術，以及能從非結構化資料中自動重建表格紀錄的模型。

2. **跨模態綱要對齊與 Join 推理**  
   當同一實體出現在不同模態且欄位名稱、格式各異時，代理需要具備綱要不變（schema-invariant）的對齊能力。可發展基於嵌入相似度、欄位型別推論與外部知識的動態 Join 規劃方法。

3. **更智慧的代理框架（agent harnesses）設計**  
   實驗顯示 harness 選擇可造成 15.36 點差距，因此如何設計具備自我驗證、錯誤回溯與工具學習（tool learning）能力的代理框架，將是提升可靠性的關鍵。

4. **擴展任務規模與領域**  
   從 410 個任務擴展到數千甚至數萬個，並涵蓋更多領域（如法律、製造、科學資料），可進一步測試代理的泛化能力。

5. **動態與互動式工作空間**  
   真實組織資料會持續更新，使用者也可能在分析過程中澄清需求。未來可設計支援資料版本、增量更新與人機協作的動態 DataSpace 變體。

6. **評估語意的擴展**  
   在保留確定性評估（deterministic evaluation）的前提下，探索如何接受視覺化輸出、機率預測、區間估計或自然語言摘要，使基準更貼近真實分析場景。

7. **跨語言與低資源語言遷移**  
   目前以中英為主，未來可加入日語、西班牙語、阿拉伯語等，測試代理在語言分佈偏移下的穩健性。

8. **對抗雜訊與干擾資料物件的魯棒性**  
   真實工作空間常包含大量無關檔案。可設計更具挑戰性的變體，增加無效但看似相關的資料物件，測試代理的資料發現與篩選能力。

9. **結合程式碼生成與檢索的混合代理**  
   未來代理可同時使用 SQL、Python、視覺模型與文件檢索，並在執行過程中根據中間結果動態調整計畫，類似於可執行的資料科學管線。

10. **效率與可擴展性**  
    面對 15 GB 甚至更大的工作空間，如何在有限上下文長度與運算成本下完成分析，是部署到真實組織時不可迴避的議題。

總結來說，DataSpace 不僅提供了一個具挑戰性的評估場域，也明確指出「多模態證據整合」與「跨來源 Join 推理」是當前資料代理（data agents）最薄弱的環節。後續研究若能針對這兩個瓶頸提出可驗證的解決方案，將大幅提升資料代理在真實異質工作空間中的可靠性。

## 論文問答

**Q1：DataSpace 主要想解決什麼問題？**
A：DataSpace 針對的是資料代理在真實組織環境中進行自然語言分析時，必須把散佈於資料庫、結構化檔案、長文件與多媒體中的證據整合成可驗證表格結果的挑戰。現有基準大多只孤立地測試結構化查詢、檢索或開放式分析，缺乏對異質工作空間、完整表格輸出與確定性評估的統一檢驗。DataSpace 因此把資料代理視為工作空間求解器，要求它僅憑問題與工作空間自動探索來源、執行多步運算，並回傳使用者可直接使用的完整結果。

**Q2：為什麼現有的基準測試無法充分評估資料代理？**
A：結構化資料基準如 Spider 與 BIRD 雖然能測試關聯式推理，但通常預先指定了相關表格或資料庫，未涵蓋來源發現與跨檔案整合。非結構化基準如 HotpotQA 與 MMLongBench-Doc 則偏重證據檢索、多跳推理或長文件理解，答案多為片段事實或自由文本，不要求完整的表格輸出。現有的資料代理基準雖然更接近開放式分析，但仍未同時滿足工作空間範圍、輸出契約與評估語義這三項核心需求，因此無法真實反映組織分析場景。

**Q3：建立這樣的異質工作空間基準為什麼重要？**
A：在實際的企業分析中，使用者提出的問題往往橫跨多種語言與多種資料模態，相關證據並不會預先整理好。DataSpace 透過統一的表格輸出目標與確定性評估，讓研究者能客觀衡量代理程式是否真正「解決」了整個工作空間，而非僅產生看似合理的摘要。此外，DataSpace 已成為 KDD Cup 2026「複雜資料分析資料代理」競賽的官方評測基準，對推動可靠且可驗證的資料代理研究具有指標意義。

**Q4：DataSpace-Builder 的核心建構流程是什麼？**
A：DataSpace-Builder 是一個基於執行的框架，它把來自 EHRSQL 與 BULL 這兩個英文 Text-to-SQL 資源的問題、資料庫與查詢邏輯，轉換成跨語言、異質工作空間的任務。流程包含跨語言轉換、約束感知關聯式取樣、模態路由與資料物件渲染，以及由 11 位領域專家進行的人工審查與任務修復。由於原始 SQL 是可執行的，參考答案能透過實際執行取得，確保了結果的正確性與可驗證性。

**Q5：DataSpace 在評估設計上有哪些關鍵創新？**
A：DataSpace 的關鍵創新之一是提出「完整表格輸出」作為統一目標，無論工作空間包含 CSV、JSON、SQLite、Markdown、PDF 或影片，代理都必須回傳可直接比對的表格。另一項創新是確定性評估器，它採用表頭不變欄位對齊、型別與精度感知正規化，以及順序感知列比較，能容忍欄位名稱、格式或順序的等價變化，同時拒絕不完整或錯誤的輸出。這種評估方式不依賴大型語言模型評判，因此具有可重現與客觀的優點。

**Q6：為什麼作者選擇從 Text-to-SQL 資源出發來建構 DataSpace？**
A：EHRSQL 與 BULL 提供了臨床與財務領域的關聯式資料庫與可執行 SQL，這些查詢具備可解析的分析邏輯，並能透過執行產生確定的參考結果。以此為基礎，作者可以利用約束感知關聯式取樣產生符合領域語義的工作空間，再透過跨語言轉換與模態路由把表格資料渲染成 CSV、JSON、Markdown、PDF 或影片等不同形式。這種設計既保留了問題與答案的語義正確性，又人工製造了真實場景中證據散佈與格式異質的挑戰。

**Q7：實驗中測試了哪些模型與框架？主要結果為何？**
A：實驗評估了六個近期釋出的前沿多模態模型，並在五個廣泛使用的代理框架上進行測試。整體最佳準確率為 66.34%，顯示 DataSpace 尚未被現有模型飽和。值得注意的是，在固定骨幹模型的情況下，僅改變代理框架就會造成 15.36 個百分點的表現差距，說明框架設計對最終效能具有重大影響。

**Q8：哪些任務特性最會降低資料代理的準確率？**
A：實驗發現，需要整合多模態證據的任務以及涉及 Join 操作的任務，會在所有六個骨幹模型上一致地降低準確率。這表示代理在把影片、PDF 或長文件中的資訊與結構化資料表連結時，容易出現來源選擇、欄位對齊或值抽取的錯誤。Join 操作則進一步考驗代理是否能正確識別關聯鍵並維持結果的完整性與精度。

**Q9：從實驗結果可以得出什麼關於模型與框架相對重要性的結論？**
A：結果顯示，即使使用相同的骨幹模型，不同代理框架之間仍存在高達 15.36 分的差距，這意味著工具編排、記憶體管理與行動規劃等框架層設計與模型能力同樣關鍵。此外，多模態證據整合與 Join 操作對所有模型都構成一致困難，指出這些並非單一模型問題，而是整體工作空間求解能力的瓶頸。因此，未來研究應同時強化骨幹模型的多模態理解與代理框架的異質資料協調能力。

**Q10：DataSpace 所模擬的實際應用場景有哪些？**
A：DataSpace 模擬的是企業分析師面對的日常工作空間，例如同時存在 CSV 銷售日誌、SQLite ERP 資料庫、PDF 合約、Markdown 報告與產品教學影片。使用者只需以自然語言提問，資料代理就必須自動發現相關資料物件、從不同模態抽取所需記錄，並產生完整的表格答案。這類場景常見於財務稽核、臨床研究、供應鏈分析與客戶關係管理等需要跨來源整合證據的領域。

**Q11：若要把 DataSpace 的能力落地到產品，需要考慮哪些設計要點？**
A：產品化時必須確保代理具備穩定的工具使用能力，能根據模態自動路由到適當的解析器、檢索器或計算工具。同時需要支援跨語言問題與資料物件，並在輸出端提供完整表格而非僅有摘要，以便使用者直接驗證與下載。此外，採用類似 DataSpace 的確定性評估器可協助產品團隊在開發與測試階段客觀定位錯誤來源，例如欄位對齊、數值精度或列順序問題。

**Q12：DataSpace 對資料代理研究領域可能帶來什麼影響？**
A：DataSpace 提供了一個統一且嚴謹的基準，讓研究者能在相同條件下比較不同模型與框架在異質工作空間上的真實能力。由於它已成為 KDD Cup 2026 的官方競賽基準，預期將吸引大量研究投入，加速資料代理從示範走向可靠應用。其強調的可驗證表格輸出與確定性評估，也有助於建立更客觀、可重現的評測文化。

**Q13：DataSpace 有哪些已知的限制？**
A：DataSpace 目前包含 410 個任務，規模相對有限，且主要衍生自 EHRSQL 與 BULL 這兩個臨床與財務領域的英文 Text-to-SQL 資源，領域覆蓋仍有擴展空間。資料模態雖然涵蓋 CSV、JSON、SQLite、Markdown、PDF 與影片，但尚未納入音訊等更多模態，跨語言部分也集中於中英雙語。此外，最佳準確率僅 66.34%，雖顯示挑戰性，但也反映現有方法在複雜異質工作空間上仍不夠穩健。

**Q14：從實驗結果推測，資料代理最容易在哪些情況下失敗？**
A：代理最容易在需要把非結構化或多模態證據轉換成結構化記錄時失敗，例如從影片或 PDF 中抽取數值並與資料庫表格進行 Join。常見錯誤包括選錯資料物件、無法對齊不同來源的欄位語義、忽略數值精度或單位轉換，以及未正確處理列順序是否重要。框架設計不良也會導致同樣骨幹模型出現顯著效能落差，顯示工具編排與錯誤恢復機制仍是關鍵弱點。

**Q15：未來研究可以朝哪些方向改進 DataSpace 與資料代理？**
A：未來可擴充更多領域、語言與模態，例如加入音訊、3D 資料或更多東亞語言，以提升基準的多樣性與真實性。同時需要發展更強大的模態路由、跨模態對齊與可解釋的規劃機制，讓代理能清楚說明每個表格值來自哪些資料物件與運算步驟。最後，結合確定性評估與人機協同驗證，將有助於建立既客觀又具透明度的資料代理開發與部署流程。

## 實務應用指南

### 適用場景

1. **跨部門財務與營運分析**：企業內部常同時存在 ERP 匯出的 CSV、財務系統的 SQLite、會計準則 PDF 與會議影片。資料代理可在單一異質工作空間中，根據自然語言問題自動發現、連結並產出可驗證的完整表格，例如「比較 Q1-Q3 各事業部營收與預算差異」。

2. **臨床醫療數據整合查詢**：醫院資訊分散於結構化電子病歷資料庫、檢驗報告 PDF、醫囑 Markdown 與教學影片。醫師或研究者可透過自然語言詢問「列出近半年符合某適應症且用過特定藥物的患者檢驗趨勢」，由代理自動完成跨模態證據整合與表格輸出。

3. **法規遵循與稽核報告**：金融機構需比對交易資料庫、客戶盡職調查文件、法規條文長文件與內部培訓影片。資料代理可協助稽核人員產出「高風險客戶交易與 KYC 文件一致性」的完整結果表，並以確定性評估驗證。

4. **供應鏈與物流異常排查**：物流資料常見於 JSON 追蹤檔、倉儲 SQLite、運輸合約 PDF 與現場監控影片。營運團隊可詢問「上週延遲交貨訂單及其對應倉儲與運輸狀態」，由代理自動 join 多來源證據並回傳可執行驗證的表格。

5. **學術與產業研究資料彙整**：研究團隊面對問卷 CSV、實驗記錄 JSON、論文 PDF 與實驗影片。資料代理可根據研究問題自動抽取、對齊欄位並產出完整分析表，減少人工整理與格式轉換成本。

### 實作前置條件

- **資料準備**：需具備任務層級的異質工作空間，至少包含兩種以上模態，例如 CSV/JSON/SQLite 等結構化檔案、Markdown/PDF 長文件，以及影片。每個任務需有對應的自然語言問題與可執行驗證的參考表格答案。
- **運算資源**：多模態骨幹模型與代理框架需要 GPU 推論資源，建議至少具備可執行 frontier multimodal models 的環境；若涉及影片處理，需額外配置影片解碼與嵌入運算資源。資料空間總量可能達數 GB 至數十 GB，需足夠儲存與 I/O 頻寬。
- **技術能力**：團隊需熟悉 Text-to-SQL、關聯式資料庫綱要、資料正規化、多模態模型推論，以及代理框架的 tool-use 設計。建議至少有一名具備領域知識的專家負責人工審查與任務修復。

### 實作步驟建議

1. **定義輸出契約與評估語義**：先決定每個任務必須產出「完整表格」而非片段事實或開放式報告，並設計確定性評估器，支援表頭不變欄位對齊、型別與精度感知正規化，以及順序感知列比較。

2. **蒐集與清理來源資料**：從現有結構化資料庫與文件開始，將問題、資料庫與可執行 SQL 邏輯整理成標準格式。可參考 DataSpace-Builder 以 EHRSQL、BULL 等 Text-to-SQL 資源作為起點。

3. **跨語言與異質轉換**：使用 Cross-Language Transformation 將問題與資料物件轉換為目標語言組合；透過 Constraint-Aware Relational Sampling 產生符合領域約束的樣本，避免洩漏答案或產生不可執行的查詢。

4. **模態路由與資料物件渲染**：建立 Modality Routing 模組，依據 CSV、JSON、SQLite、Markdown、PDF、Video 等格式決定處理路徑，並將各資料物件渲染為模型可理解的輸入形式，例如將 PDF 轉為結構化文字、影片轉為關鍵影格與字幕。

5. **專家審查與任務修復**：由領域專家進行人工審查，針對問題歧義、資料遺漏、參考答案錯誤等進行 Task Repair，並在釋出前達成共識。

6. **選擇骨幹模型與代理框架**：根據任務需求選擇多模態骨幹模型，並搭配適當的 Agent Harness。實證顯示，在固定骨幹模型下，框架選擇可造成超過 15 個百分點的準確率差異，應針對 tool-use、記憶體管理與錯誤恢復機制進行比較。

7. **持續評估與迭代**：使用確定性評估器進行大規模測試，特別關注多模態證據整合與 join 操作，這兩類任務在所有骨幹模型上均一致降低準確率，應作為優先改進項目。

### 潛在風險與注意事項

- **表格完整性不足**：代理可能只回傳部分欄位或遺漏列，導致評估失敗。可透過明確的輸出契約與後處理檢查，要求代理在終止前驗證結果是否涵蓋所有必要欄位與列。
- **跨模態對齊錯誤**：PDF 表格與資料庫欄位名稱不一致、影片時間戳與事件記錄錯位，容易導致 join 錯誤。建議引入 schema-invariant 對齊機制與領域專家標註的對照表。
- **數值精度與格式問題**：不同資料來源對日期、貨幣、單位的表示方式不同，可能使正確答案被誤判為錯誤。評估器必須支援型別與精度感知正規化，並在任務配置中明確比較規則。
- **語言混合造成的理解偏差**：問題與工作空間使用不同語言時，模型可能誤解欄位語義。建議在訓練與提示中強化跨語言對應，並保留雙語欄位對照。
- **過度依賴模型判斷**：避免使用 LLM judge 作為主要評估方式，應以可執行查詢與確定性規則為主，確保結果可重現、可驗證。

### 與其他技術的整合建議

- **與資料湖 / 資料倉儲整合**：可將 DataSpace 的任務介面視為資料湖上的一層自然語言查詢層，透過統一中繼資料目錄描述各資料物件的位置、格式與語義，再由代理進行來源發現與選擇。
- **與 RAG 與文件解析管線整合**：針對 PDF 與 Markdown 長文件，可結合現有文件解析、版面分析與檢索增強生成技術，先將文件轉為結構化記錄，再餵入代理進行下游分析。
- **與 BI / 視覺化工具整合**：代理產出的 CSV 表格可直接匯入 Tableau、Power BI 或自製儀表板，形成「自然語言提問 → 自動資料整合 → 可驗證表格 → 視覺化呈現」的完整流程。
- **與 MLOps / 評估平台整合**：將確定性評估器嵌入 CI/CD 流程，對每次模型或框架更新進行回歸測試，並追蹤多模態證據整合與 join 任務的準確率變化。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先從「適用場景」與「實作前置條件」開始，理解資料代理與傳統問答系統的差異，再透過 glossary 掌握跨語言、異質工作空間、確定性評估等核心概念，最後參考實作步驟建立一個小型 CSV + PDF 的雙模態原型。

- **AI 工程師**：重點閱讀 DataSpace-Builder 的四個階段與確定性評估器設計，深入分析不同骨幹模型與代理框架的表現差異，並在實作中特別處理 header-invariant column alignment、type- and precision-aware normalization、order-aware row comparison 等技術細節。

- **研究人員**：建議聚焦於論文對現有基準的比較與三個核心性質（workspace scope、output contract、evaluation semantics），思考如何將 DataSpace 的設計原則延伸至其他領域，並針對多模態證據整合與 join 操作帶來的準確率下降進行機理性分析。

- **產品經理**：建議從適用場景與風險注意事項切入，評估資料代理在自身業務中的落地價值與限制，並將「完整表格輸出」與「確定性評估」作為產品可信度與可解釋性的核心賣點，同時預留專家審查與任務修復的人工作業流程。
