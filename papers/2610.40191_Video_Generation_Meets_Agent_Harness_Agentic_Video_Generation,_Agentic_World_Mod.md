## 摘要翻譯

影片生成（Video Generation）正從端到端合成（End-to-End Synthesis）轉向代理式生成，其中規劃（Planning）、工具使用（Tool Use）與回饋（Feedback）使一致性（Coherent）、可控（Controllable）的多鏡頭影片（Multi-shot Video）成為可能。與此同時，影片世界模型（World Model）提供動作條件觀察（Action-Conditioned Observation）與預測未來（Predicted Future），作為代理的互動式環境（Interactive Environment）。我們透過代理執行框架（Agent Harness）研究其交集：這是一個可執行執行環境（Executable Runtime），能建構上下文（Context Construction）、提供工具、維護狀態（State Maintenance）、路由回饋（Feedback Routing），並管理影片模型的預算（Budget Management）。本報告探討三個方向。第一，代理式影片生成，其中執行框架協調腳本編寫（Scripting）、鏡頭規劃（Shot Planning）、資產管理（Asset Management）、鏡頭製作（Shot Production）與剪輯後製（Editing and Post-Production），以及這些系統的評估挑戰（Evaluation Challenge）。第二，代理式世界建模，其中執行框架中介觀察（Observation）、控制（Control）、執行（Execution）與狀態。我們討論混合設計（Hybrid Design），其中遊戲引擎（Game Engine）或代理編寫程式（Agent-Written Program）維護顯式世界狀態（Explicit World State），而影片模型渲染（Render）觀察，以及代理與世界模型如何相互評估（Mutual Evaluation）並相互改進（Mutual Improvement）彼此。第三，影片模型開發中的遞迴自我改進（RSI），區分輸出修訂（Output Revision）、框架狀態（Harness State）更新、生成器參數（Generator Parameter）與評估器（Evaluator），以及改進程序（Improvement Procedure）本身的變更。我們分析這些改進如何回饋至後續開發。在這些方向中，我們分析核心代理能力，包括視聽感知（Audiovisual Perception）、長程規劃（Long-Horizon Planning）、終身記憶（Lifelong Memory）、基於程式碼的互動（Code-Based Interaction）、回饋引導控制（Feedback-Guided Control）、技能重用（Skill Reuse）與多代理協調（Multi-Agent Coordination）。我們總結多項挑戰，包括自主影片製作（Autonomous Video Production）、終身記憶、可程式化混合控制（Programmable Hybrid Control）、自主模型開發、來源追蹤（Provenance）、成本核算（Cost Accounting），以及如何透過評估將影片品質（Video Quality）與任務表現（Task Performance）連結至模型與框架的持續改進（Sustained Improvement）。

### 核心貢獻（3～5點）
- 提出以「代理執行框架」（Agent Harness）作為統一視角，串接代理式影片生成、代理式世界建模與遞迴自我改進三大研究方向，釐清影片生成從端到端合成走向代理式生成的典範轉移。

A：論文指出代理式影片生成面臨獨特的評估挑戰，因為這類系統涉及多個組件（規劃、工具使用、回饋路由）的協調，傳統的影片品質指標（如 FID、FVD）不足以捕捉敘事連貫性、跨鏡頭一致性或任務完成度。論文強調需要新的評估方法論，能夠連結影片品質和任務表現，並追蹤模型和框架的持續改進。這包括評估代理在長程規劃、錯誤恢復、資源預算管理等方面的能力，以及評估多代理協調的效率和效果，這些都是傳統影片生成基準所忽略的面向。

**Q8：在代理式世界建模中，評估面臨哪些特殊挑戰？**

A：代理式世界建模的評估需要同時考慮影片品質和互動品質兩個維度：影片品質涉及視覺真實性、時間一致性等傳統指標；互動品質則涉及動作條件觀察的準確性、預測未來的合理性、狀態轉移的可控性等，這使得評估更加複雜。論文強調代理和世界模型可以相互評估——代理的行為軌跡可以作為世界模型預測準確性的測試，世界模型的回應則可以評估代理決策的品質。這種雙向評估為傳統單向評估提供了補充，但也帶來了評估標準循環依賴的新問題。

**Q9：遞迴自我改進的評估如何不同於傳統模型評估？**

A：遞迴自我改進的評估需要追蹤改進程序本身的演化，而不僅僅是模型輸品的品質，這要求評估方法從靜態基準測試轉向動態的長期追蹤。論文指出需要區分不同層次的改進是否真正帶來持續改進——修訂當前輸出不等於改進未來能力，因此評估需要追蹤框架狀態、生成器參數和評估器隨時間的變化，並驗證這些變化是否帶來可測量的下游改進。這種元層次的評估比傳統的基準測試更為複雜，需要長期追蹤、因果分析和對改進程序本身的反思能力。

**Q10：代理式影片生成有哪些實際應用場景？**

A：代理式影片生成適用於需要多鏡頭協調的複雜影片製作任務，例如電影預告片、廣告製作、教學影片和遊戲過場動畫，在這些場景中，創意簡報需要被分解為腳本編寫、鏡頭規劃、資產管理、鏡頭製作和剪輯等多個階段，每個階段都需要根據前一階段的結果進行調整。代理執行框架能夠自動化這些協調工作，使創作者能專注於高層次的創意決策，同時確保跨場景的一致性和敘事連貫性。此外，在需要快速迭代的場景（如社群媒體內容、即時新聞視覺化）中，代理式系統能夠顯著縮短從概念到成品的時間。

**Q11：在產品化代理式影片系統時需要考慮哪些因素？**

A：產品化需要考慮成本核算、權限管理、預算控制和來源追蹤等多個面向，因為影片生成是計算密集型任務，代理執行框架需要有效管理 GPU 時間、API 呼叫次數和儲存成本，這對於商業可行性至關重要。浮水印和來源追蹤對於防止濫用和確保內容真實性至關重要，特別是在 deepfake 和虛假訊息日益嚴重的時代。此外，框架需要提供直觀的使用者介面，讓非技術用戶能夠指導代理完成複雜的影片任務，同時保留對關鍵決策的控制權，這需要在自動化和用戶主控權之間取得平衡。

**Q12：這項研究對影片生成和 AI 代理領域的影響是什麼？**

A：這項研究將影片生成從單純的模型層面提升到系統層面，強調代理執行框架作為連接模型能力和實際任務的關鍵中介，這種視角轉變可能重塑整個領域的研究方向。對 AI 代理領域而言，它展示了如何將規劃、工具使用、回饋路由等通用代理能力應用於影片這個特定領域，提供了代理能力評估的具體場景。對影片生成領域而言，它提供了一個超越端到端合成的視角，引入了遞迴自我改進的概念，使系統能夠從經驗中持續學習和改進，這種跨領域的整合可能催生新的研究方向和應用模式。

**Q13：論文承認這項研究有哪些局限性？**

A：論文坦誠地指出多個開放挑戰：完全端到端的影片製作仍難以實現，現有系統在長程規劃和終身記憶方面存在不足，難以處理需要跨多個會話累積經驗的任務；混合程式碼-像素生成需要更精細的協調機制，目前在程式碼控制和像素渲染之間的切換還不夠流暢；無人類自主開發面臨安全性和可靠性問題，特別是在錯誤可能導致嚴重後果的場景中；效率問題（特別是大規模影片生成的計算成本）尚未解決，這限制了系統的可擴展性；來源追蹤和安全問題需要新的技術方案；新興任務（如即時互動影片、沉浸式敘事）的評估方法論尚未成熟。

**Q14：這項方法在哪些情況下可能失敗？**

A：這項方法可能在以下情況下遇到困難：當創意需求極為抽象或模糊時，代理可能難以將其轉化為可執行的鏡頭規劃，導致生成的內容偏離用戶期望；當影片需要高度專業的藝術風格或技術細節時，現有的影片模型可能無法滿足品質要求，代理的迭代改進也無法彌補底層模型的限制；當任務需要極長的時間跨度（如系列劇集）時，終身記憶機制可能不足以維持一致性，導致角色或場景細節的漂移；當多個代理需要協調時，通訊和決策衝突可能導致效率低下或產生不一致的結果；當評估標準本身存在爭議時（如藝術品質），自動化改進可能偏離人類期望的軌道。

**Q15：論文的未來研究方向是什麼？**

A：論文提出了多個未來方向：完全端到端的影片製作（從創意簡報到最終成品的全流程自動化，減少人工介入）；終身記憶機制（使代理能夠跨任務累積經驗和知識，實現真正的持續學習）；可程式化混合控制（更靈活地結合程式碼和像素生成，允許用戶精確控制影片的特定方面）；無人類自主開發（減少對人類監督的依賴，使系統能夠獨立進行模型改進）；效率提升（降低計算成本和延遲，使系統更加實用）；來源追蹤和安全（防止濫用和確保內容真實性）；新興任務（如即時互動影片、沉浸式敘事、個性化內容生成）。這些方向需要學術界和工業界的共同努力，結合影片生成、代理技術、強化學習等多個領域的進展，才能真正實現代理式影片系統的願景。

## 實務應用指南

### 適用場景

**1. 自動化短影音行銷內容生產**
電商與社群媒體團隊每日需產出數十支 15–60 秒的產品短影片。代理式影片生成系統可接收文案 brief，自動拆解為多鏡頭腳本、調用參考資產、生成鏡頭、檢查品牌一致性並完成剪輯與字幕，大幅降低人力成本。

**2. 互動式敘事遊戲與 NPC 對話影片**
遊戲敘事需要根據玩家選擇即時生成對應的過場影片。代理式世界建模讓遊戲引擎維護顯式世界狀態，影片模型負責渲染觀察幀，代理中介處理動作輸入與狀態轉移，實現「選擇→動作→新影片片段」的閉環。

**3. 電影預告片與廣告快速原型設計**
廣告代理商可在正式拍攝前，用代理系統快速生成多版預告片原型。代理負責腳本分鏡、視覺風格探索、A/B 版本比較與觀眾反應模擬，協助創意團隊在數小時內完成原本需數週的提案。

**4. 工業與醫療教育訓練模擬影片**
製造商或醫療機構需要大量情境式訓練影片（設備操作、緊急應變）。代理系統可根據訓練目標自動生成場景、注入故障情境、產出多語言旁白版本，並依據學員表現動態調整後續影片難度。

**5. 虛擬試穿／試駕等個人化電商影片**
零售平台可讓消費者輸入偏好（身形、車款、場景），代理即時生成個人化展示影片。代理需管理個人資料、維持產品一致性、處理長時序連貫性，並在預算內完成生成。

### 實作前置條件

**資料需求**
- 領域影片資料集：用於微調或檢索增強生成（RAG），建議至少數千段已標註鏡頭的影片
- 參考資產庫：角色、場景、產品、風格指南等結構化資產
- 腳本與分鏡範例：用於訓練代理的規劃能力
- 評估資料集：含人工標註的影片品質、一致性、任務達成度資料

**運算資源**
- 影片生成模型推理：單次生成需數分鐘至數小時，建議配置 A100/H100 等級 GPU 或呼叫雲端 API
- 代理 LLM：中等規模開源模型（如 70B 參數）或商用 API
- 儲存與傳輸：影片檔案龐大，需高效能物件儲存與 CDN
- 預算控制：每次生成成本需明確計價並設上限

**技能門檻**
- LLM 代理開發：熟悉 ReAct、規劃、工具呼叫、記憶架構
- 影片生成模型：理解擴散模型、條件控制、影片編解碼
- 框架工程：能設計可執行的代理執行環境，包含上下文建構、工具暴露、狀態維護、回饋路由、預算管理
- 評估設計：能建立連結影片品質與任務表現的指標體系
- 領域知識：依場景需具備行銷、遊戲、電影或工業領域專業

### 實作步驟建議

**步驟 1：定義任務邊界與評估指標**
從單一、可控的場景出發（例如「生成 30 秒產品短片」），明確定義輸入（brief、參考）、輸出（影片檔案）、成功條件（品牌一致、訊息傳達、視覺品質）。建立量化指標，避免僅依賴單一品質分數。

**步驟 2：建構最小可行代理執行框架**
實作一個可執行 runtime，包含：上下文建構器（注入 brief、參考、過往決策）、工具暴露層（呼叫影片生成、剪輯、資產檢索）、狀態維護（鏡頭清單、版本歷史）、回饋路由器（將檢測結果送回規劃模組）、預算管理器（追蹤成本與時間）。

**步驟 3：整合影片生成模型作為工具**
將影片生成模型封裝為工具，而非直接由代理端到端控制。代理透過工具呼叫介面請求生成，並接收結構化回傳（影片、潛在空間、條件資訊）。保留模型架構彈性，便於日後替換。

**步驟 4：設計腳本與鏡頭規劃模組**
代理先將 brief 拆解為鏡頭序列，每個鏡頭包含：動作描述、視覺風格、參考資產、生成參數。規劃需考慮長時序一致性，引用先前鏡頭的關鍵幀或潛在特徵作為條件。

**步驟 5：實作資產管理與版本控制**
建立結構化資產庫，代理可查詢、組合、引用資產。每次生成記錄完整 provenance（輸入、模型版本、參數、隨機性），支援後續重現、除錯與稽核。

**步驟 6：建立回饋引導控制迴路**
實作自動檢測器（畫面穩定性、物件一致性、品牌元素偵測）與人工回饋介面。代理根據回饋決定：重生成單一鏡頭、調整後續鏡頭條件、修改腳本。區分「輸出修訂」（當前影片）與「框架狀態更新」（後續任務）。

**步驟 7：引入技能重用與記憶**
代理從成功案例中抽取可重用技能（例如「處理玻璃反射」「維持角色服裝一致」），存入結構化記憶。後續任務優先檢索相關技能，而非從零規劃。

**步驟 8：邁向遞迴自我改進**
區分四個改進層次：輸出修訂、框架狀態、生成器參數、評估器；最終是改進程序本身。先從前兩層開始（成本低、風險小），逐步引入生成器微調與評估器更新，最後才考慮修改改進迴路本身。每次改動需有驗證閘門與回退機制。

**步驟 9：部署、監控與成本核算**
上線後持續監控：任務成功率、平均生成次數、成本分佈、失敗模式。定期檢視是否需要更新評估器或擴充技能庫。明確區分「影片品質」與「任務表現」指標，避免優化錯目標。

### 潛在風險與注意事項

**風險 1：成本失控**
影片生成單次成本高，代理若無嚴格預算管理，可能陷入反覆重生成的迴圈。
**緩解**：設定每任務硬性預算上限；實作早期停止條件；區分「必須重做」與「可接受瑕疵」。

**風險 2：長時序一致性崩潰**
多鏡頭影片中，角色外觀、場景細節容易在跨鏡頭時漂移。
**緩解**：使用顯式參考條件（關鍵幀、潛在特徵）；建立跨鏡頭一致性檢測；必要時退回單鏡頭獨立生成。

**風險 3：評估指標偏誤**
僅依賴影片品質分數（如 FID）會忽略任務達成度；僅依賴任務指標會忽略視覺瑕疵。
**緩解**：建立多維度評估體系，包含品質、一致性、品牌合規、任務達成；定期以人工抽樣校正。

**風險 4：混淆「輸出修訂」與「能力改進」**
修好一支影片不等於系統變好。若僅在輸出層修補，未將經驗抽象為可重用技能，下次任務仍會重蹈覆轍。
**緩解**：明確記錄每次修補的原因與解法，週期性抽取為技能；區分當前任務日誌與跨任務記憶。

**風險 5：遞迴自我改進的失控風險**
若允許系統修改自身的改進程序，可能產生難以預測的行為。
**緩解**：改進程序本身的修改需有最嚴格的驗證閘門；保留人類審查節點；設定不可修改的核心模組。

**風險 6：來源追蹤與法律風險**
生成影片可能涉及肖像權、著作權、品牌使用授權。
**緩解**：完整記錄 provenance；嵌入浮水印；建立資產使用授權資料庫；對高風險產出保留人類審查。

**風險 7：代理規劃與影片模型的介面落差**
代理以文字與結構化資料思考，影片模型以像素與潛在空間運作，兩者介面若設計不良會導致資訊流失。
**緩解**：設計豐富的條件介面（文字、影像、潛在特徵、骨架、深度圖）；保留中間表示供代理檢查。

### 與其他技術的整合建議

**與數位資產管理（DAM）系統整合**
代理框架應透過標準 API 與既有 DAM 對接，讀取品牌素材、產品圖檔、歷史影片。代理生成的影片與中間產物需回寫 DAM，建立可搜尋、可追溯的內容庫。

**與遊戲引擎整合（Unity / Unreal）**
在代理式世界建模場景中，遊戲引擎負責顯式世界狀態與物理模擬，影片模型負責渲染觀察。建議採用混合設計：引擎輸出低解析度狀態表示，影片模型據此生成高擬真觀察幀。代理透過引擎 API 執行動作，透過影片模型 API 取得觀察。

**與 CI/CD 與 MLOps 整合**
影片生成模型的版本管理、評估資料集、實驗記錄應納入 MLOps 流程。每次模型更新需自動觸發評估套件，並與代理框架的版本同步標記。

**與內容審核與浮水印系統整合**
所有生成影片應自動嵌入浮水印並送審。代理框架需將審核結果納入回饋迴路，違規產出觸發自動重生成或人工介入。

**與企業知識管理整合**
代理的長期記憶、技能庫、評估案例可與企業知識庫（如 Confluence、Notion）對接，使影片生成的經驗可被其他團隊檢索與審閱。

**與排程與專案管理工具整合**
代理任務可對接 Jira、Asana 等工具，將影片生成任務視為可追蹤的工作項目，包含成本、週期、失敗重試次數等欄位。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 章動機與第 2 章基礎概念，建立「影片生成模型」與「代理執行框架」是兩個不同層次的理解。影片模型負責合成像素，代理框架負責決策與協調。理解這個分工後，再進入第 3 章看一個具體的影片生產流程如何被代理拆解與執行，會比直接看技術細節更容易掌握全貌。

**給 AI 工程師**：重點閱讀第 2.2 節（代理與框架工程）、第 3 章（代理式影片生成的工具鏈設計）、第 5 章（遞迴自我改進的四個層次）。特別注意「框架介入統一觀點」一節，它提供了將不同影片任務抽象為統一介面的方法論。實作時應先建構框架，再逐步整合影片模型，而非反過來。

**給研究者**：第 4 章（代理式世界建模）與第 5 章（遞迴自我改進）是本報告最具研究深度的部分。建議特別關注「顯式世界狀態與生成式渲染的混合設計」以及「改進程序的自我修改」這兩個開放問題。第 6 章列出的基礎代理能力（視聽感知、長程規劃、終身記憶、基於程式碼的互動、回饋引導控制、技能重用、多代理協調）提供了清晰的研究議題地圖。

**給產品經理**：重點閱讀第 1 章（為何需要從端到端生成轉向代理式生成）、第 3 章各小節對應的產品功能（腳本規劃、資產管理、製作、剪輯、浮水印）、第 7 章（未來工作與挑戰）。理解「影片品質」與「任務表現」是兩個不同指標，有助於設定合理的產品 KPI。建議從單一垂直場景（如短影音行銷）切入驗證，再逐步擴展。
