# 釋放全雙工語音模型中大型語言模型（LLM）的能力

## ⚡ TL;DR

現有語音大型語言模型僅能口語輸出，壓抑了程式碼生成與結構化分析等原生文字能力。
本文提出「聽-寫-說」三通道典範，以詞元架構讓單一自迴歸模型同步聆聽、書寫可見文字並即時口語回應。
實驗顯示該模型在全雙工評測中表現優異，書寫與口語一致性達92.6%，且未犧牲即時回應能力。

## 摘要翻譯

以語音為基礎的大型語言模型（Large Language Model, LLM）通常僅能以口語回覆，使其面向使用者的輸出（user-facing outputs）受限於可被口語化的內容；在即時互動中，這類模型在需要持久、結構化且可檢視的中間輸出（persistent, structured, and inspectable intermediate outputs）的任務上，更會抑制諸如程式碼生成（code generation）、結構化分析（structured analysis）與多步驟推理等原生文字能力。現有研究改善了口語推理（spoken reasoning）或全雙工話輪轉換（full-duplex turn-taking），但仍將文字視為隱藏的中間狀態（hidden intermediate state）或從屬模態（subordinate modality），而非第一級輸出通道（first-class output channel）。我們提出聽-寫-說（Listen-Write-Speak, LWS），一種以文字優先的三通道典範（text-first tri-channel paradigm），其中單一自迴歸大型語言模型（autoregressive LLM）持續聆聽使用者音訊，書寫可見的自由格式文字作為其主要輸出（primary output），並在共享因果注意力脈絡（shared causal attention context）下平行說出即時口語回應（realtime oral response）。此行為完全透過詞元架構（Token Schema）實作，無需任何架構修改，並透過兩階段資料管線（two-stage data pipeline）學習，該管線合成的每秒認知標註（per-second cognitive annotations）與揭示的輸入時間軸（revealed input timeline）保持一致。實驗結果顯示，LWS 在 Full-Duplex-Bench 上展現強大的全雙工（full-duplex）互動，在 VoiceBench AlpacaEval 上達到 4.72 分，實現 92.6% 的書寫-口語一致性（writing-speaking consistency），並在 URO-Bench 上持續優於其內部消融變體。這些結果顯示，可見書寫（visible writing）可作為語音互動的第一級輸出通道（first-class output channel），同時不犧牲即時回應能力（realtime responsiveness）。程式碼與資料集可於專案頁面取得：https://royalzhang.com/project/lws-page/。

### 核心貢獻（3～5點）
- 提出聽-寫-說（LWS）以文字優先的三通道典範，將可見書寫提升為語音互動的第一級輸出通道，突破現有語音模型僅能以口語回覆的限制。
- 透過詞元架構（Token Schema）在單一自迴歸大型語言模型中實現持續聆聽、可見書寫與即時口語回應的平行運作，無需修改模型架構。
- 設計兩階段資料管線，藉由合成與揭示的輸入時間軸一致的每秒認知標註，使模型在共享因果注意力脈絡下學習全雙工行為。
- 在 Full-Duplex-Bench、VoiceBench AlpacaEval 與 URO-Bench 上驗證，達成強大的全雙工互動、92.6% 書寫-口語一致性與即時回應能力，證明可見文字輸出與即時語音回應可兼顧。

### 適合對象
從事多模態人機互動（HCI）、全雙工語音模型、語音對話系統與大型語言模型（LLM）應用之研究者與工程師，特別是關注如何將程式碼生成、結構化分析、數學推導與專業寫作等原生文字能力整合至即時語音互動場景的開發者與產品設計師。

## 深度分析

#### 方法論解析

LWS（Listen-Write-Speak，聽-寫-說）的核心在於提出一個 text-first tri-channel paradigm（以文字優先的三通道典範），將單一 autoregressive LLM（自迴歸大型語言模型）的行為同時展開為三條並行通道：Listening（聆聽）、visible writing（可見書寫）與 realtime oral response（即時口語回應）。這三條通道並非透過獨立模組或架構修改來實現，而是透過 Token Schema（詞元架構）在標準 Transformer 中以 special tokens 完成，這意味著模型本體無需任何架構變更即可支援 full-duplex（全雙工）行為。

在互動結構上，對話被切分為 temporal Units（時間單元）。在這些單元內，模型透過 shared causal attention context（共享因果注意力脈絡）同時處理三種行為：持續接收使用者音訊（Listening）、產生 user-facing outputs（面向使用者的輸出）中作為 primary output（主要輸出）的 visible text output（可見文字輸出）、以及並行生成語音（Speaking）。值得注意的是，visible writing（可見書寫）通道在聆聽階段與回覆階段皆保持活躍：在使用者說話時，模型可進行 cognition while listening (CL)（聆聽時認知，CL），將理解與推理過程即時外化為文字；在模型回覆時，則持續輸出結構化或自由形式的文字內容，同時以語音進行 realtime oral response（即時口語回應）。語音僅在 speaking Units（說話單元）中發出，而文字通道則貫穿全程。

為了訓練此一行為，作者設計了 two-stage data pipeline（兩階段資料管線）。該管線的關鍵在於合成 per-second cognitive annotations（每秒認知標註），這些標註必須與 revealed input timeline（揭示的輸入時間軸）保持因果一致（causally consistent）。換言之，模型在任何時間點所產生的文字，都只能基於截至該秒為止已揭露的輸入內容，而不能洩漏未來資訊。這種設計確保了 visible writing（可見書寫）並非事後補上的 hidden intermediate state（隱藏的中間狀態），而是與即時感知同步推進的 persistent, structured, and inspectable intermediate outputs（持久、結構化且可檢視的中間輸出）。

#### 實驗數據解讀

論文在四個維度上提供實證數據。首先，在 Full-Duplex-Bench 上，LWS（Listen-Write-Speak，聽-寫-說）展現出強勁的 full-duplex interaction（全雙工互動）能力，證明其能在持續聆聽的同時進行輸出，而不會退化成 half-duplex（半雙工）的回合制行為。其次，VoiceBench AlpacaEval 達到 4.72 分，顯示模型在將 text-native systems（原生文字系統）的能力——如 code generation（程式碼生成）、structured analysis（結構化分析）與 mathematical derivation（數學推導）——釋放到語音介面時，仍維持高品質的生成水準。

第三項指標 writing-speaking consistency（書寫-口語一致性）高達 92.6%，這是評估三通道協調性的核心數據。該數值意味著模型在絕大多數情況下，其 visible text output（可見文字輸出）與 realtime oral response（即時口語回應）的語義內容高度對齊，避免了「文字說一套、語音說另一套」的認知失調。最後，在 URO-Bench 上，LWS（Listen-Write-Speak，聽-寫-說）持續優於其內部消融實驗（internal ablations），驗證了以文字為主要輸出、而非僅將文字視為 subordinate modality（從屬模態）的設計抉擇確實帶來系統性增益。整體而言，這些結果共同支持一個重要結論：將 visible writing（可見書寫）提升為 first-class output channel（第一級輸出通道），並不會以犧牲 realtime responsiveness（即時回應能力）為代價。

#### 與現有研究的比較

透過論文提供的比較框架（表 1），可以清楚定位 LWS（Listen-Write-Speak，聽-寫-說）在現有典範中的獨特性。既有研究在以下四個維度上至少犧牲其一：full-duplex interaction (FD)（全雙工互動，FD）、free text outputs (FT)（自由文字輸出，FT）、cognition while listening (CL)（聆聽時認知，CL）、cognition while speaking (CS)（說話時認知，CS）。

Think-Before-Speak（先想後說）典範如 Step-Audio 與 TVS 雖然具備 free text outputs (FT)（自由文字輸出，FT），但缺乏全雙工能力，且其認知發生在說話之前，既不具備 cognition while listening (CL)（聆聽時認知，CL）也不具備 cognition while speaking (CS)（說話時認知，CS）。Interleaved Think-Speak（交錯式邊想邊說）如 STITCH 與 Mini-Omni-Reasoner，以及 Dual-Brain Think-Speak（雙腦邊想邊說）如 MPS，同樣受限於 half-duplex（半雙工）互動，且其推理仍依附於語音生成階段，而非持續可見的文字通道。Think-While-Listen（邊聽邊想）如 SHANKS 與 Chronological Thinking（時序思考，Chronological Thinking）雖然嘗試在使用者發言時進行推理，但這些推理仍服務於後續語音生成，且多數版本仍為 half-duplex（半雙工）；其認知過程並非持久、可編輯的輸出。

另一方面，Full-Duplex（全雙工）模型如 Moshi、LSLM 與 FlexDuo 雖然實現了低延遲的 turn-taking（話輪轉換）與重疊處理，但其 user-facing outputs（面向使用者的輸出）通常僅有語音，缺乏 free text outputs (FT)（自由文字輸出，FT）。Parallel Text-Speech（平行文字-語音）如 Qwen3-Omni 與 Kimi-Audio，以及 Multi-Channel Protocol（多通道協定）如 OpenAI Harmony，雖然並行產生文字與語音，但文字通道多用於合成控制或 hidden intermediate state（隱藏的中間狀態）分析，而非始終可見的自由形式書寫，且它們通常不具備真正的 full-duplex interaction (FD)（全雙工互動，FD）與 cognition while listening (CL)（聆聽時認知，CL）。

LWS（Listen-Write-Speak，聽-寫-說）的關鍵突破在於將 visible writing（可見書寫）視為橫跨聆聽與說話階段的 first-class output channel（第一級輸出通道），而非僅是支援語音的 internal thinking（內部思考）。然而，其限制也隨之浮現：首先，維持 92.6% 的 writing-speaking consistency（書寫-口語一致性）雖高，但剩餘的 7.4% 不一致性在關鍵任務（如 code generation（程式碼生成）或 professional writing（專業寫作））中仍可能導致使用者混淆。其次，三條並行串流在單一 shared causal attention context（共享因果注意力脈絡）中運作，可能對序列長度與推理效率造成壓力，特別是在長時間互動下。最後，two-stage data pipeline（兩階段資料管線）依賴合成資料，其品質與多樣性將直接決定模型在真實世界複雜場景中的泛化能力。

#### 可重現性評估

從可重現性角度觀之，LWS（Listen-Write-Speak，聽-寫-說）具備顯著優勢：其行為完全透過 Token Schema（詞元架構）實現，無需修改標準 autoregressive LLM（自迴歸大型語言模型）的架構。這表示任何具備現成 Transformer 實作的研究者，原則上皆可透過重新定義 special tokens 與訓練目標來複現此行為。論文亦指出原始碼與資料集已於專案頁面公開，這為社群驗證提供了基礎。

然而，完全重現仍面臨若干挑戰。two-stage data pipeline（兩階段資料管線）涉及 per-second cognitive annotations（每秒認知標註）的合成，這些標註必須嚴格遵守因果一致性，其合成邏輯與品質控管細節將大幅影響最終模型表現。若論文未完整釋出該管線的詳細演算法與超參數，重現者可能難以達到同等水準。此外，模型權重（model weights）是否公開釋出，在提供的文本中並未明確說明；若僅公開程式碼與資料集，社群仍需大量運算資源從頭訓練。儘管如此，相較於需要多模態架構重構或雙模型協調的既有方案（如 MPS 或 OpenAI Harmony），LWS（Listen-Write-Speak，聽-寫-說）在方法論層面的可重現性門檻已顯著降低。

#### 未來研究方向

LWS（Listen-Write-Speak，聽-寫-說）的提出為 Full-Duplex Speech Models（全雙工語音模型）開啟了數個值得深入的研究方向。第一，在模態擴展上，可將 visible writing（可見書寫）通道進一步結合 spatially organized information（空間組織化資訊），例如即時生成圖表、Markdown table（Markdown 表格）或數學排版，使模型在科學簡報或協作場景中更貼近 multimodal HCI（多模態人機互動，HCI）與 cognitive science（認知科學）的原理。

第二，工具使用（tool use）的整合。由於 LWS（Listen-Write-Speak，聽-寫-說）已將文字提升為 primary output（主要輸出），未來可讓模型在 visible text output（可見文字輸出）通道中直接輸出可執行的程式碼、呼叫 API 或進行 structured analysis（結構化分析），並透過語音通道同步向使用者解釋執行邏輯，實現真正的「邊寫邊說邊執行」。

第三，長期記憶與跨會話持久性。當前 visible writing（可見書寫）主要發生在單一對話的 temporal Units（時間單元）內，未來可探索如何讓這些 persistent, structured, and inspectable intermediate outputs（持久、結構化且可檢視的中間輸出）跨越多次互動，形成可回顧、可編輯的協作文件，這與 CSCW（電腦支援協同工作，CSCW）中對 persistent representational media（持久表徵媒介）的需求高度契合。

第四，一致性與效率的權衡。92.6% 的 writing-speaking consistency（書寫-口語一致性）雖已優異，但未來研究可針對剩餘不一致性設計對齊機制，或探索在極低延遲約束下如何維持高一致性。此外，two-stage data pipeline（兩階段資料管線）的簡化與自動化——例如透過更強大的基礎模型直接生成符合 revealed input timeline（揭示的輸入時間軸）的 cognitive annotations（認知標註）——將有助於降低訓練成本並提升資料多樣性。

最後，評測基準的演進亦需跟上。現有的 Full-Duplex-Bench、VoiceBench AlpacaEval 與 URO-Bench 主要評量互動品質與生成能力，但未來需要針對「結構化輸出在語音互動中的可用性」設計更細緻的指標，例如 visible writing（可見書寫）的 pragmatic coordination（語用協調）效率、grounding（共同基礎）達成速度，以及使用者在實際協作任務中對 visible text output（可見文字輸出）的信賴度與編輯頻率。

## 論文問答

**Q1：當前以語音為主要輸出的大型語言模型存在什麼根本瓶頸，使其無法充分發揮原生文字能力？**
A：當前的語音大型語言模型被迫將所有輸出壓縮到「可口語化語言」的狹窄子空間中，導致程式碼生成、結構化分析、數學推導與專業寫作等原生文字能力遭到壓抑。當使用者要求生成可執行的 Python 二分搜尋程式碼，或是需要一份結構化的 Markdown 表格時，語音模型只能將這些內容線性化為口語逐字念出，迫使使用者手動謄寫。這種限制不僅喪失了書寫的精確性、持久性與空間組織優勢，也讓模型喪失了身為原生文字系統最核心的價值。

**Q2：現有的增強推理語音模型（如先想後說、交錯式邊想邊說或邊聽邊想）為何仍無法解決上述問題？**
A：這些現有方法雖然在推理時機上有所不同，但共同前提是將文字視為支援語音的隱藏或輔助機制，而非第一級輸出通道。無論推理發生在說話前、與說話交錯進行，或是在聆聽時進行，其認知過程大多屬於內部思考，一旦進入回覆生成階段便停止，或從未以持久、可編輯、使用者可見的形式呈現。因此，它們未能將模型的完整文字能力外化為面向使用者的結構化輸出，仍然受制於語音單一模態的限制。

**Q3：從認知科學與多模態人機互動的觀點來看，為何「可見書寫」對於豐富的即時互動至關重要？**
A：認知科學、電腦支援協同工作與多模態人機互動領域的研究指出，不同表徵媒介支援不同功能：語音擅長話輪轉換、共同基礎建立與語用協調，而書寫則更適合承載精確、結構化、持久且空間組織化的資訊。在人類實務協作中，語音負責協調互動流程，但任何需要精確、可重複檢視的內容都會被書寫記錄下來。因此，若將大型語言模型限制在純語音輸出，不僅違背人類多模態溝通的本質，也會壓抑模型在結構化輸出上的獨特價值。

**Q4：什麼是「聽-寫-說（LWS）」典範？它如何重新配置聆聽、書寫與說話三者的關係？**
A：LWS 是一種以文字優先的三通道典範，由單一自迴歸大型語言模型同時執行：持續聆聽使用者音訊、將可見自由文字作為主要輸出、並即時產生口語回應。這三個通道在共享因果注意力脈絡下並行運作，使模型維持單一且統一的認知流，而非由獨立模組各自處理。特別的是，可見書寫通道在使用者說話（聆聽階段）與模型回覆（說話階段）時都保持活躍，成為持續外化認知的載體，而非短暫的隱藏中間狀態。

**Q5：詞元架構（Token Schema）如何在不修改 Transformer 架構的前提下實現三通道行為？**
A：詞元架構透過在標準自迴歸 Transformer 中引入特殊詞元（special tokens）來實現 LWS 行為，完全無需更動模型架構。這些特殊詞元用於標示當前時間步屬於聆聽、可見書寫或口語輸出，使模型能在單一序列中自迴歸地決定啟動哪個通道，同時維持三通道間的共享因果注意力。這種設計保留了現有大型語言模型基礎設施的可擴展性與可重用性，卻能實現複雜的全雙工多模態輸出。

**Q6：兩階段資料管線的設計目的為何？它如何確保與「揭示的輸入時間軸」保持因果一致性？**
A：兩階段資料管線負責合成每秒認知標註，訓練模型在輸入音訊隨時間逐步揭示的過程中，即時產生合理的書寫與口語輸出。第一階段可能生成或整理目標文字輸出，第二階段則將這些輸出與時間性音訊區塊對齊，確保模型在訓練時不會洩漏未來資訊。如此一來，在推論階段，模型的可見文字與口語回應都能因果地奠基於它截至該時刻實際聽到的內容，從而實現真正的即時全雙工互動。

**Q7：LWS 在哪些評測基準上進行驗證，這些基準分別衡量什麼能力？**
A：LWS 在 Full-Duplex-Bench、VoiceBench AlpacaEval 與 URO-Bench 三個基準上進行評估。Full-Duplex-Bench 衡量模型處理真正全雙工互動的能力，包括重疊語音與話輪轉換；VoiceBench AlpacaEval 評估語音回應的品質與實用性；URO-Bench 則檢視口語對話情境中的使用者體驗與互動品質。這三個基準共同涵蓋了即時回應能力、輸出品質與對話一致性等實際部署所需的關鍵面向。

**Q8：LWS 取得了哪些關鍵量化結果？這些數據說明了什麼？**
A：LWS 在 VoiceBench AlpacaEval 達到 4.72 分，書寫-口語一致性高達 92.6%，並在 URO-Bench 上持續優於內部消融實驗，同時在 Full-Duplex-Bench 展現強勁的全雙工互動表現。其中 92.6% 的一致性尤具指標意義，顯示可見文字輸出與語音串流在並行生成且受不同限制的情況下仍能保持高度對齊。這些結果有力地證明：將書寫提升為第一級輸出通道並不會犧牲即時回應能力，反而可能同時增強語音輸出的品質與結構化表達。

**Q9：URO-Bench 上的內部消融研究揭示了 LWS 三通道設計的哪些貢獻？**
A：消融研究顯示，任何削弱或移除三通道中任一環節的變體版本，其 URO-Bench 表現均不如完整 LWS，證明此設計具有協同效應而非冗餘。具體而言，這些結果表明可見書寫提供了隱藏式內部思考或純語音輸出所無法完全取代的認知價值。這項證據強力支持本文的核心主張：文字必須被視為持續面向使用者、可檢視的通道，而非僅是隱藏於語音背後的中間狀態。

**Q10：在哪些實務場景中，LWS 相較於傳統純語音或隱藏推理的語音助理能帶來決定性優勢？**
A：LWS 在軟體工程面試、協作寫程式、科學討論或專業會議等場景中具有決定性優勢，因為這些情境需要模型即時生成可執行程式碼、數學推導或結構化 Markdown 表格。不同於純語音系統迫使使用者手動謄寫念出的程式碼，LWS 能同時呈現乾淨、持久且可直接複製編輯的文字，讓使用者在持續口語對話的同時檢視與操作結構化內容。這種能力彌補了對話式 AI 與生產力知識工作之間的鴻溝，使語音介面終於能支援過去必須依賴圖形文字介面才能完成的任務。

**Q11：LWS 的以文字優先設計可能如何影響語音 AI 助理與硬體的產品規劃？**
A：以文字優先的設計意味著語音產品必須配備螢幕或 companion display，才能充分發揮可見書寫通道的價值，促使產品形態從純音訊裝置轉向多模態介面。對開發者而言，語音 API 應將平行文字串流視為第一級輸出，而非僅作為語音合成的副產品或隱藏中間狀態。此外，由於 LWS 透過共享因果注意力脈絡與詞元架構實現，無需額外多模型編排系統，因此更易於部署在現有的大型語言模型服務基礎設施上。

**Q12：LWS 對多模態人機互動與語音 AI 研究領域可能產生什麼更廣泛的影響？**
A：LWS 將可見書寫提升為第一級輸出通道，挑戰了語音 AI 領域長期以來將文字視為語音附屬或隱藏層的假設，可能重新定義對話代理的標準互動典範。它讓人工語音互動更貼近自然人類的多模態溝通模式，其中書寫與語音扮演互補的認知功能，而非彼此競爭。這一典範轉移可能啟發未來研究，將圖表、手勢或結構化資料等其他模態也同樣外化為主要輸出，而非僅作為隱藏的中間表徵。

**Q13：LWS 典範在模型架構與運算需求方面存在哪些已知的限制或挑戰？**
A：儘管詞元架構無需修改模型架構，但在單一共享因果注意力脈絡下同時維持三個通道，可能會增加序列長度與運算負載，相較於簡單的輪替式或單輸出系統對延遲造成更大壓力。模型必須同時處理傳入的音訊詞元、可見文字詞元與語音詞元，這在邊緣裝置或低功耗硬體上可能難以維持即時回應。此外，由於此方法依賴兩階段合成資料管線，訓練資料的品質與多樣性可能限制模型在合成認知標註未充分涵蓋的領域中的泛化能力。

**Q14：在共享脈絡下並行生成可見文字與口語回應時，可能出現哪些失效案例或一致性問題？**
A：儘管書寫-口語一致性高達 92.6%，剩餘的 7.4% 差距仍顯示在某些情境下，可見文字與語音串流可能在內容、時間點或細節程度上出現分歧，導致同時依賴雙通道的使用者產生困惑。在複雜的多步驟推理任務中，模型可能產生過於密集的結構化文字，難以在即時語音中完整複誦，進而造成口語回應被截斷或簡化，與書面版本產生落差。此外，若書寫通道過度佔用注意力資源，口語回應可能變得過於簡短或出現延遲，反而削弱了語音在語用協調與互動流暢性上應有的功能。

**Q15：這項工作為全雙工語音模型與多模態大型語言模型指出了哪些未來研究方向？**
A：未來研究可將三通道典範擴展至更多模態，例如同時生成圖表、程式碼執行環境或指令動作，使其與文字和語音並列為第一級輸出通道。研究者亦可探索自適應通道優先級機制，讓模型依據任務需求或使用者偏好動態調配書寫與說話之間的注意力分配。最後，將資料管線從純合成認知標註進一步拓展至真實人類多模態互動軌跡，有望提升開放領域對話中各通道認知表現的自然度與穩健性。

## 實務應用指南

### 適用場景

1. **即時協作軟體開發**：開發者透過語音口述需求，模型在「可見書寫」通道即時生成可執行的 Python 程式碼或 Markdown 文件，同時以「即時口語回應」確認語意與追問細節，解決傳統語音模型只能將程式碼線性化朗讀、迫使使用者手動謄寫的痛點。
2. **專業會議即時助理**：在多人全雙工對話中，模型持續聆聽並在聆聽階段即開始書寫結構化決策摘要與待辦表格，會議結束時已產出持久、可編輯的文字紀錄，而非僅有語音總結。
3. **互動式數學與科學教學**：學生以語音提問複雜推導，模型在「可見文字輸出」呈現分步驟的 LaTeX 或 Markdown 推導過程，教師可即時檢視中間步驟並糾正，語音則負責語用協調與鼓勵。
4. **即時結構化數據分析**：分析師語音詢問資料趨勢，模型同步輸出可視化程式碼（如 pandas、SQL）與分析表格，並以口語解釋圖表含義，確保「空間組織化資訊」不被語音線性化稀釋。
5. **多語言即時口譯與紀錄**：在跨語言全雙工溝通中，模型即時書寫原文與譯文的對照文字稿，同時以目標語言語音輸出，提供可回溯、可引用的持久文本。

### 實作前置條件

- **資料**：需具備時間對齊的語音-文字平行語料，並能透過合成或人工標註產生「每秒認知標註」，以訓練模型在「揭示的輸入時間軸」上保持因果一致性。建議至少數千小時含結構化輸出（程式碼、表格、推導）的多輪對話資料。
- **運算**：需支援自迴歸大型語言模型全量微調或持續預訓練的 GPU/TPU 叢集（如數十至數百卡規模），以及低延遲全雙工語音串流推論基礎設施。
- **技術能力**：團隊需熟悉 Transformer 自迴歸機制、音訊詞元化（audio tokenization）、因果注意力脈絡設計，並具備建構「兩階段資料管線」與即時串流系統的工程經驗。

### 實作步驟建議

1. **設計詞元架構（Token Schema）**：在現有自迴歸 Transformer 中引入特殊詞元，定義「聆聽」「可見書寫」「說話」三種通道狀態，無需修改模型架構，僅透過詞元序列控制行為切換與並行邏輯。
2. **建構兩階段資料管線**：第一階段將現有語音對話資料切分為每秒時間單位；第二階段合成對應的認知標註，模擬模型在該時間點已揭示的輸入內容與應產出的書寫/說話決策，確保訓練目標與推論時的因果限制一致。
3. **三通道聯合訓練**：以單一自迴歸目標同時預測音訊輸入、文字輸出與語音輸出的詞元序列，讓「共享因果注意力脈絡」學會在單一時間單位內分配注意力給不同通道。
4. **部署全雙工推論引擎**：建置支援串流音訊輸入與雙輸出（文字即時渲染＋語音即時合成）的推論服務，確保「可見書寫」作為主要輸出通道的更新頻率與「即時口語回應」的延遲均達可用水準。
5. **評估與對齊**：在 Full-Duplex-Bench 檢驗話輪重疊處理能力，以 VoiceBench AlpacaEval 衡量回應品質，並透過內部指標監控「書寫-口語一致性」，必要時針對不一致案例進行資料清洗與微調。

### 潛在風險與注意事項

- **書寫-口語不一致**：模型可能輸出與語音內容矛盾的文字（如程式碼版本不同步）。建議在訓練資料中強化配對約束，並在推論時引入一致性檢查機制，或將文字設為主要輸出、語音視為其衍生的即時摘要。
- **認知標註的因果錯位**：若合成標註未嚴格對齊「揭示的輸入時間軸」，模型在推論時會出現「偷看」未來語音的問題。務必在資料管線中實作嚴格的時間遮罩，驗證每個時間單位的輸入僅包含已揭示的音訊片段。
- **模態競爭與注意力飢餓**：在共享因果注意力脈絡下，過度活躍的書寫通道可能壓縮說話通道的表達空間。可透過損失函數加權或通道特定的注意力偏置來平衡。
- **使用者認知負荷**：同時呈現文字與語音可能讓使用者難以聚焦。產品設計應允許使用者依任務類型動態調整通道優先級（例如程式碼任務強調文字，閒聊任務隱藏文字）。
- **延遲與成本**：全雙工三通道推論的運算量顯著高於單通道。需評估是否對所有查詢啟用完整三通道，或設計路由機制在簡單查詢時降級為純語音回應。

### 與其他技術的整合建議

- **與現有 LLM 工具鏈整合**：LWS 的核心仍是自迴歸大型語言模型，可直接繼承現有的 RAG、函式呼叫（function calling）與安全對齊機制，只需將特殊詞元架構嵌入提示詞模板。
- **與 IDE 及文件系統整合**：將「可見書寫」通道對接至 VS Code、Notion 或企業 Wiki，使模型輸出的程式碼與 Markdown 表格直接寫入可編輯文件，而非僅顯示於聊天視窗。
- **與傳統 ASR–LLM–TTS 級聯系統共存**：在無法部署端到端全雙工模型的場景，可將 LWS 的詞元架構視為「虛擬協定層」，在級聯系統中模擬三通道行為，作為過渡方案。
- **與多模態輸入整合**：未來可擴展詞元架構納入影像或螢幕截圖輸入，讓模型在聆聽使用者語音、檢視共享畫面的同時，書寫對應的結構化分析與口語解釋。

### 給不同背景讀者的閱讀建議

- **初學者**：請先聚焦論文圖一與表一，理解「聽-寫-說」三通道的基本分工。重點不在技術細節，而是體會為何「把文字當成第一級輸出通道」能解放大型語言模型的原生能力——想像一位同時幫你寫程式碼又口頭解釋的搭檔，就能掌握本文的核心價值。
- **AI 工程師**：請深入研讀第三節的詞元架構與兩階段資料管線。本文的關鍵實作洞見在於「不修改 Transformer 架構，僅以特殊詞元實現三通道並行」，這意味著你可以將現有程式碼庫的微調框架直接套用，但需特別注意每秒認知標註的因果遮罩與串流推論時的詞元交錯邏輯。
- **研究人員**：請關注本文對「語音作為從屬模態」這一前提的挑戰，以及共享因果注意力脈絡下的多工學習問題。論文將書寫、說話與聆聽統一為單一自迴歸程序的理論框架，為全雙工多模態互動提供了新的形式化基礎，後續可延伸至視覺通道或探索不同通道間的資訊理論界限。
- **產品經理**：請將論文視為一份「語音互動產品的路線圖修正建議」。重點評估 Full-Duplex-Bench 與 VoiceBench AlpacaEval 的數據對你所在場景的參考價值，並思考如何在 UI 上並存「即時文字編輯區」與「語音播放」而不造成使用者困惑。核心商業洞察是：語音適合協調互動，但任何需要精確、持久、結構化的內容都應該以文字呈現。
