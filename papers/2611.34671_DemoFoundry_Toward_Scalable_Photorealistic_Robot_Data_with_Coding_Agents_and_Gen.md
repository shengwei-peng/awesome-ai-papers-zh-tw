### 實作步驟建議

**階段一：配對資料集建構（Pair Construction）**
1. 收集並整理現有機器人示範資料，確保包含 RGB 影片、機器人狀態序列、動作標籤、相機參數
2. 部署 Pair-construction agent，給予其工具集（場景重建 API、模擬器 API、對齊工具）
3. 讓 agent 自動撰寫 `pair_builder.py`：呼叫 3D 重建（如 Gaussian Splatting、NeRF）從 RGB 影片建立場景網格、對齊相機與機器人基座、在模擬器中 replay 動作產生代理影片
4. 人工檢查配對品質，迭代修正 agent 程式碼
5. 累積至少數百至上千對高品質配對（論文使用 1,884 對）

**階段二：影片渲染器訓練（Renderer Training）**
1. 選定基礎生成式影片模型（論文使用 Wan2.1、Wan2.2）
2. 以配對資料集進行監督式微調，條件輸入為代理影片 + 場景參考幀，目標輸出為真實風格影片
3. 評估視覺品質（FID、FVD）與動作-影片一致性指標
4. 將訓練好的渲染器權重儲存，供後續新場景使用

**階段三：新場景資料生成（Zero-shot Generation）**
1. 收集目標場景的參考影像（多視角 RGB）
2. 部署 Scene & code agent，給予任務指令（如「將罐子轉移到托盤」）
3. Agent 自動重建任務相關幾何、撰寫 `task_program.py`（包含 approach、grasp、place 等子任務）
4. 在模擬器中執行程式，隨機化物件佈局產生多條代理軌跡
5. 透過自動化任務執行檢查（如夾爪是否成功閉合、物件是否到達目標位置）篩選成功軌跡
6. 將成功軌跡的代理影片 + 場景參考幀輸入渲染器，產出照片級真實觀測

**階段四：策略學習與部署（Policy Learning）**
1. 將渲染後的影片與對齊的動作/狀態組裝成訓練資料
2. 使用 Diffusion Policy 或 π0.5 進行策略訓練
3. 在真實機器人上評估，比較與原始模擬訓練、真實示範訓練的效能差距
4. 根據資料規模進行 scaling 實驗，確認生成成本與效能的權衡

### 潛在風險與注意事項

**風險一：配對資料品質不穩定**
- **現象**：Pair-construction agent 產生的代理影片與真實影片在時間對齊、物件姿態上存在偏差，導致渲染器學到錯誤的對應關係
- **緩解**：建立自動化品質檢查（光流一致性、關鍵點對齊誤差），設定閾值過濾低品質配對；保留人工抽檢機制

**風險二：渲染器幻覺與物理不一致**
- **現象**：生成式影片模型可能產生接觸錯誤、物件穿透、變形等物理不一致現象，破壞策略學習
- **緩解**：在資料生成流程中加入物理一致性檢查（如接觸點合理性、軌跡平滑度）；限制渲染器輸入的代理影片必須通過模擬器物理驗證

**風險三：零樣本泛化失敗**
- **現象**：對於與訓練配對資料差異過大的場景（如極端光照、罕見材質），渲染器可能產生低品質輸出
- **緩解**：建立場景相似度評估機制，對於低相似度場景觸發人工介入或額外配對資料收集

**風險四：程式碼代理不可靠**
- **現象**：Scene & code agent 撰寫的任務程式可能存在語法錯誤、邏輯漏洞、無法達成任務
- **緩解**：建立執行回饋迴圈（agent 觀察模擬器輸出並自我修正）；設定最大重試次數；對失敗案例進行錯誤分析以改進 prompt

**風險五：成本與時間估算偏差**
- **現象**：雖然論文聲稱成本低於人工遙操作，但實際部署時 LLM API 呼叫、模擬器運算、渲染器推論的累積成本可能超預期
- **緩解**：建立成本監控儀表板；對高頻任務進行快取與重用；評估使用較小的開源 LLM 替代商業 API 的可行性

**風險六：策略遷移效果有限**
- **現象**：在某些任務或機器人平台上，生成資料訓練的策略效能可能顯著低於真實示範
- **緩解**：採用混合訓練策略（真實 + 生成資料）；針對困難任務增加生成資料的多樣性與數量
