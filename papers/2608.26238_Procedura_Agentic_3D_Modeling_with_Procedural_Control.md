## 摘要翻譯

原生 3D 生成器（Native 3D generators）如今已能從單張影像還原出令人印象深刻的網格幾何（mesh geometry）。然而，在機加工物件（machined object）理應銳利之處，密集網格（dense mesh）仍顯得圓滑；它缺乏部件分解（part decomposition），也未提供可供使用者編輯的參數（parameter）。為了解決此問題，我們探索「以程式碼表示 3D 形狀」（3D shape as code）的典範，利用並擴展大型語言模型（Large Language Model, LLM）的程式撰寫能力以進行 3D 建模。我們提出 Procedura，一個新穎的 3D 建模代理框架（3D modeling agent framework），它將物件寫成程序式組裝（procedural assembly），也就是一個參數化程式（parametric program），其中的具名部件（named parts）透過具類型、可機器檢查的接合（typed, machine-checkable mates）互相連結。從文字提示出發，代理會將物件規劃（planning）為組裝圖（assembly graph），並逐部件地撰寫程式：它根據接合座標框（mated frames）求解每個部件的放置（placement），而非直接猜測；只有在編譯檢查（compile check）、接合檢查（mate check）與連通性檢查（connectivity check）都通過後，才會將該部件提交（commit）納入組裝。隨後，解耦視覺評判器（decoupled vision critic）會一次針對一項診斷出的修正（diagnosed fix），逐步精進組裝結果。此外，同一個組裝圖還承載逐部件材質（per-part materials），以及經模擬器驗證的關節運動（simulator-validated articulation）。我們在 P3D-Bench 上以其組裝評判器（assembly judge）進行評估，並使用相同評判器在我們提出的硬表面基準測試（hard-surface benchmark）MechBench-36 上進行評估。在這兩個測試中，Procedura 在評判品質上均優於最先進的（state-of-the-art）原生 3D 生成器以及所有先前的 3D 程式碼代理；在所有評估方法中產生最銳利的邊緣；並且是唯一輸出為可編輯、具部件結構的程式（editable, part-structured program）的方法。

### 核心貢獻（3～5點）
- 提出 Procedura，一個以大型語言模型為基礎的 3D 建模代理框架，能將物件表示為可編輯、具部件結構的程序式組裝。
- 從文字提示規劃組裝圖，並以接合座標框驅動部件定位，透過編譯、接合與連通性三層驗證確保組裝正確性。
- 引入解耦視覺評判器，針對每次診斷出的修正逐步精進組裝結果。
- 同一組裝圖可同時攜帶逐部件材質與經模擬器驗證的關節運動，支援完整的生產級資產需求。
- 在 P3D-Bench 與新提出的 MechBench-36 硬表面基準測試上，於評判品質與邊緣銳利度均超越現有原生 3D 生成器與 3D 程式碼代理。

### 適合對象
適合從事 3D 生成、程序式建模、電腦輔助設計（CAD）、電腦圖學、機器人模擬與可編輯數位資產製作的研究人員與工程師；特別是對於需要將生成結果轉化為可修改、可驗證、可模擬之生產資產的讀者，本篇論文提供了具體的方法與基準。

## 深度分析

#### 方法論解析

Procedura 的核心設計是將「3D shape as code（以程式碼表示 3D 形狀）」從單次、盲目的程式生成，轉變為一個具備結構化規劃、逐步驗證與視覺回饋的代理式 3D 建模（Agentic 3D Modeling）流程。整體可拆解為三個主要階段：Planning（規劃）、Procedural Modeling（程序式建模）與 Refine（精修），並以一個統一的 assembly graph（組裝圖）貫穿全程。

**1. Assembly Graph（組裝圖）作為結構骨幹**

不同於原生 3D 生成器（Native 3D generators）輸出僅有 raw triangles（原始三角形）的 dense mesh（密集網格），Procedura 首先將物件表示為一張圖：節點是 named parts（具名部件），邊是 typed, machine-checkable mates（具類型、可機器檢查的接合）。這張圖同時承載三種語義資訊：

- 幾何組裝：每個 part（部件）如何透過 mate（接合）定位到整體結構；
- 材質指定：per-part materials（逐部件材質）可直接掛載在對應節點；
- 運動機構：articulation（關節運動）透過 mates 的軸向與運動類型定義，並可在 IsaacSim 等模擬器中驗證。

這種表示法讓「部件分解（part decomposition）」不再是後處理分割的結果，而是生成過程的一等公民。

**2. Planning（規劃）階段**

給定 text prompt（文字提示）後，代理首先合成一張 reference view（參考視圖），作為後續視覺對齊的依據。接著 LLM（Large Language Model，大型語言模型）規劃出 assembly graph：決定需要哪些 parts、它們之間的 mates 類型（例如 peg into socket（榫入孔）、hinge about axis（繞軸樞接）），以及整體的連接拓撲。此階段不產生實際幾何，而是建立高階語義與約束框架，讓後續每個部件的生成都有明確上下文。

**3. Mate-Driven Build（接合驅動建構）**

這是方法論的關鍵創新。過往 3D-code agent 常採 single pass（單次生成），一次決定所有尺寸與 placement（放置／定位），導致多部件物件容易出現錯誤的部件數量或位置偏移。Procedura 改為 part by part（逐部件）生成：每個新部件都根據其 mated frames（接合座標框）來求解 placement，而非由模型憑空猜測。

具體來說，當要加入一個新 part 時，代理會：

- 根據 assembly graph 中已定義的 mates，取得已存在部件上的接合座標框；
- 計算新部件必須滿足的變換矩陣，使其接合座標框與對應座標框對齊；
- 針對新部件的程式碼進行 compile check（編譯檢查），確保語法與幾何運算合法；
- 執行 mate check（接合檢查），驗證接合關係在空間中確實成立；
- 執行 connectivity check（連通性檢查），確保整體結構沒有漂浮或斷開的部件。

只有通過這整個 verification stack（驗證堆疊）後，該 part 才會被 commit（提交）進入 partial build（部分建構）。這種「小步前進、每步可驗證」的策略，大幅降低了多部件組裝中的累積誤差。

**4. Constructive Solid Geometry（CSG，建構實體幾何）**

Procedura 讓 LLM 以 CSG 撰寫形狀，每個面都是精確的 plane（平面）或 cylinder（圓柱面）。這與 SDF（Signed Distance Function，帶符號距離函數）或 voxel grid（體素網格）解碼出的柔軟表面截然不同：machined object（機加工物件）所需的銳利邊緣與精確面可以被直接保證，而不需要後處理銳化或法線貼圖欺騙視覺。

**5. Decoupled Vision Critic（解耦視覺評判器）**

生成完成後，Procedura 會渲染當前模型，並由一個獨立於生成器的視覺評判器進行診斷。它一次只提出一個 diagnosed fix（診斷出的修正），例如某個部件比例錯誤、接合位置偏移或缺少細節。生成代理根據這個具體診斷進行修改，然後再次驗證。這種「診斷—修正—驗證」的迴圈讓視覺回饋真正進入程式生成流程，彌補了過去 program-based 3D generation 缺乏視覺檢查的缺口。

**6. Materials 與 Articulation（材質與關節運動）**

同一張 assembly graph 還支援兩項生產級資產（production asset）所需的延伸功能：

- Paint（上色／繪製材質）：為每個 part 指定材質參數；
- Articulation（關節運動）：根據 mates 定義可動軸，並在 IsaacSim 中進行 simulator-validated articulation（模擬器驗證的關節運動），確保機構不會穿模或鎖死。

整體而言，Procedura 的方法論並非單純讓 LLM「寫更多 3D 程式碼」，而是透過 assembly graph、typed mates 與 verification stack，把一個本來不可控的單次生成問題，轉化為一系列小型、可驗證、可編輯的決策步驟。

#### 實驗數據解讀

論文在兩個基準測試集上進行評估：P3D-Bench 與作者自行提出的 MechBench-36（hard-surface benchmark，硬表面基準測試）。評估指標採用 assembly judge（組裝評判器），這是一種針對組裝結構、部件關係與整體幾何品質進行評分的機制，能同時反映形狀正確性與結構合理性。

**1. P3D-Bench 上的表現**

在 P3D-Bench 上，Procedura 與 state-of-the-art（最先進的）native 3D generators、prior 3D-code agents 以及 single-shot LLM baselines 進行比較。根據論文摘要與引言的敘述，Procedura 在 judged quality（評判品質）上優於所有對照方法。這意味著：

- 它不僅在單一視角的幾何相似度上表現良好；
- 更重要的是，輸出具有正確的 part decomposition（部件分解）與 mate 結構，符合 assembly judge 對「可組裝性」與「部件語義」的要求。

**2. MechBench-36 上的表現**

MechBench-36 是本文提出的 hard-surface benchmark，專門針對銳利邊緣、機械化、多部件的物件設計。在這個更具挑戰性的測試集上，Procedura 同樣取得最佳成績，並且是：

- 邊緣最銳利的方法：相較於 SDF/voxel 或 autoregressive generators（自迴歸生成器）輸出的 soft、scan-like（掃描感）表面，Procedura 的 CSG 表示天然保證銳利邊緣；
- 唯一輸出 editable, part-structured program（可編輯、具部件結構的程式）的方法：這不僅是量化指標上的勝利，也代表輸出資產具備後續編輯、參數調整與動畫製作的潛力。

**3. 指標意涵分析**

Assembly judge 的評分維度通常包含：

- 部件數量與類型是否正確；
- 各 part 的幾何形狀是否合理；
- Mates 是否正確連接且沒有漂浮部件；
- 整體結構是否與 prompt 語義一致。

Procedura 在這些維度上表現優異，說明其優勢不只在「看起來像」，而在「結構上對」。這對遊戲、機器人模擬與工業設計等應用至關重要，因為這些場景需要的不只是視覺相似，而是可拆解、可編輯、可模擬的 3D 資產。

**4. 尚待補充的數據細節**

由於目前可取得的上下文未包含完整表格與數值，以下幾點是進一步解讀時需要留意的：

- 各方法在 judged quality 上的絕對分數與相對差距；
- 生成一個物件所需的平均 LLM 呼叫次數與總耗時；
- 不同 mate 類型（例如 rigid mate、hinge mate、slider mate）的成功率；
- 視覺評判器精修階段平均需要幾次迭代才能收斂；
- 在 IsaacSim 中驗證 articulation 的成功率與常見失敗模式。

這些數據將有助於評估 Procedura 在實際生產流程中的成本效益與穩健性。

#### 與現有研究的比較

**1. 相較於 Native 3D Generators（原生 3D 生成器）**

Native 3D generators 包含兩大家族：一類輸出 SDF 或 voxel grid（體素網格），另一類為 autoregressive generators（自迴歸生成器），直接逐 token 生成 mesh geometry（網格幾何）。它們的共同問題是：

- 輸出為 raw triangles（原始三角形），沒有 part decomposition（部件分解）；
- 表面常呈現 soft、scan-like 質感，machined object（機加工物件）所需的銳利邊緣不足；
- 沒有可編輯 parameter（參數），使用者無法直接調整尺寸或結構；
- 部件語義必須依賴 post-hoc segmentation model（事後分割模型），而這類分割往往只依據 surface geometry（表面幾何）而非功能語義，導致「機器人左手指」這類高階語義難以正確恢復。

Procedura 透過 procedural assembly（程序式組裝）與 CSG，從根本上解決了這三個問題：幾何精確、部件結構內建、程式本身即可編輯。

**2. 相較於 Program-based 3D Generation（以程式為基礎的 3D 生成）**

早期的 CSG tree 歸納方法與 CAD-native 方法雖然能產生可編輯程式，但通常需要大量 3D 訓練資料，且較難處理開放世界中的多樣物件。近期 LLM-based 方法（例如生成 Three.js scenes 或 Blender scripts）雖然具備開放詞彙能力，但多為 single pass（單次生成），沒有 visual feedback（視覺回饋），導致：

- 多部件物件常出現錯誤的部件數量；
- 各 part 的 placement（放置／定位）容易偏移；
- 輸出多為 toy-like、low-poly（低多邊形）的簡化形狀，缺乏 fine detail（精細細節）。

Procedura 的改進在於：它讓 LLM 在每次生成新 part 時，都能參考 partial build（部分建構）的 render（渲染），並透過 mates 求解 placement，再經 verification stack（驗證堆疊）把關。這讓多部件、高細節的物件生成成為可能。

**3. 相較於 Agentic 3D-Code Generation（代理式 3D 程式碼生成）**

近期一些系統已經採用 draft-execute-revise（起草—執行—修訂）迴圈來撰寫 3D 程式碼。然而，這些方法通常仍將整個形狀視為一個待修正的整體，缺乏明確的組裝結構。Procedura 的差異化在於：

- 它將「組裝結構」本身也納入生成目標，而不只是幾何形狀；
- 透過 typed mates，placement 被轉化為可解析、可驗證的約束問題，而非自由參數；
- Decoupled vision critic（解耦視覺評判器）一次只給出一個 diagnosed fix，降低多錯誤同時修正時的複雜度與不穩定性。

**4. 相較於 Learned-Assembly Research（學習式組裝研究）**

學習式組裝研究通常假設已經有人類製作的 parts，然後預測 mates 或 joints。Procedura 則反過來：它同時生成 parts 與它們之間的 mate graph，把「結構」從輸入假設變成輸出結果。這對於沒有現成 CAD 資料的新物件特別有價值。

**5. 限制與潛在弱點**

儘管 Procedura 在多項指標上領先，仍有幾個值得注意的限制：

- **對 LLM 規劃能力的依賴**：assembly graph 的品質直接決定後續生成成敗。對於極度複雜或語義模糊的 prompt，規劃階段可能產生錯誤的部件分解或 mate 類型；
- **CSG 的表達限制**：雖然 CSG 能保證銳利邊緣，但對於有機形狀、自由曲面或高度不規則的表面，CSG 的 plane/cylinder 基元可能不如 mesh 或 SDF 靈活；
- **計算成本**：part by part 生成加上 verification stack 與 vision critic 迭代，可能導致較高的 LLM 呼叫次數與整體延遲；
- **Mate 類型的覆蓋範圍**：論文提到的 mates 類型（peg-socket、hinge 等）主要針對機械與硬表面物件，對於柔性連接、齒輪嚙合等複雜機構可能需要額外擴充。

#### 可重現性評估

根據目前可取得的摘要與引言內容，論文尚未明確說明是否會開放 source code（原始碼）、datasets（資料集）或 model weights（模型權重）。以下從幾個面向評估可重現性：

**1. 方法透明度**

Procedura 的整體流程描述相當清楚：三階段架構、assembly graph、verification stack、decoupled vision critic 等概念都有具體說明。然而，要完全重現仍需許多實作細節，例如：

- LLM 的具體版本與 prompting 策略；
- CSG 程式碼的語言與執行環境（例如 OpenSCAD、Blender Python、自訂 DSL）；
- Mate 類型的完整分類與對應的 frame 計算規則；
- Verification stack 中各檢查的閾值與容差設定；
- Vision critic 的模型選擇與診斷 prompt 設計；
- IsaacSim 中 articulation 驗證的具體流程與參數。

**2. 資料集可用性**

- P3D-Bench 是已存在的公開基準，理論上可重複使用；
- MechBench-36 是本文新提出的 hard-surface benchmark，其可重現性取決於作者是否釋出題目、ground-truth 與 assembly judge 的實作。若未釋出，其他研究者將難以直接比較。

**3. 模型權重**

Procedura 強調使用 frozen LLM（凍結的大型語言模型），因此不需要額外訓練 3D 生成模型。這降低了權重釋出的必要性，但仍需知道所使用的 LLM 版本（例如 GPT-4o、Gemini 1.5 Pro 等）以及 API 參數設定，才能重現結果。

**4. 程式碼釋出**

由於 Procedura 是一個複合式代理系統，涉及多個模組（規劃器、CSG 生成器、驗證器、視覺評判器、模擬介面），若作者能釋出完整程式碼與設定檔，將大幅提升可重現性與社群採用度。目前根據摘要與引言無法確認這一點。

**5. 建議的重現步驟**

若研究者希望重現或延伸此工作，可優先確認以下資訊：

- 是否提供 MechBench-36 的資料與評分腳本；
- 是否提供 assembly graph 的輸出格式與範例；
- 是否提供 vision critic 的 prompt 模板；
- 是否記錄每次實驗的 LLM 溫度、top-p 與 seed；
- 是否提供 IsaacSim 驗證 articulation 的場景設定。

#### 未來研究方向

Procedura 為「3D shape as code（以程式碼表示 3D 形狀）」開闢了一條結構化、可驗證的道路，未來可從以下方向延伸：

**1. 擴充 CSG 基元與曲面表達**

目前 Procedura 主要使用 plane（平面）與 cylinder（圓柱面）等精確基元。未來可引入 free-form surfaces（自由曲面）、swept surfaces（掃掠面）或 NURBS，以處理更廣泛的設計領域，例如消費性產品、建築元件或生物機械混合造型。

**2. 學習與檢索相結合的部件庫**

Procedura 目前讓 LLM 從頭生成每個 part。未來可結合可學習的 part library（部件庫）或檢索機制，讓常見零件（如螺絲、軸承、輪子）能從庫中直接取出並參數化調整，進一步提升生成效率與真實性。

**3. 更豐富的 Mate 類型與機構設計**

除了 peg-socket 與 hinge，未來可支援 gear mate（齒輪嚙合）、cam-follower（凸輪從動）、screw mate（螺旋接合）等複雜機構，並在 IsaacSim 中進行更完整的運動學與動力學驗證，使 Procedura 能生成真正可運作的機械裝置。

**4. 多模態輸入與條件控制**

目前系統主要從 text prompt（文字提示）與 reference view（參考視圖）出發。未來可擴充至 single image（單張圖片）、sketch（草圖）或 3D scan（3D 掃描）作為輸入，讓使用者能以更多方式指定設計意圖。

**5. 互動式編輯與人機協作**

Procedura 輸出的 parametric program（參數化程式）天然適合互動編輯。未來可開發圖形化介面，讓使用者直接調整參數、新增或刪除 mates、即時預覽變更，並將人類回饋納入代理的 refine 迴圈。

**6. 降低計算成本與延遲**

Part by part 生成與 vision critic 迭代雖然提升品質，但也增加成本。未來可研究如何透過更激進的 parallel generation（平行生成）、cache（快取）常用部件程式、或輕量級內部驗證器來減少對 LLM 與模擬器的呼叫次數。

**7. 與原生生成器的混合表示**

未來可探索將 Procedura 的結構化 assembly graph 與 native 3D generators 的高保真表面細節結合：由 Procedura 負責整體結構、parts 與 mates，再由 diffusion 或 autoregressive 模型為每個 part 生成精細表面紋理與微觀幾何，兼顧可編輯性與視覺豐富度。

**8. 自動化評估指標的發展**

Assembly judge 雖然能評估結構正確性，但仍可能無法完全捕捉人類對「美觀」與「功能性」的判斷。未來可發展更細緻的指標，例如 editable fidelity（可編輯保真度）、mate stability（接合穩定性）、manufacturability score（可製造性分數）等，讓評估更貼近實際應用需求。

總結來說，Procedura 不僅提出了一個新的 3D 建模代理框架，更重新定義了「高品質 3D 生成」的標準：不只是看起來像，更要結構正確、可編輯、可模擬。這為後續在遊戲資產、機器人模擬、工業設計與可解釋 AI 等領域的研究，提供了堅實的基礎與豐富的延伸空間。

## 論文問答

**Q1：Procedura 主要想解決什麼問題？為什麼這個問題對遊戲、模擬器與製造場景很重要？**

A：Procedura 針對的是如何從文字提示生成可用於生產流程的機械化、硬表面物件，例如機器、載具與工具。現有的原生 3D 生成器雖然能從單張圖片恢復出令人印象深刻的網格幾何，但輸出通常是密集、無結構的原始三角形，缺乏銳利邊緣、部件分解與可編輯參數。對於遊戲資產、機器人模擬或工廠數位孿生等應用而言，這樣的輸出難以直接進行動畫、模擬、修改或製造，因此需要一種能同時保證高精度幾何、有意義部件結構與可編輯性的生成範式。

**Q2：現有的原生 3D 生成器與自迴歸生成器為何無法滿足上述需求？**

A：原生 3D 生成器通常以帶符號距離函數或體素網格解碼形狀，導致表面在應該銳利的地方變得柔軟且類似掃描結果；自迴歸生成器則逐 token 生成網格，受 token 預算限制而難以保留細節。這兩種方法都輸出沒有結構資訊的原始三角形，無法標示哪些三角面屬於哪個部件，也沒有可供調整的參數。即使事後使用分割模型進行部件分解，這些切割仍只依據表面幾何而非語意，因此無法可靠地辨識例如機器人左手指這樣的具名部件。

**Q3：為什麼「以程式碼表示 3D 形狀」被視為有潛力的解決方向？**

A：程式本質上具有參數化與模組化特性，只要寫得好，就能同時編碼形狀、尺寸、部件關係與編輯介面。相較於密集網格，一段結構良好的程式可以明確指出每個零件的名稱、接合方式與可調參數，讓非專業使用者也能透過修改數值來改變物件。此外，建構實體幾何中的平面與圓柱面能產生精確的銳利邊緣，這正是機加工物件所需要的幾何品質。

**Q4：Procedura 的核心方法流程是什麼？它如何將文字提示轉換為可編輯的 3D 程式？**

A：Procedura 首先根據文字提示合成一張參考視圖，接著進入三個主要階段：規劃、程序式建模與細修。在規劃階段，代理將物件分解為由具名部件與具類型接合關係組成的組裝圖；在程序式建模階段，它逐部件撰寫 3D 程式，並依據接合座標框求解每個零件的放置位置；最後在細修階段，解耦視覺評判器會診斷渲染結果並一次執行一項修正。整個流程輸出的是一段參數化、部件結構清晰且可編輯的建構實體幾何程式。

**Q5：「程序式組裝」與「具類型、可機器檢查的接合」是 Procedura 的關鍵創新，它們為何如此重要？**

A：程序式組裝把物件表示為一個參數化程式，其中每個部件都有名稱，並透過類似「榫頭插入孔洞」或「繞軸旋轉的鉸鏈」等具類型接合關係連接在一起。這種表示讓每個零件的放置可以從接合座標框精確求解，而不是由語言模型憑空猜測，從而避免累積誤差與部件漂移。同時，編譯檢查、接合檢查與連通性檢查會在每次提交前自動執行，確保組裝結構正確、連通且可編輯。

**Q6：Procedura 為何選擇建構實體幾何作為形狀表示，並且要搭配解耦視覺評判器進行細修？**

A：建構實體幾何使用精確的平面、圓柱等基本體進行布林運算，因此每個面與邊都是精確定義的，能產生機加工物件所需的銳利邊緣，這是從網格或體素解碼難以達成的。解耦視覺評判器則獨立於生成模型之外，能夠客觀地診斷渲染結果中的問題，例如部件錯位或比例失調，並一次只允許一項經診斷的修正被執行。這種設計避免了生成器自己評判自己時可能出現的盲點，並逐步提升最終模型的視覺品質。

**Q7：Procedura 在哪些基準測試上進行評估？使用了什麼樣的評判標準？**

A：Procedura 在 P3D-Bench 以及作者新提出的 MechBench-36 硬表面基準測試上進行評估，兩者都使用組裝評判器來衡量輸出品質。P3D-Bench 提供了現有的組裝導向評估環境，而 MechBench-36 則專門針對銳利、機械化的硬表面物件設計，更能凸顯方法在精確幾何與部件結構上的表現。評判標準關注整體品質、部件正確性、接合關係與幾何精確度，而不只是單一視角的視覺相似度。

**Q8：Procedura 的實驗結果與現有方法相比有何突出表現？**

A：在 P3D-Bench 與 MechBench-36 上，Procedura 在組裝評判器評分下的品質均優於最先進的原生 3D 生成器以及所有先前的 3D 程式碼代理方法。它還產生了所有評估方法中最銳利的邊緣，這對硬表面物件至關重要。更重要的是，它是唯一一種輸出為可編輯、具部件結構之程式的方法，讓使用者能直接修改參數與部件，而不只是拿到一團無法編輯的網格。

**Q9：Procedura 的哪些設計選擇對實驗結果貢獻最大？有沒有隱含的消融意涵？**

A：逐部件撰寫程式並在每次提交前執行編譯、接合與連通性檢查，是避免大型程式一次生成時常見的部件錯位與結構漂移的關鍵。接合驅動建構讓每個零件的定位都基於具類型的接合座標框，這比單純讓語言模型猜測座標更穩定且可驗證。解耦視覺評判器則進一步在渲染層面診斷並修正錯誤，這些設計共同確保了高品質、可編輯且結構正確的輸出。

**Q10：Procedura 的輸出最適合應用在哪些實際場景？**

A：Procedura 的輸出特別適合需要精確幾何與可動機構的場景，例如遊戲中的載具與機械資產、機器人模擬環境、工廠數位孿生以及概念性電腦輔助設計。由於輸出是具名部件組成的參數化程式，開發者可以直接調整尺寸、替換零件或設定材質，而無需重新建模。此外，程式中還可攜帶經模擬器驗證的關節運動，使其能直接投入物理模擬與互動應用。

**Q11：從產品與使用者體驗的角度來看，Procedura 為設計師與工程師帶來什麼好處？**

A：設計師與工程師可以透過修改具名參數來快速迭代物件尺寸與形狀，而不需要手動雕刻網格或進行複雜的後處理分割。每個部件都有明確名稱與接合關係，方便資產管理、動畫綁定與模擬設定。這種「生成即資產」的流程大幅降低了從概念到可用生產資產的門檻，也讓非專業使用者能透過自然語言提示參與 3D 設計。

**Q12：Procedura 對整個 3D 生成領域可能帶來什麼樣的影響？**

A：Procedura 示範了如何將大型語言模型的程式撰寫能力擴展到高品質、多部件的 3D 形狀生成，而無需額外的 3D 訓練資料。它推動了 3D 生成從「無結構的密集網格」走向「可編輯、可驗證的結構化程式」的典範轉移。這種以代理方式進行程序式控制的思路，也可能啟發未來在可解釋、可互動與可製造設計上的更多研究。

**Q13：Procedura 目前有哪些可能的限制？**

A：Procedura 依賴建構實體幾何的基本體與布林運算，因此對於高度有機、自由曲面或無法用簡單基本體組合的形狀可能表現有限。整個流程需要多次呼叫語言模型並執行編譯與模擬驗證，生成速度可能慢於單次前向傳播的原生生成器。此外，組裝的複雜度與部件數量仍會受到語言模型上下文長度與推理能力的限制。

**Q14：在什麼樣的輸入或物件上，Procedura 可能會出現失敗案例？**

A：當文字提示過於模糊、物件包含大量非標準接合或極薄特徵時，語言模型可能難以規劃出正確的組裝圖與對應程式。如果某些形狀無法用現有的基本體精確表達，輸出可能會出現過度簡化或幾何不連續的情況。解耦視覺評判器雖然能捕捉許多視覺錯誤，但對於需要精確量測才能發現的細微偏差，仍可能無法完全診斷。

**Q15：未來可以朝哪些方向進一步擴展 Procedura？**

A：未來可以擴充基本體種類，例如加入掃掠、放樣或參數化曲面，以處理更豐富的幾何形狀。也可以結合神經表示或有機形狀生成器，讓系統同時擅長硬表面與自由曲面物件。此外，引入使用者在環編輯、從大型電腦輔助設計資料集中學習接合類型，以及將規模擴展到數百個部件的大型組裝，都是值得探索的方向。

## 實務應用指南

## 適用場景

1. **遊戲與虛擬製作的硬表面資產生成**  
   Procedura 適合快速產生車輛、武器、機械人、工具等硬表面物件。輸出為具名部件的參數化 CSG 程式，可直接匯入遊戲引擎或 DCC 工具進行後續編輯、材質指定與關節設定。

2. **機器人與自動化設備的數位雙生原型**  
   面對工廠場景中的夾爪、輸送帶、關節臂等設備，Procedura 能夠以接合圖（assembly graph）組織零件，並在 IsaacSim 中驗證可動機構，適合用於數位雙生或模擬環境的快速建置。

3. **產品設計與工業設計的早期概念建模**  
   設計師可用文字提示快速探索多種機構外型。由於輸出是參數化程式，設計師可調整尺寸、替換零件或修改接合方式，而不必從頭雕刻網格。

4. **教育與程式化建模教學**  
   Procedura 的「以程式碼表示 3D 形狀」流程可作為 CSG、組裝約束與參數化設計的教學範例，幫助學生理解零件、接合與機構運動之間的關係。

5. **合成資料生成（Synthetic Data Generation）**  
   由於輸出具備明確的部件結構、材質與可動關節，Procedura 可用於生成帶有語義標註的 3D 資料，供電腦視覺模型訓練或機器人感知測試使用。

## 實作前置條件

- **資料需求**  
  - 文字提示（text prompt）描述目標物件。  
  - 可選：參考圖片或視角資訊，用於生成 reference view 與後續視覺評判。  
  - 無需大規模 3D 訓練資料：Procedura 使用凍結的大型語言模型，不進行額外的 3D 訓練。

- **運算需求**  
  - 可呼叫大型語言模型（如 GPT-4/Gemini 等級）的 API 或本地端部署環境。  
  - 可執行 CSG 程式與渲染的運算環境（Python、OpenSCAD、Blender 或類似幾何核心）。  
  - 若需驗證關節運動，需具備 NVIDIA IsaacSim 或相容的物理模擬器。  
  - 視覺評判器（decoupled vision critic）需要多視角渲染能力，建議配備 GPU。

- **技能需求**  
  - 熟悉提示工程（prompt engineering）與 LLM API 串接。  
  - 具備基礎 3D 幾何與 CSG 概念（extrude、boolean、frame/transform）。  
  - 能夠設計或調整組裝評判器（assembly judge）與接合類型定義。  
  - 具備將參數化程式轉換為遊戲引擎 / CAD / 模擬器可用格式的能力。

## 實作步驟建議

1. **定義物件範疇與接合類型庫**  
   先決定目標物件類別（例如車輛、工具、機械人），並建立 typed mates 字典：插銷與孔洞（peg–socket）、鉸鏈（hinge）、滑軌（slider）等。這些接合類型將成為組裝圖的邊。

2. **建立 reference view 生成管線**  
   使用文字提示先合成一張參考視圖，作為後續規劃與視覺評判的依據。可結合 2D 擴散模型或直接使用多模態 LLM。

3. **規劃組裝圖（Planning）**  
   讓 LLM 將物件分解為具名部件（named parts）與接合關係，輸出 assembly graph。此階段應檢查：部件名稱語義是否合理、接合類型是否匹配、整體連通性是否成立。

4. **接合驅動的逐部件建模（Mate-driven Build）**  
   依照組裝圖順序，逐個呼叫 LLM 生成每個零件的 CSG 程式。每個零件的 placement 必須從 mated frames 計算，而非直接猜測座標。每次提交前執行三層驗證：compile check、mate check、connectivity check。

5. **視覺評判與迭代修正（Refine）**  
   渲染部分建構（partial build）與最終模型，由 decoupled vision critic 診斷問題（例如零件錯位、比例失真、缺少細節），並一次只執行一個診斷出的修正（diagnosed fix），直到通過組裝評判器（assembly judge）。

6. **材質與關節運動後處理**  
   在組裝圖上為每個部件指定 per-part materials，並將可動接合匯出至 IsaacSim 進行 simulator-validated articulation 驗證。

7. **匯出與整合至下游流程**  
   將最終的參數化程式轉換為目標格式（USD、FBX、STEP、glTF 等），匯入遊戲引擎、CAD 系統或機器人模擬環境。

## 潛在風險與注意事項

- **接合類型定義不完整導致結構錯誤**  
  若 typed mates 的語義或幾何約束定義不清，LLM 可能產生無法對齊的零件。建議從小規模物件開始迭代，逐步擴充接合類型庫。

- **LLM 幻覺造成零件數量或名稱不一致**  
  單次生成可能出現零件數目錯誤或語義名稱混亂。透過組裝圖強制規範，並在每次 commit 前執行驗證堆疊（verification stack）可降低風險。

- **視覺評判器與幾何驗證的標準不一致**  
  vision critic 可能關注外觀，而幾何驗證關注接合。兩者需對齊評分標準，避免反覆修正卻無法提升 assembly judge 分數。

- **運算成本與延遲**  
  多輪 LLM 呼叫加上渲染、模擬驗證會顯著增加單一物件的生成時間。建議設計快取機制與並行生成策略，並對簡單零件使用模板化程式。

- **輸出格式與下游工具相容性**  
  CSG 程式需轉換為目標格式，轉換過程可能遺失參數化資訊。建議保留原始程式作為 source of truth，並建立可重複執行的匯出管線。

## 與其他技術的整合建議

- **與原生 3D 生成器互補**  
  對於有機或掃描風格物件，仍可使用原生 3D 生成器產生密集網格；對於硬表面、機械化物件則使用 Procedura。兩者可透過場景圖整合，Procedura 負責結構化資產，原生生成器負責背景或自然物體。

- **與 CAD / PLM 系統銜接**  
  將 Procedura 輸出的參數化程式轉為 STEP 或 CAD 腳本，可匯入 SolidWorks、Fusion 360 等系統。接合圖可進一步轉換為工程圖中的約束與 BOM（Bill of Materials）。

- **與遊戲引擎整合**  
  匯出為 USD 或 glTF 格式，並攜帶 per-part materials 與關節資訊，可直接在 Unreal Engine、Unity 或 Omniverse 中進行互動與模擬。

- **與機器人模擬器整合**  
  利用 IsaacSim 驗證 articulation 後，可將 URDF/USD 格式匯入 ROS 2、Isaac Gym 或 NVIDIA Omniverse，作為機器人學習與控制的訓練場景。

- **與視覺語言模型（VLM）結合**  
  可將 decoupled vision critic 替換或擴充為更強大的 VLM，以提升對細節、比例與風格的診斷能力，並支援多語言提示。

## 給不同背景讀者的閱讀建議

- **初學者**  
  建議先理解「為什麼要用程式碼表示 3D 形狀」這個核心動機，並將 Procedura 想像成一位會寫 CAD 程式的 AI 助手。重點閱讀 Introduction 與圖 3 的流程概述，暫時不需要深入 CSG 或接合座標框的數學細節。

- **AI 工程師**  
  請聚焦於 Planning、Mate-driven Build 與 Refine 三階段的代理設計：LLM 如何被拆解為多次小規模呼叫、verification stack 如何降低錯誤累積、以及 decoupled vision critic 的診斷與修正迴路。這些設計對於建構穩定的 3D-code agent 最具參考價值。

- **研究人員**  
  建議深入分析 typed mates 與 assembly graph 的表徵設計，以及它們如何將「結構化 3D 生成」從後處理分割轉變為生成過程中的先驗約束。同時可關注 MechBench-36 的設計與 assembly judge 的評估指標，作為後續研究的基準。

- **產品經理**  
  請將本文視為一項「可編輯、具部件結構的 3D 資產生成方案」。重點評估它與現有原生 3D 生成器在硬表面物件上的品質差異、輸出可編輯性對工作流程的影響，以及整合至遊戲引擎、CAD 或機器人模擬器所需的工程成本與商業價值。
