## 摘要翻譯

長程代理常難以從失敗中恢復，其成因往往可追溯至數步之前，超越了局部反思或回溯所能解決的範圍。我們提出 BELIEFWEAVER，一個結合跨嘗試持久證據與修復方向前瞻性推理的框架。該框架在前沿、嘗試、觀察與檢查點上維持關聯式信念狀態。執行證據在嘗試與回溯間更新相關前沿優先度，而診斷性證據則管控執行的資格。隱式世界模型 (IWM) 評估修復假設、預測進展，並識別前沿關聯以引導探索。我們進一步將這些反覆出現的 IWM 推理元件，透過監督式微調 (SFT) 與線上策略蒸餾 (OPD) 蒸餾至一個 9B 學生模型。在三個終端機基準測試上，BELIEFWEAVER 相較於原生 Terminus-2 延續提升了 5.1 百分點的彙整最終分數，並在探索效率上呈現正向趨勢。蒸餾後的 9B 學生模型相較於所報告的原生基準提升了 9.8 百分點的最終分數，同時相較於匹配的教師模型降低了 54.8% 的估計教師 API 成本。這些結果顯示，持久證據與前瞻性推理能改善長程代理任務中的失敗恢復，同時大幅降低對教師模型推論的依賴。

### 核心貢獻（3～5點）
- 提出 BELIEFWEAVER 框架，結合跨嘗試持久證據與修復方向前瞻性推理，使長程代理能從成因發生於數步之前的失敗中恢復。
- 設計關聯式信念狀態，統一管理前沿、嘗試、觀察與檢查點，並以執行證據更新前沿優先度、以診斷性證據管控執行資格，形成雙軌證據機制。
- 引入隱式世界模型 (IWM) 評估修復假設、預測進展並識別前沿關聯，以引導探索方向。
- 透過監督式微調 (SFT) 與線上策略蒸餾 (OPD) 將 IWM 推理元件蒸餾至 9B 學生模型，在三個終端機基準測試上分別提升彙整最終分數 5.1 百分點與最終分數 9.8 百分點，並降低 54.8% 的教師 API 成本。

### 適合對象
從事長程代理、序列決策、代理式世界模型與失敗恢復機制研究的學者與工程師；關注大型語言模型蒸餾、線上策略蒸餾 (OPD) 與輕量級學生模型部署的實務研究者；以及對終端機基準測試、自主研究與電腦使用任務中代理可靠性議題感興趣的業界從業者。

## 深度分析

#### 方法論解析

BELIEFWEAVER 的核心設計理念在於將「失敗恢復」從單次的局部反思提升為跨嘗試（cross-attempt）的累積性推理過程。整體架構可分為三個相互耦合的模組：持久關聯式信念狀態（persistent relational belief state）、隱式世界模型（implicit world model, IWM），以及學生模型蒸餾（student distillation）管線。

**1. 持久關聯式信念狀態（Persistent Relational Belief State）**

此模組將探索過程形式化為四類實體的關聯圖：前沿（frontier，即候選修復假設）、嘗試（attempt）、觀察（observation）、檢查點（checkpoint）。其關鍵設計在於將「執行證據（execution evidence）」與「診斷性證據（diagnostic evidence）」分離處理：

- **執行證據**透過一元證據因子（unary evidence factor）更新前沿優先度（frontier priority），允許一次嘗試的結果影響多個相關前沿的排序，即使這些前沿在當前嘗試中並未被執行。
- **診斷性證據**則獨立控制執行資格（execution eligibility），決定哪些前沿當下可被執行。

這種分離設計避免了「診斷即執行」的耦合陷阱——傳統方法常將失敗判定與下一步行動混為一談，導致過早承諾（premature commitment）。狀態在回溯（rollback）後仍被保留，使證據得以跨嘗試累積，這是 BELIEFWEAVER 區別於樹狀方法（tree-based approach）的核心特徵。

**2. 隱式世界模型（Implicit World Model, IWM）**

IWM 並非建構可執行的環境模擬器（如 WorldCoder 或 Executable World Models），而是利用大型語言模型的隱式推理能力完成三項任務：

- **評估修復假設**：對候選前沿進行可行性與預期收益的預測。
- **估計前瞻進度**：預測若執行某前沿，後續軌跡的可能進展。
- **推斷前沿關聯**：識別前沿間的前置條件（prerequisite）共享或交互關係。

IWM 的輸出會回寫至信念狀態，形成「評估→更新優先度→選擇前沿→執行→收集證據→再次評估」的閉環。這種設計將世界建模從「預測單一動作後果」擴展為「推理前沿間的結構性關係」，使其能處理跨步失敗（failures whose causes lie several steps earlier）。

**3. 學生模型蒸餾（Student Distillation）**

由於 IWM 在每次探索中反覆調用，作者採用兩階段蒸餾將其推理能力遷移至 9B 學生模型：

- **監督式微調（Supervised Fine-Tuning, SFT）**：以教師模型的 IWM 輸出作為監督訊號。
- **線上策略蒸餾（On-Policy Distillation, OPD）**：在學生模型自身的策略分布上進行進一步優化，使其推理模式與實際部署時的狀態分布對齊。

此管線的動機在於：IWM 的推理模式具有高度重複性，適合蒸餾；同時 OPD 能緩解 SFT 常見的分布偏移問題。

#### 實驗數據解讀

**主要量化結果**

| 指標 | 數值 | 意義 |
|------|------|------|
| BELIEFWEAVER vs. 原生 Terminus-2 延續 | +5.1 百分點 | 框架本身的增益 |
| 蒸餾 9B 學生 vs. 報告原生基準 | +9.8 百分點 | 學生模型相對基準的增益 |
| 估計教師 API 成本降低 | 54.8% | 相對於匹配教師的開銷節省 |
| 探索效率 | 正向趨勢 | 達標所需嘗試數減少 |

**結果的深層解讀**

1. **5.1 百分點的框架增益**：此數字衡量的是「在相同教師模型下，引入信念狀態與 IWM 的邊際貢獻」。值得注意的是，這是「彙整最終分數（aggregate final score）」的結果，意味著在三個終端機基準測試（terminal-based benchmarks）上平均提升。對於長程任務而言，5.1 百分點屬於實質性進步，因為此類任務的基線表現通常較低，邊際改善空間有限。

2. **9.8 百分點的學生模型增益**：此數字對比的是「9B 學生模型 vs. 報告中的原生基準」，而非 vs. 教師模型。這暗示學生模型不僅保留了教師的推理能力，甚至在某些方面超越了原生基準——可能因為蒸餾過程過濾了教師的探索性冗餘行為，使學生模型更聚焦於有效推理。

3. **54.8% 的成本降低**：此數字是相對於「匹配教師（matched teacher）」的 API 成本，意味著在達到相近效能時，學生模型的推理成本僅為教師的約 45%。這對於實際部署具有重要意義，因為長程代理的推理成本隨軌跡長度線性增長。

4. **探索效率的正向趨勢**：雖然具體數字未在摘要中給出，但「正向趨勢」表明 BELIEFWEAVER 不僅提升最終成功率，還減少了達標所需的嘗試次數。這驗證了信念狀態的「累積性」設計——失敗嘗試並非被丟棄，而是轉化為後續探索的證據。

**實驗設計的潛在問題**

- 摘要未說明三個基準測試的具體名稱與難度分布，無法判斷 5.1 百分點在不同基準上的貢獻是否均勻。
- 「彙整最終分數」的計算方式（加權平均 vs. 簡單平均）未明確，可能影響結果的解讀。
- 學生模型的 9.8 百分點對比對象是「報告原生基準」，而非「同條件下的原生基準」，可能存在版本或配置差異。

#### 與現有研究的比較

**與樹狀方法（Tree-Based Approaches）的比較**

HTR（Jin et al., 2026）維護假設、產物、證據、洞察的持久樹；SciNav（Zhang and Sun, 2026）將科學編碼框定為替代分支的搜尋。BELIEFWEAVER 與這些方法的共同點在於「結構化探索」，但差異在於：

- 樹狀方法通常將證據附加於節點，難以表達「跨分支的證據傳遞」。
- BELIEFWEAVER 的關聯式信念狀態透過一元證據因子實現跨前沿的優先度更新，能處理「前置條件共享」的情境。

**與回溯方法的比較**

AgentRewind（Zhuang et al., 2026）同樣結合回溯與記憶保留，但其記憶是「失敗嘗試的歷史記錄」，而 BELIEFWEAVER 的信念狀態是「結構化的優先度分布」。後者更便於推理「下一步該嘗試什麼」，而不僅僅是「記住做過什麼」。

**與世界模型方法的比較**

FLARE、Qwen-AgentWorld、RAP、WebDreamer 等世界模型主要預測「單一動作後的環境狀態」，而 BELIEFWEAVER 的 IWM 預測的是「前沿間的結構性關係與前瞻進度」。這是一個更高層次的抽象，使其能處理需要跨步推理的失敗恢復。

**與不確定性導引方法的比較**

Uncertainty-Guided Tree Search（Mhammedi and Cohan, 2026）與 Agentic Uncertainty（Zhang et al., 2026c）使用認知不確定性（epistemic uncertainty）指導探索。BELIEFWEAVER 則使用「驗證器依據證據（verifier-grounded evidence）」，這更為可靠——不確定性可能源於模型自身的知識邊界，而驗證器反饋是環境的真實信號。

**與自改進代理的比較**

Darwin Gödel Machine、Gödel Agent、Hyperagents 等方法透過修改代理本身的程式碼或邏輯來改進。BELIEFWEAVER 不改變底層代理，僅在其上添加恢復控制器，這降低了部署風險，也便於與現有代理整合。

**限制與不足**

- **對驗證器的依賴**：診斷性證據需要可靠的驗證器（verifier），對於開放式任務或缺乏明確成功標準的場景，框架效能可能下降。
- **信念狀態的維護成本**：隨著前沿數量增長，關聯式狀態的更新與推理成本可能成為瓶頸。
- **IWM 的推理深度**：作為隱式世界模型，其推理能力受限於底層 LLM，對於需要深層因果推理的任務可能不足。
- **基準測試的範圍**：僅在終端機環境驗證，未涵蓋網頁瀏覽、機器人控制等領域。

#### 未來研究方向

**1. 信念狀態的理論化**

當前的一元證據因子設計較為啟發式，未來可探索：
- 將信念更新形式化為貝氏推理（Bayesian inference）或證據理論（belief functions），提供更嚴格的優先度更新規則。
- 研究信念狀態的收斂性與穩定性，避免長程任務中的優先度震盪。
- 探討關聯式狀態的圖神經網路（graph neural network）表示，以支援更複雜的前沿關係推理。

**2. 隱式世界模型的增強**

IWM 的推理深度是當前的主要瓶頸，可考慮：
- 結合顯式世界模型（如可執行程式碼模擬）作為 IWM 的補充，處理需要精確動力學預測的情境。
- 引入反事實推理（counterfactual reasoning）能力，評估「若當初選擇不同前沿」的後果。
- 將 IWM 與因果發現（causal discovery）結合，自動推斷前沿間的因果結構。

**3. 蒸餾策略的優化**

當前採用 SFT + OPD 兩階段蒸餾，未來可探索：
- 測試其他蒸餾方法（如 DPO、RLHF）在 IWM 蒸餾中的效果。
- 研究「推理時計算（test-time compute）」與「蒸餾規模」的權衡，尋找最佳學生模型規模。
- 探索跨任務的 IWM 蒸餾，使學生模型能泛化至未見過的任務類型。

**4. 應用領域的擴展**

當前僅在終端機環境驗證，可拓展至：
- **網頁代理**：處理需要跨頁面狀態追蹤的複雜任務。
- **機器人控制**：將 IWM 與 FLARE 等預測模型結合。
- **科學研究**：與 SciNav 等方法整合，處理需要多假設並行的探索任務。
- **多代理協作**：將信念狀態擴展為多代理共享的探索狀態。

**5. 失敗恢復的理論基礎**

當前框架主要為經驗性設計，未來可建立：
- 失敗恢復的形式化定義與理論界限。
- 信念狀態與恢復效能的理論關係（如資訊理論下界）。
- 與人類認知科學中的「後見之明偏差（hindsight bias）」與「反事實思維（counterfactual thinking）」的對比研究。

**6. 與其他代理改進方法的整合**

BELIEFWEAVER 不改變底層代理，這使其易於與其他方法整合：
- 結合 Darwin Gödel Machine 的自改進能力，使代理能動態調整恢復策略。
- 結合 SkillRL 的技能庫，將修復假設抽象為可重用的技能。
- 結合 Uncertainty-Guided Tree Search 的不確定性估計，作為信念更新的補充訊號。

**7. 評估方法的改進**

當前使用「最終分數」與「探索效率」作為主要指標，未來可考慮：
- 引入「恢復成功率」作為專門指標，衡量框架從失敗中恢復的能力。
- 設計對抗性測試，故意注入早期錯誤以評估恢復能力。
- 研究不同任務難度下的效能曲線，識別框架的適用邊界。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：論文聚焦於長程代理在多步任務中難以從早期失敗中恢復的問題。當失敗的根源發生在數步之前時，僅靠局部反思或回溯無法定位錯誤，因為相關證據往往在後續動作後才逐漸浮現。BELIEFWEAVER 試圖讓代理能跨越多次嘗試累積證據，並前瞻性地推理修復方向，從而將失敗轉化為後續探索的指引。

**Q2：為什麼現有的反思與樹狀回溯方法在長程任務中會失效？**
A：現有方法通常將替代方案組織成樹狀結構以支援分支與回溯，但長程失敗往往源自分支間共享的早期決策或假設，而非單一分支內的錯誤。單純的回溯與持久記憶能保留發生過的事，卻無法決定新證據應如何改變相關修復假設的優先順序。當前沿共享前置條件或跨步互動時，來自一次嘗試的證據可能使另一方向變得更或較不具前景，這正是現有樹狀方法難以系統性處理的盲點。

**Q3：為什麼失敗恢復對長程代理如此重要？**
A：長程任務如自主研究、電腦使用、序列決策等，軌跡極長且早期錯誤會沿軌跡傳播，導致代理陷入重複嘗試或過早承諾而難以自拔。若無法從早期失敗中有效恢復，代理的整體效能將受到根本性限制，因為錯誤會以指數級方式累積。有效的恢復機制使失敗嘗試成為後續探索的證據，而非僅僅觸發另一次重試，這對代理在真實世界中的實用性至關重要。

**Q4：BELIEFWEAVER 的核心方法是什麼？**
A：BELIEFWEAVER 結合了持久關聯式探索狀態與隱式世界模型（IWM）兩大元件。探索狀態持續追蹤前沿、嘗試、觀察與檢查點，跨回溯保留證據，並利用新結果修訂相關假設的優先度。IWM 則負責評估修復假設、估計前瞻性進展，並推論前沿之間的關聯，以指導代理下一步該探索什麼。

**Q5：這篇論文的主要創新點是什麼？**
A：主要創新在於將持久證據與前瞻性推理結合，用於長程代理的失敗恢復。具體而言，恢復控制器透過保留的執行證據與修復假設間的關聯來更新前沿優先度，能重新排序未被最新嘗試執行的候選；同時，獨立的診斷閘門控制執行資格，避免兩種功能互相干擾。另一項重要創新是將 IWM 的重複推理元件蒸餾成 9B 學生模型，透過監督式微調（SFT）與線上策略蒸餾（OPD）實現高效執行，大幅降低部署成本。

**Q6：為什麼將執行證據與診斷證據分開設計？**
A：將兩種證據分開是因為它們在恢復過程中扮演截然不同的角色：執行證據負責透過一元證據因子更新相關前沿的優先度，而診斷證據則獨立決定哪些前沿有資格被執行。這種分離讓證據從一次嘗試能重新排序相關替代方案，同時診斷閘門單獨控制執行資格，使系統在「該嘗試什麼」與「能否執行」之間取得清晰的職責劃分。這樣的設計也讓每個元件可以獨立調整與最佳化，提升整體系統的可維護性。

**Q7：實驗使用了哪些基準測試？**

A：當失敗的根源極為深遠、證據極為稀疏時，IWM 可能難以推論出正確的修復方向，因為前瞻性推理需要足夠的線索才能產生可靠的預測。此外，若前沿之間的關聯不明確或任務結構高度動態，持久信念狀態的優先度更新可能失去意義，導致探索效率下降。診斷閘門若設定過嚴，可能錯失部分本可執行的機會；若設定過寬，則可能讓代理嘗試無意義的方向。

## 實務應用指南

### 適用場景

BELIEFWEAVER 的核心價值在於「跨嘗試累積證據」與「前瞻性推理」，特別適合以下場景：

**1. 自動化軟體工程（SWE-Bench 類任務）**
在大型程式碼倉庫中修復跨檔案、跨模組的 bug 時，早期的錯誤假設（例如誤判根因模組）往往要到後續測試才會顯現。BELIEFWEAVER 的關聯式信念狀態可保留每次嘗試的證據，並透過 IWM 評估「換個根因假設重試」是否更值得探索，避免在錯誤方向上反覆提交修補。

**2. 自主研究助理（Deep Research / Literature Mining）**
當代理需要從數十篇論文中抽取資料、交叉驗證假設時，若第一步選錯了搜尋關鍵字，後續所有推論都會失準。BELIEFWEAVER 的回溯機制可保留先前查詢的觀察，並透過前沿關聯推理判斷「換一組關鍵字」或「換一個資料來源」是否更可能產出有效證據。

**3. 終端機 / DevOps 自動化（CI/CD 故障排除）**
在長時間的部署、除錯流程中，失敗往往源自多步之前的設定錯誤。BELIEFWEAVER 的檢查點機制允許代理回到先前的環境狀態，同時保留所有失敗嘗試的證據，用 IWM 評估「重試 vs. 換修復路徑」的預期進度。

**4. 機器學習 pipeline 自動化（MLEvolve / AutoML）**
在特徵工程、模型選擇、超參數調校的迭代流程中，單次失敗的證據（例如某個特徵導致資料洩漏）應該影響後續所有相關前沿的優先度。BELIEFWEAVER 的持久探索狀態正好支援這種「跨分支學習」。

**5. 企業級 RPA 與流程自動化**
當機器人流程涉及多個系統、需要數百步操作才能完成時（例如月底結帳、跨系統對帳），任何中段的錯誤都會讓整條流程卡住。BELIEFWEAVER 的診斷性證據閘門可避免在「明知會失敗」的狀態下繼續執行，節省企業級 API 與時間成本。

**資料需求**

- **檢查點序列化機制**：環境狀態必須可序列化與還原（檔案系統快照、Docker commit、資料庫 transaction log 等）。

- **教師模型 API**：原版的 IWM 推理仰賴大型語言模型（GPT-4 / Claude 等等級），需準備對應的 API 額度或自架推論服務。

- **環境執行沙箱**：每個任務需要隔離、可重置的執行環境（容器化或 VM），以支援回溯與檢查點。

**技能門檻**
- 熟悉 LLM agent 框架（LangGraph、AutoGen、Terminus-2 等）並能擴充其狀態管理。
- 具備強化學習 / 行為複製基礎，理解 SFT 與 on-policy 蒸餾的差異。
- 能設計任務專屬的驗證器，這是 BELIEFWEAVER 能否發揮效果的關鍵瓶頸。
- 具備分散式訓練經驗（DeepSpeed / FSDP）以處理 9B 模型的蒸餾。

2. 實作「關聯式信念狀態」的資料結構：定義 frontier、attempt、observation、checkpoint 四類節點及其關聯。
3. 將原生 Terminus-2 代理包裝成可記錄每次嘗試結果的工具呼叫介面。
4. 實作「一元證據因子」更新規則：根據驗證器輸出，調整對應前沿的優先度分數。
5. 實作「診斷性證據閘門」：當某前沿被判定為「執行後必失敗」時，跳過執行直接標記。

**階段二：整合 IWM（4–8 週）**
6. 設計 IWM 的 prompt 模板：要求模型評估「修復假設的可行性」、「預期進度」、「前沿之間的關聯」。

8. 引入回溯機制：當某前沿連續失敗 N 次，自動回到最近的檢查點並重新評估相關前沿。
9. 在單一基準上跑出 baseline 對照，確認信念更新與 IWM 確實帶來正向改善。

**階段三：蒸餾學生模型（8–16 週）**
10. 蒐集教師代理在多個基準上的成功軌跡，標註每步的 IWM 推理內容。

12. 進行 OPD：讓學生模型在環境中實際執行，使用教師的回饋進行策略精煉。
13. 評估學生模型在最終分數與 API 成本上的取捨，目標是 ≥9.8 百分點改善且 ≥54.8% 成本下降。

16. 設計 A/B 測試框架，比較原生代理與 BELIEFWEAVER 在真實業務指標上的差異。

### 潛在風險與注意事項

**風險一：驗證器品質決定成敗**
BELIEFWEAVER 高度依賴驗證器輸出的證據品質。若驗證器本身有誤（例如單元測試覆蓋不足），信念更新會朝錯誤方向累積。**緩解方式**：對驗證器本身進行 fuzz testing，並設計「驗證器信心分數」作為證據因子的權重。

**風險二：信念狀態膨脹導致推論成本失控**
隨著任務推進，frontier、attempt、observation 數量會快速增長，每次 IWM 推理都需要考慮這些上下文，可能造成 token 爆炸。**緩解方式**：實作「證據摘要」機制，定期將舊觀察壓縮成聚合統計；並對前沿設定 TTL（存活時間），淘汰長期無進展的假設。

**風險三：回溯過於頻繁造成任務無法收斂**
若診斷性證據閘門過於敏感，代理可能陷入「懷疑一切—回溯—再懷疑」的無限循環。**緩解方式**：設定最大回溯深度與全域嘗試次數上限；並讓 IWM 在評估時考慮「繼續執行 vs. 回溯」的預期成本。

**風險四：蒸餾後的學生模型在分布外任務失效**
9B 學生模型在訓練基準上表現良好，但面對新型任務時可能無法泛化 IWM 的推理模式。**緩解方式**：保留「教師 fallback」機制，當學生模型信心度低於閾值時自動切換回教師推理；並持續以新任務軌跡進行增量蒸餾。

**風險五：檢查點還原的副作用**
在真實環境中，檢查點還原可能無法完全清除副作用（例如外部 API 已送出無法撤回的請求、資料庫已有不可逆變更）。**緩解方式**：設計「邏輯回溯」而非「物理回溯」——只重置代理內部狀態，外部副作用透過補償交易（compensating transaction）處理。

### 與其他技術的整合建議

**與 LangGraph / AutoGen 整合**
BELIEFWEAVER 的信念狀態可作為 LangGraph 的「全域狀態」擴充，將 frontier 優先度作為 conditional edge 的路由依據；AutoGen 則可將 IWM 包裝成一個特殊的「反思代理群組」，在主代理每次失敗後自動觸發。

**與 Terminus-2 / SWE-Agent 整合**
將 BELIEFWEAVER 的回溯與信念更新層「外掛」在 Terminus-2 之上，保留其原生工具呼叫介面，僅在「何時回溯」與「下一步試什麼」兩個決策點介入，實作成本最低。

**與 RAG / 知識圖譜整合**
將「前沿關聯」改為從外部知識圖譜查詢（例如「這個檔案被哪些測試覆蓋」），可讓 IWM 的關聯推理更精確，減少對模型內部知識的依賴。

**與 RLHF / 偏好學習整合**
信念狀態中的前沿優先度本質上是一種「隱式獎訊」，可進一步用於訓練偏好模型：讓人類標註「哪個前沿更值得探索」，再以 DPO 或 PPO 訓練代理本體。

**與監控與可觀測性平台整合**
將每次信念更新、回溯決策、IWM 推理內容串流至 Langfuse、Phoenix 等可觀測性平台，方便除錯與事後分析；對企業部署而言，這也是合規審計的關鍵。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先跳過第 3 節的問題形式化，直接閱讀第 1 節的動機段落，理解「為什麼長程代理會卡在錯誤方向」這個核心痛點。接著看圖 1（若有）的系統架構圖，建立「信念狀態 + IWM + 回溯」的三層心智模型。最後回到第 4 節的實驗結果，體會 5.1 與 9.8 這兩個數字在實務上的意義——前者是「框架本身的改善」，後者是「蒸餾後學生模型相對原生基準的改善」，兩者衡量的是不同對象。

**給 AI 工程師**：重點關注第 3 節的問題形式化與第 4 節的消融實驗，特別是「執行證據 vs. 診斷性證據」的分離設計，這是 BELIEFWEAVER 與一般 tree-search 方法最大的差異。實作上，建議先在 LangGraph 中重現「一元證據因子更新」這個最小單元，驗證信念更新確實能改變代理行為後，再投入 IWM 的 prompt 工程。蒸餾階段的 OPD 是降低生產成本的關鍵，但需要先確保教師模型的軌跡品質穩定。

**給研究者**：本文最大的理論貢獻在於將「證據」明確區分為「更新優先度」與「控制執行資格」兩類，並證明這種分離設計在長程任務上優於傳統的樹狀搜尋。建議進一步探索：(1) 一元證據因子是否可推廣為高階（pairwise 或 higher-order）因子；(2) IWM 的推理內容能否以形式化邏輯表達，以支援更嚴格的正確性證明；(3) 信念狀態的「遺忘機制」如何影響長期學習效率。此外，與 Agentic Uncertainty（Zhang et al., 2026c）的比較值得深入——兩者都用不確定性引導探索，但 BELIEFWEAVER 用的是「驗證器依據的外部證據」而非「模型內部的 epistemic uncertainty」，這條路線在 RLHF 時代特別值得延伸。

**給產品經理**：BELIEFWEAVER 的商業價值不在於「更聰明的代理」，而在於「更便宜的代理」——54.8% 的 API 成本下降對任何規模化部署都是實質的毛利改善。建議在評估導入時關注三個指標：(1) 任務完成率（最終分數）的提升幅度；(2) 單次任務的平均 API 成本；(3) 「卡在錯誤方向」的人為介入頻率。第三點尤其重要，因為 BELIEFWEAVER 的核心承諾是「讓代理自己學會換方向」，這直接降低了人類監督成本。導入路徑上，建議從「失敗成本高、可自動化驗證」的任務開始（例如自動化測試、CI/CD 除錯），避開「驗證器難設計」的開放式任務。
