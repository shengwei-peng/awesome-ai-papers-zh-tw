## 摘要翻譯

智慧代理技能（Agent Skill）將操作程序（Operational Procedures）與領域專業知識（Domain Expertise）編碼為可重複使用的知識資產（Knowledge Assets），然而其以明文（Plaintext）形式分發（Distribution），使其暴露於未經授權的複製（Unauthorized Copying）與洩漏之中。然而，技能所有權驗證（Ownership Verification）與洩漏追蹤（Leakage Tracing）的實務機制仍未充分發展。在分發前進行水印嵌入（Watermark Embedding）提供了一種潛在的解決方案，但結構化且精簡的技能指令對事實與程序的準確性提出了嚴格的要求。為了解決這些挑戰，我們提出了 SkillMarker，一種基於 KGW 的水印方法，同時兼顧功能保留（Functionality Preservation）與強健的水印嵌入。SkillMarker 將品質約束改寫（Quality-constrained Rewriting）與信號導向候選搜尋（Signal-oriented Candidate Search）加以整合。前者將必要的知識與彈性的表達區分開來，以維持指令保真度（Instruction Fidelity）；後者則在保留約束（Preservation Constraints）下探索替代表達（Alternative Expressions），以獲取更強的水印信號（Watermark Signal）。我們釋出了一個開源工具包（Open-source Toolkit），整合水印嵌入、品質稽核（Quality Auditing）與偵測（Detection）功能，以支援智慧代理技能的保護。SkillMarker 旨在支援分散式技能生態系統（Skill Ecosystem）中的所有權驗證與洩漏追蹤，其中內容可能被全部或部分複製，或被整合至其他技能中。

### 核心貢獻（3～5點）
- **問題揭示**：系統性地指出智慧代理技能以明文分發所面臨的未經授權複製與洩漏風險，以及現有所有權驗證與洩漏追蹤機制的不足。
- **方法創新**：提出 SkillMarker 水印方法，基於 KGW 框架，同時兼顧功能保留與強健的水印嵌入，解決結構化技能指令對準確性的嚴格要求。
- **雙機制整合設計**：將「品質約束改寫」與「信號導向候選搜尋」兩種機制加以整合——前者分離必要知識與彈性表達以維持指令保真度，後者在保留約束下探索替代表達以強化水印信號。
- **實務工具釋出**：發布整合水印嵌入、品質稽核與偵測功能的開源工具包，提供完整的技能保護工作流程。
- **應用場景定位**：明確將方法應用於分散式技能生態系統，支援內容遭全部或部分複製、或被整合至其他技能等情境下的所有權驗證與洩漏追蹤。

### 適合對象
- **人工智慧安全與水印技術研究者**：從事文字水印、大語言模型（LLM）輸出溯源或智慧代理安全相關研究的人員。
- **智慧代理技能開發者與平台經營者**：負責設計、建置或維運智慧代理技能生態系統的工程師與架構師。
- **智慧財產權與知識資產保護從業者**：關注 AI 時代下可重用知識資產之所有權驗證與洩漏追蹤議題的實務工作者。
- **密碼學與安全（Cryptography and Security, cs.CR）社群成員**：對數位浮水印、內容溯源與代理行為（Agent Behavior）保護機制感興趣的研究者。

## 深度分析

#### 方法論解析

SkillMarker 的方法論建立在 KGW（Kirchenbauer et al., 2023）水印框架之上，並針對智慧代理技能（Agent Skill）這類特殊文本進行了深度改造。其核心設計理念是：在受限的改寫空間中，同時達成功能保留（Functionality Preservation）與強水印信號（Watermark Signal）嵌入兩個看似矛盾的目標。

**KGW 基礎機制回顧**

KGW 方法的核心是利用一個密鑰（key）$k$ 與前一個詞元（token）$w_{t-1}$，透過偽隨機函數將詞彙表 $V$ 劃分為綠名單（green list）$G_t$ 與紅名單（red list）$R_t$，其中綠名單比例由 $\gamma \in (0,1)$ 控制。在生成過程中，對綠名單詞元施加大小為 $\delta > 0$ 的 logit 偏置（Logit Bias），使模型傾向於選擇綠名單詞元。檢測時，透過統計可疑文本（Suspect Text）中綠名單詞元的比例，並結合 z-score 檢定來判斷水印是否存在。SkillMarker 完整繼承了這套機制，並引入豁免集合 $E \subset V$ 來排除特定詞元（如標點、結構符號）的偏置與計分。

**品質約束改寫（Quality-constrained Rewriting）**

這是 SkillMarker 應對挑戰 C1 的關鍵設計。方法論將技能文本區分為兩類：

1. **受保護內容（Protected Content）**：包括程式碼區塊、結構分隔符、已識別的字面值（如 API 識別碼、數值閾值），以及結構未解析的區域。這些內容在改寫過程中必須保持完全不變。論文中以 `if attempts >= 3:` 為例，說明將 `>=` 改為 `>` 會改變重試限制的觸發時機，導致代理行為（Agent Behavior）改變。

2. **可編輯片段（Editable Spans）**：周圍的散文性文字，允許替代表達（Alternative Expressions）。對於跨越受保護內容邊界的詞元也予以保護，避免破壞語意連貫性。短於特定 token 數閾值的可編輯片段則保持原樣，以維持改寫的效益成本比。

僅有受保護內容的保留並不足以保證指令保真度（Instruction Fidelity）。例如，將所有條件改為「any condition」即使保留了所有閾值，仍會改變決策邏輯。因此，SkillMarker 採用情境學習（in-context learning）方式，在改寫提示（prompt）中結合明確的保留指令（Preservation Instructions）與配對的改寫範例，引導模型在可編輯片段內進行忠實的重新表述。

**信號導向候選搜尋（Signal-oriented Candidate Search）**

這是 SkillMarker 應對挑戰 C2 的核心創新。在每個可編輯片段內，方法使用束搜尋（beam search）在 KGW 偏置分布下探索替代表達。候選評估採用雙重指標：

- **水印信號強度**：以綠名單詞元率（green-token rate）衡量
- **語言流暢度**：以困惑度（Perplexity, PPL）衡量

選擇策略為：在通過保留檢查（Preservation Checks）的候選中，優先選擇綠名單詞元率較高的候選；若綠名單詞元率相同，則以較低 PPL 作為決勝標準。這種設計巧妙地將水印強度與語言品質解耦，使方法能在不犧牲功能性的前提下最大化水印信號。

**重建與檢測流程**

改寫完成後，SkillMarker 將受保護內容按原始順序重建，形成水印化技能 $e_x$。檢測階段支援兩種模式：

1. **全文本檢測**：適用於完整複製的情境
2. **滑動視窗檢測（window-based detection）**：適用於僅有片段（Fragments）的情況，這對於實際洩漏場景至關重要

值得注意的是，檢測過程僅需要分詞器（tokenizer）與水印配置，無需模型推理，這大幅降低了部署成本。

#### 實驗數據解讀

**資料集與任務覆蓋**

論文橫跨四個資料集，涵蓋通用與專業任務。這種設計具有重要意義：通用任務驗證方法在日常場景的適用性，專業任務則測試方法在高度精確、結構化內容（如程式碼、API 呼叫）上的穩健性。雖然論文未在當前文本中列出所有資料集名稱，但從方法論描述可推測應包含程式碼生成、API 操作、決策邏輯等典型技能場景。

**功能保留的量化證據**

實驗結果顯示，水印化技能在任務效能上與原始技能相比，平均僅有可忽略的退化（negligible degradation）。這個結論的關鍵在於「平均」二字——它暗示在不同資料集與任務類型間可能存在差異，但整體波動控制在可接受範圍內。對於實際部署而言，這意味著開發者可以在不犧牲使用者體驗的前提下實施水印保護。

**偵測強健性的雙重驗證**

論文設計了兩個關鍵的技能重用情境來評估水印強健性：

1. **複製貼上（Copy-paste）情境**：偵測方法能夠在僅有 1,536 個連續詞元的複製段落中可靠識別水印。這個閾值具有重要的實務意義——1,536 詞元大約相當於一個中等長度的段落或數個完整段落，代表即使攻擊者僅複製技能的一部分，擁有者仍能主張所有權。

2. **技能合併（Skill Merging）情境**：當水印化技能與多個背景技能合併後，偵測率維持在 72.2% 至 77.8% 之間。這個數據區間值得深入解讀：
   - **下限 72.2%**：在最具挑戰性的合併情境下仍超過 70%，證明方法對內容混合具有實質抵抗力
   - **上限 77.8%**：在較有利的合併條件下接近 80%，顯示方法在多數實際場景中能提供可靠的證據強度
   - **未達 100% 的原因**：合併引入的背景詞元會稀釋綠名單詞元的統計顯著性，這是基於統計水印的固有特性

**綠名單詞元率與 PPL 的取捨**

雖然論文中未提供具體的綠名單詞元率與 PPL 數值，但從方法論描述可推斷：信號導向候選搜尋透過在多個候選中選擇綠名單詞元率最高的版本，理論上能將水印信號強度提升至接近 KGW 上限。PPL 作為決勝標準的設計，則確保了當綠名單詞元率相同時，模型傾向於選擇更自然的表達，這是一種優雅的品質保障機制。

#### 與現有研究的比較

**與 KGW 的關係**

SkillMarker 並非要取代 KGW，而是將其從通用文本生成場景擴展至技能保護場景。相較於原始 KGW 在自由文本上的應用，SkillMarker 的核心貢獻在於：

1. **結構感知**：透過保護內容與可編輯片段的劃分，使方法能處理程式碼、API、數值閾值等結構化元素
2. **信號最大化**：信號導向候選搜尋在受限空間內主動尋找強水印候選，而非被動接受生成結果
3. **雙重評估標準**：綠名單詞元率 + PPL 的組合提供了比單一指標更全面的候選評估

**與其他水印方法的定位**

在文字水印領域，存在多條技術路線：

- **基於同義詞替換的方法**：在詞彙層級進行替換，但難以處理程式碼與結構化內容
- **基於句法轉換的方法**：透過主動被動語態轉換等句法操作嵌入水印，但對技能文本的精確性要求構成挑戰
- **基於神經隱寫的方法**：利用編碼器-解碼器架構，但訓練成本高且泛化性存疑

SkillMarker 的定位是**結構化文本的精確水印**，填補了現有方法在「高精確度需求 + 有限改寫空間」場景下的空白。

**優勢分析**

1. **無需重新訓練**：基於現有 LLM 即可運作，降低部署門檻
2. **檢測無需模型推理**：僅需分詞器與配置，適合大規模部署
3. **支援片段偵測**：滑動視窗機制使其能應對部分複製的現實情境
4. **開源工具包**：整合嵌入、稽核、偵測的全流程支援

**侷限性與挑戰**

1. **依賴 LLM 的改寫能力**：若底層 LLM 對技能領域不熟悉，改寫品質可能下降
2. **統計水印的固有弱點**：面對大規模改寫或翻譯攻擊時，綠名單詞元率可能被稀釋
3. **受保護內容的識別邊界**：對於模糊的結構（如半結構化的 YAML 與散文混合），保護與可編輯的劃分可能存在灰色地帶
4. **合併偵測率未達 100%**：72.2-77.8% 的偵測率在法律證據場景中可能需要進一步強化

#### 可重現性評估

**開源工具包**

論文明確聲明釋出開源工具包（Open-source Toolkit），整合三大功能：

1. **水印嵌入（Watermark Embedding）**：實作品質約束改寫與信號導向候選搜尋

這種端到端的工具鏈設計大幅提升了研究的可重現性，研究者無需從零開始實作即可驗證結果。

**資料集可及性**

雖然當前文本未列出所有資料集名稱，但從「四個資料集跨越通用與專業任務」的描述推測，應包含公開可取得的基準資料集。論文中提到的 1,536 詞元閾值與 72.2-77.8% 偵測率等具體數字，為後續研究者提供了明確的比較基準。

**模型依賴性**

方法論需要具備 logit 存取權的 LLM，這排除了僅提供 API 存取的閉源模型。論文中未明確指定使用的 LLM，但從方法描述推測應為開源模型（如 LLaMA 系列或類似規模的模型）。研究者若要重現實驗，需要：

1. 具備 logit 輸出的開源 LLM
2. 對應的分詞器
3. 水印配置（密鑰、$\gamma$、$\delta$ 等超參數）
4. 評估用的代理執行環境

**可重現性的潛在障礙**

1. **改寫提示的具體內容**：論文中描述了「保留指令 + 配對範例」的設計，但未提供完整的 prompt 模板
2. **受保護內容的識別規則**：對於「結構未解析區域」的判定標準需要更精確的規範
3. **束搜尋的具體參數**：beam width、候選數量等超參數的設定會影響結果

這些細節的公開程度將直接影響第三方重現實驗的準確度。

#### 未來研究方向

**技術深化方向**

1. **自適應保護邊界**：目前的受保護內容識別依賴預定義規則，未來可探索基於語意理解的動態邊界判定，特別是處理半結構化內容（如 Markdown 中的混合段落）

2. **多層次水印**：現有方法在詞元層級運作，可探索結合句法層級與語意層級的多層次水印，提升對抗翻譯攻擊或大規模改寫的強健性

3. **跨語言水印**：隨著多語言技能的普及，需要研究水印在跨語言轉換後的可偵測性，這對國際化的技能生態系統至關重要

**應用擴展方向**

1. **動態技能組合的保護**：當代理從多個技能動態組合行為時，如何在組合後仍保留可追溯性是一個開放問題

2. **與智慧財產權框架的整合**：水印技術需要與法律實務接軌，研究如何將統計偵測結果轉化為具有法律效力的證據

3. **隱私保護的水印**：在保護擁有者權益的同時，如何避免水印本身洩露敏感資訊（如密鑰與擁有者身分的關聯）

**理論研究方向**

1. **資訊理論界限**：在給定的功能保留約束下，水印信號的最大可嵌入資訊量是什麼？這需要嚴格的理論分析

2. **對抗性強健性**：面對已知水印機制的對手，如何設計更強健的水印？這涉及博弈論與密碼學的交叉

3. **偵測閾值的理論基礎**：1,536 詞元的閾值是經驗值還是理論最優？是否存在任務自適應的閾值選擇機制

**生態系統方向**

1. **標準化水印協議**：推動業界對技能水印格式的標準化，使不同開發者的工具能互通

2. **去中心化追溯**：結合區塊鏈等技術，實現水印密鑰與擁有者身分的去中心化綁定

3. **開源治理模型**：在開源技能生態中，如何平衡開放性與擁有者權益是一個治理層面的挑戰

這些方向不僅能推動水印技術本身的進步，也將促進智慧代理技能生態系統的健康發展，使開發者更願意分享高品質的領域專業知識（Domain Expertise），最終受益於整個 AI 社群。

## 論文問答

**Q1：為什麼智慧代理技能（Agent Skill）的所有權保護是一個重要且未被解決的問題？**
A：智慧代理技能將領域專業知識編碼為可重複使用的指令與資源，使組織與開發者能將寶貴的專業能力跨任務部署，但這些技能以明文形式分發，使其極易被複製、轉散布或被整合進其他技能中。這種風險在技能生態系統中尤其嚴峻，因為技能內容可能被整段複製、部分片段被擷取，甚至被合併到其他技能中，使得洩漏追蹤變得困難。因此，在分發前對技能文本嵌入水印以支援所有權驗證與洩漏追蹤，是保護這類知識資產的關鍵機制。

**Q2：現有的文字水印方法為何無法直接應用於智慧代理技能？**
A：智慧代理技能具有結構化且緊湊的特性，其指令編碼了精確的操作需求，例如資源引用、決策條件與必要操作，即使微小的改動也可能改變代理行為。傳統水印方法通常假設文本具有較大的改寫彈性，但技能中的程式碼、數值閾值與結構化標記幾乎不容修改，這使得水印嵌入空間極為有限。此外，技能對準確性的嚴格要求意味著即使採用較弱的 logit 偏置也難以產生足夠的水印信號，而較強的偏置則可能破壞關鍵指令，導致功能性失效。

**Q3：SkillMarker 試圖回答的核心研究問題是什麼？**
A：本文的核心研究問題是：我們能否在不損害技能功能性的前提下，為技能嵌入水印以支援所有權驗證與洩漏追蹤？這個問題涉及兩個相互耦合的挑戰——挑戰 C1 是如何在改寫過程中保留技能功能，挑戰 C2 則是如何在有限的改寫自由度下嵌入強水印信號。SkillMarker 透過統一的品質約束改寫與信號導向候選搜尋機制，試圖同時解決這兩個挑戰，使水印後的技能仍能維持其原有的操作正確性。

**Q4：SkillMarker 的核心方法架構為何？它如何運作？**
A：SkillMarker 的核心架構包含三個階段：首先，品質約束改寫將原始技能區分為受保護內容（如程式碼、結構標記與已識別的字面值）與可編輯片段，僅對後者進行改寫以保留操作正確性；其次，信號導向候選搜尋在每個可編輯片段內透過束搜尋（beam search）探索替代表達，並根據綠名單詞元率（green-token rate）排序、以較低的困惑度（perplexity）作為平手決勝依據；最後，重建階段將受保護內容按原始順序還原，並由獨立的品質稽核與偵測模組進行後續處理。

**Q5：SkillMarker 最重要的技術創新是什麼？**
A：最重要的技術創新在於將 KGW 水印機制從一般文本生成情境，轉化為適用於結構化技能文本的雙階段框架。具體而言，品質約束改寫透過解析 Markdown 結構並結合情境學習範例，使改寫過程能區分不可變動的關鍵內容與可彈性表達的散文；而信號導向候選搜尋則將水印強度（綠名單詞元率）作為候選排序的主要指標，使有限的改寫空間能優先用於強化水印信號。這種「先保留、後強化」的設計理念是 SkillMarker 區別於傳統水印方法的關鍵。

**Q6：SkillMarker 在設計上做了哪些關鍵選擇？為何採用 KGW 而非其他水印方法？**
A：SkillMarker 選擇 KGW 是因為其基於綠名單/紅名單的 logit 偏置機制具有偵測時不需要模型推論的優勢，只需分詞器與水印配置即可進行統計檢測，這對實際部署非常重要。在設計細節上，SkillMarker 採用了多項關鍵選擇：設定豁免詞元集合 E 來避免對特定詞元施加偏置、設定可編輯片段的最小詞元數閾值以避免過短片段被改寫、以及使用困惑度作為平手決勝以兼顧語言流暢度。這些選擇共同確保了水印嵌入既強健又不損害技能的可執行性。

**Q7：SkillMarker 在哪些資料集上進行了實驗評估？**
A：根據摘要與全文描述，SkillMarker 在橫跨通用與專業任務的四個資料集上進行了評估，涵蓋了不同領域的技能類型以驗證方法的泛化能力。這種多資料集的設計是為了確保水印方法不僅在特定領域有效，還能在多樣化的技能內容中維持功能保留與水印強度。雖然具體資料集名稱在提供的全文片段中未完整列出，但實驗設計明顯強調了跨領域的實用性驗證。

**Q8：SkillMarker 的關鍵實驗結果為何？**
A：實驗結果顯示，水印後的技能在四個資料集上平均僅有可忽略的任務效能退化，證明了品質約束改寫能有效保留技能功能。在水印強健性方面，偵測方法能一致地識別出包含僅 1,536 個連續詞元的複製段落，展現了對部分複製情境的優異偵測能力。此外，在與多個背景技能合併的情境下，偵測率仍維持在 72.2% 至 77.8% 之間，證明了 SkillMarker 在技能合併攻擊下仍具備可靠的洩漏追蹤能力。

**Q9：SkillMarker 是否進行了消融研究以驗證各元件的貢獻？**
A：根據提供的全文內容，SkillMarker 的方法章節明確描述了品質約束改寫與信號導向候選搜尋兩個核心元件的設計動機與運作機制，並透過實驗展示了整體方法在功能保留與水印強健性上的表現。雖然具體的消融實驗數據在提供的片段中未完整呈現，但方法設計本身已清楚區分了兩個元件的責任分工——前者負責功能性保留，後者負責水印信號強化，這種模組化設計便於單獨評估各元件的貢獻。

**Q10：SkillMarker 的實際應用場景有哪些？**
A：SkillMarker 的主要應用場景包括兩大類：第一是所有權驗證，開發者在發布技能前嵌入帶有密鑰的水印，之後可對可疑文本進行水印檢測以確認其是否源自特定擁有者；第二是洩漏追蹤，透過為不同分發版本指派不同的密鑰，當發現可疑文本時可透過水印信號識別其來源版本。這兩種應用對於技能市集、企業內部技能分享以及開源技能生態系統的治理都具有重要價值。

**Q11：SkillMarker 釋出的開源工具包包含哪些功能？對產品化有何意義？**
A：SkillMarker 釋出的開源工具包整合了三大功能：水印嵌入、品質稽核與水印偵測。這種端到端的整合設計對產品化具有重要意義，因為它降低了實際部署的技術門�——開發者無需自行組合多個工具即可完成完整的保護流程。此外，獨立的品質稽核模組允許在嵌入後對水印文本進行功能驗證，確保分發出去的技能仍能正常運作，這對企業級應用的可靠性要求至關重要。

**Q12：SkillMarker 對智慧代理與水印技術領域的影響為何？**
A：SkillMarker 對智慧代理領域的影響在於，它為技能這種新型知識資產提供了首個系統化的所有權保護框架，填補了技能生態系統中安全機制的空白。對水印技術領域而言，SkillMarker 展示了如何將通用文本水印方法（如 KGW）適配到具有嚴格結構與功能約束的特殊文本類型，這種「約束感知的水印設計」思路可推廣至其他領域，如程式碼水印、API 文件保護等。此外，SkillMarker 對部分複製與合併情境的強健性評估，也為後續研究提供了新的基準。

**Q13：SkillMarker 存在哪些已知的限制？**
A：根據全文描述，SkillMarker 的限制主要來自技能文本本身的特性：對於極度緊湊或幾乎全由受保護內容組成的技能，可編輯片段極少，水印嵌入空間將受到嚴重限制。此外，雖然偵測在 1,536 個連續詞元的複製段落下表現良好，但對於更短片段或經過大幅改寫的可疑文本，偵測能力可能會下降。在技能合併情境下，72.2% 至 77.8% 的偵測率雖然可用，但仍有進一步提升空間，特別是當合併的背景技能數量增加時。

**Q14：SkillMarker 在哪些情境下可能會失敗？**
A：SkillMarker 可能在以下情境下表現不佳：第一，當技能幾乎完全由程式碼、API 識別符或結構化標記組成，導致可編輯片段不足以承載水印信號時；第二，當攻擊者對水印文本進行大幅改寫或翻譯，使得原始詞元序列被大幅替換時；第三，當多個不同來源的技能被深度混合，使得水印信號被稀釋至統計偵測閾值以下時。此外，若攻擊者已知水印密鑰的生成機制，也可能嘗試構造對抗性文本來規避偵測。

**Q15：SkillMarker 未來的研究方向有哪些？**
A：未來研究方向可能包括以下幾個層面：首先，可探索更精細的受保護內容識別機制，例如透過語意分析而非僅依賴結構解析來判斷哪些內容不可更動；其次，可研究適應性更強的水印偏置策略，根據可編輯片段的長度與語境動態調整 logit 偏置強度；此外，可將方法擴展至多語言技能或跨模態技能（如包含圖表的技能）；最後，可探索與其他安全機制（如加密、存取控制）的整合，構建多層次的技能保護體系，以應對更複雜的攻擊場景。

## 實務應用指南

### 適用場景

**1. 企業內部技能市集的版權保護**
大型組織內部常建立技能市集（Skill Marketplace），讓各團隊貢獻領域專業技能供其他代理重複使用。透過 SkillMarker 在發布前嵌入帶有團隊密鑰的水印，當某團隊發現自家技能被未授權複製到其他團隊的代理時，可透過檢測工具比對水印信號確認洩漏來源，並追溯到具體的分發版本。

**2. 付費技能商店的盜版追蹤**
第三方開發者將高價值技能（如金融分析、醫療問診、法律諮詢模板）上架到付費商店販售。賣家為每位購買者指派獨立水印密鑰，當技能在未授權管道（如論壇、雲端硬碟）外流時，可對可疑文本進行檢測，根據水印信號識別是哪一位買家洩漏，便於後續法律追訴或帳號處置。

**3. 開源技能專案的歸屬驗證**
開源社群（如 GitHub 上的 agent-skills 倉庫）常發生「換名重發」爭議。專案維護者可使用 SkillMarker 為每個官方版本嵌入水印，當其他倉庫聲稱「原創」並發布高度相似的技能時，維護者可對其文件進行水印檢測，若偵測到綠名單比例顯著高於隨機基線，即可作為歸屬證據提交給平台申訴。

**4. 跨組織技能合併後的貢獻溯源**
在多代理協作場景中，常將多個技能合併成一個複合技能（例如將「SQL 查詢技能」與「資料視覺化技能」合併）。當合併後的技能被外流時，可使用滑動視窗偵測（window-based detection）對合併文本分段檢測，識別出哪些段落來自哪個原始貢獻者，即使原始技能僅佔合併後文本的一部分。

**5. 教育訓練教材的完整性驗證**
教育機構將專家編寫的技能（如「程式除錯教學技能」、「論文寫作指導技能」）分發給學生。機構可為每個版本嵌入水印，並要求學生提交的作業中包含特定技能片段。教師可透過水印檢測確認學生是否使用了授權版本，避免學生使用未經審核的修改版本導致學習偏差。

### 實作前置條件

**資料準備**
- **原始技能文件**：Markdown 格式的技能本體，需包含完整的程式碼區塊、API 識別符、數值閾值與操作說明。建議長度在數百至數千詞元之間，過短的文件可編輯片段有限，水印信號可能不足。
- **領域測試集**：用於功能保留驗證的任務案例集，應涵蓋技能的核心使用情境。論文中使用四個資料集橫跨通用與專業任務，實作時建議至少準備 20–50 個代表性測試案例。
- **背景技能庫**（可選）：用於模擬技能合併場景的健壯性測試，需準備多個與目標技能無關的背景技能文本。

**運算資源**
- **語言模型推理能力**：水印嵌入階段需要存取模型的輸出 logits，因此必須使用可取得 logits 的開源模型（如 LLaMA、Qwen、Mistral 系列），而非純 API 服務。建議使用 7B–13B 規模的模型以平衡品質與成本。
- **GPU 記憶體**：beam search 候選搜尋需要同時維護多個候選序列，建議至少 24GB VRM（如 A5000、A10）；若使用 70B 以上模型則需多卡配置。
- **偵測階段無需 GPU**：水印偵測只需分詞器與水印配置參數，可在 CPU 上執行，適合部署在低成本伺服器進行批次可疑文本掃描。

**技能前置條件**
- **熟悉 KGW 水印原理**：需理解綠名單/紅名單劃分、logit 偏置 δ、綠名單比例 γ 等核心概念，這是 SkillMarker 的基礎。
- **Markdown 解析能力**：需能正確識別程式碼區塊、列表、表格等結構化元素，以劃分受保護內容與可編輯片段。
- **In-context learning 提示工程經驗**：品質約束改寫依賴精心設計的改寫範例，需具備提示工程實務經驗。
- **統計檢定基礎**：水印偵測使用 z-score 檢定，需理解假設檢定與 p 值的意義，以正確解讀偵測結果。

### 實作步驟建議

**步驟一：環境建置與工具取得**
從論文指定的開源倉庫取得 SkillMarker 工具包，安裝相依套件（PyTorch、Transformers、tiktoken 等）。確認模型權重可在本機載入，並驗證 logits 輸出介面正常運作。

**步驟二：定義水印密鑰與配置參數**
為每位發布對象（團隊、買家、版本）產生獨立密鑰 k，並設定 γ（綠名單比例，建議 0.25）與 δ（logit 偏置強度，建議 2.0）。將密鑰與參數記錄於安全的密鑰管理系統，偵測時需使用相同配置。

**步驟三：解析技能並劃分受保護內容**
使用 Markdown 解析器掃描技能文件，將程式碼區塊、API 識別符、數值閾值、結構化分隔符標記為受保護內容；其餘散文段落劃分為可編輯片段。對於跨邊界的詞元，採取保守策略予以保護，避免破壞語意完整性。

**步驟四：執行品質約束改寫**
為每個可編輯片段建構改寫提示，包含明確的保留指令（如「不可改變決策條件的語意」）與配對的改寫範例。呼叫語言模型進行改寫，並即時驗證改寫後的程式碼與數值是否與原文一致。

**步驟五：執行信號導向候選搜尋**
在每個可編輯片段上，使用 beam search 探索多個候選改寫。計算每個候選的綠名單詞元率（green-token rate）與困惑度（PPL），優先選擇綠名單比例高且 PPL 低的候選。論文中偵測閾值約在 1,536 個連續詞元即可達到穩定偵測。

**步驟六：重組水印技能並執行品質稽核**
將受保護內容按原始順序插入改寫後的可編輯片段，重組為完整的水印技能。使用獨立的品質稽核模組（建議使用不同於改寫模型的評審模型）評估功能保留程度，並在領域測試集上驗證任務效能是否下降。

**步驟七：部署偵測服務**
將水印偵測功能封裝為 API 服務，支援全文本偵測與滑動視窗偵測兩種模式。視窗大小建議設為 1,536 詞元，以對應論文的最低穩定偵測長度。設定自動化告警，當 z-score 超過閾值時通知管理員。

**步驟八：建立營運流程**
制定水印嵌入的標準作業程序（SOP），包括發布前的強制水印檢查、可疑文本的偵測流程、誤判處理程序。定期審查水印參數，根據攻擊演化的情況調整 δ 與 γ。

### 潛在風險與注意事項

**風險一：改寫破壞技能功能性**
即使有受保護內容劃分，散文中的決策邏輯描述仍可能被改寫誤改。例如將「當重試次數超過 3 次時報錯」改寫為「當重試次數超過 3 次時繼續」，將完全改變技能行為。**緩解措施**：建立自動化回歸測試，在水印嵌入後立即在領域測試集上執行，若任務成功率下降超過閾值（如 5%）則拒絕該水印版本並重新生成。

**風險二：logit 偏置過強導致文本不自然**
δ 值過高會使生成文本充斥綠名單詞元，造成語句生硬或語意偏差。**緩解措施**：設定 PPL 上限作為候選篩選條件；提供 δ 的調參指南，建議從 1.0 開始逐步增加，並以人工抽樣評估文本自然度。

**風險三：偵測誤判**
水印偵測基於統計檢定，存在第一類錯誤（將非水印文本誤判為水印）。在低詞元數或高隨機性文本上，誤判率可能上升。**緩解措施**：設定嚴格的 p 值閾值（如 p < 0.001）；要求可疑文本至少包含 1,536 個連續詞元才進行判定；對邊際案例進行人工複審。

**風險四：密鑰外洩導致水印失效**
若攻擊者取得水印密鑰與配置，可輕易移除水印或偽造水印。**緩解措施**：將密鑰儲存於硬體安全模組（HSM）或密鑰管理服務（KMS），實施嚴格的存取控制；定期輪替密鑰；對內部人員進行密鑰保護教育。

**風險五：跨語言或跨領域技能適應性**
論文的實驗涵蓋特定資料集，對於高度專業領域（如醫療、法律）或非英語技能的適用性未經驗證。**緩解措施**：在目標領域上進行小規模先導測試；針對領域特性調整受保護內容的識別規則；考慮為不同領域訓練專屬的改寫提示範例。

**風險六：對抗性改寫攻擊**
攻擊者可能使用同義詞替換、句式重組等技術試圖移除水印。論文中評估了複製貼上與技能合併兩種場景，但更複雜的改寫攻擊（如改寫後再翻譯再翻譯回來）可能降低偵測率。**緩解措施**：結合多種水印方法（如基於格式的隱寫術）作為冗餘防線；持續追蹤水印移除研究的最新進展。

### 與其他技術的整合建議

**與技能市集平台整合**
將 SkillMarker 嵌入技能市集的上架審核流程，作為強制步驟。市集後台管理員為每位上架者產生獨立密鑰，技能上架時自動觸發水印嵌入，並將水印配置加密儲存於技能元資料。下架或投訴處理時，可調用偵測 API 對爭議技能進行驗證。

**與 SIEM 與威脅情報平台整合**
將水印偵測結果串接至企業的 SIEM（Security Information and Event Management）系統，當偵測到水印信號時自動產生告警事件，並關聯至威脅情報平台中的技能資產資料庫。這有助於建立完整的洩漏事件時間軸，支援事件響應與數位鑑識。

**與數位版權管理（DRM）系統互補**
SkillMarker 屬於「被動式」水印，僅能在事後偵測；DRM 屬於「主動式」保護，可限制技能的存取與使用。建議兩者並行部署：DRM 處理存取控制，SkillMarker 處理洩漏後的歸屬追蹤。對於必須以明文分發的場景（如開源專案），SkillMarker 是主要的保護手段。

**與 LLM 代理框架整合**
在 LangChain、AutoGen、CrewAI 等代理框架中，將 SkillMarker 整合為技能載入器的中介層。代理載入技能時自動驗證水印完整性，並在技能組合（composition）時記錄各技能的來源密鑰，方便後續追蹤。

**與程式碼掃描與靜態分析工具整合**
將受保護內容識別規則與 SonarQube、Semgrep 等程式碼掃描工具的規則庫對齊，確保水印嵌入時不會誤改被掃描工具標記為關鍵的程式碼片段。同時，可利用這些工具的 API 識別能力，自動擴展受保護內容的識別範圍。

**與區塊鏈結合建立不可篡改記錄**
將水印密鑰、嵌入時間戳、發布版本雜湊值寫入區塊鏈，建立不可篡改的發布記錄。當發生版權爭議時，可從區塊鏈調取原始記錄作為法律證據，增強水印系統的公信力。

### 給不同背景讀者的閱讀建議

**給初學者**
建議先閱讀第 1 節（Introduction）了解智慧代理技能面臨的版權威脅，以及水印技術為何是潛在解決方案。接著閱讀第 2.1 節的問題定義，掌握水印密鑰、綠名單/紅名單、logit 偏置等基本術語。對於數學細節可先跳過，重點理解「為什麼需要品質約束改寫」與「為什麼需要信號導向候選搜尋」兩個核心動機。可搭配閱讀 Kirchenbauer 等人的原始 KGW 論文，建立水印技術的基礎認知。

**給 AI 工程師**
重點閱讀第 2.2 節的品質約束改寫與信號導向候選搜尋的演算法細節，理解受保護內容的劃分規則、beam search 的候選評分機制（綠名單詞元率 + PPL）。直接使用論文釋出的開源工具包進行概念驗證，評估其與現有技能管線的整合可行性。特別關注第 3 節的實驗結果，特別是四個資料集上的任務效能下降幅度與不同攻擊場景下的偵測率，這些是評估導入價值的關鍵指標。

**給研究者**
深入閱讀第 2 節的完整方法論，特別是品質約束改寫中受保護內容的形式化定義、跨邊界詞元的處理策略，以及信號導向候選搜尋中綠名單詞元率與 PPL 的聯合優化目標。第 3 節的消融實驗（如有）值得仔細分析，了解各模組的貢獻度。可考慮的延伸研究方向包括：將方法擴展至多語言技能、結合語義水印提升抗改寫攻擊能力、探討在程式碼生成技能上的特殊適應。建議在引用時對比同期其他 LLM 水印工作（如 Aaronson、Scott Aaronson 的 Gumbel-max 水印、Christ 等人的 Christ-Gunn-Zamir 水印），定位 SkillMarker 的技術貢獻。

**給產品經理**
聚焦於第 1 節的應用場景描述與第 4 節（若含）的實證討論，理解 SkillMarker 能解決哪些業務問題、無法解決哪些問題。特別注意「1,536 個連續詞元」的最低偵測長度限制，這決定了產品設計中對「片段洩漏」的保護邊界。評估導入時應考慮：技能市集的規模與價值密度、洩漏事件的歷史頻率與影響、現有 DRM 或存取控制措施的不足之處。建議先在非核心技能上進行小規模試點，驗證水印嵌入對使用者體驗的影響後再全面推廣。
