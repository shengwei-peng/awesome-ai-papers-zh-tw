# 國際數學奧林匹亞金牌的開放配方：訓練 Nemotron 用於奧林匹亞數學

## ⚡ TL;DR

本研究探討後訓練與測試時推論如何提升模型在奧林匹亞數學上的自然語言證明生成能力。
提出開放式測試時運算流程，以三個專家檢查點迭代生成、驗證並精煉自然語言證明，無形式化工具。
該系統在 IMO 2026 獲得 30 分達金牌門檻，並開源釋出模型、資料、程式碼與新基準測試。

## 摘要翻譯

我們研究模型後訓練（post-training）與測試時推論（test-time inference）設計如何影響高難度奧林匹亞數學的自然語言證明生成（natural-language proof generation）。以 Nemotron 3 Ultra 為起點，我們使用監督式微調（supervised fine-tuning, SFT）與強化學習（reinforcement learning, RL）訓練兩個專家檢查點（specialist checkpoints），並評估檢查點選擇、驗證（verification）與精煉（refinement）。基於這些發現，我們提出一個開放模型測試時運算（test-time compute）流程。整個系統完全以自然語言運作，不使用形式化證明器（formal prover）、外部工具（external tools）或網際網路存取（internet access）。三個 Nemotron 3 Ultra 檢查點（checkpoints）——一般可用模型（general-availability model）與兩個後訓練專家檢查點——驅動迭代搜尋（iterative search），生成、驗證並精煉候選證明（candidate proofs）；隨後一個獨立的高運算階段（high-compute stage）選出每個最終提交（final submission）。該系統在 2026 年國際數學奧林匹亞（IMO 2026）獲得 30/42 分，達到金牌門檻（gold-medal threshold）。我們釋出兩個後訓練檢查點、訓練資料、訓練與推論程式碼、提交解答（submitted solutions），以及 Nemotron-IMO-Bench——一個包含 200 道全新奧林匹亞級問題（olympiad-level problems）的基準測試（benchmark）。

### 核心貢獻（3～5點）
- 從 Nemotron 3 Ultra 出發，透過監督式微調（SFT）與強化學習（RL）訓練兩個數學專家檢查點，並系統性評估檢查點選擇、驗證與精煉對證明品質的影響。
- 提出一套完全以自然語言運作的開放模型測試時運算流程，無需形式化證明器、外部工具或網際網路存取，即可迭代生成、驗證、精煉候選證明，並由高運算階段選出最終提交。
- 在 IMO 2026 取得 30/42 分，達到金牌門檻，證明此方法在奧林匹亞級數學證明生成上的競爭力。
- 公開釋出兩個後訓練檢查點、訓練資料、訓練與推論程式碼、正式提交解答，以及 200 道新題組成的 Nemotron-IMO-Bench 基準測試，促進可重現性與後續研究。

### 適合對象
對大型語言模型後訓練、測試時運算、數學推理與自動證明生成有興趣的研究人員與工程師，特別是關注開放模型、奧林匹亞級數學競賽，以及希望複現或擴展此系統的學術與產業團隊。

## 深度分析

#### 方法論解析

本研究的核心方法論可視為一個「後訓練（post-training）＋測試時運算（test-time compute）」的兩階段框架：首先針對 Nemotron 3 Ultra（550B-A55B 的 Mixture-of-Experts 架構）進行數學證明專家化，再於推論階段透過多角色迭代搜尋（iterative search）產生、驗證與精煉候選證明（candidate proofs），最後以高運算階段（high-compute stage）選出最終提交（final submission）。

##### 1. 模型後訓練：從通用基礎模型到數學專家檢查點

系統使用三個 Nemotron-3-Ultra 檢查點（checkpoint）：

- **Nemotron-3-Ultra-GA**：一般可用模型（general-availability model），未經修改的基礎模型（base model）。
- **Nemotron-3-Ultra-SFT**：經監督式微調（supervised fine-tuning, SFT）的專家檢查點（specialist checkpoint）。
- **Nemotron-3-Ultra-RL**：經強化學習（reinforcement learning, RL）進一步訓練的專家檢查點。

**SFT 階段**採用長上下文設定（最大序列長度 425,984 tokens），以 BF16 精度優化標準的逐 token 交叉熵損失。訓練語料來自 AoPS（Art of Problem Solving）子集的 Nemotron-Math-Proofs-v1，共 15,879 道高難度證明題，並透過 DeepSeek-V4-Pro 進行多階段合成資料（synthetic data）生成，同時監督「長篇證明建構」與「證明驗證」兩種能力。這意味著 SFT 不僅教模型寫證明，也教模型判斷證明是否正確，為後續 verification（驗證）與 refinement（精煉）角色奠定基礎。

**RL 階段**則在 SFT 之上，使用專屬的 RL 問題集（RL problem set）進行後訓練。雖然文中未詳細說明獎勵函數設計，但可推測其目標是讓模型在證明生成與修正的決策上，學會選擇能通過驗證、結構更嚴謹、最終可獲得高分的證明路徑。

##### 2. 推論流程：生成—驗證—精煉的迭代搜尋

推論階段將三個檢查點指派為不同角色：

- **生成（generation）**：提出候選證明。
- **驗證（verification）**：判斷候選證明的正確性並產生回饋。
- **精煉（refinement）**：根據驗證回饋修正候選證明。

整個系統完全以自然語言（natural language）運作：接收 LaTeX 題目敘述，輸出自然語言解答，不使用形式化證明器（formal prover）、外部工具（external tools）或網際網路存取（internet access）。這與 AlphaProof 等依賴 Lean 等符號驗證的系統形成鮮明對比。

迭代搜尋的邏輯可理解為：先由生成模型產生多個候選證明，再由驗證模型評分並給出回饋，接著由精煉模型根據回饋進行修正；此過程可反覆進行，逐步提升候選證明的品質。最後，一個獨立的高運算階段（high-compute stage）從眾多候選中選出最終提交。這種設計體現了測試時運算（test-time compute）的規模化：透過在推論階段投入更多運算資源（生成更多樣本、反覆驗證與精煉）來彌補單一生成樣本的不足。

#### 實驗數據解讀

本研究的實驗設計圍繞一個 30 題的開發集（development set）進行，並在 IMO 2026 正式競賽中取得 30/42 分，達到金牌門檻（gold-medal threshold）。以下從數據意義與可能隱含的訊息進行解讀。

##### 1. 開發集上的消融實驗

文中指出，研究團隊在開發集上評估了：
- **檢查點選擇（checkpoint choice）**：比較 GA、SFT、RL 三個檢查點在不同角色（生成、驗證、精煉）下的表現。
- **驗證機制（verification）**：驗證模型對候選證明的正確性判斷是否可靠，以及回饋品質如何影響後續精煉。
- **完整集成模型（full ensemble）**：多模型協作與迭代搜尋的最終效果。

雖然詳細數據表格未在提供的上下文中列出，但從最終競賽結果可推論：單一檢查點的直接生成可能僅達銀牌水準（silver-medal level）或更低，而透過「專家分工＋迭代搜尋＋高運算選擇」的組合，才將系統推升至金牌水準。這暗示驗證與精煉環節對最終分數的邊際貢獻極大。

##### 2. IMO 2026 競賽成績的意義

30/42 分代表在六道題目中平均約解出 5 題（IMO 每題 7 分）。這與 2025 年 Gemini Deep Think 與 OpenAI 實驗模型達到的金牌水準相當，顯示自然語言證明生成（natural-language proof generation）已能穩定達到國際數學奧林匹亞（IMO）金牌門檻。值得注意的是，本系統是「開放模型」（open model），相較於閉源商業模型，這為學術界提供了可檢驗、可複製的研究對象。

##### 3. 資源核算（resource accounting）

本研究強調釋出運算時數（compute hours）與生成 token 數量（generated-token counts）等資源核算資訊。這對於理解測試時運算（test-time compute）的實際成本至關重要。高運算階段（high-compute stage）雖然提升了準確率，但也意味著單題推論可能消耗大量 GPU 時數與生成 token。未來若要在教育或實務場景部署，如何在「效能」與「成本」之間取捨將是關鍵議題。

#### 與現有研究的比較

##### 1. 相對於形式化／神經符號方法

過去 IMO 競賽中的領先系統多採用神經符號（neuro-symbolic）或形式化方法：
- **AlphaGeometry** 使用神經語言模型引導符號引擎。
- **AlphaProof / AlphaGeometry 2** 在 IMO 2024 達到接近人類金牌門檻。
- **DeepSeek-Prover、GoedelProver、SeedProver** 等基於 Lean 的神經定理證明器，依賴可靠的符號驗證來生成大規模訓練資料與搜尋高分支空間。

本研究的系統不使用形式化證明器（formal prover），完全以自然語言運作。其優勢在於：
- **通用性**：無需將每道題目轉換為形式語言，可處理代數、組合、數論、幾何等多元領域。
- **可解釋性**：輸出與人類數學家撰寫的證明格式一致，便於人類審閱與教學應用。
- **開放性**：釋出模型權重、資料與程式碼，降低研究門檻。

然而，其侷限也顯而易見：
- **驗證可靠性**：自然語言驗證模型可能產生誤判，尤其是面對巧妙構造的反例或邏輯漏洞時，無法像 Lean 那樣提供絕對正確性保證。
- **資料污染風險**：訓練資料來自公開數學論壇與競賽題庫，若開發集或競賽題目與訓練資料重疊，可能高估真實推理能力。
- **運算成本**：相較於單一形式化搜尋，自然語言迭代搜尋需要生成與評估大量文本，成本更高。

##### 2. 相對於其他自然語言證明系統

IMO 2025 的自然語言突破包括：
- **Gemini Deep Think**
- **OpenAI 實驗模型**
- **Huang & Yang (2025)** 的模型無關驗證—精煉流程
- **Nomos** 在 Putnam 2025 使用後訓練模型與平行生成、評分、整合機制
- **DeepSeekMath-V2** 訓練生成器、驗證器與後設驗證器，並擴大驗證運算
- **Aletheia** 使用 Gemini Deep Think 作為研究代理，具備 Generator、Verifier、Reviser 子代理

本研究的差異化定位在於：
- **開源釋出**：不同於 Gemini Deep Think 或 OpenAI 實驗模型的閉源性質，本研究釋出兩個後訓練檢查點、訓練資料、推論程式碼與提交解答。
- **簡潔的單一模型家族**：三個檢查點皆源自 Nemotron 3 Ultra，降低多模型整合的複雜度。
- **無外部工具**：相較於 Aletheia 等研究代理可能使用多種工具，本系統僅依賴自然語言推論，展示單一模型家族在極端測試時運算下的潛力。

#### 可重現性評估

本研究在可重現性（reproducibility）方面採取了相當積極的態度，釋出內容包括：

| 類別 | 釋出內容 | 授權／位置 |
|---|---|---|
| 模型權重 | Nemotron-3-Ultra-SFT、Nemotron-3-Ultra-RL | Hugging Face，OpenMDW-1.1 license |
| 基礎模型 | Nemotron-3-Ultra-GA | Hugging Face |
| 訓練資料 | SFT corpus、RL problem set | Hugging Face，CC BY 4.0 license |
| 基準測試 | Nemotron-IMO-Bench（200 道新題）＋ 30 題開發集 | Hugging Face，CC BY 4.0 license |
| 程式碼 | 推論流程、開發集組建腳本、RL 訓練食譜 | NeMo-Skills / NeMo-RL on GitHub |
| 提交解答 | IMO 2026 正式提交的證明 | 一併釋出 |
| 資源核算 | 運算時數、生成 token 數量 | 報告中說明 |

##### 可重現性的優勢

1. **完整的模型權重釋出**：釋出 SFT 與 RL 兩個專家檢查點，使其他研究者能直接複製推論流程，並進行微調或角色替換實驗。
2. **訓練資料透明**：SFT corpus 與 RL problem set 的公開，讓社群能檢驗資料來源、難度分佈與潛在污染問題。
3. **程式碼開源**：NeMo-Skills 與 NeMo-RL 提供推論與訓練腳本，降低重現門檻。
4. **新基準測試**：Nemotron-IMO-Bench 包含 200 道全新奧林匹亞級問題，有助於未來研究進行公平比較，減少資料污染爭議。

##### 可重現性的挑戰

1. **硬體門檻**：Nemotron 3 Ultra 為 550B-A55B 的超大規模模型，推論與後訓練需要大量 GPU 資源，一般學術實驗室可能難以完全重現。
2. **高運算推論成本**：迭代搜尋與高運算選擇階段需要生成大量 token，即使程式碼公開，完整複製競賽級結果仍需昂貴運算。
3. **授權限制**：OpenMDW-1.1 license 雖開放模型權重使用，但研究者仍需確認商業應用、衍生模型釋出等條款是否符合需求。
4. **資料生成細節**：SFT 語料使用 DeepSeek-V4-Pro 進行合成，若該模型或提示模板未完全公開，資料生成的可重現性會受到一定限制。

整體而言，本研究在開放科學（open science）層面已達到目前 IMO 級數學 AI 研究的領先水準，但硬體與運算成本仍是實際重現的主要障礙。

#### 未來研究方向

基於本研究的架構與侷限，以下幾個方向值得進一步探索：

##### 1. 自然語言與形式化驗證的混合系統

雖然本系統證明了純自然語言方法可達金牌門檻，但自然語言驗證的可靠性仍有上限。未來可研究如何將自然語言生成與 Lean、Coq 等形式化證明器（formal prover）結合：例如以自然語言產生證明草稿，再自動或半自動轉譯為形式語言進行最終驗證，或利用形式化驗證結果作為 RL 獎勵信號。

##### 2. 更輕量且高效的測試時運算

本系統依賴高運算階段（high-compute stage）與大量生成 token。未來可探索：
- **模型蒸餾（distillation）**：將 Nemotron-3-Ultra-RL 的能力轉移到更小模型（如 Nemotron-Cascade 2 所示）。
- **自適應測試時運算（adaptive test-time compute）**：根據題目難度與驗證信心動態調整生成與精煉次數，避免在簡單題目上浪費資源。
- **驗證器專用強化學習**：單獨訓練更強大的 verifier（驗證器），減少所需候選證明數量。

##### 3. 驗證器與回饋機制的強化

目前驗證與精煉角色由後訓練的通用語言模型兼任。未來可發展專門的驗證模型，並引入：
- **程序性回饋（process-based feedback）**：不僅判斷最終證明對錯，也指出每一步推論的問題。
- **對抗性訓練（adversarial training）**：讓生成器與驗證器互相競爭，提升對隱藏錯誤的辨識能力。
- **人類專家回饋整合**：將 IMO 教練或金牌選手的批改意見納入 RLHF 或 RL 獎勵模型。

##### 4. 從競賽數學延伸至研究級數學

Aletheia 等研究已將類似架構應用於研究級數學。未來可將 Nemotron-IMO 的迭代搜尋框架擴展至：
- 開放性問題探索與猜想生成。
- 跨領域數學（如代數幾何、分析學）的長篇證明。
- 與數學文獻檢索或符號計算工具結合的研究代理（research agent）。

##### 5. 資料污染與評估方法論

隨著訓練資料規模擴大，資料污染（data contamination）風險日益嚴重。未來研究應：
- 建立更嚴格的資料去重與洩漏檢測流程。
- 發展即時生成、未曾公開的新基準測試（如 Nemotron-IMO-Bench 的持續擴充）。
- 區分「記憶型解題」與「泛化型推理」的評估指標。

##### 6. 多模態與幾何證明

IMO 中的幾何題常涉及圖形輔助推理。未來可將自然語言證明系統擴展至多模態（multimodal）設定，結合圖像理解與幾何關係推論，並與 AlphaGeometry 等專用幾何引擎互補。

總結來說，本研究不僅提出了一個達到 IMO 金牌水準的開放自然語言證明系統，也為後續研究提供了完整的基礎設施與清晰的改進路徑：在保持開放性的同時，逐步提升驗證可靠性、降低運算成本，並將能力從競賽數學推向更廣泛的數學研究領域。

## 論文問答

**Q1：這篇論文主要想解決什麼問題？**
A：本研究聚焦於「後訓練（post-training）」與「測試時推論（test-time inference）」設計如何影響困難奧林匹亞數學題的自然語言證明生成。具體來說，作者希望從 Nemotron 3 Ultra 出發，打造一套完全以自然語言運作、無需形式化證明器或外部工具的開源系統，並在 IMO 2026 達到金牌門檻。最終目標不僅是競賽成績，也強調可重現性與未來可擴展性，因此釋出了模型檢查點、訓練資料、程式碼與新基準測試。

**Q2：為什麼 IMO 被視為 AI 數學推理能力的重要試金石？**
A：國際數學奧林匹亞（IMO）長久以來是全球最具聲望的智力競賽之一，題目需要創造性、嚴謹性與多步驟邏輯推理，遠超一般數學題庫的難度。近年 AI 系統在 IMO 的進展迅速，從 2024 年結合形式化驗證的銀牌水準，到 2025 年自然語言模型達到金牌水準，顯示這是衡量高階推理能力的重要標竿。因此，能在 IMO 奪金代表模型具備接近人類頂尖選手的數學證明能力。

**Q3：相較於既有的形式化方法，為何要發展純自然語言的證明系統？**
A：過去的神經符號或形式化方法通常依賴 Lean 等定理證明器與符號引擎，雖然驗證可靠，但需要將題目形式化，彈性與可擴展性受限。自然語言系統可以直接讀取競賽主辦方提供的 LaTeX 題目，並產出人類可讀的解答，流程更接近真實競賽情境。本研究證明，只要透過適當的後訓練與測試時運算，純自然語言的生成、驗證與精煉迴路也能達到 IMO 金牌水準。

**Q4：本系統的核心方法架構是什麼？**
A：系統以三個 Nemotron 3 Ultra 檢查點為基礎，分別是一般可用模型（GA）、監督式微調專家（SFT）與強化學習專家（RL），並在推論流程中扮演生成、驗證、評分與精煉等不同角色。整體採用迭代搜尋：先產生多個候選證明，再由驗證模型判斷正確性並給出回饋，接著精煉模型根據回饋修正證明，最後進入高運算階段選出最終提交的解答。整個流程完全以自然語言進行，不使用形式化證明器、外部工具或網際網路存取。

**Q5：這項研究有哪些關鍵創新？**
A：首先，作者系統性地研究了不同檢查點、驗證機制與多模型集成對證明品質的影響，並提出一套可重現的開源測試時運算流程。其次，釋出了兩個後訓練專家檢查點、訓練資料、推論程式碼與 IMO 2026 的提交解答，大幅降低後續研究的進入門檻。此外，還推出了 Nemotron-IMO-Bench，包含 200 道全新奧林匹亞級題目，為自然語言數學證明研究提供新的評估基準。

**Q6：作者在方法設計上做了哪些重要選擇？**
A：作者選擇以 Nemotron 3 Ultra 為基礎模型，並透過長上下文監督式微調（最長 425,984 tokens）與強化學習訓練出兩個專家檢查點，分別強化證明生成與驗證能力。在推論階段，他們比較了 GA、SFT、RL 三種檢查點在不同角色上的表現，並評估驗證與精煉迴路對最終成績的貢獻。這些設計選擇都在 30 題開發集上進行驗證，以確保系統在正式競賽時能穩定發揮。

**Q7：論文的主要實驗結果與基準測試有哪些？**
A：在 IMO 2026 正式競賽中，本系統獲得 30 分（滿分 42 分），達到金牌門檻，顯示自然語言方法已能與頂尖人類選手媲美。研究還使用了 30 題的開發集來調校與評估後訓練、驗證與集成策略。此外，釋出的 Nemotron-IMO-Bench 包含 200 道與 Titu Andreescu 教授合作設計的全新奧林匹亞級題目，可用於未來的模型能力評估。

**Q8：作者進行了哪些消融研究來驗證各元件的效果？**
A：作者在開發集上評估了檢查點選擇的影響，比較基礎 GA 模型與 SFT、RL 後訓練專家在生成、驗證與精煉任務上的差異。同時也研究了驗證機制本身是否能有效篩選錯誤證明，以及多模型集成與迭代精煉對最終正確率的貢獻。這些消融研究幫助確認：專家化後訓練與測試時運算放大是達成金牌表現的關鍵因素。

**Q9：這套系統的運算成本與資源消耗如何？**
A：論文特別強調資源核算，詳細記錄了競賽執行過程中的運算時數與生成 token 數量，以提升透明度與可重現性。由於採用迭代搜尋與高運算階段的最終選擇策略，系統在測試時使用了大量額外運算資源來換取更高的正確率。這也反映了當前大型語言模型在困難推理任務上的一個重要趨勢：透過測試時運算擴展來提升表現。

**Q10：這項技術有哪些實際應用場景？**
A：這套自然語言證明系統可應用於數學教育、自動家教、競賽準備與研究輔助，因為它能產生人類可讀的完整證明過程。學生可以透過系統獲得詳細解答與回饋，教師也能用它來生成題目解析或評量學生推理過程。由於系統不使用外部工具，部署門檻相對較低，更容易整合到現有的學習平台或教育產品中。

**Q11：若要將此技術產品化，需要考慮哪些因素？**
A：首先必須平衡測試時運算成本與正確率，因為高運算階段會顯著增加推論開銷。其次，自然語言驗證並非絕對可靠，可能遺漏細微錯誤，因此產品中需要額外的可信度機制或人機協作審查。此外，長上下文處理、模型幻覺控制，以及針對不同難度與領域的適應性，也都是實際落地時必須仔細設計的環節。

**Q12：這項研究對 AI 與數學領域可能帶來什麼影響？**
A：本研究證明開源模型透過適當的後訓練與測試時運算，也能在 IMO 達到金牌水準，縮小了開源與閉源前沿系統之間的差距。釋出的模型、資料、程式碼與基準將加速後續在自然語言定理證明與高階推理上的研究。長遠來看，這類系統有望從競賽數學延伸至研究級數學，成為數學家探索與驗證新猜想的重要輔助工具。

**Q13：作者承認了哪些限制？**
A：由於系統完全以自然語言運作，沒有形式化證明器的嚴格保證，因此可能產生看似合理但實際錯誤的證明。此外，達到金牌表現需要大量測試時運算資源，對於資源有限的研究者或應用場景仍具挑戰。最後，儘管系統在 IMO 2026 表現優異，但並未解決所有題目，顯示在極端困難問題上仍有進步空間。

**Q14：這套系統可能在哪些類型的題目或情境下失敗？**
A：對於需要複雜幾何構造、極長推理鏈或高深數論技巧的題目，生成模型可能難以找到正確思路，驗證模型也可能無法識別隱藏錯誤。若精煉過程中的回饋本身有偏誤，還可能導致錯誤在迭代中被強化而非修正。此外，當題目敘述存在歧義或需要非標準定義時，純自然語言系統的理解與推理穩定性也可能下降。

**Q15：未來可以朝哪些方向繼續發展？**
A：未來可以探索將自然語言推理與輕量級形式化驗證結合，在保持可讀性的同時提升正確性保證。另一個方向是改進驗證模型的可靠性，使其能更精準地發現細微錯誤並給出有效回饋。此外，降低測試時運算成本、擴展到研究級數學問題，以及建立更大規模、更多元領域的基準測試，都是值得持續投入的研究課題。

### 實作前置條件

**資料準備**
- 需具備高品質的證明語料庫，例如類似 Nemotron-Math-Proofs-v3-SFT 的長篇證明資料，涵蓋數論、代數、幾何與組合等領域。
- 需準備用於強化學習的問題集（RL problem set），並搭配可自動評分的標準答案或評分規則。
- 建議擁有領域專家（如數學奧林匹亞教練）協助標註與驗證資料品質。

**運算資源**
- 基礎模型為 Nemotron 3 Ultra（550B-A55B），推論與後訓練需大量 GPU 叢集資源。
- 監督式微調需支援長上下文（最大序列長度達 425,984 tokens）的 BF16 訓練環境。
- 測試時運算（test-time compute）涉及迭代生成、驗證與精煉，需預留充足的推論運算時數與生成 token 配額。

**技術與人才**
- 熟悉大型語言模型的監督式微調與強化學習流程。
- 具備分散式訓練與推論經驗，能操作 NeMo-Skills 與 NeMo-RL 等框架。
- 需有數學領域知識，能判斷自然語言證明的正確性並設計驗證策略。

### 實作步驟建議

1. **環境與模型準備**：從 Hugging Face 取得 Nemotron-3-Ultra-GA 基礎模型，並確認硬體環境可載入 550B-A55B 權重。安裝 NeMo-Skills 與 NeMo-RL 推論及訓練程式碼。

2. **資料建構與後訓練**：蒐集並清理證明語料，執行監督式微調以產生 Nemotron-3-Ultra-SFT；接著以奧林匹亞級問題集進行強化學習，訓練出 Nemotron-3-Ultra-RL。兩個專家檢查點分別承擔生成、驗證與精煉角色。

3. **推論流程建置**：實作迭代搜尋流程，讓生成器產出多組候選證明，驗證器判斷正確性並產出回饋，精煉器再根據回饋修正證明。此流程完全以自然語言運作，不倚賴形式化證明器或外部工具。

4. **高運算最終選擇階段**：在迭代搜尋後，加入高運算階段對候選證明進行最終評分與篩選，選出最可信的解答作為最終提交。

5. **評估與部署**：使用 Nemotron-IMO-Bench 或自建的開發集進行系統評估，監控生成 token 數量、運算時數與通過率。部署時建立人機協作審查機制，並記錄資源核算。

### 潛在風險與注意事項

- **證明幻覺與邏輯漏洞**：自然語言證明可能出現看似合理但實際錯誤的推論。建議搭配多重驗證器與高運算最終選擇階段，並保留人工複審關卡。

- **運算成本高昂**：550B 等級模型的迭代搜尋與高運算階段會消耗大量 GPU 時數與生成 token。建議先以小規模開發集估算成本，再決定正式部署規模。

- **驗證器本身的偏誤**：驗證檢查點可能對正確證明給出錯誤回饋，或對錯誤證明過度寬容。應持續以專家標註資料校準驗證器，並結合多模型集成策略。

- **資料污染與過擬合**：訓練資料若包含競賽真題，可能導致模型記憶而非推理。建議使用原創題目（如 Nemotron-IMO-Bench）進行公正評估。

- **授權與合規限制**：釋出的檢查點與資料分別受 OpenMDW-1.1 與 CC BY 4.0 授權條款規範，商業應用前需詳閱授權範圍與歸屬要求。

### 與其他技術的整合建議

- **形式化證明器輔助驗證**：雖然本系統完全以自然語言運作，但可選擇性將關鍵步驟轉譯至 Lean 或 Coq 進行形式化驗證，作為第二層正確性把關。

- **檢索增強生成（RAG）**：連接數學知識庫、定理庫或歷年競賽題庫，在生成證明前提供相關定理與範例，提升證明品質與多樣性。

- **學習管理系統（LMS）整合**：透過 LTI 等標準協定將系統嵌入線上課程平台，讓學生提交作答後自動獲得回饋與精煉建議。

- **人機協作審查介面**：為教練、教師或研究人員設計審查儀表板，顯示候選證明、驗證分數與精煉歷程，支援快速人工覆核。

- **多模型集成與路由**：除了 Nemotron 3 Ultra 系列，可視需求整合其他開源模型作為輔助生成器或驗證器，透過模型路由器動態分配任務。
