JockeyBench 的方法論設計在重複事件預測（Repeated Event Forecasting）領域具有顯著的系統性與嚴謹性，其核心在於將「預測能力」、「適應性」、「資源使用」與「決策價值」四個維度進行解耦評測，避免單一指標掩蓋代理的真實表現。

**資料基礎與資訊控制**：該基準測試建構於 JRDB（日本賽馬資料庫）之上，涵蓋賽事、參賽馬、過往表現、操練紀錄與賽果等關聯紀錄。為防止「未來資訊洩漏」（future leakage），系統採用受限介面（Restricted Interface）強制執行歷史資訊截止點（Historical Information Cut-Offs），並延遲結果釋出（Outcome Release）直至預測封存（Prediction Seal）。值得注意的是，賠率（Odds）與專家評分（Expert Ratings）被刻意排除於代理輸入之外，迫使代理僅能從事實證據（Factual Evidence）建構預測，這一設計排除了市場隱含機率的捷徑，提升了預測品質的純度。

**雙工作流設計**：JockeyBench 提出兩種互補的工作流（Workflow）以定位 LLM 推理在預測流程中的角色：
1. **InProgram**：LLM 撰寫並修訂一個可執行預測器（Executable Predictor），屬於可重複使用程式工作流（Reusable-Program Workflow），強調程式碼生成與持續最佳化。
2. **Adaptive Acquisition（適應性擷取）**：代理維護一個證據擷取程式（Evidence-Acquisition Program），但每場賽事仍由 LLM 進行新鮮預測，屬於每場賽事 LLM 預測（Per-Race LLM Forecast）模式。

此設計的精妙之處在於：InProgram 將推理「外化」至持久化程式（Persistent Programs），而 Adaptive Acquisition 將推理「內化」於每次預測，從而得以比較不同推理定位對資源消耗與預測品質的影響。

**凍結程式對照組（Frozen-Program Controls）**：每個修訂軌跡（Revised Trajectory）皆與其在相同賽事上的凍結初始程式（Frozen Initial Program）配對，形成修訂增益（Revision Gains）的內部參照基準。這一設計區分了「最終預測品質」與「修訂帶來的增量價值」，是評測適應性的關鍵機制。

**計價機制與淨效用**：系統對證據存取、工具呼叫與計算皆收取研究費用（Research Fees），並定義協議專屬的淨效用（Net Utility），將預測獎勵與研究費用在統一費率下結合。此做法呼應 Kapoor 等人（2025）所倡議的準確率—成本聯合評測理念。

**結算規則**：投注決策採用回溯式封頂凱利下注（Retrospective Capped-Kelly Staking），全額凱利比例（Full-Kelly Fraction）上限設為日初資金池（Day-Start Bankroll）的 1%，並以官方 JRA WIN 派彩（含 20% 抽佣）作為結算依據。此規則將預測機率轉化為可量化的決策後果，但同時保留了風險指標（如最大回撤）的獨立角色。

#### 實驗數據解讀

實驗涵蓋 28 種模型—框架配置（Model-Scaffold Configurations），橫跨 324 場賽事、10 個共享日，規模與嚴謹度兼具。

**整體投注表現**：圖 1 顯示，所有 28 種配置在封頂凱利結算下皆呈現負的平均利潤（Mean Profit）。具體而言，GPT-6-Astra 以最終資金池 ¥96.8K 居首，MiMo-V2.6-Pro（¥92.8K）與 Claude Opus 5（¥91.2K）緊隨其後，而 DeepSeek-V4-Flash 以 ¥61.7K 殿後。這意味著即使是最強配置，相對於初始資金池 ¥100K 仍處於虧損狀態，凸顯了賽馬市場中預測優勢轉化為實際價值的困難性。

**修訂增益分析**：配對檢定（Paired Tests）在多重檢定校正（Multiple-Testing Correction）後識別出 7 項修訂增益與 2 項修訂衰退。這一結果揭示了兩個重要現象：（1）多數配置的修訂並未帶來統計顯著的改善；（2）修訂甚至可能導致負面效果，說明代理在持續最佳化過程中存在過度擬合或策略漂移的風險。

**工作流比較**：在四模型對比中，InProgram 工作流的平均投注利潤（Mean Betting Profit）高於 Adaptive Acquisition，且研究費用更低。然而，兩種工作流在平均意義上皆為虧損。這暗示將推理外化至持久化程式雖能降低重複推理成本，但並不足以克服賽馬市場的結構性挑戰。

**診斷分析**：研究進一步揭示了兩個值得警惕的現象：
- **平均機率偏誤反轉（Mean Probability Bias Reversal）**：在篩選投注（Selected Bets）上，平均機率偏誤的方向與整體樣本相反，意味著代理可能系統性地高估或低估特定子群的勝率。
- **集中式回報依賴（Concentrated Returns Dependence）**：獲利個別回合（Profitable Individual Runs）往往依賴少數高賠率命中，顯示均值指標可能掩蓋風險集中的問題。

**指標分離的必要性**：實驗結果有力支持了論文的核心理念——最終預測品質高並不意味著修訂增益大；預測獎勵的提升可能被研究費用抵消；正的對數增益（Log Gain）並不保證正的實現投注利潤。這三個解耦關係凸顯了單一指標評測的局限性。

**6. 對抗性與非平穩環境**：賽馬市場存在策略性參與者與資訊不對稱，未來可研究代理在面對對手適應性行為時的穩健性，以及市場結構變化下的持續學習能力。

**7. 多模態證據整合**：目前 JockeyBench 僅使用結構化數據，未來可探索整合影片（如賽事轉播）、文字解說（如專家評論）等多模態證據對預測品質的提升。

**8. 理論基礎建立**：論文的實證發現豐富，但缺乏統一的理論框架來解釋「為何預測優勢難以轉化為決策價值」。未來可從資訊理論、賽局理論或學習理論角度建立形式化模型，為基準測試的設計提供原則性指導。

**9. 人機協作模式**：既然 LLM 代理在獨立預測上表現有限，未來可探索人機協作模式，例如代理負責證據擷取與初步分析，人類負責最終決策，藉由互補優勢提升整體表現。

**10. 倫理與監管框架**：隨著 LLM 代理在金融與博彩領域的應用增加，未來需建立相應的倫理準則與監管框架，確保此類技術的負責任發展。JockeyBench 作為受控實驗環境，可為相關政策制定提供實證依據。

## 論文問答

**Q1：JockeyBench 主要解決什麼樣的研究問題？**
A：JockeyBench 聚焦於「重複事件預測」（repeated event forecasting）這項任務，要求 LLM 代理從雜訊高的歷史證據中萃取預測訊號，並在多場連續決策中評估這些訊號的價值。相較於單次預測基準，此設定更貼近真實金融與賽馬情境，代理必須決定要擷取哪些證據、如何建構與修訂預測程序，並隨著結果釋出持續調整策略。此問題的核心挑戰在於：當預測優勢存在時，它是否真能轉化為跨多次決策的經濟價值，以及修訂機制與資訊成本如何影響該價值。

**Q2：現有的 LLM 代理評測方法為何不足以處理此問題？**
A：現有基準如 ForecastBench、Prophet Arena、PolyBench 雖然涵蓋預測任務，但多未同時納入「時序門控資料」、「計價工具」、「凍結程式對照組」與「雙工作流」等設計要素。KellyBench 雖結合序列預測與投注決策，卻缺乏對程式修訂與證據擷取成本的細緻分離。此外，多數基準未將「預測能力」、「適應性」、「資源使用」與「決策價值」四個面向獨立評估，導致高預測品質可能被誤認為等於高決策價值。JockeyBench 正是為了填補這些評測缺口而設計。

**Q3：為何選擇日本賽馬作為此問題的具體研究場景？**
A：日本賽馬提供「重複事件、結構化歷史證據、可驗證結果」三大特性，非常適合用來研究反覆預測與決策價值之間的關係。JRDB 資料庫收錄了賽事、參賽馬、過往表現、操練紀錄與賽果等關聯紀錄，且官方派彩（含 JRA WIN 派彩）允許在固定投注規則下進行回溯式評估。更重要的是，受限介面強制執行歷史資訊截止點並延遲結果釋出，能有效防止代理存取未來紀錄，確保評測的嚴謹性。

**Q4：JockeyBench 評測協定的核心設計是什麼？**
A：協定的核心在於結合「持久化程式」、「計價證據存取」與「受控資訊釋出」三大機制。具體而言，代理必須在受限介面下運作，所有證據擷取、工具呼叫與計算皆須按固定費率付費，而預測必須在結果釋出前完成封存。這種設計讓研究者能同時衡量預測準確度、研究支出與最終投注利潤，並透過配對檢定區分「預測品質」與「修訂增益」。

**Q5：「InProgram」與「Adaptive Acquisition」兩種工作流的關鍵創新為何？**
A：兩種工作流將 LLM 推理置於預測流程的不同位置，藉此比較「程式內推理」與「證據擷取後推理」的差異。InProgram 工作流讓 LLM 建構並修訂一個可執行預測器，隨著賽事進行持續優化；Adaptive Acquisition 則維持一個證據擷取程式，但每場賽事仍由 LLM 進行全新的預測。這種雙軌設計使研究者能釐清：究竟是把推理「編碼」進持久化程式較有利，還是讓 LLM 在每場賽事中靈活運用最新證據較有利。

**Q6：為何要設計「凍結初始程式對照組」與「配對檢定」？**
A：凍結初始程式對照組提供了一個「修訂前」的參照基準，使每條修訂軌跡都能與其在相同賽事上的初始版本直接比較。這種配對設計能精確分離「修訂帶來的增益」與「最終預測品質」這兩個常被混淆的概念。透過配對檢定並進行多重檢定校正，研究者得以嚴謹地辨識哪些配置確實從修訂中獲益、哪些反而退步，避免將隨機波動誤判為實質改進。

**Q7：JockeyBench 的實驗規模與評測配置為何？**
A：研究涵蓋 28 種模型—框架配置，在 10 個共享日、合計 324 場賽事上進行評測。模型橫跨 GPT-6-Astra、MiMo-V2.6-Pro、Claude Opus 5、Kimi-K3、Qwen3.8-2.4T-A95B、DeepSeek-V4-Pro、GLM-5.3、Hunyuan-4-Preview 等多家供應商的不同規模版本。投注結算採用回溯式封頂凱利下注策略，初始資金池為日圓 100,000 元，每場賽事最高下注額為日初資金池的 1%，並使用歷史賽事結果與官方 JRA WIN 派彩（含 20% 抽佣）計算回報。

**Q8：實驗中最關鍵的發現是什麼？**
A：最關鍵的發現可歸納為三點：第一，配對檢定在多重檢定校正後僅辨識出 7 項修訂增益與 2 項修訂退步，顯示修訂並非總能帶來正面效益；第二，在封頂凱利結算下，所有 28 種配置的「平均利潤」皆為負值，即使是表現最佳的 GPT-6-Astra 也僅將資金池維持在約 96.8K 日圓；第三，在四模型比較中，可重複使用程式工作流（InProgram）雖有較高的平均投注利潤與較低的研究費用，但兩種工作流平均而言皆虧損。

**Q9：診斷分析揭示了哪些容易被忽略的細節？**
A：診斷分析顯示「平均機率偏誤」在篩選投注上會發生反轉，亦即整體看似無偏誤的機率估計，在實際下注的子樣本上可能呈現系統性偏差。此外，個別獲利回合往往依賴「集中式回報」——即少數高賠率命中支撐整體正報酬，這意味著平均利潤的正面結果可能掩蓋了高度集中的風險。這些發現提醒研究者：聚合的機率摘要與孤立的獲利回合都可能給出對決策績效不完整的描述。

**Q10：JockeyBench 的設計對哪些實際應用場景具有參考價值？**
A：此基準的設計原則可直接應用於任何需要「反覆預測並據以行動」的領域，例如量化交易、體育博彩、動態定價與庫存管理。在這些場景中，代理同樣面臨「擷取哪些資訊」、「如何建構預測模型」、「何時修訂策略」以及「如何權衡資訊成本與決策收益」等核心問題。JockeyBench 提供的分離式評測框架，能幫助實務界辨識哪些模型真正具備從預測轉化為價值的能力。

**Q11：在產品化 LLM 代理時，JockeyBench 揭示了哪些關鍵考量？**
A：產品化時必須正視三項關鍵考量：首先是「預測品質不等於決策價值」，高 log gain 並不保證正報酬，因此產品設計需將投注或行動規則與預測模型分離評估；其次是「資訊成本結構」，研究費用、工具呼叫與計算成本必須明確計價並反映於淨效用中；最後是「修訂機制的雙刃性」，並非所有修訂都帶來增益，產品應提供凍結對照組以驗證修訂是否真的改善表現。

**Q12：JockeyBench 對 LLM 代理研究領域的整體影響為何？**
A：JockeyBench 推動了評測典範的轉移，從單純的「預測準確度」轉向涵蓋「預測能力、適應性、資源使用、決策價值」四面向的聯合評估。這種分離式評測有助於學界與業界更細緻地診斷代理的強項與弱點，避免被聚合指標誤導。同時，其「配對對照組 + 計價工具 + 雙工作流」的設計組合，可作為未來類似基準的範本，促進跨領域的可比較性與方法論嚴謹度。

**Q13：JockeyBench 本身存在哪些已知的限制？**
A：作者明確指出幾項限制：首先是賽事樣本僅限於日本賽馬的 324 場，跨賽制、跨地區的泛化性仍待驗證；其次是投注結算採回溯式封頂凱利策略，未涵蓋實際下注時的滑價、賽事取消與即時賠率變動等摩擦成本；最後是「未實際下注」，所有結果皆為模擬，因此無法反映真實市場中的流動性限制與莊家行為。這些限制提醒讀者將結論外推時須謹慎。

**Q14：實驗中觀察到哪些典型的失敗案例？**
A：典型的失敗案例包括：所有 28 種配置在封頂凱利結算下皆呈現負的平均利潤，顯示預測優勢未能有效轉化為投注收益；部分配置的修訂軌跡在多重檢定校正後被判定為「修訂退步」，意味著持續調整反而損害了表現；此外，平均機率偏誤在篩選投注上反轉的現象，說明代理可能在「選擇下注標的」這一環節產生系統性錯誤。這些失敗凸顯了「會預測」與「會賺錢」之間存在巨大鴻溝。

**Q15：基於這些發現，未來有哪些值得探索的研究方向？**
A：未來方向可分為四類：第一，發展能更有效將預測轉化為決策價值的下注規則與風險控管機制；第二，設計更智慧的證據擷取策略，以降低研究費用同時維持預測品質；第三，探索跨賽制、跨資產類別的泛化性，驗證 JockeyBench 的設計原則是否適用於其他重複事件預測場景；第四，引入即時賠率、滑價與市場摩擦等更真實的結算條件，縮小模擬與實務之間的差距。這些方向將共同推動 LLM 代理從「預測」走向「價值創造」。

### 實作步驟建議

1. **界定領域與決策規則**：選定目標場域（賽馬、交易、預測市場），定義「事件—參與者—結算」的對應關係，並選定固定決策規則（如封頂凱利下注，比例上限 1% 日初資金池）。

2. **建構受限資料介面**：實作時序門控 API，強制每場事件的資訊截止點；延遲釋出結果直到預測封存；排除賠率、專家評分等「洩漏未來」欄位，僅保留事實證據。

3. **設計計價工具與研究費率**：為每項證據存取、工具呼叫、程式碼執行設定單位成本；建立統一日誌，記錄每場事件的累計研究費用。

4. **實作雙工作流**：
   - **InProgram（可重複使用程式）**：代理在 Day 1 撰寫可執行預測器，每日根據釋出的賽果進行修訂；保留每次修訂軌跡。
   - **Adaptive Acquisition（適應性擷取）**：代理維護證據擷取程式，每場賽事重新呼叫 LLM 進行預測。

5. **建立凍結對照組**：每次修訂後，將修訂版與其凍結初始版本在同一批賽事上配對執行，提供修訂增益的參照基準。

6. **執行多模型—多框架實驗**：至少 4 個模型 × 2 種工作流 × 多種框架配置，總計建議 20–30 組配置；每組在 300 場以上賽事重複執行多次。

7. **分層評估指標**：
   - 預測品質：對數收益、Brier score。
   - 淨效用：預測獎勵 − 研究費用（依協定費率）。
   - 投注回報：平均利潤、最大回撤、Sharpe ratio。
   - 適應性：配對檢定後的修訂增益（需做多重檢定校正，如 Benjamini-Hochberg）。

8. **診斷分析**：檢視「篩選投注」上的平均機率偏誤是否反轉；分析獲利回合是否依賴集中式回報（少數高賠率命中掩蓋多數虧損）。

9. **產出決策儀表板**：將預測能力、適應性、資源使用、決策價值四個面向分開呈現，避免單一指標誤導。

### 潛在風險與注意事項

- **平均機率偏誤反轉**：整體平均機率可能看似校準良好，但在「實際下注的篩選投注」上偏誤方向可能反轉，導致投注決策與預測品質背離。**緩解**：分層檢視未下注 vs. 已下注的校準曲線。

- **集中式回報掩蓋虧損**：個別獲利回合可能來自少數高賠率命中，平均利潤為正但中位數為負。**緩解**：同時報告平均與中位數回報，並繪製逐場損益分布。

- **研究費用吞噬預測增益**：預測品質提升可能被計價工具的累積費用抵消，淨效用為負。**緩解**：設定每日研究費用上限，並在淨效用指標中強制扣除。

- **多重檢定膨脹**：28 組配置 × 多項指標的配對檢定若未校正，假陽性率將急劇上升。**緩解**：一律套用 Benjamini-Hochberg 或 Bonferroni 校正，並區分「探索性」與「確認性」分析。

- **未來資料洩漏**：受限介面若實作不嚴，代理可能透過時間戳、隱含欄位讀取未來紀錄。**緩解**：建立紅隊測試，主動嘗試繞過截止點；對每次預測記錄「資訊指紋」以利事後稽核。

- **抽成與手續費忽略**：JRA WIN 派彩含 20% 抽成，忽略此項會高估期望值。**緩解**：在結算模型中明確納入所有抽成、稅費、滑價成本。

- **凍結對照組的污染**：若凍結程式的訓練資料包含釋出後的賽果，將失去對照意義。**緩解**：嚴格隔離凍結版本的訓練切點，並在論文中標註資料切點日期。

- **小樣本下的凱利下注失真**：封頂凱利在樣本數小時波動劇烈，單次實驗結果不具代表性。**緩解**：重複執行多次，報告信賴區間而非單點估計。

### 與其他技術的整合建議

- **KellyBench（序列預測 + 投注）**：JockeyBench 的投注結算層可借用 KellyBench 的序列預測框架，兩者互補——KellyBench 偏重預測品質，JockeyBench 強調工作流與修訂機制。
- **MLE-bench / MLAgentBench / AIDE（機器學習代理）**：InProgram 工作流的「代理撰寫並修訂可執行預測器」可直接借用 MLE-bench 的評測骨架，將競賽資料集替換為賽馬或金融資料。
- **CostBench（計價工具規劃）**：JockeyBench 的計價工具與研究費用設計可參考 CostBench 的成本模型，統一工具定價單位（如每次 API 呼叫、每 KB 資料）。
- **ForecastBench / Prophet Arena / PolyBench（預測基準）**：作為「無程式碼、無修訂」的對照組，驗證 InProgram 工作流的修訂增益是否真的來自代理能力，而非僅是更好的提示。
- **Reflexion / Self-Refine / Self-Debugging（反思式代理）**：在 Adaptive Acquisition 工作流中嵌入反思機制，評估反思步驟對每場預測品質的邊際貢獻。
- **SPIKE（事件觸發介入）**：用於模擬「賽果釋出 → 觸發程式修訂」的節點控制，與 JockeyBench 的結果釋出機制對接。
- **既有投注／交易平台**：將評測結果以 API 形式輸出至既有平台（如 Bloomberg、Polymarket），作為「AI 代理研發後台」與「前端決策介面」之間的中介層。
- **MLOps / LLMOps 工具鏈**：實驗排程、結果追蹤、模型版本控管可整合 Weights & Biases、MLflow 或 LangSmith，確保 28 組配置的可重現性。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的問題動機與圖 1 的資金池曲線，直觀理解「為什麼預測準確率高不等於賺錢」。接著跳過技術細節，直接看摘要中的七大發現，特別是「所有配置在封頂凱利結算下平均利潤為負」這項結論，它揭示了預測與決策之間的鴻溝，是理解整篇論文的鑰匙。

**給 AI 工程師**：重點關注第 1 節的協定設計（時序門控、計價工具、凍結對照組）與第 2 節的相關工作表格（Table 1）。Table 1 清楚標示了 JockeyBench 相較於 ForecastBench、KellyBench、MLE-bench 等的獨特設計點（雙工作流、結果修訂、風險指標、計價工具、凍結控制），可作為你在自家代理系統中引入「成本感知評測」時的設計 checklist。

**給研究者**：第 1 節末尾列出的四個評測面向（預測能力、適應性、資源使用、決策價值）與多重檢定校正方法是方法論上的主要貢獻。建議仔細研讀配對檢定的設計邏輯——為何要將「修訂軌跡 vs. 凍結初始程式」配對在同一批賽事上，這是區分「預測能力提升」與「修訂機制價值」的關鍵實驗設計，可延伸至其他重複事件預測研究。

**給產品經理**：聚焦於「預測品質 ≠ 決策價值」這項核心訊息，以及圖 1 中 28 組配置的最終排名與資金池曲線。在向高層或客戶報告 AI 代理成效時，務必將「平均預測準確率」、「研究成本」、「實際投注／決策回報」分開呈現，並強調「個別獲利回合可能依賴集中式回報」這項風險——這能幫助你設定合理的產品 KPI，避免被單一指標誤導，也能在合約中明確界定「預測服務」與「決策服務」的責任邊界。
