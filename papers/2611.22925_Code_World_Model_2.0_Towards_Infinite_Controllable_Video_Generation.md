## 深度分析

#### 方法論解析

Invoker-Render 的核心設計理念在於將「可控性」與「即時性」這兩個常被視為互相衝突的需求，透過一個統一的條件介面與分階段訓練策略加以調和。整體框架由兩個互補的模型組成：雙向創作模型（bidirectional creation model）負責離線片段創作（offline clip creation），因果四步串流模型（causal four-step streaming model）負責即時互動串流（real-time interactive streaming），兩者共享同一個條件介面，接受結構代理（structural proxies）、外觀參考（appearance reference）與語言（language）三類輸入。

**共享條件介面與多粒度代理處理**

此設計最關鍵的創新在於「代理粒度」（proxy granularity）的彈性處理。傳統的代理條件渲染（proxy-conditioned rendering）方法通常要求代理的細節程度與訓練資料一致，導致同一模型難以同時處理粗略佈局（coarse layouts）與精細關節式幾何（articulated geometry）。Invoker-Render 透過共享介面，使單一權重組態能同時解讀語意佈局（semantic layouts）、帶陰影幾何（shaded geometry）、關節式姿態（articulated poses）等不同代理類型（proxy families），並在代理粒度不足時自主合成合理的局部運動（local motion）。例如，當輸入僅提供根部姿態（root pose）時，模型應約束全域位置（global position）與朝向（heading），但不應凍結肢體姿態（limb posture），而是生成自然的肢體動作。

**漸進式強制（Progressive Forcing, ProForcing）訓練策略**

ProForcing 是本論文最具技術深度的貢獻，旨在解決「步驟壓縮」（step compression）與「展開漂移」（rollout drift）兩個串流生成中的核心難題。其訓練分為四個遞進階段：

1. **教師強制（Teacher Forcing, TF）階段**：基於 MiniMax-H3 骨幹網路（backbone）並採用無引導訓練（Guidance-Free Training, GFT）將引導蒸餾骨幹網路（guidance-distilled backbone）適配至代理條件化（proxy conditioning）。此階段訓練區塊因果預測（block-causal prediction），使用乾淨影片前綴（clean video prefixes）作為歷史。

2. **重採樣強制（Resampling Forcing, RF）階段**：將已觀察前綴（observed prefixes）加入噪訊並用當前模型逐步精煉，構造不完美的歷史。這模擬了自生成歷史中可能出現的誤差，使模型學會對歷史中的不完美具有容忍度。

3. **RF-DMD 階段**：保留重採樣歷史的同時，透過分布匹配蒸餾（Distribution Matching Distillation, DMD）將因果預測器（causal predictor）蒸餾為四步渲染器（four-step renderer），並輔以 GAN 損失（auxiliary GAN loss）。此階段的學生模型、可訓練評分模型（trainable score model）與 GAN 判別器（discriminator）三者共同訓練。

4. **SF-DMD 階段**：訓練轉移至連續自生成展開（continuous self-generated rollouts），學生、評分模型與判別器在自生成歷史下繼續訓練，實現長展開（long-rollout）訓練。

此課程式設計的精妙之處在於：先建立四步生成器與監督模型，再進入自生成歷史訓練，避免了「從零開始訓練自生成展開」所帶來的不穩定性。

**多粒度語料庫（Multi-granularity Corpus）**

訓練資料為約 200 小時的對齊語料庫（aligned corpus），採用階層式文字標註（hierarchical text），涵蓋不同代理類型與粒度。這使得單一檢查點（checkpoint）能支援執行階段（runtime）對輸入細節程度的選擇。

**流水線服務堆疊（Pipelined Serving Stack）**

為支援低延遲互動串流，系統採用持續歷史快取（persistent history caching）與代理編碼、影片解碼的流水線化（pipelined proxy encoding and video decoding），降低服務開銷。

#### 與現有研究的比較

**與世界模型相關研究的定位**

在互動世界模型（interactive world models）的脈絡下，現有研究大致分為兩類：(1) 將動力學與視覺合成統一在一個網路中的端到端方法，如 Matrix-Game 系列、WorldPlay、WorldCrafter 等；(2) 將狀態模擬與視覺合成解耦的代理渲染方法，如 Code World Model、Programmable World Model、AgentGarten、Marionette、Wizard 等。Invoker-Render 屬於第二類，並透過共享介面與多粒度處理進一步推進此範式。

**與代理條件渲染的比較**

相較於 DiffusionRenderer、Generative World Renderer 等需要密集幾何、光照、材質緩衝的配對方法，Invoker-Render 透過多粒度設計放寬了對代理細節的要求。相較於 Proxy2World 透過 RGB-D 剪輯放鬆配對監督，Invoker-Render 則在代理類型與粒度兩個維度上提供彈性。SolarRenderer 雖支援異質結構影片，但其加速 LoRA 與 Invoker-Render 的四步因果渲染在技術路線上有所不同。

**與串流擴散模型的比較**

在串流影片擴散（streaming video diffusion）領域，Diffusion Forcing 訓練獨立 token 噪訊等級的因果模型；CausVid 將雙向教師蒸餾為自回歸學生；Self Forcing 在自身預測上展開。Invoker-Render 的 ProForcing 整合了這些思想，並透過 GAN 監督與 DMD 蒸餾的結合，實現四步生成與長時穩定性的平衡。

**與即時渲染系統的比較**

StreamRender-H3、Streaming CWM、Magpie、BoxWorld 等系統將遊戲或模擬器後端與神經渲染器耦合。Invoker-Render 的差異化在於：(1) 強調代理粒度的彈性；(2) 統一的雙向創作與因果串流介面；(3) 30 分鐘級別的長時穩定性。

**局限性分析**

儘管成果顯著，仍存在以下局限性：(1) 200 小時的訓練資料規模相對有限，可能限制泛化能力；(2) 四步生成雖快，但對於極低延遲需求（如 60 FPS 以上）仍可能不足；(3) 代理類型雖多元，但對於物理模擬、粒子效果等動態元素的處理能力未明確說明；(4) 30 分鐘穩定性僅在競速場景驗證，其他場景類型的泛化性有待確認。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：這篇論文聚焦於「可控影片生成」中的兩個關鍵挑戰：上游代理（proxy）的多樣性與串流推論的即時性問題。具體而言，互動式影片世界模型需要根據使用者動作合成連貫的觀察結果，但實務上代理的細節程度差異極大——從粗略的場景佈局到精細的關節式幾何皆有可能，端看互動情境而定。同時，串流推論必須在極少的因果步驟內完成，且不能因自生成歷史的累積誤差而產生展開漂移（rollout drift）。因此，論文試圖打造一個能同時支援離線片段創作與即時互動串流的統一渲染框架。

**Q2：為何現有的方法無法有效解決這個問題？**
A：現有方法主要分為兩類，但各自都有明顯的侷限性。第一類是將動力學與視覺合成整合在單一網路中的「端到端」方法（如 Matrix-Game、WorldPlay 等），雖然能處理開放世界互動，但難以修改場景結構或強制執行持續的物理規則，因為視覺轉換模型同時掌管狀態演化與渲染。第二類則是將代理視為狀態到渲染器的契約（如 DiffusionRenderer、Code Video Model 等），但這些方法通常要求密集配對的幾何監督，或僅在訓練時使用單一代理粒度，無法在同一模型內同時處理粗略與精細的代理輸入。此外，串流式影片擴散模型（如 CausVid、Self Forcing）雖然解決了少步取樣的問題，但缺乏對結構代理的細粒度控制能力。

**Q3：為什麼這個問題對學術界與工業界如此重要？**
A：這個問題的重要性體現在三個層面。首先，從學術角度來看，它觸及了生成式模型中「可控性」與「效率」之間的核心張力——如何在不犧牲視覺品質的前提下，讓模型服從多樣化的結構約束並即時回應使用者輸入。其次，從應用角度來看，遊戲、電影預覽、機器人模擬、虛擬實境等場景都迫切需要能夠長時間穩定運作且支援使用者即時介入的影片生成系統。第三，從產業落地角度來看，30 分鐘的穩定展開（racing rollouts）意味著系統已具備商業化部署的可能性，這對於沉浸式娛樂與數位孿生等產業具有直接的變革意義。

**Q4：Invoker-Render 的核心方法架構為何？**
A：Invoker-Render 採用「雙模型共享介面」的設計理念，包含一個雙向創作模型與一個因果四步串流模型，兩者共用同一個條件化介面。這個介面接受三類輸入：結構代理（從語意佈局到帶陰影幾何）、外觀參考影像，以及語言描述。雙向模型用於離線片段創作，能在完整代理序列上進行全域編輯；因果模型則用於即時串流，以區塊因果注意力（block-causal attention）方式增量消費代理區塊與局部文字，每個區塊僅需四個去噪步驟即可生成。整個系統基於 MiniMax-H3 骨幹網路，並採用無引導訓練（GFT）將其引導蒸餾版本適配至代理條件化任務。

**Q5：ProForcing（漸進式強制）的關鍵創新是什麼？**
A：ProForcing 的核心創新在於將「步驟壓縮」與「展開漂移」這兩個挑戰解耦為漸進式的訓練課程。第一階段使用教師強制（TF）在乾淨影片前綴上訓練區塊因果預測，建立基本的因果預測能力。第二階段引入重採樣強制（RF），透過對已觀察前綴加噪並用當前模型依序精煉，構造不完美的歷史以模擬推論時的誤差累積。第三階段 RF-DMD 結合分布匹配蒸餾（DMD）與輔助 GAN 損失，學習四步生成並保留重採樣歷史。最後階段 SF-DMD 讓學生模型、可訓練評分模型與 GAN 判別器在連續自生成歷史上繼續訓練，從而跨越從乾淨監督到自生成歷史的鴻溝。

**Q6：為何選擇「多粒度代理」與「共享介面」這樣的設計？**
A：這個設計選擇反映了對實務應用場景的深刻理解。在真實互動中，代理的細節程度往往隨任務而變動——廣域導航只需粗略的場景幾何與根部軌跡，而近距離互動則需要關節式姿態或更細緻的表面結構。透過共享條件介面，單一模型權重能同時處理粗略與精細代理，使用者可在執行階段依據建構與傳輸成本選擇合適的輸入粒度。這種設計避免了為每種粒度訓練獨立模型的資源浪費，也避免了訓練-測試不一致的問題。此外，當代理僅約束全域位置與朝向時（如追蹤角色根部姿態的人體模型），模型仍能合成合理的局部肢體運動，避免了「凍結肢體姿態」這類過度約束的問題。

**Q7：實驗中使用了哪些基準測試與評估指標？**
A：論文在 140 個串流展開上進行了全面評估，涵蓋視覺品質、結構遵循度與參考保留度三個維度。視覺品質方面採用標準的影片生成評估指標（如 FID、FVD 等）；結構遵循度衡量生成影片與輸入代理（語意佈局、帶陰影幾何等）的一致性；參考保留度則評估主體外觀在長時間展開中的穩定性。實驗特別強調了 30 分鐘競速展開的長期穩定性測試，這是業界少見的長時間一致性評估。此外，論文還與近期串流基線（如 CausVid、Self Forcing 等）進行了直接比較，並測試了模型在不同代理類型（語意佈局、帶陰影幾何）、不同粒度（粗略到精細）以及不同相機路徑下的表現。

**Q8：實驗結果中最關鍵的發現是什麼？**
A：最關鍵的發現是 Invoker-Render 在三個維度上同時取得了一致性增益，並展現了前所未有的長期穩定性。具體而言，在 140 個串流展開中，模型在視覺品質、結構遵循度與參考保留度上均優於近期串流基線。更令人矚目的是，模型能在 30 分鐘的競速展開中維持場景與主體外觀的穩定性，這對於實際應用至關重要。此外，實驗還驗證了「單一權重處理多粒度代理」這一設計假設——同一檢查點既能遵循精細代理的幾何約束，又能在粗略代理下合成合理的局部運動，證明了共享介面的有效性。

**Q9：論文中進行了哪些消融實驗來驗證設計選擇？**
A：雖然完整消融實驗細節需參考論文正文，但從方法描述可推斷出幾項關鍵消融：首先是 ProForcing 各階段的必要性——比較僅使用 TF、TF+RF、TF+RF+RF-DMD、以及完整四階段訓練的效能差異，以驗證漸進式課程的價值。其次是四步生成與更多步數的權衡——證明四步渲染器在品質與延遲間的最佳平衡點。第三是 GAN 損失的貢獻——驗證輔助 GAN 損失對於穩定 DMD 訓練的重要性。第四是自生成歷史訓練的必要性——比較僅在乾淨歷史上訓練與在自生成歷史上繼續訓練的長期展開穩定性差異。

**Q10：Invoker-Render 的實際應用場景有哪些？**
A：Invoker-Render 的應用場景極為廣泛，涵蓋遊戲、電影預覽、虛擬實境、機器人模擬等多個領域。在遊戲產業中，開發者可在執行階段選擇代理粒度——廣域探索時使用粗略佈局以降低傳輸成本，戰鬥或互動場景則切換至精細幾何以獲得更精確的視覺回饋。在電影與動畫預覽中，導演可透過編輯完整代理序列來調整相機路徑、角色軌跡與事件時序，再由雙向模型生成高品質預覽片段。在虛擬實境與沉浸式娛樂中，因果四步串流模型能即時回應使用者動作，支援長達 30 分鐘的穩定互動體驗。在機器人模擬中，則可作為神經渲染器，將模擬器的物理狀態轉化為照片級真實感的觀察影像。

**Q11：將此技術產品化時需要考量哪些工程因素？**
A：產品化過程中需考量多項工程因素。首先是延遲與吞吐量——四步渲染器雖已大幅降低計算成本，但仍需配合流水線服務堆疊（pipelined serving stack）來進一步減少服務開銷，論文中提到的「持續歷史快取」與「流水線代理編碼與影片解碼」正是為此設計。其次是代理建構成本——粗略代理雖輕量，但精細代理的建構本身就需要算力，產品需提供從粗到細的漸進式工具鏈。第三是長程一致性——30 分鐘穩定性雖已驗證，但實際產品可能需要更長的執行時間，需持續優化外觀保留機制。第四是內容審查與安全性——可控影片生成可能被濫用於深偽（deepfake）等場景，需內建相應的防護機制。

**Q12：這項研究對影片生成領域的整體影響為何？**
A：這項研究的影響體現在三個層面。在技術層面，它將「可控性」與「即時性」這兩個過去被視為相互排斥的目標統一起來，為未來研究提供了「漸進式強制」這一新範式。在方法論層面，「多粒度代理共享介面」的設計挑戰了「為每種條件訓練專用模型」的傳統思路，展示了單一模型處理多樣化輸入的可行性。在產業層面，30 分鐘穩定展開的成果標誌著影片世界模型從「短片段演示」邁向「實用系統」的關鍵一步，可能加速遊戲、電影、虛擬實境等產業的 AI 轉型。此外，約 200 小時的多粒度對齊語料庫也為社群提供了寶貴的訓練資源。

**Q13：論文中承認了哪些限制？**
A：儘管成果令人印象深刻，論文仍存在若干限制。首先，約 200 小時的訓練語料規模相對有限，雖然涵蓋多粒度，但對於涵蓋所有可能的代理類型與場景仍顯不足。其次，30 分鐘的穩定性雖已驗證，但對於需要數小時甚至數天的長程應用（如開放世界遊戲）仍需進一步驗證。第三，模型對代理品質的依賴性——若輸入代理本身存在錯誤或不準確，渲染結果可能放大這些瑕疵。第四，四步渲染雖實現即時串流，但在極端複雜場景下可能犧牲部分視覺細節。第五，論文的評估主要集中在特定任務（如競速遊戲），對於其他互動類型（如策略遊戲、社交模擬）的泛化能力仍待驗證。

**Q14：在哪些情況下 Invoker-Render 可能會失敗？**
A：基於方法特性，Invoker-Render 可能在以下場景中表現不佳。第一，當代理與外觀參考之間存在嚴重衝突時——例如代理指定某個角色位於畫面左側，但外觀參考顯示該角色在右側，模型可能產生不一致的結果。第二，當輸入代理超出訓練分布時——例如訓練語料中未涵蓋的高度風格化場景或極端相機運動。第三，當使用者動作序列過於劇烈或不符合物理直覺時，模型可能難以合成合理的運動過渡。第四，在極度稀疏的代理輸入下（如僅有相機路徑而無任何場景佈局），模型可能產生幻覺或不一致的場景結構。第五，長時間展開中若遭遇訓練中未見過的罕見事件組合，仍可能出現外觀漂移或場景崩塌。

**Q15：未來的研究方向有哪些？**
A：基於本研究的成果與限制，未來可朝以下方向延伸。首先是擴展語料規模與多樣性——建構更大規模、涵蓋更多場景與代理類型的對齊語料庫，以提升模型的泛化能力。其次是探索更長程的一致性機制——例如引入顯式的記憶模組或層次化世界模型，以支援數小時甚至數天的穩定展開。第三是結合語言模型作為代理生成器——讓大型語言模型根據使用者意圖自動產生結構代理，進一步降低使用門檻。第四是研究互動式代理編輯——允許使用者在串流過程中即時修改代理並觀察視覺效果的即時更新。第五是探索 3D 感知的世界表示——將代理從 2D 佈局擴展至完整的 3D 場景圖，以支援更豐富的視角變化與空間推理。第六是研究多模態代理——整合音訊、觸覺等額外信號，邁向真正多感官的世界模型。

## 實務應用指南

### 適用場景

Invoker-Render 的雙向創作 + 因果四步串流雙模式設計，使其在以下場景具有明確的落地價值：

1. **互動式遊戲與即時娛樂串流**：將遊戲引擎（Unity、Unreal、Godot）輸出的語意佈局、骨骼姿態、深度圖等結構代理即時轉為照片級畫面。論文展示的 30 分鐘穩定賽車展開證明此模式可承受長時互動，適合雲端遊戲（GeForce Now、Stadia 類型服務）或賽車模擬器。

2. **影視 / 動畫前期預覽（Pre-vis）**：導演可在粗略佈局階段快速迭代鏡頭與時序，再切換到精細關節式幾何階段驗證角色動作。同一模型權重支援不同代理粒度，可大幅縮短前期視覺化成本。

3. **機器人與自駕車模擬訓練**：將模擬器（CARLA、Isaac Sim、MuJoCo）輸出的語意分割、bounding box、深度緩衝作為代理，搭配外觀參考圖生成多樣化訓練視訊，補強 corner case 資料。

4. **電商與虛擬試穿 / 室內設計**：使用者提供房間佈局或家具擺放（粗略代理），模型合成自然擺設與光影；或以人體模型（mannequin）控制全域位置與朝向，由模型補完肢體動作。

5. **AR / VR 內容創作**：以輕量代理（手機 LiDAR 掃描的粗略幾何）即時生成沉浸式場景，降低頭戴裝置的傳輸與算力負擔。

---

### 實作前置條件

**資料需求**
- 約 200 小時的多粒度對齊語料庫，需同時包含粗略佈局（語意分割、bounding box）與精細代理（帶陰影幾何、articulated mesh、深度圖）。
- 每段影片需有階層式文字標註（全域描述 + 局部事件描述），並對齊到代理區塊。
- 外觀參考幀（reference frame）需與代理在時間軸上對齊。
- 建議自建資料時使用 Blender / Unreal 合成管線以取得精確代理，或採用 Proxy2World 風格的 RGB-D 配對以降低標註成本。

**算力需求**
- 訓練階段：多機多 GPU（建議 64+ A100/H100 等級），DMD 蒸餾需同時持有學生模型、可訓練評分模型、GAN 鑑別器三套權重。
- 推論階段：單張高階 GPU（如 H100）即可支援四步串流；多使用者場景需搭配流水線服務堆疊（persistent KV cache + 異步代理編碼 / 影片解碼）。

**技能門檻**
- 熟悉擴散模型架構（DiT / U-Net）、蒸餾（DMD、CausVid 概念）與 GAN 鑑別器訓練。
- 具備 3D 幾何、代理表示（語意、深度、mesh）的工程處理能力。
- 串流系統經驗：block-causal attention、KV cache 管理、pipelined serving。
- 遊戲引擎或模擬器整合經驗（讀取結構代理的 API）。

---

### 實作步驟建議

1. **界定代理契約（Proxy Contract）**
   - 先盤點上游引擎能輸出的代理類型與粒度，決定要支援哪些「代理家族」（語意佈局 vs. 帶陰影幾何）。
   - 設計統一的條件介面：結構代理 + 外觀參考 + 文字，三者皆為可選輸入。

2. **建立多粒度語料庫**
   - 從現有影片資料集（如遊戲實況、駕駛資料）以離線工具（Grounded-SAM、Depth Anything、SMPL-X 擬合）回推代理。
   - 為每段影片產生階層式文字標註，並驗證代理與畫面在時間軸上的對齊品質。

3. **訓練雙向創作模型**
   - 以 MiniMax-H3 為骨幹，套用 Guidance-Free Training (GFT) 將引導蒸餾骨幹適配到代理條件化。
   - 在混合粒度資料上訓練，使單一權重同時能遵循精細約束與在粗略代理下補完局部運動。

4. **執行 ProForcing 課程學習**
   - **階段 A（TF）**：教師強制訓練區塊因果預測器，使用乾淨影片前綴。
   - **階段 B（RF）**：重採樣強制——對已觀察前綴加噪後由當前模型逐步修正，建立對不完美歷史的容忍度。
   - **階段 C（RF-DMD）**：在重採樣歷史上以 DMD + 輔助 GAN 損失學習四步生成。
   - **階段 D（SF-DMD）**：切換到自生成歷史的連續展開訓練，學生、評分模型、鑑別器共同演化。

5. **部署流水線服務堆疊**
   - 實作 persistent history cache，避免重複計算已生成區塊的 KV。
   - 將代理編碼與影片解碼異步化，與主生成管線並行。
   - 設計 chunk 切分策略，平衡延遲與因果依賴範圍。

6. **上線監控與長時驗證**
   - 部署後跑 30 分鐘級的長時 rollouts，監測主體外觀漂移、場景一致性、結構遵循度。
   - 建立回退機制：當漂移超過閾值時切回較粗代理或重新注入外觀參考。

---

### 潛在風險與注意事項

- **展開漂移（Rollout Drift）**：自生成歷史的誤差會累積，導致主體外觀或場景結構在長時序列中緩慢變形。緩解：嚴格執行 ProForcing 的 SF-DMD 階段、保留外觀參考的週期性重新注入、設置漂移偵測與自動回退。

- **步驟壓縮導致細節損失**：四步蒸餾相較於完整去噪必然犧牲部分細節。緩解：在創作模式（非即時）下保留雙向模型使用更多步數；串流模式僅在需要即時性時啟用。

- **代理粒度錯配**：上游若提供過粗代理而下游期待精細動作，模型會「自由發揮」並可能違反使用者意圖。緩解：在 UI 明確標示當前代理粒度與模型將補完的範圍；提供「鎖定局部運動」的進階選項。

- **代理與外觀參考不一致**：當代理指定的位置與參考圖中的主體位置衝突時，模型行為可能不穩定。緩解：在訓練資料中加入衝突樣本並學習優先順序；推論時加入一致性檢查。

- **長時記憶成本**：30 分鐘展開的 KV cache 會非常龐大。緩解：採用 sliding window + 摘要 token、壓縮歷史幀、或週期性重新編碼。

- **資料偏誤與安全**：遊戲 / 駕駛語料可能帶有偏誤或敏感內容。緩解：建立內容審核管線、對輸出做 NSFW / 暴力偵測過濾。

- **代理傳輸延遲**：即時互動中代理本身的上傳延遲可能成為瓶頸。緩解：代理端做時序預測與插值、降低代理幀率、邊緣預編碼。

---

### 與其他技術的整合建議

- **遊戲引擎（Unity / Unreal / Godot）**：透過引擎 plugin 將場景圖、骨骼動畫、深度 pass 即時輸出為代理；引擎端負責物理與邏輯，Invoker-Render 負責視覺合成。建議封裝為引擎的 PostProcess 層。

- **機器人模擬器（Isaac Sim / CARLA / MuJoCo）**：將語意分割、bounding box、深度緩衝作為代理，搭配文字指令生成多樣化訓練視訊。可與域隨機化（domain randomization）互補。

- **3D 重建流程（NeRF / 3DGS / Gaussian Splatting）**：以重建結果作為精細代理來源，支援「先掃描、後渲染」的工作流；亦可將 Invoker-Render 輸出蒸餾回 3D 表示。

- **雲端串流平台**：與 GeForce Now、PS Cloud Streaming 等架構整合，代理在雲端編碼、影片幀串流到客戶端；persistent KV cache 可跨 session 復用以加速冷啟動。

- **內容創作工具（Blender / Houdini / DaVinci）**：作為外掛插件，讓動畫師在時間軸上編輯代理並即時預覽神經渲染結果。

- **多模態 LLM 代理**：以 LLM 解析使用者自然語言指令，轉換為結構代理（場景圖、軌跡），再交給 Invoker-Render 渲染，形成「語言 → 代理 → 影片」鏈路。

- **數位孿生平台**：將 IoT 感測器、即時定位資料轉為代理，渲染城市、工廠的即時視覺化。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先讀第 1 節建立「視覺代理」與「可控影片生成」的直覺——想像把遊戲引擎的線框圖交給一個會畫畫的 AI，它會根據線框畫出逼真畫面。重點理解「粗略代理」與「精細代理」的差別，以及為什麼需要「即時串流」與「離線創作」兩種模式。技術細節可先跳過，著重在應用想像。

**給 AI 工程師**：直接聚焦第 1 節末段與第 3 節的 ProForcing 訓練流程。理解 TF → RF → RF-DMD → SF-DMD 四階段課程的設計邏輯：先學因果預測、再容忍不完美歷史、再蒸餾到四步、最後在自生成歷史上持續訓練。DMD + 輔助 GAN 損失的組合、block-causal attention 的實作細節、GFT 對骨幹的適配方式，都是落地時的關鍵。

**給研究者**：本論文在「代理粒度」與「長時串流穩定性」兩個軸向上推進。值得深入比較的對象包括 CausVid、Diffusion Forcing、Self Forcing、Matrix-Game 系列、StreamRender-H3、Marionette 等。開放問題包含：代理粒度的理論刻畫、漂移的量化分析、蒸餾步數與可控性的 Pareto 前緣、多代理家族統一表示的可行性。

**給產品經理**：核心訊息是「同一模型權重可同時服務離線創作與即時串流」，這對成本結構與產品矩陣設計有重大意義。30 分鐘穩定展開的數據點是商業可行性的關鍵指標。需關注的權衡：代理粒度選擇對使用者體驗的影響、上行代理傳輸成本、KV cache 對單機併發的約束。建議先以「遊戲雲端串流」或「影視前期預覽」為切入點驗證 PMF，再擴展到機器人訓練與 AR/VR。
