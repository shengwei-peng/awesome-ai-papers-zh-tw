## ⚡ TL;DR

現有公開資料用於電腦代理微調會造成負遷移，且缺乏大規模多樣桌面軌跡。
本文提出ProCUA-SFT，以自動化流程合成扎根任務並驗證前置條件，產生三百一十萬步驟級樣本。
微調後於OSWorld達45%成功率，較基礎模型提升18.7百分點，並已納入Nemotron訓練。

## 摘要翻譯

訓練電腦使用代理 (computer-use agents, CUAs)——即透過螢幕截圖 (screenshots) 與鍵盤/滑鼠操作 (keyboard/mouse actions) 與圖形桌面互動的模型——需要於完整桌面環境 (desktop environments) 中收集大規模且多樣化的軌跡資料 (trajectory data)。目前最大的公開資源 AgentNet（22.5K 人類軌跡 (human trajectories)）用於監督式微調 (supervised fine-tuning, SFT) 時會導致負遷移 (negative transfer)：在 AgentNet 上持續訓練 UI-TARS 7B，將使 OSWorld 成功率 (success rate) 從 26.3% 下降至 8–10%。我們提出 ProCUA-SFT，這是一個從涵蓋 2,484 種應用程式組合 (application combinations) 的 93K 合成軌跡 (synthetic trajectories) 中提煉而得、包含 3.1M 步驟級 SFT 樣本 (step-level SFT samples) 的資料集。該資料集由全自動化流程 (automated pipeline) 產生，此流程 (i) 於已預載真實世界內容 (real-world content) 的即時桌面 (live desktops) 上合成扎根任務 (grounded tasks)——內容包含來自 SpreadsheetBench 的 912 份試算表 (spreadsheets)、約 10K 份來自 Zenodo10K 的寬鬆授權 (permissively-licensed) 簡報 (presentations)，以及多應用程式 OSWorld 設定 (multi-application configs)——並 (ii) 於執行 (rollout) 前透過二元前置條件檢查 (binary precondition checking) 驗證每項任務的可行性。單一視覺語言模型 (Vision-Language Model, VLM) Kimi-K2.5 同時擔任目標生成器 (goal generator)、前置條件判定器 (precondition judge) 與軌跡執行器 (trajectory executor)，消除了規劃-執行能力落差 (planner-actor capability gap)。每條軌跡均展開為步驟前綴樣本 (step-prefix samples)，精確重現推論時間 (inference time) 所見的上下文版面配置 (context layout)。使用 ProCUA-SFT 對 UI-TARS 7B 微調一個訓練週期 (epoch)，於 OSWorld 達到 45.0%——相較基礎模型 (base model) 提升 18.7 百分點 (percentage-point)，且較以 AgentNet 訓練的模型高出超過 35%。部分 ProCUA 資料被納入 Nemotron 3 Nano Omni 模型的訓練資料中，為其電腦使用能力 (computer-use capabilities) 做出貢獻。

### 核心貢獻（3～5點）
- 建構目前最大規模的步驟級 SFT 資料集 ProCUA-SFT（3.1M 步驟級 SFT 樣本），涵蓋 93K 合成軌跡與 2,484 種應用程式組合，有效解決現有公開資源 AgentNet 導致負遷移的問題。
- 設計全自動化資料生成流程，於已預載真實世界內容的即時桌面上合成扎根任務，並透過二元前置條件檢查確保任務可行性，從源頭提升資料品質。
- 以單一 VLM（Kimi-K2.5）同時擔任目標生成器、前置條件判定器與軌跡執行器，消除規劃-執行能力落差，並將軌跡展開為步驟前綴樣本以精確重現推論時間的上下文版面配置。
- 使用 ProCUA-SFT 對 UI-TARS 7B 微調一個訓練週期，即於 OSWorld 達到 45.0% 成功率，較基礎模型提升 18.7 百分點，且較 AgentNet 訓練模型高出逾 35%。
- 資料集已實際應用於 Nemotron 3 Nano Omni 的訓練，驗證其對提升商業模型電腦使用能力的實用價值。

### 適合對象
從事電腦使用代理 (CUA)、視覺語言模型 (VLM) 與代理微調研究的學術與產業研究者，以及需要建構大規模桌面自動化訓練資料、評估真實桌面環境任務表現，或開發跨應用程式推理能力的工程師與開發者。

## 深度分析

#### 方法論解析

ProCUA-SFT 的核心貢獻在於建立一套全自動化流程（automated pipeline），以單一視覺語言模型（VLM）——Kimi-K2.5——同時擔任目標生成器（goal generator）、前置條件判定器（precondition judge）與軌跡執行器（trajectory executor），從而產出 3.1M 步驟級 SFT 樣本（step-level SFT samples）。此流程圍繞四項關鍵設計決策展開：

首先，扎根任務（grounded tasks）的合成與二元前置條件（binary preconditions）驗證機制。不同於過往先隨機生成目標再執行的做法，系統要求 VLM 在產出每個任務目標時，一併列出可透過螢幕截圖（screenshots）與作業系統層級設定（OS-level config）獨立驗證的二元前置條件（例如「桌面是否存在 Q3.xlsx？」）。判定提示（judge prompt）會針對即時桌面（live desktop）進行檢查，僅當所有前置條件皆通過才進入執行（rollout）階段；未通過者則回饋至生成端進行迭代重試（iterative retry）。這從源頭杜絕了不可行目標（infeasible goals）浪費運算資源的問題。

其次，真實世界內容（real-world content）的植入。研究團隊在即時桌面中預先載入 912 份來自 SpreadsheetBench 的真實試算表（spreadsheets）（含超過 100 欄、20K 列的複雜表格）、約 10K 份來自 Zenodo10K 的寬鬆授權（permissively-licensed）簡報（presentations），以及多應用程式設定（multi-application configs）。這使得合成軌跡（synthetic trajectories）必須操作具備真實公式、圖表（charts）、多工作表引用（multi-sheet references）的文件，而非僅在預設應用程式狀態（default application states）下執行空泛指令。

第三，單一 VLM 執行（single-VLM rollout）以閉合規劃-執行能力落差（planner-actor capability gap）。傳統分工架構中，規劃模型提出的目標可能超出執行模型的能力邊界；而採用同一模型同時負責目標合成與軌跡執行，可確保「不會提出自身無法完成的任務」，顯著提升軌跡成功完成的比率。

第四，步驟前綴樣本（step-prefix samples）的展開策略。一條包含 T 步的軌跡會被擴展為 T 筆訓練樣本，其中第 t 筆樣本包含從第一步到第 t 步的完整螢幕截圖與鍵盤/滑鼠操作（keyboard/mouse actions）歷史。這種設計精確重現了推論時間（inference time）逐步增長的上下文版面配置（context layout），避免訓練-推論分佈偏移。

在基礎建設層面，流程採用解耦架構——本地 KVM 透過 Singularity 執行，並搭配無伺服器 NVCF——實現跨異質運算資源的平行化收集。

#### 實驗數據解讀

論文以 OSWorld 作為主要基準測試（benchmark），其評估指標為任務成功率（success rate）。基礎模型（base model）UI-TARS 7B 的原始表現為 26.3%；然而，當以目前最大公開資源 AgentNet（22.5K 人類軌跡）進行一個訓練週期（epoch）的監督式微調（SFT）後，成功率竟暴跌至 8–10%，呈現典型的負遷移（negative transfer）現象。相對地，以 ProCUA-SFT 微調同樣一個訓練週期後，成功率大幅提升至 45.0%。

這組數據具有三層意義：
1. 絕對增益達 18.7 百分點（percentage-point），顯示 3.1M 步驟級樣本確實有效強化了模型對圖形桌面的理解與操作能力。
2. 相較於 AgentNet 訓練後的模型，ProCUA-SFT 高出超過 35 百分點，證明單純堆疊人類示範資料並不保證性能提升，資料品質與任務多樣性遠比數量重要。
3. 該資料集涵蓋 93K 合成軌跡與 2,484 種應用程式組合（application combinations），其規模與跨應用覆蓋度是促成跨應用程式推理（cross-application reasoning）能力提升的關鍵。

此外，論文提及部分 ProCUA 資料已被納入 Nemotron 3 Nano Omni 的訓練資料，並對其電腦使用能力（computer-use capabilities）產生貢獻。這項外部採用可視為對資料集實用性的獨立驗證。

#### 與現有研究的比較

相較於現有文獻，ProCUA-SFT 在資料合成策略上呈現三項顯著差異：

第一，相對於 AgentNet 等群眾外包示範（crowd-sourced demonstrations）資料集，ProCUA-SFT 透過合成方法（synthetic approach）規避了標註雜訊（annotation noise）。AgentNet 雖有 22.5K 軌跡，但多為單一應用程式工作流程（single-application workflows）（中位數僅 17 步），且缺乏複雜跨應用程式推理任務，這正是導致負遷移的主因。

第二，相較於其他自動化合成研究——如 AgentTrek、Explorer、InSTA、Go-Browse、SynthAgent、AgentSynth 與 PC Agent 系列——ProCUA-SFT 採用迴圈內（in-loop）二元前置條件檢查（precondition checking），而非事後過濾（post-hoc filtering）。這確保了每一條進入執行階段的軌跡都具備可行性，顯著提升運算效率。同時，透過植入 SpreadsheetBench 與 Zenodo10K 的真實文件，任務難度遠高於在預設或空白狀態下生成的軌跡。

第三，就規模而言，3.1M 步驟級樣本、93K 軌跡、橫跨 2,484 種應用程式組合，使其成為目前最大的開源桌面電腦使用代理（CUA）訓練資料集。

然而，本研究亦存在侷限性：其一，目前僅報告單一訓練週期的結果，多週期訓練是否會造成過擬合或進一步增益仍屬未知；其二，評估集中於 OSWorld，尚未於 Windows Agent Arena 或 WebArena 等基準測試上驗證跨環境泛化性；其三，整個流程高度依賴 Kimi-K2.5 這一特定 VLM，若該模型為閉源 API，則資料集的持續擴充與社群復現將受到限制。

#### 可重現性評估

從技術報告揭露的資訊來看，ProCUA-SFT 在資料層面具備良好的可重現性基礎：其所使用的真實世界內容來源——SpreadsheetBench（912 份試算表）、Zenodo10K（約 10K 份簡報）以及 OSWorld 的多應用程式設定——均為公開資源。論文明確宣稱 ProCUA-SFT 是「最大的開源桌面 CUA 訓練資料集」（largest open-source desktop CUA training dataset），暗示資料集本身應已或即將對外釋出。

在基礎建設方面，作者詳述了本地 KVM（透過 Singularity）與無伺服器 NVCF 的混合架構，這為異質運算環境下的平行收集提供了可參考的工程範本。

然而，可重現性的主要瓶頸在於流程對單一視覺語言模型 Kimi-K2.5 的深度依賴。由於該模型同時擔任目標生成、前置條件判定與軌跡執行，若 Kimi-K2.5 為商業閉源 API，則其他研究者難以完全復現相同的資料生成流程，僅能使用已釋出的靜態資料集進行監督式微調（SFT）。此外，技術報告並未明確提及自動化流程的原始碼（code）或 UI-TARS 7B 經微調後的模型權重（model weights）是否公開，這使得「從零開始復現整條管線」的難度仍高。

#### 未來研究方向

基於 ProCUA-SFT 的架構與實驗結果，以下幾個方向值得後續探索：

1. 多週期訓練與強化學習（RL）的結合：目前僅驗證單一訓練週期的效益。未來可探討多週期 SFT 的邊際效益遞減點，或參考 DigiRL 的線上強化學習（online RL）框架，在 ProCUA-SFT 上進行進一步的策略優化。

2. 跨基準測試（benchmark）泛化驗證：將訓練後的模型擴展至 Windows Agent Arena、WebArena、VisualWebArena 與 AndroidWorld 等環境，檢驗其跨作業系統（operating systems）與跨平台（web、mobile、desktop）的通用性。

3. 降低對單一閉源 VLM 的依賴：驗證其他開源視覺語言模型（如 Qwen2.5-VL、Llama-Vision 等）是否能同時勝任目標生成、前置條件判定與軌跡執行三重角色，並比較其規劃-執行能力落差（planner-actor capability gap）的閉合程度。

4. 動態難度調適與長期軌跡合成：目前 93K 軌跡已涵蓋 2,484 種應用程式組合，但長期軌跡（long-horizon tasks）與資訊不對稱任務（參考 AgentSynth）的結合，可進一步挑戰模型在複雜桌面環境中的系統二推理（system-2 reasoning）能力。

5. 自我修正與資料集自我擴充：借鏡 AgentRefine 的概念，利用模型對失敗軌跡進行自我修正（self-correction），並將修正後的成功案例回流至 ProCUA-SFT，形成自動化的資料飛輪（data flywheel）。

6. 推論時間（inference time）的上下文壓縮：隨著步驟前綴樣本在推論時不斷增長，如何設計高效的視覺 token 壓縮機制（如 ShowUI 的 UI-guided selection）以降低延遲，亦是實用化的關鍵課題。

## 論文問答

**Q1：ProCUA-SFT 旨在解決訓練電腦使用代理（CUA）時的什麼核心問題？**

A：ProCUA-SFT 主要解決的是大規模、高品質且具多樣性的桌面軌跡資料嚴重不足的瓶頸。現有最大的公開資源 AgentNet 雖然包含 2.25 萬條人類軌跡，卻會在監督式微調時造成負遷移，使 UI-TARS 7B 在 OSWorld 上的成功率從 26.3% 暴跌至 8–10%。這顯示單純依靠現有人類示範資料無法有效提升開源 CUA 的能力，因此需要一套能自動生成大規模可行且高難度任務軌跡的新方法。

**Q2：為什麼目前最大的公開人類軌跡資料集 AgentNet 會在監督式微調中導致負遷移？**

A：AgentNet 導致負遷移可歸因於三大因素：首先，其任務多樣性有限，大多數軌跡是單一應用程式的工作流程，中位數僅 17 個步驟；其次，資料中缺乏需要複雜跨應用程式推理的任務；最後，群眾外包示範本身帶有標註雜訊。這些問題使得模型從中學習到的行為模式過於狹隘且帶有錯誤，反而損害了原本具備的桌面操作能力。

**Q3：相較於純文字指令微調，為什麼高品質的軌跡資料對電腦使用代理特別重要？**

A：不同於純文字任務，每一條 CUA 軌跡都需要一個完整實例化的桌面環境，包括已開機的虛擬機器、安裝好的應用程式以及真實的檔案內容，這使得資料收集的成本與複雜度遠高於整理文字語料。若缺乏足夠多樣且扎根於真實內容的訓練資料，代理便難以學會處理圖形介面中的視覺細節與長程規劃。因此，突破資料瓶頸是推動開源 CUA 從實驗室走向實用化的關鍵前提。

**Q4：ProCUA-SFT 生成 310 萬筆步驟級訓練樣本的核心方法為何？**

A：ProCUA-SFT 採用一套全自動化流程，在即時桌面上以真實世界內容為種子合成扎根任務，並透過二元前置條件檢查驗證每個任務的可行性，再由單一視覺語言模型執行軌跡。接著，每條軌跡會被展開為步驟前綴樣本，讓每一筆訓練資料都精確重現推論時所見的成長式上下文版面配置。這種設計確保了訓練樣本不僅在任務層面可行，也在視覺與互動脈絡上與實際推論環境高度一致。

**Q5：相較於朴素的合成軌跡生成，ProCUA-SFT 的四項關鍵設計決策是什麼？**

A：第一項是「扎根任務合成與前置條件驗證」，透過二元檢查確保任務在目標桌面上確實可執行；第二項是「真實世界內容播種」，使用 SpreadsheetBench 與 Zenodo10K 等真實複雜文件作為操作對象，而非空白的預設狀態；第三項是「單一 VLM 執行」，以 Kimi-K2.5 同時擔任目標生成器與軌跡執行器，消除規劃者與執行者之間的能力落差；第四項是「步驟前綴展開」，將每條軌跡拆解為符合推論時上下文布局的步驟級樣本。這四項決策共同確保了資料品質、多樣性與訓練推論一致性。

**Q6：單一 VLM 的設計如何解決規劃-執行能力落差，且這對合成資料生成為何重要？**

A：傳統方法常由較強的規劃模型生成目標，再由較弱的執行模型實作，導致產生許多執行者根本無法完成的不可行目標。ProCUA-SFT 讓 Kimi-K2.5 同時負責生成目標與執行軌跡，因此模型絕不會提出超出自身能力範圍的任務。這大幅提升了軌跡成功完成的比率，避免浪費大量運算資源在無效的執行上，是合成資料能夠規模化的核心關鍵。

**Q7：ProCUA-SFT 主要在哪些基準測試上進行評估，基線比較為何？**

A：ProCUA-SFT 的主要評估基準是 OSWorld，該測試在真實的 Linux、Windows 與 macOS 虛擬機器中提供 369 項桌面任務，並允許不受限制的鍵盤與滑鼠控制。基線方面，UI-TARS 7B 基礎模型的成功率為 26.3%，而在 AgentNet 上微調一個週期後則慘跌至 8–10%。這些基線清楚展示了負遷移現象，也為 ProCUA-SFT 的改進幅度提供了嚴格的比較基礎。

**Q8：在 UI-TARS 7B 上進行 ProCUA-SFT 微調後，取得了哪些關鍵量化成果？**

A：在 ProCUA-SFT 上微調一個週期後，UI-TARS 7B 在 OSWorld 上的成功率達到 45.0%，較基礎模型提升了 18.7 個百分點。與在 AgentNet 上訓練的模型相比，更是高出超過 35 個百分點。這些數據證明 ProCUA-SFT 不僅完全避免了負遷移，還大幅推進了開源電腦使用代理的效能上限。

**Q9：ProCUA-SFT 與直接使用 AgentNet 這類人類收集軌跡相比，表現差異為何？**

A：AgentNet 雖擁有 2.25 萬條人類跨平台軌跡，但用於監督式微調卻導致 OSWorld 成功率從 26.3% 大幅下滑至 8–10%，顯示人類示範的規模與真實性並不保證訓練效益。相對地，ProCUA-SFT 以 9.3 萬條合成軌跡產出 310 萬筆樣本，成功將成功率推升至 45.0%。這項對比凸顯了資料的可行性驗證、任務多樣性與跨應用程式複雜度，遠比單純的人類標註更為關鍵。

**Q10：ProCUA-SFT 訓練出的代理在哪些真實桌面自動化場景中最具應用價值？**

A：由於訓練資料播種了來自 SpreadsheetBench 的複雜試算表與 Zenodo10K 的真實簡報，訓練出的代理特別擅長處理涉及多應用程式的文件操作，例如編輯含公式、圖表與多工作表引用的試算表，或修改內容豐富的簡報檔。這些能力可直接應用於企業辦公自動化、個人生產力助理以及軟體測試等場景。相較於僅在預設空白狀態下訓練的代理，這種扎根於真實內容的資料使模型更能應對實際工作負載。

**Q11：為何 ProCUA 的部分資料會被納入 Nemotron 3 Nano Omni 的訓練數據，這暗示了什麼樣的產品價值？**

A：ProCUA 的子集被用於 Nemotron 3 Nano Omni 的訓練，並為該模型的電腦使用能力做出貢獻，這代表其合成軌跡的品質已達到可投入商業級模型開發的水準。被主流模型家族採用，說明 ProCUA-SFT 不僅是學術研究資料集，更具備實際的產品應用價值。這也顯示該資料集能作為多模態模型訓練的有效互補來源，協助提升終端產品的桌面自動化功能。

**Q12：ProCUA-SFT 如何以「不僅是另一個訓練資料集」的方式推動視覺型 GUI 代理領域？**

A：ProCUA-SFT 提出了一套可擴展的全自動化流程，結合可行性驗證與真實內容播種，為桌面 CUA 訓練資料的生成建立了新標準。其規模達到 310 萬筆樣本、涵蓋 2,484 種應用程式組合，是目前最大的開源桌面 CUA 訓練資料集，直接回應了長期以來阻礙領域進展的資料瓶頸。此外，前置條件檢查與單一 VLM 執行等創新設計，更為未來的合成資料研究提供了可複用的方法論框架。

**Q13：儘管具備前置條件驗證，ProCUA-SFT 流程仍面臨哪些固有挑戰或限制？**

A：整個流程高度依賴單一視覺語言模型 Kimi-K2.5 的能力，這意味著合成任務的複雜度上限受制於該模型本身的規劃與執行水準，可能無法涵蓋需要更高階推理的任務。此外，雖然任務扎根於真實內容，但目標本身仍是合成生成，未必能完整覆蓋真實使用者所有細微意圖與邊緣行為。同時，維護大量即時虛擬機器與異構運算基礎設施所需的運算成本，也可能對部分研究團隊的參與構成門檻。

**Q14：在哪些任務或情境下，ProCUA-SFT 流程可能會失敗或產出低品質軌跡？**

A：若任務需要超越目前 VLM 能力範圍的抽象推理，或是涉及無法透過簡單二元前置條件與螢幕截圖捕捉的細微系統狀態，則可能在通過初步檢查後仍於執行階段失敗。對於需要極長程規劃的複雜跨應用程式任務，模型也可能在軌跡中途偏離目標而產出不完整的示範。另外，若播種的真實世界內容包含罕見格式或損毀檔案，而判定提示未能預先識別，則生成的任務可能會引用無法正常操作的資料狀態。

**Q15：根據目前的設計與成果，ProCUA-SFT 未來可朝哪些方向改進或延伸？**

A：未來可整合類似 DigiRL 的線上強化學習機制，在靜態監督式微調之外進一步優化軌跡品質，或借鏡 AgentRefine 的自我修正框架來精煉失敗軌跡。前置條件檢查也可從目前的二元判斷擴展為更細緻的語義驗證，以降低殘留的不可行任務比例。此外，將流程擴展到更多作業系統與應用程式，並引入人類在迴路驗證，將有助於縮小合成訓練分佈與真實世界使用者任務之間的差距。

## 實務應用指南

### 適用場景

1. **企業跨應用程式流程自動化（RPA 2.0）**  
   適合需要串聯多個桌面應用程式的業務流程，例如從含多工作表引用、公式與圖表的試算表擷取數據，自動生成並排版簡報，再透過電子郵件客戶端寄出。ProCUA-SFT 的 2,484 種應用程式組合與跨應用程式推理能力，可直接取代傳統僅能操作單一應用程式的 RPA 腳本。

2. **複雜文件處理與資料轉換**  
   針對財務、法律或生管單位需處理的大型真實世界內容（如超過 100 欄、20K 列的試算表，或含多層投影片的簡報），可訓練電腦使用代理（CUA）自動執行格式轉換、樞紐分析、圖表更新等任務，無需人工逐一操作。

3. **軟體測試與端到端 QA 驗證**  
   在實例化桌面（開機 VM、安裝完整應用程式、載入真實檔案）中，讓代理模擬真人透過螢幕截圖與鍵盤/滑鼠操作執行回歸測試，特別適合驗證涉及多視窗互動的桌面軟體流程。

4. **智慧生產力助理**  
   整合於作業系統層級的數位助理，可理解使用者自然語言指令，直接在桌面環境中操作試算表、簡報軟體與瀏覽器完成任務，例如「將 Q3 財報試算表的圖表貼到董事會簡報第 5 頁」。

5. **合成訓練資料服務**  
   對於缺乏大規模人類軌跡的特定垂直領域（如醫療影像 DICOM 工作站或 CAD 軟體），可借用 ProCUA-SFT 的自動化流程，以單一視覺語言模型（VLM）生成扎根任務、執行前置條件檢查並收集合成軌跡，快速產出步驟級 SFT 樣本。

### 實作前置條件

**資料準備**
- 真實世界內容作為播種素材：需取得 SpreadsheetBench 等真實試算表、Zenodo10K 等寬鬆授權簡報，以及多應用程式設定（如 OSWorld configs），避免僅使用預設應用程式狀態。
- 基礎模型與評估基準：準備 UI-TARS 7B 等開源 CUA 基礎模型，以及 OSWorld 等桌面任務基準測試作為驗證環境。

**運算資源**
- 虛擬機器基礎設施：需建置支援 KVM 的本地運算叢集，並以 Singularity 管理容器化桌面環境；或具備 NVCF 等無伺服器運算資源以支援平行收集。
- GPU 推論與訓練資源：執行 Kimi-K2.5 等 VLM 進行目標生成、前置條件判定與軌跡執行需大量 GPU 推論容量；後續監督式微調（SFT）至少需支援 7B 模型全參數微調的顯示記憶體。

**技術能力**
- 熟悉 VLM 提示工程：能設計二元前置條件的判定提示（judge prompt），並處理迭代重試邏輯。
- VM 與作業系統管理：具備 Linux/Windows 虛擬機器（VM）自動化部署、螢幕截圖擷取與鍵盤/滑鼠指令注入的實作經驗。
- 模型微調工程：理解步驟前綴擴展（step-prefix expansion）的資料格式設計，並能執行一個訓練週期（epoch）的 SFT。

---

### 實作步驟建議

**步驟一：建置實例化桌面叢集**  
部署本地 KVM 環境並以 Singularity 封裝不同作業系統的桌面映像檔，確保每個執行個體都具備完整圖形介面、已安裝的應用程式與可寫入的檔案系統。同步設定 NVCF 或類似無伺服器架構，以便後續平行執行軌跡收集。

**步驟二：播種真實世界內容**  
將 912 份 SpreadsheetBench 試算表（含複雜公式、圖表與多工作表引用）、約 10K 份 Zenodo10K 簡報，以及 OSWorld 多應用程式設定檔，自動化注入各虛擬機器的桌面與文件資料夾，確保任務目標能扎根於真實文件而非空殼環境。

**步驟三：自動化扎根任務合成與前置條件驗證**  
使用 Kimi-K2.5 作為單一目標生成器，針對目前桌面狀態產出任務描述與一組二元前置條件（例如「Desktop 上是否存在 Q3.xlsx？」）。透過獨立的前置條件判定器（同一 VLM 切換判定提示）比對螢幕截圖與作業系統層級設定；僅當所有前置條件通過才進入執行階段，否則回饋失敗原因進行迭代重試。

**步驟四：單一 VLM 執行與步驟級樣本擴展**  
由同一 VLM 擔任軌跡執行器，消除規劃-執行能力落差。每條軌跡在執行過程中記錄每一步的螢幕截圖與鍵盤/滑鼠操作，並透過步驟前綴擴展將長度為 T 的軌跡轉換為 T 個訓練樣本，使每個樣本都包含截至該步為止的完整上下文版面配置，精確重現推論時間的成長中歷史紀錄。

**步驟五：監督式微調**  
將收集到的 3.1M 步驟級 SFT 樣本（ProCUA-SFT）用於微調 UI-TARS 7B 等基礎模型。根據論文結果，通常只需一個訓練週期即可在 OSWorld 上將成功率從 26.3% 提升至 45.0%。

**步驟六：評估與產品化部署**  
於 OSWorld 或自訂基準測試驗證成功率，確認無負遷移現象後，將模型整合至產品後端，並透過 API 提供桌面操作能力。

### 潛在風險與注意事項

- **負遷移風險**：直接使用人類軌跡（如 AgentNet）進行監督式微調可能導致成功率從 26.3% 跌至 8–10%。若已有舊版人類標註資料，應審慎評估其任務多樣性與標註雜訊，或優先採用經前置條件檢查驗證的合成軌跡。
- **不可行目標浪費運算**：若未在執行前驗證檔案存在性與應用程式狀態，大型語言模型生成任務容易參照不存在的路徑，導致大量無效執行。務必落實二元前置條件檢查於執行（rollout）之前，而非僅做事後過濾。
- **規劃-執行能力落差**：若目標生成器與軌跡執行器採用不同模型，規劃端可能提出執行端無法完成的複雜目標。建議採用單一 VLM 執行，確保模型不會提出超出自身能力範圍的任務。
- **上下文版面配置偏差**：訓練時若僅儲存軌跡最終狀態或固定長度視窗，將與推論時間的成長中歷史產生分佈偏移。必須使用步驟前綴樣本，讓模型在訓練階段就適應逐步累積的螢幕截圖與操作歷史。
- **授權與合規**：播種內容包含外部真實世界內容（試算表、簡報），需確認寬鬆授權條款允許用於合成軌跡與模型訓練，避免衍生商業應用的法律風險。

### 與其他技術的整合建議

- **傳統 RPA 與遺留系統**：對於缺乏 API 的老舊桌面軟體，ProCUA-SFT 訓練出的 CUA 可透過螢幕截圖與鍵盤/滑鼠指令直接操作，作為傳統 RPA 的視覺層補強，無需解析 DOM 樹或 accessibility API。
- **LLM 編排框架**：可將微調後的模型封裝為 LangChain、AutoGen 或 LlamaIndex 中的工具節點（Tool Node），負責「桌面操作」技能，讓上層規劃器專注於任務分解，而 CUA 專注於執行跨應用程式推理。
- **雲端虛擬桌面基礎設施**：搭配 AWS WorkSpaces、Azure Virtual Desktop 或 Citrix，在隔離的雲端 VM 中執行代理，確保企業資料不落地，同時利用彈性運算資源擴展軌跡收集。
- **資料管線與 BI 工具**：上游連接企業資料湖，自動將原始數據轉換為播種用的試算表與簡報；下游銜接 Power BI 或 Tableau，由 CUA 自動完成資料整理與報告產出。
- **線上強化學習與自我修正**：參考 AgentRefine 等技術，將執行失敗的軌跡回饋至自動化流程，透過自我修正精煉後重新納入訓練資料，形成持續學習閉環。

### 給不同背景讀者的閱讀建議

**給初學者**  
建議先建立電腦使用代理（CUA）的基本概念：它是一種透過螢幕截圖觀察桌面、再輸出鍵盤/滑鼠操作來完成任務的 AI 模型。閱讀時請聚焦「適用場景」與「實作步驟建議」，將本技術想像成一位可 24 小時操作試算表與簡報軟體的數位實習生；VLM 架構與前置條件檢查的技術細節可先略過，待熟悉整體流程後再回頭深究。

**給 AI 工程師**  
請重點研讀「單一 VLM 執行」與「步驟前綴擴展」的實作細節，這是論文提升成功率的兩大關鍵。你應評估如何將 Kimi-K2.5 的角色（目標生成器、前置條件判定器、軌跡執行器）移植至團隊現有的視覺語言模型，並注意 KVM/Singularity 與 NVCF 的混合基礎設施如何實現平行收集。此外，請仔細比較 ProCUA-SFT 與 AgentNet 的資料格式差異，以避免負遷移。

**給研究人員**  
本論文的核心貢獻在於揭示「資料品質與驗證機制」對桌面代理的因果影響。建議深入分析：為何 AgentNet 這類大規模人類軌跡會引發負遷移？二元前置條件檢查相較於事後過濾，對資料效率與軌跡成功率的具体量化貢獻為何？此外，可思考如何將此前置條件驗證框架擴展至多模態推理、跨作業系統遷移學習，或結合線上 RL 進一步超越 SFT 天花板。

**給產品經理**  
請將閱讀重心放在「適用場景」與「潛在風險與注意事項」。評估導入 ProCUA-SFT 訓練流程的 ROI 時，請注意：相較於傳統 RPA 或人力，此方案能以單一訓練週期即顯著提升基準測試成功率（18.7 百分點），大幅降低資料收集成本。但同時需評估真實世界內容播種帶來的授權合規議題，以及維護虛擬機器叢集的營運成本。與 Nemotron 3 Nano Omni 的合作案例可作為說服內部利害關係人的參考依據。
