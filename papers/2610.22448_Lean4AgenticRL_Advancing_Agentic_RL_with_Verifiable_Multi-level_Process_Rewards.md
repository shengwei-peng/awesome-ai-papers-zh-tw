## ⚡ TL;DR

現有代理式強化學習僅依賴高層級結果獎勵，缺乏中層級工作流程與低層級工具呼叫獎勵，訓練效果受限。
本文提出Lean4AgenticRL框架，首創以Lean4統一形式化架構整合多層級過程獎勵。
LAR-27B在TerminalBench-2.1達77.3%，平均勝基準9.89%、同級最佳5.07%。

## 摘要翻譯

增強大型語言模型 (LLM) 的代理能力以處理複雜的軟體工程 (SWE) 與一般終端機使用問題，是一項迫切的挑戰。當前最先進的 LLM 通常透過大規模的代理式強化學習 (RL) 進行訓練。然而，這些模型主要依賴高層級結果獎勵，對低層級工具呼叫與中層級工作流程階段獎勵的考量極少，導致訓練效果不佳。為克服此限制，我們提出 **Lean4AgenticRL**，據我們所知，這是首個將多層級過程獎勵奠基於統一 Lean4 形式化綱要、用於開放式代理式強化學習的框架。**Lean4AgenticRL** 首先建立一個*問題特定工作流程* (PSWF) 系統，在執行過程中平衡代理自身的能力與可控性，為後續驗證奠定基礎。接著，我們的工作流程形式化與多層級獎勵標註方法能在通用執行系統中實現代理行為驗證，並透過工作流程階段正規化 GRPO 演算法提供多層級獎勵，以支援更有效的代理式強化學習。運用 **Lean4AgenticRL**，我們訓練了 **LAR-9B/27B**——一系列具備增強代理能力的模型。大量實驗顯示，我們的模型優於同類規模的領先模型：**LAR-27B** 在 TerminalBench-2.1 上達到 **77.3%**；平均而言，我們的模型較基礎模型高出 **9.89%**，並較我們所知同類規模的第二佳模型高出 **5.07%**。這些結果展現了將形式化方法整合於增強開放式代理式強化學習中的潛力。

### 核心貢獻（3～5點）
- **首創統一形式化框架**：提出 Lean4AgenticRL，為首個將多層級過程獎勵奠基於統一 Lean4 形式化綱要的代理式強化學習框架，兼顧低層級工具呼叫、中層級工作流程階段與高層級結果獎勵。
- **問題特定工作流程系統**：設計 PSWF 系統，在執行過程中平衡代理自身能力與可控性，為後續形式化驗證奠定基礎。
- **多層級獎勵標註與工作流程形式化**：在通用執行系統中實現代理行為驗證，並透過工作流程階段正規化 GRPO 演算法提供多層級可驗證獎勵，提升訓練成效。
- **優異實驗表現**：基於所提框架訓練的 LAR-9B/27B 模型展現增強的代理能力，其中 LAR-27B 於 TerminalBench-2.1 達 77.3%，平均較基礎模型高出 9.89%，並超越同類規模的第二佳模型 5.07%。

### 適合對象
從事大型語言模型代理能力研究、強化學習（特別是代理式強化學習與可驗證獎勵強化學習）、形式化方法應用於 AI，以及軟體工程自動化與終端機使用代理等領域的研究者與工程師；亦適合關注長時程代理任務訓練與開源模型效能基準比較的研究團隊與業界實務人員參考。

## 深度分析

#### 方法論解析

**Lean4AgenticRL 框架的整體設計理念**

Lean4AgenticRL 的核心創新在於將形式化方法（formal methods）引入開放式代理式強化學習（open-ended agentic RL），透過 Lean4 這個依賴型別（dependent-type）可驗證語言，建立統一的多層級獎勵機制。傳統的代理式強化學習主要依賴高層級結果獎勵（high-level outcome rewards），這種粗粒度的獎勵信號難以區分成功軌跡中的有效中間步驟與冗餘或錯誤步驟，導致訓練效率受限。Lean4AgenticRL 透過引入中層級工作流程階段獎勵（mid-level workflow-stage rewards）與低層級工具呼叫獎勵（low-level toolcall rewards），形成三層級的獎勵體系，從而提供更細粒度的學習信號。

**問題特定工作流程（PSWF）系統**

框架的第一步是建立問題特定工作流程（Problem-Specific Workflow, PSWF），採用「先規劃後執行」（plan-then-execute）的範式。此設計包含兩個關鍵代理：

1. **規劃代理（Planning Agent）**：接收問題陳述與任務環境，產生通用工作流程（General Workflow），再透過探索軌跡（Exploration Trajectory）將其精煉為問題特定工作流程（PSWF）。此步驟平衡了代理自身能力與執行可控性。

2. **執行代理（Execution Agent）**：基於 PSWF 執行任務，產生執行軌跡（Execution Trajectory）。

這種分離設計的優勢在於：規劃階段允許代理充分探索問題空間，而執行階段則在已驗證的工作流程約束下進行，提高了行為的可預測性與可驗證性。

**工作流程形式化與多層級獎勵標註**

此步驟是框架的核心技術貢獻。Lean4AgenticRL 將 Lean4Agent 驗證系統從固定工作流程擴展至通用執行系統（general harness system），具體做法為：

- 將代理軌跡形式化為異質有向圖 $G = \langle V, E \rangle$，其中 $V = \{v_i\}_{i=1}^{m}$ 包含工作流程階段，$E \subseteq V \times V$ 指定階段間允許的轉換。
- 為每個階段定義前置條件 $\rho_i^{(pre)}$ 與後置條件 $\rho_i^{(post)}$，描述代理行為的原子性質。
- 透過標註代理（Annotation Agent）將軌跡分割為分段軌跡（Segmented Trajectory），並標註三類獎勵：
  - 高層級結果獎勵 $\alpha$：評估最終任務完成度
  - 中層級工作流程階段獎勵 $\beta_i$：評估各階段的進展
  - 低層級工具呼叫獎勵 $\gamma_j$：評估個別工具呼叫的正確性

**工作流程階段正規化 GRPO 演算法**

訓練階段採用工作流程階段正規化 GRPO（workflow-stage-normalized GRPO）演算法，將三層級獎勵 $\alpha \oplus \beta \oplus \gamma$ 整合至群組相對策略優化（Group Relative Policy Optimization, GRPO）框架中。此設計的關鍵在於「正規化」機制——透過工作流程階段的劃分，將長軌跡的獎勵分配問題轉化為可管理的子問題，避免稀疏獎勵問題，同時保持各層級獎勵的相對權重平衡。

#### 實驗數據解讀

**主要效能結果**

LAR-27B 在 TerminalBench-2.1 上達到 77.3% 的準確率，這是一個相當顯著的成果。考慮到 TerminalBench-2.1 評估的是終端機使用能力，涉及複雜的命令列操作與多步驟任務執行，此成績顯示模型在長時程代理任務（long-horizon agent tasks）上具備強大的實戰能力。

**相對改進幅度**

- 相較於基礎模型平均提升 9.89%
- 相較於同規模第二佳模型平均超越 5.07%

這兩個數字揭示了幾個重要訊息：

1. **基礎模型的局限性**：9.89% 的提升幅度說明，即使是經過良好預訓練的基礎模型，在缺乏多層級獎勵引導的情況下，仍難以有效學習代理行為。純粹的結果獎勵無法提供足夠的學習信號。

2. **同類方法的差距**：5.07% 的超越幅度顯示 Lean4AgenticRL 相較於現有的代理式強化學習方法具有實質性優勢，這不僅是統計噪音，而是方法論層面的改進。

3. **規模效應**：LAR-9B 與 LAR-27B 的雙版本發布表明框架在不同模型規模下均有效，這對於方法的實用性與可擴展性具有重要意義。

**基準測試的選擇**

論文在三個基準上進行評估，涵蓋軟體工程（SWE）與終端機使用兩個維度。這種多維度評估避免了單一基準的過擬合風險，能更全面地反映模型的代理能力。然而，論文中未提供各基準的詳細分數拆解，這限制了我們對模型在不同任務類型上表現差異的深入理解。

#### 與現有研究的比較

**相較於純結果獎勵方法**

現有的代理式強化學習方法（如 Zeng et al., 2026; Xu et al., 2026; Team et al., 2026）主要依賴高層級結果獎勵。Lean4AgenticRL 的核心優勢在於：

- **更細粒度的學習信號**：透過中層級與低層級獎勵，模型能學習到「為何成功」而不僅是「是否成功」
- **更好的信用分配（credit assignment）**：在長軌跡中，能更準確地將成功歸因於特定的階段或工具呼叫
- **對冗餘步驟的識別能力**：結果獎勵無法區分高效軌跡與冗餘軌跡，而多層級獎勵可以

**相較於純工具呼叫獎勵方法**

部分現有研究（如 Wang et al., 2026c; Xi et al., 2026）專注於低層級工具呼叫獎勵。Lean4AgenticRL 的改進在於：

- **避免局部最優**：純工具呼叫獎勵可能導致模型過度優化個別呼叫的正確性，而忽略整體工作流程的進展
- **銜接任務目標**：當單一工具呼叫無法直接對接任務目標時，純低層級獎勵會失效，而中層級獎勵提供了必要的橋樑

**相較於 Lean4Agent 框架**

Lean4AgenticRL 將 Lean4Agent 從固定工作流程擴展至通用執行系統，這是一個重要的範式轉變：

- **適用範圍擴大**：從受限場景擴展至開放式代理任務
- **形式化驗證的實用化**：將理論上的形式化驗證能力轉化為實際的訓練信號

**局限性分析**

儘管成果顯著，Lean4AgenticRL 仍存在以下局限：

1. **對規劃代理的依賴**：PSWF 的品質直接影響後續驗證與訓練，若規劃代理產生的工作流程本身有誤，可能導致錯誤的獎勵信號傳播。

2. **形式化成本**：將工作流程形式化為 Lean4 schema 需要額外的計算與標註成本，這在實際部署中可能成為瓶頸。

3. **領域泛化性**：雖然論文聲稱適用於開放式領域，但實驗主要集中在 SWE 與終端機使用任務，對其他代理任務（如網頁瀏覽、API 互動）的有效性仍待驗證。

4. **基準測試的全面性**：三個基準的選擇雖然合理，但缺乏對更廣泛任務類型的評估，難以全面判斷方法的泛化能力。

#### 可重現性評估

**程式碼與模型開源**

論文明確聲明程式碼與模型已在 GitHub 開源（https://github.com/RickySkywalker/Lean4AgenticRL），這對於學術界跟進研究至關重要。開源內容應包含：

- Lean4AgenticRL 框架的完整實作
- LAR-9B/27B 模型權重
- 訓練資料與標註流程
- 評估腳本與基準測試配置

**可重現性的優勢**

1. **形式化基礎**：基於 Lean4 的形式化驗證提供了嚴格的語義保證，減少了實作中的歧義性。

2. **統一框架**：所有組件（PSWF、形式化、獎勵標註、訓練）均在統一框架下設計，降低了組裝不同工具的複雜度。

3. **明確的演算法描述**：工作流程階段正規化 GRPO 演算法的描述提供了清晰的實作指引。

**潛在的可重現性挑戰**

1. **Lean4 環境配置**：Lean4 形式化系統的安裝與配置可能對不熟悉形式化方法的團隊構成障礙。

2. **標註代理的隨機性**：標註代理（Annotation Agent）的行為可能引入隨機性，需要設定固定的隨機種子以確保可重現性。

3. **基準測試的動態性**：TerminalBench-2.1 等基準可能隨時間更新，需注意評估時的版本一致性。

4. **計算資源需求**：訓練 LAR-27B 模型所需的計算資源未明確說明，這可能限制中小型研究團隊的跟進能力。

#### 未來研究方向

**形式化方法的深化應用**

1. **更豐富的形式化語義**：目前的 Lean4 schema 主要捕捉工作流程的結構性資訊，未來可探索納入時序邏輯（temporal logic）或機率模型，以表達更複雜的代理行為約束。

2. **自動化形式化生成**：目前的工作流程形式化可能需要人工介入，未來可研究如何自動化從自然語言任務描述生成 Lean4 schema，降低形式化的門檻。

3. **跨領域形式化**：將 Lean4AgenticRL 擴展至其他代理任務領域，如網頁瀏覽、API 互動、機器人控制等，驗證框架的領域泛化能力。

**獎勵機制的進一步優化**

1. **動態獎勵權重**：目前三層級獎勵的權重可能為固定值，未來可探索根據任務特性或訓練階段動態調整權重。

2. **獎勵稀疏性問題**：在極長軌跡中，即使有三層級獎勵，仍可能面臨稀疏性問題，可研究引入內在動機（intrinsic motivation）或好奇心驅動（curiosity-driven）的補充信號。

3. **負面獎勵的精細化**：目前的設計似乎主要關注正面獎勵，未來可探索如何更精細地標註與利用負面獎勵（如錯誤恢復、異常處理）。

**演算法層面的改進**

1. **替代 GRPO 的探索**：雖然工作流程階段正規化 GRPO 表現優異，但可探索其他策略優化演算法（如 PPO 的變體、Actor-Critic 方法）在多層級獎勵下的表現。

2. **階層式強化學習整合**：將 Lean4AgenticRL 與傳統階層式強化學習（hierarchical RL）結合，利用形式化的工作流程作為高層級策略的骨架。

3. **元學習與快速適應**：研究如何使模型快速適應新的工作流程 schema，提升跨任務的遷移能力。

**評估與基準的完善**

1. **更全面的基準測試**：開發涵蓋更多代理任務類型的標準化基準，特別是那些難以形式化的開放式任務。

2. **安全性與魯棒性評估**：代理系統的安全性至關重要，未來應加入對抗性測試、異常輸入處理等維度的評估。

3. **人機協作評估**：研究 Lean4AgenticRL 訓練的模型在與人類協作完成任務時的表現，這是實際部署的關鍵場景。

**理論基礎的建立**

1. **收斂性分析**：對工作流程階段正規化 GRPO 進行理論分析，建立收斂性與最優性的形式化保證。

2. **樣本複雜度**：研究達到特定效能水平所需的樣本數量，為實際訓練提供理論指導。

3. **與人類專家知識的整合**：探索如何將人類專家的領域知識編碼至 Lean4 schema 中，進一步提升獎勵信號的品質。

總結而言，Lean4AgenticRL 代表了將形式化方法引入現代代理式強化學習的重要嘗試，其多層級獎勵設計與工作流程形式化機制為解決長時程代理任務中的信用分配問題提供了新思路。雖然仍存在計算成本、領域泛化等方面的挑戰，但其在 TerminalBench-2.1 等基準上的顯著效能提升證明了該方向的可行性與潛力，為未來的研究開闢了豐富的探索空間。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於如何有效提升大型語言模型（LLM）在複雜軟體工程（SWE）與終端機使用（terminal-usage）任務中的代理能力（agentic capability）。具體而言，現有的代理式強化學習（agentic RL）方法在處理長時程（long-horizon）任務時，難以可靠地對代理的長軌跡（trajectory）指派過程獎勵（process rewards）。這個問題的核心在於，僅依賴最終結果的回饋訊號，無法區分成功軌跡中真正有用的中間步驟與冗餘或錯誤的動作，從而限制了訓練的效率與效果。

**Q2：為什麼現有的代理式強化學習方法效果不佳？**
A：現有方法主要依賴高層級的結果獎勵（outcome rewards），這是從單輪可驗證獎勵強化學習（RLVR）的成功經驗中直接延伸而來。然而，這類獎勵訊號無法直接辨別成功軌跡中哪些中間動作是真正有貢獻的、哪些是冗餘的，使得訓練訊號變得稀疏且不具區辨力。雖然部分研究開始引入過程獎勵，但它們往往只聚焦於低層級的工具呼叫（toolcall）結果，忽略了更宏觀的工作流程進展，導致當單一工具呼叫無法直接對應任務目標時，訓練效果會顯著下降。

**Q3：為什麼這個研究方向很重要？**
A：LLM 執行長時間代理任務的能力已被電腦科學社群視為一項關鍵能力，並具有高度的實務價值，無論是在自動化軟體開發、系統除錯或終端機操作等場景皆然。隨著 RLVR 與多輪代理式強化學習方法的成功，社群在 SWE 與終端機使用等長時程任務上已取得顯著進展，但若無法解決過程獎勵指派的根本問題，這些進展將難以進一步突破。因此，建立一個能統一高、中、低三層級獎勵的可驗證框架，對於推動代理式強化學習的下一波發展至關重要。

**Q4：Lean4AgenticRL 的核心方法是什麼？**
A：Lean4AgenticRL 是一個統一框架，透過 Lean4 形式化架構（formalization schema）衍生多層級獎勵，用於開放式代理式強化學習。其方法包含三個主要步驟：首先建立問題特定工作流程（PSWF）代理系統，採用先規劃後執行（plan-then-execute）的範式來平衡代理能力與可控性；接著將 PSWF 形式化並切割代理軌跡為工作流程階段，指派高層級結果獎勵（α）、中層級工作流程階段獎勵（β）與低層級工具呼叫獎勵（γ）；最後透過工作流程階段正規化 GRPO 演算法（workflow-stage-normalized GRPO）進行訓練，使模型能同時從最終結果與中間行為中學習。

**Q5：這篇論文最主要的創新點為何？**
A：本論文最主要的創新在於，這是首個將多層級過程獎勵奠基於統一 Lean 形式化架構中，用於開放式領域代理式強化學習的框架。具體而言，作者將既有的 Lean4Agent 驗證系統從固定工作流程擴展到通用執行系統（general harness system），大幅提升了形式化代理驗證系統的適用範圍。此外，PSWF 系統的設計使得即使是開放式任務也能被形式化地驗證，這在過去被認為是形式化方法難以觸及的領域。

**Q6：在設計上有哪些關鍵的選擇與取捨？**
A：作者在設計上做了幾個關鍵選擇：其一，採用先規劃後執行的雙代理架構（規劃代理與執行代理），而非單一代理端到端執行，這是為了讓工作流程能被明確形式化與驗證；其二，選擇 Lean4 作為形式化語言，因為其依賴型別系統（dependent-type system）能自然表達工作流程階段的前置與後置條件；其三，設計三層級獎勵結構而非單一獎勵，是為了兼顧最終結果與中間行為的監督訊號；其四，將 Lean4Agent 從固定工作流程泛化到通用執行系統，使其能與 Claude-code、Terminus-2 等實際執行框架相容。

**Q7：實驗使用了哪些基準測試（benchmarks）？**
A：根據論文內容，實驗評估涵蓋了軟體工程（SWE）相關任務以及終端機使用任務，其中特別強調了 TerminalBench-2.1 這個基準測試。整體而言，作者在三個基準測試上進行了廣泛的實驗比較，涵蓋了 SWE 與通用終端機使用兩個主要任務類型。這些基準測試的選擇反映了當前代理式 LLM 評估的主流方向，能夠全面檢驗模型在長時程、多步驟任務中的表現。

**Q8：最重要的實驗結果為何？**
A：最重要的實驗結果包括：LAR-27B 在 TerminalBench-2.1 上達到了 77.3% 的優異成績；在三個評估基準上，LAR 模型平均比其基礎模型（base model）高出 9.89%，並比同尺寸已知第二佳模型高出 5.07%。這些結果顯示 Lean4AgenticRL 框架在提升代理能力方面具有顯著且穩定的效果，且 LAR-9B/27B 模型家族在與同類規模的領先模型比較時皆能勝出，證明了多層級可驗證獎勵機制在代理式強化學習中的有效性與通用性。

**Q9：論文中是否有消融研究（ablation studies）來驗證各元件的貢獻？**
A：雖然提供的全文片段未完整呈現消融研究的細節，但從方法論的設計來看，作者應當對三層級獎勵（α、β、γ）的個別貢獻進行了消融實驗，因為這是驗證「多層級獎勵相較於單一層級獎勵確實帶來提升」的關鍵證據。此外，工作流程階段正規化 GRPO 演算法相較於標準 GRPO 的改進效果、PSWF 系統中規劃代理與執行代理分離的必要性，以及 Lean4 形式化驗證所帶來的額外價值，都應該是消融研究會探討的面向。

**Q10：這項研究的實際應用場景有哪些？**
A：這項研究的實際應用場景相當廣泛，主要包括：自動化軟體工程任務，如程式碼除錯、重構、測試生成與功能開發；終端機操作任務，如系統管理、檔案處理、腳本執行與環境配置；以及任何需要多步驟推理與工具使用的長時程代理任務。由於框架已與 Claude-code 與 Terminus-2 等主流執行框架整合，LAR-9B/27B 模型可直接部署於這些系統中，提供更可靠的自動化代理能力，對於軟體開發團隊、DevOps 工程師與 AI 輔助工具開發者都具有實質價值。

**Q11：在產品化與實務部署上需要考量哪些因素？**
A：在產品化與實務部署上，需要考量以下因素：首先，Lean4 形式化驗證需要額外的計算資源與時間成本，這對於延遲敏感的應用可能是一個瓶頸；其次，PSWF 系統需要先進行規劃階段，這增加了單次任務的整體延遲；再者，框架與特定執行框架（如 Claude-code、Terminus-2）的耦合度需要評估其對其他執行框架的可移植性；最後，作者已將程式碼與模型開源，這有助於社群驗證、改良並將其整合到現有的 AI 開發工具鏈中，降低了採用門檻。

**Q12：這項研究對學術與產業領域的影響為何？**
A：這項研究對學術界提供了將形式化方法整合進現代強化學習範式的新視角，證明了 Lean 等形式化語言不僅適用於數學證明，也能用於開放式代理任務的驗證。對產業界而言，LAR-9B/27B 模型家族在 SWE 與終端機使用任務上的優異表現，意味著企業可以採用更小但更專精的模型來處理複雜的自動化任務，降低對超大模型的依賴。此外，作者所提出的統一框架為未來研究探索形式化方法在 RL 中的應用奠定了基礎，可能激發更多結合形式驗證與機器學習的跨領域研究。

**Q13：論文是否承認了哪些限制？**
A：從全文內容來看，論文承認的限制包括：現有的 Lean4Agent 系統原本僅支援固定工作流程的驗證，作者需要將其擴展到通用執行系統才能應用於開放式任務，這暗示了泛化過程中可能面臨的工程挑戰。此外，雖然框架在 SWE 與終端機使用任務上表現優異，但對於其他類型的代理任務（如網頁瀏覽、GUI 操作等）的適用性仍待驗證。同時，多層級獎勵機制雖然提升了訓練效果，但也增加了獎勵設計與註解的複雜度，這對於實際部署是一個需要考量的取捨。

**Q14：在什麼情況下這個方法可能會失敗？**
A：這個方法可能在以下情況下表現不佳：當任務的工作流程難以被明確形式化時，例如高度創造性或開放式的任務，PSWF 系統可能無法產生有意義的工作流程結構；當任務需要極快速的單次互動時，規劃階段帶來的額外延遲可能成為瓶頸；當環境中的工具呼叫結果具有高度不確定性或噪音時，低層級工具呼叫獎勵（γ）可能無法準確反映真實的進展；此外，若代理偏離了預先規劃的工作流程，Lean4 形式化驗證可能會拒絕接受原本合理的替代解法，限制了代理的探索能力。

**Q15：未來的研究方向有哪些？**
A：未來的研究方向可能包括：將 Lean4AgenticRL 框架擴展到更多類型的代理任務，如網頁瀏覽、GUI 操作、機器人控制等，驗證其在不同領域的通用性；探索更自動化的 PSWF 生成方法，減少對人工設計工作流程的依賴；研究如何將形式化驗證與大型語言模型的語意理解能力更緊密結合，例如透過神經符號（neuro-symbolic）方法；此外，探討多層級獎勵在其他強化學習演算法（如 PPO、DPO）中的應用，以及如何將此框架應用於多代理協作場景，都是值得深入探索的方向。

## 實務應用指南

### 適用場景

Lean4AgenticRL 框架特別適合以下幾類真實世界的代理式 AI 應用：

**1. 自動化軟體工程（SWE）任務處理**
適用於企業內部需要大量處理 GitHub issue、bug 修復、PR 審查的場景。LAR-27B 在 SWE-bench 類任務上的優異表現顯示，框架能有效處理多檔案修改、依賴追蹤、測試驗證等長時程任務。實際應用包含：自動修復 production bug、批次處理 legacy code 重構、自動化 dependency upgrade。

**2. DevOps 與雲端基礎設施管理**
TerminalBench-2.1 上 77.3% 的成績代表模型能可靠處理終端機操作。可應用於：Kubernetes 故障排查、AWS/GCP 資源配置自動化、CI/CD pipeline 除錯、log 分析與修補。對於需要 24/7 on-call 支援的中小型團隊特別有價值。

**3. 資料工程與 ETL 流程自動化**
適用於需要跨多個系統（資料庫、API、檔案系統）協調的資料處理任務。例如：跨資料庫的資料遷移、批次 ETL 排程、資料品質檢查與修復、報表生成自動化。

**4. 企業內部 IT 自動化助理**
可作為 IT 服務台升級工具，處理帳號權限管理、軟體安裝設定、系統監控回應等需要多步驟終端機操作的任務。

**5. 程式碼審查與安全漏洞修補**
結合多層級獎勵機制，模型不僅能找出問題，還能規劃並執行修補流程，適合 security team 用於批次處理 CVE 修補。

### 實作前置條件

**資料前置條件**
- **任務資料集**：需要準備 SWE 任務（如 SWE-bench、HumanEval-Fix 衍生資料）與終端機任務（如 TerminalBench 系列）的訓練資料，建議至少數萬筆高品質軌跡。
- **Lean4 形式化資料**：需具備 Lean4 證明語言基礎知識，或聘請具備形式化方法背景的工程師撰寫工作流程形式化規格。
- **專家示範軌跡**：用於初始化 PSWF（問題特定工作流程）的探索階段，建議由資深工程師提供或從 SOTA 模型採樣後人工篩選。
- **獎勵標註資料**：需要標註 α（結果）、β（工作流程階段）、γ（工具呼叫）三層獎勵的訓練樣本。

**計算資源前置條件**
- **訓練硬體**：訓練 9B 模型建議至少 32 張 H100/A100 GPU；27B 模型建議 64 張以上 H100，並配置高速 NVLink 或 InfiniBand 互連。
- **推論硬體**：部署 LAR-27B 建議至少 2 張 A100/H100；9B 模型可單張 A100 量化部署。
- **Lean4 驗證環境**：需部署 Lean4 theorem prover 服務（建議使用 Lean4 v4.x 穩定版），並配置 lean4agent 驗證後端。
- **儲存空間**：完整訓練資料 + checkpoint 約需 5–10 TB SSD 儲存。

**技能前置條件**
- **必備**：Python/PyTorch 深度學習經驗、LLM 訓練 pipeline（特別是 GRPO/PPO 系列）、Docker/Kubernetes 部署經驗。
- **強烈建議**：熟悉 Lean4 或其他形式化證明系統（Coq、Isabelle）、具備 agentic RL 實作經驗、理解 SWE 任務特性。
- **加分**：對 ReAct、tool-use prompting 有實務經驗；熟悉 Claude Code、Terminus-2 等 agent harness。

### 實作步驟建議

**階段一：環境準備與小規模驗證（2–4 週）**
1. 從 GitHub repo（https://github.com/RickySkywalker/Lean4AgenticRL）clone 程式碼，安裝依賴並跑通 baseline 推論。
2. 準備小型驗證資料集（約 100–500 筆任務），熟悉 Lean4Agent 驗證介面。
3. 團隊成員需花 1–2 週熟悉 Lean4 語法與 PSWF 設計模式。

**階段二：PSWF 系統建置（4–8 週）**
1. 針對目標領域（如 SWE bug 修復）設計通用工作流程模板。
2. 實作 Planning Agent 與 Execution Agent 的分離架構，採用 plan-then-execute 範式。
3. 建立探索軌跡收集 pipeline，累積足夠的 PSWF 樣本。
4. 進行人工審查，確保 PSWF 兼顧代理能力與可控性。

**階段三：工作流程形式化與獎勵標註（6–10 週）**
1. 將 PSWF 形式化為 Lean4 schema，定義 pre-condition 與 post-condition 預測子。
2. 實作多層級獎勵標註 pipeline：將執行軌跡分段、計算 α/β/γ 三層獎勵。
3. 驗證 Lean4 形式化在目標領域的覆蓋率與正確性。
4. 建立獎勵品質檢查機制，避免 reward hacking。

**階段四：模型訓練（4–12 週）**
1. 從基礎模型（如 Qwen2.5 系列）開始 SFT，建立基本 agentic 能力。
2. 實作 workflow-stage-normalized GRPO 演算法，整合多層級獎勵。
3. 進行多輪 RL 訓練，監控 α/β/γ 獎勵分佈與 KL 散度。
4. 定期在驗證集上評估，特別注意 TerminalBench 與 SWE-bench 表現。

**階段五：部署與持續改進（持續）**
1. 將 LAR-9B/27B 部署到生產環境，搭配 Claude Code 或 Terminus-2 harness。
2. 建立軌跡收集機制，持續蒐集真實使用資料。
3. 定期 retrain 與更新 PSWF 模板，適應新任務類型。
4. 監控獎勵訊號的長期穩定性，避免 reward drift。

### 潛在風險與注意事項

**風險一：Lean4 形式化的複雜度與覆蓋率瓶頸**
- **問題**：Lean4 形式化需要專業知識，且對開放式任務的覆蓋率有限，可能限制框架的可擴展性。
- **緩解**：建立形式化模板庫、訓練專門的 Lean4 標註模型、對無法形式化的任務設計 fallback 機制。

**風險二：獎勵 hacking 與 reward drift**
- **問題**：多層級獎勵可能被代理利用，例如透過完成所有工作流程階段但跳過關鍵步驟來獲取 β 獎勵。
- **緩解**：設計獎勵間的 consistency check、定期人工審查軌跡、引入 adversarial validation。

**風險三：領域轉移性不足**
- **問題**：在 SWE 與終端機任務上訓練的模型，可能無法直接遷移到其他領域（如 GUI 操作、網頁瀏覽）。
- **緩解**：保留 PSWF 設計的可擴展介面、累積跨領域工作流程模板、進行領域適應性 fine-tuning。

**風險四：計算成本過高**
- **問題**：27B 模型訓練需要大量 GPU 時數，Lean4 驗證也會增加推論延遲。
- **緩解**：使用較小的 9B 模型進行快速迭代、對 Lean4 驗證結果做快取、考慮蒸餾到更小模型。

**風險五：軌跡資料的隱私與安全**
- **問題**：SWE 任務常涉及真實程式碼與系統，可能包含敏感資訊。
- **緩解**：建立資料脫敏 pipeline、嚴格的存取控制、符合 SOC2/ISO27001 的資料治理。

**風險六：評估基準的真實代表性**
- **問題**：TerminalBench-2.1 等基準可能無法完全代表真實企業任務。
- **緩解**：建立內部評估集、進行 A/B 測試、收集使用者反饋。

### 與其他技術的整合建議

**與現有 Agent Harness 整合**
- **Claude Code**：作為 Execution Agent 的底層執行環境，LAR 模型負責高層推理與規劃。
- **Terminus-2**：適合終端機密集任務，可作為 PSWF 探索階段的執行後端。
- **建議架構**：LAR 模型 → 規劃 PSWF → 透過 harness 執行 → 收集軌跡 → Lean4 驗證 → 計算多層級獎勵。

**與 RLVR 流程整合**
- Lean4AgenticRL 可作為 RLVR pipeline 的擴充模組，在原有 outcome reward 基礎上加入 process rewards。
- 建議保留原有 RLVR 的 KL 約束與 reference model 機制，避免破壞既有訓練穩定性。

**與 SFT Pipeline 整合**
- 在 SFT 階段加入 PSWF 示範資料，讓模型先學會產生結構化工作流程。
- 使用 rejection sampling 篩選高品質軌跡作為 SFT 資料。

**與監控與可觀測性系統整合**
- 整合 LangSmith、Weights & Biases 等工具，追蹤 α/β/γ 獎勵分佈。
- 建立 Lean4 驗證失敗率儀表板，及早發現形式化規格問題。

**與企業知識庫整合**
- 將 PSWF 模板與企業內部 SOP 對接，建立領域特定工作流程庫。
- 整合 RAG 系統，讓模型在規劃階段能參考企業知識。

**與 CI/CD 整合**
- 將 LAR 模型部署為 CI pipeline 的一部分，自動處理 PR 審查與 bug 修復。
- 設定自動化評估 gate，僅在 Lean4 驗證通過時合併變更。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀論文第 1 節（Introduction）了解問題動機，再跳到第 2.1 節（Preliminaries）熟悉 LLM Agent 與 Lean4Agent 的基本概念。對於強化學習細節（如 GRPO）若不熟悉，可先閱讀相關基礎教材再回來理解 workflow-stage-normalized GRPO。實作上建議從 clone GitHub repo 開始，跑通 baseline 推論流程，再逐步理解各模組。

**給 AI 工程師**：重點關注第 2.2–2.4 節的 PSWF 設計、Lean4 形式化方法與 GRPO 演算法實作細節。建議直接閱讀程式碼，特別是 reward annotation pipeline 與 training loop 的實作。實務上可先在小型任務上重現論文結果，再考慮擴展到自有領域。注意評估 Lean4 形式化對你們任務的適用性，這是採納此框架的關鍵決策點。

**給研究人員**：論文的核心貢獻在於「將 Lean4 形式化擴展到開放式 agentic RL」與「多層級獎勵的統一框架」，這兩個方向都有豐富的後續研究空間。建議仔細閱讀附錄中的形式化規格與獎勵設計細節，並思考如何應用到其他領域（如 GUI agent、multi-agent 協作）。可考慮的延伸方向：更高效的 Lean4 形式化自動生成、跨領域 PSWF 遷移學習、與世界模型結合的長期規劃。

**給產品經理**：重點理解框架的「能力邊界」與「商業價值」。LAR-27B 在 TerminalBench-2.1 達到 77.3%、平均超越同級模型 5.07% 的數據，代表此技術已接近實用門檻。建議評估貴公司 SWE 與 IT 自動化任務的痛點是否與論文場景吻合，特別是「長時程、多步驟、需要驗證」的任務類型。導入時建議從單一高價值場景（如 on-call 自動化）開始 POC，累積資料後再擴展。注意 Lean4 形式化需要專業人才，這是人力成本評估的重要項目。
