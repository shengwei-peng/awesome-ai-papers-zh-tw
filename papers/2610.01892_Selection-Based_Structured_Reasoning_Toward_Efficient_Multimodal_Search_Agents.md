# 選擇式結構化推理：邁向高效的多模態搜尋代理

**原文標題：** Selection-Based Structured Reasoning: Toward Efficient Multimodal Search Agents

**發布日期：** 2026-10-01

## ⚡ TL;DR

小型多模態搜尋代理在動作前產生冗長的自由形式推理，造成大量推論成本卻缺乏有效指引。
本文提出選擇式結構化推理（SSR），將推理改為從預設候選項中選擇，並以共享 KV 快取並行評分。
SSR 在七項基準維持與領先代理相當的成功率，每輪推理延遲降逾九成，每題總延遲降 28-54%。

## 摘要翻譯

多模態代理（Multimodal Agent）通常在每個動作（Action）前產生自由形式推理（Free-form Reasoning）。對於小型模型（Small Model）而言，有限的模型容量（Model Capacity）可能導致冗長的推理，對動作生成提供的有用指引有限，同時造成大量的推論成本。為了解決此挑戰，我們提出了選擇式結構化推理（Selection-based Structured Reasoning, SSR），這是一個將推理重新建構為選擇而非開放式生成（Open-ended Generation）的框架。SSR 將重複出現的高階推理表示為預先指定的、可重複使用的自然語言候選項（Reusable Natural-language Candidate）。在每一輪中，模型根據這些推理候選項在當前上下文下的可能性（Likelihood）進行選擇，無需輔助任務頭（Auxiliary Task Head）。使用預先指定的推理軌跡（Reasoning Trace）得以實現並行評分（Parallel Scoring），其中教師強制預填充（Teacher-forced Prefilling）透過共享上下文 KV 快取（Shared Context KV Cache），同時計算各候選項內部及候選項之間的詞元可能性（Token Likelihood）。我們使用 2B 模型（2B Model）和 4B 模型（4B Model）在七個多模態搜尋基準測試（Benchmark）上評估 SSR。在多種強化學習（Reinforcement Learning）目標及監督式微調（Supervised Fine-Tuning, SFT）下，SSR 在不犧牲任務效能（Task Performance）的情況下實現顯著的效率增益（Efficiency Gain）。SSR 達到了與同規模領先搜尋代理（Search Agent）相當的平均成功率（Success Rate），同時將每輪推理延遲（Per-turn Reasoning Latency）降低超過 90%，並將每題模型總推論延遲（Per-question Model Inference Latency）降低 28–54%。專案頁面（Project Page）：https://zfy0314.github.io/ssr-webpage/。

### 核心貢獻（3～5點）
- 提出選擇式結構化推理（SSR）框架，將推理從開放式生成重新定義為從預先指定、可重複使用的自然語言候選項中進行選擇，有效緩解小型模型因模型容量有限而產生的冗長推理問題。
- 設計無需輔助任務頭的選擇機制，模型直接根據推理候選項在當前上下文下的詞元可能性進行判斷，簡化架構並降低額外參數負擔。
- 透過教師強制預填充與共享上下文 KV 快取實現並行評分，能同時計算候選項內部及跨候選項的詞元可能性，大幅提升推論效率。
- 在七個多模態搜尋基準測試上，以 2B 與 4B 模型進行多種強化學習目標與監督式微調的實驗驗證，證明 SSR 在不犧牲任務效能的前提下，將每輪推理延遲降低超過 90%，每題模型總推論延遲降低 28–54%。
- 達到與同規模領先搜尋代理相當的平均成功率，展現兼顧效能與效率的實用價值。

### 適合對象
本研究特別適合以下讀者閱讀：
- 從事多模態代理、搜尋代理或工具增強型語言模型研究的研究人員與工程師。
- 關注裝置端模型（On-device Model）與小型模型推論效率最佳化的學者與業界開發者。
- 對強化學習、監督式微調及推論加速技術（如 KV 快取、並行解碼）感興趣的機器學習研究者。
- 正在評估如何在資源受限環境中部署高效多模態推理系統的產品技術負責人。

## 深度分析

#### 方法論解析

本文提出之核心方法「選擇式結構化推理」(Selection-based Structured Reasoning, SSR) 從根本上重新定義了多模態代理 (multimodal agent) 中推理步驟的表示方式與計算範式。以下從三個層次進行深入剖析。

**一、表示層次：從生成到選擇的範式轉移**

傳統多模態代理採用「觀察—自由形式推理—動作」(observation–free-form reasoning–action) 的交錯結構，每個動作前皆需以自迴歸方式 (autoregressive decoding) 生成一段自然語言推理軌跡 (reasoning trace)。此設計對小型裝置端模型 (on-device model) 構成雙重負擔：(1) 序列詞元生成 (sequential token generation) 帶來高昂的推論延遲 (inference latency)；(2) 小模型有限的推理能力 (reasoning capacity) 常導致冗長但低引導價值的文字。

SSR 的關鍵觀察在於：多模態搜尋任務中，雖然實體、查詢與觀察隨問題變化，但高階推理模式高度重複。例如「尋找即將舉辦的 AI 會議地點」與「找出 LEGO 創立年份」共享同一推理骨架——「實體已知但所需屬性未知，應搜尋實體名稱與目標屬性」。因此，所需推理空間遠小於完整自然語言空間 (natural language space)，僅需少量候選項即可涵蓋。

具體而言，SSR 將推理預先定義為一組可重複使用的自然語言候選項 (reusable natural-language candidates)，每輪代理根據當前互動歷史 (interaction history) 從中選擇最合適者，再以該選擇結果作為自然語言引導，產生下一個動作及其參數。此設計將「可重複的推理模式」與「實例特定的執行細節」解耦——候選項提供動作的「為什麼」(rationale)，動作生成則提供「如何做」(execution details)。

**二、計算層次：並行推理解碼 (Parallel Reasoning Decoding)**

SSR 最具技術創新性的部分在於其評分機制。傳統分類任務通常需要新增輔助任務頭 (auxiliary task head)，但 SSR 直接將語言模型本身用作候選項分類器，無需任何額外參數或 SFT 暖啟動 (warm start)。

具體計算流程為：
1. 對於每個推理候選項 $c_i$，計算其在當前上下文條件下的長度正規化可能性 (length-normalized likelihood)：
$$s_i = \frac{1}{|c_i|} \sum_{t=1}^{|c_i|} \log P(c_i^{(t)} | \text{context}, c_i^{(<t)})$$
2. 由於所有候選項皆為預先指定，教師強制預填充 (teacher-forced prefilling) 可同時計算候選項內所有詞元的可能性。
3. 不同候選項之間亦可並行評分，並共享同一 KV 快取 (shared context KV cache)，避免重複計算上下文表示。
4. 最終根據分數對候選項進行抽樣，並將選中的推理文字插入上下文，作為下一動作生成的引導。

此機制徹底消除了推理階段的自迴歸依賴，將原本需 $O(|c|)$ 次序列解碼的過程壓縮為單次批次選擇，理論上可達到接近 $O(1)$ 的推理延遲。

**三、訓練層次：與多種訓練範式的相容性**

SSR 並非綁定特定訓練方法，而是作為推理表示的替代方案，可與監督式微調 (SFT) 及多種強化學習 (RL) 目標——GRPO、GSPO、 SAPO——無縫整合。這顯示其效率增益並非來自特定訓練技巧，而是源於表示本身的結構化特性，具有良好的通用性。

#### 實驗數據解讀

**一、基準測試與模型規模**

實驗涵蓋七個多模態搜尋基準測試 (benchmark)，橫跨 2B 與 4B 兩種模型規模，並對比四種訓練目標（SFT、GRPO、GSPO、 SAPO）。此設計形成 2×4 的實驗矩陣，能系統性驗證 SSR 在不同規模與訓練範式下的穩健性。

**二、核心效能數據**

1. **成功率 (Success Rate)**：4B SSR + GRPO 達到 61.37% 平均成功率，與同規模頂尖搜尋代理的 61.25% 持平甚至略勝，證明推理表示的替換並未犧牲任務效能。
2. **每輪推理延遲 (Per-turn Reasoning Latency)**：降幅超過 90%，這是因為推理階段從自迴歸生成轉為單次並行評分，消除了序列解碼瓶頸。
3. **每題模型推論延遲 (Per-question Model Inference Latency)**：總體降幅 28–54%。值得注意的是，總延遲降幅小於每輪降幅，因為動作生成階段仍需自迴歸解碼，且整體延遲還包含工具呼叫、檢索等非模型開銷。

**三、圖表解讀**

圖 1(b) 呈現「平均成功率 vs. 平均每輪思考延遲」的散點圖，橫跨四種訓練方法與兩種模型規模。SSR 資料點（藍色）相較自由形式推理（橘色）皆位於左側（低延遲）且縱向位置相當或更高，直觀展示「向左移動」（效率提升）而不「向下移動」（效能下降）的理想結果。配對變化（paired change）連線進一步凸顯每種訓練設定下 SSR 相對基線的改善幅度。

**四、與高效推理基線的比較**

論文聲稱 SSR 在與四個代表性高效推理基線的比較中，於成功率、模型推論時間與延遲穩定性三個維度皆表現更佳。這暗示 SSR 並非僅是「更快的推理」，而是同時維持了輸出品質的一致性——這對實際部署至關重要，因為僅追求速度而犧牲穩定性的方法在生產環境中價值有限。

**五、實驗設計的潛在侷限**

- 雖然涵蓋七個基準，但未說明基準的具體組成（搜尋類型、視覺需求比例、難度分布），讀者難以判斷結果的泛化邊界。
- 延遲測量環境（硬體、批次大小、KV 快取配置）未在擷取段落中詳述，可能影響絕對數值的可比性。
- 候選項數量與品質對效能的敏感度分析未在擷取內容中呈現，這是評估 SSR 實用性的關鍵參數。

#### 與現有研究的比較

**一、與多模態搜尋代理研究的關係**

本文將自身定位為與 MMSearch-R1、DeepMMSearch-R1、Visual-ARFT、DeepEyes、DeepEyesV2、SenseNova-MARS、TAPO、WebWatcher、VSearcher、ProMMSearchAgent 等工作的「正交方向」(orthogonal direction)。後者聚焦於訓練資料混合、梯度路由 (gradient routing)、信用分配 (credit assignment) 等訓練層面的改進，而 SSR 則從推論表示層面切入。兩者互補意味著未來可將 SSR 與上述訓練改進疊加，潛在獲得雙重增益。

**二、與高效推理研究的關係**

傳統高效推理方法（Han et al., 2025; Ma et al., 2025; Sui et al., 2025）透過詞元預算、早停、壓縮思維鏈或自適應測試時計算控制模型「思考長度」，但仍保留自迴歸解碼的序列依賴。SSR 採取更激進路線：直接改變推理的表示形式，從根本上消除序列生成需求。

與最相關的 HyperEyes (Li et al., 2026) 相比，HyperEyes 將推論效率視為一階訓練目標，透過並行派發多個基礎查詢並獎勵避免冗餘工具呼叫來減少互動輪數；而 SSR 則在不改變訓練目標的前提下，於單輪內部降低推理成本。兩者分別從「輪數」與「每輪延遲」兩個維度優化，理論上可正交組合。

**三、與思維模板 (Thought Template) 研究的關係**

Yang et al. (2024) 與 Ouyang et al. (2026) 的思維模板工作同樣觀察到推理模式的可重複性，但 SSR 將此觀察從「提示工程」或「軌跡重用」推進至「結構化表示 + 並行計算」，實現了真正的計算加速，而非僅是文字層面的精簡。

**四、方法論侷限**

1. **候選項設計的依賴性**：SSR 的效能高度依賴預定義候選項的完整性与代表性。若候選項未涵蓋某場景所需推理模式，模型將無法正確引導動作生成。論文中未充分討論候選項的構建流程與品質控制。
2. **領域遷移性**：論文的觀察（「高階推理模式高度重複」）基於多模態搜尋任務。在需要長鏈推理、開放探索或創造性思考的任務中，推理空間可能遠大於候選項所能覆蓋的範圍，SSR 的適用性存疑。
3. **可能性評分的偏差**：長度正規化可能性作為選擇依據隱含假設「較高可能性 = 較合適推理」，但語言模型的校準 (calibration) 未必完美，可能導致選擇偏差。
4. **動作生成成本未消除**：雖然推理階段延遲降低 90%，但動作生成仍需自迴歸解碼，這限制了總體加速比的理論上限。

**三、可重現性的潛在障礙**

1. **候選項清單的公開性**：SSR 的核心元件是預定義推理候選項集合。若此集合未完整公開或僅以截錄形式呈現，將嚴重阻礙獨立重現。
2. **KV 快取並行實作細節**：並行評分涉及具體的批次處理、記憶體管理與注意力遮罩設計，這些工程細節對重現至關重要。
3. **評估環境的一致性**：搜尋代理的評估涉及即時網路互動，不同時間點的搜尋結果可能不同，影響可重現性。論文中是否採用靜態沙盒 (static sandbox)（如 ProMMSearchAgent 所用）值得關注。
4. **2B 與 4B 模型的基線**：具體使用的骨幹模型（base model）名稱未在擷取段落中說明，這對重現實驗至關重要。

**四、整體評估**

#### 未來研究方向

**一、候選項學習與動態擴展**

當前 SSR 依賴人工預定義的候選項集合。未來可探索：
- **自動化候選項挖掘**：從大規模搜尋軌跡中自動聚類、提煉高頻推理模式，減少人工設計成本。
- **層次化候選項**：將候選項組織為多層次結構（高階策略 → 子策略 → 動作模板），支援更細粒度的選擇。
- **動態候選項池**：根據任務類型或領域自適應擴展候選項，提升跨領域泛化能力。

**二、與其他效率技術的組合**

SSR 與現有多種效率方向正交，組合潛力巨大：
- **與 HyperEyes 結合**：前者降低每輪延遲，後者減少互動輪數，理論上可獲得乘性加速。
- **與詞元預算控制結合**：在動作生成階段引入動態詞元預算，進一步壓縮非推理開銷。
- **與模型量化、投機解碼 (speculative decoding) 結合**：在硬體層面進一步降低推論成本。

**三、從搜尋代理到通用代理的擴展**

論文的觀察（「高階推理模式高度重複」）是否適用於其他代理任務值得系統研究：
- **程式設計代理**：除錯、重構、測試等高階策略是否同樣高度模板化？
- **對話代理**：意圖識別、回應策略的選擇是否可結構化？
- **機器人代理**：操作序列的高階規劃是否適合候選項表示？

**四、理論分析**

SSR 提出了若干值得深入分析的理論問題：
- **表示能力邊界**：候選項集合的最小完備條件為何？是否存在資訊理論下界？
- **可能性評分的理論保證**：長度正規化可能性作為選擇依據的統計性質與泛化界。
- **與自迴歸生成的等價性條件**：在何種條件下，選擇式推理能完全等價或優於自由形式生成？

**五、評估協議的標準化**

當前多模態搜尋代理的評估缺乏統一標準，不同工作使用不同基準與指標。建議社群：
- 建立標準化評估套件，統一成功率、延遲、成本的測量協議。
- 引入「效率—效能帕雷托曲線」(Pareto frontier) 作為標準比較維度。
- 開發靜態沙盒基準，消除即時網路互動帶來的可重現性問題。

**六、安全與可解釋性**

SSR 的結構化表示帶來額外的可解釋性優勢：選中的推理候選項本身即為人類可讀的決策依據。未來可探索：
- 將候選項選擇過程視為決策審計線索，用於錯誤分析與除錯。
- 結合人類反饋，動態調整候選項的優先級或新增候選項。
- 在安全敏感場景中，以候選項白名單限制代理的推理空間，防止越權行為。

**七、硬體協同設計**

並行評分對硬體（特別是裝置端 NPU）有特殊親和性。未來可探索：
- 專用硬體加速器設計，最佳化批次可能性計算。
- 候選項預編碼 (pre-encoding) 與 KV 快取預計算，進一步降低首次推論延遲。
- 與裝置端模型（如手機 SoC 上的小型 LLM）的深度整合，實現真正的即時多模態代理。

## 論文問答

**Q1：這篇論文試圖解決的核心問題是什麼？**
A：論文聚焦於小型多模態代理在多輪搜尋任務中「推理成本過高但效益有限」的問題。傳統多模態代理在每個動作前都會以自由形式生成推理文字，但對於 2B、4B 等裝置端小型模型而言，受限的模型容量往往導致冗長、重複的推理文字，不僅推論延遲高，也無法有效引導後續動作生成。論文的目標是在不犧牲任務效能的前提下，大幅降低每輪推理與整體推論的延遲。

**Q2：現有的效率化推理方法為何不足以解決這個問題？**
A：現有方法（例如提示簡潔軌跡或獎勵較短推理）雖然減少了生成文字量，但本質上仍維持自迴歸解碼中詞元之間的序列依賴，因此無法根本消除「逐詞元生成」的瓶頸。此外，這些方法並未改變推理本身的表示方式，仍是開放式生成，因此對於小型模型而言，推理品質與成本之間的取捨依然受限。論文因此主張應從「改變推理表示」這個正交方向切入，而非只在生成長度上做文章。

**Q3：為什麼這個問題在多模態搜尋領域特別重要？**
A：多模態搜尋任務需要多輪互動，每一輪都包含觀察、推理與動作，這使得推理成本會隨著輪數線性放大，對裝置端小型模型尤其致命。論文中觀察到，雖然實體、查詢與觀察隨題目而異，但「採取下一個動作的高階推理」常常重複出現，這意味著搜尋代理所需的推理空間遠小於整個自然語言空間。這個觀察為「以選擇取代生成」提供了關鍵動機，也凸顯了該問題在效率與可部署性上的重要性。

**Q4：選擇式結構化推理（SSR）的核心機制是什麼？**
A：SSR 將推理重新表述為「從預先指定、可重複使用的自然語言候選項中進行選擇」，而非開放式生成。在每一輪中，模型根據當前互動歷史，從一組推理候選項中挑選最合適的一項，再以該推理作為引導產生下一個動作及其參數。這種設計將「可重複使用的推理模式」與「實例特定的執行細節」分離開來，使代理無需在任何階段生成自由形式的推理軌跡。

**Q5：什麼是「並行推理解碼」，為何這是關鍵創新？**
A：並行推理解碼利用語言模型本身作為候選項分類器，依據長度正規化後的詞元可能性對每個推理候選項評分，而無需新增任何輔助任務頭。由於所有候選項的詞元都是預先指定的，教師強制預填充可以同時計算候選項內部與候選項之間的詞元可能性，並透過共享上下文 KV 快取進一步加速。這徹底消除了推理軌跡的自迴歸生成，使每輪推理延遲降低超過 90%。

**Q6：SSR 在設計上有哪些關鍵選擇值得注意？**
A：首先，SSR 不引入輔助分類頭，而是直接以語言模型的詞元可能性作為評分依據，這避免了額外參數與 SFT 暖啟動的需求。其次，採用長度正規化可能性來處理候選項長度不一致的問題，使評分更具可比性。最後，候選項以自然語言形式呈現並插入上下文中作為動作生成的引導，這保留了可解釋性，也讓人類可以檢視代理所選用的推理。

**Q7：論文中使用了哪些基準測試來評估 SSR？**
A：論文在七個多模態搜尋基準測試上評估 SSR，涵蓋了不同難度與場景的搜尋任務。實驗橫跨 2B 與 4B 兩種模型規模，並結合 GRPO、GSPO、SAPO 等強化學習目標以及監督式微調（SFT）進行訓練。這樣的設計能驗證 SSR 在不同訓練方法與模型容量下的通用性，而非僅在單一設定下表現良好。

**Q8：SSR 在效率與效能上的關鍵結果為何？**
A：4B SSR 搭配 GRPO 訓練時，平均成功率達到 61.37%，與同規模的領先搜尋代理（61.25%）相當，但每輪平均推理延遲降低超過 90%，每題整體模型推論延遲降低 28–54%。在 GRPO、GSPO、SAPO 與 SFT 四種訓練目標下，SSR 代理皆維持與自由形式推理對手相當的任務效能，同時顯著降低推論時間。相較於四個具代表性的效率化推理基線，SSR 在成功率、推論時間與延遲穩定性上皆更為優異。

**Q9：論文中進行了哪些消融實驗或對比來驗證設計選擇？**
A：論文將 SSR 與多個效率化推理基線進行比較，結果顯示 SSR 在成功率更高、推論時間更低、延遲更一致三個面向皆佔優。此外，論文中以圖示呈現了自由形式推理與 SSR 在解碼方式上的差異，並透過多訓練目標與多模型規模的交叉實驗，驗證了「以選擇取代生成」這項設計在不同情境下的穩健性。這些對比共同支持了「改變推理表示」相較於「縮短推理文字」的正交價值。

**Q10：SSR 適合哪些實際應用場景？**
A：SSR 特別適合需要即時反應的裝置端多模態搜尋應用，例如行動裝置上的視覺問答、擴增實境中的資訊查詢、或邊緣裝置上的智慧助理。在這些場景中，每輪推理延遲的降低直接影響使用者體驗，而 28–54% 的整體推論時間節省則能延長電池壽命並降低運算成本。此外，由於推理候選項為預先指定的自然語言，部署時也較容易進行稽核與除錯。

**Q11：從產品化的角度，SSR 帶來哪些設計上的考量？**
A：產品化時需要事先定義一組高品質、可重複使用的推理候選項，這需要領域專家參與設計並隨任務演進持續維護。同時，候選項集合的大小會影響選擇的精細度與評分成本，需在覆蓋率與效率之間取得平衡。此外，由於推理以自然語言形式插入上下文，產品可以選擇是否將其暴露給終端使用者，作為可解釋性的一環。

**Q12：這項研究對多模態代理領域的整體影響是什麼？**
A：SSR 提出了「推理即選擇」這個新範式，挑戰了「推理必須是開放式生成」的傳統假設，並展示了透過改變表示方式即可同時兼顧效能與效率。這也鼓勵後續研究探索其他任務領域中是否存在類似的「高階推理重複性」，進而設計專屬的選擇式推理框架。整體而言，SSR 為裝置端小型多模態代理的實用化鋪平了道路。

**Q13：論文中承認了哪些限制？**
A：論文的設定聚焦於多模態搜尋任務，雖然該領域的高階推理重複性已被觀察到，但其他類型的代理任務（例如開放式對話、複雜規劃）所需的推理空間可能更大，SSR 的適用性尚待驗證。此外，候選項集合的設計目前仰賴人為預先指定，若任務演進或領域轉移，可能需要重新設計。最後，論文中也指出推理候選項的品質會直接影響選擇結果，這對維護成本與泛化能力構成挑戰。

**Q14：SSR 可能出現哪些失敗情境？**
A：當面臨訓練或候選項設計未涵蓋的新情境時，模型可能無法從既有候選項中找到合適的推理，導致選擇錯誤並引發後續動作偏差。此外，若候選項之間的長度差異過大，即使經過長度正規化，仍可能產生評分偏差。在多輪互動中，早期的錯誤選擇也可能被後續步驟放大，形成連鎖失敗。

**Q15：基於這項工作，未來有哪些值得探索的方向？**
A：未來可研究如何自動從資料中挖掘或擴充推理候選項集合，以降低人為設計成本並提升泛化能力。另一個方向是將 SSR 推廣到搜尋以外的代理任務，檢驗「選擇式推理」在其他領域的適用性與極限。此外，結合動態候選項生成、階層式推理選擇、或與測試階段預算控制機制整合，都是值得探索的延伸方向。

## 實務應用指南

### 適用場景

1. **裝置端多模態助理（On-device Multimodal Assistant）**：在手機、平板或智慧音箱等資源受限裝置上部署多模態搜尋代理時，SSR 可將每輪推理延遲降低超過 90%，使視覺+文字混合查詢（如「拍攝這張植物照片並查詢其學名與照顧方式」）能在數百毫秒內完成單輪決策，適合即時互動體驗。

2. **電商視覺搜尋與商品比價**：在購物 App 中，使用者上傳商品圖片並詢問「找類似款式且最便宜的鏈條項鍊」。SSR 將「搜尋相似圖片」、「查詢價格」、「比較規格」等高頻推理模式預編為候選項，避免小型模型在每輪重複生成冗長推理，特別適合每秒需處理數百次請求的批次化服務。

3. **企業內部知識庫多模態問答**：在需要結合文件圖表、截圖與文字查詢的企業助理（如 IT 故障排除、財報分析）中，SSR 可將「讀取圖表數據」、「交叉比對多份文件」、「定位特定欄位」等推理模式預先結構化，使 2B–4B 等小型模型在單一 GPU 上即可服務，無需依賴大型雲端模型。

4. **教育與無障礙輔助工具**：為視障或學習障礙使用者打造的「拍照問答」工具，使用者拍攝課本、菜單或路標後詢問細節。SSR 透過預定義推理候選項（如「OCR 後翻譯」、「查詢背景知識」、「朗讀重點」）降低延遲，讓邊緣裝置能在 1 秒內回應，提升可用性。

5. **機器人與無人機的視覺導航決策模組**：在倉儲機器人或巡檢無人機中，多模態代理需根據攝影機畫面與感測器觀察決定下一步動作。SSR 可將「障礙物辨識後規劃路徑」、「標的物定位後靠近」、「異常偵測後回報」等推理模式候選化，使裝置端推理在低功耗晶片上即時完成。

### 實作前置條件

**資料需求**
- **推理候選項語料**：需蒐集或人工撰寫數十至數百條「高層次推理候選項」，涵蓋目標任務的所有典型決策模式（例如：「實體已知但屬性未知 → 搜尋實體名稱與目標屬性」、「圖片資訊不足 → 裁切或放大局部區域」）。可從既有 SFT 軌跡中聚類萃取，或參考 Thought Template 相關文獻。
- **多模態搜尋軌跡資料**：用於監督式微調（SFT）與強化學習（RL）訓練的完整多輪互動紀錄，包含圖片、文字查詢、工具呼叫與最終答案。建議至少數萬條高品質軌跡。
- **基準測試集**：用於評估的 7 類多模態搜尋基準（如 MMSearch、InfoSeek 等），需事先準備好圖像與標註。

**運算資源**
- **訓練階段**：4B 模型搭配 GRPO/GSPO/SAPO 等 RL 目標時，建議至少 4×A100（80GB）或同等級 H100 GPU；SFT 階段可降至 2×A100。
- **推論階段**：2B 模型可在單張消費級 GPU（如 RTX 4090）或高階行動 SoC 上運行；4B 模型建議至少 24GB 顯存。
- **KV Cache 共享機制**：需支援 vLLM、SGLang 或自實作的 prefix sharing 推論引擎，以實現候選項並行評分。

**技能門檻**
- 熟悉多模態大型語言模型（MLLM）的架構（如 Qwen-VL、LLaVA 系列）與其推論管線。
- 具備強化學習實作經驗（GRPO/GSPO/SAPO 演算法、reward shaping、KL 約束）。
- 理解 teacher forcing、prefix caching 與長度標準化可能性（length-normalized likelihood）的數學原理。
- 能撰寫工具呼叫（tool-use）harness，負責將選定的推理候選項插入上下文並產生下一個動作。

### 實作步驟建議

**階段一：推理候選項設計與驗證（2–4 週）**
1. 從現有 SFT 軌跡中抽取 500–2000 條高頻推理模式，由領域專家與 LLM 協同改寫為簡潔、可重用的自然語言候選項（每條 20–80 個 token）。
2. 將候選項分層組織（例如：資訊蒐集層、圖像操作層、答案確認層），並為每條候選項標註適用的場景與典型後續動作。
3. 在小型驗證集上以 zero-shot 方式測試候選項覆蓋率，確保能處理至少 90% 的常見決策情境。

**階段二：監督式微調（SFT）暖啟動（1–2 週）**
4. 將候選項清單嵌入系統提示（system prompt），並改寫 SFT 資料：將原本的自由形式推理替換為「選擇第 N 號候選項」的標籤。
5. 使用標準 cross-entropy 損失訓練 2B 或 4B 模型，使其學會根據互動歷史選取最合適的候選項。
6. 驗證模型在驗證集上的候選項選擇準確率（top-1 與 top-3），目標 ≥ 85%。

**階段三：強化學習最佳化（2–4 週）**
7. 設計 reward function：結合任務成功率（最終答案正確性）、每輪推理延遲懲罰項，以及候選項多樣性正則項。
8. 採用 GRPO、GSPO 或 SAPO 任一目標進行 RL 訓練；注意 SSR 的動作空間為離散的候選項索引加上連續的動作參數，需相應調整策略網路輸出層。
9. 監控 KL 散度避免策略偏移過大，並定期在基準測試上評估成功率與延遲。

**階段四：推論管線工程化（2–3 週）**
10. 實作「並行推理解碼」服務：使用 vLLM 或 SGLang 的 prefix sharing 功能，將所有候選項的 token 在同一 batch 中以 teacher forcing 方式評分。
11. 整合候選項評分 → 機率取樣 → 插入上下文 → 動作生成的完整流程，確保 KV cache 在候選項評分階段可被後續動作生成階段重用。
12. 加入長度標準化（除以 token 數）以避免模型偏好較短的候選項，並實作 temperature/top-k 取樣控制多樣性。

**階段五：部署與監控（持續）**
13. 將模型與推論服務容器化，部署至邊緣裝置或內部 GPU 叢集；設定 autoscaling 規則。
14. 建立監控儀表板，追蹤成功率、平均延遲、候選項分佈、KV cache 命中率等指標。
15. 蒐集線上失敗案例，定期回饋至候選項清單與訓練資料，形成閉環迭代。

### 潛在風險與注意事項

**風險 1：候選項覆蓋不足導致長尾任務失敗**
- *現象*：當遇到訓練資料未涵蓋的推理模式時，模型被迫從不相關的候選項中選擇，造成錯誤動作。
- *緩解*：保留「自由形式推理」作為 fallback 機制；當所有候選項的可能性都低於閾值時，自動切換至標準自迴歸推理；定期以失敗案例擴充候選項清單。

**風險 2：長度標準化偏差**
- *現象*：長度標準化（length normalization）會使模型傾向選擇較短的候選項，即使較長的候選項語意上更合適。
- *緩解*：嘗試不同的標準化方式（如幾何平均、perplexity-based）；或在 reward 中加入候選項長度懲罰項以平衡。

**風險 3：KV Cache 共享的硬體限制**
- *現象*：當候選項數量過多（如 >100 條）或單條候選項過長時，prefix sharing 帶來的加速效益會被候選項評分的總計算量抵消。
- *緩解*：將候選項分組（例如依任務階段），每輪只在相關子集中評分；或使用投影片式（sliding window）候選項管理。

**風險 4：強化學習訓練不穩定**
- *現象*：候選項選擇的離散動作空間可能導致策略梯度估計方差過大，訓練出現 reward collapse。
- *緩解*：採用 GSPO 或 SAPO 等方差較低的 RL 目標；加入 entropy bonus 鼓勵探索；使用較小的學習率與嚴格的 KL 約束。

**風險 5：多模態觀察的編碼成本未降低**
- *現象*：SSR 僅降低推理階段的延遲，視覺編碼（ViT forward pass）仍佔據大量時間，整體加速效果不如預期。
- *緩解*：搭配視覺 token 壓縮、影像快取或動態解析度策略；將 SSR 與高效視覺編碼器（如 SigLIP）結合。

**風險 6：可解釋性與除錯困難**
- *現象*：相較於自由形式推理，候選項選擇的決策過程較不透明，除錯時難以理解模型為何選錯。
- *緩解*：記錄每輪的候選項機率分佈與 top-k 選項；建立視覺化工具展示「上下文 → 候選項機率 → 動作」的對應關係。

---

### 與其他技術的整合建議

1. **與視覺 token 壓縮技術整合**：將 SSR 與 FastV、Token Merging（ToMe）或動態解析度調整結合，可在視覺編碼階段就降低計算量，與 SSR 的推理階段加速形成「雙重壓縮」效果。

2. **與工具呼叫框架整合**：SSR 的輸出（選定候選項 + 動作參數）可直接接入 LangChain、AutoGen 或自有的 tool-use harness；候選項本身可作為「高層次計畫」的抽象層，使工具呼叫更具結構化。

3. **與 RAG 系統整合**：在多輪搜尋代理中，SSR 可與傳統 RAG 結合——候選項決定「何時觸發檢索」與「檢索什麼類型的資訊」，而 RAG 負責實際的文件召回與重排序，兩者分工明確。

4. **與模型蒸餾技術整合**：可將大型教師模型（如 70B）的推理軌跡先聚類為候選項，再用 SSR 框架訓練小型學生模型（2B/4B），使蒸餾過程更具結構化且效率更高。

5. **與邊緣推論框架整合**：搭配 llama.cpp、MLX 或 ONNX Runtime 等裝置端推論引擎時，SSR 的並行評分特性可充分利用 SIMD 指令與批次化推論，進一步降低單次請求的能耗。

6. **與可觀測性平台整合**：將候選項選擇日誌接入 LangSmith、Phoenix 或自建的 observability 平台，便於追蹤代理行為模式、偵測漂移並進行 A/B 測試。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的圖 1，直觀理解「自由形式推理」與「選擇式推理」的差異；接著跳過數學細節，專注於「為什麼小型模型會浪費推理成本」這個核心問題。實作上可從小規模候選項（10–20 條）開始，在簡單的視覺問答任務上重現論文的加速效果，再逐步擴展。

**給 AI 工程師**：重點關注第 1.2 節的「並行推理解碼」機制與第 2 節的相關工作比較，理解 SSR 如何在不增加輔助任務頭的前提下，利用 teacher forcing 與 KV cache 共享實現加速。實作時建議直接使用 vLLM 的 prefix caching 功能，並仔細調校長度標準化方式與候選項取樣溫度。

**給研究者**：本文的核心 insight 在於「推理空間遠小於自然語言空間」，這與 Thought Template、Program-of-Thought 等結構化推理路線形成對照。建議深入分析候選項數量與任務效能的 scaling law，並探索 SSR 在非搜尋類多輪代理（如程式碼生成、機器人控制）中的適用性；亦可研究如何自動從大型模型的軌跡中萃取候選項。

**給產品經理**：SSR 的商業價值在於「用更小的模型達成同等效能」，可顯著降低雲端 API 成本或使邊緣部署成為可能。建議評估自家產品的搜尋/問答流程是否能拆解為 10–50 個高頻推理模式；若可，SSR 即可帶來 28–54% 的推論成本節省，同時維持使用者體驗。需注意候選項維護需要領域專家持續投入，應納入產品迭代流程。
