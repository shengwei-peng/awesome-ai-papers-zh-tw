本文提出的核心方法稱為**搜尋原生預訓練（Search-Native Pretraining）**，其核心思想是在預訓練階段而非僅在後訓練階段教導語言模型使用搜尋工具。這個方法論的設計動機源於一個關鍵觀察：現代語言模型在推論時越來越多地配備搜尋工具，但預訓練仍主要聚焦於靜態文本的下一詞元預測（next-token prediction），搜尋能力通常在後訓練階段才被引入。

**資料增強管線（Data Augmentation Pipeline）**

方法的第一步是從普通預訓練語料庫中建構搜尋增強預訓練語料庫。具體流程如下：

1. **插入點識別（Insertion Point Identification）**：對於每個文件，識別一組搜尋查詢插入點 $A = \{a_1, ..., a_k\}$，每個插入點 $a_i$ 分隔一個前綴 $p_i$，該前綴設定了激勵搜尋的上下文。

2. **查詢生成（Query Generation）**：基於前綴上下文生成搜尋查詢 $q_i$，這些查詢模擬人類在面對特定資訊需求時會發出的搜尋行為。

3. **證據擷取（Evidence Retrieval）**：使用本地索引（local index）對網路進行搜尋，獲取對應的網路回應 $r_i$。

4. **文件重組（Document Reconstruction）**：將原始文件與內嵌的搜尋查詢和擷取證據組合成最終的增強文件，保留原始的下一詞元預測目標。

從圖3的範例可以看出，原本描述 Racetrack Playa 滑石的文本被增強為包含三個搜尋查詢（`q₀: RacetrackPlaya`、`q₁: RacetrackPlaya stone trail`、`q₂: RacetrackPlaya stone propelled by`）和對應擷取證據的版本。這種設計讓模型學會三個關鍵能力：**何時搜尋（when to search）**、**搜尋什麼（what to search for）**、以及**如何使用擷取證據（how to use retrieved evidence）**。

**訓練目標設計**

值得注意的是，該方法保留了原始的下一詞元預測目標，而非引入額外的監督式損失。這意味著搜尋行為的學習是從增強資料中自然湧現的——模型必須學會生成搜尋呼叫並整合擷取證據，才能更好地預測原始文件的接續。這種設計避免了對搜尋行為進行顯式標註的需求，使方法能夠擴展到普通預訓練語料庫。

**QueryLM 架構**

QueryLM 從頭訓練，參數規模涵蓋 360M 到 3.3B。雖然具體架構細節在提供的文本中未完全展開，但從方法論描述可以推斷，模型需要能夠：

- 將擷取證據整合到後續的語言建模中
- 在推論時可選擇性地使用搜尋功能

**關鍵效能結果**

1. **知識密集型任務的改進**：QueryLM 在知識密集型任務上相較於 FLOP 匹配的基準模型有顯著提升。具體而言，1.4B 的 QueryLM 在所有知識密集型任務上持續優於或匹配 3.3B 的基準模型，這意味著搜尋預訓練帶來了約 2.4 倍的參數效率提升。

2. **極端的計算效率**：400M 的 QueryLM（配備搜尋）在平均問答效能上超越了 SmolLM3-3B（無搜尋評估），儘管預訓練算力少了約 6,700 倍。這是一個極具說服力的結果，展示了搜尋能力如何從根本上改變小型模型的知識獲取效率。

3. **後訓練後的持續優勢**：這是本文最重要的發現之一。即使在監督式微調（SFT）之後，搜尋預訓練模型的優勢仍然存在。這表明：

   - 預訓練階段的早期接觸（early exposure）對能力培養具有不可替代的價值

4. **可引導性（Steerability）提升**：QueryLM 不僅能正確回答更多問題，還更容易根據提供的證據調整其預測，包括與訓練期間所見事實相矛盾的證據。這對於處理過時資訊和需要即時更新的場景尤為重要。

#### 與現有研究的比較

**與後訓練搜尋方法的比較**

傳統方法（如 Lazaridou et al., 2022; Nakano et al., 2022; Schick et al., 2023; Yao et al., 2023）都是在後訓練階段引入搜尋能力。QueryLM 的根本差異在於將搜尋能力視為預訓練的核心組成部分，而非後續添加的功能。這種「從一開始就搜尋」的範式轉換帶來了兩個關鍵優勢：
- 能力發展更為根本，無法被後訓練完全複製
- 小型模型也能獲得強大的知識獲取能力

**與 Toolformer 的比較**

Toolformer（Schick et al., 2023）與本文方法最為相關，因為它也採用內嵌式工具呼叫示範。然而，Toolformer 是透過微調而非預訓練來注入工具呼叫能力，且其規模和資料需求限制了實際應用。QueryLM 將這一思想擴展到預訓練階段，並展示了在大規模語料庫上的可行性。

**與聯合訓練擷取器方法的比較**

REALM（Guu et al., 2020）和 Retro（Borgeaud et al., 2022）等方法採用聯合訓練的擷取器或專門的注意力層來處理擷取資訊。QueryLM 不需要架構修改，使其更容易整合到現有的預訓練流程中。

**與基於實體鍵值儲存方法的比較**

LMLM（Zhao et al., 2025）和 Co-LMLM（Feldman et al., 2026）建構顯式的基於實體的鍵值儲存，並訓練語言模型查詢這些儲存。QueryLM 的優勢在於：
- 學習發出靈活的搜尋查詢，而非僅限於實體查詢
- 不需要預先建構的實體索引
- 可以擷取任何網路上的資訊，而非僅限於預定義的儲存

**與預訓練資料增強研究的比較**

本文與近期探索在預訓練早期引入能力相關資料的研究（Akter et al., 2025b; Zhou et al., 2026; Cheng et al., 2024; Maini et al., 2025; Gao et al., 2025; Akter et al., 2025a; Ruan et al., 2025; Huang et al., 2026b）一致，發現早期接觸能力相關資料能帶來持久益處。QueryLM 將這一原則應用於搜尋能力，並展示了其可擴展性。

## 實務應用指南

### 適用場景

1. **企業內部知識庫問答系統**：當公司政策、產品規格、客戶合約等事實經常變動時，搜尋原生預訓練模型能在不重新訓練的情況下擷取最新內部文件，特別適合 IT 支援、HR 政策查詢、銷售輔助等場景。

2. **新聞媒體與事實查核工具**：記者與編輯在撰稿時需要即時驗證人物、事件、數字，模型可主動發出搜尋查詢並引用擷取來源，降低幻覺並提供可追溯依據。

3. **學術研究助理**：研究生與分析師需要查證最新論文、統計資料、跨領域術語，搜尋原生模型可在生成過程中即時擷取 arXiv、PubMed 等開放資料庫的內容。

4. **法律與合規諮詢助手**：法條、判例、監管規範隨時更新，模型可擷取官方公告與判決書，並在回答中標註證據來源，協助律師助理進行初步研究。

5. **教育領域個人化學習助理**：K-12 與大學生問答場景中，模型可依據學生提問擷取教材、維基百科、可汗學院等資源，並依據擷取證據調整解釋深度。

### 實作前置條件

**資料需求**
- 一個可離線查詢的本地索引（建議使用 ColBERTv2、BM25 或 Pyserini 等開源檢索系統），索引規模需對應目標領域的網頁或文件量。

- 訓練 3.3B 模型：建議 64–128 張 H100，並準備分散式訓練框架（DeepSpeed、FSDP）。
- 推論階段需部署檢索服務（向量資料庫 + 倒排索引），並預期每次查詢增加 100–500ms 延遲。

**技能需求**
- 熟悉預訓練管線（Megatron-LM、LitGPT、torchtune 等）與檢索增強生成（RAG）系統。
- 具備評估知識密集任務（NaturalQuestions、TriviaQA、PopQA）的能力。
- 了解工具呼叫格式設計與詞元預算控制。

### 實作步驟建議

1. **界定領域與擷取範圍**：先選定目標領域（內部知識庫、特定產業或開放網路），並決定擷取來源是否需限定白名單，以控制證據品質。

2. **建立本地索引**：將目標網頁或文件以 ColBERTv2 或 SPLADE 編入本地索引，確保回應時間 < 200ms，並建立更新機制（每日/每週重新爬取）。

3. **準備搜尋增強語料**：參考論文 Figure 3 的標註範例，在原始文件上識別查詢插入點（建議每 50–150 個詞元插入一次），並用啟發式或小型 LM 產生查詢，再以本地索引擷取對應回應。

4. **執行搜尋原生預訓練**：採用論文釋出的訓練配方，從頭訓練 360M–1.4B 模型；如算力受限，可從已釋出的檢查點繼續訓練或微調。

5. **後訓練微調**：在監督式微調階段加入搜尋增強的指令資料（包含「何時該搜尋」、「如何解讀證據」），並評估模型在有/無搜尋兩種模式下的表現。

6. **評估與消融**：依論文 Section 5 的指標（知識密集任務、可引導性、一般能力）建立評估管線，並針對擷取品質、回應長度、插入頻率進行消融實驗。

7. **部署與監控**：將模型與檢索服務封裝為 API，設計 fallback 機制（搜尋失敗時回到純參數化回答），並監控查詢發出率、證據使用率與幻覺率。

### 潛在風險與注意事項

- **擷取品質低落**：若本地索引過時或排名模型不佳，模型可能學會引用錯誤證據。**緩解**：定期重建索引、引入品質過濾器、對擷取結果進行信心評分。
- **訓練成本過高**：搜尋增強語料會顯著增加詞元量（論文 DCLM-Edu 增強版超過 100B 詞元）。**緩解**：採用較小的模型規模（400M–1.4B 已能超越 3.3B 基準）、控制插入頻率。
- **推論延遲增加**：每次搜尋呼叫都會增加網路往返與 LLM 推論時間。**緩解**：快取常見查詢、批次處理、限制單次回答的最大搜尋次數。
- **證據偏見與過度依賴**：模型可能過度相信擷取內容，即使內容與訓練知識矛盾。**緩解**：在微調階段加入「證據與先驗衝突」的對抗樣本。
- **工具呼叫格式相容性**：不同部署環境可能使用不同的 function calling 格式。**緩解**：採用標準化格式（如 OpenAI、Anthropic 規範）並在微調資料中涵蓋多種變體。
- **後訓練無法完全恢復能力**：論文顯示搜尋預訓練的優勢在 SFT 後仍存在，但若後訓練資料未涵蓋搜尋互動，優勢可能被抹平。**緩解**：後訓練階段務必保留搜尋增強資料。

### 與其他技術的整合建議

- **與傳統 RAG 系統整合**：QueryLM 可作為 RAG 的生成器，但因模型已內建「何時該搜尋」的能力，可簡化傳統 RAG 中「總是先擷取」的設計，改為「按需擷取」。
- **與 Function Calling 框架整合**：將 `<WEB-QUERY>` 與 `<WEB-RESPONSE>` 標籤映射到既有 function calling 格式（如 JSON schema），方便與 LangChain、LlamaIndex 等中介層對接。
- **與持續預訓練（Continual Pretraining）整合**：在領域適應階段，可將搜尋增強語料混入既有預訓練資料流，讓模型在學習領域知識的同時強化搜尋行為。
- **與 RLHF/DPO 整合**：以「正確引用證據」、「拒絕回答無證據問題」作為獎勵訊號，進一步強化模型的證據使用行為。
- **與多模態擷取整合**：未來可將搜尋擴展至圖片、表格、影片，使模型能擷取並引用多模態證據。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀摘要與 Figure 3，理解「在文件中插入查詢與回應」的核心概念，再看 Section 5.1 的主要結果（1.4B 對決 3.3B），即可掌握論文想解決的問題與結論，不必深究訓練細節。

**給 AI 工程師**：重點閱讀 Section 3（搜尋原生預訓練的具體流程）與 Section 6（消融實驗），特別是「擷取品質、回應長度、插入頻率」對效能與成本的影響，這些是實作時必須調控的超參數；同時關注論文釋出的訓練產出物與檢查點，可作為快速實驗的起點。

**給研究者**：建議從 Section 2（相關工作）切入，理解本文與 Toolformer、LMLM、Co-LMLM 等方法的差異；接著深入 Section 5.2（可引導性實驗）與 Section 5.3（一般能力保留），探討「為何後訓練無法完全恢復預訓練階段學到的能力」，這是值得延伸的開放問題。

**給產品經理**：聚焦於 Section 1 的商業意涵——400M 模型搭配搜尋即可超越 3.3B 基準，這代表在成本受限的部署場景（如邊緣裝置、內部工具）可採用更小的模型搭配搜尋功能；同時留意「擷取來源的可控性」與「證據可追溯性」對企業合規與使用者信任的價值。
