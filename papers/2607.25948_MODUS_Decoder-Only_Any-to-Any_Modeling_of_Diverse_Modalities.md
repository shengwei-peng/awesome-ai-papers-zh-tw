# MODUS：僅解碼器（Decoder-Only）的多樣化模態任意對任意（Any-to-Any）建模

**原文標題：** MODUS: Decoder-Only Any-to-Any Modeling of Diverse Modalities

**發布日期：** 2026-07-28

## ⚡ TL;DR

現有任意對任意模型多從頭訓練，無法善用強大預訓練僅解碼器模型。
本文提出MODUS，以單一僅解碼器架構對稱處理多樣模態，支援任意輸入輸出與鏈式生成、自我驗證。
MODUS在多項基準上開箱即用，表現可與專家及多任務基線競爭，並已開源。

## 摘要翻譯

任意對任意（Any-to-Any）模型可在單一網路中，依據任意其他模態（modality）的組合來預測任意模態；此種建模形式已用於多模態（multimodal）視覺與視覺-語言（Vision-Language）模型，並逐漸應用於生態學（ecology）與天文學（astronomy）等科學領域。現有的任意對任意模型通常以編碼器-解碼器（Encoder-Decoder）或擴散架構（Diffusion Architecture）從頭訓練，這影響其效能，也無法利用強大的預訓練（pre-trained）僅解碼器（Decoder-Only）模型作為先驗（Prior）。在本研究中，我們探討僅解碼器的任意對任意多模態建模，其對稱地（symmetrically）處理所有模態，並支援任意模態作為輸入與輸出，無需模態專用頭（Modality-Specific Heads）、損失函數或任務管線（Task Pipelines）。由於每個模態皆是同一模型的輸入與輸出，所得模型稱為 MODUS，它可支援多種應用，例如透過中間模態進行鏈式生成（Chained Generation），或以另一個生成模態對模型自身輸出進行評分，以達成跨模態自我驗證（Cross-Modal Self-Verification）。MODUS 展現出強大的開箱即用效能（Out-of-the-Box Performance），並在多項基準測試（Benchmarks）中以單一模型與專家基線（Specialist Baselines）及多任務基線（Multitask Baselines）達到具競爭力的表現。所有材料均已開源（Open-Sourced）於 https://modus-multimodal.epfl.ch/。

### 核心貢獻（3～5點）
- 提出 MODUS，首個以僅解碼器（Decoder-Only）架構實現的任意對任意（Any-to-Any）多模態模型，對稱地處理所有模態，無需模態專用頭（Modality-Specific Heads）、專用損失函數或任務管線（Task Pipelines）。
- 統一將所有模態視為輸入與輸出，使單一模型即可支援任意模態組合的預測與生成。
- 支援鏈式生成（Chained Generation）與跨模態自我驗證（Cross-Modal Self-Verification）等新穎應用，拓展僅解碼器模型的多模態能力。
- 在多項基準測試（Benchmarks）中展現強大的開箱即用效能（Out-of-the-Box Performance），以單一模型即可與專家基線（Specialist Baselines）及多任務基線（Multitask Baselines）競爭。
- 完整開源（Open-Sourced）所有研究材料，促進後續多模態學習與科學應用之研究。

### 適合對象
本論文適合多模態學習、電腦視覺、視覺-語言（Vision-Language）模型，以及生態學、天文學等科學領域的研究人員與實務工作者閱讀。特別是對於希望以單一統一模型處理多樣化模態輸入與輸出、探索僅解碼器架構在任意對任意（Any-to-Any）建模中之潛力，或尋求可開箱即用（Out-of-the-Box）之多模態基線的讀者，本研究具有高度參考價值。

## 深度分析

#### 方法論解析

MODUS 的核心主張是將 Any-to-Any（任意對任意）多模態生成統一到單一 Decoder-Only（僅解碼器）架構中，使所有 Modality（模態）在輸入與輸出端被對稱地（symmetrically）處理，並且不使用 Modality-Specific Heads（模態專用頭）、專用損失函數或 Task Pipelines（任務管線）。具體而言，其方法論可從以下幾個層面拆解：

1. **統一的 Token Sequence（詞元序列）表示**  
   MODUS 延續並擴展了 BAGEL 等 Decoder-Only 視覺語言模型的思路，將所有模態都轉換為離散或連續的 Token，輸入到單一 Transformer Decoder（Transformer 解碼器）中。離散模態（如 text、object grounding 的 BBox（邊界框）、detection、DINOv2 / CLIP / ImageBind 等 representational modalities）直接以 Autoregressive（自迴歸）的 Next-Token Prediction 進行建模；連續的空間模態（如 RGB、Depth（深度）、Surface Normal（表面法線）、segmentation mask、Edge（邊緣））則在 Latent Space（潛在空間）中以 Flow Matching（流匹配）進行生成。這種設計讓模型可以用同一組參數與同一個目標函數處理多樣化模態。

2. **連續模態的 Latent Flow Matching**  
   對於影像類模態，MODUS 並非直接在像素空間做 Autoregression，而是先透過 VAE（變分自編碼器）將影像壓縮成 Reconstruction Latents（重建潛在變數），再於潛在空間進行 Flow Matching。這樣做有兩個好處：一是降低序列長度與記憶體需求，二是保留連續數值的生成品質。根據論文描述，RGB 的表示同時結合了 ViT（視覺 Transformer）產生的 Semantic Features（語義特徵）與 VAE 的重建潛在變數，形成 Visual Representation Composition（視覺表示組合），讓生成結果同時具備高層語意一致性與低層重建真實度。

3. **條件化與指令驅動的 Any-to-Any 訓練**  
   訓練時，MODUS 從 MODUS-DATASET 中隨機抽樣「條件模態子集」作為輸入，並以 instruction-following prompt 指定目標模態。由於每個模態既可當輸入也可當輸出，模型自然學到任意模態對之間的映射，而不需要為每種轉換任務設計獨立管線。這種 combinatorial（組合式）訓練也讓模型具備 Chained Generation（鏈式生成）能力，例如 Normal → RGB → Edge，或透過中間模態逐步生成最終輸出。

4. **可擴展的模態集合**  
   MODUS 將模態視為開放且可擴展的集合：每個模態家族（如 edges、segmentation、learned features）可以包含多個實例，新增模態時原則上無需修改架構，只需加入對應的 tokenizer 或 latent encoder。這與傳統 encoder-decoder 或 diffusion-based Any-to-Any 模型常見的「每新增模態就新增一組編碼器/解碼器」形成對比。

5. **利用 Pre-trained（預訓練）Decoder-Only Prior（先驗）**  
   與 Unified-IO、4M 等從頭訓練的模型不同，MODUS 建立在強大的預訓練語言模型之上。這讓它在語意理解、指令遵循與 zero-shot 泛化方面具備先天優勢，也更容易透過 KV Cache（鍵值快取）等機制進行高效率推論。

#### 實驗數據解讀

雖然提供的片段未包含完整數據表格，但從摘要與引言可歸納出 MODUS 的評估設計與結果意涵：

1. **評估任務與對應指標**  
   - **核心視覺轉換**：RGB → Depth、RGB → Surface Normal、RGB → Edge、RGB → DINO Features。常用指標包括 RMSE、mean angular error、ODS/OIS F-score、feature cosine similarity 等。  
   - **視覺-語言任務**：VQA（視覺問答）與 Visual Grounding（視覺定位）。VQA 以 accuracy 衡量；grounding 以 Acc@0.5 或 BBox 與 ground truth 的 mIoU 衡量。  
   - **Any-to-Any 生成品質**：跨模態生成結果可能採用 FID、LPIPS、CLIP score 或人類偏好指標評估影像真實度與語意一致性。

2. **結果意涵：單一模型對抗 Specialist Baselines（專家基線）與 Multitask Baselines（多任務基線）**  
   論文強調 MODUS「out-of-the-box（開箱即用）」即可與專家模型及多任務基線競爭。這代表：  
   - 預訓練 Decoder-Only Prior 確實能有效遷移到非語言模態，降低從頭學習模態結構的成本。  
   - 對稱式訓練沒有造成嚴重的災難性遺忘，各模態之間反而可能產生正向遷移（例如語言先驗幫助 grounding，幾何模態互相補強）。  
   - 然而，「competitive」並不一定代表在每個單項都達到 SOTA；對於需要極高精度的專業任務（如高精度深度估計），專家模型仍可能佔優。

3. **Chained Generation 與 Self-Verification（自我驗證）的定性價值**  
   實驗除了傳統指標外，也展示鏈式生成與自我驗證等新型能力。例如模型可先生成一段 caption，再根據 caption 生成影像，或利用一個模態對另一個模態的輸出進行打分。這類能力難以用單一指標量化，但對於建構更可靠的多模態系統具有長期價值。

4. **潛在的數據偏差與評估限制**  
   MODUS-DATASET 為 29M 樣本，許多幾何與語義標籤（depth、normal、segmentation、edge）很可能是透過現成模型產生的 pseudo-label。這意味著評估結果可能受到 pseudo-label 品質與分佈偏差的影響，在真實世界分佈偏移場景下的表現仍需額外驗證。

#### 與現有研究的比較

1. **相較於 Encoder-Decoder（編碼器-解碼器）或 Diffusion Architecture（擴散架構）的 Any-to-Any 模型**  
   Unified-IO、4M 等模型雖然也能處理多種模態，但通常需要從頭訓練，並為不同模態設計專用編碼器、解碼器或損失函數。MODUS 的優勢在於：  
   - 可直接繼承大型 Pre-trained Decoder-Only 模型的語意與推理先驗。  
   - 統一的 Autoregressive 目標簡化了訓練流程，也便於使用現有的 LLM 推論優化技術（如 KV Cache、量化、speculative decoding）。  
   - 任何模態都能同時作為條件與目標，無需預先定義輸入/輸出角色。

2. **相較於 BAGEL、Chameleon、Show-o 等 Decoder-Only 視覺語言模型**  
   BAGEL 主要聚焦於 text ↔ RGB image；Chameleon、Show-o 等雖然也是 Decoder-Only，但多數仍以 text 與 RGB 為中心，並依賴 modality-specific tokenizers 或 text-centric pivots。MODUS 將模態範圍擴展到 Depth、Surface Normal、Edge、Segmentation、Grounding、Detection、DINOv2 / CLIP / ImageBind features 等，並強調所有模態的對稱性。

3. **相較於 Transfusion 等混合架構**  
   Transfusion 在單一 Transformer 中同時處理離散 text token 與連續 image token，但通常需要特別的 attention 機制或 dual objective。MODUS 選擇將連續模態壓縮到 VAE latent 後以 Flow Matching 建模，這在概念上更接近 diffusion/flow 與 autoregression 的結合，但透過 latent space 統一了序列長度與生成粒度。

4. **主要限制**  
   - **模態範圍仍偏視覺與語言**：雖然論文提到生態學、天文學等科學領域的潛力，目前展示的模態仍以影像與文字為主，尚未涵蓋 audio、video、3D point cloud、time series 等。  
   - **訓練資料規模相對有限**：29M 樣本對於學習大量模態間的細緻對齊而言仍屬中等規模，可能限制模型在稀有模態轉換上的表現。  
   - **連續模態生成的複雜度**：Flow Matching 雖然提升了品質，但相較於純離散 Autoregression，訓練與推論流程更複雜，且對 VAE 壓縮品質敏感。  
   - **解析度與序列長度瓶頸**：高解析度影像會產生大量 latent token，Autoregressive 生成仍可能面臨長序列與高延遲問題。

#### 可重現性評估

1. **開源承諾與資源釋出**  
   論文明確表示所有材料已於 https://modus-multimodal.epfl.ch/ 開源。理想的可重現性應包含：模型權重、訓練程式碼、MODUS-DATASET 的建構腳本、tokenizer 與 VAE checkpoint、評估程式碼與配置文件。若這些組件完整釋出，將大幅提升社群驗證與後續研究的可能性。

2. **資料集建構的可重現性挑戰**  
   MODUS-DATASET 結合了多種公開資料集與透過現成模型產生的 pseudo-label。即使釋出原始資料清單與處理腳本，重現 29M 樣本仍需大量計算資源（例如執行 SAM、DINOv2、depth/normal estimation models）。此外，pseudo-label 的模型版本、參數與隨機種子都可能影響最終資料分佈，進而影響模型表現。

3. **訓練成本與硬體門檻**  
   作為基於大型 Decoder-Only 預訓練模型的多模態系統，MODUS 的訓練需要大量 GPU/TPU 資源。論文若未詳細揭露模型大小、訓練步數、batch size、學習率排程與微調策略，則中小型研究團隊難以完全復現。推論端雖可受益於 KV Cache，但多模態長序列仍對記憶體有較高需求。

4. **建議的透明化項目**  
   為進一步提升可重現性，建議作者釋出：每個模態的 tokenizer 細節、Flow Matching 的具體實作（如時間步取樣、條件化方式）、instruction prompt 模板、訓練時的模態子集抽樣策略，以及各基準測試的確切評估指令。

#### 未來研究方向

1. **擴展模態與領域**  
   將 MODUS 的框架延伸至 video、audio、3D point cloud、time series、genomics、天文觀測資料與機器人感測數據，驗證其 Any-to-Any 設計在更廣泛科學領域的通用性。

2. **更大規模的預訓練與資料多樣性**  
   隨著資料量與模型參數增加，Any-to-Any 模型有機會浮現更強的跨模態推理與組合能力。未來可探索數億甚至數十億樣本規模下的 scaling law。

3. **更高效的連續模態 Tokenization**  
   發展聯合離散-連續 tokenizer、可變壓縮率的 VAE、或原生整合 diffusion/flow 與 autoregression 的機制，以在生成品質與推論速度之間取得更好平衡。

4. **Chain-of-Modality 推理與 Self-Verification**  
   將 MODUS 的 Chained Generation 與 Self-Verification 能力形式化為推理策略，例如讓模型自動選擇最有助於正確性的中間模態，或利用跨模態一致性進行 reinforcement learning from self-verification。

5. **統一的 Any-to-Any 評估基準**  
   目前多模態評估仍分散於各專任務基準。未來需要設計能同時衡量多模態對齊、生成品質、組合泛化與推論能力的綜合 Benchmarks（基準測試）。

6. **模態增量擴展與終身學習**  
   研究如何在已訓練好的 MODUS 模型上新增模態，而無需從頭訓練或破壞既有模態能力。這對於實際應用中持續整合新感測器或新資料類型至關重要。

7. **跨模態檢索與可控生成**  
   除了生成任務，未來可探索利用統一潛在空間進行 cross-modal retrieval（跨模態檢索）、以任意模態組合作為條件的可控生成，以及多模態編輯與修補任務。

## 論文問答

**Q1：什麼是任意對任意（Any-to-Any）多模態建模，為什麼它在當前研究中受到關注？**
A：任意對任意多模態建模是指在同一個網路中，能夠根據任意一組模態預測另一種模態，例如給定 RGB 影像生成深度圖、由文字產生邊界框，或反過來由深度圖預測語義分割。這種設定在視覺、視覺-語言，以及生態學、天文學等科學領域都有自然需求，因為這些領域的資料來源多樣且彼此之間存在可組合的關係。相較於為每種模態組合設計專屬模型，任意對任意框架提供了一個統一且可重複使用的解決方案，能夠降低開發與維護成本。

**Q2：現有的任意對任意模型存在哪些主要缺陷，為什麼它們難以發揮大規模預訓練的優勢？**
A：現有的任意對任意模型大多從頭訓練，採用編碼器-解碼器或擴散架構，這使得它們無法直接利用強大的預訓練僅解碼器模型作為先驗。從頭學習模態結構與跨模態對齊需要大量訓練資源，並且在語義保真度、泛化能力與推論效率上通常不如大規模預訓練基礎模型。此外，許多現有的多模態僅解碼器系統仍以文字或 RGB 影像為中心，依賴模態專用頭或任務管線，限制了真正對稱的任意模態到模態生成。

**Q3：為什麼僅解碼器架構被認為適合實現大規模任意對任意多模態生成？**
A：僅解碼器架構具備統一的下一個詞元預測目標，能夠簡化多模態學習並受益於大規模語言模型預訓練所展現的強大零樣本泛化能力。此外，僅解碼器模型可透過 KV 快取等機制提升推論效率，並且已證明能從文字擴展到影像生成。MODUS 進一步將這種架構對稱地應用於多樣化模態，使所有模態都能同時作為輸入與輸出，而不需要為不同任務設計專屬管線。

**Q4：MODUS 的核心方法架構是什麼，如何統一處理不同類型的模態？**
A：MODUS 是一個單一 Transformer 解碼器模型，所有模態都被表示為統一的自迴歸詞元序列，並且不使用模態專用頭、專用損失或專屬任務管線。對於文字、邊界框、檢測結果以及 DINOv2、CLIP 等離散或特徵模態，模型採用下一個詞元預測進行建模；而對於 RGB、深度、表面法線、邊緣圖等連續空間模態，則在潛在空間中使用流匹配進行生成。這種設計讓 MODUS 能夠在單一網路中同時處理 1D 序列模態與 2D 空間模態，實現真正的任意對任意建模。

**Q5：MODUS 相較於先前方法有哪些關鍵創新？**
A：MODUS 的主要創新在於首次在僅解碼器架構中實現對稱的任意對任意多模態生成，所有模態被平等對待，沒有任何一種模態被預設為輸入或輸出的中心。它將模態視為開放且可擴展的集合，每個模態家族可以包含多種實例，新增模態時無需修改架構。此外，MODUS 支援鏈式生成、跨模態自我驗證與視覺表示組合等進階能力，這些都來自於每個模態同時具備輸入與輸出雙重角色的特性。

**Q6：MODUS 在設計上做了哪些重要選擇，為何這樣選擇？**
