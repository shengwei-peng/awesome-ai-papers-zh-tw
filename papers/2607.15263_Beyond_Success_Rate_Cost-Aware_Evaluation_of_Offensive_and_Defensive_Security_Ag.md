# 超越成功率：攻擊型與防禦型安全代理的成本感知評估

**原文標題：** Beyond Success Rate: Cost-Aware Evaluation of Offensive and Defensive Security Agents  
**作者：** Paul Kassianik、Blaine Nelson、Yaron Singer  
**發布日期：** 2026-07-17  
**HF 連結：** [https://huggingface.co/papers/2607.15263](https://huggingface.co/papers/2607.15263)

## ⚡ TL;DR

現行安全代理評估偏重充足預算下的峰值攻擊能力，忽略實際營運成本。
本文提出成本感知評估，在固定預算下比較 Cybench 與 BOTS v1 的紅藍隊表現。
結果顯示攻擊任務隨運算提升，防禦任務則更依賴工具紀律與選擇性擴充。

## 摘要翻譯

安全代理（security agent）評估通常衡量在寬裕推理預算（inference budget）下的峰值攻擊能力（peak offensive capability），強調漏洞發現（vulnerability discovery）、漏洞利用開發（exploit development）、滲透測試（penetration testing）與搶旗賽（Capture The Flag, CTF）解題。此類衡量雖有參考價值，但仍不完整：在實際的安全營運（security operations）中，每一次推理步驟、工具呼叫（tool call）、遙測查詢（telemetry query）與擴充請求（enrichment request）都會消耗預算。我們透過成本—成功率權衡（cost-success tradeoff）的視角，在攻擊型 Cybench 挑戰與防禦型 Splunk BOTS v1 調查挑戰上評估語言模型安全代理。我們不僅報告最佳情境成功率（best-case success），更在固定成本水準（fixed cost level）下比較模型，並按推理支出（inference spend）與工具支出（tool spend）拆解表現。結果顯示，紅隊與藍隊任務呈現不同的擴展模式（scaling regime）。攻擊型搶旗賽表現會隨著額外的測試時運算（test-time compute）而提升，且經過規模化擴展的開源權重模型（open-weight model）能夠逼近前沿專有系統（frontier proprietary system），同時仍具成本競爭力（cost-competitive）。防禦型 SOC 調查則不會以相同方式擴展：成功與其說取決於原始推理預算（raw reasoning budget）本身，更高度仰賴工具紀律（tool discipline）、遙測導航（telemetry navigation）與選擇性擴充（selective enrichment）。我們主張，安全代理基準測試除了任務成功率之外，也應衡量經濟效率（economic efficiency）與作業適配性（operational fit）。成本感知的原生 SOC 評估（SOC-native evaluation）能更清楚地呈現哪些模型在現今具有實用價值，以及防禦型代理還需在哪些方面改進。我們提供一個互動式網站以展示結果：https://evals.frontier.security。

### 核心貢獻（3～5點）
- 提出成本感知評估（cost-aware evaluation）框架，在固定成本水準下比較攻擊型與防禦型安全代理，並拆解推理支出與工具支出對整體表現的影響。
- 發現紅隊與藍隊任務具有截然不同的擴展模式：攻擊型 CTF 表現可隨測試時運算提升，而防禦型 SOC 調查更仰賴工具紀律、遙測導航與選擇性擴充。
- 證明經過規模化擴展的開源權重模型在攻擊任務上能逼近前沿專有系統，同時維持成本競爭力。
- 主張安全代理基準測試應同時衡量經濟效率與作業適配性，並提供原生 SOC 評估以反映實務場景。
- 建置互動式評估網站，公開比較多種模型在 Cybench 與 Splunk BOTS v1 上的成本—成功率權衡結果。

### 適合對象
本論文最適合從事 AI 安全代理研究與開發的學者與工程師、資安營運中心（SOC）分析師與管理者，以及關注大型語言模型在紅隊／藍隊任務實際部署成本效益的資安決策者與基準測試設計者閱讀。

## 深度分析

#### 方法論解析

本研究的核心方法是將「成本—成功率權衡（cost-success tradeoff）」作為評估攻擊型安全代理（offensive security agent）與防禦型安全代理（defensive security agent）的共同主軸，而非僅報告無預算限制下的最佳情境成功率（best-case success）。作者設計了一個統一的代理評估框架（agent-evaluation harness），同時執行兩類性質迥異的任務族（task family）：攻擊面的 Cybench 搶旗賽（Capture The Flag, CTF）任務，以及防禦面的 Splunk Boss of the SOC（BOTS）v1 調查任務。透過這個框架，研究把「成功」重新定義為在固定成本水準（fixed cost level）或固定工具呼叫上限下能完成的任務比例，從而將安全代理的評估從「峰值攻擊能力（peak offensive capability）」轉向「經濟效率（economic efficiency）」與「作業適配性（operational fit）」。

在成本拆解上，作者明確區分兩類支出。第一類是推理支出（inference spend），即模型在測試時運算（test-time compute）所消耗的 token 成本；第二類是工具支出（tool spend），包括 Splunk 查詢（Splunk query）、事件檢視（event inspection）、網頁搜尋（web search）、WHOIS 歷史（WHOIS history）與其他情報擴充請求（enrichment request）。對於攻擊型任務，邊際支出（marginal spend）主要來自額外推理與命令執行（command execution）；對於防禦型任務，則還包含大量分析師導向資源（analyst-facing resource）。這種區分是本文方法論的關鍵，因為它讓「每單位預算買到多少能力」成為可比較的運作點（operating point）。

具體評估設計包含以下幾個層次：

1. **回顧式每樣本成本預算上限（retrospective per-sample cost budget cap）**：對於 Cybench，作者事後設定一個成本上限 x，只有當某題的模型 token 花費不超過 x 時，該題才會被計入在預算 x 下的成功率。這樣可以畫出「成功率對成本上限」的曲線，觀察不同模型隨預算增加而擴展的軌跡。
2. **工具呼叫上限與二元答案準確率（binary answer accuracy）**：對於 BOTS v1，作者以每樣本的工具呼叫（tool call）數量為橫軸，並使用對稱對數軸（symmetric-log axis）呈現，觀察防禦代理在有限查詢次數下能達到的答題正確率。
3. **模型 token 與計價工具成本會計（model-token plus priced-tool cost accounting）**：除了計算工具呼叫次數，作者還將 Splunk 查詢、外部情報擴充等工具賦予實際價格，計算「每 1,000 分 BOTS 積分所需的成本」，作為 SOC 場景的經濟效率指標。
4. **無工具對照組（no-tools controls）**：由於 BOTS v1 是公開資料集，作者特別設計不使用任何工具的對照實驗，以檢驗模型是否僅靠記憶或直接答案恢復（direct answer recovery）就能得分。結果顯示部分模型在無工具情況下仍有顯著得分，凸顯在解讀絕對分數前必須進行去汙染檢查（decontamination checks）。

整體而言，本文方法論的價值在於把「成本」內建為評估維度，並透過固定預算將不同模型、不同任務的表現轉換為可比的運作點。這種做法特別適合安全營運中心（Security Operations Center, SOC）的實際需求：分析師不只需要知道「最強模型在無限預算下能否解題」，更需要知道「在有限查詢與預算下，代理能否做出分析師級答案（analyst-grade answer）」。

#### 實驗數據解讀

實驗主要圍繞圖 1 的兩條曲線展開。左圖呈現 Cybench 上各模型的成功率隨每樣本成本預算上限（per-sample cost budget cap）變化的情形；右圖則呈現 BOTS v1 上各模型的二元答案準確率隨每樣本工具呼叫上限變化的情形。這兩張圖揭示了紅隊與藍隊任務截然不同的擴展模式（scaling regime）。

在攻擊面 Cybench 上，實驗顯示 CTF 表現隨著額外測試時運算而穩定提升。Claude Opus 4.8 與 DeepSeek v4 Flash 在提高預算後仍有明顯成長空間，代表這些模型還沒有觸及能力高原（plateau）；相對地，GPT-5.5 在較低成本上限下就已解決大多數它能解的題目，顯示其對於這組 CTF 任務的邊際推理支出效率較高。更重要的是，放大後的開源權重模型（open-weight model）能夠逼近前沿專有系統（frontier proprietary system），同時保持成本競爭力（cost-competitive）。這個結果對實務有重要意義：在攻擊型場景中，「堆疊推理預算（inference budget）」確實能帶來可預期的能力增益，而開源模型不一定需要犧牲太多效能。

在防禦面 BOTS v1 上，數據呈現完全不同的圖像。增加工具呼叫上限或提高成本上限，對最強模型的幫助非常有限：表現最好的模型在大約 20 次工具呼叫內就接近飽和。相反地，DeepSeek v4 Flash 即使進行超過 100 次工具呼叫，最終也只能達到較低的高原。這說明防禦型任務的成功並不取決於原始推理預算（raw reasoning budget）或工具數量，而是取決於工具紀律（tool discipline）、遙測導航（telemetry navigation）與選擇性擴充（selective enrichment）。換句話說，藍隊代理的價值在於「知道該查什麼、何時停止、何時值得為情報付費」，而不是單純地進行大量 Splunk 查詢（Splunk query）或外部擴充。

作者進一步提出「每 1,000 分 BOTS 積分的成本」作為 SOC 場景的經濟效率指標。這個指標把模型表現與實際營運開支掛鉤，讓管理者能夠判斷：為了獲得同樣的調查分數，不同模型在推理支出與工具支出上的總花費是多少。對於需要大量執行調查任務的 SOC 而言，這遠比單純的準確率更有決策價值。

無工具對照組的結果則帶來一項重要警示：由於 BOTS v1 是公開資料集，部分模型即使不使用任何工具也能取得可觀分數，這可能是因為訓練資料中已經收錄了相關題目或答案。因此，在宣稱某個防禦型安全代理「會調查」之前，必須先排除資料汙染（benchmark contamination）所造成的虛高分數。這也說明原生 SOC 評估（SOC-native evaluation）不能只看最終答案正確與否，還必須檢視代理是否真正使用了遙測查詢（telemetry query）與分析流程來得出結論。

綜合來看，實驗數據支持本文的核心論點：攻擊與防禦代理應該用不同的成本透鏡來評估。紅隊任務可以透過增加測試時運算來擴展能力；藍隊任務則更依賴節制的工具使用與精準的遙測導航。

#### 與現有研究的比較

在攻擊型安全代理評估領域，已有大量基準著重於互動式執行與峰值成功率。例如 InterCode 與 InterCode-CTF 標準化了程式碼任務與搶旗賽的執行回饋機制；NYU CTF Bench 擴展了公開 CTF 題目的覆蓋率；Cybench 則引入專業級 CTF 任務與沙箱化（sandboxed）命令執行；CVE-Bench 進一步走向真實網頁應用漏洞利用；PentestGPT 評估大型語言模型在滲透測試（penetration testing）子任務中的支援效果；EnIGMA 顯示互動式除錯器與連線工具能顯著協助漏洞發現（vulnerability discovery）代理；BountyBench 則把評估單位擴大到真實程式碼庫上的偵測、利用與修補任務，並以美元計價的漏洞獎金衡量成果。這些研究大多聚焦於「在充足資源下能完成什麼」，而本文的差異在於系統性地比較「成本—成功率權衡」與「預算上限下的運作點」。

在防禦型與 SOC 評估方面，現有文獻主要來自事件應變指引與資安人力職能分類（如 NIST 相關文件），強調偵測、分析、證據處理、應變協調與作業判斷。Splunk BOTS 系列提供了公開安全遙測、題目、答案與計分文件，是藍隊演練的經典資料集。近期研究也開始填補防禦代理基準的缺口：SIABench 將安全事件分析框架為警報分類與多步驟惡意軟體、釣魚、鑑識與日誌分析工作流程；ExCyTIn-Bench 從圖關聯的安全日誌衍生網路威脅調查問題；CyberTeam 將藍隊威脅狩獵建模為具身函式呼叫工作流程；Cyber Defense Benchmark 則評估在原始 Windows 事件日誌上的開放式威脅狩獵。本文與這些研究的關係是互補的：它保留了 BOTS v1 的官方計分規則（scoring rule），但額外加入固定預算比較、模型 token 成本、計價外部工具支出與工具效率視角，從而填補「經濟效率」這一維度。

在基準完整性方面，本文也呼應了近年關於資料汙染與洩漏控制的研究。Deng、Wang、Li 等人的工作指出，公開測試集可能與模型訓練資料重疊，或能從模型行為中部分恢復，導致能力被高估。實務上建議採取保護測試發布、訓練排除控制、私有或回顧式保留集，以及謹慎處理 API 媒介洩漏等機制。本文的無工具對照組正是這類去汙染檢查的具體實踐，提醒社群在解讀 BOTS v1 等公開資料集的絕對分數時必須謹慎。

然而，本研究也存在若干限制。首先，它只涵蓋兩個任務族：Cybench 與 BOTS v1，雖然具代表性，但無法涵蓋所有攻擊與防禦場景。其次，BOTS v1 是公開資料集，資料汙染風險無法完全排除，即使作者設計了無工具對照組，仍難以斷言所有模型都未受訓練資料影響。第三，成本會計依賴特定價格假設，而實際 API 定價、工具訂價與匯率會隨時間變動，可能影響跨時比較。第四，固定預算上限是一種簡化的靜態設定，真實 SOC 作業中預算分配往往是動態的，代理需要根據中間線索決定是否繼續投入資源。第五，防禦評估目前主要使用二元答案準確率，對於調查過程的品質、證據引用、誤判權衡等面向仍有擴充空間。最後，實驗未納入服務水準協議（SLA）、警報量、分析師審查時間等真實營運限制。

#### 可重現性評估

本研究在資料可取得性方面具備良好基礎。Cybench 與 Splunk BOTS v1 均為公開資料集，研究者可以自行下載並重跑實驗。Cybench 提供沙箱化 CTF 環境與標準化的任務介面；BOTS v1 提供公開遙測、官方題目、答案與計分規則，這些都降低了重複實驗的門檻。此外，作者建立了互動式網站 https://evals.frontier.security，用於呈現實驗結果，這對於理解不同模型在各成本水準下的相對表現非常有幫助。

在模型可取得性方面，研究同時評估了專有商業模型與開源權重模型。專有模型如 Claude 系列與 GPT 系列可透過 API 呼叫重現；開源權重模型如 DeepSeek v4 Flash 的權重原則上可公開取得，研究者可以在本地或自有基礎設施上部署。這種混合設計讓社群能夠在能力與成本兩個維度上進行比較。

不過，根據目前提供的上下文，完整的代理評估框架原始碼、提示詞（prompt）、工具模式（tool schema）、成本計算腳本與實驗配置並未明確釋出。雖然網站提供了結果視覺化，但若缺少底層程式碼，其他研究者要完全重現相同的運作點仍會面臨挑戰。理想情況下，作者應公開以下內容以提升可重現性：統一的代理評估框架程式碼、各模型使用的系統提示與工具描述、Splunk 查詢與外部情報工具的計價表、無工具對照組的執行方式，以及每個樣本的詳細成本與工具呼叫日誌。這些資訊能讓後續研究在相同基準上進行公平比較，並驗證作者的成本會計假設。

整體而言，本研究的可重現性處於「中等偏上」水準：公開資料集與互動式網站提供了良好的起點，但若要達到完全可重現，仍需補充更多實作細節與程式碼釋出。

#### 未來研究方向

基於本文的成本感知評估框架，未來研究可以朝以下幾個方向延伸：

1. **擴展任務與資料集覆蓋率**：除了 Cybench 與 BOTS v1，可納入 BOTS v2/v3、CVE-Bench、SIABench、Cyber Defense Benchmark 與企業級 SIEM 日誌，檢驗成本—成功率權衡是否在不同任務族中保持一致。特別是加入真實網頁應用漏洞利用與企業內網滲透測試場景，能讓評估更貼近實際攻擊鏈。

2. **動態預算分配與早期停止機制**：本文使用固定成本上限，但未來可研究讓代理在執行過程中根據中間線索與預期收益決定是否繼續投入資源。這涉及強化學習、成本效益估計與貝葉斯最佳停止問題，對 SOC 作業尤為重要。

3. **多目標帕累托前沿分析**：除了成本與成功率，還可加入延遲（latency）、誤判率、分析師信任度與可解釋性等指標，繪製多維度帕累托前沿，幫助營運團隊根據自身偏好選擇最適模型。

4. **強化去汙染與基準完整性**：對於公開資料集，應建立更嚴謹的去汙染檢查流程，例如私有保留集、金絲雀測試（canary tests）、訓練資料排除審計，以及 API 媒介洩漏監控。未來也可發展「過程導向」評估，要求代理不僅給出正確答案，還必須展示正確的遙測查詢與證據鏈。

5. **細粒度防禦品質指標**：超越二元答案準確率，發展衡量調查品質的指標，例如證據引用完整性、假設更新軌跡、誤報與漏報權衡、以及與人類分析師答案的語義相似度。這能更真實地反映藍隊代理的作業價值。

6. **工具定價與營運限制的真實化**：未來評估可納入分級 API 定價、速率限制、並行限制、SLA 違約成本，以及分析師審查與升級的人力成本。這將使「經濟效率」指標更貼近 SOC 採購與部署決策。

7. **紅藍對抗的聯合評估**：設計同時包含攻擊與防禦代理的對抗場景，衡量攻擊方的滲透成本與防禦方的偵測成本。這種聯合視角能揭示「偵測—規避」賽局中的成本動態，並評估代理在持續對抗中的穩健性。

8. **拒絕行為與濫用風險的成本分析**：本文觀察到 Claude Fable 5 在 Cybench 上出現拒絕（refusals）。未來可系統性地研究模型拒絕行為如何隨預算、提示與任務類型變化，並評估在成本受限下濫用風險是否會因模型選擇而改變。

9. **人機協作成本模型**：將人類分析師的介入視為另一種成本，研究代理在何時應該自主完成調查、何時應該請求人類確認。這對於設計可部署的 SOC 輔助系統至關重要。

10. **信心校準與選擇性回答**：發展能夠估計自身不確定性的防禦代理，讓它在信心不足時選擇不回答或請求更多線索，而不是進行大量無效工具呼叫。這直接對應到本文所強調的工具紀律與選擇性擴充。

總結來說，本文為安全代理評估開啟了「成本感知」的新維度，未來研究應在此基礎上進一步細化任務場景、動態決策、多目標權衡與真實營運限制，從而讓安全代理的評估更接近實際部署環境。

## 論文問答

**Q1：這篇論文指出目前安全代理評估存在什麼問題？**
A：現行的安全代理評估通常在高推理預算下測量峰值攻擊能力，強調漏洞發現、漏洞利用開發、滲透測試與搶旗賽（CTF）完成度。這類測量雖能追蹤攻擊者可能利用的能力，卻忽略了在實際營運中，每一步推理、每一次工具呼叫、每一筆遙測查詢與每一個擴充請求都會消耗預算。因此，單純的最佳情境成功率無法反映模型在真實生產環境中的可負擔性與實用性。

**Q2：為什麼峰值能力測量對於作業型資安而言並不足夠？**
A：作業型資安並非峰值能力演練，安全營運中心（SOC）的代理必須在有限的時間、token 與工具預算內導航遙測資料並產出分析師級答案。一個在數百萬 token 預算下能解出 CTF 的模型，若每次事件調查都過於昂貴或耗時，在經濟上仍不可行。所以，在固定成本上限下測量能力，才更能代表模型對實際營運的價值。

**Q3：成本感知評估對防禦型 SOC 代理為何特別重要？**
A：防禦任務涉及大量分析師導向資源，例如 Splunk 查詢、事件檢視、網頁搜尋與 WHOIS 歷史等，這些成本都超出模型推理本身。若代理發出過多或選擇不當的查詢，可能在未提升準確率的情況下迅速耗盡 SOC 的作業預算。因此，成本感知評估能衡量代理是否透過有紀律的工具使用與選擇性擴充來交付高品質答案。

**Q4：論文提出的核心方法論轉變是什麼？**
A：作者將「成本」作為比較攻擊型與防禦型安全代理的共同軸線，把成功率轉化為「每花一美元能買到多少能力」的作業問題。他們在固定成本水準下比較模型，並將總支出拆解為推理支出與工具支出，而非僅呈現單一最佳排行榜。這種做法讓每個運作點都由模型、任務族、成本上限、可用工具與計分規則共同刻畫。

**Q5：評估框架的關鍵創新有哪些？**
A：論文建立了一個共同的代理評估框架，能同時執行攻擊型 Cybench 題目與防禦型 Splunk BOTS v1 調查，並採用統一的成本會計。它進行配對式預算餘量分析，透過回顧式地對每樣本設定支出上限，觀察不同預算下的分數變化。此外，框架納入定價工具成本會計與無工具對照組，以區分真正的調查能力與單純記憶或直接答案回復。

**Q6：為什麼論文要區分推理支出與工具支出？**
A：在攻擊型 CTF 中，邊際支出主要來自測試時運算與命令執行；而在 SOC 調查中，還需支付 Splunk 查詢與外部擴充等分析師導向資源。若將兩者混為一談，會掩蓋重要的行為差異：某個模型可能 token 花費很少，卻透過大量不必要的工具呼叫來 brute-force。分開計算後，才能判斷高分是來自聰明的推理，還是來自昂貴的查詢暴力。

**Q7：研究使用了哪些基準測試，為何選擇它們？**
A：攻擊面使用 Cybench，它提供具沙箱化 shell 與 Python 存取的 CTF 風格任務；防禦面使用 Splunk Boss of the SOC（BOTS）v1，它提供公開安全遙測、官方競賽題目、答案與計分機制。這兩個基準都具備真實的代理迴路：Cybench 需要互動式漏洞利用，BOTS v1 則需要發現日誌綱要、修訂 SPL、關聯事件與決定是否擴充。兩者都有明確的成功指標，並允許對模型推理與工具使用進行成本核算。

**Q8：在攻擊任務上的主要實證發現是什麼？**
A：在 Cybench 上，成功率隨測試時運算增加而穩定上升，Claude Opus 4.8 與 DeepSeek v4 Flash 仍顯示明顯餘量，而 GPT-5.5 已在較低成本上限下解出多數成功題目。規模化後的開源權重模型能逼近前沿專有系統，同時保持成本競爭力。這顯示攻擊型 CTF 表現會受推理預算提升而改善，且開源模型正成為可行的替代方案。

**Q9：在防禦任務上的主要實證發現是什麼？**
A：在 BOTS v1 上，額外預算對成功的預測力遠低於 Cybench；最強模型在大約二十次工具呼叫內已接近最佳表現。DeepSeek v4 Flash 雖將工具呼叫量增加到一百次以上，卻在較低準確率上進入高原，顯示防禦任務重視的是工具紀律而非數量。因此，SOC 調查的成功更依賴遙測導航與選擇性擴充，而非單純的原始推理預算。

**Q10：無工具對照組揭示了什麼，為何重要？**
A：無工具對照組顯示，部分模型在完全不存取遙測資料的情況下，仍能對公開的 BOTS v1 題目給出相當比例的正確答案。這意味公開基準可能存在資料污染或部分記憶現象，導致表面能力被高估。因此，在解讀絕對分數前，必須先進行去污染檢查，否則無法確定模型是否具備真正的調查能力。

**Q11：成本感知評估如何協助安全代理的產品決策？**
A：透過在固定成本水準下比較模型，廠商與 SOC 團隊能找出每花費一美元推理與工具成本後，最能產出分析師級答案的模型。它也能凸顯高成功率是來自高效推理，還是來自大規模不可持續的暴力查詢。產品路線圖因此可以優先改善工具紀律與遙測導航，而非僅僅擴大推理預算。

**Q12：成本感知、原生 SOC 評估對整個領域可能產生什麼更廣泛影響？**
A：這類評估促使基準同時測量經濟效率與作業適配性，而不只是原始任務成功率，讓研究誘因更貼近生產需求。它有助於實務工作者區分令人驚豔的展示效能與在真實 SOC 預算下可長期運行的代理。長期來看，這將推動開發出更具紀律、可解釋且價格合理的防禦型代理，以支援日常事件應變。

**Q13：論文承認了哪些限制？**
A：研究僅使用一個攻擊基準 Cybench 與一個防禦資料集 Splunk BOTS v1，可能無法涵蓋現代資安任務的全部多樣性。BOTS v1 的公開性帶來污染疑慮，而無工具對照組也顯示部分分數可能反映記憶而非真實調查能力。此外，固定每樣本預算簡化了真實營運中還包含延遲、並行度與人工監督等複雜限制。

**Q14：論文強調了哪些失敗案例或負面結果？**
A：Claude Fable 5 在 Cybench 攻擊任務上出現拒絕行為，因此只能在 BOTS v1 上評估，顯示安全拒答可能限制跨任務比較。DeepSeek v4 Flash 在 BOTS v1 上發出超過一百次工具呼叫，卻在較低準確率上停滯，說明更多查詢並不保證更好的防禦表現。這些案例共同強調：原始活動量或預算並不是能力的可靠代理指標。

**Q15：論文建議了哪些未來研究方向？**
A：未來研究應將成本感知評估擴展到更新的 BOTS 資料集、即時遙測串流，以及更多真實世界漏洞利用等攻擊基準。也可探索自適應預算分配、多代理協作，以及更符合 SOC 工作流程的人機協作成本模型。最後，需要更強的去污染控制與私有測試釋出機制，以確保報告的成功率反映真正的代理能力，而非訓練資料洩漏。

## 實務應用指南

### 適用場景

1. **紅隊自動化滲透測試的成本控管**  
   企業紅隊或委外滲測團隊可利用成本感知評估，為不同模型設定「每案成本上限」，在 CTF 或真實漏洞演練中比較「每美元能發現多少弱點」，避免無限制呼叫高成本推理模型。

2. **SOC 調查代理的選型與上線評估**  
   資安營運中心在導入藍隊調查代理時，可依固定工具呼叫預算與 Splunk 查詢成本，評估模型在有限遙測資源下能否產出分析師級答案，作為採購或內部部署的依據。

3. **資安產品定價與服務層級設計**  
   資安平台廠商可將「每 1,000 BOTS 分成本」或「每成功解題成本」轉化為產品計價單位，設計不同推理強度與工具擴充等級的服務方案。

4. **開源權重模型與閉源前沿系統的採購比較**  
   當組織在 DeepSeek、GPT、Claude 等模型間抉擇時，可透過固定成本水準的橫向比較，判斷開源權重模型是否能在攻擊任務上達到與專有系統相近的經濟效率。

5. **防禦代理的紀律性工具使用訓練**  
   藍隊可利用 BOTS v1 這類原生 SOC 評估，訓練代理在 20 次工具呼叫內完成調查，強化選擇性擴充與遙測導航能力，而非單純堆疊推理預算。

  - 防禦面：取得 Splunk BOTS v1 公開遙測、官方題目、答案與計分規則；建議同時準備未公開的保留測試集以進行汙染檢查。

  - 可執行代理評估框架的運算環境（容器或 VM）。

  - 工具呼叫計價表：Splunk 查詢、網頁搜尋、WHOIS 歷史、威脅情資擴充等每筆費用。

- **技能需求**
  - 熟悉資安紅隊流程（漏洞發現、漏洞利用開發、滲透測試）與藍隊流程（SPL、事件檢視、事件應變）。
  - 具備語言模型代理開發經驗，能設計工具呼叫介面、提示詞與預算中斷機制。
  - 具備基礎資料分析能力，能繪製成本—成功率權衡曲線並解讀高原現象。

### 實作步驟建議

1. **定義運作點**  
   為每個模型、任務族、工具組合與計分規則建立運作點，例如：「GPT-5.6 高推理強度 + Cybench + 每樣本 $X 上限」。

2. **建立統一代理評估框架**  
   將 Cybench 與 BOTS v1 接入同一個 harness，統一記錄模型 token 消耗、工具呼叫次數、每次工具支出與執行時間。

3. **設定回顧式成本上限**  
   先以寬鬆預算跑完全部樣本，再事後套用多個每樣本成本預算上限，觀察不同上限下的成功率變化，找出預算紅利與高原區。

4. **拆分推理支出與工具支出**  
   攻擊任務著重測試時運算與命令執行成本；防禦任務則將 Splunk 查詢、事件檢視、擴充請求分開計價，計算每 1,000 BOTS 分成本。

5. **執行無工具對照組**  
   在 BOTS v1 上執行不給任何工具的模型，評估直接答案恢復比例，作為資料汙染與基線能力的校正。

6. **繪製並比較成本—成功率曲線**  
   使用對稱對數軸或線性軸呈現攻擊與防禦曲線，觀察：攻擊成功率是否隨預算穩定上升；防禦模型是否在約 20 次工具呼叫後即達高原。

7. **迭代優化工具紀律**  
   針對防禦代理，加入工具選擇獎懲、搜尋策略提示與預算耗盡預警，減少無效遙測導航與過度擴充。

8. **建立互動式結果網站或儀表板**  
   參考論文網站模式，讓營運與採購團隊可依模型、成本上限、任務族篩選結果。

### 潛在風險與注意事項

- **資料汙染與過度樂觀的絕對分數**  
  BOTS v1 為公開資料集，模型可能已透過訓練資料直接恢復答案。務必執行無工具控制組，並以相對比較為主、絕對分數為輔。

- **將攻擊任務的擴展模式錯誤套用到防禦任務**  
  攻擊成功率通常隨測試時運算增加而提升，但防禦任務更依賴工具紀律。若僅提高推理預算而不改善搜尋策略，可能只會增加成本。

- **工具計價遺漏**  
  實務中的 Splunk 授權、威脅情資訂閱、網頁搜尋 API 計價方式各異，建議建立組織專屬的「每工具呼叫成本表」，避免低估營運支出。

- **沙箱與執行安全**  
  Cybench 涉及命令執行與漏洞利用開發，必須在隔離沙箱中執行，防止評估過程本身成為內部威脅。

- **過度聚焦峰值攻擊能力**  
  若只報告最佳情境成功率，會忽略生產環境的預算限制。建議每次報告都附帶至少三個固定成本水準的結果。

- **模型拒答導致樣本偏差**  
  部分模型（如 Claude Fable 5）可能對攻擊任務拒答，需在報告中標註並分開分析，避免將拒答樣本計入成功率。

### 與其他技術的整合建議

- **SIEM／SOAR 平台**  
  將防禦代理的工具呼叫對接到 Splunk、Microsoft Sentinel 或 Chronicle，並把成本上限與 SOAR 劇本中的「最大查詢次數」欄位綁定，實現預算中斷。

- **漏洞管理與滲透測試工具鏈**  
  攻擊代理可整合 Nmap、Metasploit、Burp Suite 等工具，並將每次呼叫的計價與執行結果回寫至漏洞管理平台，形成「每弱點發現成本」指標。

- **LLM 可觀測性與成本監控**  
  接入 Langfuse、LangSmith 或自研成本追蹤器，即時記錄模型 token、推理強度與工具支出，並在接近每樣本成本預算上限時觸發告警。

- **RAG 與內部知識庫**  
  在 SOC 調查中，將常見攻擊手法、內部日誌 schema 與過往事件報告建入 RAG，減少對外部付費擴充的依賴，提升選擇性擴充的品質。

- **紅藍隊對抗演練平台**  
  把成本感知評估框架嵌入定期紅藍對抗，動態比較攻擊代理的「每美元滲透深度」與防禦代理的「每美元檢測覆蓋率」。

- **AI 工程師**  
  重點閱讀代理評估框架、模型 token 與工具支出的拆分方式，以及無工具控制組的實作細節。可據此設計自己的 harness，並把「每樣本成本預算上限」實作成硬中斷條件。

- **研究人員**  
  請關注兩種擴展模式的差異、資料汙染對絕對分數的影響，以及 SOC 原生評估方法論的貢獻。可進一步延伸至多輪對話、動態對手或更真實的企業遙測環境。

- **產品經理**  
  從適用場景與經濟效率出發，把論文結果轉化為產品規格：例如設計「輕量調查」「深度調查」「紅隊自動化」三種服務層級，並用每 1,000 BOTS 分成本或每成功解題成本作為定價與採購談判依據。
