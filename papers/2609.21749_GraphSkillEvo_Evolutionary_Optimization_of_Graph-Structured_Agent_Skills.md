## ⚡ TL;DR

現有技能最佳化以非結構化自然語言表示技能，導致工作流程指引不清且搜尋空間冗餘龐大。
本文提出圖結構技能與GraphSkillEvo族群式演化框架，以結構感知突變與交配運算子進行最佳化。
五項測試顯示GraphSkillEvo優於SkillOpt，LLM準確率提升4.01%與1.76%。

## 摘要翻譯

技能可透過提供任務專屬程序性指引（task-specific procedural guidance），提升大型語言模型（Large Language Model, LLM）智慧體（agent）的表現，而技能最佳化（skill optimization）則可透過迭代式精煉（iterative refinement）進一步提升其有效性。然而，現有的技能最佳化方法通常將技能表示為非結構化自然語言指令，帶來兩個關鍵挑戰：1）非結構化技能（unstructured skill）通常缺乏明確的工作流程層級指引（workflow-level guidance），且包含大量冗餘（redundancy），使得 LLM 難以執行；2）無約束的自然語言技能所具有的龐大搜尋空間（search space），使技能最佳化效果不彰。為解決這些挑戰，我們提出將技能表示為圖結構化自然語言產物（graph-structured natural-language artifact）。在圖結構技能（graph-structured skill）中，每個節點（node）代表一個執行步驟（execution step）及其操作指引（operational guidance），而有向邊（directed edge）則編碼步驟間的情境相依轉移（context-dependent transition）。相較於非結構化技能，圖結構技能能提供清晰的工作流程層級指引。此外，此圖結構技能表徵亦能促進技能最佳化。基於此結構化表徵，我們提出 GraphSkillEvo，一個具備突變運算子（mutation operator）與交配運算子（crossover operator）、專為圖結構技能設計的族群式演化最佳化框架（population-based evolutionary optimization framework）。透過維護多個候選技能（candidate skill）並結合有效元件（effective component），GraphSkillEvo 能夠比純粹基於 LLM 的迭代式自我精煉（iterative self-refinement）更廣泛且更全面地探索結構化技能空間。橫跨五個智慧體基準測試（benchmark）的大量實驗顯示，GraphSkillEvo 持續優於強大的技能最佳化基線 SkillOpt，在 GPT-5.4-nano 上平均準確率（average accuracy）提升 4.01%，在 GPT-5.4 上提升 1.76%。我們的程式碼已公開於 https://github.com/ruisun7/GraphSkillEvo。

### 核心貢獻（3～5點）
- 提出以圖結構化自然語言產物（graph-structured natural-language artifact）表示技能，透過節點（node）與有向邊（directed edge）提供清晰的工作流程層級指引（workflow-level guidance），並降低非結構化技能中的冗餘（redundancy）。
- 設計 GraphSkillEvo 族群式演化最佳化框架（population-based evolutionary optimization framework），包含針對圖結構技能的突變運算子（mutation operator）與交配運算子（crossover operator）。
- 透過維護多個候選技能（candidate skill）並組合有效元件（effective component），實現比純 LLM 迭代式自我精煉（iterative self-refinement）更廣泛且全面的結構化技能空間探索。
- 在五個智慧體基準測試（benchmark）上驗證，GraphSkillEvo 持續優於強大基線 SkillOpt，於 GPT-5.4-nano 與 GPT-5.4 上分別提升平均準確率（average accuracy）4.01% 與 1.76%。

### 適合對象
本論文適合對 LLM 智慧體（LLM agent）、技能最佳化（skill optimization）及複雜任務（complex task）自動化感興趣的研究者與工程師，特別是關注如何以結構化方式提升智慧體執行表現、或希望將可重複使用（reusable）技能應用於真實世界應用（real-world application）的讀者。

## 深度分析

#### 方法論解析

GraphSkillEvo 的核心貢獻在於將傳統的「非結構化技能（unstructured skill）」重新定義為「圖結構技能（graph-structured skill）」，並在此基礎上設計了一個「族群式演化最佳化框架（population-based evolutionary optimization framework）」。以下分三個層次深入解析其方法論。

**1. 圖結構技能（Graph-Structured Skill）的表徵設計**

在 GraphSkillEvo 中，每一個技能（skill）不再是一篇長篇的自然語言指令或條列式檢查清單（checklist），而是一個有向圖（directed graph）：

- **節點（node）**：每個節點對應一個「智慧體執行步驟（agentic execution step）」，內含獨立完整的操作指引（self-contained operational guidance），例如該步驟應遵循的指令、規則與輸出限制（output constraint）。
- **有向邊（directed edge）**：邊表示「情境相依轉移（context-dependent transition）」，即根據當前任務條件（task condition）決定下一步應該走向哪個節點，從而形成不同的執行路徑（execution path）。

這種設計帶來兩個關鍵優勢：

- **執行層面**：工作流程（workflow）被顯式地結構化，LLM 智慧體（LLM agent）在每一步都能清楚知道當前應參考哪一段指引，以及下一步該往哪裡走，特別對能力較弱的模型（如 GPT-5.4-nano）有顯著幫助。
- **最佳化層面**：圖結構減少了表徵冗餘（representational redundancy）。相同的程序性知識（procedural knowledge）在非結構化文字中可能以多種不同方式書寫，但在圖中則被收斂為節點與邊的組合，從而壓縮搜尋空間（search space）。

**2. GraphSkillEvo 的演化最佳化流程**

GraphSkillEvo 採用「族群式演化最佳化（evolutionary optimization）」而非單一技能的迭代式自我精煉（iterative self-refinement）。其流程可概括如下：

- **初始化**：從初始技能（initial skill）出發，建立一組候選技能（candidate skill）構成的族群（population）。
- **執行與評估**：將每個候選技能提供給智慧體（agent），在訓練集（training set）上收集執行軌跡（execution trajectory），並在驗證集（validation set）上以任務專屬的評分函數（scoring function）評估表現。
- **突變運算子（mutation operator）**：根據單一技能的執行軌跡進行分析，對其圖結構進行局部修改，例如新增、刪除或重寫節點與邊。
- **交配運算子（crossover operator）**：從不同候選技能中識別出互補且有效的圖元件（effective component），進行重組，產生結合多個優點的新技能。

透過同時維護多個候選技能，GraphSkillEvo 能夠在結構化的技能空間中進行更廣泛且全面的探索，避免單一 LLM 自我精煉容易陷入局部最優的問題。

**3. 方法論的設計哲學**

GraphSkillEvo 的設計體現了「結構即搜尋空間」的思想：透過將技能從自由文字轉換為圖結構化自然語言產物（graph-structured natural-language artifact），不僅提升了可執行性，也讓最佳化演算法能夠在更具語義意義的單元（節點與邊）上操作。這與傳統提示工程（prompt engineering）中將提示視為純文字字串的做法形成鮮明對比。

#### 實驗數據解讀

根據摘要與引言中的描述，GraphSkillEvo 在五個智慧體基準測試（agent benchmark）上進行了廣泛實驗，並與強基線 SkillOpt 進行比較。主要結果如下：

- 在 **GPT-5.4-nano** 上，平均準確率（average accuracy）提升 **4.01%**。
- 在 **GPT-5.4** 上，平均準確率提升 **1.76%**。
- 實驗涵蓋兩種不同的 LLM、兩種不同的執行框架（harness）以及五種基準測試設定。

**1. 結果的意涵**

提升幅度在 GPT-5.4-nano 上明顯高於 GPT-5.4，這與方法論的動機高度一致：圖結構技能（graph-structured skill）透過顯式的工作流程層級指引（workflow-level guidance），對能力較弱的模型幫助更大。這些模型在處理冗長、非結構化的自然語言指令（natural-language instruction）時更容易迷失方向，而圖結構能夠將其注意力引導至當前步驟所需的指引。

在較強的 GPT-5.4 上，1.76% 的提升雖然較小，但仍然顯示出 GraphSkillEvo 具有穩定的正向效果。這暗示即使在強模型上，結構化的程序性指引（procedural guidance）仍能帶來邊際效益，尤其是在需要多步推理或複雜任務（complex task）的基準測試中。

**2. 跨基準測試的一致性**

結果強調 GraphSkillEvo「一致性地（consistently）」優於 SkillOpt，這表示其優勢並非來自於單一任務的過度擬合（overfitting），而是具有某種程度的泛化性（generalization）。這對於技能的跨模型可攜性（cross-model portability）尤為重要，因為技能作為可重複使用（reusable）的提示層級自然語言產物（prompt-level natural-language artifact），其價值在於能夠在不同模型與應用之間遷移。

**3. 需要注意的解讀限制**

由於目前僅能看到摘要與部分引言，尚無法取得完整的實驗表格，因此以下問題仍有待檢視：

- 五個基準測試的任務類型與難度分佈為何？
- 提升是否集中在特定類型的任務（例如需要多步規劃的任務）？
- 驗證集（validation set）與測試集（test set）的劃分方式是否會影響結果的穩健性？
- 是否有進行消融實驗（ablation study）以區分圖結構表徵與族群式演化各自的貢獻？

#### 與現有研究的比較

GraphSkillEvo 與現有技能最佳化（skill optimization）研究相比，主要差異體現在「表徵形式」與「最佳化策略」兩個維度。

**1. 與 SkillOpt 的比較**

SkillOpt 是代表性的技能最佳化基線，其流程為：從初始技能出發，在訓練集上執行、收集軌跡、由 LLM 生成文字修補（textual patch）、應用於當前技能，並在驗證集上決定是否接受更新。這是一種「單一軌跡、單一候選」的迭代式自我精煉（iterative self-refinement）。

GraphSkillEvo 相對於 SkillOpt 的改進包括：

- **表徵改進**：將技能從非結構化自然語言指令轉換為圖結構技能，提供明確的工作流程層級指引。
- **搜尋策略改進**：維護多個候選技能，透過突變運算子（mutation operator）與交配運算子（crossover operator）進行族群式探索，而非僅依賴單一 LLM 的局部修補。
- **冗餘降低**：圖結構減少了表徵變體（representational variant）所帶來的無效搜尋，使最佳化過程更聚焦於實質的程序性改變。

**2. 與其他技能最佳化方法的比較**

- **EvoSkill**：透過迭代式失敗分析與帕雷托選擇（Pareto-based selection）來發現與精煉技能。GraphSkillEvo 同樣使用演化計算（evolutionary computation），但更強調圖結構表徵與結構感知運算子。
- **Trace2Skill**：將多個執行軌跡修補合併為單一可攜式技能（portable skill）。GraphSkillEvo 則進一步將技能組織為圖，並透過族群演化進行全局探索。
- **SkillX**：從執行軌跡中提取多層次技能並建立技能庫（skill library）。GraphSkillEvo 目前聚焦於單一任務的技能最佳化，未來可與技能庫概念結合。

**3. 定位與貢獻**

GraphSkillEvo 的定位介於「提示工程（prompt engineering）」與「自動化程序學習（automated procedure learning）」之間。它保留了自然語言的靈活性與可解釋性，同時引入了圖結構的組合性與可最佳化性。這對於需要跨模型可攜性（cross-model portability）的應用場景特別有價值。

**4. 現有方法的限制**

儘管 GraphSkillEvo 具有明顯優勢，仍存在一些潛在限制：

- **圖結構的複雜性**：相較於純文字指令，圖結構技能可能需要更複雜的解析與執行機制，增加了執行框架（harness）的設計負擔。
- **演化計算的成本**：維護族群並進行多次評估需要大量的 LLM 呼叫，計算成本可能顯著高於單一技能的迭代式精煉。
- **對 LLM 能力的依賴**：突變與交配運算子本質上仍由 LLM 執行，若 LLM 無法正確理解圖結構語義，則可能產生無效或矛盾的修改。
- **圖的合法性問題**：目前尚不清楚 GraphSkillEvo 如何保證演化後的圖不會出現循環（cycle）、死路（dead end）或語義不一致的轉移。
- **最佳化範圍限制**：根據問題定義，GraphSkillEvo 僅最佳化技能產物（skill artifact），而固定 LLM 參數與執行框架。這意味著其上限仍受制於底層模型的能力。

#### 可重現性評估

**1. 程式碼開放性**

論文明確指出原始碼已公開於 GitHub：`https://github.com/ruisun7/GraphSkillEvo`。這是提升可重現性（reproducibility）的正面訊號，其他研究者可以檢視實作細節、執行環境設定以及超參數配置。

**2. 資料集與模型**

- **資料集**：實驗使用五個智慧體基準測試（agent benchmark），但摘要中未詳細列出其名稱。由於這些通常是公開資料集（如 WebShop、HotpotQA、ScienceWorld 等常見 agent benchmark），原則上應可重現。
- **模型**：實驗使用 GPT-5.4-nano 與 GPT-5.4。需要注意的是，這些模型名稱可能對應於未來或特定 API 版本，研究者需確認其公開可用性與 API 穩定性。
- **模型權重**：由於使用的是閉源商業 API（如 OpenAI API），模型權重（model weights）並不公開，這是當前 LLM 研究的常態，但會對完全可重現性造成一定限制。

**3. 可重現性的潛在挑戰**

- **LLM 的非確定性**：即使使用相同提示與資料，LLM API 的溫度參數（temperature）與抽樣機制可能導致結果波動。
- **演化過程的隨機性**：族群初始化、突變與交配的隨機性可能使不同執行之間存在差異，需要多次實驗並報告標準差。
- **圖結構的解析器依賴**：重現 GraphSkillEvo 需要正確實作圖結構技能的解析與執行邏輯，這部分細節在公開程式碼中應有說明。

整體而言，GraphSkillEvo 的可重現性處於「中等偏上」水準：程式碼已公開，資料集與模型原則上可取得，但仍受商業 API 與隨機性影響。

#### 未來研究方向

GraphSkillEvo 開啟了多個值得後續探索的研究方向：

**1. 階層式圖結構技能（Hierarchical Graph-Structured Skills）**

目前的圖結構技能可能是扁平的。未來可引入階層式結構，讓高層節點代表抽象目標，低層節點代表具體操作，進一步提升對複雜任務（complex task）的處理能力。

**2. 多目標最佳化（Multi-Objective Optimization）**

除了準確率（accuracy）之外，技能的長度、執行成本、可解釋性（interpretability）與跨模型可攜性（cross-model portability）都可納入最佳化目標。未來可結合帕雷托最佳化（Pareto optimization）來探索不同取捨。

**3. 圖結構的語法與語義驗證**

發展自動化機制以驗證演化後的圖是否合法（無循環、無死路）且語義一致，並在突變與交配過程中施加結構約束，可提升最佳化的穩定性與效率。

**4. 跨任務與跨領域遷移**

GraphSkillEvo 目前針對單一任務進行最佳化。未來可研究如何將一個任務上學到的圖結構技能遷移到相關任務，甚至建立可共享的圖結構技能庫（skill library）。

**5. 與符號規劃（Symbolic Planning）的結合**

圖結構技能本質上與規劃領域的狀態轉移圖有相似之處。未來可探索將符號規劃技術與 LLM 驅動的演化最佳化結合，以提升技能的正確性與可驗證性。

**6. 人機協作的最佳化（Human-in-the-Loop Skill Evolution）**

讓領域專家能夠在演化過程中介入，例如標註關鍵節點、修正錯誤轉移或提供高層設計原則，可加速收斂並提升技能品質。

**7. 線上適應（Online Adaptation）**

目前的最佳化是離線進行於固定的訓練集與驗證集。未來可研究如何在部署後根據新的執行軌跡持續調整圖結構技能，以適應動態變化的任務環境。

**8. 理論分析搜尋空間**

對圖結構技能空間的大小、冗餘度與演化運算子的覆蓋能力進行理論分析，有助於理解 GraphSkillEvo 為何有效，並指導更高效的演算法設計。

## 論文問答

**Q1：技能最佳化試圖解決什麼問題？為何人工撰寫或一次性 LLM 生成的技能仍不足夠？**

A：技能最佳化旨在針對特定任務，反覆精煉提供給 LLM 智慧體的程序性指引，以提升其解題表現。人工撰寫的技能或一次性 LLM 生成的技能往往不完整且脆弱，容易遺漏邊界情況、缺乏細緻的操作規則，並在不同實例上表現不穩定。因此，需要透過執行軌跡的回饋來迭代更新技能，使其更能因應真實任務的複雜需求。

**Q2：現有技能最佳化方法存在哪些根本性挑戰？**

A：現有方法通常將技能視為非結構化的自然語言指令，導致兩大問題。首先，非結構化技能常以冗長的檢查清單或條列式指令呈現，缺乏明確的工作流程層級指引，使智慧體難以判斷當前應遵循哪條規則以及下一步該做什麼，這對能力較弱的模型尤其嚴重。其次，由於相似的工作流程可以用多種不同的文字表達，搜尋空間既龐大又充滿表徵冗餘，讓最佳化過程難以有效探索真正有意義的程序變化。

**Q3：為什麼將技能表示為圖結構化產物具有重要價值？**

A：圖結構技能能將執行步驟與情境相依轉移明確化，使工作流程一目了然，從而改善智慧體的執行能力。同時，圖結構透過節點與有向邊組織步驟間的依賴關係，減少了非結構化文字中的表徵冗餘，縮小了搜尋空間。此外，技能所編碼的程序知識具有跨模型可攜性，當底層 LLM 更新或替換時，結構清晰的工作流程更容易被保留與重複使用。

**Q4：GraphSkillEvo 提出的「圖結構技能」具體是如何定義的？**

A：在圖結構技能中，每個節點代表一個智慧體執行步驟，並包含該步驟所需的獨立完整操作指引，例如指令、規則與輸出限制。每條有向邊則代表不同任務條件下步驟之間的情境相依轉移，允許智慧體根據中間結果選擇不同的執行路徑。這種表示方式類似流程圖，能將原本隱含在長篇文字中的工作流程顯式化，讓智慧體更容易遵循。

**Q5：GraphSkillEvo 的核心框架如何運作？**

A：GraphSkillEvo 是一個族群式演化最佳化框架，會同時維護多個候選技能以保留多樣性。它透過結構感知突變運算子，根據個別技能的執行軌跡來修正節點或邊的內容；並透過交配運算子，從不同候選技能中重組互補且有效的圖元件。這種族群導向的演化機制比單一技能的迭代式自我精煉能進行更廣泛且全面的搜尋。

**Q6：為何選擇演化式方法而非純粹的 LLM 自我精煉？結構感知運算子的設計考量為何？**

A：純粹的 LLM 自我精煉通常只維護單一技能，容易陷入局部最佳，而族群式方法能同時保留多個高品質候選，避免過早收斂。結構感知運算子則是針對圖結構搜尋空間設計：突變利用執行軌跡回饋精準修改特定步驟，交配則在圖拓樸層面合併不同候選的優勢子結構。這樣的設計能充分利用圖結構帶來的緊湊搜尋空間，提升最佳化效率。

**Q7：實驗在哪些設定下進行？使用了哪些基準與模型？**

**Q9：突變與交配運算子各自對整體表現可能貢獻什麼？**

A：突變運算子根據執行軌跡中的錯誤或不足，對單一技能的節點內容與邊轉移進行局部修正，有助於逐步提升現有候選的品質。交配運算子則能將來自不同候選技能的有效元件組合在一起，產生原本單一譜系難以達到的新穎工作流程。兩者相輔相成，加上族群維護機制，共同避免了過早收斂並促進更全面的探索。

**Q10：GraphSkillEvo 在哪些實際應用場景中特別有潛力？**

A：圖結構技能特別適合具有多步驟、條件分支與工具呼叫的複雜任務，例如客戶服務對話流程、資料分析管線、醫療診斷輔助或軟體測試流程。在這些場景中，智慧體需要根據中間結果決定下一步動作，而圖結構能清楚編碼這些情境相依轉移。此外，由於技能可重複使用，企業在更換底層模型時能保留已累積的程序知識，降低維護成本。

**Q11：若將 GraphSkillEvo 應用於產品開發，需要考量哪些部署與維護因素？**

**Q12：這項研究可能對 LLM 智慧體與技能最佳化領域帶來什麼影響？**

A：本研究將技能表示從扁平自然語言文字推向結構化圖形產物，為提示工程與程序知識編碼開啟新的研究方向。它連結了流程圖、程式合成與 LLM 智慧體的工作流程設計，使技能更像可執行的高階程序。未來可能催生更多結構感知最佳化演算法，並促進自動化、可驗證且可重複使用的智慧體技能庫發展。

**Q13：GraphSkillEvo 可能存在哪些限制或代價？**

A：雖然論文未明確列出所有限制，但族群式演化最佳化需要維護並評估多個候選技能，計算成本顯著高於單一技能的迭代式精煉。此外，圖結構雖然適合程序性任務，但對於高度開放、創意導向或無明確步驟順序的對話任務，強制使用圖結構可能反而造成限制。最後，突變與交配的品質仍依賴底層 LLM 產生修補建議，若修補模型能力不足，最佳化效果會受到影響。

- LLM 推論資源：需能呼叫目標 LLM（如 GPT-5.4-nano 或 GPT-5.4）進行技能執行與最佳化過程中的文本生成。

- 演化運算資源：由於 GraphSkillEvo 維護多個候選技能並進行多輪突變與交配，需足夠的 API 配額與平行化評估能力。

**能力與知識前提**
- 提示工程經驗：能設計高品質的初始自然語言指令。
- 圖結構設計能力：能將任務拆解為執行步驟，並定義節點與有向邊。
- 評估與指標設計：熟悉任務成效衡量，並能辨識過擬合風險。

### 實作步驟建議

1. **任務定義與成功指標設計**  
   明確界定智慧體需完成的複雜任務，並設計可量化的評分函式。此指標將決定 GraphSkillEvo 中候選技能的篩選標準。

2. **將現有技能轉換為圖結構技能**  
   無論是人工撰寫技能或一次性 LLM 生成技能，都應將其重構為圖結構化自然語言產物：每個節點包含獨立完整的操作指引，每條有向邊標示觸發條件與情境相依轉移。

3. **建置執行框架與軌跡收集機制**  
   確保智慧體能在給定技能下執行任務，並完整記錄執行軌跡。軌跡需包含節點進入順序、轉移條件與最終結果，作為後續突變的依據。

4. **初始化 GraphSkillEvo 族群**  
   產生多樣化的初始圖結構技能族群，可透過對初始技能進行結構變化（如增刪節點、重組邊）或針對不同任務條件設計專路子圖。

5. **執行演化最佳化循環**  
   反覆進行以下步驟：
   - 在訓練集上執行每個候選技能，收集執行軌跡。
   - 使用突變運算子根據軌跡修正個別技能。
   - 使用交配運算子重組來自不同候選技能的有效元件。
   - 在驗證集上評估新候選技能，保留表現較佳者進入下一代。

6. **最終驗證與部署**  
   選出驗證集表現最佳的圖結構技能，在獨立測試集上進行最終評估。通過後整合至生產環境，並建立版本控制與監控機制。

7. **持續監控與迭代精煉**  
   部署後持續收集真實世界執行軌跡，定期重新執行 GraphSkillEvo 或針對新任務條件擴充節點與邊，保持技能的跨模型可攜性與有效性。

### 潛在風險與注意事項

- **過擬合驗證集**  
  GraphSkillEvo 會在驗證集上不斷篩選候選技能，可能導致技能過度適應驗證資料。建議保留獨立測試集進行最終評估，並定期以新資料重新驗證。

- **圖結構過於複雜**  
  節點與有向邊過多會增加執行與最佳化難度，尤其對 GPT-5.4-nano 等較輕量模型。應定期檢視圖結構，合併冗餘節點、移除無效邊，維持工作流程層級指引的清晰度。

- **API 成本與延遲**  
  族群式演化需要多次呼叫 LLM 進行執行、突變與交配，可能產生顯著成本。建議先以小規模族群與少量訓練樣本進行實驗，再逐步擴大規模。

- **邊覆蓋不足**  
  若訓練資料未能涵蓋所有任務條件，某些情境相依轉移可能從未被觸發，導致技能在邊緣案例上表現不佳。應確保訓練集具備足夠的多樣性。

- **維護與可解釋性**  
  圖結構技能雖比非結構化技能更易理解，但經過多輪演化後仍可能變得難以維護。建議為每個節點與邊撰寫說明文件，並保留技能版本歷程。

- **多模型評測平台**

建議聚焦於適用場景、潛在風險與整合建議。理解 GraphSkillEvo 能為哪些產品流程帶來價值、需要哪些資料與運算資源，以及部署後如何持續監控與維護，將有助於評估導入時機與商業可行性。
