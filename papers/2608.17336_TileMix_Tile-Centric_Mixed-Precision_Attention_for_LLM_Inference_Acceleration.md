## ⚡ TL;DR

長上下文預填充的稠密自注意力計算與記憶體流量龐大，現有方法缺乏硬體對齊分數圖塊的空間精度路由。
TileMix 以位元遮罩將硬體對齊分數圖塊群組路由到 FP16/INT8 路徑並共享 softmax。
TileMix 在長上下文基準上恢復統一 INT8 的品質損失，提升 FP16 預填充吞吐量且無需訓練。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）中的長上下文預填充（Long-context prefill）會帶來大量計算與記憶體流量，因為稠密自注意力（Dense self-attention）需計算平方級的查詢-鍵值分數（Query-key scores）。現有方法要不是採用統一低精度路徑（Uniform low-precision path），就是選擇詞元交互作用（Token interactions），使得在硬體對齊的分數圖塊（Hardware-aligned score tiles）上進行空間精度路由（Spatial precision routing），仍無法納入融合稠密注意力（Fused dense attention）之中。我們提出 TileMix，一個以圖塊為中心的精度路由核心（Tile-centric precision-routing kernel），將數值精度（Numerical precision）轉化為融合稠密注意力內部、針對分數圖塊群組（Score-tile groups）可執行的空間決策。TileMix 將注意力矩陣（Attention matrix）劃分為硬體對齊的分數圖塊，把路由決策（Routing decisions）封裝為緊湊位元遮罩（Compact bitmasks），並將每個圖塊群組分派至 FP16 或 INT8 的分數計算路徑，兩種路徑均更新共享的線上 Softmax 狀態（Online-softmax state）。可擴展精度分組（Scalable precision grouping）讓每個路由位元（Routing bit）能夠控制多個相鄰鍵值圖塊（Adjacent key tiles），在長上下文下仍保留硬體對齊的計算圖塊與緊湊的中繼資料。透過對所有合法圖塊群組進行路由，TileMix 保留了稠密詞元連通性（Dense token connectivity），無需訓練，並支援分組查詢注意力（Grouped-query attention, GQA）、變長批次（Variable-length batches）以及 INT8 鍵值快取（INT8 key/value caches）。在 LLaMA、Qwen 與 Vicuna 上的 LongEval、LV-Eval 與 A100 預填充基準測試（A100 prefill benchmarks）中，TileMix 能夠恢復統一 INT8 下損失的長上下文品質，並相較於 FP16 提升預填充吞吐量（Prefill throughput），在不同模型系列間提供可控制的準確度-效率權衡邊界（Accuracy-efficiency frontier）。實作已公開於 https://github.com/HanzhiZhang-Ulrica/TileMix。

### 核心貢獻（3～5點）
- 提出以圖塊為中心的精度路由核心 TileMix，將數值精度轉化為融合稠密注意力內部、針對分數圖塊群組可執行的空間決策。
- 設計緊湊位元遮罩與可擴展精度分組機制，在長上下文下仍保留硬體對齊的計算圖塊與緊湊的中繼資料。
- 保留稠密詞元連通性，無需訓練，並支援分組查詢注意力、變長批次與 INT8 鍵值快取。
- 在 LLaMA、Qwen、Vicuna 等模型上驗證，相較於統一 INT8 恢復長上下文品質，並相較於 FP16 提升預填充吞吐量，提供可控制的準確度-效率權衡邊界。

### 適合對象
本論文適合從事大型語言模型推理加速、注意力機制量化與稀疏化，以及 GPU 核心優化的研究人員與工程師閱讀，特別是關注長上下文預填充效率與準確度權衡的讀者。

## 深度分析

#### 方法論解析

TileMix 的核心貢獻是將「數值精度（numerical precision）」從傳統的「張量層級」或「運算子層級」決策，轉化為「空間執行決策（spatial execution decision）」。具體而言，它把稠密自注意力（dense self-attention）的完整注意力矩陣（attention matrix）劃分為與 GPU Tensor Core 對齊的硬體對齊分數圖塊（hardware-aligned score tiles），並在融合稠密注意力（fused dense attention）的單一核心內，對每個分數圖塊群組（score-tile groups）動態選擇走 FP16 或 INT8 的運算路徑（arithmetic path）。

其執行流程可拆解為以下幾個環節：

1. **圖塊化與路由決策（tiling and routing decisions）**  
   對於每個查詢圖塊（query tile），TileMix 會載入一個緊湊位元遮罩（compact bitmask）。遮罩中的每一個位元（routing bit）對應一組相鄰鍵值圖塊（adjacent key tiles）的精度選擇。這種「可擴展精度分組（scalable precision grouping）」讓單一位元可以一次控制多個相鄰鍵值圖塊，從而在長序列（long context）下維持極小的中繼資料（metadata）開銷，同時仍保留底層硬體對齊的計算圖塊。

2. **常數時間內部迴圈查詢（constant-time inner-loop lookup）**  
   在 FlashAttention 風格的串流迴圈（streaming loop）中，TileMix 透過位元運算解碼每個鍵值圖塊群組（key-tile group）該使用 FP16 或 INT8。由於遮罩是緊湊打包的，解碼動作可在常數時間內完成，不會因序列長度增加而膨脹，這對長上下文預填充（long-context prefill）的延遲至關重要。

3. **異構分數計算與共享線上 Softmax 狀態（shared online-softmax state）**  
   被路由到 INT8 路徑的圖塊會先經過 rescaling，再與 FP16 路徑的輸出對齊到共同的分數域（common score domain）。兩條路徑隨後更新同一個線上 Softmax 狀態（online-softmax state），包括逐列最大值（row-wise maximum）、正規化因子（normalizer）與輸出累加器（output accumulator）。這樣的設計讓異構精度計算能夠無縫整合進單一融合核心，避免多次啟動核心（kernel launch）所帶來的額外 I/O 與同步開銷。

4. **保留稠密詞元連通性（dense token connectivity）**  
   不同於稀疏注意力（sparsity-based attention）會移除部分詞元交互作用（token interactions），TileMix 會「路由所有合法圖塊群組（route all legal tile groups）」，因此完整注意力圖（attention graph）得以保留。這意味著它不需要重新訓練模型，也不會因為丟棄注意力邊而損失長距離依賴。

5. **實用推論特性**  
   論文強調 TileMix 支援分組查詢注意力（grouped-query attention, GQA）、變長批次（variable-length batches）以及 INT8 鍵值快取（INT8 key/value caches）。這些都是實際 LLM 服務化（serving）場景中的剛性需求，顯示該方法並非僅是理論設計，而是針對生產環境的推論加速。

總結來說，TileMix 把「精度」視為一種可在空間上調度的資源，透過硬體對齊的圖塊為單位，在 FP16 與 INT8 之間做細粒度、可擴展、無訓練（training-free）的混合精度調度。

#### 實驗數據解讀

論文在 LongEval、LV-Eval 以及 A100 預填充基準測試（A100 prefill benchmarks）上，針對 LLaMA、Qwen 與 Vicuna 等模型家族進行評估。雖然提供的上下文未列出完整數值表格，但從摘要與引言可歸納出以下實驗結論與其意涵：

1. **長上下文品質恢復**  
   均勻 INT8 注意力（uniform INT8 attention）通常會因為數值誤差累積而損失長上下文品質。TileMix 透過在關鍵分數圖塊保留 FP16、在數值較不敏感區域使用 INT8，能夠「恢復（recover）」這些品質損失。這顯示精度路由策略有效區分了注意力矩陣中對輸出品質敏感與不敏感的區域。

2. **預填充吞吐量優於 FP16**  
   TileMix 在 A100 上的預填充吞吐量（prefill throughput）超過純 FP16 執行。這來自於兩方面：一是 INT8 路徑提升了算術吞吐量並降低記憶體頻寬需求；二是融合核心（fused kernel）減少了資料移動（data movement）與核心啟動次數。由於預填充階段的計算複雜度為 \(O(L^2)\)，任何能降低實際運算量與記憶體流量的方法都會帶來顯著加速。

3. **可控的準確度—效率權衡邊界（accuracy-efficiency frontier）**  
   TileMix 提供了一個可在 FP16 與均勻 INT8 之間連續調整的權衡邊界。透過改變路由遮罩中 FP16 與 INT8 的比例，使用者可以根據應用場景選擇更高的準確度或更高的效率。這對於需要服務等級協議（SLA）的部署特別重要。

4. **跨模型家族的泛化性**  
   實驗涵蓋 LLaMA、Qwen、Vicuna 等不同架構與訓練來源的模型，顯示 TileMix 的路由機制具有相當的泛化能力，並非僅對單一模型家族有效。

5. **數值分析與品質指標**  
   論文提到進行了「數值分析（numerical analyses）」，這通常包括最大誤差、相對誤差、Softmax 輸出分佈偏差、以及下游任務（如長文本檢索與問答）的準確率。這類分析有助於驗證混合精度路徑在共享線上 Softmax 狀態下不會因精度轉換而產生系統性偏差。

整體而言，實驗設計同時關注「效率指標」（吞吐量、延遲）與「品質指標」（長上下文檢索、問答準確率），符合一篇推論加速論文應有的嚴謹性。

#### 與現有研究的比較

論文將現有方法歸納為三大方向：低精度量化（quantization）、I/O 感知融合注意力（IO-aware fused attention）與結構化稀疏性（structural sparsity）。TileMix 與這些方向的關係可從以下角度理解：

1. **相較於均勻低精度量化**  
   傳統 INT8 量化（如 Xiao et al., 2023；Zhang et al., 2025）通常對整個運算子或張量使用單一精度。這種「統一低精度路徑（uniform low-precision path）」雖然實作簡單，但無法針對注意力矩陣內部不同區域的數值敏感度做區分。TileMix 的改進在於把精度決策細分到圖塊層級，並在單一核心內混合兩種精度，從而達到比均勻 INT8 更好的品質，同時仍享有大部分 INT8 的效率優勢。

2. **相較於稀疏注意力**  
   稀疏或區塊注意力方法（如 Yuan et al., 2026；Zaheer et al., 2021；Beltagy et al., 2020）透過選擇活躍詞元交互作用（active token interactions）來降低計算量，但會改變注意力圖的拓撲結構，通常需要重新訓練或微調，且可能遺失長距離依賴。TileMix 不丟棄任何合法交互作用，因此保留了稠密詞元連通性（dense token connectivity），屬於「無訓練（training-free）」部署方案。

3. **相較於 I/O 感知融合注意力**  
   FlashAttention（Dao et al., 2022）等融合核心透過硬體對齊圖塊與線上 Softmax 減少記憶體流量，但其內部仍使用統一的分數計算路徑。TileMix 進一步在融合核心內部引入異構精度路徑，並讓兩條路徑共享線上 Softmax 狀態。這是方法論上的延伸：從「統一運算路徑的融合」進展到「多精度運算路徑的融合」。

4. **相較於近期量化注意力核心**  
   近期研究（Chen et al., 2024；Kang et al., 2024；Zhang et al., 2025；Sharratt, 2026）也嘗試將低精度分數計算、數值近似與值聚合整合進融合執行。然而，這些方法大多在張量或運算子層級決定格式，並未將「空間精度路由（spatial precision routing）」作為核心抽象。TileMix 的獨特之處在於把路由決策嵌入到分數圖塊群組，並以緊湊位元遮罩實現常數時間查詢。

5. **限制與潛在弱點**  
   儘管 TileMix 具有上述優勢，仍有幾點值得注意：
   - **路由策略的來源**：論文強調無需訓練，但如何決定哪些圖塊走 FP16、哪些走 INT8 的「路由策略（routing policy）」並未在提供的上下文中詳細說明。若策略依賴啟發式或校準（calibration），則在不同任務或分佈偏移下可能需要額外調校。
   - **硬體特定性**：目前實作聚焦於 A100 與 Tensor Core，對於其他架構（如 AMD GPU、TPU、或新世代 FP8 Tensor Core）的適配性仍需驗證。
   - **遮罩儲存與傳輸**：雖然論文聲稱中繼資料為 \(O(H_q T_m)\)，但在極長序列或極小圖塊下，遮罩本身仍可能成為不可忽略的開銷。
   - **與稀疏方法的效率上限**：由於 TileMix 保留所有合法交互作用，其計算量下限仍為稠密注意力的計算量，無法像稀疏方法那樣達到次二次（sub-quadratic）複雜度。

#### 未來研究方向

1. **自適應與學習式路由策略**  
   目前 TileMix 的路由決策似乎是基於某種啟發式或靜態策略。未來可探索根據輸入序列動態生成遮罩的自適應機制，甚至引入輕量級學習模型來預測每個圖塊的最佳精度，以進一步逼近 FP16 品質並最大化 INT8 使用率。

2. **擴展到更多數值格式**  
   除了 FP16 與 INT8，未來可納入 FP8、INT4、或自訂浮點格式（custom floating-point formats）。這將使精度—效率權衡邊界更加豐富，但也會增加共享線上 Softmax 狀態的數值管理難度。

3. **與稀疏注意力協同**  
   TileMix 目前保留稠密連通性。未來可研究「精度路由 + 稀疏性」的混合策略：在注意力分數極低的區塊直接跳過計算，同時對其餘區塊進行 FP16/INT8 路由，以突破稠密計算的效率上限。

4. **多 GPU 與序列平行（sequence parallelism）整合**  
   當序列長度持續增加，單一 GPU 的記憶體與計算資源將成為瓶頸。將 TileMix 的路由遮罩與分散式注意力（如 Ring Attention、DistAttention）結合，可支援更長的上下文。

5. **硬體架構共同設計**  
   目前設計針對 NVIDIA A100 Tensor Core。未來可針對支援 FP8 或專用稀疏單元的下一代 GPU（如 H100、B200、或 Blackwell 架構）重新設計圖塊大小與位元遮罩格式，以發揮新硬體特性。

6. **理論誤差界限與品質保證**  
   建立 TileMix 混合精度注意力相對於 FP16 的誤差上界，並在特定條件下給出品質保證，將有助於在對數值穩定性敏感的應用（如科學計算、程式碼生成）中安全部署。

7. **校準-free 與零樣本路由**  
   若未來能發展出無需任何校準資料即可決定路由遮罩的機制，將大幅降低部署門檻，並提升方法在動態環境中的實用性。

8. **與推論系統其他層級的聯合優化**  
   TileMix 專注於注意力核心。未來可將其與量化權重、壓縮 KV cache、推測解碼（speculative decoding）、以及排程器（scheduler）結合，形成端到端的 LLM 推論加速方案。

## 論文問答

**Q1：長上下文預填充階段的主要計算瓶頸是什麼？**

A：在大型語言模型的長上下文預填充階段，主要的計算瓶頸來自於稠密自注意力機制需要計算所有查詢與鍵值詞元之間的配對分數，其計算複雜度相對於序列長度呈現二次方成長。這種 O(L²) 的查詢-鍵值分數運算不僅帶來龐大的算力需求，也造成顯著的記憶體流量壓力，使得長文件處理與檢索增強生成等應用難以高效執行。因此，如何在保持模型品質的前提下降低注意力運算成本，成為實用化長序列推論的核心挑戰。

**Q2：現有的加速方法為何無法充分解決長上下文注意力的效率問題？**

A：現有方法主要分為統一低精度量化、稀疏注意力與 I/O 感知融合注意力三類，但各自存在限制。統一低精度路徑在整個注意力運算中使用單一數值格式，難以針對不同區域的數值敏感度進行調整，容易在長上下文場景中損失品質。稀疏或區塊注意力則透過選擇性詞元交互作用減少計算，但會改變稠密詞元連通性；而現有的融合注意力核心雖然善用硬體對齊的分數圖塊來優化資料搬移，卻仍維持單一的運算路徑，未能將空間精度路由納入串流迴圈內部。

**Q3：為何高效處理長上下文對現代大型語言模型如此重要？**

A：現代大型語言模型越來越依賴長上下文來完成文件摘要、多頁問答與檢索增強生成等任務，這些應用都需要模型在一次前向傳播中處理大量詞元。若預填充階段效率不足，不僅會延長使用者等待時間，也會限制可處理的上下文長度，進而影響應用場景的實用性與使用者體驗。因此，開發能同時維持準確度與吞吐量的長上下文推論技術，是讓大型語言模型真正落地於知識密集型工作的關鍵。

**Q4：TileMix 的核心方法是如何運作的？**

A：TileMix 是一個以圖塊為中心的精度路由核心，它將注意力矩陣劃分為硬體對齊的分數圖塊，並針對每個分數圖塊群組決定要使用 FP16 或 INT8 運算路徑。這些路由決策被編碼成緊湊位元遮罩，在核心內部透過常數時間的位元操作解碼，從而將不同精度路徑整合到單一 FlashAttention 風格的融合執行流程中。透過這種設計，TileMix 能在同一個串流計算中靈活調度高精度與低精度運算，而不需要犧牲稠密注意力完整的詞元連通性。

**Q5：TileMix 相較於既有量化與融合注意力方法的關鍵創新是什麼？**

A：TileMix 的關鍵創新在於將「數值精度」轉化為可在融合稠密注意力內部執行的空間決策，而非僅在運算子或呼叫層級選擇單一格式。它讓 FP16 與 INT8 兩條異質運算路徑對齊到共同的分數域，並在經過縮放後共同更新同一個線上 Softmax 狀態，確保數值穩定性與輸出一致性。此外，可擴展精度分組機制讓單一路由位元能夠控制多個相鄰鍵值圖塊，在保持硬體對齊計算圖塊的同時，讓中繼資料隨著序列增長仍維持緊湊。

**Q6：為什麼 TileMix 選擇以「圖塊群組」與「位元遮罩」作為路由抽象？**

A：圖塊群組的設計能夠直接對應 GPU Tensor Core 的硬體對齊計算單元，確保不同精度路徑都能以規則且高效的方式執行，避免因不規則記憶體存取而損失效能。位元遮罩則提供極度緊湊的路由中繼資料表示法，使得核心在延遲敏感的內部迴圈中能以常數時間查詢每個群組的精度決策。可擴展精度分組進一步讓中繼資料量僅為 O(H T_m)，在長上下文下仍能有效控制記憶體與查詢開銷，這是將精度路由實際嵌入融合核心的必要條件。

**Q7：論文在哪些基準測試與模型上驗證 TileMix？**

A：論文在 LongEval、LV-Eval 以及 A100 預填充基準測試上進行評估，涵蓋長上下文檢索、問答與數值分析等面向。模型方面則選用了 LLaMA、Qwen 與 Vicuna 等不同模型家族，以驗證 TileMix 的泛用性與跨架構適用性。這樣的評估組合能同時檢視 TileMix 在長上下文品質恢復與實際推論吞吐量上的表現。

**Q8：TileMix 的主要實驗結果為何？**

A：實驗結果顯示，TileMix 能夠恢復統一 INT8 注意力在長上下文任務中損失的品質，同時相較於 FP16 提升預填充吞吐量，形成一條可控制的準確度-效率權衡邊界。這表示使用者可以根據延遲與品質需求，在不同精度配置之間彈性選擇，而不必受限於全高精度或全低精度的二元選項。跨 LLaMA、Qwen 與 Vicuna 的結果也顯示，TileMix 的效益具有模型家族間的一致性。

**Q9：論文進行了哪些數值或設計上的消融分析？**

A：論文透過數值分析驗證 FP16 與 INT8 路徑在共同線上 Softmax 狀態下整合的正確性與穩定性，並探討可擴展精度分組對中繼資料大小與硬體對齊的影響。此外，實作層面也驗證了 TileMix 對分組查詢注意力、變長批次與 INT8 鍵值快取的支援能力，這些都是實際部署場景中不可或缺的特性。這些分析共同說明 TileMix 不僅是理論上的精度路由框架，更是可直接整合至現代推論系統的核心設計。

**Q10：TileMix 最適合應用在哪些實際場景？**

A：TileMix 特別適合需要處理長輸入序列的應用，例如長文件摘要、多頁問答系統、檢索增強生成以及長對話紀錄理解等場景。在這些應用中，注意力矩陣龐大且不同區域的數值敏感度各異，透過圖塊級精度路由可以在不遺失重要詞元交互作用的前提下降低運算成本。由於 TileMix 不需要重新訓練模型，因此特別適合已部署的服務希望在不修改模型權重的情況下提升長上下文推論效率。

**Q11：在實際產品部署時，採用 TileMix 需要考慮哪些因素？**

A：首先，產品團隊需要評估目標硬體是否支援高效的 FP16 與 INT8 Tensor Core 路徑，因為 TileMix 的效益來自於異質精度運算的有效調度。其次，由於 TileMix 支援分組查詢注意力、變長批次與 INT8 鍵值快取，部署時可與現代推論優化技術疊加使用，但仍需根據目標任務調整精度路由策略以平衡延遲與品質。最後，因為 TileMix 無需訓練，整合門檻相對較低，但仍需進行充分的任務層級驗證，確保所選的精度配置不會影響關鍵應用的輸出品質。

**Q12：TileMix 對大型語言模型推論領域可能帶來什麼影響？**

A：TileMix 將低精度量化與 I/O 感知融合注意力兩條研究路線結合起來，證明精度可以在融合核心的內部迴圈中作為空間決策被執行，而不僅是運算子層級的全局選擇。這為未來的推論核心設計開啟了新的可能性，使得模型可以在保持稠密注意力完整連通性的同時，根據輸入內容動態調整運算精度。這種以硬體對齊圖塊為單位的精度調度思維，也可能影響後續針對 FP8、INT4 或其他數值格式的混合精度注意力研究。

**Q13：TileMix 目前有哪些潛在的限制？**

A：雖然論文未明確列出所有限制，但從設計中可以推知，TileMix 的路由決策品質會直接影響最終的準確度與效率權衡，若路由策略不當，仍可能在某些敏感區域引入數值誤差。此外，由於核心需要同時支援 FP16 與 INT8 兩條 Tensor Core 路徑，其實作複雜度與硬體相依性較高，可能需要針對不同 GPU 架構進行調整。在極短序列的情境下，精度路由與位元遮罩查詢的額外開銷可能會抵銷部分效能增益，因此較不適合短上下文為主的工作負載。

**Q14：在什麼情況下 TileMix 可能表現不佳或失效？**

A：當注意力矩陣中存在大量對數值誤差極度敏感的區域，而路由策略又將這些區域分配給 INT8 路徑時，可能會導致明顯的品質下降。此外，若目標硬體的 INT8 Tensor Core 吞吐量或縮放支援不足，則異質精度調度的優勢將難以發揮，甚至可能因額外的資料轉換與狀態同步而降低效能。最後，對於序列長度很短、注意力運算本身不是瓶頸的場景，TileMix 引入的路由中繼資料與分支邏輯可能無法帶來可觀的加速，反而增加核心複雜度。

**Q15：未來可以從哪些方向延伸 TileMix 的研究？**

A：未來可以探索基於學習或啟發式的動態路由策略，讓精度分配能根據輸入內容與層級特性自動調整，而非依賴固定規則。另一個方向是將 TileMix 的圖塊級精度路由擴展至 FP8、INT4 等更低精度格式，或應用於解碼階段以進一步降低自迴歸生成的延遲。此外，結合多 GPU 或多節點的序列平行策略，以及與推測解碼、分頁注意力等技術整合，也是值得發展的後續研究方向。

## 實務應用指南

### 適用場景

1. **長文件摘要與法律／醫療文件分析**  
   當輸入動輒數萬詞元（tokens）的合約、病歷或研究報告時，TileMix 可在保留完整稠密詞元連通性的前提下，將部分查詢-鍵值分數（query-key scores）改以 INT8 計算，降低長上下文預填充（long-context prefill）的記憶體頻寬與運算壓力，同時維持關鍵事實抽取的準確度。

2. **檢索增強生成（RAG）的長提示預填充**  
   RAG 系統常把多篇檢索文件拼接成長提示。TileMix 以硬體對齊的分數圖塊（hardware-aligned score tiles）為單位進行 FP16/INT8 空間精度路由，能在不裁剪或稀疏化注意力圖（attention graph）的情況下加速預填充，適合需要保留所有文件片段關聯的問答與多跳推理場景。

3. **批次化長序列推理服務**  
   對於同時處理多條變長序列（variable-length batches）的線上 API 或聊天機器人後端，TileMix 支援分組查詢注意力（GQA）與 INT8 鍵值快取（INT8 KV cache），可在單一融合核心內動態調度不同精度路徑，提升 A100 等 GPU 的預填充吞吐量（prefill throughput）。

4. **邊緣或私有部署的資源受限環境**  
   在記憶體與算力有限的資料中心或企業內部叢集，TileMix 提供介於 FP16 與統一 INT8 之間的可控準確度-效率權衡邊界（accuracy-efficiency frontier），讓維運團隊依任務敏感度選擇路由閾值，而非直接犧牲模型品質。

5. **多語言長文本模型（如 Qwen、LLaMA、Vicuna）的推理加速**  
   TileMix 無需訓練即可跨模型家族部署，特別適合已採用 INT8 權重或啟動量化、但仍希望降低注意力運算開銷的多語言應用。

### 實作前置條件

**資料與模型**
- 已具備支援 CUDA 與 Tensor Core 的 NVIDIA GPU（論文基準測試使用 A100；建議至少 Ampere 架構以上）。
- 目標模型需為 LLaMA、Qwen、Vicuna 等基於稠密自注意力（dense self-attention）的解碼器架構，並已支援分組查詢注意力（GQA）。
- 若計畫啟用 INT8 鍵值快取，需確認現有推理框架支援 INT8 KV cache 的載入與儲存格式。

**運算環境**
- CUDA Toolkit 與 PyTorch 開發環境，並能編譯客製化 CUDA kernel。
- 足夠的 GPU 記憶體以容納長序列與 bitmask 路由中繼資料（論文指出中繼資料量為 O(H T_k / m)，其中 m 為群組大小，通常極小）。

**技能需求**
- 熟悉 FlashAttention 或類似 I/O 感知融合注意力（IO-aware fused attention）核心的運作原理。
- 具備 CUDA / Triton kernel 開發或除錯經驗，能理解 FP16 與 INT8 Tensor Core 路徑的縮放（rescaling）與線上 Softmax 狀態（online-softmax state）整合。
- 能執行長上下文評測基準（如 LongEval、LV-Eval）以驗證品質退化。

### 實作步驟建議

1. **建立基線與品質指標**  
   在目標任務上先測量 FP16 與統一 INT8 注意力的預填充延遲、吞吐量與 LongEval / LV-Eval 分數，作為後續比較基準。

2. **決定路由策略與群組大小**  
   依任務敏感度選擇「哪些分數圖塊群組（score-tile groups）走 FP16、哪些走 INT8」。論文使用可擴展精度分組（scalable precision grouping），讓單一路由位元（routing bit）同時控制多個相鄰鍵值圖塊（adjacent key tiles）。建議從較大群組（例如每個 bit 控制 4–8 個 key tiles）開始，降低中繼資料與分支開銷。

3. **產生緊湊位元遮罩（compact bitmasks）**  
   根據選定的啟發式或校準統計（如分數圖塊內的數值範圍、離群值比例），為每個查詢圖塊列（query-tile row）產生 packed routing word。確保 bitmask 查詢在核心內迴圈（inner loop）為常數時間。

4. **整合融合核心**  
   將 TileMix 核心嵌入現有 FlashAttention 風格的串流迴圈（streaming loop）：載入 Q/K/V 圖塊、解碼 bitmask、依決策將 QK 計算分派至 FP16 或 INT8 Tensor Core 路徑，並在縮放後讓兩條路徑更新共享的線上 Softmax 狀態與輸出累加器。

5. **啟用 GQA、變長批次與 INT8 KV cache**  
   確認核心能處理分組查詢注意力與變長批次；若使用 INT8 KV cache，驗證載入／儲存時的縮放因子與 TileMix 內部 INT8 分數路徑一致。

6. **端到端驗證與微調**  
   在 LongEval、LV-Eval 及自有業務資料上比較 TileMix 與 FP16/INT8 基線。若品質下降過多，縮小精度群組或提高 FP16 路由比例；若吞吐量未達預期，檢查 bitmask 解碼與記憶體合併存取是否造成額外延遲。

7. **部署與監控**  
   將核心包裝為 vLLM、TensorRT-LLM 或自研推理引擎的客製化 attention backend，並在生產環境持續監控 perplexity、長上下文檢索正確率與延遲分佈。

### 潛在風險與注意事項

- **數值精度漂移**  
  INT8 分數路徑可能因縮放誤差或離群值導致 Softmax 歸一化偏差。建議在核心內保留 FP32 累加器進行線上 Softmax 狀態更新，並對 INT8 結果做適當 rescaling。

- **路由中繼資料開銷**  
  雖然 bitmask 已相當緊湊，但在超長序列（如 100K+ tokens）下仍需評估額外記憶體佔用。可透過增大 precision grouping 的 m 值來壓低中繼資料，但會犧牲細粒度。

- **核心分支與 warp 發散**  
  同一 warp 內若同時存在 FP16 與 INT8 分數圖塊，可能導致執行路徑發散。建議讓群組大小對齊 warp 執行單元，並在實作中讓整個 tile group 走相同精度。

- **任務相關的品質敏感區域**  
  某些長上下文任務對特定 token 交互作用（token interactions）極度敏感。建議以校準資料識別高影響力圖塊並強制走 FP16，而非僅依靜態啟發式。

- **與現有量化方案的相容性**  
  若模型已使用 INT4 權重或其他非對稱量化，需確認 TileMix 的 INT8 分數路徑與其縮放因子不衝突，必要時調整 kernel 介面。

---

### 與其他技術的整合建議

- **vLLM / TensorRT-LLM / SGLang**  
  可將 TileMix 實作為客製化 attention kernel，替換或並行於現有 FlashAttention backend。由於 TileMix 支援變長批次與 GQA，整合時主要需調整 page-based KV cache 的載入邏輯以配合分數圖塊對齊。

- **現有量化管線（AWQ、GPTQ、SmoothQuant）**  
  TileMix 專注於注意力分數運算路徑，可與權重／啟動量化疊加。建議讓 SmoothQuant 等校準統計同時提供離群值分佈，輔助 TileMix 的路由決策。

- **稀疏注意力與投機解碼**  
  雖然 TileMix 本身保留稠密詞元連通性，但可在預填充階段使用 TileMix，而在解碼階段搭配稀疏注意力或投機解碼（speculative decoding），形成分階段加速策略。

- **長上下文評測與可觀測性工具**  
  將 LongEval、LV-Eval 與自訂指標嵌入 CI/CD，並記錄每次路由比例變更對準確度與延遲的影響，作為線上 A/B 測試依據。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先理解「為何長上下文注意力很貴」——即序列長度 L 帶來 O(L²) 的查詢-鍵值分數計算，以及 FlashAttention 如何透過圖塊化與線上 Softmax 降低記憶體搬運。接著把 TileMix 想像成「在原本只能選全 FP16 或全 INT8 的計算中，加入一個依圖塊位置決定精度的開關」，不必一開始深入 CUDA 細節，重點放在它「保留所有詞元交互作用且無需訓練」的優勢。

**AI 工程師**  
請聚焦第 2–3 節的核心設計：硬體對齊分數圖塊、packed bitmask 路由、共享 online-softmax state 的 FP16/INT8 整合，以及可擴展精度分組如何壓低中繼資料。實作時應親自編譯並跑過論文提供的開源實作，比較不同群組大小與路由比例在 A100 上的延遲與 LongEval 分數，並注意 INT8 KV cache 與現有推理框架的介面銜接。

**研究人員**  
可從「空間精度路由」這個執行抽象出發，思考是否能將其擴展至其他數值格式（如 FP8、INT4）或與動態稀疏性結合。論文的貢獻在於把精度決策從張量／運算子層級下放到分數圖塊群組層級，未來可探索基於梯度或任務感知的路由學習，以及更細緻的理論誤差界限。

**產品經理**  
請把 TileMix 視為一個「可控的準確度-效率滑桿」：在需要高正確率的場景保留較多 FP16 分數圖塊，在成本敏感場景提高 INT8 比例。評估時應同時看預填充吞吐量與長上下文品質基準（LongEval、LV-Eval），並與工程團隊確認部署複雜度、維護成本，以及是否需客製化 CUDA kernel 才能接入現有推理服務。
