## 摘要翻譯

電商直播（E-Commerce Live Streaming）需要對帶有雜訊的長時間延展串流（Noisy, Temporally Extended Streams）進行全模態理解（Omni-Modal Understanding），其中產品事實（Product Facts）分散於主播語音（Host Speech）、影片影格（Video Frames）、產品圖像（Product Images）、疊加文字（Overlaid Text）與使用者查詢（User Queries）之中。我們提出 TLive-Omni，一個專為直播電商（Live-Commerce）情境設計的全模態理解模型（Omni-Modal Understanding Model），可將圖像、影片、音訊與文字輸入映射至統一表示空間（Unified Representation Space）。針對長篇直播串流分析（Long-Form Live Streaming Analysis），我們提出 Per-vGrid，一種帶時間戳記的 token 組織方式（Timestamped Token Organization），以明確的邊界 token（Boundary Tokens）將每個影片網格（Video Grid）與其時間對應的音訊歸為一組，以促進時間對齊（Temporal Alignment）。我們設計了三階段監督式訓練配方（Three-Stage Supervised Training Recipe），逐步培養直播電商理解能力，從全模態感知（Omni-Modal Perception）到遵循指令的回應（Instruction-Following Responses）。接著我們提出 Faithful-RFT，一個強化微調（Reinforcement Fine-Tuning, RFT）階段，在滿足即時需求（Real-Time Demands）的同時，進一步提升答案忠實度（Answer Faithfulness）與表達品質（Expression Quality），直接以任務可驗證回饋（Task-Verifiable Feedback）評分最終回應（Final Responses），而非在 rollout 過程中優化推理式探索（Reasoning-Style Exploration）。此外，TLive-Omni 以面向情境的原子能力分類法（Scenario-Oriented Atomic Capability Taxonomy）與精簡的資料生產引擎（Data Production Engine）為後盾，將直播電商的音訊、圖像與影片串流轉換為語音辨識（Speech Recognition）、說話者分析（Speaker Analysis）、產品視覺定位（Product Visual Grounding）、文字辨識（Text Recognition）、時間定位（Temporal Grounding）、影片密集字幕（Video Dense Caption）以及全模態問答（Omni-Modal QA）等訓練訊號（Training Signals）。為實現可擴展訓練（Scalable Training），同步化長度分組取樣器（Synchronized Length-Grouped Sampler）可減少填充（Padding），同時在工作節點（Workers）間維持相近的工作負載（Workloads）；而輕量動態取樣策略（Lightweight Dynamic Sampling Strategy）則以趨近零的獎勵變異數（Near-Zero Reward Variance）重新生成 rollout 群組（Rollout Groups），以維持 GRPO（Group Relative Policy Optimization）有意義的相對優勢（Relative Advantages）。在電商直播基準（Live-Commerce Benchmarks）上的實驗顯示，本模型在直播電商領域任務上表現優異，並在通用基準（General Benchmarks）上展現出色的泛化能力（Generalization）。

### 核心貢獻（3～5點）
- 提出 TLive-Omni，專為電商直播情境設計的全模態理解模型，統一處理圖像、影片、音訊與文字輸入。
- 提出 Per-vGrid 帶時間戳記的 token 組織方式，透過邊界 token 將影片網格與時間對應音訊歸為一組，強化長篇直播串流的時間對齊。
- 設計三階段監督式訓練配方，並提出 Faithful-RFT 強化微調階段，以任務可驗證回饋直接評分最終回應，提升答案忠實度與表達品質。
- 建立面向情境的原子能力分類法與資料生產引擎，系統化產生語音辨識、產品視覺定位、時間定位、影片密集字幕及全模態問答等訓練訊號。
- 提出同步化長度分組取樣器與輕量動態取樣策略，支援可擴展訓練並維持 GRPO 的相對優勢。

### 適合對象
適合從事多模態學習、直播電商應用、長影片理解、強化學習微調，以及大規模模型訓練系統的研究人員與工程師閱讀。

## 深度分析

#### 方法論解析

##### 1. 整體架構：以 Qwen3.5 為骨幹模型（Backbone）的全模態擴展
TLive-Omni 採用 **Qwen3.5** 作為語言與視覺骨幹模型（Backbone），並將 **Qwen3-Omni** 的預訓練音訊編碼器（Pretrained Audio Encoder），即 **AuT（Audio Transformer）**，透過輕量級音訊對齊器（Audio Aligner）嫁接到同一嵌入空間。這種設計的關鍵在於：視覺與語言已經在 Qwen3.5 內部高度整合，而音訊則作為一條額外輸入路徑被引入，並在後續監督式微調（Supervised Fine-Tuning, SFT）階段與骨幹模型進一步對齊。模型僅輸出文字（text-only output），這符合電商直播（E-Commerce Live Streaming）場景中對於即時回應與可控生成的需求。

視覺 token 的計算方式延續 Qwen3.5 的空間合併（Spatial Merging）機制：每張圖像產生 (h/32)×(w/32) 個視覺 token；每段取樣影片則產生 ⌈f/2⌉×(h/32)×(w/32) 個視覺 token，其中 f 為取樣影格數（Sampled Frame Indices）。這樣的壓縮比例讓模型能夠在 256K token 的長上下文（Long-Context Capacity）範圍內處理長時間直播串流。

音訊方面，AuT 在 2,000 萬小時音訊資料上從頭訓練，以 16kHz 的 128 維梅爾頻譜（Mel-Spectrogram）為輸入，將語音壓縮至約每秒 13 個 token。這對於動輒數分鐘的直播片段至關重要，因為它能在保留說話者身份（Speaker Identity）與副語言線索（Paralinguistic Cues）的同時，避免上下文預算被過度佔用。

##### 2. Per-vGrid：時間戳記 token 組織方式（Timestamped Token Organization）
本文最具技術特色的設計之一是 **Per-vGrid**，它解決了長篇直播串流分析（Long-Form Live Streaming Analysis）中音訊–影片對齊（Audio-Video Alignment）的問題。不同於過去將整段音訊與整段影片分別編碼後再拼接的做法，Per-vGrid 將影片網格（Video Grid）與覆蓋相同時間區間的音訊區段（Audio Span）放入同一個以邊界 token（Boundary Tokens）標記的區段（Span）內，並為每個網格加上文字時間戳（Textual Timestamp）。

更具體地說，Per-vGrid 的創新點包括：
- **明確的網格層級分組（Explicit Grid-Level Grouping）**：每個網格的視覺 token 與對應音訊 token 在輸入序列（Input Sequence）中相鄰，使模型能直接識別其對應關係。
- **真實取樣影格索引（Sampled Frame Indices）決定時間戳**：Per-vGrid 不依賴請求的取樣率（例如 2 FPS），而是根據實際取樣到的影格索引來計算每個網格的時間戳與音訊跨度。這在整數取樣導致實際取樣率偏離請求值時尤為重要。例如，119 影格、30 FPS 的影片若請求 2 FPS，實際取樣影格為 [0,20,39,59,79,98,118]，實際取樣率約為 1.76 FPS，每個完整網格約 1.13 秒，對應約 14–15 個音訊 token，而非理論上的 13 個。
- **序列層級的分隔**：相鄰網格之間在序列層級被明確分開，避免時間邊界模糊。

這種設計對於需要精確時間定位的任務（如時間定位 Temporal Grounding、影片密集字幕 Video Dense Caption、全模態問答 Omni-Modal QA）具有顯著優勢，因為模型可以直接從輸入結構中讀取「這段話出現在這個視覺區間」。

##### 3. 三階段監督式訓練配方（Three-Stage Supervised Training Recipe）
訓練分為三個漸進階段：
1. **全模態感知（Omni-Modal Perception）**：先建立對異質訊號（Heterogeneous Signals）的基本感知能力，包括語音辨識（Speech Recognition）、文字辨識（Text Recognition）、產品視覺定位（Product Visual Grounding）等。
2. **情境對齊與指令遵循（Instruction-Following Responses）**：將感知能力轉化為遵循指令的回應，結合直播電商（Live-Commerce）與通用多模態監督（General Multimodal Supervision）。
3. **強化微調（Reinforcement Fine-Tuning, RFT）**：透過 **Faithful-RFT** 進一步提升答案忠實度（Answer Faithfulness）與表達品質（Expression Quality）。

這種漸進式設計符合認知負載遞增原則：先學會「看、聽、讀」，再學會「回答問題」，最後學會「忠實且流暢地表達」。

##### 4. Faithful-RFT：以任務可驗證回饋（Task-Verifiable Feedback）為導向的強化微調
Faithful-RFT 是本文在強化學習層面的核心貢獻。其設計動機來自電商直播的兩個矛盾需求：
- **答案必須忠實於感知證據（Perception-Derived Answers）**：不能幻覺（hallucinate）產品事實（Product Facts）。
- **必須滿足即時需求（Real-Time Demands）**：不能為了推理而產生冗長的顯式思考軌跡（Explicit Think Traces）。

為此，Faithful-RFT 採取以下策略：
- **抑制顯式思考軌跡**：不同於一些推理模型在 rollout 過程中進行推理式探索（Reasoning-Style Exploration），Faithful-RFT 直接對最終回應（Final Responses）進行評分。
- **任務可驗證獎勵（Task-Verifiable Rewards）**：獎勵函數基於任務本身的可驗證性，例如 ASR 答案是否與轉錄一致、視覺定位框是否正確、時間定位是否準確等。
- **輕量動態取樣策略（Lightweight Dynamic Sampling Strategy）**：在 rollout 過程中，若某些回應群組（Response Groups）的獎勵變異數（Reward Variance）趨近零（Near-Zero Reward Variance），則動態重新取樣，以產生更高變異數的群組相對回饋，從而維持 GRPO（Group Relative Policy Optimization）所需的相對優勢（Relative Advantages）。此過程由 **vLLM** 提供生成加速。

這種設計的優點在於：它避免了為了探索而犧牲延遲，同時透過動態重取樣確保強化學習訊號不會退化。

##### 5. 資料生產引擎（Data Production Engine）與原子能力分類法（Atomic Capability Taxonomy）
TLive-Omni 圍繞一套面向情境的原子能力分類法（Scenario-Oriented Atomic Capability Taxonomy）建構，涵蓋音訊、圖像、影片與全模態理解四大領域，具體包括：
- 語音辨識（Speech Recognition）
- 說話者分析（Speaker Analysis）
- 產品視覺定位（Product Visual Grounding）
- 文字辨識（Text Recognition）
- 時間定位（Temporal Grounding）
- 影片密集字幕（Video Dense Caption）
- 全模態問答（Omni-Modal QA）

資料生產引擎（Data Production Engine）則將直播電商串流中的音訊、圖像、影片轉換為上述能力的訓練訊號（Training Signals）。這種模組化設計讓訓練資料能夠系統性地對應到各項原子能力，便於追蹤模型進步與診斷弱點。

##### 6. 可擴展訓練（Scalable Training）：同步化長度分組取樣（Synchronized Length-Grouped Sampling）
為了處理混合模態批次（Mixed-Modality Batches）中序列長度（Sequence Lengths）差異大的問題，作者提出同步化長度分組取樣（Synchronized Length-Grouped Sampling）。該方法將長度相近的樣本分組，以減少填充（Padding），同時確保各工作節點（Workers）之間的工作負載（Workloads）可比，從而提升訓練效率。這對於同時包含短圖像問答與長影片直播的批次尤為重要。

#### 實驗數據解讀

由於提供的全文脈絡未包含具體的實驗表格與數值，以下分析主要基於摘要與引言中的實驗宣稱，並指出解讀時應注意的幾個關鍵點。

##### 1. 評估面向
作者建構了一套內部直播電商評測套件（In-House Live-Commerce Evaluation Suite），涵蓋以下關鍵維度：
- **直播電商基準（Live-Commerce Benchmarks）**：驗證模型在電商直播情境下的原子能力，如產品視覺定位、時間定位、全模態問答等。
- **通用多模態與全模態基準（General-Purpose Multimodal and Omni Benchmarks）**：驗證模型的泛化能力（Generalization），避免過度擬合直播電商領域。

##### 2. 結果宣稱的意涵
摘要指出 TLive-Omni 在直播電商領域任務上表現強勁，同時在多個通用基準上取得領先結果，其餘則保持競爭力。這暗示：
- **領域特化未嚴重損害通用能力**：這是全模態模型微調中常見的權衡，作者透過混合通用多模態監督（General Multimodal Supervision）與三階段漸進訓練來緩解災難性遺忘（Catastrophic Forgetting）。
- **Per-vGrid 與 Faithful-RFT 的協同效應**：時間對齊（Temporal Alignment）的改善應直接反映在時間定位與影片密集字幕等任務上；而 Faithful-RFT 則應提升全模態問答的答案忠實度（Answer Faithfulness）。

##### 3. 解讀時需注意的問題
- **缺乏具體數值**：目前無法判斷「強勁」與「領先」的絕對差距。例如，在通用基準上領先多少百分點？在直播電商基準上相較於 Qwen3-Omni 或 Valley3 的相對提升是多少？
- **內部評測套件的透明度**：內部基準的資料收集方式、標註品質、測試集規模與難度分佈尚未揭露，這會影響結果的可比較性。
- **獎勵函數的細節**：Faithful-RFT 的任務可驗證獎勵（Task-Verifiable Rewards）如何設計？是否包含人工設計的規則、模型評判器（Model-Based Judge）或自動化指標？這些細節對於評估其穩健性至關重要。
- **即時性指標**：雖然論文強調即時需求（Real-Time Demands），但目前未見延遲（Latency）、吞吐量（Throughput）或每秒 token 數（Tokens Per Second）等數據。

##### 4. 預期應顯著的實驗趨勢
若完整論文公開，預期應觀察到：
- 在需要音訊–影片對齊的任務（如時間定位、影片密集字幕）上，使用 Per-vGrid 相較於無時間戳記或全局音訊拼接的基線有明顯提升。
- Faithful-RFT 相較於純 SFT 能減少幻覺（Hallucination），並提升表達流暢度，但可能對需要複雜多步推理的任務幫助有限。
- 同步化長度分組取樣（Synchronized Length-Grouped Sampling）應在訓練效率上帶來可量化的加速，例如減少 10–30% 的無效填充計算。

#### 與現有研究的比較

##### 1. 相較於通用全模態模型（General Omni Models）
TLive-Omni 與 **MiniCPM-o 4.5**、**Qwen3-Omni**、**OmniVinci**、**Nemotron3 NanoOmni** 等開源全模態模型（Open-Source Omni Models）的主要區別在於：
- **場景聚焦**：這些通用模型展示統一全模態互動（Unified Omni Interaction）的可行性，但其資料與評估並非以產品為中心的直播理解（Product-Centric Live Streaming Understanding）為核心組織。
- **時間對齊機制**：Qwen3-Omni 雖然也處理音訊與視覺，但 Per-vGrid 進一步引入文字時間戳（Textual Timestamp）、邊界 token（Boundary Tokens）與真實取樣影格索引（Sampled Frame Indices），使網格層級的對應關係更明確。
- **輸出形式**：TLive-Omni 為 text-only output，這使其更適合即時問答與檢索型任務，但可能不如支援多模態生成的模型靈活。

##### 2. 相較於電商導向系統
**Valley3** 是另一個朝向電子商務情境（E-Commerce Scenarios）擴展的模型，但作者指出 Valley3 並非主要圍繞細粒度原子能力（Fine-Grained Atomic Capabilities）與直播串流組織。TLive-Omni 的優勢在於：
- 明確的原子能力分類法（Atomic Capability Taxonomy），使能力建構與評估更系統化。
- 針對長時間直播串流的時間對齊與長上下文（Long-Context Capacity）設計。
- 透過 Faithful-RFT 強化答案忠實度，這對於電商場景中「不能說錯產品規格」的商業需求尤為關鍵。

##### 3. 主要改進與貢獻
- **Per-vGrid** 提供了一種可解釋且精確的音訊–影片對齊方式，特別適合幀取樣不規則的實際直播影片。
- **Faithful-RFT** 在強化微調（Reinforcement Fine-Tuning）中平衡了忠實度與即時性，並透過動態取樣維持 GRPO 的學習訊號。
- **資料生產引擎** 將直播串流系統性地轉化為多項原子能力的訓練訊號，降低了領域適應的資料工程成本。

##### 4. 潛在限制
- **模型規模與計算成本**：基於 Qwen3.5 骨幹並支援 256K token 上下文，推論與訓練成本可能較高，對於邊緣部署或低延遲直播互動構成挑戰。
- **Text-only output 的限制**：無法直接生成語音或視覺回應，限制了其在多模態互動（如語音客服、視覺化推薦）中的應用。
- **對音訊編碼器的依賴**：AuT 雖然強大，但直接繼承自 Qwen3-Omni，其對於直播電商中特定口音、背景噪音、多人對話的適應性可能需要更多領域資料驗證。
- **動態取樣的開銷**：雖然稱為輕量動態取樣策略（Lightweight Dynamic Sampling Strategy），但在大規模 rollout 中反覆重新取樣仍可能增加訓練時間與 vLLM 排程複雜度。
- **缺乏開源細節**：目前尚不清楚模型權重、訓練程式碼與資料集是否公開，這影響學術界進一步驗證與改進。

##### 1. 開源狀態

- 訓練程式碼（Training Code）
- 資料生產引擎（Data Production Engine）的實作
- 內部直播電商評測套件（In-House Live-Commerce Evaluation Suite）

這使得可重現性（Reproducibility）處於不確定狀態。若作者後續開源，將大幅提升該工作的影響力；若僅發表技術報告而不釋出資源，則其他研究者難以驗證其宣稱。

##### 2. 資料與評估的透明度
可重現性的另一個關鍵在於資料建構細節：
- 直播電商資料的來源（是否來自公開平台、合作商家或內部收集）？
- 資料去識別化與隱私處理方式？
- 各項原子能力的訓練樣本數量與分佈？
- 內部評測套件的題目設計、標註流程與評分標準？

目前這些資訊均未揭露，這是評估可重現性時的重大缺口。

##### 3. 方法層面的可重現性
儘管資源開放程度不明，方法本身具有較高的可重現潛力：
- Per-vGrid 的實作邏輯清晰：根據實際取樣影格索引計算時間戳與音訊跨度，並以邊界 token 標記區段。只要有 Qwen3.5 與 Qwen3-Omni 的 AuT，研究者可以復現其輸入組織方式。
- Faithful-RFT 的訓練框架基於 GRPO 與 vLLM，這兩者皆為公開技術，核心挑戰在於任務可驗證獎勵函數的設計。
- 同步化長度分組取樣（Synchronized Length-Grouped Sampling）是已知的資料載入優化技術，實作難度不高。

##### 4. 建議的改進
為提升可重現性，作者可考慮：
- 釋出模型權重與推論程式碼，至少提供 demo 或 API。
- 公開資料生產引擎的處理流程與部分範例資料。
- 詳細描述內部評測套件的建構方式，或將其開源。
- 提供訓練超參數、硬體配置與訓練時間，以便其他研究者估算復現成本。

#### 未來研究方向

##### 1. 多模態生成能力的擴展
目前 TLive-Omni 僅輸出文字，未來可探索擴展為真正的多模態生成模型，例如：
- 生成語音回應（Voice Response），實現直播中的語音客服。
- 生成視覺化推薦卡片或產品對比圖，增強互動體驗。
- 結合擴散模型（Diffusion Model）進行產品圖像編輯或虛擬主播（Virtual Host）生成。

##### 2. 更細緻的時間推理與因果理解
電商直播中的產品事實（Product Facts）往往分散在不同時間點，且存在因果關係（例如「因為 A 成分，所以 B 效果」）。未來可研究：
- 跨網格的長程時間推理（Long-Range Temporal Reasoning）。
- 事件因果鏈（Causal Event Chain）的抽取與驗證。
- 結合外部知識庫（Knowledge Base）進行事實核查（Fact-Checking）。

##### 3. 即時性與效率的進一步最佳化
雖然 Faithful-RFT 已考慮即時需求，但未來仍可在以下方向深化：
- 開發針對直播場景的串流處理架構，支援邊到端（Edge-to-End）低延遲推論。
- 設計自適應 token 壓縮機制，根據內容重要性動態減少視覺與音訊 token 數量。
- 結合推測解碼（Speculative Decoding）與 vLLM 的頁式注意力（PagedAttention）進一步降低延遲。

##### 4. 獎勵函數與強化學習的精進
Faithful-RFT 使用任務可驗證獎勵（Task-Verifiable Rewards），但未來可探索：
- 結合人類偏好回饋（Human Preference Feedback）與可驗證獎勵的混合獎勵設計。
- 針對開放式生成任務（如影片密集字幕 Video Dense Caption）設計更細緻的模型評判器（Model-Based Judge）。
- 研究獎勵駭客（Reward Hacking）問題，確保模型不會為了高分而產生看似正確但實際誤導的回答。

##### 5. 跨語言與跨文化直播電商
目前的訓練與評估可能主要集中於中文或特定市場。未來可擴展至：
- 多語言直播理解（Multilingual Live-Commerce Understanding）。
- 跨文化消費者行為與產品描述風格的適應。
- 針對不同電商平台（如 TikTok Shop、Amazon Live、Shopee Live）的領域適應。

##### 6. 資料引擎的開放與標準化
建立開放的直播電商多模態資料集與標準化評測基準，將有助於：
- 促進學術界與產業界的公平比較。
- 降低後續研究的資料收集門檻。
- 推動以產品為中心的直播理解（Product-Centric Live Streaming Understanding）成為獨立的研究子領域。

##### 7. 與檢索增強生成（RAG）的結合
電商直播中的產品規格、價格、庫存等資訊變動頻繁，單靠模型參數難以即時更新。未來可研究：
- 將 TLive-Omni 作為多模態檢索器（Multimodal Retriever）的重新排序器（Reranker）。
- 結合產品知識圖譜（Product Knowledge Graph）進行結構化問答。
- 即時從直播畫面與語音中更新產品資訊，實現動態知識庫。

## 論文問答

**【Background & Motivation】**

**Q1：電商直播串流為全模態理解帶來了哪些核心挑戰？**
A：電商直播的產品事實分散於主播語音、影片影格、產品圖像、畫面疊加文字以及使用者查詢等多種異質訊號中，且這些支持證據可能在長時間串流的不同時間點出現。模型因此必須同時解讀多種模態，而非單獨處理每一種模態，並且要將音訊與視覺證據對齊到以產品為中心的時間片段。此外，為了滿足直播電商的即時需求，模型還必須在感知證據的基礎上忠實地表達答案，避免產生幻覺或過度推論。

**Q2：現有的通用全模態模型與電商導向系統為何不足以解決直播電商理解問題？**
A：開源全模態模型如 MiniCPM-o 4.5、Qwen3-Omni、OmniVinci 與 Nemotron3 NanoOmni 雖然展示了統一全模態互動的可行性，但其資料與評估並非圍繞以產品為中心的直播串流理解來設計。另一方面，Valley3 雖然延伸至電子商務情境，卻未以細粒度的直播原子能力為主要組織架構。因此，現有方法缺乏針對直播電商場景的時間對齊機制、原子能力分類法，以及能夠系統化產生訓練訊號的資料生產引擎。

**Q3：為何答案的忠實度與即時性對直播電商理解特別重要？**
A：在直播電商中，觀眾通常會在短時間內針對產品提出問題，若模型無法及時回應，將錯失互動與轉換的關鍵時機。同時，答案必須忠實於當下感知到的證據，因為任何錯誤的產品資訊都可能損害消費者信任並導致購物決策失誤。因此，模型必須在真實性與回應速度之間取得平衡，這也是 TLive-Omni 設計 Faithful-RFT 階段的主要動機。

**【Method & Innovation】**

**Q4：TLive-Omni 的核心架構由哪些元件組成？**
A：TLive-Omni 以 Qwen3.5 作為語言與視覺骨幹模型，並將 Qwen3-Omni 的預訓練音訊編碼器 AuT 透過輕量級音訊對齊器嫁接至統一嵌入空間。該模型支援圖像、影片、音訊與文字輸入，並以純文字輸出回應，最多可處理 256K token 的多模態上下文，足以涵蓋長篇直播片段。整體設計讓視覺與音訊訊號能夠在同一表示空間中被聯合理解，為後續的時間對齊與監督式訓練奠定基礎。

**Q5：Per-vGrid 的設計原理是什麼？它如何改善音訊–影片的時間對齊？**
A：Per-vGrid 是一種帶時間戳記的 token 組織方式，它將每個影片網格與涵蓋相同時間區間的音訊區段放在以邊界 token 標記的同一區段內，並在每個網格前加入文字時間戳。與 Qwen3-Omni 相比，Per-vGrid 讓網格邊界更明確、視覺與音訊 token 保持連續，並在序列層級區隔相鄰網格，使模型能直接辨識對應關係。此外，時間戳與音訊跨度是根據實際取樣影格索引計算而來，因此即使整數取樣造成實際取樣率與請求率不同，仍能保留更精確的時間對齊。

**Q6：Faithful-RFT 與傳統強化微調有何不同？它如何同時提升忠實度與表達品質？**
A：Faithful-RFT 是一個專為直播電商設計的強化微調階段，它抑制顯式思考軌跡，直接對最終回應使用任務可驗證獎勵進行評分，而非在 rollout 過程中進行推理式探索。這種設計不僅減少了不必要的推理延遲，更符合即時直播的需求，同時透過任務可驗證回饋引導模型產生更忠實於感知證據的答案。為了維持 GRPO 所需的相對優勢，TLive-Omni 還提出輕量動態取樣策略，重新產生獎勵變異數趨近零的 rollout 群組，以獲得更高變異數的群組相對回饋。

**【Experiments & Results】**

**Q7：TLive-Omni 在哪些任務與基準上進行評估？**
A：研究團隊建構了一套內部直播電商評估套件，涵蓋自動語音辨識、說話者分析、產品視覺定位、光學字元辨識、時間定位、影片密集字幕與全模態問答等原子能力。除了直播電商基準外，模型也在通用多模態與全模態基準上進行測試，以檢驗其泛化能力。這樣的評估設計能同時驗證模型在商業導向任務上的專精程度，以及其在一般場景中的通用理解表現。

**Q8：實驗結果顯示 TLive-Omni 有哪些關鍵優勢？**
A：實驗結果顯示，TLive-Omni 在直播電商領域任務上具有強勁表現，能夠有效處理分散於語音、影像與文字中的產品事實。與此同時，它在多個通用多模態與全模態基準上取得領先成績，並在其余基準上保持競爭力。這些結果說明，針對直播電商場景設計的架構與訓練配方，不僅能提升商業任務表現，也不會犧牲模型在通用領域的泛化能力。

**Q9：哪些消融研究或設計驗證了 TLive-Omni 各元件的有效性？**
A：Per-vGrid 的引入顯著改善了音訊與影片之間的時間對齊，使模型能更準確地將主播話語對應到正確的視覺片段。Faithful-RFT 則進一步提升了答案忠實度與表達品質，並透過抑制顯式思考軌跡滿足即時需求。此外，同步化長度分組取樣有效減少了填充並平衡各工作節點負載，而輕量動態取樣策略則穩定了 GRPO 的相對優勢估計，這些設計共同支撐了可擴展且穩定的訓練流程。

**【Applications & Impact】**

**Q10：TLive-Omni 可應用於哪些實際的直播電商場景？**
A：TLive-Omni 可部署為即時購物助手，自動回答觀眾關於產品規格、價格與優惠的問題。它也能用於自動生成直播字幕與影片密集描述，協助平台快速產生內容摘要與搜尋索引。此外，模型還可支援精彩片段剪輯、商品視覺定位、疊加文字辨識以及內容審核等應用，全面提升直播電商的營運效率。

**Q11：在產品化過程中，TLive-Omni 有哪些工程與效能考量？**
A：由於直播場景對延遲敏感，模型必須在長上下文處理與生成速度之間取得平衡，而 TLive-Omni 支援 256K token 並以約每秒 13 個 token 壓縮音訊，使長時間錄音仍落在可負擔的上下文預算內。Faithful-RFT 透過 vLLM 加速動態 rollout 過程，並避免顯式思考軌跡帶來的額外延遲。同步化長度分組取樣與輕量動態取樣策略則讓混合模態批次訓練更具擴展性，適合大規模部署。

**Q12：TLive-Omni 對全模態研究與直播電商領域可能帶來什麼影響？**
A：TLive-Omni 將全模態理解研究從通用互動導向更具挑戰性的產品中心直播場景，填補了現有方法在細粒度原子能力與時間對齊上的空白。其提出的情境導向原子能力分類法與緊湊資料生產引擎，為後續研究者提供了一套可複製的訓練訊號建構框架。整體而言，它不僅推動了直播電商 AI 的實用化，也為多模態模型在垂直領域的落地提供了重要參考。

**【Limitations & Future】**

**Q13：TLive-Omni 目前有哪些已知的限制？**
A：TLive-Omni 目前為純文字輸出模型，無法直接生成音訊或影片內容，這限制了其在多媒體回應場景中的應用。其性能也高度依賴 Qwen3.5 骨幹模型與 Qwen3-Omni 音訊編碼器的預訓練品質，對於骨幹未涵蓋的語言或文化情境可能表現較弱。此外，雖然資料生產引擎已涵蓋多種原子能力，但面對極少見產品類別或高度口語化的方言直播時，監督訊號仍可能不足。

**Q14：在哪些情況下 TLive-Omni 可能出現失敗或表現不佳？**
A：當直播環境噪音過大、多位主播同時說話或音訊品質不佳時，語音辨識與說話者分析可能出錯。若產品被手部、包裝或其他物件遮擋，視覺定位與文字辨識的準確度也會下降。此外，當影格取樣因整數捨入導致實際時間戳與預期有偏差，或問題需要跨越多個時間片段進行複雜多跳推理時，模型可能難以給出完全正確的答案。

**Q15：未來可以朝哪些方向進一步發展 TLive-Omni？**
A：未來可將模型擴展為能夠生成音訊或影片回應的全模態生成系統，以提供更豐富的互動體驗。也可針對多語言、多方言與跨文化直播電商場景擴充資料與評估，提升全球適用性。此外，進一步優化即時串流推理管線、開放更大規模的直播電商評估基準，以及探索更細緻的時間推理與因果推論能力，都是值得持續研究的方向。

## 實務應用指南

### 適用場景

1. **直播商品問答助手**
   在電商直播進行中，觀眾透過聊天室詢問「這件外套有沒有 S 號？」「剛才提到的優惠券怎麼領？」TLive-Omni 可同時讀取主播語音、畫面中的商品、疊加文字與使用者查詢，直接給出與當下直播內容一致的答案，減少客服人力並縮短回應時間。

2. **自動直播內容稽核與重點剪輯**
   平台需要確認直播中有無誇大宣稱、違規用語或價格錯誤。模型可對長時間串流進行時間定位（Temporal Grounding），標記「主播在 03:15 提到保固十年」的區段，並自動產出影片密集字幕（Video Dense Caption），協助稽核員快速複查或生成短影片重點。

3. **商品視覺定位與導購**
   當畫面同時出現多個商品或切換展示時，系統可執行產品視覺定位（Product Visual Grounding），回答「畫面左邊那瓶精華液是什麼成分？」並結合主播語音中的產品事實，提供結構化商品資訊給購物車或推薦系統。

4. **多語言直播字幕與說話者分析**
   針對跨境電商直播，模型可進行自動語音辨識（ASR）、說話者分析（Speaker Analysis）與光學字元辨識（OCR），產出帶時間戳記的雙語字幕，並區分主播、助理與背景音，提升無障礙觀看與內容檢索體驗。

5. **直播後知識庫建構**
   將整場直播的音訊、影像與彈幕轉為結構化資料，建立可搜尋的產品事實庫。使用者後續可查詢「上週直播中哪一款手機支援防水？」模型透過全模態問答（Omni-Modal QA）回傳對應片段與摘要。

### 實作步驟建議

1. **定義原子能力與評估指標**
   依據論文的情境導向原子能力分類法，列出產品需要的核心能力（如 ASR、OCR、Product Visual Grounding、Temporal Grounding、Omni-Modal QA），並為每項能力設計可驗證的評分規則，作為後續 Faithful-RFT 的獎勵來源。

2. **建立資料生產引擎**
   將直播串流拆解為音訊、影像、商品圖與文字，依照 Per-vGrid 的設計，把每個影片網格（Video Grid）與對應時間區間的音訊一起打包，並加上文字時間戳記與邊界 token。注意使用實際取樣影格索引來計算時間，而非僅用請求的取樣率。

3. **三階段監督式微調（SFT）**
   - 第一階段：全模態感知對齊，讓模型學會將影像、影片、音訊與文字對應到統一表示空間。
   - 第二階段：直播電商領域任務訓練，使用商品定位、時間定位、密集字幕等任務資料。
   - 第三階段：指令遵循對話，加入使用者查詢與自然語言回應，提升互動品質。

4. **Faithful-RFT 強化微調**
   在 GRPO 訓練中抑制顯式思考軌跡，直接對最終回應給出任務可驗證獎勵。搭配輕量動態取樣策略，重新生成 rollout 群組以降低趨近零獎勵變異數的問題，確保群組相對優勢（Relative Advantages）仍然有意義。

5. **推論系統部署**
   使用 vLLM 提供即時生成，並將 Per-vGrid 的前處理模組化為線上服務。針對長直播，可採用滑動視窗或分段處理，避免超過 256K token 上限，同時保留足夠上下文。

6. **持續監控與迭代**
   上線後收集真實互動資料，定期檢視答案忠實度（Answer Faithfulness）與表達品質（Expression Quality），並將高品質案例回流至資料生產引擎，形成持續學習迴圈。

### 潛在風險與注意事項

| 風險 | 說明與緩解 |
|---|---|
| **時間對齊誤差** | 若使用請求的取樣率而非實際取樣影格索引，音訊與畫面可能錯位。應嚴格遵循 Per-vGrid 方法，根據實際取樣影格計算網格時間戳與音訊 token 範圍。 |
| **幻覺與不忠實回答** | 模型可能生成聽起來合理但與直播內容不符的答案。Faithful-RFT 的任務可驗證回饋可緩解此問題，但仍需保留人工抽樣稽核機制。 |
| **長上下文成本** | 256K token 雖可涵蓋長直播，但訓練與推論成本高昂。建議採用同步化長度分組取樣（Synchronized Length-Grouped Sampling）減少填充，並在推論時做適當分段。 |
| **獎勵變異數過低** | GRPO 若遇到獎勵變異數趨近零，相對優勢會失效。需實作動態取樣策略，重新生成 rollout 群組以維持足夠的獎勵差異。 |
| **多模態雜訊** | 直播畫面常有快速切換、低解析度、背景音與口音等雜訊。資料生產引擎需包含品質篩選與去噪步驟，避免低品質樣本污染訓練。 |
| **法規與倫理** | 語音與人臉資料涉及個資，需取得同意並落實去識別化；同時需避免模型學習到歧視性或誤導性銷售話術。 |

### 與其他技術的整合建議

- **推薦系統**：將 TLive-Omni 萃取的產品事實與時間定位結果寫入商品知識圖譜，作為即時推薦與搜尋排序的特徵。
- **客服機器人**：把模型的全模態 QA 能力封裝為 API，讓現有對話機器人在無法回答時，自動查詢當下或歷史直播內容。
- **內容管理系統（CMS）**：將影片密集字幕、時間戳記與視覺定位框匯入 CMS，支援編輯人員快速剪輯、下標與合規審查。
- **即時串流基礎設施**：在直播推流鏈路中部署 Per-vGrid 前處理節點，與現有的轉碼、字幕、彈幕服務並行運作，降低端到端延遲。
- **資料倉儲與 BI**：將模型輸出的結構化資訊（如商品提及次數、優惠券發放時段、觀眾提問主題）匯入數據倉儲，支援營運分析。

### 給不同背景讀者的閱讀建議

**初學者**
建議先從「適用場景」與「潛在風險」開始，理解電商直播為什麼需要同時處理語音、畫面與文字，並把 Per-vGrid 想像成「給每個畫面片段貼上時間標籤並配上對應聲音」的方法；技術細節可先略過，重點放在模型能解決什麼商業問題。

**AI 工程師**
請聚焦第 2 章架構、第 3 章三階段監督式訓練配方，以及 Faithful-RFT 與動態取樣策略的實作細節。特別注意 Per-vGrid 的時間戳計算方式、同步化長度分組取樣對訓練效率的影響，以及如何用 vLLM 支援即時 rollout。

**研究人員**
建議深入分析 Per-vGrid 與現有全模態對齊方法的差異、Faithful-RFT 中「直接對最終回應評分」相對於推理式探索的設計選擇，以及動態取樣在維持 GRPO 相對優勢上的理論意義。也可進一步探討該方法泛化到其他長時序多模態任務的可能性。

**產品經理**
請把重點放在適用場景、實作前置條件與整合建議。評估導入時需同時考量資料取得成本、GPU 運算預算、即時延遲要求與合規風險，並優先選擇一項高價值且可驗證的任務（如直播問答或自動稽核）作為最小可行產品（MVP）。
