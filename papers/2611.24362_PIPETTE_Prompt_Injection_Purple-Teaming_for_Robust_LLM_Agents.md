PIPETTE 的核心設計理念在於將「紅隊演練（red-teaming）」與「對抗訓練（adversarial training）」視為一個統一的紫隊演練（purple-teaming）閉環系統，而非兩個獨立階段的串接。這種設計直接回應了論文中所揭示的「目標不匹配（objective mismatch）」問題——現有方法如 RL-Hammer 與 PISmith 雖然在紅隊階段能達到高攻擊成功率（ASR），但其後續對抗訓練所產生的防禦者卻未必具備強魯棒性。

**第一階段：基於字典學習的策略覆蓋獎勵（Dictionary Learning-based Strategy Coverage Reward）**

傳統基於強化學習的紅隊方法以「最大化攻擊成功率」作為主要獎勵訊號，這導致策略容易陷入模式崩潰（mode collapse）——一旦發現某個有效攻擊策略（例如宣稱用戶任務已完成），策略便會反覆利用該策略以獲取高獎勵。PISmith 與 RL-Hammer 雖引入 token 級熵獎勵或嵌入距離獎勵作為正則化項，但這些僅衡量表層文字差異，無法捕捉「攻擊如何覆蓋用戶指令」這一語意層面的策略差異，從而引發獎勵破解（reward hacking）現象。

PIPETTE 的創新在於採用字典學習（dictionary learning）將生成的攻擊分解為一組稀疏、可重用的「字典元件」，這些元件對應於不同的攻擊策略。具體而言，當紅隊策略生成一個新的成功攻擊時，系統會檢查該攻擊是否能被既有字典元件線性組合所解釋；若無法解釋，則代表發現了新的攻擊策略，給予紅隊策略額外獎勵。這種設計迫使紅隊策略去探索策略空間（strategy space）而非僅僅是措辭變體（rephrasing variations），從根本上解決了模式崩潰問題。

**第二階段：在策略對抗訓練管道（On-policy Adversarial Training Pipeline）**

論文中明確指出，IPI 防禦與越獄（jailbreak）防禦存在本質差異：在 IPI 場景下，代理不能簡單地拒絕執行，因為外部資料中可能包含完成用戶任務所需的合法資訊；代理必須「忽略」注入指令，同時「利用」周圍的良性資料。標準的軌跡級結果獎勵（trajectory-level outcome reward）僅給出單一標量分數，無法定位失敗的具體 token，導致代理學會「遇到可疑外部資料就放棄」的退化策略。

PIPETTE 採用兩項關鍵技術來解決此問題：

1. **推理引導強化學習（Reasoning-guided RL）**：在對抗訓練過程中，鼓勵代理產生明確的推理步驟，使其能區分用戶指令與注入指令。

2. **Token 級在策略自蒸餾（On-policy Self-Distillation, OPSD）**：此技術將獎勵信號從軌跡級別下沉到 token 級別，能夠精確識別哪些推理或動作 token 是由注入指令驅動的，並對其進行抑制；同時強化完成用戶任務所需的 token。這種細粒度的信用分配（credit assignment）使代理學會「選擇性忽略」而非「全面拒絕」。

**整體工作流程**

如圖 1 所示，PIPETTE 的紫隊演練工作流程包含三個循環步驟：(1) 紅隊 LLM 代理探測並產生攻擊；(2) 將成功注入歸檔至攻擊存檔；(3) 對代理進行對抗訓練以對齊其行為。這一閉環持續運作，直到防禦者在多樣化攻擊下均能保持低 ASR 與高良性效用。

#### 實驗數據解讀

論文中呈現的關鍵實驗數據揭示了 PIPETTE 在多個維度上的優勢：

**攻擊成功率（ASR）表現**

在 AgentDojo 基準測試上，PIPETTE 訓練出的防禦者在靜態攻擊下達到接近零的 ASR，並能抵禦強自適應攻擊，ASR 範圍僅在 0% 至 10% 之間（涵蓋三個測試模型）。這是一個極具意義的結果，因為自適應攻擊通常被視為最嚴格的安全評估標準——攻擊者知曉防禦機制並針對性地調整攻擊策略。

**良性任務效用（Benign Task Utility）保留**

PIPETTE 在四個模型上的良性任務效用均接近未防禦基線（undefended baseline）。這表明 PIPETTE 並非以犧牲任務完成能力為代價來換取安全性，而是真正實現了「安全性與效用性的平衡」——這正是 IPI 防禦的核心挑戰。

**紅隊階段的策略多樣性**

#### 與現有研究的比較

**相較於 RL-Hammer 與 PISmith 的優勢**

PIPETTE 與這兩個最先進的基於強化學習的紅隊方法相比，主要在兩個層面實現突破：

1. **獎勵設計的根本性差異**：RL-Hammer 與 PISmith 使用表層文字差異作為正則化，而 PIPETTE 使用字典學習捕捉語意層面的策略差異。這使得 PIPETTE 能夠發現真正多樣化的攻擊，而非同一策略的措辭變體。

2. **紅隊與防禦的協同設計**：PIPETTE 並非將紅隊與對抗訓練視為獨立階段，而是將其統一在一個紫隊演練框架下，使兩者朝著「最大化硬化代理魯棒性」的共同目標優化。

**相較於標準 RL 防禦的優勢**

標準的軌跡級結果獎勵防禦方法（如基於 PPO 的 RLHF 變體）容易導致代理學會「過度防禦」——遇到外部資料就拒絕執行。PIPETTE 透過 token 級自蒸餾實現了細粒度的信用分配，使代理能夠區分注入指令與良性資料，這是標準方法無法實現的。

**相較於靜態防禦的優勢**

許多現有 IPI 防禦採用靜態方法（如提示工程、輸入過濾、隔離標記等），這些方法容易被自適應攻擊繞過。PIPETTE 透過對抗訓練使防禦者具備動態魯棒性，能夠抵禦知曉防禦機制的攻擊者。

**侷限性與未涵蓋的面向**

儘管 PIPETTE 表現優異，仍存在以下侷限：

1. **計算成本**：字典學習與 token 級自蒸餾都需要額外的計算開銷，相較於簡單的軌跡級 RL 訓練成本更高。
2. **字典大小的選擇**：字典元件數量是一個超參數，論文中未深入探討其對最終性能的影響。
3. **攻擊策略的可解釋性**：雖然字典學習提供了某種程度的策略分解，但如何將字典元件對應到人類可理解的攻擊類型仍需進一步研究。
4. **對極強自適應攻擊的評估**：雖然 PIPETTE 在「強自適應攻擊」下表現良好，但論文中未說明「最強」自適應攻擊的具體形式，可能存在更強的攻擊尚未被測試。

4. **多 API 串接的工作流程代理**：代理呼叫多個外部 API（如行事曆、CRM、付款系統）完成用戶任務。任一 API 回傳值都可能被污染。PIPETTE 的在策略對抗訓練可教導代理在保留任務完成度的同時，忽略工具回傳中的注入指令。

5. **程式碼與文件處理代理**：代理讀取外部 GitHub 儲存庫、PDF 報告或試算表以完成分析任務。PIPETTE 適合用於保護此類代理免於透過 README、註解或隱藏文字欄位發動的注入攻擊。

### 實作前置條件

**資料需求**
- 一組可信的用戶任務集合（trusted user tasks），用於訓練與評估良性效用
- 一組外部資料來源（含乾淨與污染版本），需涵蓋代理實際部署時會遇到的資料型態
- 注入任務的標註資料，用於計算攻擊成功率與獎勵訊號
- 建議採用 AgentDojo 或 ASB 等公開基準作為起點，再擴充至領域特定資料

**運算資源**
- 紅隊階段：需訓練生成式紅隊策略，建議至少 4×A100（80GB）等級 GPU；RL 訓練通常需數天至一週
- 防禦階段：在策略對抗訓練需對目標代理進行微調，視模型規模從數小時到數天不等
- 評估階段：靜態攻擊與自適應攻擊評估各需數小時
- 字典學習獎勵的稀疏分解需額外記憶體儲存攻擊策略字典

**技能需求**
- 熟悉強化學習（PPO、GRPO 等策略最佳化演算法）
- 具備 LLM 微調經驗（SFT、RLHF、token-level 信用分配）
- 理解提示注入攻擊與防禦的攻防動態
- 具備字典學習或稀疏表示的基礎知識
- 能夠設計並實作代理環境（tool use、observation handling）

### 實作步驟建議

**步驟一：建立代理環境與基準**
- 選定目標代理架構（支援 tool calling 的 LLM）
- 在 AgentDojo 或 ASB 上建立 baseline，記錄未防禦代理的良性效用與 ASR
- 確認評估指標：良性任務成功率、靜態攻擊 ASR、自適應攻擊 ASR

**步驟二：實作字典學習獎勵的紅隊策略**
- 將攻擊分解為稀疏字典元件，每個元件代表一種攻擊策略（如「宣稱任務已完成」、「偽裝成系統訊息」）
- 訓練紅隊策略時，當新攻擊無法被既有字典元件解釋時給予額外獎勵
- 監控字典元件數量隨訓練步數的成長，確認策略覆蓋率持續提升而非陷入模式崩潰

**步驟三：收集多樣化攻擊樣本**
- 從紅隊策略收集成功攻擊，依字典元件分群
- 過濾掉僅有表面文字差異但屬同一策略的樣本
- 保留跨策略的代表性樣本用於後續對抗訓練

**步驟四：執行在策略對抗訓練**
- 結合推理導向 RL 與 token-level on-policy self-distillation（OPSD）
- 設計獎勵函式同時考慮：任務完成度、是否執行注入指令、token-level 信用
- 避免僅使用 trajectory-level outcome reward，否則代理可能學會「遇到外部資料就拒絕」

**步驟五：多層次評估**
- 靜態攻擊評估：使用訓練時未見過的注入樣本測試 ASR
- 自適應攻擊評估：讓攻擊者根據防禦代理的行為調整策略
- 良性效用評估：在乾淨輸入上確認任務完成度未顯著下降
- 跨基準泛化測試：在 AgentDojo 訓練、在 ASB 評估（或反之）

**步驟六：持續監控與迭代**
- 部署後持續收集新型攻擊樣本
- 定期重訓字典與紅隊策略
- 建立紅隊→防禦→評估的自動化 pipeline

### 潛在風險與注意事項

**模式崩潰未完全解決**
即使採用字典學習獎勵，紅隊策略仍可能收斂到字典無法捕捉的細微策略變體。建議定期人工檢視字典元件的語意品質，並設置策略覆蓋率的成長下限作為早期停止條件。

**獎勵破解（Reward Hacking）的風險**
代理可能學會「表面上忽略注入但實際上仍執行」或「產出看起來正確但實際未完成任務」的行為。應結合軌跡級與 token 級獎勵，並以人工抽樣驗證代理行為的合理性。

**良性效用的退化**
過度強化的防禦可能使代理變得過度保守，在乾淨輸入上也拒絕執行。建議在訓練過程中持續追蹤良性效用，一旦下降超過閾值（如 5%）即調整獎勵權重。

**自適應攻擊者的演化**
論文中的自適應攻擊基於固定預算的迭代攻擊。實際部署後，攻擊者可能採用更長期的策略演化或結合社會工程。應將評估視為下限，而非絕對安全性保證。

**運算成本與延遲**
紅隊階段的 RL 訓練成本高昂，且字典學習獎勵會增加每步推論時間。對於資源受限的團隊，可考慮先用 PISmith 或 RL-Hammer 收集初始攻擊，再以 PIPETTE 的字典機制做增量式擴充。

**評估基準的侷限性**
AgentDojo 與 ASB 的注入任務分布未必涵蓋所有真實攻擊情境。建議在自家領域資料上額外評估，並建立內部紅隊基準。

**資料污染風險**
若訓練資料中已包含攻擊樣本，紅隊策略可能「記住」而非「發現」攻擊，導致評估失真。應嚴格區分訓練集與測試集，並使用 held-out 攻擊樣本驗證。

### 與其他技術的整合建議

**與既有 RLHF 流程整合**
PIPETTE 的在策略對抗訓練可作為 RLHF 的延伸階段：在完成標準對齊後，加入 IPI 防禦專項訓練。建議將 OPSD 模組化，使其與現有的偏好資料 pipeline 相容。

**與輸入過濾防禦互補**
PIPETTE 專注於代理層的魯棒性，可與輸入側的提示注入偵測器（如基於分類器或 perplexity 的過濾器）組合使用，形成縱深防禦。建議先過濾已知攻擊模式，再以 PIPETTE 處理繞過過濾器的攻擊。

**與監控與可觀測性系統整合**
將 PIPETTE 訓練期間收集的字典元件作為監控系統的啟發式規則：當代理行為符合某字典元件特徵時觸發告警。這有助於將離線紅隊發現轉化為線上防禦訊號。

**與多代理架構整合**
在多代理系統中，可對每個子代理分別套用 PIPETTE 訓練，並在協調層加入注入偵測。需注意代理間的訊息傳遞本身也是潛在注入點。

**與模型架構解耦**
PIPETTE 的方法與具體模型架構無關，可應用於 dense 模型、MoE 模型或不同規模的 LLM。論文已展示在 Qwen3-4B 等模型上的效果，遷移至其他模型時主要需調整訓練超參數。

**與持續整合/持續部署（CI/CD）整合**
將紅隊與對抗訓練納入模型發版的必經流程：每次基礎模型更新或代理邏輯變更後，自動觸發 PIPETTE pipeline 重新評估，ASR 超過閾值時阻擋發版。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節（Introduction）以理解間接提示注入的威脅模型與紫隊演練的概念框架。第 2 節的代理工作流程描述有助於建立術語基礎。實作細節可先略過，重點掌握「為什麼高 ASR 不等於高魯棒性」這個核心洞見，以及 PIPETTE 試圖解決的雙重挑戰（紅隊模式崩潰與防禦效用退化）。

**給 AI 工程師**：應聚焦於第 4 節（方法）與附錄中的實作細節。字典學習獎勵的設計、OPSD 的 token-level 信用分配機制、以及紅隊與防禦的聯合訓練流程是工程實作的核心。建議在 AgentDojo 上重現論文的 baseline 實驗，再逐步替換為 PIPETTE 的元件，以驗證每個設計選擇的貢獻。特別注意獎勵函式的權重平衡，這是影響最終效果的關鍵超參數。

**給研究者**：本論文的核心貢獻在於揭示 RL 紅隊演練中的「目標不匹配」問題，並提出以字典學習作為策略層級多樣性的代理指標。建議深入分析第 3 節的診斷實驗，理解為何 PISmith 訓練時 ASR 更高但防禦後魯棒性更差。第 5 節的跨基準泛化結果與自適應攻擊評估是評估方法實用性的關鍵證據。可進一步探索的方向包括：字典元件的自動化語意標註、與人類專家紅隊的比較、以及在更大規模模型（如 70B 級別）上的可擴展性。

**給產品經理**：重點關注三個面向：（1）PIPETTE 在 AgentDojo 與 ASB 上達到 0%–10% 的自適應攻擊 ASR，同時良性效用接近未防禦基線，這代表可在不犧牲用戶體驗的前提下顯著提升安全性；（2）紅隊→對抗訓練的紫隊流程可整合至模型發版流程，作為安全閘門；（3）運算成本是主要採用門檻，建議在導入初期先以 AgentDojo 等基準驗證概念，再評估在自家資料上的投資報酬率。需注意「接近零 ASR」並非絕對安全保證，仍需搭配監控與事件回應機制。
