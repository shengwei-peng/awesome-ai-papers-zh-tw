## ⚡ TL;DR

現有基準測試多為短程靜態任務，難以評估持續性環境中狀態累積的長期安全風險。
本文提出 OpenART 與 EMHA，透過授權狀態轉換回饋驅動環境演化，評估代理長期安全性。
EMHA 於 75 配置達 85.0% ASR，複雜任務中環境演化更易暴露安全失效，實作差異對安全影響顯著。

## 摘要翻譯

AI 代理（AI agents）運作於持續性環境（persistent environments）中，早期的狀態變化可能對未來很久之後的決策造成影響。與傳統語言模型互動（language-model interactions）不同，代理行為是透過共享狀態（shared state）進行調節，而該狀態在長期工作流程（long-horizon workflows）中被反覆修改與重複使用。現行的安全性基準測試（safety benchmarks）經常無法捕捉這些累積風險（cumulative risks），因為它們聚焦於短期、靜態的任務（static tasks）。為了解決這些限制，我們提出 OpenART，一個可擴展的開放式測試場域（open-ended arena），透過環境演化（environment evolution）進行代理紅隊測試（Agent Red Teaming）。OpenART 提供橫跨 50 個領域（domains）、超過 10,000 個經過驗證的有狀態情境（stateful scenarios），並從超過 500,000 個工具與技能（tools and skills）組成的資源池中汲取。這些任務的工具呼叫（tool calls）次數中位數（median）為 97 次，且能在 75 種不同的代理模型配置（agent-model configurations）間進行統一評估。為了系統性地探索這些不斷演化的攻擊面（attack surfaces），我們提出演化式馬可夫超圖攻擊（Evolutionary Markov Hypergraph Attack, EMHA）。EMHA 是一種黑箱策略（black-box policy），透過協調授權狀態轉換（authorized state transitions）來執行回饋驅動環境演化（feedback-driven environment evolution），且無需參數更新（parameter updates）。在整個評估過程中，任務目標（task objectives）保持固定，僅環境狀態（environment state）改變。在所有配置中，EMHA 的彙總攻擊成功率（Attack Success Rate, ASR）達 85.0%。相較於僅指令演化（instruction-only evolution），其優勢從簡單環境的約 2% 提升至最複雜環境的 17% 以上，顯示隨著任務複雜度（task complexity）增加，環境演化會愈發暴露出安全性失效（safety failures）。此外，我們的分析顯示，在考量底層模型能力（underlying model's capabilities）之後，代理的特定執行階段實作（runtime implementation）仍能解釋相當大比例的安全性變異（safety variation）。這些結果確立了 OpenART 作為在複雜、演化環境（evolving environments）中研究代理安全性（agent safety）的可擴展基礎。

### 核心貢獻（3～5點）
- 提出 OpenART，一個可透過開放式環境演化（Open-Ended Environment Evolution）進行規模化代理紅隊測試的開放式測試場域，提供超過 10,000 個經驗證的有狀態情境，涵蓋 50 個領域。
- 提出演化式馬可夫超圖攻擊（EMHA），一種無需參數更新的黑箱策略，透過協調授權狀態轉換執行回饋驅動環境演化。
- 在 75 種代理模型配置上達到 85.0% 的彙總攻擊成功率（ASR），並證明環境演化在複雜任務中比僅指令演化更具優勢。
- 發現代理的執行階段實作對安全性變異的解釋力顯著，超越底層模型能力的影響。

### 適合對象
AI 安全性研究者、紅隊測試工程師、AI 代理開發者，以及關注長期工作流程中累積風險與狀態依賴安全問題的學術與產業界人士。

## 深度分析

#### 方法論解析

OpenART（Open-Ended Environment Evolution for Agent Red Teaming）的核心方法論在於把紅隊測試（Red Teaming）的基本單位從「單一提示（prompt）」轉移到「可執行的有狀態環境（stateful executable environment）」。傳統的語言模型互動（language-model interactions）通常把安全性視為單輪或短輪對話的屬性，但 AI 代理（AI agents）的行為是透過共享狀態（shared state）不斷被調節的：工具呼叫會修改檔案、權限、記憶體與外部資源，而這些修改會在長期工作流程（long-horizon workflows）中持續影響後續決策。OpenART 正是為了捕捉這種「延遲顯現、累積放大」的風險而設計。

在情境建構（Scenario Construction）階段，OpenART 先從 50 個領域（domains）的種子出發，結合超過 50 萬筆 Tools（工具）、MCPs（模型上下文協定，Model Context Protocol）與 Skills（技能）組成的大型能力語料庫（Capability Corpus），由規劃器（planner）生成帶有隱藏安全契約（hidden safety contract）的任務束（task bundle）。每個情境都會被轉換成可執行的依賴圖（dependency graph），並經過決定性評估器（deterministic evaluator）與自動化行為探針（automated behavioral probes）驗證，最終產出超過 10,000 個經過驗證的有狀態情境（validated stateful scenarios）。這些情境的中位數工具呼叫次數（median tool calls）達到 97 次，遠超過現有大多數代理基準測試（agent safety benchmarks）的規模。

為了實現跨代理對齊（Cross-Agent Alignment），OpenART 採用目標專屬轉接器（target-specific adapters），把同一組任務目標（task objectives）、隱藏安全契約與評估準則投影到 15 個已部署代理（deployed agents）的原生介面，並分別搭配 GPT-5.5、Claude-Opus-4.8、GLM-5.2、Qwen-3.7-Max 與 DeepSeek-V4-Protoform 等 5 個底層模型，形成 75 種代理模型配置（agent-model configurations）。轉接器會根據各代理支援的能力，暴露八種目標可見攻擊向量（target-visible attack vectors）：workspace（工作空間）、instructions（指令）、Skills（技能）、Tools（工具）、MCPs、short-term memory（短期記憶）、plan state（計畫狀態）與 long-term memory（長期記憶）。這種設計確保不同代理執行的是語義相同、評估標準一致的情境，從而進行受控且可直接比較的評估。

在紅隊測試框架（Red Teaming Framework）中，OpenART 實作了受控環境演化（Controlled Environment Evolution）：任務目標與安全契約保持固定，只有環境狀態（environment state）會隨著執行而改變。每次執行後，評估器的回饋會授權並引導下一次狀態轉換（authorized state transitions），使同一個底層情境在語義不變的前提下逐漸增加難度。為了系統化地探索這些演化中的攻擊面（attack surfaces），作者提出 EMHA（演化式馬可夫超圖攻擊，Evolutionary Markov Hypergraph Attack）。EMHA 是一種黑箱策略（black-box policy），它把協調式的環境演化建模為超圖遍歷（hypergraph traversal）：環境組態是節點，跨多個攻擊向量的同步狀態轉換是超邊（hyperedges）。EMHA 根據評估器回饋迭代地精煉未來的狀態轉換，且不需要任何參數更新（parameter updates）。OpenART 的策略無關（policy-agnostic）介面也允許未來替換成其他黑箱搜尋策略。

#### 實驗數據解讀

OpenART 的實驗規模相當可觀：10,000 個以上經過驗證的情境、50 個領域、超過 500,000 個工具與技能（tools and skills）、中位數 97 次工具呼叫，以及橫跨 75 種代理模型配置的統一評估。情境建構品質（Scenario Construction Quality）方面，自動化驗證後再經人類專家抽樣確認，正確率達到 99.3%，顯示大量生成後的過濾與修復機制具有相當高的可靠性。

在紅隊測試成效（Red-Teaming Effectiveness）上，以 EMHA 作為參考策略時，OpenART 在所有 75 種配置上的彙總嚴格攻擊成功率（pooled Strict ASR）達到 85.0%。這個數字本身已經說明：當攻擊者能夠持續、協調地操縱環境狀態時，現有代理系統普遍存在顯著的安全缺口。更值得關注的是環境演化與任務複雜度（task complexity）之間的交互作用：與僅指令演化（instruction-only evolution）的基線相比，完整環境演化在簡單情境上只提升 ASR 約 1.8–2.7%，但在最複雜的情境上提升幅度高達 17.2–17.6%。這意味著隨著任務複雜度增加，安全性失效（safety failures）越來越不是來自單一惡意提示，而是來自多步驟狀態操縱的累積效應；簡單的靜態任務（static tasks）無法充分暴露這類長程風險。

另一項關鍵發現是：代理的執行階段實作（runtime implementation）解釋了相當大比例的安全性變異（safety variation），且這種變異無法單純用底層模型能力（underlying model's capabilities）來解釋。換句話說，同樣的基礎模型放在不同的代理架構中（例如記憶體管理、計畫狀態維護、工具綁定方式不同），其被攻擊成功率可能差異很大。這對安全工程具有重要意涵：除了改進語言模型本身的對齊（alignment），代理層的記憶、規劃、工具呼叫與狀態追蹤機制同樣需要嚴格的紅隊測試。

個案研究（Case Studies）進一步細化了這些發現，例如 Safety-Debt Accumulation Attack（安全債務累積攻擊）顯示早期看似無害的狀態修改會在後期引發違規；Plan–Referent Drift Attack（計畫指稱漂移攻擊）顯示計畫狀態與實際指稱對象偏離後的風險；Template-Authority Override Attack（模板權限覆寫攻擊）、Compliance-Rebinding Attack（合規重新綁定攻擊）、Provenance-Composition Attack（來源組合攻擊）與 Controlled MCP Capability-Rebinding Attack（受控 MCP 能力重新綁定攻擊）則分別對應權限、合規對象、來源追蹤與 MCP 能力綁定等攻擊面。這些案例說明 OpenART 不僅能量化 ASR，也能具體定位失效機制。

#### 與現有研究的比較

現有的代理安全性基準測試（safety benchmarks）大多聚焦於靜態或可在每輪重置的環境，且工作流程相對短暫，執行也常與特定基礎設施緊密耦合，例如 AgentBench、WebArena、SWE-bench、ToolBench、AgentHarm 等。這些測試在評估單次或短程工具使用、程式碼修復、網頁導航等任務上非常有價值，但對於持續性環境（persistent environments）中的狀態操縱、延遲攻擊傳播（delayed attack propagation）與長程安全性失效的覆蓋有限。

OpenART 的主要進展在於四個層面。第一，它把評估單位從提示或任務提升到可執行環境，能夠研究「環境媒介失效」（environment-mediated failure）。第二，它透過跨代理執行階段投影（Cross-Agent Runtime Projection）實現了不同代理與模型之間的公平比較，這在過去常被代理專屬介面所阻礙。第三，它引入開放式環境演化（open-ended environment evolution），使同一情境可以持續增加難度，從而系統化地研究攻擊面如何隨環境複雜度擴大。第四，它提供了一個大規模競技場（Large-Scale Arena），結合豐富攻擊面（Rich Attack Surface）與受控狀態轉換（controlled state transitions），為代理安全性研究提供了可擴展的基礎。

然而，OpenART 也存在若干限制。首先，它假設攻擊者能夠執行授權狀態轉換（authorized state transitions），這對應的是內部威脅或已具備環境寫入權限的對手，而非所有外部對手。其次，EMHA 作為黑箱策略（black-box policy）雖然具備通用性，但沒有利用模型內部梯度資訊，可能錯過某些需要細微參數層攻擊的場景。第三，大規模長程評估的運算成本相當高，可能限制頻繁重複實驗。第四，情境生成依賴能力語料庫（Capability Corpus），若語料庫存在領域偏誤，生成情境也會繼承。第五，雖然人類驗證正確率高，但抽樣驗證並不能保證 10,000 個情境全部無誤。最後，目前結果主要以 ASR（攻擊成功率）呈現，對於危害嚴重度、影響範圍與可歸因性的刻畫仍較二元。

#### 可重現性評估

從本文提供的附錄來看，OpenART 在方法細節揭露上相當完整：包含領域分類法（Domain Taxonomy）、代表性情境種子（Representative Scenario Seeds）、競技場目錄（Arena Catalog）、物件階層（Object Hierarchy）、能力語料庫（Capability Corpus）、目標代理與攻擊向量（Target Agents and Attack Vectors）、規劃器提示建構（Planner Prompt Construction）、EMHA 攻擊者提示建構（EMHA Attacker Prompt Construction）、固定攻擊者教義（Fixed Attacker Doctrine）以及多個環境媒介失效案例（Case Studies of Environment-Mediated Failure）。這些資料對於理解實驗設計與重現提示工程非常有幫助。

不過，單就提供的上下文判斷，目前並未明確說明是否公開釋出原始碼、經過驗證的情境規格、能力語料庫、目標專屬轉接器（target-specific adapters）、決定性評估器（deterministic evaluator）程式碼，以及完整執行日誌。若缺少這些元件，獨立研究者只能重現提示設計與部分概念驗證，難以完全複製 10,000 個情境與 75 種代理模型配置的完整實驗。此外，部分目標模型（如 GPT-5.5、Claude-Opus-4.8 等）若為未來或內部版本，其模型權重（model weights）通常不公開，只能透過 API 端點近似；這也會對結果的精確重現造成限制。

若要提升可重現性（reproducibility），建議作者釋出以下項目：情境規格的結構化格式（如 JSON 或 YAML）、評估器與行為探針程式碼、各代理的轉接器實作、EMHA 的完整狀態轉換邏輯、能力語料庫的來源與篩選紀錄（provenance），以及每個配置下的詳細 ASR 分解表。這樣不僅能讓社群驗證結果，也能促進後續在 OpenART 基礎上的改進與擴展。

#### 未來研究方向

OpenART 為代理安全性研究開啟了多條值得深入探索的路徑。首先，可以將環境演化擴展到多代理系統（multi-agent systems）與動態即時環境，研究代理之間的狀態共享與協作如何放大或抑制安全風險。其次，需要發展更細緻的因果歸因方法，以判斷是哪一次狀態轉換（state transition）最終導致安全性失效，而不僅止於二元 ASR。

第三，未來可結合強化學習（Reinforcement Learning）或進化演算法，學習更強大的攻擊策略，並與 EMHA 這類無參數更新（no parameter updates）的黑箱策略進行比較。第四，應該研究對應的防禦機制，例如代理自我監控（self-monitoring）、安全債務（safety-debt）檢測、計畫狀態驗證、記憶體完整性保護，以及受攻擊後的狀態回滾（rollback）能力。

第五，可以將環境演化與傳統的提示越獄（jailbreak）攻擊結合，探討兩者是否具有加成效果。第六，情境生成可進一步自動化，並擴展到跨語言、跨文化與更多高風險領域（如醫療、金融、法律），同時建立更細緻的危害嚴重度量表。第七，OpenART 的框架也可用於建立標準化的代理安全性排行榜（leaderboard），推動產業與學界在真實、有狀態、會演化的環境中持續評估與改進代理系統。

最後，針對「執行階段實作（runtime implementation）比底層模型能力更能解釋安全性變異」這一發現，未來可以系統化地拆解代理架構中的各個模組（記憶、規劃、工具綁定、MCP 整合），找出對安全性影響最大的設計選擇，並據此提出可驗證的安全設計原則。這將使 OpenART 不僅是一個攻擊評估平台，也成為建構更安全 AI 代理的設計工具。

## 論文問答

**Q1：AI 代理在持續性環境中運作時，究竟帶來了什麼根本性的安全挑戰？**

A：AI 代理會透過工具反覆修改共享狀態、資料、權限與外部資源，使得單一動作的影響會在長期工作流程中不斷傳遞。某個在當下看來無害的狀態變更，可能潛伏多步之後才顯現為有害行為。因此，安全失效不再只是單一提示或單一步驟的問題，而是整個互動軌跡的屬性，這讓預測、歸因與評估都變得更加困難。

**Q2：現有的代理安全性基準測試為何難以捕捉這類長期風險？**

A：現有基準大多在靜態或可重設的環境中進行，且工作流程相對短暫，執行也常綁定特定測試基礎設施。它們較少涵蓋持續狀態操縱、延遲攻擊傳播，以及隨環境演化才浮現的長程安全失效。換句話說，它們主要評估單次、靜態任務，而忽略了累積風險與狀態依賴所帶來的動態威脅。

**Q3：為什麼紅隊測試應該把「環境」而非「單一提示」當作基本單位？**

A：因為代理行為是透過共享狀態來媒介的，改變環境狀態能夠觸發單純修改指令所無法暴露的潛在弱點。在真實應用中，任務目標通常保持不變，但周圍的資料、權限與工具狀態卻會不斷演變。將環境視為紅隊測試單位，才能貼近現實並發現長期工作流程中才會出現的安全失效。

**Q4：OpenART 的核心架構與主要組成是什麼？**

A：OpenART 是一個大規模的代理安全性測試場域，把可執行的環境當作紅隊測試的基本單位。它從 50 個領域的種子與超過 50 萬個工具、MCP 和技能中，建構出超過一萬個經過驗證的有狀態情境。每個情境會透過輕量的目標專屬轉接器，投影到 15 個已部署代理與 5 種基礎模型所組成的 75 種代理—模型配置中進行統一評估。

**Q5：什麼是 EMHA，它如何執行環境演化攻擊？**

A：EMHA 全名是演化式馬可夫超圖攻擊，是一種黑箱策略，它把協調式的環境演化建模為超圖遍歷。每次執行後，它利用評估器的回饋來授權並引導下一個狀態轉換，無需更新任何模型參數。透過這種回饋驅動環境演化，EMHA 能在固定任務目標與安全合約的前提下，逐步提升同一情境的攻擊難度。

**Q6：OpenART 為何選擇固定任務目標，只改變環境狀態？**

A：這樣的設計可以隔離環境演化對安全性的影響，讓實驗具有對照性。任務語義不變，意味著攻擊成功率的提升只能歸因於狀態操縱，而非任務本身被改寫。這也符合真實場景：代理常被賦予穩定的目標，但執行過程中的環境狀態卻會動態變化。

**Q7：OpenART 的測試規模與情境驗證品質如何？**

A：OpenART 提供橫跨 50 個領域、超過一萬個經過驗證的有狀態情境，每個情境在納入前都必須通過確定性評估器與自動化行為探針，並在人類專家驗證下達到 99.3% 的正確性。這些任務的中位數工具呼叫次數高達 97 次，遠超過現有大多數代理基準。情境本身與目標代理無關，直到執行時才透過轉接器投影到各代理的原生介面。

**Q8：OpenART 與 EMHA 的主要實驗結果是什麼？**

A：在 75 種代理—模型配置上，EMHA 達到了 85.0% 的彙總嚴格攻擊成功率。相較於僅改變指令的基線，完整環境演化在簡單情境上只提升約 2%，但在最複雜的情境上卻提升了 17.2% 至 17.6%。這顯示隨著任務複雜度增加，環境演化越能有效地暴露代理的安全失效。

**Q9：實驗分析對「模型能力」與「執行階段實作」的相對重要性有什麼發現？**

A：研究發現，特定代理的執行階段實作解釋了相當大比例的安全性變異，這部分影響超越了底層模型能力本身。這意味著代理的架構、工具介面、記憶體設計與規劃機制，對安全性有決定性影響。因此，安全性評估不應只針對基礎語言模型，而必須把整個代理系統納入考量。

**Q10：OpenART 能夠捕捉哪些真實世界中的安全失效類型？**

A：OpenART 能夠重現安全債務累積、計畫指稱漂移、模板權限覆寫、合規重新綁定、來源組合攻擊，以及受控 MCP 能力重新綁定等多種長期失效模式。這些問題常出現在雲端工作空間、程式碼倉儲與多步驟業務流程等持續性環境中。它們顯示微小的狀態變化可能在後續引發代理違反安全合約。

**Q11：產品開發團隊應如何運用 OpenART 來提升代理安全性？**

A：開發者可以透過轉接器將共享情境投影到自己的代理上，評估其在動態環境狀態下的安全表現。OpenART 允許在不同模型與執行階段實作之間進行一致比較，幫助團隊找出最脆弱的攻擊面。定期以 OpenART 進行紅隊測試，有助於在部署前發現潛伏的長期風險。

**Q12：這項研究可能對代理安全研究與產業評估帶來什麼影響？**

A：它將紅隊測試的焦點從孤立提示攻擊，轉移到以可執行環境演化為核心的評估典範。OpenART 提供可擴展且可重複使用的基準，讓不同代理、模型與介面能在相同語義下被公平比較。這也會推動防禦機制的發展，例如監控並限制長期軌跡中的狀態轉換。

**Q13：OpenART 目前有哪些可能的限制？**

A：OpenART 目前主要聚焦在目標可見攻擊向量內的授權狀態轉換，可能未涵蓋社交工程或實體世界攻擊等外部威脅。EMHA 雖為黑箱參考策略，但並不保證找到最優攻擊，且搜尋空間可能隨情境複雜度快速膨脹。此外，即使人類驗證正確率高達 99.3%，仍可能遺漏細微的語義漂移或新穎失效模式。

**Q14：個案研究中的環境媒介失效告訴我們什麼？**

A：個案研究顯示，即使任務目標與提示內容看似未變，環境狀態仍能讓代理累積安全債務、偏離原訂計畫、被模板權限覆寫，或錯誤地重新綁定合規對象。這些失效證明環境狀態本身就可以顛覆安全機制，而不需要直接改寫指令。它們強調必須在執行階段建立狀態依賴追蹤與授權邊界檢查。

**Q15：OpenART 指出了哪些未來研究方向？**

A：未來可以擴展到更多領域與更長的互動軌跡，並結合自適應防禦機制來研究攻防動態。也可以發展出比 EMHA 更強大的黑箱搜尋策略，或針對記憶體、規劃與安全監控設計更穩健的代理架構。此外，將 OpenART 整合到持續部署流程中，可望在代理與環境不斷演化的同時，提供長期且自動化的安全保證。

## 實務應用指南

## 適用場景

1. **企業級 AI 代理上線前的長期安全審查**  
   當代理需要持續操作資料庫、檔案系統、API 與外部工具時，OpenART 可用來建立數萬個有狀態情境，模擬「早期無害動作累積成後期有害結果」的攻擊路徑，例如權限逐步提升、敏感資料外洩或合規條件被重新綁定。

2. **多代理協作平台的安全性對齊測試**  
   若產品同時支援多種代理框架（如不同 MCP 伺服器、記憶體模組與規劃器），可透過 OpenART 的跨代理執行階段投影，把同一組任務目標與隱藏安全契約投影到不同代理實作上，比較各框架在相同環境演化下的安全表現。

3. **工具與技能生態系統的風險盤點**  
   對於擁有數十萬個 Tools、MCPs 或 Skills 的平台，OpenART 能從能力語料庫中系統化組合攻擊面，找出「單獨無害、組合後危險」的工具鏈，例如檔案讀取 + 電子郵件發送 + 日誌清除所構成的資料外洩路徑。

4. **基礎模型與代理執行階段實作的責任歸屬**  
   當安全失效難以判斷是模型能力不足還是代理實作缺陷時，OpenART 提供 75 種代理—模型配置的控制變因實驗，協助團隊量化「底層模型能力」與「執行階段實作」各自對安全性變異的貢獻。

5. **紅隊測試自動化與持續監控**  
   安全團隊可將 EMHA 整合至 CI/CD 或定期排程，讓環境在每次模型或代理更新後自動演化，持續發現因版本變更而暴露的新攻擊面，避免僅依賴靜態、單輪的提示注入測試。

## 實作前置條件

### 資料準備
- **領域種子與任務定義**：至少準備數十個高品質的代表性情境種子，涵蓋目標業務領域（如財務、醫療、DevOps、客戶支援），並明確定義每個任務的良性目標與隱藏安全契約。
- **能力語料庫**：收集或建置代理可呼叫的工具、MCPs、Skills 清單，規模建議達數千到數萬以上，才能發揮大規模組合攻擊面的優勢。
- **評估器與行為探針**：針對每個情境設計確定性評估器（deterministic evaluator）與自動化行為探針，用於驗證情境可執行性與攻擊成功與否。

### 運算資源
- **情境生成與驗證**：需要大量 LLM 呼叫與自動化執行環境，建議具備可平行化的容器化沙盒（如 Kubernetes）與足夠的 API 配額。
- **長期工作流執行**：中位數 97 次工具呼叫代表單一情境可能耗費數分鐘到數十分鐘，建議預留可擴展的執行佇列與狀態持久化儲存。
- **環境演化運算**：EMHA 雖無需參數更新，但每輪演化都需重新執行代理並收集回饋，建議配置實驗追蹤系統（如 MLflow、Weights & Biases）以管理數萬次執行紀錄。

### 技能與團隊
- **AI 安全紅隊工程師**：熟悉提示注入、工具鏈濫用、權限提升等攻擊手法。
- **代理系統工程師**：能將抽象情境投影到不同代理框架，並開發 target-specific adapters。
- **領域專家**：負責審查情境的業務合理性與安全契約設計，避免產生不切實際或倫理爭議的測試案例。
- **平台維運人員**：確保沙盒隔離、資料去識別化，以及測試過程不影響生產環境。

## 實作步驟建議

1. **定義評估範圍與安全契約**  
   先選定要測試的代理框架與底層模型，列出八種原生攻擊向量（workspace、instructions、Skills、Tools、MCPs、短期記憶、計畫狀態、長期記憶）中哪些對目標代理可見，並為每個領域寫下「絕對不能發生」的安全契約。

2. **建置能力語料庫與物件階層**  
   依照附錄 B 的概念，建立 Object Hierarchy 與 Capability Corpus，記錄每個工具或技能的輸入輸出、副作用、權限需求與來源（provenance），作為後續情境組合的基礎。

3. **生成並驗證第一批情境**  
   使用規劃器提示（Planner Prompt）從領域種子生成任務束（task bundle），再透過驗證驅動修復迴圈（Validation-Driven Repair）反覆修正，直到通過確定性評估器。目標是先達到高驗證通過率（如 99% 以上），再擴大規模。

4. **開發跨代理投影適配器**  
   為每個目標代理建立輕量 adapter，將相同任務目標、安全契約與評估器轉譯為該代理的原生介面。確保不同代理執行的是「語義一致」的情境，而非各自獨立的測試案例。

5. **部署 EMHA 進行受控環境演化**  
   以黑箱方式執行 EMHA：固定任務目標，只改變環境狀態，並利用評估器回饋授權下一輪狀態轉換。從簡單環境開始，逐步增加工具呼叫數量與狀態依賴深度，觀察 ASR 如何隨任務複雜度上升。

6. **分析結果並建立修復優先順序**  
   比較 75 種代理—模型配置的攻擊成功率，識別「同模型、不同代理實作」之間的安全落差。針對高風險的環境媒介失效模式（如安全債務累積、計畫指稱漂移、合規重新綁定）優先修復。

7. **整合至持續安全測試流程**  
   將通過驗證的情境庫與 EMHA 演化流程納入自動化測試，每次模型或代理更新後重新執行關鍵情境，並用版本控制追蹤情境規格與評估器變更。

## 潛在風險與注意事項

- **沙盒隔離不足導致真實損害**  
  OpenART 的情境雖在測試環境執行，但若工具呼叫可觸及真實 API、資料庫或電子郵件伺服器，可能意外造成資料外洩或操作。務必使用完全隔離的沙盒、假資料與模擬外部服務。

- **情境品質過度依賴自動驗證**  
  自動化評估器可能無法捕捉所有語義偏差，建議定期進行人類專家抽樣審查（如論文中 99.3% 正確率仍需人工驗證），特別是在高風險領域如醫療或金融。

- **攻擊成功率的解讀陷阱**  
  85.0% 的彙總 ASR 是跨 75 配置的結果，不能直接推論到單一產品。應細分至特定代理、模型、領域與攻擊向量，避免過度概括。

- **環境演化偏離真實使用者行為**  
  EMHA 產生的狀態轉換雖受控，但可能過度最佳化攻擊路徑。建議同時收集真實使用者軌跡作為對照，確保發現的風險在實際工作流中具有可復現性。

- **法規與倫理合規**  
  紅隊測試可能產生涉及歧視、隱私或惡意行為的內容。應建立內部審查機制，確保測試目的僅為提升安全性，並符合當地法規與平台政策。

- **過度聚焦環境而忽略提示安全**  
  OpenART 強調環境演化，但傳統提示注入與越獄攻擊仍是重要風險。建議將兩者並行，形成多層次的紅隊測試策略。

## 與其他技術的整合建議

- **與現有 LLM 評估框架整合**  
  可將 OpenART 的情境規格輸出為標準化格式（如 JSON / YAML），與現有評估工具（如 AgentBench、SWE-bench、TRUST）對接，補強這些框架在長期、有狀態攻擊上的不足。

- **與 CI/CD 與 MLOps 管線整合**  
  將情境生成、驗證、執行與 EMHA 演化包裝成容器化工作流，在每次模型微調、代理框架更新或工具新增時自動觸發，作為上線閘門之一。

- **與可觀測性平台整合**  
  把代理執行過程中的工具呼叫、狀態變更與評估器回饋匯入可觀測性系統（如 LangSmith、Langfuse、OpenTelemetry），協助團隊在生產環境中偵測類似的環境媒介失效模式。

- **與威脅情報庫整合**  
  將 EMHA 發現的攻擊路徑（如 MCP 能力重新綁定、模板權限覆寫）轉換為結構化威脅情報，與 MITRE ATLAS、OWASP LLM Top 10 等框架對應，提升與資安團隊的溝通效率。

- **與模型對齊訓練整合**  
  把高風險情境及其成功攻擊軌跡轉為微調或 RLHF 的負例資料，針對長期狀態依賴與工具鏈濫用進行強化學習，改善模型在持續性環境中的安全決策。
