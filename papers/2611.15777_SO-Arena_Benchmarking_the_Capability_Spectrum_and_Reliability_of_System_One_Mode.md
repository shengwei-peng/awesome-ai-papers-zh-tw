SO-Arena 的方法論核心在於建立一個能同時評估「能力光譜 (capability spectrum)」與「決策可靠性 (decision reliability)」的統一基準測試框架。其方法論設計可從以下幾個層面深入剖析：

**決策介面統一化 (Unified Decision Interface)**

論文將 System One 決策模型 (System One decision models) 形式化為一個三元組實例 $x = (s, q, C)$，其中 $s$ 為供應狀態 (supplied state)、$q$ 為決策目標 (decision objective)、$C = \{c_1, ..., c_K\}$ 為可採納結果 (admissible outcomes) 集合。模型回傳一個在結果空間上的機率分佈 $p_\theta(\cdot | x)$。此設計的關鍵優勢在於將異質任務（包含文字、結構化記錄、擷取段落、互動歷史等）抽象為統一的機率預測問題，並支援三種輸出格式：

- **類別選擇 (categorical selection / choice)**：無序的明確替代選項
- **二元判斷 (binary judgment / noul)**：是/否類型的介面問題
- **序數評估 (ordinal assessment / score)**：有序描述等級

這種介面設計源自 Jev-style interface，使不同領域的任務能在同一評估框架下進行比較，避免了傳統基準測試中「蘋果對橘子」的比較困境。

**能力類別與領域組織**

SO-Arena 涵蓋 11 個領域，組織成 5 個能力類別 (capability families)：

1. 語義理解 (semantic understanding)
2. 知識與推理 (knowledge and reasoning)
3. 安全與政策合規 (safety and policy compliance)
4. 證據評估 (evidence assessment)
5. 代理任務完成 (agent task completion)

此分類法的設計理念在於超越傳統的「學科分類」（如數學、程式設計），轉而以「決策所需的能力本質」為分類軸。這使得跨領域的能力比較更具意義，例如「推理」能力可同時在數學、科學、邏輯等領域中被評估。

**難度分層機制 (Difficulty Tiering)**

論文引入領域特定的難度分層 (domain-specific difficulty tiers)，這是方法論上的一大創新。不同於傳統基準測試僅提供單一難度或隨機抽樣，SO-Arena 根據各領域的特性定義難度標準，使評估能夠：

- 區分模型在不同複雜度下的表現差異
- 建構加權的能力排行榜 (capability leaderboard)，強調最具挑戰性的任務
- 揭示模型在難度提升時的退化模式

**證據基礎評估 (Evidence-Grounded Evaluation)**

方法論上特別強調「參考標籤必須由模型可見證據 (model-visible evidence) 支持」。這意味著：

- 所有參考標籤經過人工驗證 (manual verification)
- 評估參考 (evaluation references) 與模型輸入 (model inputs) 分離
- 來源可追溯 (traceable sources)

此設計避免了「模型因缺乏資訊而無法正確回答」的混淆，確保評估的是模型的推理與決策能力，而非資訊擷取能力。

**互動式評估 (Interactive Evaluation)**

在代理任務完成類別中，SO-Arena 採用沙盒 (sandboxes) 環境進行真實互動式評估，模型需：

- 迭代執行動作 (iteratively execute actions)
- 在網頁環境 (web environments) 與工具環境 (tool environments) 中進行序列決策 (sequential decisions)
- 同時評估「動作選擇 (action selection)」與「完成驗證 (completion verification)」

完成驗證的設計尤為細緻——即使最終目標狀態 (final goal states) 相同，中間需求 (intermediate requirements) 的合規性 (compliance) 可能不同，這迫使模型理解過程而非僅看結果。

**可靠性評估的雙維度設計**

決策可靠性 (decision reliability) 的評估是 SO-Arena 最具方法論創新性的部分，包含兩個互補測量 (complementary measures)：

1. **決策穩定性 (decision stability)**：在選項集變更 (option-set changes) 下，模型是否能維持一致決策。具體做法是重新排列選項順序，觀察模型是否改變答案。
2. **缺失答案識別 (missing-answer recognition)**：當正確選項被移除時，模型是否能識別「無有效選項 (no valid option)」的情況，而非強行選擇一個錯誤答案。

這兩個維度結合形成一個獨立於能力的可靠性分數，揭示了「能答對」與「答得可靠」之間的本質差異。

**系統一與系統二比較設計**

方法論上特別設計了推理密集型任務 (reasoning-intensive tasks)，在匹配的任務條件 (matched task conditions) 下比較：

- 直接系統一決策 (direct System One decisions)
- 顯式系統二推理 (explicit System Two reasoning)

此設計使兩種範式的比較具有公平性，避免因任務不同而產生的混淆。

### 潛在風險與注意事項

**風險一：能力與可靠性脫鉤導致選型誤判**
僅看整體準確率可能選出「看起來很強但實際上會在邊界案例胡亂作答」的模型。緩解方式：務必將可靠性分數作為獨立的選型門檻，特別是在安全敏感場景中。

**風險二：領域表現不均導致泛化誤判**
論文明確指出「擴展與額外推理的效益在不同領域間差異極大」，整體排名無法代表特定領域表現。緩解方式：依業務領域權重自訂評分，而非直接採用論文的等權重排行榜。

**風險三：互動式評估的環境偏差**
沙盒環境與真實生產環境存在落差，模型在受控環境中的表現未必能完全外推。緩解方式：搭配小規模的真實環境 A/B 測試驗證，並關注「完成驗證」指標以發現代理在長程任務中的隱性失敗。

**風險四：參考標籤的證據依賴性**
SO-Arena 強調參考標籤必須由模型可見證據支持，若業務場景中存在模型無法取得的隱藏資訊，評估結果可能失真。緩解方式：在採用評估結果前，先審視各任務的資訊可見性是否符合自身業務情境。

**風險五：評估成本隨模型規模膨脹**
System Two 參考模型雖表現領先，但推論成本顯著高於 System One 模型。緩解方式：建立「成本—能力—可靠性」三維決策矩陣，明確各場景可接受的延遲與成本上限。

**風險六：難度分層的領域耦合性**
論文的難度分層採領域特定標準，跨領域比較時需注意難度定義不可直接對等。緩解方式：在跨領域分析時以相對排名而非絕對分數進行比較。
