# SynthDocBench：針對長上下文視覺文件理解的控制式基準測試

## ⚡ TL;DR

現有長上下文視覺文件基準混淆多項因子，難以診斷視覺語言模型失效原因。
該基準透過LLM流程端到端生成六種版面原型，並以40%隨機覆寫避免模型學到虛假相關。
評測七個前沿模型發現三種失效模式：隨長度與複雜度劇降、中段位置敏感性，以及長文件中圖表理解崩潰。

## 摘要翻譯

視覺語言模型（Vision Language Models, VLMs）在 DocVQA、ChartQA 與 MMLongBench-Doc 等視覺文件理解（Visual Document Understanding）基準測試上已展現強勁表現。然而，真實世界文件結合了長度、版面複雜度（Layout Complexity）、模態（Modality）與問題難度（Question Difficulty）等多種因素，使得難以將模型失效歸因於特定原因。我們提出 SynthDocBench，一個針對長上下文視覺文件理解（Long-Context Visual Document Understanding）的完全合成基準測試，系統性地控制文件長度（Document Length）、版面結構（Layout Structure）、模態組成（Modality Composition）與問題類型（Question Type）等因素。該基準測試採用組合設計（Combinatorial Design）建構，每項因素在生成的文件中獨立變化，以實現對模型行為的控制式分析。文件透過大型語言模型流程（LLM Pipeline）端對端生成，涵蓋六種版面原型（Layout Archetypes），並引入 40% 的隨機覆寫（Random Override）機制，以防止模型利用虛假相關性（Spurious Correlations）。此外，SynthDocBench 所涵蓋的長上下文文件，其長度與結構多樣性均顯著高於現有基準測試。我們評估了七個前沿視覺語言模型，發現三種現有基準測試無法揭示的失效模式（Failure Modes）：隨文件長度增加而急遽惡化、系統性的位置敏感性（Positional Sensitivity）：文件的中間三分之一對六個模型中的五個來說最困難，且六個模型中有五個呈現負向的由前至後趨勢（Early-to-Late Trend），最大降幅達 8.3 個百分點，以及長文件設定下圖表理解（Chart Comprehension）的崩壞。這些結果顯示，當前模型可能過度擬合基準測試的人為特徵，而非達成穩健的長上下文視覺文件理解。

### 核心貢獻（3～5點）
- 提出 SynthDocBench：首個針對長上下文視覺文件理解的完全合成控制式基準測試，透過組合設計獨立控制文件長度、版面結構、模態組成與問題類型等變因。
- 建立端到端文件生成流程：以大型語言模型流程生成涵蓋六種版面原型的文件，並引入 40% 隨機覆寫機制以抑制虛假相關性。
- 揭示現有基準測試無法發現的三種失效模式：模型表現隨文件長度急遽下降、系統性的位置敏感性（中段最困難且多數模型呈現負向由前至後趨勢），以及長文件情境下圖表理解崩壞。
- 提供兼具高生態效度與可解釋性的評測框架：文件長度與結構多樣性顯著超越現有基準，支援對模型行為的細緻歸因分析。

### 適合對象
從事視覺語言模型、文件理解、多模態評測與長上下文建模研究的學者與工程師；特別適合關注模型失效分析、基準測試設計，以及希望了解當前前沿模型在複雜長文件情境下穩健性的讀者。

## 深度分析

#### 方法論解析

**SynthDocBench** 的核心方法論是將長上下文視覺文件理解（Long-Context Visual Document Understanding）這一高度混雜的任務，拆解為數個可獨立操縱的實驗因子（experimental factors）：文件長度（document length）、頁面深度（page depth）、模態組成（modality composition）與問題類型／難度（question type / difficulty）。這種組合設計（combinatorial design）讓研究者能夠將模型失效歸因到特定原因，而非僅得到一個無法解釋的總體分數。

在資料生成端，作者採用一個全自動化的大型語言模型流程（LLM pipeline），端到端生成文件。該流程包含兩個關鍵設計：

1. **雙層文件設計（dual-layer document design）**：每張圖表同時以 D3.js 視覺化形式渲染，並伴隨一個隱藏的結構化後設資料區塊（structured metadata block）。後設資料僅用於推導標準答案，因此答案在構造上即為確定性（deterministic by construction），避免了人工標註的不一致或模糊性。
2. **版面原型（layout archetypes）與隨機覆寫（random override）**：文件橫跨六種版面原型，並對 40% 的內容進行隨機覆寫，以防止模型利用版面或內容上的虛假相關性（spurious correlations）投機作答。

SynthDocBench 進一步釋出為三個任務導向子集：

- **charts**：涵蓋 24 種 D3.js 圖表類型，包括啞鈴圖（dumbbell chart）、棒棒糖圖（lollipop chart）、斜率圖（slope chart）與 sparkline grids 等視覺上容易混淆的形式，要求模型進行精確數值讀取，且無法僅靠周圍文字推論。
- **cross_modal**：將輔助圖表與佐證文字分置於文件的不同、非相鄰區段，測試模型在長距離依賴（long-range dependencies）下的跨模態對齊（cross-modal grounding）。
- **complex**：要求模型整合 2 至 4 個來自文字與圖表的證據單元（evidence units），難度從 L1 的直接數值查詢到 L5 的跨節點綜合推理（cross-section synthesis）。

整體而言，SynthDocBench 平均文件長度達 51.1 頁，遠超 DocVQA、ChartQA 等單頁或短篇基準，也超過 MMLongBench-Doc 的 47.5 頁，並在文字密度與結構多樣性上佔據獨特位置。

#### 實驗數據解讀

作者評估了七個前沿視覺語言模型（Vision Language Models, VLMs），並透過 GPT-5 與 Gemini 作為評判者（as-judge）進行交叉驗證。兩位評判者在所有問題類型上的準確率（accuracy）差異小於 3.5 個百分點，相關係數 r ≥ 0.94，顯示評分結果具有高度穩健性。

實驗揭示了現有基準難以浮現的三種失效模式（failure modes）：

1. **隨證據複雜度與推理深度急遽退化**：從 L1 到 L5，模型表現隨問題難度增加而顯著下降。這說明當前模型在簡單查詢上可能已趨近飽和（saturation），但在需要多步推理與跨模態整合的複雜問題上仍然脆弱。
2. **系統性的位置敏感性（positional sensitivity）**：在六個模型中，有五個模型對文件中段（middle third）的表現最差；同樣有五個模型呈現負向的由前至後趨勢（negative Early-to-Late trend），其中最陡的下降達 8.3 個百分點。這與純文字長上下文領域中觀察到的「lost in the middle」現象一致，顯示多模態文件理解同樣受到位置偏誤影響。
3. **長文件情境下圖表理解崩解（collapse of chart comprehension）**：即使某些模型在 ChartQA 等孤立圖表基準上表現良好，一旦圖表嵌入長文件脈絡，精確讀圖能力便明顯下滑。這暗示現有圖表理解能力可能部分建立在對孤立圖表統計規律的過度擬合（overfitting to benchmark artifacts），而非真正穩健的視覺數值推理。

這三種失效模式並非彼此獨立：長文件帶來的分散注意力、跨頁證據整合（cross-page evidence integration）的困難，以及版面複雜度（layout complexity）的提升，會共同放大模型的錯誤率。SynthDocBench 的價值正在於能夠將這些交互作用拆解為可量化的單一變因效應。

#### 與現有研究的比較

相較於既有基準，SynthDocBench 的定位可從以下幾個面向理解：

- **與 ChartQA、ChartQA Pro、VisuLogic、ChartMuseum 的比較**：這些基準專注於孤立圖表（isolated charts）或孤立影像（isolated images）的圖表推理，雖然能精細診斷圖表本身的邏輯與感知推理，但無法評估圖表在真實文件脈絡中的理解。SynthDocBench 將圖表置於長文件中，並要求結合周圍文字與表格進行聯合推理（joint reasoning）。
- **與 DocVQA、MP-DocVQA、SlideVQA 的比較**：這些基準主要處理單頁或約二十頁內的文件，且多數聚焦於跨頁跨度擷取（span extraction）。SynthDocBench 則將平均長度推進到 51.1 頁，並強調跨頁證據整合與跨模態推理。
- **與 MMLongBench-Doc、LongDocURL、M-LongDoc 的比較**：這些長上下文文件基準雖然涵蓋真實文件，但真實資料的缺點在於混淆因子（confounds）無法分離——答案深度、呈現模態、版面密度與跨頁證據整合往往共同變化。SynthDocBench 以合成資料換取可解釋性（interpretability），透過組合設計讓各因子獨立變化，從而進行因果式的診斷分析。
- **與 ChartGalaxy 的比較**：ChartGalaxy 展示了以大規模程式化生成達成圖表類型多樣性的可行性，SynthDocBench 則進一步將此合成方法論擴展到完整文件層級，並結合文字、表格與圖表的多模態生成。

然而，SynthDocBench 的設計也伴隨權衡：

- **生態效度（ecological validity）的折損**：合成文件雖然可控，但在視覺風格、語言分佈與真實世界雜訊方面可能與實際文件有落差。
- **生成器偏誤（generator bias）**：文件與問題皆由 LLM 生成，可能繼承模型的語言偏好或推理模式，進而影響對受測模型的診斷效度。
- **規模相對有限**：相較於 ChartGalaxy 的百萬級圖表，SynthDocBench 僅包含 200 份文件、3,340 張圖表與 1,788 道問題，雖足以進行控制式診斷，但對於訓練導向的應用可能資料量不足。

#### 可重現性評估

根據論文所述，SynthDocBench 以三個任務導向子集的形式釋出，並採用確定性生成流程，理論上具備良好的可重現性（reproducibility）。雙層文件設計意味著只要使用相同的後設資料與 D3.js 渲染參數，即可重新產生一致的視覺文件與標準答案。

不過，從可重現性的實務角度，仍有幾點需要確認：

- **開源程式碼與資料集**：論文提及釋出子集，但未在提供的片段中詳細說明是否公開完整的 LLM pipeline、提示詞（prompts）、D3.js 模板與後設資料格式。完整的可重現性需要這些元件一併開放。
- **模型權重與推論細節**：七個受測前沿 VLMs 的模型權重（model weights）多數由各家機構提供，但論文是否公開完整的推論設定（解析度、取樣參數、上下文長度限制等）會影響結果複製。
- **評判者一致性**：雖然 GPT-5 與 Gemini 的評分一致性很高，但自動評判器本身可能對答案格式或數值近似有不同的容忍度，建議作者釋出評分腳本與範例，以便其他研究者驗證。
- **隨機覆寫種子**：為了確保不同實驗間的可比性，隨機覆寫機制所使用的亂數種子與覆寫規則應詳細記錄。

整體而言，SynthDocBench 在方法論層面具備可重現的潛力，但實際重現程度仍取決於作者後續釋出的完整程式碼與文件。

#### 未來研究方向

SynthDocBench 的診斷框架為長上下文視覺文件理解開啟了多個後續研究方向：

1. **從診斷到訓練**：將 SynthDocBench 的合成資料用於微調或持續預訓練（continual pre-training），觀察是否能有效緩解位置敏感性與長文件圖表理解崩解的問題。
2. **真實與合成資料的橋接**：發展領域適應（domain adaptation）或風格遷移技術，使在 SynthDocBench 上訓練或診斷出的能力能遷移到真實 PDF、財報、法律文件等場景。
3. **位置偏誤的機制研究**：深入分析為何文件中段最難，並探索緩解策略，例如基於頁面重要性重新取樣、層級式摘要（hierarchical summarization）或專門的長上下文注意力機制。
4. **更開放的生成式評估**：目前問題多為可評分的數值或簡答形式，未來可擴展到開放式回答（open-ended generation）、多輪對話與文件摘要，並發展更細緻的評判標準。
5. **多語言與多文化文件**：現有合成流程可能以英文為主，未來可擴展到中文、日文等具有不同書寫方向與版面慣例的語言。
6. **動態與互動文件**：將靜態文件延伸至包含互動式圖表、表格篩選或超連結的動態文件，進一步貼近現代網頁與儀表板（dashboard）應用。
7. **因果歸因方法**：結合模型內部注意力軌跡或對抗式樣本生成，建立從 SynthDocBench 的受控變因到模型錯誤的因果歸因鏈。
8. **與人類表現的對照**：進行人類受試者實驗，以確認哪些失效模式源於任務本身困難，哪些則是模型特有的限制，從而更準確地評估生態效度與實用影響。

## 論文問答

【背景與動機】

**Q1：視覺語言模型在長上下文視覺文件理解上面臨什麼核心挑戰？為何這個問題重要？**
A：真實世界的文件通常橫跨數十到數百頁，並交錯文字、表格、圖表與複雜版面結構，這要求模型同時具備長距離檢索與跨模態推理能力。然而，當模型在這類文件上失敗時，研究者很難判斷失敗是來自文件長度、版面複雜度、模態組成還是問題難度，因為這些因子在真實文件中互相混淆。因此，能夠獨立控制這些變因的評測方式，對於診斷模型弱點與推動穩健的視覺文件理解至關重要。

**Q2：現有的 DocVQA、ChartQA 與 MMLongBench-Doc 等基準測試為何難以診斷模型失效？**
A：DocVQA 與 ChartQA 多聚焦於單頁或孤立圖表，已接近表現飽和，無法反映圖表在長文件脈絡中的真實理解難度。MMLongBench-Doc、LongDocURL 與 M-LongDoc 雖然納入長文件，但使用真實文件，導致答案深度、呈現模態、版面密度與跨頁證據整合等混淆因子同時變動，難以歸因失敗原因。此外，這些基準大多未要求模型同時對圖表與分散在遠距離頁面的文字進行聯合推理，因此無法揭露長上下文下的圖表理解崩潰等問題。

**Q3：為什麼需要合成式、控制式基準測試？這樣的設計犧牲了什麼？**
A：合成基準測試透過程式化生成資料，能將文件長度、頁面深度、模態組成與問題類型設為獨立控制軸，讓研究者可以精確歸因模型失敗到特定原因。這種方法繼承了 bAbI、SCAN、CLEVR 等經典合成基準的精神，以生態效度換取可解釋性與診斷力。相對地，由於文件是人工生成而非真實世界文件，其外觀與雜訊分布可能較為規則，因此結果在推廣到極度混亂的真實文件時需要額外驗證。

【方法與創新】

**Q4：SynthDocBench 的核心方法論是什麼？它如何系統性地控制各項因子？**
A：SynthDocBench 採用組合設計，將文件長度、頁面深度、模態組成與問題類型作為可獨立變動的軸向，透過端到端的大型語言模型流程生成文件。該流程涵蓋六種版面原型，並橫跨 24 種 D3.js 圖表類型，平均文件長度達 51.1 頁，包含 200 份文件、3,340 張圖表與 1,788 道問題。這種控制式設計讓研究者得以在保持其他因子不變的情況下單獨檢驗特定變因，而不會被真實文件中相互糾結的混淆因子所干擾。

**Q5：SynthDocBench 包含哪三個任務子集？它們各自測試什麼能力？**
A：SynthDocBench 釋出為 chart、cross_modal 與 complex 三個子集。chart 子集涵蓋 24 種 D3.js 圖表類型，包括啞鈴圖、棒棒糖圖、斜率圖與 sparkline 網格等視覺上容易混淆的形式，要求模型進行精確數值判讀，無法僅靠周圍文字推論。cross_modal 子集將支援性圖表與佐證文字分散在不同且不相鄰的區段，測試模型在長距離依賴下進行跨模態對應的能力；complex 子集則要求模型整合兩到四個來自文字與圖表的證據單元，並依難度 L1 到 L5 進行從直接查值到跨節點綜合的推理。

**Q6：什麼是「雙層文件設計」與「40% 隨機覆寫」？它們為何重要？**
A：雙層文件設計是指每張圖表在生成時，同時產生可視覺化的 D3.js 圖表與僅用於推導正確答案的隱藏結構化後設資料區塊，使答案在構造上即為確定性，避免人工標註錯誤。40% 隨機覆寫機制則是在生成過程中有意識地打亂部分預設模式，防止模型利用版面或內容上的虛假相關性來投機取巧。這兩項設計確保了評測分數能真實反映模型的理解與推理能力，而非對資料生成偏差的過度擬合。

【實驗與結果】

**Q7：實驗評估了哪些模型？最重要的三項發現是什麼？**
A：論文評估了七個前沿視覺語言模型，並透過 GPT-5 與 Gemini 作為評判者進行交叉驗證，兩者準確率差距在 3.5 個百分點以內，相關係數 r ≥ 0.94。實驗發現模型隨著證據複雜度與推理深度從 L1 提升到 L5，表現出急劇衰退；同時出現系統性的位置敏感性，即文件中段對多數模型最困難，且由前至後的表現呈現負向趨勢，最大跌幅達 8.3 個百分點。此外，即使在孤立圖表基準上表現良好的模型，在長文件情境下的精確圖表讀取能力也會崩潰。

**Q8：SynthDocBench 揭露的位置敏感性現象具體內容為何？**
A：研究發現，在文件長度增加時，資訊所在位置會顯著影響模型正確率，其中文件的中間三分之一對五個受測模型來說是最困難的區段。同時，五個模型呈現負向的 Early-to-Late 趨勢，也就是從文件前段到後段，正確率持續下降，最明顯的模型跌幅達到 8.3 個百分點。這種系統性的位置偏差顯示，現有模型可能依賴位置捷徑或注意力機制的偏態，而非真正均勻地理解整份長文件。

**Q9：除了主要結果，論文還進行了哪些穩健性檢查？**
A：為了確保評分結果可靠，作者使用 GPT-5 與 Gemini 作為自動評判者，對所有問題類型進行交叉評分，結果顯示兩者準確率差異不超過 3.5 個百分點，且相關係數 r 達到 0.94 以上。這表示不同評判模型對答案正確與否的判斷高度一致，增強了實驗發現的可信度。此外，透過 40% 隨機覆寫與六種版面原型的多樣化設計，也降低了模型因記憶特定生成樣式而獲得不實高分的風險。

【應用與影響】

**Q10：產品團隊可以如何運用 SynthDocBench？**
A：產品團隊可以利用 SynthDocBench 在部署前系統性診斷視覺語言模型在長文件、圖表判讀與跨模態整合上的弱點，並針對性地改進模型或調整應用流程。例如，若發現模型在文件中段表現特別差，團隊可考慮在檢索增強生成系統中強化中段內容的召回策略，或對長文件進行分段重排。由於 SynthDocBench 的控制軸清晰，團隊也能根據自身產品場景，優先選擇與其文件長度、版面結構與模態組成最相關的子集進行評測。

**Q11：哪些實際應用場景最能受惠於這類長上下文視覺文件理解評測？**
A：財務報告、科學論文、法律合約、技術手冊與醫療病歷等文件，通常包含數十頁以上的文字、表格與圖表，且答案常需整合跨頁資訊，因此特別需要長上下文視覺文件理解能力。SynthDocBench 能幫助開發者了解模型在這些場景中是否會因文件長度、資訊位置或圖表類型而失效。透過這樣的診斷，產品可以更穩健地提供摘要、問答、稽核與決策支援等功能。

**Q12：SynthDocBench 對視覺語言模型研究領域可能帶來什麼影響？**
A：SynthDocBench 提供了一個可解釋的診斷工具，使研究者能從單一的分數飽和現象，轉向分析模型在長度、位置、模態與推理深度上的具體失效模式。這有助於引導未來模型架構與訓練資料的設計，特別是改善長距離注意力、跨模態對齊與精確圖表閱讀能力。長遠來看，這類控制式基準能促使領域發展出更穩健、更少依賴基準測試假影的真實文件理解系統。

【限制與未來方向】

**Q13：SynthDocBench 有哪些已知的限制？**
A：由於 SynthDocBench 是完全合成的基準測試，其文件內容與版面雖然多樣，但仍可能缺乏真實文件中常見的掃描雜訊、非標準字型、手寫註記與語意上的細微歧義。因此，其生態效度相對於真實文件基準較低，高分並不保證模型在真實世界文件中同樣表現優異。此外，目前的研究主要聚焦於英文與特定圖表類型，對於多語言、多欄位複雜版面或動態互動式文件的覆蓋仍有限。

**Q14：根據實驗結果，模型在哪些情況下仍會明顯失敗？**
A：當問題需要整合多個分散在文件不同位置的文字與圖表證據時，模型正確率會隨著證據數量與推理步驟增加而顯著下降。此外，即使模型在 ChartQA 等孤立圖表基準上表現良好，一旦圖表被嵌入長文件脈絡中，其精確數值判讀能力便會崩潰。模型也對資訊位置過度敏感，文件中段與後段的內容較容易被忽略或誤解，顯示其長上下文理解仍不夠均勻與穩健。

**Q15：未來研究可以朝哪些方向延伸 SynthDocBench？**
A：未來可以將合成控制與真實文件結合，建立混合式基準，以同時保留可解釋性並提升生態效度。也可以擴展到更多模態，例如手寫文字、流程圖、地圖與互動式視覺化，並納入多語言與更複雜的版面原型。此外，針對位置敏感性與圖表理解崩潰等失效模式，未來可設計專門的訓練資料與模型架構，例如改進長距離注意力機制、引入圖表專用編碼器，或發展能主動重新排序與檢索文件內容的代理系統。

## 實務應用指南

## 適用場景

1. **長文件智慧問答與稽核系統**  
   企業內部動輒數十頁的財報、法規遵循文件、合約或技術手冊，常混合格式化文字、表格與圖表。SynthDocBench 的受控設計可協助團隊診斷：當 VLM 在這類文件中答錯時，究竟是因為文件太長、證據位於中段、圖表閱讀失準，還是跨模態推理不足。

2. **金融與醫療圖表長文件分析**  
   投資研究報告、病患長期追蹤病歷或臨床試驗文件，常把關鍵數據圖表與解釋文字分散在不同章節。利用本研究的版面原型與跨模態任務設計，可建立專屬測試集，評估模型在「圖表＋遠距文字」聯合推理上的穩健度。

3. **法律與合規文件審查**  
   法律條文、判決書或合約附件往往超過 50 頁，且證據鏈橫跨多頁。透過控制文件長度與頁面深度，產品團隊能找出模型最容易遺漏的區段（例如中段資訊），並據此設計檢索增強或分段策略。

4. **模型選型與採購評估**  
   當企業評估不同商用或開源 VLM 時，可用 SynthDocBench 的組合設計產生標準化壓力測試，比較各模型在長上下文、複雜版面與多模態證據整合上的表現，避免被單一飽和基準誤導。

5. **教育與教材自動解題與輔助閱讀**  
   教科書、講義與學術論文同時包含文字、圖表與公式。依據本研究的 L1–L5 難度分級與 24 種圖表類型，可設計由淺入深的診斷題組，協助開發適應學生程度的互動式學習助手。

## 實作前置條件

**資料條件**
- 雖然 SynthDocBench 是合成生成，但仍需準備高品質的「領域知識種子」：例如產業常用詞彙、數值範圍、圖表語意模板與版面風格規範，作為 LLM 生成文件內容的約束條件。
- 若要用於特定領域（如醫療或法律），需額外準備去識別化真實文件樣本，以校準版面原型與問題類型，確保生態效度不會過低。

**運算條件**
- **生成端**：需能執行 D3.js 渲染的環境（Node.js + Puppeteer 或 Playwright），並搭配可呼叫的大型語言模型 API（如 GPT-4/GPT-5、Gemini、Claude）進行端到端文件與題目生成。
- **推論端**：測試 frontier VLM 需準備足夠的 GPU 或 API 額度；長上下文推理成本與延遲會隨頁數顯著上升，建議預留每份文件數千至數萬 token 的預算。
- **評估端**：需部署自動評分腳本與至少一個 judge model（如 GPT-5 或 Gemini-as-judge）進行跨評審穩健性檢查。

**技能條件**
- 熟悉多模態模型推論與 prompt engineering。
- 具備前端視覺化能力（D3.js、HTML/CSS）以產生與微調圖表。
- 具備資料分析與實驗設計能力，能操作組合設計並解讀位置敏感性、難度梯度等指標。
- 建議具備領域知識，以設計合理的答案推導邏輯與 ground-truth 驗證。

## 實作步驟建議

1. **定義診斷目標與控制軸**  
   根據產品場景選擇要獨立變動的因子：文件長度（頁數）、頁面深度（證據位置）、模態組成（純文字、文字＋表格、文字＋圖表、混合）、問題類型（L1 直接查詢到 L5 跨節綜合）。

2. **建立版面原型與內容模板**  
   參考論文的六種版面原型，設計符合自身領域的文件結構；同時為每種原型準備文字段落、表格欄位與 D3.js 圖表規格，並保留隱藏結構化 metadata 區塊作為 ground truth。

3. **實作 LLM 生成管線**  
   讓 LLM 同時產生：(a) 可視覺渲染的文件內容與 D3.js 圖表；(b) 隱藏 metadata，記錄每個數值、圖表類型與證據位置。接著自動渲染成 PDF 或圖像序列，並由程式依 metadata 推導正確答案。

4. **加入隨機覆寫機制**  
   在生成過程中保留約 40% 的隨機覆寫，例如調換圖表類型、改變數值範圍或打亂版面元素，避免模型學到版面位置或固定用語等虛假相關性。

5. **建構三類任務子集**  
   依照論文架構，分別建立：
   - **chart**：測試 24 種 D3.js 圖表的精確數值讀取；
   - **cross_modal**：把圖表與佐證文字放在非相鄰區段，測試長距離跨模態對齊；
   - **complex**：設計需要 2–4 個證據單元、橫跨 L1–L5 的綜合推理題。

6. **執行模型評估與交叉評審**  
   對目標 VLM 進行批次推論，使用 exact match 或數值容差評分，並以 GPT-5 / Gemini-as-judge 進行二次驗證，確保評分一致性（目標可參考 r ≥ 0.94、差距 ≤ 3.5 百分點）。

7. **分析失效模式並迭代產品設計**  
   檢視三項關鍵指標：隨長度與難度遞增的效能衰退、中段與前後段的位置敏感性、長文件中圖表理解崩潰。根據結果決定是否引入檢索增強生成（RAG）、分段摘要、或專用圖表解析模組。

## 潛在風險與注意事項

- **生態效度與真實文件落差**  
  合成資料雖然可控，但可能缺乏真實世界中的掃描雜訊、手寫批註、非標準排版與語意含糊。建議在產品上線前，以真實文件樣本進行額外驗證，避免過度優化合成基準。

- **模型對合成風格的過度擬合**  
  即使加入 40% 隨機覆寫，若圖表風格、字型、配色過於單一，模型仍可能學到風格捷徑。應定期擴充樣式變化（顏色主題、字級、邊界、解析度）並監控跨風格表現。

- **Ground-truth 推導錯誤**  
  自動由 metadata 產生答案雖然確定性高，但若 LLM 生成管線本身產生語意不一致或數值矛盾，會連帶污染標籤。建議抽樣人工複查，特別是 L4–L5 綜合題。

- **長上下文成本與延遲**  
  平均 51 頁的文件會帶來高額 API 費用與長時間等待。實務上可先以較短文件篩選模型，再針對通過門檻的模型進行長上下文壓力測試。

- **位置敏感性的產品影響**  
  若發現模型對中段資訊特別弱，應避免把關鍵結論放在文件中央；或搭配主動檢索、重排（reranking）與多輪摘要來補強。

- **Judge model 偏誤**  
  不同 judge model 對開放式答案的評分標準可能不同，建議至少使用兩個獨立 judge 並報告一致性，對爭議題目引入人工仲裁。

## 與其他技術的整合建議

- **檢索增強生成（RAG）**  
  針對長文件的位置敏感性與長距離檢索困難，可將 SynthDocBench 的版面原型與證據位置標註作為訓練資料，學習更精準的跨頁段落與圖表召回策略。

- **專用圖表解析模組**  
  對於圖表理解崩潰的問題，可串接專門的 chart-to-table 模型或視覺解析工具，先將圖表轉為結構化表格，再交由 VLM 進行問答。

- **文件版面分析（Document Layout Analysis）**  
  整合版面偵測模型以自動識別標題、段落、表格、圖表區塊，並將 SynthDocBench 的六種版面原型作為預訓練或微調資料，提升對複雜排版的理解。

- **多智能體或分層摘要系統**  
  對於超過 50 頁的文件，可先由一個模型產生章節摘要與圖表索引，再由主模型根據問題定位相關區段，降低長上下文雜訊。

- **持續評測與模型監控平台**  
  將 SynthDocBench 的組合設計嵌入 CI/CD 流程，定期對新版本模型進行回歸測試，監控長度、深度、模態、問題類型四軸的效能變化。

**AI 工程師**

**研究人員**  
建議深入閱讀組合設計、六種版面原型、24 種圖表類型與 L1–L5 問題難度分級的方法論；並留意跨評審穩健性檢查的設計，這對後續設計可解釋、可重複的長上下文多模態評測具有參考價值。

**產品經理**  
把重點放在適用場景、潛在風險與整合建議；理解位置敏感性與圖表理解崩潰對使用者體驗的影響，並據此規劇產品功能優先順序，例如優先強化文件中段資訊的召回、或為圖表密集文件設計專屬互動介面。
