## ⚡ TL;DR

現有多智能體框架在競賽程式設計中缺乏狀態累積，無法傳承過往解題與除錯經驗。
提出Solvita以四智能體閉環搭配圖知識網路，透過強化學習動態路由，不更新底層模型而持續演化。
在多項基準創最佳成績，GPT-5.4骨幹的pass@1從40%躍升至82.4%，幾乎翻倍單次基準。

## 摘要翻譯

大型語言模型（Large Language Models, LLMs）在面對高難度競賽程式設計（Competitive Programming）的嚴謹推理需求時仍難以應對。儘管近期的多智能體框架（Multi-agent Frameworks）試圖彌補此可靠性差距，但它們本質上仍屬無狀態（Stateless）：依賴靜態檢索（Static Retrieval），並捨棄了從先前任務中獲得的寶貴解題與除錯經驗。為解決此問題，我們提出 Solvita，一個智能體演化（Agentic Evolution）框架，能夠在不對底層大型語言模型進行權重更新（Weight Updates）的情況下實現持續學習。Solvita 將解題流程重構為一個閉環系統（Closed-loop System），包含策略選擇（Strategy Selection）、程式合成、認證式監督與針對性攻擊，並由四個專門的智能體執行：Planner、Solver、Oracle 與 Hacker。關鍵在於，每個智能體都配有一個可訓練的圖結構知識網路。當系統運作時，諸如通過與否的判定結果、測試驗證品質，以及由 Hacker 發現的對抗性漏洞等結果訊號，會被轉化為針對這些網路權重的強化學習（Reinforcement Learning）更新。這使得各智能體能夠根據過去的成功與失敗動態導引後續查詢，並隨時間有效地累積可遷移的推理經驗。在 CodeContests、APPS、AetherCode 與實際舉辦的 Codeforces 賽事上的評測結果顯示，Solvita 在程式生成智能體中達到新的最先進水準（state-of-the-art），超越現有的多智能體流程，且相較單次生成基線，準確率提升近一倍。

## 深度分析

#### 方法論解析

Solvita 的核心貢獻在於提出一套 Agentic Evolution（智能體演化）機制，使 LLM（Large Language Model，大型語言模型）無需進行 Weight Updates（權重更新）即可累積跨任務的推理經驗。框架由四個專職智能體構成 Closed-loop System（閉環系統）：Planner（規劃器）負責 Strategy Selection（策略選擇）與問題正規化；Solver（求解器）執行程式合成與基於搜尋取代（search-and-replace）的 Patch-based Repair（修補式修復），避免完整重生成的高額成本；Oracle（神諭驗證者）建構經認證的內部測試套件，提供品質監督訊號；Hacker（駭客）則發動 Targeted Hacking（針對性攻擊），挖掘 Adversarial Vulnerabilities（對抗性弱點）。四者透過閉環串接，使任何失敗訊號能跨智能體傳播並觸發交叉修正。

與傳統 Stateless（無狀態）管線不同，Solvita 為每位智能體配置一組 Graph-structured Knowledge Network（圖結構化知識網路）。該網路以問題查詢、後設認知分析與可複用演算法技能為節點，透過邊權重動態學習問題與策略間的映射。當系統運作時，Oracle 產生的 Test Certification Quality（測試認證品質）與 Hacker 發現的對抗性弱點等 Outcome Signals（結果訊號），被重新鑄造為 Reinforcement Learning（強化學習，RL）的更新目標，僅調整知識網路的邊權重，而底層 LLM 參數保持凍結。這將記憶機制從 Static Retrieval（靜態檢索）的平面文件庫，轉化為可學習的主動路由機制，並在智能體當前遭遇困難的區域精確擴張。

在資料層面，研究團隊從 Codeforces、AtCoder、Aizu Online Judge、LeetCode 等異質平台收集原始題目，經 Schema Unification（模式統一）轉為標準 JSON 後，執行四階段過濾：Completeness（完整性）篩選確保具備公開與隱藏測試、演算法標籤與難度訊號；Tag Load Balancing（標籤負載平衡）限制單一標籤上限以避免分布偏斜；Deduplication（去重複）透過 text-embedding-3-large 計算餘弦相似度；Difficulty Pruning（難度剪枝）則剔除過於簡單的題目。最終從 30,018 題收斂至 8,017 題，形成高品質的 Cold-start Corpus（冷啟動語料庫），為知識網路提供初始訓練基礎。

#### 實驗數據解讀

Solvita 的評估橫跨 CodeContests、APPS、AetherCode 以及 Live Codeforces Rounds（現場 Codeforces 賽事）。在靜態基準測試中，採用 GPT-5.4 作為 Backbone Model（骨幹模型）時，CodeContests 的 Pass@1 Accuracy（pass@1 準確率）從 Single-pass Baseline（單次通過基準線）的 40.0% 提升至 82.4%，幾乎翻倍。此增幅並非來自無限制的 Token Consumption（詞元消耗），因為其足跡與現有多智能體管線相近，顯示效率與效能同步優化。

更值得關注的是 Live Codeforces Rounds 的驗證。靜態資料集可能存在資料污染或過擬合風險，而現場賽事提供真正未見的問題與即時評測環境。Solvita 在此設定下仍達到 Code-generation Agents（程式生成智能體）中的 State-of-the-art（最佳水準），強調其經驗累積機制具備真實世界的一般化能力。數據亦暗示，隨著處理題目串流（stream of tasks）的增加，知識網路學習到的 Routing Weights（路由權重）能持續將問題導向正確策略與失效預防戰術，實現單調遞增的推理能力成長。

#### 與現有研究的比較

現有 LLM 競賽程式設計的主流範式仍為 Single-shot Generation（單次生成），將理解、規劃、編碼與驗證混為一體的單一巨集呼叫。近期 Multi-agent Frameworks（多智能體框架）如 AlphaCodium 與 MapCoder 雖引入階層式規劃與迭代精煉，但其本質仍屬 Stateless（無狀態）：每道新題皆從零開始，過去錯誤累積的經驗被完全丟棄。RAG（Retrieval-augmented Generation，檢索增強生成）變體試圖注入記憶，卻僅執行 Static Retrieval（靜態檢索）的相似度查詢，將原始文本塞回提示並未根本改變底層推理程序。

Solvita 的差異化在於三點。第一，經驗的可遷移性：透過圖結構化知識網路，系統學習「何種策略適配何種問題結構」，類比資深人類程式設計師的模式識別。第二，對抗性內建循環：Hacker 智能體在提交前主動攻擊自身解法，這在既有管線中極為罕見，能顯著降低在隱藏測試上意外失敗的機率。第三，參數效率：在不觸動 LLM 龐大參數的前提下，僅以輕量級的網路邊權重更新達成持續學習，規避了完整微調的計算與災難性遺忘成本。

然而，框架亦存在侷限。四智能體協調的複雜度顯著高於線性管線，任何一環的延遲或錯誤傳播皆可能放大。知識網路的 Cold-start（冷啟動）依賴精心篩選的 8,017 題語料庫，若領域轉移至缺乏大規模標註資料的場景，收斂速度可能受限。此外，圖網路的規模隨經驗累積而增長，長期運作下的推理延遲與記憶體佔用需進一步評估。最後，部分結果基於 GPT-5.4 這類高階骨幹模型，其在較弱基礎模型上的增益幅度仍有待驗證。

#### 可重現性評估

從提供的文本脈絡檢視，Solvita 在方法論層面具備相對完整的敘述：資料過濾的四階段參數（如餘弦相似度閾值 δ、各標籤難度下限、上限）詳列於附錄 A，圖結構化知識網路的更新邏輯與強化學習訊號定義亦有所交代。然而，就開放科學（Open Science）標準而言，目前未見原始碼倉庫、釋出的模型權重或統一化 JSON 語料庫的下載連結。

具體而言，重現門檻包含以下挑戰。其一，原始語料來自多個競賽平台的直接抓取，涉及網站結構變動與使用條款限制，研究團隊若未公開去識別化後的統一資料集，外部研究者難以完全複製 8,017 題的最終分佈。其二，Graph-structured Knowledge Network（圖結構化知識網路）的實作細節（如圖神經網路層數、節點編碼器架構、RL 演算法選型）在摘要與引言中尚未揭露，缺乏這些超參數將無法重建訓練循環。其三，實驗使用 GPT-5.4 作為骨幹，該模型的可取得性與版本控制本身即構成重現變數。因此，當前論文的可重現性仍停留在「方法可理解」階段，距離「實驗可複製」尚須官方釋出程式碼與中繼資料。

#### 未來研究方向

Solvita 開啟了以智能體層級記憶取代模型微調的嶄新路徑，後續研究可沿多軸展開。第一，混合式學習：將知識網路的路由策略與輕量級的 LLM 參數更新（如 LoRA）結合，探討宏觀記憶與微觀參數知識的互補效應。第二，跨領域遷移：驗證 Agentic Evolution（智能體演化）機制是否適用於數學證明、形式邏輯驗證或科學推理等同樣需要嚴謹結構化思考的領域。第三，強化對抗性測試：為 Hacker（駭客）引入 Fuzzing（模糊測試）或 Symbolic Execution（符號執行），提升弱點發現的系統性與數學完備性。第四，持續學習理論：深入研究圖網路邊權重的 Catastrophic Forgetting（災難性遺忘）與收斂性質，確保長期累積經驗時的穩定性。第五，效率與可解釋性：將學習到的路由策略蒸餾為可讀的提示模板或決策規則，降低推理延遲並增強人機協作透明度。最後，多模態擴展：競賽題目常含圖表與數學式，未來可讓 Planner（規劃器）處理視覺輸入，建構真正的多模態競賽求解系統。

## 論文問答

**Q1：競賽程式設計對大型語言模型構成了什麼根本挑戰，為何它成為評估結構化推理的標準試驗場？**

A：競賽程式設計要求將自然語言規格轉譯為正確且高效的程式，這涉及精確的形式化、審慎的策略選擇以及嚴格的驗證。這類任務在受控環境中完整捕捉了結構化推理的嚴苛需求，因此成為評估大型語言模型能力的標準試驗場。然而，現有模型在面對高難度題目時，仍難以滿足這些嚴謹的推理要求，顯示出單次生成範式的根本侷限。

**Q2：現有的多智能體框架與檢索增強生成方法為何無法彌補競賽程式設計中的可靠性落差？**

A：現有的多智能體框架本質上仍屬無狀態，每道新題目都從零開始解決，導致過去除錯與解題的寶貴經驗被完全丟棄。檢索增強生成變體雖試圖加入記憶，但僅將檢索視為靜態的相似度查詢，把原始文本注入提示並未根本改變底層的推理流程。相較之下，人類程式設計師的進步正是來自累積可遷移的經驗，而這些現有方法無法複製這種隨時間持續學習的能力。

**Q3：為何累積可遷移的經驗對競賽程式設計智能體至關重要？**

A：可遷移經驗的累積使智能體能夠學習哪些策略適合特定的問題結構，並識別某些實作為何容易在特定邊界條件下失敗。若缺乏這種經驗，智能體將重複犯下相同的錯誤，無法針對未來的相似挑戰動態調整推理方式。透過持續學習，先前的解題與除錯歷程能直接塑造後續問題的處理路徑，從而顯著提升解題效率與準確率。

**Q4：Solvita 的核心架構為何，四個專業化智能體如何協同運作？**

A：Solvita 將解題流程重組為一個閉環系統，包含負責策略選擇與問題正規化的 Planner、負責程式合成與基於修補之修復的 Solver、負責建構經認證內部測試套組的 Oracle，以及負責發動針對性對抗攻擊的 Hacker。這四個智能體緊密協作，使失敗訊號能夠在整個系統中傳播，實現跨智能體的交叉修正與協同改進。這種互動式閉環確保了程式合成、驗證與對抗發現能持續相互啟發與約束，形成動態的問題解決生態。

**Q5：Solvita 實現「無需更新底層大型語言模型權重即可持續學習」的關鍵創新是什麼？**

A：其關鍵創新在於為每個智能體配備一個可訓練的圖結構知識網路，作為宏觀層級的記憶機制。系統將通過與否的裁決、測試認證品質以及對抗弱點等結果訊號，重新定義為強化學習的更新訊號，用以動態調整這些網路的路由權重。這種設計將記憶從被動檢索轉化為主動學習的路由機制，讓底層保持凍結的大型語言模型在使用過程中單調地提升整體推理能力。

**Q6：Solvita 為何選擇圖結構知識網路與基於修補的修復方式，而非傳統的靜態檢索與完整重生成？**

A：圖結構知識網路能夠連結問題查詢、後設認知分析與可重用的演算法技能，並根據學習到的結果動態調整路由，而非僅依賴靜態語意相似度。Solver 使用搜尋與取代的修補方式，能在保留部分正確程式結構的同時進行針對性修正，節省大量 token 消耗並避免全盤捨棄已有進度。這些設計選擇共同建構了一個高效率、以經驗為導向的系統，能夠精確地在智能體當前遭遇困難的領域擴展能力。

**Q7：Solvita 在哪些基準測試與平台上進行了評估？**

A：Solvita 在多個基準測試上進行了全面評估，包括 CodeContests、APPS、AetherCode 以及現場的 Codeforces 比賽。其訓練語料直接來自 Codeforces、AtCoder、Aizu Online Judge、LeetCode、SPOJ 與 UOJ 等多個異質性的競賽程式設計平台。這種跨平台、跨難度的多樣化評估，確保了該框架能夠泛化至不同風格與難度層級的演算法問題。

**Q8：Solvita 取得了哪些最關鍵的量化成果？**

A：在 CodeContests 基準上，即使底層僅使用凍結的 GPT-5.4 模型，Solvita 仍將 pass@1 準確率從單次生成的 40.0% 大幅提升至 82.4%，幾乎將冷啟動基準翻倍，且 token 消耗量與現有多智能體流程相當。這項成果使 Solvita 在多個基準上成為程式生成智能體的新 state-of-the-art。這些結果證明，透過智能體演化與學習式路由，無需更新大型語言模型權重即可顯著增強其解題能力。

**Q9：Solvita 的訓練語料是如何建構的，四階段過濾管線為何重要？**

A：研究團隊從 30,018 道原始題目開始，經過統一 JSON 綱要後，依序執行完整性檢查、標籤負載平衡、嵌入去重與難度修剪等四階段過濾，最終得到 8,017 道高品質題目。這套精心設計的過濾管線確保了語料具備完整的測試資料與演算法標籤，同時避免少數熱門標籤主導分布並移除冗餘與過於簡單的題目。如此嚴謹的資料處理對於知識網路至關重要，因為它能防止訓練偏頗，並確保智能體從有意義且非重複的問題結構中學習。

**Q10：除了基準評估，Solvita 在哪些實務場景中具有應用潛力？**

A：在實務應用上，Solvita 可作為智慧輔導系統，透過跨練習階段累積經驗，針對學生反覆出現的錯誤類型進行適應性指導。它也能驅動自動化的程式面試平台，利用 Oracle 與 Hacker 生成嚴格的測試案例與對抗挑戰，全面驗證應試者的解決方案。此外，專業軟體工程師可借助 Solvita 不斷演化的策略庫，處理大型系統中複雜的演算法元件設計。

**Q11：將 Solvita 部署於真實產品環境時，需要考量哪些關鍵因素？**

A：在產品化部署時，由於僅更新知識網路權重而無需微調底層大型語言模型，基礎設施成本與運算開銷相對可控。然而，系統需要高品質的冷啟動語料庫以及持續的線上互動才能達到最佳效能，這意味著必須提供穩定的題目流或長期的使用者參與。此外，隨著競賽趨勢演變，圖結構記憶中的路由權重可能累積偏見或過時，因此需要定期監控與適當的遺忘或更新機制。

**Q12：Solvita 可能對大型語言模型推理與多智能體系統領域帶來什麼廣泛影響？**

A：Solvita 證明了透過可訓練的知識網路作為宏觀記憶，可以在不更新大型語言模型權重的情況下實現能力的單調提升。這種從靜態管線轉向動態、經驗驅動生態系統的典範轉移，可能啟發數學推理、形式化驗證與科學發現等領域的類似架構。透過證明具備結構化記憶的智能體回饋迴路優於無狀態的多智能體流程，Solvita 為工具增強型大型語言模型系統中的持續學習設立了新的標竿。

**Q13：Solvita 的設計中存在哪些與生俱來的限制？**

A：Solvita 的設計仍依賴高品質的冷啟動語料庫，在極度缺乏資料的領域中，圖網路可能因缺乏足夠的種子邊而無法進行有意義的路由。其次，由於底層大型語言模型保持凍結，框架無法從根本上擴展基礎模型既有的潛在知識或推理容量上限。此外，Oracle 與 Hacker 的效能取決於可執行環境與測試基礎設施的完備性，這對於某些程式語言或封閉系統而言可能難以建置。

**Q14：在什麼條件下 Solvita 可能會失效或表現不佳？**

A：Solvita 可能在題目需要訓練語料中完全未出現的全新演算法典範時表現不佳，因為知識網路將無法路由至有效的對應策略。若 Oracle 生成的內部測試強度不足，或 Hacker 未能發現潛在的對抗弱點，強化學習訊號會變得嘈雜，甚至可能強化次優的路由權重。另外，當初始解決方案的結構性錯誤超出局部修補範圍時，Solver 基於搜尋與取代的修復機制可能難以奏效，此時系統仍需面對完整重生成所帶來的挑戰。

**Q15：基於 Solvita 的架構，未來有哪些值得探索的研究方向？**

A：研究者可以將 Solvita 的閉環演化機制擴展至數學證明或形式化驗證等其他結構化推理任務，以驗證其通用性。另一個方向是讓知識網路支援跨語言與多模態的問題描述，從而處理包含圖表或數學式子的複雜題目。此外，在真實的線上競賽環境中即時部署 Solvita，觀察其面對全新題型與動態對手策略時的適應速度，也是極具價值的實證研究方向。

## 實務應用指南

### 適用場景

**1. 企業內部自動化程式碼審查與漏洞挖掘**
利用 Oracle 智能體自動生成認證級測試套件，並由 Hacker 智能體主動發掘邊界條件漏洞，適用於金融、醫療等對程式正確性要求極高的產業。系統在每次審查後透過知識網絡累積常見漏洞模式，逐步提升對特定程式碼壞味的偵測率。

**2. 競賽程式設計培訓與解題平台**
將 Solvita 部署為教練系統，Planner 根據學生當前弱點選擇解題策略（如動態規劃、圖論），Solver 產生可執行程式碼並以 patch 方式修復錯誤。知識網絡會隨著解題歷程記錄「何種問題結構適用何種策略」，實現個人化學習路徑推薦。

**3. 遺留系統重構與現代化遷移**
針對大型單體式程式碼庫，Planner 將重構任務拆解為演算法策略選擇（例如將遞迴改寫為迭代、引入記憶化搜尋），Solver 則以 search-and-replace patch 進行局部改寫而非全量重寫，降低回歸風險。Oracle 確保重構後的輸出與原系統通過同等測試認證。

**4. 演算法交易與高頻交易腳本驗證**
在量化金融場景中，交易邏輯的邊界條件與對極端市場資料的處理至關重要。Hacker 可針對歷史極端行情生成對抗資料，Oracle 建立內部認證測試，確保交易腳本在正式上線前通過嚴格的對抗性驗證，且知識網絡會記錄特定市場模式與適用演算法的對應關係。

**5. 教育科技中的個人化演算法導師**
將 Solvita 作為後端引擎，為每位學習者維護獨立的知識網絡子圖。當學生在特定標籤（如「區間 DP」或「並查集」）反覆失敗時，系統自動強化該節點與相關解題策略之間的連結權重，動態調整未來出題難度與提示方向。

### 實作前置條件

**資料條件**
- 需準備帶有**公開與隱藏測試集**、**演算法標籤**、**難度訊號**（如平台評分或等級）以及**可解析 I/O 規格**的題庫，原始資料量建議至少 3 萬題以支撐四階段過濾後仍保留 8,000 題以上的高品質語料。
- 需建立統一 JSON Schema，涵蓋題目敘述、型別宣告、約束邊界、測資對、官方題解、提交紀錄與評測結果。
- 需劃分「訓練子集」（用於智能體演化）與「技能子集」（用於冷啟動技能庫）。

**運算條件**
- **LLM 骨幹**：需 GPT-4 級別以上的大型語言模型 API 權限，支援長上下文以容納多智能體協作歷程。
- **嵌入與圖運算**：需 text-embedding-3-large 等級的嵌入模型計算資源，以及可訓練圖結構知識網絡的環境（如 PyTorch Geometric 或自訂圖神經網絡框架）。
- **執行沙箱**：需隔離的程式碼執行環境以安全運行 Oracle 生成的測試與 Hacker 的對抗攻擊腳本。

**技能條件**
- 團隊需具備**強化學習（RL）**基礎，理解如何將通過/失敗、認證品質、對抗發現等訊號轉換為獎勵函數。
- 需熟悉**提示工程**與**多智能體協調架構**，能設計 Planner、Solver、Oracle、Hacker 的角色邊界與訊息傳遞協定。
- 需具備**競賽程式設計知識**，以便驗證系統產出的演算法策略合理性，並維護受控詞彙的標籤體系。

### 實作步驟建議

**步驟一：建構高品質冷啟動語料**
依論文所述執行四階段過濾：完整性篩選 → 標籤負載平衡（設定每標籤上限 C_max）→ 基於 text-embedding-3-large 的語意向量去重（餘弦相似度門檻 δ）→ 難度修剪（依平台難度設定各標籤下限 d_min^(τ)）。此階段決定知識網絡的初始品質，不可省略。

**步驟二：初始化圖結構知識網絡**
以技能子集中的經典題目與官方題解為節點，建立「問題查詢—後設認知分析—可複用演算法技能」的三層圖結構。初始邊權重可基於共現頻率或專家規則設定，後續交由強化學習動態調整。

**步驟三：設計智能體提示與協作協定**
- **Planner**：設計提示以輸出正規化後的問題結構與選定的演算法典範（paradigm）。
- **Solver**：限制其輸出為可執行程式碼與 search-and-replace patch，禁止全量重寫以節省 token。
- **Oracle**：提示需包含生成內部認證測試的規範，並輸出測試覆蓋率品質分數。
- **Hacker**：設計對抗攻擊目標，要求針對 Solver 產出發現邊界漏洞，並回報脆弱性事件。

**步驟四：建立閉環訊號與獎勵機制**
將 Oracle 回傳的「認證品質」與 Hacker 回傳的「對抗脆弱性事件」量化為純量獎勵。使用策略梯度或類似方法更新各智能體對應知識網絡的邊權重，**保持底層 LLM 權重凍結**。確保失敗訊號可跨智能體傳播（例如 Hacker 發現漏洞 → Solver 獲得負向獎勵 → Planner 調整策略選擇）。

**步驟五：漸進式領域部署**
先針對單一標籤（如「陣列+雜湊」）或單一難度區間進行封閉測試，監控知識網絡的邊權重收斂情形。驗證通過後，再擴展至多標籤與全難度範圍，避免早期獎勵稀疏導致訓練震盪。

**步驟六：持續監控與人機協作審查**
定期抽樣檢視 Planner 的路由決策解釋性（例如為何選擇特定策略），並由領域專家標註錯誤路由，作為額外監督訊號注入知識網絡，防止強化學習在稀疏獎勵下收斂至局部最優。

### 潛在風險與注意事項

**冷啟動偏差風險**
若初期資料過濾不嚴格（例如未執行標籤負載平衡），知識網絡會過度偏向高頻標籤（如「實作題」），導致 Planner 在面對稀有題型時策略選擇失準。**緩解措施**：嚴格執行四階段過濾，並在冷啟動時為低頻標籤人工注入專家示範軌跡。

**獎勵訊號稀疏與延遲**
競賽題目的通過/失敗多為二元訊號，且回饋週期長（需完整執行測試），可能導致 RL 更新效率低下。**緩解措施**：善用 Oracle 的「測試認證品質」與 Hacker 的「脆弱性發現位置」作為稠密輔助獎勵，拆解單一解題軌跡為多個中間決策點。

**知識網絡的災難性遺忘**
雖然 LLM 權重凍結，但圖網絡在持續學習新題型時，可能覆寫早期學到的有效路由。**緩解措施**：實施經驗回放機制（experience replay），定期將歷史高獎勵軌跡重新注入訓練緩衝區；或採用彈性權重鞏固（EWC）的變體保護重要邊權重。

**計算與 Token 成本失控**
四智能體閉環加上多次 LLM 呼叫，單題成本可能遠超單次生成基線。**緩解措施**：為 Solver 設置 patch 次數上限；為 Hacker 設置對抗嘗試預算；當 Oracle 認證品質達門檻後提前停止循環。論文顯示 Solvita 可在與現有多智能體管線相近的 token 消耗下達成更高準確率，但需謹慎實施早期停止。

**對抗攻擊的安全性風險**
Hacker 生成的對抗測試可能包含惡意輸入或觸發不安全系統呼叫。**緩解措施**：所有程式碼執行必須在隔離沙箱中進行，限制執行時間、記憶體與系統呼叫白名單，並對 Hacker 的輸出進行靜態分析過濾。

### 與其他技術的整合建議

**與現有 IDE 與編輯器整合**
可透過 Language Server Protocol（LSP）或 VS Code / JetBrains 外掛形式，將 Solvita 的 Planner 策略建議與 Solver patch 直接嵌入開發者工作流程。開發者撰寫程式碼時，Planner 即時提示「此問題結構建議使用單調隊列優化」，Solver 則提供可應用的程式碼片段 patch。

**與 CI/CD 管線整合**
將 Oracle 模組作為自動化測試生成引擎，於合併請求（Pull Request）階段自動補充邊界測試案例；Hacker 模組則作為模糊測試（fuzzing）前置步驟，在正式部署前發掘潛在崩潰點。知識網絡可隨著每次 CI 執行累積該程式碼庫的常見失敗模式。

**與傳統 RAG 系統整合**
Solvita 的知識網絡可作為 RAG 的**動態路由層**。傳統 RAG 僅依語意相似度檢索相關題解文本，而 Solvita 的圖網絡能依據過往成功/失敗經驗，動態調整檢索路徑與提示組裝方式。建議將兩者結合：以 RAG 召回候選文本，再以知識網絡決定最終注入提示的內容與順序。

**與輕量模型微調管線整合**
雖然論文核心主張不更新 LLM 權重，但企業可定期將 Solvita 在閉環中產生的高品質「問題—策略—程式碼」三元組，用於輕量級的 LoRA 或 prompt tuning。此舉能讓底層 LLM 的冷啟動表現更接近 Solvita 演化後的狀態，縮短新部署環境的收斂時間。

### 給不同背景讀者的閱讀建議

**給初學者**
請將 Solvita 想像為一支由四位專家組成的解題團隊：Planner 負責擬定作戰計畫、Solver 負責寫程式與修 bug、Oracle 負責出考題驗證、Hacker 則扮演找碴角色。閱讀時請優先理解這四個角色如何透過「閉環」互相修正，暫時跳過強化學習與圖神經網絡的數學細節，把重點放在「為什麼記住失敗經驗能讓系統越變越強」這個核心概念上。

**給 AI 工程師**
請聚焦於第 3 節的框架實作細節，特別是「知識網絡」的圖結構設計、各智能體間的訊息傳遞格式，以及如何将通過/失敗、認證品質、對抗發現等異質訊號統一為可訓練的獎勵函數。建議深入評估 search-and-replace patch 相較於全量重寫在 token 效率與收斂穩定性上的實務權衡，並留意四階段資料過濾管線中各參數（δ、C_max、d_min）對下游效能的敏感度。

**給研究人員**
本文的核心貢獻在於「無需權重更新即可實現持續學習」的機制設計。請重點檢視知識網絡作為巨觀記憶體（macro-level memory）的理論定位：它如何將被動檢索轉化為主動路由？圖結構相較於 flat document store 或傳統 RAG 在可解釋性與組合泛化上有何優勢？此外，論文以 CodeContests、APPS、Codeforces 等嚴苛基準驗證，建議關注其與單次生成、靜態多步驟管線（如 AlphaCodium、MapCoder）的對照實驗設計與統計顯著性。

**給產品經理**
請理解 Solvita 並非「下單即產出」的一次性生成工具，而是需要**前期資料投資**與**持續運營**的經驗累積型系統。導入前需評估貴組織是否具備足夠的帶標籤題庫與測試資源，以及是否能承受初期的冷啟動成本。產品設計上應預留「人機協作審查介面」，讓領域專家能糾正 Planner 的策略路由，因為知識網絡的學習曲線在前期的提升幅度最為顯著（論文顯示 pass@1 從 40.0% 提升至 82.4%），適合作為長期競爭護城河而非短期功能賣點。
