# 我們的模型建立在哪些模型之上？稽核現代大型語言模型中不可見的相依性

**原文標題：** Which Models Are Our Models Built On? Auditing Invisible Dependencies in Modern LLMs  
**作者：** Sanjay Adhikesaven、Haoxiang Sun、Sewon Min  
**發布日期：** 2026-06-10  
**HF 連結：** [https://huggingface.co/papers/2606.12385](https://huggingface.co/papers/2606.12385)  
**arXiv：** [https://arxiv.org/abs/2606.12385](https://arxiv.org/abs/2606.12385)  

---

## ⚡ TL;DR

現代大型語言模型的遞迴式相依關係散落於異質公開文件中，難以人工追溯，導致授權、污染與評估偏誤等風險。
本文提出 ModSleuth，以遞迴重建與產物識別技術，從異質文件還原語言模型的相依性圖譜。
應用於四個公開模型，重建出千餘筆溯源證實的相依關係，揭露多跳授權義務、訓練評估耦合及文件不一致等問題。

## 摘要翻譯

現代大型語言模型（Modern LLM）的訓練管線日益依賴其他模型來進行資料生成（data generation）、語料庫過濾（corpus filtering）、評判輸出，並指導開發決策。這些相依性（dependency）是遞迴的：一個模型可能依賴某個上游產物（upstream artifact），而該產物自身的相依性僅記載於個別的發布版本與產物中。因此，完整的相依性結構分散於異質（heterogeneous）的公開產物（public artifact）之間，其複雜度與遞迴深度已遠超人類的追溯能力。我們提出 ModSleuth，這是一個以溯源證據（source-grounded evidence）為基礎，從公開產物中遞迴式重建（recursive reconstruction）大型語言模型相依性圖譜（dependency graph）的代理系統（agentic system）。我們發現，主要的挑戰不再是資訊擷取，而是定義何謂相依性，以及調和文件不一致性（documentation inconsistency）中的產物引用。我們透過形式化方法來解決這些挑戰，該方法區分直接相依性（direct dependency）與間接相依性（indirect dependency），透過以操作為中心的關係（operation-centered relationship）來表示異質的管線角色（pipeline role），並解決跨名稱、版本與儲存庫（repository）的產物識別（artifact identity）問題。我們將 ModSleuth 應用於四個公開產物豐富的大型語言模型發布版本，復原了 1,060 個經來源驗證的相依性，並建構了現代大型語言模型開發的大規模相依性圖譜。這些圖譜揭示了多跳授權義務（multi-hop license obligation）、訓練與評估耦合（train-evaluation coupling）、已發布產物與訓練階段產物之間的差異，以及在其他情況下難以發現的文件不一致性。我們公開釋出 ModSleuth 以及所產生的相依性圖譜，以支持對現代大型語言模型底層日益複雜生態系統的透明化分析。

### 核心貢獻（3～5點）
- 提出形式化框架，區分直接相依性與間接相依性，並透過以操作為中心的關係表示異質管線角色，同時解決跨名稱、版本與儲存庫的產物識別問題。
- 設計並實作 ModSleuth 代理系統，從公開產物中遞迴式重建大型語言模型的相依性圖譜，並以溯源證據驗證每筆相依性。
- 針對四個公開產物豐富的大型語言模型發布版本進行稽核，復原 1,060 個經來源驗證的相依性，建構大規模相依性圖譜。
- 透過圖譜分析揭示多跳授權義務、訓練與評估耦合、已發布產物與訓練階段產物的差異，以及文件不一致性等隱藏風險。
- 公開釋出 ModSleuth 工具與所得相依性圖譜，以支持現代大型語言模型底層生態系統的透明化分析。

### 適合對象
大型語言模型研究者、機器學習工程師、開源治理與授權合規專業人員，以及關注 AI 供應鏈透明度與模型溯源之政策制定者。

## 深度分析

#### 方法論解析

本研究提出的 ModSleuth 是一個代理系統 (agentic system)，旨在從異質 (heterogeneous) 的公開產物 (public artifact)——如技術報告 (technical report)、模型卡 (model card)、儲存庫 (repository) 與資料集——中執行遞迴式重建 (recursive reconstruction)，以還原現代大型語言模型 (Modern LLM) 的相依性圖譜 (dependency graph)。與傳統資訊抽取任務不同，作者明確指出當前瓶頸已非資料擷取能力，而是語義與表徵層面的挑戰：究竟何謂「相依性」，以及如何在名稱、版本、模型家族與開發階段均不一致的文件中完成產物識別 (artifact identity)。

為此，ModSleuth 建立了一套形式化框架。首先，它區分直接相依性 (direct dependency)——即實質影響模型權重 (weight) 的上游產物——與間接相依性 (indirect dependency)——即僅影響開發決策（如評估基準選擇、資料篩選策略）但未進入訓練流程的產物。其次，框架採用以操作為中心的關係 (operation-centered relationship) 來描述管線角色 (pipeline role)，將邊緣語義從籠統的「使用」細分為資料生成 (data generation)、語料庫過濾 (corpus filtering)、重寫 (rewriting)、光學字元辨識（OCR 系統, OCR system）、評估 (evaluation)、偏好學習 (preference learning) 等具體操作。這使得同一個上游模型（例如 Qwen 3 32B）可因同時扮演直接偏好最佳化 (DPO, Direct Preference Optimization) 資料生成器與強化學習 (RL, Reinforcement Learning) 評判模型 (judge model) 而被賦予不同語義的邊。

在產物識別 (artifact identity) 上，ModSleuth 引入 identity lattice 機制，透過層次化比對解決跨來源的名稱歧義、版本號碼差異與儲存庫 (repository) 分散問題，確保同一個上游產物在不同公開產物 (public artifact) 中被正確歸一。整個流程強制要求溯源證據 (source-grounded evidence)：每條相依性邊都必須附帶可回溯至原始文件的明確出處，從而避免幻覺式推論。

#### 實驗數據解讀

研究團隊將 ModSleuth 應用於四個公開產物豐富的現代大型語言模型 (Modern LLM) 釋出版本（包含 Olmo 3、DR Tulu、SmolLM 3 等），共復原 1,060 條經溯源證據 (source-grounded evidence) 驗證的相依性，並建構出大規模相依性圖譜 (dependency graph)。數據顯示，相依性鏈 (dependency chain) 的深度可達八跳 (eight hops)，遠超人工追溯能力，顯示當前 LLM 生態系統的遞迴結構極為深層。

具體案例分析揭示數項關鍵現象：

1. **文件不一致性 (documentation inconsistency) 與 Underreporting**：DR Tulu 的監督式微調 (SFT, Supervised Fine-Tuning) 資料透過 ScholarQA 追溯至 Claude Sonnet 3.7，但此關係在原始文件中並未被明確記載。這顯示模型開發者本身可能未完整掌握上游合成資料集 (synthetic dataset) 的來源。

2. **多跳授權義務 (multi-hop license obligation)**：SmolLM 3 的 FineMath 資料集透過一個以 Llama 3 Instruct 訓練的分類器進行品質篩選，導致 Llama 的授權限制 (license restriction) 透過間接路徑傳播。這類路徑若無遞迴式重建，極易被標準的譜系 (lineage) 追蹤所忽略。

3. **訓練與評估耦合 (train-evaluation coupling) 與遞迴偏好迴路**：Olmo 3 在 IFEval 衍生資料上進行訓練，同時又將 IFEval 作為評估基準，形成資料污染 (data contamination) 風險；Qwen 3 32B 則同時充當 DPO 階段的生成器與 RL 階段的評判模型 (judge model)，使偏好訊號可能產生自我強化的偏差。

這些發現表明，標準去污染 (decontamination) 流程僅針對直接訓練語料，無法處理經由多跳路徑傳播的資料污染；而授權與使用條款風險亦會隨著合成資料集 (synthetic dataset) 的遞迴使用而靜默擴散。

#### 與現有研究的比較

現有揭露機制 (disclosure mechanism)——如模型卡 (model card)、資料卡 (data card) 與資料表 (datasheet)——雖提供有用的綱要，但本研究指出它們本質上過於扁平，無法捕捉現代 LLM 開發中遞迴、多階段的管線角色 (pipeline role)。既有生態系統映射 (ecosystem mapping) 與資料集溯源 (dataset provenance) 研究多聚焦於初始化 (initialization) 或訓練資料的譜系 (lineage)，未能涵蓋上游模型透過評估、偏好學習 (preference learning)、語料庫過濾 (corpus filtering) 或重寫模型 (rewriting model) 等多元方式影響下游模型的情境。

另一方面，透過權重或行為訊號 (behavioral signal) 進行的血統推論 (ancestry inference) 雖能推測模型間的傳承關係，但缺乏明確的溯源證據 (source-grounded evidence)，也無法區分直接相依性 (direct dependency) 與間接相依性 (indirect dependency)。ModSleuth 的核心貢獻在於將「操作」置於中心，以操作為中心的關係 (operation-centered relationship) 精確描繪了模型對模型的多元影響，而非僅止於資料流或權重繼承。

然而，本研究亦坦承其限制：ModSleuth 僅能辨識「已宣告的相依性」(declared dependencies)，因此復原結果僅代表實際相依性的下限 (lower bound)。若某模型（如部分封閉系統）的公開產物 (public artifact) 稀缺，其在圖譜中可能顯得孤立，這並不代表該模型真正獨立於上游產物。跨模型比較時必須謹慎解讀，避免因揭露程度差異而得出錯誤結論。

#### 可重現性評估

作者已公開釋出 ModSleuth 系統與重建後的相依性圖譜 (dependency graph)，為後續研究提供可驗證的基礎。方法論上，由於每條相依性邊均要求附帶溯源證據 (source-grounded evidence)，第三方原則上可依據提供的原始出處連結人工驗證每一筆邊的真實性，這大幅提升了結果的可信度。

不過，可重現性仍受若干因素制約。首先，整個流程高度依賴公開產物 (public artifact) 的持續可用性；若技術報告 (technical report)、儲存庫 (repository) 或資料集在釋出後被修改、移除或轉移，則特定相依性鏈可能難以完全復現。其次，ModSleuth 作為代理系統 (agentic system)（其實作參考了 Claude Code 等工具），其資訊擷取過程可能存在非確定性行為，不同執行間或許會產生差異；儘管溯源證據要求可壓抑幻覺，但自動化代理在面對異質 (heterogeneous) 文件格式時的解析穩定性仍需持續監控。

此外，由於系統僅追蹤已宣告的相依性，任何重現實驗都必須理解這是一個帶有系統性偏差的「下限」估計，而非完整生態的全貌。產物識別 (artifact identity) 所使用的 identity lattice 雖有效解決當前命名不一致問題，但其規則與對照表需要持續維護，以適應未來不斷湧現的新模型家族、版本號碼慣例與分散式儲存庫 (repository) 結構。

#### 未來研究方向

基於 ModSleuth 所揭示的結構性缺口，未來研究可朝以下方向推進：

1. **從宣告式到真實相依性**：結合血統推論 (ancestry inference) 與行為訊號 (behavioral signal) 分析，發展能偵測「未揭露但真實存在」之相依性的技術，彌補目前僅能發現下限的限制。

2. **自動化授權與治理工具**：基於已建構的相依性圖譜 (dependency graph)，開發能自動追蹤與預警多跳授權義務 (multi-hop license obligation) 傳播的系統，協助開發者與法務人員評估授權限制 (license restriction) 風險。

3. **多跳去污染 (decontamination) 機制**：現有去污染方法無法處理經由合成資料集 (synthetic dataset) 與評判模型 (judge model) 遞迴擴散的資料污染 (data contamination)。未來需設計能於相依性圖譜上執行多跳路徑分析的去污染演算法。

4. **文件標準化與揭露機制強化**：推動模型卡 (model card) 與資料卡 (data card) 納入標準化的「上游操作」欄位，減少產物識別 (artifact identity) 負擔，從源頭降低遞迴式重建的難度。

5. **擴展至封閉與部分開放生態**：儘管 GPT 4.1、Claude Sonnet 3.7 等系統的公開產物 (public artifact) 有限，但未來可嘗試透過 API 文件、第三方資料集與行為比對進行有限追溯，以理解封閉系統在生態系統中的樞紐角色。

6. **動態相依性圖譜**：目前圖譜為靜態快照。未來可探索隨儲存庫 (repository) 與資料集版本迭代自動更新的動態系統，即時反映上游釋出或撤回所造成的生態變動。

7. **跨模態管線角色分析**：將以操作為中心的關係 (operation-centered relationship) 擴展至多模態場景，深入分析 OCR 系統 (OCR system)、重寫模型 (rewriting model) 與視覺-語言模型間的交互相依性，並評估其對模型崩潰 (model collapse) 與偏差強化 (bias reinforcement) 的影響。

## 論文問答

**Q1：現代大型語言模型在開發過程中出現了什麼樣的結構性透明化問題？**
A：現代 LLM 的訓練管線越來越依賴其他模型來生成資料、過濾語料庫、評判輸出與引導開發決策，形成了深度遞迴的相依結構。這些相依鏈散落在技術報告、模型卡、儲存庫與資料集等異質公開產物中，文件記載往往碎片化且不一致，導致其複雜度與遞迴深度遠超人類手動追溯的能力。因此，即便是模型開發者本身，也難以完整掌握上游產物的全貌，造成了結構性的透明化缺口。

**Q2：為何現有的揭露機制與稽核方法無法有效捕捉現代 LLM 的相依性？**
A：現有的揭露機制如模型卡、資料表與資料卡雖然提供了有用的架構，但通常過於扁平且內容不完整，無法捕捉多階段且遞迴的模型—模型相依關係。既有的稽核方法多聚焦於狹隘的譜系概念，例如權重初始化或訓練資料來源，卻忽略了上游模型以過濾、重寫、OCR、評估等多元方式塑造下游模型的影響。這些方法未能涵蓋現代管線中各種以操作為中心的關係，因此無法完整呈現 LLM 生態系統的真實複雜度。

**Q3：這種看不見的相依性若未被揭露，會對模型開發與使用帶來哪些具體風險？**
A：若缺乏透明的相依結構，授權限制可能透過多跳合成資料集靜默傳播，導致潛在的授權與使用條款爭議；資料污染也可能沿著多跳路徑層層擴散，使標準的去污染程序無法有效追蹤。此外，當評判模型與被評估系統共享祖先或訓練資料時，會產生訓練與評估耦合的循環性偏誤，進而損害評估的公正性與模型的可信度。

**Q4：ModSleuth 的核心運作方式為何？它如何從公開產物中重建相依性圖譜？**
A：ModSleuth 是一個代理系統，能夠遞迴地從技術報告、模型卡、儲存庫與資料集等公開產物中擷取資訊，並以溯源證據為基礎重建 LLM 的相依性圖譜。它利用近期代理能力的進展來處理資訊擷取，並透過遞迴探查每個上游產物自身的文件，將分散在各處的相依鏈串連起來。最終，系統會產出大規模的相依性圖譜，清楚呈現模型之間的直接與間接關係及其操作角色。

**Q5：相較於傳統的資訊擷取，ModSleuth 面臨的主要挑戰與核心創新是什麼？**
A：研究發現主要挑戰已不再是資訊擷取本身，而是語義與表徵層面的問題：如何定義「相依性」的構成，以及如何在名稱、版本、模型家族與儲存庫不一致的文件中調解產物識別。為此，作者提出了一套形式化框架，區分會實質影響模型權重的直接相依性，以及僅影響開發決策卻未進入訓練的間接相依性，並透過以操作為中心的關係來表徵異質管線角色。此外，系統引入身分格理論來統一解析不同來源對同一產物的指涉，從而解決異質文件間的參照不一致問題。

**Q6：ModSleuth 為何選擇採用「以操作為中心的關係」來表徵相依性，而非僅記錄資料或權重的傳遞？**
A：因為現代 LLM 開發中的上游模型扮演極其多元的角色，包括合成資料生成、語料庫過濾、重寫、光學字元辨識與評估等，這些影響無法被簡化為單純的「初始化」或「資料集衍生」關係。採用以操作為中心的關係能更精確地捕捉上游產物究竟以何種方式介入下游模型的開發管線，無論其是否直接改變模型權重。這種設計選擇使得相依性圖譜能夠反映真實的開發生態，而非僅呈現扁平的資料流。

**Q7：研究團隊將 ModSleuth 應用於哪些模型釋出，並從中回收了多少經過來源驗證的相依性？**
A：研究團隊將 ModSleuth 應用於四個公開產物豐富的 LLM 釋出，成功回收了 1,060 個經過來源驗證的相依性，並據此建構了大規模的相依性圖譜。這些圖譜顯示相依鏈可長達八跳，涵蓋了遠比過往認知更廣泛且更具組合性的生態系統。分析對象包括 Olmo 3、DR Tulu、SmolLM 3 與 Qwen 3 32B 等模型，揭示了它們在訓練與評估過程中複雜且深度的上游連結。

**Q8：重建後的相依性圖譜揭示了現代 LLM 生態系統中哪些令人擔憂的具體現象？**
A：圖譜揭示了多項令人擔憂的實務現象，包括多跳授權義務、訓練與評估耦合、釋出文件與實際訓練產物之間的差異，以及跨文件的不一致性。例如，DR Tulu 的監督式微調軌跡透過 ScholarQA 回溯至 Claude Sonnet 3.7；SmolLM 3 的 FineMath 則透過以 Llama 訓練的分類器連結到受 Llama 授權規範的產物；Olmo 3 則出現在 IFEval 衍生資料上訓練卻同時用其評估的耦合情況。這些發現顯示，當前開發實務中存在著連原始開發者都未必知曉的隱藏相依路徑。

**Q9：研究結果顯示，這些被揭露的相依性與模型開發者自身認知之間存在什麼樣的落差？**
A：在若干案例中，ModSleuth 所恢復的相依性連開發者本身都未曾察覺，這顯示問題不僅源於個別疏忽，更反映了當前開發與稽核實務中的結構性限制。由於相依資訊分散在技術報告、程式碼儲存庫與模型卡等不同媒介中，且缺乏統一的報告規範，開發團隊難以全面掌握遞迴上游的全貌。這項發現強調，單靠人工揭露已不足以應對現代 LLM 的深度遞迴生態，必須借助自動化代理系統進行結構性重建。

**Q10：ModSleuth 與其產出的相依性圖譜可如何應用於實務中的模型治理與合規查核？**
A：ModSleuth 與其相依性圖譜為模型治理提供了可驗證的基礎，使稽核人員能夠系統性地追蹤多跳授權義務，避免授權限制在合成資料或過濾管線中靜默傳播。企業與研究機構可利用這些圖譜在部署前進行盡職調查，確認上游產物的使用條款是否與下游應用相容，降低法律風險。此外，透過視覺化訓練與評估之間的耦合關係，開發團隊也能及早發現潛在的資料污染或評估偏誤，從而提升模型的可靠性與負責任的使用。

**Q11：對於希望提升透明度的模型釋出方，這項研究提出了哪些具體的產品與文件改進建議？**
A：研究指出，模型釋出方應超越傳統扁平的模型卡或資料卡，提供能夠反映遞迴、多階段相依性的結構化文件，並統一產物在不同儲存庫與版本中的命名與識別方式。釋出方應明確記載所有參與資料生成、過濾、重寫與評估的上游模型，無論其是否直接影響最終權重，以區分直接相依性與間接相依性。透過減少技術報告、程式碼與模型卡之間的文件不一致性，開發者能顯著降低外部稽核的難度，並建立更值得信賴的釋出流程。

**Q12：這項研究對整個 LLM 生態系統的未來發展與學術研究可能帶來什麼樣的深遠影響？**
A：這項研究揭示了現代 LLM 生態系統遠比以往認知的更加互聯且具組合性，為後續的稽核、理解與治理遞迴式 AI 系統奠定了基礎。它促使學界與業界正視模型—模型相依性的複雜度，並可能推動新一代揭露標準與生態系統映射方法的發展。長遠來看，ModSleuth 所開創的代理式遞迴重建範式，有望成為評估資料污染、模型崩潰風險與行為遺傳的重要工具，進而影響負責任 AI 的規範制定。

**Q13：作者明確指出了 ModSleuth 的哪些主要限制？**
A：作者明確指出，ModSleuth 識別的是「已宣告的相依性」而非「真實的相依性」，因此所偵測到的相依性僅代表實際相依性的下限，可能仍有大量未公開記載的上游影響未被捕捉。此外，跨模型的比較應謹慎解讀，因為某個模型看似較少或沒有相依性，可能只是由於其公開揭露的資訊有限，而非實際開發中獨立於其他模型。這項限制意味著系統的覆蓋範圍與準確性高度依賴公開產物的完整性與透明度。

**Q14：在哪些情況下，ModSleuth 可能無法正確重建或完全遺漏某些重要的相依關係？**
A：當上游產物的文件嚴重缺失、刻意隱藏，或指涉同一模型時使用了極度不一致的名稱、版本與儲存庫路徑，ModSleuth 的身分格與代理系統可能難以正確調解與匹配，導致遺漏或斷鏈。對於完全閉源的系統或僅提供極少技術細節的釋出，由於缺乏公開產物作為溯源基礎，系統幾乎無法進行有效的遞迴重建。此外，若相依性並未以文字形式記載於任何公開管道，而是僅存在於開發者的內部紀錄中，則該方法必然無法偵測。

**Q15：基於目前的研究成果與限制，未來有哪些值得探索的方向可以進一步強化 LLM 相依性的稽核能力？**
A：未來研究可朝向擴展身分格理論以處理更模糊的產物指涉、整合非文字性的行為訊號或權重分析來補足公開文件的不足，並探索如何將方法論延伸至完全閉源或部分開放的模型釋出。另一個重要方向是建立自動化的即時監測機制，在模型釋出後持續追蹤新浮現的上游相依性與文件更新，以維持圖譜的時效性。最後，將 ModSleuth 的框架與法律合規工具鏈結合，發展能夠自動標示多跳授權義務與潛在衝突的治理系統，將有助於實現更全面且可持續的 AI 生態系統透明化。

## 實務應用指南

### 適用場景

1. **開源模型發布前的合規審查**  
   在發布大型語言模型前，利用 ModSleuth 遞迴掃描技術報告、模型卡與儲存庫，重建完整的上游相依性圖譜。特別適用於偵測合成資料集與偏好學習管線中的多跳授權義務，避免 Llama 授權或商業條款透過間接路徑靜默傳播。

2. **企業內部模型供應鏈治理**  
   當組織內部微調或部署第三方模型（如 Qwen、Olmo、DR Tulu）時，透過代理系統自動追溯其訓練與評估階段使用的所有上游產物，建立企業級模型物料清單（AI-SBOM），供法務與開源治理辦公室（OSPO）審查。

3. **學術評估基準的污染排查**  
   針對公開基準（如 IFEval）或學術問答資料集，檢視其是否被下游模型同時用於訓練與評估，導致訓練與評估耦合。此場景可揭露標準去污染流程無法追溯的多跳資料污染路徑。

4. **合成資料集採購的盡職調查**  
   在採購或引用外部合成資料集（如 FineMath、ScholarQA Traces）時，驗證其生成過程中是否使用了未揭露的商業模型（如 Claude Sonnet 3.7 或 GPT-4.1），以評估授權限制與使用條款風險。

5. **第三方 API 與模型即服務（MaaS）的風險評估**  
   對於僅提供模型端點的服務商，透過其公開技術文件重建相依性圖譜，識別評判模型與獎勵模型是否與被評估模型存在血統推論上的重疊，降低評估偏差與循環驗證的風險。

### 實作前置條件

**資料需求**
- 目標模型與其上游產物的完整公開產物集合：技術報告、模型卡、資料卡、GitHub / Hugging Face 儲存庫、論文附錄。
- 結構化的授權條款資料庫（如 OSI 授權條款、Llama 社群授權、商業使用條款），用於比對多跳授權義務。
- 歷史版本對照表，以處理異質文件間的命名不一致與版本漂移。

**運算需求**
- LLM API 存取權限（建議具備長上下文與工具使用能力的代理系統，如 Claude Code 或同等級模型），用於遞迴解析與資訊擷取。
- 圖譜資料庫（如 Neo4j 或 Amazon Neptune）或 RDF 儲存系統，用於儲存與查詢大規模相依性圖譜。
- 運算負載以文字處理與圖遍歷為主，無需大規模 GPU 叢集，但需穩定的網路環境存取分散的公開產物。

**技能需求**
- 熟悉 Python 與代理系統開發框架，具備設計多步驟工具呼叫與記憶體管理的能力。
- 理解現代 LLM 訓練管線各階段（預訓練、監督式微調、直接偏好最佳化、強化學習）及其對應的上游產物角色。
- 具備授權條款基礎解讀能力，或能與法務團隊協作審查圖譜中的授權傳播路徑。
- 熟悉圖資料庫查詢語言（如 Cypher）與資料清洗管線，以實作產物識別與去重複。

### 實作步驟建議

1. **定義相依性語意與管線角色**  
   依據組織需求，先區分直接相依性（實質影響模型權重，如訓練資料生成、初始化）與間接相依性（影響開發決策但未進入訓練，如評判模型、開發階段的過濾器）。同時列舉以操作為中心的關係類型：生成、重寫、語料庫過濾、OCR、評估、偏好標註等。

2. **建立產物識別機制（Identity Lattice）**  
   在開始擷取前，先建構統一的產物識別層，將不同公開產物中出現的異質名稱、版本號、模型家族與儲存庫連結對齊到同一實體。例如將 "Llama-3-8B-Instruct"、"llama3-8b-instruct" 與對應的 Hugging Face repo ID 解析為單一節點。

3. **部署 ModSleuth 代理系統進行遞迴式重建**  
   以 LLM 代理為核心，設計遞迴工作流程：讀取目標模型的技術報告與程式碼 → 擷取上游產物引用 → 對每個上游產物重複相同流程。強制要求每條邊都附帶溯源證據（來源段落、URL、截圖或程式碼片段），避免幻覺。

4. **建構與驗證相依性圖譜**  
   將擷取結果寫入圖譜資料庫，節點為模型、資料集、工具，邊為以操作為中心的關係。執行多跳驗證：檢查技術報告與程式碼之間的文件不一致性、標註未揭露的依賴、並計算遞迴深度。

5. **風險標注與互動式視覺化**  
   在圖譜上疊加風險層：紅色標記潛在授權衝突路徑、黃色標記訓練與評估耦合、藍色標記合成資料集的遞迴生成環路。產出可互動的審計儀表板，供非技術利害關係人瀏覽。

6. **建立持續監控與更新機制**  
   將系統整合至 CI/CD 或模型發布流程，當上游模型釋出新版本、新論文或更新模型卡時，自動觸發增量掃描，維持相依性圖譜的時效性。

### 潛在風險與注意事項

1. **揭露下限（Lower Bound）風險**  
   ModSleuth 僅能識別公開產物中「已宣告」的相依性。若開發者刻意或無意未揭露某上游模型，系統無法偵測。建議將此圖譜視為實際相依性的下限，並輔以權重比對或行為訊號推論作為交叉驗證。

2. **文件不一致性導致的誤判**  
   技術報告、模型卡與程式碼儲存庫之間常存在矛盾（如論文提及使用 A 模型過濾，但程式碼預設值為 B 模型）。切勿仰賴單一來源，必須設計交叉驗證規則，並在圖譜中保留衝突標記供人工複審。

3. **授權解釋的法律風險**  
   自動化代理可能誤判授權條款的相容性（如將「僅限研究使用」與「商業友善」錯誤連結）。所有授權相關的圖譜推論應僅作為初步標注，最終解釋必須由具備法律專業的人員審定。

4. **圖譜規模爆炸與遞迴過深**  
   實務上相依鏈可達八跳以上，且每個輔助工具（如 OCR 系統、品質分類器）本身又有訓練資料，導致節點數量急劇增長。建議設定明確的遞迴終止條件，例如僅追蹤直接相依性，或排除通用基礎設施（如 PyTorch、CUDA）。

5. **代理幻覺與過度推論**  
   LLM 代理可能在缺乏明確證據時，推論出並不存在的相依性關係。必須強制要求每條邊都附帶公開產物中的原始出處，並定期進行人工抽樣驗證，確保溯源證據的真實性。

### 與其他技術的整合建議

1. **MLOps / LLMOps 平台**  
   將 ModSleuth 嵌入模型註冊表（Model Registry），在每次執行監督式微調或 RL 階段時，自動觸發相依性掃描。可與 MLflow、Weights & Biases 等實驗追蹤系統串接，將上游產物版本寫入實驗紀錄。

2. **軟體組成分析（SCA）與 SBOM 工具**  
   傳統 SCA（如 Snyk、FOSSology）專注於程式碼層級的相依性。建議將 ModSleuth 產出的「模型層級」相依性圖譜匯出為標準 SBOM 格式（如 SPDX 或 CycloneDX），與程式碼 SBOM 合併，形成涵蓋資料、模型與程式碼的完整 AI 物料清單。

3. **資料溯源與版本控制系統**  
   整合 DVC 或 Hugging Face Datasets 的 metadata 功能，在資料卡（Data Card）中自動寫入 ModSleuth 發現的上游模型生成紀錄與操作類型，使資料集使用者能於下載前即掌握其合成血統。

4. **企業合規與法務管理系統**  
   將多跳授權義務與文件不一致性警示，透過 API 匯入企業的合規儀表板或 Jira / ServiceNow 審批流程，讓法務與 OSPO 在模型採購或發布前完成強制審查關卡。

5. **模型行為審計與權重分析**  
   對於圖譜中標記的高風險相依性（如未揭露的偏好學習資料來源），可進一步整合權重比對技術（如 Git Re-Basin）或行為探針，驗證宣告的相依性是否確實反映在下游模型的行為與輸出分佈中。

### 給不同背景讀者的閱讀建議

**給初學者：**  
建議從摘要與圖 1 開始，先建立「模型並非從零打造，而是建立在其他模型之上」的直覺。可將遞迴相依性類比為食品成分標示中的「加工助劑」與「原料原料」，無需深究技術細節，重點在於理解現代 LLM 生態系中透明性不足的結構性問題。

**給 AI 工程師：**  
請著重閱讀方法論中「直接與間接相依性」的區分，以及「以操作為中心的關係」與「產物識別」的設計。思考如何將此框架整合進你目前的訓練管線——特別是在合成資料生成、評估與偏好學習階段，主動記錄並揭露上游模型資訊，降低發布後的合規風險。

**給研究人員：**  
關注形式化定義（直接/間接相依性、遞迴深度、身份格）與實證發現（多跳授權義務、訓練與評估耦合、文件不一致性）。這些發現為模型治理、開源合規、資料污染與模型崩潰（model collapse）研究提供了新的問題設定、基線數據與可擴展的審計工具。

**給產品經理：**  
請聚焦於「適用場景」與「潛在風險」章節，評估這套系統如何具體降低第三方模型採購或合成資料商用的法務風險。同時可將「模型溯源能力」轉化為產品信任中心（Trust Center）的差異化賣點，向企業客戶證明供應鏈透明度與負責任的 AI 治理。
