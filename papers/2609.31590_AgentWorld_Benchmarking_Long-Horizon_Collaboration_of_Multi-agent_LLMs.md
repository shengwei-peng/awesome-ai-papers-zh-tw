## 摘要翻譯

現有的多智能體基準測試主要針對競爭性設定、少於 20 步的短程互動，或僅將個別表現簡單加總，無法區分並凸顯基於大型語言模型之智能體（LLM-based agents）的真實協作能力。本文提出 AgentWorld，一個包含 100 項人工標註任務（human-annotated tasks）與 100 項擴增變體（augmented variants）的基準測試，用於評估長期多智能體協作（Multi-agent Collaboration, MAC）。任務在豐富的大型多人線上角色扮演沙盒（MMORPG sandbox）中進行，跨越 50 個以上的互動回合（interaction rounds），並要求 3 至 20 個具有非對稱角色與能力（asymmetric roles and abilities）的智能體，在黑箱設定（blackbox setting）下獨立運作、無法取得其他智能體的內部狀態（internal states），並透過溝通、聯合規劃（joint planning）與資源共享（resource sharing）進行協調。為了在傳統二元任務成功率（task success）指標之外量化協作效益，我們提出因果協作效益（Causal Collaboration Effectiveness, CCE），一種圖形化指標（graph-based metric），可追蹤智能體動作間的因果依賴關係（causal dependencies），並衡量團隊努力中實際對結果產生貢獻的比例。使用 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 與 DeepSeek R1-70B 進行的實驗顯示，即使最佳模型也僅達到 52.0% 的任務成功率，且出現溝通崩解（communication breakdowns）、角色混淆（role confusion），以及無法跨互動回合維持共享計畫（shared plans）等系統性失效模式（systematic failure modes）。AgentWorld 完全開源（open-source）。

### 核心貢獻（3～5點）
- 提出 AgentWorld 基準測試平台，包含 100 項人工標註任務與 100 項擴增變體，專門用於評估長期多智能體協作（MAC）。
- 設計豐富的 MMORPG 沙盒環境，要求 3 至 20 個具有非對稱角色與能力的智能體，在黑箱設定下進行跨 50 個以上互動回合的協作。
- 提出因果協作效益（CCE）圖形化指標，透過追蹤智能體動作間的因果依賴關係，衡量團隊努力中真正貢獻結果的比例。
- 對 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 與 DeepSeek R1-70B 等前沿模型進行實證評估，揭示溝通崩解、角色混淆與無法維持共享計畫等系統性失效模式。
- AgentWorld 完全開源，促進多智能體協作研究之可重現性與後續發展。

### 適合對象
本論文適合多智能體系統、大型語言模型智能體、人機協作與人工智慧評估領域的研究者與工程師，特別是關注長期協作、非對稱角色協調、黑箱多智能體互動，以及多智能體基準測試設計的讀者。對於希望了解當前前沿模型在真實協作情境中系統性限制的研究者尤具參考價值。

## 深度分析

#### 方法論解析

AgentWorld 的核心方法論可拆解為三個層次：**模擬環境（simulator）設計**、**任務（tasks）設計**，以及**評估指標（metrics）設計**。三者共同圍繞一個目標：將「協作能力」從低階動作控制（action-control proficiency）與單一智能體表現中分離出來，單獨測量多智能體大型語言模型（Multi-agent LLMs）的長期協作（Long-Horizon Collaboration）能力。

##### 1. 模擬環境：Kaetram MMORPG 沙盒

本研究採用名為 **Kaetram** 的模擬器（simulator），其本質是一個大型多人線上角色扮演沙盒（MMORPG sandbox）。與 Minecraft 或 Overcooked 等環境不同，Kaetram 的設計重點不在於物理精確度，而在於提供一個**高階 API 工具（high-level API tools）**層，將戰鬥（combat）、製作（crafting）、導航（navigation）等低階遊戲機制（game mechanics）抽象化為 13 個高階操作介面。這樣做的好處是：智能體不需要學習精確的 3D 移動或像素級控制，而是透過語言理解與規劃來決定「做什麼」，從而讓評分真正反映**協作品質**而非動作執行熟練度。

環境支援多達 1,000 個並行智能體（concurrent agents），並採用**黑箱設定（blackbox setting）**：每個智能體只能觀察自己的觀測與對話紀錄，無法讀取其他智能體的內部狀態（internal states）。這強迫智能體必須透過**自然語言（natural language）**溝通來協調，無法仰賴中央控制器或共享記憶體作弊。

##### 2. 任務設計：長期、非對稱、不可單獨完成

AgentWorld 包含 100 個人工標註任務（human-annotated tasks）與 100 個擴增變體（augmented variants），橫跨戰鬥（combat）、製作（crafting）、採集（gathering）、交易（trading）、探索（exploration）、生存（survival）、建造（construction）與協調（coordination）八個類別。每個任務具有以下特徵：

- **長期性**：任務橫跨 25–55 個互動回合（interaction rounds），遠超過現有基準常見的 10 步以內。
- **非對稱角色與能力（asymmetric roles and abilities）**：參與智能體數量為 3–20 個，各自擁有不同技能、裝備、物品欄與出生位置。例如 Task 86「Forge Vanguard」中，礦工（miners）負責挖礦、冶煉師（smelter）負責熔煉、鐵匠（smiths）負責鍛造武器，形成一條 mine → smelt → craft 的流水線。
- **必須協作**：任務目標無法由單一智能體獨立達成，必須透過**聯合規劃（joint planning）**、**資源共享（resource sharing）**與**時序協調（temporal coordination）**來完成。

這種設計確保了任務失敗往往不是因為單一智能體能力不足，而是因為團隊層次的協調失敗。

##### 3. 評估指標：Causal Collaboration Effectiveness（CCE）

傳統的任務成功率（task success）是二元指標，只能回答「有沒有完成」，無法回答「團隊合作得有多好」。為此，作者提出**因果協作效益（Causal Collaboration Effectiveness, CCE）**，這是一個圖形化指標（graph-based metric）。

CCE 的計算流程如下：

1. **建立因果動作圖（causal action graph）**：針對一次任務軌跡，利用 LLM 判斷哪些智能體動作之間存在**因果依賴關係（causal dependencies）**。例如「礦工把鐵礦交給冶煉師」與「冶煉師熔出鐵錠」之間存在因果關係。
2. **回溯任務結果的因果路徑**：從最終完成的任務目標往回追蹤，找出所有對結果有因果貢獻的動作節點。
3. **計算比例**：CCE = 有因果貢獻的動作數 / 總動作數。

這個指標的關鍵優勢在於：它**只使用 LLM 來建構動作間的因果關係圖**，而不是讓 LLM 直接對整體表現打分。後者常見於 LLM-as-a-judge 的評估方式，容易引入主觀性；而 CCE 在建立因果圖後，貢獻比例的計算是基於圖結構的客觀計數，因此相對更穩定、更可解釋。

總結來說，AgentWorld 的方法論透過「高階抽象環境 + 長期非對稱任務 + 因果圖評估」的三位一體設計，將多智能體協作（MAC）從單智能體能力與低階控制中剝離，提供了一個專門衡量協作本身的實驗框架。

#### 實驗數據解讀

作者在 AgentWorld 上測試了四個前沿模型（frontier models）：Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 與 DeepSeek R1-70B。實驗結果可從兩個層次解讀：**整體成功率**與**協作品質**。

##### 1. 任務成功率：即使最佳模型也僅達 52.0%

實驗顯示，表現最好的模型在 AgentWorld 上的任務成功率（task success）也只有 **52.0%**，代表在長期、非對稱、黑箱的多智能體協作場景中，目前最先進的 LLM 仍無法穩定完成任務。這個數字相對於傳統短程基準動輒 80–90% 的成功率形成強烈對比，凸顯了長期協作對現有模型而言仍是重大挑戰。

值得注意的是，論文並未詳細列出四個模型各自的確切成功率與 CCE 數值，僅強調最佳模型的表現為 52.0% 成功率與 CCE = 0.320。這暗示不同模型之間可能存在顯著差距，但整體而言都處於「不及格」或「勉強過半」的水準。

##### 2. CCE = 0.320：不到三分之一的動作真正貢獻結果

CCE 的數值更具啟發性。最佳模型的 CCE 僅為 **0.320**，意味著在所有智能體執行的動作中，只有不到三分之一真正對任務完成產生因果貢獻。換句話說，**超過三分之二的動作是冗餘、無效或偏離目標的**。

這個指標比成功率更能揭示問題本質：即使某些任務最終成功了，團隊的協作過程也可能是低效的。例如智能體可能反覆確認、重複採集相同資源、或進行無關對話，最後靠運氣或個別智能體的單打獨鬥勉強完成目標。CCE 將這種「虛假的協作」量化出來。

##### 3. 系統性失效模式（systematic failure modes）

作者進一步透過質性分析歸納出三類主要失效模式：

- **溝通崩解（communication breakdowns）**：智能體未能有效分享關鍵資訊，例如礦工已經挖到礦石卻沒有告知冶煉師，導致下游流程停滯。
- **角色混淆（role confusion）**：多個智能體重複執行相同工作，或偏離指定角色（例如鐵匠跑去採礦），造成資源與時間浪費。
- **無法維持共享計畫（inability to maintain shared plans）**：隨著回合數增加，智能體難以記住並更新共同的行動計畫，導致中後期行動脫節。

這三種失效模式彼此相關：溝通不足導致角色分工模糊，角色模糊又讓共享計畫難以維持。它們共同指向一個核心問題——現有 LLM 智能體缺乏穩定的**長期共享記憶（shared memory）**與**共識維護機制（consensus maintenance mechanism）**。

##### 4. 數據的深層意義

這些數據挑戰了一個常見假設：只要單一 LLM 夠強，多智能體系統自然就能協作。AgentWorld 的結果顯示，單輪推理（single-turn reasoning）與自主工具使用（autonomous tool use）的強大並不能直接轉化為長期協作能力。協作需要額外的機制設計，例如結構化溝通協定、角色綁定、計畫版本控制與衝突解決機制。

#### 與現有研究的比較

AgentWorld 在現有多智能體基準測試版圖中佔據了一個相對獨特的位置。以下從幾個維度進行比較。

##### 1. 與短程協作基準的比較

現有許多多智能體基準（如 Collab-Overcooked、MINDAGENT、MultiAgentBench）的任務長度通常在 20 步以內，甚至少於 10 步。這類基準適合測試即時協調（如「誰去切菜、誰去煮飯」），但無法評估需要**長期規劃**與**持續溝通**的複雜協作。AgentWorld 將任務長度擴展到 25–55 個互動回合（interaction rounds），並要求跨回合維持共享計畫（shared plans），這是對短程基準的重要補充。

##### 2. 與 Minecraft 類平台的比較

TeamCraft、MineLand、VOYAGER 等基於 Minecraft 的平台雖然支援開放世界（open world）與製作（crafting），但它們往往要求智能體處理大量低階控制問題，例如精確的 3D 導航（navigation）與方塊放置。這使得基準分數受到動作控制熟練度（action-control proficiency）的干擾，難以單獨衡量協作能力。AgentWorld 透過 13 個高階 API 工具（high-level API tools）將低階遊戲機制（game mechanics）抽象化，讓智能體專注於「決策與協調」而非「操作執行」。

##### 3. 與社會模擬（social simulations）的比較

Generative Agents、Project Sid、AgentSociety 等平台強調湧現社會行為（emergent social behavior），但這類研究通常缺乏具體、可量化的任務目標。AgentWorld 則提供 200 個具有明確成功條件與驗證器（verifiers）的任務，並結合 CCE 進行量化評估，彌補了社會模擬在「可測量成果」上的不足。

##### 4. 與單智能體基準的比較

AgentBench、AgentBoard 等單智能體基準雖然推動了 LLM 智能體的評估，但它們本質上無法測試多智能體協作（MAC）中的獨特挑戰，例如溝通協定、角色分工與資源共享。AgentWorld 明確將這些協作維度納入設計核心。

##### 5. AgentWorld 的獨特組合

根據論文 Table 1，AgentWorld 是少數同時具備以下特徵的基準：

- **黑箱設定（blackbox setting）**：智能體無法觀察彼此內部狀態（internal states）。
- **非對稱角色與能力（asymmetric roles and abilities）**：不同智能體擁有不同技能與起始條件。
- **長期任務視野（long task horizon）**：25–55 回合。
- **高階 API 工具（high-level API tools）**：抽象化低階控制。
- **量化協作評估（quantitative collaboration evaluation）**：結合成功率與 CCE。

這種組合使 AgentWorld 能夠更精確地隔離並測量「真正的協作能力」，而非單純的個體能力總和。

##### 6. 限制與待釐清之處

儘管 AgentWorld 在設計上具有創新性，仍有幾點需要審視：

- **LLM 作為因果圖建構者的可靠性**：CCE 雖然只讓 LLM 判斷動作間的因果依賴關係（causal dependencies），但這一步本身仍可能出錯。若 LLM 對因果關係的判斷有偏誤，CCE 的客觀性會受到影響。論文未詳細報告因果圖建構的內部一致性（inter-annotator agreement）或與人工標註的對照。
- **任務難度的均勻性**：100 個人工標註任務與 100 個擴增變體（augmented variants）的難度分布、類別平衡與失敗模式是否一致，論文著墨不多。
- **模型細節與提示工程（prompt engineering）**：不同模型的表現差異可能受到提示設計、記憶體長度與 API 工具呼叫方式的影響，這些實作細節對重現與比較至關重要。

#### 可重現性評估

可重現性（reproducibility）是基準測試論文能否被社群採納的關鍵。AgentWorld 在這方面採取了相對開放的策略。

##### 1. 開源釋出內容

根據論文，AgentWorld 已全面開源（open-source），釋出內容包括：

- **Kaetram 模擬器（simulator）**：包含支援 1,000 個並行智能體（concurrent agents）的 MMORPG 沙盒環境。
- **任務定義與驗證器（task definitions with verifiers）**：200 個任務的具體目標、初始條件與自動化成功判定程式。
- **評估腳本（evaluation scripts）**：包含任務成功率（task success）與 CCE 的計算流程。
- **資料標註平台（data annotation platform）**：讓社群能夠擴充新任務或進行人工標註。

這些釋出內容涵蓋了從環境、資料到評估的完整 pipeline，理論上能讓其他研究者重現主要實驗結果。

##### 2. 模型權重與 API 的可取得性

實驗中使用的四個模型——Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B——均為商業或開放權重模型。其中 DeepSeek R1-70B 的權重可能公開，而 Gemini、Claude、GPT 系列則需透過 API 存取。這意味著重現實驗需要一定的 API 成本，但這是當前 LLM 研究的常態，並非 AgentWorld 本身的缺陷。

##### 3. 重現時可能遇到的挑戰

- **隨機性與非確定性**：LLM 生成與多智能體互動具有高度隨機性，單次運行結果可能波動較大。論文未說明是否進行多次重複實驗並報告標準差。
- **提示與智能體架構細節**：雖然環境與任務開源，但智能體的提示模板（prompt templates）、記憶體管理策略與 API 工具呼叫邏輯若未完整釋出，重現結果可能與原論文有落差。
- **CCE 計算的主觀殘留**：如前所述，CCE 依賴 LLM 判斷因果關係，不同 LLM 作為因果圖建構者可能產生不同分數。重現時需要明確指定用於建構因果圖的模型與提示。

##### 4. 整體評價

整體而言，AgentWorld 在可重現性方面表現良好，尤其是環境、任務與評估工具的完整開源。若能進一步補充實驗的隨機性分析、提示模板與 CCE 建構的詳細協定，將更有助於社群進行公平比較與後續改進。

#### 未來研究方向

AgentWorld 的實驗結果揭示了當前多智能體 LLM 在長期協作上的顯著缺口，也為後續研究開闢了多條路徑。

##### 1. 結構化溝通協定（structured communication protocols）

針對溝通崩解（communication breakdowns）問題，未來可設計專門的溝通協定，例如強制每回合進行狀態同步、引入「廣播（broadcast）」與「私訊（private message）」機制、或規定訊息格式（如 JSON 結構化訊息）。這類協定可與自由自然語言（natural language）溝通進行對照實驗，找出效率與彈性的最佳平衡。

##### 2. 長期共享記憶與計畫維護機制

為解決無法維持共享計畫（inability to maintain shared plans）的問題，可研究如何讓智能體共同維護一個**共享記憶（shared memory）**或**共識計畫（consensus plan）**。例如引入計畫版本控制、多數決更新機制、或專門的「協調者（coordinator）」角色來追蹤全局進度。

##### 3. 動態角色分配與衝突解決

角色混淆（role confusion）可透過動態角色分配（dynamic role assignment）與衝突偵測機制來緩解。未來研究可探討智能體如何根據當前狀態重新協商分工、偵測重複工作並自動調整任務分配。

##### 4. 結合強化學習（RL）與 LLM 的混合方法

目前 AgentWorld 主要測試純 LLM 智能體。未來可引入強化學習（Reinforcement Learning, RL）來學習溝通策略與協作政策，並與 LLM 的規劃能力結合，形成「LLM 負責高階規劃、RL 負責策略優化」的混合架構。

##### 5. 擴展至更多智能體與更長視野

AgentWorld 支援最多 1,000 個並行智能體（concurrent agents），但當前實驗僅使用 3–20 個。未來可測試更大規模團隊（如 50–100 個智能體）在更長時間跨度下的協作，研究規模化帶來的協調挑戰。

##### 6. 多模態（multi-modal）協作

雖然 AgentWorld 目前主要透過文字溝通，但 MMORPG 環境本質上包含豐富的視覺與空間資訊。未來可加入視覺輸入，研究多模態資訊如何影響協作效率與溝通內容。

##### 7. 真實世界應用遷移

AgentWorld 的任務設計（如軟體開發流水線、科學研究團隊、複雜營運）與真實世界高度類比。未來可將在此學到的協作機制遷移到真實的多智能體系統，例如自動化軟體開發團隊或研究助理群組。

##### 8. CCE 指標的進一步完善

CCE 可作為一個通用協作評估框架推廣到其他多智能體基準。未來可研究如何降低 LLM 建構因果圖的成本、提高因果判斷的準確度，並將 CCE 擴展到考慮動作時序、資源貢獻度與溝通訊息的貢獻。

##### 9. 課程學習（curriculum learning）與自動任務生成

利用 AgentWorld 的資料標註平台，可發展自動任務生成與課程學習方法，讓智能體從簡單的短期協作任務逐步學習到複雜的長期協作任務。

##### 10. 可解釋性（interpretability）與失敗分析工具

最後，鑒於 CCE 提供了動作層級的因果貢獻資訊，未來可發展視覺化工具，幫助研究者理解哪些動作、哪些智能體、在哪些回合出現協作失效，從加速診斷與改進。

總結而言，AgentWorld 不僅是一個基準測試，更是一個研究平台。它所揭示的溝通崩解、角色混淆與計畫維護困難等問題，將成為下一代多智能體協作系統必須優先解決的核心挑戰。

## 論文問答

**Q1：AgentWorld 主要想解決什麼問題？**

A：AgentWorld 旨在解決現有多智能體基準測試難以真正衡量「協作能力」的問題。現有基準大多聚焦競爭情境、少於 20 步的短期互動，或僅將個別智能體的表現加總，無法凸顯多智能體大型語言模型之間真正的長期協作。因此，本研究提出一個包含 100 道人工標註任務與 100 道擴增變體的長期協作基準，讓 3 到 20 個具備非對稱角色與能力的智能體，在黑箱設定下透過溝通、聯合規劃與資源共享來完成任務。

**Q2：為什麼現有的多智能體基準測試無法有效評估協作能力？**

A：現有基準測試主要存在三個缺陷：第一，任務視野太短，通常少於 10 到 20 個互動回合，不足以觀察持續協調；第二，它們常把低階動作控制與協作混為一談，智能體必須花費大量心力在精細的 3D 導航或方塊放置上，而非協作本身；第三，像 Project Sid 這類大規模社會模擬雖然能觀察湧現社會行為，但缺乏可量測的具體任務成果，難以評估團隊是否真正達成目標。

**Q3：評估長期多智能體協作為什麼重要？**

A：隨著基於大型語言模型的智能體從單輪推理發展到自主工具使用、規劃與多步驟執行，協作成為關鍵能力。現實世界中許多複雜任務，例如軟體開發、科學研究與大型營運操作，都需要多個專業智能體共同協調以達成共享目標。系統化地評估這項能力，有助於理解當前前沿模型的優勢與限制，並為未來研究指明改進方向。

**Q4：AgentWorld 的核心方法與架構是什麼？**

A：AgentWorld 由一個豐富的大型多人線上角色扮演沙盒模擬器 Kaetram，以及建構其上的長期協作基準組成。模擬器支援多達 1,000 個並行智能體，內含 380 多種物品、144 種生物類型、70 多個非玩家角色，並提供 13 個高階 API 工具來抽象化戰鬥、製作與導航等低階遊戲機制。基準包含 100 道人工標註任務與 100 道擴增變體，橫跨戰鬥、製作、採集、交易、探索、生存、建設與協調等八大類別，每道任務需要 3 到 20 個智能體在 25 到 55 個互動回合內完成。

**Q5：什麼是因果協作效益（CCE），它的關鍵創新在哪裡？**

A：因果協作效益（CCE）是一種圖形化指標，它會在任務軌跡上建構因果動作圖，追蹤智能體行為之間的因果依賴關係，並衡量有多少比例的團隊努力真正對最終結果產生因果貢獻。與傳統僅看任務成功與否的二元指標不同，CCE 能區分有效行動與冗餘或無效行動。其創新之處在於只使用大型語言模型來建構動作間的因果關係圖，而非讓模型直接評判整體表現，從而減少純 LLM 評判器常見的主觀性問題。

**Q6：AgentWorld 為何採用黑箱設定與高階 API 工具？**

A：黑箱設定確保每個智能體無法觀察其他智能體的內部狀態，迫使它們必須透過自然語言溝通與協調來交換資訊，而不是仰賴共享記憶或全局觀察。高階 API 工具則將低階遊戲機制抽象化，讓智能體不需要精通精細的動作控制，就能執行戰鬥、製作與導航等行為。這兩項設計使得基準分數更能反映協作品質，而非個別智能體的動作控制熟練度。

**Q7：實驗中測試了哪些模型，主要結果是什麼？**

A：研究團隊在 AgentWorld 上測試了 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 與 DeepSeek R1-70B 四個前沿模型。實驗結果顯示，即使表現最好的模型，其任務成功率也僅有 52.0%，而因果協作效益（CCE）更只有 0.320。這表示即便任務有時能完成，團隊中超過三分之二的行動並未對最終成果產生因果貢獻，凸顯當前模型在協作效率上的嚴重不足。

**Q8：實驗發現了哪些系統性失效模式？**

A：定性分析揭示了三大系統性失效模式：首先是溝通崩解，智能體未能及時分享關鍵資訊；其次是角色混淆，智能體重複執行相同工作或偏離指定角色；第三是無法在跨回合間維持共享計畫，導致後續行動偏離原始目標。這些問題顯示，即使個別模型具備強大的單輪推理能力，長期協作仍然是當前基礎模型普遍的弱點。

**Q9：CCE 如何幫助分析實驗結果？**

A：CCE 透過因果動作圖將團隊努力拆解為「有因果貢獻」與「無因果貢獻」的行動，從而量化協作的有效性。它不僅能補充二元任務成功率的不足，還能指出哪些行動是冗餘的、哪些角色之間的協調出現斷裂。這種細粒度分析有助於研究者針對溝通、角色分配與計畫維護等環節進行針對性改進。

**Q10：AgentWorld 的評估框架可應用於哪些實際場景？**

A：AgentWorld 的設計理念可類比到許多需要長期協作的現實場景，例如軟體開發團隊中的程式設計、測試與專案管理分工，科學研究中不同實驗室之間的資料與資源共享，以及物流調度、緊急應變等複雜營運操作。這些場景都需要多個具備非對稱角色與能力的專業智能體，在無法完全掌握彼此內部狀態的情況下進行聯合規劃與資源共享。AgentWorld 提供了一個可控的測試環境，讓研究者能在部署到真實系統前先評估協作風險。

**Q11：若要將這類多智能體協作系統產品化，需要考慮哪些因素？**

A：產品化時必須設計穩定的溝通協定、明確的角色指派機制，以及能夠跨回合維持的共享計畫與記憶模組。評估指標不應只看最終任務是否成功，還應納入類似 CCE 的協作品質指標，以診斷團隊中是否存在大量無效或重複行動。此外，系統需要具備錯誤復原能力，當某個智能體偏離角色或溝通中斷時，能夠自動偵測並重新協調。

**Q12：AgentWorld 對多智能體研究領域可能帶來什麼影響？**

A：AgentWorld 將評估焦點從單一智能體能力轉移到團隊層級的長期協作品質，並透過開源沙盒降低相關研究的進入門檻。它提供了一個標準化的測試平台，讓社群能夠比較不同模型與協作演算法的效果，並針對溝通崩解、角色混淆等問題提出新方法。長遠來看，這可能催生專為多智能體協作設計的訓練架構、記憶機制與協調協定。

**Q13：這項研究有哪些已知的限制？**

A：首先，AgentWorld 的任務仍建構在 MMORPG 沙盒中，雖然比現有基準更複雜，但仍無法完全涵蓋真實世界的所有動態與不確定性。其次，人工標註任務與 LLM 擴增變體的過程可能引入某種程度的偏差，影響任務分佈的代表性。最後，CCE 雖然比純 LLM 評判器更客觀，但仍需使用大型語言模型來建構因果關係圖，其正確性會受到模型能力的限制。

**Q14：能否舉例說明 AgentWorld 中典型的失敗案例？**

A：以論文中提到的「Forge Vanguard」任務為例，該任務需要礦工、冶煉師與鐵匠沿著開採→冶煉→製作的管線協作。常見的失敗情況包括礦工未分享礦石與煤炭的位置、多名礦工重複開採同一資源、冶煉師在材料不足時提前作業，或是智能體在跨回合後忘記原本的聯合計畫。由於這類任務具有強烈的時序協調與資源共享依賴，任何一個環節出現溝通崩解或角色混淆，都會導致整個團隊無法完成目標。

**Q15：未來可以朝哪些方向延伸這項研究？**

A：未來可以將 AgentWorld 的框架擴展到更貼近真實世界的領域，例如模擬企業營運、醫療團隊合作或科學實驗協作。另一方面，可以結合強化學習或專門的多智能體訓練方法，提升智能體在長期互動中的溝通、記憶與計畫維護能力。此外，也可進一步結合 CCE 與人類評估，發展更穩健的協作品質指標，並根據發現的系統性失效模式設計針對性的訓練課程。

## 實作前置條件

### 資料準備
- **任務定義**：需準備包含目標、角色能力、初始狀態、勝利條件與驗證器（verifier）的結構化任務檔案；可參考 AgentWorld 提供的 100 人工標註任務與 100 擴增變體格式。
- **領域知識庫**：若應用於真實場景，需將領域文件（如 API 文件、操作手冊、地圖、物品表）轉換為智能體可讀取的觀察與工具描述。
- **對照標註軌跡**：用於校準 CCE 的因果依賴關係圖，建議預先標註部分成功／失敗案例的關鍵動作鏈。

### 運算資源
- **模擬環境**：需可執行 AgentWorld／Kaetram 沙盒的伺服器，支援最多 1,000 個並行智能體；建議至少具備多核心 CPU、16 GB 以上記憶體與穩定網路。
- **LLM 推論**：每回合每個智能體皆需呼叫前沿模型（如 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B），長期任務可能產生數千次 API 呼叫，需預留足夠 token 配額與預算。
- **評估運算**：CCE 需額外建立因果動作圖，可採用較小模型或本地部署模型以降低 LLM-as-judge 成本。

### 技能需求
- **多智能體系統設計**：熟悉角色分配、通訊協定、觀察空間與動作空間設計。
- **LLM 提示工程**：能為不同非對稱角色撰寫系統提示，並加入計畫維護、溝通與資源共享的指導。
- **Python 與沙盒整合**：能修改 AgentWorld 開源程式碼、連接高階 API 工具、撰寫 verifier 與評估腳本。
- **因果／圖分析基礎**：理解 CCE 的圖形化指標計算方式，並能據此診斷系統性失效模式。

## 實作步驟建議

1. **部署沙盒與基線任務**  
   下載 AgentWorld 開源模擬器、任務定義與評估腳本，先執行論文提供的標準任務（如 Task 86: Forge Vanguard），確認環境、高階 API 工具與 verifier 可正常運作。

2. **定義真實場景任務**  
   將業務流程拆解為「目標 → 角色 → 必要資源 → 時序協調點」，轉寫為 AgentWorld 任務格式；確保單一智能體無法獨立完成，以強制產生協作需求。

3. **配置黑箱智能體**  
   為每個角色設定獨立系統提示、技能、裝備／工具與初始位置；關閉智能體間內部狀態共享，僅允許透過自然語言溝通，以符合黑箱設定。

4. **執行長期協作回合**  
   執行 25–55 個互動回合的實驗，記錄每個智能體的觀察、發言與高階 API 工具呼叫，形成完整軌跡（trajectory）。

5. **計算任務成功率與 CCE**  
   使用 verifier 判斷二元任務成功與否，再以 CCE 建立因果動作圖，計算真正對結果有因果貢獻的動作比例，避免僅以成功率掩蓋無效忙碌。

6. **診斷失效模式並迭代**  
   針對溝通崩解、角色混淆、共享計畫無法維持等問題，調整提示（如加入會議紀要、角色檢查清單、狀態廣播機制）或通訊協定，並重新跑實驗驗證。

7. **產品化對接**  
   將驗證後的角色提示、協作協定與評估流程封裝為可重複執行的 pipeline，接入現有排程、監控或人機協作介面。

## 潛在風險與注意事項

- **溝通崩解導致任務卡關**  
  智能體可能遺漏關鍵資訊或各說各話。建議在提示中強制要求每回合結束前廣播「目前狀態／持有資源／下一步需求」，並限制發言格式。

- **角色混淆與重複工作**  
  非對稱角色若提示不清，容易出現兩個智能體同時採集相同資源或無人負責關鍵步驟。可為每個角色提供明確的職責清單與依賴檢查點。

- **共享計畫隨回合漂移**  
  長期協作中智能體可能遺忘初始計畫。建議引入「共享計畫文件」機制，讓某個智能體或外部模組每數回合彙整並廣播最新計畫。

- **評估成本與 LLM 主觀性**  
  CCE 雖已減少純 LLM 評判的主觀性，但建立因果關係圖仍需呼叫 LLM。建議先用小規模軌跡校準，再擴大到完整任務；並保留人工抽樣審查。

- **過度擬合沙盒規則**  
  AgentWorld 的高階 API 工具已抽象化低階遊戲機制，轉移到真實世界時需重新設計工具與觀察介面，避免將遊戲內捷徑誤認為通用協作能力。

---

## 與其他技術的整合建議

- **多智能體框架**  
  可將 AgentWorld 沙盒作為 AutoGen、CAMEL 或 AgentVerse 的後端環境，利用這些框架的對話管理與角色編排能力，再透過 AgentWorld 進行長期協作評估。

- **檢索增強生成（RAG）**  
  為每個智能體配置領域知識庫，讓其在黑箱環境中根據文件決定工具使用與資源交換，特別適合軟體開發或科學研究場景。

- **可觀測性與監控平台**  
  將每回合的觀察、溝通與動作匯出到追蹤系統（如 LangSmith、Langfuse 或自研儀表板），即時視覺化 CCE 與任務進度，便於快速定位溝通崩解或角色混淆。

- **人機協作介面**  
  在關鍵決策點引入人類監督員，當 CCE 持續下降或任務成功率低於門檻時，由人類介入修正計畫或重新分配角色。

- **強化學習與規劃演算法**  
  對於重複出現的協作模式，可將 CCE 分析結果作為獎勵訊號或規劃約束，進一步訓練或微調智能體的策略與溝通協定。

## 給不同背景讀者的閱讀建議

**初學者**  
建議先從摘要與「適用場景」開始，理解什麼是長期協作與黑箱設定，再透過 AgentWorld 開源的標準任務（如 Forge Vanguard）實際跑一次，觀察智能體如何溝通與分工；不必一開始就深入 CCE 的圖形化計算，重點是體會「為什麼多智能體協作這麼難」。

**AI 工程師**  
請聚焦實作步驟、高階 API 工具設計與 CCE 評估腳本；建議直接下載開源程式碼，嘗試將自己的業務流程改寫為 AgentWorld 任務，並針對溝通崩解、角色混淆等失效模式調整提示與協定，把 CCE 當作除錯指標而非僅是論文貢獻。

**研究人員**  
建議細讀 CCE 的數學與圖形化定義，思考其在其他多智能體基準上的可遷移性；同時可探討黑箱設定、非對稱角色與長期互動回合如何影響 LLM 的湧現協作行為，並將 AgentWorld 作為驗證新協作演算法或通訊協定的標準平台。

**產品經理**  
請把重點放在適用場景、潛在風險與整合建議；AgentWorld 的價值在於提供可量化的協作品質指標（成功率 + CCE），幫助團隊在導入多智能體產品前，先評估模型在長期、非對稱分工情境下的真實表現，並據此決定是否需要人機協作或額外的流程設計。
