## 摘要翻譯

影片世界模型透過在生成過程中儲存 KV 快取來達成長程時間一致性，但日益增長的快取使得 KV 快取記憶體成為主要的部署瓶頸，因而推動了旨在提升效率的低位元量化研究。現有的 2 位元 KV 快取量化方法在 VBench 上可達到近乎無損的效能；然而，當應用於影片世界模型時，我們發現它們仍會造成嚴重的時間閃爍與視覺退化。同時，更深入的研究顯示，Key（鍵）量化雖比 Value（值）量化產生更小的重建誤差，卻出乎意料地導致更大的輸出退化。我們將此差異追溯至影片世界模型中的注意力：Key 擾動會改變注意力對數機率（attention logits），並使 Query（查詢）所選擇的時空權杖（temporal-spatial tokens）發生偏移。這些觀察結果促使我們在 KV 快取量化過程中保留注意力對數機率（attention logits）與時空權杖選擇。為了解決此問題，我們提出 QuantWM，一個針對影片世界模型的免訓練 2 位元 KV 快取量化框架。QuantWM 引入兩項互補技術以緩解注意力偏移。首先，量化敏感度感知分群（QSAC）同時考量歷史 Query 敏感度與殘差範圍，以選擇適用 INT2 的 Key 質心，從而減少對注意力更為關鍵的通道內量化誤差。此外，主子空間注意力補償（PSAC）利用低秩投影沿主要 Query 子空間還原剩餘的 Key 誤差，提供直接且高效的修正以穩定注意力對數機率（attention logits）。在 LingBot-World-v2、HY-World 1.5、Matrix-Game-2、Longcat-Video 與 Causal-Forcing 上的實驗顯示，QuantWM 顯著改善視覺品質與時間一致性，同時在跨基準上優於現有方法，並達到高達 6.20 倍的 KV 快取記憶體壓縮與有限的額外開銷。

### 核心貢獻（3～5點）
- 揭示現有 2 位元 KV 快取量化方法應用於影片世界模型時，雖在 VBench 上近乎無損，卻會造成嚴重的時間閃爍與視覺退化。
- 發現 Key（鍵）量化雖重建誤差較小，卻因改變注意力對數機率（attention logits）與時空權杖選擇而導致更大的輸出退化。
- 提出 QuantWM，一個免訓練的 2 位元 KV 快取量化框架，專為影片世界模型設計，透過保留注意力對數機率與時空權杖選擇來緩解注意力偏移。
- 設計兩項互補技術：量化敏感度感知分群（QSAC）選擇適用 INT2 的 Key 質心，以及主子空間注意力補償（PSAC）以低秩投影穩定注意力對數機率。
- 在 LingBot-World-v2、HY-World 1.5、Matrix-Game-2、Longcat-Video 與 Causal-Forcing 等多個影片基準上驗證，達到高達 6.20 倍的 KV 快取記憶體壓縮，並顯著改善視覺品質與時間一致性。

### 適合對象
本論文適合從事影片世界模型、自迴歸影片生成、視覺合成、模型壓縮與低位元量化研究的研究人員與工程師，特別是關注 KV 快取記憶體壓縮、長程時間一致性，以及如何在記憶體受限裝置上實際部署大型影片生成模型之讀者。對於希望理解注意力機制對量化敏感度，並尋求免訓練量化方案以減少部署瓶頸的實務開發者亦具高度參考價值。

## 深度分析

#### 方法論解析

##### 1. 問題設定與整體框架

QuantWM 針對的是**因果自迴歸影片世界模型（causal and autoregressive video world models）**在部署時的 **KV 快取（KV cache）** 記憶體瓶頸。這類模型在生成過程中會把歷史的 **Key（鍵）** 與 **Value（值）** 儲存下來，讓後續生成區塊（generated chunk）能夠關注（attend to）先前的世界上下文（world context），以維持**長程時間一致性（long-range temporal consistency）**。然而，影片的時空權杖（spatial-temporal tokens）數量龐大，導致 KV 快取極度**記憶體密集（memory-intensive）**——例如 LingBot-World-v2 生成 5 秒影片（約 93 個影格）就需要超過 21 GiB 的 KV 快取記憶體。

QuantWM 是一個**免訓練（training-free）**的 **2 位元 KV 快取量化（2-bit KV cache quantization）**框架，目標是在大幅壓縮記憶體的同時，避免現有方法造成的**時間閃爍（temporal flickering）**與**視覺退化（visual degradation）**。其核心洞察是：**Key 量化雖然重建誤差（reconstruction errors）比 Value 量化小，卻會造成更大的輸出退化（output degradation）**，因為 Key 擾動會改變 **注意力對數機率（attention logits）**，進而改變 **Query（查詢）** 所選擇的時空權杖（temporal-spatial tokens）。

##### 2. 基礎量化表示：Centroid-Residual Quantization

QuantWM 建立在 QVG（Quant-VideoGen）提出的 **centroid-residual 表示法**之上。對於一個 Key 權杖 \(k_i \in \mathbb{R}^d\)，先透過分群（clustering）將其分配到某個質心（centroid）\(\mu_{z_i}\)，並分解為：

\[
r_i = k_i - \mu_{z_i}
\]

質心以 **BF16** 儲存，而殘差（residual）張量 \(r_i\) 則量化為低位元（此處為 **INT2**）。重建後的 Key 與量化誤差為：

\[
\hat{k}_i = \mu_{z_i} + Q_b(r_i)
\]

這種表示法的優點在於：質心保留了粗略的權杖結構，殘差只需編碼剩餘的細節，因此非常適合極低位元量化。

##### 3. 量化敏感度感知分群（QSAC）

現有方法（如 QVG）通常使用 **K-means clustering（K-means 分群）** 來選擇質心，目標是最小化殘差的重建誤差。然而，QuantWM 發現這並不等同於最小化對注意力機制（attention mechanism）的影響。因為注意力分數為：

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V
\]

Key 的誤差會透過 \(QK^\top\) 影響 **注意力對數機率（attention logits）**，進而改變權杖選擇（token selection）的排序。某些通道對 Query 的投影特別敏感，即使殘差範圍（residual ranges）不大，也可能顯著改變注意力分布。

因此，QSAC 在選擇 **Key 質心（Key centroids）** 時，**聯合考慮歷史 Query 敏感度（historical Query sensitivity）與殘差範圍**，挑選對 **INT2** 量化更友善、且對 \(QK^\top\) 影響較小的質心。直觀來說，QSAC 會把質心往「對注意力影響較小」或「殘差在敏感 Query 方向上較小」的位置調整，從源頭降低 Key 量化誤差對注意力對數機率的衝擊。

##### 4. 主子空間注意力補償（PSAC）

即使經過 QSAC，仍會有殘留的 Key 誤差。PSAC 進一步透過**低秩投影（low-rank projections）**在**主要 Query 子空間（dominant Query subspace）**上補償這些殘差。

具體而言，PSAC 會：

1. 從歷史或當前的 **Query（查詢）** 中提取主要子空間（principal subspace），也就是對注意力分數影響最大的方向。
2. 將剩餘的 **Key 誤差（Key errors）** 投影到這些敏感方向上。
3. 透過低秩表示來補償注意力對數機率的偏移，使其接近 BF16 基準。

由於只針對主要 Query 子空間進行低秩修正，PSAC 的額外計算開銷有限，卻能直接穩定注意力行為。這與單純最小化 Key 的 MSE 不同：PSAC 目標是「讓注意力輸出不要偏移」，因此對視覺品質與時間一致性的保護更為精準。

##### 5. 整體流程

QuantWM 的推論流程可概括為：

1. 對 Key 進行 **QSAC**：根據歷史 Query 敏感度與殘差範圍選擇質心，並將殘差量化為 **INT2**。
2. 對 Value 進行標準的 2 位元量化（Value 量化較不敏感）。
3. 在注意力計算時，透過 **PSAC** 對 Key 殘差在主要 Query 子空間上進行低秩補償。
4. 使用補償後的 Key 計算注意力，產生下一個生成區塊。

整體而言，QuantWM 透過「減少敏感方向上的量化誤差」與「直接補償注意力對數機率」這兩個互補技術（complementary techniques），在免訓練的前提下達到高達 **6.20× 的 KV 快取記憶體壓縮（KV cache memory compression）**。

#### 實驗數據解讀

##### 1. 基準模型與設定

論文在多個代表性的**影片世界模型（video world models）**與**影片生成模型（video generation models）**上進行評估：

- **LingBot-World-v2**
- **HY-World 1.5**
- **Matrix-Game-2**
- **LongCat-Video**
- **Causal-Forcing**

這些模型涵蓋了互動式世界模擬（interactive world simulation）與自迴歸影片生成（autoregressive video generation），能夠驗證 QuantWM 在不同場景下的泛化能力。

##### 2. 關鍵發現：VBench 分數與視覺品質的脫節

論文指出，現有的 2 位元 KV 快取量化方法（如 QVG）在 **VBench** 等影片基準（video benchmarks）上呈現「**近乎無損（nearly lossless）**」的量化分數，但實際生成的影片卻出現明顯的**時間閃爍（temporal flickering）**、**模糊（blurring）**與**偽影（artifacts）**。這說明：

- **VBench Score** 等自動化指標對短程、局部閃爍不夠敏感。
- 單純依賴報告分數（reported scores）可能會**忽視視覺退化（overlooked visual degradation）**。
- 對於**影片世界模型**這類需要長程時間一致性的應用，現有指標需要輔以視覺檢查與更細緻的時間一致性指標。

##### 3. Key 與 Value 量化的不對稱性

論文透過對照實驗（K16V2、K2V16、K2V2）發現：

- **K16V2**（Key 用 BF16、Value 用 2-bit）：視覺品質接近 BF16，幾乎沒有明顯退化。
- **K2V16**（Key 用 2-bit、Value 用 BF16）：出現嚴重的時間閃爍與視覺退化。
- **K2V2**（兩者皆 2-bit）：退化主要來自 Key。

這顯示 **Key 比 Value 對輸出品質更敏感**。更有趣的是，表 1 顯示 Key 量化的 **MSE** 通常低於 Value 量化，但輸出 MSE 卻更高。這證實了「重建誤差大小」並不能直接解釋「輸出退化程度」，關鍵在於誤差是否改變了注意力對數機率與權杖選擇。

##### 4. 注意力偏移的可視化

圖 3 展示了在不同模型上，Key 量化後 **Top-1 選擇的時空 patch** 發生偏移。例如：

- 在 HY-World 1.5 中，BF16 選擇第 8 幀的 (7,11)，而 K2 量化後變成第 12 幀的 (8,11)。
- 在 LongCat-Video 中，BF16 選擇第 48 幀的 (10,2)，K2 量化後變成第 44 幀的 (6,10)。

這些偏移會讓 Query 關注到錯誤的影格或空間區域，直接導致時間閃爍與視覺不一致。QuantWM 的設計正是要抑制這類 **注意力偏移（attention shifts）**。

##### 5. QuantWM 的整體成效

QuantWM 在以上基準上達成：

- **顯著改善視覺品質（visual quality）**與**時間一致性（temporal consistency）**。
- 在傳統影片分數上維持強勁表現。
- **高達 6.20× 的 KV 快取記憶體壓縮**。
- **有限的額外開銷（limited additional overhead）**。

這表示 QuantWM 成功在壓縮率與視覺品質之間取得平衡，特別適合部署在**記憶體受限裝置（memory-constrained devices）**上。

#### 與現有研究的比較

##### 1. 相對於 QVG 等 2-bit KV 快取量化方法

Quant-VideoGen（QVG）是首個將 2-bit KV 快取量化擴展到自迴歸影片生成的方法，並在 VBench 上取得近乎無損的表現。然而，QVG 主要關注整體重建誤差與傳統影片分數，並未特別考慮影片世界模型中**注意力對數機率（attention logits）**的穩定性。

QuantWM 的改進在於：

- **從「重建誤差」轉向「注意力行為」**：不僅最小化 Key 的重建誤差，更直接保護注意力對數機率與權杖選擇。
- **Key 導向的設計**：發現 Key 是退化的主要來源，並針對 Key 提出 QSAC 與 PSAC。
- **適用於互動式世界模擬**：影片世界模型對長程時間一致性與動作條件化更敏感，QuantWM 的設計更符合這類應用需求。

##### 2. 相對於大型語言模型（LLMs）的 KV 快取量化

LLM 領域的 KV 快取量化方法（如各種 2-bit 或更低位元方法）通常假設權杖序列為一維文字，且注意力模式較為稀疏或平滑。然而，影片世界模型具有：

- **高維時空結構**：權杖同時包含時間與空間資訊。
- **連續的視覺動態**：相鄰影格之間的細微變化對視覺品質至關重要。
- **動作與相機軌跡條件化**：使用者動作會改變未來生成，對歷史上下文的準確性要求更高。

因此，直接套用 LLM 的 KV 快取量化方法會導致時間閃爍，QuantWM 針對影片特性進行了專門設計。

##### 3. 優勢總結

- **免訓練**：不需要額外的微調或量化感知訓練，部署成本低。
- **高壓縮比**：6.20× 的記憶體壓縮對實際部署非常有吸引力。
- **注意力感知**：QSAC 與 PSAC 直接針對注意力機制進行保護，而非僅優化重建誤差。
- **跨模型泛化**：在多個影片世界模型與影片生成模型上都有效。

##### 4. 限制與潛在弱點

- **主要針對 Key**：雖然 Value 也量化為 2-bit，但方法設計與分析主要聚焦於 Key。若未來發現 Value 在某些模型或任務上也敏感，可能需要進一步擴展。
- **PSAC 的額外計算**：雖然論文聲稱額外開銷有限，但低秩投影仍會增加一些推論計算，對極度延遲敏感的場景可能需要更細緻的剖析。
- **指標不足**：論文強調現有影片基準無法完全捕捉視覺退化，但未提出新的自動化指標，未來可補充。
- **長影片與極長上下文**：實驗主要針對 5 秒左右的影片，對於更長的互動式模擬（例如數分鐘），KV 快取累積誤差是否會放大仍需驗證。

#### 未來研究方向

##### 1. 更細緻的位元分配與混合精度量化

QuantWM 目前統一使用 2-bit 量化 Key 與 Value。未來可探索**自適應位元分配（adaptive bit allocation）**：對注意力敏感度高的層或權杖使用較高位元，對不敏感的層使用更低位元，以在相同記憶體預算下進一步提升品質。

##### 2. 聯合 K/V 的注意力感知量化

雖然 QuantWM 發現 Key 是主要瓶頸，但未來可設計同時考慮 Key 與 Value 對注意力輸出聯合影響的量化目標，例如以注意力輸出分佈的 KL 散度或 Fisher 資訊作為敏感度指標。

##### 3. 針對長程互動式模擬的量化

影片世界模型最終目標是長時間、連續的互動式模擬。未來研究可探討：

- KV 快取在數百至數千影格下的誤差累積問題。
- 滑動視窗或壓縮式 KV 快取與低位元量化的結合。
- 動作條件化對 KV 快取敏感度的影響。

##### 4. 硬體感知量化與核心優化

QuantWM 的 PSAC 涉及低秩投影，需要高效的 GPU/TPU 核心支援。未來可開發專用的 **INT2** 量化與低秩補償核心，將方法整合到 vLLM、TensorRT-LLM 或自訂推論引擎中，以實現真正的低延遲部署。

##### 5. 更貼近人類感知的評估指標

論文已指出 VBench 等指標無法完全捕捉時間閃爍。未來可發展：

- 專門衡量時間閃爍與長程一致性的指標。
- 結合人類偏好學習（human preference learning）的評估框架。
- 針對世界模型互動一致性的評估協定。

##### 6. 量化感知訓練（Quantization-Aware Training, QAT）的結合

QuantWM 是免訓練方法，部署方便。但未來可探索將 QSAC/PSAC 整合進量化感知訓練，讓模型本身學習對低位元 Key 量化更穩定的表示，進一步推升壓縮率或品質。

##### 7. 擴展到其他世界模型架構

除了自迴歸 Transformer，未來的影片世界模型可能採用擴散模型（diffusion models）、Mamba 狀態空間模型或其他架構。QuantWM 的「注意力對數機率保護」思想可推廣到這些架構的對應壓縮問題上，例如保護狀態空間模型的轉移動態。

## 論文問答

**Q1：QuantWM 主要解決什麼問題？為什麼 KV 快取量化對影片世界模型如此重要？**

A：QuantWM 針對的是因果自迴歸影片世界模型在部署時面臨的 KV 快取記憶體瓶頸問題。這類模型為了維持長程時間一致性，必須在生成過程中儲存歷史的 Key 與 Value，而大量的時空權杖使得 KV 快取極度記憶體密集，例如 LingBot-World-v2 生成一段 5 秒影片就需要超過 21 GiB 的 KV 快取記憶體。透過低位元量化技術將 KV 快取壓縮到 2 位元，能顯著降低儲存成本，使模型得以在記憶體受限裝置上部署。QuantWM 正是在此背景下，專門為影片世界模型設計的免訓練 2 位元 KV 快取量化框架。

**Q2：現有的 2 位元 KV 快取量化方法為何在影片世界模型上失效，即使它們在 VBench 上表現近乎無損？**

A：現有方法如 Quant-VideoGen（QVG）雖然在 VBench 等影片基準上報告近乎無損的分數，但應用到影片世界模型時卻會產生明顯的時間閃爍、模糊與偽影等視覺退化。這是因為傳統評測指標無法完整捕捉時間一致性與細節穩定性，導致量化分數與實際視覺品質之間出現意想不到的差異。更根本的原因是，Key 量化會改變注意力對數機率，進而造成時空權杖選擇的偏移，使 Query 關注到錯誤的歷史影格或空間區域。因此，僅優化重建誤差或影片分數並不足以保證影片世界模型的生成品質。

**Q3：為什麼 Key 比 Value 更敏感？這個發現對量化方法設計有什麼啟示？**

A：研究發現 Key 的重建誤差其實比 Value 更小，但卻造成更大的輸出退化，這顯示 Key 的敏感度無法單純用重建誤差大小來解釋。其根本原因在於 Key 決定了 Query 與快取權杖之間的匹配分數，Key 的擾動會改變注意力對數機率與權杖排序，導致頻繁的權杖選擇偏移。在影片世界模型中，這種偏移會使 Query 指向不正確的歷史影格或空間位置，從而引發時間閃爍與視覺退化。這啟示我們在設計量化方法時，必須直接保護注意力行為與時空權杖選擇，而非僅僅最小化逐元素的重建誤差。

**Q4：QuantWM 的核心框架是什麼？它包含哪兩項互補技術？**

A：QuantWM 是一個免訓練的 2 位元 KV 快取量化框架，專門用於在量化過程中保留影片世界模型的注意力行為。它包含兩項互補技術：首先是量化敏感度感知分群（QSAC），透過考慮 Query 敏感度與殘差範圍來選擇更適合 INT2 量化的 Key 質心；其次是主子空間注意力補償（PSAC），利用低秩投影在主要 Query 子空間上直接補償殘留的 Key 誤差。這兩項技術分別從減少量化誤差與直接修正注意力對數機率兩個角度，協同緩解注意力偏移問題。

**Q5：QSAC 如何運作？它與 QVG 中使用的標準 K-means 分群有何不同？**

A：QSAC 建立在 QVG 的質心殘差表示法之上，但改進了質心選擇策略。不同於標準 K-means 僅根據資料分布選擇質心，QSAC 聯合考慮歷史 Query 的敏感度以及 Key 殘差的動態範圍，選出對 QK⊤ 影響較小的 INT2 友好質心。這樣可以讓殘差在量化後對注意力對數機率的干擾降到最低，特別是在對 Query 更關鍵的通道上減少量化誤差。因此，QSAC 能夠在相同的 2 位元儲存預算下，更有效地保護注意力計算的穩定性。

**Q6：PSAC 如何運作？為什麼低秩投影對注意力補償特別有效？**

A：PSAC 在推論階段直接補償注意力對數機率，它首先萃取主要的 Query 子空間，然後將殘留的 Key 誤差成分沿著這些敏感方向以低秩投影表示。由於注意力分數主要由 Query 與 Key 的內積決定，Key 誤差在 Query 主方向上的投影對輸出影響最大，因此針對這些方向進行補償能達到直接且高效的修正效果。低秩投影的計算成本相對較低，卻能顯著穩定注意力對數機率，這使得 PSAC 在額外開銷有限的情況下大幅提升視覺品質與時間一致性。

**Q7：QuantWM 在哪些基準上進行評估？主要實驗結果為何？**

A：QuantWM 在多個具代表性的影片世界模型與影片生成模型上進行評估，包括 LingBot-World-v2、HY-World 1.5、Matrix-Game-2、LongCat-Video 與 Causal-Forcing。實驗結果顯示，QuantWM 能顯著改善時間閃爍與視覺退化問題，同時在各項基準上維持強勁表現並優於現有方法。在記憶體效率方面，QuantWM 可達到高達 6.20 倍的 KV 快取記憶體壓縮，例如將 HY-World 1.5 的 KV 快取從 12.09 GiB 降至 1.95 GiB。這些結果證明了 QuantWM 在視覺品質、時間一致性與記憶體效率之間取得了良好的平衡。

**Q8：有哪些消融研究或比較實驗能證明 QSAC 與 PSAC 的有效性？**

A：論文透過 K16V2、K2V16 與 K2V2 等對比設定，直觀展示了僅量化 Key（K2V16）會比僅量化 Value（K16V2）產生更嚴重的時間閃爍與視覺退化，證明 Key 是主導性能退化的因素。進一步的視覺化顯示，K2 量化會導致 top-1 時空權杖選擇發生明顯偏移，例如關注到錯誤的影格編號或空間位置。QuantWM 結合 QSAC 與 PSAC 後，能夠有效減少這類注意力偏移，並在多個基準上同時提升量化分數與實際視覺品質。這些消融與比較結果清楚說明了兩項技術在穩定注意力行為上的互補貢獻。

**Q9：QuantWM 在記憶體壓縮與額外開銷之間的權衡如何？**

A：QuantWM 可實現高達 6.20 倍的 KV 快取記憶體壓縮，將原本需要數十 GiB 的快取大幅縮小至數 GiB 等級，對於記憶體受限裝置的部署極具吸引力。儘管引入了 QSAC 與 PSAC，論文指出其額外推論開銷相當有限，主要因為低秩投影與敏感度感知分群的計算成本經過仔細設計。這樣的權衡使得 QuantWM 不僅節省大量記憶體，還能在實際應用中保持可接受的延遲與吞吐量。

**Q10：QuantWM 在哪些實際部署場景中最具價值？**

A：QuantWM 最適合應用於需要在記憶體受限裝置上進行長影片生成與互動式世界模擬的場景，例如虛擬實境、擴增實境、遊戲引擎與機器人模擬。在這些應用中，模型必須根據使用者動作與相機軌跡持續生成一致的視覺內容，而龐大的 KV 快取往往成為即時互動的瓶頸。透過 QuantWM，開發者可以在消費級 GPU 或邊緣裝置上部署影片世界模型，同時維持良好的視覺品質與時間一致性。

**Q11：在實際產品中部署 QuantWM 時需要考慮哪些因素？**

A：首先需評估目標硬體對 INT2 運算與低秩投影的支援程度，因為這會影響實際的延遲與能耗表現。其次，不同應用對視覺品質與壓縮比的要求不同，產品團隊可能需要根據場景調整 QSAC 與 PSAC 的參數，在記憶體節省與生成品質之間取得平衡。此外，由於現有影片基準可能無法完整反映時間一致性問題，建議在產品層級加入額外的視覺品質檢驗與使用者研究，以確保量化後的輸出符合使用者期望。

**Q12：QuantWM 對影片世界模型領域可能帶來什麼影響？**

A：QuantWM 揭示了僅優化重建誤差或傳統影片分數並不足以保證量化後的生成品質，推動領域更加重視注意力行為與時間一致性的保護。它為影片世界模型在資源受限環境中的實際部署開闢了道路，有助於加速互動式世界模擬、遊戲與機器人等應用的落地。此外，這項工作也凸顯了現有影片基準在捕捉時間閃爍等細微退化上的不足，可能激發未來研究開發更完善的評測指標與注意力感知壓縮方法。

**Q13：QuantWM 有哪些已知的限制？**

A：QuantWM 目前主要針對因果自迴歸影片世界模型設計，對於非自迴歸或其他架構的影片生成模型，其適用性與效果可能需要進一步驗證。作為免訓練方法，QuantWM 雖然部署方便，但其性能上限可能低於經過微調或聯合訓練的量化方法。此外，PSAC 的低秩投影與 QSAC 的敏感度計算雖然開銷有限，但在極端低延遲場景中仍可能成為需要權衡的因素。

**Q14：在哪些情況下 QuantWM 可能會失效或產生次優結果？**

A：當影片場景包含極快速的運動或劇烈的視覺變化時，Query 與 Key 的注意力分布可能高度動態，此時量化誤差更容易造成顯著的權杖選擇偏移。若生成序列非常長，殘留的量化誤差可能隨時間累積，進而影響長程時間一致性。此外，如果推論時的 Query 分布與歷史 Query 統計特性差異很大，QSAC 與 PSAC 基於歷史 Query 所做的敏感度估計可能不再準確，導致補償效果下降。

**Q15：基於 QuantWM，未來有哪些值得探索的研究方向？**

A：未來研究可以進一步將 QuantWM 擴展到 1 位元或更低位元的 KV 快取量化，並探索與模型微調或量化感知訓練結合以突破免訓練方法的上限。另一個方向是發展更精準的時間一致性評測指標，彌補現有影片基準無法充分捕捉時間閃爍與視覺退化的不足。此外，將注意力感知的量化理念應用於其他生成模型元件，或結合稀疏化、剪枝等壓縮技術，也有潛力進一步提升影片世界模型的部署效率與生成品質。

## 實務應用指南

### 適用場景

1. **互動式影片世界模型部署**  
   適用於需要在邊緣裝置或雲端 GPU 上長時間運行的因果自迴歸影片世界模型，例如根據使用者動作與相機軌跡即時生成連續場景的遊戲引擎或模擬器。QuantWM 可將 KV 快取記憶體壓縮至約 1/6，降低長程世界上下文帶來的記憶體瓶頸。

2. **長影片生成服務**  
   對於需要生成數十秒至數分鐘影片的產品（如廣告素材、影視預覽、短影片生成平台），2-bit KV 快取量化能顯著減少每個生成區塊的記憶體佔用，讓單卡可服務更多並行請求。

3. **記憶體受限裝置上的影片 AI**  
   適用於 VR/AR 頭戴裝置、車載系統或行動裝置中的影片生成與世界模擬模組。透過 QuantWM 的免訓練量化，開發者可在不重新訓練模型的前提下，將模型部署到記憶體受限裝置。

4. **即時串流與互動敘事**  
   在需要持續接收使用者輸入並維持時間一致性的互動敘事、虛擬角色或直播特效場景中，QuantWM 可緩解 Key 量化造成的時間閃爍與視覺退化，提升觀看體驗。

5. **多使用者共享 GPU 的推理平台**  
   對於採用動態批次或連續批次的推理服務，降低 KV 快取記憶體可提升吞吐量並減少交換（swapping）開銷，特別適合以影片世界模型為後端的 SaaS 平台。

### 實作前置條件

**資料前提**
- 需取得目標模型的 BF16 權重與推理程式碼，並能存取歷史 Query 與 Key 的中繼特徵。
- 建議準備少量代表性影片提示（prompt）與動作序列，用於校驗量化後的時間一致性與視覺品質，因為 VBench 分數可能無法完整反映時間閃爍問題。

**運算前提**
- 至少一張具備充足顯存的 GPU，用於執行原始 BF16 模型作為黃金標準（ground truth）並比對量化結果。
- 需支援 INT2 儲存與低秩投影運算的推理框架或自訂 CUDA kernel；若使用現有框架，需確認其支援 per-group / per-channel 量化與動態反量化。

**技能前提**
- 熟悉 Transformer 注意力機制、KV cache 運作原理與常見量化流程（scale、zero-point、group-wise quantization）。
- 具備閱讀與修改推理框架程式碼的能力，特別是 attention kernel 與 KV cache 管理模組。
- 了解 K-means 分群、低秩近似（low-rank projection）與數值線性代數基礎，以便實作或調整 QSAC 與 PSAC。

### 實作步驟建議

1. **建立 BF16 基線與評測管線**  
   先以 BF16 KV 快取運行目標影片世界模型，記錄 VBench 分數、輸出特徵 MSE、注意力對數機率分布，以及視覺品質樣本，作為後續比對基準。

2. **實作 QVG 基線量化**  
   先導入現有的 centroid-residual 2-bit 量化（QVG），觀察是否出現時間閃爍與視覺退化。同時分別測試 K16V2、K2V16、K2V2，確認 Key 是否為主要退化來源。

3. **導入 QSAC：量化敏感度感知分群**  
   取代原本基於 K-means 的 Key 質心選擇，改為聯合考量歷史 Query 敏感度與殘差範圍，選出對 QK⊤ 影響較小的 INT2-friendly 質心。建議從中間層與最後一層開始調校，因為這些層對輸出退化最敏感。

4. **導入 PSAC：主子空間注意力補償**  
   針對 QSAC 後仍殘留的 Key 誤差，提取主要 Query 子空間，並以低秩投影將誤差分量映射回該子空間進行補償。可先嘗試較低秩（如 rank 8–32），評估額外開銷與視覺品質的權衡。

5. **端到端驗證與迭代調校**  
   比較 QuantWM 與 BF16、QVG 在 VBench 與自訂時間一致性指標上的差異；針對仍出現閃爍的場景，調整分群數量、殘差分群粒度、PSAC 秩與啟用層數。

6. **部署最佳化**  
   將量化後的 KV 快取儲存格式、反量化與 PSAC 補償整合進推理引擎，啟用記憶體池與連續批次，並監控延遲與吞吐量變化。

### 潛在風險與注意事項

- **基準分數與主觀品質脫節**  
  VBench 等影片分數可能「近乎無損」，但實際影片仍會出現時間閃爍與偽影。建議除了自動化指標外，必須進行人眼檢視與注意力權杖選擇分析。

- **Key 量化比 Value 更敏感**  
  不要僅以重建誤差（MSE）判斷量化品質。Key 擾動會改變注意力對數機率與時空權杖選擇，應優先保護 Key 的注意力行為。

- **PSAC 帶來的額外計算開銷**  
  低秩投影雖然計算量小，但在每層 attention 都執行仍會增加延遲。建議只在關鍵層啟用，或將其與反量化 kernel 融合以減少記憶體搬移。

- **不同模型架構的適用性差異**  
  QuantWM 針對因果自迴歸影片世界模型設計，若應用於非自迴歸或純空間生成模型，QSAC 與 PSAC 的敏感度定義可能需要重新調整。

- **質心儲存成本**  
  centroid-residual 方法需保留 BF16 質心，若分群數過多會抵銷部分記憶體壓縮收益。應根據目標壓縮率選擇分群數與殘差分群粒度。

### 與其他技術的整合建議

- **與推論框架整合**  
  可將 QuantWM 封裝為 vLLM、TensorRT-LLM 或自研推理引擎的 KV cache 量化外掛，重點修改 KV cache 分配器、attention kernel 與反量化路徑。

- **與模型壓縮技術搭配**  
  QuantWM 專注於 KV 快取量化，可與權重量化、activation 量化或投機解碼（speculative decoding）並行使用，進一步降低端到端延遲與記憶體。

- **與快取驅逐（cache eviction）策略結合**  
  在極長影片生成場景中，可將 QuantWM 與基於重要性的 KV 快取裁剪或壓縮策略結合，先量化再依注意力分數決定是否保留，兼顧長程一致性與記憶體上限。

- **與監控系統整合**  
  在生產環境中記錄每層 attention logits 的分布變化、量化後輸出 MSE 與記憶體使用量，當指標異常時自動切換回 BF16 或啟用更高位元量化。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先理解「KV 快取是什麼」以及「為什麼影片世界模型需要長程時間一致性」，再閱讀圖 1 與圖 2 的視覺比較，直觀感受 2-bit 量化造成的時間閃爍。技術細節可先跳過 QSAC 與 PSAC 的數學推導，重點掌握「Key 比 Value 更敏感」這個核心發現。

**AI 工程師**  
請聚焦第 3 節的動機分析與 QuantWM 的兩項技術實作細節：如何從 K-means 改為敏感度感知分群，以及如何用低秩投影補償注意力對數機率。建議對照你目前使用的推理框架，評估導入 QSAC/PSAC 所需的 kernel 修改與記憶體格式調整。

**研究人員**  
本文的關鍵貢獻在於揭示「Key 重建誤差小卻造成更大輸出退化」的現象，並將其歸因於注意力對數機率與時空權杖選擇的偏移。建議深入探討這一機制是否適用於其他長序列生成任務（如長文本、音訊），以及能否將 PSAC 推廣為通用的注意力穩定化模組。

**產品經理**  
請將本文視為一個「在記憶體節省與視覺品質之間取得平衡」的部署方案。重點關注圖 1 的記憶體壓縮數字（BF16 12.09 GiB → QuantWM 1.95 GiB）以及各基準的視覺品質改善，評估其對邊緣部署成本、並行服務量與使用者體驗的影響，同時留意基準分數無法完全反映主觀品質的風險。
