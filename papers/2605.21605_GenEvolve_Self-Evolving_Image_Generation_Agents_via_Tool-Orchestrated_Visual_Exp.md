## ⚡ TL;DR

開放式圖像生成需協調內部能力與外部工具，現有方法難以有效學習完整生成軌跡。

## 摘要翻譯

開放式圖像生成（open-ended image generation）不再是一個單純的提示到圖像（prompt-to-image）問題。高品質生成通常需要智慧體（agent）結合模型的內部生成能力（internal generative ability）與外部資源（external resource）。隨著需求變得更加多樣且嚴苛，我們旨在開發一個能夠透過軌跡（trajectory）自我演化、並在各種生成挑戰中更有效地使用工具的通用圖像生成智慧體（general image-generation agent）。為此，我們提出 GenEvolve，一個以工具編排視覺經驗蒸餾（Tool-Orchestrated Visual Experience Distillation）為基礎的自我演化框架。在 GenEvolve 中，每一次生成嘗試均被建模為工具編排軌跡（tool-orchestrated trajectory），其中智慧體收集證據（evidence）、選擇參考圖像（reference）、啟用生成技能（generation skill），並將它們組合成一個提示-參考程式（prompt-reference program）。不同於現有的智慧體生成方法（agentic generation method）主要依賴圖像級純量獎勵（image-level scalar reward），GenEvolve 會針對同一個需求比較多個軌跡，並將最佳-最差差異（best-worst difference）抽象為結構化視覺經驗（structured visual experience），且僅提供給特權教師分支（privileged teacher branch）。受同策略自我蒸餾（on-policy self-distillation）啟發，視覺經驗蒸餾（Visual Experience Distillation）提供密集詞元級監督（dense token-level supervision），協助學生模型（student）內化更優的搜尋（search）、知識活化（knowledge activation）、參考選擇（reference selection）與提示建構（prompt construction）能力。我們進一步建構了 GenEvolve-Data 與 GenEvolve-Bench。在公開基準測試（benchmark）與 GenEvolve-Bench 上的實驗顯示，相較於強大的基線模型取得顯著提升，並在現有的圖像生成框架（image-generation framework）中達到最先進水準（state-of-the-art）。我們的網站如下：https://ephemeral182.github.io/GenEvolve/

### 核心貢獻（3～5點）
- 提出 GenEvolve 自我演化框架，核心為工具編排視覺經驗蒸餾，將每次生成嘗試建模為工具編排軌跡，整合證據收集、參考選擇、生成技能啟用與提示-參考程式組合。
- 針對同一需求比較多個軌跡，將最佳-最差差異抽象為結構化視覺經驗並僅提供給特權教師分支，透過視覺經驗蒸餾提供密集詞元級監督，協助學生模型內化搜尋、知識活化、參考選擇與提示建構能力。
- 建構專屬訓練資料集 GenEvolve-Data 與評測基準 GenEvolve-Bench，以支援開放式圖像生成智慧體的訓練與評估。
- 在公開基準測試與 GenEvolve-Bench 上顯著優於強大基線模型，達到現有圖像生成框架中最先進水準。

### 適合對象
對圖像生成、智慧體系統與工具學習有興趣的研究人員與工程師，特別是關注開放式生成、自我演化框架、視覺經驗蒸餾，以及希望結合外部工具與內部模型能力以提升生成品質的進階使用者。

## 深度分析

#### 方法論解析

GenEvolve 的核心貢獻在於將 open-ended image generation（開放式圖像生成）重新定義為一個 agentic trajectory learning（智慧體軌跡學習）問題。不同於傳統的 prompt-to-image（提示到圖像）範式，該框架將每一次生成嘗試建模為 tool-orchestrated trajectory（工具編排軌跡），其完整流程涵蓋：搜集 textual evidence（文字證據）、檢索並篩選 visual reference（視覺參考圖像）、啟動 callable generation knowledge（可呼叫生成知識，即 generation skill（生成技能）），最終合成一組 prompt-reference program（提示-參考程式）z = (g, R)。其中 g 代表面向 downstream generator（下游生成器）的 targeted prompt（目標提示），R 則為經過篩選的 reference images（參考圖像）集合。此程式化表達明確區分了「智慧體的決策空間」與「生成器的執行空間」，使得 agent（智慧體）必須學習如何協調 internal generative knowledge（內部生成知識）與 external resource（外部資源）。

在學習機制上，作者指出現有 agentic generation method（智慧體生成方法）大多仰賴 image-level scalar reward（圖像級純量獎勵）進行軌跡優化，這類獎勵僅能告知「哪條軌跡較佳」，卻無法解釋「哪些決策導致了品質差異」。為此，GenEvolve 提出 Visual Experience Distillation（視覺經驗蒸餾，VED）。其運作邏輯是：針對同一請求採樣多條軌跡，比較 best-worst difference（最佳-最差差異），並將差異抽象為 structured visual experience（結構化視覺經驗）。此經驗僅餵入 privileged teacher branch（特權教師分支），而 student（學生模型）則在標準推論情境下運作。透過 on-policy self-distillation（同策略自我蒸餾）的框架，VED 提供 dense token-level supervision（密集 Token 級監督），使學生模型內化更優的 search（搜尋）、knowledge activation（知識活化）、reference selection（參考選擇）與 prompt construction（提示建構）策略。訓練目標結合了 group-relative policy optimization，讓 tool orchestration（工具編排）與 generator-facing program（面向生成器的程式）合成能力在軌跡層級得到細粒度優化。

為支撐此訓練流程，作者建構了 GenEvolve-Data。該資料集超越傳統的提示重寫語料，提供具備工具編排標註的軌跡資料，並篩選具備明確視覺回饋意義的 GT image cases，使 self-evolution（自我演化）過程中的視覺訊號具備可學習性。

#### 實驗數據解讀

評測層面，作者提出 GenEvolve-Bench，採用雙軌制設計：Knowledge-Anchored track（知識錨定組別）評估智慧體在外部事實檢索、長尾知識與多來源證據整合上的表現；Quality-Anchored track（品質錨定組別）則聚焦於生成品質、layout（版面配置）、attribute binding（屬性綁定）與 text rendering（文字渲染）等純生成維度。評分採用 KScore 搭配四項 judge dimension（評審維度），並輔以 WISE benchmark（WISE 基準測試）進行外部驗證。

實驗結果顯示，GenEvolve 在 GenEvolve-Bench 與 WISE 上均顯著優於強勁的 direct generator（直接生成器）與 agentic baseline（智慧體基線模型）。值得注意的是，框架在採用 NanoBananaPro 與 Qwen-Image-Edit 兩種不同 downstream generator（下游生成器）時皆能取得增益，顯示其學習到的 prompt-reference program（提示-參考程式）具備良好的可遷移性（transferability）。這暗示 GenEvolve 的進步並非來自於強化單一生成器的內部先驗，而是來自於更優的 tool orchestration（工具編排）與 generator-facing program（面向生成器的程式）合成能力。從量化趨勢觀察，無論是知識密集型或品質敏感型的請求，框架皆能透過軌跡比較與經驗蒸餾持續提升表現，達到 state-of-the-art（SOTA）水準。

#### 與現有研究的比較

相較於現代 image generation model（圖像生成模型）——如 DiT、FLUX、Hunyuan-DiT、NanoBanana Pro 或統一多模態模型如 Chameleon、OmniGen2 等——這些模型雖具備強大的 internal knowledge（內部知識）與 visual prior（視覺先驗），但本質上仍屬被動的 generator（生成器），不具備主動決定何時進行 factual lookup（事實查詢）、信任哪些 reference（參考資料）或活化何種生成知識的能力。GenEvolve 透過 agentic process（智慧體流程）填補了此一空缺。

在 agentic image generation（智慧體圖像生成）領域中，現有系統多僅處理生成流程的局部環節。GenAgent（GenAgent）強調 multi-turn reasoning（多輪推理）、tool use（工具使用）與 reflection（反思），但未針對軌跡決策提供 dense supervision（密集監督）；Gen-Searcher 與 ORIG 專注於 retrieval-augmented generation（檢索增強生成）以強化事實根據，卻較少觸及 reference selection（參考選擇）與 prompt-reference program（提示-參考程式）的聯合優化；GEMS 與 Mind-Brush 分別引入 memory（記憶）與 research-style workflow（研究式工作流程），但缺乏基於視覺回饋的自我演化機制；Maestro 與 CRAFT 利用 critic feedback（評論家回饋）或 verifier agent（驗證智慧體）進行迭代修正，然而其優化多發生於 inference time（推論階段），而非透過軌跡比較進行結構化經驗的內化。

GenEvolve 的差異化在於：它將 tool orchestration（工具編排）、reference selection（參考選擇）、knowledge activation（知識活化）、prompt-reference program synthesis（提示-參考程式合成）與 generator interaction（生成器互動）視為聯合優化目標，並透過 Visual Experience Distillation（視覺經驗蒸餾）實現可解釋的軌跡層級學習。然而，從方法論限制來看，該框架仍高度依賴 downstream generator（下游生成器）的渲染能力；若生成器本身對 reference images（參考圖像）的遵循性不足，則 prompt-reference program（提示-參考程式）的效益將受限制。此外，multi-trajectory comparison（多軌跡比較）與 best-worst difference（最佳-最差差異）的抽象過程涉及額外運算成本，且對於具備高度主觀審美或 implicit user intent（隱含使用者意圖）的請求，structured visual experience（結構化視覺經驗）的構建可能面臨標註模糊性。

#### 可重現性評估

就再現性而言，作者提供了專案網站（https://ephemeral182.github.io/GenEvolve/），但從提供的文本脈絡中，尚未明確提及原始碼、GenEvolve-Data 資料集或模型權重是否完整開源。GenEvolve-Data 的建構涉及複雜的軌跡收集、工具調用標註與 GT image cases 篩選，若缺乏公開的資料建構管線，第三方研究者難以複製相同的訓練環境。同樣地，VED 機制中的 privileged teacher branch（特權教師分支）與 group-relative policy optimization 的實作細節（如軌跡採樣數量、經驗抽象的具體特徵表示、教師分支的網路架構等）在摘要與引言中尚未完整揭露。

另一方面，GenEvolve-Bench 作為新的 diagnostic benchmark（診斷基準測試），其 Knowledge-Anchored track（知識錨定組別）與 Quality-Anchored track（品質錨定組別）的題目設計、評分者協議與 KScore 計算方式，亦有待更詳細的技術文件釋出，方能確保社群能進行公平的跨模型比較。在完整原始碼與資料釋出前，該研究的可重現性仍屬「部分受限」狀態。

#### 未來研究方向

GenEvolve 為自我演化圖像生成智慧體開闢了數個值得延伸的研究方向。首先，目前的 Visual Experience Distillation（視覺經驗蒸餾）屬於後訓練機制，未來可探索 online self-evolution（線上自我演化），使智慧體在部署後能持續透過與使用者互動及工具回饋更新策略，而非僅依賴靜態的軌跡資料集。其次，工具空間可進一步擴充至 3D 生成、image editing（影像編輯）與向量圖形工具，超越現有的 search（搜尋）與 reference retrieval（參考檢索）範疇。

第三，降低多軌跡採樣所帶來的運算開銷是實用化的關鍵；可研究如何透過輕量級的軌跡價值估計器或稀疏經驗蒸餾，在維持 dense token-level supervision（密集 Token 級監督）效益的同時減少記憶體與時間成本。第四，將此框架遷移至 video generation（影片生成）或其他多模態生成任務，檢驗 tool-orchestrated trajectory（工具編排軌跡）在時間序列資料上的泛化能力。最後，結合更強大的 vision-language model（視覺語言模型）來自動化 structured visual experience（結構化視覺經驗）的抽象與語言化，或許能進一步縮小 best-worst difference（最佳-最差差異）的語義鴻溝，提升 distillation（蒸餾）效率與最終生成品質。

## 論文問答

**Q1：為何開放式圖像生成不再被視為單純的提示到圖像（prompt-to-image）問題？**

A：現實中的生成需求往往涉及複雜的決策過程，智慧體必須判斷生成器已具備哪些內部知識、需要從外部取得哪些事實與參考圖像，以及如何將這些多元訊號轉譯為下游生成器可執行的指令。高品質生成已逐漸轉變為一個包含規劃、工具編排與回饋驅動適應的智慧體流程，而非僅僅是一次性的提示重寫。此外，使用者請求可能涵蓋長尾事實知識、參考特定外觀、多來源視覺證據、專業設計限制或隱含意圖，這些都無法透過單一提示完整捕捉。

**Q2：現有的智慧體生成方法存在哪些主要不足，使得它們難以應對多樣化的生成挑戰？**

A：現有方法大多僅處理生成流程的局部環節，例如僅專注於取得外部證據、包裹黑箱生成器，或在推論階段演化提示，卻未將工具使用、參考選擇、知識活化與提示建構進行聯合最佳化。更重要的是，這些方法主要依賴圖像級純量獎勵來優化軌跡，這類獎勵雖能指出哪條軌跡較佳，卻無法解釋具體是哪些決策導致了品質差異，導致學習訊號過於稀疏。因此，現有系統缺乏將視覺結果轉化為結構化經驗以指導智慧體自我演化的機制，難以在開放式情境中持續精進工具編排能力。

**Q3：建構能夠自我演化的通用圖像生成智慧體為何對當前領域至關重要？**

A：隨著圖像生成請求日益多樣與嚴苛，單靠提升模型內部逼真度已無法解決開放式生成問題，因為強大的生成器本身並不會決定何時需要搜尋、如何活用內部知識、哪些參考圖像值得信任，或如何利用失敗經驗指導未來行為。一個通用智慧體必須學會協調內部生成知識與外部工具，透過互動學習何時進行事實查詢、發出何種查詢、啟動哪些可呼叫的生成技能，並將這些訊號綁定為面向生成器的程式。這種從「單次提示」到「完整軌跡學習」的典範轉移，是實現能夠處理建築、創意轉移、科學插圖等複雜真實場景的關鍵。

**Q4：GenEvolve 的核心訓練框架「工具編排視覺經驗蒸餾」是如何運作的？**

A：GenEvolve 將每一次生成嘗試建模為一條工具編排軌跡，智慧體在其中蒐集文字證據、檢索並選擇視覺參考、呼叫可複用的生成技能，最終合成一個提示-參考程式 z=(g,R)。針對同一請求，系統會比較多條軌跡的視覺結果，將最佳與最差軌跡之間的差異抽象為結構化視覺經驗，並僅提供給特權教師分支。學生模型則在正常推論情境下運作，透過同策略自我蒸餾與群體相對策略優化，接收來自教師的密集詞元級監督，從而內化更優的搜尋、知識活化與提示建構能力。

**Q5：相較於傳統的圖像級純量獎勵，視覺經驗蒸餾（Visual Experience Distillation）帶來了哪些關鍵突破？**

A：傳統純量獎勵僅能告訴智慧體哪條軌跡整體較好，卻無法指出軌跡中哪些具體決策造成了品質落差，導致學習訊號稀疏且難以歸因。視覺經驗蒸餾則透過比較同一請求下的多條軌跡，將最佳與最差結果的差異轉化為結構化的視覺經驗，提供密集的詞元級監督訊號。這種教師-學生架構讓特權教師分支在擁有結構化經驗的條件下生成更優的目標分佈，而學生則能在正常推論上下文中學習內化這些細緻的決策差異，顯著提升工具編排與程式合成的精準度。

**Q6：為何 GenEvolve 選擇將生成過程建模為「軌跡學習」，並額外建構 GenEvolve-Data 與 GenEvolve-Bench？**

A：將生成視為軌跡學習能讓學習目標不再僅是單一提示，而是涵蓋工具決策、面向生成器的指令、生成結果與回饋的完整執行路徑，這對於協調內部知識與外部工具至關重要。GenEvolve-Data 超越了傳統的提示重寫語料庫，提供工具編排軌跡與經過篩選的真實圖像案例，使視覺回饋對自我演化具有實質意義。GenEvolve-Bench 則透過知識錨定與品質錨定雙軌設定，同時評估最終圖像品質與智慧體行為表現，填補了通用圖像生成智慧體在訓練資料與診斷基準上的缺口。

**Q7：本文使用了哪些評測基準來驗證 GenEvolve 的有效性？**

A：本文除了使用外部公開的 WISE 基準測試進行跨框架比較外，還自行建構了 GenEvolve-Bench 以進行更細緻的診斷評估。GenEvolve-Bench 包含知識錨定組別與品質錨定組別，分別檢視智慧體在外部事實 grounding 與品質敏感生成要求的表現，並採用 KScore 與四個評審維度進行量化。這些基準共同確保評估不僅涵蓋最終圖像品質，也涵蓋了智慧體在工具使用、參考選擇與提示-參考忠實度等方面的行為表現。

**Q8：GenEvolve 在實驗中展現了哪些具體的效能優勢？**

A：在 GenEvolve-Bench 與 WISE 等公開基準上，GenEvolve 均顯著優於強大的直接生成器與近期的智慧體基線模型，達到當前圖像生成框架中的最先進水準。實驗顯示，無論是使用 NanoBananaPro 或 Qwen-Image-Edit 作為下游生成器，GenEvolve 都能持續提升生成品質，證明其學得的提示-參考程式與工具編排策略具有良好的可遷移性。這些結果一致表明，透過視覺經驗蒸餾進行自我演化的智慧體，能夠在涵蓋建築、街景、科學插圖等多樣開放式請求中產出高品質圖像。

**Q9：從方法設計推論，視覺經驗蒸餾中的哪些組件對 GenEvolve 的效能至關重要？**

A：結構化視覺經驗的建構與檢索是核心，因為它將稀疏的圖像級獎勵轉化為可解釋的密集監督，使智慧體能明確學習最佳與最差軌跡間的決策差異。特權教師分支的設計同樣關鍵，它確保結構化經驗僅用於指導教師生成目標分佈，避免學生在推論時依賴額外資訊，從而維持同策略自我蒸餾的有效性。此外，群體相對策略優化與詞元級監督的結合，讓學生模型能在正常推論上下文中逐步內化更優的搜尋、參考選擇與提示合成策略。

**Q10：GenEvolve 特別適合應用於哪些實際的開放式生成場景？**

A：GenEvolve 特別適合需要協調外部知識與內部生成能力的複雜場景，例如需要精確事實查證的科學插圖、依賴特定參考外觀的建築設計與創意風格轉移，以及需要整合多來源視覺證據的街景生成。在這些情境中，單純的重寫提示無法滿足專業設計限制或隱含使用者意圖，而 GenEvolve 的工具編排軌跡能主動檢索證據、選擇適當參考並活化對應生成技能。這種能力使其能夠處理傳統直接生成器難以應對的長尾知識與多約束合成任務。

**Q11：若將 GenEvolve 部署於實際產品，其架構設計帶來哪些營運與擴展上的優勢？**

A：GenEvolve 的自我演化機制能隨著互動持續改進工具編排策略，減少對人工提示工程與後期修正的依賴，從而降低營運成本並提升自動化程度。其模組化的軌跡設計讓系統能夠對接不同的下游生成器，實驗已驗證其在 NanoBananaPro 與 Qwen-Image-Edit 上的可遷移性，使產品可靈活替換底層模型而無需重構整體流程。此外，結構化的提示-參考程式輸出具有可解釋性，便於開發者診斷智慧體在搜尋、參考選擇或技能路由上的決策路徑。

**Q12：GenEvolve 對圖像生成領域可能帶來哪些深遠的影響或典範轉移？**

A：GenEvolve 推動了從「單次提示到圖像」向「完整智慧體軌跡學習」的典範轉移，證明開放式圖像生成的核心挑戰在於如何協調內部知識與外部工具，而非僅提升單一模型的逼真度。其提出的視覺經驗蒸餾機制為智慧體學習提供了比純量獎勵更細緻的密集監督範式，可能啟發後續研究在視覺規劃、工具學習與自我改進方面的探索。同時，GenEvolve-Data 與 GenEvolve-Bench 的釋出也為通用圖像生成智慧體的訓練與評估建立了重要基礎，有助於加速該領域從封閉生成走向開放式、可互動的視覺智慧體生態系。

**Q13：GenEvolve 的方法論可能存在哪些固有的限制或挑戰？**

A：由於 GenEvolve 依賴下游生成器執行最終的圖像合成，其整體效能天花板仍受底層模型能力限制，若下游生成器對提示-參考程式的理解存在偏差，智慧體的優化成果可能無法完全展現。此外，為了比較多條軌跡並萃取結構化視覺經驗，系統在訓練階段需要額外的計算資源來生成與評估多個候選軌跡，這在資源受限的環境中可能構成部署障礙。再者，對於極端長尾或高度動態的事實知識，外部檢索工具的覆蓋率與時效性仍可能影響最終生成結果的準確度。

**Q14：在哪些情況下，GenEvolve 的工具編排與視覺經驗蒸餾可能遭遇失敗或表現不佳？**

A：當外部檢索工具無法提供與請求相關的高品質視覺或事實證據時，智慧體可能因錯誤的參考選擇而產生偏離使用者意圖的結果，此時視覺經驗蒸餾的監督訊號也會受到雜訊干擾。在需要極精細屬性綁定或複雜計數的任務中，即使軌跡規劃正確，下游生成器本身的限制仍可能導致最終圖像出現瑕疵，使得軌跡層級的優化難以完全彌補底層模型的不足。此外，若同一請求下的多條軌跡品質差異過小，最佳與最差差異的抽象可能變得模糊，進而削弱結構化視覺經驗的指導效力。

**Q15：基於 GenEvolve 的框架，未來研究可以朝哪些方向進一步拓展？**

A：未來可將工具編排視覺經驗蒸餾的範式擴展至影片生成、三維合成或多模態內容創作，讓智慧體在更複雜的時空或幾何場景中進行自我演化。另一方向是引入即時人類回饋或線上適應機制，使智慧體不僅依賴離線的軌跡比較，還能在與使用者互動過程中動態調整工具使用策略。此外，開發更輕量化的軌跡採樣與經驗萃取方法，或整合更多元的外部工具，將有助於降低運算成本並提升智慧體在開放世界中的知識覆蓋率與生成穩健性。

## 實務應用指南

### 適用場景

**建築與室內設計視覺化**：在需要同時滿足專業設計限制（如建築法規、結構邏輯、風格史料）的場景中，GenEvolve 可透過事實查詢與參考選擇，將多來源視覺證據與內部生成能力協調，輸出面向生成器的程式，產生具備正確透視、材質與空間關係的設計渲染圖，而非僅仰賴單一重寫提示。

**科學與醫學插畫生成**：針對涉及長尾事實知識（如特定生物構造、罕見疾病特徵、化學分子結構）的開放式圖像生成需求，智慧體可先執行搜尋以取得外部證據，再活化對應的生成技能，確保最終插畫在解剖比例、標示細節與視覺呈現上皆為有根據的生成，降低黑箱生成器常見的幻覺風險。

**品牌創意與視覺轉移**：當行銷團隊希望將參考特定外觀（如品牌既有視覺資產、藝術家參考風格）融入新創作，同時捕捉隱含使用者意圖（品牌調性、情感訴求）時，GenEvolve 能透過工具編排軌跡自動檢索並篩選參考圖像，建構提示-參考程式，驅動下游生成器完成高一致性的創意轉移。

**電商商品情境合成**：在商品圖拍攝成本高昂的情境下，系統可根據產品規格執行事實查詢，從內部資產庫檢索場景參考，並透過參考選擇與版面配置規劃，生成符合目標受眾與平台規範的高品質情境圖，並透過回饋驅動適應持續優化點擊率導向的視覺風格。

**城市街景與觀光模擬**：對於需要結合現實地理事實（如特定街區建築樣式、歷史街景樣貌）的生成任務，智慧體可協調外部搜尋與視覺先驗，在工具編排過程中驗證建築細節與環境脈絡，輸出貼近真實的街景或都市規劃模擬圖，適用於觀光導覽、遊戲場景或都市設計溝通。

### 實作前置條件

**資料需求**：需建構類似 GenEvolve-Data 的工具編排軌跡資料集，內容應涵蓋使用者請求、事實查詢字串、檢索所得參考圖像與其後設資料、生成技能路由決策、提示-參考程式（包含目標提示與選定參考圖像集合），以及對應的圖像級評估結果與診斷資訊。此外，需準備經過濾的真實影像案例作為視覺回饋來源，以支撐結構化視覺經驗的萃取。

**運算資源**：需具備支援大型多模態模型訓練與推論的 GPU 叢集（如 NVIDIA A100 / H100），用於學生模型與特權教師分支的同步訓練；另需建置向量資料庫與大規模圖像檢索索引（如 FAISS 或 Milvus），以支援即時參考選擇。若採用群組相對策略優化，需額外配置可同時處理多條軌跡採樣的批次運算環境。

**技能與團隊配置**：團隊需具備 LLM / VLM 智慧體開發經驗，熟悉檢索增強生成（RAG）系統建置、擴散模型或統一多模態模型（如 NanoBanana Pro、Qwen-Image-Edit）的部署與 API 整合，並具備強化學習或同策略自我蒸餾的訓練知識。此外，需有領域專家協助定義評審維度與知識錨定組別的評估標準。

### 實作步驟建議

**步驟一：定義軌跡空間與工具集**。明確智慧體在每次生成嘗試中可執行的離散動作，包括事實查詢、外部參考檢索、內部生成技能（如文字渲染、版面配置、屬性綁定）的知識活化，以及提示-參考程式的輸出格式。設計面向生成器的程式結構，確保下游生成器能正確解析提示與參考圖像的對應關係。

**步驟二：建構軌跡資料與回饋機制**。收集或標註高品質的工具編排軌跡，建立從請求到最終圖像的完整路徑。設計自動化與人工混合的評估流程，產生圖像級純量獎勵與細部診斷（如工具使用正確性、參考選擇適切性、提示-參考忠實度），作為後續視覺經驗蒸餾的訓練訊號來源。

**步驟三：部署雙分支架構**。建立學生模型（在標準推論階段上下文運作）與特權教師分支（僅在訓練階段接收結構化視覺經驗）。教師分支應具備存取最佳-最差軌跡差異摘要的權限，而學生模型僅依賴其自身歷史軌跡與正常可見資訊進行決策，確保蒸餾過程符合同策略自我蒸餾的設定。

**步驟四：實作視覺經驗蒸餾（VED）**。針對同一請求採樣多條工具編排軌跡，比較最佳與最差軌跡在各決策點的差異，將這些最佳-最差差異抽象為結構化視覺經驗。透過密集 Token 級監督，將教師分支的改進建議蒸餾至學生模型，結合群組相對策略優化穩定訓練，使學生內部化更好的搜尋、知識活化與提示建構策略。

**步驟五：整合下游生成器與產品管線**。將訓練完成的智慧體輸出（提示-參考程式）對接至選定的下游生成器（如 NanoBanana Pro 或 Qwen-Image-Edit），建立端到端的生成與評測管道。在 GenEvolve-Bench 或內部基準測試上驗證知識錨定組別與品質錨定組別的表現，確保工具編排策略能有效提升最終圖像品質。

**步驟六：持續演化與監控**。在生產環境中收集使用者回饋、生成結果與軌跡日誌，定期執行新一輪的同策略自我蒸餾。透過比較線上軌跡的優劣，持續更新結構化視覺經驗庫，使通用圖像生成智慧體能隨時間自我演化，適應新興的生成挑戰與使用者偏好。

### 潛在風險與注意事項

**推論延遲與成本膨脹**：工具編排涉及多次外部呼叫（搜尋引擎、圖像檢索、驗證智慧體），可能顯著增加推論階段延遲與營運成本。建議導入工具呼叫快取、參考圖像預索引機制，並設定每次請求的工具預算上限，避免過度展開多輪推理。

**參考圖像的版權與隱私風險**：檢索外部參考圖像可能觸及版權或個資問題。實務上應優先使用企業內部授權資產庫或公開授權圖庫，並在參考選擇階段加入來源過濾與使用授權檢查，確保生成流程合規。

**經驗蒸餾的偏差累積**：若結構化視覺經驗的建構邏輯存在系統性偏差（例如過度偏好特定搜尋引擎結果或錯誤的參考選擇模式），可能透過視覺經驗蒸餾放大錯誤行為。需定期以自動化評審維度（如 KScore）與人工抽查進行軌跡品質稽核，並建立限制驅動修正機制。

**與下游生成器的過度耦合**：提示-參考程式可能針對特定下游生成器的特性過度優化，降低跨模型的可轉移性。建議在訓練過程中輪替使用不同直接生成器進行驗證，或保留通用提示建構規範，避免緊密綁定單一黑箱生成器。

**事實幻覺與錯誤證據**：事實查詢可能引入錯誤或過時的外部證據，導致有根據的生成反而產生偽根據。應整合驗證智慧體或評論家回饋機制，對檢索到的文本與視覺證據進行交叉驗證，並在關鍵領域（如醫學、法律）保留人工最終確認關卡。

### 與其他技術的整合建議

**與現有 RAG 與企業知識庫整合**：將 GenEvolve 的工具編排層嵌入現有檢索增強生成架構，取代單純的文本片段檢索，強化視覺證據的選擇與使用。連接企業內部產品資料庫、設計規範庫或科學文獻庫，使事實查詢與參考選擇能活化內部知識，提升專業場景的生成準確度。

**與設計與創意工作流程整合**：透過 API 將智慧體輸出的提示-參考程式對接至 Figma、Blender、Adobe Creative Cloud 等設計工具，作為自動化概念發想與情緒板（mood board）生成的前端模組。設計師可在此基礎上進行微調，縮短從需求到視覺雛形的周期。

**與 MLOps / LLMOps 平台整合**：將工具編排軌跡、結構化視覺經驗與 GenEvolve-Bench 的評估指標接入現有的實驗追蹤與模型監控系統（如 Weights & Biases、MLflow）。透過持續記錄軌跡層級的表現，實現智慧體策略的 A/B 測試與線上學習閉環。

**與多模態理解模型整合**：利用統一多模態模型（如 BLIP3-o、Hunyuan Image 3.0）作為評論家回饋或驗證智慧體，對生成結果進行細部診斷（如屬性綁定正確性、版面配置合理性）。這些理解模型可提供比傳統圖像級純量獎勵更豐富的視覺經驗訊號，強化蒸餾品質。

**與低程式碼自動化平台整合**：將 GenEvolve 封裝為可呼叫的生成服務，整合至 Zapier、Make 或企業內部自動化流程中，讓非技術團隊（如行銷、營運）能透過表單或聊天介面觸發複雜的開放式圖像生成任務，無需手動處理提示工程或參考圖搜尋。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先建立「開放式圖像生成不同於單純提示到圖像」的核心直覺，將 GenEvolve 理解為一位會主動查資料、找參考、再下指令的虛擬設計師。可先從圖一的多元生成結果與適用場景切入，暫時略過同策略自我蒸餾與群組相對策略優化的數學細節，重點掌握工具編排軌跡與提示-參考程式的概念即可。

**給 AI 工程師**：請聚焦於視覺經驗蒸餾的實作細節，特別是學生-教師雙分支的資料流設計、最佳-最差軌跡比較的邏輯實作，以及如何將密集 Token 級監督整合進現有語言模型訓練框架。建議同時評估工具編排帶來的延遲成本，並規劃快取與批次採樣策略以符合生產環境的效能需求。

**給研究人員**：本文的核心貢獻在於將傳統圖像級純量獎勵提升為結構化視覺經驗的 token 級監督，並透過軌跡比較實現通用圖像生成智慧體的自我演化。建議深入分析 GenEvolve-Bench 中知識錨定組別與品質錨定組別的設計邏輯，以及此方法對多模態智慧體學習、工具使用與視覺推理交叉領域的啟發與限制。

**給產品經理**：請評估 GenEvolve 對現有產品生成管線的替代或增強價值，特別是在需要外部知識與參考圖像的專業場景（如電商、設計、教育內容）。導入時應權衡推論成本、工具延遲與 GenEvolve-Data 的建置投入，建議採取分階段路徑：先以特定高價值場景驗證智慧體編排相對於直接生成器的投資報酬率，再逐步擴展至開放式生成需求。
