## ⚡ TL;DR

協作音樂代理需要豐富且保留人類主導權的內部表徵。
以 JEPA 目標訓練階層式 Swin V2 編碼器學習 MIDI 鋼琴捲軸表徵，並用條件流匹配模型生成。

## 摘要翻譯

協作音樂代理（collaborative music agent）需要足夠豐富的內部表示，以同時支撐理解與生成；又要足夠靈活，能適應人類保有主導權（human agency）的工作流程。我們提出一個用於符號音樂（symbolic music）的階層式自監督（hierarchical self-supervised）「世界模型（world model）」：一個 255 萬參數的 Swin V2 編碼器（encoder），在 MIDI 鋼琴捲軸譜（piano-roll）影像上，以 JEPA 風格的目標〔音高平移等變性（pitch-shift equivariance）、時間平移等變性（time-shift equivariance）、遮蔽嵌入預測（masked embedding prediction），以及分佈正則化器（distributional regularizer）〕進行訓練，未使用任何標籤，也未使用音樂理論詞彙。探測凍結嵌入（frozen embedding）後發現，音樂屬性變得可解碼（decodable）的層級與其音樂時間尺度（musical time scale）相對應：樂句邊界（phrase boundary）可從最粗層級（coarsest level）讀取，音符密度（note density）與和聲細節（harmonic detail）則可從最細層級（finest level）讀取。時間結構（temporal structure）與樂句結構（phrase structure）僅從自監督目標中浮現，而和聲內容（harmonic content）則需額外監督才能顯現；一個小型和弦監督頭（chord supervision head）可將聯合和弦恢復（joint chord recovery）從 0.18 提升到 0.54，並使從未受監督的調性偵測（key detection）從 0.16 提升到 0.70。遵循表示自編碼器（Representation AutoEncoder）典範，一個條件流匹配模型（conditional flow-matching model）取代了經過訓練的解碼器（decoder），以 PCA 降維後的條件在像素空間（pixel space）中進行流匹配：它能以像素 F1（Pixel F1）0.996 重現目標視窗（target window），而同一種逐層條件化丟棄（per-level conditioning dropout）（用於控制生成變化偏離原稿的程度）也能在沒有專用填補取樣器（inpainting-specific sampler）的情況下，實現圖形提示（graphical prompting）的遮蔽填補（masked inpainting）。整個流程在 CPU 上執行，可在 2.8 秒內產生一個建議，在 Apple MPS 上則為 0.6 秒，我們並以現場互動式示範（interactive demo）展示。與基於 LLM 的大腦（LLM-based brain）協同運作時，這些能力構成了協作音樂代理的核心，服務於人類主導權，而非取而代之。

### 核心貢獻（3～5點）
- 提出一個 255 萬參數的階層式自監督世界模型，以 JEPA 風格目標在 MIDI 鋼琴捲軸譜上訓練，無需標籤或音樂理論詞彙。
- 發現凍結嵌入的階層式可解碼性與音樂時間尺度對應：樂句邊界在最粗層級，音符密度與和聲細節在最細層級。
- 證明時間結構與樂句結構可從自監督目標自然浮現，而和聲內容需額外監督；小型和弦監督頭顯著提升和弦恢復與調性偵測表現。
- 以條件流匹配模型實現 Representation AutoEncoder 典範，達到像素 F1 0.996 的重現品質，並透過逐層條件化丟棄支援圖形提示遮蔽填補。
- 整體流程具備即時互動潛力（CPU 2.8 秒 / Apple MPS 0.6 秒），並與 LLM 大腦整合以服務人類主導的音樂共同創作。

### 適合對象
對 AI 音樂理解與生成、自監督學習、JEPA 架構，以及人機協作音樂創作系統有興趣的研究人員與開發者；特別適合關注無標籤音樂表徵學習、階層式世界模型，以及即時互動式音樂共同創作應用的讀者。

## 深度分析

#### 方法論解析

本研究提出一套以「協作音樂代理（collaborative music agent）」為目標的「世界模型（world model）」，核心由一個僅 2.55M 參數的階層式 Swin V2 編碼器（hierarchical Swin V2 encoder）擔任「耳朵（Ears）」，再以條件流匹配模型（conditional flow-matching model）擔任「嘴巴（Mouth）」，負責將內部表示轉回可聽／可編輯的符號音樂（symbolic music）。整體設計遵循「表示自編碼器（Representation AutoEncoder, RAE）」典範：編碼器（encoder）只學習豐富的感知表示，不負責重建；重建與生成則交給獨立的生成模型處理。

**輸入表示：MIDI 鋼琴捲軸譜（MIDI piano-roll images）**  
為了兼顧可解釋性與 CPU 即時推論，作者將 MIDI 轉為二值化的鋼琴捲軸影像（binary piano-roll images）。每個裁切（crop）固定為 128×128 像素（pixels），時間軸以 32 分音符為最小單位並做速度正規化（tempo-normalized grid），因此一個裁切在 4/4 拍號下相當於 4 小節（bars）、在 120 BPM 下約 8 秒。像素為二值，故捨棄了力度（velocity）資訊；作者認為對歌曲創作（songwriting）場景而言，這樣的簡化是可接受的。區域外以空白填充，這讓「平移」操作有明確的語義：時間軸平移對應音樂的時間位移，音高軸平移對應半音移調。

**階層式 Swin V2 編碼器**  
編碼器採用 Swin V2 Transformer，從 L0 到 L5 共六個層級，對應的 patch 尺寸從 4×4 逐層放大到 128×128。這種階層結構讓最細層級（finest level）保留音符密度（note density）與和聲細節（harmonic detail），而最粗層級（coarsest level）則捕捉樂句邊界（phrase boundary）等長時間尺度結構。模型總參數僅 2.55M，是刻意為「GPU 資源有限的音樂人」所設計，並能在純 CPU 環境即時運行。

**自監督目標：JEPA 風格任務**  
訓練完全不使用標籤，也不引入任何音樂理論詞彙（music-theory vocabulary），目標函數包含三項 JEPA（Joint Embedding Predictive Architecture）風格任務與一項分佈正則化器（distributional regularizer）：

1. **音高平移等變性（pitch-shift equivariance）**：給定一個裁切與垂直位移向量 Δy（半音數），模型預測平移後裁切的嵌入（embedding）。這強制模型將音高軸的結構顯式編碼，而非讓位置編碼（positional encoding）隱含吸收。
2. **時間平移等變性（time-shift equivariance）**：給定水平位移 Δx（時間步），預測時間平移後裁切的嵌入。這讓模型學到節奏與時間結構（temporal structure）的穩定表示。
3. **遮蔽嵌入預測（masked embedding prediction）**：遮蔽輸入的某些區域，從上下文預測被遮蔽區域的嵌入，類似視覺與語言模型中的填空任務，促進局部音樂語境的學習。
4. **分佈正則化器 SIGReg**：採用 LeJEPA 風格的 SIGReg，避免表示崩塌（representational collapse）。與許多自監督方法使用 EMA 教師（EMA teacher）不同，這裡透過約束嵌入分佈來維持多樣性。

**生成端：條件流匹配模型作為解碼器（decoder）**  
遵循 RAE 典範，編碼器訓練完畢後即被凍結（frozen embedding），不再參與重建。生成端使用條件流匹配模型（conditional flow-matching model）在像素空間（pixel space）中進行生成，條件來自經主成分分析（PCA）降維後的凍結嵌入。這種設計的關鍵優勢是：

- 表示學習與重建解耦，編碼器可專注於判別性與結構性資訊；
- 透過「逐層條件化丟棄（per-level conditioning dropout）」控制生成偏離條件的程度：丟棄越多，生成結果越自由變化；丟棄越少，越忠實重現原始片段；
- 同一套 dropout 機制也能實現圖形提示（graphical prompting）的遮蔽填補（masked inpainting），無需額外的專用填補取樣器（inpainting-specific sampler）。

**推論效率**  
整條管線在 CPU 上產生一個建議需 2.8 秒，在 Apple MPS 上僅 0.6 秒，並已有現場互動式示範（interactive demo）。這對於需要即時回饋的協作創作流程至關重要。

#### 實驗數據解讀

作者透過線性探針（linear probing）檢驗凍結嵌入（frozen embedding）中各音樂屬性的可解碼性（decodability），並測試生成端的重建與控制能力。

**階層表示與音樂時間尺度的對應**  
最重要的發現是：不同音樂屬性的可解碼層級與其音樂時間尺度（musical time scale）高度一致。

- **樂句邊界（phrase boundary）** 與長程時間結構（temporal structure）可在最粗層級（coarsest level）被讀取；
- **音符密度（note density）** 與 **和聲細節（harmonic detail）** 則主要在最細層級（finest level）解碼。

這顯示模型並未將所有資訊混雜在同一層，而是自發地將不同時間粒度的音樂結構分配到適合的階層。這種結構化是純粹從自監督目標中湧現（emerge）的，無需任何樂理標籤。

**和聲資訊需要額外監督**  
實驗也指出，單靠自監督目標無法充分學習和聲內容（harmonic content）：聯合和弦恢復（joint chord recovery）的表現僅 0.18。然而，只要在凍結嵌入上加一個極小的和弦監督頭（chord supervision head），該指標便躍升至 0.54。更有趣的是，調性偵測（key detection）從未接受任何監督，卻從 0.16 提升至 0.70。這暗示：

- 凍結嵌入中已蘊含足夠的音高集合與調性線索，但缺乏「和弦功能」或「調性中心」的顯式組織；
- 少量的和弦標籤即可作為「錨點」，將原本分散的音高資訊重新組織成可解碼的和聲與調性表示。

這對實務應用有重要意涵：若目標是協助歌曲創作，可選擇性地加入和弦標籤監督，而不必從頭標註大量樂理資料。

**生成品質：像素 F1 與可控性**  
條件流匹配模型從 PCA 降維後的條件生成目標視窗（target window），達到像素 F1（pixel F1）0.996。對二值鋼琴捲軸影像而言，這代表幾乎完美的像素級重建。值得注意的是，編碼器從未以重建為目標進行訓練，因此這個結果強烈支持 RAE 典範：好的表示即使經過大幅降維，仍能支撐高品質生成。

**逐層條件化丟棄的雙重角色**  
同一個 dropout 機制同時控制兩件事：

1. **變化程度**：條件丟棄越多，生成結果偏離原始片段越遠，適合產生「靈感建議」；
2. **遮蔽填補（masked inpainting）**：使用者可在鋼琴捲軸上以圖形方式標示要保留與要生成的區域，模型無需專用填補取樣器即可完成區域性重寫。

雖然文中未提供變化程度與填補品質的量化指標，但 0.996 的像素 F1 與現場示範暗示該機制在實際互動中足夠穩定。

**推論速度**  
CPU 2.8 秒、Apple MPS 0.6 秒的延遲使系統適合即時互動。這在當前以大型 GPU 叢集為主流的生成音樂研究中相對罕見，也呼應了「為 GPU 貧乏的音樂人設計」的工程約束。

#### 與現有研究的比較

本研究處於「音樂理解」與「音樂生成」的交界，並與多條研究線有明確區隔。

**相對於大型音訊—語言模型（audio-language models）**  
近期大型音訊語言模型在通用音訊任務上表現亮眼，但多項研究指出，在特定音樂任務上，小型、針對性模型往往優於大型模型。本文直接採用符號音樂（symbolic music）與輕量編碼器，避免將作品上傳雲端，也降低運算門檻。這與「為創作者保留主導權（human agency）」的設計哲學一致。

**相對於隱式編碼音樂結構的生成模型**  
許多生成音樂模型（無論是音訊或符號領域）確實在內部隱式編碼了風格與結構，但它們難以「說出」自己聽到了什麼。協作夥伴需要能夠描述「這裡有個樂句邊界」或「這段和弦進行可以怎麼改」。本文透過 RAE 典範將表示學習與生成分離，使凍結嵌入可被探針、可被 LLM 理解，從而支援對話式回饋。

**相對於其他 JEPA 音樂研究**

- **Stem-JEPA**：從音訊預測樂器分軌（stem）相容性，屬於音訊域；本文則聚焦符號 MIDI，且採用階層式影像編碼器。
- **Hachana & Rasheed 的符號 JEPA**：在 tokenized 符號音樂上使用音樂動機的遮蔽策略，但發現表示被位置資訊主導，限制了風格與內容任務的遷移。本文改用鋼琴捲軸影像，並將音高／時間平移結構顯式寫入目標函數，減少位置偏見；同時以 SIGReg 取代 EMA 教師，進一步避免崩塌。
- **Music-JEPA**：學習動作條件化的音訊世界模型，需要鋼琴音訊與演奏資料的配對。本文無需任何表演動作或配對資料，僅需 MIDI。
- **ARIMA**：學習視窗化的符號音樂潛在預測表示。本文額外引入階層式多尺度架構與生成管線，並強調與 LLM 協作的應用場景。

**相對於傳統自編碼器（AutoEncoder）與變分自編碼器（VAE）**  
傳統上，表示學習與重建被視為權衡：壓縮過度會損失判別資訊，保留過多則失去抽象性。RAE 典範指出這是壓縮造成的假象——潛在變數可接近原始維度並重新排列輸入，重建由獨立模型負責。本文將此典範應用於音樂，並以流匹配模型（flow-matching model）作為生成端的「解碼器」。

**主要限制**

- **僅處理符號音樂**：無法直接分析或生成真實音訊，力度、音色、演奏表情等資訊被捨棄。
- **固定 4 小節視窗**：雖然適合歌曲創作片段，但對於長篇結構（如整首歌曲的段落安排）需要額外機制。
- **和聲需額外監督**：自監督目標本身不足以學出和弦功能，實際部署時仍需和弦標籤或知識庫。
- **評估指標偏重像素級**：0.996 的 pixel F1 並不保證音樂性；和弦與調性探針的數據集與評估細節在提供的摘錄中未詳述。

**已公開資訊**

**待確認或建議補強的項目**  
由於提供的摘錄未包含附錄與補充材料全文，以下項目仍需進一步確認：

- **原始碼（code）**：是否提供完整的訓練與推論腳本？
- **模型權重（model weights）**：2.55M 的小模型非常適合釋出，讓社群直接測試。
- **資料集（datasets）**：訓練使用了哪些 MIDI 資料集？前處理流程（濾除、轉調、速度正規化）是否公開？
- **訓練超參數**：學習率排程、優化器、batch size、訓練步數、硬體需求等。
- **評估資料與程式碼**：和弦與調性探針的資料集來源、訓練／測試分割、評分方式。
- **互動式示範（interactive demo）**：是否開放原始碼，或僅提供線上試用？

**可重現性優勢**  
- 模型極小（2.55M 參數），可在 CPU 上運行，降低硬體門檻；
- 輸入為標準 MIDI 轉鋼琴捲軸，資料取得與前處理相對簡單；
- 訓練無需標籤，理論上任何 MIDI 資料集皆可使用。

**可重現性風險**  
- 若補充材料未釋出程式碼與權重，其他研究者需從頭實作 Swin V2 與流匹配管線，細節差異可能導致結果難以對齊；
- 速度正規化、空白填充、裁切策略等工程細節對最終表現影響大，需要精確文件化。

#### 未來研究方向

**1. 跨模態與更豐富的音樂表示**  
目前系統僅處理二值化 MIDI 鋼琴捲軸。未來可將音符力度（velocity）、音色（timbre）、表情（expression）、微時間（micro-timing）納入輸入；或進一步發展音訊—符號聯合嵌入（audio-symbolic joint embedding），讓「耳朵」同時聽得懂錄音與 MIDI。

**2. 長程結構與歌曲層級理解**  
固定 4 小節視窗適合片段創作，但完整歌曲包含前奏、主歌、副歌、橋段等更大尺度結構。未來可探索階層式記憶機制、滑動視窗聚合、或歌曲級圖結構（graph-based reasoning），讓模型掌握數分鐘長度的音樂敘事。

**3. 自監督和聲學習**  
既然和聲內容（harmonic content）無法單靠現有目標湧現，可設計更強的音樂先驗，例如：移調不變的音高集合預測、相對音高對比學習、或和弦進行掩碼預測。目標是在不依賴大量和弦標籤的情況下，提升凍結嵌入對和聲的敏感度。

**4. 與 LLM 大腦的深度融合**  
本文將「耳朵」與「嘴巴」準備好，但未處理「大腦（Brain）」。未來可研究如何將多層級嵌入餵入大型語言模型（LLM），讓 LLM 進行音樂理論推理、風格比較、建議生成，並以自然語言與創作者對話。關鍵挑戰在於如何讓 LLM 理解這些非語言的音樂嵌入。

**5. 主觀與協作導向的評估**  
目前的評估以探針準確率與 pixel F1 為主。未來需要設計人類主觀實驗，衡量：建議是否真正有用、是否保留人類主導權（human agency）、是否激發而非取代創意。可採用 A/B 測試、創作者訪談、或長期協作日誌分析。

**6. 更靈活的可控生成**  
除了現有的逐層條件化丟棄與遮蔽填補（masked inpainting），未來可加入風格、情緒、流派、樂器等條件控制；也可發展「漸進式共同創作」介面，例如讓使用者先給一個和弦進行，再由模型補充旋律或對位。

**7. 即時 DAW 插件與低延遲串流**  
雖然目前 CPU 2.8 秒已可互動，但對於即時演奏或 DAW 內部使用仍顯不足。未來可優化模型架構（如知識蒸餾、量化、神經網路編譯），並開發 VST/AU 插件，讓音樂人在熟悉的工作環境中直接使用。

**8. 多樂器與編曲層次**  
目前鋼琴捲軸譜主要適合鍵盤式多聲部表示。未來可擴展至多軌 MIDI，讓模型理解不同樂器間的編曲關係，並生成包含節奏組、低音線、伴奏與主旋律的完整編曲建議。

**9. 理論分析：為何結構會湧現？**  
樂句結構（phrase structure）與時間結構（temporal structure）能從平移等變性與遮蔽預測中自然出現，而和聲卻不能。未來可進行更嚴謹的表示幾何分析，例如利用互資訊（mutual information）、探針複雜度、或因果介入（causal intervention），來理解不同自監督目標分別編碼了哪些音樂知識，並據此設計更高效的預訓練任務。

## 論文問答

**Q1：這篇論文想要解決的核心問題是什麼？為什麼「協作音樂代理」很難同時做到理解與生成，又不奪走人類主導權？**

A：這篇論文的核心問題是打造一個能夠真正「聆聽」並協助創作的音樂 AI，使其內部表徵同時支援音樂理解與音樂生成，卻仍讓人類掌握最終決定權。現有的大型音訊語言模型雖然能產生音樂，卻常在基礎音樂任務上表現不佳，且容易變成「替人完成」的黑箱生成器。因此，作者認為協作代理需要專屬的感知表徵與可控生成模組，才能在人類主導的創作流程中提供有意義的回饋與建議，而非取代創作者。

**Q2：現有的大型音訊語言模型或端到端生成模型，為何不適合直接拿來當共同創作夥伴？**

A：大型音訊語言模型缺乏精細的音樂感知能力，許多簡單的音樂任務反而由小型專門模型表現更好。端到端生成模型雖然隱含地編碼了音樂結構與風格，但這種隱含編碼無法「說明」樂曲中到底有什麼、或為什麼某個改動會更好。對人類創作者而言，可理解的描述與可控的建議遠比梯度或不可解釋的輸出更有用，因此需要分離表徵學習與重建生成。

**Q3：為什麼保有人類主導權對 AI 音樂工具很重要？本文如何定位這個助理的角色？**

A：在創意領域中，創作者普遍擔心 AI 會取代自己的判斷與品味，因此工具應該強化而非取代人類的創意決策。本文以「AI Rick Rubin」為隱喻，想像一位善於聆聽、能果斷表達喜好的製作人，但他只提供回饋與建議，實際執行仍交還給藝人。這種定位把代理視為對話式夥伴：它負責「耳朵」的感知與「嘴巴」的有限生成建議，最終選擇權始終在人類手中。

**Q4：本文提出的核心方法是什麼？請說明編碼器與訓練目標。**

A：作者提出了一個階層式自監督的符號音樂世界模型，使用僅 2.55M 參數的 Swin V2 編碼器，在 MIDI 鋼琴捲軸影像上進行訓練。訓練目標採用 JEPA 風格，包括音高平移等變性、時間平移等變性、遮蔽嵌入預測，以及 LeJEPA 風格的分佈正則化器 SIGReg。整個預訓練過程不使用任何標籤，也不依賴音樂理論詞彙，純粹從符號影像的結構中學習。

**Q5：與先前的 JEPA 音樂研究相比，本文的關鍵創新在哪裡？**

A：不同於先前在 token 化符號音樂或音訊上應用 JEPA 的工作，本文直接以 MIDI 鼼琴捲軸影像為輸入，並使用多尺度的階層式 Swin V2 編碼器。它把平移結構明確寫入目標函式，而不是讓位置編碼隱含吸收；同時以 SIGReg 防止表徵崩潰，而非使用 EMA 教師網路。這些設計讓學到的凍結嵌入能夠對應不同音樂時間尺度，使樂句邊界、音符密度、和聲細節等性質在不同層級被解碼。

**Q6：為什麼採用 Representation AutoEncoder 典範，並用條件流匹配模型充當解碼器？為何不直接訓練標準 VAE？**

A：傳統自編碼器常面臨壓縮與重建之間的取捨，而 Representation AutoEncoder 指出這個取捨其實是壓縮造成的假象；它讓潛在表徵接近原始維度，並把重建交給獨立的生成模型處理。本文以一個條件流匹配模型作為解碼器，在像素空間中根據 PCA 降維後的編碼器條件進行生成。如此一來，同一個無重建目標、訓練後凍結的編碼器就能同時擔任「耳朵」與「嘴巴」的條件來源，兼顧理解與生成。

**Q7：作者用哪些探針任務或指標來評估學到的表徵？**

A：作者在凍結嵌入上接上小型任務專屬頭部，探測樂句邊界、音符密度、和聲細節、和弦恢復與調性偵測等音樂屬性。他們特別觀察每種屬性在階層的哪一層變得可解碼，以驗證表徵是否對應音樂時間尺度。生成端則以像素 F1 衡量目標視窗重現能力，並評估遮蔽填補的效果與可控性。

**Q8：本文的關鍵量化結果有哪些？**

A：條件流匹配解碼器能夠以像素 F1 達到 0.996 的精準度重現目標視窗，顯示生成品質極高。在理解端，單靠自監督時聯合和弦恢復僅 0.18，但加上小型和弦監督頭後提升至 0.54；而從未直接監督的調性偵測也從 0.16 提升到 0.70。此外，時間結構與樂句結構能單純從自監督目標中湧現，和聲內容則需要額外監督才能達到實用表現。

**Q9：文中強調了哪些消融研究或設計選擇？**

A：模型架構的超參數是透過補充材料中的系列消融研究所選出，包括各層 patch 大小、深度與維度。128×128 的裁切尺寸、二值化像素、32 分音符的節拍正規化網格，以及 SIGReg 分佈正則化器，都是在音樂保真度與 CPU 推論速度之間權衡後的選擇。逐層條件化丟棄（per-level conditioning dropout）不僅控制生成變異程度，也讓圖形提示的遮蔽填補無需專用取樣器即可實現。

**Q10：這項技術在實務上可以應用在哪些創作情境？**

A：作曲者可以哼唱或彈奏一段想法，系統便能分析其結構、密度與和聲，並以自然語言給出回饋與改進建議。代理也能在鋼琴捲軸上生成短片段建議，或根據圖形提示對遮蔽區域進行填補。所有生成結果都只是建議，創作者可以決定是否採納、修改或忽略，從而維持人類主導權。

**Q11：哪些產品或工程考量形塑了這套系統的設計？**

A：為了讓沒有高效 GPU 的音樂人也能使用，並避免把未完成作品上傳到雲端，作者把「CPU 即時推論」設為基本工程限制。整個管線在 CPU 上產生一個建議只需 2.8 秒，在 Apple MPS 上更可縮短至 0.6 秒。模型僅 2.55M 參數，輸入為符號 MIDI，這讓記憶體與延遲都保持在個人裝置可負擔的範圍內。

**Q12：這項研究可能對 AI 音樂與人機協作領域帶來什麼影響？**

A：它證明小型、自監督的符號模型就能在音樂感知任務上達到可觀表現，同時保持可控與可解釋性，挑戰了「越大越好」的預設。耳朵／大腦／嘴巴的模組化架構也示範了如何把領域專屬感知模組接在大型語言模型之前，以彌補通用模型的音樂盲點。長遠來看，這有助於推動「輔助型、保有人類主導權」的創作工具，而非單純取代創作者的生成器。

**Q13：本文承認了哪些限制？**

A：作者明確指出「大腦」模組——也就是專家知識整合與基於 LLM 的推理——不在本文範圍內，因此完整的對話式共同創作尚未實現。模型使用二值化鋼琴捲軸影像，捨棄了音符力度等表現資訊。此外，系統僅處理符號 MIDI，未處理音訊訊號，因此音色、演奏細節與聲音品質都不在考量之內。

**Q14：這套方法可能的失敗案例或弱點是什麼？**

A：和聲內容無法單靠自監督目標充分湧現：在無監督情況下，聯合和弦恢復僅 0.18，顯示未監督表徵可能遺漏重要和聲資訊。固定的 128×128 裁切只涵蓋 4/4 拍下的四小節，可能無法捕捉更長程的曲式結構。二值像素與節拍正規化網格也可能扭曲帶有彈性速度、搖擺感或複雜微時值的音樂。

**Q15：未來可以朝哪些方向延伸或改進？**

A：下一步可將編碼器與基於 LLM 的「大腦」整合，實現完整的對話式回饋與音樂理論解釋。也可以嘗試擴展到音訊或多軌演奏表徵，同時維持低延遲。此外，未來可探索更多自監督目標或更大規模資料集，使和聲資訊能在無標籤情況下自然湧現，並開發更直覺的即時互動介面，讓共同創作流程更流暢。

## 實務應用指南

## 適用場景

1. **對話式共同作曲助理**：將系統嵌入一款 DAW 外掛或聊天機器人，讓音樂人上傳一段 MIDI 草稿後，AI 先「聽懂」樂句結構與節奏密度，再以自然語言回饋「這段副歌前似乎少了推進感」，並生成數小節的替代建議 MIDI，供創作者自行決定是否採用。

2. **互動式旋律／伴奏填補工具**：在鋼琴捲軸譜介面中，使用者框選某幾小節並給予圖形提示（graphical prompting），模型以遮蔽填補（masked inpainting）方式補完該區域，同時保留前後樂句風格；適合詞曲創作卡關時快速產生靈感素材。

3. **無標籤音樂資料探勘與策展**：對音樂平台或遊戲公司而言，可用凍結嵌入（frozen embedding）對大量 MIDI 進行分群、檢索相似樂句或偵測樂曲結構，無需人工標註和弦、調性或段落，降低內容管理成本。

4. **教育與音樂理論輔助**：將編碼器的中階表示視覺化，幫助學生觀察樂句邊界、音符密度與和聲細節如何對應到不同層級，並結合 LLM 解釋「為什麼這裡聽起來像要進入副歌」。

5. **在地化、離線優先的音樂 AI 工具**：由於模型僅 2.55M 參數且可在 CPU 上 2.8 秒、Apple MPS 上 0.6 秒產出建議，適合打造注重隱私、不需連雲端的桌面應用，讓音樂人不必把未發表作品上傳到第三方服務。

## 實作前置條件

- **資料**：大量符號音樂（symbolic music）MIDI 檔案，建議數萬至數十萬首；需能轉換為 128×128 二值鋼琴捲軸譜（piano-roll），時間量化為 32 分音符、速度正規化至固定 BPM。若目標包含和聲任務，可額外準備少量帶和弦標記的 MIDI 作為監督訊號。

- **運算**：訓練階段建議至少一張中階 GPU（如 NVIDIA A100 / RTX 4090 或同等記憶體），因 JEPA 風格目標與階層式 Swin V2 編碼器需要多次前向與對比計算；推論階段則可完全在 CPU 或 Apple MPS 執行，符合「GPU-poor」與離線使用情境。

- **技術能力**：熟悉 Python、PyTorch、Transformer 與電腦視覺基礎；具備 MIDI 處理經驗（如 `mido`、`pretty_midi`、`music21`）；了解自監督學習（self-supervised learning）、流匹配（flow matching）與 LLM 整合者為佳。

- **領域知識**：雖然模型本身不使用音樂理論詞彙，但產品設計者最好具備基礎樂理，才能正確解讀探針結果、設計回饋語句，並避免生成建議違反音樂常識。

## 實作步驟建議

1. **資料預處理管線**：將 MIDI 轉為二值鋼琴捲軸影像，解析度 128×128，時間軸對齊 32 分音符，並做音高與時間平移的資料擴增；建立 crop 配對，用於音高平移等變性（pitch-shift equivariance）與時間平移等變性（time-shift equivariance）目標。

2. **訓練階層式 JEPA 編碼器**：以 Swin V2 為骨幹，採用 JEPA 風格目標——遮蔽嵌入預測（masked embedding prediction）、平移等變性與分佈正則化器（distributional regularizer，如 SIGReg）——進行自監督訓練，全程不使用標籤。訓練完成後將編碼器凍結。

3. **探針與層級分析**：在凍結嵌入上訓練小型線性或 MLP 探針，驗證樂句邊界（phrase boundary）在最粗層級可解碼、音符密度與和聲細節在最細層級可解碼；若產品需要和弦或調性資訊，可加一個小型和弦監督頭（chord supervision head），以少量標記資料將聯合和弦恢復與調性偵測表現提升。

4. **建立條件流匹配生成器**：遵循 Representation AutoEncoder（RAE）典範，不訓練傳統解碼器，而是以條件流匹配模型（conditional flow-matching model）在像素空間生成鋼琴捲軸譜；條件來自 PCA 降維後的凍結嵌入，並引入逐層條件化丟棄（per-level conditioning dropout）以控制變化幅度。

5. **實作圖形提示與遮蔽填補**：利用同一套條件化丟棄機制，支援使用者在鋼琴捲軸上畫出遮罩，模型只對遮蔽區域進行填補，無需額外的專用填補取樣器（inpainting-specific sampler）。

6. **串接 LLM 大腦**：將編碼器輸出的中階表示與簡單音樂指標（速度、調性、音符密度）餵給 LLM，讓其扮演「AI Rick Rubin」角色，產生文字回饋與生成建議的描述；確保 LLM 只提供建議，不直接覆蓋使用者創作。

7. **部署與互動介面**：將模型轉為 ONNX 或 TorchScript 以加速 CPU 推論；開發網頁或 DAW 外掛介面，提供上傳 MIDI、視覺化嵌入、文字對話與一鍵匯入建議 MIDI 等功能。

## 潛在風險與注意項

- **和聲資訊不足**：自監督目標本身能學到時間結構與樂句結構，但和聲內容（harmonic content）較弱；若產品需要準確和弦或調性，必須額外加入監督訊號，否則可能產生聽起來「對拍不對調」的建議。

- **表示崩塌（representation collapse）**：JEPA 訓練容易出現崩塌，需確實使用分佈正則化器（如 SIGReg）並監控嵌入分佈；建議定期檢查不同 crop 的嵌入變異量。

- **二值化導致資訊遺失**：鋼琴捲軸為二值影像，捨棄了力度（velocity）與部分表情資訊；對於需要細膩演奏感的古典或電影配樂場景，可能需額外通道或後處理。

- **版權與資料偏見**：訓練 MIDI 資料集的版權狀態與風格分佈會影響生成建議；商用前應確認授權，並評估模型是否過度偏向特定流派或時代。

- **過度依賴與創作主導權**：產品設計應讓 AI 始終處於「服務而非取代」的角色，建議以可選方式呈現，並保留使用者最終決定權，避免創作同質化。

- **延遲與品質權衡**：雖然 CPU 推論僅 2.8 秒，但若同時執行 LLM 與多軌生成，整體回應時間可能拉長；建議對編碼器與流匹配模型做量化或快取常用嵌入。

## 與其他技術的整合建議

- **DAW 與 MIDI 工作站**：透過標準 MIDI 檔案或即時 MIDI 串流與 Ableton Live、Logic Pro、Cubase 等連接；可開發 VST/AU 外掛，讓音樂人在熟悉環境中直接取得 AI 建議。

- **大型語言模型（LLM）**：將凍結嵌入與探針輸出轉為結構化提示（如 JSON 描述樂句邊界、密度、調性），交由 LLM 進行專家知識整合與圖形推理，再將文字回饋與生成指令傳回音樂模組。

- **音訊模型與符號模型混合**：若產品需要處理錄音，可先以音訊轉 MIDI 工具（如基本頻率追蹤）將音訊轉為符號音樂，再送入本系統；生成結果亦可再經音色渲染模型轉為音訊預覽。

- **檢索與推薦系統**：利用凍結嵌入建立向量資料庫，支援以樂句搜尋樂句、自動標籤風格或情緒，並與現有內容管理後台整合。

- **互動式視覺化前端**：使用 Web Audio API 與 Canvas/WebGL 繪製鋼琴捲軸，讓使用者直接進行圖形提示與遮蔽填補，並即時預覽生成結果。

## 給不同背景讀者的閱讀建議

- **初學者**：建議先從「AI Rick Rubin」這個比喻開始理解整體願景——AI 不是幫你寫完整首歌，而是像一位有品味的製作人給回饋與片段建議。接著可略過 JEPA 與流匹配的數學細節，專注於圖 1 的耳朵／大腦／嘴巴流程，以及「凍結嵌入」與「遮蔽填補」這兩個最直觀的功能。

- **AI 工程師**：請重點閱讀第 2、3 節的模型架構與訓練目標，特別是階層式 Swin V2 編碼器如何與 JEPA 目標結合、SIGReg 如何避免崩塌，以及 Representation AutoEncoder 典範下條件流匹配模型如何取代傳統解碼器。實作時請留意資料擴增、PCA 條件維度與逐層條件化丟棄的實作細節。

- **研究人員**：本文的貢獻在於證明純符號、無標籤、無音樂理論詞彙的自監督目標，能夠依音樂時間尺度在不同層級浮現可解碼結構；建議深入探討為何和聲內容需要額外監督、樂句邊界為何出現在最粗層級，並思考如何將此方法擴展至多軌、多樂器或跨風格遷移。

- **產品經理**：請聚焦於「人類主導權」的設計原則與運算成本優勢——2.55M 參數、CPU 可跑、無需雲端，這些都是打造隱私優先、低門檻音樂工具的核心賣點。同時需評估和聲監督資料的需求、與 DAW 整合的使用者體驗，以及如何避免 AI 建議流於同質化。
