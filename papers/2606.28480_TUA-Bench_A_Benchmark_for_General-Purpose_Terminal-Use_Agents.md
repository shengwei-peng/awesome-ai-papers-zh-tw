## ⚡ TL;DR

現有基準測試多針對圖形介面或程式導向任務，缺乏對通用終端機代理人的全面評估。
本文提出TUA-Bench，收錄120真實任務，涵蓋日常與專業工作流程，並以確定環境與執行結果評分。
評估顯示最強終端機代理人僅達65.8%成功率，揭露規劃與錯誤恢復等顯著缺口。

## 摘要翻譯

隨著大型語言模型（large language models, LLM）與駕馭框架（harness frameworks）持續進步，運作於終端機的代理人越來越能夠執行範圍更廣、超越程式編寫的通用電腦使用任務。然而，現有基準測試（benchmarks）無法充分評估通用型終端機使用代理人（Terminal-Use Agent, TUA）：通用電腦使用基準測試主要針對圖形使用者介面（Graphical User Interface, GUI），而以終端機為基礎的基準測試則大多強調歷來原生於 Shell、以技術與程式設計為中心的工作流程。我們提出 TUA-Bench，一個針對終端機使用代理人（Terminal-Use Agent, TUA）的通用型基準測試（benchmark）。TUA-Bench 包含 120 項真實世界任務（real-world tasks），橫跨五個任務家族（task families），涵蓋日常數位活動（routine digital activities）——包括文件編輯（document editing）、電子郵件管理（email management）與即時網路資訊搜尋（live-web information seeking）——以及與博士級領域專家（PhD-level domain experts）共同設計、需要使用專業軟體（specialized software）的科學與工程工作流程（scientific and engineering workflows）。這樣的廣度使 TUA-Bench 有別於先前聚焦於 Shell 或特定領域的基準測試。每項任務皆為手動設計，於具有確定性設定指令碼（deterministic setup script）的真實終端機中執行，並透過基於執行的評分協定（execution-based scoring protocol）進行評估。我們發現，最強大的前沿代理人（frontier agent）Claude Code 搭配 Claude Opus 4.8 的最高推理強度（max reasoning effort），達到 65.8% 的整體表現（overall performance），且在兩個軌道（tracks）中均存在顯著差距。透過提供對終端機使用能力的廣泛且真實的評估，TUA-Bench 旨在加速從狹義且任務特定的助理轉變為能夠於多樣數位環境中可靠運作的通用型代理人（general-purpose agents）。

### 核心貢獻（3～5點）
- 提出 TUA-Bench，首個專為通用型終端機使用代理人設計的基準測試，填補既有評測僅聚焦圖形使用者介面或狹義 Shell 工作流程的缺口。
- 收錄 120 項手動設計的真實世界任務，橫跨五個任務家族，同時涵蓋日常數位活動（如文件編輯、電子郵件管理、即時網路資訊搜尋）與需專業軟體的博士級科學與工程工作流程。
- 透過確定性設定指令碼與基於執行的評分協定，建立可重現且客觀的評估環境。
- 實證顯示當前最強前沿代理人 Claude Code（Claude Opus 4.8）之整體表現僅達 65.8%，揭示終端機通用任務仍有大幅進步空間。

### 適合對象
從事大型語言模型、自主代理人與終端機工具使用研究的學者與工程師；特別是關注基準測試設計、通用型代理人能力評測，以及欲建構能於真實終端機環境中執行日常數位活動與科學工程工作流程之可靠代理人的研究團隊與開發者。

## 深度分析

#### 方法論解析

TUA-Bench 的方法論核心在於建立一個能精確評量 General-Purpose Agent (通用型代理人) 核心能力，同時排除非本質雜訊的測試環境。不同於既有以 Graphical User Interface (GUI)（圖形使用者介面）為主的 Computer-Use Agent (電腦使用代理人) 基準測試——這類測試要求代理人處理 Visual Perception（視覺感知）、Grounding（定位／對齊）與 Coordinate-Level Control（座標級控制）等視覺相關變因——TUA-Bench 選擇 Command-Line Interface (CLI)（命令列介面）作為互動媒介，使 Large Language Model (LLM)（大型語言模型）能在其 Text-Native Form（文字原生形式）的優勢領域中運作，從而更純粹地評量語言推理、規劃與工具組合能力。

在任務設計上，TUA-Bench 採用雙 Track（類別／軌道）架構，涵蓋 120 個手動設計的 Real-World Task（真實世界任務）。第一類 Track 為 Routine Digital Activity（日常數位活動），包括 Document Editing（文件編輯）、Email Management（電子郵件管理）、Live-Web Information Seeking（即時網路資訊搜尋）與 Multimedia Processing（多媒體處理）等一般性數位工作；第二類 Track 則為 Scientific and Engineering Workflow（科學與工程工作流程），由 PhD-Level（博士級）的 Domain Expert（領域專家）共同設計，涉及 Specialized Software（專業軟體）與高階專業流程。這種廣度使 TUA-Bench 顯著區別於過往聚焦 Shell（命令列解譯環境）或純 Programming Assistant（程式設計助理）場景的基準測試。

為確保評量的可靠性與公平性，每項任務均配備 Deterministic Setup Script（確定性設定指令碼），在真實終端機環境中建立可重現的初始狀態。評分機制採用 Execution-Based Scoring Protocol（基於執行的評分協定），透過驗證輸出檔案、系統狀態或指令執行結果來判定任務是否成功，而非僅比對文字輸出，從而避免評分上的主觀歧義。此外，研究團隊從 394 個候選任務中，經由嚴謹的人工篩選與修訂，剔除指令模糊、解法過於簡單或輸入輸出不一致的樣本，最終保留 120 個高品質任務，並手動驗證其正確性與難度梯度。

#### 實驗數據解讀

研究團隊對多個 Frontier Agent（前沿代理人）與 Harness Framework（駕馭框架）進行全面評測，並針對 Reasoning Effort（推理強度）進行消融實驗。實驗結果顯示，目前最強的組合——Claude Code 搭配 Claude Opus 4.8 並使用 max Reasoning Effort（推理強度）——其 Overall Performance（整體表現）僅達到 65.8%。

這一數據揭示了幾個關鍵訊息。首先，即使是最先進的 Autonomous Agent（自主代理人），在終端機環境中仍有超過三分之一的任務無法完成，顯示現階段技術距離「可靠的一般性終端機操作」尚存在顯著鴻溝。其次，無論是在 Routine Digital Activity（日常數位活動）或 Scientific and Engineering Workflow（科學與工程工作流程）Track（類別／軌道）中，均存在 Substantial Gaps（顯著差距），這意味著困難並非僅來自專業領域知識；即便是相對常規的文件處理或電子郵件管理，代理人在面對 Long-Horizon Planning（長期規劃）、Tool Use（工具使用）、Execution Monitoring（執行監控）與 Error Recovery（錯誤恢復）時依然表現不佳。

消融實驗中對 Reasoning Effort（推理強度）的調整進一步暗示，單純增加模型的推理計算量雖能帶來一定增益，但無法完全彌補架構性缺陷。這說明終端機代理人的瓶頸不僅在於基礎模型的推理能力，更在於 Harness Framework（駕馭框架）如何有效整合環境回饋、進行 Multi-Step Workflow（多步驟工作流程）的狀態追蹤，以及在開放式指令下維持行動一致性。

#### 與現有研究的比較

相較於現有研究，TUA-Bench 的定位十分明確。當前絕大多數 General Computer-Use Benchmark（通用電腦使用基準測試）以 GUI 為互動介面，例如 OSWorld、WindowsAgentArena、macOSWorld 等。這類基準測試雖能評估代理人在真實桌面環境中的能力，但不可避免地混雜了視覺定位與版面解析的雜訊，使得評量結果部分反映的是 Visual Perception（視覺感知）與 Coordinate-Level Control（座標級控制）能力，而非純粹的規劃與推理。TUA-Bench 透過 CLI 環境排除了這些變因，使研究者能更精確地診斷代理人在規劃、工具組合與邏輯推理上的缺陷。

另一方面，現有的 Terminal-Based Benchmark（終端機基準測試）大多聚焦於技術性與 Programming-Centric Workflow（以程式設計為中心的工作流程），例如 SWE-agent 與 OpenHands 主要處理 Software Engineering（軟體工程）任務。TUA-Bench 則將範疇擴展至一般性數位活動與跨領域專業流程，填補了「通用型終端機使用」在評量上的空白，並與 GUI 基準測試形成互補。

然而，TUA-Bench 也存在侷限性。由於其完全基於 CLI，對於那些本質上依賴圖形化操作或視覺回饋的任務（如複雜的所見即所得編輯或視覺化設計）則無法涵蓋。此外，雖然越來越多平台提供 Command-Line Tool（命令列工具），但部分應用程式的 CLI 功能仍不如 GUI 完整，這可能限制了基準測試對某些數位工作流的代表性。同時，TUA-Bench 目前聚焦於單一代理人與終端機的互動，尚未涉及多代理人協作或分散式 System Administration（系統管理）的複雜場景。

#### 可重現性評估

從可重現性的角度來看，TUA-Bench 在方法論層面具備堅實的基礎。每項任務均搭配 Deterministic Setup Script（確定性設定指令碼），確保執行環境的初始狀態一致，這是科學實驗可重現的核心前提。評分採用 Execution-Based Scoring Protocol（基於執行的評分協定），以客觀的執行結果取代主觀的人工判斷，降低了評分者間的變異。任務規格以標準化格式記錄，並經過手動驗證與篩選，理論上能讓其他研究者依相同條件復現實驗。

不過，根據目前提供的文本，關於原始碼、完整資料集與模型權重的公開釋出細節尚未明確說明。一個理想的 Benchmark（基準測試）開源釋出應包含：自動化評分腳本、容器化或虛擬化的執行環境、以及詳細的任務敘述與答案驗證邏輯。若 TUA-Bench 能進一步提供這些資源，將大幅提升其在學術界與產業界的採用度與信任度。此外，由於部分任務涉及 Live-Web Information Seeking（即時網路資訊搜尋），網路環境的動態變化可能對長期可重現性構成挑戰，需要透過網路存取的快照或快取機制來緩解。

#### 未來研究方向

基於 TUA-Bench 的實驗發現，未來研究可朝以下方向推進：

第一，強化開放式終端機環境中的 Long-Horizon Planning（長期規劃）與 Error Recovery（錯誤恢復）機制。65.8% 的成功率顯示現有代理人在 Multi-Step Workflow（多步驟工作流程）中容易因單一步驟失敗而無法回復，未來需要更強健的執行監控與回溯策略。

第二，發展混合式介面代理人（Hybrid Agent）。雖然 CLI 具備文字原生優勢，但現實中許多工作流程需要 GUI 與 CLI 協作。未來可探索能同時操作 Terminal-Use Agent (TUA)（終端機使用代理人）與 GUI-based Agent（圖形介面代理人）的統一架構，並建立對應的跨介面基準測試。

第三，針對 Specialized Software（專業軟體）與 Scientific Computing（科學計算）領域，建構更具深度的 Domain-Specific Benchmark（領域專屬基準測試）。TUA-Bench 已揭示專業 Track（類別／軌道）的挑戰，未來可與更多 Domain Expert（領域專家）合作，設計需要複雜實驗設計、Data Analysis（資料分析）與模擬驗證的長期任務。

第四，提升效率與安全性。目前最強表現依賴 max Reasoning Effort（推理強度），推論成本與延遲可能極高。未來研究可探討如何在維持效能的前提下降低計算開銷，同時評估賦予代理人廣泛 Shell（命令列解譯環境）存取權限所帶來的安全風險。

第五，利用 TUA-Bench 作為訓練信號。除了作為評量工具，其 Execution-Based Scoring Protocol（基於執行的評分協定）也可轉化為強化學習或自我改進（self-improvement）的回饋機制，訓練出更擅長終端機操作的 General-Purpose Agent（通用型代理人）。

## 論文問答

**Q1：TUA-Bench 旨在解決評估電腦使用代理人時的哪個根本缺口？**

A：TUA-Bench 旨在填補通用型終端機使用代理人（TUA）在評估上的重大空白。現有的通用電腦使用基準測試絕大多數針對圖形使用者介面（GUI），而現有的終端機基準測試則過度聚焦於歷史上原生於 Shell 的技術性與程式設計中心工作流程，導致日常數位活動與跨領域專業任務長期缺乏系統性的評估標準。這種斷層使得研究者難以準確衡量代理人在真實終端環境中執行多樣化、通用型任務的能力，因此 TUA-Bench 透過建立一個廣泛且真實的測試平台，來銜接這個關鍵的評估缺口。

**Q2：為何現有的 GUI 基準測試與終端機基準測試皆不足以評估通用型終端機代理人？**

A：現有的 GUI 基準測試要求代理人結合語言推理與視覺感知，必須解讀螢幕截圖、將動作定位到精確的螢幕座標，並對版面配置、解析度和渲染變化保持穩健，這些需求引入了感知與定位挑戰，使得評估部分測量的是視覺理解與座標級控制，而非核心的規劃與工具使用能力。另一方面，現有的終端機基準測試大多強調技術性與程式設計為中心的工作流程，未能涵蓋文件編輯、電子郵件管理、即時網路資訊搜尋等日常數位活動，以及需要專業軟體的科學與工程工作流程。因此，這兩類基準測試都無法全面評估代理人在終端機環境中執行通用電腦使用任務的真實能力，導致研究社群缺乏適當的評估依據。

**Q3：相較於圖形使用者介面，終端機介面為何特別適合大型語言模型代理人？**

A：命令列介面（CLI）以文字原生形式呈現電腦互動，指令明確、回饋為文字形式，且複雜工作流程可透過指令碼、管線和專門程式組合完成，這些特性與語言模型的優勢自然契合。相較於 GUI 需要處理視覺感知與空間定位的額外負擔，終端機環境讓代理人能更專注於核心的規劃、推理與工具使用能力，減少了非語言性的干擾因素。此外，許多高價值的專業工作流程——包括軟體工程、資料分析、科學計算、系統管理與多媒體處理——已主要透過終端機執行，且越來越多的平台提供官方命令列工具，使得終端機成為評估與部署通用型代理人的關鍵場域。

**Q4：TUA-Bench 的核心結構與涵蓋範圍為何？**

A：TUA-Bench 的核心結構包含 120 個真實世界任務，橫跨五個任務家族，涵蓋日常數位活動與專業工作流程兩大類別軌道。這些任務包括文件編輯、電子郵件管理、即時網路資訊搜尋等常見數位工作，以及與博士級領域專家共同設計、需要使用專業軟體的科學與工程工作流程。每個任務皆採手動設計，在真實終端機環境中透過確定性設定指令碼執行，並採用基於執行的評分協定來驗證完成度，確保評估的可靠性與可重現性。

**Q5：TUA-Bench 相較於先前終端機基準測試的關鍵創新為何？**

A：TUA-Bench 的關鍵創新在於其廣度與真實性，這使其有別於過往聚焦於 Shell 或特定領域的基準測試。它不僅涵蓋傳統的程式設計與系統管理工作，更擴展到簡報製作、試算表處理、圖像編輯、生物醫學影像分析與工程模擬等多元應用，真實反映現代終端機的多樣性。此外，所有任務均經過嚴謹的人工篩選與驗證，從 394 個候選任務中精選而出，移除指令模糊、解法過於簡單或輸入輸出不一致的項目，並搭配標準化格式、可執行環境與驗證程序，提供了一個高品質且具挑戰性的評估套件。

**Q6：TUA-Bench 採取了哪些具體設計選擇以確保任務品質與評估可靠性？**

A：為確保任務品質與難度，研究團隊從初始的候選任務池開始，應用嚴格的篩選流程，過濾或修訂指令模糊、解法過於簡單，或輸入檔案與目標輸出不匹配的任務。最終的基準測試經過人工驗證與設計，每個任務都配備確定性設定指令碼以確保環境可重現，並採用基於執行的評分協定來客觀判斷成功與否。這些設計選擇確保 TUA-Bench 能提供可靠、具挑戰性且資訊豐富的評估，真實反映終端機使用代理人在長期規劃、工具使用與錯誤恢復方面的能力。

**Q7：研究團隊在 TUA-Bench 上評估了哪些前沿模型與代理人框架？**

A：研究團隊對多個前沿模型與代理人框架進行了全面評估，其中包括當前能力最強的 Claude Code 搭配 Claude Opus 4.8 模型。評估設計特別包含對模型推理強度（reasoning effort）的消融實驗，以了解不同推理程度設定對終端機任務表現的影響。這些評估涵蓋了日常數位工作與科學工程兩大類別軌道，旨在全面檢視現有前沿代理人在通用終端機使用場景中的優勢與侷限。

## 實務應用指南

### 適用場景

**自動化日常數位辦公流程**
適合需要透過終端機批次處理文件編輯、試算表分析、簡報生成與電子郵件管理的場景。例如，讓終端機使用代理人（TUA）依據自然語言指令，在無圖形介面的伺服器環境中整理 CSV 報表、撰寫並發送客製化郵件，或將 Markdown 文件轉換為格式化的 PDF。

**科學與工程專業計算**
針對需要呼叫專業軟體（如生物資訊學套件、有限元素分析工具或資料處理函式庫）的研究與工程團隊。TUA-Bench 顯示，這類科學與工程工作流程需要博士級領域知識，代理人可協助研究人員在終端機中串接多步驟指令、管理依賴環境，並自動化實驗管線。

**即時網路資訊整合與動態報告生成**
適用於需結合即時網路資訊搜尋與本機資料處理的應用，例如金融分析師要求代理人查詢即時匯率、擷取網頁表格並與本機試算表進行交叉比對，最終在終端機中生成結構化分析報告。

**開發維運與系統組態管理**
在 DevOps 與系統管理場景中，代理人可透過命令列介面（CLI）執行系統設定、應用程式環境配置、日誌分析與故障排除。由於 CLI 回饋為文字原生形式，特別適合整合至現有的 Shell 工作流程與自動化腳本中。

**多媒體批次處理與內容轉換**
適合需要處理影像、音訊或影片轉碼、剪輯與後製的工作室或內容平台。透過命令列工具（如 FFmpeg、ImageMagick），代理人可在無頭（headless）伺服器上執行大規模批次多媒體處理，並監控執行狀態與錯誤復原。

### 實作前置條件

**資料與任務設計**
需準備高品質、手動設計的任務定義，涵蓋明確的初始狀態、目標描述與驗證邏輯。建議從大量候選任務（如論文中初始的 394 個候選）開始，並具備領域專家共同設計科學與工程類任務家族，以確保專業度與真實性。

**運算與環境資源**
每項任務需搭配可重現的執行環境，建議使用容器技術（如 Docker）搭配確定性設定指令碼，確保每次評測的初始狀態一致。此外，需準備終端機環境的運算節點，以及呼叫前沿大型語言模型（LLM）的 API 配額與推理強度設定（如 Claude Opus 4.8 的 max reasoning effort）。

**技術與技能門檻**
團隊需熟悉 Shell 腳本撰寫、Python 自動化、以及 LLM 駕馭框架（harness framework）的整合。設計基於執行的評分協定需具備測試工程經驗，能撰寫驗證程式來比對輸出檔案、資料庫狀態或命令執行結果，而非僅進行文字比對。

### 實作步驟建議

**步驟一：定義任務範疇與家族分類**
依據目標應用場景，劃分任務家族（如日常數位活動、科學與工程、即時網路資訊等）。針對每個家族細分子類別，確保覆蓋文件、郵件、多媒體、軟體開發與系統管理等維度，避免過度集中於單一程式設計領域。

**步驟二：設計確定性環境與初始化腳本**
為每項任務撰寫確定性設定指令碼，自動配置所需的輸入檔案、安裝依賴套件、設定環境變數與模擬外部服務。所有腳本應在隔離容器中執行，確保評測結果不會因環境殘留狀態而產生偏差。

**步驟三：建立基於執行的評分協定**
開發自動化驗證機制，透過檢查檔案系統狀態、命令輸出、資料格式正確性或特定字串模式來判定任務成功與否。避免使用主觀性評分，優先採用二元或數量化的執行結果驗證，以確保評分客觀且可重現。

**步驟四：建構代理人框架與工具呼叫介面**
整合現有駕馭框架或自建終端機互動層，使 LLM 能夠發送 Shell 命令、讀取文字回饋、管理長期上下文，並在多步驟工作流程中進行規劃與錯誤復原。確保代理人具備工具使用能力與執行監控機制。

**步驟五：迭代式任務篩選與難度校準**
從初始候選任務池中，手動過濾指令模糊、解法過於簡單或輸入輸出不一致的任務。透過先導測試（pilot run）觀察前沿代理人的表現，調整任務難度至合理範圍（如最強模型成功率約 60-70%，保留足夠的進步空間）。

**步驟六：部署評測管線與錯誤分析機制**
建立自動化批次評測管線，記錄每項任務的完整命令歷史、中介狀態與失敗原因。針對長期規劃、工具使用、執行監控與錯誤復原等維度進行細部分析，產生結構化報告以指引後續模型與框架的改進方向。

### 潛在風險與注意事項

**環境不可重現與狀態污染**
若初始化腳本未徹底清理環境或依賴外部網路資源，可能導致相同任務在不同時間執行結果不一致。建議嚴格使用離線或模擬的外部服務，並在每次評測前重置容器狀態。

**指令語意模糊與評分爭議**
任務描述若存在多重詮釋空間，將導致代理人行為偏離預期，且難以判定是否成功。務必在任務設計階段由多人審查，並透過基於執行的評分協定明確定義「完成」的客觀標準。

**安全性與惡意指令執行**
終端機代理人擁有執行系統命令的權限，存在誤刪檔案、洩漏敏感資訊或執行危險操作的风险。必須在沙箱環境中運行，限制網路權限與檔案系統存取範圍，並實行命令白名單或人工審查機制。

**任務難度過度擬合特定模型**
若任務設計僅針對當前最強模型（如 Claude Code）優化，可能導致基準測試很快過時或失去區辨度。應定期納入新模型進行測試，並保留一定比例需要長期規劃與複合工具使用的挑戰性任務。

**忽視視覺與圖形介面能力的缺口**
TUA-Bench 專注於文字原生介面，但許多真實應用仍需圖形使用者介面（GUI）操作。在評估通用型代理人時，應意識到此基準測試並未涵蓋視覺感知與座標級控制，需與 GUI 基準測試互補使用。

### 與其他技術的整合建議

**與 CI/CD 及自動化測試管線整合**
將 TUA-Bench 的評測邏輯嵌入持續整合／持續部署（CI/CD）流程，作為終端機代理人版本發布前的回歸測試。每次框架更新後，自動執行全套任務並比對成功率變化，確保新功能不會破壞現有能力。

**與現有駕馭框架（如 OpenHands、SWE-agent）銜接**
無需從頭建構代理人核心，可將 TUA-Bench 的任務環境與評分協定封裝為標準化介面，供現有 CLI 導向的代理人框架呼叫。這能加速實驗迭代，並直接比較不同框架在通用電腦使用任務上的優劣。

**與容器編排及雲端基礎設施結合**
利用 Kubernetes 或 Docker Swarm 大規模並行執行確定性設定指令碼，支援大量任務的批次評測。雲端環境亦便於模擬多樣化的作業系統與應用程式配置，擴展基準測試的覆蓋廣度。

**與 GUI 基準測試形成互補評估體系**
建議同時採用 OSWorld、WebArena 等圖形介面基準測試，建立「文字介面 + 圖形介面」的雙軌評估。對於需要跨介面操作的產品，可設計混合軌道，評估代理人依據任務特性自動選擇最適介面的能力。

**與可觀測性工具整合**
接入結構化日誌系統與追蹤工具（如 OpenTelemetry），詳細記錄代理人的推理鏈、工具呼叫序列與錯誤復原行為。這些資料不僅用於評分，更能作為改進長期規劃與執行監控演算法的訓練素材。
