## 摘要翻譯

僅解碼器大型視角合成模型（Large View Synthesis Models, LVSMs）結合 KV 快取（KV-cache），近期透過神經網路回歸新視角而無需重建三維幾何，達到了最先進的品質，而測試時訓練（Test-Time Training, TTT）層雖能節省計算量，但會犧牲品質。我們提出測試時烘焙（Test-Time Baking, TTB），這是一種從跨視角注意力（cross-view attention）中學習將全域場景資訊烘焙至輕量級多層感知器（Multi-Layer Perceptron, MLP）的策略，能實現快速且高保真的新視角解碼。第一個關鍵在於重新利用 TTT 的快速權重多層感知器（fast-weight MLP），使其從輸入輸出對中明確學習跨視角注意力映射（cross-view attention mapping），而非完全取代注意力，在達到與 TTT 相同的渲染效率的同時，提供顯著更高的品質。第二個關鍵解決了上下文預填充（context prefilling）與新視角渲染之間的模態不對齊（modality misalignment）問題：我們將上下文標記（context tokens）解耦為僅相機上下文渲染標記（camera-only context rendering tokens，作為 TTB 輸入）以及包含影像內容的上下文真實標記（context ground-truth tokens，作為 TTB 映射目標），確保烘焙後的多層感知器免於面對上下文與新視角處理之間的模態泛化（modality generalization）挑戰。我們的方法在多個基準測試上實現了高達 **23 倍**的渲染加速，同時品質與最先進方法相當。專案頁面：https://test-time-baking.github.io

### 核心貢獻（3～5點）
- 提出測試時烘焙（Test-Time Baking, TTB）策略，將跨視角注意力中的全域場景資訊烘焙至輕量級多層感知器，兼顧渲染效率與高保真品質。
- 重新利用測試時訓練（TTT）的快速權重多層感知器，使其從輸入輸出對中明確學習跨視角注意力映射，在不取代注意力的前提下達到與 TTT 相同的渲染效率，並顯著提升品質。
- 解決上下文預填充與新視角渲染之間的模態不對齊問題：將上下文標記解耦為僅相機上下文渲染標記（作為 TTB 輸入）與包含影像內容的上下文真實標記（作為 TTB 映射目標），使烘焙後的多層感知器免於面對模態泛化挑戰。
- 在多個基準測試上實現高達 23 倍的渲染加速，品質與最先進方法相當。

### 適合對象
從事新視角合成（novel-view synthesis）、三維視覺、視覺變換器（Transformer）架構優化，以及對高效神經渲染、測試時自適應方法與大型視覺模型推論加速感興趣的研究人員與工程師。

## 深度分析

#### 方法論解析

本文提出測試時烘焙（Test-Time Baking, TTB），其核心思想在於重新定位測試時訓練（Test-Time Training, TTT）內循環優化的學習目標，從而兼顧渲染效率與品質。

**問題背景與動機**

大型視角合成模型（Large View Synthesis Models, LVSMs）採用僅解碼器（decoder-only）架構，透過跨視角注意力（cross-view attention）層處理上下文視角（context views）並渲染新視角（novel views）。DVSM 引入 KV 快取（KV-cache）作為全域場景狀態（global scene state），雖然提升了品質與效率，但在密集上下文視角（dense context view）條件下，每個標記（token）對 KV 快取的線性複雜度（linear complexity）注意力運算仍使渲染時間過於昂貴。LaCT 採用 TTT 層取代跨視角注意力層，透過快速權重多層感知器（fast-weight MLP）的內循環優化（inner-loop optimization）實現常數複雜度（constant-complexity）渲染，但代價是渲染品質（rendering quality）顯著下降。

**TTB 的核心機制**

TTB 的第一個關鍵在於改變內循環學習目標（inner-loop learning target）。傳統 TTT 將快速權重 MLP 訓練為直接從查詢映射到原始值標記（value tokens），本質上是線性注意力（linear attention）的變體。TTB 則將學習目標設定為跨視角注意力的輸出標記，即讓快速權重 MLP 學習跨視角注意力映射（cross-view attention mapping）的輸入輸出對（input-output pairs）。這種設計使快速權重 MLP 與注意力機制協作而非取代它，從而保留跨視角注意力所編碼的豐富場景資訊（scene information）。此設計也使 TTB 超越線性注意力的詮釋框架，學習目標可來自任意非線性層或富含額外場景資訊的標記。

**模態不對齊問題與解決方案**

第二個關鍵洞見在於識別並解決模態不對齊（modality misalignment）問題。在重建階段（reconstruction stage），快速權重 MLP 使用同時包含相機與影像資訊的上下文標記進行更新；在渲染階段，更新後的 MLP 卻需處理僅含相機資訊（無影像內容）的新視角標記。這種重建-渲染輸入模態差異迫使烘焙後的 MLP 承擔模態泛化（modality generalization）的挑戰。

TTB 的解決方案是將每個上下文視角解耦為兩類標記對：（1）上下文真實標記（context ground-truth tokens），由輸入相機與影像產生，承載待烘焙的全域場景資訊；（2）僅相機上下文渲染標記（camera-only context rendering tokens），僅由相機輸入產生，模擬新視角渲染條件。在每個 TTB 層，快速權重 MLP 被優化以將渲染標記映射到對應的真實標記，後者包含影像與跨視角注意力資訊。優化後的 TTB-MLP 隨後在上下文渲染標記與下游新視角渲染標記間共享，確保所有層的條件化（conditioning）保持一致。

**與光場優化的類比**

TTB 與傳統隱式輻射場與光場重建存在自然類比：傳統方法將 MLP 優化為從空間座標映射到輻射值，而 TTB 將快速權重 MLP 優化為從射線-區塊潛在座標（ray-patch latent coordinates）映射到其外觀潛在表示（appearance latent representations），本質上是在潛在空間中執行少步驟的光場優化。這一觀點啟發了收斂導向（convergence-oriented）的多步驟 MSE 訓練策略，強調迭代優化而非一次性摘要。

#### 實驗數據解讀

**渲染加速效果**

TTB 實現高達 23 倍的渲染加速（rendering speedup），這是一個極具實用價值的成果。在密集上下文視角場景下，傳統基於 KV 快取的跨視角注意力需要對所有上下文標記執行注意力運算，計算量隨上下文視角數線性增長。TTB 透過將場景資訊烘焙進常數大小的 MLP，使新視角渲染時僅需執行 MLP 前向傳播，計算量與上下文視角數無關，從根本上解決了可擴展性瓶頸。

**品質保持**

TTB 在多個基準測試（benchmarks）上達到與最先進（state-of-the-art）方法相當的品質，這意味著 23 倍加速並非以犧牲品質為代價。相較於 LaCT（TTT 變體）顯著的品質下降，TTB 透過將學習目標從原始值標記轉向跨視角注意力輸出，成功保留了注意力機制所編碼的豐富上下文資訊。

**帕累托前緣的達成**

實驗結果（圖 1）顯示 TTB 達成了品質與速度的帕累托前緣（Pareto frontier）。這意味著在給定品質預算下，TTB 提供最快的渲染速度；在給定速度預算下，TTB 提供最高的渲染品質。這種雙重優勢來自於 TTB 的設計哲學：以額外的上下文視角處理時間（context-view processing time）換取更快、更高保真（high-fidelity）的新視角渲染（novel-view rendering）。

**模態解耦策略的有效性**

將上下文標記解耦為真實標記與渲染標記的策略，消除了重建-渲染階段的模態不對齊問題。實驗結果間接驗證了此設計的必要性：若不進行此解耦，烘焙後的 MLP 將難以泛化到僅含相機資訊的新視角查詢（novel-view queries），導致品質下降。

#### 與現有研究的比較

**相較於 LaCT（TTT 變體）**

LaCT 將跨視角注意力層完全替換為 TTT 層，雖然實現常數複雜度渲染，但品質顯著下降。TTB 的核心改進在於不取代注意力，而是烘焙注意力的輸出，使快速權重 MLP 成為注意力的補充而非替代。從預訓練僅解碼器模型（pretrained decoder-only model）權重初始化雖能部分改善 LaCT 品質，但品質差距（quality gap）仍然顯著；TTB 則透過改變學習目標本身來縮小此差距。

**相較於 DVSM（KV 快取變體）**

DVSM 透過 KV 快取預填充實現品質與效率的初步平衡，但在密集上下文視角下仍受限於線性複雜度。TTB 將全域場景狀態從 KV 快取轉移至烘焙後的 MLP，實現了真正的常數複雜度渲染，同時保持 KV 快取版本的高品質特性。

**相較於基於幾何的方法**

相較於三維高斯潑濺（3D Gaussian Splatting, 3DGS）等基於幾何的方法，TTB 繼承了 LVSM 的無幾何場景表示（geometry-free scene representations）優勢，在鏡面反射（mirror reflections）、半透明材質（translucent material）等 3DGS 難以處理的場景中表現更佳。此外，TTB 將場景烘焙為常數大小的 MLP，避免了顯式 3D 表示在更多輸入視角下輸出大小線性增長的問題。

**相較於每場景優化方法**

每場景優化（per-scene optimization）方法（如 NeRF、3DGS）雖能達到高品質，但無法隨訓練場景擴展（scaling），且在少輸入視角下品質快速下降。TTB 屬於基於學習（learning-based）的前饋方法，繼承了 LVSM 的可擴展性優勢，同時透過烘焙機制實現接近每場景優化的品質。

**限制與侷限**

TTB 的限制在於需要額外的上下文視角處理時間來執行烘焙過程。雖然新視角渲染極快，但整體流程的時間預算需考慮烘焙成本。此外，烘焙後的 MLP 為場景特定，無法跨場景共享，這與每場景優化方法有相似的特性。對於需要即時處理多個場景的應用，此限制可能成為瓶頸。

實驗在多個基準測試上進行，這些基準應為新視角合成領域的標準資料集（如 RealEstate10K、DL3DV、ScanNet 等）。具體使用的資料集需參考論文後續章節的實驗設定部分。

#### 未來研究方向

**烘焙效率的進一步優化**

當前 TTB 以額外上下文視角處理時間換取新視角渲染加速。未來研究可探索：（1）減少烘焙所需的內循環步數；（2）並行化烘焙過程；（3）增量式烘焙策略，允許在新增上下文視角時高效更新烘焙後的 MLP。

**跨場景泛化的烘焙**

目前烘焙後的 MLP 為場景特定。若能發展出可跨場景共享部分參數的烘焙機制，將進一步提升方法的實用性。這可能涉及元學習（meta-learning）或條件化 MLP 等技術。

**與生成式模型的整合**

LVSM 已有生成式擴展，TTB 可與此類擴展結合，實現高效的生成式新視角合成。烘焙機制可能為條件化生成提供更緊緻的場景表示。

**動態場景的烘焙**

當前方法假設靜態場景。將 TTB 擴展至動態場景是自然的下一步，這需要在烘焙過程中編碼時間維度的資訊，並設計能處理時變查詢的快速權重 MLP。

**理論分析的深化**

TTB 與光場優化的類比開啟了理論分析的新方向。未來研究可深入探討：（1）TTB 內循環的收斂性；（2）烘焙後 MLP 的表達能力邊界；（3）模態解耦策略的理論必要性。

**與其他高效注意力機制的結合**

TTB 的學習目標可來自任意非線性層，未來可探索將 TTB 與稀疏注意力、局部注意力等其他高效注意力變體結合，在不同層採用不同的烘焙策略，進一步優化品質-效率權衡。

**硬體加速的適配**

烘焙後的 MLP 為標準的前饋網路，易於在 GPU、TPU 等硬體上加速。未來可探索專門的硬體優化，如將烘焙過程與渲染過程在異質硬體上分離執行，以最大化整體吞吐量。

## 論文問答

**Q1：TTB 試圖解決的核心問題是什麼？**
A：TTB 主要解決的是僅解碼器大型視角合成模型（Decoder-only LVSM）在新視角渲染時的效率問題。雖然配備 KV 快取的 DVSM 已達到最先進的渲染品質，但在密集上下文視角條件下，由於每個標記對 KV 快取具有線性複雜度的注意力運算，渲染時間仍不切實際。TTB 的目標是在維持高保真渲染品質的同時，大幅降低新視角解碼的計算成本，從而達到品質與速度之間的帕累托前緣。

**Q2：為什麼現有方法（如 LaCT 的 TTT 層）無法同時兼顧品質與效率？**
A：LaCT 採用測試時訓練（TTT）層取代跨視角注意力層，雖然能達到常數複雜度的渲染速度，但卻顯著犧牲了渲染品質。這是因為 TTT 將快速權重 MLP 的內循環優化目標設定為原始的 value 標記，等同於完全取代了注意力機制，而非與之協作。即使從預訓練僅解碼器模型權重初始化，品質差距仍然明顯，無法真正逼近預訓練模型的表現。

**Q3：為什麼這個問題在新視角合成領域如此重要？**
A：新視角合成在虛擬實境、擴增實境、三維內容創作等應用中扮演關鍵角色，而這些場景對即時性與高保真度都有嚴格要求。基於 Transformer 的渲染器雖然具備優異的擴展性與學習能力，能處理鏡面反射、半透明材質等傳統幾何表示難以應對的場景，但若渲染速度過慢，便難以實際部署。TTB 透過將全域場景資訊烘焙進輕量 MLP，使高品質新視角渲染變得可行，對於推動此技術的實用化具有重要意義。

**Q4：TTB 的核心方法是什麼？**
A：TTB 的核心方法是將 TTT 快速權重 MLP 的內循環學習目標從原始的 value 標記重新設定為跨視角注意力的輸出標記。換言之，MLP 不再試圖取代注意力機制，而是學習「烘焙」跨視角注意力所產生的全域場景資訊。這種設計使烘焙後的 MLP 能在新視角渲染時，以常數複雜度快速檢索場景資訊，同時保留注意力所帶來的豐富場景理解能力。

**Q5：TTB 如何解決模態不對齊問題？**
A：TTB 識別出 MLP 快速權重預填充中存在重建與渲染階段的模態不對齊問題：重建階段使用同時包含相機與影像資訊的標記，而渲染階段僅使用相機輸入。為解決此問題，TTB 將每個上下文視角解耦為兩類標記——僅相機上下文渲染標記（模擬新視角渲染條件）與上下文真實標記（包含影像內容）。快速權重 MLP 被優化以將前者映射到後者，確保烘焙後的 MLP 在所有層級中對渲染標記的條件化保持一致。

**Q6：TTB 的關鍵設計選擇有哪些？**
A：TTB 採用收斂導向的內循環訓練機制（多步 MSE 損失），而非一次性總結，這與其在潛在空間中進行少步驟光場優化的詮釋一致。此外，TTB 的學習目標可泛化至任意非線性層的輸出標記，而不僅限於線性注意力的解釋。這些設計選擇使 TTB 能夠在維持渲染效率的同時，逼近預訓練模型的渲染品質。

**Q7：TTB 在哪些基準測試上進行了評估？**
A：根據摘要與內文，TTB 在多個基準測試上進行了評估，涵蓋不同的輸入條件與場景特性。這些基準測試用於驗證 TTB 在各種新視角合成任務中的泛化能力，包括不同視角密度與場景複雜度的設定。具體的基準測試名稱雖未在提供的內文中完整列出，但摘要明確指出其結果橫跨多個基準測試。

**Q8：TTB 的關鍵量化結果為何？**
A：TTB 達到了高達 23 倍的渲染加速，同時在多個基準測試上維持與最先進方法相當的渲染品質。這意味著 TTB 在品質與速度的帕累托前緣上取得了顯著進展，使高品質新視角渲染在實際應用中變得可行。具體的品質指標（如 PSNR、SSIM、LPIPS 等）雖未在提供的內文中詳列，但摘要強調其品質與最先進方法持平。

**Q9：TTB 進行了哪些消融研究？**
A：雖然提供的內文未詳列所有消融研究，但從方法描述可推斷，消融研究應包括：(1) 比較將學習目標設定為跨視角注意力輸出（TTB）與原始 value 標記（TTT）的差異；(2) 驗證模態不對齊解決方案（解耦上下文標記）的必要性；(3) 比較一次性總結與多步 MSE 收斂導向訓練的效果。這些消融研究共同支持了 TTB 各設計選擇的合理性。

**Q10：TTB 的實際應用場景有哪些？**
A：TTB 適用於需要即時高品質新視角渲染的場景，例如虛擬實境頭戴裝置中的場景瀏覽、擴增實境中的三維物件展示，以及三維內容創作工具中的預覽功能。在這些應用中，使用者通常會提供多張上下文影像，並期望從任意新視角快速獲得高品質渲染結果。TTB 的 23 倍渲染加速使這些互動式應用成為可能。

**Q11：TTB 在產品化考量上有哪些優勢？**
A：TTB 的核心產品化優勢在於其品質與速度的權衡設計：它以額外的上下文視角處理時間換取更快、更高品質的新視角渲染。這種設計特別適合「一次性預填充、多次渲染」的產品場景，例如預先載入場景後供使用者自由瀏覽。此外，TTB 烘焙出的 MLP 為常數大小，不會隨上下文視角數量線性增長，有利於記憶體管理與部署。

**Q12：TTB 對新視角合成領域的更廣泛影響是什麼？**
A：TTB 建立了 TTB 內循環與潛在空間光場優化之間的自然類比，將傳統的隱式輻射場與光場重建方法與現代 Transformer 架構連結起來。這種觀點啟發了基於收斂導向的訓練機制，並暗示 TTB 可被視為在潛在空間中進行的少步驟光場優化。此外，TTB 證明了快速權重 MLP 可作為烘焙跨視角注意力的有效媒介，為未來探索更高效的幾何自由表示鋪路。

**Q13：TTB 有哪些已承認的限制？**
A：TTB 的主要限制在於其需要額外的上下文視角處理時間來烘焙 MLP，這在僅需單次渲染的場景中可能不划算。此外，TTB 的效能可能依賴於預訓練模型的品質，若預訓練模型本身在新視角合成上表現不佳，TTB 也難以超越其上限。雖然提供的內文未詳列所有限制，但這些可從方法設計中合理推斷。

**Q14：TTB 在哪些情況下可能會失敗？**
A：TTB 可能會在以下情況下表現不佳：(1) 當上下文視角極度稀疏時，烘焙的 MLP 可能無法捕捉足夠的場景資訊；(2) 當場景包含大量未在上下文視角中出現的遮擋區域時，新視角渲染品質可能下降；(3) 當預訓練模型對特定場景類型（如極端光照條件或高度動態場景）泛化能力不足時，TTB 也會繼承這些弱點。

**Q15：TTB 未來的研究方向有哪些？**
A：未來研究方向可能包括：(1) 將 TTB 擴展至其他類型的層（如非線性層或更深層的注意力輸出），以烘焙更豐富的場景資訊；(2) 將 TTB 應用於生成式新視角合成設定，結合擴散模型等生成式架構；(3) 探索 TTB 在未校準相機或動態場景等更具挑戰性的輸入條件下的表現；(4) 進一步優化上下文預填充流程，以減少烘焙階段的時間成本，使 TTB 在更多場景中具有實用性。

## 實務應用指南

### 適用場景

1. **沉浸式 VR/AR 內容生成**：在頭戴裝置即時渲染新視角時，TTB 可將場景資訊烘焙為輕量 MLP，使裝置端在維持高幀率的同時輸出高品質畫面，特別適合 6DoF 影片、虛擬展間與社交虛擬實境。

2. **電子商務 360° 商品展示**：商家僅需拍攝數十張商品影像即可讓消費者自由旋轉、縮放檢視細節；TTB 的 23× 加速使雲端渲染成本顯著降低，並支援鏡面反射、半透明材質等 3DGS 難以處理的表面。

3. **不動產與飯店虛擬看房**：將多張室內照片烘焙為場景 MLP 後，潛在買客可在瀏覽器即時切換視角，無需預先昂貴的 3D 掃描或人工建模。

4. **影視與廣告預覽（Previs）**：導演與美術團隊可在拍攝前快速從稀疏參考圖生成可自由運鏡的場景預覽，加速鏡頭設計與燈光規劃。

5. **機器人與自駕車的視覺模擬**：將行車記錄器多視角影像烘焙後，用於閉環測試中即時合成未見過的相機視角，補強訓練資料覆蓋率。

### 實作前置條件

**資料需求**
- 每個場景至少數十張具已知內外參的影像（建議 32–128 張，覆蓋目標視角範圍）。
- 精確的相機姿態（COLMAP、ARKit、LiDAR SLAM 等產出皆可）。
- 影像解析度建議 ≥ 512×512，並具備足夠的視角重疊以利跨視角注意力學習。

**運算資源**
- 訓練/烘焙階段：單張 A100/H100 等級 GPU（≥ 80GB VRAM）即可處理單一場景；批次烘焙多場景建議多卡並行。
- 推論階段：烘焙後的 MLP 為常數大小，可在 RTX 4090、Apple M-series 或雲端 T4 等中階 GPU 上即時渲染。
- 預訓練的 decoder-only LVSM 權重（論文使用之模型尚未完全開源，需自行預訓練或洽詢作者）。

**技能門檻**
- 熟悉 PyTorch、Transformer 架構與 KV-cache 機制。
- 具備 3D 視覺基礎（相機模型、epipolar geometry、COLMAP 工作流程）。
- 理解 Test-Time Training 與 inner-loop optimization 概念（建議先讀 TTT 與 LaCT 原始論文）。
- 具備模型部署經驗（ONNX/TorchScript 導出、量化、推論服務化）。

---

### 實作步驟建議

1. **階段一：基礎建設（2–4 週）**
   - 建立資料管線：COLMAP 重建 → 相機參數正規化 → 影像分塊（patch tokenization）。
   - 取得或自行預訓練 decoder-only LVSM（建議從公開的 LVSM checkpoint 開始微調）。
   - 實作 KV-cache 版本的 cross-view attention 層，作為烘焙目標的來源。

2. **階段二：TTB 核心模組（3–5 週）**
   - 將 TTT 的 fast-weight MLP 模組化，使其可獨立替換學習目標。
   - 將學習目標由原始 value tokens 改為 cross-view attention 輸出 tokens。
   - 實作「上下文配對」機制：每個 context view 同時產生 camera-only rendering token 與 ground-truth token。
   - 採用多步 MSE（multi-step MSE）收斂導向的 inner-loop 訓練食譜。

3. **階段三：品質與速度驗證（2–3 週）**
   - 在 RealEstate10K、DL3DV、ScanNet 等基準上重現論文的 23× 加速與品質指標（PSNR/SSIM/LPIPS）。
   - 進行消融實驗：比較 TTB vs. TTT vs. 完整 cross-view attention 的品質/速度帕累托曲線。
   - 壓力測試：密集視角（>100 張）、極端視角變化、鏡面/半透明場景。

4. **階段四：產品化（4–6 週）**
   - 將烘焙後的 MLP 序列化為單一檔案（< 數 MB），設計版本管理與快取機制。
   - 整合至推論服務（FastAPI/Triton），提供 REST/gRPC API。
   - 開發前端 SDK（WebGL/Three.js 或原生 Unity/Unreal plugin）以消費烘焙產物。
   - 建立監控：渲染延遲、PSNR 漂移、GPU 利用率。

5. **階段五：迭代優化（持續）**
   - 收集線上失敗案例，累積為 fine-tuning 資料集。
   - 探索混合策略：對靜態區域用 TTB，對動態物件退回完整 attention。
   - 量化（INT8/FP8）以進一步降低推論成本。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解措施 |
|------|------|----------|
| **預訓練權重依賴** | TTB 品質高度依賴 decoder-only LVSM 的預訓練品質；自訓成本極高。 | 優先洽詢作者或使用社群開源 checkpoint；規劃自訓預算時預留 ≥ 4 週 GPU 機時。 |
| **烘焙時間過長** | 雖然渲染加速 23×，但每場景烘焙仍需數十秒至數分鐘。 | 採用多步 MSE 收斂導向訓練；對靜態場景預先批次烘焙並快取；研究蒸餾到更小 MLP。 |
| **模態不對齊未完全解決** | 若 context 與 novel-view 的相機分佈差異過大，烘焙 MLP 仍可能失效。 | 在訓練資料中加入視角分佈增廣；對極端視角退回完整 attention 作為 fallback。 |
| **動態場景失效** | TTB 假設場景靜態，動態物件會被「烘死」在 MLP 中。 | 採用時序分段烘焙；對動態區域標記並使用獨立 MLP 或退回 cross-view attention。 |
| **基準外泛化風險** | 論文基準多為室內/街景，工業場景、醫療影像等可能未涵蓋。 | 部署前在目標領域做小樣本驗證；準備領域微調流程。 |
| **KV-cache 記憶體成本** | 烘焙階段仍需完整 KV-cache，密集視角下記憶體可能爆炸。 | 採用分塊 attention、視角降採樣、或梯度檢查點技術。 |
| **評估指標偏誤** | PSNR/SSIM 對高頻細節不敏感，可能掩蓋紋理退化。 | 補充 LPIPS、感知使用者研究，並人工抽檢關鍵幀。 |

### 與其他技術的整合建議

1. **與 3DGS / NeRF 互補**：在鏡面反射、半透明材質場景優先使用 TTB；在標準漫反射場景保留 3DGS 以利編輯；可發展「混合表示」管線，根據材質自動選擇。

2. **與 Gaussian Splatting 編輯工具整合**：將 TTB 烘焙結果作為初始場景，再用 Gaussian 編輯工具（如 gaussian-editor）進行局部修改，兼顧速度與可編輯性。

3. **與 NeRF Studio / gsplat 生態系整合**：將 TTB 烘焙模組封裝為外掛，輸出標準格式（如 .ply + 相機參數），供下游工具鏈消費。

4. **與生成式模型串接**：將 TTB 烘焙的 MLP 作為條件注入 diffusion-based 視角合成模型（如 ReconFusion），用於填補稀疏視角或風格化。

5. **與雲端渲染管線整合**：在 AWS ThinkBox Deadline 或 Kubernetes 上批次烘焙，烘焙產物推送至 CDN 邊緣節點，使用者端僅做輕量 MLP 推論。

6. **與 SLAM / SfM 整合**：將 COLMAP 或 ARKit 輸出直接餵入 TTB，省去人工對齊；對機器人應用可形成「即時重建 → 即時烘焙 → 即時渲染」閉環。

**產品經理**：聚焦於「23× 渲染加速 + 維持 SOTA 品質」這個核心商業價值，以及它如何降低 VR/AR、電商、不動產等場景的單位渲染成本；理解烘焙時間（一次性成本）與渲染時間（每次成本）的權衡，有助於設計定價模型與 SLA；同時關注動態場景失效與基準外泛化風險，這些將直接影響產品承諾的邊界。
