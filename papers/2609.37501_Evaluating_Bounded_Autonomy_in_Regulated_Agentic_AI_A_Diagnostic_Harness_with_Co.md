## ⚡ TL;DR

受監管代理式 AI 難以可靠判斷何時應自行回答、何時須上報人類。
本文提出 RegLLM，結合六項可信度訊號、領域憲法獎勵與確定性執行期監督器。
煙霧測試顯示治理可提升上報召回率並降低不安全行動率，但小樣本實驗暴露配置變異極大。

## 摘要翻譯

我們提出 RegLLM，一個針對受監管代理式工作流程（regulated agentic workflows）中有限自主權（bounded autonomy）的診斷框架（diagnostic harness）。它建置了六項可信度訊號（trustworthiness signals）：引用有效性（citation validity）、來源扎根（source grounding）、模式合規性（schema compliance）、上報正確性（escalation correctness）、憲法對齊度（constitutional alignment），以及不安全行動率（unsafe-action rate）。這些訊號依其監督來源區分：程式化驗證器（programmatic verifiers）、任務層級上報標籤（task-level escalation labels），或 AI 評審分數（AI-judge scores）。確定性執行期監督器（deterministic runtime supervisor）會阻擋無依據答案（ungrounded answers）並強制上報，同時記錄介入行為。同一份領域憲法（domain constitution）即為評估、訓練獎勵與服務階段護欄（guardrails）的共同依據。任務層級應上報標籤（should-escalate labels）使行動 vs. 迴避決策（act-versus-defer decision）成為可量測的訓練訊號。我們在煙霧測試規模（smoke scale）下展示此框架。一項離線基準執行（offline reference run，n=12）在啟用治理機制後，將上報召回率（escalation recall）從 0 提升至 0.67，並將不安全行動率從 0.33 降至 0.08。兩項在單一 GPU 上進行的 Qwen2.5-3B 低秩適應（LoRA）／直接偏好最佳化（DPO）先導實驗（n=8，相同種子與評估分割）顯示出顯著變異：名義上相同的強化學習基礎配置（RL-base configurations）分別產生 0.25 與 0.12 的任務成功率（task success），以及 1.0 與 0.5 的上報召回率。答案品質適配器（answer-quality adapter）於 Run A 使召回率由 1.0 降至 0.5，於 Run B 則由 0.5 升至 1.0。上報感知變體（escalation-aware variant）在 Run B 中未產生可量測的變化。這些小型先導實驗無法確立可靠的適配器效應或生產就緒性。其貢獻具有診斷性質：配置變異（configuration variance）可能壓過在有限自主權指標上看似明顯的調優效應，凸顯擴大評估集（eval sets）並進行多種子執行（multi-seed runs）的必要性。

### 核心貢獻（3～5點）
- 提出 RegLLM，一個用於評估受監管代理式工作流程（regulated agentic workflows）中有限自主權（bounded autonomy）的診斷框架（diagnostic harness），並建置六項可信度訊號（trustworthiness signals），區分其監督來源為程式化驗證器（programmatic verifiers）、任務層級上報標籤（task-level escalation labels）與 AI 評審分數（AI-judge scores）。
- 以同一份領域憲法（domain constitution）統一評估、憲法獎勵（Constitutional Rewards）與服務階段護欄（guardrails），並透過確定性執行期監督器（deterministic runtime supervisor）阻擋無依據答案（ungrounded answers）、強制上報並記錄介入行為。
- 將任務層級應上報標籤（should-escalate labels）轉化為可量測的訓練訊號，使行動 vs. 迴避決策（act-versus-defer decision）得以在模型訓練中被明確優化。
- 在煙霧測試規模（smoke scale）下驗證治理機制的效用：離線基準執行（offline reference run）顯示，啟用治理後上報召回率（escalation recall）由 0 提升至 0.67，不安全行動率（unsafe-action rate）由 0.33 降至 0.08。
- 透過小型 Qwen2.5-3B LoRA/DPO 先導實驗指出，配置變異（configuration variance）可能壓過調優效應，強調在有限自主權指標上需要更大的評估集（eval sets）與多種子執行（multi-seed runs）方能得出可靠結論。

### 適合對象
從事代理式安全（agentic-safety）、受監管代理式 AI（regulated agentic AI）治理、LLM 護欄（guardrails）與可稽核性（auditability）研究的學者與工程師；特別是關注金融合規（financial compliance）、法律或醫療等高風險領域中，如何設計執行期監督器（runtime supervisor）與上報機制的 MLOps 實務者與政策制定者。

## 深度分析

#### 方法論解析

##### 核心問題與設計哲學
RegLLM 針對的是「受監管代理式 AI（regulated agentic AI）」中的 central decision：當面對一個高風險任務時，agent 應該自行回答（act）還是將問題上報給合格人員（defer）。在傳統系統中，這個「行動 vs. 迴避決策（act-versus-defer decision）」通常依賴手調閾值（hand-coded thresholds），既難以學習也難以稽核。RegLLM 的方法論 pivot 在於：如果每個任務都帶有「應上報標籤（should-escalate labels）」，那麼上報與否就變成了一個可驗證的訓練訊號，從而讓「有限自主權（bounded autonomy）」成為可測量、可訓練、可稽核的行為，而不是單純的啟發式規則。

##### 任務標籤與可信度訊號（trustworthiness signals）
框架 instrument 六項可信度訊號：
1. **引用有效性（citation validity）**：agent 引用的法規條文是否真實存在且相關。
2. **來源扎根（source grounding）**：答案是否有可靠來源支撐。
3. **模式合規性（schema compliance）**：輸出是否符合預定義結構。
4. **上報正確性（escalation correctness）**：agent 的終端決策是否與任務的 should-escalate 標籤一致。
5. **憲法對齊度（constitutional alignment）**：輸出與領域憲法（domain constitution）原則的一致性，由 AI 評審（AI-judge）打分。
6. **不安全行動率（unsafe-action rate）**：產生無依據答案（ungrounded answers）或應上報卻未上報等不當行為的比例。

這些訊號依監督來源分為三類：
- **程式化驗證器（programmatic verifiers）**：引用有效性、來源扎根、模式合規性、上報正確性。
- **任務層級上報標籤（task-level escalation labels）**：上報正確性的 ground truth。
- **AI 評審分數（AI-judge scores）**：憲法對齊度作為軟獎勵項（soft reward term）。

##### 混合獎勵函數（hybrid reward）
獎勵由兩部分組成：
- **可驗證的硬訊號**：引用、schema、上報標籤等可程式化檢查的項目。
- **軟獎勵項**：以領域憲法為原則，由 AI-judge 對答案品質與合規性進行評分。

這樣的設計讓「正確上報」與「正確引用條文」以相同方式貢獻到軌跡分數，從而將 bounded autonomy 納入 RL 目標。

##### 領域憲法（domain constitution）的雙重角色
論文以英國金融行為監管局（FCA）手冊中的 16 項金融服務原則作為 worked example。同一份憲法同時扮演：
- **訓練角色**：作為軟獎勵項的評分依據。
- **執行期護欄（runtime guardrails）**：定義能力邊界、不確定性與專家轉介原則，驅動確定性監督器。

這種「one constitution, two roles」的設計讓評估、訓練與服務階段使用同一份治理 artefact，降低訓練與部署之間的規則漂移。

##### 確定性執行期監督器（deterministic runtime supervisor）
監督器在 inference 階段運作：
- 攔截無依據答案（ungrounded answers）。
- 對觸發 out-of-scope 條件的查詢強制上報（force escalation）。
- 將每次介入寫入「僅可追加（append-only）」的介入日誌（intervention logs），並以觸發原則作為 key。

這層監督器是安全網：即使訓練後的 policy 仍有殘留失敗，執行期護欄也能阻止其進入生產輸出，並提供可稽核性（auditability）。

##### 訓練流程：DPO + LoRA
論文使用 Qwen2.5-3B 模型，以 LoRA（低秩適應）進行參數高效微調，並以 DPO（直接偏好最佳化）對偏好軌跡進行對齊。實驗比較了：
- **RL-base configuration**：基礎偏好學習設定。
- **answer-quality adapter**：針對答案品質的 LoRA 適配器。
- **escalation-aware variant**：在訓練中額外納入上報訊號的變體。

底層 agent 抽象採用 ReAct loop，讓模型在推理與行動之間交替。

##### 整體資料流
1. 輸入任務帶有 should-escalate 標籤。
2. Agent 在 ReAct loop 中產生答案或決定上報。
3. 程式化驗證器與 AI-judge 同時計算六項可信度訊號。
4. 混合獎勵用於 DPO 訓練。
5. 執行期監督器在部署時攔截殘留風險並記錄介入。

#### 實驗數據解讀

##### 離線基準執行（offline reference run，n=12）
在未啟用治理（governance disabled）的弱基線上：
- **上報召回率（escalation recall）= 0**：所有應上報任務都未被正確上報。
- **不安全行動率（unsafe-action rate）= 0.33**：約三分之一的行動屬於不安全。

啟用確定性執行期監督器後：
- escalation recall 提升至 **0.67**。
- unsafe-action rate 下降至 **0.08**。

這說明單靠執行期護欄就能顯著改善 bounded-autonomy 行為，但仍有殘留風險（recall 未達 1.0、unsafe-action rate 不為 0），凸顯訓練階段也需要學習上報決策。

##### 兩組單 GPU pilot（n=8，same seed & eval split）
論文進行了兩次「名義上相同」的 Qwen2.5-3B LoRA/DPO 實驗，結果呈現高度變異：

| 指標 | Run A | Run B |
|---|---|---|
| task success | 0.25 | 0.12 |
| escalation recall | 1.0 | 0.5 |

即使在相同 seed 與相同 eval split 下，基礎配置的表現仍相差一倍，這本身就是論文強調的主要發現。

##### Adapter 效應的方向翻轉
- **answer-quality adapter**：
  - Run A：escalation recall 從 1.0 降至 0.5。
  - Run B：escalation recall 從 0.5 升至 1.0。
- **escalation-aware variant**：
  - 在 Run B 中未觀察到可測量的變化。

這表示在小樣本下，adapter 的「效果」無法與採樣變異（sampling variance）和硬體變異（hardware variance）區分開來。

##### 變異性分析
論文將這種變異視為核心貢獻，而非失敗。它指出：在 agentic-AI pilot 常見的樣本量與訓練預算下，bounded-autonomy 指標對配置變化極度敏感。這意味著：
- 單一 run 的結果可能無法複製。
- Adapter 的「改善」可能是隨機波動。
- 需要多種子執行（multi-seed runs）與更大的評估集（eval sets）才能得出可靠結論。

##### 指標間的權衡
answer-quality adapter 在 Run A 中提升了答案品質，卻犧牲了 escalation recall（1.0 → 0.5）。這暗示答案品質與上報保守度之間存在張力：模型可能為了給出「更好」的答案而傾向自行回答，反而降低 bounded autonomy。這是監管場景中特別危險的 trade-off。

##### 限制與詮釋
作者明確表示這些 pilot 處於「煙霧測試規模（smoke scale）」，不具生產就緒性（production readiness）。數據的價值在於診斷：它讓「小樣本導致結論不可靠」這個常見警吿變得具體可見。

#### 與現有研究的比較

##### 相較於可驗證獎勵強化學習（RL with verifiable rewards）
DeepSeek-R1 等推理模型依賴數學與程式碼的「可機器檢驗答案（machine-checkable answers）」。RegLLM 承認監管建議（regulatory advice）無法被機器完全驗證——不同專家對同一事實模式（fact pattern）可能意見分歧。因此它採用混合策略：將可程式化檢查的部分（引用、schema、上報標籤）分離出來，對剩餘的判斷性部分使用 AI-judge。這不是發明新的監管正確性驗證器，而是系統性地劃分「可驗證」與「需判斷」的邊界。

##### 相較於 RLHF / DPO / Constitutional AI
傳統 RLHF 與 DPO 依賴人類偏好標籤；Constitutional AI 則用憲法生成批判與修訂資料，再餵給下游對齊流程。RegLLM 的差異在於：
- 憲法不僅是資料生成裝置，而是同時出現在 **RL 獎勵** 與 **執行期護欄** 中。
- 偏好訊號中包含可驗證的任務層級標籤，而非僅有相對偏好。

這讓治理 artefact 從「訓練後的裝飾」變成「訓練與部署的共同基礎」。

##### 相較於代理式安全護欄（agentic-safety guardrails）
現有 guardrail 系統（如 Xiang et al., Luo et al., Wu et al.）擅長阻擋有害輸出，但缺乏「何時應該詢問人類」的學習機制。RegLLM 提供：
- 可驗證的上報正確性作為學習目標。
- 訓練後仍保留確定性監督器作為最後防線。

這將「被動阻擋」提升為「主動學習何時 defer」。

##### 相較於金融 NLP / RegTech
FinBERT、BloombergGPT、FinGPT 等專注於金融文本理解；RegTech 文獻聚焦市場與文件流程。RegLLM 的目標不是文件分類或市場預測，而是「在監管約束下的自主行動治理（governed autonomous action）」。這是從「理解監管文本」到「依據監管原則行動並可稽核」的躍遷。

##### 主要貢獻與限制
主要貢獻：
- 將 bounded autonomy 轉化為可驗證的 RL 訊號。
- 以單一領域憲法統一評估、訓練與服務。
- 透過小規模實驗凸顯配置變異對指標的影響。

主要限制：
- 樣本量極小（n=12 與 n=8），統計檢定力不足。
- 標籤由作者從模板生成，非專家標註。
- 僅使用單一領域（金融合規）與單一小型模型（Qwen2.5-3B）。
- 未與更大模型或 reasoning models 進行系統比較。

#### 未來研究方向

##### 1. 擴大評估規模與多種子實驗
論文已明確指出：需要更大的評估集（eval sets）與多種子執行（multi-seed runs）才能區分 adapter 效應與隨機變異。未來應建立標準化的 bounded-autonomy benchmark，涵蓋數百至數千個任務。

##### 2. 跨領域驗證
目前僅以英國 FCA 金融合規為例。未來可擴展至：
- 醫療建議（healthcare advice）中的「何時轉介醫師」。
- 法律初步篩選（legal triage）中的「何時交由律師」。
- 稅務、保險、資料隱私等其他高風險監管領域。

##### 3. 專家標註與標籤品質
作者生成的模板標籤可能過於簡化。未來應引入領域專家標註，並研究專家間歧義（inter-annotator disagreement）對 should-escalate labels 與獎勵函數的影響。

##### 4. 更強大的程式化驗證器
可整合外部權威資料源（如法規 API、判例資料庫、公司內部政策庫）來自動檢查引用有效性與來源扎根，降低對 AI-judge 的依賴。

##### 5. AI-judge 的校準與偏誤
憲法對齊度（constitutional alignment）由 AI-judge 評分，其一致性與偏誤需要系統性評估。未來可引入：
- 多 judge 集成。
- 人類 judge 作為參考標準。
- 對 judge prompt 的敏感性分析。

##### 6. 與推理模型（reasoning models）結合
可將 RegLLM 的獎勵與監督機制應用於 DeepSeek-R1 等 reasoning models，觀察其在監管場景中是否能產生更可解釋的 act-vs-defer 推理鏈。

##### 7. 線上學習與人類回饋迴路
在生產環境中，可將執行期監督器的介入日誌回饋至訓練流程，形成「部署 → 介入 → 再訓練」的閉環，持續改善 bounded autonomy。

##### 8. 獎勵駭客（reward hacking）防範
當上報正確性成為可優化目標時，模型可能學會過度上報或形式化地滿足指標。未來需設計更細緻的獎勵 shaping 與對抗性評估。

##### 9. 自適應執行期護欄
目前的監督器是確定性規則。未來可研究結合模型不確定性估計（uncertainty estimation）與風險校準（risk calibration）的自適應護欄，在保守與效能之間動態調整。

##### 10. 跨組織的憲法共享與標準化
若同一領域憲法可跨機構使用，將有助於建立產業級的監管合規基準。未來可探索憲法版本控制、原則衝突解決機制，以及與監管機構共同制定標準的可能性。

## 論文問答

**Q1：RegLLM 主要想解決什麼問題？為什麼這個問題在受監管領域特別重要？**

A：RegLLM 針對的是受監管代理式 AI（regulated agentic AI）中的「有限自主權」評估問題，也就是代理人在高風險場景（如金融合規、醫療建議、法律分流）中，應該自行回答還是將問題上報給人類的判斷。在這些領域裡，一個錯誤答案可能導致監管罰款、客戶受損或義務被忽略，因此「何時行動、何時迴避」的決策比單純答案正確性更關鍵。現有系統往往把這個決策交給手寫門檻，缺乏可測量、可訓練且可稽核的機制，RegLLM 正是要把這個決策變成可驗證的訓練訊號。

**Q2：為什麼現有的可驗證獎勵強化學習與偏好對齊方法，難以直接套用到受監管代理式 AI？**

A：可驗證獎勵強化學習在數學與程式領域有效，是因為答案可以被機器自動檢驗，但監管建議往往涉及專家判斷，不同專家對同一事實樣態可能看法不同，無法直接用程式判定對錯。RLHF 與 DPO 雖然能對齊人類偏好，但它們依賴偏好標籤，並未直接處理「應否上報」這種具有明確對錯標籤的決策。此外，現有的護欄系統雖能阻擋有害輸出，卻沒有提供原則性的方法來學習「何時應該請教人類」，因此無法滿足受監管工作流程的需求。

**Q3：為什麼把「行動 vs. 迴避」決策變成可測量訊號，對有限自主權如此重要？**

A：在受監管場景中，代理人若在不確定時仍貿然回答，可能產生無依據答案或不安全行動；反之，過度上報又會降低效率，因此「act-versus-defer」是核心決策。透過任務層級的應上報標籤（should-escalate labels），這個決策可以像引用有效性或模式合規性一樣被程式化驗證，從 brittle 的手寫門檻轉為可學習的強化學習目標。這讓有限自主權行為變得可測量、可訓練且可稽核，並能與執行期護欄共同運作。

**Q4：RegLLM 的核心方法架構包含哪些元件？它們如何協同運作？**

A：RegLLM 包含六個可信度訊號（引用有效性、來源扎根、模式合規性、上報正確性、憲法對齊度、不安全行動率），並依監督來源區分為程式化驗證器、任務層級上報標籤與 AI 評審分數。這些訊號組成混合獎勵函數，同時由一個確定性執行期監督器（deterministic runtime supervisor）在推論階段阻擋無依據答案並強制上報。同一套領域憲法（domain constitution）同時驅動軟獎勵項與執行期護欄，使評估、訓練與服務共用同一治理文件。

**Q5：RegLLM 相較於既有方法，最關鍵的創新是什麼？**

A：最關鍵的創新是把「上報正確性」視為可驗證的學習訊號，讓 bounded autonomy 不再只是工程上的安全閥，而是可以透過 DPO 等偏好學習方法直接訓練的目標。其次，同一領域憲法同時出現在獎勵函數與執行期護欄中，確保訓練與服務階段的治理原則一致。最後，確定性執行期監督器會攔截訓練未能覆蓋的殘餘失敗，並寫入不可竄改的介入日誌，強化可稽核性。

**Q6：為什麼 RegLLM 要同時使用程式化驗證器、AI 評審與任務標籤，而不是單一監督來源？**

A：因為受監管任務中不同面向的可信度性質不同：引用是否存在、輸出是否符合模式、是否正確上報，都可以透過規則或標籤明確判定；但答案是否符合領域憲法、語意是否穩健，則需要 AI 評審這類軟訊號。混合使用這三種監督來源，可以在可驗證的部分保持客觀，在需要判斷的部分保留彈性。這種分層設計也讓執行期監督器能針對最關鍵的硬規則（如無依據回答與強制上報觸發條件）進行確定性介入。

**Q7：論文進行了哪些實驗來驗證這個診斷框架？**

A：作者先進行了一個離線基準執行（offline reference run），樣本數為 12，用來觀察啟用治理前後的指標變化。接著進行了兩個單 GPU 的 Qwen2.5-3B LoRA／DPO 試驗，每個試驗評估集為 8 筆，使用相同種子與相同切分，以控制變因。這些實驗屬於煙霧測試規模（smoke scale），目的不是建立生產就緒的模型，而是診斷小樣本偏好調優流程中的變異問題。

**Q8：實驗中最主要的量化結果是什麼？**

A：在離線基準執行中，啟用確定性執行期監督器後，上報召回率（escalation recall）從 0 提升到 0.67，不安全行動率（unsafe-action rate）則從 0.33 下降到 0.08。然而，在兩個單 GPU DPO 試驗中，即使 RL 基礎配置名義上相同，任務成功率卻分別為 0.25 與 0.12，上報召回率也分別為 1.0 與 0.5，顯示出顯著的配置變異。這些結果凸顯了小樣本試驗下，適配器效果可能被採樣與硬體變異淹沒。

**Q9：答案品質適配器與上報感知變體的實驗，帶來什麼診斷性發現？**

A：答案品質適配器對上報召回率的影響在兩次執行中方向相反：Run A 中召回率從 1.0 降至 0.5，Run B 中卻從 0.5 升至 1.0，顯示同一調整並沒有穩定效果。原本為了解決 Run A 問題而設計的上報感知變體，在 Run B 中卻未觀察到可測量的變化。這些發現說明，在樣本數極小的代理式 AI 試驗中，配置變異可能壓過看似明顯的調優效應，因此不能僅憑單次執行就推斷適配器的好壞。

**Q10：RegLLM 可以應用在哪些實際場景？論文以什麼領域作為範例？**

A：RegLLM 適用於任何錯誤代價高昂、需要明確能力邊界的受監管代理式工作流程，例如金融合規、醫療建議與法律分流。論文以金融服務為例，採用來自英國金融行為監管局手冊（FCA Handbook）的 16 項原則作為領域憲法，要求代理人引用真實條文、識別超出範圍的查詢並在必要時上報。在這些場景中，代理人不僅要回答正確，還必須證明其回答有來源依據且符合監管原則。

**Q11：若要把 RegLLM 落地為產品，有哪些工程與治理上的考量？**

A：產品化時必須部署確定性執行期監督器作為服務階段的最後一道防線，並確保所有介入行為都寫入可稽核的日誌。同時，領域憲法需要隨法規更新而維護，並由領域專家審核任務層級的應上報標籤，而非僅依賴模板生成。此外，由於小樣本試驗無法保證穩定性，產品團隊必須進行多種子執行與更大規模評估集，才能判斷模型是否真正具備生產就緒的有限自主權。

**Q12：這項研究對 AI 安全與受監管代理式系統的發展可能帶來什麼影響？**

A：RegLLM 把「可驗證獎勵」的概念從數學與程式領域延伸到監管建議這類知識密集型任務，填補了現有強化學習與護欄研究之間的缺口。它也提醒研究者與工程師：在受監管場景中，偏好調優流程必須納入上報正確性等硬訊號，而不能只靠模型自動判斷。最終，這個框架讓「負責任地評估受監管代理人」從口號變成可操作的測量與治理流程。

**Q13：論文承認了哪些主要限制？**

A：作者明確指出所有實驗都屬於煙霧測試規模，樣本數僅 8 到 12 筆，遠不足以建立統計上可靠的結論或生產就緒的模型。由於樣本太小，無法區分適配器效果與採樣、硬體變異，因此不能宣稱某個 LoRA 或 DPO 變體確實更好。此外，任務層級的應上報標籤在試驗中由模板生成，在真實部署中需要領域專家進行標註與審查。

**Q14：在實際運作中，RegLLM 可能出現哪些失敗或風險案例？**

A：如果執行期監督器的規則覆蓋不足，代理人仍可能在未引用真實條文的情況下產生無依據答案，或在面對超出能力範圍的查詢時未能正確上報。AI 評審分數本身也可能因模型偏誤而對語意穩健的判斷出現不一致，進而影響軟獎勵項。更重要的是，小樣本評估可能讓開發者誤以為某個調整有效，實際上只是隨機變異，從而在生產環境中部署不穩定的策略。

**Q15：未來研究可以朝哪些方向延伸 RegLLM？**

A：未來可以擴大評估集規模並進行多種子執行，以量化配置變異並建立更可信的適配器比較。也可以引入領域專家標註的應上報標籤，並開發更強大的程式化驗證器來檢查引用真實性與法規適用範圍。此外，將憲法獎勵與新興推理模型（如 DeepSeek-R1 類架構）結合，或把框架擴展到醫療、法律等其他高風險領域，都是值得探索的方向。

## 實務應用指南

### 適用場景

1. **金融合規第一線問答**：銀行或證券商的內部合規助手，面對「這筆交易是否觸及市場濫用條款？」等問題時，必須在能回答時給出扎根於監管條文的答案，在邊界外或事實不足時正確上報給法遵人員。
2. **醫療分診與用藥建議**：協助基層診所或藥師處理「這位患者是否適用某種藥物？」等查詢，系統應對超出執業範圍、需要專科醫師判斷的個案主動迴避並轉介。
3. **法律初步篩選與客戶盡職調查**：律師事務所或企業法務部門用於初步判斷合約風險、客戶背景或訴訟時效，對於需要執業律師簽核的事項強制上報。
4. **保險理賠初步判定**：處理理賠申請時，對於條款明確、文件齊全的案件給出扎根條款的初步意見；對於涉及詐欺疑慮、醫療鑑定或法律爭議的案件強制轉人工。
5. **政府福利資格審查**：協助民眾查詢社會福利或補助資格，對於涉及個案審酌、行政裁量或需要社工具訪視的情形，引導至正式申請管道而非直接給出確定性結論。

### 實作前置條件

**資料準備**
- 一份可機讀的**領域憲法**：例如 16 條金融服務原則，需明確定義能力邊界、不確定性處理與專家轉介規則。
- 帶有 **should-escalate 標籤**的任務資料集：每個任務都要標註「應由代理回答」或「應上報人類」，並附上正確引用來源與預期輸出模式。
- 經過驗證的來源文件庫：用於檢查**引用有效性**與**來源扎根**。
- 輸出模式定義（schema）：規範答案格式，例如必須包含引用條文、信心區間、決策標籤等欄位。

**運算資源**
- 實驗階段：單張 GPU 即可進行 Qwen2.5-3B 的 LoRA/DPO 試驗，但論文強調樣本數極小時結果波動極大。
- 生產階段：需要能支撐多種子執行、較大評估集與線上監督器的運算環境，並保留完整的**介入日誌**。

**技能組合**
- 機器學習工程能力：能實作 LoRA/DPO 訓練、混合獎勵函數與評估流程。
- 領域專家：能撰寫憲法、產生 should-escalate 標籤，並審查 AI 評審的判斷。
- 護欄與可稽核工程：能建構確定性**執行期監督器**、審計日誌與人工複查介面。

### 實作步驟建議

1. **定義領域憲法與能力邊界**：先與法遵、醫事或法律專家共同撰寫憲法，明確哪些情境代理可以回答、哪些必須上報。
2. **建立帶標籤的任務資料集**：從真實案例或模板產生任務，並由領域專家標註 should-escalate 標籤、正確引用與預期輸出。
3. **建構程式化驗證器**：實作引用有效性、來源扎根、模式合規與上報正確性的自動檢查。
4. **設計混合獎勵函數**：將程式化驗證器的硬獎勵與憲法對齊的軟獎勵項結合，後者可由 AI 評審打分。
5. **進行小規模 DPO/LoRA 試驗**：在單張 GPU 上訓練基礎適配器與上報感知變體，但要把結果視為診斷而非定論。
6. **部署確定性執行期監督器**：在服務階段攔截無依據答案、強制邊界外問題上報，並寫入不可竄改的介入日誌。
7. **執行多種子、多配置的評估**：論文顯示相同配置在不同執行下結果差異極大，必須擴大評估集並重複執行。
8. **建立人工複查與持續迭代機制**：將監督器觸發的案例、AI 評審低分案例定期回饋給訓練資料與憲法更新。

### 潛在風險與注意事項

- **小樣本導致的採樣變異**：論文以 n=8 的試驗顯示，相同配置可能出現 0.25 對 0.12 的任務成功率差異。不要以單次小樣本結果推論適配器效果。
- **硬體與環境變異**：即使使用相同種子與評估切分，不同硬體或軟體堆疊仍可能產生不同結果，生產評估應固定環境並記錄版本。
- **AI 評審分數的不穩定性**：憲法對齊分數屬於軟獎勵，可能隨模型版本或提示詞變化而漂移，需定期以領域專家標註校正。
- **過度依賴執行期監督器**：監督器能攔截無依據答案，但不能取代訓練；若代理過度依賴被攔截後才上報，會影響使用者體驗與延遲。
- **領域憲法與法規變動**：監管條文更新時，憲法、驗證器與訓練資料必須同步更新，否則可能產生過時或錯誤的扎根答案。
- **標籤品質**：should-escalate 標籤是核心訓練訊號，標註錯誤會直接導致代理學會錯誤的行動／迴避策略。

### 與其他技術的整合建議

- **RAG 與知識庫**：將來源扎根檢查與向量檢索系統結合，確保代理引用的條文確實來自授權文件庫，而非模型幻覺。
- **現有案件管理系統**：將強制上報的案件自動開立工單或案件編號，並把介入日誌與代理輸出一併寫入，方便人工複查。
- **模型監控與可觀測性平台**：持續追蹤六項可信度訊號的分布變化，特別是**不安全行動率**與**上報召回率**，作為早期預警。
- **LLM 閘道器與身分認證**：在閘道層統一執行模式合規與存取控制，並依使用者角色決定是否允許特定查詢或強制上報。
- **人機協作介面**：設計清楚的「代理建議 + 人工確認」流程，讓領域專家能快速覆寫、補充或結案，並將結果回饋至訓練資料。

### 給不同背景讀者的閱讀建議

**給初學者**：這篇論文的核心概念是「讓 AI 學會在該說不知道時上報」。你可以把它想像成一位有執業範圍的實習生：能處理的事要給出依據，不能處理的事要轉交給資深同事。閱讀時請先聚焦於「有限自主權」與「應上報標籤」這兩個概念，技術細節如 LoRA/DPO 可以暫時略過。

**給 AI 工程師**：本文的實作重點在於混合獎勵設計與確定性執行期監督器的搭配。請特別留意論文揭露的變異問題：小樣本 DPO 試驗中，相同配置與相同種子仍可能出現顯著差異，這意味著你不能只跑單次實驗就下結論。建議把多種子執行與較大評估集納入你的開發流程。

**給研究者**：本文的方法論貢獻在於將「行動 vs. 迴避」決策轉化為可驗證的訓練訊號，並讓同一份領域憲法同時驅動評估、訓練與服務護欄。未來研究可探討如何降低小樣本偏好調優的變異、如何提升 AI 評審在監管領域的穩定性，以及如何將此框架擴展到多領域或多代理系統。

**給產品經理**：這篇論文提供了一個可落地的治理框架，而非一個現成產品。它的價值在於讓「AI 何時可以回答、何時必須上報」變得可衡量、可訓練、可稽核。規劃產品時，請預留領域專家參與憲法撰寫與標籤審查的時間，並把執行期監督器與人工複查流程視為上線必要條件，而非後續優化項目。
