AltRA-Test 的核心目標是解決一個在大型語言模型 (Large Language Model, LLM) 取代人類標註者 (annotator) 時所面臨的統計檢定問題：當我們無法確保所有項目都由同一批標註者標註時，如何判斷 LLM 是否能作為「合格的替代標註者」(alternative annotator)？這個問題在現實應用中極為常見，例如群眾外包 (crowdsourcing)、偏好標註 (preference annotation)，以及需要高度專業知識的任務（如長文檔事實查核）。

**方法核心：配對百分位自助法 (Paired Percentile Bootstrap)**

AltRA-Test 採用配對百分位自助法 (paired percentile bootstrap) 作為其統計推論基礎。其運作流程可分為四個階段：

1. **抽樣與替換 (Sample & Swap)**：對於 B 次自助法迭代 (bootstrap iteration) 中的每一次，從資料集中以放回抽樣 (sampling with replacement) 方式抽取 N 個項目。對每個項目，抽取 k 個人類標註結果，並將其中一個標註替換為 LLM 的標註，從而產生兩種配對小組：全人類標註小組 (human-only panel) 與人類-LLM 混合小組 (human-LLM panel)。

2. **一致性計算與差距評估 (Agreement & Gap)**：計算兩種小組的標註者間一致性 (Inter-Annotator Agreement, IAA)，並計算替換差距 (substitution gap) Δ̂⁽ᵇ⁾ = R⁽ᵇ⁾ₘ − R⁽ᵇ⁾ₕ，其中 Rₘ 為混合小組的 IAA，Rₕ 為全人類小組的 IAA。同時引入自適應邊界 (adaptive margin) ε⁽ᵇ⁾ = c(1 − R⁽ᵇ⁾ₕ)，允許 IAA 出現與人類內部歧異程度成比例的小幅下降。

3. **近最差差距 (Near-Worst Gap)**：將 B 次迭代的自適應差距排序，取 α 分位數 (α-quantile) 作為決策統計量 (decision statistic) q*α。

4. **決策 (Decision)**：若 q*α > 0，則拒絕虛無假設 H₀: Δ + ε ≤ 0，判定 LLM 通過檢定，可作為人類標註者的替代。

**自適應邊界的設計意義**

自適應邊界 ε⁽ᵇ⁾ = c(1 − R⁽ᵇ⁾ₕ) 是此方法的一個關鍵設計巧思。在客觀任務中，人類標註者高度一致 (Rₕ 接近 1)，邊界 ε 很小，要求 LLM 必須幾乎完美地保留一致性訊號；在主觀任務中，人類標註者本身就有固有歧異 (Rₕ 較低)，邊界 ε 較大，允許 LLM 出現相應程度的偏差。預設校準值 c = 0.1 允許最多 10% 的歧異增加，這個設計使同一檢定能同時適用於客觀與主觀任務。

**理論性質**

作者證明了 AltRA-Test 是一個漸進水準 α 的一致性檢定 (consistent test of asymptotic level α)。這意味著：
- 當項目數 N 趨於無窮大時，合格的 LLM 通過檢定的機率趨近於 1；
- 不合格的 LLM 通過檢定的機率上限為 α。

這個理論保證為方法的可靠性提供了堅實的數學基礎，使其不僅是經驗性的啟發式方法，而是具有嚴謹統計性質的正規檢定程序。

**與 Alt-Test 的關鍵差異**

Alt-Test (Calderon et al., 2025b) 要求所有項目都由同一批標註者標註，這在密集設定 (dense setting) 下可行，但在稀疏設定 (sparse setting) 下不適用。AltRA-Test 的核心創新在於「重抽樣標註」(resampled annotations)——它在每個項目內部重抽樣標註，因此從不需要使用標註者的身份資訊。這使得該方法能應用於 11/20 的現有資料集，而這些資料集無法滿足 Alt-Test 的要求。

#### 與現有研究的比較

**與 Alt-Test (Calderon et al., 2025b) 的比較**

Alt-Test 是 AltRA-Test 的直接前身，兩者共享「非劣效性檢定」(non-inferiority test) 的核心框架。AltRA-Test 的關鍵改進在於：
- **放寬假設**：Alt-Test 要求所有項目由同一批標註者標註；AltRA-Test 僅要求每個項目有多個標註，不要求標註者身份一致。
- **適用範圍擴大**：在作者的 20 個資料集中，11 個無法滿足 Alt-Test 的要求，但都能使用 AltRA-Test。
- **保留理論性質**：儘管放寬了假設，AltRA-Test 仍保持了一致性與漸進水準 α 的理論保證。

**與 Statistical Turing Test (STT; He et al., 2025a) 的比較**

STT 同樣要求密集設定 (dense setting)，且其檢定邏輯與 Alt-Test 類似。AltRA-Test 在稀疏設定下的適用性是其相對優勢。

**與基於準確率/F1 的傳統評估比較**

傳統方法（如 Ziems et al., 2024; Bavaresco et al., 2025; Elangovan et al., 2025; Guerdan et al., 2025）使用 LLM 標註與多數決標籤 (majority-vote label) 之間的準確率、F1 或相關性作為評估指標。AltRA-Test 的批評指出：這些指標無法提供統計上可靠的替換決策，因為人類標註者本身也會與多數決標籤不一致，其上限取決於任務而未知。AltRA-Test 採用 IAA 作為比較基準，更貼近人類標註品質的評估方式 (Hayes & Krippendorff, 2007; Klie et al., 2024)。

**與 LLM-as-a-judge 文獻的關係**

AltRA-Test 為 LLM-as-a-judge (Zheng et al., 2023; Wei et al., 2024; Li et al., 2025) 的可靠性提供了統計檢驗工具。許多研究已指出 LLM 在主觀任務上與人類系統性分歧 (Lissak et al., 2024; Elangovan et al., 2025; Zhang et al., 2025)，AltRA-Test 提供了一個量化、可決策的框架來處理這些問題。

**限制與未解決問題**

1. **IAA 指標的選擇**：AltRA-Test 的結論取決於所選用的 IAA 指標 (如 Krippendorff's α、Cohen's κ 等)，不同指標可能產生不同結論。
2. **k 值的選擇**：每個項目抽取的人類標註數 k 影響檢定效能，但作者未深入探討最佳 k 值。
3. **LLM 標註的隨機性**：若 LLM 標註本身具有隨機性 (如 temperature > 0)，單次 LLM 標註可能不具代表性。
4. **計算成本**：B 次自助法迭代 × N 個項目 × k 個標註的計算量在大型資料集上可能相當可觀。
5. **無法處理標註者分歧本身是研究對象的情境**：作者承認其方法主要針對「共享訊號」目標，對於以分歧為研究對象的設定 (Aroyo & Welty, 2015; Basile et al., 2021; Uma et al., 2021; Plank, 2022) 需要進一步適配。

A：未來研究可以朝幾個方向延伸：首先，將 AltRA-Test 推廣到更多元的 IAA 指標（例如考慮標註者身分或加權版本），以涵蓋分歧本身即為研究對象的情境；其次，探討如何將檢定與主動學習（active learning）結合，讓系統在標註過程中動態決定哪些項目值得請人類標註、哪些可放心交給 LLM；第三，發展多 LLM 比較的延伸版本，協助研究者在多個候選模型中選出最適合特定任務的替代標註者；最後，將此方法應用於多語言與跨文化場景，檢驗 LLM 在不同語言與文化脈絡下是否同樣能保留人類的共享訊號。

### 實作步驟建議

**步驟一：準備評估資料集**
從現有標註資料中選取約 100–200 筆項目，每項至少有 3 個人類標註。記錄每筆項目的人類標註分布，並對同一批項目取得 LLM 標註。建議先以小規模試驗確認 LLM 標註格式與人類標註相容。

**步驟二：選擇 IAA 指標**
根據任務類型選擇合適的 IAA 指標：
- 類別標註：Krippendorff's α（名義）或 Cohen's κ
- 序數標註：Krippendorff's α（序數）
- 連續值：Krippendorff's α（區間）或 ICC

**步驟三：實作配對自助法核心**
對 `B` 次迭代（建議 `B≥1000`）：
1. 以放回抽樣方式抽取 `N` 個項目
2. 對每個抽中的項目，抽取 `k` 個人類標註
3. 將其中一個標註替換為 LLM 標註，形成混合小組
4. 分別計算全人類小組與混合小組的 IAA
5. 計算替換差距 `Δ̂(b)` 與自適應邊界 `ε(b)`
6. 計算調整後差距 `Δ̂_adj(b) = Δ̂(b) + ε(b)`

**步驟四：建立決策規則**
收集所有 `B` 次迭代的調整後差距，取 α 分位數（預設 α=0.05）作為決策統計量 `q*α`。若 `q*α > 0`，則拒絕虛無假設，判定 LLM 通過檢定，可作為人類標註者的替代。

**步驟五：驗證與監控**
- 在已知 LLM 優於/劣於人類的模擬情境下驗證檢定行為
- 對不同任務、提示技巧、模型版本重複執行
- 建立定期重測機制，因為 LLM 行為可能隨版本更新而改變

**步驟六：文件化決策依據**
記錄通過/未通過的設定、使用的 IAA 指標、`c` 值、樣本數等參數，便於日後稽核與重現。

### 潛在風險與注意事項

**風險一：抽樣代表性不足**
若評估項目未能涵蓋任務的多樣性，檢定結果可能無法推廣到整體標註任務。**緩解措施**：採用分層抽樣，確保評估集涵蓋困難案例、邊界案例與典型案例。

**風險二：LLM 標註的確定性問題**
LLM 在非零溫度下可能產生不同標註，破壞檢定的可重現性。**緩解措施**：使用 temperature=0 或固定隨機種子；對同一項目多次取樣並報告變異。

**風險三：標註洩漏（contamination）**
若 LLM 在訓練階段已接觸過評估項目，可能產生過於樂觀的結果。**緩解措施**：使用近期、未公開的項目作為評估集；記錄資料來源與時間戳記。

**風險四：將「通過檢定」誤讀為「LLM 等同人類」**
AltRA-Test 僅檢驗 LLM 是否保留人類標註者群體的共享訊號，不保證 LLM 在所有下游任務中表現相同。**緩解措施**：在文件中明確說明檢定的範圍限制；對關鍵決策保留人類覆核機制。

**風險五：自適應邊界 `c` 的選擇影響結論**
較大的 `c` 值使檢定更容易通過，可能掩蓋真實的品質下降。**緩解措施**：根據任務的容錯需求預先設定 `c`，並進行敏感度分析（嘗試多個 `c` 值）。

**風險六：忽略標註分歧本身的研究價值**
對於以分歧為研究對象的任務（如標註爭議性內容），AltRA-Test 的設計目標並不適用。**緩解措施**：在這類任務中，應改用人類標註者間的分布比較，而非聚合 IAA。

### 與其他技術的整合建議

**與 LLM 評審管線（LLM-as-a-judge pipeline）整合**
AltRA-Test 可作為部署前的把關機制：在將 LLM 評審整合到評估管線前，先以 AltRA-Test 確認其標註品質。建議將檢定結果作為模型卡（model card）的一部分記錄。

**與主動學習（Active Learning）整合**
在主動學習迴圈中，可使用 AltRA-Test 動態決定哪些項目可由 LLM 標註、哪些需送回人類。當 LLM 信心高且通過檢定的任務類型，可優先採用 LLM 標註以加速迭代。

**與資料品質監控儀表板整合**
將 AltRA-Test 的決策統計量 `q*α`、IAA 差距、樣本數等指標整合到 ML observability 平台（如 Weights & Biases、MLflow），建立標註品質的長期追蹤。

**與 A/B 測試框架整合**
當組織在多個 LLM 之間選擇時，可將 AltRA-Test 結果與下游模型效能的 A/B 測試結果交叉比對，找出統計顯著性與實務效益的最佳組合。

**與版本控制與 CI/CD 整合**
將 AltRA-Test 納入 LLM 升級的 CI 流程：每次更換模型版本或提示技巧時，自動執行檢定並比對與前一版本的差異，避免無意中降低標註品質。
