## ⚡ TL;DR

現有基準測試難以嚴謹評估資料智能體在多元真實場景的細粒度表現。
提出AgenticDataBench，涵蓋十五領域真實任務與細粒度標籤，萃取資料科學技能以系統評估。
評估了最先進的資料智能體，提供技能層級的詳細洞察並開源測試平台。

## 摘要翻譯

資料科學（Data Science）旨在從異質原始資料（Heterogeneous Raw Data）中獲取可執行洞察（Actionable Insights），釋放現代社會所產生大量資料的價值。自動化此流程對於減少資料科學家的勞力密集工作，以及實現可擴展的資料驅動應用（Data-driven Applications）至關重要。近期，基於大型語言模型（Large Language Model, LLM）的資料智能體（Data Agent）已成為自動化資料科學工作流程（Data Science Workflows）的極具潛力的解決方案。然而，此領域缺乏綜合性基準測試（Benchmark），以在多樣化情境中對這些智能體進行嚴謹且細粒度的評估。為填補此空白，我們提出 AgenticDataBench，這是一個綜合性基準測試，具備橫跨多樣領域的真實任務，並附有細粒度的真實標籤（Ground-truth Labels）。這使評估得以捕捉資料科學工作流程的多樣性與複雜性，以及智能體的詳盡表現。首先，為涵蓋多樣領域，我們從 15 個垂直領域（Vertical Domains）收集真實資料集與任務，其中包括來自一家領先金融科技（Fintech）公司的 5 個真實世界 B2B 使用案例（B2B Use Cases）。其次，為消除真實世界任務中的冗餘，並為缺乏真實資料的領域生成高品質任務，我們引入資料科學技能（Data Science Skills），即重複出現的以資料為中心的操作模式（Data-centric Operational Patterns），並以納入的技能數量來量化基準測試覆蓋率（Benchmark Coverage）。我們使用技能對齊階層式分群（Skill-aligned Hierarchical Clustering），從 Stack Overflow 上的大規模任務解決方案中萃取代表性技能。第三，針對真實世界商業任務，我們選取能最大化技能組成（Skill Composition）多樣性的任務-解決方案配對（Task-solution Pairs），以確保廣泛涵蓋實務情境。第四，為在缺乏真實任務的領域中生成真實任務，我們提出一種系統性的基於 LLM 的任務生成（LLM-based Task Generation）方法，以根據這些技能建立工作流程與任務。最後，我們使用已標註的基準測試與開源測試平台（Open-sourced Testbed）來評估最先進的（State-of-the-art）資料智能體，並提供詳細的技能層級洞察（Skill-level Insights）。

### 核心貢獻（3～5點）
- 建構跨領域真實任務集：從 15 個垂直領域（含 5 個金融科技 B2B 使用案例）收集真實資料集與任務，並以細粒度真實標籤進行標註，確保評估貼近實務情境。
- 提出以資料科學技能為核心的覆蓋率量化框架：定義「資料科學技能」為重複出現的以資料為中心的操作模式，並透過技能對齊階層式分群從 Stack Overflow 大規模解決方案中萃取代表性技能，以技能數量量化基準測試覆蓋率。
- 設計兼顧多樣性與擴展性的任務篩選與生成機制：針對真實任務，選取技能組成多樣性最高的任務-解決方案配對；針對缺乏真實資料的領域，提出系統性的基於 LLM 的任務生成方法，以確保廣泛涵蓋各類資料科學工作流程。
- 提供開源測試平台與細粒度評估洞察：釋出已標註的基準測試與開源測試平台，並針對最先進的資料智能體提供技能層級的詳盡表現分析。

### 適合對象
從事資料科學、自然語言處理或智能體系統研究的學者與工程師；特別適合關注大型語言模型在資料分析與商業決策應用、以及需要嚴謹評估資料智能體表現的基準測試開發者與企業資料團隊。

## 深度分析

#### 方法論解析

本研究提出之 AgenticDataBench（綜合性資料智能體基準測試）建構流程可分為四個核心階段，其設計邏輯旨在同時確保**真實性（realism）**、**領域多樣性（domain diversity）**與**評估細粒度（fine-grained granularity）**。

首先，在**真實世界資料收集**階段，作者從 15 個 vertical domains（垂直領域）蒐集真實資料集與任務，其中包含 5 個來自領先 fintech（金融科技）公司的 real-world B2B use cases（真實世界 B2B 使用案例）。這些商業任務保留了真實資料科學工作流程中的隱性領域知識與指令歧義性（instruction ambiguity），異質資料綱要（heterogeneous data schemas）與大規模資料集（large-scale datasets）所帶來的挑戰。

其次，為了消除真實任務間的冗餘，並為缺乏真實資料的領域建立高品質任務，作者引入 **data science skills（資料科學技能）** 的概念，將其定義為 recurring data-centric operational patterns（重複出現的以資料為中心的操作模式），例如 Handling Missing Data（缺失值處理）。具體而言，作者從 Stack Overflow 大規模任務解決方案中，透過 **skill-aligned hierarchical clustering（技能對齊階層式分群）** 自動萃取具代表性的技能集合，並以此量化 **benchmark coverage（基準測試覆蓋率）**。這種由底向上、以程式碼行為為基礎的分群方式，相較於人工歸納的粗粒度類別，更能反映實務上資料科學家面對的細部操作單元。

第三，針對真實商業任務，作者採用最大化 **skill composition（技能組成）** 多樣性的策略，篩選 **task-solution pairs（任務-解決方案配對）**，確保最終入選的任務能廣泛覆蓋各種實務情境，而非集中於少數重複的操作模式。

第四，對於缺乏真實任務的領域，本研究提出系統化的 **LLM-based task generation（基於 LLM 的任務生成）** 方法。該方法並非直接請求 LLM 憑空生成任務，而是以先前萃取出的技能庫為骨架，先建構合理的工作流程（workflow），再具體化為可執行的任務描述與 ground-truth labels（真實標籤）。這種「技能驅動生成」的策略有效提升了合成任務的結構真實性與操作連貫性。

最終，AgenticDataBench 提供具備細粒度標註的 benchmark（基準測試）與 open-sourced testbed（開源測試平台），使評估者能針對資料智能體在規劃（planning）、迭代執行（iterative execution）與終止（termination）各階段的表現，輸出 **skill-level insight（技能層級洞察）**。

#### 實驗數據解讀

作者利用 AgenticDataBench 評估多款 state-of-the-art（最先進的）data agents（資料智能體），包含 CodeX、Smolagents 與 DA-Agent。實驗設計的核心價值在於：不僅提供總體正確率，更透過細粒度標註揭示失敗根因。

以圖 1a 之 Loan Risk Control Task（貸款風險控制任務）為例，任務要求資料智能體讀取 input.csv，以 apply_date 作為月份分群，計算所有特徵欄位（feature columns）的月度統計量與 predictive metrics（預測指標），包含 missing rate（缺失率）與 KS（KS 統計量，Kolmogorov-Smirnov statistic），並明確指示缺失值（missing values）須以 -1 填補，最終輸出指定格式之 output.csv。此任務同時檢驗資料智能體對於指令解析、時間分群、缺失值處理（Handling Missing Data）與金融風控領域指標計算的能力。

實驗結果顯示，CodeX 在整體 leaderboard（排行榜）上表現最佳，能正確產出符合要求的統計量與指標；相對地，Smolagents 在該任務的 Skill-Level Analysis（技能層級分析）中，於 Handling Missing Data（缺失值處理）項目被標記為失敗（❌）。這顯示儘管 Smolagents 具備程式碼生成能力，但在理解明確的前處理指令（preprocess instruction）並將其對應至正確的資料清理步驟上仍有明顯缺陷。此外，實驗觀察到部分 agent 出現 step timeout（步驟逾時）與 efficient data structures and algorithms（高效資料結構與演算法）使用不當的問題，例如在計算 KS 統計量時採用低效的逐門檻迴圈而非向量化運算，導致在時間限制內無法完成任務。

這些結果凸顯當前 LLM-based data agents 的三大瓶頸：
1. **指令接地（instruction grounding）不足**：難以將高階自然語言指令精準對應至具體的資料操作參數（如缺失值填補常數 -1）。
2. **迭代探索（iterative exploration）能力薄弱**：面對 large-scale datasets（大規模資料集）時，缺乏自動調整特徵處理策略或選擇更適演算法的自我修正機制。
3. **執行效率與穩定性**：在運算資源或步驟數受限的環境下，生成程式碼的時間複雜度與記憶體管理仍不理想。

#### 與現有研究的比較

透過表 1 與文獻回顧可見，AgenticDataBench 相較於既有資料智能體基準測試，在以下面向實現顯著躍進：

| 比較面向 | 既有基準測試（DSBench、BLADE、DA-Code 等） | AgenticDataBench |
|---|---|---|
| **資料來源** | 多依賴 public dataset（公開資料集），缺乏真實商業場景的複雜度 | 同時納入 public dataset 與真實 Business（商業）資料，包含 fintech 領域之 B2B use cases |
| **領域覆蓋** | 領域單一或有限 | 橫跨 15 個 vertical domains（垂直領域），涵蓋金融、農業、醫療、電商等 |
| **技能粒度** | 僅提供 coarse-grained（粗粒度）任務類別與總分 | 定義 20 項 data science skills，提供 skill-level insight，可定位至 File I/O、Data Cleaning、Feature Engineering 等具體環節 |
| **任務真實性** | 任務多為人工設計或過度簡化，忽略指令歧義與隱性領域知識 | 任務源自真實工作流程，保留 heterogeneous raw data（異質原始資料）與模糊需求 |
| **評估維度** | 偏重最終輸出是否正確 | 結合 ground-truth labels 與技能層級標註，評估規劃、執行、終止全鏈路 |

具體而言，DSBench 與 DA-Code 等基準雖具備一定規模，但缺乏 business domain（商業領域）資料，且任務類型傾向單一程式碼生成；BLADE 雖涵蓋較多技能概念，但任務數量極少，難以支撐穩健的統計評估。AgenticDataBench 透過 skill composition 多樣性篩選與 LLM-based task generation，在任務廣度與結構真實性間取得平衡。

然而，本研究仍存在若干侷限：
- **任務規模**：相較於某些程式碼生成基準測試動輒數千題，AgenticDataBench 目前收錄之任務總數（表 1 顯示 48 項任務）仍屬中等規模，對於極端長尾（long-tail）技能的覆蓋可能不足。
- **生成任務的真實性上限**：對於無真實資料的領域，其任務係透過 LLM 基於技能骨架生成，雖然結構合理，但可能缺乏真實世界資料中難以預期的雜訊與業務邏輯陷阱。
- **評估指標**：目前採用 approximate match（近似匹配）評估統計輸出，對於開放式分析任務（如「提出商業建議」）的評估方式仍較為有限。

#### 可重現性評估

在可重現性（reproducibility）方面，AgenticDataBench 採取開放科學導向的策略，但仍面臨資料性質與技術依賴所帶來的挑戰。

**正面因素**：
- 作者明確提及提供 **open-sourced testbed（開源測試平台）**，並釋出帶有 ground-truth labels（真實標籤）的 annotated benchmark（標註基準測試），使其他研究者能複現評估流程。
- 技能萃取方法（skill-aligned hierarchical clustering）基於公開之 Stack Overflow 資料，方法論本身具備可複製性。
- 任務生成流程被設計為系統化 pipeline，降低單純 prompt engineering 帶來的隨機性。

**限制與風險**：
- **商業資料可用性**：5 個核心 B2B use cases 來自領先 fintech 公司，即便資料可能已脫敏，其公開程度與授權條款仍可能限制外部研究者完全重現商業領域實驗。
- **LLM 生成之非確定性**：LLM-based task generation 與部分 agent（如 CodeX）依賴 proprietary LLM APIs（專有大型語言模型介面），模型版本更新（如 GPT-4 系列迭代）與溫度參數（temperature）設定可能導致生成任務與實驗結果難以完全固定。
- **模型權重（model weights）**：評估涉及之 Smolagents、DA-Agent 等框架雖可能開源，但底層驅動之 LLM（如 GPT-4、Claude 等）權重並未公開，這意味著「完全從頭重現」仍受限於商業 API 的可及性與成本。

整體而言，AgenticDataBench 在基準測試結構與評估腳本上具備高度可重現性，但在資料與模型權重層面仍屬於「部分開放」狀態，建議後續釋出更多中繼資料（metadata）與任務生成種子（seeds）以強化嚴謹度。

#### 未來研究方向

基於 AgenticDataBench 的設計架構與實驗發現，以下為幾個具潛力之後續研究方向：

1. **動態與持續演化基準測試（Dynamic Benchmarking）**  
   由於 LLM-based data agents 快速演進，靜態 benchmark 容易面臨過擬合（overfitting）風險。未來可結合 LLM-based task generation 機制，建立能依據新興 data science skills 自動擴充題庫的動態測試平台，甚至引入對抗性生成（adversarial generation）以產生更具挑戰性的邊界案例。

2. **強化式學習與技能層級獎勵設計（RL with Skill-Level Rewards）**  
   目前 benchmark 主要用於離線評估。未來可將 skill-level insight 轉化為細粒度獎勵訊號，訓練具備自我修正能力之資料智能體，特別針對 Handling Missing Data、Feature Engineering（特徵工程）等薄弱環節進行專項強化。

3. **多模態資料科學工作流程（Multimodal Data Science Workflows）**  
   當前任務主要圍繞結構化資料（structured data）與文字。後續可擴展至圖像、地理資訊（如 GeoJSON）、時間序列感測器資料等，評估資料智能體在跨模態（cross-modal）資料清理與特徵萃取上的能力。

4. **人機協同與模糊任務評估（Human-in-the-Loop & Ambiguous Task Evaluation）**  
   真實資料科學任務常伴隨需求模糊性。未來研究可引入人類專家於迴路中，評估 agent 在面對開放式詮釋（如「分析使用者流失原因」）時，其產出之可解釋性（interpretability）與商業價值，而非僅以 ground-truth labels 論斷對錯。

5. **效率與成本感知評估（Efficiency & Cost-Aware Evaluation）**  
   除了正確率，應系統性評估資料智能體之 token 消耗、API 呼叫成本與執行時間。建立 Pareto frontier（帕雷托前緣）分析框架，探討在有限運算預算下，不同 agent 於準確度與成本間的權衡。

6. **跨領域遷移與元學習（Cross-Domain Transfer & Meta-Learning）**  
   利用 AgenticDataBench 涵蓋 15 個 vertical domains 之優勢，研究 agent 在某一領域習得之技能（如金融風控之 KS 計算）能否透過 meta-learning（元學習）快速遷移至醫療或能源領域，降低對領域專屬微調的依賴。

7. **開源權重模型之專項評測（Open-Weight Model Evaluation）**  
   目前 leaderboard 以商業 API 為主。未來應系統性評測 Llama、Qwen、DeepSeek 等 open-weight LLMs（開源權重大型語言模型）在資料智能體框架下之表現，並分析模型規模與資料科學推理能力之縮放法則（scaling law）。

## 論文問答

**Q1：是什麼樣的根本挑戰促使研究者建立 AgenticDataBench 這個基準測試？**
A：現代社會產生大量異質原始資料，資料科學的核心目標是從中提煉可執行洞察，但傳統流程極度依賴資料科學家的人工處理與反覆迭代。雖然基於大型語言模型的資料智能體被視為自動化資料科學工作流程的有前景方案，但該領域長期缺乏能夠嚴謹評估這些智能體的綜合性基準測試。這種評估缺口使得研究者難以系統性地比較不同智能體在真實且複雜情境下的表現，也阻礙了可擴展資料驅動應用的發展。

**Q2：現有的基準測試為何無法充分評估基於大型語言模型的資料智能體？**
A：現有的基準測試通常僅依賴少數人工挑選的任務類型，無法涵蓋真實商業應用中的複雜性與多樣性。此外，這些測試往往只提供粗粒度的任務分類與總體分數，導致智能體在步驟層級的行為細節被掩蓋，難以診斷具體的失敗原因。這種缺乏細粒度真實標籤與跨領域覆蓋的評估方式，無法捕捉資料科學工作流程的真實多樣性與複雜度。

**Q3：為何具備細粒度標籤的綜合性基準測試對於推動資料智能體的發展至關重要？**

## 實務應用指南

### 適用場景

1. **金融風控模型開發與驗證**：適用於金融科技業者評估資料智能體在真實 B2B 使用案例中的表現，例如自動化執行貸款風險控制任務，計算特徵欄位的缺失率、KS 統計量等預測指標，並確保智能體能正確處理缺失值與大規模異質原始資料。
2. **跨領域資料科學團隊能力評鑑**：當企業橫跨多個垂直領域（如電商、醫療、能源、不動產）時，可利用涵蓋 15 個領域的基準測試，透過細粒度的技能層級洞察，比較不同資料智能體在各自專業領域的優劣。
3. **LLM 資料智能體選型與採購決策**：企業在導入最先進的資料智能體前，可透過 AgenticDataBench 的標準化測試平台與真實標籤，進行客觀的 POC（概念驗證），避免僅依賴供應商提供的聚合分數而忽略步驟層級的失敗風險。
4. **自動化資料分析流程上線前的壓力測試**：在將資料驅動應用部署至生產環境前，利用具備多樣技能組成的任務-解決方案配對，驗證智能體在規劃（Planning）、迭代執行（Iterative Execution）與終止（Termination）各階段的穩定性。
5. **資料科學教育與人才培訓**：將從 Stack Overflow 萃取的資料科學技能（如缺失值處理、特徵工程、資料清理）作為教學大綱，搭配基準測試中的工作流程範例，建立結構化的實戰訓練教材。

### 實作前置條件

- **資料準備**：至少需具備一組真實業務資料集（如論文中的 input.csv 格式），並搭配領域專家撰寫的任務規格書；若涉及敏感 B2B 資料，需先完成去識別化。對於缺乏真實資料的垂直領域，需準備技能本體論作為基於 LLM 的任務生成之輸入。
- **運算資源**：獨立的 Python 沙箱執行環境（隔離程式碼執行、防止破壞性操作）、LLM API 存取權限（支援長上下文與程式碼生成）、足夠處理大規模資料的記憶體與運算資源，以及設定步驟逾時（Step Timeout）機制所需的系統權限。
- **技能需求**：團隊需具備資料科學基礎（熟悉 pandas、scikit-learn 等工具）、LLM 提示工程能力、軟體工程能力以部署測試平台，並需要領域專家（如風控、行銷）協助驗證真實標籤的正確性。

### 實作步驟建議

1. **盤點與萃取技能**：梳理企業內部歷史資料科學任務，識別重複出現的以資料為中心的操作模式（如缺失值處理、資料正規化、特徵欄位編碼），建立內部資料科學技能清單，作為量化基準測試覆蓋率的依據。
2. **蒐集真實任務-解決方案配對**：從現有業務流程（如貸款風險控制、行銷策略分析）中挑選具代表性的案例，確保其技能組成具有高度多樣性，避免任務同質化。
3. **生成合成任務補足缺口**：針對缺乏真實資料的垂直領域，運用論文提出的系統化基於 LLM 的任務生成方法，依據已建立的技能清單自動產生工作流程與對應任務。
4. **建立細粒度真實標籤**：為每個任務標註步驟層級的正確答案、中間產物（如經預處理後的資料表、特徵工程結果）與最終輸出規格，確保評估時能捕捉智能體的詳細行為。
5. **部署測試平台**：建置支援程式碼執行、資料 I/O 與自動評分的測試平台，整合沙箱環境與 KS 統計量等預測指標的近似比對邏輯。
6. **執行技能層級評估**：對候選的資料智能體（如 Smolagents、CodeX 等）執行基準測試，產出各項資料科學技能的優劣分析報告，識別其強項與弱項。
7. **生產環境整合與持續監控**：將通過驗證的智能體整合至企業工作流程，並在實際運作中持續追蹤其在規劃、迭代執行與終止階段的表現，定期回頭更新基準測試的任務庫。

### 潛在風險與注意事項

- **指令歧義風險**：真實業務任務常存在隱含假設（例如缺失值應填補 -1 而非平均值），若使用者指令模糊，智能體可能產出符合語法但違反領域知識的結果。**緩解措施**：在任務描述中明確化所有前處理規則，並建立領域知識庫供智能體查詢。
- **資料隱私與安全**：使用真實 B2B 資料進行基準測試時，有洩漏敏感資訊的風險；同時，智能體自動生成的程式碼可能在沙箱外造成破壞。**緩解措施**：嚴格執行資料去識別化，並將程式碼執行限制於完全隔離的容器化環境，設定檔案系統與網路存取白名單。
- **過度擬合常見技能**：智能體可能針對高頻率出現的資料科學技能（如基本資料清理）過度優化，卻在長尾技能（如特定領域的特徵工程）上表現不佳。**緩解措施**：定期檢視基準測試覆蓋率，確保技能組成包含足夠的邊緣案例與複雜工作流程。
- **評分偏差**：自動評分機制若僅採用輸出檔案的近似匹配，可能無法辨識語意正確但實作路徑不同的優質解決方案。**緩解措施**：設計多維度評分函數，結合執行結果正確性、技能使用適切性與程式碼效率進行綜合判斷。
- **執行資源耗盡**：資料智能體在迭代執行過程中可能因陷入無窮迴圈或處理過大資料集而耗盡運算資源。**緩解措施**：嚴格設定步驟逾時與總執行時間上限，並在規劃階段引入成本估算機制。

### 與其他技術的整合建議

- **MLOps / DevOps 平台**：將 AgenticDataBench 的測試平台整合至現有 CI/CD 管線，作為資料智能體版本發布前的自動化回歸測試閘道，確保新模型不會在已通過的技能上產生退化。
- **企業資料倉儲**：讓測試平台與現有資料倉儲（如 Hive、Snowflake、PostgreSQL）連接，使基準測試中的任務能直接操作企業實際的異質原始資料，提升評估的真實性。
- **向量資料庫與 RAG**：將從 Stack Overflow 萃取的技能向量與歷史任務-解決方案配對儲存於向量資料庫，為資料智能體提供檢索增強生成（RAG）能力，強化其在規劃階段的推理品質。
- **監控與可觀測性系統**：整合現有 APM（Application Performance Monitoring）工具，針對智能體的規劃、迭代執行與終止三階段分別追蹤延遲、錯誤率與 Token 消耗，將技能層級洞察轉化為維運儀表板。
- **低程式碼 / BI 平台**：將通過基準測試驗證的資料智能體封裝為標準化 API 或視覺化元件，讓非技術背景的商業使用者也能在安全範圍內觸發複雜的資料科學工作流程。

### 給不同背景讀者的閱讀建議

- **初學者**：建議從圖 1(a) 的貸款風險控制任務範例入手，先理解資料智能體如何從原始資料產出可執行洞察，掌握「規劃—迭代執行—終止」的基本工作流程後，再逐步認識各項資料科學技能（如缺失值處理、特徵欄位預處理）的實際意義，無需急著深入技術細節。
- **AI 工程師**：應深入理解論文中技能對齊階層式分群的方法論與基於 LLM 的任務生成流程，重點關注測試平台的沙箱設計、技能層級評分機制，以及如何將此基準測試框架客製化為內部資料智能體的持續整合與迭代優化工具。
- **研究人員**：可聚焦於本基準測試相較於 DSBench、BLADE 等現有工作的差異化貢獻，特別是細粒度真實標籤與跨 15 個垂直領域的覆蓋率設計；可進一步延伸探討資料科學技能本體論的自動建構、動態更新機制，以及更精細的步驟層級評估理論。
- **產品經理**：請優先掌握 15 個垂直領域與 5 個真實 B2B 使用案例的商業價值，理解「基準測試覆蓋率」如何量化為產品可靠性指標，並學習將技能層級洞察轉化為產品路線圖中功能優先順序的決策依據，以評估導入資料智能體的投資報酬率與風險邊界。
