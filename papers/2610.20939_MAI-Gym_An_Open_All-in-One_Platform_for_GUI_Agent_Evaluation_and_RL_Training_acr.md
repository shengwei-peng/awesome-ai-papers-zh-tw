# MAI-Gym：一個涵蓋行動裝置與電腦環境、用於圖形介面代理 (GUI Agent) 評估與強化學習 (RL) 訓練的開源一站式平台

## ⚡ TL;DR

線上強化學習應用於GUI代理面臨環境成本高昂與真實訓練任務稀缺等挑戰。
本文提出MAI-Gym統一平台，支援多平台GUI代理評估與線上強化學習，並自動合成模擬應用與任務。
MAI-Gym-9B在基準測試中達到開源代理最先進表現，模擬訓練可有效遷移至真實應用。

## 摘要翻譯

線上強化學習 (Online RL) 結合可驗證獎勵 (Verifiable Rewards) 已在數學、程式設計與工具使用領域取得快速進展，但由於互動式環境的高昂成本以及真實訓練任務的稀缺，將此成功擴展至圖形介面代理 (GUI Agent) 仍具挑戰性。我們推出 MAI-Gym，一個開源一站式平台 (All-in-One Platform)，統一整合行動裝置、電腦與網頁環境下的圖形介面代理評估、資料收集與線上強化學習訓練。透過共享的推展流程 (Rollout Pipeline)，MAI-Gym 確保評估與訓練間一致的代理行為 (Consistent Agent Behavior)，支援十個既有的基準測試 (Benchmark)，並可擴展至 20,000 個平行環境實例 (Parallel Environment Instances)。除了可擴展的基礎設施 (Scalable Infrastructure) 外，MAI-Gym 支援多樣化圖形介面應用程式與具挑戰性任務的自動化合成 (Automated Synthesis)，包括可重置模擬應用程式 (Resettable Mocked Apps)，以及配備執行驗證式任務驗證器 (Execution-Validated Task Verifier) 的一致性跨應用程式世界 (Coherent Cross-App Worlds)。利用 MAI-Gym，我們訓練出 MAI-Gym-9B，一個用於行動裝置使用 (Mobile Use) 與電腦使用 (Computer Use) 的統一 9B 代理，在 10B 參數以下的開源圖形介面代理 (Open GUI Agents) 中達到最先進 (SOTA) 的表現：在 MobileWorld 上達到 78.4%，在 OSWorld-Verified 上達到 76.2%。重要的是，在模擬購票應用程式 (Mocked Train-Ticketing App) 中進行的強化學習可遷移至其真實世界對應版本，將實體手機 (Physical Phone) 上的任務成功率 (Task Success) 從 28.8% 提升至 48.1%。我們公開框架 (Framework)、合成技能 (Synthesis Skills)、模擬應用程式、2,000 個已驗證任務 (Verified Tasks) 以及模型檢查點 (Model Checkpoint)，以支援可重現研究 (Reproducible Research) 並推動可擴展圖形介面代理訓練的進一步發展。

### 核心貢獻（3～5點）
- **統一化基礎設施**：提出 MAI-Gym 開源一站式平台，透過共享推展流程統一行動裝置、電腦與網頁環境下的圖形介面代理評估、資料收集與線上強化學習訓練，支援十個既有基準測試並可擴展至 20,000 個平行環境實例。
- **自動化環境與任務合成**：實現多樣化圖形介面應用程式的自動化合成，包含可重置模擬應用程式與配備執行驗證式任務驗證器的一致性跨應用程式世界，大幅降低互動式環境建置成本。
- **頂尖開源模型表現**：基於 MAI-Gym 訓練的 MAI-Gym-9B 統一代理，在 10B 參數以下的開源圖形介面代理中達到最先進表現，於 MobileWorld 與 OSWorld-Verified 基準測試分別取得 78.4% 與 76.2% 的優異成績。
- **模擬到真實的遷移驗證**：實證在模擬購票應用程式中進行的強化學習可有效遷移至真實世界對應版本，將實體手機上的任務成功率從 28.8% 提升至 48.1%，驗證了模擬環境訓練的實用價值。
- **全面開源釋出**：公開框架、合成技能、模擬應用程式、2,000 個已驗證任務及模型檢查點，支援可重現研究並促進可擴展圖形介面代理訓練領域的後續發展。

### 適合對象
- **圖形介面代理 (GUI Agent) 研究者**：從事行動裝置、電腦或網頁自動化代理研發，需要統一評估與訓練基礎設施的學術與產業研究者。
- **強化學習實踐者**：關注線上強化學習、可驗證獎勵及模擬到真實遷移學習 (Sim-to-Real Transfer) 技術的機器學習工程師與研究員。
- **大型語言模型 / 視覺語言模型開發者**：從事多模態模型 (Multimodal)、視覺語言模型 (VLM) 微調與部署，特別是代理式人工智慧 (Agentic AI) 應用的開發團隊。
- **開源社群貢獻者**：對開源工具、基準測試與可重現研究有興趣，欲利用 MAI-Gym 框架進行後續實驗或擴展應用的開發者。
- **企業 AI 應用團隊**：尋求將圖形介面自動化技術導入實際產品（如智慧型手機操作自動化、桌面工作流程自動化）的技術決策者與解決方案架構師。

## 深度分析

#### 方法論解析

MAI-Gym 的核心設計理念在於解決 GUI 代理 (GUI Agent) 線上強化學習 (Online RL) 領域中兩個根本性挑戰：互動式環境的高擴展成本與真實任務的稀缺性。該平台採用「共享推展路徑」(Shared Rollout Pipeline) 作為中央架構決策，確保評估、資料收集與訓練三個環節共用相同的觀察處理、上下文建構與動作執行邏輯，從根本上消除代理實作在評估與訓練之間的漂移問題。

**系統架構層面**，MAI-Gym 採用統一介面設計，能同時支援行動裝置 (Mobile)、電腦 (Computer) 與網頁 (Web) 三類環境。平台自動化管理環境的配置、隔離、重置與恢復流程，並已驗證可擴展至 20,000 個平行環境實例 (Parallel Environment Instances)。此規模遠超現有開源 GUI 訓練基礎設施（通常僅數百個環境），為大規模線上 RL 訓練奠定基礎。

**環境合成 (Environment Synthesis) 機制**是 MAI-Gym 的另一關鍵創新。系統利用編碼代理 (Coding Agent) 自動建構兩類應用程式：(1) 真實世界克隆 (Real-World Clones)，即模擬既有應用程式介面與功能的可重置版本；(2) 原創應用程式 (Novel Apps)，用於評估代理對未見過介面的適應能力。這些模擬應用程式 (Mocked Apps) 配備自包含的可重置後端，使訓練過程可在不影響真實系統的前提下進行。

**跨應用程式世界建構 (Cross-App World Construction)** 解決了現有任務合成方法僅依賴孤立輸入檔案或共享範例資料的限制。MAI-Gym 能夠建構跨多個應用程式的一致性世界狀態，例如讓電子郵件、附件與發票內容在環境中保持邏輯一致，從而產生更貼近真實工作流程的任務。

**任務與驗證器合成 (Task and Verifier Synthesis)** 採用執行驗證式任務驗證器 (Execution-Validated Task Verifier)，透過實際執行程式碼來判定任務完成狀態，而非僅依賴表層特徵比對。這種設計大幅提升了獎勵信號 (Reward Signal) 的可靠性。

**線上 RL 訓練**方面，MAI-Gym 支援 GRPO (Group Relative Policy Optimization，分組相對策略最佳化) 與 SAO 兩種演算法，並實現行動裝置與電腦任務的聯合訓練 (Joint Training)。此設計使單一模型能同時處理異質環境，驗證了跨領域遷移學習的可行性。

#### 實驗數據解讀

**主要效能結果**顯示 MAI-Gym-9B 在開源 GUI 代理領域達到最先進 (SOTA) 水平：在 MobileWorld 基準上達成 78.4% 成功率，在 OSWorld-Verified 上達成 76.2% 成功率，且模型規模控制在 10B 參數 (Parameters) 以下。這項結果的意義在於：(1) 證明了線上 RL 訓練對 GUI 代理的實質效益，而非僅依賴預訓練 (Pre-training) 與監督微調 (SFT)；(2) 9B 規模的模型能與更大規模的閉源模型競爭，顯示訓練方法的重要性。

**模擬到真實的遷移實驗**尤為關鍵：在模擬購票應用程式 (Train-Ticketing App) 上進行強化學習訓練後，代理在實體手機 (Physical Phone) 上執行相同任務的成功率從 28.8% 提升至 48.1%，提升幅度達 19.3 個百分點。此結果驗證了模擬環境作為訓練來源的實用價值，解決了真實交易類應用程式不適合訓練的安全性顧慮。

**基礎設施擴展性驗證**透過 20,000 個平行環境實例的運行，證明了系統在工業級規模下的可行性。吞吐量 (Throughput) 與延遲 (Latency) 指標需在附錄中進一步檢視，但此規模本身已具里程碑意義。

**消融實驗 (Ablation Study) 涵蓋多個維度**：(1) 聯合強化學習 (Joint RL) 優於專家模型合併 (Expert Merging)，證明端到端訓練比模型集成更有效；(2) 合成任務的規模化能持續提升泛化 (Generalization) 能力，顯示資料多樣性的價值；(3) 克隆訓練 (Clone Training) 可遷移至真實應用程式 (Real App)，驗證模擬環境的訓練訊號有效性；(4) 代理能從獎勵中學習未見過的應用程式，展示了線上 RL 對新介面的適應能力；(5) GRPO 與 SAO 的比較為演算法選擇提供實證依據。

**值得注意的是**，實驗結果中跨領域泛化的具體數據（如行動裝置訓練對電腦任務的幫助程度）需在論文中進一步確認，這對於評估聯合訓練策略的實際效益至關重要。

#### 與現有研究的比較

**相較於基礎設施導向的 GUI Gym**（如 BrowserGym、AndroidWorld），MAI-Gym 的核心優勢在於：(1) 跨平台統一性，單一系統同時支援行動裝置、電腦與網頁環境；(2) 訓練規模的數量級提升，從數百個環境擴展至 20,000 個；(3) 整合環境合成能力，突破固定基準的限制。然而，這些平台在特定領域的成熟度仍可能優於 MAI-Gym，特別是在瀏覽器互動或 Android 系統層級整合方面。

**相較於資料導向的 Gym**（如 AppWorld、OS-Genesis 等），MAI-Gym 提供了完整的訓練閉環，不僅釋出新任務與環境，還提供可執行的訓練程式碼。這填補了現有生態系中「資料豐富但無法訓練」或「可訓練但任務有限」之間的鴻溝。

**與近期 GUI 代理 RL 工作**（如 UI-TARS、OpenCUA 等）的比較中，MAI-Gym-9B 的 9B 參數規模與 SOTA 表現顯示出極佳的參數效率 (Parameter Efficiency)。然而，與閉源商業系統（如 Anthropic 的 Computer Use、OpenAI 的 Operator）相比，開源方案在複雜多步驟任務上的絕對能力仍有差距。

**限制與不足**：(1) 模擬環境與真實環境之間仍存在視覺與互動層面的差距，雖然購票應用程式遷移實驗驗證了可行性，但其他類型應用程式的遷移效果需進一步驗證；(2) 環境合成依賴編碼代理的品質，可能引入系統性偏差；(3) 20,000 平行環境的硬體需求對一般研究機構構成門檻；(4) 對於需要真實帳號、支付等不可重置操作的場景，模擬環境的覆蓋能力有限。

#### 可重現性評估

MAI-Gym 在可重現性 (Reproducibility) 方面展現了極高的承諾，釋出內容涵蓋五大面向：

1. **框架程式碼 (Framework)**：完整的系統實作，支援評估與訓練流程
2. **合成技能 (Synthesis Skills)**：環境與任務生成的程式化方法
3. **模擬應用程式 (Mocked Apps)**：包含真實世界克隆與原創應用程式
4. **2,000 個已驗證任務 (Verified Tasks)**：附帶執行驗證式驗證器
5. **模型檢查點 (Model Checkpoint)**：MAI-Gym-9B 的完整權重

此釋出策略符合開放科學 (Open Science) 最佳實踐，使研究者能：(1) 直接重現論文中所有基準測試結果；(2) 在統一的環境中比較新方法；(3) 利用釋出的合成技能擴展任務集；(4) 基於 MAI-Gym-9B 進行下游微調或遷移學習。

**潛在的可重現性風險**包括：(1) 20,000 平行環境的硬體配置需求可能限制完整重現；(2) 部分基準測試（如 OSWorld-Verified）的評估可能受環境隨機性影響；(3) 編碼代理的版本與模型依賴可能影響合成任務的品質。然而，相較於同領域多數僅釋出模型權重或僅釋出程式碼的工作，MAI-Gym 的釋出完整性已屬標竿。

#### 未來研究方向

**第一，模擬到真實遷移的深化研究**。購票應用程式的成功遷移（28.8% → 48.1%）開啟了系統性研究模擬環境訓練效用的方向。未來工作可探索：(1) 何種類型的任務最容易從模擬遷移至真實；(2) 模擬環境與真實環境之間的視覺/互動差距如何量化與縮小；(3) 領域自適應 (Domain Adaptation) 技術能否進一步縮小 Sim-to-Real Gap。

**第二，環境與任務合成的品質提升**。當前合成方法依賴編碼代理，未來可結合：(1) 從真實使用者互動日誌中學習環境模型；(2) 引入人類回饋 (RLHF) 指導任務難度分級；(3) 探索課程學習 (Curriculum Learning) 策略，從簡單任務逐步過渡到複雜跨應用程式工作流程。

**第三，多模態與推理能力的整合**。GUI 代理的長期發展需要更強的視覺語言模型 (VLM) 推理能力。未來方向包括：(1) 整合思維鏈 (Chain-of-Thought, CoT) 推理，使代理能規劃多步驟操作；(2) 結合反思 (Reflection) 機制，從失敗中學習；(3) 探索記憶 (Memory) 架構，支援跨對話的狀態追蹤。

**第四，安全與對齊研究**。隨著 GUI 代理能力增強，安全考量日益重要：(1) 防止代理執行不可逆操作（如刪除檔案、發送訊息）；(2) 建立人類監督 (Human-in-the-Loop) 機制；(3) 研究對抗攻擊 (Adversarial Attack) 下的穩健性 (Robustness)。

**第五，效率與可持續性**。20,000 平行環境的能耗與成本問題值得關注：(1) 探索模型蒸餾 (Distillation) 將大模型能力壓縮至小模型；(2) 研究樣本效率 (Sample Efficiency) 更高的 RL 演算法；(3) 評估量化 (Quantization) 與剪枝 (Pruning) 對部署的影響。

**第六，評估基準的擴展**。現有基準（如 MobileWorld、OSWorld-Verified）覆蓋有限，未來可：(1) 建構涵蓋更多應用程式類型的基準；(2) 設計評估長期任務規劃能力的新指標；(3) 引入真實使用者需求的測試場景。

**第七，持續學習與終身學習**。GUI 應用程式介面持續演進，代理需具備持續學習 (Continual Learning) 能力以避免災難性遺忘 (Catastrophic Forgetting)，這是部署於真實環境的關鍵能力。

MAI-Gym 的開源釋出為上述所有方向提供了實驗基礎，預期將加速 GUI 代理研究從基準測試導向走向實際部署導向的轉變。

## 論文問答

**Q1：MAI-Gym 主要解決什麼核心問題？為什麼將線上強化學習擴展到 GUI 代理比數學或程式領域更具挑戰性？**

A：MAI-Gym 旨在解決將線上強化學習（Online RL）成功擴展至 GUI 代理時所面臨的兩大根本挑戰：互動式 GUI 環境的高昂執行成本，以及真實且具意義的訓練任務的稀缺性。與數學題目可自動驗證答案、程式碼可透過測試套件執行不同，GUI 環境無法被並行嘗試共享，因為代理會對整個螢幕與裝置檔案進行操作，每次嘗試都需要獨立的裝置或瀏覽器實例。此外，GUI 任務通常涉及跨應用程式的複雜工作流程，需要一致的環境狀態才能進行有意義的訓練，這使得任務合成與環境建構比純文字領域困難許多。

**Q2：現有的 GUI 訓練平台為何無法滿足需求？基礎設施導向與資料導向的健身房各有什麼限制？**

A：現有的 GUI 健身房通常只解決部分問題。基礎設施導向的平台（如 BrowserGym 等）雖然讓評估或訓練易於重現，但每個平台僅涵蓋單一作業系統，且釋出訓練程式碼者最多僅能並行執行數百個環境，難以擴展到大規模訓練。資料導向的健身房雖然策劃了許多新應用程式與任務，但既不釋出訓練程式碼，也未提供執行既有基準測試的方法。這兩類限制其實相互糾結——可擴展的基礎設施需要持續供應有意義的任務，而合成的任務只有在能被有效評估並用於學習時才真正有價值，因此需要一個結合兩者的統一平台。

**Q3：為什麼這項研究對 AI 代理與 GUI 自動化領域至關重要？**

A：這項研究的重要性在於它填補了 GUI 代理領域中基礎設施與任務供應之間的關鍵鴻溝，使得大規模線上強化學習在 GUI 領域成為可能。透過統一評估、資料收集與訓練流程，MAI-Gym 確保了代理行為在評估與訓練間的一致性，解決了「測量效能可能取決於執行框架而非模型本身」的問題。此外，自動化合成逼真且可重置的環境與任務，使得代理能夠在安全且多樣化的條件下學習複雜的跨應用程式工作流程，這對於推動 GUI 代理從基準測試走向真實世界部署具有關鍵意義。

**Q4：MAI-Gym 的核心架構設計是什麼？什麼是「共享推展流程」（shared rollout pipeline）？**

A：MAI-Gym 的核心設計選擇是共享推展流程：對於給定的代理與環境，評估、資料收集與訓練會重複使用相同的觀察處理、上下文建構與動作執行，因此對代理程式碼的任何修正會同時傳遞到三者。這種設計消除了評估與訓練之間的「漂移」問題，確保測量到的效能真正反映模型能力而非執行框架差異。透過單一指令，研究人員可以在十個既有基準測試（三個行動裝置、四個電腦、三個網頁）上評估本地或 API 託管的模型，並透過儀表板檢視每條軌跡；另一個指令則可啟動線上強化學習訓練，包括行動裝置與電腦任務的聯合訓練。

**Q5：MAI-Gym 在環境與任務合成方面的關鍵創新是什麼？如何實現自動化合成模擬應用程式與跨應用程式世界？**

A：MAI-Gym 的關鍵創新在於結合了可擴展執行基礎設施與自動化環境/任務合成。在應用程式層級，編碼代理會建構模擬應用程式（mocked apps）——這些是具有可重置後端的自包含應用程式，既包含真實世界應用程式的克隆，也包含全新設計的應用程式。在跨應用程式世界建構方面，MAI-Gym 能夠生成具有一致檔案與應用程式狀態的連貫世界，使得代理可以處理依賴多個應用程式資訊的真實工作流程（例如根據附件發票回覆電子郵件）。任務與驗證器合成則透過執行驗證式任務驗證器（execution-validated task verifiers）確保任務的可驗證性，從而支援可驗證獎勵的線上強化學習。

**Q6：MAI-Gym 系統架構中有哪些關鍵設計選擇？如何實現 20,000 個平行環境實例的擴展性？**

A：MAI-Gym 的關鍵設計選擇包括自動化的環境配置、隔離、重置與恢復管理機制，使得大規模並行執行成為可能。系統採用共享推展流程作為核心架構原則，確保觀察處理、上下文建構與動作執行在評估與訓練間完全一致。為了達到 20,000 個平行環境實例的規模，平台必須有效處理 GUI 環境特有的挑戰——每個實例都需要獨立的裝置或瀏覽器、已知的初始狀態，以及在代理完成後的重置機制。這種規模的擴展性使得大規模線上強化學習訓練成為現實，遠超以往僅能並行數百個環境的限制。

**Q7：MAI-Gym 支援哪些基準測試？其在行動裝置、電腦與網頁環境的評估覆蓋範圍如何？**

A：MAI-Gym 支援十個既有基準測試，涵蓋三個行動裝置基準、四個電腦基準與三個網頁基準，提供了跨平台的全面評估能力。這種廣泛的基準測試支援使得研究人員可以使用單一指令評估本地或 API 託管的模型，並透過儀表板檢視每條軌跡進行細部分析。重要的是，由於評估與訓練共用相同的代理執行框架，基準測試上的效能能夠真實反映模型在訓練後的泛化能力，避免了因執行框架差異而導致的效能失真。

**Q8：MAI-Gym-9B 的主要實驗結果為何？它達到了什麼樣的最先進效能？**

A：MAI-Gym-9B 是一個統一的 90 億參數代理，適用於行動裝置與電腦使用，在 10B 參數以下的開源 GUI 代理中達到了最先進的效能：它在 MobileWorld 上達到 78.4%，在 OSWorld-Verified 上達到 76.2%。更令人矚目的是，在模擬的購票應用程式中進行的強化學習訓練能夠遷移至其真實世界對應版本，將實體手機上的任務成功率從 28.8% 提升至 48.1%，證明了在合成環境中訓練的代理能夠有效泛化至真實場景。這些結果顯示了 MAI-Gym 平台在訓練高效能 GUI 代理方面的有效性。

**Q9：MAI-Gym 進行了哪些關鍵的消融實驗？有哪些重要發現？**

A：MAI-Gym 進行了多項重要的消融實驗，涵蓋基礎設施擴展性、聯合強化學習 vs 專家模型合併、合成任務擴展、克隆訓練遷移、從獎勵學習未見過的應用程式，以及 GRPO 與 SAO 的比較等面向。其中「聯合強化學習優於專家模型合併」的發現表明，跨平台的聯合訓練比分別訓練後合併更有效；「擴展合成任務能改善泛化」證明了任務多樣性對代理泛化能力的重要性；「克隆訓練能遷移至真實應用程式」則驗證了模擬環境訓練的實用價值。這些消融實驗為平台設計與訓練策略提供了實證依據。

**Q10：MAI-Gym 支援哪些實際應用場景？克隆訓練如何遷移至真實世界的應用程式？**

A：MAI-Gym 支援多種實際應用場景，特別是在涉及交易或不適合直接訓練的真實世界應用程式（如購票應用程式）中，透過模擬版本進行訓練後遷移至真實版本。實驗結果顯示，在模擬購票應用程式中進行的強化學習訓練能夠將實體手機上的任務成功率從 28.8% 提升至 48.1%，證明了合成環境訓練的實用價值。這種「克隆訓練」策略使得研究人員能夠在安全、可控且可重置的環境中訓練代理，避免了在真實應用程式上進行訓練可能帶來的安全風險或實際成本，同時仍能獲得在真實世界中有效的代理能力。

**Q11：將使用 MAI-Gym 訓練的 GUI 代理部署到生產環境時，需要考慮哪些因素？**

A：將使用 MAI-Gym 訓練的 GUI 代理部署到生產環境時，需要考慮多項因素。首先是模擬到真實的遷移差距——雖然克隆訓練顯示出良好的遷移能力，但真實應用程式的介面更新、版本變化仍可能影響代理效能，因此需要持續的監控與再訓練機制。其次是安全性與可靠性——GUI 代理在真實裝置上執行操作時，需要設置適當的權限控制與操作邊界，避免意外操作。此外，延遲與吞吐量也是重要考量，因為 GUI 代理通常需要多次螢幕截圖與模型呼叫才能完成任務，這對即時性要求高的場景構成挑戰。

**Q12：MAI-Gym 對 GUI 代理與線上強化學習研究領域的更廣泛影響是什麼？**

A：MAI-Gym 對該領域的更廣泛影響在於它提供了一個開放、可重現的研究基礎設施，使得 GUI 代理的線上強化學習研究能夠以類似於數學與程式領域的方式進行大規模實驗。透過釋出框架、合成技能、模擬應用程式、2,000 個已驗證任務與模型檢查點，MAI-Gym 大幅降低了該領域研究的進入門檻，促進了可重現研究的發展。此外，統一評估與訓練流程的設計理念可能影響未來 GUI 代理平台的設計方向，推動該領域從分散的基準測試與訓練方法走向標準化，從而加速整體研究進展。

**Q13：MAI-Gym 有哪些已承認的限制？**

A：MAI-Gym 的限制主要體現在幾個方面。首先，雖然平台支援 20,000 個平行環境實例，但 GUI 環境的執行成本仍然高於純文字領域，這限制了某些類型的大規模實驗。其次，模擬應用程式雖然能夠有效支援訓練，但與真實應用程式之間仍存在差距，特別是在介面複雜度、邊緣情況處理等方面。此外，平台目前主要支援特定的作業系統與瀏覽器環境，對於新興平台或特殊裝置的支援可能需要額外的開發工作。最後，雖然克隆訓練顯示出良好的遷移能力，但對於高度動態或經常更新的真實應用程式，遷移效果仍需進一步驗證。

**Q14：MAI-Gym 識別了哪些失敗案例或挑戰？**

A：MAI-Gym 在實驗中識別了若干挑戰與失敗案例。在跨應用程式工作流程方面，雖然平台支援跨應用程式世界建構，但涉及多個應用程式協調的複雜任務仍然對代理構成顯著挑戰。在模擬到真實的遷移方面，雖然購票應用程式的克隆訓練顯示出正面結果，但對於介面差異更大的應用程式，遷移效果可能不如預期。此外，代理在面對未見過的應用程式時，雖然能從獎勵信號中學習，但學習效率與最終效能仍可能受到任務複雜度與獎勵稀疏性的影響。這些挑戰表明，雖然 MAI-Gym 提供了強大的基礎設施，但 GUI 代理的完全自主化仍有許多待解決的問題。

**Q15：MAI-Gym 論文提出了哪些未來研究方向？**

A：MAI-Gym 論文提出的未來研究方向涵蓋多個層面。在基礎設施層面，可以進一步擴展支援的平台與裝置類型，並提升環境執行的效率與成本效益。在任務合成方面，可以探索更複雜、更逼真的跨應用程式工作流程生成，以及更精細的獎勵函數設計。在訓練方法方面，可以研究更高效的強化學習演算法、課程學習策略，以及結合模仿學習與強化學習的混合方法。此外，模擬到真實的遷移仍是一個重要方向，需要更系統地研究如何縮小模擬環境與真實應用程式之間的差距，以及如何使代理能夠適應真實應用程式的持續更新與變化。

## 實務應用指南

### 適用場景

1. **企業內部系統自動化助手開發**：針對 ERP、CRM、客製化內部網站等缺乏公開 API 的系統，訓練 GUI 代理自動執行重複性操作（如報表匯出、訂單核對、跨系統資料搬運），降低人力成本並減少人為錯誤。

2. **行動 App 無障礙與自動化測試**：QA 團隊可利用 MAI-Gym 的模擬應用程式與跨應用程式世界，在 CI/CD 流程中對 Android/iOS App 進行大規模並行回歸測試，覆蓋真實使用者跨 App 操作路徑（如從電子郵件附件開啟發票並回覆）。

3. **金融與政務領域的數位勞動力 (Digital Workforce)**：在涉及交易、申報、查詢等高敏感操作的場景中，先於模擬購票、模擬申報 App 訓練代理，再將學到的策略遷移至真實 App，兼顧安全性與訓練效率（論文已驗證購票 App 從 28.8% 提升至 48.1%）。

4. **GUI 代理研究基準與排行榜建置**：學術團隊可基於 MAI-Gym 統一推展流程，確保評測與訓練使用相同的代理行為，消除「harness 差異導致效能偏差」的問題，產出可重現的基準比較結果。

5. **新興介面適應與冷啟動訓練**：當企業推出全新內部工具或代理需進入未見過的第三方 SaaS 時，可透過 MAI-Gym 的環境合成功能快速生成模擬 App 與任務，僅憑獎勵信號即可讓代理學會操作陌生介面。

### 實作前置條件

**資料需求**
- 目標 GUI 環境的螢幕截圖與無障礙樹（Accessibility Tree）擷取能力
- 任務定義資料集：自然語言指令、初始狀態、預期終態、可執行驗證腳本
- 若使用合成功能：目標 App 的 UI 規格、狀態機描述、檔案結構範本

**算力需求**
- 評估階段：單一基準測試通常需要數十至數百個並行環境實例，建議配置 8–16 顆 GPU（A100/H100 等級）作為推論節點
- 線上 RL 訓練階段：論文已展示 20,000 個並行環境實例的規模，需配置 Kubernetes 叢集搭配容器化 Android 模擬器、虛擬機（VM）或瀏覽器實例，整體 GPU 數量視 rollout 吞吐量而定（建議至少 32 顆以上高階 GPU）
- 環境託管節點：每個並行實例需獨立 CPU/RAM/儲存資源，行動裝置模擬器單實例建議 2–4 GB RAM

**技能需求**
- 熟悉 PyTorch 與分散式訓練框架（FSDP、DeepSpeed）
- 具備 Android/iOS 模擬器、Android Debug Bridge (ADB)、Docker、Kubernetes 操作經驗
- 了解視覺語言模型（VLM）推論管線與 GUI 動作空間設計（點擊、輸入、滑動等）
- 具備強化學習基礎（GRPO、PPO、優勢函數估計）
- 程式碼代理（coding agent）使用經驗，以便擴展模擬 App 與任務合成流程

### 實作步驟建議

**步驟一：環境部署與基準驗證**
- 從官方開源倉庫取得 MAI-Gym 框架程式碼與預訓練檢查點（MAI-Gym-9B）
- 部署容器化環境池，先以小規模（100–500 個並行實例）重現論文中 MobileWorld 與 OSWorld-Verified 的基準數字，作為後續客製化的可信賴基線
- 啟動 MAI-Gym Dashboard，檢視每條軌跡的觀察、動作、獎勵，確認代理行為符合預期

**步驟二：動作空間與代理執行框架對齊**
- 盤點企業內部系統或目標 App 的可執行操作，映射至 MAI-Gym 的標準動作空間（點擊座標、輸入文字、滑動、捲動等）
- 若目標系統提供結構化資訊（如 DOM、無障礙節點），將其整合進觀察處理流程，提升代理的感知效率
- 統一評估、資料收集、訓練三條流程的代理程式碼，遵循「shared rollout pipeline」原則，避免行為漂移

**步驟三：任務與驗證器設計**
- 為每個目標業務流程定義「可執行任務」：自然語言指令 + 初始環境狀態 + 執行驗證式驗證器（execution-validated verifier）
- 對於涉及多系統協作的真實工作流（如「從信件附件讀取發票金額並回覆」），採用論文的「跨應用程式世界建構」方法，確保檔案、應用狀態的一致性
- 對於交易類高風險任務，優先建立「真實世界克隆」模擬 App，於模擬環境完成訓練後再遷移至真實 App

**步驟四：合成資料擴增**
- 運用 MAI-Gym 的環境合成功能，由程式碼代理自動生成多樣化模擬 App 與任務，擴充訓練資料分布
- 採用「Scaling Synthesized Tasks Improves Generalization」的策略，逐步擴增合成任務數量並監控泛化指標
- 為每個合成任務配置可執行的獎勵函數，避免僅依賴稀疏的最終獎勵

**步驟五：線上 RL 訓練與監控**
- 啟動線上 RL 訓練管線，採用 GRPO 或 SAO 等演算法（論文 §4.3.6 比較兩者差異）
- 對行動裝置與電腦任務進行「聯合訓練」（Joint RL），論文中證明此方式優於「專家模型合併」（Expert Merging）
- 透過 Dashboard 即時監控 rollout 吞吐量、獎勵曲線、訓練穩定性，設定早停條件

**步驟六：模擬到真實的遷移驗證**
- 在模擬環境訓練完成後，於受控的真實裝置（如實體手機、桌面瀏覽器）上執行小規模驗證
- 採用論文的「Clone Training Transfers to the Real App」方法論，量化遷移效益
- 收集真實環境的失敗案例，回流至訓練資料形成閉環

**步驟七：部署與持續迭代**
- 將訓練後的代理封裝為 API 服務或本地執行程序，整合至企業工作流
- 建立監控與日誌機制，追蹤任務成功率、延遲、異常軌跡
- 定期以新資料微調代理，適應 UI 變更與新業務流程

### 潛在風險與注意事項

**風險一：模擬到真實的分布偏移**
- 模擬 App 與真實 App 在視覺細節、載入速度、邊界案例上存在差異，可能導致代理在真實環境效能下降
- **緩解**：採用「真實世界克隆」策略而非完全虛構的 App；於真實環境保留小規模驗證集持續監控；在訓練中加入隨機化（字型、圖示、載入延遲）以提升穩健性

**風險二：訓練成本與資源管理複雜度**
- 20,000 個並行環境實例的規模對叢集管理、容器隔離、狀態重置提出極高要求，環境故障可能中斷訓練
- **緩解**：建立自動化的環境健康檢查與故障恢復機制；採用漸進式擴展策略，從小規模驗證後再放大；預留冗餘資源

**風險三：獎勵 hacking 與驗證器漏洞**
- 代理可能學會「通過驗證器但未真正完成任務」的捷徑，尤其當驗證器僅檢查表面狀態時
- **緩解**：採用「執行驗證式驗證器」（執行完整業務邏輯而非單純比對 UI 狀態）；定期人工審查軌跡；對高風險任務設置多層驗證

**風險四：動作空間與平台差異**
- 行動裝置、電腦、網頁三種環境的動作語意不同，統一動作空間可能犧牲表達力或引入歧義
- **緩解**：保留平台特定的擴展動作；於觀察中明確標註當前平台；針對跨平台任務設計專屬的動作組合

**風險五：安全性與合規**
- GUI 代理可能誤觸敏感操作（刪除檔案、發送錯誤訊息、完成未授權交易）
- **緩解**：於高風險動作前設置確認機制；採用「乾跑預覽」模式；對涉及金流、個資的操作實施人工審核閘門；遵守企業資料治理與隱私法規

**風險六：基準過擬合與泛化不足**
- 在固定基準上表現優異的代理，可能無法應對 UI 更新或新版本 App
- **緩解**：定期更新基準與模擬 App；採用「未見過的應用程式」測試集（論文中 Agents Learn Unfamiliar Apps from Reward 的驗證方式）；持續收集真實環境資料

### 與其他技術的整合建議

**與 RAG（檢索增強生成）整合**
- 將企業知識庫、文件庫透過 RAG 接入代理的上下文建構流程，使代理在執行 GUI 操作時可參考操作手冊、業務規則
- 適用於複雜業務流程（如「依據公司報銷政策處理發票」）

**與函式呼叫 / 工具使用整合**
- 對於可透過 API 完成的子任務，優先呼叫 API 而非操作 GUI，提升效率與可靠性
- GUI 操作保留作為 API 不可用時的後備方案，形成「API 優先、GUI 兜底」的混合策略

**與工作流編排系統整合**
- 將 MAI-Gym 訓練的代理嵌入 LangChain、AutoGen 等代理編排框架，作為「GUI 操作工具」節點
- 與其他專業代理（如資料分析代理、文件生成代理）協作，處理端到端業務流程

**與 CI/CD 與 MLOps 整合**
- 將 GUI 代理的評估流程整合至 CI/CD，每次模型更新自動執行基準測試
- 使用 Weights & Biases 或 MLflow 追蹤訓練實驗、模型版本、評估指標
- 採用 Git 版本控制管理代理程式碼、動作空間定義、任務配置

**與監控與可觀測性平台整合**
- 整合 Prometheus、Grafana 監控 rollout 吞吐量、GPU 使用率、環境健康度
- 將代理軌跡、結構化日誌送入企業日誌系統（如 ELK Stack），便於事後稽核與除錯

**與既有 RPA 平台整合**
- 對於已有 UiPath、Automation Anywhere 等 RPA 部署的企業，可將 MAI-Gym 訓練的代理作為「智慧型例外處理」層，處理傳統 RPA 規則無法覆蓋的彈性場景

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀論文第 1 節（Introduction）與第 2 節（Preliminaries），理解 GUI 代理、可執行任務、線上代理式強化學習的基本概念。接著瀏覽第 3.1 節（System Architecture）的系統架構圖，掌握「共享推展流程」這個核心設計理念。可先在個人電腦上以小規模（數個並行環境）部署 MAI-Gym，重現論文的基準數字，從實作中建立直覺。暫時跳過訓練演算法細節，聚焦於「如何讓代理在環境中執行任務並獲得獎勵」的端到端流程。

**給 AI 工程師**：重點研讀第 3.2 節（Scalable and Efficient Rollouts）與第 3.5 節（Online RL Training），理解分散式環境池的設計、rollout 吞吐量優化、GRPO 與 SAO 演算法的實作差異。第 4.3 節的消融實驗（特別是「Joint RL Beats Expert Merging」與「Comparing GRPO and SAO」）對實際訓練決策極具參考價值。附錄 A.4 與 A.5 的超參數與訓練配置是寶貴的實務參考，建議直接複用並依自身場景微調。評估自身的 GPU 與叢集資源，從小規模（數百並行實例）開始驗證，再逐步放大。

**給研究者**：論文的關鍵學術貢獻在於「統一評估與訓練的共享推展流程」以及「跨應用程式世界建構」方法論，建議深入研讀第 3.4 節（Synthesizing Environments and Tasks）與相關消融實驗。可關注以下研究方向：（1）如何進一步縮小模擬到真實的差距；（2）獎勵函數設計與驗證器魯棒性；（3）聯合訓練 vs. 專家合併的理論分析；（4）合成任務的規模化對泛化的影響。論文的開源釋出（框架、合成技能、模擬 App、2,000 個已驗證任務、模型檢查點）提供了絕佳的研究起點，建議以此為基礎探索新演算法或新場景。

**給產品經理**：聚焦於論文的實際效益數字（MobileWorld 78.4%、OSWorld-Verified 76.2%、購票 App 從 28.8% 提升至 48.1%）與「適用場景」一節列出的企業應用方向。理解 MAI-Gym 的價值主張：透過統一平台降低 GUI 代理的研發門檻，透過模擬環境解決訓練資料稀缺與安全性問題。評估自身業務流程中哪些環節適合導入 GUI 自動化（建議從高重複性、跨系統、規則明確的流程開始），並與技術團隊討論部署成本、預期效益、風險控管。論文的「Clone Training Transfers to the Real App」結果特別值得參考，可作為向管理層說服導入的關鍵案例。
