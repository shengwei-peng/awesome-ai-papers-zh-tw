## ⚡ TL;DR

直播電商數位人需在低延遲下頻繁更新業務規則，但小模型易過擬合固定 Harness 並喪失泛化。
提出 HAT，以 HSA 擴增 Harness 狀態，並透過 SFT、蒸餾與 RL 三階段訓練。
直播 QA 94.8、變體 94.6，P50 延遲 3.4 秒，線上 A/B 提升 GMV 與瀏覽量。

## 摘要翻譯

AI 數位人主播（AI-powered digital avatar streamers）必須即時回答商品問題（product questions）、與觀眾互動（viewer engagement），並執行行銷策略（marketing strategies），這對低延遲（latency）、頻繁的策略更新，以及準確且有效的回覆提出了要求。可演化 Harness（Evolvable Harnesses）中的 Skills（技能）、Hooks（鉤子）、提示詞（prompts）與工具（tools）可獨立於模型權重進行更新，使其得以快速迭代，但也帶出一項權衡：大型模型能零樣本（zero-shot）適應，卻延遲過高；緊湊模型雖能滿足延遲目標，卻會對固定 Harness 配置過度擬合（overfit）。我們提出 Harness 感知訓練（Harness-Aware Training, HAT），用於訓練緊湊模型以適應不斷變化的 Harness。其核心元件 Harness 狀態增強（Harness-State Augmentation, HSA）會對 Skill 識別碼與內容、工具結構描述（tool schemas）、提示詞結構及 Hook 函式進行任務保留變換（task-preserving transformations）。訓練分為三個階段：HSA 監督式微調（HSA-Supervised Fine-Tuning, HSA-SFT）從強模型在多樣環境下的執行軌跡（trajectories）學習推理與工具使用；廣義同策略蒸餾（General On-Policy Distillation）恢復 SFT 階段喪失的泛化能力（generalization）；HSA 強化學習（HSA-Reinforcement Learning, HSA-RL）則在增強環境（augmented environments）中透過強化學習（reinforcement learning）提升對 Harness 變化的穩健性（robustness）。在四個評估集合上，HAT 於直播問答（Live-Stream QA）達到 94.8（基座模型（base model）：80.3；最強通用大型語言模型（strongest general LLM）：93.0），並於 Harness 變體問答（Harness-Variant QA）達到 94.6（基座模型：75.4）。相較於基座模型，固定 Harness 監督式微調（Fixed-Harness SFT）使 IFEval 下降 7.7 分，而 HAT 避免此衰退並達到 83.5。在單張 NVIDIA H20 GPU 上，經最佳化的系統 P50 延遲（P50 latency）與 P95 延遲（P95 latency）分別為 3.4 秒與 8.1 秒。部署於淘寶直播（Taobao Live）數位人服務後，線上 A/B 測試（A/B test）在 GMV（商品交易總額，Gross Merchandise Volume）與商品頁瀏覽量（item-page views）方面均取得正向結果。

### 核心貢獻（3～5點）
- 提出 Harness 感知訓練（HAT），讓緊湊模型在 Harness 獨立演化的情況下仍能適應，解決大型模型延遲過高與固定 Harness 監督式微調過擬合的兩難。
- 設計 Harness 狀態增強（HSA），對 Skill、Hook、提示詞與工具結構描述等進行任務保留變換，提升模型對 Harness 變化的穩健性。
- 建立三階段訓練流程：HSA-SFT 學習推理與工具使用、廣義同策略蒸餾恢復泛化能力、HSA-RL 在增強環境中強化對變化 Harness 的穩健性。
- 在直播問答與 Harness 變體問答上顯著超越基座模型，並避免 Fixed-Harness SFT 在 IFEval 的衰退，同時於單張 NVIDIA H20 GPU 達成 P50 3.4 秒 / P95 8.1 秒的延遲。
- 實際部署於淘寶直播數位人服務，線上 A/B 測試顯示 GMV 與商品頁瀏覽量均有正向提升。

### 適合對象
從事大型語言模型智慧體、數位人、直播電商應用的研究人員與工程師，特別是關注低延遲部署、可演化系統、模型泛化與穩健性，以及線上 A/B 測試成效的讀者。

## 深度分析

#### 方法論解析

##### 1. Evolvable Harness（可演化 Harness）架構的設計邏輯
本文將數位人主播（AI-powered digital avatar streamers）的核心能力拆分為「緩慢更新的凍結策略模型（frozen policy model）」與「可快速演化的執行環境（execution environment）」兩部分。後者稱為 Harness，由四個可獨立版本化的模組組成：

- **Skills（技能）**：回覆規則（reply rules）與行銷策略（marketing strategies）。
- **Hooks（鉤子）**：驗證邏輯（validation logic）。
- **System Prompt Pipeline（系統提示詞管線）**：動態指令（dynamic instructions）。
- **Tool Registry（工具註冊表）**：可供模型呼叫的外部工具（tools）。

透過 **Harness Evolution（Harness 演化）**——即開發者審核的診斷-編輯-評估循環（diagnose-edit-evaluate loop）——業務方可在數小時內調整直播話術、合規規則或工具介面，而無需重新訓練模型權重。這種分離在工業場景中極具價值，因為它將「模型訓練週期」與「業務迭代週期」解耦。

然而，這也改變了訓練問題：策略模型必須在 **變化的 Harness 狀態** 上運作，而非單一靜態配置。這是本文方法論的核心張力。

##### 2. 核心問題：表面形式過擬合（surface-form overfitting）
作者指出，若僅在固定 Harness 配置上做監督式微調（Fixed-Harness SFT），緊湊模型會出現 **表面形式過擬合**：模型記憶特定 skill 名稱、tool 名稱與 prompt 模板，而非真正理解指令語義。這導致兩個後果：

1. **Harness 一演化就失效**：當 skill 識別碼、tool schema 或 prompt 結構改變時，模型無法正確解讀。
2. **通用指令遵循能力退化**：在 IFEval 基準上，Fixed-Harness SFT 相較基座模型（base model）下降 7.7 分。

這揭示了直播電商（live-streaming e-commerce）場景的一個基本權衡：大模型（如 DeepSeek-V4-flash）可零樣本（zero-shot）適應新 Harness，但延遲（latency）過高（中位數端到端延遲超過 11 秒）；緊湊模型（如 Qwen3.6-35B-A3B）能滿足延遲目標，卻必須透過領域訓練（domain-trained）提升準確率，而傳統 SFT 又會損害其對 Harness 變化的穩健性（robustness）。

##### 3. Harness-Aware Training（HAT）的三階段流程
為解決上述問題，作者提出 **Harness-Aware Training（HAT，Harness 感知訓練）**，其關鍵在於將 Harness 狀態視為訓練分布（training distribution）的一部分，而非部署時的固定常數。HAT 由三個階段組成：

**（1）HSA-SFT：Harness 狀態增強監督式微調**
- 使用強教師模型（stronger teacher model）在經 **Harness-State Augmentation（HSA，Harness 狀態增強）** 多樣化後的 Harness 環境中生成高品質軌跡（trajectories）。
- 緊湊模型從這些軌跡中學習推理（reasoning）與工具使用（tool use）。
- HSA 對 Skill 內容、Skill 識別碼、tool schemas、prompt 結構與 Hook 函數施加 **任務保留變換（task-preserving transformations）**，確保語義不變但表面形式改變，從而迫使模型學習「依據當前 Harness 狀態進行條件化推理」，而非記憶固定配置。

**（2）General On-Policy Distillation（General OPD，廣義同策略蒸餾）**
- 領域 SFT 常會壓縮模型的通用能力。General OPD 讓模型從基座模型（base model）自身在通用領域資料上的輸出進行知識蒸餾（distillation），恢復在 HSA-SFT 過程中損失的泛化能力（generalization）。
- 這一步對維持 IFEval 表現至關重要，避免模型為了直播任務而過度偏離通用指令遵循能力。

**（3）HSA-RL：Harness 狀態增強強化學習**
- 在生產資訊驅動的直播間模擬器（production-informed live-room simulator）中，對模型進行強化學習（reinforcement learning）。
- 訓練環境同樣經過 HSA 擾動，使模型進一步提升對變化 Harness 的穩健性，並在動態環境中精進工具呼叫能力。

##### 4. Harness-State Augmentation（HSA）的技術內涵
HSA 是 HAT 的核心元件。其設計原則是「保留任務語義、改變表面形式」，具體包括：

- **Skill 識別碼與內容**：重新命名 skill ID、改寫 skill 描述，但保持其策略意圖不變。
- **Tool schemas（工具模式）**：修改工具名稱、參數名稱、參數順序或描述，但保持功能等價。
- **Prompt structures（提示詞結構）**：調整系統提示詞的段落順序、標記格式、列舉方式。
- **Hook functions（鉤子函數）**：改變驗證邏輯的表達形式或觸發條件。

這些變換本質上是一種 **結構化資料增強（structured data augmentation）**，類似於程式碼領域的語義保留變換（semantics-preserving program transformations）。它強迫模型學習 Harness 的「語義條件化表示」，從而具備與 Harness 共同演化（evolve with their Harness）的能力。

##### 5. 推理與部署最佳化
為滿足直播場景的延遲需求，作者在單張 NVIDIA H20 GPU 上結合 **MTP（Multi-Token Prediction）** 等推論加速技術進行最佳化。完整 agent 達到 P50 延遲 3.407 秒、P95 延遲 8.114 秒，顯著低於 DeepSeek-V4-flash 的 11 秒以上中位數延遲，滿足即時互動需求。

#### 實驗數據解讀

##### 1. 四個互補評估集的設計
作者建構了四個評估集，分別檢驗不同維度：

- **Live-Stream QA（直播問答）**：衡量真實直播場景下的回覆品質。
- **Harness-Variant QA（Harness 變體問答）**：衡量模型對 Harness 變化的適應能力。
- **Tool / Prompt Robustness（工具與提示詞穩健性）**：檢驗 tool schema 與 prompt 結構變動下的表現。
- **IFEval**：衡量通用指令遵循能力（instruction-following ability）。

這種多維度評估設計避免了「只提升領域分數、卻犧牲通用能力」的假象。

##### 2. 主要結果分析
| 評估項目 | HAT | Base Model | Fixed-Harness SFT | 最強通用 LLM |
|---|---|---|---|---|
| Live-Stream QA | **94.8** | 80.3 | — | 93.0 |
| Harness-Variant QA | **94.6** | 75.4 | — | — |
| IFEval | **83.5** | 基準 | 下降 7.7 | — |

- **Live-Stream QA 94.8**：不僅大幅超越未調校的基座模型（+14.5），也超過最強通用大型語言模型（strongest general LLM）的 93.0。這說明 HAT 成功將緊湊模型訓練到足以應對專業直播電商任務，同時保持可部署的延遲。
- **Harness-Variant QA 94.6**：相較基座模型的 75.4，提升近 20 分，證明 HAT 顯著增強了對 Harness 變化的穩健性。
- **IFEval 83.5**：關鍵在於 HAT **避免**了 Fixed-Harness SFT 造成的 7.7 分退化，顯示 General OPD 與 HSA 共同維護了通用指令遵循能力。

##### 3. 延遲與線上表現
- 在單張 NVIDIA H20 GPU 上，完整 agent 的 P50 延遲為 3.4 秒、P95 為 8.1 秒，符合直播電商的即時性要求。
- 淘寶直播（Taobao Live）的線上 A/B 測試顯示，HAT 系統在 UV 正規化後的 GMV（商品交易總額）與商品頁瀏覽量（item-page views）均有正向提升。
- 人類盲測中，HAT 獲得的偏好度也高於 ReAct。

##### 4. 數據背後的意義
這些結果共同說明：HAT 並非單純的「領域 SFT + RL」，而是一套能同時達成 **高效能、低延遲、高適應性、保留通用能力** 的系統性方法。特別是 IFEval 未退化這一點，在實務上極為重要——直播 agent 除了回答商品問題，還需遵守格式與內容約束（formatting and content constraints），例如輸出特定優惠碼格式、避免違規用語等。

#### 與現有研究的比較

##### 1. 與 Runtime Optimization / Modular Agent 框架的關係
近年來，DSPy（Khattab et al., 2023）、其他 runtime optimization 框架，以及各種模組化 agent 架構，都試圖將「提示工程（prompt engineering）」、「工具選擇」與「模型權重」分離。本文的 Evolvable Harness 可視為這一趨勢在直播電商場景的工業級實現：

- 不同於一般框架僅優化固定 pipeline，Harness 明確將 **Skills、Hooks、prompts、tools** 視為可獨立演化的版本化模組。
- 更重要的是，本文首次系統性地提出 **如何訓練一個能與 Harness 共同演化的緊湊策略模型**，這是過去模組化 agent 研究較少觸及的問題。

##### 2. 與 Test-Time Adaptation（測試時適應）的比較
測試時適應（test-time adaptation）方法雖可提升模型對新環境的適應力，但通常需要額外計算步驟，違反直播場景嚴格的延遲預算（latency budget）。HAT 的創新在於將適應性「前置」到訓練階段，透過 HSA 讓模型在推理時僅需讀取當前 Harness 狀態即可正確反應，無需額外適應計算。

##### 3. 與 Continual Learning（持續學習）的比較
持續學習（continual learning）理論上可讓模型隨 Harness 更新而更新，但每次 Harness 編輯都需重新訓練，在頻繁更新頻率（update frequency）下成本不可持續。HAT 透過將 Harness 狀態納入訓練分布，使模型權重保持凍結即可適應新 Harness，從根本上改變了成本結構。

##### 4. 與知識蒸餾（Distillation）的關係
HAT 的 HSA-SFT 可視為一種「跨 Harness 環境的軌跡蒸餾」，而 General OPD 則是「同策略自我蒸餾」。後者與近期「SFT 後進行通用能力恢復」的研究方向一致（如 Lu & Lab, 2025），但本文將其整合進一個完整的 agent 訓練流程，並證明其對 IFEval 的保護作用。

##### 5. 與強化學習（RL）在 Agent 中應用的比較
HSA-RL 並非首次將 RL 用於工具使用 agent，但其獨特之處在於在 **增強環境（augmented environments）** 中進行 RL，使獎勵信號不僅來自正確完成任務，也來自正確理解變化的 Harness 配置。這類似於領域隨機化（domain randomization）在機器人學習中的應用，但應用於離散符號化的 agent 環境。

##### 6. 主要貢獻與侷限
**主要貢獻：**
- 明確定義並形式化了「可演化 Harness」帶來的訓練問題。
- 提出 HSA 作為低成本、高效率的穩健性提升手段。
- 透過三階段訓練流程，同時達成領域效能、通用能力與部署延遲的平衡。
- 在真實工業場景（淘寶直播）中驗證了 GMV 與瀏覽量的正向影響。

**侷限：**
- HSA 的變換空間依賴人工設計的任務保留規則，對於更開放、語義更模糊的 Harness 模組（如創意行銷話術），如何確保「任務保留」可能需要更細緻的語義判斷。
- 實驗主要集中於單一領域（直播電商）與單一語言（中文），跨領域與跨語言的泛化能力尚需驗證。
- 對於極端 Harness 變化（例如新增完全未見過的工具類別、或 Hooks 邏輯發生結構性改變），HAT 的零樣本適應能力仍有上限，可能需要結合少量範例或更強的推理模型。

##### 3. 可重現的要素

- **HSA 的設計原則**（任務保留變換、對 Skill/tool/prompt/Hook 進行結構化增強）可被其他研究者借鑑並應用於自身領域。
- **三階段訓練流程**（HSA-SFT → General OPD → HSA-RL）的架構清晰，可在其他 agent 框架中複製。
- 使用的基礎模型（Qwen3.6-35B-A3B）與部分技術（MTP、DeepSeek-V4-flash）為公開或商業可用資源。

##### 4. 對學術界的啟示
本文再次凸顯工業級 agent 研究的一個現實：核心創新往往無法完全開源，但方法論與問題定義本身具有高度參考價值。未來若作者能釋出部分去識別化的評估樣本、HSA 變換規則或 judge 提示詞，將大幅提升社群重現與驗證的可能性。

#### 未來研究方向

##### 1. 自動化 Harness-State Augmentation
目前 HSA 的變換規則仍部分依賴人工設計。未來可探索：
- 使用大型語言模型自動生成任務保留變換（task-preserving transformations），並透過語義等價檢驗（如執行軌跡比對、形式化驗證）篩選有效變換。
- 學習式的增強策略：根據模型在驗證集上的弱點，自動決定應對哪些 Harness 元件進行擾動。

##### 2. 理論理解 HAT 的泛化機制
- 分析 HSA 如何改變模型的注意力模式與表示學習：模型是否真正學會「語義條件化」，或只是學到更魯棒的名稱對應？
- 建立 Harness 變化程度與模型表現退化的量化關係，為業務方提供「哪些修改無需重新訓練」的決策依據。

##### 3. 跨領域與跨語言遷移
- 將 HAT 應用於其他互動式 agent 場景，如客服、教育、醫療諮詢，驗證其是否為通用方法。
- 研究多語言直播場景下，HSA 對不同語言 Harness 狀態的適用性。

##### 4. 線上持續學習與人機協同演化
- 雖然 HAT 避免了每次 Harness 編輯都重新訓練，但當 Harness 變化超出訓練分布時，仍需機制將線上回饋（如觀眾負評、GMV 變化）納入模型更新。
- 探索「輕量級線上適應」與 HAT 的結合：平時凍結權重，僅在偵測到顯著分布偏移時觸發低成本微調。

##### 5. 多模態數位人整合
- 當前系統主要聚焦文字回覆與工具呼叫。未來可將 HAT 擴展至多模態 Harness，包括 TTS 風格、 avatar 表情動作、商品圖片與影片理解，使「回覆規則」與「多模態呈現」同步演化。

##### 6. 安全性與對齊
- 隨著 Harness 可由業務方快速編輯，如何確保新 Harness 不會引入幻覺（hallucination）、違規內容或偏見？
- 發展自動化的 Harness 安全驗證與對齊檢查，並將其整合進 Harness Evolution 的 diagnose-edit-evaluate loop。

##### 7. 更高效的推論架構
- 雖然目前已達 P50 3.4 秒，但對於更高互動頻率的直播場景，延遲仍有壓縮空間。
- 結合推測解碼（speculative decoding）、模型量化、專家混合（MoE）稀疏啟動等技術，進一步降低 P95 延遲。

##### 8. 開放基準與評估工具
- 建立公開的「Evolvable Agent Benchmark」，包含標準化的 Harness 變化類型、評估指標與 judge 協議，促進學術界對此問題的系統性研究。

## 論文問答

**Q1：AI 數位人主播在直播電商中必須同時滿足哪三項嚴苛要求，它們之間為何會產生張力？**

A：根據論文，AI 數位人主播必須同時達成超低延遲、頻繁適應行銷規則與合規變化，以及準確且有效地回應觀眾意圖並避免幻覺。這三項要求彼此牽制：強大的通用大型語言模型雖然能零樣本理解新規則，但端到端延遲過高，無法滿足即時直播的互動節奏；反之，緊湊模型雖然延遲低，但若只在固定設定上訓練，容易記憶特定 skill 名稱與 prompt 模板，導致 Harness 一更新就失效。因此，如何在「夠快」與「夠能適應變化」之間取得平衡，正是本文要解決的核心衝突。

**Q2：什麼是可演化 Harness，它如何改變策略模型的訓練問題？**

A：可演化 Harness 是一種將執行環境與凍結策略模型解耦的模組化架構，包含 Skills、Hooks、系統提示詞管線與工具註冊表四個可獨立更新的模組。開發者可以透過「診斷–編輯–評估」的 Harness 演化迴圈，在數小時內調整業務行為，而無需重新訓練模型權重。這使得策略模型必須學會在「會變動的執行環境」中運作，而不是只記住某一套固定的 skill 名稱、tool schema 或 prompt 結構，因此訓練目標從「擬合單一設定」轉變為「條件於任意給定的 Harness 狀態」。

**Q3：為何強大的零樣本大型語言模型與固定 Harness 監督式微調都無法滿足實際需求？**

A：以 DeepSeek-V4-flash 為例的強大零樣本模型雖然能直接理解修改後的 Harness，但其中位數端到端延遲超過 11 秒，遠超直播互動可接受的即時性門檻。另一方面，對緊湊模型進行固定 Harness 監督式微調雖能提升領域任務表現，卻會造成表面形式過擬合：模型記住特定名稱與模板，而非真正理解指令，導致 Harness 一演化就失效，並在 IFEval 上相較基座模型退步 7.7 分。測試時適應會違反延遲預算，持續學習則每次 Harness 編輯都要重新訓練，更新頻率過高時並不可行。

**Q4：Harness 感知訓練（HAT）的核心思想是什麼，它與固定 Harness 監督式微調有何根本差異？**

A：Harness 感知訓練把 Harness 狀態視為訓練分佈的一部分，而非部署時才給定的固定常數。不同於固定 Harness 監督式微調只讓模型擬合當前生產環境的單一設定，HAT 在多樣化的 Harness 狀態上分佈式訓練，使模型學會根據當下給定的 Harness 進行條件化推理。這樣一來，當業務規則、工具名稱或提示詞結構改變時，模型能夠持續正確解讀並執行，而不會因為表面形式的變化而崩潰。

**Q5：Harness 狀態增強（HSA）具體會對哪些 Harness 元件進行任務保留變換？**

A：HSA 會對 Skill 識別碼與內容、工具 schema、提示詞結構以及 Hook 函數等執行環境元件施加任務保留變換。這些變換在不改變底層任務語義的前提下，改變模型看到的表面形式，例如重新命名 skill、調整 tool schema 的欄位順序或改寫 prompt 結構。透過在訓練時讓模型接觸大量這類變體，HSA 迫使模型學習從 Harness 內容本身推導行為，而非背誦特定名稱或模板。

**Q6：HAT 為何採用 HSA-SFT、廣義同策略蒸餾與 HSA-RL 三階段管線，各自解決什麼問題？**

A：第一階段 HSA-SFT 讓緊湊模型學習強教師模型在 HSA 多樣化環境中產生的高品質軌跡，以掌握工具使用與領域推理能力。第二階段廣義同策略蒸餾則針對領域微調常見的副作用，利用通用領域資料從基座模型蒸餾，恢復在固定 Harness 監督式微調中流失的通用指令遵循能力。第三階段 HSA-RL 在模擬的真實直播環境中進行強化學習，進一步提升模型面對動態 Harness 變化時的穩健性與工具呼叫正確性。

**Q7：論文建構了哪四個互補的評估集合，各自評估什麼面向？**

A：四個評估集合分別是直播問答（Live-Stream QA）、Harness 變體問答（Harness-Variant QA）、工具與提示詞穩健性測試，以及通用指令遵循基準 IFEval。直播問答衡量模型在真實直播場景中回答商品問題與執行行銷策略的品質；Harness-Variant QA 評估當 skill、tool 或 prompt 結構改變時，模型是否仍能正確理解與回應；工具與提示詞穩健性測試檢視模型對工具 schema 與提示詞變動的適應力；IFEval 則用來監控模型在領域訓練後是否仍保留通用的格式與內容約束遵循能力。

**Q8：HAT 在 Live-Stream QA、Harness-Variant QA 與 IFEval 上的關鍵量化結果為何？**

A：在 Live-Stream QA 上，經 HAT 訓練的 Qwen3.6-35B-A3B 平均得分達到 94.8，明顯優於基座模型的 80.3 與最強通用大型語言模型的 93.0。在 Harness-Variant QA 上，HAT 取得 94.6，相較基座模型的 75.4 有大幅提升，顯示其對 Harness 變化的穩健性。至於 IFEval，固定 Harness 監督式微調會讓基座模型退步 7.7 分，而 HAT 不僅避免此衰退，還達到 83.5，顯示其在提升領域能力的同時保留了通用指令遵循能力。

**Q9：有哪些對照證據顯示 HAT 能避免固定 Harness 監督式微調造成的性能衰退？**

A：最直接的證據來自 IFEval：固定 Harness 監督式微調使模型相較基座模型下降 7.7 分，而 HAT 不僅沒有退步，反而提升到 83.5，顯示其透過廣義同策略蒸餾成功恢復通用能力。此外，在 Harness-Variant QA 上，固定訓練的模型會因為記憶特定 skill 與 tool 名稱而在變體上失效，HAT 則透過 HSA 在多樣化 Harness 狀態上訓練，顯著提升對變體的適應力。這些結果共同說明，把 Harness 變化納入訓練分佈，是避免表面形式過擬合的關鍵。

**Q10：部署時系統如何滿足延遲需求，實測的 P50 與 P95 延遲各是多少？**

A：為了滿足直播互動的即時性要求，系統採用緊湊的 Qwen3.6-35B-A3B 作為策略模型，並結合 MTP 等推論加速技術進行最佳化。在單張 NVIDIA H20 GPU 的受控完整 Agent 回放測試中，端到端牆面時鐘延遲的 P50 為 3.407 秒，P95 為 8.114 秒。這樣的延遲水準遠低於強大零樣本模型的 11 秒以上中位數延遲，使數位人主播能夠在觀眾可接受的時間內回應與互動。

**Q11：在淘寶直播的線上 A/B 測試中觀察到什麼結果，這代表什麼意義？**

A：論文報告在淘寶直播數位人服務上線後，線上 A/B 測試顯示經 UV 正規化後的 GMV 與商品頁瀏覽量均有正向提升。這表示 HAT 不僅在離線評測中表現良好，在真實商業環境中也能產生可衡量的業務價值。對直播平台而言，這證明了低延遲、可隨 Harness 演化的 AI 數位人主播確實能促進觀眾轉化與商品曝光，而不只是實驗室裡的技術展示。

**Q12：將策略模型權重與 Harness 模組解耦，對實際業務營運有什麼具體影響？**

A：這種解耦讓營運團隊可以在數小時內透過 Harness 演化迴圈調整回覆規則、行銷策略、合規驗證與可用工具，而無需經歷漫長的模型重新訓練與部署流程。對快速變動的直播電商而言，這意味著能及時響應促銷活動、平台規範與商家偏好的變化，大幅縮短業務迭代週期。同時，由於策略模型保持凍結，也降低了頻繁更新帶來的訓練成本與線上風險，使技術架構更具可維護性與擴展性。

**Q13：論文目前承認的主要限制或約束有哪些？**

A：一項主要限制是 HAT 雖然能處理已納入訓練分佈的 Harness 變化，但對於極端或訓練時未見過的結構性變更，其泛化能力仍有邊界。此外，HSA 的設計需要針對不同 Harness 元件仔細定義任務保留變換，這增加了訓練流程的工程複雜度與驗證成本。最後，線上 A/B 測試雖顯示正向業務指標，但具體提升幅度與長期穩定性仍有待更多場景與更長時間的驗證。

**Q14：在哪些失敗情境下，HAT 仍可能難以應對 Harness 的演化？**

A：如果 Harness 變更涉及全新的工具語義、與訓練分佈差異極大的 prompt 結構，或違反既有業務邏輯的 Hook 約束，模型可能無法正確推斷預期行為。例如，某個新引入的工具雖然名稱與舊工具相似，但功能完全相反，而 HSA 的變換未能覆蓋這種語義翻轉時，模型就可能錯誤呼叫。此外，當多個 Harness 模組同時發生高度耦合的劇烈變化時，模型對整體執行環境的理解也可能出現偏差，需要開發者介入診斷與修正。

**Q15：未來可以如何延伸 Harness 感知訓練，超越直播電商數位人的應用範疇？**

A：Harness 感知訓練的核心概念——將執行環境狀態納入訓練分佈——可推廣到任何需要頻繁更新規則、工具或提示詞的互動式 AI 系統，例如客戶服務機器人、教育輔導代理或醫療問診助手。未來研究可進一步探索自動化的 Harness 變化發現機制，讓模型在真實部署中持續學習新出現的環境設定，而不僅依賴人工設計的增強策略。此外，結合更強大的世界模型或線上適應技術，在仍滿足延遲預算的前提下提升對未見 Harness 配置的即時適應能力，也是值得發展的方向。

## 實務應用指南

### 適用場景

1. **直播電商 AI 數位人主播**：這是本文核心場景。AI 主播需在毫秒級延遲內回答商品規格、庫存、優惠問題，同時依據即時行銷策略（例如限時折扣、滿額贈品）調整話術，並可呼叫查價、查庫存、推薦商品等工具。

2. **金融/保險數位人客服**：需要頻繁因應法規變更、產品條款調整與合規話術更新。可演化 Harness 讓法務/業務單位在數小時內更新回覆規則與驗證邏輯，而無需重新訓練模型權重。

3. **教育與企業培訓互動助教**：課程內容、考試規則、學習路徑經常調整。透過 Skills 與 System Prompt Pipeline 模組化更新教學策略，並利用 HSA 訓練讓模型適應不同課程版本的指令與工具。

4. **醫療衛教與健康諮詢代理**：需嚴格遵守不斷演進的醫療合規指引與用藥建議。Hooks 可作為安全驗證閘門，確保輸出符合最新臨床指引；HSA-RL 則強化模型對更新後規則的遵循能力。

5. **企業內部知識服務代理**：串接 HR、IT、財務等部門的即時政策與內部系統。Harness 的 Tool Registry 可對接各部門 API，Skills 則封裝各部門的話術與流程，並隨組織政策快速迭代。

### 實作前置條件

**資料準備**
- 高品質對話軌跡：包含真實用戶問題、對話上下文、正確工具呼叫與回覆，建議至少數萬筆以上。
- 商品/領域知識庫：結構化商品屬性、FAQ、行銷活動規則、合規文件。
- Harness 配置樣本：Skills、Hooks、System Prompt、Tool Schema 的多版本資料，作為 HSA 增強的基礎。
- 人工標註與偏好資料：用於校準 Agent-as-a-Judge 評測器，以及 RL 階段的獎勵模型或偏好最佳化。
- 通用能力資料：用於 General OPD 階段，恢復模型在 IFEval 等通用指令遵循基準上的表現。

**運算資源**
- 訓練：至少一張 NVIDIA H20 等級 GPU 用於完整 Agent 推理與延遲測試；SFT 與 RL 建議使用多卡叢集（如 8×H20 或同等 A100/H100）。
- 強模型 API：用於生成 HSA-SFT 教師軌跡，例如 DeepSeek-V4-flash 等級模型，需評估成本與延遲。
- 推理最佳化：需支援 MTP（Multi-Token Prediction）或類似推測解碼技術，以達成 P50 3.4 秒、P95 8.1 秒的延遲目標。

**技能與團隊**
- LLM 微調與 RL 工程師：熟悉 SFT、PPO/DPO/GRPO 等 RL 演算法、工具呼叫格式。
- 領域專家：能定義 Skills、Hooks 與業務規則，並參與 Harness Evolution 的診斷-編輯-評估循環。
- 評測工程師：能設計 Live-Stream QA、Harness-Variant QA、IFEval 等互補評測集，並建立人機校準流程。
- MLOps/後端工程師：負責低延遲服務、A/B 測試、線上監控與 Harness 版本管理。

### 實作步驟建議

1. **設計可演化 Harness 架構**
   將業務邏輯拆分為四個獨立模組：Skills（回覆規則與行銷策略）、Hooks（驗證邏輯）、System Prompt Pipeline（動態指令）、Tool Registry（工具 schema）。確保每個模組可獨立版本化與熱更新，並定義模組間介面與資料流。

2. **建立生產級模擬器與評測集**
   建構能模擬真實直播間互動的環境，包含觀眾問題生成、商品後設資料、即時狀態與工具回傳。同步建立四類評測集：直播問答品質、Harness 變體問答、工具與提示詞穩健性、通用指令遵循（IFEval）。

3. **執行 HSA-SFT**
   使用強模型在經 HSA 增強的多樣 Harness 環境中生成高品質軌跡。HSA 需對 Skill 識別碼與內容、tool schema、prompt 結構、Hook 函數進行任務保留變換。將過濾後的軌跡用於監督式微調，讓緊湊模型學習推理與工具使用。

4. **執行 General On-Policy Distillation**
   在通用領域資料上，讓模型從基座模型蒸餾，修復 SFT 階段損失的通用指令遵循與泛化能力。此步驟對避免 IFEval 分數衰退至關重要。

5. **執行 HSA-RL**
   在生產模擬器中，以 HSA 多樣 Harness 環境進行強化學習。獎勵函數需同時考量回覆正確性、工具呼叫準確度、格式遵循、延遲與業務目標（如轉換率）。建議從小規模實驗開始，監控獎勵駭入與訓練不穩定。

6. **延遲最佳化與部署**
   在單張 NVIDIA H20 上進行完整 Agent 重播，測量 P50/P95 延遲。導入 MTP、批次推理、KV-cache 管理等技術。確保工具呼叫與後端 API 延遲在預算內。

7. **線上 A/B 測試與持續監控**
   將模型部署至小流量，對比 GMV、商品頁瀏覽量、觀眾停留時間與人工偏好。建立 Harness 變更後的自動迴歸測試，並持續收集線上軌跡用於下一輪訓練。

---

### 潛在風險與注意事項

- **表面形式過擬合**：若僅用固定 Harness 做 SFT，模型會記憶特定 skill 名稱、tool 名稱與 prompt 模板，導致 Harness 一更新就失效。務必透過 HSA 在訓練時引入多樣 Harness 狀態。
- **延遲與品質權衡**：強大零樣本模型雖準確但延遲過高（如 DeepSeek-V4-flash 中位數延遲超過 11 秒）。緊湊模型需經過完整 HAT 訓練才能彌補能力差距，不可直接上線。
- **獎勵駭入與 RL 不穩定**：HSA-RL 可能學到鑽獎勵函數漏洞的行為，例如過度呼叫工具或產生虛假資訊。建議結合人工審核軌跡、限制工具呼叫次數、並使用多維度獎勵。
- **Harness 版本相容性**：Skills、Hooks、prompts、tools 獨立更新可能產生組合爆炸。需建立版本矩陣測試與回滾機制，確保新舊配置組合不會造成執行錯誤。
- **幻覺與事實正確性**：直播內容公開播出，幻覺風險極高。Hooks 應作為最後一道驗證閘門，並結合 RAG 或即時工具查詢，避免模型憑空生成商品資訊。
- **評測器校準偏差**：Agent-as-a-Judge 若未經人工標註校準，可能與真實用戶偏好脫節。建議定期抽樣人工複審，並將評測器分數與線上指標連動分析。

### 與其他技術的整合建議

- **RAG 與領域知識庫**：將商品規格、活動規則、合規文件以向量資料庫或結構化知識圖譜形式接入 Tool Registry，讓模型透過工具查詢取得最新資訊，而非依賴參數記憶。
- **TTS 與數位人渲染管線**：將 Agent 輸出文字同步送至 TTS 與音訊驅動的數位人生成模型。需預留緩衝與串流機制，確保音畫同步與低延遲播出。
- **即時資料管線**：整合直播間即時評論、商品庫存、價格、訂單狀態等串流資料，作為 Agent 輸入上下文。建議使用訊息佇列與快取層降低資料取得延遲。
- **現有客服/CRM 系統**：將 Harness 的 Tool Registry 對接企業現有 API，例如會員查詢、訂單追蹤、工單系統，讓數位人代理成為既有服務的前端入口。
- **模型路由與 fallback 機制**：對於高風險或複雜問題，可設計路由將請求轉給更強大但較慢的模型，或轉接真人客服。緊湊模型處理常規問題，強模型處理邊角案例。
- **CI/CD for Harness Evolution**：將診斷-編輯-評估循環納入版本控制與自動化測試，讓業務團隊能像部署程式碼一樣部署 Harness 更新，並自動觸發迴歸測試。

---

### 給不同背景讀者的閱讀建議

**給初學者**：本文圍繞「如何讓一個小型 AI 模型聽懂不斷變化的業務規則」展開。建議先理解直播電商數位人的基本流程（觀眾提問 → AI 思考 → 回覆與工具動作 → 播出），再聚焦「可演化 Harness」與「Harness-State Augmentation」這兩個核心概念，暫時略過 RL 與蒸餾的技術細節。

**給 AI 工程師**：重點關注 HAT 的三階段訓練管線：HSA-SFT、General OPD、HSA-RL，以及它們如何分別解決工具學習、通用能力退化與 Harness 穩健性問題。建議仔細研究 HSA 的具體變換設計與生產模擬器的建構方式，並評估自身場景的延遲最佳化需求。

**給研究人員**：本文提出了一個值得深入探討的訓練問題——策略模型需在權重凍結的前提下適應動態執行環境。可進一步研究 HSA 的理論基礎（例如何種變換能真正保留任務語意）、RL 在動態 Harness 下的收斂性，以及 Agent-as-a-Judge 在開放式對話中的校準極限。

**給產品經理**：請將本文視為一套「業務敏捷性」方案：它讓營運/法務團隊能在數小時內更新回覆策略，而無需等待數週的模型重訓練。建議關注線上 A/B 測試結果（GMV、商品頁瀏覽量）與延遲指標，並思考如何將 Harness Evolution 流程融入現有的產品迭代節奏。
