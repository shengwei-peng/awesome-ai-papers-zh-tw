# OmniHarness：透過符號策略學習駕馭可泛化視覺生成

## ⚡ TL;DR

現有視覺生成方法難以跨任務泛化、缺乏即時反思，且僅在被動回應需求時才學習。
提出 OmniHarness，將驗證執行抽象為可重用符號策略，並以自主探索與執行驗證持續精進。
於多項基準測試表現優異，ComfyBench 創意任務解決率達 95%，超越最強基線 27.5%。

## 摘要翻譯

統一多模態大型語言模型（Unified Multimodal Large Language Models, MLLMs）與多智慧體系統（Multi-Agent Systems, MAS）已推動視覺生成（Visual Generation）的發展。然而，仍存在三項限制：（1）現有方法通常蒸餾（Distillation）任務特定經驗，泛化能力有限；（2）反思（Reflection）往往延後到任務完成後才進行；（3）知識往往僅在被動回應下游任務需求（Downstream Task Demands）時才獲取。為了解決這些限制，我們提出 OmniHarness，一個透過符號策略學習（Symbolic Policy Learning）實現可泛化視覺生成（Generalizable Visual Generation）的控制架構（Harness）。OmniHarness 將已驗證的執行抽象化為視覺生成任務家族（Task Families）的符號策略（Symbolic Policies），捕捉共享程序（Shared Procedures）與適用條件（Applicability Conditions），同時移除實例特定輸入（Instance-Specific Inputs）。此控制架構會針對新任務對這些策略進行工作流程實例化（Workflow Instantiation）、策略適應（Policy Adaptation）與策略組合（Policy Composition）。執行中驗證（Intermediate Verification）會引導精煉與失敗恢復（Failure Recovery）。透過自主探索（Self-Directed Inquiry），OmniHarness 在下游目標明確之前，即在其能力極限（Capability Limits）附近自主生成並執行練習任務（Practice Tasks）。執行回饋（Execution Feedback）持續精煉策略，同時模型參數維持凍結（Frozen Model Parameters）。在橫跨六項基準測試、三個 MLLM 骨幹模型（Backbone Models）與三個視覺智慧體框架（Visual Agent Frameworks）的實驗中，OmniHarness 展現出優異效能與持續能力擴展（Continual Capability Expansion）。在 ComfyBench 的 Creative（創意）任務上，OmniHarness 達到 95.0% 的解決率（Resolve Rate），超越最強基線 27.5 個百分點。凍結策略快照（Frozen Policy Snapshots）可透過隨插即用複用（Plug-and-Play Reuse），提升現有視覺智慧體系統的效能。

### 核心貢獻（3～5點）
- 提出符號策略學習（Symbolic Policy Learning）機制，將已驗證執行抽象為可跨任務重複使用的符號策略（Symbolic Policies），以提升視覺生成的可泛化性。
- 透過執行中驗證（Intermediate Verification）與失敗恢復（Failure Recovery），在任務執行過程中即時修正錯誤，而非僅在任務完成後才進行反思。
- 引入自主探索（Self-Directed Inquiry）機制，使智慧體能在下游目標明確前，主動於能力極限（Capability Limits）附近生成並執行練習任務（Practice Tasks）。
- 以執行回饋（Execution Feedback）持續精煉策略，同時維持模型參數凍結（Frozen Model Parameters），並支援凍結策略快照（Frozen Policy Snapshots）的隨插即用複用（Plug-and-Play Reuse）。
- 在 ComfyBench 創意任務上達到 95.0% 的解決率（Resolve Rate），顯著超越現有基線，並展現持續能力擴展（Continual Capability Expansion）。

### 適合對象
本論文適合對視覺生成（Visual Generation）、統一多模態大型語言模型（MLLMs）、多智慧體系統（MAS）、視覺智慧體框架（Visual Agent Frameworks）、可泛化策略學習，以及自我演化智慧體（Self-Evolving Agents）有興趣的研究人員與工程師。特別適合希望提升視覺生成系統跨任務遷移能力、執行中自我修正能力，以及希望將學習到的策略以凍結快照形式隨插即用整合至現有系統的開發者。

## 深度分析

#### 方法論解析

OmniHarness 的核心方法論可視為一種「控制架構（harness）驅動的符號策略學習（symbolic policy learning）」。它並非直接微調統一多模態大型語言模型（unified multimodal large language models, MLLMs）的參數，而是在模型參數凍結（frozen model parameters）的前提下，透過自主探索（self-directed inquiry）與執行回饋（execution feedback）持續累積可重複使用的符號策略（symbolic policies）。整體架構圍繞三大機制：自主探索、回饋引導執行、符號策略庫演化。

**1. 符號策略（symbolic policies）的抽象與表示**

傳統多智慧體系統（multi-agent systems, MAS）或視覺生成流程往往將成功執行保留為特定實例的工作紀錄，難以跨任務遷移（cross-task transfer）。OmniHarness 則將驗證過的執行經驗蒸餾（distillation）成符號策略，這些策略是針對「任務家族（task families）」而非單一案例的抽象工作流程模板。具體而言，符號策略會保留跨實例共享的程序（shared procedures）與適用條件（applicability conditions），並去除實例特定輸入（instance-specific inputs）。這樣的設計讓策略具備「授人以漁」的特性：當面對新任務時，可進行工作流程實例化（workflow instantiation）、策略適應（policy adaptation）與策略組合（policy composition），而非從頭規劃。

**2. 自主探索（self-directed inquiry）**

受王陽明「格物致知」思想啟發，OmniHarness 在下游任務需求（downstream task demands）尚未出現前，就主動生成並執行練習任務（practice tasks）。在每一次迭代 t，命題器（proposer）根據能力空間（capability space）G、場景脈絡 c_t 與策略庫狀態 S_t = (L_t, F_t) 產生候選任務 τ。此處 L_t 為工作流程庫（workflow library），儲存符號策略；F_t 為失敗庫（failure library），記錄失敗證據與修正策略。透過這種方式，系統能主動探測自身能力極限（capability limits），在真正需要執行下游任務前就先累積經驗，彌補反應式學習（reactive learning）的不足。

**3. 回饋引導執行（feedback-guided execution）**

執行過程中，OmniHarness 不會等到任務完成才進行事後反思（hindsight），而是對中間輸出進行執行中驗證（intermediate verification）。一旦發現錯誤，系統會啟動失敗恢復（failure recovery）機制，即時修復失敗步驟，避免錯誤傳播。這種「邊做邊驗證」的設計對視覺生成特別重要，因為生成流程中的中間節點（如遮罩、姿態圖、風格轉換結果）若出現偏差，後續節點往往會放大錯誤。

**4. 策略庫的持續演化**

執行回饋會持續精煉符號策略，而底層 MLLM 的參數保持凍結。這意味著 OmniHarness 將「知識」儲存在符號層級的策略庫中，而非模型權重裡。這帶來幾項優勢：可解釋性較高、可離線儲存為凍結策略快照（frozen policy snapshots）、並能隨插即用複用（plug-and-play reuse）於不同的視覺智慧體框架（visual agent frameworks）。同時，由於不依賴梯度更新，系統可以在不重新訓練骨幹模型（backbone models）的情況下持續擴展能力（continual capability expansion）。

#### 實驗數據解讀

儘管提供的上下文未列出完整實驗表格，但從摘要與引言可歸納出以下實驗設計與結果重點：

**1. 評估規模與多樣性**

實驗橫跨六個基準測試（six benchmarks）、三個 MLLM 骨幹模型（three MLLM backbones）與三個視覺智慧體框架（three visual agent frameworks）。這樣的設計意在驗證 OmniHarness 的泛化性：不僅對單一模型或單一框架有效，而是能在不同後端與不同代理生態間遷移。

**2. 核心指標：解決率（resolve rate）**

在 ComfyBench 的 Creative tasks 上，OmniHarness 達到 95.0% 的解決率（resolve rate），相較最強基線提升 27.5 個百分點。這是一個非常顯著的差距，顯示符號策略學習與執行中驗證對複雜創意視覺生成任務的幫助極大。ComfyBench 本身評估的是自主建構 ComfyUI 工作流程（ComfyUI workflows）的能力，因此高解決率代表系統能穩定地將高層任務描述轉換為可執行、可驗證的節點流程。

**3. 持續能力擴展（continual capability expansion）**

實驗強調「持續能力擴展」，意味著隨著自主探索與執行回饋的累積，策略庫會不斷成長，系統能處理的任務家族範圍也隨之擴大。這與傳統一次性訓練或固定提示工程（prompt optimization）形成對比：後者的能力上限在部署時即被鎖定，而 OmniHarness 可透過持續執行與反思突破原有邊界。

**4. 跨框架遷移與凍結策略快照**

實驗還驗證了凍結策略快照（frozen policy snapshots）可透過隨插即用複用（plug-and-play reuse）提升現有視覺智慧體系統。這表示學到的符號策略不僅服務於 OmniHarness 本身，也能作為外部知識模組，被其他遵循不同通訊拓撲（fixed communication topologies）或不同工具呼叫慣例的代理框架所採用。

**5. 數據解讀的注意事項**

雖然 95.0% 的解決率非常亮眼，但讀者仍應留意：ComfyBench Creative tasks 的難度分布、基線是否具備同等的工具使用（tool use）與驗證機制、以及自主探索階段消耗了多少額外計算資源。若基線是純粹的端對端（end-to-end）MLLM 或固定手動工作流程（manual workflows），則 27.5 個百分點的提升可歸因於「符號化 + 驗證 + 自主練習」的綜合效應；但若比較對象已具備部分規劃能力，則提升更顯得來自策略抽象與中間驗證的獨特價值。

#### 與現有研究的比較

**1. 相對於端對端統一 MLLMs**

統一多模態大型語言模型（unified MLLMs）將視覺感知（visual perception）、多模態推理（multimodal reasoning）與圖像生成整合於單一模型，具備快速直覺（fast intuition）般的生成速度。然而，它們通常缺乏深思推理（deliberate reasoning）、明確的自我修正（self-correction）與持續知識累積（persistent knowledge accumulation）。OmniHarness 不取代這些模型，而是將其作為骨幹，並在外層加入可驗證、可演化的符號策略層，彌補了端對端系統在複雜推理（complex reasoning）與錯誤恢復上的不足。

**2. 相對於現有多智慧體系統（MAS）**

現有 MAS 雖然引入協作推理與記憶，但許多系統仍依賴手動定義的 ComfyUI 工作流程或固定通訊拓撲（fixed communication topologies）。即使近期研究自動化提示優化（prompt optimization）或拓撲優化（topology optimization），協調方式仍難以根據協作經驗（collaboration experience）動態調整。OmniHarness 的關鍵差異在於：它將成功執行轉化為可複用技能（reusable skills）與符號策略，而非僅保存個案解決方案，從而實現真正的跨任務遷移。

**3. 相對於 ComfyBench 上的自主工作流程建構方法**

ComfyBench 相關研究聚焦於自動規劃與回饋建構工作流程。OmniHarness 進一步引入「執行中驗證」與「失敗恢復」，避免錯誤在節點間傳播；同時透過自主探索在任務來臨前預先累積經驗。這兩點都是傳統「接到任務才規劃」方法所缺乏的。

**4. 相對於符號概念學習方法**

近期有研究從傳入任務中學習可重複使用的符號概念（symbolic concepts）。OmniHarness 的符號策略更強調「程序性知識」——不僅知道「什麼」是有效的，還知道「在何種條件下」以及「如何依序執行」。此外，透過失敗庫（failure library）記錄負面經驗，策略學習同時納入正反兩面證據，提升穩健性。

**5. 主要限制**

首先，符號策略的抽象能力受限於底層 MLLM 的推理與歸納能力；若任務過於新穎或偏離既有任務家族，策略可能難以即時組合。其次，自主探索雖能擴展能力，但也帶來計算成本與潛在的安全風險——系統主動生成的練習任務可能產生不當內容或無意義的資源消耗。第三，執行中驗證需要可靠的驗證器（critic），若驗證本身出錯，錯誤恢復可能適得其反。最後，策略庫規模持續增長後，如何高效檢索、合併相似策略、避免冗餘，將是實際部署的挑戰。

#### 可重現性評估

**1. 程式碼與資料開放性**

從提供的上下文來看，論文並未明確說明是否釋出原始碼、資料集或模型權重。由於 OmniHarness 依賴現成的 MLLM 骨幹與 ComfyUI 等外部工具，理論上可透過公開 API 與開源框架重建，但核心細節——例如命題器（proposer）的提示設計、策略抽象演算法、失敗庫的更新規則、中間驗證的具體標準——若未公開，將大幅影響可重現性。

**2. 依賴元件的可取得性**

實驗使用的 ComfyBench、ComfyUI 與多個視覺智慧體框架多為公開資源，但部分 MLLM 骨幹可能僅提供 API 或需申請權限。若論文未提供策略快照（policy snapshots）的下載，則其他研究者無法直接驗證「隨插即用複用（plug-and-play reuse）」的宣稱。

**3. 再現所需資源**

自主探索階段需要大量生成與驗證呼叫，重現完整實驗可能涉及可觀的 GPU 時數與 API 費用。論文若未詳細報告探索次數、失敗率與總計算預算，將難以評估結果的穩定性與成本效益。

**4. 建議**

為提升可重現性，作者應考慮釋出：（1）OmniHarness 的完整實作程式碼；（2）學習到的凍結策略快照（frozen policy snapshots）；（3）自主探索階段使用的任務生成配置與種子；（4）各基準測試的詳細評估腳本與超參數。這將有助於社群驗證 95.0% 解決率的穩健性，並促進後續研究在該框架上擴展。

#### 未來研究方向

**1. 多模態與多領域擴展**

目前 OmniHarness 聚焦於視覺生成，但未來可將符號策略學習擴展至影片生成、3D 資產生成、音訊生成，甚至機器人操作等需要複雜工具鏈的領域。關鍵挑戰在於設計適用於不同模態的中間驗證機制。

**2. 階層式符號策略（hierarchical symbolic policies）**

隨著策略庫成長，可引入階層式結構：高階策略描述任務分解原則，低階策略處理具體工具呼叫。這將提升組合效率，並讓系統能處理更長、更複雜的生成流程。

**3. 與人類回饋或偏好對齊**

自主探索目前主要依賴執行回饋，未來可整合人類回饋強化學習（RLHF）或偏好學習，讓策略不僅「成功執行」，更符合美學、風格或倫理偏好。

**4. 更智慧的探索策略**

現有自主探索可能在能力邊界附近產生大量無效任務。未來可研究基於不確定性估計或好奇心的探索策略，以更少計算成本獲得更高品質的練習經驗。

**5. 參數化與符號化學習的混合**

雖然凍結模型參數有助於穩定與可解釋，但某些複雜模式可能難以完全符號化。未來可探索「輕量參數更新 + 符號策略庫」的混合架構，在保持可解釋性的同時提升對新穎任務的適應力。

**6. 安全性與可控性**

自主生成練習任務可能觸及版權、隱私或不當內容風險。未來需要建立更嚴格的內容過濾、價值對齊與資源監控機制，確保自我演化智慧體（self-evolving agents）在開放環境中的安全部署。

**7. 跨框架策略標準化**

為了讓凍結策略快照真正實現跨視覺智慧體框架的隨插即用複用，社群可發展標準化的策略描述語言或中介表示，降低不同工具呼叫慣例之間的轉換成本。

## 論文問答

**Q1：現有視覺生成方法存在哪些主要限制？**
A：現有方法通常只針對單一任務蒸餾經驗，導致策略難以跨任務遷移；反思往往等到任務完成後才進行，使得中間錯誤會持續傳播而無法及時修正；此外，知識多半是被動地在下游需求出現後才學習，無法在面對新任務前主動補足能力缺口。這三項限制共同限制了視覺生成系統的泛化性、可靠性與持續成長。

**Q2：為何保留成功執行紀錄不一定能產生可複用技能？**
A：單純記錄成功案例往往只保存了特定輸入與對應解決方案，卻未抽取出跨案例共享的程序與適用條件；這就像「給魚而非授漁」，系統能重現舊案例，但遇到新情境時缺乏可遷移的原則。因此，必須將執行經驗抽象為符號策略，才能在不同任務間建立可重複使用的知識。

**Q3：學習可泛化的符號策略為何比記住實例特定解更重要？**
A：視覺生成任務家族內部通常共享相似的程序與前置條件，符號策略能去除實例特定輸入，保留通用流程與適用條件；這使得系統面對新任務時，可以根據條件實例化、調整並組合策略，而不必從頭學習。長期來看，這種知識累積方式能持續擴展能力邊界，並支援隨插即用的跨框架複用。

**Q4：OmniHarness 的符號策略學習是什麼，與傳統任務特定經驗蒸餾有何不同？**
A：OmniHarness 將經過驗證的執行過程蒸餾成符號化的工作流程模板，每個模板對應一個視覺生成任務家族，並明確記錄其適用條件與共享程序；與傳統方法不同，這些策略不綁定特定輸入，因此能跨實例重複使用。透過不斷的執行回饋，策略庫會持續精煉，而底層模型參數保持凍結，實現知識層面的自我演化。

**Q5：執行中驗證與失敗恢復如何提升 OmniHarness 的可靠性？**
A：OmniHarness 在執行過程中會驗證中間產出，一旦發現偏差或錯誤，便立即觸發工作流程的調整與修復，而非等到任務結束後才回顧；這種即時回饋能有效限制錯誤傳播，避免前期小錯演變成最終失敗。相較於僅做事後反思的系統，中間驗證讓智慧體在「行動中反思」，顯著提升複雜視覺生成任務的成功率。

**Q6：自主探索在 OmniHarness 中扮演什麼角色？**
A：自主探索讓 OmniHarness 在下游目標尚未指定前，主動生成並執行接近其能力極限的練習任務；透過這些自我導向的練習，系統能探索能力邊界、收集失敗與成功案例，並將其轉化為符號策略與修正策略。這種「格物致知」式的學習方式，使系統在真正面對應用需求前，就已具備更完整且可遷移的知識基礎。

**Q7：OmniHarness 的實驗設置涵蓋哪些層面？**
A：實驗橫跨六個視覺生成基準測試、三種不同的統一多模態大型語言模型骨幹，以及三種視覺智慧體框架；這樣的設計能同時評估策略學習的泛化性、跨模型穩定性，以及在不同代理系統間的遷移能力。透過與現有視覺代理系統的整合，研究進一步驗證了凍結策略快照的隨插即用複用價值。

**Q8：OmniHarness 在 ComfyBench Creative 任務上的關鍵結果是什麼？**
A：在 ComfyBench 的 Creative 任務上，OmniHarness 達到 95.0% 的解決率，較最強基線高出 27.5 個百分點；這顯示符號策略學習結合執行中驗證與自主探索，能顯著提升複雜創意視覺生成任務的成功率。如此大幅度的領先也說明，抽象化共享程序比單純針對個別任務調整提示或工作流程更具優勢。

**Q9：實驗如何顯示 OmniHarness 的持續能力擴展與遷移性？**
A：實驗結果顯示，隨著執行回饋不斷累積，OmniHarness 的策略庫持續精煉，系統能力也隨之擴展，而整個過程無需更新模型參數。此外，凍結的策略快照可以直接套用到現有視覺智慧體框架中，透過隨插即用複用提升其表現。這證明了符號策略不僅能在單一系統內持續演化，也能作為可攜式知識資產跨框架遷移。

**Q10：OmniHarness 如何整合到現有視覺智慧體框架？**
A：OmniHarness 提供凍結的策略快照，這些快照以符號化工作流程與適用條件的形式存在，可直接被其他視覺智慧體載入並用於新任務。由於模型參數保持凍結，現有框架無需重新訓練或微調即可受益。這種隨插即用複用方式降低了整合成本，也讓不同系統能共享從大量執行回饋中提煉出的可靠知識。

**Q11：哪些實際應用場景最能受惠於 OmniHarness 的自主探索與可複用策略？**
A：需要頻繁處理多樣化視覺生成需求的場景，例如電商廣告圖、遊戲資產、媒體內容創作與自動化設計流程，都能受惠於可泛化的符號策略。自主探索讓系統在正式任務到來前先累積經驗，縮短上線後的試錯時間。同時，執行中驗證與失敗恢復機制能確保高風險或高成本的視覺產出維持穩定品質。

**Q12：這項研究對未來視覺生成 AI 的發展有何影響？**
A：OmniHarness 將焦點從單一模型能力轉向可累積、可驗證、可遷移的符號知識，為視覺生成系統提供了一種類似「學習如何學習」的架構。這可能促使未來產品更重視智慧體層次的協調、記憶與自我修正，而非僅追求更大的端對端模型。長遠來看，這種控制架構導向的設計有助於建立更安全、可解釋且持續進化的視覺生成服務。

**Q13：OmniHarness 在開放或極度複雜的視覺領域可能面臨哪些限制？**
A：符號策略的有效性取決於能否從執行經驗中穩定抽取出共享程序與適用條件，若任務變異過大或規則難以符號化，策略庫可能變得龐大且難以管理。此外，當視覺品質的評估標準高度主觀或需要細粒度美學判斷時，中間驗證可能難以設計可靠的檢查點。這些情況下，系統仍可能需要人類回饋或更強大的感知模型來輔助策略學習。

**Q14：在哪些失敗案例中，中間驗證與失敗恢復仍可能不足？**
A：若錯誤發生在策略適用條件本身被誤判，例如系統將不適用的符號策略套用到新任務，後續的中間驗證可能只會在錯誤框架內打轉。此外，當多個步驟的錯誤相互耦合，或需要創造性跳脫既有程序才能解決時，單純的局部修復可能無法找到全局最優解。這類案例凸顯了持續擴充失敗庫與發展高階後設推理能力的重要性。

**Q15：OmniHarness 未來可以朝哪些方向擴展？**
A：未來可結合人類在迴路回饋，讓策略學習在開放式創意領域獲得更可靠的美學與語意指導。也可將符號策略學習擴展到影片、3D 生成等多模態任務，並探索線上適應機制以因應快速變化的需求。此外，發展更強大的策略組合與規劃演算法，將有助於處理更長、更複雜的工作流程，並進一步提升跨任務遷移的效率。

## 實務應用指南

### 適用場景

1. **電商大量商品情境圖生成**  
   針對同一商品家族（例如「服飾平拍轉換為模特兒穿搭圖」），OmniHarness 可學習可重複使用的符號策略，自動根據不同 SKU 實例化生成流程，並在執行中驗證構圖、文字與品牌風格，減少人工逐案調整。

2. **行銷創意素材的 A/B 測試自動化**  
   廣告團隊可將「節慶主題海報」、「社群貼文配圖」等任務家族抽象為符號策略，透過自主探索產生多種風格變體，並利用執行回饋持續擴充策略庫，加速創意迭代。

3. **遊戲與影視前期資產快速原型**  
   在概念美術階段，OmniHarness 可學習「角色設計」、「場景氛圍圖」、「道具生成」等任務家族的共享程序，並組合多個策略生成複雜概念圖，同時透過中間驗證修正結構錯誤。

4. **建築與室內設計視覺化**  
   將「空間配置渲染」、「風格遷移」、「材質替換」等流程抽象為符號策略，設計師只需輸入空間描述與參考圖，系統即可實例化並調整 ComfyUI 工作流程，並在渲染過程中檢查透視與比例。

5. **自動化社群媒體內容生產**  
   針對每日發文需求，OmniHarness 可在無明確下游任務前透過自主探索練習不同排版與主題，累積可複用策略；接到正式需求後即時組合策略並生成符合品牌規範的圖文素材。

### 實作步驟建議

1. **定義任務家族與成功準則**  
   將業務需求拆解為具共享程序的任務家族，例如「產品去背 + 情境合成」，並明確適用條件與驗證指標（解析度、風格一致性、文字正確性）。

2. **收集並整理已驗證執行紀錄**  
   從現有成功案例與失敗案例中萃取出工作流程、輸入參數與修正動作，作為符號策略學習的種子資料。

3. **蒸餾初始符號策略庫**  
   利用 MLLM 將已驗證執行抽象化，移除實例特定輸入，保留共享程序與適用條件，建立可重複使用的工作流程模板。

4. **建立失敗證據庫與修復規則**  
   記錄常見失敗模式（如手部畸形、文字亂碼、風格偏移）及其對應的修正策略，供執行中驗證與失敗恢復使用。

5. **啟動自主探索迴圈**  
   在尚無明確下游任務前，讓系統根據能力空間主動生成練習任務，並在能力極限附近執行，以擴充策略庫與失敗庫。

6. **部署執行中驗證與回饋機制**  
   每個中間步驟（如去背、構圖、風格轉換）都設定輕量驗證器，發現錯誤即時觸發策略調整或重試，避免錯誤傳播。

7. **凍結策略快照並隨插即用**  
   當策略庫達到穩定品質後，產生凍結策略快照，匯出為標準格式供現有視覺智慧體框架或 ComfyUI 工作流程直接載入。

8. **持續監控與週期性擴充**  
   在生產環境中收集執行回饋，定期重新執行自主探索，更新策略庫；模型參數保持凍結，僅迭代符號策略。

### 潛在風險與注意事項

| 風險 | 說明 | 緩解方式 |
|---|---|---|
| **策略過度擬合特定任務** | 符號策略若未充分抽象，會只記住個案解法而無法跨任務遷移。 | 嚴格區分共享程序與實例特定輸入，並在新任務家族上進行遷移測試。 |
| **策略庫膨脹** | 長期自主探索可能產生大量重複或低價值策略，降低檢索效率。 | 定期評估策略覆蓋率與使用率，合併相似策略並淘汰低頻策略。 |
| **執行中驗證成本過高** | 每步驗證與重試會增加延遲與運算開銷。 | 採用分層驗證：輕量規則優先，必要時才呼叫 MLLM 或人工檢核。 |
| **自主探索產生不當內容** | 系統可能生成違反版權、隱私或安全規範的練習任務。 | 設定內容過濾器、禁止清單與人工審查閘門，並限制練習任務的輸入範圍。 |
| **骨幹模型能力天花板** | MLLM 對複雜視覺推理或精細編輯的理解不足會限制策略品質。 | 結合領域專用驗證器與人工回饋，必要時更換或微調骨幹模型。 |
| **智慧財產權爭議** | 生成圖像可能涉及訓練資料或參考風格的版權風險。 | 建立明確的參考圖授權審查流程，並記錄生成過程以供追溯。 |

### 與其他技術的整合建議

- **現有視覺智慧體框架**：將 OmniHarness 的凍結策略快照以 API 或插件形式整合至 AutoGen、CrewAI、LangGraph 等框架，讓現有代理在規劃階段即可查詢並實例化符號策略。
- **ComfyUI 生態**：把學習到的策略輸出為 ComfyUI 工作流程模板，並與現有節點庫、自訂節點與模型管理工具（如 ComfyUI-Manager）共用。
- **MLOps / CI/CD**：將策略庫版本化，納入持續整合流程，每次更新後自動執行基準測試（如 ComfyBench 創意任務），確保凍結快照品質穩定。
- **數位資產管理（DAM）**：把生成結果、策略版本與驗證紀錄寫入 DAM，讓行銷與設計團隊可追溯素材來源並進行人工回饋。
- **統一多模態大型語言模型**：OmniHarness 可搭配 GPT-4V、Qwen-VL 等統一多模態大型語言模型作為骨幹，同時利用其視覺理解能力進行中間驗證與策略調整。

**研究人員**：本文的核心貢獻在於將視覺生成經驗提升為跨任務遷移的符號策略，並結合王陽明「格物致知」的自主探索概念；建議深入分析策略抽象化、適用條件推論與持續能力擴展的理論機制，並與現有提示優化、拓撲優化及可複用技能學習研究進行比較。
