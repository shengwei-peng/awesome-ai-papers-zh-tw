## ⚡ TL;DR

現有情境學習評估多聚焦文字，難以檢視多模態情境中證據定位、資訊應用與知識學習的失效環節。
本文提出CLBench-V，以三層能力階層整合公開與新建多模態任務，並以自動化流程降低建構成本。
在六個模型、3,443筆實例上，最佳分僅0.2847，顯示多模態情境學習仍遠未飽和且層級表現各異。

## 摘要翻譯

現實世界任務通常要求模型從任務特定情境（Task-specific Context）中學習，而非僅仰賴預訓練知識（Pre-trained Knowledge）。雖然近期研究將此能力稱為情境學習（Context Learning），但現有評估主要聚焦於文字情境。然而在許多實際場景中，待學習的情境是多模態的：科學發現透過圖表與表格傳達，財務指標散佈於經轉換的報告中，而空間決策則依賴地圖、場景或網頁。我們提出 CLBench-V，一個用於多模態情境學習（Multimodal Context Learning）的基準，透過將任務按三個能力層級——情境接地（Context Grounding）、新資訊應用（New Information Application）與新知識學習（New Knowledge Learning）——組織，以解決定位情境運用在何處失效的困難。CLBench-V 結合經轉換的公開基準與新建構的資料集，涵蓋科學、財務、長文件理解（Long-document Understanding）、空間推理（Spatial Reasoning）與網頁視覺問答（Web-based Visual Question Answering）等領域。為降低建構領域特定情境學習任務的成本，我們進一步對新建構的資料集採用自動化建構（Automated Construction）與篩選程序（Filtering Procedure）。在 3,443 個實例與六個近期的多模態模型中，最佳整體分數僅為 0.2847，顯示多模態情境學習仍遠未飽和。此外，InternVL3.5-30B-A3B 在情境接地與新知識學習上表現最佳，而 Qwen3.5-Plus 在新資訊應用上表現最佳。我們進一步分析評判可靠性（Judge Reliability）、情境長度（Context Length）、圖片數量（Image Count）以及具代表性的失敗案例（Failure Case）。程式碼可於 https://github.com/IamLihua/CLBench-V 取得。

### 核心貢獻（3～5點）
- 提出 CLBench-V，一個聚焦於多模態情境學習的綜合性基準，涵蓋科學、財務、長文件理解、空間推理與網頁視覺問答等多元領域。
- 建立三層能力架構（L0–L2）：情境接地、新資訊應用與新知識學習，以診斷式評估定位模型在多模態情境運用上的失效環節。
- 設計自動化建構與篩選程序，降低領域特定情境學習任務的建構成本，並確保資料品質。
- 對六個近期多模態模型進行大規模評估（3,443 個實例），揭示多模態情境學習仍遠未飽和，並比較不同模型的優勢面向。
- 深入分析評判可靠性、情境長度、圖片數量與代表性失敗案例，為後續研究提供具體改進方向。

## 深度分析

#### 方法論解析

CLBench-V 的核心貢獻在於將「情境學習（Context Learning）」從純文字場景延伸至多模態（Multimodal）場景，並提出一個可診斷錯誤來源的三層能力層級（Capability Hierarchy）。以下從四個面向剖析其方法設計。

**1. 三層能力層級：從定位證據到學習新知識**

作者將多模態情境學習拆解為：

- **L0 Context Grounding（情境接地 / 證據定位）**：模型必須在圖表、表格、版面配置（Layout）等視覺格式（Visual Format）中，正確定位並綁定相關證據（Evidence）。這一層對應的失敗模式包括遺漏證據（Missed Evidence）與圖表錯誤綁定（Wrong Image/Table Binding）。
- **L1 New Information Application（新資訊應用）**：模型在已經取得證據後，能否正確使用情境中提供的新事實、數值或案例進行推理。常見失敗是資訊誤用（Information Misuse），例如引用錯誤數值，或讓過時先驗覆蓋情境（Outdated Prior Overrides Context）。
- **L2 New Knowledge Learning（新知識學習）**：模型需要從情境中學習新的規則、發現或任務語義，而非僅靠預訓練知識（Pre-trained Knowledge）回答。失敗模式包括忽略新規則/發現（Ignore New Rule/Finding）與無依據的額外主張（Unsupported Extra Claim）。

這個層級設計的價值在於把「模型表現差」這個籠統觀察，轉換成可定位的診斷訊號：是找不到證據、找到卻用錯，還是無法內化情境定義的知識。

## 論文問答

**Q1：CLBench-V 主要想解決什麼問題？為什麼多模態情境學習很重要？**  
A：現實任務常要求模型在推論時從任務特定情境學習，而非僅依賴預訓練知識；然而既有評測多聚焦文字情境，忽略了科學論文、財報、地圖、網頁等富含圖表與版面的多模態情境。CLBench-V 因此建立一套多模態情境學習基準，涵蓋科學、財金、長文件、空間推理與網頁視覺問答等領域，以衡量模型能否正確擷取並使用這些分散且視覺化的證據。這項工作的重要性在於，只有當模型能同時定位、理解並內化多模態情境中的資訊，它們才能在真實應用中可靠地輔助決策與知識獲取。

**Q2：現有的情境學習評測為什麼不足以應對多模態場景？**  
A：現有評測大多只處理文字情境，難以反映現實中證據分散於圖片、表格與版面配置的情況；此外，它們雖能顯示模型忽略或誤用情境，卻不易診斷究竟是哪一環節出錯。CLBench-V 透過三層能力層級，把失敗拆解為接地失敗、資訊誤用與知識學習失敗，讓研究者能精確定位模型表現退化的位置。同時，高品質的情境學習任務過去多靠昂貴人工標註，CLBench-V 也引入自動化建構與篩選程序來降低建置成本。

**Q3：模型能接收多模態輸入就足夠了嗎？為什麼？**  
A：僅僅接受圖文交錯輸入並不保證模型能可靠地學習情境，因為長情境容量與情境學習是兩回事；模型可能看得見長輸入，卻仍無法內化情境定義的規則或解決跨模態衝突。CLBench-V 的實驗顯示，六個近期多模態模型的最佳總分僅 0.2847，且不同模型在 L0、L1、L2 的表現差異顯著，例如 InternVL3.5-30B-A3B 在接地與新知識學習上較強，而 Qwen3.5-Plus 在新資訊應用上較強。這說明多模態情境學習仍遠未飽和，需要針對性地提升證據定位、資訊應用與知識獲取能力。

**Q4：CLBench-V 提出的三層能力層級是什麼？各自評測什麼能力？**  
A：CLBench-V 將多模態情境學習分為 L0 情境接地、L1 新資訊應用與 L2 新知識學習三個層級。L0 情境接地測試模型能否在多模態情境中定位、閱讀並結合相關證據，例如從圖表或表格中找到正確數值。L1 新資訊應用測試模型能否運用已具備的能力去處理新提供的事實、數值或案例，而不被過時的先驗知識覆蓋。L2 新知識學習則測試模型能否從情境本身學習新的規則、發現、任務語義或經驗結論，這要求模型真正內化情境定義的知識。

**Q5：CLBench-V 的核心方法與關鍵創新是什麼？**  
A：其核心方法是建立一個以三層能力層級為架構的統一評測框架，並結合轉換後的公開基準與自行建構的領域任務，涵蓋科學論文、財務報告、長文件、地圖路線、運動場景與網頁視覺問答。關鍵創新在於把「多模態情境學習」從單一準確率指標，轉化為可診斷的層級化能力評估，能區分模型是找不到證據、找到卻用錯，還是忽略情境定義的新知識。此外，為了降低領域任務的建置成本，作者設計自動化建構與篩選流程，大規模產生候選實例並保留任務專屬品質，使基準兼具規模與診斷價值。

**Q6：CLBench-V 如何將錯誤對應到具體的失敗模式？**  
A：三層能力層級各自對應典型的失敗模式：L0 情境接地的失敗表現為遺漏證據或圖表錯誤綁定，即模型未能正確定位並關聯多模態證據。L1 新資訊應用的失敗則是資訊誤用，例如引用錯誤數值，或讓過時的先驗知識凌駕於情境提供的新事實。L2 新知識學習的失敗包括忽略情境定義的新規則或發現，以及做出無依據的額外主張；透過這種對應，研究者可以判斷模型需要在哪一層能力上加強。

**Q7：實驗涵蓋哪些資料集、領域與規模？**  
A：CLBench-V 共包含 3,443 個實例，橫跨科學論文、財務報告、長文件理解、空間推理與網頁視覺問答等多個領域。其中部分任務來自轉換後的公開基準，另有一部分是作者針對最新醫學論文結論推論與財報 ROE 分析等新領域自行建構的資料集。這樣的組合既利用了現有資源的廣度，也補足了真實多模態情境中對專業領域、長文件與視覺版面理解的需求。

**Q8：主要實驗結果是什麼？哪個模型表現最好？**  
A：在六個近期多模態模型上，CLBench-V 的最佳總分僅為 0.2847，顯示多模態情境學習仍遠未達飽和。InternVL3.5-30B-A3B 在 L0 情境接地與 L2 新知識學習上表現最佳，顯示其在證據定位與學習情境定義規則方面較強。相對地，Qwen3.5-Plus 在 L1 新資訊應用上表現最佳，說明不同模型在接地、應用與知識獲取三個層級上的可靠性存在明顯差異，單一高分並不能代表全面的情境學習能力。

**Q9：作者進行了哪些額外的分析來深化理解？**  
A：除了層級化準確率比較，作者還評估了不同大型語言模型評判者的可靠性，以確保自動評分的穩定性與一致性。他們也分析情境長度、圖片數量、答案類型等因素對模型表現的影響，並展示具代表性的失敗案例。這些分析有助於理解模型在更長、更密集的視覺干擾情境下，是否仍能正確擷取證據、應用新資訊與學習新知識。

**Q10：多模態情境學習在哪些實際場景中特別重要？**  
A：在科學研究中，模型需要從論文的圖表與表格理解最新發現；在金融分析中，必須從財報的數字與版面擷取 ROE 等指標並進行推理。地圖與路線規劃、運動場景判讀以及網頁視覺問答等場景，也要求模型結合空間、版面與文字資訊做出決策。這些應用的共同點是：相關證據並非以純文字呈現，而是分散在多種視覺格式中，模型必須在推論時學習並使用這些情境特定資訊。

**Q11：若將這項技術落地為產品，需要考慮哪些問題？**  
A：產品化時必須確保模型能穩定地定位並綁定正確的圖片或表格，避免在長文件中遺漏關鍵證據。其次，當情境提供的新事實與模型預訓練知識衝突時，系統應優先採納情境資訊，防止過時先驗覆蓋正確答案。此外，產品還需要具備可解釋的失敗診斷機制，讓使用者知道答案是來自證據接地、數值應用還是情境規則學習，並在出現無依據主張時能及時警示。

**Q12：CLBench-V 對多模態模型研究領域可能帶來什麼影響？**  
A：CLBench-V 提供了一個診斷式的多模態情境學習基準，讓研究者能夠清楚區分模型在接地、應用與知識獲取上的強弱項。它揭示了即使具備長情境輸入能力的模型，也未必能真正從多模態情境學習，從而促使未來研究針對這些缺口設計更強的架構與訓練策略。長遠來看，這類基準有助於推動多模態模型在科學、金融與專業文件理解等真實應用中的可靠性與實用性。

**Q13：這項研究有哪些可能的限制？**  
A：目前實驗僅評估了六個近期多模態模型，樣本數與模型多樣性仍有擴充空間，未必能完全代表所有架構的表現。雖然作者採用自動化建構與篩選來降低成本，但自動產生的候選實例仍可能帶有雜訊，需要額外的品質控制與人工檢驗。此外，評分依賴大型語言模型評判者，其可靠性會受到題目類型與答案格式的影響，因此未來仍需持續驗證評分標準的穩健性。

**Q14：文中提到的代表性失敗案例有哪些？**  
A：在 L0 情境接地層級，模型可能遺漏證據，或把數值綁定到錯誤的圖片或表格。在 L1 新資訊應用層級，常見錯誤包括引用錯誤數值，以及讓預訓練得到的過時先驗凌駕於情境新提供的事實。在 L2 新知識學習層級，模型可能忽略情境定義的新規則或發現，或在答案中加入無依據的額外主張；這些案例具體說明了多模態情境學習在不同環節上可能崩潰。

**Q15：未來可以朝哪些方向改進或延伸？**  
A：未來研究可以針對密集視覺與長文件情境，強化模型的證據定位與跨模態綁定能力，減少接地失敗。也可以設計更好的知識衝突解決機制，使模型在面對新規則或新發現時，能正確抑制不適用的預訓練先驗。此外，擴充更多領域與語言的資料、改進自動化建構與篩選流程，以及發展更可靠的自動評判方法，都是提升 CLBench-V 與多模態情境學習整體水準的重要方向。

## 實務應用指南

### 適用場景

1. **智慧財經報告分析**：讓多模態模型閱讀季度財報中的表格、圖表與附註，根據當期數據回答 ROE、現金流或異常科目問題，而非依賴預訓練時的過時知識。
2. **學術文獻與醫療影像輔助解讀**：模型需從論文圖表、實驗結果與補充材料中定位證據，推論最新發現或驗證假設，適用於醫學影像報告、藥物試驗摘要等場景。
3. **長文件與網頁視覺問答**：處理數十頁合約、產品規格書或網頁截圖，回答需要跨頁、跨圖表比對的問題，例如「比較兩份保單條款的理賠差異」。
4. **空間與路線決策支援**：結合地圖、街景與路線規劃圖，讓模型根據當下提供的路網情境回答導航、選址或物流調度問題。
5. **多模態客服與知識獲取**：在體育賽事、電商商品頁等場景中，模型需從圖片、表格與文字描述中學習即時資訊並回答用戶問題。

### 實作前置條件

- **資料準備**：需收集與目標領域相關的多模態長情境，例如 PDF 文件、圖表、網頁截圖、地圖或影片幀。資料應具備明確的任務標註或可用於自動化建構與篩選的結構化來源。
- **運算資源**：建議具備可呼叫多模態大型語言模型（MLLM）的 API 或本地 GPU 推論環境；若進行自動化建構，需要額外的運算資源進行候選實例生成、過濾與評判。
- **技能需求**：團隊需熟悉提示工程、多模態模型推論、文件解析（OCR／版面分析）、自動化資料管線，以及具備領域知識以設計 L0／L1／L2 三層能力任務與評分準則。

### 實作步驟建議

1. **定義能力層級與失敗模式**：依據 CLBench-V 的架構，將目標任務區分為 L0 情境接地、L1 新資訊應用、L2 新知識學習，並預先列出遺漏證據、資訊誤用、忽略情境定義規則等失敗模式。
2. **收集與轉換現有資料**：優先使用公開基準或內部已標註資料，轉換為統一格式的多模態情境問答實例，確保每題都能對應到明確的證據位置。
3. **自動化建構與篩選**：針對領域特定任務，設計自動化管線生成候選實例，再利用規則型或模型型篩選程序移除品質不佳、答案模糊或證據不明確的樣本。
4. **建立評判機制**：採用 LLM-as-a-judge 或規則式評分，並以人工抽樣驗證評判可靠性；對數值型答案建議使用容差比對，對開放式答案則需設計細部評分維度。
5. **小規模試驗與錯誤分析**：先以少量實例測試數個多模態模型，分析在不同情境長度、圖片數量與答案類型下的表現，找出最頻繁的失敗類型。
6. **產品化與持續監控**：將評估流程整合至模型上線前的驗收測試，並在生產環境中持續收集真實錯誤案例，定期回補至評估資料集以形成回饋迴路。

### 潛在風險與注意事項

- **評判可靠性不足**：LLM 評判者可能對開放式答案或細微語義產生不一致。建議採用多人／多模型評判並計算一致性，必要時以人工覆核邊界案例。
- **情境長度與圖片數量的效能衰減**：模型在長情境或大量圖片中容易遺漏中間位置的證據。應設計不同長度與圖片數量的子集進行壓力測試。
- **預訓練知識干擾**：模型可能用既有的先驗知識覆蓋情境中提供的新資訊。任務設計應強制使用情境內證據，並透過對抗式問題檢測此類失敗。
- **自動化建構的品質漂移**：自動生成資料容易產生語意重複、證據不清或答案可猜測的樣本。必須保留嚴格的篩選程序與領域專家抽檢。
- **隱私與授權風險**：財務、醫療或合約文件常涉及敏感資訊。應使用去識別化資料或在私有環境中執行模型推論與評估。

### 與其他技術的整合建議

- **檢索增強生成（RAG）**：將 CLBench-V 的評估邏輯用於驗證 RAG 系統在多模態文件中的檢索與推理品質，確保檢索到的圖表、表格能被正確綁定與使用。
- **文件解析與版面分析管線**：搭配 OCR、表格偵測與版面還原工具，把原始 PDF 或網頁轉換為模型可理解的圖像與結構化表示，降低接地失敗率。
- **向量資料庫與多模態索引**：對長文件或大量圖片建立跨模態索引，支援依據問題動態召回相關頁面或圖表，再交由 MLLM 進行情境學習。
- **Agent 工作流程**：把 L0／L1／L2 任務拆解為「證據定位 → 資訊提取 → 推理回答」的多步驟 agent，並在每個階段加入自我檢查機制以減少資訊誤用。
- **人機協作驗證**：在高風險場景（如醫療、財務）中，將模型輸出與對應的接地證據一併呈現給領域專家，作為最終決策前的輔助依據。

### 給不同背景讀者的閱讀建議

- **初學者**：建議先從圖 1 的三層能力架構與常見失敗模式開始，理解「情境接地、新資訊應用、新知識學習」的差異；接著閱讀實驗結果，觀察目前多模態模型在真實任務上的分數仍低，體會這個領域的挑戰與機會。
- **AI 工程師**：請重點關注自動化建構與篩選程序、評判機制設計，以及不同模型在 L0／L1／L2 的表現差異；這些內容能直接幫助你設計內部評估管線與挑選適合業務場景的模型。
- **研究人員**：建議深入分析能力層級的理論基礎、與現有長情境／多圖片基準的關係，以及失敗案例所揭示的模型限制；可進一步探索如何改進模型在跨模態證據綁定與情境定義知識內化上的能力。
- **產品經理**：請聚焦適用場景與實驗結論，理解「支援多模態輸入」並不等於「能可靠地從情境學習」；在規劃產品時，應預留評估、人工覆核與逐步擴大應用範圍的資源，避免過度信任模型在複雜多模態任務上的表現。
