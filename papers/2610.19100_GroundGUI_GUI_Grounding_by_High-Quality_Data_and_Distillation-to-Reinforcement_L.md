## ⚡ TL;DR

跨平台 GUI 定位缺乏高品質資料，且監督微調泛化不足、強化學習獎勵稀疏。
提出 ScreenRef 資料集與 D2RL 蒸餾到強化學習兩階段訓練方法。
GroundGUI-8B 在多項基準測試中達到最優效能，超越閉源資料訓練的同級模型。

## 摘要翻譯

建構穩健的 GUI 代理仰賴多模態視覺定位：精確地將自然語言意圖對應到螢幕上可操作的元件。儘管桌面、網頁與行動裝置基準測試眾多，但針對多元環境量身打造的高品質資源卻出乎意料地稀少。為弭平此差距，我們推出螢幕指代定位資料集（Screen Referring Grounding Dataset，ScreenRef），這是一個全面的 GUI 定位資料集，包含 GUI 螢幕截圖，並搭配自然語言指代表達（Referring Expression）與邊界框（Bounding Box）或點標註（Point Annotation）。ScreenRef 橫跨桌面、網頁與行動裝置領域，包含 586K 張螢幕截圖與超過 633K 個指代表達實例，涵蓋文字識別（Text Recognition）、視覺匹配（Visual Matching）、空間理解（Spatial Understanding）與拒絕情境（Refusal Scenarios）等任務。為提升模型的定位效能，我們提出蒸餾到強化學習（Distillation-to-Reinforcement Learning，D2RL）方法，以解決監督式微調（Supervised Fine-Tuning，SFT）泛化能力有限以及強化學習（Reinforcement Learning，RL）中稀疏獎勵（Sparse Reward）的問題。利用 ScreenRef，我們透過依序進行 SFT 與 D2RL 訓練來訓練 Qwen3-VL-8B-Instruct，產出 GroundGUI-8B。GroundGUI-8B 在 ScreenSpot-V2 上達到 95.2%、ScreenSpot-Pro 上達到 63.9%、OSWorld-G 上達到 65.4%、MMBench-GUI L2 上達到 86.8%，以及 UI-Vision 上達到 38.3%。在 8B 規模的模型中，它相較於以開源（Open-Source）資料集訓練的模型產生顯著提升，效能可媲美甚至超越以閉源（Closed-Source）資料訓練的模型。程式碼、模型與資料集可於 https://github.com/PrentisAI/GroundGUI 取得。

### 核心貢獻（3～5點）
- **推出 ScreenRef 螢幕指代定位資料集**：橫跨桌面、網頁與行動裝置三大領域，包含 586K 張螢幕截圖與逾 633K 個指代表達實例，涵蓋文字識別、視覺匹配、空間理解與拒絕情境等多樣化任務。
- **提出 D2RL 蒸餾到強化學習方法**：結合蒸餾（Distillation）與強化學習的優勢，同時解決監督式微調泛化能力有限與強化學習稀疏獎勵兩大難題。
- **訓練並開源 GroundGUI-8B 模型**：以 Qwen3-VL-8B-Instruct 為基礎，透過依序 SFT 與 D2RL 訓練產出，在 ScreenSpot-V2、ScreenSpot-Pro、OSWorld-G、MMBench-GUI L2、UI-Vision 等五項基準測試中皆取得優異成績。
- **在 8B 規模模型中達到閉源等級效能**：相較於其他以開源資料訓練的同規模模型有顯著提升，效能可媲美甚至超越以閉源資料訓練的模型。

### 適合對象
- 從事 GUI 代理（GUI Agent）、智慧型使用者介面自動化研究的學者與工程師
- 研究多模態視覺語言模型（Multimodal VLM）、視覺定位（Visual Grounding）與指代表達理解的研究者
- 探討強化學習（特別是稀疏獎勵處理與策略蒸餾）應用於視覺任務的研究人員
- 從事 UI 自動化測試、軟體機器人流程自動化（RPA）、無障礙輔助技術開發的實務工程師
- 對開源高效能 GUI 定位模型感興趣、欲將其整合至下游應用的 AI 開發者與產品團隊

## 深度分析

#### 方法論解析

本論文提出兩個核心方法論貢獻：高品質 GUI 定位資料集 ScreenRef 的建構流程，以及兩階段後訓練框架 D2RL（蒸餾到強化學習）。以下分別深入剖析。

**ScreenRef 資料集建構方法**

ScreenRef 的建構採用雙路徑管線設計（Figure 1），體現了對 GUI 資料多樣性與準確性的雙重追求：

- **路徑 1（截圖爬取路徑）**：依序執行截圖爬取（screenshot crawling）、元資料過濾（metadata filtering）、指令生成（instruction generation）、以及驗證（verification）四個階段。此路徑適合處理結構化、可程式化存取的網頁與行動裝置介面。
- **路徑 2（教學影片路徑）**：包含教學影片爬取、關鍵幀候選提取（keyframe candidate extraction）、聯合指令與動作生成、以及座標生成階段。此路徑利用人類示範影片作為弱監督來源，特別適合處理缺乏結構化標註的桌面應用軟體。

兩條路徑互補的設計具有重要意義：桌面環境的 GUI 元件往往缺乏標準化的 HTML/DOM 結構或 accessibility tree，因此單純依賴結構化爬取會產生大量標註噪音；透過教學影片中的人類操作軌跡，可以自然地獲取真實的互動意圖與對應座標。

資料集涵蓋四類任務：（1）文字識別（text recognition）— 透過自然語言描述螢幕上的文字內容並定位；（2）視覺匹配（visual matching）— 根據視覺特徵（如圖示、按鈕外觀）對應目標元件；（3）空間理解（spatial understanding）— 利用空間關係詞（如「左上角」、「右側第二個」）進行定位；（4）拒絕情境（refusal scenarios）— 訓練模型在無法定位時主動拒絕回答，這對 GUI 代理的安全性至關重要。

解析度範圍從 0.1M 到 8.3M 像素，橫跨三個數量級，這對於處理高解析度桌面螢幕（4K/8K 顯示器）尤其關鍵。相較於既有資料集多數僅覆蓋 0.5–2.1M 像素範圍，ScreenRef 在解析度多樣性上有顯著突破。

**D2RL 兩階段後訓練框架**

D2RL 的核心洞見在於：純粹的監督式微調（SFT）容易過擬合特定領域，而純粹的強化學習（RL）面臨稀疏獎勵問題（sparse reward problem）— 在困難樣本上，所有推演（rollout）皆獲得零獎勵，導致策略無法有效更新。

D2RL 採用兩階段設計：

- **階段一：同策略自我蒸餾（OPSD, On-Policy Self-Distillation）**。此階段借鑒 Zhao et al. (2026a) 的 OPSD 概念，但針對 GUI 定位任務進行特化。關鍵設計是：教師模型（teacher）能夠看到真實邊界框（ground-truth bounding box），因此可以產生高品質的詞元層級監督（token-level supervision）。學生模型（student）則僅看到螢幕截圖與自然語言指令，必須學習模仿教師的座標生成過程。這種設計為後續 RL 提供了「更好的起始策略」（better starting policy），使模型在進入 RL 階段時已具備較強的座標預測能力。

- **階段二：REINFORCE 留一法（RLOO, REINFORCE Leave-One-Out）**。在 OPSD 提供的良好初始化基礎上，採用 RLOO（Ahmadian et al., 2024）進行策略最佳化。RLOO 相較於 GRPO 的優勢在於其留一估計基線（leave-one-out baseline）能提供更低方差的優勢估計，且不需要訓練價值函數（value function）。

兩階段的銜接邏輯清晰：OPSD 解決「冷啟動」問題，讓模型在進入 RL 前已具備基本能力，避免 RL 在隨機初始化下浪費大量推演；RLOO 則在良好起點上進一步提升泛化能力與定位精度。

#### 實驗數據解讀

GroundGUI-8B 在五個 GUI 定位基準測試上展現了全面的領先表現：

| 基準測試 | GroundGUI-8B | 意義解讀 |
|---------|--------------|---------|
| ScreenSpot-V2 | 95.2% | 標準跨平台 GUI 定位，接近飽和，顯示模型對常見 UI 模式掌握良好 |
| ScreenSpot-Pro | 63.9% | 專業軟體 GUI 定位，較 ScreenSpot-V2 難度大幅提升，桌面環境的關鍵指標 |
| OSWorld-G | 65.4% | 真實作業系統環境的定位能力，反映實用性 |
| MMBench-GUI L2 | 86.8% | 多模態綜合 GUI 能力評估 |
| UI-Vision | 38.3% | 較新且更具挑戰性的基準，數值偏低但相對競爭對手仍有顯著優勢 |

**關鍵觀察**：

1. **ScreenSpot-V2 與 ScreenSpot-Pro 的落差**（95.2% vs 63.9%）揭示了 GUI 定位的核心挑戰：當介面變得專業化、密集化、視覺歧異化時，定位難度呈現階躍式上升。ScreenSpot-Pro 包含高解析度專業軟體介面（如 Photoshop、VS Code），這正是 ScreenRef 資料集強調覆蓋的場景。

2. **與閉源資料訓練模型的比較**：GroundGUI-8B 大幅超越 Holo2-8B 與 Step-GUI-8B（兩者皆使用閉源資料訓練），這是論文最重要的宣稱之一。它證明了「資料品質 + 訓練方法」的組合可以超越「單純的資料規模」。

3. **與 32B 規模模型的比較**：GroundGUI-8B 在 8B 參數規模下超越 ScaleCUA-32B、OpenCUA-32B、GTA1-32B 等 32B 模型，挑戰了「模型規模越大越好」的傳統假設，凸顯了高品質資料與訓練策略的槓桿效應。

4. **UI-Vision 38.3% 的相對意義**：雖然絕對數值看似不高，但需考慮 UI-Vision 是一個刻意設計的高難度基準，包含大量需要深層視覺理解的場景。在 8B 規模模型中，此成績仍具競爭力。

#### 與現有研究的比較

**資料集層面的定位**：

ScreenRef 在 GUI 定位資料集的生態系中佔據獨特位置。相較於既有資料集：

- **vs. OS-ATLAS**：OS-ATLAS 雖規模大（1.85M 影像），但依賴 accessibility tree 提取桌面元素，標註噪音問題嚴重。ScreenRef 透過多階段過濾與驗證，在品質上更具優勢。
- **vs. JEDI**：JEDI 透過合成介面生成擴大規模（575K 影像、4M 指令），但合成螢幕無法捕捉真實桌面軟體的複雜度。ScreenRef 採用真實截圖，在視覺真實性上更優。
- **vs. GroundCUA/ScaleCUA/Wild2GUI**：這些近期資料集雖提供密集標註或跨平台覆蓋，但標註不準確或多樣性不足限制了模型表現。ScreenRef 透過雙路徑建構管線，在多樣性與準確性間取得較佳平衡。
- **vs. MolmoPoint-GUISyn**：雖然 MolmoPoint-GUISyn 解析度範圍同樣達到 8.3M，但僅 36K 影像、10M 指令的規模在影像多樣性上受限。

**訓練方法層面的定位**：

D2RL 與現有 GUI 代理訓練方法的關係：

- **vs. 純 SFT 方法**（CogAgent、ShowUI、Ferret-UI、OS-Genesis、GUI-Actor、UI-TARS）：這些方法單純依賴 SFT，雖然在特定領域表現良好，但泛化能力受限。D2RL 透過 RL 階段顯著提升泛化性。
- **vs. 純 GRPO 方法**（GUI-R1、GUI-G2、GUI-C2、InfiGUI-G1）：這些方法直接採用 GRPO 進行 RL 訓練，但面臨稀疏獎勵問題。D2RL 透過前置 OPSD 階段緩解此問題，提供更好的起始策略。
- **vs. OPSD 原始方法**：D2RL 將 OPSD 從通用領域特化至 GUI 定位任務，並與 RLOO 結合形成完整管線，而非僅作為獨立訓練階段。

**論文承認的局限性**：

從論文中可推斷的潛在限制包括：（1）ScreenRef 雖覆蓋三大平台，但桌面環境的覆蓋深度仍可能受限於教學影片的可用性；（2）D2RL 的兩階段設計增加了訓練複雜度與計算成本；（3）拒絕情境的訓練資料比例與品質未在論文中詳細說明；（4）模型在極高解析度（8.3M 像素）下的推理效率未深入討論。

本論文在可重現性方面表現優異，具備完整的開源承諾：

#### 未來研究方向

基於本論文的研究成果與方法論框架，以下方向值得進一步探索：

**1. 資料集擴展與品質提升**

- **多語言支援**：當前 ScreenRef 主要基於英文介面與英文指令，未來可擴展至中文、日文等多語言 GUI 環境，提升跨語言代理能力。
- **動態介面處理**：現有資料集以靜態截圖為主，未來可納入動態介面元素（如動畫、過渡效果、彈出視窗）的處理。
- **細粒度互動類型**：擴展至更複雜的互動手勢（滑動、縮放、拖拽）與多點觸控場景。

**2. 訓練方法創新**

- **D2RL 的理論分析**：深入分析 OPSD 階段為何能提供「更好的起始策略」，以及 RLOO 相較於 GRPO 在 GUI 定位任務上的具體優勢機制。
- **課程學習整合**：將 D2RL 與課程學習（curriculum learning）結合，從簡單到困難樣本逐步訓練，可能進一步提升困難樣本上的表現。
- **多模態獎勵設計**：當前 RL 階段的獎勵主要基於座標準確度，未來可設計結合語義一致性的多維度獎勵函數。

**3. 模型架構探索**

- **解析度自適應機制**：針對 0.1M 到 8.3M 像素的巨大解析度差異，設計自適應的視覺編碼策略，避免高解析度場景下的計算瓶頸。
- **層次化定位**：先進行粗粒度區域定位，再進行細粒度座標預測，可能提升複雜介面上的定位效率與精度。
- **與大型視覺語言模型的整合**：探索 GroundGUI 作為視覺定位模組與更大規模推理模型（如 GPT-4V、Claude）的協作架構。

**4. 應用場景拓展**

- **無障礙輔助技術**：將精確的 GUI 定位能力應用於視障人士的螢幕閱讀輔助。
- **自動化測試**：在軟體測試領域，利用 GUI 代理自動產生測試案例並驗證 UI 行為。
- **跨平台工作流自動化**：建構能同時操作桌面、網頁與行動裝置的統一代理，實現真正的跨平台自動化。

**5. 安全性與可靠性研究**

- **拒絕機制的深入分析**：研究模型在什麼情況下應該拒絕定位，以及如何區分「真正無法定位」與「模型能力不足」。
- **對抗性攻擊魯棒性**：評估 GUI 定位模型在對抗性介面變化（如微小像素擾動、視覺欺騙）下的穩定性。
- **隱私考量**：研究 GUI 代理在處理敏感資訊（如密碼輸入、個人資料）時的隱私保護機制。

本論文為 GUI 代理領域提供了紮實的基礎設施（ScreenRef）與方法論創新（D2RL），其開源承諾將加速整個領域的研究進展。後續工作可在資料品質、訓練效率、模型架構與應用場景等多個維度上持續推進，最終朝向真正可靠的跨平台 GUI 代理邁進。

## 論文問答

**Q1：這篇論文要解決的核心問題是什麼？**
A：這篇論文聚焦於視覺 GUI 定位（Visual GUI Grounding）這項基礎任務，也就是將自然語言指令精準對應到螢幕上可操作的互動元件像素座標。隨著 GUI 代理在桌面、網頁與行動裝置等跨平台環境中日益普及，穩健的跨平台定位能力成為建構可靠代理的基石。然而現代應用程式畫布解析度高、版面密集且視覺歧異性細微，使得空間定位極具挑戰性；再加上領域專屬軟體的圖示語意特殊，模型在跨域場景下表現容易退化。因此論文將「跨平台、高精度的 GUI 定位」定義為核心研究問題，並試圖從資料與訓練方法兩個層面同時突破。

**Q2：為什麼現有的 GUI 定位方法表現不夠理想？**
A：現有方法面臨兩大瓶頸：首先是資料面，雖然業界有 Mobile-Agent-v3.5、UI-Venus-1.5、UI-TARS-2、MAI-UI 等表現優異的模型，但它們仰賴專有的大規模資料，社群無法取得；而開源的 GroundCUA、ScaleCUA 等資料集又因多樣性或標註準確度不足，導致訓練出來的模型表現次佳。其次是訓練方法面，監督式微調（SFT）容易過擬合特定領域、泛化能力受限；而基於 GRPO 的強化學習方法雖然能改善泛化，卻在困難樣本上遭遇稀疏獎勵問題——當所有推演都得到零獎勵時，模型無法獲得有效學習訊號。這兩層因素共同限制了現有 GUI 定位模型的實用性。

**Q3：為什麼高品質的 GUI 定位資料集如此重要？**
A：資料是模型能力的根本，但建構覆蓋面廣、品質高的 GUI 定位資料集極具挑戰性。現有資料集各有缺陷：行動裝置資料（如 RICO、AMEX）版面標準化但密度與視覺變化不足；網頁資料（如 SeeClick、UGround）仰賴 HTML/DOM 結構，偏好帶文字元素而忽略純圖示控制項；桌面資料尤其稀缺，OS-ATLAS 透過無障礙樹擷取但標籤雜訊多，JEDI 雖擴大規模卻因合成螢幕過於簡化而無法反映真實桌面複雜度。為此論文提出 ScreenRef，涵蓋 586K 張截圖與 633K 個指代表達實例，橫跨桌面、網頁與行動裝置平台，並透過多階段過濾與驗證機制確保資料品質。

**Q4：D2RL 方法的核心概念是什麼？它如何運作？**
A：D2RL（Distillation-to-Reinforcement Learning，蒸餾到強化學習）是一個兩階段的訓練後框架，結合了同策略自我蒸餾（OPSD）與 REINFORCE 留一法（RLOO）。第一階段的 OPSD 為 GUI 定位量身打造，透過讓「看見真實邊界框」的教師提供豐富的詞元層級監督，協助模型從精準的座標生成中學習，這解決了強化學習在困難樣本上的稀疏獎勵問題。第二階段則採用 RLOO 強化學習，進一步提升模型的泛化能力與定位準確度。這種「先蒸餾、後強化」的設計理念，是為了塑造一個更強的起始策略，使後續強化學習能更有效地釋放潛力。

**Q5：為 GUI 定位量身打造的 OPSD 有什麼關鍵創新？**
A：OPSD 的核心創新在於提供密集的詞元層級監督，這與傳統強化學習中獎勵訊號稀疏的特性形成對比。在 GUI 定位任務中，模型需要輸出精確的座標，若所有推演結果都偏離真實位置，GRPO 等方法就會給予所有樣本零獎勵，導致學習訊號消失。OPSD 透過單次推演並讓教師（能看見真實邊界框）對學生的詞元序列提供細粒度指導，使模型即使在困難樣本上也能獲得有意義的學習訊號。這種設計特別適合 GUI 定位這種需要精細座標生成的任務，因為它能在強化學習開始前就為模型奠定更穩固的起點。

**Q6：為什麼選擇「先 OPSD 再 RLOO」的兩階段設計，而非單獨使用其中一種？**
A：這個設計選擇反映了對兩種方法優缺點的深刻理解。單獨使用 SFT 容易過擬合、泛化不足；單獨使用 GRPO 等強化學習則在困難樣本上因稀疏獎勵而難以學習。OPSD 雖然能提供密集監督，但本質上仍屬於模仿學習範疇，無法像強化學習那樣主動探索更廣泛的策略空間。因此先以 OPSD 為模型注入精準的座標生成能力，建立強健的起始策略，再透過 RLOO 進行策略探索與泛化優化，能兼顧「學得會」與「學得好」兩個目標。這種循序漸進的訓練流程，是 D2RL 能在多項基準測試中取得突破性表現的關鍵。

**Q7：論文中使用了哪些基準測試？GroundGUI-8B 的關鍵結果為何？**
A：論文在五個 GUI 定位基準測試上評估 GroundGUI-8B：ScreenSpot-V2、ScreenSpot-Pro、OSWorld-G、MMBench-GUI L2 與 UI-Vision。GroundGUI-8B 取得了 95.2%（ScreenSpot-V2）、63.9%（ScreenSpot-Pro）、65.4%（OSWorld-G）、86.8%（MMBench-GUI L2）以及 38.3%（UI-Vision）的成績。這些結果顯示模型在多樣化的測試場景中皆表現優異，特別是在跨平台、跨複雜度的 GUI 環境中展現了穩健的定位能力。

**Q8：GroundGUI-8B 與其他 8B 規模模型相比表現如何？**
A：在 8B 規模模型中，GroundGUI-8B 相較於使用開源資料訓練的模型有大幅度的領先提升。更值得注意的是，它的表現甚至可媲美或超越使用閉源資料訓練的模型，例如 Holo2-8B 與 Step-GUI-8B。此外，GroundGUI-8B 還超越了多個 32B 規模的模型，包括 ScaleCUA-32B、OpenCUA-32B 與 GTA1-32B，展現出極高的參數效率。這意味著透過高品質資料與創新訓練方法的結合，小模型也能達到甚至超越大模型的表現。

**Q9：論文中是否有消融實驗來驗證各元件的貢獻？**
A：雖然提供的全文片段未完整展示消融實驗的細節，但從方法論描述可推論，論文的消融設計應涵蓋 ScreenRef 資料集品質的影響、D2RL 兩階段訓練的必要性，以及 OPSD 與 RLOO 各別的貢獻。透過逐步移除或替換關鍵元件，應能驗證：(1) ScreenRef 的多階段過濾與驗證機制對最終表現的提升；(2) 兩階段訓練相較於單獨 SFT 或單獨 RL 的優勢；(3) OPSD 在解決稀疏獎勵問題上的具體效益。這類消融設計有助於釐清每個元件對整體效能的邊際貢獻。

**Q10：GroundGUI 在哪些實際應用場景中能發揮價值？**
A：GroundGUI 的高精度跨平台定位能力可應用於多種實際場景：在企業自動化中，可作為 RPA（機器人流程自動化）的視覺引擎，處理跨桌面軟體、網頁服務與行動 App 的複雜流程；在無障礙輔助技術上，能幫助視障使用者透過語音指令操作各類應用；在軟體測試領域，可自動化產生 UI 測試案例並驗證互動元素的正確性。此外，對於個人助理代理（如自動訂票、填表、跨平台資料搬運），GroundGUI 提供的精準座標輸出是執行操作的基礎，能顯著提升任務成功率與使用者體驗。

**Q11：將 GroundGUI 整合到產品中需要考量哪些因素？**
A：產品化 GroundGUI 時需考量多項因素：首先是延遲與回應速度，8B 規模模型在邊緣裝置部署可能需要量化或蒸餾；其次是隱私與資料安全，GUI 截圖往往包含敏感資訊，部署時應考慮本地化推論或嚴格的資料處理規範；再者是錯誤容忍度，定位失敗時的優雅降級機制（如提示使用者手動確認）對使用者信任至關重要。此外，模型的更新維護、跨作業系統版本（Windows、macOS、各家瀏覽器）的相容性測試，以及與上游語言理解模組的串接設計，都是實際產品化時不可忽視的工程議題。

**Q12：這項研究對 GUI 代理領域的整體影響為何？**
A：這項研究的影響體現在三個層面：在資料層面，ScreenRef 公開釋出後將降低社群研究的門檻，使更多團隊能訓練高品質的 GUI 定位模型；在方法論層面，D2RL 提出的「先蒸餾、後強化」框架為解決稀疏獎勵問題提供了新思路，可能影響後續 GUI 代理乃至其他視覺語言任務的訓練策略；在產業層面，8B 模型能達到甚至超越 32B 模型的表現，顯示「資料品質 + 訓練方法」的組合比單純堆疊參數量更具效益，這對資源有限的學術與新創團隊是重要啟發。整體而言，這項工作推動了 GUI 代理領域朝向更開放、更高效的方向發展。

**Q13：論文承認哪些研究限制？**
A：從全文內容可推論，論文的限制主要體現在幾個方面：首先是規模與平台覆蓋，雖然 ScreenRef 涵蓋桌面、網頁與行動裝置，但相較於專有資料集（如 UI-TARS-2、MAI-UI 所使用的）規模仍較小，可能在極端長尾場景下表現受限。其次是模型規模，GroundGUI-8B 雖在 8B 級別達到 SOTA，但對於需要更高推理能力的複雜多步任務，仍可能不及更大規模的專有模型。此外，論文中部分引用文獻年份標註為 2026 年，這暗示該領域發展極為迅速，方法的時效性與後續追趕將是持續挑戰。

**Q14：GroundGUI 可能會在哪些情境下失敗？**
A：GroundGUI 可能在以下情境中遭遇困難：在高度動態的 GUI 環境中（如即時更新的儀表板、動畫密集的遊戲介面），截圖可能無法反映當下真實的可互動狀態；在極度非標準化的應用程式（如自訂工業控制軟體、特殊無障礙介面）中，訓練資料的覆蓋可能不足；對於需要多步推理才能定位的複合指令（例如「點選第三個分頁中倒數第二個選項」），單純的視覺定位模型可能難以處理。此外，在低解析度、模糊或經過特殊渲染的截圖上，模型的視覺感知能力也可能受到影響。

**Q15：未來的研究方向有哪些？**
A：基於論文的框架與限制，未來可朝幾個方向延伸：在資料面，可探索更大規模、更多語言、更多作業系統版本的 GUI 資料建構，並納入影片與互動軌跡以支援多步任務；在方法面，可將 D2RL 框架擴展至多步 GUI 代理任務，結合規劃與長期獎勵設計；在模型面，可研究如何將 GroundGUI 與語言推理能力結合，使模型能處理更複雜的指令；此外，跨模態（如語音、觸控）整合、個性化適應（學習使用者特定介面偏好），以及安全性與對抗攻擊防禦，都是值得探索的長期方向。整體而言，從「單步定位」走向「多步智慧代理」將是下一階段的核心願景。

### 實作步驟建議

**階段一：環境建置與基線評估**
1. 複製官方 GitHub 倉庫（PrentisAI/GroundGUI），安裝依賴套件並下載 GroundGUI-8B 權重。
2. 在自有資料上跑 ScreenSpot-V2 或 ScreenSpot-Pro 子集，確認模型在目標領域的基線表現。
3. 建立錯誤案例分析 pipeline，統計模型在哪些類型任務（文字識別、視覺匹配、空間理解、拒絕）上表現較弱。

**階段二：領域微調（SFT）**
4. 將自有螢幕截圖轉換為 ScreenRef 格式：每張截圖搭配自然語言指代表達與邊界框/點標註。
5. 採用 Qwen3-VL-8B-Instruct 作為起點，依官方流程進行監督式微調；建議學習率 1e-5 至 5e-6，訓練 1-3 個 epoch。
6. 驗證 SFT 後模型在驗證集的定位準確度，特別關注高解析度（>2K）截圖的表現。

**階段三：強化學習最佳化（D2RL）**
7. 實作 OPSD（On-Policy Self-Distillation）：讓模型在看到真實邊界框的條件下產生 token 級監督訊號，作為密集獎勵來源。
8. 接續執行 RLOO 階段：對每個 prompt 採樣多組 rollout，以留一法估計基線，計算相對優勢。
9. 監控獎勵曲線與定位準確度的聯合變化，避免獎勵 hacking（例如模型學會輸出固定座標）。

**階段四：產品化整合**
10. 將模型封裝為 API 服務（建議用 vLLM 提供 OpenAI 相容介面），設計請求格式：截圖 + 自然語言指令 → 回傳座標與信心分數。
11. 整合至既有自動化框架（如 Selenium、Playwright、PyAutoGUI），座標輸出可直接轉換為滑鼠點擊事件。
12. 設計信心閾值機制：當模型回傳信心低於設定值時，觸發人工確認流程或拒絕執行。

**階段五：監控與迭代**
13. 上線後持續蒐集失敗案例，定期回饋至訓練資料。
14. 建立 A/B 測試框架，比較 GroundGUI 與既有定位方法（如 OCR + 規則匹配）的成功率與執行時間。

### 潛在風險與注意事項

**座標漂移與解析度敏感**
- 模型在不同解析度螢幕（從 0.1M 到 8.3M 像素）下的表現可能不一致。**緩解方式**：在推論前將截圖縮放至訓練時常見的解析度區間，或在資料增強階段加入多解析度訓練樣本。

**強化學習的稀疏獎勵陷阱**
- 在困難樣本上，所有 rollout 可能都得到零獎勵，導致策略無法更新。**緩解方式**：D2RL 的 OPSD 階段正是為解決此問題而設計，務必依序執行 SFT → OPSD → RLOO，不可跳過 OPSD 直接進入 RLOO。

**拒絕機制的誤觸發**
- 模型可能在可定位情境下過度保守地回報「無法定位」。**緩解方式**：在訓練資料中維持正負樣本平衡，並監控「假拒絕率」指標，必要時調整拒絕分類器的決策閾值。

**閉源模型競爭風險**
- UI-TARS-2、MAI-UI 等閉源模型在部分基準上仍領先。**緩解方式**：聚焦於閉源模型難以觸及的私有領域資料（如企業內部系統），發揮開源模型可客製化的優勢。

**延遲與成本**
- 8B 模型單次推論約需數百毫秒至數秒，對即時操作場景可能過慢。**緩解方式**：採用 speculative decoding 或將模型蒸餾至 3B 規模；對非即時批次任務則影響較小。

**座標到動作的轉換誤差**
- 模型輸出的是相對座標或像素座標，需正確對應到作業系統的滑鼠事件系統。**緩解方式**：在高 DPI 螢幕或縮放比例非 100% 的環境下，需進行座標系轉換並加入邊界檢查。

---

### 與其他技術的整合建議

**與大型語言模型（LLM）規劃器整合**
- 將 GroundGUI 作為「執行層」，上游搭配 GPT-4、Claude 或本地 LLM 進行任務拆解與規劃。LLM 將高階指令分解為子步驟，每個子步驟交由 GroundGUI 定位並執行，形成「規劃—定位—執行」的閉環。

**與 OCR 引擎互補**
- 對於純文字按鈕（如「確定」「取消」），OCR 引擎可能更快速且精準。可設計路由機制：先以輕量 OCR 嘗試匹配，失敗時再呼叫 GroundGUI 處理圖示或複合視覺元素。

**與 RAG（檢索增強生成）整合**
- 將應用程式的 UI 文件、使用手冊建立向量索引，當 GroundGUI 對某個元件信心不足時，自動檢索相關說明並提供給模型作為額外上下文，提升定位準確度。

**與電腦視覺預處理整合**
- 在送入 GroundGUI 前，可先用物件偵測模型（如 YOLO、DETR）找出畫面中的候選元件，僅將候選區域與指令一起送入 GroundGUI，降低計算量並提升小元件的定位率。

**與監控與可觀測性平台整合**
- 將每次定位請求的截圖、指令、預測座標、信心分數記錄至可觀測性平台（如 Langfuse、Phoenix），便於除錯、稽核與持續改進。

### 給不同背景讀者的閱讀建議

**給初學者**：建議先閱讀第 1 節的「視覺 GUI 定位」概念，理解為什麼需要將語言對應到螢幕座標；接著瀏覽 ScreenRef 資料集的統計表格，感受資料規模與多樣性；最後直接用官方提供的 GroundGUI-8B 權重搭配 Gradio 介面玩玩看，體驗模型在 ScreenSpot-V2 範例上的表現，不必急於深入訓練細節。

**給 AI 工程師**：重點放在 D2RL 的兩階段設計——OPSD 如何提供 token 級密集監督、RLOO 如何在 GUI 定位任務中避免稀疏獎勵問題。建議複製官方訓練程式碼，在自有資料上重現 SFT → OPSD → RLOO 的流程，並嘗試替換不同的基礎模型（如 Qwen2.5-VL、LLaVA-OneVision）以評估遷移效果。

**給研究者**：ScreenRef 的多階段過濾與驗證 pipeline 是值得深入探討的工程細節，可從附錄中的資料品質分析章節切入；D2RL 結合 on-policy 蒸餾與 RL 的思路可延伸至其他視覺定位任務（如機器人操作、AR 互動）。此外，模型在 UI-Vision 上僅 38.3% 的表現，顯示仍有顯著的研究空間，特別是在長尾分布與跨文化 UI 元素的處理上。

**給產品經理**：GroundGUI-8B 在 8B 規模下已能與部分閉源 32B 模型匹敵，意味著可在合理的硬體成本（單張 A100）下部署企業級 GUI 代理。建議評估自家產品的 UI 複雜度與自動化需求，優先從內部系統、客服輔助、自動化測試等場景切入，並預留 2-3 個月的微調與迭代時間，以達到生產環境所需的可靠性。
