## 摘要翻譯

近年來，多模態基礎模型（multimodal foundation models）與代理系統（agent systems）的進展，已促使 GUI 代理（GUI agents）從單平台（single-platform）任務執行邁向跨平台互動（cross-platform interaction）。然而，建構多平台 GUI 代理（multi-platform GUI agents）仍充滿挑戰。一方面，高品質（high-quality）且可執行（executable）的跨平台互動軌跡（cross-platform interaction trajectories）仍屬稀少，且現有資料的平台覆蓋率（platform coverage）通常有限。另一方面，不同平台展現出各自的互動慣例（interaction conventions），使聯合訓練（joint training）或持續訓練（continual training）容易引發行為模式混合（behavioral pattern mixing）、平台特定能力退化（platform-specific capability degradation）以及災難性遺忘（catastrophic forgetting）。為解決這些挑戰，本研究建構了 Uni-GUI（cross-platform GUI interaction dataset），一個高品質的跨平台 GUI 互動資料集，並提出 UI-MOPD（Multi-Platform On-Policy Distillation），為首個將多教師在線策略蒸餾（multi-teacher on-policy distillation）應用於持續性 GUI 代理學習（Continual GUI Agent Learning）的方法。UI-MOPD 依據目前環境（current environment）動態選擇平台特定教師（platform-specific teacher），並透過平台條件化蒸餾（platform-conditioned distillation）將平台特定行為先驗（platform-specific behavioral priors）轉移至共享策略（shared policy），使其能夠在適應新平台（adaptation to new platforms）的同時保留現有平台（existing platforms）的能力。在 OSWorld（互動式電腦環境基準）與 MobileWorld（行動環境基準）上的實驗顯示，UI-MOPD 分別達到 38.2% 與 12.0% 的任務成功率（task success rate），展現其在平衡跨平台能力保留（cross-platform capability retention）與新平台適應（new-platform adaptation）方面的有效性。

專案頁面（Project page）：https://elispectre.github.io/UI-MOPD/。

### 核心貢獻（3～5點）
- 建構 Uni-GUI：一個高品質且可執行的跨平台 GUI 互動資料集，彌補現有資料在平台覆蓋率上的不足。
- 提出 UI-MOPD：首次將多教師在線策略蒸餾整合至持續性 GUI 代理學習，透過平台條件化教師路由與平台條件化蒸餾，動態選擇平台特定教師並轉移平台特定行為先驗。
- 實現跨平台能力保留與新平台適應的平衡：在共享策略學習新平台的同時，減緩行為模式混合、平台特定能力退化與災難性遺忘。
- 在 OSWorld 與 MobileWorld 上驗證方法有效性，任務成功率分別達 38.2% 與 12.0%。

### 適合對象
對多模態基礎模型、GUI 代理、持續學習與跨平台互動有興趣的研究者與工程師，特別是關注如何在異質 GUI 環境中建構能持續學習新平台並保留既有平台能力之互動式代理的讀者。

## 深度分析

#### 方法論解析

##### 核心問題與整體框架

本文提出的 UI-MOPD（Multi-Platform On-Policy Distillation，多平台在線策略蒸餾）鎖定一個在 GUI 代理（Graphical User Interface agent）領域日益關鍵的問題：如何讓單一共享策略（shared policy）在持續學習（continual learning）的過程中，不斷適應異質 GUI 環境（heterogeneous GUI environments），同時保留各平台特有的互動慣例（interaction conventions）。傳統的聯合訓練（joint training）把電腦與行動裝置的軌跡混合後直接進行監督式微調（Supervised Fine-Tuning，SFT）或強化學習（Reinforcement Learning，RL），容易導致行為模式混合（behavioral pattern mixing）與平台特定能力退化（platform-specific capability degradation）；而持續訓練（continual training）若缺乏行為錨點，則會出現災難性遺忘（catastrophic forgetting）。UI-MOPD 的解法是引入「平台特定教師（platform-specific teacher）」作為穩定的行為先驗（behavioral priors），透過平台條件化蒸餾（Platform-Conditioned Distillation）把各平台的動作分布轉移到共享策略，從而讓學生策略在面對新平台時能適應，面對舊平台時不忘記。

##### Uni-GUI 資料集建構

方法論的基礎是 Uni-GUI（跨平台 GUI 互動資料集）。作者先建立統一的跨平台資料收集框架（unified cross-platform data-collection harness），讓電腦環境（computer environments）與行動環境（mobile environments）使用一致的動作介面（action interface）與紀錄格式（logging format）。原始收集量約為 110K 個電腦互動步驟與 50K 個行動互動步驟，經過嚴格的品質控管與過濾後，得到近 10K 條高品質跨平台互動軌跡（high-quality cross-platform interaction trajectories）。這個資料集的價值不只在數量，更在於它提供可執行（executable）、狀態—動作對齊準確、且涵蓋不同平台的軌跡，為後續的策略學習與蒸餾提供穩定的示範來源。

##### UI-MOPD：多教師在線策略蒸餾

UI-MOPD 的核心可拆解為四個環節：

1. **共享策略與平台條件化（Shared Policy & Platform Conditioning）**  
   學生模型是一個多模態基礎模型（multimodal foundation model），輸入包含螢幕截圖、自然語言任務指令，以及平台識別符號（platform identifier）。透過平台條件化（platform conditioning）——例如把平台標記附加在提示詞（prompt）中，或使用平台專屬的嵌入層——讓單一模型能根據目前環境啟動不同的互動模式。

2. **平台條件化教師路由（Platform-Conditioned Teacher Routing）**  
   系統維護一組平台特定教師，每個教師專精於單一平台（如電腦或行動裝置）的互動慣例。在每次 rollout 時，根據目前環境（current environment）的平台標籤動態選擇對應教師。這個路由機制確保不同平台的行為信號不會在優化過程中被無差別混合。

3. **在線策略蒸餾（On-Policy Distillation）**  
   與傳統行為複製（behavior cloning）直接使用教師生成的離線軌跡不同，UI-MOPD 讓學生策略與環境互動產生在線軌跡（on-policy rollouts），再由教師對這些學生實際造訪過的狀態輸出動作分布。學生策略透過蒸餾損失（distillation loss）——常見形式為 KL 散度（Kullback-Leibler divergence）或交叉熵（cross-entropy）——對齊教師的動作分布。這樣做的好處是：學生仍能探索環境並從任務獎勵學習，但教師作為行為錨點，防止策略偏離平台特定的操作語義。

4. **獎勵設計（Reward Design）與訓練目標（Training Objective）**  
   獎勵設計通常結合稀疏的任務成功信號與步驟層級的中間獎勵，並可能加入對教師分布的 KL 正則項，以避免學生策略過度偏離平台先驗。整體訓練目標可視為強化學習目標（如 PPO 的策略梯度與價值函數損失）加上蒸餾損失，並可能輔以在 Uni-GUI 上的 SFT 回放損失，以進一步穩定持續學習。

##### 與持續學習的結合

UI-MOPD 把多教師在線策略蒸餾（Multi-Teacher On-Policy Distillation）引入持續性 GUI 代理學習（Continual GUI Agent Learning），其關鍵在於「教師不隨學生一起更新」。當學生策略接觸到新平台時，對應的新教師被加入路由；舊平台教師保持凍結，持續提供穩定的行為先驗。這種設計讓共享策略在參數空間中學到可轉移的介面推理能力（transferable interface reasoning），同時透過蒸餾保留各平台獨特的動作語義，例如電腦上的「關閉視窗」對應行動裝置上的「返回鍵」。

#### 實驗數據解讀

##### 基準與指標

實驗選用兩個具代表性的互動式基準：OSWorld（互動式電腦環境基準）與 MobileWorld（行動環境基準）。評估指標主要為任務成功率（task success rate），即代理在給定任務中是否完成所有目標步驟。這兩個基準都屬於長程（long-horizon）、以平台為基礎的互動（platform-grounded interaction），對視覺理解、規劃與動作執行都有高度要求。

##### 主要結果

UI-MOPD 在 OSWorld 達到 38.2% 的任務成功率，在 MobileWorld 達到 12.0%。相較於基礎模型（base model），分別帶來 12.7% 與 55.8% 的相對提升。從數字可觀察到幾點：

- **電腦平台仍有顯著進步**：OSWorld 的絕對成功率已達 38.2%，在該基準上屬於具競爭力的表現；12.7% 的相對提升說明即使在原本較強的領域，平台條件化蒸餾仍能減少行為模式混合所帶來的負面影響。
- **行動平台適應效果更明顯**：MobileWorld 從約 7.7% 提升至 12.0%，相對提升高達 55.8%。這顯示基礎模型在行動環境上的初始能力較弱，而 UI-MOPD 透過平台特定教師有效彌補了新平台適應（new-platform adaptation）的缺口。
- **無犧牲舊平台能力**：兩個平台同時提升，意味著方法確實在「跨平台能力保留（cross-platform capability retention）」與「新平台適應」之間取得平衡，而非以犧牲電腦效能來換取行動效能。

##### 跨平台能力轉移分析

雖然具體表格未在提供的上下文中出現，但從論文標題與摘要可推斷，作者應比較了「僅在單平台訓練」、「聯合訓練」與「持續學習 + UI-MOPD」三種設定。預期聯合訓練會讓電腦與行動動作語義互相干擾，導致兩平台表現都低於 UI-MOPD；而純持續訓練則會在學習行動平台後遺忘電腦平台的特定行為。UI-MOPD 透過凍結教師提供的行為錨點，應能顯著緩解這些問題。

##### 靜態理解與定位評估

論文另設有 General GUI Static Understanding and Grounding Evaluation，目的在於確認策略蒸餾不會損害模型的視覺理解與定位能力（static understanding and grounding）。這項評估很重要，因為過度強調動作分布對齊可能讓模型忽略螢幕元素的語義。若結果顯示 UI-MOPD 在靜態定位任務上維持或提升表現，則說明平台條件化蒸餾並未壓縮視覺表徵，反而因為跨平台資料的多樣性增強了通用 GUI 理解。

##### 案例研究觀察

案例研究（case study）部分預期會展示平台感知行為：面對電腦任務時，代理傾向使用關閉視窗、鍵盤快捷鍵、右鍵選單等桌面互動慣例；面對行動任務時，則會使用返回鍵、滑動手勢、長按等觸控慣例。這種根據環境上下文自動切換互動模式的能力，正是 UI-MOPD 相較於單一平均化策略的最大優勢。

#### 與現有研究的比較

##### 相對於單平台與多平台 GUI 代理

早期 GUI 代理多聚焦於單平台（single-platform）任務，例如網頁導覽（web navigation）或電腦自動化（computer automation）。這類方法在專屬平台上表現優異，但無法處理跨平台工作流程。近期研究開始朝向多平台 GUI 代理（multi-platform GUI agent）發展，常見做法包括擴充互動資料（如 OpenCUA、OpenMobile）或透過混合 SFT／RL 訓練共享策略。UI-MOPD 的差異在於不把跨平台學習視為單純的資料聚合，而是透過平台特定教師維持行為錨點，從而解決行為模式混合與災難性遺忘。

##### 相對於資料擴充與模型合併

另一條研究路線是模型合併（model merging），即分別訓練平台專屬模型後再合併權重。這種方法雖能保留部分平台特性，但合併後的模型是靜態的，無法根據目前環境動態調整行為。UI-MOPD 的平台條件化教師路由（Platform-Conditioned Teacher Routing）讓單一共享策略在執行階段依據平台標識啟動對應行為模式，具備更高的彈性與可擴展性。

##### 限制與未解決問題

儘管 UI-MOPD 在電腦與行動平台取得進展，仍存在若干限制：

- **平台覆蓋率（platform coverage）有限**：目前僅涵蓋電腦與行動兩大平台，尚未納入網頁（web）或其他新興介面（如 AR/VR、車載系統）。
- **絕對成功率仍有提升空間**：MobileWorld 的 12.0% 雖是顯著相對進步，但絕對值仍低，顯示行動平台長程互動仍是極具挑戰的問題。
- **教師品質依賴**：蒸餾效果受限於平台特定教師的品質；若教師本身在某類任務上有偏誤，學生策略會繼承該偏誤。
- **計算成本**：維護並推理多個教師模型會增加訓練與部署開銷，特別是在需要大規模在線 rollout 的場景。
- **平台標識需預先已知**：目前路由依賴明確的平台標籤，對於平台邊界模糊或混合介面的情境可能不夠靈活。

#### 未來研究方向

1. **擴展至更多平台與網頁環境**  
   將 UI-MOPD 從電腦與行動裝置延伸至網頁（web）、物聯網裝置、AR/VR 等異質 GUI 環境，並探討平台標識自動偵測的可能性。

2. **動態教師路由與混合專家模型**  
   目前路由是硬分派（hard routing）至單一平台教師。未來可研究基於狀態的軟路由（soft routing）或混合專家模型（Mixture-of-Experts，MoE），讓代理在混合介面中同時參考多個教師。

3. **結合離線示範與在線強化學習**  
   在 Uni-GUI 的離線軌跡上進行預訓練，再透過 UI-MOPD 進行在線微調，可能進一步提升樣本效率與最終效能。

4. **長程規劃與獎勵塑形**  
   針對 MobileWorld 等長程任務，設計更細緻的子目標獎勵（subgoal reward）與規劃模組，以提升絕對成功率。

5. **持續學習的任務邊界未知設定**  
   目前假設平台標籤已知。未來可研究無任務邊界（task-free continual learning）的 GUI 代理，讓模型自動發現並適應新平台。

6. **安全性、隱私與可解釋性**  
   隨著 GUI 代理能跨平台操作，動作的可解釋性、錯誤恢復能力以及對敏感操作的防護機制將成為重要課題。

7. **從更強教師進行蒸餾**  
   探索使用更大規模或具備工具使用能力（tool-use capabilities）的專有模型作為教師，以提升平台特定行為的品質上限。

8. **跨平台遷移學習的理論分析**  
   建立行為先驗蒸餾與災難性遺忘緩解之間的理論連結，幫助設計更穩定的持續學習演算法。

## 論文問答

**Q1：UI-MOPD 主要想解決什麼問題？**
A：UI-MOPD 旨在解決多平台 GUI 代理的持續學習問題，特別是當代理需要在電腦、行動裝置等異質 GUI 環境之間切換時，如何同時具備跨平台適應能力與平台特定行為保留能力。現實工作流程往往橫跨多種平台，因此代理不能僅精通單一平台，而必須根據不同環境採取對應的互動慣例。然而，現有高品質且可執行的跨平台互動軌跡仍然稀少，而不同平台的動作語義差異又會導致行為模式混合與災難性遺忘，這正是本文要處理的核心挑戰。

**Q2：為什麼現有的聯合訓練或持續訓練方法難以直接應用於多平台 GUI 代理？**
A：現有方法多半將跨平台學習視為單純的資料聚合或異質訓練訊號混合，例如直接進行混合監督式微調或混合強化學習。這種做法容易產生過度平均化的策略，因為電腦與行動平台的動作語義不同，例如「返回上一頁」在電腦可能是關閉視窗，在行動裝置則是按下返回鍵。若不加區分地混合這些訊號，代理會混淆互動慣例，造成平台特定能力退化，並在持續學習新平台時遺忘舊平台的行為模式。

**Q3：為什麼保留平台特定的互動慣例對跨平台 GUI 代理如此重要？**
A：不同 GUI 平台雖然共享高層次的介面推理能力，例如理解螢幕內容與規劃操作步驟，但在低層級動作上卻有截然不同的慣例與可供性。如果代理無法區分這些慣例，就可能把適合電腦的動作錯誤地套用到行動裝置，導致任務失敗。因此，建立穩定的平台特定行為錨點，是讓共享策略在跨平台環境中正確運作的關鍵，也是 UI-MOPD 設計多教師機制的動機。

**Q4：UI-MOPD 的核心方法架構是什麼？**
A：UI-MOPD 提出多平台在線策略蒸餾（Multi-Platform On-Policy Distillation），並結合平台條件化教師路由（Platform-Conditioned Teacher Routing）。在每次 rollout 時，系統會根據目前環境動態選擇對應的平台特定教師，再將該教師保留的平台特定行為先驗蒸餾到共享策略中。這種環境條件化的策略對齊方式，讓單一共享策略能夠在不同平台啟動不同的互動模式，同時避免不同平台的行為訊號被無差別混合。

**Q5：平台條件化教師路由的設計目的與運作邏輯為何？**
A：平台條件化教師路由的主要目的是根據目前環境決定應該由哪一位平台特定教師提供蒸餾目標，從而為共享策略提供穩定的行為錨點。當代理處於電腦環境時，路由會選擇電腦教師，讓策略對齊原生電腦互動模式；處於行動環境時則切換至行動教師。這種設計確保不同平台的動作語義不會在優化過程中互相干擾，有助於緩解行為模式混合與災難性遺忘。

**Q6：Uni-GUI 資料集在本研究中扮演什麼角色？又是如何建構的？**
A：Uni-GUI 是本文建構的高品質跨平台 GUI 互動資料集，為 UI-MOPD 提供穩定且可執行的訓練基礎。研究團隊先建立統一的跨平台資料收集框架，以一致的動作介面與日誌格式從電腦與行動環境中收集互動資料，分別取得約 11 萬步與 5 萬步的原始軌跡。經過嚴格的篩選與品質控管後，最終形成約 1 萬條高品質跨平台互動軌跡，彌補了現有資料集在平台覆蓋率與動作品質上的不足。

**Q7：實驗採用哪些基準與評估指標？**
A：實驗主要在 OSWorld 與 MobileWorld 兩個互動式環境基準上進行，分別對應電腦平台與行動平台。評估指標為任務成功率（task success rate），用來衡量代理在長程、以平台為基礎的互動任務中完成使用者目標的能力。這兩個基準能夠檢驗代理是否真正理解螢幕內容並執行正確的介面層級動作，而非僅具備靜態介面理解能力。

**Q8：UI-MOPD 在主要實驗中取得了什麼成果？**
A：在 OSWorld 上，UI-MOPD 達到 38.2% 的任務成功率，相較於基礎模型提升 12.7%；在 MobileWorld 上則達到 12.0%，相對提升 55.8%。值得注意的是，這兩個平台同時都獲得改善，顯示 UI-MOPD 並未為了適應新平台而犧牲既有平台的能力。這些結果說明多教師在線策略蒸餾能夠在跨平台能力保留與新平台適應之間取得較佳平衡。

**Q9：跨平台能力轉移的分析帶來什麼啟示？**
A：實驗結果顯示，無論是電腦環境還是行動環境，UI-MOPD 都能帶來正向增益，這代表共享策略學會了平台感知的互動模式。透過平台條件化蒸餾，策略能夠根據環境脈絡啟動不同的互動行為，而不是學到一個過度泛化卻忽略平台細節的平均策略。這也暗示平台特定教師不僅提供額外監督，更扮演穩定行為錨點的角色，使持續學習過程更為穩健。

**Q10：UI-MOPD 在實務上可應用於哪些場景？**
A：UI-MOPD 可應用於跨裝置個人助理，例如同時操作電腦與手機完成預訂、查詢與檔案管理等任務。它也適用於企業流程自動化，讓單一代理在不同平台的應用程式之間執行重複性工作流程。此外，對於需要長期持續學習新平台或新應用程式的智慧代理系統，UI-MOPD 提供了一個減少災難性遺忘的訓練範式。

**Q11：若將 UI-MOPD 產品化，需要考慮哪些工程與設計議題？**
A：首先需要維護統一的動作介面與日誌格式，並為每個目標平台準備高品質的平台特定教師。其次，平台條件化教師路由必須能準確偵測目前環境，否則會將錯誤的行為先驗蒸餾給共享策略。此外，持續學習管線需要包含資料品質控管、安全防護機制與線上監控，以確保代理在學習新平台時不會產生危險或無效的動作。

**Q12：這項研究對 GUI 代理領域可能帶來什麼影響？**
A：UI-MOPD 將 GUI 代理的研究從單平台執行推向持續性多平台適應，強調跨平台學習不只是資料規模的擴充，更需要處理異質互動慣例。它證明了多教師在線策略蒸餾可以作為緩解災難性遺忘與行為混合的有效手段。這種以平台條件化方式保留行為先驗的思路，也可能啟發未來在網頁、桌面與行動裝置之外更多異質環境中的代理設計。

**Q13：這項研究有哪些可能的限制？**
A：目前實驗主要聚焦於電腦與行動兩種平台，尚未涵蓋網頁或其他更多樣的 GUI 環境，因此泛化性仍有待驗證。Uni-GUI 雖經過篩選，但資料規模與任務多樣性相較於大型單平台資料集仍屬有限。此外，平台特定教師本身的品質會直接影響蒸餾效果，若教師在某些平台的能力不足，共享策略也可能繼承這些缺陷。

**Q14：UI-MOPD 在哪些情況下可能會失敗？**
A：在極為複雜的長程任務中，若狀態與動作之間的對齊不夠精確，代理可能會累積錯誤並偏離目標。當平台特定教師對某些罕見互動慣例的覆蓋不足時，共享策略也可能無法正確觸發對應行為。此外，若平台條件化路由誤判目前環境，就會把錯誤平台的行為先驗注入策略，導致執行出不適當的介面層級動作。

**Q15：未來可以朝哪些方向延伸這項研究？**
A：未來可將 UI-MOPD 擴展到網頁、遊戲介面或嵌入式裝置等更多異質平台，並探索更強大的平台自動識別與教師動態生成機制。另一方面，可以結合更精細的獎勵設計與強化學習演算法，進一步提升長程任務的成功率。最後，研究零樣本跨平台轉移與終身學習設定，將有助於讓 GUI 代理在持續接觸新平台時，仍能保持穩定且可解釋的行為。

## 實務應用指南

### 適用場景

1. **跨裝置企業流程自動化**  
   同一套 GUI 代理需依序操作 Windows／macOS 辦公軟體與 Android／iOS 企業 App，例如自動完成報表填寫、審批簽核與行動裝置通知確認。UI-MOPD 可在新增行動平台任務時，保留電腦平台已學會的快捷鍵、選單操作等互動慣例。

2. **多平台客服與技術支援機器人**  
   客服代理必須在網頁後台、桌面 CRM 與行動客服 App 之間切換，處理查詢、建單與派工。透過平台條件化教師路由，代理能根據目前環境啟動對應的互動模式，降低誤把「關閉視窗」當成「返回鍵」的風險。

3. **無障礙輔助操作代理**  
   為視障或行動不便使用者提供跨平台語音指令操作，例如同時控制電腦瀏覽器與手機相簿。持續學習機制讓代理在新增 App 支援時，不致遺忘既有平台的無障礙操作順序。

4. **跨平台軟體測試與品質保證**  
   自動化測試腳本需在桌面與行動版本執行相同使用者故事。利用 Uni-GUI 與 UI-MOPD，可建立共享策略並透過平台特定教師維持各平台原生手勢與輸入方式的差異。

5. **個人化數位助理**  
   協助使用者在筆電、平板與手機間無縫完成任務，例如「把電腦上的會議摘要傳到手機備忘錄」。多平台在線策略蒸餾讓助理持續適應新裝置，同時保留舊裝置的操作習慣。

### 實作前置條件

**資料條件**
- 需要大量且可執行的跨平台互動軌跡，建議參考 Uni-GUI 的建構流程：統一動作介面與日誌格式、嚴格過濾無效動作與狀態動作對齊錯誤。
- 每個平台至少需數千條高品質軌跡作為教師模型的訓練基礎；若無現成資料，需具備在電腦（OSWorld）與行動（MobileWorld）模擬環境中收集軌跡的能力。

**運算條件**
- 多模態基礎模型微調與強化學習需要 GPU 叢集（建議至少數十 GB 視訊記憶體），並支援大規模在線 rollout 與多教師推理。
- 需能同時維護多個平台特定教師模型與一個共享策略，對記憶體與儲存空間要求較高。

**技術與人才條件**
- 熟悉多模態大型語言模型（MLLM）微調、強化學習（RL）與知識蒸餾。
- 具備 GUI 自動化與模擬環境經驗，例如 OSWorld、MobileWorld 或 Android Emulator。
- 了解持續學習與災難性遺忘的緩解策略，能設計平台條件化獎勵與蒸餾目標。

---

### 實作步驟建議

1. **建立統一資料收集管線**  
   參考 Uni-GUI 的做法，設計跨平台一致的動作空間（點擊、打字、滑動等）與日誌格式，並在電腦與行動模擬環境中自動化收集軌跡。

2. **品質控管與資料過濾**  
   移除無效動作、狀態動作不一致與任務粒度不均的軌跡，保留接近 10K 等級的高品質跨平台互動資料。

3. **訓練平台特定教師模型**  
   針對每個目標平台（如電腦、行動）各自訓練或微調一個教師模型，使其充分掌握該平台的互動慣例與原生行為先驗。

4. **建構共享策略與平台條件化路由**  
   設計共享策略網路，並依據目前環境動態選擇對應的平台特定教師。將平台識別符或環境特徵作為條件輸入，實現平台條件化蒸餾。

5. **執行多教師在線策略蒸餾**  
   在 rollout 過程中，由對應教師產生行為分布，並透過蒸餾損失將平台特定行為先驗轉移至共享策略，同時結合任務獎勵進行策略最佳化。

6. **持續學習與能力保留評估**  
   依序加入新平台資料，定期在舊平台基準（OSWorld、MobileWorld）上評估任務成功率，監控災難性遺忘與平台特定能力退化。

7. **產品化部署**  
   將訓練好的共享策略封裝為可呼叫的代理服務，整合至現有自動化流程或對話系統中，並保留平台識別與錯誤回退機制。

---

### 潛在風險與注意事項

- **行為模式混合**  
  若教師選擇或平台條件輸入設計不當，共享策略可能學到「平均化」的動作分布，導致在電腦上誤用行動手勢。建議強化平台識別特徵，並在蒸餾時明確區分各教師的責任範圍。

- **災難性遺忘**  
  持續加入新平台資料時，舊平台成功率可能下降。除了多教師蒸餾外，可輔以經驗回放（experience replay）或彈性權重鞏固（EWC）等持續學習機制。

- **資料品質不足**  
  低品質軌跡會直接污染教師模型與共享策略。必須建立自動化驗證流程，例如檢查動作是否可執行、最終狀態是否達成目標。

- **運算成本高昂**  
  多教師在線推理與 rollout 會顯著增加訓練開銷。建議先在小規模子集上驗證方法有效性，再擴大到完整資料集。

- **平台差異過大導致遷移困難**  
  若動作空間差異過大（如僅有鍵盤的終端機 vs. 觸控螢幕），共享策略可能難以泛化。此時應考慮分層動作介面或模組化策略設計。

---

### 與其他技術的整合建議

- **RAG 與知識庫**  
  將各平台的操作手冊、常見任務流程與介面截圖存入向量資料庫，讓代理在執行前檢索平台特定提示，補強蒸餾所得的行為先驗。

- **現有自動化框架**  
  可與 Selenium、Appium、PyAutoGUI 等工具結合，由 UI-MOPD 負責高階決策，底層工具負責精確執行動作並回傳環境狀態。

- **對話式代理與 LLM 編排**  
  將 UI-MOPD 作為工具節點接入 LangChain、LangGraph 或自研對話系統，讓語言模型根據使用者目標決定是否呼叫 GUI 代理，以及在哪個平台上執行。

- **監控與可解釋性工具**  
  整合軌跡視覺化與獎勵分解工具，追蹤平台條件化路由的決策依據，便於除錯與持續最佳化。

- **模型合併與模型編輯技術**  
  在部署前可評估是否透過模型合併進一步整合各平台教師的知識，但需注意可能破壞平台條件化行為的風險。

### 給不同背景讀者的閱讀建議

**初學者**  
建議先從摘要與適用場景開始，理解「為什麼需要跨平台 GUI 代理」以及「持續學習會帶來什麼問題」。接著閱讀方法概述與案例研究，建立對平台條件化教師路由的直覺，技術細節可暫時略過。

**AI 工程師**  
重點閱讀 Method 中的多教師在線策略蒸餾、平台條件化教師路由、獎勵設計與訓練目標，並參考實作步驟建議與潛在風險。實作時需特別注意統一動作介面、教師模型訓練與共享策略的蒸餾損失實作。

**研究人員**  
建議深入分析跨平台能力轉移實驗與靜態理解定位評估，思考多教師蒸餾與持續學習理論的結合點。可進一步探討教師數量擴展、動態教師選擇策略，以及與其他災難性遺忘緩解方法的比較。

**產品經理**  
聚焦適用場景、主要結果與整合建議，評估 UI-MOPD 對自家多平台自動化需求的適配度。需特別關注資料收集成本、運算資源投入與平台特定行為錯誤的商業風險，並規劃分階段上線與人機協作回退機制。
