## 摘要翻譯

我們提出 Endless Exam（無盡考試），一項涵蓋十四個數學構造問題（mathematical construction problems）參數化家族（parameterised families）的基準測試（benchmark），以可驗證分數（verifiable scores）區分達到已發表數學前沿（published mathematical frontiers）之前與超越之後的進展。每個提交物件（submitted object）均會自動檢查有效性（validity），並相對於已發表前沿（published frontier）或構造基線（construction baseline）賦予相對品質分數（relative quality score），且不將改進上限設為 1（without capping improvements at 1）。此基準測試從開放數學問題（open mathematical problems）中汲取長期挑戰（long-term challenges），並透過改變參數（varying parameters）產生更大規模的實例（instances）。簡潔證書（Compact certificates）使大型構造無需列出每個元素即可驗證。在對九個模型、六十九個不同實例（distinct instances）的評測中，即使三十個已發表前沿參考解（published-frontier references）皆未被超越，連續品質分數（continuous quality scores）仍能區分表現差異。大小-品質曲線（Size-quality curves）顯示構造品質（construction quality）如何隨問題規模增加而變化。我們釋出（release）生成器（generators）、驗證器（verifiers）、參考解（references）、模型回應（model responses）與分析（analysis），以支持在人類前沿（human frontiers）之前與超越之後的持續衡量（continued measurement）。

### 核心貢獻（3～5點）
- 提出 Endless Exam（無盡考試）基準測試，涵蓋十四個參數化家族的數學構造問題，並以可驗證分數區分達到已發表數學前沿之前與超越之後的進展。
- 設計自動驗證機制與相對品質分數，相對於已發表前沿或構造基線評分，且不將改進上限設為 1，使進步幅度可被持續追蹤。
- 透過改變參數從開放數學問題中生成更大規模實例，並以簡潔證書支援大型構造的高效驗證。
- 對九個模型在六十九個實例上進行評測，以連續品質分數與大小-品質曲線分析模型表現，即使未超越已發表前沿仍能區分差異。
- 釋出生成器、驗證器、參考解、模型回應與分析，支持在人類前沿之前與超越之後的長期持續衡量。

### 適合對象
人工智慧研究者、數學家、基準測試設計者，以及關注人工超級智慧（ASI）發展與長期評測框架的學術與產業研究人員。特別適合對數學構造問題、可驗證評分機制，以及模型能力超越人類前沿之衡量方法感興趣的讀者。

## 深度分析

#### 方法論解析

##### 從證明導向轉向構造導向的評量
Endless Exam（無盡考試）的核心設計是將評量對象從「證明一個命題」轉為「構造一個具體數學物件」。在 mathematical construction problems（數學構造問題）中，模型必須產生一個可被客觀檢驗的 object（物件），例如一個 progression-free set（無等差數列集合）、一個 graph（圖形）、或一個 code（碼）。這種設計有兩個優勢：第一，validity（有效性）可以透過數學性質自動檢查；第二，quality（品質）可以透過物件的規模、大小或效率等指標連續衡量。相較於許多數學推理 benchmark（基準測試）依賴人工評分或模型 judge，Endless Exam 的 automatic verification（自動驗證）機制大幅降低了主觀性與 reward hacking（獎勵駭取）的風險。

##### 參數化家族與可擴充實例
本研究選定十四個 parameterised families（參數化家族），透過改變 dimension（維度）、graph degree（圖的度）、code length（碼長）等參數，產生 69 個 evaluation instances（評估實例）。這種設計讓 benchmark 具有 expandable suite（可擴充套件）的特性：當模型在某個規模表現飽和時，只需放大參數即可產生 harder instances（更困難的實例）。例如 progression-free set 在 F_5^n（n 維模 5 向量空間）中，改變 n 就得到不同難度的題目。這直接回應了 benchmark saturation（基準飽和）的問題，使 Endless Exam 能夠作為朝向 artificial superintelligence (ASI)（人工超級智慧）的 long-term challenges（長期挑戰）。

##### 相對品質分數與無上限衡量
評分採用 relative quality score（相對品質分數），計算方式為模型構造的 objective value（目標值）除以 published frontier（已發表前沿）或 construction baseline（構造基線）的對應值。這是一種 uncapped measure（無上限衡量指標）：若模型結果超越參考解，分數可超過 1，且改進的 magnitude of improvements（改進幅度）會被保留下來；若構造 invalid（無效），則分數為 0。這種 common scale（共同尺度）讓不同 construction objectives（構造目標）之間可以橫向比較，也讓評量能區分「接近人類前沿」與「超越人類前沿」兩個階段。

##### 自動驗證與簡潔證書
為了處理大型構造，Endless Exam 引入 compact certificates（簡潔證書）與代數驗證技術。例如某些 submitted codes（提交的碼）擁有超過一兆個 codewords（碼字），無法逐一列舉檢查；此時驗證器利用代數結構或生成規則確認其性質。這使得 automatic verification（自動驗證）能夠擴展到極大規模的物件，而不必知道真正的 optimum（最佳值）。

##### 防範獎勵駭取
由於分數完全基於提交的物件本身，而非模型的說明文字，因此模型無法透過 persuasive prose（說服性文字）或 unsupported quality claims（未經證實的品質宣稱）來提高分數。這對於評估 superintelligence（超級智慧）尤為重要，因為隨著模型能力增強，傳統基於文字評分的 benchmark 更容易被操縱。

#### 實驗數據解讀

##### 評測配置與模型陣容
研究評估了九個模型，共十四種 tool-free configurations（無工具配置），包括 GPT-6 Astra、GPT-5.6 Luna、Claude Fable 5.1、Claude Opus 5.5、DeepSeek V4.1 Flash、Qwen3.8-27B，以及 Qwen3.5（4B / 9B / 27B）。此外，Astra、Luna 與 Opus 5.5 也在 high effort with code and web access（高強度搭配程式碼與網路存取）的條件下進行評測，以檢驗工具使用與 reasoning effort（推理努力）的影響。

##### 整體表現：尚未跨越已發表前沿
實驗結果顯示，在所有 30 個 published-frontier references（已發表前沿參考解）上，沒有任何模型能夠 surpass（超越）人類最佳已知構造。這說明儘管當前 leading models（領先模型）在許多傳統 benchmark 上已接近飽和，但在這類需要真正新想法的數學構造問題上，仍與人類前沿存在明顯差距。同時，由於分數是 uncapped（無上限）的，這個結果也保留了未來模型突破時的衡量空間。

##### 連續分數與大小-品質曲線
Endless Exam 使用 continuous quality scores（連續品質分數），因此即使所有模型都未達參考解，仍然可以細緻區分它們的相對表現。研究進一步繪製 size-quality curves（大小-品質曲線），觀察 construction quality（構造品質）如何隨 problem size（問題規模）變化。這類曲線對於理解模型的 scaling behavior（規模化行為）非常重要：若品質隨規模增加而快速下降，表示模型缺乏可擴展的構造策略；若曲線相對平穩，則表示模型可能掌握了某種結構化方法。

##### 工具與高推理努力的效應
雖然具備 code and web access（程式碼與網路存取）以及 high reasoning effort（高推理努力）的設定通常能提升表現，但實驗顯示這些輔助尚未足以讓模型突破 published frontier（已發表前沿）。這暗示當前模型的瓶頸不在於計算資源或工具使用，而在於發現新數學構造的能力本身。對於未來評估，這也提供了一個清晰的訊號：當模型開始穩定超越參考解時，才是真正接近 ASI（人工超級智慧）的轉折點。

#### 與現有研究的比較

##### 與數學推理基準的差異
相較於 Humanity’s Last Exam、FrontierMath、IMProofBench、FirstProof、IMO-AnswerBench 等以證明或解答為主的 benchmark，Endless Exam 專注於 construction problems（構造問題）。這些現有基準大多評估模型是否能正確回答已有人類解答的問題，而 Endless Exam 的題目來自 open mathematical problems（開放數學問題），其 optimum（最佳值）往往未知。此外，Endless Exam 提供 uncapped score（無上限分數）與 automatic evaluation（自動評估），這是許多研究級數學基準所不具備的。

##### 與可驗證構造/問題生成研究的關係
MathConstruct 與 MathConstraint 同樣採用自動檢查構造的方式，但它們主要針對奧林匹亞或約束滿足問題，且分數多為二元或有限等級。HorizonMath 雖然也評估開放問題並自動驗證，但採用的是「解決比例」這類離散指標。Endless Exam 的改進在於引入 relative quality（相對品質）與 continuous scores（連續分數），能夠測量「部分進步」與「超越幅度」。

##### 相對於數學發現系統的定位
FunSearch、AlphaEvolve、AlphaTensor 等系統已經在特定數學構造上取得突破，但它們通常針對單一問題設計，難以橫向比較。Endless Exam 提供一個 common framework（共同框架），讓不同模型、演算法與問題家族能在相同指標下比較。這對於追蹤 AlphaEvolve 這類系統的 generalisation（泛化能力）與 scaling 行為特別有價值。

##### 限制與待解決問題
儘管設計嚴謹，Endless Exam 仍有若干限制。首先，它僅涵蓋可自動驗證的構造問題，無法評估需要全新證明或理論框架的數學發現。其次，reference（參考解）的選擇會影響 relative quality score（相對品質分數）；若文獻中的 frontier 被更新，整個分數尺度需要重新校正。第三，某些家族的驗證計算成本可能隨規模指數增長，需要持續優化 verifiers（驗證器）。最後，模型可能針對 verifier 的檢查邏輯進行 exploit（利用），因此 verifier 的安全性與完備性需要長期維護。

#### 可重現性評估

##### 開源釋出內容
本研究將 generators（生成器）、verifiers（驗證器）、references（參考解）、model responses（模型回應）與 analysis（分析）全部公開於 GitHub，符合 open-source benchmark（開源基準測試）的標準。這讓其他研究者能夠重新執行評估、加入新的 construction families（構造家族）、或改進驗證邏輯。

##### 模型輸出與 API 再現性
雖然 benchmark 的資料與程式碼完全開源，但模型輸出來自商業 API，其 exact reproducibility（精確再現性）受到 API 供應商更新、temperature 設定與抽樣隨機性的影響。研究應已記錄所使用的模型版本與設定，但外部研究者若要完全重現相同數字，可能需要固定隨機種子與 API 版本。模型 weights（權重）本身並未公開，這是當前大型語言模型研究的普遍限制。

##### 驗證器與參考解的可信度
驗證器的正確性直接決定分數的可信度。由於題目來自已發表的數學文獻，reference 的來源相對透明；但對於開放問題，reference 僅代表「目前已知最佳」，並非真正的 optimum（最佳值）。社群可以透過提交更優構造來更新 reference，這也是 Endless Exam 設計為可持續演進 benchmark 的原因。

#### 未來研究方向

##### 擴充題目家族與動態難度
未來可以加入更多數學領域的 construction families（構造家族），例如數論、代數幾何、組合設計與最佳化理論。同時，可以發展 adaptive instance generation（自適應實例生成），根據模型當前表現動態調整參數，使 benchmark 始終處於適當難度。

##### 與程式搜尋/演化演算法的結合
Endless Exam 非常適合作為 FunSearch、AlphaEvolve 等數學發現系統的評估平台。未來研究可以探討這些系統在 69 個 instances（實例）上的表現，並比較它們與大型語言模型在發現新構造上的優劣。

##### 形式化證明與證書標準化
目前 compact certificates（簡潔證書）主要用於驗證構造的有效性。未來可以進一步將其與 Lean 等形式化證明工具整合，讓模型不僅提交構造，還能提交構造正確性的 machine-checkable proof（機器可檢查證明），提升可信度與理論深度。

##### 長期追蹤與社群排行榜
建立公開 leaderboard（排行榜）並持續追蹤模型進展，是發揮 Endless Exam 長期價值的關鍵。透過社群貢獻新的 constructions（構造）、references（參考解）與 verifier improvements（驗證器改進），可以使這個 benchmark 真正成為測量「before and beyond human frontiers（達到人類前沿之前與超越之後）」的持續平台。

##### 工具使用策略與可解釋性研究
未來也可以深入分析模型在具備 code and web access（程式碼與網路存取）時的策略差異，例如它們是否會搜尋文獻、執行搜尋演算法、或進行自我驗證。這將有助於理解模型在數學發現過程中的認知機制與限制。

## 論文問答

**Q1：Endless Exam 主要想解決什麼樣的評測問題？**

A：Endless Exam 針對的是現有基準測試逐漸飽和、難以區分頂尖模型進步的問題。許多語言模型基準已經出現高分天花板，例如 ARC-AGI-3 半私有測試集上 GPT-6 Astra 在特定設定下達到 99.9%，使得傳統分數無法再細緻反映能力差異。因此，本研究提出一個以數學構造為核心的長期評測框架，讓模型即使在超越人類最佳結果之後，仍然有持續可量化的進步空間。

**Q2：現有的數學推理或構造基準為什麼不足以支撐「超越人類前沿」的測量？**

A：現有基準大多採用固定題庫與二元或上限為 1 的分數，例如證明題只記錄「對／錯」，或構造題的分數最高只到參考解的 100%。這種設計在模型接近或達到人類最佳解後就會飽和，無法區分小幅改進與重大突破。此外，許多研究級證明基準仍需要人工評分，而自動評分的構造基準又常常把改進幅度截斷，無法保留超越文獻最佳值的真正幅度。

**Q3：為什麼數學構造問題特別適合用來衡量朝向超級智慧的進展？**

A：數學構造問題要求模型提出一個具體物件，其有效性可以自動驗證，而品質可以透過目標函數直接比較，例如集合大小、圖的頂點數或矩陣乘法所需的純量乘法次數。這些問題通常與開放數學難題相連，找到更好的構造往往需要新想法，而不只是記憶或模式比對。同時，透過改變維度、度數、碼長等參數，可以持續產生更大、更難的實例，形成幾乎無窮的評測空間。

**Q4：Endless Exam 的核心評測流程是什麼？**

A：流程分為三步：首先，模型針對某個參數化實例提交一個構造物件；接著，驗證器自動檢查該物件是否滿足所有數學條件；最後，系統計算其目標值，並以相對品質分數與已發表前沿或基線構造進行比較。這個分數不設上限，因此即使提交的構造超越文獻最佳解，也能準確反映改進幅度。整個過程不依賴模型裁判或人工評分，而是直接基於物件本身的數學性質進行判斷。

**Q5：相較於其他數學基準，Endless Exam 最關鍵的創新是什麼？**

A：最關鍵的創新是將「無上限的相對品質分數」與「可擴充的參數化構造家族」結合在一起，形成一個能持續測量進步的共同尺度。不同構造目標可以透過相對品質統一比較，而且分數不會因為達到參考解就被截斷，能保留超越人類前沿後的實際差距。此外，簡潔證書與代數驗證機制讓系統能處理大到無法逐一列舉的物件，例如超過一兆個碼字的編碼。

**Q6：在設計上，Endless Exam 做了哪些重要選擇來確保評測的公平性與可擴展性？**

A：設計上選擇以「提交的物件」為評分依據，而非依賴模型生成的解釋文字，這大幅降低了透過說服性語言獲取不當分數的風險。驗證過程完全自動化，並且不需要知道理論最佳值，因此即使在最佳解仍未知的開放問題上也能評分。為了處理大規模實例，研究團隊採用緊湊描述與代數證書，讓驗證器不必窮舉每個元素就能確認構造有效。

**Q7：本研究實際評測了哪些模型與實例？**

A：研究評測了九個模型，共十四種無工具配置，包括 GPT-6 Astra、GPT-5.6 Luna、Claude Fable 5.1、Claude Opus 5.5、DeepSeek V4.1 Flash，以及多個尺寸的 Qwen 模型。此外，也針對 Astra、Luna 與 Opus 5.5 在高強度推理下搭配程式碼與網路存取進行額外測試。評測對象涵蓋十四個問題家族、共 69 個實例，領域包括無等差數列集合、圖論、編碼理論與代數設計等。

**Q8：實驗中最主要的結果是什麼？**

A：在所有 30 個已發表前沿參考解中，沒有任何一個被參與評測的模型超越，顯示當前模型在這些數學構造問題上尚未突破人類最佳水準。然而，連續的相對品質分數成功區分了不同模型與配置之間的表現差異，即使它們都未達到文獻最佳解。大小—品質曲線進一步揭示，隨著問題規模增加，模型構造品質的變化趨勢，提供了比單一分數更豐富的診斷資訊。

**Q9：研究中有哪些對照或消融分析值得注意？**

A：研究比較了無工具配置與高強度搭配程式碼、網路存取的配置，以觀察外部工具對構造品質的影響。同時，透過不同規模的 Qwen 模型，可以分析模型參數量與數學構造能力之間的關係。相對品質分數的設計也讓研究者能夠比較同一模型在不同參數大小實例上的表現衰減，進而評估其泛化與規模化能力。

**Q10：Endless Exam 在實務上可以應用在哪些場景？**

A：它可以作為追蹤人工超級智慧進展的長期指標，幫助研究機構判斷模型是否開始在開放數學問題上超越人類。對於數學發現系統如 FunSearch、AlphaEvolve 或 AlphaTensor，Endless Exam 提供了一個統一框架來比較不同方法在多個家族與規模下的表現。此外，開發者也能利用它來篩選具有創新構造能力的模型，並監控新版本在持續變難的實例上的穩定性。

**Q11：若要把 Endless Exam 產品化或開放給社群使用，需要考慮哪些因素？**

A：首先必須確保生成器、驗證器與參考解的穩定性與正確性，因為任何驗證漏洞都可能導致分數失真或被投機利用。其次，大型構造的驗證雖可透過簡潔證書加速，但仍需足夠的運算資源與清晰的成本規劃。最後，為了維持長期活力，平台需要開放社群貢獻新的構造、問題家族與驗證改進，並建立透明的版本控制與參考解更新機制。

**Q12：這項研究對 AI 評測領域與數學研究可能帶來什麼影響？**

A：它推動基準測試從「固定題庫、追求滿分」轉向「可無限擴展、重視改進幅度」的新典範，有助於緩解飽和問題。對數學研究而言，自動化驗證與開放資料能降低驗證新構造的門檻，加速人機協作的探索過程。長期來看，這種框架也可能成為評估 AI 是否能產生真正原創數學想法的重要參考依據。

**Q13：作者承認了哪些限制？**

A：目前 Endless Exam 只涵蓋構造型問題，並未處理需要完整數學證明的命題，因此無法全面評估模型的理論推理能力。69 個實例雖然橫跨 14 個家族，但仍只是數學廣袤領域中的一小部分，可能無法代表所有類型的開放難題。此外，儘管驗證是自動的，驗證器本身的正確性與參考解的時效性仍需要持續維護與社群監督。

**Q14：在實驗中可能出現哪些失敗或值得警惕的情況？**

A：如果模型提交的構造違反了數學條件，例如包含禁止三元組，驗證器會將其判定為無效並給予零分，這可能導致某些模型在複雜實例上頻繁失敗。模型也可能產生看似合理但缺乏嚴謹支援的敘述，雖然評分以物件為準，但這反映了模型在「說服」與「正確構造」之間的落差。另外，即使給予程式碼與網路存取，模型仍未必能系統性地搜尋到更好的構造，顯示問題本身的困難度。

**Q15：未來可以朝哪些方向擴展或改進 Endless Exam？**

A：未來可以加入更多類型的問題家族，例如拓撲、數論或組合設計，並進一步擴大參數範圍以產生更具挑戰性的實例。驗證器也可以與形式化證明系統如 Lean 整合，讓構造的正確性獲得更強的數學保證。同時，社群可以持續提交新的構造與參考解，使 Endless Exam 成為一個動態更新的共同平台，真正實現「在人類前沿之前與超越之後」的持續衡量。

## 實務應用指南

### 適用場景

1. **前沿推理模型的持續評測**  
   當現有語言模型基準趨近飽和時，Endless Exam 可作為長期追蹤工具，透過無等差數列集合、圖形、碼等參數化家族，持續區分 GPT-6 Astra、Claude Opus 5.5、Qwen3.5 等領先模型在「達到人類前沿之前」與「超越之後」的表現。

2. **數學發現系統的驗證平台**  
   對於 FunSearch、AlphaEvolve 這類以程式演化尋找構造的系統，Endless Exam 提供自動驗證器與相對品質分數，讓研究者確認新構造是否有效，並量化其相對於已發表前沿的改進幅度。

3. **編碼理論與通訊演算法的設計評估**  
   在錯誤更正碼、低密度同位檢查碼等場景中，可利用碼家族產生不同長度與參數的實例，比較模型或演算法產生的碼是否達到更好的速率—距離權衡，並透過簡潔證書驗證大型碼。

4. **奧林匹亞與進階數學教育的題目生成**  
   教師與出題者可藉由生成器自動產生不同難度的構造題，例如改變維度 n 的無等差數列集合問題，並用驗證器即時檢查學生提交物件的有效性與品質。

5. **開放數學問題的群眾協作與長期挑戰**  
   研究社群可將尚未解決的組合、圖論或代數設計問題納入 Endless Exam，透過可驗證分數與公開排行榜，持續收集超越已發表前沿的新構造。

### 實作前置條件

**資料**
- 從官方倉庫取得生成器、驗證器、參考解與已發表前沿資料。
- 準備模型 API 金鑰或本地推論環境，以及用於儲存提交物件與中間結果的資料庫或檔案系統。
- 若要比較自訂構造，需額外蒐集該領域的最佳已知上界與基線構造。

**運算**
- 驗證小型實例（如低維度無等差數列集合）一般只需一般 CPU。
- 大型實例（如包含超過一兆個碼字的編碼）需要高效能運算或分散式驗證，並善用簡潔證書避免窮舉每個元素。
- 執行高強度推理模型時，需預留足夠的 GPU 或 API 預算。

**技能**
- 熟悉 Python 與命令列工具，能閱讀並修改生成器與驗證器。
- 具備組合數學、圖論或編碼理論基礎，以理解各家族的數學限制與目標。
- 了解如何將模型輸出解析為可驗證的提交物件，並具備基準測試工程經驗。

---

### 實作步驟建議

1. **安裝與環境設定**  
   複製 Endless Exam 倉庫，安裝相依套件，並確認生成器與驗證器可在本地執行。

2. **選擇問題家族與參數**  
   依據應用目標挑選 1–3 個家族，例如從無等差數列集合或圖形家族開始，再透過改變維度、度數或長度產生不同難度的實例。

3. **設計模型呼叫與輸出解析管線**  
   將題目敘述與參數餵給模型，並把模型回應轉換為驗證器接受的格式（如點集合、鄰接矩陣或程式碼）。

4. **執行生成與驗證**  
   對每個實例產生題目，讓模型提交物件，再使用驗證器自動檢查有效性。

5. **計算相對品質分數**  
   以已發表前沿或構造基線為分母，計算相對品質；若模型結果超越參考解，分數可超過 1，保留改進幅度。

6. **繪製大小—品質曲線**  
   固定模型與家族，改變參數並觀察構造品質隨問題規模增加的變化，找出模型擅長或衰退的區間。

7. **迭代與貢獻**  
   根據驗證結果調整提示、加入程式碼與網路存取，或改進驗證器，最後將新構造、新家族或分析回饋給社群。

### 潛在風險與注意事項

- **驗證器的正確性風險**  
  若驗證器本身有漏洞，可能誤判無效構造為有效。建議對關鍵家族進行形式化檢查或與獨立實作交叉比對。

- **獎勵駭客與投機性輸出**  
  模型可能產生看似合理但無效的物件，或宣稱不存在的性質。應堅持只根據提交物件的數學性質計算分數，不接受自然語言辯解。

- **參考解過時導致分數失真**  
  已發表前沿會隨時間進步，需定期更新參考基準，否則「超越人類前沿」的門檻會被低估。

- **運算成本爆炸**  
  隨著參數放大，驗證與模型推理成本可能急遽上升。應先在小規模實例上驗證管線，再逐步擴展。

- **過度擬合特定家族**  
  模型可能在少數家族上表現突出，但無法泛化。建議同時評估多個家族，並觀察跨實例的穩定性。

### 與其他技術的整合建議

- **LLM 評測框架**  
  可將 Endless Exam 包裝為 `lm-eval-harness` 或自訂評測腳本的任務，統一管理模型呼叫、快取與指標彙整。

- **MLOps 與實驗追蹤平台**  
  將相對品質分數、大小—品質曲線與無效構造比例記錄到 Weights & Biases、MLflow 等工具，便於長期追蹤不同模型版本的進展。

- **形式化證明輔助器**  
  對於需要更高可信度的家族，可將驗證邏輯移植到 Lean 或 Coq，與 Formal Conjectures 等計畫銜接，強化自動驗證的嚴謹度。

- **數學發現與程式演化系統**  
  把 Endless Exam 的分數作為 AlphaEvolve、FunSearch 等系統的適應度函數，讓程式搜尋在無上限分數下持續優化構造。

- **教育與協作平台**  
  與線上評測系統或學習管理系統整合，讓學生與研究者提交構造後即時取得有效性與相對品質回饋。
