## ⚡ TL;DR

解決推薦模型優化仰賴人工迭代，且LLM同時決定方向與生成假設會在有限預算下搜尋不穩定。

## 摘要翻譯

優化現代推薦模型（recommender models）仍高度依賴工程師手動迭代調整架構、目標函數（objective）與訓練策略（training strategy）。雖然基於大型語言模型（Large Language Model, LLM）的智慧體（agents）可自動化此試誤過程（trial-and-error process），但讓 LLM 同時負責選擇修改方向（modification direction）與產生具體假設（concrete hypotheses），在有限實驗預算（limited experiment budgets）下常導致不穩定搜尋（unstable search）。受此挑戰啟發，我們提出 RecHarness，一個用於自動化推薦模型優化（automated recommender model optimization）的強盜路由式智慧體框架（Bandit-Routed Agentic Harness）。RecHarness 將優化過程拆分為兩個步驟：強盜路由器（bandit router）根據歷史驗證回饋（historical validation feedback）選擇下一個修改方向，而 LLM 則在所選方向內產生具體的優化假設（optimization hypothesis）與可執行的程式碼編輯（executable code edit）。為維持長期探索（long-horizon exploration），RecHarness 採用跳躍盆地機制（jump-basin mechanism），當局部編輯（local edits）陷入停滯（stagnation）時，啟動結構跳躍臂（structural-jump arm）。跨越多個推薦任務（recommendation tasks）、資料集（datasets）與模型骨幹（model backbones），RecHarness 達成更穩定的效能提升（performance improvements），並相較於 LLM 推理搜尋（LLM-reasoning search）更有效地運用有限的試驗預算（trial budget）。於大規模短影片廣告平台（large-scale short-video advertising platform）上進行為期七天的線上 A/B 測試（7-day online A/B test）期間，選出的候選方案（selected candidate）使 ADVV、營收（Revenue）與曝光量（Exposure）分別提升 2.084%、0.534% 與 0.559%。程式碼可於 https://github.com/6lyc/RecHarness 取得。

### 核心貢獻（3～5點）
- 提出 RecHarness，一個強盜路由式智慧體框架，將推薦模型優化拆解為「方向選擇」與「假設生成」兩個步驟，降低 LLM 同時負責兩者所造成的不穩定搜尋。
- 設計跳躍盆地機制與結構跳躍臂，在局部編輯停滯時啟動結構性跳躍，以維持長期探索能力並逃離局部最優。
- 在多個推薦任務、資料集與模型骨幹上驗證，相較於 LLM 推理搜尋，RecHarness 能更穩定地提升效能並更有效運用有限試驗預算。
- 於大規模短影片廣告平台完成為期七天的線上 A/B 測試，選出的候選方案在 ADVV、營收與曝光量上均帶來顯著提升。

### 適合對象
適合推薦系統、機器學習工程自動化，以及基於 LLM 智慧體相關領域的研究人員與工程師；特別是關注如何以自動化方式進行推薦模型架構、目標函數與訓練策略迭代優化，並需在有限實驗預算下穩定提升線上指標的實務工作者。

## 深度分析

#### 方法論解析

RecHarness 將「自動化推薦模型優化（automated recommender model optimization）」重新定義為一個序列決策問題：在有限的試驗預算（trial budget）內，反覆選擇修改方向（modification direction）、執行程式碼編輯（executable code edit）、訓練並取得驗證回饋（validation feedback），最終收斂到比初始模型更強的候選方案（candidate）。其核心設計哲學是「分離高階路由與低階生成」：由 bandit router（強盜路由器）負責在抽象層選擇下一個優化方向，再由 LLM（大型語言模型）在該方向內產生具體的優化假設（optimization hypothesis）與可執行程式碼。這樣的兩階段架構避免了讓 LLM 同時承擔「方向選擇」與「程式碼生成」所導致的不穩定搜尋（unstable search）。

具體而言，RecHarness 會針對目標推薦場景預先定義一組 candidate arms（候選臂），每一條臂對應一個修改方向，例如骨幹架構（backbone architecture）、訓練目標（training objective）、正規化（regularization）、特徵交互設計（feature interaction design）、序列建模選擇（sequence modeling choice）或優化策略（optimization strategy）等。每一輪試驗結束後，系統會根據該臂所產生的驗證分數與執行日誌更新其後驗狀態，並採用 Thompson-style routing（Thompson 採樣式路由）在探索與利用之間取得平衡，從而決定下一条要啟動的臂。這種做法把歷史驗證回饋轉化為結構化的後驗資訊，而不是僅僅把分數壓縮成純量後丟給 LLM 自由聯想。

當 bandit router 選定方向後，LLM 會基於以下資訊生成程式碼修改：當前最佳候選模型（incumbent）、執行日誌、驗證趨勢，以及從實驗記憶中蒸餾出的 Experiment Skill（實驗技能）。Experiment Skill 可視為一種動態更新的文字型優化訊號（textual optimization signal），它記錄了過去試驗中哪些修改在什麼情境下有效、哪些導致訓練不穩定或失敗，從而引導 LLM 提出更有方向性的程式碼更新（directed code updates）。這與 Reasoning-as-Gradient 的概念一脈相承，但 RecHarness 進一步把這些文字回饋嵌入到一個長期記憶與結構化路由框架中。

為了支撐長期探索（long-horizon exploration），RecHarness 設計了 jump-basin mechanism（跳躍盆地機制）。當局部編輯（local edits）在一段試驗內持續停滯（stagnation）——例如連續多輪都無法顯著提升驗證指標——系統會啟動 structural-jump arm（結構跳躍臂），進行影響層級更大的結構性變更，例如替換整個模型家族（model family）或重新設計損失函數。這相當於在優化景觀中從當前盆地跳脫到另一個盆地，避免被困在局部最佳解。對於這類高影響力的變更，RecHarness 還支援 retuning（重新調參訓練），因為架構或目標函數的改變通常需要配合新的超參數設定才能發揮效果。

整體來看，RecHarness 的優勢在於把「工程搜尋空間（engineering search space）」從固定推薦模板（fixed recommender template）擴展到程式碼層級的變更，同時透過 bandit 機制提供演算法層級的探索紀律，降低純 LLM 推理搜尋（LLM-reasoning search）的變異性與預算浪費。

#### 實驗數據解讀

論文在多個推薦任務（recommendation tasks）、資料集（datasets）與模型骨幹（model backbones）上進行離線驗證，並與 LLM-reasoning search 進行比較。結果顯示 RecHarness 能在有限的試驗預算下達成更穩定的效能提升（performance improvements），且對預算的使用更有效率。這裡的「穩定」意味著在不同任務與不同初始條件下，RecHarness 的改進幅度與收斂行為變異較小；「更有效率」則表示在相同試驗次數下，它能更快達到較高的驗證指標。雖然摘要中未列出詳細的離線數值表格，但從方法論設計可推論：bandit router 透過後驗更新避免重複試探低效益方向，而 jump-basin mechanism 則防止資源耗盡在無潛力的局部區域。

更具說服力的是為期七天的線上 A/B 測試（7-day online A/B test）。在一個大規模短影片廣告平台（large-scale short-video advertising platform）上，RecHarness 選出的候選方案相較於對照組帶來：
- ADVV 提升 2.084%
- Revenue（營收）提升 0.534%
- Exposure（曝光量）提升 0.559%

ADVV 是廣告價值相關指標，2.084% 的相對提升在廣告系統中屬於顯著的業務收益；Revenue 與 Exposure 同時正向成長，則說明該優化並未以犧牲使用者參與或廣告曝光為代價，而是同時改善了廣告品質與平台收益。值得注意的是，線上指標通常受到大量外部因素干擾，七天的大型平台實驗雖具高度實務參考價值，但論文未提供信賴區間或顯著性檢定細節，因此在解讀時仍應保留一定謹慎。此外，離線驗證指標與線上業務指標之間存在常見的 gap，RecHarness 能夠在兩個階段都取得正向結果，顯示其具備一定的泛化與實用性。

#### 與現有研究的比較

相較於傳統的超參數最佳化（Hyperparameter Optimization, HPO）或 AutoML 方法，RecHarness 的搜尋空間（search space）不再局限於可枚舉的數值超參數或固定架構模板，而是允許重新設計損失函數、替換特徵交互模組、改變序列建模方式等程式碼層級變更。這使其更貼近真實的推薦系統開發流程。

在 LLM-based MLE agents（基於 LLM 的機器學習工程師智慧體）領域，AIDE 採用樹狀搜尋並以貪婪策略擴展最佳節點，AIRA 則把智慧體形式化為在運算子集合上的搜尋策略。這類方法大多屬於梯度自由搜尋，將執行回饋壓縮為純量驗證分數後僅用於排序與剪枝。RecHarness 與它們的關鍵差異在於：它同時利用驗證分數進行結構化的 bandit 後驗更新，並保留執行日誌與訓練動態作為文字型優化訊號，供 LLM 進行有方向性的程式碼更新。

Reasoning-as-Gradient 強調錯誤日誌、訓練動態與驗證結果都應被視為「文字梯度（textual gradients）」來引導更新。RecHarness 可視為該理念在推薦場景的系統化實現：它不僅讓 LLM 閱讀這些訊號，還透過 bandit router 與 Experiment Skill 把跨輪訊息累積成可重複使用的優化知識。此外，近期關於 in-context bandit（上下文強盜）與 LLM-enhanced bandit 的研究指出，通用 LLM 在探索任務上需要外部摘要或演算法支援，而 RecHarness 正是把這一洞見具體落實到推薦模型優化中。

與其他 agentic recommender work（智慧體推薦相關研究）相比，RecHarness 的獨特貢獻在於提出「bandit-routed（強盜路由的）」架構與 jump-basin mechanism，把持續訓練—程式碼迭代（continuous training-code iteration）從一個完全由 LLM 主導的試誤過程（trial-and-error process），轉變為一個具備長期記憶（persistent memory）、方向選擇紀律與逃離局部停滯機制的自我演化推薦系統（self-evolving recommender systems）。

然而，RecHarness 也存在一些限制。首先，candidate arms 需要針對目標場景預先定義，這意味著系統仍依賴領域知識來設計臂的集合；其次，bandit 模型假設臂的獎勵分佈在某種程度上可被後驗追蹤，但推薦模型優化本質上是非穩態且高維的，理論上的遺憾界（regret bound）尚未被探討；最後，與 LLM-reasoning search 的比較雖然正向，但基線細節與完整實驗表格在提供的摘要中並未完全揭露。

#### 可重現性評估

論文作者已將程式碼開源於 https://github.com/6lyc/RecHarness，這對方法的可重現性（reproducibility）是一大加分。研究者可以檢視 bandit router、jump-basin mechanism、Experiment Skill 更新邏輯以及 LLM prompt 的實作細節（implementation details），並在自己的環境中複現其核心流程。

然而，可重現性仍面臨幾項挑戰。首先，線上 A/B 測試所使用的資料來自 Kuaishou 的大規模短影片廣告平台，屬於專有資料，無法公開釋出；其次，論文未提及是否釋出離線實驗所用的資料集、預處理流程或模型權重（model weights）。對於學術界而言，若僅有程式碼而缺乏對應資料與初始模型，便難以完全驗證離線數據與線上指標。建議未來可補充公開：臂的定義檔、 anonymized 實驗日誌、離線實驗所用的公開資料集版本，以及基線方法的詳細設定，以提升社群的可重現性與可比較性。

#### 未來研究方向

1. **自動化臂發現（automated arm discovery）**：目前 candidate arms 仍由人工預先定義，未來可讓 LLM 根據任務描述與歷史資料自動提議新的修改方向，進一步擴展工程搜尋空間。
2. **非穩態 bandit 與理論保證**：推薦模型優化過程中，臂的獎勵分佈會隨著模型狀態改變而變化，發展適用於此情境的 bandit 演算法並給出遺憾界分析，將大幅提升方法的嚴謹性。
3. **多目標路由（multi-objective routing）**：除了單一驗證指標，未來可同時考量準確度、延遲、公平性、營收與曝光量等目標，透過多目標 bandit 或 Pareto 前沿搜尋產生多樣化的候選方案。
4. **跨任務與跨領域遷移**：Experiment Skill 本質上是一種經驗知識，研究如何將其從一個推薦任務遷移到另一個任務，或從離線資料遷移到線上環境，將是極具價值的方向。
5. **線上持續學習與安全部署**：把 RecHarness 嵌入真實生產管線時，需要設計 guardrails（防護機制）、漸進式上線與自動回滾策略，以避免高風險的結構跳躍對使用者體驗造成負面衝擊。
6. **結合可微分架構搜尋（Differentiable NAS）**：對於某些架構變更，可將 LLM 提出的候選結構進一步透過可微分搜尋精煉，結合 bandit 的高階規劃與梯度式微調的優勢。
7. **可解釋性與人機協作**：讓工程師能理解 bandit router 為何選擇某個方向、LLM 為何提出某個修改，並在關鍵決策點引入人類回饋，將有助於提升系統在工業場景中的接受度與可控性。

## 論文問答

**Q1：RecHarness 欲解決的核心問題是什麼？**  
A：現代推薦模型的優化仍高度依賴工程師手動迭代架構、目標函數與訓練策略等變更，這個過程耗時且難以規模化。雖然基於 LLM 的智慧體能夠自動化這種試誤過程，但若同時讓 LLM 負責選擇修改方向並產生具體假設，容易在有限實驗預算下造成不穩定的搜尋。RecHarness 因此提出一個強盜路由的智慧體框架，將方向選擇與假設生成解耦，以實現更穩定且預算效率更高的自動化推薦模型優化。

**Q2：現有的 LLM 推理搜尋方法在推薦模型優化上有何不足？**  
A：現有方法常將執行回饋壓縮成單一驗證分數，僅用於排序或剪枝候選程式，忽略了訓練動態、錯誤日誌與收斂行為等豐富訊號。此外，讓 LLM 同時決定下一個修改方向並生成程式碼，會使搜尋過程在預算有限時變得不穩定，難以持續累積跨試驗的證據。推薦系統的每次試驗都涉及訓練與驗證，成本高昂，因此需要能夠解釋文字型回饋並以演算法機制穩定探索的框架。

**Q3：為何推薦系統優化特別適合也特別挑戰智慧體自動化？**  
A：推薦系統開發本質上是持續的訓練—程式碼迭代，其最佳解取決於資料集、任務設定、模型家族與評估目標，形成廣闊的工程搜尋空間。每次試驗不僅產生驗證分數，還包含收斂行為、訓練穩定性與失敗模式等資訊，必須結合當前模型狀態與歷史修改來解讀。這使得自動化優化器不能僅仰賴純量回饋，而必須具備解析日誌、趨勢與失敗訊號的能力，並持續累積跨回合證據。

**Q4：RecHarness 的核心方法流程為何？**  
A：RecHarness 將優化流程分為兩個步驟：首先由強盜路由器根據歷史驗證回饋，以 Thompson 採樣風格選出下一個修改方向；接著 LLM 在選定的方向內，利用當前最佳候選、執行日誌、驗證趨勢以及動態更新的 Experiment Skill，產生具體的優化假設與可執行的程式碼編輯。對於架構或損失函數等高影響力變更，系統還支援重新調校，以確保修改後的模型能夠充分收斂。

**Q5：將方向選擇與假設生成分開的關鍵創新是什麼？**  
A：此設計讓強盜演算法專注於在有限試驗預算下進行穩定的探索與利用，而 LLM 則專注於根據選定方向產生高品質的程式碼級假設，避免兩項任務互相干擾。強盜路由器能夠根據驗證回饋持續更新各臂的後驗狀態，從而系統化地累積跨試驗證據，降低單純依賴 LLM 推理所帶來的不穩定性。這種分層架構不僅提升了搜尋效率，也使得長期探索與局部開發能夠更有紀律地進行。

**Q6：什麼是 jump-basin 機制，它的作用是什麼？**  
A：jump-basin 機制是一種長期探索機制，當局部編輯在驗證表現上出現停滯時，會啟動結構跳躍臂以嘗試高影響力的結構性變更。此機制幫助系統逃離局部最佳解，避免在小幅程式碼修改中耗盡有限的試驗預算。透過在適當時機引入結構跳躍，RecHarness 能夠在長期優化過程中維持探索動能，並提升找到顯著效能提升方案的機會。

**Q7：論文在哪些實驗設定上評估 RecHarness？**  
A：論文在多個推薦任務、資料集與模型骨幹上進行離線評估，涵蓋序列推薦、排序、點擊預測與觀看時長預測等不同任務設定。此外，作者還在一個大規模短影片廣告平台上進行為期七天的線上 A/B 測試，以驗證選出候選方案在真實生產環境中的效果。這樣的離線與線上結合設計，能夠同時檢驗方法的泛用性與實務價值。

**Q8：離線實驗的主要結果是什麼？**  
A：RecHarness 在多個推薦任務與模型骨幹上，相較於純粹的 LLM 推理搜尋，展現出更穩定的效能提升。更重要的是，在有限的試驗預算下，它能更有效地分配每次試驗，避免將資源浪費在低潛力的修改方向上。這顯示強盜路由與 LLM 程式碼生成的結合，能夠在搜尋穩定性與預算效率之間取得更好的平衡。

**Q9：線上 A/B 測試帶來哪些業務指標提升？**  
A：在為期七天的線上 A/B 測試中，RecHarness 選出的候選方案使 ADVV 提升 2.084%、Revenue 提升 0.534%，並使 Exposure 提升 0.559%。這些指標涵蓋廣告效益、營收與曝光量，顯示該方法不僅在離線驗證指標上有效，也能轉化為實際的商業價值。此結果也證明了自動化推薦模型優化在大型廣告平台上部署的可行性。

**Q10：RecHarness 可應用於哪些實務場景？**  
A：RecHarness 適用於任何需要反覆迭代推薦模型的工業場景，例如排序、點擊預測、觀看時長預測與廣告推薦等。由於其框架可根據不同任務設定、模型家族與評估目標定義候選優化臂，因此能夠適應多樣化的推薦系統需求。對於擁有持續流量與驗證回饋的大型平台而言，這種自我演化的優化流程能夠顯著減少人工工程負擔。

**Q11：在產品化部署 RecHarness 時需要考慮哪些因素？**  
A：部署時需要為每個目標推薦場景預先定義候選優化臂，並確保每次試驗都能在隔離的訓練—驗證環境中執行，以便穩定收集驗證回饋與執行日誌。對於架構或損失函數等高影響力修改，必須額外安排重新調校，以確保模型能夠正常收斂。此外，由於每次試驗都消耗可觀的運算與時間成本，因此試驗預算、線上 A/B 測試機制與安全防護措施都需要謹慎設計。

**Q12：RecHarness 對推薦系統與智慧體研究領域有何影響？**  
A：RecHarness 展示了如何將經典強盜演算法的探索機制與 LLM 的程式碼生成能力結合，為自動化機器學習工程智慧體在推薦領域的應用提供了一個可擴展的架構。它強調驗證回饋不應僅被壓縮為純量分數，而應同時作為文字型訊號與後驗狀態來引導後續試驗。這種設計思路可望影響未來自我演化推薦系統與更廣泛的 LLM 驅動自動化機器學習研究。

**Q13：RecHarness 有哪些可能的限制？**  
A：該方法依賴預先定義的候選優化臂空間，若某些關鍵修改方向未被納入，則可能無法發現對應的最佳解。此外，LLM 產生的程式碼品質與可執行性會直接影響每次試驗的成敗，對於複雜或新穎的結構變更仍可能出現錯誤。重新調校與線上驗證也需要額外的運算與時間成本，這在資源極度受限的環境中可能構成挑戰。

**Q14：RecHarness 可能遇到哪些失敗案例？**  
A：若 LLM 對執行日誌或驗證趨勢的解讀錯誤，可能會產生無法編譯或導致訓練發散的程式碼編輯，浪費一次寶貴的試驗預算。強盜路由器在驗證訊號雜訊較大時，也可能錯誤地將資源分配到潛力較低的臂，延緩收斂速度。此外，當 jump-basin 機制過早或過晚啟動時，可能會錯失局部優化的機會，或在不適當的時機進行高成本的結構跳躍。

**Q15：未來可以朝哪些方向延伸 RecHarness？**  
A：未來可進一步讓系統自動發現新的優化臂，而非僅依賴人工預先定義的臂空間，以擴大搜尋範圍。也可以整合更豐富的回饋訊號，例如梯度資訊、模型嵌入或使用者行為日誌，來提升強盜路由器與 LLM 的決策品質。此外，加入多目標優化、安全約束與更長期的記憶機制，將有助於在真實生產環境中實現更穩健、可解釋且持續自我演化的推薦系統。

## 實務應用指南

### 適用場景

1. **大規模短影片廣告平台的推薦模型持續優化**：如論文所述，在短影片廣告平台中，可透過 RecHarness 自動迭代排序、點擊預測與觀看時長預測模型，並在為期七天的線上 A/B 測試中驗證 ADVV、Revenue 與 Exposure 的成長。
2. **電商平台的點擊率與轉換率預測模型自動迭代**：針對商品推薦中的特徵交互設計、訓練目標與正規化策略，讓智慧體框架在有限試驗預算下持續探索有效的修改方向。
3. **串流媒體的觀看時長預測與排序模型優化**：利用結構跳躍臂逃離局部編輯停滯，嘗試不同的序列建模選擇與骨幹架構變更，以提升使用者參與度。
4. **多任務推薦系統的訓練策略自動搜尋**：當模型同時優化多個評估目標時，RecHarness 可依據歷史驗證回饋，動態選擇下一個要調整的目標函數或優化策略方向。
5. **推薦模型上線前的工程搜尋空間探索**：在新資料集或新任務設定下，用於快速篩選適合的模型家族、實作細節與訓練策略，減少人工試誤過程。

### 實作前置條件

**資料與實驗基礎建設**
- 可重複執行的訓練—驗證試驗管線，並有穩定的離線評估目標。
- 歷史驗證回饋、執行日誌與訓練動態紀錄，作為強盜路由器與 LLM 推理的依據。
- 線上 A/B 測試環境與流量分桶能力，以便將選出的候選方案部署驗證。

**運算資源**
- 支援多次模型訓練與驗證的 GPU/TPU 叢集。
- 能夠承載連續試驗的運算排程與儲存資源，並支援早期停止以控制試驗預算。

**技術能力**
- 熟悉推薦系統任務（序列推薦、排序、點擊預測、觀看時長預測）。
- 具備 LLM 提示工程與程式碼生成結果評估能力。
- 能設計多臂強盜演算法（如 Thompson-style routing）與修改方向的配置空間。
- 熟悉 MLOps/CI-CD，能將自動化實驗管線整合至現有開發流程。

### 實作步驟建議

1. **定義優化目標與工程搜尋空間**：明確推薦任務、評估目標、模型骨幹，以及允許的修改方向（架構變更、目標函數、訓練策略、正規化、特徵交互設計、序列建模選擇等）。
2. **建立可重複執行的實驗管線**：確保每次試驗都能自動完成程式碼編輯、訓練、驗證與日誌記錄，並能穩定產出驗證回饋。
3. **設計強盜臂與跳躍盆地機制**：為每個修改方向建立臂，並設定局部編輯停滯時啟動結構跳躍臂的條件，以維持長期探索。
4. **建構實驗記憶與文字型優化訊號**：整理執行日誌、訓練動態與驗證結果，形成可供 LLM 推理的脈絡與 Experiment Skill。
5. **整合 LLM 生成優化假設與可執行程式碼編輯**：讓 LLM 在強盜路由器選定的方向內，產出具體假設並生成可執行的程式碼修改。
6. **離線驗證與線上 A/B 測試**：先在多個資料集與模型骨幹上進行離線驗證，確認穩定性後，再部署至線上進行為期數天的 A/B 測試。
7. **持續監控與自我演化**：根據線上指標回饋更新強盜後驗狀態，讓系統形成持續的自我演化推薦系統。

### 潛在風險與注意事項

- **不穩定搜尋與預算浪費**：若讓 LLM 同時負責選擇修改方向與生成具體假設，容易在有限實驗預算下產生震盪。應透過強盜路由器明確分離兩者職責。
- **局部編輯停滯與過度跳躍**：長期探索可能困在局部最優，但結構跳躍臂啟動過於頻繁也可能導致收斂困難。需謹慎設計停滯判斷條件與跳躍頻率。
- **LLM 生成程式碼的可執行性與正確性**：LLM 可能產生語法錯誤或語意不正確的程式碼。建議加入靜態檢查、單元測試與沙箱執行機制。
- **離線指標與線上指標不一致**：離線驗證的效能提升不一定轉化為線上營收或曝光量成長。應設計階段性閘道，從離線逐步過渡到線上 A/B 測試。
- **試驗成本高昂**：每次試驗都需完整訓練與驗證。可透過早期停止、低資源篩選試驗，以及強盜機制的預算感知路由來控制成本。

### 與其他技術的整合建議

- **MLOps/CI-CD 管線**：將 RecHarness 嵌入現有的持續整合與部署流程，自動觸發試驗、記錄程式碼版本，並在失敗時快速回滾。
- **特徵平台與資料管線**：與特徵商店整合，確保 LLM 生成的特徵交互設計能取得一致且正確的輸入資料。
- **現有 AutoML/HPO 工具**：可將 RecHarness 視為高階工程搜尋層，與底層超參數優化工具（如 Optuna、Ray Tune）互補：前者負責程式碼級修改方向，後者負責細部參數調校。
- **線上實驗平台**：整合 A/B 測試框架與指標監控系統，讓線上驗證回饋能即時回流至強盜路由器，更新臂的後驗狀態。
- **LLM 代理框架**：可與 LangChain、AutoGen 等框架結合，強化持久記憶管理、工具呼叫與多智慧體協作能力。

### 給不同背景讀者的閱讀建議

**初學者**：建議先掌握推薦系統的基本任務（序列推薦、排序、點擊預測）與多臂強盜問題的核心概念，再理解 RecHarness 如何將「選擇修改方向」與「生成具體假設」分開，最後關注論文中的線上 A/B 測試結果，建立對整體流程的直覺。

**AI 工程師**：應重點關注強盜路由器的實作細節、Thompson-style routing 的更新邏輯、跳躍盆地機制的觸發條件，以及如何將 LLM 生成的可執行程式碼編輯整合到現有訓練管線與 CI/CD 流程中。

**研究人員**：可深入探討將驗證回饋同時作為文字型回饋與明確後驗狀態的設計動機，並與 Reasoning-as-Gradient、AIDE、AIRA 等 LLM-based MLE 代理方法進行比較，思考強盜機制與 LLM 推理的互補性與未來擴展方向。

**產品經理**：請聚焦於 RecHarness 能帶來的業務價值（如 ADVV、Revenue、Exposure 的提升）、所需的試驗預算與前置條件，以及如何在產品路線圖中分階段導入，從離線驗證逐步推進到線上 A/B 測試。
