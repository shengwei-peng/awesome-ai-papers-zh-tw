# MoTE：用於多任務影片理解的任務專家混合模型（Mixture of Task Experts）

## ⚡ TL;DR

多任務程序影片理解中，密集解碼器共用前饋網路易混淆任務行為，傳統詞符級MoE路由也難對齊任務目標。
本文提出MoTE，把LLM前饋網路換成任務專家並保留共享骨幹，每樣本依任務路徑啟動對應專家。
VideoLLM-MoTE在COIN任務上準確率優於基線，每樣本僅啟動2B參數，可遷移至文件理解。

## 摘要翻譯

程序性影片-語言模型（procedural video-language models）必須從相同的視覺證據（visual evidence）中解決異質任務（heterogeneous tasks），包括動作辨識（action recognition）、動作預測（forecasting）與程序預測（procedure prediction）。密集式 Transformer 解碼器（Dense transformer decoders）在所有任務間共用相同的前饋網路（feed-forward networks, FFNs），可能使任務行為（task behavior）相互糾纏，並使可控的能力擴展（controlled capability expansion）難以實現。稀疏混合專家（Sparse Mixture-of-Experts, MoE）解碼器提供條件式計算（conditional computation），但詞符層級的學習路由（token-level learned routing）未能自然地與任務層級的程序目標（task-level procedural objectives）對齊。我們提出 MoTE（Mixture of Task Experts，任務專家混合模型），一種將大型語言模型（large language model, LLM）前饋網路轉換為任務專屬專家，同時維持多模態骨幹網路（multimodal backbone）共享的解碼器架構。每個樣本遵循一條樣本層級的任務路徑（sample-level task route），因此實際被啟動的任務專家計算與儲存的任務專家（stored task experts）數量無關。我們將此設計實例化為 VideoLLM-MoTE，並在五個 COIN 基準測試（COIN benchmarks）上使用顯式任務路徑（explicit task routes）進行評估。五專家模型（five-expert model）每個樣本啟動約 20 億個大型語言模型參數（LLM parameters），並達到比近期 VideoLLM 基線模型（VideoLLM baselines）更高的平均 Top-1 準確率（average top-1 accuracy）。在相同的專家拓樸下，它優於密集式全專家激活（dense all-expert activation）與學習式稀疏路由對照組（learned sparse-routing controls）。這些結果顯示，任務結構化路由（task-structured routing）為多任務影片-語言學習（multi-task video-language learning）提供了一個可解釋且運算效率高的解碼器替代方案。

### 核心貢獻（3～5點）
- 提出 MoTE（Mixture of Task Experts）解碼器架構，將 LLM 的 FFN 轉換為任務專屬專家，同時維持多模態骨幹網路共享。
- 採用樣本層級的任務路徑（sample-level task route），使每個樣本僅啟動對應任務專家，計算成本與儲存的任務專家數量無關。
- 實例化為 VideoLLM-MoTE，在五個 COIN 基準測試上驗證，五專家模型每樣本僅啟動約 20 億 LLM 參數，平均 Top-1 準確率優於近期 VideoLLM 基線。
- 在相同專家拓樸下，MoTE 優於密集式全專家激活與學習式稀疏路由對照組，顯示任務結構化路由的可解釋性與運算效率優勢。

### 適合對象
適合對多任務影片-語言學習（multi-task video-language learning）、程序性影片理解、混合專家（MoE）架構，以及智慧多模態助理（intelligent multimodal assistants）有興趣的研究者與工程師。特別是關注如何在單一模型中有效處理異質任務（如動作辨識、預測與程序預測）、同時控制計算成本與避免負遷移（negative transfer）的讀者。

## 深度分析

#### 方法論解析

##### 1. 核心設計理念：從 token 層級路由到樣本層級任務路由

傳統稀疏混合專家（Sparse Mixture-of-Experts，MoE）Transformer 通常採用 token-level learned routing（詞符層級學習路由），即對每一個輸入 token 獨立學習一個 gate（閘門）來決定啟動哪些 FFN（feed-forward networks，前饋網路）專家。這種做法雖然能在語言、視覺與大型視覺-語言模型（large vision-language models，LVLMs）中擴充儲存容量，但其路由決策與「任務層級的程序目標（task-level procedural objectives）」並無天然對齊。在程序性影片-語言模型（procedural video-language models）中，同一組視覺證據必須支援異質任務（heterogeneous tasks），例如動作辨識（action recognition）、動作預測（forecasting）與程序預測（procedure prediction）。這些任務的提示詞（prompts）在時間視野與輸出結構上差異顯著，若所有任務共用同一條密集解碼路徑，容易產生負遷移（negative transfer）。

MoTE（Mixture of Task Experts，任務專家混合模型）將「任務身份（task identity）」提升為顯式的路由變數。具體而言，MoTE 把 LLM（large language model，大型語言模型）解碼器中的每一個 FFN 轉換成：
- 一個 always-active shared expert（恆定啟動的共享專家），負責任務無關的通用視覺-語言基礎對應（shared visual-language grounding）；
- 多個 task-specific experts（任務特定專家），各自學習特定任務的轉換。

由於每個樣本（sample）只走一條 sample-level task route（樣本層級任務路徑），因此實際被激活的計算量與儲存的任務專家數量（stored task experts）無關。這是一種條件式計算（conditional computation）：儲存容量可以隨任務增加而擴展，但每個樣本的活躍參數量保持固定。

##### 2. VideoLLM-MoTE 的架構細節

圖 1 概述了 VideoLLM-MoTE 的資料流：
1. **輸入編碼**：使用者提示詞（prompt tokens）與取樣影片畫面（sampled video frames）分別進入文字嵌入層與視覺編碼器（visual encoder），再經由視覺 MLP 投影器（Visual MLP Encoder Projector）轉為視覺詞符（visual tokens）。
2. **專家選擇**：系統根據提示詞與已註冊的專家描述（registered expert descriptions）進行 prompt-conditioned expert selection（以提示詞為條件的專家選擇），輸出選定的專家識別碼（selected expert id）。
3. **解碼生成**：選定的專家識別碼被傳入經過 MoTE 修改的 LLM 解碼器，模型在共享注意力路徑與選定的任務專家協同下生成回應（response）。

訓練時，視覺編碼器與基礎語言模型（base LM）保持凍結（frozen），僅更新 MLP 投影器、LoRA（Low-Rank Adaptation，低秩適配）適配器以及被選中的任務專家。這種設計大幅降低了可訓練參數（trainable params）量，並避免破壞預訓練的語言與視覺知識。

##### 3. 路由監督與推論方式

MoTE 的路由並非完全由學習閘門隱式決定，而是利用已知的任務結構：
- **訓練階段**：任務標籤（task labels）直接提供 route supervision（路徑監督），告訴模型應該啟動哪一個任務專家。
- **推論階段**：路由可以外部給定，也可以透過比對提示詞與已註冊專家描述來選擇。

這種顯式任務路徑（explicit task routes）帶來兩大好處：
- **可解釋性（interpretability）高**：每個專家對應一個語義明確的任務，研究者可以直接檢視、新增或移除專家。
- **模組化（modularity）強**：新增任務時只需增加新的任務專家，並在共享骨幹（shared backbone）與既有專家中保留先前學到的知識；移除專家則可視為一種 controlled capability expansion（可控的能力擴展）或縮減。

##### 4. 與密集式解碼器及學習式稀疏路由的對照

在相同專家拓撲（expert topology）下，作者設計了兩個重要對照：
- **密集全專家激活（dense all-expert activation）**：所有任務專家與共享專家同時啟動，相當於傳統密集式 Transformer 解碼器（dense transformer decoder）。這會讓不同任務的 FFN 轉換互相糾纏（entangle task behavior）。
- **學習式稀疏路由對照（learned sparse-routing controls）**：保留同樣的專家集合，但改由學習閘門決定 token 層級路由。

MoTE 在這兩種設定下都取得提升，顯示「任務結構化路由（task-structured routing）」本身即具有建模優勢，而不只是參數量或稀疏性的效果。

#### 實驗數據解讀

##### 1. COIN 多任務影片理解評測

作者在 COIN benchmarks（COIN 基準測試）上評估 VideoLLM-MoTE，涵蓋五項程序性影片任務。五專家模型（five-expert model）每次樣本僅激活約 20 億個 LLM 參數（~2B LLM parameters per sample），卻能在平均 Top-1 準確率（average top-1 accuracy）上超越近期的 VideoLLM baselines（VideoLLM 基線模型）。

這個結果的意義可從三個層次解讀：
- **參數效率**：雖然模型「儲存」了多個任務專家，但每個樣本只走一條路徑，因此活躍計算量遠低於同時激活所有專家的密集模型。這驗證了 conditional computation 在影片-語言領域的有效性。
- **任務分離效果**：相較於所有任務共用同一組 FFN，任務專家能夠學習到更具專一性的轉換，減少異質任務間的負遷移。
- **路由層級的影響**：在相同專家拓撲下，MoTE 勝過 learned sparse-routing controls，說明樣本層級的任務身份資訊比 token 層級的隱式閘門更適合程序性影片任務。

##### 2. 跨領域遷移：文件理解

為了驗證 MoTE 作為通用架構原則的跨領域適用性，作者將 GLM-OCR 轉換為 GLM-OCR-MoTE，並在文件理解任務上區分 OCR（Optical Character Recognition，光學字元辨識）與 KIE（Key Information Extraction，關鍵資訊抽取）兩條任務路徑。實驗成功顯示任務分離（task separation）可以在不同領域複製，強化了「將 LLM 的 FFN 專家化」這一原則的通用性。

##### 3. 專家新增與移除分析

作者進一步進行 expert addition（專家新增）與 explicit expert-removal mechanism（顯式專家移除機制）分析。這些實驗旨在說明：
- **新增專家**：可以在不重新訓練整個模型的情況下擴展新任務能力，符合 modular units（模組單元）的設計目標。
- **移除專家**：可以將特定任務對應的 FFN 區塊移除，觀察模型行為變化，從而驗證專家確實承擔了對應的任務功能。

雖然提供的上下文未給出具體數值，但從敘述來看，這些分析支持 MoTE 具備良好的可解釋性與可控性。

##### 4. 數據解讀的限制

由於目前僅能看到摘要與部分引言，缺乏完整的實驗表格、標準差、樣本數與超參數設定，因此以下推論仍需配合原文完整數據：
- 尚不清楚五項 COIN 任務各自的 top-1 accuracy 分布是否均衡，或是否存在某些任務受益較大、某些任務提升有限的情況。
- 與 VideoLLM-online、VideoLLM-MoD 等串流方法的比較細節未明，無法判斷 MoTE 在長時與串流輸入（long and streaming inputs）上的實際開銷。
- 文件理解實驗僅提及兩個資料集，樣本規模與任務難度可能不足以完全證明跨領域泛化。

#### 與現有研究的比較

##### 1. 相對於傳統稀疏 MoE

表 1 清楚比較了 MoTE 與既有 MoE 方法的差異。傳統方法如 Sparse MoE、GShard、Switch Transformer、V-MoE、Sparse Upcycling、LLaMA-MoE、MoE-LLaVA 等，大多在 token 或 patch 層級進行 learned top-k / top-1 路由，interpretability（可解釋性）低，且並非 task-aware（具任務意識）。MoTE 則在 sample 層級依據 task index 或 prompt 進行專家選擇，interpretability 高且 task-aware。

這種差異的關鍵在於：傳統 MoE 的路由目標是「擴充模型容量並維持稀疏激活」，而 MoTE 的路由目標是「顯式分離異質任務的計算路徑」。因此 MoTE 更適合需要明確任務控制的應用場景，例如智慧多模態助理（intelligent multimodal assistants）在程序性影片上的多種指令。

##### 2. 相對於任務條件式 MoE

MoCLE、M3ViT、Edge-MoE、Cross-task MoE 等方法已經嘗試將任務資訊納入路由，但大多仍依賴學習閘門（learned gates）或聚類條件（cluster-conditioned routing），interpretability 僅為中等。MoTE 進一步將路由簡化為「任務身份 → 專家識別碼」的顯式對應，避免了閘門學習的不穩定性，也讓專家新增與移除變得可行。

##### 3. 相對於串流影片語言模型

VideoLLM-online、VideoLLM-MoD 等研究聚焦於 memory（記憶機制）、causal processing（因果處理）、token selection（詞符選擇）與 computation scheduling（計算排程）等面向，以改善長時與串流輸入的處理效率。MoTE 並未取代這些機制，而是補充了「解碼器端的任務特定計算（task-specific computation）」。理論上，MoTE 可以與這些串流技術結合，在保持共享視覺-語言骨幹的同時，為不同程序任務提供專屬解碼路徑。

##### 4. 主要優勢總結

- **顯式任務控制**：任務身份成為可觀察、可干預的變數。
- **計算與儲存解耦**：儲存多個專家，但每樣本激活量固定。
- **模組化擴展**：支援專家新增與移除，利於持續學習與能力客製化。
- **參數效率**：在 ~2B 活躍參數預算下超越密集基線。

##### 5. 限制與潛在弱點

- **任務結構需預先已知**：MoTE 依賴 task labels 或已註冊的 expert descriptions，對於任務邊界模糊或動態組合的場景（例如一個提示詞同時要求「辨識目前動作並預測下一步」）可能難以單一路由處理。
- **提示詞匹配的不確定性**：推論時若採用 prompt-conditioned expert selection，提示詞與專家描述的比對品質會直接影響效能。對於措辭多變或隱含任務的指令，可能需要更強大的語義匹配機制。
- **僅專家化 FFN**：注意力路徑（attention path）仍為共享，對於需要極端不同時間結構的任務（例如長程程序預測 vs. 當前影格動作辨識），共享注意力可能成為瓶頸。
- **未在真實串流設定驗證**：雖然引言強調串流程序影片的重要性，但主要實驗似乎仍基於 COIN 的離線片段，MoTE 在 live stream（即時串流）場景下的延遲與路由決策時機尚待驗證。
- **專家數量擴展性**：當任務數量從五個擴展到數十或數百個時，儲存成本與專家描述管理將成為新的挑戰。

- **資料集**：COIN benchmarks 與文件理解所使用的資料集（GLM-OCR 相關資料）屬於公開或半公開資源，原則上可取得。

- **程式碼與權重**：未見 open-source code 或 model weights 的明確聲明。

##### 2. 重現難度評估

綜合來看，MoTE 的概念層面相對清晰——將 LLM 解碼器的 FFN 替換為任務條件式專家，並在訓練時根據 task labels 選擇專家。具備 Transformer 與 LoRA 實作經驗的研究者應能根據論文描述重建原型。然而，要完全重現 VideoLLM-MoTE 在 COIN 上的準確率，仍需依賴作者釋出的完整訓練設定與資料前處理流程。

##### 3. 建議

為提升可重現性，作者可考慮公開：

- 用於註冊專家描述的模板與推論時的匹配策略。

#### 未來研究方向

##### 1. 與串流機制結合

MoTE 目前主要針對離線片段設計，未來可探索如何與 VideoLLM-online、VideoLLM-MoD 等串流技術整合，發展能夠在 live stream（即時串流）中動態選擇任務專家的線上模型。這需要解決「何時觸發路由」與「如何在不完整影片中進行動作預測」等問題。

##### 2. 動態與層次化路由

目前的 MoTE 採用單一樣本層級任務路徑。未來可研究：
- **層次化任務專家**：例如將程序預測進一步細分為「短期下一步預測」與「長期目標預測」專家。
- **動態組合路由**：允許一個樣本同時激活多個專家，以處理複合式提示詞（例如同時進行動作辨識與程序預測）。

##### 3. 持續學習與專家管理

MoTE 的模組化特性非常適合持續學習（continual learning）。未來可研究：
- 如何自動決定何時新增專家，而非依賴預先定義的任務數量。
- 專家合併（expert merging）與剪枝（expert pruning）技術，以控制儲存成本。
- 避免新任務專家干擾舊任務專家的正則化策略。

##### 4. 更強大的提示詞-專家匹配機制

目前採用提示詞與專家描述的比對方式，未來可引入：
- 學習式語義檢索模型，將提示詞嵌入與專家描述嵌入對齊。
- 少樣本示例（few-shot examples）來輔助路由決策。
- 不確定性估計，當匹配信心不足時回退到共享專家或請求人類確認。

##### 5. 擴展至更多模態與任務

MoTE 的原則已在影片理解與文件理解上驗證，未來可擴展至：
- 多語言程序影片理解。
- 機器人操作影片中的動作規劃與執行。
- 醫療程序影片中的步驟辨識與風險預警。
- 音訊-視覺-語言多模態任務。

##### 6. 注意力路徑的任務適配

目前僅 FFN 被專家化，未來可探討是否也需要為不同任務設計條件式注意力（conditional attention）或任務特定的位置編碼（task-specific positional encoding），以進一步提升對時間視野差異大的任務的處理能力。

##### 7. 開源與標準化評測

為了推動社群發展，建立 MoTE 的開源實作與標準化多任務影片-語言評測協議，將有助於比輕不同路由策略、專家數量與任務組合對效能的影響。

## 論文問答

**Q1：程序性影片理解的核心挑戰是什麼？為何需要 MoTE？**
A：在程序性影片理解中，同一段視覺證據必須同時支撐多種異質任務，例如動作辨識、未來步驟預測與程序目標預測等。傳統密集式 Transformer 解碼器讓所有任務共用相同的前饋網路，容易導致任務行為糾纏與負遷移，並使後續依任務擴展能力變得困難。MoTE 因此將大型語言模型的前饋網路轉換為任務專屬專家，在保留共享多模態骨幹的同時，讓每個樣本走一條明確的任務路徑，從而分離不同任務的計算。

**Q2：密集式 Transformer 解碼器在多任務影片學習中為何表現受限？**
A：密集式解碼器要求所有任務的特徵轉換都擠在同一組前饋網路區塊中完成，而這些區塊同時被每個任務更新。當任務提示在時間範圍與輸出結構上差異很大時，共用參數會產生負遷移，使模型難以學到穩定的任務特定轉換。此外，若要在部署後新增任務，必須更動已訓練好的共用參數，難以做到可控的能力擴展。

**Q3：現有的稀疏混合專家（MoE）解碼器為何無法直接滿足程序性影片任務的需求？**
A：傳統稀疏 MoE 通常以詞符或影像區塊為單位進行學習式路由，雖然能有效擴大儲存容量，但路由決策與高層任務語義並未對齊。這種細粒度路由無法為程序性提示提供穩定且可解釋的任務層級計算路徑。相較之下，MoTE 直接以任務身份作為路由變數，使每個樣本遵循單一任務路徑，從而與程序性任務目標自然對齊。

**Q4：MoTE 的核心架構設計是什麼？**
A：MoTE 將解碼器中每個前饋網路替換為數個任務專屬專家與一個恆常啟動的共享專家，同時保留視覺-語言骨幹與注意力路徑為共享。每個訓練樣本會根據其任務標籤選擇一個樣本層級的任務路徑，只啟動對應的任務專家與共享專家。如此一來，無論模型儲存了多少個任務專家，單一樣本的活躍計算量都保持固定。

**Q5：MoTE 相較於傳統 MoE 的關鍵創新在哪裡？**
A：關鍵創新在於把「任務身份」變成顯式的路由變數，而非讓模型在詞符層級隱式學習路由。這種任務結構化路由不僅提升可解釋性，也讓每個專家對應到明確的任務語義。由於專家是獨立模組，新增任務時只需加入新的任務專家，原有共享骨幹與已學會的專家知識得以保留。

**Q6：VideoLLM-MoTE 在實作上有哪些重要設計選擇？**
A：視覺編碼器與基礎語言模型保持凍結，僅訓練視覺 MLP 投影器、LoRA 低秩適配層以及被選中的任務專家，以降低訓練成本並保留預訓練知識。在推論時，系統會將使用者提示與已註冊的專家描述進行匹配，選出對應的專家識別碼後再送入解碼器。這種以提示詞為條件的專家選擇讓任務路由既直觀又可控。

**Q7：論文在哪些實驗設定上評估了 MoTE？**
A：作者將 MoTE 實例化為 VideoLLM-MoTE，並在五個 COIN 程序性影片理解任務上以顯式任務路徑進行評估。為了驗證跨領域適用性，他們還把 GLM-OCR 轉換為 GLM-OCR-MoTE，在文件理解領域分離光學字元辨識與收據關鍵資訊擷取兩條任務路徑。這兩組實驗分別涵蓋影片-語言與文件-語言兩個不同領域。

**Q8：VideoLLM-MoTE 的主要實驗結果為何？**
A：在五專家設定下，VideoLLM-MoTE 每個樣本僅啟動約二十億個大型語言模型參數，卻在平均 Top-1 準確率上優於近期的 VideoLLM 基線模型。在相同專家拓撲下，它也勝過密集式全專家激活以及學習式稀疏路由對照組。這顯示任務層級路由能以較少的活躍參數達到更好的多任務表現。

**Q9：論文如何驗證 MoTE 的模組化與可擴展性？**
A：作者進行了專家新增與移除分析，結果顯示可以在不干擾既有知識的情況下加入新任務專家。透過顯式移除特定任務專家，也能觀察到對應任務能力的變化，證明任務對齊的前饋網路專家確實是獨立模組。這些模組化實驗進一步說明 MoTE 具備可控的能力擴展與可解釋的任務分離特性。

**Q10：MoTE 在實際應用中適合哪些場景？**
A：MoTE 特別適合需要同時處理多種程序性查詢的智慧多模態助理，例如教學影片問答、即時串流助理與步驟預測系統。使用者可能詢問「我現在在做什麼？」、「下一步該做什麼？」或「這段程序的目標是什麼？」，這些問題對應不同任務卻共享同一影片輸入。MoTE 能依提示選擇最適合的任務專家，提供準確且具解釋性的回應。

**Q11：若將 MoTE 部署為產品，有哪些工程與設計考量？**
A：由於每個樣本只啟動一個任務專家與共享專家，活躍參數量不隨儲存的任務專家數量增加，適合在資源有限的邊緣或串流環境部署。產品團隊可以透過註冊新的專家描述來擴充新任務，而無需重新訓練整個模型。此外，任務路由由提示詞或外部任務標籤決定，便於監控、除錯與人為介入。

**Q12：MoTE 對多任務影片-語言學習領域可能帶來什麼影響？**
A：MoTE 在密集共用解碼器與傳統詞符級稀疏 MoE 之間提供了一條任務結構化路由的中間路徑，強調可解釋性與任務對齊。它證明將前饋網路專家化後，模型能在保持共享視覺-語言基礎對應的同時，顯著提升多任務表現。這種設計原則還可跨域轉移到文件理解等其他應用，推動模組化多模態模型的發展。

**Q13：MoTE 目前有哪些潛在限制？**
A：MoTE 假設任務結構在訓練時已知，並需要任務標籤來監督樣本層級的路由，因此對於完全無標籤或任務邊界模糊的設定較不直接適用。在推論時，任務路徑必須由外部提供或透過提示詞匹配來選擇，若提示詞過於模糊可能選錯專家。此外，對於未註冊的新任務，模型缺乏自動發現與分配專家的機制。

**Q14：在哪些情況下 MoTE 可能出現失敗或表現下降？**
A：當使用者提示同時混合多種任務語義，或任務描述與實際查詢不一致時，以提示詞為條件的路由可能選錯專家，導致生成不相關的回應。如果某個新任務與已訓練任務差異極大，而共享專家又無法提供足夠的任務無關轉換，則新任務的表現可能受限。另外，在訓練資料嚴重不平衡時，某些任務專家可能學得不如其他專家穩定。

**Q15：未來研究可以朝哪些方向延伸 MoTE？**
A：未來可探索自動任務發現與動態專家分配，使模型在面對未註冊任務時仍能建立新路徑。將 MoTE 與串流記憶機制、詞符選擇或計算排程技術結合，可進一步提升長時與即時影片理解的效率。此外，把任務結構化路由推廣到更多領域，如機器人操作、醫療程序分析或互動式教學，也是值得發展的方向。

## 實務應用指南

### 適用場景

1. **智慧廚房與家電助理**  
   使用者一邊烹飪一邊與助理互動，系統需同時處理「目前在做什麼」（動作辨識）、「下一步該做什麼」（動作預測）、「這道菜的完整步驟是什麼」（程序預測）等異質任務。MoTE 可讓每種任務走專屬的任務專家路徑，避免任務行為互相干擾。

2. **工業 SOP 培訓與品質檢測**  
   在裝配、維修或品檢影片中，模型需要辨識當前工序、預測後續步驟、判斷最終目標，甚至回答操作規範問題。透過任務結構化路由，可針對不同工序或檢測站點擴展新任務專家，而不影響已學會的知識。

3. **線上教育與技能教學平台**  
   針對程序性教學影片（如樂器、運動、手作），平台可提供「步驟解說」「下一步提示」「學習摘要」等多種互動。MoTE 的樣本層級任務路由讓每個學習互動只啟動對應專家，降低推理成本。

4. **醫療復健動作指導**  
   復健或手術準備影片中，系統可辨識患者動作、預測下一個動作、確認治療目標，並給出口語回饋。任務專家的模組化設計有助於在新增復健項目時安全擴展。

5. **文件與票據智慧處理**  
   借鏡論文在文件理解領域的驗證，可將 MoTE 應用於 OCR 與 KIE（Key Information Extraction）分離場景，例如發票、收據、合約：不同任務啟動不同專家，減少文字辨識與資訊擷取之間的負遷移。

### 實作前置條件

**資料條件**
- 多任務影片–語言配對資料，每個樣本需標註任務類別（如 action recognition、forecasting、procedure prediction）。
- 對應的提示詞模板（prompt templates）與已註冊的專家描述（expert descriptions），讓提示詞能對應到正確任務專家。
- 若應用於文件領域，則需準備 OCR 與 KIE 的標註資料，並定義清楚任務邊界。

**運算條件**
- 需一個凍結的基礎 LLM（如 Llama-3.2）與視覺編碼器，並訓練視覺投影器（Visual MLP Projector）與 LoRA。
- 雖然每個樣本只啟動一個任務專家（例如五專家模型每樣本約啟動 2B LLM 參數），但儲存的總參數量會隨專家數增加，因此仍需足夠 GPU 記憶體與分散式訓練框架（如 DeepSpeed、FSDP）。
- 推理階段需支援條件式專家載入，以發揮「儲存多、啟動少」的優勢。

**技術條件**
- 熟悉 LLM 指令微調、LoRA、多模態投影器設計。
- 理解 Transformer FFN 結構與 MoE 路由機制。
- 具備提示工程（prompt engineering）與任務導向評估（如 COIN benchmark）經驗。

### 實作步驟建議

1. **拆解產品需求為任務並設計專家描述**  
   將應用場景拆分為具體異質任務，例如「動作辨識」「動作預測」「程序預測」「摘要生成」。為每個任務撰寫明確的專家描述，作為提示詞條件路由的依據。

2. **準備與標註多任務資料**  
   收集影片–語言樣本，標註任務 ID、程序目標、時間戳與對應答案。確保各任務樣本數量平衡，並建立訓練 / 驗證 / 測試集。

3. **選定並凍結多模態骨幹**  
   選擇視覺編碼器與基礎語言模型（如 Llama-3.2），訓練視覺投影器將視覺詞符對齊到語言模型空間，並在注意力路徑加入 LoRA。

4. **將 FFN 轉換為 MoTE 結構**  
   將解碼器中每層共享 FFN 替換為「共享專家（shared expert）＋ 多個任務專家」。可從原始 FFN 初始化共享專家，再根據任務資料初始化任務專家。

5. **實作樣本層級任務路由**  
   訓練時使用任務標籤直接指定 expert id；推理時透過提示詞與已註冊專家描述匹配，產生 sample-level 任務路徑。可保留 fallback 機制，在匹配不確定時使用共享專家或人工指定。

6. **多任務指令微調**  
   聯合訓練所有任務，但每個樣本只更新對應任務專家、LoRA 與投影器，保持視覺編碼器與基礎語言模型凍結。這樣可避免任務間互相覆蓋參數。

7. **評估與對照實驗**  
   與密集式解碼器（dense all-expert activation）及學習式稀疏路由（learned sparse-routing）比較平均 Top-1 準確率，並檢查是否存在負遷移或任務間干擾。

8. **部署與持續擴展**  
   上線後根據提示詞動態選擇專家。新增任務時，只需新增任務專家並針對新任務微調，無需重新訓練整個模型，並驗證舊任務表現是否穩定。

9. **監控與迭代**  
   追蹤各專家的使用率、錯誤分佈與延遲。若發現某些任務經常被錯誤路由，則調整專家描述或提示詞模板。

### 潛在風險與注意事項

- **任務邊界模糊**：若任務定義重疊（例如「動作預測」與「程序預測」界線不清），可能導致路由錯誤或專家學習內容重疊。建議在設計階段明確任務輸入（時間範圍）與輸出格式。
- **資料不平衡**：某些任務樣本過少會讓對應專家訓練不足。可採用平衡採樣、加權損失或資料增強來緩解。
- **總參數量與記憶體壓力**：雖然每樣本啟動參數固定，但儲存的專家總數增加會提高記憶體與模型並行通訊成本。需評估專家卸載（offloading）或分片策略。
- **提示詞與專家描述匹配失準**：使用者提示詞可能同時包含多種任務意圖。建議設計 robust 的匹配規則，或允許系統在模糊情況下要求使用者確認任務類型。
- **新增任務時的遺忘風險**：MoTE 雖然設計上保留既有知識，但新增專家後仍建議在舊任務驗證集上進行回歸測試，確保沒有性能衰退。
- **可解釋性的限制**：路由決策本身可解釋，但專家內部的計算仍是黑箱。若應用於高風險場景（如醫療），需搭配額外的可解釋性分析與人機協同審查。

### 與其他技術的整合建議

- **與 RAG / 知識庫整合**  
  任務專家負責程序推理與生成，RAG 負責檢索外部 SOP、食譜或維修手冊。兩者結合可提升事實性與領域適應性。

- **與串流影片處理框架整合**  
  可將 MoTE 與 VideoLLM-online、VideoLLM-MoD 等串流處理技術結合：前者處理長時與因果輸入，MoTE 負責在互動點進行任務路由。

- **與 RLHF / 偏好學習整合**  
  針對特定任務專家進行人類回饋強化學習，優化該任務的回應風格與準確性，而不影響其他任務專家。

- **與邊緣部署優化整合**  
  選定專家後可進行量化、剪枝或 LoRA 合併，進一步降低延遲與功耗，適合手機、家電或工業邊緣裝置。

- **與 MLOps / 模組化管理整合**  
  將每個任務專家視為可版本化的模組，支援動態載入、A/B 測試與灰度發布。新增任務時只需部署新專家模組，降低上線風險。

### 給不同背景讀者的閱讀建議

**給初學者**  
先把 MoTE 理解為「每個任務擁有專屬前饋網路，但注意力與視覺骨幹共用」的架構。重點看圖 1 的整體流程與實驗中「五專家模型每樣本只啟動約 2B 參數」的結論，不必一開始深入路由數學。

**給 AI 工程師**  
請聚焦實作細節：如何將 Llama-3.2 的 FFN 拆成 shared expert 與 task-specific experts、LoRA 與視覺投影器的訓練範圍、提示詞條件路由的程式實現，以及訓練時只更新被選定專家的技巧。評估時可對照密集式解碼器與學習式稀疏路由。

**給研究人員**  
本文的核心貢獻在於將路由粒度從 token 提升到樣本層級的任務路由，並強調可解釋性與可控擴展。建議關注與傳統 token-level MoE 的對比、跨領域遷移到文件理解的實驗，以及專家增刪分析所展示的模組化特性。

**給產品經理**  
MoTE 的商業價值在於用可控的每樣本計算成本支援多任務，並能透過新增專家擴展能力。評估時請同時考慮資料收集成本、提示詞與專家描述的維護成本，以及可解釋路由對使用者信任與監管合規的幫助。
