# Repo-To-Skill（從儲存庫到技能）：將 GitHub 儲存庫蒸餾為 AI4AI 技能（用於 AI 的 AI 技能）

## ⚡ TL;DR

自主機器學習研究代理缺乏讓方法真正運作的實務操作知識。
提出 DisCo，透過雙重蒸餾產生可驗證技能並建構 AREX-Skill 技能庫。

---

## 摘要翻譯

自主代理（autonomous agents）已開始能夠端到端（end-to-end）執行機器學習（machine learning, ML）研究。這些代理結合了模型骨幹（model backbone）與一個用於規劃（planning）、執行（execution）、記憶（memory）和驗證（verification）的 harness（框架），但此種架構仍將領域專屬的實務訣竅（know-how）排除在代理之外。我們稱這個缺失層（missing layer）為操作知識（operational knowledge），亦即區分「知道一個方法」與「讓方法運作」的實務訣竅。這類知識在該領域中並未缺席，它存在於儲存庫與論文中，但多以人類讀者為對象撰寫，且篇幅過大，難以在任務執行期間載入。一旦蒸餾（distilling）為精簡且經驗證的技能（skills），這些知識便可跨任務重複使用，無需在每次執行中重新發現。

我們提出 DisCo，一個技能驅動的研究代理（skill-powered research agent），可創建技能並在研究過程中加以運用。其蒸餾運作分為兩種互補形式：任務無關（task-agnostic），將領域中廣泛使用的儲存庫蒸餾為可重複使用的技能；以及任務導向（task-oriented），產生具體任務（concrete task）所需的技能。前者橫跨整個開放生態系統（open ecosystem）應用，產生了 AREX-Skill Library（AREX-Skill 技能庫），其中包含 5,000 多個經驗證的技能，由 1,000 個廣泛使用的 ML 儲存庫蒸餾而來，並組織為 20 個領域（areas）與 178 個能力家族（capability families）。在 GPT-5.5 骨幹、研究框架（research harness）與下游執行預算（downstream execution budget）均保持固定的條件下，相較於未配備技能的同一代理，配備技能的研究代理在 MLE-bench、PaperBench、FrontierCS 與 PassNet 上分別高出 134.3%、34.4%、9.2% 與 14.0%。這些提升源於在該固定設定下納入經蒸餾的操作上下文（operating context）。

### 核心貢獻（3～5點）
- 指出自主代理在執行 ML 研究時存在「操作知識（operational knowledge）」這一缺失層，並將其形式化為可重複使用的技能（skills）。
- 提出 DisCo，一個能同時進行任務無關（task-agnostic）與任務導向（task-oriented）蒸餾的技能驅動研究代理（skill-powered research agent）。
- 建構 AREX-Skill Library（AREX-Skill 技能庫），從 1,000 多個廣泛使用的 ML 儲存庫蒸餾出 5,000 多個經驗證技能，並組織為 20 個領域（areas）與 178 個能力家族（capability families）。
- 在固定 GPT-5.5 模型骨幹、研究框架（research harness）與下游執行預算（downstream execution budget）下，於 MLE-bench、PaperBench、FrontierCS 與 PassNet 上顯著提升表現，證明經蒸餾的操作上下文（operating context）是主要增益來源。

### 適合對象
從事自主代理（autonomous agents）、AI4AI 技能、機器學習研究自動化、編碼代理（coding agents）與代理系統（agentic systems）編排（orchestration）的研究者與工程師；特別適合關注如何將儲存庫中的實務訣竅轉化為可重複使用技能，以提升研究代理在固定模型與執行預算下表現的讀者。

## 深度分析

#### 方法論解析

本研究的核心論點是：自主研究代理（autonomous research agent）的效能瓶頸不在於模型骨幹（model backbone）或 harness（框架）本身，而在於「操作知識（operational knowledge）」這一缺失層（missing layer）。操作知識指的是讓方法真正運作所需的實務訣竅（know-how），例如如何選擇方法、設定實驗、正確呼叫套件 API（package API）、配置訓練流程（training pipeline），以及避開常見的實作陷阱（implementation pitfalls）與評估陷阱（evaluation pitfalls）。這些知識大量散佈於 GitHub 儲存庫（GitHub repositories）與論文中，但原始形式是為人類讀者撰寫、體積龐大且難以在單一任務的上下文（context）中載入。為此，作者提出 **DisCo**，一個技能驅動的研究代理（skill-powered research agent），透過「蒸餾（distilling）」將儲存庫知識轉換為結構化、可驗證且可重複使用的技能（skill）。

##### 1. 技能表示形式（Skill Representation）

論文採用的技能載體是 **SKILL.md** 檔案，其設計原則是「開頭摘要、按需展開」。每個 SKILL.md 會說明：

- 該技能的用途（what the skill is for）
- 適用情境（when it applies）
- 執行步驟（how to proceed）

此外，技能還包含參考文件（reference documents）作為證據，以及腳本（scripts）自動化例行操作。這種設計讓代理可以在記憶體中保存數千個技能，但只在需要時讀取少數幾個，從而解決知識層規模化與上下文長度限制之間的張力。

##### 2. 雙軌蒸餾策略

DisCo 的技能蒸餾分為兩種互補形式：

- **任務無關蒸餾（task-agnostic distillation）**：預先對領域內廣泛使用的儲存庫進行蒸餾，產生可跨任務重用的技能。這構成了 **AREX-Skill Library（AREX-Skill 技能庫）**，涵蓋從 1,000 個廣泛使用的 ML 儲存庫蒸餾出的 5,000+ 個經驗證技能（verified skills），並按 20 個領域（areas）與 178 個能力家族（capability families）組織。
- **任務導向蒸餾（task-oriented distillation）**：針對具體任務（concrete task）即時探索所需知識，動態生成該任務呼叫的技能。

這兩種形式形成「離線預蒸餾＋線上任務適配」的混合架構：前者提供廣泛覆蓋的基礎知識，後者補足特定任務所需的細節。

##### 3. 儲存庫到技能的圖結構

每個儲存庫被蒸餾成一個技能圖（skill graph），而技能庫層級的路由器（router）會根據請求將其導向相關圖。這意味著技能不是扁平的關鍵字列表，而是保留了儲存庫內部模組與功能之間的結構關係，有助於代理在複雜任務中進行多跳推理與工具選擇。

##### 4. 驗證機制

論文強調「未經驗證不進入技能層」。每個候選技能會被檢查、盡可能修復，並記錄殘留缺口。這降低了幻覺（hallucination）風險，也讓技能具備可審計性。雖然摘要未詳述驗證是靜態測試、動態執行或兩者兼具，但「verified skills」的宣稱暗示至少包含可執行腳本的語法與語義檢查。

---

#### 實驗數據解讀

為了隔離技能本身的效果，作者採用嚴格的對照設計：固定 GPT-5.5 骨幹、固定研究框架（research harness）、固定下游執行預算（downstream execution budget），僅在運行時有無蒸餾技能（distilled skills）之間比較。技能建構在下游執行開始前即已完成，因此運行時的唯一變數就是操作知識層。

| 基準（Benchmark） | 有技能相對無技能的提升 |
|---|---|
| MLE-bench | +134.3% |
| PaperBench | +34.4% |
| FrontierCS | +9.2% |
| PassNet | +14.0% |

##### 1. MLE-bench：工程導向任務獲益最大

MLE-bench 是機器學習工程基準，強調從資料處理、模型訓練到提交結果的端到端（end-to-end）流程。134.3% 的大幅提升說明：當任務涉及大量套件 API、訓練流程配置與常見實作細節時，預先蒸餾的操作知識能顯著減少試誤法（trial and error）所消耗的預算（budget）。這與論文論點高度一致：沒有操作知識時，代理必須在任務內推論套件行為，錯誤往往在預算耗盡後才浮現。

##### 2. PaperBench：複現論文需要領域知識

PaperBench 測試論文複現能力，提升 34.4%。這顯示技能不僅能輔助程式碼實作，也能提供方法選擇、超參數設定與評估流程的領域內容（domain content）。對於需要理解論文方法並轉化為可執行程式碼的任務，蒸餾自儲存庫與論文的技能提供了關鍵上下文。

##### 3. FrontierCS 與 PassNet：較低但仍正向的提升

FrontierCS 與 PassNet 分別僅提升 9.2% 與 14.0%。這可能反映：

- 這些基準更側重高階研究設計或理論推導，對「如何讓套件運作」的依賴較低；
- 現有儲存庫覆蓋與這些任務的知識需求存在缺口；
- 任務導向蒸餾雖可動態補充，但受限於即時探索的預算與深度。

儘管增幅較小，四個基準全部正向提升，顯示操作知識層具有跨任務的通用價值，而非僅對特定工程任務有效。

##### 4. 實驗設計的優點與限制

優點在於「固定其他變數」的對照方式，能較乾淨地歸因於技能。然而，摘要與引言未提供：

- 各基準的絕對分數與標準差；
- 技能數量與任務表現的劑量反應關係；
- 任務無關與任務導向技能各自的邊際貢獻；
- 驗證失敗率與修復成本。

這些資訊對於評估方法穩健性與成本效益至關重要。

#### 與現有研究的比較

##### 1. 定位：從「更強模型」到「更豐富知識層」

過去自主研究代理的進展主要來自兩個方向：更強大的模型骨幹（frontier generations）與更成熟的 harness 工程。本研究明確區分第三個維度——操作知識層，並主張在模型與框架不變的情況下，僅透過注入蒸餾後的操作上下文（operating context）即可顯著提升表現。這與近期強調「工具使用」、「記憶體擴充」或「檢索增強生成（RAG）」的研究不同：DisCo 不僅檢索原始文件，而是將文件轉化為可直接執行的技能單元。

##### 2. 與 RAG 與長上下文模型的差異

長上下文模型（long-context models）與 RAG 系統試圖在任務進行時載入大量原始素材。本研究指出原始素材「太大而無法在任務中載入」，且格式不適合代理消費。DisCo 的解法是預先將素材轉換為緊湊、結構化、可驗證的技能，這比單純檢索原始 README 或論文段落更接近「可執行知識」。

##### 3. 與程式碼代理（Coding Agents）的關係

編碼代理（coding agents）已在軟體任務中展現強大能力，但 ML 研究是專業知識密集型任務，成功取決於方法選擇與實作細節。DisCo 可視為在編碼代理之上疊加領域專家知識庫，將無引導的試誤轉為引導式執行（guided execution）。

##### 4. 主要限制

- **覆蓋偏差（Coverage Bias）**：AREX-Skill Library 來自 1,000 個廣泛使用的 ML 儲存庫，可能偏向熱門專案與主流方法，冷門或新興領域的知識可能不足。
- **時效性（Staleness）**：儲存庫持續更新，技能可能隨版本漂移而過時。論文雖強調驗證，但未說明更新頻率與版本對齊機制。
- **驗證成本**：大規模蒸餾與驗證 5,000+ 技能需要可觀的計算與模型呼叫成本，可能限制即時擴展到整個開放生態系統（open ecosystem）。
- **對 GPT-5.5 的依賴**：實驗僅使用 GPT-5.5 作為骨幹，尚不清楚技能層對其他模型（如開源模型或較小模型）的增益是否一致。
- **評估範圍**：四個基準均聚焦 ML 研究，未涵蓋其他科學領域或工業級軟體工程任務，泛化性有待驗證。
- **可解釋性與除錯**：當技能導致錯誤時，代理如何回溯到原始儲存庫段落、如何更新技能，這些機制在摘要中著墨不多。

#### 可重現性評估

根據目前提供的摘要與引言，論文尚未明確說明是否公開以下資源：

- DisCo 的完整原始碼與 harness 實作；
- AREX-Skill Library 的 5,000+ 技能檔案與對應儲存庫快照；
- 任務導向蒸餾與驗證流程的詳細演算法；
- 四個基準上的具體執行日誌與中間產物；
- 用於蒸餾與驗證的提示（prompts）與評估腳本。

若這些資源未開源，則可重現性會受到明顯限制：其他研究者難以驗證 134.3% 的提升是否來自特定實作細節、難以在自己的任務上測試 AREX-Skill Library，也難以比較公平基線。此外，GPT-5.5 作為尚未廣泛可及的骨幹模型，也會造成重現門檻。

建議作者至少釋出：

1. SKILL.md 的規範與範例；
2. 從儲存庫到技能圖的蒸餾流程；
3. 驗證失敗率與修復統計；
4. 基準評估的詳細設定與原始分數。

這將大幅提升社群對該方法的理解與後續改進。

#### 未來研究方向

##### 1. 自動化與持續更新機制

儲存庫與套件版本不斷演進，未來可研究如何讓技能庫自動偵測版本變更、觸發增量蒸餾與回歸驗證，解決時效性問題。

##### 2. 跨領域遷移

目前 AREX-Skill Library 聚焦機器學習研究。將相同框架應用於其他程式密集型領域（如生物資訊、機器人、資料工程）是自然的延伸，但需要重新定義能力家族與驗證標準。

##### 3. 技能組合與規劃推理

現有技能是離散單元，未來可探索技能之間的組合語義：如何自動將多個技能串接成複雜研究計畫、如何偵測技能衝突、如何進行條件式技能選擇。

##### 4. 人機協作與主動學習

讓領域專家能夠標註、修正與擴充技能，並透過主動學習（active learning）優先蒸餾高不確定性或高影響力的儲存庫，可提升技能品質與覆蓋率。

##### 5. 因果與語義驗證

目前的驗證可能偏重語法與執行層面。未來可引入因果驗證（causal verification）與語義一致性檢查，確保技能不僅能跑，還能正確實現其宣稱的方法。

##### 6. 輕量化與開源模型適配

研究技能層對較小開源模型的增益，以及如何在邊緣或低成本環境中部署 DisCo，將有助於降低進入門檻並擴大應用場景。

##### 7. 基準擴充與細粒度分析

建立專門衡量「操作知識」貢獻的診斷基準，例如區分「API 使用」、「方法選擇」、「超參數調整」、「評估流程」等子能力，將幫助社群更精確地理解技能層的價值與缺口。

## 論文問答

**Q1：自主機器學習研究代理中，「操作知識」這個缺失層具體指什麼？它與模型骨幹和 harness 有何不同？**  
A：操作知識指的是把「知道一個方法」轉化為「讓這個方法真正運作」的實務訣竅，涵蓋如何選擇方法、設定實驗、正確使用套件 API、配置訓練流程以及避開常見實作與評估陷阱。模型骨幹提供理解、推理、規劃與執行的通用能力，harness（框架）負責編排、記憶、驗證與迭代細化的流程控制，但兩者都不攜帶領域專屬的內容。因此，操作知識是獨立於模型與 harness 的第三層，決定了代理在開始研究時「知道什麼」。

**Q2：為什麼現有的 GitHub 儲存庫與論文不能直接填補這個缺失層？**  
A：這些來源素材主要是為人類讀者撰寫，篇幅龐大且充斥與當前任務無關的細節，無法在代理的上下文預算內直接載入。此外，儲存庫會隨版本釋出而漂移，文件常遺漏實務陷阱，且內容多為宣告式描述而非可執行的 know-how。因此必須透過蒸餾將其轉換為精簡、可操作且經驗證的技能，才能被代理有效使用。

**Q3：將操作知識轉化為「技能」對代理的跨任務能力為何至關重要？**  
A：若沒有技能形式的知識，代理只能在單一任務內以試誤法推斷套件行為，錯誤往往在預算耗盡後才浮現，且這些發現無法被保留到下一個任務。技能以 SKILL.md 等結構化文件封裝 know-how，開頭即提供摘要，僅在需要時展開細節，使代理能同時持有數千個技能卻只載入少數相關項目。這種可發現、可載入且立即可用的形式，讓知識層能隨規模擴展而不擠壓上下文，並實現跨任務的引導式執行。

**Q4：DisCo 的核心方法如何同時處理「預先準備」與「按需生成」兩種技能需求？**  
A：DisCo 採用任務無關與任務導向兩種互補的蒸餾形式：任務無關蒸餾在事前進行，把領域中廣泛使用的儲存庫與日常工具濃縮成可重複使用的技能；任務導向蒸餾則在面對具體任務時啟動，探索該任務觸及的知識並產出所需技能。兩種形式都會經過驗證，確保進入技能庫的每個候選技能都具備可操作性。這樣的設計讓代理既能享有開放生態系統的通用知識，也能針對當前問題動態補充特定技能。

**Q5：技能的表示方式為何採用 SKILL.md、參考文件與腳本的組合？這對代理的上下文管理有何幫助？**  
A：SKILL.md 明確說明技能的用途、適用情境與執行步驟，參考文件提供證據與細節，腳本則自動化例行操作，三者共同把隱性 know-how 轉為結構化、可執行的單元。由於每個技能都以摘要開頭，代理可以先快速判斷相關性，只在確認需要時才深入展開，從而避免一次性載入大量無關內容。這種「按需展開」的設計讓代理能管理數千個技能，同時將上下文保留給真正重要的操作知識。

**Q6：DisCo 如何確保蒸餾出的技能品質與可靠性？**  
A：DisCo 對每個候選技能進行驗證，能修復的問題會被修復，無法完全解決的缺口則會被記錄下來，未經驗證的技能不會進入操作知識層。這套驗證機制在下游執行開始前即完成，因此在實驗對照中，技能成為唯一的變因。透過這種嚴格的品質把關，代理才能信任並正確應用技能，減少因錯誤知識導致的預算浪費。

**Q7：論文在哪些基準上評估 DisCo，並採用什麼樣的對照設定來隔離技能的效果？**  
A：評估涵蓋 MLE-bench、PaperBench、FrontierCS 與 PassNet 四個基準，分別對應機器學習工程、論文複現、前沿電腦科學與網路通過率等不同面向。實驗固定使用 GPT-5.5 作為模型骨幹、相同的研究框架與相同的下游執行預算，僅比較「配備技能」與「未配備技能」的同一代理。由於技能建構在下游執行前已完成，任何表現差異都可歸因於蒸餾出的操作上下文。

**Q8：加入技能後，代理在各基準上的表現提升幅度為何？這說明了什麼？**  
A：配備技能的代理在 MLE-bench 上提升 134.3%，PaperBench 提升 34.4%，FrontierCS 提升 9.2%，PassNet 提升 14.0%。這些增益來自於在模型、框架與執行預算完全相同的前提下，額外加入了經蒸餾的操作上下文。結果顯示，操作知識層本身就能顯著改善研究代理的端到端表現，而不必依賴更強大的模型或更複雜的 harness。

**Q9：從實驗設計來看，這些結果對「模型進步 vs. 知識工程」的辯論有何啟示？**  
A：實驗刻意固定模型骨幹與 harness，讓技能成為唯一變因，因此能清楚量化知識工程帶來的邊際效益。這說明除了等待前沿世代模型變強或優化編排框架外，系統性地蒸餾與注入領域操作知識同樣是提升代理能力的重要途徑。對於機器學習研究這類專業領域，know-how 的可重用性可能與模型規模同等關鍵。

**Q10：AREX-Skill Library 在實務上可以如何被研究人員或工程師使用？**  
A：AREX-Skill Library 從 1,000 個廣泛使用的機器學習儲存庫蒸餾出 5,000 多個經驗證的技能，並依 20 個領域與 178 個能力家族組織，使用者可透過庫級路由器快速定位相關技能。研究人員在面對新任務時，不必再從頭閱讀儲存庫文件或反覆試誤，而是直接載入對應技能來正確使用套件 API、配置訓練流程與處理評估陷阱。這種可重用的知識層能顯著縮短實作與實驗設置的時間，並降低因經驗不足造成的錯誤。

**Q11：若要將技能層產品化，需要考慮哪些維護與設計挑戰？**  
A：首先，儲存庫與套件持續更新會導致技能內容漂移，因此需要建立持續監控與重新蒸餾的機制。其次，技能庫規模龐大，必須透過領域與能力家族的分類以及庫級路由器，確保代理能快速發現並只載入最相關的技能，避免上下文超載。最後，驗證流程需要與實際執行環境緊密整合，才能及時標記過時或存在缺口的技能，維持整體可靠性。

**Q12：Repo-To-Skill 這套典範對自主研究代理的長遠發展可能帶來什麼影響？**  
A：它把研究焦點從單純強化模型與 harness，擴展到建構可重用的領域操作知識基礎設施。當越來越多領域的儲存庫與論文被蒸餾成技能，自主代理將能站在集體實務經驗上進行研究，而非每次任務都重新發明輪子。這可能催生出類似「技能市場」或領域專用技能庫的生態，進一步降低機器學習研究的門檻並加速創新。

**Q13：論文承認了哪些方法或評估上的限制？**  
A：目前的技能庫快照僅涵蓋 1,000 個儲存庫與特定機器學習領域，尚未覆蓋所有子領域或最新的閉源工具。來源素材本身會隨版本漂移，且常遺漏實務陷阱，使得蒸餾出的技能可能帶有缺口或需要持續更新。此外，驗證雖能過濾部分錯誤，但無法保證在所有邊界情況下都正確無誤。

**Q14：在哪些情況下，DisCo 蒸餾出的技能可能會失效或造成誤導？**  
A：當儲存庫釋出新版本而技能未及時更新時，API 或預設行為的改變可能使原有步驟失效。若任務涉及高度新穎或跨領域的問題，現有能力家族中可能找不到適用的技能，導致代理錯誤套用相似但不正確的 know-how。此外，驗證若未能觸發特定邊界條件，技能中潛藏的錯誤可能在後續執行中才顯現，浪費執行預算。

**Q15：未來研究可以朝哪些方向擴展 Repo-To-Skill 與 DisCo？**  
A：未來可擴大蒸餾範圍，納入更多儲存庫、論文與其他科學領域，並建立自動化的持續更新管道以應對版本漂移。驗證機制也可進一步強化，例如結合互動式執行、人類回饋與形式化檢查，以減少未被發現的缺口。此外，探索如何讓代理在執行過程中動態學習並產出新技能，將使操作知識層從靜態庫進化為能自我成長的研究基礎設施。

## 實務應用指南

### 適用場景

1. **企業內部 ML 平台加速實驗迭代**  
   資料科學團隊可將內部常用套件、訓練流程與評估腳本蒸餾成技能，讓編碼代理在 MLE-bench 類任務中直接載入「公司慣用做法」，減少重複試誤。

2. **開源專案維護與入門引導**  
   針對 GitHub 上廣泛使用的 ML 儲存庫，自動產生 SKILL.md 與參考文件，降低新貢獻者的學習曲線，並讓代理協助回答「這個 API 怎麼用、什麼情況下會出錯」。

3. **學術論文複現輔助**  
   在 PaperBench 類任務中，代理可透過任務導向蒸餾，把論文與對應程式碼轉成操作知識，協助研究者正確設定實驗條件、避開實作陷阱。

4. **自動化程式碼審查與最佳實踐建議**  
   將領域內的常見錯誤與修復方式蒸餾為經驗證的技能，整合到 CI/CD 流程，讓代理在提交階段就檢查套件 API 使用、訓練流程配置等問題。

5. **跨領域研究工具組裝**  
   當任務涉及多個領域（如 CV、NLP、強化學習）時，透過 AREX-Skill Library 的領域路由器，動態載入不同能力家族的技能，協助代理快速組合正確工具鏈。

### 實作前置條件

- **資料準備**
  - 目標 GitHub 儲存庫的原始碼、README、文件與範例腳本。
  - 若採任務導向蒸餾，需準備具體任務描述、資料集、目標規格與評估指標。
  - 現有錯誤日誌、常見問題或內部技術文件，可提升技能驗證效率。

- **運算資源**
  - 蒸餾階段需要 LLM API 呼叫預算（如 GPT-5.5 等級骨幹）以及執行儲存庫範例的運算環境。
  - 驗證階段需可執行容器化環境，用於測試腳本、確認技能產出的程式碼能正確運作。
  - 下游執行預算需與研究框架匹配，避免把技能載入後的執行成本低估。

- **技能與系統前提**
  - 已具備研究框架（harness），能支援規劃、記憶、驗證與迭代細化。
  - 熟悉 SKILL.md 格式與技能圖（skill graph）結構。
  - 有能力建立或整合技能庫路由器，讓代理依任務選取相關能力家族。

---

### 實作步驟建議

1. **盤點操作知識來源**  
   列出團隊最常使用的 ML 儲存庫、內部套件與論文實作，區分「任務無關」的通用知識與「任務導向」的特定知識。

2. **建立技能蒸餾管線**  
   參考 DisCo 的雙軌蒸餾：  
   - **任務無關**：對每個儲存庫產生技能圖，濃縮 README、API 文件與範例為 SKILL.md、參考文件與自動化腳本。  
   - **任務導向**：針對具體任務，探索其觸及的知識範圍，動態產生所需技能。

3. **導入驗證與修復機制**  
   每個候選技能必須經過執行驗證；失敗者嘗試自動修復，無法修復的需標註缺口，避免未經驗證的技能進入技能庫。

4. **組織技能庫與路由器**  
   將技能依領域與能力家族分類，建立庫級路由器，使代理能根據任務描述快速縮小到相關技能圖，避免上下文過載。

5. **與研究代理整合並固定變因評估**  
   在相同模型骨幹、研究框架與下游執行預算下，比較「有技能」與「無技能」的表現，確認增益來自操作上下文而非其他工程改動。

6. **持續維護與版本更新**  
   儲存庫與套件會隨版本漂移，需定期重新蒸餾與驗證技能，並將新發現的實作陷阱補充進既有技能。

---

### 潛在風險與注意事項

- **來源素材品質不穩定**  
  儲存庫文件常省略實務訣竅或版本細節，導致蒸餾出的技能過於理想化。建議搭配實際執行結果與錯誤日誌進行驗證。

- **技能過時與版本漂移**  
  套件 API 與最佳實踐會變動，未定期更新會讓代理依賴錯誤知識。應建立版本標註與週期性重新驗證流程。

- **過度依賴技能而忽略推理**  
  技能應作為操作上下文輔助模型推理，而非取代規劃與驗證。研究框架仍需負責編排與迭代細化。

- **驗證成本被低估**  
  大規模蒸餾需要大量執行與 LLM 呼叫，建議先從高影響力的核心儲存庫開始，逐步擴充，而非一次蒸餾整個開放生態系統。

- **智慧財產與授權議題**  
  蒸餾開源儲存庫時需注意授權條款；內部程式碼則要控管技能庫的存取權限，避免敏感實作細節外洩。

---

### 與其他技術的整合建議

- **與現有 MLOps 平台整合**  
  將技能庫掛接到實驗追蹤、模型註冊與工作流程編排工具，讓代理在啟動實驗前自動載入對應訓練流程與評估設定。

- **與檢索增強生成（RAG）互補**  
  RAG 提供原始文件片段，技能則提供已驗證、可執行的操作知識。兩者結合可讓代理同時擁有「背景資訊」與「現成做法」。

- **與編碼代理（coding agents）協作**  
  技能驅動的研究代理可將 SKILL.md 與腳本餵給底層編碼代理，後者專注於程式碼生成與除錯，前者負責領域知識選擇與任務規劃。

- **與持續整合／持續部署（CI/CD）結合**  
  在 PR 審查或部署前，利用技能庫檢查常見實作陷阱與 API 誤用，將操作知識轉化為自動化閘道。

- **與企業知識管理系統連接**  
  把內部技術文件、會議紀錄與問題回報也納入蒸餾來源，補充開源儲存庫無法涵蓋的組織特定操作知識。

### 給不同背景讀者的閱讀建議

- **初學者**：  
  本論文的核心概念是「讓 AI 代理不只會寫程式，還知道怎麼把事情做對」。建議先聚焦於「操作知識」與「技能」這兩個名詞，理解它們如何彌補模型先驗與研究框架之間的缺口，再回頭看 MLE-bench 等實驗數據，就能明白為何加入技能後表現大幅提升。

- **AI 工程師**：  
  重點關注 DisCo 的蒸餾管線、驗證機制與技能庫路由設計。論文強調在固定模型骨幹、研究框架與下游執行預算下進行比較，這對你設計可重現的 A/B 測試非常有參考價值；同時可思考如何將 SKILL.md 格式與既有代理系統對接。

- **研究人員**：  
  請留意任務無關與任務導向蒸餾的互補性，以及「操作知識」作為獨立層次的理論定位。這不僅是工程優化，也提出了一個新的研究問題：如何從聲明式文件自動產生可執行的實務訣竅，並在開放生態系統中規模化驗證。

- **產品經理**：  
  這篇論文提供了一個可落地的商業化路徑：把組織內的領域知識封裝成可重複使用的技能資產。閱讀時請著眼於「降低重複試誤成本」與「加速新成員上手」這兩個業務價值，並評估導入技能庫所需的資料、運算與維護成本。
